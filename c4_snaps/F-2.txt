    uid=13_55 heading "Finding Description" level="3"
    uid=13_56 StaticText "The validatePrice() function is meant to validate the trade price against a time-weighted average price (TWAP) from a Uniswap V2 pair, enforcing a maximum allowed slippage. Correct TWAP-based validation is a core security mechanism against flash loans, sandwich attacks, and short-term price manipulation by averaging prices over time."
    uid=13_57 StaticText "Uniswap V2 exposes cumulative price variables (price0CumulativeLast and price1CumulativeLast) that grow monotonically over time, encoding the reserve ratio in UQ112x112 format multiplied by elapsed time. To compute a TWAP, a consumer must:"
    uid=13_58 StaticText "Snapshot cumulative prices and timestamps at time t0"
    uid=13_59 StaticText "Read cumulative prices again at time t1"
    uid=13_60 StaticText "Compute the average price as the difference divided by elapsed time"
    uid=13_61 StaticText "validatePrice() deviates from this design:"
    uid=13_62 StaticText "It reads the latest cumulative price from the pair"
    uid=13_63 StaticText "Reads blockTimestampLast from getReserves()"
    uid=13_64 StaticText "Builds an artificial “cumulative price” using the current tradePrice"
    uid=13_65 StaticText "Derives a “TWAP” from these values"
    uid=13_66 StaticText "Compares that “TWAP” to the current trade price to enforce slippage"

    uid=13_128 StaticText "The computed TWAP is always equal to the current tradePrice, regardless of history, elapsed time, or pool liquidity. The slippage check is effectively nullified because the deviation is always zero (aside from rounding)."
    uid=13_129 StaticText "Further issues:"
    uid=13_130 StaticText "tradePrice comes from getPrice() and is not guaranteed to reflect Uniswap reserves."
    uid=13_131 StaticText "The Uniswap V2 cumulative prices are UQ112x112, but the function uses raw uint256 math without proper fixed-point handling."
    uid=13_132 StaticText "blockTimestampLast reflects the last reserve update, not a consumer-controlled oracle observation."
    uid=13_133 StaticText "The function is view and uses no persisted state, so it is fully exploitable via flash loans or same-block reserve manipulation."
    uid=13_134 StaticText "UniswapPriceOracle is used on chains with Uniswap V2 pools (e.g. Ethereum mainnet). validatePrice() is the gate for all OLAS swap and liquidity-exit flows that use V2 oracles."
    uid=13_135 StaticText "1. BuyBackBurner._buyOLAS() (V2 path)"
    uid=13_136 StaticText "Called from buyBack(secondToken, secondTokenAmount) when using V2 pools."
    uid=13_137 StaticText "Flow: require(IOracle(poolOracle).validatePrice(maxSlippage), "Before swap slippage limit is breached") → getPrice() → _performSwap() → getPrice() again → post-swap bounds check."
    uid=13_138 StaticText "Anyone can call buyBack() after secondTokens (e.g. WETH) are deposited into the contract. The protocol swaps treasury/user deposits for OLAS and sends it to bridge2Burner for burning or bridging."
    uid=13_139 StaticText "Because validatePrice() always passes (TWAP ≈ spot), the pre-swap check is ineffective. An attacker can flash-loan, manipulate the pool, and have the buyback execute at the manipulated price. The protocol receives less OLAS per unit of ETH, and the attacker can unwind to capture arbitrage profit."
    uid=13_140 StaticText "2. LiquidityManagerETH._checkTokensAndRemoveLiquidityV2() and LiquidityManagerOptimism._checkTokensAndRemoveLiquidityV2()"
    uid=13_141 StaticText "Called from convertToV3() when migrating V2 LP to V3."
    uid=13_142 StaticText "Flow: if (!IOracle(oracleV2).validatePrice(maxSlippage / 100)) revert SlippageLimitBreached() → remove V2 liquidity → mint V3."
    uid=13_143 StaticText "Only the owner can call convertToV3(). The oracle is used to ensure the V2 exit happens at a fair price before migrating to V3."
    uid=13_144 StaticText "Because validatePrice() always passes, the protocol can exit V2 liquidity at a manipulated price. The resulting token amounts (OLAS and quote) are worse than the true TWAP would imply, and the attacker can profit from the price deviation when the protocol swaps or migrates."
    uid=13_145 StaticText "Attacker scenario"
    uid=13_146 StaticText "Observe a buyBack() or convertToV3() transaction in the mempool."
    uid=13_147 StaticText "Swap to move the Uniswap V2 pool price (e.g. large swap in either direction)."
    uid=13_148 StaticText "Execute the victim transaction in the same block."
    uid=13_149 StaticText "validatePrice() passes because TWAP ≈ manipulated spot."
    uid=13_150 StaticText "Swap or liquidity removal executes at the manipulated price."
    uid=13_151 StaticText "Attacker reverses the pool manipulation in the same block."
    uid=13_152 StaticText "Attacker pockets the arbitrage; the protocol or users take the loss."
    uid=13_153 StaticText "The attack is cheap (flash loan + gas), permissionless, and repeatable. The same logic applies to any chain where UniswapPriceOracle is used for OLAS swaps or liquidity exits."
    uid=13_154 heading "Recommendation" level="3"
    uid=13_155 StaticText "Implement a proper Uniswap V2 TWAP oracle pattern by persisting cumulative price snapshots across blocks and computing averages from differences between observations:"
    uid=13_156 StaticText "Store price{0,1}CumulativeLast and timestampLast in contract storage"
    uid=13_157 StaticText "Update them in a state-changing function (e.g. updateOracle())"
    uid=13_158 StaticText "Compute TWAPs using cumulative price deltas"
    uid=13_159 StaticText "Correctly handle UQ112x112 fixed-point math"
    uid=13_160 StaticText "Slippage should be evaluated only after a correct TWAP is computed. This restores the intended oracle guarantees and protects against same-block and flash-loan-based price manipulation."
