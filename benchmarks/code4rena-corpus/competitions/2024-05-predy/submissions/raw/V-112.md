# Vulnerability details

## Impact
The following problems may occur due to lack of access control in the `PredyPool.sol#initialize()` function.
1.An attacker can set the `uniswapFactory` address to an invalid address.
2.An attacker can hijack `operator` privileges.

## Proof of Concept
`PredyPool.sol` implements openzeppelin's `Initializable` model. The problem is that it's unprotected from an attacker initializing the contract. The uninitialized contract can be taken over by the attacker for example by front-running the original deployer's `intialize()` call.

[See OpenZeppelin's comment in their documentation:](https://docs.openzeppelin.com/upgrades-plugins/1.x/writing-upgradeable#initializers)

>Do not leave an implementation contract uninitialized. An uninitialized implementation contract can be taken over by an attacker, which may impact the proxy. To prevent the implementation contract from being used, you should invoke the _disableInitializers function in the constructor to automatically lock it when it is deployed:

```solidity
    function initialize(address uniswapFactory) public initializer {
        __ReentrancyGuard_init();
        AddPairLogic.initializeGlobalData(globalData, uniswapFactory);

        operator = msg.sender;
    }
```
As a result, an attacker can set the `uniswapFactory` address to an invalid address.
And he can also hijack `operator` privileges.
The `operator` permission can access core functionality of the protocol, such as registering a new trading pair or withdrawing protocol revenue from that pair.
```solidity
109: function registerPair(AddPairLogic.AddPairParams memory addPairParam) external onlyOperator returns (uint256) {
```
```solidity
177:    function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external onlyOperator {
```
Therefore, if the `operator` authority is taken away, the protocol may face a catastrophic situation in which it may become bankrupt.
This phenomenon also appeared in `GammaTradeMarket.sol` and `PerpMarketV1.sol`.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider to add _disableInitializers() function and the constructor to `PredyPool.sol`:
```solidity
    constructor() {
	    _disableInitializers();
    }
```
