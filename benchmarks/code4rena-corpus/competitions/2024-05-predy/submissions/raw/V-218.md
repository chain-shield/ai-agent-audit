# Vulnerability details

## Impact
Update periods in `TWAP` oracles reflect `risk` of an asset. Updating more frequently accurately prices an `asset` but increases capabilities of manipulation (which should be harder with more stable assets) whereas longer update periods prevent manipulation but do not accurately price assets (due to the time difference between updates).

Volatility of an asset should be considered when calculating updating periods. 

However, in `UniHelper.sol` no such considerations are made.
The `_ORACLE_PERIOD` cannot be changed after deployment of the contract. Additionally, each asset uses the same `_ORACLE_PERIOD` which does not adequately account for the difference in risk for each asset.

This could lead to inadequate pricing of assets.

## Vulnerability Details
 [_ORACLE_PERIOD](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L11) in `UniHelper.sol` is fixed at `30 minutes`
 ```solidity
 uint256 internal constant _ORACLE_PERIOD = 30 minutes;
 ```
To get the square root of time weighted average price, this same `_ORACLE_PERIOD` is used everytime in [getSqrtTWAP](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L20-L22).
 ```solidity
    function getSqrtTWAP(address uniswapPoolAddress) internal view returns (uint160 sqrtTwapX96) {
        (sqrtTwapX96,) = callUniswapObserve(IUniswapV3Pool(uniswapPoolAddress), _ORACLE_PERIOD); // @audit-issue Same update period used
    }
 ```
This means that regardless of which asset whose price is being fetched, the same update period is used with no account whatsoever for the risks.

This is evident when oracle is set to `address(0)` in `PositionCalculator.sol`.
Here, [getSqrtIndexPrice()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/PositionCalculator.sol#L141-L149) uses two methods to fetch asset price.
1. If oracle is set, it uses the oracle price
2. If this is not set, it fetches TWAP

 ```solidity
    function getSqrtIndexPrice(DataType.PairStatus memory pairStatus) internal view returns (uint256 sqrtPriceX96) {
        if (pairStatus.priceFeed != address(0)) {
            return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
        } else {
            return UniHelper.convertSqrtPrice(
                UniHelper.getSqrtTWAP(pairStatus.sqrtAssetStatus.uniswapPool), pairStatus.isQuoteZero // @audit-issue Twap fetched here
            );
        }
    }
 ```
Evidently, if `oracle` is not set, it fetches `TWAP` by invoking `UniHelper.getSqrtTWAP()` which as seen above, uses the same `_ORACLE_PERIOD`.

This will lead to inadequate pricing for different assets.

 ## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a method do update the `_ORACLE_PERIOD` to account for all asset risks
