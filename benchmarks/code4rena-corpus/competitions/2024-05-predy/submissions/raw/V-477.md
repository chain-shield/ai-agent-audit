# Vulnerability details

## Impact
Users face potential unjust liquidation due to fillers having access to two different prices in a single transaction.
This issue may also stem from user oversight, as traders must grasp and mitigate the associated risks.
## Proof of Concept
When a trade is initiated, the trader signs the order and forwards both the order and signature to a filler. The filler then calls either executeOrderV3 or executeTrade(). However, the system does not ensure that prices from Pyth are updated before being used in trade execution. This vulnerability enables a filler to manipulate execution by using outdated prices, potentially leading to user liquidation.

The Pyth oracles allow for retrieving two distinct prices within one transaction, which can be exploited for arbitrage. Pyth network prices update every 400ms, indicating that the latest price recorded on-chain may not be the most recent one.

## Tool Used
Manual review

## Recommended  Mitigation Steps 
To mitigate risks associated with significant discrepancies, ensure that all Pyth pricing data used during trade execution is updated by calling Pyth's updatePriceFeeds() function to obtain the latest prices.
