# Vulnerability details


## Summary

This report identifies a potential vulnerability in the `registerPair` function of the protocol. The function allows anyone (Since anyone can add a new pair based on the sponsor's input on the discord group) to register a new trading pair. However, the function lacks proper validation for the `IRMParams` (Interest Rate Model Parameters) associated with the pair. An attacker could exploit this by registering a pair with inflated `IRMParams` values, leading to:

* **Manipulated Interest Rates:** The inflated `IRMParams` could cause the `calculateInterestRate` function to calculate an artificially high interest rate for the pool.
* **Excessive Fees:** This high interest rate would then be used to calculate exorbitant protocol fees and creator fees, potentially draining all or even more than the collected fees from the pool.

## Impact

If not addressed, this vulnerability could lead to

* **Loss of Funds:** Users who deposit funds into the manipulated pool might incur unexpectedly high fees, leading to potential losses.

## Recommended Mitigation Steps

To mitigate this vulnerability, it's crucial to implement a validation check for all input parameters within the `_storePairStatus` function, including the `IRMParams`. Here's a suggested approach:

1. **Validation Check:** Before storing the pair information, add a validation step within `_storePairStatus` to ensure that all `IRMParams` in the `_addPairParam` struct fall within the predefined acceptable ranges.
2. **Error Handling:** If any `IRMParam` value violates the defined range, revert the function or throw an error message, preventing the creation of a manipulated pool.
