# Vulnerability details

## Impact
```
    function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        ...snip...
        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);
        ...snip...
```

`PriceFeed.getSqrtPrice()` uses the `basePrice` returned from the Pyth oracle but never checks the data's confidence interval. This can lead to using an very uncertain price for the base token.

```
interface IPyth {
    struct Price {
        // Price
        int64 price;
        // Confidence interval around the price
@>      uint64 conf;
        // Price exponent
        int32 expo;
        // Unix timestamp describing when the price was published
        uint256 publishTime;
    }
```

Note that the Pyth oracle returns the confidence interval (`basePrice.conf`) along with the price. The wider the `basePrice.conf`, the further the true price could be from the reported price.

It's recommended to set a maximum tolerance for the confidence interval. Without this, the protocol might make decisions based on deviated prices, potentially causing losses.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider setting a maximum allowed width of the confidence interval (MAX_CONF_BPS), then check that the confidence interval is within this threashold:
```diff
        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);
+       require(basePrice.conf < basPrice.price * MAX_CONF_BPS / FULL_BPS, "uncertain price");
```
