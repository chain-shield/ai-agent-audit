# Vulnerability details

## Impact
`PredyPool` allows users to supply tokens to pools in exchange for `bond tokens`.

Users can later withdraw the tokens they have supplied by calling `PredyPool::withdraw`, which burns their `bond tokens`.

When calculating the amount to burn, the protocol `rounds down`. This favors the user, as less `bond tokens` will be burned for the amount of tokens withdrawn, causing loss of funds for other lenders

## Proof of Concept
[PredyPool.sol#L230-L243](https://github.com/code-423n4/2024-05-predy/blob/main/src/PredyPool.sol#L230-L243)
```javascript
    /**
     * @notice Withdraws either the quoteToken or the baseToken from the lending pool.
     * In return, the lender burns the bond tokens.
     * @param pairId The id of pair to withdraw liquidity
     * @param isQuoteAsset Whether the token is quote or base
     * @param withdrawAmount The amount of tokens to withdraw
     */
    function withdraw(uint256 pairId, bool isQuoteAsset, uint256 withdrawAmount)
        external
        nonReentrant
        returns (uint256 finalBurnAmount, uint256 finalWithdrawAmount)
    {
        return SupplyLogic.withdraw(globalData, pairId, withdrawAmount, isQuoteAsset);
    }
```

Lenders can withdraw their tokens by burning `bond tokens.`

The amount to burn is calculated as follows:

[ScaledAsset.sol#L57](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L57)
```javascript
uint256 burnAmount = FixedPointMathLib.mulDivDown(_amount, Constants.ONE, tokenState.assetScaler);
```

We can see it rounds down in favor of the users, causing a lower amount of `bond tokens` to be burned for the amount they withdraw. Other lenders will lose funds.

## Recommended Mitigation Steps
Round up in favor of protocol

```diff
- uint256 burnAmount = FixedPointMathLib.mulDivDown(_amount, Constants.ONE, tokenState.assetScaler);
+ uint256 burnAmount = FixedPointMathLib.mulDivUp(_amount, Constants.ONE, tokenState.assetScaler);
```
