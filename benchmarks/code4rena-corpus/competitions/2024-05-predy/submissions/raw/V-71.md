# Vulnerability details

## Impact
Lack of validation for the parameters passed to the `_permit2.permitWitnessTransferFrom` could allow an attacker to craft malicious orders and transfer tokens without proper authorization, and this could result in the following consequences below:

**`Unauthorized Token Transfers`:** Attacker could transfer tokens from an address they do not own by providing a malicious `order.info.trader` address and a valid signature (`order.sig`).

**`Unintended Token Transfers`:** Attacker could transfer tokens to an unintended recipient address by providing a malicious `order.transferDetails(address(this))` parameter.

**`Incorrect Token Amounts`:** Attacker could transfer an incorrect amount of tokens by providing a malicious `order.toPermit()` parameter with an incorrect token amount.

**`Code:`** [src/markets/gamma/GammaTradeMarket.sol#_verifyOrder](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L444-L455)
The vulnerability stems from the lack of validation in the `_verifyOrder`, which directly passes the parameters from the `order` struct to the `_permit2.permitWitnessTransferFrom` without any checks.
```solidity
function _verifyOrder(ResolvedOrder memory order) internal {
    order.validate(); // This function may or may not perform sufficient validation

    _permit2.permitWitnessTransferFrom(
        order.toPermit(), // No validation of the returned parameters
        order.transferDetails(address(this)), // No validation of the returned parameters
        order.info.trader, // No validation of the trader address
        order.hash, // No validation of the hash
        GammaOrderLib.PERMIT2_ORDER_TYPE, // Constant value, but not validated
        order.sig // No validation of the signature
    );
}
```
## Proof of Concept
let's assume that the `order.toPermit()` function returns a `PermitTransferFrom` struct with the following fields:
```solidity
struct PermitTransferFrom {
    TokenPermissions permitted;
    uint256 nonce;
    uint256 deadline;
}

struct TokenPermissions {
    address token;
    uint256 amount;
}
```
An attacker could potentially craft a malicious `order` with the following values
```solidity
ResolvedOrder memory maliciousOrder = ResolvedOrder({
    token: validTokenAddress, // A valid token address
    amount: maxUint256, // The maximum possible token amount
    info: OrderInfo({
        trader: victim, // The address of the victim
        nonce: 0,
        deadline: type(uint256).max
    }),
    hash: bytes32(0), // An arbitrary hash value
    sig: validSignature // A valid signature for the malicious order
});
```
By passing this malicious order to the `_verifyOrder` function, the `_permit2.permitWitnessTransferFrom` function would be called with the following parameters
```solidity
_permit2.permitWitnessTransferFrom(
    PermitTransferFrom({
        permitted: TokenPermissions({
            token: validTokenAddress,
            amount: maxUint256
        }),
        nonce: 0,
        deadline: type(uint256).max
    }),
    SignatureTransferDetails({
        to: address(this),
        requestedAmount: maxUint256
    }),
    victim, // The victim's address as the token owner
    bytes32(0), // An arbitrary hash value
    GammaOrderLib.PERMIT2_ORDER_TYPE,
    validSignature // A valid signature for the malicious order
);
```
If the `permitWitnessTransferFrom` function does not perform proper validation, it could transfer the maximum possible token amount from the victim's address to the contract address `(address(this))`, resulting in an unauthorized token transfer.

## Recommended Mitigation Steps
The `_verifyOrder` function should validate all the parameters passed to the `_permit2.permitWitnessTransferFrom` by adding additional checks and validations within the `_verifyOrder` function or by creating separate functions to validate each parameter.
