# Vulnerability details

## Impact
The [ApplyInterestForToken](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ApplyInterestLib.sol#L26) function of the `ApplyInterestLib` calculates and add  interest whenever there  is an interaction of either `Supply` or `withdraw` and other functionalities.

As per the natspec, interest rate should not be applied more than once in a single block:
```
 function applyInterestForToken(mapping(uint256 => DataType.PairStatus) storage pairs, uint256 pairId) internal {
        DataType.PairStatus storage pairStatus = pairs[pairId];

        Perp.updateFeeAndPremiumGrowth(pairId, pairStatus.sqrtAssetStatus);

        // avoid applying interest rate multiple times in the same block
        if (pairStatus.lastUpdateTimestamp >= block.timestamp) {
            return;
        }
```
 and if that happens, the function will just return without calculating or adding the interest rate.

what can go wrong here? well the issue is that the check isn't sufficient to prevent incurring the interest rate more than once in a single block, this is due to where the contracts/protocol will be deployed.

As per the readMe, the protocol will be deployed on L2 networks like `Base`, `OP` and `Arbitrum`

This would work normal on `Arbitrum` as its block seconds is just `0.2` secs, but for the likes of `Base` and `OP`, the block seconds is `2` seconds, this means the check here:
```
if (pairStatus.lastUpdateTimestamp >= block.timestamp) {
            return;
        }
```
 is not sufficient as this checks whether the `last` update is more than or equal to the `block.timestamp`.

see: https://chainspect.app/compare/arbitrum-vs-base

Consider when there are two transactions in one block, the first one gets executed in the `first` seconds of the block and the `second` in the final seconds of the block, the second will also return false as that one second is more than the `lastUpdateTimestamp`, in this case the interest  rate gets incurred / calculated twice in the same block. This breaks the idea of incurring more than once in a single block.

## Proof of Concept
```
function applyInterestForToken(mapping(uint256 => DataType.PairStatus) storage pairs, uint256 pairId) internal {
        DataType.PairStatus storage pairStatus = pairs[pairId];

        Perp.updateFeeAndPremiumGrowth(pairId, pairStatus.sqrtAssetStatus);

        // avoid applying interest rate multiple times in the same block
        if (pairStatus.lastUpdateTimestamp >= block.timestamp) {
            return;
        }

        (uint256 interestRateQuote, uint256 protocolFeeQuote) =
            applyInterestForPoolStatus(pairStatus.quotePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

        (uint256 interestRateBase, uint256 protocolFeeBase) =
            applyInterestForPoolStatus(pairStatus.basePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

        // Update last update timestamp
        pairStatus.lastUpdateTimestamp = block.timestamp;

        if (interestRateQuote > 0 || interestRateBase > 0) {
            emitInterestGrowthEvent(pairStatus, interestRateQuote, interestRateBase, protocolFeeQuote, protocolFeeBase);
        }
    }
```

## Recommended Mitigation Steps

Since the protocol is to be deployed on all L2s, adding + `1 sec` after the check will solve the problem.

something like:
```
 // avoid applying interest rate multiple times in the same block
        if (pairStatus.lastUpdateTimestamp >= block.timestamp + 1 seconds) {
            return;
        }
```
