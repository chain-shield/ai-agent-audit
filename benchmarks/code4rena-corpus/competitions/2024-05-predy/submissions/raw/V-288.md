# Vulnerability details

Because the pools will be permissionless any token can be used as the quote or base. Some tokens do not allow zero value transfers and will revert if attempted to do so. In most every case throughout the protocol there are checks to ensure zero value transfers do not occur. 

However `_verifyOrder` is called where permit is used to transfer funds to the protocol. It is important to note that `_verifyOrder` is called without and check as to what amount ought to be transferred. 

```
uint256 cost = 0;

 if (marginAmountUpdate > 0) {
     cost = uint256(marginAmountUpdate);
}

_verifyOrderV3(callbackData.resolvedOrder, cost);

```

As you can see here if the `marginAmountUpdate` less than or equal to zero `_verifyOrderV3` will try and call `permitWitnessTransferFrom` with a value of 0. For certain ERC20 tokens this will lead to a revert. 

## Impact
Users of certain pools will not be able to close their position as the `marginAmountUpdate` will not be greater than 0 and the `permitWitnessTransferFrom` will lead to a revert. 

## Proof of Concept
Alice creates a long position where the quote token is the token that reverts on zero value transfers. 

Alice long position is in profit and Alice decides to close her position

`marginAmountUpdate` is not greater than 0 so `cost` remains 0. 

`permitWitnessTransferFrom` is called and 0 of the quote token is attempted to be transferred.

The transfer fails due to the value being 0. 

Alice cannot close her position.  

 
## Tools Used

Manual analysis 

## Recommended Mitigation Steps

Check that `cost` is greater than zero before calling `_verifyOrderV3`.
