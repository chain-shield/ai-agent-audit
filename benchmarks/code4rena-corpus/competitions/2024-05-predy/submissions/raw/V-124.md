# Vulnerability details


## Proof of Concept

Whenever there is an attempt to liquidate a vault via `LiquidationLogic#liquidate()` there is always a query to to before checking if the movement is within the slippage tolerance to ensure the liquidator doesn't make too much profit, i.e https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L75-L86

```solidity
        (tradeResult.minMargin,, hasPosition,) =
            PositionCalculator.calculateMinMargin(pairStatus, vault, DataType.FeeAmount(0, 0));

        // Check if the price is within the slippage tolerance range to ensure that the price does not become
        // excessively favorable to the liquidator.
        SlippageLib.checkPrice(
            sqrtOraclePrice,
            tradeResult,
            slippageTolerance,
            tradeParams.tradeAmountSqrt == 0 ? 0 : _MAX_ACCEPTABLE_SQRT_PRICE_RANGE
        );

```

Now going to the implementation of `PositionCalculator.calculateMinMargin` here https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/PositionCalculator.sol#L74-L101

```solidity

    function calculateMinMargin(
        DataType.PairStatus memory pairStatus,
        DataType.Vault memory vault,
        DataType.FeeAmount memory feeAmount
    ) internal view returns (int256 minMargin, int256 vaultValue, bool hasPosition, uint256 sqrtOraclePrice) {
        int256 minValue;
        uint256 debtValue;

        sqrtOraclePrice = getSqrtIndexPrice(pairStatus);

        (minValue, vaultValue, debtValue, hasPosition) = calculateMinValue(
            vault.margin,
            getPositionWithFeeAmount(vault.openPosition, feeAmount),
            sqrtOraclePrice,
            pairStatus.riskParams.riskRatio
        );

        int256 minMinValue =
            (calculateRequiredCollateralWithDebt(pairStatus.riskParams.debtRiskRatio) * debtValue).toInt256() / 1e6;
    //@audit
        minMargin = vaultValue - minValue + minMinValue;

        if (hasPosition && minMargin < Constants.MIN_MARGIN_AMOUNT) {
            minMargin = Constants.MIN_MARGIN_AMOUNT;
        }
    }

```

We can see that this implementation is susceptible to an underflow due to this operation `        minMargin = vaultValue - minValue + minMinValue;`, i.e in a case where `vaultValue + minMinValue` > `minValue` but, `vaultValue` < `minValue` the execution wrongly reverts, which then bubbles back up to our attempt at liquidating the vault which also reverts.

## Impact

DOS to valid attempts at liquidating vaults that are in danger, which showcases how protocol's core functionality is broken.

## Recommended Mitigation Steps

Consider reimplementing the pattern the mathematical operations are being queried.
