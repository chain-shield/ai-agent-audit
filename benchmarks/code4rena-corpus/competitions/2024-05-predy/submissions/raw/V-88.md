# Vulnerability details

## Impact
The `ratio()` function in `PerpMarketLib` is designed to calculate the percentage difference between two prices, scaled by a constant `Bps.ONE`. 
However, the issue here lies in the inconsistency of the `denominator` used when `price1` is less than `price2`.

This yields an incorrect value. 

## Proof of Concept
Here is the [ratio()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L178-L186) function:
```solidity
function ratio(uint256 price1, uint256 price2) internal pure returns (uint256) {
    if (price1 == price2) {
        return 0;
    } else if (price1 > price2) {
        return (price1 - price2) * Bps.ONE / price2;
    } else {
        return (price2 - price1) * Bps.ONE / price2;
    }
}
```
When `price1 < price2`, the function uses `price2` as the `denominator`. 
```solidity
        } else {
            return (price2 - price1) * Bps.ONE / price2;
        }
```
This is inconsistent with the case where `price1 > price2`, which uses `price2` as the `denominator`.

#### Breakdown
With the current implementation:

1. `if (price1 > price2)`
Here, ratio = `(price1 - price2) * Bps.ONE / price2;`
Example: Let price1 = 10e6, price2 = 5e6, Bps.ONE = 1e6
Then:
```solidity
ratio = (10e6 - 5e6) * 1e6 / 5e6 = 1e6
```

2. `if (price2 > price1)`
Here, ratio = `(price2 - price1) * Bps.ONE / price2;`
Example: Let price2 = 10e6, price1 = 5e6, Bps.ONE = 1e6
Then:
```solidity
ratio = (10e6 - 5e6) * 1e6 / 10e6 = 5e5
```
The `ratio` calculated in the first instance is`1e6` but the second case yields `5e5`. This is incorrect since the wrong `denominator` is used here i.e (`price2`).

The `ratio()` function is then used in [validateStopPrice()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L147-L153) to calculate `decayedSlippageTorelance`:
```solidity
        uint256 decayedSlippageTorelance = DecayLib.decay2(
            auctionParams.startPrice,
            auctionParams.endPrice,
            auctionParams.startTime,
            auctionParams.endTime,
  @>        ratio(oraclePrice, stopPrice) // @audit-issue ratio used here
        );
``` 
From this, the whole calculation will be flawed.

## Recommended Mitigation Steps
The `denominator` in the `else` block should be `price1` instead of `price2` to maintain a consistent approach to calculating the `ratio`.
```diff
        } else {
-           return (price2 - price1) * Bps.ONE / price2;
+           return (price2 - price1) * Bps.ONE / price1;
        }
```

i.e 
`if (price2 > price1)`
Here, ratio should be: `(price2 - price1) * Bps.ONE / price1;`
Example: Let price2 = 10e6, price1 = 5e6, Bps.ONE = 1e6
Then:
```solidity
ratio = (10e6 - 5e6) * 1e6 / 5e6 = 1e6
```
The `ratio` returned is now consistent in both cases.
