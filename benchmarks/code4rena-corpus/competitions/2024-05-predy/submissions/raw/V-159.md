# Vulnerability details

## Impact
The supply interest rate is used to calculate the interest earned by users who supply assets to the protocol. An incorrect calculation of the supply interest rate can lead to users being under-rewarded or over-rewarded for their supplied assets, resulting in a loss or gain of funds for the protocol or users.

`ScaledAsset:updateScaler` the calculation for `supplyInterestRate` is as follows: [#L201-L207](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/ScaledAsset.sol#L201-L207)
```solidity
uint256 supplyInterestRate = FixedPointMathLib.mulDivDown(
    FixedPointMathLib.mulDivDown(
        _interestRate, getTotalDebtValue(tokenState), getTotalCollateralValue(tokenState)
    ),
    100 - _reserveFactor,
    100
);
```
The intended formula for calculating the supply interest rate should be.
```solidity
supplyInterestRate = interestRate * (1 - reserveFactor) * utilization
```
Where `utilization` is the ratio of `getTotalDebtValue(tokenState)` to `getTotalCollateralValue(tokenState)`.

However, in the code, the calculation is.
```solidity
supplyInterestRate = interestRate * utilization * (100 - reserveFactor) / 100
```
This means that the `(100 - _reserveFactor)` term is being multiplied instead of being used as a factor to subtract from 1.

## Proof of Concept
Suppose we have the following values.

`_interestRate` = 0.1 (10%)
`_reserveFactor` = 10 (10%)
`getTotalDebtValue(tokenState)` = 1000
`getTotalCollateralValue(tokenState)` = 2000

The intended calculation for `supplyInterestRate` should be.
```solidity
utilization = getTotalDebtValue(tokenState) / getTotalCollateralValue(tokenState)
           = 1000 / 2000
           = 0.5

supplyInterestRate = _interestRate * (1 - _reserveFactor) * utilization
                   = 0.1 * (1 - 0.1) * 0.5
                   = 0.045 (4.5%)
```
However, the current implementation calculates `supplyInterestRate` as.
```solidity
supplyInterestRate = FixedPointMathLib.mulDivDown(
                         FixedPointMathLib.mulDivDown(_interestRate, getTotalDebtValue(tokenState), getTotalCollateralValue(tokenState)),
                         100 - _reserveFactor,
                         100
                     )
                   = FixedPointMathLib.mulDivDown(
                         FixedPointMathLib.mulDivDown(0.1, 1000, 2000),
                         90,
                         100
                     )
                   = FixedPointMathLib.mulDivDown(0.05, 90, 100)
                   = 0.045 (4.5%)
```
While the result is the same in this example, the calculation is incorrect and can lead to different results depending on the input values.

## Recommended Mitigation Steps
the calculation should be modified as follows
```solidity
uint256 utilization = FixedPointMathLib.mulDivDown(
    getTotalDebtValue(tokenState),
    Constants.ONE,
    getTotalCollateralValue(tokenState)
);

uint256 supplyInterestRate = FixedPointMathLib.mulDivDown(
    FixedPointMathLib.mulDivDown(_interestRate, utilization, Constants.ONE),
    Constants.ONE - _reserveFactor,
    Constants.ONE
);
```
This way, the `utilization` is calculated correctly, and the `(1 - reserveFactor)` term is applied correctly to the `interestRate * utilization` product.
