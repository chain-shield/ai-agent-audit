# Vulnerability details

## Impact
Break of Protocol Functionality due to Deflation in Premium Curve Value as a result of Math Error in Implementation in PremiumCurveModel contract
## Proof of Concept
```solidity

>>>     * 1.6 * (UR-0.1)^2 {0.1 < ur}
     * @param utilization utilization ratio scaled by 1e18

        if (utilization <= Constants.SQUART_KINK_UR) {
            return 0;
        }

        uint256 b = (utilization - Constants.SQUART_KINK_UR);

>>>        return (1600 * b * b / Constants.ONE) / Constants.ONE;
    }
```
The code provided above shows how PremiumCurve is calculated in the PremiumCurveModel.sol contract, as can be noted from the first pointer above a breakdown of how the implementation should proceed can be noted, i.e **1.6 * (UR-0.1)^2** when utilization is greater than Constants.SQUART_KINK_UR. The problem is that instead of simply implementing (UR-0.1)^2 the protocol divide by 1e18 i.e Constants.ONE which was not noted in the comment description and would lead to excessive deflation of the PremiumCurve value that should be returned by 1e36
