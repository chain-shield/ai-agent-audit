# Vulnerability details

## Impact
In the `Perp.SqrtPerpAssetStatus` struct, the [lastRebalanceTotalSquartAmount](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L85) field is defined as a `uint256`. This field is used to store the total amount of positions that will have to pay rebalancing interest in the future. Since it is a `uint256`, it cannot represent negative values.

If the `totalAmount` and `borrowedAmount` fields are both negative (which is theoretically possible with the `int256` type), their sum could result in a negative value. In this case, assigning this negative value to `lastRebalanceTotalSquartAmount` (which is a `uint256`) would cause an underflow and lead to unexpected behavior or vulnerabilities.

## Proof of Concept
The `totalAmount` and `borrowedAmount` fields are defined as `uint256`, which can only represent non-negative values, these fields are used to track the total amount of positions and the total amount of borrowed positions, respectively. [Perp.#L78-L89](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L78-L89)
```solidity
struct SqrtPerpAssetStatus {
    // ...
    uint256 totalAmount;
    uint256 borrowedAmount;
    // ...
}
```
The `lastRebalanceTotalSquartAmount` field is used to store the sum of `totalAmount` and `borrowedAmount`, which represents the total amount of positions that will have to pay rebalancing interest in the future. This value is calculated and updated in the [Perp.finalizeReallocation](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L815-L819)
```solidity
function finalizeReallocation(SqrtPerpAssetStatus storage sqrtPerpStatus) internal {
    sqrtPerpStatus.lastRebalanceTotalSquartAmount = sqrtPerpStatus.totalAmount + sqrtPerpStatus.borrowedAmount;
    sqrtPerpStatus.numRebalance++;
}
```
If both `totalAmount` and `borrowedAmount` are negative values (which is possible since they are `int256` types), their sum could result in a negative value, since `lastRebalanceTotalSquartAmount` is defined as a `uint256`, assigning a negative value to it would cause an underflow.

An underflow in this context could lead to unexpected behavior or potential vulnerabilities. For example, if the underflowed value is used in calculations or comparisons, it could result in incorrect results or unintended logic execution.

**`Consider the following scenario`**

Assume `totalAmount` is `-100` (represented as an `int256`).
Assume `borrowedAmount` is `-200` (represented as an int256).
The sum of `totalAmount` and `borrowedAmount` would be `-300` (represented as an `int256`).
When assigning this value to `lastRebalanceTotalSquartAmount` (which is a `uint256`), an underflow would occur, and the value would become `2^256 - 300` (a very large positive number).

This unexpected value could then be used in other parts of the system, leading to incorrect calculations, incorrect state updates, or other unintended consequences.
