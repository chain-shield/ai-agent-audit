# Vulnerability details

## Impact
In case if `int24(tickCumulatives[1] - tickCumulatives[0])` is negative and `((tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0`, then returned tick will be bigger than it should be which places protocol wanting prices to be right not be able to achieve this goal, this will also hamper important functions like liquidations, 

```solidity
(uint256 sqrtOraclePrice, uint256 slippageTolerance) =
            checkVaultIsDanger(pairStatus, vault, globalData.rebalanceFeeGrowthCache);
```
`Liquidation` function is getting the price `sqrtOraclePrice` from the `checkVaultIsDanger` function , which further calls `isLiquidatable` to check for the validity of the price and is the position liquidatable , which gets the `sqrtOraclePrice` from the `calculateMinMargin` 

```solidity
(minMargin, vaultValue, hasPosition, sqrtOraclePrice) = calculateMinMargin(pairStatus, _vault, feeAmount);
```

now lastly `calculateMinMargin` fetches the `sqrtOraclePrice` from the `getSqrtIndexPrice` function which is given below :


```solidity
function getSqrtIndexPrice(DataType.PairStatus memory pairStatus) internal view returns (uint256 sqrtPriceX96) {
        if (pairStatus.priceFeed != address(0)) {
            return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
        } else {
            return UniHelper.convertSqrtPrice(
                UniHelper.getSqrtTWAP(pairStatus.sqrtAssetStatus.uniswapPool), pairStatus.isQuoteZero
            );
        }
    }

```

The above function is dependent on `Unihelper.convertSqrtPrice()` function which will return wrong prices and will not let positions liquidate.

Also the `convertSqrtPrice` function is dependent on `slot0` as well as TWAP and both are wrong in this case so liquidation will surely suffer

## Proof of Concept
```solidity
 function callUniswapObserve(IUniswapV3Pool uniswapPool, uint256 ago) internal view returns (uint160, uint256) {
        uint32[] memory secondsAgos = new uint32[](2);

        secondsAgos[0] = uint32(ago);
        secondsAgos[1] = 0;
            (,, uint16 index, uint16 cardinality,,,) = uniswapPool.slot0();

            (uint32 oldestAvailableAge,,, bool initialized) = uniswapPool.observations((index + 1) % cardinality);
        int56[] memory tickCumulatives = abi.decode(data, (int56[]));
        int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));//@audit no rounding up is done if the ticks are negative
        uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(tick);
        return (sqrtPriceX96, ago);
    }
```


The above function in `Unihelper.sol`  is  used to calculate the reference pool price, It uses either the latest slot price or TWAP based on twapSeconds.

The problem is that in case if `int24(tickCumulatives[1] - tickCumulatives[0]) `is negative, then the tick should be rounded down as it's done in the [uniswap library](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L36).

As result, in case if `int24(tickCumulatives[1] - tickCumulatives[0])` is negative and `(tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0`, then returned tick will be bigger then it should be, which opens possibility for some price manipulations and arbitrage opportunities.
