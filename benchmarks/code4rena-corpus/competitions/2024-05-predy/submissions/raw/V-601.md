# Vulnerability details

## Impact
As anybody can create pool, malicious pool owners can prevent existing traders from adjusting or closing their positions, making them prone to liquidations.

## Proof of Concept
There was an update regarding trusted roles - https://discord.com/channels/810916927919620096/1242872233345679501/1245440813144477707

>In the All trusted roles in the protocol chart, the sponsor would like to also note that 

>In the future, it is expected that anyone will be able to add pairs.

This implies that not just the operator but any user can add a pair in `PredyPool`.  Since anybody can add a pair, the role cannot be trusted then.

```solidity
    function registerPair(AddPairLogic.AddPairParams memory addPairParam) external onlyOperator returns (uint256) {
        return AddPairLogic.addPair(globalData, allowedUniswapPools, addPairParam);
    }
```

If anybody can add a pair, that implies anybody can set the `poolOwner`:

```solidity
    function _storePairStatus(
        address quoteToken,
        mapping(uint256 => DataType.PairStatus) storage _pairs,
        uint256 _pairId,
        address _tokenAddress,
        bool _isQuoteZero,
        AddPairParams memory _addPairParam
    ) internal {
        validateRiskParams(_addPairParam.assetRiskParams);
        validateFeeRatio(_addPairParam.fee);

        require(_pairs[_pairId].id == 0, "AAA");

        _pairs[_pairId] = DataType.PairStatus(
            _pairId,
            quoteToken,
            _addPairParam.poolOwner, //@audit
            Perp.AssetPoolStatus(
                quoteToken,
                deploySupplyToken(quoteToken),
                ScaledAsset.createAssetStatus(),
                _addPairParam.quoteIrmParams,
                0,
                0
            ),
```

Note: `_storePairStatus` is called when `registerPair` is called.

That implies that anybody can become a `poolOwner`. The `poolOwner` has certain privileges:

```solidity
    function allowTrader(uint256 pairId, address trader, bool enabled) external onlyPoolOwner(pairId) {
        require(globalData.pairs[pairId].allowlistEnabled);

        allowedTraders[trader][pairId] = enabled;
    }
```

Let's assume that the `poolOwner` has initially allowed some traders to interact with the `PredyPool` contract and open positions by calling the `trade` function:

```solidity
    function trade(TradeParams memory tradeParams, bytes memory settlementData)
        external
        nonReentrant
        returns (TradeResult memory tradeResult)
    {
        globalData.validate(tradeParams.pairId);

        if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
            revert TraderNotAllowed();
        }

        tradeParams.vaultId = globalData.createOrGetVault(tradeParams.vaultId, tradeParams.pairId);

        return TradeLogic.trade(globalData, tradeParams, settlementData);
    }
```
This check initially passes as the poolOwner has allowed the traders to open positions:

```solidity
        if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
            revert TraderNotAllowed();
        }
```

Now, traders open their positions. After they are opened, the pool owner (who has malicious intent), calls the `allowTrader` function and disables the traders. So, the existing traders will not be able to trade anymore. They will not be able to close or adjust their positions. This makes their positions prone to liquidation. The malicious pool owner can liquidate their positions himself, as this check isn't present in liquidation functions:

```solidity
        if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
            revert TraderNotAllowed();
        }
```

Hence, it's possible to liquidate positions while users have no chance to adjust their positions.

## Tools Used
Manual review

## Recommended Mitigation Steps
Ensure that liquidations also have this check or similar checks that restrict liquidation in such situations:

```solidity
        if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
            revert TraderNotAllowed();
        }
```

So, even if users cannot trade anymore, their positions cannot get liquidated.
