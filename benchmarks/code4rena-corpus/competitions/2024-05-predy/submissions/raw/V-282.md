# Vulnerability details

Pools can become undercollateralized because unearned yield is prematurely counted upon withdrawals.

```
    function getTotalCollateralValue(AssetStatus memory tokenState) internal pure returns (uint256) {
        return FixedPointMathLib.mulDivDown(tokenState.totalCompoundDeposited, tokenState.assetScaler, Constants.ONE)
            + tokenState.totalNormalDeposited;
    }
```

This is the function used to determine the collateral value, which is then used to determine the amount lenders can withdraw.

```
    function getAvailableCollateralValue(AssetStatus memory tokenState) internal pure returns (uint256) {
        return getTotalCollateralValue(tokenState) - getTotalDebtValue(tokenState);
    }
```

The collateral value is a combination of `totalCompoundDeposited` scaled by the current `assetScaler` and the `totalNormalDeposited`. The issue is in the first part of this calculation: when `totalCompoundDeposited` is scaled by the current `assetScaler`, it is being scaled in part by unpaid borrowing fees. This means that the collateral value is being inflated by funds that don't yet exist in the pool. With collateral value being inflated, the amount available for withdrawal is also inflated, leading to a situation where there are not enough funds in the pool for the positions to be fully collateralized.

The longer the perpetual positions are held, the more borrowing fees will accrue, and the more the pools will overestimate what can be withdrawn, putting the pool in an unhealthy state.

In addition to having an undercollateralized pool, counting unearned yield towards collateral value will lead to a suppressed utilization ratio, resulting in fewer borrowing fees being collected. This punishes lenders as they are getting less yield relative to the percentage of their funds that is being lent. Calculating the utilization is based on debt/collateralValue. The larger the collateralValue (denominator) is, the smaller the utilization will become. Accounting for unearned yield when determining the utilization leads to a loss of yield for all users.

## Proof of Concept


- Alice opens a pool with the quote and base being WETH<>USDC and supplies 100k USD of both quote and base.
- Bob opens an identical pool.
- Charlie borrows ~100k USD of WETH for a 5x position.
- After 3 weeks, the price of WETH has moved up enough to keep Charlie's position healthy despite the fees. Currently, Charlie owes 100k in fees.
- **NOTE:** At this point, the utilization is only 50% even though all available funds are being used up, suppressing the amount of yield lenders should be getting.
- Alice decides to withdraw 100k. Since that amount of fees is being prematurely counted towards the collateral value, this will work.

At this point, the pool has no more ETH, yet Charlie has a long position that far exceeds the balance of the pool, meaning the pool is undercollateralized.

Manual analysis.
## Recommended Mitigation Steps
When `supply` is called, track the actual token amount that was deposited (be sure to reduce this amount upon withdrawals). Then when determining how much is available from deposits in the `getTotalCollateralValue` function, use `totalTokenAmount` instead of scaled `totalCompoundDeposited`.
