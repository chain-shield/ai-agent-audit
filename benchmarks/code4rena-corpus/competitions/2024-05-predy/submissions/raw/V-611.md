# Vulnerability details

## Impact
The `getSqrtPrice` function in the `PriceFeed` contract lacks checks for minimum and maximum values of the `quoteAnswer`. This can lead to incorrect calculations if extreme values are returned by the `AggregatorV3Interface`. Additionally, there is no circuit breaker mechanism to halt operations when handling invalid or unreliable price feed data.

## Proof of Concept
The `getSqrtPrice` function calculates the square root of the base token price quoted in the quote token.

```solidity
    function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();


        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);


        require(basePrice.expo == -8, "INVALID_EXP");


        require(quoteAnswer > 0 && basePrice.price > 0);


        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;


        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```

Without `minAnswer` and `maxAnswer` checks, the contract may process extreme values, leading to incorrect square root price calculations. These inaccuracies can lead to significant financial discrepancies and potential losses for users.

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement checks for `minAnswer` and `maxAnswer` ranges and a circuit breaker mechanism to handle invalid or unreliable price feed data. This ensures that only reliable and valid price feed data is used and the contract will operate within safe parameters and can be paused in case of abnormal conditions.
