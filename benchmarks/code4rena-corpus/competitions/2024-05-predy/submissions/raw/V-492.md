# Vulnerability details

## Impact
Users can execute trades via the `Perp Market` or `Gamma Market`, where `quote token` can be traded for `base token` and vice versa.

Pairs can have the following tokens for `quote token` and `base token`: `WETH, USDC, ARB, USDT, DAI, WBTC`

When finalizing trades, the protocol utilizes `permitWitnessTransferFrom`, which is described by [Uniswap docs](https://docs.uniswap.org/contracts/permit2/reference/signature-transfer#:~:text=Use%20permitWitnessTransferFrom%20when%20you%20want%20to%20transfer%20a%20token%20from%20an%20owner%20through%20signature%20validation%2C%20but%20you%20would%20also%20like%20to%20validate%20other%20data.%20Any%20other%20data%20you%20wish%20to%20be%20validated%20can%20be%20passed%20through%20with%20the%20witness%20param.) as the following: `"Use permitWitnessTransferFrom when you want to transfer a token from an owner through signature validation, but you would also like to validate other data. Any other data you wish to be validated can be passed through with the witness param."`

The problem is that there is no validation of the receiving token, an attacker can send an ERC20 token that is worth less than the one they are trading for, causing a loss for pool lenders.

## Proof of Concept
This issue applies to both markets. Let's look at `Perp Market`

The trade callback validates the order:

[PerpMarketV1.sol#L123](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/perp/PerpMarketV1.sol#L123)
```javascript
_verifyOrderV3(callbackData.resolvedOrder, cost);
```

[PerpMarketV1.sol#L327-L338](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/perp/PerpMarketV1.sol#L327-L338)
```javascript
    function _verifyOrderV3(ResolvedOrder memory order, uint256 amount) internal {
@>      order.validate();

        _permit2.permitWitnessTransferFrom(
            order.toPermit(),
            ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: amount}),
            order.info.trader,
            order.hash,
            PerpOrderV3Lib.PERMIT2_ORDER_TYPE,
            order.sig
        );
    }
```

[ResolvedOrder.sol#L23-L31](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/orders/ResolvedOrder.sol#L23-L31)
```javascript
    function validate(ResolvedOrder memory resolvedOrder) internal view {
        if (address(this) != address(resolvedOrder.info.market)) {
            revert InvalidMarket();
        }

        if (block.timestamp > resolvedOrder.info.deadline) {
            revert DeadlinePassed();
        }
    }
```

However, when validating the order, there is no validation that the `resolvedOrder.token` matches the token that is being traded.

A user can send a token that is worth less than the token they are trading for, causing a loss of funds for the protocol and pool lenders.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Verify that the `order.token` is the actual token they are trading for. (i.e, if trading quote token `require(order.token == quoteToken, "Invalid token")`)
