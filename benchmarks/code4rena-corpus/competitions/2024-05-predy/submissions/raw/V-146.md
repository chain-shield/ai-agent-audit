# Vulnerability details

## Impact
The liquidation Lib handles the liquidation of positions that meet the liquidations threshold, the [ExecLiquidationCall](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L313) is where the call is being made to the [liquidate](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39) function in the library, here is the implementation of it:
```solidity
/**
     * @notice Executes a liquidation call to close an unsafe vault.
     * @param vaultId The identifier of the vault to be liquidated.
     * @param closeRatio The ratio at which the position will be closed.
     * @param settlementData SettlementData struct for trade settlement.
     * @return tradeResult TradeResult struct with the result of the liquidation.
     */
    function execLiquidationCall(uint256 vaultId, uint256 closeRatio, bytes memory settlementData)
        external
        nonReentrant
        returns (TradeResult memory tradeResult)
    {
        return LiquidationLogic.liquidate(vaultId, closeRatio, globalData, settlementData);
    }
```
the liquidator earns profit from the differences in the liquidation process as per the docs:

>When a trader's position meets the conditions for liquidation, the Liquidator forcibly closes the position. Liquidators can earn profits from the differences in the liquidation process.

The issue here is that during the liquidation and when the `vault` has a positive margin, the excess margin is sent to the `recipient` (specified by the vault Owner), but when there is a negative value, the liquidator is required to fill the deficit and transfer the remaining amount to the contract:
```solidity
// To prevent the liquidator from unfairly profiting through arbitrage trades in the AMM and passing losses onto the protocol,
                // any losses that cannot be covered by the vault must be compensated by the liquidator
                ERC20(pairStatus.quotePool.token).safeTransferFrom(msg.sender, address(this), uint256(-remainingMargin));
```
what can go wrong here? well instead of incentivizing  the `liquidator` , he is now required to send or fund the deficit in the vault, this would discourage the liquidation process and make it a  complete useless as many would rather choose to to leave than to make up the deficit, This will leave the vault Unliquidated at all
