# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L604-L617

```solidity
    function getUtilizationRatio(SqrtPerpAssetStatus memory _assetStatus) internal pure returns (uint256) {
        if (_assetStatus.totalAmount == 0) {
            return 0;
        }

        uint256 utilization = _assetStatus.borrowedAmount * Constants.ONE / _assetStatus.totalAmount;

        if (utilization > 1e18) {
            return 1e18;
        }

        return utilization;
    }

```

This function is used to get the current utilization ratio, note that it is always called updating the fee and the premium growth via `Perp#updateFeeAndPremiumGrowth()` as seen here: https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L394. And the `Perp#updateFeeAndPremiumGrowth()` is always used when applying interest for a token via `ApplyInterestLib#applyInterestForToken()` as seen here: https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ApplyInterestLib.sol#L29, note that as documented and as executed by code each time a user interacts with the contract, interest and premium from the previous interaction to the current one are applied via `ApplyInterestLib#applyInterestForToken()` , so this increases the amount available for withdrawal by the lender and the premium income for Squart... this has been clearly [documented](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ApplyInterestLib.sol#L23-L24) and we can confirm this by using this search command to see how much of importance the function is used in the Logic contracts: [https://github.com/search?q=repo%3Acode-423n4%2F2024-05-predy+applyInterestForToken+path%3A%2F%5Esrc%5C%2Flibraries%5C%2Flogic%5C%2F%2F&type=code](https://github.com/search?q=repo%3Acode-423n4%2F2024-05-predy+applyInterestForToken+path%3A%2F%5Esrc%5C%2Flibraries%5C%2Flogic%5C%2F%2F&type=code).

Issue with the `getUtilizationRatio()` however is the fact that protocol wrongly assumes that when `assets = 0` the utilization ratio should also be `0` instead of it being the maximum in this case `1e18`. A short math logic as to why this is problematic is when we consider that generally, utilization ratio is `borrows / assets` an indetermination if both are `0` since it equates to `0/0`. So mathematically, when `assets == 0,` this equates to `borrows / 0`, And it goes to` infinity (1)` if `borrows != 0`. If `borrows == 0`, it's` 0/0`, which should also go to `1` to protect the protocol considering this is an indetermination we should always use a utilization ratio that protects and favors protocol over users which in this case would be `1`, because using 0 would favor borrowers and give the risk to protocol, cause as long as assets are 0, there may be debt, but the utilization rate will always be 0, so users may now take any loan, as big as they want, for the lowest fee, while getting the protocol closer to insolvency.

That's to say, due to [the current logic](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L606) of having the utilization ratio as `0` when assets are `0` for the protocol it then easily allows borrowers to game their integrations within protocol. A borrow could then be taken with the lowest interest rate possible due to the utilization being 0 when the assets are 0, this borrow would obviously then protocol at quite an unwanted/risky state, considering it was placed with a very minimal interest rate contrary to having it be with highest possible interest rate if the utilization ratio was `1` instead. Technically, in this case we should have it in mind that this must not be done in the first deposit, as throughout the lifetime of protocol the assets could be `0` at any time.

## Impact

Assuming `assets == 0` means `0` utilization rate is wrong since it increases protocol's risk of insolvency and heavily favors borrowers instead of ensuring protocol is safe.

## Recommended Mitigation Steps

Consider having the interest rate be the maximum when assets are 0 this way we can always ensure protocol safety.
