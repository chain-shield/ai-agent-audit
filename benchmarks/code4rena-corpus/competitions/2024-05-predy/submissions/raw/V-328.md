# Vulnerability details

Report:

Title: Arithmetic Overflow and Underflow Vulnerability in the `trade` Function

Issue:
The `trade` function in the `PredyPool` contract suffers from an integer arithmetic overflow and underflow vulnerability when calculating the `_amountOwed` and `_amountToReceive` values. This can lead to security issues, unauthorized access to funds, and unpredictable contract behavior.

Impact:
If an attacker can exploit this vulnerability, they may be able to manipulate the contract's internal state, leading to potential governance attacks on the affected system. The manipulation could allow the attacker to gain unauthorized access to funds, affect the intended behavior of the contract and its dependent systems, and cause a severe security breach.

Proof of Concept:
Let's consider the following scenario:

1. An attacker creates a trade with a very large `_amountToReceive` value that, when subtracted from `_totalAmountOwed`, causes an arithmetic underflow. This can result in an extremely large `_amountOwed` value.
2. The contract calculates the `_amountOwed` incorrectly, allowing the attacker to manipulate the internal state of the contract.
3. The attacker can then exploit this vulnerability to gain unauthorized access to funds and cause unpredictable contract behavior.

Recommendation:
To prevent integer arithmetic overflows and underflows, update the `trade` function to perform proper arithmetic checks and handle such cases:

1. Use SafeMath library or equivalent solidity functions (e.g., `safeAdd`, `safeSub`) to ensure correct arithmetic operations.
2. Implement checks to ensure that the arithmetic operations do not result in overflows or underflows.

Example:

```solidity
import "https://github.com/OpenZeppelin/openzeppelin-solidity/contracts/math/SafeMath.sol";

contract PredyPool is IPredyPool, IUniswapV3MintCallback, Initializable, ReentrancyGuard {
    using SafeMath for uint256;

    function trade(...) external nonReentrant {
        // ...

        // Replace the following lines:
        // _amountOwed = _totalAmountOwed.sub(amountToReceive);
        // _amountToReceive = _amountToReceive.add(_amountOwed);

        // With the following lines:
        uint256 newTotalAmountOwed = _totalAmountOwed.sub(amountToReceive);
        require(newTotalAmountOwed >= 0, "Arithmetic underflow");
        _amountOwed = newTotalAmountOwed;

        _amountToReceive = amountToReceive.add(_amountOwed);

        // ...
    }
}
```

Implementing these changes will help prevent arithmetic overflows and underflows, ensuring the correct behavior of the contract and the secure handling of funds.
