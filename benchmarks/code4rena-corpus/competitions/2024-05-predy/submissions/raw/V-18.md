# Vulnerability details

## Description 
The uniswapV3MintCallback function in the PredyPool contract does not check the contract's token balances before attempting to transfer tokens to the Uniswap pool. This can lead to transaction failures if the contract does not have sufficient tokens to cover the transfer amounts (amount0 and amount1).
```
function uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata) external override {
    require(allowedUniswapPools[msg.sender]);

    IUniswapV3Pool uniswapPool = IUniswapV3Pool(msg.sender);

    if (amount0 > 0) {
        ERC20(uniswapPool.token0()).safeTransfer(msg.sender, amount0);
    }
    if (amount1 > 0) {
        ERC20(uniswapPool.token1()).safeTransfer(msg.sender, amount1);
    }
}
```

## Impact
1. If the contract does not have sufficient balance of token0 or token1, the safeTransfer call will fail, causing the entire uniswapV3MintCallback function to revert. This will halt the minting process initiated by the Uniswap pool.

2. Functions that rely on successful minting operations with Uniswap pools could be disrupted. For example, the supply and reallocate functions may fail if they involve minting operations.

3. Operational Disruption:
- Functions that rely on successful minting operations with Uniswap pools could be disrupted. For example, the supply and reallocate functions may fail if they involve minting operations.

- Users attempting to supply tokens or reallocate liquidity positions may experience failed transactions, leading to frustration and potential loss of trust in the contract's reliability.

- Frequent transaction failures could also lead to higher gas costs for users, as they would need to retry their transactions.

## Proof of Concept
Scenario:
- A user attempts to supply liquidity to the Uniswap pool via the supply function.
- The contract does not have sufficient balance of token0 or token1.

Outcome:
- The uniswapV3MintCallback function is called as part of the minting process.
- The safeTransfer call fails due to insufficient balance, causing the entire transaction to revert.
- The user receives a transaction failure, and the supply operation is not completed.

## Recommended Mitigation Steps
1. Add checks for the contract's balance of token0 and token1 before attempting the transfer in the uniswapV3MintCallback function.

2. Provide clear error messages or events to inform users about the reason for transaction failures, specifically indicating insufficient balances.

3. Implement mechanisms to ensure the contract maintains sufficient balances of token0 and token1. This could involve automated top-ups or alerts for low balances.

Here is the modified uniswapV3MintCallback function with balance checks:
```
function uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata) external override {
    require(allowedUniswapPools[msg.sender]);

    IUniswapV3Pool uniswapPool = IUniswapV3Pool(msg.sender);

    if (amount0 > 0) {
        require(ERC20(uniswapPool.token0()).balanceOf(address(this)) >= amount0, "Insufficient token0 balance");
        ERC20(uniswapPool.token0()).safeTransfer(msg.sender, amount0);
    }
    if (amount1 > 0) {
        require(ERC20(uniswapPool.token1()).balanceOf(address(this)) >= amount1, "Insufficient token1 balance");
        ERC20(uniswapPool.token1()).safeTransfer(msg.sender, amount1);
    }
}
```
