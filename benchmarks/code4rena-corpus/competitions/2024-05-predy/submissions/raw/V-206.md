# Vulnerability details

## Impact
Without  any `slippage control`, users may pay or receive `incorrect amounts` of tokens leading to financial losses if the `liquidity` addition/removal is done at a rate significantly different from the expected market price.

## Vulnerability Details
[mint()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/lib/v3-core/contracts/interfaces/pool/IUniswapV3PoolActions.sol#L23-L29) and [burn()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/lib/v3-core/contracts/interfaces/pool/IUniswapV3PoolActions.sol#L59-L63) are used to add/remove `liquidity`  for a given user.
```solidity
    /// @notice Burn liquidity from the sender and account tokens owed for the liquidity to the position
    function burn(
        int24 tickLower,
        int24 tickUpper, 
        uint128 amount
    ) external returns (uint256 amount0, uint256 amount1);

    /// @notice Adds liquidity for the given recipient/tickLower/tickUpper position
    function mint(
        address recipient,
        int24 tickLower,
        int24 tickUpper,
        uint128 amount,
        bytes calldata data
    ) external returns (uint256 amount0, uint256 amount1);
```
These functions are called within [increase()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L711-L713) and [decrease()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L727-L729) functions to calculate the `amount0` and `amount1` which represent the amount of `token0` and `token1` paid to mint the given amount of liquidity or sent to the `recipient` after liquidity removal.
```solidity
    function increase(SqrtPerpAssetStatus memory _assetStatus, uint256 _liquidityAmount)
        internal
        returns (int256 requiredAmount0, int256 requiredAmount1)
    {
        (uint256 amount0, uint256 amount1) = IUniswapV3Pool(_assetStatus.uniswapPool).mint(
            address(this), _assetStatus.tickLower, _assetStatus.tickUpper, _liquidityAmount.safeCastTo128(), ""
        );

        //...
    }
```
```solidity
    function decrease(SqrtPerpAssetStatus memory _assetStatus, uint256 _liquidityAmount)
        internal
        returns (int256 receivedAmount0, int256 receivedAmount1)
    {
        //...

        (uint256 amount0, uint256 amount1) = IUniswapV3Pool(_assetStatus.uniswapPool).burn(
            _assetStatus.tickLower, _assetStatus.tickUpper, _liquidityAmount.safeCastTo128()
        );

        //...
    }
```
The absence of `slippage control` means that the liquidity addition/removal could be subject to unfavorable exchange rates due to market volatility or manipulation resulting in the users providing excess tokens for little liquidity or receiving very few tokens, (`amount0` and `amount1`) that do not accurately represent the value of the removed liquidity.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement slippage control mechanism by defining maximum allowed slippage percentages. Include a check that revers if the actual rate of asset exchange falls outside the acceptable range.
