# Vulnerability details

## Impact
Every time, the pool owner updates the Interest Rate model for the pair, the 
accrued interest rate since the last Update Timestamp to the time of update should be computed and reflected on the accumulated protocol revenue and creator revenue, before the new Interest Rate model takes effect.

If the new rates are applied directly into the config/Global storage without considering the accrued interest rate, then new rates will apply from the last Update Timestamp which is not correct. The last update time stamp could vary pair to pair based on interactions with the pair.

## Proof of Concept
When pool Owner updates the interest rate model for quote and base pair based on the pair id, before the new rates are applied on to the global storage, the logic should first update the accrued interest rate based on old rates that contribute to the protocol and creator revenue.

The current implementation does not compute the accrued interest rate based on old model, meaning, the interest rates will be computed based on new rates from the last update when the update is called due to interaction with the pair.

The updates happens based on the interaction with the pair. This impacts the protocol and creator revenue calculated in positive or negative way based on the direction of interest rate model update.

The correct implementation should be to **apply the old rate until now** as a cut off until the point of update for reflecting the accrued values and let the new rates/model apply going forward.

The below function directly updates the interest rate model storage.
```
  function updateIRMParams(
        uint256 pairId,
        InterestRateModel.IRMParams memory quoteIrmParams,
        InterestRateModel.IRMParams memory baseIrmParams
    ) external onlyPoolOwner(pairId) {
        AddPairLogic.updateIRMParams(globalData.pairs[pairId], quoteIrmParams, baseIrmParams);
    }

```

## Tools Used

## Recommended Mitigation Steps
The recommendation is to call ApplyInterestLib::applyInterestForToken() for the pairId before updating the global storage. This will ensure the accruals are computed based on old interest rate/model.
