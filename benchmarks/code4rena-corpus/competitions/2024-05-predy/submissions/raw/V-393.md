# Vulnerability details

## Impact
Trader can avoid liquidations.

## Proof of Concept
The function [liquidate()](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/LiquidationLogic.sol#L39)

```solidity
 (uint256 sqrtOraclePrice, uint256 slippageTolerance) =
            checkVaultIsDanger(pairStatus, vault, globalData.rebalanceFeeGrowthCache);
```

checks if the vault is in danger and proceeds to liquidate the position
and calculates the vault margin :

```solidity
vault.margin += tradeResult.fee + tradeResult.payoff.perpPayoff + tradeResult.payoff.sqrtPayoff;
```

and accordingly transfers the `remainingMargin` to the owner specified `recipient` address

```solidity
 if (vault.recipient != address(0)) {
// Send the remaining margin to the recipient.
vault.margin = 0;
sentMarginAmount = uint256(remainingMargin);
ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient,sentMarginAmount);} <@ audit if recipient is a blacklisted address transfer will fail
```

If the `quoteToken` is `USDC/USDT` , the owner of the vault can decide the address of the `recipient` while opening the position and he can simply give an address which is blacklisted for the `quoteToken` and can avoid liquidation since the `safeTransfer` will revert in that case.
