# Vulnerability details



## Impact

The absence of defined storage gaps in the inherited contracts poses a significant risk during upgrades for the Boosted3TokenAuraVault and MetaStable2TokenAuraVault contracts. Storage collisions may occur, potentially corrupting the storage layout of the vaults. This could result in broken vault functionality and assets becoming inaccessible.

### Explanation:

The inherited contracts lack defined storage gaps, which could lead to storage collisions during upgrades. Without these gaps, new storage variables added to inherited contracts may overwrite existing storage, causing unpredictable behavior.

## Recommended Mitigation Steps

To mitigate the risk of storage collisions during upgrades, it is recommended to define appropriate storage gaps in each upgradeable parent contract. These gaps should be placed at the end of all storage variable definitions. An example implementation is provided below:

```solidity
uint256[50] __gap; // gap to reserve storage in the contract for future variable additions
```

Implementing storage gaps ensures that space is reserved for future variable additions, safeguarding against storage collisions and preserving the integrity of the upgradeable contracts.
