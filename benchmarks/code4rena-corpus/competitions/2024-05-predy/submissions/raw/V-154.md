# Vulnerability details

## Impact
The calculation of `minMinValue` [Line 92-93](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PositionCalculator.sol#L92-L93)
```solidity
int256 minMinValue =
    (calculateRequiredCollateralWithDebt(pairStatus.riskParams.debtRiskRatio) * debtValue).toInt256() / 1e6;
```
In the division by `1e6`, this division operation truncates the result towards zero, which can lead to incorrect results when dealing with negative values.

For example, `if calculateRequiredCollateralWithDebt(pairStatus.riskParams.debtRiskRatio) * debtValue` is `-1000000`, then `(-1000000).toInt256() / 1e6` will result in `0` instead of the expected `-1`.

## Proof of Concept
The `minMinValue` variable represents the minimum collateral required based on the debt value and the risk parameters, but due to the truncation caused by the division operation `/ 1e6`, the `minMinValue` can be incorrectly calculated, especially when dealing with negative values.

If the `minMinValue` is incorrectly calculated to be lower than its actual value, it can lead to an underestimation of the minimum margin required for a vault. This means that a vault might be considered safe or not liquidatable when it should be marked as insolvent or liquidatable.

The `minMargin` value is used to determine the safety and liquidation status of a vault through functions like `getIsSafe` and `isLiquidatable`. An incorrect `minMargin` calculation can lead to incorrect vault status assessments, potentially allowing users to open or maintain positions that should be disallowed or liquidated.

Here's how this can manifest:
```solidity
// Assuming pairStatus.riskParams.debtRiskRatio = 1e6 (100%)
uint256 debtValue = 1000000; // 1,000,000 debt value

// Incorrect calculation
int256 minMinValue = (calculateRequiredCollateralWithDebt(1e6) * debtValue).toInt256() / 1e6;
// minMinValue = (1e6 * 1000000).toInt256() / 1e6 = 0 (truncated due to division)

// Correct calculation
int256 correctMinMinValue = SafeCast.toInt256((calculateRequiredCollateralWithDebt(1e6) * debtValue) / 1e6);
// correctMinMinValue = SafeCast.toInt256((1e6 * 1000000) / 1e6) = 1000000
```
The `minMinValue` is incorrectly calculated as `0` instead of the expected `1000000`, which can lead to the issues mentioned above, such as incorrect vault status assessments and potential losses.

## Recommended Mitigation Steps
The division should be performed using proper rounding or flooring functions to handle negative values correctly. For example.
```solidity
import "@openzeppelin/contracts/utils/math/SafeCast.sol";

// ...

int256 minMinValue =
    SafeCast.toInt256(
        (calculateRequiredCollateralWithDebt(pairStatus.riskParams.debtRiskRatio) * debtValue) / 1e6
    );
```
By using `SafeCast.toInt256`, the division result will be correctly rounded or floored before being cast to `int256`, ensuring that negative values are handled correctly.
