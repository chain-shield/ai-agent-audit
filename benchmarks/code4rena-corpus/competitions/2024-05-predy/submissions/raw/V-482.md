# Vulnerability details

## Vulnerability Details

Some tokens like USDT have approval race condition protection, meaning you can only approve the tokens when the allowance is zero.

In the `UniswapSettlement:swapExactOut` the `amountInMaximum` is approved for the ` _swapRouter` and it performs `exactOutput` swap. The problem is that the `amountInMaximum` approved for the router is not fully utilized, so after this interaction, the allowance for the router will not be zero. 

If another trader interacts with this function it is going to revert due to the approval race condition protection that is present in USDT. 


```javascript
    function swapExactOut(
        address quoteToken,
        address,
        bytes memory data,
        uint256 amountOut,
        uint256 amountInMaximum,
        address recipient
    ) external override returns (uint256 amountIn) {
        ERC20(quoteToken).safeTransferFrom(msg.sender, address(this), amountInMaximum);
        //@audit use force approve
        ERC20(quoteToken).approve(address(_swapRouter), amountInMaximum);

        amountIn = _swapRouter.exactOutput(
            ISwapRouter.ExactOutputParams(data, recipient, block.timestamp, amountOut, amountInMaximum)
        );

        if (amountInMaximum > amountIn) {
            ERC20(quoteToken).safeTransfer(msg.sender, amountInMaximum - amountIn);
        }
    }
```


## Impact

Buying on the spot market will stop working, as it relies on this function.
