# Vulnerability details

## Impact
If `tickCumulatives[1] - tickCumulatives[0] is negative and ((tickCumulatives[1] - tickCumulatives[0]) % ago != 0`, then returned tick will be bigger than it should be.

## Proof of Concept
In `UniHelper` library function [getSqrtTWAP()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L20-L22) used to get square root of time weighted average price.

The problem is that if `tickCumulatives[1] - tickCumulatives[0]` is negative, then timeWeightedTick should be rounded down, as is done in the [Uniswap library](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L36)

As a result, if `tickCumulatives[1] - tickCumulatives[0]` is negative and `(tickCumulatives[1] - tickCumulatives[0]) % ago != 0`, the tick will be bigger than it should be. This opens the possibility for arbitrage opportunities.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Tick should be rounded down in this case:
```solidity
int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));
// @audit Always round to negative infinity
if ((tickCumulatives[1] - tickCumulatives[0]) < 0 && ((tickCumulatives[1] - tickCumulatives[0]) % ago != 0)) tick--;
```





## Assessed type

Uniswap
