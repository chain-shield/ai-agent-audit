# Vulnerability details

## Impact
There is a potential underflow issue in the code where the subtraction operation `sqrtRatioA - sqrtPrice` may result in an underflow if `sqrtPrice` is greater than `sqrtRatioA`.

## Proof of Concept:

```solidty
   // Fuzz Test
    function test_Undeffolw_In_calculateAmount1ForLiquidity(
        uint160 sqrtRatioA,
        uint256 available,
        uint256 liquidityAmount
    ) public {
        liquidityAmount = bound(liquidityAmount,1,type(uint64).max);

        uint160 sqrtPrice = ((available * FixedPoint96.Q96) / liquidityAmount).toUint160();

        if (sqrtRatioA <= sqrtPrice + TickMath.MIN_SQRT_RATIO + 1) return;

        // This should revert due to underflow protection
        // sqrtRatioA = 10;
        // available = 1 ether;
        // liquidityAmount = 10 ether;

       uint160 result = Reallocation.calculateAmount1ForLiquidity(sqrtRatioA,available,liquidityAmount);

        assert(result > 0);
        
    }
```

- Fuzz Test
## Recommended Mitigation Steps :

1 . Add check before return :

```solidity

    require(sqrtRatioA >= sqrtPrice, "Underflow error");
    return sqrtRatioA - sqrtPrice;
```
