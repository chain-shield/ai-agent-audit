# Vulnerability details

# validateRiskParams doesn't check sanity of min and max slippage
## Impact 
- Users' positions will be liquidated more than it should be.
## Proof-of-Concept
Pool's owner must specify risk parameters when registering a new pool.  
Risk parameters consist of:  
```
struct AssetRiskParams {
    uint128 riskRatio;
    uint128 debtRiskRatio;
    int24 rangeSize;
    int24 rebalanceThreshold;
    uint64 minSlippage;
    uint64 maxSlippage;
}
```
All parameters except `debtRiskRatio`, `minSlippage` and `maxSlippage` are validated inside `AddPairLogic.sol#validateRiskParams` since they're involved in critical operations.  

```
function validateRiskParams(Perp.AssetRiskParams memory _assetRiskParams) internal pure {
    require(1e8 < _assetRiskParams.riskRatio && _assetRiskParams.riskRatio <= 10 * 1e8, "C0");

    require(_assetRiskParams.rangeSize > 0 && _assetRiskParams.rebalanceThreshold > 0, "C0");
}
```
See: [AddPairLogic.sol#validateRiskParams](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/AddPairLogic.sol#L213-L217)

However, `minSlippage` and `maxSlippage` are also involved in a critical operation, i.e. liquidation.  
They are used to calculate the slippage tolerance during liquidation, in other words, incentive for liquidators.  

```
function calculateSlippageTolerance(int256 minMargin, int256 vaultValue, Perp.AssetRiskParams memory riskParams)
    internal
    pure
    returns (uint256)
{
    if (vaultValue <= 0 || minMargin == 0) {
        return riskParams.maxSlippage;
    }

    uint256 ratio = uint256(vaultValue * 1e4 / minMargin);

    if (ratio > 1e4) {
        return riskParams.minSlippage;
    }

    return (riskParams.maxSlippage - ratio * (riskParams.maxSlippage - riskParams.minSlippage) / 1e4);
}
```
See: [LiquidationLogic.sol#L159-L176](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/LiquidationLogic.sol#L159-L176)

A lack of boundry checking for these parameters could allow them to be set to a very high value, rendering slippage check during liquidation ineffective.  
Especially, if it is expected that anyone will be able to create a new pair/pool. A malicious pool's owner can easily gain an edge on liquidation by setting the riskParams atomically.  

## Tools Used
- Manual Review

## Recommended Mitigations
- Add boundary check for min and max slippage inside `validateRiskParams`
