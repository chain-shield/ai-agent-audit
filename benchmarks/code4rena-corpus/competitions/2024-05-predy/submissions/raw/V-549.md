# Vulnerability details

## Impact

Setting a vault's recipient to a blacklisted address causes partial liquidations to fail, potentially allowing vault owners to avoid liquidation and leading to the accumulation of bad debt for the protocol.

## Proof of Concept

In the 'liquidate()' function, if the closeRatio is below 1e18, any remaining margin is transferred to a recipient designated by the vault owner. 

```solidity
function liquidate(
  uint256 vaultId,
  uint256 closeRatio,
  GlobalDataLibrary.GlobalData storage globalData,
  bytes memory settlementData
) external returns (IPredyPool.TradeResult memory tradeResult) {

  require(closeRatio > 0 && closeRatio <= 1e18, "ICR");
  ...
  ...
  if (!hasPosition) {
       int256 remainingMargin = vault.margin;

       if (remainingMargin > 0) {
          if (vault.recipient != address(0)) {
             // Send the remaining margin to the recipient.
             vault.margin = 0;

             sentMarginAmount = uint256(remainingMargin);

             ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);
```


This recipient address, which can be set by the user, is configurable via the 'updateRecipient()' function.

```solidity
function updateRecepient(uint256 vaultId, address recipient) external onlyVaultOwner(vaultId) {
    DataType.Vault storage vault = globalData.vaults[vaultId];
    vault.recipient = recipient;
    emit RecepientUpdated(vaultId, recipient);
}
```

A problem arises when a vault that uses USDC as collateral (a supported token) has its recipient set to a blacklisted address. This configuration results in partial liquidations failing because the 'safeTransfer()' function reverts when it attempts to transfer the remaining margin. As a result, vault owners can potentially avoid liquidation, causing the protocol to accrue bad debt when full liquidations cannot proceed.

Exploitable scenarious:

1. Alice sets up a vault, designates a blacklisted address as the recipient, and uses USDC as collateral. 
2. When market prices fluctuate, Alice's vault becomes eligible for liquidation. 
3. Bob tries to liquidate Alice's vault by invoking the 'execLiquidationCall()' function with a closeRatio of less than 1e18, but the liquidation fails due to the safeTransfer() function reverting.

```solidity
function execLiquidationCall(
    uint256 vaultId,
    uint256 closeRatio,
    IFillerMarket.SettlementParamsV3 memory settlementParams
) external virtual returns (IPredyPool.TradeResult memory) {
    return
        _predyPool.execLiquidationCall(vaultId, closeRatio, _getSettlementDataFromV3(settlementParams, msg.sender));
}
```

## Recommended Mitigation Steps

Consider to update the 'liquidate()' function to bypass transactions involving blacklisted addresses, allowing liquidations to proceed without encountering reverts.
