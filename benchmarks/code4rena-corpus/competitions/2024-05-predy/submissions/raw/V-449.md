# Vulnerability details

## Impact
A malicious user can prevent himself from liquidation by making the `vault.recipient` a blacklisted USDC address when the quote token is USDC. This will result in making his position insolvent which will lead to loss of funds to the protocol

## Proof of Concept
Consider the following scenario:

1. A malicious user opens a long position with a very small sum, something like 10 USDC

2. Then he calls `PredyPool::updateRecepient()` and passes blacklisted USDC address as `recipient`
https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L286

3. The `baseToken` value starts going down and his position has to be liquidated

4. Liquidator calls `LiquidationLogic::liquidate()` 
https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39

The transaction will revert because the malicious user's margin is not 0. The only way to liquidate him will be if his margin goes to 0 or under, which will make his position insolvent

## Tools Used
Manual Analysis
## Recommended Mitigation Steps
Send the remaining margin to an escrow contract where a user can then withdraw it, so even if he is blacklisted it will not cause any harm to the protocol
