# Vulnerability details

## Impact
[BaseMarketUpgradable.decodeParamsV3](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/base/BaseMarketUpgradable.sol#L49-L66) the calculation of the `minQuoteAmount` and `maxQuoteAmount`.

The `BaseMarketUpgradable.decodeParamsV3` assumes that `baseAmountDelta` is positive when calculating `minQuoteAmount`, and negative when calculating `maxQuoteAmount`. This assumption may not always hold true, leading to incorrect calculations.

The scenario where the bug could occur:

Assume `baseAmountDelta` is a negative value, representing a sell order.
The function calculates `minQuoteAmount` using `settlementParamsV3.minQuoteAmountPrice * tradeAmountAbs / Constants.Q96`.
Since `baseAmountDelta` is negative, the `minQuoteAmount` should represent the maximum amount of the quote token that the user is willing to receive.
Similarly, the function calculates `maxQuoteAmount` using `settlementParamsV3.maxQuoteAmountPrice * tradeAmountAbs / Constants.Q96`.
Since `baseAmountDelta` is negative, the `maxQuoteAmount` should represent the minimum amount of the quote token that the user is willing to receive.

## Proof of Concept
**`Incorrect Quote Amount Range`**
`minQuoteAmount` and `maxQuoteAmoun`t represent the range of acceptable quote token amounts for a trade or settlement operation. If these values are calculated incorrectly, it can lead to trades or settlements being executed outside the intended range, potentially resulting in financial losses or unexpected behavior.

**`Violation of User Preferences`**
`minQuoteAmount` and `maxQuoteAmount` are typically set by the user or a third-party contract to define the acceptable range of quote token amounts for a trade or settlement. If these values are calculated incorrectly, it can violate the user's preferences or the intended behavior of the third-party contract.

**`Potential Exploitation`**
_If an attacker or malicious actor is aware of this issue, they may be able to exploit it by crafting specific trade or settlement parameters that would result in incorrect quote amount range calculations, potentially allowing them to extract more funds than intended or manipulate the settlement process in their favor._

**`Code Example`**
**`Consider the following scenario`**

A user wants to sell 100 base tokens and sets the `minQuoteAmountPrice` to 1.5 (meaning they expect to receive at least 150 quote tokens).
The `baseAmountDelta` is -100 (negative value representing a sell order).
The `BaseMarketUpgradable.decodeParamsV3` calculates `minQuoteAmount` as `settlementParamsV3.minQuoteAmountPrice * tradeAmountAbs / Constants.Q96`, which is `1.5 * 100 / Constants.Q96 = 150`.
But since `baseAmountDelta` is negative, the `minQuoteAmount` should represent the maximum amount of the quote token that the user is willing to receive, not the minimum.
The correct calculation for `minQuoteAmount` in this case should be `settlementParamsV3.maxQuoteAmountPrice * tradeAmountAbs / Constants.Q96`, which could be a higher value than 150.

By incorrectly calculating `minQuoteAmount`, the settlement process may execute a trade or settlement that violates the user's preferences or the intended behavior of the third-party contract, potentially resulting in financial losses or unexpected behavior.

Here's how the issue could be exploited
```solidity
// Assume settlementParamsV3.minQuoteAmountPrice = 1.5
// Assume settlementParamsV3.maxQuoteAmountPrice = 2.0
```

## Recommended Mitigation Steps
The `BaseMarketUpgradable.decodeParamsV3` should swap the assignment of `minQuoteAmount` and `maxQuoteAmount` based on the sign of `baseAmountDelta`.
```solidity
uint256 maxQuoteAmount = baseAmountDelta > 0
    ? settlementParamsV3.maxQuoteAmountPrice * tradeAmountAbs / Constants.Q96
    : settlementParamsV3.minQuoteAmountPrice * tradeAmountAbs / Constants.Q96;

uint256 minQuoteAmount = baseAmountDelta > 0
    ? settlementParamsV3.minQuoteAmountPrice * tradeAmountAbs / Constants.Q96
    : settlementParamsV3.maxQuoteAmountPrice * tradeAmountAbs / Constants.Q96;
```
By making this change, the function will correctly calculate the `minQuoteAmount` and `maxQuoteAmount` based on the sign of `baseAmountDelta`, the settlement process can ensure that trades or settlements are executed within the intended range, preserving the user's preferences and the intended behavior of third-party contracts.
