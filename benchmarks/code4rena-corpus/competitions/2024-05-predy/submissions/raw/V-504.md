# Vulnerability details

## Impact
During `reallocation` of pairs (pairs act as liquidity pools), the `tick range` is updated to correctly reflect the tick range of the `Uniswap V3 pool`.

However, due to direct `division before multiplication` (solidity rounds down on division), the new tick range calculation will experience precision loss.

Thus, the new `tick range` will be incorrect and will not correctly reflect the amount of liquidity and pricing of that range. 

This can lead to many issues, for example lead to `DoS of trades`, since the pair may not have the amount of liquidity that was calculated for that `tick range`.

## Proof of Concept
During reallocation, the tick range of the pair is updated:

[Perp.sol#L276-L277](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/Perp.sol#L276-L277)
```javascript
    (_sqrtAssetStatus.tickLower, _sqrtAssetStatus.tickUpper) =
        Reallocation.getNewRange(_assetStatusUnderlying, _currentTick);
```

The `tick spacing` is fetched from the pool and used to calculate the `lower` and `upper` ticks

[Reallocation.sol#L23](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/Reallocation.sol#L23)
```javascript
int24 tickSpacing = IUniswapV3Pool(_assetStatusUnderlying.sqrtAssetStatus.uniswapPool).tickSpacing();
```

[Reallocation.sol#L85-L86](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/Reallocation.sol#L85-L86)
```javascript
    lower = calculateUsableTick(lower, tickSpacing);
    upper = calculateUsableTick(upper, tickSpacing);
```

The problem is `calculateUsableTick` performs division before multiplication.

[Reallocation.sol#L109-L121](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/Reallocation.sol#L109-L121)
```javascript
    function calculateUsableTick(int24 _tick, int24 tickSpacing) internal pure returns (int24 result) {
        require(tickSpacing > 0);

        result = _tick;

        if (result < TickMath.MIN_TICK) {
            result = TickMath.MIN_TICK;
        } else if (result > TickMath.MAX_TICK) {
            result = TickMath.MAX_TICK;
        }

@>      result = (result / tickSpacing) * tickSpacing;
    }
```

Solidity rounds down when division is performed, so when multiplication is performed after, it will experience precision loss.

I will display this using `chisel`, where the `tickSpacing` and `tick` values were obtained from [this pool](https://polygonscan.com/address/0x50eaEDB835021E4A108B7290636d62E9765cc6d7#readContract)

```javascript
int24 tickSpacing = 10;
int24 tick = 259515;
int24 resultDivisionBeforeMultiplication = (tick / tickSpacing) * tickSpacing;
int24 resultMultiplicationBeforeDivision = (tick * tickSpacing) / tickSpacing;
resultDivisionBeforeMultiplication
Type: int
├ Hex: 0x000000000000000000000000000000000000000000000000000000000003f5b6
└ Decimal: 259510 <@
resultMultiplicationBeforeDivision
Type: int
├ Hex: 0x000000000000000000000000000000000000000000000000000000000003f5bb
└ Decimal: 259515 <@
```

There is clear precision loss when dividing before multiplying (259510 vs 259515)  . [Uniswap v3 pools have a tick range from a minimum of -887272 to a maximum of 887272](https://support.uniswap.org/hc/en-us/articles/21069524840589-What-is-a-tick-when-providing-liquidity#:~:text=Uniswap%20v3%20pools%20have%20a%20tick%20range%20from%20a%20minimum%20of%20%2D887272%20to%20a%20maximum%20of%20887272), so with a greater tick range and spacing, more precision loss will occur.

Both lower and upper ticks will experience precision loss causing an incorrect tick range.

The pricing and liquidity values will then be incorrect for this range, which can have many issues, such as DoS on trades due to insufficient liquidity.

## Tools Used
Manual review, chisel

## Recommended Mitigation Steps
Multiply before dividing instead to prevent precision loss

```diff
    function calculateUsableTick(int24 _tick, int24 tickSpacing) internal pure returns (int24 result) {
        require(tickSpacing > 0);

        result = _tick;

        if (result < TickMath.MIN_TICK) {
            result = TickMath.MIN_TICK;
        } else if (result > TickMath.MAX_TICK) {
            result = TickMath.MAX_TICK;
        }

-       result = (result / tickSpacing) * tickSpacing;
+       result = (result * tickSpacing) / tickSpacing;
    }
```
