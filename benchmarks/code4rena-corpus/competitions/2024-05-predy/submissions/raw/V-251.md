# Vulnerability details

`PriceFeed::getSqrtPrice` may return an incorrect price.

## Proof of Concept

The code in predy finance gets the USD-denominated price of the quoteToken in this way:
```cpp
PriceFeed.sol#L46=>
(, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();
```
This does not check whether the price received was a stale one.

Since this value is used to calculate the sqrt of the price of the base token in terms of the quote token as shown below, then it being stale can lead to an incorrect price.
``` cpp
PriceFeed.sol#L54-#L57=>
uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
price = price * Constants.Q96 / _decimalsDiff;

sqrtPrice = FixedPointMathLib.sqrt(price);
```
## Impact
When a pair is using a price feed instead of uniswap Twap the functions relying on an accurate price feed might not work as expected, having an incorrect price might lead to fund loss. The impacts vary and depend on the specific situation like the following:

- Liquidation of vaults that are supposed to be considered Safe
- Inability to Liquidate vaults that are supposed to be considered Unsafe

Since those 2 are considered as invariants as it is said in the contest's Read me file and they are broken in this situation, I give this a high impact and since its likelihood is low, I give it a medium risk rating.

## Recommended Mitigation Steps 
Since the protocol already specifies that the price gotten from Pyth is no older than 5 minutes it may do the same with the price from Chainlink.

This is an example of how the fixed code should look like:
```diff
- (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();
+ (, int256 quoteAnswer,,Uint256 UpdatedAt,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();
+ require(block.timestamp - UpdatedAt > VALID_TIME_PERIOD);
```
