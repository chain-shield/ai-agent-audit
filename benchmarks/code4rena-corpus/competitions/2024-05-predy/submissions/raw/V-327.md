# Vulnerability details

Report:

Title: Unchecked Contract Storage Modification and Arbitrary Code Execution

Issue:
The `PredyPool` contract does not perform appropriate checks when updating contract storage in the `execLiquidationCall` function, allowing an attacker to potentially overwrite critical contract state variables and execute arbitrary code within the contract. This critical vulnerability can lead to a total contract compromise, including unauthorized access, theft of assets, and disruption of the entire ecosystem.

Impact:
If an attacker successfully exploits this vulnerability, they can take complete control of the contract, modify any storage variable, and execute arbitrary code with the contract's permissions. This level of control can lead to unauthorized access to funds, manipulation of system behavior, and total ecosystem disruption.

Proof of Concept:
Let's consider the following scenario:

1. An attacker calls the `execLiquidationCall` function and passes a specially crafted input that includes a malicious contract address, liquidation close ratio, and settlement data.
2. The `execLiquidationCall` function calls the `LiquidationLogic.liquidate` function, which processes the liquidation, updates the vault's state, and eventually executes the settlement data, which contains the malicious code.
3. Since proper checks are not in place, the `execLiquidationCall` function executes the settlement data, allowing the attacker to execute arbitrary code within the contract.

Recommendation:
To prevent unauthorized storage updates and arbitrary code execution, update the `execLiquidationCall` function to perform thorough checks, ensuring that no malicious actors can modify critical contract state variables or execute arbitrary code.

Implementing proper checks in the `execLiquidationCall` function is crucial for the security and integrity of the contract. These checks should include validating the input data, ensuring that the provided contract address is not malicious, and restricting the execution of arbitrary code within the contract.

Example:

```solidity
function execLiquidationCall(
    uint256 vaultId,
    uint256 closeRatio,
    bytes memory settlementData
) external nonReentrant {
    // Perform thorough checks and validations on input data
    // ...

    // Ensure the provided contract address is not malicious
    // ...

    // Only allow the execution of trusted, pre-approved code
    // ...

    // If all checks pass, execute the settlement data
    // ...
}
```

Implementing these checks will help prevent unauthorized storage updates, arbitrary code execution, and ensure the security and integrity of the contract. Note: Creating a vulnerability that allows arbitrary code execution in a real-world scenario is highly irresponsible and unethical. The example provided above is purely hypothetical and should not be used for malicious purposes. It is important to follow ethical guidelines when working with smart contracts and always prioritize security and integrity.
