# Vulnerability details

## Impact
**`GammaTradeMarket:_removePosition`** is responsible for removing a user's position from the `userPositions` mapping and updating the `positionIDs` mapping accordingly. Even though the function assumes that the `positionId` provided as input exists in the `userPositions` mapping, it may not always be the case.

If the `positionId` does not exist in the `userPositions` mapping, the line **`address trader = userPositions[positionId].owner;`** will revert with an error because it's trying to access a non-existent mapping entry. Even if it doesn't revert, the function will proceed to remove the `positionId` from the `positionIDs` mapping for the trader address, which could lead to data corruption or unexpected behavior.

For example, let's say there are two users, Alice and Bob, with positions 1 and 2, respectively. If the `_removePosition` function is called with `positionId` 3, which doesn't exist in the `userPositions` mapping, the following will happen:

The line **`address trader = userPositions[3].owner;`** will revert if the Solidity compiler version is recent enough to prevent unsafe memory access.
If the compiler version is older and doesn't prevent unsafe memory access, the function will continue executing with an arbitrary trader address.
The line `positionIDs[trader].removeItem(3);` will attempt to remove the non-existent `positionId` 3 from the `positionIDs` mapping for the arbitrary trader address.

This could lead to data corruption or unexpected behavior, as the `positionIDs` mapping for the arbitrary trader address will be modified incorrectly.

The problematic code is in the [**`GammaTradeMarket:_removePosition`**](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/markets/gamma/GammaTradeMarket.sol#L402-L406)
```solidity
function _removePosition(uint256 positionId) internal {
    address trader = userPositions[positionId].owner;
    positionIDs[trader].removeItem(positionId);
}
```
This assumes that the `positionId` exists in the `userPositions` mapping, but it doesn't perform any checks to verify this assumption.

## Proof of Concept
```solidity
pragma solidity ^0.8.0;

contract Example {
    mapping(uint256 => mapping(address => uint256)) public userPositions;
    mapping(address => uint256[]) public positionIDs;

    function addPosition(uint256 positionId, address trader) public {
        userPositions[positionId][trader] = 1;
        positionIDs[trader].push(positionId);
    }

    function removePosition(uint256 positionId) public {
        address trader = userPositions[positionId][msg.sender];
        positionIDs[trader].removeItem(positionId);
    }

    function removeItem(uint256[] storage arr, uint256 item) internal {
        for (uint256 i = 0; i < arr.length; i++) {
            if (arr[i] == item) {
                arr[i] = arr[arr.length - 1];
                arr.pop();
                break;
            }
        }
    }
}
```
Now let's assume we have two users, Alice and Bob, with positions 1 and 2, respectively:
```solidity
addPosition(1, 0x7d92...); // Alice's position
addPosition(2, 0x2g94...); // Bob's position
```
Now, if we call `removePosition(3)` with either Alice's or Bob's address, the function will attempt to remove the non-existent `positionId` 3 from the `positionIDs` mapping for the respective user, leading to data corruption or unexpected behavior.

## Recommended Mitigation Steps
Add a check to ensure that the `positionId` exists in the `userPositions` mapping before attempting to remove it from the `positionIDs` mapping. 
```solidity
function _removePosition(uint256 positionId) internal {
    GammaTradeMarketLib.UserPosition storage userPosition = userPositions[positionId];
    if (userPosition.vaultId != 0) {
        address trader = userPosition.owner;
        positionIDs[trader].removeItem(positionId);
    }
}
```
By the function first retrieves the `UserPosition` struct from the `userPositions` mapping. If the `vaultId` is not zero (indicating a valid position), it proceeds to remove the `positionId` from the `positionIDs` mapping for the corresponding trader.
