# Vulnerability details

## Impact
There will be no incentive for liquidators to liquidate trader's positions.

## Proof of Concept

https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L106

```javascript
 else if (remainingMargin < 0) {
                vault.margin = 0;

                // To prevent the liquidator from unfairly profiting through arbitrage trades in the AMM and passing losses onto the protocol,
                // any losses that cannot be covered by the vault must be compensated by the liquidator
                ERC20(pairStatus.quotePool.token).safeTransferFrom(msg.sender, address(this), uint256(-remainingMargin)); 
            }
```

The above can be a problem when there are big price swings or when the `minMargin` is small causing the `remainingMargin` to become negative quickly. Liquidators will lose all incentive to liquidate traders.

Trades will not be liquidated.



## Tools Used
Manual review

## Recommended Mitigation Steps
Create a vault that will be receive a percentage of protocol fees and will cover the protocol's bad debt. Liquidators need to always be incentivized, but the incentive cannot be too high as to encourage traders to liquidate themselves. 

Possibly, have a `minLiquidationReward` that is a percentage of the fee for opening a trade. This will guarantee liquidators always have and incentive to perform liquidations.
