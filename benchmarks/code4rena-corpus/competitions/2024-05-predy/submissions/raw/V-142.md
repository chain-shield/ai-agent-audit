# Vulnerability details

## Impact
1. Denial of service when Pyth price is not updated with the Pyth's `updatePriceFeeds(...)` as recommended in the Pyth docs in the last 5minutes.

2. Possible use of stale price during market price turbulence.

## Proof of Concept
The main issue is that the Pyth oracle is used as if it is a `PUSH` oracle. However  Pyth oracle is a `PULL` Oracle.

The major difference is that for Pull oracles like Pyth is that data is only updated when needed and Pyth allows users to update the price with the `updatePriceFeeds(...)` function they provided.

According to Pyth's [docs](https://docs.pyth.network/price-feeds/pull-updates#pull-oracles):

>In contrast to push oracles, pull oracles only update the on-chain price when requested. There are different ways for users to request an updated price from a pull oracle. Some pull oracles respond to on-chain requests: applications send one transaction to request data from the oracle, which then submits the response in a second transaction. Pyth uses a simpler system where users can request the latest price update from an off-chain service. Anyone can submit a price update to the on-chain Pyth contract, which verifies its authenticity and stores it for later use. This system allows applications to use a single transaction flow that first updates the price then performs the necessary application logic.

As can be seen in the code above the `VALID_TIME_PERIOD` that is used for the `getPriceNoOlderThan` function call is 5 minutes. This means that if the last time the price was updated is more than 5 minutes in the past, the transaction will revert.

The second issue is that Predy does not update price before calling the `getPriceNoOlderThan` function but relies on other calls to update price outside Predy. If no one updates the price outside Predy, the price retrieval will continously revert.

Pyth docs explains the Updating price issue here with examples and tests to show here: https://docs.pyth.network/price-feeds/create-your-first-pyth-app/evm/part-1#update-pyth-prices

## Recommended Mitigation Steps
Consider following this detailed example that also explains the issue with [updating the price oracle here](https://docs.pyth.network/price-feeds/create-your-first-pyth-app/evm/part-1#update-pyth-prices)

These are possible suggested steps:
- Create a payable function to update Pyth price like below. 
```solidity
function updatePythPrice(bytes[] calldata pythPriceUpdate) external payable {
    uint updateFee = pyth.getUpdateFee(pythPriceUpdate);
    pyth.updatePriceFeeds{ value: updateFee }(pythPriceUpdate);
  }
```
- Create another function `updatePythandGetPrice(...)`  that will first call the `updatePythPrice(...)` function above before calling the existing `getSqrtPrice` function.
