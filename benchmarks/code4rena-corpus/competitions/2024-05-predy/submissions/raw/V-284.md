# Vulnerability details


A user can prevent partial liquidations on their account by setting the receiver to a blacklisted USDC address while liquidatable. By doing this, users can avoid liquidations when that liquidation would have resulted in the user having remaining margin. Being able to prevent liquidations of this type risks the pool taking on bad debt, as liquidations would be delayed until a liquidation can be done without there being any margin leftover.

In pools that have `allowlistEnabled` set to false and USDC as a token in their pool, users will leverage this attack by calling `updateRecepient` and setting the recipient of their vault funds to a USDC blacklisted address. Then, when the position is unhealthy and eligible for a liquidation that leaves any amount of margin in their vault, those funds will be sent to the recipient of the vault.

```
            if (remainingMargin > 0) {
                if (vault.recipient != address(0)) {
                    // Send the remaining margin to the recipient.
                    vault.margin = 0;

                    sentMarginAmount = uint256(remainingMargin);

                    ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);
                }
            }
```

This transfer will fail as the quote token is USDC and the address that these funds are being sent to is an address blacklisted by Circle. Because of the revert here, the whole transaction will revert and the liquidation will fail. Overall, this allows a position to not be initially liquidatable, leading to positions accruing bad debt or the position having a chance to be profitable again.

## Impact
Users can prevent some liquidations

## Proof of Concept
1. Alice creates a leveraged position where the quote token is USDC.
2. Alice calls `updateRecepient` and sets the address to one of the USDC blacklisted addresses.
3. Alice's position is losing and Alice is now liquidatable.
4. Bob attempts to liquidate the position but fails due to: `ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);`

**Two paths from here:**

**1:** Alice's position continues to fall, and now the debt exceeds her available collateral. Bob liquidates but has to pay off Alice's bad debt, putting Bob at a loss.

**2:** Alice's position starts to win and now Alice has a position that is in profit. Alice changes the recipient to an address she owns that is not blacklisted. Alice closes the position in profit after an extended period of time being liquidatable.

## Tools Used
Manual analysis

## Recommended Mitigation Steps

In the `updateRecepient` function, check if the token is USDC and if it is, use Circle's `isBlackListed` function. If the function returns true, revert.
