# Vulnerability details

## Impact
A user could be DoSed  if `finalWithdrawAmount` exceeds the available collateral in the protocol. This is because the `require(getAvailableCollateralValue(tokenState) >= finalWithdrawAmount, "S0");` check will revert the transaction, preventing the user from withdrawing their assets.

## Proof of Concept
[withdraw()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L242) calls [removeAsset()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ScaledAsset.sol#L67) function which allows users to withdraw assets from the protocol.
It calculates the `finalBurnAmount` and `finalWithdrawAmount` based on the user's request and the current state of the protocol.

Before allowing the withdrawal, the function checks if the available collateral is sufficient to cover the `finalWithdrawAmount`:
```solidity
require(getAvailableCollateralValue(tokenState) >= finalWithdrawAmount, "S0");
```
The [getAvailableCollateralValue()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ScaledAsset.sol#L226-L228) returns the diffrence between total deposited collateral and total borrows:
```solidity
    function getAvailableCollateralValue(AssetStatus memory tokenState) internal pure returns (uint256) {
        return getTotalCollateralValue(tokenState) - getTotalDebtValue(tokenState);
    }
```
As seen, if the available collateral is less than the `finalWithdrawAmount`, the transaction reverts with the error `"S0"`.

This means the user cannot proceed with the withdrawal, effectively locking their assets in the protocol.
This situation can occur if the protocol's collateral is heavily utilized.

Therefore, the user will be forced to perform another withdrawal attempt with the hopes that it would succeed this time. However, there's no such guarantees as there are chances that there still won't be enough collateral to cover for his withdraw amount. 

Combined with the fact that he may not be the only user trying to withdraw their funds, this situation can stick indefinitely. 

## Tools Used
Manual Review

## Recommended Mitigation Steps
Allow partial withdrawals if the full amount cannot be withdrawn. This can be achieved by adjusting the `finalWithdrawAmount` to the available collateral.
