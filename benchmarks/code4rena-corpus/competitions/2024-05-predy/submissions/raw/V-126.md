# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/lens/GammaTradeMarketQuoter.sol#L20-L28

```solidity
    function quoteTrade(GammaOrder memory order, IFillerMarket.SettlementParamsV3 memory settlementData)
        external
        returns (IPredyPool.TradeResult memory tradeResult)
    {
        try gammaTradeMarket.quoteTrade(order, settlementData) {}
        catch (bytes memory reason) {
            tradeResult = _parseRevertReason(reason);
        }
    }
```

Now going to the implementation of `gammaTradeMarket.quoteTrade()` here: https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L315-L331

```solidity
    function quoteTrade(GammaOrder memory gammaOrder, SettlementParamsV3 memory settlementParams) external {
        // execute trade
        _predyPool.trade(
            IPredyPool.TradeParams(
                gammaOrder.pairId,
                gammaOrder.positionId,
                gammaOrder.quantity,
                gammaOrder.quantitySqrt,
                abi.encode(
                    CallbackData(
                        GammaTradeMarketLib.CallbackType.QUOTE, gammaOrder.info.trader, gammaOrder.marginAmount
                    )
                )
            ),
            _getSettlementDataFromV3(settlementParams, msg.sender)
        );
    }
```

We can see that this is the function that ends up finalizing and executing the trade via `predyPool.trade()`, issue however is that the implementation of `predyPool.trade()` itself lacks any slippage mechanism which is why all other instances from `gammaTradeMarket` that query this, then check the `tradePrice` the trade was finalized in and then check if it is acceptable by the protocol set slippage an exanple can be seen here https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L310-L312

```solidity
        tradeResult = _predyPool.trade(tradeParams, _getSettlementDataFromV3(settlementParams, msg.sender));

        SlippageLib.checkPrice(sqrtPrice, tradeResult, slippageTorelance, SlippageLib.MAX_ACCEPTABLE_SQRT_PRICE_RANGE);
```

However this implementation is absent in the `gammaTradeMarket.quoteTrade()` function which then leaves this attempt at swapping vulnerable to slippage attacks.

## Impact

No slippage checks when after a trade has being processed in the `predyPool` via `gammaTradeMarket.quoteTrade()`, which leaves users querying this to be vulnerable to the popular slippage attacks.

## Recommended Mitigation Steps

Consider applying a similar slippage check to `gammaTradeMarket.quoteTrade()` as is being done for all other three instances where `_predyPool.trade()` is being queried.
