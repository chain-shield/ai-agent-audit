# Vulnerability details

## Description 
The withdrawProtocolRevenue function in the PredyPool contract transfers the entire accumulated protocol revenue to the operator without considering any potential fees or deductions that might be applicable, such as operational fees or reserve requirements.
```
function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external onlyOperator {
    Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);

    uint256 amount = pool.accumulatedProtocolRevenue;

    require(amount > 0, "AZ");

    pool.accumulatedProtocolRevenue = 0;

    if (amount > 0) {
        ERC20(pool.token).safeTransfer(msg.sender, amount);
    }

    emit ProtocolRevenueWithdrawn(pairId, isQuoteToken, amount);
}
```

## Impact
1. The function transfers the full accumulated revenue without accounting for any necessary deductions, leading to incorrect revenue distribution.

2. Without deducting operational fees, the protocol may lack funds for maintenance and operational costs, affecting its sustainability.

3. Failing to retain reserve requirements could compromise the protocol's ability to meet future liabilities or obligations, affecting its financial integrity.

## Proof of Concept
Scenario:
- The operator calls withdrawProtocolRevenue with a valid pairId and isQuoteToken flag.

Steps:
- The function retrieves the AssetPoolStatus for the specified pairId and isQuoteToken.
- It checks if accumulatedProtocolRevenue is greater than 0.
- It resets accumulatedProtocolRevenue to 0.
- It transfers the entire amount to the operator without any deductions.
- Emits the ProtocolRevenueWithdrawn event.

Impact:
- The entire accumulated revenue is transferred to the operator without considering any operational fees or reserve requirements.
- This can lead to insufficient funds for protocol maintenance and future liabilities.

## Recommended Mitigation Steps
To address this issue, the function should include logic to deduct any applicable fees or reserve requirements before transferring the remaining revenue to the operator.
```
function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external onlyOperator {
    // Validate that the pairId exists
    require(globalData.pairs[pairId].id != 0, "Invalid pairId");

    Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);

    uint256 amount = pool.accumulatedProtocolRevenue;

    require(amount > 0, "AZ");

    // Example: Deduct operational fees and reserve requirements
    uint256 operationalFee = calculateOperationalFee(amount);
    uint256 reserveRequirement = calculateReserveRequirement(amount);
    uint256 netAmount = amount - operationalFee - reserveRequirement;

    // Ensure the net amount is still positive after deductions
    require(netAmount > 0, "Net amount must be positive");

    // Reset accumulated protocol revenue
    pool.accumulatedProtocolRevenue = 0;

    // Transfer the net amount to the operator
    ERC20(pool.token).safeTransfer(msg.sender, netAmount);

    // Handle operational fee and reserve requirement
    if (operationalFee > 0) {
        ERC20(pool.token).safeTransfer(operationalFeeRecipient, operationalFee);
    }
    if (reserveRequirement > 0) {
        ERC20(pool.token).safeTransfer(reserveRecipient, reserveRequirement);
    }

    emit ProtocolRevenueWithdrawn(pairId, isQuoteToken, netAmount);
}

// Example functions to calculate fees and reserve requirements
function calculateOperationalFee(uint256 amount) internal view returns (uint256) {
    // Implement the logic to calculate operational fees
    return amount * operationalFeeRate / 100;
}

function calculateReserveRequirement(uint256 amount) internal view returns (uint256) {
    // Implement the logic to calculate reserve requirements
    return amount * reserveRate / 100;
}
```

Benefits of the Change:
1. Ensures that only the net revenue, after deducting applicable fees and reserve requirements, is transferred to the operator.

2. Retaining reserve requirements ensures the protocol can meet future liabilities and obligations, maintaining financial integrity.
