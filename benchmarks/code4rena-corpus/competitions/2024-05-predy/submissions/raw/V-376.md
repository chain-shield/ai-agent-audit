# Vulnerability details

## Impact
The impact of the finding lies in the potential risk introduced by the presence of both a constructor and an `initialize` function in the `PredyPool.sol` contract. This dual initialization mechanism can lead to unexpected behavior during contract deployment and upgrades, potentially compromising the integrity and security of the contract.

## Proof of Concept
### Code Snippet:
```solidity
    constructor() {} // @audit should use disable initializers

    function initialize(address uniswapFactory) public initializer {
        __ReentrancyGuard_init();
        AddPairLogic.initializeGlobalData(globalData, uniswapFactory);

        operator = msg.sender;
    }
}
```
### Explanation:
The `constructor` is defined in the `PredyPool.sol` contract, alongside an `initialize` function. The presence of both constructs can lead to ambiguity during contract initialization and upgrading processes.

### Recommendation:
To mitigate this issue, it is recommended to either remove the constructor entirely or implement the `disableInitializers` function to prevent unexpected behavior. This ensures a clear and predictable contract initialization process, reducing the likelihood of vulnerabilities arising from conflicting initialization mechanisms.

## Tools Used
Manual review

## Recommended Mitigation Steps
1. **Remove Constructor:** Consider removing the constructor from the `PredyPool.sol` contract if it is not required for contract initialization or if the functionality provided by the `initialize` function adequately covers initialization requirements.

2. **Implement `disableInitializers`:** If retaining the constructor is necessary, implement the `disableInitializers` function provided by the upgradeable contracts library. This function disables the ability to use initializers after contract deployment, ensuring consistent and secure contract initialization behavior.

By taking these mitigation steps, the risk associated with conflicting initialization mechanisms in the `PredyPool.sol` contract can be effectively addressed, enhancing the overall security and reliability of the contract.
