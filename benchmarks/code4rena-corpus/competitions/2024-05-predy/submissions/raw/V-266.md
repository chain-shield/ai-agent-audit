## Impact
This assumption forces liquidity to be symmetrically distributed around zero, preventing liquidity providers from placing their liquidity at the most profitable or strategically advantageous price ranges based on market conditions.
## Proof of Concept
The code snippet provided is part of `AddPairLogic` contract system designed to interact with Uniswap V3, a decentralized exchange protocol. Specifically, the focus is on the `_storePairStatus` function within the `AddPairLogic` library. This function is responsible for initializing and storing the status of a newly added token pair, including its associated risk parameters and interest rate model parameters.

A critical aspect of this process involves defining the active price range for the token pair, represented by `tickLower` and `tickUpper`. These values are derived from the `rangeSize` parameter within the `AssetRiskParams` structure, which is passed through the `AddPairParams` during the addition of a new pair. The code sets `tickLower` to `-rangeSize` and `tickUpper` to `rangeSize`, implying a symmetric price range around zero.

However, this approach may lead to a misunderstanding or misinterpretation of how the price range is calculated and intended to be used within the context of Uniswap V3. In Uniswap V3, the concept of ticks and their ranges is fundamental to understanding the liquidity available at different price points. The `rangeSize` parameter, as used here, does not directly translate to a `tickRange` but rather sets the boundaries of the active price range for the asset. This distinction is crucial for ensuring that the price range accurately reflects the intended risk parameters and market conditions.

The values of `tickLower` and `tickUpper` in a Uniswap V3 pool should not be assumed to always be symmetrical around zero. In the context of Uniswap V3, `tickLower` and `tickUpper` represent the bounds of a price range within which liquidity is provided, and these bounds can be set to any valid tick values depending on the desired strategy.

In the provided code, it appears that `tickLower` and `tickUpper` are being set to -`_addPairParam.assetRiskParams.rangeSize` and `_addPairParam.assetRiskParams.rangeSize`,:
This implementation assumes a symmetric range around zero, which might not always be the case. It is possible for `tickLower` to be a positive value and `tickUpper` to be a higher positive value, or both could be negative.
### Example Scenario
Consider an asset pair with the current price well above zero. If the desired liquidity range is between `tickLower = 1000` and `tickUpper = 3000`, setting `tickLower` to `-rangeSize` (e.g., `-2000`) and `tickUpper` to `rangeSize` (e.g., `2000`) means:

The liquidity from `-2000` to `1000` is essentially wasted since the current price is much higher than 0.
Only part of the actual price range of interest (`1000` to `2000`) will have sufficient liquidity, potentially leading to inefficiency.

```solidity
function addPair(
    GlobalDataLibrary.GlobalData storage _global,
    mapping(address => bool) storage allowedUniswapPools,
    AddPairParams memory _addPairParam
) external returns (uint256 pairId) {
    pairId = _global.pairsCount;

    require(pairId < Constants.MAX_PAIRS, "MAXP");

    IUniswapV3Pool uniswapPool = IUniswapV3Pool(_addPairParam.uniswapPool);

    address stableTokenAddress = _addPairParam.quoteToken;

    IUniswapV3Factory uniswapV3Factory = IUniswapV3Factory(_global.uniswapFactory);

    // check the uniswap pool is registered in UniswapV3Factory
    if (
        uniswapV3Factory.getPool(uniswapPool.token0(), uniswapPool.token1(), uniswapPool.fee())
            != _addPairParam.uniswapPool
    ) {
        revert InvalidUniswapPool();
    }

    require(uniswapPool.token0() == stableTokenAddress || uniswapPool.token1() == stableTokenAddress, "C3");

    bool isQuoteZero = uniswapPool.token0() == stableTokenAddress;

    _storePairStatus(
        stableTokenAddress,
        _global.pairs,
        pairId,
        isQuoteZero ? uniswapPool.token1() : uniswapPool.token0(),
        isQuoteZero,
        _addPairParam
    );

    allowedUniswapPools[_addPairParam.uniswapPool] = true;

    _global.pairsCount++;

    emit PairAdded(pairId, _addPairParam.quoteToken, _addPairParam.uniswapPool);
}
```
