# Vulnerability details

## Impact
`PriceFeed.getSqrtPrice` calculation of the price variable: [PriceFeed.getSqrtPrice#L54-L55](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/PriceFeed.sol#L54-L55)
```solidity
uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
price = price * Constants.Q96 / _decimalsDiff;
```
The problem is that the order of operations is not preserved due to the way the calculations are split into two lines. The intended calculation should be.
```solidity
price = (uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer)) * Constants.Q96 / _decimalsDiff;
```
The way it is currently written, the calculation is effectively:
```solidity
price = (uint256(int256(basePrice.price)) * Constants.Q96) / (uint256(quoteAnswer) * _decimalsDiff);
```
Means that the `quoteAnswer` is being multiplied by `_decimalsDiff` instead of being divided by it, which is likely not the intended behavior.

## Proof of Concept
The order of operations in the calculation of the price variable in the `PriceFeed.getSqrtPrice` can lead to incorrect price calculations, resulting in significant financial losses or gains for users of the protocol.

Incorrect Price Calculation: The current implementation of the `price` calculation is effectively.
```solidity
price = (uint256(int256(basePrice.price)) * Constants.Q96) / (uint256(quoteAnswer) * _decimalsDiff);
```
This means that instead of dividing the `quoteAnswer` by `_decimalsDiff`, it is multiplying the `quoteAnswer` with `_decimalsDiff`. This can lead to a significant deviation from the intended price calculation, especially if the `_decimalsDiff` value is not equal to 1.

Suppose we have the following values:

`basePrice.price` = 1000000000 (1 base token = 1 USD)
`quoteAnswer` = 1000000000 (1 quote token = 1 USD)
`Constants.Q96` = 2^96 (fixed-point representation of 1)
`_decimalsDiff` = 10^12 (base token has 12 decimal places, quote token has 18 decimal places)

The intended calculation should be:
```solidity
price = (1000000000 * 2^96 / 1000000000) * 2^96 / 10^12
      = 1 * 2^96 / 10^12
      = 2^84
```
The current implementation calculates:
```solidity
price = (1000000000 * 2^96) / (1000000000 * 10^12)
      = 2^96 / 10^12
      = 2^84 * 10^12
```
This results in a price that is 10^12 (1 trillion) times higher than the intended price, which could lead to significant financial losses or gains for users.

## Recommended Mitigation Steps
The calculation should be combined into a single line or parentheses should be used to ensure the correct order of operations.
```solidity
uint256 price = (uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer)) * Constants.Q96 / _decimalsDiff;
```
or
```solidity
uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / (uint256(quoteAnswer) * _decimalsDiff);
```
