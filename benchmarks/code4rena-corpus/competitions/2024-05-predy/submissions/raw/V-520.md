# Vulnerability details


## Impact

In the PriceFeed.sol, the chainlink `_quotePriceFeed` address is set to immutable and deployed in the constructor. However, that a chainlink oracle current works does not mean it will keeps working or be supported by chainlink in the future. In certain cases, feeds have been updated and have add their addresses changed. Also, the current price feed can become buggy and there's no way to change it.  Setting the `_quotePriceFeed` as immutable therefore, risks causing the contract to completely break if the feed is taken down or moved to another address potentially forcing redeployment.

## Proof of Concept

From PriceFeed.sol, it can be seen that `_quotePriceFeed` which is the price feed address for the quote token is set as immutable meaning it cannot be changed. To support this, the contract lacks a change feed function. 

```solidity
contract PriceFeed {
    address private immutable _quotePriceFeed;
    ...
    constructor(address quotePrice, address pyth, bytes32 priceId, uint256 decimalsDiff) {
        _quotePriceFeed = quotePrice;
        _pyth = pyth;
        _priceId = priceId;
        _decimalsDiff = decimalsDiff;
    }

```

However, chainlink price feeds are not immutable as they can change, either by being taken down or being updated to a new address which is one of the reasons [advertises](<https://blog.chain.link/introducing-the-chainlink-feed-registry/)>) the use of their registry contract. 
When this occurs or if the price feed gets buggy, changing the pricefeed will be impossible, breaking the protocol's functionality and will force redeployment of the contract which doesn't come cheap.


## Recommended Mitigation Steps

Consider making it not immutable and introducing an admin protected function to modify the `_quotePriceFeed`.
