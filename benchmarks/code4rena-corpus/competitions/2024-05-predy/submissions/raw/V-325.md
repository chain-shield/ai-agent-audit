# Vulnerability details

Report:

Title: Missing Access Control Checks in `withdrawProtocolRevenue` and `withdrawCreatorRevenue`

Issue:
The `withdrawProtocolRevenue` and `withdrawCreatorRevenue` functions do not perform access control checks to ensure that the caller is an owner of the specified pair. As a result, any user can potentially withdraw protocol or creator revenue from any pair, leading to unauthorized access and potential security issues.

Impact:
If an attacker can exploit this vulnerability, they may be able to manipulate the internal state of the contract, leading to potential governance attacks on the affected system. The manipulation could allow the attacker to gain unauthorized access to funds, affecting the intended behavior of the contract and its dependent systems.

Proof of Concept:
Let's consider the following scenario:

1. An attacker calls the `withdrawProtocolRevenue` or `withdrawCreatorRevenue` function with a pairId they do not own.
2. The function does not perform any access control checks to ensure that the caller is an owner of the specified pair.
3. As a result, the attacker can potentially withdraw protocol or creator revenue from any pair, even if they are not the owner.

Recommendation:
To prevent unauthorized access, update the `withdrawProtocolRevenue` and `withdrawCreatorRevenue` functions to perform access control checks:

1. Introduce a mapping that stores pair owners.
2. Modify the functions to check if the calling address is the owner of the specified pair.

For example:

```solidity
mapping(uint256 => address) public pairOwners;

constructor() {
    // Initialize the pairOwners mapping with the poolOwner addresses during initialization
    for (uint256 pairId; pairId < globalData.pairs.length; pairId++) {
        pairOwners[pairId] = globalData.pairs[pairId].poolOwner;
    }
}

function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external onlyPoolOwner(pairId) {
    // ... the rest of the function
}

function withdrawCreatorRevenue(uint256 pairId, bool isQuoteToken) external onlyPoolOwner(pairId) {
    // ... the rest of the function
}
```

Implementing this change will help prevent unauthorized access and ensure the correct behavior of the contract.
