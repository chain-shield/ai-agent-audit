# Vulnerability details

## Impact
`operator` variable is a state variable that represents the address of the contract operator. It is initialized with the value of `msg.sender` in the `initialize` function. However, the line `operator = msg.sender;` is executed after the call to `AddPairLogic.initializeGlobalData(globalData, uniswapFactory);`.

[src/PredyPool.sol#initialize ](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L70-L75)
```solidity
    function initialize(address uniswapFactory) public initializer {
        __ReentrancyGuard_init();
        AddPairLogic.initializeGlobalData(globalData, uniswapFactory);


        operator = msg.sender;
    }
```

## Proof of Concept
Let's consider this hypothetical scenario where the `initializeGlobalData` function has the following logic:
```solidity
function initializeGlobalData(GlobalDataLibrary.GlobalData storage global, address uniswapFactory) external {
    // Some initialization logic...

    // Access control check that relies on the operator variable
    require(msg.sender == global.operator, "Only operator can initialize global data");

    // More initialization logic...
}
```
In this case, the access control check `require(msg.sender == global.operator, "Only operator can initialize global data"); `will fail because the operator variable has not been set correctly at this point during the initialization process.

## Recommended Mitigation Steps
```solidity
function initialize(address uniswapFactory) public initializer {
    __ReentrancyGuard_init();
    operator = msg.sender; // Move this line before calling external functions
    AddPairLogic.initializeGlobalData(globalData, uniswapFactory);
}
```
By setting the `operator` variable before calling `initializeGlobalData`, we ensure that any logic within that function or its dependencies that relies on the `operator` is set correctly will work as intended, and the contract's state will be initialized correctly during the initialization process.
