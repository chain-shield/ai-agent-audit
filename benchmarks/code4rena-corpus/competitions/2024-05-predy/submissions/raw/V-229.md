# Vulnerability details

## Impact
[PerpOrderV3Lib.resolve](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpOrderV3.sol#L78-L80) responsible for resolving the order details and verifying the signature. Passing an empty `bytes("")` as the signature could have the following consequences:

**`Signature Verification Bypass`** If the `resolve` does not handle the empty signature case properly, it could bypass the signature verification process entirely. This would allow anyone to execute orders without a valid signature, leading to a severe security vulnerability.

Even if the resolve function handles the empty signature case gracefully (e.g., by reverting the transaction), passing an empty signature could lead to unintended order execution or unexpected behavior.

Relevant Code:
The `PerpOrderV3Lib.resolve` is defined in the `PerpOrderV3.sol` file: https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpOrderV3.sol#L78-L80
```solidity
// File: src/markets/perp/PerpOrderV3.sol
function resolve(PerpOrderV3 memory perpOrder, bytes memory sig) internal pure returns (ResolvedOrder memory) {
    return ResolvedOrder(perpOrder.info, perpOrder.entryTokenAddress, perpOrder.marginAmount, hash(perpOrder), sig);
}
```
The `hash` function, which is used to calculate the order hash for signature verification, is defined in the same file:
```solidity
function hash(PerpOrderV3 memory order) internal pure returns (bytes32) {
    return keccak256(abi.encode(PERP_ORDER_V3_TYPE_HASH, order.info.hash(), order.pairId, order.entryTokenAddress, keccak256(bytes(order.side)), order.quantity, order.marginAmount, order.limitPrice, order.stopPrice, order.leverage, order.reduceOnly, order.closePosition, keccak256(order.auctionData)));
}
```
As can be seen, the `resolve` function does not perform any validation or checks on the provided `sig` parameter. If an empty `bytes("")` is passed, it will be used as-is in the `ResolvedOrder` struct, potentially leading to the issues mentioned above.

## Proof of Concept
Assume that the `PerpMarketV1` contract's `_executeOrderV3` function relies on the `ResolvedOrder` struct returned by `PerpOrderV3Lib.resolve` to verify the signature and execute the order. If an attacker can call the `quoteExecuteOrderV3` function with an empty signature, they could potentially bypass the signature verification and execute arbitrary orders without proper authorization. ## Recommended Mitigation Steps
Pass the actual signature of the order instead of an empty `bytes("")`.
Ensure that the `PerpOrderV3Lib.resolve` function handles the empty signature case correctly and does not introduce any vulnerabilities or unintended behavior.
