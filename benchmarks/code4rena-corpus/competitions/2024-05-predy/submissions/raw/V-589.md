# Vulnerability details

## Impact

The incorrect handling of negative tick deltas in the [callUniswapObserve](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L35) function can lead to inaccurate price calculations. This mispricing can affect any contract logic that relies on these prices, such as trading strategies, arbitrage opportunities, and risk management systems

## Proof of Concept

The issue arises when calculating the tick from cumulative tick values over a specified period, where the result of the division is not handled correctly for negative values. Here's a demonstration of how this can lead to incorrect calculations:

```javascript
// Assume these are the observed tick cumulatives at two different times for a given pool
int56 tickCumulativeNow = -100000; // Current cumulative tick
int56 tickCumulativePast = -50000; // Cumulative tick 30 minutes ago
uint256 ago = 1800; // 30 minutes in seconds

// Incorrect calculation due to Solidity's default rounding towards zero for negative numbers
int24 tick = int24((tickCumulativeNow - tickCumulativePast) / int56(ago)); // Results in -27 instead of the correct -28

// This results in a higher sqrtPriceX96 than expected
uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(tick);
```

This simplified example shows how a negative tick delta that is not divisible by the period (ago) results in a tick that is less negative than it should be, leading to a higher price calculation.
