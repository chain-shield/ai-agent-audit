# Vulnerability details

## Impact
The old `settlementParams.contractAddress`  will continue to have `ERC20` token approvals for `Token` so it can continue to spend the  tokens when this is not the protocol's intention as it has changed settlementParams.contractAddress


## Proof of Concept

Below in the function `_execSell()` :

```solidty
  function _execSell(
        address quoteToken,
        address baseToken,
        SettlementParams memory settlementParams,
        uint256 price,
        uint256 sellAmount
    ) internal {
        if (settlementParams.contractAddress == address(0)) {
            uint256 quoteAmount = sellAmount * price / Constants.Q96;

            ERC20(baseToken).safeTransfer(msg.sender, sellAmount);

            ERC20(quoteToken).safeTransferFrom(msg.sender, address(this), quoteAmount);

            return;
        }
      
     @----->   ERC20(baseToken).approve(settlementParams.contractAddress, sellAmount);

        //  //       //      //    //   
    }

```
This allows the contract to enter a state where `settlementParams.contractAddress` is updated via [settlementParams struct](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/interfaces/IFillerMarket.sol#L16) and [updateWhitelistSettlement()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/base/BaseMarketUpgradable.sol#L140) function but the ERC20 token approvals given to the old `contractAddress` are not removed. 

This includes 3 other instances  in the functions [buy()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/base/SettlementCallbackLib.sol#L158) , [sell()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/base/SettlementCallbackLib.sol#L111)  and 
[__execBuy()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/spot/SpotMarket.sol#L305)
