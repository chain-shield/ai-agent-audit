# Vulnerability details

## Incorrect calculation of decayedSlippageTorelance
When calculating [upper bound](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/math/Bps.sol#L7) of the price it is used current price and bps value. But when calculating the upper bound price in [validateStopPrice](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L147) function it is used decayed price for bps value. So it finally caused incorrect comparison [here](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L161).

## Proof of Concept
```solidity
function validateStopPrice(
        uint256 oraclePrice,
        uint256 tradePrice,
        int256 tradeAmount,
        uint256 stopPrice,
        bytes memory auctionData
    ) internal pure returns (bool) {
        AuctionParams memory auctionParams = abi.decode(auctionData, (AuctionParams));

        uint256 decayedSlippageTorelance = DecayLib.decay2(
            auctionParams.startPrice,
            auctionParams.endPrice,
            auctionParams.startTime,
            auctionParams.endTime,
            ratio(oraclePrice, stopPrice)
        );

        if (tradeAmount > 0) {
            // buy
            if (stopPrice > oraclePrice) {
                return false;
            }

            if (tradePrice > Bps.upper(oraclePrice, decayedSlippageTorelance)) {
                return false;
            }
```

Here [decay2](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/DecayLib.sol#L16) function returns the price value. Its a decay price between startPrice and endPrice relative to current time. But when calculating the [upper bound of the price](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/math/Bps.sol#L7) , it should be given oracle Price and BPS value.But here its used decay price as a bps value. Even when considering the units it can be proven. 

 Here it is compare the two price values. 
```solidity
tradePrice > Bps.upper(oraclePrice, decayedSlippageTorelance)
```
```solidity
 function upper(uint256 price, uint256 bps) internal pure returns (uint256) {
        return price * bps / ONE;
    }
```
 But with this implemenation Bps.upper(oraclePrice, decayedSlippageTorelance) , units is in price^2 . Since oraclePrice and decayedSlippageTorelance are in price units and ONE is unitless ratio. 

## Impact
Due to this , [decayedSlippageTorelance](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L147C17-L147C40) returns price value between start and stop price so its a relative big number compared to BPS value as well as ONE. (Since ONE is 1e6 , 5% bps value mean 1050000 but [here](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L147C44-L147C59)  it is a large value so eventually upper function returns a extreme large value)So [Bps.upper(oraclePrice, decayedSlippageTorelance)](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L161C30-L161C78) returns a big number which is allowed to do higher [trade price](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L161C17-L161C18) that is unfavorable to user.
