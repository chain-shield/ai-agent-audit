# Vulnerability details

## Summary

The current implementation of the system employs a `PriceFeed.sol` contract. Which is an option for pair owners to create a price feed and add it to the pair, if they decide not to add, the price defaults from the uniswapv3s' twap oracle.


```solidity
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();
        

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        require(quoteAnswer > 0 && basePrice.price > 0);

        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;

        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```

However the function (especially the chainlink price feeds implementation) lacks addititonal checks to make sure the price returned is fresh.

1. Not checking for stale data.
- Oracle data feeds can return data for a variety of reason, in the current implementation, if any of the chainlink data feeds were to go stale, the code will run without a problem. Since the `getSqrtPrice` function is also getting the price from the Pyth network, the function can return really incorrect prices, which can affect the protocol


Consider checking if the price returned is fresh.

```diff
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
-       (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        be different

```

2. Since the code will be deployed mostly on L2 networks, the current implementation is not checking, if the L2 sequencer for any of the price feeds is down

- When using Chainlink price feeds with L2 chains like Arbitrum (which is currently in scope), it is reccomended to check whether the L2 sequencer is down to avoid stale pricing data that appears fresh.

Consider getting the sequncer in the constructor of the `PriceFeedLibrary` like done with pyth and pass it on to the `PriceFeed`. The addresses to L2 sequncers for the corresponding chain can be found [here](https://docs.chain.link/data-feeds/l2-sequencer-feeds#available-networks)

```diff
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();
+       (, int256 answer, uint256 startedAt,,) = sequencerUptimeFeed.latestRoundData();


        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        // Answer == 0: Sequencer is up
        // Answer == 1: Sequencer is down
+       bool isSequencerUp = answer == 0;
+       uint256 timeSinceUp = block.timestamp - startedAt;

+        require(isSequencerUp);
         //@note -> Different sequencers might have different hearbeats.
+        require(timeSinceUp > 3600);
    
        if (timeSinceUp <= GRACE_PERIOD_TIME) {
            revert GracePeriodNotOver();
        }

        require(quoteAnswer > 0 && basePrice.price > 0);

```

3. Oracles are able to return inccorect prices during flash crashes.

- Chainlink oracles have in-built minimum & maximum prices they will return. If anything was to happen to the prices (flash crash, depeging) and the price drops below the oracle's minimum price. The oracle will now return the minimum price instead of the actual price. Which can open doors for attackers to buy the asset on somewhere else (DEX) for cheaper, and come here to open a position here with the incorrect price..

```diff
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();


        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");
    
        if (timeSinceUp <= GRACE_PERIOD_TIME) {
            revert GracePeriodNotOver();
        }
+       require(price >= minPrice && price <= maxPrice);
        require(quoteAnswer > 0 && basePrice.price > 0);

        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;

        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```

Applying those fixes above, will make sure that the prices returned by the PriceFeed contract will always be up to date and the protocol will not be operating with stale prices.
