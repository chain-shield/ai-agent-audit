# Vulnerability details

## Impact
When a trader opens a short position (i.e., `sqrtPerp.amount` is negative), the fees should be negative, representing a cost to the trader. However, due to the way the fee calculation is implemented, the fees for short positions are calculated as positive values, which is counterintuitive and incorrect.

Relevant Code:
The problematic code is in the `else if` block of the `computePremium` function, where the fee calculation for short positions is handled: [computePremium#L77-L84](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PerpFee.sol#L77-L84)
```solidity
else if (sqrtPerp.amount < 0) {
    growthDiff0 = baseAssetStatus.sqrtAssetStatus.borrowPremium0Growth - sqrtPerp.entryTradeFee0;
    growthDiff1 = baseAssetStatus.sqrtAssetStatus.borrowPremium1Growth - sqrtPerp.entryTradeFee1;
}

int256 fee0 = Math.fullMulDivDownInt256(sqrtPerp.amount, growthDiff0, Constants.Q128);
int256 fee1 = Math.fullMulDivDownInt256(sqrtPerp.amount, growthDiff1, Constants.Q128);
```
The issue lies in the calculation of `growthDiff0` and `growthDiff1`. For short positions, `sqrtPerp.amount` is negative, but `baseAssetStatus.sqrtAssetStatus.borrowPremium0Growth` and `baseAssetStatus.sqrtAssetStatus.borrowPremium1Growth` are expected to be positive and increasing over time.

This means that the calculated `growthDiff0` and `growthDiff1` values will be negative, as they are the difference between the positive `borrowPremium0Growth` and `borrowPremium1Growth` values and the smaller `entryTradeFee0` and entryTradeFee1 values.

When these negative `growthDiff0` and `growthDiff1` values are multiplied by the negative `sqrtPerp.amount` in the subsequent [lines 83-84](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PerpFee.sol#L83-L84)
```solidity
int256 fee0 = Math.fullMulDivDownInt256(sqrtPerp.amount, growthDiff0, Constants.Q128);
int256 fee1 = Math.fullMulDivDownInt256(sqrtPerp.amount, growthDiff1, Constants.Q128);
```
The resulting `fee0` and `fee1` values become positive, which is incorrect for a short position.

## Proof of Concept
Assume the following values:

`sqrtPerp.amount` = -10000000000 (a short position)
`baseAssetStatus.sqrtAssetStatus.borrowPremium0Growth` = 1000000
`baseAssetStatus.sqrtAssetStatus.borrowPremium1Growth` = 2000000
`sqrtPerp.entryTradeFee0` = 500000
`sqrtPerp.entryTradeFee1` = 1000000

In this scenario, the calculations would be:
```solidity
growthDiff0 = 1000000 - 500000 = 500000
growthDiff1 = 2000000 - 1000000 = 1000000

fee0 = -10000000000 * 500000 / 2^128 = -500000000 (should be positive)
fee1 = -10000000000 * 1000000 / 2^128 = -1000000000 (should be positive)
```
You can see, the calculated `fee0` and `fee1` values are negative, which is incorrect for a short position, where the fees should represent a cost to the trader and should be positive.

## Recommended Mitigation Steps
Consider negating the `growthDiff0` and `growthDiff1` values when `sqrtPerp.amount` is negative, like this.
```solidity
if (sqrtPerp.amount < 0) {
    growthDiff0 = sqrtPerp.entryTradeFee0 - baseAssetStatus.sqrtAssetStatus.borrowPremium0Growth;
    growthDiff1 = sqrtPerp.entryTradeFee1 - baseAssetStatus.sqrtAssetStatus.borrowPremium1Growth;
}
```
This way, when `sqrtPerp.amount` is negative, `growthDiff0` and `growthDiff1` will be positive, and when multiplied by the negative `sqrtPerp.amount`, the resulting `fee0` and `fee1` values will be negative, as expected for a short position.
