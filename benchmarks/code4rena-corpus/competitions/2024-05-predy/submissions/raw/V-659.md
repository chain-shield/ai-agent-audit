# Vulnerability details

## Impact
The protocol team expects that anyone can freely add pairs to the PredyPool. Currently, adding a new pair requires the user to have an operator role. Given that everyone will be able to add pairs, the operator role can be assigned to everyone or removed entirely.

The `withdrawProtocolRevenue` function, which handles the logic for withdrawing the protocol revenue, has an `onlyOperator` restriction. If anyone can have the operator role or it is removed entirely, then everyone can withdraw the protocol revenue because the tokens are sent directly to` msg.sender`.

```solidity
if (amount > 0) {
    ERC20(pool.token).safeTransfer(msg.sender, amount);
}
```

The funds of the protocol can easily be drained if the operator role is not handled correctly, especially if everyone can have the role.


## Tools Used
Manual Review

## Recommended Mitigation Steps
Send the revenue to the treasury address of the protocol instead of to msg.sender
