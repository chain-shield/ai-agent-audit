# Vulnerability details

## Impact
Trade transactions can be DOS’d causing [`trade(...)`](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/TradeLogic.sol#L42) calls to revert because the `currentTick` is sourced from `slot0` of the pool.

## Proof of Concept
Users call `trade(...)` to open a trade position and in the process a call is made to `Perp::computeRequiredAmounts(...)` to compute required amounts to increase or decrease `sqrt` positions.

However, there is a [safeguard](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Reallocation.sol#L92-L104) to ensure the trade call reverts when the specified tick is outside the range specified for the trade and this is done using `slot0` which is the most recent price tick in the pool. `slot0` is easily manipulated.

This allows a malicious user to manipulate the `currentTick` pushing it further away from the actual current tick in the pool and causing the `trade(...)` call to revert an as such the malicious user can conveniently DoS trades at will.
