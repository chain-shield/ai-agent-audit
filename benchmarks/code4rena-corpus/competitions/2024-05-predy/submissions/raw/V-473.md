# Vulnerability details

## Impact

For the first vault ever created, if the user tries to reduce/close his position, we will always try to create a new vault with a negative margin, which will ultimately revert/


## Proof of Concept

Before executing a trade inside of `PredyPool::trade`, we are first checking, if we should get or create a vault.

As we can see from the snippet above, the first ever vault will be an id of 0, and the order will get executed succesfully.

However, if the user decides to reduce/lower the position there can be many problems.

1. The user creates the first ever position, also creates the first ever vault

2. Some time passes and the user decides to reduce the position calling any of the markets with `reduceOnly=true`.

For simplcity I will use the `PerpMarketV1.sol` as an example.


The filler will call `PerpMarketV1::executeOrderV3` which will decode the order and pass it to `PerpMarketV1::_executeOrderV3` an internal function, which handles the logic of the trade.


The problem occurs inside of `PredyPool::trade`. Since the the user's vault is at id of 0. The function will create a new vault, and since we are reducing the position and most of the values are negative the newer vault's margin will be negative, hence not passing the safeCheck.


```solidity

        GlobalDataLibrary.GlobalData storage globalData,
        IPredyPool.TradeParams memory tradeParams,
        bytes memory settlementData
    ) external returns (IPredyPool.TradeResult memory tradeResult) {

        ApplyInterestLib.applyInterestForToken(globalData.pairs, tradeParams.pairId);

        Perp.updateRebalanceInterestGrowth(pairStatus, pairStatus.sqrtAssetStatus);

        tradeResult = Trade.trade(globalData, tradeParams, settlementData);


        globalData.vaults[tradeParams.vaultId].margin +=
            tradeResult.fee + tradeResult.payoff.perpPayoff + tradeResult.payoff.sqrtPayoff;

        (tradeResult.minMargin,,, tradeResult.sqrtTwap) = PositionCalculator.calculateMinMargin(
            pairStatus, globalData.vaults[tradeParams.vaultId], DataType.FeeAmount(0, 0)
        );
        
        // @review - Here we call, PerpMarketV1::predyTradeAfterCallback.
        // And since the amount for the trade is negative, because we are reducing the position, the callback will take from the pool resulting in a negative margin update.
        callTradeAfterCallback(globalData, tradeParams, tradeResult);

            PositionCalculator.checkSafe(pairStatus, globalData.vaults[tradeParams.vaultId], DataType.FeeAmount(0, 0));
```
