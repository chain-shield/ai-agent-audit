# Vulnerability details


## Impact
The supply function allows users to supply quoteToken or baseToken to the lending pool without checking the slippage.
This can lead to a loss of funds for the user if the slippage is not checked.

## Proof of Concept
The user receives the bond token when supplying the quoteToken or baseToken.
The bond token amount is calculated based on the amount of quoteToken or baseToken divided by the assetScaler.

When supply, the bond amount to be received is calculated as follows: (https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L42)
> claimAmount = _amount * Constants.ONE / tokenState.assetScaler;

When withdraw, the bond amount to be burned is calculated as follows: (https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L57-L65)
> burnAmount = _amount * Constants.ONE / tokenState.assetScaler;

>finalWithdrawAmount = finalBurnAmount * tokenState.assetScaler / Constants.ONE;

This assetScaler will be increased in ScaledAsset.updateScaler function.(https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L210)

The interest rate can not be changed in the same block ([applyInterestForToken](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L32))

However, the attacker can obstruct the user's supply or withdrawal transaction by providing more gas than the user's transaction.
If the attacker's supply transaction is executed in the previous block and the user's supply occurs in the subsequent block, the attacker can withdraw more tokens.

## Tools Used
Manual review

## Recommended Mitigation Steps
It's recommended to add the slippage check in the supply and withdraw functions to prevent the loss of funds for the user.
