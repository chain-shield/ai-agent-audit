# Vulnerability details

## Impact
[Reallocation:calculateMinLowerTick](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/Reallocation.sol#L126-L142), In [Line:137](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/Reallocation.sol#L137)
```solidity
minLowerTick += tickSpacing;
```
This line adds `tickSpacing` to the calculated `minLowerTick`, but according to the "UniswapV3" documentation, the tick values should be multiples of the `tickSpacing`. By adding `tickSpacing` to `minLowerTick`, the resulting value may not be a valid tick value.

## Proof of Concept
The line `minLowerTick += tickSpacing;` in the `calculateMinLowerTick` is problematic because it can lead to an invalid tick value being generated.

In the Uniswap V3 protocol, tick values are used to represent price ranges. The `tickSpacing` parameter is used to define the spacing between valid tick values. For example, if `tickSpacing` is set to 1, then valid tick values would be integers like -1, 0, 1, 2, etc. If `tickSpacing` is set to 10, then valid tick values would be multiples of 10, like -10, 0, 10, 20, etc.

The line `minLowerTick += tickSpacing;` adds the `tickSpacing` value to `minLowerTick`. However, this operation does not guarantee that the resulting `minLowerTick` value will be a valid tick value according to the specified `tickSpacing`.

For example, if `tickSpacing` is 10, and `minLowerTick` is 20, then `minLowerTick += tickSpacing;` would result in `minLowerTick` being 30. However, 30 is not a valid tick value because it is not a multiple of 10 (the `tickSpacing`).

This issue is documented in the `openzeppelin-contracts` repository's [CHANGELOG.md](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/CHANGELOG.md) file:
```solidity
# Changelog

## 4.8.3 (2023-04-13)

- `TickMath.getTickAtSqrtRatio(sqrtPrice)`: Fixed a bug where the returned tick value may not be a multiple of `tickSpacing`.
```

## Recommended Mitigation Steps
The correct approach should be to round down `minLowerTick` to the nearest multiple of `tickSpacing` instead of adding `tickSpacing`. Can be achieved by using the following expression:
```solidity
minLowerTick = (minLowerTick / tickSpacing) * tickSpacing;
```
Alternatively, use the `TickMath.getTickAtSqrtRatio` function directly, as it should handle the rounding correctly
```solidity
minLowerTick = TickMath.getTickAtSqrtRatio(sqrtPrice);
```
