# Vulnerability details

## Impact
Before explaining this finding, it's important to note that although initially the protocol mentions in contest README that pool owners are trusted, this was changed as specified in the Code4rena Predy discord:

C4 Moderator: `"In the All trusted roles in the protocol chart, the sponsor would like to also note that in the future, it is expected that anyone will be able to add pairs."` (pair = pool)

The sponsor also mentioned that `"The first pool owner is trusted, but the pool must not be affected if a non-trusted pool owner creates new pool"`

This is because the initial pools will be created by trusted roles, but new pools can be created by anyone. Therefore, the pools that can be created by anyone have an owner who is not trusted.

There is an issue within `PredyPool::updatePriceOracle` that allows a pool owner to manipulate the `sqrt price` to force liquidate `safe vaults`, causing loss for users and breaking protocol invariant.

The severity is high, as the protocol mentions in the contest README how this is one of the main invariant:

`Assuming sufficient liquidity, safe vaults cannot be liquidated, whereas unsafe vaults can be liquidated. This ensures that only positions that pose a risk to the system are targeted for liquidation, maintaining the integrity of the platform.`

## Proof of Concept
[PredyPool.sol#L167-L169](https://github.com/code-423n4/2024-05-predy/blob/main/src/PredyPool.sol#L167-L169)
```javascript
    function updatePriceOracle(uint256 pairId, address priceFeed) external onlyPoolOwner(pairId) {
        AddPairLogic.updatePriceOracle(globalData.pairs[pairId], priceFeed);
    }
```

This call updates the address of the `price feed oracle`. Note the `onlyPoolOwner(pairId)` access control modifier.

[AddPairLogic.sol#L112-L116](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/AddPairLogic.sol#L112-L116)
```javascript
    function updatePriceOracle(DataType.PairStatus storage _pairStatus, address _priceOracle) external {
        _pairStatus.priceFeed = _priceOracle;

        emit PriceOracleUpdated(_pairStatus.id, _priceOracle);
    }
```

Recall that any user can add a pair, and the user that adds a pair becomes the owner of that pool (pair is a pair of tokens in the pool). The protocol erroneously allows pool owners the ability to update the address of the price oracle, which is used to calculate the `sqrt price`.

[PositionCalculator.sol#L142-L144](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L142-L144)
```javascript
        if (pairStatus.priceFeed != address(0)) {
            return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
        }
```

Which is used for calculating `min values` of a vault

[PositionCalculator.sol#L83-L90](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L83-L90)
```javascript
    (minValue, vaultValue, debtValue, hasPosition) = calculateMinValue(
        vault.margin,
        getPositionWithFeeAmount(vault.openPosition, feeAmount),
@>      sqrtOraclePrice,
        pairStatus.riskParams.riskRatio
    );
```

The `min values` are used to determine if a vault is unsafe and should be liquidated

[PositionCalculator.sol#L41-L45](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L41-L45)
```javascript
    (minMargin, vaultValue, hasPosition, sqrtOraclePrice) = calculateMinMargin(pairStatus, _vault, feeAmount);

    bool isSafe = vaultValue >= minMargin && _vault.margin >= 0;

    _isLiquidatable = !isSafe && hasPosition;
```

Anyone can liquidate a vault if it is determined that is is unsafe.

In this case, a malicious pool owner can craft a `price oracle` contract that returns a `sqrt price` chosen to manipulate the vault values, which can allow liquidation of `safe vaults`, breaking protocol invariant and causing a loss for users.

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Do not let pool owners to update the `price oracle` address. It may be best to use the [PriceFeed contract](https://github.com/code-423n4/2024-05-predy/blob/main/src/PriceFeed.sol) as the `price oracle`.
