# Vulnerability details

## Impact
If a user wants to liquidate themselves  and calls liquidate for their particular market which ultimately checks the price [PositionCalc::getSqrtIndexPrice](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/PositionCalculator.sol#L143) through [LiquidationLogic::checkVaultinDanger](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L142)  which ultimately reverts .

## Proof of Concept
Based on the current implementation the project wants to use chainlink oracles for fetching the prices of quote tokens. But there is a known issue with chainlink that  "it is possible, chainlink's multisigs can immediately block access to price feeds at will " Thus calling ` (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();` will make the function
`PriceFeed.sol::getSqrtPrice()` revert which causes DOS of functions in cases of liquidation,  etc.

## Tools Used
Chainlink / OZ

## Recommended Mitigation Steps
Wrap the chainlink aggregator: latestAnswer fetch in a try-catch block.
