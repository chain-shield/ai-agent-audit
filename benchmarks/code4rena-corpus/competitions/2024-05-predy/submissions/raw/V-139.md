# Vulnerability details

## Impact
in the function `Reallocation::calculateUsableTick`, `result` could be zero if `tickSpacing` is greater than `_tick` which is equated to `result`. And this happens because Solidity's integer division truncates.

This will cause `result` to be zero anytime `tickSpacing` is greater than `_tick` which may occur often.
```
   function calculateUsableTick(int24 _tick, int24 tickSpacing) internal pure returns (int24 result) {
        require(tickSpacing > 0);

        result = _tick;

        if (result < TickMath.MIN_TICK) {
            result = TickMath.MIN_TICK;
        } else if (result > TickMath.MAX_TICK) {
            result = TickMath.MAX_TICK;
        }

   @>     result = (result / tickSpacing) * tickSpacing;
        // 5/10 = 0.5 but .5 is truncate in solidity, so
        // 0 x 10 = 0
    }
```

## Proof of Concept
details here: https://github.com/crytic/slither/wiki/Detector-Documentation#divide-before-multiply
Let's say `_tick` = 5 and `tickSpacng` = 10
using the formula: result = (result / tickSpacing) * tickSpacing;
on a standard math, we should get: (5/10) * 10 = 0.5 * 10 = 2
but in solidity, numbers after `.` are disregarded so we get:
(5/10)* 10
(0.5)* 10 ~ .5 is disregarded
=> (0) * 10
 result = 0;
