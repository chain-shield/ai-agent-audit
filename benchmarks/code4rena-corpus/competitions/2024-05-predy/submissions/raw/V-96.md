# Vulnerability details

## Impact
In the `calculateEntry` the calculation of `closeStableAmount` when closing a position partially. In the case where `_positionAmount.abs() >= _tradeAmount.abs()`, which represents a partial position close, the calculation of `closeStableAmount is`: [#L689](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L689)
```solidity
int256 closeStableAmount = _entryValue * _tradeAmount / _positionAmount;
```
This calculation assumes that the `_entryValue` is the entry value for the entire position. However, when closing a position partially, the entry value should be proportional to the amount being closed.

## Proof of Concept
`calculateEntry` is responsible for calculating the payoff when a position is being closed or partially closed. It takes four parameters:

`_positionAmount`: The current position amount (positive for long, negative for short).
`_entryValue`: The entry value of the position (the value at which the position was opened).
`_tradeAmount`: The trade amount (positive for buy, negative for sell).
`_valueUpdate`: The value update (the difference between the entry value and the current value).

The function handles two cases when closing a position:

**`Full position close`**: When `_positionAmount.abs() < _tradeAmount.abs()`, the entire position is being closed.
**`Partial position close`**: When `_positionAmount.abs() >= _tradeAmount.abs()`, only a portion of the position is being closed.

In the case of a partial position close, the function calculates the `closeStableAmount` using the following line: [#L689](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L689)
```solidity
int256 closeStableAmount = _entryValue * _tradeAmount / _positionAmount;
```
The issue with this calculation is that it assumes that `_entryValue` is the entry value for the entire position. Although, when closing a position partially, the entry value should be proportional to the amount being closed.

For example, let's consider a trader with a long position of 100 units with an entry value of 10. If the trader wants to close 50 units of the position, the correct entry value for the closed portion should be 5 (50% of 10). However, the current calculation will use the full entry value of 10, leading to an incorrect payoff calculation.

For the impact, let's consider a scenario where the `_valueUpdate` is 12. The correct payoff for closing 50 units should be:
```solidity
closeStableAmount = 5 (proportional entry value for 50 units)
payoff = _valueUpdate - closeStableAmount = 12 - 5 = 7
```
But the current implementation will calculate
```solidity
closeStableAmount = 10 * 50 / 100 = 5 (incorrect, using full entry value)
payoff = _valueUpdate - closeStableAmount = 12 - 5 = 7 (incorrect payoff)
```
This incorrect calculation of `closeStableAmount` can lead to traders receiving an incorrect payoff when partially closing a position, potentially resulting in financial losses or gains that should not have occurred.

## Recommended Mitigation Steps
The calculation of `closeStableAmount` should be adjusted to account for the proportional entry value by introducing a new variable to store the proportional entry value, like this:
```solidity
int256 proportionalEntryValue = _entryValue * _tradeAmount / _positionAmount;
int256 closeStableAmount = proportionalEntryValue;
```
By calculating the proportional entry value first and then using it to calculate `closeStableAmount`, the function should correctly handle partial position closes.
