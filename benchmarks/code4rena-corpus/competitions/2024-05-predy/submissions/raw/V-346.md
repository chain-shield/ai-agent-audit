# Vulnerability details

## Impact
The `allowedTraders` mapping in the `PredyPool` contract does not have an explicit way to reset or remove traders. This oversight can lead to security vulnerabilities and management issues, where unauthorized or former traders might retain trading permissions inadvertently. Proper management of the `allowedTraders` mapping is crucial to ensure that only authorized traders can interact with specific trading pairs, thus maintaining the integrity and security of the trading system.

Additionally, the lack of proper management functions for the `allowedTraders` mapping can lead to significant gas consumption issues. If the list of allowed traders grows large, operations to manage or reset these traders can become very expensive and potentially result in out-of-gas errors. This can hinder the functionality and usability of the contract.

```solidity
mapping(address trader => mapping(uint256 pairId => bool)) public allowedTraders;

// Function to allow trader
function allowTrader(uint256 pairId, address trader, bool enabled) external onlyPoolOwner(pairId) {
    require(globalData.pairs[pairId].allowlistEnabled);
    allowedTraders[trader][pairId] = enabled;
}
```

The function `allowTrader` is used to manage the `allowedTraders` mapping, but it lacks comprehensive functionality for managing and resetting traders effectively.

### Out of Gas Impact
Without an efficient way to manage the `allowedTraders` list, particularly to reset or remove traders, operations on this mapping can become gas-intensive. For instance, iterating over a large list of traders to reset permissions could exceed the block gas limit, causing transactions to fail due to out-of-gas errors. This makes the contract less reliable and can prevent critical management operations from being executed.

## Tools Used
Manual

## Recommended Mitigation Steps
1. Add a function to reset all traders for a specific pair or globally.
2. Add a function to explicitly remove a trader from the allowed list.
