# Vulnerability details

## Impact
Relying solely on oracle-based slippage parameters can lead to significant losses due to sandwich attacks. Attackers can exploit the slippage tolerance to manipulate prices and profit at the expense of the transaction initiator.

## Proof of Concept
The liquidate function currently relies on the oracle to check if price is within the slippage tolerance. The differences between the true value and the oracle value can be systematically exploited via sandwich attacks. these losses can cause significant loss

```javascript
// Check if the price is within the slippage tolerance range to ensure that the price does not become
// excessively favorable to the liquidator.
SlippageLib.checkPrice(
    sqrtOraclePrice,
    tradeResult,
    slippageTolerance,
    tradeParams.tradeAmountSqrt == 0 ? 0 : _MAX_ACCEPTABLE_SQRT_PRICE_RANGE
);
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Allow liquidators to specify their own slippage value while ensuring it is within a reasonable margin of the oracle price. This approach combines user-defined slippage limits with oracle-based validation to provide better protection against manipulation.
