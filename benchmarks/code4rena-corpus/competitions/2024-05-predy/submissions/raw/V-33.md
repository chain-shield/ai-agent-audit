# Vulnerability details

Introduction
This report outlines a replay attack vulnerability identified in the PerpMarketV1 contract. This flaw allows a malicious actor to re-execute the same order multiple times, leading to potential financial loss and system abuse.

Impact
The vulnerability can result in:

Unauthorized repeated execution of trades.
Significant financial loss due to repeated order execution.
Degradation of trust in the system's security.
Explanation
The executeOrderV3 function in PerpMarketV1 lacks mechanisms to prevent replay attacks. Specifically, it does not use nonces or unique identifiers to ensure each order is executed only once. This oversight allows attackers to replay captured orders.

This PoC shows that the same order is processed multiple times, demonstrating the replay attack vulnerability.

Fix:
Introduce a nonce or unique identifier for each order to ensure it can only be executed once.

Fixed Code Example:

solidity
Copy code
mapping(bytes32 => bool) public executedOrders;

function executeOrderV3(SignedOrder memory order, SettlementParamsV3 memory settlementParams)
    external
    nonReentrant
    returns (IPredyPool.TradeResult memory)
{
    bytes32 orderHash = keccak256(abi.encode(order));
    require(!executedOrders[orderHash], "Order already executed");

    executedOrders[orderHash] = true;

    PerpOrderV3 memory perpOrder = abi.decode(order.order, (PerpOrderV3));
    return _executeOrderV3(perpOrder, order.sig, settlementParams, 0);
}

Fix
To prevent replay attacks, introduce a nonce or unique identifier for each order, ensuring it can only be executed once.
