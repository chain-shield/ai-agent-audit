# Vulnerability details

## Impact
Attacker can submit two different prices to update Pyth Oracle in order to perform arbitrage transaction within a single transaction.



## Proof of Concept
The GammaTradeMarketWrapper.sol is in scope.

An attacker can pass 2 different prices to Pyth oracle in order perform 2 trades with the `executeTrade(...)` for arbitrage profits. The `executeTrade(...)` function will be called twice with 2 different prices updated to Pyth oracle in a single transaction.

```solidity
File: GammaTradeMarketWrapper.sol
contract GammaTradeMarketWrapper is GammaTradeMarketL2 {
    // execute trade
    function executeTrade(GammaOrder memory gammaOrder, bytes memory sig, SettlementParamsV3 memory settlementParams)
        external
        returns (IPredyPool.TradeResult memory tradeResult)
    {
        return _executeTrade(gammaOrder, sig, settlementParams);
    }
}

```

## Recommended Mitigation Steps
Consider adding the nonRentrant modifier to the `executeTrade(...)` function.

```diff
File: GammaTradeMarketWrapper.sol
--  contract GammaTradeMarketWrapper is GammaTradeMarketL2 {
++ contract GammaTradeMarketWrapper is GammaTradeMarketL2, ReentrancyGuard {
    // execute trade
    function executeTrade(GammaOrder memory gammaOrder, bytes memory sig, SettlementParamsV3 memory settlementParams)
        external
++      nonReentrant
        returns (IPredyPool.TradeResult memory tradeResult)
    {
        return _executeTrade(gammaOrder, sig, settlementParams);
    }
}
```
