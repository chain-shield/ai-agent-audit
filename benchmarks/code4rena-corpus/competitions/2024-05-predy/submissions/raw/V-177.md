# Vulnerability details

## Impact
The `hash` function does not include the `chainid` in its hash calculation. This omission makes it vulnerable to replay attacks across different chains. In such attacks, a valid transaction executed on one chain can be replayed on another chain, leading to unintended consequences such as the loss of funds or unexpected behaviors.

As specified by the EIP4337 standard to prevent replay attacks ... the signature should depend on chainid

## Proof of Concept

The vulnerability arises because the hash calculation does not differentiate between chains. Here’s how a replay attack could occur:

On Chain A:

A user signs an `OrderInfo` transaction and submits it.
The transaction is processed and executed as expected.
On Chain B:

An attacker replays the same signed `OrderInfo` transaction from Chain A.
Since the hash calculation is the same and the signature is valid, the transaction is processed on Chain B as well.
The hash function currently looks like this:

```javascript
/// @notice hash an OrderInfo object
/// @param info The OrderInfo object to hash
function hash(OrderInfo memory info) internal pure returns (bytes32) {
    return keccak256(abi.encode(ORDER_INFO_TYPE_HASH, info.market, info.trader, info.nonce, info.deadline));
}
```
Example
Consider the following OrderInfo object:

```javascript
OrderInfo memory order = OrderInfo({
    market: "ETH/USD",
    trader: msg.sender,
    nonce: 1,
    deadline: block.timestamp + 1 days
});
```
Without including `chainid`, the hash for this order will be the same on any chain, making it susceptible to replay attacks.

The issue was also found in other protocols as shown below

https://solodit.xyz/issues/m-03-cross-chain-signature-replay-attack-code4rena-biconomy-biconomy-smart-contract-wallet-contest-git

## Recommended Mitigation Steps
Include the chainid in the hash calculation.

```javascript
/// @notice hash an OrderInfo object
/// @param info The OrderInfo object to hash
function hash(OrderInfo memory info) internal view returns (bytes32) {
    return keccak256(abi.encode(
        ORDER_INFO_TYPE_HASH,
        info.market,
        info.trader,
        info.nonce,
        info.deadline,
        block.chainid  // Include chain id to prevent replay attacks
    ));
}
```
