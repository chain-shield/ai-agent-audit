# Vulnerability details

## Impact
The documentation specifies the calculation of the `PremiumCurve` based on the utilization rate (UR):
- For UR ≤ 0.1, the output should be 0.
- For 0.1 < UR, the formula `1.6 * (UR - 0.1)^2` applies.
However, the `calculatePremiumCurve` method incorrectly returns 0 for UR values below 0.125, leading to precision loss.

```javascript
function calculatePremiumCurve(uint256 utilization) internal pure returns (uint256) {
        if (utilization <= Constants.SQUART_KINK_UR) {
            //10 * 1e16 = 1e17 = 0.1 basis point
            return 0;
        }

        uint256 b = (utilization - Constants.SQUART_KINK_UR);

@>      return (1600 * b * b / Constants.ONE) / Constants.ONE;
        //assuming utilization rate = 0.125 :: 125e16
        //b= 125e16 - 1e17 = 2.5e16
        //1600b*b = 1600*2.5e16*2.5e16/1e36 = 1e36 /1e36 = 1
    }
```
Moreover, since this function is utilized to calculate the fee's growth parameter in `perp::updateFeeAndPremiumGrowth`, the protocol may receive less fees in cases of low utilization rates. This miscalculation could significantly impact the protocol's revenue, especially in scenarios where precise fee calculations are crucial for profitability and operational efficiency.

## Recommended Mitigation Steps
The current scaling factor in the `calculatePremiumCurve` function is insufficient, resulting in precision loss for UR values below 0.125. To address this, increase the scaling factor from 1e3 to 1e4 to accurately reflect the calculations specified in the documentation.
