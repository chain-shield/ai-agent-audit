# Vulnerability details

## Impact

The function that handles the swap of quote and base tokens checks the balance of the contract for each of the tokens, which can be manipulated with a small donation, leading to a revert and therefore a `Denial of Service`.

## Proof of Concept

When the function [executeOrder](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L85-L92) in [SpotMarket](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol) gets called, it calls its internal function, which in turn calls [_swap](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L206-L226). The [_swap](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L206-L226) function makes sure that the reserves of both the `quote` and `base` tokens remain accurate after a settlement is executed. That same settlement takes place due to the call to [_execSettlement](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L228-L247), which poses a risk of the reserves getting updated inaccurately. Because of this, the balance before and after the call is saved in variables, however, there’s an issue in the way the balances are got after the settlement:
```solidity
 …
    _execSettlement(spotOrder.quoteToken, spotOrder.baseToken, settlementParams, - totalBaseAmount);

    uint256 afterQuoteReserve = ERC20(spotOrder.quoteToken).balanceOf(address(this));
 @> uint256 afterBaseReserve = ERC20(spotOrder.baseToken).balanceOf(address(this));
 …
```
By directly checking the balance of each token with `balanceOf(address(this))`, a malicious user could back-run the call to `_execSettlement` by donating `1 wei` to the base token balance. The small discrepancy of `1 wei` would make the following [check](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L221-L223) revert:
```solidity
 if (totalBaseAmount + baseReserve.toInt256() != afterBaseReserve.toInt256()) {
  revert BaseCurrencyNotSettled();
 }
```

The flow of the attack is simple, imagine the following scenario:
1. Alice notices a fluctuation in the prices, so she creates a new order.
2. After [executeOrder](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/spot/SpotMarket.sol#L85-L92) is called, the logic behind opening a new position is being executed.
3. Bob spots the call to `_execSettlement` and back-runs it by donating `1 wei` to the `base` token balance of the contract.
4. The call reverts, and Alice has her strategy broken.

This could be repeated numerous times, as `1 wei` is such a miniscule amount that it wouldn’t cost anything for Bob to deny Alice for however long he wants to.

As a conclusion: a bot could be set up in such a way that multiple calls could be reverted with a small amount of `1 wei`, which breaks one of the core functionalities of the `SpotMarket` contract.

## Tools Used

Manual Review

## Recommended Mitigation Steps

For this issue to be resolved, a mapping within the `SpotMarket` contract should be created that tracks its balance for both the quote and base tokens, which would only be increased by internal calls in the contract.
