# Vulnerability details

## Summary 
As for the sponsor's word, it is said to assume that in the future anyone will be able to create a pair.


However with the creation of the pair the user can specify any price feed address he wants, or even create a malicious one through the `PriceFeedFactory.sol::createPriceFeed`

```solidity
    function createPriceFeed(address quotePrice, bytes32 priceId, uint256 decimalsDiff) external returns (address) {
        PriceFeed priceFeed = new PriceFeed(quotePrice, _pyth, priceId, decimalsDiff);

        emit PriceFeedCreated(quotePrice, priceId, decimalsDiff, address(priceFeed));

        return address(priceFeed);
    }
```


The owner of the pair is able to change the price oracle all he wants, as there are no checks for the address

The user that registered the pair is able to change the price feed freely, whenever he likes with params of his choice by calling `PredyPool:::updatePriceOracle`.

```solidity
    function updatePriceOracle(uint256 pairId, address priceFeed) external onlyPoolOwner(pairId) {
        // @review -> No checks whether the address is a correct oracle
        AddPairLogic.updatePriceOracle(globalData.pairs[pairId], priceFeed);
    }
```

As we can see from the snippet above we are providing 
1. `quotePrice` which is the chainlink's price feed
2. `priceid`, which will be used for Pyth, which is again an oracle.
3. `decimalsDiff` which will be used to calculate the difference in decimals, when converting the price to `sqrtPrice`.


The function `PositionCalculator::getSqrtIndexPrice` is the main entry point for getting either the TWAP price or the price feed's price which widely used accross the codebase.

```solidity
    function getSqrtIndexPrice(DataType.PairStatus memory pairStatus) internal view returns (uint256 sqrtPriceX96) {
        //@review -> If there is a price feed provided, call it, either use the twap oracle
        if (pairStatus.priceFeed != address(0)) { 
            return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
        } else {
            return UniHelper.convertSqrtPrice(
                UniHelper.getSqrtTWAP(pairStatus.sqrtAssetStatus.uniswapPool), pairStatus.isQuoteZero
            );
        }
    }
```

`PositionCalculator::getSqrtIndexPrice` is called in these scenarios:

- [PerpMarketV1::_calculateInitialMargin](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L227), this function is used to calculate the marginUpdate, after a trade in `PerpMarketV1::predyTradeAfterCallback`, to determine the cost of the trade.

- [PositionCalculator::calculateMinMargin](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/PositionCalculator.sol#L83) which is a very crucial function, that checks, if the vault has enough margin to cover for initia losses. The function is also called [after executing, a trade](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/TradeLogic.sol#L55-L56) and inside of [LiquidationLogic::liquidate](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L75-L76).


As we can see from above the function is really important to keep the whole protocol running healthy.

## Proof of concept

There are many paths the creator of the pair can take in order to exploit the system, for the simplicity of the report, we will just cover a liquidation one.

The malicious price feed can be set in many ways. 

- Bob can just create a malicious contract the just has the `getSqrtPrice` and returns a hardcoded price and call `PredyPool::updatePriceOracle` to set the oracle to the maliciously crafted one.
- Bob can deploy via the `PriceFeedFactory::createPriceFeed` and pass wrong `decimalsDiff` or again a `quotePrice` address that returns hardcoded price and again set it.

PoC: 
1. Bob creates a pair and does not provide any price feed address, in order for `PositionCalculator::getSqrtIndexPrice` to default to the uniswapv3's twap, and then supplies the pair in order to have some initial value.

2. Bob waits for the pair to gain attraction and money in it.

3. After that in one transaction, Bob changes the price feed to a malicious one causing the price to drop brutally, after that bob in a for loop, can liquidate every user that has positions on his pair, and steal the money from perfectly healthy positions.

4. Bob then transfers the money to himself and walks away with the profit


## Recommended Mitigation

My recommended mitigation for when the time comes to allow anyone to create a pair is:

- Save the created priceFeeds and only allow to set the price feed address, if it is created through the factory.

```diff
    function updatePriceOracle(uint256 pairId, address priceFeed) external onlyPoolOwner(pairId) {
+       require(priceFeedFactory.isPriceFeed(priceFeed))
        AddPairLogic.updatePriceOracle(globalData.pairs[pairId], priceFeed);
    }
```
- Create some kind of a queue mechanism, where a owner can approve the createdPriceFeeds. (Check for wrong chainlink address, check for wrong decimalsDiff)
