# Vulnerability details

## Impact
Predy Pool uses permit2.permitWitnessTransferFrom(),to verify for the signature of the user, but none of them check token used is *entryAddresstoken*. Allowing a filler to use permit signature from any ERC20 token use it for trades.

## Proof of Concept
Let a user signs a order with USDC as the quote token but If a user had already permitted a different token, say USDT for a different market then the filler can take the token USDT and use it for order execution since there are no specific checks for the token

In GammaMarket the check is done directly since the amount of additional collateral is specified by the user in [here](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L160)
In PerpMarket the user specifies the leverage, So the verification is done when exact amount of collateral is determined after the transaction in [here](
https://github.com/code-423n4/2024-05predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L123)

This might result in a huge loss for the users since the order is highly dependent on the token, & they can be liquidated early by other users making a profit for them in the process.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add this in `verifyOrder` of GamaTradeMarket.sol & `verifyOrderV3` PredyMarket.sol
```require(entryTokenAddress==permit.permittedToken,"Not the correct token");```
