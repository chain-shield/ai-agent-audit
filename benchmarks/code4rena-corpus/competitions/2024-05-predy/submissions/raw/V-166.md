# Vulnerability details

## Impact
A `trader` signs an `order` off-chain and submits it to the `whitelistFiller` who then calls `executeOrderV3()` function to verify `signature` of the `order_v3` and execute the `trade`.
 
However, after setting `userPosition.vaultId`, the function invokes `_predyPool.updateRecepient()` to set the `trader` whose `order` is being executed as the vault's `recipient`. This will revert since the `updateRecepient()` implementation is restricted by `onlyVaultOwner` modifier.

Since the `whitelistFiller` is not the owner of this `vault`, this function reverts.

## Vulnerability Details
The `executeOrderV3()` invokes [_executeOrderV3()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L200-L205) which ensures that only whitelisted `filler` can open position:
```solidity
        if (tradeResult.minMargin > 0) {
            // only whitelisted filler can open position
            if (msg.sender != whitelistFiller) {
                revert CallerIsNotFiller();
            }
        }
```
The function then checks if `userPosition.vaultId == 0` and then [updates it as follows](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L207-L211):
```solidity
        if (userPosition.vaultId == 0) {
            userPosition.vaultId = tradeResult.vaultId;

            _predyPool.updateRecepient(tradeResult.vaultId, perpOrder.info.trader); // @audit-issue Access control conflict
        }
```
Within this check, it proceeds to update the `recipient` for this `vault` by invoking `_predyPool.updateRecepient()`. However, the [updateRecepient()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L286-L292) implementation is restricted by `onlyVaultOwner` modifier in `PredyPool` contract:

```solidity
    function updateRecepient(uint256 vaultId, address recipient) external onlyVaultOwner(vaultId) {
        DataType.Vault storage vault = globalData.vaults[vaultId];

        vault.recipient = recipient;

        emit RecepientUpdated(vaultId, recipient);
    }
```
The [onlyVaultOwner](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L63-L66) modifier is implementated here:
```solidity
    modifier onlyVaultOwner(uint256 vaultId) {
        if (globalData.vaults[vaultId].owner != msg.sender) revert CallerIsNotVaultOwner();
        _;
    }
```

As seen, the operation to update the vault `recipient` will revert at this point due to the `access control` modifier (`onlyVaultOwner`) therefore halting the whole `order` execution.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a way to allow the `whitelistFiller` to perfom this update as well or any other workaround possible.
