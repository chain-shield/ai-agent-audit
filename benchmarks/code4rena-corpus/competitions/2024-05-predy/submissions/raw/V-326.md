# Vulnerability details

Report:

Title: Reentrancy Vulnerability in `supply` and `withdraw` Functions

Issue:
The `supply` and `withdraw` functions in the `PredyPool` contract do not use a reentrancy guard, which can lead to a reentrancy attack. This can cause problems with the internal state of the contract, potentially resulting in security issues and unintended behavior.

Impact:
If an attacker can exploit this vulnerability, they may be able to manipulate the internal state of the contract, leading to potential governance attacks on the affected system. The manipulation could allow the attacker to gain unauthorized access to funds, affecting the intended behavior of the contract and its dependent systems.

Proof of Concept:
Let's consider the following scenario:

1. An attacker calls the `supply` or `withdraw` function.
2. The function starts updating the contract's internal state.
3. The attacker calls the same function again (or another vulnerable function) before the first call's state update is complete.
4. This reentrancy can lead to unpredictable behavior, incorrect state updates, or security issues in the contract.

Recommendation:
To prevent reentrancy attacks, update the `supply` and `withdraw` functions to use a reentrancy guard:

1. Use OpenZeppelin's `ReentrancyGuard` contract.
2. Initialize the `ReentrancyGuard` within the `PredyPool` contract.
3. Use the `nonReentrant` modifier provided by `ReentrancyGuard` in the `supply` and `withdraw` functions.

Example:

```solidity
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract PredyPool is IPredyPool, IUniswapV3MintCallback, Initializable, ReentrancyGuard {
    // ...
    using ReentrancyGuard for ReentrancyGuard;

    constructor() Initializable() {
        __gap = _calculateGap(bytes("PredyPool"));
        __init();
    }

    function initialize(address uniswapFactory) public initializer {
        // ...
        __ReentrancyGuard_init();
        // ...
    }

    function supply(...) external nonReentrant {
        // ...
    }

    function withdraw(...) external nonReentrant {
        // ...
    }
}
```

Implementing this change will help prevent reentrancy attacks and ensure the correct behavior of the contract.
