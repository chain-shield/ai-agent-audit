# Vulnerability details

## Impact
If `getTotalDebtValue(tokenState)` > `getTotalCollateralValue(tokenState)` is not considered, the ratio may be greater than 1, so the supply interest rate will be amplified, causing the economic system to face the risk of instability. By limiting the ratio to 1, the supply interest rate is ensured to be within a reasonable range and the stability of the system is maintained.
## Proof of Concept
According to the design of the protocol, the calculation method of utilization needs to consider the ratio of `getTotalDebtValue(tokenState)/getTotalCollateralValue(tokenState)`.
https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L235-L241
```sol
        uint256 utilization = FixedPointMathLib.mulDivDown(
            getTotalDebtValue(tokenState), Constants.ONE, getTotalCollateralValue(tokenState)
        );

        if (utilization > 1e18) {
            return 1e18;
        }
```
https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ScaledAsset.sol#L200
Because the supply interest rate is `InterestRate * Utilization * (1 - ReserveFactor)`, and the calculation of the Utilization value must take into account the situation where `getTotalDebtValue(tokenState)`>`getTotalCollateralValue(tokenState)` (1 without scaling, 1e18 with scaling)

```sol
        // supply interest rate is InterestRate * Utilization * (1 - ReserveFactor)
        uint256 supplyInterestRate = FixedPointMathLib.mulDivDown(
            FixedPointMathLib.mulDivDown(
                _interestRate, getTotalDebtValue(tokenState), getTotalCollateralValue(tokenState)
            ),
            100 - _reserveFactor,
            100
        );
```
We can see that there is no scaling of 1e18 in this calculation, so we only need to consider getTotalDebtValue(tokenState)/getTotalCollateralValue(tokenState)>1

### Prove that in this case, supplyInterestRate will be very large and has no upper limit:

`_interestRate`：1e16
`getTotalDebtValue(tokenState)`：10e18
`getTotalCollateralValue(tokenState)`：2e18
`supplyInterestRate`=（1e16* 10e18/2e18）*（100-10）/100=4.5e16

Because 10e18>2e18, the correct calculation formula should be (1e16* 1)* (100-10)/100=9e15
Without considering `getTotalDebtValue(tokenState)`/`getTotalCollateralValue(tokenState)`>1, the calculated result is 5 times larger than the correct result.
### Why should we consider this situation? 
If we do not consider the situation where getTotalDebtValue(tokenState) > getTotalCollateralValue(tokenState), the ratio may be greater than 1, so the supply rate will be amplified, causing the economic system to face the risk of instability.
