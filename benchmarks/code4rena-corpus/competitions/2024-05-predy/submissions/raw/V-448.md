# Vulnerability details

## Impact
`trade()` function in `PredyPool.sol` can be called by anyone which means that trades can be opened directly from the pool and skip the checks in the execute functions that are in the market contracts. According to the readme only the `Filler` should be executing the orders of the traders.

## Proof of Concept
This is the `trade()` function
https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L265 
```solidity

 function trade(TradeParams memory tradeParams, bytes memory settlementData)
        external
        nonReentrant
        returns (TradeResult memory tradeResult)
    {
        globalData.validate(tradeParams.pairId);

        if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
            revert TraderNotAllowed();
        }

        tradeParams.vaultId = globalData.createOrGetVault(tradeParams.vaultId, tradeParams.pairId);

        return TradeLogic.trade(globalData, tradeParams, settlementData);
    }

```

Everyone can just call it which will create a vault for him and execute a trade, which can result in unexpected behaviour because none of them will be checked and verified by the `filler`

## Tools Used
Manual Analysis
## Recommended Mitigation Steps
Add modifier to the function so it can be called only by the market contracts and the filler
