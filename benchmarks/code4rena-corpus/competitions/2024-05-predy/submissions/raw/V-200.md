# Vulnerability details

## Impact
For the the calculation of the new tick range when the total liquidity is zero, there's an issue lies in the following lines: [Perp.reallocate.sol#L223-L230](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L223-L230)
```solidity
if (totalLiquidityAmount == 0) {
    (_sqrtAssetStatus.tickLower, _sqrtAssetStatus.tickUpper) =
        Reallocation.getNewRange(_assetStatusUnderlying, currentTick);

    saveLastFeeGrowth(_sqrtAssetStatus);

    return (false, true, 0, 0);
}
```
When the total liquidity is zero, the function updates the `tickLower` and `tickUpper` values using the `Reallocation.getNewRange` function, it then immediately returns without performing any rebalancing or swapping operations.

This could lead to a situation where the new tick range is set, but the liquidity is not properly reallocated or swapped. As a result, the contract's state may become inconsistent.

## Proof of Concept
When the total liquidity is zero, the function misses the opportunity to rebalance the liquidity position. Even though there is no existing liquidity, the contract should still perform the necessary rebalancing operations to ensure that the liquidity position is correctly initialized when new liquidity is added.

Suppose the contract starts with zero liquidity, and a user wants to add liquidity to the pool. The user calls a function that internally calls the `Perp.reallocate` to ensure that the liquidity position is correctly initialized and within the desired range.

Due to the early return when the total liquidity is zero, the `reallocate` function does not perform any rebalancing or swapping operations. As a result, the liquidity position may not be correctly initialized, leading to potential issues or vulnerabilities when the user's liquidity is added to the pool.

Simplified example:
```solidity
function addLiquidity(uint256 amount0, uint256 amount1) external {
    // ... (other code)

    // Call reallocate to initialize the liquidity position
    (bool relocationOccurred, bool isRangeChanged, , ) = reallocate(assetStatusUnderlying, sqrtAssetStatus);

    // Add liquidity based on the assumption that the liquidity position is correctly initialized
    // ... (code to add liquidity)
}
```
The `addLiquidity` function calls `reallocate` to initialize the liquidity position before adding liquidity, if the `reallocate` function returns early without performing any operations, the liquidity position may not be correctly initialized, potentially leading to issues or vulnerabilities when the liquidity is added.

## Recommended Mitigation Steps
**`Remove the early return`** Instead of returning immediately when the total liquidity is zero, continue with the rebalancing and swapping operations using the new `tick` range. This would ensure that the contract's state remains consistent even when there is no liquidity.

**`Separate the tick range update`** Move the logic for updating the `tick` range to a separate function or condition block. This way, the tick range update would only occur when necessary, and the rebalancing and swapping operations would still be performed even when the total liquidity is zero.
