# Vulnerability details

## Impact
Wrongly calculated price will be used causing loss of assets

## Proof of Concept
In the `getSqrtPrice()` function the price of base token per quote token is first calculated before finding the square root of the price.

However the calculations on the price before the square root calculation are wrong.

The calculation is wrong due basically to 2 main issues
1. The `price` was multiplied by `Constants.Q96` twice
2. The `basePrice.expo` was not used to calculate the `price` as recommended by the Pyth [docs](https://docs.pyth.network/price-feeds/best-practices#fixed-point-numeric-representation)

```solidity
/// @notice This function returns the square root of the baseToken price quoted in quoteToken.
    function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        require(quoteAnswer > 0 && basePrice.price > 0);

@>        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;//@audit FINDING: price is multiplied by Constants.Q96 twice
@>
        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```

## Recommended Mitigation Steps
Consider calculating the price as recommended by Pyth [docs](https://docs.pyth.network/price-feeds/best-practices#fixed-point-numeric-representation) first before scaling for precision
