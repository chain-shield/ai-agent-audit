# Vulnerability details

## Impact
`src/PredyPool.sol#uniswapV3MintCallback` function is part of the `IUniswapV3MintCallback` interface, which is required to be implemented by any contract that calls the `mint` function of the UniswapV3 pool contract. The purpose of this callback function is to transfer the tokens owed to the pool contract for the minted liquidity position.

Currently uses the following lines to transfer the tokens: [src/PredyPool.sol#uniswapV3MintCallback#L84-L89](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L84-L89)
```solidity
if (amount0 > 0) {
    ERC20(uniswapPool.token0()).safeTransfer(msg.sender, amount0);
}
if (amount1 > 0) {
    ERC20(uniswapPool.token1()).safeTransfer(msg.sender, amount1);
}
```

By transferring the tokens to `msg.sender` (which is the Uniswap V3 pool contract address) instead of the pool contract itself, the implementation fails to pay the pool the tokens owed for the minted liquidity. This means that the pool contract will not receive the required tokens, effectively creating an imbalance in the pool's liquidity and potentially leading to loss of funds for liquidity providers and traders. According to the "Uniswap V3 documentation", `uniswapV3MintCallback` function is called by the Uniswap V3 pool contract after minting liquidity, and the implementation of this function is expected to transfer the tokens owed to the pool contract.

**`Code References:`**

**`Uniswap V3 Core Repository:`**
The `IUniswapV3MintCallback` interface is defined in the Uniswap V3 core repository: [IUniswapV3MintCallback.sol](https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/interfaces/callback/IUniswapV3MintCallback.sol#L6-L18)
```solidity
interface IUniswapV3MintCallback {
    /// @notice Called to `msg.sender` after minting liquidity to a position from IUniswapV3Pool#mint.
    /// @dev In the implementation you must pay the pool tokens owed for the minted liquidity.
    /// The caller of this method must be checked to be a UniswapV3Pool deployed by the canonical UniswapV3Factory.
    /// @param amount0Owed The amount of token0 due to the pool for the minted liquidity
    /// @param amount1Owed The amount of token1 due to the pool for the minted liquidity
    /// @param data Any data passed through by the caller via the IUniswapV3PoolActions#mint call
    function uniswapV3MintCallback(
        uint256 amount0Owed,
        uint256 amount1Owed,
        bytes calldata data
    ) external;
}
```
The documentation clearly states that the implementation must "pay the pool tokens owed for the minted liquidity."

## Recommended Mitigation Steps
The `uniswapV3MintCallback` should be corrected to transfer the tokens to the pool contract itself.
```solidity
function uniswapV3MintCallback(uint256 amount0Owed, uint256 amount1Owed, bytes calldata data) external override {
    // Correct implementation
    if (amount0Owed > 0) {
        ERC20(pool.token0()).safeTransfer(address(pool), amount0Owed);
    }
    if (amount1Owed > 0) {
        ERC20(pool.token1()).safeTransfer(address(pool), amount1Owed);
    }
}
```
By transferring the tokens to `address(pool)` instead of `msg.sender`, the implementation correctly pays the pool the tokens owed for the minted liquidity, ensuring the proper functioning of the UniswapV3 protocol and preventing potential loss of funds.
