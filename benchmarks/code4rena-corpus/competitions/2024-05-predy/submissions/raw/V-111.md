# Vulnerability details

## Impact

The `withdrawProtocolRevenue` and `withdrawCreatorRevenue` functions in the `PredyPool` contract have incorrect access control, potentially allowing unauthorized users to withdraw funds.

The `withdrawProtocolRevenue` function is intended to be called only by the `operator` to withdraw accumulated protocol revenue. However, the function lacks the `onlyOperator` modifier, meaning anyone can call this function and withdraw the protocol revenue.

Similarly, the `withdrawCreatorRevenue` function is designed for the `poolOwner` to withdraw accumulated creator revenue. However, it also lacks the `onlyPoolOwner` modifier, allowing any user to withdraw creator revenue for any pair.

This lack of access control poses a significant risk as it allows unauthorized users to drain funds from the protocol, leading to financial losses for both the protocol and its users.

## Proof of Concept

The following code snippets from the `PredyPool.sol` contract demonstrate the issue:

```solidity
function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external { // onlyOperator modifier is missing
    // ... (rest of the function logic)
}

function withdrawCreatorRevenue(uint256 pairId, bool isQuoteToken) external { // onlyPoolOwner modifier is missing
    // ... (rest of the function logic)
}
```

As shown above, both functions lack the necessary modifiers to restrict access to authorized users.

## Recommended Mitigation Steps

1.  **Add Access Control Modifiers:**
    *   Add the `onlyOperator` modifier to the `withdrawProtocolRevenue` function.
    *   Add the `onlyPoolOwner(pairId)` modifier to the `withdrawCreatorRevenue` function.

2.  **Consider Role-Based Access Control:**
    *   Implement a more robust role-based access control mechanism to manage permissions for different functions in the contract. This can help prevent similar access control issues in the future.
