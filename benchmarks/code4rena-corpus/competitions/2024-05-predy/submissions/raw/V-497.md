# Vulnerability details

## Impact

The protocol mentions in the `ApplyInterestLib.sol` docs that `"Each time a user interacts with the contract, interest and premium from the previous interaction to the current one are applied."`. This refers to each time users liquidate, supply, withdraw, reallocate, etc.

The `interest rate` that is calculated gives rewards to the protocol and designated creator role, which is taken from the `predy pool`.

The problem is that the `interest rate` calculation is multiplied by the number of years that have passed since the last update.

Since the last reward update is set to `block.timestamp` after each call to `ApplyInterestLib::applyInterestForPoolStatus`, at least one year may never pass and `interestRate` will always be 0.

This will cause the protocol and designated creator role to lose rewards, as the interest fee is supposed be transferred to them from the `predy pool`.

## Proof of Concept
[ApplyInterestLib.sol#L22-L48](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L22-L48)
```javascript
    /**
     * @notice Each time a user interacts with the contract, interest and premium from the previous interaction to the current one are applied.
     * This increases the amount available for withdrawal by the lender and the premium income for Squart.
    */
    function applyInterestForToken(mapping(uint256 => DataType.PairStatus) storage pairs, uint256 pairId) internal {
        DataType.PairStatus storage pairStatus = pairs[pairId];

        Perp.updateFeeAndPremiumGrowth(pairId, pairStatus.sqrtAssetStatus);

        // avoid applying interest rate multiple times in the same block
        if (pairStatus.lastUpdateTimestamp >= block.timestamp) {
            return;
        }

@>      (uint256 interestRateQuote, uint256 protocolFeeQuote) =
            applyInterestForPoolStatus(pairStatus.quotePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

@>      (uint256 interestRateBase, uint256 protocolFeeBase) =
            applyInterestForPoolStatus(pairStatus.basePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

        // Update last update timestamp
@>      pairStatus.lastUpdateTimestamp = block.timestamp;

        if (interestRateQuote > 0 || interestRateBase > 0) {
            emitInterestGrowthEvent(pairStatus, interestRateQuote, interestRateBase, protocolFeeQuote, protocolFeeBase);
        }
    }
```

After the calls to `applyInterestForPoolStatus`, the `pairStatus.lastUpdateTimestamp` is *always* updated to the current `block.timestamp`.

`ApplyInterestLib::applyInterestForPoolStatus` [#L65-L72](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L65-L72)
```javascript
    // Calculates interest rate
    interestRate = InterestRateModel.calculateInterestRate(poolStatus.irmParams, utilizationRatio)
        * (block.timestamp - lastUpdateTimestamp) / 365 days; //@audit at least one year must pass since `lastUpdateTimestamp`

    totalProtocolFee = poolStatus.tokenStatus.updateScaler(interestRate, fee);

    poolStatus.accumulatedProtocolRevenue += totalProtocolFee / 2; //@audit rewards will not be earned
    poolStatus.accumulatedCreatorRevenue += totalProtocolFee / 2;
```

The `interestRate` calculation is multiplied by `(block.timestamp - lastUpdateTimestamp) / 365 days`. If `(block.timestamp - lastUpdateTimestamp) < 365 days`, this will round down to 0, as shown using `chisel`:

```javascript
uint256 oneYear = 365 days;
uint256 lessThanOneYear = 365 days - 1 days;
uint256 testTimePassed = lessThanOneYear/oneYear;
testTimePassed
Type: uint
├ Hex: 0x0
└ Decimal: 0
```

Therefore `interestRate = InterestRateModel.calculateInterestRate(poolStatus.irmParams, utilizationRatio) * (block.timestamp - lastUpdateTimestamp) / 365 days;` 

= `interestRate = InterestRateModel.calculateInterestRate(poolStatus.irmParams, utilizationRatio) * 0` 

= `0`. 

The `interestRate` will be 0, causing the `totalProtocolFee` to be 0.

The `poolStatus.accumulatedProtocolRevenue` and `poolStatus.accumulatedCreatorRevenue` will not updated, causing the `protocol` and `creator` to lose rewards.

## Tools Used
Manual Review, chisel

## Recommended Mitigation Steps
If the intention is to update the interest rate yearly, it doesn't make sense to update the `pairStatus.lastUpdateTimestamp` to `block.timestamp` each time `applyInterestForToken()` is called. Consider only updating it when `poolStatus.accumulatedProtocolRevenue` and `poolStatus.accumulatedCreatorRevenue` are updated.

The protocol can also consider redesigning the interest rate calculation so that at least one year does not have to pass since the last update for protocol and creator to earn rewards.
