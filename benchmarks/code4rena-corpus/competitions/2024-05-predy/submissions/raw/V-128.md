```solidity
    function swapExactOut(
        address quoteToken,
        address,
        bytes memory data,
        uint256 amountOut,
        uint256 amountInMaximum,
        address recipient
    ) external override returns (uint256 amountIn) {
        ERC20(quoteToken).safeTransferFrom(msg.sender, address(this), amountInMaximum);
        ERC20(quoteToken).approve(address(_swapRouter), amountInMaximum);

        amountIn = _swapRouter.exactOutput(
            ISwapRouter.ExactOutputParams(data, recipient, block.timestamp, amountOut, amountInMaximum)
        );

        if (amountInMaximum > amountIn) {
            ERC20(quoteToken).safeTransfer(msg.sender, amountInMaximum - amountIn);
        }
    }
```

This function is used to perform the popular Uniswap router's `exactOutput` swap, and in this case the user specifies the maximum amount of tokens they are willing to spend for their specified `amountOut`, issue however is that this logic when `(amountInMaximum > amountIn)` protocol returns back the extra tokens and erroneously **doesn't revert** the allowance of the router back to `0`.

This then means that an attacker can take the steps below to create a permanent DOS to this channel:

- First among the supported tokens, `USDT` exists and a special logic around this token is that approvals from non-zero to non-zero values always revert so as to curb the approval race condition issue.
- So an attacker would specify a swap and pass in the data that leaves minute value of approval after the swap has concluded, _could aswell be as low as a leftover of `1`_.
- After the swap the `  if (amountInMaximum > amountIn)` block is trigerred, which then transfers back the `1` wei worth of assets to the attacker.
- However on next attempts to `UniswapSettlement#swapExactOut` the query is going to fail for every other person, cause [this attempt at apporval](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/settlements/UniswapSettlement.sol#L47) reverts since the current approval is `1`.

## Impact

Complete DOS to a core functionality of protocol for as low as `1 wei worth of USDC`.
Note that only the bug flow is required to route through `swapExactOut` however after the attacker successfully executes this attack, even `swapExactIn()` would becone unusable since [this attempt](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/settlements/UniswapSettlement.sol#L31) at approving would also revert for the token.
