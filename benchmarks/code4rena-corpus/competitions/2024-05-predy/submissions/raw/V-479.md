# Vulnerability details

## Impact
Within the [LiquidationLogic::liquidate()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39) function, if `closeRatio < 1e18`, the remaining margin is transferred to a recipient specified by the vault owner on [L99](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L99). The recipient address is user-controlled and can be arbitrarily set using [PredyPool::updateRecipient()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L286). 

An issue arises when a vault, backed by `USDC` as collateral (one of the supported tokens), has its recipient set to a blacklisted address. This configuration causes partial liquidations to fail on [L99](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L99) because the `safeTransfer()` function reverts when attempting to transfer the remaining margin. Consequently, this allows vault owners to potentially prevent their vaults from being liquidated, leading to instances of accruing bad debt for the protocol when full liquidations cannot be executed.

## Proof of Concept
1. Alice creates a vault, sets the recipient to a blacklisted address, and uses `USDC` as collateral.
2. Due to price fluctuations, Alice's vault becomes liquidatable.
3. Bob attempts to liquidate Alice's vault by calling [BaseMarketUpgradeable::execLiquidationCall()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/base/BaseMarketUpgradable.sol#L96) with `closeRatio < 1e18`, resulting in the liquidation failing due to the `safeTransfer()` function reverting.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Two solutions can address this problem effectively:
1. Implement a pull-over-push pattern for the vault recipient, allowing recipients to claim funds rather than vaults pushing funds to recipients.
2. Modify the `LiquidationLogic::liquidate()` function to skip transactions involving blacklisted addresses, thereby enabling liquidations to proceed without encountering reverts.
