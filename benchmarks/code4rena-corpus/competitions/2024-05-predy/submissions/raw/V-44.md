# Vulnerability details

## Impact

The `createPriceFeed` function in `PriceFeed.sol` deploys a new `PriceFeed` contract using the `create` method. This deployment mechanism is susceptible to re-org attacks, particularly on L2 networks like Arbitrum and Optimism, where the protocol is intended to be deployed. In a re-org scenario, an attacker could exploit the nonce-based address derivation to predict and intercept the deployment, potentially resulting in the loss of user funds and compromising the integrity of the protocol.

## Proof of Concept

In the `PriceFeed.sol` contract, the `createPriceFeed` function is implemented as follows:

```solidity
function createPriceFeed(
  address quotePrice,
  bytes32 priceId,
  uint256 decimalsDiff
) external returns (address) {
  PriceFeed priceFeed = new PriceFeed(quotePrice, _pyth, priceId, decimalsDiff); // @audit possible reOrg using create

  emit PriceFeedCreated(quotePrice, priceId, decimalsDiff, address(priceFeed));

  return address(priceFeed);
}
```

### Example of Issue

Re-org attacks can occur on EVM-compatible L2 chains, such as Arbitrum and Optimism, where the protocol plans to deploy. An attacker could take advantage of a re-org to manipulate the address derivation and intercept contract deployments, potentially leading to the theft of user funds.

### Scenario

1. Alice deploys a new `PriceFeed` contract using the `createPriceFeed` function and sends funds to it.
2. Bob observes a network re-org and calls `createPriceFeed` with the same parameters, creating a `PriceFeed` contract with the same address.
3. Alice's transaction is then executed again, transferring funds to the contract controlled by Bob.

## Recommended Mitigation Steps

To mitigate the risk of re-org attacks, use the `create2` method for deploying contracts. `create2` allows for deterministic address generation based on a given salt, which can include `msg.sender` to ensure unique and predictable addresses. Here's how to refactor the `createPriceFeed` function:

 Refactor the `createPriceFeed` function to use `create2`:

   ```solidity
   function createPriceFeed(
     address quotePrice,
     bytes32 priceId,
     uint256 decimalsDiff
   ) external returns (address) {
     bytes32 salt = keccak256(
       abi.encodePacked(quotePrice, priceId, msg.sender)
     );
     PriceFeed priceFeed = new PriceFeed{ salt: salt }(
       quotePrice,
       _pyth,
       priceId,
       decimalsDiff
     ); // @audit mitigate reOrg using create2

     emit PriceFeedCreated(
       quotePrice,
       priceId,
       decimalsDiff,
       address(priceFeed)
     );

     return address(priceFeed);
   }
   ```

### Explanation

Using `create2` with a salt that includes `msg.sender` ensures that the address of the new `PriceFeed` contract is unique to the sender and predictable only by them. This prevents attackers from exploiting re-orgs to manipulate contract deployments and intercept funds.

By adopting this approach, the protocol can safeguard against re-org attacks, ensuring secure and reliable contract deployments on EVM-compatible L2 networks.
