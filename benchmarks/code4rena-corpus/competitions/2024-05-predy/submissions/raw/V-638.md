# Vulnerability details

## Impact
Liquidation can not be carried out successfully.

## Proof of Concept

When look at the liquidation logic, the bad vault can be liquidated by anyone other then the vault owner.

The liquidation flow could be, let see as an example for gamma position.

[GammaTradeMarket](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L138-L149) - [PreddyPool](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L312-L319) -- [liquidate](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39-L45).

If we look at the liquidate function,

[LiquidationLogic.sol#L75-L108](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L75-L108)

```solidity
       (tradeResult.minMargin,, hasPosition,) =
            PositionCalculator.calculateMinMargin(pairStatus, vault, DataType.FeeAmount(0, 0));

        // Check if the price is within the slippage tolerance range to ensure that the price does not become
        // excessively favorable to the liquidator.
        SlippageLib.checkPrice(
            sqrtOraclePrice,
            tradeResult,
            slippageTolerance,
            tradeParams.tradeAmountSqrt == 0 ? 0 : _MAX_ACCEPTABLE_SQRT_PRICE_RANGE
        );

        uint256 sentMarginAmount = 0;

        if (!hasPosition) {
            int256 remainingMargin = vault.margin;

            if (remainingMargin > 0) {
                if (vault.recipient != address(0)) {
                    // Send the remaining margin to the recipient.
                    vault.margin = 0;

                    sentMarginAmount = uint256(remainingMargin);

                    ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount); ---->> could be reverted in this call purposefully
                }
            } else if (remainingMargin < 0) {
                vault.margin = 0;

                // To prevent the liquidator from unfairly profiting through arbitrage trades in the AMM and passing losses onto the protocol,
                // any losses that cannot be covered by the vault must be compensated by the liquidator
                ERC20(pairStatus.quotePool.token).safeTransferFrom(msg.sender, address(this), uint256(-remainingMargin));
            }
        }
```

when the vault has valid position, the logic tries to send the remaining `vault.margin` to the `vault.recipient` who could be the owner.

When the vault.recipient is malicious, they could revert the call purposefully to escape from liquidation.

Later they can fund the vault and bring back to healthy state. This would beat the purpose of liquidation.


## Tools Used

Manual review.

## Recommended Mitigation Steps

We would suggest to use try/catch block when refunding to `vault.recipient`.
