# Vulnerability details

## Impact
The current implementation allows pool owner to update price feed without any restriction, such as timelock. This leads to an attack vector that a malicious pool owner can steal funds.
There is a potential vulnerability in the `updatePriceOracle` function due to the ability of the pool owner to update the price oracle without any restrictions such as a timelock. This could allow a malicious pool owner to update the price oracle to a malicious contract, leading to the manipulation of prices and potential theft of user collateral during liquidations.

```javascript
/**
 * @notice Updates price oracle
 * @dev The function can be called by pool owner.
 * @param pairId The id of pair to update oracle.
 * @param priceFeed The address of price feed
 */
function updatePriceOracle(uint256 pairId, address priceFeed) external onlyPoolOwner(pairId) {
    AddPairLogic.updatePriceOracle(globalData.pairs[pairId], priceFeed);
}
```
Potential Vulnerability
The vulnerability arises from the following:

The updatePriceOracle function allows the pool owner to update the price feed at any time without any delay or additional checks.
A malicious pool owner could set the priceFeed to a malicious contract that manipulates prices, which could lead to improper liquidations.
Impact
If a pool owner updates the price feed to a malicious oracle, they can manipulate the reported prices, causing incorrect liquidation conditions. This could allow the pool owner or an accomplice to liquidate users' positions unfairly and steal their collateral.

## Proof of Concept
A malicious pool owner could deploy a fake price oracle that reports extremely low prices for collateral tokens, leading to the liquidation of users' positions at a fraction of their true value. Here is a conceptual malicious oracle:

Here is an example of a fake oracle

```javascript
contract MaliciousPriceOracle {
    address public attacker;

    constructor(address _attacker) {
        attacker = _attacker;
    }

    function getPrice(address _underlying) external view returns (uint256 price, uint8 decimals) {
        if (msg.sender == attacker) {
            return (1, 18); // Extremely low price
        } else {
            // Return a normal price
            return (1000 ether, 18);
        }
    }
}
```

The attacker could then call the `updatePriceOracle` function to set this malicious oracle and impact some functions.
