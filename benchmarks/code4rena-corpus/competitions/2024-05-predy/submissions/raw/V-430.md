# Vulnerability details

If the Vault Value becomes smaller than the Min. Margin, the vault can be forcefully closed. The liquidation price is determined through a Dutch auction, based on the ratio of Vault Value to Min Margin.

The issue is that the `liquidate()` inside the LiquidationLogic contract can be directly called by anyone instead of calling it through the `execLiquidationCall()` in the PredyPool contract. 

This enables anyone to liquidate a vault which is not in danger with variable inputs which would successfully pass the checks, sending the funds to the attacker,

## Proof of Concept
The issue is simply due to lack of access control allowing anyone to call liquidate with the manipulated inputs.

Scenario: 
- Alice has a vault with enough margins that can't be currently liquidated.
- Bob calls `liquidate()` with false parameters with Alice's vault id & setting himself as the `vault.recipient` inside globalData. All the checks pass & the remaining margin is sent to Bob.


## Impact
Anyone can liquidate a healthy vault & steal funds.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Make the `liquidate()` internal or introduce a check to ensure that the function is only called from the PredyPool contract.
