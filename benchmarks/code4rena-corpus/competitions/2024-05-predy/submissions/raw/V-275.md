# Vulnerability details

## Impact
The [Liquidate](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39) function of the `LiquidationLogic` library constitute the logic behind liquidation of under-water or unhealthy positions.

Whats with the function? the thing here is that whenever during the liquidation the remaining margin ( as in `remainingMargin`) is more than zero ( meaning positive margin) the remaining margin is sent to the recipient , who is the position [owner](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L200) in this case.
```
 if (remainingMargin > 0) {
                if (vault.recipient != address(0)) {
                    // Send the remaining margin to the recipient.
                    vault.margin = 0;

                    sentMarginAmount = uint256(remainingMargin);

                    ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);
                }
```

What can happen here thats worth paying attention to? well, the position owner with `USDT` market can prevent himself from being liquidated by `blackListing` his address, this is due to the blackListing feature of the `uSDT` token.

This means that a trader can prevent himself from being liquidated, and the `UpdateRecipient` function would not be of a use to mitigate the issue as it requires the `vaultOwner` to be called which in this case is the market contract itself

```

} catch {}
```
