# Vulnerability details

## Description

According to the OpenZeppelin Docs about [Proxies](https://docs.openzeppelin.com/contracts/5.x/api/proxy#Initializable), we should avoid leaving a contract uninitialized.

> An uninitialized contract can be taken over by an attacker. This applies to both a proxy and its implementation contract, which may impact the proxy. To prevent the implementation contract from being used, you should invoke the `_disableInitializers` function in the constructor to automatically lock it when it is deployed.
> 

However, all the contracts that implement `Initializable` do not call `_disableInitializers` in their constructors.

## Recommendation

Invoke `_disableInitializers` in the constructors of contracts which implement `Initializable` including the following:

```diff
PredyPool
BaseHookCallbackUpgradable
BaseMarketUpgradable 
GammaTradeMarket 
PerpMarketV1 
```
