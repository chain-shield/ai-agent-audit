# Vulnerability details

## Impact
The discovered issue in the `PerpMarketV1` contract's `_executeOrderV3` function creates a critical vulnerability where invalid trades are not correctly reverted. This occurs due to an invalid validation in the `PerpMarketLib.validateTrade` function. Specifically, the validation logic allows a trade to proceed if either `validateLimitPrice` or `validateStopPrice` returns true. As a result, trades with invalid parameters might still be executed.

## Proof of Concept
To illustrate this issue, consider the following scenarios and corresponding proof:

#### Scenario: Invalid Trade Execution

**Steps:**

1. A trade is initiated with specific `limitPrice` and `stopPrice` parameters.
2. The `PerpMarketLib.validateTrade` function is called to validate the trade at line 213 in `PerpMarketV1.sol`.

```solidity
PerpMarketLib.validateTrade(
      tradeResult, tradeAmount, perpOrder.limitPrice, perpOrder.stopPrice, perpOrder.auctionData
    );
```

3. The current logic checks:

```solidity
if (limitPrice > 0 && stopPrice > 0) {
      // limit & stop order
      if (
        !validateLimitPrice(tradePrice, tradeAmount, limitPrice)
          && !validateStopPrice(oraclePrice, tradePrice, tradeAmount, stopPrice, auctionData)
      ) {
        revert LimitStopOrderDoesNotMatch();
      }
    }
```

4. This code only reverts if both `validateLimitPrice` and `validateStopPrice` return false. If either one is true, the trade does not revert and proceeds.

Consider a trade where `validateLimitPrice` returns false (invalid limit price) and `validateStopPrice` returns true (valid stop price):

```solidity
// Example function calls
bool limitPriceValid = validateLimitPrice(tradePrice, tradeAmount, limitPrice); // returns false
bool stopPriceValid = validateStopPrice(oraclePrice, tradePrice, tradeAmount, stopPrice, auctionData); // returns true
```

- The trade is incorrectly validated and proceeds despite the invalid limit price.

## Recommended Mitigation Steps

To address this vulnerability, modify the validation logic in the `PerpMarketLib.validateTrade` function to ensure that the trade reverts if either validation fails. The corrected code should look like this:

```solidity
if (limitPrice > 0 && stopPrice > 0) {
      // limit & stop order
      if (
        !validateLimitPrice(tradePrice, tradeAmount, limitPrice)
          || !validateStopPrice(oraclePrice, tradePrice, tradeAmount, stopPrice, auctionData)
      ) {
        revert LimitStopOrderDoesNotMatch();
      }
    }
```
