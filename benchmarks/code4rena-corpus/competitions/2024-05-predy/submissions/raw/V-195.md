# Vulnerability details

## Vulnerability Description
`SettlementCallbackLib.execSettlementInternal` takes an `int256` parameter called `baseAmountDelta`. When `baseAmountDelta` is negative, the function calls the buy function with `uint256(-baseAmountDelta)` as the `buyAmount` parameter. ## Impact
The conversion from `int256` to `uint256` using the unary negation operator (`-`) can lead to an overflow or underflow if the absolute value of `baseAmountDelta` is greater than the maximum value of `uint256` (2^256 - 1).

For example, if `baseAmountDelta` is equal to the minimum value of `int256` (which is `-2^255`), then `-baseAmountDelta` would be 2^255, which exceeds the maximum value of `uint256`. This would result in an overflow, and an incorrect value would be passed to the buy function.

Similarly, if `baseAmountDelta` is equal to the maximum value of `int256` (which is `2^255 - 1`), then `-baseAmountDelta` would be `-2^255 + 1`, which is a negative value, since the result is being cast to `uint256`, it would underflow and wrap around to a very large positive value, again leading to an incorrect value being passed to the buy function.

**`Consequences`**
If the buy function does not validate the input or performs calculations based on the incorrect value, it could lead to the following issues:

Incorrect calculations or state updates within the contract.
Potential loss of funds or tokens due to incorrect transfers or accounting.
Denial of service (DoS) if the contract reverts or enters an invalid state.

```solidity
    function testUnderflow() public pure returns (uint256) {

```
In the `testOverflow` function, when we convert the minimum value of `int256` (`-2^255`) to `uint256` using the unary negation operator, it should return `0`. Due to the overflow, it returns `2^255` instead.

In the `testUnderflow` function, when we convert the maximum value of `int256` (`2^255 - 1`) to `uint256` using the unary negation operator, it should return `1`. Due to the underflow, it returns a very large value (`2^256 - (2^255 - 1)`) instead.

## Recommended Mitigation Steps
Should handle the conversion from `int256` to `uint256` more carefully, potentially by using a safe casting function or by checking the range of `baseAmountDelta` before performing the conversion.

```solidity
function execSettlementInternal(
    IPredyPool predyPool,
    address quoteToken,
    address baseToken,
    SettlementParams memory settlementParams,
    int256 baseAmountDelta
) internal {
    if (baseAmountDelta > 0) {
        sell(
            predyPool,
            quoteToken,
            baseToken,
            settlementParams,
            settlementParams.sender,
            settlementParams.price,
            uint256(baseAmountDelta)
        );
    } else if (baseAmountDelta < 0) {
        uint256 buyAmount = uint256(-baseAmountDelta);
        require(int256(buyAmount) == -baseAmountDelta, "SafeCast: value doesn't fit in 256 bits");
        buy(
            predyPool,
            quoteToken,
            baseToken,
            settlementParams,
            settlementParams.sender,
            settlementParams.price,
            buyAmount
        );
    }
}
```
we first convert `-baseAmountDelta` to `uint256` and store it in the `buyAmount` variable. Then, we check if the conversion back to `int256` results in the original value of `-baseAmountDelta`. If the values match, it means the conversion was safe, and we can proceed with calling the buy function. If the values don't match, it means an overflow or underflow occurred, and we can revert the transaction with an appropriate error message.
