# Vulnerability details

## Impact
In the `updateFeeAndPremiumGrowth`, the code updates the `lastFee0Growth` and `lastFee1Growth` values after calculating the new `fee0Growth` and `fee1Growth` values. Although, in the `saveLastFeeGrowth` function, the code overwrites the `lastFee0Growth` and `lastFee1Growth` values with the current `feeGrowthInside0X128` and `feeGrowthInside1X128` values, effectively discarding the updated values from the `updateFeeAndPremiumGrowth` function.

If `saveLastFeeGrowth` is called after `updateFeeAndPremiumGrowth`, the `lastFee0Growth and lastFee1Growth` values will be reset to their previous values, potentially causing incorrect calculations in subsequent calls to `updateFeeAndPremiumGrowth`.

## Proof of Concept
In the `updateFeeAndPremiumGrowth` function, the `lastFee0Growth` and `lastFee1Growth` values are updated after calculating the new `fee0Growth` and `fee1Growth` values: [updateFeeAndPremiumGrowth#L398-L409](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L398-L409)
```solidity
_assetStatus.fee0Growth += FullMath.mulDiv(
    f0, _assetStatus.totalAmount + _assetStatus.borrowedAmount * spreadParam / 1000, _assetStatus.totalAmount
);
_assetStatus.fee1Growth += FullMath.mulDiv(
    f1, _assetStatus.totalAmount + _assetStatus.borrowedAmount * spreadParam / 1000, _assetStatus.totalAmount
);

_assetStatus.borrowPremium0Growth += FullMath.mulDiv(f0, 1000 + spreadParam, 1000);
_assetStatus.borrowPremium1Growth += FullMath.mulDiv(f1, 1000 + spreadParam, 1000);

_assetStatus.lastFee0Growth = feeGrowthInside0X128;
_assetStatus.lastFee1Growth = feeGrowthInside1X128;
```
Even so, in the `saveLastFeeGrowth` function, the `lastFee0Growth` and `lastFee1Growth` values are overwritten with the current `feeGrowthInside0X128` and `feeGrowthInside1X128` values: [Perp.sol#saveLastFeeGrowth](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L414-L420)
```solidity
function saveLastFeeGrowth(SqrtPerpAssetStatus storage _assetStatus) internal {
    (uint256 feeGrowthInside0X128, uint256 feeGrowthInside1X128) =
        UniHelper.getFeeGrowthInside(_assetStatus.uniswapPool, _assetStatus.tickLower, _assetStatus.tickUpper);

    _assetStatus.lastFee0Growth = feeGrowthInside0X128;
    _assetStatus.lastFee1Growth = feeGrowthInside1X128;
}
```
If `saveLastFeeGrowth` is called after `updateFeeAndPremiumGrowth`, the updated `lastFee0Growth` and `lastFee1Growth` values from `updateFeeAndPremiumGrowth` will be overwritten with the previous values, effectively discarding the newly calculated fee and premium growth.

The impact of this is that subsequent calls to `updateFeeAndPremiumGrowth` will use the incorrect `lastFee0Growth` and `lastFee1Growth` values, leading to incorrect calculations of fee and premium growth. This can result in users being charged incorrect fees or premiums for their positions, potentially causing financial losses or gains depending on the direction of the error.

**Concept Illustration.**
`updateFeeAndPremiumGrowth` is called, and the `lastFee0Growth` and `lastFee1Growth` values are updated to `X` and `Y`, respectively.
`saveLastFeeGrowth` is called, overwriting `lastFee0Growth` and `lastFee1Growth` with their previous values, let's say `A` and `B`.
In the next call to `updateFeeAndPremiumGrowth`, the calculations will use `A` and `B` as the starting points for `lastFee0Growth` and `lastFee1Growth`, instead of the correct values `X` and `Y`.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove the `saveLastFeeGrowth` and update the `lastFee0Growth` and `lastFee1Growth` values only in the `updateFeeAndPremiumGrowth` function, **or** Ensure that `saveLastFeeGrowth` is called before `updateFeeAndPremiumGrowth`, and update the `lastFee0Growth` and `lastFee1Growth` values in `updateFeeAndPremiumGrowth` using the values returned by `getFeeGrowthInside` instead of the cached values.
