# Vulnerability details

## Impact
If `tickCumulatives[1] - tickCumulatives[0]` is negative and `((tickCumulatives[1] - tickCumulatives[0]) % int56(int256(ago)) != 0)`, then returned `tick` will be bigger than it should be  which places operations requiring prices to be right not be able to achieve this goal.

As such, in the case where  `TWAP` is required, then protocol would work with a `flawed prices` since the returned price would be different than it really is, potentially leading to say for example some positions that should be `liquidatable` not being liquidated because before liquidation there is a check to see if the loan is `healthy`. 

Now this check queries the value of this asset via `getSqrtTWAP()` and if returned price is wrong then `unhealthy` loans could be pronounced as `healthy` and vice versa.

## Proof of Concept
In `UniHelper` contract, [getSqrtTWAP()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L20-L22) function is used by protocol to get `average price`.
```solidity
    function getSqrtTWAP(address uniswapPoolAddress) internal view returns (uint160 sqrtTwapX96) {
        (sqrtTwapX96,) = callUniswapObserve(IUniswapV3Pool(uniswapPoolAddress), _ORACLE_PERIOD);
    }
```

This calls [callUniswapObserve()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L68-L74) which actually performs the price calculation:
```solidity
        //...
        int56[] memory tickCumulatives = abi.decode(data, (int56[]));

        int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));

        uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(tick);

        return (sqrtPriceX96, ago);
```
It is required that if `tickCumulatives[1] - tickCumulatives[0]` is negative, then `tick` should be rounded down like in [Uniswap library](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol#L36).

However, this is not done. As result, if `tickCumulatives[1] - tickCumulatives[0]` is negative and `(tickCumulatives[1] - tickCumulatives[0]) % int56(int256(ago)) != 0)`, `tick` will be bigger then it should be. Which opens possibility for arbitrage opportunities.

## Tools Used
Manual Review

## Recommended Mitigation Steps
`tick` should be rounded down in this case:
```diff
    int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));
+  if ((tickCumulatives[1] - tickCumulatives[0]) < 0 && ((tickCumulatives[1] - tickCumulatives[0]) % int56(int256(ago)) != 0)) tick--;
```
