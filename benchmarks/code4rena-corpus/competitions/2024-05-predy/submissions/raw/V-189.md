# Vulnerability details

In the `PredyPool.uniswapV3MintCallback`, the function is transferring tokens directly to the Uniswap V3 pool contract address (`msg.sender`). According to the Uniswap V3 documentation, the `uniswapV3MintCallback function` is called by the Uniswap V3 pool contract after a successful mint operation, and the expected behavior is to transfer the tokens to the recipient address specified during the mint operation, not to the pool contract itself.

Here's the relevant excerpt from the Uniswap V3 documentation:
> "The callback is called on the target contract with the following signature `uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata data)`. The `data` parameter contains the recipient address to send the minted tokens to."

## Impact
The `PredyPool.uniswapV3MintCallback` is part of the Uniswap V3 callback interface, which is designed to handle the transfer of tokens after a successful mint operation. According to the Uniswap V3 documentation, the function should transfer the minted tokens to the recipient address specified during the mint operation. in the current implementation, the tokens are being transferred directly to the Uniswap V3 pool contract address (`msg.sender`).

This behavior is incorrect and can lead to the loss of user funds. When a user initiates a mint operation on the Uniswap V3 pool, they expect the minted tokens to be credited to their address or a specified recipient address. Because the bug in the `PredyPool.uniswapV3MintCallback`, the tokens are being sent to the pool contract itself, effectively locking them and making them inaccessible to the user.

**Relevant Code References:**

**Uniswap V3 Documentation:**
The Uniswap V3 documentation clearly states that the `PredyPool.uniswapV3MintCallback` should transfer the tokens to the recipient address specified in the data parameter:
> "The callback is called on the target contract with the following signature `uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata data)`. The `data` parameter contains the recipient address to send the minted tokens to."

Buggy Implementation in [PredyPool.uniswapV3MintCallback](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/PredyPool.sol#L78-L90) is as follows:
```solidity
function uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata) external override {
    // Only the uniswap pool has access to this function.
    require(allowedUniswapPools[msg.sender]);

    IUniswapV3Pool uniswapPool = IUniswapV3Pool(msg.sender);

    if (amount0 > 0) {
        ERC20(uniswapPool.token0()).safeTransfer(msg.sender, amount0); // Tokens are transferred to the pool contract
    }
    if (amount1 > 0) {
        ERC20(uniswapPool.token1()).safeTransfer(msg.sender, amount1); // Tokens are transferred to the pool contract
    }
}
```
As you can see, the tokens are being transferred to `msg.sender`, which is the Uniswap V3 pool contract address, instead of the intended recipient address specified in the `data` parameter.

## Proof of Concept
To illustrate the concept further, let's consider a scenario where a user initiates a mint operation on the Uniswap V3 pool, specifying their address as the recipient. The Uniswap V3 pool contract will call the `PredyPool.uniswapV3MintCallback` on the PredyPool contract, passing the minted token amounts and the user's address in the data parameter.

Due to the bug in the `PredyPool.uniswapV3MintCallback`, the tokens will be transferred to the Uniswap V3 pool contract address instead of the user's address. This means that the user will not receive the minted tokens, and the tokens will be locked in the Uniswap V3 pool contract, effectively leading to a loss of funds for the user.

## Recommended Mitigation Steps
So, the correct implementation should be to extract the recipient address from the `data` parameter and transfer the tokens to that address instead of `msg.sender`.
```solidity
function uniswapV3MintCallback(uint256 amount0, uint256 amount1, bytes calldata data) external override {
    // Only the uniswap pool has access to this function.
    require(allowedUniswapPools[msg.sender]);

    IUniswapV3Pool uniswapPool = IUniswapV3Pool(msg.sender);

    // Extract the recipient address from the data parameter
    address recipient = abi.decode(data, (address));

    if (amount0 > 0) {
        ERC20(uniswapPool.token0()).safeTransfer(recipient, amount0);
    }
    if (amount1 > 0) {
        ERC20(uniswapPool.token1()).safeTransfer(recipient, amount1);
    }
}
```
By making this, the tokens will be transferred to the intended recipient address specified during the Uniswap V3 mint operation, rather than the pool contract itself.
