# Vulnerability details


## Description
The function getSqrtTWAP() is responsible for querying uniswap pool directly to get sqrtTwapX96 value using the internal function [callUniswapObserve()](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/UniHelper.sol#L35-L75).
Lets take a look at this function:
```solidity
    function callUniswapObserve(IUniswapV3Pool uniswapPool, uint256 ago) internal view returns (uint160, uint256) {
        uint32[] memory secondsAgos = new uint32[](2);

        secondsAgos[0] = uint32(ago);
        secondsAgos[1] = 0;

        (bool success, bytes memory data) =
            address(uniswapPool).staticcall(abi.encodeWithSelector(IUniswapV3PoolOracle.observe.selector, secondsAgos));
        if (!success) {
            .....
            ....
            ...
        }
        int56[] memory tickCumulatives = abi.decode(data, (int56[]));

        int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));

        uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(tick); //@audit-issue missing check fof negative ticks 

        return (sqrtPriceX96, ago);
    }
```
This function is used to calculate the reference pool price using ticks, note that this is like the original [uniswap implementation](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol#L30), in Predy the delta of the tick cumulative is being calculated in the [same way as uni](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/UniHelper.sol#L70), protocol implements (tickCumulatives[1] - tickCumulatives[0] which is because here, secondsAgos[0] = uint32(ago); and secondsAgos[1] = 0; exactly like in [Uniswap OracleLibrary](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol#L23C1-L26C1) where secondsAgos[0] = secondsAgo; and secondsAgos[1] = 0;, so everything checks out and the tick deltas are calculated accurately, i.e in our case tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0].

The problem now is that in the case if our tickCumulativesDelta is negative, i.e int24(tickCumulatives[1] - tickCumulatives[0] < 0) , then the tick should be rounded down, as it's done in the [uniswap library](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L36).

But this is not being done and as a result, in the case if int24(tickCumulatives[1] - tickCumulatives[0]) is negative and (tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0, then the returned tick will be bigger then it should be; which opens possibility for some price manipulations and arbitrage opportunities.


## Impact
In this case, if int24(tickCumulatives[1] - tickCumulatives[0]) is negative and ((tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0, then returned tick will be bigger than it should be which places protocol wanting prices to be right not be able to achieve this goal.

Note that major protocol function use the function [getSqrtTWAP()](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/UniHelper.sol#L20-L22) to get sources of price such as [`getSqrtIndexPrice()` in PositionCalculator](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L146) library, the function getSqrtIndexPrice() is also used in [calculateMinMargin()](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L83) which is heavily used by the [LiquidationLogic library in `liquidate()` function](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/LiquidationLogic.sol#L76) and also in [TradeLogic `trade()` function](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/logic/TradeLogic.sol#L47).

Now in this case where the implemented pricing mode is TWAP, the protocol would work with a flawed price since the returned price would be different than it really is; potentially leading to say, for example, some positions that should be liquidatable not being liquidated. 

## Tools Used
[Uniswap V3's OracleLibrary](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol)

## Recommended Mitigation Steps
Add this line: if (tickCumulatives[1] - tickCumulatives[0] < 0 && (tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0) timeWeightedTick --;.
