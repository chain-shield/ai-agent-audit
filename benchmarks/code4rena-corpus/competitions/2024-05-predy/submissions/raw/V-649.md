# Vulnerability details

## Summary
The `callUniswapObserve` function computes the Time-Weighted Average Price (TWAP) by calculating the delta of tick cumulatives over a specified time period. However, the current implementation does not handle negative tick deltas properly. This omission can lead to incorrect tick values, which impacts all functionalities relying on the TWAP, including liquidations
## Impact
Incorrect handling of negative tick deltas can result in inaccurate TWAP calculations. Specifically, when the tick cumulative delta is negative and not perfectly divisible by the time period, the calculated tick should be rounded down. Without this correction, the TWAP may be inaccurately computed, potentially leading to incorrect pricing data being used in various financial operations, such as liquidations and trades.

## Proof of Concept
In the current implementation, the code does not account for the scenario where `tickCumulatives[1] - tickCumulatives[0]` is negative and not divisible evenly by `ago`
```
int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));

```

## Recommended Mitigation Steps
Update the `callUniswapObserve` function to include the check for negative tick deltas and adjust the arithmetic mean tick accordingly
```
int56 tickCumulativeDelta = tickCumulatives[1] - tickCumulatives[0];
int24 arithmeticMeanTick = int24(tickCumulativeDelta / int56(int256(ago)));

if (tickCumulativeDelta < 0 && (tickCumulativeDelta % int56(int256(ago)) != 0)) {
    arithmeticMeanTick--;
}

uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(arithmeticMeanTick);
```
