# Vulnerability details

## Summary
In `validateStopPrice()`, the `value` parameter is set to `ratio(oraclePrice, stopPrice)`, which is a `price ratio`, not a `time value`. This leads to errors in the decay calculation.

## Proof of Concept
When [decay()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/DecayLib.sol#L13) invokes `decay2()` to calculate `decayedPrice `, it passes `block.timestamp` as the  last parameter, `value`.
```solidity
        decayedPrice = decay2(startPrice, endPrice, decayStartTime, decayEndTime, block.timestamp);
```
This is because the `value` parameter in `decay2()` is set to accept a `time value` therefore allowing logical comparisons between `decayEndTime` and this provided `time value`.

However, [validateStopPrice()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L147-L153) passes `ratio(oraclePrice, stopPrice)`, which is a `price ratio` as the `value` parameter to the `DecayLib.decay2()` to calculate the `decayedSlippageTorelance`:

```solidity
uint256 decayedSlippageTorelance = DecayLib.decay2(
    auctionParams.startPrice,
    auctionParams.endPrice,
    auctionParams.startTime,
    auctionParams.endTime,
    ratio(oraclePrice, stopPrice)  // @ audit-issue Incorrect parameter
);
```
##### Problem:
The `value` parameter in [DecayLib.decay2()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/DecayLib.sol#L16-L37) is intended to represent a `time point` within the decay period not `price ratio`.

```solidity
function decay2(uint256 startPrice, uint256 endPrice, uint256 decayStartTime, uint256 decayEndTime, uint256 value)
        internal
        pure
        returns (uint256 decayedPrice)
    {
     //...
    }
```

`DecayLib.decay2()` expects the `value` parameter to be a `time value`, but it receives a `price ratio`. The `decayEndTime` therefore ends up being [compared against a price ratio instead of time stamp](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/DecayLib.sol#L23-L27).

```solidity
} else if (decayEndTime <= value) {
            decayedPrice = endPrice; // @audit-issue decayedPrice set wrt the comparison which may be wrong
        } else if (decayStartTime >= value) {
            decayedPrice = startPrice; // @audit-issue decayedPrice set wrt the comparison which may be wrong
        }
```
This leads to incorrect calculations within the function.

## Impact
This `decayedSlippageTorelance ` returned is then used to [validate price](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L161-L172):
```solidity
            if (tradePrice > Bps.upper(oraclePrice, decayedSlippageTorelance)) { // @ audit-issue Used here
                return false;
            }
        } else if (tradeAmount < 0) {
            // sell
            if (stopPrice < oraclePrice) {
                return false;
            }


            if (tradePrice < Bps.lower(oraclePrice, decayedSlippageTorelance)) { // @ audit-issue Used here
                return false;
            }
```
As seen above, the whole validation will be flawed.

## Recommended Mitigation Steps
Ensure that the `value` parameter passed to `DecayLib.decay2()` is a `time value`. 
---> You can only compare time against time.
