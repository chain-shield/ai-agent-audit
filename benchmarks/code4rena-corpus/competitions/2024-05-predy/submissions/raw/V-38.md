# Vulnerability details

## Description 
The trade function in the PredyPool contract can be called without ensuring that initial states and setup processes are correctly executed. This includes pair registration, risk parameter setup, price oracle configuration, collateral and margin management, allowlist configuration, and fee setup. Bypassing these initial states can lead to significant issues, including financial instability, incorrect trade execution, protocol exploitation, and revenue loss.
```
function trade(TradeParams memory tradeParams, bytes memory settlementData) external nonReentrant returns (TradeResult memory tradeResult) {
    globalData.validate(tradeParams.pairId);

    if (globalData.pairs[tradeParams.pairId].allowlistEnabled && !allowedTraders[msg.sender][tradeParams.pairId]) {
        revert TraderNotAllowed();
    }

    tradeParams.vaultId = globalData.createOrGetVault(tradeParams.vaultId, tradeParams.pairId);

    return TradeLogic.trade(globalData, tradeParams, settlementData);
}
```

## Impact
1. Financial Instability:
- Incorrect trade execution, insufficient collateral, and mismanaged risk parameters can lead to financial instability, increasing the risk of defaults and liquidation issues.

2. Incorrect Trade Execution:
- Operating on invalid or non-existent pairId values, incorrect asset pricing, and unauthorized trading can result in trades being executed under unfavorable or unintended conditions, leading to financial losses.

3. Protocol Exploitation:
- Unauthorized traders exploiting the protocol due to unconfigured allowlists can lead to misuse and potential security vulnerabilities.

4. Revenue Loss:
- Incorrect fee collection can impact the protocol's revenue, affecting its financial sustainability and ability to cover operational costs.

## Proof of Concept
Scenario:
- A user calls the trade function without prior initialization and setup of pairs, risk parameters, price oracles, collateral, allowlists, and fees.

Steps: 
- The trade function is called with a pairId that has not been registered.
- The function attempts to validate the pairId, create or retrieve a vault, and execute the trade logic.
- Due to the lack of initial setup, the function operates on uninitialized or incorrect data, leading to unexpected behavior and potential financial losses.

Impact:
- The protocol's state could be corrupted, leading to financial losses or operational failures.
- Unauthorized trades could be executed, compromising the integrity and safety of the protocol.
- Incorrect fee collection could impact the protocol's revenue and financial sustainability.

Manual review 

## Recommended Mitigation Steps
1. Add checks to ensure that the initialize function has been called before allowing any trades.

2. Ensure that the pairId is valid and registered before executing trades.

3. Add checks to ensure that risk parameters and price oracles are configured before allowing trades.

4. Add checks to ensure that collateral and margin requirements are configured before allowing trades.

5. Add checks to ensure that fees are configured before allowing trades. This ensures that the protocol collects the intended revenue from each trade.
