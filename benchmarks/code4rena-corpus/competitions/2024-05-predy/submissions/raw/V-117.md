# Vulnerability details


## Proof of Concept

First take a look at https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L20-L23

```solidity
    function getSqrtTWAP(address uniswapPoolAddress) internal view returns (uint160 sqrtTwapX96) {
        (sqrtTwapX96,) = callUniswapObserve(IUniswapV3Pool(uniswapPoolAddress), _ORACLE_PERIOD);
    }

```

This function is queried to get the square root of time weighted average price, using an `_ORACLE_PERIOD` of 30 minutes as can be seen here: https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L11

Now consider the implementation of `UniHelper.callUniswapObserve()` at https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L35-L76

```solidity
    function callUniswapObserve(IUniswapV3Pool uniswapPool, uint256 ago) internal view returns (uint160, uint256) {
        uint32[] memory secondsAgos = new uint32[](2);

        secondsAgos[0] = uint32(ago);
        secondsAgos[1] = 0;

        (bool success, bytes memory data) =
            address(uniswapPool).staticcall(abi.encodeWithSelector(IUniswapV3PoolOracle.observe.selector, secondsAgos));

        if (!success) {
            if (keccak256(data) != keccak256(abi.encodeWithSignature("Error(string)", "OLD"))) {
                revertBytes(data);
            }

            (,, uint16 index, uint16 cardinality,,,) = uniswapPool.slot0();

            (uint32 oldestAvailableAge,,, bool initialized) = uniswapPool.observations((index + 1) % cardinality);

            if (!initialized) {
                (oldestAvailableAge,,,) = uniswapPool.observations(0);
            }

            ago = block.timestamp - oldestAvailableAge;
            secondsAgos[0] = uint32(ago);

            (success, data) = address(uniswapPool).staticcall(
                abi.encodeWithSelector(IUniswapV3PoolOracle.observe.selector, secondsAgos)
            );
            if (!success) {
                revertBytes(data);
            }
        }

        int56[] memory tickCumulatives = abi.decode(data, (int56[]));

        int24 tick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(int256(ago)));

        uint160 sqrtPriceX96 = TickMath.getSqrtRatioAtTick(tick);

        return (sqrtPriceX96, ago);
    }

```

This function is used to compute the twap of a Uniswap V3 pool using data from its oracle, and then it returns the final calculated `sqrtPriceX96` and the `ago` parameter.

Now, let's consider the [native implementation in Uniswap](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L36)), we can see that the differences between the tickCummulatives is considered the `tickCummulativeDelta`, and in a case where this delta is less than `0`, a check is implemented to see if the delta is directly divisible by the twap duration, if not the tick calculated is rounded down, i.e: `        if (tickCumulativesDelta < 0 && (tickCumulativesDelta % secondsAgo != 0)) arithmeticMeanTick--;`

Now note that just like in [the original uniswap implementation](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol#L30), here the delta of the tick cummulatives is being calculated in a similar manner, i.e [Predy implements ` int24(tickCumulatives[1] - tickCumulatives[0])` for the delta ](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/UniHelper.sol#L70).

But contrary to Uniswap's native implementation in Predy's current implementation case, if ` int24(tickCumulatives[1] - tickCumulatives[0])` is negative and ` int24(tickCumulatives[1] - tickCumulatives[0])  % int56(int256(ago)) != 0` then the returned tick will be bigger then it should be, which opens possibility for some price manipulations and arbitrage opportunities.

Remember that this function is directly queried via `getSqrtTWAP()`, which ends up being used for most of protocol's core functionalities that require any pricing logic, i.e even during liquidations.

The call route for how the price returned from this query can be seen from the scope as `LiquidationLogic#liquidate() -> LiquidationLogic#checkVaultIsDanger() ->  PositionCalculator#isLiquidatable() -> PositionCalculator#calculateMinMargin() -> UniHelper#convertSqrtPrice() -> UniHelper#getSqrtTWAP()` . This route then showcases how integrating a wrong price as would be done in the case explained in this report would be wrong cause liquidatable positions might now be pronounced an non-liquidatable or vice versa.

## Impact

If ` int24(tickCumulatives[1] - tickCumulatives[0])` is negative and ` int24(tickCumulatives[1] - tickCumulatives[0])  % int56(int256(ago)) != 0` then the returned tick will be bigger than it should be which places protocol wanting prices to be right not be able to achieve this goal, note that Predy relies on the price attached to this to be valid and uses them directly in other core functionalities including when [liquidating](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L39-L119) since there is a [check](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L59-L63) to see if the vault is in danger via `checkVaultIsDanger()` , having the wrong price being returned from Uniswap easily causes reverts on valid attempts to liquidate since the price would be inaccurate, alternatively, it could actually cause for unfair liquidations on users if the wrong price returned does not favor their position.

## Recommended Mitigation Steps

Make the price returned by this function to the same with the [the original uniswap implementation](https://github.com/Uniswap/v3-periphery/blob/697c2474757ea89fec12a4e6db16a574fe259610/contracts/libraries/OracleLibrary.sol#L30), where the tick is rounded down in the case where ` int24(tickCumulatives[1] - tickCumulatives[0])` is negative and ` int24(tickCumulatives[1] - tickCumulatives[0])  % int56(int256(ago)) != 0`
