# Vulnerability details

## Impact
Lack of a proper check when `tradeResult.minMargin` is zero allows any caller, not just the `whitelistFiller`, to reduce or close an existing position. This means that an attacker could potentially target existing positions and manipulate or close them without the position owner's consent or authorization. The consequences of this vulnerability could be severe, including financial losses for position owners and potential disruption of the overall market.

if (tradeResult.minMargin > 0) {

When `tradeResult.minMargin` is zero, indicating an existing position is being reduced or closed, there is no check to verify if the caller (`msg.sender`) is authorized to perform this action. The code proceeds to update the `userPosition.vaultId` and call `_predyPool.updateRecepient` without any restrictions.

## Proof of Concept
To illustrate the concept, let's consider the following scenario:

Alice opens a position by executing an order through the `_executeOrderV3` function.

Bob, an attacker, wants to manipulate or close Alice's position.

Bob constructs a `PerpOrderV3` with the following parameters:

`perpOrder.info.trader`: Alice's address
`perpOrder.pairId`: The same pair ID as Alice's position
`perpOrder.quantity`: A value that would reduce or close Alice's position
Other parameters set accordingly

Bob calls the _executeOrderV3 function with the constructed PerpOrderV3.

Since `tradeResult.minMargin` is zero (existing position), the code skips the `whitelistFiller` check and proceeds to update Alice's position based on Bob's order.

By exploiting this vulnerability, Bob, an unauthorized party, can manipulate or close Alice's existing position without her consent or authorization.

## Recommended Mitigation Steps
This can be mitigated by adding a check to ensure that only the position owner or the `whitelistFiller` can reduce or close an existing position. 
```solidity
if (tradeResult.minMargin > 0) {
    // only whitelisted filler can open position
    if (msg.sender != whitelistFiller) {
        revert CallerIsNotFiller();
    }
} else {
    // only position owner or whitelisted filler can reduce/close position
    if (msg.sender != perpOrder.info.trader && msg.sender != whitelistFiller) {
        revert CallerIsNotPositionOwnerOrFiller();
    }
}
```
By adding this additional check, the code ensures that only authorized parties (the position owner or the `whitelistFiller`) can modify existing positions, mitigating the risk of unauthorized position manipulation or closure.
