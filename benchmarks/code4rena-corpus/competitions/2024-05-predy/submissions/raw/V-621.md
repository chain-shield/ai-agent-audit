# Vulnerability details

## Impact
The `PredyPool` contract is upgradeable. 

However, the implementation contract lacks protection against unauthorized initialization, leaving it vulnerable to being taken over by an attacker.

## Proof of Concept
The `initialize` function, marked as `initializer`, is intended to set up the contract state, including initializing the reentrancy guard and setting the operator.

The `constructor` is empty, which means the implementation contract is neither locked nor initialized when it is deployed.

```solidity
    constructor() {}


    function initialize(address uniswapFactory) public initializer {
        __ReentrancyGuard_init();
        AddPairLogic.initializeGlobalData(globalData, uniswapFactory);


        operator = msg.sender;
    }
```

Since the `constructor` is empty, the implementation contract can be initialized by anyone, allowing a malicious actor to set themselves as the operator and perform unauthorized actions.

## Tools Used
Manual review

## Recommended Mitigation Steps
To prevent the implementation contract from being used maliciously, invoke the `_disableInitializers` function in the `constructor` to automatically lock it when deployed.

```solidity
constructor() {
    _disableInitializers();
}

function initialize(address uniswapFactory) public initializer {
    __ReentrancyGuard_init();
    AddPairLogic.initializeGlobalData(globalData, uniswapFactory);

    operator = msg.sender;
}
```

This change ensures that the implementation contract cannot be initialized by an attacker, thereby  significantly reducing the risk of exploitation.
