# Vulnerability details

## Summary
The `take` function in the `PreddyPool` contract is vulnerable to potential misuse, allowing the contract's funds to be drained. This issue arises due to the lack of restrictions on the amount that can be transferred and the fact that the locker role, which can call this function, is not a trusted role within the protocol.

## Vulnerability Detail
The `take` function allows token transfers to be made from within the `predySettlementCallback` and `predyTradeAfterCallback` functions. While it is restricted to being called only by the current locker, there are no limitations on the amount of tokens that can be transferred. Additionally, the locker role, which has the authority to call this function, is not considered a trusted role in the protocol, further increasing the risk of misuse.

## Impact
The lack of constraints on the `take` function combined with the untrusted nature of the locker role could lead to the contract's funds being drained. An attacker with control over the locker role could potentially transfer an unlimited amount of tokens out of the contract, resulting in significant financial loss.

## Code Snippet
```solidity
/**
 * @notice Transfers tokens. It can only be called from within the `predySettlementCallback` and
 * `predyTradeAfterCallback` of the contract that invoked the trade function.
 * @dev Only the current locker can call this function
 * @param isQuoteAsset Whether the token is quote or base
 * @param to The address to transfer the tokens to
 * @param amount The amount of tokens to transfer
 */
function take(bool isQuoteAsset, address to, uint256 amount) external onlyByLocker {
	globalData.take(isQuoteAsset, to, amount);
}
```

## Tool used
Manual Review

## Recommendation
Implement restrictions on the `take` function to limit the amount of tokens that can be transferred in a single call or within a certain timeframe. Additionally, reassess the trustworthiness of the locker role and consider implementing more stringent access controls or oversight mechanisms for roles with such critical permissions.
