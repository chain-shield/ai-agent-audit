# Vulnerability details

## Impact
In the way `checkAutoHedgeAndClose` handles the case when `vault.openPosition.perp.amount` and `vault.openPosition.sqrtPerp.amount` are both zero.
[src/markets/gamma/GammaTradeMarket.solcheckAutoHedgeAndClose#L342-L344](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L342-L344)
```solidity
if (vault.openPosition.perp.amount == 0 && vault.openPosition.sqrtPerp.amount == 0) {
    return (false, false, positionId);
}
```
In this case, the function returns `false` for both `hedgeRequired` and `closeRequired`, and returns the original `positionId`. The code assumes that if the open position amounts are zero, there is no need for hedging or closing the position, but this assumption may not hold true in all cases.

Suppose a user has an open position with non-zero `perp.amount` and `sqrtPerp.amount`. Later, the position is closed or hedged, but the `userPosition` struct in the contract is not updated accordingly due to a bug or other issue.

In this case, when the `checkAutoHedgeAndClose function` is called, it will encounter the following condition: [src/markets/gamma/GammaTradeMarket.solcheckAutoHedgeAndClose#L342-L344](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L342-L344)
```solidity
if (vault.openPosition.perp.amount == 0 && vault.openPosition.sqrtPerp.amount == 0) {
    return (false, false, positionId);
}
```
Since the `vault.openPosition.perp.amount` and `vault.openPosition.sqrtPerp.amount` are both zero (due to the position being closed or hedged), the function will return `false` for both `hedgeRequired` and `closeRequired`, and return the original `positionId`.

However, this is an incorrect decision because the position has already been closed or hedged, and there may be other conditions or triggers (e.g., expiration time, price triggers) that require further action, such as settling the position or transferring funds.

## Tools Used
Vs

## Recommended Mitigation Steps
Check the position's status/other relevant conditions before returning `false` for `hedgeRequired` and `closeRequired`. Alternatively, the function could return an additional status or error code to indicate that the position has already been closed or hedged, instead of assuming that no action is required.
