# Vulnerability details

## Impact
The resolve() function within the PerpOrderV3Lib library performs signature verification but does not demonstrate the implementation of this verification process. Without proper validation, malicious actors could potentially submit fraudulent signatures leading to unauthorized order resolutions. An attacker could forge a signature and pass it to the resolve() function, resulting in the execution of orders without the legitimate owner's consent. This could lead to financial losses, manipulation of market positions, or other forms of abuse depending on the broader application context of the PerpOrderV3Lib library.

## Proof of Concept
To illustrate the concept, consider a scenario where an attacker generates a fake signature for an existing order. If the resolve() function does not adequately verify the signature against the expected public key of the order's creator, the attacker could trick the system into resolving the order as if it were genuinely signed by the legitimate owner.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement Secure Signature Verification: Integrate a robust signature verification mechanism within the resolve() function. This should involve comparing the provided signature against the expected signature generated using the private key of the order's creator. Consider using established cryptographic libraries or patterns known for secure signature verification in the Ethereum ecosystem.
Use Established Libraries: For added security, utilize well-tested libraries designed for secure signature verification and message signing. Examples include ecrecover for Ethereum-specific applications or third-party libraries like OpenZeppelin's ECDSA library.
