# Vulnerability details

## Impact
The calculation of the `quoteAmount` when the `price` is not zero: [SettlementCallbackLib.sell#L124-L134](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/base/SettlementCallbackLib.sol#L124-L134)
```solidity
} else {
    uint256 quoteAmount = sellAmount * price / Constants.Q96;

    if (quoteAmount > quoteAmountFromUni) {
        ERC20(quoteToken).safeTransferFrom(sender, address(this), quoteAmount - quoteAmountFromUni);
    } else if (quoteAmountFromUni > quoteAmount) {
        ERC20(quoteToken).safeTransfer(sender, quoteAmountFromUni - quoteAmount);
    }

    ERC20(quoteToken).safeTransfer(address(predyPool), quoteAmount);
}
```
The `quoteAmount` is calculated as `sellAmount * price / Constants.Q96`. This calculation assumes that the price is already scaled by `Constants.Q96`. If the price is not scaled correctly, the `quoteAmount` calculation will be incorrect.

For example, if `sellAmount` is 1000, `price` is 1.5 (instead of `1.5 * Constants.Q96`), and `Constants.Q96` is 1e18, the expected `quoteAmount` should be 1500 (1000 * 1.5), the current calculation will result in `quoteAmount` being 1 (1000 * 1.5 / 1e18).

**`Incorrect Token Transfers`** If the price is not scaled correctly by `Constants.Q96`, the `quoteAmount` calculation will be incorrect. This can lead to incorrect amounts of quote tokens being transferred between the parties involved (sender, contract, and predyPool). For example, if the price is not scaled correctly, the sender might receive too many or too few quote tokens, or the predyPool might receive an incorrect amount of quote tokens.

**`Violation of Contract Invariants`** The incorrect calculation of `quoteAmount` can violate the invariants and assumptions of the contract, leading to inconsistent state and potential vulnerabilities. For example, if the predyPool receives an incorrect amount of quote tokens, it might affect the pool's liquidity and pricing calculations, potentially causing further issues downstream.

## Proof of Concept
```solidity
uint256 sellAmount = 1000;
uint256 price = 1500000; // Assuming Constants.Q96 is 1e6, this price is not scaled correctly
uint256 quoteAmountFromUni = 1500000;

// Incorrect calculation
uint256 quoteAmount = sellAmount * price / Constants.Q96; // quoteAmount = 1000 * 1500000 / 1e6 = 1500

// Expected correct calculation
uint256 expectedQuoteAmount = sellAmount * price; // expectedQuoteAmount = 1000 * 1500000 = 1500000000
```
the `quoteAmount` is calculated as 1500, while the expected correct amount should be 1500000000. This discrepancy can lead to incorrect token transfers and potential loss of funds.

## Recommended Mitigation Steps
the price should be scaled by Constants.Q96 before performing the calculation, or the calculation should be adjusted to account for the scaling factor. For example: [SettlementCallbackLib.sell#L101](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/base/SettlementCallbackLib.sol#L101)
```solidity
uint256 quoteAmount = sellAmount * price / Constants.Q96;
```
could be replaced with:
```solidity
uint256 quoteAmount = sellAmount * price;
```
or:
```solidity
uint256 quoteAmount = sellAmount * (price * Constants.Q96) / (Constants.Q96 * Constants.Q96);
```
