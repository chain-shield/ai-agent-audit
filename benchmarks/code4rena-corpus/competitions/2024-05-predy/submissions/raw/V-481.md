# Vulnerability details

## Impact
Some token functions revert due to blacklist functionality. For example, USDC tokens cannot be transferred to/from a blacklisted address. In the current implementation of the liquidation logic, if the vault has no open positions, it must transfer the remaining tokens to the recipient. This can be a problem if the recipient is blacklisted. In this case the protocol will lose funds because of liquidation failure.

## Proof of Concept

https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L89-L108

1.Non blacklisted Bob enters with USDC.
2.Bob becomes blacklisted.
3.His position gets into trouble and has to be liquidated.
4.Since this is Bob's only position, the protocol should restore the remaining funds during liquidation, but this is not possible since the transfer function will revert due to Bob's blacklisting.

In the current implementation, the scenario described above would  revert, making it impossible to liquidate Bob's position. This will result in a loss of funds for the protocol when Bob gets insolvent.

## Tools Used
Manual review

## Recommended Mitigation Steps
Make sure that the liquidation function will not revert under any circumstances. For example use claim pattern. Instead of transferring tokens, only increase internal balances and introduce a claim function.
