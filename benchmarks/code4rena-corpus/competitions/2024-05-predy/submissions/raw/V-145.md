# Vulnerability details

## Impact
Loss of asset during market price turbulence

## Proof of Concept
The `getPriceNoOlderThan(...)` function is used to get price from Pyth Oracle. 

```solidity
IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);
```

The issue is that the `basePrice.conf` is not checked to be within an acceptable interval. Also there is supposed to be different prices for ask and buy

Below is the full function
```solidity
File: PriceFeed.sol
/// @notice This function returns the square root of the baseToken price quoted in quoteToken.
    function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        require(quoteAnswer > 0 && basePrice.price > 0);

        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;

        sqrtPrice = FixedPointMathLib.sqrt(price);
    }

```

According to the Pyth docs, Protocols can decide that there is too much uncertainty when confidence interval exceeds some threshold and choose to pause any new activity that depends on the price of the asset.

## Tools Used
Pyth docs: https://docs.pyth.network/price-feeds/best-practices#confidence-intervals


## Recommended Mitigation Steps

Consider implementing a validation for accepted price intervals as recommended by the Pyth's [docs](https://docs.pyth.network/price-feeds/best-practices#confidence-intervals)

Consider also creating prices for ask and buy with the confidence interval.
