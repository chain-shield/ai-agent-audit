# Vulnerability details

## Impact
The protocol earns rewards based off the interest rate calculation that is deducted from the `predy pool`.

However, this formula will return an incorrect `interest rate` under a certain condition, causing the protocol to receive an incorrect amount of rewards.

## Proof of Concept
As defined in the [predy-v6 docs](https://docs.predy.finance/predy-v6/dev/interest-rate-model#:~:text=and%20borrowing%20environment.-,The%20interest%20rate%20R%20follows%20the%20model%3A,KinkRate), the `interest rate` calculation is as follows:

```javascript
R=Base+U⋅Slope1 (U<KinkRate)

R=Base+KinkRate⋅Slope1+(U−KinkRate)⋅Slope2 (U≥KinkRate)
```

As we can see, `R=Base+U⋅Slope1` only when `U (utilization ratio)` is STRICTLY LESS than the `KinkRate`. Otherwise, we have `R=Base+KinkRate⋅Slope1+(U−KinkRate)⋅Slope2`.

However, the actual coded `interest rate` calculation does not reflect this:

[InterestRateModel.sol#L18-L33](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/InterestRateModel.sol#L18-L33)
```javascript
    function calculateInterestRate(IRMParams memory irmParams, uint256 utilizationRatio)
        internal
        pure
        returns (uint256)
    {
        uint256 ir = irmParams.baseRate;

        if (utilizationRatio <= irmParams.kinkRate) {
            ir += (utilizationRatio * irmParams.slope1) / _ONE;
        } else {
            ir += (irmParams.kinkRate * irmParams.slope1) / _ONE;
            ir += (irmParams.slope2 * (utilizationRatio - irmParams.kinkRate)) / _ONE;
        }

        return ir;
    }
```

We can see that when `utilizationRatio <= irmParams.kinkRate`, then `interest rate = Base+U⋅Slope1`.

This calculation is incorrect when `utilizationRatio = irmParams.kinkRate` and the protocol will receive an incorrect amount of rewards:

[ApplyInterestLib.sol#L65-L72](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L65-L72)
```javascript
    // Calculates interest rate
    interestRate = InterestRateModel.calculateInterestRate(poolStatus.irmParams, utilizationRatio)
        * (block.timestamp - lastUpdateTimestamp) / 365 days;

    totalProtocolFee = poolStatus.tokenStatus.updateScaler(interestRate, fee);

    poolStatus.accumulatedProtocolRevenue += totalProtocolFee / 2;
    poolStatus.accumulatedCreatorRevenue += totalProtocolFee / 2;
```

## Recommended Mitigation Steps
Adjust the calculation so that `interest rate = Base+U⋅Slope1` only when `U (utilization ratio)` is strictly less than the `KinkRate`

```diff

    {
```
