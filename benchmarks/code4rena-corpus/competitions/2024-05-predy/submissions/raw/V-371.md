# Vulnerability details

## Impact

The documentation (https://docs.predy.finance/predy-v6/dev/architecture#pricefeedfactory) states that Chainlink Oracle is used for quotePrice and Pyth Oracle is used for baseToken.

```
In quotePrice, specify the Chainlink address corresponding to the USD-denominated price of the quoteToken. In priceId, specify the Pyth address corresponding to the USD-denominated price of the baseToken.
```

However, there are no workarounds in the `PriceFeed.sol:getSqrtPrice` if one of the Oracles revert and may result in Denial-of-Service. Especially Pyth documentation states that (https://docs.pyth.network/price-feeds/api-reference/evm/get-price-no-older-than): The call reverts with a StalePriceError if the on-chain price is from more than age seconds in the past (with respect to the current on-chain timestamp).

## Recommended Mitigation Steps

Place the price fetching logic in the try-catch block, for example:

```
  try AggregatorV3Interface(_quotePriceFeed).latestRoundData() returns (
      uint80 roundID,
      int256 quoteAnswer,
      uint256 startedAt,
      uint256 updatedAt,
      uint80 answeredInRound
  ) {
      // Process the returned values
      // For example:
      if (quoteAnswer > 0) {
          // Do something with quoteAnswer
      }
  } catch (Error memory e) {
      // This is executed in case of revert() or require() errors
      emit LogError(e);
  } catch (bytes memory lowLevelData) {
      // This is executed in case of invalid opcode or other low-level errors
      emit LogLowLevelError(lowLevelData);
  }
```
