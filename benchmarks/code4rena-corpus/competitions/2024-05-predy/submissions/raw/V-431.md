# Vulnerability details

## Impact

As the protocol’s current intent is to use `WETH, USDC, ARB, USDT, DAI, WBTC`, it is evident that they wouldn’t want other tokens to be added as pairs. With improper validation, it is completely possible for any user to add any token that is supported by `Uniswap`.

## Proof of Concept

The current implementation of the protocol has `PredyPool`’s function [registerPair](https://github.com/code-423n4/2024-05-predy/blob/main/src/PredyPool.sol#L109-L111) limited to only be called by users with the [operator](https://docs.predy.finance/predy-v6/dev/architecture#operator-poolcreator) role, however, it [was confirmed](https://discord.com/channels/810916927919620096/1242872233345679501/1245440813144477707) that any user would be able to create pairs. Therefore, once users have access to the function, they will be able to create a pair with any token they desire, as long as it’s available on `Uniswap`. At the moment, there’s no way for the protocol to differentiate the allowed tokens from the disallowed ones, thereby enabling users to use all other tokens besides `WETH, USDC, ARB, USDT, DAI, WBTC`.

## Tools Used

Manual Review

## Recommended Mitigation Steps

In order for the issue to be mitigated, a mapping with the whitelisted tokens should be created, which would restrict users from creating pairs with tokens outside of it.
