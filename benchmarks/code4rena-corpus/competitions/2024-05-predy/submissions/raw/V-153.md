# Vulnerability details

In the [getIsSafe function](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PositionCalculator.sol#L63-L73), the `isSafe` value is calculated as follows [Line 72](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PositionCalculator.sol#L72)
```solidity
isSafe = vaultValue >= minMargin && _vault.margin >= 0;
```
This calculation may not be correct in certain scenarios. The condition `_vault.margin >= 0` checks if the margin of the vault is non-negative, but it does not consider the case where the vault has a negative margin and the `vaultValue` is greater than or equal to the absolute value of the negative margin.

For example, let's assume that `minMargin` is -100, `vaultValue` is 50, and `_vault.margin` is -80. In this case, the position should be considered safe because the `vaultValue` (50) is greater than or equal to the absolute value of the negative margin (-80). But the current calculation of `isSafe` would result in `false` because `_vault.margin` (-80) is less than 0.

## Impact
The current implementation of the `getIsSafe` function fails to handle the case where the vault has a negative margin, but the `vaultValue` is greater than or equal to the absolute value of the negative margin. In such cases, the position should be considered safe, but the current calculation incorrectly marks it as unsafe.

Example:

`minMargin` = -100
`vaultValue` = 50
`_vault.margin` = -80

In this example, the position should be considered safe because the `vaultValue` (50) is greater than or equal to the absolute value of the negative margin (-80). Though, the current calculation of `isSafe` would result in `false` because `_vault.margin` (-80) is less than 0.
```solidity
isSafe = vaultValue >= minMargin && _vault.margin >= 0;
// Evaluates to: 50 >= -100 && -80 >= 0
// Result: false (incorrect)
```
**`Potential Loss of Funds or Liquidation of Safe Positions`**
If a position is incorrectly marked as unsafe due to the bug in the `getIsSafe`, it could lead to unintended consequences, such as the liquidation of a safe position or the loss of funds for the user.

For example, if the `getIsSafe` function is used to determine whether a position should be liquidated, a safe position with a negative margin but a sufficient `vaultValue` could be incorrectly liquidated, resulting in a loss of funds for the user.

**`Violation of Contract Invariants and Inconsistent State`**
The incorrect calculation of the safety of a position can lead to violations of contract "invariants" and an inconsistent state within the contract. This can further propagate errors and introduce additional bugs or vulnerabilities in other parts of the contract that rely on the correct calculation of position safety.

## Recommended Mitigation Steps
The code should consider the absolute value of the margin when evaluating the safety of a position, like so:
```solidity
isSafe = vaultValue >= minMargin && (_vault.margin >= 0 || vaultValue >= abs(_vault.margin));
```
Or:

The calculation of `isSafe` should be modified to consider the absolute value of the negative margin when `_vault.margi`n is negative.
```solidity
function getIsSafe(
    DataType.PairStatus memory pairStatus,
    DataType.Vault memory _vault,
    DataType.FeeAmount memory feeAmount
) internal view returns (int256 minMargin, bool isSafe, bool hasPosition) {
    int256 vaultValue;

    (minMargin, vaultValue, hasPosition,) = calculateMinMargin(pairStatus, _vault, feeAmount);

    if (_vault.margin >= 0) {
        isSafe = vaultValue >= minMargin && _vault.margin >= 0;
    } else {
        isSafe = vaultValue >= -_vault.margin;
    }
}
```
In this version, if `_vault.margin` is non-negative, the original condition `vaultValue >= minMargin && _vault.margin >= 0` is used. But, if `_vault.margin` is negative, the condition `vaultValue >= -_vault.margin` is used, which checks if the `vaultValue` is greater than or equal to the absolute value of the negative margin.
