# Vulnerability details

## Summary

`GammaTradeMarket` contract code contains a change to storage layout that is not backwards compatible with the version of the contract currently deployed on chain. Upgrading `GammaTradeMarket` contract will result in storage corruption.

## Vulnerability Details

`GammaTradeMarket.sol` has a mapping that stores user positions.
```
mapping(uint256 positionId => GammaTradeMarketLib.UserPosition) internal userPositions;
```
[Link](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L51)

`UserPosition` is defined as follow in the currently deployed contract. 
```
    struct UserPosition {
        uint256 vaultId;        // 32 bytes | 1st slot
        address owner;          // 20 bytes | 2nd slot
        uint64 pairId;          // 8  bytes | 2nd slot
        uint8 leverage;         // 1  byte  | 2nd slot 
        uint256 expiration;     // 32 bytes | 3rd slot
        uint256 lowerLimit;     
        uint256 upperLimit;
        uint256 lastHedgedTime;
        uint256 hedgeInterval;
        uint256 lastHedgedSqrtPrice;
        uint256 sqrtPriceTrigger;
        GammaTradeMarketLib.AuctionParams auctionParams; // 14 bytes | last slot
    }
```
[Link](https://arbiscan.io/address/0x4a037b48012e358ca891b4361bd248ba93df95d9#code#F51#L44)

Note that `owner`, `pairId`, and `leverage` are all packed into the second storage slot because they are only 29 bytes total.

`UserPosition` is defined as follow in the new version of the contract that is not deployed yet.  
```
    struct UserPosition {
        uint256 vaultId;        // 32 bytes | 1st slot
        address owner;          // 20 bytes | 2nd slot
        uint64 pairId;          // 8  bytes | 2nd slot
        uint8 leverage;         // 1  byte  | 2nd slot 
+       int64 maximaDeviation;  // 8  bytes | 3rd slot (does not fit into 2nd slot)
        uint256 expiration;     // 32 bytes | 4th slot
        uint256 lowerLimit;
        uint256 upperLimit;
        uint256 lastHedgedTime;
        uint256 hedgeInterval;
        uint256 lastHedgedSqrtPrice;
        uint256 sqrtPriceTrigger;
        GammaTradeMarketLib.AuctionParams auctionParams; // 14 bytes | last slot
    }
```
[Link](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarketLib.sol#L14-L28)

In the new implementation, `maximaDeviation` has to occupy its own storage slot, since it can't fit into the 2nd slot which only has 3 bytes of free space left. 

After a contract upgrade, every field after `maximaDeviation` will shift by one storage slot. Notably, the very last storage slot of `UserPosition` contains `auctionParams`, and it will contain all zeroes in the new contract.


## Impact

Existing user positions are corrupted if `GammaTradeMarket` contract upgrades. With `AuctionParams` now all zeroes, `calculateSlippageTolerance()` and `calculateSlippageToleranceByPrice()` have a division by zero. 

```
        uint256 elapsed = (currentTime - startTime) * Bps.ONE / auctionParams.auctionPeriod;
```
[Link](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarketLib.sol#L150)

```
            auctionParams.minSlippageTolerance
                + ratio * (auctionParams.maxSlippageTolerance - auctionParams.minSlippageTolerance)
                    / auctionParams.auctionRange
```
[Link](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarketLib.sol#L183-L185)

This means that, `autoHedge()` and `autoClose()` always revert. Without a way to close a position, customer funds are stuck until storage is recovered to a valid state.

Note that this error doesn't trigger an outflow of funds. 

## Recommended Mitigation Steps

`maximaDeviation` field should be moved to the end of `UserPosition` before new version of the contract is rolled out. This way location of existing fields is preserved across a contract upgrade.
