# Vulnerability details

## Impact
At present, the protocol (the operator) has only one method of claiming accumulated revenue. To do this, they use the `PredyPool::withdrawProtocolRevenue` function which transfers the amount of the ERC20 asset from `pool.accumulatedProtocolRevenue` to the protocol operator.  
This function can be used to withdraw _only_ the amount in `pool.accumulatedProtocolRevenue` and _nothing else_. The variable is also updated in `ApplyInterestLib` when applying interest in the pool.

The operator can withdraw any revenue that the protocol generates and this is perfectly correct.
However, let's consider the case where someone has randomly or mistakenly sent ERC20 tokens into the protocol or any other case in which the protocol receives more ERC20 tokens than it should have.
These funds can never be withdrawn from the `Predy` contracts.  
This results in a potential loss of assets on the part of the counterpart.

## Recommended Mitigation Steps

Set a new function called `collectExtra (IERC20 asset, uint256 amount)` which can be used to remove any additional amounts other than fees from the contract.
A naive  implementation could look like this:

```solidity
function collectExtra(uint256 pairId, bool isQuoteToken, uint256 amount) external onlyOperator {
        Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);

        uint256 extra = ERC20(pool.token).balanceOf(address(this)) - pool.accumulatedProtocolRevenue;
        
        require(extra >= amount, "Insufficient extra");
        
        if (amount > 0) {
            ERC20(pool.token).safeTransfer(msg.sender, amount);
        }

        emit ExtraAssetWithdrawn(pairId, isQuoteToken, amount);
    }
```

Implement a function to ensure that the protocol administrator also has the ability to extract native tokens from the chain outside the contract, such as ETH, ARB, etc.
These native tokens can be sent in the current contracts, even against the will of the contract. Take a look at [unexpected ether transfers](https://scsfg.io/hackers/unexpected-ether/)
