# Vulnerability details

## Summary
When the `decayEndTime` is before the `current time`, then it might be wrong.

If the `decay()` function is invoked to calculate a price when the decay period has ended, this could produce misleading results. For example, using wrong/unintended `decayEndTime` and expecting the function to return a meaningful decayed price based on the current time would not yield accurate outcomes.

## Proof of Concept
The [decay()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/DecayLib.sol#L21-L22) function only performs the following check:
```solidity
        if (decayEndTime < decayStartTime) {
            revert EndTimeBeforeStartTime();
```
However, it does not verify that the `decayEndTime` provided is indeed in the future.

This `decay()` function is used in [validateMarketOrder()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L195-L197) to fetch `decayedPrice ` associated with some `AuctionParams`:

```solidity
        uint256 decayedPrice = DecayLib.decay(
            auctionParams.startPrice, auctionParams.endPrice, auctionParams.startTime, auctionParams.endTime
        );
```
If the `decay()` function does not verify that `auctionParams.endTime` is a future timestamp, then the returned value, (`decayedPrice`) will by all means be incorrect.

## Impact
With this incorrect value returned, the market order may be [validated wrongly](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L199-L209):
```solidity
        if (tradeAmount != 0) {
            if (tradeAmount > 0 && decayedPrice < tradePrice) { // @audit-issue The value used here
                return false;
            }


            if (tradeAmount < 0 && decayedPrice > tradePrice) { // @audit-issue The value used here
                return false;
            }
        }


        return true;
```
From this, the whole validation relies on the `decayedPrice` returned and as such, if this value is incorrect, the whole validation is incorrect.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Therefore, the system should include a sanity check to ensure `decayEndTime > block.timestamp`.

Add the following check:

```solidity
if (decayEndTime <= block.timestamp) revert EndTimeLessThanCurrentTime();
```
