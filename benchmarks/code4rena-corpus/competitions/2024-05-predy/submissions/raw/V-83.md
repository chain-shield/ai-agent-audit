# Vulnerability details

## Impact
Break of Protocol Functionality when position Amount and trade Amount are both Negative values which will wrongly assume position is Open when it is not an Open Position as positionAmount & tradeAmount are negative there by assigning a wrong value to the return of deltaEntry and payoff variable in contract
## Proof of Concept

The code above shows how entry is calculated in the Perp.sol contract, it can be noted from the pointer in code above that when _positionAmount multply by _tradeAmount is greater than or equal to 0, it assumes the position is open and assigns _valueUpdate to deltaEntry. The problem is that this condition has a flaw as it is assuming only positive _positionAmount and positive _tradeAmount should mean position is open but that would not be the case when they are both negative as the multiplication of negative _positionAmount and negative _tradeAmount would give a positive value which will give the wrong assumption that the position is open when it is not actually open there by assigning a wrong value to deltaEntry and payoff variable
