# Vulnerability details

## Impact
The `receivedAmount0` and `receivedAmount1` values are obtained from the `burn` operation on the UniswapV3Pool contract. These values represent the amounts of tokens received after burning the liquidity position.

[Perp.rebalanceForInRange#L284-L288](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L284-L288)
```solidity
updateRebalancePosition(
    _assetStatusUnderlying,
    int256(receivedAmount0) - int256(requiredAmount0),
    int256(receivedAmount1) - int256(requiredAmount1)
);
```
The `requiredAmount0` and `requiredAmount1` values are obtained from the `mint `operation on the UniswapV3Pool contract. These values represent the amounts of tokens required to mint the new liquidity position.

> The problem arises when the `receivedAmount0` and `receivedAmount1` values are smaller than the `requiredAmount0` and `requiredAmount1` values, respectively. In this case, the subtraction operation will result in negative values, which may not be the intended behavior.

For example, if `receivedAmount0` is 100 and `requiredAmount0` is 200, the subtraction `int256(receivedAmount0) - int256(requiredAmount0)` will result in -100. This negative value may not be handled correctly by the `updateRebalancePosition` function.

An example of how the `updateRebalancePosition` function might be implemented
```solidity
function updateRebalancePosition(
    DataType.PairStatus storage _pairStatus,
    int256 _updateAmount0,
    int256 _updateAmount1
) internal {
    SqrtPerpAssetStatus storage sqrtAsset = _pairStatus.sqrtAssetStatus;

    if (_pairStatus.isQuoteZero) {
        _pairStatus.quotePool.tokenStatus.updatePosition(
            sqrtAsset.rebalancePositionQuote, _updateAmount0, _pairStatus.id, true
        );
        _pairStatus.basePool.tokenStatus.updatePosition(
            sqrtAsset.rebalancePositionBase, _updateAmount1, _pairStatus.id, false
        );
    } else {
        _pairStatus.basePool.tokenStatus.updatePosition(
            sqrtAsset.rebalancePositionBase, _updateAmount0, _pairStatus.id, false
        );
        _pairStatus.quotePool.tokenStatus.updatePosition(
            sqrtAsset.rebalancePositionQuote, _updateAmount1, _pairStatus.id, true
        );
    }
}
```
In this implementation, the `updatePosition` function is called with the negative values for `_updateAmount0` and `_updateAmount1`. If the `updatePosition` function is not designed to handle negative values correctly, it could lead to unexpected behavior or errors.

## Recommended Mitigation Steps
Adding a check to ensure that the `receivedAmount0` and `receivedAmount1` values are greater than or equal to the `requiredAmount0` and `requiredAmount1` values, respectively. If the received amounts are smaller, you could handle the situation appropriately, such as reverting the transaction or logging an error message.
