# Vulnerability details

## Impact
Malicious users cannot be liquidated resulting to bad debt

## Proof of Concept
The major issue is that the liquidation transaction tries to send `quotePool.token`   to the liquidated user's `vault.recipient` in the middle of the liquidation transaction. For tokens that have blacklist feature like USDC, a malicious user can simply copy one of the blacklisted addresses [here](https://etherscan.io/address/0x10DF6B6fe66dd319B1f82BaB2d054cbb61cdAD2e)

For example this address `0x0E6b8E34dC115a2848F585851AF23D99D09b8463` was blacklisted 8 days ago.

A malicious user can set the above blacklisted account as their `vault.recipient` with the `updateRecepient(...)` function when their account is about to be liquidated to prevent liquidation.

USDC is one of the tokens to be integrated to Predy as indicated on the contest page, a user can prevent themselves from being liquidated by setting their `vault.recipient` as any USDC blakclisted account. This way the transaction will revert when trying to transfer USDC to the `vault.recipient` with the line below
```
ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);//@audit blacklisted vault.recipient can be used to prevent liquidation
```

## Recommended Mitigation Steps
Consider updating the state with the `sentMarginAmount` so that the liquidated user pulls their token themselves in a different transaction from the liquidation instead of trying to send token to the liquidated user in the middle of the liquidation transaction.
