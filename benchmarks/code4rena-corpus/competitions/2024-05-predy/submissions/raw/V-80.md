# Vulnerability details

## Impact
`USDC` is supported by the protocol. Note, it has `blacklist` functionality. Thus `USDC` tokens can't be transferred to/from blacklisted address.

During the `liquidation` process, any remaining `margin` will be  transferred to the `vault recipient`. This could be distributed using any tokens supported by the protocol, including `USDC`. 

However, if the `USDC` contract blacklists the `vault recipient`, the liquidation transaction will revert. As a result, the  debt will be unable to be liquidated if they have been blacklisted by the `USDC` token contract.

## Proof of Concept
The [liquidate()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L93-L100) executes a liquidation call to close an unsafe `vault` and sends the `remaining margin` to the recipient.
```solidity
                if (vault.recipient != address(0)) {
                    // Send the remaining margin to the recipient.
                    vault.margin = 0;


                    sentMarginAmount = uint256(remainingMargin);


                    ERC20(pairStatus.quotePool.token).safeTransfer(vault.recipient, sentMarginAmount);
                }
```
If `pairStatus.quotePool.token` is `USDC`, the liquidation process might DoS due to its reliance on paying back remaining `margin`. This will error where transferring `USDC` tokens to blacklisted users can cause the transaction to be reverted, disrupting the liquidation flow. This will result in a `bad debt` for the platform.

**There is also a possibility that this can be done intentionally by a malicious vault owner.**
---> During vault creation, the creator is both the `owner` and `recipient`. But later, the vault owner can change the `recipient`.
 
- A malicious vault owner calls the [updateRecepient()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L286-L292)
```solidity
    function updateRecepient(uint256 vaultId, address recipient) external onlyVaultOwner(vaultId) {
        DataType.Vault storage vault = globalData.vaults[vaultId];


        vault.recipient = recipient;


        emit RecepientUpdated(vaultId, recipient);
    }
```
This function enables him to set the `recipient` to a USDC blacklisted address by intention.

As such, during liquidation, the whole flow reverts and his vault remains a debt bomb. 

## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove the transfer of remaining `margin` to the `recipient` during the liquidation flow. Instead, allow the user to withdraw their remaining `margin` on their own after the liquidation process is complete.
