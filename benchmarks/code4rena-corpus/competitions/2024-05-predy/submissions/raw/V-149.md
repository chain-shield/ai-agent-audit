# Vulnerability details

## Impact
The Predy protocol relies on a Chainlink price which lacks checks for the staleness of the price obtained from Chainlink. If the price is stale, the function `getSqrtPrice()` will return a wrong price. 

## Description
The function `getSqrtPrice()` is using Chainlink price and Pyth price to calculate the square root of the baseToken price quoted in quoteToken:
```solidity
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        require(quoteAnswer > 0 && basePrice.price > 0);

        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;

        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```
The problem is that there is not check for stale data from Chainlink. There are some [reasons](https://ethereum.stackexchange.com/questions/133242/how-future-resilient-is-a-chainlink-price-feed/133843#133843) that the price feed can become stale.

Additionally, it is important to check if the Arbitrum sequencer is active. Please refer to the [chainlink](https://docs.chain.link/data-feeds/l2-sequencer-feeds) doc for more information.

Impact: The same issue found in other [C4 report](https://github.com/code-423n4/2023-06-stader-findings/issues/15#issuecomment-1596573683) is defined as Medium

## Tools Used
Manual Review

## Recommended Mitigation Steps
Read the [updatedAt](https://docs.chain.link/data-feeds/api-reference#latestrounddata) return value from the Chainlink.latestRoundData() function and verify that is not older than than specific time tolerance.
