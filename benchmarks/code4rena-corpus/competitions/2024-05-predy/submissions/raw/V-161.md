# Vulnerability details

## Impact
The current condition **`if (gammaOrder.quantity != 0 || gammaOrder.quantitySqrt != 0 || gammaOrder.marginAmount != 0)`** is checking if any of the order quantities or the margin amount is non-zero. If this condition is true, it reverts the transaction with the `InvalidOrder` error. However, based on the function's name and the subsequent code that calls `_saveUserPosition` with `gammaOrder.modifyInfo`, the intended behavior seems to be allowing modifications to the user's position when the order quantities and margin amount are zero.

This means that if a user tries to modify their position without changing the quantities or margin amount (e.g., updating the hedge interval, slippage tolerance, or other position parameters), the transaction will be reverted due to the incorrect condition check. This behavior is counterintuitive and prevents users from modifying their positions as intended.

Additionally, if the condition is satisfied (i.e., all order quantities and margin amount are zero), the function proceeds to call `_saveUserPosition` with `gammaOrder.modifyInfo`. This suggests that the intended behavior is to modify the user's position based on the provided `modifyInfo` parameters, which could include changes to various position settings like hedge interval, slippage tolerance, expiration, etc.

## Proof of Concept
A user has an existing position with `positionId 1`.
The user wants to modify the position by changing the hedge interval and slippage tolerance, but without changing the position quantities or margin amount.
The user creates a `GammaOrder` with `quantity`, `quantitySqrt`, and `marginAmount` set to 0, and the desired `modifyInfo` parameters.
When the user calls `_modifyAutoHedgeAndClose` with this order, the condition `if (gammaOrder.quantity != 0 || gammaOrder.quantitySqrt != 0 || gammaOrder.marginAmount != 0)` will be false, causing the function to revert with the `InvalidOrder` error.

This prevents the user from modifying their position as intended, even though the order quantities and margin amount are zero, which should be a valid case for position modification.

## Recommended Mitigation Steps
The condition should be inverted to:
```solidity
if (gammaOrder.quantity == 0 && gammaOrder.quantitySqrt == 0 && gammaOrder.marginAmount == 0) {
    // Proceed with modifying the user position
    ResolvedOrder memory resolvedOrder = GammaOrderLib.resolve(gammaOrder, sig);
    _verifyOrder(resolvedOrder);

    // save user position
    GammaTradeMarketLib.UserPosition storage userPosition =
        _getOrInitPosition(gammaOrder.positionId, false, gammaOrder.info.trader, gammaOrder.pairId);

    _saveUserPosition(userPosition, gammaOrder.modifyInfo);
} else {
    revert InvalidOrder("Order quantities or margin amount must be zero for position modification");
}
```
This way, the function will only proceed with modifying the user's position if the order quantities and margin amount are all zero, as intended. If any of them are non-zero, it will revert with a more informative error message.
