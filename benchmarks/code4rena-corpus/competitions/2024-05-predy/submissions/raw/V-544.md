# Vulnerability details

## Impact
A malicous creator can manipulate the fees with a cheap token then withdraw with more expensive token.

## Proof of Concept
- Since anyone can create a pair an attacker creates `WBTC/USDC` pair.
- The attacker manipulates the protocol by trading the pair.
- `creatorRevenue` is the accumulated fees in the protocol. Lets say for the pair WBTC/USDC. and the accumulated usdc fees is 200. 
The amount the attacker can withdraw should be 200 USDC. but the `poolOwner` calls 
`withdrawCreatorRevenue` and marks the `isQuoteToken` as false
- The function retrieves the pool 
```javascript
     Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);
```
- Then it checks the accumulated amount 
```javascript
     uint256 amount = pool.accumulatedCreatorRevenue;;
```
- if it was 200 usdc it sends 200wBTC instead since there is no check to see the typeof Accumulated Fees.

```javascript
if (amount > 0) {
            ERC20(pool.token).safeTransfer(msg.sender, amount);
        }
```
