# Vulnerability details

## Impact
- Market operation involving `_removePosition` will fail due to outOfGas error
## Description
`GammaTradeMarket` stores each user's positionId in a mapping array. One user can have many positions.  
```
mapping(address owner => uint256[]) internal positionIDs;
```
It manipulates the array using a function in `ArrayLib.sol`.  

There is a remove operation function that iterates each item on the array one by one until the match is found.  
See: [ArrayLib.sol#L9-L31](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/gamma/ArrayLib.sol#L9-L31)
```
function removeItem(uint256[] storage items, uint256 item) internal {
    uint256 index = getItemIndex(items, item);

    removeItemByIndex(items, index);
}

function removeItemByIndex(uint256[] storage items, uint256 index) internal {
    items[index] = items[items.length - 1];
    items.pop();
}

function getItemIndex(uint256[] memory items, uint256 item) internal pure returns (uint256) {
    uint256 index = type(uint256).max;

    for (uint256 i = 0; i < items.length; i++) {
        if (items[i] == item) {
            index = i;
            break;
        }
    }

    return index;
}
```
Reading value from storage is an expensive operation, iterating over a large array will cost a very large amount of gas.  
The worst case here is O(n) where match is in the last item of positionIds array.  

Therefore, an execution flow involving `removeItem` can potentially fail due to outOfGas error for user with many positions.  
`execLiquidationCall`, a function to liquidate user's position, uses `removeItem` when the position is completely closed.  
See: [GammaTradeMarket.sol#L138-L149](https://github.com/code-423n4/2024-05-predy/blob/main/src/markets/gamma/GammaTradeMarket.sol#L138-L149)
```
function execLiquidationCall(
    uint256 vaultId,
    uint256 closeRatio,
    IFillerMarket.SettlementParamsV3 memory settlementParams
) external override returns (IPredyPool.TradeResult memory tradeResult) {
    tradeResult =
        _predyPool.execLiquidationCall(vaultId, closeRatio, _getSettlementDataFromV3(settlementParams, msg.sender));

    if (closeRatio == 1e18) {
        _removePosition(vaultId);
    }
}
```

A malicious user can open a lot of small positions and one real position at the end, this would likely cause outOfGas error when `execLiquidationCall` is called to liquidate that position.  

However, only `execLiquidationCall` in `GammaTradeMarket` is affected. Liquidation can still be triggerred directly in `PredyPool.sol`


## Proof-of-Concept
I wrote a test to demonstrate that if the match is at the last index of a very large array it will consume gas more than block limit on Arbitrum and Optimism.  
### Steps
(1) Add a new test below in `2024-05-predy/test/market/gamma/ArrayLib.t.sol`  
(2) Run `forge test --gas-report --match-contract TestArrayLib --match-test testRemoveManyItems -vv`
```
function testRemoveManyItems() public{
    uint i=0;
    for(i=0;i<2000;++i){
        ArrayLib.addItem(_items, i);
    }
    ArrayLib.removeItem(_items, i-1);
}
```  
(3) Observe that it consume `45_571_853` gas.
