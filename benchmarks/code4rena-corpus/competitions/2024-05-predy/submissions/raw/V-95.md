# Vulnerability details

## Impact
Incorrect handling of `closeAmount` and `openAmount` can result in the following issues:

  - If the user is attempting to partially close their existing position, the current implementation may incorrectly interpret it as closing the entire position and opening a new position in the opposite direction. This can lead to incorrect updates to the user's position and the overall system state.
  - If the user's position is not updated correctly, it can result in financial losses or unintended gains. For example, if the user intends to partially close their position but the system incorrectly opens a new position in the opposite direction, the user may end up with an unintended exposure to market movements.
  - The incorrect position updates can lead to an inconsistent system state, where the user's position and the overall system state do not accurately reflect the intended actions and market conditions.

The issue is the following block of code: [updateSqrtPosition#L538-L543](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L538-L543)
```solidity
if (_userStatus.sqrtPerp.amount.abs() >= _amount.abs()) {
    closeAmount = _amount;
} else {
    openAmount = _userStatus.sqrtPerp.amount + _amount;
    closeAmount = -_userStatus.sqrtPerp.amount;
}
```
This code block assumes that if the absolute value of `_userStatus.sqrtPerp.amount` is less than the absolute value of `_amount`, then the user is closing their existing position and opening a new position in the opposite direction.

But despite that, this assumption may not always be correct. Consider the following scenario.

`_userStatus.sqrtPerp.amount` is initially 100
`_amount` is -50

In this case, the user is not opening a new position in the opposite direction but rather partially closing their existing position. The correct behavior should be:

`closeAmount` should be -50 (the user is closing part of their existing position)
`openAmount` should be 0 (the user is not opening a new position)

The current implementation would incorrectly set `openAmount` to 50 and `closeAmount` to -100, which is not the intended behavior.

## Proof of Concept
Consider the following scenario:

`_userStatus.sqrtPerp.amount` is initially 100 (representing a long position)
`_amount` is -50 (the user wants to partially close their long position)

According to the current implementation, the following assignments will occur: [updateSqrtPosition#L541-L543](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L541-L543)
```solidity
openAmount = _userStatus.sqrtPerp.amount + _amount; // openAmount = 100 + (-50) = 50
closeAmount = -_userStatus.sqrtPerp.amount; // closeAmount = -100
```
This means that instead of partially closing the existing long position of 100 by 50, the system will interpret it as:

test that confirms Closing the entire long position of 100 (`closeAmount = -100`)
Opening a new short position of 50 (`openAmount = 50`)

This behavior is incorrect and does not align with the user's intended action of partially closing their existing long position.
```solidity

import "forge-std/Test.sol";
import "../Perp.sol";

contract PerpTest is Test {
    Perp.UserStatus userStatus;

    function setUp() public {
        userStatus.sqrtPerp.amount = 100;

    function testPartialClosePosition() public {
        int256 amount = -50;

        int256 openAmount;
        int256 closeAmount;

        if (userStatus.sqrtPerp.amount.abs() >= amount.abs()) {
            closeAmount = amount;
        } else {
            openAmount = userStatus.sqrtPerp.amount + amount;
            closeAmount = -userStatus.sqrtPerp.amount;
        }

        // Incorrect behavior
        assertEq(openAmount, 50);
        assertEq(closeAmount, -100);

        // Expected behavior
        assertEq(openAmount, 0);
        assertEq(closeAmount, -50);
    }
}
```

## Recommended Mitigation Steps
```solidity
if (_userStatus.sqrtPerp.amount * _amount >= 0) {
    openAmount = _amount;
    closeAmount = 0;
} else {
    int256 remainingAmount = _userStatus.sqrtPerp.amount + _amount;
    if (remainingAmount == 0) {
        openAmount = 0;
        closeAmount = _userStatus.sqrtPerp.amount;
    } else if (remainingAmount > 0) {
        openAmount = remainingAmount;
        closeAmount = -_userStatus.sqrtPerp.amount;
    } else {
        openAmount = 0;
        closeAmount = _amount;
    }
}
```
This code handles the cases where the user is partially closing their existing position, as well as the cases where they are fully closing their position or opening a new position in the opposite direction.
