# Vulnerability details

## Impact
`GammaTradeMarket::getUserPositions` will always revert for users that have 100's or 1000's of trades open.

## Proof of Concept
Unbounded for loops are dangerous and should be avoid if possible, see the following [article](https://medium.com/@JohnnyTime/solidity-smart-contract-unbounded-loops-dos-attack-vulnerability-explained-with-real-example-f4b4aca27c08). 

Steps to attack are:
1. User opens 100's of trades
2. Then calling `GammaTradeMarket::getUserPositions` will revert due reaching the block gas limit.

This can be a critical problem if other contracts call this function or this function is used to update user's open positions for __liquidation bots__.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a variable that will limit the number of loops to prevent from reaching the gas limit. This will ensure that the `getUserPositions` function is still useful even if the users have 100's or 1000's of trades open.

See the code below for a possible solution:
```
        function getUserPositions(address owner, uint256 numberResults) external returns (UserPositionResult[] memory) {
        uint256[] memory userPositionIDs = positionIDs[owner];
        uint256 loopLimit;

        if (numberResults < userPositionIDs.length) {
            UserPositionResult[] memory results = new UserPositionResult[](numberResults);
            loopLimit = numberResults;
        } else {
            UserPositionResult[] memory results = new UserPositionResult[](userPositionIDs.length);
            loopLimit = userPositionIDs.length;
        }

        for (uint64 i = 0; i < loopLimit; i++) {
            uint256 positionId = userPositionIDs[i];

            results[i] = _getUserPosition(positionId);
        }

        return results;
    }

```
