# Vulnerability details

## Proof of Concept
The function `sell` in the `SettlementCallbackLib` library contains a potential issue where the calculation of `quoteAmount` may round down to zero due to integer division in Solidity. This occurs when the `sellAmount` and `price` values are not appropriately scaled relative to `Constants.Q96`.

Here is the relevant code snippet:
```solidity
function sell(
    IPredyPool predyPool,
    address quoteToken,
    address baseToken,
    SettlementParams memory settlementParams,
    address sender,
    uint256 price,
    uint256 sellAmount
) internal {
    if (settlementParams.contractAddress == address(0)) {
        // direct fill
        uint256 quoteAmount = sellAmount * price / Constants.Q96;

        predyPool.take(false, sender, sellAmount);

        ERC20(quoteToken).safeTransferFrom(sender, address(predyPool), quoteAmount);

        return;
    }

    // Additional logic for contract-based settlement
}
```
[SettlementCallbackLib.sol#L101](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/base/SettlementCallbackLib.sol#L101)
The potential issue arises in this calculation:
```solidity
uint256 quoteAmount = sellAmount * price / Constants.Q96;
```
Given the constants:
Constants.Q96: 7.9228163×10^28
`sellAmount`: 10^8 (for 1 WETH in wei)
`price`: 10^18 (if price is significantly lower)
Substituting the values:
`10^8 x 10^18 / 7.9228163 x 10^28 = 10^26 / 7.9228163 x 10^28 ≈ 0.012621774`
When using integer division in Solidity, this result will round down to zero, potentially leading to incorrect settlements.
## Impact
The impact of this rounding issue is that it may result in the quoteAmount being calculated as zero, which could lead to erroneous or incomplete settlements.

## Recommended Mitigation Steps
Scale the price to maintain precision before performing the division. This ensures that the division does not inadvertently round down to zero.
```solidity
function sell(
    IPredyPool predyPool,
    address quoteToken,
    address baseToken,
    SettlementParams memory settlementParams,
    address sender,
    uint256 price,
    uint256 sellAmount
) internal {
    if (settlementParams.contractAddress == address(0)) {
        // direct fill
        uint256 scaledPrice = price * 1e18; // Scale price to maintain precision
        uint256 quoteAmount = (sellAmount * scaledPrice) / Constants.Q96;

        predyPool.take(false, sender, sellAmount);

        ERC20(quoteToken).safeTransferFrom(sender, address(predyPool), quoteAmount);

        return;
    }

    // Additional logic for contract-based settlement
}
```
By scaling the `price` with a factor of 10^18, the division operation retains more precision, thereby preventing the result from rounding down to zero. This ensures the `quoteAmount` calculation is accurate and settlements are executed correctly.
