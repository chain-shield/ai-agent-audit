# Vulnerability details

## Impact
In the `calculateSlippageTolerance` function, there is a potential for underflow due to inconsistent data types used in arithmetic operations.

An underflow in the slippage tolerance calculation can lead to incorrect slippage values.

## Proof of Concept
The `calculateSlippageTolerance` function calculates the slippage tolerance based on the `minMargin` and `vaultValue` parameters. The function uses the `riskParams.maxSlippage` and `riskParams.minSlippage` values to determine the slippage tolerance.

```solidity
    function calculateSlippageTolerance(int256 minMargin, int256 vaultValue, Perp.AssetRiskParams memory riskParams)
        internal
        pure
        returns (uint256)
    {
        if (vaultValue <= 0 || minMargin == 0) {
            return riskParams.maxSlippage;
        }


        uint256 ratio = uint256(vaultValue * 1e4 / minMargin);


        if (ratio > 1e4) {
            return riskParams.minSlippage;
        }


        return (riskParams.maxSlippage - ratio * (riskParams.maxSlippage - riskParams.minSlippage) / 1e4);
    }
```

While the `ratio` variable is a `uint256`, the `riskParams.maxSlippage` is a `uint64`

```solidity
    struct AssetRiskParams {
        uint128 riskRatio;
        uint128 debtRiskRatio;
        int24 rangeSize;
        int24 rebalanceThreshold;
        uint64 minSlippage;
        uint64 maxSlippage;
    }
```

If `riskParams.maxSlippage` is less than the calculated `ratio` multiplied by the difference between `riskParams.maxSlippage` and `riskParams.minSlippage`, the operation can result in an underflow.

This can cause the function to return an incorrect slippage tolerance value, potentially resulting in financial losses.

## Tools Used
Manual review

## Recommended Mitigation Steps
To avoid the potential underflow, the `riskParams.maxSlippage` value should be cast to `uint256` before performing the subtraction.
