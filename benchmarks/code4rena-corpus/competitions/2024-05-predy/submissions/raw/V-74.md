# Vulnerability details

### Background
- There is a function in the `PriceFeed` contract for a given pair that returns the square root of the baseToken price quoted in quoteToken.

```solidity
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
    (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

    IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

    require(basePrice.expo == -8, "INVALID_EXP");
    require(quoteAnswer > 0 && basePrice.price > 0);

    uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
    price = price * Constants.Q96 / _decimalsDiff;

    sqrtPrice = FixedPointMathLib.sqrt(price);
}
```

- This function is called by `getSqrtIndexPrice()` in the `PositionCalculator` whenever a price feed is available.

```solidity
function getSqrtIndexPrice(DataType.PairStatus memory pairStatus) internal view returns (uint256 sqrtPriceX96) {
    if (pairStatus.priceFeed != address(0)) {
        return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
    } else {
        return UniHelper.convertSqrtPrice(
            UniHelper.getSqrtTWAP(pairStatus.sqrtAssetStatus.uniswapPool), pairStatus.isQuoteZero
        );
    }
}
```

- This function is, in turn, called by the function with the same name in the `PredyPool` contract and by the internal `calculateMinMargin()` function in the `PositionCalculator`.

1. **PredyPool's `getSqrtIndexPrice()` Function**

    ```solidity
    
    function getSqrtIndexPrice(uint256 pairId) external view returns (uint256) {
        return PositionCalculator.getSqrtIndexPrice(globalData.pairs[pairId]);
    }

    ```

    This function is called by:
    - The `autoHedge()` and `autoClose()` routines in the `GammaTradeMarket` contract to perform actions like hedging or closing positions based on the position price.
    - The `predyTradeAfterCallback()` function in the `PrepMarketV1` contract, via the internal `_calculateInitialMargin()` routine, to calculate the margin amount that users need to provide when executing orders.

2. **PositionCalculator's Internal `calculateMinMargin()` Function**

    ```solidity

    function calculateMinMargin(
        DataType.PairStatus memory pairStatus,
        DataType.Vault memory vault,
        DataType.FeeAmount memory feeAmount
    ) internal view returns (int256 minMargin, int256 vaultValue, bool hasPosition, uint256 sqrtOraclePrice) {
        int256 minValue;
        uint256 debtValue;

        sqrtOraclePrice = getSqrtIndexPrice(pairStatus);

        (minValue, vaultValue, debtValue, hasPosition) = calculateMinValue(
            vault.margin,
            getPositionWithFeeAmount(vault.openPosition, feeAmount),
            sqrtOraclePrice,
            pairStatus.riskParams.riskRatio
        );

        int256 minMinValue = (calculateRequiredCollateralWithDebt(pairStatus.riskParams.debtRiskRatio) * debtValue).toInt256() / 1e6;

        minMargin = vaultValue - minValue + minMinValue;

        if (hasPosition && minMargin < Constants.MIN_MARGIN_AMOUNT) {
            minMargin = Constants.MIN_MARGIN_AMOUNT;
        }
    }

    ```

   - This function is called by various functions such as `liquidate()`, `trade()`, and `getIsSafe()`, all of which essentially check the minimum margin requirements after important actions.

### Impact:

- It is essential that the price returned by the `getSqrtIndexPrice()` function in the `PositionCalculator` library is accurate. If it is not, it can disrupt many critical functionalities and lead to many vulnerabilities.
- Since this `getSqrtPrice` function is a key part of several important operations, an incorrect price update can have significant impacts, including but not limited to:
   - **Bypassing Minimum Margin Requirements**: Users can create positions bypassing the minimum margin requirement. 
   - **Inflated Margin Accounting**: Users my higher leverage than they should due to inflated margin calculations, or they will be DOS from creating position if the deflated price is reported.
  - **Disruption of Automated Functions**: Key features like `autoHedge()` and `autoClose()` for gamma trading could malfunction or become inoperable.

### Vulnerbility 
- Problem here is that in getSqrtPrice() function, when quote price is fetched by chainlink oracle/Aggregator via chainlinks `latestRoundData()`,tere is no check ensuring freshness of the price.

```
   function getSqrtPrice() external view returns (uint256 sqrtPrice) {
       (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();


       IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);


       require(basePrice.expo == -8, "INVALID_EXP");


       require(quoteAnswer > 0 && basePrice.price > 0);
       uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
       price = price * Constants.Q96 / _decimalsDiff;


       sqrtPrice = FixedPointMathLib.sqrt(price);
   }

```
- There is no verification of the timestamp returned by this latest round of aggregator, this allows for possibility that the latest round may be from a long time ago, when the asset's price was significantly different from its current value.
- Chainlink also advise developers to check for the updatedAt variable before using the price:

    -  "Your application should track the latestTimestamp variable or use the updatedAt value from the latestRoundData() function to make sure that the latest answer is recent enough for your application to use it. If your application detects that the reported answer is not updated within the heartbeat or within time limits that you determine are acceptable for your application, pause operation or switch to an alternate operation mode while identifying the cause of the delay."

### Recommendation
 - Consider implementing the checks suggested as per [chainlink documentation](https://docs.chain.link/data-feeds/api-reference) when calling lastestRounData()
