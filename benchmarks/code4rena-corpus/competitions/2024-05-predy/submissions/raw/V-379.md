# Vulnerability details

## Impact

A common code is to check Chainlink `updateAt` returned data against a __maximum feed age__ for staleness issue. Although it check for an answer greater than zero, `PriceFeed::getSqrtPrice()` doesn't check for previous issue.

```solidity
    function getSqrtPrice() external view returns (uint256 sqrtPrice) {
@-->    (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);

        require(basePrice.expo == -8, "INVALID_EXP");

        require(quoteAnswer > 0 && basePrice.price > 0);

        uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
        price = price * Constants.Q96 / _decimalsDiff;

        sqrtPrice = FixedPointMathLib.sqrt(price);
    }
```

Many [reasons](https://ethereum.stackexchange.com/questions/133242/how-future-resilient-is-a-chainlink-price-feed/133843#133843) can explain that an Oracle price feed becomes stale. Using a stale price will result in incorrect calculations of the square root of the baseToken price quoted in quoteToken.

In the meantime, Chainlink aggregators have a built in circuit breaker if the price of an asset goes outside of a predetermined price band. The result is that if an asset experiences a huge drop in value, the price of the oracle will continue to return the minPrice instead of the actual price of the asset. This would allow user to continue borrowing with the asset but at the wrong price.  
If an asset collapses, the protocol can be manipulated and behave unpredictably.

It's also important to mention that the protocol will be deployed Arbitrum and Optimism among others chains, which means that it's crucial to ensure that the prices provided are not falsely perceived as fresh, even when the sequencer is down. Which it is not ensured in the contracts, allowing malicious actors to gain an unfair advantage.

## Recommended Mitigation Steps

Read the `updatedAt` parameter from the call to the aggregator's `latestRoundData` function and verify it isn't below a certain value (time). In the example below, I checked `quoteAnswer` against zero for gas optimization purpose.
