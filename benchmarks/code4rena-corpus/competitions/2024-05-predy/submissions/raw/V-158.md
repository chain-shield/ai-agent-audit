# Vulnerability details

## Impact
Users may receive more tokens than they should when withdrawing assets from the contract.

**`Explanation`**
The `removeAsset` function is responsible for calculating the amount of tokens that should be burned (`finalBurnAmount`) and the corresponding amount of underlying assets that should be withdrawn (`finalWithdrawAmount`). The calculation of `finalWithdrawAmount` is performed using the following https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/ScaledAsset.sol#L65
```solidity
finalWithdrawAmount = FixedPointMathLib.mulDivDown(finalBurnAmount, tokenState.assetScaler, Constants.ONE);
```
The `FixedPointMathLib.mulDivDown` function performs a multiplication and division operation, rounding down the result to the nearest integer. The intention is to calculate the amount of underlying assets that correspond to the `finalBurnAmount` of tokens, based on the current `assetScaler` value.

However, this calculation assumes that `tokenState.assetScaler` is always greater than or equal to `Constants.ONE`. If `tokenState.assetScaler` is less than `Constants.ONE`, the calculation will result in a value that is greater than the intended `finalWithdrawAmount`.

Example:
Let's consider the example you provided:

`finalBurnAmount` = 100
`tokenState.assetScaler` = 0.9
`Constants.ONE` = 1

The calculation would be:
```solidity
finalWithdrawAmount = FixedPointMathLib.mulDivDown(100, 0.9, 1)
                    = 100 * 0.9 / 1 (rounded down)
                    = 90
```
In this case, the `finalWithdrawAmount` should be less than 100 since the `assetScaler` is 0.9 (less than 1). However, the calculation results in 90, which is greater than the intended value.

## Proof of Concept
A test case where the `tokenState.assetScaler` is set to a value less than `Constants.ONE`, and then calling the `removeAsset` function with a non-zero `_amount`. The resulting `finalWithdrawAmount` will be greater than the expected value.

test case:
```solidity
import "forge-std/Test.sol";
import "../ScaledAsset.sol";

contract ScaledAssetTest is Test {
    ScaledAsset.AssetStatus assetStatus;

    function setUp() public {
        assetStatus = ScaledAsset.createAssetStatus();
        assetStatus.assetScaler = 0.9 * Constants.ONE; // Set assetScaler to 0.9
    }

    function testRemoveAssetWithAssetScalerLessThanOne() public {
        uint256 amount = 100;
        uint256 supplyTokenAmount = amount;

        (uint256 finalBurnAmount, uint256 finalWithdrawAmount) = ScaledAsset.removeAsset(
            assetStatus,
            supplyTokenAmount,
            amount
        );

        // Expected finalWithdrawAmount should be less than 100
        assertLt(finalWithdrawAmount, amount);
    }
}
```
In this test case, the `assetScaler` is set to 0.9 * `Constants.ONE` (assuming `Constants.ONE` is 1e18). When calling `removeAsset` with an amount of 100, the `finalWithdrawAmount` should be less than 100, but the current implementation will result in a value greater than or equal to 100.

The test passes because the `finalWithdrawAmount` is less than the original amount (100), as expected. This is due to the `assetScaler` being set to 0.9, which scales down the withdrawn amount.

## Recommended Mitigation Steps
The calculation should be modified to handle cases where `tokenState.assetScaler` is less than `Constants.ONE`. One possible solution is to use `FixedPointMathLib.mulDivUp` instead of `FixedPointMathLib.mulDivDown` to ensure that the result is always rounded up.
```solidity
finalWithdrawAmount = FixedPointMathLib.mulDivUp(finalBurnAmount, tokenState.assetScaler, Constants.ONE);
```
This way, if `tokenState.assetScaler` is less than `Constants.ONE`, the result will be rounded up to the nearest integer, ensuring that the `finalWithdrawAmount` is not greater than the intended value.
