# Vulnerability details

## Impact
The current implementation of the `PriceFeed` contract only accepts base prices with an exponent of `-8`. This strict requirement limits the contract's ability to interface with price feeds that provide values with different exponents. Most financial data can vary in exponent, especially in decentralized finance platforms, where different tokens and oracles may represent price values in various formats. This limitation could lead to potential integration issues, reducing the flexibility and usability of the contract across diverse protocols.

## Proof of Concept

```solidity
require(basePrice.expo == -8, "INVALID_EXP");
```
**Affected Code Snippet:**
```solidity
IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD);
require(basePrice.expo == -8, "INVALID_EXP");
require(quoteAnswer > 0 && basePrice.price > 0);
uint256 price = uint256(int256(basePrice.price)) * Constants.Q96 / uint256(quoteAnswer);
price = price * Constants.Q96 / _decimalsDiff;
sqrtPrice = FixedPointMathLib.sqrt(price);
```
**Explanation:**
The contract enforces that the exponent (`expo`) of the base price must be `-8`. If the exponent differs, even if valid and correctly representing a price value, the transaction is reverted. This strict validation doesn't allow for flexibility in handling prices with different scales or formats.

## Recommended Mitigation Steps
Adjust the price calculation logic to dynamically handle the exponent. Modify the contract to scale the price calculation based on the actual exponent of the base price.

```solidity
     if (basePrice.expo < 0) {
         price = uint256(int256(basePrice.price)) * (10 ** uint256(-basePrice.expo)) * Constants.Q96 / uint256(quoteAnswer);
     } else {
         price = uint256(int256(basePrice.price)) * Constants.Q96 / (10 ** uint256(basePrice.expo)) / uint256(quoteAnswer);
     }
```

Replace the strict exponent check with a validation that ensures the exponent is within a reasonable range (e.g., between `-18` and `0` for most ERC20 tokens)
