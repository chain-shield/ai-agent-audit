# Vulnerability details


## Impact

The protocol aims to deploy on Arbitrum, Base, Optimism and in certain cases, can choose to not deploy or use the chainlink/pyth oracle pricefeed for certain assets. In this case, uniswap oracle is used as a sort of fallback oracle. The issue however is that cost of manipulating TWAP on L2 networks is very low, and even Uniswap team has major concerns about using their oracle on L2s.

## Proof of Concept

From the readme

> Chains the protocol will be deployed on	Arbitrum,Base,Optimism

The information provided by the Uniswap team, as documented in the Uniswap Oracle Integration on [Layer 2 Rollups guide](https://docs.uniswap.org/concepts/protocol/oracle#oracles-integrations-on-layer-2-rollups), it discusses the pitfalls and issues that might arise with integration of uniswap oracle on l2. One important reason is due to their relatively small block times e.g arbitrum has approximately 0,25 seconds per block, making it them potentially vulnerable to price manipulations.

> Oracles Integrations on Layer 2 Rollups

> Optimism

> On Optimism, every transaction is confirmed as an individual block. The block.timestamp of these blocks, however, reflect the block.timestamp of the last L1 block ingested by the Sequencer. For this reason, Uniswap pools on Optimism are not suitable for providing oracle prices, as this high-latency block.timestamp update process makes the oracle much less costly to manipulate. In the future, it's possible that the Optimism block.timestamp will have much higher granularity (with a small trust assumption in the Sequencer), or that forced inclusion transactions will improve oracle security. For more information on these potential upcoming changes, please see the Optimistic Specs repo. For the time being, usage of the oracle feature on Optimism should be avoided.


Now, the contract has the option of using chainlink/pyth combination, but if its not set or not available, uniswap is used to query the price, exposing the vulnerability.

```solidity
    function getSqrtIndexPrice(DataType.PairStatus memory pairStatus) internal view returns (uint256 sqrtPriceX96) {
        if (pairStatus.priceFeed != address(0)) {
            return PriceFeed(pairStatus.priceFeed).getSqrtPrice();
        } else {
            return UniHelper.convertSqrtPrice(
                UniHelper.getSqrtTWAP(pairStatus.sqrtAssetStatus.uniswapPool), pairStatus.isQuoteZero
            );
        }
    }

```

The gotten `sqrtPriceX96` is then used to [calculate min margin](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/PositionCalculator.sol#L75) which helps check for a position's liquidatable state. It's also used in gamma market to [`autoHedge`](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L237), [`autoClose`](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L286) and to do [both](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L346). It's also used in [PerpMarketV1 contract](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L227). These function are all vulnerable to manipulations by a malicious user who can use this to gain an unfair advantage or grief other users.
