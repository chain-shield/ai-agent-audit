# Vulnerability details

## Impact
The absence of a reentrancy guard in the uniswapV3MintCallback function exposes the contract to a critical reentrancy attack. An attacker can exploit this vulnerability to call the uniswapV3MintCallback function recursively, which could result in unauthorized and unlimited transfers of tokens. This could lead to a complete depletion of the assets in the contract, as observed in the recent incident where Predy Pool was entirely drained of 219,585.737814 USDC and 83.9 WETH

## Proof of Concept
1- Setup: The attacker deploys a malicious contract that interacts with the vulnerable uniswapV3MintCallback function.
2- Initial Call: The attacker calls the uniswapV3MintCallback function, initiating the token transfer.
3- Reentrancy: Within the uniswapV3MintCallback, the attacker’s contract makes recursive calls to uniswapV3MintCallback before the initial execution completes.
4- Asset Drain: Each recursive call transfers tokens to the attacker, potentially draining the entire contract balance.
Even though the contract inherits from ReentrancyGuardUpgradeable, the current implementation of the uniswapV3MintCallback function does not benefit from reentrancy protection because it doesn't explicitly mark any function as nonReentrant. 
While it's true that the function is restricted to certain addresses (presumably those representing valid Uniswap pools) ,if the function interacts with external contracts (like transferring tokens to another contract), a reentrant call could exploit vulnerabilities , And if malicious actors can somehow manipulate this mapping to include their addresses, they could potentially gain unauthorized access to the function.

manual review

## Recommended Mitigation Steps
The reentrancy guard will ensure that the function cannot be called recursively, thus mitigating the risk of reentrancy exploits.
