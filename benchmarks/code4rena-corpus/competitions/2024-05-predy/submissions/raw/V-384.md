# Vulnerability details

## Summary
The `Bps::lower()` and `Bps::upper()` functions are not returning the correct values as per the design specified by the protocol team member. There is a discrepancy in the results when tested with specific inputs.

## Vulnerability Detail
The `lower` function is expected to return the value calculated as `lower = price / (1 + (0.01 * bps))`, and the `upper` function should return `upper = price * (1 + (0.01 * bps))`. However, when calling `lower` with `price = 10000` and `bps = 1`, it returns `10000000000` (in 1e6 base), which is incorrect. The expected result is `9900990100` (in the same 1e6 base). Similarly, the `upper` function should return `10100000000` but instead returns `0`. For larger arguments (`price = 10000000` and `bps = 1`), the `upper` function incorrectly returns `10`.

## Impact
Incorrect calculations in the `lower` and `upper` functions can lead to erroneous financial computations, potentially causing significant discrepancies in protocol operations and affecting the reliability and accuracy of the system.

## Code Snippet
```solidity
function upper(uint256 price, uint256 bps) internal pure returns (uint256) {
	return price * bps / ONE;
}

function lower(uint256 price, uint256 bps) internal pure returns (uint256) {
	return price * ONE / bps;
}
```
