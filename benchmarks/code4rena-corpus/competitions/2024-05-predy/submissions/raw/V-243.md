# Vulnerability details

## Impact
The method used to calculate the minimum value is incorrect which can lead to the result of minimum margin is incorrct.

## Proof of Concept
According to docs [position-value](https://docs.predy.finance/predy-v6/dev/position-value):
>To ensure the position value does not become zero even if the price moves by r, the difference between the minimum value of the position within a price movement of +/- r% and the current value is set as the minMargin

As we can see the r is risk parameter(e.g. r = 1.02).



protocol used [PositionCalculator.sol::calculateMinValue](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/PositionCalculator.sol#L186-L194) to calculate the upperPrice and the lowerPrice
```solidity 
function calculateMinValue(uint256 _sqrtPrice, PositionParams memory _positionParams, uint256 _riskRatio)
    internal
    pure
    returns (int256 minValue)
{
    minValue = type(int256).max;

    uint256 upperPrice = _sqrtPrice * _riskRatio / RISK_RATIO_ONE; //@audit
    uint256 lowerPrice = _sqrtPrice * RISK_RATIO_ONE / _riskRatio;
```

However due to above method we can't get a price movement of +/- r% on current price.
Assuming current price is `30000`, the riskRatio is `1.2`(20 percent of current price)

the upperPrice and the lowerPrice
```shell
upperPrice = 30000 * 1.2 / 1 = 36000
lowerPrice = 30000 * 1 / 1.2 = 25000
``` 

the percent of price movement
```shell
upperPrice = (36000 - 30000)/30000 = 0.2 = 20%
lowerPrice = (30000 - 25000)/30000 = 0.16 = 16%
```

As we can see there is 4 percent difference between 2 results.

## Tools Used
Foundry
## Recommended Mitigation Steps

when calculate the lowerPrice use

```shell
lowerPrice = _sqrtPrice * (RISK_RATIO_ONE - （_riskRatio - RISK_RATIO_ONE)) = 30000 * 0.8 = 24000
```
