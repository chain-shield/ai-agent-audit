# Vulnerability details

## Bug Description
In the calculation of `netValue` using the `_calculateNetValue`:
```solidity
uint256 netValue = _calculateNetValue(vault, price);
```
The problem is that the `_calculateNetValue`, based on the name of the function and the context, seems that the `netValue` should represent the total value of the user's position, including both the margin and the position value.

If this is the case, then the calculation of the initial margin requirement is incorrect:
```solidity
return (netValue / leverage).toInt256() - _calculatePositionValue(vault, sqrtPrice);
```
The initial margin requirement should be calculated as the difference between the total value of the position and the position value, not the other way around.

## Impact
The initial margin requirement is calculated as follows: [_calculateInitialMargin#L233](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L233)
```solidity
return (netValue / leverage).toInt256() - _calculatePositionValue(vault, sqrtPrice);
```
However, the correct calculation should be:
```solidity
return _calculatePositionValue(vault, sqrtPrice) - (netValue / leverage).toInt256();
```
The initial margin requirement should be the portion of the total position value that needs to be covered by the user's margin, taking into account the leverage factor.

**`Impact on Undercollateralized Positions`**
If the initial margin requirement is underestimated due to the incorrect calculation, users may be allowed to open positions with insufficient margin. This can lead to undercollateralized positions, where the user's margin is not enough to cover potential losses in case of adverse price movements.

For example, let's assume the following values:

`netValue` = 100 (total value of the user's position)
`leverage` = 2
`_calculatePositionValue(vault, sqrtPrice)` = 80

With the incorrect calculation.
```solidity
initialMarginRequirement = (100 / 2) - 80 = -30
```
The user would be required to deposit a negative margin, which is impossible. In this case, the user would likely be allowed to open the position without any margin, leading to an undercollateralized position.

With the correct calculation.
```solidity
initialMarginRequirement = 80 - (100 / 2) = 30
```
The user would be required to deposit a margin of 30, ensuring that the position is properly collateralized.

**`Impact on Excessive Margin Requirements`**
Conversely, if the initial margin requirement is overestimated due to the incorrect calculation, users may be required to deposit excessive margin, which can discourage participation and reduce the overall liquidity in the system.

## Proof of Concept
```solidity
// Assuming the following values
uint256 netValue = 100;
uint256 leverage = 2;
int256 positionValue = 80;

// Incorrect calculation
int256 initialMarginRequirement = (netValue / leverage).toInt256() - positionValue;
// initialMarginRequirement = 50 - 80 = -30 (incorrect)

// Correct calculation
int256 correctInitialMarginRequirement = positionValue - (netValue / leverage).toInt256();
// correctInitialMarginRequirement = 80 - 50 = 30 (correct)
```
The incorrect calculation results in a negative initial margin requirement, which is invalid and can lead to undercollateralized positions.

## Recommended Mitigation Steps
The correct calculation should be
```solidity
return _calculatePositionValue(vault, sqrtPrice) - (netValue / leverage).toInt256();
```
This way, the initial margin requirement is calculated as the portion of the total position value that needs to be covered by the user's margin, taking into account the leverage factor.
