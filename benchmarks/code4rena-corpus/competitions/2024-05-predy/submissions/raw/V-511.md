# Vulnerability details

## Impact
The `executeTradeL2`  decodes order parameters and uses them to execute a trade. However, the signature verification process does not include the `chainId`. Without incorporating the `chainId`, the same signed message can be replayed across different Ethereum networks, leading to potential unauthorized or repeated trades on multiple chains.

The replay attack could lead to:

- Unauthorized repeated trades across different Ethereum networks
- Financial losses for users
- Potential manipulation of trading logic or market prices

## Proof of Concept

To demonstrate the vulnerability, an attacker could:
1. Capture a valid `executeTradeL2` transaction with its `GammaOrderL2` data and signature on one Ethereum network.
2. Replay the same transaction on another Ethereum network where the contract is deployed, resulting in multiple executions of the trade.

## Recommended Mitigation Steps

To prevent this signature replay attack, incorporate the `chainId` in the signature verification process. 

1. **Update `OrderInfo` Struct to Include `chainId`**:

   ```solidity
   struct OrderInfo {
        address market;
        address trader;
        uint256 nonce;
        uint256 deadline;
        uint256 chainId; // Include chainId
   }

   ```

2. **Update Signature Generation to Include `chainId`**:
   Ensure the `chainId` is included in the hash. Here's an example using EIP-712:
   ```solidity

   library OrderInfoLib {
    bytes internal constant ORDER_INFO_TYPE = "OrderInfo(address market,address trader,uint256 nonce,uint256 deadline,uint256 chainId)";
    bytes32 internal constant ORDER_INFO_TYPE_HASH = keccak256(ORDER_INFO_TYPE);

    /// @notice hash an OrderInfo object
    /// @param info The OrderInfo object to hash
    function hash(OrderInfo memory info) internal pure returns (bytes32) {
        
        return keccak256(
            abi.encode(
                ORDER_INFO_TYPE_HASH,
                info.market, 
                info.trader, 
                info.nonce, 
                info.deadline
                info.chainId // Include chainId in the hash
        ,));
    }

   }

   ```


#### Additional Information
Including the `chainId` in the signature verification process ensures that signatures are valid only for the specific network, preventing replay attacks across different Ethereum networks. This modification enhances the security and integrity of the contract's trading functionality.
