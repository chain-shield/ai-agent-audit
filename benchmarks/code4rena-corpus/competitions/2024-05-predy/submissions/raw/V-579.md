# Vulnerability details

## Impact
Due to absence of proper access control of `initialize()` function of `PredyPool.sol`, attacker can frontrun the function and become `Operator`(Admin) of the protocol.

## Proof of Concept
In `PredyPool.sol`, `initialize()` function do not have any access control , due to which an attacker can frontrun the function when the real Operator calls `initialize()` function to initialize the pool and become `Operator`. 
```
function initialize(address uniswapFactory) public initializer {
        __ReentrancyGuard_init();
        AddPairLogic.initializeGlobalData(globalData, uniswapFactory);

        operator = msg.sender;
    }
```

## Tools Used
Manual Review
## Recommended Mitigation Steps
Implement proper access control on `initialize()` function of `PredyPool.sol` .
