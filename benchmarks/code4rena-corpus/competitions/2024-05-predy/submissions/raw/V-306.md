# Vulnerability details

## Proof of Concept
The vulnerability lies in the declaration of the [decimalsDiff](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PriceFeed.sol#L32) variable within the `PriceFeed` contract. Let's delve deeper into this:

In the current implementation, `decimalsDiff` is declared as a `uint256`:
```solidity
uint256 private immutable _decimalsDiff;
```
This data type choice restricts the variable to holding only non-negative integers. However, the nature of token decimals in financial systems can vary widely, and in some cases, the difference in decimals between the base token and the quote token can be negative. This situation arises when the base token has fewer decimals than the quote token.

For instance, consider a scenario where the base token has 8 decimals, while the quote token has 18 decimals. In this case, the difference in decimals would be -10.
```solidity
// Example where base token has 8 decimals and quote token has 18 decimals
int256 decimalsDiff = 8 - 18 = -10;
```
By restricting `decimalsDiff` to only non-negative values, the contract fails to account for cases where the base token has fewer decimals than the quote token. Consequently, the contract's functionality becomes limited, and it cannot accurately calculate prices for such token pairs.

This vulnerability affects the reliability and accuracy of the price feed mechanism, potentially leading to incorrect price calculations or even failures in scenarios where the base token has fewer decimals than the quote token.

## Impact
This vulnerability affects the reliability and accuracy of the price feed mechanism, potentially leading to incorrect price calculations or even failures in scenarios where the base token has fewer decimals than the quote token.
