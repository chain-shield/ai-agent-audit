# Vulnerability details

## Impact
`executeOrderV3` via `_executeOrderV3()` verifies `signature` of the `order_v3` and executes trade. However, this function fails to invoke the `_verifyOrderV3` within it to perform various verification on the provided trade details `perpOrder` before proceeding with trade execution. 

As such, a trade may be executed for a user with unsanitized information such as expired `deadline` and invalid `market`.

## Vulnerability Details
The [_executeTrade()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L160) in `GammaTradeMarket` first invokes `_verifyOrder` before proceeding with trade execution as shown here:
```solidity
        //...
        _verifyOrder(resolvedOrder); // @audit order verified here

        // execute trade
        tradeResult = _predyPool.trade(
            IPredyPool.TradeParams(
                gammaOrder.pairId,
                gammaOrder.positionId,
                gammaOrder.quantity,
                gammaOrder.quantitySqrt,
                abi.encode(
                    CallbackData(
                        GammaTradeMarketLib.CallbackType.TRADE, gammaOrder.info.trader, gammaOrder.marginAmount
                    )
                )
            ),
            _getSettlementDataFromV3(settlementParams, msg.sender)
        );
```
[_verifyOrder()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L444-L455) ensures that a trade can only be executed if the `order info` is validated to be as required by the protocol.
```solidity
    function _verifyOrder(ResolvedOrder memory order) internal {
        order.validate();

        _permit2.permitWitnessTransferFrom(
            order.toPermit(),
            order.transferDetails(address(this)),
            order.info.trader,
            order.hash,
            GammaOrderLib.PERMIT2_ORDER_TYPE,
            order.sig
        );
    }
```
Here is call [order.validate()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/orders/ResolvedOrder.sol#L21-L31) which performs the following verifications:
```solidity
    /// @notice Validates a resolved order, reverting if invalid
    /// @param resolvedOrder resovled order
    function validate(ResolvedOrder memory resolvedOrder) internal view {
        if (address(this) != address(resolvedOrder.info.market)) {
            revert InvalidMarket();
        }

        if (block.timestamp > resolvedOrder.info.deadline) {
            revert DeadlinePassed();
        }
    }
```
From this, an `order` cannot be traded if its `deadline` has expired or provided `market` is invalid.

However, in [_executeOrderV3()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L159), this verification is not performed:
```solidity
        //...
        // @audit-issue Missing trade verification
        tradeResult = _predyPool.trade(
            IPredyPool.TradeParams(
                perpOrder.pairId,
                userPosition.vaultId,
                tradeAmount,
                0,
                abi.encode(
                    CallbackData(
                        CallbackSource.TRADE3, perpOrder.info.trader, 0, perpOrder.leverage, resolvedOrder, orderId //!
                    )
                )
            ),
            _getSettlementDataFromV3(settlementParams, msg.sender)
        );
```
Without `order` verification, orders with expired `deadline` and invalid `market` can be traded which is not a desired occurance by the protocol.

## Recommended Mitigation Steps
Invoke [_verifyOrderV3()]() within `_executeOrderV3()` before proceeding with trade execution:
```solidity
_verifyOrderV3(resolvedOrder);
```
