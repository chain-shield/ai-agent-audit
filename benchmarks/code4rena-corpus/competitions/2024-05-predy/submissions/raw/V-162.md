# Vulnerability details

## Impact
**`GammaTradeMarket:autoClose`** is intended to close an existing position by executing a trade with the opposite position size. However, due to the negative sign applied to `vault.openPosition.perp.amount` and `vault.openPosition.sqrtPerp.amount`, the function is actually attempting to open a new position in the opposite direction of the existing position, rather than closing it.

> Instead of closing the existing position, the function will open a new position in the opposite direction, effectively doubling the user's exposure.

> If the newly opened position moves against the user, it can lead to a significant loss of funds, as the user's margin is now allocated to two opposing positions.

> The newly opened position will require additional margin, which may deplete the user's available margin, potentially triggering a liquidation event.

Present in the following line of code: [#L298-L304](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/markets/gamma/GammaTradeMarket.sol#L298-L304)
```solidity
IPredyPool.TradeParams memory tradeParams = IPredyPool.TradeParams(
    userPosition.pairId,
    userPosition.vaultId,
    -vault.openPosition.perp.amount, // Incorrect: Negative sign applied
    -vault.openPosition.sqrtPerp.amount, // Incorrect: Negative sign applied
    abi.encode(CallbackData(triggerType, userPosition.owner, 0))
);
```
To close the position correctly, the `tradeAmount` and `tradeAmountSqrt` should be assigned the values from `vault.openPosition.perp.amount` and `vault.openPosition.sqrtPerp.amount` without the negative sign.
```solidity
IPredyPool.TradeParams memory tradeParams = IPredyPool.TradeParams(
    userPosition.pairId,
    userPosition.vaultId,
    vault.openPosition.perp.amount, // Correct: No negative sign
    vault.openPosition.sqrtPerp.amount, // Correct: No negative sign
    abi.encode(CallbackData(triggerType, userPosition.owner, 0))
);
```
## Proof of Concept
Let's consider an example where a user has an existing long position with `vault.openPosition.perp.amount` equal to `100` and `vault.openPosition.sqrtPerp.amount` equal to `50`.

With the current implementation, the `autoClose` function will create a `tradeParams` with `tradeAmount` equal to `-100` and `tradeAmountSqrt` equal to `-50`, effectively opening a new short position instead of closing the existing long position.

_This can be easily reproduced by executing the `autoClose` function with an existing position and verifying that a new position in the opposite direction is opened instead of closing the existing one._
