# Vulnerability details

## Impact

Any external integrations that depends on the bool parameter risks being fed wrong data upon querying the `reallocate` function. This is because the function expects to return the `relocationOccurred` bool where as the internally queried `reallocate` function returns the `isRangeChanged` function instead. This can lead to unexpected reversions in these integrations, potential loss of funds, and poor user experience if active users continuosly trying to reallocate but keep getting showed the wrong information, or not believing that reallocation has occured when it infact hasn't, i.e silent reallocation failures.

BaseMarket.sol
```solidity
    function reallocate(uint256 pairId, IFillerMarket.SettlementParams memory settlementParams)
        external
        returns (bool relocationOccurred)
    {
        return _predyPool.reallocate(pairId, _getSettlementData(settlementParams));
    }
```
BaseMarketUpgradable.sol
```solidity
    function reallocate(uint256 pairId, IFillerMarket.SettlementParamsV3 memory settlementParams)
        external
        returns (bool relocationOccurred)
    {
        return _predyPool.reallocate(pairId, _getSettlementDataFromV3(settlementParams, msg.sender));
    }
```

The two contracts above call the `reallocate` function in PredyPool.sol which calls `reallocate` in  ReallocationLogic.sol
```solidity
    function reallocate(uint256 pairId, bytes memory settlementData)
        external
        nonReentrant
        returns (bool relocationOccurred)
    {
        return ReallocationLogic.reallocate(globalData, pairId, settlementData);
    }
```
In ReallocationLogic.sol, the `isRangeChanged` bool is returned instead, causing that information fed to the contracts above will be the status of the `isRangedChanged` rather than `relocationOccurred`.
```solidity
    function reallocate(GlobalDataLibrary.GlobalData storage globalData, uint256 pairId, bytes memory settlementData)
        external
        returns (bool isRangeChanged)
    {
```
