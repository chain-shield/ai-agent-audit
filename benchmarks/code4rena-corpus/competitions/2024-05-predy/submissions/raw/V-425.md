# Vulnerability details

## Impact
Part of the incentives is for creators to earn from depositing liquidity and protocol creator may lose fund to the Pool contract as its not properly implemented
In the `PreedyPool::withdrawCreatorRevenue`.
Initializes the revenue to 0 and still makes a check before sending out the token
## Proof of Concept
The function is meant to send the generated creator fees to the creators address
```solidity
tion withdrawCreatorRevenue(uint256 pairId, bool isQuoteToken) external onlyPoolOwner(pairId) {
        Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);

        uint256 amount = pool.accumulatedCreatorRevenue;

        require(amount > 0, "AZ");

        pool.accumulatedCreatorRevenue = 0;

```
It then makes a check again after initializing the pool accumulated to 0
```solidity
        if (amount > 0) {
            ERC20(pool.token).safeTransfer(msg.sender, amount);
        }
```

## Tools Used
Manual

## Recommended Mitigation Steps
To remove the require statement
```solidity
        if (amount > 0) {
            pool.accumulatedCreatorRevenue = 0
            ERC20(pool.token).safeTransfer(msg.sender, amount);
        }
```
