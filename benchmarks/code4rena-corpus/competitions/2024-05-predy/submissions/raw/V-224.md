# Vulnerability details

## Impact
`PerpMarketLib#validateLimitPrice` is designed to validate whether a given limit price is acceptable for a trade based on the trade amount and the current trade price. However, due to the logical bug, the function may return `true` (indicating that the limit price is valid) even when the trade amount is zero, which should be considered an invalid case.

```solidity
if (tradeAmount > 0 && limitPrice < tradePrice) {
    return false;
}

if (tradeAmount < 0 && limitPrice > tradePrice) {
    return false;
}
```
The issue is that the conditions for `tradeAmount > 0` and `tradeAmount < 0` are not mutually exclusive. When `tradeAmount` is equal to 0, both conditions will be false, and the function will return `true`, which is incorrect behavior.

The function should return false when `tradeAmount` is 0, as stated in the first condition:
```solidity
if (tradeAmount == 0) {
    return false;
}
```
Allowing trades with a zero trade amount can have several consequences.

**_`Violation of Contract Invariants`_** Executing trades with a zero trade amount may violate the invariants and assumptions of the contract, leading to unexpected behavior or inconsistent state.

## Proof of Concept
The logical bug can be illustrated by considering the following code snippet from the [validateLimitPrice#L127-L133](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketLib.sol#L127-L133)
```solidity
if (tradeAmount > 0 && limitPrice < tradePrice) {
    return false;
}

if (tradeAmount < 0 && limitPrice > tradePrice) {
    return false;
}
```
In this code, the two `if` statements check the conditions for positive and negative trade amounts, respectively. However, when `tradeAmount` is equal to zero, both conditions will be false, and the function will implicitly return true without any additional checks.

Consider the following example:
```solidity
uint256 tradePrice = 100;
int256 tradeAmount = 0;
uint256 limitPrice = 90;

bool isValid = validateLimitPrice(tradePrice, tradeAmount, limitPrice);
// isValid will be true, even though tradeAmount is 0
```
The `validateLimitPrice` function will return `true`, indicating that the limit price of 90 is valid for a trade with a zero trade amount and a trade price of 100. This behavior is incorrect, as trades with a zero trade amount should be considered invalid.

## Recommended Mitigation Steps
The conditions for `tradeAmount > 0` and `tradeAmount < 0` should be combined into a single `else` block
```solidity
function validateLimitPrice(uint256 tradePrice, int256 tradeAmount, uint256 limitPrice)
    internal
    pure
    returns (bool)
{
    if (tradeAmount == 0) {
        return false;
    } else if (tradeAmount > 0 && limitPrice < tradePrice) {
        return false;
    } else if (tradeAmount < 0 && limitPrice > tradePrice) {
        return false;
    }

    return true;
}
```
In this way, the function will correctly handle the case when `tradeAmount` is 0 and return `false`, and it will also handle the cases when `tradeAmount` is positive or negative, checking the limit price accordingly.
