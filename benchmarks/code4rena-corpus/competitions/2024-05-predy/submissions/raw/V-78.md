# Vulnerability details

## Impact
The `supply()` and `withdraw()` functions in `PredyPool` contract are used to supply to or withdraw either the `quoteToken` or the `baseToken` from the `lending pool` respectively. When `lenders` do supply tokens, they get minted `bond` tokens in return and during withdrawal, these `bond` tokens get burned. 

However, the logic behind this minting/burning is restricted by `onlyController` modifier which only gives the `controller` address access. As such, `lenders` will not be in a position to bypass this access barrier and therefore cannot supply or withdraw tokens.

## Proof of Concept 
[supply()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L222-L228) and [withdraw()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L237-L243)

```solidity
    function supply(uint256 pairId, bool isQuoteAsset, uint256 supplyAmount)
        external
        nonReentrant
        returns (uint256 finalSuppliedAmount)
    {
        return SupplyLogic.supply(globalData, pairId, supplyAmount, isQuoteAsset);
    }

    function withdraw(uint256 pairId, bool isQuoteAsset, uint256 withdrawAmount)
        external
        nonReentrant
        returns (uint256 finalBurnAmount, uint256 finalWithdrawAmount)
    {
        return SupplyLogic.withdraw(globalData, pairId, withdrawAmount, isQuoteAsset);
    }
```
These functions makes calls to [SupplyLogic.supply()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L37-L41) and [SupplyLogic.withdraw()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L70-L74)

```solidity
        if (_isStable) {
            mintAmount = receiveTokenAndMintBond(pair.quotePool, _amount);
        } else {
            mintAmount = receiveTokenAndMintBond(pair.basePool, _amount);
        }

        if (_isStable) {
            (finalburntAmount, finalWithdrawalAmount) = burnBondAndTransferToken(pair.quotePool, _amount);
        } else {
            (finalburntAmount, finalWithdrawalAmount) = burnBondAndTransferToken(pair.basePool, _amount);
        }
```
The [receiveTokenAndMintBond()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L54) and [burnBondAndTransferToken()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L88) perform calls to the `mint()` and `burn()` which actually does the minting/burning of `bond` tokens:

```solidity
        ISupplyToken(_pool.supplyTokenAddress).mint(msg.sender, mintAmount);

        ISupplyToken(supplyTokenAddress).burn(msg.sender, finalburntAmount);
```
The [mint() and burn()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/tokenization/SupplyToken.sol#L21-L27) are implemented as follows:

```solidity
    function mint(address account, uint256 amount) external virtual override onlyController {
        _mint(account, amount);
    }


    function burn(address account, uint256 amount) external virtual override onlyController {
        _burn(account, amount);
    }
```
As seen, these functions are restricted by `onlyController` modifier which only gives the `controller` address access.

```solidity
    modifier onlyController() {
        require(_controller == msg.sender, "ST0");
        _;
    }
```

The moment these transactions reach this level, they will always `revert` since the modifier will always check if the `msg.sender` is the `controller` address. But since the `supply()` & `withdraw()` are intended to be called by any `lender`, this check fails. 

Therefore, `lenders` will not be in a position to bypass this access barrier and therefore cannot supply or withdraw tokens.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Let the minting/burning be a separate operation. i.e Let supply and withdraw be performed indipendently, then the respective minting/burning of `bond` tokens be queued and executed by the `controller` as another operation on its own.
