# Vulnerability details

## Impact
Using another variable instead of msg.sender in the transferFrom function, an attacker can pretend to be someone else and transfer tokens in someone else's place.
Allow the attacker to spend other people's tokens.


## Proof of Concept
https://github.com/crytic/slither/wiki/Detector-Documentation#arbitrary-from-in-transferfrom

In the following code, the protocol doesn't use msg.sender in the transferFrom function.

1.

    ERC20(quoteToken).safeTransferFrom(settlementParams.sender, address(predyPool), uint256(-settlementParams.fee));

2.

    ERC20(quoteToken).safeTransferFrom(sender, address(predyPool), quoteAmount);

3.

    ERC20(quoteToken).safeTransferFrom(sender, address(this), quoteAmount - quoteAmountFromUni);

4.

    ERC20(baseToken).safeTransferFrom(sender, address(predyPool), buyAmount);

5.

    ERC20(quoteToken).safeTransferFrom(sender, address(this), quoteAmountToUni - quoteAmount);


## Tools Used
slither


## Recommended Mitigation Steps
Use msg.sender as from in transferFrom.
