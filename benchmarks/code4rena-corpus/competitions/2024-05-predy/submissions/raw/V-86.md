# Vulnerability details

## Impact
Each time a user interacts with the contract the following two functions comes to play:
1. [applyInterestForToken()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/ApplyInterestLib.sol#L26-L48): Here, interest and premium from the previous interaction to the current one are applied.
2. [updateRebalanceInterestGrowth()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Perp.sol#L158-L174): This settles the interest on rebalance positions up to this block and update the rebalance fee growth value.

Both of these are invoked within functions such as `liquidate()`, `reallocate()` and  `trade()`.

However, in `supply()` and `withdraw()`, only `applyInterestForToken()` is called to update `interest growth` whereas `updateRebalanceInterestGrowth()` is not. 

As such, `rebalance interest growth` is never updated during these operations.

## Proof of Concept
In [liquidate()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/LiquidationLogic.sol#L49-L53), [reallocate()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/ReallocationLogic.sol#L34-L40) and [trade()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/TradeLogic.sol#L36-L40), both two functions are invoked:
```solidity
        // update interest growth
        ApplyInterestLib.applyInterestForToken(globalData.pairs, vault.openPosition.pairId);


        // update rebalance interest growth
        Perp.updateRebalanceInterestGrowth(pairStatus, pairStatus.sqrtAssetStatus);
```
These ensure that both `interest growth` and `rebalance interest growth` are updated up to the current block.

However, in `supply()` and `withdraw()`, only `applyInterestForToken()` is invoked.
[supply()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L32-L33)
```solidity
        // Updates interest rate related to the pair
        ApplyInterestLib.applyInterestForToken(globalData.pairs, _pairId);
```

[withdraw()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/logic/SupplyLogic.sol#L65-L66)
```solidity
        // Updates interest rate related to the pair
        ApplyInterestLib.applyInterestForToken(globalData.pairs, _pairId);
```
As seen above, `rebalance interest growth` is never updated during these operations. This means that any interests on rebalance positions are never settled  and fees never updated. 

Subsequent operations that follow any supply or withdrawal are then done with outdated interest and fee updates as these were omitted prior. 

## Tools Used
Manual Review

## Recommended Mitigation Steps
Modify the `supply()` and `withdraw()` functions to update both interest growth and rebalance interest growth.
```diff
        // update interest growth
        ApplyInterestLib.applyInterestForToken(globalData.pairs, _pairId);

+       // update rebalance interest growth
+       Perp.updateRebalanceInterestGrowth(pairStatus, pairStatus.sqrtAssetStatus);
```
