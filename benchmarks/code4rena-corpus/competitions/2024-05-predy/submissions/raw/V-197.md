# Vulnerability details

## Impact
In the `SettlementCallbackLib.buy`, the handling of the `quoteAmount` calculation and the subsequent token transfers: [SettlementCallbackLib.buy#L169-180](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/base/SettlementCallbackLib.sol#L169-L181)
```solidity
if (price == 0) {
    ERC20(quoteToken).safeTransfer(address(predyPool), settlementParams.maxQuoteAmount - quoteAmountToUni);
} else {
    uint256 quoteAmount = buyAmount * price / Constants.Q96;

    if (quoteAmount > quoteAmountToUni) {
        ERC20(quoteToken).safeTransfer(sender, quoteAmount - quoteAmountToUni);
    } else if (quoteAmountToUni > quoteAmount) {
        ERC20(quoteToken).safeTransferFrom(sender, address(this), quoteAmountToUni - quoteAmount);
    }

    ERC20(quoteToken).safeTransfer(address(predyPool), settlementParams.maxQuoteAmount - quoteAmount);
}
```
In the case where `price` is not zero, and `quoteAmountToUni` is greater than `quoteAmount`. In this scenario, the code attempts to transfer `quoteAmountToUni - quoteAmount` tokens from the `sender` to the contract (`address(this)`), the contract may not have the necessary approval or allowance from the `sender` to perform this transfer.

In this scenario, the code attempts to transfer the difference (`quoteAmountToUni - quoteAmount`) from the sender to the contract (`address(this)`) using the `ERC20.safeTransferFrom`.

This transfer can only succeed if the contract has been granted the necessary approval or allowance from the `sender` to transfer the specified amount of tokens. If the contract does not have the required approval or allowance, the `safeTransferFrom` call will fail, and the transaction will revert.

**`This can lead to several undesirable consequences such as`**

**`Unexpected Reverts`** If the contract does not have the required approval or allowance, the transaction will revert unexpectedly, causing inconvenience to users and potentially leading to lost gas fees.

**`Potential Loss of Funds`** If the `sender` has granted the contract an unlimited approval or allowance (which is a common practice for user convenience), the contract could potentially transfer more tokens than intended from the sender to itself. This could result in a loss of funds for the sender.

## Recommended Mitigation Steps
Ensure that the contract has the necessary approval or allowance from the `sender` before attempting the `safeTransferFrom` operation, or
Revert the transaction if `quoteAmountToUni` is greater than `quoteAmount`, as this scenario may indicate an unexpected or invalid state.

Additionally, it's worth noting that the quoteAmount calculation (`buyAmount * price / Constants.Q96)` could potentially overflow or underflow, depending on the values of `buyAmount`and `price`. You should consider using SafeMath or other overflow/underflow prevention techniques to mitigate this risk.
