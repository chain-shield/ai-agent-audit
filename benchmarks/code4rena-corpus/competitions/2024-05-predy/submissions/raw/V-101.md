# Vulnerability details

## Impact
`lastRebalanceTotalSquartAmount` is a crucial variable that represents the total amount of positions that will have to pay rebalancing interest in the future. If this value is incorrectly updated, it can lead to inaccurate calculations of rebalancing interest for subsequent users, potentially resulting in either overpayment or underpayment of interest.

In line: [settleRebalanceInterest#L148](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PerpFee.sol#L148)
```solidity
assetStatus.lastRebalanceTotalSquartAmount -= rebalanceAmount;
```
This is intended to update the `lastRebalanceTotalSquartAmount` by subtracting the `rebalanceAmount` from it. Though this operation is performed unconditionally, even when `rebalanceInterestBase` and `rebalanceInterestQuote` are both zero (i.e., when `userStatus.sqrtPerp.amount == 0` or `userStatus.lastNumRebalance == assetStatus.numRebalance`).

In such cases, there is no need to update `lastRebalanceTotalSquartAmount` because no rebalance interest is being settled. Subtracting a non-zero `rebalanceAmount` from `lastRebalanceTotalSquartAmount` in these cases could lead to an incorrect value.

## Proof of Concept
Let's consider a scenario where `userStatus.sqrtPerp.amount` is zero, but `rebalanceAmount` is non-zero (e.g., due to a previous position that was closed). In this case, `rebalanceInterestBase` and `rebalanceInterestQuote` will both be zero, as there is no open position to accrue interest.

On the other hand, the line `assetStatus.lastRebalanceTotalSquartAmount -= rebalanceAmount;` will still execute, subtracting the non-zero `rebalanceAmount` from `lastRebalanceTotalSquartAmount`. This means that the `lastRebalanceTotalSquartAmount` will be incorrectly decreased, even though no rebalance interest was actually settled.

Illustration of the concept:

Suppose the initial values are:

`userStatus.sqrtPerp.amount = 0`
`rebalanceAmount = 100`
`assetStatus.lastRebalanceTotalSquartAmount = 1000`

After executing [settleRebalanceInterest](https://github.com/code-423n4/2024-05-predy/blob/e96f378007e3dc56b184079f0c0e4fe48a72efaa/src/libraries/PerpFee.sol#L136-L154), the values will be:

`rebalanceInterestBase = 0`
`rebalanceInterestQuote = 0`
`assetStatus.lastRebalanceTotalSquartAmount = 900` (incorrectly decreased)

In this case, `lastRebalanceTotalSquartAmount` should have remained at 1000, as no rebalance interest was actually settled. However, due to the unconditional subtraction, it was incorrectly decreased to 900.

This incorrect accounting of `lastRebalanceTotalSquartAmount` can propagate and lead to further inaccuracies in the calculation of rebalancing interest for subsequent users.

Manual Review

## Recommended Mitigation Steps
Wrap the line `assetStatus.lastRebalanceTotalSquartAmount -= rebalanceAmount;` within an additional condition that checks if `rebalanceInterestBase` or `rebalanceInterestQuote` is non-zero. This way, the subtraction will only occur when there is an actual rebalance interest to settle.
```solidity
if (rebalanceInterestBase != 0 || rebalanceInterestQuote != 0) {
    assetStatus.lastRebalanceTotalSquartAmount -= rebalanceAmount;
}
```
