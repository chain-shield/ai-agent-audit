# Vulnerability details

## Impact
` computeRequiredAmounts` calls `saveLastFeeGrowth(_sqrtAssetStatus)` when the total amount and borrowed amount are equal, and a new position is being opened (i.e., `_tradeSqrtAmount > 0`). This condition is intended to update the last fee growth when the first liquidity is added to the pool.

Although, there is a potential edge case where this condition could be triggered unexpectedly. If the total amount and borrowed amount are equal, and a position is being decreased (i.e., `_tradeSqrtAmount < 0`), the `saveLastFeeGrowth` function will not be called. This could lead to inconsistent fee growth tracking if the pool goes from having no liquidity to having liquidity again.

## Proof of Concept
`computeRequiredAmounts` function, Specifically, the code block: [#L443-L449](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L443-L449)
```solidity
if (_tradeSqrtAmount > 0) {
    (requiredAmount0, requiredAmount1) = increase(_sqrtAssetStatus, uint256(_tradeSqrtAmount));

    if (_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount) {
        // if available liquidity was 0 and added first liquidity then update last fee growth
        saveLastFeeGrowth(_sqrtAssetStatus);
    }
}
```
The intention here is to update the last fee growth when the first liquidity is added to the pool, which is when `_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount` and a new position is being opened (`_tradeSqrtAmount > 0`).

The issue is that if a position is being decreased (`_tradeSqrtAmount < 0`) and the condition `_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount` is true, the [saveLastFeeGrowth function](https://github.com/code-423n4/2024-05-predy/blob/2fb1e0ec7a52fc06c2e9c8e561bccba84302e4bb/src/libraries/Perp.sol#L414-L420) will not be called. This could lead to inconsistent fee growth tracking if the pool goes from having no liquidity to having liquidity again.

The impact is that the fee growth tracking for the Uniswap V3 pool could become inconsistent and incorrect, leading to potential financial losses for liquidity providers and users of the protocol. Incorrect fee growth tracking could result in incorrect calculation of fees, rewards, and payouts for liquidity providers and traders.

**Concept Illustration:**

Initially, the pool has no liquidity, so `_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount == 0`.
A new position is opened, increasing the total amount, and the `saveLastFeeGrowth` function is correctly called.
Later, the position is partially decreased, such that `_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount` again, but this time with a non-zero value.
In this case, the `saveLastFeeGrowth` function will not be called, even though the pool is transitioning from having no liquidity to having liquidity again.

## Recommended Mitigation Steps
Adding a check to ensure that `saveLastFeeGrowth` is called whenever the pool transitions from having no liquidity to having liquidity, regardless of whether the position increases or decreases.
```solidity
if (_tradeSqrtAmount > 0) {
    (requiredAmount0, requiredAmount1) = increase(_sqrtAssetStatus, uint256(_tradeSqrtAmount));

    if (_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount) {
        // if available liquidity was 0 and added first liquidity then update last fee growth
        saveLastFeeGrowth(_sqrtAssetStatus);
    }
} else if (_tradeSqrtAmount < 0) {
    (requiredAmount0, requiredAmount1) = decrease(_sqrtAssetStatus, uint256(-_tradeSqrtAmount));

    if (_sqrtAssetStatus.totalAmount == _sqrtAssetStatus.borrowedAmount + uint256(-_tradeSqrtAmount)) {
        // if available liquidity was 0 and added first liquidity then update last fee growth
        saveLastFeeGrowth(_sqrtAssetStatus);
    }
}
```
By adding the check for the `_tradeSqrtAmount < 0` case, we ensure that the last fee growth is updated consistently whenever the pool transitions from having no liquidity to having liquidity, regardless of whether the position is being increased or decreased.
