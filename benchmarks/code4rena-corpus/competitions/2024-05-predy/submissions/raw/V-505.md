# Vulnerability details

## Impact

`callUniswapObserve()`is used to get TWAP price tick using uniswap oracle. if `int24(tickCumulatives[1] - tickCumulatives[0])` is negative and `((tickCumulatives[1] - tickCumulatives[0]) % secondsAgo != 0,` the value returned will be higher than it should be, which affects the protocol from getting accurate prices and opens possibility for some price manipulations and arbitrage opportunities.

## Proof of Concept

https://vscode.dev/github/code-423n4/2024-05-predy/blob/main/src/libraries/UniHelper.sol#L35-L75

`callUniswapObserve()` is used to get TWAP price tick using uniswap oracle. Hence, an attacker can manipulate the market to ensure that the tick price becomes negative, which will result in an incorrect price calculation because `callUniswapObserve()` does not round up for negative value.
The tick should be rounded down as it's done in the [uniswap library](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L36)

## Recommended Mitigation Steps

Consider handling rounding for negative tick values.

`if (tickCumulativesDelta < 0 && (tickCumulativesDelta % secondsAgo != 0)) arithmeticMeanTick--;`
