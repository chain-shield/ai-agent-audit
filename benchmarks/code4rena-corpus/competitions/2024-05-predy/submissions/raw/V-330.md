# Vulnerability details

## Impact
In `IPyth.sol`, the following [comment](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/vendors/IPyth.sol#L22) is provided on `getPriceNoOlderThan()`:
```solidity
/// @return price - please read the documentation of PythStructs.Price to understand how to use this safely.
```
Now, according to [Ipyth Documentation](https://docs.fringe.fi/v2-smart-contract-documentation/readme/priceoracle/priceproviders/pythpriceprovider):
> `setValidTimePeriod()`: Sets validTimePeriod used to check if price is older than  validTimePeriod  to perform price update. Only the moderator can call this function.

However in `PriceFeed.sol`, the `VALID_TIME_PERIOD` constant is hardcoded to `5 minutes`. While this may be suitable for some use cases, it lacks `flexibility` and adaptability for different scenarios or changing requirements.

Different use cases may require different `validity periods` for price data.
---> The hardcoded value may not be optimal for all scenarios, potentially leading to less accurate or outdated price data. 


## Proof of Concept
The [VALID_TIME_PERIOD](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PriceFeed.sol#L35) constant is hardcoded to `5 minutes`.
```solidity
uint256 private constant VALID_TIME_PERIOD = 5 * 60;
```
This `VALID_TIME_PERIOD` is used in the [getSqrtPrice()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PriceFeed.sol#L48) function to ensure that the price data retrieved from the `IPyth` contract is not older than the specified validity period.
```solidity
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        (, int256 quoteAnswer,,,) = AggregatorV3Interface(_quotePriceFeed).latestRoundData();

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, VALID_TIME_PERIOD); // @audit-issue used here

        //...
    }
```
- If the `VALID_TIME_PERIOD` is too long, the price data may be outdated.
---> This can lead to inaccurate price calculations, affecting the reliability of the protocol.

- If the `VALID_TIME_PERIOD` is too short, the contract may frequently fail to find price data within the validity period.
---> This can result in frequent reverts of the `getSqrtPrice()`

## Recommended Mitigation Steps
Make the hardcoded `VALID_TIME_PERIOD` configurable.

```solidity
// @audit Replace the hardcoded constant with a state variable that can be updated.
uint256 private _validTimePeriod;

// @audit Initialize the _validTimePeriod in the constructor.
constructor(address quotePrice, address pyth, bytes32 priceId, uint256 decimalsDiff, uint256 validTimePeriod) {
    //...
    _validTimePeriod = validTimePeriod;
}


// @audit Add a function to update the _validTimePeriod. This function should be restricted to authorized users
function setValidTimePeriod(uint256 validTimePeriod) external onlyOwner {
    _validTimePeriod = validTimePeriod;
}

// @audit Replace the hardcoded VALID_TIME_PERIOD with the state variable _validTimePeriod.
function getSqrtPrice() external view returns (uint256 sqrtPrice) {
        //...

        IPyth.Price memory basePrice = IPyth(_pyth).getPriceNoOlderThan(_priceId, _validTimePeriod); // @audit Updated here

        //...
}

```
