# Vulnerability details

## Impact
Malicious Users can DOS the  `predyPool` and not to work again forever.
This is due to how the protocol handles the creation of a new vault, which is Permissionless.


```js

    /**
     * @notice Creates a new vault
     * @param pairId The id of pair to create vault
     */
    function createVault(uint256 pairId) external returns (uint256) {
        globalData.validate(pairId);

        return globalData.createOrGetVault(0, pairId);
    }
```


The contracts will be deployed on L2s like `Base` and/Or `Arbitrum`, gas fess on this chains are relatively very small, This would allow the malicious user to create until the `globalData.vaultCount++` is no more able to accept any, in this case any further call to the [createVault](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/PredyPool.sol#L337) function will result in it reverting

## Proof of Concept
```js

    function createOrGetVault(GlobalDataLibrary.GlobalData storage globalData, uint256 vaultId, uint256 pairId)
        internal
        returns (uint256)
    {
        address quoteToken = globalData.pairs[pairId].quoteToken;

        if (vaultId == 0) {
            uint256 finalVaultId = globalData.vaultCount;

            // Initialize a new vault
            DataType.Vault storage vault = globalData.vaults[finalVaultId];

            vault.id = finalVaultId;
            vault.owner = msg.sender;
            vault.recipient = msg.sender;
            vault.openPosition.pairId = pairId;
            vault.quoteToken = quoteToken;

            globalData.vaultCount++;

            emit VaultCreated(vault.id, vault.owner, quoteToken, pairId);

            return vault.id;
```

## Recommended Mitigation Steps

Add some sort of an access control to the function or make it internal and only call it when there's an interaction that requires lot of money like trade or something, this will make it harder for the malicious entities to DOS the pool.
