# Vulnerability details

## Description
The withdrawProtocolRevenue function in the PredyPool contract does not validate whether the provided pairId exists in the globalData.pairs mapping. This omission can lead to potential issues if an invalid pairId is passed.
```
function withdrawProtocolRevenue(uint256 pairId, bool isQuoteToken) external onlyOperator {
    Perp.AssetPoolStatus storage pool = _getAssetStatusPool(pairId, isQuoteToken);

    uint256 amount = pool.accumulatedProtocolRevenue;

    require(amount > 0, "AZ");

    pool.accumulatedProtocolRevenue = 0;

    if (amount > 0) {
        ERC20(pool.token).safeTransfer(msg.sender, amount);
    }

    emit ProtocolRevenueWithdrawn(pairId, isQuoteToken, amount);
}
```

## Impact
1.  If an invalid pairId is provided, the function might access an uninitialized or non-existent AssetPoolStatus, leading to incorrect or unintended behavior
2. Without validation, the function might inadvertently reset or transfer funds from an incorrect or non-existent pool, causing state corruption.
3.  Invalid pairId values could lead to the loss of funds by transferring from an unintended pool or resetting the accumulated revenue incorrectly

## Proof of Concept
1. Scenario:
- An operator mistakenly or maliciously calls withdrawProtocolRevenue with an invalid pairId.

2. Steps:
- The function accesses the globalData.pairs mapping with the invalid pairId.
- Since the pairId does not exist, it might access an uninitialized or default AssetPoolStatus.
- The function then resets accumulatedProtocolRevenue to 0 and attempts to transfer funds, potentially leading to unintended behavior or loss of funds.

Impact:
- Funds might be transferred from an unintended pool.
- The state of the accumulatedProtocolRevenue might be incorrectly reset, causing financial discrepancies.
