# Vulnerability details

## Impact

The `swapExactIn` and `swapExactOut` functions in the `UniswapSettlement.sol` contract use the `approve` method to set allowances for token transfers. However, some non-standard tokens, such as USDT, revert if `approve` is called when the current allowance is non-zero and also it does not return a boolean value upon approval. Since the protocol states that USDT will be used, this behavior can lead to failed transactions, blocking further operations and causing potential disruptions in the protocol's functionality.

## Proof of Concept

In the `UniswapSettlement.sol` contract, the `swapExactIn` and `swapExactOut` functions include the following code:

```solidity
function swapExactIn(
  address,
  address baseToken,
  bytes memory data,
  uint256 amountIn,
  uint256 amountOutMinimum,
  address recipient
) external override returns (uint256 amountOut) {
  ERC20(baseToken).safeTransferFrom(msg.sender, address(this), amountIn);
  ERC20(baseToken).approve(address(_swapRouter), amountIn); // @audit <--- should use safeApprove for tokens like usdt

  amountOut = _swapRouter.exactInput(
    ISwapRouter.ExactInputParams(
      data,
      recipient,
      block.timestamp,
      amountIn,
      amountOutMinimum
    )
  );
}

function swapExactOut(
  address quoteToken,
  address,
  bytes memory data,
  uint256 amountOut,
  uint256 amountInMaximum,
  address recipient
) external override returns (uint256 amountIn) {
  ERC20(quoteToken).safeTransferFrom(
    msg.sender,
    address(this),
    amountInMaximum
  );
  ERC20(quoteToken).approve(address(_swapRouter), amountInMaximum); // @audit <--- should use safeApprove for tokens like usdt

  amountIn = _swapRouter.exactOutput(
    ISwapRouter.ExactOutputParams(
      data,
      recipient,
      block.timestamp,
      amountOut,
      amountInMaximum
    )
  );

  if (amountInMaximum > amountIn) {
    ERC20(quoteToken).safeTransfer(msg.sender, amountInMaximum - amountIn);
  }
}
```

### Example of Issue

USDT (Tether) is known to revert the transaction if `approve` is called with a non-zero allowance and USDT (Tether) does not return a boolean value. If the `approve` method is called without resetting the allowance to zero first, the transaction will fail, blocking any subsequent token transfers.

## Recommended Mitigation Steps

To handle non-standard tokens like USDT correctly, use safeApprove from the Solmate library, which accommodates tokens with non-standard behavior. Here’s how to refactor the functions:

```solidity
function swapExactIn(
  address,
  address baseToken,
  bytes memory data,
  uint256 amountIn,
  uint256 amountOutMinimum,
  address recipient
) external override returns (uint256 amountOut) {
  ERC20(baseToken).safeTransferFrom(msg.sender, address(this), amountIn);

  // Use safeApprove for USDT compatibility
  SafeERC20.safeApprove(ERC20(baseToken), address(_swapRouter), amountIn);

  amountOut = _swapRouter.exactInput(
    ISwapRouter.ExactInputParams(
      data,
      recipient,
      block.timestamp,
      amountIn,
      amountOutMinimum
    )
  );
}

function swapExactOut(
  address quoteToken,
  address,
  bytes memory data,
  uint256 amountOut,
  uint256 amountInMaximum,
  address recipient
) external override returns (uint256 amountIn) {
  ERC20(quoteToken).safeTransferFrom(
    msg.sender,
    address(this),
    amountInMaximum
  );

  // Use safeApprove for USDT compatibility
  SafeERC20.safeApprove(
    ERC20(quoteToken),
    address(_swapRouter),
    amountInMaximum
  );

  amountIn = _swapRouter.exactOutput(
    ISwapRouter.ExactOutputParams(
      data,
      recipient,
      block.timestamp,
      amountOut,
      amountInMaximum
    )
  );

  if (amountInMaximum > amountIn) {
    ERC20(quoteToken).safeTransfer(msg.sender, amountInMaximum - amountIn);
  }
}
```

Using safeApprove ensures compatibility with non-standard tokens like USDT, preventing unexpected reverts and ensuring smooth operation of the protocol.
