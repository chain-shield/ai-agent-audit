# Vulnerability details

## Impact
In `Trade.sol`, the function `trade()` uses `UniswapV3.slot0` to get the value of `sqrtPrice`, which is used to perform the swap. However, the `sqrtPrice` is pulled from `UniswapV3.slot0`, which is the most recent data point and can be manipulated easily via MEV bots and flash loans with sandwich attacks, which can cause the loss of funds.

## Proof of Concept
You can see the [trade()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Trade.sol#L49-L60) function in `Trade.sol` here:
```solidity
   tradeResult.sqrtPrice = getSqrtPrice(pairStatus.sqrtAssetStatus.uniswapPool, pairStatus.isQuoteZero);

        // swap tokens

        SwapStableResult memory swapResult = swap(
```

https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Trade.sol#L49-L60

The function [getSqrtPrice()](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/libraries/Trade.sol#L112-L114) returns the uint256 converted `sqrtPriceX96` pulled from `UniswapV3.slot0`, which is used for `tradeResult.sqrtPrice`. An attacker can manipulate the `sqrtPrice`, and if the `sqrtPrice` is used to swap tokens, the tokens will be bought at a higher price. The attacker can then run a transaction to sell, thereby earning gains but causing a loss of funds to whoever called those functions.
