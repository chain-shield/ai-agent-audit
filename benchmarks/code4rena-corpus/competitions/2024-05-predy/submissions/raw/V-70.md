# Vulnerability details

## Impact
The way `_getOrInitPosition` handles `positionId` parameter, the function allows creating a new position with an arbitrary `positionId` in a way that could lead to a collision with an existing position, resulting in unexpected behavior or data corruption.

Suppose there is an existing position with `positionId = 1` owned by trader1. An attacker can call `_getOrInitPosition` with `isCreatedNew = true`, `trader = attacker, pairId = someValidPairId, and positionId = 1`. The function will create a new position with `positionId = 1` for the attacker, overwriting the existing position owned by `trader1`. This can lead to data corruption and unexpected behavior, as the attacker's position will now be associated with trader1's position data.

## Proof of Concept
[src/markets/gamma/GammaTradeMarket.sol#_getOrInitPosition](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/gamma/GammaTradeMarket.sol#L408-L434)

When `isCreatedNew` is `true`, the function creates a new `UserPosition` struct and assigns the provided `positionId`, trader, and `pairId` without any checks for uniqueness or collision with existing positions.

## Recommended Mitigation Steps
The function should ensure that the `positionId` is unique for each new position. Use a counter or a mapping to keep track of the next available `positionId` and assign it to the new position. Alternatively, the function could be modified to accept a `positionId` parameter only when `isCreatedNew` is `false` (i.e., when retrieving an existing position). For creating new positions, the function could generate a new unique `positionId` internally.
