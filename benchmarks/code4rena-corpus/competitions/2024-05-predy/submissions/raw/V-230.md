# Vulnerability details

## Impact
In the Permit2 protocol, the `permitWitnessTransferFrom` is used to verify the signature of a "witness" who has signed a permit authorizing the transfer of tokens. _It expects the following arguments:_

`permit`: The PermitTransferFrom struct containing the details of the permitted transfer, including the token address, amount, nonce, and deadline.
`transferDetails`: The SignatureTransferDetails struct containing the recipient address and the requested amount to be transferred.
`from`: The address of the "witness" who signed the permit.
`witness`: The hash of the witness data used to generate the signature.
`witnessTypehash`: The typehash of the witness data structure.
`sig`: The signature of the witness.

The `_verifyOrder function` in `PerpMarketV1.sol` is responsible for verifying the order and permitting the transfer of tokens. However, it incorrectly passes `order.info.trader` as the third argument (`from`) to the `permitWitnessTransferFrom` function, which is expected to be the address of the witness who signed the permit.

Code: [PerpMarketV1#_verifyOrder](https://github.com/code-423n4/2024-05-predy/blob/a9246db5f874a91fb71c296aac6a66902289306a/src/markets/perp/PerpMarketV1.sol#L314-L325)
```solidity
function _verifyOrder(ResolvedOrder memory order, uint256 amount) internal {
    order.validate();

    _permit2.permitWitnessTransferFrom(
        order.toPermit(),
        ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: amount}),
        order.info.trader, // Incorrect argument, should be the witness address
        order.hash,
        PerpOrderLib.PERMIT2_ORDER_TYPE,
        order.sig
    );
}
```
**The impact is twofold:**

**`Signature Verification Failure`** If the trader's address is different from the witness address, the signature verification performed by `permitWitnessTransferFrom` will fail, causing legitimate orders to be rejected.

**`Unauthorized Transfers`** In the case where the trader's address happens to be the same as the witness address (_which is unlikely but possible_), the signature verification will succeed, but the transfer will be authorized by the trader's signature instead of the witness's signature. This could allow unauthorized transfers if the trader's signature is compromised or if the trader is malicious.

## Proof of Concept
Suppose Alice is the trader who wants to place an order, and Bob is the witness who signs the permit authorizing the transfer of tokens. The `ResolvedOrder` struct should contain the following information:
```solidity
ResolvedOrder memory order = ResolvedOrder({
    info: OrderInfo({
        market: address(perpMarket),
        trader: address(Alice), // Trader's address
        nonce: 0,
        deadline: block.timestamp + 1 hours
    }),
    token: address(token),
    amount: 1000 ether,
    sig: signature, // Signature signed by Bob (the witness)
    hash: keccak256(abi.encode(witness_data)) // Hash of the witness data
});
```
When `_verifyOrder` is called with this order, it should pass `address(Bob)` as the third argument (`from`) to `permitWitnessTransferFrom`. However, it incorrectly passes `address(Alice)` (the trader's address) instead.

If `address(Alice)` is different from `address(Bob)`, the signature verification will fail, and the legitimate order will be rejected. If `address(Alice)` happens to be the same as `address(Bob)`, the signature verification will succeed, but the transfer will be authorized by Alice's signature instead of Bob's signature, potentially allowing unauthorized transfers.

## Recommended Mitigation Steps
Assuming that the `ResolvedOrder` struct contains a witness field that stores the address of the witness who signed the permit, this change should fix and ensure that the correct witness address is used for signature verification.
```solidity
function _verifyOrder(ResolvedOrder memory order, uint256 amount) internal {
    order.validate();

    _permit2.permitWitnessTransferFrom(
        order.toPermit(),
        ISignatureTransfer.SignatureTransferDetails({to: address(this), requestedAmount: amount}),
        order.info.witness, // Use the witness address instead of the trader address
        order.hash,
        PerpOrderLib.PERMIT2_ORDER_TYPE,
        order.sig
    );
}
```
