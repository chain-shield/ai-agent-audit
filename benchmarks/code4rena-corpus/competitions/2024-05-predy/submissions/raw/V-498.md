# Vulnerability details

## Impact
The protocol mentions in the `ApplyInterestLib.sol` docs that `"Each time a user interacts with the contract, interest and premium from the previous interaction to the current one are applied."`. This refers to each time users liquidate, supply, withdraw, reallocate, etc.

The `interest rate` that is calculated gives rewards to the protocol and designated creator role, which is taken from the `predy pool`.

In certain cases, the function to update the `pool status` (which includes protocol and creator rewards) does not actually update these values.

Despite no update occuring, the `last updated timestamp` is still set to the current `block.timestamp`.

This will give the protocol and creator less rewards the next time the interest rate is updated.

## Proof of Concept
[ApplyInterestLib.sol#L22-L48](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L22-L48)
```javascript
    /**
     * @notice Each time a user interacts with the contract, interest and premium from the previous interaction to the current one are applied.
     * This increases the amount available for withdrawal by the lender and the premium income for Squart.
    */
    function applyInterestForToken(mapping(uint256 => DataType.PairStatus) storage pairs, uint256 pairId) internal {
        DataType.PairStatus storage pairStatus = pairs[pairId];

        Perp.updateFeeAndPremiumGrowth(pairId, pairStatus.sqrtAssetStatus);

        // avoid applying interest rate multiple times in the same block
        if (pairStatus.lastUpdateTimestamp >= block.timestamp) {
            return;
        }

@>      (uint256 interestRateQuote, uint256 protocolFeeQuote) =
            applyInterestForPoolStatus(pairStatus.quotePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

@>      (uint256 interestRateBase, uint256 protocolFeeBase) =
            applyInterestForPoolStatus(pairStatus.basePool, pairStatus.lastUpdateTimestamp, pairStatus.feeRatio);

        // Update last update timestamp
@>      pairStatus.lastUpdateTimestamp = block.timestamp;

        if (interestRateQuote > 0 || interestRateBase > 0) {
            emitInterestGrowthEvent(pairStatus, interestRateQuote, interestRateBase, protocolFeeQuote, protocolFeeBase);
        }
    }
```

After the calls to `applyInterestForPoolStatus`, the `pairStatus.lastUpdateTimestamp` is updated to the current `block.timestamp`.

`ApplyInterestLib::applyInterestForPoolStatus` [#L50-L73](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L50-L73)
```javascript
    function applyInterestForPoolStatus(Perp.AssetPoolStatus storage poolStatus, uint256 lastUpdateTimestamp, uint8 fee)
        internal
        returns (uint256 interestRate, uint256 totalProtocolFee)
    {
@>      if (block.timestamp <= lastUpdateTimestamp) {
            return (0, 0);
        }

        uint256 utilizationRatio = poolStatus.tokenStatus.getUtilizationRatio();

        // Skip calculating interest if utilization ratio is 0
@>      if (utilizationRatio == 0) {
            return (0, 0);
        }

        // Calculates interest rate
@>      interestRate = InterestRateModel.calculateInterestRate(poolStatus.irmParams, utilizationRatio)
            * (block.timestamp - lastUpdateTimestamp) / 365 days;

        totalProtocolFee = poolStatus.tokenStatus.updateScaler(interestRate, fee);

        poolStatus.accumulatedProtocolRevenue += totalProtocolFee / 2;
        poolStatus.accumulatedCreatorRevenue += totalProtocolFee / 2;
    }
```

When the `interestRate` is calculated it is multiplied by the last time rewards were updated  `* (block.timestamp - lastUpdateTimestamp) / 365 days;`.

This value is then used to calculate the `totalProtocolFee`, which is distributed to the `protocol` and `creator`.

However, we can see that there are cases in which the `interestRate` is not calculated and rewards are not updated:

1. `if (block.timestamp <= lastUpdateTimestamp)`
2. `if (utilizationRatio == 0)`

In these cases, the function call returns and there is no interest rate calculation and no update to the protocol rewards.

However, when the function call returns, the `lastUpdateTimestamp` is updated:

[ApplyInterestLib.sol#L43](https://github.com/code-423n4/2024-05-predy/blob/main/src/libraries/ApplyInterestLib.sol#L43)
```javascript
pairStatus.lastUpdateTimestamp = block.timestamp;
```

Despite no update to the rewards and all other values that are affected by the interest rate, the last reward timestamp is still updated. This means that the `interestRate` calculation will be much lower the next time it is updated.

The protocol will lose rewards in this case.

## Recommended Mitigation Steps
Do not update the `lastUpdateTimestamp` if there is no update to the protocol fee and interest rate
