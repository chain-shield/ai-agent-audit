## Brief Summary

The order of operations when updating the `_locked` variable for the reentrancy guard. Currently, the function sets `_locked = 2` at the beginning and then sets `_locked = 1` at the end of the function. However, if an exception occurs after `_locked` is set to 2 but before it is set back to 1, the contract will be left in a state where `_locked` is permanently set to 2, effectively disabling the `redeem` function for future calls.
