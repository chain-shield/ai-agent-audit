# Vulnerability details

## Impact

Refunded tokens will not be accepted by L1, will be lost in contract.

## Proof of Concept

When calling `WormholeTargetDispenserL2._sendMessage()` to send a message from L2 to L1, the refund account is set to `msg.sender if it is set at address(0).

```
  function _sendMessage(uint256 amount, bytes memory bridgePayload) internal override {
        // Check for the bridge payload length
        if (bridgePayload.length != BRIDGE_PAYLOAD_LENGTH) {
            revert IncorrectDataLength(BRIDGE_PAYLOAD_LENGTH, bridgePayload.length);
        }

        // Extract refundAccount and gasLimitMessage from bridgePayload
        (address refundAccount, uint256 gasLimitMessage) = abi.decode(bridgePayload, (address, uint256));
        // If refundAccount is zero, default to msg.sender
        if (refundAccount == address(0)) {
            refundAccount = msg.sender;
        }
```

`msg.sender` means the `DefaultTargetDispenserL2()` is the msg.sender, and in L1, the refund address will be the Dispenser contract in L1. 

However, the dispenser contract has no way of receiving the native tokens and withdrawing them.

Looking at the L1 -> L2 transfer, if there is a refund, the owner can call `drain()` in the DefaultTargetDispenserL2.sol to retrieve refunds
