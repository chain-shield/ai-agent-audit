# Vulnerability details

## Impact
In the  constructors of `WormholeDepositProcessorL1.sol` and `DepositProcessorL1.sol`, there is no explicit check for `l2TargetChainId` exceeding type(uint16).max. This could potentially lead to unexpected behavior if `l2TargetChainId` exceeds this value, as the cast to uint16 would truncate the higher bits of the uint256 value, leading to an incorrect chain ID being used in the message sent to L2.

At the same time, the `wormholeTargetChainId` before casting is subjected to the necessary checks.

## Proof of Concept
       
```
       if (_wormholeTargetChainId > type(uint16).max) {
            revert Overflow(_wormholeTargetChainId, type(uint16).max);
        }
```
```
sequence = sendTokenWithPayloadToEvm(uint16(wormholeTargetChainId), l2TargetDispenser, data, 0,
            gasLimitMessage, olas, transferAmount, uint16(l2TargetChainId), refundAccount);
```
## Tools Used
Manual

## Recommended Mitigation Steps

To mitigate this risk, it would be prudent to add a similar overflow check for `l2TargetChainId` as is done for `_wormholeTargetChainId` in the constructor. Here is how you could implement such a check:
```
if (l2TargetChainId > type(uint16).max) {
    revert Overflow(l2TargetChainId, type(uint16).max);
}
```
