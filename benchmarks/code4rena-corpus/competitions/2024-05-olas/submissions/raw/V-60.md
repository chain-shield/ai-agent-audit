# Vulnerability details

## Impact
The `for` loop that iterates over the `evictServiceIds` array. The loop uses the length property of the array to determine how many elements to iterate over, but it does not check if the length of the array is greater than zero before doing so. 

## Proof of Concept
https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L449-L460

An example where the `evictServiceIds` array has a length of 5, but only 3 elements are actually filled with values. If the code uses a `for` loop to iterate over the array without checking its length first, it may try to access the fourth and fifth elements, which do not exist and will cause the program to crash or behave in unexpected ways.
```solidity
uint256[] memory evictServiceIds = new uint256[](5);
evictServiceIds[0] = 1;
evictServiceIds[1] = 2;
evictServiceIds[2] = 3;

for (uint256 i = 0; i < evictServiceIds.length; ++i) {
    if (evictServiceIds[i] > 0) {
        serviceId = evictServiceIds[i];
        // ...
    }
}
```
In this example, the for loop will iterate over the first three elements of the array, but it will also try to access the fourth and fifth elements, which do not exist. This can cause the program to crash or behave in unexpected ways.

## Tools Used
Vs

## Recommended Mitigation Steps
The code should check the length of the array before iterating over it.
```solidity
for (uint256 i = 0; i < evictServiceIds.length && i < evictServiceIds.length; ++i) {
    if (evictServiceIds[i] > 0) {
        serviceId = evictServiceIds[i];
        // ...
    }
}
```
In this example, the for loop checks the length of the array before iterating over it, so it will only iterate over the elements that actually exist.
