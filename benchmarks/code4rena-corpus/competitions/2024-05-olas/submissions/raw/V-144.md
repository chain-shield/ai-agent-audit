# Vulnerability details

## Impact

The current implementation of the `StakingBase` contract allows users to stake `serviceId` to get the rewards and then unstake if after some period of time. However, due to insufficient checking, the users can get the rewards even though the minimum staking duration has not passed yet. This would give an unfair disadvantage to some users who may stake less than others but still get the rewards.

## Proof of Concept

There is a following check in `unstake()` function of `StakingBase` contract:

https://github.com/code-423n4/2024-05-olas/blob/main/registries/contracts/staking/StakingBase.sol#L818-820
```
if (ts <= minStakingDuration && availableRewards > 0) {
            revert NotEnoughTimeStaked(serviceId, ts, minStakingDuration);
        }

```

It checks whether the time since the start of staking a particular serviceId has passed AND available rewards for the staking > 0. So if one of the conditions is not true, the function would not revert and allow for unstaking. The problem is that the user can catch the moment where there are some rewards in the contract, claim them and then unstake serviceId immediately when there are again no rewards.

So, let's say there are some rewards in the contract and the time since the last checkpoint has become greater than `livenessPeriod` (and there are also `lastAvailableRewards()` to claim). The service can be staked for a short period of time, meet all the ratio pass criteria and then unstake right away not waiting for the `minStakingDuration` to pass by catching the moment when all the available rewards are distributed and again == 0:


https://github.com/code-423n4/2024-05-olas/blob/main/registries/contracts/staking/StakingBase.sol#L507-508
```
 address multisig = sInfo.multisig;
        _withdraw(multisig, reward);
```

https://github.com/code-423n4/2024-05-olas/blob/main/registries/contracts/staking/StakingBase.sol#L645
```
  lastAvailableRewards = 0;
```


`minStakingDuration` is always bigger than the `livenessRatio` and this allows that situation to happen:

https://github.com/code-423n4/2024-05-olas/blob/main/registries/contracts/staking/StakingBase.sol#L350
```
minStakingDuration = _stakingParams.minNumStakingPeriods * livenessPeriod;
```

## Tools Used

Manual review.

## Recommended Mitigation Steps

Make sure that `livenessPeriod` and `minStakingDuration` are synchronized and attacker is not able to gain the rewards not staking the necessary amount of time.
