# Vulnerability details

## Impact
The provided code appears to have a logical flaw when calculating the supply cap for years beyond the first 10 years. Specifically, the loop used to calculate the compounded supply cap returns the total supply cap rather than the cap for just the current year.

## Proof of Concept
If numYears is 10 or more, the function calculates the supply cap using an inflation rate of 2% per year.

numYears is adjusted by subtracting 9 to account for the 0-based index of the array and to start the calculation from the 10th year onwards.

The base supply cap after 10 years is set to 1,000,000,000e18.

The function then iterates over the years beyond the first 10, increasing the supply cap by 2% each year.

```
  function getSupplyCapForYear(uint256 numYears) public pure returns (uint256 supplyCap) {
        // For the first 10 years the supply caps are pre-defined
        if (numYears < 10) {
            uint96[10] memory supplyCaps = [
                529_659_000e18,
                569_913_084e18,
                610_313_084e18,
                666_313_084e18,
                746_313_084e18,
                818_313_084e18,
                882_313_084e18,
                930_313_084e18,
                970_313_084e18,
                1_000_000_000e18
            ];
            supplyCap = supplyCaps[numYears];
        } else {
            // Number of years after ten years have passed (including ongoing ones)
            numYears -= 9;
            // Max cap for the first 10 years
            supplyCap = 1_000_000_000e18;
            // After that the inflation is 2% per year as defined by the OLAS contract
            uint256 maxMintCapFraction = 2;

            // Get the supply cap until the current year
            for (uint256 i = 0; i < numYears; ++i) {
                supplyCap += (supplyCap * maxMintCapFraction) / 100;
            }
            // Return the difference between last two caps (inflation for the current year)
            return supplyCap;
        }
    }
```
The [getSupplyCapForYear()](https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/tokenomics/contracts/TokenomicsConstants.sol#L33C3-L65C1) function incorrectly calculates the supply cap for years beyond the first 10. Instead of returning the supply cap for the specific year requested, it returns the cumulative supply cap up to that year.

Call the getSupplyCapForYear function with numYears set to 11.

Observe that the function returns the cumulative supply cap up to year 11 instead of the specific supply cap for the 11th year.


***Steps to Reproduce:***

Call the getSupplyCapForYear function with numYears set to 11.
Observe that the function returns the cumulative supply cap up to year 11 instead of the specific supply cap for the 11th year.

***Expected Behavior:***
The function should return the supply cap for the specific year requested, accurately reflecting the yearly cap, including the 2% inflation for years beyond the first 10.

The function returns the cumulative supply cap, leading to inflated values and incorrect reporting.

## Recommended Mitigation Steps
Use P * (1 + r)^n formula instead:
where; P is the base supply cap after 10 years (1_000_000_000e18).
r is the annual inflation rate (2%).
n is the number of years after the first 10 years.

And change the  [numYears -= 9;](https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/tokenomics/contracts/TokenomicsConstants.sol#L51) to numYears -= 10
