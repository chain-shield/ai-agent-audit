# Vulnerability details

## Impact
In the handling of the `withheldAmount`, If the `withheldAmount` is greater than or equal to the `transferAmounts[i]`, the code subtracts the `transferAmounts[i]` from the `withheldAmount` and sets `transferAmounts[i]` to zero. However, it doesn't update the `totalAmounts[1]`, which represents the total transfer amount across all the targets.

[@Dispenser.sol:618-624](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L618-L624)
```solidity
if (withheldAmount >= transferAmounts[i]) {
    withheldAmount -= transferAmounts[i];
    transferAmounts[i] = 0;
} else {
    transferAmounts[i] -= withheldAmount;
    withheldAmount = 0;
}
```
If the `withheldAmount` is greater than or equal to the `transferAmounts[i]`, setting `transferAmounts[i]` to zero will result in an incorrect total transfer amount because `totalAmounts[1]` is not updated accordingly.

> Inside the function is a loop that iterates over each chain ID and its corresponding staking targets. For each chain ID, it calculates the staking incentives and transfer amounts.

[@Dispenser.sol:615-530](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L615-L631)
```solidity
if (transferAmounts[i] > 0) {
    uint256 withheldAmount = mapChainIdWithheldAmounts[chainIds[i]];
    if (withheldAmount > 0) {
        if (withheldAmount >= transferAmounts[i]) {
            withheldAmount -= transferAmounts[i];
            transferAmounts[i] = 0;
        } else {
            transferAmounts[i] -= withheldAmount;
            withheldAmount = 0;
        }
        mapChainIdWithheldAmounts[chainIds[i]] = withheldAmount;
    }
}
```
In this code, if the `withheldAmount` is greater than or equal to the `transferAmounts[i]`, it subtracts the `transferAmounts[i]` from the `withheldAmount` and sets `transferAmounts[i]` to zero. However, it doesn't update the `totalAmounts[1]`, which represents the total transfer amount across all the targets.

The impact of this is that if the `withheldAmount` is greater than or equal to the `transferAmounts[i]`, the `totalAmounts[1]` will not be updated correctly. It will still include the original value of `transferAmounts[i]`, even though it has been set to zero.

As a result, the total transfer amount returned by the function will be incorrect. It will be higher than the actual total transfer amount because it includes the original value of `transferAmounts[i]` that should have been subtracted.

> This discrepancy in the total transfer amount can lead to incorrect accounting and distribution of staking incentives. The `_calculateStakingIncentivesBatch function` may indicate a higher total transfer amount than what is actually being transferred, potentially causing issues in the overall tokenomics and reward calculations.

## Proof of Concept
   - Suppose `totalAmounts[1]` is initially 1000.
   - For a particular chain ID, `transferAmounts[i]` is 500, and `withheldAmount` is 600.
   - In this case, since `withheldAmount` is greater than transferAmounts[i], the code will set `transferAmounts[i]` to zero and subtract 500 from `withheldAmount`, resulting in `withheldAmount` becoming 100.
   - However, `totalAmounts[1]` will still remain as 1000, even though it should have been reduced by 500 to reflect the actual total transfer amount of 500.

## Recommended Mitigation Steps
Subtract the `transferAmounts[i]` from `totalAmounts[1]` when setting `transferAmounts[i]` to zero.
```solidity
if (withheldAmount >= transferAmounts[i]) {
    withheldAmount -= transferAmounts[i];
    totalAmounts[1] -= transferAmounts[i];
    transferAmounts[i] = 0;
} else {
    transferAmounts[i] -= withheldAmount;
    totalAmounts[1] -= withheldAmount;
    withheldAmount = 0;
}
```
By updating `totalAmounts[1]` in both cases, the total transfer amount will be correctly calculated even when the `withheldAmount` is greater than or equal to the `transferAmounts[i]`.
