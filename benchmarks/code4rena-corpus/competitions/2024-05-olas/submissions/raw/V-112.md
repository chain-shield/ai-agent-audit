# Vulnerability details

## Impact
[@Dispenser.sol:424](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L424)
```solidity
address stakingTargetEVM = address(uint160(uint256(stakingTarget)));
```
In this line, `stakingTarget` is of type `bytes32`, and it is being converted to an `address` by first converting it to `uint256` and then to `uint160`. However, this conversion assumes that the `stakingTarget` always represents a valid Ethereum address.

If the `stakingTarget` is not a valid Ethereum address or if it contains any data other than an address, this conversion will result in an incorrect address. This could lead to the staking incentives being sent to the wrong address or even to an invalid address.v

## Proof of Concept
In cases where the `stakingTarget` contains data that is not a valid Ethereum address, the conversion will produce an invalid address. Sending staking incentives to an invalid address will result in the permanent loss of those incentives, as they will be sent to an address that doesn't exist on the Ethereum network.

When we look at this as where the `stakingTarget` is not a valid Ethereum address.
```solidity

```
In this example, `invalidStakingTarget` is a `bytes32` value that does not represent a valid Ethereum address. When converted to an address using the same conversion logic as in the `_distributeStakingIncentives` function, it will result in an incorrect address.

The converted address will be 0x1234567890123456789012345678901234567890, which is not a valid Ethereum address. Sending staking incentives to this address would result in the loss of those incentives.

## Recommended Mitigation Steps
ensure that the `stakingTarget` is indeed a valid Ethereum address before performing the conversion. One way to do this is to check if the `stakingTarget` is exactly 20 bytes long (the length of an Ethereum address) before converting it to an address. If it's not 20 bytes, you should handle the case appropriately, such as reverting the transaction or using a different logic.
```solidity
if (chainId <= MAX_EVM_CHAIN_ID) {
    require(stakingTarget.length == 20, "Invalid staking target");
    address stakingTargetEVM = address(uint160(uint256(stakingTarget)));
    // ...
}
```
