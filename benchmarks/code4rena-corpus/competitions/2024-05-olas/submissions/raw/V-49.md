# Vulnerability details

## Impact
- If the `staticcall` to `getMultisigNonces` fails or returns data with an invalid length, the `currentNonces` variable will be left uninitialized.
- The subsequent code that uses currentNonces to make the `staticcall` to `isRatioPass` will be operating on an uninitialized array.
- This can lead to unexpected behavior and potentially incorrect results.

## Proof of Concept
1. getMultisigNonces staticcall (StakingBase.sol:406-413): https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L406-L413
```solidity
bytes memory activityData = abi.encodeCall(IActivityChecker.getMultisigNonces, multisig);
(bool success, bytes memory returnData) = activityChecker.staticcall(activityData);

if (success && returnData.length > 63 && (returnData.length % 32 == 0)) {
    currentNonces = abi.decode(returnData, (uint256[]));
}
```
If the `staticcall` fails or returns data with an invalid length, the code continues without initializing `currentNonces`.
2. `isRatioPass staticcall` (StakingBase.sol:415-422): https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L416-L422

activityData = abi.encodeCall(IActivityChecker.isRatioPass, (currentNonces, lastNonces, ts));

**Other Relevant Proof:**

1. Solidity documentation on `staticcall:`

- The `staticcall` function is used to make a call to another contract without modifying the state of the calling contract.
- If the called function reverts or runs out of gas, `staticcall` returns false as the success value.
- In the `_checkRatioPass` function, the code does not handle the case when success is false, leading to the issues described above.

2. Solidity documentation on uninitialized variables:

- In Solidity, uninitialized variables have a default value depending on their type.
- For `bool` variables, the default value is false.
- For arrays, the default value is an empty array.
- However, relying on default values can lead to unexpected behavior and should be avoided.

## Recommended Mitigation Steps
Consider adding appropriate error handling and revert statements when the `staticcall` fails or returns unexpected data. For example:
```solidity
// If the function call was successful, check the return value
// The return data length must be the exact number of full slots
if (success && returnData.length > 63 && (returnData.length % 32 == 0)) {
    // Parse nonces
    currentNonces = abi.decode(returnData, (uint256[]));
} else {
    // Revert with an appropriate error message
    revert("Invalid getMultisigNonces response");
}

// Get the ratio pass activity check
activityData = abi.encodeCall(IActivityChecker.isRatioPass, (currentNonces, lastNonces, ts));
(success, returnData) = activityChecker.staticcall(activityData);

// The return data must match the size of bool
if (success && returnData.length == 32) {
    ratioPass = abi.decode(returnData, (bool));
} else {
    // Revert with an appropriate error message
    revert("Invalid isRatioPass response");
}
```
