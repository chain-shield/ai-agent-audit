# Vulnerability details

## Impact

The current implementation of the `_maxAndSub` function in the `VoteWeighting` contract can lead to incorrect updates of nominee weights and the total weight sum. Specifically, when the `oldBias` value is greater than the sum of the current weight (`_getWeight(account, chainId)`) and the new bias (`newBias`), or greater than the sum of the current total weight (`_getSum()`) and the new bias, the `_maxAndSub` function silently returns 0. This behavior can result in the following impacts:

1. **Inaccurate Weight History**: Incorrect historical data for nominee weights, making it difficult to track and audit past voting behavior accurately.
2. **Misrepresentation of Voting Power**: Nominees whose weights are incorrectly set to zero may lose their voting power, misrepresenting the actual distribution of voting power.
3. **Disproportionate Influence**: Other nominees might gain disproportionate influence if certain nominees' weights are set to zero, disrupting the intended balance of power and fairness in the voting process.
4. **Silent Failure**: The function silently fails without providing any indication or error message, making it challenging to detect and debug issues.
5. **Risk of Manipulation**: Malicious actors could exploit this behavior to manipulate the voting system by deliberately causing underflows to zero out weights and sums, thereby altering the voting dynamics to their advantage or detriment of everyone.

## Proof of Concept

### Line of Code
```solidity
function _maxAndSub(uint256 a, uint256 b) internal pure returns (uint256) {
    return a > b ? a - b : 0;
}
```

### Affected Code Snippet

https://github.com/code-423n4/2024-05-olas/blob/main/governance/contracts/VoteWeighting.sol#L532

1. Updating nominee weights:
```solidity
pointsWeight[nomineeHash][nextTime].bias = _maxAndSub(_getWeight(account, chainId) + newBias, oldBias);
```

2. Updating total weight sum:
```solidity
pointsSum[nextTime].bias = _maxAndSub(_getSum() + newBias, oldBias);
```

### Example Scenario

1. **Inaccurate Weight History**:
   - Suppose a nominee had a weight of 1000 (`oldBias = 1000 * time difference`). After some votes, the new weight calculation results in a combined weight of 500 (current weight + new bias). Since 1000 > 500, the `_maxAndSub` function sets the weight to zero, inaccurately recording the nominee's weight as zero.

2. **Misrepresentation of Voting Power**:
   - A user votes for a nominee, initially giving them a weight of 800 (`oldBias = 800 * time difference`). Later, the user's voting power decreases, and the new calculation results in a combined weight of 400. Since 800 > 400, the weight is set to zero, misrepresenting the nominee's actual voting power.
   
3. **Disproportionate Influence**: 
   - Nominee A has a significant weight of 1500. After an underflow due to a new vote, their weight is set to zero. Other nominees with stable weights (e.g., 600, 700) now have disproportionate influence compared to their intended distribution.

4. **Silent Failure**: 

   - During a routine update, the system recalculates weights. Due to an unexpected change, the oldBias is greater than the combined weight, setting the value to zero without any error message. The failure goes unnoticed, leading to inaccurate governance data.

## Recommended Mitigation Steps

Replace the `_maxAndSub` function with a safe subtraction function that reverts the transaction when an underflow occurs. Here's an example implementation:

```solidity
function _safeSub(uint256 a, uint256 b) internal pure returns (uint256) {
    require(b <= a, "Subtraction overflow");
    return a - b;
}
```

### Update Affected Code Snippets

1. Updating nominee weights:
```solidity
pointsWeight[nomineeHash][nextTime].bias = _safeSub(_getWeight(account, chainId) + newBias, oldBias);
```

2. Updating total weight sum:
```solidity
pointsSum[nextTime].bias = _safeSub(_getSum() + newBias, oldBias);
```

By using the `_safeSub` function, if `oldBias` is greater than `_getWeight(account, chainId) + newBias` or `_getSum() + newBias`, the transaction will revert with an explicit error message, preventing incorrect state updates and alerting the contract administrators to potential issues.
