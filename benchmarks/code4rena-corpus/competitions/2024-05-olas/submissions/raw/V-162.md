# Vulnerability details

## Impact
An attacker will claim the incentives belonging to an owner of components/agents due to poor access control.

## Proof of Concept
https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/tokenomics/contracts/Dispenser.sol#L783
This comment states that msg.sender` must be the owner of components / agents they are passing, otherwise the function will revert. But throughout the function, there was no check of whether the msg.sender is the owner of component.

    function claimOwnerIncentives(
        uint256[] memory unitTypes,
        uint256[] memory unitIds
    ) external returns (uint256 reward, uint256 topUp) {
        // Reentrancy guard
        if (_locked > 1) {
            revert ReentrancyGuard();
        }
        _locked = 2;

However, the function checks for reentrancy, which is fine, it doesn't confirm if the user calling the function is the owner of the agent.


        if ((reward + topUp) > 0) {
            // Get the current OLAS balance
            uint256 olasBalance;
            if (topUp > 0) {
                olasBalance = IToken(olas).balanceOf(msg.sender);
            }


            success = ITreasury(treasury).withdrawToAccount(msg.sender, reward, topUp);


            // Check the balance after the OLAS mint, if applicable
            if (topUp > 0){
                olasBalance = IToken(olas).balanceOf(msg.sender) - olasBalance;
                if (olasBalance != topUp) {
                    revert WrongAmount(olasBalance, topUp);

This snippet also Request treasury to transfer funds to msg.sender if reward > 0 or topUp > 0 which is fine. But it doesn't ensure if the user calling the function, owns the agent. And this might lead to loss of incentives to an attacker.

## Recommended Mitigation Steps
This is typically implemented using a require statement that check whether the caller is the owner of the component/agent before proceeding with the function execution to claim incentives. Thanks
