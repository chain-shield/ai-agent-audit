# Vulnerability details

## Impact
checkpoint function can lead to incorrect reward allocation when the total allocated rewards exceed the available rewards, and there is only one eligible service (i.e., `numServices` is 1). In this case, the service at index 0 will receive the entire `lastAvailableRewards` instead of the proportionally adjusted reward. This can result in the service being overpaid and the available rewards being depleted more quickly than intended.

In the loop, the rewards are adjusted for services starting from index 1 up to `numServices - 1`. However, the reward for the service at index 0 is processed separately after the loop. This can lead to incorrect reward allocation if `numServices` is 1.

## Proof of Concept
Suppose we have the following values:

  - `lastAvailableRewards` = 1000
  - `totalRewards` = 1500
  - numServices` = 1
  - `eligibleServiceIds` = [42]
  - `eligibleServiceRewards` = [1500]

Now, let's trace the execution of the problematic code.

  1. The loop condition `i = 1; i < numServices` is false since `numServices` is 1, so the loop is skipped entirely.

  2. The code proceeds to process the first service separately:
```solidity
updatedReward = (eligibleServiceRewards[0] * lastAvailableRewards) / totalRewards;
// updatedReward = (1500 * 1000) / 1500 = 1000

updatedTotalRewards += updatedReward;
// updatedTotalRewards = 1000

curServiceId = eligibleServiceIds[0];
// curServiceId = 42

finalEligibleServiceIds[0] = eligibleServiceIds[0];
// finalEligibleServiceIds[0] = 42

if (lastAvailableRewards > updatedTotalRewards) {
    updatedReward += lastAvailableRewards - updatedTotalRewards;
}
// This condition is false since lastAvailableRewards (1000) is not greater than updatedTotalRewards (1000)

finalEligibleServiceRewards[0] = updatedReward;
// finalEligibleServiceRewards[0] = 1000

mapServiceInfo[curServiceId].reward += updatedReward;
// mapServiceInfo[42].reward += 1000
```
As a result, the service with ID 42 (at index 0) receives the entire `lastAvailableRewards` of 1000, instead of the proportionally adjusted reward of 666 (1000 * 1000 / 1500).

To further illustrate the concept, let's consider the corrected code:
```solidity
uint256 updatedReward;
uint256 updatedTotalRewards;
for (uint256 i = 0; i < numServices; ++i) {
    updatedReward = (eligibleServiceRewards[i] * lastAvailableRewards) / totalRewards;
    updatedTotalRewards += updatedReward;
    curServiceId = eligibleServiceIds[i];
    finalEligibleServiceIds[i] = eligibleServiceIds[i];
    finalEligibleServiceRewards[i] = updatedReward;
    mapServiceInfo[curServiceId].reward += updatedReward;
}

if (lastAvailableRewards > updatedTotalRewards) {
    finalEligibleServiceRewards[0] += lastAvailableRewards - updatedTotalRewards;
    mapServiceInfo[eligibleServiceIds[0]].reward += lastAvailableRewards - updatedTotalRewards;
}
```
With the corrected code, the service at index 0 would receive the proportionally adjusted reward of 666 (1000 * 1000 / 1500), and any leftover rewards would be added to its reward amount.

## Recommended Mitigation Steps
Modify the loop to start from index 0 and process all services uniformly, including the service at index 0.
```solidity
// Traverse all the eligible services and adjust their rewards proportional to leftovers
uint256 updatedReward;
uint256 updatedTotalRewards;
for (uint256 i = 0; i < numServices; ++i) {
    // Calculate the updated reward
    updatedReward = (eligibleServiceRewards[i] * lastAvailableRewards) / totalRewards;
    // Add to the total updated reward
    updatedTotalRewards += updatedReward;
    // Add reward to the overall service reward
    curServiceId = eligibleServiceIds[i];
    finalEligibleServiceIds[i] = eligibleServiceIds[i];
    finalEligibleServiceRewards[i] = updatedReward;
    mapServiceInfo[curServiceId].reward += updatedReward;
}

// If the reward adjustment happened to have small leftovers, add it to the first service
if (lastAvailableRewards > updatedTotalRewards) {
    finalEligibleServiceRewards[0] += lastAvailableRewards - updatedTotalRewards;
    mapServiceInfo[eligibleServiceIds[0]].reward += lastAvailableRewards - updatedTotalRewards;
}
```
After the modification, all services, including the one at index 0, will adjust their rewards proportionally, and any leftover rewards will be added to the first service.
