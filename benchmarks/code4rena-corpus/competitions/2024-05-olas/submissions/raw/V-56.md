# Vulnerability details

## Impact
When a user's voting power is revoked for a removed nominee, the previously scheduled weight changes are not properly canceled. Instead of adding the `oldSlope.slope` back to `changesWeight[nomineeHash][oldSlope.end]` and `changesSum[oldSlope.end]`, the function incorrectly subtracts the `oldSlope.slope` from these values.

This means that the weight changes scheduled at `oldSlope.end` for the removed nominee will still be applied, even though the user's voting power has been revoked. As a result, the nominee's weight will be incorrectly updated, leading to an inaccurate representation of the voting power distribution among the remaining nominees.

## Proof of Concept
To illustrate the issue, consider the following scenario:

User A votes for Nominee X with a weight of 100 at time T1, with the weight change scheduled to take effect at time T2.
At time T1, the following updates occur:
`changesWeight[nomineeHash][T2] += 100`
`changesSum[T2] += 100`

Later, Nominee X is removed, and User A calls `revokeRemovedNomineeVotingPower` to revoke their voting power.
The function incorrectly executes the following:
`changesWeight[nomineeHash][T2] -= 100`
`changesSum[T2] -= 100`

Instead of canceling the scheduled weight changes by adding the `oldSlope.slope` (100) back to `changesWeight[nomineeHash][T2]` and `changesSum[T2]`, the function subtracts the `oldSlope.slope` from these values.

As a result, when the weight update is applied at time T2, the nominee's weight will be incorrectly decreased by 200 (100 from the original vote, and another 100 from the incorrect subtraction during the revocation process).

This can lead to significant discrepancies in the nominee weight calculations, affecting the outcome of voting processes and undermining the fairness and integrity of the system.

## Recommended Mitigation Steps
By adding the `oldSlope.slope` back to `changesWeight[nomineeHash][oldSlope.end]` and `changesSum[oldSlope.end]`, the previously scheduled weight changes will be properly canceled, ensuring accurate nominee weight calculations after revoking a user's voting power for a removed nominee.
```solidity
// Cancel old slope changes if they still didn't happen
if (oldSlope.end > block.timestamp) {
    changesWeight[nomineeHash][oldSlope.end] += oldSlope.slope;
    changesSum[oldSlope.end] += oldSlope.slope;
}
```
