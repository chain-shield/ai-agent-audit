# Vulnerability details

## Impact

In the current implementation, `Dispenser` contract is used to assign `stakingIncentive` (that is formed by determined OLAS inflation amount per epoch) to a staking target that called `claimStakingIncentives()` function. The problem is that the user may not get any rewards at all as the variable can be nullified right away before distribution.

## Proof of Concept

Let's look at the following scenario:

1. User calls `claimStakingIncentives()` and the incentives are calculated inside of `calculateStakingIncentives()`:

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L993-994

```
   (uint256 stakingIncentive, uint256 returnAmount, uint256 lastClaimedEpoch, bytes32 nomineeHash) =
            calculateStakingIncentives(numClaimedEpochs, chainId, stakingTarget, bridgingDecimals);
```

2. Then the transfer amount is calculated based on the amount that the contract may cover by using `withheldAmount` (amount of tokens that were withheld from L2 due to failed verification process). Consider the following case:

1. User's initial transfer amount = 100 (staking incentive)

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L1008
```
transferAmount = stakingIncentive
```

2. Now `withheldAmount` is used to determine how much tokens can be covered by it:

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L1015-1017
```
if (withheldAmount >= transferAmount) {
                    withheldAmount -= transferAmount;
                    transferAmount = 0;
```

For simplicity, let's say it was equal to 50. Now `transferAmount` is equal to 50:

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L1020-1021
```
 transferAmount -= withheldAmount;
 withheldAmount = 0;
```

3. Now we transfer the insufficient OLAS amount (50 tokens) from the `Treasury`. At this step there are no changes to the `transferAmount`:

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L1031
```
 ITreasury(treasury).withdrawToAccount(address(this), 0, transferAmount);
```


4. The problem is that the `_distributeStakingIncentives()` has updated `transferAmount` (equal to 50 tokens) instead of initial staking incentive:

https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Dispenser.sol#L1041
```
 _distributeStakingIncentives(chainId, stakingTarget, stakingIncentive, bridgePayload, transferAmount);
```

This would lead to a situation where the user's incentive is significantly reduced by substracting the `withheldAmount` from it and the user ending up not getting all the rewards.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Use the correct value of `transferAmount` variable when passing it to the `_distributeStakingIncentives()` function.
