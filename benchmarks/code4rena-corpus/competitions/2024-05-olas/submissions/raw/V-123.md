# Vulnerability details

## Impact
To address the reentrancy risks in the addNomineeEVM, addNomineeNonEVM, and removeNominee functions, we need to follow the Checks-Effects-Interactions pattern. This pattern involves first performing all necessary state changes (effects) before making any external calls (interactions).

## Proof of Concept

### addNomineeEVM and addNomineeNonEVM Functions
1. No direct changes were made to these functions, but they rely on the updated _addNominee function, inheriting its reentrancy protection improvements.

Here are the changes made to the original code to mitigate reentrancy risks by following the Checks-Effects-Interactions pattern:

### _addNominee Function
1. State Changes First:
The state changes (e.g., updating mapNomineeIds, setNominees, timeWeight) are performed before the external call to IDispenser.

2. External Call Moved Last:
The call to IDispenser.addNominee is moved to the end of the function, after all state changes and event emissions.

Original Code:

function _addNominee(Nominee memory nominee) internal {
    // Existing code
    address localDispenser = dispenser;
    if (localDispenser != address(0)) {
        IDispenser(localDispenser).addNominee(nomineeHash);
    }
    emit AddNominee(nominee.account, nominee.chainId, id);
}

Modified Code:


function _addNominee(Nominee memory nominee) internal {
    // Existing code for state changes
    emit AddNominee(nominee.account, nominee.chainId, id);

    // External call moved after state changes
    address localDispenser = dispenser;
    if (localDispenser != address(0)) {
        IDispenser(localDispenser).addNominee(nomineeHash);
    }
}

## Recommended Mitigation Steps
Summary of Changes
1. State Changes First: All necessary state modifications are performed before any external calls.
2. External Calls Last: External interactions with IDispenser are moved to the end of the functions, ensuring the contract state is updated before any potential reentrancy can occur.
3. Event Emissions: Events are emitted before making external calls, maintaining a clear record of state changes.

These changes ensure the contract adheres to the Checks-Effects-Interactions pattern, mitigating reentrancy risks.
