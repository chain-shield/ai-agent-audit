# Vulnerability details

## Impact

Reward accounting error. The first eligible service will not get the excess amounts and the excess amount will still get stuck in the contract.

## Proof of Concept

When calculating rewards in `StakingBase.checkpoint()`, the function calls `_calculateStakingRewards()` and gets back an array of `eligibleServiceRewards`.

If the `totalRewards > lastAvailableRewards`, meaning that if the total rewards for eligible stakers is more than the available rewards, then the rewards will be proportioned to the percentage of `lastAvailableRewards / totalRewards`.

For example, if there are 4 stakers with 10 tokens as reward each. The `totalRewards` is 40 tokens, but the available rewards is only 39 tokens. Each staker will get `10 * 39/40` tokens instead (9.75 tokens each)

```
if (totalRewards > lastAvailableRewards) {
                // Traverse all the eligible services and adjust their rewards proportional to leftovers
                uint256 updatedReward;
                uint256 updatedTotalRewards;
                for (uint256 i = 1; i < numServices; ++i) {
                    // Calculate the updated reward
>                   updatedReward = (eligibleServiceRewards[i] * lastAvailableRewards) / totalRewards;
                    // Add to the total updated reward
>                   updatedTotalRewards += updatedReward;
                    // Add reward to the overall service reward
                    curServiceId = eligibleServiceIds[i];
                    finalEligibleServiceIds[i] = eligibleServiceIds[i];
                    finalEligibleServiceRewards[i] = updatedReward;
                    mapServiceInfo[curServiceId].reward += updatedReward;
                }
```

If there are dust values still avaible after the division (due to truncation), then the remaining dust value is given to the first staker.

```
  // Process the first service in the set
                updatedReward = (eligibleServiceRewards[0] * lastAvailableRewards) / totalRewards;
                updatedTotalRewards += updatedReward;
                curServiceId = eligibleServiceIds[0];
                finalEligibleServiceIds[0] = eligibleServiceIds[0];
                // If the reward adjustment happened to have small leftovers, add it to the first service
                if (lastAvailableRewards > updatedTotalRewards) {
                    updatedReward += lastAvailableRewards - updatedTotalRewards;
                }
                finalEligibleServiceRewards[0] = updatedReward;
                // Add reward to the overall service reward
                mapServiceInfo[curServiceId].reward += updatedReward;
                // Set available rewards to zero
                lastAvailableRewards = 0;
```

This calculation of giving the first staker the dust value is incorrectly calculated.

Let's say the `totalRewards` is 40e18 and the `lastAvailableRewards` is 39e18. Assuming a small value for `rewardsPerSecond()` (the test file writes 0.0001 ether but lets assume a much smaller value for obvious truncation result), then each user gets about 9.7e18 tokens with some leftover as truncation, and updateTotalRewards is `38.8e18` tokens.

Now, the code is supposed to sweep the 0.05e18 * 4 tokens to the first staker.

First, it calls ` updatedReward = (eligibleServiceRewards[0] * lastAvailableRewards) / totalRewards`, to get the eligible awards of the first user again, which is 9.7e18

Then, it calls `updatedTotalRewards += updateReward`. This is the issue since the updatedTotalRewards will become 38.8e18 + 9.7e18 which is greater than 40e18.

Next, it checks if `lastAvailableRewards > updatedTotalRewards`, which by now is not greater anymore, so the excess reward will not be swept into the first service staker and will instead be stuck in the contract. 

## Tools Used

Manual Review

## Recommended Mitigation Steps

Remove the `updatedTotalRewards += updatedReward;` line in L634 of stakingBase since it erroneously increases the `updatedTotalRewards`.

What should happen instead is the code should get the leftover amount, which is `lastAvailableRewards - updatedTotalRewards`. If there is indeed a leftover, then just add the leftover rewards to the first service staker `finalEligibleServiceRewards[0] = updatedReward + leftover;`.
