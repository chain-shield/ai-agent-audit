# Vulnerability details

## Impact

The use of staticcall in smart contracts, particularly when interacting with other contracts, poses a significant security risk. According to the solidity docs, if a staticcall encounters a state change, it burns up all gas and returns. If the called contract contains state-changing operations, it could potentially consume all available gas during the execution of the staticcall, leading to a Denial of Service (DoS) condition.

The `_checkRatioPass` function in the contract contains a vulnerability that could potentially lead to denial-of-service (DoS) attacks or out-of-gas errors. This vulnerability arises due to the use of staticcall without limiting the amount of gas forwarded, which could result in the exhaustion of all available gas if the called function attempts to modify state.

This vulnerability has already been called out in known protocols ie balancer and has been addressed see below

https://github.com/balancer/balancer-v2-monorepo/blob/227683919a7031615c0bc7f144666cdf3883d212/pkg/pool-utils/contracts/lib/VaultReentrancyLib.sol#L48-L53

According to EIP150, a call gets allocated 63/64 bits of the gas, and the entire 63/64 parts of the gas is burnt up after the staticcall, since the staticcall will always encounter a storage change.

Similar Finding https://solodit.xyz/issues/m-17-oog-unexpected-reverts-due-to-incorrect-usage-of-staticcall-sherlock-tokemak-git

## Proof of Concept

Consider a smart contract that uses staticcall to interact with another contract, which, upon interaction, performs state-changing operations. If the called contract's operations are not properly bounded or if the gas limit for the staticcall is not adequately capped, the entire gas budget allocated for the transaction could be consumed by the called contract's operations. This could lead to a situation where subsequent operations within the same transaction fail due to insufficient gas, effectively causing a DoS condition.

An attacker crafts a malicious signature and sends a transaction invoking the `_checkRatioPass` function with excessive gas. The `_checkRatioPass` function executes a staticcall to the signer's address to validate the signature. If the called function within the signer contract performs any state-changing operations, it consumes all available gas, leading to an out-of-gas error. As a result, the transaction fails, potentially causing a denial-of-service condition.

## Recommended Mitigation Steps
modify the `_checkRatioPass` function to include a fixed gas stipend when performing the staticcall. This ensures that even if the called function attempts to change state, it won't consume excessive gas or cause out-of-gas errors.

```javascript
(bool success, bytes memory returnData) = activityChecker.staticcall{gas: FIXED_GAS_AMOUNT}(activityData);
```
