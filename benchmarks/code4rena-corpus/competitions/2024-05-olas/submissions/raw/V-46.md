# Vulnerability details

## Impact
Whether slopes happen are not judged suitably,  then vote power of a user will be lost in some scenario.

## Proof of Concept
https://github.com/code-423n4/2024-05-olas/blob/main/governance/contracts/VoteWeighting.sol#L542

Votes are calculated to the next week. In function voteForNomineeWeights(), old slope changes will be cancelled if they didn't happen. Whether slopes happen are not judged suitably. oldSlope.end should be compared to the beginning of next week.

       if (oldSlope.end > block.timestamp) {
            // Cancel old slope changes if they still didn't happen
            changesWeight[nomineeHash][oldSlope.end] -= oldSlope.slope;
            changesSum[oldSlope.end] -= oldSlope.slope;
        }

should be:
        if (oldSlope.end > nextTime ) {
            // Cancel old slope changes if they still didn't happen
            changesWeight[nomineeHash][oldSlope.end] -= oldSlope.slope;
            changesSum[oldSlope.end] -= oldSlope.slope;
        }

Then some of the user's vote power will be lost in the following steps, for example.
1, user lock tokens until the end of week16.
2, user vote in week1.
3, user vote again in week 16, just several minutes before the end of week16.

Since "oldSlope.end" is bigger than block.timestamp, old slope changes will be cancelled.

change from:
       if (oldSlope.end > block.timestamp) {
to： 
       if (oldSlope.end > nextTime ) {
