# Vulnerability details

## Impact
To mitigate the security risks associated with the use of delegatecall in the fallback function, you can take several steps:
1. Use a Trusted Implementation Contract: Ensure the implementation contract is thoroughly audited and trusted.
2. Restrict Upgradeability: Allow upgrades only from a trusted owner or admin.
Check for Reentrancy: Implement reentrancy guards to prevent reentrancy attacks.
3. Use OpenZeppelin's Proxy Pattern: Use well-tested proxy patterns like OpenZeppelin's UpgradeableProxy which includes built-in security features.

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.25;

import "@openzeppelin/contracts/security/ReentrancyGuard.sol";
import "@openzeppelin/contracts/proxy/utils/UUPSUpgradeable.sol";
import "@openzeppelin/contracts/proxy/ERC1967/ERC1967Upgrade.sol";

/// @dev Zero implementation address.
error ZeroImplementationAddress();
/// @dev Unauthorized caller.
/// @param caller Caller address.
error UnauthorizedCaller(address caller);

/*
* This is a Service Staking proxy contract.
* Proxy implementation is created based on the Universal Upgradeable Proxy Standard (UUPS) EIP-1822.
* The implementation address must be located in a unique storage slot of the proxy contract.
* The upgrade logic must be located in the implementation contract.
* Special service staking implementation address slot is produced by hashing the "SERVICE_STAKING_PROXY"
* string in order to make the slot unique.
* The fallback() implementation for all the delegatecall-s is inspired by the Gnosis Safe set of contracts.
*/

/// @title StakingProxy - Smart contract for service staking proxy
/// @author Aleksandr Kuperman - <aleksandr.kuperman@valory.xyz>
/// @author Andrey Lebedev - <andrey.lebedev@valory.xyz>
/// @author Mariapia Moscatiello - <mariapia.moscatiello@valory.xyz>
contract StakingProxy is ERC1967Upgrade, ReentrancyGuard {
    // Code position in storage is keccak256("SERVICE_STAKING_PROXY") = "0x9e5e169c1098011e4e5940a3ec1797686b2a8294a9b77a4c676b121bdc0ebb5e"
    bytes32 public constant SERVICE_STAKING_PROXY = 0x9e5e169c1098011e4e5940a3ec1797686b2a8294a9b77a4c676b121bdc0ebb5e;
    // Contract owner
    address public owner;

    /// @dev StakingProxy constructor.
    /// @param implementation Service staking implementation address.
    constructor(address implementation) {
        // Check for the zero address, since the delegatecall works even with the zero one
        if (implementation == address(0)) {
            revert ZeroImplementationAddress();
        }

        // Set the contract owner
        owner = msg.sender;

        // Store the service staking implementation address
        _upgradeTo(implementation);
    }

    /// @dev Updates the implementation address.
    /// @param newImplementation New implementation address.
    function updateImplementation(address newImplementation) external {
        if (msg.sender != owner) {
            revert UnauthorizedCaller(msg.sender);
        }
        if (newImplementation == address(0)) {
            revert ZeroImplementationAddress();
        }

        _upgradeTo(newImplementation);
    }

    /// @dev Delegatecall to all the incoming data.
    fallback() external payable nonReentrant {
        address implementation = _getImplementation();
        assembly {
            calldatacopy(0, 0, calldatasize())
            let success := delegatecall(gas(), implementation, 0, calldatasize(), 0, 0)
            returndatacopy(0, 0, returndatasize())
            if eq(success, 0) {
                revert(0, returndatasize())
            }
            return(0, returndatasize())
        }
    }

    /// @dev Gets the implementation address.
    function getImplementation() external view returns (address implementation) {
        implementation = _getImplementation();
    }
}

## Recommended Mitigation Steps

### Import OpenZeppelin Libraries:
1. ReentrancyGuard to prevent reentrancy attacks.
2. ERC1967Upgrade to use the standardized storage slots for upgradeable contracts.

### Modified Constructor:
1. Setting the initial implementation using _upgradeTo from ERC1967Upgrade.
### Updated updateImplementation Function:
1. Used _upgradeTo from ERC1967Upgrade for secure upgrades.
### Added nonReentrant Modifier to fallback:
1. Prevent reentrancy in the fallback function by using the nonReentrant modifier.

### Additional Security Considerations
1. Ownership Transfer: Consider implementing a function to securely transfer ownership.
2. Audit Implementation Contract: Ensure the implementation contract is thoroughly audited.
3. Role-Based Access Control: For more complex systems, consider using role-based access control (RBAC) to manage permissions.

These changes enhance the security of the proxy contract by mitigating the risks associated with delegatecall and ensuring only authorized users can upgrade the implementation.
