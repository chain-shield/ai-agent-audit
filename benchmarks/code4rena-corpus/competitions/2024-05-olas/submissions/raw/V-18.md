# Vulnerability details

## Impact

The `registerPair` function in the `PredyPool` contract, which is used to add new trading pairs, lacks validation for the `uniswapPool` address provided in the `addPairParam` struct. This missing validation can lead to the registration of invalid or malicious Uniswap V3 pools, potentially causing significant financial losses for users interacting with the Predy protocol.

If an invalid or malicious `uniswapPool` address is registered, it could lead to several issues:

1.  **Incorrect Price Oracles:** The Predy protocol relies on Uniswap V3 pools for price oracles. If an invalid pool is registered, it could provide incorrect price information, leading to miscalculations in trading, liquidations, and other critical operations.
2.  **Manipulation of Trading:** Malicious actors could create fake Uniswap V3 pools with manipulated prices and register them through the `registerPair` function. This could allow them to manipulate trading outcomes and profit at the expense of other users.
3.  **Loss of Funds:** If users interact with a malicious Uniswap V3 pool registered through the `registerPair` function, they could lose their funds due to unexpected behavior or malicious actions by the pool's creator.

## Proof of Concept

The following code snippets from the `PredyPool.sol` and `AddPairLogic.sol` contracts demonstrate the issue:

```solidity
// PredyPool.sol
function registerPair(AddPairLogic.AddPairParams memory addPairParam) external onlyOperator returns (uint256) {
    return AddPairLogic.addPair(globalData, allowedUniswapPools, addPairParam);
}

// AddPairLogic.sol
function addPair(
    // ...
) internal returns (uint256 pairId) {
    // ... (no validation for uniswapPool)

    // ... (rest of the function logic)
}
```

As shown above, the `registerPair` function directly calls `AddPairLogic.addPair` without performing any validation on the `uniswapPool` address. The `addPair` function also does not include any validation for the `uniswapPool` address, allowing any address to be registered as a valid Uniswap V3 pool.

## Recommended Mitigation Steps

1.  **Validate Uniswap V3 Pool Address:**
    *   In the `AddPairLogic.addPair` function, add validation to ensure that the provided `uniswapPool` address is a valid Uniswap V3 pool. This can be done by checking the pool's factory address, fee tier, or other relevant parameters.
2.  **Consider Whitelisting:**
    *   Implement a whitelist of trusted Uniswap V3 pool addresses that can be registered through the `registerPair` function. This can provide an additional layer of security by preventing the registration of unknown or potentially malicious pools.
