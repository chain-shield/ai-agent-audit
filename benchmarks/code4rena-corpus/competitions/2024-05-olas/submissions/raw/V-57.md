# Vulnerability details

In the [VoteWeighting:getNominee](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/governance/contracts/VoteWeighting.sol#L744-L755) and [VoteWeighting:getRemovedNominee](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/governance/contracts/VoteWeighting.sol#L761-L772) functions, the functions handle the case when the `id` parameter is equal to the length of the respective array (`setNominees` or `setRemovedNominees`).

In both functions, the following condition is used to check for overflow: [#L750-L752](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/governance/contracts/VoteWeighting.sol#L750-L752)
```solidity
if (id > totalNumNominees) {
    revert Overflow(id, totalNumNominees);
}
```
However, this condition does not account for the case when `id` is equal to the length of the array. In that case, the functions will try to access an index that is out of bounds, which will result in an error.

For example, if `setNominees.length` is `5`, and the `id` parameter is `5`, the function will try to access `setNominees[5]`, which is an invalid index (valid indices are 0 to 4).

## Impact
The impact of this issue is that it can cause the contract to revert when trying to access an invalid index in the `setNominees` or `setRemovedNominees` arrays. This can happen when the `id` parameter passed to these functions is equal to the length of the respective array.

## Proof of Concept
https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/governance/contracts/VoteWeighting.sol#L744-L755
```solidity
function getNominee(uint256 id) external view returns (Nominee memory) {
    // Get the total number of nominees in the contract
    uint256 totalNumNominees = setNominees.length - 1;
    // Check for the zero id or the overflow
    if (id == 0) {
        revert ZeroValue();
    } else if (id > totalNumNominees) {
        revert Overflow(id, totalNumNominees);
    }

    return setNominees[id];
}
```
In the condition `id > totalNumNominees`. This condition does not account for the case when `id` is equal to `totalNumNominees`. In that case, the function will try to access `setNominees[id]`, which is an out-of-bounds index.

For example, let's say `setNominees.length` is `5`. This means that `totalNumNominees` will be 4 (since the array indices start from 0). If the `id` parameter is passed as 4, the function will try to access `setNominees[4]`, which is a valid index. However, if the `id` parameter is passed as 5, the function will try to access `setNominees[5]`, which is an invalid index and will cause the contract to revert.

The same issue exists in the **`getRemovedNominee function`**, which has a similar implementation.

Concept Illustration:
To better illustrate the concept, let's consider an example array `arr` with a length of 5.
```solidity
arr = [1, 2, 3, 4, 5]
```
The valid indices for this array are 0, 1, 2, 3, and 4. If you try to access `arr[5]`, it will result in an out-of-bounds error because the index 5 is not a valid index for this array.

## Recommended Mitigation Steps
The condition should be changed to:
```solidity
if (id >= totalNumNominees) {
    revert Overflow(id, totalNumNominees);
}
```
This way, the functions will correctly handle the case when `id` is equal to the length of the array, preventing out-of-bounds access.

Alternatively, you could also check if `id` is strictly less than the length of the array, like this:
```solidity
if (id == 0 || id > totalNumNominees) {
    revert Overflow(id, totalNumNominees);
}
```
This condition combines the check for zero value and the check for overflow in a single condition.
