# Vulnerability details

## Impact
In the `calculateStakingIncentives` function, the function is declared as `public` and is intended to be called via `staticcall` to avoid writing to the nominee checkpoint map. Though, the function modifies the state by calling `IVoteWeighting(voteWeighting).checkpointNominee(stakingTarget, chainId)`, which checkpoints the staking target nominee in the Vote Weighting contract.

If this function is called via a regular transaction (not `staticcall`), it will modify the state, which goes against the intended behavior mentioned in the comment: [tokenomics/contracts/Dispenser.sol#L840](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L840)
```solidity
/// @notice Call this function via staticcall in order not to write in the nominee checkpoint map.
```

## Proof of Concept
When the function is called via a regular transaction, it will execute the `IVoteWeighting(voteWeighting).checkpointNominee(stakingTarget, chainId)` line, which checkpoints the staking target nominee in the Vote Weighting contract. This modification of the contract state goes against the intended behavior mentioned in the comment:
```solidity
/// @notice Call this function via staticcall in order not to write in the nominee checkpoint map.
```
Purpose of using `staticcall` is to ensure that the function execution does not modify the state and only reads from the contract. Yet, the presence of the `checkpointNominee` call within the function violates this expectation. [tokenomics/contracts/Dispenser.sol#L877-L878](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L877-L878)

```solidity
function calculateStakingIncentives(
    uint256 numClaimedEpochs,
    uint256 chainId,
    bytes32 stakingTarget,
    uint256 bridgingDecimals
) public returns (
    uint256 totalStakingIncentive,
    uint256 totalReturnAmount,
    uint256 lastClaimedEpoch,
    bytes32 nomineeHash
) {
    // ...

    // Checkpoint staking target nominee in the Vote Weighting contract
    IVoteWeighting(voteWeighting).checkpointNominee(stakingTarget, chainId);

    // ...
}
```
The impact can be significant, especially if the `calculateStakingIncentives` function is called frequently or by external entities. It can lead to unexpected changes in the contract state, such as updating the nominee checkpoint map when it shouldn't be updated.

## Tools Used

## Recommended Mitigation Steps
1. Remove the `checkpointNominee` call from the function if it's not necessary for the calculation of staking incentives. This way, the function will not modify the state.

2. Change the function visibility to `view` instead of `public.` This will ensure that the function can only be called externally via `staticcall` and will not allow state modifications. However, you'll need to remove the `checkpointNominee` call in this case as well.
```solidity
function calculateStakingIncentives(
    uint256 numClaimedEpochs,
    uint256 chainId,
    bytes32 stakingTarget,
    uint256 bridgingDecimals
) public view returns (
    uint256 totalStakingIncentive,
    uint256 totalReturnAmount,
    uint256 lastClaimedEpoch,
    bytes32 nomineeHash
) {
    // ... (rest of the code remains the same)

    // Remove the following line
    // IVoteWeighting(voteWeighting).checkpointNominee(stakingTarget, chainId);

    // ... (rest of the code remains the same)
}
```
By making this change, the function will no longer modify the state and will adhere to the intended behavior of being called via staticcall.
