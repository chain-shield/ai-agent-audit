# Vulnerability details

## Impact
To mitigate the issue of looping over potentially unbounded arrays, we need to ensure that loops in functions _calculateStakingRewards and _evict have a reasonable maximum iteration count. If necessary, break down large loops into multiple transactions.

## Proof of Concept
By introducing startIndex and endIndex parameters and enforcing a reasonable maximum iteration count, we can prevent gas limit issues when looping over potentially unbounded arrays. This approach ensures that loops in functions _calculateStakingRewards and _evict do not exceed the gas limit

            uint256 ts = sInfo.tsStart;

                serviceCheckpoint = ts;

### _evict Function
Original _evict Function:

function _evict(
    uint256[] memory evictServiceIds,
    uint256[] memory serviceInactivity,
    uint256 numEvictServices
) internal {
    uint256 totalNumServices = evictServiceIds.length;

    uint256[] memory serviceIds = new uint256[](numEvictServices);
    address[] memory owners = new address[](numEvictServices);
    address[] memory multisigs = new address[](numEvictServices);
    uint256[] memory inactivity = new uint256[](numEvictServices);
    uint256[] memory serviceIndexes = new uint256[](numEvictServices);

    uint256 sCounter;
    uint256 serviceId;
    for (uint256 i = 0; i < totalNumServices; ++i) {
        if (evictServiceIds[i] > 0) {
            serviceId = evictServiceIds[i];
            serviceIds[sCounter] = serviceId;

            ServiceInfo storage sInfo = mapServiceInfo[serviceId];
            owners[sCounter] = sInfo.owner;
            multisigs[sCounter] = sInfo.multisig;
            inactivity[sCounter] = serviceInactivity[i];
            serviceIndexes[sCounter] = i;
            sCounter++;
        }
    }

    for (uint256 i = numEvictServices; i > 0; --i) {
        totalNumServices--;
        uint256 idx = serviceIndexes[i - 1];
        setServiceIds[idx] = setServiceIds[totalNumServices];
        setServiceIds.pop();
    }

    emit ServicesEvicted(epochCounter, serviceIds, owners, multisigs, inactivity);
}

This approach typically involves maintaining state between calls and ensuring that a full loop can be broken into smaller parts. We introduce startIndex and endIndex to define the range of indices that each function call will process.
