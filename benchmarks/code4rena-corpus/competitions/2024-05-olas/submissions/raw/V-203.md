# Vulnerability details

## Impact
The current code checks if `eBond >= amount`, and if true, it proceeds to subtract `amount` from `eBond`. However, this condition should be a strict inequality `eBond > amount` to ensure that the subtraction doesn't result in an underflow.

If `eBond` is exactly equal to the `amount`, the subtraction `eBond -= amount` will result in `eBond` becoming zero. This violates the `postcondition` comment `old(effectiveBond) > amount ==> effectiveBond == old(effectiveBond) - amount`, which expects `effectiveBond` to be equal to `old(effectiveBond) - amount when old(effectiveBond) > amount`.

## Proof of Concept
1. **`Violation of Postcondition`**: The postcondition comment `old(effectiveBond) > amount ==> effectiveBond == old(effectiveBond) - amount` specifies the expected behavior of the function. It states that if `old(effectiveBond)` (the value of `effectiveBond` before the function execution) is greater than `amount`, then after the function execution, `effectiveBond` should be equal to `old(effectiveBond) - amount`.

However, with the current code, if `eBond` is exactly equal to `amount`, the subtraction `eBond -= amount` will result in `eBond` becoming zero. This violates the `postcondition because effectiveBond` will not be equal to `old(effectiveBond) - amount` in this case.

2. **`Underflow Vulnerability`**: When `eBond` is exactly equal to `amount`, the subtraction `eBond -= amount` will result in `eBond` becoming zero. This is an underflow vulnerability because the subtraction operation is not checked for underflow.

```solidity
/// @dev Reserves OLAS amount from the effective bond to be minted during a bond program.
/// @notice Programs exceeding the limit of the effective bond are not allowed.
/// @param amount Requested amount for the bond program.
/// @return success True if effective bond threshold is not reached.
/// #if_succeeds {:msg "effectiveBond"} old(effectiveBond) > amount ==> effectiveBond == old(effectiveBond) - amount;
function reserveAmountForBondProgram(uint256 amount) external returns (bool success) {
    // Check for the depository access
    if (depository != msg.sender) {
        revert ManagerOnly(msg.sender, depository);
    }

    // Effective bond must be bigger than the requested amount
    uint256 eBond = effectiveBond;
    if (eBond >= amount) {
        // The effective bond value is adjusted with the amount that is reserved for bonding
        // The unrealized part of the bonding amount will be returned when the bonding program is closed
        eBond -= amount;
        effectiveBond = uint96(eBond);
        success = true;
        emit EffectiveBondUpdated(epochCounter, eBond);
    }
}
```

## Recommended Mitigation Steps
Change the condition to a strict inequality
```solidity
if (eBond > amount) {
    // The effective bond value is adjusted with the amount that is reserved for bonding
    // The unrealized part of the bonding amount will be returned when the bonding program is closed
    eBond -= amount;
    effectiveBond = uint96(eBond);
    success = true;
    emit EffectiveBondUpdated(epochCounter, eBond);
}
```
By using `eBond > amount`, it ensures that the subtraction only happens when `eBond` is strictly greater than `amount`, avoiding the potential underflow and satisfying the postcondition.
