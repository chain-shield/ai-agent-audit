# Vulnerability details

In the `removeNominee` function there are inconsistencies between the `setNominees` array and the `mapNomineeIds` mapping. This inconsistency can cause incorrect behavior when retrieving nominees or their weights, as the mapping will point to the wrong nominee after the shift operation.

## Impact
The `mapNomineeIds` mapping is used to associate a nominee's hash (derived from their account and chain ID) with their corresponding ID in the `setNominees` array.
When a nominee is removed, the last nominee in the `setNominees` array is shifted to the position of the removed nominee, but the `mapNomineeIds` mapping is not updated for the shifted nominee.
This means that the `mapNomineeIds` mapping will still point to the old nominee hash for the shifted nominee's ID, even though the nominee at that position has changed.
As a result, any function that relies on the `mapNomineeIds` mapping to retrieve nominee information or weights will return incorrect data for the shifted nominee.
This can lead to various issues, such as incorrect weight calculations, voting power assignments, or other operations that depend on the accurate mapping between nominee hashes and IDs.

```solidity
function removeNominee(bytes32 account, uint256 chainId) external {
    // ...

    // Get the nominee id in the nominee set
    uint256 id = mapNomineeIds[nomineeHash];
    if (id == 0) {
        revert NomineeDoesNotExist(account, chainId);
    }

    // ...

    // Remove nominee from the map
    mapNomineeIds[nomineeHash] = 0;

    // Shuffle the current last nominee id in the set to be placed to the removed one
    nominee = setNominees[setNominees.length - 1];
    bytes32 replacedNomineeHash = keccak256(abi.encode(nominee));
    mapNomineeIds[replacedNomineeHash] = id; // <-- This line updates the mapping for the removed nominee
    setNominees[id] = nominee; // <-- This line shifts the last nominee to the position of the removed nominee
    // Pop the last element from the set
    setNominees.pop();

    // ...
}
```
The line `mapNomineeIds[replacedNomineeHash] = id;` updates the `mapNomineeIds` mapping for the removed nominee correctly.

However, the line `setNominees[id] = nominee;` shifts the last nominee in the `setNominees` array to the position of the removed nominee.

**`The problem is that there is no corresponding update to the `mapNomineeIds` mapping for the shifted nominee.`**

As a result, the `mapNomineeIds` mapping will still point to the old nominee hash for the ID of the shifted nominee, even though the nominee at that position has changed.

This inconsistency between the `setNominees` array and the `mapNomineeIds` mapping can lead to incorrect data being returned or processed when retrieving nominee information or weights using the `mapNomineeIds` mapping.

## Proof of Concept
Consider the following scenario

Initially, there are three nominees with the following details:

Nominee 1: `account = 0x1234...`, `chainId = 1, id = 1`
Nominee 2: `account = 0x5678...`, `chainId = 1, id = 2`
Nominee 3: `account = 0x9abc...`, `chainId = 1, id = 3`

The `mapNomineeIds` mapping correctly associates the nominee hashes with their respective IDs:

`mapNomineeIds[keccak256(abi.encode(Nominee(0x1234..., 1)))] = 1`
`mapNomineeIds[keccak256(abi.encode(Nominee(0x5678..., 1)))] = 2`
`mapNomineeIds[keccak256(abi.encode(Nominee(0x9abc..., 1)))] = 3`

Now, let's remove the nominee with ID `2` (account `0x5678...`).

The nominee with ID `3` (account `0x9abc...`) is shifted to the position of the removed nominee (ID `2`).
The `mapNomineeIds` mapping is updated correctly for the removed nominee (ID `2`):
`delete mapNomineeIds[keccak256(abi.encode(Nominee(0x5678..., 1)))]`

However, the `mapNomineeIds` mapping is not updated for the shifted nominee (ID `3`). It still points to the old nominee hash:
`mapNomineeIds[keccak256(abi.encode(Nominee(0x9abc..., 1)))] = 3`

Now, if you try to retrieve the nominee information or weight using the `getNominee` function with ID `3`, it will return the old nominee (account `0x9abc...`) instead of the shifted nominee (account `0x1234...`).

This inconsistency between the `setNominees` array and the `mapNomineeIds` mapping can lead to incorrect data being returned or processed, potentially causing issues in various parts of the system that rely on accurate nominee information and weight calculations.

## Recommended Mitigation Steps
We should update the `mapNomineeIds` mapping for the nominee that was shifted after removing a nominee.
```solidity
function removeNominee(bytes32 account, uint256 chainId) external {
    // ... (existing code)

    // Get the nominee id in the nominee set
    uint256 id = mapNomineeIds[nomineeHash];
    if (id == 0) {
        revert NomineeDoesNotExist(account, chainId);
    }

    // Remove the nominee from the set
    uint256 lastIndex = setNominees.length - 1;
    if (id != lastIndex) {
        // Shift the last nominee to the position of the removed nominee
        Nominee memory lastNominee = setNominees[lastIndex];
        setNominees[id] = lastNominee;

        // Update the mapNomineeIds mapping for the shifted nominee
        bytes32 lastNomineeHash = keccak256(abi.encode(lastNominee));
        mapNomineeIds[lastNomineeHash] = id;
    }

    // Remove the last nominee from the set
    setNominees.pop();

    // Update the mapNomineeIds mapping for the removed nominee
    delete mapNomineeIds[nomineeHash];

    // ... (existing code)
}
```
