# Vulnerability details

## Impact

Refunds will be lost.

## Proof of Concept

In both L1 and L2 WormholeDepositProcessor contracts, if the refundAccount is not set, set it to the `msg.sender`.

```
        // If refundAccount is zero, default to msg.sender
        if (refundAccount == address(0)) {
            refundAccount = msg.sender;
        }
```

In this case, the `msg.sender` is eith the Dispenser or the DefaultTargetDispenserL2 contract. The function assumes that the L1 and L2 addresses is the same, so that the refund can go to the same address, just on different chain.

However, that might not be the case as the same contract may have a different address on a different chain. 0x123 on L1 may be 0x456 on L2, which means that the `msg.sender` will be of a different address. 

## Tools Used

Manual Review

## Recommended Mitigation Steps

Best is to not assume that contracts on a different chain have the same address, and make sure `refundAccount` is always set by the caller. It will be ideal if the `refundAccount` is reverted if it is address(0), instead of being the msg.sender.
