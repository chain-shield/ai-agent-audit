# Vulnerability details

## Impact
If the `totalSum` variable is zero, the line `weight = 1e18 * nomineeWeight / totalSum;` will result in a division by zero, which is not allowed in Solidity. This will cause the transaction to revert, and any state changes or operations performed before the revert will also be reverted.

The code is: [_nomineeRelativeWeight#L432](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/governance/contracts/VoteWeighting.sol#L432)
```solidity
weight = 1e18 * nomineeWeight / totalSum;
```
This line is executed within the `_nomineeRelativeWeight` function, which is defined as.
```solidity
function _nomineeRelativeWeight(
    bytes32 account,
    uint256 chainId,
    uint256 time
) internal view returns (uint256 weight, uint256 totalSum) {
    uint256 t = time / WEEK * WEEK;
    totalSum = pointsSum[t].bias;

    Nominee memory nominee = Nominee(account, chainId);
    bytes32 nomineeHash = keccak256(abi.encode(nominee));

    if (totalSum > 0) {
        uint256 nomineeWeight = pointsWeight[nomineeHash][t].bias;
        weight = 1e18 * nomineeWeight / totalSum;
    }
}
```
If the `_nomineeRelativeWeight` function is called in a critical path of the contract's execution, the division by zero error can lead to unexpected behavior or failure of the contract's functionality.
Users or other contracts interacting with this contract may experience unexpected reverts, leading to a poor user experience or potential loss of funds (if the transaction involves transferring assets).
The contract may become unusable or enter an inconsistent state if the division by zero error occurs during a critical operation.

## Proof of Concept
Consider the following scenario:
Assume that the `pointsSum` mapping is empty or has a value of zero for the given t (time) value.
In this case, `totalSum` will be assigned a value of zero.
When the line `weight = 1e18 * nomineeWeight / totalSum;` is executed, it will attempt to divide by zero, which is not allowed in Solidity.
This will cause the transaction to revert, and any state changes or operations performed before the revert will be reverted as well.

## Recommended Mitigation Steps
Check to ensure that `totalSum` is not zero before performing the division.
```solidity
if (totalSum > 0) {
    uint256 nomineeWeight = pointsWeight[nomineeHash][t].bias;
    weight = (1e18 * nomineeWeight) / totalSum;
} else {
    weight = 0;
}
```
By adding an `else` block and setting `weight` to zero when `totalSum` is zero can prevent the division by zero error and handle the edge case correctly.
