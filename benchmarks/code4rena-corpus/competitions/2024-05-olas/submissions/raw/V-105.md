# Vulnerability details

## Impact
In the `verifyInstanceAndGetEmissionsAmount`, if the `verifyInstance` call returns `false`, indicating that the instance verification failed, the function still proceeds to retrieve the emissions amount using `IStaking(instance).emissionsAmount()`. This is problematic because if the instance is not verified, calling `emissionsAmount()` on an invalid instance address could lead to unexpected behavior or even revert the transaction.

## Proof of Concept
If the `instance` address is not a valid staking contract or does not implement the `IStaking` interface correctly, calling `emissionsAmount()` on it may return an arbitrary value or even revert the transaction.

Code snippet that illustrates the issue is as follows: [@StakingFactory.sol:294-310](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingFactory.sol#L294-L310)
```solidity
function verifyInstanceAndGetEmissionsAmount(address instance) external view returns (uint256 amount) {
    // Verify the proxy instance
    bool success = verifyInstance(instance);

    if (success) {
        // Get the proxy instance emissions amount
        amount = IStaking(instance).emissionsAmount();

        // If there is a verifier, adjust the amount
        address localVerifier = verifier;
        if (localVerifier != address(0)) {
            // Get the max possible emissions amount
            uint256 maxEmissions = IStakingVerifier(localVerifier).getEmissionsAmountLimit(instance);
            // Limit excessive emissions amount
            if (amount > maxEmissions) {
                amount = maxEmissions;
            }
        }
    }
}
```
As you can see, even if `success` is `false`, the function continues to execute the emissions amount retrieval and adjustment logic using the unverified `instance` address.

Example: Let's consider an example to illustrate the potential issue:

  1. Suppose an attacker calls the `verifyInstanceAndGetEmissionsAmount` function with an invalid `instance` address that does not correspond to a valid staking contract.

  2. The `verifyInstance` returns `false`, indicating that the instance verification failed.

  3. However, the function proceeds to call `IStaking(instance).emissionsAmount()` on the invalid `instance` address.

  4. If the `instance` address is a malicious contract, it could execute arbitrary code or return a manipulated emissions amount.

  5. The function continues with the emissions amount adjustment logic using the potentially manipulated value.

## Recommended Mitigation Steps
Add an early return statement or wrap the emissions amount retrieval logic inside an `if` block that only executes when `success` is `true`.
```solidity

            // Get the max possible emissions amount

            // Limit excessive emissions amount
            if (amount > maxEmissions) {
                amount = maxEmissions;
            }
        }
    } else {
        // Return 0 or revert if the instance verification fails
        // amount = 0; // or

    }
}
```
