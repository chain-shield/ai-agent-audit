# Vulnerability details

## Impact
In the loop that iterates over the epochs from `firstClaimedEpoch` to `lastClaimedEpoch`, the `totalReturnAmount` is calculated by multiplying `stakingPoint.stakingIncentive` with `stakingWeight`. However, `stakingWeight` is obtained from the `nomineeRelativeWeight` function of the `IVoteWeighting` contract, which likely returns a value with 18 decimal places (assuming it follows the common convention in Ethereum).

When `totalReturnAmount` is divided by `1e18` after the loop. This division is intended to remove the extra 18 decimal places, but it is done only once at the end of the loop. As a result, if there are multiple iterations in the loop, the `totalReturnAmount` will accumulate values with 18 decimal places in each iteration, leading to an incorrect final value.

## Proof of Concept
- Let's assume there are 3 epochs to iterate over, with the following values.
   - Epoch 1: `stakingPoint.stakingIncentive = 100`, `stakingWeight = 1e18`
   - Epoch 2: `stakingPoint.stakingIncentive = 200`, `stakingWeight = 1.5e18`
   - Epoch 3: `stakingPoint.stakingIncentive = 300`, `stakingWeight = 2e18`

- With the current implementation, the `totalReturnAmount` calculation would be.
   - Epoch 1: `totalReturnAmount = 100 * 1e18 = 100e18`
   - Epoch 2: `totalReturnAmount = 100e18 + 200 * 1.5e18 = 400e18`
   - Epoch 3: `totalReturnAmount = 400e18 + 300 * 2e18 = 1000e18`

- After the loop, `totalReturnAmount` is divided by `1e18`, resulting in `1000`.
-  However, the correct calculation should be:
   - Epoch 1: `totalReturnAmount = (100 * 1e18) / 1e18 = 100`
   - Epoch 2: `totalReturnAmount = 100 + (200 * 1.5e18) / 1e18 = 400`
   - Epoch 3: `totalReturnAmount = 400 + (300 * 2e18) / 1e18 = 1000`

The correct `totalReturnAmount` should be `1000`, but the current implementation yields `1000e18`, which is a significantly inflated value.

The affected code snippet: [tokenomics/contracts/Dispenser.sol#L1146-1159](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L1146-L1159)
```solidity
for (uint256 j = firstClaimedEpoch; j < lastClaimedEpoch; ++j) {
    // ...
    totalReturnAmount += stakingPoint.stakingIncentive * stakingWeight;
}
totalReturnAmount /= 1e18;
```
**`The corrected code should be`**
```solidity
for (uint256 j = firstClaimedEpoch; j < lastClaimedEpoch; ++j) {
    // ...
    totalReturnAmount += (stakingPoint.stakingIncentive * stakingWeight) / 1e18;
}
```

## Recommended Mitigation Steps
The division by `1e18` should be done within the loop for each iteration.
```solidity
for (uint256 j = firstClaimedEpoch; j < lastClaimedEpoch; ++j) {
    // ...

    (uint256 stakingWeight, ) = IVoteWeighting(voteWeighting).nomineeRelativeWeight(retainer,
        block.chainid, endTime);

    totalReturnAmount += (stakingPoint.stakingIncentive * stakingWeight) / 1e18;
}
```
By dividing `(stakingPoint.stakingIncentive * stakingWeight)` by `1e18` within the loop, the `totalReturnAmount` will be correctly accumulated with the intended decimal places.

It's important to note that this assumes `stakingPoint.stakingIncentive` and `stakingWeight` are both `uint256` values with 18 decimal places. If they have different decimal places, the calculation may need to be adjusted accordingly.
