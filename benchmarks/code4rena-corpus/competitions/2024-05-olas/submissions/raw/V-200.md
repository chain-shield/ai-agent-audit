# Vulnerability details

## Impact
When an invalid value is passed for `_devsPerCapital`, `_codePerDev`, `_epsilonRate`, `_epochLen`, or `_veOLASThreshold`, the function assigns the corresponding parameter to its existing value instead of the invalid value. However, this assignment is done using the input parameter name, which doesn't update the contract state variable.

For example, if an invalid value is passed for `_devsPerCapital`, the function executes the following line: [tokenomics/contracts/Dispenser.sol#L656](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Tokenomics.sol#L656)
```solidity
_devsPerCapital = devsPerCapital;
```
This line assigns the current value of `devsPerCapital` to the input parameter `_devsPerCapital`, but it doesn't update the contract state variable `devsPerCapital`.

The same issue occurs for `_codePerDev`, `_epsilonRate`, `_epochLen`, and `_veOLASThreshold`.

## Proof of Concept
When invalid values are passed to the [changeTokenomicsParameters](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Tokenomics.sol#L639) function, the function fails to properly handle these cases and update the contract state variables as intended. This can lead to unexpected behavior and inconsistencies in the contract's state.

## Recommended Mitigation Steps
Update the assignments to use the contract state variables instead of the input parameters when the input values are invalid. For example:
```solidity
// Update this line
_devsPerCapital = devsPerCapital;
// to
devsPerCapital = devsPerCapital;
```
Make similar changes for `_codePerDev`, `_epsilonRate`, `_epochLen`, and `_veOLASThreshold`.
