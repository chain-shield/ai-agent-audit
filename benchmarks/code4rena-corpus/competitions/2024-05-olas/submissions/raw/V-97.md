# Vulnerability details

In the `VoteWeighting` contract, I found a potential issue related to integer overflows in the `_addToChanges` function. The function calculates the new weight by adding the provided slope, but it does not validate whether the result will cause an overflow.

Here's the relevant part of the code:

```solidity
function _addToChanges(NomineeStorage storage self, uint256 _time, uint256 _slope) internal {
    changesWeight[self][_time] += _slope;
    changesSum[_time] += _slope;
}
```

This function can cause an integer overflow if `changesWeight[self][_time]` or `changesSum[_time]` plus the provided slope is bigger than the maximum value for `uint256`. Overflow can lead to unpredictable behavior in the contract, potentially allowing attackers to manipulate the system.

To mitigate this issue, you should add checks to prevent overflows. You can use the `SafeMath` library from OpenZeppelin to ensure safe arithmetic operations and prevent overflows.

Here's the modified `_addToChanges` function using the `SafeMath` library:

```solidity
using SafeMath for uint256;

function _addToChanges(NomineeStorage storage self, uint256 _time, uint256 _slope) internal {
    uint256 currentWeight = changesWeight[self][_time];
    require(currentWeight.add(_slope) <= uint256(-1), "Integer overflow in '_addToChanges'");
    changesWeight[self][_time] = currentWeight.add(_slope);

    uint256 currentSum = changesSum[_time];
    require(currentSum.add(_slope) <= uint256(-1), "Integer overflow in '_addToChanges'");
    changesSum[_time] = currentSum.add(_slope);
}
```

Using the `SafeMath` library ensures that arithmetic operations cannot cause overflows, preventing unpredictable behavior and ensuring that the contract works as intended.
