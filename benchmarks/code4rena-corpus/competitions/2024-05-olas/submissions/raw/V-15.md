# Vulnerability details

## Impact
Detailed description of the impact of this finding.
The lack of a modifier on the `receiveWormholeMessages` function means that there are no checks on who can call this function. In a real-world scenario, this could lead to unauthorised message processing if the function is meant to be restricted to certain addresses or conditions.

## Recommended Mitigation Steps
Implement access control checks to restrict who can call the `receiveWormholeMessages` function. This could be achieved by using modifiers such as `onlyOwner` or custom modifiers that check for specific conditions.
- **Validation**: Consider adding validation logic within the function to verify the integrity and authenticity of the message before processing it.
- **Error Handling**: Introduce error handling mechanisms to provide more informative feedback and to prevent unauthorised or malformed messages from being processed.
- **Audit Trail**: Maintain an audit trail by logging additional information, such as the timestamp and the transaction hash, when messages are received.
