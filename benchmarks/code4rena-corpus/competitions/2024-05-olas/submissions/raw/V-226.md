# Vulnerability details

## Description
There is a rounding error in the `nextTime` calculation due to dividing before multiplying by `WEEK`:
```solidity
uint256 nextTime = (block.timestamp + WEEK) / WEEK * WEEK;
```

The calculation of `nextTime` using integer division rounds down the result. When `block.timestamp + WEEK` is divided by `WEEK` before multiplying by `WEEK`, it causes the intermediate division result to round down, leading to an incorrect `nextTime`.
## Impact
- The incorrect `nextTime` value results in an inaccurate lock period.
- Users may vote after their lock period has expired, compromising the integrity of the voting system.
## Proof of Concept
Assuming:
- `block.timestamp = NOW`
- `WEEK = 86400 * 7` (one week in seconds)

Given:
- `NOW = 1622520000` (an example timestamp)
- `WEEK = 604800` seconds

Current calculation:
`uint256 nextTime = (1622520000 + 604800) / 604800 * 604800; // nextTime = 1623124800 / 604800 * 604800 = 2681 * 604800 = 1622524800`

Expected `nextTime`:
`1622520000 + 604800 = 1623124800`

The error is `1623124800 - 1622524800 = 4800` seconds (1 hour 20 minutes).

## Tools Used
Manual review
## Recommended Mitigation Steps
Change the calculation to multiply by `WEEK` first, then divide by `WEEK`:
uint256 nextTime = (block.timestamp + WEEK) * WEEK / WEEK;
