# Vulnerability details

## Impact
redeem will fail when there are the same hashes.

## Proof of Concept
In the function `_processData`, when there are same targets and amounts, the calculated queueHash will be the same. Therefore, in the redeem, it will fail in the second time.

## Tools Used
VScode

## Recommended Mitigation Steps
Change stakingQueueingNonces to mapping(byte32 => uint8) type to record the counts.
```solidity
// Hash of target + amount + batchNonce
bytes32 queueHash = keccak256(abi.encode(target, amount, batchNonce));
// Queue the hash for further redeem
stakingQueueingNonces[queueHash] += 1;
```
