# Vulnerability details

## Impact

The StakingFactory contract uses a simple boolean flag (_locked) to provide reentrancy protection around the createStakingInstance function. 

 However, this guard is flawed because it only checks if _locked > 1 to prevent reentrancy in the createStakingInstance function.

If two re-entrant calls were made simultaneously, the guard will allow them to proceed because _locked equals 2 after the guard is locked, permitting any number of reentrant calls until the function finishes executing. 

This can lead to unpredictable behavior that can be exploited to drain funds.


## Proof of Concept
```solidity
    function createStakingInstance(
        address implementation,
        bytes memory initPayload
    ) external returns (address payable instance) {
        // Reentrancy guard
        if (_locked > 1) {
            revert ReentrancyGuard();
        }
        _locked = 2;
        ...
        _locked = 1;
    }
```
In this block, if a failure happens after `_locked` is set to 2 and before it is set back to 1, the contract will remain in the locked state.

## Recommended Mitigation Steps

Use the reentrancy guard supplied in OpenZeppelin's SafeGuard contract instead.
It offers a more secure mechanism against reentrancy attacks by distinguishing between different types of calls, and ensures that the locked state is not maintained after a function fails.
