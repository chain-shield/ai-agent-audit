# Vulnerability details

## Impact
When claiming the message on the destination layer, if the message failed to execute with various reasons (e.g. wrong target contract address, wrong contract logic, out of gas, malicious contract), the Ether sent with sendMessage on the original layer will be stuck.

## Proof of Concept
However, the     function _sendMessage() checks for 0 value, but it doesn't provide an avenue for refund to users, if message claim failed on the destination layer.

https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/tokenomics/contracts/staking/GnosisDepositProcessorL1.sol#L80-L81

Unlike on the ArbitrumDepositProcessorL1.sendMessage(), it checks for the refund address.
