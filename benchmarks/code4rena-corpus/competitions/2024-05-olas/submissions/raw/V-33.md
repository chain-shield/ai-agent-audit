# Vulnerability details

## Impact
`setFxChildTunnel` function allows the owner to set the `fxChildTunnel` address, which is intended to be the L2 target dispenser address. However, it does not update the `l2TargetDispenser` variable, which is used in the `_processMessageFromChild` function to process messages received from the L2 Child Tunnel. This inconsistency can lead to a situation where the `fxChildTunnel` address is updated, but the `l2TargetDispenser` still points to the old address. As a result, messages received from the L2 Child Tunnel may not be processed correctly.

## Proof of Concept
The inconsistency between the `fxChildTunnel` and `l2TargetDispenser` variables can lead to a critical issue in the communication between the L1 and L2 contracts. When the owner updates the `fxChildTunnel` address using the `setFxChildTunnel` function, it is expected that the new address will be used for processing messages received from the L2 Child Tunnel. However, since the `l2TargetDispenser` variable is not updated accordingly, the contract will continue to use the old address for processing messages.

This means that any messages sent from the updated L2 Child Tunnel will not be processed correctly by the L1 contract. The `_processMessageFromChild` function, which is responsible for handling messages from L2, uses the `l2TargetDispenser` variable to determine the target address for processing the received data. If `l2TargetDispenser` points to an outdated or incorrect address, the messages will be sent to the wrong contract or not processed at all.

   2. The `fxChildTunnel` variable is updated to the new address, but the `l2TargetDispenser` variable remains unchanged, still pointing to the old address.
   3. The L2 Child Tunnel sends a message to the L1 contract using the new `fxChildTunnel` address.
   4. The `_processMessageFromChild` function is called to handle the received message.
   5. Inside `_processMessageFromChild`, the `_receiveMessage` function is called with the `l2TargetDispense`r variable as the target address.
   6. Since `l2TargetDispenser` still points to the old address, the message is sent to the wrong contract or not processed at all, leading to unexpected behavior or failure in the communication between L1 and L2.

## Recommended Mitigation Steps
Consider updating the l2TargetDispenser variable along with `fxChildTunnel` in the `setFxChildTunnel` function. By updating `l2TargetDispenser` along with `fxChildTunnel` ensures that the correct L2 target dispenser address is used when processing messages from the L2 Child Tunnel.
```solidity
function setFxChildTunnel(address l2Dispenser) public override {
    // Check for the ownership
    if (msg.sender != owner) {
        revert OwnerOnly(msg.sender, owner);
    }

    // Check for zero address
    if (l2Dispenser == address(0)) {
        revert ZeroAddress();
    }

    // Set L1 deposit processor address
    fxChildTunnel = l2Dispenser;

    // Update l2TargetDispenser to match fxChildTunnel
    l2TargetDispenser = l2Dispenser;

    emit FxChildTunnelUpdated(l2Dispenser);
}
```
