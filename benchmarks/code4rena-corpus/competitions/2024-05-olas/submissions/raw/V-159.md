# Vulnerability details

## Impact
The vulnerability in the stake function, which allows evicted services to bypass the intended inactivity penalties, has several significant impacts on the staking system. The staking system is designed to reward active and compliant services while penalizing inactive ones. This vulnerability allows services to continuously receive rewards without maintaining the required activity level.

By enabling evicted services to stake again without serving their penalty period, the rewards pool gets diluted. This reduction negatively impacts other compliant services.

## Proof of Concept

The staking contract is designed to reward services that remain active and compliant. However, the service attempts to stake again without addressing the inactivity. Since there’s no eviction check in the stake function, it passes the current checks.

A service is marked as evicted if it remains inactive for a period longer than maxInactivityDuration.


However, it was written/ stated that there should be a check for [evicted service that has not been unstaked](https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/registries/contracts/staking/StakingBase.sol#L725) in which the evicted services are intended to serve a penalty period during which they are not eligible for rewards. Allowing restaking without checking the eviction status undermines this penalty mechanism.


The contract maintains various states [(e.g., Staked, Unstaked, Evicted)](https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/registries/contracts/staking/StakingBase.sol#L31C3-L38C6). Without proper eviction checks, the state management becomes inconsistent.

## Recommended Mitigation Steps
Add a check for inactivity in the stake function to ensure evicted services cannot stake again without serving their penalty.

```
 function stake(uint256 serviceId) external {
        // Check if there available rewards
        if (availableRewards == 0) {
            revert NoRewardsAvailable();
        }

        // Check if the evicted service has not yet unstaked
        ServiceInfo storage sInfo = mapServiceInfo[serviceId];
        // tsStart being greater than zero means that the service was not yet unstaked: still staking or evicted

+++++      // Check if the service has been evicted due to inactivity
    if (sInfo.inactivity > maxInactivityDuration) {
        revert("Service is evicted due to inactivity");
    }

        if (sInfo.tsStart > 0) {
            revert ServiceNotUnstaked(serviceId);
        }
```
Where ```maxInactivityDuration``` is calculated as maxInactivityDuration = maxNumInactivityPeriods * livenessPeriod
