# Vulnerability details

## Impact
When the `serviceId` is not found in the `eligibleServiceIds` array, In this case, the loop will complete without setting the reward variable, and the function will return the default value of `reward`, which is 0.
This means that if the `serviceId` is not eligible for rewards, the function will still return 0 instead of indicating that no reward is available for that service.

If a caller of the function provides a `serviceId` that is not eligible for rewards, the function will return 0, falsely indicating that the service has no reward available. This can cause confusion and incorrect assumptions about the staking rewards for that particular service.

In a scenario where a user or another contract relies on the returned value of `calculateStakingLastReward` to make decisions or perform further actions, the incorrect return value of 0 can lead to unintended consequences. For example, if a user expects a reward for a service but receives 0 due to this bug, they may mistakenly believe that the service has no rewards, leading to confusion and potential dissatisfaction.

The bug occurs in the `calculateStakingLastReward` function [@StakingBase.calculateStakingLastReward:888-911](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L888-L911)
```solidity
function calculateStakingLastReward(uint256 serviceId) public view returns (uint256 reward) {
    // Calculate overall staking rewards
    (uint256 lastAvailableRewards, uint256 numServices, uint256 totalRewards, uint256[] memory eligibleServiceIds,
        uint256[] memory eligibleServiceRewards, , , ) = _calculateStakingRewards();

    // If there are eligible services, proceed with staking calculation and update rewards for the service Id
    for (uint256 i = 0; i < numServices; ++i) {
        // Get the service index in the eligible service set and calculate its latest reward
        if (eligibleServiceIds[i] == serviceId) {
            // If total allocated rewards are not enough, adjust the reward value
            if (totalRewards > lastAvailableRewards) {
                reward = (eligibleServiceRewards[i] * lastAvailableRewards) / totalRewards;
            } else {
                reward = eligibleServiceRewards[i];
            }
            break;
        }
    }
    // BUG: The function will return 0 if the serviceId is not found in the eligibleServiceIds array
    // It should revert or return a special value to indicate that the service is not eligible for rewards
}
```
The bug lies in the fact that if the `serviceId` is not found in the `eligibleServiceIds` array, the loop will complete without setting the reward variable. As a result, the function will return the default value of reward, which is 0.

The buggy behavior occurs in lines 900-910, where the loop iterates over the `eligibleServiceIds` array to find a match for the given `serviceId`. If no match is found, the loop completes without any explicit handling of the case when the service is not eligible for rewards.

## Proof of Concept
A scenario where the` eligibleServiceIds` array does not contain the `serviceId` passed to the `calculateStakingLastReward` function.

Suppose we have the following state:

  - `eligibleServiceIds` = [1, 2, 3]
  - `eligibleServiceRewards` = [100, 200, 300]
  - `lastAvailableRewards` = 1000
  - `totalRewards` = 600

If we call `calculateStakingLastReward(4)`, the function will iterate through the `eligibleServiceIds` array but will not find a match for `serviceId = 4`. As a result, the loop will complete without setting the reward variable, and the function will return the default value of reward, which is 0.

However, the expected behavior in this case should be to indicate that the service with ID 4 is not eligible for rewards, rather than returning 0.

## Recommended Mitigation Steps
Return a special value or revert with an error message when the `serviceId` is not found in the eligible services. 
```solidity
function calculateStakingLastReward(uint256 serviceId) public view returns (uint256 reward) {
    // Calculate overall staking rewards
    (uint256 lastAvailableRewards, uint256 numServices, uint256 totalRewards, uint256[] memory eligibleServiceIds,
        uint256[] memory eligibleServiceRewards, , , ) = _calculateStakingRewards();

    // If there are eligible services, proceed with staking calculation and update rewards for the service Id
    for (uint256 i = 0; i < numServices; ++i) {
        // Get the service index in the eligible service set and calculate its latest reward
        if (eligibleServiceIds[i] == serviceId) {
            // If total allocated rewards are not enough, adjust the reward value
            if (totalRewards > lastAvailableRewards) {
                reward = (eligibleServiceRewards[i] * lastAvailableRewards) / totalRewards;
            } else {
                reward = eligibleServiceRewards[i];
            }
            return reward;
        }
    }

    // If the serviceId is not found in the eligible services, revert with an error message
    revert("Service is not eligible for rewards");
}
```
If the `serviceId` is found in the eligible services, the function calculates and returns the reward as before. However, if the loop completes without finding the `serviceId`, the function will revert with an error message indicating that the service is not eligible for rewards. This way, the function handles the case when the `serviceId` is not eligible, and it prevents returning a misleading zero reward value.
