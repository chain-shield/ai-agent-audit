# Vulnerability details

## Impact
The case when `sInfo.tsStart` is 0 and `sInfo.inactivity` is less than or equal to `maxInactivityDuration`. In this code, the `getStakingState` function retrieves the `ServiceInfo` for a given `serviceId` from the `mapServiceInfo` mapping. It then checks two conditions:

1. If `sInfo.inactivity` is greater than `maxInactivityDuration`, the service is considered evicted, and `stakingState` is set to `StakingState.Evicted`.
2. If `sInfo.tsStart` is greater than 0, the service is considered staked, and `stakingState` is set to `StakingState.Staked`.

However, if both conditions are not met (i.e., `sInfo.tsStart` is 0 and `sInfo.inactivity` is less than or equal to `maxInactivityDuration`), the function does not explicitly set the `stakingState`. As a result, the default value of `StakingState.Unstaked` is returned. [StakingBase.sol:928-935](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L928-L935)
```solidity
/// @dev Gets the service staking state.
/// @param serviceId.
/// @return stakingState Staking state of the service.
function getStakingState(uint256 serviceId) external view returns (StakingState stakingState) {
    ServiceInfo memory sInfo = mapServiceInfo[serviceId];
    if (sInfo.inactivity > maxInactivityDuration) {
        stakingState = StakingState.Evicted;
    } else if (sInfo.tsStart > 0) {
        stakingState = StakingState.Staked;
    }
    // Bug: Missing else clause to handle the case when sInfo.tsStart is 0 and sInfo.inactivity is less than or equal to maxInactivityDuration
}
```
The buggy code is missing an `else` clause to handle the case when `sInfo.tsStart` is 0 and `sInfo.inactivity` is less than or equal to `maxInactivityDuration`. Without the `else` clause, the function will return the default value of `StakingState.Unstaked` (assuming it is defined as the first enum value) for this case, even though the service might be in a different state.

## Proof of Concept
Assuming if we set a service info using `setServiceInfo(1, 0, 50)`, where `tsStart` is 0 and `inactivity` is 50 (which is less than `maxInactivityDuration)`, and then call `getStakingState(1)`, it will return `StakingState.Unstaked` even though the service is not explicitly unstaked.
```solidity
enum StakingState { Unstaked, Staked, Evicted }

struct ServiceInfo {
    uint256 tsStart;
    uint256 inactivity;
}

mapping(uint256 => ServiceInfo) public mapServiceInfo;
uint256 public maxInactivityDuration = 100;

function setServiceInfo(uint256 serviceId, uint256 tsStart, uint256 inactivity) external {
    mapServiceInfo[serviceId] = ServiceInfo(tsStart, inactivity);
}

function getStakingState(uint256 serviceId) external view returns (StakingState stakingState) {
    ServiceInfo memory sInfo = mapServiceInfo[serviceId];
    if (sInfo.inactivity > maxInactivityDuration) {
        stakingState = StakingState.Evicted;
    } else if (sInfo.tsStart > 0) {
        stakingState = StakingState.Staked;
    }
}
```

## Recommended Mitigation Steps
An else clause should be added to explicitly set the `stakingState` to `StakingState.Unstaked` when the service is neither evicted nor staked.
```solidity
/// @dev Gets the service staking state.
/// @param serviceId.
/// @return stakingState Staking state of the service.
function getStakingState(uint256 serviceId) external view returns (StakingState stakingState) {
    ServiceInfo memory sInfo = mapServiceInfo[serviceId];
    if (sInfo.inactivity > maxInactivityDuration) {
        stakingState = StakingState.Evicted;
    } else if (sInfo.tsStart > 0) {
        stakingState = StakingState.Staked;
    } else {
        stakingState = StakingState.Unstaked;
    }
}
```
