When a service is being evicted due to an extended period of inactivity, their `serviceId` is removed from `setServiceIds` by overwriting it with the last one in the queue and poping the last element.

The issue occurs due to the fact that `serviceIndexes` used in the function will point to the `i` itteration counter which is equal to the number of total services, rather than the actual `serviceId` linked to the inactive service which should be retrieved from:
```solidity
            if (evictServiceIds[i] > 0) {services that need to be evicted
>               serviceId = evictServiceIds[i];
>               serviceIds[sCounter] = serviceId;
```
This leads to the line
```solidity
uint256 idx = serviceIndexes[i - 1];
```
Being equal to `i` from the previous loop (instead of `evictServiceIds[i]`/`serviceId`), which is only a counter for the length of `evictServiceIds`/ `setServiceIds`:
```solidity
uint256 totalNumServices = evictServiceIds.length;
```

This will lead to the wrong service from being overwritten, which may be active and currently performing honest work for the protocol.

```diff

            if (evictServiceIds[i] > 0) {
```
