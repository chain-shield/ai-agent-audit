# Vulnerability details

Report:

## Impact

Reentrancy vulnerabilities can lead to attackers manipulating the contract state, which, in this case, may allow them to change the voting power of specific users maliciously.

## Proof of Concept

In the `revokeRemovedNomineeVotingPower` function, there is no protection against reentrancy. An attacker can repeatedly call the function, updating the voting power in an unintended manner.

## Proposed Mitigation

To fix the reentrancy vulnerability, you can apply the Checks-Effects-Interactions pattern or implement a reentrancy guard.

### Checks-Effects-Interactions Pattern

Move the `voteUserPower[msg.sender] = powerUsed;` line before the `delete voteUserSlopes[msg.sender][nomineeHash];` line to ensure that the voting power is updated before any possible reentrancy attempt.

### Reentrancy Guard

Implement a reentrancy guard by using a boolean variable (`reentrancyLock` in the example above) to prevent the function from executing twice simultaneously. By setting the lock to true at the beginning of the function and setting it back to false after executing the logic, you ensure that the function can only be executed once at a time, thereby eliminating the reentrancy risk.

By implementing the proposed mitigation, you can prevent attackers from exploiting the reentrancy vulnerability and manipulating the contract's state.
