# Vulnerability details

## Impact
For `getOwnerIncentives` function, the calculation of `topUp` within the loop is a problem: [@>accountOwnerIncentives#L1449](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Tokenomics.sol#L1449)
```solidity
uint256 sumUnitIncentives = uint256(mapEpochTokenomics[lastEpoch].unitPoints[unitTypes[i]].sumUnitTopUpsOLAS) * 100;
```
The `sumUnitIncentives` variable is calculated by multiplying `sumUnitTopUpsOLAS` by 100. Nevertheless, this multiplication can lead to an overflow if the value of `sumUnitTopUpsOLAS` is large enough.

## Proof of Concept
If an overflow occurs, the calculated value of `sumUnitIncentives` will be incorrect. This can lead to incorrect calculation of the `topUp` amount in the subsequent line: [@>accountOwnerIncentives#L1451](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Tokenomics.sol#L1451)
```solidity
topUp += totalIncentives / sumUnitIncentives;
```
As a result, the `topUp` amount will be calculated based on an incorrect value, leading to incorrect incentive distribution. If the `topUp` amount is calculated incorrectly due to an overflow, it can result in financial loss for the users or the contract owner. Users may receive incorrect incentives, and the contract owner may distribute more or fewer tokens than intended.

_Suppose `sumUnitTopUpsOLAS` has a value of `2^256 - 1` (the maximum value for a uint256). When multiplied by 100, the result would be:_
```solidity
(2^256 - 1) * 100 = 2^256 * 100 - 100
```
However, since `uint256` can only represent values up to `2^256 - 1`, the result would overflow and wrap around to a smaller number. This smaller number would be used in the subsequent calculation of `topUp`, leading to incorrect incentive distribution.

## Recommended Mitigation Steps
It's best to modify the calculation to avoid the multiplication and instead divide `totalIncentives` by `sumUnitTopUpsOLAS` first before multiplying by 100. By dividing `totalIncentives` by `sumUnitTopUpsOLAS` first, it ensure that the division is performed before the multiplication, reducing the risk of an overflow.
```solidity
uint256 topUpAmount = totalIncentives / mapEpochTokenomics[lastEpoch].unitPoints[unitTypes[i]].sumUnitTopUpsOLAS;
topUp += topUpAmount * 100;
```
Additionally, the function assumes that `mapEpochTokenomics[lastEpoch].unitPoints[unitTypes[i]].sumUnitTopUpsOLAS` is always greater than zero. If there's a possibility that it could be zero, we should add a check to avoid a division by zero error.
```solidity
uint256 sumUnitTopUpsOLAS = mapEpochTokenomics[lastEpoch].unitPoints[unitTypes[i]].sumUnitTopUpsOLAS;
if (sumUnitTopUpsOLAS > 0) {
    uint256 topUpAmount = totalIncentives / sumUnitTopUpsOLAS;
    topUp += topUpAmount * 100;
}
```
