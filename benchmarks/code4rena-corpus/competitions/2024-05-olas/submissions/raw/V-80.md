# Vulnerability details

### Vulnerability Report: Reentrancy and Withheld Amount Exploitation in `Dispenser.sol`

#### Summary
This vulnerability arises from the handling of the `withheldAmount` variable within the `claimStakingIncentives` and `claimStakingIncentivesBatch` functions. The insufficient depletion and lack of proper authorization checks can be exploited, allowing an attacker to repeatedly claim incentives, potentially leading to a rug pull scenario. Please take care that `claimStakingIncentivesBatch` contains many nested loops in the functions that it invokes. The withheld amount is depleted accordingly before control is returned back to `claimStakingIncentivesBatch`. Simply depleting some of the withheld amount does not translate to the depletion of the entire withheld amount. Thus the concern is whilst there is any withheld amount given that `incentives[]` is pretty much a constant and provided there is ease of accessibility toward the contract. Please take care that solidity automatically generates getter functions for public state variables where those variables allow the attacker to easily bypass any of the contract checks. some of this public variables are inherited from OpenZeppelin. Numerous private variables and functions are made either public or external implicitly so due to the lack of auth within the externally invoked invoking functions. We wish to turn some attention to how `totalStakingIncentive` in `function calculateStakingIncentives` represents `stakingIncentive` in `function claimStakingIncentives`. Thus `stakingPoint.stakingIncentive` can be followed all the way to `ITokenomics.StakingPoint memory stakingPoint =
                ITokenomics(tokenomics).mapEpochStakingPoints(j);` `mapEpochStakingPoints[eCounter].stakingIncentive = uint96(incentives[8]);`

#### Vulnerability Details

**Functions**: `claimStakingIncentives`, `claimStakingIncentivesBatch`

**Key Points of Exploitation**:

1. **Withheld Amount Variable**:
   - The `withheldAmount` variable is used to track amounts that are temporarily withheld.
   - In the `claimStakingIncentives` function, `withheldAmount` is decremented by `transferAmount` but is not always fully depleted.
   - An attacker can manipulate `withheldAmount` while it is remaining at a high value, allowing for repeated incentive claims.

2. **Lack of Authorization Checks**:
   - The functions do not have sufficient authorization checks, allowing any user to call these functions and potentially exploit the system.
   - This lack of restriction can enable unauthorized users to manipulate the incentives system.

3. **Reentrancy Risk**:
   - The functions include a reentrancy guard (`_locked`), but the implementation might not be robust enough to prevent reentrant calls effectively.
   - If `_locked` is not properly managed, it could lead to reentrancy attacks where the function is called multiple times before the state is updated, leading to unauthorized fund transfers.

4. **Publicly Accessible State Variables**:
   - Key state variables like `withheldAmount`, `incentives[]`, and other mapping structures (`mapChainIdWithheldAmounts`, `mapChainIdDepositProcessors`) are publicly accessible or can be inferred through other public functions.
   - Attackers can monitor and exploit these variables to predict or manipulate incentive claims.

5. **Incentives Array**:
   - The `incentives[]` array is crucial for tracking and distributing staking incentives.
   - It is accessed and modified within the `claimStakingIncentives` and `claimStakingIncentivesBatch` functions.
   - Improper handling or depletion of this array can lead to an infinite distribution of incentives, further facilitating exploitation.

#### Steps to Reproduce the Vulnerability

1. **Deploy the Contract**:
   - Deploy the `Dispenser` contract with necessary dependencies and initial configurations.

2. **Set a High `withheldAmount`**:
   - Manually set a high value for the `withheldAmount` associated with a specific `chainId` using the `mapChainIdWithheldAmounts` mapping.

3. **Repeatedly Call `claimStakingIncentives`**:
   - Call the `claimStakingIncentives` function repeatedly with crafted parameters to exploit the high `withheldAmount`.

4. **Monitor the Incentives**:
   - Observe the incorrect incentive claims and unauthorized transfers occurring due to the manipulation of `withheldAmount`.

#### Recommendations

1. **Implement Robust Reentrancy Guard**:
   - Ensure the reentrancy guard is correctly implemented to prevent multiple simultaneous function executions.

2. **Add Strict Authorization Checks**:
   - Implement comprehensive authorization checks to ensure that only authorized users can call functions that handle incentives and `withheldAmount`.

3. **Ensure Proper Depletion of Withheld Amount**:
   - Modify the functions to ensure `withheldAmount` is correctly and completely depleted during transactions, preventing it from being exploited.

4. **Secure Handling of Incentives Array**:
   - Implement dynamic management of the `incentives[]` array, ensuring it is correctly updated and depleted based on actual claims.

5. **Audit Publicly Accessible Variables**:
   - Review and restrict access to state variables to prevent external manipulation and monitoring by unauthorized users.

By addressing these vulnerabilities, the `Dispenser` contract will be more secure against potential reentrancy attacks and unauthorized incentive claims, safeguarding the overall integrity of the staking incentives system.

### Code Vulnerability Report: Potential Reentrancy and Withheld Amount Exploitation in `Dispenser.sol`

#### Summary
The vulnerability lies in the handling of the `withheldAmount` variable within the `claimStakingIncentives` and `claimStakingIncentivesBatch` functions. The lack of proper depletion and authorization checks can be exploited, allowing an attacker to repeatedly claim incentives and potentially execute a rug pull.

#### Vulnerability Details

**File**: `Dispenser.sol`

```solidity
// claimStakingIncentives
function claimStakingIncentives(
    uint256 numClaimedEpochs,
    uint256 chainId,
    bytes32 stakingTarget,
    bytes memory bridgePayload
) external payable {
    // Reentrancy guard
    if (_locked > 1) {
        revert ReentrancyGuard();
    }
    _locked = 2;

    // Check for zero chain Id
    if (chainId == 0) {
        revert ZeroValue();
    }

    // Check for zero target address
    if (stakingTarget == 0) {
        revert ZeroAddress();
    }

    // Check the number of claimed epochs
    uint256 localMaxNumClaimingEpochs = maxNumClaimingEpochs;
    if (numClaimedEpochs > localMaxNumClaimingEpochs) {
        revert Overflow(numClaimedEpochs, localMaxNumClaimingEpochs);
    }

    // Check for the paused state
    Pause currentPause = paused;
    if (currentPause == Pause.StakingIncentivesPaused || currentPause == Pause.AllPaused ||
        ITreasury(treasury).paused() == 2) {
        revert Paused();
    }

    // Get deposit processor bridging decimals corresponding to a chain Id
    address depositProcessor = mapChainIdDepositProcessors[chainId];
    uint256 bridgingDecimals = IDepositProcessor(depositProcessor).getBridgingDecimals();

    // Get the staking incentive to send as a deposit with, and the amount to return back to staking inflation
    (uint256 stakingIncentive, uint256 returnAmount, uint256 lastClaimedEpoch, bytes32 nomineeHash) =
        calculateStakingIncentives(numClaimedEpochs, chainId, stakingTarget, bridgingDecimals);

    // Write last claimed epoch counter to start claiming from the next time
    mapLastClaimedStakingEpochs[nomineeHash] = lastClaimedEpoch;

    // Refund returned amount back to tokenomics inflation
    if (returnAmount > 0) {
        ITokenomics(tokenomics).refundFromStaking(returnAmount);
    }

    uint256 transferAmount;

    // Check if staking incentive is deposited
    if (stakingIncentive > 0) {
        transferAmount = stakingIncentive;
        // Account for possible withheld OLAS amounts
        // Note: in case of normalized staking incentives with bridging decimals, this is correctly managed
        // as normalized amounts are returned from another side
        uint256 withheldAmount = mapChainIdWithheldAmounts[chainId];
        if (withheldAmount > 0) {
            // If withheld amount is enough to cover all the staking incentives, the transfer of OLAS is not needed
            if (withheldAmount >= transferAmount) {
                withheldAmount -= transferAmount;
                transferAmount = 0;
            } else {
                // Otherwise, reduce the transfer of tokens for the OLAS withheld amount
                transferAmount -= withheldAmount;
                withheldAmount = 0;
            }
            mapChainIdWithheldAmounts[chainId] = withheldAmount;
        }

        // Check if minting is needed as the actual OLAS transfer is required
        if (transferAmount > 0) {
            uint256 olasBalance = IToken(olas).balanceOf(address(this));

            // Mint tokens to self in order to distribute to the staking deposit processor
            ITreasury(treasury).withdrawToAccount(address(this), 0, transferAmount);

            // Check the balance after the mint
            olasBalance = IToken(olas).balanceOf(address(this)) - olasBalance;
            if (olasBalance != transferAmount) {
                revert WrongAmount(olasBalance, transferAmount);
            }
        }

        // Dispense to a service staking target
        _distributeStakingIncentives(chainId, stakingTarget, stakingIncentive, bridgePayload, transferAmount);
    }

    emit StakingIncentivesClaimed(msg.sender, stakingIncentive, transferAmount, returnAmount);

    _locked = 1;
}
```

```solidity
function claimStakingIncentivesBatch(
    uint256 numClaimedEpochs,
    uint256[] memory chainIds,
    bytes32[][] memory stakingTargets,
    bytes[] memory bridgePayloads,
    uint256[] memory valueAmounts
) external payable {
    // Reentrancy guard
    if (_locked > 1) {
        revert ReentrancyGuard();
    }
    _locked = 2;

    _checkOrderAndValues(chainIds, stakingTargets, bridgePayloads, valueAmounts);

    // Check the number of claimed epochs
    uint256 localMaxNumClaimingEpochs = maxNumClaimingEpochs;
    if (numClaimedEpochs > localMaxNumClaimingEpochs) {
        revert Overflow(numClaimedEpochs, localMaxNumClaimingEpochs);
    }

    Pause currentPause = paused;
    if (currentPause == Pause.StakingIncentivesPaused || currentPause == Pause.AllPaused ||
        ITreasury(treasury).paused() == 2) {
        revert Paused();
    }

    // Total staking incentives
    // 0: Staking incentive across all the targets to send as a deposit
    // 1: Actual OLAS transfer amount across all the targets
    // 2: Staking incentive to return back to staking inflation
    uint256[] memory totalAmounts;
    // Arrays of staking and transfer amounts
    uint256[][] memory stakingIncentives;
    uint256[] memory transferAmounts;

    (totalAmounts, stakingIncentives, transferAmounts) = _calculateStakingIncentivesBatch(numClaimedEpochs, chainIds,
        stakingTargets);

    // Refund returned amount back to tokenomics inflation
    if (totalAmounts[2] > 0) {
        ITokenomics(tokenomics).refundFromStaking(totalAmounts[2]);
    }

    // Check if staking incentive is deposited
    if (totalAmounts[0] > 0) {
        // Check if minting is needed as the actual OLAS transfer is required
        if (totalAmounts[1] > 0) {
            uint256 olasBalance = IToken(olas).balanceOf(address(this));

            // Mint tokens to self in order to distribute to staking deposit processors
            ITreasury(treasury).withdrawToAccount(address(this), 0, totalAmounts[1]);

            // Check the balance after the mint
            olasBalance = IToken(olas).balanceOf(address(this)) - olasBalance;
            if (olasBalance != totalAmounts[1]) {
                revert WrongAmount(olasBalance, totalAmounts[1]);
            }
        }

        // Dispense all the service staking targets, if the total staking incentive is not equal to zero
        _distributeStakingIncentivesBatch(chainIds, stakingTargets, stakingIncentives, bridgePayloads, transferAmounts,
            valueAmounts);
    }

    emit StakingIncentivesClaimed(msg.sender, totalAmounts[0], totalAmounts[1], totalAmounts[2]);

    _locked = 1;
}
```
