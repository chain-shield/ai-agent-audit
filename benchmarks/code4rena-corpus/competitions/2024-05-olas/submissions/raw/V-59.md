# Vulnerability details

## Impact
In the second loop where the services are being evicted from the global set of staked services. The `serviceIndexes` array this occurs when the loop variable `i` becomes 0, and the code tries to access `serviceIndexes[i - 1]`, which is equivalent to `serviceIndexes[-1]`. Accessing an array with a negative index is an invalid operation and can cause unexpected behavior or even a runtime exception.

If this bug is triggered, it can lead to the following:

1. In the worst case, if the invalid memory access happens to modify critical data structures or contract state, it could compromise the integrity of the staking system.

Referenced Code: [_evict#L464-L472](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/registries/contracts/staking/StakingBase.sol#L464-L473)
```solidity
for (uint256 i = numEvictServices; i > 0; --i) {
    // ...
    uint256 idx = serviceIndexes[i - 1];
    // ...
}
```
In this loop, `i` starts from `numEvictServices` and decrements until it reaches `1`. However, when `i` becomes `0`, the expression `i - 1` evaluates to `-1`, leading to an out-of-bounds access attempt on the `serviceIndexe`s array.

## Proof of Concept
Let's consider a scenario where `numEvictServices` is 3, and the `serviceIndexes` array contains the following values: `[1, 2, 3]`.

When the loop starts, `i` is initially 3, and the code executes as expected:

  - `i = 3`: `serviceIndexes[i - 1]` evaluates to `serviceIndexes[2]`, which is valid and accesses the element at index 2.

As the loop continues, `i` decrements:

  - `i = 2`: `serviceIndexes[i - 1]` evaluates to `serviceIndexes[1]`, which is valid and accesses the element at index 1.
  - `i = 1`: `serviceIndexes[i - 1]` evaluates to `serviceIndexes[0]`, which is valid and accesses the element at index 0.

However, when `i` becomes 0, the problematic behavior occurs:

  - `i = 0`: `serviceIndexes[i - 1]` evaluates to `serviceIndexes[-1]`, which is an invalid index and triggers an out-of-bounds access attempt.

At this point, the code may throw a runtime exception or exhibit undefined behavior.

## Recommended Mitigation Steps
Modify the loop condition to iterate until `i` is greater than or equal to 1, like this:
```solidity
for (uint256 i = numEvictServices; i >= 1; --i) {
    // ...
    uint256 idx = serviceIndexes[i - 1];
    // ...
}
```
