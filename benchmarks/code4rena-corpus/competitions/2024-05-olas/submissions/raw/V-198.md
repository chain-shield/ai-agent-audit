# Vulnerability details

## Impact
In this line of the syncWithheldAmount function: 
```solidity
uint256 withheldAmount = mapChainIdWithheldAmounts[chainId] + amount;
```
The problem is that the addition operation `mapChainIdWithheldAmounts[chainId] + amount` can overflow if the sum exceeds the maximum value that can be stored in a `uint256`. If an overflow occurs, the resulting `withheldAmount` will wrap around and have an incorrect value.

## Proof of Concept
[tokenomics/contracts/Dispenser.sol#L1183](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L1183)
```solidity
uint256 withheldAmount = mapChainIdWithheldAmounts[chainId] + amount;
```
This line performs an addition operation between the existing withheld amount stored in mapChainIdWithheldAmounts[chainId] and the new amount provided as a parameter. If the sum exceeds the maximum value that can be stored in a uint256, an overflow will occur.
1. Suppose the current value of mapChainIdWithheldAmounts[chainId] is 2^256 - 1 (the maximum value for uint256).
2. Now, if the syncWithheldAmount function is called with an amount greater than 0, the addition operation will overflow.
3. The resulting withheldAmount will wrap around and have a value that is significantly smaller than expected.

Here's code snippet that demonstrates the overflow:
```solidity
uint256 maxUint256 = type(uint256).max;
uint256 currentWithheldAmount = maxUint256;
uint256 newAmount = 1;

uint256 withheldAmount = currentWithheldAmount + newAmount;

// Expected: withheldAmount should be 0 (overflow)
// Actual: withheldAmount will be 0
```
In this example, currentWithheldAmount is set to the maximum value of uint256, and newAmount is set to 1. When the addition operation is performed, an overflow occurs, and the resulting withheldAmount wraps around to 0.

## Recommended Mitigation Steps
We can use the `SafeMath` library or the built-in Solidity overflow checks (if using Solidity version 0.8.0 or higher) to perform the addition safely.
```solidity
uint256 withheldAmount = mapChainIdWithheldAmounts[chainId].add(amount);
```
Using `SafeMath.add()`, the addition operation will revert if an overflow occurs, preventing the incorrect updating of the `withheldAmount`.

Alternatively, since we are using Solidity version 0.8.0 higher, we can rely on the built-in overflow checks by simply adding the unchecked keyword before the addition operation:
```solidity
unchecked {
    uint256 withheldAmount = mapChainIdWithheldAmounts[chainId] + amount;
}
```
This will disable the overflow check for that specific operation, allowing the code to handle the overflow manually if needed.
