# Vulnerability details

## Impact
An issue in the calculation of the `totalCost` variable in the `_sendMessage`: [@>tokenomics/contracts/staking/OptimismTargetDispenserL2.sol#L152-L165](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/ArbitrumDepositProcessorL1.sol#L152-L165)
```solidity
// Calculate token and message transfer cost
uint256[] memory cost = new uint256[](2);
if (transferAmount > 0) {
    if (maxSubmissionCostToken == 0) {
        revert ZeroValue();
    }

    // Calculate token transfer gas cost
    cost[0] = maxSubmissionCostToken + TOKEN_GAS_LIMIT * gasPriceBid;
}

// Calculate cost for the message transfer
cost[1] = maxSubmissionCostMessage + gasLimitMessage * gasPriceBid;
// Get the total cost
uint256 totalCost = cost[0] + cost[1];
```
When `transferAmount` is zero, In this case, `cost[0]` is not assigned any value and remains at its default value of zero. However, when calculating `totalCost`, it still includes `cost[0]`, which is incorrect because no token transfer cost should be added when `transferAmount` is zero.

## Proof of Concept
_sendMessage incorrectly calculates the total cost when no tokens are being transferred (i.e., `transferAmount` is zero). This can lead to incorrect behavior and potential financial losses for users interacting with the contract.

1. The `cost` array is initialized with a length of 2: [@>tokenomics/contracts/staking/OptimismTargetDispenserL2.sol#L152](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/ArbitrumDepositProcessorL1.sol#L152)
```solidity
uint256[] memory cost = new uint256[](2);
```
This array is intended to store the token transfer cost `(cost[0])` and the message transfer cost `(cost[1])`.

2. The code then checks if `transferAmount` is greater than zero: [@>tokenomics/contracts/staking/OptimismTargetDispenserL2.sol#L153-L159](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/ArbitrumDepositProcessorL1.sol#L153-L160)
```solidity
if (transferAmount > 0) {
    if (maxSubmissionCostToken == 0) {
        revert ZeroValue();
    }
    cost[0] = maxSubmissionCostToken + TOKEN_GAS_LIMIT * gasPriceBid;
}
```
If `transferAmount` is greater than zero, it calculates the token transfer cost and assigns it to `cost[0]`. However, if `transferAmount` is zero, `cost[0]` is not assigned any value and remains at its default value of zero.

3. The message transfer cost is calculated and assigned to `cost[1]`: [@>tokenomics/contracts/staking/OptimismTargetDispenserL2.sol#L163](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/ArbitrumDepositProcessorL1.sol#L163)
```solidity
cost[1] = maxSubmissionCostMessage + gasLimitMessage * gasPriceBid;
```
4. The total cost is calculated by adding `cost[0]` and `cost[1]`: [@>tokenomics/contracts/staking/OptimismTargetDispenserL2.sol#L165](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/ArbitrumDepositProcessorL1.sol#L165)
```solidity
uint256 totalCost = cost[0] + cost[1];
```
This is where the bug occurs. When transferAmount is zero, cost[0] is still included in the total cost calculation, even though no token transfer cost should be added.

_The impact of this bug is as follows:_

  - Users may be charged an incorrect total cost when no tokens are being transferred. The total cost will include the token transfer cost `(cost[0])`, even though it should be zero.
  - This can lead to users paying more than necessary for the transaction, as they will be charged for a token transfer cost that is not incurred.
  - If the contract relies on the total cost calculation for any further processing or decision-making, it may lead to incorrect behavior or unexpected results.

_Consider an example:_

  - Suppose `transferAmount` is zero, `maxSubmissionCostMessage` is 100, `gasLimitMessage` is 50000, and `gasPriceBid` is 10.
  - In this case, `cost[0]` will remain at its default value of zero since no token transfer is occurring.
  - The message transfer cost will be calculated as: `cost[1] = 100 + 50000 * 10 = 500100`.
  - The total cost will be calculated as: `totalCost = cost[0] + cost[1] = 0 + 500100 = 500100`.
  - However, the correct total cost should only include the message transfer cost, which is 500100. The inclusion of `cost[0]` (which is zero) in the total cost calculation is incorrect.

## Recommended Mitigation Steps
By adding the condition `(transferAmount > 0 ? cost[0] : 0)`, we ensure that `cost[0]` is only included in `totalCost` when `transferAmount` is greater than zero. If `transferAmount` is zero, `cost[0]` will not be added to `totalCost`.
```solidity
// Calculate token and message transfer cost
uint256[] memory cost = new uint256[](2);
if (transferAmount > 0) {
    if (maxSubmissionCostToken == 0) {
        revert ZeroValue();
    }

    // Calculate token transfer gas cost
    cost[0] = maxSubmissionCostToken + TOKEN_GAS_LIMIT * gasPriceBid;
}

// Calculate cost for the message transfer
cost[1] = maxSubmissionCostMessage + gasLimitMessage * gasPriceBid;
// Get the total cost
uint256 totalCost = (transferAmount > 0 ? cost[0] : 0) + cost[1];
```
