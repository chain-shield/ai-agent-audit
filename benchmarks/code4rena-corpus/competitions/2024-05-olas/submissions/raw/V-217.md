# Vulnerability details

## Impact
The function incorrectly reverts transactions when the staking duration precisely meets the minimum staking duration requirement, due to a less than or equal comparison. This issue could lead to unnecessary reverts when services are staked for exactly the minimum required duration, potentially disrupting user transactions and affecting system usability.

## Proof of Concept
Consider a scenario where a service is staked for exactly the minimum duration required (minStakingDuration). The current check:

`if (ts <= minStakingScale && availableRewards > 0) {
    revert NotEnoughTimeStaked(serviceId, ts, minStakingScale);
}`

incorrectly triggers a revert, even though the condition of minimum duration has been met.

## Tools Used

## Recommended Mitigation Steps
Modify the conditional check to:

`if (ts < minStakingDuration && availableRewards > 0) {
    revert NotEnoughTimeStaked(serviceId, ts, minStakingDuration);
}`
