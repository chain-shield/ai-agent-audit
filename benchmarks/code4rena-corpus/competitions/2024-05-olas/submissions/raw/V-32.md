# Vulnerability details

## Impact
`_sendMessage` function returns the `stakingBatchNonce` as the sequence value, regardless of whether a message was actually sent to L2 or not. This can lead to incorrect sequence numbers being returned. If `transferAmount` is greater than zero, the function will deposit OLAS tokens and send a message to L2 using `_sendMessageToChild(data)`. However, if `transferAmount` is zero, no message will be sent to L2, but the function will still return the `stakingBatchNonce` as the sequence.

## Proof of Concept
The incorrect sequence number returned by the `_sendMessage` function can lead to several issues such as:

   1. Inconsistent sequence numbers: If the function returns the stakingBatchNonce even when no message is sent to L2, it can result in gaps or inconsistencies in the sequence numbers. This can make it difficult to track and correlate messages between L1 and L2.

   2. Incorrect message processing: If the L2 contract relies on the sequence number to process messages in a specific order or to identify missing messages, the incorrect sequence numbers can lead to incorrect processing or synchronization issues between L1 and L2.

Let's take a closer look at the code that illustrates the concept: [@>tokenomics/contracts/staking/WormholeDepositProcessorL1.sol](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/staking/PolygonDepositProcessorL1.sol#L57-L84)

   1. The `_sendMessage` function:
```solidity
function _sendMessage(
    address[] memory targets,
    uint256[] memory stakingIncentives,
    bytes memory,
    uint256 transferAmount
) internal override returns (uint256 sequence) {
    // ...

    // Since there is no returned message sequence, use the staking batch nonce
    sequence = stakingBatchNonce;
}
```
As mentioned earlier, the function always returns the `stakingBatchNonce` as the `sequence`, regardless of whether a message was sent to L2 or not.

   2. The `_sendMessageToChild` function
```solidity
function _sendMessageToChild(bytes memory data) internal {
    // Source: https://github.com/0xPolygon/fx-portal/blob/731959279a77b0779f8a1eccdaea710e0babee19/contracts/FxRoot.sol#L29
    // Doc: https://docs.polygon.technology/pos/how-to/bridging/l1-l2-communication/state-transfer/#root-tunnel-contract
    // Send message to L2
    fxRootTunnel.sendMessageToChild(data);
}
```
This function is called within the `_sendMessage` function to send a message to L2 using the Polygon FX Portal's `sendMessageToChild` function. However, it is only called when `transferAmount` is greater than zero.

> The Polygon documentation on L1 to L2 communication using the State Transfer mechanism provides additional context on how messages are sent from L1 to L2:

   - [Polygon Docs: L1 to L2 Communication - State Transfer](https://docs.polygon.technology/pos/how-to/bridging/l1-l2-communication/state-transfer/#)

The documentation highlights the importance of correctly handling message sequences and provides examples of how to send and receive messages between L1 and L2.

## Recommended Mitigation Steps
Consider returning a different value or throwing an error when no message is sent to L2. Alternatively, increment the `stakingBatchNonce` only when a message is sent.
```solidity
function _sendMessage(
    address[] memory targets,
    uint256[] memory stakingIncentives,
    bytes memory,
    uint256 transferAmount
) internal override returns (uint256 sequence) {
    // Check for the transferAmount > 0
    if (transferAmount > 0) {
        // ... (existing code for depositing OLAS and sending message to L2)

        // Increment the stakingBatchNonce only when a message is sent
        stakingBatchNonce++;

        // Return the updated stakingBatchNonce as the sequence
        sequence = stakingBatchNonce;
    } else {
        // If no message is sent, return a default value or throw an error
        sequence = 0; // or revert with an error message
    }
}
```
