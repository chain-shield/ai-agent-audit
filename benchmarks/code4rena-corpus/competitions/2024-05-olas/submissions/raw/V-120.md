# Vulnerability details

## Impact
When claiming the reward incentives, if treasury does not have enough `ETHFromServices`, then the reward transfer will be skipped silently leading to a situation that the user does not receive any reward but the mapping resets it to zero.

## Proof of Concept
To claim incentives for the owner of components or agents, the function `claimOwnerIncentives` should be called where it invokes the external function `accountOwnerIncentives` to calculate the amount of incentives in terms of reward (ETH) and topUp (OLAS). Then, the external function `withdrawToAccount` is called to transfer the calculated incentives to the `msg.sender`.
```solidity
    function claimOwnerIncentives(
        uint256[] memory unitTypes,
        uint256[] memory unitIds
    ) external returns (uint256 reward, uint256 topUp) {
        //....

        // Calculate incentives
        (reward, topUp) = ITokenomics(tokenomics).accountOwnerIncentives(msg.sender, unitTypes, unitIds);

        bool success;
        // Request treasury to transfer funds to msg.sender if reward > 0 or topUp > 0
        if ((reward + topUp) > 0) {
            // Get the current OLAS balance
            uint256 olasBalance;
            if (topUp > 0) {
                olasBalance = IToken(olas).balanceOf(msg.sender);
            }

            success = ITreasury(treasury).withdrawToAccount(msg.sender, reward, topUp);

            // Check the balance after the OLAS mint, if applicable
            if (topUp > 0){
                olasBalance = IToken(olas).balanceOf(msg.sender) - olasBalance;
                if (olasBalance != topUp) {
                    revert WrongAmount(olasBalance, topUp);
                }
            }
        }

        // Check if the claim is successful and has at least one non-zero incentive.
        if (!success) {
            revert ClaimIncentivesFailed(msg.sender, reward, topUp);
        }

        //.....
    }
```

In the function `withdrawToAccount`, to transfer the reward, it checks whether `ETHFromServices` is higher than the reward or not. If it is not, then reward transfer is skipped, and it continues to transfer the topUp. If topUp transfer is successful, the `true` boolean is returned.
```solidity

        returns (bool success)
    {
        // Check if the contract is paused

            revert Paused();
        }

        // Check for the dispenser access
        if (dispenser != msg.sender) {
            revert ManagerOnly(msg.sender, dispenser);

        uint256 amountETHFromServices = ETHFromServices;

        if (accountRewards > 0 && amountETHFromServices >= accountRewards) {
```

The issue is that skipping the reward transfer is done silently. While, during the function call `accountOwnerIncentives`, it assumes that the reward will be transferred to the user, so it resets it to zero.
```solidity

        address account,
        uint256[] memory unitTypes,
        uint256[] memory unitIds
    ) external returns (uint256 reward, uint256 topUp) {
        //......

        reward += mapUnitIncentives[unitTypes[i]][unitIds[i]].reward;
        mapUnitIncentives[unitTypes[i]][unitIds[i]].reward = 0;

        //......
    }
```
https://github.com/code-423n4/2024-05-olas/blob/main/tokenomics/contracts/Tokenomics.sol#L1370-L1371

So, in case the `topUp > 0`, `reward > 0`, and `ETHFromServices < reward`, the owner of incentives will receive his topUps, but he will not receive any reward. Moreover, the mapping `mapUnitIncentives` related to the user will set the reward and topUp to zero. In other words, although the user does not receive any reward, the mapping is set to zero, and he loses his reward.

## Recommended Mitigation Steps

The reward transfer should be implemented differently, like the following code:


```solidity
    function withdrawToAccount(address account, uint256 accountRewards, uint256 accountTopUps) external
        returns (bool success)
    {
        // ....


        uint256 amountETHFromServices = ETHFromServices;
        // Send ETH rewards, if any
        if (accountRewards > 0 && amountETHFromServices >= accountRewards) {
            amountETHFromServices -= accountRewards;
            ETHFromServices = uint96(amountETHFromServices);
            emit Withdraw(ETH_TOKEN_ADDRESS, account, accountRewards);
            (success, ) = account.call{value: accountRewards}("");
            if (!success) {
                revert TransferFailed(address(0), address(this), account, accountRewards);
            }
        } else if (accountRewards > 0 && amountETHFromServices < accountRewards) {
            revert TransferFailed(address(0), address(this), account, accountRewards);
        } else if (accountRewards == 0){
            success = true;
        }

        // Send OLAS top-ups
        if (accountTopUps > 0) {
            // Tokenomics has already accounted for the account's top-up amount,
            // thus the the mint does not break the inflation schedule
            IOLAS(olas).mint(account, accountTopUps);
            emit Withdraw(olas, account, accountTopUps);
        }

    }
```
