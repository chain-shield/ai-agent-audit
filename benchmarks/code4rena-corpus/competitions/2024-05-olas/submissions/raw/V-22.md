# Vulnerability details

## Impact
In the __decreaseAllowance__ function, there is a potential issue where allowance could be decreased below zero, which can lead to an underflow vulnerability. This can allow an attacker to manipulate the allowance to their benefit, potentially granting them an unintentional and very large allowance due to the nature of underflow in unsigned integers.

## Proof of Concept
1.Setup:
Alice approves Bob to spend 100 OLA tokens on her behalf.

function approve(address spender, uint256 amount) public virtual returns (bool) {
    allowance[msg.sender][spender] = amount;
    emit Approval(msg.sender, spender, amount);
    return true;
}

2.Alice calls approve with Bob's address and an allowance of 100 tokens.

ERC20 token = new OLA(0);
token.approve(bob, 100);

3.Spending Tokens:
-Bob spends 60 tokens.
token.transferFrom(alice, vendor, 60);
-Allowance after spending 60 tokens is 40 tokens.
assert(token.allowance(alice, bob) == 40);

4.Underflow Vulnerability: https://gist.github.com/Hiiamgogo/16fbd7ec88dceed2cbfc86f6741ec463

Fix
To fix this vulnerability, add a check to ensure that the allowance is not decreased below zero:https://gist.github.com/Hiiamgogo/12666ee53483780a6480b292d601dc7e

## Recommended Mitigation Steps
Add a check to ensure that the allowance is not decreased below zero:
Check for Underflow:
Ensure spenderAllowance is greater than or equal to amount before subtraction.

require(spenderAllowance >= amount, "ERC20: decreased allowance below zero");
spenderAllowance -= amount;

The __decreaseAllowance__ function in the OLA token contract was vulnerable to an underflow attack. By reducing the allowance without checking if the current allowance is sufficient, an attacker could create an extremely large allowance due to underflow, allowing them to spend more tokens than intended. Adding a check to ensure that the allowance is not decreased below zero effectively mitigates this risk.
