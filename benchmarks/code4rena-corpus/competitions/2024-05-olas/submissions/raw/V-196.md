# Vulnerability details

## Impact
In the code of `claimStakingIncentives` function  code snippet: [tokenomics/contracts/Dispenser.sol#L1009-L1024](https://github.com/code-423n4/2024-05-olas/blob/e2a8bc31d2769bfb578a06cc64919ad369a82c08/tokenomics/contracts/Dispenser.sol#L1009-L1024)
```solidity
// Account for possible withheld OLAS amounts
// Note: in case of normalized staking incentives with bridging decimals, this is correctly managed
// as normalized amounts are returned from another side
uint256 withheldAmount = mapChainIdWithheldAmounts[chainId];
if (withheldAmount > 0) {
    // If withheld amount is enough to cover all the staking incentives, the transfer of OLAS is not needed
    if (withheldAmount >= transferAmount) {
        withheldAmount -= transferAmount;
        transferAmount = 0;
    } else {
        // Otherwise, reduce the transfer of tokens for the OLAS withheld amount
        transferAmount -= withheldAmount;
        withheldAmount = 0;
    }
    mapChainIdWithheldAmounts[chainId] = withheldAmount;
}
```
The issue is in the calculation of the `transferAmount` when the `withheldAmount` is greater than zero but less than the `transferAmount`. In this case, the `transferAmount` is reduced by the `withheldAmount`, but the `withheldAmount` is set to zero.

But, the updated `withheldAmount` is then stored back into the `mapChainIdWithheldAmounts` mapping, effectively setting the withheld amount to zero for that specific `chainId`. This means that any remaining withheld amount is lost and not accounted for in future calculations.

## Recommended Mitigation Steps
Update the `withheldAmount` in the mapping only when it is fully consumed. 
```solidity
// Account for possible withheld OLAS amounts
// Note: in case of normalized staking incentives with bridging decimals, this is correctly managed
// as normalized amounts are returned from another side
uint256 withheldAmount = mapChainIdWithheldAmounts[chainId];
if (withheldAmount > 0) {
    // If withheld amount is enough to cover all the staking incentives, the transfer of OLAS is not needed
    if (withheldAmount >= transferAmount) {
        withheldAmount -= transferAmount;
        mapChainIdWithheldAmounts[chainId] = withheldAmount;
        transferAmount = 0;
    } else {
        // Otherwise, reduce the transfer of tokens for the OLAS withheld amount
        transferAmount -= withheldAmount;
        mapChainIdWithheldAmounts[chainId] = 0;
    }
}
```
With this correction, the `withheldAmount` is updated in the mapping only when it is fully consumed (`withheldAmount >= transferAmount`). If the `withheldAmount` is less than the `transferAmount`, the `transferAmount` is reduced accordingly, and the `withheldAmount` in the mapping is set to zero.
