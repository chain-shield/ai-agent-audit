# Vulnerability details

## Impact

Users can mint free tokens on the destination chain.

## Proof of Concept

The process of ITS service is as such:

- Users will first call `interchainTransfer()` to initiate an interchain transfer.
- `_takeToken()` is called, and one branch of execution is to transfer tokens to the TokenManager.
- The function will eventually call `gatewayCaller.delegateCall`. DelegateCall is used so the msg.sender of the gatewayCaller is the user, and not the ITS contract.
- GatewayCaller calls gasService.payNativeGasForContractCall 
- GatewayCaller calls gateway.callContract

The function flow:

> interchainTransfer() -> _takeToken() -> _transmitInterchainTransfer() -> _callContract() -> gatewayCaller.delegateCall (GatewayCaller.callContract.selector) -> gateway.callContract

In GatewayCaller.callContract(), there is no access control. Users can directly call `callContract()` and build the payload themselves, and send the payload directly to the gateway without depositing their funds to the TokenManager in the source chain.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Set `callContract()` and all its variance to internal in `GatewayCaller.sol` so users cannot bypass the checks in the InterchainTokenService functions and call functions in GatewayCaller directly.
