Issue however is that the native Rust's ITS hub lack any pausable logic as can be seen in all of [state.rs#L1-L233](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/state.rs#L1-L233).

Which then means that in the case of a black swan event there is no how to stop the native implementation on the Rust ITS hub's implementation.

### Impact

Per documentation, protocol integrates multiple logic to help for compromistation or black swan events, including the flow limiting logic and also having core functions being protected with `whenNotPaused` modifiers, however this sort of logic is not applied to [state.rs#L1-L233](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/state.rs#L1-L233) or any other entry point via the Rust ITS Hub's [axelarnet-gateway](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/) breaking intended functionality.

### Recommended Mitigation Steps

Consider integrating a similar logic which would have the core functionalities being pausable in compromised situations.
