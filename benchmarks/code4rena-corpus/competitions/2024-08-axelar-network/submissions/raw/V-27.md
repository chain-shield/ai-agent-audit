# Vulnerability details

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L527-L551

## Impact
Lack of estimated `msg.value` in `transmitInterchainTransfer` function can lead to transaction failures and potentially lost gas fees. The function relies on the assumption that `msg.value` provided by the caller will be sufficient to cover the `gasValue` required for cross-chain transactions. However, if `msg.value` is insufficient, the transaction may revert unexpectedly.


## Proof of Concept
The `transmitInterchainTransfer` function calls the `_transmitInterchainTransfer` function, which in turn invokes the `_callContract` function. Within `_callContract`, the `gatewayCaller` function is used to initiate a cross-chain transaction. This function includes the `gasValue` parameter, which represents the amount of gas to be paid for the cross-chain message. The `msg.value` must be equal or greater than `gasValue` for the transaction to proceed as intended.

However, the code does not explicitly check if `msg.value` is equal or less than the required gas fee, leading to potential issues if the provided `msg.value` is insufficient.

## Example scenario
> A user initiates a cross-chain transfer by calling `transmitInterchainTransfer`, which sends a specified `msg.value` along with the transaction.

> The function then calls _transmitInterchainTransfer, which further calls `_callContract`.

> `_callContract` attempts to pay for gas using `gasValue` by extracting the amount from msg.value.

> If `msg.value` is less than `gasValue`, the gas payment may fail, leading to a failed transaction.

> Without an explicit check, users may inadvertently underpay, leading to transaction failures and wasted gas fees.

## Tools Used
Manual code review

## Recommended Mitigation Step
To prevent this issue, an explicit check should be added to ensure that `msg.value` is sufficient to cover `gasValue` before proceeding with the transaction. This can be done by comparing msg.value with `gasValue` and reverting the transaction with a clear error message if the provided value is insufficient.
