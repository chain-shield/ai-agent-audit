# Vulnerability details

## Vulnerability Details
The `deployRemoteInterchainToken` function is designed to deploy an existing interchain token to a new blockchain. It's a critical function for expanding the token's presence across multiple chains.

The function lacks proper access control. Any external caller can invoke this function to deploy a remote version of any existing interchain token, regardless of whether they own or have rights to that token.

## Code Snippet
```solidity
function deployRemoteInterchainToken(
    string calldata originalChainName,
    bytes32 salt,
    address minter,
    string memory destinationChain,
    uint256 gasValue
) external payable returns (bytes32 tokenId) {
    // ... (existing code)
    
    address sender = msg.sender;
    salt = interchainTokenSalt(chainNameHash_, sender, salt);
    tokenId = interchainTokenService.interchainTokenId(TOKEN_FACTORY_DEPLOYER, salt);

    IInterchainToken token = IInterchainToken(interchainTokenService.interchainTokenAddress(tokenId));

    // ... (rest of the function)
}
```

## Impact
1. Unauthorized Deployment: Anyone can deploy remote versions of tokens they don't own or control.
2. Potential for Confusion: It could lead to multiple unauthorized deployments of the same token on different chains.
3. Possible Economic Attacks: Malicious actors could exploit this to manipulate token availability across chains.

## Scenario
1. Alice creates an interchain token "AliceCoin" on Chain A.
2. Bob, who doesn't own AliceCoin, calls `deployRemoteInterchainToken` for AliceCoin on Chain B.
3. An unauthorized version of AliceCoin is now deployed on Chain B, potentially causing confusion and diluting the original token's value.

## Fix
Implement proper access control. Only allow the token's owner or an authorized address to deploy the token remotely. 

```solidity
function deployRemoteInterchainToken(
    string calldata originalChainName,
    bytes32 salt,
    address minter,
    string memory destinationChain,
    uint256 gasValue
) external payable returns (bytes32 tokenId) {
    // ... (existing code to determine chainNameHash_ and calculate salt)

    address sender = msg.sender;
    salt = interchainTokenSalt(chainNameHash_, sender, salt);
    tokenId = interchainTokenService.interchainTokenId(TOKEN_FACTORY_DEPLOYER, salt);

    IInterchainToken token = IInterchainToken(interchainTokenService.interchainTokenAddress(tokenId));
    
    // Add this check
    require(token.owner() == sender, "Caller is not the token owner");

    // ... (rest of the function)
}
```

This fix ensures that only the token owner can deploy the token to a new chain, maintaining proper control and preventing unauthorized deployments.
