Detailed description of the impact of this finding.

Allowance Under-run in _spendAllowance Function within InterchainToken contract

The _spendAllowance function in the InterchainToken contract contains a potential arithmetic error that can lead to incorrect allowance handling. 

Specifically, the function subtracts the amount from _allowance without ensuring that amount is less than or equal to _allowance. 

This can result in a subtraction under-run, where the calculated allowance wraps around to a large integer, effectively bypassing the allowance check and allowing the spender to transfer more tokens than intended.

This vulnerability could allow malicious users to spend more tokens than permitted by their allowance, leading to unauthorised token transfers and potential financial loss for token holders.

## Proof of Concept

***Here is an example illustrating the potential exploit:***

	1.	Assume a spender is granted an allowance of 100 tokens.
	2.	The spender attempts to transfer 150 tokens.
	3.	In the current implementation, this will result in an under-run because _allowance - amount (100 - 150) wraps around to a large number.
	4.	The allowance check is effectively bypassed, allowing the unauthorised transfer of 150 tokens.

***Code Location:***
The vulnerability is located in the _spendAllowance function of the InterchainToken contract:
```sol
    function _spendAllowance(address sender, address spender, uint256 amount) internal override {
        uint256 _allowance = allowance[sender][spender];


        if (_allowance != UINT256_MAX) {
            _approve(sender, spender, _allowance - amount);
        }
    }
```

## Recommended Mitigation Steps

To mitigate this issue, a check should be added to ensure that amount is less than or equal to _allowance before performing the subtraction. 

This can prevent the under-run and ensure that the allowance logic is correctly enforced.

***Mitigation Code***

Here is the revised code for the _spendAllowance function with the necessary check:
```sol
function _spendAllowance(address sender, address spender, uint256 amount) internal override {
    uint256 _allowance = allowance[sender][spender];

    if (_allowance != UINT256_MAX) {
        require(amount <= _allowance, "ERC20: insufficient allowance");
        _approve(sender, spender, _allowance - amount);
    }
}
```

By adding the ```require(amount <= _allowance, "ERC20: insufficient allowance");``` statement, we ensure that an attempt to spend more than the allowed amount results in a transaction revert, preventing any unauthorised token transfers.
