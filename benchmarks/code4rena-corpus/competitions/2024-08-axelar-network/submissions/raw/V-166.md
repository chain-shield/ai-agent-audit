# Vulnerability details

## Impact
The `expressExecute` method in the `InterchainTokenService` contract allows for user-controlled inputs to dictate the execution flow of cross-chain operations. Specifically, the `destinationAddressBytes` parameter, which is derived from a user-controlled `payload`, can be manipulated to point to arbitrary contract addresses. This opens up several attack vectors, including:

1. **Arbitrary Contract Call**: Attackers can direct the contract to interact with any contract they choose, potentially executing malicious logic within the target contract.
2. **Asset Theft or Freezing**: By directing tokens or calls to invalid or malicious addresses, attackers can cause tokens to be irretrievably lost or frozen, effectively stealing them from the intended recipients.

Steps to Exploit

1. **Manipulate `payload`**: An attacker can craft a specific payload that sets `destinationAddressBytes` to a contract they control.
2. **Trigger the call**: By calling `expressExecute` with this manipulated payload, the contract will attempt to execute a method on the attacker's contract.
3. **Execute malicious logic**: The attacker's contract can exploit the reentrancy vulnerability or other logic flaws, potentially resulting in unauthorized transfers or other malicious outcomes.

## Recommended Mitigation Steps

Input Validation: Implement strict validation of the destinationAddress derived from destinationAddressBytes. Ensure it matches a list of known, trusted addresses, or conforms to expected patterns.

White-listing: Restrict the contracts that can be called via expressExecute to a whitelist of trusted contracts.

Fail-Safe Mechanisms: Ensure that, in the event of an error, any affected tokens can be recovered or redirected to a safe address to prevent loss or freezing of assets.
