# Vulnerability Details

The `init` function in the `InterchainToken` contract is responsible for setting up the token's properties and assigning minting permissions. It's designed to be called only once to initialize the token.

The function allows setting the `minter` address to `address(0)` (the zero address) without any checks. This can lead to a permanent loss of minting capability if not handled correctly.

## Code Snippet
https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/interchain-token/InterchainToken.sol#L86

```solidity
function init(bytes32 tokenId_, address minter, string calldata tokenName, string calldata tokenSymbol, uint8 tokenDecimals) external {
    // ... (other initialization logic)

    /**
     * @dev Set the token service as a minter to allow it to mint and burn tokens.
     * Also add the provided address as a minter. If `address(0)` was provided,
     * add it as a minter to allow anyone to easily check that no custom minter was set.
     */
    _addMinter(interchainTokenService_);
    _addMinter(minter);

    // ...
}
```

## Impact
If `address(0)` is provided as the `minter` parameter, either accidentally or intentionally, it will be added as a minter. This leads to two major issues:
1. No entity will have minting permissions except for the `interchainTokenService_`.
2. It becomes impossible to distinguish between a case where no custom minter was intended and a case where the zero address was accidentally provided.

## Scenario
1. The contract is deployed and initialized with `minter` set to `address(0)`.
2. The `interchainTokenService_` is the only address with minting permissions.
3. If the `interchainTokenService_` is not designed to handle all minting operations, the token becomes severely limited in functionality.
4. There's no way to add a new minter later, as the contract doesn't appear to have a function to add minters post-initialization.

## Fix
Implement a check to prevent setting the zero address as a minter, and provide a clear way to indicate that no custom minter is needed.

```solidity
function init(bytes32 tokenId_, address minter, string calldata tokenName, string calldata tokenSymbol, uint8 tokenDecimals) external {
    // ... (other initialization checks)

    if (_isInitialized()) revert AlreadyInitialized();
    _initialize();

    // ... (setting token properties)

    _addMinter(interchainTokenService_);
    
    if (minter != address(0)) {
        _addMinter(minter);
    }

    // ... (rest of the initialization)
}
```
