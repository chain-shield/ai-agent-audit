# Vulnerability details

## Impact

In the `execute.rs` contract of the ITS Hub, there is a function `apply_tracking_balances()` that tracks token amounts both on the source chain and on the destination chain. The problem is that when deploying interchain token on the destination chain, it only starts tracking balance for it ignoring the interchain token on the source chain. So when interchain transfer happens, the balance of the token on the source chain as it's untracked will be unchanged and the balance on the destination chain will be increased.

## Proof of Concept

Let's consider `apply_tracking_balances()` functionality:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/contract/execute.rs#L135-138
```
 ItsMessage::DeployInterchainToken { token_id, .. } => {
            start_token_balance(storage, token_id.clone(), destination_chain.clone(), true)
                .change_context(Error::InvalidStoreAccess)?
        }

```

When deploying the token on the destination chain, we start track balance for it on the destination chain:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/state.rs#L147-153
```
match TOKEN_BALANCES.may_load(storage, key.clone())? {
        None => {
            let initial_balance = if track_balance {
                TokenBalance::Tracked(Uint256::zero())
            } else {
                TokenBalance::Untracked
            };
```

The problem is that when we have the same token on the source chain and on the destination chain, we can make interchain transfer. But the balance on the source chain will be untracked if the chain was not deployed remotely:

1. Let's say we want to transfer some tokenA from chainX (native chain) to chainY.

2. We deploy tokenA on the native chainX so it does not go through ITS Hub and the balance of it is untracked.

3. Then we deploy tokenA on chainY remotely so the balance is tracked. Now when we implement interchain transfer, the balance on chainX will be unchanged as the tracking has not been started yet and on chainY it will be increased:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/state.rs#L177-188
```
 match token_balance {
        Some(TokenBalance::Tracked(balance)) => {
            let token_balance = if is_deposit {
                balance
                    .checked_add(amount)
                    .map_err(|_| Error::MissingConfig)?
            } else {
                balance
                    .checked_sub(amount)
                    .map_err(|_| Error::MissingConfig)?
            }
            .then(TokenBalance::Tracked);

            TOKEN_BALANCES.save(storage, key.clone(), &token_balance)?;
        }
        Some(_) | None => (),
    }
```

As you can see, the balance will not be fetched on chainX as it's not tracked. This will lead to incorrect balance update on one of the chains.

Manual review.

## Recommended Mitigation Steps

Make sure ITS Hub takes into account tokens on both chains.
