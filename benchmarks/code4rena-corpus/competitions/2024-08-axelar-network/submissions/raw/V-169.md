# Vulnerability details

## Impact
The `InterchainToken` contract contains a critical initialization vulnerability. When the contract is deployed, the `constructor` is automatically invoked, initializing crucial parameters such as the `interchainTokenService_` address. If an attempt is made to reinitialize the contract using the `init` method after deployment, the `init` method will fail because the contract is already marked as initialized. This prevents the proper setting of essential parameters like `name`, `symbol`, `decimals`, and the `interchainTokenService_` address. As a result, the core functionalities of the contract, such as minting and burning cross-chain tokens, may fail. Moreover, the `interchainTokenService_` address will remain as the zero address if `init` is incorrectly relied upon, which could lead to failures in cross-chain token management and pose significant risks to user assets.

## Proof of Concept

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/interchain-token/InterchainToken.sol#L86

In the `InterchainToken` contract, the constructor is defined as follows:

```
constructor(address interchainTokenServiceAddress) {
    _initialize();

    if (interchainTokenServiceAddress == address(0)) revert InterchainTokenServiceAddressZero();

    interchainTokenService_ = interchainTokenServiceAddress;
}
```

This constructor is automatically called during contract deployment, setting the `interchainTokenService_` address and marking the contract as initialized.

The `init` method is defined as:

```
function init(bytes32 tokenId_, address minter, string calldata tokenName, string calldata tokenSymbol, uint8 tokenDecimals) external {
    if (_isInitialized()) revert AlreadyInitialized();

    _initialize();

    if (tokenId_ == bytes32(0)) revert TokenIdZero();
    if (bytes(tokenName).length == 0) revert TokenNameEmpty();
    if (bytes(tokenSymbol).length == 0) revert TokenSymbolEmpty();

    name = tokenName;
    symbol = tokenSymbol;
    decimals = tokenDecimals;
    tokenId = tokenId_;

    _addMinter(interchainTokenService_);
    _addMinter(minter);

    _setNameHash(tokenName);
}
```

Since `_isInitialized()` will return `true` after the constructor has run, any subsequent calls to the `init` method will fail due to the `AlreadyInitialized` revert. This causes the following issues:

1. The contract’s essential parameters, such as `name`, `symbol`, and `decimals`, remain unset.
2. The `interchainTokenService_` address is not properly configured, leading to failures in functions dependent on this address, such as cross-chain token transfers.

## Recommended Mitigation Steps

1. **Remove the `init` method**: Given that the constructor already handles the necessary initialization, the `init` method can be removed entirely. This prevents unnecessary calls and ensures all initialization logic is completed during contract deployment.
2. **Enhance Constructor Initialization**: If further initialization is required after deployment, consider passing all necessary parameters to the constructor and ensuring all initialization logic is completed within the constructor. Avoid relying on external methods for initialization.
3. **Ensure Single Initialization Point**: Ensure that all initialization operations are conducted solely through the constructor, preventing confusion or failure from multiple entry points for initialization.
