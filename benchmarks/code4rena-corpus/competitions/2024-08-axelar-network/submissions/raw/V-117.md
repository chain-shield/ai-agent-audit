# Vulnerability details

The `isCommandExecuted` function in the `BaseAmplifierGateway.sol` contract is designed as a backward-compatible function to check whether a message has been executed. However, it currently returns a boolean indicating that a message has been executed if it is not in the `MESSAGE_NONEXISTENT` state. This is problematic because messages that are approved (where the message state is the payload hash) will also be returned as executed, even though they have not been.

## Impact
This issue results in messages being incorrectly marked as executed, which can cause various functions to revert. For example, the `expressExecute` function in both the `InterchainTokenService.sol` and `AxelarExpressExecutable.sol` contracts will revert under the false assumption that the message has already been executed. In the `InterchainTokenService::expressExecute` function it would prevent users from "express" executing their interchain transfer messages.

## Proof of Concept
The `isCommandExecuted` function currently checks if the message is not equal to `MESSAGE_NONEXISTENT`:
```solidity
    /// @dev Message can be in one of three states: non-existent, approved, or executed
    /// Non-existent: The message has not been seen before. Equal to 0
    /// Approved: The message has been seen and approved. Equal to keccak256 of the message data
    /// Executed: The message has been seen and executed. Equal to 1
    bytes32 internal constant MESSAGE_NONEXISTENT = 0;
    bytes32 internal constant MESSAGE_EXECUTED = bytes32(uint256(1));

...

    function isCommandExecuted(bytes32 commandId) public view override returns (bool) {
@>      return _baseAmplifierGatewayStorage().messages[commandId] != MESSAGE_NONEXISTENT;
    }
```
In the `InterchainTokenService::expressExecute` function, the logic will revert if the message is approved while not executed:
```solidity
    function expressExecute(
        bytes32 commandId,
        string calldata sourceChain,
        string calldata sourceAddress,
        bytes calldata payload
    ) public payable whenNotPaused {
        ...

@>      if (gateway.isCommandExecuted(commandId)) revert AlreadyExecuted();

        ...
    }
```

## Recommended Mitigation Steps
Change the `isCommandExecuted` function so it correctly checks if a message is executed:
```diff
    function isCommandExecuted(bytes32 commandId) public view override returns (bool) {
-       return _baseAmplifierGatewayStorage().messages[commandId] != MESSAGE_NONEXISTENT;
+       return _baseAmplifierGatewayStorage().messages[commandId] == MESSAGE_EXECUTED;
    }
```
So it aligns with the `isMessageExecuted` function:
```solidity
    function isMessageExecuted(string calldata sourceChain, string calldata messageId) external view returns (bool) {
        return _baseAmplifierGatewayStorage().messages[messageToCommandId(sourceChain, messageId)] == MESSAGE_EXECUTED;
    }
```
