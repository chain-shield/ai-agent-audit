# Vulnerability details

## Impact
In the client contract and executable contract implementation, any user is allowed to repeatedly call the `execute` and `call_contract` methods without restrictions or access control. Due to the lack of verification and protection mechanisms, malicious users can send the same message or a large number of malicious messages by calling these methods multiple times, leading to the following potential security issues:

1. **Repeatedly calling the same message**: If the same message is sent and executed multiple times, it may lead to repeated operations. For example, if a cross-chain transfer message is repeatedly executed, it may lead to multiple transfers of funds, resulting in fund loss or system abnormalities.
2. **Sending a large number of malicious messages**: Attackers can send a large number of useless or malicious messages, occupying contract execution resources and blockchain network resources, resulting in longer service response time or triggering a denial of service attack (DoS), thereby affecting the normal operation of other users.
3. **Fee issue**: Each call to a smart contract consumes Gas fees. If there is no limit, attackers can consume a large amount of Gas fees by executing a large number of requests, resulting in increased fees for legitimate users, making them unaffordable.

In the `Client::execute` and `Client::call_contract` methods, there is no restriction on repeated calls of the same message or sending a large number of messages. Attackers can take advantage of this by calling these methods multiple times to execute the same cross-chain message or send a large number of malicious messages, causing inconsistent system state, resource exhaustion, and potential financial losses. The following is a code example:

```
    pub fn call_contract(
        &self,
        destination_chain: ChainName,
        destination_address: Address,
        payload: HexBinary,
    ) -> WasmMsg {
        self.client.execute(&ExecuteMsg::CallContract {
            destination_chain,
            destination_address,
            payload,
        })
    }

    pub fn execute(&self, cc_id: CrossChainId, payload: HexBinary) -> WasmMsg {
        self.client.execute(&ExecuteMsg::Execute { cc_id, payload })
    }
```

## Recommended Mitigation Steps

1. **Introduce unique identifiers or timestamps**: Introduce unique identifiers or timestamps for each message to ensure that the same message can only be processed once, thereby preventing repeated execution.
2. **Increase call frequency limit**: Limit the number of calls each user can make in a short period of time to prevent sending a large number of malicious messages that occupy system resources.
3. **Increase message processing fees**: Increase the cost of processing messages so that malicious users need to pay a higher cost to launch attacks and reduce abuse.
4. **Status check and rollback mechanism**: Add status checks before performing operations to ensure that messages are not executed repeatedly, and retry or rollback when operations fail to ensure system status consistency.
