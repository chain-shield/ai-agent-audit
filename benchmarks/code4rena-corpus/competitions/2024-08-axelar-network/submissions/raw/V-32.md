# Vulnerability details

## Impact
The missing check for whether `_allowance` is less than the `amount` in the `_spendAllowance` function can lead to critical security vulnerabilities in the token contract. Specifically, it creates the risk of an underflow, which can cause the allowance to wrap around to a very large value instead of reverting when attempting to subtract more than the available allowance. This would allow a spender to spend more tokens than they were authorized to, potentially draining the balance of the sender and leading to significant loss of funds. This flaw violates the expected behavior of ERC20 tokens, where transactions should revert if a spender attempts to transfer more than their allowed amount.

## Proof of Concept
```solidity
function _spendAllowance(address sender, address spender, uint256 amount) internal override {
    uint256 _allowance = allowance[sender][spender];

    if (_allowance != UINT256_MAX) {
        _approve(sender, spender, _allowance - amount);
    }
}
```

## Recommended Mitigation Steps
To prevent this vulnerability, it is essential to add a check that ensures `_allowance` is greater than or equal to `amount` before performing the subtraction. The modified function should look like this:

```solidity
function _spendAllowance(address sender, address spender, uint256 amount) internal override {
    uint256 _allowance = allowance[sender][spender];

    if (_allowance != UINT256_MAX) {  
       if(_allowance < amount){
           revert InsufficientAllowance(spender,_allowance  , value);      
    }
    unchecked {
       _approve(sender, spender, _allowance - amount);
     }
}
```
