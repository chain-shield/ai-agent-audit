# Vulnerability details

## Vulnerability Details
The `GatewayCaller` contract is designed to facilitate cross-chain calls using the Axelar network. The `callContractWithToken` function is meant to make a cross-chain call while also transferring tokens.

The function does not verify if the caller has approved the contract to spend the specified amount of tokens before making the cross-chain call.

The function accepts parameters for token symbol and amount but does not perform any checks to ensure that:
1. The caller has the specified amount of tokens.
2. The caller has approved the `GatewayCaller` contract to spend these tokens.

## Code Snippet

```solidity
function callContractWithToken(
    string calldata destinationChain,
    string calldata destinationAddress,
    bytes calldata payload,
    string calldata symbol,
    uint256 amount,
    MetadataVersion metadataVersion,
    uint256 gasValue
) external payable override {
    // ... (gas payment logic)

    gateway.callContractWithToken(destinationChain, destinationAddress, payload, symbol, amount);
}
```

## Impact
1. The function may fail at the Axelar gateway level if the token transfer cannot be completed.
2. This could lead to inconsistent state where gas is paid, but the actual cross-chain call fails.
3. Users might mistakenly believe their transaction was successful when it actually failed due to token transfer issues.

## Scenario
1. Alice calls `callContractWithToken` with 100 tokens of symbol "ABC".
2. Alice has 100 ABC tokens but hasn't approved the `GatewayCaller` contract.
3. The function processes the gas payment successfully.
4. The call to `gateway.callContractWithToken` fails because it can't transfer the tokens.
5. Alice loses gas but the cross-chain call doesn't happen.

## Fix
Add token approval checks before making the cross-chain call. This involves:
1. Interfacing with the token contract to check balance and allowance.
2. Reverting the transaction if the caller doesn't have sufficient balance or allowance.
