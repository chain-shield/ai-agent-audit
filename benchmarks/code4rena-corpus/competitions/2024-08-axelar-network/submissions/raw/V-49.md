# Vulnerability details


## Description

The `InterchainTokenFactory` contract contains a critical function [`deployInterchainToken()`](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/interchain-token-service/contracts/InterchainTokenFactory.sol#L126-L161) responsible for deploying new interchain tokens. This function handles the initial setup of the token, including assigning the minter and configuring flow limiter settings. However, the current implementation has a logical flaw that can lead to inconsistent token management.

The function takes several parameters, including `initialSupply` and `minter`. The issue arises from the conditional execution of minter assignment and flow limiter configuration based solely on the `initialSupply` value. Specifically:

1. If `initialSupply > 0`, the contract sets itself as the initial minter, mints tokens, transfers mintership, and configures flow limiters.
2. If `initialSupply == 0`, regardless of the `minter` parameter, no minter assignment or flow limiter configuration occurs.

This logic creates a scenario where a token can be deployed with a specified `minter`, but the minter is not actually assigned if `initialSupply` is zero. The relevant code snippet is:


This inconsistency can lead to tokens being deployed without proper minter assignment or flow limiter settings, potentially compromising the intended token management structure.

## Impact

The inconsistent handling of minter assignment and flow limiter settings can lead to several issues:

- Tokens deployed with zero initial supply will lack proper minter assignment, potentially rendering them unmanageable or requiring additional transactions to set up correctly.
- Flow limiter settings will not be configured for tokens with zero initial supply, which could lead to unexpected behavior in token transfers or other operations that rely on these settings.


## Proof of Concept

1. Alice calls `deployInterchainToken()` with the following parameters:
   - `initialSupply` = 0
   - `minter` = Alice's address (non-zero)
2. The function executes, deploying a new token.
3. The `if (initialSupply > 0)` condition is not met, so the minter assignment and flow limiter configuration are skipped.
4. The resulting token has no assigned minter, despite Alice specifying her address as the minter.
5. Alice attempts to mint tokens but fails because she is not the minter.

## Tools Used

Manual review

## Recommended Mitigation Steps

Decouple the handling of the `minter` parameter and the flow limiter logic from the `initialSupply` condition to ensure consistent behavior.
