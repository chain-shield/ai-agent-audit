# Vulnerability details

## Vulnerability Details

The `BaseWeightedMultisig` contract is designed to implement a weighted multisig system with support for signer rotation. The `_validateProof` function is crucial for validating multisig proofs.

The `_validateProof` function is vulnerable to signature replay attacks. It does not include any mechanism to prevent the reuse of valid signatures across different transactions or time periods.

The function validates the signers and their signatures but doesn't incorporate any unique identifier for each transaction or a nonce. This means that once a valid signature is created, it can be reused for different transactions as long as the signer set remains valid.

## Code Snippet

```solidity
function _validateProof(bytes32 dataHash, Proof calldata proof) internal view returns (bool isLatestSigners) {
        BaseWeightedMultisigStorage storage slot = _baseWeightedMultisigStorage();

        WeightedSigners calldata signers = proof.signers;

        bytes32 signersHash = keccak256(abi.encode(signers));
        uint256 signerEpoch = slot.epochBySignerHash[signersHash];
        uint256 currentEpoch = slot.epoch;

        isLatestSigners = signerEpoch == currentEpoch;

        if (signerEpoch == 0 || currentEpoch - signerEpoch > previousSignersRetention) revert InvalidSigners();

        bytes32 messageHash = messageHashToSign(signersHash, dataHash);

        _validateSignatures(messageHash, signers, proof.signatures);
    }
}
```

## Impact
An attacker could replay a valid signature to execute multiple transactions or repeat the same transaction, potentially leading to unauthorized actions or fund losses.

## Scenario
1. A valid multisig transaction is signed by the required signers.
2. The transaction is executed successfully.
3. An attacker captures these signatures.
4. The attacker reuses these signatures to execute the same or a different transaction without obtaining new approvals from the signers.

## Fix
Introduce a nonce or unique identifier for each transaction. This could be implemented as follows:

1. Add a `nonce` field to the `BaseWeightedMultisigStorage` struct:
```solidity
struct BaseWeightedMultisigStorage {
    // ... (existing fields)
    uint256 nonce;
}
```

2. Modify the `_validateProof` function to include the nonce in the message hash:
```solidity
function _validateProof(bytes32 dataHash, Proof calldata proof) internal returns (bool isLatestSigners) {
    BaseWeightedMultisigStorage storage slot = _baseWeightedMultisigStorage();
    
    // ... (existing code)

    bytes32 messageHash = messageHashToSign(signersHash, dataHash, slot.nonce);

    _validateSignatures(messageHash, signers, proof.signatures);

    // Increment nonce after successful validation
    slot.nonce++;
}
```

3. Update the `messageHashToSign` function:
```solidity
function messageHashToSign(bytes32 signersHash, bytes32 dataHash, uint256 nonce) public view returns (bytes32) {
    return keccak256(bytes.concat('\x19Ethereum Signed Message:\n128', domainSeparator, signersHash, dataHash, abi.encodePacked(nonce)));
}
```

This fix ensures that each signature is only valid for a single transaction, preventing replay attacks and significantly improving the security of the multisig system.
