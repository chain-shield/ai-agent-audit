# Vulnerability details

## Impact

In `execute.rs` of Axelarnet Gateway, it's said that apps are required to implement  `AxelarExecutableMsg::Execute` interface. The problem is that in ITS Hub there is no such interface explicitly exposed. This goes in deviation with the spec and causes the problem when executing the message.


## Proof of Concept

In `execute.rs` you can see the following:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L137-144
```
let executable: AxelarExecutableClient =
        client::Client::new(querier, destination_contract).into();

    // Call the destination contract
    // Apps are required to expose AxelarExecutableMsg::Execute interface
    Ok(Response::new()
        .add_message(executable.execute(msg.cc_id.clone(), msg.source_address.clone(), payload))
        .add_event(AxelarnetGatewayEvent::MessageExecuted { msg }.into()))
```

The problem here is that the ITS Hub app does not implement `AxelarExecutableMsg::Execute interface` which makes it impossible to execute the message.


## Tools Used

Manual review.

## Recommended Mitigation Steps

Implement `AxelarExecutableMsg::Execute` interface in the ITS Hub app.
