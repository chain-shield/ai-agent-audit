# Vulnerability details

## Impact
With some tokens [takeToken](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L91-L123) will revert, preventing them from being bridged.

## Proof of Concept
[takeToken](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L91-L123) is used by token service to pull tokens from users before they are bridged. That function will revert with some tokens because it tries to assign `.symbol()` to a string value, but some tokens like [MKR](https://github.com/d-xo/weird-erc20?tab=readme-ov-file#non-string-metadata) use bytes as their name and symbol.

```solidity
    } else if (tokenManagerType == uint256(TokenManagerType.GATEWAY)) {
        symbol = IERC20Named(tokenAddress).symbol();
        _transferTokenFrom(tokenAddress, from, address(this), amount);
```

This will cause [takeToken](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L91-L123) to revert, which in tern reverts the bridging TX.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Handle the name as bytes, or use a try/catch.
