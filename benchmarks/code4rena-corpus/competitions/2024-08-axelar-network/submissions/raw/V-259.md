# Vulnerability details

## Vulnerability Details

The `TokenManagerProxy` contract's constructor is responsible for initializing the proxy and setting up the connection to the correct implementation. There's an issue in how the constructor attempts to call `getTokenAddressFromParams` on the implementation contract.

## Code Snippet

```solidity
tokenAddress = IBaseTokenManager(implementation_).getTokenAddressFromParams(params);
```

## Impact

This line attempts to call a function on the implementation contract directly, rather than through a delegatecall. This is problematic because:

1. The `implementation_` address is used in the context of the proxy, not as the actual contract to call.
2. This call won't use the proxy's storage, which may lead to incorrect state reads/writes.
3. It may fail entirely if the implementation contract doesn't have this function publicly accessible.


## Scenario

When deploying the `TokenManagerProxy`, the constructor will likely revert when trying to set the `tokenAddress`, preventing the contract from being deployed successfully.

## Fix
Instead of calling the implementation directly, use another delegatecall to get the token address:

```solidity
bytes memory data = abi.encodeWithSelector(IBaseTokenManager.getTokenAddressFromParams.selector, params);
(bool success, bytes memory result) = implementation_.delegatecall(data);
require(success, "Failed to get token address");
tokenAddress = abi.decode(result, (address));
```
