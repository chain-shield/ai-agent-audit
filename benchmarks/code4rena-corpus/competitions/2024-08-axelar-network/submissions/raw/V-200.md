# Vulnerability details

## Impact
Hardcoding refund address to be the tx.origin may cause refunded amount to be lost in some cases 

## Bug Description 
`GasService` is the  smart contract that manages gas payments and refunds for cross-chain communication on the Axelar network. It allows an application to prepay gas fees on the source chain and increase the gas paid for a transaction. If too much gas is paid for a transaction, it can calculate and refund the sender. `gasService.payNativeGasForContractCall()` is called during the execution of interchain token transfers and remote token deployment or remote executions via the `interchainTokenService` contract. The `interchainTokenService` contract's [_callContract()](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L816-L835) function actually does a delegate call to `GatewayCaller.callContract()` to achieve this.

Hardcoding refund address to be the tx.origin as it is done here may cause refunded amount to be lost in some cases, especially in the cases of smart wallets/ meta transactions where the tx.origin is the relayer or bundler. This will mean the refund is not sent to the user but to the relayer/bundler. 

Take an instance where a user instructs the relayer/bundler to execute an interchain transfer or remote token deployment at a later time and the user sends the eth gas amount needed for the action to the relayer/bundler. At the set time the transaction is executed by the relayer/bundler, but the eth gas amount sent in is not all used up, so the refund of the remainder eth is then sent to the tx.origin which in this case is the relayer/bundler. The user cannot claim the eth from the relayer/bundler and so the ether value refunded is lost. 

It is better to allow users to specify their refund addresses so as to avoid sending refunds to the wrong addresses
