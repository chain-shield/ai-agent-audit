# Vulnerability details

## Impact
Any user can call the update_trusted_address method, which may cause malicious users to arbitrarily change trusted addresses, thus threatening system security. This will disrupt the normal process of cross-chain operations and enable unauthorized addresses to operate.

## Proof of Concept

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/contract/execute.rs#L148

Currently there is no permission check in the update_trusted_address method, which means that any user can call this function to update a trusted address:
```
pub fn update_trusted_address(
    deps: DepsMut,
    chain: ChainName,
    address: Address,
) -> Result<Response, Error> {
    save_trusted_address(deps.storage, &chain, &address)
        .change_context(Error::InvalidStoreAccess)?;

    Ok(
        Response::new()
            .add_event(ItsContractEvent::TrustedAddressUpdated { chain, address }.into()),
    )
}
```


## Tools Used

## Recommended Mitigation Steps

Add permission checks to ensure that only authorized users can call the update_trusted_address method.
You can limit the caller's access to this method through role management or permission control mechanisms.
