# Vulnerability details

## Impact
The `InterchainTokenService` contract relies on trusted addresses for cross-chain communication. If the trusted addresses are misconfigured or not properly validated, it could lead to unauthorized access or incorrect routing of messages. This could result in loss of funds, unauthorized token transfers, or disruption of the interchain token service.

## Proof of Concept
The `setTrustedAddress` and `removeTrustedAddress` functions allow the owner to set and remove trusted addresses:

```solidity
function setTrustedAddress(string memory chain, string memory address_) external onlyOwner {
    _setTrustedAddress(chain, address_);
}

function removeTrustedAddress(string memory chain) external onlyOwner {
    _removeTrustedAddress(chain);
}
```

If the owner accidentally sets an incorrect address or removes a necessary trusted address, it could lead to security issues or service disruptions.

## Tools Used
Manual code review

## Recommended Mitigation Steps
To mitigate the risk of misconfiguration of trusted addresses, consider implementing the following measures:

1. **Validation of Trusted Addresses**: Add validation checks to ensure that the provided addresses are valid and meet certain criteria before setting them as trusted addresses.

2. **Event Emission**: Emit events when trusted addresses are set or removed to provide transparency and allow for off-chain monitoring.

3. **Multisig Approval**: Require multisig approval for setting or removing trusted addresses to reduce the risk of accidental or malicious changes.

4. **Time-Lock Mechanism**: Implement a time-lock mechanism for changes to trusted addresses, allowing for community oversight and potential intervention before the changes take effect.

Example implementation of validation and event emission:

```solidity
event TrustedAddressSet(string chain, string address_);
event TrustedAddressRemoved(string chain);

function setTrustedAddress(string memory chain, string memory address_) external onlyOwner {
    require(bytes(chain).length > 0, "Invalid chain name");
    require(bytes(address_).length > 0, "Invalid address");

    _setTrustedAddress(chain, address_);
    emit TrustedAddressSet(chain, address_);
}

function removeTrustedAddress(string memory chain) external onlyOwner {
    require(bytes(chain).length > 0, "Invalid chain name");

    _removeTrustedAddress(chain);
    emit TrustedAddressRemoved(chain);
}
```

By implementing these changes, you can reduce the risk of misconfiguration of trusted addresses and enhance the security and reliability of the interchain token service.
