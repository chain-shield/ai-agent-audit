# Vulnerability details

When the ITS Hub receives an ITS message to process, it always calls the `apply_balance_tracking` function to either track or initiate tracking of the token balance on a chain based on the `ItsMessage`. For both `ItsMessage::DeployInterchainToken` and `ItsMessage::DeployTokenManager` messages, the function attempts to start balance tracking by calling `start_token_balance`. However, `start_token_balance` will fail if balance tracking has already been initiated. Consider the following scenario:

1. The ITS Hub receives an `ItsMessage::DeployInterchainToken` message. The Hub initiates balance tracking and sets it to `TokenBalance::Tracked(Uint256::zero())`.
2. Subsequently, the ITS Hub receives an `ItsMessage::DeployTokenManager` message to deploy a token manager for the already deployed interchain token. 

In this scenario, step 2 will always fail because the ITS Hub attempts to initiate balance tracking by setting it to `TokenBalance::Untracked` (as tracking is unnecessary when a token manager is present). However, since balance tracking was already initiated in step 1, the `start_token_balance` function will return an error.

## Impact
Deploying a token manager for an interchain token, or vice versa, will always fail in the ITS Hub. Having a token manager for an interchain token is a core functionality, and since the ITS Hub contract is a crucial component of a cross-chain ITS protocol, this issue severely impacts the overall functionality and reliability of the system.

For both `ItsMessage::DeployInterchainToken` and `ItsMessage::DeployTokenManager`, the function attempts to start token balance tracking:
```rust

    storage: &mut dyn Storage,
    source_chain: ChainName,
    destination_chain: ChainName,
    message: &ItsMessage,
) -> Result<(), Error> {
    match message {
        ...
        ItsMessage::DeployInterchainToken { token_id, .. } => {
@>          start_token_balance(storage, token_id.clone(), destination_chain.clone(), true)

        ItsMessage::DeployTokenManager { token_id, .. } => {
@>          start_token_balance(storage, token_id.clone(), destination_chain.clone(), false)
                .change_context(Error::InvalidStoreAccess)?

```

## Recommended Mitigation Steps
Before initiating token balance tracking, first check if it has already been initiated. When processing an `ItsMessage::DeployTokenManager`, if the balance is already initiated, update the tracking status to `TokenBalance::Untracked` instead of attempting to reinitialize it.
