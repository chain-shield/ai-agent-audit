# Vulnerability details

## Impact

In `execute.rs` contract of the ITS Hub, there is a function `apply_balance_tracking()` that tracks the balance of the token on both chains and also initializes tracking of the balances if it's deployment call. The problem is that it does not account for fee-on-transfer tokens on the destination chain as it just increases the balance on the source chain and decreases on the destination chain on the same amount. This will be an issue if the token implements fee-on-transfer mechanics as the amount will be decreased again when token is repeatedly transferred on the destination chain.

## Proof of Concept

Take a look at the `apply_balance_tracking()` functionality:

```
   // Update the balance on the source chain
            update_token_balance(
                storage,
                token_id.clone(),
                source_chain.clone(),
                *amount,
                false,
            )
            .change_context_lazy(|| Error::BalanceUpdateFailed(source_chain, token_id.clone()))?;

            // Update the balance on the destination chain
            update_token_balance(
                storage,
                token_id.clone(),
                destination_chain.clone(),
                *amount,
                true,
            )

```

It first updates the amount on the source chain and does this correct as fees are already taken for fee-on-transfer tokens when taking the tokens from user in `TokenHandler`:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L110-111
```
} else if (tokenManagerType == uint256(TokenManagerType.LOCK_UNLOCK_FEE)) {
            amount = _transferTokenFromWithFee(tokenAddress, from, tokenManager, amount);
```

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L193-202
```
  uint256 balanceBefore = IERC20(tokenAddress).balanceOf(to);

        _transferTokenFrom(tokenAddress, from, to, amount);

        uint256 diff = IERC20(tokenAddress).balanceOf(to) - balanceBefore;
        if (diff < amount) {
            amount = diff;
        }

        return amount;
```

The problem is that when tokens are given to the destination address on the destination chain, the fees are taken again so that the amount is not the same as it was on the source chain and it's not the same as it was reflected in ITS Hub contract:

`giveToken()` function

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L68-71
```
if (tokenManagerType == uint256(TokenManagerType.LOCK_UNLOCK_FEE)) {
            amount = _transferTokenFromWithFee(tokenAddress, tokenManager, to, amount);
            return (amount, tokenAddress);
        }
```

ITS Hub only reflects the amount from the source chain but on the destination chain it does not take fees into account and reflects incorrect amount.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Make sure ITS Hub takes into account fee-on-transfer tokens and correctly reflects the transferred amount.
