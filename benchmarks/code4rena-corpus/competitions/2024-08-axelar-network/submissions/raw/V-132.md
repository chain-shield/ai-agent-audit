# Vulnerability details

## Impact
The protocol is not compatible with rebasing tokens, leading to two major impacts:
- Users lose potential token yields.
- Rebasing tokens become stuck in the tokan manager contract.

## Proof of Concept
Per to doc rebasing token is in scope
>Balance changes outside of transfers In scope

Let's take aave as example:
>Aave enables users to supply and borrow digital assets through liquidity pools. Suppliers receive protocol-issued aTokens, holding the user’s supplied assets and accrued yield. 

`aTokens` can be register via [registerCanonicalInterchainToken]() function. The default manager type is `TokenManagerType.LOCK_UNLOCK`. Which means `aTokens` can be unlocked on source chain and minted on other chains if it's transfered.

[https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenFactory.sol#L249-L256](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenFactory.sol#L249-L256)
```solidity
function registerCanonicalInterchainToken(address tokenAddress) external payable returns (bytes32 tokenId) {
    bytes memory params = abi.encode('', tokenAddress);

    if (_isGatewayToken(tokenAddress)) revert GatewayToken(tokenAddress);

    bytes32 salt = canonicalInterchainTokenSalt(chainNameHash, tokenAddress);
    tokenId = interchainTokenService.deployTokenManager(salt, '', TokenManagerType.LOCK_UNLOCK, params, 0);
}
```

Per to aave's features,`aTokens` holders can receive yield which comes from:
- Lending Interes
- Flash Loan Fees
- Protocol Incentives
- Liquidation Fees

However when user makes a interchain transfer,convert interchain token back to `aTokens` those yiled is ignored,result in user lost token yield and those yiled get stuck in contract.
