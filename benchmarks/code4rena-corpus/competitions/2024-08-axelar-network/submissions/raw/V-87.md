# Vulnerability details

## Description
The `_validateProof` function is responsible for validating the proof data against the signers who are supposed to have signed a particular command. It ensures that the signers' combined weight meets the required threshold and that the proof is associated with the most recent set of signers (determined by the current epoch). However, the function does not currently check for the presence of duplicate signers within the signers array.

```solidity
function _validateProof(bytes32 dataHash, Proof calldata proof) internal view returns (bool isLatestSigners) {
    BaseWeightedMultisigStorage storage slot = _baseWeightedMultisigStorage();

    WeightedSigners calldata signers = proof.signers;
    bytes32 signersHash = keccak256(abi.encode(signers));
    uint256 signerEpoch = slot.epochBySignerHash[signersHash];
    uint256 currentEpoch = slot.epoch;

    isLatestSigners = signerEpoch == currentEpoch;

    if (signerEpoch == 0 || currentEpoch - signerEpoch > previousSignersRetention) revert InvalidSigners();

    bytes32 messageHash = messageHashToSign(signersHash, dataHash);
    _validateSignatures(messageHash, signers, proof.signatures);
}
```


### Vulnerability Details

- The function computes the signersHash and checks it against the recorded epoch data to determine 
 if the proof corresponds to the latest signers.
- However, it does not ensure that all signers within the signers array are unique before proceeding with validation.
- Without this check, an attacker can craft a proof with duplicate signers, which might incorrectly satisfy the weight threshold required for proof validation.

     ###### How This Happens:

  - ***The validateProof function receives a WeightedSigners structure, which includes an array of signer addresses (signers.addresses) and their respective weights.***

  - ***The function checks whether the cumulative weight of the signers meets the required threshold for validating the proof. However, it does not explicitly check if there are duplicate addresses in the signers.addresses array.***

  - ***If an attacker includes the same address multiple times in the signers.addresses array, the cumulative weight calculation might exceed the threshold, even though the proof is not valid according to the intended rules of the contract.***
> The validateProof function is responsible for verifying that the proof submitted to the contract is signed by a valid set of signers.

In this scenario, we will explore how an attacker can exploit the absence of a duplicate signer check in the _validateProof function. By submitting a Proof that includes duplicate entries in the signers array. 

## Proof of Concept
   ###### Epoch 1: Initial Signer Set
          - Setup:

***In Epoch 1, the contract begins with an initial set of signers: A, B, and C.
Each signer has an equal weight, and the combined weight of all three signers is required to meet or exceed a certain threshold to validate a proof.***

        -  Mappings:
```signerHashByEpoch[1] = hash(SignerSet1), where SignerSet1 = [A, B, C].
epochBySignerHash[hash(SignerSet1)] = 1.
```
***These mappings associate the signer set with Epoch 1 and allow the contract to verify proofs signed by this set.***

         - Usage:
***During Epoch 1, any proof submitted for validation must be signed by a combination of A, B, and C whose combined weight meets the required threshold.***

   ###### Epoch 2: New Signer Set
        - Rotation of Signers:

***The contract undergoes a rotation of signers, resulting in a new set of signers: D, E, and F.
This rotation is necessary to maintain the security of the system by periodically updating the authorized signers.***

         - Updated Mappings:

```signerHashByEpoch[2] = hash(SignerSet2), where SignerSet2 = [D, E, F].
epochBySignerHash[hash(SignerSet2)] = 2.
```
***These mappings update the association of the new signer set with Epoch 2.***

         - Usage:

***For any proof submitted during Epoch 2, it must be validated by signers D, E, and F whose combined weight meets the threshold.
The proof validation ensures that the current epoch's signer set has signed off on the transaction, maintaining the chain of trust.***

*Attack Scenario:* Exploiting the Lack of Duplicate Signer Checks

           - Attacker's Goal:

***The attacker seeks to manipulate the approveMessages function by submitting a proof that the contract should not consider valid.
The attacker's aim is to bypass the intended threshold of signer weight required for validation by exploiting the absence of a duplicate signer check.***

           - Crafting the Malicious Proof:
***The attacker is aware that during Epoch 2, the required signer set is D, E, and F.
The attacker constructs a malicious Proof object where the signers array includes duplicate entries: [D, D, E].
Here, D appears twice, and E appears once. Since there is no check for duplicate signers, the contract might erroneously treat this as a legitimate proof.***

 ###### Why This Works:

***The `_validateProof` function computes the weight of the signers by summing up the weights of all entries in the signers array. Since D appears twice, the weight contributed by D is counted twice.
Suppose the weight threshold required for validation is 3. If D and E each have a weight of 2, the total weight from [D, D, E] would be 4, which exceeds the required threshold.***

### Impact
The acceptance of such a malicious proof could result in unauthorized message approvals and invalid signer rotations.

## Recommended Mitigation Steps
To prevent this type of attack, the `_validateProof` function must be modified to include a check for duplicate signers in the signers array before proceeding with the weight calculation and validation. This ensures that each signer is counted only once, preserving the integrity of the multi-signature validation process.

```solidity
function _validateProof(bytes32 dataHash, Proof calldata proof) internal view returns (bool isLatestSigners) {
    BaseWeightedMultisigStorage storage slot = _baseWeightedMultisigStorage();

    WeightedSigners calldata signers = proof.signers;

    // Check for duplicate signers
 +++   uint256 signersLength = signers.addresses.length;
+++    for (uint256 i = 0; i < signersLength - 1; i++) {
 +++       for (uint256 j = i + 1; j < signersLength; j++) {
   +++         if (signers.addresses[i] == signers.addresses[j]) {
  +++              revert DuplicateSigners(keccak256(abi.encode(signers)));
            }
        }
    }

    bytes32 signersHash = keccak256(abi.encode(signers));
    uint256 signerEpoch = slot.epochBySignerHash[signersHash];
    uint256 currentEpoch = slot.epoch;

    isLatestSigners = signerEpoch == currentEpoch;

    if (signerEpoch == 0 || currentEpoch - signerEpoch > previousSignersRetention) revert InvalidSigners();

    bytes32 messageHash = messageHashToSign(signersHash, dataHash);
    _validateSignatures(messageHash, signers, proof.signatures);
}
```
