# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The omission of the override specifier in an overriding function leads to a compilation error, rendering the contract non-deployable. This disrupts the deployment pipeline and prevents the contract from being tested or executed on the blockchain. The absence of the override specifier also increases the risk of introducing bugs during future contract maintenance.

In Solidity, when a function in a contract overrides a function from a parent contract or an interface, the override keyword must be used. The override specifier explicitly tells the compiler that the function is intended to replace a function with the same signature in a base contract or interface. Failing to include this keyword results in a compilation error.

This error occurs because the lastRotationTimestamp function in the BaseWeightedMultisig contract is meant to override a function defined in the IBaseWeightedMultisig interface. The lack of the override specifier prevents the Solidity compiler from correctly linking the function to its parent, causing a fatal error during compilation.

## Recommended Mitigation Steps

To fix this issue, add the override keyword to the function declaration in the BaseWeightedMultisig contract. This explicitly indicates to the compiler that the function is intended to override a function in an interface or base contract, thereby resolving the compilation error.

The corrected function in the BaseWeightedMultisig contract should be:
```sol
// In BaseWeightedMultisig.sol

function lastRotationTimestamp() external view override returns (uint256) {
    return _baseWeightedMultisigStorage().lastRotationTimestamp;
}
```

By including the override specifier, the Solidity compiler will correctly process the function as an override, allowing the contract to compile and function as expected.
