# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The omission of the override specifier for a public state variable that overrides a function in a base contract or interface results in a compilation error. This issue prevents the contract from being deployed or executed, thereby disrupting the deployment process and potentially leading to confusion or errors during contract maintenance.

In Solidity, when a public state variable in a contract shadows or overrides a function from a parent contract or interface, the override keyword must be used. The override specifier informs the compiler that the state variable is intentionally replacing the function defined in a base contract or interface. Failing to include the override specifier causes the Solidity compiler to produce an error.

The specific error reported by the Solidity compiler is:
```sol
[ERROR]: Solc experienced a fatal error.

TypeError: Overriding public state variable is missing "override" specifier.
  --> .../2024-08-axelar-network/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol:27:5:
   |
27 |     uint256 public immutable previousSignersRetention;
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
Note: Overridden public state variable is here:
  --> .../2024-08-axelar-network/axelar-gmp-sdk-solidity/contracts/interfaces/IBaseWeightedMultisig.sol:21:5:
   |
21 |     function previousSignersRetention() external view returns (uint256);
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```

This error occurs because the previousSignersRetention state variable in the BaseWeightedMultisig contract is meant to override a function defined in the IBaseWeightedMultisig interface. Without the override specifier, the compiler cannot correctly recognize the state variable as an override, leading to a fatal error during compilation.

## Recommended Mitigation Steps

To resolve this issue, add the override keyword to the state variable declaration in the BaseWeightedMultisig contract. This explicitly indicates that the state variable is intended to override a function in the base contract or interface, allowing the compiler to correctly link the two.

The state variable should be updated as follows:
```sol
// In BaseWeightedMultisig.sol

uint256 public immutable override previousSignersRetention;
```

By including the override specifier, the Solidity compiler will correctly recognise the state variable as an override, enabling the contract to compile and function as intended.
