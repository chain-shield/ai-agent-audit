# Vulnerability details

## Impact
[_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192) has a critical revert that will revert every time and even prevent [rotateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L96) to be called. This will brick the whole signers mechanic, stopping singers from approving messages or being rotated.

## Proof of Concept
[_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192-L234) makes sure the signatures are valid, but has a one very specific requirement, and that is for the signatures to be just enough to cover the threshold. Meaning that if 4/ signatures are enough to cover the threshold the function will revert.

```solidity
    if (totalWeight >= weightedSigners.threshold) {
        if (i + 1 == signaturesLength) return;

        revert RedundantSignaturesProvided(i + 1, signaturesLength);
    }
```

However [_validateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L259-L289) - the function that validates the signers and their weight when they are committed, doesn't make this specific check. This means that signers who's signatures revert every time can be submitted and will cause a breakdown of the system.

That is because [_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192-L234) is used in [_validateProof](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L114-L130) which in tern is used in [approveMessages](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L80-L85) and [rotateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L96-L107). 

The only way to fix this issue if it occurs is to [rotateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L96-L107), however since that function also revert, it would be impossible once it takes place.

Example:
1. A new rotation is made with 4 signers A, B, C, D each having 10k weight respectfully 
2. The rotation has threshold of 30k
3. The TX gets send and  [rotateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L96-L107) passes, setting the new signers.


Now these signers will not be able to make any changes, like approving messages or rotating further, as the threshold inside [_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192-L234) is reached.

```solidity
    if (totalWeight >= weightedSigners.threshold) {
        // 2 + 1 == 4 -> false
        if (i + 1 == signaturesLength) return;

        // revert here
        revert RedundantSignaturesProvided(i + 1, signaturesLength);
    }
```

Note that above [rotateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L96-L107) this [comment](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L90-L91) is used:

> The minimum rotation delay is enforced by default, unless the caller is the gateway operator.
> The gateway operator allows recovery in case of an incorrect/malicious rotation, while still requiring a valid proof from a recent signer set.

Indicating that if a bad rotation happens the operator would be able to interrupt the process and make a new rotation. However in the current issue that's not the case, and the operator will not be able to save the rotation.

## Recommended Mitigation Steps
Add a check inside [_validateSigners](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L259-L289) to revert if the weight is excessive.

```diff
    if (weight == 0) revert InvalidWeights();

    totalWeight = totalWeight + weight;

+   if (totalWeight >= weightedSigners.threshold) {
+       if (i + 1 == signaturesLength) continue;
+
+       revert RedundantSignaturesProvided(i + 1, signaturesLength);
+   }
```
