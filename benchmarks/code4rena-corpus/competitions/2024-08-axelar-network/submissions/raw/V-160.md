# Vulnerability details

## Impact
The start_token_balance method lacks proper access control, which means that any user can call this method to initialize token balance tracking. This situation may lead to unauthorized users initializing token balances on any chain, which may have a significant impact on the integrity and security of the system. For example, a malicious user may initialize token tracking on an unrelated chain, resulting in a chaotic system state or inconsistent data.

Unauthorized token initialization may undermine the logical integrity of the system, leading to potential token abuse or misuse, affecting the asset security of users, and may even cause abnormalities in inter-chain operations, further affecting the stability of the entire cross-chain system.

## Proof of Concept

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/state.rs#L139

In the implementation of the start_token_balance method, the caller's permissions are not verified, which means that the method can be called by any user. For example, a malicious user can call this method to initialize the token balance on an unauthorized chain, thereby affecting the state of the system.
```
pub fn start_token_balance(
    storage: &mut dyn Storage,
    token_id: TokenId,
    chain: ChainName,
    track_balance: bool,
) -> Result<(), Error> {
    let key = TokenChainPair { token_id, chain };
    match TOKEN_BALANCES.may_load(storage, key.clone())? {
        None => {
            let initial_balance = if track_balance {
                TokenBalance::Tracked(Uint256::zero())
            } else {
                TokenBalance::Untracked
            };
            TOKEN_BALANCES.save(storage, key, &initial_balance)?;
            Ok(())
        }
        Some(_) => Err(Error::TokenAlreadyRegistered {
            token_id: key.token_id,
            chain: key.chain,
        }),
    }
}
```
In the above code, there is no check to restrict which users can call the start_token_balance method, which means that any user can call this method to initialize or reinitialize the token balance.

## Recommended Mitigation Steps
Add permission control logic to the start_token_balance method to ensure that only authorized users or contract internal logic can call this method. For example, a role management mechanism can be introduced to limit only users with specific permissions to perform this operation.
Validate the input of the chain and token ID to ensure that they are valid and allowed before initialization.
