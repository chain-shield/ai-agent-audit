# Vulnerability details

## Vulnerability Details

The primary objective of the _create3 function is to deploy contracts at deterministic addresses. However, there's a potential issue with the way the deterministic address is calculated in the _create3Address function, which could lead to address collisions.

The _create3Address function calculates two deterministic addresses:deployer: The address of the CreateDeploy helper contract.deployed: The final address where the target contract will be deployed.

Both of these addresses are derived using the keccak256 hash function on encoded data that includes a constant prefix, the address of the current contract (address(this)), the deployment salt, and, in the case of deployer, the hash of the CreateDeploy contract's bytecode.The potential issue lies in the fact that the address(this) is included in the calculation for both addresses.

If multiple contracts inherit from Create3Fixed and attempt to deploy contracts using the same salt, there's a chance that the deployer addresses for these deployments could collide.

```solidity
function _create3Address(bytes32 deploySalt) internal view returns (address deployed) {
        address deployer = address(
            uint160(uint256(keccak256(abi.encodePacked(hex'ff', address(this), deploySalt, CREATE_DEPLOY_BYTECODE_HASH))))
        );

        deployed = address(uint160(uint256(keccak256(abi.encodePacked(hex'd6_94', deployer, hex'01')))));
    }
}
```


## Scenario
Two contracts, ContractA and ContractB, both inherit from Create3Fixed. Both contracts attempt to deploy new contracts using the same salt value. Due to the inclusion of address(this) in the calculation, the deployer addresses for both deployments could end up being the same.This would lead to a conflict, as only one CreateDeploy contract can exist at that address.One of the deployments would fail, potentially causing unexpected behavior or loss of funds if the deployment was part of a larger transaction.

## Impact
Failed deployments due to address collisions.Unexpected behavior in applications relying on the deterministic deployment of contracts.Potential loss of funds if failed deployments are part of complex transactions.

## Fix

Include a unique identifier for each inheriting contract in the address calculation. This could be a contract-specific salt or a hash of the inheriting contract's bytecode.
