# Vulnerability details

## Impact
The ``deployInterchainToken`` function in the ``InterchainTokenFactory`` contract is marked as ``payable`` but lacks any validation or handling of the ``msg.value``. This can lead to ETH being permanently trapped in the contract, resulting in financial losses for users and potential contract bloat.
The deployInterchainToken function is defined as payable but does not use or check the msg.value. This allows users to send ETH along with their token deployment transaction, but the ETH is not used or accounted for in any way. 
```solidity
function deployInterchainToken(
    bytes32 salt,
    string calldata name,
    string calldata symbol,
    uint8 decimals,
    uint256 initialSupply,
    address minter
) external payable returns (bytes32 tokenId) {
   
    // No check or use of msg.value
}
```

```solidity
contract TestToken {
    InterchainTokenFactory public factory;

    constructor(address _factory) {
        factory = InterchainTokenFactory(_factory);
    }

    function TestDeploy() external payable {
        // Deploy a token while sending 1 ETH
        factory.deployInterchainToken{value: 1 ether}(
            bytes32(0),
            "Test Token",
            "TEST",
            18,
            1000000,
            address(this)
        );
        // The 1 ETH is now trapped in the factory contract
    }
}
```

## Recommended Mitigation Steps
If ETH is not intended to be used in this function, add a check to reject any ETH sent.
```solidity
    require(msg.value == 0, "ETH not accepted for token deployment");
```
Otherwise implement a withdrawal function for any trapped ETH
