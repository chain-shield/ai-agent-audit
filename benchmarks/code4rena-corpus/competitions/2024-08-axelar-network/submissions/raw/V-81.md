# Vulnerability details

`TokenManagerDeployer` & `InterchainTokenDeployer` contracts are used to deploy new instances of the TokenManagerProxy & InterchainTokenProxy contracts respectively.
Both these contracts use the CREATE3 method for deploying.

## Proof of Concept
Inside the `TokenManagerDeployer` contract, the parameters are encoded and passed to the `_create3()`.

```solidity
File: TokenManagerDeployer.sol

   function deployTokenManager(
        bytes32 tokenId,
        uint256 implementationType,
        bytes calldata params
    ) external payable returns (address tokenManager) {
        bytes memory args = abi.encode(address(this), implementationType, tokenId, params);
        // slither-disable-next-line too-many-digits
        bytes memory bytecode = abi.encodePacked(type(TokenManagerProxy).creationCode, args);

>       tokenManager = _create3(bytecode, tokenId);

        if (tokenManager.code.length == 0) revert TokenManagerDeploymentFailed();
    }
```
`create3()` first deploys the CreateDeploy contract using the CREATE2 opcode and then utilizes the CreateDeploy to deploy the new contract with the CREATE opcode.
The `tokenId` is being used as the `deploySalt`.

```solidity
File:

    function _create3(bytes memory bytecode, bytes32 deploySalt) internal returns (address deployed) {
        deployed = _create3Address(deploySalt);

        if (bytecode.length == 0) revert EmptyBytecode();
        if (deployed.isContract()) revert AlreadyDeployed();
        ...
```
Incase a contract is already deployed with the same salt, the function reverts.

An issue could be that an attacker can frontrun the deploy transaction with their own deploy request with the same parameters. This would return the exact address created by the `_create3Address()` call, since the parameters and the deploy salt is the same. 
When the victim's transaction is executed, the address being **non-empty** leads to a revert during creation. This would result in a bad UX for a user, who thinks the creation did not succeed. The resultant contract would still be usable, but would be hard to track as it was created in another transaction.
