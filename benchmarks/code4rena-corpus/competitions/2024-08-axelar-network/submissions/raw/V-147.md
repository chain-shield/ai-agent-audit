# Vulnerability details

## Impact
The approveMessages function allows any user to call it and submit a valid proof to approve messages. If a user obtains or observes a valid proof, they can submit the proof on-chain, potentially leading to unauthorized message approvals.

## Proof of Concept
The vulnerability is present in the following section of the contract:
[AxelarAmplifierGateway.sol Line 80-86](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L80-L86)
**No Access Control:** The `approveMessages` function is `external` and lacks any access control, meaning anyone can call it as long as they have a valid proof.

**Example Code Flow:**
1. An attacker monitors the network for valid proofs or exploits an off-chain vulnerability to obtain one.
2. The attacker calls the `approveMessages` function with the valid proof.
3. The `_validateProof` function checks the proof and verifies the signatures, but since there's no restriction on who can call the function, the attacker's call succeeds.
4. The `_approveMessages` function is then executed, approving the messages and potentially triggering unauthorized cross-chain transactions.

## Tools Used
Manual Review

## Recommended Mitigation Steps
**Add Access Control**: Restrict the `approveMessages` function so that only authorized entities, such as specific roles or the operator, can call it. This can be done using OpenZeppelin’s `AccessControl` or by implementing a custom role management
