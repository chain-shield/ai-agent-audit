# Vulnerability details

## Impact
This vulnerability can lead to:

1. Loss of funds for users utilizing smart contract wallets.
2. Potential theft of gas payments intended for cross-chain transactions.
3. Misdirection of refunds to unintended recipients.
4. Loss of trust in the cross-chain messaging system.
5. Possible disruption of cross-chain operations relying on correct gas payments.
## Proof of Concept
The vulnerability exists in the callContract function:

```
function callContract(
    string calldata destinationChain,
    string calldata destinationAddress,
    bytes calldata payload,
    MetadataVersion metadataVersion,
    uint256 gasValue
) external payable override {
    if (gasValue > 0) {
        if (metadataVersion == MetadataVersion.CONTRACT_CALL) {
            gasService.payNativeGasForContractCall{ value: gasValue }(
                address(this),
                destinationChain,
                destinationAddress,
                payload,
                tx.origin  // Vulnerable line
            );
        }
        // ... (similar issue in EXPRESS_CALL case)
    }
    // ... (rest of the function)
}
```
Vulnerability breakdown:
* The function uses tx.origin as the refund address when paying for gas.
* For smart contract wallets, tx.origin will be the EOA that initiated the transaction, not the wallet contract.

To exploit:

1. An attacker monitors the mempool for transactions to popular smart wallet contracts (e.g., Gnosis Safe).
2. When a transaction to callContract is detected, the attacker copies the transaction data.
3. The attacker submits the same transaction from their EOA, front-running the original.
4. The smart wallet executes the transaction, paying for gas.
5. The tx.origin is set to the attacker's address, making them the recipient of any gas refunds.
## Recommended Mitigation Steps
make user set refund address themselves
