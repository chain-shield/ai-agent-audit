# Vulnerability details

## Vulnerability details
The purpose of the `contractCallWithTokenValue` function is: `Returns the amount of token that this call is worth`. The issue is that in order for a user to get the amount, they are looking for, they need to supply the same amount. This is contradictory to the entire purpose of the function and users will be unable to get the value they are looking for.

This function is important as stated by the protocol team: `These functions are queried by the express relayer to determine the value of the ITS call. They are not the main focus of the audit but support the relayer in processing transactions.` Therefore, the express relayer will be hurdled in determining the value of an ITS contract call with token.

## Impact
Due to issues in the logic of the `contractCallWithTokenValue` function, it will be practically unusable.

## Proof of Concept
As we can see in the code, `contractCallWithTokenValue` makes a call to `_checkPayloadAgainstGatewayData`:

```solidity
function contractCallWithTokenValue(
        string calldata sourceChain,
        string calldata sourceAddress,
        bytes calldata payload,
        string calldata symbol,
        uint256 amount
    ) public view virtual onlyRemoteService(sourceChain, sourceAddress) whenNotPaused returns (address, uint256) {
        _checkPayloadAgainstGatewayData(payload, symbol, amount);
        return _contractCallValue(payload);
    }
```

This is problematic, as `_checkPayloadAgainstGatewayData` requires the caller to supply `amount` as a parameter. The `amount` that the user needs to supply is the same as the `amount` that they are querying the function for, contradictory to the purpose of the function.

## Tools Used
Manual review

## Recommended Mitigation Steps
The `_checkPayloadAgainstGatewayData` in `contractCallWithTokenValue` is practically not needed and can be omitted.
