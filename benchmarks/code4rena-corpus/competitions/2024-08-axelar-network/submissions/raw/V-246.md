# Vulnerability details

## Vulnerability Details

The `GatewayCaller` contract, responsible for facilitating cross-chain calls via the Axelar network, contains a critical vulnerability in its gas payment logic. Both `callContract` and `callContractWithToken` functions allow users to specify a `gasValue` for cross-chain transactions but fail to validate that the provided `msg.value` is sufficient to cover this amount. This oversight can lead to failed transactions, potential loss of funds, and disruption of cross-chain communication.

```solidity
// In callContract function
if (gasValue > 0) {
    if (metadataVersion == MetadataVersion.CONTRACT_CALL) {
        gasService.payNativeGasForContractCall{ value: gasValue }(
            address(this),
            destinationChain,
            destinationAddress,
            payload,
            tx.origin
        );
    } else if (metadataVersion == MetadataVersion.EXPRESS_CALL) {
        gasService.payNativeGasForExpressCall{ value: gasValue }(
            address(this),
            destinationChain,
            destinationAddress,
            payload,
            tx.origin
        );
    } else {
        revert InvalidMetadataVersion(uint32(metadataVersion));
    }
}

// Similar structure in callContractWithToken function
```

The absence of a `require(msg.value >= gasValue)` check before the gas payment logic allows users to initiate cross-chain calls with insufficient funds. This can result in:

1. Silent failure of gas payments
2. Execution of `gateway.callContract` or `gateway.callContractWithToken` without proper gas allocation
3. Potential loss or stuck transactions on the destination chain

## Impact

1. **Failed Transactions**: Gas payment transactions will revert if `msg.value` is insufficient, wasting gas and potentially confusing users.
2. **Cross-Chain Message Disruption**: Messages may be sent to the destination chain without adequate gas, leading to stuck or dropped transactions.
3. **Broken Contract Invariants**: The implicit assumption that sufficient funds are provided for gas payments is violated, reducing contract reliability and predictability.
4. **Poor User Experience**: Users may believe their cross-chain calls were successful when they actually failed due to insufficient gas payment.
5. **Potential Fund Loss**: In cases where partial execution occurs, users might lose funds without achieving their intended cross-chain operation.

## Scenario

1. User calls `callContract` with `gasValue` set to 1 ether.
2. User only sends 0.5 ether as `msg.value`.
3. The contract attempts to execute `gasService.payNativeGasForContractCall` with 1 ether.
4. This sub-call reverts due to insufficient funds.
5. The main transaction continues, calling `gateway.callContract` without proper gas allocation.

## Fix

Add a require statement at the beginning of the gas payment logic in both `callContract` and `callContractWithToken` functions:

```solidity
if (gasValue > 0) {
    require(msg.value >= gasValue, "Insufficient funds for gas payment");
    // Existing gas payment logic follows
}
```
