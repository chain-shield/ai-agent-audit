# Vulnerability details

## Vulnerability Details

The InterchainTokenFactory contract enforces the use of canonical tokens for cross-chain transfers within the Axelar network. While this approach streamlines token management and ensures consistency across chains, it limits flexibility in customizing token behavior for specific blockchain environments.

The contract's design prevents a single token from having different characteristics (e.g., transaction fees, governance models, privacy features) on different blockchains.


## Impact
Projects requiring tailored token behavior across chains are restricted. For instance, a gaming token may need faster transactions and lower fees on a gaming-optimized chain, but higher security on a main chain. Similarly, financial tokens may need to comply with varying regulatory requirements on different chains.

## Scenario

- A project wants to deploy a token that needs faster transaction speeds on Chain A and higher security on Chain B.
- Using deployInterchainToken, they create a token with baseline parameters.
- They attempt to register this token as canonical on both chains using registerCanonicalInterchainToken.
- The canonical token's behavior is now fixed across both chains, preventing the project from implementing the desired chain-specific optimizations.

## Fix

- Introduce a mechanism for chain-specific token extensions or overrides: Allow projects to deploy additional contracts on specific chains that modify the behavior of the canonical token on that chain.

- Consider a more flexible token model: Explore alternatives to the strict canonical token approach, allowing for multiple token versions with shared identity but varying behaviors across chains.
