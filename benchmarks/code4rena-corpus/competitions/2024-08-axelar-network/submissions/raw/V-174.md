# Vulnerability details


### Proof of Concept

Take a look at https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L17-L60

```rust
pub(crate) fn call_contract(
    store: &mut dyn Storage,
    router: &Router,
    chain_name: ChainName,
    sender: Addr,
    destination_chain: ChainName,
    destination_address: Address,
    payload: HexBinary,
) -> Result<Response, Error> {
    let counter = state::increment_msg_counter(store).change_context(Error::InvalidStoreAccess)?;

    let message_id = HexTxHashAndEventIndex {
        tx_hash: PLACEHOLDER_TX_HASH,
        event_index: counter,
    }
    .to_string();

    let cc_id = CrossChainId {
        source_chain: chain_name.into(),
        message_id: nonempty::String::try_from(message_id)
            .change_context(Error::InvalidMessageId)?,
    };

    let payload_hash = Keccak256::digest(payload.as_slice()).into();

    let msg = Message {
        cc_id: cc_id.clone(),
        source_address: Address::try_from(sender.clone().into_string())
            .expect("failed to convert sender address"),
        destination_chain,
        destination_address,
        payload_hash,
    };

    state::save_incoming_msg(store, cc_id, &msg).change_context(Error::InvalidStoreAccess)?;

    let (wasm_msg, events) = route(router, vec![msg.clone()])?;

    Ok(Response::new()
        .add_message(wasm_msg)
        .add_event(AxelarnetGatewayEvent::ContractCalled { msg, payload }.into())
        .add_events(events))
}

```

This function is used in order to initiate a cross chain contract call, now to do this it [increases the message counter](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L26) to be used later on [for unique identification](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L28-L32).

Since when the message is received and needs to be saved [it is saved to the contract's state along with its cc_id, which includes the msg.id.](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L51) This action inherently requires the msg.id to be unique to prevent overwriting existing messages. And then we have to call `route_outgoing_messages()` to process these messages, where [there is a check against the cc_id and stored messages where if they diverge the execution reverts](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/contract/execute.rs#L62-L76).

Now considering the msg_id is stored in a `u32` var.

This allows an attacker to request cross chain calls from the amount already processed up until `uint32.max` on the cheapest supported chain, bloat the queue and then, any next attempt on a cross chain call would revert cause the message Id is not unique, since the incrementation [here](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/contracts/axelarnet-gateway/src/state.rs#L161-L163) would've overflowm the `u32` var:

```rust

pub(crate) fn increment_msg_counter(storage: &mut dyn Storage) -> Result<u32, Error> {
    COUNTER.incr(storage).map_err(Error::from)
}
```

### Impact

An attacker can cause a permanent DOS to cross chain calls, by passing in `call_contract()` requests on the cheapest chain and bloating the queue, causing subsequent calls to have an overflown msg_id and as such non-unique.

The severity here is M considering the amount of `$` this would cost to be achieved, but navigating to the current chains Axelar supports on here: https://axelarscan.io/resources/chains, we can see multiple chains where the average gas fee are in the cents or could even be less than a cent are supported, which coupled with normal integration and scaling would drastically reduce the cost of this being achievable.

### Recommended Mitigation Steps

Have message_id as a u256 instead, this easily makes this attack unreasonable to execute, considering \(2^{224}\) `u32.max` values can fit into a `u256`.
