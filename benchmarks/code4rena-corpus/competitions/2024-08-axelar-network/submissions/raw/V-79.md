# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The Solidity compiler (solc) encountered a fatal error during the compilation of the contract. 

The error was due to a syntax issue caused by using a Solidity version that does not support the new syntax introduced in later versions. 

Specifically, the syntax for the revert statement with custom errors is not supported in Solidity versions prior to 0.8.4.

The root cause of this issue is that the contract uses a Solidity version that does not recognise the syntax for the revert statement with custom error types.

In this case, the pragma directive in the contract is set to a version lower than 0.8.4.

This syntax error prevents the contract from being compiled under certain Solidity versions, leading to a complete loss of functionality for the BaseAmplifierGateway contract. 

The inability to compile the contract means that no further development, testing, or deployment can proceed until the issue is resolved.

This impacts the project by delaying development and potentially causing compatibility issues with other contracts or systems expecting this contract to be functional.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

The issue arises in the following code snippet when using a Solidity version lower than 0.8.4: being 0.8.0.
```sol
function _approveMessages(Message[] calldata messages) internal {
        uint256 length = messages.length;
        if (length == 0) revert InvalidMessages();

        for (uint256 i; i < length; ++i) {
            // Ignores message if it has already been approved before
            _approveMessage(messages[i]);
        }
    }
```

Attempting to compile the contract with a pragma version lower than 0.8.4 will produce the ParserError as described as follows.

The error message produced by the compiler is as follows:
```sol
pragma solidity ^0.8.0;
```

## Recommended Mitigation Steps
To resolve this issue, the Solidity version used in the contract should be updated to a version that supports the revert statement with custom errors. 

The pragma directive should be set to ^0.8.4 or later.

Update the pragma directive in the contract to specify a compatible Solidity version:
```sol
pragma solidity ^0.8.4;
```

By specifying pragma solidity ^0.8.4;, the contract will compile successfully, and the revert statement with custom errors will be correctly recognised by the compiler.
