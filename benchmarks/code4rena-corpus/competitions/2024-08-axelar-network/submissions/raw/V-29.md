# Vulnerability details

## Impact
Approved users can revert [decreaseAllowance](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/interchain-token/ERC20.sol#L123-L126) and prevent their approvers from removing their allowance, essentially causing an approval sandwich. 

## Proof of Concept
The following code shows how [decreaseAllowance](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/interchain-token/ERC20.sol#L123-L126) directly calls [_approve](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/interchain-token/ERC20.sol#L199-L204) with `allowance[msg.sender][spender] - subtractedValue`:

```solidity
    function decreaseAllowance(address spender, uint256 subtractedValue) external virtual returns (bool) {
        _approve(msg.sender, spender, allowance[msg.sender][spender] - subtractedValue);
        return true;
    }
```

However, this call will revert with an underflow if the allowance is smaller than the value to be removed, meaning that the approver will not reduce the balance of the approved user, thus causing an approval sandwich.

Example:
1. Alice has 500 tokens and has given an allowance to Bob for 200 tokens.
2. She doesn't want Bob to spend 200 tokens, so she calls [decreaseAllowance](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/interchain-token/ERC20.sol#L123-L126) and removes 100 tokens from his allowance.
3. Bob front-runs her (or just accidentally spends before the decrease) and spends 110 tokens.
4. Alice's transaction reverts, and Bob still has an allowance of 90 tokens.

## Tools Used
Manual review

## Recommended Mitigation Steps
Make a slight modification to remove the whole allowance if `allowance[msg.sender][spender]` is smaller than `subtractedValue`.

```diff
    function decreaseAllowance(address spender, uint256 subtractedValue) external virtual returns (bool) {
+       if(allowance[msg.sender][spender] > subtractedValue){
+           _approve(msg.sender, spender, allowance[msg.sender][spender] - subtractedValue);
+       } else {
+           _approve(msg.sender, spender, 0);
+       }
-      _approve(msg.sender, spender, allowance[msg.sender][spender] - subtractedValue);
        return true;
    }
```
