# Vulnerability details

## Impact
`expressExecuteWithToken` and `expressExecute`  are used to transfer tokens to `destinationAddress` before `execute` are called on dest chain, and later when `execute` the tokens will be sent to the caller to repay the tokens.

## Proof of Concept
I will take [InterchainTokenService.expressExecute](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L375-L396) as an example, before sending tokens to `destinationAddress`, the only check `InterchainTokenService.expressExecute` perform is to make sure the `commandId` is not executed in [InterchainTokenService.sol#L386](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L386)

And based on onchain tx, the check is not sufficient.
I'll take onchain tx [0x14233d77b1b842ed2966f6e537f1138dc2e1e25a57cd18b5e9b6a9d073d30f8c](https://polygonscan.com/tx/0x14233d77b1b842ed2966f6e537f1138dc2e1e25a57cd18b5e9b6a9d073d30f8c) and [0xa2b449ef4f7ca209ce7d051c6a12f68433450bee6243a57c714e90a9c2fdcb03](https://polygonscan.com/tx/0xa2b449ef4f7ca209ce7d051c6a12f68433450bee6243a57c714e90a9c2fdcb03) as an example.

As show in [InterchainTokenService.sol#L386](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L386), when calling `InterchainTokenService.expressExecute` the function calls `if (gateway.isCommandExecuted(commandId)) revert AlreadyExecuted();` to make sure `commandId` hasn't been executed.
And then according to onchain [tx 0xa2b449ef4f7ca209ce7d051c6a12f68433450bee6243a57c714e90a9c2fdcb03](https://polygonscan.com/tx/0xa2b449ef4f7ca209ce7d051c6a12f68433450bee6243a57c714e90a9c2fdcb03), commandId(0xe0d17b56b8c9103330ceb9df8154d1585d8e92d3a0ef1b2858d7b783c7fab350) is set as executed in [block 60998951](https://polygonscan.com/tx/0xa2b449ef4f7ca209ce7d051c6a12f68433450bee6243a57c714e90a9c2fdcb03)
After that in [block 60998960 tx 0x14233d77b1b842ed2966f6e537f1138dc2e1e25a57cd18b5e9b6a9d073d30f8c](https://polygonscan.com/tx/0x14233d77b1b842ed2966f6e537f1138dc2e1e25a57cd18b5e9b6a9d073d30f8c), commandId(0xe0d17b56b8c9103330ceb9df8154d1585d8e92d3a0ef1b2858d7b783c7fab350) gets executed.

To sum up, in order to use `InterchainTokenService.expressExecute` successfully, Alice has to call `InterchainTokenService.expressExecute` before `block 60998951`(we will use **block 60998950** as example). And then in `block 60998951`, the Axelar Relayer calls `Axelar.Gateway.execute` to set the commandId(0xe0d17b56b8c9103330ceb9df8154d1585d8e92d3a0ef1b2858d7b783c7fab350) as executed. And finally, in `block 60998960`, `InterchainTokenService.execute` is called, in this function, token will sent to Alice instead of `destinationAddress`.

Now please consider reorg happens for polygon, the reorg depth can be [36 block](https://polygonscan.com/block/53035402/f?hash=0xba1e90f7bdc63880443e99ee63f38ec188c2c54cc994c6cca86bfe4b4c007af8).So please consider after reorg:
1. `InterchainTokenService.execute` is called in `block 60998950`
2. Alice calls `InterchainTokenService.expressExecute` in `block 60998951`
3. Axelar Relayer calls `Axelar.Gateway.execute` to set the commandId as executed in `block 60998960`

In such case, Alice's token will be stuck
