# Vulnerability details

## Vulnerability Details

The approveMessages function in the AxelarAmplifierGateway contract is a critical component of the Axelar Network's cross-chain communication protocol. It handles the verification and approval of messages from various source chains, ensuring secure and authorized interactions across the network. However, the current implementation's direct handling of large message arrays within the abi.encode function can lead to scalability issues and negatively impact user experience. 

The gas cost of processing large message arrays within the approveMessages function can become prohibitively high, potentially exceeding the block gas limit. This can result in failed transactions, increased costs for users, delayed interactions, and potential denial-of-service vulnerabilities.

## Impact

**Failed Transactions and Financial Losses:** Users attempting to approve a large batch of messages might experience transaction failures due to exceeding the block gas limit. This results in the loss of transaction fees and potential disruption of critical cross-chain operations.

**Increased Transaction Costs:** Even if transactions succeed, processing large message arrays can lead to significantly higher gas fees, making the contract expensive to use, especially for users with limited resources or those dealing with high-value transactions.

**Delayed or Blocked Interactions:** During periods of high network congestion, transactions with large message arrays might face delays or get stuck in the mempool due to their high gas requirements. This can hinder timely cross-chain communication and negatively impact user experience.

**Denial-of-Service:** Malicious actors could exploit this issue by submitting transactions with massive message arrays, aiming to congest the network and disrupt its operation for legitimate users. 

## Fix

Implement a Merkle tree data structure to efficiently handle large message arrays. By encoding only the Merkle root instead of the entire array, the gas cost can be significantly reduced, ensuring scalability and a smoother user experience. The contract will be able to handle a much larger number of messages per transaction, enabling efficient cross-chain communication even during peak usage.
