# Vulnerability details

## Impact

In the `deployInterchainToken` function of the `InterchainTokenFactory` contract, two potential bugs could lead to the loss of InterchainTokens. The first bug occurs when the minter address is the zero address and the initial supply is not zero. In this case, the `transferMintership`, `addFlowLimiter`, and `transferOperatorship` functions are called with the zero address, which could result in the loss of InterchainTokens. The second bug occurs when the initial supply is zero and the minter address is still the zero address. In this scenario, the `minterBytes` variable will be zero bytes, which will pass to the `_deployInterchainToken` function. In the `interchainTokenService::deployInterchainToken` function, the minter address is declared. If the length of `minterBytes` is zero, the minter address will default to the zero address. This could result in calling the minter as the zero address in the `InterchainTokenDeployer::deployInterchainToken` function, initializing the interchain token with the zero address as the minter in the `InterchainToken::init` function.

## Proof of Concept

### If the minter address is zero and the initial supply is not zero:

If the minter address is zero, the function attempts to transfer mintership, manage the flow limiter, and transfer operatorship to the zero address. This results in the mintership, flow limiter, and operatorship being transferred to the zero address, leading to a loss of control over the interchain token.

```solidity
function deployInterchainToken(
    bytes32 salt,
    string calldata name,
    string calldata symbol,
    uint8 decimals,
    uint256 initialSupply,
    address minter
) external payable returns (bytes32 tokenId) {
    address sender = msg.sender;
    salt = interchainTokenSalt(chainNameHash, sender, salt);
    bytes memory minterBytes = new bytes(0);

    if (initialSupply > 0) {
        minterBytes = address(this).toBytes();
    } else if (minter != address(0)) {
        minterBytes = minter.toBytes();
    }

    tokenId = _deployInterchainToken(salt, '', name, symbol, decimals, minterBytes, 0);

    if (initialSupply > 0) {
        IInterchainToken token = IInterchainToken(interchainTokenService.interchainTokenAddress(tokenId));
        ITokenManager tokenManager = ITokenManager(interchainTokenService.tokenManagerAddress(tokenId));

        token.mint(sender, initialSupply);

        tokenManager.removeFlowLimiter(address(this));

        // If minter == address(0), we still set it as a flow limiter for consistency with the remote token manager.
@>>        tokenManager.addFlowLimiter(minter);

```

### If the minter address is zero and the initial supply is zero:

The function defaults `minterBytes` to zero bytes, leading to `_deployInterchainToken` passing this zero-byte value downstream. The interchain token is initialized with the zero address as the minter.

In this case, the zero bytes are passed to `InterchainTokenFactory::_deployInterchainToken` and then to `interchainTokenService.deployInterchainToken`. In the `interchainTokenService.deployInterchainToken` function, a minter address is declared. If the length of `minterBytes` is zero, the minter defaults to the zero address.

```solidity
function _deployInterchainToken(
    bytes32 tokenId,
    bytes memory minterBytes, 
    string memory name,
    string memory symbol,
    uint8 decimals
) internal returns (address tokenAddress) {

    bytes32 salt = _getInterchainTokenSalt(tokenId);
    address minter;

    if (bytes(minterBytes).length != 0) minter = minterBytes.toAddress();

    (bool success, bytes memory returnData) = interchainTokenDeployer.delegatecall(
        abi.encodeWithSelector(IInterchainTokenDeployer.deployInterchainToken.selector, salt, tokenId, minter, name, symbol, decimals)
    );
```

Then, a delegate call is made to the `InterchainTokenDeployer::deployInterchainToken` function, where the `InterchainToken` contract initializes the interchain token.

```solidity
IInterchainToken(tokenAddress).init(tokenId, minter, name, symbol, decimals);
```

In the `InterchainToken::init` function, there is no check that ensures the minter must not be the zero address:

```solidity

    symbol = tokenSymbol;
    decimals = tokenDecimals;

@>>    _addMinter(minter);

    _setNameHash(tokenName);

```

Thus, the zero address is assigned the minter role:

```solidity
function _addMinter(address minter_) internal {
    _addRole(minter_, uint8(Roles.MINTER));
}
```

## Recommended Mitigation Steps

To mitigate these issues, it is recommended to add checks to ensure that the minter address is not the zero address before proceeding with the token deployment and initialization processes.
