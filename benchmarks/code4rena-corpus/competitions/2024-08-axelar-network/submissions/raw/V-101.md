# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The missing override specifier in an overriding function results in a compilation error, which prevents the contract from being deployed and executed. This issue can delay development and deployment and may cause confusion or errors during contract maintenance if not promptly addressed.

In Solidity, when a function in a contract overrides a function declared in a parent contract or interface, it is mandatory to include the override keyword. This keyword explicitly informs the compiler that the function is intended to override a base function. If the override keyword is omitted, the Solidity compiler will generate an error, as it cannot confirm the function’s intention to override.

function epochBySignerHash(bytes32 signerHash) external view returns (uint256) {

// In IBaseWeightedMultisig.sol

function epochBySignerHash(bytes32 signerHash) external view returns (uint256);

Because the override specifier is missing, the contract will not compile, making it impossible to deploy or test.

## Recommended Mitigation Steps

To resolve this issue, add the override keyword to the function declaration in the BaseWeightedMultisig contract. This clearly indicates that the function is meant to override a function in a base contract or interface, allowing the compiler to successfully compile the contract.

The function should be modified as follows:
```sol
// In BaseWeightedMultisig.sol

function epochBySignerHash(bytes32 signerHash) external view override returns (uint256) {
    return _baseWeightedMultisigStorage().epochBySignerHash[signerHash];
}
```

By including the override specifier, the Solidity compiler will correctly recognise the function as an override, enabling the contract to compile and function as intended.
