# Vulnerability details

## Impact
`BaseAmplifierGateway.isCommandExecuted` isn't correct. 
Combining this function and `BaseAmplifierGateway.approveMessages`, a malicious signer can DOS `express execute operations` in some case.

## Proof of Concept
[BaseAmplifierGateway.isCommandExecuted](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/BaseAmplifierGateway.sol#L115-L117) has two issues.
First it doesn't consistent with [BaseAmplifierGateway.isMessageExecuted](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/BaseAmplifierGateway.sol#L75-L77)
```solidity
 75     function isMessageExecuted(string calldata sourceChain, string calldata messageId) external view returns (bool) {
 76         return _baseAmplifierGatewayStorage().messages[messageToCommandId(sourceChain, messageId)] == MESSAGE_EXECUTED; <<<--- check if message's state is MESSAGE_EXECUTED
 77     }
 ...
115     function isCommandExecuted(bytes32 commandId) public view override returns (bool) {
116         return _baseAmplifierGatewayStorage().messages[commandId] != MESSAGE_NONEXISTENT; <<<--- check if message's state is not MESSAGE_NONEXISTENT
117     }
```

Second, even though there are two states MESSAGE_EXECUTED and MESSAGE_NONEXISTENT defined, but there is another state `approved` as described in [BaseAmplifierGateway.sol#L15-L20](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/BaseAmplifierGateway.sol#L15-L20). 
And Because `isCommandExecuted` is used by `express execute operations` like [expressExecute](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/express/AxelarValuedExpressExecutable.sol#L131-L152) and [expressExecuteWithToken](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/express/AxelarValuedExpressExecutable.sol#L154-L204), a malicious signer might abusing this function and [AxelarAmplifierGateway.approveMessages](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L80-L86) to DOS `express execute operations`

Please consider the following case:
1. Alice the malicious signer has enough weights for [BaseWeightedMultisig._validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192-L234) to be successful
2. Bob wants to run express execute operations to speed up some tx
3. Alice sees Bob's express operations in mempool, and she wants to DOS the tx
4. Alice front-run Bob's tx by calling [AxelarAmplifierGateway.approveMessages](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/AxelarAmplifierGateway.sol#L80-L86) to approve the message, because she has enough weights for `BaseWeightedMultisig._validateSignatures`, Alice's tx will success, and **the message's state will be set to APPROVED**
5. When Bob's express operation gets executed, the function will check if the message has been executed by calling `BaseAmplifierGateway.isCommandExecuted`, because the message's state is not `MESSAGE_NONEXISTENT`, Bob's tx will be reverted
