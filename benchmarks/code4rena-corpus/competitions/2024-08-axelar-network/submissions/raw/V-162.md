# Vulnerability details

## Impact
In the execute_message method, the risk of replay attacks is high due to the lack of checks on message uniqueness.

If the same cross-chain message is executed multiple times, it may cause repeated state changes. For example, if a cross-chain token transfer message is executed repeatedly, it may cause the token to be received multiple times on the target chain, leading to double payment problems or inconsistent token quantities. This will not only lead to user fund losses, but also affect the reliability and integrity of the entire cross-chain operation.

## Proof of Concept

In the execute_message method, there is no clear mechanism to prevent replay attacks. The specific code is as follows:
```
let its_hub_message = ItsHubMessage::abi_decode(&payload).change_context(Error::InvalidPayload)?;
```
This code snippet decodes and processes the payload, but does not further check whether the message has been processed before. For example, when receiving the same payload, it may cause the system to perform the same cross-chain operation multiple times, thus causing a replay attack.

## Recommended Mitigation Steps

Introduce unique identification: Introduce a unique message ID (such as transaction hash or timestamp) for each cross-chain message, and check whether the ID has been processed before execution. Each message is only allowed to be processed once to prevent repeated execution.
Use time window: When receiving cross-chain messages, introduce a time window that only allows messages to be processed within a specific time range. This can reduce the effective time of replay attacks.
