# Vulnerability details


## Summary

The `executeProposal` function in the `InterchainGovernance` contract accepts an unbounded `callData` parameter, which can be exploited to cause Denial of Service (DoS) or excessive gas consumption.

## Description

In the `InterchainGovernance:executeProposal` function, there's no limit on the size of the `callData` parameter. This allows an attacker to pass extremely large data, which can lead to various Out-of-gas errors or issue when calculating the proposalHash or emitting the ProposalExecuted event. 

The `_call` function is responsible for this execution and an attacker can basically pass in a very large `callData` since the value type is strictly bytes which can hold a very large value.

An attacker can craft a proposal with extremely large callData tha tWhen executeProposal is called, the transaction may fail due to out-of-gas error or consume an excessive amount of gas.
If the transaction succeeds, it may still prevent other legitimate proposals from being executed due to block gas limits.

Manual review


## POC

```solidity
    function executeProposal( 
    address target,
    bytes calldata callData,
    uint256 nativeValue
) external payable {
    bytes32 proposalHash = _getProposalHash(target, callData, nativeValue);

    _finalizeTimeLock(proposalHash);

    emit ProposalExecuted(proposalHash, target, callData, nativeValue, block.timestamp);

    _call(target, callData, nativeValue);
}
```


## Impact

The vulnerability allows an attacker to submit arbitrarily large `callData`, potentially causing out-of-gas errors during execution or significantly increasing the gas costs for legitimate users. This can disrupt the governance process, prevent the execution of important proposals, and potentially lock funds or critical functionality.

## Recommended Mitigation

Implement a size limit for the `callData `parameter:

uint256 constant MAX_CALLDATA_SIZE = 10000; // Adjust this value as needed
