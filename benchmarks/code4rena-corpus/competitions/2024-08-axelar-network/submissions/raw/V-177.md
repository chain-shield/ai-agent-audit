# Vulnerability details

## Impact

In `execute.rs` contract of the ITS Hub, there is a function `execute_messages()` that gets the data and transmits it to the Axelarnet gateway. The problem is that when checking `source_address` it makes a mistake by comparing it with `trusted_source_address` as `source_address` is specified when triggering the message on ITS contract as `msg.sender` and not ITS contract itself.

## Proof of Concept

Take a look at `execute_messages()` functionality:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/contract/execute.rs#L27-33
```
  let source_chain = ChainName::try_from(cc_id.source_chain.clone().to_string())
        .change_context(Error::InvalidPayload)?;
    let trusted_source_address = load_trusted_address(deps.storage, &source_chain)
        .change_context(Error::InvalidStoreAccess)?;
    if source_address != trusted_source_address {
        return Err(report!(Error::UntrustedAddress(source_address)));
    }

```

We get `source_chain` from `cc_id` and then load trusted address for it meaning that the contract checks if the ITS contract that triggered the message is the trusted ITS contract on the source chain. But the problem is that `source_address` is set as `msg.sender` so it's the user who triggered `interchainTransfer()` transaction inside of ITS contract:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L467-469
```

            tokenId,
```

So it checks for incorrect address which will make the tx revert.

Manual review.

## Recommended Mitigation Steps

Change the source address to ITS contract when specifying it inside of ITS contract.
