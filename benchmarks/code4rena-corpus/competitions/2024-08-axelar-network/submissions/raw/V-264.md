# Vulnerability details

## Vulnerability Details

The existing transferOperatorship function allows for a direct and immediate transfer of the operator role, creating opportunities for accidental or malicious exploitation.

```solidity
function transferOperatorship(address operator) external onlyRole(uint8(Roles.OPERATOR)) {
        _transferRole(msg.sender, operator, uint8(Roles.OPERATOR));
    }
```


## Impact
The single-step transfer mechanism is prone to errors. A simple typo in the new operator's address could result in an irreversible transfer of control to an unintended entity.

If the current operator's private key is compromised, an attacker can instantly transfer operatorship to themselves. This grants them the ability to bypass crucial security checks, potentially leading to unauthorized actions such as approving harmful messages or manipulating the signer set.

## Mitigation

Implement a two-step operatorship transfer process.

1. Initiate Transfer: The current operator or owner initiates a transfer request by calling a designated function and providing the new operator's address. This action should emit an event to create a public record of the intended transfer.

2. Claim Operatorship: The new operator then calls a separate function to claim the role. This second step ensures that the intended recipient is aware of the transfer and actively accepts the responsibility.

3. Add Timelock: Additionally introducing a time delay between initiation and claim allows for a window to detect and potentially reverse malicious transfer attempts.

4. Revocation Mechanism: The initiator should have the ability to revoke the transfer request within the time delay if any suspicious activity is detected.
