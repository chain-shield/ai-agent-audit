# Vulnerability details

## Impact

The axelarnet gateway will not be feasible as a message parser.

## Proof of Concept

In the docs, the purpose of the Axelarnet Gateway is:

> Axelarnet Gateway: This is a specific gateway contract that allows apps on Axelar to send/receive `cross-chain messages` via the Amplifier protocol. ITS Hub is one such app that will interact with this gateway.

From the [diagrams](https://bright-ambert-2bd.notion.site/ITS-Token-Hub-External-dd30ee912d1e48e683d9488acf75e350), the Axelarnet Gateway either routes the incoming messages from the ITS Hub to the Amplifier Router, or executes outgoing messages from the Amplifier Router to the ITS Hub.

There are three functions in axelarnet-gateway, `ExecuteMsg::CallContract`  `ExecuteMsg::RouteMessages` and `ExecuteMsg::Execute`

Looking at `RouteMessages`, either `route_outgoing_messages` or `route_incoming_messages` is called:

```
  ExecuteMsg::RouteMessages(msgs) => {
            if info.sender == router.address {

```

For `route_incoming_messages`, the `msgs` are checked, if the messages are not the same as those in the storage, revert.


These messages are saved when `call_contract` is called, and it is saved in a mapping.

```
const INCOMING_MESSAGES: Map<CrossChainId, Message> = Map::new(INCOMING_MESSAGES_NAME);
```

Note the mapping is `CrossChainId -> Message`. The issue is that for every `CrossChainId` key, there can only be one `Message` value. 

`mapping[CrossChainA] -> "Message"`

If there are more than one message for the particular crossChainId key, then the message will be overwritten.

## Recommended Mitigation Steps

The mapping should be the other way round, `Message -> CrossChainId`. This way, there can be different messages and all the messages should point to the same CrossChainId value, which should be the `chain_name` in the CONFIG file.

```
#[cw_serde]
pub(crate) struct Config {
    pub chain_name: ChainName,
    pub router: Addr,
}
```

Same for `OUTGOING_MESSAGES`

```
const OUTGOING_MESSAGES: Map<CrossChainId, MessageWithStatus> = Map::new(OUTGOING_MESSAGES_NAME);
```
