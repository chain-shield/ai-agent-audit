# Vulnerability details

## Impact
The lack of implementation to return unused msg.value in the deployInterchainToken function can lead to unintentional retention of funds within the contract. This could result to:

- Locked Funds: Users may inadvertently send excess Ether when invoking the function, leading to locked funds within the contract that are inaccessible to the user.
- User Frustration: Users may lose trust in the contract due to the unreturned Ether, causing a potential loss of reputation and credibility for the platform.
- Malicious actors might exploit the contract by calling the function with excessive msg.value, leading to unnecessary accumulation of funds within the contract creating balance imbalance.
## Proof of Concept
```solidity
    function deployInterchainToken(
        bytes32 salt,
        string calldata destinationChain,
        string memory name,
        string memory symbol,
        uint8 decimals,
        bytes memory minter,
        uint256 gasValue
>>>    ) external payable whenNotPaused returns (bytes32 tokenId) {
        address deployer = msg.sender;

        if (deployer == interchainTokenFactory) deployer = TOKEN_FACTORY_DEPLOYER;

        tokenId = interchainTokenId(deployer, salt);

        if (bytes(destinationChain).length == 0) {
            address tokenAddress = _deployInterchainToken(tokenId, minter, name, symbol, decimals);

            _deployTokenManager(tokenId, TokenManagerType.NATIVE_INTERCHAIN_TOKEN, abi.encode(minter, tokenAddress));
        } else {
            _deployRemoteInterchainToken(tokenId, name, symbol, decimals, minter, destinationChain, gasValue);
        }
    }
```
As provided in the code above the deployInterchainToken function from the InterchainTokenService contract is declared as payable, allowing it to accept Ether when called. However, there is no logic within the function to return any unused portion of the msg.value to the sender.
The problem in this implementation is that, when a user sends more Ether than required for the gasValue, the excess amount is not returned to the sender, resulting in a loss of funds for the user.
