# Vulnerability details

## Impact
The update_token_balance method also lacks proper access control, which allows any user to call this method and directly modify the token balance on the chain. This may cause an attacker to maliciously increase or decrease the token balance on a certain chain, thereby threatening the overall security of the system. Unauthorized balance operations may lead to loss of funds, inconsistent transactions, and logical anomalies in the system.

Without proper access control, an attacker can directly manipulate the token balance on the chain by repeatedly calling the update_token_balance method, thereby creating systemic risks and posing a threat to user assets.

## Proof of Concept

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-amplifier/interchain-token-service/src/state.rs#L166

In the implementation of the update_token_balance method, there is no permission verification, allowing any user to call and modify the token balance at will. The following is the relevant code:
```
pub fn update_token_balance(
    storage: &mut dyn Storage,
    token_id: TokenId,
    chain: ChainName,
    amount: Uint256,
    is_deposit: bool,
) -> Result<(), Error> {
    let key = TokenChainPair { token_id, chain };
    let token_balance = TOKEN_BALANCES.may_load(storage, key.clone())?;
    match token_balance {
        Some(TokenBalance::Tracked(balance)) => {
            let token_balance = if is_deposit {
                balance.checked_add(amount).map_err(|_| Error::InvalidAmount)?
            } else {
                balance.checked_sub(amount).map_err(|_| Error::InvalidAmount)?
            };
            TOKEN_BALANCES.save(storage, key, &token_balance)?;
        }
        _ => (),
    }
    Ok(())
}
```
As shown above, the code does not impose any restrictions or verification on the caller, resulting in any user being able to call this method to modify the token balance at will.

## Recommended Mitigation Steps

Introduce permission control in the update_token_balance method to ensure that only authorized users or contract internal logic can modify the token balance.
Implement permission verification to limit which users can perform this operation and record operation logs for audit.
