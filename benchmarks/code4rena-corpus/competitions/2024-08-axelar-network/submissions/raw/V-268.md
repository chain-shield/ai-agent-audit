# Vulnerability details

## Impact
the deployInterchainToken() function allows setting a minter address without verifying that it's not the zero address.
If minter is set to ``address(0)`` and ```initialSupply > 0```, the function will transfer critical roles (minter and operator) to the zero address, potentially causing permanent loss of minting capabilities, inability to manage token flow limits and potential loss of operational control over the token
## Proof of Concept
```solidity
function exploitVulnerability() external {
    deployInterchainToken(
        bytes32(0),
        "Vulnerable Token",
        "VUL",
        18,
        1000000, // initialSupply > 0
        address(0) // Zero address for minter
    );
    // This transfers mintership and operatorship to the zero address
}
```

## Tools Used
manual review
## Recommended Mitigation Steps
Add a zero-address check for minter at the beginning of the function. This check will prevent the accidental assignment of critical roles to the zero address.
```solidity
function deployInterchainToken(
    bytes32 salt,
    string calldata name,
    string calldata symbol,
    uint8 decimals,
    uint256 initialSupply,
    address minter
) external payable returns (bytes32 tokenId) {
    require(minter != address(0), "Minter cannot be zero address");
    // ... snip ...
}
```
