# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The absence of the override specifier in the function implementation results in a compilation error, preventing the contract from being deployed or tested. This issue can disrupt the deployment process and may cause confusion or errors during future contract maintenance if not corrected.

In Solidity, when a function is intended to override a function in a base contract or an interface, it must include the override keyword. This specifier explicitly informs the Solidity compiler that the function is meant to override a parent function. Without the override specifier, the compiler generates an error, as it cannot confirm that the function is correctly overriding the intended function.

The specific error reported by the Solidity compiler is:

This error occurs because the timeSinceRotation function in the BaseWeightedMultisig contract is intended to override a function defined in the IBaseWeightedMultisig interface. The omission of the override specifier leads to a compilation error, making it impossible to deploy or use the contract.

## Recommended Mitigation Steps

To resolve this issue, the override keyword should be added to the function declaration in the BaseWeightedMultisig contract. This explicitly indicates that the function is intended to override a parent or interface function, allowing the compiler to correctly process the function and resolve the error.

The function should be updated as follows:
```sol
// In BaseWeightedMultisig.sol

function timeSinceRotation() external view override returns (uint256) {
    return block.timestamp - _baseWeightedMultisigStorage().lastRotationTimestamp;
}
```

By including the override specifier, the Solidity compiler will correctly recognise the function as an override, enabling the contract to compile and function as intended.
