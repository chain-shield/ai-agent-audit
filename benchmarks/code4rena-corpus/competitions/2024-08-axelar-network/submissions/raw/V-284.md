# Vulnerability details

## Impact
Token manager address derivation from tokenId in [_create3Address()](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/utils/Create3AddressFixed.sol#L22) is vulnerable to a [birthday attack](https://en.wikipedia.org/wiki/Birthday_attack
).

Output of `_create3Address()` is an EVM address which is 160 bit long. Finding a collision between:
1. output of `_create3Address()`
2. attacker-controlled addresses (e.g. created using `create2`)

takes approximately 2^80 tries.

Importantly, [TokenHandler](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/TokenHandler.sol#L98) derives the `TokenMananger` from user-supplied `tokenId`, then asks the `TokenMananger` for the token address.

There is no verification of TokenMananger beyond [the fact that it's a contract](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L198).

Once an attacker mines a `tokenId` such that `_create3Address(tokenId)` is controlled by attacker, they can make ITS use a malicious `TokenManager` and directly steal funds.

Note to judges:
- Similar findings have been previously found as valid on code4rena, e.g.
https://github.com/code-423n4/2023-11-panoptic-findings/issues/128
- Mysten Labs claim that, "a 2^80 attack would cost a few million dollars”.
https://mystenlabs.com/blog/ambush-attacks-on-160bit-objectids-addresses

## Proof of Concept
Assume attacker mined a `tokenId`, such that such that `_create3Address(tokenId)` generates an address that attacker controls.

An example attack would be to initiate an interchain transfer and inject a malicious `TokenManager`, which
1. is `LOCK_UNLOCK` on source side.
2. is `NATIVE_INTERCHAIN_TOKEN` on destination side.
        
Since attacker control source and destination addresses and `TokenManagers` on both sides, they don't actually lock any tokens on the source side, but are able to mint tokens on destination side.

The following patch add a PoC to `interchain-token-service/test/InterchainTokenServiceFullFlow.js` that illustrates the idea. (It's a little contrived because I can't mine the required token ID, so I had to modify `_create3Address()`).

## Tools Used
Manual inspection.

## Recommended Mitigation Steps
The simplest mitigation is to have ITS keep track of all previously deployed tokenIDs and disallow usage of tokenIDs that haven't been registered.
