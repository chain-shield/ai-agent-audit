```solidity
    function toAddress(bytes memory bytesAddress) internal pure returns (address addr) {
        if (bytesAddress.length != 20) revert InvalidBytesLength(bytesAddress);

        assembly {
            addr := mload(add(bytesAddress, 20))
        }
    }
```

Evidently, there is an enforcal that the addresses length must be `20`, now whereas this holds true for EVM chains, this isn't true for non-EVM chains as the length of the addresses `!=20`, which then causes the execution attempt to always revert [here](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/interchain-token-service/contracts/InterchainTokenService.sol#L737-L738).

## Impact

As hinted under _Proof of concept_, executions are broken for non-evm chains since they'd always revert [here](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/interchain-token-service/contracts/InterchainTokenService.sol#L737-L738) due to the check on the address's length meaning the integration with Sol/Aptos would not work since the addresses are 32 bytes.

## Recommended Mitigation Steps

Correctly support these address types as destinations and reroute the getter logic from `AddressBytes#toAddress()`
