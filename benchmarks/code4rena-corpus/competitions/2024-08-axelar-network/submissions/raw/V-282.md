# Vulnerability details

## Impact
When an interchain transfer call occurs, on the destination chain, the respective user is minted the tokens. The issue is that since the token manager contract is not assigned the MINTER role on the InterchainToken.sol contract, the call would revert. 

## Proof of Concept
Let's go through the execution path to understand why this occurs:

1. The [_giveToken()](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L1202C14-L1202C24) function on the ITS contract is called on the destination chain. (**Note: The POC won't cover how the call led to the _giveToken() function since that can be back-traced and is not specifically relevant to the issue being pointed out**).
 - On the first line, we delegatecall to the [giveToken()](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/TokenHandler.sol#L45) function on the TokenHandler.sol contract.

```solidity
    function _giveToken(bytes32 tokenId, address to, uint256 amount) internal returns (uint256, address tokenAddress) {
        (bool success, bytes memory data) = tokenHandler.delegatecall(
            abi.encodeWithSelector(ITokenHandler.giveToken.selector, tokenId, to, amount)
        );
        if (!success) revert GiveTokenFailed(data);
        (amount, tokenAddress) = abi.decode(data, (uint256, address));


        return (amount, tokenAddress);
    }
```

2. In giveToken(), let's assume the below function is called internally due to implementation type being MINT_BURN. This makes an external call to the function mintToken in the tokenManager contract.

```solidity
 function _mintToken(address tokenManager, address tokenAddress, address to, uint256 amount) internal {
        ITokenManager(tokenManager).mintToken(tokenAddress, to, amount);
    }
```

3. In this mintToken() function on the TokenManager contract, it ensures the msg.sender is the InterchainTokenService contract. In this case it is the msg.sender since the call originates from it. This mintToken() function now makes a call to the mint() function on the InterchainToken contract.

```solidity
function mintToken(address tokenAddress_, address to, uint256 amount) external onlyService {
        IERC20(tokenAddress_).safeCall(abi.encodeWithSelector(IERC20MintableBurnable.mint.selector, to, amount));
    }
```

4. In the InterchainToken contract, it expects the msg.sender (in this case the token manager) to have the MINTER role. But since it does not, the call reverts.

```solidity
 function mint(address account, uint256 amount) external onlyRole(uint8(Roles.MINTER)) {
        _mint(account, amount);
    }
```

5. In the init() function, the minter is set to the ITS contract while the call actually arrives from the token manager. Due to this, the call reverts as mentioned in step 4. 

```solidity
_addMinter(interchainTokenService_);
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the tokenManager contract as a MINTER during deployment of the interchain token.
