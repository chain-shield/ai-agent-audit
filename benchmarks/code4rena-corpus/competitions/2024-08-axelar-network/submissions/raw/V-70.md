# Vulnerability details

The `ExecuteMsg::UpdateTrustedAddress` message in the ITS Hub contract requires `Elevated` permissions, meaning only addresses with `Admin` or `Governance` roles can execute this message. However, the admin and governance addresses are never set in the ITS Hub contract.

## Impact
Trusted addresses can never be added or updated, which would result in the ITS Hub being unable to handle ITS messages from source addresses that aren't set as trusted addresses during the contract's instantiation. Additionally, if a trusted address becomes compromised on a chain then it can't be updated, which further compromises the security and functionality.

## Proof of Concept
`ExecuteMsg::UpdateTrustedAddress` requires `Elevated = (Permission::Admin | Permission::Governance)` permission:
```rust
#[cw_serde]
#[derive(EnsurePermissions)]
pub enum ExecuteMsg {
    #[permission(Specific(gateway))]
    Execute {
        cc_id: CrossChainId,
        source_address: Address,
        payload: HexBinary,
    },
@>  #[permission(Elevated)]
    UpdateTrustedAddress { chain: ChainName, address: Address },
}
```
```rust
flags! {
    #[repr(u8)]
    #[derive(Serialize, Deserialize)]
    pub enum Permission: u8 {
        NoPrivilege = 0b001, // this specifies that the user MUST NOT have an elevated role
        Admin = 0b010,
        Governance = 0b100,
@>      Elevated = (Permission::Admin | Permission::Governance).bits(),
        Any = (Permission::NoPrivilege | Permission::Elevated).bits(),
    }
}
```
Permissions are enforced when calling `execute` on the ITS Hub contract:
```rust
#[cfg_attr(not(feature = "library"), entry_point)]
pub fn execute(
    deps: DepsMut,
    _: Env,
    info: MessageInfo,
    msg: ExecuteMsg,
) -> Result<Response, axelar_wasm_std::error::ContractError> {
@>  let msg = msg.ensure_permissions(deps.storage, &info.sender, match_gateway)?;
    ...
}
```
Admin or governance addresses are never set in the ITS Hub contract, see storage and functions that needs to be called:
```rust
const ADMIN: Item<Addr> = Item::new("permission_control_contract_admin_addr");

const GOVERNANCE: Item<Addr> = Item::new("permission_control_governance_addr");

pub fn set_admin(storage: &mut dyn cosmwasm_std::Storage, addr: &Addr) -> StdResult<()> {
    ADMIN.save(storage, addr)
}

pub fn set_governance(storage: &mut dyn cosmwasm_std::Storage, addr: &Addr) -> StdResult<()> {
    GOVERNANCE.save(storage, addr)
}
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add that the `instantiate` function calls `permission_control::set_admin` and/or `permission_control::set_governance`. Additionally, consider implementing the ability to update the admin/governance addresses.
