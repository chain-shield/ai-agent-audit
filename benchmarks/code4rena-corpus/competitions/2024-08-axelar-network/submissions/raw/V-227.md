# Vulnerability details

## Vulnerability Detail
The `init` function in the InterchainToken contract is externally accessible without any access control. This function is responsible for setting critical parameters of the token, including the token ID, minter address, name, symbol, and decimals. The vulnerability allows any external actor to call this function and initialize the contract with arbitrary values, as long as it hasn't been initialized before.
This is also visible in other contracts of the protocol
While there is a check to prevent multiple initializations, there's no restriction on who can perform the initial setup.
## Impact
- Unauthorized Control: An attacker could initialize the contract with their chosen parameters, potentially setting themselves as the minter and gaining control over token minting and burning.
- Token Identity Manipulation: The attacker could set misleading token name and symbol, potentially impersonating another token or creating confusion among users.
- Functionality Disruption: Incorrect initialization could render the token contract unusable or behave in unexpected ways, disrupting its intended functionality.

## Proof of Concept
```
function init(bytes32 tokenId_, address minter, string calldata tokenName, string calldata tokenSymbol, uint8 tokenDecimals) external {
    if (_isInitialized()) revert AlreadyInitialized();

    _initialize();

    // ... (setting of token parameters)
}
```
## Tools Used
Manual code review
## Recommended Mitigation Steps
Use an onlyOwner modifier:
```
   function init(bytes32 tokenId_, address minter, string calldata tokenName, string calldata tokenSymbol, uint8 tokenDecimals) external onlyOwner {
       // ... existing initialization logic
   }
```
