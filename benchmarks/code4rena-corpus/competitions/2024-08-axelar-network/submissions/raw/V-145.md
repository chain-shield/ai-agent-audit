# Vulnerability details

## Impact
An attacker could deploy a gateway token(TokenManagerType.GATEWAY) and use it to drain the token on ITS.

## Proof of Concept
Only owner is allowed to deploy `GATEWAY` token on `InterchainTokenFactory`

[InterchainTokenFactory.sol#L301-L309](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenFactory.sol#L301-L309)
```solidity
function registerGatewayToken(bytes32 tokenIdentifier, string calldata symbol) external onlyOwner returns (bytes32 tokenId) {
    address tokenAddress = gateway.tokenAddresses(symbol);
    if (tokenAddress == address(0)) revert NotGatewayToken(symbol);

    bytes memory params = abi.encode('', tokenAddress);
    bytes32 salt = gatewayTokenSalt(tokenIdentifier);

    tokenId = interchainTokenService.deployTokenManager(salt, '', TokenManagerType.GATEWAY, params, 0);
}
```
however user can deploy `GATEWAY` via [InterchainTokenService.deployTokenManager](https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L286-L311)
```solidity
function deployTokenManager(
    bytes32 salt,
    string calldata destinationChain,
    TokenManagerType tokenManagerType,
    bytes calldata params,
    uint256 gasValue
) external payable whenNotPaused returns (bytes32 tokenId) {
    // Custom token managers can't be deployed with native interchain token type, which is reserved for interchain tokens
    if (tokenManagerType == TokenManagerType.NATIVE_INTERCHAIN_TOKEN) revert CannotDeploy(tokenManagerType);

    address deployer = msg.sender;

    if (deployer == interchainTokenFactory) {
        deployer = TOKEN_FACTORY_DEPLOYER;
    }

    tokenId = interchainTokenId(deployer, salt);

    emit InterchainTokenIdClaimed(tokenId, deployer, salt);

    if (bytes(destinationChain).length == 0) {
        _deployTokenManager(tokenId, tokenManagerType, params); <@
    } else {
        _deployRemoteTokenManager(tokenId, destinationChain, gasValue, tokenManagerType, params);
    }
}
```

An attacker could first deploy a `GATEWAY` token on `chain1`, and then deploy a `NATIVE_INTERCHAIN_TOKEN` on chain2. For this `NATIVE_INTERCHAIN_TOKEN`, the deployer can set a minter address and use it to mint tokens for themselves. The attacker can specify a token address that matches the legitimate gateway token. Finally, the attacker transfers the newly minted tokens to a remote chain that has the same gateway token. These newly minted tokens are then burned on the source chain, allowing the attacker to receive the legitimate gateway tokens on the remote chain.

We have to comments `onlyRemoteService` and `onlyOwner` code to make this test run successfully
