# Vulnerability details

## Impact
In the `interchain-token-service` package's `state.rs` contract, the `TokenChainPair` struct's `KeyDeserialize` trait implementation incorrectly parses the length of `Vec<u8>` data. It only checks for the presence of the `tokenId` without verifying if the `chain` field exists. This oversight can lead to an empty `chain` being parsed into a `TokenChainPair` variant, which affects the contract's ability to accurately track and update on-chain token balances. Additionally, this issue can disrupt the execution of other contract-related messages.

## Proof of Concept
In the `interchain-token-service` package's `state.rs` contract, the `TokenChainPair` struct's `KeyDeserialize` trait is responsible for deserializing `Vec<u8>` data into a `TokenChainPair` struct. The struct contains two components: `tokenId` and `chain`. The `from_vec` method parses the first 32 bytes of `value` into the `tokenId`, and any remaining bytes are parsed into the `chain`. The issue arises because the `from_vec` method only checks if the length of the data is less than 32 (`if value.len() < 32`), which only ensures the presence of the `tokenId`. If `value.len() = 32`, the data can be parsed into a `tokenId` with an empty `chain`, affecting the functionality related to token balance tracking and updating. This, in turn, can impact the execution of other contract-related messages.

## Recommended Mitigation Steps
It is recommended to modify the length check from `if value.len() < 32` to `if value.len() <= 32` to ensure that the data being deserialized into the `TokenChainPair` struct includes both the `tokenId` and the `chain`.
