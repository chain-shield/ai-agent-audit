# Vulnerability details

# Potential Risk of Trapped Ether in Core Contracts Due to Lack of Recovery Mechanism

## Impact

While the core contracts of the Axelar protocol are designed to use received Ether for specific purposes (primarily gas payments for cross-chain operations), the lack of a recovery mechanism presents a potential risk. In the event of failed transactions, protocol changes, or unforeseen circumstances, there's a possibility that Ether could become trapped in these contracts without a way to recover it. This could lead to:

1. Potential loss of funds in edge cases where Ether is not fully utilized as intended.
2. Reduced protocol flexibility in handling unexpected scenarios or upgrades.
3. Possible complications in future protocol migrations or upgrades where residual Ether needs to be addressed.

The severity of this issue is considered Medium. While the risk is not immediate given the intended usage of Ether in these contracts, it represents a notable concern in terms of protocol design and adherence to best practices for handling Ether in smart contracts.

## Recommended Mitigation Steps

1. Implement Recovery Functions:
   Add a recovery function to each affected contract, allowing authorized parties to withdraw any unused or trapped Ether. This serves as a safety net for edge cases.

   ```solidity
   function recoverEther() external onlyOwner {
       uint256 balance = address(this).balance;
       (bool success, ) = owner().call{value: balance}("");
       require(success, "Recovery failed");
   }
   ```

2. Enhance Ether Handling:
   Implement more robust checks to ensure all received Ether is used as intended, with a mechanism to return any excess to the sender.

3. Improve Documentation:
   Clearly document the Ether flow in all payable functions, including how potential excess Ether is handled.

4. Consider Accounting System:
   Implement a system to track Ether meant for gas payments versus any accumulated excess, facilitating easier management and potential recovery.

By implementing these measures, the Axelar protocol can maintain its intended functionality while adding an extra layer of safety and flexibility in handling Ether, thus mitigating the risk of permanently trapped funds in edge cases.
