# Vulnerability details

## Impact

Inside of the current implementation of ITS contract, `execute()` function calls internal `_getExecuteParams()` before finishing the execution, and this function assigns `messageType, originalSourceChain, payload`. The problem is that the contract checks for `originalSourceChain` to be `ITS_HUB_ROUTING_IDENTIFIER_HASH` in the second GMP call (when executing the transaction). This would lead to excessive gas funds to be spent unlike in the case when the first GMP call will be reverted.


## Proof of Concept

Take a look at `_getExecuteParams()` functionality:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L981
```
if (trustedAddressHash(originalSourceChain) != ITS_HUB_ROUTING_IDENTIFIER_HASH) revert UntrustedChain();
```
As you can see, it checks whether the trusted address of the original source chain is ITS Hub address. But it should be checked on the source chain to avoid implementing the second GMP call and spending excessive gas on the second transaction. On the source chain, in contrary, it checks the trusted address of the destination chain and forgets to check the trusted address of the source chain:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L881-887

## Recommended Mitigation Steps

Check for the trusted address of the source chain on the source chain and not on the destination chain.
