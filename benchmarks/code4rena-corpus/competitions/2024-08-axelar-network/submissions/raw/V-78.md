# Vulnerability details


## Impact
A Denial of Service (DoS) will occur for all applications and users attempting to call `executeWithToken` on the ITS edge.

## Proof of Concept (PoC)
According to the documentation, the Axelar Amplifier Gateway is expected to be backward compatible with the standard Gateway.

```
The EVM Amplifier gateway also supports legacy methods for compatibility with the existing EVM AxelarExecutable contract. These aren't needed for gateway implementations for non-EVM chains.
```

[Source](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/gateway/INTEGRATION.md#interface)

There are two methods to execute a message on the destination chain: `execute` and `executeWithTokens`. These methods require message validation before execution on the destination chain. This validation is performed by making a call to the `gateway` to obtain a boolean value indicating whether the message is valid.

The `executeWithTokens` function calls `validateContractCallAndMint`, which validates the message and mints a specific amount of tokens.

```solidity
function _executeWithToken(
    bytes32 commandId,
    string calldata sourceChain,
    string calldata sourceAddress,
    bytes memory payload,
    string calldata tokenSymbol,
    uint256 amount
) internal {
    bytes32 payloadHash = keccak256(payload);

    if (!gateway.validateContractCallAndMint(commandId, sourceChain, sourceAddress, payloadHash, tokenSymbol, amount))
        revert NotApprovedByGateway();
}
```

[Source](https://github.com/axelarnetwork/interchain-token-service/blob/498a02b5ca59871e657b42871dba061796cf7860/contracts/InterchainTokenService.sol#L923-L935)

However, the `validateContractCallAndMint` function is not implemented by the `AxelarAmplifierGateway`, which prevents the validation of `executeWithTokens` messages, despite the claim of backward compatibility.

The `AxelarAmplifierGateway` only implements the `validateContractCall` function, which is used by the `execute` method.

```solidity
function validateContractCall(
    bytes32 commandId,
    string calldata sourceChain,
    string calldata sourceAddress,
    bytes32 payloadHash
) external override returns (bool valid) {
    valid = _validateMessage(commandId, sourceChain, sourceAddress, payloadHash);
}
```

[Source](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-gmp-sdk-solidity/contracts/gateway/BaseAmplifierGateway.sol#L129-L136)

So also the function `validateContractCallAndMint` should be implemented by the `axelarAmplifierGateway` .

for now , If the call is approved in the Axelar Amplifier Gateway, attempting to execute the message on the ITS edge will always result in failure.

## Recommendations
The Axelar Gateway contract should implement the `validateContractCallAndMint` function to ensure full backward compatibility.
```solidity 
    function validateContractCallAndMint(
        bytes32 commandId,
        string calldata sourceChain,
        string calldata sourceAddress,
        bytes32 payloadHash,
        string calldata symbol,
        uint256 amount
    ) external override returns (bool valid) {
        bytes32 key = _getIsContractCallApprovedWithMintKey(commandId, sourceChain, sourceAddress, msg.sender, payloadHash, symbol, amount);
        valid = getBool(key);
        if (valid) {
            // Prevent re-entrancy
            _setBool(key, false);


            emit ContractCallExecuted(commandId);


            _mintToken(symbol, msg.sender, amount);
        }
    }
```
