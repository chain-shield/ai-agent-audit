While starting the tracking we have a simple check that ensures that the token is not already registered https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/interchain-token-service/src/state.rs#L139-L164

```rust
pub fn start_token_balance(
    storage: &mut dyn Storage,
    token_id: TokenId,
    chain: ChainName,
    track_balance: bool,
) -> Result<(), Error> {
    let key = TokenChainPair { token_id, chain };

    match TOKEN_BALANCES.may_load(storage, key.clone())? {
        None => {
            let initial_balance = if track_balance {
                TokenBalance::Tracked(Uint256::zero())
            } else {
                TokenBalance::Untracked
            };

            TOKEN_BALANCES
                .save(storage, key, &initial_balance)?
                .then(Ok)
        }
        Some(_) => Err(Error::TokenAlreadyRegistered {//@audit
            token_id: key.token_id,
            chain: key.chain,
        }),
    }
}
```

Issue however is that since we support tokens with multiple addresses this would allow different balance tracking logic to be applied and as such even if the token was previously registered via one of it's multiple addresses the attempt at registering the token and starting fresh balances [here](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/interchain-token-service/src/state.rs#L139-L164) again [does not revert](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/interchain-token-service/src/state.rs#L159) since we use another address whereas it should.

```rust
    #[test]
    fn token_with_multiple_addresses() {
        let mut deps = setup();

        let source_chain: ChainName = "source-chain".parse().unwrap();
        let destination_chain: ChainName = "destination-chain".parse().unwrap();
        let source_address: Address = "trusted-source".parse().unwrap();
        let destination_address: Address = "trusted-destination".parse().unwrap();

        register_trusted_address(&mut deps.as_mut(), source_chain.as_ref(), &source_address);
        register_trusted_address(
            &mut deps.as_mut(),
            destination_chain.as_ref(),
            &destination_address,
        );

        // Create two different token IDs for the same logical token
        let token_id_1 = TokenId::new([1u8; 32]);
        let token_id_2 = TokenId::new([2u8; 32]);

        // Deploy a token manager with address1 and token_id_1
        let deploy_manager_message = ItsMessage::DeployTokenManager {
            token_id: token_id_1.clone(),
            token_manager_type: crate::primitives::TokenManagerType::MintBurn,
            params: HexBinary::from_hex("1111111111111111111111111111111111111111").unwrap(),
        };
        let its_hub_message = ItsHubMessage::SendToHub {
            destination_chain: destination_chain.clone(),
            message: deploy_manager_message,
        };

        let payload = its_hub_message.abi_encode();
        let cc_id = CrossChainId::new(source_chain.clone(), "deploy-token-manager-message-id-1").unwrap();
        let result = execute_message(deps.as_mut(), cc_id, source_address.clone(), payload);
        assert!(result.is_ok());

        // Verify that the token balance for token_id_1 is untracked
        let balance_1 = state::may_load_token_balance(deps.as_ref().storage, &token_id_1, &destination_chain).unwrap();
        assert_eq!(balance_1, Some(TokenBalance::Untracked));

        // Now, deploy an interchain token with token_id_2 and a different address
        let deploy_token_message = ItsMessage::DeployInterchainToken {
            token_id: token_id_2.clone(),
            name: "Test Token".to_string(),
            symbol: "TST".to_string(),
            decimals: 18,
            minter: HexBinary::from_hex("2222222222222222222222222222222222222222").unwrap(),
        };
        let its_hub_message = ItsHubMessage::SendToHub {
            destination_chain: destination_chain.clone(),
            message: deploy_token_message,
        };

        let payload = its_hub_message.abi_encode();
        let cc_id = CrossChainId::new(source_chain.clone(), "deploy-interchain-token-message-id-2").unwrap();
        let result = execute_message(deps.as_mut(), cc_id, source_address, payload);

        // The execution should succeed, even though it's the same logical token
        assert!(result.is_ok());

        // Verify that the token balance for token_id_2 is now tracked
        let balance_2 = state::may_load_token_balance(deps.as_ref().storage, &token_id_2, &destination_chain).unwrap();
        assert_eq!(balance_2, Some(TokenBalance::Tracked(Uint256::zero())));

        // This demonstrates that the same logical token can have different balance tracking logic
        assert_ne!(balance_1, balance_2);
    }
```

### Impact

Balances can't be accurately tracked for these set of tokens considering, a [fresh balance can just be started](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/axelar-amplifier/interchain-token-service/src/state.rs#L139-L164) whenever which effectively resets the tracked balance for said token via this address.

### Recommended Mitigation Steps

Do not support these tokens.
