# Vulnerability details

## Vulnerability details
As the developer comments state in `rotateSigners`: `The gateway operator allows recovery in case of an incorrect/malicious rotation, while still requiring a valid proof from a recent signer set.`. The issue is that there are edge-cases in which the operator will be unable to prevent a malicious rotation. It is important to add that the protocol team has stated on the contest's page that this is a valid functional concern: [Can the signer rotation function address potential edge cases and ensure proper updates to the signer set?](https://code4rena.com/audits/2024-08-axelar-network#top:~:text=Can%20the%20signer%20rotation%20function%20address%20potential%20edge%20cases%20and%20ensure%20proper%20updates%20to%20the%20signer%20set%3F)

## Impact
If any of the three attacks, provided in `Proof of Concept`, occur `AmplifierGateway` will be entirely under the control of malicious signers and invalid/harmful messages will be approved.


## Proof of Concept
Here are the possible edge-cases:

1/ A set of malicious signers is able to call `rotateSigners` with addresses under their control `previousSignersRetention` times. Now all possible sets of signers that the operator can use to call `rotateSigners` will be controlled by the initial set of malicious signers. Thus, the malicious signers are completely free to approve any harmful messages without the danger of being rotated by the operator.

2/ If the first rotation of signers is malicious the operator will be unable to rotate to a different set of signers. This happens as the only way for `_validateProof` to not revert will be if the malicious set of signers approves the rotation, which will not occur.

3/ If `previousSignersRetention` is set to 0 the operator will again need the signatures of the malicious signers, which will be unsuccessful as explained in the previous point.

It is important to note that `previousSignersRetention` is immutable and the operator will not be able to increase it to prevent an attack.

## Tools Used
Manual review

## Recommended Mitigation Steps
There are multiple ways to resolve the issue, one is to allow the operator or owner to rotate the signers in case of an attack without the need for signatures of previous signers.
