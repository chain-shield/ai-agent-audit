# Vulnerability details

## Bug Description
With several functions in several contracts in the codebase, the structs are not encoded recursively as defined by [EIP-712](https://eips.ethereum.org/EIPS/eip-712#definition-of-encodedata), the standard for hashing and signing of typed structured data. 

## Vulnerabilty Details
EIP 712 states that 
> The struct values are encoded recursively as hashStruct(value). This is undefined for cyclical data.
https://eips.ethereum.org/EIPS/eip-712#definition-of-encodedata 

In several instances in the codebase, the structs are abi encoded into a keccak hash without encoding them properly. They should be encoded like the example below

```solidity
struct Person {
    string name;
    uint256 age;
}

struct Mail {
    Person from;
    Person to;
    string contents;
}
bytes32 personTypeHash = keccak256("Person(string name,uint256 age)");
bytes32 mailTypeHash = keccak256("Mail(Person from,Person to,string contents)Person(string name,uint256 age)");

function hashPerson(Person memory person) internal pure returns (bytes32) {
    return keccak256(
        abi.encode(
            personTypeHash,
            keccak256(bytes(person.name)),
            person.age
        )
    );
}

function hashMail(Mail memory mail) internal pure returns (bytes32) {
    return keccak256(
        abi.encode(
            mailTypeHash,
            hashPerson(mail.from), // Recursive hashing
            hashPerson(mail.to),   // Recursive hashing
            keccak256(bytes(mail.contents))
        )
    );
}

```

-  it is an array and it is not encoded as it should but instead the message array is passed directly into the hash encoding. Arrays should be encoded like `keccak256(abi.encodePacked(messages))` when passing the into the dataHash. 
-  as the array elements are  also structs, their  variables ought to be hashed properly and recursively(if a struct is within a struct), following the EIP-712 standard (please reference my first snippet example above) 
- there is no typehash defined.

As arrays/structs are encoded incorrectly, the signature verification in the functions listed above is not [EIP-712](https://eips.ethereum.org/EIPS/eip-712) compliant.

Contracts or dapps/backends that encode arrays/structs according to the rules specified in [EIP-712](https://eips.ethereum.org/EIPS/eip-712) will end up with different signatures, causing any of the functions listed above to revert when called.
