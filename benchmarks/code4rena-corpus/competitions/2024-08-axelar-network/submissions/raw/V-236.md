# Vulnerability details

## Impact
Some tokens have different implementation on different chains. For example, [USDT](https://etherscan.io/token/0xdac17f958d2ee523a2206206994597c13d831ec7#writeContract#F6) has `pause` function on Eth, and doesn't have `pause` on [ploygonscan](https://polygonscan.com/token/0xc2132d05d31c914a87c6611c10748aeb04b58e8f#writeProxyContract). 
If such tokens are used, on the source chain, the token can be transferred as expect, but on the dest chain, the token is paused, which will lead the token be stuck in source chain.
## Proof of Concept
I'll take [InterchainTokenService.interchainTransfer](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L454-L478) as an example.
Suppose on Polygon, USDT(doesn't have `pause` function) is used, Alice calls `InterchainTokenService.interchainTransfer` to transfer USDT to Ethereum. But on Ethereum, USDT(which has `pause` function) is paused.

While Alice calls `InterchainTokenService.interchainTransfer` to transfer USDT from polygon to ethereum, in [InterchainTokenService.interchainTransfer](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L454-L478), the function doesn't check the USDT on ethereum has been paused, `interchainTransfer` calls `_takeToken` to transfer USDT from Alice, and compose a message which will be routed to ethereum.
And for `InterchainTokenService.execute` on the ethereum(dest chain), while calling `_giveToken`, the tx will be reverted because USDT is paused on ethereum.
In such case, the USDT on polygon will be stuck
