# Vulnerability details

## Impact
This vulnerability allows any caller to manipulate token balances across chains, potentially leading to:

* Unauthorized minting of tokens on the destination chain.
* Economic attacks by inflating token supply.
* Disruption of the entire cross-chain token ecosystem.
* Loss of funds for users and complete breakdown of trust in the system.

## Proof of Concept
The vulnerability exists in the execute_message function:

```
pub fn execute_message(
    deps: DepsMut,
    cc_id: CrossChainId,
    source_address: Address,
    payload: HexBinary,
) -> Result<Response, Error> {
    // ... (code omitted for brevity)

    if source_address != trusted_source_address {
        return Err(report!(Error::UntrustedAddress(source_address)));
    }

    let its_hub_message =
        ItsHubMessage::abi_decode(&payload).change_context(Error::InvalidPayload)?;

    match its_hub_message {
        ItsHubMessage::SendToHub {
            destination_chain,
            message: its_message,
        } => {
            apply_balance_tracking(
                deps.storage,
                source_chain.clone(),
                destination_chain.clone(),
                &its_message,
            )?;
            // ... (rest of the code)
        }
        _ => Err(report!(Error::InvalidPayload)),
    }
}
```
Vulnerability breakdown:
* The function only checks if the source_address matches a trusted address.
* Once this check passes, it processes the its_message without further validation.
* The apply_balance_tracking function is called with the message content, potentially allowing arbitrary balance changes.

To exploit:
1. An attacker discovers a trusted source address for a particular chain.
2. They craft a message with an arbitrary token ID and amount.
3. They call execute_message with the correct source_address and their crafted payload.
4. The function processes the message, potentially creating or manipulating token balances.
