# Vulnerability details

## Vulnerability Detail
The `deployInterchainToken` function in the `InterchainTokenDeployer` contract uses a `salt` parameter for deterministic address generation when deploying new token contracts. However, there is no mechanism to prevent the reuse of salts. This can lead to deployment failures if the same salt is used multiple times, as the CREATE3 opcode will attempt to deploy to an already occupied address.

## Impact
- Deployment Failures: Repeated use of the same salt will cause subsequent deployments to fail, leading to inconsistent states where expected token deployments do not occur.
- Denial of Service (DoS): An attacker could intentionally use up a large number of salts, making it difficult or impossible for legitimate users to deploy new tokens.

## Proof of Concept
The vulnerable function is deployInterchainToken in the InterchainTokenDeployer contract:
```
function deployInterchainToken(
    bytes32 salt,
    bytes32 tokenId,
    address minter,
    string calldata name,
    string calldata symbol,
    uint8 decimals
) external returns (address tokenAddress) {
    // ... deployment logic
    tokenAddress = _create3(bytecode, salt);
    if (tokenAddress.code.length == 0) revert TokenDeploymentFailed();
    // ...
}
```

## Recommended Mitigation Steps
- Track used salts:
```
mapping(bytes32 => bool) private usedSalts;

function deployInterchainToken(
    bytes32 salt,
    // ... other parameters
) external returns (address tokenAddress) {
    require(!usedSalts[salt], "Salt already used");
    usedSalts[salt] = true;
    
    // ... rest of the function
}
```
- Use a nonce-based salt generation:
```
uint256 private nonce;

function deployInterchainToken(
    // ... other parameters
) external returns (address tokenAddress) {
    bytes32 salt = keccak256(abi.encodePacked(msg.sender, nonce++));
    
    // ... rest of the function
}
```
