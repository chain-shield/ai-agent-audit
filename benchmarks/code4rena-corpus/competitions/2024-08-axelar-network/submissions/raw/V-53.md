# Vulnerability details

## Description

The `InterchainTokenService` contract is designed to facilitate interchain token transfers. It includes an [`expressExecute()` function](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/interchain-token-service/contracts/InterchainTokenService.sol#L375-L396) that allows for expedited execution of cross-chain transactions. This function works in conjunction with [`_contractCallValue()`](https://github.com/code-423n4/2024-08-axelar-network/blob/69c4f2c3fcefb1b8eb2129af9c3685a44ae5b6fe/interchain-token-service/contracts/InterchainTokenService.sol#L1219-L1226), which determines the token and amount for these executions.

The core issue lies in the lack of payload integrity verification in both `expressExecute()` and `_contractCallValue()`. The `expressExecute()` function decodes the payload to check the `messageType` and verifies if the command has been executed, but it doesn't validate the payload against any stored data. Similarly, `_contractCallValue()` decodes the payload to extract `messageType`, `tokenId`, and `amount` without verifying the payload's integrity.

This issue creates a scenario where an attacker can craft a malicious payload to manipulate token transfers. By observing a legitimate interchain transfer and creating a payload with the same `commandId` but different `tokenId` and/or amount, an attacker can call `expressExecute()` with this malicious payload. The contract would accept this payload, potentially leading to unauthorized token transfers.

For example, if a legitimate transfer of 100 TokenA is in progress, an attacker could craft a payload requesting 1000 TokenB with the same `commandId`. When this payload is passed to `expressExecute()`, the function would process it without verifying its authenticity, potentially resulting in the transfer of 1000 TokenB to the attacker.

## Impact
It allows attackers to initiate unauthorized token transfers, potentially leading to significant theft of tokens from the protocol. It undermines the security of the entire express execution mechanism, which is crucial for fast cross-chain transfers. 

## Proof of Concept
1. Alice initiates a legitimate interchain transfer of 100 TokenA (tokenId1) from Chain A to Chain B.
2. The attacker observes this transfer and notes the `commandId`.
3. Before the transfer is executed on Chain B, the attacker crafts a malicious payload with the same `commandId` but requesting 1000 TokenB (tokenId2).
4. The attacker calls `expressExecute()` on Chain B with this malicious payload:

```solidity
function expressExecute(
    bytes32 commandId, // Same as Alice's transfer
    string calldata sourceChain,
    string calldata sourceAddress,
    bytes calldata payload // Malicious payload with tokenId2 and amount 1000
)
```

5. The `expressExecute()` function processes this payload without verifying its authenticity:

```solidity
uint256 messageType = abi.decode(payload, (uint256));
if (messageType != MESSAGE_TYPE_INTERCHAIN_TRANSFER) {
    revert InvalidExpressMessageType(messageType);
}

if (gateway.isCommandExecuted(commandId)) revert AlreadyExecuted();

// ... rest of the function
```

6. The `_contractCallValue()` function is called internally, which also fails to verify the payload:

```solidity
function _contractCallValue(bytes calldata payload) internal view returns (address, uint256) {
    (uint256 messageType, bytes32 tokenId, , , uint256 amount) = abi.decode(payload, (uint256, bytes32, bytes, bytes, uint256));
    if (messageType != MESSAGE_TYPE_INTERCHAIN_TRANSFER) {
        revert InvalidExpressMessageType(messageType);
    }

    return (validTokenAddress(tokenId), amount);
}
```

7. The attacker successfully receives 1000 TokenB instead of Alice receiving her 100 TokenA.

## Tools Used
Manual review

## Recommended Mitigation Steps
To mitigate this issue, implement a robust payload integrity verification system:

1. Store the hash of the original payload when initiating an interchain transfer.
2. Verify the integrity of the payload in both `expressExecute()` and `_contractCallValue()` functions.
