# Vulnerability details

## Impact

Only one unique message can be sent per chain, which is not ideal.

## Proof of Concept

Some cross-chain messages should be repeatable, like transferring the same amount of tokens or sending/receiving a simple message. In the axelarnet-gateway, the message can only be sent once. In `execute_rs`, when `call_contract` is called, `state::save_incoming_msg` will be called.

If there are identical messages, for example a simple "Hello", then only one message can be sent and the subsequent ones will fail as the `INCOMING_MESSAGES` storage already stored the message "Hello". 

Same goes for `OUTGOING_MESSAGES`. After a successful execution where the state of the message has been changed from `Approved` to `Executed` through `update_msg_status()`,

## Recommended Mitigation Steps

For incoming messages, after successfully routing to the Amplifier Router, the message in the `INCOMING_MESSAGES` storage should be deleted.

For outgoing messages, after successful execution to the ITSHub, the message in the `OUTGOING_MESSAGES` should be deleted. It will be good for OUTGOING_MESSAGES to have another status `Success` to track that the message has been successfully delivered, and only then will the message be deleted from storage.

```
#[cw_serde]
pub(crate) enum MessageStatus {
    Approved,
    Executed,
++  Success,
}

#[cw_serde]
pub(crate) struct MessageWithStatus {
    pub msg: Message,
    pub status: MessageStatus,
}
```
