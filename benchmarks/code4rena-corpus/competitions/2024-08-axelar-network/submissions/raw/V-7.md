# Vulnerability details

## Impact
[_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192) doesn't validate any signatures, but only their weight. This means that bad signatures can be used.

## Proof of Concept
[_validateSignatures](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L192) doesn't properly validate  nay of the signatures and only checks if the provided signatures are assigned enough weight to pass the threshold.

```solidity
        for (uint256 i; i < signaturesLength; ++i) {
            address recoveredSigner = ECDSA.recover(messageHash, signatures[i]);

            //@audit this doesn't do anything
            for (; signerIndex < signersLength && recoveredSigner != signers[signerIndex].signer; ++signerIndex) {}

            if (signerIndex == signersLength) revert MalformedSignatures();
            totalWeight = totalWeight + signers[signerIndex].weight;


            if (totalWeight >= weightedSigners.threshold) {
                if (i + 1 == signaturesLength) return;
                revert RedundantSignaturesProvided(i + 1, signaturesLength);
            }

            ++signerIndex;
        }
```
In tern [_validateProof](https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/governance/BaseWeightedMultisig.sol#L129) will not validate anything as it depends on `_validateSignatures`. Because of that `executeCalls`, `approveMessages` and other functions that rely on `_validateProof` will allow malicious proof to execute the code.
