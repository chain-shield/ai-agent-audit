# Vulnerability details

`_validateProof()` is called either to approve messages, rotate signers or even execute calls.
However a check inside the function will always lead to the function reverting.

## Proof of Concept
The `signerEpoch` is calculated from the `signerHash` which depends on the weighted signers payload `WeightedSigners signers` inside the Proof struct.

```solidity
File: BaseWeightedMultisig.sol

    function _validateProof(bytes32 dataHash, Proof calldata proof) internal view returns (bool isLatestSigners) {
        BaseWeightedMultisigStorage storage slot = _baseWeightedMultisigStorage();

        WeightedSigners calldata signers = proof.signers;

        bytes32 signersHash = keccak256(abi.encode(signers));
>       uint256 signerEpoch = slot.epochBySignerHash[signersHash];   /// @note - zero for the first signers
        uint256 currentEpoch = slot.epoch;

        isLatestSigners = signerEpoch == currentEpoch;

>       if (signerEpoch == 0 || currentEpoch - signerEpoch > previousSignersRetention) revert InvalidSigners();     /// @note - will revert because the first check is true

        bytes32 messageHash = messageHashToSign(signersHash, dataHash);

        _validateSignatures(messageHash, signers, proof.signatures);
    }
```
Whenever `slot.epochBySignerHash()` will be called to get the `signerEpoch` for the first time, it will return `0` because it has not been initialized yet. When the function enters the `if` block, the first check will be true & it will revert.

```solidity
   
    if (signerEpoch == 0 || currentEpoch - signerEpoch > previousSignersRetention) revert InvalidSigners();
```

## Impact
DoS when calling `_validateProof()` for the first time because it is not initialized 

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a function which allows the operator to set the first signers.
