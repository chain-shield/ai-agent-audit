# Vulnerability details

## Impact
ITS hub tracks token balances so that a chain does not bridge out more than what was bridged in. However, the issue is that a chain could bridge out what was never deployed. 

A chain can have 3 possible values for TokenBalance 
* Tracked: when ITS token is deployed remotely
* Untracked: when TokenManager is deployed remotely
* None: when no remote is deployed

None means 2 things, not 1.
* It means the original chain (that hosts the original ITS token)
* It could also mean a strange chain. A strange chain is one that has neither the original nor a remote token.

When a chain is compromised, it cannot bridge out unlimited remote ITS tokens that were deployed because the balance is tracked. However, they can bridge out unlimited ITS tokens that were never deployed remotely because we return Ok() when the balance is None. This would be a lot of tokens on several chains. 

The compromised chain is pretending to own the original ITS token. This is very severe, especially considering that the main purpose of the hub and audit is to reduce damage to the wider ecosystem when a chain is compromised.


## Proof of Concept
Assuming, there are 2 ITS tokens that are native on Ethereum: TokenA and TokenB. And then
* TokenA was deployed remotely to MeowChain. TokenA balance would be tracked.
* 1,000 TokenA was sent from Ethereum to MeowChain
* MeowChain gets compromised

Let's compare 2 scenarios.
* MeowChain tries to send 1,001 TokenA to Ethereum
* Hub::update_token_balance would return an error and block the message
* This is good. The damage is contained

Vs

* MeowChain tries to send 1,000,000,000 TokenB to Ethereum
* Hub::update_token_balance would return Ok()
* 1,000,000,000 TokenB would be minted on Ethereum
* Repeat for every undeployed token from every other chain
* This is bad, the whole system could crumble

A compromised chain cannot exit its ITS tokens, but can still exit across all remaining ITS tokens. This would mean a lot of ITS tokens would be at risk. The more risky a chain is or the less popular it is, the fewer tokens would be deployed remotely, and therefore the more valuable tokens would be at risk during a compromise.

For example, MeowChain is a new amplifier chain that is not popular and has only 2 remote ITS tokens. One from Ethereum, and one from Arbitrum. If MeowChain gets compromised, those 2 ITS tokens would be protected. But, every other ITS token on Ethereum and Arbitrum and every other connected chain--which could be thousands of distinct tokens that are worth billions of dollars--is now at risk.

Examples of a compromise that could happen include
* Bad precompiles or revert handling: [Godwoken](https://medium.com/risk-dao/how-i-could-drain-an-entire-blockchain-post-mortem-on-a-bug-in-godwoken-chain-2451f83f72d2), [evmos](https://www.asymmetric.re/blog/evmos-precompile-state-commit-infinite-mint)
* Invalid transactions: [frontier](https://github.com/polkadot-evm/frontier/security/advisories/GHSA-hw4v-5x4h-c3xm)
* Consensus or malicious validator: [NEAR](https://hackenproof.com/blog/for-hackers/near-rewards-1-8-million-to-ethical-hackers-at-hackenproof#h2_2)
* Compiler bugs: [vyper](https://medium.com/rektify-ai/the-vyper-compiler-saga-unraveling-the-reentrancy-bug-that-shook-defi-86ade6c54265)
* Event spoofing
* Contract compromise: e.g admin key, take over, bug
* amplifier/routing architecture compromise: External Gateway, Gateway for X on Axelar, Prover, Verifier, Relayer

#[test]
fn none_balance_tracking_interchain_transfer() {
    let mut deps = setup();

    let source_chain: ChainName = "compromised-chain".parse().unwrap();
    let destination_chain: ChainName = "original-chain".parse().unwrap();
    let source_address: Address = "trusted-source".parse().unwrap();
    let destination_address: Address = "trusted-destination".parse().unwrap();

    register_trusted_address(&mut deps.as_mut(), source_chain.as_ref(), &source_address);
    register_trusted_address(
        &mut deps.as_mut(),
        destination_chain.as_ref(),
        &destination_address,
    );

    let token_id = TokenId::new([1u8; 32]);
    let amount = Uint256::from(1000u128);

    let transfer_message = ItsMessage::InterchainTransfer {
        token_id: token_id.clone(),
        source_address: HexBinary::from_hex("1234").unwrap(),
        destination_address: HexBinary::from_hex("5678").unwrap(),
        amount,
        data: HexBinary::from_hex("abcd").unwrap(),
    };
    let its_hub_message = ItsHubMessage::SendToHub {
        destination_chain: destination_chain.clone(),
        message: transfer_message.clone(),
    };

    let payload = its_hub_message.abi_encode();
    let cc_id = CrossChainId::new(source_chain.clone(), "transfer-message-id").unwrap();
    let result = execute_message(deps.as_mut(), cc_id, source_address, payload).unwrap();

    // Check balances after transfer
    let source_balance =
        state::may_load_token_balance(deps.as_ref().storage, &token_id, &source_chain).unwrap();
    let destination_balance =
        state::may_load_token_balance(deps.as_ref().storage, &token_id, &destination_chain)
            .unwrap();

    assert_eq!(source_balance, None);
    assert_eq!(destination_balance, None);

    let axelarnet_gateway: axelarnet_gateway::Client =
        client::Client::new(deps.as_mut().querier, Addr::unchecked("gateway")).into();
    let expected_msg = axelarnet_gateway.call_contract(
        destination_chain.clone(),
        destination_address,
        ItsHubMessage::ReceiveFromHub {
            source_chain: source_chain.clone(),
            message: transfer_message.clone(),
        }
        .abi_encode(),
    );
    assert_eq!(result.messages.len(), 1);
    assert_eq!(result.messages[0].msg, CosmosMsg::Wasm(expected_msg));
}

## Recommended Mitigation Steps
Make a distinction between the 2 kinds of None and return Error if it is a strange chain. We could set original tokens to Untracked balance and return an Error for every other case.

```diff
- Some(_) | None => (),
+ Some(_) => (),
+ None => return Err(Error::TokenNotRegistered),
```
