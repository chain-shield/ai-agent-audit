# Vulnerability details

## Impact

`_getExecuteParams()` function is used to validate the source chain (which should be Axelarnet in the case of routing via ITS Hub) and retrieves the original source chain from the payload. The problem is that the function incorrectly checks for the  source chain inside of the if-else statement making all the messages revert if they directly came from Axelarnet.

## Proof of Concept

`_getExecuteParams()` current implementation:


https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L975-988
```
 if (messageType == MESSAGE_TYPE_RECEIVE_FROM_HUB) {
            if (keccak256(abi.encodePacked(sourceChain)) != ITS_HUB_CHAIN_NAME_HASH) revert UntrustedChain();

            (, originalSourceChain, payload) = abi.decode(payload, (uint256, string, bytes));

            // Check whether the original source chain is expected to be routed via the ITS Hub
            if (trustedAddressHash(originalSourceChain) != ITS_HUB_ROUTING_IDENTIFIER_HASH) revert UntrustedChain();

            // Get message type of the inner ITS message
            messageType = _getMessageType(payload);
        } else {
            // Prevent receiving a direct message from the ITS Hub. This is not supported yet.
            if (keccak256(abi.encodePacked(sourceChain)) == ITS_HUB_CHAIN_NAME_HASH) revert UntrustedChain();
        }

```

As you can see, it first checks whether the message type is `MESSAGE_TYPE_RECEIVE_FROM_HUB` and then it verifies if the source chain is Axelarnet. And if it's not, the message reverts as the source chain is untrusted. The problem here is that inside of the else-statement it checks again for the source chain (if the message type is different) and reverts the message if Axelarnet. The comment points to the fact that direct messages from ITS cannot be received at the moment. But ITS Hub is not the only app that would make use of Axelarnet as stated in the docs:

```
This is a specific gateway contract that allows apps on Axelar to send/receive cross-chain messages via the Amplifier protocol. ITS Hub is one such app that will interact with this gateway. 
```

So there can be potentially other apps that would interact with it in the future and every message that was directly sent from Axelarnet would basically revert.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Change the second check of the source chain if the if condition is not true.
