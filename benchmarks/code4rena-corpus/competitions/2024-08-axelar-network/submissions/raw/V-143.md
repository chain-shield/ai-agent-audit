# Vulnerability details

## Impact
The ITS system which is design to make use of the Axelarnet gateway contract to facilitate sending or receiving cross-chain message. Among other function the execute_message() which receives and executes an incoming ITS message verifies the source address, decodes the message sent, applies balance tracking and then forwards the message to the destination chain lack verification on the destination chain been the same with the source chain.
Thus a malicious user could exploit the absence of this verification in order to flood the Axelarnet gateway contract which are responsible for facilitating the sending or receiving of cross-chain messages with false transactions which could temporarily cause the system to halt execution of other transaction depending on the magnitude of the amount of false transaction sent by the malicious user.
This attack can be feasible because an attacker could cross-chain message calls on a trusted low-fee, low-latency network as the source chain/address to the same chain/address as many times as possible in which the gateway will have to act upon thereby consuming computational resources, bloating the storage which could potentially slow down the system and result to economic damage to the protocol.

## Proof of Concept
1. James which is a griefer creates a theoretically infinite series of transactions on Arbitrum, a low-fee, low-latency network as a source_chain with a address of "0x1" for example and destination_chain as Arbitrum and destination_address of "0x1" and a crafted message which is acceptable by the system.
2. Messages are sent to the system and this incoming ITS message are received by the execute_message function which validated the source and destination address to be from trusted source although they are from the same chain
3. The ITS Hub which make use of the Axelarnet gateway contract to facilitate sending this false cross-chain message continuously send this message back and forth to the same address
4. Meanwhile John requests a cross-chain message call; however, because the gateway must handle many of Jame’s transactions first, John has to wait an undefined amount of time for her transaction to be executed.

Add this to execute_message()
