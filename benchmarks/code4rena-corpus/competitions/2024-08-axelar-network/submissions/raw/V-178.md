# Vulnerability details

## Impact
Multicall being marked as payable can lead to 2 impact:
- user pay more eth than expected those exceed eth stuck in contract
- the msg.value is used many times

## Proof of Concept
Multicall function:
```solidity
  function multicall(bytes[] calldata data) public payable returns (bytes[] memory results) {
      results = new bytes[](data.length);
      bool success;
      bytes memory result;
      for (uint256 i = 0; i < data.length; ++i) {
          // slither-disable-next-line calls-loop,delegatecall-loop
          (success, result) = address(this).delegatecall(data[i]);

          if (!success) {
              if (result.length == 0) revert MulticallFailed();
              assembly {
                  revert(add(32, result), mload(result))
              }
          }

          results[i] = result;
      }
  }
```
Many contract is inherit Multicall function:

```solidity
contract InterchainTokenService is
    Upgradable,
    Operator,
    Pausable,
    Multicall,  <@
    Create3AddressFixed,
    ExpressExecutorTracker,
    InterchainAddressTracker,
    IInterchainTokenService
{
    using AddressBytes for bytes;
    using AddressBytes for address;
```

```solidity
contract InterchainTokenFactory is IInterchainTokenFactory, ITokenManagerType, Multicall, Upgradable {  <@
    using AddressBytes for address;

    IInterchainTokenService public immutable interchainTokenService;
    bytes32 public immutable chainNameHash;
    IAxelarGateway public immutable gateway;
```

msg.value persist over calls, if above contract holding eth , multiple ETH deposits will use the same msg.value in each of them, resulting in multiple deposits, that sums up to much bigger accounted value than actually deposited value, up to contract's ETH holdings.
