# Vulnerability details

## Impact

In the `execute_message` function, there is a potential logic bug related to a missed check:

The function verifies that the source address matches the trusted address for the source chain, but it does not verify that the destination chain in the message matches the current chain (config.chain_name). This means that messages intended for other chains could be executed on this chain if they come from a trusted source address.


## Proof of Concept


1. The ITS Hub contract acts as a central router for cross-chain token operations.
2. It receives messages from trusted ITS contracts on other chains via the Axelarnet gateway.
3. The bug allows messages intended for other chains to be executed on the wrong chain.

Impact and PoC:
1. Attacker sends a malicious "DeployInterchainToken" message from Chain A to ITS Hub, but specifies Chain B as destination.
2. ITS Hub on Axelar processes this message, deploying the token on Axelar instead of Chain B.
3. This could lead to inconsistent token states across chains

4. The attacker could potentially manipulate token balances or create unauthorized tokens on unintended chains.

This bug breaks the fundamental assumption of correct message routing in the cross-chain system.

## Recommended Mitigation Steps

To fix this, an additional check should be added after verifying the source address:

```rust
if its_hub_message.destination_chain() != config.chain_name {
    return Err(report!(Error::InvalidDestinationChain(its_hub_message.destination_chain())));
}
```
