# Vulnerability details

## Impact
The approved message at the destination chain may be skipped for execution by maliciously front running the validation which can be called by anyone and make the status of message as executed.

## Proof of Concept
After an interchain message is initiated at the source chain, the message will be process and signed by validators. Once the threshold of signatures is reached, relayer can call `AxelarAmplifierGateway.approveMessages()` at the destination chain to make it ready for execution. The actual execution will call `validateContractCall()` or `validateMessage()` to check if the message is approved by validators and mark it as executed. However, these two function do not have any access control. Malicious actor can front run the call for these two functions and the status will be changed as executed but no actual execution was taken.
