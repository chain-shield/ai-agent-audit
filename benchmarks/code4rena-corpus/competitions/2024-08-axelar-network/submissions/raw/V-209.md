# Vulnerability details

## Impact
This vulnerability can lead to:

1. Permanent loss of funds intended for gas fees in cross-chain transactions.
2. Failure of cross-chain transactions due to insufficient gas on the destination chain.
3. Accumulation of stuck ETH in the contract with no recovery mechanism.
4. Potential Denial of Service (DoS) for cross-chain functionality.

## Proof of Concept
The vulnerability exists in the _callContract and _callContractWithToken functions:

```
function _callContract(
    string memory destinationChain,
    bytes memory payload,
    IGatewayCaller.MetadataVersion metadataVersion,
    uint256 gasValue
) internal {
    // ... (code omitted for brevity)

    (bool success, bytes memory returnData) = gatewayCaller.delegatecall(
        abi.encodeWithSelector(
            IGatewayCaller.callContract.selector,
            destinationChain,
            destinationAddress,
            payload,
            metadataVersion,
            gasValue
        )
    );

    if (!success) revert GatewayCallFailed(returnData);
}
```
Vulnerability breakdown:
1. The function uses delegatecall to call the gatewayCaller contract.
2. delegatecall executes the code of the called contract in the context of the calling contract, meaning:

* The msg.value is not forwarded to the called contract.
* Any ETH sent with the transaction remains in the calling contract.


3. There is no mechanism to retrieve or forward the stuck ETH.

To reproduce:

1. A user initiates a cross-chain transaction with a non-zero gasValue.
2. The ETH sent for gas fees remains in the contract instead of being forwarded.
3. The cross-chain transaction may fail on the destination chain due to lack of gas.
4. The ETH becomes permanently stuck in the contract.
## Tools Used
Manual code review
## Recommended Mitigation Steps
Replace delegatecall with a regular call and forward the msg.value
