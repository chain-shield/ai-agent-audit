# Vulnerability details

## Description
The approveService function at the TokenManager contract does an approve safe call to a token contract in order to increase the current approved value the InterchainTokenService contract is entlited to spend from the TokenManager contract.
The logic flow approves UINT256_MAX for the InterchainTokenService, as can be seen in the following code snippet:
```solidity
function approveService() external onlyService {IERC20(this.tokenAddress()).safeCall(abi.encodeWithSelector(IERC20.approve.selector, interchainTokenService, UINT256_MAX));
    }
```

This is not correct for tokens such as USDT, as they require the user to first set the approval to zero then to set it to another value. In this contract's case, to the UINT256_MAX value.
## Impact
The approveService function will not be able to renew USDT approvals unless the current approved value is already zero.
## Tools Used
Manual review
## Recommended Mitigation Steps
Make sure to set the token approval to zero first then set it to UINT256_MAX after, as this pattern accommodates non-standard token approval flows.
