# Vulnerability details

## Description
ITS accounting can be bricked during the `message execution` in case the source balance is updated properly but the `destination balance update fails` which seems to warrant `High` severity as funds would be lost.

During the message execution, `apply_balance_tracking` is called to update the token balance for the source and destination chain. There is a specific case which is not handled properly which is where the source has sufficient funds and balance is updated properly, but somehow the destination balance update fails (could be any storage error), which will cause the token balance to be subtracted from the source chain but not deposited into the destination chain, which is effectively a funds loss for the user.

```rust
fn apply_balance_tracking(
    storage: &mut dyn Storage,
    source_chain: ChainName,
    destination_chain: ChainName,
    message: &ItsMessage,
) -> Result<(), Error> {
    match message {
        ItsMessage::InterchainTransfer {
            token_id, amount, ..
        } => {
            // Update the balance on the source chain
            update_token_balance(
                storage,
                token_id.clone(),
                source_chain.clone(),
                *amount,
                false,
            )
            .change_context_lazy(|| Error::BalanceUpdateFailed(source_chain, token_id.clone()))?;

            // Update the balance on the destination chain
            update_token_balance_force_fail(
                storage,
                token_id.clone(),
                destination_chain.clone(),
                *amount,
                true,
            )
            .change_context_lazy(|| {
                Error::BalanceUpdateFailed(destination_chain, token_id.clone())            // <----------------------- When this fails!
            })?
        }
        // Start balance tracking for the token on the destination chain when a token deployment is seen
        // No invariants can be assumed on the source since the token might pre-exist on the source chain
        ItsMessage::DeployInterchainToken { token_id, .. } => {
            start_token_balance(storage, token_id.clone(), destination_chain.clone(), true)
                .change_context(Error::InvalidStoreAccess)?
        }
        ItsMessage::DeployTokenManager { token_id, .. } => {
            start_token_balance(storage, token_id.clone(), destination_chain.clone(), false)
                .change_context(Error::InvalidStoreAccess)?
        }
    };

    Ok(())
}
```


## Impact
User could lost the tokens transfered if the internal destination balance update fails.

## PoC
Apply the following changes in `interchain-token-service/src/contract/execute.rs` and run the command `cargo test balance_tracking_sufficient_balance_but_destination_fails`

This will simulate an `execute_message` but when the `apply_balance_tracking` is called, it works only partially, the source balance works fine, but the destination fails for some reasons, in such case the source balance is still modified, which means `user funds loss`, as not transfered to the destination chain but removed from the source chain.

Add also this function in `interchain-token-service/src/state.rs`

```rust
pub fn update_token_balance_force_fail(
    _storage: &mut dyn Storage,
    token_id: TokenId,
    chain: ChainName,
    _amount: Uint256,
    _is_deposit: bool,
) -> Result<(), Error> {
    Err(Error::TokenAlreadyRegistered { token_id, chain }) // could be any error really with the storage, here using this for simplicity reasons.
}
```

    #[test]
    fn balance_tracking_sufficient_balance_but_destination_fails() {
        let mut deps = setup();

        let source_chain: ChainName = "source-chain".parse().unwrap();
        let destination_chain: ChainName = "destination-chain".parse().unwrap();
        let source_address: Address = "trusted-source".parse().unwrap();
        let destination_address: Address = "trusted-destination".parse().unwrap();

        register_trusted_address(&mut deps.as_mut(), source_chain.as_ref(), &source_address);
        register_trusted_address(
            &mut deps.as_mut(),
            destination_chain.as_ref(),
            &destination_address,
        );

        let token_id = TokenId::new([3u8; 32]);
        let transfer_amount = Uint256::from(1000u128);

        // Set up a sufficient balance on the source chain
        let sufficient_amount = Uint256::from(1500u128);
        state::start_token_balance(
            deps.as_mut().storage,
            token_id.clone(),
            source_chain.clone(),
            true,
        )
        .unwrap();
        state::update_token_balance(
            deps.as_mut().storage,
            token_id.clone(),
            source_chain.clone(),
            sufficient_amount,
            true,
        )
        .unwrap();

        // Create a transfer message
        let transfer_message = ItsMessage::InterchainTransfer {
            token_id: token_id.clone(),
            source_address: HexBinary::from_hex("1234").unwrap(),
            destination_address: HexBinary::from_hex("5678").unwrap(),
            amount: transfer_amount,
            data: HexBinary::from_hex("abcd").unwrap(),
        };
        let its_hub_message = ItsHubMessage::SendToHub {
            destination_chain: destination_chain.clone(),
            message: transfer_message,
        };

        let payload = its_hub_message.abi_encode();
        let cc_id = CrossChainId::new(source_chain.clone(), "destination-update-fail-message-id").unwrap();

        let result = execute_message(deps.as_mut(), cc_id, source_address.clone(), payload);

        assert!(result.is_err());
        assert!(err_contains!(
            result.unwrap_err(),
            Error,
            Error::BalanceUpdateFailed(..)
        ));

        // Check that the source balance remains unchanged
        let source_balance = state::may_load_token_balance(deps.as_ref().storage, &token_id, &source_chain).unwrap();
        assert_eq!(source_balance, Some(TokenBalance::Tracked(sufficient_amount)));
    }
