# Vulnerability details

## Summary

The deploy function in the Deployer contract attempts to transfer native tokens to the contract address before the contract is actually deployed, leading to potential loss of funds and deployment failures.

## Description

In the the `Deployer::deploy`, it tries to transfer native tokens (ETH) to the contract address that is about to be deployed. However, this transfer occurs before the actual deployment takes place which means the transfer would fail leading to potential loss of funds

The problematic code is:

```solidity
    if (msg.value > 0) {
    // slither-disable-next-line unused-return
    deployedAddress_.safeNativeTransfer(msg.value);
    }

    deployedAddress_ = _deploy(bytecode, deploySalt);
```


This sequence of operations is incorrect because it tries to send funds to an address that doesn't yet contain a contract. As a result, the transfer will fail, potentially causing the entire deployment transaction to revert or, worse, sending funds to an address that could later be controlled by an attacker.

**Illustration**

1. A user calls `deploy` function with some ETH value. 
2. The function calculates the future contract address. 
3. It attempts to transfer ETH to this address, which fails as no contract exists there yet. 
4. The actual deployment of the contract address occurs after this failed transfer.
