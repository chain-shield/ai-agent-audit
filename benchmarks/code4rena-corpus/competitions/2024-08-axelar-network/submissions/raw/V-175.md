# Vulnerability details

## Impact

ITS contracts in the current implementation are used to transfer tokens between chains and also deploy remote interchain tokens and token managers for them. The problem is that the contract converts the address of the destination contract to Ethereum type address with 20 bytes and not all the chains have the same address size. This will lead to tx revert on some other chains and will make it impossible to implement remote transactions.


## Proof of Concept

Take a look at `_processInterchainTransferPayload()` functionality:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/InterchainTokenService.sol#L733-739
```
{
            bytes memory destinationAddressBytes;
            (, tokenId, sourceAddress, destinationAddressBytes, amount, data) = abi.decode(
                payload,
                (uint256, bytes32, bytes, bytes, uint256, bytes)
            );
            destinationAddress = destinationAddressBytes.toAddress();
        }

```

It takes the payload and decodes `destinationAddressBytes` from it. Then it calls `toAddress()`:

https://github.com/code-423n4/2024-08-axelar-network/blob/main/axelar-gmp-sdk-solidity/contracts/libs/AddressBytes.sol#L17-23
```
 function toAddress(bytes memory bytesAddress) internal pure returns (address addr) {
        if (bytesAddress.length != 20) revert InvalidBytesLength(bytesAddress);

        assembly {
            addr := mload(add(bytesAddress, 20))
        }
    }

```

So if the address is not equal to the 20 bytes, the tx will revert. This will cause problems with implementation on Solana, for instance, where 32 bytes addresses are used:

https://solana.com/docs/core/accounts

## Tools Used

Manual review.

## Recommended Mitigation Steps

Handle the address conversion logic differently to ensure chain compatibility.
