# Vulnerability details

## Vulnerability Detail
The `burn` function in `InterchainToken.sol` allows any address with the `MINTER` role to burn tokens from any account without proper authorization checks. This function calls an internal `_burn` function that directly modifies balances without verifying the caller's relationship to the account being burned from.

The vulnerable code is in two parts:

- The external burn function:
```
function burn(address account, uint256 amount) external onlyRole(uint8(Roles.MINTER)) {
    _burn(account, amount);
}
```
- The internal _burn function:
```
    function _burn(address account, uint256 amount) internal virtual {
        if (account == address(0)) revert InvalidAccount();

        balanceOf[account] -= amount;
        totalSupply -= amount;
        emit Transfer(account, address(0), amount);
    }

```
While the `burn` function is restricted to the MINTER role, it allows burning tokens from any non-zero address without additional authorization checks.
## Impact
- Unauthorized Token Destruction: Any address with the `MINTER` role can burn tokens from any account without the account owner's permission.

## Proof of Concept
To demonstrate this vulnerability:

- Assume Alice has 1000 tokens and Bob has the MINTER role.
- Bob, despite not owning Alice's tokens, can call:
```
   interchainToken.burn(aliceAddress, 1000);
   ```
- This call will succeed, burning all of Alice's tokens without her permission.

## Recommended Mitigation Steps
- Add authorization checks in the external burn function:
```
function burn(address account, uint256 amount) external onlyRole(uint8(Roles.MINTER)) {
    require(account == msg.sender || isApprovedForAll(account, msg.sender), "Not authorized to burn");
    _burn(account, amount);
}
```
