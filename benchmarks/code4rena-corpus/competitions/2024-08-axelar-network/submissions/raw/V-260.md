# Vulnerability details

## Vulnerability Details

The InterchainTokenFactory contract allows for the registration of gateway tokens, which are crucial for cross-chain token operations. The `registerGatewayToken` function is responsible for this registration process. The `registerGatewayToken` function has a critical centralization risk. It's restricted to be called only by the contract owner, which creates a single point of failure and trust issue.

```solidity
function registerGatewayToken(bytes32 tokenIdentifier, string calldata symbol) external onlyOwner returns (bytes32 tokenId) {
    address tokenAddress = gateway.tokenAddresses(symbol);
    if (tokenAddress == address(0)) revert NotGatewayToken(symbol);

    bytes memory params = abi.encode('', tokenAddress);
    bytes32 salt = gatewayTokenSalt(tokenIdentifier);

    tokenId = interchainTokenService.deployTokenManager(salt, '', TokenManagerType.GATEWAY, params, 0);
}
```
    

## Impact

1. Centralization: Only the contract owner can register gateway tokens, creating a central point of control.
2. Trust Requirement: Users must trust the owner not to register malicious or incorrect tokens.
3. Scalability Issues: As the system grows, relying on a single entity for registration could become a bottleneck.
4. Potential for Abuse: An compromised owner account could register unauthorized tokens or prevent legitimate tokens from being registered.


## Scenario

Imagine a scenario where a new legitimate gateway token needs to be registered urgently, but the owner is unavailable or the owner's private key is compromised. This could lead to significant delays or potential system manipulation.


## Fix

Implement a multi-signature wallet or a governance mechanism for registering gateway tokens. This could involve:

1. Creating a separate governance contract with voting mechanisms.
2. Implementing a time-lock for registration requests to allow for community review.
3. Requiring multiple trusted parties to approve a token registration.
