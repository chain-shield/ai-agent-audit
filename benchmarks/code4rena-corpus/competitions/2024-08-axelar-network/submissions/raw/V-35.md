# Vulnerability details

https://github.com/code-423n4/2024-08-axelar-network/blob/main/interchain-token-service/contracts/utils/InterchainTokenDeployer.sol#L63

## Impact
The `deployInterchainToken` function in the `InterchainTokenDeployer` contract is vulnerable to front-running attacks. The `salt` is a user-supplied parameter and it is used in the contract deployment, allowing attackers to predict the address of the newly deployed contract. An attacker can precompute the deployment address using the same salt and front-run the transaction, deploying a contract at the desired address before the legitimate user does. This could lead to the loss of deployment opportunities for legitimate users, misdirection of funds or functionality.

By front-running, an attacker could deploy a token with the same parameters as intended by the original deployer but gain control over the token's initial distribution.

Since `salt` is provided by the user and used directly in the `_create3` function, an attacker can precompute the address of the contract that will be deployed and deploy their own contract at that address first. This can be particularly problematic if the legitimate user is trying to deploy a token contract with significant value.

Manual code review

## Recommended Mitigation Steps
Consider adding and encoding `block.timestamp` and `block.number` combined with the user's `salt` or combine the `salt` with other unique data, such as the `msg.sender` address or a `nonce`. This will make the address less predictable and reduce the risk of front-running:
