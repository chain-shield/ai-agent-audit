# Vulnerability details

## Impact

The presence of an uninitialized state variable, specifically the 'nameHash' in the provided 'ERC20Permit' contract, poses significant risks to the smart contract's functionality and integrity. If the 'nameHash' variable is accessed before it has been expressly initialized, it will contain its default value of '0x0'.

## Proof of Concept

The uninitialized state variable nameHash in the ERC20Permit smart contract poses a risk of unexpected behavior during contract execution. If nameHash is accessed without being initialized, it will contain its default value of 0x0. This can lead to incorrect processing within critical functions that rely on nameHash as a valid domain separator for EIP-712 signatures, potentially leading to authorization failures or vulnerabilities in token transfers.



    bytes32 public nameHash;

    string private constant EIP191_PREFIX_FOR_EIP712_STRUCTURED_DATA = '\x19\x01';

    // keccak256('EIP712Domain(string name,string version,uint256 chainId,address verifyingContract)')
    bytes32 private constant DOMAIN_TYPE_SIGNATURE_HASH = bytes32(0x8b73c3c69bb8fe3d512ecc4cf759cc79239f7b179b0ffacaa9a75d522b39400f);

    // keccak256('Permit(address owner,address spender,uint256 value,uint256 nonce,uint256 deadline)')
    bytes32 private constant PERMIT_SIGNATURE_HASH = bytes32(0x6e71edae12b1b97f4d1f60370fef10105fa2faae0126114a169c64845d6126c9);



The attacker deploys the ERC20Permit contract without properly passing a name string into the constructor, or waits until after deployment to call the _setNameHash function (if not properly restricted).

## Recommended Mitigation Steps

Ensure that the nameHash variable is initialized either at the point of declaration or within the contract's constructor. Orelse, Modify the contract constructor to accept a name and set the 'nameHash' directly.
