# Lack of ERC-1271 Compliance in AxelarAmplifierGateway, BaseWeighted MultiSig and ERC20Permit.


Absence of ERC-1271 Support Limits Compatibility with Smart Contract Wallets

## Issue Description

The AxelarAmplifierGateway, BaseWeightedMultisig, and ERC20Permit contracts do not implement the ERC-1271 standard for signature validation. While these contracts offer sophisticated multi-signature and permit functionalities through custom implementations, the absence of ERC-1271 support may significantly limit interoperability with smart contract wallets and certain DeFi protocols that expect ERC-1271 compliance.

## Impact

The lack of ERC-1271 support has the following impacts:

1. Limited Compatibility: Smart contract wallets relying on ERC-1271 for signature validation cannot interact directly with these contracts using their standard signature mechanisms.

2. Reduced Interoperability: Integration with protocols or tools expecting ERC-1271 compliance may be challenging or impossible without additional adapters or modifications.

3. User Experience: Users with smart contract wallets may face difficulties or be unable to use certain features requiring signature validation.

4. Ecosystem Fragmentation: Lack of adherence to this standard contributes to ecosystem fragmentation, potentially limiting protocol adoption and integration possibilities.

5. Additional Complexity: Users or developers interacting with the contract may need to use non-standard signature validation methods, increasing complexity.
## Proof of Concept

The issue is evident in multiple parts of the provided contracts:

1. AxelarAmplifierGateway:

```solidity
function validateProof(bytes32 dataHash, Proof calldata proof) external view returns (bool isLatestSigners) {
    return _validateProof(dataHash, proof);
}
```

This function uses a custom `Proof` struct instead of the ERC-1271 signature format. The `Proof` struct is defined as:

```solidity
struct Proof {
    WeightedSigners signers;
    bytes[] signatures;
}
```

2. BaseWeightedMultisig:

```solidity
function _validateSignatures(
    bytes32 messageHash,
    WeightedSigners calldata weightedSigners,
    bytes[] calldata signatures
) internal pure {
    // Custom signature validation logic
}
```

This function implements a weighted multi-sig scheme, diverging significantly from ERC-1271's single-signature approach.

3. ERC20Permit:

```solidity
function permit(address issuer, address spender, uint256 value, uint256 deadline, uint8 v, bytes32 r, bytes32 s) external {
    // EIP-2612 implementation
}
```

This function implements EIP-2612, which is different from ERC-1271 and doesn't address compatibility for smart contract wallets.

Comparative Analysis with ERC-1271:

a. Function Signature:

   - ERC-1271: `isValidSignature(bytes32 hash, bytes memory signature)`
   - Contracts: No equivalent function
   - 
   Implication: The contracts lack the standard ERC-1271 function, causing integration issues.

b. Parameters:

   - ERC-1271: Simple `bytes32 hash` and `bytes memory signature`
   - Contracts: Complex structs (`Proof`, `WeightedSigners`) and multiple parameters

   Implication: Custom structs and parameter formats are incompatible with standard ERC-1271 calls.

c. Return Type:

   - ERC-1271: `bytes4 magicValue`
   - Contracts: `bool` or `void`

   Implication: Return values don't match ERC-1271 expected magic value.

d. Signature Validation Logic:

   - ERC-1271: Single signature validation
   - Contracts: Complex multi-signature scheme with weights and thresholds, and EIP-2612 style validation
   
   Implication: The implemented logic is significantly different from ERC-1271, lacking compatibility.

## Recommendations

To implement ERC-1271 compliance while maintaining existing functionality:

1. Implement the standard ERC-1271 interface alongside existing functions:

   ```
   function isValidSignature(bytes32 hash, bytes memory signature) external view returns (bytes4 magicValue) {
       Proof memory proof = convertSignatureToProof(signature);
       bool isValid = validateProof(hash, proof);
       return isValid ? 0x1626ba7e : 0xffffffff;
   }
   ```
2. Update existing functions to optionally support ERC-1271:

   ```
   function validateProof(bytes32 dataHash, bytes memory signatureOrProof, bool isERC1271) external view returns (bool) {
       if (isERC1271) {
           return isValidSignature(dataHash, signatureOrProof) == 0x1626ba7e;
       } else {
           Proof memory proof = abi.decode(signatureOrProof, (Proof));
           return _validateProof(dataHash, proof);
       }
   }
   ```  
3. Update documentation to clearly explain both standard ERC-1271 and custom validation methods.
  
By implementing these recommendations, the contracts can maintain their current sophisticated functionality while also providing support for ERC-1271, thereby increasing compatibility with smart contract wallets and improving overall interoperability within the Ethereum ecosystem.
