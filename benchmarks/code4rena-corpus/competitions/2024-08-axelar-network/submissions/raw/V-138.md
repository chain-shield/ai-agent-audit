# Vulnerability details

## Impact
In `contract.rs`, the `instantiate` and `execute` functions handle and update trusted addresses. However, since there is no limit on the array length and no mechanism to prevent exceeding the gas limit, this could lead to issues with saving new addresses or executing message transmission functions.

## Proof of Concept
The `instantiate` function in `contract.rs` is used to iterate over and store trusted addresses. 
[axelar-amplifier/interchain-token-service/src/contract.rs:instantiate_L76](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-amplifier/interchain-token-service/src/contract.rs#L76)
```rust

#[cfg_attr(not(feature = "library"), entry_point)]
pub fn instantiate(
    deps: DepsMut,
    _: Env,
    _: MessageInfo,
    msg: InstantiateMsg,
) -> Result<Response, axelar_wasm_std::error::ContractError> {
    cw2::set_contract_version(deps.storage, CONTRACT_NAME, CONTRACT_VERSION)?;

    let gateway = deps
        .api
        .addr_validate(&msg.gateway_address)
        .change_context(Error::InvalidAddress)
        .attach_printable(msg.gateway_address.clone())?;

    state::save_config(
        deps.storage,
        &Config {
            chain_name: msg.chain_name,
            gateway,
        },
    )?;

    if let Some(trusted_addresses) = msg.trusted_addresses {
@=>     for (chain, address) in trusted_addresses {
            state::save_trusted_address(deps.storage, &chain, &address)?;
        }
    }

    Ok(Response::new())
}

```

The `execute` function calls `update_trusted_address` from `execute.rs` to update these trusted addresses. 
[axelar-amplifier/interchain-token-service/src/contract.rs:execute_L100](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-amplifier/interchain-token-service/src/contract.rs#L100)
```rust

#[cfg_attr(not(feature = "library"), entry_point)]
pub fn execute(
    deps: DepsMut,
    _: Env,
    info: MessageInfo,
    msg: ExecuteMsg,
) -> Result<Response, axelar_wasm_std::error::ContractError> {
    let msg = msg.ensure_permissions(deps.storage, &info.sender, match_gateway)?;

    match msg {
        ExecuteMsg::Execute {
            cc_id,
            source_address,
            payload,
        } => execute::execute_message(deps, cc_id, source_address, payload),
@=>     ExecuteMsg::UpdateTrustedAddress { chain, address } => {
            execute::update_trusted_address(deps, chain, address)
        }
    }?
    .then(Ok)
}

```

However, the length of the trusted address array is not limited, and the system loops through this array multiple times without any mechanism to prevent exceeding the block gas limit. This could lead to issues where trusted addresses cannot be saved, and the contract is unable to execute message transmission functions.

Therefore, if the `trusted_addresses` array becomes too large, the block gas limit will be reached, preventing the `trusted_addresses` from being saved and the contract from executing message transmission functions.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a minimum check and modify to only query for a limited number of specific `trusted_addresses` instead of all `trusted_addresses`.
