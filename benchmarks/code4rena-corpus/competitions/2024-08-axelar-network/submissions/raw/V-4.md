# Vulnerability details

## Impact
The message_id is generated using a counter combined with a placeholder transaction hash, which may not be unique. This could lead to message ID collisions, especially if the counter is reset or reused

## Proof of Concept
If the counter is reset, an attacker could send a message with a matching ID to overwrite or hijack another message's processing.

## Tools Used
manual review

## Recommended Mitigation Steps
Use a more robust method to generate unique message IDs, such as combining the actual transaction hash with a timestamp or nonce.
