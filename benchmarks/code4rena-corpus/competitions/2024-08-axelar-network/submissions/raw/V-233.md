# Vulnerability details

## Impact
In `GatewayCaller.callContract` and `GatewayCaller.callContractWithToken`, `tx.origin` is used to receive the refund gas fee. There are some case in L2 that the user might not be able to receive the refund gas fee.

Quting for [tx.origin](https://docs.optimism.io/chain/differences):
>If the transaction is an L1 ⇒ L2 transaction triggered by a smart contract on L1, then tx.origin is set to the aliased address of the address that triggered the L1 ⇒ L2 transaction. Otherwise, this opcode behaves normally.

So please consider in a case that:
1. a `MESSAGE_TYPE_INTERCHAIN_TRANSFER` tx is bridge from ETH to OPTIMISM by optimism's bridge
2. after OPTIMISM receives the tx, it will calls [InterchainTokenService.interchainTransfer](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L454-L478)
3. in [InterchainTokenService._transmitInterchainTransfer](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L1148-L1184), [InterchainTokenService._callContract](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/InterchainTokenService.sol#L815-L838) is called.
4. and in [Caller.sol#L51](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/interchain-token-service/contracts/utils/GatewayCaller.sol#L51), the refund address is set to `aliased address`
5. in such case, the `aliased address` will not received the refund gas fee.
