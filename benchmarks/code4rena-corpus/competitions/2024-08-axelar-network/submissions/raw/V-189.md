# Vulnerability details

## Impact 
The `save_outgoing_msg` function in `axelarnet-gateway` package's `state.rs` mistakenly compares a message field within `MessageWithStatus` instead of the function's parameter, leading to ineffective checks and failure to detect mismatched `CrossChainId` messages.

## Proof of Concept
In the `axelarnet-gateway` package's `state.rs` contract, the `save_outgoing_msg` function is responsible for saving outgoing messages. The function first checks if a message with the given `CrossChainId` already exists in storage. If a different message is found according to the `CrossChainId`,  it raises an error of `MessageMismatch`; if the message is identical, it skips saving. However, the issue arises from the comparison condition `if msg != existing_msg`, where `msg` could refer to the `MessageWithStatus` struct's field, not the `save_outgoing_msg` function's parameter `msg`. As a result, since the `msg` field within `MessageWithStatus` will always match `existing_msg`, this leads to an ineffective check, failing to detect messages that do not match the `CrossChainId`.
[axelar-amplifier/contracts/axelarnet-gateway/src/state.rs:save_outgoing_msg_L110](https://github.com/code-423n4/2024-08-axelar-network/blob/4572617124bed39add9025317d2c326acfef29f1/axelar-amplifier/contracts/axelarnet-gateway/src/state.rs#L110)
```rust
pub(crate) fn save_outgoing_msg(
    storage: &mut dyn Storage,
    cc_id: CrossChainId,
@audit=> msg: Message,
) -> Result<(), Error> {
    let existing = OUTGOING_MESSAGES
        .may_load(storage, cc_id.clone())
        .map_err(Error::from)?;

    match existing {
        Some(MessageWithStatus {
@audit=>    msg: existing_msg, ..
@audit=>}) if msg != existing_msg => Err(Error::MessageMismatch(msg.cc_id.clone())),
        Some(_) => Ok(()), // new message is identical, no need to store it
        None => OUTGOING_MESSAGES
            .save(
                storage,
                cc_id,
                &MessageWithStatus {
                    msg,
                    status: MessageStatus::Approved,
                },
            )
            .map_err(Error::from)?
            .then(Ok),
    }
}
```

## Recommended Mitigation Steps
It's recommended to rename the `save_outgoing_msg` function's parameter to avoid conflict with the `MessageWithStatus` struct's `msg` field, and adjust the comparison accordingly. For instance, change the parameter name to `outgoing_msg: Message` and update the condition to `if outgoing_msg != existing_msg`.
