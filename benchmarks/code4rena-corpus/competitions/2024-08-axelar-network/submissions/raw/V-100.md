# Vulnerability details

## Impact

`route_incoming_messages` will be redundant as there is no storage being saved.

## Proof of Concept

In axelarnet-gateway, there is a function `call_contract` and a function `route_incoming_messages`. In the [docs](https://bright-ambert-2bd.notion.site/ITS-Token-Hub-External-dd30ee912d1e48e683d9488acf75e350#8f70ac2860de437aa729ec09a1d289f9), the ITS Hub calls `call_contract` on the axelarnet gateway.

This function creates a msg object, saves the incoming message into the INCOMING_MESSAGES storage, and calls route().

```
pub(crate) fn call_contract(
    ...
>   let msg = Message {
        cc_id: cc_id.clone(),
        source_address: Address::try_from(sender.clone().into_string())
            .expect("failed to convert sender address"),
        destination_chain,
        destination_address,
        payload_hash,
    };

>   state::save_incoming_msg(store, cc_id, &msg).change_context(Error::InvalidStoreAccess)?;

>   let (wasm_msg, events) = route(router, vec![msg.clone()])?;
```

There is a ? postfix operator behind `save_incoming_msg` and `route`. This is intended to propogate the error to the calling function.

If route() fails, then the state transition from `save_incoming_msg` will be reverted.

```
pub(crate) fn save_incoming_msg(
    storage: &mut dyn Storage,
    key: CrossChainId,
    msg: &Message,
) -> Result<(), Error> {
    match INCOMING_MESSAGES.may_load(storage, key.clone())? {
        Some(_) => Err(Error::MessageAlreadyExists(key)),
        None => INCOMING_MESSAGES
            .save(storage, key, msg)
            .map_err(Error::from),
    }
}
```

This is the `route()` function, which calls `router.route()`. If `router.route()` fails, it returns Err with a specified error.

```
fn route(
    router: &Router,
    msgs: Vec<Message>,
) -> Result<(WasmMsg, impl IntoIterator<Item = Event>), Error> {
    Ok((
>       router.route(msgs.clone()).ok_or(Error::RoutingFailed)?,
        msgs.into_iter()
            .map(|msg| AxelarnetGatewayEvent::Routing { msg }.into()),
    ))
}
```

There is another function which is `route_incoming_messages`. This function loads the message from storage through `may_load_incoming_msgs`, and checks if the `stored_msg` is the same as the message being routed. If there is no message, revert. The function then calls route().

```
pub(crate) fn route_incoming_messages(
    store: &mut dyn Storage,
    router: &Router,
    msgs: Vec<Message>,
) -> Result<Response, Error> {
    for msg in msgs.iter() {
>       let stored_msg = state::may_load_incoming_msg(store, &msg.cc_id)
            .change_context(Error::InvalidStoreAccess)?;

        match stored_msg {
>           Some(message) if msg != &message => {
                Err(report!(Error::MessageMismatch(msg.cc_id.clone())))
            }
            Some(_) => Ok(()),
            None => Err(report!(Error::MessageNotFound(msg.cc_id.clone()))),
        }?
    }

    let (wasm_msg, events) = route(router, msgs)?;

    Ok(Response::new().add_message(wasm_msg).add_events(events))
}
```

`route_incoming_messages` is used presumably if `call_contract` fails, because there is no storage change in the function. That means that should `route()` fail the first time, this function can retry the routing process.

The issue is that `route_incoming_messages` will be redundant because there will not be a point where `route()` fails and the `INCOMING_MESSAGES` state is changed due to atomicity. So, if `call_contract` fails, then `route_incoming_messages` does not have any messages to route since the storage did not save anything as the entire transaction call will be reverted.

## Recommended Mitigation Steps

Use [Submessages](https://docs.cosmwasm.com/docs/smart-contracts/contract-semantics/#submessages) instead and use `ReplyOn::Always` so that the messages error don't abort the whole transaction.

Another way is to have a privileged address recreate the message by hand and route it in case of any routing errors, so `route_incoming_messages` have to call `state::save_incoming_msg` as well.
