# Vulnerability details

### Description
The `_setup` function is invoked during upgrades, where it processes a new list of signers for rotation:
```javascript
    function _setup(bytes calldata data) internal override {
        (address operator_, WeightedSigners[] memory signers) = abi.decode(data, (address, WeightedSigners[]));

        // operator is an optional parameter. The gateway owner can set it later via `transferOperatorship` if needed.
        // This also simplifies setup for upgrades so if the current operator doesn't need to be changed, then it can be skipped, instead of having to specify the current operator again.
        if (operator_ != address(0)) {
            _transferOperatorship(operator_);
        }

        for (uint256 i = 0; i < signers.length; i++) {
=>            _rotateSigners(signers[i], false);
        }
    }
```

For each signer in the signers list, `_rotateSigners` is called, which in turn triggers `_validateSigners`. This function checks the signers' weights against a set threshold and will revert if the threshold is not met:
```javascript
function _validateSigners(WeightedSigners memory weightedSigners) internal pure {
    WeightedSigner[] memory signers = weightedSigners.signers;
    uint256 length = signers.length;
    uint256 totalWeight;
    if (length == 0) revert InvalidSigners();
    // since signers need to be in strictly increasing order,
    // this prevents address(0) from being a valid signer
    address prevSigner = address(0);
    for (uint256 i = 0; i < length; ++i) {
        WeightedSigner memory weightedSigner = signers[i];
        address currSigner = weightedSigner.signer;
        if (prevSigner >= currSigner) {
            revert InvalidSigners();
        }
        prevSigner = currSigner;
        uint256 weight = weightedSigner.weight;
        if (weight == 0) revert InvalidWeights();
        totalWeight = totalWeight + weight;
    }
    uint128 threshold = weightedSigners.threshold;
=>    if (threshold == 0 || totalWeight < threshold) revert InvalidThreshold();
}
```

The problem is that when using the `_setup` function, only one signer is processed each time `_rotateSigners` is invoked. Normally, `_rotateSigners` is called with a batch of `signers`, allowing all the weights to be correctly counted and checked against the threshold.

According to the sponsor, the practical numbers for the threshold and signers are as follows:

[Source](https://bright-ambert-2bd.notion.site/C4E-Audit-Axelar-Amplifier-FAQs-Aug-2024-External-5ded3250fa504e3e882e9551179b7548):
```
- How many signers are there on average in a signer set?

This depends on the chain. Initial Amplifier connections will start with 25 signers and a threshold of 17. More signers may be added in the future.
```

This means that by default, the threshold is set to 17, but with only one signer being processed and checked against this threshold, the setup will consistently fail because a single signer is used instead of a batch of signers.

### Recommendation
Handle the logic so that `_setup` can be correctly used
