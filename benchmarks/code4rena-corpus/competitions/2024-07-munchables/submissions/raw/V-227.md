# Vulnerability details

## Impact

A DoS of the contract will happen for a user when the _toiler.lastToilDate > timestamp. This scenario will happen when the `PRICE_PER_PLOT` is changed so that the `_getNumPlots()` returns less plots than the `_toiler.plotId` and the `toilerState[tokenId].dirty` should be set to true. The functionalities for the user will be DoSed until the `_getNumPlots` returns again a size bigger than the `_toiler.plotId`. They will be DoSed because the `forceFarmPlots` modifier which invokes `_farmPlots()` inside is set at every function a user can call

## Proof of Concept
Consider the following scenario:

The account manager calls `updatePlotMetadata()` for a landlord and it hits the case where it sets his `lastUpdated` to `block.timestamp` here:

 ```solidity
 function updatePlotMetadata(address landlord) external override onlyConfiguredContract(StorageKey.AccountManager) {
        if (plotMetadata[landlord].lastUpdated == 0) {
            plotMetadata[landlord] = PlotMetadata({lastUpdated: block.timestamp, currentTaxRate: DEFAULT_TAX_RATE});
        } else {
>>          plotMetadata[landlord].lastUpdated = block.timestamp;
        }

        emit UpdatePlotsMeta(landlord);
    }
```

After that a user just calls `stakeMunchable()` and passes the same `landlord` address

The `totalPlotsAvail` are 6 for example and the user stakes at the 6th plot.

The `toilerState.lastToilDate` is set to `block.timestamp` here (now the lastToilDate > plotMetadata[landlord].lastUpdated):

```solidity
  toilerState[tokenId] = ToilerState({
>>          lastToilDate: block.timestamp,
            plotId: plotId,
            landlord: landlord,
            latestTaxRate: plotMetadata[landlord].currentTaxRate,
            dirty: false
        });
```
 
After some time the `PRICE_PER_PLOT` gets updated and this function starts returning 4 plots for this land instead of 6

```solidity
 function _getNumPlots(address _account) internal view returns (uint256) {
        return lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT;
    }
```

Now when the `_farmPlots` is invoked this `toilerState[tokenId].dirty` will be set to true here
but also the timestamp will be set to the `plotMetadata[landlord].lastUpdated` which is a time that is in the past and it is before the `_toiler.lastToilDate`

```solidity
 function _farmPlots(address _sender) internal {
  ...

  if (_getNumPlots(landlord) < _toiler.plotId) {
>>              timestamp = plotMetadata[landlord].lastUpdated;
>>              toilerState[tokenId].dirty = true;
  }

  ...

 }

```

Then we come here where the overflow will happen in the `schnibblesTotal` calculation 

```solidity
 schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
```
The `toiler.lastToilDate` is a time that is after the `timestamp` so the transaction will always revert here


## Tools Used
Manual review

## Recommended Mitigation Steps
You should check if the  `_toiler.lastToilDate > timestamp` and in this scenario the formula should be reversed like this
```diff
- schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
+ schnibblesTotal = (_toiler.lastToilDate - timestamp) * BASE_SCHNIBBLE_RATE;
```
