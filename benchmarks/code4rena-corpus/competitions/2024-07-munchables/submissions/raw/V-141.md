# Vulnerability details


## Impact
The vulnerability in the `_farmPlots` function's schnibble calculation logic allows for incorrect application of the bonus, potentially leading to significant distortions in schnibble rewards.

```javascript
    finalBonus = int16(
                    REALM_BONUSES[
                        (uint256(immutableAttributes.realm) * 5) +
                            uint256(landlordMetadata.snuggeryRealm)
                    ]
                ) +
                int16(
                    int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])
                );
    schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
    schnibblesTotal = uint256(
                (int256(schnibblesTotal) +
                    (int256(schnibblesTotal) * finalBonus)) / 100
            );
```
The current calculation erroneously adds the bonus to the schnibble total rather than applying it as a percentage calculation, The existing calculation method with a negative finalBonus can cause overflow errors or incorrect values due to the negative results of the intermediate calculations and the conversion to uint256.

## Proof of Concept

For example, if schnibblesTotal is 1000 and finalBonus is 50, the result would be:
(1000 + (1000 * 50)) / 100 = 510 instead of the likely intended 1000 * 1.5 = 1500
If the final bonus is negative the goal is to reduce rewards however tthe current implementation raises a huge error:
(1000+1000*(-50))/100= -490, however this result is casted in `uint256`, This results may an overflow calculated error `115792089237316195423570985008687907853269984665640564039457584007913129639446` or any unexpected behavior which will lead to huge loss of rewards.

## Tools Used
Manual Review.

## Recommended Mitigation Steps
fix the math formula to:
```javascript
schnibblesTotal = uint256(
    (int256(schnibblesTotal) * (100 + finalBonus)) / 100
);
```
this way even if finalBonus is negative, for instance -50 the result will be 1000*(100-50)/100 = 500 which makes sense
