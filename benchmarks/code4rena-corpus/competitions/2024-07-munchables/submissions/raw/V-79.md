# Vulnerability details

## Impact
Updating `landlordMetadata.lastPetMunchable` and not `renterMetadata.lastPetMunchable` will enable the user (who just farmed his plots) to pet NFTs, but will stop a landlord (who's plot was farmed) to pet.

## Proof of Concept
[_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L299) misses to update `lastPetMunchable` for the main accounts (who's farming) and only updates it for his landlord: 

```solidity
   //@audit we don't update `renterMetadata.lastPetMunchable`
   landlordMetadata.lastPetMunchable = uint32(timestamp);

   accountManager.updatePlayer(landlord, landlordMetadata);
```

This would prevent landlord from petting NFTs after such an update, but it would fully allow users to [pet](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/SnuggeryManager.sol#L232-L233) them:

```solidity
   (address _petterMainAccount, MunchablesCommonLib.Player memory _petterPlayer) =
            _getMainAccountRequireRegistered(msg.sender); 
   
   ...

   if (_petterPlayer.lastPetMunchable + 10 minutes > block.timestamp) {
       revert PetTooSoonError();
   }
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Update `lastPetMunchable` for the user farming his plots:
```diff
+   renterMetadata.lastPetMunchable = uint32(block.timesatmp);
    accountManager.updatePlayer(mainAccount, renterMetadata);
```
