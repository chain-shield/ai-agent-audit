# Vulnerability details

## Impact

The calculation of `schnibblesLandlord` in `_farmPlots` function can result in zero due to integer division truncation when latestTaxRate is set to a small non 0 value by Landlord. Also schnibblesTotal variable has no decimal setting.

## Proof of Concept

This issue is, if a Landlord sets taxRate a relatively small value and when schnibblesTotal is small enough that the multiplication result of `schnibblesTotal` and `latestTaxRate` , when divided by 1e18, is truncated to 0. 
This could lead to landlords receiving no schnibbles despite having a non 0 tax rate. schnibblesTotal variable has no precision detail so having a small value of schnibblesTotal in the beginning is high likely.

```solidity
schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
schnibblesTotal = uint256((int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100);
schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18; //@audit in some values of latestTaxRate can make schnibblesLandlord 0
```

## Tools Used

Manual review

## Recommended Mitigation Steps

1- Verify that BASE_SCHNIBBLE_RATE and the time difference between timestamp and _toiler.lastToilDate are large enough to avoid small schnibblesTotal values.

2- Put additional checks to avoid cases where latestTaxRate is small, ensuring that schnibblesLandlord does not truncate to 0.
