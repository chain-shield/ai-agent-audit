# Vulnerability details

## Impact
If the USD value of the locked tokens decreases or landlord withdraws funds, it will lower the lockWeightValueUSD, which in turn reduces the numOfPlots. This can cause legitimate users who have staked their Munchables on a landlord's plot to fail the condition `if (_getNumPlots(landlord) < _toiler.plotId)`, resulting in their toilerState being set to true and preventing them from farming their staked Munchables. 

## Proof of Concept
This is the function used to calculate numOfPlots
```js
function _getNumPlots(address _account) internal view returns (uint256) {
        return lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT;
    }
```

And each time the `_farmPlots` function is call this condition is check

```js
if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```
We can imagine that any minor change in LockedWeightedValue can change the numOfPlots, especially due to rounding during division. For example, if a user staked their pet on plot 40 of a landlord and, next time they want to farm, _getNumPlots returns 39, their pet will be set to dirty, preventing the user from farming it further.


## Tools Used
Manual review

## Recommended Mitigation Steps
Implement a validation mechanism that ensures users' staked positions remain valid even if numOfPlots changes slightly.
