# Vulnerability details

## Impact
Price updates can be triggered for different contracts with less (2) than the required threshold (3).

Change in the price will also change the weight on **each** landlord, as [_getNumPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L344-L346) relies on LockManager's weight, which in tern is [quantity * price](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L481-L491).

## Proof of Concept
When a new price for contracts is requested with [proposeUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L142) it needs to pass a threshold (currently 3) of approvals or disapproval in order to be accepted or deleted.

However currently the only validation, inside [approveUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L177) or [disapproveUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L212), that is done is on the price, missing a check if the proposed contracts are the same as the ones that are approved:

```solidity
    function approveUSDPrice(uint256 _price) external
        onlyOneOfRoles([Role.PriceFeed_1, Role.PriceFeed_2, Role.PriceFeed_3, Role.PriceFeed_4, Role.PriceFeed_5])
    {
        ...
        if (usdUpdateProposal.proposedPrice != _price) {
            revert ProposalPriceNotMatchedError();
        }
```

This would allow a corrupt oracle to front-run an approval with [disapproveUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L212), followed by [proposeUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L142) and make the approval for another set of contracts.

Example:
1. Price X is proposed for contracts 1,2,3.
2. 1 oracle votes for approval and 2 for disapproval.
3. Another oracle votes for approval.
4. However a front-run:
- calls [disapproveUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L212) to remove the current vote
- calls [proposeUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L142) on the same price - X, bit for contracts 4,5,6
5. The original approval for contracts 1,2,3 is now an approval for contract 4,5,6

The attacker has gained 1 extra vote for, making him 2/5, requiring one more in order to capture the proposal.


---


The above would enable anyone controlling 2/5 price feeds to control the prices.
Changing the threshold to 2 will make any singe price feed have control over the prices.

**This is breaking the core invariant of requiring 3 price feeds (majority) to agree on the same rice for the same contracts.**

## Tools Used
Manual review

## Recommended Mitigation Steps
Use an ID for each proposal that will encode the `price` and `_contracts`. This will make each proposal different from the last.
