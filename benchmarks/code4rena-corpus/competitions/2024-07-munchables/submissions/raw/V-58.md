# Vulnerability details

## Impact
The LandManager contract allows users to stake/unstake their tokens and receive rewards based on various factors. Each time a user stakes or unstakes a token, they will first farm their rewards before proceeding with the action, due to the forceFarmPlots modifier. However, there could be a situation where a user's token toiler becomes "dirty," which will update the timestamp of the rewards calculation:

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L259-L260
```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```
Making it the last time when plotMetadata for landlord was updated. But the problem lies in the code that goes next:

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L280-L282
```solidity
          schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
```
Here we calculate `schnibblesTotal` with the implicit assumption that `timestamp` is greater than `_toiler.lastToilDate`. However, this might not be true because we updated it from `block.timestamp` to `plotMetadata[landlord].lastUpdated`. If timestamp is lower than `_toiler.lastToilDate`, the transaction will revert, making it impossible to stake or unstake any token until you have this "dirty" token or until the AccountManager updates the `plotMetadata[landlord].lastUpdated` value.

## Proof of Concept

Let's consider this example (just to make it easier to understand let's suggest that current timestamp is 10):
1. AccountManager updates plotMetadata[landlord].lastUpdated making it 10.
2. Alice stakes her token. timestamp is 11 => _toiler.lastToilDate = 11
3. _getNumPlots changes making Alice's toiler dirty (if _farmPlots would be called). timestamp is 12
4. Alice tries to unstake her tokens, but because her token toiler is now "dirty" timestamp is updated to `plotMetadata[landlord].lastUpdated` making it 10 instead of 13. According to this formula: `schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;` we would get schnibblesTotal = (10 - 11) * BASE_SCHNIBBLE_RATE and this expression will revert.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Either continue loop after setting 'dirty' to true or add explicit check that timestamp is bigger than  _toiler.lastToilDate.
