# Vulnerability details

### Impact
In the `updateTaxRate` function within the `LandManager.sol`, attackers could exploit the contract through reentrancy attacks. A successful exploitation could lead to unauthorized manipulation of the contract's state, including changing tax rates, potentially draining funds, or disrupting the intended functionality of the contract. This poses a significant risk to the integrity and security of the contract, affecting both users and the overall ecosystem relying on it.

### Proof of Concept
The [`updateTaxRate`](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L92-L101) function allows an external caller to update the tax rate for a specific landlord. However, it does not implement any reentrancy protection check. An attacker could create a malicious contract that, upon receiving a callback from `updateTaxRate`, calls `updateTaxRate` again before the initial state change is finalized. This recursive call could be used to repeatedly execute the function, potentially causing unintended side effects such as altering tax rates or exploiting other functionalities within the contract.

Manual review

### Recommended Mitigation Steps
Use the `nonReentrant` modifier from OpenZeppelin's ReentrancyGuard library to protect the `updateTaxRate` function and any other function that modifies the contract's state and interacts with external contracts. This modifier will ensure that the function cannot be re-entered while it is still executing.

    ```solidity

            // Function implementation...
        }

    }
    ```
