# Vulnerability details

## Impact
The `transferToUnoccupiedPlot` function does not update the `plotId` in `toilerState[tokenId]` when setting the new `plotId`. As a result, it continues using the old `plotId`. This leads to inaccuracies in the calculations performed by functions like `_farmPlots`, which rely on the `plotId` for `timestamp` and `toilerState[tokenId].dirty` calculations. Consequently, values such as `schnibblesTotal`, `schnibblesLandlord`, `renterMetadata.unfedSchnibbles`, `landlordMetadata.unfedSchnibbles`, `toilerState[tokenId].lastToilDate`, and `landlordMetadata.lastPetMunchable` are computed incorrectly.

## Proof of Concept
In the `transferToUnoccupiedPlot` function, the `plotId` in `toilerState[tokenId]` is not updated when a new `plotId` is set. This leads to the continued use of the old `plotId`. The relevant code can be found here: 
[src/managers/LandManager.sol:transferToUnoccupiedPlot_L119-L226](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L199C1-L226C6)
```solidity
    function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
@audit=> uint256 oldPlotId = _toiler.plotId;
        uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
        if (plotOccupied[_toiler.landlord][plotId].occupied)
            revert OccupiedPlotError(_toiler.landlord, plotId);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```

This issue causes the `_farmPlots` function to incorrectly check `_getNumPlots(landlord) < _toiler.plotId` and miscalculate the `timestamp` and `toilerState[tokenId].dirty` using the old `plotId`. Incorrect `timestamp` calculations directly affect the values of `toilerState[tokenId].lastToilDate`, `landlordMetadata.lastPetMunchable`, and `schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE`. These incorrect `schnibblesTotal` calculations further lead to inaccuracies in `schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18`, `renterMetadata.unfedSchnibbles += (schnibblesTotal - schnibblesLandlord)`, and `landlordMetadata.unfedSchnibbles += schnibblesLandlord`. Ultimately, these inaccuracies prevent the `_farmPlots` function from performing its intended functionality correctly.
