# Vulnerability details

## Impact
The tx to call `_farmPlots()` will be reverted due to the incorrect usage of `timestamp`, leading to DoS of contract and users lose their NFT.

## Proof of Concept

The usages of variable `timestamp`:

l. L248: Initiated to `block.timestamp`
2. L259: Set to `plotMetadata[landlord].lastUpdated` if `_getNumPlots(landlord) < _toiler.plotId`

However, this reassignment can lead to an issue where `timestamp` becomes smaller than `_toiler.lastToilDate`, causing the calculation at line 281 to revert.

```solidity
232:     function _farmPlots(address _sender) internal {
...
247:         for (uint8 i = 0; i < staked.length; i++) {
248:             timestamp = block.timestamp;
...
258:             if (_getNumPlots(landlord) < _toiler.plotId) {
259:                 timestamp = plotMetadata[landlord].lastUpdated;
260:                 toilerState[tokenId].dirty = true;
261:             }
...
280:             schnibblesTotal =
281:                 (timestamp - _toiler.lastToilDate) * // <= reverts
282:                 BASE_SCHNIBBLE_RATE;
```

Consider the following scenario:

1.  The `plotMetadata[landlord].lastUpdated` is set to 2024-07-01.
2.  An NFT, having been farmed earlier, has its `toilerState[tokenId].lastToilDate` set to 2024-08-01.
3.  The NFT's `plotId` becomes unfit due a reduction in locked weight.
4.  The condition `_getNumPlots(landlord) < _toiler.plotId` is true, leading to `timestamp` being set to `plotMetadata[landlord].lastUpdated` (2024-07-01).
5.  The subtraction `timestamp - _toiler.lastToilDate` becomes negative (2024-07-01 - 2024-08-01), causing the transaction to revert.

## Tools Used
manual

## Recommended Mitigation Steps

Ensure that `timestamp` is always greater than or equal to `_toiler.lastToilDate`. A check should be added to verify this condition before performing the subtraction.
