# Vulnerability details

## Description
The calculation of the renter's share of schnibbles is susceptible to integer overflow if the `unfedSchnibbles` accumulates to a very large value over time.


## Code snippet

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L295

```solidity
renterMetadata.unfedSchnibbles += (schnibblesTotal - schnibblesLandlord);
```

The `+=` operation can lead to an integer overflow if `unfedSchnibbles` becomes very large. In Solidity 0.8.0 and later, this would cause a runtime error and revert the transaction.

## Impact
Transactions could start failing unexpectedly when `unfedSchnibbles` reaches a large value, preventing renters from claiming their rewards.


## Suggested Fix

1. Implement a cap on `unfedSchnibbles`:

```solidity
uint256 constant MAX_UNFED_SCHNIBBLES = /* some large but safe value */;
uint256 newUnfedSchnibbles = renterMetadata.unfedSchnibbles + (schnibblesTotal - schnibblesLandlord);
renterMetadata.unfedSchnibbles = newUnfedSchnibbles > MAX_UNFED_SCHNIBBLES ? MAX_UNFED_SCHNIBBLES : newUnfedSchnibbles;
```

2. Regularly reset or claim `unfedSchnibbles` to prevent accumulation to very large values.
