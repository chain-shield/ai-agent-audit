# Vulnerability details

## Impact
`LandManager::unstakeMunchable` unstakes a munchable from a plot and resets the `ToilerState` plotId value to zero to indicate that the munchable is no longer staked to a plot. This creates an issue in a scenario where the munchable was originally staked to a plot with Id of zero. So, unstaking it will still indicate that the munchable still belongs in the plotId/the plotId is still in use.

This adds ambiguity to the system and compromises management of state and interactions.

## Recommended Mitigation Steps
 Consider using `type(uint256).max` as a sentinel value for plotId during unstaking.

```diff
function unstakeMunchable(
    uint256 tokenId
) external override forceFarmPlots(msg.sender) notPaused {
    (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
    ToilerState memory _toiler = toilerState[tokenId];
    if (_toiler.landlord == address(0)) revert NotStakedError();
    if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();

    
    plotOccupied[_toiler.landlord][_toiler.plotId] = Plot({
        occupied: false,
        tokenId: 0
    });

    // Reset the toiler state to a sentinel value
    toilerState[tokenId] = ToilerState({
        lastToilDate: 0,
-       plotId: 0,
       
+       plotId: type(uint256).max,  // Use a sentinel value
        landlord: address(0),
        latestTaxRate: 0,
        dirty: false
    });

    munchableOwner[tokenId] = address(0);
    _removeTokenIdFromStakedList(mainAccount, tokenId);

    munchNFT.transferFrom(address(this), mainAccount, tokenId);
    emit FarmPlotLeave(_toiler.landlord, tokenId, _toiler.plotId);
}
