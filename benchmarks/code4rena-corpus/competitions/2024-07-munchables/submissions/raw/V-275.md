# Vulnerability details

## Impact
The `plotMetadata[landlord].lastUpdated` field is not updated in the `updateTaxRate` function, leading to inconsistencies in the use of the `lastUpdated` field. This can result in incorrect tax calculations, as the timestamp remains unchanged from its previous value.

## Proof of Concept

In the `LandManager` contract, users can call the updateTaxRate function to update the `currentTaxRate`. However, the `plotMetadata[landlord].lastUpdated` field is not updated when this function is called.

```solidity
    function updateTaxRate(uint256 newTaxRate) external override notPaused {
        (address landlord, ) = _getMainAccountRequireRegistered(msg.sender);
        if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE)
            revert InvalidTaxRateError();
 @=》   if (plotMetadata[landlord].lastUpdated == 0)
            revert PlotMetadataNotUpdatedError();
        uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
        plotMetadata[landlord].currentTaxRate = newTaxRate; // @note chaning currentTaxRate half-way would cause issues.
        emit TaxRateChanged(landlord, oldTaxRate, newTaxRate);
    }
```

This is inconsistent with the usage of `lastUpdated` field. Since every time the meta-info is updated, the `lastUpdated` field should be changed accordingly.

Since the `lastUpdated` field is used later in `_farmPlots` to calculate the tax, failure to update it in `updateTaxRate` can lead to incorrect calculations.

```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
@=>             timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
            ...
            schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *

```

## Recommended Mitigation Steps

To mitigate this issue, it is recommended to update the `lastUpdated` field in the function `updateTaxRate`.
