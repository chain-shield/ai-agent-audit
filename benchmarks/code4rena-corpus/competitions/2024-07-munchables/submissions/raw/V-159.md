# Vulnerability details

## Impact
Users that staked their MunchableNFTs at plotId 0 of a landload will forever be farming the plot even when the landload has 0 plots(no locked asset enough to buy plot).

In `_farmPlots` internal function there is a code that check to set `toilerState[tokenId].dirty = true` when landload's plots number is less than `toilerState[tokenId].plotId` which will pass even when the landload has 0 plot and `toilerState[tokenId].plotId = 0` because 0 is not less than 0.
```javascript
if (_getNumPlots(landlord) < _toiler.plotId) {
    timestamp = plotMetadata[landlord].lastUpdated;
    toilerState[tokenId].dirty = true;
}
```

Even though in publicly known issues it was mentioned that the above check has something to look at but that referred to getting timestamp for calculating schnibblesTotal not about users that staked at plotId 0.

## Proof of Concept
The following scenario shows how Bob can take advantage of staking at plotId 0 to farm even when landload has no plots.

1. Bob staked his MunchableNFT to plotId 0 of Alice(landload).
2. Bob call `farmPlots()` after a day to farm his plot for schnibbles.
3. Alice reduce his locked asset to an amount that can not buy a single plot. Now Alice have 0 plot.
4. Bob can continue to call `farmPlots()` successfully even though the landload has no plotId.  

## Tools Used
Manual review

## Recommended Mitigation Steps
Change the check condition to be less than or equals to since user can not stake at plotId that is equals to landload's plot number in `stakeMunchable` function.
```
if (_getNumPlots(landlord) <= _toiler.plotId) {
    timestamp = plotMetadata[landlord].lastUpdated;
    toilerState[tokenId].dirty = true;
}
```
