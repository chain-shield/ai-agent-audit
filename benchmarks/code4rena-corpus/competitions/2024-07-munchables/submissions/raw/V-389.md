# Vulnerability details

## Impact
In the munchNFT.sol code [here](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/tokens/MunchNFT.sol#L111), we can see that it is possible for a tokenId to be blacklisted. The issue is that if a tokenId is blacklisted while it is staked in the LandManager.sol contract, it continues earning schnibble rewards. Although the munchable is frozen, the attacker can claim schnibbles by calling farmPlots(). This should not be allowed since a deactivated munchNFT should not be able to interact and receive rewards from the system. 

Additionally, the munchable remains in the landlord's plots, decreasing the total number of actual plots available for other users.

## Proof of Concept

1. Attacker stakes munchable tokenId using stakeMunchable() function.

2. Team blacklists the munchable tokenId in munchNFT.sol contract.

3. Attacker calls farmPlots() to claim and receive the schnibbles from the system. 

Even if the tokenId is unblacklisted by the protocol to allow the attacker to unstake it, it is upto the attacker whether to unstake it or not. It is highly unlikely the attacker would want to unstake it though.

## Tools Used 
Manual Review

## Recommended Mitigation Steps
We don't want the munchable to be locked in the landlord's plots as well as to be earning any rewards. The best solution is to implement a function that allows the team to unstake blacklisted NFTs from the plots.
