# Vulnerability details

## Impact
updatePlayer() takes main account & player as input to update the players mapping in accountManager.sol
```solidity
   function updatePlayer(
        address _account,
        MunchablesCommonLib.Player calldata _player
    )
        external
        onlyConfiguredContract3(
            StorageKey.SnuggeryManager,
            StorageKey.PrimordialManager,
            // Signifies LandManager
            StorageKey.PrimordialsEnabled
        )
    {
        players[_account] = _player;
    }
```

But in _farmPlots(), for updating landlord's player data it pass landlord address instead of landlord's mainAccount
```solidity
   accountManager.updatePlayer(landlord, landlordMetadata);
``` 
As result there will be 2 players mapping created in accountManager.sol for same user
