# Vulnerability details

## Impact
The transferToUnoccupiedPlot function does not update toilerState[tokenId].plotId. As a result, a single munchable can occupy multiple plots simultaneously, leading to inconsistent game states and potential exploitation.
Malicious renters can fill all landlord's plots with only one munchable using this error.

## Proof of Concept
https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L199-L226

    it("test", async () => {
      await testContracts.landManagerProxy.contract.simulate.transferToUnoccupiedPlot([1, 119], {
        account: bob,
      });
      await testContracts.landManagerProxy.contract.simulate.transferToUnoccupiedPlot([1, 118], {
        account: bob,
      });
      await testContracts.munchNFT.contract.write.approve(
        [testContracts.landManagerProxy.contract.address, 2],
        { account: bob }
      );
      await assert.rejects(
        await testContracts.landManagerProxy.contract.simulate.stakeMunchable([alice, 2, 119], {
          account: bob,
        }),
        (err: Error) => assertContractFunctionRevertedError(err, "OccupiedPlotError")
      );
    });

This is the test code of `transferToUnoccupiedPlot()` function.
As you can see, this function does not change `toilerState[tokenId].plotId`.
If a rentor call `transferToUnoccupiedPlot(1, 119)` and `transferToUnoccupiedPlot(1, 118)`, `plotOccupied[_toiler.landlord][119].occupied` and `plotOccupied[_toiler.landlord][118].occupied` are both true.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Update the `toilerState[tokenId].plotId` to the new `plotId` within the `transferToUnoccupiedPlot` function.

`toilerState[tokenId].plotId = plotId;`

Adding this line ensures that the plotId is correctly updated, preventing a munchable from occupying multiple plots simultaneously.
