# Vulnerability details

## Impact
The `triggerPlotMetadata` function only does two things: 
1. update the timestamp
2. set the `currentTaxRate` as the `DEFAULT_TAX_RATE`

In some certain market conditions, i.e. when the market becomes competitive and the average tax rate set by the cohort of landlords is generally way higher than the `DEFAULT_TAX_RATE`, this function will become prone to back-running attack. The renters can use bots to back-run it with `stakeMunchable` function and seize these plots immediately, because that tax rate is a steal in the current market condition. Even though the landlords can use `updateTaxRate` function to update the number later, but the previous undesired `DEFAULT_TAX_RATE` number had already been written into `toilerState[tokenId].latestTaxRate`. This numbers will be the effective tax rate until the next time the renter calls the `farmPlots` function.

When they call the `farmPlots` function, the yield will be calculated using that undesired `DEFAULT_TAX_RATE` first, and then the `toilerState[tokenId].latestTaxRate` will get updated to the landlord's updated tax rate. The landlord suffers from the unfair tax rate for the whole time being, until the `farmPlots` function gets called by the renter. This leads to a loss of yield to the landlord.

## Proof of Concept
1. When `landlordBob` calls `triggerPlotMetadata()`, this [Line#110](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L110C29-L110C45) ensures `DEFAULT_TAX_RATE` is applied to him.
2. When `renterAlice`'s bot found Bob's trxn, she immediately back run it with `stakeMunchable` to seize the plot, and this [Line#166](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L166) makes the undesired `DEFAULT_TAX_RATE` get written into `toilerState[tokenId].latestTaxRate`.
3. When Alice calls `farmPlots` function, this [Line#288](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L288) leads to the undesired `DEFAULT_TAX_RATE` is used for the whole time being; only after the calculation is finished, this [Line#292-293](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L292-L293) updates the landlord's new tax rate to be effective.

## Tools Used
Manual review

## Recommended Mitigation Steps
Revise the `triggerPlotMetadata` function to make it take an additional param -- the intended tax rate, to be passed in by the caller, and use that instead of using the `DEFAULT_TAX_RATE`.
