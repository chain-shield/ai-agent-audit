# Vulnerability details

## Impact
Based on the Nat spec only users who already have locked funds should trigger the [triggerPlotMetadata](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L104) function as we can see here:
> // Only to be triggered by msg sender if they had locked before the land manager was deployed
## Proof of Concept
The function only check if main account is registered and if it was not updated before in `plotMetadata` mapping and then it creates the default plot metadata and connect it to the registered main account address.

The issue arise because it does not check if user who want to have plod have locked funds and it would allow for users who don't have enough funds locked to have plots which they can rent.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Implement the following check to make sure users have locked funds before their plot metadata is created:
```diff
    function triggerPlotMetadata() external override notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
+        uint256 availablePlots = _getNumPlots(mainAccount);
+        if(availablePlots >= 1) {
        if (plotMetadata[mainAccount].lastUpdated != 0)
            revert PlotMetadataTriggeredError();
        plotMetadata[mainAccount] = PlotMetadata({
            lastUpdated: block.timestamp,
            currentTaxRate: DEFAULT_TAX_RATE
        });
+        } revert NotEnoughtFundsLockedError();

        emit UpdatePlotsMeta(mainAccount);
    }
```
