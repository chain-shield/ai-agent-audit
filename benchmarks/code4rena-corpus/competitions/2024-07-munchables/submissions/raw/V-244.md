# Vulnerability details

## Impact
User schinbble rewards will not be properly calculated in an event where the landlord changes the plot's tax after having munchables staked, leading to inconsistencies.

## Proof of Concept
In the current `LandManager` implementation, schnibbles rewards are farmed during staking, unstaking, and changing staked positions to unclaimed plots:

```solidity
function stakeMunchable(
    address landlord,
    uint256 tokenId,
    uint256 plotId
@> ) external override forceFarmPlots(msg.sender) notPaused {
    __SNIP__
}
```

```solidity
function unstakeMunchable(
    uint256 tokenId
@> ) external override forceFarmPlots(msg.sender) notPaused {
    __SNIP__
}
```

```solidity
function transferToUnoccupiedPlot(
    uint256 tokenId,
    uint256 plotId
@> ) external override forceFarmPlots(msg.sender) notPaused {
    __SNIP__
}
```

Users can also call `LandManager::farmPlots(...)` at any time to acquire rewards from their staked munchables. Schnibbles reward rates depend on how much rewards are subtracted to be given to the landlord, where this amount is directly linked to the plot's `currentTaxRate`, which is updated after each farm to match the landlord's `latestTaxRate`. Landlords have an option to change their tax rates at any time:

```solidity
function updateTaxRate(uint256 newTaxRate) external override notPaused {
    (address landlord, ) = _getMainAccountRequireRegistered(msg.sender);
    if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE)
        revert InvalidTaxRateError();
    if (plotMetadata[landlord].lastUpdated == 0)
        revert PlotMetadataNotUpdatedError();
    uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
@>    plotMetadata[landlord].currentTaxRate = newTaxRate;
    emit TaxRateChanged(landlord, oldTaxRate, newTaxRate);
}
```

The issue arises from the fact that the plot's `latestTaxRate` is updated _AFTER_ the `schnibblesLandlord` has been calculated in the `_farmPlots()` function:

```solidity
schnibblesLandlord =
@>        (schnibblesTotal * _toiler.latestTaxRate) /
        1e18;

    toilerState[tokenId].lastToilDate = timestamp;
@>    toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
        .currentTaxRate;
```

If two users stake identical munchables and a landlord decides to update their plot's tax rate, the user who stays idle before unstaking will receive more rewards compared to the one who regularly farms his staked plot.

## Recommended Mitigation Steps

Update the `_toiler.latestTaxRate` in `_farmPlots()` prior to the `schnibblesLandlord` calculation.

