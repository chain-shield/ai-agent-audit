# Vulnerability details

## Impact
Since the `farmPlots` function will update the landlord's `lastPetMunchable`, the user can continuously call the `farmPlots` function to prevent the landlord from petting.

## Proof of Concept
background:
1. The [`farmPlots` function](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L228) is used to collect Schnibbles. During this period, the landlord's `lastPetMunchable` will be updated.
2. Landowners need to use the [`pet` function](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/SnuggeryManager.sol#L208-L233) to receive different Schnibbles. The `pet` function has a calling time limit and can only be called 10 minutes after `lastPetMunchable` has been updated.
```solidity
    function pet(address _pettedOwner, uint256 _tokenId) external notPaused {
    ···
        if (pettedAttributes.lastPettedTime + 5 minutes > block.timestamp)
            revert PettedTooSoonError();
        if (_petterPlayer.lastPetMunchable + 10 minutes > block.timestamp)
            revert PetTooSoonError();
```

So users can continuously call the `farmPlots` function to continuously update the landlord's `lastPetMunchable`. As a result, the landlord cannot call the pet function.

This gives attackers the possibility to prevent landowners from receiving Schnibbles. Caused financial losses. However, the attack cost is high and it needs to be called every 10 minutes, so I judged it to be MEd.

## Tools Used
manual

## Recommended Mitigation Steps
It is recommended to update mainAccount's lastPetMunchable in the `_farmPlots` function instead of updating landlord's lastPetMunchable.
