# Vulnerability details

## Impact
In `LandManager::updateTaxRate(uint256)` the lastUpdated variable is not updated upon tax rate updation. As a result the lastUpdated variable is incorrect and in `LandManager::_farmPots` it is used to set a `timestamp` variable used for further calculations:
                
```solidity                
timestamp = plotMetadata[landlord].lastUpdated;
```

Which later on is used in the same function for a calculation:

```solidity
schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
```

And to set other object fields:
1. `toilerState[tokenId].lastToilDate = timestamp;`
2. `landlordMetadata.lastPetMunchable = uint32(timestamp);`

Causing the saved data to be incorrect and the `schnibblesTotal` to be inaccurate.

## Proof of Concept
1. Deploy and initialize `LandManager` contract
2. Configure initial tax rates by calling relevant functions as usual
3. Call `updateTaxRate(uint256)`

## Tools Used
Solidity

## Recommended Mitigation Steps

Add the following line of code to the `LandManager::updateTaxRate(uint256)`:

```solidity
    function updateTaxRate(uint256 newTaxRate) external override notPaused {
        (address landlord, ) = _getMainAccountRequireRegistered(msg.sender);
        if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE)
            revert InvalidTaxRateError();
        if (plotMetadata[landlord].lastUpdated == 0)
            revert PlotMetadataNotUpdatedError();
        uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
        plotMetadata[landlord].currentTaxRate = newTaxRate;
+       plotMetadata[landlord].lastUpdated = block.timestamp;
        emit TaxRateChanged(landlord, oldTaxRate, newTaxRate);
    }
```
