# Vulnerability details

## Impact

After the available plots get reduced by withdrawing locks by the landlord, the toiler and its landlord can keep earning Schnibbles from the last plot 

## Proof of Concept

As `plotId` starts from `0`(the sponsor confirmed), the maximum value of `plotId` is `_getNumPlots() - 1`.

Let's assume this scenario:

A landlord has `6` available plots, and toilers stakes Munchables to all of them. After a while, the landlord withdraws his locked assets, so the available plots decreases to `4`.

But because of this check in the `_farmPlots()` function, `Plot 4` can successfully be escaped from being dirty and its toiler can keep earning Schnibbles.

```solidity
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
```

## Tools Used

Manual Review

## Recommended Mitigation Steps

I think the conditional check should be changed like the below:

```solidity
-   if (_getNumPlots(landlord) < _toiler.plotId) {
+   if (_getNumPlots(landlord) <= _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
```
