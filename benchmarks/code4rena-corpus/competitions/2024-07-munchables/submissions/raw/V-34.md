# Vulnerability details

## Impact
Users will not be able to receive rewards for plots that no longer exist, solving the issue with the edge case the protocol team stated.

## Proof of Concept
The only time when this issue would arise is when the landlord calls `LockManager::unlock`, using that information we simply make a few changes to the function. Before reducing the `lockedToken.quantity` we call `uint256 availablePlotsBeforeUnlock = landManager._getNumPlots(msg.sender)` (of course we make the function public) and save it in a variable. Then after the quantity is reduced we again call the same function `uint256 availablePlotsAfterUnlock = landManager._getNumPlots(msg.sender)`. Now all that is left is to call a newly created function in `LandManager` which can be called for example `farmDirtyPlots(address landlord, uint256 previousAmountOfPlots)`

```solidity
function farmDirtyPlots(address landlord, uint256 previousAmountOfPlots) external{
    plotsLost = previousAmountOfPlots - _getNumPlots(landlord);
    for(uint256 i = 0; i < plotsLost;i++){
        //checks if the lost plot had anyone staking on it
        if(plotOccupied[landlord][previousAmountOfPlots - plotsLost].occupied){
            _farmPlots(munchablesOwner[plotOccupied[landlord][previousAmountOfPlots - plotsLost].tokenId]);
        //gets the owner of the token staked at the plot that was removed
        }
    } 
}
```

After the full execution of the function all of the plots will be marked as dirty and will no longer receive rewards even if `LandManger::farmPlots` is called because of the check `if (_toiler.dirty) continue;`
