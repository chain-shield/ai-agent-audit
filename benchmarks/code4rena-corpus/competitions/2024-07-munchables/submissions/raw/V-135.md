# Vulnerability details

## Impact
In `LandManager::_removeTokenIdFromStakedList` whenever we find the tokenId to remove from the array inside the map we reassign the `munchablesStaked[mainAccount][i]` tokenId to remove to 
`munchablesStaked[mainAccount][stakedLength - 1]` the last tokenId, which does not make sense.
Later on if we decide to remove the tokenId at `munchablesStaked[mainAccount][stakedLength - 1]` we will remove only one of its occurrences in the array. Additionally, array.pop() removes the last element causing the actual tokenId, provided it's NOT the actual last one in the array, to be present and the incorrect tokenId to be removed.

```solidity
        for (uint256 i = 0; i < stakedLength; i++) {
            if (munchablesStaked[mainAccount][i] == tokenId) {
                munchablesStaked[mainAccount][i] = munchablesStaked[
                    mainAccount
                ][stakedLength - 1]; // audit-high
                found = true;
                munchablesStaked[mainAccount].pop();
                break;
            }
        }
```

High - incorrect tokenId deletion

## Proof of Concept
1. Deploy and initialize 'LandManager' contract
2. Configure initial tax rates by calling relevant functions as usual
3. Some munchables are staked and at least one of them will have multiple tokenIds for a single mainAccount 
4. Call `LandManager::_removeTokenIdFromStakedList` with any valid params

## Tools Used
Solidity

## Recommended Mitigation Steps
Instead of having an array inside a map, have a map the other way around, namely tokenIds to addresses:

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L27

```solidity
+     mapping(uint256 => address) munchablesTokenIdsToAddress;
-     mapping(address => uint256[]) munchablesStaked;
```

Additionally, make relevant changes to the logic inside the `LandManager::_removeTokenIdFromStakedList` so it adheres to the change above. Saving on gas and have constant time to look up tokenIds, also improving readability and not have to iterate (potential DOS) every single time through a seemingly growing array.
