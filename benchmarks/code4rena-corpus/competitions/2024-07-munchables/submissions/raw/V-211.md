# Vulnerability details

## Impact
Regardless the number of plots owned by a given landlord, those plots can be marked as occupied by the attacker so that they are unusable.

## Proof of Concept
The function `transferToUnoccupiedPlot(tokenId, plotId)` is used by rentor to move their staked token to different plot within the same landlord. The function is incorrectly implemented because it doesn't update the `toilerState[tokenId].plotId` to the new `plotId`. This condition can be used by attackers to mark the plots owned by the landlord as occupied so that other rentor can't stake munchable to those plots.

```javascript
function transferToUnoccupiedPlot(
    uint256 tokenId,
    uint256 plotId
) external override forceFarmPlots(msg.sender) notPaused {
    (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
    ToilerState memory _toiler = toilerState[tokenId];
    uint256 oldPlotId = _toiler.plotId;
    uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
    if (_toiler.landlord == address(0)) revert NotStakedError();
    if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
    if (plotOccupied[_toiler.landlord][plotId].occupied)
        revert OccupiedPlotError(_toiler.landlord, plotId);
    if (plotId >= totalPlotsAvail) revert PlotTooHighError();

    toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
        .currentTaxRate;
>>  plotOccupied[_toiler.landlord][oldPlotId] = Plot({
        occupied: false,
        tokenId: 0
    });
>>  plotOccupied[_toiler.landlord][plotId] = Plot({
        occupied: true,
        tokenId: tokenId
    });

    emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
    emit FarmPlotTaken(toilerState[tokenId], tokenId);
}
```

In the code above, the old plot is set to unoccupied and the new plot is set to occupied but the value of `plotId` in `toilerState[tokenId]` is still the old plot.

Let's assume a `landlord` have 5 available plots.

Now the attacker can do the following steps:

1. Attacker stake to the last plot (plotId 4). `landManager.stakeMunchable(landlord, tokenId, 4)`

2. Attacker now move the token to unoccupied plot multiple times.

    * `landManager.transferToUnoccupiedPlot(tokenId, 0)`
    * `landManager.transferToUnoccupiedPlot(tokenId, 1)`
    * `landManager.transferToUnoccupiedPlot(tokenId, 2)`
    * `landManager.transferToUnoccupiedPlot(tokenId, 3)`

    The status of plot with id 0 up to 3 now are occupied. The plot with id 4 is now left unoccupied.

3. The last step, the attacker transfer the token to the original plot so that all plots have occupied status. `landManager.transferToUnoccupiedPlot(tokenId, 4)`

## Tools Used
Manual Review

## Recommended Mitigation
Set `toilerState[tokenid].plotId` to the new `plotId`.

