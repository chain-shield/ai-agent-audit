# Vulnerability details

## Impact
The variable `toilerState[tokenId].latestTaxRate` does not track the latest tax rate, resulting in inaccurate `schnibblesLandlord` calculation.

## Proof of Concept

In `_farmPlots()`, the `schnibblesLandlord` is calculated utilizes `toilerState[tokenId].latestTaxRate`. However, the actual latest tax rate is stored in `plotMetadata[_toiler.landlord].currentTaxRate`, which is updated AFTER the latest tax rate is used to calculate the `schnibblesLandlord`:

```solidity
287:             schnibblesLandlord =
288:                 (schnibblesTotal * _toiler.latestTaxRate) / <= used before updating
289:                 1e18;
290: 
291:             toilerState[tokenId].lastToilDate = timestamp;
292:             toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord] // <= updated after the schnibblesLandlord calc
293:                 .currentTaxRate;
```

The reason `toilerState[tokenId].latestTaxRate` is outdated:

- The `toilerState[tokenId].latestTaxRate` is updated when [`stakeMunchable()`](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L166), [`transferToUnoccupiedPlot()`](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L213) and [`_farmPlots()`](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L292).

- If users call `updateTaxRate()` to change `plotMetadata[landlord].currentTaxRate` after the aforementioned changes for `toilerState[tokenId].latestTaxRate`, the `toilerState[tokenId].latestTaxRate` is no longer the latest tax rate.
