# Vulnerability details

## Impact
The protocol includes a feature that enables accounts to create sub-accounts, allowing users to access the application on their mobile devices, for example. These sub-accounts function as fully-fledged accounts, albeit with certain restrictions. From the current codebase, it is evident that sub-accounts can become owners of munchables. However, if a sub-account becomes the owner of the NFT, neither the main account nor the sub-account will be able to utilize the `LandManager::stakeMunchable(...)` functionality, as it will always compare the main account with the owner of the NFT, which is the sub-account.

## Recommended Mitigation Steps

Add a new function in the `AccountManager.sol` to check if an account is actually a sub-account and then check if the NFT owner is either owned by the main account or if the owner is a sub-account of the main account.

Add the following to `AccountManager.sol` (also add it to the interface):

```solidity
function isSubAccount(address _player, address _subAccount) external view returns (bool isSubAccount) {
        uint256 subAccountsLength = subAccounts[_player].length;

        for (uint256 i = 0; i < subAccountsLength; i++) {
            if (subAccounts[_player][i] == _subAccount) {
                isSubAccount = true;
                break;
            }
        }
    }
```
