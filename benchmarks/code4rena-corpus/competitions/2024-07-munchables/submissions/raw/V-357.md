# Vulnerability details

## Impact

When farming plots, a bonus is calculated. A portion of the bonus corresponds to the tokens rarity and this is indexed from a uint8 array, cast to int8 then cast to int16. When casting from int8 to uint8, the value will underflow if it is >= 128.

## Proof of Concept

The array of bonuses is declared as:
```solidity
    uint8[] RARITY_BONUSES;
```
<https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L18>

The unsafe cast during caluclation is:
```solidity
                int16(
                    int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])
                );
```
<https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L277-L279>


Consider the following Echidna test, replacing RARITY_BONUSES with an abritray uint8 variable which can be set externally. The casting is identical to that in LandManager.

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity 0.8.25;

contract NoUnderflow{
    uint8 public rarityBonus;

    function setBonus(uint8 newBonus) public {
        rarityBonus = newBonus;
    }


    function echidna_no_underflow() public view returns (bool) {
        int16 bonus = int16(int8(rarityBonus));
        return (bonus >= 0);
    }
}
```

It is seen that the test fails with rarity bonus values >= 128.
