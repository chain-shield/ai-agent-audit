# Vulnerability details

## Impact

As AccountManager.addSubAccount() can arbitrarily overwrite anyone’s main account, an attacker can prevent a chosen victim from staking their MunchNFT. Hence, the victim will never be able to participate in the game.

## Proof of Concept
Consider the following scenario:

1. Assume Alice has registered her account usually via `AccountManager.register()`. And Alice owns her NFT (`tokenId = 1`) and wants to stake it to participate in the game
2. Bob frontruns Alice by calling `AccountManager.addSubAccount(alice)` which sets `mainAccounts[alice]` to Bob’s address
3. When Alice calls `stakeMunchable()`, the call will revert due to `InvalidOwnerError`. This is because of `munchNFT.ownerOf(tokenId) != mainAccount` as `mainAccount` is now set to Bob’s address. This prevents Alice from participating in the game forever.

## Tools Used

Manual review

## Recommended Mitigation Steps

The AccountManager logic must be reworked to ensure that no authorized party can arbitrarily modify someone’s main account address. The simplest fix would be to remove the entire concept of subaccount. If that’s not feasible, one potential mitigation is to require an approval signature from the original main account’s address in order to override the original main account address.
