# Vulnerability details

## Description

In the `LandManager` contract, the amount of available plots depends on the landlord's `getLockedWeightedValue()` from the `LockManager` contract.

Due to price changes or the landlord unlocking some of his tokens, the number of plots can decrease. When this happens, the munchable tokens staked on plots outside of the new range will be set as dirty, preventing the user and the landlord from earning schnibbles for them until they are unstaked and restaked to a valid plot.

There is a flaw in the `transferToUnoccupiedPlot()` function which fails to update `toilerState[tokenId].plotId`, allowing a user to occupy all of the landlord's plots with a single token.

The function occupies a new plot but does not update `oldPlotId`, allowing a user to repeatedly occupy new plots while keeping the original plot marked as occupied.

## Impact

User can occupy all of landlord's plots with only a single token, preventing the landlord from earning schnibbles from any of their plots.

The landlord cannot do anything to remove the tokens from the plots, which completely breaks the intended functionality of the protocol.

## Recommended Mitigation Steps

Update `plotId` inside `toilerState` when moving plots

```diff
        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
+        toilerState[tokenId].plotId = plotId;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
```
