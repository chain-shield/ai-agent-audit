# Vulnerability details

## Description
The `getNumPlots` function uses integer division to calculate plot allocation, which can lead to the loss of significant value due to truncation, especially given the high `PRICE_PER_PLOT`.

## Code snippet
https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L344
```solidity
function getNumPlots(address _account) internal view returns (uint256) {
    return lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT;
}
```

The `PRICE_PER_PLOT` is set to 30 ETH (30e18 wei).

## Problem
Integer division in Solidity truncates any remainder. With `PRICE_PER_PLOT` at 30 ETH, users could potentially lose up to 29.99... ETH worth of value without receiving a corresponding plot. This becomes significant when dealing with large locked values.

For example:
- If a user locks 89 ETH, they will receive 2 plots (89 / 30 = 2.96..., truncated to 2).
- The user effectively loses the benefit of 29 ETH of their locked value.

## Impact
While this issue affects all users, it's particularly impactful for:
1. Users locking large amounts of value.
2. The protocol itself, which may accumulate substantial "unused" locked value over time.

The high `PRICE_PER_PLOT` means that each instance of truncation can represent a significant amount of value (up to 29.99... ETH).

## Suggested Fixes

1. Implement a credit system:

```solidity
mapping(address => uint256) public plotCredits;

function getNumPlots(address _account) internal returns (uint256) {
    uint256 totalValue = lockManager.getLockedWeightedValue(_account) + plotCredits[_account];
    uint256 plots = totalValue / PRICE_PER_PLOT;
    plotCredits[_account] = totalValue % PRICE_PER_PLOT;
    return plots;
}
```
This system accumulates "change" for future plot purchases.

2. Allow fractional plot ownership:

Consider implementing a system where users can own fractions of plots, represented as a separate token or within the existing NFT structure.


3. Rounding up (with caution):

```solidity
function getNumPlots(address _account) internal view returns (uint256) {
    uint256 lockedValue = lockManager.getLockedWeightedValue(_account);
    return (lockedValue + PRICE_PER_PLOT - 1) / PRICE_PER_PLOT;
}
```

Note: This approach always favors the user and may need additional mechanisms to prevent exploitation.
