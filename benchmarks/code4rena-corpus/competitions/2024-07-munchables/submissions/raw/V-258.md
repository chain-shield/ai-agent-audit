# Vulnerability details



## Summary
The _farmPlots() function incorrectly updates the timestamp for "dirty" plots, potentially leading to significant underestimation of rewards for affected Munchables.

## Vulnerability Details
In the _farmPlots() function:

```solidity
if (_getNumPlots(landlord) < _toiler.plotId) {
    timestamp = plotMetadata[landlord].lastUpdated;
    toilerState[tokenId].dirty = true;
}
```

When a plot is marked as "dirty" (i.e., the plot ID no longer fits the landlord's available plots), the function uses plotMetadata[landlord].lastUpdated as the timestamp for reward calculations. This value could be much more recent than the actual last farming time for the Munchable.

## Impact

- Users with Munchables on "dirty" plots will receive significantly reduced rewards.
- The longer a user goes without farming, the more severe the impact becomes.
- This could lead to substantial economic losses for affected users and disrupt the game's reward distribution mechanics.

## Tools Used
- Manual code review


## Recommendations
1. Store the original staking timestamp for each Munchable:
   ```solidity
   struct ToilerState {
       uint256 originalStakeTimestamp;
       // other fields...
   }
   ```
2. Use the stored original timestamp for reward calculations:
   ```solidity
   uint256 rewardPeriod = timestamp - _toiler.originalStakeTimestamp;
   ```
3. Implement a mechanism to properly migrate "dirty" plots to new valid plots without losing accumulated reward time.
4. Add events to notify users when their plots become "dirty" so they can take action.
