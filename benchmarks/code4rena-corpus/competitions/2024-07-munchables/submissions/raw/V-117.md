# Vulnerability details

## Impact
When a user transfer it's staked NFT to a different PlotId it calls **transferToUnoccupiedPlot()**. This method doesn't update **toilerState[tokenId].plotId** which causes 2 major problems:
- If a user stakes another NFT on previous PlotId, it leads to **toilerState[tokenId].plotId** being same for 2 TokenIds.
- If the user unstake it's NFT the **unstakeMunchable()** set old PlotId as unoccupied because **toilerState[tokenId]** will returns the old PlotId and the new PlotId where the NFT was transfered to previously stay as occupied. Now, the new PlotId will remain in occupied state even though there's no NFT staked to it. The old PlotId will be marked as unoccupied irrespective of if a new user has staked NFT on it.

Add a few view functions in the solidity contract for testing
``` solidity
function getToilerState(uint256 tokenId) public returns (uint256, uint256, uint256, address, bool) {
    ToilerState memory _toilerState = toilerState[tokenId];
    return (_toilerState.plotId, _toilerState.latestTaxRate, _toilerState.lastToilDate, _toilerState.landlord, _toilerState.dirty);
}

function getNumberOfPlots(address landlord) public returns(uint256) {
    return _getNumPlots(landlord);
}

function getPlotOccupiedState(address landlord, uint256 plotId) public returns (uint256, bool) {
    return (plotOccupied[landlord][plotId].tokenId, plotOccupied[landlord][plotId].occupied);
}
```

## Recommended Mitigation Steps
Update the PlotId in **transferToUnoccupiedPlot()**
``` solidity
toilerState[tokenId].plotId = plotId
```
