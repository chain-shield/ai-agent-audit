# Vulnerability details

## Impact
Not updating the time will cause [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261) to farm more rewards to users than they should.

## Proof of Concept
[updateTaxRate](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L92-L101) doesn't update `plotMetadata[landlord].lastUpdated`. This cna be considered an issue as it breaks the implementation inside [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261) made to calculate the new rewards based on `lastUpdated` if the plot is dirty.

```solidity
   if (_getNumPlots(landlord) < _toiler.plotId) {
       timestamp = plotMetadata[landlord].lastUpdated;
       toilerState[tokenId].dirty = true;
   }
   ...
   schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
```

Since the above concept is implemented inside [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261), it's intentions are clearly to use the last tax updated timestamp --`plotMetadata[landlord].lastUpdated` -- as timestamp when the `toilerState` is marked as `dirty`.

However that won't be the case as multiple tax chnages can be made without updating `plotMetadata[landlord].lastUpdated`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the `lastUpdated` time inside [updateTaxRate](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L98C9-L99):

```diff
    uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
    plotMetadata[landlord].currentTaxRate = newTaxRate;
+   plotMetadata[landlord].lastUpdated = block.timestamp;
```
