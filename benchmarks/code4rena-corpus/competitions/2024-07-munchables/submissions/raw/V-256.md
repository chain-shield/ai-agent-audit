# Vulnerability details

## Impact
The `_farmPlots` function in the `LandManager` contract contains an unbounded loop that iterates over all staked munchables. This could lead to excessively high gas costs or even cause transactions to fail due to reaching the block gas limit, potentially resulting in a denial of service (DoS) condition.
## Proof of Concept
The vulnerability exists in the `_farmPlots` function:

```solidity
function _farmPlots(address _sender) internal {
    // ... (earlier code)

    uint256[] memory staked = munchablesStaked[mainAccount];
    // ... (variable declarations)

    for (uint8 i = 0; i < staked.length; i++) {
        // ... (loop body with multiple state changes and calculations)
    }

    // ... (remaining code)
}
```

To exploit this:
1. A user (or attacker) stakes a large number of munchables, e.g., 300 or more.
2. When `_farmPlots` is called (either directly via `farmPlots` or indirectly via other functions), the loop will iterate over all staked munchables.
3. With a large number of iterations, the function may consume more gas than the block gas limit, causing the transaction to fail.
4. This could prevent users from performing actions that trigger `_farmPlots`, effectively causing a denial of service.

## Tools Used

Manual code review and theoretical gas limit analysis.

## Recommended Mitigation Steps

1. Implement a batching mechanism to process a limited number of munchables per transaction:

```solidity
uint256 constant MAX_BATCH_SIZE = 50;

function _farmPlots(address _sender) internal {
    // ... (earlier code)

    uint256[] memory staked = munchablesStaked[mainAccount];
    uint256 endIndex = Math.min(staked.length, MAX_BATCH_SIZE);

    for (uint256 i = 0; i < endIndex; i++) {
        // ... (existing loop body)
    }

    // If there are more munchables to process, emit an event
    if (staked.length > MAX_BATCH_SIZE) {
        emit RemainingMunchablesNeedProcessing(mainAccount, staked.length - MAX_BATCH_SIZE);
    }

    // ... (remaining code)
}
```

2. Implement a separate function for processing remaining munchables:

```solidity
function processBatchMunchables(uint256 startIndex, uint256 batchSize) external {
    // ... (implementation to process a batch of munchables)
}
```

3. Consider implementing a pull-payment pattern instead of the current push-based approach:

```solidity
mapping(uint256 => uint256) public unclaimedSchnibbles;

function claimSchnibbles(uint256 tokenId) external {
    // ... (claim logic for a single munchable)
}
```

These changes will prevent potential DoS attacks by limiting the gas consumption per transaction and allowing for incremental processing of large numbers of staked munchables.
