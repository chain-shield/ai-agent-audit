# Vulnerability details

## Impact
When the user transferred his munchableNFT from a dirty plot to a valid plot 2 issues are noticed
1) He is denied from earning scnubbles from them because the dirty status of the toiler is not changed from true to false.
2) When the first issue is solved , he starts getting more schnibbles since the toiler.timestamp is not updated to currenttimestamp and hence he will get undeserved schnibbles while calculating schnibbles next time.

## Proof of Concept

In the `function transferToUnoccupiedPlot(uint256 tokenId,uint256 plotId)` , we are not changing the dirty status of the toiler even thogh the munchable has been staked to a new valid plot.
https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L213-L222

Now if the above issue is resolved then we can observe that the user is getting more schnibbles than deserved by understanding this sequence of steps

1) User has updated farm by calling `farmPlot`. The NFT which was staked by user in a valid plot is now in a dirty plot.So `Toiler.timestamp `is updated to `plotMetadata[landlord].lastUpdate`. -[code](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L291)
2) After some blocks , user has transfered that dirty NFT to a valid plot using `transferToUnoccupiedPlot()`. `farmPlot` is executed but since our NFT is dirty it will [skip for that](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L251).
Also the `Toiler.timestamp ` has not changed and holds the value of `plotMetadata[landlord].lastUpdate`. -[code](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L213-L222)
3) Now user has again decided to call `farmPlot`. Now schnibbles for that NFT is calculated based on the  `plotMetadata[landlord].lastUpdate` instead of the actual timestamp when the NFT is restaked to a valid plot again. -[code](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L280-L282)

As a result users schnibbles is calculated based on timestamp where `plotMetada` is last updated before the NFT had been changed to dirty instead of the timestamp where the NFT is actually been transferred to a valid plot.

        toilerState[tokenId].dirty = false;
