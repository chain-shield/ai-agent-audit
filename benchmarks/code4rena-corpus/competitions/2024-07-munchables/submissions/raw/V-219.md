# Vulnerability details

## Impact
User can stake multiple munchables on a single plot.

## Proof of Concept
If we have Alice as staker
Bob as landlord:

1. Alice calls stakeMunchable(landlord = Bob, tokenId = 1, plotId = 1)
2. Alice transfersToUnocupiedPlot(tokenId = 1, plotId = 2)
3. Alice calls stakeMunchable(landlord = Bob, tokenId = 2, plotId = 1)

If we look at the toilerStates for tokenId = 1 and tokenId = 2 they would look like this:

```solidity
///tokenId = 1
 struct ToilerState {
        uint256 lastToilDate = random
        uint256 plotId = 1
        address landlord = 0x0Bob
        uint256 latestTaxRate 0x0Bob.taxrate
        bool dirty = false
    }

///tokenId = 2
 struct ToilerState {
        uint256 lastToilDate = random
        uint256 plotId = 1
        address landlord = 0x0Bob
        uint256 latestTaxRate 0x0Bob.taxrate
        bool dirty = false
    }
```

This is happening because the function transfersToUnocupiedPlot() does not update the current plotId leaving
it to be the last one in this case plotId = 1, that means that Alice now has two nft's on plotId = 1, breaking the core game mechanic.

Likelihood = high
Impact = high
Severity = high

Add new unocupied plotId to toilerState

if (plotId >= totalPlotsAvail) revert PlotTooHighError();
