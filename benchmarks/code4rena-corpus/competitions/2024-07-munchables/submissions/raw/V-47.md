# Vulnerability details

## Impact
Users can capture rewards even when their plots are `dirty`.

## Proof of Concept
1. [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261) has the ability to make a plot `dirty` if the current landlord available plots are smaller than the ID of this plot:

```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```

When a plot is made dirty it's rewards are claimed for the last time, and it becomes basically useless. The only way to remove the `dirty` tag is to unstake and stake the NFT again. That implies that if a plot gets `dirty` even once, it's rewards are stopped. 

2. The number of available plots is calculates inside [_getNumPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L344-L346) and it represents the weight of our user divided by the price per plot:
```solidity
    function _getNumPlots(address _account) internal view returns (uint256) {
        // weight / price
        return lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT;
    }
```
Where weight is calculated inside [getLockedWeightedValue](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L481-L491), as `quantity * price`:

```solidity
lockedWeighted += (
   deltaDecimal 
   * lockedTokens[_player][configuredTokenContracts[i]].quantity
   * configuredTokens[configuredTokenContracts[i]].usdPrice) 
   / 1e18;
```

3. And finally the `price` can be changed by oracle providers using [proposeUSDPrice](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L142).

---

When we take the above points into account we can see that a change in price can cause a change in available plots, which in tern my make some plots dirty.

However users can avoid such changes, by waiting them out and claiming the rewards for the whole period, even the time when their plot should have been considered `dirty`.

Example:
- Plot price is 100 weight, where each asset is priced as 1.
1. At T1 user has 200 weight and 2 plots.
2. At T2 price changes from 1 to 0.95, making his weight 195 and causing his plot to become dirty **if farmed**.
3. At T3 price goes up again to 1.
4. User farms his plot capturing rewards for T1 to T3, even thought his plot would have been dirty from T2 to T3.

In the above case our user captured rewards for a time where his plot should have been dirty. 

## Tools Used
Manual review

## Recommended Mitigation Steps
Given the current implementation I cannot provide a simple solution to this issue. My best suggestion is to enable anyone to farm plots inside the LandManager, but that may cause issues in other parts of the code. Another solution can be to introduce PVP in the form of liquidations, rewarding users who punish dirty plots.
