# Vulnerability details

## Impact
If the `landlord` unstakes their money from `lockManager` and their plots are marked as dirty, the `landlord` will not be able to receive rewards for a new plotId that becomes available when they stake money again.
A user who stakes a `MunchNFT` on the landlord's plotId could potentially never unstake it, preventing the `landlord` from receiving rewards.
In that case, the user can grief the landlord until he unstake the corresponding MunchNFT.

## Proof of Concept
- The `landlord` stakes money in `lockManager` for 10 plots, i.e. `_getNumPlots(landlord) returns 10`
- Users occupy all of the landlord's plots.
- The `landlord` unstakes part or all tokens for a short period.
- During this period, if a user performs any action with munchNFT, the internal `_farmPlots()` function marks the `landlord`'s plots as dirty.
- The `landlord` stakes part or all tokens back in `lockManager`.
- Now `_getNumPlots(landlord) returns 10` again.
- However, not all users unstake munchNFTs from the `dirty` plots of the `landlord`.
- The `landlord`'s plot IDs will remain marked as `dirty` until the user unstakes the NFT.

Dirty toilers will always be `skipped`, even if `_getNumPlots(landlord) < _toiler.plotId` is false:
```solidity
    timestamp = block.timestamp;
    tokenId = staked[i];
    _toiler = toilerState[tokenId];
@>  if (_toiler.dirty) continue;
    landlord = _toiler.landlord;
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        // @audit if toiler is marked dirty it can't be marked as clean again, 
        toilerState[tokenId].dirty = true;
    }
```

The `dirty` flag changes to `false` only in `unstakeMunchable()`:

```solidity
    toilerState[tokenId] = ToilerState({
        lastToilDate: 0,
        plotId: 0,
        landlord: address(0),
        latestTaxRate: 0,
@>      dirty: false
    });
```
## Tools Used
manual review

## Recommended Mitigation Steps
Implement a system that tracks the occupied time, so when the `landlord` stakes tokens again, their occupied time begins to increase again.
