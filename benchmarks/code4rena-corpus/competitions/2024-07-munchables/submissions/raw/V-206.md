# Vulnerability details

## Description

In the `LandManger` contract, users can stake their munchable tokens on the plots of landlords to earn schnibbles for both themselves and the landlords. Each landlord has a certain number of plots determined by `_getNumPlots(landlord)`.

When the number of plots (`_getNumPlots(landlord)`) decreases due to a price change or the landlord unlocking some tokens from the `LockManager` contract, the munchable tokens staked on plots now outside of the new range are marked as dirty. Dirty tokens cannot earn schnibbles until they are unstaked and restaked on a valid plot.

```solidity

            timestamp = plotMetadata[landlord].lastUpdated;
  ❌@>     toilerState[tokenId].dirty = true;
        }
      ...
```

If a user's token gets marked as dirty, they can move it to a new plot using `transferToUnoccupiedPlot()`, occupying a plot that could've been used by a token that is not dirty. This prevents the landlord from earnning schnibbles from that plot and griefs the landlord / disrupts the intended functionality of the `LandManager` contract.

```solidity

            timestamp = block.timestamp;

  ❌@>     if (_toiler.dirty) continue;
```

This can also be done with multiple dirty tokens, occupying several plots and further reducting the landlord's potential earnings.

## Impact

A renter can grief landlords by moving their dirty tokens to new plots, preventing landlords from earning schnibbles from these plots. Renters also won't be able to earn schnibbles for these dirty tokens, but they can still disrupt the landlords' earnings.

## Recommended Mitigation Steps

Add `if (_toiler.dirty) revert DirtyToken();` inside `transferToUnoccupiedPlot()` function to prevent moving dirty tokens to new plots.
