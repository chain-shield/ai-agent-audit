# Vulnerability details

## Impact
The function [updateTaxRate](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L92) is making the following checks:
User  is registered:
```js
        (address landlord, ) = _getMainAccountRequireRegistered(msg.sender);
```
The provided amount of tax rate is within predefined range:
```js
        if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE)
                    revert InvalidTaxRateError();
```
The actual landlord plot is created before updating:
```js
        if (plotMetadata[landlord].lastUpdated == 0)
            revert PlotMetadataNotUpdatedError();
```
Then it proceeds with replacing old tax rate with new desired tax rate.

In order to have plots landlords must have certain amount locked.
## Proof of Concept
Bob have his funds locked and want to become landlord. His plot metadata is created and stored in `plotMetadata` mapping and that plot metadata is associated with his landlord address. Bob decide to change his tax rate so he calls `updateTaxRate` to change his current tax rate with new tax rate. Everything is good and in order as it should be.
Then some time passes and Bob decides to withdraw his locked funds and not be a landlord anymore. Since Bob's address is still in the `plotMetadata` mapping he can call `updateTaxRate` function still, even thou he don't have any funds locked anymore and should not be landlord. Bob decide to be malicious and does exactly that and he can keep collecting and updating taxes even he should not.
