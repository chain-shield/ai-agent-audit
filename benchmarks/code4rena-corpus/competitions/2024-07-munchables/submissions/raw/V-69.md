# Vulnerability details

## Impact
When a plot can be marked as `dirty` it will pay rewards only from `toilerState[tokenId].lastToilDate` up to `plotMetadata[landlord].lastUpdated`, which may mean, that rewards are not paid up to the current `block.timestamp`.

However users can update their own metadata and claim for their `dirty` plot up to `block.timestamp`

## Proof of Concept
If a plot is to be marked as `dirty` [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261) will claim the rewards only up to `plotMetadata[landlord].lastUpdated`, which can be in the past.


```solidity
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }

    ...

    schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
```

However users can prevent that and claim their rewards for their dirty plots by updating their landlord's `plotMetadata` using [updatePlotMetadata](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L124-L126). That can be done by locking some amount (can be 1 wei) for their landlord with [LockManager::lockOnBehalf](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L278-L294), which will trigger [AccountManager::forceHarvest](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/AccountManager.sol#L151-L155), setting their `plotMetadata[landlord].lastUpdated` to the current `block.timestamp`.

Example:
1. At T1 our user stakes at the last free slot of a landlord.
2. At T2 the landlord withdraws some of his locked tokens, decreasing his active plots.
3. At T3 our user, who's plot is less than the active plots (will be `dirty` after harvest), wants to claim his rewards.
4. He calls [lockOnBehalf](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L278-L294) for the landlord, locking 1 wei and updating his metadata.
5. Then he claims his rewards, claiming from T1 to T3.

Notice how our user has claimed rewards for time that his plot would have been considered `dirty` (T2-T3) and not paid rewards.

## Recommended Mitigation Steps
A really good solution would be to make a landlord specific map that will track the time at which plots become `dirty` and when [_farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261) is invoked it will only query that plot and see if it's dirty or not. Example code:

```solidity
   if (_getNumPlots(landlord) < _toiler.plotId) {
      timestamp = plotDirtyTime[_toiler.plotId];
      toilerState[tokenId].dirty = true;
      plotDirtyTime[_toiler.plotId] = 0;
   }
```
The only downside to this would be that on [LockManager::unlock](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L407) we would need to iterate over the array and set the removed plots to the current `block.timestamp`. That may also cause an issue if we unlock for more than 500 or 1000 plots as the gas would get expensive.
