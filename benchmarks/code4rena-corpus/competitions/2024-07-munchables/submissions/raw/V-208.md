# Vulnerability details

## Impact
The uint256 `PRICE_PER_PLOT` variable can be found in 3 places of the `LandManager` contract. The first one is on the 16th line where it is declared:
```solidity
uint256 PRICE_PER_PLOT;
```
The second is on the 77th line where it is set to a value retrieved from the `ConfigStorage` contract:
```solidity
PRICE_PER_PLOT = IConfigStorage(configStorage).getUint(
            StorageKey.NFTOverlord
        );
```
and the third is on the 347th line where it is used for calculation:
```solidity
function _getNumPlots(address _account) internal view returns (uint256) {
        return lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT;
    }
```
After a short review of the `ConfigStorage` contract and a query to the documentation bot called `Docs Wolf`, I came to the conclusion that nowhere is it checked whether `PRICE_PER_PLOT` has a value equal to 0. Thus, every function that uses `_getNumPlots` to calculate the available plots could revert due to division by zero.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Create a check method that ensures the value of `PRICE_PER_PLOT` is not zero, and if it is, revert with an error.
