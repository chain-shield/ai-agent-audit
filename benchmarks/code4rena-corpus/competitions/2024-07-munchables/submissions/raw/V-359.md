# Vulnerability details

## Impact
Users will be staked to Landlords that they see having `MIN_TAX_RATE` but will be subjected to `MAX_TAX_RATE` leading to unintended loss of `schnibbles` due to those accounting here 
```solidity
            schnibblesLandlord =
                (schnibblesTotal * _toiler.latestTaxRate) /
                1e18;
```
and here 

```solidity
            renterMetadata.unfedSchnibbles += (schnibblesTotal -
                schnibblesLandlord);
```

## Proof of Concept

The problem arises from the fact that `updateTaxRate` function doesn't have timelock

This allow players to have their `currentTaxRate` at `MIN_TAX_RATE` to attract users to stake their Munchables on them

Now whenever a Landlord sees a user txn of `stakeMunchable` with their address as `landlord` he can sandwich attack that txn frontrunning it to update his taxRate to `MAX_TAX_RATE` then back run the user txn to update his taxRate to `MIN_TAX_RATE`

This will work cause in `stakeMunchable` the `currentTaxRate` (which was fortrun to be at Max) will be stored in the `toilerState` of the token of the user and retreived later when the user calls `farmPlots` 

```solidity
File: LandManager.sol
162:         toilerState[tokenId] = ToilerState({
163:             lastToilDate: block.timestamp,
164:             plotId: plotId,
165:             landlord: landlord,
166:             latestTaxRate: plotMetadata[landlord].currentTaxRate,
167:             dirty: false
168:         });
```

So Landlord will only make his taxRate to max only at that specific txn.

in addition to that the LandLord can do the same to users while `_farmPlots` is called through other functions

cause as we see here in `_farmPlots` 

```solidity
File: LandManager.sol
292:             toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
293:                 .currentTaxRate;
```
the `currentTaxRate` is updated at the end of every call. so yet again the LandLord will sandwich attack those calls too to keep the stored tax of `toilerState[tokenId].latestTaxRate` to be at Max always
