# Vulnerability details

## Description
When a landlord calls the `updateTaxRate` function, his/her plotMetadata.currentTaxRate is set to the newTaxRate:
```solidity
function updateTaxRate(uint256 newTaxRate) external override notPaused {
...
plotMetadata[landlord].currentTaxRate = newTaxRate;
...
}
```

However, when a user calls `_farmPlots`, the enforced taxRate is the one that was set during either the moment when the stake was created or when the stake was last farmed:
```solidity
function _farmPlots(address _sender) internal {
...
schnibblesLandlord =
    (schnibblesTotal * _toiler.latestTaxRate) /
    1e18;
...
}
```

Then, the function sets the stake/toiler's latestTaxRate to the newest one:
```solidity
function _farmPlots(address _sender) internal {
...
toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
                .currentTaxRate;
...
}
```

The issue with that is a landlord may set a new tax rate, but the users may avoid it altogether by not calling any action at the contract. Then call the unstake function to accrue its schnibbles only when it really desires to stop using the contract, avoiding the new tax rates completely.

## Impact
Users are able to avoid new tax rates set by the landlord entirely.

## Tools Used
Manual review
## Recommended Mitigation Steps
Consider introducing timestamp-based epochs/periods to determine a the toiler's state, this way users cannot maliciously become inactive to avoid a landlord's taxation.
