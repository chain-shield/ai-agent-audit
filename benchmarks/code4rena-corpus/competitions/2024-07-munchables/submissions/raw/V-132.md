# Vulnerability details

## Impact
In `LandManager::_removeTokenIdFromStakedList` every single time the function is called we iterate through the whole `munchablesStaked` in order to:
1. Check that there is a tokenId with such tokenId
2. If there is one then to remove it.

Provided that a lot of users stake munchables the array inside the map `munchablesStaked` will become way to gas expensive to iterate through causing self DOS.

High - too many staked munchables result in extremely high gas consumption making `_removeTokenIdFromStakedList` unusable and not be able to remove tokenIds from staked list

## Proof of Concept
1. Deploy and initialize `LandManager` contract
2. Configure initial tax rates by calling relevant functions as usual
3. Large amount of munchables are staked
4. Call `LandManager::_removeTokenIdFromStakedList` with any valid params

## Tools Used
Solidity

## Recommended Mitigation Steps
Use another map to store the tokenIds to address. Thus, you will NOT have to iterate through the whole list just to check whether there is such a tokenId to be removed and saving massively from gas:

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L27

```solidity
+     mapping(uint256 => address) munchablesTokenIdsToAddress;
-     mapping(address => uint256[]) munchablesStaked;
```

Another alternative is to have a map which stores the tokenIds indexs by ranges and iterating only a specific range (batches) instead of the whole map. However, this adds additional complexity, because each time a token is added/removed you have to update the other map as well and make sure you set the correct ranges.

Overall, the first solution above is one of the best.
