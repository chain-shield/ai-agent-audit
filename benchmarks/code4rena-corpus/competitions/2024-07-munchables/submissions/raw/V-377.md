# Vulnerability details

## Impact
User earns significantly lesser schnibbles if the plot they staked on becomes unexistent due to landlord removing funds

## Proof of Concept
In the farm plots function, if the plot a user stakes their nft on becomes inactive, the nft is put into a dirty state and the rewards based on the last time the landlord's plot was active. 
```
if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```
However, the timestamp used in the above block is unfair to the user as they can end up receiving a significantly lower amount of schnibbles than they deserve. This is because the timestamp is set to the last time the plot was active and rewards are calculated from that point onwards:
```
schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
```
This is implemented wrongly because the reward is calculated from the plot's last active timestamp to the current timestamp, when it should have been calculated from the last time the user farmed rewards down to the point where the plot became inactive.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The schnibblesTotal should be calculated as:
```
//current block timestamp
timestamp = block.timestamp;

plotLastUpdated = plotMetadata[landlord].lastUpdated

//this ensures the reward time is considered from the point when the user staked to the point when the plot became inactive
schnibblesTotal =
                (timestamp - plotLastUpdated - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
```

This approach also helps disincentivize inactivity as it would be in the user's best interest to transfer the nft to an active plot so they can start earning rewards again
