# Vulnerability details

## Description
The calculation of total schnibbles generated is at extremely high risk of integer overflow due to the combination of a large BASE_SCHNIBBLE_RATE and unchecked time differences.

## Code snippet
https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L280
```solidity
schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
```


The BASE_SCHNIBBLE_RATE is set to 1e15 (1,000,000,000,000,000) in the configuration.

## Problem
The extremely high BASE_SCHNIBBLE_RATE of 1e15 creates a critical risk of integer overflow:

1. Even small time differences lead to massive numbers:

- A time difference of just 1,000 seconds (about 17 minutes) results in:
1,000 * 1e15 = 1e18, which is already at the limit of uint256.
- Any time difference greater than 17 minutes will cause an overflow.

2. This makes the system unusable for any practical farming timeframes.

3. Runtime errors causing all farming operations to fail after short periods.

## Impact
1. The schnibble generation system is effectively broken:
- Users cannot farm for more than ~17 minutes without causing issues.
- Long-term farming, a key aspect of many blockchain games, is impossible.

2. Severe disruption to game economy:
- In 0.8.0+: Farming operations consistently fail, preventing any schnibble generation.

3. Complete breakdown of the intended game mechanics related to schnibble farming.

4. Loss of user trust and engagement due to non-functional core game feature.

## Suggested Fixes

1. Drastically reduce BASE_SCHNIBBLE_RATE and implement scaling:

```solidity
uint256 constant SCALE = 1e15;
uint256 constant BASE_SCHNIBBLE_RATE = 1; // Reduced from 1e15
...
schnibblesTotal = ((timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE) / SCALE;
```

2. Implement a cap on time difference along with rate reduction:

```solidity
uint256 constant MAX_TIME_DIFF = 30 days;
uint256 constant BASE_SCHNIBBLE_RATE = 1e5; // Reduced significantly
...
uint256 timeDiff = timestamp - _toiler.lastToilDate;
if (timeDiff > MAX_TIME_DIFF) {
    timeDiff = MAX_TIME_DIFF;
}
schnibblesTotal = timeDiff * BASE_SCHNIBBLE_RATE;
```

3. Use a "per second" rate and accumulate over time:

```solidity
uint256 constant SCHNIBBLES_PER_SECOND = 1e7; // Adjust as needed
...
uint256 timeDiff = timestamp - _toiler.lastToilDate;
schnibblesTotal = timeDiff * SCHNIBBLES_PER_SECOND;
```
