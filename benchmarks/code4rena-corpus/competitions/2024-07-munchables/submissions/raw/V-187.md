# Vulnerability details

## Impact
This bug does not allow any farm points to be calculated and added to the munchable owner and landlord, failing the main functionality of the farming points contract.

## Proof of Concept
In `_farmPlots()` function, a loop is setup to go through each munchable that `mainAccount` has staked, calculate points accumulated across them and update the tally for `mainAccount` and all the landlords involved in staking. All the calculation logic is executed after this line of code:

```solidity
251:            if (_toiler.dirty) continue;
```

It executes to calculate the points if `dirty` is set true for the given staked munchable in loop. But, by default all the instances initialising `toilerState` for any munchable sets it as `false` in the contract.

```solidity
162:        toilerState[tokenId] = ToilerState({
            lastToilDate: block.timestamp,
            plotId: plotId,
            landlord: landlord,
            latestTaxRate: plotMetadata[landlord].currentTaxRate,
            dirty: false
        });

185:        toilerState[tokenId] = ToilerState({
            lastToilDate: 0,
            plotId: 0,
            landlord: address(0),
            latestTaxRate: 0,
            dirty: false
        });

```

First initialisation happens when a munchable is staked. Second one is when it's unstaked, so it isn't useful after that anyways.

As for any instances of setting `dirty` to `true` come after the initial `if(_toiler.dirty) continue;` statement comes.

```solidity
251:            if (_toiler.dirty) continue;
            landlord = _toiler.landlord;
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```

That also if given plotId is larger than number of plots landlord has. Calculating points code is followed after this block of code.

```solidity
247:        for (uint8 i = 0; i < staked.length; i++) {
            timestamp = block.timestamp;
            tokenId = staked[i];
            _toiler = toilerState[tokenId];
            if (_toiler.dirty) continue;
            landlord = _toiler.landlord;
            // use last updated plot metadata time if the plot id doesn't fit
            // track a dirty bool to signify this was done once
            // the edge case where this doesnt work is if the user hasnt farmed in a while and the landlord
            // updates their plots multiple times. then the last updated time will be the last time they updated their plot details
            // instead of the first
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
            (
                ,
                MunchablesCommonLib.Player memory landlordMetadata
            ) = _getMainAccountRequireRegistered(landlord);

            immutableAttributes = nftAttributesManager.getImmutableAttributes(
                tokenId
            );
            finalBonus =
                int16(
                    REALM_BONUSES[
                        (uint256(immutableAttributes.realm) * 5) +
                            uint256(landlordMetadata.snuggeryRealm)
                    ]
                ) +
                int16(
                    int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])

                1e18;

                .currentTaxRate;

            renterMetadata.unfedSchnibbles += (schnibblesTotal -
                schnibblesLandlord);

```

So, as it can be seen from above, that for calculating points, `_toiler.dirty` has to be true, which it cannot be as the only instance of setting it true comes after checking if `_toiler.dirty` is true, plus another condition, which means that `toilerState[tokenId].dirty = true` statement is inaccessible and never going to be executed. Thus along with that, the whole points calculation logic will also be not executed.

## Recommended Mitigation Steps
Change how dirty variable is used, possibly set it to true when initialising it after staking and making it false when the plotId becomes more than number of plots owner has.
