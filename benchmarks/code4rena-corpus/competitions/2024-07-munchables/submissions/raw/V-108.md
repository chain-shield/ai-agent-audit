# Vulnerability details

## Impact
There is a method to **transferToUnoccupiedPlot()** where users can transfer to an unoccupied plotId. This method doesn't account the dirty status of existing plot. Hence, the user will still not get rewards for this tokenId if **_toiler.dirty** was true initially.

### Output
Initially Alice had 1 Ether staked. So it had 125 plots available. Bob staked at 124th plot of Alice. Now, Alice withdraws 0.5 Ether. Which leads to her plots decreasing to 62 plots. Now, whenever Bob calls **transferToUnoccupiedPlot()** method **farmPlots()** will be triggered. Which will mark it as dirty as the plot id is not valid anymore. But since Bob has transfered it's NFT to a valid unoccupied plot, The dirty flag should've been changed to false. So Bob can acquire  rewards for it's staked NFT. But this won't happen as the plot is still being marked as dirty.

## Recommended Mitigation Steps
Change the plot status to dirty = false in toilerState as the plot is a valid unoccupied plot only.

``` solidity
toilerState[tokenId].dirty = false
```
