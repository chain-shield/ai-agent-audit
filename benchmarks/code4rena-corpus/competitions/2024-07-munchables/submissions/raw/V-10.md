# Vulnerability details

## Impact
A user can own a plot and receive rewards from farming without having any funds locked because of a wrong check in `LandManager::_farmPlots`.

## Proof of Concept

The contract team has outlined an edge case where the landlord has withdrawn/unlocked their funds and as a result own less plots than before and some of the users that have staked on them can no longer use them. They have decided that if a user were to be staking on a no longer existing plot they would give them the rewards once and mark it as `dirty` and stop giving both the landlord and user rewards. However this edge case is not handled properly and allows for a landlord to own a plot while having 0 funds locked and for a user to stake on it and receive rewards as if the plot existed.

If we take a look inside `LandManager::_farmPlots` we can see the check that takes care of the edge case:

```solidity
            // use last updated plot metadata time if the plot id doesn't fit
            // track a dirty bool to signify this was done once
            // the edge case where this doesnt work is if the user hasnt farmed in a while and the landlord
            // updates their plots multiple times. then the last updated time will be the last time they updated their plot details
            // instead of the first
@>          if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```

The problem arises from the fact that `plotId` are numbers starting from 0,1,2... , meaning that the first plot a landlord gets will have `plotId = 0`. This is confirmed from the check in `LandManager::stakeMunchable`

```solidity
        uint256 totalPlotsAvail = _getNumPlots(landlord);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();
```

The return value of `_getNumPlots` is the exact number of how many plots a landlord owns. For example if `_getNumPlots` returns 1, the landlord has 1 plot with `plotId = 0`. But if we again take a look at the check in `LandManager::_farmPlots` we can see that we will not enter the stated edge case even if we provide a `plotId` that shouldn't exist.

E.g. 

```solidity
//           1              <      1         => false
 if (_getNumPlots(landlord) < _toiler.plotId) {
```

That means we will not enter the edge case and mark the plot as dirty even though the landlord does not own the plot with `plotId = 1`.

## Recommended Mitigation Steps

```diff
            // use last updated plot metadata time if the plot id doesn't fit
            // track a dirty bool to signify this was done once
            // the edge case where this doesnt work is if the user hasnt farmed in a while and the landlord
            // updates their plots multiple times. then the last updated time will be the last time they updated their plot details
            // instead of the first
-           if (_getNumPlots(landlord) < _toiler.plotId) {
+           if (_getNumPlots(landlord) <= _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
```
