# Vulnerability details

## Impact
The current implementation allows users to bypass the intended limit of 11 staked Munchables per account. This leads to unfair advantage for users with more resources. This breaks an important invariant of the game. They will also take up most of the available plots.

## Proof of Concept
The vulnerable check is in the stakeMunchable function:

```js
if (munchablesStaked[mainAccount].length > 10)
    revert TooManyStakedMunchiesError();
```

This check can be bypassed by following these steps:

A user with more than 11 Munchable NFTs transfers excess tokens to a new account.
The new account registers as a player, and can now stake up to 11 additional Munchables, effectively allowing the original user to stake more than the intended limit. These users can monopolize all the available plots and prevent other users from participating.

    function testBypassMaxStakedNFT() public {

        // Assume Alice has 2 addresses
        address aliceFirstAddress = makeAddr("First Address");
        address aliceSecondAddress = makeAddr("Second Address");

        lm.lock{value: 1 ether}(address(0), 1 ether);
        vm.stopPrank();

        vm.startPrank(aliceSecondAddress);
        amp.register(MunchablesCommonLib.Realm.Everfrost, address(0));
        lm.lock{value: 1 ether}(address(0), 1 ether);
        vm.stopPrank();

        // We assume the first address is here main account where all the tokens are minted. We assume more than 10 tokens are minted to her
        vm.startPrank(address(nfto));
        for(uint256 i=1; i < 13; i++){
        stakerToTokenIds[alice].push(nft.mint(aliceFirstAddress));
        }
        vm.stopPrank();

        // She stakes 11 tokens which is the limit
        vm.startPrank(aliceFirstAddress);
        for(uint256 i=1; i < 12; i++){
            IERC721(address(nft)).approve(address(lamp), i);
            lamp.stakeMunchable(landlord1, i, i);
        }

        // Check that she is not able to stake more NFTs
        IERC721(address(nft)).approve(address(lamp), 12);
        vm.expectRevert(bytes4(keccak256("TooManyStakedMunchiesError()")));
        lamp.stakeMunchable(landlord1, 12, 12);

        // She decides to transfer to her second account
        IERC721(address(nft)).transferFrom(aliceFirstAddress, aliceSecondAddress, 12);    

        vm.stopPrank();

        // She stakes the rest of her NFTs
        vm.prank(aliceSecondAddress);
        IERC721(address(nft)).approve(address(lamp), 12);
        vm.prank(aliceSecondAddress);
        lamp.stakeMunchable(landlord1, 12, 12);

    }
```

This process can be repeated with multiple accounts, allowing a single entity to stake an unlimited number of Munchables.

## Tools Used

Manual review and foundry testing.

## Recommended Mitigation Steps

Implement a global tracking mechanism for Munchables minted to each account, regardless of current ownership. Use this tracker to then allow staking of only minted NFTs for a specific user up to 11 NFTs.

Example :

`mapping(address => uint256) public totalMunchablesAcquired;`

When a token gets minted to an account it should increment this mapping :
```js
contract MunchNFT {

function mint(address user) external {

// ... mint logic


totalMunchablesAcquired[user] += 1;

}
```

Use this mapping to check if the stake cap is reached :

```js
if (munchablesStaked[mainAccount].length > 10 && totalMunchablesAcquired[mainAccount] < munchablesStaked[mainAccount].length){
    revert TooManyStakedMunchiesError();
}
