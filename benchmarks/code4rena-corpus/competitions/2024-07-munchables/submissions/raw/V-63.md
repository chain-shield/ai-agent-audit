# Vulnerability details

## Impact
Particular combinations of a landlord snuggery realm, munchable rarity and munchable realm can make the function `_farmPlots` revert due to an overflow error while calculating the schnibble rewards.

Given that the function `_farmPlots` executes whenever a player wants to stake, unstake or transfer a staked munchable, those three actions will always revert for the player. Once the bug is triggered, this will happen always for that player, with any munchable and landlord he tries to use from there on, leaving any staked munchable stuck and denying the player the possibility of staking or unstaking any munchables.

Additionally, the landlord will be partially impacted because he will have at least one plot occupied that will not collect schnibbles from taxes.

## Proof of Concept
The overflow occurs due to what appears to be an incorrect way of adding the bonuses to the `schnibblesTotal` computed in the `_farmPlots` function.

In the line `283` of the file `src/managers/LandManager.sol` it looks like the intention was to increase by a percentage the value of the `schnibblesTotal` variable (or decrease if the bonus was negative):
```
            schnibblesTotal = uint256(
                (int256(schnibblesTotal) +
                    (int256(schnibblesTotal) * finalBonus)) / 100
            );
```
However, the division by `100` is not correctly applied. The division should be done on the amount `int256(schnibblesTotal) * finalBonus` , but it is actually done over `int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus))`.

As a consequence, if the value of `finalBonus` is negative (which can happen if the realm of the landlord and the realm of the munchable are different), then the value of the expression `(int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100` will be negative, and when it is casted to a `uint256` the result will be a big positive number (it can be in the order of `10**69`).

In line `287`, `schnibblesTotal` is multiplied by the landlord's tax rate (greater or equal than `20 * 10**16` according to the test values), making the result of the multiplication greater or equal than `20 * 10**85`, which is more than what a `uint256` can store, causing a revert by overflow.


In the following proof of concept a player with a munchable of `Common` rarity and realm `Everfrost` is staked in a plot of a landlord with a Snuggery realm of `Drench`, this is enough for triggering the bug.

The following values are assumed in accordance to the values provided in the test suites:
```

export const RARITY_BONUSES = [0, 0, 10, 20, 30, 50];
```

## Recommended Mitigation Steps
If the intention in the line `283` of the file `src/managers/LandManager.sol` was to add a percentage as a bonus, then fix the division by `100` leaving the computation as follows:

```
            schnibblesTotal = uint256(
                int256(schnibblesTotal) +
                    ((int256(schnibblesTotal) * finalBonus) / 100)
            );
```

If that was not the intention, then it is recommended to review the desired computation and add checks after computing the value to ensure it is on a desired range that will not overflow when multiplied by the tax rate.
