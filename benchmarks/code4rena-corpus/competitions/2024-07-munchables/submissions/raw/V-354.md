# Vulnerability details

## Impact

Tokens staked to the zero address become stuck and can never be unstaked as it is possible to stake to any landlord even if they haven't registered.

## Proof of Concept

Add the following test to <https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/tests/managers/LandManager/stakeMunchable.test.ts>

```solidity
    it("tried to stake to zero", async () => {
      const txHashApproval = await testContracts.munchNFT.contract.write.approve(
        [testContracts.landManagerProxy.contract.address, 14n],
        { account: alice }
      );
      await assertTxSuccess({ txHash: txHashApproval });
      await assert.rejects(
        testContracts.landManagerProxy.contract.simulate.stakeMunchable([0, 14, 0], {
          account: alice,
        }),
        (err: Error) => assertContractFunctionRevertedError(err, "CantStakeToSelfError")
      );
    });
```

This shows that tokens can be staked successfully to the zero address, however due to the following check in `unstakeMunchable` it will revert as a zero address landlord is considered as no landlord and not being staked.

```
        if (_toiler.landlord == address(0)) revert NotStakedError();
```
<https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L178>

## Tools Used

Manual review.

## Recommended Mitigation Steps

Require landlords to register and have a `plotMetadata.lastUpdated` > 0 before they can be staked to, also check that the landlord is not the zero address when staking.
