# Vulnerability details

## Impact

The lack of bounds checking on the `REALM_BONUSES` array can lead to out-of-bounds errors, causing the following potential issues:

1. **Runtime Exceptions**: If the calculated index exceeds the array length, it may cause a runtime exception, leading to the transaction being reverted.

2. **Disrupted Farming Calculations**: The farming calculations rely on the `REALM_BONUSES` array for determining bonuses. If the array access fails due to an out-of-bounds error, users will be unable to farm their staked Munchables.





## Proof of Concept

The REALM_BONUSES array is stored in a central configuration storage, and its size is dynamic. This means the array can have varying lengths, and there is no inherent guarantee about its minimum size at any given point. Proper bounds checking is crucial to avoid accessing invalid indices.

**Index Calculation** 

The index for accessing the `REALM_BONUSES` array is calculated as `(uint256(immutableAttributes.realm) * 5) + uint256(landlordMetadata.snuggeryRealm) `

Consider the following enum definitions:

```js
enum Realm {
    Everfrost, // 0
    Drench,    // 1
    Moltania,  // 2
    Arridia,   // 3
    Verdentis, // 4
    Invalid    // 5
}
```

Both `immutableAttributes.realm` and `landlordMetadata.snuggeryRealm` use this enum, so they can have values from 0 to 5.

Given that both enum values can range from 0 to 5, the maximum possible index calculation would be `(uint256(5) * 5) + uint256(5) = 25 + 5 = 30` 

To avoid out-of-bounds errors, the REALM_BONUSES array must contain at least 31 elements, as the code assumes the length is correctly set and does not perform any length checks before accessing indices
