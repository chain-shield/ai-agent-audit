# Vulnerability details

## Impact
If value of `lockedTokens[_player][configuredTokenContracts[i]].quantity *configuredTokens[configuredTokenContracts[i]].usdPrice` is less than or equal to `1e10` , `_getNumPlots will return wrong value

The `_getNumPlots` function in `LandManager.sol` returns -
```
lockManager.getLockedWeightedValue(_account) / PRICE_PER_PLOT
```
Which is calling the `getLockedWeightedValue` function from `LockManager.sol` contract. 
The calculation of `lockedWeighted` is as follows
```
 lockedWeighted +=(deltaDecimal * lockedTokens[_player][configuredTokenContracts[i]].quantity *configuredTokens[configuredTokenContracts[i]].usdPrice) /1e18;
```
The calculation of `deltaDecimal ` is as follows - 
```
uint256 deltaDecimal = 10 **(18 - configuredTokens[configuredTokenContracts[i]].decimals);
```
The `configuredTokens` here is `MunchTokens` which contains `1e12` decimals, hence `deltaDecimal` = 10e(18-12)=10e6 

So for correct calculation of `lockedWeighted ` , `lockedTokens[_player][configuredTokenContracts[i]].quantity *configuredTokens[configuredTokenContracts[i]].usdPrice` must be in the range of `1e11` 

If it has decimals less than 11 then it would cause the value to return 0.
As in solidity -> 10e6*1e10=1e17/1e18 , would return 0.

If the value returned is wrong then the `_getNumPlots` will also return wrong value which would then effect the functionality of the other functions which is using `_getNumPlots` like `_farmPlots` , `transferToUnoccupiedPlot` , `stakeMunchable` function.
