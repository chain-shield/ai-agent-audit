# Vulnerability details

## Description
When farming a plot, at the `_farmPlots` function there's a check to ensure if the landlord can still accomodate a toiler's plot Id:
```solidity
if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
}
```

Notice the if condition at the code snippet above.
The `_getNumPlots` returns an unsigned integer, so the smallest value it can return is zero.
Now, if we have a plotId of value zero, it is impossible to set its state to dirty, even if the lardlord has no locked tokens left.This enables the staker to farm forever on such a plot, even though there are no locks to back the plot's existence.
## Impact
Users that stake their tokens to plotId zero on lands are able to farm forever.
## Tools Used
Manual review
## Recommended Mitigation Steps
The `stakeMunchable` function is already protected from this edge case by utilizing the >= sign:
```solidity
uint256 totalPlotsAvail = _getNumPlots(landlord);
if (plotId >= totalPlotsAvail) revert PlotTooHighError();
```

To fix this issue, a similar fix should be implemented at the `_farmPlots function`:
```solidity
if (_getNumPlots(landlord) <= _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
}
```
