# Vulnerability details

## Impact

In `LandManager::stakeMunchable(address,uint256,uint256)` when transfering munch NFT from main account to the LandManager contract:

```solidity
    munchNFT.transferFrom(mainAccount, address(this), tokenId);
```

We need to make sure that the address can receive ERC721 even if we are using address(this) and we know the currect contract can receive ERC721. It is best practice to have a confirmation, providing security for future developments as well and it is decided to logic to be changed.

## Recommended Mitigation Steps

From security point of view it is better to use safeTransferFrom from ERC721 and implementing onERC721Received in your contract so it can confirm that it is capable of handling ERC-721 token transfers, preventing potential issues with frozen tokens. Add useSafeTransferFrom instead of transferFrom:

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L152

```solidity
+    munchNFT.safeTransferFrom(mainAccount, address(this), tokenId);
-    munchNFT.transferFrom(mainAccount, address(this), tokenId);
```

Even though address(this) refers to the current contract, adhering to the safeTransferFrom pattern ensures future compatibility and security.
