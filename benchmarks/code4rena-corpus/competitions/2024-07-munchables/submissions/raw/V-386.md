# Vulnerability details

## Summary
Due to dynamic nature of checking the collaterals value when farming (checked on every farm), a users NFT can be stuck on the contract due to a underflow in subtraction on line 281.

Problem arises when in ```_farmPlots(address)``` function the ```plotMetadata[landlord].lastUpdated``` is used as the timestamp. However this timestamp can be lower than ```_toiler.lastToilDate``` when the USD value of landlord collateral drops thus making the users plot suddenly invalid.

## Impact
Users Munchable (NFT) is stuck on the contract permanently until the subtraction on line 281 stops underflowing.  

## Proof of Concept
Here we describe a scenario in which a users Munchable becomes bricked:
#1 - Landlord updates his lock on x timestamp
#2 - User stakes his NFT on landlords plot at x+1 timestamp
#3 - He farms his points at x+2 timestamp
#4 - The value of collateral drops and suddenly - user Munchable is on invalid plot
#5 - x will be used as timestamp and x+2 as ```_toiler.lastToilDate``` since thats the last time the user farmed.

User can not unstake/transfer his NFT because every time he tries to ```forceFarmPlots``` modifier will be called with a revert on line 281.

This issue persists until:
1. Landlord updated lock/unlock
2. Collateral gains in value thus making the plot valid again
