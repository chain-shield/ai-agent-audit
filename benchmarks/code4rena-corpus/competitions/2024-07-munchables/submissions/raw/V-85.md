# Vulnerability details

## Impact
This will cause confusion in contract variable data. Land that is not dirty may eventually become dirty. User's Schnibbles will be lost.

## Proof of Concept
background:
1. The function of [`transferToUnoccupiedPlot` ](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L199)is to move an NFT from the previous plot to another plot. This is achieved by modifying `plotId`.
2. `toilerState` represents some data of a certain NFT, where `toileterState.plotId` represents which plot this NFT is currently on.
3. In the `_farmPlots` function, [whether a piece of land is dirty is determined based on the landlord's pledge. If it is dirty, Schnibbles will not be updated after this time](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L258-L261).
```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```


The update of `toileterState.plotId` is missing in the `transferToUnoccupiedPlot` function.
Both users and landowners will lose Schnibbles if:
1. User A places the NFT on landowner B’s land No. 5.
2. User A moved the NFT from location No. 5 to location No. 2.
3. Landowner B withdrew some funds, causing his land No. 5 to be dirty.

At this time, since `toileterState.plotId` is still 5, in the following judgment, this NFT will become dirty. Both users and landowners lose Schnibbles after this time.

Since this seriously affects the contract's state variable updates and easily causes capital losses, I judge this to be high.
