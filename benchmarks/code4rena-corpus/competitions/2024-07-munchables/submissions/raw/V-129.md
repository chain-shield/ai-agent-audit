# Vulnerability details

## Impact

In `LandManager::_reconfigure` the state variables are set. REALM_BONUSES is set the following way:
        
```solidity
    REALM_BONUSES = configStorage.getSmallIntArray(StorageKey.RealmBonuses);
```

Which may result in setting negative numbers as REALM_BONUSES may have its values set as negative.

Later on, whenever `LandManager::_farmPlots(address)` is used the logic inside it uses the values of the REALM_BONUSES based on index:

```solidity
finalBonus =
                int16(
                    REALM_BONUSES[
                        (uint256(immutableAttributes.realm) * 5) +
                            uint256(landlordMetadata.snuggeryRealm)
                    ]
                ) +
                int16(
                    int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])
                );
```

As a result if one of the values inside REALM_BONUSES is negative and the index happens to be the one in which the REALM_BONUSES stores the negative value, this will cause the inaccuracy.

The `finalBonus` variable inside the `LandManager::_farmPlots(address)` is used for multiplication and causing the `schnibblesTotal` to be inaccurate too which is used for multiplication and substraction and so forth.

## Proof of Concept
1. Deploy and initialize 'LandManager' contract
2. Configure initial tax rates by calling relevant functions as usual
3. Call `LandManager::stakeMunchables` (has a forceFarmPlots modifier) with valid data or directly `LandManager::_farmPlots`

## Tools Used
Solidity

## Recommended Mitigation Steps
Make REALM_BONUSES of type `uint16[]` instead of `int16[]` and thus update in `LandManager::_reconfigure` 
```solidity
+    REALM_BONUSES = configStorage.getSmallUintArray(StorageKey.RealmBonuses);
-    REALM_BONUSES = configStorage.getSmallIntArray(StorageKey.RealmBonuses);
```
