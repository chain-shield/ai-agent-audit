# Vulnerability details

## Summary
The game has a feature where a player can earn schnibbles by petting other player's munchables. The `SnuggeryManager.pet()` function can be called once in 10 minutes at maximum (see code fragment below).

```javascript
File: src/managers/SnuggeryManager.sol
function pet(address _pettedOwner, uint256 _tokenId) external notPaused {
    // ... other logic

    if (pettedAttributes.lastPettedTime + 5 minutes > block.timestamp)
        revert PettedTooSoonError();
@>> if (_petterPlayer.lastPetMunchable + 10 minutes > block.timestamp)
        revert PetTooSoonError();

    // ... other logic

    _petterPlayer.unfedSchnibbles += petterSchnibbles;
@>> _petterPlayer.lastPetMunchable = uint32(block.timestamp);
    accountManager.updatePlayer(_petterMainAccount, _petterPlayer);

    // ... other logic
}
```

The value of `_petterPlayer.lastPetMunchable` is set to the current `block.timestamp`.

The problem arise when a rentor farming plots. Every time a rentor farming plots (`LandManager.farmPlots()`), the value of `lastPetMunchable` of the landlord is updated. See code below:

```javascript
File: src/managers/LandManager.sol
function _farmPlots(address _sender) internal {
    // ... other logic

    for (uint8 i = 0; i < staked.length; i++) {
        timestamp = block.timestamp;
        
        // ... other logic

        if (_getNumPlots(landlord) < _toiler.plotId) {
            timestamp = plotMetadata[landlord].lastUpdated;
            toilerState[tokenId].dirty = true;
        }

        // ... other logic

        landlordMetadata.unfedSchnibbles += schnibblesLandlord;
@>>     landlordMetadata.lastPetMunchable = uint32(timestamp);
        accountManager.updatePlayer(landlord, landlordMetadata);
        emit FarmedSchnibbles(
            _toiler.landlord,
            tokenId,
            _toiler.plotId,
            schnibblesTotal - schnibblesLandlord,
            schnibblesLandlord
        );
    }
    accountManager.updatePlayer(mainAccount, renterMetadata);
}
```

The value of `landlordMetadata.lastPetMunchable` is set to timestamp, where the timestamp is `block.timestamp` if the `_toiler.plotId` is in the valid plots range, otherwise the value depends on `plotMetadata[landlord].lastUpdated`.

Now the landlord can only pet other player's munchables 10 minutes after the plots farming. But if the rentor farm the plots again before the timestamp has passed, the waiting time for the landlord to be able to pet other player's munchables is extended again.

## Impact
The attacked landlord now can not pet other player's munchables to earn schnibbles.

## Proof of Concept
The attacker can do the following:

1. Attacker stake munchable to the victim landlord. `LandManager.stakeMunchable(victimLandlord, attackerTokenId, plotId)`

2. Attacker call `LandManager.farmPlots()` every 10 minutes or less.

3. When the landlord call `SnuggeryManager.pet(pettedOwner, tokenId)`, the function will revert with `PetTooSoonError()` error.

## Tools Used
Manual Review

## Recommended Mitigation
Consider to remove the line that update the landlord's `lastPetMunchable` in `LandManager._farmPlots()`. Farming and petting are two different concepts. The petting is controlled by the player who pet other player's munchable, on the other hand the farming is controlled by the rentor not the landlord. So it should not change the landlord's `lastPetMunchable` because the landlord has no control over the plots farming activity.
