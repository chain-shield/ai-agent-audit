# Vulnerability details

## Impact
The function doesn't perform as documented which could lead to  misuse.
unauthorized users can set their plot metadata arbitrarily.

## Proof of Concept
The function `triggerPlotMetadata()` has a comment indicating it should `"Only to be triggered by msg sender if they had locked before the land manager was deployed" `. However, the function's implementation does not check for this condition. Instead, it only checks if the plot metadata has been previously updated

Current behavior:

1. The function checks if the caller is registered.
2. It reverts if the plot metadata for the main account has been previously updated.
3. If not previously updated, it sets the plot metadata with the current timestamp and a default tax rate.

Expected behavior based on documentation:
The function should check if the caller had locked before the land manager was deployed, but this check is not implemented

## Tools Used
Manual Review
## Recommended Mitigation Steps
Update the function to include a check for whether the caller had locked before the land manager was deployed.
