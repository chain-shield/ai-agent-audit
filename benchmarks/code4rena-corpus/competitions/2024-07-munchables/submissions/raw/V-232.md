# Vulnerability details

**Impact**
When a user calls `transferToUnoccupiedSlot` it changes the `plotOccupied` mapping for the new and old plots. However it does not update the `plotId` or `dirty` fields of the `toilerState[tokenId]` mapping. Below are all the state changes made during `transferToUnoccupiedSlot`:
```solidity
        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });
```

Therefore because `toilerState[tokenId].plotId` and `toilerState[tokenId].dirty`are not updated, when calling `_farmPlots` to calculate users rewards it will use `toilerState[tokenId]` as shown here:
```solidity
    _toiler = toilerState[tokenId];
    if (_toiler.dirty) continue;
    landlord = _toiler.landlord;
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
```
This  means that previous `plotId` will be used and if the old plot was `dirty` the user won't be rewarded even if their actual plot is not. Conversely if the users actual plot should be flagged as `dirty` but the previous plot is not they could use this to continue to get rewards.  

**Proof Of Concept**
Consider the following scenario:
- Alice is staked in `LockManager` and has 4 plots available to stake in `LandManager`
- Bob originally stakes in `plotId` 3 (indexed from 0)
- When Alice's lock expires she chooses to relock a smaller amount, now only having 2 plots available
- Bob sees this and calls `transferToUnoccupiedSlot` to transfer to Alice's `plotId` 1 to ensure he keeps earning rewards
- However when during the `forceFarmPlots` modifier, Bob's token's `toilerState` will be updated to `dirty = true` when calculating rewards based on his current `plotId` (3)
- This state change will not be reset to false during the `transferToUnoccupiedSlot` logic
- When Bob later comes to claim his rewards in `_farmPlots` the `if (_toiler.dirty)` check will be true, breaking out of the loop before applying rewards, even though the plot should not be `dirty`

**Recommended Mitigation**
The `transferToUnoccupiedPlot` function should add the following state changes to ensure the `toilerState` mapping is updated correctly:
```diff
    function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        // -- snip --

+       toilerState[tokenId].plotId = plotId;
+       toilerState[tokenId].dirty = false;
        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```
