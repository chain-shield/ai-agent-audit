# Vulnerability details

## Impact
Failing to identify the dirty plot when the `_toiler.plotId` = `_getNumPlots(landlord)` in the `_farmPlots()`. This can cause the  NFT in a dirty plot to gain undeserved  schnibbles.

## Proof of Concept

In the `_farmPlots()`  we are checking whether the `plotId` of the each NFT staked is `dirty` by checking whether it is greater than `_getNumPlots(landlord)`.

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L258-L261
```solidity
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
```
If `x` = `_getNumPlots(landlord)` , that means plots are calculated from `0` to `x - 1`.And `plotId==x` is invalid and hence that plotId is considered as `dirty`.

But in case if `_toiler.plotId == _getNumPlots(landlord)` =>  that  plotId  is actually not in the plots allocated to the landlord.
So it should make the toilerstate to dirty.
But instead , due to the lack of equality check ,  function failed to mark it as dirty.

## Recommended Mitigation Steps
```solidity
    if (_getNumPlots(landlord) <= _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
```
