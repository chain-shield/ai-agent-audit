# Vulnerability details

## Impact 
The `stakeMunchable` function in the `LandManager.sol` contract fails to properly check authorization conditions. Specifically, when `!munchNFT.isApprovedForAll(mainAccount, address(this))` or `munchNFT.getApproved(tokenId) != address(this)` is true, it does not revert an error.

## Proof of Concept
The `stakeMunchable` function in the `LandManager.sol` contract checks authorization using the condition `!munchNFT.isApprovedForAll(mainAccount, address(this)) && munchNFT.getApproved(tokenId) != address(this)`. This means that an error is revert only when both conditions are simultaneously true. Therefore, if either `!munchNFT.isApprovedForAll(mainAccount, address(this))` or `munchNFT.getApproved(tokenId) != address(this)` is true (but not both), no error is revert, and the user can still execute the `stakeMunchable` function. This results in the authorization check being ineffective.
