# Vulnerability details

## Impact
Every call to `LandManager::farmPlots(...)` will update the plot's landlord `lastPetMunchable` timestamp, blocking landlords from being able to use the `SnuggeryManager::pet(...)` functionality.

## Proof of Concept
The `LandManager.sol` contract allows users to stake their munchables onto other players' plots. When a munchable is staked, users can regularly invoke the `farmPlots(...)` function to farm schnibble rewards based on the time they've staked (landlords also get an amount of these schnibbles). However, by doing so, they will constantly update the `lastPetMunchable` for the landlord:

```solidity
function _farmPlots(address _sender) internal {
   
    __SNIP__    
        landlordMetadata.unfedSchnibbles += schnibblesLandlord;
@>      landlordMetadata.lastPetMunchable = uint32(timestamp);
        accountManager.updatePlayer(landlord, landlordMetadata);
        emit FarmedSchnibbles(
            _toiler.landlord,
            tokenId,
            _toiler.plotId,
            schnibblesTotal - schnibblesLandlord,
            schnibblesLandlord
        );
    }
    accountManager.updatePlayer(mainAccount, renterMetadata);
}
```

Because of this, landlords who have staked munchables on their plots will not be able to consistently utilize the `SnuggeryManager::pet(...)`, as it will always revert:

```solidity
function pet(address _pettedOwner, uint256_tokenId) external notPaused {
    __SNIP__

    if (pettedAttributes.lastPettedTime + 5 minutes > block.timestamp)
        revert PettedTooSoonError();
@>  if (_petterPlayer.lastPetMunchable + 10 minutes > block.timestamp)
        revert PetTooSoonError();

    __SNIP__
}
```

To make matters even worse, a single user can stake munchables on different landlords' plots, meaning that a single user can block multiple landlords with a single call to `farmPlots(...)`. If there is a malicious user, he/she can time these calls to fully block landlords from being able to pet munchables, where [petting](https://munchables.gitbook.io/munchables/explorers-guide/glossary/petting) is considered a very important part of the munchable experience.

Disclaimer: The test below shows an example for one user and one landlord to show the general idea, the impact can be quite bigger with multiple users and multiple landlords.

The coded `POC` below can be added in the `LandManager` test suit (I've worked with the `unstakeMunchable.test.ts` and have created two new users Naruto and Sasuke):
