# Lines of code

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L199


# Vulnerability details

## Overview
The ```toilerState.plotId``` is not set in the ```transferToUnoccupiedPlot(uint256 tokenId, uint256 plotId)``` function. This would lead to a DoS when another user would stake on a specific plot.

## Proof of Concept
Below is a step-by-step PoC explaining the issue in detail.

Let's suppose a user X stakes one of his Munchables on Y's plot with plotId = 9. Let us assume Y has 20 plots in total. X would do this by:

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L131

```solidity
    function stakeMunchable(
        address landlord,
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        if (landlord == mainAccount) revert CantStakeToSelfError();
        if (plotOccupied[landlord][plotId].occupied)
            revert OccupiedPlotError(landlord, plotId);
        if (munchablesStaked[mainAccount].length > 10)
            revert TooManyStakedMunchiesError();
        if (munchNFT.ownerOf(tokenId) != mainAccount)
            revert InvalidOwnerError();

        uint256 totalPlotsAvail = _getNumPlots(landlord);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        if (
            !munchNFT.isApprovedForAll(mainAccount, address(this)) &&
            munchNFT.getApproved(tokenId) != address(this)
        ) revert NotApprovedError();
        munchNFT.transferFrom(mainAccount, address(this), tokenId);

        plotOccupied[landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        munchablesStaked[mainAccount].push(tokenId);
        munchableOwner[tokenId] = mainAccount;

        toilerState[tokenId] = ToilerState({
            lastToilDate: block.timestamp,
            plotId: plotId,
            landlord: landlord,
            latestTaxRate: plotMetadata[landlord].currentTaxRate,
            dirty: false
        });

        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```

Now, X decides to transfer his Munchable from plot 9 to plot 11, assuming plot 11 is unoccupied at present. So, X calls:

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L199

```solidity
    function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
        uint256 oldPlotId = _toiler.plotId;
        uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
        if (plotOccupied[_toiler.landlord][plotId].occupied)
            revert OccupiedPlotError(_toiler.landlord, plotId);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```

As can be seen, there is no set as the following in the transfer function:

```solidity
toilerState[tokenId].plotId = plotId;
```

This means that the protocol seems to think that X has his Munchable on plot Id 11. However, X's toiler state still points to plot Id 9. 

Moreover, ```plotOccupied``` has:

```solidity
plotOccupied[Y][9].occupied = false;
plotOccupied[Y][9].tokenId = 0;

plotOccupied[Y][11].occupied = true;
```

Let us suppose X again calls the ```transferToUnoccupiedPlot(uint256 tokenId, uint256 plotId)``` function with ```plotId``` as 9. Now, the ```plotOccupied``` would have:

```solidity
plotOccupied[Y][9].occupied = true;
```


And, the toiler state of X's Munchable would have:

```solidity
            lastToilDate: block.timestamp,
            plotId: 9,
            landlord: Y,
            latestTaxRate: {whatever set by the landlord},
            dirty: false
```

However, the ```plotOccupied``` also has:

```solidity
plotOccupied[Y][11].occupied = true;
```

Now, no other staker would be able to stake on Y's plot 11 as in the stake function:

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L138

```solidity
        if (plotOccupied[landlord][plotId].occupied)
            revert OccupiedPlotError(landlord, plotId);
```

This would lead to a DoS for other stakers. And there would be no way to remove it.

## Severity
Impact: The impact is a permanent DoS for other users who would want to stake on a specific plot. This means the availability of a component of a protocol is impacted. So, the impact is Medium.

Likelihood: The likelihood seems High as the functions involved can be called by anyone and they would be called quite frequently.

Therefore, the severity is Medium.
