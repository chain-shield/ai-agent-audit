# Vulnerability details

## Impact
The function `transferToUnoccupiedPlot` never changes the `plotId` in the `toilerState`. This leads to stale data in the contract.

```solidity
function transferToUnoccupiedPlot(
	uint256 tokenId,
	uint256 plotId
) external override forceFarmPlots(msg.sender) notPaused {
	(address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
	ToilerState memory _toiler = toilerState[tokenId];
	uint256 oldPlotId = _toiler.plotId;
	uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
	if (_toiler.landlord == address(0)) revert NotStakedError();
	if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
	if (plotOccupied[_toiler.landlord][plotId].occupied)
		revert OccupiedPlotError(_toiler.landlord, plotId);
	if (plotId >= totalPlotsAvail) revert PlotTooHighError();

	toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
		.currentTaxRate;
	plotOccupied[_toiler.landlord][oldPlotId] = Plot({
		occupied: false,
		tokenId: 0
	});
	plotOccupied[_toiler.landlord][plotId] = Plot({
		occupied: true,
		tokenId: tokenId
	});

	emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
	emit FarmPlotTaken(toilerState[tokenId], tokenId);
}
```

This issue leads to stale data in `toilerState` and also to `plotOccupied[_toiler.landlord][_toiler.plotId]` when the function `unstakeMunchable` is called after that.

Also, `_farmPlots` will not work correctly as this check:
```solidity
if (_getNumPlots(landlord) < _toiler.plotId) {
    timestamp = plotMetadata[landlord].lastUpdated;
    toilerState[tokenId].dirty = true;
}
```    
will be wrong.

## Proof of Concept
Attack vectors caused by this issue: 

**Manipulating Reward Calculations** 
By ensuring the `plotId` remains stale, an attacker can manipulate the `_farmPlots` function to use incorrect timestamps, leading to unfair reward calculations. 

Steps:

1. Stake a toiler and perform operations that prevent `plotId` from being updated.
2. The `_farmPlots` function will use incorrect timestamps, resulting in inflated or deflated `schnibblesTotal` and `schnibblesLandlord`.

**Monopolising All But One `plotIds`** 
Assume the following initial state:

- There are 5 plots available for staking (plot IDs 0 to 4).
- The user has one toiler (tokenId = 1) initially staked at `plotId` 0.
- The `toilerState` for `tokenId` 1 is as follows:
```solidity
toilerState[1] = ToilerState({
    lastToilDate: <timestamp>,
    plotId: 0,
    landlord: <landlord_address>,
    latestTaxRate: <tax_rate>,
    dirty: false
});
```
- The `plotOccupied` mapping is as follows:
```solidity
plotOccupied[<landlord_address>][0] = Plot({
    occupied: true,
    tokenId: 1
});
```

Steps:

1. First Transfer to Plot 1    
	- The `toilerState[1].plotId` remains 0;
	- `plotOccupied[<landlord_address>][0]` is set to false;
	- `plotOccupied[<landlord_address>][1]` is set to true.
2. Second Transfer to Plot 2:
    - The `toilerState[1].plotId` remains 0;
    - `plotOccupied[<landlord_address>][0]` is set to false;
    - `plotOccupied[<landlord_address>][2]` is set to true;
    - `plotOccupied[<landlord_address>][1]` remains true.
3. Third Transfer to Plot 3
    - The `toilerState[1].plotId` remains 0;
    - `plotOccupied[<landlord_address>][0]` is set to false;
    - `plotOccupied[<landlord_address>][3]` is set to true;
    - `plotOccupied[<landlord_address>][1]` remains true;
    - `plotOccupied[<landlord_address>][2]` remains true.
4. Fourth Transfer to Plot 4:
    - The `toilerState[1].plotId` remains 0;
    - `plotOccupied[<landlord_address>][0]` is set to false;
    - `plotOccupied[<landlord_address>][4]` is set to true;
    - `plotOccupied[<landlord_address>][1]` remains true;
    - `plotOccupied[<landlord_address>][2]` remains true;
    - `plotOccupied[<landlord_address>][3]` remains true.
5. All future calls that have a check with the `plotOccupied` mapping will revert if the `plotId` is not equal to 0.
