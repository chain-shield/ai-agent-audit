# Vulnerability details

## Impact
The `LandManager` contract allows landlords to update tax rates without users' knowledge, potentially leading to unexpected and higher fees for users who have staked their Munchables. This can result in financial losses for users and undermine trust in the system.

The impact is significant because:

1. Users may be charged higher rates than expected when unstaking.
2. Transferring to a new plot can result in unexpected tax rate changes.
3. Users with multiple staked Munchables may face higher rates on all their stakes when interacting with just one.

## Proof of Concept
There are several scenarios where this could be possible:

1. ***Front-running stakeMunchable:*** A landlord can front-run a user's `stakeMunchable` transaction by calling `updateTaxRate`:
```
function updateTaxRate(uint256 newTaxRate) external override notPaused {
    // ... (code omitted for brevity)
    plotMetadata[landlord].currentTaxRate = newTaxRate;
}
```
This new rate is then set in the `stakeMunchable` function:
```
toilerState[tokenId] = ToilerState({
    // ... (other fields)
    latestTaxRate: plotMetadata[landlord].currentTaxRate,
});
```
When the user later unstakes, they'll be charged at this higher rate:
```solidity
function _farmPlots(address _sender) internal {
    // ...
schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;
}
```

2. ***Exploiting transferToUnoccupiedPlot:*** The landlord can change the tax rate just before a user calls `transferToUnoccupiedPlot` function. Similar to the first scenario, the landlord calls `updateTaxRate`, then the user calls the `transferToUnoccupiedPlot` function, and the state will be updated:
```
function transferToUnoccupiedPlot(uint256 tokenId, uint256 plotId) external override forceFarmPlots(msg.sender) notPaused {
    // ... (code omitted for brevity)
    toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord].currentTaxRate;
}
```
When the user later unstakes, they'll be charged at this higher rate.

3. ***Affecting multiple staked Munchables:*** If a user has more than one Munchable token, even if the landlord doesn't update the tax rate for the first token, the `forceFarmPlots` modifier used in the `stakeMunchable`, `unstakeMunchable`, and `transferToUnoccupiedPlot` functions means any interaction with one Munchable will update the rates for all of a user's staked Munchables:
```
for (uint8 i = 0; i < staked.length; i++) {
    // ... (code omitted for brevity)
    toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord].currentTaxRate;
}
```
