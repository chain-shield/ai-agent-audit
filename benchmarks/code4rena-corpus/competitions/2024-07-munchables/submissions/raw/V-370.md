# Vulnerability details

## Impact

Many errors can occur due to the way the `LandManager.sol` contract updates/reconfigures contract state variables (specifically tax rates). For example, the current `landlord.currentTaxRate` may be different from the `latestTaxRate` for a specific toiler state, or the `landlord.currentTaxRate` may be less than `MIN_TAX_RATE` or greater than `MAX_TAX_RATE`.

The `LandManager.sol` contract in the Munchables Protocol involves complex state management, particularly concerning tax rates and other configuration settings. Several potential bugs and issues arise from the way the contract updates and reconfigures these state variables. These include inconsistent tax rates, tax rates out of bounds, mismanagement of the `dirty` flag, and incorrect farming calculations due to timestamp issues.

These issues can lead to incorrect reward calculations, unfair reward distributions, inconsistent states, and potential violations of the protocol's economic constraints. The impact includes:

- Incorrect schnibbles reward calculations during farming, staking, and unstaking operations.
- Unfair reward distributions due to tax rates being set out of bounds.
- Inconsistent state management leading to potential reward discrepancies.
- Reduced trust in the protocol's fairness and reliability.

## Proof of Concept

### 1. Inconsistent Tax Rates

**Issue**: The current `landlord.currentTaxRate` may differ from the `latestTaxRate` stored in the `toilerState`.

**Impact**: This inconsistency can lead to incorrect reward calculations during farming, staking, and unstaking operations.

**Example Scenario**:

- A landlord updates the tax rate after a Munchable has been staked.
- The `latestTaxRate` in the `toilerState` remains outdated, causing incorrect calculations for rewards and distributions.

**Code Reference**: [LandManager.sol#updateTaxRate()](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L92-L101)

```solidity
function updateTaxRate(uint256 newTaxRate) external override notPaused {
    (address landlord, ) = _getMainAccountRequireRegistered(msg.sender);
    if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE)
        revert InvalidTaxRateError();
    if (plotMetadata[landlord].lastUpdated == 0)
        revert PlotMetadataNotUpdatedError();

    uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
    plotMetadata[landlord].currentTaxRate = newTaxRate;

    // Missing: Harvest rewards before updating the tax rate
    for (uint256 plotId = 0; plotId < _getNumPlots(landlord); plotId++) {
        Plot memory plot = plotOccupied[landlord][plotId];
        if (plot.occupied) {
            accountManager.forceHarvest(toilerState[plot.tokenId].landlord);
        }
    }

    // Update all toilerStates for this landlord
    for (uint256 plotId = 0; plotId < _getNumPlots(landlord); plotId++) {
        Plot memory plot = plotOccupied[landlord][plotId];
        if (plot.occupied) {
            toilerState[plot.tokenId].latestTaxRate = newTaxRate;
        }
    }

    emit TaxRateChanged(landlord, oldTaxRate, newTaxRate);
}

```

### 2. Tax Rate Out of Bounds

**Issue**: The `landlord.currentTaxRate` may be set to a value less than `MIN_TAX_RATE` or greater than `MAX_TAX_RATE`.

- A landlord accidentally or maliciously sets a tax rate beyond the allowed bounds.
- The contract does not enforce the bounds, causing unintended behavior in the reward calculations.

- Rewards continue to be calculated based on outdated or invalid data.

### 4. Incorrect Farming Calculations Due to Timestamp Issues

**Issue**: The use of `plotMetadata[landlord].lastUpdated` as a fallback when the `dirty` flag is set can cause incorrect farming reward calculations.

**Impact**: This can lead to stakers receiving fewer rewards than they should.

- When `toilerState.dirty` is set, rewards are calculated based on a potentially shorter or incorrect time period.

## Recommended Mitigation Steps

### 1. Fix for Inconsistent Tax Rates

**Mitigation**: Update the `toilerState.latestTaxRate` whenever the `landlord.currentTaxRate` changes and ensure it is used consistently in all relevant calculations.

