# Vulnerability details

## Vulnerability details
When a user stakes munchable then currentTaxRate of landlord is set to latestTaxRate of toilerState
```solidity
toilerState[tokenId] = ToilerState({
            lastToilDate: block.timestamp,
            plotId: plotId,
            landlord: landlord,
        @>  latestTaxRate: plotMetadata[landlord].currentTaxRate,
            dirty: false
        });
```
There can be situation where plotMetadata of landlord is not triggered because they had locked before the land manager was deployed, which means landlord has locked his position in LockManager but his currentTaxRate in plotMetadata is 0(default value) as its not triggered
```solidity
 // Only to be triggered by msg sender if they had locked before the land manager was deployed
    function triggerPlotMetadata() external override notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        if (plotMetadata[mainAccount].lastUpdated != 0)
            revert PlotMetadataTriggeredError();
        plotMetadata[mainAccount] = PlotMetadata({
            lastUpdated: block.timestamp,
            currentTaxRate: DEFAULT_TAX_RATE
        });

        emit UpdatePlotsMeta(mainAccount);
    }
```
Now the problem is, a malicious user can take advantage of the above situation to stake munchable with a landlord whose plotMetadata is not triggered, which means latestTaxRate of user in toilerState will be 0 ie default value of plotMetadata[landlord].currentTaxRate

## Impact
User will be able avoid taxRate & landlord will lose `unfedSchnibbles`, which is calculated in _farmPlots() using toilerState.latestTaxRate
```solidity
schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;
landlordMetadata.unfedSchnibbles += schnibblesLandlord;
```
