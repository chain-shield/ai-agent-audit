# Vulnerability details

## Impact
[transferToUnoccupiedPlot](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L199-L226) misses to change the old `toilerState[tokenId].plotId` to the new `plotId`, causing a mess in plots and rewards. The damage can be summarized into:
1. Landlords get their plots locked
2. Users can clear already occupied plots, bricking other users' NFTs

## Proof of Concept
[transferToUnoccupiedPlot](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L199-L226) can be used by a user to transfer his `tokenId` to another plot of the same landlord. 

However when setting the new parameters the function misses one - `toilerState[tokenId].plotId`. On a second change (B -> C), when moving A -> B -> C it won't erase `plotOccupied[landlord][B]` making plot B count as filled, even thought the NFT is now on plot C.

---

When we break the above down, for simplex understanding, we can see that when moving the NFT from plot A to B, since `toilerState[tokenId].plotId` is not set to B, it will remain as A.

Then when moving from B to C, since `toilerState[tokenId].plotId == A` the system will clear A (even thought A was already empty) and move on, without clearing plot B (as it should):

```solidity
   ToilerState memory _toiler = toilerState[tokenId];

   // plot A
   uint256 oldPlotId = _toiler.plotId; 

   ...

   // plotOccupied[landlord][A] = Plot({occupied: false, tokenId: 0});
   plotOccupied[_toiler.landlord][oldPlotId] = Plot({occupied: false, tokenId: 0});

   // plotOccupied[landlord][C] = Plot({occupied: true, tokenId: tokenId});
   plotOccupied[_toiler.landlord][plotId] = Plot({occupied: true, tokenId: tokenId});
```

This can be used by malicious users to fill the landlords plots, lowering his reward generation. It can also accidentally happen, which makes the issue even more dangerous.

Note: Another impact of this issue is that if user2 moves to the previously occupied plot, and user1 unstakes, then the unstake will clear user2 plot.


## Tools Used
Manual review

## Recommended Mitigation Steps
Make sure the `plotId` is updated to the new one:

```diff
     toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord].currentTaxRate;
+    toilerState[tokenId].plotId = plotId;

     emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
     emit FarmPlotTaken(toilerState[tokenId], tokenId);
```
