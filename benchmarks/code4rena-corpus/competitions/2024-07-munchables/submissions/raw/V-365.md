# Vulnerability details

## Impact

The `LandManager.sol` contract in the Munchables Protocol contains a bug related to the management of the `toilerState[tokenId].dirty` flag and the calculation of staking rewards. This bug arises when the number of available plots (`totalPlotsAvail`) for a landlord decreases, causing the `toilerState[tokenId].dirty` flag to be set to `true`. This leads to the `lastToilDate` being updated to an earlier `lastUpdated` timestamp from the plot metadata instead of the current timestamp. As a result, users can lose a portion of their accrued rewards due to this retroactive adjustment.

When the `dirty` flag is set and the `lastToilDate` is adjusted to an earlier timestamp, users effectively lose out on the rewards they have accrued during the actual staking period. This is particularly unfair to users who have staked their Munchables for extended periods, as their rewards are reduced based on a past timestamp. The bug undermines the trust and satisfaction of users, affects a broad user base, and can harm the protocol's reputation for fairness and integrity.

## Proof of Concept

[`LandManager.sol#_farmPlots()`](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L232-L310) function:

```solidity
function _farmPlots(address _sender) internal {
    (address mainAccount, MunchablesCommonLib.Player memory renterMetadata) = _getMainAccountRequireRegistered(_sender);

    uint256[] memory staked = munchablesStaked[mainAccount];
    MunchablesCommonLib.NFTImmutableAttributes memory immutableAttributes;
    ToilerState memory _toiler;
    uint256 timestamp;
    address landlord;
    uint256 tokenId;
    int256 finalBonus;
    uint256 schnibblesTotal;
    uint256 schnibblesLandlord;
    uint256 dirtyTimestamp;

    for (uint8 i = 0; i < staked.length; i++) {
        timestamp = block.timestamp;
        tokenId = staked[i];
        _toiler = toilerState[tokenId];
        landlord = _toiler.landlord;

        uint256 totalPlotsAvail = _getNumPlots(landlord);
        if (_toiler.plotId >= totalPlotsAvail) {
            dirtyTimestamp = plotMetadata[landlord].lastUpdated;
            toilerState[tokenId].dirty = true;
        } else {
            dirtyTimestamp = timestamp;
            toilerState[tokenId].dirty = false;
        }

        (, MunchablesCommonLib.Player memory landlordMetadata) = _getMainAccountRequireRegistered(landlord);

        immutableAttributes = nftAttributesManager.getImmutableAttributes(tokenId);
        finalBonus = int16(REALM_BONUSES[(uint256(immutableAttributes.realm) * 5) + uint256(landlordMetadata.snuggeryRealm)]) +
                     int16(int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)]));

        // Calculate rewards up to the dirty timestamp
        schnibblesTotal = (dirtyTimestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
        schnibblesTotal = uint256((int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100);
        schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;

        // Update rewards
        renterMetadata.unfedSchnibbles += (schnibblesTotal - schnibblesLandlord);
        landlordMetadata.unfedSchnibbles += schnibblesLandlord;

        // If the plot is dirty, update the last toil date to the dirty timestamp and calculate rewards from there to now
        if (_toiler.dirty) {
            _toiler.lastToilDate = dirtyTimestamp;
            schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
            schnibblesTotal = uint256((int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100);
            schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;

            renterMetadata.unfedSchnibbles += (schnibblesTotal - schnibblesLandlord);
            landlordMetadata.unfedSchnibbles += schnibblesLandlord;
        }

        toilerState[tokenId].lastToilDate = timestamp;
        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord].currentTaxRate;

        accountManager.updatePlayer(landlord, landlordMetadata);
        emit FarmedSchnibbles(_toiler.landlord, tokenId, _toiler.plotId, schnibblesTotal - schnibblesLandlord, schnibblesLandlord);
    }
    accountManager.updatePlayer(mainAccount, renterMetadata);
}

```

**Example Scenario**:

1. A user stakes a Munchable NFT token, and initially, `toilerState[tokenId].dirty = false`.
2. The user accrues rewards over time.
3. Before unstaking, the `totalPlotsAvail` for the landlord decreases, making the current plot ID invalid.
4. The `toilerState[tokenId].dirty` flag is set to `true`.
5. The `_farmPlots` function adjusts the `lastToilDate` to the `lastUpdated` timestamp from the plot metadata, which can be significantly in the past.
6. This results in the user losing rewards accrued from the actual staking period to the `lastUpdated` timestamp.

## Tools Used

- Manual Review

## Recommended Mitigation Steps

1. **Record Accrued Rewards Before Adjustment**:
    - Calculate and record the rewards accrued up to the current timestamp before updating the `lastToilDate` to an earlier `lastUpdated` timestamp.
2. **Split Reward Calculation**:
    - Implement logic to split the reward calculation into two parts: rewards accrued before the plot became dirty and rewards accrued after. This ensures users do not lose the rewards they earned during the clean period.
