# Vulnerability details

## Vulnerability Details

**transferToUnoccupiedPlot** provides functionality such that a particular token id (the Munchable) can be transferred to a new plot id which belongs to the same landlord as long as the plot is not occupied. However, the function seems to **only reflect latestTaxRate change** to the toilerState struct associated with the tokenId moved **and does not update new plot id**.

## Impact

The consequence of this fact is that the next time forceFarmPlots modifier is triggered (farming rewards), the calculations are going to use the old plot id of the affected toiler which would eventually lead to wrong calculations due to the possibility of the wrong timestamp being used (in case if statement on line 258 gets triggered)

## Proof of Concept
1. A user stakes a Munchable to a particular plotId
2. later, user decides to transfer the Munchable to an unoccpied plotId (transferToUnoccupiedPlot)
3. User stakes another Munchable, or unstakes a Munchable -> forceFarmPlots modifier gets triggered & farming eventually uses wrong calculations

Manual Review

## Recommended Mitigation Steps

Update toilerState.plotId = newPlotId in transferToUnoccupiedPlot function
