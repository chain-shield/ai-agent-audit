# Vulnerability details

The `transferToUnoccupiedPlot` function is responsible for users to move a tokenId (representing a toiler or munchable) from one plot of land to another within the same landlord's estate,. However the function check that the new plotId should not be occupied anymore. And then it sets landlord's oldPlotId as not occupied that means it is no longer usable to farm rewards with current tokenId(Munchable). 

```javascript
 function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
        uint256 oldPlotId = _toiler.plotId;
        uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
        if (plotOccupied[_toiler.landlord][plotId].occupied)
            revert OccupiedPlotError(_toiler.landlord, plotId);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```
But the problem is here that the function does not update the toilerState for any munchable, which will always consist oldPlotId not the new one. Resulting if they do `unstakeMunchable`  then the rewards for landlord & renter will be generating in a wrong plotId(which is no longer occupied anymore).

## Impact
Even if the new plotId is occupied, it will always farm rewards in a old plotId. Since the old plotId is no longer occupied for any landlord's munchable , we can re-stake with that plotId again for same landlord with new munchables.
It means the different munchable can be staked multiple times with same landlord and same plotId.

## Recommended Mitigation Steps
Consider updating the plotId on munchable toilerState in the `transferToUnoccupiedPlot` function.
```diff
+  toilerState[tokenId].plotId = plotId
```
