# Vulnerability details

## Impact
All plots of land belonging to a landlord can be DoS and made unusable by any ```munchNFT``` owner, because ```toilerState[tokenId]``` is not updated upon transferring a ```tokenId``` to an unoccupied ```plotId```.

I suggest a HIGH severity as this renders the whole staking mechanism potentially unusable for all munchNFT owners.

## Proof of Concept

Let us take a look at the [```transferToUnoccupiedPlot```](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L199-L226) function

```javascript
    function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
        uint256 oldPlotId = _toiler.plotId;
        uint256 totalPlotsAvail = _getNumPlots(_toiler.landlord);
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();
        if (plotOccupied[_toiler.landlord][plotId].occupied)
            revert OccupiedPlotError(_toiler.landlord, plotId);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```

In the above code, only the ```latestTaxRate``` of the ```toilerStatep[tokenId]``` is updated while the its ```plotId``` is not updated. 

Let's now take a look at the [```unstakeMunchable```](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L173-L197) function below

```javascript
    function unstakeMunchable(
        uint256 tokenId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
        if (_toiler.landlord == address(0)) revert NotStakedError();
        if (munchableOwner[tokenId] != mainAccount) revert InvalidOwnerError();

        plotOccupied[_toiler.landlord][_toiler.plotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        toilerState[tokenId] = ToilerState({
            lastToilDate: 0,
            plotId: 0,
            landlord: address(0),
            latestTaxRate: 0,
            dirty: false
        });
        munchableOwner[tokenId] = address(0);
        _removeTokenIdFromStakedList(mainAccount, tokenId);

        munchNFT.transferFrom(address(this), mainAccount, tokenId);
        emit FarmPlotLeave(_toiler.landlord, tokenId, _toiler.plotId);
    }
```

We see above that we fetch the ```_toiler.plotId``` for this given ```tokenId``` before setting its ```occupied``` parameter to 0. However, if the NFT was previously transferred to an unoccupied plot, the initial ```Plot``` was already set to have ```occupied=false```, and the new ```plotId``` will never be set to ```false```, even after unstaking.

Let us consider the below scenario.

```Bob``` is a ```munchNFT``` owner. ```Alice``` is a landlord with two ```plotIds``` 1 and 2, both unoccupied.

1. ```Bob``` uses ```stakeMunchable``` to stake his NFT with ```tokenId``` 1 on ```Alice```'s plot with ```plotId``` 1.
2. ```Bob``` uses ```transferToUnoccupiedPlot``` to transfer his NFT from plot 1 to plot 2. This goes through as plot 2 is unoccupied. Plot 1 is set to ```occupied=false``` and plot 2 is set to ```occcupied=true```.
3. ```Bob``` uses ```unstakeMunchable``` to unstake his NFT. As the ```toilerState``` of ```tokenId``` 1 is still pointing to ```plotId``` 1, plot 1 is set to ```occupied=false``` a second time, which has no impact. Howver plot 2 is still set to ```occupied=true``` and will be unusable forever as no one will ever be able to stake their NFT on this plot. We cannot call ```transferToUnoccupiedPlot``` on the previously used ```tokenId``` either even if ```Bob``` decided to stake it again, as the toiler would still point to the initial ```plotId```.

Note that ```Bob``` only needs 1 NFT to DoS every unoccupied plot as he could keep calling ```transferToUnoccupiedPlot```, as the ```oldPlotId``` will always point to the initial ```plotId```, he could then "transfer" the same NFT to every unoccupied ```plotId``` and render the whole ```landlord``` unusable by any other user.
