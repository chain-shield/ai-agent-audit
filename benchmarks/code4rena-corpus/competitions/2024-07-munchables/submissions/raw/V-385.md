# Vulnerability details

## Impact
If there are duplicate tokenId in the `munchablesStaked` mapping for an account then `_removeTokenIdFromStakedList` function will only remove the first occurence of the tokenId from the list. Ideally it should check for duplicate tokenIds in the array and remove all occurences from the list.

## Tools Used
```
 function _removeTokenIdFromStakedList(
        address mainAccount,
        uint256 tokenId
    ) internal {
        uint256 stakedLength = munchablesStaked[mainAccount].length;
        bool found = false;
        for (uint256 i = 0; i < stakedLength; i++) {
            if (munchablesStaked[mainAccount][i] == tokenId) {
                munchablesStaked[mainAccount][i] = munchablesStaked[
                    mainAccount
                ][stakedLength - 1];
                found = true;
                munchablesStaked[mainAccount].pop();
                break;
            }
        }

        if (!found) revert InvalidTokenIdError();
    }
```

In above code when the tokenId matches with munchablesStaked[mainAccount][i] then the last element is replaced with the ith element and then the last element is popped and then a break. But for duplicate values this logic will not work. 

## Recommended Mitigation Steps
A new temporary list can be created where the elements not equal to tokenId can be pushed. Then this temporary list is assigned to the mapping with the landlord. This way you can deal with duplicates in O(n) complexity.

```
uint256[] memory uniqueTokens;
for(uint256 i = 0; i < stakedLength; i++){
   if(munchablesStaked[mainAccount][i] != tokenId){
                uniqueTokens.push(munchablesStaked[mainAccount][i]);
    }
}
munchablesStaked[mainAccount] = uniqueTokens;      
```
