# Vulnerability details

## Impact
When a user stakes on a `plot Id` and they decide to transfer to another `unoccupied plot Id`, when the user `unstakes` from the plot Id they moved to they render that plot Id associated with the landlords main account  `useless(meaning no other user can stake to that plotId) forever`, regardless of if the landlord `locks or unlocks`.

E.g user stakes their token Id on `plot Id 4` and transfers to `plot Id 6`. Once the user `unstakes` from `plotId 6`. No other user can stake on that landlords `plot Id 6` ever.

Landlord `locks tokens` in order to have a certain number of plots that they can use to `earn schnibbles` from users staking in them. Users transfering their token Id from their current plot Id to unoccupied plot Id's are `natural phenomena` that should happen in the LandManager contract `without consequence`. If this happens over and over again due to the natural activity of transferring from plot to plot, almost all the lands owned by the landlords main account can be rendered useless.

## Proof of Concept
This occurs due to the improper updating of the toiler state plotId in the `transferToUnoccupiedPlot` function.

We'll take a scenario of a userA staking their `token Id 3` on `landlord: Alice` `plot 5` and then transferring to `plot 6`.
Then userB or any user not being able to stake on `plot 6`

We'll keep track of the following things we need after every action:
toilerState[tokenId].plotId
plotOccupied[landlord][plotId].occupied

- userA stakes `tokenId 3` on landord Alice `plot Id 5` by calling `stakeMunchable`

 toilerState[3].plotId = 5
 plotOccupied[Alice][5].occupied = true

- userA transfers`tokenId 3` on landord Alice from `plot Id 5` to unoccupied `plot Id 6` by calling `transferToUnoccupiedPlot`

 toilerState[3].plotId = 5
 plotOccupied[Alice][5].occupied = false
 plotOccupied[Alice][6].occupied = true

The toiler state plot Id isn't updated on the transferToUnoccupiedPlot to the new plot its being transferred to

- userA unstakes `tokenId 3` on landord Alice from `plot Id 6` by calling `unstakeMunchable`

  This is the code that updates the occupied status for the plot Id 
 `plotOccupied[_toiler.landlord][_toiler.plotId] = Plot({occupied: false, tokenId: 0});`

  Since the `toiler.landlord = alice` & `the toiler.plotId = 5`
  **This is because on transferring the plot the toiler plot Id wasn't updated**
  This is what happens even though
  plotOccupied[Alice][5].occupied = false
  plotOccupied[Alice][6].occupied = true // this isn't updated at all
  toilerState[3].plotId = 0

- userB tries to stake `tokenId 21` on landord Alice `plot Id 6` by calling `stakeMunchable`
  
  plotOccupied[Alice][6].occupied = true

  userB or any other user `always reverts` because even though `userA has unstaked` from `plot Id 6`
  The plot Id 6 will always show as `occupied = true`

  A check is always made before a munchable is staked to a plot Id which is
  `if (plotOccupied[landlord][plotId].occupied) {
      revert OccupiedPlotError(landlord, plotId);
   }`
  Meaning this check would always revert for affected plots.
  
## Recommended Mitigation Steps
Updating the toiler state plot Id in the `transferToUnoccupiedPlot` function.
