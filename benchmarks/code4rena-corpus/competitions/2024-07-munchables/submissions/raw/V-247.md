# Vulnerability details

## Impact
The LandManager contract has a vulnerability that allows for "Continuous Plot Hopping for Attribute Farming." This issue is primarily due to the lack of cooldown mechanisms and rate-limiting controls in the functions stakeMunchable and transferToUnoccupiedPlot. Both functions use the forceFarmPlots modifier, which calls the _farmPlots function without adequate checks, allowing the following issues:

Rapid Accumulation of In-Game Currency: Users can exploit this vulnerability to accumulate schnibbles (in-game currency) rapidly. By repeatedly calling stakeMunchable and transferToUnoccupiedPlot in quick succession, players can farm schnibbles at an accelerated rate. This undermines the in-game economy by disproportionately increasing the currency held by a single player.

Unfair Advantage: The exploit allows players to achieve faster attribute growth for their NFTs compared to others. This creates an imbalance in the game, as players who exploit this vulnerability gain an unfair advantage over those who do not or cannot.

Disruption of Economic Balance: The uncontrolled and frequent accumulation of schnibbles can disrupt the overall economic balance of the game. This not only affects gameplay but also impacts the value of in-game assets, potentially leading to inflation and a devaluation of rewards and items.

## Proof of Concept
Break down of attack contract structure to prove this vulnerability. 

Interface Definition:

The IPlotMunchables interface defines the stakeMunchable and transferToUnoccupiedPlot functions that are part of the target contract.

The constructor takes two parameters: the address of the target PlotMunchables contract and the tokenId of the NFT to be exploited.

Exploit Function:

The exploit function repeatedly calls stakeMunchable and transferToUnoccupiedPlot on the NFT. The loop can be adjusted to simulate the intensity of the exploit.

How it all works together:

This PoC demonstrates how an attacker could use a contract to automate the exploit, repeatedly staking and transferring an NFT to accumulate in-game benefits quickly. This PoC is based on the assumption that the target contract lacks proper rate-limiting or cooldown mechanisms, allowing the rapid and repeated farming of rewards. 

```solidity 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

interface IPlotMunchables {
    function stakeMunchable(uint256 tokenId) external;
    function transferToUnoccupiedPlot(uint256 tokenId) external;
}

contract PlotHoppingExploit {
    IPlotMunchables public munchablesContract;
    uint256 public munchableTokenId;

    constructor(address _munchablesContract, uint256 _munchableTokenId) {
        munchablesContract = IPlotMunchables(_munchablesContract);
        munchableTokenId = _munchableTokenId;
    }

    function exploit() external {
        for (uint256 i = 0; i < 10; i++) {
            munchablesContract.stakeMunchable(munchableTokenId);
            munchablesContract.transferToUnoccupiedPlot(munchableTokenId);
        }
    }
}
```

## Recommended Mitigation Steps

Implement Cooldown Period: Add a cooldown period between plot transfers to prevent rapid exploitation.

```solidity 
mapping(uint256 => uint256) lastFarmTime;
uint256 constant FARM_COOLDOWN = 1 hours;

function _farmPlots(address _sender) internal {
    uint256[] memory staked = munchablesStaked[_sender];
    for (uint8 i = 0; i < staked.length; i++) {
        uint256 tokenId = staked[i];
        if (block.timestamp - lastFarmTime[tokenId] < FARM_COOLDOWN) {
            continue; // Skip farming if cooldown hasn't elapsed
        }
        // Perform farming logic here
        lastFarmTime[tokenId] = block.timestamp;
    }
}

```
Another way to assist in negating this vulnerability would be to change the reward accrual mechanism from being transaction-based to time-based. This would mean that rewards are accumulated over time rather than per action, reducing the incentive to perform rapid actions.
