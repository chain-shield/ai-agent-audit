# Vulnerability details

## Impact
One invariant of the system is that tokens should not farm schnibbles rewards on invalid plots. The current implementation of `_farmPlots` does not handle an edge case already mentioned in the contest README in which schnibbles can be farmed for players being on invalid plots, even for a long time. **In addition, the README also notes that suggesting an alternative implementation will result in a valid finding**:
> This is a known edge case that we are comfortable with. **HOWEVER**, we will accept alternative solutions to mitigate this issue 

Let's first review the edge case and then explain an implementation to fix it.

The edge case in `_farmPlots` arises when the plot ID is lower than the maximum plot amount, making the plot ID invalid. In such cases, the system uses the last updated time from the plot metadata to track changes. However, if a user has not interacted with their plot for a significant period, and during this time the landlord has performed multiple updates on the plots (such as locking and unlocking); meaning the plots became invalid and valid multiple times, the last updated time will reflect the time of the latest update rather than the first update in the sequence of actions:
```solidity
// use last updated plot metadata time if the plot id doesn't fit
// track a dirty bool to signify this was done once
// the edge case where this doesnt work is if the user hasnt farmed in a while and the landlord
// updates their plots multiple times. then the last updated time will be the last time they updated their plot details
// instead of the first
if (_getNumPlots(landlord) < _toiler.plotId) { 
    timestamp = plotMetadata[landlord].lastUpdated;
    toilerState[tokenId].dirty = true;
}
```

The proposed implementation discussed below will efficiently handle this edge case by ensuring the users earn rewards only for valid periods and detect the moment the plot becomes dirty for the first time, ignoring all subsequent times after that (even if the plot becomes valid again), as illustrated below:

## Proposed implementation 
The main idea is to track the highest valid plot per landlord. Whenever there is a metadata update (indicating the number of valid plots has changed), we go over the occupied plots that become invalid and, for each one, update the `lastToilDate`, calculate the farmed schnibbles, and set the `dirty` status to true:
```solidity
// landlord => plotId
mapping(address => uint) highestAvailablePlot;

// ...

function updatePlotMetadata(
    address landlord
) external override onlyConfiguredContract(StorageKey.AccountManager) {
    uint totalAvailablePlots =  _getNumPlots(landlord);
    if (plotMetadata[landlord].lastUpdated == 0) {
        plotMetadata[landlord] = PlotMetadata({
            lastUpdated: block.timestamp,
            currentTaxRate: DEFAULT_TAX_RATE
        });
    } else {
        plotMetadata[landlord].lastUpdated = block.timestamp;
        
        if (highestAvailablePlot[landlord] >= totalAvailablePlots) {
            // We have some plots that become invalid, we go over them
            for (uint i = totalAvailablePlots; i <= highestAvailablePlot[landlord]; i++) {
                Plot memory plot = plotOccupied[landlord][i];

                // we check that the plot is occupied and that it is not dirty already
                if (plot.occupied && !toilerState[plot.tokenId].dirty) {
                    // we update the `lastToilDate` before calling `_farmPlots` to farm schnibbles for valid period
                    toilerState[plot.tokenId].lastToilDate = block.timestamp;
                    // we farm the schnibbles for the token owner
                    _farmPlots(munchableOwner[plot.tokenId]);
                    // We set the dirty status to true so that schnibbles will not be farmed for this token until he moves
                    toilerState[plot.tokenId].dirty = true;
                }
            }
        }
    }

    // we update the highest available plot state for the landlord
    highestAvailablePlot[landlord] = totalAvailablePlots > 0 ? totalAvailablePlots - 1: 0;
    
    emit UpdatePlotsMeta(landlord);
}
```

This ensures that whenever a plot becomes invalid for the first time, schnibbles are calculated only for the past valid period, and the dirty status is set.

The `_farmPlots` function needs to be updated accordingly, as it no longer needs to check for invalid plots:
```diff

-        }

```
