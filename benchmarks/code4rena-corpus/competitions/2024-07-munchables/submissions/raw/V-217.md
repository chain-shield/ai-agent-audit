# Vulnerability details

A user can stake their munchable on a landlord's unoccupied plot to earn some rewards. The user can transfer his munchable to another empty plot thereby vacating the current plot.

The issue is that when the user transfers his munchable, the `plotId` parameter is not updated to the new one. When unstaking, the original `plotId` when the user had initially staked is used. Thus the user is able to withdraw his nft leaving the landlord's plot occupied denying other user from staking.

## Proof of Concept
When the user transfers his munchable, we can see that only the tax rate is being updated for the token id. The previous plot's occupancy is set false & the new one's to true

```solidity

    function transferToUnoccupiedPlot(

        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        ToilerState memory _toiler = toilerState[tokenId];
        uint256 oldPlotId = _toiler.plotId;
        ...

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });
        ...
```
Inside `unstakeMunchable()`, we can see `_toiler.plotId` being used which has not been updated & still fetches the original plot id when the user initially staked.


**`plotOccupied` for the original plot id has already been set to false when the user transferred to the new plot. Its just being reset again.**
Every other parameter is then set to 0 & the user withdraws their munchable leaving the landlord's plot occupied.

### Scenario:
- Bob is the landlord who has 5 plots available for users to stake their munchable.
- Alice stakes her munchable at `plotId` `1`.
- After sometime, Alice transfers her munchable to `plotId` `3`.
- Inside `transferToUnoccupiedPlot()`, the necessary changes are made except updating the `plotId` inside `toilerState` for that token id.
- Alice decides to unstake her munchable. 
- However her previous `plotId` that is `1` (which has already been set to false) is used instead of her current `plotId` which is `3`.

```solidity
   plotOccupied[_toiler.landlord][_toiler.plotId] = Plot({
            occupied: false,
            tokenId: 0
        });
```
- Alice is removed from the list of stakers & receives her nft back.
- Bob's `plotId` `3` is still occupied despite having no nft being staked.

Worse case would be, taking the above scenario, that Alice staked at plotId `1`, transfers to another plot & then unstakes. This process is repeated until all of the plots of Bob are occupied. Alice only has to stake only at one position & now none of the users can stake at any of Bob's plot.

## Impact
Landlord's plot remain occupied despite having any munchable staked which also denies new users from staking on that plot & earning rewards

Manual Review

## Recommended Mitigation Steps
Update the `plotId` when an nft is transferred to a new plot.

```solidity
function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
```
