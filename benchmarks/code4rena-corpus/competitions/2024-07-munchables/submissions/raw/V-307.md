# Vulnerability details

## Impact
The `LandManager::_farmPlots(...)` can potentially revert due to `Index out of bounds` error, if the global `REALM_BONUSES` or `RARITY_BONUSES` arrays are not properly set.

## Proof of Concept
The `LandManager.sol` contract allows users to stake their munchables to other users' plots, in order to farm schnibbles. The schnibble rewards are increased with a bonus, which is formed from various user and NFT attributes. The calculation of this bonus is based on the `REALM_BONUSES` and `RARITY_BONUSES` arrays, which are set prior to deployment:

```solidity
function _farmPlots(address _sender) internal {
       __SNIP
    finalBonus =
        int16(
@>            REALM_BONUSES[
                (uint256(immutableAttributes.realm) * 5) +
                    uint256(landlordMetadata.snuggeryRealm)
            ]
        ) +
        int16(
@>            int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])
        );
    __SNIP__
}
```

If the values in these arrays are misconfiguted, then the current calculation for the indexes will fail for specific realm and rarity combinations, leading to `_farmPlots()` to always revert, blocking all functionalities in the `LandManager` contract. This has been properly handled in the [BonusManager::getFeedBonus(...)](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/BonusManager.sol#L102-L112) function, meaning that the dev elopment team are aware of such a problem.

## Tools Used

Manual review

## Recommended Mitigation Steps

Use the same index checks as done in the [BonusManager::getFeedBonus(...)](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/BonusManager.sol#L102-L112) function, but instead of reverting set a default value.
