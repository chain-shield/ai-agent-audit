# Vulnerability details

## Impact
Issue can result in the schnibblesLandlord calculation yielding 0, leading to landlords receiving no schnibbles.
## Proof of Concept

In _farmPlots function, there is a block that calculates schnibbles earned by landlord. Calculation multiplies `schnibblesTotal` with `_toiler.latestTaxRate`.

If `MIN_TAX_RATE` is set to 0, landlords can set `newTaxRate` to 0 by mistake, causing `schnibblesLandlord` to be 0 regardless of `schnibblesTotal`. Since `MIN_TAX_RATE` is not strictly set to some value, it could be set to 0. Adding `updateTaxRate` fn below.

```solidity
function updateTaxRate(uint256 newTaxRate) external override notPaused {
        (address landlord,) = _getMainAccountRequireRegistered(msg.sender);
        if (newTaxRate < MIN_TAX_RATE || newTaxRate > MAX_TAX_RATE) {
            revert InvalidTaxRateError();
        }
        if (plotMetadata[landlord].lastUpdated == 0) {
            revert PlotMetadataNotUpdatedError();
        }
        uint256 oldTaxRate = plotMetadata[landlord].currentTaxRate;
        plotMetadata[landlord].currentTaxRate = newTaxRate;
        emit TaxRateChanged(landlord, oldTaxRate, newTaxRate);
    }
``` 

After a landlord mistakenly sets taxRate to 0, he will receive no schnibble. Nothing is blocking this scenario. See below calculation in _farmPlots


```solidity
schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
schnibblesTotal = uint256((int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100);
schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;
```
## Tools Used

Manual review

## Recommended Mitigation Steps

Set minimum and maximum tax rates:

Ensure that MIN_TAX_RATE is set to a non 0 value to prevent the tax rate from being set to 0.
Ensure that MAX_TAX_RATE is set to a value no greater than 1e18 to prevent potential overflow or other issues.
