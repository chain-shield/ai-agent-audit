# Vulnerability details

## Impact
The `plotMetadata[landlord].currentTaxRate` can be changed to a larger value during staking, allowing users to deliberately avoid farming and accumulate staking rewards with less tax. This behavior can lead to edge cases per discussed in the comment,  potentially causing losses for other users.

## Proof of Concept
In the `_farmPlots` function, `schnibblesLandlord` is calculated based on `_toiler.latestTaxRate`. Later, `toilerState[tokenId].latestTaxRate` is updated to `plotMetadata[_toiler.landlord].currentTaxRate`.

```solidity
            schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;
            schnibblesTotal = uint256(
                (int256(schnibblesTotal) +
                    (int256(schnibblesTotal) * finalBonus)) / 100
            );
            schnibblesLandlord =
 @=>            (schnibblesTotal * _toiler.latestTaxRate) /
                1e18;

            toilerState[tokenId].lastToilDate = timestamp;
@=>         toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
                .currentTaxRate;
```

If the `plotMetadata[landlord].currentTaxRate` is increased during staking, users may avoid farming to accumulate rewards with the previous, lower tax rate. This behavior increases the likelihood of edge cases as noted in the comment:

```solidity
            // use last updated plot metadata time if the plot id doesn't fit
            // track a dirty bool to signify this was done once
d            // the edge case where this doesnt work is if the user hasnt farme in a while and the landlord
            // updates their plots multiple times. then the last updated time will be the last time they updated their plot details
            // instead of the first
```

## Recommended Mitigation Steps

To mitigate this issue:
- **Implement a Minimum Farming Interval**:  Introduce a minimum interval between farming actions to reduce the likelihood of users avoiding farming to accumulate rewards with a lower tax rate.
- **Track Accrued Rewards Separately**: Implement a mechanism to track accrued rewards separately from the tax rate, ensuring that rewards are taxed based on the rate at the time they were earned rather than the current rate.
