# Vulnerability details

## Impact
Plot Id is not changed to the new plotId while `transferToUnoccupiedPlot` is executed.Hence when the user unstakes the transferred NFT , incorrect `plotOccupied[_toiler.landlord][_toiler.plotId]` is changed affecting another user. Also user can no more transfer the same NFT since `plotOccupied[_toiler.landlord][_toiler.plotId].occupied` will fail.

## Proof of Concept
In the `transferToUnoccupiedPlot(uint256 tokenId,uint256 plotId)` , plotId is not changed from `oldPlotId` to `newPlotId` in the `toiler[tokenId]`.

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L199-L226

```solidity
    function transferToUnoccupiedPlot(
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        .....

        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });


        emit FarmPlotLeave(_toiler.landlord, tokenId, oldPlotId);
        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }
```
Only the `latestTaxRate` has been changed for that `toiler`.
