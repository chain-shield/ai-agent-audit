# Vulnerability details

## Impact
Schnibbles can be defrauded from the agreement without the landlord needing to stake too much.

## Proof of Concept
This is a publicly known issue. Here is a brief explanation of how to cause harm, mainly focusing on repair suggestions. Good solutions that the client has stated will be accepted.

Users can use different addresses as landlords and NFT pledgers. The landowner first pledges a lot and opens up a lot of land, and then pledges a lot of NFT. The landowner can then take out the pledge. after a while. The landowner changes the pledge amount again (the change can be small.) The NFT staker calls `farmPlots` for settlement. At this time, settlement will be based on the latest update time of the landlord. As a result, users can obtain more land with a small pledge amount.

Due to breaking the principle of stake rewards. Similar to stealing funds from the protocol, so I judge it to be high.

## Tools Used
manual

## Recommended Mitigation Steps
The main purpose of the modification is that if the landowner reduces the mortgage, settlement should be based on the time of the first landowner renewal.

So at the end of the function where the landlord reduces the pledge, add the following logic.
If the user is reducing the pledge, use the [plotOccupied variable](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L23) to find the pieces of land that exceed the current pledge. Settle those pieces of land.
