# Vulnerability details

## Impact
Landlords can lock their assets for 1 block (only when harvesting), in order to avoid any risk exposures.

## Proof of Concept
In order for stakers to ear rewards, they need to stake to an empty active plot and that plot to be not `dirty` when claiming rewards. The plot is labeled `dirty`  when the current `plotId` is bigger than the available plots the landlord has:

https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258-L261
```solidity
   if (_getNumPlots(landlord) < _toiler.plotId) {
      timestamp = plotMetadata[landlord].lastUpdated;
      toilerState[tokenId].dirty = true;
   }
```

Plots are calculated with [_getNumPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L344-L346) doing `weight / price`, where the weight (as seen in [getLockedWeightedValue](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L481-L491)) is calculated as `quantity * price`, adjusted to 18 decimals. In short free plots are:
```markdown
number of free plots = token quantity * price per token / price per plot
```

The above means that in order for users to stake to a landlord he needs to lock his own tokens inside the market for a given duration, as seen inside [LockManager::_lock](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L349-L373)

```solidity
    if (_lockDuration == 0) {
       _lockDuration = lockdrop.minLockDuration;
    }
    if (lockdrop.start <= uint32(block.timestamp) && lockdrop.end >= uint32(block.timestamp)) {
        if ( _lockDuration < lockdrop.minLockDuration 
           || _lockDuration > uint32(configStorage.getUint(StorageKey.MaxLockDuration))
           ) revert InvalidLockDurationError();
```

However the issue that appears here is that lock duration is only checked if we are inside a `lockdrop` event. If outside one, only only restriction landlords have is:

```solidity
        if (_lockDuration == 0) {
            _lockDuration = lockdrop.minLockDuration;
        }
``` 

However that can also be avoided, by setting `lockDuration` to 1 using [setLockDuration](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L247), where there are no checks preventing users from setting it bellow the `lockdrop.minLockDuration`. 

Setting `lockDuration` to 1 second will allow landlords to lock their tokens, stake from anther account to their plots and unlock their tokens in the next block. When they decide to claim their rewards, they can again lock and call [farmPlots](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L228-L230) to claim their rewards.

This will allow landlords to generate rewards while avoiding risk and not contributing to the system.

Example:
1. `lockdrop.minLockDuration` is 7 days, but we are not in a `lockdrop` event
2. Landlord sets his `lockDuration` to 1 second using [setLockDuration](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L247).
3. He locks to generate a few free plots and stakes his NFTs to them.
4. On the next block he unlocks and uses his assets for something else.
5. After some time he locks again, farms his plots and unlocks on the next block.

This can be repeated by landlords allowing them to farm tokens from `LandManager` and use their assets for other purposes (staking/borrowing/LP to pools...).


Note that having `lockdrop.minLockDuration` set to 0 will also enable them to use flashloans to borrow -> lock -> stake -> unlock -> repay FL and essentially ear rewards for free.

## Recommended Mitigation Steps
The current `duration` validation in [setLockDuration](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LockManager.sol#L247) will not suffice, as setting it to 1 second will enable him to change it on the next block. Impose another validation checking every lock for a min time:

```diff
    function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration)) {
            revert MaximumLockDurationError();
        }

+       if (_duration < configStorage.getUint(StorageKey.MinLockDuration)) {
+           revert MinimumLockDurationError();
+       }
```
