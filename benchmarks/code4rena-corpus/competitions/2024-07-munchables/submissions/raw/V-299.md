# Vulnerability details

## Impact
The current contract checks  `_toiler.plotId` against `_getNumPlots(landlord)`, assuming that plots are occupied in order. This assumption can lead to incorrect marking of plots as dirty even when the landlord’s plots are not fully occupied.

## Proof of Concept
In the `_farmPlots` function, a check is performed to determine if a plot should be marked as `dirty`.

```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```

However, this check assumes that plots are occupied in a sequential order, which is often not the case. Consider the following scenario:

Consider the following scenario:
1. `_getNumPlots(bob)` = 6 and Alice stakes her `munchable` in bob’s plot4 because plot0, plot1, plot2, and plot3 are all occupied.
2. Later, plot0, plot1, plot2, and plot3 are all released due to unstaking.
3. `_getNumPlots(bob)` changes to 3, however, Alice’s `munchable` is marked as dirty even though it is the only one staking.
## Tools Used

Manual

## Recommended Mitigation Steps

Reconsider the check and potentially perform an automatic attempt to `transferToUnoccupiedPlot` before marking an NFT as dirty.
