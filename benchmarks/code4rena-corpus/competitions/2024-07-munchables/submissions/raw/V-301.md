# Vulnerability details

## Impact
The `stakeMunchable` function in the contract is vulnerable to a front-running attack, where a malicious user can repeatedly `front-run` and occupy a specific landlord-plotId, causing a `Denial of Service (DoS)` for legitimate users attempting to stake on the same plot.

## Proof of Concept
In the `stakeMunchable` function, users can stake on a specific `landlord-plotId`. However, there is a strict check to ensure that the plot is not already occupied.

```solidity
        if (plotOccupied[landlord][plotId].occupied) // @note front-run to take?
            revert OccupiedPlotError(landlord, plotId);
```

Due to this check, a malicious user can front-run the staking transaction and occupy the plot, effectively preventing the legitimate user from staking. For instance:

1. Alice intends to stake on ADDRESS-PLOT.
2. Observing Alice’s intent, Bob calls `stakeMunchable` to occupy the plot just before Alice’s transaction is processed, causing Alice’s staking attempt to fail.

## Tools Used

Manual

## Recommended Mitigation Steps

To mitigate this issue:
1. **Introduce a Minimum Staking Time**: Implement a minimum staking time to add a cost for front-running, making it less attractive for attackers.
2. **Iterate to Find an Unoccupied Plot**: Allow the staking function to automatically find and use an unoccupied plot if the specified plot is already occupied.
