# Vulnerability details

## Impact
In the `farmPlots()` function there is a logic that is supposed to give a final bonus % to the token Id added to the schnibbles they've accumulated over a period of time. The final bonus can be a negative or positive value, based on the staked token Id's realm and rarity attributes, the landlords snuggeryRealm attrribute, along with REALM_BONUS and RARITY_BONUS array values.

Due to the way the casting and order of operations in the `schnibblesTotal` is calculated with its `finalBonus`, `token Id realm and rarity attributes` and `landlord realm attributes` 
The result can be a negative final bonus value which in turn causes subsequent calculations in the _farmPlots function to revert due to arithmetic overflow from making the `schnibblesTotal` a very large number. 


Since the _farmPlots() function is called before every external function regarding the token Id staked as a modifier i.e `unstakeMunchable(uint256 tokenId) external override forceFarmPlots(msg.sender)` , 
`transferToUnoccupiedPlot(uint256 tokenId, uint256 plotId) external override forceFarmPlots(msg.sender)` if the user wants to transfer or unstake their token Id they wont be able to due to the arithmetic overflow revert. 

If they are still able to somehow farm or unstake, they get a ridiculous amount of undeserved schnibbles.
For users who's nft attributes and landlord attributes are fine, the logic is still flawed and doesn't give the accurate bonus percentage instead gives a lesser value than intended.
Stems from the same root cause so included it in this submission.


## Proof of Concept

Lets take an account stakes their their mucnhNFT, `token Id of 4` into the `LandManager.sol`. Each token Id has an immutable attributes for `Realm` and `Rarity` values as well as a landlord has a `snuggeryRealm` value which can be one of the following enum values excluding the `Invalid` and `Primordial` values. Meaning valid realm values are from 0-4 and rarity values 1-5.

[Link to the enum values here](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/libraries/MunchablesCommonLib.sol#L5-L22)

The situation that could occur that could lead to this issue would be a user having token Id attributes and landlord realm attributes giving a negative value. The schnibblesTotal calculation doesn't handle this well.

Let's take values of the `token Id: 4` `realm and rarity attributes` to be `2 and 1` respectively, while the `landlord snuggeryRealm` attribute to be `4`.
This would give a finalBonus of `-10`.


In the `_farmPlots()` function, when using this finalBonus and the flawed logic, the schnibbles total would result in a very huge value that when multiplying with the landlord tax rate would result in an arithmetic overflow which would revert. This is due to the type casting and order of operations.

Link to code [here](https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L270-L289)

`schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;`

`schnibblesTotal = uint256((int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100);`

`schnibblesLandlord = (schnibblesTotal * _toiler.latestTaxRate) / 1e18;`

In essence stopping the user from being able to unstake this particular tokenId leading to a loss of asset for the user.
If somehow the user is still able to unstake the token Id then the user comes out with a ridiculous amount of schnibbles.


## Recommended Mitigation Steps
Using a function that takes into account positive & negative `finalBonus` values and calculates the increment or decrement of the `schnibblesTotal` accordingly.
This also fixes the issue of receiving lesser amount of schnibbles for NFT's without this overflow issue.

Something similar to this.

```solidity
function fixedTotalSchnibblesPlusBonus(int16 _finalBonus, uint256 _duration) public view returns (uint256) {
      uint256 schnibblesTotal = _duration * BASE_SCHNIBBLE_RATE;
      int256 bonus = (int256(schnibblesTotal) * _finalBonus) / 100;
      uint256 totalSchnibbles = uint256(int256(schnibblesTotal) + bonus);
      return totalSchnibbles;
}
```
