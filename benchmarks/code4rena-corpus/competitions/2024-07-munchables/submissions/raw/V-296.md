# Vulnerability details

## Impact
Last pet munchable timestamp is miscalculated for landlord if the last munchedNFT is classified as dirty in the same execution.

## Proof of Concept

A user executed `_farmPlots()` to update the schinbbles for each of their staked NFT.

WHile calculating the schnibbles , an NFT is identified as `dirty` and hence `timestamp` value is changed from `block.timestamp` to `plotMetadata[landlord].lastUpdated`.

https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L258-L261
```solidity
 for (uint8 i = 0; i < staked.length; i++) {
    timestamp = block.timestamp;
            ....
    if (_getNumPlots(landlord) < _toiler.plotId) {
        timestamp = plotMetadata[landlord].lastUpdated;
        toilerState[tokenId].dirty = true;
    }
    ...
 }
```

landlordMetadata.lastPetMunchable  should have the value of the timestamp when the last munchableNFT has been petted/taken care of which is the timestamp when the `_farmPlots()` is called.


https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L299
```solidity
     landlordMetadata.lastPetMunchable = uint32(timestamp);
```
But here we are mistakenly assigning the incorrect `timestamp`. Because in this case `timestamp` has the value of `plotMetadata[landlord].lastUpdated`.

## Tools Used
Manual

## Recommended Mitigation Steps
make it to 
landlordMetadata.lastPetMunchable = uint32(block.timestamp); instead
