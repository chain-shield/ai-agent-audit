# Vulnerability details

## Impact
There's an off-by-one error in `LandManager`'s `_farmPlots()`, which results in considering dirty plots as non-dirty and hence providing a more than expected amount of farmed schnibbles.

## Proof of Concept

In `LandManager._farmPlots()`, the following snippet handles cases where the plot id doesn’t fit in the current plot metadata. 

```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
                timestamp = plotMetadata[landlord].lastUpdated;
                toilerState[tokenId].dirty = true;
            }
```

However, this logic is incorrect because when `_getNumPlots(landlord) == _toiler.plotId`, it’s not marked dirty even though it should be. 

As the plot id is an index while _getNumPlots returns the size, when `_getNumPlots(landlord) == _toiler.plotId`, such a plot id does not fit in the metadata. But because the current code leaves such a plot out of this if-clause, `dirty` and `timestamp = block.timestamp` would remain unchanged, which results in more amount of farmed schnibbles than expected for this plot.

```solidity
            schnibblesTotal =
                (timestamp - _toiler.lastToilDate) *
                BASE_SCHNIBBLE_RATE;

```
