# Vulnerability details

## Impact

As AccountManager.addSubAccount() can arbitrarily overwrite anyone’s main account, an attacker can prevent a chosen victim from transferring their stakedMunchNFT to another plot via `transferToUnoccupiedPlot()`. This would make any game action that relies on this function invalid. 

## Proof of Concept
Consider the following scenario:

1. Assume Alice has a staked NFT with `tokenId = 1` at `plotId = 1`
2. Bob calls `AccountManager.addSubAccount(alice)` which sets `mainAccounts[alice]` to Bob’s address.
3. Alice calls `transferToUnoccupiedPlot()` which would revert due to `InvalidOwnerError`. This is because `mainAccount` which is now set to Bob’s address doesn’t match with `munchableOwner[1]` which is set to Alice's address.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The AccountManager logic must be reworked to ensure that no authorized party can arbitrarily modify someone’s main account address. The simplest fix would be to remove the entire concept of subaccount. If that’s not feasible, one potential mitigation is to require an approval signature from the original main account’s address in order to override the original main account address.

`transferToUnoccupiedPlot()` also needs to make sure that the original staker can transfer their token even if their main account changed.
