# Vulnerability details

## Impact
The `stakeMunchable` function contains a plot ID validation that incorrectly prevents staking on valid plots. The condition if `(plotId >= totalPlotsAvail) revert PlotTooHighError();` does not account for `plotId` starting from `0`, which leads to legitimate staking attempts being blocked when `plotId` equals `totalPlotsAvail - 1`. This bug prevents users from staking on valid plots, disrupting the expected functionality and user experience.

## Proof of Concept
The plot ID validation logic is flawed, causing legitimate staking attempts to be incorrectly rejected. This issue arises because 0 is a valid `plotId`(Confirmed by the sponsor in discord), and the check `plotId >= totalPlotsAvail` fails to allow valid cases where `plotId` is less than `totalPlotsAvail`.

Issue arises in the `stakeMunchable` function at this line: 
https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L146

```solidity
    function stakeMunchable(
        address landlord,
        uint256 tokenId,
        uint256 plotId
    ) external override forceFarmPlots(msg.sender) notPaused {
        (address mainAccount, ) = _getMainAccountRequireRegistered(msg.sender);
        if (landlord == mainAccount) revert CantStakeToSelfError();
        if (plotOccupied[landlord][plotId].occupied)
            revert OccupiedPlotError(landlord, plotId);
        if (munchablesStaked[mainAccount].length > 10)
            revert TooManyStakedMunchiesError();
        if (munchNFT.ownerOf(tokenId) != mainAccount)
            revert InvalidOwnerError();

        uint256 totalPlotsAvail = _getNumPlots(landlord);
        if (plotId >= totalPlotsAvail) revert PlotTooHighError();  //@audit

        if (
            !munchNFT.isApprovedForAll(mainAccount, address(this)) &&
            munchNFT.getApproved(tokenId) != address(this)
        ) revert NotApprovedError();
        munchNFT.transferFrom(mainAccount, address(this), tokenId);

        plotOccupied[landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });

        munchablesStaked[mainAccount].push(tokenId);
        munchableOwner[tokenId] = mainAccount;

        toilerState[tokenId] = ToilerState({
            lastToilDate: block.timestamp,
            plotId: plotId,
            landlord: landlord,
            latestTaxRate: plotMetadata[landlord].currentTaxRate,
            dirty: false
        });

        emit FarmPlotTaken(toilerState[tokenId], tokenId);
    }

```
Proof of Concept:
Consider the following scenarios:

1. A landlord has exactly one plot, making `totalPlotsAvail` equal to `1`.
* Alice tries to stake on this plot with `plotId` of `0`.
* The condition `if (plotId >= totalPlotsAvail)` evaluates as if `(0 >= 1)`, which is false.
* The function reverts with `PlotTooHighError`, preventing Alice from staking.


2. A landlord has two plots, making `totalPlotsAvail` equal to `2`.
* Alice tries to stake on the second plot with `plotId` of `1`.
* The condition if `(plotId >= totalPlotsAvail)` evaluates as if `(1 >= 2)`, which is false.
* The function reverts with `PlotTooHighError`, preventing Alice from staking.
