# Vulnerability details

## Impact

Since `toiletState.plotId` will not be updated, the user will not be able to get the farming reward after transferring the plot ID from an invalid plot to a valid plot, even if the current plot becomes invalid after the plot transfer, the user will still be able to get the farming reward using the previous plot ID. This disrupts the expected game mechanics.

## Proof of Concept

The [code snippet](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L213-L222):

```solidity
        toilerState[tokenId].latestTaxRate = plotMetadata[_toiler.landlord]
            .currentTaxRate;
        plotOccupied[_toiler.landlord][oldPlotId] = Plot({
            occupied: false,
            tokenId: 0
        });
        plotOccupied[_toiler.landlord][plotId] = Plot({
            occupied: true,
            tokenId: tokenId
        });
```

And [the line of code](https://github.com/code-423n4/2024-07-munchables/blob/main/src/managers/LandManager.sol#L258) in the `_farmPlot` function:

```solidity
            if (_getNumPlots(landlord) < _toiler.plotId) {
```

This issue occurs in the following steps:

The first case:

1. When the plot currently occupied by the user is invalid, user attempts to transfer their token to an unoccupied plot using the `transferToUnoccupiedPlot` function.
2. Although the function updates the plot's occupancy status, it does not update `toilerState.plotId`.
3. The user cannot receive farming rewards since the `toilerState.plotId` remains unchanged.

In the second case, vice versa.
