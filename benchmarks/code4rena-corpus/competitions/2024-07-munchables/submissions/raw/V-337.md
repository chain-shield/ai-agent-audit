# Vulnerability details

## Impact

Stakers could receive extremely high schnibble rewards due to int to uint typecast in function _farmPlots().

## Proof of Concept

We'll be using the code snippet below to understand the issue.
```solidity
File: LandManager.sol
282:             finalBonus =
283:                 int16(
284:                     REALM_BONUSES[
285:                         (uint256(immutableAttributes.realm) * 5) +
286:                             uint256(landlordMetadata.snuggeryRealm)
287:                     ]
288:                 ) +
289:                 int16(
290:                     int8(RARITY_BONUSES[uint256(immutableAttributes.rarity)])
291:                 );
292:                 
293:             schnibblesTotal =
294:                 (timestamp - _toiler.lastToilDate) *
295:                 BASE_SCHNIBBLE_RATE;
296:             schnibblesTotal = uint256(
297:                 (int256(schnibblesTotal) +
298:                     (int256(schnibblesTotal) * finalBonus)) / 100 
299:             );
```

1. First let's take a look at finalBonus. This variable is an int16 meaning that it can hold negative values as well. Currently the value is calculated using REALM_BONUSES[index] + RARITY_BONUSES[index]. As per the scripts, these arrays can hold the following values:

```solidity
export const REALM_BONUSES = [
  10, -10, -5, 0, 5, -10, 10, -5, 5, 0, -5, 0, 10, 5, -10, 0, -5, 10, 10, -10, 5, 10, 0, -10, 10,
];

export const RARITY_BONUSES = [0, 0, 10, 20, 30, 50];
```

2. Let's say we get -10 from REALM_BONUSES and 0 from RARITY_BONUSES. This means finalBonus = -10 + 0 = -10.

3. On Line 293, let's say the difference `timestamp - _toiler.lastToilDate` = 1000 and as per the scripts the BASE_SCHNIBBLE_RATE = 1e15. This sets the schnibblesTotal = 1000 * 1e15 = 1e18.

4. Now when we calculate schnibblesTotal on Line 296, it results to an extremely large number: 115792089237316195423570985008687907853269984665640564039457494007913129639936

You can use this in remix by passing finalBonus as -10:
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.26;

contract Calculations {

    uint256 public schnibblesTotal;

    function x(int256 finalBonus) public {
        schnibblesTotal = 1e18;
        schnibblesTotal = uint256(
            (int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100
        );
    }
}
```

5. Due to this, the schnibbles rewarded are extremely high than the intended. This occurred due to the int to uint typecast.

## Recommended Mitigation Steps
After discussions with the sponsor, the intended behaviour was expected to be:

If final bonus is negative 10 (for example), then the outcome should be 90% of the schnibblesTotal base amount. If it is positive 10, then the outcome should be 110% of the base.
