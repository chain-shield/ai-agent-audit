# Vulnerability details

## Impact
The incorrect calculation of `schnibblesTotal` in the `_farmPlots` function results in significantly lower rewards being calculated and distributed. `schnibblesTotal` value represents the total rewards (`schnibbles`) generated by the staked munchables over a period of time. Therefore an incorrect calculation of `schnibblesTotal` means that the rewards distributed to both the `renter` and the `landlord` will be significantly lower than intended.

Also, the `renterMetadata.unfedSchnibbles` and `landlordMetadata.unfedSchnibbles` are updated based on the `schnibblesTotal` value. An incorrect `schnibblesTotal` results in incorrect updates to these state variables, causing inaccurate tracking of rewards.

>I reached out to the sponsor to confirm  if the protocol's intention was to apply `finalBonus` as a percentage modifier to `schnibblesTotal` and his response was "Yes" and he also confirmed the bug described in this report.


## Proof of Concept
Take a look at this part of the code: https://github.com/code-423n4/2024-07-munchables/blob/94cf468aaabf526b7a8319f7eba34014ccebe7b9/src/managers/LandManager.sol#L280-L286

```solidity
schnibblesTotal =
    (timestamp - _toiler.lastToilDate) *
    BASE_SCHNIBBLE_RATE;
schnibblesTotal = uint256(
    (int256(schnibblesTotal) +
        (int256(schnibblesTotal) * finalBonus)) / 100
);
```

As seen above, the code attempts to apply a bonus by adding the product of `schnibblesTotal` and `finalBonus` to `schnibblesTotal` itself, and then dividing by 100. This is not correct because it effectively reduces the `schnibblesTotal` by a factor of 100.

For example let's say:

- `timestamp = 2000`
- `_toiler.lastToilDate = 1000`
- `BASE_SCHNIBBLE_RATE = 10`
- `finalBonus = 20` (representing a 20% bonus)

The implemented code will calculate it as:

1. **Calculate `schnibblesTotal` without bonus:**
   ```solidity
   schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;

   schnibblesTotal = (2000 - 1000) * 10;
   schnibblesTotal = 10000;
   ```

2. **Apply the bonus:**
   ```solidity
   schnibblesTotal = uint256(
       (int256(schnibblesTotal) + (int256(schnibblesTotal) * finalBonus)) / 100
   );

   schnibblesTotal = uint256(
       (10000 + (10000 * 20)) / 100
   );
   schnibblesTotal = uint256(
       (10000 + 200000) / 100
   );
   schnibblesTotal = uint256(
       210000 / 100
   );
   schnibblesTotal = 2100;
   ```

BUT, It should actually be calculated this way:

1. **Calculate `schnibblesTotal` without bonus:**
   ```solidity
   schnibblesTotal = (timestamp - _toiler.lastToilDate) * BASE_SCHNIBBLE_RATE;
   schnibblesTotal = (2000 - 1000) * 10;
   schnibblesTotal = 10000;
   ```

2. **Apply the bonus:**
   ```solidity
   schnibblesTotal = uint256(
       (int256(schnibblesTotal) * (100 + finalBonus)) / 100
   );
   schnibblesTotal = uint256(
       (10000 * (100 + 20)) / 100
   );
   schnibblesTotal = uint256(
       (10000 * 120) / 100
   );
   schnibblesTotal = uint256(
       1200000 / 100
   );
   schnibblesTotal = 12000;
   ```

Comparing the results;

- Original Code Result = `2100`
- Suggested Correction Result = `12000` which effectively calculates a 20% bonus increase



It's worth nothing that `finalBonus` is defined as an `int16`, which means it can be negative. The proposed fix handles both positive and negative bonuses correctly. For instance, if `finalBonus` is -10 (representing a 10% penalty), the calculation would be:

```solidity
schnibblesTotal = uint256(
    (int256(schnibblesTotal) * (100 + (-10))) / 100
);
```

This would correctly apply a 10% reduction to the `schnibblesTotal`.

## Recommended Mitigation Steps
We have to make sure the bonus is applied as a percentage increase over the base amount so as to achieve accurate reward calculation

```diff
schnibblesTotal =
    (timestamp - _toiler.lastToilDate) *
    BASE_SCHNIBBLE_RATE;
- schnibblesTotal = uint256(
-     (int256(schnibblesTotal) +
-         (int256(schnibblesTotal) * finalBonus)) / 100
- );
+ schnibblesTotal = uint256(
+     (int256(schnibblesTotal) * (100 + finalBonus)) / 100
+ );
```
