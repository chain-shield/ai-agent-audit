# Vulnerability details

## Vulnerability Detail

Using _safeTransferFrom guarantees that the receiver address is either a smart contract that implements `IERC721Receiver.onERC721Received` or an EOA.

While unstaking Munchable the NFT is transferred back to the caller using `transferFrom` instead of `safeTransfer`. This might lead to loss of funds if the call is a contract expecting the `IERC721Receiver.onERC721Received` hook to be called to update the contract.


```sol
    function unstakeMunchable(
        uint256 tokenId
    ) external override forceFarmPlots(msg.sender) notPaused {
        ...
        //@audit use of transferFrom instead of safeTranfer
@->     munchNFT.transferFrom(address(this), mainAccount, tokenId);
        emit FarmPlotLeave(_toiler.landlord, tokenId, _toiler.plotId);
    }

```


## Impact

Loss of token if transferred to a smart contract that can't properly handle ERC721 tokens.


## Tools Used

Manual

## Recommended Mitigation Steps

Use `safeTransfer` instead of `transferFrom`
