# Vulnerability details

## Impact
The `_sweepEbtc()` function is marked as `private`, which it can only be called internally within the contract. However, it directly transfers the balance to `msg.sender`, which is the address that initiated the transaction. [LeverageZapRouterBase.sol#76-L86](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L76-L86)
```solidity
    function _sweepEbtc() private {
        /**
         * SWEEP TO CALLER *
         */
        // Safe unchecked because known tokens
        uint256 bal = ebtcToken.balanceOf(address(this));


        if (bal > 0) {
            ebtcToken.transfer(msg.sender, bal);
        }
    }
```
In Solidity, the `msg.sender` is a global variable representing the address of the entity that called the function. If `_sweepEbtc()` does not have proper access controls to restrict who can call it, and if it can be triggered through some public or external function indirectly, it could be exploited.

Typically, sensitive functions like these should include checks to ensure that only authorized addresses _(like the contract owner or specific admin addresses)_ can execute them, or they should be structured in a way that their execution cannot lead to unintended consequences.

## Proof of Concept
There is a public function that calls `_sweepEbtc()` in the `LeverageZapRouterBase.sol` contract. The function [_closeCdpOperation](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L200-L230) includes a call to `_sweepEbtc()`. 
```solidity
function _closeCdpOperation(
    bytes32 _cdpId, 
    uint256 _debt, 
    TradeData calldata _tradeData
) internal {
    CloseCdpOperation memory cdp;
    cdp.debtToRepay = _debt;
    cdp.tradeData = _tradeData;
    // other operations
    _sweepEbtc(); // This is the call to _sweepEbtc()
}
```
Additionally, the function [_openCdpOperation](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L165-L198) in the same contract also calls `_sweepEbtc()`.
```solidity
function _openCdpOperation(
    bytes32 _cdpId,

    uint256 _flAmount, 
    TradeData calldata _tradeData

    // setup operation data
    _doOperation(

        _cdpId

    _sweepEbtc(); // This is the call to _sweepEbtc()
    _sweepStEth();
}
```
