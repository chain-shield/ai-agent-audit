# Vulnerability details

## Impact
The `_getOwnerAddress` function within the `ZapRouterBase` contract contains an unsafe downcast that can lead to unexpected behaviour and potential security vulnerabilities.
Unexpected errors or malfunctions if the address is used for authorization checks.
Denial-of-Service (DoS) attacks if the contract gets stuck due to invalid addresses.
## Proof of Concept
```solidity
function _getOwnerAddress(bytes32 cdpId) internal pure returns (address) {
    uint256 _tmp = uint256(cdpId) >> 96;
    return address(uint160(_tmp));
}
```
The `_getOwnerAddress` function:
Converts the bytes32 value to a `uint256`. Shifts the value right by `96 bits`, keeping the lower `160 bits`.
Downcasts the result to `uint160` and converts it to an address.
If `cdpId` contains non-zero data in the `upper 96 bits`, this data is lost during the shift operation, leading to potential incorrect address extraction. An attacker can exploit this by providing a `cdpId` with non-zero upper `96 bits`, causing the contract to extract an incorrect address and potentially leading to a permanent DoS.

## Recommended Mitigation Steps
To prevent unsafe downcasting and ensure the integrity of address extraction, validate that the upper 96 bits of cdpId are zero before performing the downcast:
```solidity
function _getOwnerAddress(bytes32 cdpId) internal pure returns (address) {
    // Check if the upper 96 bits are zero
    require(uint256(cdpId) >> 160 == 0, "Invalid cdpId: non-zero upper bits");

    // Perform the safe downcast
    uint256 _tmp = uint256(cdpId) >> 96;
    return address(uint160(_tmp));
}

```
