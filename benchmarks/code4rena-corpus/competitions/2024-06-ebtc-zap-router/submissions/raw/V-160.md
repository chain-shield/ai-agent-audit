# Vulnerability details

## Impact
In the `EbtcLeverageZapRouter` contract, from the functions of `_openCdp()`, `_closeCdp()` and `_adjustCdp()` we can see they are using `nonReentrant`, this means the protocol is designed as not allowing reentrance into the methods above.

However, this `nonReentrant` only works for its residing contract. Since this protocol has two separate user touchpoint router contracts (`EbtcLeverageZapRouter` and `EbtcZapRouter`), hence, a malicious user can still perform a reentrancy-ish operation which is supposed to be forbidden by the protocol. I'll demonstrate how it is done in the POC section below. This issue can let the user get around the protocol's designed non-reentrancy, and mess up operations with CDP which were supposed to be disallowed actions.

## Proof of Concept
1. The user can start with the adjust/close/open CDP related function in the contract `EbtcLeverageZapRouter`. Such functions accept arbitrary data `_tradeData`, this is what the malicious user can utilize;
2. These functions will make a series of call stack, they will go to the `LeverageMacroBase` contract, thru `_doOperation`=>`_handleOperation`=>`_doSwaps`=>`_doSwap`
3. Here in `_doSwap` the call to an arbitrary external contract is happening. The user can prepare a malicious external contract as the `swapData.addressForSwap`, when being called, the malicious contract will call the other router contract `EbtcZapRouter` and it can totally get into the adjust/close/open CDP related function again because there is no reentrancy guard in that contract.
4. This kind of reentrancy attack cannot have more than 1 extra round because it does not get the reentrancy point again for a 2nd round. However, it can enter for 1 extra round so it already breaks the protocol's design.


## Tools Used
Manual review.

## Recommended Mitigation Steps
Deploy a separate contract functioning as the Global Reentrancy Guard, this contract holds a state variable as the lock status. All necessary functions in the multiple user touchpoint contracts come here to toggle the lock and read the universal lock status, so it makes any cross-contract reentrancy impossible.
