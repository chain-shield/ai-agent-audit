# Vulnerability details

## Details
By design there should not be any locked tokens in LeverageZapRouter (`EbtcLeverageZapRouter`) contract. But there's no guarantee for this because as we know anyone can directly send these tokens to the contract and lock them, in such case the first user to open CDP position when executing `_sweepEbtc` or `_sweepStEth` will gain ALL of the tokens not just the ones intended for him. Also this approach is in contrast with protocol's design before transferring any tokens to check "balanceBefore" like here https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-zap-router/src/EbtcLeverageZapRouter.sol#L453 (just one example)

## Impact
User can gain more eBTC and/or stETH tokens than intended.

## Proof of Concept
1. Alice accidentally (or forcibly) sends `eBTC` and/or `stETH` directly to `EbtcLeverageZapRouter`
2. Tokens are locked 
3. Bob is opening a CDP position
4. By design after the swap any remaining or "residue" tokens (both eBTC and stETH) are transferred back to the caller
5. Bob will not just get the residue tokens from his transaction but he will get all of the eBTC or stETH locked tokens

```
function _sweepEbtc() private {
        /**
         * SWEEP TO CALLER *
         */
        // Safe unchecked because known tokens
       @---> uint256 bal = ebtcToken.balanceOf(address(this));

        if (bal > 0) {
            ebtcToken.transfer(msg.sender, bal);
        }
    }

    function _sweepStEth() private {
        /**
         * SWEEP TO CALLER *
         */
        // Safe unchecked because known tokens
        @---> uint256 bal = stEth.sharesOf(address(this));

        if (bal > 0) {
            stEth.transferShares(msg.sender, bal);
        }
    }

```

This is a rare scenario, but not impossible as you can not guarantee there won't be any tokens locked in the contract that's why I consider this bug as a medium

## Tools Used
Manual review 
## Recommended Mitigation Steps

Add validation for `_eBtcBalanceBefore` and `_stEthBalanceBefore` before sending all of them to the first user who opens CDP position.

```
function _sweepEbtc(uint256 _eBtcBalanceBefore) private {
    /**
        * SWEEP TO CALLER *
        */
    // Safe unchecked because known tokens
    uint256 bal = ebtcToken.balanceOf(address(this)) - _eBtcBalanceBefore;

    if (bal > 0) {
        ebtcToken.transfer(msg.sender, bal);
    }
}
```
