# Vulnerability details

## Vulnerability Details 

The _getAdjustCdpParams function it's assumes that the caller has transferred the required collateral before calling the function, and This assumption is critical as the function is proceeds to adjust the CDP without verifying the actual transfer of collateral.
```solidity
  op.tokenToTransferIn = address(stETH);
        // collateral already transferred in by the caller
        op.amountToTransferIn = 0;
        op.operationType = OperationType.AdjustCdpOperation;
        op.OperationData = abi.encode(_cdp);
```
The issue is arise from the assumption that the collateral is already transferred by the caller. This assumption is not verified within the function, is leading to  issues if the collateral is not present. so The function does not include a check in the balance of the collateral token before proceeding with the operation.
## Impact
The function is attempts to proceed with CDP adjustment without sufficient collateral, and this causing the operation to fails so if the operation does not revert, the contract is end up in an incorrect state, leading to inconsistent data and loss of funds

## Proof of Concept
Here is a scenario that show this issue :
- let's Assume that Alice has a CDP with 100 eBTC debt and 50 stETH collateral.
- Alice wants to increase her debt by 50 eBTC, which requires her to add an additional 10 stETH as collateral.
- the contract has the _getAdjustCdpParams function that assumes collateral is transferred by the caller before the function is called.
- The function does not check if the collateral is actually present in the contract.
- Now Alice decides to call the adjustCdpOperation function to increase her debt.
- Alice intends to add 10 stETH as collateral but forgets to transfer the stETH to the contract.
- Alice calls adjustCdpOperation with the following parameters:
```
    cdpId: The ID of Alice's CDP.
    flType: The type of flash loan.
    flAmount: 1000 (amount involved in the flash loan operation).
    cdp: An instance of AdjustCdpOperation with isDebtIncrease set to true, EBTCChange set to 50, stEthBalanceIncrease set to 10, and stEthBalanceDecrease set to 0.
    debt: 100 (current debt).
    coll: 50 (current collateral).
    tradeData: An instance of TradeData with necessary swap operation data.
```
- The adjustCdpOperation function is executed and Inside this function, _getAdjustCdpParams is called to set up the operation parameters and the getAdjustCdpParams assumes the collateral (10 stETH) is already transferred and sets op.amountToTransferIn to 0.
- Since Alice did not transfer the 10 stETH collateral to the contract, the contract does not have sufficient collateral for the operation.
- The function does not verify the presence of the collateral and proceeds with the operation.
- as result The contract attempts to adjust the CDP with insufficient collateral
and it's lead to one of two outcomes:
- The operation fails and reverts due to insufficient collateral during the adjustment process.
- If the operation does not revert, the contract ends up in an incorrect state with an increased debt but without the necessary collateral, potentially leading to an undercollateralized position and financial risk.
