# Vulnerability details

## Impact

Calls can be made through the Zap Router despite an expired permit deadline. Users that rely on the protocol to check for an expired deadline before their funds are transacted will be affected. The following functionality can be executed when an expired deadline should prevent such actions:

- Opening a CDP
- Closing a CDP
- Adjusting a CDP
- Adding collateral to a CDP

## Proof of Concept

In order to interact with the [EbtcZapRouter](https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-zap-router/src/EbtcZapRouter.sol) contract users must set the router as a position manager; when [opening a CDP](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/EbtcZapRouter.sol#L51) through `EbtcZapRouter` users then provide a [permit](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/EbtcZapRouter.sol#L56) to indicate this. The permit is checked [here](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/ZapRouterBase.sol#L115-L133):

```solidity
function _permitPositionManagerApproval(
    IBorrowerOperations borrowerOperations,
    PositionManagerPermit memory _positionManagerPermit
) internal {
    try
        borrowerOperations.permitPositionManagerApproval(
            msg.sender,
            address(this),
            IPositionManagers.PositionManagerApproval.OneTime,
            _positionManagerPermit.deadline,
            _positionManagerPermit.v,
            _positionManagerPermit.r,
            _positionManagerPermit.s
        )
    {} catch {
        /// @notice adding try...catch around to mitigate potential permit front-running
        /// see: https://www.trust-security.xyz/post/permission-denied
    }
}
```

A `try` statement is implemented to prevent [this](https://www.trust-security.xyz/post/permission-denied) attack. This does effectively mitigate the attack. However a new issue is introduced.

When [setting a position manager](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/BorrowerOperations.sol#L626-L637) users have the [option](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/Interfaces/IPositionManagers.sol#L6-L10) to set the `PositionManagerApproval` to `Persistent` or `OneTime`. Meaning the position manager can make calls on behalf of the user continuously or only once respectively. The issue is introduced when users set the Zap Router as a `Persistent` position manager and the [deadline](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/interface/IEbtcZapRouterBase.sol#L6) is reached.

`_permitPositionManagerApproval()` will `try` to call `permitPositionManagerApproval()` and since the deadline has expired the call will fail. The `catch` clause will then be triggered at which point no logic is executed, since it is empty, and the transaction continues. Below is a test case that demonstrates this.

pragma solidity 0.8.17;

import {Test} from "forge-std/Test.sol";
import {EbtcZapRouter} from "../src/EbtcZapRouter.sol";
import {IERC20} from "@ebtc/contracts/Dependencies/IERC20.sol";
import {IStETH} from "../src/interface/IStETH.sol";
import {IBorrowerOperations} from "@ebtc/contracts/LeverageMacroBase.sol";
import {BorrowerOperations} from "@ebtc/contracts/BorrowerOperations.sol";
import {ICdpManager} from "@ebtc/contracts/Interfaces/ICdpManager.sol";
import {IEbtcZapRouterBase} from "../src/interface/IEbtcZapRouterBase.sol";
import {IPositionManagers} from "@ebtc/contracts/Interfaces/IPositionManagers.sol";
import {IEbtcZapRouter} from "../src/interface/IEbtcZapRouter.sol";

contract EbtcZapRouterTest is Test {
    EbtcZapRouter ebtcZapRouter;
    IStETH stEth = IStETH(0xae7ab96520DE3A18E5e111B5EaAb095312D7fE84);
    BorrowerOperations borrowerOperations = BorrowerOperations(0xd366e016Ae0677CdCE93472e603b75051E022AD0);

    function setUp() public {
        vm.createSelectFork("RPC_URL");
        ebtcZapRouter = new EbtcZapRouter(
            IERC20(0x7f39C581F595B53c5cb19bD0b3f8dA6c935E2Ca0),
            IERC20(0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2),
            stEth,
            IERC20(0x661c70333AA1850CcDBAe82776Bb436A0fCfeEfB),
            IBorrowerOperations(borrowerOperations),
            ICdpManager(0xc4cbaE499bb4Ca41E78f52F07f5d98c375711774),
            address(0xA967Ba66Fb284EC18bbe59f65bcf42dD11BA8128)
        );
    }

    function test_expiredDeadline() public {
        address user = vm.addr(1);
        address positionManager = address(ebtcZapRouter);

        // stETH holder transfers tokens to user
        vm.prank(address(0xE53FFF67f9f384d20Ebea36F43b93DC49Ed22753));
        stEth.transfer(user, 10e18);

        vm.prank(user);
        stEth.approve(address(ebtcZapRouter), type(uint256).max);

        uint256 deadline = (block.timestamp + 1800);
        IPositionManagers.PositionManagerApproval approval = IPositionManagers.PositionManagerApproval.Persistent;

        vm.startPrank(user);
        bytes32 digest = _generatePermitSignature(user, positionManager, approval, deadline);
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(1, digest);
        vm.stopPrank();

        IEbtcZapRouter.PositionManagerPermit memory positionManagerPermit = IEbtcZapRouterBase.PositionManagerPermit(deadline, v, r, s);

        vm.prank(user);
        borrowerOperations.setPositionManagerApproval(address(ebtcZapRouter), IPositionManagers.PositionManagerApproval.Persistent);

        // Skip past the deadline
        vm.warp(deadline + 100);

        // Call succeeds despite expired deadline
        vm.prank(user);
        ebtcZapRouter.openCdp(1000, bytes32(0), bytes32(0), 10e18, positionManagerPermit);
    }

    function _generatePermitSignature(
        address _signer,
        address _positionManager,
        IPositionManagers.PositionManagerApproval _approval,
        uint _deadline
    ) internal view returns (bytes32) {
        bytes32 digest = keccak256(
            abi.encodePacked(
                "\x19\x01",
                borrowerOperations.DOMAIN_SEPARATOR(),
                keccak256(
                    abi.encode(
                        borrowerOperations.permitTypeHash(),
                        _signer,
                        _positionManager,
                        _approval,
                        borrowerOperations.nonces(_signer),
                        _deadline
                    )
                )
            )
        );
        return digest;
    }
}

## Recommended Mitigation Steps

The `try` statement effectively mitigates `permitPositionManagerApproval()` front-running attacks for `OneTime` permits without introducing any new issues, however consider the edge cases when it comes to `Persistent` permits and add sanity checks e.g.:

```diff
function _permitPositionManagerApproval(
    IBorrowerOperations borrowerOperations,
    PositionManagerPermit memory _positionManagerPermit
) internal {
    try
        ...
    {} catch {
        /// @notice adding try...catch around to mitigate potential permit front-running
        /// see: https://www.trust-security.xyz/post/permission-denied
+       if (_positionManagerPermit.deadline >= block.timestamp) {
+           return;
+       }
    }
+   revert("Permit failure");
}
```
