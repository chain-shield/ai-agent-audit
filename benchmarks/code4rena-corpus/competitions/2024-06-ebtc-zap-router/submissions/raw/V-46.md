# Vulnerability details

## Impact

This could allow users to artificially inflate the amount of stETH or wstETH they receive when closing their CDP. An attacker could exploit this to drain excess collateral from the protocol, leading to losses. This has a direct impact on the protocol's funds and the relative ease of exploitation.

## Proof of Concept

Look at the `_closeCdp` function of the `EbtcLeverageZapRouter` contract: https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/EbtcLeverageZapRouter.sol#L276-L308

```solidity
function _closeCdp(
    bytes32 _cdpId,
    bytes calldata _positionManagerPermit,
    bool _useWstETH,
    TradeData calldata _tradeData
) internal nonReentrant {
    // ... (omitted code for brevity)

    uint256 _zapStEthBalanceBefore = stEth.balanceOf(address(this));
    _closeCdpOperation({
        _cdpId: _cdpId,
        _debt: debt,
        _tradeData: _tradeData
    });
    uint256 _zapStEthBalanceAfter = stEth.balanceOf(address(this));
    uint256 _stETHDiff = _zapStEthBalanceAfter - _zapStEthBalanceBefore;

    _transferStEthToCaller(_cdpId, EthVariantZapOperationType.CloseCdp, _useWstETH, _stETHDiff);
}
```

As seeen, the function calculates the amount of stETH to return based on the difference in the contract's stETH balance before and after the `_closeCdpOperation`. This approach is vulnerable to manipulation.

Let's consider a scenario:
1. Alice wants to close her CDP, which has 100 stETH as collateral.
2. Just before Alice's transaction is processed, an attacker Bob sends 50 stETH directly to the `EbtcLeverageZapRouter` contract.
3. Alice's `_closeCdp` function executes:
   - `_zapStEthBalanceBefore` is recorded as 50 (the amount Bob sent)
   - The CDP is closed, releasing Alice's 100 stETH
   - `_zapStEthBalanceAfter` is now 150 (Bob's 50 + Alice's 100)
   - `_stETHDiff` is calculated as 150 - 50 = 100
4. The function transfers 100 stETH to Alice (or the equivalent in wstETH if `_useWstETH` is true)
5. Bob withdraws his 50 stETH in a separate transaction

Finally, Alice receives 100 stETH instead of the 50 stETH she should have received (assuming 50% of the collateral was used to repay the debt). The protocol loses 50 stETH.


## Tools Used
Manual code analysis

## Recommended Mitigation Steps

The contract should not rely on balance differences. Instead, it should track the exact amount of collateral released from the CDP during the closure operation.
