# Vulnerability details

## Impact
If the `_initialETH` value is below the minimum deposit threshold, the function will deposit 0 ETH into Lido, which may result in a loss of funds.

`_depositRawEthIntoLido()` should include a check to ensure that the `_initialETH` value is greater than or equal to the minimum deposit threshold required by Lido. Without this check, if the `_initialETH` value is below the minimum threshold, the function will attempt to deposit 0 ETH.

## Proof of Concept
[ZapRouterBase.sol#L34-L40](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/ZapRouterBase.sol#L34-L41)
```solidity
function _depositRawEthIntoLido(uint256 _initialETH) internal returns (uint256) {
    uint256 _balBefore = stEth.balanceOf(address(this));
    // TODO call submit() with a referral?
    payable(address(stEth)).call{value: _initialETH}("");
    uint256 _deposit = stEth.balanceOf(address(this)) - _balBefore;
    return _deposit;
}
```
The `_initialETH` value is sent to the Lido contract without any checks on its size relative to a minimum deposit threshold. If `_initialETH` is below this threshold, the Lido contract might not issue any stETH in return, effectively resulting in a deposit of 0 ETH. This could lead to a situation where the ETH is sent but no stETH is received, which would indeed be a loss of funds.

Manual Review
## Recommended Mitigation Steps
Add a validation step in the `_depositRawEthIntoLido()` function to ensure that the `_initialETH` amount meets the minimum requirements set by Lido for deposits.
