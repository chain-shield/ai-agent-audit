# Vulnerability details

## Impact
**`_adjustCdpOperation()`** is an internal function designed to modify a CDP by increasing or decreasing the debt or collateral. To obtain the shares amount to modify the collateral is used **`getSharesByPooledEth()`** from stETH contract, in which is incorrectly used the amount of stETH instead of ETH to do the calculation, leading to an incorrect calculation of the shares obtained consequently obtaining an incorrect value for **`newColl`**.
## Proof of Concept
**`_adjustCdpOperation()`** is used to modify a CDP.
```Solidity
function _adjustCdpOperation(
        bytes32 _cdpId,
        FlashLoanType _flType,
        uint256 _flAmount,
        AdjustCdpOperation memory _cdp,
        uint256 debt,
        uint256 coll,
        TradeData calldata _tradeData
    ) internal {
        uint256 newDebt = _cdp._isDebtIncrease ? debt + _cdp._EBTCChange : debt - _cdp._EBTCChange;
        uint256 newColl = _cdp._stEthBalanceIncrease > 0 ? 
@>           coll + stEth.getSharesByPooledEth(_cdp._stEthBalanceIncrease) : 
@>           coll - stEth.getSharesByPooledEth(_cdp._stEthBalanceDecrease);

        _doOperation(
            _flType,
            _flAmount,
            _getAdjustCdpParams(_cdp, _tradeData),
            PostOperationCheck.cdpStats,
            _getPostCheckParams(
                _cdpId, 
                newDebt, 
                newColl, 
                ICdpManagerData.Status.active,
                _tradeData.collValidationBufferBPS
            ),
            _cdpId
        );

        _sweepEbtc();
        // sweepStEth happens outside of this call
    }
```
As you can see, if the collateral is modified, the function checks whether it is increased or decreased and uses **`stEth.getSharesByPooledEth()`** to calculate the shares to add or subtract from the current collateral. The issue arises because it uses stETH (**`_cdp._stEthBalanceIncrease`** or **`_cdp._stEthBalanceDecrease`**), which is incorrect. It should be using the amount of ETH, not stETH.

**`adjustCdp()`** is the entry point for a user to adjust their CDP. 

```Solidity
function adjustCdp(
        bytes32 _cdpId,
        AdjustCdpParams memory _params,
        bytes calldata _positionManagerPermit,
        TradeData calldata _tradeData
    ) external {
        uint256 _zapStEthBalanceBefore = stEth.balanceOf(address(this));
        if (_params.isStEthMarginIncrease && _params.stEthMarginBalance > 0) {
@>           _params.stEthMarginBalance = _transferInitialStETHFromCaller(_params.stEthMarginBalance); 
        }
        _adjustCdp(_cdpId, _params, _positionManagerPermit, _tradeData, _zapStEthBalanceBefore);
    }
```
As you can see, **`_params.stEthMarginBalance`** is setting the amount of stETH instead of the amount of ETH.

[getSharesByPooledEth()](https://etherscan.io/address/0x17144556fd3424edc8fc8a4c940b2d04936d17eb#code#F27#L300) in StETH.sol is used to obtain the corresponding stETH shares for a given amount of ETH.
```Solidity
/**
     * @return the amount of shares that corresponds to `_ethAmount` protocol-controlled Ether.
     */
    function getSharesByPooledEth(uint256 _ethAmount) public view returns (uint256) {
        return _ethAmount
            .mul(_getTotalShares())
            .div(_getTotalPooledEther());
    }
```
As you can see, it specifies that the amount needs to be in ETH, not stETH. However, the protocol incorrectly uses stETH, resulting in an incorrect calculation of the shares and obtaining an incorrect value for **`newColl`** causing the postChecks could fail and reverts the transaction.
