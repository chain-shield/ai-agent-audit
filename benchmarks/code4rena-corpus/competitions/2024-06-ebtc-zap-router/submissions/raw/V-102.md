# Vulnerability details

## Impact
When making adjustments of CDP's using TradeData advesary can bypass the min amount out to sandwich attack swaps done up to an arbitrary value.

## Proof of Concept
The `LeverageZapRouterBase` contract allows users to make adjustments to cdps and include a `TradeData` field. This struct contains a field called `expectedMinOut` which will dictate the minimum amount of tokens out the user will accept in the swap to avoid slippage and MEV.

```solidity 
interface IEbtcLeverageZapRouter is IEbtcZapRouterBase {
...
    struct TradeData {
        bytes exchangeData;
>>      uint256 expectedMinOut;
        bool performSwapChecks;
        uint256 approvalAmount;
        uint256 collValidationBufferBPS;
    }
```

If the adjustment is a debt increase then the swap that the trade data will be used for will be an eBTC to STETH swap. After the swap is made on the hardcoded DEX the function `_doSwapChecks` is called. This function iterates through the swaps (in this case the single swap above) and checks that the contract holds more than the minimum amount of the token out (STETH).


For the `_adjustCdpOperation` method unlike the `_openCdp` method only eBTC is swept and returned to the user at the end of the call which transfers all eBTC in the contract to the user. Then in the outside method `_adjustCdp` only the STETH difference is swept up, this being the difference in STETH in the contract between the start and end of the transaction. This means that any STETH in the contract beforehand will remain there.


If there is any STETH in the contract therefore before the transaction begins the swap will only need to receive `[Min Amount - Starting Contract STETH]` to be satisfied. Once the swap is complete only the added STETH will be returned to the message sender and the starting STETH will remain in the contract.

Another user can then call the `openCdp` with the minimum amount. At the end of the transaction `_sweepStEth` is called in the `_openCdpOperation` function returning all STETH to them including any that was present in the contract before the transaction.

```solidity 
abstract contract LeverageZapRouterBase {
...
    function _openCdpOperation(
        bytes32 _cdpId,
        OpenCdpForOperation memory _cdp,
        uint256 _flAmount,
        TradeData calldata _tradeData
    ) internal {
	    ...
        _sweepEbtc();
>>      _sweepStEth();
    }
```

Given the above the steps to exploit are:


  1. Adversary sees `adjustCdp` transaction in mempool and frontruns it sending contract STETH. The amount is calculated to optimise  how far past the users given minimum amount out we want to push the swap.
  2. The swap being made is also frontrun extracting malicious MEV from the user, greater than their given slippage.
  3. Adversary then backruns the transaction calling  `openCdp` with the minimum amount to return them their remaining STETH. They can then close this immediately if desired.

## Recommended Mitigation Steps

One possible avenue would be to simply bring parity to the cdp operations and add a sweep STETH in `_adjustCdpOperation` here:
```solidity 
    function _adjustCdpOperation(
        bytes32 _cdpId,
        FlashLoanType _flType,
        uint256 _flAmount,
        AdjustCdpOperation memory _cdp,
        uint256 debt,
        uint256 coll,
        TradeData calldata _tradeData
    ) internal {
	    ...
        _sweepEbtc();
++      _sweepStEth();
    }
```

Another solution would be to use the starting token balance in the swap check in the same way that it is used when returning the steth in the `LeverageMacroBase` contract.

```solidity 
    function _doSwapChecks(SwapCheck[] memory swapChecks) internal {
        uint256 length = swapChecks.length;
        unchecked {
            for (uint256 i; i < length; ++i) {
                // > because if you don't want to check for 0, just don't have the check
                require(
                    IERC20(swapChecks[i].tokenToCheck).balanceOf(address(this)) >
++                      swapChecks[i].expectedMinOut + swapChecks[i].startingTokenBalance,
                    "LeverageMacroReference: swap check failure!"
                );
            }
        }
    }
```
