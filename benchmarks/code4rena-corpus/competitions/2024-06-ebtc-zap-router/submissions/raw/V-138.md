# Vulnerability details

## Summary 
Malicous user can abuse with `TradeData` parameters as there's no validation for some of them.

## Proof of Concept
Possible scenarios
1. User can execute any method from `1inch` or `0x` different than `swap` by passing malicious arbitrary data
2. User can pass any tokens different than `eBTC` or `stETH` to try to execute `swap`
3. User can approve more tokens than needed by `TradeData.approvalAmount`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add validation for 
1. `TradeData.exchangeData` to ensure only `swap` operations can be executed
2. `TradeData.exchangeData` to ensure only `eBTC` and `stETH` can be swapped 
3. `TradeData.approvalAmount` is no more than the `debt`

In `LeverageMacroBase` before executing `excessivelySafeCall` at L463 decode `swapData.calldataForSwap` and add validation for `selector` (DEX method), and that `tokenIn`,`tokenOut` are either `eBTC` or `stETH`.
