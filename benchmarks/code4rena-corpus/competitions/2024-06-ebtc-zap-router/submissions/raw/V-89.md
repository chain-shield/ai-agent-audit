# Vulnerability details

## Proof of Concept
The vulnerability revolves around the incorrect handling of the collateral value when opening a Collateralized Debt Position (CDP) through the [openCdpWithEth](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/EbtcLeverageZapRouter.sol#L34) function. This issue stems from the fact that the function calculates the correct amount of `stETH` (`_collVal`) to be used as collateral by converting the margin balance from raw Ether to `stETH`. However, this calculated value is not properly utilized in the subsequent [_openCdp](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/EbtcLeverageZapRouter.sol#L205) function call, where the actual collateral amount (`_stEthDepositAmount`) is used instead of `_collVal`.

Despite calculating `_collVal` correctly, the `_openCdp` function is called with `_stEthDepositAmount` as the collateral amount. This means that the function operates with an incorrect collateral value, potentially leading to mismanagement of the CDP's collateralization ratio (CR).

## Impact
By not utilizing the correctly converted `stETH` value (`_collVal`) as the collateral amount, the system may underestimate or overestimate the collateralization ratio (CR), which is crucial for maintaining the health of the CDPs. This could result in users being able to open CDPs with insufficient collateral, increasing the risk of liquidation events or other unintended consequences.

## Tools Used
Manual
## Recommended Mitigation Steps
 The `_openCdp` function should be modified to accept `_collVal` as the actual collateral value to be used when opening a CDP.
