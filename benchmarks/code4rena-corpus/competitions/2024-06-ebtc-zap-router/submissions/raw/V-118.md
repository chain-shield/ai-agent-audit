# Vulnerability details

## Proof of Concept
In the [_depositRawEthIntoLido](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/ZapRouterBase.sol#L38) function of the `ZapRouterBase` contract, there is a potentially unsafe transfer of ETH to the `stEth` contract using a low-level call. The function sends `_initialETH` without verifying if the transfer was successful. This is done using the following line:
```solidity
payable(address(stEth)).call{value: _initialETH}("");
```
The purpose of this function is to deposit raw ETH into the Lido staking protocol and return the amount of `stETH` received. However, if the call to `stEth` fails (e.g., if the stEth contract reverts), the transaction will not throw an error, and the function will continue executing, leading to an incorrect calculation of the `_deposit` value.


## Impact
If the transfer of ETH to the `stEth` contract fails, the function will not revert, resulting in an inaccurate `_deposit` value. This could lead to incorrect state updates, potential loss of funds, and overall unexpected behavior in the contract logic.


## Tools Used
Manual
## Recommended Mitigation Steps
The return value of the low-level call should be checked, and the transaction should revert if the call fails. 
```solidity
function _depositRawEthIntoLido(uint256 _initialETH) internal returns (uint256) {
    // check before-after balances for 1-wei corner case
    uint256 _balBefore = stEth.balanceOf(address(this));
    // call submit() with a referral if needed
    (bool success, ) = payable(address(stEth)).call{value: _initialETH}("");
    require(success, "EbtcZapRouter: ETH deposit to Lido failed");
    uint256 _deposit = stEth.balanceOf(address(this)) - _balBefore;
    return _deposit;
}

```
