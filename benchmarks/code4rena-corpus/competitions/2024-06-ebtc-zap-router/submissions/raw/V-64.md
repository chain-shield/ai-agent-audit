# Vulnerability details

Title:
Reentrancy Attack in flashLoan Function

Severity:
High

Description:
The flashLoan function in the EbtcLeverageZapRouter.sol contract is vulnerable to a reentrancy attack. This vulnerability allows an attacker to manipulate the contract’s state by making nested calls to the function before its execution is complete. The external call to the lending protocol’s flashLoan method can potentially invoke a contract controlled by an attacker, enabling them to re-enter the flashLoan function and exploit the contract.

Affected Code:
The following code snippet from EbtcLeverageZapRouter.sol demonstrates the vulnerable flashLoan function:

solidity
Copy code
function flashLoan(uint256 amount) external {
    // 1. External call to a lending protocol to borrow funds
    lendingProtocol.flashLoan(amount);

    // 2. Perform some operations with the borrowed funds
    _executeLeverage(amount);

    // 3. Repay the flash loan
    lendingProtocol.repayLoan(amount);
}
Steps to Reproduce:
Deploy the EbtcLeverageZapRouter.sol contract.
Create a malicious contract that:
Calls the flashLoan function.
In its fallback function, re-enters the flashLoan function before the loan is repaid.
Execute the malicious contract to exploit the reentrancy vulnerability, manipulating the state of the EbtcLeverageZapRouter contract.

contract MaliciousContract {
    EbtcLeverageZapRouter zapRouter;

Recommended Fix:
To prevent reentrancy attacks, implement the ReentrancyGuard modifier or use the checks-effects-interactions pattern. Here’s an improved version of the function using ReentrancyGuard:

Using ReentrancyGuard Modifier:

solidity
Copy code
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract EbtcLeverageZapRouter is ReentrancyGuard {
    function flashLoan(uint256 amount) external nonReentrant {
        // 1. External call to a lending protocol to borrow funds
        lendingProtocol.flashLoan(amount);

        // 2. Perform some operations with the borrowed funds
        _executeLeverage(amount);

        // 3. Repay the flash loan
        lendingProtocol.repayLoan(amount);
    }
}
Using Checks-Effects-Interactions Pattern:

solidity
Copy code
function flashLoan(uint256 amount) external {
    // 1. Check the state and update it before the external call
    require(amount <= maxLoanAmount, "Loan amount exceeds limit");

    // 2. Perform some operations before the external call
    _prepareForLoan(amount);

    // 3. External call to a lending protocol to borrow funds
    lendingProtocol.flashLoan(amount);

    // 4. Complete operations with the borrowed funds
    _executeLeverage(amount);

    // 5. Repay the flash loan
    lendingProtocol.repayLoan(amount);
}
By implementing these changes, the contract ensures that no reentrant calls can manipulate its state during the execution of the flashLoan function.
