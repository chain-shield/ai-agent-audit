# Vulnerability details

## Proof of Concept
In the `LeverageZapRouterBase` contract, the [_getSwapOperations](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L232-L247) function is responsible for setting up swap operations between tokens `_tokenIn` and `_tokenOut` using a decentralized exchange (`DEX`). However, the function lacks validation to ensure that `_tokenIn` and `_tokenOut` correspond correctly to expected tokens (`ebtc` and `stETH`). This oversight can lead to unintended consequences when handling tokens within the contract's operations.
The `_getSwapOperations` function is designed to prepare swap operations based on the input and output tokens provided to it. Here’s the vulnerable code snippet:
```solidity
function _getSwapOperations(
    address _tokenIn,
    address _tokenOut,
    TradeData calldata _tradeData
) internal view returns (SwapOperation[] memory swaps) {
    //@audit-info No validation or restriction on _tokenIn and _tokenOut
    swaps = new SwapOperation ;

    swaps[0].tokenForSwap = _tokenIn;
    swaps[0].addressForApprove = DEX;
    swaps[0].exactApproveAmount = _tradeData.approvalAmount;
    swaps[0].addressForSwap = DEX;
    swaps[0].calldataForSwap = _tradeData.exchangeData;
    if (_tradeData.performSwapChecks) {
        swaps[0].swapChecks = _getSwapChecks(_tokenOut, _tradeData.expectedMinOut);            
    }
}

```
The function does not enforce any validation on `_tokenIn` and `_tokenOut` to ensure they are limited to expected tokens (`ebtc` and `stETH`). This lack of validation allows any address to be passed as `_tokenIn` and `_tokenOut`, potentially leading to incorrect token handling. Without proper validation, there is a risk that `_tokenIn` could be mistakenly handled as ebtc when it should be `stETH`, or vice versa. Similarly, `_tokenOut` could be misinterpreted, leading to unintended swap operations between incorrect tokens.
## Impact
Incorrect token handling can compromise the integrity and security of the contract. It may result in loss of funds, unexpected behavior in token swaps, or exploitation by malicious actors leveraging unexpected token interactions.
## Tools Used
Manual
## Recommended Mitigation Steps
Add a `require` statement ensures that `_tokenIn` and `_tokenOut` are either `ebtc` and `stETH` or `stETH` and `ebtc`, respectively.
