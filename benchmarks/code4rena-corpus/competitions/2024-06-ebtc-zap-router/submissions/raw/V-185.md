# Vulnerability details

## Vulnerability Details
Lido's Staked Ether (stETH) is a rebasing token that represents staked ETH in the Ethereum 2.0 beacon chain. The balance of stETH tokens can increase over time due to staking rewards, a process called rebasing. These rebases typically occur daily and affect all stETH holders simultaneously.

In DeFi protocols interfacing with stETH, it's crucial to accurately account for deposits and distinguish between balance increases due to new deposits and those resulting from rebases. Failure to do so can lead to incorrect accounting, potential exploits, and misrepresentation of user positions.

## Issue
This _depositRawEthIntoLido function may report a successful deposit even if the ETH transfer to Lido fails, due to a coincidental stETH rebase:

https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-zap-router/src/ZapRouterBase.sol#L34

```solidity
function _depositRawEthIntoLido(uint256 _initialETH) internal returns (uint256) {
    uint256 _balBefore = stEth.balanceOf(address(this));
    payable(address(stEth)).call{value: _initialETH}("");
    uint256 _deposit = stEth.balanceOf(address(this)) - _balBefore;
    return _deposit;
}
```

The issue arises because:

1. The function checks the stETH balance before and after the attempted deposit to calculate the deposited amount.
2. It doesn't verify if the `call` to Lido's contract succeeded.
3. If a rebase occurs during the execution of this function, the final balance check will show an increase, even if the ETH deposit failed.

## Impact

This can lead to:
- False reporting of successful deposits
- Incorrect accounting of user positions
- Potential loss of user funds if ETH is not actually deposited but recorded as such
- Inconsistencies in the protocol's state and collateral tracking

The impact is severe because:
- Users may believe they've deposited collateral when they haven't
- The protocol may create undercollateralized positions
- It could be exploited by malicious actors to manipulate their position's collateral ratio

To mitigate this issue, the function should:
1. Properly check the return value of the `call` to Lido
2. Use Lido's interface to call the `submit` function directly, which returns the amount of stETH minted
3. Implement a slippage check to ensure the received stETH is within an acceptable range of the expected amount
