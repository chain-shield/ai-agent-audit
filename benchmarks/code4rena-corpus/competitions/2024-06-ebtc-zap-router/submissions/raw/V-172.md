# Vulnerability details

## Impact
The `_permitPositionManagerApproval` function in `ZapRouterBase.sol` utilizes a try...catch block to handle potential failures when calling permit on `IBorrowerOperations`. However, this approach becomes ineffective if `IBorrowerOperations` has a `phantom permit` function (e.g., it does not revert when permit is called without proper approval). This could allow an attacker to front-run the permit call with a different signature, bypassing intended user approvals and potentially manipulating critical operations.

## Proof of Concept
```solidity
    function _permitPositionManagerApproval(
        IBorrowerOperations borrowerOperations,
        PositionManagerPermit memory _positionManagerPermit
    ) internal {
        try
            borrowerOperations.permitPositionManagerApproval(
                msg.sender,
                address(this),
                IPositionManagers.PositionManagerApproval.OneTime,
                _positionManagerPermit.deadline,
                _positionManagerPermit.v,
                _positionManagerPermit.r,
                _positionManagerPermit.s
            )
        {} catch {
            /// @notice adding try...catch around to mitigate potential permit front-running
            /// see: https://www.trust-security.xyz/post/permission-denied
        }
    }
```
The try...catch block used around the permit call becomes ineffective.
An attacker could exploit this by front-running the permit call with a different signature, potentially manipulating the user's approval even if the try...catch catches the revert from the front-run attempt.
This could lead to unauthorized actions, manipulation of user assets, or disruption of contract functionality.
Tokens with phantom permit functions (those that don't revert on failure) could be used with this contract in the future, leading to unexpected behaviour.

## Tools Used
Manual review
## Recommended Mitigation Steps
Consider modifying the ZapRouterBase contract to explicitly revert the `_permitPositionManagerApproval` function if the permit call fails.
Explicitly reverting in `_permitPositionManagerApproval` provides clearer error messages to users in case of permit failures.
