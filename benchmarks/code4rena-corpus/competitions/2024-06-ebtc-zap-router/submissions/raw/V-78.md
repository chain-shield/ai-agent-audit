# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Issue: Unexpected Ether Balance (SWC-132)
Location: ZapRouterBase.sol, Line 45

The contract may hold unexpected Ether balances due to the lack of validation after the transferFrom call. This could lead to potential loss of funds or misuse.

Unprotected Ether withdrawal due to missing or insufficient access controls can allow malicious parties to withdraw Ether from the contract account. This bug may be caused by unintentionally exposing initialization functions or by incorrectly naming a constructor function, causing the constructor code to be included in the runtime bytecode and callable by anyone to re-initialize the contract. Unauthorized withdrawals can lead to significant financial loss and compromise the integrity and security of the smart contract.

## Recommended Mitigation Steps
Ensure that the transferFrom call is validated to confirm the transfer was successful. This can be done by wrapping the transferFrom call with a require statement to revert the transaction if the transfer fails.

Code After Mitigation:
```sol
require(
    wrappedEth.transferFrom(msg.sender, address(this), _initialWETH),
    "Transfer of WETH failed"
);
```

Code Before Mitigation:
EbtcLeverageZapRouter.sol
***openCdpWithWrappedEth function:***
```sol
        uint256 _collVal = _convertWrappedEthToStETH(_wethMarginBalance);
```
***adjustCdpWithWrappedEth function:***
```sol
_params.stEthMarginBalance = _convertWrappedEthToStETH(_params.stEthMarginBalance);
```
Code After Mitigation:
EbtcLeverageZapRouter.sol
***openCdpWithWrappedEth function:***
```sol
        uint256 _collVal = _convertWrappedEthToStETH(_wethMarginBalance);
require(_collVal > 0, "Invalid collateral value");
```
***adjustCdpWithWrappedEth function:***
```sol
_params.stEthMarginBalance = _convertWrappedEthToStETH(_params.stEthMarginBalance);
require(_params.stEthMarginBalance > 0, "Invalid collateral value");
```

This change ensures that the contract only proceeds if the transfer of WETH to the contract is successful, preventing any unexpected Ether balances.

By adding require statements to check the success of the transferFrom function and ensuring the collateral value is greater than zero, the vulnerability related to unprotected Ether withdrawal is mitigated. This prevents unauthorized users from exploiting the contract to withdraw Ether.
