# Vulnerability details

## Impact
When user open Cdp with leverage, he potentially wants his collateral to be as large as possible not fall below some lower bound. To allow the user to set such a boundary, the protocol has a parameter [collValidationBufferBPS in the struct TradeData](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/interface/IEbtcLeverageZapRouter.sol#L50).
By setting the comparison operator [gte](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L269) in the function [_getPostCheckParams](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L257), we set an upper bound for the collateral instead of a lower bound.
Thus, if a slippage occurs during cdp creation and the collateral value decreases, the function which open cdp will not revert and the user will lose part of the collateral.

To simulate a slippage situation, let's add the following code to the `BorrowerOperations` contract on [line 522](https://github.com/ebtc-protocol/ebtc/blob/2da05f2d1354190eacf64ec256d2c5c5358e5fa2/packages/contracts/contracts/BorrowerOperations.sol#L522) (add this only for testing, not for real contract)

```diff
+        /// @note add for test
+       uint256 IDfromTest = 26189721900423420331969230490131130767792397847514657037538250302899882033153;
+       if (_cdpId == bytes32(IDfromTest)) {
+          _netCollAsShares = _netCollAsShares - 1e18;
+       }
```

This piece of code will model collateral slippage for our CdpId at 1e18 stETH shares.

The test won't revert even if we lower the collateral by 10e18 stETH shares or more.
Thus the user's lower bound collateral is limited only by `BorrowerOperations` contract internal checks for compliance with the ICR(MCR, etc) and the user may lose some collateral when slippage occurs.

## Recommended Mitigation Steps

1. Change the comparison operator in [line 269](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L269) to lte.

```diff
-   operator: Operator.gte
+   operator: Operator.lte
```

2. Change the value of `collValidationBufferBPS` in test files `LeverageZaps.t.sol` and `TargetFunctionsWithLeverage.sol` from 10500 to 9500. 9500 would mean that our collateral could decline by no more than 5%.
