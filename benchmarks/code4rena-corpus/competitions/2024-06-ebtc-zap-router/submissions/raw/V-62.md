# Vulnerability details

`LeverageZapRouterBase` contract implements token sweeping mechanisms through the `_sweepEbtc()` and `_sweepStEth()` functions. These functions are designed to transfer any remaining tokens from the contract to the caller after operations. However, the implementation of these sweeping functions is inconsistent across different operations, **_violating the invariant that the `ZapRouter` should not hold any tokens after each operation (aside from rounding)._**

Specifically, in the `_adjustCdpOperation()` function, while `_sweepEbtc()` is called,` _sweepStEth()` is notably absent: [LeverageZapRouterBase.sol#L161-L163](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/LeverageZapRouterBase.sol#L161-L163)
```solidity
function _adjustCdpOperation( 
    bytes32 _cdpId, 
    FlashLoanType _flType, 
    uint256 _flAmount, 
    AdjustCdpOperation memory _cdp, 
    uint256 debt, 
    uint256 coll, 
    TradeData calldata _tradeData
 ) internal { // ... 
    _sweepEbtc();
// sweepStEth happens outside of this call
```
This inconsistency in token sweeping could lead to stETH tokens being left in the contract after certain operations, violating the stated invariant and potentially causing accounting issues or unexpected behavior in subsequent operations.

## Impact
Violation of the contract's invariant that it should not hold tokens after operations
Accounting discrepancies in subsequent operations
Possible loss of user funds if tokens are left in the contract and not properly accounted for

## Proof of Concept
1. User initiates an `adjustCdp` operation that involves stETH
2. The `_adjustCdpOperation()` function is called
3. The operation completes, and `_sweepEbtc()` is called
4. Any remaining stETH is not swept, as `_sweepStEth()` is not called within this function
5. The contract retains a balance of stETH, violating the invariant

## Recommended Mitigation Steps
Ensure that token sweeping is consistently handled within the contract functions that might leave a residual balance, thus adhering strictly to the invariant by `uncommenting` and properly implementing the `_sweepStEth()` call within the `_adjustCdpOperation()` or ensuring that any external handling of the sweeping is foolproof and documented to avoid oversight.
