# Vulnerability details

## Impact
The `adjustCdpWithWrappedEth` function has a misleading comment and incorrect logic.

The function `adjustCdpWithWrappedEth` in the EbtcLeverageZapRouter.sol is documented to "increase collateral with wrapped Ether" and manage debt of a CDP. However, the function's implementation converts the `_params.stEthMarginBalance` to stETH using `_convertWrappedEthToStETH`, which suggests that it is handling wrapped stETH (WstETH) instead of wrapped Ether (WETH).

This inconsistency can lead to confusion and errors, as the function name and documentation suggest that it should handle WETH, but the logic is set up for WstETH. This could result in incorrect asset handling and unexpected behavior when users interact with this function under the assumption that they are dealing with WETH.

```solidity
    function adjustCdpWithWrappedEth(
        bytes32 _cdpId,
        AdjustCdpParams memory _params,
        bytes calldata _positionManagerPermit,
        TradeData calldata _tradeData
    ) external {
        uint256 _zapStEthBalanceBefore = stEth.balanceOf(address(this));
        if (_params.isStEthMarginIncrease && _params.stEthMarginBalance > 0) {
            _params.stEthMarginBalance = _convertWrappedEthToStETH(_params.stEthMarginBalance);
        }
        _adjustCdp(_cdpId, _params, _positionManagerPermit, _tradeData, _zapStEthBalanceBefore);
    }
```
This checks if there is an intention to increase the stETH margin (`_params.isStEthMarginIncrease`) and if the `stEthMarginBalance` is greater than 0. If both conditions are met, it converts the margin balance using `_convertWrappedEthToStETH`, which is misleading given the function's name and documentation.

## Recommended Mitigation Steps
The correct approach would be to ensure that the function name, documentation, and logic are all aligned. If the function is intended to handle WETH, the conversion method and internal logic should reflect that, converting WETH to stETH as expected. If it is supposed to handle WstETH, then the function name and documentation should be updated to clearly indicate this.
