# Vulnerability details

## Impact
The `adjustCdp` function in the `EbtcLeverageZapRouter` contract allows users to manipulate their CDP's position in the sorted list through the `upperHint` and `lowerHint` parameters without proper validation. This could lead to unfair advantages in liquidation order or other priority-based operations, potentially impacting the fairness and intended functionality of the protocol.

Specifically:
1. Users could potentially position their CDPs more favorably in the queue, affecting liquidation order.
2. This manipulation could result in some users gaining unfair advantages in terms of liquidation risk or redemption priority.
3. The system's intended order of CDPs could be disrupted, leading to unexpected behavior in critical operations.
4. Depending on the implementation of the sorted list, there may be gas cost implications for CDPs at different positions in the queue. Typically, operations on CDPs at the extremes of the list (front or back) might be less expensive in terms of gas compared to those in the middle. This could potentially be exploited by users to optimize their gas costs unfairly.

While this doesn't directly lead to asset loss, it could indirectly impact user positions and system integrity over time.

## Proof of Concept
No code is provided for this PoC due to the complexity of setting up a full test environment. However, the vulnerability can be demonstrated conceptually:

1. The `AdjustCdpParams` struct in `EbtcLeverageZapRouter` includes `upperHint` and `lowerHint` parameters:

```solidity 
struct AdjustCdpParams {
    // ... other parameters ...
```

2. These parameters are part of the `AdjustCdpParams` struct, which is passed to the `adjustCdp` function without apparent validation, potentially allowing for manipulation of the CDP's position in the sorted list:
```solidity 
function adjustCdp( 
   bytes32 _cdpId, 
   AdjustCdpParams memory _params, 
   bytes calldata _positionManagerPermit,
   ```

3. A malicious user could potentially:
   - Observe the current state of the CDP list
   - Craft specific `upperHint` and `lowerHint` values to position their CDP more favorably
   - Call `adjustCdp` with these crafted hints, potentially moving their CDP to a more advantageous position in the queue

This could be particularly impactful in scenarios where CDP position affects liquidation order or redemption priority.

## Recommended Mitigation Steps
1. Implement proper validation for `upperHint` and `lowerHint` parameters in the `EbtcLeverageZapRouter` contract.
2. Consider implementing a mechanism to verify that the provided hints result in a valid and fair position in the CDP queue.
3. Add checks to ensure that the resulting position after applying these hints doesn't violate any system invariants or fairness principles.
4. Consider removing direct user control over these hint parameters and instead calculate them internally based on the CDP's characteristics.
5. If user control over these parameters is necessary, implement strict bounds on how much a CDP's position can change in a single operation.
