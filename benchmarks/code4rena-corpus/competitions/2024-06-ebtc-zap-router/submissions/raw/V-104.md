# Vulnerability details

## Proof of Concept
In the `LeverageMacroBase` contract, the [_openCdpCallback](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L510) function is responsible for opening a new CDP (Collateralized Debt Position). However, the function does not correctly pass the borrower's address to the [borrowerOperations.openCdp](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L516C26-L516C52) method. This omission can lead to inconsistencies and potential security issues in the handling of CDP ownership.

Here is the relevant portion of the LeverageMacroBase contract:
```solidity
function _openCdpCallback(bytes memory data) internal virtual {
    OpenCdpOperation memory flData = abi.decode(data, (OpenCdpOperation));

    /**
     * Open CDP and Emit event
     */
    bytes32 _cdpId = borrowerOperations.openCdp(
        flData.eBTCToMint,
        flData._upperHint,
        flData._lowerHint,
        flData.stETHToDeposit
        // Missing borrower address
    );
}
```
In the above code, the `borrowerOperations.openCdp` function is called with parameters for minting eBTC, upper and lower hints, and `stETH` deposit, but it omits the borrower's address. This could lead to the borrower being incorrectly assigned or not assigned at all.

To illustrate the correct approach, consider the [_openCdpForCallback](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L524) function, which correctly passes the borrower's address:
```solidity

    function _openCdpForCallback(bytes memory data) internal virtual {
        OpenCdpForOperation memory flData = abi.decode(data, (OpenCdpForOperation));

        /**
         * Open CDP and Emit event
         */
        bytes32 _cdpId = borrowerOperations.openCdpFor(
            flData.eBTCToMint,
            flData._upperHint,
            flData._lowerHint,
            flData.stETHToDeposit,
            flData.borrower
        );
    }
```
## Impact
The absence of the borrower's address in the `_openCdpCallback` function can lead to incorrect borrower assignments, resulting in potential security risks and mismanagement of the CDP system. This can cause operational issues, where CDPs are not correctly attributed to the contract, potentially allowing unauthorized actions.

## Recommended Mitigation Steps
The `_openCdpCallback` function should pass the contract's address `(address(this))` to the `borrowerOperations.openCdp` function. 
```solidity
function _openCdpCallback(bytes memory data) internal virtual {
    OpenCdpOperation memory flData = abi.decode(data, (OpenCdpOperation));

    /**
     * Open CDP and Emit event
     */
    bytes32 _cdpId = borrowerOperations.openCdp(
        flData.eBTCToMint,
        flData._upperHint,
        flData._lowerHint,
        flData.stETHToDeposit,
        address(this) // Specify address(this) as the borrower
    );
}
```
Update the struct too:
```solidity
struct OpenCdpOperation {
    uint256 eBTCToMint;
    bytes32 _upperHint;
    bytes32 _lowerHint;
    uint256 stETHToDeposit;
    address address(this); // Include the borrower address
}

```
