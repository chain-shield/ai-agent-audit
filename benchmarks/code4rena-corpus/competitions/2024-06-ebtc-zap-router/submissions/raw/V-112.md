# Vulnerability details

The `_doSwapChecks` function currently uses a strict greater-than (`>`) condition to check if the balance of a token after a swap exceeds the `expectedMinOut`. This logic can lead to unintended swap failures if the actual output of the swap is exactly equal to the `expectedMinOut`. Such failures can prevent swaps from completing, effectively causing a Denial of Service (DoS) for users who set `performSwapCheck` to true.

Users can choose to allow swap checks or not in the `tradeData` users who set `performSwapCheck` will encounter this error whenever the contract balance is equal to the `expectedMinOut`.
When the balance check uses `>`, it fails if the swap result is exactly equal to the `expectedMinOut`.
   This can cause swaps to fail unnecessarily, even though the result meets the acceptable minimum.

   

## Impact

user who sets slippage to to a specific  value and swap check to `true` will face swap failures if the output is exactly equal to the expected minimum. This can prevent users from completing their swaps.

## Proof of Concept
https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-protocol%2Fpackages%2Fcontracts%2Fcontracts%2FLeverageMacroBase.sol#L485-L493

```solidity
function _doSwapChecks(SwapCheck[] memory swapChecks) internal {
    uint256 length = swapChecks.length;
    unchecked {
        for (uint256 i; i < length; ++i) {
            // > because if you don't want to check for 0, just don't have the check
            require(
                IERC20(swapChecks[i].tokenToCheck).balanceOf(address(this)) >
                    swapChecks[i].expectedMinOut,
                "LeverageMacroReference: swap check failure!"
            );
        }
    }
}
```

- If a user sets `expectedMinOut` to 100 tokens and the actual swap results in exactly 100 tokens, the check `balanceOf(address(this)) > swapChecks[i].expectedMinOut` will fail.
- This failure prevents the swap from completing, effectively causing a DoS for users who set slippage.

## Recommended Mitigation Steps

Change the strict greater-than (`>`) condition to a greater than or equal to (`>=`) condition to ensure that swaps do not fail if the output is exactly equal to the `expectedMinOut`.


```solidity
function _doSwapChecks(SwapCheck[] memory swapChecks) internal {
    uint256 length = swapChecks.length;
    unchecked {
        for (uint256 i; i < length; ++i) {
            // >= to account for slippage and ensure minimum expected output
            require(
                IERC20(swapChecks[i].tokenToCheck).balanceOf(address(this)) >=
                    swapChecks[i].expectedMinOut,
                "LeverageMacroReference: swap check failure!"
            );
        }
    }
}
```
