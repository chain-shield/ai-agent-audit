# Vulnerability details

## Impact
When the number of tokens obtained from a swap exactly equals the expectedMinOut, it will revert, causing a Denial of Service (DoS). This transaction should normally execute, but due to an incorrect condition in the check, it causes a revert().

## Proof of Concept
The _doSwapChecks function is called within the _doSwap function as a means of slippage protection when trading with a DEX, to ensure that the number of tokens received from the trade is >= expectedMinOut.
Therefore, to provide effective protection, expectedMinOut should not be set to 0.

```javascript
  function _doSwapChecks(SwapCheck[] memory swapChecks) internal {
        uint256 length = swapChecks.length;
        unchecked {
            for (uint256 i; i < length; ++i) {
                // > because if you don't want to check for 0, just don't have the check
                require(
@>>                    IERC20(swapChecks[i].tokenToCheck).balanceOf(address(this)) >
                        swapChecks[i].expectedMinOut,
                    "LeverageMacroReference: swap check failure!"
                );
            }
        }
    }
```
However, from the comments in the function, it can be seen that in order to avoid a scenario where 0 equals 0, only the ‘>’ symbol is used as the condition for comparison. This is not the correct approach.
