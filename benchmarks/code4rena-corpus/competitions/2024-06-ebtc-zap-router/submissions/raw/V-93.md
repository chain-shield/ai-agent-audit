# Vulnerability details

## Impact

```solidity
// File: ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol
485:    function _doSwapChecks(SwapCheck[] memory swapChecks) internal {
        ...
490:                require(
491:                    IERC20(swapChecks[i].tokenToCheck).balanceOf(address(this)) > // <= FOUND: reading via `balanceOf` will include pre-existing balance before the swap
492:                        swapChecks[i].expectedMinOut,
493:                    "LeverageMacroReference: swap check failure!"
494:                );
495:            }
        ...
497:    }
```

The `_doSwapChecks` function is designed to check if the `tokenToCheck` balance after a swap is larger than the `expectedMinOut` amount to prevent slippage. However, the function reads the entire `balanceOf(address(this))` which may account all pre-existing tokens instead of calculating the balance change. That means, with the existing balance, the return value of `balanceOf` could easily exceed the `expectedMinOut` and the actual swap returns will be overlooked.

In cases where operations are conducted via a multi-purpose Smart Contract Wallet where the `sweepToCaller` has to be manually `delegatecall` to clear out tokens to the caller, it is easy to leave a significant amount of tokens in the wallet. Consequently, a `balanceOf` read would mistakenly account for these pre-existing tokens in the slippage check, failing to protect the user's funds in case of swap loss. This issue makes the CDP operations susceptiple to sandwich attacks.

## Proof of Concept

https://gist.github.com/hungdoo/3b690b5b1ed116c5fb04e40cb3be1cd9

The POC introduces a test where a CDP close operation with leverage of `eBTC` was executed via a `delegatecall` to a Smart Contract wallet in which the pre-existing `eBTC` tokens were not swept out yet. Apply this patch and run following command:

Following the test results, it is confirmed that extra eBTC tokens inside the smart contract (SC) wallet were unintentionally transferred out to the Flashloan provider due to a bug in LeverageMacroBase::_doSwapChecks. The sandwich attack is not demonstrated in the proof of concept (POC); however, it is clear that such an attack would force the user to sell the collateral at a much undervalued price. The eBTC loan provider unknowingly takes extra eBTC from the user's SC wallet to complete the Flashloan operation, so it is not affected. After all, the eBTC loss incurred in the user's SC wallet would translate into the attacker's profits in more collateral tokens after buying back at a lower price.

## Recommended Mitigation Steps

The `_doSwap` function (which calls `_doSwapChecks`) should implement a BEFORE balance reading based on `swapData.swapChecks` and then pass that record to `_doSwapChecks` after the swap. This ensures that only the balance changes due to the swap are considered, accurately protecting against slippage.
