# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Ability to generate random numbers is very helpful in all kinds of applications. One obvious example is gambling DApps, where pseudo-random number generator is used to pick the winner. However, creating a strong enough source of randomness in Ethereum is very challenging. For example, use of block.timestamp is insecure, as a miner can choose to provide any timestamp within a few seconds and still get his block accepted by others. Use of blockhash, block.difficulty and other fields is also insecure, as they're controlled by the miner. If the stakes are high, the miner can mine lots of blocks in a short time by renting hardware, pick the block that has required block hash for him to win, and drop all others.

The use of block attributes such as block.number to generate randomness in Ethereum smart contracts is insecure. Miners can manipulate these attributes to their advantage, particularly in scenarios with high stakes such as gambling DApps or any application where randomness is crucial. This could lead to predictable outcomes, undermining the integrity of the system.

## Recommended Mitigation Steps
To mitigate this vulnerability, you can implement an expiration check based on the block number to ensure that the CDP creation request is only valid within a certain block range. This reduces the window of opportunity for a miner to manipulate the randomness.

Code Before Mitigation:
```sol
function _openCdp(
    uint256 _debt,
    bytes32 _upperHint,
    bytes32 _lowerHint,
    uint256 _stEthLoanAmount,
    uint256 _stEthMarginAmount,
    uint256 _stEthDepositAmount,
    bytes calldata _positionManagerPermit,
    TradeData calldata _tradeData
) internal nonReentrant returns (bytes32 cdpId) {
   
    _requireZeroOrMinAdjustment(_debt);
    _requireAtLeastMinNetStEthBalance(_stEthDepositAmount - LIQUIDATOR_REWARD);

    if (_positionManagerPermit.length > 0) {
        PositionManagerPermit memory approval = abi.decode(_positionManagerPermit, (PositionManagerPermit));
        _permitPositionManagerApproval(borrowerOperations, approval);
    }

    // pre-compute cdpId for post checks
    cdpId = sortedCdps.toCdpId(msg.sender, block.number, sortedCdps.nextCdpNonce());

    OpenCdpForOperation memory cdp;

    cdp.eBTCToMint = _debt;
    cdp._upperHint = _upperHint;
    cdp._lowerHint = _lowerHint;
    cdp.stETHToDeposit = _stEthDepositAmount;
    cdp.borrower = msg.sender;

    _openCdpOperation({
        _cdpId: cdpId,
        _cdp: cdp,
        _flAmount: _stEthLoanAmount,
        _tradeData: _tradeData
    });
```

```sol
    uint256 _debt,
    bytes32 _upperHint,
    bytes32 _lowerHint,
    uint256 _stEthLoanAmount,
    uint256 _stEthMarginAmount,
    uint256 _stEthDepositAmount,
    bytes calldata _positionManagerPermit,
    TradeData calldata _tradeData
) internal nonReentrant returns (bytes32 cdpId) {
   
    _requireZeroOrMinAdjustment(_debt);
    _requireAtLeastMinNetStEthBalance(_stEthDepositAmount - LIQUIDATOR_REWARD);

    if (_positionManagerPermit.length > 0) {
        PositionManagerPermit memory approval = abi.decode(_positionManagerPermit, (PositionManagerPermit));
        _permitPositionManagerApproval(borrowerOperations, approval);
    }

    // pre-compute cdpId for post checks
    uint256 currentBlock = block.number;
    uint256 nonce = sortedCdps.nextCdpNonce();
    cdpId = sortedCdps.toCdpId(msg.sender, currentBlock, nonce);

    // Add expiration check
    uint256 expirationBlock = currentBlock + 10; // Set expiration to 10 blocks after the current block
    require(block.number <= expirationBlock, "CDP creation request has expired");

    OpenCdpForOperation memory cdp;

    cdp.eBTCToMint = _debt;
    cdp._upperHint = _upperHint;

}
```
