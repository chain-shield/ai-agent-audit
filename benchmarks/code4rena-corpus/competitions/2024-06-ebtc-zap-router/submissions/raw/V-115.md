# Vulnerability details

## Impact
The return value of the low-level call in `_depositRawEthIntoLido` is unchecked which allows the possibility of the call failing while the transaction continues without reverting.

## Vulnerability details

The call function returns a boolean value indicating whether the call was successful. However, it is important to note that this return value is not being checked in the current implementation of `_depositRawEthIntoLido`.
As a result, there is a possibility that the call wasn't successful, while the transaction continues execution without reverting.
As seen below, the return value of the call is not checked. [ZapRouterBase.sol#L38](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-zap-router/src/ZapRouterBase.sol#L38).
 ```
    function _depositRawEthIntoLido(uint256 _initialETH) internal returns (uint256) {
        // check before-after balances for 1-wei corner case
        uint256 _balBefore = stEth.balanceOf(address(this));
        // TODO call submit() with a referral?
        // @audit the call's return value is not checked.
        payable(address(stEth)).call{value: _initialETH}("");
        // The function then continues execution without checking if the call was successful.
        uint256 _deposit = stEth.balanceOf(address(this)) - _balBefore;
        return _deposit;
    }
 ```
