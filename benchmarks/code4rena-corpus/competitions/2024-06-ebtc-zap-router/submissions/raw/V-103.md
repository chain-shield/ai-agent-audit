# Vulnerability details

## Impact

The vulnerability involves multiple token swaps without setting `amountOutMinimum`, leading to:

1. **Front Running Attacks**: Malicious actors can profit from price changes by inserting transactions ahead of victims.
2. **Sandwich Attacks**: Attackers can manipulate prices by placing transactions before and after the victim's.
3. **Price Manipulation**: Without slippage protection, attackers can cause victims to receive worse rates than expected.

## Proof of Concept

The [_doSwap](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L448-L481) function lacks slippage protection:

```solidity
function _doSwap(SwapOperation memory swapData) internal {
    _ensureNotSystem(swapData.addressForSwap);
    
    IERC20(swapData.tokenForSwap).safeApprove(
        swapData.addressForApprove,
        swapData.exactApproveAmount
    );
    
    (bool success, ) = excessivelySafeCall(
        swapData.addressForSwap,
        gasleft(),
        0,
        0,
        swapData.calldataForSwap
    );
    require(success, "Call has failed");
    
    IERC20(swapData.tokenForSwap).safeApprove(swapData.addressForApprove, 0);
    
    _doSwapChecks(swapData.swapChecks);
}
```
This function performs token swaps without setting amountOutMinimum, leaving transactions vulnerable to attacks.

## Tools Used

in-house tool, manual analysis

## Recommended Mitigation Steps

1. Implement Slippage Protection:
Add amountOutMinimum parameter to all token swap operations:

```solidity
function _doSwap(SwapOperation memory swapData) internal {
    require(swapData.amountOutMinimum > 0, "Invalid amountOutMinimum");
    // ... existing code ...
}
```

2. Implement Front Running and Sandwich Attack Mitigations:
Use techniques like time-weighted average price (TWAP) or oracle-based price feeds.
