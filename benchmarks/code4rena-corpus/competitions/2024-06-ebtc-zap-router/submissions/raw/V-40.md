# Vulnerability details

## Impact
CDP operations can be performed even when the permit is expired, results in unexpected behavior.

## Proof of Concept
When a user submits to perform CDP operations (open / close / adjust), `_positionManagerPermit` can be passed to set position manager permit required for Zap approved by calling user. [permitPositionManagerApproval()](https://etherscan.io/address/0xd366e016Ae0677CdCE93472e603b75051E022AD0#code#F1#L710) in BorrowerOperations contract will be called to set the approval, and there are 2 checks: permit deadline check and signature check.
```
    function permitPositionManagerApproval(
        address _borrower,
        address _positionManager,
        PositionManagerApproval _approval,
        uint256 _deadline,
        uint8 v,
        bytes32 r,
        bytes32 s
    ) external override {
@>      require(_deadline >= block.timestamp, "BorrowerOperations: Position manager permit expired");

        ...

@>      require(
            recoveredAddress != address(0) && recoveredAddress == _borrower,
            "BorrowerOperations: Invalid signature"
        );

        ...
    }
```
In the **ZapRouter** contract, protocol adds try...catch around to **permitPositionManagerApproval()** to mitigate potential permit front-running, it simply catches the any possible error thrown by the function and proceeds.
```
    function _permitPositionManagerApproval(
        IBorrowerOperations borrowerOperations,
        PositionManagerPermit memory _positionManagerPermit
    ) internal {
        try
            borrowerOperations.permitPositionManagerApproval(
                ...
            )
@>      {} catch {
            /// @notice adding try...catch around to mitigate potential permit front-running
            /// see: https://www.trust-security.xyz/post/permission-denied
        }
    }
```
However, this can make an transaction be executed even when the permit is expired. Consider the following case:
1. Alice submits an transaction with position manager permit to adjust a leveraged CDP;
2. Alice expects the transaction to be executed within 10 minutes or not executed at all, so she set the `deadline` of the the one-time permit to be 10 minutes in the future;
3. Alice's transaction is pending for any reason (gas price went up, validator does not include TX, etc);
4. Bob sees the transaction in the mempool, he front-runs to call the permit seconds before the it becomes expired;
5. The deadline is passed and Alice's transaction gets executed, however this is not she expected.

## Recommended Mitigation Steps
Check permit deadline, if it is expired, revoke the approval and return early.
```diff
        if (_positionManagerPermit.length > 0) {
```
