# Vulnerability details

When calculating new collateral amount in [_adjustCdpOperation](https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-zap-router/src/LeverageZapRouterBase.sol#L142C16-L142C2) function its using [stETH](https://etherscan.io/address/0xae7ab96520de3a18e5e111b5eaab095312d7fe84#readProxyContract) contract & invoked getSharesByPooledEth function. Here its used stEth amount to calculate collateral amount but it should be used eth amount to calculate collateral amount.

## Proof of Concept

```solidity
 uint256 newColl = _cdp._stEthBalanceIncrease > 0 ? 
            coll + stEth.getSharesByPooledEth(_cdp._stEthBalanceIncrease) : 
            coll - stEth.getSharesByPooledEth(_cdp._stEthBalanceDecrease);

```
This is the implementation of the [getSharesByPooledEth](https://etherscan.io/address/0x17144556fd3424EDC8Fc8A4C940B2D04936d17eb#code#F27#L300) funciton

```solidity

 /**
     * @return the amount of shares that corresponds to `_ethAmount` protocol-controlled Ether.
     */
    function getSharesByPooledEth(uint256 _ethAmount) public view returns (uint256) {
        return _ethAmount
            .mul(_getTotalShares())
            .div(_getTotalPooledEther());
    }
```
Also [here](https://etherscan.io/address/0xae7ab96520de3a18e5e111b5eaab095312d7fe84#readProxyContract#F5) its not 1:1 conversion of eth to stETH. Currenlty for 1e18 eth return ~= 0.85 e18 shares. 

## Impact
Due to stEth convert again , users deposit amount is reduced significantly. (1-0.85 = 15% reduction)
