# Vulnerability details

## Impact

The `receive` function is designed to block ETH transfers from users except for the wrappedETH address. However, there is a way for users to send ETH with the current implementation.

## Proof of Concept

The contract blocks ETH transfers through the `receive` function but does not block transfers via the `fallback` function. This allows a malicious actor to send ETH to the router using the `fallback` function.

Scenario:
1. A user creates a smart contract and locks some ETH in it.
2. The user then destroys the smart contract using the `selfdestruct` function.
3. The smart contract sends all its ETH to the address specified by the user, which in this case, would be the router.

## Tools Used

Manual Review

## Recommended Mitigation Steps

- Add a `fallback` function that blocks ETH transactions to prevent ETH from being sent to the router.

```solidity
fallback() external payable {
    require(
            msg.sender == address(wrappedEth),
            "EbtcLeverageZapRouter: only allow Wrapped ETH to send Ether!"
        );
}
```

By implementing this fallback function, the contract will block any ETH transactions that do not come from the specified wrappedETH address, effectively preventing malicious actors from sending ETH to the router using methods like `selfdestruct`.
