# Vulnerability details

## Proof of Concept
The [flashLoan](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/BorrowerOperations.sol#L1083-L1122) function does not fully adhere to EIP-3156 security considerations, specifically regarding automatic approvals and data verification. Below are the relevant parts of the code and detailed analysis.

Code Snippet:
```SOLIDITY
// Flash Loan Function
function flashLoan(
    IERC3156FlashBorrower receiver,
    address token,
    uint256 amount,
    bytes calldata data
) external override returns (bool) {
    require(amount > 0, "BorrowerOperations: 0 Amount");
    uint256 fee = flashFee(token, amount); 
    require(amount <= maxFlashLoan(token), "BorrowerOperations: Too much");

    // Issue EBTC
    ebtcToken.mint(address(receiver), amount);

    // Callback
    require(
        receiver.onFlashLoan(msg.sender, token, amount, fee, data) == FLASH_SUCCESS_VALUE,
        "IERC3156: Callback failed"
    );

    // Transfer fee and amount
    ebtcToken.transferFrom(address(receiver), feeRecipientAddress, fee + amount);

    // Burn amount
    ebtcToken.burn(feeRecipientAddress, amount);

    emit FlashLoanSuccess(address(receiver), token, amount, fee);

    return true;
}

```
The [onFlashLoan](https://github.com/code-423n4/2024-06-badger/blob/9173558ee1ac8a78a7ae0a39b97b50ff0dd9e0f8/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L394-L429) Callback Function:
```solidity
function onFlashLoan(
    address initiator,
    address token,
    uint256 amount,
    uint256 fee,
    bytes calldata data
) external returns (bytes32) {
    // Implementation specific logic
    return FLASH_SUCCESS_VALUE;
}

```
In the `flashLoan` function, the contract attempts to transfer the borrowed `amount` plus the associated `fee` from the borrower's address to the fee recipient's address. This is done using the `transferFrom` function of the ERC20 token contract:
```solidity
// Transfer fee and amount
ebtcToken.transferFrom(address(receiver), feeRecipientAddress, fee + amount);
```
The code assumes that the receiver (`borrower`) has pre-approved the flash loan contract to transfer the required amount plus the fee. There is no explicit check to ensure that such an approval exists before the flash loan is executed. This can lead to several issues:
1. Transaction Reversion:
If the `receiver` has not set the appropriate allowance for the flash loan contract, the `transferFrom` call will fail, causing the entire flash loan transaction to revert. This can disrupt the expected functionality and cause failed transactions.
2. Potential Exploits:
If an attacker can manipulate the approval settings or if the `receiver` mistakenly sets an insufficient allowance, it could lead to scenarios where the flash loan cannot be repaid properly, potentially leading to contract malfunction or financial losses.

Here, the function calculates the flash loan fee and checks that the requested amount does not exceed the maximum allowed flash loan amount.
```solidity
uint256 fee = flashFee(token, amount);
require(amount <= maxFlashLoan(token), "BorrowerOperations: Too much");
```
The function mints the required amount of tokens to the borrower's address and attempts to transfer back the borrowed amount plus the fee after the flash loan operation.

```solidity
// Issue EBTC
ebtcToken.mint(address(receiver), amount);

// Callback
require(
    receiver.onFlashLoan(msg.sender, token, amount, fee, data) == FLASH_SUCCESS_VALUE,
    "IERC3156: Callback failed"
);

// Transfer fee and amount
ebtcToken.transferFrom(address(receiver), feeRecipientAddress, fee + amount);

```
[There is no check to verify the borrower's allowance for the contract before the transferFrom call, which is a critical oversight](https://eips.ethereum.org/EIPS/eip-3156#flash-lending-security-considerations).


## Impact
If the receiver has not set the appropriate approval, the transferFrom call will fail, causing the flash loan transaction to revert. This can disrupt the expected functionality and lead to unexpected behavior or failed transactions.

## Recommended Mitigation Steps
Before issuing the flash loan, the contract should check that the `receiver` has approved the contract to transfer the required amount plus the fee. This can be achieved by adding the following check:
```solidity
require(
    ebtcToken.allowance(address(receiver), address(this)) >= amount + fee,
    "BorrowerOperations: Insufficient allowance"
);

```
