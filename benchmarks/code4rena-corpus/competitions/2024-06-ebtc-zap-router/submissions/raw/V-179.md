# Vulnerability details

## Vulnerability Summary

There is a wrong validation in the `requireSingularMarginChange` function in the EbtcLeverageZapRouter contract. It only checks that either of the 2 parameters should be 0. However, it fails to check also that both of the 2 parameters cannot be 0, that is, one of the parameters must be 0, while the other is a non-zero.

And due to its usage in `EbtcLeverageZapRouter::_adjustCdp` with respect to <marginIncrease> and <marginDecrease> calculation, Attacker can weaponize this vulnerability to clear his debt to the minimum debt (1000) without any repayment, and hence increase his position's ICR as a result. 

## Vulnerability Details

1. In the external `[adjustCdp]` function, if AdjustCdpParams.stEthMarginBalance is set to 0, there won't be any transfer of stEth from the caller, as the condition 
won't be true. The external then calls the internal `_adjustCdp` function.

Assuming the following values for the parameters below...

AdjustCdpParams.stEthBalanceChange = 0;

AdjustCdpParams.stEthMarginBalance = 0;

AdjustCdpParams.debtChange = value greater than 1000, but 1000 less than my original debt.Say, if original debt is 15_000, AdjustCdpParams.debtChange <= 14000;

AdjustCdpParams.isStEthBalanceIncrease = false;

AdjustCdpParams.isDebtIncrease = false;


2. Inside the internal `[_adjustCdp]` function, all the `requireZeroOrMinAdjustment()` checks will pass. The code then pulls the original debt and original collateral shares associated with the caller's cdpId from the cdpManager contract.

3. With the values assumed above for the AdjustCdpParams, both `uint256 marginDecrease` and `uint256 marginIncrease` will be equal to 0. Now, the check `requireNonZeroAdjustment()` will pass because AdjustCdpParams.debtChange is non-zero. Also, the check `requireSingularMarginChange` will also pass because both `uint256 marginIncrease` and `uint256 marginDecrease` are 0. 

`However, the vulnerability lies in the fact that the <requireSingularMarginChange> only checks that one of the parameters should be 0. So, both parameters can be 0, and because of the logical OR operator, the check will pass. The code fails to check that both cannot be 0 too. In fact, it's clear that, the intended functionality is to ensure that only one of <marginIncrease> or <marginDecrease> is 0, and the other is a non-zero. But this check is inefficient`


3. The code then calls the internal `[_adjustCdpOperation]` function with cdp parameters set as below:

Now inside the [_adjustCdpOperation] function, there is a calculation of "newDebt" and "newCollateral". 

 + Because AdjustCdpParams.isDebtIncrease = cdp.isDebtIncrease = false, the else part of the "newDebt" calculation will execute:
      newDebt = debt - cdp.EBTCChange(AdjustCdpParams.debtChange);

   Now, because Attacker carefully chose the debtChange value, the result of the newDebt calculation will almost be equal to 1000 or near 1000, thereby overwritting attacker's original debt to a very low value than before...

 + The new collateral calculation is dependent on the value of `stEthBalanceIncrease` (marginIncrease). Note also that, `stEthBalanceDecrease` = marginDecrease = 0. 
 Now, because this "stEthBalanceIncrease" is 0, the else part of the `new coll` will execute:
    newColl = coll - stEth.getSharesByPooledEth(cdp.stEthBalanceDecrease);
=>> newColl = coll - 0 = coll

Now, the new collateral remains the same as with the original collateral, whilst the new Debt has decreased significantly.


4. Before calling the [_doOperation] internal function, it calls the `_getPostCheckParams` function with the newDebt and newColl variables as parameters. This function sets the expectedDebt and expectedColl values to the values of newDebt and newColl respectively.

## Recommended Mitigation Steps
Effective recommended mitigation will be to also check that both marginIncrease and marginDecrease cannot be 0.  You can refine the _requireSingularMarginChange() function to match the one below:

```

function _requireSingularMarginChange(
        uint256 _stEthMarginIncrease,
        uint256 _stEthMarginDecrease
    ) internal pure {
        require(
            (_stEthMarginIncrease == 0 && _stEthMarginDecrease > 0) || (stEthMarginIncrease > 0 && _stEthMarginDecrease == 0),
            "EbtcLeverageZapRouter: Cannot add and withdraw margin in same operation"
        );
    }

```
