# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The ability to generate random numbers is crucial for applications such as gambling DApps, where pseudo-random number generators are used to pick winners. However, using block attributes like block.number for randomness is insecure because miners can influence these attributes. A miner could manipulate these values to their advantage, especially in high-stakes scenarios, leading to unfair outcomes.

## Recommended Mitigation Steps
To use expiration as a validation method to mitigate the issue of weak sources of randomness, we can introduce an expiration timestamp that ensures the operation is only valid for a specific time window. This approach does not entirely replace randomness but ensures the time window is short enough to minimize the risk of manipulation.

***Code Before Mitigation***

***Code After Mitigation***
1.	Add an expiration timestamp to the doOperation function.
```sol

    FlashLoanType flType,
```

```sol
pragma solidity ^0.8.0;

contract LeverageMacroBase {
    // Placeholder definitions for referenced types and functions
    enum FlashLoanType { Type1, Type2 }
    enum OperationType { OpenCdpOperation, OpenCdpForOperation }
    enum PostOperationCheck { none, check1, check2 }

    struct LeverageMacroOperation {
        OperationType operationType;
        bytes OperationData;
    }

    struct PostCheckParams {}

    struct OpenCdpForOperation {
        address borrower;
    }

    struct SortedCdps {
        function toCdpId(address owner, uint256 nonce1, uint256 nonce2) public returns (bytes32);
        function nextCdpNonce() public returns (uint256);
    }

    SortedCdps public sortedCdps;

    function _assertOwner() internal view {}
    function _doOperation(
        FlashLoanType flType,
        uint256 borrowAmount,
        LeverageMacroOperation calldata operation,
        PostOperationCheck postCheckType,
        PostCheckParams calldata checkParams,
        bytes32 expectedCdpId
    ) internal virtual {}

    function doOperation(
        FlashLoanType flType,
        uint256 borrowAmount,
        LeverageMacroOperation calldata operation,
        PostOperationCheck postCheckType,
        PostCheckParams calldata checkParams,
        uint256 expirationTimestamp
    ) external virtual {
        _assertOwner();

        // Check that the operation is within the valid time window
        require(block.timestamp <= expirationTimestamp, "Operation expired");

        // Figure out the expected CDP ID using sortedCdps.toCdpId
        bytes32 expectedCdpId;
        uint256 nonce = sortedCdps.nextCdpNonce();

        if (
            operation.operationType == OperationType.OpenCdpOperation &&
            postCheckType != PostOperationCheck.none
        ) {
            expectedCdpId = sortedCdps.toCdpId(
                address(this),
                block.number,

            OpenCdpForOperation memory flData = abi.decode(

            expectedCdpId = sortedCdps.toCdpId(
                flData.borrower,

            );

        _doOperation(flType, borrowAmount, operation, postCheckType, checkParams, expectedCdpId);
```

In this updated code, an expirationTimestamp is passed to the doOperation function. This timestamp is checked against the current block timestamp using require(block.timestamp <= expirationTimestamp, "Operation expired"); to ensure that the operation is only valid within a specific time window. This reduces the risk of manipulation by limiting the time frame in which a block’s attributes can be used to influence outcomes.
