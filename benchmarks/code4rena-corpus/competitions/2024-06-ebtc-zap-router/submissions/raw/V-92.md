# Vulnerability details

## Not checking return value on flashLoan contract
[LeverageMacroBase](https://github.com/code-423n4/2024-06-badger/blob/main/ebtc-protocol/packages/contracts/contracts/LeverageMacroBase.sol#L185C1-L198C15)  contract use eBTC and stETH FlashLoans without verifying the return value of the FlashLoan function. As a result, if the FlashLoan transaction fails, it can do so silently without any indication. This lack of error checking can lead to unexpected behavior and potential vulnerabilities in the contract. So It's crucial to implement proper checks to ensure the FlashLoan is successful and handle any failures appropriately.

## Proof of Concept
```solidity
        // Take eBTC or stETH FlashLoan
        if (flType == FlashLoanType.eBTC) {
            IERC3156FlashLender(address(borrowerOperations)).flashLoan(
                IERC3156FlashBorrower(address(this)),
                address(ebtcToken),
                borrowAmount,
                abi.encode(operation)
            );
        } else if (flType == FlashLoanType.stETH) {
            IERC3156FlashLender(address(activePool)).flashLoan(
                IERC3156FlashBorrower(address(this)),
                address(stETH),
                borrowAmount,
                abi.encode(operation)
            );
```
Here its the [flashLoan contract](https://etherscan.io/address/0x6dBDB6D420c110290431E863A1A978AE53F69ebC#code#F1#L337) , it returns true at the end of the execution. 

## Impact
External call could failed silently due to not checking the return value.
