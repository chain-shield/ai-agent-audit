# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The constructor of the LeverageZapRouterBase contract sets the approval amount to the maximum value (uint256.max) for several tokens. This is done using the IERC20/ERC20 interface, which grants unlimited approval to the specified addresses. This practice is risky as it could allow the approved addresses to withdraw an unlimited amount of tokens, potentially leading to significant financial losses if those addresses are compromised or malicious.

By approving the maximum amount (uint256.max), the contract exposes itself to potential abuse, where the approved entity can withdraw an unlimited amount of tokens from the contract. This could result in a complete drain of the contract’s assets, leading to severe financial damage.

ebtcToken.approve(address(borrowerOperations), type(uint256).max);

stEth.approve(address(wstEth), type(uint256).max);

## Recommended Mitigation Steps
	1.	Reduce Approval Amounts: Instead of approving the maximum amount, set the approval to a more reasonable, minimal amount necessary for the contract’s operations.
	2.	Use Safe Approve Functions: Utilize safe approval functions such as safeIncreaseAllowance and safeDecreaseAllowance from libraries like OpenZeppelin to manage token allowances safely.

Here’s an example of a safer approval process:
```sol
// Using OpenZeppelin's SafeERC20 library
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

...

using SafeERC20 for IERC20;

...

ebtcToken.safeApprove(address(borrowerOperations), initialApprovalAmount);
stETH.safeApprove(address(borrowerOperations), initialApprovalAmount);
stETH.safeApprove(address(activePool), initialApprovalAmount);
stEth.safeApprove(address(wstEth), initialApprovalAmount);
```

By implementing these changes, the risk of an unlimited token withdrawal is mitigated, significantly enhancing the contract’s security.
