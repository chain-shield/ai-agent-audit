# Vulnerability details

## Details
In ZapRouterBase contract, ```_depositRawEthIntoLido``` function use low-level .call() function in order to send native ether to Lido contract and, it doesn't check the success of the .call() function.  

## Possibilities
- It can be reverted in Lido but execution will continue
1) Lido is a pausable contract it doesn't accept staking while paused (see: https://github.com/lidofinance/lido-dao/blob/5fcedc6e9a9f3ec154e69cff47c2b9e25503a78a/contracts/0.4.24/Lido.sol#L928)
2) Lido has daily staking limit implementation. Highly volatile days, it can be reverted and this limit is not applied by user based, it's applied contract based. (see: https://docs.lido.fi/guides/lido-tokens-integration-guide#staking-rate-limits)
- Temporary network issues, .call() can be failed while whole execution is completed

## Impact
ETH is locked in EbtcLeverageZapRouter while adding margin via native ether or wrapped ether

It doesn't affect ```openCdp``` function because opening position without margin is impossible but it affect ```adjustCdp``` function while adding margin.
