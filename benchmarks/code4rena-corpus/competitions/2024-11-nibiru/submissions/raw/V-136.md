# Vulnerability details

## Issue Description

The Transfer function assumes that the recipient's balance always increases when the transfer succeeds. This assumption may not hold for fee-on-transfer tokens, which deduct fees from the transferred amount.

The Transfer function only checks the success boolean but does not revert when success == false.

## Proof of Concept (PoC)

If success is false, the recipient could incorrectly believe the transfer succeeded, leading to inconsistencies.

Code #1:

    if balanceIncrease.Sign() <= 0 {
	return balanceIncrease, nil, fmt.Errorf(
		"amount of ERC20 tokens received MUST be positive: the balance of recipient %s would've 
    changed by %v for token %s",
		to.Hex(), balanceIncrease.String(), contract.Hex(),
	)
    }

Code #2:

    if !success {
      return balanceIncrease, nil, fmt.Errorf("transfer executed but returned success=false")
    }



## Impact

For tokens with transfer fees, this validation will falsely flag legitimate transfers as failed, disrupting the functionality for fee-on-transfer tokens.

Users may perceive the system as unreliable due to ambiguous failure handling

## Risk
High

## Mitigation #1:

Handle fee-on-transfer tokens gracefully by removing strict balance checks:


    if balanceIncrease.Sign() < 0 {
	return balanceIncrease, nil, fmt.Errorf("unexpected negative balance change for recipient %s", 
    to.Hex())
    }

## Mitigation #2:

    if !success {
     return nil, nil, fmt.Errorf("transfer failed: operation did not succeed")
    }
