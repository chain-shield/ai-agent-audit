# Vulnerability details

## Description:

The DeleteAccount function clears storage but fails to verify whether clearing operations are successful. Additionally, removing the account (RemoveAccount) without ensuring balance and state were fully cleared could leave remnants of the account's data.

In the DeleteAccount function, after calling SetAccBalance(ctx, addr, new(big.Int)) to clear the account balance, there is no explicit check to ensure the state is fully cleaned up, especially in cases of failure during state deletion (storage and balance clearing).

## Proof of Concept:

    k.ForEachStorage(ctx, addr, func(key, _ gethcommon.Hash) bool {
    k.SetState(ctx, addr, key, nil)
      return true
    })


## Impact:

This may lead to partial deletion, leaving inconsistent or dangling references in the state.

The account might remain partially intact, leading to potential state inconsistency and misuse of the account.

## Risk Level:
Medium.

Inconsistent states could affect other contract interactions or make the system vulnerable to unauthorized use.

## Mitigation #1:

Add checks to ensure each key-value pair in storage is cleared successfully. Log errors for any failed cleanup:

    k.ForEachStorage(ctx, addr, func(key, _ gethcommon.Hash) bool {
    k.SetState(ctx, addr, key, nil)
    if !k.isStateCleared(ctx, addr, key) {
        log.Errorf("Failed to clear state for key: %s", key.Hex())
    }
      return true
    })


## Mitigation #2:

Ensure that all changes (balance, storage, and account) are made atomically and add additional checks to verify all states have been correctly deleted:

    if err := k.SetAccBalance(ctx, addr, new(big.Int)); err != nil {
      return err
    }
    k.ForEachStorage(ctx, addr, func(key, _ gethcommon.Hash) bool {
     if err := k.SetState(ctx, addr, key, nil); err != nil {
        return false
     }
     return true
    })
