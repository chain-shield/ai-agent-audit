# Vulnerability details

## Issue Description

GetProof queries storage proofs in a loop, potentially causing performance bottlenecks for large storageKeys arrays.

## Proof of Concept

    for i, key := range storageKeys {
    hexKey := gethcommon.HexToHash(key)
    valueBz, proof, err := b.queryClient.GetProof(clientCtx, evm.StoreKey, evm.StateKey(address, 
    hexKey.Bytes()))
    if err != nil {
        return nil, err
    }
    // Inefficient loop
    }


## Impact

Nodes can experience significant delays when processing multiple storage keys due to sequential requests.

## Risk

Moderate

## Mitigation

Batch process storage proof queries where supported:

    storageProofs, err := b.queryClient.BatchGetProofs(clientCtx, evm.StoreKey, batchRequestKeys)
    if err != nil {
     return nil, err
    }
