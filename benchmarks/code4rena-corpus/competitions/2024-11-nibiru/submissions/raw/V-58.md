# Vulnerability details

## description
The function EthereumTx of msg_server.go is susceptible to a race condition when multiple transactions are processed concurrently. Since this function updates the cumulative gas used in a block, concurrent transactions may read and modify the same value simultaneously, leading to inconsistent or incorrect gas usage tracking. This could result in invalid gas calculations and potentially allow blocks to exceed the gas limit or cause transaction failures.
## impact
The race condition may cause the cumulative gas used to be calculated incorrectly, leading to block gas limits being violated.
## Proof of Concept
1. Simulate multiple transactions being processed concurrently by creating parallel goroutines that invoke the EthereumTx method.
2. Within each goroutine, execute a transaction that modifies the block's gas usage via the AddToBlockGasUsed function.
3. Observe the block gas usage via logging or debugging:
Inconsistent results in cumulative gas used indicate the presence of a race condition.
Use the Go race detector (go test -race) to confirm the issue.
## Recommended mitigation steps
Protect the gas usage update logic with a mutex to ensure only one goroutine updates the value at a time.
