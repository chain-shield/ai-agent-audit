# Vulnerability details

## Issue Description:

In the SetAccState function, if the provided stateValue is empty, the corresponding entry in AccState is deleted. This might inadvertently erase important state information that could be necessary, especially for non-empty state values in other contexts.

## Proof-of-Concept:

evm_state.go#L130

    func (state EvmState) SetAccState(
    ctx sdk.Context, addr gethcommon.Address, stateKey gethcommon.Hash, stateValue []byte,
    ) {
    if len(stateValue) != 0 {
        state.AccState.Insert(ctx, collections.Join(addr, stateKey), stateValue)
    } else {
        // Potentially harmful: Deleting state without checks
        _ = state.AccState.Delete(ctx, collections.Join(addr, stateKey))
    }
    }


## Impact:

Data Loss: Deleting state without any checks may lead to accidental removal of data that could be needed for contract execution, leading to potential data corruption.

## Risk:

Moderate to High: Deletion logic should include safeguards, as unintended state deletions could cause the smart contract to behave unpredictably or lead to vulnerabilities in the contract.

## Mitigation:

Implement a more robust condition to verify if the deletion is necessary.

Consider retaining the state even if the value is empty, or at least adding a safeguard to ensure the state deletion only happens under strict conditions.
