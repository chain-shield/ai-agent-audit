# Vulnerability details

## Finding description and impact

The implementation of `eth_getBalance` and other endpoints that accept blocks in Nibiru's RPC interface deviates from the official Ethereum JSON-RPC specification, which could cause compatibility issues with common Ethereum tooling and libraries.

For instance, consider the `GetBalance` method in `account_info.go`, which only accepts `BlockNumberOrHash` as the block parameter:

```go
func (b *Backend) GetBalance(
    address gethcommon.Address,
    blockNrOrHash rpc.BlockNumberOrHash, // Only accepts BlockNumberOrHash
) (*hexutil.Big, error)
```

However, according to the [Ethereum JSON-RPC specification](https://ethereum.github.io/execution-apis/api-documentation/), the block parameter should accept:
- Block numbers
- Block hashes
- Block tags ("earliest", "finalized", "safe", "latest", "pending")

This deviation from the spec could cause issues when using popular Ethereum development tools and libraries, which expect full compliance with the Ethereum JSON-RPC specification. These tools often use block tags like "latest" or "pending" to query balances, and the current implementation may reject these valid queries.

The impact is particularly concerning because:
1. It breaks compatibility with standard Ethereum tooling
2. It may cause integration issues for dApps trying to port to Nibiru
3. It creates inconsistent behavior compared to other EVM chains, harming developer experience

*Note on severity: Compatibility with common tooling was explicitly mentioned as an area of concern for the sponsor, because of this I consider this Medium.*

## Proof of Concept

The issue can be found in [`account_info.go`](https://github.com/code-423n4/2024-11-nibiru/blob/main/eth/rpc/backend/account_info.go#L170):

```go
func (b *Backend) GetBalance(
    address gethcommon.Address,
    blockNrOrHash rpc.BlockNumberOrHash,
) (*hexutil.Big, error)
```

Comparing this with the official Ethereum JSON-RPC spec (https://github.com/ethereum/execution-apis/blob/4140e528360fea53c34a766d86a000c6c039100e/src/eth/state.yaml#L11):

```yaml
- name: eth_getBalance
  params:
    - name: Address
      required: true
      schema:
        $ref: '#/components/schemas/address'
    - name: Block
      required: true
      schema:
        $ref: '#/components/schemas/BlockNumberOrTagOrHash'
```

And from `block.yaml`, we can see that `BlockNumberOrTagOrHash` should include block tags:

```yaml
BlockTag:
  title: Block tag
  type: string
  enum:
    - earliest
    - finalized
    - safe
    - latest
    - pending
```

## Recommended mitigation steps

1. Update the `GetBalance` method signature to accept `BlockNumberOrTagOrHash` instead of just `BlockNumberOrHash`:

```go
func (b *Backend) GetBalance(
    address gethcommon.Address,
    blockParam rpc.BlockNumberOrTagOrHash,
) (*hexutil.Big, error)
```

2. Implement proper handling of block tags in the `BlockNumberFromTendermint` function to map Ethereum block tags to appropriate Tendermint block heights:

```go
func (b *Backend) BlockNumberFromTendermint(param rpc.BlockNumberOrTagOrHash) (*big.Int, error) {
    switch param.Tag {
    case "latest":
        // Return latest block number
    case "earliest":
        // Return genesis block (0)
    case "pending":
        // Return current block + 1
    case "safe":
        // Return safe block based on chain's finality rules
    case "finalized":
        // Return finalized block based on chain's finality rules
    default:
        // Handle block number or hash as before
    }
}
```

This will ensure full compatibility with Ethereum tooling.
