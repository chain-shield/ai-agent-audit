# Vulnerability details

## Finding description and impact

At the moment `ApplyEvmMsg()` does not account for coinbase fees breaking compatibility with the standard EVM execution client. There is always a priority fee parameter that reflects how much fees has to be paid to the validator of the block but it's currently missing.

## Proof of Concept

Take a look at the geth client implementation:

https://github.com/NibiruChain/go-ethereum/blob/nibiru/geth/core/state_transition.go#L351-359
```
if st.evm.Config.NoBaseFee && st.gasFeeCap.Sign() == 0 && st.gasTipCap.Sign() == 0 {
		// Skip fee payment when NoBaseFee is set and the fee fields
		// are 0. This avoids a negative effectiveTip being applied to
		// the coinbase when simulating calls.
	} else {
		fee := new(big.Int).SetUint64(st.gasUsed())
		fee.Mul(fee, effectiveTip)
		st.state.AddBalance(st.evm.Context.Coinbase, fee)
	}

```

When sending a transaction, the Nibiru `backend` module includes `MaxPriorityFeePerGas` parameter even if it's not set by a user:

https://github.com/code-423n4/2024-11-nibiru/blob/main/eth/rpc/backend/call_tx.go#L103-109
```
if args.MaxPriorityFeePerGas == nil {
				tip, err := b.SuggestGasTipCap(head.BaseFee)
				if err != nil {
					return args, err
				}
				args.MaxPriorityFeePerGas = (*hexutil.Big)(tip)
			}
```


But when applying a message, there is no transfer to the coinbase address at all:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L249

The function only calculates the gas and subtracts all the gas costs from the gas limit but there is no any transfer of priority fee to the coinbase address.

## Recommended mitigation steps

Add coinbase address transfer similar to the vanilla geth client implementation.
