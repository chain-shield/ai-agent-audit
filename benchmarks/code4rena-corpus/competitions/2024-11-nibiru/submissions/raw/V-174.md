# Vulnerability details

## Issue Description:

The logic to synchronize the StateDB is repeated across multiple functions such as MintCoins, BurnCoins, SendCoins, etc. This duplication leads to a larger and harder-to-maintain codebase.

The SyncStateDBWithAccount function silently fails if StateDB is nil. This could lead to inconsistent state if StateDB is not properly initialized.

## Proof-of-Concept Code:

Repetitive code increases the chances of introducing bugs when making updates. It can lead to unnecessary code changes across multiple places, making it harder to refactor or improve logic.


## Risk:

Code duplication increases maintenance overhead and potential errors when updating or modifying similar logic across the contract.

## Impact:

- Silent failure may lead to debugging difficulties.

- Could cause desynchronization between Cosmos SDK state and Ethereum VM state.

## Mitigation:

Create a utility method like SyncStateDBForCoins to handle synchronization logic for accounts involved in coin operations.

     func (bk *NibiruBankKeeper) SyncStateDBWithAccount(ctx sdk.Context, acc sdk.AccAddress) {

	bk.StateDB.SetBalanceWei(eth.NibiruAddrToEthAddr(acc), balanceWei)
    }
