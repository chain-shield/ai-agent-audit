# Vulnerability details

## Issue Description:

The parseFundsArg function assumes that the input arguments (BankCoin[]) contain valid denominations and non-negative amounts. However, it lacks thorough validation to ensure these inputs are compliant with the expected standards (e.g., no negative amounts or unsupported denominations).

## Proof of Concept (PoC)

Consider the following input:

    args := []struct {
	Denom  string
	Amount *big.Int
    }{
	{"invalid_denom", big.NewInt(-1000)}, // Invalid denom and negative amount
    }
    funds, err := parseFundsArg(args)


The function will construct an sdk.Coin with invalid data.

## Impact:

- Transactions could inadvertently carry malformed coins, leading to errors downstream in contract execution or unexpected behavior in financial computations.

- The application may panic, leading to potential denial of service.

- Malformed arguments can bypass validation, leading to undefined behavior.

## Risk

High — Malformed inputs may disrupt critical contract operations.

## Mitigation

Add validation for the denominations and ensure amounts are non-negative:

    for _, coin := range raw {
	if !sdk.ValidateDenom(coin.Denom) {
		return nil, fmt.Errorf("invalid denomination: %s", coin.Denom)
	}
	if coin.Amount.Sign() < 0 {
		return nil, fmt.Errorf("amount cannot be negative: %s", coin.Amount.String())
	}
	funds = append(funds, sdk.Coin{
		Denom:  coin.Denom,
		Amount: sdk.NewIntFromBigInt(coin.Amount),
	})
    }
