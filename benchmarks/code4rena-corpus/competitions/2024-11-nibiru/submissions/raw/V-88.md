# Vulnerability details

## Finding Description and Impact

The Ethereum network is currently on the [Cancun fork](https://ethereum.org/en/history/#cancun-summary) while Nibiru EVM is on [Paris fork](https://ethereum.org/en/history/#paris). Shanghai and Cancun introduced several critical Ethereum Improvement Proposals (EIPs) and opcodes. These upgrades enhance the Ethereum Virtual Machine (EVM) with new features and changes to existing behaviour. The most relevant EIPs include:

- **[EIP-3855](https://eips.ethereum.org/EIPS/eip-3855)**: Introduces the `PUSH0` opcodes, which pushes the constant value 0 onto the stack for gas-optimized contract design.
- **[EIP-1153](https://eips.ethereum.org/EIPS/eip-1153)**: Introduces the `TSTORE` and `TLOAD` opcodes, enabling transient storage for efficient, gas-optimized contract design.
- **[EIP-5656](https://eips.ethereum.org/EIPS/eip-5656)**: Introduces the `MCOPY` instruction, allowing efficient memory copying.
- **[EIP-6780](https://eips.ethereum.org/EIPS/eip-6780)**: Alters the behaviour of `SELFDESTRUCT`, reducing its potential for misuse while preserving legacy behaviour in specific contexts.
- **[EIP-7516](https://eips.ethereum.org/EIPS/eip-7516)**: Adds the `BLOBBASEFEE` opcode for handling blob fees in rollup scaling solutions.

### Impact
1. **Feature Gap**: Some contracts, including [Uniswap V4](https://github.com/Uniswap/v4-core/blob/b619b6718e31aa5b4fa0286520c455ceb950276d/src/libraries/Lock.sol), already leverage `TSTORE` and `TLOAD` for transient storage. The lack of these opcodes restricts the deployment of advanced, gas-efficient contracts.
2. **Security Concerns**: Outdated assumptions about `SELFDESTRUCT` behaviour can introduce vulnerabilities or lead to unintended contract execution risks.
3. **Compatibility Issues**: Non-compliance with Cancun EIPs can render the blockchain incompatible with modern dApps and tooling, reducing its ecosystem attractiveness.

## Recommended Mitigation Steps

To address these issues and align with the Ethereum ecosystem's advancements, the following steps are required:

1. **Update Geth**: Upgrade to a more recent version of **Geth** that fully supports the Cancun fork.

2. **Upgrade the State Database**: Ensure the state database [statedb](https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/statedb/statedb.go#L395-L409) is updated to comply with EIP-6780 and work with the newer Geth.
