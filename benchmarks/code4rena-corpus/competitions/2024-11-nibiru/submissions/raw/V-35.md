# Vulnerability details

#### **Summary**
The `updateBlockBloom` function in the smart contract module lacks proper access control checks, allowing unauthorized entities to manipulate critical blockchain state variables, including the `BlockBloom` filter and `BlockLogSize`. This vulnerability can lead to corruption of the blockchain state and potential denial of service (DoS) attacks.

##### **Code Snippet : msg_server.go#L709**
```go
func (k *Keeper) updateBlockBloom(
	ctx sdk.Context,
	evmResp *evm.MsgEthereumTxResponse,
	logIndex uint64,
) {
	logs := evm.LogsToEthereum(evmResp.Logs)
	if len(logs) > 0 {
		k.EvmState.BlockBloom.Set(ctx, k.EvmState.CalcBloomFromLogs(ctx, logs).Bytes())
		blockLogSize := logIndex + uint64(len(logs))
		k.EvmState.BlockLogSize.Set(ctx, blockLogSize)
	}
}
```

#### **Suggested Fix**
Implement access control checks to ensure that only authorized roles (e.g., validators, system administrators) can invoke the `updateBlockBloom` function. Suggested solutions:
1. **Caller Authorization**: Verify the caller’s identity using a role-based mechanism:
   ```go
   if !k.HasPermission(ctx, callerAddress) {
       return sdkerrors.Wrap(sdkerrors.ErrUnauthorized, "caller not authorized")
   }
   ```
