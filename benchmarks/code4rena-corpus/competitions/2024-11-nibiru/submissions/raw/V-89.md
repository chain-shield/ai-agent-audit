# Vulnerability details

### Title  
**Missing Validation for Exchange Rate Bounds in `precompileOracle` Smart Contract**  

---

### Summary  
The lack of validation for minimum and maximum exchange rate bounds in the `queryExchangeRate` method will cause a mispricing vulnerability for the protocol. This allows stale or manipulated exchange rates to propagate through the system, potentially causing incorrect calculations or economic losses for protocol users and stakeholders.  

---

### Root Cause  
In the `precompileOracle`  smart contract:  
- In `queryExchangeRate` , the contract fetches the exchange rate using `p.oracleKeeper.GetDatedExchangeRate`.  
- The returned `price` is directly packed and returned without checking whether it falls within a valid range (e.g., `minPrice <= price <= maxPrice`).  

---

### Internal Pre-conditions  
1. The `oracleKeeper` must return an exchange rate for the queried asset pair.  
2. The fetched `price` must be outside the acceptable range for the given pair due to stale or incorrect oracle data.  
3. The protocol must lack configured bounds (`minPrice` and `maxPrice`) for validating the exchange rate.  

---


### Attack Path  
1. An attacker manipulates the oracle or exploits bugs in the oracle data feed to return an invalid exchange rate.  
2. The `queryExchangeRate` method fetches the manipulated rate without validating it.  
3. The manipulated rate is packed and used in other protocol operations (e.g., conversions or transactions).  
4. The protocol experiences financial loss or operational issues due to the invalid rate being used for calculations.  

---

### Impact  
The **protocol** or **users** can suffer economic losses due to mispricing of assets:  
- **Underpricing:** Allows attackers to acquire assets at a discount, draining reserves.  
- **Overpricing:** Forces users to overpay for assets, reducing trust in the system.  

---

### PoC  
1. Manipulate the oracle to return an exchange rate of `0` or an extremely high value (e.g., `10^30`).  
2. Call the `queryExchangeRate` method with the affected asset pair.  
3. Observe that the invalid rate is returned and propagated through the system.  

---

### Mitigation  
Introduce validations for exchange rate bounds in the `queryExchangeRate` method:  

1. Define `minPrice` and `maxPrice` thresholds for each asset pair, either via configuration or protocol constants.  

2. Modify `queryExchangeRate` to validate the returned exchange rate:  

   ```go
   if price.Cmp(minPrice) < 0 || price.Cmp(maxPrice) > 0 {
       return nil, fmt.Errorf("price out of bounds: %s not in range [%s, %s]", price, minPrice, maxPrice)
   }
   ```

3. Ensure these bounds are configurable and dynamically updatable based on market conditions.
