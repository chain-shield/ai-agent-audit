# Vulnerability details


## Description:

- GetTransactionByHash method, specifically where it calls b.getTransactionByHashPending(txHash) on failure of GetTxByEthHash.

- If the GetTxByEthHash method fails, the fallback to getTransactionByHashPending is attempted. However, it doesn't fully handle the case where the transaction is neither found on chain nor in the mempool.

## Impact:

The function could return nil without a proper error message, leading to difficulties in debugging or identifying the root cause of missing transactions.

## Proof-of-Concept:

    // Failed fallback logic
    tx, err := b.getTransactionByHashPending(txHash)
    if err != nil || tx == nil {
      return nil, errors.New("transaction not found in pending pool")
    }


## Risk Level:

Medium: Transaction resolution could silently fail, making debugging difficult.

## Mitigation:

Add better error handling, logging, and fallbacks to ensure that transactions are always found or an informative error is returned.

    if err != nil || tx == nil {
    b.logger.Error("transaction not found", "hash", txHash.Hex(), "error", err.Error())
      return nil, errors.New("transaction not found in pending pool")
    }
