# Vulnerability details

## Finding description and impact

In `funtoken_from_coin.go`, when creating a FunToken mapping from a Bank Coin, the decimal value from the Bank Coin's metadata is cast unsafely from an integer to uint8 without checking for overflow. This affects the `deployERC20ForBankCoin` function which deploys the corresponding ERC20 token.

The impact is that if a Bank Coin has a DenomUnit with an exponent larger than 255 (max value of `uint8`), the decimals will silently overflow, resulting in an ERC20 token with incorrect decimals. This breaks the intended 1:1 mapping between Bank Coins and ERC20 tokens since the decimal places won't match, leading to incorrect token amounts when converting between the two formats.

For example, if a Bank Coin has an exponent of 256, the ERC20 would be created with 0 decimals instead of failing, completely breaking the token conversion mechanism.

## Proof of Concept

The vulnerable code is in `funtoken_from_coin.go`:

```go
decimals := uint8(0)
if len(bankCoin.DenomUnits) > 0 {
    decimalsIdx := len(bankCoin.DenomUnits) - 1
    decimals = uint8(bankCoin.DenomUnits[decimalsIdx].Exponent) // Unsafe cast
}
```
[Link to code](https://github.com/code-423n4/2024-11-nibiru/blob/84054a4f00fdfefaa8e5849c53eb66851a762319/x/evm/keeper/funtoken_from_coin.go#L70)

Consider this scenario:
1. A Bank Coin is created with a DenomUnit exponent of 256
2. When creating the FunToken mapping, `uint8(256)` overflows to 0
3. The ERC20 is deployed with 0 decimals instead of 256
4. When converting between Bank Coin and ERC20:
   - The Bank Coin uses 256 decimal places
   - The ERC20 uses 0 decimal places
   - All conversions will be off by a factor of 10^256

The following sequence demonstrates the overflow:

```go
exponent := 256
decimals := uint8(exponent)
fmt.Println(decimals) // Prints 0 instead of 256
```

## Recommended mitigation steps

Add a validation check to ensure the exponent fits within uint8 before casting:

```go
decimals := uint8(0)
if len(bankCoin.DenomUnits) > 0 {
    decimalsIdx := len(bankCoin.DenomUnits) - 1
    exponent := bankCoin.DenomUnits[decimalsIdx].Exponent
    if exponent > 255 {
        return gethcommon.Address{}, fmt.Errorf(
            "exponent %d exceeds maximum allowed decimals (255)",
            exponent,
        )
    }
    decimals = uint8(exponent)
}
```

Additionally, consider adding a reasonable upper limit for decimals (e.g., 18 or 24) to prevent excessive decimal places that could cause other numerical issues. This aligns with common ERC20 token practices where 18 decimals is standard.
