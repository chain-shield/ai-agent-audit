# Vulnerability details

## Vulnerability Details

Nibiru's StateDB lacks EIP-6780 implementation, enabling multiple severe attack vectors including forced Ether injection, proxy implementation destruction, and delegate call vulnerabilities. This deviation from Ethereum's behavior could lead to permanent fund lockups and contract state manipulation.

The core issue in Nibiru's StateDB:
```go
//no EIP-6780 checks e.g. for new contracts
func (s *StateDB) Suicide(addr common.Address) bool {
    stateObject := s.getStateObject(addr)
    if stateObject == nil {
        return false
    }
    s.Journal.append(suicideChange{
        account:     &addr,
        prev:        stateObject.Suicided,
        prevbalance: new(big.Int).Set(stateObject.Balance()),
    })
    stateObject.Suicided = true
    stateObject.account.BalanceWei = new(big.Int)
    return true
}
```

## Impact

Permanent loss of funds through trapped Ether in destructed contracts
UUPS proxy patterns can be permanently broken
Delegatecall-based contracts vulnerable to destruction
Contract invariants broken through forced Ether injection
Multiple vector attacks possible within same block due to missing EIP-6780 protection
