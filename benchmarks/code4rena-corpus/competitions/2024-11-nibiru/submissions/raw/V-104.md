# Vulnerability details

## Issue Description:

Absence of Replay Protection for Legacy Transactions.

The current implementation conditionally allows unprotected transactions when allowUnprotectedTxs is set, exposing the system to potential replay attacks.

#1. EIP-155 Replay Protection:

Ethereum introduced EIP-155 to prevent transaction replay across chains by appending a chainId field to transaction signatures.

#2. Vulnerability: 

When allowUnprotectedTxs is set to true, the function accepts legacy (unprotected) transactions, which do not have this field. These transactions can be replayed on other chains or even within the same chain if identical accounts exist.

#3. Risk Window: 

Legacy transactions remain valid and are vulnerable to replays on all compatible networks.

## Proof-of-Concept

Replay protection is enforced only for transactions using EIP-155:

    if !b.allowUnprotectedTxs && !tx.Protected() {
     return common.Hash{}, errors.New("only replay-protected (EIP-155) transactions allowed over RPC")
    }

If allowUnprotectedTxs is set, legacy transactions could be broadcast without replay protection.


## Impact

Attackers can replay transactions across different Ethereum-compatible chains.

May result in significant financial losses.

#1. Financial Loss:

Users may unintentionally execute transactions on unintended networks, leading to loss of funds.

#2. Network Reputation: 

Accepting unprotected transactions undermines trust in the system's security.

#3. Cross-Chain Exploits:

Adversaries could exploit this vulnerability to drain funds from multi-chain wallets.


## Risk

Critical – Replay protection is a fundamental security measure.

## Mitigation

#### Mitigation 1:

Completely disallow unprotected transactions, or enforce a clear configuration for their use.

Enforce Replay Protection: 
Reject all transactions that do not comply with EIP-155, regardless of the allowUnprotectedTxs flag:

    if !tx.Protected() {
      return common.Hash{}, errors.New("unprotected transactions are not supported")
    }

#### Mitigation 2:

Audit All Incoming Transactions:

Integrate logging and monitoring to flag any legacy transactions submitted before rolling out the mitigation:

    if !tx.Protected() {
       b.logger.Warn("Unprotected transaction attempt detected", "txHash", tx.Hash().Hex())
    }
