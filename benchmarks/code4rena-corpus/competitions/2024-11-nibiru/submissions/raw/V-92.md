# Vulnerability details

## Issue:

Improper Handling of GasUsed in RPCBlockFromTendermintBlock

## Bug Description:

Gas used is accumulated directly without checking for overflows.

There's no validation to check if the gas used exceeds the block's gas limit. While a bug in the consensus might be the cause, there is no check for this condition.

## Impact: 

Overflow errors could occur with extremely high gas values, especially in scenarios involving malicious transactions.

- Exceeding gas limit: 
Transactions that exceed the block's gas limit could affect block processing and potentially cause a miscalculation in gas usage.

- Inconsistent results: 
The backend might produce inconsistent results for blocks, especially if a block contains transactions exceeding the gas limit.

## Risk Level: High

This may introduce miscalculations in the backend's calculations, leading to erroneous block data.

## Proof of Concept

If a transaction uses more gas than the available block limit, the system will continue processing without flagging the issue.
     
    gasUsed += uint64(txsResult.GetGasUsed())

If txsResult.GetGasUsed() is unusually high, the cumulative gasUsed could overflow.


## Mitigation: 

Use safe arithmetic libraries or check for overflows explicitly before accumulation.

    if gasUsed > gasLimit {
      return nil, fmt.Errorf("gas usage exceeds block limit: %d > %d", gasUsed, gasLimit)
    }
