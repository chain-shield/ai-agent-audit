# Vulnerability details

## Issue Description

In parseArgsWasmExecuteMulti, there is no validation for the execMsgs input, and malformed structures can propagate unchecked.

The function does not validate individual fields within the execMsgs array. Specifically, ContractAddr, MsgArgs, and Funds are not subjected to sufficient validation.

## Proof of Concept (PoC)

Pass a malformed input:
wasm_parse.go#L209

    args := []any{[]struct {
    ContractAddr string `json:"contractAddr"`
    MsgArgs      []byte `json:"msgArgs"`
    Funds        []struct {
        Denom  string   `json:"denom"`
        Amount *big.Int `json:"amount"`
    }{
        {"invalid_addr", []byte{}, []struct { Denom string; Amount *big.Int }{
            {"invalid_denom", big.NewInt(-1)},
        }},
    },
    }}

    msgs, err := parseArgsWasmExecuteMulti(args)
    fmt.Println(err) // No validation errors are caught.


## Impact:

- Malformed data could break contract execution or create vulnerabilities in downstream processing.

- Contracts can be executed with invalid addresses, message payloads, or funds.

- Undetected errors may result in contract execution failures or unintended outcomes.

## Risk:

Critical - Exploitable in multi-execution scenarios.

May introduce exploitable vulnerabilities in the contract logic.

## Mitigation:

Validate each execMsg field:

    for _, msg := range execMsgs {
    if _, err := sdk.AccAddressFromBech32(msg.ContractAddr); err != nil {
        return nil, fmt.Errorf("invalid contract address: %w", err)
    }
    if len(msg.MsgArgs) == 0 {
        return nil, fmt.Errorf("message arguments cannot be empty")
    }
    for _, fund := range msg.Funds {
        if fund.Amount.Sign() <= 0 {
            return nil, fmt.Errorf("fund amount must be positive")
        }
    }
    }
