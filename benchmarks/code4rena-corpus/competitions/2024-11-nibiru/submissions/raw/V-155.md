# Vulnerability details

## Finding description and impact
When a contract is self-destructed, the code, storage, and native balance of the address behind it are wiped clean in the EVM state. For the corresponding Bech32 address of that contract, its `unibi` bank coins balance and account are deleted from the SDK application state.

```go
func (k *Keeper) DeleteAccount(ctx sdk.Context, addr gethcommon.Address) error {
	nibiruAddr := sdk.AccAddress(addr.Bytes())
	acct := k.accountKeeper.GetAccount(ctx, nibiruAddr)
	if acct == nil {
		return nil
	}

	_, ok := acct.(eth.EthAccountI)
	if !ok {
		return evm.ErrInvalidAccount.Wrapf("type %T, address %s", acct, addr)
	}

	// clear balance
	if err := k.SetAccBalance(ctx, addr, new(big.Int)); err != nil {
		return err
	}

	// clear storage
	k.ForEachStorage(ctx, addr, func(key, _ gethcommon.Hash) bool {
		k.SetState(ctx, addr, key, nil)
		return true
	})

	k.accountKeeper.RemoveAccount(ctx, acct)

	return nil
}
```

The problem is, however, that if that contract address has a balance of any other bank coins and is self-destructed. In that case deleting the account would trigger the supply invariant of the `x/bank` module which would halt the chain due to inconsistency between the known total supply of the given bank coin and the sum of all accounts' balances of that coin, effectively triggering a chain halt. The other problem that allows for this is that Nibiru is using an old version of geth which still hasn't implemented [EIP-6780](https://eips.ethereum.org/EIPS/eip-6780).

As we can see this is even warned about in Nibiru's own fork of `cosmos-sdk`:
https://github.com/NibiruChain/cosmos-sdk/blob/cf419e11b3a0f5bb9b3900321e2b3521fc314c29/x/auth/keeper/account.go#L62-L67
```go
// RemoveAccount removes an account for the account mapper store.
// NOTE: this will cause supply invariant violation if called
func (ak AccountKeeper) RemoveAccount(ctx context.Context, acc sdk.AccountI) {
	err := ak.Accounts.Remove(ctx, acc.GetAddress())
	if err != nil {
		panic(err)
	}
}
```
## Proof of Concept
1. Deploy a custom ERC20 token and a self-destructable contract on Nibiru's EVM.
2. Create a bank token for it via a call to `CreateFunToken()`.
3. Convert 1 wei worth of the ERC20 token to bank coins (via calling `sendToBank()` on the FunToken precompile), specifying the self-destructable's Nibiru address as a recipient (`to`).
4. Self-destruct the contract.
5. There's no way the bank coins can be burned, triggering the supply invariant of the bank keeper.
6. Chain is halted.
## Recommended mitigation steps
Revert TXs that self-destruct ETH accounts that have an active balance in any coin in the bank module. There's also another, more harsh approach which is to directly burn all of their coins balances.
