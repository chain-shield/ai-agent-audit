# Vulnerability details

## Finding description and impact

In `msg_server.go`, the `ApplyEvmMsg` function enforces that all EVM message values must be multiples of 1 micronibi (10^12 wei) by rounding the input value using `ParseWeiAsMultipleOfMicronibi`. This poses a significant issue as many Solidity contracts validate exact wei values in their logic using `require(msg.value == X)` checks or similar precision-dependent validations.

The rounding behavior will cause these contract interactions to fail since the actual value sent will be different from what's expected, potentially causing:

1. Failed transactions and reverts for contracts that expect exact wei amounts
2. Inability to interact with contracts that require precise wei values
3. Stuck funds in worst case if a contract has for instance already processed a deposit, but the withdrawal fails because of fee validation.

This limitation significantly reduces EVM compatibility and could break functionality for many existing Ethereum contracts that rely on exact wei-level precision.

## Proof of Concept

The issue occurs in [msg_server.go#L337](https://github.com/code-423n4/2024-11-nibiru/blob/84054a4f00fdfefaa8e5849c53eb66851a762319/x/evm/keeper/msg_server.go#L337):

```go
// Inside ApplyEvmMsg
msgWei, err := ParseWeiAsMultipleOfMicronibi(msg.Value())
if err != nil {
    return nil, evmObj, errors.Wrapf(err, "ApplyEvmMsg: invalid wei amount %s", msg.Value())
}

// Later used in evmObj.Call
ret, leftoverGas, vmErr = evmObj.Call(
    sender,
    *msg.To(),
    msg.Data(),
    leftoverGas,
    msgWei, // Rounded value used here
)
```

The rounding is implemented in [const.go](https://github.com/code-423n4/2024-11-nibiru/blob/84054a4f00fdfefaa8e5849c53eb66851a762319/x/evm/const.go#L143-L170):

```go
func ParseWeiAsMultipleOfMicronibi(weiInt *big.Int) (newWeiInt *big.Int, err error) {
    // ...
    newWeiInt = NativeToWei(WeiToNative(weiInt))
    return newWeiInt, nil
}
```

Example of a contract that would break:
```solidity
contract ExactPayment {
    uint256 public constant EXACT_PAYMENT = 1234567890123; // Not a multiple of 10^12

    function deposit() external payable {
        require(msg.value == EXACT_PAYMENT, "Incorrect payment amount");
        // Process deposit
    }
}
```

This contract would always revert on Nibiru because the value would be rounded to the nearest multiple of 10^12 wei.

## Recommended mitigation steps

Consider implementing a more granular denomination system that allows for wei-level precision while maintaining compatibility with the chain's native token system.
