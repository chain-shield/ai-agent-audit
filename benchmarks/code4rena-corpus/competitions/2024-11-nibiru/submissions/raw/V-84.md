# Vulnerability details

## Finding description and impact

Currently there are 2 way to transfer liquidity between ERC20 tokens and Bank coins such as Nibiru:

1. `convertCoinToEvmBornERC20()` - the function converts a coin that was originally an ERC20 token, and that was converted to a bank coin, back to an ERC20 token.

2. `convertCoinToEvmBornCoin()` - the function Converts Bank Coins for FunToken mapping that was born from a coin (IsMadeFromCoin=true) into the ERC20 tokens.


The problem is that in both functions there is no any check to ensure that the coin was originally an ERC20 token or not because they only fetch the ERC20 address from the FunToken mapping.

## Proof of Concept

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L567-583
```
func (k Keeper) convertCoinToEvmBornERC20(
	ctx sdk.Context,
	sender sdk.AccAddress,
	recipient gethcommon.Address,
	coin sdk.Coin,
	funTokenMapping evm.FunToken,
) (*evm.MsgConvertCoinToEvmResponse, error) {
	erc20Addr := funTokenMapping.Erc20Addr.Address
	// 1 | Caller transfers Bank Coins to be converted to ERC20 tokens.
	if err := k.Bank.SendCoinsFromAccountToModule(
		ctx,
		sender,
		evm.ModuleName,
		sdk.NewCoins(coin),
	); err != nil {
		return nil, errors.Wrap(err, "error sending Bank Coins to the EVM")
	}


```

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L527-534
```
// 1 | Send Bank Coins to the EVM module
	err := k.Bank.SendCoinsFromAccountToModule(ctx, sender, evm.ModuleName, sdk.NewCoins(coin))
```

As you can see here, both methods just fetch `funTokenMapping.Erc20Addr.Address` (not checking `isMadeFromCoin` parameter) and then proceed with the implementation. However, the behavior is not correct and allows users to use methods for unintended operations such as unintended convers (for example, performing minting instead of transfer and so on).

## Recommended mitigation steps

Check `isMadeFromCoin` parameter first and then proceed with the corresponding implementation.
