# Vulnerability details

## Finding description and impact

Certain ERC20 tokens, such as [USDT](https://etherscan.io/token/0xdac17f958d2ee523a2206206994597c13d831ec7#code), deviate from the ERC20 standard by not returning a value when the `transfer` function is called. This behavior is problematic for `erc20Calls.Transfer`, as the current implementation does not handle tokens with missing return values.

The following code snippet highlights the issue:

```go
resp, err = e.CallContract(ctx, e.ABI, from, &contract, true, Erc20GasLimitExecute, "transfer", to, amount)
if err != nil {
    return balanceIncrease, nil, err
}

var erc20Bool ERC20Bool
err = e.ABI.UnpackIntoInterface(&erc20Bool, "transfer", resp.Ret)
if err != nil {
    return balanceIncrease, nil, err
}
```

### Key Issue:
- **Call Failure**: When a token that does not return a value is used (e.g., USDT), `CallContract` may not return an error (`err` is `nil`), but the `resp.Ret` field will contain an empty byte slice (`[]byte{}`).
- **Unpacking Error**: Attempting to unpack an empty byte slice using `UnpackIntoInterface` results in an error:
    * Error Message: `"abi: attempting to unmarshall an empty string while arguments are expected"`.
- **Impact**: This makes it impossible to use tokens with missing return values as FunTokens, potentially blocking their functionality in the system.


## Proof of Concept
The following test case demonstrates the issue and can be added to [erc20_test.go](https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/erc20_test.go#L69)

```go
s.T().Log("Error on empty unpack")
{
    erc20 := deps.EvmKeeper.ERC20()
    var erc20Bool struct{ Value bool }
    err := erc20.ABI.UnpackIntoInterface(&erc20Bool, "transfer", []byte{})
    if err != nil {
        s.T().Log("Error", err)
    }
    s.T().Log("Return", erc20Bool.Value)
}
```

### Result
Running the test yields the following output:

```sh
erc20_test.go:71: Error on empty unpack
erc20_test.go:77: Error abi: attempting to unmarshall an empty string while arguments are expected
erc20_test.go:79: Return false
```

This confirms the unpacking process fails when resp.Ret is an empty byte slice.


## Recommended mitigation steps

To address this issue, add a check to verify whether resp.Ret is empty before attempting to unpack. If it is empty, assume a successful transfer for tokens that do not return a value. For example:

```go
resp, err = e.CallContract(ctx, e.ABI, from, &contract, true, Erc20GasLimitExecute, "transfer", to, amount)
if err != nil {
    return balanceIncrease, nil, err
}

var erc20Bool ERC20Bool

// Check for empty response
if len(resp.Ret) == 0 {
    // Assume success for tokens that do not return a value
    erc20Bool.Value = true
} else {
    err = e.ABI.UnpackIntoInterface(&erc20Bool, "transfer", resp.Ret)
    if err != nil {
        return balanceIncrease, nil, err
    }
}
```
