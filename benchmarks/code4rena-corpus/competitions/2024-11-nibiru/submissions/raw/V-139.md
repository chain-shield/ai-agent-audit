# Vulnerability details

## Issue Description

The height variable in GetProof and GetTransactionCount can be vulnerable to overflow when using large block numbers.

### Possible Integer Overflow:

The comment marks the bn > math.MaxInt64 as a potential issue, but there's no check on the client side to prevent issues with large block numbers.

#### Inconsistent Height Handling: 

The height check appears inconsistent as it assumes blockNum.Int64() will always be valid, but no proper validation or error handling is in place for invalid block numbers.

## Proof of Concept

    height := blockNum.Int64()
    // Current block height might overflow when bn exceeds MaxInt64
    if height > math.MaxInt64 {
    return nil, fmt.Errorf("block height overflow")
    }


## Impact

This bug can crash the application when querying very large block numbers. It impacts nodes running in environments where bn returns an unbounded integer.

- Block number exceeding int64 limits could cause crashes or incorrect results.

- Invalid block heights may not be properly handled, leading to unexpected behavior.

## Risk

Moderate

## Mitigation

Validate block height during assignment:

    if bn > math.MaxInt64 {
     return nil, fmt.Errorf("block number exceeds allowed limit")
    }
    height = int64(bn)
