# Vulnerability details

## Issue Description:

The journal struct's methods (append, Revert, etc.) modify shared state (e.g., entries, dirties). There is no synchronization mechanism to prevent data races in concurrent environments.

## Proof of Concept:

In concurrent use:

    go journalInstance.append(entry1)
    go journalInstance.Revert(stateDB, 1)


## Impact:

- Data races leading to unpredictable behavior.

- Corrupted state data in entries and dirties.

## Risk Level: 
High

## Mitigation:

Use mutexes to synchronize access to shared state.

Fix Code:

    import "sync"

    type journal struct {
     entries []JournalChange
     dirties map[common.Address]int
     mutex   sync.Mutex
    }

    func (j *journal) append(entry JournalChange) {
     j.mutex.Lock()
     defer j.mutex.Unlock()
     // Existing append logic
    }

    func (j *journal) Revert(statedb *StateDB, snapshot int) {
     j.mutex.Lock()
     defer j.mutex.Unlock()
     // Existing revert logic
    }
