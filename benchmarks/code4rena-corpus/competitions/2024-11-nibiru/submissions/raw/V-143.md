# Vulnerability details

## Issue Description:

The balance comparison in the SetAccBalance function uses big.Int for each coin calculation and comparison, which can be inefficient. The logic creates new big.Int objects multiple times in each case.

## Proof-of-Concept:

statedb.go#L77

    delta := new(big.Int).Sub(amountEvmDenom, balance)

## Impact:

Medium: The frequent creation of new big.Int objects can cause unnecessary memory allocation, impacting the performance of the contract especially in a high-frequency environment.

## Risk:

Medium: It can cause higher gas costs and reduced performance due to inefficient memory handling.


## Mitigation:

Instead of using multiple big.Int objects, try using a single instance for calculations to avoid memory overhead:

    delta := new(big.Int).Set(amountEvmDenom)
    delta.Sub(delta, balance) // Reuse the `delta` object
