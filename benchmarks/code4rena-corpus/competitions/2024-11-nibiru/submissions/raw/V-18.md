# Vulnerability details

## Finding description and impact

The `CanTransferDecorator` in Nibiru's ante handler checks whether a sender has sufficient balance to cover EVM transfers. However, when processing multiple messages from the same sender within a single transaction, it validates each message's value transfer individually rather than considering their combined sum.

This can lead to transactions being incorrectly accepted when they should be rejected. The issue arises because the state is not updated between checks, so each individual message appears to have sufficient funds even though the combined transfers would exceed the sender's balance.

## Proof of Concept

The issue can be found in `evmante_can_transfer.go`:

```go
// Relevant code at line 84
if coreMsg.Value().Sign() > 0 &&
    !evmInstance.Context.CanTransfer(stateDB, coreMsg.From(), coreMsg.Value()) {
    balanceWei := stateDB.GetBalance(coreMsg.From())
    return ctx, errors.Wrapf(
        sdkerrors.ErrInsufficientFunds,
        "failed to transfer %s wei (balance=%s) from address %s using the EVM block context transfer function",
        coreMsg.Value(),
        balanceWei,
        coreMsg.From(),
    )
}
```

Consider the following scenario:

1. User has 100 wei balance
2. User creates a transaction with two messages, each transferring 60 wei from the same address
3. Current implementation checks:
   - First message: 60 wei < 100 wei balance ✓ (passes)
   - Second message: 60 wei < 100 wei balance ✓ (passes)
4. Transaction is accepted despite total transfer (120 wei) exceeding balance (100 wei)

Note that the same issue also exists in `AnteDecVerifyEthAcc`, where it is checked for each transaction if the sender can cover the fee.

## Recommended mitigation steps

1. Track cumulative transfers per sender:

```go
func (ctd CanTransferDecorator) AnteHandle(
    ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler,
) (sdk.Context, error) {
    // Track cumulative transfers per sender
    senderTotals := make(map[gethcommon.Address]*big.Int)

    for _, msg := range tx.GetMsgs() {
        // ... existing message validation ...

        sender := coreMsg.From()
        value := coreMsg.Value()

        // Get or initialize sender's total
        total, exists := senderTotals[sender]
        if !exists {
            total = new(big.Int)
            senderTotals[sender] = total
        }

        // Add current message value
        total.Add(total, value)

        // Check if cumulative total exceeds balance
        if total.Sign() > 0 &&
            !evmInstance.Context.CanTransfer(stateDB, sender, total) {
            return ctx, errors.Wrapf(
                sdkerrors.ErrInsufficientFunds,
                "insufficient funds for cumulative transfers: %s wei", total,
            )
        }
    }

    return next(ctx, tx, simulate)
}
```

2. Alternatively, consider updating a temporary state after each message validation to accurately reflect remaining balances.

These changes ensure that the total value being transferred across all messages from the same sender does not exceed their balance, maintaining the expected behavior.
