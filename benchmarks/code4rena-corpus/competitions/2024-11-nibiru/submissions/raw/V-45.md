# Vulnerability details

## Proof of Concept
Take a look at [`getAccountNonce`](https://github.com/code-423n4/2024-11-nibiru/blob/8ed91a036f664b421182e183f19f6cef1a4e28ea/eth/rpc/backend/utils.go#L91) function:

```go
  // add the uncommitted txs to the nonce counter
  // only supports `MsgEthereumTx` style tx
  for _, tx := range pendingTxs {
      for _, msg := range (*tx).GetMsgs() {
          ethMsg, ok := msg.(*evm.MsgEthereumTx)
          if !ok {
              // not ethereum tx

          }
  
          sender, err := ethMsg.GetSender(b.chainID)

```

Problem's in the `break` statement when encountering a non-Ethereum tx. Using `break` here will exit the inner `for` loop that iterates over messages potentially missing other valid Ethereum txs in the same tx that might come after a non Ethereum message. This can also result in undercounting of the nonce for accounts with pending txs.

## Recommendation

Consider using `continue` instead of `break` to skip only the current message and continue checking the remaining messages in the transaction.


```diff
for _, tx := range pendingTxs {
    for _, msg := range (*tx).GetMsgs() {
        ethMsg, ok := msg.(*evm.MsgEthereumTx)
        if !ok {
            // not ethereum tx
-             break
+            continue 
        }

        sender, err := ethMsg.GetSender(b.chainID)
        if err != nil {
            continue
        }
        if sender == accAddr {
            nonce++
        }
    }
}
```

The current implementation might lead to undercounting the nonce if there are valid Ethereum transactions that appear after a non-Ethereum message in the same transaction, which could cause transaction ordering issues.
