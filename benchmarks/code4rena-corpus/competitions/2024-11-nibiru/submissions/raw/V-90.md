# Vulnerability details

## Issue Details:

The function BlockNumber includes the following code:

    if height > math.MaxInt64 {
      return 0, fmt.Errorf("block height %d is greater than max uint64", height)
    }


The math.MaxInt64 is of type int64, but the return type for block height is hexutil.Uint64, which is an unsigned integer. This means that checking if the block height exceeds math.MaxInt64 is logically incorrect since height is a uint64 and cannot exceed the maximum value for uint64.

## Proof-of-Concept

If the block height is larger than math.MaxInt64 (which is 9223372036854775807), the code will mistakenly return an error, even though uint64 can handle larger values.

## Impact

- Incorrect validation logic: This introduces incorrect error handling and may lead to blocks being 
  mistakenly rejected as invalid.
- Data integrity issue: If a valid block number exceeds math.MaxInt64, the application will fail to 
  process it properly.


## Risk

This could lead to system crashes or missed blocks, making the system unreliable.

## Mitigation

Replace the math.MaxInt64 check with math.MaxUint64 to ensure it is compatible with hexutil.Uint64.

    if height > math.MaxUint64 {
      return 0, fmt.Errorf("block height %d is greater than max uint64", height)
    }
