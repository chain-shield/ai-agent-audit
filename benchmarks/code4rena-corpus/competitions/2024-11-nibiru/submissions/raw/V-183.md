# Vulnerability details

## Issue Description:

The function calculates blockGasUsed as k.EvmState.BlockGasUsed.GetOr(ctx, 0) + gasUsed. An integer overflow may occur if gasUsed is large enough, causing blockGasUsed to wrap around and become smaller than gasUsed.

## Proof of Concept:

    // Assuming blockGasUsed is close to uint64 max value
    gasUsed := uint64(math.MaxUint64 - 1)
    ctx := sdk.Context{}
    blockGasUsed, err := k.AddToBlockGasUsed(ctx, gasUsed)
    // Potential overflow here


## Impact:

High — Incorrect gas accounting can destabilize the EVM module, potentially allowing malicious actors to bypass gas limits.

## Risk:

Severe.

## Mitigation:

Implement safe addition with overflow checks using a utility function like math/big.Add.

Mitigation Code:

    if math.MaxUint64-k.EvmState.BlockGasUsed.GetOr(ctx, 0) < gasUsed {
    return 0, errors.Wrap(core.ErrGasUintOverflow, "gas usage exceeds uint64 max value")
    }
    blockGasUsed = k.EvmState.BlockGasUsed.GetOr(ctx, 0) + gasUsed
    k.EvmState.BlockGasUsed.Set(ctx, blockGasUsed)
