# Vulnerability details

## Issue Description:

There is no mechanism in the code to prevent replay attacks. A malicious user could reuse a signed transaction multiple times, especially if signatures are not properly handled.

## Proof-of-Concept:

Reusing the same signed Ethereum transaction bypasses Signatures validation:

    if len(sigs) > 0 {
     return ctx, errorsmod.Wrap(sdkerrors.ErrInvalidRequest, "for eth tx Signatures should be empty")
    }


## Impact:

- Potential double-spending or unauthorized state modifications.

- Risks to user funds and overall chain integrity.

## Risk Level: 

High

## Mitigation:

- Introduce nonce-based replay protection:

- Ensure each MsgEthereumTx includes and validates a unique nonce.

- Store and track processed transaction hashes to prevent reuse.
