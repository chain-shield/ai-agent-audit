# Vulnerability details

The `execute` function is responsible for invoking the "ExecuteMsg" of a Wasm contract, enabling interaction between the Ethereum Virtual Machine (EVM) and WebAssembly (Wasm). This allows the execution of Wasm contract methods through the EVM, enabling cross-VM communication.

```go
// execute invokes a Wasm contract's "ExecuteMsg", which corresponds to
// "wasm/types/MsgExecuteContract". This enables arbitrary smart contract
// execution using the Wasm VM from the EVM.
//
// Implements "execute" from evm/embeds/contracts/Wasm.sol:
//
//	```solidity
//	 function execute(
//	   string memory contractAddr,
//	   bytes memory msgArgs,
//	   BankCoin[] memory funds
//	 ) payable external returns (bytes memory response);
//	```
//
// Contract Args:
//   - contractAddr: nibi-prefixed Bech32 address of the wasm contract
//   - msgArgs: JSON encoded wasm execute invocation
//   - funds: Optional funds to supply during the execute call. It's
//     uncommon to use this field, so you'll pass an empty array most of the time.
func (p precompileWasm) execute(
	start OnRunStartResult,
	caller gethcommon.Address,
	readOnly bool,
) (bz []byte, err error) {
	method, args, ctx := start.Method, start.Args, start.CacheCtx
	defer func() {
		if err != nil {
			err = ErrMethodCalled(method, err)
		}
	}()
	if err := assertNotReadonlyTx(readOnly, method); err != nil {
		return nil, err
	}

	wasmContract, msgArgsBz, funds, err :=
	p.parseArgsWasmExecute(args) // <---------
	if err != nil {
		err = ErrInvalidArgs(err)
		return
	}
	data, err := p.Wasm.Execute(ctx, wasmContract, eth.EthAddrToNibiruAddr(caller), msgArgsBz, funds)
	if err != nil {
		return
	}
	return method.Outputs.Pack(data)
}

```

In the `parseArgsWasmExecute` function, the `contractAddrStr` is validated using `sdk.AccAddressFromBech32(contractAddrStr)` to ensure it is a valid Bech32 address. This is a good measure for confirming that the provided address follows the correct format for the Cosmos SDK. However, despite this check effectively preventing many potential issues, it does not address some additional risks, particularly security-related concerns.

Calling a contract with an invalid contract address (i.e., a valid address that either has no contract code or is not a smart contract address) may lead to the following risks:

- **Contract Call Failure**: If the contract address does not exist or lacks valid contract code, the contract execution may fail. In such cases, the smart contract call would return an error or exception, causing the transaction to fail.
- **Incorrect Fund Transfers**: Attackers could potentially construct malicious fund parameters, causing funds to be erroneously transferred to unintended addresses.
- **Privilege Abuse**: If proper permission checks are not in place, attackers might exploit valid addresses to invoke contracts they are not authorized to interact with, leading to unauthorized operations.

### Suggested Fixes:

- **Check Contract Existence**

```go
if !isContractDeployed(wasmContract) {
    return nil, fmt.Errorf("invalid contract address: not deployed")
}
```

- **Whitelist of Contract Addresses**

```go
if !isInContractWhitelist(wasmContract) {
    return nil, fmt.Errorf("contract address is not authorized")
}

```

- **Permission Validation**

```go
if !hasPermissionToExecute(caller, wasmContract) {
    return nil, fmt.Errorf("caller does not have permission to execute this contract")
}
```
