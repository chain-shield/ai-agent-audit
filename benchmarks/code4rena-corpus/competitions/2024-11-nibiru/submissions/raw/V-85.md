# Vulnerability details

## Finding description and impact

Currently, Nibiru uses `transfer()` method to handle the ERC20 tokens' transfer operations. However, there are such tokens that do not return any values and the protocol would not be able to handle such scenarios.

## Proof of Concept

There are tokens that don't return boolean for ERC20 operations. The full list can be checked here:

https://github.com/d-xo/weird-erc20?tab=readme-ov-file#no-revert-on-failure
```
Some tokens do not return a bool (e.g. USDT, BNB, OMG) on ERC20 methods. see here for a comprehensive (if somewhat outdated) list.
```

Currently, the protocol uses `transfer()` method for ERC20 operations instead of OZ `safeTransfer()` that could handle such scenarios:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/erc20.go#L85
```
resp, err = e.CallContract(ctx, e.ABI, from, &contract, true, Erc20GasLimitExecute, "transfer", to, amount)

```


## Recommended mitigation steps

Use `safeTransfer()` that is considered to be the most secure version of the ERC20 token transfer method.
