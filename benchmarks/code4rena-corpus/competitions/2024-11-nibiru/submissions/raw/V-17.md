# Vulnerability details

## Finding description and impact

The Nibiru EVM implementation does not support the RANDAO functionality by setting `Random` to `nil` in the EVM block context. This breaks compatibility with smart contracts that rely on the PREVRANDAO opcode (previously DIFFICULTY before the Merge) and prevents contracts from accessing on-chain randomness.

The impact is severe because:
1. Smart contracts using PREVRANDAO will not function as expected
2. Core functionality of protocols relying on this randomness source will be broken
3. This deviation from EVM compatibility could prevent deployment of certain protocols 
4. The implementation differs from how other EVM chains handle randomness post-Merge

## Proof of Concept

The issue occurs in [msg_server.go#L136](https://github.com/code-423n4/2024-11-nibiru/blob/84054a4f00fdfefaa8e5849c53eb66851a762319/x/evm/keeper/msg_server.go#L136):

```go
blockCtx := vm.BlockContext{
    // ...
    Random:      nil, // not supported
}
```

When contracts call the PREVRANDAO opcode (0x44), they expect the EVM to return a random value derived from the beacon chain. The opcode implementation in go-ethereum shows this:

```go
func opRandom(pc *uint64, interpreter *EVMInterpreter, scope *ScopeContext) ([]byte, error) {
    v := new(uint256.Int).SetBytes(interpreter.evm.Context.Random.Bytes())
    scope.Stack.push(v)
    return nil, nil
} 
```

By setting `Random: nil`, any contract using this opcode will panic when trying to access the nil value.

Example contract that would break:
```solidity
contract RandomConsumer {
    function getRandom() public view returns (uint256) {
        return block.prevrandao; // Will panic on Nibiru
    }
}
```

## Recommended mitigation steps

There are multiple options to properly support RANDAO:

1. Implement a deterministic randomness source using block data:

```go
blockCtx := vm.BlockContext{
    // ...
    Random: crypto.Keccak256Hash(append(header.Hash().Bytes(), 
                                       big.NewInt(header.Height).Bytes()...)),
}
```

2. Use the Tendermint consensus randomness:

```go 
blockCtx := vm.BlockContext{
    // ...
    Random: gethcommon.BytesToHash(ctx.HeaderHash().Bytes()),  
}
```
