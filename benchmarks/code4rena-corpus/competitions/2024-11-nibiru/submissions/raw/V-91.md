# Vulnerability details

## Issue Description:

The function EthMsgsFromTendermintBlock decodes transactions as follows:

    tx, err := b.clientCtx.TxConfig.TxDecoder()(tx)
     if err != nil {
      b.logger.Debug("failed to decode transaction in block", "height", block.Height, "error", 
     err.Error())
    continue
    }


The error handling logs the error and proceeds to the next iteration of the loop, ignoring the failure silently. While logging errors is useful, it doesn't properly handle the error scenario and continues processing without addressing the issue.

## Proof-of-Concept

If the transaction decoding fails, continuing the loop could result in faulty data being processed and returned.

## Impact

#1. Silent failure: The system might continue processing invalid or incomplete data, leading to 
    inaccurate or incomplete information being returned to the client.

#2. Data integrity risk: Invalid transactions could propagate into the final output.
    

## Risk

This could potentially result in incorrect or incomplete block data being exposed through the RPC.

## Mitigation

Consider returning an error instead of silently continuing to ensure the system properly handles unexpected failures. Alternatively, log the error with more context for later review.

    if err != nil {
     return nil, fmt.Errorf("failed to decode transaction in block %d: %w", block.Height, err)
    }
