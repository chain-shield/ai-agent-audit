# Vulnerability details

## Finding description and impact

Logs are crucial for off-chain components to efficiently retrieve data and enable event-driven actions. Many DApps integrate off-chain components with their smart contracts to automate processes, such as triggering actions when specific logs are emitted. Examples of tools and systems that heavily rely on logs include:

* Security Monitoring: To trigger actions such as pausing contracts when anomalies are detected.
* Exchanges: For monitoring token transfers and other financial activities.
* Cross-Chain Bridges: To facilitate and verify asset transfers across blockchains.
* Data Query Platforms: Tools like Dune Analytics and TheGraph, which depend on logs for querying and indexing blockchain data.

Currently, all logs emitted by `CallContract` transactions are lost, including critical events like ERC20 Transfer logs from FunToken precompile. This issue arises because the `EmitLogEvents` function is only invoked by EthereumTx, and logs from `CallContract` are not included in `evmResp.Logs`.

This creates a significant gap in the functionality of off-chain tools and increases the risk of exploitation. For example, a malicious actor could create a `FunToken` contract where the ERC20 transfer function allows them to perform operations which they don't want offchain components to notice. This vulnerability could lead to severe unintended consequences for the ecosystem.


## Recommended mitigation steps

Include the logs from CallContract in the transaction, whether it was triggered by `EthereumTx`, `CreateFunToken` or `ConvertCoinToEvm`
