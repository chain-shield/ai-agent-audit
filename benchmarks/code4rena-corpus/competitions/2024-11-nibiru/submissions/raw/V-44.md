# Vulnerability details

# The `ApplyEvmMsg` Function in `x/evm/keeper/msg_server.go` Allows Transfers with Negative Values

The ApplyEvmMsg function is responsible for applying a message in the Ethereum Virtual Machine (EVM) and computing the updated blockchain state.

Within ApplyEvmMsg, the ParseWeiAsMultipleOfMicronibi function is called to convert the Wei value (the smallest unit of Ether) from the message into Micronibi.

[Source Code](https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L249)

```go
func (k *Keeper) ApplyEvmMsg(ctx sdk.Context,
	msg core.Message,
	tracer vm.EVMLogger,
	commit bool,
	evmConfig *statedb.EVMConfig,
	txConfig statedb.TxConfig,
	fullRefundLeftoverGas bool,
) (resp *evm.MsgEthereumTxResponse, evmObj *vm.EVM, err error) {
	...

	msgWei, err := ParseWeiAsMultipleOfMicronibi(msg.Value()) // <--------
	if err != nil {
		return nil, evmObj, errors.Wrapf(err, "ApplyEvmMsg: invalid wei amount %s", msg.Value())
	}

	...
}
```

However, in the ParseWeiAsMultipleOfMicronibi function, when weiInt is negative, it is incorrectly returned as-is without conversion to Micronibi. One Micronibi equals 101210^{12}1012 Wei. This leads to subsequent misinterpretation of the negative Wei value as a valid Micronibi value.

[Source Code](https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L402)

```go
func ParseWeiAsMultipleOfMicronibi(weiInt *big.Int) (newWeiInt *big.Int, err error) {
	// If "weiValue" is nil, 0, or negative, early return
	if weiInt == nil || !(weiInt.Cmp(big.NewInt(0)) > 0) { // <----------
		return weiInt, nil
	}

	// Error if weiInt is too small
	tenPow12 := new(big.Int).Exp(big.NewInt(10), big.NewInt(12), nil)
	if weiInt.Cmp(tenPow12) < 0 {
		return weiInt, fmt.Errorf(
			"wei amount is too small (%s), cannot transfer less than 1 micronibi. 1 NIBI == 10^6 micronibi == 10^18 wei", weiInt)
	}

	// Truncate to the highest Micronibi amount
	newWeiInt = evm.NativeToWei(evm.WeiToNative(weiInt))
	return newWeiInt, nil
}
```

This behavior allows subsequent operations, such as evmObj.Create or evmObj.Call, to process transactions with negative transfer values.

### Example Flow of Negative Transfers

In ApplyEvmMsg, if a negative msgWei value is passed to evmObj.Call, the following chain of events occurs:

```go
func (k *Keeper) ApplyEvmMsg(ctx sdk.Context,
	msg core.Message,
	tracer vm.EVMLogger,
	commit bool,
	evmConfig *statedb.EVMConfig,
	txConfig statedb.TxConfig,
	fullRefundLeftoverGas bool,
) (resp *evm.MsgEthereumTxResponse, evmObj *vm.EVM, err error) {
	...

	msgWei, err := ParseWeiAsMultipleOfMicronibi(msg.Value())
	if err != nil {
		return nil, evmObj, errors.Wrapf(err, "ApplyEvmMsg: invalid wei amount %s", msg.Value())
	}

	if contractCreation {
		ret, _, leftoverGas, vmErr = evmObj.Create( // <---------
			sender,
			msg.Data(),
			leftoverGas,
			msgWei,
		)
	} else {
		ret, leftoverGas, vmErr = evmObj.Call( // <---------
			sender,
			*msg.To(),
			msg.Data(),
			leftoverGas,
			msgWei,
		)
	}

	...
}
```

Within evmObj.Call, if the value is negative, the CanTransfer function is invoked to verify the balance:

```go
func (evm *EVM) Call(caller ContractRef, addr common.Address, input []byte, gas uint64, value *big.Int) (ret []byte, leftOverGas uint64, err error) {
...
	// Fail if we're trying to transfer more than the available balance
	if value.Sign() != 0 && !evm.Context.
	CanTransfer(evm.StateDB, caller.Address(), value) { // <--------
		return nil, gas, ErrInsufficientBalance
	}

	evm.Context.Transfer(evm.StateDB, caller.Address(), addr, value) // <--------

...
}
```

The CanTransfer function only verifies whether the balance is sufficient but does not validate if the transfer value is negative:

```go
// CanTransfer checks whether there are enough funds in the address' account to make a transfer.
// This does not take the necessary gas into account to make the transfer valid.
func CanTransfer(db vm.StateDB, addr common.Address, amount *big.Int) bool {
	return db.GetBalance(addr).Cmp(amount) >= 0
}
```

This leads to negative transfers being processed:

```go
evm.Context.Transfer(evm.StateDB, caller.Address(), addr, value)
```

### Implications

- **Unintended Effects on Balances**:
    - The target account's balance could increase due to the negative transfer amount.
    - The sender’s balance could be incorrectly reduced.
- **System State Corruption**:
    - Invalid data, such as negative balances, could pollute the state database, causing downstream contracts or applications to behave incorrectly.
- **Chained Exploits**:
    - An attacker could exploit negative balances to trigger vulnerabilities in other smart contracts, amplifying the attack's impact.

### Proof of Concept

As noted in the code comments, the eth_call pathway bypasses the AnteHandler, avoiding additional validations.

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L292

```go
	// Should check again even if it is checked on Ante Handler, because eth_call
	// don't go through Ante Handler.
```

By invoking EthCall via the gRPC query processor (EthCall/EthEstimateGas), an attacker can craft a malicious transaction with a negative value, such as:

```json
{
  "from": "0xAttackerAddress",
  "to": "0xVictimAddress",
  "value": "-50",
  "gas": "50000",
  "data": ""
}
```

### Impact

1. **Direct Gains**:
    - The attacker’s account balance may increase unexpectedly, while the victim’s balance decreases (or becomes negative).
2. **State Corruption**:
    - Negative balances in the state database may cause logical errors in on-chain contracts or applications.
3. **Chained Attacks**:
    - The attacker could leverage negative balances to exploit other contract vulnerabilities, exacerbating the damage.

### Suggested Fix

The function should return an error for both zero and negative weiInt values instead of treating them as valid:

```go
if weiInt == nil || weiInt.Cmp(big.NewInt(0)) <= 0 {
    return nil, fmt.Errorf("wei amount cannot be zero or negative (%s)", weiInt)
}
```

This fix ensures that only positive values are processed, preventing unintended behavior.
