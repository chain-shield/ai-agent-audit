# Vulnerability details

## Finding description and impact

Currently the protocol only allows `string` to be used for ERC20 `symbol()`. But the problem is that it won't be possible to have certain tokens in the system such as MKR (Maker) that are widely used but have `bytes32` as their symbol.

## Proof of Concept

The protocol currently fetches the symbol of ERC20 contract as string:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/erc20.go#L153-157
```
func (k Keeper) LoadERC20Symbol(
	ctx sdk.Context, abi *gethabi.ABI, erc20 gethcommon.Address,
) (out string, err error) {
	return k.LoadERC20String(ctx, abi, erc20, "symbol")
}

```

`LoadERC20String()` method loads the string:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/erc20.go#L165-192
```
func (k Keeper) LoadERC20String(
	ctx sdk.Context,
	erc20Abi *gethabi.ABI,
	erc20Contract gethcommon.Address,
	methodName string,
) (out string, err error) {
	res, err := k.CallContract(
		ctx,
		erc20Abi,
		evm.EVM_MODULE_ADDRESS,
		&erc20Contract,
		false,
		Erc20GasLimitQuery,
		methodName,
	)
	if err != nil {
		return out, err
	}

	erc20Val := new(ERC20String)
	err = erc20Abi.UnpackIntoInterface(
		erc20Val, methodName, res.Ret,
	)
	if err != nil {
		return out, err
	}
	return erc20Val.Value, err
}

```

This method is used when fetching ERC20 metadata during the process of FunToken creation:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/funtoken_from_erc20.go#L69-73
```
type ERC20Metadata struct {
	Name     string
	Symbol   string
	Decimals uint8
}

```

So it won't be possible to use certain ERC20 such as token of the Maker protocol that use bytes32 as their symbol:

https://github.com/d-xo/weird-erc20?tab=readme-ov-file#balance-modifications-outside-of-transfers-rebasingairdrops
```
Some tokens (e.g. MKR) have metadata fields (name / symbol) encoded as bytes32 instead of the string prescribed by the ERC20 specification.

This may cause issues when trying to consume metadata from these tokens.

```

## Recommended mitigation steps

Allow usage of bytes32 ERC20 symbol().
