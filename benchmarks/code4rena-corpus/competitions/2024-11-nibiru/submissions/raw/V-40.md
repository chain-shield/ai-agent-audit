# Vulnerability details

## Finding description and impact

DeleteAccount function is designed to handles contract's suicide call, clearing the balance, contract bytecode, contract state, and its native account. However lack of check is current account is an contract address.

The potential problem arises when the function processes non-contract accounts, which may not have associated contract bytecode or state, leading to unnecessary operations or errors when interacting with contract-specific methods like clearing the contract's storage and bytecode.

## Proof of Concept
From the function comment we can see developer intends to clean the bytecode :
<https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/statedb.go#L155-L158>

func (k *Keeper) DeleteAccount(ctx sdk.Context, addr gethcommon.Address) error { //@audit not check if account is contract ? https://github.com/evmos/evmos/blob/main/x/evm/keeper/statedb.go#L244-L279
	nibiruAddr := sdk.AccAddress(addr.Bytes())
	acct := k.accountKeeper.GetAccount(ctx, nibiruAddr)
	if acct == nil {
		return nil
	}

	_, ok := acct.(eth.EthAccountI)
	if !ok {
		return evm.ErrInvalidAccount.Wrapf("type %T, address %s", acct, addr)
	}

	// clear balance
	if err := k.SetAccBalance(ctx, addr, new(big.Int)); err != nil {
		return err
	}

	// clear storage
	k.ForEachStorage(ctx, addr, func(key, _ gethcommon.Hash) bool {
		k.SetState(ctx, addr, key, nil)
		return true
	})

	k.accountKeeper.RemoveAccount(ctx, acct)

	return nil
}
