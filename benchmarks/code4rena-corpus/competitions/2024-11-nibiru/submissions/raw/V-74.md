# Vulnerability details

## Description:

The stopIter callback is expected to stop iteration when it returns false, but if it always returns true, the loop can iterate indefinitely.

The iterator loop in ForEachStorage uses stopIter incorrectly. When stopIter returns false, the iteration stops prematurely, but it is intended to continue iterating.

## Proof of Concept #1:

    iter := k.EvmState.AccState.Iterate(ctx, collections.PairRange[gethcommon.Address, 
    gethcommon.Hash]{}.Prefix(addr))
    defer iter.Close()
    for ; iter.Valid(); iter.Next() {
    if !stopIter(hash, gethcommon.BytesToHash(val)) {
        return
    }
    }

## Proof of Concept #2:

    if !stopIter(hash, gethcommon.BytesToHash(val)) {
      return
    }


## Impact: 

Medium. May lead to node resource exhaustion.
Important storage keys may be skipped, leading to incomplete storage traversal.

## Risk: 

Dependent on usage patterns and callback implementations.

## Mitigation #1:

    limit := 10000 // Example limit
    count := 0
    for ; iter.Valid() && count < limit; iter.Next() {
    if !stopIter(hash, gethcommon.BytesToHash(val)) {
        return
    }
    count++
    }
    if count >= limit {
      log.Warn("Iteration limit reached")
    }

## Mitigation #2:

Fix the conditional logic to allow the iterator to proceed when stopIter returns true:

    if stopIter(hash, gethcommon.BytesToHash(val)) {
      break
    }
