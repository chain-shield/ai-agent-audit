# Vulnerability details

## Issue Description:

The Mint function allows minting tokens, which is a highly sensitive operation. While the Solidity function restricts access using the onlyOwner modifier, there is no explicit check in the Go implementation to ensure only authorized users can invoke this function.

The Mint method does not explicitly verify if the caller is the contract owner. While the documentation specifies onlyOwner, the implementation does not enforce this constraint programmatically.

## Proof of Concept (PoC)

The Mint function directly calls the contract's mint method without verifying the sender's authorization.


    func (e erc20Calls) Mint(
	contract, from, to gethcommon.Address, amount *big.Int,
	ctx sdk.Context,
    ) (evmResp *evm.MsgEthereumTxResponse, err error) {
	// No access control check here.
	return e.CallContract(ctx, e.ABI, from, &contract, true, Erc20GasLimitExecute, "mint", to, 
    amount)
    }


## Impact

- If the from address is not properly validated, unauthorized parties could mint tokens, inflating the total supply and potentially compromising the token's value and ecosystem.

- An attacker could exploit this by calling the Mint function directly using a valid from address that lacks ownership permissions.

- Unauthorized users could mint tokens, leading to inflation and loss of trust in the system.

## Risk

Critical

This flaw directly affects the token's supply integrity.


## Mitigation

Enforce an ownership check before executing the Mint function.

    if !k.IsAuthorized(ctx, from) {
	return nil, errors.New("unauthorized access to mint function")
    }
