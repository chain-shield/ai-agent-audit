# Vulnerability details

## Issue Description:

The SetParams function checks if CreateFuntokenFee is negative, but no validation occurs on other parameters of params. There might be other parameters that should be validated for correct ranges, types, or values.

## Proof-of-Concept:

    func (k Keeper) SetParams(ctx sdk.Context, params evm.Params) (err error) {
    if params.CreateFuntokenFee.IsNegative() {
        return fmt.Errorf("createFuntokenFee cannot be negative: %s", params.CreateFuntokenFee)
    }

    k.EvmState.ModuleParams.Set(ctx, params)
    return
    }

## Impact:

Incomplete Validation: Missing validation for other parameters could allow unintended values to be set, potentially causing vulnerabilities or improper contract execution.

## Risk:

Moderate: Improper parameter values could introduce logic flaws or security issues, especially if the contract deals with funds or important configurations.

## Mitigation:

Implement validation for all parameters of the params struct to ensure correctness before setting them.

    func (k Keeper) SetParams(ctx sdk.Context, params evm.Params) (err error) {
    if params.CreateFuntokenFee.IsNegative() {
        return fmt.Errorf("createFuntokenFee cannot be negative: %s", params.CreateFuntokenFee)
    }

    // Additional validation for other params
    if params.SomeOtherParam < 0 {
        return fmt.Errorf("invalid parameter: SomeOtherParam cannot be negative")
    }

    k.EvmState.ModuleParams.Set(ctx, params)
    return
    }
