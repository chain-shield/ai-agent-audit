# Vulnerability details

## Issue Description:

In the GetAccount method, if the GetAccountWithoutBalance returns nil (i.e., no account is found), the function continues to access the acct object, leading to a potential nil dereference.

## Proof-of-Concept:

statedb.go#L28

    acct := k.GetAccountWithoutBalance(ctx, addr)
    if acct == nil {
     return nil
    }
    acct.BalanceNative = k.GetEvmGasBalance(ctx, addr) // Potential nil dereference
    return acct

## Impact:

High: A nil dereference can cause a runtime panic, leading to a crash of the application.
The system may not recover and could lead to data inconsistencies.

## Risk:

High: A crash could interrupt processing and affect multiple contracts and accounts.

## Mitigation: 

Add a nil check before accessing the account:

    if acct == nil {
     return nil
    }
    acct.BalanceNative = k.GetEvmGasBalance(ctx, addr)
    return acct
