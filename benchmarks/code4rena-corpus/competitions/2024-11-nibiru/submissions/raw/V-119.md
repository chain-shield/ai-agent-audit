# Vulnerability details

## Description:

In the TraceCall function, there is no input validation to ensure that the parameters passed, especially the txArgs and contextBlock, are valid and not nil.

User-provided inputs like hash, txArgs, or config are not properly validated for correctness. Malformed inputs could lead to panics or unexpected errors.

## Proof-of-Concept:

    traceTxRequest := evm.QueryTraceTxRequest{
     Msg: txArgs.ToMsgEthTx(), // txArgs is not validated before usage
    }


## Impact:

- Malformed inputs can cause system instability.

- Exposes backend to DoS attacks.

- If txArgs is nil or improperly formatted, this could result in a runtime error, crashing the application. It may also lead to incorrect behavior when invoking trace functionality.

## Risk:

High

This missing validation can lead to unexpected crashes, incorrect results, or failures in tracing due to malformed inputs.

## Mitigation:

    if txArgs == nil || txArgs.ToMsgEthTx() == nil {
      return nil, errors.New("invalid transaction arguments")
    }
    if config != nil && !isValidTraceConfig(config) {
     return nil, errors.New("invalid trace configuration")
    }
