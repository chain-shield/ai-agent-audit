# Vulnerability details

## Issue Description: 

The return value of k.FunTokens.SafeInsert is not properly checked. If the insert operation fails, the funtoken object is still returned, which can lead to inconsistencies in state and potential exploits.

## Proof-of-Concept:

    return funtoken, k.FunTokens.SafeInsert(
      ctx, erc20, bankDenom, false,
    )

Here, the return value of SafeInsert should be checked, and the function should abort on failure.

## Impact:

Failing to handle errors from SafeInsert can result in invalid or incomplete state updates. This might allow attackers to bypass restrictions or cause token mapping inconsistencies.

## Risk:

High

## Mitigation:

    err = k.FunTokens.SafeInsert(ctx, erc20, bankDenom, false)
    if err != nil {
     return nil, fmt.Errorf("failed to insert funtoken mapping: %w", err)
    }
    return funtoken, nil
