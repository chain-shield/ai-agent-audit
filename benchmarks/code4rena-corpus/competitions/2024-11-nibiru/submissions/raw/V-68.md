# Vulnerability details

## Finding description and impact

Currently, refunds are incorrectly calculated after EVM message is applied. This is because the function `EthereumTx()` uses different formula rather than using refund that's calculated inside of the `ApplyEvmMsg()` function. This leads to a situation where NibiruVM loses compatibility with EVM as refunds are handled differently.

## Proof of Concept

The current refund functionality is implemented the following way:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L85-92
```
	refundGas := uint64(0)
	if evmMsg.Gas() > blockGasUsed {
		refundGas = evmMsg.Gas() - blockGasUsed
	}
	weiPerGas := txMsg.EffectiveGasPriceWeiPerGas(evmConfig.BaseFeeWei)
	if err = k.RefundGas(ctx, evmMsg.From(), refundGas, weiPerGas); err != nil {
		return nil, errors.Wrapf(err, "EthereumTx: error refunding leftover gas to sender %s", evmMsg.From())
	}

```

As you can see here, the `refundGas` is first set to 0 and then it's calculated by using the difference between gas limit of the message and total block gas used. Later, it just calls `RefundGas()` function from the `gas_fees` where the funds are finally transferred to the `from` account. However, that's not correct, as the refunds are calculated in the geth client the following way:

https://github.com/NibiruChain/go-ethereum/blob/nibiru/geth/core/state_transition.go#L368-383
```
func (st *StateTransition) refundGas(refundQuotient uint64) {
	// Apply refund counter, capped to a refund quotient
	refund := st.gasUsed() / refundQuotient
	if refund > st.state.GetRefund() {
		refund = st.state.GetRefund()
	}
	st.gas += refund

	// Return ETH for remaining gas, exchanged at the original rate.
	remaining := new(big.Int).Mul(new(big.Int).SetUint64(st.gas), st.gasPrice)
	st.state.AddBalance(st.msg.From(), remaining)

	// Also return remaining gas to the block gas counter so it is
	// available for the next transaction.
	st.gp.AddGas(st.gas)
}

```

So it first calculates the `refund` value by using `gasUsed` and `refundQuotient` parameters. This logic is implemented inside of the `ApplyEvmMsg()` in the Nibiru client:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/msg_server.go#L369-381
```
refundQuotient := params.RefundQuotientEIP3529
	if fullRefundLeftoverGas {
		refundQuotient = 1 // 100% refund
	}
	temporaryGasUsed := msg.Gas() - leftoverGas
	refund := GasToRefund(stateDB.GetRefund(), temporaryGasUsed, refundQuotient)

	// update leftoverGas and temporaryGasUsed with refund amount
	leftoverGas += refund
	temporaryGasUsed -= refund
	if msg.Gas() < leftoverGas {
		return nil, evmObj, errors.Wrapf(core.ErrGasUintOverflow, "ApplyEvmMsg: message gas limit (%d) < leftover gas (%d)", msg.Gas(), leftoverGas)
	}

```

It uses the formula from the `gas_fees` file:

https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/gas_fees.go#L88-95
```
func GasToRefund(availableRefund, gasConsumed, refundQuotient uint64) uint64 {
	// Apply refund counter
	refund := gasConsumed / refundQuotient
	if refund > availableRefund {
		return availableRefund
	}
	return refund
}

```

The problem is that after these calculations are done in the `ApplyEvmMsg()`, gas refund is recalculated by using gas limit and block gas used in the `EthereumTx()` function which is not correct as this implementation does not use the refund values calculated in the `ApplyEvmMsg()`.

## Recommended mitigation steps

Change the logic so that refunds calculations are compatible with the ones implemented in the geth 
execution client.
