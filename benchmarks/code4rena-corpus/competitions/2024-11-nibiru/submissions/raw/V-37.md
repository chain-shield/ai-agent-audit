# Vulnerability details

SetParams is a method used to set parameters for the EVM module, specifically the configuration parameters contained in the evm.Params structure. These parameters control the behavior and settings of the EVM module, including fee parameters such as CreateFuntokenFee.

[Source code](https://github.com/code-423n4/2024-11-nibiru/blob/main/x/evm/keeper/evm_state.go#L120)

```go
// SetParams: Setter for the module parameters.
func (k Keeper) SetParams(ctx sdk.Context, params evm.Params) (err error) {
	if params.CreateFuntokenFee.IsNegative() {
		return fmt.Errorf("createFuntokenFee cannot be negative: %s", params.CreateFuntokenFee)
	}

	k.EvmState.ModuleParams.Set(ctx, params)
	return
}
```

```go
// Params defines the EVM module parameters
type Params struct {
	// extra_eips defines the additional EIPs for the vm.Config
	ExtraEIPs []int64 `protobuf:"varint,4,rep,packed,name=extra_eips,json=extraEips,proto3" json:"extra_eips,omitempty" yaml:"extra_eips"`
	// evm_channels is the list of channel identifiers from EVM compatible chains
	EVMChannels []string `protobuf:"bytes,8,rep,name=evm_channels,json=evmChannels,proto3" json:"evm_channels,omitempty"`
	// Fee deducted and burned when calling "CreateFunToken" in units of
	// "evm_denom".
	CreateFuntokenFee cosmossdk_io_math.Int `protobuf:"bytes,9,opt,name=create_funtoken_fee,json=createFuntokenFee,proto3,customtype=cosmossdk.io/math.Int" json:"create_funtoken_fee"`
}
```

- The **ExtraEIPs** parameter is a slice of integers that includes additional Ethereum Improvement Proposals (EIPs) to be enabled in the EVM configuration. This allows the system to support various Ethereum features as needed.
- The **EVMChannels** parameter is a slice of strings that lists the channel identifiers from EVM-compatible chains.
- The **CreateFuntokenFee** defines the fee (in units of evm_denom) required when calling the CreateFunToken contract.

### Impact

However, **ExtraEIPs** and **EVMChannels** should have access controls in place to prevent unauthorized modifications, as uncontrolled changes could have significant consequences:

- If the ExtraEIPs list includes unaudited or unstable EIPs, the characteristics of these EIPs could be exploited for attacks, such as increasing contract complexity or causing unnecessary gas consumption. Without strict reviews, malicious developers could leverage this feature to create vulnerabilities.
- If EVMChannels is not properly restricted, cross-chain attacks could occur. For example, a malicious chain that connects through EVMChannels might send tampered transactions or requests, exploiting the system’s trust in external chains. These attacks could include replay attacks, transaction forgery, or the transmission of malicious data.

### Suggested Fix

To prevent unauthorized modification of the ExtraEIPs list, it is recommended to restrict changes to only authorized administrators or multisig contracts.

Additionally, modifications to the EVMChannels configuration should be limited to administrators with sufficient privileges or audited contracts. All additions or changes to supported chains should undergo a strict auditing process.
