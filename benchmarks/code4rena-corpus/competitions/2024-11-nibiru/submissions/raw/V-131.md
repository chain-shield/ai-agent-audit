# Vulnerability details

## Issue Description:

The sortedDirties function creates a new slice and sorts it each time it is called, even if the dirties map has not changed.

 Sorting dirty addresses may lead to performance issues when the number of entries is large.

## Proof of Concept:

Repeated calls to sortedDirties cause redundant computation.

    func (j *journal) sortedDirties() []common.Address {
    keys := make([]common.Address, 0, len(j.dirties))
    for k := range j.dirties {
        keys = append(keys, k)
    }
    sort.Slice(keys, func(i, j int) bool {
        return bytes.Compare(keys[i].Bytes(), keys[j].Bytes()) < 0
    })
    return keys
    }


## Impact:

- Increased gas costs in cases with frequent dirty address accesses.

- Inefficiency when used in a loop or multiple times.

- Performance degradation in scenarios with a high number of dirty addresses.

##Risk Level: 

Medium

## Mitigation:

Cache the sorted list of dirties and invalidate the cache only when dirties is updated.

Fix Code:

    type journal struct {
    entries      []JournalChange
    dirties      map[common.Address]int
    sortedCache  []common.Address
    cacheInvalid bool
    }

    func (j *journal) append(entry JournalChange) {
    if addr := entry.Dirtied(); addr != nil {
        j.dirties[*addr]++
        j.cacheInvalid = true
    }
    // Existing logic
    }

    func (j *journal) sortedDirties() []common.Address {
    if j.cacheInvalid || j.sortedCache == nil {
        keys := make([]common.Address, 0, len(j.dirties))
        for k := range j.dirties {
            keys = append(keys, k)
        }
        sort.Slice(keys, func(i, j int) bool {
            return bytes.Compare(keys[i].Bytes(), keys[j].Bytes()) < 0
        })
        j.sortedCache = keys
        j.cacheInvalid = false
    }
    return j.sortedCache
    }
