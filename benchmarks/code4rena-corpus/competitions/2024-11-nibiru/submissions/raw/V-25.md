# Vulnerability details

The `requiredGas` function is responsible for calculating the gas required to execute a specific contract method, based on the input data and ABI information. It first retrieves the method from the input `data` using the method ID, and then calculates the total gas required based on the method type (whether it modifies state or not) and the configured gas costs.

```go
func requiredGas(input []byte, abi *gethabi.ABI) uint64 {
	method, err := methodById(abi, input[:4])
	if err != nil {
		// It's appropriate to return a reasonable default here
		// because the error from DecomposeInput will be handled automatically by
		// "Run". In go-ethereum/core/vm/contracts.go, you can see the execution
		// order of a precompile in the "runPrecompiledContract" function.
		return gethparams.TxGas // return reasonable default
	}
	gasCfg := store.KVGasConfig()

	// Map access could panic. We know that it won't panic because all methods
	// are in the map, which is verified by unit tests.
	var costPerByte, costFlat uint64
	if isMutation[PrecompileMethod(method.Name)] {
		costPerByte, costFlat = gasCfg.WriteCostPerByte, gasCfg.WriteCostFlat
	} else {
		costPerByte, costFlat = gasCfg.ReadCostPerByte, gasCfg.ReadCostFlat
	}

	// Calculate the total gas required based on the input size and flat cost
	return (costPerByte * uint64(len(input[4:]))) + costFlat
}

```

The return value is of type `uint64`, but due to unsafe arithmetic operations, the total gas can overflow and become 0.

```go
return (costPerByte * uint64(len(input[4:]))) + costFlat
```

### Impact

- Attackers could bypass the gas limits, consuming very little resources to execute contracts.
- It could lead to a DoS (Denial of Service) attack, consuming massive node resources and potentially causing system crashes.
- Unauthorized operations could be executed maliciously, affecting the integrity and security of contracts.
- Potential financial losses, especially for contracts related to funds transfer.
- Increased load on the blockchain network, impacting normal transactions for other users.
- Unpredictable contract behavior, potentially leading to inconsistent states or contract failures.

### Proof of Concept

We can observe that `costFlat` is fixed. For state-changing methods (e.g., write operations), the gas cost for write operations is selected; for read operations (e.g., querying state), the gas cost for read operations is selected. It’s either 1000 or 2000. Similarly, `costPerByte` is also fixed, either 3 or 30.

`uint64(len(input[4:]))` represents the input size, excluding the first four bytes (the function signature). This part is controllable by the attacker.

In other words, attackers can manipulate the input data size and choose between read or write operations to cause an overflow in the total gas calculation, even resulting in a gas value of 0.

```go
func KVGasConfig() GasConfig {
	return GasConfig{
		HasCost:          1000,
		DeleteCost:       1000,
		ReadCostFlat:     1000, // <-------
		ReadCostPerByte:  3,    // <-------
		WriteCostFlat:    2000, // <-------
		WriteCostPerByte: 30,   // <-------
		IterNextCostFlat: 30,
	}
}
```

### Suggested Fix

The solution to fix this vulnerability is simple: use safe multiplication and addition operations, or check if the result of multiplication and addition exceeds the maximum value of `uint64`. This would prevent overflow issues and ensure that the gas calculation remains within valid bounds.
