# Vulnerability details

## Finding description and impact

Currently `bankDenom` is converted to the string of the ERC20 address. The problem is that it's not supposed to be a string of an address but rather a base denomination with exponent of 0 leading to an incorrect FunToken metadata construction.

## Proof of Concept

Take a look at how `bankDenom` is assigned:

```
bankDenom := fmt.Sprintf("erc20/%s", erc20.String())

```

So it takes input parameter and converts it to string:

```
func (k *Keeper) createFunTokenFromERC20(
	ctx sdk.Context, erc20 gethcommon.Address,
)

```

As you can see here, `erc20` here is equal to the ETH address so it will be just an address converted to a string. Then it creates FunToken mapping the following way:

```
funtoken = &evm.FunToken{
		Erc20Addr: eth.EIP55Addr{
			Address: erc20,
		},
		BankDenom:      bankDenom,
		IsMadeFromCoin: false,
	}
```

As you can see, `BankDenom` is equal to the `bankDenom` assigned to a string instead of being an actual bankDenom. From the docs:

https://nibiru.fi/docs/evm/funtoken.html
```
Base denomination. The DenomUnit.Denom with an exponent of 0.

```

For example, for wei it has to be "Wei" as `bankDenom` instead of the string of the ERC20 address.

## Recommended mitigation steps

Change the `bankDenom` so it reflects the actual value accordingly.
