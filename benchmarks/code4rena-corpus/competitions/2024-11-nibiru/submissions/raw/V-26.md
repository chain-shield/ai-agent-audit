# Vulnerability details

## Finding description and impact
In the `GetTransactionCount()` function, a potential `integer overflow` issue exists due to the absence of a boundary check when converting a block number (`bn`) `int64`. While the `GetProof()` function implements a safeguard by checking if bn exceeds `math.MaxInt64` before casting, `GetTransactionCount()` directly casts bn to `int64` without this validation. 

This inconsistency could lead to `overflow`, resulting in erroneous or negative block heights, which may cause logic errors or unintended behavior.

## Proof of Concept
1. [`GetProof()`](https://github.com/code-423n4/2024-11-nibiru/blob/8ed91a036f664b421182e183f19f6cef1a4e28ea/eth/rpc/backend/account_info.go#L66-L77) function:
When retrieving the block number (`bn`), the function checks if `bn` exceeds `math.MaxInt64`. If it does, an `error` is returned, indicating that the block number is too large to safely convert to `int64`.
This check prevents `overflow` or truncation when casting bn to `int64`.
```go
    if height == 0 {
>>	bn, err := b.BlockNumber() // @audit-info block number retrieved
	if err != nil {
	    return nil, err
	}

>>	if bn > math.MaxInt64 { // @audit-info Overflow check
	    return nil, fmt.Errorf("not able to query block number greater than MaxInt64")
	}

>>	height = int64(bn) //#nosec G701 -- checked for int overflow already
    }
```

2. [`GetTransactionCount()`](https://github.com/code-423n4/2024-11-nibiru/blob/8ed91a036f664b421182e183f19f6cef1a4e28ea/eth/rpc/backend/account_info.go#L195-L201) function:
The `bn` block number is retrieved and directly cast to `int64` without any `overflow` check, even though the comment (`//#nosec G701 -- checked for int overflow already`) suggests that such a check has been performed.
```go
>>  bn, err := b.BlockNumber() // @audit-info block number retrieved
    if err != nil {
        return &n, err
    }
    // @audit-info No Overflow check (comment below isn't correct)
>>  currentHeight := int64(bn) //#nosec G701 -- checked for int overflow already
```
If `bn` is larger than `math.MaxInt64` and is cast directly to `int64`, it could wrap around and produce a `negative` or `incorrect` value. This could cause logic errors in comparisons or lead to `invalid block number` handling, potentially resulting in failures or unexpected behavior.

## Recommended mitigation steps
Ensure consistent `overflow` checks in both functions.
```diff
    bn, err := b.BlockNumber()
    if err != nil {
        return &n, err
    }
    // @audit Perform Overflow check
+   if bn > math.MaxInt64 {
+	return nil, fmt.Errorf("not able to query block number greater than MaxInt64")
+   }
    currentHeight := int64(bn) //#nosec G701 -- checked for int overflow already
```
