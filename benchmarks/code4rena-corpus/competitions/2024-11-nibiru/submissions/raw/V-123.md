# Vulnerability details

## Issue Description:

- The admin string and msgArgs byte array are not validated for length, potentially leading to oversized or malformed payloads.

- This oversight introduces potential vulnerabilities related to oversized or malformed input, which can have downstream effects.

The parseArgsWasmInstantiate function processes arguments for contract instantiation but lacks constraints on:

#1. admin: A string that should represent an optional administrator address. There is no check for:

- Maximum permissible length.

- Whether the string conforms to Bech32 encoding when provided.

#2. msgArgs: A byte array that represents the contract initialization message payload. There is no restriction on:

- The maximum allowable size of the byte array.

- The structure or format of its contents.

## Proof of Concept (PoC) #1:

    args := []any{"admin_address", uint64(1), make([]byte, 10000), "label", nil}
    _, err := parseArgsWasmInstantiate(args, "sender")
    fmt.Println(err) // Missing length validation for msgArgs.


## Proof of Concept (PoC) #2:

    // Oversized `msgArgs` (malicious payload)
    args := []any{
    "valid_admin_address", // admin
    uint64(1),             // codeID
    make([]byte, 50000),   // Oversized msgArgs (50 KB)
    "label",               // label
    nil,                   // funds
    } 

    _, err := parseArgsWasmInstantiate(args, "sender")
    fmt.Println(err) // No validation error raised for oversized msgArgs.



## Impact:

- Oversized or malformed data could exploit underlying components, consuming excessive resources.

- Contracts may be instantiated with invalid arguments.

#1. Performance Degradation:

Oversized msgArgs could lead to excessive resource consumption during processing.
Large payloads may negatively impact blockchain node memory and storage.

#2. Potential Exploitation:

If unchecked, a malicious user could craft payloads to exploit vulnerabilities in downstream components or cause denial of service (DoS).

#3. Invalid Deployments:

Without validation, invalid admin addresses or malformed initialization payloads might pass unnoticed, leading to contract misconfigurations or failures at runtime.

## Risk:

High - Malicious actors could exploit the lack of size restrictions to harm system performance.

The lack of validation introduces significant risks, especially in permissionless environments where users can submit arbitrary transaction data.

## Mitigation:

Enforce size limits and validate content:

    if len(msgArgs) > 1024 { // Arbitrary size limit
     return txMsg, fmt.Errorf("msgArgs exceeds maximum length: %d bytes", len(msgArgs))
    }  
    if len(admin) > 256 { // Arbitrary length for admin
    return txMsg, fmt.Errorf("admin address exceeds maximum length")
    }
