# Vulnerability details

## Issue Description

The smart contract backend contains several references to handling pruned nodes, such as fetching data from pruned blocks and failing gracefully when the block data is unavailable due to node pruning. Specifically, the issue arises in methods like RPCBlockFromTendermintBlock, EthBlockFromTendermintBlock, and others when attempting to fetch historical data that has been pruned.

## Bug Locations

#1. RPCBlockFromTendermintBlock:

- Error handling for BaseFeeWei fails when querying pruned blocks. The log output explicitly states, "failed to fetch Base Fee from prunned block".

#2. EthBlockFromTendermintBlock:

- Similar error occurs while attempting to retrieve BaseFeeWei. The error is logged but does not provide a fallback mechanism for constructing valid Ethereum blocks.

#3. BlockBloom:

- Relies on block results (EndBlockEvents) which may not be present in pruned blocks. The lack of a graceful fallback may lead to incomplete or malformed data.


## Impact
Severity: Medium

#### Functional Impact:

Missing data due to pruned nodes can result in incomplete Ethereum blocks being served by JSON-RPC APIs.

Applications relying on accurate historical data will fail or behave unpredictably.


#### Security Impact:

Although this issue primarily affects functionality, if malicious actors exploit reliance on missing or incomplete data, they could cause errors or denial of service in dependent applications.

## Proof of Concept

Set up a blockchain node with pruning enabled (e.g., cosmos-sdk or Ethereum node configured for pruning).

Query historical data beyond the pruning range using methods such as:

    res, err := backend.RPCBlockFromTendermintBlock(prunedBlock, ...)


## Mitigation and Recommendations

Updated error handling for BaseFeeWei in RPCBlockFromTendermintBlock:
  
    baseFeeWei, err := b.BaseFeeWei(blockRes)
    if err != nil {
    logger.Warn("BaseFeeWei missing, using default value due to pruning", "height", block.Height, 
    "error", err)
        baseFeeWei = big.NewInt(DefaultBaseFeeWei) // Fallback to a default value
    }


#1. Fallback Mechanism:

Use a default or estimated value for missing data such as BaseFeeWei in RPCBlockFromTendermintBlock and EthBlockFromTendermintBlock. For example:

    if err != nil {
      logger.Warn("BaseFeeWei missing, using default value", "height", block.Height)
      baseFeeWei = DefaultBaseFeeWei
    }


#2. Data Availability Check:

Before querying block results, add a check to ensure the requested block height is within the node's pruning range. Return a user-friendly error if the data is unavailable.

#3. Retry Logic or Archive Nodes:

For pruned blocks, allow integration with an archive node for fetching older data. This fallback should be configurable.

#4. Enhanced Logging and Metrics:

Clearly log whether the issue is due to pruning or another cause.
Introduce metrics to monitor the frequency of pruning-related errors.
