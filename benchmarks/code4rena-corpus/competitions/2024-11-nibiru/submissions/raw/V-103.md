# Vulnerability details

## Issue Description: 

The SetTxDefaults function relies on nonce fetching but does not explicitly validate the uniqueness of transactions. Without proper mechanisms, replay attacks might occur if old transactions are resubmitted.


## Proof of Concept:

In SetTxDefaults, the function fetches the account nonce without verifying the account's existence:
    
    nonce, _ := b.getAccountNonce(*args.From, true, 0, b.logger)
    args.Nonce = (*hexutil.Uint64)(&nonce)


Ignoring the error when the account doesn't exist could lead to incorrect nonce values or transaction failures.

## Impact

Transactions may be constructed with invalid nonces, causing them to fail or be replaced.
Could allow for replays or double-spending attacks if nonce management is abused.

Attackers could replay previously signed transactions, leading to double spending or resource depletion.

## Risk

High – Proper nonce handling is critical for Ethereum transactions.

## Mitigation

- Use a nonce validation mechanism and ensure transaction uniqueness before broadcasting.

Verify the account's existence before assigning the nonce:

    nonce, err := b.getAccountNonce(*args.From, true, 0, b.logger)
    if err != nil {
      return args, fmt.Errorf("failed to retrieve account nonce: %v", err)
    }
    args.Nonce = (*hexutil.Uint64)(&nonce)
