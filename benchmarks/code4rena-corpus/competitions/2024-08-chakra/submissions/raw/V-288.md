# Vulnerability details

It is mentioned in the contest page that "Only valid settlement handlers can process received cross-chain messages and callbacks."
There is a check in function `receive_cross_chain_callback` in settlement.cairo that satisfies this requirement for callbacks:
```
assert(self.created_tx.read(cross_chain_msg_id).from_handler == to_handler, 'from_handler error');
```
However, settlement.cairo does not include this check for received cross-chain messages.
Particularly, function `receive_cross_chain_msg` in settlement.cairo receives cross chain messages, and calls `receive_cross_chain_msg` function in handler contract:
```
// call handler receive_cross_chain_msg
            let handler = IHandlerDispatcher{contract_address: to_handler};
            let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

```
The handler contract address is specified in the to_handler parameter sent from the source chain. Therefore, it is essential to validate this address to ensure it corresponds to a valid settlement handler. However, function `receive_cross_chain_msg` in settlement.cairo lacks this check, and it calls any address sent from the source chain:

### An Example Attack Scenario:
As I reported in another issue titled "send_cross_chain_msg Function in ChakraSettlement.sol Should Only be Invoked by a Valid Handler", an attacker can call `send_cross_chain_msg` function in ChakraSettlement.sol directly. The attacker can create a malicious handler contract at the source chain and call `send_cross_chain_msg` via that handler. By doing so, from_handler value will be the address of malicious handler contract. The attacker can also create one malicious handler contract at the destination chain (Starknet), and passes its address as to_handler when calling `send_cross_chain_msg`. Then, a CrossChainMsg event will be emitted at the source chain. 
At the destination chain, function `receive_cross_chain_msg` in settlement.cairo will be called, which calls `receive_cross_chain_msg` function in Starknet malicious handler. This can be done since to_handler address is not checked in function `receive_cross_chain_msg` in settlement.cairo.
Consequently, the malicious handler returns true as the result, causing the status to be CrossChainMsgStatus::SUCCESS and emits CrossChainHandleResult event. 
Finally, at the source chain, function `receive_cross_chain_callback` in ChakraSettlement will be called. `receive_cross_chain_callback` calls processCrossChainCallback which calls `receive_cross_chain_callback` in the malicious handler contract in source chain. The malicious handler contract returns true, and create_cross_txs[txid].status will be set as CrossChainMsgStatus::SUCCESS, and cross chain messaging finishes. 
This example scenario shows how an attacker can exploit this bug to bypass handler contracts at both source and destination chains and reaches to a successful state.

## Recommended Mitigation Steps
Function `receive_cross_chain_msg` in settlement.cairo needs to check whether the parameter to_handler passed to it is a valid handler or not. This can be done by checking the existence of the to_handler address in a handler_whitelist.
