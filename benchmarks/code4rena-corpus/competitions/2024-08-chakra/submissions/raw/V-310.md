# Vulnerability details

## Impact
The absence of validation checks in the `set_required_validators_num` function can lead to setting an invalid number of required validators. This can cause operational issues such as setting the required validators to zero could allow transactions to be validated without any actual validation process or setting the required validators to a number greater than the total available validators (`validator_count`) could make it impossible to validate transactions because it will be impossible to gather enough signatures to meet the `required_validators` threshold , effectively halting operations.

## Proof of Concept
The ['set_required_validators_num']() function currently lacks checks for the validity of the new required validators number
```solidity
function set_required_validators_num( 
        uint256 _required_validators
    ) external onlyRole(MANAGER_ROLE) {
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement validation checks within the `set_required_validators_num` function to ensure the new required validators number is valid
```diff
function set_required_validators_num(uint256 _required_validators) external onlyRole(MANAGER_ROLE) {
+   require(_required_validators > 0, "Required validators must be greater than zero");
+   require(_required_validators <= validator_count, "Required validators must not exceed total validators");

    uint256 old = required_validators;
    required_validators = _required_validators;
    emit RequiredValidatorsChanged(msg.sender, old, required_validators);
}
```
