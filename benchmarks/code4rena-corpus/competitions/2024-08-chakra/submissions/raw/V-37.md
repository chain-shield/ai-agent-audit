# Vulnerability details

## Impact
When initiating a cross-chain ERC20 transfer, users' assets are transferred to the `ChakraSettlementHandler` contract and locked on the source chain:
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {

    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockUnlock) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockMint) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.BurnUnlock) {
        _erc20_burn(msg.sender, amount);
    }
    // --SNIP

    emit CrossChainLocked(
        txid,
        msg.sender,
        to,
        chain,
        to_chain,
        address(this),
        to_token,
        amount,
        mode
    );
}
```
The cross-chain message is then transferred to the `ChakraSettlement` contract on the destination chain for processing. There is a chance for the cross-chain message to fail on the destination chain if the source handler is unwhitelisted:

If the cross-chain message fails, the `ChakraSettlement::receive_cross_chain_callback` function on the source chain is triggered to finalize the message. However, the assets are not unlocked and not returned to the user who initiated the cross-chain message:
```solidity
function receive_cross_chain_callback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    CrossChainMsgStatus status,
    uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
    bytes calldata /* signatures */
) external onlySettlement returns (bool) {
    // --SNIP

    if (status == CrossChainMsgStatus.Failed) {
        // @audit The assets are not unlocked to the cross-chain message initiatiors
        create_cross_txs[txid].status = CrossChainTxStatus.Failed;
    }

    return true;
} 
```
As shown above, if the cross-chain message fails, the assets remain permanently locked on the source chain and are not returned to the users who initiated the transfer.
