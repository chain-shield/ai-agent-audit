# Vulnerability details

## Impact
The impact of this bug is that it allows managers to arbitrarily decrease the `validator_count` by removing non-existent validators. Unauthorized parties can remove validators, potentially compromising the integrity of the settlement process.

**The impact of this issue is twofold:**

1. The `validator_count` can be manipulated by managers, causing it to diverge from the actual number of active validators.
2. The inconsistency in the validator management system may lead to confusion and incorrect assumptions about the state of the validators.

While this does not directly lead to a loss of funds, it can cause discrepancies in the validator set and undermine the integrity of the settlement signature verification process.

## Proof of Concept
The root cause of this issue lies in the `remove_validator` function in the `SettlementSignatureVerifier` contract. The function allows a manager to remove a validator without checking if the validator exists.

In [SettlementSignatureVerifier.sol, the remove_validator](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/SettlementSignatureVerifier.sol#L83-L90) function is defined as follows:
```solidity
function remove_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == true, "Validator does not exists");
    validators[validator] = false;
    validator_count -= 1;
    emit ValidatorRemoved(msg.sender, validator);
}
```
The function only checks if the caller has the `MANAGER_ROLE` but does not properly ensure that the validator being removed actually exists in the `validators` mapping.

**Scenario illustrating the attack path**

1. An attacker obtains the `MANAGER_ROLE` through legitimate means or by exploiting a separate vulnerability.
2. The attacker calls the `remove_validator` function with a validator address that does not exist in the validators mapping.
3. The `remove_validator` function proceeds with the removal process since the caller has the `MANAGER_ROLE`.
4. The `validators` mapping is updated to set the non-existent validator's status to `false`.
5. The `validator_count` is decremented, even though no actual validator was removed.
6. The function emits a `ValidatorRemoved` event, falsely indicating that a validator was removed.

As a result, the `validator_count` becomes inconsistent with the actual number of active validators, and the `validators` mapping contains an entry for a non-existent validator.

## Recommended Mitigation Steps
The `remove_validator` function should be updated to include a check for the validator's existence before proceeding with the removal. 
```diff
function remove_validator(address validator) external onlyRole(MANAGER_ROLE) {
-   require(validators[validator] == true, "Validator does not exists");
+   require(validators[validator], "Validator does not exist");
    validators[validator] = false;
    validator_count -= 1;
    emit ValidatorRemoved(msg.sender, validator);
}
```
By updating the `require` statement to `require(validators[validator], "Validator does not exist")`, the function will only proceed with the removal if the validator exists in the `validators` mapping. This ensures that the `validator_count` remains consistent with the actual number of active validators and prevents the removal of non-existent validators.
