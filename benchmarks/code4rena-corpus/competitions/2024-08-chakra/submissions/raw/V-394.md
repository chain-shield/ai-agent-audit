# Vulnerability details

## Impact
The function `settlement/contracts/SettlementSignatureVerifier::verifyECDSA` is responsible for validating input signatures for the `ChakraSettlement::receive_cross_chain_msg` function. However, neither this function nor `SettlementSignatureVerifier::verify` properly checks for duplicate signatures. As a result, a single validator could submit their signature `required_validators` times, effectively bypassing the requirement for distinct validators' signatures needed to execute this function. Consequently, since this function calls `ChakraSettlementHandler::receive_cross_chain_msg`, it could result in the minting of a large amount of tokens ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L326)) or the unlocking of all tokens locked in the contract ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L332)).

[link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L174)

```javascript
    function verify(
        bytes32 msgHash,
        bytes calldata signatures,
        uint8 sign_type
    ) external view returns (bool) {
        if (sign_type == 0) {
            return verifyECDSA(msgHash, signatures);
        } else {
            return false;
        }
    }

    function verifyECDSA(                
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```

As shown in the code, there is no check for duplicate signatures. This allows a single signature to be repeated `required_validators` times and submitted as the input parameter for signatures.

## Recommended Mitigation Steps

Add validation to detect duplicate signatures:

```diff
SettlementSignatureVerifier::verifyECDSA

    uint256 len = signatures.length;
+   for (uint256 i = 0; i < len - 1; i += 65) {
+       for (uint j = i + 1; j < len; j += 65){
+           if(keccak256(signatures[i:i + 65]) == keccak256(signatures[j:j + 65])){
+               return false;           // or revert
+           }
+       }
+   }
    uint256 m = 0;
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
    }
```
