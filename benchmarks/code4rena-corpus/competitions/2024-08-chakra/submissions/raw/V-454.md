# Vulnerability details

## Impact
The lack of proper validation when adding or removing handlers from the whitelist can have several significant implications:

##### Unauthorized Access to Settlement Operations:
Malicious or erroneous handlers could be added to the whitelist, allowing unauthorized entities to handle critical settlement operations.
##### Financial Loss:
An attacker can potentially bypass security restrictions and perform unauthorized cross-chain settlement actions, potentially leading to unintended fund transfers.
##### System Integrity Risks:
Bypassing proper validation undermines the protocol's security model, allowing for unauthorized access to sensitive functions.

This vulnerability can cause disruption in the protocol’s normal settlement processes, leading to reputational damage and financial losses.



## Proof of Concept
The following PoC demonstrates how an attacker could exploit this issue:

1. A malicious owner (or attacker who gained owner privileges) calls the `add_handler` function, passing an arbitrary handler address to whitelist without validation:
```solidity
ChakraSettlementHandler.add_handler("InvalidChain", 123456); // Arbitrary handler
```
2. With the arbitrary handler whitelisted, the malicious actor can perform cross-chain settlements:
```solidity
ChakraSettlementHandler.cross_chain_erc20_settlement("InvalidChain", 123456, to_token, recipient, amount);
```
3. This unauthorized settlement could allow the attacker to transfer funds without proper validation, leading to significant losses.

Affected Functions:
`add_handler`
`remove_handler`

## Recommended Mitigation Steps

##### 1. Validate Handler Addresses: 
Before adding or removing handlers, ensure that the provided handler address is valid and legitimate.
example:
```solidity
function add_handler(string memory chain_name, uint256 handler) external onlyOwner {
    require(handler != address(0), "Invalid handler address");
    require(!is_valid_handler(chain_name, handler), "Handler already whitelisted");
    handler_whitelist[chain_name][handler] = true;
}
```
##### 2. Multi-Signature Approvals:
Require a multi-sig approval for adding or removing handlers to prevent any one entity from making dangerous changes to the whitelist.

##### 3. Periodically Review Whitelisted Handlers:
Conduct audits on the whitelisted handler addresses regularly to ensure no unauthorized handlers have been added.
