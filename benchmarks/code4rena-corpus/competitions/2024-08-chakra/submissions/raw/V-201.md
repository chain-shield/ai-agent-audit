# Vulnerability details

## Impact
The `SettlementSignatureVerifier` contract utilizes the UUPS (Universal Upgradeable Proxy Standard) pattern for its upgradeability. In this model, the `initialize` function is responsible for setting up the initial state of the contract and is expected to be called through the proxy by the contract owner. However, the `initialize` function in the `SettlementSignatureVerifier` contract is publicly accessible. This creates a security vulnerability where any external user can invoke the `initialize` function before the proxy owner has had the opportunity to do so. If this happens, it could result in the unauthorized setup of the contract, potentially assigning ownership or initializing sensitive contract parameters incorrectly.

## Tools Used
Manual Review

#### Recommendation
To mitigate this issue and ensure the security of the `SettlementSignatureVerifier` contract, it is crucial to protect the `initialize` function from unauthorized access. OpenZeppelin provides a robust solution through the `_disableInitializers()` function, which should be called in the constructor of the implementation contract.
