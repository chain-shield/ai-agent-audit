# Vulnerability details

## Impact
This vulnerability severely compromises the multi-signature security model of the contract. An attacker can bypass the required_validators threshold by duplicating a single valid signature, effectively reducing a multi-signature system to a single-signature system. This undermines the intended consensus mechanism and could lead to unauthorized actions or transactions being approved without the actual consent of the required number of unique validators.
This issue is present in both solidity and cairo contracts.

## Proof of Concept
Let's say, the required_validators is set to 5.
An attacker obtains a single valid signature from one validator.
The attacker constructs a signatures byte array containing this single signature repeated 5 times.
When passed to verifyECDSA, this array will be considered valid, as the function counts 5 valid signatures without checking for uniqueness.

```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
...
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
    }

    return false;
}
```
In this code, the loop increments m for each valid signature without checking if it's from a unique validator. Once m >= required_validators, it returns true, allowing the attack to succeed.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a mechanism to track which validators have already contributed a signature.
