# Vulnerability details

## Impact
If a cross_chain_erc20_settlement was initiated on ChainA but fails on Chain B, the tokens collected on ChainA cannot be claimed

## Proof of Concept
If for any reason, a CCTX fails on dest chain, there should be a refund mechanism to allow claiming of tokens that were collected on source chain.
But as we can see in both the cairo and solidity code, this functionality does not exist.
For example, if there is an error in transferring the tokens to the user due to insufficient balance of the handler contract on dest chain, the user will be unable to get his tokens back on source chain, and his funds will be unavailable indefinitely.
Even when Tx_status is Failed, users are not allowed to receive their tokens on source chain, so they remain locked.

## Tools Used
Manual Review

## Recommended Mitigation Steps

Create a function in the settlement/handler contracts that allows user to claim his tokens back on source chain in case of a failure in the dest chain(For example, when Tx_Status is "Failed", or there was an error in dest chain)
