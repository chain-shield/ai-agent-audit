# Vulnerability details


## Issue Description
In `check_chakra_signatures`, the `pass_count` variable is increased even if the signatures are not coming from different validators.
The extreme case being an array of signatures consisting of the same signature repeated $m$ times, resulting in having only one validator signature effectively checked.

```rust
    let mut pass_count = 0;
    let mut i = 0;
    loop {
        if i > signatures.len()-1{
            break;
        }
        let (r,s,y) = * signatures.at(i);
        let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
        if self.chakra_validators_pubkey.read(pub_key) > 0{
            pass_count += 1;
        }
        i += 1;
    };
    assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
```

## Impact
The protocol security is affected since only one malicious validator is sufficient to receive and invalid cross-chain message instead of `required_validators_num`.
Rendering the following assert inefficient:
```rust
    assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
```


## Proof of Concept
Reuse the same signature m times in `check_chakra_signatures`, renders the settlement public method `receive_cross_chain_msg` susceptible to an attack.

We are using the following minimal version of the settlement contract that exposes `check_chakra_signatures` for simplicity:

```rust
// file cairo/handler/src/mock_settlement.cairo
#[starknet::interface]
pub trait IMinimalSettlement<TContractState> {
    fn check_chakra_signatures(
        self: @TContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
    );
    fn set_required_validators_num(ref self: TContractState, new_num: u32) -> u32;
    fn add_validator(ref self: TContractState, new_validator: felt252) -> bool;
}

#[starknet::contract]
pub mod MinimalSettlement {
    use core::ecdsa::{recover_public_key};
    use core::hash::LegacyHash;
    use starknet::ContractAddress;
    use starknet::get_caller_address;


    #[storage]
    struct Storage {
        // storage the pubkeys as validator
        chakra_validators_pubkey: LegacyMap<felt252, u8>,
        // storage manager
        chakra_managers: LegacyMap<ContractAddress, u8>,
        // deployed chain name
        chain_name: felt252,
        // the number of verified signature
        required_validators_num: u32,
    }

    #[event]
    #[derive(Drop, starknet::Event)]
    enum Event {}

    #[constructor]
    fn constructor(ref self: ContractState, owner: ContractAddress, chain_name: felt252) {
        self.chakra_managers.write(owner, 1);
        self.chain_name.write(chain_name);
    }

    #[abi(embed_v0)]
    impl ChakraSettlementImpl of super::IMinimalSettlement<ContractState> {
        fn check_chakra_signatures(
            self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
        ) {
            let mut pass_count = 0;
            let mut i = 0;
            loop {
                if i > signatures.len() - 1 {
                    break;
                }
                let (r, s, y) = *signatures.at(i);
                let pub_key: felt252 = recover_public_key(message_hash, r, s, y).unwrap();
                if self.chakra_validators_pubkey.read(pub_key) > 0 {
                    pass_count += 1;
                }
                i += 1;
            };
            assert(
                pass_count >= self.required_validators_num.read(), 'Not enough validate signatures'
            );
        }

        fn set_required_validators_num(ref self: ContractState, new_num: u32) -> u32 {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            self.required_validators_num.write(new_num);
            return self.required_validators_num.read();
        }

        fn add_validator(ref self: ContractState, new_validator: felt252) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            assert(
                self.chakra_validators_pubkey.read(new_validator) == 0,
                'Caller is a validator already'
            );
            self.chakra_validators_pubkey.write(new_validator, 1);
            return self.chakra_validators_pubkey.read(new_validator) == 1;
        }
    }
}

```

## Recommended Mitigation Steps
Use a dictionary or mapping that stores validators addresses coming from signatures and make sure they haven't been used for the current tx.
