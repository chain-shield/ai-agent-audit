# Vulnerability details

## Vulnerability explanation
The `create_cross_txs` stores the information for each of the messages initiated in the specific handler. The data that it stores is the following:
```
struct CreatedCrossChainTx {
    uint256 txid;
    string from_chain;
    string to_chain;
    address from;
    uint256 to;
    address from_token;
    uint256 to_token;
    uint256 amount;
    CrossChainTxStatus status;
}
```
The implementation to fill each of these fields looks like this:
```
    function cross_chain_erc20_settlement(
        string memory to_chain,
        uint256 to_handler,
        uint256 to_token,
        uint256 to,
        uint256 amount
    ) external {
        ...

        // Create a new cross chain tx
        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    chain,
                    to_chain,
                    msg.sender, // from address for settlement to calculate txid
                    address(this), //  from handler for settlement to calculate txid
                    to_handler,
                    nonce_manager[msg.sender]
                )
            )
        );

        {
            // Save the cross chain tx
            create_cross_txs[txid] = CreatedCrossChainTx(
                txid,
                chain,
                to_chain,
                msg.sender,
                to,
                address(this),
                to_token,
                amount,
                CrossChainTxStatus.Pending
            );
        }

        ...
    }
```
Here we can see that all fields are set properly except from one, the `from_token`. This field is filled with `address(this)` which is wrong because the handler address is not the address of the token being bridged. It should be passed the address of the token from the handler storage. We can find this storage variable in the [BaseSettlementHandler](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/BaseSettlementHandler.sol#L70).

There is an other case where this issue happens and it is in the final event emitted by the handler. It is not as severe as storing wrong data onchain but is still an issue. The issue instance can be seen [here](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L218).

In the EVM implementation there is also an other wrong data in the settlement contract, in this case is in a field of the `receive_cross_txs` instances where it is supposed to save the address of the `to_handler` but it save the address of the settlement contract instead.
```
    function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
        {
        ...

        // struct ReceivedCrossChainTx {
        //     uint256 txid;
        //     string from_chain;
        //     string to_chain;
        //     uint256 from_address;
        //     uint256 from_handler;
        //     address to_handler;
        //     bytes payload;
        //     CrossChainMsgStatus status;
        // }
        receive_cross_txs[txid] = ReceivedCrossChainTx(
            txid,
            from_chain,
            contract_chain_name,
            from_address,
            from_handler,
            address(this),      // @audit this should be to_handler. Address(this) is the address of the settlement contract
            payload,
            CrossChainMsgStatus.Pending
        );

        ...
    }
```

There are more wrong data in Cairo's implementation. The handler's function to initiate a message has 2 of them:
```
        fn cross_chain_erc20_settlement(ref self: ContractState, to_chain: felt252, to_handler: u256, to_token: u256, to: u256, amount: u256) -> felt252{
            ...
            
            let tx_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.msg_count.read());
            let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
                    from_chain: from_chain,
                    to_chain: to_chain,
                    from: get_contract_address(),           // @audit this should be get_caller_address()
                    to: to,
                    from_token: self.token_address.read(),
                    to_token: to_token,
                    amount: amount,
                    tx_status: CrossChainTxStatus::PENDING
                };

            ...

            self.emit(
                    CrossChainLocked{
                        tx_id: tx_id,
                        from: get_caller_address(),
                        to: to,
                        from_chain: get_tx_info().unbox().chain_id,     // @audit it should be settlement.chain_name()
                        to_chain: to_chain,
                        from_token: self.token_address.read(),
                        to_token: to_token,
                        amount: amount
                    }

            return tx_id;
        }
```
