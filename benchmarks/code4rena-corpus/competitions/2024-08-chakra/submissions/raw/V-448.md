# Vulnerability details

## Impact
The ChakraSettlement and ChakraSettlementHandler contracts lack a critical pause functionality, which could allow continuous exploitation of the system even after a vulnerability is detected. This absence of an emergency stop mechanism is particularly concerning in cross-chain bridge systems where rapid response to security threats is crucial.
Without a pause function, if a vulnerability is discovered in the system (e.g., a compromised handler, a flawed signature verification, or an exploit in fund transfer logic), the contract would continue to operate. This could allow attackers to drain funds or manipulate the system continuously potentially resulting in significant financial losses and damage to the system's integrity.

This issue is present in both solidity and cairo code.

## Proof of Concept
The contracts do not implement any form of pause functionality that could halt operations in case of detected anomalies or attacks.
Critical functions like receive_cross_chain_msg can continue to execute even if malicious activity is detected:
```solidity
function receive_cross_chain_msg(
    uint256 txid,
    string memory from_chain,
    uint256 from_address,
    uint256 from_handler,
    address to_handler,
    PayloadType payload_type,
    bytes calldata payload,
    uint8 sign_type,
    bytes calldata signatures
) external {
    // Function continues to execute with no ability to pause
```
There are no apparent emergency controls that could quickly halt or limit system operations in case of a security breach.
