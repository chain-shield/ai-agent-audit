# Vulnerability details

## Vulnerability explanation
In the Solidity implementation of the settlement contract, there is an owner that has the default admin role who has the control to add and remove managers. These managers have the role of adding/removing validator signatures and the minimum threshold required for a valid call.
However, in Cairo there is an owner and there are managers, managers are the only ones that can add and remove other managers or himself. Hence, the owner has no power over this role. Let's see how the removal of a manager works:
```
        fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            self.chakra_managers.write(old_manager, 0);
            self
                .emit(
                    ManagerRemoved {
                        operator: caller,
                        old_manager: old_manager,
                        removed_at: get_block_timestamp()
                    }
                );
            return self.chakra_managers.read(old_manager) == 0;
        }
```
We can see that there is no protection for a manager from removing himself. Hence, there is a state where there are no managers registered and nobody else can add more because the only ones that have that power are managers and there are none.

## Impact
Medium, if this state is reached, there will be no way to register new managers and there will no be possible to add or remove new validator public keys nor set a minimum of signatures for a call to be accepted. It has high impact but low likelihood.
Talking to the sponsor stated that this state would be really bad but he thought that there is always possible for the owner to register new managers. This is true for the Solidity implementation but false for the Cairo one.

## Tools Used
Manual review

## Recommended Mitigation Steps
I would follow the same pattern as the Solidity implementation, enable the owner to add and remove manager roles.
