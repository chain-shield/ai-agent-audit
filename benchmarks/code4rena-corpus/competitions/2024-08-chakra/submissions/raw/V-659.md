# Vulnerability details

The `processCrossChainCallback` function in the ChakraSettlement contract is responsible for managing cross-chain transaction callbacks by updating the transaction status based on the result of a callback to an external handler contract. However, the function lacks proper validation of the transaction's status and is vulnerable to replay attacks. This vulnerability allows malicious actors to manipulate transaction status and perform unauthorized operations multiple times.



Impact : In the `receive_cross_chain_callback` function of the handler contract we can perform operations like minting and transfering depending upon the mode set in the time of initialization, with this vulnerability we can perform that action many times

## Findings
The function `processCrossChainCallback()` is called internally by `receive_cross_chain_callback()` and accepts several parameters, including CrossChainMsgStatus status. This status is passed directly to processCrossChainCallback().

The vulnerability arises in how the transaction's status is updated:

Lack of Proper Status Validation: After the external handler is called, if the handler call returns true, the contract directly updates the transaction status based on the arbitrary status value provided in the callback. There are no safeguards in place to ensure that this externally supplied status accurately reflects the transaction outcome, potentially allowing malicious actors to manipulate the status.

Replay Attack Vector: Since the only requirement is that the transaction's current status must be Pending, it is possible to replay the callback multiple times. Each replay could potentially update the transaction status to any arbitrary value supplied by the attacker.

Steps to Reproduce:
Initiate a cross-chain transaction.
Call the receive_cross_chain_callback() function with a payload, providing an arbitrary status pending in this case.
Observe that the processCrossChainCallback() function updates the transaction status based on the attacker-supplied value. (The status will be always pending)
Replay the callback and observe the status being updated again, despite the transaction having already been processed.

Recommendation 
```solidity
function processCrossChainCallback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    address to_handler,
    uint8 sign_type,
    bytes calldata signatures
) internal {
    require(
        create_cross_txs[txid].status == CrossChainMsgStatus.Pending,
        "Invalid transaction status"
    );

    // Call the external handler and determine result
    bool result = ISettlementHandler(to_handler).receive_cross_chain_callback(
        txid,
        from_chain,
        from_handler,
        CrossChainMsgStatus.Pending, // Only allow Pending as input status
        sign_type,
        signatures
    );

    // Update status based on the result of the external handler call
    if (result) {
        create_cross_txs[txid].status = CrossChainMsgStatus.Success;
    } else {
        create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
    }
}

```
