# Vulnerability details

The `settlement.cairo::check_chakra_signatures()` function is designed to verify the validity of signatures. However, as shown in the highlighted code sections, there is a critical oversight. The `recover_public_key()` function is used to retrieve the `pub_key` associated with each signature, and the subsequent validation checks if this pub_key exists in the `chakra_validators_pubkey` mapping. If found, the `pass_count` is incremented. However, there is no mechanism to ensure the uniqueness of each `pub_key`. This means that an attacker with a single valid signature can reuse it multiple times within the same verification process to meet the `required_validators_num` threshold, regardless of how many unique signatures are actually required.

## Impact
The absence of a signature uniqueness check in the `settlement.cairo::check_chakra_signatures()` function allows an attacker to bypass the `required_validators_num` threshold by reusing a single valid signature multiple times. This significantly weakens the security of the cross-chain message validation process, leading to potential unauthorized asset transfers, message forgery, and system compromise.

## Recommended Mitigation Steps
To prevent signature reuse, introduce a mechanism to track and ensure the uniqueness of each pub_key during the validation process. The following pseudo-code demonstrates a possible solution:

```diff

            self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
        ){

                    break;
                }

                let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();

+                if !used_pub_keys.contains(pub_key) && self.chakra_validators_pubkey.read(pub_key) > 0 {

+                    used_pub_keys.insert(pub_key);  // Record this pub_key as used
                }

        }
```
