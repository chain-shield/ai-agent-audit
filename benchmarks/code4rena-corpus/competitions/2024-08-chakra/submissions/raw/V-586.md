# Vulnerability details

## Impact
The `cross_chain_erc20_settlement` function handles different `SettlementMode` operations (`MintBurn`, `LockUnlock`, `LockMint`, `BurnUnlock`). However, there is no fallback or `revert` statement in case the provided `mode` does not match any of these valid options.  The user will create new cross chain tx and Create a erc20 transfer payload without LockUnlock, LockUnlock, MintBurn or BurnUnlock.

## Recommended Mitigation Steps
Need one `else` statement to revert the whole function if SettlementMode is not LockUnlock, LockUnlock, MintBurn or BurnUnlock.
```solidity
	if (mode == SettlementMode.MintBurn) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.BurnUnlock) {
            _erc20_burn(msg.sender, amount);
        }
	+   else {revert("Unsupported mode!")}
        
```
