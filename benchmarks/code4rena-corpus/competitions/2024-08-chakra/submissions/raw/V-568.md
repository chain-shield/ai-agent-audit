# Vulnerability details

## Vulnerability details

The `receive_cross_chain_msg` function in the `ChakraSettlement` contract processes cross-chain messages without ensuring that they are executed in the order they were sent. This can lead to potential transaction failures due to dependencies between messages.

## Impact

The lack of enforced message ordering can result in unexpected behavior or failures in dependent transactions. For example, if a later message depends on the successful processing of an earlier message, processing them out of order can cause the later message to fail, leading to potential loss of funds or incorrect state.

## Recommended Mitigation Steps

To ensure that cross-chain messages are processed in the order they were sent, implement a mechanism to track and enforce the order of message processing. This can be achieved by maintaining a sequence number for each message and ensuring that messages are processed in the correct sequence.

1. Introduce a sequence number for each cross-chain message.
2. Maintain a mapping of the last processed sequence number for each sender.
3. Ensure that each incoming message has a sequence number greater than the last processed sequence number for the sender.
4. Process messages in the order of their sequence numbers.

By implementing these steps, you can ensure that cross-chain messages are processed in the correct order, preventing potential transaction failures due to dependencies between messages.
