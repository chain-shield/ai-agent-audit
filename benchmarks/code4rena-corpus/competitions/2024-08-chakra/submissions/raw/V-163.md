# Vulnerability details

## Impact

The current version of `ChakraSettlement` smart contract uses `chainId` that's set when initializing the contract. The problem with this is that the chain on which the contract is deployed may hard fork and there will be two chains in parallel with the same chainId. This can lead to a signature replay attack as the tx can be executed on both chains.

## Proof of Concept

Chakra Network provides signatures when calling `receive_cross_chain_callback()` and `receive_cross_chain_msg()`:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L262-263
```
 uint8 sign_type,
 bytes calldata signatures

```

These signatures can be potentially reused by other users as anybody can call these functions on the parallel chains due to hard fork happened. Therefore, some undesired scenario may be created when there are too much tokens burnt on the source chain, for example.


## Tools Used

Grok

## Recommended Mitigation Steps

Include chainId opcode in the signature schema.
