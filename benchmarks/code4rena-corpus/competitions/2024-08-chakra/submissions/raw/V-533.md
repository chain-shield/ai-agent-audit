# Vulnerability details

## Vulnerability explanation
Each chain is meant to be identified with a string. However, in the solidity implementation to initiate a message bridge there is no check for this `to_chain`. It may lead to several problems. What if the user provides a string for the `to_chain` parameter that does not belong to any registered chain? The execution will still be successful and the user will have transfered his funds to the handler but the validators will not execute anything because the string provided does not belong to any existing chain. In the case of the Cairo implementation, this issue is not possible because it has a check that requires the `to_handler` on the `to_chain` to be registered, otherwise it will not allow the execution to go through and no funds will be transfered from the user.
```
        fn cross_chain_erc20_settlement(ref self: ContractState, to_chain: felt252, to_handler: u256, to_token: u256, to: u256, amount: u256) -> felt252{
            assert(self.support_handler.read((to_chain, to_handler)), 'not support handler');
            ...
        }
```
However in the solidity implementation, any arbitrary string can be passed and the transaction will go through.

There is an other issue with the data type used for identifying chains. The fact that strings in solidity can have any length can collide with Cairo because it stores them as felt252 which can only have 31 bytes/characters. That means that if solidity string exceeds the 31 bytes will not be possible to be passed into the Cairo implementation.

## Impact
If a user initiates a message bridge with a wrong `to_chain` will lose his funds in the handler

## Recommended Mitigation Steps
Add the same check for the handler on the destination chain just as Cairo does:
```diff
function cross_chain_erc20_settlement(
        string memory to_chain,
        uint256 to_handler,
        uint256 to_token,
        uint256 to,
        uint256 amount
    ) external {

++      if (is_valid_handler(to_chain, to_handler) == false) {
++          revert();
++      }

        require(amount > 0, "Amount must be greater than 0");
        require(to != 0, "Invalid to address");
        require(to_handler != 0, "Invalid to handler address");
        require(to_token != 0, "Invalid to token address");

        ...
    }
```
