# Vulnerability details

The `ChakraSettlementHandler` contract is responsible for handling cross-chain ERC20 settlements. The contract inherits from `BaseSettlementHandler` and implements the `ISettlementHandler` interface.

The logic where the issue lies is within the `cross_chain_erc20_settlement` function. When creating a new cross-chain transaction, the function incorrectly stores the `to_token` value in the `to_handler` field of the `CreatedCrossChainTx` struct: [ChakraSettlementHandler.sol#L154-L165](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L153-L165)
```solidity
create_cross_txs[txid] = CreatedCrossChainTx(
    txid,
    chain,
    to_chain,
    msg.sender,
    to,
    address(this),
    to_token, // Bug: should be to_handler
    amount,
    CrossChainTxStatus.Pending
);
```
The issue's root is the incorrect assignment of the `to_token` value to the `to_handler` field when storing the transaction details in the `create_cross_txs` mapping.

When a user initiates a cross-chain ERC20 settlement using the `cross_chain_erc20_settlement` function. Due to the incorrect storage of the `to_handler` value, the settlement process may fail or result in incorrect token transfers. This could lead to potential loss of funds for users participating in cross-chain settlements.

When the settlement handler attempts to process the cross-chain transaction and retrieve the transaction details using the `create_cross_txs` mapping, it will receive the incorrect `to_handler` value, leading to a mismatch between the expected and actual values. This mismatch can cause the settlement process to fail or transfer tokens to an unintended recipient.

> [!Consider this scenario]
> 1. A user calls the `cross_chain_erc20_settlement` function to initiate a cross-chain ERC20 settlement, providing the destination chain, handler, token, recipient address, and amount.
> 2. Inside the `cross_chain_erc20_settlement` function, the transaction details are stored in the `create_cross_txs` mapping. However, due to the bug, the to_token value is incorrectly stored as `to_handler`.
> 3. Later, when retrieving the transaction details using the `create_cross_txs` function, the incorrect to_handler value is returned, leading to a mismatch between the expected and actual values.
> 4. This mismatch can cause incorrect token transfers and potentially result in loss of funds for users participating in cross-chain settlements.

## Recommended Mitigation Steps
Update the line in ChakraSettlementHandler.sol where the transaction details are stored in the `create_cross_txs` mapping
```diff
- to_token, // Bug: should be to_handler
+ to_handler, // Fix: use to_handler
```
By using `to_handler` instead of `to_token`, the correct handler address will be stored and retrieved, ensuring proper functionality of the cross-chain settlement process.
