# Vulnerability details

## Impact

The remove_manager() method does not have a minimum number of managers, which may cause all managers to be deleted.

In the `ckrBTC` smart contract, there is a potential security risk in the `remove_manager` function. This function allows any existing manager to remove other managers but lacks an explicit check to ensure that at least one manager remains. If all managers are removed, the contract loses control over manager-specific operations, such as adding an operator (`add_operator`), which may eventually cause the contract to become non-functional.

If no managers remain, the following issues may occur:

- Unable to add new operators due to the unavailability of `add_operator`.
- Unable to remove operators due to the unavailability of `remove_operator`.
- All manager-exclusive operations will be blocked, limiting the contract's functionality.

This vulnerability could result in the contract losing managerial control and halting further functional operations.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/ckr_btc.cairo#L148

The vulnerability lies in the `remove_manager` function. Below is the relevant code snippet:

```
fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
    self.chakra_managers.write(old_manager, 0);
    self
        .emit(
            ManagerRemoved {
                operator: caller,
                old_manager: old_manager,
                removed_at: get_block_timestamp()
            }
        );
    return self.chakra_managers.read(old_manager) == 0;
}
```

In this code snippet, there is no check to ensure that at least one manager remains. Therefore, when the last manager is removed, the system will have no way to add new managers or execute manager-specific operations.

## Recommended Mitigation Steps

Add a check before removing a manager to ensure that at least one manager remains. For example, the following check can be added to the `remove_manager` function:

```

fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
    
    // Ensure there is at least one manager remaining
    let remaining_managers = self.chakra_managers.keys().filter(|k| self.chakra_managers.read(*k) == 1).count();
    assert(remaining_managers > 1, "At least one manager must remain");

    self.chakra_managers.write(old_manager, 0);
    self
        .emit(
            ManagerRemoved {
                operator: caller,
                old_manager: old_manager,
                removed_at: get_block_timestamp()
            }
        );
    return self.chakra_managers.read(old_manager) == 0;
}
```

This ensures that there is always at least one manager left in the system, preventing the contract from becoming inoperable due to the absence of managers.
