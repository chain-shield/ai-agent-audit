# Vulnerability details

It is mentioned in the contest page that "Only valid settlement handlers can process received cross-chain messages and callbacks". Thus, it is required for both functions `receive_cross_chain_msg` and `receive_cross_chain_callback` in settlement contracts to include validation for to_handler address parameter.
In another issue titled "Invalid settlement handlers can process received cross-chain messages in settlement.cairo", I reported that while the `receive_cross_chain_callback` function in settlement.cairo includes that validation, the `receive_cross_chain_msg` function does not. However, in ChakraSettlement.sol, both functions `receive_cross_chain_msg` and `receive_cross_chain_callback` lack such validation. Consequently, an attacker can specify arbitrary addresses for handling received cross-chain messages and callbacks:
```
...
bool result = ISettlementHandler(to_handler).receive_cross_chain_msg(
            txid,
            from_chain,
            from_address,
            from_handler,
            payload_type,
            payload,
            sign_type,
            signatures
        );

        CrossChainMsgStatus status = CrossChainMsgStatus.Failed;
        if (result == true) {
            status = CrossChainMsgStatus.Success;
            receive_cross_txs[txid].status = CrossChainMsgStatus.Success;
        } else {
            receive_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
...
```
```
...
if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
...
```
As it is shown in the code above, it is possible for the attackers to send transactions to malicious handlers and returns true as the result of handling.
### An Example Attack Scenario:
A reverse attack scenario (initiated from Starknet) similar to the one that I mentioned in issue "Invalid settlement handlers can process received cross-chain messages in settlement.cairo" can be performed here.

## Recommended Mitigation Steps
Function `receive_cross_chain_msg` and `receive_cross_chain_callback` in ChakraSettlement.sol need to check whether the parameter to_handler passed to them is a valid handler or not. 
For function `receive_cross_chain_callback`, this can be done by adding the following check to the beginning of the function:
```
require(create_cross_txs[txid].from_handler == to_handler, 'handler error');
```
For function `receive_cross_chain_msg`, this can be done by checking the existence of the to_handler address in a handler_whitelist.
