# Vulnerability details

## Description
One of the main invariant of Settlement Handler contract as stated on the C4 page is this;
“The handler receiving a cross-chain message must be on the whitelist for the source code”
For the Settlement contract, the invariant also said, **“Only valid settlement handlers can process received cross-chain messages and callbacks”.** 

In chakraSettlementHandler.sol, the function **receive_cross_chain_msg** is meant to do this check but instead it checks if the source handler is on the whitelist with this code:
```solidity
if (is_valid_handler(from_chain, from_handler) == false) {
return false;
```

The from_handler is the source handler and not the destination handler which is the handler receiving a cross-chain message.
Therefore, it fails to check if the destination handler is on the whitelist for the source chain. Hence breaking one of the main invariant of settlement Handler Contract. This would allow any handler that is not on the whitelist for the source chain to be able to receive a cross chain message. This can be exploited by an attacker to create further severe havoc.

Another instance of this is in the function **receive_cross_chain_callback.**
```solidity
if (is_valid_handler(from_chain, from_handler) == false) {
return false;
```
## Impact
Breaks one of the main invariant of Settlement Handler contract and can also allow a malicious destination handler to receive cross chain message. This can lead to severe havoc.

## Recommended Mitigation Steps
The functions **receive_cross_chain_msg** and **receive_cross_chain_callback** should be made to validate the destination handler.

Here’s a code implementing this
```solidity
function receive_cross_chain_msg(
        uint256 /**txid */,
        string memory from_chain,
        uint256 /**from_address */,
        uint256 from_handler, // Updated to reflect receiving handler
        uint256 to_handler
        PayloadType payload_type,
        bytes calldata payload,
        uint8 /**sign type */,
        bytes calldata /**signatures */
    ) external onlySettlement returns (bool) {
        // Ensure that to_handler is in the whitelist for the receiving chain
        if (is_valid_handler(from_chain, to_handler) == false) {
            return false;
        }
        
```
       
I also believe it would be better and more secure to implement a codebase that checks whether both the destination handler and the source handler are on the whitelist of the source chain.
The code I provided only checks that the handler receiving the cross chain message is on the whitelist of the source chain which is one of the main invariants of the Settlement Handler Contract.
