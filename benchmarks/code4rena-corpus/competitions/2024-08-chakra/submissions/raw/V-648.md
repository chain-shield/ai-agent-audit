# Vulnerability details

## Impact

The sender cannot get back the tokens that will be sent if the cross chain message `FAILED`

## Proof of Concept

The schema will be :

1. User call `cross_chain_erc20_settlement()` function in destination chain, on handler part

In this function, `ERC20` tokens will be sent to handler contract from `msg.sender` or burned if the selected mode is `BurnUnlock`

```solidity
if (mode == SettlementMode.MintBurn) {
            _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockMint) {
            _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.BurnUnlock) {
            _erc20_burn(msg.sender, amount);
}
```

2. Then forwarded to `send_cross_chain_msg()` function in destination chain, on settlement part
3. Fast forward, the cross chain messaging fail and the status `CrossChainMsgStatus` become `FAILED`. If we look at the `receive_cross_chain_callback` in settlement part--> `receive_cross_chain_callback` in handler part, there is no way for the sender to receive back a token which will be sent.

`receive_cross_chain_callback` in settlement

```solidity
function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) external {
        verifySignature(
            txid,
            from_handler,
            to_handler,
            status,
            sign_type,
            signatures
        );
        processCrossChainCallback(
            txid,
            from_chain,
            from_handler,
            to_handler,
            status,
            sign_type,
            signatures
        );
        emitCrossChainResult(txid);
    }
```

`receive_cross_chain_callback` in handler

```solidity
function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        CrossChainMsgStatus status,
        uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
        bytes calldata /* signatures */
    ) external onlySettlement returns (bool) {
        //  from_handler need in whitelist
        if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
        }

        require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending,
            "invalid CrossChainTxStatus"
        );

        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }

        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }

        return true;
    }
```

4. And also in the `ChakraSettlementHandler` contract there is no function to retrieve token which failed to sent.
