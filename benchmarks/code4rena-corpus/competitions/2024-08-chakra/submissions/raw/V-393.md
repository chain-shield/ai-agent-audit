# Vulnerability details

## Impact
In `ckr_btc.cairo::remove_manager` , there ought to be a check to prevent self removal. The attacker could lure the `old_manager` to remove themselves, especially if `old_manager` is their own address. Unknowingly calling this function, the manager could lose their priviledges.The malicious user can send a contaminated phrase|address to these managers, making them to remove themselves and lose their priviledges, while they consolidate a numerical advantage.  

## Proof of Concept
This is the function which lacks the check for `old_manager` self removal. 
```javascript
   fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
            self.chakra_managers.write(old_manager, 0);
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Add an assert to check and prevent old_manager from removing themselves.

```javascript
   fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
        @>  assert(caller != old_manager, Errors::CANNOT_REMOVE_SELF);
            self.chakra_managers.write(old_manager, 0);
```
The addition would ensure that the caller is by no way an `old_manager`.
