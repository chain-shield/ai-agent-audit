# Vulnerability details

## Impact
An attacker can essentially game the system but obtaining a more valuable to_token on the other side of the chain. This will lead to a loss for the protocol and a gain for the attacker.


## Proof of Concept

We also need to understand how amount works:
The amount is determined by the caller of the cross_chain_erc20_settlement function in the Solidity chain or Starknet. For this example we will be using Ethereum but this applies to all chains mentioned in the docs.



The caller must ensure that the amount is appropriate for the specific ERC20 token being used, considering its decimal places.

When the cross-chain message is created, the amount is included in the payload. This payload is then decoded in the Cairo function, where the amount is extracted and used for minting or transferring tokens.

This amount is the amount that is burned or locked when the modes are called. This amount refers to the token that is locked or burned (which  is defined in the BaseSettlementHandler contract with the following line

The specific ERC20 token being used is determined by the address assigned to the token variable during the contract's initialization.


The to_token parameter is intended to specify the token that will be received on the destination chain. This means that it can refer to a different ERC20 token than the one being locked in the current contract.



My assumption is that this design allows for flexibility in cross-chain transactions, where a user can lock one type of token (e.g., Token A) and expect to receive a different type of token (e.g. Token B) on the destination chain.


However, this means an attacker can receive a more valuable token in Starknet


POC example 1 (LockUnlock):


Setup:
Chain A (Ethereum): The attacker has some funds and will transfer a certain amount of Token A into the contract (locking it)
Chain B (Starknet): The attacker wants to receive a more valuable token that is available on Starknet.

Tokens Involved:
Token A: A less valuable ERC20 token on Ethereum (e.g. 1USDC).This is the token that is passed in in the initialize function 
Token B: A more valuable ERC20 token on Starknet (worth $10 USDC)


Steps of the Attack 
1. Preparation:
The attacker acquires a significant amount of Token A on Ethereum. For example they get $100 USDC worth of token A, which means the attacker sets the amount as 100.

2. Locking Tokens:
The attacker calls the cross_chain_erc20_settlement function on the Ethereum contract, specifying the following:
to_chain: "Starknet"
to_handler: The address of the handler on Starknet that will process the incoming message.
to_token: The address of Token B on Starknet.
to: The address where they want to receive Token B.
amount: The amount of Token A they want to lock (e.g., 100 Token A).
The contract locks the 100 Token A by calling the _erc20_lock function, which transfers the tokens from the attacker's address to the contract.


3. Sending the Cross-Chain Message:
The contract sends the cross-chain message to the Starknet handler, indicating that the attacker has locked Token A and expects to receive Token B.

4. Receiving on Starknet:
The Starknet handler processes the incoming message. Since the contract does not validate that the token being received corresponds to the token being locked, it allows the attacker to receive Token B.
The attacker receives 100 Token B (the same amount of Token A that was locked) on Starknet, which is worth $10 each, totaling $1,000.

Profit:
The attacker has effectively exchanged 100 Token A (worth $100) for 100 token B ($1000) without any loss, but they have now gained access to a more valuable token.


This works in the other modes as well where an attacker can lock a less valuable token and mint a more valuable one, or burn a less valuable token and unlock a more valuable one.
