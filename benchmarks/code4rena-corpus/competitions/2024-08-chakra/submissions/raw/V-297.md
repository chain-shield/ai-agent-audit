# Vulnerability details

## Impact
The protocol enforces several invariants to prevent the initiation of cross-chain ERC20 messages with invalid parameters, including transactions with an amount of 0. As outlined in the README:
> Cross-chain ERC20 settlements can only be initiated **with a valid amount (greater than 0)**, a valid recipient address, a valid handler address, and a valid token address.

This constraint ensures that cross-chain transactions cannot be initiated with invalid values, which would otherwise spam the network and unnecessarily burden validators. While these checks are properly enforced in the Solidity contracts, they are missing in the corresponding Cairo contracts. Specifically, the `erc20_handler::cross_chain_erc20_settlement` function lacks validation for the transaction amount, recipient address, and token address:

```rs
fn cross_chain_erc20_settlement(ref self: ContractState, to_chain: felt252, to_handler: u256, to_token: u256, to: u256, amount: u256) -> felt252 {
    assert(self.support_handler.read((to_chain, to_handler)), "not support handler");
    // @audit no check for amount, to, to_token
    let settlement = IChakraSettlementDispatcher {contract_address: self.settlement_address.read()};
    let from_chain = settlement.chain_name();
    let token = IERC20Dispatcher{contract_address: self.token_address.read()};
    let token_burnable = IERC20MintDispatcher{contract_address: self.token_address.read()};
    if self.mode.read() == SettlementMode::MintBurn{
        token.transfer_from(get_caller_address(), get_contract_address(), amount);
    }else if self.mode.read() == SettlementMode::LockMint{
        token.transfer_from(get_caller_address(), get_contract_address(), amount);
    }else if self.mode.read() == SettlementMode::BurnUnlock{
        token_burnable.burn_from(get_caller_address(), amount);
    }else if self.mode.read() == SettlementMode::LockUnlock{
        token.transfer_from(get_caller_address(), get_contract_address(), amount);
    }
    // --SNIP
}
```
This omission allows malicious actors to send cross-chain ERC20 messages with invalid or zero amounts, which do not result in any token transfers (burn/lock), effectively spamming the Chakra network. This unchecked behavior can overload validators with large volumes of invalid cross-chain messages, degrading the network's performance.

## Recommended Mitigation Steps
Consider implementing the necessary checks on cross-chain message values in cairo contract in `handler_erc20::cross_chain_erc20_settlement`:
```diff

    assert(self.support_handler.read((to_chain, to_handler)), "not support handler");
+   assert(amount > 0, 'Amount must be greater than zero');
+   assert(to != 0, 'Invalid to address');
+   assert(to_token != 0, 'invalid token address');
```
