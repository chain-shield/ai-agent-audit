# Vulnerability details

## Summary

**Context:**

Here is the execution path when a cross-chain ERC20 transfer call occurs:

Source chain:
[cross_chain_erc20_settlement()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L111) => [send_cross_chain_msg()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L111)

Destination chain:
[receive_cross_chain_msg()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L170) => [receive_cross_chain_msg()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L300)

Source chain:
[receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L256) => [receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L365)

**Issue:**
The issue exists in [receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L365) function in the ChakraSettlementHandler.sol contract. If a call fails on the destination chain (in case the `from_handler` and `from_chain` is removed as a valid handler on the destination chain before the user's transaction takes place), the tokens locked/burned on the source chain are not minted back to the user. 

**Impact:**
Due to this, since a FAILED message is not retriable on the source chain, the tokens on the user are permanently locked in the ChakraSettlementHandler.sol contract on the source chain.

## Proof of Concept

1. User calls cross_chain_erc20_settlement on the source chain handler contract, which calls the send_cross_chain_msg() function on the ChakraSettlement.sol contract.

2. Let's say the `from_chain` and `from_handler` are removed on the destination chain.

3. When the receive_cross_chain_msg() function is called on the destination chain, it checks if the source sending the message is a valid handler. Since it is not, it returns false to receive_cross_chain_msg() on the ChakraSettlement.sol contract and marks the transaction as FAILED.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider allowing users to retrieve their source chain tokens when calls on the destination chain fails. This can be done by the checking for the FAILED status set by the callback on the source chain.
