# Vulnerability details

## Impact
User sends message to another chain via ChakraSettlementHandler.cross_chain_erc20_settlement() with tokens. User may lose these tokens due to message processing error in another chain.

## Proof of Concept
1. The user sends a message to another chain via ChakraSettlementHandler.cross_chain_erc20_settlement() with tokens.
2. The message arrives at the receive_cross_chain_msg() function.
3. The function fails to meet the condition:
https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L311-L313
if (is_valid_handler(from_chain, from_handler) == false) {
return false;
}
or
https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L316
require(isValidPayloadType(payload_type), "Invalid payload type");
4. The user does not receive tokens in another chain and loses them.

## Tools Used
Manual review

## Recommended Mitigation Steps
It is necessary to provide the ability to return a transaction in the event of an error in the receiving chain.
