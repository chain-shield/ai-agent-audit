# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: TokenRoles contract has Incorrect Argument Count in __Ownable_init Call
•	Severity: Medium
•	Impact: __Ownable_init() does not accept any arguments, leading to a type error during contract deployment.
•	Status: Unresolved
•	File: TokenRoles.sol
•	Lines Affected: 20

Contract Initialization Failure.

The TokenRoles contract attempts to initialize the OwnableUpgradeable contract by calling __Ownable_init(_owner). However, __Ownable_init() does not accept any arguments, leading to a type error during contract deployment.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

This error prevents the contract from being properly initialized, which means the ownership management functionality will not work as intended. Consequently, the contract may be deployed without a valid owner, making it impossible to manage roles and other owner-specific functions.
```sol
function __TokenRoles_init(address _owner, address _operator) public {
    __Ownable_init(_owner);  // This line will fail during deployment
    _grantRole(DEFAULT_ADMIN_ROLE, _owner);
    _grantRole(OPERATOR_ROLE, _operator);
}
```

## Tools Used
Manual review & Mythril.

## Recommended Mitigation Steps
Remove the _owner argument from the __Ownable_init function call to match the expected signature. The owner is automatically set to the deploying account in __Ownable_init.
```sol
function __TokenRoles_init(address _owner, address _operator) public {
    __Ownable_init();  // Corrected initialization
    _grantRole(DEFAULT_ADMIN_ROLE, _owner);
    _grantRole(OPERATOR_ROLE, _operator);
}
```
