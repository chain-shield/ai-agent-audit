# Vulnerability details

## Impact

After cross-chain transaction is initiated inside of `handler_erc20`, it goes to the `settlement` contract where an event that's monitored by the offchain services is emitted. The problem is that `send_cross_chain_msg()` that's called from the handler contract has no access control at all allowing anybody to manipulate the payload and bypass the information that was submitted by the `handler_erc20` smart contract.

## Proof of Concept

As you can see, inside of the function `send_cross_chain_msg()`, the handler address is not checked anyhow:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L284-287
```
 fn send_cross_chain_msg(
            ref self: ContractState, to_chain: felt252, to_handler: u256, payload_type :u8,payload: Array<u8>,
        ) -> felt252 {
            let from_handler = get_caller_address();
```

It only takes `get_caller_address` and uses it as the `from_handler` address. The function has `external` visibility with no access control modifiers so anybody can just call it and change the payload that was sent from the handler. An attacker can, for example, put all the data that was sent by other users and just slightly change the payload blocking the successful settlement. 


## Tools Used

Manual review.

## Recommended Mitigation Steps

There should be corresponding handler address for the settlement contract initialized in the constructor of the contract that should be checked in all sensitive functions.
