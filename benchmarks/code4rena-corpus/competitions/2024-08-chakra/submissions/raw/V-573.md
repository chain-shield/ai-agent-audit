# Vulnerability details

## Impact
When tokens are bridged in the `ChakraSettlementHandler`, they are either locked or burnt depending on the settlement mode. However, if the cross-chain operation fails (i.e., the `receive_cross_chain_callback` reports a `CrossChainMsgStatus.Failed`), the burnt or locked tokens are never refunded, resulting in permanent loss of funds for users.

This issue impacts all users involved in cross-chain token transfers and can lead to significant financial loss if tokens are locked or burnt without any recourse in the event of failure.
## Proof of Concept
In the `ChakraSettlementHandler` contract, tokens are locked or burnt based on the settlement mode:

```solidity
        if (mode == SettlementMode.MintBurn) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockMint) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.BurnUnlock) {
            _erc20_burn(msg.sender, amount);
        }
```

However, in the `receive_cross_chain_callback`, if the cross-chain message fails, the tokens remain burnt or locked, without any refund mechanism:

```solidity
if (status == CrossChainMsgStatus.Failed) {
    // No refund mechanism for failed cross-chain message
}
```

As a result, if the cross-chain operation fails, users’ tokens are irreversibly lost.
## Tools Used

Manual

## Recommended Mitigation Steps

To prevent the loss of funds, a refund mechanism should be added to handle cases where the `CrossChainMsgStatus.Failed` occurs.
