# Vulnerability details

## Impacts
Only owners should be able to add or remove managers, as confirmed by the sponsor, and as confirmed by solidity contracts, [here](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/BaseSettlement.sol#L149C53-L149C62) and [here](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/BaseSettlement.sol#L159C56-L159C65):
```solidity
/**
* @dev Grant a manager role for address
* @notice Only owner can do this
* @param _manager The manager address
*/
function add_manager(address _manager) external
>>> onlyOwner 
 {
    grantRole(MANAGER_ROLE, _manager);
    emit ManagerAdded(msg.sender, _manager);
}
```
However, this access control is not correctly enforced in the Cairo contracts. The current implementation allows managers to add or remove other managers, which could lead to unauthorized access and management of the protocol:
```rs
// settlement.cairo

 // Managers related operations
fn add_manager(ref self: ContractState, new_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
>>>    assert(self.chakra_managers.read(caller) == 1, "Caller is not a manager"); 
    assert(caller != new_manager, "Caller is a manager already");
    self.chakra_managers.write(new_manager, 1);
    self.emit(ManagerAdded {operator: caller, new_manager: new_manager, added_at: get_block_timestamp()});
    return self.chakra_managers.read(new_manager) == 1;
}

fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
>>>    assert(self.chakra_managers.read(caller) == 1, "Caller is not a manager"); 
    self.chakra_managers.write(old_manager, 0);
    self.emit(ManagerRemoved {operator: caller,old_manager: old_manager,removed_at: get_block_timestamp()});
    return self.chakra_managers.read(old_manager) == 0;
}
```
This issue is also present in `ckr_btc.cairo` as shown [here](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/ckr_btc.cairo#L136) and [here](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/ckr_btc.cairo#L150)

## Recommended Mitigation Steps
The access control logic should be updated to ensure that only the contract owner can manage the addition and removal of managers. For example:
```diff
fn add_manager(ref self: ContractState, new_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
-   assert(self.chakra_managers.read(caller) == 1, "Caller is not a manager"); 
+   self.ownable.assert_only_owner();
    assert(caller != new_manager, "Caller is a manager already");
    self.chakra_managers.write(new_manager, 1);
    self.emit(ManagerAdded {operator: caller, new_manager: new_manager, added_at: get_block_timestamp()});
    return self.chakra_managers.read(new_manager) == 1;
}
```
