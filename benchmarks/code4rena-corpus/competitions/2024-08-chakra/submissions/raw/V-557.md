# Vulnerability details

## Impact
Anyone can call `initialize` on these contracts and destroy them, making the severity of this vulnerability HIGH.

## Proof of Concept
Taking the example of the `ChakraSettlement` contract, its initializer is defined by 

```javascript
    function initialize(
        string memory _chain_name,
        uint256 _chain_id,
        address _owner,
        address[] memory _managers,
        uint256 _required_validators,
        address _verify_contract
    ) public initializer {
        _Settlement_init(
            _chain_name,
            _chain_id,
            _owner,
            _managers,
            _required_validators,
            _verify_contract
        );
    }
```

which is not protected by any constructor and could be called by anyone.
`ChakraSettlement` inherits from `UUPSUpgradeable`, meaning an attacker can call `UUPSUpgradeable.upgradeToAndCall()` after gaining ownership of the contract through the unprotected initializer and point the logic contract to their own or selfdestruct it, preventing any future upgrade and bricking the whole protocol.

## Tools Used

Manual Review / Visual Studio

## Recommended Mitigation Steps

We recommend using a `contructor` to avoid this issue and disable initalizers as soon as the contracts are deployed

```diff
+constructor() {
+    _disableInitializers();
+ }
```

this is in line with openzeppelin's recommendation https://docs.openzeppelin.com/contracts/4.x/api/proxy#Initializable
