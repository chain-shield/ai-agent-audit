# Vulnerability details

## Impact
The current implementation of the receive_cross_chain_msg function introduces critical vulnerabilities by failing to comprehensively validate both the ERC20 token origin and the payload content in cross-chain message handling. While the isValidPayloadType function ensures that the payload is labeled as ERC20, it does not validate the actual contents of the payload beyond decoding it. Furthermore, there is no robust mechanism to ensure that the ERC20 token being minted or unlocked originates from a trusted source.

An attacker could exploit the system by introducing a malicious or unauthorized ERC20 token via compromised or insufficiently validated handlers. This could lead to unauthorized minting or unlocking of tokens. Moreover, Even when the payload is identified as an ERC20 type, an attacker can craft a payload with malicious or incorrect data. This could manipulate the recipient address, token amount, or other sensitive fields, leading to incorrect transfers, unauthorized actions, or contract manipulation.

## Proof of Concept
only the handler address is validated, and the actual ERC20 token contract is not checked. The function `is_valid_handler` checks whether a handler is valid for a specific chain but does not ensure that the ERC20 token contract being processed is from a trusted and authorized source. there is insufficient verification of the ERC20 token's origin and the handler's validity. Although the handler is checked, the actual ERC20 token contract is not validated to ensure it is a trusted source.

Additionally, While `isValidPayloadType` ensures that the payload is identified as an ERC20 type, there is no further validation of the payload's actual content (e.g., transfer amount, recipient address).
An attacker could craft a payload that matches the ERC20 type but includes malicious or incorrect data. the content of the payload itself is not thoroughly validated. This opens the door for malicious or malformed payloads

## Recommended Mitigation Steps
Implement checks to ensure that the ERC20 token being minted or unlocked is from a trusted and authorized token contract. Additionally, implement detailed checks to ensure that the payload content (e.g., transfer amount, recipient address) adheres to expected values and formats.
