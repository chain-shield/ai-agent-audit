# Vulnerability details

## Impact

The `Chakra` system uses a multi-validator security model, only signed messages by a threshold of validators is valid (`required_validators_num` in code). There should be at least 2 non-colluding validators for such system to work. However, the current implementation is vulnerable to a single malicious validator reusing his own signature `required_validators_num` times or more to validate any message (e.g, validate a user asset to himself).

### Vulnerability Details

Let's see the relevant code, `settlement::receive_cross_chain_msg()` is responsible for receiving a message from another chain:

[cairo/settlement/src/settlement.cairo#L318-L385](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/settlement/src/settlement.cairo#L318-L385)

```js
fn receive_cross_chain_msg(
    ref self: ContractState,
    // more inputs ...
    signatures: Array<(felt252, felt252, bool)>,
) -> bool {
    // message hash calculation ...
    self.check_chakra_signatures(message_hash, signatures);
    // rest of the function ...
}
```

The vulnerability is in `settlement::check_chakra_signatures()` function, it validates signatures and asserts that there's sufficient valid signatures passed to `receive_cross_chain_msg` i.e, it `assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');`:

[cairo/settlement/src/settlement.cairo#L171-L192](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/settlement/src/settlement.cairo#L171-L192)

```js
fn check_chakra_signatures(
    self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
){
    let mut pass_count = 0;
    let mut i = 0;
    loop {
        if i > signatures.len()-1{
            break;
        }
        let (r,s,y) = * signatures.at(i);
        let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
        if self.chakra_validators_pubkey.read(pub_key) > 0{
            pass_count += 1;
        }
        i += 1;
    };
    assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
}
```

The `pass_count` increases each time a `pub_key` matches an existing validator. However, there's no mechanism to verify if the same validator's public key has been used more than once in the provided signatures.

This means that if a validator's signature appears multiple times in the `signatures` array, each occurrence will be counted as a separate validation. Therefore, "a single malicious validator reuses his own signature `required_validators_num` times or more to validate any message".

## Proof of Concept

Let's take a simple scenario to understand this issue:

- A manager sets `required_validators_num` to 10.
- A malicious validator signs a message off-chain, regardless of whether other validators have signed it or not.
- The malicious validator calls `receive_cross_chain_msg`, with `signatures` array of his own signature repeated `required_validators_num` times (i.e, 10 times) or more.
- Since the signature is valid (he is a validator) and there are enough signatures (`>= required_validators_num`), the message is considered valid.

snfoundry, manual review.

## Recommended Mitigation Steps

The fix is straightforward, add a check to ensure that the same validator's signature is not used more than once:

```diff
fn check_chakra_signatures(
    self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
){
    let mut pass_count = 0;
+   let mut seen_validators: LegacyMap<felt252, u8> = Default::default(); 
    let mut i = 0;
    loop {
        if i > signatures.len()-1{
            break;
        }
        let (r,s,y) = * signatures.at(i);
        let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
+       if self.chakra_validators_pubkey.read(pub_key) > 0 && seen_validators.read(pub_key) > 0{
-       if self.chakra_validators_pubkey.read(pub_key) > 0{

            pass_count += 1;
+           seen_validators.write(pub_key, 1);
        }
        i += 1;
    };
    assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
    }
}
```
