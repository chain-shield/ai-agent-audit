# Vulnerability details

## Impact
The status of of a created cross-chain transaction transitions incorrectly breaking an invariant.

## Proof of Concept
One of the Main Invariants in Settlement Contract is:
> The status of a created cross-chain transaction can only transition from Pending to either the received status or Failed.

This is enforced in `ChakraSettlement::receive_cross_chain_callback()` via [`ChakraSettlement::processCrossChainCallback()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L313-L330) as follows:
```solidity
        require(
>>          create_cross_txs[txid].status == CrossChainMsgStatus.Pending,
            "Invalid transaction status"
        );

        if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
>>          create_cross_txs[txid].status = status; // #1
        } else {
>>          create_cross_txs[txid].status = CrossChainMsgStatus.Failed; // #2
        }
```
As seen, first the function require that the `status` of the cross-chain transaction should be `Pending` after which it can transition to `#1`->([`status`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L261) i.e received status) or `#2`->(`Failed`). Here, the invariant is upheld correctly.

However in `settlement::receive_cross_chain_callback()`, the transition is made incorrectly:
First, the function require that the [`status` of the cross-chain transaction should be `Pending`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L409) which is correct:
```solidity
    assert(self.created_tx.read(cross_chain_msg_id).tx_status == CrossChainMsgStatus::PENDING, 'tx status error');
```
Then, the [transition is made as follows](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L415-L421):
```solidity
            let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
            let mut state = CrossChainMsgStatus::PENDING;
            if success{
>>              state = CrossChainMsgStatus::SUCCESS; // @audit-info Incorrect transition.
            }else{
>>              state = CrossChainMsgStatus::FAILED;
            }
```
Notice that the `status` transitions form `PENDING` to either `SUCCESS` or `FAILED`. This is incorrect since the invariant requires only transition from `Pending` to either the `received status` or `Failed` not `success`.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The transition should be made to either `received status` or `Failed`:
```diff
            let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
            let mut state = CrossChainMsgStatus::PENDING;
            if success{
-               state = CrossChainMsgStatus::SUCCESS;
+               state = cross_chain_msg_status;
            }else{
                state = CrossChainMsgStatus::FAILED;
            }
```
