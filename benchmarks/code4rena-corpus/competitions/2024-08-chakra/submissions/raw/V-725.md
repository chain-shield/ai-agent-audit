# Vulnerability details

## Impact
The current implementation of cross-chain transaction ID generation in the `cross_chain_erc20_settlement` function lacks a unique identifier for the source chain. This omission creates a vulnerability where an attacker could potentially replay a transaction on another chain if the same user address, handler addresses, and nonce exist on both chains. Such a replay attack could lead to unauthorized token transfers, double-spending, or other malicious activities, resulting in financial losses.

## Proof of Concept
In the `cross_chain_erc20_settlement` function, the transaction ID (txid) is generated as follows:

```solidity
uint256 txid = uint256(
    keccak256(
        abi.encodePacked(
            chain,
            to_chain,
            msg.sender,
            address(this),
            to_handler,
            nonce_manager[msg.sender]
        )
    )
);
```

This implementation does not include a unique identifier for the source chain, such as a chain ID or a network-specific constant. As a result, if the same user address, handler addresses, and nonce exist on two different chains, it's possible to generate the same txid, potentially allowing a transaction to be replayed on another chain.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Include a unique chain identifier in the txid generation. This could be chain ID.
