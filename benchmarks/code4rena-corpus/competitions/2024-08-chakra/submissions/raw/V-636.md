# Vulnerability details

Different order of critical event parameters emitted between Cairo and Solidity contracts might make it impossible for validators to listen to event values between Starknet and EVM chains. (not critical, but might confuse). This issue applies to the following `CrossChainHandleResult` and `CrossChainResult` events emitted on critical Cairo settlement contract functions `receive_cross_chain_msg` and `receive_cross_chain_callback`. 
To compare, the events emitted by Solidity contract `ChakraSettlement.sol`:
```solidity
    function receive_cross_chain_msg(
    // ... other code
        emit CrossChainHandleResult(
            txid,
            status,
            contract_chain_name,
            from_chain,
            address(to_handler),
            from_handler,
            payload_type
        );
    // ... other code
    function emitCrossChainResult(uint256 txid) internal {
        emit CrossChainResult(
            txid,
            create_cross_txs[txid].from_chain,
            create_cross_txs[txid].to_chain,
            create_cross_txs[txid].from_address,
            create_cross_txs[txid].from_handler,
            create_cross_txs[txid].to_handler,
            create_cross_txs[txid].status
        );
    }
```
The events emitted by Cairo contract in `settlement.cairo`:
```cairo
        fn receive_cross_chain_msg(
            // ... other code
            self.emit(CrossChainHandleResult{
                cross_chain_settlement_id: cross_chain_msg_id,
                from_chain: to_chain,
                from_handler: to_handler,
                to_chain: from_chain,
                to_handler: from_handler,
                cross_chain_msg_status: status,
                payload_type: payload_type
            });
            // ... other code
        fn receive_cross_chain_callback(
            // ... other code
            self.emit(CrossChainResult {
                cross_chain_settlement_id: cross_chain_msg_id,
                from_address: get_tx_info().unbox().account_contract_address,
                from_chain: to_chain,
                from_handler: to_handler,
                to_chain: from_chain,
                to_handler: from_handler,
                cross_chain_msg_status: state,
            });
```

## Impact

Validators might not read the events of one of the chains properly, as a consequence, the funds might remain locked on the source chain.

## Tools Used

Manual review

## Recommended Mitigation Steps

Make sure to emit the event parameteres in the same order on both Solidity and Cairo contracts so that the validators can read the event values correctly.
