# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: TokenRoles contract Missing Implementation of _authorizeUpgrade Function
•	Severity: Medium
•	Impact: This _authorizeUpgrade function is missing in the TokenRoles contract, leaving the upgrade mechanism open to unauthorized upgrades.
•	Status: Unresolved
•	File: TokenRoles.sol
•	Lines Affected: 6

File Audited: /2024-08-chakra/solidity/handler/contracts/TokenRoles.sol

The TokenRoles contract inherits from UUPSUpgradeable, which requires the implementation of the _authorizeUpgrade function to control who can authorize upgrades of the contract. However, this function is missing in the TokenRoles contract, leaving the upgrade mechanism open to unauthorized upgrades.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

This missing implementation allows any user to upgrade the contract to a malicious version, which could result in the loss of all control over the contract, including the ability to manage roles, ownership, and other critical functions.

```sol
pragma solidity ^0.8.24;

contract MaliciousImplementation {
    // Storage variables to mimic the original contract's storage layout
    address private _owner;
    mapping(bytes32 => mapping(address => bool)) private _roles;

    // Malicious function that will be executed after the upgrade
    function exploit() external {
        // Logic to transfer ownership to the attacker
        _owner = msg.sender;

        // Logic to drain funds from the contract (if it holds any)
        payable(msg.sender).transfer(address(this).balance);

        // Potentially disrupt role management by giving the attacker all roles
        bytes32 operatorRole = keccak256("OPERATOR_ROLE");
        _roles[operatorRole][msg.sender] = true;
    }

    // Fallback function to receive Ether
    receive() external payable {}
}
```

## Tools Used
Manual review & Mythril.

## Recommended Mitigation Steps
Implement the _authorizeUpgrade function in the TokenRoles contract to restrict upgrades to authorized accounts only. Typically, this should be restricted to the contract owner or another highly privileged role.
```sol
function _authorizeUpgrade(address newImplementation) internal override onlyOwner {
    // Only the owner can authorize upgrades
}
```
