# Vulnerability details

## Impact

`cross_chain_erc20_settlement()` function serves as an entry for user cross-chain transactions. The problem is that the function does not anyhow validate the `to_handler` address except for address(0) check not checking its validity inside of the source chain handler.

## Proof of Concept

Current validation process looks like this:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L120
```
require(to_handler != 0, "Invalid to handler address");
```

The function does not check validity of the handler on the destination chain even though there is `is_valid_handler()` function inside of the contract:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L41-46
```
 /**
     * @dev Checks if a handler is valid for a given chain
     * @param chain_name The name of the chain
     * @param handler The handler address
     * @return bool True if the handler is valid, false otherwise
     */
    function is_valid_handler(
        string memory chain_name,
        uint256 handler
    ) public view returns (bool) {
        return handler_whitelist[chain_name][handler];
    }

```

So not verifying it on the source chain can lead to DoS on the destination chain and excessive gas costs being spent by the users on the execution.

From the docs:

```
The handler receiving a cross-chain message must be on the whitelist for the source chain
```

Moreover, there is the following check in the Cairo version of the contract:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L168
```
assert(self.support_handler.read((to_chain, to_handler)), 'not support handler');
```


## Tools Used

Manual review.

## Recommended Mitigation Steps

Add `is_valid_handler` check in the `cross_chain_erc20_settlement()`.
