# Vulnerability details

## Summary
The `receive_cross_chain_msg` function in the `ChakraSettlement` contract is vulnerable to front-running, allowing unauthorized parties to execute transactions intended for specific proposers, potentially leading to validator reward loss.

## Vulnerability Details
Function Accessibility: The function can be called by any address, not just the intended proposer.

According to the [docs](https://s3labs.notion.site/Contract-Design-Document-f4aa296f71fb40b1818c0890c40be55c#e0bdd961a2f746b29a851b12fba7c229), this function should only be called by the `chakraValidators`.
```javascript
//@audit anyone can call
 function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type, // erc20
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
        {
            // verify signature
            // this is a hash of the trx which is started bythe send cross chain messgae by the invoke by the handler
            // replay attack if the 
            bytes32 message_hash = keccak256(
                abi.encodePacked(
                    txid,
                    from_chain,
                    from_address,
                    from_handler,
                    to_handler,
                    keccak256(payload)
                )
            );
            //////
```
Front-Running Risk: Attackers can observe pending transactions and submit them with higher gas fees to execute them first.

## Impact
Validator Reward Loss: Validators may not receive their expected rewards if transactions are executed by unauthorized parties.

System Integrity: The integrity of the cross-chain message handling process can be compromised.

NOTE-> The `ChakraSettlement::receive_cross_chain_callback` is also lack Access control

## Tools Used
Manual Review

## Recommendations
Implement Access Control: Restrict function access to authorized proposers using role-based permissions.
