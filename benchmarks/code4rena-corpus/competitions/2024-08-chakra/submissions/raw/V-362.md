# Vulnerability details

## Impact
When the new balance is not equal to the old balance plus the amount, the function will return false without reverting.

## Proof of Concept

The mint_to function is designed to mint new tokens to a specified address. However, its implementation allows for a scenario where tokens are minted successfully, but the function returns false, indicating a failure withoug reverting. 

```
      fn mint_to(ref self: ContractState, to: ContractAddress, amount: u256) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_operators.read(caller) == 1, Errors::NOT_OPERATOR);
            let old_balance = self.erc20.balance_of(to);
            self.erc20.mint(to, amount);
            let new_balance = self.erc20.balance_of(to);
            return new_balance == old_balance + amount;
        }
```
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/ckr_btc.cairo#L199-L206

- The function checks if the caller is an authorized operator.
- It records the old balance of the recipient.
- It calls the mint function to create new tokens.
- It checks the new balance of the recipient.
- It returns a boolean value based on whether the new balance equals the old balance plus the minted amount.

However, when the function returns "false", it doesn't revert.

Consider the following sequence of events:

* Alice's balance: 5,000 tokens
* Call mint_to(alice_address, 1000)
* Internal minting operation succeeds
* Due to some reasons, Alice's balance is not updated
* Function execution:
```
let old_balance = self.erc20.balance_of(alice_address);  // Returns 5,000
self.erc20.mint(alice_address, 1000);  // Succeeds, actual total supply is now 1,001,000
let new_balance = self.erc20.balance_of(alice_address);  // Returns 5,000 due to delayed update
return new_balance == old_balance + amount;  // Returns false (5,000 != 5,000 + 1,000)
```

* Function returns false and doesn't revert
