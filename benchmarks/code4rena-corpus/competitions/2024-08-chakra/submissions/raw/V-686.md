# Vulnerability details

## Summary
The `receive_cross_chain_callback` function in the `ChakraSettlementHandler` contract does not handle the `BurnUnlock` settlement mode correctly. This can lead to tokens not being burned on the source chain when they are unlocked on the destination chain, resulting in an inflated token supply.

## Vulnerability Details
- The `receive_cross_chain_callback` function currently only handles the `MintBurn` mode for burning tokens on the source chain.
```javascript
    enum SettlementMode {
        MintBurn,
        LockMint,
        BurnUnlock,
        LockUnlock
    }
```
- When the `BurnUnlock` mode is selected, the function does not burn the tokens on the source chain, leading to a mismatch in token supply.

## Impact
- Tokens may not be burned on the source chain when they are unlocked on the destination chain, leading to an inflated token supply.
- The system may end up with an inconsistent token supply, undermining the integrity of the cross-chain token transfer mechanism.

## Tools Used
- Manual code review and analysis.

## Recommendations
Ensure that the `ChakraSettlementHandler::receive_cross_chain_callback` function handles all settlement modes, including `BurnUnlock`.
