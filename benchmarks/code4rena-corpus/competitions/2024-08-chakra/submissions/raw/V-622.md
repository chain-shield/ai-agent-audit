# Vulnerability details

## Impact

After all validators are removed, the system can no longer perform effective signature verification.

The vulnerability exists in the `remove_validator` function, where the removal of a validator is performed without any checks on the remaining number of validators. If all validators are removed from the system, the contract could become non-functional, as it would no longer have any validators available to verify signatures. This would lead to critical security risks because cross-chain transactions would no longer be validated. The absence of validators would leave the system open to attacks and manipulation, or even cause it to cease functioning entirely.

### Consequences:

- **Loss of Signature Validation**: If all validators are removed, the `check_chakra_signatures` function will not be able to perform valid signature verification on transactions. This is because the function relies on the validator public key set stored in `chakra_validators_pubkey` for verification. If all validators are removed, there will be no available public keys in `chakra_validators_pubkey` for verification, resulting in transactions not being able to obtain sufficient signature verification to pass. Since the security model of the system relies on signature verification, this will severely weaken the security of the system.
- **Systemic Failure**: The code checks `required_validators_num` to ensure that the transaction has enough validator signatures. However, if all validators are removed, the system will not be able to obtain any valid signatures even with the `required_validators_num` limit. This will cause the system to be unable to process any valid cross-chain transactions because no validator signatures can meet the verification requirements of the transaction. As a result, the system may become stuck and unable to continue processing cross-chain messages or transactions.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L225

The `remove_validator` function below demonstrates the vulnerability, where no check is performed to ensure a minimum number of validators remain in the system after removal:

```

fn remove_validator(ref self: ContractState, old_validator: felt252) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
    assert(self.chakra_validators_pubkey.read(old_validator) == 1, 'Caller is not a validator');
    self.chakra_validators_pubkey.write(old_validator, 0);
    self.emit(ValidatorRemoved { 
        operator: caller, 
        old_validator: old_validator, 
        removed_at: get_block_timestamp() 
    });
    return self.chakra_validators_pubkey.read(old_validator) == 0;
}
```

If all validators are removed using this function, the contract would be unable to validate transactions.

## Recommended Mitigation Steps

**Add Validator Count Checks**: Implement logic to ensure that at least one or more validators remain in the system after any removal. This would prevent the removal of all validators and preserve the integrity of the system.
