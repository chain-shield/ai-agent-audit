# Vulnerability details

## Impact
One of the invariants about the Settlement Handler Contract in the README of the audit states that: 

`The nonce for each sender is incremented with each cross-chain transaction to ensure uniqueness of transaction IDs.`

The problem is that each sender does not have a seperate nonce like in the solidity files. The nonce is only one which breaks the invariant

## Proof of Concept
This is the `cross_chain_erc20_settlement()` in `handler_erc20.cairo`

As we can see we have `msg_count` that represents the nonce but it is not a mapping, it is a variable unlike in the solidity files where the nonce is seperate for each address
