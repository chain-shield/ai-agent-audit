# Vulnerability details

## Impact

The remove_validator method allows the status of all validators to be set to false, which will cause the contract to fail to pass the signature verification logic and the system will no longer be able to operate normally.

SettlementSignatureVerifier contract.  The `remove_validator` method allows setting all validators to `false`, which could cause `validators[msgHash.recover(sig)]` to fail. This means that even if a signature is valid, the contract will be unable to verify it because there would be no validators available. This could lead to a complete failure of the contract's multi-signature functionalities, making it impossible to execute crucial actions such as transferring assets or performing critical operations.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L125

In the `remove_validator` method:

```

function remove_validator(
    address validator
) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == true, "Validator does not exists");
    validators[validator] = false;
    validator_count -= 1;
    emit ValidatorRemoved(msg.sender, validator);
}
```

This code allows the removal of all validators. If all validators are removed, the `validators` mapping will have no valid entries, and even correct signatures will fail to match any validators, breaking the `verifyECDSA` function's logic.

## Recommended Mitigation Steps

1. Introduce a restriction that ensures at least one validator is always present in the system when removing validators, preventing the system from losing its validation capability.
2. Check the `validator_count` variable before removal to ensure the number of remaining validators is above a minimum safe threshold.
