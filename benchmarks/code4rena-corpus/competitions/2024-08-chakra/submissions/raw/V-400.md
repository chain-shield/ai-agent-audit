# Vulnerability details

## Impact

The 6th parameter in `struct::CreatedCrossChainTx` represents the `from_token` address, as indicated [here](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/BaseSettlementHandler.sol#L59). However, in `handler/contracts/ChakraSettlementHandler::cross_chain_erc20_settlement`, when the mapping is set, the 6th parameter is assigned to `address(this)`, which refers to the `ChakraSettlementHandler` contract address instead ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L160)).

A few lines later, when creating a payload, the 4th parameter of `struct::ERC20TransferPayload` is the `from_token`, and this is correctly set to `AddressCast.to_uint256(token)`, which converts the token address to a `uint256` ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L185)). This payload is then passed as input to the settlement contract ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L203)) and is saved with the correct data ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L142)). Finally, it is emitted ([link](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L154)).

According to the document diagram, off-chain Chakra validators retrieve this payload from the network. Since this payload forms part of the hash that is later signed for interaction with the target chain, this vulnerability can lead to discrepancies between the `from_token` saved on the target chain and the initial chain. Additionally, it may cause an invalid signature vulnerability due to the incorrect token address.

## Proof of Concept

The `from_token` address is incorrectly set when creating the `CreatedCrossChainTx` structure in the `cross_chain_erc20_settlement` function:

Definition of `struct CreatedCrossChainTx`:
- [BaseSettlementHandler.sol:59](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/BaseSettlementHandler.sol#L59)
```javascript
    struct CreatedCrossChainTx {
        uint256 txid;
        string from_chain;
        string to_chain;
        address from;
        uint256 to;
        address from_token;
        uint256 to_token;
        uint256 amount;
        CrossChainTxStatus status;
    }
```

Incorrect assignment of `from_token` in `cross_chain_erc20_settlement`:
- [ChakraSettlementHandler.sol:160](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L160)

```

The correct `from_token` is set in the payload a few lines later in the same function:
- [ChakraSettlementHandler.sol:185](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L185)

@>      AddressCast.to_uint256(token),

```

## Recommended Mitigation Steps

To fix this issue, change the incorrect assignment of `from_token` from `address(this)` to `token` in the `cross_chain_erc20_settlement` function:

```diff
handler/contracts/ChakraSettlementHandler::cross_chain_erc20_settlement

    create_cross_txs[txid] = CreatedCrossChainTx(
        txid,
        chain,
        to_chain,
        msg.sender,
        to,
-       address(this),
+       token
        to_token,
        amount,
        CrossChainTxStatus.Pending
    );
```
