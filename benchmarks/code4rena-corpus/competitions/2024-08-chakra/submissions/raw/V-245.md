# Vulnerability details

## Impact
Invalid required validators updated at BaseSettlement contract due to absence of this update happening simultaneously in the signature verifier contract which would cause validator inconsistency at [L207](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L207) & [L134](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/SettlementSignatureVerifier.sol#L134) of SettlementSignatureVerifier contracts where it would affect the proper verification of ECDSA during verifyECDSA(...) function call.
- if required_validators is too short ECDSA verification would return prematurely in loop without complete verification returning true when it would have probably return false under normal circumstances
- if required_validators is too long ECDSA verification would be out of bound in loop there by returning false when it would have probably return true under correct circumstances
## Proof of Concept
```solidity

        uint256 old = required_validators;
>>>        required_validators = _required_validators;
```

The function above shows how required validators is being set in the BaseSettlement contract, a look at [L89](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/BaseSettlement.sol#L89) & [L106](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/BaseSettlement.sol#L106) of same contract as provided in the code below shows that when validators are added or remove the same command or implementation is updated in a corresponding signature verifier contract to ensure validator variable consistency. The problem with the code above is that required validators number is only set and updated in BaseSettlement contract without also updating it in the corresponding signature verifier contract which would break proper functionality of contract as the correct required_validators would not be used where necessary as noted in the impact of this report, this inconsistency would would affect normal functionality as expected by protocol

## Recommended Mitigation Steps
As adjusted below the required Validator number should not only be set in the current contract but also automatically set in the related signature contract to ensure Validator variable consistency.
```solidity
   function set_required_validators_num(
        uint256 _required_validators
    ) external onlyRole(MANAGER_ROLE) {
+++     signature_verifier.set_required_validators_num(_required_validators);
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
