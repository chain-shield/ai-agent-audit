# Vulnerability details

When receiving cross chain messages or cross chain callbacks, the `message_hash`, `signatures` & `sign_type` is verified by the validators. Also the message hash should pass the required number of validators required for the verification to return `true`.

However it is possible that the signature contains duplicate data that returns the same address of a validator until the requirement is fulfilled.

## Proof of Concept
When receiving cross chain messages or callbacks, `verify()` is called. 
```solidity
File: ChakraSettlement.sol

    function receive_cross_chain_msg(
     ...
          require(
             signature_verifier.verify(message_hash, signatures, sign_type),
             "Invalid signature"
          );
      ...
     }

     function verifySignature(
      ...
          require(
             signature_verifier.verify(message_hash, signatures, sign_type),
             "Invalid signature"
          );
       ...
      }
```
The `verify()` internally calls `verifyECDSA()` where the validation takes place.

```solidity
File: SettlementSignatureVerifier.sol

    function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
       ...
        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators  //@note - can return the same address of a valid validator multiple times   
            ) {
                return true;
            }
        }

        return false;
    }
```
Here we can see inside the `if` condition that if the `msgHash.recover(sig)` keeps on returning the same address of a valid validator, the counter `m` keeps on increasing until the function return `true`.

## Impact
Incorrect messages/callbacks would be carried out during cross chain interactions.

## Tools Used
Manual Review

## Recommended Mitigation Steps
A solution to this could be to separate the signature into different sets, arrange them in ascending order making sure that no two sets are the same.
