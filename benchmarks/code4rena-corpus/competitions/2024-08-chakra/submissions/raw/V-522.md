# Vulnerability details

### Signature Uniqueness Vulnerability in `verifyECDSA` Function in `/settlement/contracts/SettlementSignatureVerifier.sol` 
The `verify` function which is used in the `/settlement/contracts/SettlementSignatureVerifier.sol` is used to verify a given array of signatures which in turn calls the internal function `verifyECDSA` takes the params and checks if the signatures provided are correct but in there it does not check if the signatures are unique or not. 

The verify function is used in these defined places 
- https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L195
- https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L298


**Issue**: The current implementation of the function does not prevent or handle duplicate signatures.

**Impact**: An attacker can exploit this weakness by supplying duplicate signatures, which incorrectly inflates the count of valid signatures. This allows the attacker to achieve the required threshold with fewer unique signatures than intended.

Remediation : 

```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 len = signatures.length;
    uint256 uniqueValidators = 0;
    mapping(address => bool) memory seenValidators;

    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        address recoveredAddress = msgHash.recover(sig);
        
        if (validators[recoveredAddress] && !seenValidators[recoveredAddress]) {
            seenValidators[recoveredAddress] = true;
            uniqueValidators++;
            
            if (uniqueValidators >= required_validators) {
                return true;
            }
        }
    }

    return false;
}
```
