# Vulnerability details


## Summary

The Chakra protocol lacks a message cancellation mechanism for L2 to L1 cross-chain transactions, risking permanent token lockup in failed transactions.

## Impact

- Permanent asset loss can occur if a message fails and token gets stuck
- Reduced user trust in the protocol
- Decreased cross-chain liquidity
- Increased operational complexity

## Proof of Concept

1. User initiates cross-chain settlement (L2 to L1)
2. Tokens are locked/burned on the source chain
3. Transaction fails on the destination chain
4. Callback function isn't called or reports failure
5. Tokens remain locked with no cancellation mechanism

```solidity
function cross_chain_erc20_settlement(...) external {
    // Lock/burn tokens
    settlement.send_cross_chain_msg(...);
    // No cancellation mechanism
}
```

## Recommendation

Add a function to the L2 side so that user can cancel their messages incase of failures.


## Assessed type

DoS
