# Vulnerability details

## Impact
Callback won't be able to be processed if the mode is MintBurn because of an incorrect use of _burnFrom.

This is because when the mode is `MintBurn`, the contract will try to burn tokens from itself via `_burnFrom`. However, even though the contract burns tokens from itself, it still needs allowance. 
## Proof of Concept
Let's see the `receive_cross_chain_callback` function:
```
    function receive_cross_chain_callback(/*params*/) external onlySettlement returns (bool) {

        if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
        }

        require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending,
            "invalid CrossChainTxStatus"
        );

        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }

        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }

        return true;
    }
```
As  you can see, the contract is trying to burn `amount` tokens from itself:
```
_erc20_burn(address(this), create_cross_txs[txid].amount);
```
And the code of the `_erc20_burn` function:
```
    function _erc20_burn(address account, uint256 amount) internal {
        require(
            IERC20(token).balanceOf(account) >= amount,
            "Insufficient balance"
        );

        IERC20Burn(token).burn_from(account, amount);
    }
```
Here, we assume the token implements the `burn_from` function. 

Now, let's say that the token implements this function via OpenZeppelin's `ERC20Burnable` which is one of the most well-established and widely used standards.

Let's take a look at the code of [ERC20Burnable burnFrom](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/55d69573fc6c9cf2924efeb6265a4f4423a6c17e/contracts/token/ERC20/extensions/ERC20Burnable.sol#L35-L38) function:
```
    function burnFrom(address account, uint256 value) public virtual {
        _spendAllowance(account, _msgSender(), value);
        _burn(account, value);
    }
```
As you can see, the function tries to spend allowance given from `account` to `msg.sender`. In our case, such allowance still needs to be given even though the contract is burning tokens from itself. And the contract doesn't have functionality to give allowance so there's no way this will be executed. 

Let's check the [_spendAllowance function](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/55d69573fc6c9cf2924efeb6265a4f4423a6c17e/contracts/token/ERC20/ERC20.sol#L301-L311):
```
    function _spendAllowance(address owner, address spender, uint256 value) internal virtual {
        uint256 currentAllowance = allowance(owner, spender);
        if (currentAllowance != type(uint256).max) {
            if (currentAllowance < value) {
                revert ERC20InsufficientAllowance(spender, currentAllowance, value);
            }
            unchecked {
                _approve(owner, spender, currentAllowance - value, false);
            }
        }
    }
```
As you can see, there's no check if `owner` and `spender` are the same to circumvent the allowance spending. 

Here's a simple contract that implements `ERC20Burnable` from OZ that you can test in Remix:
```
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";
import "@openzeppelin/contracts/token/ERC20/extensions/ERC20Burnable.sol";

contract MyToken is ERC20, ERC20Burnable {
    constructor(
        string memory name,
        string memory symbol,
        uint256 initialSupply
    ) ERC20(name, symbol) {
        _mint(msg.sender, initialSupply);
    }
}
```
1. Deploy the contract from Account1
2. Try to burn tokens using the burnFrom(Account1, amount) function. Even though Account1 is the msg.sender, the function will fail

## Recommended Mitigation Steps
One solution is to add this to the `_erc20_burn` function:
```
if(account == address(this) {
    IERC20Burn(token).burn(amount);
}
```
