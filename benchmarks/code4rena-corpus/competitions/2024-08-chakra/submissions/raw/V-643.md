# Vulnerability details

## Summary
In ChakraSettlement.sol, the  function send_cross_chain_msg() should only be called by the whitelisted handlers. but lack of check in this function will allow an attacker to call this function with custom payload. By taking this as advantage attackers will call this function with the custom payload to mint unlimited tokens in the destination chain.

However as per the system design of the protocol txid generated in ChakraSettlement.sol is used during ChakraSettlement::receive_cross_chain_callback() call by the validator/proposer, but inside ChakraSettlementHandler::receive_cross_chain_callback() funciton create_cross_txs[txid].status will return 0 and require statement require(create_cross_txs[txid].status == CrossChainTxStatus.Pending, "invalid CrossChainTxStatus") will fail because storage associated with txid is not updated in the ChakraSettlementHandler as we directly called `send_cross_chain_msg` in ChakraSettlement. So this transaction(callback transaction) will revert as it is called by the validator.

## Impact
Due to this bug, an attacker can directly call send_cross_chain_msg with custom payload and he can able to mint unlimited tokens on the destination chain

## Proof of Concept
An attacker can directly call `send_cross_chain_msg` without transferring tokens and can emit event `CrossChainMsg`. The validator will pick up the event and will mint tokens on the destination chain
