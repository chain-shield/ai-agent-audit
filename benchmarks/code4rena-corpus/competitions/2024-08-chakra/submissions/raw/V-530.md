# Vulnerability details

In Cairo there is a particular feature that when a contract gets his class hash changed (contract upgraded) its constructor is not executed as someone could expect. Hence, creating an implementation with a constructor that sets important variables will have serious problems.

In Cairo files, we can notice that files like `handler_erc20.cairo` and `settlement.cairo` have important variable setting in its constructor. Hence, if they get upgraded following the same pattern using the constructor, it will not get executed.

`handler_erc20.cairo`
```
    #[constructor]
    fn constructor(ref self: ContractState, settlement_address: ContractAddress, owner: ContractAddress, token_address: ContractAddress, mode: u8) {
        assert(mode<=3, 'invalid mode');
        self.settlement_address.write(settlement_address);
        self.ownable.initializer(owner);
        self.token_address.write(token_address);
        self.mode.write(mode);
    }
```

`settlement.cairo`
```
    #[constructor]
    fn constructor(ref self: ContractState, owner: ContractAddress, chain_name: felt252) {
        self.ownable.initializer(owner);
        self.chakra_managers.write(owner, 1);
        self.chain_name.write(chain_name);
    }
```

## Recommended Mitigation Steps
Move these variable setting from the constructor to and initialize function that can be executed with owner permission.
