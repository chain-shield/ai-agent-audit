# Vulnerability details

## Impact

Received messages in the cairo settlement contract can be replayed multiple times and drain the contract of the deposited funds.

## Description

The function that finalizes received cross-chain messages in the cairo settlement contract - `receive_cross_chain_msg()` - does not check the transaction status (as Solidity contracts do) to validate if it was executed already, allowing them to be replayed multiple times.

This is how the function looks like:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L325

```cairo
 fn receive_cross_chain_msg(
            .....
        ) -> bool {
            .....

            // verify signatures
            .....
            self.check_chakra_signatures(message_hash, signatures);

            // call handler receive_cross_chain_msg
            let handler = IHandlerDispatcher{contract_address: to_handler};
            let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

            let mut status = CrossChainMsgStatus::SUCCESS;
            if success{
                status = CrossChainMsgStatus::SUCCESS;
            }else{
                status = CrossChainMsgStatus::FAILED;
            }

            self.received_tx.write(cross_chain_msg_id, ReceivedTx{
                .....
                tx_status: status
            });

           ....
            return true;
        }
```

The problem is that the function does not validate anywhere if the status of the transaction has been set (e.g it has been executed already). This allows anyone to call the function multiple times for the same transaction and execute the underlying transfer/mint multiple times as long as there are balances.

The internal call to `handler.receive_cross_chain_msg()` also does not contain any validation to prevent the replay attack.

For comparison here is how this is prevented in the Solidity contracts:

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L199-L203

```solidity
 function receive_cross_chain_msg(
       ....
    ) external {

 ....

        require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );


.....

}

```

## Recommended Mitigation Steps

Add a check in the `receive_cross_chain_msg()` transaction to validate if the transaction exists and revert - ` self.received_tx.read(cross_chain_msg_id)` and if it does it means it has been processed already
