# Vulnerability details

ChakraSettlementHandler contract, which inherits from the BaseSettlementHandler contract, is responsible for handling cross-chain ERC20 token settlements. The contract allows users to initiate cross-chain settlements by calling the `cross_chain_erc20_settlement` function, which locks or burns tokens based on the settlement mode and creates a new cross-chain transaction entry in the [create_cross_txs mapping](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/BaseSettlementHandler.sol#L84).

There is an issue with how the transaction amount is updated in the [create_cross_txs mapping](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/BaseSettlementHandler.sol#L84). When creating a new cross-chain transaction entry, the `cross_chain_erc20_settlement` function directly assigns the `amount` to the [CreatedCrossChainTx](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/BaseSettlementHandler.sol#L84) struct without considering any previous transaction amounts. This leads to incorrect tracking of the total transaction amounts.

```solidity
{
    // Save the cross chain tx
    create_cross_txs[txid] = CreatedCrossChainTx(
        txid,
        chain,
        to_chain,
        msg.sender,
        to,
        address(this),
        to_token,
        amount,
        CrossChainTxStatus.Pending
    );
}
```
The function directly assigns the `amount` to the `CreatedCrossChainTx` struct without checking for any existing transaction amounts. If a transaction with the same `txid` already exists, the previous amount will be overwritten, resulting in incorrect tracking of the total transaction amount.

## Impact
The highest impact scenario occurs when multiple cross-chain settlements are initiated for the same transaction ID (`txid`). Each subsequent settlement overwrites the previous transaction amount, leading to a discrepancy between the actual total amount and the recorded amount in the `create_cross_txs` mapping.

For example, consider the following scenario:

1. User A initiates a cross-chain settlement with an amount of 100 tokens.
2. The transaction is recorded in the `create_cross_txs` mapping with an amount of 100 tokens.
3. User B initiates another cross-chain settlement for the same transaction ID with an amount of 200 tokens.
4. The previous transaction amount of 100 tokens is overwritten, and the `create_cross_txs` mapping now records the amount as 200 tokens instead of the expected 300 tokens (100 + 200).

This scenario leads to a loss of funds for the users and inconsistencies in the total transaction amounts recorded by the contract. The impact can be significant if the discrepancies accumulate over multiple transactions, resulting in a substantial loss of funds.

## Recommended Mitigation Steps
The `cross_chain_erc20_settlement` function should update the transaction amount by adding the new `amount` to the existing transaction amount (if any) in the `create_cross_txs` mapping.
```diff
{
    // Save the cross chain tx
-   create_cross_txs[txid] = CreatedCrossChainTx(
+   CreatedCrossChainTx storage existingTx = create_cross_txs[txid];
+   if (existingTx.txid == 0) {
+       create_cross_txs[txid] = CreatedCrossChainTx(
            txid,
            chain,
            to_chain,
            msg.sender,
            to,
            address(this),
            to_token,
            amount,
            CrossChainTxStatus.Pending
        );
+   } else {
+       existingTx.amount += amount;
+   }
}
```
By checking if an existing transaction entry exists and updating the amount accordingly, the total transaction `amount` will be accurately tracked, preventing inconsistencies and potential loss of funds.
