# Vulnerability details

In order to initiate a cross chain message, users can call `cross_chain_erc20_settlement` in the handler contract in the source chain. Function `cross_chain_erc20_settlement` handles token transfers at the source chain depending on the SettlementMode (i.e., MintBurn, LockMint, BurnUnlock, and LockUnlock):
handler_erc20.cairo:
```
            let token = IERC20Dispatcher{contract_address: self.token_address.read()};
            let token_burnable = IERC20MintDispatcher{contract_address: self.token_address.read()};
            if self.mode.read() == SettlementMode::MintBurn{
                token.transfer_from(get_caller_address(), get_contract_address(), amount);
            }else if self.mode.read() == SettlementMode::LockMint{
                token.transfer_from(get_caller_address(), get_contract_address(), amount);
            }else if self.mode.read() == SettlementMode::BurnUnlock{
                token_burnable.burn_from(get_caller_address(), amount);
            }else if self.mode.read() == SettlementMode::LockUnlock{
                token.transfer_from(get_caller_address(), get_contract_address(), amount);
            }
```
ChakraSettlementHandler.sol:
```
        if (mode == SettlementMode.MintBurn) {
            _erc20_lock(msg.sender, address(this), amount); 
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockMint) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.BurnUnlock) {
            _erc20_burn(msg.sender, amount);
        }
``` 
After handling token transfers, function `send_cross_chain_msg` in settlement contract will be called. Then a CrossChainMsg event is emitted, then validators call `receive_cross_chain_msg` on the destination chain, then there will be another CrossChainHandleResult event that will be monitored by validators, that will call `receive_cross_chain_callback` on the settlement contract on the source chain.
Since the tokens can be locked or burnt based on the SettlementMode in the handler contract on the source chain, there must be a refund mechanism for the users' tokens in case of a failure on the destination chain. However, both handlers handler_erc20.cairo and ChakraSettlementHandler.sol lack such mechanism, and user's tokens can be locked in handler contracts or burnt permanently.

## Recommended Mitigation Steps
It is required to add a refund mechanism to the system for refunding users' tokens in case of a failure on the destination chain. Indeed, callback functions can check the status of the cross chain message coming from the destination chain, and unlock users' tokens if CrossChainMsgStatus::FAILED. It is worth noting that this issue exists for both handlers handler_erc20.cairo and ChakraSettlementHandler.sol, and the refund mechanism needs to be incorporated into each of them independently.
