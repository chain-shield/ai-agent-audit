# Vulnerability details

## Impact
The absence of protection against signature replay attacks within the multi-signature verification process poses a significant security risk. Signature replay occurs when a previously used valid signature is reused in a different context or at a different time to authorize unauthorized actions. In this contract, validators' signatures may be reused maliciously without detection, potentially allowing an attacker to fraudulently bypass the multi-signature requirements, leading to unauthorized transactions or contract behavior

## Proof of Concept
The `verifyECDSA` function verifies signatures for cross-chain settlement messages but does not include a mechanism to prevent previously valid signatures from being reused in future transactions:
 ```solidity
function verifyECDSA( 
        bytes32 msgHash,
        bytes calldata signatures 
    ) internal view returns (bool) { 
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators 
            ) {
                return true;
            }
        }

        return false;
    }
 ```
 Vulnerability Scenario:
Transaction A: A validator signs a legitimate transaction with msgHash_A. This signature is considered valid, and the transaction is processed successfully.
Transaction B: An attacker reuses the validator’s valid signature from Transaction A for a new malicious transaction with msgHash_B. Since the contract does not check for the uniqueness of the signature in the context of the new transaction, this old signature is accepted, allowing the attacker to fraudulently authorize Transaction B.
Without ensuring that each signature is tied to a specific message or time window, the validator’s signature from any prior transaction can be reused, compromising the integrity of the system.

## Recommended Mitigation Steps
To mitigate signature replay attacks, introduce a mechanism that ensures signatures are bound to specific transactions and cannot be reused. This can be achieved through various methods, such as including a nonce or timestamp within the signed data to ensure that each signature is valid only for one unique transaction.
