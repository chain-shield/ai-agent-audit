# Vulnerability details

## Impact
One of the invariants about the Settlement Handler Contract in the README of the audit states that: 

`Cross-chain transaction statuses are properly tracked and updated (Pending, Settled, or Failed).`

The problem is that in the `ChakraSettlementHandler::receive_cross_chain_callback()` this is not handled in the case where the function just returns false because it is coming from an invalid handler. The tx status in `create_cross_txs` remains `Pending` and this breaks the invariant


## Proof of Concept
This is where the problem occurs

```solidity

  function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        CrossChainMsgStatus status,
        uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
        bytes calldata /* signatures */
    ) external onlySettlement returns (bool) {
        //  from_handler need in whitelist
>>       if (is_valid_handler(from_chain, from_handler) == false) {           
>>          return false;
        }

        require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending,
            "invalid CrossChainTxStatus"
        );

        ...
    }


```

If the `from_handler` is not valid this means that this tx came from invalid handler and the transaction status should be set to `Failed` following the invariant listed by the protocol team

## Recommended Mitigation Steps

Set the tx status to Failed when it is coming from invalid handler to follow the invariant
