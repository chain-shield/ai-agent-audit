# Vulnerability details

## Impact

The main task of the settlement handler is to construct a message and then transfer it to the settlement contract for emitting an event for Chakra network to call `receive_cross_chain_msg()` on the destination chain. The problem is that the current version of `send_cross_chain_msg()` in the settlement misses `msg.sender` parameter when it's called from the handler and this can lead to some serious issues. 

## Proof of Concept

The current implementation of `send_cross_chain_msg()` call:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L216
```
 settlement.send_cross_chain_msg(to_chain, to_handler, PayloadType::ERC20, encode_message(message));
```

In the settlement contract `from_address` is used in the event emission:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L303
```
 from_address: get_tx_info().unbox().account_contract_address,
```

So it's set as the address that initiated the tx (tx.origin). The problem is that the caller was a smart contract, it'd incorrectly reflect this `from_address`. Take a look at the Solidity implementation:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L203-209
```
 settlement.send_cross_chain_msg(
                to_chain,
                msg.sender,
                to_handler,
                PayloadType.ERC20,
                cross_chain_msg_bytes
            );
```

So it uses `msg.sender` parameter as `from_address`. As the receive function on the destination chain is called by the Chakra network validators, they would use the info from the event emitted. And, as this address is incorrect, `from_address` would be also incorrect on the destination chain (for example, on Ethereum):

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L299-311
```
 self
                .emit(
                    CrossChainMsg {
                        cross_chain_settlement_id: cross_chain_settlement_id,
                        from_address: get_tx_info().unbox().account_contract_address,
                        from_chain: from_chain,
                        to_chain: to_chain,
                        from_handler: from_handler,
                        to_handler: to_handler,
                        payload_type: payload_type,
                        payload: payload
                    }
                );
```

## Tools Used

Manual review.

## Recommended Mitigation Steps

Add additional parameter to the `send_cross_chain_msg()` and use this parameter when emitting `CrossChainMsg` event.
