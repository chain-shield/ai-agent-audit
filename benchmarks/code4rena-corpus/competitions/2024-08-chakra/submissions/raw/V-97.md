# Vulnerability details

## Impact
When verifying `verifyECDSA()`, the logic verifies each of the signatures passed and returns true only if the minimum number signatures required are met.

The vulnerability arises from the fact that owner of the `SettlementSignatureVerifier` contract can reconfigure the minimum number of signatures. As there is no restriction on the minimum number, the owner of the `SettlementSignatureVerifier`  contract could potentially set the minimum number to 0 posing a risk to the bridge.
  
Similar issues exists on settlement side as well.

## Proof of Concept
The owner of the contract can set the required validators count to any number at his discretion. Setting the number to 0 would mean, there is no need for approval from validators which is risky.
```
   function set_required_validators_num(
        uint256 _required_validators
    ) external virtual onlyRole(MANAGER_ROLE) {
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```

The below `verifyECDSA()` will pass through if even one valid signature is found.The verifyECDSA should also enforce a minimum validators, hence 0 should not be allowed to be set for `required_validators`. 

```
function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```

## Tools Used
Manual review

## Recommended Mitigation Steps
The required validators shoud have a minimum value of say 2 as an example. The owner should not be allowed to set `required_validators` below 2.

This will ensure that verification will succeed if `required_validators` is met.
