# Vulnerability details

## Vulnerability Details
In the solidity side of the contracts the `cross_chain_erc20_settlement()` function in the `ChakraSettlementHandler` contract and the `send_cross_chain_msg()` function in the `ChakraSettlement` contract make use of tracking the nonce of the user to prevent signature replay attacks by using it to create a unique `tx_id`. 

```solidity
        nonce_manager[from_address] += 1;
```

The problem here is that in the cairo side of the smart contracts, the protocol does not attempt to keep track of the user's nonce, it instead only keeps track of the transaction count.

## Impact
Users will be vulnerable to signature replay attacks on other EVM chains but not on Starknet blockchain.

By not tracking the nonce of a user and only tracking the `tx_count` or `msg_count`, when the user is performing a cross-chain message they are only protected from replay attacks in the Starknet blockchain, but they will be easily vulnerable to signature attacks on other EVM chains where their nonce has not been incremented so attackers can and will take advantage of this.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add this line in the `send_cross_chain_msg` and the `cross_chain_erc20_settlement` functions of the cairo contracts before creating the `tx_id`. Then also incorporate the nonce into the `tx_id` like you did in the solidity version of the contracts.

```diff
+ nonces.write(caller_address, value=nonce+1)
```
