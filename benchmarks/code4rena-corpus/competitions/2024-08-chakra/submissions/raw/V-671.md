# Vulnerability details

## Impact

Protocol assume `from_handler` will be fit in `felt252`, this may cause unintended behaviors, i.e `from_handler` higher than `felt252` this may cause overflow and signature verification failure

## Proof of Concept

The value of `from_handler` is obtained from the `msg.sender` address which is then wrapped to `uint256`. 

```solidity
 address from_handler = msg.sender;

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    contract_chain_name, // from chain
                    to_chain,
                    from_address, // msg.sender address
                    from_handler, // settlement handler address
                    to_handler,
                    nonce_manager[from_address]
                )
            )
        );
```

Then in the `receive_cross_chain_msg` function in `settlement.cairo` contract, to validate the signature, the `message_hash` is constructed in the form of `felt252` which contains the `from_handler`. 

```solidity
let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
```

`from_handler` value potentially higher than `felt252` , which can have an impact overflow and signature verification failure

## Tools Used

Manual review

## Recommended Mitigation Steps

Add check to ensure `from_handler` is indeed a `felt252`

```solidity
let from_handlerFet = u256_to_contract_address(from_handler);

let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handlerFet, to_handler));
```
