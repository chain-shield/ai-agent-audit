# Vulnerability details

## Impact
The lack of proper `upgradeability` setup introduces operational risks, as the contract may not behave as expected during upgrade attempts, leading to potential downtime or service disruptions.

## Proof of Concept
The `TokenRoles` contract [inherits from `UUPSUpgradeable`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/TokenRoles.sol#L10), a contract from `OpenZeppelin` that provides `upgradeability` features.
```solidity
    abstract contract TokenRoles is
        OwnableUpgradeable,
>>      UUPSUpgradeable,
        AccessControlUpgradeable
    {
```
This standard requires certain initialization steps to be performed to ensure the contract is properly set up for upgrades.

However during initialization, the `__UUPSUpgradeable_init()` function is not called within the [`__TokenRoles_init()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/TokenRoles.sol#L19-L23) function.
```solidity
    function __TokenRoles_init(address _owner, address _operator) public {
        __Ownable_init(_owner);
        _grantRole(DEFAULT_ADMIN_ROLE, _owner);
        _grantRole(OPERATOR_ROLE, _operator);
    }
```
This omission leaves the upgrade mechanism improperly configured.

Since [`ChakraToken` contract inherits from `TokenRoles`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraToken.sol#L14), this contract will not be upgreadable:
---> The `UUPSUpgradeable` contract relies on an internal function [`_authorizeUpgrade()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraToken.sol#L42-L44) in `ChakraToken` contract to control who can upgrade the contract. Without proper initialization, the upgrade authorization mechanism may not function as intended, potentially preventing upgrades.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Ensure that the `__UUPSUpgradeable_init()` function is called during initialization
```diff
    function __TokenRoles_init(address _owner, address _operator) public {
        __Ownable_init(_owner);
        _grantRole(DEFAULT_ADMIN_ROLE, _owner);
        _grantRole(OPERATOR_ROLE, _operator);
+       __UUPSUpgradeable_init();
    }
```
