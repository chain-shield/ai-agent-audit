# Vulnerability details


## Impact

The `Chakra` system uses a multi-validator security model, only signed messages by a threshold of validators is valid (`required_validators` in code). There should be at least 2 non-colluding validators for such system to work. However, the current implementation is vulnerable to a single malicious validator reusing his own signature `required_validators` times or more to validate any message (e.g, validate a user asset to himself).

### Vulnerability Details

Let's see the relevant code, `ChakraSettlement::receive_cross_chain_msg()` is responsible for receiving a message from another chain:

The `m` counter increases each time a `msgHash.recover(sig)` (which corresponds to a public key) matches an existing validator. However, there's no mechanism to verify if the same validator's public key has been used more than once in the provided signatures.

This means that if a validator's `sig` appears multiple times in the `signatures` array, each occurrence will be counted as a separate validation. Therefore, "a single malicious validator reuses his own signature `required_validators` times or more to validate any message".

## Proof of Concept

Let's take a simple scenario to understand this issue:

- `required_validators` is 10.
- A malicious validator signs a message off-chain, regardless of whether other validators have signed it or not.
- The malicious validator calls `receive_cross_chain_msg`, with `signatures` array of his own signature repeated `required_validators` times (i.e, 10 times) or more.
- Since the signature is valid (he is a validator) and there are enough signatures (`>= required_validators`), the message is considered valid.

## Recommended Mitigation Steps

The fix is straightforward, add a check to ensure that the same validator's signature is not used more than once.
