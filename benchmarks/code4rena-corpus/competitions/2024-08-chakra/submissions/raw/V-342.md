# Vulnerability details

## Impact
The bug will cause the cross-chain callback to fail when the `chain_name` is changed at source after a cross-chain tx has been sent.

## Proof of Concept
When initiating a cross chain ERC20 settlement, the  [`from_chain` is given as follows](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L170):
```solidity
    let from_chain = settlement.chain_name();
```
This is then [saved for the transaction](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L186) as follows:
```solidity
            let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
>>                  from_chain: from_chain,
                    ---SNIP---
                };
>>          self.created_tx.write(tx_id, tx);
```

Also, the protocol has [`set_chain_name()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L472-L475) function used to change this `chain_name`:
```solidity
        fn set_chain_name(ref self: ContractState, chain_name: felt252){
            self.ownable.assert_only_owner();
            self.chain_name.write(chain_name);
        }
```

The issue then arises during cross chain callback:

- `receive_cross_chain_callback()`:
This function handles callbacks for cross-chain transactions that were initiated from this contract and are now responding back after processing on another chain.

It performs the following [check](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L405):
```solidity
    assert(self.created_tx.read(cross_chain_msg_id).from_chain == to_chain, 'from_chain error');
```
From this, the function will revert:

**Scenario**:
1. When initiating a cross-chain `tx1` the following parameters are used:
- `from_chain`: `chainA`
- `to_chain`: `chainD`
2. After this tx is sent, the owner calls `set_chain_name()` at source and changes the `chain_name` from  `chainA` to  `chainB`.
3. After processing `tx1` on `chainD` a callback is to be received at source chain (`chainB`), previously `chainA`.
4. Due to the checks above, `to_chain`(`chainB`) is supposed to be the same as `from_chain` that was saved for `tx1` during initialization (`chainA`) but this is not the case.
5. The `chain_name` has changed and as such, the callback will fail with `'from_chain error'`.

Manual Review

## Recommended Mitigation Steps
This is tough one.
1. Delete the `set_chain_name()` entirely and only rely on its [initialization in the `constructor()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L165)
2. Impelement another way to validate authenticity of these callback messages
