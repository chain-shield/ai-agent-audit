# Vulnerability details

## Impact
Signatures can be reused, allowing users to withdraw funds repeatedly.

## Proof of Concept
background:
1. When cross-chain, chain A sends an event to indicate a cross-chain request, and then executes the receive_cross_chain_msg function on chain B to withdraw the user's cross-chain funds.
2. The [correct signature is required when executing the receive_cross_chain_msg function](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/settlement.cairo#L339-L350).
```cairo
            // verify signatures
            let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
            let payload_span = payload.span();
            let mut i = 0;
            loop {
                if i > payload_span.len()-1{
                    break;
                }
                message_hash = LegacyHash::hash(message_hash, * payload_span.at(i));
                i += 1;
            };
            self.check_chakra_signatures(message_hash, signatures);

        fn check_chakra_signatures(
            self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
        ){
            let mut pass_count = 0;
            let mut i = 0;
            loop {
                if i > signatures.len()-1{
                    break;
                }
                let (r,s,y) = * signatures.at(i);
                let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
                if self.chakra_validators_pubkey.read(pub_key) > 0{
                    pass_count += 1;
                }
                i += 1;
            };
            assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
        }
    }
```
3. The nonce is not used in the signature, and the cross-chain status of this cross-chain transaction is not verified on chain B. So the signature can be reused.


In summary, after the user successfully cross-chain, he can continue to use the same signature to withdraw money from chain B until the corresponding handler is empty.

## Tools Used
manual

## Recommended Mitigation Steps
It is recommended to use a nonce for signatures, or verify whether each transaction has been withdrawn, and do not allow repeated withdrawals.
