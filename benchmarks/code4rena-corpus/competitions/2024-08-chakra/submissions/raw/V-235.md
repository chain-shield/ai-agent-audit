# Vulnerability details

## Impact
The ckrBTC decimals on Starknet is 18 and the ckrBTC decimals on other evm compatible chains is 8. The inconsistent decimals of ckrBTC lead to wrong received amount when bridging between chains with different ckrBTC decimals.

## Proof of Concept
ChakraTokenTest.ts file shows:
```
  const name: string = "ChakraToken";
  const symbol: string = "ckrBTC";
  const decimals = 8;
```
Sponsors also confirm ckrBTC decimals is 8 on evm compatible chains.
The cairo code of ckrBTC uses [openzeppelin erc20 template](https://github.com/OpenZeppelin/cairo-contracts/blob/8e660c7b91641afee967a7ed86dd2061d471a861/src/token/erc20/erc20.cairo#L188-L190).
```
        fn decimals(self: @ComponentState<TContractState>) -> u8 {
            18
        }
```
In the openzeppelin erc20 template, the decimals is set to 18.
Let's see what will happen when bridging ckrBTC tokens between chains with different ckrBTC decimals:
Send from Starknet: amount = 1e18, decimals = 18, value = 1 ckrBTC;
Receive on evm compatible chains: amount = 1e18, decimals = 8, value = 1e10 ckrBTC.

## Tools Used
manual

## Recommended Mitigation Steps
Change the ckrBTC decimals on Starknet to 8.
