# Vulnerability details

## Impact
The resultant `message_hash` may be incorrect since the values used to calculate it may be invalid. Depending on the use case of this value, if applied, it may result in potential issues.

## Proof of Concept
One of the Main Invariants is this:
> The handler receiving a cross-chain message must be on the whitelist for the source chain.

This is validated in both [`receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L114-L115) and [`receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L144-L145).

However, [`message_hash_receive()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L444-L456) and [`message_hash_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L458-L462) used to calculate the `message_hash` for the received cross-chain tx and callback tx do not perform any validations on the given handlers and chains:
```solidity
        fn message_hash_receive(self: @ContractState, cross_chain_msg_id: u256, from_chain: felt252, to_chain: felt252, from_handler: u256, to_handler: ContractAddress, payload: Array<u8>) -> felt252{ 
            //@audit Missing validations
            let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
            let payload_span = payload.span();
            let mut i = 0;
            loop {
                if i > payload_span.len()-1{
                    break;
                }
                message_hash = LegacyHash::hash(message_hash, * payload_span.at(i));
                i += 1;
            };
            return message_hash;
        }

        fn message_hash_callback(self: @ContractState, cross_chain_msg_id: felt252, from_chain: felt252, to_chain: felt252,from_handler: u256, to_handler: ContractAddress, cross_chain_msg_status: u8) -> felt252{ 
            //@audit Missing validations
            let mut message_hash_temp: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
            let message_hash:felt252 = LegacyHash::hash(message_hash_temp, cross_chain_msg_status);
            return message_hash;
        }
```
Since these functions are not called within other functions that perform these checks prior, there is a chance that the given parameters may not be valid. But as seen, the functions will proceed to use these values as given to generate `message_hash`.

As such, the resultant `message_hash` may be incorrect. Depending on the use case of this value, if applied, it may result in potential issues.
