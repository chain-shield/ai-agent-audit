# Vulnerability details

## Impact
User Tokens are locked inside contract on source chain if the message fails on destination chain for some reason ( for example: sequencer is down ).

Note: The same issue exist in the cairo contracts, i did not want to write a separate report for it so i will instead embed problematic cairo code also here.

## Proof of Concept
When a message is sent from source chain in mintBurn mode to destination chain, after processing on destination chain, validators calls `receive_cross_chain_callback()` on settlement contract on source chain.
In the solidity contract, what receive_cross_chain_callback() does is check if the message status succeeded, if yes and the settlement mode is mintBurn it burns the tokens on source chain.
However if the message status is `FAILED` only the crossChain transaction status is updated to be `FAILED` but user tokens are not refunded to him, instead they are locked inside the contract on source chain.

Tokens stuck scenario:
- Bob call cross_chain_erc20_settlement() on source chain
- Settlement mode is mintBurn ( Tokens are first locked on source chain, minted on detsination Chain then burned on source chain when the callback message status is SUCCESS).
- Bob tokens are locked on source chain, validators forward the msg to destination chain, The detsination chain receive the message, then something unexpected happens on destination chain ( for example the sequencer could go down )
- The message fails on detsination chain so validators forwards the callback to source chain
- Upon receiving the callback transaction, the source chain contract check the msg status, when it is `SUCCESS` they burn the tokens on source chain and when it is `FAILED` nothing is done to refund locked tokens on source chain to bob. See [code](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L391-L393)
```solidity
if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {

        if (status == CrossChainMsgStatus.Failed) {

        }
```

## Recommended Mitigation Steps
Unlock the tokens on source chain if the received callBack message status in mintBurn mode is FAILED. That way user tokens won't get stuck on source chain.
