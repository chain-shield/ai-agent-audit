# Vulnerability details

## Impact

Break the main invariants 

> **The contract can only be initialized once due to the use of the** `initializer` **modifier**
> 

and the implementation contract can be takeover 

## Proof of Concept

Most of the upgradeable contracts that do not have a `disableinitializers()` function in their constructors :

1. `ChakraSettlement.sol` is a `UUPSUpgradeable` implementation contract that inherits from the `BaseSettlement.sol` contract
2. `ChakraSettlementHandler.sol` is a `UUPSUpgradeable` implementation contract that inherits from the `BaseSettlementHandler.sol` contract
3. `SettlementSignatureVerifier.sol` in both `settlement` and `handler` part
4. `ChakraToken.sol` in `handler` part
5. `ERC20CodecV1.sol` in `handler` part

This can cause implementation contracts to be initiated more than once (break the main invariants) and can also potentially be taken over by malicious actors.

## Tools Used

Manual review

## Recommended Mitigation Steps

Consider call `disableinitializers()` in constructor

```solidity
constructor() {
    _disableInitializers();
}
```
