# Vulnerability details

## Summary
In settlement.cairo, the  functions end_cross_chain_msg() should only be called by the whitelisted handlers. but lack of check in this function will allow an attacker to call this function with custom payload. By taking this as advantage attackers will call this function with the custom payload to mint unlimited tokens in the destination chain

## Impact
Due to this bug, an attacker can directly call send_cross_chain_msg with custom payload and he can able to mint unlimited tokens on the destination chain

## Proof of Concept
In settlement.cairo
[https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L284](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L284)

An attacker can directly call send_cross_chain_msg without transferring tokens and can emit event CrossChainMsg. The validator will pick up the event and will mint tokens on the destination chain

1) The attacker will directly call send_cross_chain_msg() to mint large amount of tokens on the destination chain with custom payload without transferring actual tokens and `CrossChainMsg` event will get emitted.
2) The validator will pick up that event and call receive_cross_chain_msg() on the destination chain with the required parameters and will mint tokens to the users.
3) so the user successfully got tokens on the destination chain without depositing on the source chain will lead to increase in token supply which will break the main invariant of the protocol.

## Tools Used
Manual Inspection

## Recommended Mitigation Steps
Add necessary checks in the function `send_cross_chain_msg()` in `settlement.cairo` so that only valid handlers will able to call that function
