# Vulnerability details

## Impact
Tokens can be stolen from the protocol by any user because of this vulnerability. A valid cross chain message sent to Starknet which mints or unlocks tokens can be replayed an unlimited number of times, thus allowing an attacker to potentially empty the handler contract of all assets or mint an unlimited number of Chakra bridged ERC20 tokens.

Other handlers that rely on `ChakraSettlement` to only call them once per `cross_chain_msg_id` would also be exploitable.

Also, as the events are emitted multiple times, it is possible that off chain systems and bridges that monitor this event could also be exploited.

## Proof of Concept
The functions `ChakraSettlement.receive_cross_chain_msg()` do not perform a check on the existing status of `self.received_tx` for the received `cross_chain_msg_id`.

The functions verify signatures, but then go on to call handlers and emit the event and return `true`. It would therefore be possible for any address to resubmit a valid received cross chain message and have it processed multiple times.

Within `ERC20HandlerImpl`, its function `receive_cross_chain_msg` would be called by the `settlement` contract on this line:
```
let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);
```
The code of `ERC20HandlerImpl.receive_cross_chain_msg()` validates its input by testing to see if the settlement and handler contracts are valid. It does not check that the `cross_chain_msg_id` has not been seen before, and will therefore proceed to mint/transfer tokens repeatedly for the same message.

## Tools Used
Manual inspection

## Recommended Mitigation Steps
In `ChakraSettlement.receive_cross_chain_msg()` perform a check on the existing status of `self.received_tx` for the received `cross_chain_msg_id` and do not process the message if it has already been received.

It may also be recommended to check `cross_chain_msg_id` in `ERC20Handler.receive_cross_chain_msg()` and any other handlers, although this is an additional layer of security and should not be necessary if `ChakraSettlement` is performing the check.
