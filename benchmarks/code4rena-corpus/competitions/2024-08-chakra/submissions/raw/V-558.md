# Vulnerability details

## Impact
The function `cross_chain_erc20_settlement` allows users to specify the `to_chain` and `to_token`, but there is no validation to ensure that the `to_token` matches the `token` in the current handler. This oversight enables users to specify arbitrary tokens for the cross-chain transfer, potentially leading to unlimited or unrestricted bridging operations. 
## Proof of Concept
The `cross_chain_erc20_settlement` function accepts `to_chain` and `to_token` as inputs:

```solidity
    function cross_chain_erc20_settlement(
        string memory to_chain,
        uint256 to_handler,
        uint256 to_token,
        uint256 to,
        uint256 amount
    ) external {
		...
	}
```

Since there is no validation for `to_token`, a user can specify any token they want, leading to incorrect bridging operations. If the token is already burnt or locked, it cannot be retrieved again, causing irreversible losses.

## Tools Used
Manual

## Recommended Mitigation Steps
Add proper validation to ensure that the `to_token` refers to the correct token associated with the current handler.
