# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Unchecked mint_to return value used in the external call  receive_cross_chain_msg function from the internal call _erc20_mint function.

Title: ChakraSettlementHandler has Unchecked mint_to Return Value in External Call from _erc20_mint function.
Contract: ChakraSettlementHandler.sol.
Functions: _erc20_mint() & receive_cross_chain_msg().
Issue Type: Unchecked External Call Return Value.

The _erc20_mint function internally calls IERC20Mint(token).mint_to(account, amount). However, the return value of this external call is not checked. According to best practices, external calls can fail for various reasons, including gas issues, contract bugs, or malicious implementations. If the minting fails but the return value is not checked, the system will assume the mint operation succeeded, potentially leading to incorrect cross-chain settlement states, where tokens are thought to be minted but were not. This could result in under-collateralization or loss of user funds in cross-chain transactions.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

Consider a scenario where the mint_to function in the mintable ERC20 token fails due to a bug or other issue. Since the return value is not checked, the system will proceed as if tokens were minted successfully:
```sol
contract FaultyMintableToken {
    mapping(address => uint256) public balances;
    
    function mint_to(address account, uint256 amount) external returns (bool) {
        // Fails silently by returning false instead of minting tokens
        return false;
    }
}
```
In this scenario, the receive_cross_chain_msg function calls _erc20_mint, and even though the mint_to call fails, the contract does not revert or handle the failure, which may result in settlement processes assuming that the minting was successful:
```sol
function _erc20_mint(address account, uint256 amount) internal {
    IERC20Mint(token).mint_to(account, amount);  // Return value not checked
}

// Inside the receive_cross_chain_msg function
if (mode == SettlementMode.MintBurn) {
    _erc20_mint(AddressCast.to_address(transfer_payload.to), transfer_payload.amount);
    return true;  // Assumes mint succeeded, even if it failed
}
```
In this case, tokens are not actually minted, but the system assumes they were, leading to an incorrect settlement state.

## Recommended Mitigation Steps

To prevent this issue, the return value of the mint_to function should be checked. 

Also, add a requirement that the balance has enough to mint the stated amount.

If the minting fails (i.e., the return value is false), the transaction should revert to prevent further incorrect state changes. Here’s the mitigated code:
```sol
function _erc20_mint(address account, uint256 amount) internal {
    require(
        IERC20(token).balanceOf(account) >= amount,
        "Insufficient balance"
    );
    bool success = IERC20Mint(token).mint_to(account, amount);
    require(success, "Token minting failed");
}
```
In the receive_cross_chain_msg function, the _erc20_mint call will now ensure that minting only proceeds if the mint_to function successfully mints the tokens. If the minting fails, the transaction will revert, preventing incorrect settlements or potential loss of user funds.
