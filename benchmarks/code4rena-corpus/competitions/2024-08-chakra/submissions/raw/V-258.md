# Vulnerability details

## Impact
The manager role in the ckr_btc.cairo contract has significant control over Bitcoin liquidity operations. Weak access control could allow unauthorized users to assume this role, leading to potential control over Bitcoin staking, withdrawing, or adding/removing managers. This could cause serious security risks and financial losses.

## Proof of Concept
If the add_manager and remove_manager functions are not protected by strict access controls, malicious actors could gain the ability to alter the list of managers, gaining control over key Bitcoin operations.

Example: A malicious user who manages to become a "manager" could take control over the staking/unstaking process or drain funds by adding themselves as a manager and performing unauthorized withdrawals.

## Tools Used
1. Access Control Analysis: Using Slither to detect missing access control modifiers in manager-related functions.
2. Manual Code Review: Analyzing how managers are added/removed to ensure no loopholes exist in access control.
3. Static Analysis: Using MythX to identify governance-related vulnerabilities.

## Recommended Mitigation Steps
1. Implement role-based access control, where only specific authorized accounts can add or remove managers.
2. Introduce multi-signature validation for critical actions, such as adding or removing managers.
3. Conduct audits on governance logic to ensure access control functions are protected and cannot be bypassed.
