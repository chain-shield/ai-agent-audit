# Vulnerability details

The mode variable within the smart contract is initialized in the constructor and is immutable post-deployment. This design decision ensures that the mode cannot be altered after the contract has been deployed. However, this immutability introduces a potential risk that may lead to a Permanent Denial of Service (DoS) for certain functionalities within the contract.

Vulnerable Code 

```cairo
#[constructor]
fn constructor(ref self: ContractState, settlement_address: ContractAddress, owner: ContractAddress, token_address: ContractAddress, mode: u8) {
// ... other initializations ...
self.mode.write(mode);
}
```

Impact : HIGH

## Risks
1. **Permanent Denial of Service (DoS)**: Certain functionalities may become permanently unavailable if an incorrect mode is set.
2. **Inflexible Operations**: The contract is locked into a single operational mode (MintBurn, LockMint, BurnUnlock, or LockUnlock) for its entire lifetime.
3. **Irreversible Misconfiguration**: Any error in mode selection during deployment cannot be corrected post-deployment.

## Impact
HIGH: The immutable nature of the `mode` variable can lead to severe, irreversible consequences for contract functionality and adaptability.

## Recommendations
1. Implement an upgradable contract pattern to allow mode changes post-deployment.
2. Add a function for authorized mode changes with proper access controls.
3. Consider a more flexible design that doesn't rely on a single, immutable mode variable.
