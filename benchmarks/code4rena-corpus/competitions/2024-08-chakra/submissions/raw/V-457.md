# Vulnerability details

## Impact
The cross-chain messaging system in the Chakra protocol lacks proper validation for the destination handler (to_handler) throughout the message transmission path. This validation is missing in both the ChakraSettlement and ChakraSettlementHandler contracts. The only validation is for non-zero addresses at https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L120. The `receive_cross_chain_callback` does validate the response from the to_handler but that is after potential transfer on the destination chain. This issue is not present in cairo code which has appropriate check `assert(self.support_handler.read((to_chain, to_handler)), 'not support handler')` in cross_chain_erc20_settlement in handler_erc20.cairo

Due to this following multiple issues may occur.
a) Obsolete Handler Processing: If a handler has been recently removed or deprecated, requests may still be directed to it. This could lead to tokens being transferred from an inactive or compromised handler but keeping the transaction as pending, potentially resulting in loss of funds for the protocol.
b) Denial of Service: Users or other applications interacting with Chakra may not realise that a handler is or has become invalid. They may keep sending requests to a to_handler that would consistently revert, preventing legitimate cross-chain transfers and disrupting the protocol's operations.
c) Malicious Handler Exploitation: If Users are tricked into setting a malicious to_handler (e.g. by an intermediate app) that falsely reports successful transaction completion without actually processing the transfer. This could cause loss of funds as the transaction will remain pending.

## Proof of Concept
1. In ChakraSettlementHandler.sol, the `cross_chain_erc20_settlement` function initiates the cross-chain transfer without validating the to_handler.
2. The `send_cross_chain_msg `function in ChakraSettlement.sol forwards the message without checking the validity of the to_handler.
3. On the receiving side, `receive_cross_chain_msg` in ChakraSettlement.sol calls the to_handler without verifying its validity.

While the is_valid_handler function exists in ChakraSettlementHandler.sol, it is only used to validate the from_handler when receiving messages, not the to_handler when sending or processing them.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a validation check for the to_handler in the send_cross_chain_msg function.
