# Vulnerability details

## Impact
This report examines the data types used in the CrossChainLocked event and CreatedCrossChainTx struct in BaseSettlementHandler.sol
 Solidity contract, highlighting the invalid data.
There are critical issues with the usage of uint256 for fields that should be of type address. The fields to and to_token in both the event and struct definitions are incorrectly declared as uint256 when they represent addresses on the destination chain. This creates a scenario where the contract performs in an unexpected manner due to internal errors.

## Proof of Concept
CreatedCrossChainTx:
Invalid. The to field is intended to represent an address on the destination chain. Using uint256 for an address is incorrect and can lead to potential errors.
 Invalid. Similar to the to field, to_token should be of type address to represent a token contract address on the destination chain.
CrossChainLocked:
Invalid. The to field is supposed to represent an address on the destination chain. Using uint256 for this field is incorrect because it does not provide the type safety associated with the address type in Solidity.
Invalid. The to_token field is intended to store an address on the destination chain, similar to from_token. It should be of type address instead of uint256.

Manual analysis

## Recommended Mitigation Steps
Change uint256 to to address to in both the event and struct to ensure proper handling of Ethereum addresses.

Change uint256 to_token to address to_token in both the event and struct to maintain type safety and consistency.
