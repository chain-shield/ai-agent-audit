# Vulnerability details

## Impact
An attacker can maliciously modify the cross-chain status through front-running. The successful cross-chain can be modified to be unsuccessful, so [that the contract will not burn the locked tokens](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L383-L393). This affects the functionality of the contract. This is Med.
If the protocol performs manual refunds based on cross-chain status, it is possible to steal the funds in the protocol, which is High. So I judge this finding to be Med/High.

## Proof of Concept
background:
1. In a cross-chain transaction from chain A to chain B, if the protocol is successfully executed on chain B, an event will be emitted, and [chain A will be called from the off-chain to execute the callback](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L256).
2. Anyone can call the callback function as long as it has the correct signature.
3. The [from_chain variable is not included in the signature](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L293-L295), so anyone can monitor the memory pool to obtain the signature and use the wrong from_chain to preempt the transaction.
4. [Once from_chain is incorrect, false will be returned in the handler's callback function](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L374-L376). This bypasses [the _erc20_burn that would be executed normally](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L383-L388).
5. If the protocol performs manual refunds based on the cross-chain status, [using the incorrect from_chain will also mark the cross-chain that should have been Settled as Failed](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L317-L331). thereby fraudulently obtaining a refund.

In summary, since from_chain has no signature, the attacker only needs to modify the from_chain and steal the transaction to mark the originally successful cross-chain as Failed. Thereby bypassing _erc20_burn and possible refund fraud.

## Tools Used
manual
## Recommended Mitigation Steps
It is recommended to include from_chain in the signature as well.
