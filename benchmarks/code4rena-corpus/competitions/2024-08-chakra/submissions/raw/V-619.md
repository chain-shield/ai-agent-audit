# Vulnerability details

## Impact
The SettlementSignatureVerifier::verify() is being used to validate whether or not the msgHash are already being signed by validators, and continue the execution after the required_validators that signed the msgHash is satisfied https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/SettlementSignatureVerifier.sol#L134 , 

However, this function doesn't validate a duplicate signature, therefore, an attacker can give the same signature multiple times, to bypass the required_validators, or provide a different signature that resolve to the same address multiple times.

```
function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```

## Tools Used
Manual

## Recommended Mitigation Steps
Check every signature that being provided, and make sure there is no duplicate signature, and check its address, and make sure its not coming from the same validators.
