# Vulnerability details

## Impact
The `BaseSettlementHandler` contract has a [public _Settlement_handler_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/BaseSettlementHandler.sol#L113-L120) that initializes `owner`, `mode`, `token`, `verifier`, `chain` and `settlement`, with no access control. These are pretty much all the important state while taking control of the `owner` would be enough. The contracts `ChakraSettlementHandler` is [inheriting from](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L18) `BaseSettlementHandler`, so any user, without a need for any permission, can directly call `_Settlement_handler_init` passing their own address as `_owner` and take full control of this contract.  

## Proof of Concept
Call this and `ChakraSettlementHandler` will be pwned
```
ChakraSettlementHandler._Settlement_handler_init(your_address_as_owner, any_mode, any_token, any_verifier, any_chain, any_settlement)
```
having the control of owner, you can upgrade the contract and fix the issue so that no one else can take the control back from you.

Manual Review

## Recommended Mitigation Steps
The [_Settlement_handler_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/BaseSettlementHandler.sol#L113-L120) should be `internal` and also should include the `onlyInitializing` modifier, so that it can only be called as part of the [initialize function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L82-L90) (the function with `initializer` modifier).
