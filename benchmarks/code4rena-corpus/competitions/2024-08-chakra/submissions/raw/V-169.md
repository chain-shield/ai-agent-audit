# Vulnerability details

## Impact
In the ChakraSettlementHandler.sol smart contract, several require statements are used to verify the validity of certain parameters to ensure they are none zero addresses before proceeding with the function execution. However, the verification checks for to, to_handler, and to_token addresses are improperly conducted as if they were uint256 types rather than address types. This in the best case scenario leads to Dos if an address cannot be verified and worst case loss of fund being transferred to zero address.

## Proof of Concept
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L119-L121
The comparisons are made against 0, which is appropriate for uint256 types but not for address types. In Solidity, an address value is considered to be zero if it is equal to address(0) (0x0000000000000000000000000000000000000000).

Therefore, due to this oversight, the verification won't hold against any transfer made to zero due to ineffective check.

The standard solidity zero address check should be used.
