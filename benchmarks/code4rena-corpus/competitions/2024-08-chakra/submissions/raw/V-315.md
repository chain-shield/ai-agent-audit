# Vulnerability details



## Summary

The Chakra protocol currently lacks a critical feature: the ability to cancel cross-chain messages in scenarios where token transfers become stuck. This oversight poses a significant risk to user assets and the protocol's reliability in cross-chain operations.

## Impact

The absence of a message cancellation mechanism has severe consequences:

1. Permanent Asset Loss: Users risk losing their tokens indefinitely if cross-chain transactions fail or become stuck.
2. Reduced Protocol Trust: The inability to recover from failed transactions may erode user confidence in the Chakra protocol.
3. Ecosystem Inefficiency: Locked tokens represent inactive capital, reducing overall liquidity across connected chains.

## Proof of Concept

Consider the following scenario:

1. Alice initiates a cross-chain ERC20 settlement by calling `cross_chain_erc20_settlement` on Chain A.
2. The `ChakraSettlementHandler` on Chain A locks or burns Alice's tokens based on the settlement mode.
3. A cross-chain message is sent to Chain B to complete the transaction.
4. Due to unforeseen circumstances (e.g., network issues, contract errors on Chain B), the cross-chain message transaction fails on Chain B.
5. The `receive_cross_chain_callback` function on Chain A is never successfully called, or it's called with a failed status.
6. Alice's tokens remain locked in the `ChakraSettlementHandler` contract on Chain A, with no built-in mechanism to cancel the transaction or withdraw her tokens.

Relevant code snippet from `ChakraSettlementHandler`:

```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ... (token locking or burning logic)
    
    // Create and send cross-chain message
    settlement.send_cross_chain_msg(
        to_chain,
        msg.sender,
        to_handler,
        PayloadType.ERC20,
        cross_chain_msg_bytes
    );
    
    // No cancellation or reversal mechanism
}
```

Implement a Time-Based Cancellation Mechanism.
