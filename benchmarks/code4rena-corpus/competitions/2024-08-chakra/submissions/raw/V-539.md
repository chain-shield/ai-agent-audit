# Vulnerability details

## Impact
The current implementation lacks a direct mechanism to enforce consistent settlement modes across different chains. While an indirect method exists through the use of is_valid_handler, this approach is weak and error-prone. Each ChakraSettlementHandler operates based on its locally set mode, without verifying the compatibility of modes between the source and destination chains. This absence of direct enforcement can lead to severe inconsistencies in token economics across chains. If handlers with incompatible modes interact, it could result in unintended token minting, burning, locking, or unlocking. Consequently, this could lead to inflation, deflation, or permanent loss of user funds.

## Proof of Concept
Settlement mode is set locally for each handler without cross-chain verification:
```solidity
function initialize(
    address _owner,
    SettlementMode _mode,
    // ... other parameters
) public initializer {
    // ...
    mode = _mode;
    // ...
}
```
The cross_chain_erc20_settlement function uses only the local mode:
```solidity
if (mode == SettlementMode.MintBurn) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockUnlock) {
    _erc20_lock(msg.sender, address(this), amount);
} // ... other modes
```
The receive_cross_chain_msg function also uses only the local mode:
```solidity
if (mode == SettlementMode.MintBurn) {
    _erc20_mint(
        AddressCast.to_address(transfer_payload.to),
        transfer_payload.amount
    );
    return true;
} // ... other modes
```
The weak indirect method relies solely on is_valid_handler, which explicitly seems to check whitelist status, not mode compatibility:
```solidity
function is_valid_handler(
    string memory chain_name,
    uint256 handler
) public view returns (bool) {
    return handler_whitelist[chain_name][handler];
}
```
This indirect method is error-prone because:

1. It relies on off-chain processes to ensure only compatible handlers are whitelisted.
2. There's no on-chain verification of mode compatibility.
3. It's vulnerable to human error in whitelist management.
4. It lacks transparency, as the settlement mode isn't visible through this function.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a direct mechanism to enforce settlement mode consistency, specially since validator is aware of other chain validators as a mapping.
