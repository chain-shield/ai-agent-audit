# Vulnerability details

## Impact
Reusing a valid signature may result in funds being diverted

SettlementSignatureVerifier contract.In the verifyECDSA method, the signature verification process does not check for the uniqueness of each signature. Since validators[msgHash.recover(sig)] only checks whether the recovered signer is a validator, an attacker could reuse the same signature multiple times to meet the required required_validators threshold. This could allow an attacker to pass the multi-signature verification with fewer distinct validators than required, potentially leading to the unauthorized transfer of all funds in the contract or misuse of contract functionality.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L193

In the following code:

```

for (uint256 i = 0; i < len; i += 65) {
    bytes memory sig = signatures[i:i + 65];
    if (validators[msgHash.recover(sig)] && ++m >= required_validators) {
        return true;
    }
}
```

The code loops through signatures and uses `msgHash.recover(sig)` to extract the signer. It checks if the recovered signer is a validator, but does not ensure that each signature comes from a different validator. This allows an attacker to reuse a single validator's signature multiple times to satisfy the verification requirements.

## Recommended Mitigation Steps

Add a uniqueness check for signatures in the `verifyECDSA` method. This can be done by tracking validated signers to ensure each signature comes from a distinct validator.

Use a `mapping` or array to store the signers already verified in the current verification process to prevent signature reuse.
