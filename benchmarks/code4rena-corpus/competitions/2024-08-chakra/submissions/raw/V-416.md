# Vulnerability details


## Summary

The `send_cross_chain_msg` function in `ChakraSettlement.sol` allows users to initiate cross-chain transactions without paying for gas fees on the destination chain. This oversight can lead to economic imbalances, potential Denial of Service (DoS) attacks, and unfair resource consumption across different blockchains in the Chakra network.

## Impact

The `send_cross_chain_msg` function in `ChakraSettlement.sol` allows users to initiate cross-chain transactions without paying for gas fees on the destination chain. This can lead to several significant issues:

1. Economic imbalance: Users can flood the destination chain with transactions without bearing the associated costs, potentially leading to network congestion and increased gas prices for legitimate users on that chain.

2. Denial of Service (DoS) vulnerability: Malicious actors could exploit this to overwhelm the destination chain with a large number of cross-chain messages, causing performance degradation or even halting the network.

3. Misaligned incentives: The lack of gas fees on the destination chain removes an important economic deterrent against spam and abuse, potentially compromising the security and efficiency of the cross-chain communication mechanism.

4. Unfair resource consumption: Users on the destination chain may end up subsidizing the execution costs of cross-chain messages, leading to an unfair distribution of network resources.

## Proof of Concept

The issue can be observed in the: [`send_cross_chain_msg` function of ChakraSettlement.sol](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L111-L156).


```solidity
function send_cross_chain_msg(
    string memory to_chain,
    address from_address,
    uint256 to_handler,
    PayloadType payload_type,
    bytes calldata payload
) external {
    nonce_manager[from_address] += 1;

    address from_handler = msg.sender;

    uint256 txid = uint256(
        keccak256(
            abi.encodePacked(
                contract_chain_name, // from chain
                to_chain,
                from_address, // msg.sender address
                from_handler, // settlement handler address
                to_handler,
                nonce_manager[from_address]
            )
        )
    );

    create_cross_txs[txid] = CreatedCrossChainTx(
        txid,
        contract_chain_name,
        to_chain,
        from_address,
        from_handler,
        to_handler,
        payload,
        CrossChainMsgStatus.Pending
    );

    emit CrossChainMsg(
        txid,
        from_address,
        contract_chain_name,
        to_chain,
        from_handler,
        to_handler,
        payload_type,
        payload
    );
}
```

As we can see, this function allows a user to send a cross-chain message without any mechanism to collect or reserve gas fees for the destination chain. The transaction is created and emitted without any consideration for the execution costs on the receiving end.

## Recommended Mitigation Steps

To address this issue, consider implementing the following measures:

1. Gas fee estimation and collection: Implement a mechanism to estimate the gas cost on the destination chain and collect it from the user initiating the cross-chain transaction. This could be done by maintaining an oracle that provides gas price information for supported chains.

2. Deposit system: Require users to deposit funds in a contract on the destination chain before they can send cross-chain messages. These funds would be used to cover gas costs for incoming messages.
