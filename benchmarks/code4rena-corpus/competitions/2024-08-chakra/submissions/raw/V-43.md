# Vulnerability details


## Summary
The `handler_erc20.cairo` contract sets the `token_address` in its constructor, which is used in various functions throughout the contract. Since StarkNet's upgrade mechanism only replaces the class without invoking the constructor, it does not provide a way to update `token_address` during an upgrade. This design limitation poses a potential issue if `token_address` needs to be updated after deployment.

## Impact
- Since `replace_class_syscall` does not run a constructor, updating storage variables directly in an upgrade process is not feasible, potentially leading to disruptions in contract functionality.

- **Operational Flexibility:** If the `token_address` needs to be changed due to a token upgrade, change in token standards, or any other reason, the current contract design does not allow this through the upgrade process. This lack of flexibility could lead to difficulties in maintaining the contract over time, especially in evolving environments where changes might be necessary.
- **Risk Management:** Without the ability to update `token_address`, the contract is locked into the initial token configuration. If a vulnerability or issue is found with the initially set token, migrating to a new token address would require deploying a new contract instance and migrating all state and users, which can be complex and error-prone.
  
## Recommendations

I did some research into StarkNet forums and expert [discussions](https://youtu.be/9CIhHNrliW4?t=2086) confirms that this issue is a known limitation in Cairo upgrades. My suggestion to address storage updates, consider implementing a temporary class with an initialization function as a workaround to facilitate necessary storage changes during upgrades.

Along with this a quick solution will be to **Implement a Setter Function for `token_address`:** Introduce a function that allows the owner to update the `token_address` post-deployment. This would enable flexibility in managing token dependencies without needing to redeploy the entire contract.
   
   ```rust
   fn set_token_address(ref self: ContractState, new_token_address: ContractAddress) {
       self.ownable.assert_only_owner();
       self.token_address.write(new_token_address);
   }
   ```
