# Vulnerability details

# Impact
The `receive_cross_chain_msg` function is vulnerable to replay attacks due to the lack of a unique nonce. This allows an attacker to resend a previously valid message, leading to:

Transaction Duplication: 
Replaying a message can cause the same transaction to be executed multiple times, potentially resulting in financial losses.

State Manipulation: 
An attacker can alter the contract’s state by replaying messages that change state, causing inconsistencies or disrupting contract functionality.

# POC

Steps to Demonstrate Vulnerability:

1. Intercept a Valid Message:

Use Etherscan to capture a valid cross-chain message.
Extract the message parameters: txid, from_chain, from_address, from_handler, to_handler, payload_type, payload, and signatures.

2. Replay the Message:

Send a new transaction with the same parameters to the contract.

3. Verify the Replay:

Check if the contract processes the replayed message successfully.

```const Web3 = require('web3');
  payload: decodedMessage[6],

  from: '0x...',

    'uint256', 'string', 'uint256', 'uint256', 'address', 'uint8', 'bytes', 'bytes'

const receipt = await web3.eth.getTransactionReceipt(replayedTx.transactionHash);
if (receipt.status === '0x1') {
  console.log('Replay successful!');
} else {
  console.log('Replay failed.');
}
```


# Recommended Mitigation Steps

1. Introduce a Unique Nonce:

Add a unique nonce to each cross-chain message to ensure it cannot be reused.

2. Store Nonce in Contract State:

Implement a mapping to track and validate used nonces.

3. Validate Nonce Before Processing:

Ensure the nonce is unique and has not been used previously to prevent replay attacks.
