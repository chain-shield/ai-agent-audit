# Vulnerability details

## Impact
The current implementation of the cross-chain messaging system does not include a deadline or expiration timestamp in the signature of messages. This omission can lead to several security issues, primarily related to the indefinite validity of signatures.

Replay Attacks in Changed Contexts: While immediate replays are prevented with the use of txid and their status, the same transaction could potentially be replayed much later when the context has changed (e.g., after a hard fork, or when contract logic has been updated or contract config e.g., number of validators required has changed).
Lingering Permissions: In cases where signatures represent permissions or approvals, these would never expire, potentially outliving the intents of the signers.

This issue is present in both solidity and cairo version.

## Proof of Concept
In the current implementation, the signature covers the following elements:

```solidity
bytes32 message_hash = keccak256(
    abi.encodePacked(
        txid,
        from_chain,
        from_address,
        from_handler,
        to_handler,
        keccak256(payload)
    )
);
```
Notably absent is any form of timestamp or deadline. This allows for the following attack scenarios:

1. An attacker observes a valid cross-chain transaction.
2. The attacker waits for a significant change in the system (e.g., a contract upgrade or change in required validators).
3. The attacker then submits the old transaction, which may now have different implications or bypass new security measures.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Include an expiration timestamp in the signed message structure.
