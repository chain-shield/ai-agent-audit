# Vulnerability details

## Impact
If a single validator is compromised, it could sign a message that would cause `ChakraSettlementHandler` to unlock a large number of locked assets and send them to an attacker's address.

The purpose of having `SettlementSignatureVerifier.required_validators` is to provide a level of protection against a single validator being compromised. If that were to happen, it would not be desirable for the entire protocol to be compromised. Similarly, once the TVL of Chakra becomes significant, the incentive for a single validator to sign a bad message could become significant, allowing themselves to potentially steal large amounts of locked assets.

If any single validator can unilaterally sign messages, the entire Chakra protocol becomes as strong as its weakest validator.

## Proof of Concept
When `ChakraSettlement.receive_cross_chain_msg()` receives a cross chain message, it calls `signature_verifier.verify()` to validate the signatures. The logic for this validation is contained in  `SettlementSignatureVerifier.verifyECDSA()`. This function contains a loop which steps through the `signatures` byte array in steps of 65 characters (a signature's length) and checks each one to see if it is a valid signature of a validator. This is done by calling Openzeppelin's `ECDSA.recover()` on the individual signature and then looking up the returned signer address in the mapping `validators`.

However, there is nothing in this logic to prevent the `signatures` `bytes` array from consisting of the same single signature repeated multiple times. This would repeatedly pass the test on lines 207/134:
```
validators[msgHash.recover(sig)] && ++m >= required_validators
```
This would increase the variable `m` as many times as the signature is repeated, and so allow a single signature to count as enough to satisfy the condition of needing `required_validators` signatures to validate a received cross chain message, regardless of the value of `required_validators`.

## Tools Used
Manual inspection

## Recommended Mitigation Steps
As well as incrementing  the `uint256 m` inside `verifyECDSA()`, create an empty `address[]` array of length `required_validators`. When a signature is confirmed as coming from a known validator, check for the validator's address in this array and, if it is not found, add it. It may be useful to make use of a library that implements unique arrays with lookup functions.
