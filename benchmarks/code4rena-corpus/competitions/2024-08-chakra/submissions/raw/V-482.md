# Vulnerability details

## Impact
A single validator's signature which is less than the number of required validators can be used multiple times to achieve verification. 



## Proof of Concept
The issue is with the `verifyECDSA(...)` function of the `SettlementSignatureVerifier.sol` that is used to verify signatures in the ChakraSettlement.sol.

The `verifyECDSA(...)` function only validates that the returned address from `msgHash.recover(sig)` function call is a validator and does not validate that each signature returns a unique address from the other addresses. 

So with this, a single signature by just one validator can be repeated multiple times to bypass the number of required validators.

```solidity
File: SettlementSignatureVerifier.sol
function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
@>              validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }

```

So if the number of required validators is 3, just one signature will be repeated 3 times and it will pass the `verifyECDSA(...)` function.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider implementing a validation to ensure unique addresses of validators returned while looping through the signatures with the `msgHash.recover(sig)` function call are unique so that single signature is not repeated multiple times to pass the number of required validators.
