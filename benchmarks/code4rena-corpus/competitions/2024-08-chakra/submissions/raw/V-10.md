# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: Incorrect Argument Passed to __Ownable_init During ERC20CodecV1 Contract Initialization
•	Severity: Medium
•	Impact: The incorrect invocation of __Ownable_init with an argument can result in a fatal error during contract deployment, rendering the contract non-functional.
•	Status: Unresolved
•	File: ERC20CodecV1.sol
•	Lines Affected: 19

The incorrect invocation of __Ownable_init with an argument can result in a fatal error during contract deployment, rendering the contract non-functional. This could prevent the contract from being deployed or upgraded, potentially locking funds or halting operations dependent on the contract.

The initialize function in the ERC20CodecV1 contract incorrectly passes an argument to the __Ownable_init function. The __Ownable_init function from the OpenZeppelin’s OwnableUpgradeable library does not take any arguments. Instead, it simply initializes the contract, setting the deployer as the initial owner. Passing an argument to this function results in a TypeError and causes the Solidity compiler to fail, thereby preventing the deployment or upgrade of the contract.

The specific error encountered is:
```log
mythril.interfaces.cli [ERROR]: Solc experienced a fatal error.

TypeError: Wrong argument count for function call: 1 arguments given but expected 0.

   |

   |         ^^^^^^^^^^^^^^^^^^^^^^
```

## Recommended Mitigation Steps
To resolve this issue, the initialize function should be updated to remove the argument from the __Ownable_init function call. Instead, you should call __Ownable_init without any arguments and then use the transferOwnership function to set the desired owner.

Corrected Code:
```sol
function initialize(address _owner) public initializer {
    __Ownable_init(); // Correct usage
    __UUPSUpgradeable_init();
    transferOwnership(_owner); // Explicitly set the owner
}
```

The incorrect use of the __Ownable_init function with an argument in the initialize function leads to a compilation error that prevents the contract from being deployed. The issue is mitigated by calling __Ownable_init without arguments and explicitly setting the owner using transferOwnership. This correction ensures the contract can be successfully deployed and properly initialized.
