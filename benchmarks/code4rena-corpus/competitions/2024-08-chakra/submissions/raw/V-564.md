# Vulnerability details

## Description: 
 When a cross-chain transaction fails on the destination chain, the source chain should refund the user's amount. However, in the given implementation, the `receive_cross_chain_callback` function in `ChakraSettlementHandler` does not include any logic for refunds when the transaction status is Failed. Consequently, the source chain's `receive_cross_chain_callback` does not trigger any refund mechanism upon receiving a failed status.


## Impact: 
Loss of funds for user and locking of funds in protocol. There is no way to take this money out. The failure to refund user funds can lead to financial losses for users, which could undermine trust in the system. If users are not refunded in the event of a failure, it directly affects their assets and could lead to significant financial implications.

## Proof of Concept:
1. Scenario Setup:

    - A user initiates a cross-chain transaction from the source chain to the destination chain.
    - The handler on the destination chain is not whitelisted on the source chain, leading to a failed status for the transaction.
  
2. Observation:

    - On the destination chain, the transaction status is set to Failed, but there is no refund mechanism in place.
    - The `receive_cross_chain_callback` function on the source chain does not refund the user's amount even though the status is    Failed.
  
3. Expected Behavior:

    - If the transaction fails, the source chain should process a refund to the user.
  
4. Demonstration:

    - A transaction is initiated with an amount (e.g., 100 tokens).
    - The transaction fails on the destination chain.
    - The user's 100 tokens are not refunded to their account on the source chain.

## Recommended Mitigation:
Implement Refund Logic: Modify the `ChakraSettlementHandler` contract to include a refund mechanism in the `receive_cross_chain_callback` function when a Failed status is encountered.
