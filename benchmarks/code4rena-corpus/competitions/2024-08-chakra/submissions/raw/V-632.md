# Vulnerability details

## Impact
If msg_count in handler contract and settlement contract is different, user's message txid is different in handler contract and settlement contract. when `receive_cross_chain_callback` is called, the txid is passed directly from settlement contract to handler contract in receive-callback context. So wrong created_tx key(txid) is used to modify created_tx mapping state and get wrong created_tx mapping state in `receive_cross_chain_callback` function in handler_erc20.cairo.

## Proof of Concept
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L183
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L289
There are four handler contracts and one settlement contract on one chain. A user can set cross-chain message by arbitrary handler contract depending on the mode.
The txid is calculated using follow ways:
handler contract →
```
           let tx_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.msg_count.read());
```
settlement contract →
```
            let cross_chain_settlement_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.tx_count.read());
```
The method of calculation is the same in handler contract and settlement contract.
However we have four handler contracts and settlement contract. It's very easy to let msg_count in handler contract and settlement contract not equal as long as more than one handler contracts are used.
For example:
A user send cross-chain message by handler_1 contract. The msg_count/tx_count is same in handler contract and settlement contract. The msg_count/tx_count in settlement contract increments.
And then another user send cross-chain message by handler_2 contract. The msg_count/tx_count is different in handler contract and settlement contract. So the txid in handler contract and settlement contract is different.
Anther case: `send_cross_chain_msg` function in settlement.cairo has no access control, anyone can directly call this function and let tx_count increment. And  then msg_count/tx_count is different in handler contract and settlement contract. So the txid in handler contract and settlement contract is different.
Assume message is received in another chain.
And then `receive_cross_chain_callback` function is called. It pass the txid in settlement contract to handler contract directly. The txid input of `receive_cross_chain_callback` function in handler contract  is from settlement contract. Two txids are different. So wrong created_tx key(txid) is used to modify created_tx mapping state and get wrong created_tx mapping state in `receive_cross_chain_callback` function in handler_erc20.cairo.

## Tools Used
manual

## Recommended Mitigation Steps
Pass the txid in handler contract directly to settlement contract. Keep txid same in handler contract and settlement contract. The txid's calculation includes mode number.
