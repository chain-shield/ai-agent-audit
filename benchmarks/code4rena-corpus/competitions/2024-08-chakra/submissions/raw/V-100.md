# Vulnerability details

## Impact
For moving ERC20 tokens across chains, the protocol does not maintain the mapping for `from_token` and `to_token` along with source and destination ids.

As a transaction to move ERC20 from source to destination, it is possible for the attacker to pass different ids across chains. As the mapping for tokenId to chain Id is not present, the attacker can move `DAI` on source chain and pass the id of `Eth` on the destination chain.  

If the from_token + source chain id is mapped to to_token + destination chain id, then such cross token transaction will not work.

## Proof of Concept
There is no whitelisting for tokens to chain id to validate the tokens present in source chain to be same as tokens on destination chain. This opens a vulnerability where it is possible to create cross chain transaction for two totally different tokens across the source and destination chains.

## Tools Used
Manual review
## Recommended Mitigation Steps
It is recommended to maintain a mapping of Chain to tokenId for source and destination chains. The mapping is managed by either the owner or through governance.
