# Vulnerability details

## Impact
In ChakraSettlement.sol contract, the function `receive_cross_chain_msg()` takes following parameters as input:
```
function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external;
```
We can see that parameters `from_address` and `from_handler` are of type `uint256`, whereas `to_handler` is of type `address`. 
The `to_handler` address is passed to `ISettlementHandler` interface to be able to call `receive_cross_chain_msg()` in `ChakraSettlementHandler.sol` contract.
```
bool result = ISettlementHandler(to_handler).receive_cross_chain_msg(
            txid,
            from_chain,
            from_address,
            from_handler,
            payload_type,
            payload,
            sign_type,
            signatures
        );
```
The problem arises if the message is sent from Starknet chain, because `settlement.cairo` in the function `send_cross_chain_msg()` emits the event CrossChainMsg passing `to_handler` as `u256` address

```
fn send_cross_chain_msg(
            ref self: ContractState, to_chain: felt252, to_handler: u256, payload_type :u8,payload: Array<u8>,
        ) -> felt252 {
            let from_handler = get_caller_address();
            let from_chain = self.chain_name.read();
            let cross_chain_settlement_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.tx_count.read());
            self.created_tx.write(cross_chain_settlement_id, CreatedTx{
                tx_id:cross_chain_settlement_id,
                tx_status: CrossChainMsgStatus::PENDING,
                from_chain: from_chain,
                to_chain: to_chain,
                from_handler: from_handler,
                to_handler: to_handler
            });
            
            self
                .emit(
                    CrossChainMsg {
                        cross_chain_settlement_id: cross_chain_settlement_id,
                        from_address: get_tx_info().unbox().account_contract_address,
                        from_chain: from_chain,
                        to_chain: to_chain,
                        from_handler: from_handler,
                        to_handler: to_handler,
                        payload_type: payload_type,
                        payload: payload
                    }
                );
            self.tx_count.write(self.tx_count.read()+1);
            return cross_chain_settlement_id;
        }
```
This is the problem because in Starknet (Cairo), addresses are 256-bit (u256), while in EVM, addresses are 160-bit (address). If validators pass the u256 value (256-bit) directly to the Solidity function expecting a 160-bit address, Solidity will not automatically handle the conversion or truncation. This needs to be done explicitly, otherwise the call to ChakraSettlementHandler will fail.

## Recommended Mitigation Steps
Change the function signature as follows: 
```
function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external;
```
Then, add the address conversion before calling the ChakraSettlementHandler

`address to_handler_address = AddressCast.toAddress(to_handler);`
