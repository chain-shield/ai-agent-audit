# Vulnerability details

## Vulnerability description
The way that solidity settlement contract verifies if a message hash has enough signatures is by using an external contract `SettlementSignatureVerifier`. This contract stores the whitelisted addresses that count as valid signatures and the amount required of them to consider a message hash as valid. This signature verifier contract has these 3 functions to change these parameters that are permissioned to only managers.
```
    function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == false, "Validator already exists");
        validators[validator] = true;
        validator_count += 1;
        emit ValidatorAdded(msg.sender, validator);
    }

    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == true, "Validator does not exists");
        validators[validator] = false;
        validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }

    function set_required_validators_num(
        uint256 _required_validators
    ) external virtual onlyRole(MANAGER_ROLE) {
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
The way it works is that the settlement contract will be a manager address, because these functions are also present in the settlement contract.
```
    function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
        signature_verifier.add_validator(validator);
        require(
            chakra_validators[validator] == false,
            "Validator already exists"
        );
        chakra_validators[validator] = true;
        validator_count += 1;
        emit ValidatorAdded(msg.sender, validator);
    }

    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        signature_verifier.remove_validator(validator);
        require(
            chakra_validators[validator] == true,
            "Validator does not exists"
        );
        chakra_validators[validator] = false;
        validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }

    function set_required_validators_num(
        uint256 _required_validators
    ) external onlyRole(MANAGER_ROLE) {
        // @audit-issue it does not set the required validators in the verifier contract
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
As you can see in the `add_validator` and `remove_validator` functions from the settlement, they call the pertinent functions from the signature verifier contract to change the state in this external contract. However, for setting the amount of required signatures it does not update it in the external contract, it only updates it internally but it will have no effect because the required amount of signatures that is relevant for the signature verification is the one stored in the external contract.

## Impact
High, the owner of the settlement contract can call the `set_required_validators_num` function thinking that he will update the required number of signatures but in fact it will not be updated in the signature verifier contract so it will not take effect and will require the old amount of signatures to verify a message.


## Tools Used
Manual review

## Recommended Mitigation Steps
Call the function to update the required signatures from the verifier contract externally:
```diff
    function set_required_validators_num(
        uint256 _required_validators
    ) external onlyRole(MANAGER_ROLE) {
++      signature_verifier.set_required_validators_num(_required_validators);
        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
