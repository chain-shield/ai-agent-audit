# Vulnerability details

## Impact
Protocol does not account for decimal difference across various chains, it just uses the same amount gotten from the source chain and sends to the user which can send way more tokens or way less.

## Proof of Concept
Certain tokens don't have the same decimal precision across different chains taking USDC as an example on binance smart chain it has 18 decimal but on starknet it has 6 decimals 
https://bscscan.com/token/0x8ac76a51cc950d9822d68b83fe1ad97b32cd580d#readProxyContract#F3
https://starkscan.co/token/0x053c91253bc9682c04929ca02ed00b3e423f6710d2ee7e0d5ebb06f3ecf368a8
This precision difference is so great that if you try to pay the same amount executed on one chain on another chain it will be very high or very low costing protocol and users great financial loss 

## Tools Used
Manual Review 

## Recommended Mitigation Steps
Implement a decimal conversion that converts when token decimals don't match
