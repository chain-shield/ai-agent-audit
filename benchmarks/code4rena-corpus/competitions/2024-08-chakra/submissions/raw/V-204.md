# Vulnerability details

## Impact
Malicious users can frontrun receive_cross_chain_callback() with the correct signature and incorrect from_chain. This txid's result will be marked Failed. This will cause `create_cross_txs` status in ChakraSettlementHandler cannot be set correctly and the source chain's tokens cannot be burn when the mode is `MintBurn`

## Proof of Concept
In solidity settlement receive_cross_chain_callback(), we will verify signature based on the input parameters, and then update states and maybe burn tokens via handler's `receive_cross_chain_callback`
The problem is that the input parameter `from_chain` is not verified by signature. Considering that the protocol may be deployed on Ethereum, malicious users can frontrun one normal `receive_cross_chain_callback` with one incorrect `from_chain`.
The handler's `receive_cross_chain_callback` will return false because we have one whilelist handler check. Then this `create_cross_txs` status will be marked as `Failed`.
When the normal `receive_cross_chain_callback` try to be executed, this will be reverted because `create_cross_txs`'s status is not `PENDING`.
