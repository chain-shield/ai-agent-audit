# Vulnerability details

## Impact
One of the invariants about the Settlement Handler Contract in the README of the audit states that: 

`The contract ensures sufficient token balance before performing transfers, burns, or unlocks.`

The problem is that in both of this functions (`cross_chain_erc20_settlement()` and `receive_cross_chain_msg()`) the sufficient token balance is not checked

## Proof of Concept
These are the 2 functions


In the first function we are directly trying to transfer the tokens from the user to the contract without checking if he has sufficient balance. In the second function we are just transfering tokens to the user without checking the sufficient balance of the contract. This breaks the invariant
