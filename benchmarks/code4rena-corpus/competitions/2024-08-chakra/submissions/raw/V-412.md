# Vulnerability details


## Impact

The `to_bytes32` function in `AddressCast.sol` is defined with an incorrect parameter type. It uses `bytes calldata` for an internal function, which is incompatible with Solidity's memory model for internal function calls. This error prevents the function from being used within contracts that import the `AddressCast` library.

The impact of this issue is significant as it renders the function unusable in its current form. Any attempt to call this function internally will result in a compilation error, effectively breaking any functionality that relies on this conversion method.

## Proof of Concept

Vulnerable code location:
- [solidity/handler/.../AddressCast.sol](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/libraries/AddressCast.sol#L47-L57)

The problematic code in the `to_bytes32` function:

```solidity
    function to_bytes32(
>@      bytes calldata _addressBytes
    ) internal pure returns (bytes32 result) {
        if (_addressBytes.length > 32) revert AddressCast_InvalidAddress();
        result = bytes32(_addressBytes);
        unchecked {
            uint256 offset = 32 - _addressBytes.length;
            result = result >> (offset * 8);
        }
    }
```

## Recommended Mitigation Steps

To address this issue, change the parameter type from `bytes calldata` to `bytes memory`:

```solidity
function to_bytes32(
    bytes memory _addressBytes
) internal pure returns (bytes32 result) {
    if (_addressBytes.length > 32) revert AddressCast_InvalidAddress();
    result = bytes32(_addressBytes);
    unchecked {
        uint256 offset = 32 - _addressBytes.length;
        result = result >> (offset * 8);
    }
}
```

This change will allow the function to be called internally within contracts that import the `AddressCast` library.
