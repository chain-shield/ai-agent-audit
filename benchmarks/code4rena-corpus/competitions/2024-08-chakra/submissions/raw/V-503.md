# Vulnerability details

The `send_cross_chain_msg()` function is vulnerable to phishing attacks due to the way it handles and emits the from_address. Specifically, the from_address is set to `get_tx_info().unbox().account_contract_address, which could be spoofed or misrepresented by a malicious contract calling the function. If a user interacts with a malicious smart contract (the "caller"), that contract could forward the cross-chain message, misleading the recipient about the origin of the message.


Attack Scenario
1. An attacker deploys a malicious contract designed to forward transactions.
2. A legitimate user interacts with the malicious contract, unaware of its true nature.
3. The malicious contract calls `send_cross_chain_msg`, passing its own address as the msg.sender (from_handler) while keeping the user’s address as the from_address.
4. The emitted event shows the transaction as originating from the user’s account, even though it was initiated by the malicious contract. This could mislead recipients or other systems into trusting the message, facilitating phishing attacks.

Vulnerable Code:

[L-303](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L303)

```cairo
self.emit(
    CrossChainMsg {
        cross_chain_settlement_id: cross_chain_settlement_id,
        from_address: get_tx_info().unbox().account_contract_address,  // @audit: could be misrepresented
        from_chain: from_chain,
        to_chain: to_chain,
        from_handler: from_handler,
        to_handler: to_handler,
        payload_type: payload_type,
        payload: payload
    }
);
```

Fix
To prevent phishing attacks, it's important to ensure that the from_address accurately reflects the entity initiating the transaction. Instead of relying solely on `get_tx_info().unbox()`,account_contract_address, you should ensure that the from_address cannot be spoofed by verifying the origin and making sure it directly correlates with msg.sender or another trusted mechanism.

Here is a potential fix:

```cairo
self.emit(
    CrossChainMsg {
        cross_chain_settlement_id: cross_chain_settlement_id,
        from_address: from_handler,  // Ensure from_address matches the immediate caller (msg.sender)
        from_chain: from_chain,
        to_chain: to_chain,
        from_handler: from_handler,
        to_handler: to_handler,
        payload_type: payload_type,
        payload: payload
    }
);
```
