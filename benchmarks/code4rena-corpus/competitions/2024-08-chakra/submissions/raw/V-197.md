# Vulnerability details

## Impact
One malicious validator can repeat his signature to match the required_validators limitation.

## Proof of Concept
When we trigger receive_cross_chain_msg() in the destination chain, we need to provide multiple validators' signature to make sure this transaction's validation.
We set the `required_validators` to avoid one malicious validator sending manipulated transaction. Or if the hacker get one validator's private key, the hacker can still not send manipulated transactions because we have `required_validators` limitation.

The problem is that when we check the signature, we allow repeated signatures. This cause that malicious validators can repeat his own valid signature into the transaction to match `required_validators`.

```javascript
    function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                // @audit one validator can repeat his signature to bypass the required_validators.
                // first, we check 
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }
        return false;
    }
```

Check whether there are some repeated signatures when we verify signature via `verifyECDSA()`.
