# Vulnerability details

## Vunerability details

Protocol makes no attempt to return users funds upon status being updated to `CrossChainMsgStatus.Failed`. When the protocol receives a cross-chain messsage they have 5 settlement modes set for predertermined actions (MintBurn, LockMint, BurnUnlock, LockUnlock), if any of these are not performed the status will be updated to `CrossChainMsgStatus.Failed` and funds will not be returned on the original chain and user has no way to reclaim them.
 ## Impact
 Users funds will be locked forever as there is no method or function for the user to even try and reclaim them or for protocol to process reurns of failed cross-chain messages.
 
 ## Proof Of Concept
 AFter a cross-chain message has been received and is being processed by the `receive_cross_chain_msg()` function of the settlement contract, after verifying the signature of the user the function passes the processing over to the same function name but in the handler contract to process various actions,

        uint256 /**txid */,

        uint256 /**from_address */,
        uint256 from_handler,

        bytes calldata /**signaturs */

        //  from_handler need in whitelist
        if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
        }
        bytes calldata msg_payload = MessageV1Codec.payload(payload);


        require(isValidPayloadType(payload_type), "Invalid payload type");


        if (payload_type == PayloadType.ERC20) {
            // Cross chain transfer
            {
                // Decode transfer payload
                ERC20TransferPayload memory transfer_payload = codec
                    .deocde_transfer(msg_payload);


                if (mode == SettlementMode.MintBurn) {
                    _erc20_mint(
                        AddressCast.to_address(transfer_payload.to),
                        transfer_payload.amount
                    );
                    return true;
                } else if (mode == SettlementMode.LockUnlock) {
                    _erc20_unlock(
                        AddressCast.to_address(transfer_payload.to),
                        transfer_payload.amount
                    );


                    return true;
                } else if (mode == SettlementMode.LockMint) {
                    _erc20_mint(
                        AddressCast.to_address(transfer_payload.to),
                        transfer_payload.amount
                    );
                    return true;
                } else if (mode == SettlementMode.BurnUnlock) {
                    _erc20_unlock(
                        AddressCast.to_address(transfer_payload.to),
                        transfer_payload.amount
                    );
                    return true;
                }
            }
        }


        return false;
    }
```

depending of the `settlementMode` selected, different actions will be done such as minting token. After one of the chosen actions (MintBurn, LockMint, BurnUnlock, LockUnlock) are processed the function returns the `true` boolean back to the settlement contract, if none of those actions are performed for whatever reason the function returns `false` back to the settlement contract.

    function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
        {
            // verify signature
            bytes32 message_hash = keccak256(
                abi.encodePacked(
                    txid,
                    from_chain,
                    from_address,
                    from_handler,
                    to_handler,
                    keccak256(payload)
                )
            );


            require(
                signature_verifier.verify(message_hash, signatures, sign_type),
                "Invalid signature"
            );


            require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );
        }


        receive_cross_txs[txid] = ReceivedCrossChainTx(
            txid,
            from_chain,
            contract_chain_name,
            from_address,
            from_handler,
            address(this),
            payload,
            CrossChainMsgStatus.Pending
        );


        bool result = ISettlementHandler(to_handler).receive_cross_chain_msg(
            txid,
            from_chain,
            from_address,
            from_handler,
            payload_type,
            payload,
            sign_type,
            signatures
        );


        CrossChainMsgStatus status = CrossChainMsgStatus.Failed;
        if (result == true) {
            status = CrossChainMsgStatus.Success;
            receive_cross_txs[txid].status = CrossChainMsgStatus.Success;
        } else {
            receive_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }


        emit CrossChainHandleResult(
            txid,
            status,
            contract_chain_name,
            from_chain,
            address(to_handler),
            from_handler,
            payload_type
        );
    }
 ```
depending of the boolenan result the `receive_cross_chain_msg()` function will change the status of the message to Success or Failed depending on the boolean. The problem here is that should the result be false from the handler contract and the staus changed to `CrossChainMsgStatus.Failed`, users have no way to reclaim locked funds on the chain of origin of the transaction because the the protocol does not do anything to release the funds in the `receive_cross_chain_callback()` .

```solidity
    function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        CrossChainMsgStatus status,
        uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
        bytes calldata /* signatures */
    ) external onlySettlement returns (bool) {
        //  from_handler need in whitelist
        if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
        }


        require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending,
            "invalid CrossChainTxStatus"
        );


        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }


            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }


        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }


        return true;
    }
 ```
 As can be seen above if `status == CrossChainMsgStatus.Failed` it will only update `create_cross_txs[txid].status` to CrossChainTxStatus.Failed.

 ## Mitigation Steps
 When `create_cross_txs[txid].status == CrossChainTxStatus.Failed` the protocol should use `_erc20_unlock()` function to transfer back any funds sent to the contract when creating the cross-chain message
