# Vulnerability details

## Impact

Setting required_validators_num to 0 will completely bypass the signature verification mechanism, allowing any user to forge cross-chain transactions.

The vulnerability exists in the `set_required_validators_num` function, which allows the number of required signatures (`required_validators_num`) to be set to any value, including `0`. If a malicious or careless manager sets this value to `0`, the system would no longer require any signatures to verify transactions. This would completely bypass the signature validation mechanism, rendering the contract vulnerable to unauthorized actions, including fraudulent cross-chain transactions.

In such a scenario, the security mechanism based on validator signatures becomes ineffective, and the integrity of cross-chain transactions would be compromised. An attacker or an unauthorized party could process cross-chain transactions without the need for any validator approvals, leading to significant financial losses and potential network instability.

### Consequences:

- **Complete Bypass of Signature Validation**: Setting the required number of validators to `0` would mean that transactions can be processed without any valid signatures.
- **Unauthorized Transactions**: Without any validation, cross-chain transactions could be executed by unauthorized actors, leading to unauthorized fund transfers or fraudulent settlements.
- **Systemic Risk**: This vulnerability could lead to cascading failures across multiple blockchains if cross-chain transactions are involved, potentially causing network-wide issues.

The following code snippet shows the `set_required_validators_num` function, where the `new_num` parameter can be set to `0`, leading to the complete disabling of the signature validation system:

```

fn set_required_validators_num(ref self: ContractState, new_num: u32) -> u32 {
let caller = get_caller_address();
assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
self.required_validators_num.write(new_num);
return self.required_validators_num.read();
}
```

In this implementation, there is no restriction on the value of `new_num`. If `new_num` is set to `0`, the system will no longer require any signatures to validate transactions.

1. **Add Range Checks**: Ensure that the `set_required_validators_num` function includes a range check, ensuring that `new_num` cannot be set below a minimum value (e.g., `3`).

   Example of mitigation:

   ```

   fn set_required_validators_num(ref self: ContractState, new_num: u32) -> u32 {
       let caller = get_caller_address();
       assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
       assert(new_num >= 3, 'Number of required validators must be greater than or equal to 1');
       self.required_validators_num.write(new_num);
       return self.required_validators_num.read();
   ```
