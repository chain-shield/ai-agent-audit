# Vulnerability details

## Impact

Tokens can be minted for free.

## Proof of Concept

In a block reorganization, all transactions will be reverted and recalled again. An unsuspecting user can call `cross_chain_erc20_settlement()`, transfer some tokens into the handler contract on the source chain, and emit the message out.

```

        require(to != 0, "Invalid to address");
        require(to_handler != 0, "Invalid to handler address");
        require(to_token != 0, "Invalid to token address");

```

If there is a block reorg, the whole transaction will be repeated, and this time there will be 2 messages out with only one transfer in.

If the validators on the destination chain is not careful and proceed with the messages, then they will award the user two times the amount of tokens.

## Recommended Mitigation Steps

Don't really know the mitigation steps for this, but ensure that on the destination chain, enough time has passed before the validators on the destination chain calls `receive_cross_chain_msg()`.

One possible way is to compare the `block.timestamp` of the message in the source chain and destination chain. If it is in the past somehow (on the destination chain), then revert the whole message altogether.
