# Vulnerability details

## Impact
The `receive_cross_chain_msg` function currently accepts `payload` and `payload_type` as parameters without any validation to ensure that they are legitimate and appropriate for the context. The payload and payload_type should be verified to ensure that the message conforms to expected types This lack of validation can be exploited by attackers to pass malicious or malformed payloads, potentially leading to unauthorized actions, contract manipulation, or even denial of service. If an invalid or unexpected payload is processed, it could cause unexpected behavior in the contract or downstream contracts that interact with the payload.

As shown above we currently dont have a way to check if the `payload` and `payload_type` is valid.

## Proof of Concept
 An attacker can craft a payload that does not conform to the expected structure of ERC20 or another valid PayloadType. For example, if the system expects an ERC20 transfer, the attacker can pass arbitrary or malformed data that the contract assumes is valid.

Since there is no check to verify that the `payload_type` aligns with the contents of payload, an attacker could use this mismatch to trigger unintended actions or cause failures in downstream contracts that interact with this data.

## Recommended Mitigation Steps
ensure that:

* The payload_type corresponds correctly to the expected format and content of the payload.
* The payload adheres to the expected structure, data types, and content for the given payload_type.
