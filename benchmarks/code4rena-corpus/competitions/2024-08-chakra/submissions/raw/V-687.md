# Vulnerability details

## Summary
The `verifyECDSA` function has a severe vulnerability that allows signature reuse. It doesn't prevent the same signature from being counted multiple times, which could lead to false validation of messages.

The function loops through the provided signatures, recovering the signer's address for each and checking if it's a valid validator. However, it doesn't keep track of which validators have already been counted. This means that if the same signature is provided multiple times, it will be counted repeatedly towards the `required_validators` threshold.

```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 len = signatures.length;
    uint256 m = 0;
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
    }

    return false;
}
```

## Impact
This vulnerability could allow an attacker to:
1. Reuse a single valid signature multiple times to meet the `required_validators` threshold.
2. Falsely validate a message with fewer unique signatures than required.
3. Potentially bypass the multi-signature security measure entirely if `required_validators` is set to a value greater than 1.

## Scenario
Assume `required_validators` is set to 3, and an attacker has obtained one valid signature. They could duplicate this signature three times in the `signatures` input, causing the function to return `true` even though only one validator actually signed the message.

## Fix
To address this issue, we need to keep track of which validators have already been counted. Here's a proposed fix:

```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 len = signatures.length;
    uint256 m = 0;
    mapping(address => bool) memory usedValidators;

    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        address recoveredAddress = msgHash.recover(sig);
        if (validators[recoveredAddress] && !usedValidators[recoveredAddress]) {
            usedValidators[recoveredAddress] = true;
            if (++m >= required_validators) {
                return true;
            }
        }
    }

    return false;
}
```

This fix introduces a `usedValidators` mapping to ensure each validator is only counted once.
