# Vulnerability details


[Official document address](https://s3labs.notion.site/Contract-Design-Document-f4aa296f71fb40b1818c0890c40be55c#2286a74561ce4765909db58db373eaee)
The `send_cross_chain_msg()` function in `settlement.cairo` is designed to be called only by a designated handler, as indicated in the comments. However, the current implementation lacks a permission check, allowing any user to invoke this function. This vulnerability permits unauthorized users to increment the `tx_count` value. The function is intended to be called by `handler_erc20.cairo::cross_chain_erc20_settlement()` to create and store transaction data in `created_tx` with a mapping to `cross_chain_settlement_id`.

If a malicious actor exploits this vulnerability, they can artificially increase the `tx_count`, leading to inconsistencies between the `cross_chain_settlement_id` and `handler_erc20.cairo::tx_id`. This discrepancy can cause synchronization issues within the contract and could lead to operational failures during subsequent cross-chain operations.

## Impact
This vulnerability allows any user to call `send_cross_chain_msg()` and arbitrarily update the `tx_count`, leading to desynchronization of `cross_chain_msg_id`. Such inconsistencies can compromise the entire system's reliability, especially in cross-chain transactions involving funds or other critical assets, potentially resulting in irrecoverable losses or system-wide failures.

## Recommended Mitigation Steps
To mitigate this issue, it is recommended to centralize the management of `tx_count` and `msg_count` to ensure synchronized updates. Additionally, implement strict permission checks in `settlement.cairo::send_cross_chain_msg()` to ensure that only authorized handlers can invoke this function.
