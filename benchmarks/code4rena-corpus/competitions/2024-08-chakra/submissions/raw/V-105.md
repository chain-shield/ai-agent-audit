# Vulnerability details

## Impact
Instead of requiring multiple unique validators to approve an action, the bug allows a single validator to approve an action multiple times, effectively bypassing the intended security checks.


## Proof of Concept
The `verifyECDSA` function is designed to verify multiple ECDSA signatures against a given message hash. It's intended to ensure that a sufficient number of unique, authorized validators have signed off on a transaction or message. However, the current implementation does not track which validators have already provided a valid signature within a single verification call.

```
 function verify(
        bytes32 msgHash,
        bytes calldata signatures,
        uint8 sign_type
    ) external view returns (bool) {
        if (sign_type == 0) {
            return verifyECDSA(msgHash, signatures);
        } else {
            return false;
        }
    }

    function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```

The function increments a counter `m` each time a valid signature is found, and returns `true` when `m` reaches `required_validators`. However, it doesn't keep track of which validators have already contributed a valid signature.

Furthermore, the verify() calls the buggy verifyECDSA(). 

In ChakraSettlement.sol, both receive_cross_chain_msg() and receive_cross_chain_callback() uses verifyECDSA().
