# Vulnerability details

## Impact
A malicious user can DOS the `ChakraSettlement::receive_cross_chain_callback(...) ` function to cause failed transactions



## Proof of Concept

This is easier to perform on the ETH chain via frontrunning

This malicious user can frontrun a call to `ChakraSettlement::receive_cross_chain_callback(...) ` by using an invalid `from_chain` parameter.

As shown above if the `from_chain` parameter is not of a valid handler, then `false` will be returned from the `receive_cross_chain_callback(...)` and L329 will be executed and the status of the message will be updated to `CrossChainMsgStatus.Failed`. unfortunately, the protocol does not implement a function to retry failed messages.

The victims transaction is now has a failed status and he ends up wasting gas on the call.

A summary of the attack path on the ETH chain is as shown below:

**SUMMARY**
- Alice calls `receive_cross_chain_callback(...)`. with her `tx_id`, validator signature and other relevant and correct parameter
- Bob a malicious user sees the mempool and then calls the `receive_cross_chain_msg(...)` function with the Alice parameters including an invalid  `from_chain` value
- Bods call goes through but Alice call reverts because ` create_cross_txs[txid].status = CrossChainMsgStatus.Failed`
