# Vulnerability details

## Impact
There is a lack of pull mechanism that allows users to withdraw locked funds even if transactions failed on the other side of the chain. Due to the fact that there are a lot of reasons that a transaction would fail, such as the unlock functionality might fail if there is not enough gas or not enough amount in the contract, it is best to implement a way for users to get their locked funds. If not, these funds will be locked permanently in the contract with no way of withdrawal. Since 3 of the 4 modes involve locking users funds into the contract, there should be a way of withdrawal (but this should be done carefully to prevent users from withdrawing even if their transaction is done successfully on the other side) Elaboration of this will be done on the Recommendations.

Modes that require locking funds (such as LockUnlock or LockMint) require the user (msg.sender) to send funds into the contract. The funds will then be locked and on the Starknet side another action such such as Unlock or Minting will be done. However, if a transaction fails, for example the minting or unlocking fails for whatever reason (maybe lack of gas, the contract gets paused,or issues within Starknet itself), the funds will still remain locked on the Soliditiy? side.


This has the same effect if the lock was in the Starknet side

Funds will get locked if there is an issue with message sending or an issue on the chain using Solidity( as of now it seems to be any blockchain that supports the ERC-20 token standard). Due to the large variability and also the fact that transactions and messages might fail in blockchain due to reasons such as:

Gas Limit Exceeded:
If the transaction runs out of gas before completing the transfer, it will fail. This can happen if the gas limit set for the transaction is too low.
Lack of allowance ( contract itself does not have enough funds to unlock or mint)

Contract State Issues:
The contract may be in a state that does not allow transfers (e.g., if the contract is paused or if certain conditions are not met).

Funds will get locked forever with no means of retrieval.

## Recommended Mitigation Steps
There are different ways to handle this:

A: Add a mechanism for the user to withdraw locked funds.This can only  be done with the action on the other side of the cross chain has not been completed yet. For example, if I started a LockUnlock action on the Solidity side of the chain, and the Unlock fails in Starknet, I will receive a failed error message. Only if the transaction in Starknet failed can I get my locked funds back.
This can prevent other users from withdrawing their locked funds even after a successful transaction has been done on Starknet. This works vice versa in the other direction as well. With this method more error logging and ensuring any failed transactions will be recorded and an error will be emitted should be done on both the Solidity side and Starknet side.

B: Another solution could be only the Owner or authorized admin can withdraw these funds and distribute them back to the user. For example if I again, started a LockUnlock action on the Solidity side of the chain, and the Unlock fails in Starknet, I can notify the admin and the admin will help unlock and transfer the amount back in the Solidity side. However this requires more admin work.
