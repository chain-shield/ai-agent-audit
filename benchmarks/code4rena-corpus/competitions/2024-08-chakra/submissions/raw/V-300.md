# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Title: ChakraSettlementHandler contract has Unchecked transferFrom Return Value in _safe_transfer_from During ERC20 Locking.
Contract: ChakraSettlementHandler.sol.
Functions: _safe_transfer_from() & _erc20_lock().

The _safe_transfer_from function does not verify the return value of the external IERC20(token).transferFrom(from, to, amount) call. According to the ERC-20 standard, the transferFrom function returns a boolean indicating whether the transfer succeeded. Some ERC-20 tokens may return false instead of reverting on failure. If the contract does not check the return value, it will assume that the transfer was successful even if it failed. In cross-chain settlement systems like this one, an unchecked transfer can lead to significant issues such as unaccounted-for tokens, incorrect settlement balances, and ultimately, the loss of user funds.

## Proof of Concept

Consider the following scenario where an ERC-20 token’s transferFrom function fails silently (returns false), causing the contract to proceed without actually transferring the tokens:
```sol
contract FaultyERC20 {
    mapping(address => uint256) public balances;
    mapping(address => mapping(address => uint256)) public allowances;

    function transferFrom(address from, address to, uint256 amount) external returns (bool) {
        if (balances[from] < amount || allowances[from][msg.sender] < amount) {
            return false;  // Silently fail instead of reverting
        }
        balances[from] -= amount;
        balances[to] += amount;
        allowances[from][msg.sender] -= amount;
        return true;
    }
}
```
The following code in _safe_transfer_from would incorrectly assume the transfer succeeded even if the transferFrom function returned false:
```sol
function _safe_transfer_from(address from, address to, uint256 amount) internal {
    require(IERC20(token).balanceOf(from) >= amount, "Insufficient balance");

    // This call might fail silently and return false, but the return value is ignored
    IERC20(token).transferFrom(from, to, amount);
}

function _erc20_lock(address from, address to, uint256 amount) internal {
    _safe_transfer_from(from, to, amount); // Assumes the transfer succeeded
}
```
If transferFrom fails, the contract continues without transferring the tokens, causing a desynchronization between the actual token balances and the cross-chain settlement logic, potentially leading to financial loss or incorrect state in the settlement system.

## Recommended Mitigation Steps
To prevent this issue, the return value of the transferFrom function should be checked to ensure that the token transfer was successful. If the transfer fails (i.e., the return value is false), the transaction should revert to prevent further incorrect state changes.
```sol
function _safe_transfer_from(address from, address to, uint256 amount) internal {
    require(IERC20(token).balanceOf(from) >= amount, "Insufficient balance");

    // Check the return value to ensure the transfer succeeded
    bool success = IERC20(token).transferFrom(from, to, amount);
    require(success, "Token transfer failed");
}

function _erc20_lock(address from, address to, uint256 amount) internal {
    _safe_transfer_from(from, to, amount);  // Now checks that the transfer succeeded
}
```
By checking the return value of transferFrom, the contract ensures that token transfers only proceed if they are successful. If the transfer fails, the transaction reverts, protecting the integrity of the cross-chain settlement process.
