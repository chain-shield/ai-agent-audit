# Vulnerability details

The `ChakraSettlementHandler` contract contains a vulnerability in its nonce management system. The `nonce_manager` mapping, which tracks the nonce for each user, is susceptible to integer overflow. If a user's nonce reaches the maximum value of `uint256`, incrementing it further will cause it to wrap around to zero. This can lead to replay attacks and break the expected behavior of the contract.

## Impact
This vulnerability allows an attacker to bypass the nonce check and replay transactions. If a user's nonce reaches the maximum `uint256` value and then wraps around to zero, previously used nonces become valid again. This undermines the purpose of the nonce, which is to ensure each transaction is unique and cannot be replayed.

## Proof of Concept
The vulnerability stems from the nonce increment operation in the `cross_chain_erc20_settlement` function of the `ChakraSettlementHandler` contract. [ChakraSettlementHandler.sol#L135](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L134-L136)
```solidity
// ChakraSettlementHandler.sol
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ...

    {
        // Increment nonce for the sender
        nonce_manager[msg.sender] += 1;
    }

    // ...
}
```
The issue arises when `nonce_manager[msg.sender]` reaches the maximum value of `uint256 (2^256 - 1)`. When this happens, incrementing the nonce further will cause an integer overflow, and the value will wrap around to zero.

**Here's a scenario demonstrating the vulnerability:**

1. A user performs a large number of `cross_chain_erc20_settlement` transactions, causing their nonce to reach the maximum `uint256` value.

2. The user calls `cross_chain_erc20_settlement` again with the same parameters as a previous transaction.

3. Inside the function, `nonce_manager[msg.sender] += 1` is executed, causing an overflow. The nonce wraps around to zero.

4. The contract proceeds with the cross-chain settlement using the same nonce as a previous transaction, effectively replaying it.

5. The replayed transaction is processed, potentially leading to unintended behavior or loss of funds.

## Recommended Mitigation Steps
Implement a check for the maximum nonce value before incrementing it. If the nonce has reached the maximum value, the transaction should be reverted to prevent the overflow.
```diff
// ChakraSettlementHandler.sol
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ...

    {
        // Check if the nonce has reached the maximum value
+       require(nonce_manager[msg.sender] < type(uint256).max, "Nonce overflow");
        // Increment nonce for the sender
        nonce_manager[msg.sender] += 1;
    }

    // ...
}
```
