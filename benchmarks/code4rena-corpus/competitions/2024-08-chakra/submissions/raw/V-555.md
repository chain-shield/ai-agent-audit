# Vulnerability details

## Impact
The receive_cross_chain_callback function in the Cairo implementation of ERC20Handler unconditionally burns tokens in MintBurn mode and always sets the transaction status to SETTLED, regardless of the actual cross-chain operation status. This behavior differs significantly from the Solidity implementation, which checks the status before performing operations.

This vulnerability can lead to potential loss of user funds and incorrect transaction status reporting

```solidity
    string memory from_chain,
    uint256 from_handler,
    CrossChainMsgStatus status,
    // ... (other parameters omitted)

    // ... (initial checks omitted)

    if (status == CrossChainMsgStatus.Success) {

        }
        create_cross_txs[txid].status = CrossChainTxStatus.Settled;
    }

    if (status == CrossChainMsgStatus.Failed) {
        create_cross_txs[txid].status = CrossChainTxStatus.Failed;

````

## Recommended Mitigation Steps
