# Vulnerability details

## Impact
The protocol requires a certain number of validator signatures (`required_validators`) to verify a cross-`chain` message. If `required_validators` is greater than `validator_count`, the system is set up for failure because it is impossible to gather the required number of distinct `signatures`.

## Proof of Concept
`validator_count` represents the number of `registered validators` capable of signing messages.

The [`remove_validator()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L125-L132) function is designed to revoke a `validator`'s status, reducing the total number of validators (`validator_count`) available to sign `messages`.
```solidity
    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == true, "Validator does not exists");
>>      validators[validator] = false;
>>      validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }
```
If a `validator` is removed without adjusting `required_validators`, it can lead to a situation where `required_validators` exceeds `validator_count`.

**Example**:
If `required_validators` is set to `5` and there are exactly `5` validators, removing `one validator` will make it impossible to achieve the required quorum of `5 signatures`.

The removal of a `validator` without corresponding adjustments can cause legitimate cross-chain messages to be rejected in [`verifyECDSA()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L206-L213).
```solidity
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
>>          if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
>>              return true;
            }
        }

>>      return false;
```
As seen, this function will return `false` if the number of `signatures` does not meet the `required_validators` threshold.

## Recommended Mitigation Steps
1. Prevent the removal of a `validator` if it would cause `required_validators` to exceed `validator_count`.
```diff
    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == true, "Validator does not exist");
        
+       // Check if removing this validator would cause an inconsistency
+       require(
+           validator_count - 1 >= required_validators,
+           "Cannot remove validator: would exceed required validators"
+       );

+       // Proceed with removal
        validators[validator] = false;
        validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }
```
2. Add a check to prevent setting `required_validators` to a value greater than `validator_count` in [`set_required_validators_num()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/SettlementSignatureVerifier.sol#L139-L145).
```diff
    function set_required_validators_num(
        uint256 _required_validators
    ) external virtual onlyRole(MANAGER_ROLE) {

+       // Check that the new required validators count does not exceed the available validators
+       require(
+           _required_validators <= validator_count,
+           "Required validators cannot exceed the number of available validators"
+       );

        uint256 old = required_validators;
        required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
