# Vulnerability details

## Impact
When user calls message to bridge tokens, his funds get locked or even burned.

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L123-L131
```solidity
        if (mode == SettlementMode.MintBurn) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockMint) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.BurnUnlock) {
            _erc20_burn(msg.sender, amount);
        }
```

However if the transaction fails on the target chain, there is no possibility to retrieve funds back.

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L227-L233

        bool result = ISettlementHandler(to_handler).receive_cross_chain_msg(

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement withdraw() function that will allow users to withdraw locked funds for transactions with status `CrossChainMsgStatus.Failed`
Settlement mode `SettlementMode.BurnUnlock` requires different approach. Burning should be made only after transaction on target chain succeed
