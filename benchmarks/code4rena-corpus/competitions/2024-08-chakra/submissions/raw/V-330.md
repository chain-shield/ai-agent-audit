# Vulnerability details

## Impact
The lack of verification for duplicate signatures in the multi-signature verification mechanism introduces a security vulnerability in the contract. This vulnerability allows a malicious actor to reuse the same signature multiple times in a single transaction. As a result, it becomes easier to meet the required number of validator signatures without requiring unique signatures from different validators. This compromises the integrity of the multi-signature process, reducing the security of the system and increasing the risk of unauthorized or fraudulent transactions.

## Proof of Concept
In the following code, the contract iterates over a `signatures` array but fails to verify that each signature comes from a unique validator. The loop processes signatures and counts how many are valid, but duplicate signatures from the same validator are not checked:
```solidity
function verifyECDSA( 
        bytes32 msgHash,
        bytes calldata signatures 
    ) internal view returns (bool) { 
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators 
            ) {
                return true;
            }
        }

        return false;
    }
```
Vulnerability Scenario:
The attacker can submit the same signature from a single validator multiple times.
Since the contract doesn't verify if a validator's signature is repeated, the attacker can artificially inflate the count of valid signatures.
This results in bypassing the multi-signature requirement (i.e., requiring signatures from multiple unique validators).

Example attack:
Assume the system requires 3 unique validators.
The attacker could submit the same signature from one validator three times, and the contract would treat it as valid, fulfilling the requirement of 3 signatures.

## Tools Used
Manual Review

## Recommended Mitigation Steps
To prevent the submission of duplicate signatures, add a verification mechanism that ensures each signature comes from a unique validator. One approach is to maintain a set of validators whose signatures have already been counted during the transaction, and check for duplicates within the signature verification loop.
