# Vulnerability details

## Impact
`ChakraSettlement.receive_cross_chain_msg` is used to transfer token from handler to token receiver on the dest chain. But in current implementation, the function lacks of parameter
to identify the different EVM chain(the protocol will be deployed on Ethereum,Base,Arbitrum,BSC,Optimism,Polygon,zkSync), and it's quite possible that the same address of `to_handle`, `validators` are used in different EVM chain. In such case, the same `ChakraSettlement.receive_cross_chain_msg` tx can be replayed on different chain

## Proof of Concept
As show in [ChakraSettlement.receive_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L170-L244), the message hash is calculated in [ChakraSettlement.sol#L183-L192](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L183-L192), and **while calculating the message_hash, block.chainid is not included**

```solidity

171         uint256 txid,

181         {

184                 abi.encodePacked(
185                     txid,
186                     from_chain,
187                     from_address,
188                     from_handler,
189                     to_handler,
190                     keccak256(payload) <<<--- block.chainid is not included here
191                 )
192             );
...
244     }
```

Because block.chainid is not included, and both the `validators` and `to_handler`'s address can be the same on different chain, for example `0x2d5d7d31F671F86C782533cc367F14109a082712` and `0xB5FB4BE02232B1bBA4dC8f81dc24C26980dE9e3C` are used on ETH/BSC/Polygon

In such case, the same `ChakraSettlement.receive_cross_chain_msg` tx can be replayed on different chain.
Please consider the follow case:
1. Alice calls `handler_erc20.cross_chain_erc20_settlement` to transfer USDT from starknet to ETH
1. On ETH, Alice calls `ChakraSettlement.receive_cross_chain_msg` to receive her assets
1. With the same paremters, Alice can call `ChakraSettlement.receive_cross_chain_msg` on BSC again
