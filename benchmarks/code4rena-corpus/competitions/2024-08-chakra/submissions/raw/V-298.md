# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Unchecked burn_from return value used in the external call cross_chain_erc20_settlement function and receive_cross_chain_callback function via internal call _erc20_burn function.

Title: ChakraSettlementHandler contract has Unchecked burn_from Return Value in _erc20_burn function.
Contract: ChakraSettlementHandler.sol
Issue Type: Unchecked IERC20 burn_from return value.
Functions: _erc20_burn(), cross_chain_erc20_settlement(), & receive_cross_chain_callback().

The _erc20_burn function calls IERC20Burn(token).burn_from(account, amount) without verifying the return value of the external call. According to best practices, the return value of external calls must always be checked, especially for critical operations like burning tokens. If the burn_from function fails silently (i.e., returns false), the system may incorrectly assume the burn operation succeeded, leading to discrepancies in cross-chain settlements, incorrect balances, and potential financial loss.

In cross-chain settlement modes, where tokens are burned (e.g., BurnUnlock or MintBurn), an unchecked burn operation may result in double spending or an inflationary scenario where tokens on the source chain remain, while tokens on the destination chain are minted, thus breaking the economic assumptions of the settlement mechanism.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

Assume the IERC20Burn contract’s burn_from function fails due to a bug or some other issue, returning false instead of burning the tokens and reverting. This would cause the settlement system to proceed under the false assumption that the burn succeeded:
```sol
contract FaultyBurnableToken {
    mapping(address => uint256) public balances;
    
    function burn_from(address account, uint256 amount) external returns (bool) {
        // Return false instead of burning tokens, causing silent failure
        return false;
    }
}
```
Consider the following flow:

	1.	A cross-chain settlement is initiated via cross_chain_erc20_settlement.
	2.	The _erc20_burn function is called in BurnUnlock mode.
	3.	The burn operation silently fails, but the settlement continues as if the burn was successful.
	4.	The tokens are not burned, leading to an incorrect token supply and breaking the cross-chain logic.

The issue can be reproduced with the following code:
```sol
function _erc20_burn(address account, uint256 amount) internal {
    require(
        IERC20(token).balanceOf(account) >= amount,
        "Insufficient balance"
    );
    // Silent failure if burn_from returns false
    IERC20Burn(token).burn_from(account, amount);
}

// In `cross_chain_erc20_settlement` or `receive_cross_chain_callback`, _erc20_burn is called without checking success
if (mode == SettlementMode.BurnUnlock) {
    _erc20_burn(msg.sender, amount); // Assumes burn succeeded, even if it didn't
}
```

## Recommended Mitigation Steps

The contract should handle the return value of burn_from to ensure that the burn operation was successful. If burn_from returns false, the transaction should revert to prevent further operations based on the assumption that tokens were burned.

Mitigated Code for _erc20_burn:
```sol
function _erc20_burn(address account, uint256 amount) internal {
    require(
        IERC20(token).balanceOf(account) >= amount,
        "Insufficient balance"
    );

    // Check return value to ensure successful burn
    bool success = IERC20Burn(token).burn_from(account, amount);
    require(success, "Token burn failed");
}
```
In the cross_chain_erc20_settlement and receive_cross_chain_callback functions, this will ensure that any silent failure of burn_from will revert the transaction, maintaining the integrity of the cross-chain settlement system and preventing unintended outcomes such as token supply issues.
