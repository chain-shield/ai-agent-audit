# Vulnerability details

## Impact
Failure to comply with `EIP712` can lead to integration issues and potentially cause a denial of service.

## Proof of Concept
Chakra contract fails to implement the EIP712 in several cases.
According to the [`EIP712 Standard`](https://eips.ethereum.org/EIPS/eip-712):

The dynamic values bytes and string are encoded as a keccak256 hash of their contents.
However, in the function `receive_cross_chain()`, the hashing process is handled as follows:
```solidity
function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
        {
            // verify signature
            bytes32 message_hash = keccak256(
                abi.encodePacked(
                    txid,
>>                  from_chain,
                    from_address,
                    from_handler,
                    to_handler,
                    keccak256(payload)
                ) 
            );
```
As observed, `from_chain` is `string` value. The hashing (slot) directly encodes this value instead of using the `keccak256` hash of its contents as mandated by the standard.

The same is also observed in `send_cross_chain_msg` function
```solidity
   function send_cross_chain_msg(
        string memory to_chain,
        address from_address,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload
    ) external {
        nonce_manager[from_address] += 1;

        address from_handler = msg.sender;

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
>>                  contract_chain_name, // from chain
>>                  to_chain,
                    from_address, // msg.sender address
                    from_handler, // settlement handler address
                    to_handler,
                    nonce_manager[from_address]
                ) 
            )
        );
```
Here too, `to_chain` and `contract_chain_name` are `string` that are encoded as they are.

## Recommended Mitigation Steps
Here is the correct implementation; for `receive_cross_chain_msg`
```diff
function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
        {
            // verify signature
            bytes32 message_hash = keccak256(
                abi.encodePacked(
                    txid,
-                   from_chain,
+                   keccak256(from_chain),
                    from_address,
                    from_handler,
                    to_handler,
                    keccak256(payload)
                ) 
            );
```
For `send_cross_chain_msg`
