# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: Settlement/SettlementSignatureVerifier contract has Denial of Service (DoS) with Block Gas Limit in verify function
•	Severity: Medium
•	Impact: The verifyECDSA function in the SettlementSignatureVerifier contract iterates over the signatures array to validate each signature.
•	Status: Unresolved
•	File: SettlementSignatureVerifier.sol
•	Lines Affected: 174-214

The verifyECDSA function in the SettlementSignatureVerifier contract iterates over the signatures array to validate each signature. If the array is very large, this iteration could consume more gas than the block gas limit allows, potentially leading to a Denial of Service (DoS). This would prevent the transaction from being included in a block, effectively halting the contract’s operations. 

If the signatures array is large enough, it could lead to a situation where the gas required to process all signatures exceeds the block gas limit. This would cause the transaction to revert, making it impossible to process the verification. Consequently, this could prevent legitimate operations from being executed, leading to a denial of service.

## Recommended Mitigation Steps
To mitigate this issue, consider limiting the number of signatures that can be processed in a single transaction. Alternatively, implement a mechanism that allows for batching of signature verification across multiple transactions, ensuring that no single transaction can exceed the block gas limit.

Coded Mitigation

1. Limit the Maximum Number of Signatures:
• Introduce a maximum allowed number of signatures in the verifyECDSA function.
```sol
uint256 public constant MAX_SIGNATURES = 100;  // Set an upper limit on the number of signatures

function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );
    require(
        signatures.length / 65 <= MAX_SIGNATURES,
        "Too many signatures"
    );

    uint256 len = signatures.length;
    uint256 m = 0;
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
    }

    return false;
}
```
2. Batch Processing of Signatures:
• Implement a mechanism to process signatures in batches, possibly across multiple transactions, ensuring that no single transaction exceeds the block gas limit.
```sol
// Add a function to verify signatures in batches
function verifyECDSABatch(
    bytes32 msgHash,
    bytes calldata signatures,
    uint256 batchSize
) external view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );
    require(batchSize <= MAX_SIGNATURES, "Batch size too large");

    uint256 len = signatures.length;
    uint256 m = 0;
    uint256 processed = 0;

    for (uint256 i = 0; i < len && processed < batchSize; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
        processed++;
    }

    return false;
}
```
While the verifyECDSA function is generally secure, its current implementation could be exploited to create a denial of service by submitting a large number of signatures in a single transaction. By introducing a maximum signature limit or implementing batch processing, this risk can be effectively mitigated, ensuring the contract remains functional even under heavy load.
