# Vulnerability details


## Summary

The `send_cross_chain_msg` function in `settlement.cairo` allows users to initiate cross-chain transactions without paying for gas fees on the destination chain. This oversight can lead to economic imbalances, potential Denial of Service (DoS) attacks, and unfair resource consumption across different blockchains in the Chakra network, specifically when interacting with StarkNet.

## Impact

The `send_cross_chain_msg` function in `settlement.cairo` allows users to initiate cross-chain transactions without paying for gas fees on the destination chain. This can lead to several significant issues:

1. Economic imbalance: Users can flood the destination chain with transactions without bearing the associated costs, potentially leading to network congestion and increased gas prices for legitimate users on that chain.

2. Denial of Service (DoS) vulnerability: Malicious actors could exploit this to overwhelm the destination chain with a large number of cross-chain messages, causing performance degradation or even halting the network.

3. Unfair resource consumption: Users on the destination chain may end up subsidizing the execution costs of cross-chain messages, leading to an unfair distribution of network resources.

## Proof of Concept

The issue can be observed in the: [`send_cross_chain_msg` function of settlement.cairo](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/settlement/src/settlement.cairo#L280-L316):

```rust
fn send_cross_chain_msg(
    ref self: ContractState, to_chain: felt252, to_handler: u256, payload_type: u8, payload: Array<u8>,
) -> felt252 {
    let from_handler = get_caller_address();
    let from_chain = self.chain_name.read();
    let cross_chain_settlement_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.tx_count.read());
    self.created_tx.write(cross_chain_settlement_id, CreatedTx{
        tx_id: cross_chain_settlement_id,
        tx_status: CrossChainMsgStatus::PENDING,
        from_chain: from_chain,
        to_chain: to_chain,
        from_handler: from_handler,
        to_handler: to_handler
    });
    self.emit(
        CrossChainMsg {
            cross_chain_settlement_id: cross_chain_settlement_id,
            from_address: get_tx_info().unbox().account_contract_address,
            from_chain: from_chain,
            to_chain: to_chain,
            from_handler: from_handler,
            to_handler: to_handler,
            payload_type: payload_type,
            payload: payload
        }
    );
    self.tx_count.write(self.tx_count.read()+1);
    return cross_chain_settlement_id;
}
```

As we can see, this function allows a user to send a cross-chain message without any mechanism to collect or reserve gas fees for the destination chain. The transaction is created and emitted without any consideration for the execution costs on the receiving end.

## Recommended Mitigation Steps

To address this issue, consider implementing the following measures:

1. Gas fee estimation and collection: Implement a mechanism to estimate the gas cost on the destination chain and collect it from the user initiating the cross-chain transaction. This could be done by maintaining an oracle that provides gas price information for supported chains.

2. Deposit system: Require users to deposit funds in a contract on the destination chain before they can send cross-chain messages. These funds would be used to cover gas costs for incoming messages.
