# Vulnerability details

## Impact

The function casts a 'uint256' to an address by first converting it to a 'uint160'.

'uint160' is unsafe when you cast from larger types like 'uint256' without ensuring that the value fits within the 160-bit range, as this can result in data truncation and potential vulnerabilities.

Casting a 'uint256' to 'uint160' truncates the upper 96 bits (256 - 160 = 96). This means if the original 'uint256' contains important data in those upper 96 bits, it will be lost in the conversion, leading to incorrect results. If that 'uint256' is supposed to be an address but contains extra data, you could end up with an invalid or unintended address.

If the input to the cast comes from an untrusted source (such as user input or external contract data), malicious actors could potentially manipulate the input in a way that causes unexpected truncation, leading to incorrect or insecure behavior in your smart contract. This could expose the contract to attacks, such as:
1. Sending tokens to incorrect addresses.
2. Allowing unintended access to contract functions.

    using AddressCast for uint256;

    function testUnsafeCastingLeadsToIncorrectAddress() public {
        // Create a uint256 with data in the upper 96 bits
        uint256 maliciousInput = uint256(0x1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef);

        // Cast the uint256 to an address
        address result = maliciousInput.to_address();

        // The expected address should only consider the lower 160 bits
        address expected = address(uint160(maliciousInput));

        // Assert that the result matches the expected address
        assertEq(result, expected);

        // Assert that the result does not match the original malicious input
        assert(result != address(uint160(maliciousInput >> 96)));
    }
}

## Recommended Mitigation Steps

It is generally safer to ensure that the input is within the 160-bit range before casting it to an address, especially if the input originates from untrusted sources (such as user input or external contract data).
