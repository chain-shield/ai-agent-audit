# Vulnerability details

## Impact
The validators have no control over the execution of the cross-chain callback, meaning they cannot stop it even when they want to. This issue applies only for the Cairo contracts.

## Description
The `receive_cross_chain_callback()` function of `settlement.cairo` is not used anywhere in the function, except for the event emitted at the bottom. The status assigned to the transaction is determined by the result of the `handler.receive_cross_chain_callback` call, which is always TRUE:

```cairo
 fn receive_cross_chain_callback(
            ref self: ContractState,
            cross_chain_msg_id: felt252,
            from_chain: felt252,
            to_chain: felt252,
            from_handler: u256,
            to_handler: ContractAddress,
     ------>       cross_chain_msg_status: u8,
            sign_type: u8,
            signatures: Array<(felt252, felt252, bool)>,
        ) -> bool {
            ......
            let handler = IHandlerDispatcher{contract_address: to_handler};
            let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
            let mut state = CrossChainMsgStatus::PENDING;
            if success{
                state = CrossChainMsgStatus::SUCCESS;
            }else{
                state = CrossChainMsgStatus::FAILED;
            }
            
            self.created_tx.write(cross_chain_msg_id, CreatedTx{
                tx_id:cross_chain_msg_id,
                tx_status:state,
                from_chain: to_chain,
                to_chain: from_chain,
                from_handler: to_handler,
                to_handler: from_handler
            });

            ......
            return true;
        }

```

This deviates from the design set in the Solidity contracts:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L317-L330

```solidity

...

if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
....
```

As you can see if the result from the `handler.receive_cross_chain_callback()` is true the status provided as input to the function is used (e.g the status signed by the validators).

This makes sense since the validators are off-chain nodes tha validate the integrity of the data ( maybe check for blacklists, suspicious parameters, etc.) and then decide if the transaction should execute. 

For example the transaction parameters might be valid, but the sender might be blacklisted address and they provide `Failed` as `status` to prevent the transaction from being executed (even though it can)


This however is not possible for the cairo contracts, since the input `cross_chain_msg_status` is never actually used and since `handler.receive_cross_chain_callback()` always succeeds, the validators have no mechanism to prevent it's execution if that is necessary.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement the status logic for the callbacks in the Cairo contracts the same way as in the Solidity contracts.
