# Vulnerability details

## Impact

In `settlement.cairo` smart contract, `receive_cross_chain_msg()` function is used to receive cross chain message from the Chakra Network, make all the verification processes and call the handler to update the status of the transaction. However, there is no check for the txId to be `Unknow` as it's required by the specification.

## Proof of Concept

Currently there is no any check for `Unknow` status of the tx in `receive_cross_chain_msg()`:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L325-383

As you can see, the following check is successfully implemented on Ethereum:


https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L199-202
```
  require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );
```


As per specification:
```
A cross-chain message can only be received once. The status of a received transaction in receive_cross_txs must be CrossChainMsgStatus.Unknow before it can be processed.
```

Such missing check allows to process a transaction with some different status rather than `Unknow`.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Implement the same check on the Starknet chain as on Ethereum.
