# Vulnerability details

## Impact
If a single validator is compromised, it could sign a message that would cause `ERC20Handler` to unlock a large number of locked assets and send them to an attacker's address.

The purpose of having the storage variable `required_validators_num` in the `ChakraSettlement` contracts is to provide a level of protection against a single validator being compromised. If that were to happen, it would not be desirable for the entire protocol to be compromised. Similarly, once the TVL of Chakra becomes significant, the incentive for a single validator to sign a bad message could become significant, allowing themselves to potentially steal large amounts of locked assets.

If any single validator can unilaterally sign messages, the entire Chakra protocol becomes as strong as its weakest validator.

## Proof of Concept
When `ChakraSettlement.receive_cross_chain_msg()` receives a cross chain message, it calls `self.check_chakra_signatures()` to validate the signatures. This function contains a loop which steps through the `signatures` array and checks each one to see if it is a valid signature of a validator. This is done by calling `core::ecdsa::recover_public_key()` on the individual signature and then looking up the returned public key in the `LegacyMap` `chakra_validators_pubkey`. If it is found, then the variable `pass_count` is incremented.

However, there is nothing in this logic to prevent the `signatures` array from consisting of the same single signature repeated multiple times. This would repeatedly pass the test on lines 183/184:
```
let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
if self.chakra_validators_pubkey.read(pub_key) > 0{
```
This would increase the variable `pass_count` as many times as the signature is repeated, and so allow a single signature to count as enough to satisfy the condition of needing `required_validators_num` signatures to validate a received cross chain message, regardless of the value of `required_validators_num`.

## Tools Used
Manual inspection

## Recommended Mitigation Steps
As well as incrementing `pass_count` inside `check_chakra_signatures()`, create an empty `seen_pubkeys` array. When a signature is confirmed as coming from a known validator, check for the validator's address in this array and, if it is not found, add it. It may be useful to make use of a library that implements unique arrays with lookup functions.
