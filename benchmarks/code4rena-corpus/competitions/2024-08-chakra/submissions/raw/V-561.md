# Vulnerability details

## Impact
The current implementation of the cross-chain messaging system in the Cairo contracts is vulnerable to signature replay attacks. This vulnerability could lead to unauthorized minting or unlocking of tokens on the destination chain, potentially resulting in significant financial losses.
Unlike the Solidity implementation, which checks for transaction status before processing, the Cairo version lacks this crucial check. This omission allows an attacker to replay a valid cross-chain message multiple times, each time triggering the minting or unlocking of tokens.

## Proof of Concept
1. An attacker observes a valid cross-chain message being processed (or creates a valid one themselves)
2. The attacker captures the message details, including the signature.
3. The attacker repeatedly calls the receive_cross_chain_msg function on the settlement contract with the same message and signature.
4. For each call, the settlement contract verifies the signature (which is valid) and forwards the message to the handler.
5. The handler processes the message each time, minting or unlocking tokens without checking if the message has been processed before.

Key vulnerabilities in the code:

In ChakraSettlement:
```
fn receive_cross_chain_msg(
    ref self: ContractState,
    cross_chain_msg_id: u256,
    // ... other parameters ...
) -> bool {
    // No check for existing transaction status
    
    // Signature verification (doesn't prevent replay)
    self.check_chakra_signatures(message_hash, signatures);
    
    // Processing message
    let handler = IHandlerDispatcher{contract_address: to_handler};
    let success = handler.receive_cross_chain_msg(/* ... */);
    
    // Storing transaction status after processing
    self.received_tx.write(cross_chain_msg_id, ReceivedTx{
        // ... transaction details ...
    });
    
    return true;
}
```

In ERC20Handler:
```
fn receive_cross_chain_msg(
    ref self: ContractState,
    cross_chain_msg_id: u256,
    // ... other parameters ...
) -> bool {
    // No check for message uniqueness or previous processing
    
    // Processing message and minting/unlocking tokens
    if self.mode.read() == SettlementMode::MintBurn {
        erc20.mint_to(u256_to_contract_address(transfer.to), transfer.amount);
    } else if /* ... other modes ... */ {
        // Similar operations for other modes
    }
    
    return true;
}
```

In contrast solidity contract has a check 
`   require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );`

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a check in the settlement contract to ensure the message hasn't been processed before.
