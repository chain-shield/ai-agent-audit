# Vulnerability details

One of the key components is the SettlementSignatureVerifier contract, which is responsible for verifying the signatures of validators during the settlement process. This contract inherits from OwnableUpgradeable, UUPSUpgradeable, and AccessControlUpgradeable contracts from the OpenZeppelin library.

The SettlementSignatureVerifier contract allows the addition and removal of validators and managers, and it provides functions to verify signatures using ECDSA (Elliptic Curve Digital Signature Algorithm).

The specific logic of where the issue lies is within the [verifyECDSA function](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/SettlementSignatureVerifier.sol#L120-L137)
```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    // ...
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
            return true;
        }
    }
    // ...
}
```
The issue lies in the condition `validators[msgHash.recover(sig)] && ++m >= required_validators` within the `verifyECDSA` function. This condition allows the function to return `true` prematurely when the number of valid signatures (`m`) reaches the `required_validators` threshold, without verifying all the `signatures` in the signatures array.

## Impact
By providing a signatures array with fewer valid signatures than the required number, the attacker can still make the `verifyECDSA` function return `true`. This can lead to unauthorized settlements and potentially cause financial losses for the affected parties.

For example, let's say the `required_validators` is set to 3, meaning at least 3 valid signatures are required for a successful settlement. An attacker can construct a `signatures` array with only 2 valid signatures and some invalid ones. Due to the flawed condition in `verifyECDSA`, the function will return `true` as soon as it encounters the 2 valid signatures, even though the total number of valid signatures is less than the required amount.

## Proof of Concept
* The settlement process is initiated with a `msgHash` and a `signatures` array.
* The `verifyECDSA` function is called to validate the signatures.
* The attacker provides a signatures array with fewer valid signatures than `required_validators.`
* The loop in `verifyECDSA` iterates through the signatures.
* When a valid signature is encountered, `m` is incremented.
* As soon as `m` reaches `required_validators`, the function returns `true`, even though not all signatures have been verified.
* The settlement process proceeds with insufficient valid signatures, potentially leading to unauthorized actions and financial losses.

Recommended Mitigation Steps
Only return `true` if the number of valid signatures (`m`) is greater than or equal to `required_validators` after verifying all the signatures in the loop.
```diff

    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    // ...
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];

-       ) {
-           return true;
-       }

+           ++m;
+       }
    }

    // ...
```
