# Vulnerability details

Function `receive_cross_chain_callback` in settlement.cairo does not check the status of cross chain message coming from destination chain. 
Specifically, there is a CrossChainHandleResult event that is monitored by validators, which call `receive_cross_chain_callback` in settlement.cairo.
Function `receive_cross_chain_callback` calls `receive_cross_chain_callback` in handler_erc20.cairo. Depending on the result of the handler call, the cross_chain_msg_status will be set in `receive_cross_chain_callback` in settlement.cairo:
```
let handler = IHandlerDispatcher{contract_address: to_handler};
            let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
            let mut state = CrossChainMsgStatus::PENDING;
            if success{
                state = CrossChainMsgStatus::SUCCESS;
            }else{
                state = CrossChainMsgStatus::FAILED;
            }
```
However, in the code shown above, the status of message coming from destination chain is not considered for setting cross_chain_msg_status. Indeed, as it is done in function `processCrossChainCallback` in ChakraSettlement.sol, it is required to set the status of the message to the status value coming from the destination chain not CrossChainMsgStatus::SUCCESS (when the return value of handler function is true):
```
if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status; 
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
```
However, in function `receive_cross_chain_callback` in settlement.cairo, even if the status of the message coming from destination is FAILED, cross_chain_msg_status will be set to CrossChainMsgStatus::SUCCESS.

## Recommended Mitigation Steps
Modifying `state = CrossChainMsgStatus::SUCCESS;` in function receive_cross_chain_callback in settlement.cairo to `state = cross_chain_msg_status;` can address this issue.
