# Vulnerability details

## Summary
Summary
The ChakraTokenUpgradeTest.sol contract attempts to implement upgrade functionality without properly inheriting from the UUPSUpgradeable contract, leading to non-functional upgrade mechanisms.

## Vulnerability Detail
The contract implements upgrade-related functions but does not inherit from UUPSUpgradeable:
```
contract ChakraTokenUpgrade is ERC20Upgradeable, TokenRoles {
    // ...
    function _authorizeUpgrade(address newImplementation) internal override onlyOwner {}
    // ...
}
```
The contract imports UUPSUpgradeable but does not use it:
```
import "@openzeppelin/contracts-upgradeable/proxy/utils/UUPSUpgradeable.sol";
```
## Impact

If a critical bug is discovered within the ChakraTokenUpgrade contract after deployment that causes a loss of assets, the contract cannot be properly upgraded to fix the bugs. All assets within the contract will be at risk, and the contract will be unable to implement necessary security updates or feature improvements.


## Recommended Mitigation Steps
1. Inherit from UUPSUpgradeable:
```
contract ChakraTokenUpgrade is ERC20Upgradeable, TokenRoles, UUPSUpgradeable {
    // ...
}
```
2. Initialize the UUPS functionality in the initialize function:
```
function initialize(
    address _owner,
    address _operator,
    string memory _name,
    string memory _symbol,
    uint8 _decimals
) public initializer {
    __TokenRoles_init(_owner, _operator);
    __ERC20_init(_name, _symbol);
    __UUPSUpgradeable_init();  // Add this line
    set_decimals = _decimals;
}
```
