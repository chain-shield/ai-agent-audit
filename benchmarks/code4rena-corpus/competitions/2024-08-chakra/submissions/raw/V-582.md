# Vulnerability details

Validators verify messages/callbacks. A required number of validators is required to pass verification process.

However if the threshold is high, no messages/callbacks can be verified.

## Proof of Concept
Whenever a validator is added or removed, the `validator_count` is updated to track the existing of validators in the protocol.
```solidity
File: SettlementSignatureVerifier.sol

   function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == false, "Validator already exists");
        validators[validator] = true;
>       validator_count += 1;
        emit ValidatorAdded(msg.sender, validator);
    }

    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == true, "Validator does not exists");
        validators[validator] = false;
 >      validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }
```
`set_required_validators_num` sets the number of validators required to verify a message.

```solidity
File: SettlementSignatureVerifier.sol

    function set_required_validators_num(
        uint256 _required_validators
    ) external virtual onlyRole(MANAGER_ROLE) {
        uint256 old = required_validators;
>       required_validators = _required_validators;
        emit RequiredValidatorsChanged(msg.sender, old, required_validators);
    }
```
However the Manager can call the `set_required_validators_num` to change the number of validators. If the `required_validators` is greater than `validator_count`, verification will always return `false`

```solidity
File: SettlementSignatureVerifier.sol
   
  function verifyECDSA(
    ...
      if (
>         validators[msgHash.recover(sig)] && ++m >= required_validators      
      ) {
          return true;
      }
    }
    return false;
``` 
There is no check to ensure that the new threshold would not be greater than the current number of existing validators. In such a case, the cross chain messages & callbacks will always revert.

### Scenario 1 (more likely)
- There are 10 validators. `required_validators` is set to 6.
- Manager removes 5 validators making `validator_count` to 5.
- Receive functions revert.

### Scenario 2 (less likely)
- There are 10 validators. `required_validators` is set to 6.
- Manager sets the `required_validators` to 12.
- Receive functions revert.

Same issue in the [SettlementSignatureVerifier](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/SettlementSignatureVerifier.sol) in the Handler contracts.

## Tools Used
Manual Review

## Recommended Mitigation Steps
- Add a check in `set_required_validators_num` to ensure than the required number of validators does not exceed the current number of validators in the system.
- Also add a check in `remove_validator` so that the `validator_count` does not go below `required_validators`.
