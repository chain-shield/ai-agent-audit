# Vulnerability details

The `ChakraSettlement::receive_cross_chain_msg()` function processes cross-chain messages and relies on the `SettlementSignatureVerifier::verify()` function to validate these messages. The `SettlementSignatureVerifier::verifyECDSA()` function, which is invoked by `verify()`, checks if each `signature` in the provided signatures array is signed by a recognized validator. However, it does not ensure that each signature is unique. The function iterates through the `signatures` array, and once the number of valid signatures meets the `required_validators` threshold, the function returns `true`.

This implementation flaw allows an attacker to reuse the same valid signature multiple times within the `signatures` array to meet the `required_validators` condition. This effectively renders the required_validators parameter meaningless, as the security of the cross-chain message verification process is compromised. The issue is exacerbated by the fact that the `ISettlementHandler(to_handler).receive_cross_chain_msg()` function does not perform additional checks on the message parameters and executes the contents of the `payload` directly.

## Impact
The lack of signature uniqueness verification in the `SettlementSignatureVerifier::verifyECDSA()` function allows an attacker to circumvent the `required_validators` threshold by reusing a single valid signature multiple times. This significantly undermines the security of the cross-chain message processing system, potentially leading to unauthorized asset transfers, message forgery, and overall system compromise.

## Recommended Mitigation Steps
To address this issue, implement a check for signature uniqueness within the `SettlementSignatureVerifier::verifyECDSA()` function. This can be done by storing the addresses of validators that have already signed the message in a mapping and ensuring that each validator's signature is only counted once.

Here is a modified version of the `verifyECDSA()` function that includes the recommended mitigation:
