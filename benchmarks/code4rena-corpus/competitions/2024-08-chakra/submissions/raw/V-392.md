# Vulnerability details

## Impact
To complete a successful ERC20 cross-bridge, user calls `handler_erc20.cross_chain_erc20_settlement` tx to lock the assets, and afterwards `settlement.receive_cross_chain_callback` will be called to burn the `MintBurn` type token if needed, and set the necessary global state.
But there is a issue in current implementation that after `settlement.send_cross_chain_msg` is directly called by a malicious user, `handler_erc20.receive_cross_chain_callback` will be broken.

## Proof of Concept
1. when a normal user calls [handler_erc20.cross_chain_erc20_settlement](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L167-L232) to bridge tokens, `tx_id` will be generated as [LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.msg_count.read())](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L183), **please note that `self.msg_count.read()` is used here**
2. then the function will call [settlement.send_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L216)
3. in [settlement.send_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L283-L314), `cross_chain_settlement_id` is generated based on [LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.tx_count.read())](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L289), **and please note that `self.tx_count.read()` is used here**
4. after `settlement.send_cross_chain_msg` is executed, [settlement.receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L392-L442) will be called, to pass the check in [settlement.cairo#L404-L409](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L404-L409), the `cross_chain_msg_id` parameter must be equal to [cross_chain_settlement_id in settlement.cairo#L289](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L289)
5. then `handler.receive_cross_chain_callback` is called in [settlement.cairo#L415](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L415), and `cross_chain_msg_id` is passed in
6. in [handler_erc20.receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L137-L165), `cross_chain_msg_id` is directly used in [handler_erc20.cairo#L149](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L149) and [handler_erc20.cairo#L152-L162](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L152-L162). 

**So In order to execute `handler_erc20.receive_cross_chain_callback` correctly, `cross_chain_msg_id` must be equal to `txid` in [handler_erc20.cairo#L183](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L183)**. Which means that [self.msg_count.read()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L183) must be equal to [self.tx_count.read()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L289).

But in current implementation, `settlement.send_cross_chain_msg` doesn't have access control, and anyone can call the function, thus after calling the function, `self.tx_count` will be increased by one in [settlement.cairo#L312](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L312). 

In such case, [self.tx_count.read()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L289) and [self.msg_count.read()](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L183) will be different.

So next time, when `handler_erc20.cross_chain_erc20_settlement` is called, the `tx_id` used as index to store `created_tx` in [handler_erc20.cairo#L195](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L195) will be different from the `cross_chain_msg_id` used in [handler_erc20.cairo#L149](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L149) and [handler_erc20.cairo#L152-L162](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L152-L162)
