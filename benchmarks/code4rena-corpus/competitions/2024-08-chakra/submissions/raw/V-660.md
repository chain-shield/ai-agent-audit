# Vulnerability details

According to the documentation, the validators are not trusted (only operators are). To reduce the likelyhood of malicious actions or handle cases, such as receiving the same cross chain message multiple times and draining the protocol, the team has decided to require multiple validators to sign the transactions.

However, the `set_required_validators_num` function (in all its appearances across the code) allows the manager (`MANAGER` role is not in the list of trusted roles) to set the `required_validators` value to zero or one. This way, only one validator would be enough to pass the signature verification and manipulate the protocol. 

## Impact

A single malicious or compromised validator can pass the whole signature verification process and manipulate the protocol, by, for instance, receiving the same cross chain message multiple times and draining the protocol.

## Tools Used

Manual review

## Recommended Mitigation Steps

To mitigate this, require the `required_validators` value to be at least 3 when assigning it through the `set_required_validators_num` function.
