# Vulnerability details

### Description
The `receive_cross_chain_callback()` function is responsible for handling cross-chain execution responses and verifying their authenticity through a provided signature. However, the current implementation lacks mechanisms to prevent the replay of previously processed transactions. This oversight allows an attacker to reuse the same signature to execute a cross-chain message multiple times, potentially leading to unauthorized actions or repeated executions of the same transaction in this case if the mode set in the `erc_handler.cairo` it burns the erc20 tokens the amount specified everytime

The vulnerability arises from two main issues:

`Absence of Nonce Management`: The function does not implement nonce tracking to uniquely identify each cross-chain callback. Without nonce management, a signature used in one transaction can be reused in another, enabling attackers to replay the same transaction repeatedly.

`Lack of Deadline Parameter`: There is no deadline or expiration mechanism associated with the transactions. This absence allows signatures and nonces to remain valid indefinitely, increasing the risk of replay attacks. Without a deadline, transactions can be executed at any time, further amplifying the potential for misuse.

### Recommendation 

1. Implement nonce management:
   Add a nonce to each cross-chain message and store it in the contract state. Increment the nonce for each new message.

2. Add expiration mechanism:
   Include a deadline parameter in cross-chain messages. Check if the current timestamp is within the valid range before processing.

3. Prevent signature replay:
   Store processed message IDs and check against them before execution.
