# Vulnerability details

## Impact

Users may send a cross-chain message to the wrong destination, leading to locked funds.

## Proof of Concept

Users call `ChakraSettlementHandler.cross_chain_erc20_settlement()` to start the cross-chain messaging process. They set the `to_chain`, and `to_handler` in the parameter. Users then transfer / burn their tokens on the source chain and wait for their tokens on the destination chain.

```
   function cross_chain_erc20_settlement(
        string memory to_chain,
        uint256 to_handler,
        uint256 to_token,
        uint256 to,
        uint256 amount
    ) external {
        require(amount > 0, "Amount must be greater than 0");
        require(to != 0, "Invalid to address");
        require(to_handler != 0, "Invalid to handler address");
        require(to_token != 0, "Invalid to token address");
```

Note that `to_chain` and `to_handler` is not checked. If they provide an incorrect address, eg to a wrong chain or the wrong settlementHandler contract, they will be unable to receive any message from the destination chain, and their funds will be locked in the source chain.

Currently, the `is_valid_handler()` check is only done when receiving tokens from source chains.

In the cairo counterpart contract, the chain and handler is checked when calling `cross_chain_erc20_settlement()`


Since the protocol uses an upgradeable contract, it may get confusing to know what the actual handler address is, whether it's the proxy, the implementation, or the upgraded implementation so this issue is not a simple user error. Also, the user may not know which chains the protocol is currently adapting.

Ensure that the handler and the chain is correct from the user's input.
