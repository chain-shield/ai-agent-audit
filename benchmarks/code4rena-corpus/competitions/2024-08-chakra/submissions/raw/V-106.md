# Vulnerability details

## Impact
The `receive_cross_chain_msg` function in the Cairo code of the `ChakraSettlement` contract lacks proper checks to prevent the same transaction from being processed multiple times. This absence of a replay protection mechanism allows an attacker to resend the same transaction (cross_chain_msg_id) repeatedly. 

## Proof of Concept
The vulnerability exists in the `receive_cross_chain_msg` function, where there is no mechanism to check if a transaction has already been processed. This function calls `handler.receive_cross_chain_msg()` function but there is no validation inside this contract. So if a user has signatures for a valid transaction this function can be called multiple times.


```cairo
        fn receive_cross_chain_msg(
            ref self: ContractState,
            cross_chain_msg_id: u256,
            from_chain: felt252,
            to_chain: felt252,
            from_handler: u256,
            to_handler: ContractAddress,
            sign_type: u8,
            signatures: Array<(felt252, felt252, bool)>,
            payload: Array<u8>,
            payload_type: u8,
        ) -> bool {
            assert(to_chain == self.chain_name.read(), 'error to_chain');

            // verify signatures
            let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
            let payload_span = payload.span();
            let mut i = 0;
            loop {
                if i > payload_span.len()-1{
                    break;
                }
                message_hash = LegacyHash::hash(message_hash, * payload_span.at(i));
                i += 1;
            };
            self.check_chakra_signatures(message_hash, signatures);
```
