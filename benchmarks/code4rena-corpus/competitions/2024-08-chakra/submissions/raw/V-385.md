# Vulnerability details

## Impact
One of the invariants about the Settlement Contract in the README of the audit states that: 

`Only valid settlement handlers can process received cross-chain messages and callbacks.`

The problem is that the `ChakraSettlement::processCrossChainCallback()` does not provide a check if the handler is valid which breaks the invariant

## Proof of Concept

This is the current implementation of the function:

```solidity

function processCrossChainCallback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) internal {
        require(
            create_cross_txs[txid].status == CrossChainMsgStatus.Pending,
            "Invalid transaction status"
        );

        if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
     
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
    }
```
As we can see the `chakra_validators` are not used in it so the handler is not being checked as it is supposed to.

Verify the handlers using the already implemented mapping `chakra_validators`
