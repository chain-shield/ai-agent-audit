# Vulnerability details

## Impact
The `to_address` function in the `AddressCast.sol` library casts a `bytes32` value to an `address` by first converting it to `uint256` and then truncating it to `uint160`. This truncation discards the most significant 96 bits of the `bytes32` value. If the input `bytes32` value contains non-zero data in the most significant 96 bits, that data will be lost, leading to an incorrect `address` being returned.

This issue can result in incorrect behavior if the input `bytes32` value is not properly validated. Specifically, if the input is expected to represent an `address`, the most significant 96 bits should always be zero. However, if the input is arbitrary or comes from an untrusted source, there is a risk that the truncation could lead to an invalid or unintended `address`.

## Proof of Concept
The issue occurs in the following function in the `AddressCast.sol` file:

```solidity
function to_address(
    bytes32 _address
) internal pure returns (address result) {
    result = address(uint160(uint256(_address)));
}
```

### Example of Truncation:
If the input `_address` is the following `bytes32` value:

```
0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF000000000000000000000000
```

- The most significant 96 bits (`0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF`) will be discarded when casting to `uint160`.
- The resulting `address` will be:

```
0x0000000000000000000000000000000000000000
```

This is not the intended behavior, as the original `bytes32` value contained non-zero data in the most significant bits.

## Recommended Mitigation Steps
To prevent this truncation issue, add a validation check to ensure that the most significant 96 bits of the `bytes32` value are zero before performing the cast. Here's the recommended fix:

```solidity
function to_address(
    bytes32 _address
) internal pure returns (address result) {
    // Ensure that the most significant 96 bits are zero
    if (uint256(_address) >> 160 != 0) {
        revert AddressCast_InvalidAddress();
    }
    result = address(uint160(uint256(_address)));
}
```

This check ensures that the input `bytes32` value is within the valid range for an `address`, preventing unintended truncation of important data.
