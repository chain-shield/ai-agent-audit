# Vulnerability details

## Impact
Signatures in `receive_cross_chain_callback()` and `receive_cross_chain_msg()` are replayable because the message hashes do not include a nonce, they are generated from the inputs provided in as arguments for the function. This means that anyone can just monitor the mempool and get a valid signature that he can use and also the `check_chakra_signatures()` function does not invalidate an already used signature so a malicious user can just get a valid signature from the mempool and pass it multiple times in the `signatures` array to bypass the `required_validators_num` and successfully sign a transaction. There will be transaction that should revert because the `required_validators_num` are not reached, but an attacker can bypass this and successfully sign a transaction that should have reverted

There is nothing that invalides an already used signature which makes this attack possible.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a nonce to the hashes so a signature cannot be replayed, also add a mapping that invalidates an already used signature so the `required_validators_num` can not be bypassed by simple passing a valid signatures multiple times in the `signatures` argument
