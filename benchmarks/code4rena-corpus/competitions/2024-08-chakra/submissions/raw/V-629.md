# Vulnerability details

## Description: 
When a cross-chain transaction successful on the destination chain. However, in the given implementation, the `receive_cross_chain_callback` function in `ChakraSettlementHandler` does not include any logic for withdraw money which is not going to burn because when the `from_handler` from destination chain is not whitelisted on source chain. Consequently, the source chain's `receive_cross_chain_callback` does not trigger any withdraw mechanism upon receiving a not whitelisted handler from destination chain.

In other words, the `receive_cross_chain_callback` function in `ChakraSettlementHandler` checks if the `from_handler` is whitelisted using the `is_valid_handler` function. If the `from_handler` is not whitelisted, the function returns false without further processing. This can cause funds to be locked on the source chain without any withdraw or resolution for the user.

## Impact: 
If a `from_handler` is not whitelisted on the destination chain but the transaction was successful on the source chain, the user’s funds never burned on the source chain and never withdrawed from the source chain. This results in permanent loss of funds or locking of assets. Then this `create_cross_txs[txid].amount` variable always have amounts which aren't able to withdraw. 

## Proof of Concept:
1. Scenario Setup:

    - A user initiates a cross-chain transaction from the source chain to the destination chain.
    - The transaction is marked as successful on the source chain (funds are burned).
    - On the source chain, the `receive_cross_chain_callback` function detects that the `from_handler` is not whitelisted.
    - Locking of protocol funds because not burned in callback functionality even when amount minted to user on destination chain.
  
2. Steps : 
    - A user deposits an amount (e.g., 100 tokens) on the source chain and initiates a cross-chain transaction.
    - The source chain successfully processes the transaction, and the user’s funds are burned.
    - The destination chain recieve and sent acknowledge to source chain that transaction went successful.
    - When the source chain attempts to process the callback, it returns false because the `from_handler` is not whitelisted.
    - No burned is triggered, and the funds remain locked, with no resolution for the protocol and user to withdraw funds anyway.
