# Vulnerability details


**NOTE:** The 4naly3er-report-handler only references the storage gap issue in **Solidity** and not **Cairo** smart contracts.

## Impact

For upgradeable contracts, it is essential to include a storage gap to "allow developers to freely add new state variables in the future without compromising the storage compatibility with existing deployments" (as stated by OpenZeppelin). Without a storage gap, it can be very challenging to write new implementation code. If new variables are added to the base contract without a storage gap, they might overwrite variables in child contracts. This could lead to unintended and serious consequences for the child contracts, potentially resulting in the loss of user funds or causing the contract to malfunction entirely.

Refer to the bottom part of this article:  
[OpenZeppelin Upgrades: Writing Upgradeable Contracts](https://docs.openzeppelin.com/upgrades-plugins/1.x/writing-upgradeable)

## Proof of Concept

Several **Cairo** contracts in the codebase are intended to be upgradeable. However, none of these contracts include a storage gap:

- [Cairo: `handler/src/settlement.cairo`](https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo)
- [Cairo: `settlement/src/settlement.cairo`](https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/settlement/src/settlement.cairo)


The storage gap is crucial for upgradeable contracts because "it allows us to freely add new state variables in the future without compromising the storage compatibility with existing deployments." Refer to the bottom part of this article:  
[OpenZeppelin Contracts: Upgradeable Storage](https://docs.openzeppelin.com/contracts/3.x/upgradeable).

## Recommended Mitigation Steps

It is recommended to add an appropriate storage gap at the end of upgradeable contracts. This practice is common in OpenZeppelin upgradeable contract templates.

**In Cairo:**

Include a storage gap in the `Storage` struct:

```python
struct Storage {
    // other variables...
    _gap: [u8; 50],
}
```
