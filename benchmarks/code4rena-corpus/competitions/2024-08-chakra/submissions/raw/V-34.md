# Vulnerability details

## Impact
One of the protocol's critical invariants, as highlighted in the contest README, is:
> - In Settlement Handler Contract
>   - The handler receiving a cross-chain message must be on the whitelist for the source chain.

This requirement is essential to prevent users from sending cross-chain messages to unwhitelisted destination handlers, which would result in users' tokens being permanently locked on the source chain. We can see that the invarient is correctly enforced in Cairo contract:
```rs
fn cross_chain_erc20_settlement(ref self: ContractState, to_chain: felt252, to_handler: u256, to_token: u256, to: u256, amount: u256) -> felt252{
    assert(self.support_handler.read((to_chain, to_handler)), 'not support handler');
    // --SNIP
}
```
However, the current implementation of `ChakraSettlementHandler::cross_chain_erc20_settlement` in solidity contract, which initiates ERC20 cross-chain messages, does not adequately enforce this invariant:
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    require(amount > 0, "Amount must be greater than 0");
    require(to != 0, "Invalid to address");
>>>    require(to_handler != 0, "Invalid to handler address");
    require(to_token != 0, "Invalid to token address");

    // --SNIP
}
```
As illustrated above, the only check on `to_handler` is that it must be non-zero, which is insufficient to enforce the whitelisting requirement. Consequently, cross-chain messages can be initiated to unwhitelisted destination handlers, leading to users' tokens being permanently locked in the source `ChakraSettlementHandler` since the message settlement will fail in the `receive_cross_chain_callback`:
```solidity
function receive_cross_chain_callback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    CrossChainMsgStatus status,
    uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
    bytes calldata /* signatures */
) external onlySettlement returns (bool) {
    //  from_handler need in whitelist
    if (is_valid_handler(from_chain, from_handler) == false) {
        return false;
    }
    // --SNIP
}
```

## Recommended Mitigation Steps
Consider verifying in the `cross_chain_erc20_settlement` function that the `to_handler` is whitelisted:
```diff
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    require(amount > 0, "Amount must be greater than 0");
    require(to != 0, "Invalid to address");
-   require(to_handler != 0, "Invalid to handler address");
+   require(is_valid_handler(to_chain, to_handler));
    require(to_token != 0, "Invalid to token address");

    // --SNIP
}
```
