# Vulnerability details

## Impact
It is possible to replay the same message multiple times since there is no check if the transaction has been processed before. 

In the `settlement.cairo` contract, `receive_cross_chain_msg` is missing a check of the `received_tx.status` that should prevent executing the same message multiple times. This part of the function 

```
 assert(to_chain == self.chain_name.read(), 'error to_chain');

            // verify signatures
            let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
            let payload_span = payload.span();
            let mut i = 0;
            loop {
                if i > payload_span.len()-1{
                    break;
                }
                message_hash = LegacyHash::hash(message_hash, * payload_span.at(i));
                i += 1;
            };
            self.check_chakra_signatures(message_hash, signatures);
```

correctly checks if the message has been changed or not, and if the signatures are valid but it fails to check the status of the transaction. This means that  anyone can call the same function again with the same parameters and execute it multiple times, receiving tokens for free. 

## Proof of Concept
Scenario from the above described in steps.

1. Alice wants to lock 20 WETH on Ethereum and unlock them on Starknet
2. The transaction goes through smoothly and Alice gets her tokens
3. Alice can take all input parameters from the successfull call to `receive_cross_chain_msg` and call `receive_cross_chain_msg` on Starknet 1000 times.
4. Since there is no check if the same transaction has been processed before, every call will succeed and will mint free tokens on Starknet


## Tools Used
Manual Review, VS Code

## Recommended Mitigation Steps
Add the following check 

```
let tx_status = self.received_tx.read(cross_chain_msg_id).tx_status
assert(tx_status == unknown, 'transaction already processed');
```
