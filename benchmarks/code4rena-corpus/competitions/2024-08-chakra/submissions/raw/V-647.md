# Vulnerability details

## Impact

Messages can be replayed on the cairo contracts.

## Proof of Concept

The `receive_cross_chain_msg()` fn in settlement.cairo simply writes the `received_tx` into storage after verifying the signature without checking that the txid status is `Unknow`.

```
 fn receive_cross_chain_msg(
            ...
 >          self.received_tx.write(cross_chain_msg_id, ReceivedTx{
                tx_id:cross_chain_msg_id,
                from_chain: from_chain,
                from_handler: from_handler,
                to_chain: to_chain,
                to_handler: to_handler,
                tx_status: status
            });
```

In the solidity contracts, it checks that the status is `Unknow` before adding it to the `receive_cross_txs` mapping.

```
>    require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );
        }

>       receive_cross_txs[txid] = ReceivedCrossChainTx(
            txid,
            from_chain,
            contract_chain_name,
            from_address,
            from_handler,
            address(this),
            payload,
            CrossChainMsgStatus.Pending
        );
```

## Tools Used

Manual Review

## Recommended Mitigation Steps

Ensure that the status is checked in `receive_cross_chain_msg()` so that the messages cannot be replayed.
