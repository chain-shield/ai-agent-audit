# Vulnerability details

## Impact

`SettlementSignatureVerifier::verifyECDSA` code is vulnerable to a replay attack where a single malicious validator can reuse their signature multiple times to bypass the security checks. This vulnerability allows a malicious validator to manipulate the `ChakraSettlement::receive_cross_chain_msg function`, potentially leading to unauthorized token minting, or token transfers. The exploit leverages the `SettlementSignatureVerifier::verify` function, which only counts the total number of valid signatures but does not verify that each signature corresponds to a unique validator. By repeatedly using the same valid signature, a single validator could meet the required number of validators (required_validators), thus compromising the integrity of the cross-chain message validation.

## Proof of Concept

The vulnerability is in the `SettlementSignatureVerifier::verify()` function. This function counts the number of valid signatures without checking if each signature comes from a unique validator. Consequently, a single malicious validator can reuse their signature multiple times to meet the required number of validator signatures (required_validators). This oversight allows a malicious validator to bypass the security check inside `ChakraSettlement::receive_cross_chain_msg`

```solidity
    function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (//@audit there is n check or a unique signature
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```
