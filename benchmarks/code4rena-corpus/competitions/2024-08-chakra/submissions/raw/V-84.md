# Vulnerability details

## Impact
If `to_handler` is not the correct address, the returned boolean could possibly be incorrect. This means that the state update will be incorrect, potentially leading inconsistencies i.e `CrossChainMsgStatus` and `receive_cross_txs[txid].status` could be updated incorrectly.

## Proof of Concept
When receiving cross chain messages, the `to_handler` parameter should point to the receiving contract (`address(this)`).
This is validated in [`handler_erc20::receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L110) and [`handler_erc20::receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L140) as follows:
```solidity
    assert(to_handler == get_contract_address(),'error to_handler');
```
These functions are called from `settlement` contract  and therefore has to validate that indeed the `to_handler` is the receiving address.
[`settlement::receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/settlement/src/settlement.cairo#L354-L356)
```solidity
            
>>   let handler = IHandlerDispatcher{contract_address: to_handler};
>>   let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

```
[`settlement::receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/settlement/src/settlement.cairo#L416-L417)
```solidity
>>    let handler = IHandlerDispatcher{contract_address: to_handler};
>>    let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler ,  cross_chain_msg_status);
```

However, in [`ChackraSettlement::receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L216) and [`ChackraSettlement::receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L318), the `to_handler`  passed to the call but is never validated as the handler functions ([`ChackraSettlementHandler::receive_cross_chain_msg()`]() & [`ChackraSettlementHandler::receive_cross_chain_callback()`]()) do not perform this validation.

Notice that when [saving received cross chain transaction](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L211), `ChackraSettlement::receive_cross_chain_msg()` uses `address(this)` as the `to_handler` without really verifying that it points to it.
```solidity
        receive_cross_txs[txid] = ReceivedCrossChainTx(
            txid,
            from_chain,
            contract_chain_name,
            from_address,
            from_handler,
>>          address(this),
            payload,
            CrossChainMsgStatus.Pending
        );
```

Note that the  boolean returned from the calls determines the  state update in `ChackraSettlement::receive_cross_chain_msg()` and `ChackraSettlement::receive_cross_chain_callback()`.

---> If `to_handler` is not the correct address, the returned boolean could possibly be incorrect. This means that the state update will be incorrect, potentially leading inconsistencies i.e `CrossChainMsgStatus` and `receive_cross_txs[txid].status` could be updated incorrectly as shown below:
- [`ChackraSettlement::receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L216-L233)
```solidity
>>      bool result = ISettlementHandler(to_handler).receive_cross_chain_msg( //@audit-info Boolean returned
            txid,
            from_chain,
            from_address,
            from_handler,
            payload_type,
            payload,
            sign_type,
            signatures
        );

        //@audit-info State updates depend on it
        CrossChainMsgStatus status = CrossChainMsgStatus.Failed;
        if (result == true) {
            status = CrossChainMsgStatus.Success;
            receive_cross_txs[txid].status = CrossChainMsgStatus.Success;
        } else {
            receive_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
```
- [`ChackraSettlement::receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L317-L330)
```solidity
>>      if ( //@audit-info Boolean returned
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
>>          create_cross_txs[txid].status = status; //@audit-info State updates depend on it
        } else {
>>          create_cross_txs[txid].status = CrossChainMsgStatus.Failed; //@audit-info State updates depend on it
        }
```

## Recommended Mitigation Steps
To fix this bug, we should validate the `to_handler` address before the call in `ChackraSettlement::receive_cross_chain_msg()` and `ChackraSettlement::receive_cross_chain_msg()`.
```diff
+   require(to_handler == address(this),'error to_handler');
```
