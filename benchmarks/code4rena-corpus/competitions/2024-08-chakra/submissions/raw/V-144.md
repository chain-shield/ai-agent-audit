# Vulnerability details

## Impact
`send_cross_chain_msg` should be callable only by Handler contract but lacks access control in both `settlement.cairo` and `ChakraSettlement.sol`

This lets anyone submit potentially malicious messages without going through the checks in the Handler contract first.
## Proof of Concept
The functions in both contracts are external with no access control:
```
        fn send_cross_chain_msg(
            ref self: ContractState, 
            to_chain: felt252, 
            to_handler: u256, 
            payload_type :u8,
            payload: Array<u8>,
        ) -> felt252 {

```
```solidity
    function send_cross_chain_msg(
        string memory to_chain,
        address from_address,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload
    ) external {
```
Although it's evident that the intention was to be callable only by handler contract for a couple of reasons. Comment above the cairo function:
```
// @notice send cross chain message, only handler can call this function
```
`from_handler` is assigned the address of msg.sender in both of the functions:
```
address from_handler = msg.sender;
let from_handler = get_caller_address();
```
And it's obviously dangerous to let anyone send messages without going through the checks and transferring tokens in the Handler contract first. This opens up the possibility of attackers crafting malicious messages that can exploit the protocol.
## Tools Used
Manual review
## Recommended Mitigation Steps
Add access control to both of these functions to make them callable only by the specified handler contract.
