# Vulnerability details

## Impact
The `BaseSettlement` contract has a [public _Settlement_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/BaseSettlement.sol#L61) that initializes `contract_chain_name`, `chain_id`, `owner`, `managers`, `required_validators` and `signature_verifier`, with no access control. These are pretty much all the important state while taking control of the `owner` would be enough. The contracts `ChakraSettlement` is [inheriting from](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L10) `BaseSettlement`, so any user, without a need for any permission, can directly call `_Settlement_init` passing their own address as `_owner` and take full control of this contract.  

## Proof of Concept
Call this and `ChakraSettlement` will be pwned
```
ChakraSettlement._Settlement_init(any_chain_name, any_chain_id, your_address_as_owner, any_managers, any_required_validators, any_signature_verifier)
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
The [_Settlement_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/BaseSettlement.sol#L54-L61) should be `internal` and also should include the `onlyInitializing` modifier, so that it can only be called as part of the [initialize function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L85-L101) (the function with `initializer` modifier).
