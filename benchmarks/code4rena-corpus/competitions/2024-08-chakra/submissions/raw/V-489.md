# Vulnerability details

### Description
The `receive_cross_chain_msg` function is vulnerable to a **signature replay attack**. This occurs because there is no mechanism to prevent the same message and signature from being replayed multiple times. Attackers can exploit this flaw to re-execute transactions, leading to unintended consequences, such as repeated fund transfers or malicious cross-chain message handling.

### Attack Scenario
1. An attacker submits a legitimate cross-chain message with valid signatures.
2. The `receive_cross_chain_msg` function processes the message and records the transaction.
3. The attacker resubmits the same cross-chain message with the same signature, as there is no mechanism in place to prevent replay attacks.
4. The function processes the message again, allowing the attacker to exploit the system by executing the same transaction multiple times allowing him to mint and transfer tokens as many times as they want.


### Impact : [CRITICAL]

### EFFECTS 
The function internally calls the function `handler.receive_cross_chain_msg` which is defined in the `erc_handler.cairo` which is responsible for minting and  transfering tokens, if the signature can be repeated , user can mint and transfer tokens as many times as they want ,they just have to replay the signature.

### Fix

To fix the vulnerability, a **nonce** or **transaction replay protection mechanism** should be introduced. This can be done by checking if the transaction identified by `cross_chain_msg_id` has already been processed before proceeding. Additionally, adding a **timestamp** or **expiration time** can help prevent old messages from being replayed.

Here’s an updated version of the code with replay protection:

```cairo
fn receive_cross_chain_msg(
    ref self: ContractState,
    cross_chain_msg_id: u256,
    from_chain: felt252,
    to_chain: felt252,
    from_handler: u256,
    to_handler: ContractAddress,
    sign_type: u8,
    signatures: Array<(felt252, felt252, bool)>,
    payload: Array<u8>,
    payload_type: u8,
) -> bool {
    assert(to_chain == self.chain_name.read(), 'error to_chain');

    // Check if the transaction has already been processed
    assert(self.received_tx.get(cross_chain_msg_id).is_none(), 'Replay attack detected: transaction already processed');

    // verify signatures
    let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
    let payload_span = payload.span();
    let mut i = 0;
    loop {
        if i > payload_span.len() - 1 {
            break;
        }
        message_hash = LegacyHash::hash(message_hash, *payload_span.at(i));
        i += 1;
    }
    self.check_chakra_signatures(message_hash, signatures);

    // call handler receive_cross_chain_msg
    let handler = IHandlerDispatcher { contract_address: to_handler };
    let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler, payload);

    let mut status = CrossChainMsgStatus::SUCCESS;
    if success {
        status = CrossChainMsgStatus::SUCCESS;
    } else {
        status = CrossChainMsgStatus::FAILED;
    }

    // Store the received transaction data to prevent replay
    self.received_tx.write(cross_chain_msg_id, ReceivedTx {
        tx_id: cross_chain_msg_id,
        from_chain: from_chain,
        from_handler: from_handler,
        to_chain: to_chain,
        to_handler: to_handler,
        tx_status: status,
    });

    // emit event
    self.emit(CrossChainHandleResult {
        cross_chain_settlement_id: cross_chain_msg_id,
        from_chain: to_chain,
        from_handler: to_handler,
        to_chain: from_chain,
        to_handler: from_handler,
        cross_chain_msg_status: status,
        payload_type: payload_type,
    });

    return true;
}
