# Vulnerability details

### Summary
The to_bytes function attempts to extract a specified number of bytes from the input `bytes32`, but it does so incorrectly:

1. It uses a left shift (`shl`) operation, which moves the most significant bytes of the input to the beginning of the output array.
2. This approach effectively discards the least significant bytes of the input, which is typically not the desired behavior when working with Ethereum addresses or other data stored in `bytes32`.

### Code Snippet

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/libraries/AddressCast.sol#L32

```solidity
function to_bytes(
    bytes32 _addressBytes32,
    uint256 _size
) internal pure returns (bytes memory result) {
    if (_size == 0 || _size > 32)
        revert AddressCast_InvalidSizeForAddress();
    result = new bytes(_size);
    unchecked {
        uint256 offset = 256 - _size * 8;
        assembly {
            mstore(add(result, 32), shl(offset, _addressBytes32))
        }
    }
}
```

### Impact
1. **Data Loss**: The function will always return the most significant bytes of the input, regardless of where the actual data of interest is located within the `bytes32`.
2. **Inconsistency with Ethereum Conventions**: Ethereum typically stores addresses and other smaller data types in the least significant bytes of larger types like `bytes32`.

### Example Scenario
Suppose we have an Ethereum address stored in a `bytes32`:

```solidity
address addr = 0x742d35Cc6634C0532925a3b844Bc454e4438f44e;
bytes32 addrBytes32 = bytes32(uint256(uint160(addr)));
```

If we call `to_bytes(addrBytes32, 20)`, we expect to get the 20 bytes representing the address. However, the current implementation will return the 20 most significant bytes of `addrBytes32`, which would be mostly zeros, not the actual address bytes.

### Fix
A correct implementation should extract the least significant bytes:

```solidity
function to_bytes(
    bytes32 _addressBytes32,
    uint256 _size
) internal pure returns (bytes memory result) {
    if (_size == 0 || _size > 32)
        revert AddressCast_InvalidSizeForAddress();
    result = new bytes(_size);
    assembly {
        mstore(add(result, 32), _addressBytes32)
    }
}
```

This implementation simply copies the least significant bytes of the input `bytes32` to the output `bytes` array, which is the correct behavior for most Ethereum-related use cases.
