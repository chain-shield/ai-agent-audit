# Vulnerability details

## Summary:

A bug has been identified in the `SettlementSignatureVerifier` smart contract where the management of the `validator_count` variable can become inaccurate if validators are added or removed multiple times. This flaw can lead to logical inconsistencies in the contract's quorum calculations for validating transactions, which compromises the core functionality of the contract. The contract fails to properly handle scenarios where a validator is added or removed multiple times, leading to an inaccurate count of active validators.

## Vulnerability Details:

The bug exists in the `add_validator` and `remove_validator` functions, which are responsible for managing the addition and removal of validators. The `validator_count` variable is incremented when a new validator is added and decremented when a validator is removed. However, the contract does not properly prevent multiple additions or removals of the same validator, which can cause the `validator_count` to become inaccurate.

- **In `add_validator`:** If the same validator is added more than once, `validator_count` will be incremented multiple times, inflating the count.
- **In `remove_validator`:** If the same validator is removed more than once, `validator_count` will be decremented multiple times, leading to an undercount of active validators.

### Affected Code:

Below are the snippets where the issues occur:

#### `add_validator`:

```solidity
function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == false, "Validator already exists"); // Validator check
    validators[validator] = true;
    validator_count += 1; // Increment validator count
    emit ValidatorAdded(msg.sender, validator);
}
```

#### `remove_validator`:

```solidity
function remove_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == true, "Validator does not exist"); // Ensure validator exists before removal
    validators[validator] = false;
    validator_count -= 1; // Decrement validator count
    emit ValidatorRemoved(msg.sender, validator);
}
```

### Impact:

The inaccurate management of the `validator_count` variable can lead to several issues:

1. **Incorrect Validator Quorum**: The contract could miscalculate whether enough validators are available to verify a message. This can result in either:
   - **Overestimating Validators**: Validators appear more numerous than they are, leading to false positive validations.
   - **Underestimating Validators**: Validators appear fewer than they are, causing the contract to believe there are insufficient validators, halting the verification process.
2. **Operational Disruptions**: Critical contract functions that depend on the correct validator quorum could fail or behave incorrectly, undermining the contract's integrity.

In this buggy implementation, the contract does not prevent adding or removing the same validator multiple times, causing incorrect increments or decrements to the `validator_count`.

### Recommendations:

To resolve the issue, we must add checks to both the `add_validator` and `remove_validator` functions to ensure that:

1. **In `add_validator`:** The contract should verify that the validator is not already present before adding them and incrementing the count.
2. **In `remove_validator`:** The contract should verify that the validator exists before removing them and decrementing the count.

#### Fixed Code:

```solidity
function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == false, "Validator already exists"); // Ensure validator isn't already added
    validators[validator] = true;
    validator_count += 1; // Increment only when a new validator is added
    emit ValidatorAdded(msg.sender, validator);
}

function remove_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(validators[validator] == true, "Validator does not exist"); // Ensure validator exists before removal
    validators[validator] = false;
    validator_count -= 1; // Decrement only when an existing validator is removed
    emit ValidatorRemoved(msg.sender, validator);
}
```

### Conclusion:

By adding the necessary checks to ensure that validators are not added or removed multiple times, the `validator_count` will remain accurate, maintaining the integrity of the contract. This fix ensures that the contract's quorum calculations are correct and prevents potential operational issues that could arise from an incorrect count of active validators.
