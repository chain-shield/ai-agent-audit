# Vulnerability details

## Impact
Attacker can call receive_cross_chain_msg multiple times on Starknet to steal funds

## Proof of Concept

`settlement.cairo#receive_cross_chain_msg` does not check that the CCTX has not been processed before.

After a CCTX gets executed on starknet via the receive_cross_chain_msg function, nothing restricts an attacker from calling the function again with the exact same params.

This wrongly allows attacker to call a receive_cross_chain_tx with same parameters multiple times(without needing new signatures) to steal funds

Here is the function:

```
 fn receive_cross_chain_msg(
    ref self: ContractState,
    cross_chain_msg_id: u256,
    from_chain: felt252,
    to_chain: felt252,
    from_handler: u256,
    to_handler: ContractAddress,
    sign_type: u8,
    signatures: Array<(felt252, felt252, bool)>,
    payload: Array<u8>,
    payload_type: u8,
) -> bool {
    assert(to_chain == self.chain_name.read(), 'error to_chain');

    let mut message_hash: felt252 = LegacyHash::hash(from_chain, (cross_chain_msg_id, to_chain, from_handler, to_handler));
    let payload_span = payload.span();
    let mut i = 0;
    loop {
        if i > payload_span.len()-1{
            break;
        }
        message_hash = LegacyHash::hash(message_hash, * payload_span.at(i));
        i += 1;
    };
    self.check_chakra_signatures(message_hash, signatures);

    // call handler receive_cross_chain_msg
    let handler = IHandlerDispatcher{contract_address: to_handler};
    let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

    let mut status = CrossChainMsgStatus::SUCCESS;
    if success{
        status = CrossChainMsgStatus::SUCCESS;
    }else{
        status = CrossChainMsgStatus::FAILED;
    }

    self.received_tx.write(cross_chain_msg_id, ReceivedTx{
        tx_id:cross_chain_msg_id,
        from_chain: from_chain,
        from_handler: from_handler,
        to_chain: to_chain,
        to_handler: to_handler,
        tx_status: status
    });

    // emit event
    self.emit(CrossChainHandleResult{
        cross_chain_settlement_id: cross_chain_msg_id,
        from_chain: to_chain,
        from_handler: to_handler,
        to_chain: from_chain,
        to_handler: from_handler,
        cross_chain_msg_status: status,
        payload_type: payload_type
    });
    return true;
}
```

As we can see, there is no check that triggers a revert if that particular cctx has been processed before

## Tools Used
Manual Review

## Recommended Mitigation Steps
Just as was done in the EVM counterpart, consider including a check at the beginning of the function to ensure that tx_status in the received_tx mapping is neither "FAILED" nor "SUCCESS"(probably "UNKNOWN")
