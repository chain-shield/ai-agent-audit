# Vulnerability details

## Impact
The `ChakraSettlement::receive_cross_chain_callback()` function allows malicious actors to alter the `from_chain` parameter. This can result in the incorrect setting of cross-chain transaction statuses to `Failed`, causes:

1. `_erc20_burn()` is not called to burn tokens if the mode is `MintBurn`.
2. Violating the core invariant that cross-chain transaction statuses are properly tracked and updated:

> In Settlement Handler Contract: Cross-chain transaction statuses are properly tracked and updated (Pending, Settled, or Failed).

## Proof of Concept
The `from_chain` parameter is not verified by the validators:

```solidity
File: ChakraSettlement.sol
256:     function receive_cross_chain_callback(
257:         uint256 txid,
258:>>       string memory from_chain,
259:         uint256 from_handler,
260:         address to_handler,
261:         CrossChainMsgStatus status,
262:         uint8 sign_type,
263:         bytes calldata signatures
264:     ) external {
265:>>       verifySignature(
266:             txid,
267:             from_handler,
268:             to_handler,
269:             status,
270:             sign_type,
271:             signatures
272:         );
```

A malicious actor can front-run the callback transaction and change the `from_chain` parameter to an invalid value, leading to [the `ChakraSettlementHandler::is_valid_handler()` check to return false](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L374-L376). As a result, the call to [`to_handler.receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L318) returns false unexpectedly.
