# Vulnerability details

## Impact
For a handler operating in mode `MintBurn`, a cross chain message for a failed callback will still burn the user's tokens from the handler contract. This means that a user has transferred their tokens to the handler contract as part of a call to `cross_chain_erc20_settlement()` in expectation of tokens being minted by the Chakra handler on the destination chain. However, the failed callback status is a good indication that the minting has not happened. In this case, the user's tokens are burnt when they should be returned to them.

## Proof of Concept
The functions `ChakraSettlement.receive_cross_chain_msg()` receive the parameter `cross_chain_msg_status` but do not perform any check on the value of this parameter. It is used to calculate `message_hash_final` which is used to check signatures, but this is not dependant on the status being of a successful message transmission.

Instead, the handler is called on this line:
```
let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
```
As can be seen, the handler does receive the message status, but in `ERC20Handler.receive_cross_chain_callback()`, there is no check on the value of `cross_chain_msg_status` and tokens are burned:
```
if self.mode.read() == SettlementMode::MintBurn{
erc20.burn_from(get_contract_address(), self.created_tx.read(cross_chain_msg_id).amount);
}
```

## Recommended Mitigation Steps
The protocol team must determine as a design decision whether they want this check to be processed in handlers or the settlement contract.

The handler seems like the more appropriate location, as this allows the release of locked assets. In this case, it is vital that any handler checks the value of `cross_chain_msg_status` and reacts accordingly.

In the specific case of a failed status in the handler `ERC20Handler`, the contract needs to release locked tokens or mint any tokens that have already been burned. It also needs to dynamically update the status it writes on [line 161](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L161) to a failed status where appropriate.
