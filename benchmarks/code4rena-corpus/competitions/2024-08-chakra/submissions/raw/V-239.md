# Vulnerability details

## Impact
`check_chakra_signatures()` function does not check whether the `signatures` come from `unique validators`. This means that a `single validator` could submit `multiple valid signatures`, and `each signature` would be counted toward the total `pass_count`. 

The function would then pass the check even if all the `signatures` come from just `one validator`, thus bypassing the security assumption that `signatures` from `multiple validators` are needed for approval.

## Proof of Concept
Here is the current implementation [`check_chakra_signatures()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L173-L191) function.
```solidity
        fn check_chakra_signatures(
            self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
        ){
            let mut pass_count = 0;
            let mut i = 0;
            loop {
                if i > signatures.len()-1{
                    break;
                }
                let (r,s,y) = * signatures.at(i);
                let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
                if self.chakra_validators_pubkey.read(pub_key) > 0{
                    pass_count += 1;
                }
                i += 1;
            };
            assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
        }
```
This function takes in a list of `signatures`, recovers the `public key` for each `signature`, and checks if the `public key` belongs to a `registered validator`. It then counts the number of `valid signatures` and compares that count against a threshold (`required_validators_num`). If the number of `valid signatures` is below the `required threshold`, the function throws an error.

A flaw however arises because the function increments `pass_count` for every `valid signature`, regardless of whether the `public key` has already been counted.

**Example Scenario**:
- Consider a situation where the contract requires signatures from `3 distinct validators` (i.e., `required_validators_num` is `3`). 
- The validators must sign off on some transaction to ensure consensus and security in the system.
- However, if `validator A` submits three `separate signatures`, all derived from the same `public key`, the function will incorrectly count all `three signatures`, resulting in `pass_count = 3`. 
- This will meet the required number of signatures, even though only one validator has signed the message.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Ensure that the `signatures` are counted only if they come from `unique validators`.
