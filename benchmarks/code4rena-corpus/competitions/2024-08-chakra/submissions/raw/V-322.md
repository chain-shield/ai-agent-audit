# Vulnerability details

## Impact
The function `receive_cross_chain_callback` is part of the [solidity handler](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L365-L396) and the [cairo handler](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L138-L165). The solidity version is called after a cross chain message was executed on the destination chain and update the transaction status based on the parameter `status` to either `CrossChainTxStatus.Settled` or `CrossChainTxStatus.Failed`. The cairo version updates the state to settled, as that implementation has no status parameter. They both complete the burn in case the mode is set to `MintBurn`.

But either implementation only handles the "happy case", that the destination transaction succeeded. **If the destination transaction can not be executed for some reason, they do not return the locked tokens to the user**. Therefor the user tokens stay locked in the handler contract or are burned forever.

## Recommended Mitigation Steps

If the status of the transaction is `CrossChainMsgStatus.Failed` it should return the user tokens based on the `SettlementMode` by either minting new tokens or unlocking them.
