# Vulnerability details

## Impact
The lack of initialization of `AccessControlUpgradeable` in `BaseSettlementHandler` can lead to issues with role-based access control, potentially affecting the security and functionality of the `ChakraSettlementHandler` contract, which inherits from `BaseSettlementHandler`.

## Proof of Concept
`ChakraSettlementHandler` contract inherits `BaseSettlementHandler` and `AccessControlUpgradeable` but but does not invoke `AccessControlUpgradeable` individual initialzers during `BaseSettlementHandler` initialization.

```solidity
contract ChakraSettlementHandler is BaseSettlementHandler, ISettlementHandler {
```

```solidity
abstract contract BaseSettlementHandler is
    OwnableUpgradeable,
    UUPSUpgradeable,
    AccessControlUpgradeable
      ...
    function _Settlement_handler_init(
        address _owner,
        SettlementMode _mode,
        address _token,
        address _verifier,
        string memory _chain,
        address _settlement
    ) public {
        __Ownable_init(_owner);
        __UUPSUpgradeable_init();
        settlement = ISettlement(_settlement);
        verifier = ISettlementSignatureVerifier(_verifier);
        mode = _mode;
        token = _token;
        chain = _chain;
    }
```
```solodit
abstract contract AccessControlUpgradeable is Initializable, ContextUpgradeable, IAccessControl, ERC165Upgradeable {
    ...

    function __AccessControl_init() internal onlyInitializing {
    }
```

The `BaseSettlementHandler` contract is designed to utilize role-based access control, as it inherits from `AccessControlUpgradeable`. However, the `_Settlement_handler_init` function does not call `__AccessControl_init()`. While `__AccessControl_init()` currently does not perform any actions (i.e., it is empty), it ensures that all parent contracts' initialization methods are called. This practice helps avoid potential issues if the parent contract’s initialization methods need to perform actions in future updates or extensions.

What is more, the `ChakraSettlementHandler` contract inherits from `BaseSettlementHandler` and relies on it for access control functionality. If `BaseSettlementHandler` is not correctly initialized, `ChakraSettlementHandler` will inherit these issues, which could compromise the security and functionality of the entire settlement system.

Due to this functions that should be protected by access control might not enforce permissions correctly, potentially allowing unauthorized users to perform restricted operations.

What is more, roles and permissions might not be set up or enforced properly, leading to security vulnerabilities where unauthorized users could improperly grant or revoke roles.

So the incorrect initialization of `AccessControlUpgradeable` also breaks the overall code consistency of protocol.

## Recommended Mitigation Steps
Modify the `_Settlement_handler_init` function in `BaseSettlementHandler` to include the `__AccessControl_init()` function call. Even though `__AccessControl_init()` is currently empty, adding it ensures compatibility with potential future updates and maintains best practices.
