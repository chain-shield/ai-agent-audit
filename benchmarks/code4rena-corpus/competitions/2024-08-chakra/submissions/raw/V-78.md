# Vulnerability details

## Impact
Please note the same issue exist in the cairo code, i packed them in this one report, they have the same fix.

Upon receiving a crossChain callback transaction, [receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L256) is called  inside ChakraSettlement which in turn call [receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L365) in chakraSettlementHandler to process the callback transaction.
However there is a logic error in receive_cross_chain_callback() inside chakraSettlementHandler that make the function always return true even if the call failed.
Since the function always returns true, there is no way to signal to the calling contract or protocol that an error occurred. The protocol might incorrectly process or assume that the cross-chain message was handled successfully, even when it failed.

## Proof of Concept

Consider this scenario:
A callback tx was received in the settlement so receive_cross_chain_callback() is called inside the settlement.
```solidity
function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) external {
        verifySignature(
            txid,
            from_handler,
            to_handler,
            status,
            sign_type,
            signatures
        );
        processCrossChainCallback(
            txid,
            from_chain,
            from_handler,
            to_handler,
            status,
            sign_type,
            signatures
        );
        emitCrossChainResult(txid);
    }
```
It first verify that signature are valid and then process the callback transaction by calling the corresponding receive_cross_chain_callback() function on the handler contract.

```solidity
function processCrossChainCallback(

        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) internal {
        require(
            create_cross_txs[txid].status == CrossChainMsgStatus.Pending,
            "Invalid transaction status"
        );

        if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
    }
```

When receive_cross_chain_callback() is called on the handler the function verify the return value, if it is true then the cross transaction status is set to the received msg status, if it is false then the cross transaction status is set to failed.There is where the issue arise because the handler [receive_cross_chain_callback()](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L365) function does not return false for failed transactions.
Let analyse the handler receive_cross_chain_callback() function:
```solidity
function receive_cross_chain_callback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        CrossChainMsgStatus status,
        uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
        bytes calldata /* signatures */
    ) external onlySettlement returns (bool) {
        //  from_handler need in whitelist
        if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
        }

        require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending,
            "invalid CrossChainTxStatus"
        );

        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }

        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }
        // @audit: this function will always return true even if the CrossChainMsgStatus failed
        // This function is called by the corresponding function in the settlement
        // impact: Protocol will process crosschain failed messages

        return true;
    }
```

First it check that the handler on the calling chain is valid, if not it return false and that is the only time this function return false.
On the other hands the function check if the received msg status is success or failed and update the cross tx statuts accordingly.
Now even if the received msg status is failed, the function will return true at the end.
```solidity
 if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }

        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }

        return true; // here
```

Now we go back to processCrossChainCallback() function in settlement and we can see that this part of code will always process only the if block and ignore the else because the handler returned true.
```solidity
function processCrossChainCallback(
        uint256 txid,
        string memory from_chain,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) internal {
        require(
            create_cross_txs[txid].status == CrossChainMsgStatus.Pending,
            "Invalid transaction status"
        );

        if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }
    }
```

In the cairo side the handler will also always return true [see here](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L164) .
Therefore failed messages will be recorded as processed

## Recommended Mitigation Steps

Return false if the msgStatus is failed, you can do it in solidity like this:
```diff
if (status == CrossChainMsgStatus.Failed) {
    create_cross_txs[txid].status = CrossChainTxStatus.Failed;
   + return false;  // Indicate failure
}
```
Same fix for cairo contract
