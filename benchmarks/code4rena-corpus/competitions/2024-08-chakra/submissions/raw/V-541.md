# Vulnerability details

### Impact
The function `processCrossChainCallback` is responsible for processing cross-chain callbacks and finalizing the settlement process by interacting with the designated handler. However, there is a missing verification step where the handler addresses (`to_handler` and `from_handler`) and `from_chain` are not properly checked to ensure they correspond to the original cross-chain message.
```solidity
function processCrossChainCallback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    address to_handler,
    CrossChainMsgStatus status,
    uint8 sign_type,
    bytes calldata signatures
) internal {
    require(create_cross_txs[txid].status == CrossChainMsgStatus.Pending, "Invalid transaction status");

    if (ISettlementHandler(to_handler).receive_cross_chain_callback(txid, from_chain, from_handler, status, sign_type, signatures)) {
        create_cross_txs[txid].status = status;
    } else {
        create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
    }
}
```
Currently, the function proceeds without verifying whether:

- `to_handler` is indeed the handler that originally sent the cross-chain message.
- `from_handler` is the correct handler that the message was sent to.
- `from_chain` matches the chain where the message was sent to.

These missing checks could lead to unintended behavior, allowing the wrong handlers to process callback messages if validators provide incorrect or mistaken handler addresses or chain information. The likelihood of such thing happening is not negligible as Chakra network is permissionless and anyone can become a validator.

### Recommended Mitigation Steps
Consider implementing proper validation checks on the `to_handler`, `from_handler` and `from_chain` before processing the callback:
```diff
function processCrossChainCallback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    address to_handler,
    CrossChainMsgStatus status,
    uint8 sign_type,
    bytes calldata signatures
) internal {
    require(create_cross_txs[txid].status == CrossChainMsgStatus.Pending, "Invalid transaction status");
+   require(create_cross_txs[txid].to_handler == from_handler, "Invalid from_handler);
+   require(create_cross_txs[txid].from_handler == to_handler, "Invalid to_handler);
+   require(create_cross_txs[txid].to_chain == from_chain, "Invalid to_handler);

    if (ISettlementHandler(to_handler).receive_cross_chain_callback(txid, from_chain, from_handler, status, sign_type, signatures)) {
        create_cross_txs[txid].status = status;
    } else {
        create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
    }
}
```
