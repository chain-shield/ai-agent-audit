# Vulnerability details

## Impact
The wrong from address is stored in the transaction data struct when sending cross-chain messages in the Cairo contracts.

## Description
When the `cross_chain_erc20_settlement()` function of `handler_erc20.cairo` is called a new transaction is created by storing all of the relevant data in a `CreatedCrossChainTx` struct, which is used later in callback functions.

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L94-L104
```cairo
pub struct CreatedCrossChainTx {
       tx_id : felt252,
       from_chain: felt252,
       to_chain: felt252,
   --->    from: ContractAddress,
       to: u256,
       from_token: ContractAddress,
       to_token: u256,
       amount: u256,
       tx_status: u8
    }
```

Problem is that for the `from` field the `get_contract_address()` address is used, instead of `get_caller_address()` which is the actual sender:

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L188

The correct logic can be confirmed, by [looking at the Solidity contract](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L158), where `msg.sender` is used.

## Tools Used
Manual review

## Recommended Mitigation Steps
Assign `get_caller_address()` to the `from` field instead of `get_contract_address()`

Invalid Validation
