# Vulnerability details

## Impact
In the contest readme under the trusted role section it says nothing about validators being trusted so we can and should assume the worst.
Rogue validators can replay a message multiple times hence draining user's funds stored on the contract.

## Proof of Concept
Validators are in charge of processing messages on destination chains which can typically be anybody that is assigned to do this so it makes sense they can become malicious adding to the major fact that contest readme does not dispute this. The processing is done by collecting the signatures of required number of validators to process the cross chain message
 https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L350
 The issue here is that in `settlement.cairo`, the function `receive_cross_chain_msg()` does not check if the state of the message is already sucessful. It just writes the state to either `successful` or `failed` and that is all. So a rogue or malicious validator can send 10 ether on let's say ethereum come to starknet and replay that message payload 100 times getting 1000 ether; much info was not given on how the collection of required validators signatures will be done but this malicious validator will behave as if they want to sign a normal transaction so it will go through. Adding to this another completely honest validator might actually pick an already processed message payload up and it will be a successful transaction giving the `to` double of their tokens or more.
