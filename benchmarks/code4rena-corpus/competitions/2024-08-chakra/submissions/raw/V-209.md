# Vulnerability details

## Impact
One validator can repeat his signature in `signatures` to bypass the `required_validators_num` check.

## Proof of Concept
In cairo check_chakra_signatures(), we will check this transaction's signature to make sure this is one valid transaction. We set `required_validators_num` to make sure that this transaction can by executed only if multiple validators sign signature for this.
The problem is that we don't check whether there are some repeated signature in `signatures`. 
If one malicious validator sign signature for one manipulated transaction and add his signature into `signatures` array multiple times to bypass `required_validators_num` limitation, the manipulated transaction will be accepted and executed.
Considering that validators' private key may be compromised, if one validator's private key is compromised, the hacker can make use of this vulnerability to break the whole system. 
```javascript
        fn check_chakra_signatures(
            self: @ContractState, message_hash: felt252, signatures: Array<(felt252, felt252, bool)>
        ){
            let mut pass_count = 0;
            let mut i = 0;
            loop {
                if i > signatures.len()-1{
                    break;
                }
                let (r,s,y) = * signatures.at(i);
                let pub_key: felt252 = recover_public_key(message_hash,r,s,y).unwrap();
                if self.chakra_validators_pubkey.read(pub_key) > 0{
                    pass_count += 1;
                }
                i += 1;
            };
            assert(pass_count >= self.required_validators_num.read(), 'Not enough validate signatures');
        }
```

## Tools Used
Manual

## Recommended Mitigation Steps
When checking signature in check_chakra_signatures(), make sure there is not any repeated signature.
