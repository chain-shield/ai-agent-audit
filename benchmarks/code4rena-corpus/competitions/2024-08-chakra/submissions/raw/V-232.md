# Vulnerability details

## Impact
The current implementation of signature verification in SettlementSignatureVerifier contract using calldata slicing introduces a critical inefficiency that could lead to severe problems for the contract’s usability.  calldata slicing use in as would be explained in this report results in repeated, unnecessary memory allocations, significantly increasing gas consumption for every signature processed.

This inefficiency does more than just increase gas usage. In practice, this excessive gas costs can lead to transaction Reversion and any attempt to verify multiple signatures (e.g., for multi-signature transactions or consensus mechanisms) could exceed the gas limit, causing critical transactions to fail.
Also if gas consumption is too high, users might be unable to interact with the contract altogether due to prohibitive costs, essentially locking them out of the system. This creates a denial-of-service scenario where validators or users cannot complete necessary operations.

In the function and pointer noted above, signatures[i:i + 65] slices each 65-byte signature from calldata and copies it into memory for every loop iteration.
Each memory allocation is expensive and unnecessary since calldata can be accessed directly. This leads to excessive gas consumption, which could prevent the function from being successfully executed if the gas cost surpasses the block’s limit since it is in a loop. In cases where the contract is used for verifying multi-signature transactions, multiple validators need to sign off. The inefficiency in processing signatures could cause the transaction to revert due to exceeding gas limits. As a result, the contract becomes effectively unusable for its intended purpose.

## Recommended Mitigation Steps
The problem can be mitigated by avoiding memory allocation when processing calldata. Instead of copying data to memory, inline assembly can be used to directly access signatures from calldata. This approach reduces gas consumption significantly and avoids transaction reverts due to excessive gas usage.
```solidity
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 validatorsCount = 0;
    uint256 requiredSignatures = required_validators;

    for (uint256 i = 0; i < signatures.length; i += 65) {
        bytes32 r;
        bytes32 s;
        uint8 v;

        // Extract r, s, and v directly from calldata using assembly
        assembly {
            r := calldataload(add(signatures.offset, i))
            s := calldataload(add(add(signatures.offset, i), 32))
            v := byte(0, calldataload(add(add(signatures.offset, i), 64)))
        }

        // Recover the address and verify it as a validator
        address recovered = ecrecover(msgHash, v, r, s);
        if (validators[recovered]) {
            validatorsCount++;
            if (validatorsCount >= requiredSignatures) {
                return true;
            }
        }
    }

    return false;
}
```
