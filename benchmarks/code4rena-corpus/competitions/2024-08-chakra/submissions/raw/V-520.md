# Vulnerability details

## Impact
The inheritance chain of ChakraSettlement and ChakraSettlementHandler lacks proper storage gap implementations in their respective base contracts (BaseSettlement and BaseSettlementHandler). This oversight creates a significant risk for storage layout collisions in future upgrades, potentially leading to data corruption or loss of functionality in the inheriting contracts.

## Proof of Concept
ChakraSettlement inherits from BaseSettlement:
```solidity
contract ChakraSettlement is BaseSettlement {
    // Inherits storage layout from BaseSettlement
}
```

BaseSettlement, the parent contract, lacks a storage gap:
```solidity
abstract contract BaseSettlement is
    OwnableUpgradeable,
    UUPSUpgradeable,
    AccessControlUpgradeable
{
    // Contract implementation
    // No storage gap defined for future extensions
}
```
Similarly, ChakraSettlementHandler inherits from BaseSettlementHandler:
```solidity
contract ChakraSettlementHandler is BaseSettlementHandler, ISettlementHandler {
    // Inherits storage layout from BaseSettlementHandler
}
```
BaseSettlementHandler, also a parent contract, lacks a storage gap:
```solidity
abstract contract BaseSettlementHandler is
    OwnableUpgradeable,
    UUPSUpgradeable,
    AccessControlUpgradeable
{
    // Contract implementation
    // No storage gap defined for future extensions
}
```

Manual review


## Recommended Mitigation Steps
Implement storage gaps in all base contracts of the inheritance chain
