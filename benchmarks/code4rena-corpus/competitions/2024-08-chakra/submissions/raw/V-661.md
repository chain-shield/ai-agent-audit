# Vulnerability details

## Impact
If a newly added manager can remove the original owner/manager, the control of the contract could be shifted entirely away from the original deployer. This can lead to a complete loss of control over the contract, enabling malicious actors to perform actions that would normally require the owner's approval, such as upgrading the contract, adding other managers, or removing legitimate managers.

## Proof of Concept
The vulnerability lies in the `remove_manager` function, which allows any manager to remove another manager, including the original owner. Since there is no restriction preventing newly added managers from removing the original owner or any other critical roles, this opens up the possibility for privilege escalation and takeover.

### Attack Flow:
Step 1: The contract is initialized with an original owner (Alice) who is also the first manager.
Step 2: Alice adds a new manager (Bob).
Step 3: Bob, now a manager, removes Alice from the manager list, leaving Alice with no control over the contract.
Step 4: Bob can now add and remove other managers, completely taking over the contract.



## Recommended Mitigation Steps

We can add a check to the `remove_manager` function to ensure that the original owner cannot be removed by other managers:
```
fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            assert(old_manager != self.ownable.owner(), 'Cannot remove the owner');  // Prevent removing the owner
            self.chakra_managers.write(old_manager, 0);
            self
                .emit(
                    ManagerRemoved {
                        operator: caller,
                        old_manager: old_manager,
                        removed_at: get_block_timestamp()
                    }
                );
            return self.chakra_managers.read(old_manager) == 0;
        }
```

We could also a `transfer_ownership` function where the owner explicitly transfers their ownership rights.

```
fn transfer_ownership(ref self: ContractState, new_owner: ContractAddress) {
    self.ownable.assert_only_owner();  // Only the owner can transfer ownership
    assert(new_owner != ContractAddress::zero(), 'New owner cannot be zero address');
    self.ownable.transfer_ownership(new_owner);  // Transfer ownership explicitly
    self.emit(OwnershipTransferred { old_owner: self.ownable.owner(), new_owner: new_owner });
}

```
