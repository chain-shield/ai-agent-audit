# Vulnerability details

The `ChakraSettlementHandler::cross_chain_erc20_settlement()` function is responsible for sending cross-chain messages. However, there is a critical problem with the way the function emits the `CrossChainLocked` event. Specifically, the parameters passed to the event are incorrect, which can cause serious problems in tracking and processing cross-chain transactions.
In cross-chain projects, the accuracy of emitted events is as important as the correctness of the underlying logic. These events are often used to verify the integrity of cross-chain transactions, trigger actions in other contracts, or notify off-chain systems. Therefore, any discrepancy in the event data can lead to a chain reaction of errors that can jeopardize the entire cross-chain operation.
The relevant code snippet of the `ChakraSettlementHandler::cross_chain_erc20_settlement()` function is as follows:

Issues Identified:
Misplaced Parameters: The current contract address (address(this)) is incorrectly used as the from_token parameter. This should instead represent the actual ERC20 token address involved in the cross-chain transaction.

## Impact
The impact of this issue is significant because it undermines the reliability and accuracy of event logs, which are crucial for cross-chain communication. Inaccurate event data can cause:

1. Misalignment of Chain Data: Off-chain systems or other contracts that rely on these events to track cross-chain operations may act on incorrect information, leading to failures in executing transactions or validating operations.
2. Security Risks: Incorrect event parameters could be exploited by malicious actors to disrupt the integrity of cross-chain transactions, potentially leading to financial losses or denial of service.
3. Operational Failures: Systems designed to monitor cross-chain events may fail to detect or respond to transactions correctly, resulting in incomplete or failed operations.

## Recommended Mitigation Steps
Correct Parameter Assignment: Ensure that the parameters passed to the CrossChainLocked event are accurate. Specifically, replace `address(this)` with the correct ERC20 token address that should be passed as the `from_token` parameter.
