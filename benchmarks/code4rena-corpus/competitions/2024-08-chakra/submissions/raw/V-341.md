# Vulnerability details

As mentioned in the contest page "A cross-chain message can only be received once. The status of a received transaction in receive_cross_txs must be CrossChainMsgStatus.Unknow before it can be processed".
Specifically, the status of a cross chain message can be Unknow, Pending, Success, or Failed. When a cross chain message is received in the function `receive_cross_chain_msg` in settlement contract, the status of the message can only transition from Unknow to either Success or Failed.
This is a requirement for preventing duplicate reception of cross chain messages, which is fulfilled in `receive_cross_chain_msg` function in ChakraSettlement.sol:
```
require(receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow, "Invalid transaction status");
```
However, there is no validation for the status of received messages in `receive_cross_chain_msg` function in settlement.cairo. Consequently, the settlement contract can receive and handle the same cross chain message multiple times. Additionally, since `receive_cross_chain_msg` in handler_erc20.cairo does not check the status of received messages, tokens can also be transferred multiple times, leading to a loss of funds.

## Recommended Mitigation Steps
Similar to function `receive_cross_chain_msg` in ChakraSettlement.sol, it is required to add following check to the beginning of `receive_cross_chain_msg` function in settlement.cairo to address this issue:
```
assert(self.received_tx.read(cross_chain_msg_id).tx_status == CrossChainMsgStatus::UNKNOW, 'tx status error');
```
