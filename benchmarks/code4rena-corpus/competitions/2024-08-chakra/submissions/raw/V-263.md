# Vulnerability details

## Impact
The lack of strict validation for manager and operator roles allows unauthorized users to gain access to critical functions in the contract. This could lead to unauthorized actors adding themselves as managers or operators, which gives them control over the protocol’s operations, such as staking, withdrawal, or contract upgrades.



## Proof of Concept
There are no access control checks to ensure that only authorized users can add or remove managers or operators. This leaves the door open for malicious actors to assign themselves as managers or operators.

Attack Scenario:

An unauthorized user calls add_manager and adds themselves as a manager.
This grants them access to critical protocol functions like staking and withdrawal, allowing them to drain funds or disrupt operations.

## Tools Used
Access Control Testing: Slither to detect missing access control in critical functions.
Unit Testing: Simulating unauthorized role changes using the StarkNet testing framework.

## Recommended Mitigation Steps
1. Access Control Modifiers: Add strict access control using modifiers like onlyOwner to restrict critical operations to authorized users. Example:


fn add_manager(ref self: TContractState, new_manager: ContractAddress) -> bool {
    assert(get_caller_address() == self.owner, 'Unauthorized');
    self.managers.append(new_manager);
}

2. Multi-Signature Authorization: Implement multi-signature authorization for sensitive operations like adding or removing managers and operators. Example:


fn add_manager_multi_sig(ref self: TContractState, new_manager: ContractAddress, approvals: Array<u256>) -> bool {
    assert(approvals.len() >= 3, 'Insufficient approvals');
    self.managers.append(new_manager);
}

3. Event Logging: Emit events every time a manager or operator is added or removed. This improves transparency and auditability. Example:


#[event]
fn ManagerAdded(manager: ContractAddress);

fn add_manager(ref self: TContractState, new_manager: ContractAddress) -> bool {
    assert(get_caller_address() == self.owner, 'Unauthorized');
    self.managers.append(new_manager);
    emit ManagerAdded(new_manager);
}

4. Unit Testing for Access Control: Write tests that simulate unauthorized attempts to modify managers and operators. Ensure these operations are blocked for unauthorized users. Example:


#[test]
fn test_unauthorized_manager_addition() {
    let unauthorized_address = <malicious address>;
    let result = add_manager(unauthorized_address);
    assert_eq!(result, false, 'Unauthorized manager addition should fail');
}
