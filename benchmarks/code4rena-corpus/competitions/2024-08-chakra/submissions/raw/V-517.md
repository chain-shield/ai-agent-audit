# Vulnerability details

## Impact
The __TokenRoles_init() function is marked as public. Initialization functions should generally be marked as internal to prevent them from being called by anyone after the initialized contract. Leaving the function public could expose the contract to potential attacks or unwanted re-initializations, especially in upgradeable contracts.

## Proof of Concept
Since the __TokenRoles_init() function is marked as public, any external caller can call it at any time, potentially reinitializing the contract with new roles. In a scenario where the function is mistakenly called after initialization, an attacker could reset the contract's ownership and roles.

```
await tokenRoles.__TokenRoles_init(attacker.address, attacker.address);
```

## Tools Used
Manual

## Recommended Mitigation Steps
Change the visibility of __TokenRoles_init() from public to internal to prevent external calls to this function after the contract is deployed.
```
function __TokenRoles_init(address _owner, address _operator) internal {
    __Ownable_init(_owner);
    _grantRole(DEFAULT_ADMIN_ROLE, _owner);
    _grantRole(OPERATOR_ROLE, _operator);
}
```
