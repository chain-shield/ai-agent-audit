# Vulnerability details

## Vulnerability details
Function outputs of the cairo `send_cross_chain_msg()`  do not correlate with solidity function inputs of `receive_cross_chain_msg()` input in the `ChakraSettlement` contacts of these two versions. This could result in errors when starknet is in involved in any cross-chain message.

## Impact
Stakrtnet will be unable to send cross-chain messages to other EVM chains using the protocol.

## Proof Of Concept
Let's look at the output of the `send_cross_chain_msg()` in the cairo version along with the input of the `receive_cross_chain_msg()` of the solidity version.

 ```solidity
             function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external { ... }
  ```
  Let's look at how they will match: (left side is cairo version)
 cross_chain_settlement_id = txid
  - from_address = from_chain
  - from_chain: from_address,
  - to_chain: from_handler,
  - from_handler: to_handler,
  - to_handler: payload_type,
  - payload_type: payload,
  - payload: sign_type,
  - ... = signatures
   
 As can be seen above `from_chain` and `from_address` on the cairo side are mixed up with the solidity side and there is no `to_chain` variable on the receiving end which throws off the matching system even further.

   ## Recommended Mitigation steps
   Ensure that the outputs from cairo functions that will serve as inputs for solidity functions are properly matched.
