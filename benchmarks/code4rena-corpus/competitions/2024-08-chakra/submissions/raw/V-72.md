# Vulnerability details

## Impact

`TokenRoles` contract is the contract that helps to add / remove operators. However, the initialization function can be called again and again allowing to reinitialize the contract which should not be the case.

## Proof of Concept

Current functionality of the initialization:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/TokenRoles.sol#L19-23
```
    function __TokenRoles_init(address _owner, address _operator) public {
        __Ownable_init(_owner);
        _grantRole(DEFAULT_ADMIN_ROLE, _owner);
        _grantRole(OPERATOR_ROLE, _operator);
    }
```

As you can see, the function has no `initializer` modifier that allows to reinitialize the contract. Putting the `initializer()` in the implementation ensures that the storage variable alignment will be automatically correct.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Add `initializer` modifier to the initialization function.
