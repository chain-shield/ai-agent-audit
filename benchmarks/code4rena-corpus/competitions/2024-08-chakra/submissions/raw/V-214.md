# Vulnerability details

## Impact

>I'd like to note that I raised this issue to the sponsors and they also think the remove_manager function should not include the owner.


The `remove_manager` function allows any manager to remove any other manager, including the contract owner.
and from the ReadMe, the manager role is not a trusted role.  This issue could lead to a complete loss of governance control if the owner is removed as a manager. 

## Proof of Concept
Take a look at the [`remove_manager` function](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/ckr_btc.cairo#L148-L161):

```cairo
fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
    self.chakra_managers.write(old_manager, 0);
    self.emit(
        ManagerRemoved {
            operator: caller,
            old_manager: old_manager,
            removed_at: get_block_timestamp()
        }
    );
    return self.chakra_managers.read(old_manager) == 0;
}
```

This function allows any address with manager status to remove any other manager, including the contract owner. There's no check to prevent the removal of the owner from the manager list. An attacker with manager privileges could exploit this to remove the owner's management rights leading to a loss of control over the contract.

Manual review

## Recommended Mitigation Steps
Add a check to prevent the removal of the contract owner as a manager. Additionally, ensure that the address being removed is actually a manager. 

```diff
fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);
+   assert(self.ownable.owner() != old_manager, 'Cannot remove owner as manager');
+   assert(self.chakra_managers.read(old_manager) == 1, 'Address is not a manager');
    self.chakra_managers.write(old_manager, 0);
    self.emit(
```
