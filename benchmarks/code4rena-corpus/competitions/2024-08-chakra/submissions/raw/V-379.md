# Vulnerability details

## Impact
By abusing `ChakraSettlement.send_cross_chain_msg` function, `ChakraSettlementHandler.receive_cross_chain_callback` can be DOSed for ever, which results:
1. for `SettlementMode.MintBurn` mode token, it can't be burned by [ChakraSettlementHandler.sol#L385](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L385)
1. `ChakraSettlementHandler.create_cross_txs[txid].status` will always be `CrossChainTxStatus.Pending`

## Proof of Concept
1. In [ChakraSettlementHandler.cross_chain_erc20_settlement](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L111-L223), the `txid` is calculated based on a group of paramters in [ChakraSettlementHandler.sol#L139-L150](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L139-L150), and one of them is **nonce_manager[msg.sender]**
2. Then in [ChakraSettlementHandler.sol#L154-L163](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L154-L163), a new `create_cross_txs` is created and its status is `CrossChainTxStatus.Pending`
3. Then the function call [settlement.send_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L203-L208)
4. in [ChakraSettlement.send_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L111-L156), another `txid` is created in [ChakraSettlement.sol#L122-L133](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L122-L133), **and please note that `nonce_manager[from_address]` is used here.** And then, `ChakraSettlement.create_cross_txs` is created in [ChakraSettlement.sol#L135-L144](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L135-L144)
5. after `ChakraSettlement.send_cross_chain_msg` finishes executing, [ChakraSettlement.receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L256-L283) will be called, in function `ChakraSettlement.processCrossChainCallback`, `create_cross_txs[txid].status` is checked in [ChakraSettlement.sol#L312-L315](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L312-L315). **Please note that it means that the `txid` here must be equal to the txid generated in [ChakraSettlement.sol#L122-L133](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L122-L133)**, otherwise, the function will revert
6. then the function will call [ISettlementHandler(to_handler).receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L318-L325)
7. in [ChakraSettlementHandler.receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L365-L396), there is a statuc check in [ChakraSettlementHandler.sol#L378-L381](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L378-L381), which means the `txid` used here must be equal to [ChakraSettlementHandler.sol#L139-L150](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L139-L150), otherwise, the function will revert.

So far, to execute `ChakraSettlementHandler.cross_chain_erc20_settlement` successfully, `txid` generated by [ChakraSettlementHandler.cross_chain_erc20_settlement](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L139-L150) must be equal to `txid` generated by [ChakraSettlement.send_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L122-L133)

As shown in [ChakraSettlementHandler.sol#L139-L150](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L139-L150) and [ChakraSettlement.sol#L122-L133](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L122-L133), most of the parameters are the same except the last one: [nonce_manager[msg.sender]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L147) and [nonce_manager[from_address]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L130).

Becase `ChakraSettlement.send_cross_chain_msg` can be called by anyone and [from_address](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L113) is a parameter and can be set to any value, and if `from_address` is set to `ChakraSettlementHandler's address` by a malicious user, `nonce_manager[from_address]` will be increased by one in [ChakraSettlement.sol#L118](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L118), and thus [nonce_manager[from_address]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L118C9-L118C37) will be different from [nonce_manager[msg.sender]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L147).

So after the malicious's call, when a normal user calls `ChakraSettlementHandler.cross_chain_erc20_settlement`, the [nonce_manager[msg.sender]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L147) will be different from [nonce_manager[from_address]](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L130C21-L130C48), which leads different `txid` between `ChakraSettlementHandler.sol` and `ChakraSettlement.sol`.

Then when `ChakraSettlement.receive_cross_chain_callback` is called, the tx will be reverted
