# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: ChakraSettlement contract has Transaction Order Dependence (TOD) in send_cross_chain_msg function.
•	Severity: Medium
•	Impact: Transaction Order Dependence (TOD)
•	Status: Unresolved
•	File: ChakraSettlement.sol
•	Lines Affected: 111-156

There is a potential for Transaction Order Dependence (TOD) in the ChakraSettlement contract, particularly in how transactions are added and managed in the create_cross_txs and receive_cross_txs mappings. If the same txid can be reused or if transactions are processed in a non-sequential order, it could lead to unexpected behavior or even exploitation. This can happen if the ordering of transactions is critical to the correct operation of the contract but is not properly enforced.

Reusing a txid: 
An attacker might exploit the ability to reuse or predict a txid in order to manipulate the contract state. If a transaction is processed out of order or if an older transaction is replayed, it could overwrite important state variables or lead to incorrect handling of cross-chain transactions.

            address(0x1234)
        );
        vm.deal(address(this), 1000 ether);
    }

    function testTxidReuse() public {
        // Simulate sending a cross-chain message
        bytes memory payload = abi.encode("TestPayload");
        settlement.send_cross_chain_msg(
            "TargetChain",
            address(this),
            1,
            PayloadType.Raw,
            payload
        );

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    "TestChain",
                    "TargetChain",
                    address(this),
                    address(this),
                    "1",
                    "1"
                )
            )
        );

        // Manipulate the transaction order by reusing the txid
        // This simulates the replay or out-of-order processing
        settlement.send_cross_chain_msg(
            "TargetChain",
            address(this),
            1,
            PayloadType.Raw,
            payload
        );

        // Verify that the second transaction did not override the first one
        // and the state is as expected
    }
}

## Recommended Mitigation Steps
To mitigate the risk of transaction order dependence, the contract should implement a mechanism to ensure that transactions are processed in the correct order and that txids cannot be reused or overwritten. One possible solution is to add a nonce or timestamp to the transaction data to make txids unique and non-reusable.
```sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract ChakraSettlement is BaseSettlement {
    mapping(uint256 => CreatedCrossChainTx) public create_cross_txs;
    mapping(uint256 => ReceivedCrossChainTx) public receive_cross_txs;
    mapping(address => uint256) public nonce_manager; // Add a nonce mapping to enforce order

    /**
     * @dev Struct for created cross-chain transactions
     */
    struct CreatedCrossChainTx {
        uint256 txid;
        string from_chain;
        string to_chain;
        address from_address;
        address from_handler;
        uint256 to_handler;
        bytes payload;
        CrossChainMsgStatus status;
        uint256 nonce; // Include a nonce to enforce transaction order
    }

    /**
     * @dev Function to send cross-chain message
     */
    function send_cross_chain_msg(
        string memory to_chain,
        address from_address,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload
    ) external {
        nonce_manager[from_address] += 1; // Increment the nonce

        address from_handler = msg.sender;

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    contract_chain_name,
                    to_chain,
                    from_address,
                    from_handler,
                    to_handler,
                    nonce_manager[from_address] // Include nonce in txid calculation
                )
            )
        );

        create_cross_txs[txid] = CreatedCrossChainTx(
            txid,
            contract_chain_name,
            to_chain,
            from_address,
            from_handler,
            to_handler,
            payload,
            CrossChainMsgStatus.Pending,
            nonce_manager[from_address] // Store nonce in transaction
        );

        emit CrossChainMsg(
            txid,
            from_address,
            contract_chain_name,
            to_chain,
            from_handler,
            to_handler,
            payload_type,
            payload
        );
    }
}
```
The ChakraSettlement contract has a potential vulnerability due to transaction order dependence. By implementing nonce management and enforcing the correct processing order of transactions, this issue can be mitigated effectively.
