# Vulnerability details

## Impact

`message_hash` is incorrectly computed, which will not allow signature verification.

## Proof of Concept

The `message_hash` that validators will sign to execute `receive_cross_chain_msg()` contains 2 fields (`payload` and `from_chain`) that are dynamic types (`bytes` and `string`).

```solidity
function receive_cross_chain_msg(
    uint256 txid,
    string memory from_chain,
    uint256 from_address,
    uint256 from_handler,
    address to_handler,
    PayloadType payload_type,
    bytes calldata payload,
    uint8 sign_type, // validators signature type /  multisig or bls sr25519
    bytes calldata signatures // signature array
) external {
    {
        // verify signature
        bytes32 message_hash = keccak256(
            abi.encodePacked(
                txid,
                from_chain, // AUDIT - missing keccak256
                from_address,
                from_handler,
                to_handler,
                keccak256(payload)
            )
        );
```

When a parameter of either of these two types is used in `message_hash`, its `keccak256` result must be used, since the value of these types is `dynamic`.

## Recommended Mitigation Steps

```diff
function receive_cross_chain_msg(
    uint256 txid,
    string memory from_chain,
    uint256 from_address,
    uint256 from_handler,
    address to_handler,
    PayloadType payload_type,
    bytes calldata payload,
    uint8 sign_type, // validators signature type /  multisig or bls sr25519
    bytes calldata signatures // signature array
) external {
    {
        // verify signature
        bytes32 message_hash = keccak256(
            abi.encodePacked(
                txid,
-               from_chain,
+               keccak256(from_chain),
                from_address,
                from_handler,
                to_handler,
                keccak256(payload)
            )
        );
```
