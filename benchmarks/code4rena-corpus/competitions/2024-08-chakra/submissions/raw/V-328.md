# Vulnerability details

The two functions, `add_validator` and `remove_validator`, are essential components for managing validators in the contract. They allow for adding and removing validators who are critical for maintaining the integrity of the system. However, their current structure could lead to potential issues, such as external calls to signature_verifier are made before checking or updating the state of the contract, for `add-validator`, it lead to adding an already existing validator to the signature_verifier contract, which can cause duplicate validator entries where validators can be added multiple times in the external contract if not checked beforehand and inconsistent validator states where the signature_verifier may accept a validator, but the internal contract might not reflect this addition if the validator already exists. For the `remove_validator`, it can lead to unnecessary external calls, wasted gas, and possibly a failed operation.

## Proof of Concept
In the current implementation of [`add_validator`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/BaseSettlement.sol#L88-L97),  the external call to `signature_verifier.add_validator(validator)` is made before checking if the validator already exists in the `chakra_validators` mapping. 

```solidity
function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
        signature_verifier.add_validator(validator);
        require(
            chakra_validators[validator] == false,
            "Validator already exists"
        );
        chakra_validators[validator] = true;
        validator_count += 1;  
        emit ValidatorAdded(msg.sender, validator);
    }
```
Also in [`remove_validator`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/BaseSettlement.sol#L103-L114), the external call to `signature_verifier.remove_validator(validator)` is made before validating whether the validator exists in the internal state (`chakra_validators`). This can lead to unnecessary external calls, wasted gas, and possibly a failed operation.
```solidity
function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        signature_verifier.remove_validator(validator);
        require(
            chakra_validators[validator] == true,
            "Validator does not exists"
        );
        chakra_validators[validator] = false;
        validator_count -= 1;
        emit ValidatorRemoved(msg.sender, validator);
    }
```

## Recommended Mitigation Steps
Reorder the operations in the `add_validator` and `remove_validator` functions to perform state checks before interacting with the `signature_verifier`. This ensures that unnecessary operations are avoided and logical consistency is maintained.
For the `add_validator` function, check if the validator already exists in `chakra_validators` before calling `signature_verifier.add_validator`.
```diff
function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(chakra_validators[validator] == false, "Validator already exists");
    signature_verifier.add_validator(validator);
    chakra_validators[validator] = true;
    validator_count += 1;
    emit ValidatorAdded(msg.sender, validator);
}
```
For the `remove_validator`, verify if the validator exists in `chakra_validators` before calling `signature_verifier.remove_validator`.
```diff
function remove_validator(address validator) external onlyRole(MANAGER_ROLE) {
    require(chakra_validators[validator] == true, "Validator does not exist");
    signature_verifier.remove_validator(validator);
    chakra_validators[validator] = false;
    validator_count -= 1;
    emit ValidatorRemoved(msg.sender, validator);
}
```
