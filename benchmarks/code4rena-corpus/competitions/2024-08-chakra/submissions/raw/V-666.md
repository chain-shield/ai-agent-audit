# Vulnerability details

## Impact
The wrong address is saved inside the Struct holding the data for the created transactions from `ChakraSettleHandler.sol`, which can lead to unexpected behavior when executing transfers.

## Description
The `ChakraSettlementHandler::cross_chain_erc20_settlement()` function saves all the details of a transaction in a `CreatedCrossChainTx` struct:

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/ChakraSettlementHandler.sol#L152-L164

```solidity
function cross_chain_erc20_settlement(
        string memory to_chain,
        uint256 to_handler,
        uint256 to_token,
        uint256 to,
        uint256 amount
    ) external {

...

           // Save the cross chain tx
            create_cross_txs[txid] = CreatedCrossChainTx(
                txid,
                chain,
                to_chain,
                msg.sender,
                to,
        ---->        address(this),
                to_token,
                amount,
                CrossChainTxStatus.Pending
            );
...

}
```

And this is the definition of the struct:

```solidity
struct CreatedCrossChainTx {
        uint256 txid;
        string from_chain;
        string to_chain;
        address from;
        uint256 to;
        address from_token; <-----
        uint256 to_token;
        uint256 amount;
        CrossChainTxStatus status;
}
```

If you compare the two snippets you will see that `address(this)` (`ChakraSettlementHandler.sol`) is assigned as `from_token`. Which is not the correct address, since the token is a separate contract( storen in the `token` variable).

As proof that `address(this)` is not the intended address by the protocol team, we can look at the same code used in the Cairo contracts:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L184-L194

```cairo

fn cross_chain_erc20_settlement(......) -> felt252 {

....

 let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
                    from_chain: from_chain,
                    to_chain: to_chain,
                    from: get_contract_address(),
                    to: to,
        ----->            from_token: self.token_address.read(),
                    to_token: to_token,
                    amount: amount,
                    tx_status: CrossChainTxStatus::PENDING
                };
....
}

``` 

As you can see the `token` variable is used and not `address(this)`. The `token` is the one that is used when executing transfers in and out of the handler contract so it is the correct one to be assigned.

## Tools Used
Manual review

## Recommended Mitigation Steps

Update the `from_token` field of the `CreatedCrossChainTx` struct inside `ChakraSettleHandler.sol` to use `token` variable and not `address(this)`

Invalid Validation
