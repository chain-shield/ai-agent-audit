# Vulnerability details

## Description  

The `ChakraSettlementHandler` contract is designed to handle cross-chain ERC20 settlements. It supports multiple settlement modes (`MintBurn`, `LockUnlock`, `LockMint`, `BurnUnlock`) which dictate how tokens are managed during cross-chain transactions. The [`cross_chain_erc20_settlement()` function](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L111-L223) initiates these transactions by locking or burning tokens based on the mode. However, the [`receive_cross_chain_callback()` function](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L365-L396), which processes the completion of these transactions, only handles the `MintBurn` mode correctly. This oversight can lead to significant issues in other modes.

### Detailed Description

   The `cross_chain_erc20_settlement()` function locks or burns tokens based on the `SettlementMode`.

2. **Receive Cross-Chain Callback Function**:

Other modes (`LockUnlock`, `LockMint`, `BurnUnlock`) are not handled properly, leading to potential fund loss or freezing.

### Issue

- **LockUnlock and LockMint Modes**:
  Tokens are locked in the contract but never released or burned, leading to indefinite freezing of user funds.

- **BurnUnlock Mode**:
  Tokens are burned initially but never minted back if the transaction fails, leading to permanent loss of funds.

## Impact

The improper handling of cross-chain transaction modes can lead to significant financial losses for users. In `LockUnlock` and `LockMint` modes, tokens can be indefinitely frozen in the contract. In `BurnUnlock` mode, tokens can be permanently lost if the transaction fails. This undermines the reliability and security of the cross-chain settlement process.

## Proof of Concept

1. **User initiates a cross-chain transaction in `LockUnlock` mode**:
   - The `cross_chain_erc20_settlement()` function locks tokens in the contract.

2. **Cross-chain transaction completes successfully**:
   - The `receive_cross_chain_callback()` function is called but does not unlock the tokens, leading to indefinite freezing of user funds.

## Tools Used

Manual review

## Recommended Mitigation Steps

Update the `receive_cross_chain_callback()` function to handle all settlement modes correctly
