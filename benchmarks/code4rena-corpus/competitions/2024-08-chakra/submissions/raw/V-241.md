# Vulnerability details

## Impact
The TokenRoles.sol, BaseSettlementHandler.sol, and BaseSettlement.sol contracts are abstract contracts intended for inheritance. However, these contracts lack a storage gap feature. This omission could potentially lead to storage collisions when upgrading contract implementations. In upgradeable contracts, this issue could result in unintended overwriting of variables in child contracts by new variables added to the base contract during upgrades.

## Proof of Concept
You can check the following link as a reference from OZ:
https://docs.openzeppelin.com/contracts/3.x/upgradeable#:~:text=Storage%20Gaps,50%20storage%20slots).

## Tools Used
Manual review

## Recommended Mitigation Steps
Add storage gaps to the abstract contracts. Consider using the following pattern:
```
uint256[50] private __gap;
```
This pattern aligns with best practices recommended by OZ for upgradeable contract deployments. By implementing this storage gap, developers can safely extend contract functionality without risking unintended consequences in existing deployments.
