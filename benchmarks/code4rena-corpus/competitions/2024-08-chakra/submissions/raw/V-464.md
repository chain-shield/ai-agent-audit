# Vulnerability details

## Impact
The `cross_chain_erc20_settlement` function in the ChakraSettlementHandler contract incorrectly handles tokens in the MintBurn settlement mode. Instead of burning tokens as expected in a MintBurn model, it locks them. This discrepancy can lead to:

Inconsistent token supply across chains: Tokens are minted on the destination chain without being destroyed on the source chain, potentially inflating the total supply.
Violation of the MintBurn settlement model: The actual behavior doesn't match the expected MintBurn operation, which could disrupt cross-chain settlements and cause confusion for users and integrators.
Potential for double-spending: If tokens are locked instead of burned, there's a risk they could be unlocked and spent again on the source chain.

## Proof of Concept
In the cross_chain_erc20_settlement function:
```solidity
if (mode == SettlementMode.MintBurn) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockUnlock) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockMint) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.BurnUnlock) {
    _erc20_burn(msg.sender, amount);
}
```
The MintBurn mode uses _erc20_lock instead of _erc20_burn, which is inconsistent with the expected behavior of a MintBurn settlement model.
