# Vulnerability details

## Impact

In Cairo contracts (`ckr_btc.cairo` and `settlements.cairo`) **`add/remove`** manager **can be performed by other managers** instead of being based on the owner as in solidity contracts.

```solidity
function add_manager(address _manager) external onlyOwner {
    grantRole(MANAGER_ROLE, _manager);
    emit ManagerAdded(msg.sender, _manager);
}

function remove_manager(address _manager) external onlyOwner {
    revokeRole(MANAGER_ROLE, _manager);
    emit ManagerRemoved(msg.sender, _manager);
}
```

## Proof of Concept

Cairo contracts should be the same as Solidity's, they just allow Starknet to be used as a chain. But there is a difference in the authority hierarchy that allows managers to remove other managers, remove the owner from manager mappings, etc.

`add_manager()` and `remove_manager()` must have the `onlyOwner` modifier to prevent other managers from modifying it.

```rust
fn add_manager(ref self: ContractState, new_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
    assert(caller != new_manager, 'Caller is a manager already');
    self.chakra_managers.write(new_manager, 1);
    self
        .emit(
            ManagerAdded {
                operator: caller, new_manager: new_manager, added_at: get_block_timestamp()
            }
        );
    return self.chakra_managers.read(new_manager) == 1;
}

fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
    self.chakra_managers.write(old_manager, 0);
    self
        .emit(
            ManagerRemoved {
                operator: caller,
                old_manager: old_manager,
                removed_at: get_block_timestamp()
            }
        );
    return self.chakra_managers.read(old_manager) == 0;
}
```

## Tools Used

Manual Review

## Recommended Mitigation Steps

`add_manager()` and `remove_manager()` should be `onlyOwner`, prevent the manager from removing other managers, and maintain the same hierarchy in all the chains.
