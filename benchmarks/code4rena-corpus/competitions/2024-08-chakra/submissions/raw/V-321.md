# Vulnerability details

## Impact
The contract use `verify` function to ensure data is signed by validators set by `MANAGER_ROLE`. But it was false to check if a validator is already used in signature verification. e.g. Validator A can  sign msg `hello poc` three times and provide the msg and 3 same signature to `verify` function, because A is the valid validator, each time in for loop `validators[msgHash.recover(sig)]` is True and `m` also increase, which finally meets the required_validators(assume threshold is 3).

In this case, one validator can make malicious cross chain request.

## Proof of Concept
Provide same signature when `receive_cross_chain_msg` function is called 

## Tools Used
Manually review

## Recommended Mitigation Steps
1. Each time a validator is used, add `is_used_validator[validator] == True`
2. Before verification is stared, check ``is_used_validator[validator] == False`
