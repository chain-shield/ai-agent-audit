# Vulnerability details

The check_chakra_signatures function in settlement.cairo only checks if the number of valid signatures is greater than or equal to required_validators_num. However, there's no check to ensure that the signatures correspond to the correct transaction or message. This can lead to replay attacks where a valid signature from one transaction is reused for another, compromising the integrity of the system.

AFFECTED LINES OF CODE:

fn check_chakra_signatures(

            let mut pass_count = 0;
            let mut i = 0;

                    pass_count += 1;

                i += 1;

        }
    }



Impact: Allows unauthorized transactions to be validated, potentially leading to loss of funds or unauthorized actions.




Remediation
To mitigate this vulnerability, the check_chakra_signatures function should be modified to verify the signature against the specific message hash. This can be done by incorporating the message hash into the signature verification process.

Here's a modified version of the function that includes the necessary checks:



fn check_chakra_signatures(
    self: @ContractState,
    message_hash: felt252,
    signatures: Array<(felt252, felt252, bool)>
) {
    let mut pass_count = 0;
    let mut i = 0;
    loop {
        if i > signatures.len() - 1 {
            break;
        }
        let (r, s, y) = *signatures.at(i);
        let pub_key: felt252 = recover_public_key(message_hash, r, s, y).unwrap();
        if self.chakra_validators_pubkey.read(pub_key) > 0 {
            // Verify signature for the specific message_hash
            assert!(verify_signature(message_hash, pub_key, r, s, y), "Invalid signature");
            pass_count += 1;
        }
        i += 1;
    }
    assert!(pass_count >= self.required_validators_num.read(), "Not enough valid signatures");
}
