# Vulnerability details

## Impact

In the `cross_chain_erc20_settlement()`, users submit their cross-chain transactions to transfer tokens and release them on the destination handler contract. However, as per specification, there is no nonce increase to ensure the uniqueness of the transaction ids.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L167-232

As you can see, the nonce is not incremented the same way it's done in the Ethereum part of the codebase:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L133-136
```
 {
            // Increment nonce for the sender
            nonce_manager[msg.sender] += 1;
        }
```

As per docs:

```
The nonce for each sender is incremented with each cross-chain transaction to ensure uniqueness of transaction IDs.
```

## Tools Used

Manual review.

## Recommended Mitigation Steps

Create `nonce_manager` mapping in the contract and increase the nonce for `msg.sender` with each transaction.
