# Vulnerability details

## Impact
The absence of the `_disableInitializers()` function in the Chakra contracts using the `initialize()` function presents a critical vulnerability. The `initialize()` function is typically used in upgradeable contracts (based on proxy patterns) to replace constructors. Without calling `_disableInitializers()`, the contract is vulnerable to reinitialization attacks, where an attacker could reinitialize the contract and take control by setting themselves as the owner or altering critical parameters. This vulnerability could result in loss of control over the contract and manipulation of the contract state, leading to potential financial loss, fraud, or denial of service to the contract's users.

## Proof of Concept
Consider a contract using the `initialize` function, for example the the `BaseSettlement` contract
```solidity
        function _Settlement_handler_init(
        address _owner,
        SettlementMode _mode,
        address _token,
        address _verifier,
        string memory _chain,
        address _settlement
    ) public {
        __Ownable_init(_owner);
        __UUPSUpgradeable_init();
        settlement = ISettlement(_settlement);
        verifier = ISettlementSignatureVerifier(_verifier);
        mode = _mode;
        token = _token;
        chain = _chain;
    }
```
In the above implementation, `initialize()` can only be called once when using the `initializer` modifier. However, without `_disableInitializers()`, after the contract is deployed, a malicious actor could potentially deploy a new proxy pointing to the same implementation contract and call `initialize() again`, taking control of the contract. This can lead to unauthorized ownership change, alteration of contract logic and states or potential manipulation of users' funds

## Tools Used
Manual Review

## Recommended Mitigation Steps
To mitigate this issue, after the contract is initialized, call the `_disableInitializers()` function to lock the contract against any further reinitializations. This ensures that the `initialize()` function can only be used once, even if the contract is redeployed via proxy.
