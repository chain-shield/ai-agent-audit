# Vulnerability details

## Impact
Cairo code has a critical vulnerability due to inconsistent creation of tx_ids between `ERC20Handler` and `ChakraSettlement` contracts.The tx_id is generated using different storage values (`msg_count` in ERC20Handler and `tx_count` in ChakraSettlement). The assumption is that both contracts will produce the same tx_id for corresponding cross-chain transactions. However, the function `ChakraSettlement::send_cross_chain_msg` can be called by anyone, which allows unauthorized updates to the `tx_count` storage variable in the ChakraSettlement contract. Due to this discrepancy, the tx_id values generated by `ChakraSettlement` and `ERC20Handler` can become unsynchronized. 
This would broke the logic in `ChakraSettlement::receive_cross_chain_callback` function that use this tx_id and call `ERC20Handler::receive_cross_chain_callback`.


## Proof of Concept

`ERC20Handler::cross_chain_erc20_settlement` function creates new tx_id using transaction hash and msg_count storage variable.Then increase msg_count and calls settlement contract.
