# Vulnerability details


The `ChakraSettlement::receive_cross_chain_msg()` function is responsible for handling incoming cross-chain messages. However, there is a critical issue in the way this function emits the `CrossChainHandleResult` event. Specifically, the parameters passed to the event are incorrect, which can lead to severe issues in tracking and processing cross-chain transactions.

In cross-chain projects, the accuracy of emitted events is as important as the correctness of the underlying logic. These events are often used to verify the integrity of cross-chain transactions, trigger actions in other contracts, or notify off-chain systems. Therefore, any discrepancy in the event data can cause a chain reaction of errors, potentially compromising the entire cross-chain operation.

The relevant code snippet from the `ChakraSettlement::receive_cross_chain_msg()` function is as follows:
```js
    // ChakraSettlement::CrossChainHandleResult()  
    // cross chain handle result emit by receive side
    event CrossChainHandleResult(
        uint256 indexed txid,
        CrossChainMsgStatus status,
        string from_chain,
        string to_chain,
        address from_handler,
        uint256 to_handler,
        PayloadType payload_type
    );
    // ChakraSettlement::receive_cross_chain_msg()
    function receive_cross_chain_msg(
        uint256 txid,
        string memory from_chain,
        uint256 from_address,
        uint256 from_handler,
        address to_handler,
        PayloadType payload_type,
        bytes calldata payload,
        uint8 sign_type, // validators signature type /  multisig or bls sr25519
        bytes calldata signatures // signature array
    ) external {
 
        // SNIP... 

        emit CrossChainHandleResult(
            txid,
            status,
@>            contract_chain_name, // from_chain
@>            from_chain, // to_chain
@>            address(to_handler), // from_handler
@>            from_handler, // to_handler
            payload_type
        );
    }
```
Misplaced Parameters:
1. `contract_chain_name` is assigned to the `from_chain` parameter of the event, whereas it should logically represent the `to_chain` since it refers to the current contract's chain.
2. `from_chain` is incorrectly assigned to the `to_chain` parameter.
3. `address(to_handler)` is mistakenly passed as `from_handler`, while `from_handler`(which is a uint256) is used as `to_handler`.
These incorrect assignments lead to the emission of an event that misrepresents the source and destination of the cross-chain message, as well as the handlers involved in the transaction.
## Impact
The impact of this issue is significant because it undermines the reliability and accuracy of event logs, which are crucial for cross-chain communication. Inaccurate event data can cause:

1. Misalignment of Chain Data: Off-chain systems or other contracts that rely on these events to track cross-chain operations may act on incorrect information, leading to failures in executing transactions or validating operations.
2. Security Risks: Incorrect event parameters could be exploited by malicious actors to disrupt the integrity of cross-chain transactions, potentially leading to financial losses or denial of service.
3. Operational Failures: Systems designed to monitor cross-chain events may fail to detect or respond to transactions correctly, resulting in incomplete or failed operations.

## Recommended Mitigation Steps

Correct Parameter Assignment: Ensure that the parameters passed to the `CrossChainHandleResult` event reflect the correct values:
Assign `contract_chain_name` to `to_chain`.
Assign `from_chain` to `from_chain`.
Assign `address(to_handler)` correctly as `to_handler`.
Assign `from_handler` correctly as `from_handler`.
