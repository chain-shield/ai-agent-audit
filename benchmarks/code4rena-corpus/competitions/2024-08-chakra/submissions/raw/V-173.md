# Vulnerability details

## Impact
The system relies on the `status` of transactions to ensure that actions are taken based on the current state. Without checking the `status` of a received tx, the system might re-process transactions that are already marked as `Failed` or `Success`, leading to inconsistencies in transaction history and state.

## Proof of Concept
One of the Main Invariants in Settlement Contract is:
> A cross-chain message can only be received once. The status of a received transaction in receive_cross_txs must be CrossChainMsgStatus.Unknow before it can be processed.

Therefore, in `ChakraSettlement.sol`, before processing the received cross-chain message, there is a [verification step](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L199-L202) that checks the `status` of the transaction:
```solidity
            require(
                receive_cross_txs[txid].status == CrossChainMsgStatus.Unknow,
                "Invalid transaction status"
            );
```
This line ensures that the transaction status is `Unknow` (indicating that it has not been processed) before proceeding. If the transaction has already been processed (status is not `Unknow`), the function will revert, stopping any further execution and preventing duplicate processing.

After the message is successfully processed, the [status is updated](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L228-L233) to either `Success` or `Failed` based on the outcome of the processing:
```solidity
    if (result == true) {
        status = CrossChainMsgStatus.Success;
>>      receive_cross_txs[txid].status = CrossChainMsgStatus.Success;
    } else {
>>      receive_cross_txs[txid].status = CrossChainMsgStatus.Failed;
    }
```

However, in [`settlement::receive_cross_chain_msg()`](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L352-L370) the status of the received transaction is not verified. 
The function simply calls handler `receive_cross_chain_msg` and updates the receive tx status as follows:

```solidity
            // call handler receive_cross_chain_msg
            let handler = IHandlerDispatcher{contract_address: to_handler};
>>          let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

            let mut status = CrossChainMsgStatus::SUCCESS;
            if success{
                status = CrossChainMsgStatus::SUCCESS;
            }else{
                status = CrossChainMsgStatus::FAILED;
            }

            self.received_tx.write(cross_chain_msg_id, ReceivedTx{
                tx_id:cross_chain_msg_id,
                from_chain: from_chain,
                from_handler: from_handler,
                to_chain: to_chain,
                to_handler: to_handler,
>>              tx_status: status
            });
```
This would result in a cross-chain message being received and processed more than once.

## Recommended Mitigation Steps
Perform received-status validation before processing the message
```diff
+   assert(self.received_tx.read(cross_chain_msg_id).tx_status == CrossChainMsgStatus::UNKNOW, 'tx status error');
```
