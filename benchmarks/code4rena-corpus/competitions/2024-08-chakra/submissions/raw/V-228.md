# Vulnerability details


## Impact
The `set_required_validators_num` function allows any address with the `MANAGER_ROLE` to set the `required_validators` to an invalid value. Since the `MANAGER_ROLE` is not a trusted role, this could lead to two critical issues:
1. Setting `required_validators` to zero, which would disable the validation mechanism entirely.
2. Setting `required_validators` to a value greater than the current number of validators (`validator_count`), making it impossible to reach consensus and halting the contract's operations.

This could result in a denial of service (DoS) or a complete breakdown of the validation system, as the contract would be unable to function correctly without a valid number of validators.

## Proof of Concept
 `set_required_validators_num` function does not include any checks to ensure that the new value for `required_validators` is valid:
https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/BaseSettlement.sol#L121-L127

```solidity
function set_required_validators_num(
    uint256 _required_validators
) external onlyRole(MANAGER_ROLE) {
    uint256 old = required_validators;
    required_validators = _required_validators;
    emit RequiredValidatorsChanged(msg.sender, old, required_validators);
}
```

### Issue 1: Setting `required_validators` to zero
A manager could call the function with `_required_validators = 0`, effectively disabling the validation mechanism, as no validators would be required to approve transactions.

### Issue 2: Setting `required_validators` higher than `validator_count`
A manager could set `_required_validators` to a value greater than the current number of validators (`validator_count`). This would make it impossible to reach the required number of validator approvals, potentially halting the contract's operations.


## Tools used
Manual review

## Recommended Mitigation Steps
implement strict checks within the `set_required_validators_num` function. Ensure that the new value is greater than zero and does not exceed the current total validator count. Alternatively, consider implementing a multi-signature or time-lock mechanism for changing critical parameters like `required_validators`, especially given that managers are not trusted roles.
