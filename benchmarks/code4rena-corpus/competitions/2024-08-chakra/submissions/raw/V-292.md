# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Title: ChakraSettlementHandler contract has Lack of Return Value Handling in ERC20 Token Transfer on safe_transfer function.
Severity: Medium.
Issue Type: Unsafe token transfer on return value.
Contract: ChakraSettlementHandler.sol
Function: _safe_transfer(address to, uint256 amount)

The _safe_transfer function does not correctly handle the return value of the IERC20(token).transfer(to, amount) call. According to the ERC-20 standard, the transfer function returns a boolean value indicating success. Some tokens (particularly non-standard or improperly implemented ERC-20 tokens) may return false instead of reverting on failure, leading to situations where the contract assumes the transfer succeeded when it actually failed. This could cause significant issues, including loss of funds or incorrect accounting in cross-chain settlements, particularly because this function handles token transfers between chains.

## Proof of Concept

Consider the following ERC-20 token implementation, which silently returns false on failure without reverting:
```sol
contract FaultyERC20 {
    mapping(address => uint256) public balances;

    function transfer(address to, uint256 amount) external returns (bool) {
        if (balances[msg.sender] < amount) {
            return false; // Silently fail
        }
        balances[msg.sender] -= amount;
        balances[to] += amount;
        return true;
    }
}
```

The _safe_transfer function in ChakraSettlementHandler would behave as follows:
```sol
function _safe_transfer(address to, uint256 amount) internal {
    require(
        IERC20(token).balanceOf(address(this)) >= amount,
        "Insufficient balance"
    );

    // transfer tokens
    IERC20(token).transfer(to, amount); // Fails silently if transfer returns false
}
```

In this case, if IERC20(token).transfer(to, amount) returns false, the function would not revert, and the contract would proceed assuming the transfer succeeded. This could lead to incorrect behavior such as continuing with a cross-chain settlement while tokens were not actually transferred.

## Recommended Mitigation Steps

To ensure safety, the contract should check the return value of the transfer function and revert if the transfer fails. The function can be modified as follows:
```sol
function _safe_transfer(address to, uint256 amount) internal {
    require(
        IERC20(token).balanceOf(address(this)) >= amount,
        "Insufficient balance"
    );

    // transfer tokens and ensure success
    bool success = IERC20(token).transfer(to, amount);
    require(success, "Token transfer failed");
}
```

This update ensures that if the transfer function fails, the transaction will revert, preventing any incorrect state updates or assumptions within the contract.
