# Vulnerability details

## Impact
During cross chain `callback`, tokens are burned even if the tx fails. There is no check to ensure that tokens are only burned when the cross-chain operation has been confirmed to be successful. This thereby undermines consistency and integrity of token management across chains.

## Proof of Concept
`Token burning` process during the `cross-chain callback` is crucial because it confirms the completion of the transaction. Once the `cross-chain message` is successfully processed and the tokens are minted on the `destination chain`, the corresponding amount of tokens is burned on the `source chain` to finalize the transaction and balance the `token supply`.

According to the `ChakraSettlementHandler.sol` contract, the burning of tokens occurs within the [`receive_cross_chain_callback`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L383-L393) function only when the `status` of the cross-chain message is `CrossChainMsgStatus.Success`. If the status is `CrossChainMsgStatus.Failed`, the transaction status is updated to Failed, but no burning occurs.
```solidity
        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }

        if (status == CrossChainMsgStatus.Failed) {
            create_cross_txs[txid].status = CrossChainTxStatus.Failed;
        }
```

However, in [`handler_erc20::receive_cross_chain_callback()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L148-L162), the status of the cross-chain message (`cross_chain_msg_status`)  is not used to determine whether or not to `burn tokens`:
```solidity
        fn receive_cross_chain_callback(ref self: ContractState, cross_chain_msg_id: felt252, from_chain: felt252, to_chain:   felt252, from_handler: u256, to_handler: ContractAddress, cross_chain_msg_status: u8) -> bool{

            // @audit-info  Does not check if cross_chain_msg_status::SUCCESS before burning
            if self.mode.read() == SettlementMode::MintBurn{
>>              erc20.burn_from(get_contract_address(), self.created_tx.read(cross_chain_msg_id).amount);
            }
            let created_tx = self.created_tx.read(cross_chain_msg_id);
            self.created_tx.write(cross_chain_msg_id, CreatedCrossChainTx{
                tx_id: created_tx.tx_id,
                from_chain: created_tx.from_chain,
                to_chain: created_tx.to_chain,
                from:created_tx.from,
                to:created_tx.to,

                to_token: created_tx.to_token,
                amount: created_tx.amount,
>>              tx_status: CrossChainTxStatus::SETTLED
            });
            // @audit-info  Does not handle when cross_chain_msg_status::FAILED

```
As seen above, the function directly burns the tokens and sets `tx_status` to `SETTLED` without making any refference to the status of the cross-chain message (`cross_chain_msg_status`).
---> This is incorrect as any status will result in token burning nonetheless.
