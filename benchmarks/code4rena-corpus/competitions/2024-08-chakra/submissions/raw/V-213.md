# Vulnerability details

## Impact

The owner of the handler / settlement contract has to be able to add / remove the owner of the handler. However, on the Starknet chain it cannot be done done so as `remove_handler()` functionality is missing.

## Proof of Concept

There is only `set_support_handler()` function in the cairo version of the handler contract:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L238
```
   fn set_support_handler(ref self:ContractState, chain_name: felt252, handler: u256, support: bool){
            self.ownable.assert_only_owner();
            self.support_handler.write((chain_name, handler), support);
        }
```

According to the spec:

```
Only the owner can add or remove handlers from the whitelist for a given chain.
```

In contrary, this functionality is properly implemented on Ethereum:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L65-70
```
 function remove_handler(
        string memory chain_name,
        uint256 handler
    ) external onlyOwner {
        handler_whitelist[chain_name][handler] = false;
    }

```

Therefore, the current implementation has deviations from the docs resulting in an unexpected behavior where the owner cannot remove the handler in some cases when he needs to.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Add `remove_handler()` functionality in the `handler_erc20`.
