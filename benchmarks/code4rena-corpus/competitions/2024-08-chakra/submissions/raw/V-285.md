# Vulnerability details

Cross-chain callbacks can only be processed for transactions that have a Pending status in the created_tx mapping.
Users can call `cross_chain_erc20_settlement` in the handler_erc20.cairo. `cross_chain_erc20_settlement` creates a mapping for this new transaction in created_tx with tx_status set as CrossChainTxStatus::PENDING:
```
let tx_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.msg_count.read()); //@audit-ok dont we need nonce?
            let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
                    from_chain: from_chain,
                    to_chain: to_chain,
                    from: get_contract_address(),
                    to: to,
                    from_token: self.token_address.read(),
                    to_token: to_token,
                    amount: amount,
                    tx_status: CrossChainTxStatus::PENDING
                };
            self.created_tx.write(tx_id, tx);
```
 
Then, function `send_cross_chain_msg` in settlement.cairo is called, and a CrossChainMsg event is emitted. Then, validators call `receive_cross_chain_msg` in ChakraSettlement.sol, then there will be another CrossChainHandleResult event that will be monitored by validators, that will call `receive_cross_chain_callback` in settlement.cairo. Function `receive_cross_chain_callback` will call `receive_cross_chain_callback` in handler_erc20.cairo. Now, it is needed to check the status of transaction since cross-chain callbacks can only be processed for transactions that have a Pending status in the created_tx mapping. This check exists in function `receive_cross_chain_callback` in ChakraSettlementHandler.sol:
```
require(
            create_cross_txs[txid].status == CrossChainTxStatus.Pending, 
            "invalid CrossChainTxStatus"
        );
```
However, function `receive_cross_chain_callback` in handler_erc20.cairo lacks this check. Indeed, the transaction status in handler_erc20.cairo which is set in function `cross_chain_erc20_settlement` has never being checked:
```
fn receive_cross_chain_callback(ref self: ContractState, cross_chain_msg_id: felt252, from_chain: felt252, to_chain: felt252,
        from_handler: u256, to_handler: ContractAddress, cross_chain_msg_status: u8) -> bool{
            assert(to_handler == get_contract_address(),'error to_handler');

            assert(self.settlement_address.read() == get_caller_address(), 'not settlement');

            assert(self.support_handler.read((from_chain, from_handler)) && 
                    self.support_handler.read((to_chain, contract_address_to_u256(to_handler))), 'not support handler');

            let erc20 = IERC20MintDispatcher{contract_address: self.token_address.read()};
            if self.mode.read() == SettlementMode::MintBurn{
                erc20.burn_from(get_contract_address(), self.created_tx.read(cross_chain_msg_id).amount);
            }
            let created_tx = self.created_tx.read(cross_chain_msg_id);
            self.created_tx.write(cross_chain_msg_id, CreatedCrossChainTx{
                tx_id: created_tx.tx_id,
                from_chain: created_tx.from_chain,
                to_chain: created_tx.to_chain,
                from:created_tx.from,
                to:created_tx.to,
                from_token: created_tx.from_token,
                to_token: created_tx.to_token,
                amount: created_tx.amount,
                tx_status: CrossChainTxStatus::SETTLED
            });

            return true;
        }
```

## Recommended Mitigation Steps
Adding following check to the beginning of function `receive_cross_chain_callback` in handler_erc20.cairo can address this issue:
```
assert(self.created_tx.read(cross_chain_msg_id).tx_status == CrossChainMsgStatus::PENDING, 'tx status error');
```
