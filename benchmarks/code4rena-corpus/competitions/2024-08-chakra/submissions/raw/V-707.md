# Vulnerability details

## Impact

If a validator uses a smart contract wallet instead of an externally owned account (EOA), the `SettlementSignatureVerifier` fails to validate its signature. 

## Proof of Concept

* The current implementation of `SettlementSignatureVerifier` uses the `ECDSA.recover` method to validate signatures from validators.

[Link to code](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/SettlementSignatureVerifier.sol#L134)

**Issue:**

* The `ECDSA.recover` function only supports signatures from EOAs.

* Smart contract wallets, which follow the `EIP-1271` standard, cannot be validated using `ECDSA.recover`. EIP-1271 defines a way for contracts to verify signatures, but it requires a different method for signature validation.

* The use of account abstraction and smart contract wallets (e.g., Argent, Gnosis Safe) is increasing, and these wallets use the EIP-1271 standard for signature verification.

* The current implementation of `SettlementSignatureVerifier` does not account for validators using smart contract wallets that implement EIP-1271, meaning those signatures will fail validation.

**Issue Leads To:**

* A validator using an EIP-1271-compliant smart contract wallet will not have their signature validated, resulting in their inability to participate in the cross-chain settlement process.

Even ZK Sync has Suggested the same in their docs [here](https://docs.zksync.io/build/developer-reference/best-practices#use-native-account-abstraction-over-ecrecover-for-validation).

## Recommended Mitigation Steps

To support both EOAs and smart contract wallets, OpenZeppelin provides the [SignatureChecker](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/5ed5a86d1d22f387ce69ab4e0ace405de8bc888d/contracts/utils/cryptography/SignatureChecker.sol) library, which can:

* Verify ECDSA signatures for EOAs.
* Verify ERC1271 signatures for smart contract wallets.
