# Vulnerability details

## Impact

The current functionality of `receive_cross_chain_msg` on both Starknet and Ethereum does not allow the transaction to be processed in a non-reverting way. So initially the received tx must have the status `Unknow` that will be changed to `Success` or `Failed` later. But the problem is that the `receive_cross_chain_msg()` can potentially revert meaning the transaction status will be not changed at all and the event that's monitored by off-chain services will be not emitted.

## Proof of Concept

`receive_cross_chain_msg()` may currently fail on multiple occasions:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L170-244

Therefore, the transaction may not change status at all and this will affect the process of making a callback on the source chain as the tx status is not changed and if the off-chain services monitor the events that are emitted by the functions, this event will be not present as well as the tx will simply revert:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L235-243
```
  emit CrossChainHandleResult(
            txid,
            status,
            contract_chain_name,
            from_chain,
            address(to_handler),
            from_handler,
            payload_type
        );

```

As per docs:

```
Events are emitted for all major cross-chain operations: message sending, message receiving, and callback processing.
```

## Tools Used

Manual review.

## Recommended Mitigation Steps

Return false instead of reverting a tx if some conditions are not satisfied in `receive_cross_chain_msg()` function.
