# Vulnerability details

## Impact
Please note that the same issue exists in both solidity code and cairo code. So I'll use solidity `SettlementSignatureVerifier.verifyECDSA` as an example.

Duplicated signatures can be used to call `SettlementSignatureVerifier.verifyECDSA`,which will cause the function return true even if there are not enough signatures(validate signatures should >= required_validators_num).

## Proof of Concept
Take [SettlementSignatureVerifier.verifyECDSA](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/SettlementSignatureVerifier.sol#L120-L141) as an exmaple.
As the following code shows, the function doesn't check if the `sig` is duplicated, and as long as the sig is valid, `m` will be increased by one.
```solidity
120     function verifyECDSA(
121         bytes32 msgHash,
122         bytes calldata signatures
123     ) internal view returns (bool) {
124         require(
125             signatures.length % 65 == 0,
126             "Signature length must be a multiple of 65"
127         );
128
129         uint256 len = signatures.length;
130         uint256 m = 0;
131         for (uint256 i = 0; i < len; i += 65) {
132             bytes memory sig = signatures[i:i + 65];
133             if (
134                 validators[msgHash.recover(sig)] && ++m >= required_validators
135             ) {
136                 return true;
137             }
138         }
139
140         return false;
141     }
```

Please consider in a case that the attacker owns one valid signature, he can re-use the signature with `required_validators` times, by doing so, the code flow will fall in [if condition](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/SettlementSignatureVerifier.sol#L133-L137), and the function will return true.

Please note that the same issue also exist in cairo version [settlement.check_chakra_signatures](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L173-L190)
