# Vulnerability details

## Impact

Manager can remove the access control of the owner and DoS the protocol.

## Proof of Concept

In solidity, the contracts uses AccessControl, giving the owner the `DEFAULT_ADMIN_ROLE` access and managers the `MANAGER_ROLE`.

The cairo contracts does it differently. The owner and manager both have the same 'role'.

In the cairo contracts, the owner is part of the `chakra_manager` mapping.

```
   #[constructor]
    fn constructor(ref self: ContractState, owner: ContractAddress, chain_name: felt252) {
        self.ownable.initializer(owner);
        self.chakra_managers.write(owner, 1);
        self.chain_name.write(chain_name);
    }
```

This maps a contract address to a u8.

```
        // storage manager
        chakra_managers: LegacyMap<ContractAddress, u8>,
```

In add and remove managers, the function checks that the caller has a '1' value in the `chakra_managers` mapping, and adds a new manager into the mapping.

```
  // Managers related operations
        fn add_manager(ref self: ContractState, new_manager: ContractAddress) - bool {
            let caller = get_caller_address();
>           assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            assert(caller != new_manager, 'Caller is a manager already');
>           self.chakra_managers.write(new_manager, 1);
            self
                .emit(
                    ManagerAdded {
                        operator: caller, new_manager: new_manager, added_at: get_block_timestamp()
                    }
                );
            return self.chakra_managers.read(new_manager) == 1;
        }

```

In `remove_manager`, the manager can remove everyone, including the owner and himself, and DoS the whole protocol.

```
        fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
>           assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
>           self.chakra_managers.write(old_manager, 0);
            self
                .emit(
                    ManagerRemoved {
                        operator: caller,
                        old_manager: old_manager,
                        removed_at: get_block_timestamp()
                    }
                );
            return self.chakra_managers.read(old_manager) == 0;
        }
```

The manager is not supposed to be fully trusted unlike the owner.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Have another mapping for the manager(s) like how it is done for the validators. The manager should not be able to remove the owner's control.
