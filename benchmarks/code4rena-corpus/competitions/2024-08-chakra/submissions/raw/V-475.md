# Vulnerability details

## Impact
The send_cross_chain_msg function in the ChakraSettlement contract can be called by any external actor without restrictions. This permissive access control allows malicious actors to flood the cross-chain messaging system with a large number of messages, potentially leading to a Denial of Service (DOS) condition. This could significantly degrade the performance of the cross-chain bridge, delay legitimate transactions, and increase operational costs for validators and relayers. This issue is present in both solidity and cairo code.

## Proof of Concept
An attacker can repeatedly call the send_cross_chain_msg function with different parameters:

```solidity
function send_cross_chain_msg(
    string memory to_chain,
    address from_address,
    uint256 to_handler,
    PayloadType payload_type,
    bytes calldata payload
) external {
    // Function body
}
```

Each call generates a new cross-chain message and emits a CrossChainMsg event:

```solidity
emit CrossChainMsg(
    txid,
    from_address,
    contract_chain_name,
    to_chain,
    from_handler,
    to_handler,
    payload_type,
    payload
);
```

While validators won't sign malicious messages, they still need to process each event, consuming resources.
This flood of messages could overwhelm the off-chain validator network, potentially causing delays in processing legitimate transactions.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Implement access control on the send_cross_chain_msg function to restrict who can initiate cross-chain messages by checkin if the msg.sender is a valid handler.
