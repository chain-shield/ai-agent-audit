# Vulnerability details

## Impact
Currently there is no way the function is protected from replay attacks as there is no nonce or even a deadline. Without a deadline (or expiration time) for signatures in cross-chain message verification or a nonce, an attacker could potentially reuse a valid signature indefinitely. This lack of temporal restriction can open up the system to replay attacks, where old messages are resent to manipulate the system, bypass intended logic, or disrupt operations.

It is always a good idea to use deadlines and nonce whenever signatures are involved

```javascript
function verifySignature(
        uint256 txid,
        uint256 from_handler,
        address to_handler,
        CrossChainMsgStatus status,
        uint8 sign_type,
        bytes calldata signatures
    ) internal view {
        bytes32 message_hash = keccak256(
            abi.encodePacked(txid, from_handler, to_handler, status)
        );

        require(
            signature_verifier.verify(message_hash, signatures, sign_type),
            "Invalid signature"
        );
    }
```

## Proof of Concept
A legitimate cross-chain message is sent and signed by the authorized signers. The message includes a valid payload, and the signature is correctly verified.

Since the system does not impose any deadline or nonce on the validity of the signature, an attacker intercepts and stores this signed message.

At a later time, when the context has changed (e.g., balances, states, or other critical variables have altered), the attacker resends the previously valid message, which still carries a valid signature.

The system, lacking a timestamp or deadline check, accepts this old message as legitimate, leading to unintended consequences, such as unauthorized transfers, state manipulations, or triggering of unintended logic.

## Recommended Mitigation Steps
Introduce protective measures for replay attacks, in the cross-chain message structure and the signature verification process. This parameter should specify a timestamp after which the signature becomes invalid. The deadline should be included in the hash that is signed by the validators to ensure that any replay of the message after the deadline is rejected. This should be done in all functions that implement signatures:

For example:

```javascript
// Include a deadline parameter in the message
function receive_cross_chain_msg(
    uint256 txid,
    string memory from_chain,
    address from_address,
    uint256 from_handler,
    address to_handler,
    PayloadType payload_type,
    bytes calldata payload,
    uint8 sign_type,
    bytes calldata signatures,
    uint256 deadline // Add deadline parameter
) external {
    require(block.timestamp <= deadline, "Signature expired"); // Check deadline

    bytes32 message_hash = keccak256(
        abi.encodePacked(
            txid,
            from_chain,
            from_address,
            from_handler,
            to_handler,
            keccak256(payload),
            deadline // Include deadline in the hash
        )
    );

    require(
        signature_verifier.verify(message_hash, signatures, sign_type),
        "Invalid signature"
    );

    // Remaining logic...
}
```
Implementing a deadline will ensure that signatures cannot be reused after a certain period, reducing the risk of replay attacks and enhancing the overall security of the cross-chain messaging system.
