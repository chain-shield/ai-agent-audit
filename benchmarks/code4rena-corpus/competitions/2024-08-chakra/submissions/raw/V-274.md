# Vulnerability details

## Impact
The `send_cross_chain_msg` function is responsible for initiating cross-chain messages. However, it lacks a critical security measure which is important as it ensures that the messages are indeed from the claimed sender, Without verifying the actual sender and signature, the function is vulnerable to unauthorized usage, where malicious actors could potentially send fraudulent messages or impersonate other users. This could lead to serious security breaches, including loss of funds, unauthorized transactions, or exploitation of the cross-chain communication process.

## Proof of Concept
The `send_cross_chain_msg` function does not include any mechanism to verify that the message sender (`from_address`) is the legitimate owner of the transaction.
An attacker could exploit this vulnerability by invoking the function with any arbitrary `from_address`, triggering cross-chain operations that are not authorized by the actual address owner.
As a result, the lack of signature verification leaves the cross-chain messaging process open to abuse, potentially leading to unauthorized cross-chain transactions and the exploitation of the protocol.

```javascript
 function send_cross_chain_msg(
        string memory to_chain,
        address from_address,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload
    ) external {
        nonce_manager[from_address] += 1;

        address from_handler = msg.sender;

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    contract_chain_name, // from chain // @ audit what about the chain id
                    to_chain,
                    from_address, // msg.sender address
                    from_handler, // settlement handler address
                    to_handler,
                    nonce_manager[from_address]
                )
            )
        );

        create_cross_txs[txid] = CreatedCrossChainTx(
            txid,
            contract_chain_name,
            to_chain,
            from_address,
            from_handler,
            to_handler,
            payload,
            CrossChainMsgStatus.Pending
        );

        emit CrossChainMsg(
            txid,
            from_address,
            contract_chain_name,
            to_chain,
            from_handler,
            to_handler,
            payload_type,
            payload
        );
    }
```
The function does not verify the authenticity of the `from_address`. An attacker could potentially exploit this by using an arbitrary `from_address` to trigger unauthorized cross-chain operations.

## Recommended Mitigation Steps
ensure that the sender is indeed authorized to initiate the cross-chain message. This can be done by including a signature parameter and verifying it against the from_address before proceeding with the transaction.

```javascript
function send_cross_chain_msg(
    string memory to_chain,
    address from_address,
    uint256 to_handler,
    PayloadType payload_type,
    bytes calldata payload,
    bytes calldata signature
) external {
    // Verify the signature
    bytes32 message_hash = keccak256(
        abi.encodePacked(
            contract_chain_name,
            to_chain,
            from_address,
            to_handler,
            nonce_manager[from_address]
        )
    );

    require(
        signature_verifier.verify(message_hash, signature),
        "Invalid signature"
    );

    // Rest of the function logic
}

```
