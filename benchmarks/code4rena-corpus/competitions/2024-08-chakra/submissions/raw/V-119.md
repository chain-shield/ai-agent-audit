# Vulnerability details

## Impact
The `SettlementSignatureVerifier` contract is designed to verify signatures for cross-chain settlement. However, due to a flaw in the signature verification logic, valid signatures may be incorrectly rejected. This can lead to a denial of service for users attempting to settle cross-chain transactions, as their valid signatures will not be accepted by the contract.

In the condition `validators[msgHash.recover(sig)] && ++m >= required_validators`. Even if the signature is valid and the recovered address is a validator, the function will return false if `m` is not greater than or equal to `required_validators`.

## Proof of Concept
In the `verifyECDSA` function within the SettlementSignatureVerifier contract. [SettlementSignatureVerifier.sol#L133-L137](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/SettlementSignatureVerifier.sol#L133-L137)
```solidity
if (
    validators[msgHash.recover(sig)] && ++m >= required_validators
) {
    return true;
}
```
The problem arises from the `&&` operator, which _short-circuits_ the evaluation if the first condition is false. As a result, even if a signature is valid and the recovered address is a validator, the function will return `false` if `m` is not greater than or equal to `required_validators`.

**Let's consider a scenario where `required_validators` is set to 1 and a valid signature is provided**

1. The `verifyECDSA` function is called with a `msgHash` and a `signatures` byte array containing a single valid signature.
2. The function iterates through the signatures and recovers the address from the first signature.
3. The recovered address is checked against the `validators` mapping, and it is found to be a valid validator.
4. However, since `m` starts at 0, the condition `++m >= required_validators` evaluates to `false`.
5. The function returns `false`, indicating that the signature is invalid, even though it is actually valid.

As a result, the settlement process fails, and the user's transaction is not accepted.

## Recommended Mitigation Steps
The signature verification logic in the `verifyECDSA` function should be updated. The condition should be split into two separate checks:
```diff
function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 len = signatures.length;
-   uint256 m = 0;
+   uint256 validSignatures = 0;
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
-       if (
-           validators[msgHash.recover(sig)] && ++m >= required_validators
-       ) {
-           return true;
+       if (validators[msgHash.recover(sig)]) {
+           validSignatures++;
        }
    }

-   return false;
+   return validSignatures >= required_validators;
}
```
By separating the checks, the function will correctly increment `m` for each valid signature and return true when the number of valid signatures from validators matches or exceeds `required_validators`.
