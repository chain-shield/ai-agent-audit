# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: Handler.SettlementSignatureVerifier contract has DoS With Block Gas Limit in verifyECDSA Function
•	Severity: High
•	Impact: The verifyECDSA function in the SettlementSignatureVerifier contract is vulnerable to a Denial of Service (DoS) attack due to the potential for excessive gas consumption.
•	Status: Unresolved
•	File: SettlementSignatureVerifier.sol
•	Lines Affected: 108-141

The verifyECDSA function in the SettlementSignatureVerifier contract is vulnerable to a Denial of Service (DoS) attack due to the potential for excessive gas consumption. The function iterates over the signatures array with a step of 65 bytes, and the absence of a cap on the length of this array allows an attacker to pass in a very large array. This could cause the function to exceed the block gas limit, resulting in a denial of service where legitimate transactions fail.

Vulnerable Code
```sol
function verify(
        bytes32 msgHash,
        bytes calldata signatures,
        uint8 sign_type
    ) external view returns (bool) {
        if (sign_type == 0) {
            return verifyECDSA(msgHash, signatures);
        } else {
            return false;
        }
    }

function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```

## Recommended Mitigation Steps
To mitigate this issue, impose a reasonable upper limit on the length of the signatures array. This can be done by adding a requirement that limits the maximum number of signatures that can be processed in a single transaction. For example:
```sol
function verifyECDSA(
        bytes32 msgHash,
        bytes calldata signatures
    ) internal view returns (bool) {
        require(
            signatures.length % 65 == 0,
            "Signature length must be a multiple of 65"
        );

        // Cap the maximum number of signatures processed in a single call
        uint256 maxSignatures = 10;
        require(
            signatures.length <= maxSignatures * 65,
            "Too many signatures, potential DoS risk"
        );

        uint256 len = signatures.length;
        uint256 m = 0;
        for (uint256 i = 0; i < len; i += 65) {
            bytes memory sig = signatures[i:i + 65];
            if (
                validators[msgHash.recover(sig)] && ++m >= required_validators
            ) {
                return true;
            }
        }

        return false;
    }
```
By limiting the number of signatures that can be processed in a single transaction, the risk of DoS via block gas limit can be significantly reduced. This mitigation ensures that the contract remains functional and secure even in the face of attempts to overwhelm it with large signature arrays.
