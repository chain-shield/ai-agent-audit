# Vulnerability details

## Impact
The cross chain tx details saved in `handle_erc20::cross_chain_erc20_settlement()` is incorrect as the function uses the address of the contract as the `from` address instead of the `caller's address`. 
Depending on the use case, if this information is used, it could result in potential issues.

## Proof of Concept
When initiating a cross-chain ERC20 settlement, the `from` address refers to the address of the `caller`.

In [`ChakraSettlementHandler::cross_chain_erc20_settlement()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L158), the caller (`msg.sender`) is used as the `from` address when saving the cross chain tx details:
```solidity
            // Save the cross chain tx
            create_cross_txs[txid] = CreatedCrossChainTx(
                txid,
                chain,
                to_chain,
>>              msg.sender, //@audit-info Caller address used.
                ---SNIP---
            );
```
[Here](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/BaseSettlementHandler.sol#L57) is `CreatedCrossChainTx` signature.

The same value is used when [creating a erc20 transfer payload](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L183) as `from`:
```solidity
            // Create a erc20 transfer payload
            ERC20TransferPayload memory payload = ERC20TransferPayload(
                ERC20Method.Transfer,
>>              AddressCast.to_uint256(msg.sender),
                ---SNIP---
            );
```
The same is used when emitting [`CrossChainLocked`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L214) event again as the `from` address.


However, in [`handle_erc20::cross_chain_erc20_settlement()`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L188), the function uses the contract address (`get_contract_address()`) as the `from` address when saving the tx details:
```solidity
        let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
                    from_chain: from_chain,
                    to_chain: to_chain,
>>                  from: get_contract_address(), //@audit-info Contract address used (issue)
                    ---SNIP---
                };
```
Yet when [creating a erc20 transfer payload](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L201), caller (`get_caller_address()`) is used as `from`:
```solidity
        let transfer = ERC20Transfer{
                method_id: 1,
>>              from: contract_address_to_u256(get_caller_address()),
                ---SNIP---
            };
```
And when emitting the [`CrossChainLocked`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/cairo/handler/src/handler_erc20.cairo#L222) event, the caller address is still used as `from`.

As seen above, incorrect information (from address) is saved for the tx.

## Recommended Mitigation Steps
Correct this as follows:
```diff
        let tx: CreatedCrossChainTx = CreatedCrossChainTx{
                    tx_id: tx_id,
                    from_chain: from_chain,
                    to_chain: to_chain,
-                   from: get_contract_address(),
+                   from: get_caller_address(), //@audit Use the caller address used.
                    ---SNIP---
                };
```
