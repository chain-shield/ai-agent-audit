# Vulnerability details


## Summary
The Chakra protocol lacks payload size limits for cross-chain messages on both L1 and L2. Large token transfers may result in oversized payloads that fail to transmit, leading to tokens being locked in the handler contract.

## Impact
- User tokens can be permanently locked in the handler contract
- Potential for system abuse through intentionally oversized payloads
- Increased gas costs for unnecessarily large transactions
- Possible network congestion due to oversized messages

## Proof of Concept
In the `cross_chain_erc20_settlement` function:

```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ... (token locking logic)
    
    bytes memory cross_chain_msg_bytes = MessageV1Codec.encode(cross_chain_msg);
    
    // No size check before sending
    settlement.send_cross_chain_msg(
        to_chain,
        msg.sender,
        to_handler,
        PayloadType.ERC20,
        cross_chain_msg_bytes
    );
}
```

A malicious user or a user unaware of system limitations could initiate a transfer with an extremely large `amount`, resulting in an oversized payload.

## Recommendation
Implement payload size limits on both L1 and L2:

```solidity
uint256 constant MAX_PAYLOAD_SIZE = 1024; // Example size, adjust as needed

function cross_chain_erc20_settlement(...) external {
    // ... (existing logic)
    
    bytes memory cross_chain_msg_bytes = MessageV1Codec.encode(cross_chain_msg);
    require(payload.length <= MAX_PAYLOAD_SIZE, "Payload too large");
    
    settlement.send_cross_chain_msg(...);
}
```
