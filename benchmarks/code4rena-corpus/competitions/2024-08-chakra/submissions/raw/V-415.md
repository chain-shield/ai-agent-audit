# Vulnerability details


## Summary

Throughout the Chakra codebase, implementation contracts using the UUPS (Universal Upgradeable Proxy Standard) proxy pattern from OpenZeppelin lack the crucial `_disableInitializers()` function call in their constructors. This omission can lead to potential vulnerabilities where the initializer functions of implementation contracts could be called directly, potentially leading to unauthorized initialization or re-initialization of the contract logic.

## Impact

The absence of `_disableInitializers()` in the implementation contracts' constructors can have several severe consequences:

1. Unauthorized Initialization: An attacker could potentially call the initializer function directly on the implementation contract, setting up a malicious state.

2. Logic Corruption: If an implementation contract is initialized directly, it could lead to a corrupt state that doesn't align with the proxy's storage, causing unexpected behavior.

3. Upgrade Vulnerabilities: In some scenarios, this could be exploited during contract upgrades, potentially allowing an attacker to manipulate the contract's state or behavior.

4. Inconsistent State: It may lead to inconsistencies between the proxy and implementation contract states, causing the system to behave unpredictably.

## Recommended Mitigation Steps

To mitigate this vulnerability, add the `_disableInitializers()` function call in the constructor of each implementation contract that uses the UUPS proxy pattern. This ensures that the initializers cannot be called on the implementation contract directly.

Example fix for `SettlementSignatureVerifier.sol`:

```diff
contract SettlementSignatureVerifier is
    OwnableUpgradeable,
    UUPSUpgradeable,
    AccessControlUpgradeable,
    ISettlementSignatureVerifier
{
+   /// @custom:oz-upgrades-unsafe-allow constructor
+   constructor() {
+       _disableInitializers();
+   }

    // Rest of the contract remains the same
    // ...
}
```

Apply similar changes to all UUPS proxy implementation contracts in the codebase.
