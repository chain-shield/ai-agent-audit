# Vulnerability details

## Summary

A vulnerability has been identified in the `verifyECDSA` function of the `SignatureVerifier` contract used by both `ChakraSettlementHandler` and `ChakraSettlement`. The flaw allows a single validator to sign multiple times and successfully bypass the intended requirement for multi-validator approval, leading to potential acceptance of malicious transactions in the `receive_cross_chain_msg` and `receive_cross_chain_callback` functions.

## Impact

This vulnerability significantly undermines the security of cross-chain settlement operations, allowing an attacker to bypass the multi-signature requirement with a single validator. This could lead to the acceptance of fraudulent or malicious transactions across the settlement network, exposing users and the protocol to loss of funds and operational integrity issues. Specifically, the vulnerability allows a malicious actor to:

1. Manipulate the cross-chain settlement flow by providing the required number of signatures using just one validator.
2. Approve transactions without proper consensus, violating the trust model that requires signatures from multiple validators.

This could result in unauthorized or malicious settlement transactions being accepted by the contract, leading to financial loss for users and damage to the integrity of the settlement system.

## Proof of Concept

The vulnerability is rooted in the `verifyECDSA` function of the `SignatureVerifier` contract. Below is the relevant portion of the code that verifies the signatures for a transaction:

```solidity
for (uint256 i = 0; i < len; i += 65) {
    bytes memory sig = signatures[i:i + 65];
    if (validators[msgHash.recover(sig)] && ++m >= required_validators) {
        return true;
    }
}
```

## Recommendation
To prevent this vulnerability, the verifyECDSA function should be modified to ensure that signatures come from unique validators. One possible solution is to track the validators that have signed the message and ensure no duplicate signatures are counted:

```solidity
mapping(address => bool) signedValidators;

for (uint256 i = 0; i < len; i += 65) {
    bytes memory sig = signatures[i:i + 65];
    address recovered = msgHash.recover(sig);

    require(!signedValidators[recovered], "Duplicate validator signature");
    require(validators[recovered], "Invalid validator");

    signedValidators[recovered] = true;

    if (++m >= required_validators) {
        return true;
    }
}

```
