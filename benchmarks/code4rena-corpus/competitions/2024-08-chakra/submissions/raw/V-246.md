# Vulnerability details

## Impact
Loss of Fund Due to Minting of Token of Burning in the ChakraSettlementHandler contract during the MintBurn settlement mode
## Proof of Concept
```solidity

        uint256 /**txid */,
        string memory from_chain,
        uint256 /**from_address */,
        uint256 from_handler,
        PayloadType payload_type,
        bytes calldata payload,

        require(isValidPayloadType(payload_type), "Invalid payload type");

        if (payload_type == PayloadType.ERC20) {
            // Cross chain transfer
            {
                // Decode transfer payload
                ERC20TransferPayload memory transfer_payload = codec
                    .deocde_transfer(msg_payload);

                } else if (mode == SettlementMode.LockMint) {
                    _erc20_mint(

                } else if (mode == SettlementMode.BurnUnlock) {
                    _erc20_unlock(

```
The code above shows how receive_cross_chain_msg(...) is implemented in the ChakraSettlementHandler contract, it can be  noted that the conditional statements handling the settlement mode erc20 call have a pattern i.e BurnUnlock calls unlock function, LockMint calls mint function, LockUnlock calls Unlock so it would be expected that the final mode of MintBurn should call the burn function however Mint was called instead as noted in the pointer which would cause loss of fund to contract due to minting instead of burning
