# Vulnerability details

## Impact
Users attempting to initiate cross-chain settlements with insufficient token balance will experience transaction failures and loss of gas fees. `cross_chain_erc20_settlement` function allows users to initiate settlements even when they do not have enough tokens to cover the transfer amount.

## Proof of Concept
This issue lies in the `cross_chain_erc20_settlement` function in the `ChakraSettlementHandler` contract. The function does not include a check to ensure that the sender has sufficient token balance before proceeding with the token transfer.

In `ChakraSettlementHandler.sol`, the `cross_chain_erc20_settlement` function calls the `_erc20_lock` function without verifying the sender's balance: [ChakraSettlementHandler.sol#L123-L124](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L123-L124)
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ...
    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    }
    // ...
}
```
The `_erc20_lock` function internally calls the `_safe_transfer_from` function, which checks the sender's balance against the transfer amount: [ChakraSettlementHandler.sol#L257-L269](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L257-L269)
```solidity
function _safe_transfer_from(
    address from,
    address to,
    uint256 amount
) internal {
    require(
        IERC20(token).balanceOf(from) >= amount,
        "Insufficient balance"
    );
    // ...
}
```
However, if the sender's balance is insufficient, the `require` statement in `_safe_transfer_from` will fail, causing the entire transaction to revert.

**Here's a scenario illustrating the issue**

1. User A has a token balance of 50 tokens in their account.
2. User A calls the `cross_chain_erc20_settlement` function with the following parameters:

   * `to_chain`: "chain2"
   * `to_handle`r: 1
   * `to_token`: 1
   * `to`: 1
   * `amount`: 100

3. The `cross_chain_erc20_settlement` function proceeds to call `_erc20_lock` with the transfer amount of 100 tokens.
4. Inside `_erc20_lock`, the `_safe_transfer_from` function is called, which checks if User A's balance is greater than or equal to 100 tokens.
5. Since User A's balance is only 50 tokens, the `require` statement in `_safe_transfer_from` fails, causing the transaction to revert.
6. User A's transaction fails, and they lose the gas fees associated with the transaction.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Add a balance check in the `cross_chain_erc20_settlement` function before proceeding with the token transfer. 
```diff
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ...
+   require(IERC20(token).balanceOf(msg.sender) >= amount, "Insufficient balance");
    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    }
    // ...
}
```
