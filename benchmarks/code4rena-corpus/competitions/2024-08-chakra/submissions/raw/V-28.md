# Vulnerability details

## Impact
In the `ChakraSettlement::receive_cross_chain_msg()` function, the `payload_type` parameter is not included in the `message_hash`, allowing it to be manipulated without being verified by validators. Malicious actors can front-run the transaction with an invalid `payload_type`, causing the token receive transaction to fail and leaving users' tokens locked.

## Proof of Concept

The `payload_type` parameter is not included in the `message_hash` used for verification:

```solidity
File: ChakraSettlement.sol
170:     function receive_cross_chain_msg(
171:         uint256 txid,
172:         string memory from_chain,
173:         uint256 from_address,
174:         uint256 from_handler,
175:         address to_handler,
176:>>       PayloadType payload_type,
177:         bytes calldata payload,
178:         uint8 sign_type, // validators signature type /  multisig or bls sr25519
179:         bytes calldata signatures // signature array
180:     ) external {
181:         {
182:             // verify signature
183:>>           bytes32 message_hash = keccak256(
184:                 abi.encodePacked(
185:                     txid,
186:                     from_chain,
187:                     from_address,
188:                     from_handler,
189:                     to_handler,
190:                     keccak256(payload)
191:                 )
192:             );
```

A malicious actor could exploit this by monitoring transactions that execute `receive_cross_chain_msg()` and front-running them with a modified `payload_type` value. Since the `payload_type` is not verified, the function proceeds with an invalid input. As the `payload_type` is invalid, [the handler will not unlock or mint tokens for the recipient](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L318).

As a result, the [`receive_cross_txs[txid].status` is set to `CrossChainMsgStatus.Failed`](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L232), the victim cross-chain receive transation will be reverted, effectively locking the user's tokens.

## Recommended Mitigation Steps
The `payload_type` parameter should be included in the `message_hash` used for validation.
