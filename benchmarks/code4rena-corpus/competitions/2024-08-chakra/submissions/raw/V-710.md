# Vulnerability details

## Abstract

The Chakra protocol is responsible of sending tokens between Ethereum and Starknet blockchains, when everything goes well the sent tokens should be credited to the receiving address on the receiving chain. But if the transaction fails it is expected to return the tokens to the initiator.

## Impact
- Loss of funds for user when transaction fails due to any reason, without a way to recover tokens from the contract.

- Tokens are burnt when user send the message
https://github.com/code-423n4/2024-08-chakra/blob/f61c899c22492bdf5bdcb07cdb62ea9b4cd38825/solidity/handler/contracts/ChakraSettlementHandler.sol#L130 
making it not possible to recover the tokens in case of failed message

## Proof of Concept

- Not refunding tokens and just marking the transaction as failed

- Not checking the `cross_chain_msg_status`

Manual review

## Recommended Mitigation Steps

- Provide a way for the user to withdraw the deposited tokens if the transaction status is `failed`.

- Only process the "burning" of tokens in the callback if the status was successful.
