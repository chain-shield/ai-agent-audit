# Vulnerability details

## Impact
The issue lies in both the solidity EVM side and Starknet. Ideally, the `cross_chain_erc20_settelement` function validates necessary parameters and requirements and calls the settlement contract function `send_cross_chain_msg` it emits the necessary details and validator pickup does the necessary transformation of data, signs them, and calls the target chain and handler with data it got. 

The spam message won’t cause any damage to the protocol directly as the destination chain validates if the message is emitted from a valid handler and valid chain i.e. source chain contract in case of EVM `ChakraSettlementHandler.sol` and in case of Starknet `handler_erc20.cairo` where the call should originate. These spam calls are made from another contract `ChakraSettlement.sol` function `send_cross_chain_msg` bypassing the handler contracts. 

However, with the missing access control on `send_cross_chain_message` on both sides of chains,  anyone can call the function with minimal parameters and it emits the event and validator pickups and calls to the target chain function. This function can be abused with frequent calls with minimal attack cost as code would be deployed in L2. 

This can potentially be an out-of-service situation, as at first the signatures are validated in the `receive_cross_chain_message` functions across the starknet and EVM side. A spam call with an enormous large payload and multiple calls can drain the validator gas as the validator needs to submit alongside signatures and other parameters.

## Proof of Concept
For Starknet side.

Call the function `send_cross_chain_msg` of `settlement.cairo` contracts multiple times as there are no restrictions on who can call.

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/settlement.cairo#L284-L314
```
        fn send_cross_chain_msg(
            ref self: ContractState, to_chain: felt252, to_handler: u256, payload_type :u8,payload: Array<u8>,
        ) -> felt252 {
            let from_handler = get_caller_address();
            let from_chain = self.chain_name.read();
            let cross_chain_settlement_id = LegacyHash::hash(get_tx_info().unbox().transaction_hash, self.tx_count.read());
            self.created_tx.write(cross_chain_settlement_id, CreatedTx{
                tx_id:cross_chain_settlement_id,
                tx_status: CrossChainMsgStatus::PENDING,
                from_chain: from_chain,
                to_chain: to_chain,
                from_handler: from_handler,
                to_handler: to_handler
            });
            
            self
                .emit(
                    CrossChainMsg {
                        cross_chain_settlement_id: cross_chain_settlement_id,
                        from_address: get_tx_info().unbox().account_contract_address,
                        from_chain: from_chain,
                        to_chain: to_chain,
                        from_handler: from_handler,
                        to_handler: to_handler,
                        payload_type: payload_type,
                        payload: payload
                    }
                );
            self.tx_count.write(self.tx_count.read()+1);
            return cross_chain_settlement_id;
        }
```
For EVM Side

Call the function `send_cross_chain_msg` of `ChakraSettlement.sol` multiple times as there are also no restrictions and modifiers. 

https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/ChakraSettlement.sol#L111-L156
```
function send_cross_chain_msg(
        string memory to_chain,
        address from_address,
        uint256 to_handler,
        PayloadType payload_type,
        bytes calldata payload
    ) external {
        nonce_manager[from_address] += 1;

        address from_handler = msg.sender;

        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    contract_chain_name, // from chain
                    to_chain,
                    from_address, // msg.sender address
                    from_handler, // settlement handler address
                    to_handler,
                    nonce_manager[from_address]
                )
            )
        );

        create_cross_txs[txid] = CreatedCrossChainTx(
            txid,
            contract_chain_name,
            to_chain,
            from_address,
            from_handler,
            to_handler,
            payload,
            CrossChainMsgStatus.Pending
        );

        emit CrossChainMsg(
            txid,
            from_address,
            contract_chain_name,
            to_chain,
            from_handler,
            to_handler,
            payload_type,
            payload
        );
    }
```

## Recommended Mitigation Steps
Recommendation is relevant to both sides EVM and Starknet. Like the only settlement contract can call the handler contract functions like `receive_cross_chain_msg` and callback ones. Make a whitelist of valid handlers on settlement contract and restrict the call `send_cross_chain_msg` to be made from the already deployed valid handler. As there would be multiple handlers of different modes the whitelist option would be better.
