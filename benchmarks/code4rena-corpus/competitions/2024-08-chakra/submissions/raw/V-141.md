# Vulnerability details

The ChakraSettlementHandler contract, which is responsible for handling cross-chain ERC20 token settlements, contains a logic error in the `cross_chain_erc20_settlement` function. This issue leads to incorrect handling of the `MintBurn` settlement mode, resulting in inconsistent token balances and unexpected behavior in the cross-chain settlement process.

The `ChakraSettlementHandler` contract inherits from the `BaseSettlementHandler` contract and implements the `ISettlementHandler` interface. It provides functionality for cross-chain ERC20 token settlements using different settlement modes defined in the `SettlementMode` enum.

The `cross_chain_erc20_settlement` function is responsible for initiating a cross-chain ERC20 settlement based on the specified settlement mode. However, there is an issue in the logic for handling the `MintBurn` settlement mode.

In the `BaseSettlementHandler` contract, the `SettlementMode` enum defines four possible settlement modes: [BaseSettlementHandler.sol#L34-L39](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/BaseSettlementHandler.sol#L34-L39)
```solidity
enum SettlementMode {
    MintBurn,
    LockMint,
    BurnUnlock,
    LockUnlock
}
```
The `cross_chain_erc20_settlement` function in the `ChakraSettlementHandler` contract checks the current settlement mode and performs the corresponding actions based on the mode: [ChakraSettlementHandler.sol#L123-L130](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L123-L131)
```solidity
if (mode == SettlementMode.MintBurn) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockUnlock) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockMint) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.BurnUnlock) {
    _erc20_burn(msg.sender, amount);
}
```
The issue lies in the handling of the `MintBurn` settlement mode. According to the expected behavior, when the settlement mode is `MintBurn`, both the `_erc20_lock` and `_erc20_bur`n functions should be called to lock the tokens and burn them. However, in the current implementation, only the `_erc20_lock` function is called, and the `_erc20_burn` function is not invoked.

This incorrect handling of the `MintBurn` settlement mode can lead to inconsistent token balances and unexpected behavior in the cross-chain settlement process. The tokens are locked but not burned, resulting in a mismatch between the locked and minted tokens on the destination chain.

## Impact
* The tokens are locked but not burned, leading to a mismatch between the locked tokens on the source chain and the minted tokens on the destination chain.
* The cross-chain settlement process may not function as intended, causing confusion and issues for users and other systems relying on the correct settlement of tokens.

## Proof of Concept
Consider the following scenario:

* The `ChakraSettlementHandler` contract is deployed with the `MintBurn` settlement mode.
* A user initiates a cross-chain ERC20 settlement by calling the `cross_chain_erc20_settlement` function with valid parameters.
* The function checks the settlement mode and enters the `MintBurn` case.
* The `_erc20_lock` function is called, locking the specified amount of tokens.
* The `_erc20_burn` function is not called, leaving the locked tokens unburned.
* The cross-chain settlement process continues, but the locked tokens are not properly burned, leading to inconsistent token balances and unexpected behavior.

## Recommended Mitigation Steps
There are 2 options to address this issue.

1. The `cross_chain_erc20_settlement` function should be updated to correctly handle the `MintBurn` settlement mode by calling both the `_erc20_lock` and `_erc20_burn` functions
```diff
if (mode == SettlementMode.MintBurn) {
    _erc20_lock(msg.sender, address(this), amount);
+   _erc20_burn(msg.sender, amount);
} else if (mode == SettlementMode.LockUnlock) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.LockMint) {
    _erc20_lock(msg.sender, address(this), amount);
} else if (mode == SettlementMode.BurnUnlock) {
    _erc20_burn(msg.sender, amount);
}
```
By adding the `_erc20_burn` function call in the` MintBurn` case, the locked tokens will be burned, ensuring consistent token balances and expected behavior in the cross-chain settlement process.
