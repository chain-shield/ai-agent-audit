# Vulnerability details

## Impact
The chakra_operators privileged role can destroy any user's funds.

In the `ckrBTC` contract, the `chakra_operators` privileged role has the authority to burn any user's funds. The `burn_from` function allows operators to burn a specified `u256` amount of tokens from a user’s address without any additional checks or user approval. Although the function ensures that the caller is an authorized operator, it does not require user consent or authorization for this operation. As a result, any account with operator privileges can burn the funds of any user.

This vulnerability can have a significant impact, as an attacker with operator privileges could directly destroy user funds, leading to unauthorized losses of assets and severely compromising the security and trustworthiness of the contract.

## Proof of Concept

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/ckr_btc.cairo#L209

The following is a snippet of the `burn_from` function, where it allows operators to burn any user's funds:

```

fn burn_from(ref self: ContractState, to: ContractAddress, amount: u256) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_operators.read(caller) == 1, Errors::NOT_OPERATOR);
    let old_balance = self.erc20.balance_of(to);
    assert(old_balance >= amount, Errors::BALANCE_NOT_ENOUGH);
    self.erc20.burn(to, amount);
    let new_balance = self.erc20.balance_of(to);
    return new_balance == old_balance - amount;
}
```

This code allows operators to directly burn tokens from a user’s address without requiring any authorization from the user, which could result in irreversible loss of user funds.

## Recommended Mitigation Steps

To prevent operators from arbitrarily burning user tokens, it is recommended to introduce a user authorization mechanism in the `burn_from` function, ensuring that operators can only perform the burn operation with the user's consent. For example, an `allowance` and `approve` mechanism, similar to what is used in the ERC20 standard, can be implemented to ensure that operators cannot burn user funds without explicit approval:

```

fn burn_from(ref self: ContractState, to: ContractAddress, amount: u256) -> bool {
    let caller = get_caller_address();
    assert(self.chakra_operators.read(caller) == 1, Errors::NOT_OPERATOR);
    let allowance = self.erc20.allowance(to, caller);
    assert(allowance >= amount, Errors::NOT_APPROVED);  // Ensure user has approved the burn amount
    let old_balance = self.erc20.balance_of(to);
    assert(old_balance >= amount, Errors::BALANCE_NOT_ENOUGH);
    self.erc20.burn(to, amount);
    let new_balance = self.erc20.balance_of(to);
    return new_balance == old_balance - amount;
}
```

This ensures that operators can only burn tokens after the user has explicitly approved it, preventing unauthorized loss of funds.
