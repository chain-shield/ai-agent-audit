# Vulnerability details

## Impact
The functions [ChakraSettlement::receive_cross_chain_msg](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L195) and [ChakraSettlement::receive_cross_chain_callback](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/settlement/contracts/ChakraSettlement.sol#L298) rely on `SettlementSignatureVerifier::verify` to validate the signatures. For the `signatures` to be considered valid, two conditions must be met:
1. The signatures must be from authorized validators.
2. The minimum required number of validators must sign the message.

The issue lies in the fact that `SettlementSignatureVerifier::verify` does not correctly enforce the second requirement:
```solidity
function verify(
    bytes32 msgHash,
    bytes calldata signatures,
    uint8 sign_type
) external view returns (bool) {
    if (sign_type == 0) {
        return verifyECDSA(msgHash, signatures);
    } else {
        return false;
    }
}


function verifyECDSA(
    bytes32 msgHash,
    bytes calldata signatures
) internal view returns (bool) {
    require(
        signatures.length % 65 == 0,
        "Signature length must be a multiple of 65"
    );

    uint256 len = signatures.length;
    uint256 m = 0;
    for (uint256 i = 0; i < len; i += 65) {
        bytes memory sig = signatures[i:i + 65];
        if (
>>>            validators[msgHash.recover(sig)] && ++m >= required_validators
        ) {
             return true;
        }
    }

    return false;
}
```
As shown above, the following logic fails to adequately verify the second requirement:
```solidity
validators[msgHash.recover(sig)] && ++m >= required_validators
```
A **single** validator can create one signature and duplicate it multiple times to meet the `required_validators` threshold, effectively bypassing the minimum validator requirement. As a result, a single validator can temper with cross-chain messages without reaching a consensus on the Chakra network

## Recommended Mitigation Steps
Modify the loop within `verifyECDSA` on the solidity code and `check_chakra_signatures` on cairo code to ensure that each signature is distinct and that there are no duplicate signatures
