# Vulnerability details

## Impact
If failed cross chain message is sent to `receive_cross_chain_callback` function on Starknet, the status of message will always be successful after callback. `cross_chain_msg_status` in `CrossChainResult` will be emitted wrongly.

## Proof of Concept
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/handler/src/handler_erc20.cairo#L138-L165
From above code, the `cross_chain_msg_status` is included in the input of `receive_cross_chain_callback` function. However this function doesn't consider the case of failed cross chain message. It assumes all cross chain message is successful which isn't right.
https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/cairo/settlement/src/settlement.cairo#L417-L423
From above code, if the call to handler is successful, the status of cross chain message will be successful which didn't consider the case of failed cross chain message.
`receive_cross_chain_callback` function doesn't handle the case of failed cross chain message.

## Recommended Mitigation Steps
1. handler_erc20.cairo
Add struct:
```
    pub mod CrossChainMsgStatus {
        pub const UNKNOW: u8 = 0;
        pub const PENDING: u8 = 1;
        pub const SUCCESS: u8 = 2;
        pub const FAILED: u8 = 3;
    }
```
Then(`receive_cross_chain_callback`):
