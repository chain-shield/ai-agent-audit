# Vulnerability details

## Description
In `settlement.cairo`,  the amount of required validators can be set by calling `set_required_validators_num()`:
```rust
        fn set_required_validators_num(ref self: ContractState, new_num: u32) -> u32 {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
            self.required_validators_num.write(new_num);
            return self.required_validators_num.read();
        }
```

The problem is that changing the required validators will always lead to one or more xchain messages not being able to be executed.
## Proof of Concept
Let:
- `required validators = 5`

Consider the following scenario:
- Alice makes a xchain transfer, signature is signed off by 5 validators
- While the xchain call is in flight, honest admin changes the to required amount to 6 validators
- Alice's message will not be able to be executed, leading to funds lost.
## Recommended Mitigation Steps
Handle in-flight changes differently
