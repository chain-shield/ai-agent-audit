# Vulnerability details

Any manager role calling functions `add_manager` and `remove_manager` through  `settlement.cairo` and `ckr_btc.cairo` can assign more managers even though those functioins should only be available to a contract owner.

According to the documentation, only the contract owner can add or remove managers from the list. The NatSpec comment describes the access control for the functions in Solidity settlement contract as follows:
```solidity
    /**
     * @dev Grant a manager role for address
     * @notice Only owner can do this
     * @param _manager The manager address
     */
    function add_manager(address _manager) external onlyOwner {
    // ... other code ...
    /**
     * @dev Revoke a manager role for address
     * @notice Only owner can do this
     * @param _manager The manager address
     */
    function remove_manager(address _manager) external onlyOwner {
```
[BaseSettlement.sol#L144-L149](https://github.com/code-423n4/2024-08-chakra/blob/f61c899c22492bdf5bdcb07cdb62ea9b4cd38825/solidity/settlement/contracts/BaseSettlement.sol#L144-L149), [BaseSettlement.sol#L154-L162](https://github.com/code-423n4/2024-08-chakra/blob/f61c899c22492bdf5bdcb07cdb62ea9b4cd38825/solidity/settlement/contracts/BaseSettlement.sol#L154-L162)
The access control is ensured by using `onlyOwner` modifier.

Also, as mentioned in the docs, manager is not a trusted role (only the operator is). 
However, the Cairo settlement contract, instead of checking for caller to be the owner only checks for the manager role. 

## Impact

The lack of proper access control, allows anybody with a manager role to call `add_manager` and `remove_manager` functions:
```cairo
        fn add_manager(ref self: ContractState, new_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
        // ... other code ...
        fn remove_manager(ref self: ContractState, old_manager: ContractAddress) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
```
As a consequence, any malicious manager can change the amount of change the number of validators required to sign the transaction, add new, potentially malicious, validators.

Manual review

## Recommended Mitigation Steps

Replace `assert(self.chakra_managers.read(caller) == 1, Errors::NOT_MANAGER);` with `self.ownable.assert_only_owner();` in `add_manager` and `remove_manager` functions of Cairo contracts.
