# Vulnerability details

## Impact
Erroneous operation incorrectly increases the balance of the contract instead of burning the `msg.sender`(caller's) token amount.

## Proof of Concept

Before understanding the issue let us familiarize with some of the variables/values used here

The below code is responsible for handling cross chain ERC20 operation and is dependent on the `SettlementMode` (set at time of initialization 
using `_Settlement_handler_init(..)` )

If the mode = SettlementMode.MintBurn, it means that on the source chain the mentioned token amounts need to be burned from the caller(`msg.sender`) and on the destination chain the token amount should be Minted to the `to` address.  

It should be done via the `_erc20_burn(msg.sender, amount)` defined as follows: 

```solidity
    function _erc20_burn(address account, uint256 amount) internal {
        require(
            IERC20(token).balanceOf(account) >= amount,
            "Insufficient balance"
        );

        IERC20Burn(token).burn_from(account, amount);
    }
```
But the code incorrectly calls `_erc20_lock(msg.sender, address(this),amount)`
```solidity
function _erc20_lock(address from, address to, uint256 amount) internal {
    _safe_transfer_from(from, to, amount);
}
// 
   function _safe_transfer_from(
        address from,
        address to,
        uint256 amount
    ) internal {
        require(
            IERC20(token).balanceOf(from) >= amount,
            "Insufficient balance"
        );

        IERC20(token).transferFrom(from, to, amount);
    }
```
Increasing the balance of the contract by transferring the amount to it, instead of burning the tokens.
