# Vulnerability details

## Impact
Incorrect or inconsistent encoding/decoding of cross-chain messages can lead to manipulated payloads being passed between chains. If a payload is incorrectly decoded or lacks strict validation, an attacker could craft a message that bypasses intended checks, causing incorrect transaction processing or unauthorized transfers.

## Proof of Concept
The Message struct relies on the consistent encoding/decoding of payloads. If the payload types or their formats are not validated strictly, an attacker could forge a message that bypasses validation, leading to invalid operations being performed on the chain.

Example: An attacker could craft a message that appears valid but contains manipulated payload data, causing unexpected behavior in token transfers or liquidity operations.
## Tools Used
1. Fuzz Testing: Using Echidna to randomly generate messages and test edge cases in encoding and decoding.
2. Static Analysis: Slither for inspecting how messages are decoded and how payloads are handled.
3. Unit Testing: StarkNet testing framework to validate encoding/decoding scenarios and simulate potential exploits.
## Recommended Mitigation Steps
1. Implement strict validation on the encoded message fields (such as payload type and payload format).
2. Use cryptographic hashing or signatures to ensure that the message contents cannot be tampered with.
3. Add unit tests and fuzz tests to cover various edge cases in message encoding/decoding.
4. Consider using a schema validation tool to ensure that message formats comply with expected standards.
