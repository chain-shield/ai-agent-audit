# Vulnerability details

## Impact
There exists a transaction replay vulnerability which leads to the draining of the contract's funds
The invariant will be broken:

A cross-chain message can only be received once. The status of a received transaction in receive_cross_txs must be CrossChainMsgStatus.Unknow before it can be processed. 

IF an attacker can keep on replaying his tickets, he only has to transfer or lock his tokens once, but can keep on unlocking and receiving tokens on the Starknet side.

## Proof of Concept

                "Invalid signature"
            );

                "Invalid transaction status"
            );
        }

We can see that on the Solidity side, this is done

Due to the lack of such checks an attacker could replay certain modes several time and drain the account



Example attack (using LockUnlock):

1. An attacker first locks a certain amount of tokens via 
   
        else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } 
        
2. He proceeds with the transaction normally, and the contract sends a cross chain message via send_cross_chain_msg

3. He will get the unlocked tokens on the Starknet side

            }else if self.mode.read() == SettlementMode::LockUnlock{
                token.transfer(u256_to_contract_address(transfer.to), transfer.amount);
            }
            

4.Since there is nothing stopping the message to be replayed again, an attacker can simple send the same ticket again and again, tricking the contract on the Starknet side to call transfer and transfer the tokens again and again.



Example attack (using LockMint):

1. An attacker first locks a certain amount of tokens via 
   
        else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } 
        
2. He proceeds with the transaction normally, and the contract sends a cross chain message via send_cross_chain_msg

3. He will then get minted tokens via

            }else if self.mode.read() == SettlementMode::LockMint{
                erc20.mint_to(u256_to_contract_address(transfer.to), transfer.amount);
            }

4.Since there is nothing stopping the message to be replayed again, an attacker can simple send the same ticket again and again, tricking the contract on the Starknet side to call mint_to and mint the tokens again and again to his address, ultimately draining the contract dry.
