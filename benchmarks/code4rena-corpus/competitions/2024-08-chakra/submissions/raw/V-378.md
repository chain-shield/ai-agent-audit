# Vulnerability details

## Impact
The `TokenRoles` contract has a [public __TokenRoles_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/TokenRoles.sol#L19) that initializes `owner` and `operator`, with no access control. Taking control of the `owner` and `operator` means full control. The contracts `ChakraToken` is [inheriting from](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraToken.sol#L14) `TokenRoles`, so any user, without a need for any permission, can directly call `__TokenRoles_init` passing their own address as `_owner` and take full control of this contract.  

## Proof of Concept
Call this and `ChakraToken  will be pwned
```
ChakraToken.__TokenRoles_init(your_address_as_owner, your_address_as_operator)
```
having the control of owner, you can upgrade the contract and fix the issue so that no one else can take the control back from you.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The [__TokenRoles_init function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/TokenRoles.sol#L19) should be `internal` and also should include the `onlyInitializing` modifier, so that it can only be called as part of the [initialize function](https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraToken.sol#L26-L32) (the function with `initializer` modifier).
