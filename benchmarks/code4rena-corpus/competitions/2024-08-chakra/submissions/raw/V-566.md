# Vulnerability details

## Impact
There is an inconsistency in how the contract handles `SettlementMode.MintBurn` and `SettlementMode.BurnUnlock`. For `MintBurn`, tokens are only burnt when the cross-chain callback confirms that the status is `Success`. On the other hand, in `BurnUnlock`, tokens are immediately burnt, even if the status of the operation might eventually fail. This discrepancy could lead to irreversible token loss in the case of BurnUnlock, whereas MintBurn offers a chance to recover tokens if the operation fails.

## Proof of Concept
In the `cross_chain_erc20_settlement` function, the different settlement modes are handled as follows:

```solidity
        if (mode == SettlementMode.MintBurn) {
@=>         _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockUnlock) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.LockMint) {
            _erc20_lock(msg.sender, address(this), amount);
        } else if (mode == SettlementMode.BurnUnlock) {
@=>         _erc20_burn(msg.sender, amount);
        }
```

For `MintBurn`, tokens are locked first, and only burnt when the cross-chain callback confirms success:

```solidity
        if (status == CrossChainMsgStatus.Success) {
            if (mode == SettlementMode.MintBurn) {
                _erc20_burn(address(this), create_cross_txs[txid].amount);
            }

            create_cross_txs[txid].status = CrossChainTxStatus.Settled;
        }
```

However, in `BurnUnlock`, tokens are burnt directly without waiting for the operation’s success, causing irreversible burning even in the case of failure.

This inconsistency introduces risks:
• In `BurnUnlock`, tokens may be burnt prematurely without ensuring the operation’s success, leading to irreversible losses.
• In `MintBurn`, tokens are temporarily locked and only burnt upon success, allowing for better recovery in case of failure.

## Tools Used
Manual

## Recommended Mitigation Steps

Consider modifying `BurnUnlock` so that tokens are only burnt after confirming the success of the cross-chain operation, similar to the `MintBurn` process.
