# Vulnerability details

## Impact
There is one of the main invariants that states following: 
"The handler receiving a cross-chain message must be on the whitelist for the source chain." 

However in the `ChakraSettlementHandler.sol` contract we see the following check in the function `receive_cross_chain_msg()`: 
```
if (is_valid_handler(from_chain, from_handler) == false) {
            return false;
}
```
This checks if the `from_handler` is on the whitelist for the `from_chain` in the "receiving handler's" whitelist. Although this check might be necessarry and useful (not explicitly stated) it does not ensure that the invariant from the above holds. This check says that the sending handler is considered a valid one for the chain from which the message is coming.

If we take a look at the `cross_chain_erc20_settlement()` function in `ChakraSettlementHandler.sol` we will only find the following check with regard to `to_handler`: 
`require(to_handler != 0, "Invalid to handler address");`

However we do not check if the `to_handler` (handler receiving the message) is whitelisted on the source-chain (chain from which the `cross_chain_erc20_settlement()` function is executed), exposing users to possible interaction with a malicious handler.

## Proof of Concept
If we have two chains: Chain A and Chain B, this implies we also have two handlers: Handler A and Handler B

If sending a transaction from Chain A to Chain B, the source chain would be Chain A and the destination chain Chain B. 

The main invariant says that the receiving handler (Handler B) must be whitelisted on the source chain (Chain A). 

This means that we need to check if the Handler B is whitelisted on the source chain before sending the message to it, otherwise it might be possible to interact with a malicious handler. 

## Tools Used
Manual Review, VS Code
## Recommended Mitigation Steps
Add following check at the beginning of the `cross_chain_erc20_settlement()` function: 

`require(isValidHandler(to_chain, to_handler), "Receiving handler not whitelisted")`
