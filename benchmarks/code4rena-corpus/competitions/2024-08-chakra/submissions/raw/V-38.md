# Vulnerability details

## Impact
In the Chakra cross-chain messaging system, a pair of `ChakraSettlement` and `ChakraSettlementHandler` contracts are deployed on each supported chain to manage cross-chain transactions. Four settlement modes are supported: `MintBurn`, `LockUnlock`, `LockMint`, and `BurnUnlock`. Each mode can be used on any chain. When a cross-chain message is initiated on the source chain, assets are managed according to the specified settlement mode:
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {

    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockUnlock) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockMint) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.BurnUnlock) {
        _erc20_burn(msg.sender, amount);
    }

    // --SNIP
}
```

This discrepancy can lead to inconsistencies in the ERC20 token state across chains. The settlement mode on the destination chain should match the mode used to initiate the cross-chain message.

For example, consider a scenario where the settlement mode on Ethereum is `MintBurn`, and on Polygon, it is `LockUnlock`. If a user bridges tokens from Ethereum (using `MintBurn` mode), the tokens are burned on Ethereum and should be minted on Polygon. However, Polygon contracts incorrectly uses its `LockUnlock` mode, the tokens will be unlocked rather than minted. This inconsistency will lead to the loss of assets on the destination chain, as the unlocked tokens correspond to other users' locked assets.

## Recommended Mitigation Steps
Consider including the settlement mode in the cross-chain message payload and use it to properly handle the message settlement on the destination chain.
