# Vulnerability details

## Vulnerability explanation
Currently, the only crosschain replay protection is to use different string identifiers for each chain. However, when a chain have a hard fork it will copy the current state of the blockchain but changing his `chainId` to a new blockchain. Since the string chain identifier will remain the same, it will be possible to replay the messages in the forked chain. The only parameter that would prevent this issue is to use the `chainId` in the message.

## Impact
Medium, the impact is high because a message can be used twice but the likelihood is low.

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement the `chainId` in the message so it gets unique to each chain even if gets forked.
