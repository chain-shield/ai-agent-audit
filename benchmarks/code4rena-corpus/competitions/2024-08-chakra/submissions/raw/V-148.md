# Vulnerability details

## Summary

`_Settlement_init()::BaseSettlement.sol` is meant to be called by `initialize() public initializer` function, like you can see here :

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L85-L101

As you can see, this `initialize()::ChakraSettlement.sol` function has an `initializer` modifier. But `_Settlement_init()` can be called by anyone (this function is public with no modifier). 

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/BaseSettlement.sol#L54-L74

## Impact

`_Settlement_init()` can be called directly to **bypass the restriction** given by the `initializer modifier` from the `initialize()` function, **allowing to initialize a second time with new parameters** like the `owner`.

## Proof of Concept

-> First, Initialize the contract.

-> Then, try to initialize a **second time** using the `_Settlement_init()` function directly.

## Tools Used

Github, VisualCode.

## Recommended Mitigation Steps

Set this `_Settlement_init()::BaseSettlement.sol` function as `internal`.
