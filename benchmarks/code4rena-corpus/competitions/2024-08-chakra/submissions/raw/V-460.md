# Vulnerability details

## Impact
Malicious managers can add and remove validators allowing them to set themselves as validators and validate malicious transactions. 

The issue is present in both the cairo and solidity part. 

The manager role is NOT trusted according to the contest description.
## Proof of Concept
Validators are of extreme importance as they validate the cross-chain transactions. Adding malicious validators will allow them to validate malicious transactions and lead to loss of funds for the protocol.

Managers are not trusted but they can add and remove validators. Can be seen in `settlement.cairo`:
```
        fn add_validator(ref self: ContractState, new_validator: felt252) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
//rest of the function
```
```
fn remove_validator(ref self: ContractState, old_validator: felt252) -> bool {
            let caller = get_caller_address();
            assert(self.chakra_managers.read(caller) == 1, 'Caller is not a manager');
//rest of the function
```
And in `SettlementSignatureVerifier.sol`:
```
function add_validator(address validator) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == false, "Validator already exists");
        validators[validator] = true;
        validator_count += 1;
        
        emit ValidatorAdded(msg.sender, validator);
    }
```
```
    function remove_validator(
        address validator
    ) external onlyRole(MANAGER_ROLE) {
        require(validators[validator] == true, "Validator does not exists");
        validators[validator] = false;
        validator_count -= 1;

        emit ValidatorRemoved(msg.sender, validator);
    }
```
There's nothing stopping a manager from removing the legit validators, add their own malicious ones, and execute a transaction that drains the protocol. 

Even if the owner later removed the manager, the protocol was still drained. 
## Tools Used
Manual review
## Recommended Mitigation Steps
Make the add and remove operator functions restricted for trusted roles like owner or operators.

Access Control
