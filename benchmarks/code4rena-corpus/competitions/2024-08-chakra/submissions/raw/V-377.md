# Vulnerability details

## Impact
Excess tokens can be minted on the starknet via reentrancy due to missing input validation for the status of the transaction being received.

## Proof of Concept
When the `settlement::receive_cross_chain_msg(..)` function is called to to receive cross-chain message on starknet, the signature of the transaction is validated and that transaction status is updated for the `tx_id` being received for success or failure.

However the problem is that the status of the `tx_id` is never validated during the call and as such a user can call the `receive_cross_chain_msg(...)` function  continuously with the same parameters to mint the same amount of tokens to the recipient
