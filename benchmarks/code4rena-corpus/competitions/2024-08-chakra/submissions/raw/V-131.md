# Vulnerability details

## Impact

In current implementation of `settlement.cairo` smart contract, `receive_cross_chain_msg()` functionality is used to process the messages coming from the source chain. The function first calls handler contract and then, depending on the result of that call, updates the status of the message from `UNKNOW` to `SUCCESS` or `FAILED`. However, the `receive_cross_chain_msg()` function can only return true which means that it's not possible to set status `FAILED` at all. This can lead to several issues - for instance, the failed transaction will be set as successful and it will as well impact the callback functionality.

## Proof of Concept

The current implementation of `receive_cross_chain_msg()`:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L354-361
```
 let success = handler.receive_cross_chain_msg(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , payload);

            let mut status = CrossChainMsgStatus::SUCCESS;
            if success{
                status = CrossChainMsgStatus::SUCCESS;
            }else{
                status = CrossChainMsgStatus::FAILED;
            }

```

Now let's take a look at the returning value of the `receive_cross_chain_msg()` function in the handler contract:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/handler_erc20.cairo#L135
```
return true;
```

So the function can either revert if one of the conditions was not satisfied or return true. This leads to a problem when one of the transfer functions, for instance, can silently failed returning a boolean `false` and the function will still return true not allowing to set a transaction to a FAILED status. On Ethereum, for example, if all of the conditions were not met, the function returns false:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/handler/contracts/ChakraSettlementHandler.sol#L344-354

```

                    return true;
                }
            }
        }
```

Manual review.

## Recommended Mitigation Steps

Set return value to `false` if the transaction was not successful in the handler contract.
