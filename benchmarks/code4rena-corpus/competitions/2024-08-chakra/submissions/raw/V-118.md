# Vulnerability details

## Impact

Solidity code has a critical vulnerability due to inconsistent creation of txIds between `ChakraSettlementHandler` and `ChakraSettlement` contracts.The txIds are generated by using nonce_manager storage value for both contracts. The assumption is that both contracts will produce the same txId for corresponding cross-chain transactions. However, the function `ChakraSettlement::send_cross_chain_msg` can be called by anyone, to increase spesific nonce_manager value. Due to this discrepancy, the txIds values generated by `ChakraSettlement` and `ChakraSettlementHandler` can become unsynchronized. 
This would broke the logic in `receive_cross_chain_callback` functions that shares the same txId values. Since `ChakraSettlementHandler` create_cross_txs woulnt be initialized its status would be unknown and transactions will fail.

## Proof of Concept

`ChakraSettlementHandler::cross_chain_erc20_settlement` function creates new txId using nonce_manager storage variable for a caller. Then increase msg_count and calls settlement contract.

```solidity
    function cross_chain_erc20_settlement(){
...
         nonce_manager[msg.sender] += 1;

           uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    chain,
                    to_chain,
                    msg.sender, // from address for settlement to calculate txid
                    address(this), //  from handler for settlement to calculate
                    to_handler,
                    nonce_manager[msg.sender]
                )
            )
        );
       settlement.send_cross_chain_msg(...);

```

`ChakraSettlement::send_cross_chain_msg` function uses nonce_manager and msg.sender to create new txId. Since txId is going to be used by `receive_cross_chain_callback` functions for both contracts these two txIds must be same.  But the problem is this function can be called by anyone to increase nonce_manager without updating ChakraSettlementHandler. When this happened txId between contracts wont match.

```solidity
    function send_cross_chain_msg(){
...
        //@audit nonce can be increased by anyone
        nonce_manager[from_address] += 1;
        address from_handler = msg.sender;
        uint256 txid = uint256(
            keccak256(
                abi.encodePacked(
                    contract_chain_name, // from chain
                    to_chain,
                    from_address, // msg.sender address
                    from_handler, // settlement handler address
                    to_handler,
                    nonce_manager[from_address]
                )
            )
        );

```
