# Vulnerability details

## Impact
The cross_chain_erc20_settlement function accepts a to_token parameter, but fails to validate that this token matches the token associated with the to_handler. This lack of validation can lead to inconsistencies between the intended destination token and the actually used token on the destination chain. As a result, users may experience unexpected token transfers, potentially leading to loss of funds or unintended token swaps. This is issue is present in both solidity and cairo contracts.

## Proof of Concept
In the cross_chain_erc20_settlement function, to_token is passed as a parameter but not validated:
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {
    // ... (no validation of to_token)
}
```

The to_token is included in the created cross-chain transaction:
```solidity
create_cross_txs[txid] = CreatedCrossChainTx(
    txid,
    chain,
    to_chain,
    msg.sender,
    to,
    address(this),
    to_token,
    amount,
    CrossChainTxStatus.Pending
);
```
However, in the receive_cross_chain_msg function on the destination chain, the local token address is used for minting or unlocking, regardless of the to_token specified in the original transaction:
```solidity

if (mode == SettlementMode.MintBurn) {
    _erc20_mint(
        AddressCast.to_address(transfer_payload.to),
        transfer_payload.amount
    );
    return true;
}

function _erc20_mint(address account, uint256 amount) internal {
        IERC20Mint(token).mint_to(account, amount);
    }
//to_token is present in payload but is not used or validated
```

Scenario demonstrating the vulnerability:

1. User initiates a cross-chain transfer, specifying to_token as Token A
2. The source chain creates a transaction record with Token A as the destination token
3. The destination chain receives the message but uses its locally set token (Token B) for minting or unlocking
4. Result: User receives Token B instead of the expected Token A
## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a validation check in the cross_chain_erc20_settlement function to ensure to_token matches the token associated with to_handler.
