# Vulnerability details


## Impact

The `to_bytes` function in `AddressCast.sol`, found in both `/handler` and `/settlement` directories, contains a logical error when converting `bytes32` to `bytes`. The function incorrectly left-shifts the input data, which is already left-aligned in Solidity's `bytes32` type. This misalignment results in data loss when the `_size` parameter is less than 32 bytes.

This error stems from a misunderstanding of EVM data alignment. Types such as `bytes` and `bytesX` (where X is 1, 2, ..., 32) are left-aligned in the EVM.

## Proof of Concept

- [solidity/handler/.../AddressCast.sol](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/handler/contracts/libraries/AddressCast.sol#L32-L45)
- [solidity/settlement/.../AddressCast.sol](https://github.com/code-423n4/2024-08-chakra/blob/d0d45ae1d26ca1b87034e67180fac07ce9642fd9/solidity/settlement/contracts/libraries/AddressCast.sol#L48-L75)

The problematic code in the `to_bytes` function:

```solidity
function to_bytes(
    bytes32 _addressBytes32,
    uint256 _size
) internal pure returns (bytes memory result) {
    if (_size == 0 || _size > 32)
        revert AddressCast_InvalidSizeForAddress();
    result = new bytes(_size);
    unchecked {
        uint256 offset = 256 - _size * 8;
        assembly {
            mstore(add(result, 32), shl(offset, _addressBytes32))
        }
    }
}
```

Test case demonstrating the issue:

```solidity
    function testToBytes() public pure {
```

## Recommended Mitigation Steps

Remove the shift operation entirely. The correct implementation should directly copy the required number of bytes from the input `bytes32`. Here's the corrected function:

```diff
function to_bytes(
    bytes32 _addressBytes32,
    uint256 _size
) internal pure returns (bytes memory result) {
    if (_size == 0 || _size > 32)
        revert AddressCast_InvalidSizeForAddress();
    result = new bytes(_size);
    assembly {
-        mstore(add(result, 32), shl(offset, _addressBytes32))
+        mstore(add(result, 32), _addressBytes32)
    }
}
```

This implementation stores `_addressBytes32` into the result buffer without shifting. The Solidity compiler will handle the proper memory layout, ensuring that only the first `_size` bytes are included in the returned `bytes` array.
