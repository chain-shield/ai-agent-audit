# Vulnerability details

## Summary 

The protocol contract does not invoke the `_disableInitializers` function, leaving the implementation contract vulnerable to unauthorized initialization. This oversight introduces a security risk, as it allows attackers to directly initialize the implementation contract, granting them unauthorized access and increasing the likelihood of exploitation.

## Vulnerability details 

The `disableInitializers` function is intended to lock the initializer functions once the contract has been deployed, ensuring that no further initializations can occur directly on the implementation contract.

Failure to invoke this function leaves the implementation contract vulnerable to unauthorized initialization by an attacker.

An attacker could directly initialize the implementation contract, assuming ownership. With this control, they would be able to execute functions restricted by the `onlyOwner` modifier, including those that could issue a `delegatecall` to a self-destruct opcode, rendering the implementation contract inoperable and preventing future proxy upgrades.

## Impact

Without invoking `_disableInitializers`, an attacker can initialize and gain control of the implementation contract.

The attacker could then issue a `delegatecall` to a contract containing a self-destruct opcode, effectively destroying the implementation contract and rendering the assets within the proxy inaccessible indefinitely.

## Recommendations

1. **Add Constructor with `_disableInitializers()`**:

    _disableInitializers();
