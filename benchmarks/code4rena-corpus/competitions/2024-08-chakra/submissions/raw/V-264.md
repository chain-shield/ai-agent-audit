# Vulnerability details


## Summary

In the Cairo implementation of cross-chain transaction processing via `receive_cross_chain_msg` function, few status checks are missing. Specifically, there is no verification of a transaction’s prior status before processing, and the intermediate `Pending` status is not implemented. This can result in reprocessing of transactions, lack of visibility into transaction states, and potential inconsistencies between cross-chain systems of Chakra.


## Vulnerability Details

In the Cairo code, the `receive_cross_chain_msg` function directly writes transaction details to the `received_tx` mapping without checking whether the transaction has been processed before. In contrast, the Solidity implementation ensures that the transaction’s status is `Unknow` before processing. Additionally, the Cairo implementation does not track transactions with a `Pending` status, which is a critical step in the Solidity version to indicate that the transaction is being processed.

### Missing Checks:
1. **Status Check**: No validation of whether the transaction is new or already processed.
2. **Pending State**: Direct finalization of transaction status without a `Pending` state during processing.


## Impact

1. **Reprocessing & Replay Attacks**: Without proper status checks, the same transaction can be processed multiple times, potentially leading to:
   - Double withdrawals or token minting.
   - Exploitation via replay attacks.
   
2. **Cross-Chain Inconsistencies**: The lack of a `Pending` status can lead to discrepancies in transaction states between chains, causing mismatches in user balances and system states.

3. **Loss of Transparency**: The absence of `Pending` status tracking reduces visibility, making it difficult to monitor and debug in-progress transactions.


## Recommendation

1. **Add Status Check**: Implement a check to ensure that the transaction has not been processed before writing to `received_tx` by verifying that its current status is `Unknow`.

2. **Implement Pending Status**: Introduce a `Pending` status to track the processing state of cross-chain transactions, ensuring that the transaction is only finalized once processing is complete.
