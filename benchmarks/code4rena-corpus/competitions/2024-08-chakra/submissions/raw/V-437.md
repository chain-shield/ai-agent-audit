# Vulnerability details

The `__TokenRoles_init()` function, inherited by the `ChakraToken` contract from the `TokenRoles` contract, is marked as `public`. This exposes the `ChakraToken` contract to unauthorized re-initialization of token roles, allowing an attacker to reset critical roles such as the owner and operator, potentially gaining control over the contract.

## Impact
An attacker can exploit the public visibility of the `__TokenRoles_init()` function to reset the ownership and operator roles of the `ChakraToken` contract. This would result in the following consequences:

1. **Take over ownership of the contract**: The attacker can set themselves as the owner, granting them full administrative control over the contract.
  
2. **Mint unlimited tokens**: By becoming the operator, the attacker can mint an arbitrary amount of tokens, causing inflation and devaluing the token.
   
3. **Burn any user's tokens**: The attacker can burn tokens from any user’s account without restriction, causing users to lose their tokens permanently.

4. **Upgrade the contract**: The attacker can upgrade the contract to a malicious version, potentially introducing more vulnerabilities or siphoning funds.

These actions can disrupt the token's supply, result in significant loss of funds for users, and give the attacker full control over the contract, leading to a total compromise of the `ChakraToken` system.

## Proof of Concept
The `ChakraToken` contract inherits the `__TokenRoles_init()` function from the `TokenRoles` contract. This function is intended to initialize the owner and operator of the contract during the deployment phase. However, because it is marked as `public`, it can be called by anyone after deployment, which could allow a malicious actor to reinitialize the contract with themselves as the owner and operator.

The `initialize` function of the `ChakraToken` contract calls the `__TokenRoles_init()` function:

## Recommended Mitigation Steps
To secure the `ChakraToken` contract, the visibility of the `__TokenRoles_init()` function should be changed from `public` to `internal` to prevent external calls. The function should only be called during the initialization process.

```diff
-   function __TokenRoles_init(address _owner, address _operator) public {
+   function __TokenRoles_init(address _owner, address _operator) internal {
        __Ownable_init(_owner);
        _grantRole(DEFAULT_ADMIN_ROLE, _owner);
        _grantRole(OPERATOR_ROLE, _operator);
    }
```
