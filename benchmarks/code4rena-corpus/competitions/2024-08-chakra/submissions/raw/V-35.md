# Vulnerability details

## Impact
The protocol supports two bridging modes that require burning assets on the source chain: `MintBurn` and `BurnUnlock`. In the `MintBurn` mode, assets being bridged to the destination chain are first **locked** on the source chain and then [burned only after the successful settlement](https://github.com/code-423n4/2024-08-chakra/blob/abef77d95866f2fec93270491fc5abc9ab14f86d/solidity/handler/contracts/ChakraSettlementHandler.sol#L384-L386) of the cross-chain message in the `receive_cross_chain_callback`:
##### Locking the assets on the source chain when initiating cross-chain message
```solidity

    uint256 to,
```


However, this safe approach is not applied to the `BurnUnlock` mode, where assets are **immediately** burned on the source chain during the initialization of the cross-chain message:
```solidity
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {

    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockUnlock) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockMint) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.BurnUnlock) {
>>>        _erc20_burn(msg.sender, amount);
    }
    // --SNIP
}
```
This is problematic as cross-chain messages can fail on the destination chain (e.g., if the source handler is removed from the whitelist). In such cases, the assets fail to be bridged to the destination chain but are still burned on the source chain, leading to a permanent loss of users' assets.

## Recommended Mitigation Steps
Consider deferring the burn of assets in the `BurnUnlock` mode until the successful settlement is confirmed in the callback function
```diff
function cross_chain_erc20_settlement(
    string memory to_chain,
    uint256 to_handler,
    uint256 to_token,
    uint256 to,
    uint256 amount
) external {

    if (mode == SettlementMode.MintBurn) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockUnlock) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.LockMint) {
        _erc20_lock(msg.sender, address(this), amount);
    } else if (mode == SettlementMode.BurnUnlock) {
-        _erc20_burn(msg.sender, amount);
+        _erc20_lock(msg.sender, amount);
    }
    // --SNIP
}

function receive_cross_chain_callback(
    uint256 txid,
    string memory from_chain,
    uint256 from_handler,
    CrossChainMsgStatus status,
    uint8 /* sign_type */, // validators signature type /  multisig or bls sr25519
    bytes calldata /* signatures */
) external onlySettlement returns (bool) {
    // --SNIP
    if (status == CrossChainMsgStatus.Success) {
-       if (mode == SettlementMode.MintBurn) {
+       if (mode == SettlementMode.MintBurn || mode == SettlementMode.BurnUnlock) {
            _erc20_burn(address(this), create_cross_txs[txid].amount);
        }
        create_cross_txs[txid].status = CrossChainTxStatus.Settled;
    // --SNIP
    }
}
```
