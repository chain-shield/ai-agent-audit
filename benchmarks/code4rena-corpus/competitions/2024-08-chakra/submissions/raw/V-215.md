# Vulnerability details

## Impact

In the settlement smart contract on the Starknet chain, `receive_cross_chain_callback()` is called by the Chakra network to notify about the status of the call on the destination chain. And if it was successful, proceed with the call and release the funds, for instance (in case of the minting). In the case of a failed call, just set status to failed. The problem is that the status that's sent by the network is not respected. And if the call failed on the destination chain but `receive_cross_chain_callback()`callback call  to the handler contract was successful, the status of the message will be set to true no matter what the status was sent by the network.

## Proof of Concept

Take a look at the `receive_cross_chain_callback()` function in the `settlement.cairo` smart contract:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L415-421
```
 let success = handler.receive_cross_chain_callback(cross_chain_msg_id, from_chain, to_chain, from_handler, to_handler , cross_chain_msg_status);
            let mut state = CrossChainMsgStatus::PENDING;
            if success{
                state = CrossChainMsgStatus::SUCCESS;
            }else{
                state = CrossChainMsgStatus::FAILED;
            }
```

This part of the code shows that there is a call to the handler contract and, depending on the result of that call, the state will be changed to `SUCCESS` or `FAILED`. However, this is an unexpected behavior as status of the message is provided by the Chakra network and it should correspond to it:

https://github.com/code-423n4/2024-08-chakra/blob/main/cairo/handler/src/settlement.cairo#L400
```
 cross_chain_msg_status: u8,
```

On Ethereum, if the result of the call to the handler was successful, the status will be changed to the status that's provided by the Chakra network. Otherwise, it will be set to `FAILED` anyway. And this seems like a correct way to handle it:

https://github.com/code-423n4/2024-08-chakra/blob/main/solidity/settlement/contracts/ChakraSettlement.sol#L317-330
```
if (
            ISettlementHandler(to_handler).receive_cross_chain_callback(
                txid,
                from_chain,
                from_handler,
                status,
                sign_type,
                signatures
            )
        ) {
            create_cross_txs[txid].status = status;
        } else {
            create_cross_txs[txid].status = CrossChainMsgStatus.Failed;
        }

```

## Recommended Mitigation Steps

Ultimately, the status should correspond to the status provided by the network and does not depend on any other calls.
