# Vulnerability details

## Impact
The `cross_chain_erc20_settlement` function allows users to specify the `to_handler` for cross-chain transactions without validating whether the handler is part of a predefined whitelist. This creates a potential vulnerability, where an invalid or malicious handler could be used, leading to improper execution of cross-chain settlements. Such an issue could result in fund loss, erroneous cross-chain messaging, or other security breaches.

## Proof of Concept
In the `cross_chain_erc20_settlement` function, parameters like `to_handler`, to_token, and amount are passed by the caller to initiate the settlement. However, there is no check to confirm that the to_handler is part of a secure whitelist, despite the presence of an add_handler and remove_handler function elsewhere in the contract.

A malicious actor could provide an arbitrary to_handler value that is not part of the whitelist and initiate a cross-chain settlement. As a result, the transaction could be sent to an unauthorized or malicious handler, causing unexpected behavior or loss of assets.

```javascript
require(to_handler != 0, "Invalid to handler address");
```
While there is a check that `to_handler` is not 0, there is no validation against a whitelist:

```javascript
handler_whitelist[chain_name][handler] = true;
```
The function does not ensure that `to_handler` is part of the whitelist, which makes it vulnerable to accepting arbitrary addresses.
