# Vulnerability details

## Impact
Transfer of ownership for Chakra Token will revert as the logic flow invokes revoke of `DEFAULT_ADMIN_ROLE` for the current user(msg.sender) before setting access entitlements for the new user. As a result, the current user will not have the access entitlements to setup the role for the new user leading to revert.

## Proof of Concept
Refer to the below code snippet where the transfer Of ownership for Chakra Token is implemented in the base contract `TokenRoles.sol`.

In the below logic flow, the `DEFAULT_ADMIN_ROLE` role for the `msg.sender` is revoked before granting the role to `newOwner`.

In order to grant the role, the caller should have the entitlements.

```solidity
function transferOwnership(address newOwner) public override onlyOwner {
-->      _revokeRole(DEFAULT_ADMIN_ROLE, msg.sender);
        _grantRole(DEFAULT_ADMIN_ROLE, newOwner);
        _transferOwnership(newOwner);
    }
```
Refer to the init function where the `owner` and the `DEFAULT_ADMIN_ROLE` role was setup for `msg.sender`. But, with ` _revokeRole()` call, the msg.sender lost the entitlements to grant role to other account.

```
 function __TokenRoles_init(address _owner, address _operator) public {
        __Ownable_init(_owner);
        _grantRole(DEFAULT_ADMIN_ROLE, _owner);
        _grantRole(OPERATOR_ROLE, _operator);
    }
```


The `DEFAULT_ADMIN_ROLE` is also its own admin: it has permission to
 * grant and revoke this role. Extra precautions should be taken to secure
 * accounts that have been granted it. We recommend using {AccessControlDefaultAdminRules}
 * to enforce additional security measures for this role.

Since the caller(msg.sender) role was revoked, the caller cannot setup the role for `newOwner`

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Revise the implementation as below

```solidity
function transferOwnership(address newOwner) public override onlyOwner {
        _grantRole(DEFAULT_ADMIN_ROLE, newOwner);
        _revokeRole(DEFAULT_ADMIN_ROLE, msg.sender);
        _transferOwnership(newOwner);
    }
```
