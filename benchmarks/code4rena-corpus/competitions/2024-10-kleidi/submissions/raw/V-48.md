# Vulnerability details

Timelock contract's `executeWhitelisted` function contains a flaw due to insufficient validation of input data. This function, intended to allow trusted signers to execute whitelisted actions, fails to properly validate the entire calldata, potentially allowing malicious transactions to bypass security checks.

Why it happened is because the `checkCalldata` function, called within `executeWhitelisted`, does not validate the entire payload. It likely only checks specific segments of the calldata, allowing carefully crafted malicious payloads to pass through undetected.
```solidity
function executeWhitelisted(
    address target,
    uint256 value,
    bytes calldata payload
) external payable onlyRole(HOT_SIGNER_ROLE) whenNotPaused {
    checkCalldata(target, payload);  // <= FOUND
    _execute(target, value, payload);
    emit CallExecuted(bytes32(0), 0, target, value, payload);
}
```
_The `checkCalldata` function's implementation likely focuses on validating specific parts of the payload, such as function selectors or certain parameters, without ensuring the integrity of the entire calldata. This partial validation creates a security gap that can be exploited._

1. Assume a whitelisted function `transfer(address,uint256)` on a target contract.
2. Create a malicious payload that appears to call `transfer` but actually contains additional data to execute an unauthorized action.
3. Call `executeWhitelisted` with:

   * `target`: The address of the whitelisted contract
   * `value`: 0
   * `payload`: The malicious payload

The `checkCalldata` function will pass this payload as valid, and `_execute` will process it.

## Proof of Concept
Consider a scenario where a whitelisted function `transfer(address,uint256)` exists on a target contract. An attacker with the HOT_SIGNER_ROLE could craft a malicious payload that appears to call `transfer` but contains additional data to execute an unauthorized action.

1. Attacker crafts a payload: `transfer(address,uint256) + malicious_data`
2. Attacker calls `executeWhitelisted(target, 0, malicious_payload)`
3. `checkCalldata` validates only the initial part of the payload, passing the check
4. `_execute` processes the entire payload, including the malicious part

We can see in this POC how partial validation in `checkCalldata` can be exploited to execute unauthorized actions through the timelock.
