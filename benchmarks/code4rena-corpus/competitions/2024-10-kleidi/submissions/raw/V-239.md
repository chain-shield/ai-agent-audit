# Vulnerability details

## Description

The `initialize` function in the `Timelock` contract lacks validation to ensure that the arrays passed to the `_addCalldataChecks` function have consistent lengths. This could lead to unexpected behavior or errors during initialization if the arrays are mismatched.

## Vulnerable Code

```solidity
function initialize(
    address[] memory contractAddresses,
    bytes4[] memory selectors,
    uint16[] memory startIndexes,
    uint16[] memory endIndexes,
    bytes[][] memory datas
) external {
    require(!initialized, "Timelock: already initialized");
    initialized = true;

    _addCalldataChecks(
        contractAddresses, selectors, startIndexes, endIndexes, datas 
    );
}
```

## Scenario

If the `initialize` function is called with arrays of inconsistent lengths (e.g., `contractAddresses` has 3 elements, but `selectors` has 2), the `_addCalldataChecks` function might try to access elements outside the bounds of one or more arrays. This could result in:

* **Unexpected Behavior:** The calldata checks might be applied incorrectly, potentially leading to unintended whitelisting or restrictions.
* **Reverts:** The contract could revert due to out-of-bounds array access, preventing proper initialization.

## Impact

This issue could compromise the security and functionality of the timelock contract if it's not initialized correctly. It could lead to:

* **Incorrect Whitelisting:**  Unauthorized transactions might be allowed if calldata checks are misapplied.
* **Denial of Service:**  The timelock might become unusable if initialization fails due to a revert.

## Recommendation

Add length consistency checks within the `initialize` function before calling `_addCalldataChecks`:

```solidity
function initialize(...) external {
    // ... 

    require(
        contractAddresses.length == selectors.length && 
        selectors.length == startIndexes.length && 
        startIndexes.length == endIndexes.length && 
        endIndexes.length == datas.length,
        "Timelock: Array lengths must be equal"
    );

    _addCalldataChecks(...);
}
```

This ensures that all arrays have the same number of elements, preventing out-of-bounds access and ensuring correct initialization.
