# Vulnerability details

## Proof of Concept
The `cancel` function in Timelock contract allows cancellation of an operation without checking if it has already been executed. It only checks if the operation exists and is in the `_liveProposals` set. As a result, even executed operations can be cancelled, effectively "un-executing" them in the contract's state.

Operations that have been executed can appear as pending or non-existent. Cancelled operations could potentially be re-executed. 

Consider the following sequence of events

1. An operation with ID `x` is scheduled.
2. The operation is executed, setting `timestamps[x] = 1` (DONE_TIMESTAMP).
3. The `cancel(x)` function is called, which succeeds.
4. The cancellation removes `x` from `_liveProposals` and sets `timestamps[x] = 0`.
5. Now, `isOperation(x)` returns true (because `timestamps[x] = 0`), but the operation has been executed.

In the [Timelock contract:#L657-L665](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L657-L665)
```solidity
function cancel(bytes32 id) external onlySafe whenNotPaused {
    require(
        isOperation(id) && _liveProposals.remove(id),
        "Timelock: operation does not exist"
    );

    delete timestamps[id]; // <= FOUND
    emit Cancelled(id);
}
```
## Recommended Mitigation Steps
Implement a check in the cancel function to ensure that only non-executed operations can be cancelled.
```diff
function cancel(bytes32 id) external onlySafe whenNotPaused {
    require(
-       isOperation(id) && _liveProposals.remove(id),
+       isOperation(id) && !isOperationDone(id) && _liveProposals.remove(id),
        "Timelock: operation does not exist or is already executed"
    );

    delete timestamps[id];
    emit Cancelled(id);
}
```
