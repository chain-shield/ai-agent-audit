# Vulnerability details

## Proof of Concept
**Summary**
When a proposal is scheduled its added to the list of live proposals`(_liveProposals)` whereby after delay time passing it will be ready for execution.The problem arises when the pause function is called by the guardian where by all pending and non executed operations will be cancelled making the proposals to be rescheduled again since the current timestamp won't be cached.

**Vulnerability Detail**
- When the `pause` function is called by the Guardian it will delete the timestamp and remove the pending and non executed operations from the list of liveproposals as shown below:
```solidity
function pause() public override {
        /// check that msg.sender is the pause guardian, pause the contract
        super.pause();

        bytes32[] memory proposals = _liveProposals.values();
        for (uint256 i = 0; i < proposals.length; i++) {
            bytes32 id = proposals[i];

@>          delete timestamps[id];
@>          assert(_liveProposals.remove(id));
            emit Cancelled(id);
        }
    }

```
- This will make there be need for the operation to be rescheduled again by calling the `schedule` function which will make delay time be set or start counting again.

**Attack Scenario**
- Alices' operation gets schedule by the safe with a delay of 20 days
- The Pause Guardian cancels all outstanding pending operation by calling pause on day 15.
- On unpause Alices' operation will get scheduled again lets use a delay of 20 days.
- If it won't be paused the operation will have taken her 15 more days than the expected time.
- But if it gets paused and the loop continues it can take her more than `MAX_DELAY` time waiting. 


## Recommended Mitigation Steps
- Add logic whereby pending operations will be executed on pause since scheduled operations may take more time to execute especially when cancelled and rescheduled again which may make delay time even more than MAX_DELAY.
- On pause let scheduled operations be paused temporarily and continue counting from the left delay time on unpause.
