# Vulnerability details

## Proof of Concept
`updateExpirationPeriod` function allows updating the expiration period for timelocked actions, but it checks the new period against a constant `MIN_DELAY` instead of the variable `minDelay`. This inconsistency can lead to setting an expiration period shorter than the current minimum delay.

> The function is using the constant `MIN_DELAY` for its check, rather than the variable `minDelay`. This means that even if `minDelay` has been increased at some point, the `updateExpirationPeriod` function would still allow setting the expiration period to a value potentially lower than the current `minDelay`, as long as it's not lower than the constant `MIN_DELAY`.

This discrepancy between using the constant `MIN_DELAY` instead of the variable `minDelay` is the core of the issue.

The bug is in the `updateExpirationPeriod` function in Timelock.sol.
```solidity
function updateExpirationPeriod(uint256 newPeriod) external onlyTimelock {
    require(newPeriod >= MIN_DELAY, "Timelock: delay out of bounds");
    // @Audit: Vulnerability - should check against minDelay instead of MIN_DELAY

    emit ExpirationPeriodChange(expirationPeriod, newPeriod);
    expirationPeriod = newPeriod;
}
```
The issue is that the `MIN_DELAY` constant is used for the check, not the `minDelay` variable. This allows setting the expiration period to a value less than the current `minDelay`, which could lead to unexpected behavior in the contract.

To reproduce this issue

1. Set `minDelay` to a value greater than `MIN_DELAY` (e.g., 2 days).
2. Call `updateExpirationPeriod` with a value less than `minDelay` but greater than or equal to `MIN_DELAY`.

### PoC

1. Initially, let `MIN_DELAY = 1` day and `minDelay = 1 day`
2. Increase `minDelay` to 2 days using the `updateDelay` function
3. Call `updateExpirationPeriod` with a value of 1 day + 1 second
4. This call will succeed, setting `expirationPeriod` to a value less than `minDelay`

Located in the `updateExpirationPeriod` function in Timelock.sol. It connects to the broader timelock mechanism, affecting all operations that rely on the correct relationship between `minDelay` and `expirationPeriod`.

## Recommended Mitigation Steps
Check against the `minDelay` variable instead of the `MIN_DELAY` constant:
```diff
function updateExpirationPeriod(uint256 newPeriod) external onlyTimelock {
-   require(newPeriod >= MIN_DELAY, "Timelock: delay out of bounds");
+   require(newPeriod >= minDelay, "Timelock: expiration period must be >= minDelay");

    emit ExpirationPerirationChange(expirationPeriod, newPeriod);

```
