# Vulnerability details

## Proof of Concept
[Root cause]
The [INVARIANT.md](https://github.com/solidity-labs-io/kleidi/blob/main/docs/INVARIANTS.md#Recovery-Spells) stated as follows.
```
The following must always be true for any recovery spell created through the factory:
There is at least one new owner.
```
But the [RecoverySpellFactory.createRecoverySpell()](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/RecoverySpellFactory.sol#L44-L78) function is the following.
```solidity
    function createRecoverySpell(
        bytes32 salt,
        address[] memory owners,
        address safe,
        uint256 threshold,
        uint256 recoveryThreshold,
        uint256 delay
    ) external returns (RecoverySpell recovery) {
        _paramChecks(owners, threshold, recoveryThreshold, delay);
        /// no checks on parameters as all valid recovery spells are
        /// deployed from the factory which will not allow a recovery
        /// spell to be created that does not have valid parameters
        require(safe.code.length != 0, "RecoverySpell: safe non-existent");

        /// duplicate owner check
        for (uint256 i = 0; i < owners.length; i++) {
            /// not touching memory, we only use the stack and transient storage
            /// so we can use memory-safe for the assembly block
            address owner = owners[i];
            bool found;
            assembly ("memory-safe") {
                found := tload(owner)
                /// save a write to transient storage if the owner is found
                if eq(found, 0) { tstore(owner, 1) }
            }

            require(!found, "RecoverySpell: Duplicate owner");
        }

        recovery = new RecoverySpell{salt: salt}(
            owners, safe, threshold, recoveryThreshold, delay
        );

        emit RecoverySpellCreated(address(recovery), address(safe));
    }
```
As can be seen, the above function doesn't check if there is at least one new owner.

[Proof of Concept]
Add the following test function into the [RecoverySpells.t.sol](https://github.com/code-423n4/2024-10-kleidi/blob/main/test/integration/RecoverySpells.t.sol).
```solidity
    function test_invariant_atLeastOneNewOwner() public {
        // create recovery spell with recovery owners which is the same as exsiting owners
        address[] memory existingOwners = safe.getOwners();
        RecoverySpell spell = recoveryFactory.createRecoverySpell(
            recoverySalt,
            existingOwners, // equal to the exsiting owners
            address(safe),
            recoveryThreshold,
            RECOVERY_THRESHOLD_OWNERS,
            recoveryDelay
        );
    }
}
```
And then run the following command in console.
```bash
forge test --mt test_invariant_atLeastOneNewOwner -vvv --fork-url $ETH_RPC_URL --fork-block-number 20515328
```
The output is the following.
```bash
Ran 1 test for test/integration/RecoverySpells.t.sol:RecoverySpellsIntegrationTest
[PASS] test_invariant_atLeastOneNewOwner() (gas: 1372303)
Suite result: ok. 1 passed; 0 failed; 0 skipped; finished in 30.63ms (858.70µs CPU time)

Ran 1 test suite in 1.69s (30.63ms CPU time): 1 tests passed, 0 failed, 0 skipped (1 total tests)
```
As can be seen, we can create the recovery spell while there is no new user at all.

[Impact]
Break of Invariant because we can create the recovery spell while there is no new user.

## Recommended Mitigation Steps
Add a check of new owner into the [RecoverySpellFactory.createRecoverySpell()](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/RecoverySpellFactory.sol#L44-L78) function as follows.
