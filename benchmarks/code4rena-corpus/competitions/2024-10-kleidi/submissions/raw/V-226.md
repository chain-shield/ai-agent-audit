# Vulnerability details

## Proof of Concept
#### Impact
Absence of payable value tracking would cause loss of excess msg.value sent to Timelock contract for Operation Execution by caller without refund
#### Description
```solidity
    function executeBatch(
        address[] calldata targets,
        uint256[] calldata values,
        bytes[] calldata payloads,
        bytes32 salt
    ) external payable whenNotPaused {
        require(
            targets.length == values.length && targets.length == payloads.length,
            "Timelock: length mismatch"
        );

        bytes32 id = hashOperationBatch(targets, values, payloads, salt);

        /// first reentrancy check, impossible to reenter and execute the same
        /// proposal twice
        require(_liveProposals.remove(id), "Timelock: proposal does not exist");
        require(isOperationReady(id), "Timelock: operation is not ready");

        for (uint256 i = 0; i < targets.length; i++) {
            bytes calldata payload = payloads[i];

>>>            _execute(targets[i], values[i], payload);
            emit CallExecuted(id, i, targets[i], values[i], payload);
        }

        /// second reentrancy check, second check that operation is ready,
        /// operation will be not ready if already executed as timestamp will
        /// be set to 1
        _afterCall(id);
    }
```
The code above shows how execution batch is implemented in the timelock contract, it is a payable function and it can be noted from the pointer above that a call is made to _execute(...) function with a specific value from values array, this value is used to carryout the _execution function as provided below. The problem is that the protocol assumes the cumulative value used for the call would be exactly equal msg.value used to make the call, but this would not always be the case, with the implication that excess fund attached to the related function call would completely lost.
```solidity
    function _execute(address target, uint256 value, bytes calldata data)
        private
    {
>>>        (bool success,) = target.call{value: value}(data);
        require(success, "Timelock: underlying transaction reverted");
    }
```
other instances of where the _execute(..) function is called and where this vulnerability can be noted at [L602](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L602), [L723](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L723) & [L751](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L751).
