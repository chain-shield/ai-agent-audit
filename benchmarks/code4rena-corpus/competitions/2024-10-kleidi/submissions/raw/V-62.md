# Vulnerability details

## Summary

Currently using the `updatePauseDuration()` the timelock is able to immediately cancel the pause no matter what duration is set.

## Vulnerability details

#### Original functionality

Once pause started it could not be disabled anyway. Best case scenario Timelock could call updatePauseDuration and reduce the duration **one day**.

#### Post _setPauseTime(0) addition

To fix the bug of extending pause duration using `updatePauseDuration(uint128 newPauseDuration)` and bringing back the contracts into the state of paused. But this introduces an unintended side-effect:

It is now possible (intentionally or otherwise) to immediately ended pause whenever the update is called. Because it sets the pauseStartTime to 0.

## Proof of Concept

Sequence of actions:
- PauseGuardian calls pause() -> pauseStartTime = now; paused() returns true
- Timelock calls updatePauseDuration() -> pauseStartTime = 0; paused() returns true (no matter what newPeriod is passed)
- Contract is no longer paused.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Even though the comments in _updatePauseDuration, say
```
/// should only be called when the contract is unpaused
```
There is nothing preventing it from calling it.
