# Vulnerability details

## Proof of Concept
The Timelock contract allows scheduling of both individual and batch operations. However, there's a flaw in the implementation that allows the same operation to be scheduled both individually and as part of a batch. This inconsistency can lead to potential duplicate executions of operations, undermining the integrity of the timelock mechanism.

The issue stems from the `scheduleBatch` function not cross-checking its operations against already scheduled individual operations. Similarly, the schedule function for individual operations doesn't verify if the operation is already part of a scheduled batch.

The vulnerability is primarily in the [scheduleBatch function#L556-L570](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L556-L570)
```solidity
function scheduleBatch(
    address[] calldata targets,
    uint256[] calldata values,
    bytes[] calldata payloads,
    bytes32 salt,
    uint256 delay
) external onlySafe whenNotPaused {
    // ...

    bytes32 id = hashOperationBatch(targets, values, payloads, salt); 

    require(_liveProposals.add(id), "Timelock: duplicate id");

    _schedule(id, delay);

    // ...
} // <= FOUND
```
To demonstrate

1. Schedule an individual operation
```solidity
timelock.schedule(target1, value1, payload1, salt1, delay);
```
2. Schedule a batch operation including the same operation
```solidity
address[] memory targets = [target1, target2];
uint256[] memory values = [value1, value2];
bytes[] memory payloads = [payload1, payload2];
timelock.scheduleBatch(targets, values, payloads, salt2, delay);
```
```solidity
// Assume 'timelock' is an instance of the Timelock contract
address target1 = address(0x123);
uint256 value1 = 1 ether;
bytes memory payload1 = abi.encodeWithSignature("someFunction()");
bytes32 salt1 = bytes32(0);
uint256 delay = 1 days;

// Schedule individual operation
timelock.schedule(target1, value1, payload1, salt1, delay);

// Schedule batch operation including the same operation
address[] memory targets = [target1, address(0x456)];
uint256[] memory values = [value1, 2 ether];
bytes[] memory payloads = [payload1, abi.encodeWithSignature("anotherFunction()")];
bytes32 salt2 = bytes32(1);

timelock.scheduleBatch(targets, values, payloads, salt2, delay);

// Both operations are now scheduled, potentially leading to duplicate executions
```
Both operations are now scheduled, potentially leading to duplicate executions.

The issue's because the `scheduleBatch` function only checks for duplicate batch IDs but doesn't verify if any component of the batch is already scheduled individually. Similarly, the schedule function for individual operations doesn't check if the operation is part of an existing batch.

## Recommended Mitigation Steps
1. Implement a mapping to track which individual operations are part of batches.
2. In the `schedule` function, check if the operation is part of an existing batch and prevent scheduling if it is.
3. In the `scheduleBatch` function, check if any of the individual operations are already scheduled and prevent batch scheduling if they are.
