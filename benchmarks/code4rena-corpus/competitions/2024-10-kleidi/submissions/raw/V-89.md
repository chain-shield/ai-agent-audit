# Vulnerability details

## Proof of Concept

The vulnerability lies in the `pause()` function of the Timelock contract, where the contract is designed to be paused by the `pauseGuardian`. The issue arises because the `pause()` function contains a loop over all active proposals in `_liveProposals`. Each proposal requires gas to be canceled and removed from the set of active proposals. When the number of active proposals exceeds 9302, the gas required to execute the `pause()` function exceeds the block gas limit (30 million gas units), causing the transaction to fail due to out-of-gas errors.

Here’s a simplified explanation of the code involved:

- The `pause()` function begins by calling `super.pause()`, which ensures only the `pauseGuardian` can execute the function and marks the contract as paused.
- It then iterates over the `_liveProposals` set, deleting timestamps and removing each proposal one by one.
- If there are more than 9302 proposals, this process will consume more than the available block gas, resulting in a denial of service (DoS), as the `pause()` function will not be able to complete execution. As a result, the contract cannot be paused when it becomes necessary, potentially exposing it to further risks.

```solidity
function pause() public override {
    /// check that msg.sender is the pause guardian, pause the contract
    super.pause();

    bytes32[] memory proposals = _liveProposals.values();
    for (uint256 i = 0; i < proposals.length; i++) {
        bytes32 id = proposals[i];

        delete timestamps[id];
        assert(_liveProposals.remove(id));

        emit Cancelled(id);
    }
}
```

The following test demonstrates the DoS condition when there are more than 9302 proposals.

To execute it, on the `\test\unit\Timelock.t.sol` file: 
1. add `import {console} from "forge-std/console.sol";` at the beggining of the file.
2. add the following function
```solidity
function testPausePOC() public {
    uint256 newDelay = MINIMUM_DELAY + 3 days;
    uint256 size = 9303;

    for (uint256 i = 0; i < size; i++) {
        _schedule({
            caller: address(safe),
            timelock: address(timelock),
            target: address(timelock),
            value: 0,
            data: abi.encodeWithSelector(timelock.updateDelay.selector, newDelay),
            salt: bytes32(abi.encode(i)),
            delay: MINIMUM_DELAY
        });
    }

    vm.prank(guardian);

    uint256 gasBefore = gasleft();
    timelock.pause();

    uint256 gas = gasBefore - gasleft();
    console.log(gas);

    assertTrue(timelock.paused(), "timelock should be paused");
}
```

When this test is executed using the command `forge test --match-test testPausePOC -vvv`, the output shows that the transaction consumes 30,001,690 gas, exceeding the block gas limit:

```
Logs:
  30001690
```

This demonstrates that the `pause()` function will fail if there are more than 9302 proposals, resulting in a denial of service as the contract cannot be paused.

## Impact
This vulnerability is not critical but poses a potential risk in scenarios where an unexpectedly high number of proposals (9303 or more) are active. While the occurrence of such a situation is unlikely, it could happens in some specific usage of the protocol and lead to a situation where it breaks one of the smart contract functionality.

## Recommended Mitigation Steps

Implement a maximum limit on the number of proposals that can be active at one time to ensure the `pause()` function always stays within gas limits.
