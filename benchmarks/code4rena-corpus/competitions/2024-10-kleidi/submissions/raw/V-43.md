# Vulnerability details

## Proof of Concept
In the [`createSystemInstance()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/InstanceDeployer.sol#L139-L404) function, there are no validations performed on key parameters from the `instance` object. This stands in contrast to other parts of the protocol, where similar parameters undergo strict validation checks. Specifically:

`owners` parameter is not validated in this function, but it is strictly checked in other parts of the protocol as done in [`_paramChecks()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/RecoverySpellFactory.sol#L124-L137):
```solidity
    for (uint256 i = 0; i < owners.length; i++) {
        require(owners[i] != address(0), "RecoverySpell: Owner cannot be 0");
    }
```

## Impact
The lack of validation on these parameters introduces potential vulnerabilities:
- The absence of checks on `owner addresses` could allow the inclusion of the `zero address`, which could disrupt the normal operation of owner-based security mechanisms.

## Recommended Mitigation Steps
The following validation checks should be added to `createSystemInstance()`:
```diff
+   for (uint256 i = 0; i < instance.owners.length; i++) {
+       require(
+           instance.owners[i] != address(0),
+           "InstanceDeployer: Owner cannot be 0"
+       );
+   }
```
