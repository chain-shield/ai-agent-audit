# Vulnerability details

## Proof of Concept

Currently, recovery spells are used for safety of the wallet users. If the current owner of the Gnosis safe is compromised, recovery spells can be used for swapping the owners with the new owners.

But the current system design still takes some risks because it allows to deploy a recovery spell with 1 owner. If the that recovery owner is compromised then attacker can take the control of the Gnosis safe immediately in this situation

```solidity
    function _paramChecks(
        address[] memory owners,
        uint256 threshold,
        uint256 recoveryThreshold,
        uint256 delay
    ) private pure {
        require(
            threshold <= owners.length,
            "RecoverySpell: Threshold must be lte number of owners"
        );
        require(
            recoveryThreshold <= owners.length,
            "RecoverySpell: Recovery threshold must be lte number of owners"
        );

        require(threshold != 0, "RecoverySpell: Threshold must be gt 0");
        require(delay <= 365 days, "RecoverySpell: Delay must be lte a year");
        for (uint256 i = 0; i < owners.length; i++) {
            require(owners[i] != address(0), "RecoverySpell: Owner cannot be 0");
        }
    }
```

Using only 1 owner and allowing the value 1 as threshold is not safe for the wallet owners. After compromising, the attacker will be the new owner of the Gnosis safe and he can stole the tokens and ETH from the wallet.

## Recommended Mitigation Steps

The threshold for recovery spell should be 2 at least in order to reduce the risk. Maybe 1 owner can be compromised but the possibility of compromising of the both 2 owners is significantly low.
