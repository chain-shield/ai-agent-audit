# Vulnerability details

## Vulnerability Details
The `checkCalldata()` function allows the registration of wildcard entries (with `startIndex == endIndex`) that cause the function to return early, bypassing further calldata checks. This is problematic because:

Multiple entries can exist for a single function selector.
If a wildcard entry is placed before more restrictive checks, it results in the function exiting early, skipping the stricter validations.
This creates an attack vector where malicious actors can register a wildcard entry to bypass all remaining checks and execute unauthorized operations.

Affected Code Snippet
```solidity
function checkCalldata(address contractAddress, bytes memory data) public view {
    bytes4 selector = data.getFunctionSignature();
    Index[] storage calldataChecks = _calldataList[contractAddress][selector];

    require(calldataChecks.length > 0, "CalldataList: No calldata checks found");

    for (uint256 i = 0; i < calldataChecks.length; i++) {
        Index storage calldataCheck = calldataChecks[i];

        // Early exit on wildcard entry
        if (calldataCheck.startIndex == calldataCheck.endIndex) {
            return;  // Wildcard detected, skipping further checks
        }

        require(
            calldataCheck.dataHashes.contains(
                data.getSlicedBytesHash(
                    calldataCheck.startIndex, calldataCheck.endIndex
                )
            ),
            "CalldataList: Calldata does not match expected value"
        );
    }
}
```

## Proof of Concept
Scenario: Exploiting the Wildcard Entry
Register a wildcard entry:
```
_addCalldataCheck(
    targetContractAddress, 
    targetFunctionSelector, 
    4, 
    4,  // Wildcard (startIndex == endIndex)
    []
);
```
Register stricter checks:
```
_addCalldataCheck(
    targetContractAddress, 
    targetFunctionSelector, 
    10, 
    20, 
    [validCalldataHash]
);
```
Execute a call with malicious calldata:
```
bytes memory maliciousCalldata = abi.encodeWithSelector(targetFunctionSelector, ...);
timelock.checkCalldata(targetContractAddress, maliciousCalldata);
```
Result:
The function exits early on detecting the wildcard entry, skipping stricter validations that would have rejected the malicious calldata. This allows the unauthorized execution of operations

## Recommended Mitigation Steps
Remove the Early Return Logic:
Modify the loop to continue evaluating all entries, even when encountering a wildcard entry. This ensures that all checks are performed and stricter validations are not skipped.

Updated code:
```
for (uint256 i = 0; i < calldataChecks.length; i++) {
    Index storage calldataCheck = calldataChecks[i];

    // Skip the wildcard, but continue the loop
    if (calldataCheck.startIndex == calldataCheck.endIndex) {
        continue;  // Just skip this entry instead of returning early
    }

    require(
        calldataCheck.dataHashes.contains(
            data.getSlicedBytesHash(
                calldataCheck.startIndex, calldataCheck.endIndex
            )
        ),
        "CalldataList: Calldata does not match expected value"
    );
}
```
