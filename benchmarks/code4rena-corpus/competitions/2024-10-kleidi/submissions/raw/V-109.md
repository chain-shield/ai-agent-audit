# Vulnerability details


## Impact

Executing a recovery on `zkSync` or Avalanche's `C-Chain` would be impossible due to the lack of support for the `tload` and `tstore` opcodes, which is used in functions like [executeRecovery](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/RecoverySpell.sol#L165). Without these opcodes being supported on these chains, executing recovery operations would fail, rendering the function ineffective on these platforms.

## Description

According to the [README](https://github.com/code-423n4/2024-10-kleidi#:~:text=The%20system%20only%20works%20on%20EVM%20compatible%20chains%2C%20does%20not%20work%20on%20chains%20that%20have%20not%20undergone%20the%20Shanghai%20EVM%20upgrade), the wallet is designed to be compatible with all EVM-compatible chains:



> - The system only works on EVM compatible chains, does not work on chains that have not undergone the Shanghai EVM upgrade

However, the use of specific opcodes like `tload` and `tstore` makes it almost impossible for the wallet to function on certain EVM-compatible chains, such as `zkSync` and Avalanche's `C-Chain`, as these chains do not yet support these opcodes.

for `zkSync` refer to [https://www.rollup.codes/zksync-era#opcodes](https://www.rollup.codes/zksync-era#opcodes) 

here's also an example of a failed transaction on avalanche : [https://snowscan.xyz/tx/0x9ed251fa0d64868a635bf8a0d0273600773bebc819e6987b0220f99acf499b18](https://snowscan.xyz/tx/0x9ed251fa0d64868a635bf8a0d0273600773bebc819e6987b0220f99acf499b18)

This issue could present challenges for certain functions, particularly the [executeRecovery](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/RecoverySpell.sol#L165), where these `opcodes` are employed.
