# Vulnerability details

## Proof of Concept
Description: The deploy() function is permissionless, allowing anyone to deploy the contracts. There’s no access control or restriction preventing malicious actors from executing the deployment.

Risk:
-Malicious Deployments: An attacker could trigger a deployment with malicious intentions, such as misconfiguring addresses, deploying fake or malicious contracts, or rerouting funds.
-Denial of Service (DoS): Attackers could spam deployments, causing excessive resource consumption, leading to a denial of service.
Impact: Malicious actors could misconfigure the system, potentially hijacking governance, stealing funds, or rendering the system unusable.

## Recommended Mitigation Steps
1.Restrict access to the deployment function to authorized roles only (e.g., using Ownable or AccessControl), preventing unauthorized actors from deploying contracts.
for example:
import "@openzeppelin/contracts/access/Ownable.sol";

contract SystemDeploy is MultisigProposal, Ownable {
    function deploy() public override onlyOwner {
        ...
    }
}

2.Multisig Approvals: Another layer of security could involve using a multisig wallet for approvals of key deployment actions, especially for governance-critical contracts.
