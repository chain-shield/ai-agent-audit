# Vulnerability details

## Proof of Concept
The RecoverySpellFactory.sol contract uses transient storage (tstore and tload) in assembly to check for duplicate owners during the creation of new RecoverySpell contracts. This approach can be prone to logic errors or improper state handling, allowing the same owner to be added multiple times. If duplicate owners are allowed, it effectively reduces the security threshold, allowing one user to control multiple "owners" in the Safe's recovery process.
The intended security model requires multiple unique owners to sign off on recovery actions, but this check can be bypassed if an attacker submits the same owner address multiple times.

```
for (uint256 i = 0; i < owners.length; i++) {
    address owner = owners[i];
    bool found;

    assembly ("memory-safe") {
        found := tload(owner)
        if eq(found, 0) { tstore(owner, 1) }
    }

    require(!found, "RecoverySpell: Duplicate owner");
}
```


An attacker can deploy a RecoverySpell contract where the same owner is listed multiple times in the owners array. This will allow the attacker to bypass the requirement for multiple unique owners during the recovery process, gaining control of the Safe with fewer independent signatures than expected.

Steps to Reproduce:
Deploy the RecoverySpellFactory.sol contract.
Call createRecoverySpell() with an array of owners that includes the same owner address multiple times.
Observe that the contract allows the creation of a recovery spell even though duplicate owners are present, bypassing the multi-owner security check.

PoC
```
pragma solidity ^0.8.25;

import "./RecoverySpellFactory.sol";

contract TestDuplicateOwnersAttack {
    RecoverySpellFactory recoverySpellFactory;

    constructor(address _recoverySpellFactory) {
        recoverySpellFactory = RecoverySpellFactory(_recoverySpellFactory);
    }

    function createWithDuplicateOwners(
        bytes32 salt,
        address owner,  // Same owner used multiple times
        address safe,
        uint256 threshold,
        uint256 recoveryThreshold,
        uint256 delay
    ) external {
        address[] memory owners = new address[](3);
        owners[0] = owner;
        owners[1] = owner;  // Duplicate owner
        owners[2] = owner;  // Duplicate owner

        // Attempt to create a recovery spell with duplicate owners
        recoverySpellFactory.createRecoverySpell(salt, owners, safe, threshold, recoveryThreshold, delay);
    }
}
```

Observed Behavior: The recovery spell is created with the same owner address repeated multiple times, bypassing the requirement for multiple unique owners.
Correct Behavior: The contract should reject recovery spells where the same owner address is used more than once.

Exploit Impact
Security Bypass: By submitting duplicate owners, an attacker can lower the security threshold and gain control of the Safe with fewer unique signatures than required.
Ownership Takeover: This could allow an attacker to perform unauthorized recovery processes and gain full control of the Safe.



## Recommended Mitigation Steps
Implement a memory-based owner validation mechanism that ensures no duplicate owners are allowed in the owners array. Avoid using assembly for this, as it increases complexity and the potential for bugs.

```
mapping(address => bool) ownerExists;

for (uint256 i = 0; i < owners.length; i++) {
    require(!ownerExists[owners[i]], "RecoverySpell: Duplicate owner");
    ownerExists[owners[i]] = true;
}
```
