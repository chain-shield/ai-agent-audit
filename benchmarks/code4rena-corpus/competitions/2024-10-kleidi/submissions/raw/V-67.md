# Vulnerability details

### Overview

The `onlyTimelock` modifier in the contract is improperly implemented, preventing external calls to functions like `addCalldataChecks()` and `removeCalldataCheck()`. Additionally, these functions are not invoked anywhere in the project, making them effectively unreachable.

### Issue Description

1. **Incorrect `onlyTimelock` Modifier**:
The current modifier checks if `msg.sender` is `address(this)`, restricting function calls to the contract itself. This prevents any external timelock contract from triggering functions, contrary to the expected use case.
2. **Unreachable Functions**:
Functions such as `addCalldataChecks()` and `removeCalldataCheck()` are defined but are never called within the project, leading to dead code.

### Impact

- **Dead Code**: These unused functions take up storage and gas but are never executed.
- **Failed Timelock Operations**: The timelock contract cannot trigger restricted functions, leading to incomplete functionality.

### Recommendations

1. **Fix the `onlyTimelock` Modifier**:
Update the modifier to check against a stored `timelock` address:
    
    ```solidity
    address public timelock;
    
    modifier onlyTimelock() {
        require(msg.sender == timelock, "Timelock: caller is not the timelock");
        _;
    }
    
    ```
    
2. **Add Invocation Points**:
Ensure `addCalldataChecks()` and `removeCalldataCheck()` are called where necessary or remove them if not needed.
