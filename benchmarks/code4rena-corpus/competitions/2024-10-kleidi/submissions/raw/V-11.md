# Vulnerability details

## Summary
The `execute()` and `executeBatch()` functions lack proper validation of `msg.value` (the ether sent with the transaction). This can result in failure to refund excess ether when too much is sent.

1. No Refund for Excess Ether:
When more ether is sent than necessary (`msg.value > value` or `msg.value > sum(values) in the batch`), the excess remains in the contract without being refunded to the caller.


## Recommended Mitigation Steps
1. Add Refund Logic for Excess Ether: If the ether sent exceeds the required amount, implement logic to refund the excess ether back to the sender.

For `execute()`:
```diff
    // Ensure that msg.value matches the value being transferred
+   require(msg.value >= value, "Insufficient msg.value");

    _execute(target, value, payload);

    // Refund any excess msg.value
+   if (msg.value > value) {
+       payable(msg.sender).transfer(msg.value - value);
+   }
```

For `executeBatch()`:
```diff
    // Ensure that msg.value matches the total value being transferred
+   require(msg.value >= totalValue, "Insufficient msg.value");

    for (uint256 i = 0; i < targets.length; i++) {
        bytes calldata payload = payloads[i];

        _execute(targets[i], values[i], payload);
        emit CallExecuted(id, i, targets[i], values[i], payload);
    }

    // Refund any excess msg.value
+   if (msg.value > totalValue) {
+       payable(msg.sender).transfer(msg.value - totalValue);
+   }
```
