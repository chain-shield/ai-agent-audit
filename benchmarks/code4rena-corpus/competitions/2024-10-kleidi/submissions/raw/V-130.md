# Vulnerability details

## Proof of Concept
The [`_execute`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1021-L1026) function is responsible for executing transactions by making a low-level call to a target contract.This function includes the option to send Ether (`value`) as part of the execution. However, the function is not marked as `payable`, which leads to an issue when attempting to send Ether along with the transaction.
```solidity
    function _execute(address target, uint256 value, bytes calldata data)
        private
    {
        (bool success,) = target.call{value: value}(data);
        require(success, "Timelock: underlying transaction reverted");
    }
```
The line `(bool success,) = target.call{value: value}(data)`; is used to send Ether to the target contract. However, since the `_execute` function is not marked as payable, it cannot send Ether. The lack of the `payable` modifier causes the function to revert if the `value` parameter is non-zero (i.e., if Ether is involved in the transaction).

## Recommended Mitigation Steps
The `_execute` function should be declared as payable to allow it to send Ether to the target contract when needed. This change ensures that the function can handle both regular calls and calls that transfer Ether
```diff
    function _execute(address target, uint256 value, bytes calldata data)
        private
+       payable
    {
        (bool success,) = target.call{value: value}(data);
        require(success, "Timelock: underlying transaction reverted");
    }
```
