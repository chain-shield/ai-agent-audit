# Vulnerability details

## Proof of Concept

For context, the below code snippet contains a delegatecall injection in RecoverySpell.sol:

```solidity
require(
            safe.execTransactionFromModule(
                MULTICALL3,
                0,
                abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3),
                Enum.Operation.DelegateCall
            ),
            "RecoverySpell: Recovery failed"
        );
```

The code snippet demonstrates a potential Delegatecall Injection vulnerability. 

Specifically, the `safe.execTransactionFromModule` function is used to execute a transaction delegating execution to the `MULTICALL3` contract.  The `abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3)` part constructs the call data for the `aggregate3` function of the `MULTICALL3` contract. An attacker can manipulate the `calls3` array to include malicious delegate calls that execute arbitrary code within the context of the `safe` contract. 

The `safe.execTransactionFromModule` function, when used with `DelegateCall`, allows an attacker to control the target of the delegate call through manipulation of the `calls3` array. This enables arbitrary code execution within the context of the `safe` contract.

## Recommended Mitigation Steps

How to mitigate this vulnerability

-->. VALIDATE the calls3 array entries.

The most important step is to introduce input validation for the calls3 array to ensure that only trusted contracts and calls are being processed. This will prevent arbitrary delegate calls from being made.

Here's an example of how to do this, although there are several ways to do it. 

```solidity

function validateCalls(IMulticall3.Call3[] memory calls3) internal view {
    for (uint256 i = 0; i < calls3.length; i++) {
        // check if target address is a trusted contract
        require(isTrustedContract(calls3[i].target), "Invalid target address");
        
        // or devs can also validate the call data if specific function selectors are allowed
        require(isAllowedFunction(calls3[i].callData), "Invalid function call");
    }
}
//whitelist trusted contracts

mapping(address => bool) private trustedContracts;

function isTrustedContract(address target) internal view returns (bool) {
    return trustedContracts[target];
}

function isAllowedFunction(bytes memory callData) internal pure returns (bool) {
    bytes4 functionSelector;
    assembly {
        functionSelector := mload(add(callData, 32)) 
    }

    // explicitly stating allowed function selectors
    return functionSelector == GnosisSafe.transferOwnership.selector || 
           functionSelector == SomeOtherAllowedFunction.selector;
}

```

--> implement access control of who can initiate calls 

Another KEY improvement is to ensure only authorized entities can propose recovery operations or interact with critical functions such as those involving the calls3 array.

Require devs to implement role-based access control (RBAC) to restrict access to functions that involve delegate calls, particularly to avoid unauthorized proposals of recovery operations.

Here's one way to do it: 

```solidity

import "@openzeppelin/contracts/access/AccessControl.sol";

contract RecoverySpell is AccessControl {
    bytes32 public constant RECOVERY_ROLE = keccak256("RECOVERY_ROLE");

    constructor() {
        _setupRole(DEFAULT_ADMIN_ROLE, msg.sender);
        _setupRole(RECOVERY_ROLE, msg.sender);  // Admin has recovery role initially
    }

    // limit execution of critical operations to users with RECOVERY_ROLE
    function executeRecovery(IMulticall3.Call3[] memory calls3) external onlyRole(RECOVERY_ROLE) {
        validateCalls(calls3);
        require(
            safe.execTransactionFromModule(
                MULTICALL3,
                0,
                abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3),
                Enum.Operation.DelegateCall
            ),
            "RecoverySpell: Recovery failed"
        );
    }
}
```

--> REALLY LIMIT DELEGATECALL usage in the code.  Replace delegatecall with standard external calls (Enum.Operation.Call) wherever possible, especially for non-critical or non-upgradeable code paths. Delegatecall gives the target contract the ability to execute within the calling contract's context, which should be avoided unless Absolutely necessary.

--> last suggestion is to use multi signature approval for these kind of sensitive operations. 

Require approval from multiple trusted signers (in line with Gnosis Safe's multisig philosophy)
