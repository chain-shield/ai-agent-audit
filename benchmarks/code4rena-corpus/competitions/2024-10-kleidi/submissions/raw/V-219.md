# Vulnerability details

## **Summary: The Security Mindset of Kleidi**

The **Kleidi** team has built the project with security as a top priority, ensuring robust mechanisms to safeguard users and assets across the platform. The architecture reflects a thoughtful approach where user interactions with external protocols are carefully constrained, emphasizing protection. One of the ways Kleidi demonstrates this is through its whitelisting of contracts, where only approved contract addresses, function selectors, and associated calldata are allowed. These restrictions are vital in maintaining security, as they limit the scope for unauthorized or malicious interactions.

However, despite this careful design, one area for optimization lies in how low-level external calls are handled in the protocol’s codebase. Specifically, the `_execute` function in the **Timelock** contract employs a standard Solidity `call`, which opens the door for gas griefing or theft if malicious external contracts are involved.

## Proof of Concept

The vulnerability arises in the `_execute` function of the **Timelock** contract, which is responsible for executing operations by calling external contracts. Here's the code in question:

```solidity
    function _execute(address target, uint256 value, bytes calldata data) private {
@>      (bool success,) = target.call{value: value}(data); // @audit-issue Gas grieding/theft is possible on unsafe external call.
        require(success, "Timelock: underlying transaction reverted");
    }
```

This call to an external contract sends a specified value along with the provided calldata but doesn’t safeguard against malicious payloads. A malicious contract could exploit this by returning an extremely large amount of data, causing significant memory allocation on the Kleidi contract’s side. Since memory allocation can be expensive, especially with large payloads, this opens up the risk of gas griefing.

For example, if the external contract’s fallback function returns a huge payload, the user initiating the transaction might pay a significant amount in gas fees, which would be unfairly high compared to the intended operation.

### NOTE 
There is no doubt that the Kleidi team has done a very hard job in making the protocol as safe as possible. Even though interactions with external protocols currently happen with whitelisting mechanisms, we cannot ensure that at some point these protocols won't be compromised in a manner that could harm Kleidi users. However, we can do something else to further show that Kleidi really takes security seriously. We can reduce the possibility of this issue occurring by implementing external calls as safely as possible. Thus, it does not matter whether external protocols will be compromised or not - control will remain with Kleidi, and its users will be safe!

## Impact

The impact of this issue is that an attacker could deliberately induce high gas consumption through a griefing attack. By making a seemingly legitimate external call that returns a large payload, the attacker forces the users to absorb the cost of memory allocation for this large response.

If exploited, this would lead to increased operational costs (fund loss for users) and decreased trust in the system (potential fund and reputation loss for the protocol).

## Recommended Mitigation Steps

To protect against this potential attack, the Kleidi team should switch to using a low-level `assembly`-based `call` for external operations. This approach prevents any return data from being automatically copied into memory, thereby mitigating the gas griefing issue.

Additionally, to ensure that legitimate external calls can still process return data, we recommend allowing for a certain length of return data but enforcing a strict upper limit. This allows the function to handle normal-sized responses while preventing malicious contracts from returning excessively large amounts of data to exhaust gas.

### Revised `_execute` Function:

```solidity
function _execute(address target, uint256 value, bytes calldata data) private {
    bool success;
    uint256 returnDataSize;

    assembly {
        // Perform the external call
        success := call(gas(), target, value, add(data, 0x20), mload(data), 0, 0)

        // Retrieve the size of the returned data
        returnDataSize := returndatasize()

        // Copy the return data only if it's within the allowed size
        if and(gt(returnDataSize, 0), lt(returnDataSize, maxReturnSize)) { // @audit The maxReturnSize must be set by the Kleidi team after they decide what the maximum amount of data they will allow to be returned.
            returndatacopy(0, 0, returnDataSize)
        }
    }

    require(success, "Timelock: underlying transaction reverted");
}
```
