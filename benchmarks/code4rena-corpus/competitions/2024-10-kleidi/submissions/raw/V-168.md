# Vulnerability details

## Proof of Concept
 in the contract ConfigurablePause.sol;
- `function _updatePauseDuration` grants access control to only timelock
- If called to update pause period when the contract was previously paused, the contract will be temporarily unpaused at line ` _setPauseTime(0);`. 
-of note is also that the present pauseGuardian may not have been changed or be equal to address(0) depending on the situation. 

  https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/ConfigurablePause.sol#L113

 implications
 - a malicious actor can write contracts to exploit this brief unpaused period.
 - a malicious pause guardian can re-enter the unpaused period to exploit as he gains access control during the unpaused period

mitigation
if `_setPauseTime(block.timestamp)` is used to return the current time, there would still be an unpausing and re-pausing, it could still introduce a tiny window for a function call by an attacker .

1.  a safer option would be to update the duration to set the pause end time instead of `pauseStartTime`. this way, timelock can set `_setEndTime(0)` to teminate pausing immediately or extend the end time if it needs to be increased, so as not to temporarily create an entrance for an attacker.

2.  call the `_grantGuardian` in the `function _updatePauseDuration` so that a malicious guardian does not have any likely access
