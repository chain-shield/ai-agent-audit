# Vulnerability details

## Proof of Concept
In the [`InstanceDeployer`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/InstanceDeployer.sol#L335-L380) contract, a signature is crafted using inline assembly to authorize transactions on the Safe. The signature is constructed as follows:

```solidity
        bytes memory signature;
        /// craft the signature singing off on all of the multicall
        /// operations
        {
>           bytes32 r = bytes32(uint256(uint160(address(this))));
>           uint8 v = 1;


            assembly ("memory-safe") {
                /// Load free memory location
                let ptr := mload(0x40)


                /// We allocate memory for the return data by setting the free memory location to
                /// current free memory location + data size + 32 bytes for data size value


                ///         4 -> 82
                mstore(0x40, add(ptr, 97))
                ///         4 -> 179


                /// Store the size of the signature in the first 32 bytes:
                /// 65 (r + s + v)
                mstore(ptr, 65)


                ///
                ///                              Data Offsets
                ///
                ///                 --------------------------------------
                ///  bytes length   |      32     |   32  |  32   |   1  |
                ///                 --------------------------------------
                ///      bytes      |     0-31    | 32-63 | 64-95 |  96  |
                ///                 --------------------------------------
                ///      data       | length = 65 |   r   |   s   |   v  |
                ///                 --------------------------------------
                ///


                /// store r at offset 32 to 64 in the allocated pointer
                mstore(add(ptr, 0x20), r)


                /// no need to store s, this should be 0 bytes


                /// store v at offset 96 to 97 in the allocated pointer
                mstore8(add(ptr, 0x60), v)


                /// Point the signature data to the correct memory location
                signature := ptr
            }
        }
```
`r`: Set to the address of the InstanceDeployer contract.
`s`: Implicitly set to 0.
`v`: Set to 1.

This signature format deviates from the standard ECDSA signature format, which typically requires:
`r` and `s` to be derived from a valid cryptographic signing process.
`v` to be either 27 or 28 to indicate the recovery ID.
The crafted signature is used in the `execTransaction` function call on the Safe, which expects a valid signature for transaction authorization.

## Recommended Mitigation Steps
To ensure compatibility and security, it is recommended to use a standard ECDSA signature format
