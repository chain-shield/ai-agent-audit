# Vulnerability details

## Proof of Concept
The [`_removeCalldataCheck`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1219-L1231) function in the Timelock contract contains a logical flaw when removing elements from the `calldataChecks` array. The current implementation attempts to swap the element to be removed with the last element of the array, even when the element to be removed is already the last element.
```
    function _removeCalldataCheck(
        address contractAddress,
        bytes4 selector,
        uint256 index
    ) private {
        Index[] storage calldataChecks =
            _calldataList[contractAddress][selector];

        //...SNIP ...

        if (calldataChecks.length > 1) {
            /// index check to overwrite the specified index check with
            Index storage lastIndexCheck =
                calldataChecks[calldataChecks.length - 1];

            indexCheck.startIndex = lastIndexCheck.startIndex;
            indexCheck.endIndex = lastIndexCheck.endIndex;
            bytes32[] memory dataHashes = lastIndexCheck.dataHashes.values();

            for (uint256 i = 0; i < dataHashes.length; i++) {
>>              assert(indexCheck.dataHashes.add(dataHashes[i]));
                assert(lastIndexCheck.dataHashes.remove(dataHashes[i]));
            }
        }

        calldataChecks.pop();

        emit CalldataRemoved(
            contractAddress,
            selector,
            removedStartIndex,
            removedEndIndex,
            removedDataHashes
        );
    }

```
This implementation leads to the following issues when removing the last element:
1. Unnecessary data copying from the last element to itself.
2. Attempted addition of already existing hashes, which will fail the `assert` check.
3. Unnecessary removal of hashes from the element being removed.
4. Potential double removal of the last element.
These issues can result in transaction failures, unnecessary gas consumption, and potential data corruption.

## Recommended Mitigation Steps
To address this issue, modify the function to only perform the swap operation when the index to be removed is not the last index in the array
