Issue: Missing Access Control on createTimelock Function

Severity: High
Issue Type: Missing Access Control

Impact

The createTimelock function in the TimelockFactory contract lacks proper access control mechanisms. This omission allows any external account to invoke the function and deploy new Timelock contracts arbitrarily. Potential risks include:

	•	Unauthorized Deployments: Malicious actors can deploy multiple Timelock contracts, leading to resource exhaustion.
	•	Resource Drain: Excessive deployments can strain network resources and potentially increase gas costs for legitimate users.
	•	Reputation Risk: Unauthorized deployments may be used for malicious purposes, tarnishing the project’s reputation.

Location

	•	File: TimelockFactory.sol
	•	Function: createTimelock
	•	Lines: 37-55

Proof of Concept (PoC)

An attacker can deploy a malicious Timelock by calling the createTimelock function without any restrictions:

## Recommended Mitigation Steps

Implement robust access control to restrict who can invoke the createTimelock function. One common approach is to use the Ownable pattern, ensuring that only the contract owner can deploy new Timelock instances.

Updated TimelockFactory Contract with Access Control:

```Solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.25;

import {Timelock} from "src/Timelock.sol";
import {calculateCreate2Address} from "src/utils/Create2Helper.sol";
import "@openzeppelin/contracts/access/Ownable.sol";

struct DeploymentParams {
    uint256 minDelay;
    uint256 expirationPeriod;
    address pauser;
    uint128 pauseDuration;
    address[] hotSigners;
    address[] contractAddresses;
    bytes4[] selectors;
    uint16[] startIndexes;
    uint16[] endIndexes;
    bytes[][] datas;
    bytes32 salt;
}

/// @notice simple factory contract that creates timelocks
contract TimelockFactory is Ownable {
    /// ---------------------------------------------------------
    /// ------------------------- EVENT -------------------------
    /// ---------------------------------------------------------

    /// @notice Emitted when a call is scheduled as part of operation `id`.
    /// @param timelock address of the newly created timelock
    /// @param creationTime of the new timelock
    /// @param sender that called the contract to create the timelock
    event TimelockCreated(
        address indexed timelock, uint256 creationTime, address indexed sender
    );

    /// @notice Creates a timelock for a given safe and deployment parameters
    /// @dev Restricted to contract owner
    function createTimelock(address safe, DeploymentParams memory params)
        external
        onlyOwner
        returns (address timelock)
    {
        timelock = address(
            new Timelock{
                salt: keccak256(abi.encodePacked(params.salt, msg.sender))
            }(
                safe,
                params.minDelay,
                params.expirationPeriod,
                params.pauser,
                params.pauseDuration,
                params.hotSigners
            )
        );

        emit TimelockCreated(timelock, block.timestamp, msg.sender);
    }

    function timelockCreationCode() external pure returns (bytes memory) {
        return type(Timelock).creationCode;
    }
}
```

Key Changes:

	1.	Inheritance from Ownable:
The TimelockFactory now inherits from OpenZeppelin’s Ownable contract, providing ownership management functionalities.
	2.	Access Restriction:
The createTimelock function is modified with the onlyOwner modifier, ensuring that only the contract owner can deploy new Timelock instances.
