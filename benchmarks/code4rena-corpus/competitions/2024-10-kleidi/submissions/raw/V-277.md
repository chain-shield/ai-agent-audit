# Vulnerability details

## Description
The RecoverySpell contract uses transient storage (`tstore`/`tload`) to track valid signers during signature verification. The contract assumes storage values of 0 indicate invalid/used signatures. However, this creates a vulnerability due to how EOA (Externally Owned Account) self-destruct and contract deployment work in Ethereum.

The signature verification logic:
```solidity
for (uint256 i = 0; i < owners.length; i++) {
    address owner = owners[i];
    assembly ("memory-safe") {
        tstore(owner, 1)  // Mark valid signers
    }
}

for (uint256 i = 0; i < v.length; i++) {
    address recoveredAddress = ECDSA.recover(digest, v[i], r[i], s[i]);
    bool valid;
    
    assembly ("memory-safe") {
        valid := tload(recoveredAddress)
        if eq(valid, 1) { tstore(recoveredAddress, 0) }  // Mark as used
    }
    
    require(
        valid && recoveredAddress != address(0),
        "RecoverySpell: Invalid signature"
    );
}
```

The vulnerability arises because:
1. The contract uses transient storage value of 1 to mark valid signers
2. It checks `tload(address)` to verify signatures
3. A value of 0 is considered invalid/used
4. But crucially, transient storage for EOAs can be manipulated through self-destruct and redeployment

## Attack Scenario
1. Attacker identifies one of the recovery signers (address A)
2. Attacker deploys a contract to address A through CREATE2 with specific salt
3. Contract self-destructs, clearing transient storage
4. Due to deterministic addressing, attacker can redeploy to same address multiple times
5. This allows the same signature to be reused multiple times
6. Recovery threshold can be met with fewer actual signatures than required

## Impact
- Allows bypass of signature threshold requirements
- Recovery can be executed with fewer legitimate signers than intended
- Undermines core security assumptions of the recovery mechanism

## Fix
There are several potential fixes:

1. Use permanent storage instead of transient storage:
```solidity
mapping(address => bool) private validSigners;
mapping(address => bool) private usedSignatures;

// In signature verification:
validSigners[owner] = true;
...
require(validSigners[recoveredAddress] && !usedSignatures[recoveredAddress]);
usedSignatures[recoveredAddress] = true;
```

2. Add nonce tracking:
```solidity
mapping(address => uint256) public signerNonces;

function getDigest() public view returns (bytes32) {
    return keccak256(
        abi.encodePacked(
            "\x19\x01",
            _domainSeparatorV4(),
            keccak256(
                abi.encode(
                    RECOVERY_TYPEHASH,
                    safe,
                    threshold,
                    recoveryThreshold,
                    delay,
                    signerNonces[msg.sender]  // Add nonce
                )
            )
        )
    );
}
```

3. Store recovered addresses in array and check for duplicates:
```solidity
address[] memory recoveredAddresses = new address[](v.length);
for(uint i = 0; i < v.length; i++) {
    address recovered = ECDSA.recover(digest, v[i], r[i], s[i]);
    // Check for duplicates
    for(uint j = 0; j < i; j++) {
        require(recoveredAddresses[j] != recovered, "Duplicate signature");
    }
    recoveredAddresses[i] = recovered;
    require(isOwner[recovered], "Not an owner");
}
```

The recommended fix is option 1 as it:
- Is most gas efficient
- Maintains clear state tracking
- Is resistant to replay attacks
- Doesn't rely on memory arrays
