# Vulnerability details

## Proof of Concept

The function `_execute` executes arbitrary code and does not handle the possibility of a re-entrancy attack. It interacts with arbitrary contracts by calling an external function in an unsafe way.

```solidity
function _execute(address target, uint256 value, bytes calldata data) private {
    (bool success,) = target.call{value: value}(data);
    require(success, "Timelock: underlying transaction reverted");
}
```

The function allows sending value and data to an arbitrary contract specified by `target`. 
The contract does not guard against re-entrance attacks. 

## Recommended Mitigation Steps

External calls can be a security risk and should be handled carefully. They can potentially execute untrusted contract code. 

Re-entrancy attacks can be prevented by making sure that all changes to the contract's state variables are finalized before calling an external function.  

Consider using the 'Checks-Effects-Interactions' pattern: 

```solidity
function _execute(address target, uint256 value, bytes calldata data) private {
   // Checks
   require(value <= address(this).balance, "Not enough balance");

   // Effects
   balances[msg.sender] -= value;

   // Interactions
   (bool success,) = target.call{value: value}(data);
   require(success, "Timelock: underlying transaction reverted");
}
```
