# Vulnerability details


## Vulnerability details

The `removeCalldataCheckDatahash` function in the Timelock contract can inadvertently remove a wildcard check when attempting to remove a specific data hash. This occurs because the function doesn't distinguish between wildcard checks (where `startIndex == endIndex == 4`) and specific checks.

When a wildcard check is added with an empty data array (as required by the contract), attempting to remove a specific data hash will succeed in removing the entire wildcard check. This is because the keccak256 hash of an empty byte array is treated as a valid data hash to remove.

This vulnerability could lead to unintended removal of wildcard checks, potentially allowing unauthorized transactions to be executed if an attacker can manipulate the removal process.

```solidity
contract TimelockWildcardRemovalTest is Test {

    MockSafe public safe;

        console.log("Timelock deployed at:", address(timelock));

        console.log("Timelock initialized");

        console.log("Starting testWildcardRemoval");

        bytes[] memory data = new bytes[](0); // Empty array for wildcard check

        console.logBytes4(EXAMPLE_SELECTOR);
        console.log("Data length:", data.length);

        vm.prank(address(timelock));
```

To run this test:

1. Save the above code in a file named `test/unit/TimelockWildcardRemoval.t.sol` in your project directory.
2. Run the test using Forge:
   ```
   forge test --match-test testWildcardRemoval -vvv
   ```

The test demonstrates that:
1. A wildcard check can be added successfully.
2. The wildcard check initially works as expected.
3. Attempting to remove a specific data hash (the hash of an empty byte array) inadvertently removes the entire wildcard check.
4. After the removal, the wildcard check no longer exists, allowing potentially unauthorized transactions.

## Recommended Mitigation Steps

1. Modify the `removeCalldataCheckDatahash` function to check if the removal target is a wildcard check:

```solidity
function removeCalldataCheckDatahash(
    address contractAddress,
    bytes4 selector,
    uint256 index,
    bytes32 dataHash
) external onlyTimelock {
    Index[] storage calldataChecks = _calldataList[contractAddress][selector];
    require(index < calldataChecks.length, "CalldataList: Calldata index out of bounds");

    Index storage indexCheck = calldataChecks[index];

    // Check if it's a wildcard check
    if (indexCheck.startIndex == indexCheck.endIndex && indexCheck.startIndex == 4) {
        revert("Cannot remove data hash from wildcard check");
    }

    require(indexCheck.dataHashes.remove(dataHash), "CalldataList: DataHash does not exist");

    // ... rest of the function remains the same
}
```

2. Implement a separate function for removing wildcard checks entirely, if that functionality is needed.

3. Add tests to ensure that wildcard checks cannot be inadvertently removed by `removeCalldataCheckDatahash`.

By implementing these changes, the contract will prevent accidental removal of wildcard checks, maintaining the intended security model for calldata validation.
