# Vulnerability details

## Proof of Concept
The [`_addCalldataCheck`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1089-L1100) function is designed to add or update calldata checks, but its current implementation may lead to inconsistent states when multiple matching indexes exist. 
The current implementation only updates the first matching index it finds when adding or updating a calldata check. If multiple indexes with the same `startIndex` and `endIndex` exist, only the first one encountered will be updated, while others are ignored.
Relevant code snippet
```solidity
    // ... SNIP ...
Index[] storage indexes = _calldataList[contractAddress][selector];
uint256 targetIndex = indexes.length;
{
    bool found;
    for (uint256 i = 0; i < indexes.length; i++) {
        if (
            indexes[i].startIndex == startIndex
                && indexes[i].endIndex == endIndex
        ) {
            targetIndex = i;
            found = true;
            break;
        }
    }
    // ... SNIP ...
}
```
Impact
1. Inconsistent State: Multiple indexes with the same start and end points could exist with different associated data.
2. Outdated Checks: Some calldata checks may remain outdated if not all matching indexes are updated.
3. Unpredictable Behavior: The contract's behavior could become unpredictable as it's unclear which check will be applied.

## Recommended Mitigation Steps
1. Remove the `break` statement and update all matching indexes found 
2. Implement a check to ensure that duplicate indexes cannot be added in the first place.
