# Vulnerability details

## Summary
The Kleidi protocol's contracts are built using Solidity version 0.8.25, which includes the BLOBBASEFEE opcode (introduced in Solidity v0.8.24). However, this opcode is currently not supported on the Arbitrum network, as shown in this [screenshot](https://ibb.co/41nZV0N). This lack of support prevents the deployment of Kleidi contracts on Arbitrum, which is the intended network for deployment as stated in the contest page's [Scoping Q&A section](https://code4rena.com/audits/2024-10-kleidi): "Chains the protocol will be deployed on: Arbitrum, Ethereum, Optimism, Base."

## Proof of Concept
The Kleidi project's smart contracts use Solidity version 0.8.25, which incorporates the BLOBBASEFEE opcode, introduced in Solidity v0.8.24 as noted [here](https://github.com/ethereum/solidity/releases/tag/v0.8.24). However, as of the time of this report, the Arbitrum chain does not support this opcode, making deployment with this Solidity version impossible. According to the C4 documentation, this would correspond to a severity level of "2 — Med: Assets not at direct risk, but the function of the protocol or its availability could be impacted." The inability to deploy on Arbitrum exactly impacts the protocol's availability and functionality on the network, so this issue is marked as Medium severity.

## Impact
The project cannot currently be deployed on the Arbitrum network.

## Recommended Mitigation Steps
Consider using a different version of Solidity for the Arbitrum network. Alternatively, if you prefer deploying with Solidity v0.8.25, you can use this [tool](https://www.evmdiff.com/features?feature=opcodes) to check if Arbitrum has added support for the BLOBBASEFEE opcode.
