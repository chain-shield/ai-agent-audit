# Vulnerability Details

## Impact

A comment in `RecoverySpellFactory.sol` [states](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/RecoverySpellFactory.sol#L25-L26) that a recovery spell with `delay = 0` can be executed immediately, but this is not true.

This could lead to unexpected reverts as a user expects that a recovery spell with `delay = 0` means that we can construct and execute the recovery in one transaction but this is not possible.


External contract logic that wants to create and execute the recovery spell in one transaction will not work.
For example:
Imagine an external contract that relies on a recovery spell with `delay = 0` to be created and executed in one transaction.

## Proof of Concept

Consider the following scenario with `delay of RecoverySpellA = 0`:

1. The cold signers get compromised.

2. RecoverySpellA gets created and executed in the same transaction to rotate signing keys, as the external contract expects this to work and does not have a backup plan.

3. The transaction will revert and the external contract logic that relies on the transaction to succeed, as the comment states, will be broken.

## Recommended Mitigation Steps

In `RecoverySpell.executeRecovery()` the following should be changed:

```diff
require(
-    block.timestamp > recoveryInitiated + delay,
    "RecoverySpell: Recovery not ready"
);

require(
+    block.timestamp >= recoveryInitiated + delay,
    "RecoverySpell: Recovery not ready"
);
```
