# Vulnerability details

## Proof of Concept
The `executeWhitelisted` function makes an external call through the `_execute` function without implementing reentrancy guards. The `_execute` function uses a **low-level call**, which can allow the called contract to execute arbitrary code, including calling back into the Timelock contract before the original execution completes.

This design allows a malicious whitelisted contract to re-enter the Timelock contract, potentially executing multiple operations or bypassing intended restrictions before the initial call completes. (( Even though "Hot signers" is trusted role, Still it gives an attack windows the Hot signers will never see coming.))

1. The `executeWhitelisted` function is called with a specific target, value, and data.
2. Inside this function, `checkCalldata` is called to verify the whitelisted calldata.
3. If the check passes, the contract executes the call to the target address using `_execute`.
4. The bug occurs because the `_execute` function allows arbitrary external calls, which could call back into the Timelock contract and modify its state.

The issue is happening because:

1. The `executeWhitelisted` function doesn't have reentrancy protection.
2. The `_execute` function makes an external call without any checks or protections against reentrancy.

The vulnerable code is the `executeWhitelisted` and `_execute` functions in the Timelock.sol contract.

[Timelock.sol:executeWhitelisted](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L715-L726)
```solidity
function executeWhitelisted(
    address target,
    uint256 value,
    bytes calldata payload
) external payable onlyRole(HOT_SIGNER_ROLE) whenNotPaused {
    /// first ensure calldata to target is whitelisted,
    /// and that parameters are not malicious
    checkCalldata(target, payload);
    _execute(target, value, payload); // <@Audit: Potential reentrancy vulnerability

    emit CallExecuted(bytes32(0), 0, target, value, payload);
}
```
[Timelock.sol:_execute](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1021-L1026)
```solidity
function _execute(address target, uint256 value, bytes calldata data)
    private
{
    (bool success,) = target.call{value: value}(data); // <@Audit: Potential reentrancy vulnerability
    require(success, "Timelock: underlying transaction reverted");
}
```
We can reproduce this issue when we

1. Create a malicious contract that, when called by the Timelock, calls back into the Timelock's `executeWhitelisted` function.
2. Set up this malicious contract as a whitelisted target with approved calldata.
3. Call `executeWhitelisted` with the malicious contract as the target.

## Recommended Mitigation Steps
Consider adding additional checks or restrictions on the types of operations that can be performed through `executeWhitelisted`, especially for operations that could significantly impact the contract's state.
```diff
+ import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

- contract Timelock is ConfigurablePause, AccessControlEnumerable, IERC1155Receiver, IERC721Receiver {
+ contract Timelock is ConfigurablePause, AccessControlEnumerable, IERC1155Receiver, IERC721Receiver, ReentrancyGuard {

-    function executeWhitelisted(address target, uint256 value, bytes calldata payload) external payable onlyRole(HOT_SIGNER_ROLE) whenNotPaused {
+    function executeWhitelisted(address target, uint256 value, bytes calldata payload) external payable onlyRole(HOT_SIGNER_ROLE) whenNotPaused nonReentrant {
        checkCalldata(target, payload);
        _execute(target, value, payload);
        emit CallExecuted(bytes32(0), 0, target, value, payload);
    }
```
