# Vulnerability details

## Proof of Concept
The InstanceDeployer.sol contract does not provide a fallback or retry mechanism in case of Safe creation failure. If the Safe creation fails due to issues like front-running, the contract emits a SafeCreationFailed event, but no further action is taken to retry or recover from the failure. This can leave the system in an inconsistent state, with partially deployed Timelocks or recovery spells.

```
try SafeProxyFactory(safeProxyFactory).createProxyWithNonce(
    safeProxyLogic, safeInitdata, creationSalt
) returns (SafeProxy safeProxy) {
    walletInstance.safe = safeProxy;
} catch {
    emit SafeCreationFailed(
        msg.sender,
        block.timestamp,
        address(walletInstance.safe),
        safeInitdata,
        creationSalt
    );
}
```

A front-running attack could prevent the Safe from being created. The SafeCreationFailed event is emitted, but the user has no way to recover the situation without redeploying the entire contract manually.
Timelocks and recovery spells may be partially deployed, but the Safe remains missing, leaving the system unusable.



Inconsistent State: If the Safe creation fails, there could be partially deployed components like Timelocks or recovery spells that remain without a Safe, leading to an inconsistent state.
Denial of Service: Users may be unable to deploy a Safe, leading to a denial of service if no fallback mechanism is provided.




## Recommended Mitigation Steps
Retry Mechanism:
Implement a mechanism to retry Safe creation if it fails. You could allow users to retry manually or automatically retry the creation process a certain number of times.

```
uint256 retryLimit = 3;
for (uint256 i = 0; i < retryLimit; i++) {
    try SafeProxyFactory(safeProxyFactory).createProxyWithNonce(
        safeProxyLogic, safeInitdata, creationSalt
    ) returns (SafeProxy safeProxy) {
        walletInstance.safe = safeProxy;
        break;
    } catch {
        if (i == retryLimit - 1) {
            emit SafeCreationFailed(
                msg.sender,
                block.timestamp,
                address(walletInstance.safe),
                safeInitdata,
                creationSalt
            );
        }
    }
}
```

If the Safe creation fails, clean up any partially deployed components to prevent an inconsistent state. This could involve deleting Timelocks or recovery spells that were deployed without the Safe.
