# Vulnerability details

## Proof of Concept
Data type matching: The purpose of this function is to extract segments of raw bytes. Since you are dealing with bytes data, it makes sense to return it in the same format. If you return uint256, you lose the raw byte information and may need to do a conversion to interpret the data correctly.
https://github.com/code-423n4/2024-10-kleidi/blob/main/src/BytesHelper.sol#L16-L28
```solidity
    /// @notice function to grab the first 32 bytes of returned memory
    /// @param toSlice the calldata payload
    function getFirstWord(bytes memory toSlice)
        public
        pure
        returns (uint256 value)
    {
        require(toSlice.length >= 32, "Length less than 32 bytes");

        assembly ("memory-safe") {
            value := mload(add(toSlice, 0x20))
        }
    }
```
The following two examples have the following impacts
Assuming the bytes: `0x0102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f20`

## Recommended Mitigation Steps
To modify the getFirstWord function to return a bytes type instead of a uint256, you’ll need to create a new bytes array that contains the first 32 bytes from the input. Here’s how you can do it:
```solidity
    function getFirstWord(bytes memory toSlice)
        public
        pure
        returns (bytes memory)
    {
        require(toSlice.length >= 32, "Length less than 32 bytes");

        // Create a new bytes array of size 32
        bytes memory result = new bytes(32);

        // Use assembly to copy the first 32 bytes
        assembly {
            // Copy the first 32 bytes from toSlice to result
            mstore(add(result, 0x20), mload(add(toSlice, 0x20)))
        }

        return result;
    }
}
```
