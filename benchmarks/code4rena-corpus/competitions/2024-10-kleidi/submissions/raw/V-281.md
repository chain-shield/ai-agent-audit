# Vulnerability details

## Explanation
In case different chains are using the same recovery spell, certain attack vectors are possible:
(1) In case one of the chains has undergone a recovery that other chains haven't, and the new owners are compromised, the wallets on other chains can be enforced to change to the compromised keys. 
(2) Once the recovery spell on one of the chains has been created, those can be created on other chains as well and start the timer on `recoveryInitiated + delay`

## Impact
The precondition on this issue is that wallets on different chains use the same set of revcovery spells.
Since the protocol can not enforce the different recovery spells, once the first set of keys on all chains is compromised, if different networks on different chains do not migrate via the same module they all can be attacked.

## Proof of Concept
- Two wallets on Ethereum and Optimism have two recovery spells `A`, and `B`
- Original owners get compromised so Ethereum changes to `A`, and Optimism changes to `B`
- If the Ethereum's new keys get compromised as well, the attackers can create the recovery spell on Optimism and enforce the wallet on optimism to change to the compromised owners as well. This can happen after attackers use the stolen keys to create valid signatures to call `executeRecovery` with.
- Attackers need to take control of one of the new chains to take over all others.


## Recommended Mitigation Steps
Ensure users use different recovery spells on different networks.
