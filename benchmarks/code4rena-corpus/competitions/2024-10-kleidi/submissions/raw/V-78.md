# Vulnerability details

## Proof of Concept
The RecoverySpell.sol contract assumes that the recovery delay set in the constructor is shorter than the timelock for Safe transactions. However, this assumption is not validated by the contract itself. A misconfigured recovery delay longer than the timelock could allow attackers to complete the recovery process before the timelock on Safe transactions expires, leading to unsafe execution.
```
constructor(
    address[] memory _owners,
    address _safe,
    uint256 _safeThreshold,
    uint256 _recoveryThreshold,
    uint256 _delay
) {
    // No validation to check if delay < timelock
    owners = _owners;
    safe = Safe(payable(_safe));
    threshold = _safeThreshold;
    recoveryThreshold = _recoveryThreshold;
    delay = _delay;
}
```

The deployer sets a recovery delay of 7 days, but the Safe’s timelock is configured for 5 days.
An attacker initiates the recovery process and completes it before the Safe’s timelock expires, effectively bypassing the timelock’s security mechanisms.

Steps to Reproduce:
Deploy a Safe with a timelock shorter than the recovery delay.
Initiate the recovery process and complete it before the Safe’s timelock expires.
Observe that the timelock is bypassed and the attacker can take control of the Safe.

Potential Impact
Timelock Bypass: If the recovery delay is longer than the Safe’s timelock, attackers could execute recovery before the timelock expires, defeating the purpose of the timelock.
Unauthorized Safe Access: An attacker could gain unauthorized control of the Safe before the timelock protects the transactions.



## Recommended Mitigation Steps
Add a check in the constructor to ensure that the recovery delay is always shorter than the Safe’s timelock. This will prevent misconfigurations during deployment.
```
constructor(
    address[] memory _owners,
    address _safe,
    uint256 _safeThreshold,
    uint256 _recoveryThreshold,
    uint256 _delay,
    uint256 safeTimelockDelay
) {
    require(_delay < safeTimelockDelay, "Recovery delay must be shorter than Safe timelock");
    owners = _owners;
    safe = Safe(payable(_safe));
    threshold = _safeThreshold;
    recoveryThreshold = _recoveryThreshold;
    delay = _delay;
}
```
Provide warnings or alerts to users deploying the contract if the recovery delay is close to or longer than the Safe’s timelock.
