# Vulnerability details

# Proof of Concept

## Potential Impact and Explanation

### The createTimelock function (lines 37-55) lacks access control, meaning any external address can invoke it to create a timelock. This lack of restriction can result in unauthorized timelocks being created, possibly leading to security vulnerabilities. For example:

### Resource Drain: If there is a limit on the number of timelocks that can be supported, a malicious user could attempt to exhaust this limit.
Confusion or Conflicting States: Unauthorized creation of timelocks could also lead to administrative confusion or conflicting states within the system, potentially undermining its reliability or stability.

## Proof in Context

## Below is a code snippet illustrating the lack of access control in the createTimelock function:

 function createTimelock(address safe, DeploymentParams memory params)
     external
     returns (address timelock)
 {
     timelock = address(
        new Timelock{
             salt: keccak256(abi.encodePacked(params.salt, msg.sender))
         }(
             safe,
             params.minDelay,
             params.expirationPeriod,
             params.pauser,
             params.pauseDuration,
             params.hotSigners
         )
     );

     emit TimelockCreated(timelock, block.timestamp, msg.sender);
 }

## As observed, this function is marked as external and is callable by any address. There is no access modifier to limit the function's execution to authorized addresses only.

## A Potential Exploit
### A malicious actor could simply call createTimelock() from any arbitrary address and create multiple unauthorized timelocks.

## Validation of Claims
### You can validate the vulnerability by interacting with the deployed contract and invoking the createTimelock function from any address. Since there are no access restrictions, this should execute successfully irrespective of the caller.

## Recommended Mitigation Steps
### Add Access Control: To mitigate this issue, you should restrict access to the createTimelock function to ensure that only authorized users can call it. This can be achieved by adding appropriate access modifiers, such as:

modifier onlyAuthorized() {
    require(msg.sender == owner || authorizedAddresses[msg.sender], "Not authorized");
    _;
}

function createTimelock(address safe, DeploymentParams memory params)
      external
      onlyAuthorized
      returns (address timelock)
  {
      timelock = address(
          new Timelock{

  }
