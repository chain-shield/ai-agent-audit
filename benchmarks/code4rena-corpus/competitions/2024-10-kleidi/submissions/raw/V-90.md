# Vulnerability details

## Vulnerability details
`Timelock` can take a contract off pause. In natspec it is described that the function 
`_updatePauseDuration` *should only be called when the contract is unpaused*
but in the function body there is a function that unpauses the contract.

```solidity 
  /// @notice helper function to update the pause duration
    /// should only be called when the contract is unpaused
    /// @param newPauseDuration new pause duration
    function _updatePauseDuration(uint128 newPauseDuration) internal {
        require(
            newPauseDuration >= MIN_PAUSE_DURATION
                && newPauseDuration <= MAX_PAUSE_DURATION,
            "ConfigurablePause: pause duration out of bounds"
        );

        /// if the contract was already paused, reset the pauseStartTime to 0
        /// so that this function cannot pause the contract again
@->     _setPauseTime(0);

        uint256 oldPauseDuration = pauseDuration;
        pauseDuration = newPauseDuration;

        emit PauseDurationUpdated(oldPauseDuration, pauseDuration);
    }

```
## Impact
Suppose that `pauser` and `admin` are currently not communicating with each other. And in one block there are two transactions in which first pauser pauses the contract. And at this moment admin decides to update the pause duration. 
Depending on the purpose of the pause, vulnerability or something else, this will give time for at least **compromised** `HOT_WALLETS` to exploit this vulnerability, because in order to pause the contract again, a new pauser must first be appointed and only then must the paused contract be paused. It also gives the admin extra powers, which can have a bad effect on trust.

## Recommended Mitigation Steps
It would be more logical to add the `whenNotPaused` modifier to the `updatePauseDuration` function and delete `_setPauseTime(0)`

```solidity 
function updatePauseDuration(

uint128 newPauseDuration

) external onlyTimelock whenNotPaused {

/// min and max checks are done in the internal function

_updatePauseDuration(newPauseDuration);

}
```

