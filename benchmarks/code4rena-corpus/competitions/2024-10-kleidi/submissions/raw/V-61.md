# Vulnerability details

## Proof of Concept
Timelock contract's `pause()` function fails to reset the total number of operations when pausing the contract. This creates an inconsistency between the actual state (no live proposals) and the reported state (non-zero total operations).

The `pause()` function indeed removes all live proposals and their timestamps, but it doesn't update a global counter that tracks the total number of operations. This counter is likely maintained elsewhere in the contract but is not reset during the pause operation.

1. Assume Timelock's contract is deployed with initial state

   * Assume `totalOperations = 5`
   * `_liveProposals` contains 5 proposal IDs

2. Call the `pause()` function:
```solidity
timelock.pause();
```
3. After `pause()` executes

   * `_liveProposals` is empty (all proposals removed)
   * `timestamps` for all proposal IDs are deleted
   * `totalOperations` remains 5 (unchanged)

4. Check the total operations and live proposals
```solidity
uint256 operations = timelock.totalOperations();
assert(operations == 5); // This assertion passes, revealing the bug

bytes32[] memory proposals = timelock.getAllProposals();
assert(proposals.length == 0); // This assertion passes
```
Relevant code in [Timelock.sol:pause](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L687-L700)
```solidity
function pause() public override {
    /// check that msg.sender is the pause guardian, pause the contract
    super.pause();

    bytes32[] memory proposals = _liveProposals.values();
    for (uint256 i = 0; i < proposals.length; i++) {
        bytes32 id = proposals[i];

        delete timestamps[id];
        assert(_liveProposals.remove(id));

        emit Cancelled(id);
    }
    // @Audit: Missing reset of totalOperations to 0
}
```


> The root cause is that the `pause()` function removes all live proposals and their timestamps but fails to reset a global counter of total operations. This bug creates an inconsistency between the actual state of the contract (no live proposals) and the reported number of total operations. If the contract is unpaused, it may incorrectly report that there are ongoing operations when in reality there are none.

## Recommended Mitigation Steps
Update the `pause()` function to reset the total operations counter
```diff
function pause() public override {
    /// check that msg.sender is the pause guardian, pause the contract
    super.pause();

    bytes32[] memory proposals = _liveProposals.values();
    for (uint256 i = 0; i < proposals.length; i++) {
        bytes32 id = proposals[i];

        delete timestamps[id];
        assert(_liveProposals.remove(id));

        emit Cancelled(id);
    }
+   totalOperations = 0;
+   emit TotalOperationsReset();
}
```
