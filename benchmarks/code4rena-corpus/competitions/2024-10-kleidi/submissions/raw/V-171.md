```solidity
function executeWhitelisted(
    address target,
    uint256 value,
    bytes calldata payload
) external payable onlyRole(HOT_SIGNER_ROLE) whenNotPaused {
    // @audit-issue Hot signers can execute admin functions if whitelisted
    checkCalldata(target, payload);
    _execute(target, value, payload);
}

function _addCalldataCheck(
    address contractAddress,
    bytes4 selector,
    uint16 startIndex,
    uint16 endIndex,
    bytes[] memory data
) private {
    // @audit-issue No validation preventing admin functions from being whitelisted
    require(
        contractAddress != address(this),
        "CalldataList: Address cannot be this"
    );
}
```
Privilege Escalation in Timelock allows hot signers to execute administrative functions through whitelisted calls, bypassing timelock governance controls.

The issue exists in the interaction between three key components:

1. Hot signer role permissions
2. `Calldata` whitelisting mechanism
3. Administrative function access controls

> If administrative functions can be whitelisted, it breaks the core security assumption that these functions must go through timelock governance.

Attack Scenario:

1. Alice is a hot signer with `HOT_SIGNER_ROLE`
2. Alice crafts a payload targeting `updateDelay()`
3. Alice executes this through `executeWhitelisted()`
4. The delay parameter is modified immediately, bypassing timelock

## Proof of Concept
The core issue is that while the contract prevents direct calls to admin functions via the `onlyTimelock` modifier, it doesn't prevent these functions from being whitelisted and executed through the hot signer role's `executeWhitelisted` function. This creates a privilege escalation path where hot signers could gain admin capabilities through the whitelisting mechanism.

The vulnerability connects the access control system (**HOT_SIGNER_ROLE**) with the whitelisting mechanism and administrative functions, allowing an unintended bypass of governance timelock requirements.

Root Cause:

* The whitelisting mechanism doesn't differentiate between DeFi operations and admin functions
* Missing validation layer to prevent admin function selectors from being whitelisted
* Incomplete privilege separation between hot signers and timelock governance

For this reason, hot signers can bypass timelock governance by executing whitelisted admin calls. Administrative parameters like delays and guardians can be modified without timelock breaking the core security assumption of timelock-protected governance

There are no technical barriers to exploitation once admin functions are whitelisted. only requires "HOT_SIGNER_ROLE" access, for can be executed in a single transaction
