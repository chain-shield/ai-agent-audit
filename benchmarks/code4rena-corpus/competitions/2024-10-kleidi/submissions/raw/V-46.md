# Vulnerability details

`removeCalldataCheck` function in the Timelock contract allows the removal of `calldata` checks for any address, including the Timelock contract itself and its associated Safe. This vulnerability compromises a critical security invariant that should prevent modifications to the Timelock's own checks.

It happens because the `removeCalldataCheck` function directly calls the internal `_removeCalldataCheck` function without validating the `contractAddress` parameter. 

## Proof of Concept
* What: Calldata checks for the timelock contract can be removed, compromising its security.
* Why: The `removeCalldataCheck` function doesn't validate the `contractAddress` parameter against the timelock's own address or its safe's address.
* Where: In the `removeCalldataCheck` function of `Timelock.so`l.

To reproduce or validate: Call `removeCalldataCheck` with the timelock's own address as the `contractAddress` parameter.


```solidity
    function removeCalldataCheck(
        address contractAddress,
        bytes4 selector,
        uint256 index
    ) external onlyTimelock {
        _removeCalldataCheck(contractAddress, selector, index); // <= FOUND
    }
```
The function lacks a crucial check to prevent removal of calldata checks for the timelock contract itself or its associated safe. It directly calls the internal `_removeCalldataCheck` function without validating the `contractAddress` parameter.
