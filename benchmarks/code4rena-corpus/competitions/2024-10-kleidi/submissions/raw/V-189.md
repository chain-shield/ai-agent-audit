# Vulnerability details

## Proof of Concept
Static Address Assumptions: The contract relies on static assumptions for the addresses of key contracts like SAFE_FACTORY or SAFE_LOGIC. These static assumptions could become outdated or incorrect, leading the system to interact with unintended contracts.

Risk:
-Outdated or Incorrect Contracts: If the addresses change or become obsolete, the system could start interacting with outdated or even malicious contracts.
-Contract Mismatches: Relying on static addresses could lead to version mismatches or incorrect contract logic being used.
Impact: This could result in unexpected behavior, potential security vulnerabilities, and financial losses due to incorrect interactions with contracts.

## Recommended Mitigation Steps

Dynamic Address Retrieval: Instead of hardcoding or assuming these addresses, you could implement a dynamic mechanism to fetch the latest addresses from an upgradable contract registry or use a proxy mechanism to ensure future upgrades are handled gracefully.
Upgradeable Patterns: Utilize upgradeable contract patterns, such as the proxy pattern, to handle the future upgrade of external dependencies without breaking the system.
Example of an Improved deploy Function:

import "@openzeppelin/contracts/access/Ownable.sol";

contract SystemDeploy is MultisigProposal, Ownable {
    function deploy() public override onlyOwner {
        if (!addresses.isAddressSet("TIMELOCK_FACTORY")) {
            TimelockFactory factory = new TimelockFactory{salt: generateSalt()}();
            require(address(factory) != address(0), "Factory deployment failed");
            addresses.addAddress("TIMELOCK_FACTORY", address(factory), true);
        }
        // Repeat for other components with similar checks...
    }

    function generateSalt() internal view returns (bytes32) {
        return keccak256(abi.encodePacked(block.timestamp, msg.sender));
    }
}
