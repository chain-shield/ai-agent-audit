# Vulnerability details

## Description

The RecoverySpell contract uses ECDSA signatures to authorize Safe recovery, requiring `recoveryThreshold` signatures from new owners. The signatures are collected off-chain and submitted in a single transaction via `executeRecovery`.

## Vulnerability Details
The contract doesn't protect against frontrunning of signatures. Since signatures are collected off-chain and don't include nonces or timestamps, they remain valid indefinitely once the delay period has passed. A malicious actor could:
1. Collect valid signatures for one set of recovery parameters
2. Wait for the delay period
3. Front-run another recovery attempt with the previously collected signatures

## Vulnerable Code Snippets:

```solidity
// Vulnerable digest generation without nonce/timestamp
function getDigest() public view returns (bytes32) {

```

## Impact
A malicious actor could:
1. Collect signatures for a legitimate recovery
2. Hold these signatures
3. Use them to front-run a different legitimate recovery attempt
4. Take control of the Safe without current authorization

## Attack Scenario

1. Legitimate Recovery Process:
```
- Safe owners initiate recovery with new owners A, B, C
- Delay period of 1 day starts
- New owners A and B sign the recovery (meeting threshold of 2)
```

2. Malicious Actor:
```
- Observes and collects these signatures
- Waits for delay period to pass
- When legitimate owners try to execute recovery
- Front-runs with collected signatures
```

## Fix

Add nonce and deadline to the signature digest:

```solidity
contract RecoverySpell is EIP712 {
    // Add nonce tracking
    uint256 public recoveryNonce;
    
    bytes32 public constant RECOVERY_TYPEHASH = keccak256(
        "Recovery(address safe,uint256 newSafeThreshold,uint256 newRecoveryThreshold,uint256 delay,uint256 nonce,uint256 deadline)"
    );
    
    function getDigest(uint256 deadline) public view returns (bytes32) {
        return keccak256(
            abi.encodePacked(
                "\x19\x01",
                _domainSeparatorV4(),
                keccak256(
                    abi.encode(
                        RECOVERY_TYPEHASH,
                        safe,
                        threshold,
                        recoveryThreshold,
                        delay,
                        recoveryNonce,
                        deadline
                    )
                )
            )
        );
    }
    
    function executeRecovery(
        address previousModule,
        uint8[] calldata v,
        bytes32[] calldata r,
        bytes32[] calldata s,
        uint256 deadline
    ) external {
        require(block.timestamp <= deadline, "RecoverySpell: Signature expired");
        
        bytes32 digest = getDigest(deadline);
        
        // ... rest of signature verification ...
        
        // Increment nonce before executing recovery
        recoveryNonce++;
        
        // ... rest of recovery logic ...
    }
}
```

## Test

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.25;

import {Test} from "forge-std/Test.sol";
import {RecoverySpell} from "../src/RecoverySpell.sol";

contract RecoverySpellTest is Test {
    RecoverySpell public spell;
    address[] public newOwners;
    uint256[] public privateKeys;
    
    function setUp() public {
        // Create 3 owners with known private keys
        for(uint i = 0; i < 3; i++) {
            uint256 privateKey = uint256(keccak256(abi.encodePacked("owner", i)));
            address owner = vm.addr(privateKey);
            newOwners.push(owner);
            privateKeys.push(privateKey);
        }
        
        spell = new RecoverySpell(
            newOwners,
            address(0x1),  // mock safe address
            2,             // safe threshold
            2,             // recovery threshold
            1 days         // delay
        );
    }
    
    function testFrontrunningAttack() public {
        // Advance time past delay
        vm.warp(block.timestamp + 1 days + 1);
        
        // First recovery attempt
        uint256 deadline1 = block.timestamp + 1 hours;
        bytes32 digest1 = spell.getDigest(deadline1);
        
        // Generate valid signatures
        (
            uint8[] memory v1,
            bytes32[] memory r1,
            bytes32[] memory s1
        ) = generateSignatures(digest1, 2);
        
        // Execute first recovery
        spell.executeRecovery(address(0), v1, r1, s1, deadline1);
        
        // Try to reuse same signatures
        vm.warp(block.timestamp + 2 hours);
        
        // Should revert due to nonce change
        vm.expectRevert("RecoverySpell: Invalid signature");
        spell.executeRecovery(address(0), v1, r1, s1, deadline1);
    }
    
    function generateSignatures(bytes32 digest, uint256 count) 
        internal 
        view 
        returns (
            uint8[] memory v,
            bytes32[] memory r,
            bytes32[] memory s
        )
    {
        require(count <= privateKeys.length, "Too many signatures requested");
        
        v = new uint8[](count);
        r = new bytes32[](count);
        s = new bytes32[](count);
        
        for(uint i = 0; i < count; i++) {
            (v[i], r[i], s[i]) = vm.sign(privateKeys[i], digest);
        }
    }
}

```

The fix ensures that:
1. Signatures are only valid until a specified deadline
2. Each successful recovery invalidates previous signatures via nonce increment
3. Front-running attacks are prevented as signatures are tied to specific recovery attempts
4. Recovery participants must generate fresh signatures for each attempt

This significantly improves the security of the recovery process by preventing signature reuse and front-running attacks.
