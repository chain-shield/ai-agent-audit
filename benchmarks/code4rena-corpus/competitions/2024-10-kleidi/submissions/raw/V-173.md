# Vulnerability details

Unchecked arithmetic when combining delay values with block timestamps in the scheduling mechanism. This affects the core security guarantees of the timelock.

When scheduling operations, the contract adds the delay to the current block.timestamp: [src/Timelock.sol#L1004](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1004)
```solidity
timestamps[id] = block.timestamp + delay;
```
There's insufficient validation of the delay values to prevent overflow in this calculation.

## Proof of Concept
The core issue is unchecked arithmetic when:

1. Setting new delay values that will be used in timestamp calculations
2. Adding delay to block.timestamp in scheduling operations
3. Lack of overflow protection in critical timing calculations

This could lead to timestamp overflow vulnerabilities in the timelock's core functionality.

[src/Timelock.sol#L960-L968](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L960-L968)

```solidity
function _schedule(bytes32 id, uint256 delay) private {
    require(!isOperation(id), "Timelock: operation already scheduled");
    require(delay >= minDelay, "Timelock: insufficient delay"); 
    // @audit Arithmetic overflow: block.timestamp + delay can overflow
    timestamps[id] = block.timestamp + delay;
}

function updateDelay(uint256 newDelay) external onlyTimelock {
    // @audit Insufficient validation: newDelay bounds check doesn't prevent overflow when used in timestamp calculation
    require(newDelay >= MIN_DELAY && newDelay <= MAX_DELAY, "Timelock: delay out of bounds");
    emit MinDelayChange(minDelay, newDelay);
    minDelay = newDelay;
}
```
The vulnerability affects critical timelock security functions:

* `updateDelay()` sets delay parameter
* `_schedule()` uses delay in timestamp calculation
* `isOperationReady()` checks resulting timestamp
* `execute()` relies on these checks

This creates a complete attack path through the core timelock functionality.

## Recommended Mitigation Steps
Add overflow protection when calculating timestamps.
```diff
function _schedule(bytes32 id, uint256 delay) private {
    require(!isOperation(id), "Timelock: operation already scheduled");
    require(delay >= minDelay, "Timelock: insufficient delay");
+   require(block.timestamp + delay >= block.timestamp, 
+           "Timelock: delay overflow");
    timestamps[id] = block.timestamp + delay;
}

function updateDelay(uint256 newDelay) external onlyTimelock {
    require(newDelay >= MIN_DELAY && newDelay <= MAX_DELAY,
            "Timelock: delay out of bounds");
+   // Validate delay won't cause overflow with max timestamp
+   require(type(uint256).max - block.timestamp >= newDelay,
+           "Timelock: delay too large");
    emit MinDelayChange(minDelay, newDelay);
    minDelay = newDelay;
}
```
