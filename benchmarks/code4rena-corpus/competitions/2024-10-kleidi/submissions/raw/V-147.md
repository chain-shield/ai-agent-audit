# Vulnerability details

## Proof of Concept
In the current implementation of the [`checkTransaction()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Guard.sol#L56-L60) function, the check if (`to == msg.sender`) is designed to prevent `self-calls`, where the target address (`to`) is the same as the direct caller (`msg.sender`). 
However, this enforcement doesn't take into account scenarios where transactions are initiated from an `EOA` but routed through `smart contract wallets`.

Implementation:
```solidity
        if (to == msg.sender) {
            /// only allow self calls to effectively cancel a transaction by
            /// using a nonce without any payload and value.
            require(data.length == 0 && value == 0, "Guard: no self calls");
        }
```
1. **Direct Call**:

If an `EOA` calls the contract directly, `msg.sender` is the `EOA`, and the check ensures that `to == msg.sender` only passes if there is no payload (`data.length == 0`) and no value transfer (`value == 0`).

2. **Call via Smart Contract Wallet**:

If an `EOA` uses a `smart contract wallet` to interact with the contract, `msg.sender` will be the address of the smart contract wallet. In this case:
- Even if `to` is the original `EOA`'s address, the check will not trigger, because `msg.sender` is now the `smart contract wallet`, not the `EOA`.

## Impact
This allows calls where `to` is the original `EOA`'s address to bypass the check, as the condition `to == msg.sender` is no longer met.

## Recommended Mitigation Steps
The check could be updated to ensure that both `to == msg.sender` and `to == tx.origin`, thus preventing an intermediary smart contract from calling the function on behalf of an `EOA`.
```diff
-       if (to == msg.sender) {
+       if (to == msg.sender || to == tx.origin) {
            /// only allow self calls to effectively cancel a transaction by
            /// using a nonce without any payload and value.
            require(data.length == 0 && value == 0, "Guard: no self calls");
        }
```
