# Vulnerability details

## Proof of Concept
In timelock contract, any proposal needs to be delayed for a period of time. After the delay period expires, this proposal can be executed.
From the dev comments, this timelock operation's delay should between MIN_DELAY and MAX_DELAY:
```solidity
/// @dev minimum delay for timelocked operations
uint256 constant MIN_DELAY = 1 days;

/// @dev maximum delay for timelocked operations
uint256 constant MAX_DELAY = 30 days;
```
But the problem is that we don't check whether the input delay is larger than MAX_DELAY. We just check that the input delay needs to be larger than `minDelay`. So proposals can be set the delay which exceeds the maximum delay.
```solidity
    function _schedule(bytes32 id, uint256 delay) private {
        require(!isOperation(id), "Timelock: operation already scheduled");
        require(delay >= minDelay, "Timelock: insufficient delay");
        // We record the unlock time for this proposal.
        timestamps[id] = block.timestamp + delay;
    }
```
## Recommended Mitigation Steps
Add one check for the maximum delay.
