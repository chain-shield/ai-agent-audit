# Vulnerability details

## Description
The `deploy()` function creates unnecessary gas waste by allowing multiple contract deployments to succeed before failing on missing prerequisites for the `InstanceDeployer`. This causes maximum gas consumption while guaranteeing deployment failure in certain conditions.

The current deployment sequence deploys contracts in this order:
```solidity
function deploy() public override {
    // Expensive contract deployments that succeed
    if (!addresses.isAddressSet("TIMELOCK_FACTORY")) {
        TimelockFactory factory = new TimelockFactory{salt: salt}();
        addresses.addAddress("TIMELOCK_FACTORY", address(factory), true);
    }

    if (!addresses.isAddressSet("RECOVERY_SPELL_FACTORY")) {
        RecoverySpellFactory recoveryFactory = new RecoverySpellFactory{salt: salt}();
        addresses.addAddress("RECOVERY_SPELL_FACTORY", address(recoveryFactory), true);
    }

    if (!addresses.isAddressSet("GUARD")) {
        Guard guard = new Guard{salt: salt}();
        addresses.addAddress("GUARD", address(guard), true);
    }

    // Fails here if prerequisites missing
    if (!addresses.isAddressSet("INSTANCE_DEPLOYER")) {
        InstanceDeployer deployer = new InstanceDeployer{salt: salt}(
            addresses.getAddress("SAFE_FACTORY"),  // Reverts if not set
            addresses.getAddress("SAFE_LOGIC"),    // Reverts if not set
            addresses.getAddress("TIMELOCK_FACTORY"),
            addresses.getAddress("GUARD"),
            addresses.getAddress("MULTICALL3")     // Reverts if not set
        );
    }
}
```

## Gas Wastage

1. **Contract Creation Opcodes**
   - Each successful deployment consumes gas for CREATE2 operations
   - Storage writes for contract bytecode
   - Contract initialization costs

2. **Storage Operations**
   - Address registration in mapping
   - Storage slots updated for each successful deployment

3. **Failed Transaction**
   - All gas used by successful deployments is wasted
   - Transaction reverts but gas is still consumed

4. **Unnecessary State Changes**
   - Deployed contracts remain on-chain
   - Storage slots modified without achieving deployment goal

## Optimized Solution

```solidity
function deploy() public override {
    // Cheap prerequisite check before expensive operations
    require(
        addresses.isAddressSet("SAFE_FACTORY") &&
        addresses.isAddressSet("SAFE_LOGIC") &&
        addresses.isAddressSet("MULTICALL3"),
        "Prerequisites not met"
    );

    _performDeployments();
}
```

## Gas Optimization Benefits

1. **Early Failure**
- Reverts before any contract deployments
- Only basic SLOAD operations for checks
- No wasted CREATE2 operations
- No storage modifications

2. **Predictable Gas Usage**
- Failed cases use minimal gas
- Successful cases only proceed when likely to complete
- No partial deployment state

3. **Network Impact**
- Reduced network congestion from failed deployments
- More efficient block space usage
- Lower total gas costs across all chains

## Recommendations
- Implement early checks before any deployments
- Use read-only operations for validation
- Fail fast pattern for missing dependencies
- Implement resume functionality for partial deployments
