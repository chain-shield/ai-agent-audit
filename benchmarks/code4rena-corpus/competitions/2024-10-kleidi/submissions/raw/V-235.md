# Vulnerability details

## Description

A vulnerability exists in the `_updatePauseDuration()` function that allows an attacker to prematurely end an active pause and re-pause the contract, bypassing the intended cooldown period.

The `_updatePauseDuration()` function resets the `pauseStartTime` to 0 if the contract is already paused. This is intended to prevent the function from being used to re-pause the contract immediately.

However, an attacker can exploit this by calling `_updatePauseDuration()` with a very short duration during an active pause. This effectively ends the pause by resetting `pauseStartTime`.

The attacker can then immediately call `pause()` again, as the contract is no longer considered paused.

## Impact

This vulnerability undermines the pause mechanism, allowing unauthorized actions to be performed during what should be a paused state. 

## Proof of Concept

1. **Deploy the contract** with an initial `pauseGuardian` and `pauseDuration`.
2. **Call `pause()`** as the `pauseGuardian` to initiate a pause.
3. **Call `_updatePauseDuration()`** with a very short duration (e.g., 1 second).
4. **Call `pause()`** again. The contract will be paused again, bypassing the original pause duration.

## Recommended Fix

Modify the `_updatePauseDuration()` function to prevent it from being called during an active pause. This can be achieved by adding a check to ensure `pauseStartTime` is 0 (indicating no active pause) before proceeding with the update:

```solidity
function _updatePauseDuration(uint128 newPauseDuration) internal {
    // ... (validation code) ...

    /// Ensure the contract is NOT currently paused before allowing an update
    require(pauseStartTime == 0, "ConfigurablePause: cannot update duration while paused"); 

    // ... (update pauseDuration) ...
}
```
