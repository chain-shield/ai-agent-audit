# Vulnerability Details

## Impact

When a hot signer calls `executeWhitelisted()` or `executeWhitelistedBatch()`, `checkcalldata()` is executed to check the `payload` that he provided.
Inside this function, the calldata is checked to determine whether it is whitelisted.

It is documented that dynamic calldata, such as arrays, cannot be checked because parameters can be at unpredictable indexes depending on the array length. It is also stated that all supported protocols will have fixed-size calldata, so this is not a concern.

However, a compromised hot signer could execute whitelisted calldata to a whitelisted contract with excessive calldata by simply appending data to the whitelisted calldata.
This could alter the execution of the function specified by the calldata.

## Proof of Concept

Consider this function which would be vulnerable even though the formal function paramter contains no array:

```solidity
function transfer(uint amount) public view returns (uint res) {
    assembly {
        res := calldataload(36)
    }
    return res;
}
```

The following scenario is possible if the above function is whitelisted:

1. A hot signer is compromised

2. He calls `executeWhitelisted()` with the whitelisted calldata for the function but appends additional calldata at the end.

3. The function is executed, but it executes unexpected logic (for example it could transfer too much funds or interact with a defi protocol in an unexpected way), as the timelock does not check the length of the calldata.

## Recommended Mitigation Steps

Consider adding an option to set a size limit for the calldata when it is whitelisted.
