# Vulnerability details

## Description

The `checkTransaction` function in the `Guard` contract has an insufficient validation issue that could allow certain types of self-calls to bypass the delegate call restriction, potentially enabling unauthorized modifications to the Gnosis Safe.

## Vulnerable Code

```solidity
function checkTransaction(
    address to,
    uint256 value,
    bytes memory data,
    Enum.Operation operationType,
    uint256,
    uint256,
    uint256,
    address,
    address payable,
    bytes memory,
    address
) external view {
    if (to == msg.sender) {
        // Allows empty self-calls for nonce cancellation
        require(data.length == 0 && value == 0, "Guard: no self calls"); 
    }
    // Delegate call restriction only applied to non-self calls
    require(operationType == Enum.Operation.Call, "Guard: delegate call disallowed"); 
}
```

## Vulnerability Details

The `checkTransaction` function aims to prevent unauthorized modifications to the Gnosis Safe by restricting delegate calls and self-calls. However, the logic for checking the `operationType` is flawed.

* **Intended Behavior:** The code intends to allow only empty self-calls (zero value and zero data) for the purpose of canceling nonces. All other self-calls and any delegate calls should be blocked.
* **Actual Behavior:**  The code only checks the `operationType` for non-self calls. This means that a self-call with zero value and zero data can have any `operationType`, including `DelegateCall`, and still pass the validation.

## Scenario

1. **Malicious Module:** A malicious or compromised module is present in the Gnosis Safe.
2. **Self-Call Exploitation:** This module could craft a transaction with the following characteristics:
   - `to`: Address of the Gnosis Safe itself (a self-call)
   - `value`: 0
   - `data`: Empty (length 0)
   - `operationType`: `DelegateCall` (or another operation type that allows modifying the Safe's state)

This transaction would bypass the delegate call restriction because the `require(operationType == Enum.Operation.Call, ...)` check is only executed for non-self calls.

## Impact

This validation gap could allow a malicious module to:

* **Execute Delegate Calls:** Perform a delegate call to itself or another contract, potentially modifying the Safe's state, including its owners, modules, or other critical parameters.
* **Bypass Timelock:**  Circumvent the timelock mechanism by making unauthorized changes directly through the malicious module, as the guard is designed to rely on the timelock for authorized modifications.

## Recommendation

To fix this issue, the `operationType` check should be enforced even for self-calls with zero value and zero data:

```solidity
function checkTransaction(...) external view {
    if (to == msg.sender) {
        require(data.length == 0 && value == 0, "Guard: no self calls");
        // Enforce operationType check even for empty self-calls
        require(operationType == Enum.Operation.Call, "Guard: delegate call disallowed");  
    } else {
        require(operationType == Enum.Operation.Call, "Guard: delegate call disallowed");
    }
}
```

This ensures that only empty self-calls with `operationType` set to `Call` are allowed, preventing any delegate calls, even in the context of nonce cancellation.
