# Vulnerability details

## Proof of Concept

The InstanceDeployer.sol contract uses IMulticall3.aggregate3 with Enum.Operation.DelegateCall to batch multiple operations, including adding owners and enabling modules on the Gnosis Safe.

Delegate calls are risky because they allow external contracts to execute code in the context of the calling contract, potentially leading to storage corruption or reentrancy attacks. If any malicious recovery spells or modules are added during the multicall, they can exploit this delegate call to manipulate storage or reenter critical functions.

```
require(
    Safe(payable(walletInstance.safe)).execTransaction(
        multicall3,
        0,
        abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3),
        Enum.Operation.DelegateCall,
        0,
        0,
        0,
        address(0),
        payable(0),
        signature
    ),
    "InstanceDeployer: Safe delegate call failed"
);
```
An attacker adds a malicious recovery spell during the multicall. The spell’s code is executed in the context of the Safe due to the delegateCall. As a result, it can corrupt storage, modify the Safe's owners, or execute unauthorized code.
Additionally, the delegate call could open the door to reentrancy attacks, especially if one of the contracts called during the multicall interacts with external systems.

Storage Corruption: If the delegate call executes code from an external contract with a different storage layout, it can overwrite critical state variables, potentially causing unauthorized access or loss of control over the Safe.
Reentrancy Attacks: Delegate calls allow contracts to execute in the caller’s context, which can lead to reentrancy vulnerabilities if not properly guarded. An attacker could exploit reentrant behavior to gain unauthorized control or funds.




## Recommended Mitigation Steps


Avoid delegateCall Where Possible:
Use direct calls (Enum.Operation.Call) to avoid storage corruption or malicious code execution.
Replace the delegateCall operation with a regular call:

```

require(
    Safe(payable(walletInstance.safe)).execTransaction(
        multicall3,
        0,
        abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3),
        Enum.Operation.Call,  // Replace DelegateCall with Call
        0,
        0,
        0,
        address(0),
        payable(0),
        signature
    ),
    "InstanceDeployer: Safe call failed"
);
```

Strict Validation of External Contracts:

Ensure all modules and recovery spells being added are validated and trusted. This can be done by using a whitelist or requiring security audits for all modules and contracts involved in the multicall.
Use Reentrancy Guards:

Implement reentrancy protection mechanisms (e.g., ReentrancyGuard) in critical functions to ensure that even if a reentrant call is attempted, it cannot affect the state

```

pragma solidity ^0.8.25;
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract InstanceDeployer is ReentrancyGuard {
    // Existing code...
    
    function createSystemInstance(NewInstance memory instance) 
        external 
        nonReentrant 
        returns (SystemInstance memory walletInstance) 
    {
        // Function logic...
    }
}
```
