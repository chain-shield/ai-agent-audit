# Vulnerability details

## Proof of Concept
In the executeRecovery function, the contract batches multiple state-changing operations using the execTransactionFromModule function. This function allows delegate calls, which may involve external contracts, introducing a potential reentrancy vulnerability. If a malicious contract is called during this batch process, it could reenter the contract before the recovery is fully completed, resulting in unauthorized actions or control over the Safe.

```
require(
    safe.execTransactionFromModule(
        MULTICALL3,
        0,
        abi.encodeWithSelector(IMulticall3.aggregate3.selector, calls3),
        Enum.Operation.DelegateCall
    ),
    "RecoverySpell: Recovery failed"
);
```
The execTransactionFromModule function allows external calls that could invoke a malicious contract capable of reentering the contract before the recovery is fully executed.
A malicious contract exploits this by making repeated reentrant calls during the recovery process, gaining unauthorized access or blocking the legitimate recovery process.

Reentrancy Attack: If an external contract is able to reenter during recovery execution, it could manipulate the state of the Safe, resulting in unauthorized actions such as:
Adding malicious owners.
Blocking legitimate recovery processes.
Asset Theft: A successful reentrancy attack could allow an attacker to gain unauthorized control of the Safe and steal funds.





## Recommended Mitigation Steps
Implement a reentrancy guard to prevent reentrant calls from manipulating the recovery process. This can be done using OpenZeppelin’s ReentrancyGuard
```
pragma solidity ^0.8.25;
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract RecoverySpell is ReentrancyGuard {
    // ...
    function executeRecovery(...) external nonReentrant {
        // Recovery logic
    }
}
```

Delegate calls introduce significant risks, especially in complex systems involving multiple external contracts. Where possible, avoid using delegate calls and opt for standard function calls to isolate execution contexts.

Only allow interactions with whitelisted contracts during the recovery process. This reduces the attack surface by preventing interactions with untrusted or malicious contracts.
