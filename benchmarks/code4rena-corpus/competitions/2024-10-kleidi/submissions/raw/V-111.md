# Vulnerability details

## Proof of Concept
background:
1. The safe wallet can remove restrictions on a specific dataHash through removeCalldataCheckDatahash.
2. The calldataChecks array stores the calldata of specific functions of a contract that can be called. When calldata is deleted, it is removed from calldataChecks.
3. The deletion method described in 2 is: store the value of the last element in the position to be deleted, and then pop the last bit.

```solidity
        /// remove the index check if the dataHashes are empty
        if (indexCheck.dataHashes.length() == 0) {
            /// index check to overwrite the specified index check with
            Index storage lastIndexCheck =
                calldataChecks[calldataChecks.length - 1];

            indexCheck.startIndex = lastIndexCheck.startIndex;
            indexCheck.endIndex = lastIndexCheck.endIndex;
            bytes32[] memory dataHashes = lastIndexCheck.dataHashes.values();

            for (uint256 i = 0; i < dataHashes.length; i++) {
@>              assert(indexCheck.dataHashes.add(dataHashes[i]));
                assert(lastIndexCheck.dataHashes.remove(dataHashes[i]));
            }
```

But there is a specific situation. If the length of calldataChecks is 1, then the last bit must be the element to be deleted. However, the contract will not pop directly, and will still assign the "last bit" to the "position to be deleted". In this case, indexCheck == lastIndexCheck.

The protocol first adds dataHashes through the `add` function. At this time, since the dataHashes have the same value, add will not succeed, so the call will revert.

## Recommended Mitigation Steps
Determine when the length of calldataChecks is 1, directly remove and then pop
