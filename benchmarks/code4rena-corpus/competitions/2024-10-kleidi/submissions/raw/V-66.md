# Vulnerability details

### **Vulnerability Description:**
The internal function `_execute` in the **Timelock** contract allows executing calls to arbitrary addresses using low-level calls. However, there is no prior check to verify whether the `target` address has any contract code implemented. This may allow valid calls to be made to addresses without code (such as EOAs), which could result in loss of funds or undesired behavior. The vulnerability affects the `execute`, `executeBatch`, `executeWhitelisted`, and `executeWhitelistedBatch` functions.

- https://github.com/code-423n4/2024-10-kleidi/blob/main/src/Timelock.sol#L1017-L1026 
```solidity 
    /// @dev Execute an operation's call.
    /// @param target the address of the contract to call
    /// @param value the value in native tokens to send in the call
    /// @param data the calldata to send in the call
    function _execute(address target, uint256 value, bytes calldata data)
        private
    {
        (bool success,) = target.call{value: value}(data);
        require(success, "Timelock: underlying transaction reverted");
    }
```

In the docs the team clarify that Timelock contract `holds all funds` and requires a delay before a transaction can be executed.This delay can be set to any time period between 1 and 30 days. This delay prevents an attacker from immediately executing a transaction after coercing a user into signing a transaction. `The timelock can whitelist contract calls and calldata, this allows hot signers to execute interactions with other smart contracts as long as the contract, function signature, and certain parts of the calldata are whitelisted.`

### **Proof of Concept (PoC):**

The following PoC demonstrates the execution of a call to an address without code using the vulnerable `execute` function but also the others functions with _execute have the issue. This test confirms that the contract allows an operation to be successfully scheduled and executed, even when the `target` address has no code.

1. Paste this test in `Timelock.t.sol` test.
```solidity
function testCallToEmptyAddressSucceeds() public {
    // 1. Prepare the parameters
    address target = address(0x01); // Address without code
    uint256 value = 0; 
    bytes memory payload = hex"deadbeef"; // Arbitrary calldata

    console.log("Initializing call.....");

    // 2. Schedule the operation simulating with 'safe'
    vm.prank(address(safe));
    timelock.schedule(target, value, payload, bytes32(0), MINIMUM_DELAY);

    // 3. Warp time to meet the minimum delay
    vm.warp(block.timestamp + MINIMUM_DELAY);

    // 4. Verify that the 'target' address has no code
    assertEq(target.code.length, 0, "Target should have no code");

    // 5. Execute the call to the address without code
    timelock.execute(target, value, payload, bytes32(0));

    // 6. Verify the operation was executed and marked as done
    bytes32 id = timelock.hashOperation(target, value, payload, bytes32(0));
    assertTrue(timelock.isOperationDone(id), "Operation should be marked as done");
    assertTrue(timelock.isOperation(id), "Operation should exist");
    
    console.log("Call to an address without code executed successfully");
}
```
2. Run the test with this command:
```bash 
forge test --match-test testCallToEmptyAddressSucceeds -vvv
```
3.  The result should be:
```bash
Ran 1 test for test/unit/Timelock.t.sol:TimelockUnitTest
[PASS] testCallToEmptyAddressSucceeds() (gas: 101833)
Logs:
  Inizializing call.....
  call with target without code executed successfully
```


### **Impact:**
- **Calls to Addresses Without Code**: Allowing calls to addresses without code can lead to unexpected results since such addresses do not have any logic to handle the transaction.
- **Potential Loss of Funds**: If native token is transferred as part of the call, the funds could be lost since there would be no contract to handle the transfer logic.
- **Silent Executions**: As demonstrated in the PoC, calls to addresses without code can successfully execute at the EVM level without obvious failures, which could mask logical or programming errors.

---

### **Recommendations:**
1. **Code Check for `target` Address**:
   A check should be added to ensure that the `target` address has code before proceeding with the call execution.
   ```solidity
   require(target.code.length > 0, "Timelock: target has no code");
   ```

2. **Use of OpenZeppelin’s `Address` Library**:
   OpenZeppelin offers safe functions for making contract calls. It is recommended to use their `Address.functionCallWithValue` function to enhance security.
   ```solidity
   import "@openzeppelin/contracts/utils/Address.sol";

   function _execute(address target, uint256 value, bytes calldata data) private {
       Address.functionCallWithValue(target, data, value, "Timelock: call failed");
   }
   ```
