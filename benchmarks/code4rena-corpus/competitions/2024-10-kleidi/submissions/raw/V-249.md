# Vulnerability details

## Description

The RecoverySpellFactory contract provides two key functions:
1. `createRecoverySpell`: Actually deploys the recovery contract
2. `calculateAddress`: Predicts where the contract will be deployed

These functions should be perfectly aligned in their validation logic to ensure the predicted address matches the actual deployment address.

The duplicate owner check implementations differ between the two functions, which can lead to a situation where `calculateAddress` returns an address but `createRecoverySpell` reverts for the same input parameters.

## Vulnerable Code Snippets:

1. `calculateAddress` implementation (inefficient O(n²) check):
```solidity
// In calculateAddress:
for (uint256 i = 0; i < owners.length; i++) {
    for (uint256 j = i + 1; j < owners.length; j++) {
        require(
            owners[i] != owners[j], "RecoverySpell: Duplicate owner"
        );
    }
}
```

2. `createRecoverySpell` implementation (O(n) check using transient storage):
```solidity
// In createRecoverySpell:
for (uint256 i = 0; i < owners.length; i++) {
    address owner = owners[i];
    bool found;
    assembly ("memory-safe") {
        found := tload(owner)
        if eq(found, 0) { tstore(owner, 1) }
    }
    require(!found, "RecoverySpell: Duplicate owner");
}
```

## Impact:
- Different validation logic could lead to different results for the same input
- Could break integrations relying on address prediction
- Potential DOS vector if integrating contracts don't account for this discrepancy
- Wasted gas when transactions revert due to mismatched validation

## Attack Scenario:

```solidity
// Consider this array of owners with duplicate at different positions
address[] owners = [
    address(0x1),
    address(0x2),
    address(0x3),
    address(0x1)  // duplicate of first address
];

// Step 1: Attacker calls calculateAddress
address predicted = factory.calculateAddress(
    salt,
    owners,
    safe,
    threshold,
    recoveryThreshold,
    delay
);
// This could pass with some owner arrays but fail with others due to
// different iteration patterns

// Step 2: Attacker calls createRecoverySpell
// This will revert with "RecoverySpell: Duplicate owner"
// but the revert reason might come from a different duplicate than expected
```

## Fix:

The validation logic should be identical between both functions. Here's the recommended fix:

```solidity
// Create a shared internal function for duplicate checking
function _checkDuplicateOwners(address[] memory owners) internal pure {
    for (uint256 i = 0; i < owners.length; i++) {
        for (uint256 j = i + 1; j < owners.length; j++) {
            require(
                owners[i] != owners[j],
                "RecoverySpell: Duplicate owner"
            );
        }
    }
}

// Update both functions to use this shared check
function calculateAddress(...) external view returns (address) {
    _paramChecks(owners, threshold, recoveryThreshold, delay);
    _checkDuplicateOwners(owners);
    ...
}

function createRecoverySpell(...) external returns (RecoverySpell) {
    _paramChecks(owners, threshold, recoveryThreshold, delay);
    _checkDuplicateOwners(owners);
    ...
}
```

## Test

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.25;

import {Test} from "forge-std/Test.sol";
import {RecoverySpellFactory} from "../src/RecoverySpellFactory.sol";

contract RecoverySpellFactoryTest is Test {
    RecoverySpellFactory factory;
    
    function setUp() public {
        factory = new RecoverySpellFactory();
    }
    
    function testInconsistentDuplicateValidation() public {
        address[] memory owners = new address[](4);
        owners[0] = address(0x1);
        owners[1] = address(0x2);
        owners[2] = address(0x3);
        owners[3] = address(0x1);  // duplicate of first address
        
        bytes32 salt = bytes32(0);
        address safe = address(0x999);
        uint256 threshold = 2;
        uint256 recoveryThreshold = 2;
        uint256 delay = 1 days;
        
        // First try calculateAddress
        try factory.calculateAddress(
            salt, owners, safe, threshold, recoveryThreshold, delay
        ) returns (address predicted) {
            // Now try createRecoverySpell
            vm.expectRevert("RecoverySpell: Duplicate owner");
            factory.createRecoverySpell(
                salt, owners, safe, threshold, recoveryThreshold, delay
            );
        } catch {
            fail("calculateAddress should not revert");
        }
    }
}
```

The fix ensures that both functions will always agree on what constitutes valid input parameters.
