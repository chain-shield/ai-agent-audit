# Vulnerability details

## Proof of Concept

For context, there is a delegatecall injection in the following code snippet: 

```solidity
        require(
            operationType == Enum.Operation.Call,
            "Guard: delegate call disallowed"
        );
```


The code snippet demonstrates a Delegatecall Injection vulnerability. The `checkTransaction` function explicitly disallows delegate calls (`operationType == Enum.Operation.DelegateCall`) by requiring the operation type to be `Enum.Operation.Call`.  

While this mitigates some risks, it doesn't fully address the possibility of an attacker manipulating the `operationType` parameter during a transaction execution. 

An attacker could potentially craft a malicious transaction where they control the value passed to `operationType`, bypassing the check and executing a delegate call. This could allow them to execute arbitrary code within the Safe contract, potentially leading to unauthorized modifications of owners, modules, or other sensitive data.

While the code explicitly disallows delegate calls, an attacker could manipulate the value passed to `operationType` during transaction execution. This could bypass the intended check and allow for unauthorized delegate calls. 


```solidity
pragma solidity ^0.8.0;

contract Exploit {
    address public targetContract;

    constructor(address _targetContract) {
        targetContract = _targetContract;
    }

    function exploit() public {
        // Construct a malicious transaction with manipulated operationType
        bytes memory data = abi.encodeWithSignature("checkTransaction(address,uint256,bytes,Enum.Operation,uint256,uint256,uint256,address,address payable,bytes memory,address)", 
            targetContract, 0, new bytes(0), Enum.Operation.DelegateCall, 0, 0, 0, address(this), address(0), new bytes(0), address(0));

        // Trigger the delegate call to execute malicious code
        (bool success,) = targetContract.call{value: 0}(data);

        if (success) {
            print("Vulnerability Present and Triggered: True");
        } else {
            print("Vulnerability Not Triggered: False");
        }
    }
}
```


Explanation of the above Exploit PoC:

1. The target contract address-- The `targetContract` variable stores the address of the vulnerable contract (`Guard` in this case). 

2. The exploit function --The `exploit()` function orchestrates the attack.

3. Regarding the malicious transaction function --this is the code that constructs a transaction payload using `abi.encodeWithSignature`. This payload includes:
   - The target contract address (`targetContract`).
   - A value of 0 (no Ether transfer).
   - An empty bytes array for data.
   - Crucially, the `operationType` is set to `Enum.Operation.DelegateCall`, bypassing the intended restriction.

4. The actual delegattecall injetion-- The `targetContract.call{value: 0}(data)` line executes a delegate call to the vulnerable contract using the constructed payload. This forces the execution of code within the target contract as if it were called directly, potentially allowing for unauthorized actions.

5. The success and failure execution--the code checks if the delegate call was successful (`success`) and prints an appropriate message indicating whether the vulnerability was triggered or not.


Some important notes:

- This exploit assumes that the `Enum.Operation` type is defined in a way that allows for manipulation of its values.
- The success of this exploit depends on the specific implementation details of the vulnerable contract (`Guard`) and how it handles delegate calls.

## Recommended Mitigation Steps

Code level mitigations I'd recommend are as follows: 

--> Disallow the delegatecall completely.  
```solidity
require(operationType != Enum.Operation.DelegateCall, "Delegatecall disallowed");
```

--> Implement role based access.  Use OpenZeppelin's access control to restrict sensitive operations to specific roles. 

--> Strict imput validation.   Ensure the operationType is checked explicitly for allowed operations ONLY, avoiding any manipulation:

here's an example code snippet of such a thing:
```solidity
require(operationType == Enum.Operation.Call, "Only direct calls allowed");
```
