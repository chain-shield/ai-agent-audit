# Vulnerability details

## Proof of Concept
Context:
1. _removeCalldataCheck function is used to remove a certain index in calldataChecks, i.e., to remove a certain check for a certain function call. 2.
2. when calldataChecks.length==1, that is, need to remove the last section of this function check, will not remove the value in dataHashes, but directly pop. pop after the value still exists. If a check for this function is added later, then the check itself exists.

So, this will result in an unclean removal of the check for the function.If this function is allowed to be called again, there will be an additional calldata that is allowed to be used.The impact of the vulnerability is widespread.

```solidity
        /// pop the index without swap if index is same as last index
        if (calldataChecks.length > 1) {
            /// index check to overwrite the specified index check with
            Index storage lastIndexCheck =
                calldataChecks[calldataChecks.length - 1];

            indexCheck.startIndex = lastIndexCheck.startIndex;
            indexCheck.endIndex = lastIndexCheck.endIndex;
            bytes32[] memory dataHashes = lastIndexCheck.dataHashes.values();

            for (uint256 i = 0; i < dataHashes.length; i++) {
                assert(indexCheck.dataHashes.add(dataHashes[i]));
                assert(lastIndexCheck.dataHashes.remove(dataHashes[i]));
            }
        }

        calldataChecks.pop();
```

This is an indication of the residual poc that exists if you go directly through pop without removing:

## Recommended Mitigation Steps
When calldataChecks.length==1, remove the data in dataHashes and then pop it.
