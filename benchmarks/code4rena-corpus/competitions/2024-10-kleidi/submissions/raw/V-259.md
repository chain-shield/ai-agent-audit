# Vulnerability details

## Proof of Concept

This issue is about the lack of validation of inputs in the `createTimelock` method of the `TimelockFactory` contract. 

The method creates a new `Timelock` contract with salt and other parameters without validating them.

This opens up possibilities for passing harmful input parameters which can result in undesired functionality or potentially dangerous situations like creating contracts with unexpected state.

 

```solidity
function createTimelock(address safe, DeploymentParams memory params)
    external
    returns (address timelock)
{
    timelock = address(
        new Timelock{
            salt: keccak256(abi.encodePacked(params.salt, msg.sender))
        }(
            safe,
            params.minDelay,
            params.expirationPeriod,
            params.pauser,
            params.pauseDuration,
            params.hotSigners
        )
    );

    emit TimelockCreated(timelock, block.timestamp, msg.sender);
}

```

## Recommended Mitigation Steps

It's recommended to validate external inputs and ensure they behave as expected. 

For example, non-zero address validation for the `safe`, check if `params.minDelay`, `params.expirationPeriod`, and `params.pauseDuration` are within acceptable ranges. 

Validate the array lengths too, as overly long arrays can cause gas issues. 

Always follow the practice of "Don't Trust User Input".
