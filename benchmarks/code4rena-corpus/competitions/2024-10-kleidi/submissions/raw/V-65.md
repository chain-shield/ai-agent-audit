# Vulnerability details

## Proof of Concept
totalOperations count can change by more than 1 in a single function call. The `_execute()` function allows arbitrary external calls without restricting changes to totalOperations. The `_execute` function performs an unchecked external call to an arbitrary target contract. This call can execute any code, including operations that modify the Timelock contract's state multiple times. totalOperations count, which is expected to change by at most 1 per function call, can be manipulated to change by more than 1.

For example, consider this sequence of events

1. A user calls the `execute` function on the Timelock contract.
2. The `execute` function internally calls `_execute`.
3. `_execute` makes an external call to a malicious contract.
4. The malicious contract performs multiple operations that each increment
5. The `_execute` function completes, but total Operation has changed by more than 1.

In [Timelock.sol:1021-1026](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L1021-L1026), the vulnerable code path
```solidity
function _execute(address target, uint256 value, bytes calldata data)
    private
{
    (bool success,) = target.call{value: value}(data); // <@Audit Vulnerable external call
    require(success, "Timelock: underlying transaction reverted");
}
```
The vulnerability lies in the unchecked external call that allows arbitrary execution. This can lead to unexpected state changes.

## Recommended Mitigation Steps
1. Implement a wrapper or proxy pattern to control external interactions
