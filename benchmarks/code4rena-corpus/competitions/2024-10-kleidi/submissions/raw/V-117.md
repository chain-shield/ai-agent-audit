# Vulnerability details

## Proof of Concept
background:
1. The _removeCalldataCheck function is used to remove the check of a certain piece of data of a function in the calldata whitelist.
2. When removing the calldata whitelist, the last data of calldataChecks, lastIndexCheck, will be moved to the location to be deleted, indexCheck. The add function will be called to move.
```solidity
            Index storage lastIndexCheck =
                calldataChecks[calldataChecks.length - 1];

            indexCheck.startIndex = lastIndexCheck.startIndex;
            indexCheck.endIndex = lastIndexCheck.endIndex;
            bytes32[] memory dataHashes = lastIndexCheck.dataHashes.values();

            for (uint256 i = 0; i < dataHashes.length; i++) {
                assert(indexCheck.dataHashes.add(dataHashes[i]));
                assert(lastIndexCheck.dataHashes.remove(dataHashes[i]));
            }
```

Therefore, if there is the same datahash as lastIndexCheck in indexCheck, the add function will fail to call, causing _removeCalldataCheck to fail.
Specifically, if a certain function A in the whitelist has two identical restricted parameters. For example, function A requires two address parameters, b and c. The whitelist restrictions b and c must be timelock addresses. When the restriction of b is removed, the _removeCalldataCheck call will fail.
## Recommended Mitigation Steps
```diff
            for (uint256 i = 0; i < dataHashes.length; i++) {
```
