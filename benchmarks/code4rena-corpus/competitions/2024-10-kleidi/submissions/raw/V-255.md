# Vulnerability details

## Proof of Concept

The contract attempts to check for duplicate owners in the `createRecoverySpell` function in order to prevent the same address from being used as an owner more than once. 

However, this check is flawed because the developer intended to perform this check using inline assembly in the function, but no actual check for duplicate owners is done. 

The current behavior allows the code to keep a runtime map of added owners in transient storage with a guard clause that reverts if the owner is found. 

However, the check for `found` is done after transient storage has been updated. 

Even if a duplicate owner is found, the check will always pass on the first run because the storage update takes place after the check. 

This results in the duplicate owner check failing to revert the transaction as expected in the case of duplicate owners found.

https://github.com/code-423n4/2024-10-kleidi/blob/main/src/RecoverySpellFactory.sol#L58-L75

```solidity
for (uint256 i = 0; i < owners.length; i++) {
    address owner = owners[i];
    bool found;
    assembly ("memory-safe") {
        found := tload(owner)
        if eq(found, 0) {
            tstore(owner, 1)
        }
    }
    require(!found,"RecoverySpell: Duplicate owner");
}
```


## Recommended Mitigation Steps

It is recommended to do the check for duplicate owners in memory using Solidity itself, ensuring that all parameters are validated before the execution of the contract, similar as in the function 'calculateAddress' 

 
```solidity
require(owners.length > 0, "RecoverySpell: Owners required");
for (uint256 i = 0; i < owners.length; i++) {
    for (uint256 j = i + 1; j < owners.length; j++) {
        require(owners[i] != owners[j], "RecoverySpell: Duplicate owner found");
    }
}
```
