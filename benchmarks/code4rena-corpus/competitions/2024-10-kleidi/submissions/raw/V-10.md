# Vulnerability details

## Proof of Concept
`Timelock` contracts do not implement `EIP712` correctly.

According to [EIP712 Standard](https://eips.ethereum.org/EIPS/eip-712#definition-of-typed-structured-data-%F0%9D%95%8A):

> The dynamic values `bytes` and `string` are encoded as a `keccak256` hash of their contents.

However, in [`Timelock:hashOperation()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L429-L436) and [`Timelock:hashOperationBatch()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L443-L450), the hashing is done as follows:
```solidity
    function hashOperation(
        address target,
        uint256 value,
>>      bytes calldata data, // bytes
        bytes32 salt
    ) public pure returns (bytes32) {
>>      return keccak256(abi.encode(target, value, data, salt)); // encoded & hashed directly
    }

    function hashOperationBatch(
        address[] calldata targets,
        uint256[] calldata values,
>>      bytes[] calldata payloads, // bytes
        bytes32 salt
    ) public pure returns (bytes32) {
>>      return keccak256(abi.encode(targets, values, payloads, salt)); // encoded & hashed directly
    }
```
As seen, both `data` and `payloads` are `bytes` values. However, the hashing encodes these values directly and not the `keccak256` hash of their contents as required by the standard.

**Affected functions**:
1. [`schedule()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L528)
2. [`scheduleBatch()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L562)
3. [`execute()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L595)
4. [`executeBatch()`](https://github.com/code-423n4/2024-10-kleidi/blob/ab89bcb443249e1524496b694ddb19e298dca799/src/Timelock.sol#L632)

## Impact
---> Non-compliance with `EIP712` can cause problems with integrators and potentially lead to denial of service.

## Recommended Mitigation Steps
Correct this as follows:
```diff
    // hashOperation()
-   return keccak256(abi.encode(target, value, data, salt));
+   return keccak256(abi.encode(target, value, keccak256(data), salt));

    // hashOperationBatch()
-   return keccak256(abi.encode(targets, values, payloads, salt));
+   return keccak256(abi.encode(targets, values, keccak256(payloads), salt));
```
