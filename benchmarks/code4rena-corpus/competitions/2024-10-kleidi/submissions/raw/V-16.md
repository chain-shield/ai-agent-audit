# Vulnerability details

## Proof of Concept
The pause function in timelock is critical because it's designed to slow down the attacker. It's stated with following lines:

> Wrench Resistant: One of the guiding principles of this system is to be resistant to $5 wrench attacks. Even if an attacker is able to coerce a user into signing a transaction, the system of recovery spells and guardians slows down an attacker trying to steal funds. With a 30 day timelock as the delay on new transactions, an attacker would need to kidnap a user for a month and remain undetected for the entire period in order to steal funds.

The current implementation in pause, removes the live proposals and then pause all the operations in the timelock contract. The problem in here, we don't know how many live proposals are in the timelock.

Actually, if our cold signers removes the expired proposals using clean feature, it won't be a problem. But there is no guarantee that the users will use clean feature regularly. 

In the following PoC, we can check the gas usage of pausing and cleaning 100 proposals from the list.

```solidity
    function testScheduleProposalSafeSucceedsWithParam(uint256 salt) public{
        _schedule({
            caller: address(safe),
            timelock: address(timelock),
            target: address(timelock),
            value: 0,
            data: abi.encodeWithSelector(
                timelock.updateDelay.selector, MINIMUM_DELAY
            ),
            salt: bytes32(salt),
            delay: MINIMUM_DELAY
        });

    }
    function test_DoSInPause() public {
        for(uint i = 0; i < 100; i++){
            testScheduleProposalSafeSucceedsWithParam(i); 
        }

        vm.startPrank(guardian);
        uint256 gasLeft = gasleft();
        timelock.pause();
        console.log("Consumed gas for 100 proposal approx: %s", gasLeft - gasleft());
    }
```

The output will be 334373 gas for 100 proposals. The current block gas limit in Ethereum is 30 Million. In conclusion if the users don't clean their expired proposals regularly and if it reachs 10000 live proposals, it can revert on pause due to block gas limit.

In the impact part, the pause feature is critical because it's time sensitive and it should be executed immediately in emergency situations. In conclusion, DoS in pause function can have massive impacts on the contract such as loss of funds.

## Recommended Mitigation Steps

In every schedule call by gnosis safe removing all the expired executions from the live proposals can save the contract from DoS.
