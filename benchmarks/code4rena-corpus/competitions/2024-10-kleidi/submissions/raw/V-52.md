# Vulnerability details

## Proof of Concept
background:
1. pauseGuardian can pause timelock.
2. The safe wallet can set the pauseGuardian and pause time of timelock.
3. No one can prevent pauseGuardian from pausing or unpausing, not even the spell contract.
4. In the [document](https://code4rena.com/audits/2024-10-kleidi), pauseGuardian is not a trusted role.

```solidity
    function pause() public virtual whenNotPaused {
        /// if msg.sender == pause guardian, contract is not paused
        /// this implies that pause is not used
        require(
            msg.sender == pauseGuardian,
            "ConfigurablePauseGuardian: only pause guardian"
        );

        /// pause, set pauseStartTime to current block timestamp
        /// safe unchecked downcast because maximum would be 2^128 - 1 which is
        /// a very large number and very far in the future
        _setPauseTime(uint128(block.timestamp));
```

So, if the pauseGuardian is malicious, he can maliciously pause the wallet, or even when safe wants to replace the original pauseGuardian with someone else. Before this liveProposal can be executed, a malicious pause is performed.

## Recommended Mitigation Steps
Allow the spell contract to choose whether to cancel the timelock pause when executingRecovery.
