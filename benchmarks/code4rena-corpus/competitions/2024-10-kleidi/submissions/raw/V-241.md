# Vulnerability details

The `_paramChecks` function in the `RecoverySpellFactory` contract incorrectly validates the maximum allowed `delay` for recovery operations. It assumes a year always consists of 365 days, failing to account for leap years. This can lead to unexpected transaction reverts when attempting to set a delay that includes February 29th in a leap year.

This bug affects the createRecoverySpell and calculateAddress functions, as they rely on _paramChecks for parameter validation.

## Steps to Reproduce

1.  Use the `createRecoverySpell` function in a leap year (e.g., 2024).
2.  Provide a `delay` value that equates to 366 days or more (including February 29th).
3.  The transaction will revert with the error "RecoverySpell: Delay must be lte a year."

## Expected Result

The transaction should succeed as long as the provided `delay` is within one year from the current date, correctly accounting for leap years.

## Actual Result

The transaction reverts due to the inaccurate calculation of the maximum allowed delay.

## Vulnerability Details

The following line in the `_paramChecks` function causes the issue:

```solidity
require(delay <= 365 days, "RecoverySpell: Delay must be lte a year"); 
```

This hardcoded value of `365 days` does not adapt to leap years.

## Impact

This bug affects users who need to set recovery delays that span across leap years. It can disrupt the intended functionality of the contract and lead to confusion.

## Proposed Solution

1.  **Calculate the exact timestamp one year from now**:

    ```solidity
    uint256 oneYearFromNow = block.timestamp + 365 days; 
    // Add an extra day if the current year is a leap year
    if ((block.timestamp % 4 == 0 && block.timestamp % 100 != 0) || block.timestamp % 400 == 0) {
        oneYearFromNow += 1 days;
    }
    require(delay <= oneYearFromNow, "RecoverySpell: Delay must be lte a year");
    ```

2.  **Alternatively, use a time library:** Consider using a well-tested library like OpenZeppelin's `Time` library for more robust and accurate time calculations.
