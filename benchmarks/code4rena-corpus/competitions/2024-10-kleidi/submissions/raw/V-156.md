# Vulnerability details


## Description

inside the `InstanceDeployer`, there's no setter function, in order to change addresses stored in each state incase of incorrect address assignment when deploying the `InstsanceDeployer`. also they're marked as `immutable`.

this leads to `InstanceDeployer` being unsuable and useless in that particular scenario where, deployer assigns incorrect addresses to only one of the state variables. and then deployer will be forced to deploy new `InstanceDeployer` and pay additional gas for no reason.

## Impact

If Invalid addresses are provided during deployment of `InstanceDeployer`, the `safe` and `Timelock` deployment process which relies on these states (such as safe proxy creation, timelock, multicall and...) could fail/revert or lead to deploying both contract not the way is expected to and that cause problems later on.

also `InstanceDeployer` will become completely unsuable/useless and user will be forced to deploy new `InstanceDeployer` and pay additional gas fees. this could be easily avoided by just having a simple setter function that only deployer of `InstanceDeployer` can use.

## Proof Of Concept

as we can see on [#L68-L81](https://github.com/solidity-labs-io/kleidi/blob/0d72b6cb5725c1380212dc76257da96fcfacf22f/src/InstanceDeployer.sol#L68-L81), state variables are marked `immutable`, meaning values associated with it cannot change and also there's no setter function to change each state value incase wrong address assignment on deployment.

## Recommended Mitigation

* add setter function for each state, where owner can modify their values, incase if he deployed `InstanceDeployer` with passing incorrect addresses for variables.
* remove states immutablity to be able to change it's value.

-       address public immutable timelockFactory;
