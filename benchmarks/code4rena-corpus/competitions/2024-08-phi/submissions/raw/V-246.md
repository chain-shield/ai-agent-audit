# Vulnerability details

## Impact

The `setProtocolFee` and `setArtCreateFee` functions are designed to update fees in the protocol. However, the implementation incorrectly expects these values to be provided as percentages in basis points (i.e., scaled by 10,000), whereas they should be receiving absolute fee amounts. This mismatch between expected and actual parameter types leads to practical limitations on fee adjustments.


```
/// @notice Sets the protocol fee percentage.
/// @param protocolFee_ The new protocol fee percentage (in basis points).
function setProtocolFee(uint256 protocolFee_) external onlyOwner {
    // @> mintProtocolFee is expected to be a fixed ETH amount, not a percentage.
    if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
    mintProtocolFee = protocolFee_;
    emit ProtocolFeeSet(protocolFee_);
}

/// @notice Sets the art creation fee percentage.
/// @param artCreateFee_ The new art creation fee percentage (in basis points).
function setArtCreateFee(uint256 artCreateFee_) external onlyOwner {
    // @> artCreateFee is expected to be a fixed ETH amount, not a percentage.
    if (artCreateFee_ > 10_000) revert ArtCreateFeeTooHigh();
    artCreateFee = artCreateFee_;
    emit ArtCreateFeeSet(artCreateFee_);
}
```

In these functions, the parameters `protocolFee_` and `artCreateFee_` are intended to set absolute fee amounts but are incorrectly interpreted as percentage values. The actual implementation treats these parameters as if they represent percentages, which is not aligned with how the rest of the code uses these values.

For example, consider the `getArtMintFee` function used to calculate the cost of minting art:

```
/// @notice Returns the mint fee for a art.
/// @param artId_ The ID of the art.
/// @return The mint fee for the art.
function getArtMintFee(uint256 artId_, uint256 quantity_) public view returns (uint256) {
    return IPhiRewards(phiRewardsAddress).computeMintReward(quantity_, arts[artId_].mintFee)
        + quantity_ * mintProtocolFee;
}
```

Here, `mintProtocolFee` is used as an absolute value, multiplied by the quantity of art being minted. If `mintProtocolFee` were intended to be a percentage, it should have been divided by 10,000 in the calculation. The absence of this division indicates that `mintProtocolFee` is being used as an absolute amount, contrary to how it is set.

Due to this implementation flaw, the `protocolFee` and `artCreateFee` functions are effectively constrained to an upper bound of 10_000 wei.

## Proof of Concept

Add the following two tests to `test/PhiFactory.t.sol`.

These tests demonstrate that attempting to set fees higher than 10,000 wei will cause the functions to revert.

```solidity
function test_setProtocolFee() public {
    vm.startPrank(owner);
    vm.expectRevert(IPhiFactory.ProtocolFeeTooHigh.selector);
    phiFactory.setProtocolFee(10_001);
    vm.stopPrank();
}

function test_setCreateArtFee() public {
    vm.startPrank(owner);
    vm.expectRevert(IPhiFactory.ArtCreatFeeTooHigh.selector);
    phiFactory.setArtCreatFee(10_001);
    vm.stopPrank();
}
```

## Recommended Mitigation Steps


Replace the current upper bound check in the fee-setting functions with an absolute value limit.

```diff
/// @notice Sets the protocol fee percentage.
/// @param protocolFee_ The new protocol fee percentage (in basis points).
function setProtocolFee(uint256 protocolFee_) external onlyOwner {
-   if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
+   if (protocolFee_ > 1 ether) revert ProtocolFeeTooHigh();
    mintProtocolFee = protocolFee_;
    emit ProtocolFeeSet(protocolFee_);
}

/// @notice Sets the art creation fee percentage.
/// @param artCreateFee_ The new art creation fee percentage (in basis points).
function setArtCreateFee(uint256 artCreateFee_) external onlyOwner {
-   if (artCreateFee_ > 10_000) revert ArtCreateFeeTooHigh();
+   if (artCreateFee_ > 1 ether) revert ArtCreateFeeTooHigh();
    artCreateFee = artCreateFee_;
    emit ArtCreateFeeSet(artCreateFee_);
}
```
