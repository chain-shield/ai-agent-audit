# Vulnerability details


## Description

The `BondingCurve` contract implements a bonding curve mechanism to determine token prices based on the current supply. The [`getSellPrice()` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/curve/BondingCurve.sol#L98-L100) is crucial for calculating the price when selling tokens. However, the current implementation calculates the price based on the supply after the sell operation, rather than the current supply before the sale. This leads to a significant undervaluation of tokens being sold, especially for larger amounts.

The `getSellPrice()` function is defined as follows:

```solidity
File: BondingCurve.sol
098:     function getSellPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
099:         return getPrice(supply_ - amount_, amount_);
100:     }

```


The issue lies in the argument passed to the `getPrice()` function. By using `supply_ - amount_`, the function calculates the price based on the reduced supply after the sale, rather than the current supply. This results in a lower price than what sellers should receive.

This incorrect calculation affects other functions in the contract, such as [`getSellPriceAfterFee()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/curve/BondingCurve.sol#L106-L111) and [`getPriceData()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/curve/BondingCurve.sol#L51-L72) , which rely on `getSellPrice()`. As a result, the entire selling mechanism of the protocol is compromised, potentially leading to significant financial losses for users.

## Impact

Users selling tokens will receive significantly less value than they should, especially for large sell orders. This could be exploited by malicious actors to drain value from the system by buying at the correct price and selling at the artificially low price. This directly impacts the valuation of assets and can lead to substantial financial losses for users.

## Proof of Concept

Consider the following scenario:

1. The current token supply is 1000 tokens.
2. Alice wants to sell 100 tokens.
3. The correct price calculation should be `getPrice(1000, 100)`.
4. However, the current implementation calculates `getPrice(900, 100)`.
5. Due to the nature of bonding curves, where price typically increases with supply, `getPrice(900, 100)` will return a significantly lower value than `getPrice(1000, 100)`.

Let's assume a simple linear bonding curve for illustration:
- Correct price: `getPrice(1000, 100) = 100 * (1000/1000) = 100`
- Incorrect price: `getPrice(900, 100) = 100 * (900/1000) = 90`

In this example, Alice receives 10% less value for her tokens than she should.
