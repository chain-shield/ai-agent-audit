# Vulnerability details

## Impact
[signatureClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L327-L346) and [merkleClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L352-L383) both use the internal function [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L702-L721). This does the following check:
```solidity
if (tx.origin != _msgSender() && msg.sender != art.artAddress && msg.sender != address(this)) {
    revert TxOriginMismatch();
}
```

This will revert for smart contract wallets, as those use an EOA as an entry point. The smart wallet would be msg.sender and the EOA would be tx.origin. Therefor this would always revert and those users would be excluded from using the protocol.
