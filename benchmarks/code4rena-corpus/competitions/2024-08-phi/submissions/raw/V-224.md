# Vulnerability details

## Impact
In ```_handleTrade``` in [Cred.sol](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L826), there is no check for whether the priceLimit, maxPrice_ for buys and minPrice_ for sells is equal 0. The function only checks whether the priceLimit is enough to cover price and fees while it is larger than 0. Because of this, if msg.value is enough to cover the cost, trades succeed even when their priceLimit is obviously insufficient, being 0.

An analogous issue occurs for batch trades in [```_validateAndCalculateBatch()```](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L861).

## Proof of Concept
The following is an existing test for a buy action, with 0 passed as maxPrice_, modified to expect a revert, which fails.

```solidity
function test_TradeAction() public {
    _createCred("BASIC", "SIGNATURE", 0x0);
    uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
    assertEq(buyPrice, 1_091_874_359_329_268, "buy price is correct");
    vm.startPrank(anyone);
    
    uint256 maxPrice = 0;
    cred.buyShareCred{ value: buyPrice }(1, 1, 0);
    vm.expectRevert();
    assertEq(cred.isShareHolder(1, anyone), true, "cred 0 is voted by anyone");
}
```

## Recommended Mitigation Steps
Remove ```priceLimit != 0``` from the checks, leaving the function able to revert with a 0 price limit value from comparing it to calculated amounts.

In [```_handleTrade()```](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L614):
```diff
if (isBuy) {
-    if (priceLimit != 0 && price + protocolFee + creatorFee > priceLimit) revert PriceExceedsLimit();
+    if (price + protocolFee + creatorFee > priceLimit) revert PriceExceedsLimit();
    if (supply + amount_ > MAX_SUPPLY) {
        revert MaxSupplyReached();
    }

    if (msg.value < price + protocolFee + creatorFee) {
        revert InsufficientPayment();
    }
} else {
-   if (priceLimit != 0 && price - protocolFee - creatorFee < priceLimit) revert PriceBelowLimit();
+   if (price - protocolFee - creatorFee < priceLimit) revert PriceBelowLimit();
    if (block.timestamp <= lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD) {
        revert ShareLockPeriodNotPassed(
            block.timestamp, lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD
        );
    }
    (, uint256 nums) = shareBalance[credId_].tryGet(curator_);
    if (nums < amount_) {
        revert InsufficientShares();
    }
}
```
