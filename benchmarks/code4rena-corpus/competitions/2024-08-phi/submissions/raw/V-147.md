# Vulnerability details

## Impact

PhiFactory has `processClaim` function https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L723-L758 that allows users to mint their NFTs using a signature (`signatureClaim`) or Merkle proof (`merkleClaim`). The `processClaim` function contains logic to handle excess ETH and send it back to the `msg.sender`. However, this function can be indirectly called by using the PhiNFT1155 contract, which inherits from the `Claimable` abstract contract. Specifically, it can be invoked through the `merkleClaim` (https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/Claimable.sol#L47-L65) and `signatureClaim` (https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/Claimable.sol#L22-L44) functions.

The issue arises when excess ETH is sent through the `Claimable` contract, as the excess ETH will not be returned. In this scenario, the `msg.sender` would be the PhiNFT1155 contract, which implements the `receive` function. Since the `receive` function does not revert, the user would lose their funds.

One example of when this could happen:
1. A user submits a claim.
2. The art creator decides to lower the mint fee by 50%, from 1 ether to 0.5 ether.
3. The art creator's transaction is mined first.
4. Because the user sent the claim with the previous price, he would lose 0.5 ether.

## Proof of Concept:

Insert the following into `Claimable.t.sol`:
```solidity
import { ICreatorRoyaltiesControl } from "../src/interfaces/ICreatorRoyaltiesControl.sol";

function test_claimWithExcessBug() public {
    uint256 artId = 1;
    address artAddress = phiFactory.getArtAddress(artId);

    vm.warp(START_TIME + 2);
    bytes memory data = _createSigSignData(false);
    bytes memory payload = abi.encodePacked(abi.encodeWithSignature("signatureClaim()"), data);

    vm.recordLogs();
    uint256 totalMintFee = phiFactory.getArtMintFee(artId, 1);
    IPhiFactory.ArtData memory originalArt = phiFactory.artData(artId);
    vm.startPrank(originalArt.artist);

    ICreatorRoyaltiesControl.RoyaltyConfiguration memory newRoyaltyConfig = ICreatorRoyaltiesControl.RoyaltyConfiguration({
        royaltyRecipient: address(0x789),
        royaltyBPS: 500 // 5%
    });

    phiFactory.updateArtSettings(
        artId,
        "",
        address(0x456),
        originalArt.maxSupply + 100,
        originalArt.mintFee / 2, // ART CREATOR DECIDES TO DECREASE THE PRICE
        originalArt.startTime,
        originalArt.endTime + 2 days,
        false,
        newRoyaltyConfig
    );
    vm.startPrank(anyone, anyone);
    uint balanceBefore = anyone.balance;
    uint artAddressBalanceBefore = artAddress.balance;
    uint256 realPrice = phiFactory.getArtMintFee(artId, 1);
    (bool success,) = artAddress.call{ value: totalMintFee }(payload);
    require(success, "1155 artAddress.call failed");
    uint balanceAfter = anyone.balance;
    uint artAddressBalanceAfter = artAddress.balance;
    console2.log("SPENT = ", balanceBefore - balanceAfter);
    console2.log("REAL PRICE = ", realPrice);
    console2.log("USER LOST = ",  balanceBefore - balanceAfter - realPrice);
    console2.log("ART CONTRACT RECEIVED ", artAddressBalanceAfter - artAddressBalanceBefore);
}
```

## Tools Used

Foundry

## Recommended Mitigation Steps

Send excess ETH to `tx.origin`, or add an excess ETH handler to the `merkleClaim` and `signatureClaim` functions in the `Claimable` contract.
