# Vulnerability details

## Description
In the `PhiRewards::updateCuratorRewardsDistributor` function, there is a lack of validation for the `curatorRewardsDistributor_` address. The function allows the assignment of any address to the `curatorRewardsDistributor` variable without checking whether the provided address is valid. This could result in the contract accepting an unintended or incorrect address, such as the zero address (address(0)), which might lead to potential issues when the contract attempts to interact with the `curatorRewardsDistributor`.

## Impact
If an invalid address, such as the zero address, is mistakenly assigned to `curatorRewardsDistributor`, it could cause the contract to malfunction. Future interactions that rely on this address, such as calling functions on the `curatorRewardsDistributor`, would likely revert, leading to a denial of service or disrupted reward distribution mechanisms within the protocol. This could negatively impact the functionality and reliability of the contract.

Manual Review

## Recommended Mitigation Steps
Add a validation check in the `PhiRewards::updateCuratorRewardsDistributor` function to ensure that `curatorRewardsDistributor_` is not the zero address. If the address is invalid, the function should revert with an appropriate error message. Example mitigation:

```diff
function updateCuratorRewardsDistributor(address curatorRewardsDistributor_) external onlyOwner {
+    if (curatorRewardsDistributor_ == address(0)) {
+        revert("Invalid curator rewards distributor address");
+    }
    curatorRewardsDistributor = ICuratorRewardsDistributor(curatorRewardsDistributor_);
    emit CuratorRewardsDistributorUpdated(curatorRewardsDistributor_);
}

```
