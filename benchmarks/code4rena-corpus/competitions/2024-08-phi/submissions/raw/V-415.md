# Vulnerability details

The current implementation of the `distribute` function in `CuratorRewardsDistributor.sol` depends on the `depositBatch` function from `RewardControl.sol` for batch distribution. If any recipient within the batch causes the `depositBatch` function to revert (e.g., due to an invalid address or insufficient balance), the entire `distribute` function will revert, causing no recipients to receive their rewards.

## Impact
A single invalid recipient address or other issue within the batch can prevent all recipients from receiving their rewards. This can lead to significant disruption, particularly if distributing rewards to a large number of recipients.

## Recommended Mitigation Steps
Modify the `distribute` function to handle each recipient transfer individually using a try/catch statement, ensuring that a failure for any single recipient does not stop the entire distribution.
