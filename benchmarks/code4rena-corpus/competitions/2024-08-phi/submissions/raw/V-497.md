# Vulnerability details

## Description
In `Cred::createCred()` & `Cred::updateCred()`, creator sends the signedData as param which includes `expiresIn, ... , credURL, credType, verificationType, merkleRoot_`.
Here these params are **signed** by an authorized signer of protocol aka `phiSignerAddress` and before this signing, protocol saves `credURL, credType, merkleAddress` off chain in backend.

A cred creator of in `chain-1` might save this `signedData & signature` and replay it on `chain-2`. Bypassing saving the above mentioned data in the backend.
This would make the information of `chain-1` related data present in the `Cred.sol` contract of `chain-2` but not in the backend of the `chain-2`.

Leading to state mismatch. Although `phiSignerAddress/protocol` did not want this to happen.

## Impact
- `Cred.sol` would have data which is baseless or gibberish, and not data is present at the backend to back it up.
- If some artist tries to represent this `CredId` as an Art, its invalid and still an art would be created with no data to back it up
- If a `minter` tries to claim the art generated via this credId, its almost always gonna revert. Because the Merkle proof is always gonna fail

## Recommended Mitigation Steps
- Add a `nonce` in the signedData, so that it cannot be replayed ever again.
- Add a `chainId` in the signedData & check while creating and updating the credentials, which will make cross-chain replay attack stop

```diff
function createCred() {
        ...
        (
            uint256 expiresIn,
            ,
        +   uint256 nonce,
        +   uint256 chainId,
            address sender,
            address bondingCurve,
            string memory credURL,
            string memory credType,
            string memory verificationType,
            bytes32 merkleRoot_
        ) = abi.decode(signedData_, (uint256, uint256, uint256, uint256, address, 
        uint256, address, string, string, string, bytes32));
        + if (chainId != block.chainid) revert ChainMismatch();
        + if (nonce != storedNonce) revert tx_AlreadyExecuted();
        ...
}
```
