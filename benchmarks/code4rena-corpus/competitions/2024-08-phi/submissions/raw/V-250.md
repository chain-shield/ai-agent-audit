# Vulnerability details

To create an Art a user have to get a valid signature and then call the `createArt` (normally this is handle by the front end) the problem is that the signature is not hashing all the inputs and is not checking that the caller have to be `credCreator` allowing an attacker to front run the `createArt` tx setting the inputs that are not being hashing:

```
        art.uri = createData_.uri;
        art.artist = createData_.artist;
        art.receiver = createData_.receiver;
        art.maxSupply = createData_.maxSupply;
        art.mintFee = createData_.mintFee;
        art.startTime = createData_.startTime;
        art.endTime = createData_.endTime;
        art.soulBounded = createData_.soulBounded;

```

See the next scenario:

1. Creator has a signature an call  `createArt`  function.
2. Attacker see this tx in the mempool take the signature and front run the tx calling the `createArt` with the same signature and with more gas to get his tx execute first.
3. Attacker change all the values and put whatever he want, he can just silence change the receiver.

## Impact
A malicious attacker can front run the  `createArt`  tx setting the values that are not being hashed like the artist, uri, receiver, max Supply, mint fee, see the entire list in the description

## Recommended Mitigation Steps

Consider allow to call the function just by the `credCreator` otherwise consider hashing all the values that are required to complete the `PhiArt` struct.
