# Vulnerability details

## Impact
The implementation of [distribute](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L77-L130) allows anyone to call the function:
```solidty
function distribute(uint256 credId) external {
```

The contract sends the royalty fee to msg.sender [1](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L120):
```soldity
_msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);
```

Therefor the protocol would not be paid their royalty fee.


## Proof of Concept

The poc is done as part of the existing [CuratorRewardsDistributor.t.sol](https://github.com/code-423n4/2024-08-phi/blob/main/test/CuratorRewardsDistributor.t.sol) test. Update [testDistribute](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/test/CuratorRewardsDistributor.t.sol#L37-L95) as displayed below:

```diff

+++ b/CuratorRewardsDistributor.t.sol
@@ -63,7 +63,8 @@ contract CuratorRewardsDistributorTest is Settings {
         uint256 ownerBalance = owner.balance;

         // Distribute rewards
-        vm.prank(owner);
+        address alice = address(0x123);
+        vm.prank(alice);
         curatorRewardsDistributor.distribute(credId);

         // Check final balances
```

The updated test calls `distribute` from a random EOA account called alice. The call does not revert as the function has access rights. The test fails at the [check for the owners balance](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/test/CuratorRewardsDistributor.t.sol#L85-L87), as the owner balance was not increased as expected. Instead the fee was send to alice.
