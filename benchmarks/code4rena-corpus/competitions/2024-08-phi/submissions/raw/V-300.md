# Vulnerability details

##Summary

The _curve function contains a division operation where TOTAL_SUPPLY_FACTOR - targetAmount_ is used as the denominator. If targetAmount_ equals TOTAL_SUPPLY_FACTOR, this results in a division by zero, which will cause the contract to revert. This could potentially disrupt the normal operation of the bonding curve and prevent transactions from being processed correctly.


## Impact
Contract Reversion: Transactions involving _curve calculations could fail.
Service Disruption: Could affect the contract's functionality, leading to potential loss of funds or contract usability issues.


## Proof of Concept

Steps:

Deploy the Contract: Deploy the BondingCurve contract to a test network.

Set the Total Supply Factor: The TOTAL_SUPPLY_FACTOR is set to 1000 ether, and you should be able to control targetAmount_ to reach this value.

Call _curve Function: Manually or through a function, call _curve with targetAmount_ set to 1000 ether.

**Example:**

```
contract Test {
    BondingCurve public bondingCurve;

    function setBondingCurve(address _bondingCurve) external {
        bondingCurve = BondingCurve(_bondingCurve);
    }

    function testCurve() external view returns (uint256) {
        return bondingCurve._curve(1000 ether);
    }
}

```

 Expected Result:

The function call should result in a division by zero error due to the denominator being zero when targetAmount_ is 1000 ether.





## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a check to ensure that targetAmount_ is never equal to TOTAL_SUPPLY_FACTOR before performing the division. For example:

```
require(targetAmount_ < TOTAL_SUPPLY_FACTOR, "Target amount too high");
```
