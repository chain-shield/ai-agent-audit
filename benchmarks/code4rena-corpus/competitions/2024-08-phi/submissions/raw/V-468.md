# Vulnerability details

## Impact
When claiming an NFT from `PhiFactory`, as part of the `MintArgs` the user is allowed to pass a custom `imageURL` as shown here:
```solidity
    struct MintArgs {
        uint256 tokenId;
        uint256 quantity;
        string imageURI;
    }
```
This `imageURI` is set only for the `tokenId` being minted. However as the value passed to `imageURI` is not passed as part of the signature it is possible that this value could be anything including but not limited to:
- Invalid/Broken Links
- Unmoderated/Offensive Content
- Links to Malicious Code

## Proof of Concept
Add the following test to `PhiFactory.t.sol` to show this:
```solidity
    function test_Toad_userSetsRandomImgURI() public {
        address artAddr = _createArtReturnAddr(ART_ID_URL_STRING, false);
        uint256 artId = 1;
        bytes32 advanced_data = bytes32("1");
        bytes memory signData =
            abi.encode(expiresIn, participant, referrer, verifier, artId, block.chainid, advanced_data);
        bytes32 msgHash = keccak256(signData);
        bytes32 digest = ECDSA.toEthSignedMessageHash(msgHash);
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(claimSignerPrivateKey, digest);
        if (v != 27) s = s | bytes32(uint256(1) << 255);
        bytes memory signature = abi.encodePacked(r, s);
        // User sends their own imageURI
        string memory randomURL = "www.somethingweird.xyz";

        bytes memory data =
            abi.encode(1, participant, referrer, verifier, expiresIn, uint256(1), advanced_data, randomURL, signature);
        bytes memory dataCompressed = LibZip.cdCompress(data);
        uint256 totalMintFee = phiFactory.getArtMintFee(1, 1);

        // User mints with their random URL
        vm.startPrank(participant, participant);
        phiFactory.claim{ value: totalMintFee }(dataCompressed);
        vm.stopPrank();

        // Confirm random URI is what gets returned
        string memory randomURI = IPhiNFT1155Uri(artAddr).uri(1, participant);
        console2.log("randomURI", randomURI);
    }

    // Edited _createArt function to return the art contract address
    function _createArtReturnAddr(string memory artIdUrl_, bool soulBounded_) internal returns(address){
        bytes memory credData = abi.encode(1, owner, "SIGNATURE", 31_337, bytes32(0));
        bytes memory signCreateData = abi.encode(expiresIn, artIdUrl_, credData);
        bytes32 createMsgHash = keccak256(signCreateData);
        bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
        (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
        if (cv != 27) cs = cs | bytes32(uint256(1) << 255);
        IPhiFactory.CreateConfig memory config =
            IPhiFactory.CreateConfig(artCreator, receiver, END_TIME, START_TIME, MAX_SUPPLY, MINT_FEE, soulBounded_);
        address artAddr = phiFactory.createArt{ value: NFT_ART_CREATE_FEE }(signCreateData, abi.encodePacked(cr, cs), config);
        return artAddr;
    }
```

## Recommended Mitigation
It is recommended that the the protocol's frontend performs at least some basic validations on the `imageURI` passed by a user. The `imageURI` should then be part of the data signed by `phiSignerAddress` to confirm the user cannot set their `imageURI` to any arbitrary string, as is already the case with the `uri_` passed when calling `PhiFactory::createArt`.
