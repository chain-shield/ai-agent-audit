# Vulnerability details

## Impact
Users can claim an NFT via the `PhiNFT1155.sol`, which inherits `Claimable.sol`, with `Claimable:signatureClaim` or `Claimable:merkleClaim`. 
In `Claimable:signatureClaim` or `Claimable:merkleClaim` the whole `msg.value` is passed to the `PhiFactory.sol`.
`PhiFactory.sol` returns the excess value, but it returns it to the `_msgSender`, which will be the `PhiNFT1155.sol` and not the user.
These funds will be locked since the `PhiNFT1155.sol` has a receive function, which is `"intentionally left empty to allow the contract to receive ETH"`
Users may lose funds when claiming an NFT and lock them inside `PhiNFT1155.sol`

## Proof of Concept
Please Open the `Claimable.t.sol` test file and place the following test at the bottom:

```javascript
function test_user_lose_funds() public {
    uint256 artId = 1;
    address artAddress = phiFactory.getArtAddress(artId);

    bytes memory data = _createSigSignData(false);
    bytes memory payload = abi.encodePacked(abi.encodeWithSignature("signatureClaim()"), data);

    vm.startPrank(anyone, anyone);
    uint256 anyoneInitialBalance = 3 ether;
    vm.deal(anyone, anyoneInitialBalance);

    assertEq(artAddress.balance, 0);

    uint256 totalMintFee = phiFactory.getArtMintFee(artId, 1);
    uint256 sentValue = 3 ether;

 (bool success,) = artAddress.call{ value: sentValue }(payload);
    require(success, "1155 artAddress.call failed");

    assertEq(artAddress.balance, sentValue - totalMintFee);
    assertEq(anyone.balance, anyoneInitialBalance - sentValue);
}
```
