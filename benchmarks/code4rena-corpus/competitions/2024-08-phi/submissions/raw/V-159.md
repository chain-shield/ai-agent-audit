# Vulnerability details

## Impact
The withdrawWithSig function in the provided smart contract code allows users to authorize the transfer of tokens from one address to another using an off-chain signature. The function includes a deadline parameter intended to limit the validity period of the signature. However, the current implementation has a subtle flaw where transfers can still be executed at the exact moment when block.timestamp equals deadline. This creates a potential edge case where users may assume their signature has expired, but it is still valid for one more block. This report analyzes the implications of this issue and provides recommendations for addressing it.

A malicious actor aware of this behavior could craft transactions to be executed exactly at the deadline timestamp, enabling them to execute a withdrawal at the last possible moment. This could be particularly problematic in high-frequency or high-value transactions.

manual analysis

## Recommended Mitigation Steps
The condition now uses >= instead of >. This change ensures that any transaction mined at block.timestamp equal to or greater than the deadline will revert, preventing the function from executing the withdrawal.
