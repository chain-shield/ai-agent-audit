# Vulnerability details

## Impact
As mentioned in the docs of the Phi Protocol -> https://docs.philand.xyz/explore-phi/developers/architecture

> The Cred, PhiFactory, and PhiNFT1155 contracts use the UUPS upgradeability pattern and can be upgraded by the owner.

However, in the current implementation its **not possible to upgrade** a `PhiNFT1155` contract. The upgrade functionality is limited to the owner/initializer of the `PhiNFT1155` contract. 

The problem arises, because the `PhiFactory` is the one deploying proxies that point to `PhiNFT1155`, but it lacks functionality to upgrade a deployment of `PhiNFT1155`.

## Proof of Concept

Creation of a new PhiNFT1155 happens when new art is being created, eventually in the flow after calling `createArt` the `_createNewNFTContract` is called to create the NFT.

The `_createNewNFTContract` uses Solady's LibClone to create Minimal proxy using [ERC1167](https://eips.ethereum.org/EIPS/eip-1167) proxy pattern. 
- [Solady LibClone](https://github.com/Vectorized/solady/blob/main/src/utils/LibClone.sol)

```solidity
    function _createNewNFTContract(.....)
    {
        address payable newArt =
@>>         payable(erc1155ArtAddress.cloneDeterministic(keccak256(abi.encodePacked(block.chainid, newArtId, credId))));
.....
```

The `initialize` function in the `PhiNFT1155.sol` contract is called, and the owner is set to `msg.sender`, which is the `PhiFactory.sol` contract.

```solidity
  function initialize(.....)
        external
        initializer
    {
@>>     __Ownable_init(msg.sender);
.....
```

Since the _authorizeUpgrade in PhiNFT1155.sol is overridden with `onlyOwner`, only the owner, i.e. the PhiFactory can call `upgradeTo` function to upgrade the implementation.

```solidity
@>> function _authorizeUpgrade(address newImplementation) internal override onlyOwner {
        // This function is intentionally left empty to allow for upgrades
    }
```

**Conclusion**:
Since upgrading the PhiNFT1155 is limited to the owner, which is the PhiFactory, and the PhiFactory does not have any logic to allow upgrading the NFTs we are essentially unable to do so.

## Tools Used
Manual review

## Recommended Mitigation Steps

A possible solution to allow the owner of the PhiFactory to upgrade the implementation for the different PhiNFT1155s would be to add a method in PhiFactory that calls the upgradeTo function in a specific minimal proxy deployment.
