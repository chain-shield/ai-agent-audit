# Vulnerability details


## Description
In the current implementation of the `Cred:_handleTrade`, & `PhiFactory:signatureClaim` functions, signatures that are used exactly at the expiration timestamp are incorrectly rejected. This behavior is not consistent with the standard practice of allowing signatures to be valid up until the exact moment of expiration.

The relevant section of code checks the expiration timestamp of the signature as follows:

```solidity
if (expiresIn_ <= block.timestamp) revert SignatureExpired();
```
This logic implies that any signature used at the exact second of expiration (`expiresIn_ == block.timestamp`) will be considered expired, which is not aligned with best practices. According to `EIP-2612`, signatures should be valid until the end of the specified expiration time, including the moment when the `expiresIn_` is equal to `block.timestamp`. This approach ensures that users can utilize the signature up until the very last moment, thereby providing a better user experience and avoiding unnecessary transaction failures.
## Impact
Users who attempt to execute a trade or claim exactly at the expiration time may find their transactions rejected due to the signature being considered expired. This could lead to confusion and frustration, especially in time-sensitive scenarios. Valid signatures that should be accepted are instead causing transaction failures. This could potentially lead to missed opportunities or financial losses for users, especially in a high-frequency trading environment or during time-critical operations.

The current implementation is inconsistent with established standards like `EIP-2612`, which clearly states that signatures should be valid until the exact expiration time. This inconsistency could result in reduced interoperability and predictability for developers and users familiar with the `EIP-2612` behavior.

Manual Review

## Recommendation
The expiration check should be adjusted to ensure that signatures are valid up until the exact expiration time. The revised code should be:

```solidity
if (expiresIn_ < block.timestamp) revert SignatureExpired();
```
This change ensures that signatures will be accepted as long as the current time is less than or equal to the expiration time, aligning with the intent of allowing signatures to be valid until the precise expiration moment.
