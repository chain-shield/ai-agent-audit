# Vulnerability details

## Impact
Users of the Cred system may suffer financial losses due to inconsistent buy and sell prices. An attacker could exploit these inconsistencies to manipulate the market and profit at the expense of other users.

## Proof of Concept
The incorrect calculation of buy and sell prices in the `BondingCurve` contract will cause inconsistent pricing for users of the Cred system. An attacker can exploit this vulnerability by strategically buying and selling creds to take advantage of the price discrepancies.

The `getPrice` function calculates the price based on the current supply and the amount being bought or sold.
```solidity
function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
    return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
}
```
However, this calculation does not take into account the actual state changes that occur after a buy or sell operation. As a result, the prices returned by this function can become stale and inconsistent with the true state of the system.

Steps.
1. The `buyShareCred` function in `Cred.sol` needs to be called to update the supply and perform a buy operation.
2. The `sellShareCred` function in `Cred.sol` needs to be called to update the supply and perform a sell operation.

**Scenario**

   * `buyShareCred` is called with `credId = 1` and `amount = 1`, which succeeds.
   * `sellShareCred` is called with the same `credId` and `amount`, which also succeeds.

However, the expected buy and sell prices after these operations do not match the actual prices returned by the `getCredBuyPrice` and `getCredSellPrice` functions.

The bug lies in the `BondingCurve.sol` contract. Specifically, the issue is in the `getPrice` function: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/curve/BondingCurve.sol#L47-L49
```solidity
function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
    return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
}
```
The `getPrice` function calculates the price based on the current supply and the amount being bought or sold. However, it does not take into account the actual state changes that occur after a buy or sell operation.

1. The attacker monitors the Cred system and identifies a cred with inconsistent buy and sell prices.
2. The attacker calls the `buyShareCred` function to purchase a significant amount of the cred at the lower buy price.
3. The attacker then immediately calls the `sellShareCred` function to sell the same amount of the cred at the higher sell price.
4. Due to the price inconsistency, the attacker profits from the difference between the buy and sell prices.
5. The attacker repeats this process, exploiting the price discrepancies to accumulate profits at the expense of other users.

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the `getPric`e function in BondingCurve.sol to accurately calculate the prices based on the updated supply after a buy or sell operation.
```diff
- function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
+ function getPrice(uint256 supply_, uint256 amount_, bool isBuy) public view returns (uint256) {
+     uint256 updatedSupply = isBuy ? supply_ + amount_ : supply_ - amount_;
-     return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
+     return _curve(updatedSupply * 1 ether) - _curve(supply_ * 1 ether);
  }
```
