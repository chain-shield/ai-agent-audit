# Vulnerability details

## Impact

When a user calls `PhiFactory::createArt` with more ETH than the `artFee` required, either by mistake or by assuming that any excess ETH would be refunded to his account, this excess ETH will instead be refunded to the `PhiFactory` contract itself.

Although the `PhiFactory` defines a `withdraw` function allowing the owner to withdraw ETH held by this contract ot the `protocolFeeDestination` contract, we still consider this a HIGH severity issue as funds could be misused/misdistributed once in the `protocolFeeDestination` contract.

## Proof of Concept

Let's have a look at the [`PhiFactory::createArt`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L196-L213) function below

```javascript
    function createArt(
        bytes calldata signedData_,
        bytes calldata signature_,
        CreateConfig memory createConfig_
    )
        external
        payable
        nonReentrant
        whenNotPaused
        returns (address)
    {
        _validateArtCreationSignature(signedData_, signature_);
        (, string memory uri_, bytes memory credData) = abi.decode(signedData_, (uint256, string, bytes));
        ERC1155Data memory erc1155Data = _createERC1155Data(artIdCounter, createConfig_, uri_, credData);
        address artAddress = createERC1155Internal(artIdCounter, erc1155Data);
        artIdCounter++;
        return artAddress;
    }
```

this function in turns calls [`createERC1155Internal`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L551-L568)

```javascript
    function createERC1155Internal(uint256 newArtId, ERC1155Data memory createData_) internal returns (address) {
        // Todo check if artid exists, if artid exists, reverts
        _validateArtCreation(createData_);
        PhiArt storage currentArt = arts[newArtId];
        _initializePhiArt(currentArt, createData_);

        (uint256 credId,, string memory verificationType, uint256 credChainId,) =
            abi.decode(createData_.credData, (uint256, address, string, uint256, bytes32));

        address artAddress;
        if (credNFTContracts[credChainId][credId] == address(0)) {
            artAddress = _createNewNFTContract(currentArt, newArtId, createData_, credId, credChainId, verificationType);
        } else {
            artAddress = _useExistingNFTContract(currentArt, newArtId, createData_, credId, credChainId);
        }

        return artAddress;
    }
```

let's assume `credNFTContracts[credChainId][credId] == address(0)` for the sake of this proof of concept, we then call the `_createNewNFTContract` function below

```javascript
    function _createNewNFTContract(
        PhiArt storage art,
        uint256 newArtId,
        ERC1155Data memory createData_,
        uint256 credId,
        uint256 credChainId,
        string memory verificationType
    )
        private
        returns (address)
    {
        address payable newArt =
            payable(erc1155ArtAddress.cloneDeterministic(keccak256(abi.encodePacked(block.chainid, newArtId, credId))));

        art.artAddress = newArt;

        IPhiNFT1155Ownable(newArt).initialize(credChainId, credId, verificationType, protocolFeeDestination);

        credNFTContracts[credChainId][credId] = address(newArt);

        (bool success_, bytes memory response) =
            newArt.call{ value: msg.value }(abi.encodeWithSignature("createArtFromFactory(uint256)", newArtId));

        if (!success_) revert CreateFailed();
        uint256 tokenId = abi.decode(response, (uint256));
        emit ArtContractCreated(createData_.artist, address(newArt), credId);
        emit NewArtCreated(createData_.artist, credId, credChainId, newArtId, createData_.uri, address(newArt), tokenId);

        return address(newArt);
    }
```

on line 641, the `PhiNFT1155::createArtFromFactory` is called by its identifier, and is passed the initial `msg.value` sent by user in the initial transaction.
Let's have a look at the `PhiNFT1155::createArtFromFactory` function

```javascript
    function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
        _artIdToTokenId[artId_] = tokenIdCounter;
        _tokenIdToArtId[tokenIdCounter] = artId_;

        uint256 artFee = phiFactoryContract.artCreateFee();

        protocolFeeDestination.safeTransferETH(artFee);
        emit ArtCreated(artId_, tokenIdCounter);
        uint256 createdTokenId = tokenIdCounter;

        unchecked {
            tokenIdCounter += 1;
        }
        // @audit what happens when artFee is greater??
        if ((msg.value - artFee) > 0) {
            _msgSender().safeTransferETH(msg.value - artFee);
        }

        return createdTokenId;
    }
```

we see that the intend is to refund the excess ETH to the user via

```javascript
if ((msg.value - artFee) > 0) {
    _msgSender().safeTransferETH(msg.value - artFee);
}
```

However, here `_msgSender()` is the `PhiFactory` contract and NOT the inital sender, meaning the excess ETH will be sent to this contract and not the the initial user. Meaning these funds could be potentially misused/misdistributed.

In fact, `_msgSender()` is inherited from the `ERC1155SupplyUpgradeable` which itself inherits from the `ContextUpgradable` contract from openzeppelin, defined as below

```javacript
    function _msgSender() internal view returns (address payable) {
        return msg.sender;
    }
```

so it simply returns the `msg.sender` which in this case is the sending contract i.e. `PhiFactory`.

## Recommended Mitigation Steps

To avoid this issue, it would make sense to refund any excess ETH before entering the `PhiNFT1155` contract.

For example, we could modify the function as below

```diff
    function createArt(
        bytes calldata signedData_,
        bytes calldata signature_,
        CreateConfig memory createConfig_
    )
        external
        payable
        nonReentrant
        whenNotPaused
        returns (address)
    {

+        if ((msg.value - artCreateFee) > 0) {
+            _msgSender().safeTransferETH(msg.value - artFee);
+        }

        _validateArtCreationSignature(signedData_, signature_);
        (, string memory uri_, bytes memory credData) = abi.decode(signedData_, (uint256, string, bytes));
        ERC1155Data memory erc1155Data = _createERC1155Data(artIdCounter, createConfig_, uri_, credData);
        address artAddress = createERC1155Internal(artIdCounter, erc1155Data);
        artIdCounter++;
        return artAddress;
    }
```
