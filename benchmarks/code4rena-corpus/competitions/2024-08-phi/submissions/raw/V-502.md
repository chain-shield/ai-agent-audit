# Vulnerability details

## Impact
The `getPriceData` function in the smart contract calculates the price, protocol fee, and creator fee based on the provided `credId_`, `supply_`, `amount_`, and `isSign_`. However, the function does not verify whether the `credId_` provided corresponds to a valid and existing creator or royalty information within the credContract. This could behave unexpectedly and would eat up unnecessary gas.

## Proof of Concept  
This is the code of `curve/BondingCurve.sol::getPriceData` and it's clear that there is no validation which is checking if `credId_` exists or not. It is passed to the `getCreatorRoyalty` 
```
    function getPriceData(
        uint256 credId_,
        uint256 supply_,
        uint256 amount_,
        bool isSign_
    )
        public
        view
        returns (uint256 price, uint256 protocolFee, uint256 creatorFee)
    {
        (uint16 buyShareRoyalty, uint16 sellShareRoyalty) = credContract.getCreatorRoyalty(credId_);

        price = isSign_ ? getPrice(supply_, amount_) : getPrice(supply_ - amount_, amount_);

        protocolFee = _getProtocolFee(price);
        if (supply_ == 0) {
            creatorFee = 0;
            return (price, protocolFee, creatorFee);
        }
        uint16 royaltyRate = isSign_ ? buyShareRoyalty : sellShareRoyalty;
        creatorFee = (price * royaltyRate) / RATIO_BASE;
    }
```

```
        uint256 credId_,
        uint256 supply_,
        uint256 amount_,
        bool isSign_
    )
        public
        view
        returns (uint256 price, uint256 protocolFee, uint256 creatorFee)
    {
+       if (!credContract.isExist(credId_)) {

        protocolFee = _getProtocolFee(price);
        if (supply_ == 0) {
            creatorFee = 0;
            return (price, protocolFee, creatorFee);
        }
        uint16 royaltyRate = isSign_ ? buyShareRoyalty : sellShareRoyalty;
        creatorFee = (price * royaltyRate) / RATIO_BASE;

```

The following code was added : 
```
if (!credContract.isExist(credId_)) {
    return (0,0,0);
}
```
This would firstly validate the credId_ and then further pass the parameters and calculate the functions. This won't show falsified data to the user due to  improper input and also help to save gas.
