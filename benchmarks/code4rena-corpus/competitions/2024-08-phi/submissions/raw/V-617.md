# Vulnerability details

## Impact
Corruptible Upgradability Pattern

## Proof of Concept
Storage gaps in upgradable Solidity contracts are essential to prevent accidental data overwrites. By leaving empty spaces between data variables, these gaps ensure compatibility between different contract versions and facilitate smooth upgrades. This approach helps maintain the integrity and adaptability of the contract throughout its lifecycle.

Without storage gaps in parent contracts, upgradable child contracts risk data corruption. New variables in child contracts might overwrite existing data, leading to serious consequences.

```solidity 
contract PhiNFT1155 is
    //..
    CreatorRoyaltiesControl //@audit no storage gaps 
{
```
`PhiNFT1155 ` contract is suppossed to be an upgradeable contract which inherits from  `CreatorRoyaltiesControl ` . But this parent contract does not implement any storage gaps which may lead to serious consequences while upgrading ! 

## Tools Used
Manual Review ! 
## Recommended Mitigation Steps
Add storage gaps to `CreatorRoyaltiesControl ` contract tp maintain a consistent storage layout between upgrades .
