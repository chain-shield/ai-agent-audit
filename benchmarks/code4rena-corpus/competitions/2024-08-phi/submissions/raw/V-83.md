# Vulnerability details

## Impact
'abi.encodePacked()' should not be used with dinamyc types when passing the result to a hash function such as 'keccak256()' which caused hash collision. 


From the solidity documentation: https://docs.soliditylang.org/en/v0.8.17/abi-spec.html?highlight=collisions#non-standard-packed-mode > If you use keccak256(abi.encodePacked(a, b)) and both a and b are dynamic types, it is easy to craft collisions in the hash value by moving parts of a into b and vice-versa. More specifically, abi.encodePacked("a", "bc") == abi.encodePacked("ab", "c").

## Proof of Concept

As the solidity docs describe, two or more dynamic types are passed to abi.encodePacked. Moreover, these dynamic values are user-specified function arguments in external functions, meaning anyone can directly specify the value of these arguments when calling the function. 

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.25;

import "forge-std/Test.sol";
import "../src/PhiFactory.sol";
import "../src/interfaces/IPhiNFT1155Ownable.sol";
import "../src/interfaces/IPhiRewards.sol";

contract PhiFactoryTest is Test {
    PhiFactory factory;
    address phiSignerAddress = address(0x123);
    address protocolFeeDestination = address(0x456);
    address erc1155ArtAddress = address(0x789);
    address phiRewardsAddress = address(0xabc);
    address ownerAddress = address(this);
    uint256 protocolFee = 100;
    uint256 artCreateFee = 200;

    function setUp() public {
        factory = new PhiFactory();
        factory.initialize(
            phiSignerAddress,
            protocolFeeDestination,
            erc1155ArtAddress,
            phiRewardsAddress,
            ownerAddress,
            protocolFee,
            artCreateFee
        );
    }

    function testHashCollision() public {
        // Prepare data for hash collision
        address minter = address(0xdef);
        bytes32 leafPart1 = keccak256(abi.encodePacked("data1"));
        bytes32 leafPart2 = keccak256(abi.encodePacked("data2"));

        // Ensure leafPart1 and leafPart2 cause a collision when encoded
        assertEq(keccak256(abi.encodePacked(minter, leafPart1)), keccak256(abi.encodePacked(minter, leafPart2)));

        // Set up the Merkle root to match the collision
        uint256 credChainId = 1;
        uint256 credId = 1;
        bytes32 merkleRoot = keccak256(abi.encodePacked(minter, leafPart1));
        factory.credMerkleRoot(credChainId, credId) = merkleRoot;

        // Attempt to claim with both leaf parts
        bytes32[] memory proof = new bytes32[](1);
        proof[0] = keccak256(abi.encodePacked(minter, leafPart1));

        // This should pass due to the collision
        factory.merkleClaim(proof, abi.encode(minter, address(0), 1), MintArgs(1, 1, ""), leafPart1);

        // This should also pass due to the collision
        factory.merkleClaim(proof, abi.encode(minter, address(0), 1), MintArgs(1, 1, ""), leafPart2);
    }
}
```

## Recommended Mitigation Steps
Unless there is a compelling reason, abi.encode should be preferred which will pad items to 32 bytes which will prevent hash collision. If there is only one argument to abi.encodePacked() it can often be cast to bytes() or bytes32() instead. If all arguments are strings and or bytes, bytes.concat() should be used instead.

Instead of writing functions to accept several arguments that are hashed inside the function, consider rewriting the function to take the hashed value as a function argument directly so that the hashing process happens off-chain. This approach would solve the issue and save gas.
