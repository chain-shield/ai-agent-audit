# Vulnerability details


## Description
The `getTotalMintFee` function is responsible for calculating the total mint fee for multiple art items. It takes in two arrays as input: `artId_` (an array of art IDs) and `quantitys_` (an array of corresponding quantities). The function then iterates over these arrays to calculate the total mint fee.

However, the function does not check whether the lengths of the two input arrays are equal before starting the loop. If the `quantitys_` array is shorter than the `artId_` array, accessing an element of quantitys_ beyond its length could cause an out-of-bounds error. If the `quantitys_` array is longer than the `artId_` array, the extra quantities would be ignored, potentially resulting in an underestimation of the total mint fee.
## Impact
An out-of-bounds error could cause the transaction to revert, leading to an unexpected failure in the contract's operation. If the function does not account for all quantities correctly due to mismatched array lengths, users may end up paying incorrect mint fees, which could result in financial discrepancies.
## Tools Used
Manual Review

## Recommendation
To mitigate this issue, it is recommended to add a validation check at the beginning of the `getTotalMintFee` function to ensure that the lengths of the `artId_` and `quantitys_` arrays are equal.
