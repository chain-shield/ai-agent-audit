# Vulnerability details

## Impact

The `supportsInterface` function in the `PhiNFT1155` contract does not explicitly check for the `IERC2981` interface, which is the standard interface for NFT royalties. This could lead to a situation where marketplaces or other contracts that rely on `supportsInterface` to determine royalty support may incorrectly conclude that the contract does not support royalties. As a result, they may not collect or forward royalty fees to the creators, leading to a potential loss of revenue.

The implementation of the `supportsInterface` (EIP-165) within the contract is incorrect, potentially leading to a loss of assets, as shown in the scenario below:

>A marketplace wants to determine if the PhiNFT1155 contract supports the [ERC-2981](https://eips.ethereum.org/EIPS/eip-2981) (NFT Royalty Standard) or has royalties by calling the PhiNFT1155.supportsInterface function. Since the PhiNFT1155.supportsInterface function returns false, the marketplace concluded that the PhiNFT1155 does not support ERC-2981 or does not have royalties. Thus, the marketplace will not collect royalties from the buyers and will not forward the royalties to the creators, leading to a loss of royalty fees for them.

## Proof of Concept
The `supportsInterface` function in the `PhiNFT1155` contract is implemented as follows:
https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L216-L225

```solidity
function supportsInterface(bytes4 interfaceId)
    public
    view
    virtual
    override(CreatorRoyaltiesControl, ERC1155Upgradeable, IERC165)
    returns (bool)
{
    return super.supportsInterface(interfaceId) || interfaceId == type(IPhiNFT1155).interfaceId
        || ERC1155Upgradeable.supportsInterface(interfaceId);
}
```
The function relies on `super.supportsInterface(interfaceId)` to check for supported interfaces, including `IERC2981`.
However, if the inheritance chain does not properly implement `supportsInterface` for `IERC2981`, the function may return `false` for the royalty interface.
This could lead to a scenario where a marketplace or another contract incorrectly determines that the `PhiNFT1155` contract does not support the `IERC2981` interface, resulting in the failure to collect and distribute royalty fees.


## Recommended Mitigation Steps
To ensure that the `supportsInterface` function correctly reports support for all relevant interfaces, including `IERC2981`, the function should be updated to explicitly check for the `IERC2981` interface. 

```diff
function supportsInterface(bytes4 interfaceId)
    public
    view
    virtual
    override(CreatorRoyaltiesControl, ERC1155Upgradeable, IERC165)
    returns (bool)
{
    return
        super.supportsInterface(interfaceId) ||
        interfaceId == type(IPhiNFT1155).interfaceId ||
+       interfaceId == type(IERC2981).interfaceId ||
        ERC1155Upgradeable.supportsInterface(interfaceId);
}
```
