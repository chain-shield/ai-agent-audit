# Vulnerability details


## Description
The `_validateAndCalculateBatch` function is designed to handle the validation and calculation of prices when processing batch transactions in the `Cred` contract. This function plays a crucial role in ensuring that the prices for buying or selling shares are within the user-defined limits (priceLimit) for each transaction in the batch. However, the current implementation lacks comprehensive validation of the priceLimit parameter, leading to potential issues when executing batch transactions.

The `priceLimit` parameter is intended to act as a safeguard, ensuring that transactions are only executed if the prices are within the acceptable range specified by the user. However, in the `_validateAndCalculateBatch` function, there is no explicit validation to ensure that the `priceLimit` values provided are non-zero, consistent, and correctly applied across all transactions in the batch. 

Without proper validation, there is a risk that transactions could be executed at prices that exceed the user’s intended limits. For instance, if the priceLimit is inadvertently set to zero or is not checked against the calculated prices, the transaction may proceed at an unfavorable rate, causing financial loss to the user.
## Impact
Users may unknowingly execute transactions at prices higher than their intended limits, leading to potential financial losses, especially in volatile markets.

Manual Review

## Recommendation
Ensure that `priceLimit` array length is validated as done for amounts array. 
```solidity
if (length != priceLimit.length) {
    revert InvalidArrayLength();
}
```
