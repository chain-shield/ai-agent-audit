# Vulnerability details

The distribute function calls _msgSender().safeTransferETH to send funds to the caller. If the caller's contract is malicious, it could re-enter the distribute function before the transfer is complete, leading to multiple distributions of the same funds.
If _msgSender() is a contract, that contract can have a fallback function or receive function that is triggered on receiving ETH.
The fallback function can re-enter the distribute function before the first call has completed, potentially causing multiple distributions of the same funds.
A malicious contract can implement a fallback or receive function that calls the distribute function again.


contract Malicious {
    CuratorRewardsDistributor distributor;

    constructor(address _distributor) {
        distributor = CuratorRewardsDistributor(_distributor);
    }

    receive() external payable {
        distributor.distribute(1); // Re-enter distribute function
    }
}

The attacker deposits funds and then calls the distribute function.
The transfer to the malicious contract triggers its fallback or receive function.
The fallback function re-enters the distribute function, potentially causing duplicate distributions.

Mitigation
To mitigate this issue, you can
1. use a reentrancy guard to prevent multiple re-entrances into critical functions. For example:


import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract CuratorRewardsDistributor is ReentrancyGuard {
    // Existing code

    function distribute(uint256 credId) external nonReentrant {
        // Function implementation
    }
}
Update State Before Transfer:

2.Update the state of the contract before making any external calls (like transfers). This ensures that the critical state is set before the external call is made.

function distribute(uint256 credId) external nonReentrant {
    // Update state
    uint256 totalBalance = balanceOf[credId];
    balanceOf[credId] = 0; // Set balance to 0 before transferring funds

    // Perform transfer
    uint256 royaltyfee = (totalBalance * withdrawRoyalty) / RATIO_BASE;
    uint256 distributeAmount = totalBalance - royaltyfee;
    _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);

    // Continue with distribution
    phiRewardsContract.depositBatch{ value: actualDistributeAmount }(
        distributeAddresses, amounts, reasons, "deposit from curator rewards distributor"
    );

    emit RewardsDistributed(
        credId, _msgSender(), royaltyfee + distributeAmount - actualDistributeAmount, distributeAmount, totalBalance
    );
}
