# Vulnerability details


## Description
The `Claimable` contract contains two external functions, `signatureClaim` and `merkleClaim`, intended to handle different types of claims within the system. These functions are supposed to interact with the `IPhiFactory` contract to process claims. However, there is a critical mismatch between the function signatures in the `Claimable` contract and the corresponding functions defined in the `IPhiFactory` interface.

The `signatureClaim` function in the `Claimable` contract does not accept any parameters explicitly. Instead, it decodes the required data from the transaction's calldata within the function itself. This differs from the `signatureClaim` function in the `IPhiFactory` interface, which explicitly requires three parameters: `signature`, `encodeData`, and `MintArgs`.

Similarly, the `merkleClaim` function in the `Claimable` contract also does not accept any parameters explicitly and decodes the necessary data from the transaction's calldata. In contrast, the `merkleClaim` function in the `IPhiFactory` interface requires four parameters: `proof`, `encodeData`, `MintArgs`, and `leafPart`.

When the `Claimable` contract calls the `signatureClaim` or `merkleClaim` functions on the `IPhiFactory` contract, it passes the decoded data as arguments. However, due to the mismatch in function signatures, the `IPhiFactory` contract expects these parameters to be passed explicitly, leading to failures in execution. Specifically, the IPhiFactory contract will not receive the necessary parameters in the expected format, causing the transaction to revert. This can result in the claims not being processed, leading to a significant disruption in the functionality of the system.
## Impact
Users attempting to process claims through the Claimable contract will encounter failures due to the incorrect function signatures. This will prevent them from successfully claiming their assets, leading to potential financial losses and frustration. 
## Tools Used
Manual Review

## Recommendation
The `Claimable` contract should be updated to align its function signatures with those defined in the `IPhiFactory` interface. This involves modifying the `signatureClaim` and `merkleClaim` functions to accept the required parameters explicitly, as defined in the `IPhiFactory` interface.
