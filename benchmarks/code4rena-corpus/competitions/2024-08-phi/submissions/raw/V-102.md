# Vulnerability details

## Impact

The `PhiNFT1155` contract, according to the protocol's logic flow, should be deployed using the `PhiFactory` (as referenced here: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L631-L632) so that the `PhiFactory` has full control over it and becomes the owner of this contracе. However, the issue is that the `PhiNFT1155` contract is a proxy contract, designed with the intention of allowing upgrades. But since the `PhiFactory` lacks any wrapper function to perform upgrades, it is currently impossible to upgrade the contract.

## Proof of Concept

1. The `authorizeUpgrade` function for the `PhiNFT1155` contract is overridden so that only the owner has the ability to upgrade it, as seen here: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L352.  
2. The owner of the `PhiNFT1155` contract is always the `PhiFactory` contract, as indicated here: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L631-L632.  
3. However, if we examine the `PhiFactory` contract, we find that there is no function available for upgrading the `PhiNFT1155` contract, leading to the inability to upgrade `PhiNFT1155` at all.

## Tools Used
Manual review.

## Recommended Mitigation Steps

Add a wrapper function for upgrading `PhiNFT1155`, similar to how the pause/unpause functions are implemented (as seen here: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L170-L172).
