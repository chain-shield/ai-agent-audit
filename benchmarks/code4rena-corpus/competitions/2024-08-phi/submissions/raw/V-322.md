# Vulnerability details

## Impact
Art creator can set up a 100% royalty fee

## Proof of Concept
The _updateRoyalties() is called by PhiNFT1155.sol in the updateRoyalties() and no checks exist about the value that's being set to the royalty fee, so the artist (it has an modifier that checks the role, must be an artist) can set it to 100%, and the user will lose of all his funds in the tx if that happens.

The royalty functionality is related to the EIP-2981, so the value that's set will be used by the marketplace.

## Tools Used
Manual review

## Recommended Mitigation Steps
Simple, add a validation that's checks the value before it is being set.


## Assessed type

Invalid Validation
