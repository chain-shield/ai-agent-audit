# Vulnerability details

Insufficient payment validation in `createCred` will cause the function to revert for creators as they will be unable to create new creds even when the contract is not paused.

### Root Cause
In Cred.sol, the [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L242) function calls [buyShareCred(credIdCounter, 1, 0)](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L570) after creating a new cred, without ensuring that sufficient `msg.value` is provided to cover the price, protocol fee, and creator fee for this initial share purchase.
```solidity
function createCred(
    address creator_,
    bytes calldata signedData_,
    bytes calldata signature_,
    uint16 buyShareRoyalty_,
    uint16 sellShareRoyalty_
)
    public
    payable
    whenNotPaused
{
    // ...

    buyShareCred(credIdCounter, 1, 0);

    // ...
}
```
After creating a new cred, `createCred` calls `buyShareCred(credIdCounter, 1, 0)` to buy 1 share of the newly created cred. However, it doesn't ensure that sufficient `msg.value` is provided to cover the price, protocol fee, and creator fee for this purchase.

If `createCred` is called with `msg.value = 0`, the subsequent `buyShareCred` call will revert due to insufficient payment, causing `createCred` to revert even when the contract is not paused.

## Impact
The creators suffer an inability to create new creds when the provided `msg.value` is insufficient to cover the initial share purchase, even if the contract is not paused.

## Proof of Concept
**Internal pre-conditions**

1. The contract is not paused.
2. The `msg.value` sent with the `createCred` call is less than the required amount for the initial share purchase.

**Attack Path**

1. Creator calls [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232) with valid parameters but insufficient `msg.value`.
2. Inside `createCred`, a new cred is created, and [buyShareCred(credIdCounter, 1, 0)](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L570) is called.
3. `buyShareCred` reverts due to insufficient payment, causing `createCred` to revert.

## Tools Used
Manual review

## Recommended Mitigation Steps
`createCred` should either:

Require a minimum `msg.value` that covers the price, protocol fee, and creator fee for the initial share purchase.
```diff
function createCred(
    address creator_,
    bytes calldata signedData_,
    bytes calldata signature_,
    uint16 buyShareRoyalty_,
    uint16 sellShareRoyalty_
)
    public
    payable
    whenNotPaused
{
    // ...

+   uint256 initialSharePrice = getCredBuyPriceWithFee(credIdCounter, 1);
+   require(msg.value >= initialSharePrice, "Insufficient payment for initial share purchase");

    buyShareCred(credIdCounter, 1, 0);

    // ...
}
```

2. Handle the case when `buyShareCred` reverts due to insufficient payment and avoid propagating the revert to `createCred`.

```diff
function createCred(
    address creator_,
    bytes calldata signedData_,
    bytes calldata signature_,
    uint16 buyShareRoyalty_,
    uint16 sellShareRoyalty_
)
    public
    payable
    whenNotPaused
{
    // ...

+   try buyShareCred(credIdCounter, 1, 0) {} catch {}

    // ...
}
```
