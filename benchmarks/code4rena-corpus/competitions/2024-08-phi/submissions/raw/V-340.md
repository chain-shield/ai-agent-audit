# Vulnerability details

## Impact

When a curator would like to buy or sell the amount of the shares for multiple Cred IDs, the curator would call the Cred#`batchBuyShareCred()` or Cred#`batchSellShareCred()`.

Within the Cred#`_validateAndCalculateBatch()`, the number of a given `credIds_` would be stored into the `length` array variable.
Then, it would be validated whether or not the `length` (`credIds_.length`) is equal to the length of a given `amounts` array (`amounts_.length`).
Then, it would be looped based on the number of the `length` (`credIds_.length`).
Inside the loop's block, it would be validated whether or not a given `credId` of `priceLimits_` (`priceLimits_[i] != 0`) is not zero and whether or not the sum of `prices[i] + protocolFees[i] + creatorFees[i]` is larger than the ` priceLimits_[i]` like this:

```solidity
    function _validateAndCalculateBatch(
        uint256[] calldata credIds_, ///<---------- @audit
        uint256[] calldata amounts_, ///<---------- @audit
        uint256[] calldata priceLimits_, ///<---------- @audit
        bool isBuy
    )
        internal
        view
        returns (
            uint256 totalAmount,
            uint256[] memory prices,
            uint256[] memory protocolFees,
            uint256[] memory creatorFees
        )
    {
        uint256 length = credIds_.length; ///<---------- @audit
        if (length != amounts_.length) { ///<---------- @audit
            revert InvalidArrayLength();
        }
        if (length == 0) {
            revert EmptyBatchOperation();
        }

        prices = new uint256[](length);
        protocolFees = new uint256[](length);
        creatorFees = new uint256[](length);

        uint256[] memory processedCredIds = new uint256[](length);
        for (uint256 i = 0; i < length; ++i) { ///<---------- @audit
            uint256 credId = credIds_[i];
            uint256 amount = amounts_[i];
            ...

            for (uint256 j = 0; j < i; ++j) {
                if (processedCredIds[j] == credId) {
                    revert DuplicateCredId();
                }
            }
            processedCredIds[i] = credId;

            PhiCred storage cred = creds[credId];

            (prices[i], protocolFees[i], creatorFees[i]) =
                IBondingCurve(cred.bondingCurve).getPriceData(credId, cred.currentSupply, amount, isBuy);

            if (isBuy) {
                if (priceLimits_[i] != 0 && prices[i] + protocolFees[i] + creatorFees[i] > priceLimits_[i]) { ///<---------- @audit
                    revert PriceExceedsLimit();
                }
                if (cred.currentSupply + amount > MAX_SUPPLY) {
                    revert MaxSupplyReached();
                }
            } else { /// @audit info - "Sell" order / if (isBuy == False)
                if (priceLimits_[i] != 0 && prices[i] - protocolFees[i] - creatorFees[i] < priceLimits_[i]) { ///<---------- @audit
                    revert PriceBelowLimit();
                }
                (, uint256 num) = shareBalance[credId].tryGet(_msgSender());
                if (num < amount) {
                    revert InsufficientShares();
                }
            }

            if (isBuy) {
                totalAmount += prices[i] + protocolFees[i] + creatorFees[i]; 
            } else {  /// @audit info - "Sell" order / if (isBuy == False)
                totalAmount += prices[i] - protocolFees[i] - creatorFees[i];
            }
        }
    }
```

Within the Cred#`_validateAndCalculateBatch()` above, the length of the following three arrays are supposed to be equal:
- `credIds_.length` ([`length`](https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L825))
- `amounts_.length`
- `priceLimits_.length`


Within the Cred#`_validateAndCalculateBatch()`, there is the validation to check whether or not the `credIds_.length` ([`length`](https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L825)) is equal to the `amounts_.length`.

However, within the Cred#`_validateAndCalculateBatch()` above, there is **no** validation to check whether or not  the `credIds_.length` ([`length`](https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L825)) is equal to the `priceLimits_.length`, which lead the TX of the Cred#`_validateAndCalculateBatch()` to being DOSed in the **for-loop** due to a **mismatch** of the length of the three arrays (`credIds_[i]`, `amounts_[i]`, `priceLimits_[i]`) like this: 

## Proof of Concept

For example, if a curator would call either Cred#`batchBuyShareCred()` or Cred#`batchSellShareCred()` with the following number of the three arrays (`credIds_`, `amounts_`, `priceLimit_`), the number of each array's length would be like below:
- `credIds_.length` ([`length`](https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L825)) == 6
- `amounts_.length` == 6
- `priceLimits_.length` == 5

In this case, the TX of the Cred#`_validateAndCalculateBatch()` would be reverted at the validation in the for-loop inside the Cred#`_validateAndCalculateBatch()`.
Since the Cred#`_validateAndCalculateBatch()` would be DOSed, the Cred#`batchBuyShareCred()` or Cred#`batchSellShareCred()` (which the Cred#`_validateAndCalculateBatch()` is internally called) is reverted:
```solidity
        for (uint256 i = 0; i < length; ++i) { ///<---------- @audit
```
