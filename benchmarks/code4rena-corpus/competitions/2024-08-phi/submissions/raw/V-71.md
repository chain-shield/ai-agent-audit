# Vulnerability details

When there are no shares to distribute for the given `credId`.
```solidity
function distribute(uint256 credId) external {
    // ...

    if (totalNum == 0) {
        revert NoSharesToDistribute();
    }

    // ...
}
```
If `totalNum` (the total number of shares) is zero, the function reverts with the `NoSharesToDistribute` error. However, the balance of the `credId` is not updated in this case.

The incorrect handling of the case when there are no shares to distribute will cause an incorrect distribution of rewards for curators as the contract will not update the balance of the credId after calling the distribute function.

**Root Cause**

In [CuratorRewardsDistributor.sol:91-93](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L91-L93) the [distribute](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L77-L99) function reverts when there are no shares to distribute without updating the balance of the `credId`.
```solidity
if (totalNum == 0) {
    revert NoSharesToDistribute();
}
```
## Impact
The curators suffer an approximate loss of their entitled rewards. The protocol retains the rewards that should have been distributed to the curators.

## Proof of Concept
**Internal pre-conditions**

- The `credId` needs to have a balance greater than zero in the `CuratorRewardsDistributor` contract.
- The total number of shares for the `credId` needs to be exactly zero.

**Attack Path**

* The curator calls the `distribute` function with the `credId` that meets the pre-conditions.
* The `distribut` function retrieves the total balance for the `credId` using [balanceOf[credId]](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L118).
3. The function retrieves the curator addresses for the `credId` using [credContract.getCuratorAddresses(credId, 0, 0)](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L84).
4. The function calculates the total number of shares (`totalNum`) by iterating over the curator addresses and summing their share numbers using [credContract.getShareNumber(credId, distributeAddresses[i])](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L88).
* Since totalNum is zero, the function reverts with the `NoSharesToDistribute` error.
* The balance of the `credId` remains unchanged, and the rewards are not distributed to the curators.

## 
Recommended Mitigation Steps
The [distribute](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L91-L93) function should handle the case when there are no shares to distribute by updating the balance of the `credId` to zero. Here's the recommended code change:
```diff
 if (totalNum == 0) {
-    revert NoSharesToDistribute();
+    balanceOf[credId] = 0;
+    emit RewardsDistributed(credId, _msgSender(), totalBalance, 0, totalBalance);
+    return;
 }
```
By setting the balance to zero when there are no shares to distribute and emitting the `RewardsDistributed` event with appropriate values, the contract ensures that the balance is correctly updated, and the curators receive their entitled rewards.
