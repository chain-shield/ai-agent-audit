# Vulnerability details

## Impact
As from [code comments from function `PhiFactory#setProtocolFee` and `PhiFactory#setArtCreatFee`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L420-L434), the protocol mint fee and art create fee are in basis points  with value range `[0, 10_000]`.
However, as confirmed from sponsor and from code implementation, these fees are used as absolute amount, i.e [the use of protocol mint fee in `PhiFactory#getArtMintFee()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L509-L512), [the use of art create fee in `PhiNFT1155#createArtFromFactory()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L138-L156). Also from tests, values used for these fees are in absolute amounts https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/test/helpers/Settings.sol#L111-L113

With this property for fees, these 2 functions `PhiFactory#setProtocolFee` and `PhiFactory#setArtCreatFee` can not update fee with values `> 10_000`. 


## Proof of Concept
Add this test to test file `test/PhiFactory.t.sol`:
```solidity
function test_updateFees() public {
      vm.startPrank(owner);

      uint expectedFeeValue = 0.0001 ether;

      vm.expectRevert();
      phiFactory.setProtocolFee(expectedFeeValue);
      

      vm.expectRevert();
      phiFactory.setArtCreatFee(expectedFeeValue);
    }
```

Run the test and the console shows:
```bash
Ran 1 test for test/PhiFactory.t.sol:TestPhiFactory
[PASS] test_updateFees() (gas: 21888)
```
