# Vulnerability details

Currently, there is a field called `PhiFactory::soulBounded` for each piece of art
`artData` that indicates whether an NFT can be transferred. The issue is that the artist can change this field after the NFT(it can change it all the time) has been minted and distributed, potentially making the NFT non-transferable even after some users have already acquired it.

```solidity
function soulBounded(uint256 tokenId_) public view returns (bool) {
    return phiFactoryContract.artData(_tokenIdToArtId[tokenId_]).soulBounded;
}

function safeTransferFrom(
        address from_,
        address to_,
        uint256 id_,
        uint256 value_,
        bytes memory data_
    )
        public
        override
    {
        if (from_ != address(0) && soulBounded(id_)) revert TokenNotTransferable();
        address sender = _msgSender();
        if (from_ != sender && !isApprovedForAll(from_, sender)) {
            revert ERC1155MissingApprovalForAll(sender, from_);
        }

        _safeTransferFrom(from_, to_, id_, value_, data_);
    } 

    /// @notice Safely transfers multiple art tokens from one address to another.
    /// @param from_ The sender address.
    /// @param to_ The recipient address.
    /// @param ids_ The token IDs.
    /// @param values_ The amounts to transfer.
    /// @param data_ Additional data.
    function safeBatchTransferFrom(
        address from_,
        address to_,
        uint256[] memory ids_,
        uint256[] memory values_,
        bytes memory data_
    )
        public
        override
    {
        for (uint256 i; i < ids_.length; i++) {
            if (from_ != address(0) && soulBounded(ids_[i])) revert TokenNotTransferable();
        }
        address sender = _msgSender();
        if (from_ != sender && !isApprovedForAll(from_, sender)) {
            revert ERC1155MissingApprovalForAll(sender, from_);
        }
        _safeBatchTransferFrom(from_, to_, ids_, values_, data_);
    }
```

## Impact

I will describe the problems that can be faced with changing this field: 

1. Allowing an artist to change the `soulBounded` field after an NFT for art has been distributed can severely undermine both trust and market value. Users purchase NFTs with the expectation that their properties, including transferability, are consistent and immutable. 

2. If an NFT is suddenly made non-transferable, it can lead to a loss of trust in the artist and the platform, as well as a decrease in the NFT's market value due to reduced liquidity. This unpredictability can deter users from engaging in the platform, as they may fear sudden changes that could affect the resale or trade of their assets.

## Proof of Concept

Let's look at the following scenario: 

1. We have an art, which can be transferred.
2. Art owner decides to make the art to be not transferrable with setting the `soulBounded` to true.
3. All users that already have this art minted can't transfer it or trade it.

`soulBounded` should not be modifiable and users should know does an art can be transferred or not.

## Tools Used
Manual review

## Recommended Mitigation Steps
After a discussion with the protocol team, it has been decided to remove the `soulBounded` field. This change will ensure that users are informed about the transferability status of the art before minting, providing transparency and protecting users from unexpected changes after they have acquired the NFT.
