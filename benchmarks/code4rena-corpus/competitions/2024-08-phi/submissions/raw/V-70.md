# Vulnerability details

In [CuratorRewardsDistributor.sol:120](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L120), the excess balance after distributing rewards to curators is transferred back to the caller:
```solidity
_msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);
```
This is a mistake because the excess balance should be kept in the contract for future distributions, rather than being sent back to the caller.

[CuratorRewardsDistributor#distribute](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L77-L130)
```solidity
function distribute(uint256 credId) external {
    // ...

    uint256 royaltyfee = (totalBalance * withdrawRoyalty) / RATIO_BASE;
    uint256 distributeAmount = totalBalance - royaltyfee;

    // ...

    _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);

    // ...
}
```
The issue is that the contract sends back the remaining balance (`royaltyfee + distributeAmount - actualDistributeAmount`) to the caller (`_msgSender()`) instead of keeping it in the contract for future distributions.

## Impact
The curators suffer a loss of the excess rewards that are incorrectly sent to the caller. The caller gains this excess amount without being entitled to it.

## Proof of Concept
**Internal pre-conditions:**

* The `CuratorRewardsDistributor` contract needs to have a balance greater than zero for a specific `credId`.

**Attack Path:**

* The caller calls the `distribute` function with a `credId` that has a balance greater than zero.
* The contract calculates the `royaltyfee` and `distributeAmount` based on the total balance and the `withdrawRoyalty` percentage.
* The contract calculates the rewards for each curator based on their share of the total shares.
* The `actualDistributeAmount` is calculated by summing up the rewards for each curator.
* The contract sends the excess balance (`royaltyfee + distributeAmount - actualDistributeAmount`) back to the caller, instead of keeping it in the contract for future distributions.

## Tools Used
Manual review

## Recommended Mitigation Steps
Remove [the line](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L120) that sends the excess balance back to the caller:
```diff
- _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);
```
Instead, the excess balance should be kept in the contract for future distributions. This can be achieved by updating the `balanceOf` mapping with the excess balance:
```diff
+ balanceOf[credId] += royaltyfee + distributeAmount - actualDistributeAmount;
```
This way, the excess balance will be available for future distributions, ensuring that curators receive their fair share of rewards.
