# Vulnerability details

## Impact
Creating Art will revert if the amount of Eth sent to `PhiFactory::createArt(...)` is greater than create fee. The revert occurs because the excess eth is sent back to the `msg.sender` which happens to the `PhiFactory`. `PhiFactory` contract does not accept eth directly as it does not support `receive()` or `fallback()` functions.

## Proof of Concept
When `PhiFactory::createArt(...)` function call is made, it calls `createERC1155Internal(...)` function which checks if the credentials exists or not. Based on whether the credentials exists or not, the call flows to either `new` or `existing` NFT function.

```
   function createERC1155Internal(uint256 newArtId, ERC1155Data memory createData_) internal returns (address) {
        ...suppressed code
        address artAddress;
        if (credNFTContracts[credChainId][credId] == address(0)) {
            artAddress = _createNewNFTContract(currentArt, newArtId, createData_, credId, credChainId, verificationType);
        } else {
            artAddress = _useExistingNFTContract(currentArt, newArtId, createData_, credId, credChainId);
        }
  
        return artAddress;
    }
```

Both `new` or `existing` routes the call to `PhiNFT1155::createArtFromFactory(...)` function which creates the new art work, transfers the fee applicable to the receiving address and return excess ether to the caller of this function. Also, returns the new  token id.

The problem is in the returning of Eth to the caller. As the caller is `PhiFactory` contract which does not necessary functions implemented to accept Ether, the call will revert resulting in Art work not being minted.

```
  function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
        ... 
        if ((msg.value - artFee) > 0) {
 ==>           _msgSender().safeTransferETH(msg.value - artFee);
        }
        return createdTokenId;
    }
```
`_msgSender().safeTransferETH(...)` is the the reason for reverting. There are two problems here.

a) Excess Ether is being sent to `PhiFactory` contract which does not accept Ether, which is a technical problem

b) Excess Ether should be returned to the original caller of `PhiFactory::createArt(...)` function which is the bug in the logic.

### POC
In the `_createArt(...)`, pass excess Ether as below.

` phiFactory.createArt{ value: NFT_ART_CREATE_FEE + 1 }(signCreateData, abi.encodePacked(cr, cs), config);`


## Tools Used
Manual Review and Foundry

## Recommended Mitigation Steps
a) Add original minter as additional parameter to `createArtFromFactory(...)`
b) pass the caller of `PhiFactory::createArt(...)` as minter address to `createArtFromFactory(...)` when called from the factory
c) return excess Ether to minter address passed as parameter.

This will ensure the excess ether is sent back to the caller of `createArt(...)`, the intended received of excess ether.
