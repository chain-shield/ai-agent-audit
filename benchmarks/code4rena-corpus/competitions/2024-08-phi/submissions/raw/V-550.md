# Vulnerability details


## Impact
While it doesn't directly risk user funds, it could lead to lost royalties if misused. The current implementation in the `_updateRoyalties` function of `PhiNFT1155.sol` allows setting a 0 royalty percentage with a valid recipient address.
## Proof of Concept

The vulnerability is present in the `PhiNFT1155.sol` contract on lines [L202](https://github.com/code-423n4/2024-08-phi/blob/main/src/art/PhiNFT1155.sol#L202):
       
```solidity
_updateRoyalties(tokenId_, configuration);
```

specifically in the `_updateRoyalties` function [L58-L66](https://github.com/code-423n4/2024-08-phi/blob/main/src/abstract/CreatorRoyaltiesControl.sol#L58-L66):
```solidity
    function _updateRoyalties(uint256 tokenId, RoyaltyConfiguration memory configuration) internal {
        if (configuration.royaltyRecipient == address(0) && configuration.royaltyBPS > 0) {
            revert InvalidRoyaltyRecipient();
        }
    
        royalties[tokenId] = configuration;
    
        emit UpdatedRoyalties(tokenId, msg.sender, configuration);
    }
```


This check only reverts if the royalty recipient is set to address(0) AND the royalty percentage (BPS) is greater than 0.
However, It allows setting a zero royalty percentage with a valid address.

This implementation allows for the following scenarios:

1. Turning off royalties:
   ```solidity
   _updateRoyalties(tokenId, RoyaltyConfiguration({
       royaltyRecipient: address(0),
       royaltyBPS: 0
   }));
   ```
   This call will succeed, effectively disabling royalties for the token.

2. Setting valid royalties:
   ```solidity
   _updateRoyalties(tokenId, RoyaltyConfiguration({
       royaltyRecipient: validAddress,
       royaltyBPS: 500 // 5%
   }));
   ```
   This call will succeed, setting a 5% royalty to a valid address.

3. Attempting to set invalid royalties:
   ```solidity
   _updateRoyalties(tokenId, RoyaltyConfiguration({
       royaltyRecipient: address(0),
       royaltyBPS: 500 // 5%
   }));
   ```
   This call will revert due to the `InvalidRoyaltyRecipient()` error.


**The issue scenario:**
Attempting to set invalid royalties:
   ```solidity
   _updateRoyalties(tokenId, RoyaltyConfiguration({
       royaltyRecipient: validAddress,
       royaltyBPS: 0 // 0%
   }));
   ```
   This call will succeed, unintentionally causing loss of royalty for the art owner.

## Recommended Mitigation Steps
Implement the necessary check in the `_updateRoyalties` function to prevent this issue.
