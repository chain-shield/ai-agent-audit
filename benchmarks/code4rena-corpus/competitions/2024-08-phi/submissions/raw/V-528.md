# Vulnerability details

## Impact
The soulBounded property of an art piece can be changed after creation through the updateArtSettings function in the PhiFactory contract. This property determines whether tokens are transferable or not, as checked in the PhiNFT1155 contract's safeTransferFrom function.
Allowing this property to be modified after creation can lead to:

1. Unexpected changes in token transferability, violating user expectations.
2. Potential market manipulation by art creators.

This issue impacts the fundamental nature of the tokens and could lead to loss of value or unexpected lock-up of assets for token holders.
## Proof of Concept
Art Creation:
```solidity function createArt(
    bytes calldata signedData_,
    bytes calldata signature_,
    CreateConfig memory createConfig_
)
    external
    payable
```

Art Update:
```solidity function updateArtSettings(
    uint256 artId_,

    address receiver_,

    uint256 mintFee_,
    uint256 startTime_,
    uint256 endTime_,

    external

{
    // ... (validation)
    PhiArt storage art = arts[artId_];
    art.soulBounded = soulBounded_;
    // ... (other updates)
}
```

Token Transfer Check:
```solidity function safeTransferFrom(
    address from_,
    address to_,
    uint256 id_,
    uint256 value_,
    bytes memory data_
)
    public
    override
{
    if (from_ != address(0) && soulBounded(id_)) revert TokenNotTransferable();
    // ... (rest of the function)
}
```

Scenario:

1. An art piece is created with soulBounded = false.
2. Users mint and trade tokens freely.
3. The art creator calls updateArtSettings with soulBounded = true.
4. All existing tokens suddenly become non-transferable, potentially trapping value.
