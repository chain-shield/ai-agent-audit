# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The nonReentrant modifier in the PhiFactory contract is incorrectly implemented, rendering the reentrancy protection ineffective. The modifier is designed to prevent reentrant calls by checking the value of a locked state variable. However, the initial value of locked is always set to 1 in the initialize() function or constructor, which means the reentrancy protection might not work as intended. Specifically, without the correct initialization, the modifier might never revert reentrant calls, potentially exposing critical functions like createArt to reentrancy attacks.

The lack of effective reentrancy protection can lead to severe vulnerabilities. Attackers could potentially reenter functions marked with the nonReentrant modifier, allowing them to exploit the contract by repeatedly calling these functions before the first invocation completes. This could lead to unauthorized creation of art or other unintended consequences that can compromise the integrity of the contract.

## Recommended Mitigation Steps

To ensure the nonReentrant modifier functions correctly, the locked variable must be properly initialized in the initialize() function. The correct initialization of locked should be done as follows:
```sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract PhiFactory {
    uint256 private locked;
    uint256 public artIdCounter;
    mapping(uint256 => address) public arts;

    modifier nonReentrant() {
        require(locked == 1, "Reentrant call");
        locked = 2;
        _;
        locked = 1;
    }

    function initialize() external {
        locked = 2;  // Correctly initializing the locked variable
    }

    function createArt(
        bytes calldata /*signedData_*/,
        bytes calldata /*signature_*/,
        CreateConfig calldata createConfig_
    ) external payable nonReentrant returns (address) {
        // Simulating the creation of an art contract
        artIdCounter++;
        arts[artIdCounter] = createConfig_.artist;
        return createConfig_.artist;
    }

    // Function to receive ETH
    receive() external payable {}
}
```

The locked variable is initialized to 2 in the initialize() function, ensuring that the nonReentrant modifier works as intended and prevents reentrancy attacks.

With this fix, the ReentrancyAttack contract will no longer be able to exploit the vulnerability.
