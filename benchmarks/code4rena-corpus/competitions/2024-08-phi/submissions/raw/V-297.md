# Vulnerability details


## Impact
The `_withdraw` function in the `RewardControl` contract allows users to withdraw their entire balance by passing `0` as the `amount` parameter. This behavior is triggered by the private constant `FULL_BALANCE` being set to `0`. If this behavior is not intended, it can lead to unintended full balance withdrawals, where users might accidentally withdraw their entire balance when they only intended to withdraw nothing or a specific amount.

The use of `0` as a special value to indicate "withdraw full balance" is not explicit and could easily be misunderstood, leading to errors in the code or misuse by users. This was also not stated in the documentation.

## Proof of Concept
The vulnerability is present in the `_withdraw` function of the `RewardControl` contract. The relevant code is as follows:

```solidity
function _withdraw(address from, address to, uint256 amount) internal {
    if (to == address(0)) revert InvalidAddressZero();

    uint256 balance = balanceOf[from];
    if (amount == FULL_BALANCE) {
        amount = balance;
    }

    if (amount > balance) revert InvalidAmount();

    unchecked {
        balanceOf[from] = balance - amount;
    }

    emit Withdraw(from, to, amount);

    to.safeTransferETH(amount);
}
```

## Recommended Mitigation Steps
1. **Add a Check for Zero Amount**: Modify the `_withdraw` function to revert if the `amount` is `0`, unless you have a specific reason to allow `0` as a valid input. this makes the `if` condition redundant and not needed

   ```solidity
   function _withdraw(address from, address to, uint256 amount) internal {
       if (to == address(0)) revert InvalidAddressZero();
       if (amount == 0) revert InvalidAmount(); // Prevents withdrawing full balance with 0

       uint256 balance = balanceOf[from];
       if (amount == FULL_BALANCE) {
           amount = balance;
       }

       if (amount > balance) revert InvalidAmount();

       unchecked {
           balanceOf[from] = balance - amount;
       }

       emit Withdraw(from, to, amount);

       to.safeTransferETH(amount);
   }
   ```

2. **Separate Function for Full Balance Withdrawal**: If you want to allow users to withdraw their full balance, consider creating a separate function for that purpose, such as `withdrawFullBalance(address to)`. This makes the intention clear and avoids confusion.

3. **Documentation**: If you decide to keep the current behavior, ensure it is documented so that users and developers know how the function works.
