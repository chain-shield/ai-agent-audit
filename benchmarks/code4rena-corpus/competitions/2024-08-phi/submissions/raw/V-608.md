# Vulnerability details

## SUMMARY

The vulnerability revolves around the reward distribution mechanism within the Phi Protocol's smart contracts, specifically impacting the `CuratorRewardsDistributor` and `PhiRewards` contracts. The issue arises due to the reliance on the immediate state of reward calculations, lacking historical context, which can lead to strategic exploitation by users. This design flaw allows savvy participants to time their interactions with the system to disproportionately benefit from reward allocations. Specifically, the dynamic calculations performed by functions like `handleRewardsAndGetValueSent` in the `PhiRewards` contract and the `distribute` function in the `CuratorRewardsDistributor` contract can be manipulated. Users can strategically call these functions based on their knowledge of the contracts' current state and the actions of other users to maximize their reward at the expense of others. This vulnerability does not consider historical data, rendering the reward distribution susceptible to timing attacks and leading to an unfair reward distribution among participants exploiting this flaw.

function distribute(uint256 credId) external {
    if (!credContract.isExist(credId)) revert InvalidCredId();
    uint256 totalBalance = balanceOf[credId];
    if (totalBalance == 0) {
        revert NoBalanceToDistribute();
    }

    address[] memory distributeAddresses = credContract.getCuratorAddresses(credId, 0, 0);
    uint256 totalNum;

    for (uint256 i = 0; i < distributeAddresses.length; i++) {
        totalNum += credContract.getShareNumber(credId, distributeAddresses[i]);
    }

    if (totalNum == 0) {
        revert NoSharesToDistribute();
    }

    uint256[] memory amounts = new uint256[](distributeAddresses.length);
    bytes4[] memory reasons = new bytes4[](distributeAddresses.length);

    uint256 royaltyfee = (totalBalance * withdrawRoyalty) / RATIO_BASE;
    uint256 distributeAmount = totalBalance - royaltyfee;

    uint256 actualDistributeAmount = 0;
    for (uint256 i = 0; i < distributeAddresses.length; i++) {
        address user = distributeAddresses[i];

        uint256 userAmounts = credContract.getShareNumber(credId, user);
        uint256 userRewards = (distributeAmount * userAmounts) / totalNum;

        if (userRewards > 0) {
            amounts[i] = userRewards;
            actualDistributeAmount += userRewards;
        }
    }

    balanceOf[credId] -= totalBalance;

    _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);

    phiRewardsContract.depositBatch{ value: actualDistributeAmount }(
        distributeAddresses, amounts, reasons, "deposit from curator rewards distributor"
    );

    emit RewardsDistributed(
        credId, _msgSender(), royaltyfee + distributeAmount - actualDistributeAmount, distributeAmount, totalBalance
    );
}

## VULNERABILITY DETAILS

The core of the vulnerability within the Phi Protocol lies in its reward distribution mechanism that hinges on the real-time state values without accounting for the historical state necessary for fair distribution. Primarily focused within the `CuratorRewardsDistributor` and `PhiRewards` contracts, this flaw enables timing attacks where an actor can claim disproportionately higher rewards by aligning their transactions with the protocol's immediate rather than historical state. Specifically, the function `handleRewardsAndGetValueSent` in the `PhiRewards` contract calculates, processes, and distributes rewards instantly based on the current `quantity_`, `mintFee_`, and standard reward constants, overlooking previous state changes or accumulated values over time. Subsequently, in the `CuratorRewardsDistributor`’s `distribute` function, rewards are allocated purely based on the immediate snapshot of the `balanceOf` mapping without considering historical contributions or share transactions. This setup allows for users who are acutely aware of contract states and the actions of other users to manipulate claim and trade timing to maximize their rewards. Given that the computations adjust dynamically according to the immediate snapshot of network activity, the system opens up for exploitation where one can simply observe the buildup of others’ actions and claim at opportune moments for maximized gain, significantly causing injustice in fund distributions among other participants.

## TECHNICAL IMPACT

The identified vulnerability in the Phi Protocol manifests as a significant flaw in the reward distribution mechanism within the `CuratorRewardsDistributor` and `PhiRewards` contracts. The essence of this vulnerability lies in the reliance on current state variables for reward calculations, without incorporating historical transaction data or contributions. This leads to several technical impacts:

1. **Exploitable Timing Attack**: The vulnerability enables knowledgeable users to strategically time their reward claims or share transactions in a manner that maximizes their rewards. This exploit leverages the immediate states used in functions like `handleRewardsAndGetValueSent` and `distribute`—where calculations are based on current values such as `totalBalance`, `credId`, and `quantity_`—without consideration for the historical context of contributions or previous states.

2. **Fairness and Equity Disruption**: As the reward distribution relies solely on mutable snapshots (e.g., real-time balances and numbers of shares), users who are aware of these dynamics can manipulate the process to their advantage. This creates an unlevel playing field where rewards are disproportionately allocated, disadvantaging honest but less opportunistic participants.

3. **Financial Implications**: The immediate state reliance in reward distribution functions like `computeMintReward` could lead to financial imbalances. Rewards may not reflect the true historical contributions of participants, leading to incorrect incentive structures. Consequently, this mismatch can financially burden the protocol or wrongfully enrich certain users, impacting the protocol's overall economic stability.

4. **Systemic Reliability and Integrity**: By allowing exploitation based on timing and immediate state conditions, the vulnerability weakens the systemic reliability of the network. Participants could lose trust in the fair distribution of rewards, deterred by the potential for strategic and exploitative behavior by others.

The technical impact essentially destabilizes the protocol's reward integrity, fostering an environment where strategic exploitations prevail over equitable distributions. This undermines the fundamental principles of decentralized reward systems, emphasizing the need for robust, historically-aware computations in reward calculations to prevent such vulnerabilities.
