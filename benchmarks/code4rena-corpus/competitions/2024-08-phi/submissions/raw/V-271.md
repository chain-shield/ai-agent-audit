# Vulnerability details

## Impact
Minters may be blocked from future mints even if their initial mint failed, and the `numberMinted` variable in `PhiFactory` can become out of sync with the actual total supply minted in the art contract. This could lead to minters being unfairly excluded from minting and inaccurate tracking of the total minted amount.

## Proof of Concept
In the `PhiFactory` contract, the `signatureClaim` function is responsible for processing user mints. It does this in two steps:

1. It calls the internal [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L342) function which updates `PhiFactory` state variables `artMinted[artId][minter]` and `arts[artId].numberMinted` to reflect a successful mint for the user.

2. It then calls the internal [_processClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L343) function which performs the mint by making a low-level call to the `claimFromFactory` function on the art contract.

The issue is that [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L342) updates the `PhiFactory` state before confirming the mint was actually successful in the art contract. If the low-level call in `_processClaim` reverts for any reason, `PhiFactory` state will incorrectly reflect a successful mint even though the user didn't receive the NFT.

Specifically, in [PhiFactory.sol:327-346](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L327-L346)

The call to [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L342) on **line 342** sets `artMinted[artId][minter]` to true and increments `arts[artId].numberMinted`. But the actual mint isn't attempted until `_processClaim` is called on the next line.

If the low-level call in `_processClaim` fails, the prior state updates are not reverted, leading to the inconsistency between `PhiFactory` state and the actual art contract state.

**Scenario** 
1. Initially `artMinted[artId][minter]` is false and `arts[artId].numberMinted` is 0.

2. The [signatureClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L327-L346) function is called with valid parameters, including `quantity_ = 1`.

3. Inside `signatureClaim`, the [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L342) function is called which does:
```solidity
artMinted[artId_][minter_] = true;
art.numberMinted += quantity_;
```
This sets `artMinted[artId][minter]` to true and increments `numberMinted` by 1.

4. However, the [_processClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L723-L755) function is then called which delegates the actual minting to the art contract via:
```solidity
(bool success_,) = art.artAddress.call{value: mintFee - mintProtocolFee * quantity_}(
    abi.encodeWithSignature(
        "claimFromFactory(uint256,address,address,address,uint256,bytes32,string)", 
        artId_,
        minter_,
        ref_,
        verifier_,
        quantity_,
        data_,
        imageURI_
    )
);
```
5. As a result, `artMinted[artId][minter]` remains true but `numberMinted` is not actually incremented because the mint didn't succeed.

The impact is that a minter could be blocked from future mints (since `artMinted[artId][minter]` is true) even though they didn't receive the NFT. And `numberMinted` would be out of sync with the actual supply.

## Recommended Mitigation Steps
The state updates in [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L342) should be moved after the low-level call in [_processClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L343). This way, `artMinted` and `numberMinted` are only updated if the mint definitively succeeds.

