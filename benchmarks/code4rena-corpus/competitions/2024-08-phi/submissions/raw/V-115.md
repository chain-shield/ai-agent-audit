# Vulnerability details


## Description 

The `PhiFactory` contract is designed to manage the creation and claiming of art NFTs. The [`claim` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L264-L305) allows users to claim art rewards, which internally calls either [`merkleClaim`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L352-L383) or [`signatureClaim`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L327-L346), both of which call [`_validateAndUpdateClaimState()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L701-L721) to validate and update the claim state. This function performs several checks and updates state variables such as `credMinted`, `artMinted`, and `numberMinted`.

However, there is a issue in the [`_validateAndUpdateClaimState()` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L701-L721). The `artMinted` mapping is set to `true` but is never checked, allowing users to mint multiple times for the same art. Additionally, while `numberMinted` is incremented correctly, there is no check to ensure it doesn't exceed the `maxSupply` for individual users.

The relevant part of the code is as follows:


## Impact

A malicious user can mint multiple times for the same art, bypassing the intended restrictions. This undermines the scarcity and value proposition of the NFTs, as it allows a single user to mint an unlimited number of tokens for a specific art, as long as the overall `maxSupply` hasn't been reached. 


## Proof of Concept

1. A user calls the `claim()` function to mint the maximum allowed quantity for an art.
2. The `claim()` function internally calls either `merkleClaim` or `signatureClaim`, which in turn call `_validateAndUpdateClaimState()`.
3. `_validateAndUpdateClaimState()` sets `artMinted` to `true` but does not check it.
4. The user calls the `claim()` function again for the same art, bypassing the intended restrictions.
5. The user repeats this process until the `maxSupply` is reached or exceeded.

Manual review

## Recommended Mitigation Steps

To fix this issue, the `_validateAndUpdateClaimState()` function should check if the user has already minted the art and ensure the `artMinted` mapping is used to prevent multiple mints for the same art by the same user.
