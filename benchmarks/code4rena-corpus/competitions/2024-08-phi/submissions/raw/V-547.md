# Vulnerability details

## Summary  
The contracts `PhiNFT1155.sol`, `Cred.sol`, and `PhiFactory.sol` lack a storage gap, which is essential for upgradeable contracts. Without this storage gap, adding new variables during contract upgrades could lead to storage slot collisions, potentially causing serious malfunctions or loss of user funds.

## Vulnerability Details  
Upgradeable contracts must include a storage gap to allow future additions of state variables without compromising storage compatibility. This storage gap ensures that new variables added in an upgraded base contract do not overwrite variables in child contracts. The contracts `PhiNFT1155.sol`, `Cred.sol`, and `PhiFactory.sol` do not have such a storage gap, making them vulnerable to storage slot collisions during upgrades.

Without a storage gap:
- **Variable Overwrite**: New variables added to the base contract during an upgrade might overwrite existing variables in child contracts.
- **Potential Malfunction**: Overwritten variables could cause contracts to behave unexpectedly, leading to contract malfunctions.


## Impact  
The absence of a storage gap in these contracts could lead to storage slot collisions during future upgrades, causing unintended overwriting of variables. This could lead to the malfunctioning of the contracts.

## Tools Used  
- Manual code review
- OpenZeppelin documentation

## Recommendations  
1. **Introduce a Storage Gap**: Add a storage gap in each of the contracts (`PhiNFT1155.sol`, `Cred.sol`, `PhiFactory.sol`) by including a reserved space using an array or a fixed-size buffer. This will allow for the safe addition of new state variables in future upgrades without risking storage collisions.

Example:
   ```solidity
   uint256[50] private __gap;
   ```
