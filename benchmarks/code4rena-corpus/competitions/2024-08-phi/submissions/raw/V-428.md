# Vulnerability details

## Impact
The lack of an upper limit on NFT royalties allows setting excessively high fees. This could lead to unexpected behavior, financial losses for users, or render NFTs unsellable.

## Proof of Concept
In the CreatorRoyaltiesControl contract, the _updateRoyalties function allows setting royalties without any upper bound:
```solidity
function _updateRoyalties(uint256 tokenId, RoyaltyConfiguration memory configuration) internal {
    if (configuration.royaltyRecipient == address(0) && configuration.royaltyBPS > 0) {
        revert InvalidRoyaltyRecipient();
    }

    royalties[tokenId] = configuration;

    emit UpdatedRoyalties(tokenId, msg.sender, configuration);
}
```
This function is called by PhiNFT1155 contract's updateRoyalties function:
```solidity
function updateRoyalties(
    uint256 tokenId_,
    RoyaltyConfiguration memory configuration
)
    external
    onlyArtCreator(tokenId_)
{
    _updateRoyalties(tokenId_, configuration);
}
```
An art creator could set the royaltyBPS to an arbitrarily high value, even exceeding 10000 (100%), as there are no checks in place

Manual Review

Implement a cap on royaltyBPS
