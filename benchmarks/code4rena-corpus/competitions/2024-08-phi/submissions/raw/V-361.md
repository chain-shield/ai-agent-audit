# Vulnerability details

## Impact
Detailed description of the impact of this finding.
The `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions are used to increase/decrease credentials per address. They are incremented or decremented in the `_updateCuratorShareBalance` function which is used in every trade. 

Unfortunately, these functions were most probably meant to be private but they are public currently which opens a DoS attack vector as anyone can call them.
E.g. one can just remove from credentials of an user until it's empty, that user won't be able to share them due to a revert that is triggered on sell:
- sell function calls `_handleTrade`
- inside `_handleTrade` the `_updateCuratorShareBalance` is called which should remove a cred for an address by calling `_removeCredIdPerAddress`
```solidity
if ((currentNum - amount_) == 0) {
    _removeCredIdPerAddress(credId_, sender_); <=== calls the remove
    _credIdExistsPerAddress[sender_][credId_] = false;
}
```

The remove will fail now with empty array because the attacker emptied it already

```solidity
if (_credIdsPerAddress[sender_].length == 0) revert EmptyArray();
```
