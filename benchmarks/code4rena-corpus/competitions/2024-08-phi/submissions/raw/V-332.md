# Vulnerability details

## Description
The `BondingCurve::_curve` function is an internal method invoked by the `BondingCurve::getPrice` function. However, there is no safeguard in place to prevent a potential `division by zero` error. Specifically, this issue arises if the `targetAmount_` parameter equals `TOTAL_SUPPLY_FACTOR`. When this occurs, the expression `(TOTAL_SUPPLY_FACTOR - targetAmount_)` evaluates to zero, leading to a division by zero, which in Solidity triggers a panic with the error `panic: division or modulo by zero`

```javascript
  function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
------>        return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
    }
 function _curve(uint256 targetAmount_) private pure returns (uint256) {
-------->        return (TOTAL_SUPPLY_FACTOR * CURVE_FACTOR * 1 ether) / (TOTAL_SUPPLY_FACTOR - targetAmount_)
            - CURVE_FACTOR * 1 ether - INITIAL_PRICE_FACTOR * targetAmount_ / 1000;
    }
```    

## Impact
If a division by zero occurs, the contract will revert the transaction. This could disrupt the functionality of any process that relies on the `BondingCurve::_curve` function. Specifically, this might affect users or other contracts that depend on the function’s successful execution, potentially halting critical operations and causing unexpected behavior.

## Recommended Mitigation Steps

Add a condition to check whether `targetAmount_` is equal to `TOTAL_SUPPLY_FACTOR` before performing the division. If `targetAmount_` equals `TOTAL_SUPPLY_FACTOR`, the function should revert with a clear error message or handle the case in a way that avoids the division by zero.

Example of a mitigation strategy:

```diff
function _curve(uint256 targetAmount_) public pure returns (uint256) {
+    require(targetAmount_ < TOTAL_SUPPLY_FACTOR, "Target amount cannot equal TOTAL_SUPPLY_FACTOR");
    return (TOTAL_SUPPLY_FACTOR * CURVE_FACTOR * 1 ether) / (TOTAL_SUPPLY_FACTOR - targetAmount_)
        - CURVE_FACTOR * 1 ether - INITIAL_PRICE_FACTOR * targetAmount_ / 1000;
}

```
