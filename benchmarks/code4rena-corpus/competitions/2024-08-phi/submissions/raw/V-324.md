## Proof of Concept

If a contract is deployed on multiple chains and uses signatures, it may be possible to reuse a signature used on one chain and execute the same transaction on another chain.

The expiresIn check in the createCred function is designed to prevent signature replay attacks by ensuring that a signature is only valid for a specific time frame.

## Recommended Mitigation Steps

A: Chain-Specific Nonce:
Introduce a nonce that is unique to each chain. This nonce should be included in the signed data and checked during the transaction. If the nonce has already been used on that chain, the transaction should be rejected.

B: Chain Identifier (if continue using expiresIn):
Include a chain identifier (chain id) in the signed data. This identifier can be used to verify that the signature is only valid for the intended chain. If the chain identifier does not match the current chain, the transaction should be reverted.

This could be the most convenient to implement as credChainId has already been used throughout the contract.
