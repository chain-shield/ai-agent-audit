# Vulnerability details

The `setProtocolFeeDestination()` function in the `PhiFactory` contract is designed to change the address where protocol fees are sent. However, when this address is updated, the `PhiNFT1155` contract does not reflect this change because it only initializes the `protocolFeeDestination` once during its `initialize()` function. As a result, the `createArtFromFactory()` function in `PhiNFT1155` continues to send fees to the old address, ignoring the new destination set in `PhiFactory`. This leads to a situation where protocol fees are directed to the outdated address, effectively rendering the new address unused.

## Impact
This issue causes a Denial of Service (DoS) in fee reception by the intended new `protocolFeeDestination` address. All fees generated in the `PhiNFT1155` contract continue to be sent to the old address, meaning the new address set in `PhiFactory` is ignored. This misalignment can result in financial loss, where fees are not collected by the intended party, and the purpose of updating the fee destination is defeated.

## Proof of Concept

Add this code to the `PhiFactory.t.sol` file and run the following command:
`forge test -vvv --match-test POC`:

```
    function test_POC() public {
        protocolFeeDestination = phiFactory.protocolFeeDestination();
        console2.log(protocolFeeDestination);
        console2.log("address balance before creation",address(protocolFeeDestination).balance);
        string memory artIdURL = "sample-art-id";
        _createArt(artIdURL);
        console2.log("address balance after creation",address(protocolFeeDestination).balance);
        address newProtocolFeeDestination = address(1337);

        console2.log("newProtocolFeeDestination balance before creation",address(newProtocolFeeDestination).balance);
        vm.prank(owner);
        phiFactory.setProtocolFeeDestination(newProtocolFeeDestination);

        string memory artId2 = "7TSCqFM7ISlsDOIlAf-7TSCqFM7ISlsDOIlAfTUs5ts";
        _createArt(artId2);

        console2.log("newProtocolFeeDestination balance before creation",address(newProtocolFeeDestination).balance);
        // Here you can see that ETH was transferred to the previous protocolFeeDestination instead of the newProtocolFeeDestination.
        console2.log("address balance after creation",address(protocolFeeDestination).balance);

    }
```

## Recommended Mitigation Steps
To ensure that the correct `protocolFeeDestination` is always used, the `createArtFromFactory()` function in `PhiNFT1155` should dynamically fetch the fee destination from `PhiFactory` every time a fee transfer is made:

```
function createArtFromFactory(...) external {
    ...
    address currentFeeDestination = phiFactoryContract.protocolFeeDestination();
    currentFeeDestination.safeTransferETH(artFee);
}
```

By implementing this change, the `PhiNFT1155` contract will always use the most up-to-date `protocolFeeDestination`, ensuring that fees are sent to the correct address as intended.
