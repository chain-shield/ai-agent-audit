## Impact
`_addCredIdPerAddress` is public and it has no access restrictions. The function adds a new `credId` to the list of credentials associated with a user's address. This is crucial for keeping track of which credentials each user has interacted with, especially in a system where users can own or trade multiple credentials.

## Proof of Concept
This function is called during transactions where a user acquires a new credential, ensuring that their association with the credential is recorded and easily accessible for future operations and it should be internal.

Manual reveiw 

## Recommended Mitigation Steps
Make the function internal

```diff
[src/Cred.sol]
-       function _addCredIdPerAddress(uint256 credId_, address sender_) public {
+       function _addCredIdPerAddress(uint256 credId_, address sender_) internal {    
686         // Add the new credId to the array
687         _credIdsPerAddress[sender_].push(credId_);
688         // Store the index of the new credId
689         _credIdsPerAddressCredIdIndex[sender_][credId_] = _credIdsPerAddressArrLength[sender_];
690         // Increment the array length counter
691         _credIdsPerAddressArrLength[sender_]++;
692     }
```

> Note:
> The same applies for `_removeCredIdPerAddress` function.
