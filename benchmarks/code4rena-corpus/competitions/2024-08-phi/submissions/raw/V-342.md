# Vulnerability details

## Impact
The buyers of cred shares may experience loss due to excessive fees charged during the buy operation. The buyers pay more than the intended amount, with the excess going to the protocol and the cred creators as unintended fees.

## Proof of Concept
Improper handling of the `maxPrice_` parameter in the `buyShareCred` of the Cred.sol contract and the lack of validation against this parameter in the `getPriceData` function of the `BondingCurve.sol `contract.

In [Cred.sol:buyShareCred#L178-L180](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L178-L180)
```solidity
function buyShareCred(uint256 credId_, uint256 amount_, uint256 maxPrice_) public payable {
    _handleTrade(credId_, amount_, true, _msgSender(), maxPrice_);
}
```
The `maxPrice_` parameter is passed to the internal `_handleTrade` function, which calls the `getPriceData` function of the bonding curve contract: [Cred.sol#L611-L612](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L611-L612)
```solidity
(uint256 price, uint256 protocolFee, uint256 creatorFee) =
    IBondingCurve(cred.bondingCurve).getPriceData(credId_, supply, amount_, isBuy);
```
However, the `getPriceData` function in `BondingCurve.sol` does not consider the `maxPrice_` parameter when calculating the fees: [BondingCurve.sol#L51-L72](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/curve/BondingCurve.sol#L51-L72)
```solidity
function getPriceData(
    uint256 credId_,
    uint256 supply_,
    uint256 amount_,
    bool isSign_
)
    public
    view
    returns (uint256 price, uint256 protocolFee, uint256 creatorFee)
{
    // ...
    price = isSign_ ? getPrice(supply_, amount_) : getPrice(supply_ - amount_, amount_);

    protocolFee = _getProtocolFee(price);
    // ...
    creatorFee = (price * royaltyRate) / RATIO_BASE;
}
```
As a result, the calculated `price + protocolFee + creatorFee` can exceed the `maxPrice_` specified by the buyer.

The `_handleTrade` function in `Cred.sol` does check if the `msg.value` is sufficient to cover the total cost: [#L620-L622](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L620-L622)
```solidity
if (msg.value < price + protocolFee + creatorFee) {
    revert InsufficientPayment();
}
```
However, this check happens after the fees are already deducted from the contract balances, allowing the protocol and creators to collect excessive fees.

**Here's a scenario illustrating the attack:**

1. The buyer calls `buyShareCred` with `credId_ = 1`, `amount_ = 1`, and `maxPrice_ = 1 ETH`, sending 1 ETH as `msg.value`.

2. Inside `buyShareCred`, the `_handleTrade` function is called, which further calls `getPriceData` on the bonding curve contract.

3. The `getPriceData` function calculates the price, protocol fee, and creator fee based on the current supply and the buy amount, without considering the `maxPrice_` parameter.

4. Suppose the calculated values are: `price = 0.8 ETH`, `protocolFee = 0.1 ETH`, and `creatorFee = 0.2 ETH`, resulting in a total cost of 1.1 ETH.

5. The `_handleTrade` function then checks if `msg.value` (1 ETH) is less than the total cost (1.1 ETH) and reverts with "InsufficientPayment". However, the fees (0.3 ETH) have already been deducted from the contract balances.

As a result, the buyer loses 0.1 ETH to the protocol and 0.2 ETH to the cred creator, paying a total of 1.3 ETH instead of the intended maximum of 1 ETH.

## Recommended Mitigation Steps
The `getPriceData` function in `BondingCurve.sol` should take the `maxPrice_` parameter into account and ensure that the calculated fees do not exceed it
```diff
function getPriceData(
    uint256 credId_,
    uint256 supply_,
    uint256 amount_,
    bool isSign_,
    uint256 maxPrice_
)
    public
    view
    returns (uint256 price, uint256 protocolFee, uint256 creatorFee)
{
    // ...
    price = isSign_ ? getPrice(supply_, amount_) : getPrice(supply_ - amount_, amount_);

    protocolFee = _getProtocolFee(price);
    // ...
    creatorFee = (price * royaltyRate) / RATIO_BASE;

    require(price + protocolFee + creatorFee <= maxPrice_, "Total cost exceeds maxPrice");
}
```
Update the `buyShareCred` function in `Cred.so`l to pass the `maxPrice_` parameter to `getPriceData`
```solidity`
(uint256 price, uint256 protocolFee, uint256 creatorFee) =
    IBondingCurve(cred.bondingCurve).getPriceData(credId_, supply, amount_, isBuy, maxPrice_);
```
Ensure that the `Cred.sol` contract validates the fees against the `maxPrice_` before updating the contract balances to prevent any unauthorized fee deductions.
