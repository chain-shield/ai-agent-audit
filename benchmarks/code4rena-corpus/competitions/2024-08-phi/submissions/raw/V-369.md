# Vulnerability details

## Impact
In both functions `batchBuyShareCred()` and `batchSellShareCred()` in Cred.sol there is a call to the function `_validateAndCalculateBatch()`. In the `_validateAndCalculateBatch()` function, the user submits three arrays (credIds_, amounts_, priceLimits_). 

The expectation is that the user submitting the function will ensure that the indexes of the arrays correspond to the correct values in the other arrays, and thus that the lengths will be the same. Common practice in such a situation is to verify that the lengths are equal to ensure the user hasn't made an error.

And this check has been done for two of three arrays (credIds_ and amounts_). However, there is also a comparison (read operation) with the priceLimits_ array for slippage protection. 

If the priceLimits_ array has a different length than the other arrays, the values in these arrays will be ignored. This could lead to unexpected results and reverts.

## Recommended Mitigation Steps
Add a check to the `_validateAndCalculateBatch()` function to check the lengths of all three arrays

```solidity 
if (length != amounts_.length || length != priceLimits_.length) {
            revert InvalidArrayLength();
}
```
