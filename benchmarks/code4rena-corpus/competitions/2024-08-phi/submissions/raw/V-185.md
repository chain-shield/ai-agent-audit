# Vulnerability details

The `PhiFactory::createArt()` function is susceptible to replay attacks due to inadequate validation. The `PhiFactory::_validateArtCreationSignature()` function checks the signer's address and the expiration time of the signature but does not include any mechanism to prevent replaying the same signature. This means that a malicious user could reuse a valid signature to create multiple artworks (ERC1155 tokens) without restriction.
```js

        bytes calldata signedData_,
        bytes calldata signature_,

        address artAddress = createERC1155Internal(artIdCounter, erc1155Data);
```

## Impact

A malicious user could reuse a valid signature to repeatedly create multiple artworks (ERC1155 tokens), which could lead to significant issues, such as unauthorized minting of assets, devaluation of the artwork, or economic loss for the platform.

## Recommended Mitigation Steps
To mitigate this vulnerability, it's recommended to introduce `nonce` validation within the `signedData_` or use another mechanism that ensures the uniqueness of each signature. A `nonce` could be a timestamp, an incremental counter, or a similar unique value that is included in the signed data and validated during each transaction. This would ensure that a signature can only be used once, preventing replay attacks.
