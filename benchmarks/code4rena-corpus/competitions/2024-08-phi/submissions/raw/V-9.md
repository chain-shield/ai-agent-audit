# Vulnerability details

## Impact
`PhiNFT1155` contract derives from `CreatorRoyaltiesControl` which does not following the upgradeable name space pattern for storage layout. Due to this, the storage variables in `CreatorRoyaltiesControl` line up right before the storage variables of `PhiNFT1155` contract.

As there is no gap declared in `CreatorRoyaltiesControl`, there is lack of provision for future upgrades for `CreatorRoyaltiesControl` contract.

## Proof of Concept
`CreatorRoyaltiesControl` contract does not provide for future upgrades as there is no gap declared. 

```solidity
   abstract contract CreatorRoyaltiesControl is ICreatorRoyaltiesControl {
    mapping(uint256 _tokenId => RoyaltyConfiguration _configuration) public royalties;
    uint256 private constant ROYALTY_BPS_TO_PERCENT = 10_000;
    address private royaltyRecipient;
    bool private initilaized;

```
And since  `PhiNFT1155` contract inherits `CreatorRoyaltiesControl`, the storage layout define does not allow for addition of new state level variables in `CreatorRoyaltiesControl` contract.

```
  contract PhiNFT1155 is
    Initializable,
    UUPSUpgradeable,
    ERC1155SupplyUpgradeable,
    ReentrancyGuardUpgradeable,
    PausableUpgradeable,
    Ownable2StepUpgradeable,
    IPhiNFT1155,
    Claimable,
 ==>   CreatorRoyaltiesControl
{
```


## Tools Used
Manual Review

## Recommended Mitigation Steps
a) update `CreatorRoyaltiesControl` to use name space storage.
   This is ensure the slot assigned for the contract is unique and does not conflict with storage layout of derived contract.

b) add gap to provision addition of new state variables in future.

```
  uint256[50] private __gap;
```
