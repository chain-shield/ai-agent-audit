# Vulnerability details

## Impact
The `isArtMinted` function may return incorrect values for certain minters, leading to inconsistencies in tracking minter status and potential issues in other parts of the system relying on this information.

## Proof of Concept
In the `PhiFactory` contract, the `_validateAndUpdateClaimState` function is responsible for updating the state when a claim is made. However, there is an issue with how the `artMinted` mapping is updated.
```solidity
function _validateAndUpdateClaimState(uint256 artId_, address minter_, uint256 quantity_) private {
    // ...
    if (!credMinted[art.credChainId][art.credId][minter_]) {
        credMinted[art.credChainId][art.credId][minter_] = true;
    }
    artMinted[artId_][minter_] = true;
    art.numberMinted += quantity_;
}
```
The `artMinted` mapping is updated to `true` for the `minter` only if `credMinted[art.credChainId][art.credId][minter_]` is false. However, the `art.numberMinted` is incremented unconditionally.

This can lead to a scenario where the `numberMinted` for an art increases, but the `artMinted` status for the minter remains false, causing an inconsistency between the actual minted count and the minter's recorded status.

The choice to conditionally update `artMinted` based on `credMinted` is incorrect, as it can lead to incorrect tracking of minter status.

Recommended Mitigation Steps
The `artMinted` mapping should be updated unconditionally, similar to `art.numberMinted`, to ensure the minter status is always updated when the minted count increases.
```diff
function _validateAndUpdateClaimState(uint256 artId_, address minter_, uint256 quantity_) private {
    // ...
    if (!credMinted[art.credChainId][art.credId][minter_]) {
        credMinted[art.credChainId][art.credId][minter_] = true;
    }
-   artMinted[artId_][minter_] = true;
    art.numberMinted += quantity_;
+   artMinted[artId_][minter_] = true;
}
```
By updating `artMinted` unconditionally after incrementing `art.numberMinted`, the minter status will always be correctly recorded when a claim is made, ensuring consistency between the minted count and the minter's status.
