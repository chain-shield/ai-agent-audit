# Vulnerability details

The `PhiFactory::signatureClaim()` function is insufficiently validated, leaving it open to replay attacks. The critical portion of the code is shown below. Specifically, as indicated by the `@>` mark, the function currently relies solely on the `_recoverSigner(keccak256(encodeData_), signature_) != phiSignerAddress` check to verify the signer's address. This approach lacks additional safeguards, such as `nonce` validation, which would ensure that each signature claim is unique and cannot be replayed. Consequently, a malicious actor could repeatedly invoke this method using the same valid data to obtain tokens multiple times.
```js
    function signatureClaim(
        bytes calldata signature_,
        bytes calldata encodeData_,
        MintArgs calldata mintArgs_
    )

    {
```

## Impact
A malicious user could repeatedly use the same valid signature and `encodeData_` to claim tokens an unlimited number of times. This could lead to significant token loss or disruption of the protocol.

## Recommended Mitigation Steps

To prevent replay attacks, implement `nonce` validation within the `signature_` or `encodeData_`. Each claim request should include a unique `nonce` (e.g., based on a timestamp or an incremental counter within the contract), and ensure that a `nonce` cannot be reused once it has been consumed.
