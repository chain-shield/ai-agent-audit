# Vulnerability details

`mintProtocolFee` and `artCreateFee` setters treat input values as basis points values. However, the fees are used in 
the code as absolute values expressed in wei. As a result, it will not be possible to change the fees via setters
since they limit their arguments to `10_000` wei which is a dust amount in Ether's terms.

The setters work as follows:

```solidity
    /// @notice Sets the protocol fee percentage.
    /// @param protocolFee_ The new protocol fee percentage (in basis points).
    function setProtocolFee(uint256 protocolFee_) external onlyOwner {
        if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
        mintProtocolFee = protocolFee_;
        emit ProtocolFeeSet(protocolFee_);
    }

    /// @notice Sets the art creation fee percentage.
    /// @param artCreateFee_ The new art creation fee percentage (in basis points).
    function setArtCreatFee(uint256 artCreateFee_) external onlyOwner {
        if (artCreateFee_ > 10_000) revert ArtCreatFeeTooHigh();
        artCreateFee = artCreateFee_;
        emit ArtCreatFeeSet(artCreateFee_);
    }
```

They operate with values in basis points. However, take a look at the fees' usage:

[PhiFactory.sol#L742](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L742):

```solidity
        protocolFeeDestination.safeTransferETH(mintProtocolFee * quantity_);
```

and [PhiNFT1155.sol#L142-L144](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L142-L144):

```solidity
        uint256 artFee = phiFactoryContract.artCreateFee();

        protocolFeeDestination.safeTransferETH(artFee);
```

They are used as absolute values expressed in wei.

## Impact

It is not possible to adjust the protocol fees since `mintProtocolFee` and `artCreateFee` are both limited to `10_000 wei`.
The protocol may receive fewer fees than desired until the factory contract implementation is upgraded with a fix.
