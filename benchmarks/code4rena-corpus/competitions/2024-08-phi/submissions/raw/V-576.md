# Vulnerability details

## Impact
A user can replay legitimate signature claims across different blockchain networks or on the same network after contract redeployment. This could lead to unauthorized minting of NFTs, potentially disrupting the intended distribution and economics of the system.

## Proof of Concept
The vulnerability exists due to inconsistent handling of block.chainid in the signatureClaim and claim functions of the PhiFactory contract.

Normally the users calls claim method and it adds the block chain id, but in signatureClaim case, a user can call it and add any chain id in the encodeData_.

In the [`claim`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L264) function, block.chainid is included in the signature verification data:
```Solidity
bytes memory claimData = abi.encode(expiresIn_, minter_, ref_, verifier_, artId, block.chainid, data_);
```

However, in the [`signatureClaim`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L327) function, block.chainid is not part of the decoded data used for signature verification:
```Solidity
(uint256 expiresIn_, address minter_, address ref_, address verifier_, uint256 artId_,, bytes32 data_) =
    abi.decode(encodeData_, (uint256, address, address, address, uint256, uint256, bytes32));

```
This discrepancy allows for the following attack scenario:

1. Alice obtains a valid signature for a claim on Chain A.
2. Then Alice submits this signature to the signatureClaim function on Chain B, where the same contract is deployed.
3. Since block.chainid is not verified in signatureClaim, the transaction succeeds on Chain B, allowing unauthorized minting.

This vulnerability might applies to scenarios where the contract is redeployed on the same chain, as old signatures could be reused if they haven't expired.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Modify the signatureClaim function to include block.chainid in its signature verification process, ensuring consistency with the claim function.
