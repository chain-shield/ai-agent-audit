# Vulnerability details

## Impact
Certain functions in `PhiNFT1155` have the `onlyOwner` modifier including:
- `pause`
- `unpause`
- `_authorizeUpgrade`
- `transferOwnership`

A new `PhiNFT1155` contract is deployed for each unique `credId` in `PhiFactory::_createNewNFTContract`, which in turns clones the `PhiNFT1155` implementation and calls the `initialize` function.

`PhiNFT1155::initialize` has the following line:
```solidity
        __Ownable_init(msg.sender);
```
This means that the instance of `PhiNFT1155` will be owned by the sender (the `PhiFactory` contract).

The `PhiFactory` contract's inability to call `pause` and `unpause` was raised and then fixed in the project's [previous audit](https://github.com/code-423n4/2024-08-phi/blob/main/docs/audit/Renascence%20-%20Phi%20Audit%20Report.pdf). However the `PhiFactory` is still incapable of calling the `_authorizeUpgrade` or `transferOwnership` functions.

This means that the `PhiNFT1155` contract will not be "upgradeable" as intendedby the protocol . Additionally `PhiFactory` will also be unable to call the `transferOwnership` function to rectify this.

## Proof of Concept
See the following code exerpt from `PhiNFT1155`:
```solidity
    function _authorizeUpgrade(address newImplementation) internal override onlyOwner {
        // This function is intentionally left empty to allow for upgrades
    }
```

The `_authorizeUpgrade` functions is marked as `onlyOwner` however `PhiFactory` contract (the owner), contains no logic to call this function.

Also see the following from `Ownable2StepUpgradeable` (inherited by `PhiNFT1155`):
```solidity
    function transferOwnership(address newOwner) public virtual override onlyOwner {
        Ownable2StepStorage storage $ = _getOwnable2StepStorage();
        $._pendingOwner = newOwner;
        emit OwnershipTransferStarted(owner(), newOwner);
    }
```

This `transferOwnership` function is also marked as `onlyOwner` and `PhiFactory` has no logic to call it.


## Recommended Mitigation
Similar to the `pauseArtContract` and `unPauseArtContract` functions that are present in `PhiFactory` they should include an `upgradeArtContract` function which handles upgrading specific art contracts when necessary.

As an additional note, the `PhiNFT1155` contract includes both `onlyOwner` and `onlyPhiFactory` modifiers, one of which is redundant as the intention is that the `PhiFactory` contract will be the owner meaning both modifiers serve the same purpose. If there is never any perceived reason a contract "owner" might need to be anything other than the `PhiFactory` contract, the project could consider removing the `Ownable2StepUpgradeable` inheritance and instead marking the functions mentioned in this report as `onlyPhiFactory`.
