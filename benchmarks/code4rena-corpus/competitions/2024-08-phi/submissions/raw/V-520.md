# Vulnerability details

## Impact
The public getPrice function does not check if (supply_ + amount_) is equal TOTAL_SUPPLY_FACTOR, causing division by zero in _curve function. Neither do the callers of this function. The function will revert. Calling functions like buyShareCred, buyShareCred, buyShareCredFor, batchBuyShareCred and batchSellShareCred should never revert.

## Proof of Concept
Add the following function in
/test/Cred.t.sol
and run with
forge test --mt test_DivisionByZeroInCurve_getprice -vvvv  
```
function test_DivisionByZeroInCurve_getprice() public {
        // TOTAL_SUPPLY_FACTOR is a known constant
        // uint256 private constant TOTAL_SUPPLY_FACTOR = 1000 ether;

        // Create a cred with a specific setup
        _createCred("BASIC", "SIGNATURE", 0x0);

        // Try to buy shares such that (supply_ + amount_) * 1 ether equals TOTAL_SUPPLY_FACTOR
        uint256 supply = 500;
        uint256 amount = 500;

        // Expect a revert due to division by zero
        vm.expectRevert();
        bondingCurve.getPrice(supply, amount);
    }
```

## Tools Used
Foundry

## Recommended Mitigation Steps
```
function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
    +  require((supply_ + amount_) * 1 ether != TOTAL_SUPPLY_FACTOR, "Division by zero");
       return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
}
```
