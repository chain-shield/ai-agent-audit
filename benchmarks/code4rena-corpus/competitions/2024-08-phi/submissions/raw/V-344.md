# Vulnerability details

## Impact
Sellers inconsistency between their actual ETH balance and the contract's view of their balance after a successful sell operation. 

## Proof of Concept
In the [_handleTrade](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L638-L648) function in Cred.sol, the root cause is that the contract transfers the ETH to the seller using `safeTransferETH` but doesn't update the seller's balance in the contract's state.
```solidity
function _handleTrade(
    uint256 credId_,
    uint256 amount_,
    bool isBuy,
    address curator_,
    uint256 priceLimit
)
    internal
    whenNotPaused
{
    // ...
    if (isBuy) {
        // ...
        curator_.safeTransferETH(price - protocolFee - creatorFee);
    }
    // ...
}
```
The option to update the `shareBalance` mapping to reflect the change in shares without maintaining a separate balance mapping to track the ETH balances of users within the contract is a mistake. It leads to an inconsistency between the actual ETH balances and the contract's view of user balances.

**Scenario**

1. A seller calls the `sellShareCred` function to sell a certain amount of shares of a cred.
2. The `_handleTrade` function is called internally to handle the sell operation.
3. The contract calculates the price, protocol fee, and creator fee for the sell operation.
4. The contract transfers the ETH (price - protocolFee - creatorFee) to the seller using `safeTransferETH`.
5. The contract updates the `shareBalanc`e mapping to reflect the decrease in the seller's shares.
6. The sell operation is successful, but the contract's view of the seller's ETH balance remains unchanged.

## Tools Used
Manual review

## Recommended Mitigation Steps
The contract should maintain a separate balance mapping to track the ETH balances of users within the contract. When a sell operation occurs, the contract should update the seller's balance in this mapping to reflect the increase in their ETH balance.
```diff
+ mapping(address => uint256) private userBalances;

function _handleTrade(
    uint256 credId_,
    uint256 amount_,
    bool isBuy,
    address curator_,
    uint256 priceLimit
)
    internal
    whenNotPaused
{
    // ...
    if (!isBuy) {
        // ...
        uint256 sellerProceeds = price - protocolFee - creatorFee;
        curator_.safeTransferETH(sellerProceeds);
+       userBalances[curator_] += sellerProceeds;
    }
    // ...
}
```
