# Vulnerability details

## Impact
The current implementation of the createArt function in the PhiFactory contract allows any user to create art using a valid signature, regardless of whether they were the intended recipient of that signature. This could lead to unauthorized art creation, potential abuse of the system, and deviation from the intended art creation process.

## Proof of Concept
1. An attacker obtains a valid signature for art creation looking at mempool.
2. The attacker calls the createArt function with this signature and their own CreateConfig like receiver:

```solidity function createArt(
    bytes calldata signedData_,
    bytes calldata signature_,
    CreateConfig memory createConfig_
)
    external
    payable
    nonReentrant
    whenNotPaused
    returns (address)
{
    _validateArtCreationSignature(signedData_, signature_);
    // ... rest of the function
}
```
3. As long as the signature is valid and not expired, the art will be created, potentially with different parameters (artist, receiver, etc.) than originally intended.
