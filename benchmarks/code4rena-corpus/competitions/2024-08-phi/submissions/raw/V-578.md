# Vulnerability details


## Description
The `_updateRoyalties` function in the `CreatorRoyaltiesControl` contract does not include any validation on the `royaltyBPS` value. Since royaltyBPS (Basis Points) is a standard way of representing percentages in financial contexts, it typically ranges from 0 to 10,000, where 10,000 BPS equals 100%. If `royaltyBPS` is set outside this range, it could result in unexpected or incorrect royalty calculations.

If a developer accidentally sets `royaltyBPS` to a value greater than 10,000, the royalty amount calculated would exceed 100% of the sale price, which is likely not the intended behavior.
## Impact
Royalties could be overpaid or underpaid depending on the incorrect `royaltyBPS` value. This can lead to financial losses for the involved parties or overcharging of royalty payers. Malicious art creator could exploit this lack of validation to set `royaltyBPS` to extreme values, potentially causing disruptions in the royalty payment process.
## Tools Used
Manual Review

## Recommendation
To mitigate this issue, it is recommended to introduce a validation check in the `_updateRoyalties` function to ensure that the `royaltyBPS` value is within the acceptable range of 0 to 10,000.

```
if (configuration.royaltyBPS > ROYALTY_BPS_TO_PERCENT) {
    revert InvalidRoyaltyBPS();
}
```
This check ensures that any value assigned to `royaltyBPS` is within the valid range, thereby preventing erroneous royalty calculations.
