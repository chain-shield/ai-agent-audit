# Vulnerability details

## Summary
The Cred contract implements a share trading system with a lock period to prevent rapid buying and selling of shares. However, this lock mechanism is not consistently applied across all trading functions, potentially leading to a vulnerability.

The contract implements a share lock period in the `sellShareCred` function:

```solidity
if (block.timestamp <= lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD) {
    revert ShareLockPeriodNotPassed(
        block.timestamp, lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD
    );
}
```

However, this check is missing in the `batchSellShareCred` function, which could allow users to bypass the lock period when selling shares in batch.

## Impact
1. **Lock Period Bypass**: Users can circumvent the intended lock period by using the batch sell function, potentially leading to market manipulation or unfair advantages.
2. **Inconsistent Behavior**: The contract behaves differently for individual and batch sell operations, which could confuse users and create unexpected outcomes.
3. **Potential for Exploitation**: Sophisticated users could exploit this inconsistency to rapidly buy and sell shares, potentially manipulating prices or extracting value unfairly.

## Scenario
1. Alice buys shares in Cred #1 using `buyShareCred`.
2. Immediately after, Alice attempts to sell these shares using `sellShareCred`. This transaction fails due to the lock period check.
3. However, Alice then uses `batchSellShareCred` to sell the same shares, including Cred #1 in the batch. This transaction succeeds, bypassing the lock period.
4. Alice can repeat this process, potentially manipulating the market or gaining unfair advantages over other traders who respect the lock period.

## Recommendation
Implement the lock period check in the `_executeBatchTrade` function when `isBuy` is false (i.e., for sell operations). Here's a suggested fix:

```solidity
if (!isBuy) {
    if (block.timestamp <= lastTradeTimestamp[credId][curator] + SHARE_LOCK_PERIOD) {
        revert ShareLockPeriodNotPassed(
            block.timestamp, lastTradeTimestamp[credId][curator] + SHARE_LOCK_PERIOD
        );
    }
}
```

This change should be applied within the loop that processes each cred in the batch operation.
