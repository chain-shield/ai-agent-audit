# Vulnerability details

## Impact
Once a Cred's bonding curve is removed from the whitelist, there is no way to assign the Cred a new one so it will continue to execute all trades on outdated pricing logic which has been prohibited.

## Proof of Concept
Cred's have a bonding curve address assigned to them which is responsible for the pricing logic with which trades are executed. When a cred is created [there is a check](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L258) to make sure the bonding curve address used is whitelisted.

```solidity
    if (!curatePriceWhitelist[bondingCurve]) revert Unauthorized();
```

If a flaw is later found in the bonding curve logic, the previous address will be removed from the whitelist and a new one will be whitelisted. The issue is that there is no way to update an existing Cred's bonding curve address even with [`updateCred()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L283C14-L310). If a Cred is already well established and there's many users that have purchased shares in it, it will be problematic if its bonding curve is prohibited. Essentially, all buy/sell trades will continue to operate on outdated and flawed pricing logic.

## Tools Used
Manual review

## Recommended Mitigation Steps
Allow the bonding curve address to be updated once the old one is blacklisted.

```diff
+ address oldBondingCurve = creds[credId].bondingCurve;
+ if (!curatePriceWhitelist[oldBondingCurve]) {
+   if (!curatePriceWhitelist[newBondingCurve]) revert Unauthorized();
+   creds[credId].bondingCurve = newBondingCurve;
}
```
