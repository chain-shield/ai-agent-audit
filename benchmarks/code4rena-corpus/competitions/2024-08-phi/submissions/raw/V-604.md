# Vulnerability details

## Summary
The `RewardControl` contract is vulnerable to signature replay attacks due to the implementation of its `withdrawWithSig` function. This vulnerability allows an attacker to potentially drain a user's balance by repeatedly using a single valid signature with a far-future deadline.

## Vulnerability Details

The vulnerability is present in the `withdrawWithSig` function of the `RewardControl` contract.

The root cause is a combination of two factors:
1. The ability to set arbitrarily long deadlines for signatures
2. The nonce system only invalidating a signature after it has been successfully used

### Code Snippet
```solidity
function withdrawWithSig(address from, address to, uint256 amount, uint256 deadline, bytes calldata sig) external {
    if (block.timestamp > deadline) revert DeadlineExpired();
    if (!_verifySignature(from, to, amount, nonces[from], deadline, sig)) revert InvalidSignature();

    unchecked {
        ++nonces[from];
    }

    _withdraw(from, to, amount);
}
```

### Impact
1. Signature Replay: If the `deadline` is set far in the future, a valid signature could be replayed multiple times until the deadline expires. This is not directly caused by the `block.timestamp` vulnerability, but it's an associated risk with long-duration signatures.

2. Premature Expiration: A miner could set the block timestamp up to 15 seconds in the future. This might cause a transaction to fail with `DeadlineExpired` error slightly before the intended expiration time, potentially preventing a legitimate withdrawal.

3. Extended Validity: Conversely, if the current time is slightly past the deadline, a miner could set the timestamp a few seconds in the past, allowing a withdrawal that should have been expired. This extends the window of vulnerability for any compromised signatures.

While the 15-second manipulation window is relatively small, in financial transactions or time-sensitive operations, this could still have significant implications, especially in high-value or high-frequency scenarios. The impact is moderate, as it doesn't directly lead to fund loss but can affect the precise timing and fairness of withdrawal operations.

## Attack Scenario

1. Alice creates a signature to withdraw 1 ETH with a deadline set to 1 year in the future.
2. Bob (the attacker) intercepts or otherwise obtains Alice's signature.
3. Bob calls `withdrawWithSig` with Alice's signature, successfully withdrawing 1 ETH.
4. Bob immediately calls `withdrawWithSig` again with the same signature before Alice or anyone else can use a new nonce.
5. Step 4 is repeated until Alice's balance is drained or the deadline expires.

## Proof of Concept

```solidity
function testSignatureReplayAttack() public {
    // Setup
    address alice = address(0x1);
    address bob = address(0x2);
    uint256 initialBalance = 10 ether;
    vm.deal(address(rewardControl), initialBalance);
    rewardControl.deposit{value: initialBalance}(alice, bytes4(0), "Initial deposit");

    // Alice creates a signature
    uint256 amount = 1 ether;
    uint256 deadline = block.timestamp + 365 days;
    bytes memory signature = createWithdrawSignature(alice, alice, amount, rewardControl.nonces(alice), deadline);

    // Bob uses the signature multiple times
    for (uint256 i = 0; i < 10; i++) {
        vm.prank(bob);
        rewardControl.withdrawWithSig(alice, bob, amount, deadline, signature);
    }

    // Assert that Bob has drained Alice's account
    assertEq(rewardControl.balanceOf(alice), 0);
    assertEq(bob.balance, initialBalance);
}
```

## Recommended Fix

1. Implement a maximum duration for signature validity:

```solidity
uint256 private constant MAX_SIGNATURE_DURATION = 7 days;

function withdrawWithSig(address from, address to, uint256 amount, uint256 deadline, bytes calldata sig) external {
    if (deadline > block.timestamp + MAX_SIGNATURE_DURATION) revert DeadlineTooFar();
    // ... rest of the function
}
```

2. Implement a more robust nonce system that invalidates all previous nonces:

```solidity
mapping(address => uint256) public highestNonces;

function withdrawWithSig(address from, address to, uint256 amount, uint256 nonce, uint256 deadline, bytes calldata sig) external {
    if (block.timestamp > deadline) revert DeadlineExpired();
    if (nonce <= highestNonces[from]) revert InvalidNonce();
    if (!_verifySignature(from, to, amount, nonce, deadline, sig)) revert InvalidSignature();

    highestNonces[from] = nonce;

    _withdraw(from, to, amount);
}
```

3. Consider implementing a signature status tracking system:

```solidity
mapping(bytes32 => bool) public usedSignatures;

function withdrawWithSig(address from, address to, uint256 amount, uint256 deadline, bytes calldata sig) external {
    bytes32 sigHash = keccak256(abi.encodePacked(from, to, amount, deadline, sig));
    if (usedSignatures[sigHash]) revert SignatureAlreadyUsed();
    // ... rest of the function
    usedSignatures[sigHash] = true;
}
```
