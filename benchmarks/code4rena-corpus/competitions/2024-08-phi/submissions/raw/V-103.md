# Vulnerability details

## Impact
- Impact is that the bug, prevents the contract from reaching its intended maximum supply by causing price calculations to revert near the supply limit. Therefore disrupting users experience, for late buyers, and enables a vector to be exploited for market manipulation by creating artificial scarcity at the upper supply range.

## Proof of Concept
The bug exists is in [BondingCurve.sol](https://github.com/code-423n4/2024-08-phi/blob/main/src/curve/BondingCurve.sol#L86), in the [_curve()](https://github.com/code-423n4/2024-08-phi/blob/main/src/curve/BondingCurve.sol#L117) function which is called by [getPrice()](https://github.com/code-423n4/2024-08-phi/blob/main/src/curve/BondingCurve.sol#L47C1-L49C6), which in turn is used by [getBuyPriceAfterFee()](https://github.com/code-423n4/2024-08-phi/blob/main/src/curve/BondingCurve.sol#L86):

```solidity
function _curve(uint256 targetAmount_) private pure returns (uint256) {
    // BUG: No check for targetAmount_ >= TOTAL_SUPPLY_FACTOR
    return (TOTAL_SUPPLY_FACTOR * CURVE_FACTOR * 1 ether) / (TOTAL_SUPPLY_FACTOR - targetAmount_)
        - CURVE_FACTOR * 1 ether - INITIAL_PRICE_FACTOR * targetAmount_ / 1000;
}

function getPrice(uint256 supply_, uint256 amount_) public pure returns (uint256) {
    // BUG: This can call _curve with a value that causes division by zero
    return _curve((supply_ + amount_) * 1 ether) - _curve(supply_ * 1 ether);
}

function getBuyPriceAfterFee(uint256 credId_, uint256 supply_, uint256 amount_) public view returns (uint256) {
    // BUG: No check for supply_ + amount_ > MAX_SUPPLY
    uint256 price = getBuyPrice(supply_, amount_);
    uint256 protocolFee = _getProtocolFee(price);
    uint256 creatorFee = _getCreatorFee(credId_, supply_, price, true);

    return price + protocolFee + creatorFee;
}
```

function testBondingCurveNearMaxSupply() public {

    uint256 credId = 1;

    // Buy 998 shares (1 was already bought during creation)
    uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(credId, 1, 998);

    vm.prank(anyone);

    bondingCurve.getBuyPriceAfterFee(credId, 999, 1);

    // Verify that the supply is still at 999
    assertEq(cred.getCurrentSupply(credId), 999, "Max supply was exceeded");

    // Try to buy one more share (should fail)
    vm.expectRevert(ICred.MaxSupplyReached.selector);
    cred.buyShareCred{value: 1 ether}(credId, 1, 0);
}

## Recommended Mitigation Steps
1. You can update `getBuyPriceAfterFee` to check for maximum supply:

```solidity
function getBuyPriceAfterFee(uint256 credId_, uint256 supply_, uint256 amount_) public view returns (uint256) {
    if (supply_ + amount_ > MAX_SUPPLY) {
        revert MaxSupplyReached();
    }
    uint256 price = getBuyPrice(supply_, amount_);
    uint256 protocolFee = _getProtocolFee(price);
    uint256 creatorFee = _getCreatorFee(credId_, supply_, price, true);

    return price + protocolFee + creatorFee;
}
```

2. Also put in a check in `_curve` to prevent division by zero:

```solidity
function _curve(uint256 targetAmount_) private pure returns (uint256) {
    if (targetAmount_ >= TOTAL_SUPPLY_FACTOR) {
        revert MaxSupplyReached();
    }
    return (TOTAL_SUPPLY_FACTOR * CURVE_FACTOR * 1 ether) / (TOTAL_SUPPLY_FACTOR - targetAmount_)
        - CURVE_FACTOR * 1 ether - INITIAL_PRICE_FACTOR * targetAmount_ / 1000;
}
```

3. I suggest adding similar checks in other related functions like `getSellPriceAfterFee` also.
