# Vulnerability details

In `PhiRewards::handleRewardsAndGetValueSent` can be call by anyone. The problem is  the data that is passed to be function can be anything. There are fees that are applied in this function, but if the caller pass for `addressesData_` only his addresses, all of the funds sent will be distributed to the caller, so he will not pay any fee. 

## Impact
The problem comes with that the malicious user can pass any values for chain id and art id and the backend who is monitoring for events will receive wrong data, currently this data is visualized in the fronted. 

User can DOS the system emitting a lot of events, that can be handled in the backend and can be properly visualized in the frontend. Because the database will need to persist this data.

The problem can occur on all chains, but layer 2 chains are more vulnerable, because the price of the gas is extremely low.

## Proof of Concept

Function `handleRewardsAndGetValueSent` can be call by anyone in two different ways

1. `quantity` == 0
This will enable to user to not sent any ether and the function will just emit event. For the addresses we can pass any values. And even the quantity is zero, the  contract will emit an event with wrong values. 

2. `quantity` > 0
User will need to pass ether and also for addreses which will receive rewards it will need to pass his address.

You can add this test to `Cred.t.sol` and see that event is emitted and no access controls are needed.

Add this to the beggining of `Cred.t.sol`:

```diff

+.  event RewardsDeposit(
+        bytes credData,
+        address minter,
+        address indexed receiver,
+        address indexed referral,
+        address indexed verifier,
+        bytes rewardsData
+    );

```

And add the test: 

```solidity

function test_emit_event() public {
        bytes memory addressesData_ = abi.encode(anyone, anyone, anyone, anyone);
        bytes memory rewardsData = abi.encode(0, 0, 0, 0);
        bytes memory credData = abi.encode(2, 20, false);
        vm.expectEmit();
        emit RewardsDeposit(credData, anyone, anyone, anyone, anyone, rewardsData);

        phiRewards.handleRewardsAndGetValueSent(2, 20, 0, 100, addressesData_, false);
    }
```

The test is passing and as you can see the malicious user can send any data and float the system with dummy events.

## Recommended Mitigation Steps
Consider making the function `handleRewardsAndGetValueSent` having access controls. 

One proposal is having a mapping in the `PhiFactory` which tracks a `PhiNft1155` created by the factory. And this functions can be called only by `PhiNft1155` created by `PhiFactory`
