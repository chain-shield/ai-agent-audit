# Vulnerability details

## Description
Caller of `Cred::createCred` has the option to send an address as param which would be known as a `creator` of credential and all the rewards would be send to that address from now on.
Problem being, while a caller creates a cred using `createCred`, `msg.sender` is expected to be an address which is authorized as shown below
```solidity
function createCred(
  address creator_,
  bytes calldata signedData_,
  // ...
) public payable whenNotPaused
{
  (
    // ...
    address sender,
    // ...
  ) = abi.decode(signedData_, (uint256, address, uint256, address, string, string, 
       string, bytes32));
``` 
this gives a sense that `sender` address is what protocol treats as the significant address and thus user may send a different address as `creator` as param.

Now when the same user wants to update some attributes of the cred he just created, using `updateCred` the below check expects that the `sender` must be same as the `creator` address provided while creating cred.

```solidity
    if (sender != _msgSender()) revert Unauthorized();
    if (creds[credId].creator != _msgSender()) revert Unauthorized();
```
So if sender provided different address as `creator` & not executing the function via that address or lost that particular address cuzz its was compromised. The sender could now never be able to update the credentials created

## Impact
- This Leads to Denial of Service while sender tries to update the credentialss

## Recommended Mitigation Steps
There are 2 things which might be expected

- if its expected that sender provides the same address as sender as creator while creating the credentials, below line must be replaced in `createCred`
```diff
       ...
       uint256 credId = _createCredInternal(
-            creator_, credURL, credType, verificationType, bondingCurve, buyShareRoyalty_, sellShareRoyalty_
+            sender, credURL, credType, verificationType, bondingCurve, buyShareRoyalty_, sellShareRoyalty_
        );
       ...
```

- if its expected that sender provides 2 different address i.e. (sender, creator), while creating the credentials, below line must be replaced in `updateCred`
```diff
-       if (sender != _msgSender()) revert Unauthorized();
-       if (creds[credId].creator != _msgSender()) revert Unauthorized();
+       if(sender != _msgSender() && creds[credId].creator != _msgSender()) revert Unauthorized();
```
this tells that either caller has to be `sender` `OR` `creator`.
