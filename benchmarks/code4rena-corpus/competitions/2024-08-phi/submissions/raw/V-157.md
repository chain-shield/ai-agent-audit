# Vulnerability details

## Impact
The depositBatch function in the smart contract allows the sender to deposit ETH for multiple recipients in a single transaction, along with optional reasons and a comment. While the function includes basic checks, such as ensuring the length of the recipients, amounts, and reasons arrays match, and validating that the sum of amounts equals the msg.value, it lacks a crucial check: verifying the validity of recipient addresses. This oversight can lead to potential mistakes where ETH is mistakenly sent to incorrect addresses.

## Proof of Concept
https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/RewardControl.sol#L54

The function does not verify whether the recipient addresses are valid user addresses. This means that if a sender accidentally inputs an incorrect address, ETH can be sent to an unintended recipient without any means of recovery. For example, if a typo results in an incorrect address being provided, the deposit will still proceed, potentially causing loss of funds.
## Tools Used
Manual analysis

## Recommended Mitigation Steps
The contract could maintain a whitelist of valid recipient addresses. Only addresses on this list would be allowed as recipients.
