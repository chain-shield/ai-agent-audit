# Vulnerability details


## Description
The `createArtFromFactory` function is responsible for creating a new art token within the `PhiNFT1155` contract. However, it does not perform any validation on the `artId_` parameter, which introduces several risks. The function does not check whether the `artId_` has already been used. This omission allows for the potential reuse of `artId_`, leading to inconsistencies in the mappings `_artIdToTokenId` and `_tokenIdToArtId`. Without validation, there is a risk that `artId_` could be reused accidentally or maliciously, resulting in overwriting or hijacking another art’s data. This could lead to severe issues, such as the incorrect assignment of tokens or loss of data integrity.

Since there is no mechanism to verify the uniqueness of artId_, the same artId_ could be used multiple times. This could cause the corresponding tokenId in _artIdToTokenId to be overwritten, resulting in the loss of the original mapping. Attackers could exploit this lack of validation to intentionally reuse artId_, potentially disrupting the correct functioning of the contract and affecting other users' tokens.
## Impact
The absence of validation may result in the incorrect assignment of token IDs, leading to significant inconsistencies within the contract's state. Attckers could exploit this issue to overwrite existing art IDs, leading to the potential loss or unauthorized transfer of tokens.
## Tools Used
Manual Review

## Recommendation
Implement validation checks within the `createArtFromFactory` function to ensure that the `artId_` is unique and has not been used before.
