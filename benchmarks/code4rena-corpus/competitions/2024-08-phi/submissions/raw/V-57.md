# Vulnerability details

`PhiFactory::createArt` is responsible for creating a art. This function has three parameters, `signedData_` which is data signed by a signature, `signature_` and the last parameter is `createConfig_`, which represents the parameters that are used for creation of art. In the `createConfig_` one of the parameters is the `artist`, which is the owner of the art. 

## Impact

The main problem here is that malicious user can frontrun the request for art creation and in `createConfig_` can put for `artist` any value. This will lead to the situation, where instead of the real `artist` to be the owner of the `art`, some malicious user overtake the ownership. All the rewards for minting nft of this art, will be received by the malicious user, instead of the artist.

## Proof of Concept

Let's look at the following situation:
1. Request for creating art is signed for `credId` and `credChainId`
2. The problem is that malicious user is monitoring and frontruns the request, putting into `createConfig_` for artist his address.

As you can see the `createConfig` is not part of the signedData and `artist` value can be easily put into the `createConfig`. And lack of check for sender, make this possible.

## Recommended Mitigation Steps

Add `artist` address to be part of the signed data. All other parameters can also be added to the signed data, but their are not critical, because the artist can change them anytime. I will suggest also the sender to be part of the signed data.

The following changes needs to be done: 

First in `IPhiFactory.sol`
