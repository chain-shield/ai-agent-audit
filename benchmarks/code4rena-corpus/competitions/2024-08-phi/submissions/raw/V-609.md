# Vulnerability details

## Summary
The RewardControl contract manages deposits of ETH, tracking individual balances using the `balanceOf` mapping. However, the contract's actual ETH balance and the sum of all user balances can become inconsistent.

## Vulnerability Details
The deposit functions (`deposit` and `depositBatch`) increase user balances in the `balanceOf` mapping when ETH is sent to the contract. However, there's no mechanism to handle ETH sent directly to the contract address without calling these functions.

## Code Snippet
```solidity
function deposit(address to, bytes4 reason, string calldata comment) external payable {
    if (to == address(0)) revert InvalidAddressZero();

    unchecked {
        balanceOf[to] += msg.value;
    }

    emit Deposit(msg.sender, to, reason, msg.value, comment);
}

// Similar logic in depositBatch
```

## Impact
1. ETH sent directly to the contract address (not through `deposit` or `depositBatch`) will be locked in the contract.
2. The `totalSupply()` function will return a higher value than the sum of all user balances.
3. This discrepancy could lead to confusion and potential loss of funds.

## Scenario
1. User A sends 1 ETH to the contract using the `deposit` function. Their balance is correctly updated.
2. User B sends 1 ETH directly to the contract address (not calling any function).
3. The contract now holds 2 ETH, but only 1 ETH is accounted for in the `balanceOf` mapping.
4. `totalSupply()` returns 2 ETH, but the sum of all user balances is only 1 ETH.
5. The extra 1 ETH is effectively locked in the contract with no way to withdraw it.

## Fix
Implement a fallback function to handle direct ETH transfers and either reject them or assign them to a designated address:

```solidity
address public treasuryAddress;

// Constructor or setter to initialize treasuryAddress

receive() external payable {
    if (treasuryAddress == address(0)) revert NoTreasurySet();
    
    balanceOf[treasuryAddress] += msg.value;
    emit Deposit(msg.sender, treasuryAddress, bytes4(0), msg.value, "Direct Transfer");
}
```

Update the `totalSupply()` function to return the sum of user balances instead of the contract's ETH balance.

```solidity
function totalSupply() public view returns (uint256) {
    return _calculateTotalUserBalances();
}

function _calculateTotalUserBalances() internal view returns (uint256) {
    // Iterate through all addresses and sum their balances
    // Note: This could be gas-intensive for a large number of users
}
```
