# Vulnerability details

## Impact
An attacker can buy a large amount of Cred shares, reenter to distribute the cred's rewards, and then sell the cred shares again within the same tx. That allows them to steal the majority of the cred rewards.

## Proof of Concept
When you buy cred shares, you're able to reenter through the refund call:

```sol
    function _handleTrade(
        uint256 credId_,
        uint256 amount_,
        bool isBuy,
        address curator_,
        uint256 priceLimit
    )
        internal
        whenNotPaused
    {
        // ...
        _updateCuratorShareBalance(credId_, curator_, amount_, isBuy);

        if (isBuy) {
            cred.currentSupply += amount_;
            uint256 excessPayment = msg.value - price - protocolFee - creatorFee;
            if (excessPayment > 0) {
                _msgSender().safeTransferETH(excessPayment);
            }
            lastTradeTimestamp[credId_][curator_] = block.timestamp;
        // ...
```

You can immediately sell your shares because `lastTradeTimestamp` is set **after** the refund call.
You use the shares you've bought to award yourself the majority of the cred rewards and then sell your shares earning you a profit.
