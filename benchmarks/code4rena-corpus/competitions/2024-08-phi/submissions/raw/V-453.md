# Vulnerability details

## Impact
In the PhiFactory._createNewNFTContract() function, a new art is created (https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L631-L632):
address payable newArt = payable(erc1155ArtAddress.cloneDeterministic(keccak256(abi.encodePacked(block.chainid, newArtId, credId))));

The parameters received as salt are: block.chainid, newArtId, credId

## Proof of Concept
This can have two consequences:

1. Reorg attack

While the system is designed to be deployed on Ethereum, there have still been chain reorgs in the PoS era: https://decrypt.co/101390/ethereum-beacon-chain-blockchain-reorg.

The frequency and depth of reorgs only increases in alternate L1 and L2 layers such as Polygon and Optimism, where reorgs have reached 100+ block depth: https://protos.com/polygon-hit-by-157-block-reorg-despite-hard-fork-to-reduce-reorgs/.

In a scenario where a user's Art deployment and deposit are fully included in the reorg, an attacker can pre-emptively deploy the user's Art, effectively stealing the Art instance at that specific address.

2. DOS

As a DOS, an attacker can search the mempool to find the transaction creating the new Art. Seeing the transaction, the attacker with increased gas sends his own with the same parameters. The user receives an error.
