# Vulnerability details

## Impact
### Summary 
The `Cred::_validateAndCalculateBatch` function takes an array of `credIds_`, `amounts_` and `priceLimits_`, uses each `credIds_[i]` and `amounts_[i]` to ensure that `priceLimits_[i]` are adequate for each cred. The function checks to ensure that the lengths of `credIds_` and `amounts_` match but does not check the length of `priceLimits_`.

### Vulnerability Details
The vulnerability lies in the fact that 
1. the `Cred::_validateAndCalculateBatch` function does not check if the length of `priceLimits_` matches that of `credIds_` and `amounts_`. See https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L810-L883

### Impact
Since `Cred::_validateAndCalculateBatch` function lacks check to ensure `priceLimits_` length matches `credIds_` and `amounts_` lengths, there is possibility of having array out-of-bounds access errors when the length of `priceLimits_` is less than the length of `credIds_` and `amounts_`.

This error can occur whenever the `Cred::batchBuyShareCred` or `Cred::batchSellShareCred` functions is called with `priceLimits_` length not matching the length of `credIds_` and `amounts_`.


## Proof of Concept
1. Create `credIds_` and `amounts_` arrays of size 2 each and `priceLimits_` array of size 1.
2. Call the `Cred::batchBuyShareCred` function with the above arrays as arguments and note that this results in an array out-of-bounds access error in the middle of the function call.
