# Vulnerability details

A missing check in the [_validateArtCreationSignature](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L589-L593) function will cause an attacker to create art with expired signatures as the function compares the wrong timestamp values.

**Root Cause**

In the [_validateArtCreationSignature](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L589-L593) function in `PhiFactory.sol`, there is a missing check to compare `block.timestamp` with `config.endTime`. Instead, the function compares `block.timestamp` with `expiresIn_`, which is decoded from `signedData_`.
```solidity
function _validateArtCreationSignature(bytes calldata signedData_, bytes calldata signature_) private view {
    if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
    (uint256 expiresIn_,,) = abi.decode(signedData_, (uint256, string, bytes));
    if (expiresIn_ <= block.timestamp) revert SignatureExpired();
}
```
## Impact
The attacker can create art with expired signatures, bypassing the intended signature expiration check. This violates the expected behavior of the `createArt` function.

## Proof of Concept
Internal pre-conditions

1. The `phiSignerAddress` needs to be set to a valid signer address.
2. The `artCreateFee` needs to be set to a value the attacker can afford.

**Attack Path**

* The attacker prepares `signedData_` with an `expiresIn_` timestamp that is less than the current `block.timestamp`.
* The attacker calls the `createArt` function with the prepared `signedData_`, a valid `signature_`, and a config object where `config.endTime` is less than the current `block.timestamp`.
* The [_validateArtCreationSignature](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L589-L593) function is called internally, but it fails to revert the transaction because it compares `block.timestamp` with `expiresIn_` instead of `config.endTime`.
* The art is created successfully, even though the signature has expired according to `config.endTime`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the `_validateArtCreationSignature` function to compare `block.timestamp` with `config.endTime` instead of `expiresIn_`, so that the [createArt](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L196-L213) function reverts when called with an expired signature
```diff
- function _validateArtCreationSignature(bytes calldata signedData_, bytes calldata signature_) private view {
+ function _validateArtCreationSignature(bytes calldata signedData_, bytes calldata signature_, IPhiFactory.CreateConfig memory config) private view {
     if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
-    (uint256 expiresIn_,,) = abi.decode(signedData_, (uint256, string, bytes));
-    if (expiresIn_ <= block.timestamp) revert SignatureExpired();
+    if (block.timestamp > config.endTime) revert SignatureExpired();
 }
```
