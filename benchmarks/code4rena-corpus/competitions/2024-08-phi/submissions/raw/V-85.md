# Vulnerability details

## Impact
Users are allowed to claim art rewards by 3 ways:
- EOA calls directly to function `PhiFactory#merkeClaim` and `PhiFactory#signatureClaim` ==> refunding works properly because `msg.sender` is the EOA account from user
- Through functions `PhiFactory#batchClaim` and `PhiFactory#claim`. These functions make external calls to itself, specifically the functions `merkeClaim` and `signatureClaim`  ==> The refunding logics work improperly since `msg.sender` in this case is the `PhiFactory` contract itself
- Through functions `Claimable#signatureClaim` and `Claimable#merkleClaim`. These functions call to `PhiFactory#signatureClaim` and `PhiFactory#merkeClaim` to claim ==> In this case, the contract `PhiNFT1155` will receive refund from `PhiFactory`, and get stuck in the contract `PhiNFT1155`

## Proof of Concept
1. POC for when users claim by calling to function `PhiFactory#claim`
Note: The function `PhiFactory#batchClaim` is similar

Modify the test in file `test/PhiFactory.t.sol` as below:
```diff
    ...
    function test_claimMerkle() public {
        ...
        assertEq(
            phiFactory.checkProof(
                proof,
                keccak256(bytes.concat(keccak256(abi.encode(to, value)))),
                0xe70e719557c28ce2f2f3545d64c633728d70fbcfe6ae3db5fa01420573e0f34b //expectedRoot
            ),
            true,
            "merkle proof is correct"
        );

+        deal(participant, 100 ether);
+        uint256 ethBalanceBefore = participant.balance;
+        uint256 excessAmount = 1 ether;
-        phiFactory.claim{ value: totalMintFee }(dataCompressed);
+        phiFactory.claim{ value: totalMintFee + excessAmount }(dataCompressed);
+        uint256 ethBalanceAfter = participant.balance;
+        assertEq(ethBalanceAfter, ethBalanceBefore - totalMintFee, "excess not refunded");
    }
```
Run the test `test_claimMerkle` and the console shows:
```bash
Failing tests:
Encountered 1 failing test in test/PhiFactory.t.sol:TestPhiFactory
[FAIL. Reason: excess not refunded: 98979100000000000000 != 99979100000000000000] test_claimMerkle() (gas: 1781717)
```

2. When users claim by calling `Claimable#signatureClaim()`.
Note: `Claimable#merkleClaim()` is similar to `Claimable#signatureClaim()`.

Modify the test file `test/Claimable.t.sol` as below:
```diff
    ...
         function test_claim_1155_with_ref() public {
         ...
         vm.recordLogs();

+        vm.startPrank(participant, participant);
+        uint256 excessAmount = 1 ether;
+        deal(participant, 1000 ether);
+        uint256 balanceBefore = participant.balance;
+        uint256 fee = phiFactory.getArtMintFee(artId, 1);
-        (bool success,) = artAddress.call{ value: phiFactory.getArtMintFee(artId, 1) }(payload);
+        (bool success,) = artAddress.call{ value: fee + excessAmount }(payload);
+        require(success, "1155 artAddress.call failed");
+        uint256 balanceAfter = participant.balance; // @audit POC of not refund on PhiNFT1155 
+        assertEq(balanceBefore, balanceAfter + fee, "not refunded");
         ...
    }
```

Run the test `test_claim_1155_with_ref` and the console shows:
```bash

Encountered 1 failing test in test/Claimable.t.sol:TestClaimable
[FAIL. Reason: not refunded: 1000000000000000000000 != 999000000000000000000] test_claim_1155_with_ref() (gas: 532077)
```

## Tools Used
Manual

## Recommended Mitigation Steps
Consider adding refund logics at the very end of the functions `PhiFactory#batchClaim`, `PhiFactory#claim`, `Claimable#signatureClaim` and `Claimable#merkleClaim`
