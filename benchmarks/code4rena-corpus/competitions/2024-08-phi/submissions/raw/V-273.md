# Vulnerability details

## Impact

Observers of the blockchain, such as users, developers, or automated systems/front-end, might be misled into thinking that a rewards deposit has occurred when it hasn't. This can cause confusion and mistrust in the protocol because if an external system tracks rewards deposits based on events, it might incorrectly increase the total rewards deposited.

## Proof of Concept

`handleRewardsAndGetValueSent` is missing access control and can be called by anyone. By providing the valid parameter it can be used to call internal function `depositRewards` and incorrectly emitting `RewardsDeposit` event with any parameter as long it is a valid parameter.

## Recommended Mitigation Steps

My recommendation to mitigate this exploit is to implement access control and added function:

1. Add mapping contain whitelisted address that authorized to call `PhiRewards::handleRewardsAndGetValueSent`.
2. Add function to add/remove address to the mapping
3. Only owner and PhiFactory can call said function
4. Modify `PhiFactory::createArt` so when new NFT contracts is created it would call the whitelist function and add the NFT contract address to said mappings
