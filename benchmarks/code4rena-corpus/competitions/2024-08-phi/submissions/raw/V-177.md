# Vulnerability details

## Impact

This vulnerability refers to a potential issue in the `closeAndSweep` function of the `ContributeRewards` contract. This function allows the `rewardSetter` to close a reward and sweep any remaining tokens back to their address. However, the function does not enforce that the reward period must be closed before sweeping. This means that a `rewardSetter` could potentially sweep the remaining rewards before the claim period has ended, denying legitimate claimants their rewards. To mitigate this, the contract should ensure that the claim period has ended before allowing the sweeping of remaining rewards.

## Recommended Mitigation Steps

To resolve the issue, one should modify the `closeAndSweep` function to include a check that ensures the claim period has ended before allowing the sweeping of remaining rewards.

```
function closeAndSweep(uint256 credId, uint256 rewardId) external {
    RewardInfo storage info = rewardInfos[credId][rewardId];
    if (msg.sender != info.rewardSetter) revert Unauthorized(msg.sender);
    if (!info.isOpen) revert RewardAlreadyClosed();
    if (block.timestamp <= info.claimPeriodEnds) revert ClaimPeriodNotEnded();

    info.isOpen = false;

    uint256 remainingAmount = info.totalRewardAmount - info.claimedAmount;
    if (remainingAmount > 0) {
        IERC20(info.rewardToken).safeTransfer(msg.sender, remainingAmount);
    }

    emit RewardClosedAndSwept(credId, rewardId, msg.sender, remainingAmount);
}
```

By adding the check 
`if (block.timestamp <= info.claimPeriodEnds) revert ClaimPeriodNotEnded();`, 
one can ensure that the reward can only be closed and swept after the claim period has ended, thus protecting legitimate claimants' rights to claim their rewards.
