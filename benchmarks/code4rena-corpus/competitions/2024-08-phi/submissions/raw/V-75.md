# Vulnerability details

In the current implementation of the protocol on many places ares used signatures. The problem is that they are not protected against replay attack due to missing nonce and chainId. We need also a chainId, because the protocol will be deployed on multiple chains, and this can lead to severe problems. This problem can be found on several places: 

1. `Cred::createCred`
2. `Cred::updateCred`
3. `PhiFactory::signatureClaim`
4. `PhiFactory::createArt`
5. `RewardControl::withdrawWithSig`

## Impact

The lack of protection against replay attacks in the use of signatures within the protocol can lead to significant security vulnerabilities. Specifically, the absence of a `nonce` and `chainId` in the signature verification process allows malicious actors to reuse previously valid signatures across different transactions or even on different chains. 

Also it's important to be mentioned that the protocol will be deployed on multiple chains and `chainId` check is must! 

1. `Cred::createCred`
One user can create mutltiple Creds on the same chain with the same signature until the signature expiration. Also it's possible to be replyed on other chains by users who has the same address.  

2. `Cred::updateCred`
One user can create mutltiple Creds on the same chain with the same signature until the signature expiration. Also it's possible to be replyed on other chains. 

3. `PhiFactory::signatureClaim`
Anyone can reply this on any chain, and some of the parameters are not signed such as `quantity`, `tokenId` and `imageUri`. Minter could sign as much as tokens as he wants.

4. `PhiFactory::createArt`
Anyone can reply this on any chain, and some of the parameters are not signed.

5. `RewardControl::withdrawWithSig`
Anyone can reply this withdraw on every other chain. We need to add `chainId` here

## Proof of Concept

We will go through all of the methods that are vulnerable to this problem:

1. `Cred::createCred`

As we can see below only the expire timestamp is validated. I will suggest to add nonce which is increasing after every transaction and also a check does the `chainId` where this is executed is the same as the chain for which this signature is signed.

```solidity
function createCred(
        address creator_,
        bytes calldata signedData_,
        bytes calldata signature_,
        uint16 buyShareRoyalty_,
        uint16 sellShareRoyalty_
    )
        public
        payable
        whenNotPaused
    {
        if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
        (
            uint256 expiresIn,
            address sender,
            ,
            address bondingCurve,
            string memory credURL,
            string memory credType,
            string memory verificationType,
            bytes32 merkleRoot_
        ) = abi.decode(signedData_, (uint256, address, uint256, address, string, string, string, bytes32));
        if (expiresIn <= block.timestamp) revert SignatureExpired();
```

2. `Cred::updateCred`

Here as we can see, the problem is similar to the above one. We need to add both parameters `nonce` and `chainId` to the signature.

```solidity
function updateCred(
        bytes calldata signedData_,
        bytes calldata signature_,
        uint16 buyShareRoyalty_,
        uint16 sellShareRoyalty_
    )
        external
        whenNotPaused
    {
        if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
        (uint256 expiresIn_, address sender,, uint256 credId, string memory credURL) =
            abi.decode(signedData_, (uint256, address, uint256, uint256, string));
        if (expiresIn_ <= block.timestamp) revert SignatureExpired();
```

3. `PhiFactory::signatureClaim`

Same as above, here we need to add both nonce and chainId and validate them. 

```solidity
function signatureClaim(
        bytes calldata signature_,
        bytes calldata encodeData_,
        MintArgs calldata mintArgs_
    )
        external
        payable
        whenNotPaused
    {
        (uint256 expiresIn_, address minter_, address ref_, address verifier_, uint256 artId_,, bytes32 data_) =
            abi.decode(encodeData_, (uint256, address, address, address, uint256, uint256, bytes32));

        if (expiresIn_ <= block.timestamp) revert SignatureExpired();
        if (_recoverSigner(keccak256(encodeData_), signature_) != phiSignerAddress) revert AddressNotSigned();
```

4. `PhiFactory::createArt`

Here we need to add both nonce and chain id, otherwise this could be replayed on different chains.
```solidity
function createArt(
        bytes calldata signedData_,
        bytes calldata signature_,
        CreateConfig memory createConfig_
    )
        external
        payable
        nonReentrant
        whenNotPaused
        returns (address)
    {
        _validateArtCreationSignature(signedData_, signature_); 

function _validateArtCreationSignature(bytes calldata signedData_, bytes calldata signature_) private view {
        if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
        (uint256 expiresIn_,,) = abi.decode(signedData_, (uint256, string, bytes));
        if (expiresIn_ <= block.timestamp) revert SignatureExpired();
    }
```

5. `RewardControl::withdrawWithSig`

This method is using nonce, but still needs to add `chainId`.
