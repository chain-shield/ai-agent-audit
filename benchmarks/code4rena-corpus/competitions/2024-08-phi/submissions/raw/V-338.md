# Vulnerability details

## Impact

The Cred contract has a vulnerability due to inconsistent pause controls in its functions, particularly in `createArt` and `updateArtSettings`. The `createArt` function is protected by the `whenNotPaused` modifier, which prevents new art pieces from being created when the contract is paused. However, the `updateArtSettings` function lacks this modifier, allowing art settings to be updated even when the contract is paused. This inconsistency can lead to unexpected behavior and potential security risks, as changes can still be made during a paused state, undermining the intended security measures.

## Proof of Concept
The function `createArt` has `whenNotPaused` modifier. 
```
    function createArt(
        bytes calldata signedData_,
        bytes calldata signature_,
        CreateConfig memory createConfig_
    )
        external
        payable
        nonReentrant
        whenNotPaused
        returns (address)
```
But the function `updateArtSettings` doesn't have it. 
```
    function updateArtSettings(
        uint256 artId_,
        string memory url_,
        address receiver_,
        uint256 maxSupply_,
        uint256 mintFee_,
        uint256 startTime_,
        uint256 endTime_,
        bool soulBounded_,
        IPhiNFT1155Ownable.RoyaltyConfiguration memory configuration
    )
        external
        onlyArtCreator(artId_)
```
