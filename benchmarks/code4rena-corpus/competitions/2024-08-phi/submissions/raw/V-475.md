# Vulnerability details

## Summary
Two functions, `_addCredIdPerAddress` and `_removeCredIdPerAddress`, are marked as public but should be internal 

## Vulnerability Details
The `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions in the `Cred.sol` smart contract are currently declared as public, which means they can be called by any external actor. These functions manage the internal state of the contract by adding and removing credential IDs associated with addresses. Such operations should typically be restricted to internal use only, as they directly manipulate critical data structures.

## Impact
The exposure of these functions as public allows any external user to directly manipulate the internal mapping of credIds, potentially leading to a  exploitation by malicious actors to add or remove credential IDs at will.

## POC 
make sure to change the visibility of `_credIdsPerAddress` First

```solidity 
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../src/Cred.sol";

contract CredTest is Test {
    Cred private cred;
    address private testSender;

    function setUp() public {
        cred = new Cred();
        testSender = address(0x1234);
    }

    function testAddCredIdPerAddress() public {
        uint256 credId = 1;
        cred._addCredIdPerAddress(credId, testSender);

        assertEq(cred._credIdsPerAddress(testSender, 0), credId);
     
    }

```
