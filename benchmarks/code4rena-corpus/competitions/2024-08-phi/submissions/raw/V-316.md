# Vulnerability details

### Summary

The `PhiNFT1155` token is deployed and initialized by the `PhiFactory`, with the `PhiFactory` implementation stored in the `phiFactoryContract` variable:

```solidity
    IPhiFactory public phiFactoryContract;
```

However, if the `PhiFactory` contract is upgraded, the `PhiNFT1155` token will not be able to update the `phiFactoryContract` variable to point to the new implementation. This is because the `PhiNFT1155` contract lacks a function to update this variable. Consequently, any tokens deployed prior to the upgrade will continue to use the outdated factory implementation.

### Impact

Due to the current setup, tokens that were deployed using the old `PhiFactory` implementation will not benefit from improvements or fixes introduced in a new version of `PhiFactory`. This could lead to security vulnerabilities or outdated functionality persisting in deployed tokens.

### Tools Used

Manual Review

### Recommended Mitigation Steps

To address this issue, it is recommended to implement a function in the `PhiNFT1155` contract that allows the `phiFactoryContract` variable to be updated. This function should include appropriate access controls to ensure that only authorized entities can perform the update. For example:

```solidity
function updatePhiFactoryContract(address newFactory) external onlyOwner {
    phiFactoryContract = IPhiFactory(newFactory);
}
```
