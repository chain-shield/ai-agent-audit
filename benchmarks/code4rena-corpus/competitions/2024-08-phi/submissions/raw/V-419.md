# Vulnerability details

## Impact
DoS on share purchasing and tampering with internal accounting.

## Proof of Concept
The [`_addCredIdPerAddress`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L685-L692) function is used when updating a curator's mapping of `_credIdsPerAddress` when buying/selling shares of a cred. It is a critical function, it basically updates the system to let it know a user now owns shares of a `credId`. The issue is that it is currently left as public, so anyone can add as many non existent entires as they like (no validation if the `credId` even exists) and inflate the mapping until it reaches a state where no new cred IDs can be added.

```solidity
    function _addCredIdPerAddress(uint256 credId_, address sender_) public {
        // Add the new credId to the array
        _credIdsPerAddress[sender_].push(credId_);
        // Store the index of the new credId
        _credIdsPerAddressCredIdIndex[sender_][credId_] = _credIdsPerAddressArrLength[sender_];
        // Increment the array length counter
        _credIdsPerAddressArrLength[sender_]++;
    }
```
Additionally, it will not be possible to remove the fake/non-existent credIDs from the mapping due to not passing both the `isExist` and non-0 amount checks.
