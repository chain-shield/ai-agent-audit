# Vulnerability details

## Impact
When calling `PhiFactory::claim` for MERKLE verification type the function call flow is claim->this.merkleClaim->_processClaim. Surplus funds are handled in the last function and are sent to _msgSender. However when calling `PhiFactory::merkleClaim` from `PhiFactory::claim` it changes value of `msg.sender` to `PhiFactory` contract. It means that when handling surplus funds in last function `_processClaim` msg.sender will be always PhiFactory and surplus funds will be sent to factory instead of user.
Same thing happens when calling with verification type SIGNATURE
The issue does not occur when calling `merkleClaim` or `signatureClaim` directly.

## Proof of Concept
Add this test to `PhiFactory.t.sol`
```solidity
    function test_wrongSurplusHandling() public {
        _createArt(ART_ID_URL_STRING);

        bytes32 expectedRoot = 0xe70e719557c28ce2f2f3545d64c633728d70fbcfe6ae3db5fa01420573e0f34b;
        bytes memory credData = abi.encode(1, owner, "MERKLE", 31_337, expectedRoot);
        bytes memory signCreateData = abi.encode(expiresIn, ART_ID2_URL_STRING, credData);
        bytes32 createMsgHash = keccak256(signCreateData);
        bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
        (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
        if (cv != 27) cs = cs | bytes32(uint256(1) << 255);
        phiFactory.createArt{ value: NFT_ART_CREATE_FEE }(
            signCreateData,
            abi.encodePacked(cr, cs),
            IPhiFactory.CreateConfig(participant, receiver, END_TIME, START_TIME, MAX_SUPPLY, MINT_FEE, false)
        );

        bytes32[] memory proof = new bytes32[](2);
        proof[0] = 0x0927f012522ebd33191e00fe62c11db25288016345e12e6b63709bb618d777d4;
        proof[1] = 0xdd05ddd79adc5569806124d3c5d8151b75bc81032a0ea21d4cd74fd964947bf5;
        address to = 0x1111111111111111111111111111111111111111;
        bytes32 value = 0x0000000000000000000000000000000003c2f7086aed236c807a1b5000000000;
        uint256 artId = 2;
        bytes memory data = abi.encode(artId, to, proof, referrer, uint256(2), value, IMAGE_URL2);

        bytes memory dataCompressed = LibZip.cdCompress(data);
        uint256 totalMintFee = phiFactory.getArtMintFee(artId, 2);

        uint256 participantStartingBalance = participant.balance;
        uint256 factoryStartingBalance = address(phiFactory).balance; // starting factory balance is 0
        uint256 surplusSent = 0.001 ether;

        vm.startPrank(participant, participant);
        phiFactory.claim{ value: totalMintFee + surplusSent}(dataCompressed);
        vm.stopPrank();

        uint256 participantEndingBalance = participant.balance;
        uint256 factoryEndingBalance = address(phiFactory).balance;

        assertEq(factoryEndingBalance, 0); // factory ending balance should be still 0 as mintFee is sent to protocolFee address
        assertEq(participantEndingBalance, participantStartingBalance - totalMintFee); // surplus should be returned to user
    }
```
and run `forge test --mt test_wrongSurplusHandling`.
We expect to have factory starting and ending balance to be 0 as all fees are sent to selected protocolFee address. We also expect that user ending balance will be `startingBalance - fee` and he receive all surplus.
Above test will fail however, this means the function does not work as expected.
