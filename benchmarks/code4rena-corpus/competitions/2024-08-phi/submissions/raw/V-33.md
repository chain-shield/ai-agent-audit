# Vulnerability details

## Impact

The `withdrawWithSig` function is vulnerable to a Signature Replay Attack due to the absence of EIP-155 replay protection. This flaw allows an attacker to reuse a valid signature across different chains, leading to unauthorized withdrawals and potential financial loss.

Specifically, the function `_verifySignature` does not include chain ID in the signature, which is crucial for preventing replay attacks across different chains. Without this protection, a valid signature on one chain can be reused on another, and an attacker can exploit this vulnerability to perform unauthorized withdrawals on different chains using the same signature, potentially causing significant financial damage.

## Recommended Mitigation Steps

To fix the issue, include the chain ID in the signature by modifying the `structHash`:

```
function _verifySignature(
    address from,
    address to,
    uint256 amount,
    uint256 nonce,
    uint256 deadline,
    bytes calldata sig
)
    internal
    view
    returns (bool)
{
    uint256 chainId;
    assembly {
        chainId := chainid()
    }
    bytes32 structHash = keccak256(abi.encode(WITHDRAW_TYPEHASH, from, to, amount, nonce, deadline, chainId));
    bytes32 digest = _hashTypedData(structHash);
    return SignatureCheckerLib.isValidSignatureNowCalldata(from, digest, sig);
}
```
