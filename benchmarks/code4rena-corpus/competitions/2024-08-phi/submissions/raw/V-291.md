# Vulnerability details

## Impact
An attacker can set their minter status for an art without actually minting any tokens or increasing the total minted count.

**This breaks a key invariant in the system:** _if an address is marked as having minted an art, then either it was already marked before, or the total minted quantity for that art has increased. Violating this invariant can lead to various inconsistencies and incorrect assumptions in other parts of the system that rely on accurate minter status._

While this issue doesn't directly lead to any loss of funds, it can confuse and undermine the reliability and integrity of the minting process and the data it generates.

## Proof of Concept
In the `_validateAndUpdateClaimState` function which allows updating `artMinted` mapping even when the minting `quantity_ == 0`.

In PhiFactory.sol, the `signatureClaim` and `merkleClaim` functions call `_validateAndUpdateClaimState`
```solidity
function _validateAndUpdateClaimState(uint256 artId_, address minter_, uint256 quantity_) private {
    // ...
    if (quantity_ == 0) revert InvalidQuantity();
    // ...
    artMinted[artId_][minter_] = true;
    art.numberMinted += quantity_;
}
```
The `quantity_ == 0` check is performed after the `artMinted` update. This allows a scenario where `artMinted[artId_][minter_]` is set to `true`, but `art.numberMinted` is not incremented because the check reverts the function afterwards.

Pre-conditions:

a. An art with `artId_` needs to exist.
b. `minter_` should not have already minted the art.

**Action**
1. Admin calls `createArt` to create a new art with `artId = 1`.
2. Attacker calls `signatureClaim` or `merkleClaim` with `artId_ = 1`, `minter_ = attackerAddress`, and `quantity_ = 0`.
3. In `_validateAndUpdateClaimState`, `artMinted[1][attackerAddress]` is set to true.
4. The `if (quantity_ == 0) revert InvalidQuantity();` check fails and reverts the function.
5. The transaction is reverted, but the `artMinted` state update persists, incorrectly marking the attacker as a minter for `artId = 1`.

As a result, `isArtMinted(1, attackerAddress)` will return true, even though `getNumberMinted(1)` will return `0`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Move the `quantity_` check to the beginning of the `signatureClaim` and `merkleClaim` functions, before any state updates occur:
```diff
function signatureClaim(...) external payable whenNotPaused {
+   if (quantity_ == 0) revert InvalidQuantity();
    _validateAndUpdateClaimState(artId_, minter_, quantity_);
    // ...
}

function merkleClaim(...) external payable whenNotPaused {
+   if (quantity_ == 0) revert InvalidQuantity();
    _validateAndUpdateClaimState(artId_, minter_, quantity_);
    // ...
}
```
