# Vulnerability details

## Impact
Anyone could call the 'initializeRoyalties' function and set themselves as the 'royaltyRecipient'. This would allow them to receive royalties from the contract, and diverting funds away from the rightful recipient.

## Proof of Concept

https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/CreatorRoyaltiesControl.sol#L17-L22

The primary purpose of the function is to assign an address that will receive royalty payments. This address is stored in the royaltyRecipient state variable.

The function includes a boolean flag, `initialized` (currently misspelled as `initilaized`), intended to ensure that the initialization occurs only once. Additionally, it checks that the `_royaltyRecipient` parameter is not the zero address (`address(0)`). If an invalid address is provided, the function reverts with an `InvalidRoyaltyRecipient` error.

## Recommended Mitigation Steps
To enhance the security of the `initializeRoyalties` function, it is recommended to implement an access control modifier, such as `onlyOwner` from OpenZeppelin's Ownable contract, or a custom modifier that restricts access to authorized users only. Additionally, utilize OpenZeppelin's `initializer` modifier to ensure the function is executed only once. This approach prevents unauthorized or repeated initializations, safeguarding the correct assignment of the `royaltyRecipient` by the designated party during the initialization phase.

```solidity
function initializeRoyalties(address _royaltyRecipient) internal onlyOwner initializer {
    require(_royaltyRecipient != address(0), "Invalid royalty recipient");
    royaltyRecipient = _royaltyRecipient;
}
```

Implementing these changes will enhance the contract's security by ensuring that only authorized personnel can set the `royaltyRecipient`, and it can only be initialized once.
