# Vulnerability details

## Impact
The _handleTrade and _validateAndCalculateBatch functions in Cred.sol lacks a critical check to ensure that the cred.bondingCurve address is whitelisted. This omission could potentially allow a non whitelisted bonding curve contract to be used in trades, leading to unwanted pricing calculations, protocol fee transfers, and royalty payments.

## Proof of Concept
The cred.bondingCurve address is used directly without any validation against a whitelist. This means that unwanted address could potentially be used as bonding curve contract.

To illustrate the issue, consider the scenario where a removed from whitelist bonding curve contract is used. This can make price calculations (getPriceData function) to use unwanted logic that could lead to malicious price calculations being used in trades, inappropriate protocol fees being deducted, or incorrect royalty payments being made.

## Tools Used
Manual review

## Recommended Mitigation Steps
To mitigate this vulnerability, it is recommended to implement a checks within the _handleTrade and _validateAndCalculateBatch functions to verify that cred.bondingCurve is whitelisted. For example this can be achieved by integrating the following check before invoking the getPriceData function:
```
require(curatePriceWhitelist[cred.bondingCurve], "Bonding curve is not whitelisted");
```
Also in Cred.sol::updateCred implement a logic which gives possibility for to update bondingCurve_.
