# Vulnerability details

## Impact
The bug occurs because the `createCred` function uses the `>` operator instead of the `>=` operator when comparing the royalty percentages with `MAX_ROYALTY_RANGE`. This allows the royalty percentages to be equal to the maximum allowed value, violating the intended limit. The buyers and sellers of cred shares suffer from higher than expected royalty fees. The creator gains the excess royalty fees.

## Proof of Concept
A missing check on the royalty percentages will cause the creator to set invalid royalty percentages affecting buyers and sellers as the creator will set royalty percentages exceeding the intended limit.

In Cred.sol:269-270, the check on the royalty percentages is incorrect: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L269-L271
```solidity
if (buyShareRoyalty_ > MAX_ROYALTY_RANGE || sellShareRoyalty_ > MAX_ROYALTY_RANGE) {
    revert InvalidRoyaltyRange();
}
```
The `>` operator is used instead of `>=`, allowing the royalty percentages to be equal to the maximum allowed value of 5000 (50%), violating the intended limit.

Conditions

The `MAX_ROYALTY_RANGE` constant is set to 5000, representing a maximum royalty percentage of 50%.

**Attack Scenario**

1. The creator calls the `createCred` function with `buyShareRoyalty_` or `sellShareRoyalty_` set to 5000 (50%).
2. The `createCred` function proceeds without reverting, allowing the invalid royalty percentages to be set.
3. Buyers and sellers of the cred shares are charged the higher than expected royalty fees.

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the condition in the `createCred` function to use the `>=` operator:
```js
- if (buyShareRoyalty_ > MAX_ROYALTY_RANGE || sellShareRoyalty_ > MAX_ROYALTY_RANGE) {
+ if (buyShareRoyalty_ >= MAX_ROYALTY_RANGE || sellShareRoyalty_ >= MAX_ROYALTY_RANGE) {
    revert InvalidRoyaltyRange();
}
```
The royalty percentages cannot exceed or be equal to the maximum allowed value of 50%.
