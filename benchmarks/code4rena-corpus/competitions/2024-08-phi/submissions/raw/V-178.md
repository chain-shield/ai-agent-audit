# Vulnerability details

## Impact

While a previous audit confirmed that the [H-1] vulnerability was fixed, this attack vector still remains exploitable through a reentrancy attack. A malicious user can utilize a flash loan to purchase multiple cred shares and then call curatorReward.distribute() to claim a disproportionately large share of rewards. Subsequently, the attacker can sell the shares in same transaction.

The fundamental issue lies in the `cred` contract's handling of the `lastTradeTimestamp`, which is intended to track user trades and prevent the immediate selling of shares. However, the `lastTradeTimestamp` is updated after an excess payment is sent to the user, creating a window for a reentrancy attack. Since the `lastTradeTimestamp` is not updated before the ETH transfer, the attacker can exploit this timing gap to execute a reentrant call and sell the shares without adhering to the intended cooldown period.


## Proof of Concept

In the cred contract, the code snippet below demonstrates the vulnerable transaction flow:

```solidity
        if (isBuy) {
            cred.currentSupply += amount_;
            uint256 excessPayment = msg.value - price - protocolFee - creatorFee;
            if (excessPayment > 0) {
                _msgSender().safeTransferETH(excessPayment);
            }
            lastTradeTimestamp[credId_][curator_] = block.timestamp;
        } else {
            cred.currentSupply -= amount_;
            curator_.safeTransferETH(price - protocolFee - creatorFee);
        }
```
The safeTransferETH function is called to send the excess payment back to the sender before the lastTradeTimestamp is updated. This is a classic case where a reentrancy attack can occur. An attacker can utilize a flash loan to buy a large number of cred shares and then, before the lastTradeTimestamp is updated, call curatorReward.distribute(), claiming a significant portion of the rewards based on their inflated share holdings and execute a reentrant call to the sellShareCred function. This allows the attacker to bypass the cooldown mechanism and quickly sell the shares.
