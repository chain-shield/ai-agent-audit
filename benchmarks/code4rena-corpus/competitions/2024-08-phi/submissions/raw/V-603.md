# Vulnerability details

## Summary

The Cred contract implements a signature-based verification system for creating and updating creds. This system relies on checking the expiration time of signatures against the current block timestamp.

## Vulnerability Details

The contract's signature expiration check is vulnerable to miner manipulation, potentially leading to Denial of Service (DoS) attacks. The vulnerability is present in the `createCred` and `updateCred` functions.

### Affected Code Snippet

```solidity
if (expiresIn <= block.timestamp) revert SignatureExpired();
```

This check is performed without any buffer, making it susceptible to minor timestamp manipulations by miners.

## Impact

A malicious miner could slightly delay the block timestamp to invalidate otherwise valid signatures, preventing legitimate transactions from being processed. This could result in:

1. **Denial of Service**: Users may be unable to create or update creds, even with valid signatures.
2. **Inconsistent contract behavior**: The same signature might be valid in one block but invalid in the next.
3. **Potential financial losses**: If users pay gas fees for transactions that are then reverted due to "expired" signatures, they incur unnecessary costs.

## Attack Scenario

1. A user generates a valid signature for creating or updating a cred, setting `expiresIn` to the current time plus a short duration (e.g., 5 minutes).
2. The user submits the transaction to the network.
3. A malicious miner receives the transaction and intentionally delays the block timestamp by a few seconds.
4. When the transaction is processed, the condition `expiresIn <= block.timestamp` evaluates to true due to the miner's manipulation.
5. The transaction reverts with a `SignatureExpired` error, despite the signature being legitimately within its intended validity period.
6. The user's operation fails, and they lose the gas paid for the transaction.

## Proposed Fix

Implement a buffer in the expiration check to make it resistant to minor timestamp manipulations:

```solidity
uint256 constant EXPIRATION_BUFFER = 5 minutes;

if (expiresIn + EXPIRATION_BUFFER <= block.timestamp) revert SignatureExpired();
```

This change adds a 5-minute buffer to the expiration time, making it significantly harder for miners to manipulate the outcome of the check.

Additionally, update the off-chain signature generation process to account for this buffer, ensuring that `expiresIn` is set sufficiently far in the future.
