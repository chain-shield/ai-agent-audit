# Vulnerability details

## Impact
Any user can call the `distribute` function and receive the royalty fee and any remaining balance, which should be distributed to the rightful recipients. This vulnerability could lead to substantial financial losses for the protocol and its users.

## Proof of Concept
The vulnerability exists in the [distribute](https://github.com/code-423n4/2024-08-phi/blob/main/src/reward/CuratorRewardsDistributor.sol#L77) function of the CuratorRewardsDistributor contract.

```Solidity
function distribute(uint256 credId) external {
    // ... (distribution logic)

    uint256 royaltyfee = (totalBalance * withdrawRoyalty) / RATIO_BASE;
    uint256 distributeAmount = totalBalance - royaltyfee;

    // ... (more distribution logic)

    _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);

    // ... (rest of the function)
}
```

The function is `external` and can be called by any address. At the end of the function, it transfers the royalty fee and any remaining balance to `_msgSender()`, which is the caller of the function in this context.

An attacker could exploit this in the following way:
1. Wait for rewards to accumulate in the CuratorRewardsDistributor contract.
2. Call the `distribute` function for a specific `credId`.
3. Receive the royalty fee and any undistributed balance, stealing funds meant for royalty fee owner.

This process could be repeated for different `credId` values, potentially draining the contract of all its funds.
It seems the protocol oversight _msgSender() as the protocol should override it.

    uint256 credId = 1;
    uint256 depositAmount = 1 ether;

    // Deposit some ETH to the curatorRewardsDistributor
    curatorRewardsDistributor.deposit{ value: depositAmount }(credId, depositAmount);

    // Signal creds for different users with specific amounts to force rounding errors
    vm.startPrank(user1);
    vm.deal(user1, bondingCurve.getBuyPriceAfterFee(credId, 1, 3));

    vm.deal(user2, bondingCurve.getBuyPriceAfterFee(credId, 4, 2));
    cred.buyShareCred{ value: bondingCurve.getBuyPriceAfterFee(credId, 4, 2) }(credId, 2, 0);
    vm.stopPrank();

    // Record initial balances
    uint256 initialContractBalance = address(curatorRewardsDistributor).balance;
    uint256 initialOwnerBalance = owner.balance;
    uint256 initialPhiRewardsBalance = address(phiRewards).balance;

    // Distribute rewards
    //vm.prank(owner);

    curatorRewardsDistributor.distribute(credId);

    // Check final balances
    uint256 finalContractBalance = address(curatorRewardsDistributor).balance;
    uint256 finalOwnerBalance = owner.balance;
    uint256 finalPhiRewardsBalance = address(phiRewards).balance;

    // Calculate total distributed to PhiRewards
    uint256 totalDistributedToPhiRewards = finalPhiRewardsBalance - initialPhiRewardsBalance;

    // Calculate amount received by owner
    uint256 ownerReceived = finalOwnerBalance - initialOwnerBalance;

    // The contract balance should be zero after distribution
    assertEq(finalContractBalance, 0, "Contract should have zero balance after distribution");

    // The total distributed amount should equal the initial deposit
    assertEq(
        totalDistributedToPhiRewards + ownerReceived,
        depositAmount,
        "Total distributed amount doesn't match initial deposit"
    );

    // Check that the owner doesn't receive significantly more than expected
    // Assuming the royalty should be around 1% (adjust this value based on your actual implementation)
    uint256 expectedMaxRoyalty = depositAmount / 100;
    assertLe(ownerReceived, expectedMaxRoyalty, "Owner received significantly more than expected royalty");

    // Optional: Check that most of the funds went to PhiRewards
    assertGt(totalDistributedToPhiRewards, depositAmount * 95 / 100, "Less than 95% of funds went to PhiRewards");
}
