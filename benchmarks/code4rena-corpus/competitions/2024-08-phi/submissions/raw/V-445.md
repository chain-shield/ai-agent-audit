# Vulnerability details

## Impact
In many functions within `PhiFactory.sol`, excess funds are refunded to the sender. Both the `_createNewNFTContract()` and `_useExistingNFTContract()` functions forward `msg.value` to the `PhiNFT1155.sol` contract, where the art creation takes place. The `createArtFromFactory()` function in `PhiNFT1155.sol` can only be called by PhiFactory due to the `onlyPhiFactory` modifier.

This means that the refund operation is handled within this function in the following way:

```solidity 
if ((msg.value - artFee) > 0) {
            _msgSender().safeTransferETH(msg.value - artFee);
}
```
This code will return excess ether to the PhiFactory contract, and not to the artist, i.e., the original sender. However, this call will cause the whole function to revert, because there is no `fallback()` or `receive()` function in the PhiFactory.sol contract so the ether won't be transferred there as well.

## Recommended Mitigation Steps
Get the value of the art fee inside `PhiFactory.sol`, subtract it from the `msg.value` and do the refund after the `createArtFromFactory()` function call. 

Forward only `artFee` to the `createArtFromFactory()` and not the whole `msg.value`. 

Another option would be to do all transfers (protocolFee, refund) inside the `PhiFactory.sol` and to not forward anything to the `PhiNFT1155.sol`
