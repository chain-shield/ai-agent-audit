# Vulnerability details

## Impact
The protocol suffers from inconsistencies in the `credIdCounter`, skipping cred IDs. This can lead to issues with cred management and tracking, affecting the overall integrity of the system.

## Proof of Concept
The incorrect placement of `credIdCounter` increment in the [_createCredInternal function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L544-L577) will cause inconsistencies in the `credIdCounter` for the protocol as the attacker will exploit the revert behavior of `buyShareCred` to manipulate the `credIdCounte`.

In the `_createCredInternal` function of Cred.sol, the `credIdCounter` is incremented after calling the `buyShareCred` function.
```solidity
function _createCredInternal(
    // ...
)
    internal
    whenNotPaused
    returns (uint256)
{
    // ...

    buyShareCred(credIdCounter, 1, 0);

    emit CredCreated(creator_, credIdCounter, credURL_, credType_, verificationType_);

    credIdCounter += 1;

    return credIdCounter - 1;
}
```
If the [buyShareCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L178-L180) function reverts, the `credIdCounter` will still be incremented, leading to a gap in the `credIdCounter` sequence.

**Attack Scenario**
* The attacker calls the [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L254) function with valid parameters.
* Inside `createCred`, the [_createCredInternal](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L273-L275) function is called.
* The `buyShareCred` function is called with the current `credIdCounter` value.
* If `buyShareCred` reverts due to any reason (e.g., insufficient payment, max supply reached), the execution continues.
* The `credIdCounter` is incremented after the revert.
* The incremented `credIdCounter` is returned, effectively skipping a `cred` ID.

## Tools Used
Manual review

## Recommended Mitigation Steps
By incrementing the `credIdCounter` before calling `buyShareCred` and returning the incremented value, the issue of skipping cred IDs can be resolved. This ensures that the `credIdCounter` remains consistent and reliable for cred management and tracking.
```diff
function _createCredInternal(
    // ...
)
    internal
    whenNotPaused
    returns (uint256)
{
    // ...

+   credIdCounter += 1;
+
    buyShareCred(credIdCounter, 1, 0);

    emit CredCreated(creator_, credIdCounter, credURL_, credType_, verificationType_);

-   credIdCounter += 1;
-
-   return credIdCounter - 1;
+   return credIdCounter;
}
```
