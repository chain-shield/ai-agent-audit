# Vulnerability details

## Impact
PhiFactory contract incorrectly updates the minter status when a signature claim is made, leading to inconsistencies in tracking and validating mints. This issue can result in the contract's state not accurately reflecting whether a minter has claimed an art or not.

> While this bug does not directly cause financial losses, it can lead to confusion and incorrect assumptions about the minting status of users. If the contract's state is relied upon for other functionality or off-chain processes, it could result in unintended consequences or incorrect decision-making.

## Proof of Concept
The root cause of the issue lies in the [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L702-L721) function in the PhiFactory contract. Specifically, the `artMinted` mapping is updated incorrectly when a signature claim is made.
```solidity
function _validateAndUpdateClaimState(uint256 artId_, address minter_, uint256 quantity_) private {
    // ...
    if (!credMinted[art.credChainId][art.credId][minter_]) {
        credMinted[art.credChainId][art.credId][minter_] = true;
    }
    artMinted[artId_][minter_] = true;
    art.numberMinted += quantity_;
}
```
The [artMinted[artId_][minter_] = true;](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L719) statement is placed outside the `if` block that checks `credMinted`. As a result, if `credMinted` is already true for the minter, `artMinted` won't be updated correctly.

The choice to place the `artMinted` update outside the `if` block is a mistake, as it leads to inconsistent updating of the minter status.

_When the `credMinted` mapping to be set to true for the given `credChainId`, `credId`, and minter._

Scenario
* A minter calls the [signatureClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L327-L346) function with valid parameters to claim an art.
* Inside the [_validateAndUpdateClaimState](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L702-L721) function, the `if` condition [!credMinted[art.credChainId][art.credId][minter_]](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L716) evaluates to `false` because `credMinted` is already true for the minter.
* The `artMinted` mapping is set to true for the `artId` and minter, regardless of the `if` condition.
* The `art.numberMinted` is incremented by the quantity.
* The function completes, but the `artMinted` status for the minter remains false, even though the minting occurred and `numberMinted` increased.

## Recommended Mitigation Steps
Move the `artMinted[artId_][minter_] = true;` statement inside the `if` block.
```diff
 function _validateAndUpdateClaimState(uint256 artId_, address minter_, uint256 quantity_) private {
     // ...
     if (!credMinted[art.credChainId][art.credId][minter_]) {
         credMinted[art.credChainId][art.credId][minter_] = true;
+        artMinted[artId_][minter_] = true;
     }
-    artMinted[artId_][minter_] = true;
     art.numberMinted += quantity_;
 }
```
