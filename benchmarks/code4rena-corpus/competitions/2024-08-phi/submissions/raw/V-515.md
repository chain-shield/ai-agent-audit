# Vulnerability details


## Description
The `Cred:createCred` function is responsible for creating a new "cred" and assigning it a unique identifier, credId. This function likely interacts with a factory or registry that manages the various credentials or tokens within the system. However, there is a significant issue in the createCred function that allows for the possibility of creating multiple credentials with the same credId. This issue arises due to the lack of proper validation and checks within the function, which fails to ensure that the credId is indeed unique before creating a new credential.
## Impact
Multiple credentials with the same `credId` can lead to inconsistencies within the system, making it difficult to track and manage individual credentials correctly. If duplicate `credId` values are created, an attacker might exploit this vulnerability to overwrite or hijack existing credentials, potentially gaining unauthorized access or control over another user's credentials. The presence of duplicate `credId` values could disrupt the normal operation of the contract, leading to failed transactions, erroneous behavior, or even complete system failure.
## Tools Used
Manual Review

## Recommendation
Implement a validation check within the createCred function to ensure that the credId being created does not already exist in the system. This can be done by maintaining a mapping of existing credId values and checking against this mapping before proceeding with the creation of a new credential.
