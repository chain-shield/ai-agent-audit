# Vulnerability details

## Impact
The current implementation in set methods could only work for extremely low fees , significantly impacting the protocol's revenue model, in case fee changes are required. This occurs because:

The artCreateFee and mintProtocolFee are set with checks that limit them to a maximum of 10,000 (100% in basis points).
However, these fees are then used as absolute amounts in wei when collecting fees.

As a result, the maximum fee that can be set if required to be changed is 0.00000000000001 ETH (10,000 wei), which is negligible and likely not the intended.

## Proof of Concept
In PhiFactory.sol, setArtCreatFee and setProtocolFee functions limit the fee to 10,000:

```solidity
function setArtCreatFee(uint256 artCreateFee_) external onlyOwner {
    if (artCreateFee_ > 10_000) revert ArtCreatFeeTooHigh();
    artCreateFee = artCreateFee_;
    emit ArtCreatFeeSet(artCreateFee_);
}
```

```solidity
function setProtocolFee(uint256 protocolFee_) external onlyOwner {
    if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
    mintProtocolFee = protocolFee_;
    emit ProtocolFeeSet(protocolFee_);
}
```

However, in PhiNFT1155.sol, artCreateFee is used as an absolute amount:

```solidity
uint256 artFee = phiFactoryContract.artCreateFee();
protocolFeeDestination.safeTransferETH(artFee);
```

Similarly, in PhiFactory.sol, mintProtocolFee is used as an absolute amount:

```solidity
protocolFeeDestination.safeTransferETH(mintProtocolFee * quantity_);
```

Manual Review

## Recommended Mitigation Steps
Remove the 10,000 limit in the setter functions and implement appropriate checks for maximum fee amounts.
