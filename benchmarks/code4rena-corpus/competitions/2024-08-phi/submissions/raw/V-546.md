# Vulnerability details

The `phiSignerAddress` in the contract is used to verify that signatures received from the backend are valid. The signatures are checked against this address in the `_validateArtCreationSignature()` function. However, if the `phiSignerAddress` is updated using the `setPhiSignerAddress()` function, all previously issued signatures that are still pending will become invalid. This is because the signer address stored in the smart contract is no longer the same as the address that generated the signatures. As a result, all pending art creation transactions that rely on these signatures will fail.


## Impact
When the `phiSignerAddress` is changed, it causes all pending signatures to become invalid. This will lead to a failure in the art creation process for any artists who have paid for and obtained signatures from the previous address but have not yet completed their transactions. This could result in financial losses, frustration for users, and a disruption in the functionality of the contract, as all pending art creation operations would be halted.

## Proof of Concept
Add this code to the `PhiFactory.t.sol` file and run the following command:
`forge test -vvv --match-test POC`:

```
    function test_POC() public {
        // This creation will pass without any problem
        _createArt(ART_ID_URL_STRING);

        // Owner decided to change the phiSignerAddress
        vm.prank(owner);
        phiFactory.setPhiSignerAddress(address(1337));

        // This creation will revert
        vm.expectRevert(IPhiFactory.AddressNotSigned.selector);
        _createArt(ART_ID2_URL_STRING);
    }
```

## Recommended Mitigation Steps
To prevent this issue, it is recommended to carefully manage when and how the `phiSignerAddress` is updated. One approach could be to include a grace period or notification mechanism before the update takes effect, allowing all pending transactions to complete. Another approach could be to store and validate signatures with their respective signer addresses, ensuring that previous signatures remain valid even after the signer address is updated. This way, the contract can handle multiple valid signer addresses over time.
