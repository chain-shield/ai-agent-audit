# Vulnerability details

## Impact
```solidity
function signatureClaim(
    bytes calldata signature_,
    bytes calldata encodeData_,
    MintArgs calldata mintArgs_
)
    external
    payable
    whenNotPaused
{
    (uint256 expiresIn_, address minter_, address ref_, address verifier_, uint256 artId_,, bytes32 data_) =
        abi.decode(encodeData_, (uint256, address, address, address, uint256, uint256, bytes32));

    if (expiresIn_ <= block.timestamp) revert SignatureExpired();
    if (_recoverSigner(keccak256(encodeData_), signature_) != phiSignerAddress) revert AddressNotSigned();

    _validateAndUpdateClaimState(artId_, minter_, mintArgs_.quantity);
    _processClaim(artId_, minter_, ref_, verifier_, mintArgs_.quantity, data_, mintArgs_.imageURI, msg.value);

    emit ArtClaimedData(artId_, "SIGNATURE", minter_, ref_, verifier_, arts[artId_].artAddress, mintArgs_.quantity);
}
```

In the file `PhiFactory.sol`, function `signatureClaim` does not revert if `art.verificationType` is not equals to `"SIGNATURE"`. Meaning an art with `art.verificationType` set to `"MERKLE"` can still be claimed through the function `signatureClaim`.

For example, we can see that in `merkleClaim`:
```solidity
if (minter_ == address(0) || !art.verificationType.eq("MERKLE") || credMerkleRootHash == bytes32(0)) {
    revert InvalidMerkleProof();
}
```
There is an if statement to revert if the art's verificationType isnt what is intended.

Also, in the function [`claim(bytes calldata encodeData_)` Line269-283:](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L269-L283)<br/>
The function restricts that if `art.verificationType` is set to "MERKLE", **only the function** `merkleClaim` can be called.

However, since `signatureClaim` is an **external** function, users can call it **directly** instead of calling `claim(bytes calldata encodeData_)` which will **bypass** the part where `claim` chooses which function to call based on `art.verificationType`.

Hence, by calling `signatureClaim` directly, user can illegally use a signature to claim it, even though that art is meant to be claimed through the `merkleClaim` function **only**.

## Proof Of Concept
Add this function to `test/PhiFactory.t.sol:TestPhiFactory`
```solidity
function test_claimWrongType() public {
    bytes memory credData = abi.encode(1, owner, "MERKLE", 31_337, bytes32(0));
    bytes memory signCreateData = abi.encode(expiresIn, ART_ID_URL_STRING, credData);
    bytes32 createMsgHash = keccak256(signCreateData);
    bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
    (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
    if (cv != 27) cs = cs | bytes32(uint256(1) << 255);
    IPhiFactory.CreateConfig memory config =
        IPhiFactory.CreateConfig(artCreator, receiver, END_TIME, START_TIME, MAX_SUPPLY, MINT_FEE, false);
    phiFactory.createArt{ value: NFT_ART_CREATE_FEE }(signCreateData, abi.encodePacked(cr, cs), config);

    uint256 artId = 1;
    bytes32 advanced_data = bytes32("1");
    
    bytes memory signData =
        abi.encode(expiresIn, msg.sender, referrer, verifier, artId, block.chainid, advanced_data);
    bytes32 msgHash = keccak256(signData);
    bytes32 digest = ECDSA.toEthSignedMessageHash(msgHash);
    (uint8 v, bytes32 r, bytes32 s) = vm.sign(claimSignerPrivateKey, digest);
    if (v != 27) s = s | bytes32(uint256(1) << 255);
    bytes memory signature = abi.encodePacked(r, s);

    bytes memory encodeData = abi.encode(expiresIn, msg.sender, referrer, verifier, 1, block.chainid, advanced_data);
    IPhiFactory.MintArgs memory mintArgs = IPhiFactory.MintArgs({ tokenId: 1, quantity: 1, imageURI: IMAGE_URL });
    uint256 totalMintFee = phiFactory.getArtMintFee(1, 1);

    vm.startPrank(msg.sender);
    phiFactory.signatureClaim{ value: totalMintFee }(signature, encodeData, mintArgs);
}
```

User manages to call `signatureClaim` and the function **does not revert** but instead executes the claim successfully, which should **not** be the case.

## Recommended Mitigation Steps
Add the following line into `signatureClaim`.
```solidity
require(art.verificationType.eq("SIGNATURE"), "Wrong Verification Type for this art!!");
```

**Or alternatively:**

You could restrict access for `signatureClaim` and `merkleClaim` to `address(this)`. Forcing the users to only be able to claim through the function `claim(bytes calldata encodeData_)` which will determine correctly which signature or merkle claim function to call based on `art.verificationType`.
