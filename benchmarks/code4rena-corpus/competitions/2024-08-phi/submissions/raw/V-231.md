# Vulnerability details

## Impact
Loss of minting fees and the intended minting verification process are bypassed. An attacker can claim multiple NFTs without meeting the required conditions, potentially gaining undeserved rewards or benefits.

## Proof of Concept
In the `PhiFactory` contract, the `batchClaim` function allows users to claim multiple art rewards in a batch by providing an array of `encodeDatas` and corresponding `ethValue` for each claim. However, the function does not verify that at least one art is minted successfully during the batch claiming process.

The root cause [PhiFactory.sol#batchClaim](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L308-L321)
```solidity
    function batchClaim(bytes[] calldata encodeDatas_, uint256[] calldata ethValue_) external payable {
        if (encodeDatas_.length != ethValue_.length) revert ArrayLengthMismatch();


        // calc claim fee
        uint256 totalEthValue;
        for (uint256 i = 0; i < encodeDatas_.length; i++) {
            totalEthValue = totalEthValue + ethValue_[i];
        }
        if (msg.value != totalEthValue) revert InvalidEthValue();


        for (uint256 i = 0; i < encodeDatas_.length; i++) {
            this.claim{ value: ethValue_[i] }(encodeDatas_[i]);
        }
    }
```
The function iterates over the `encodeDatas` array and calls the `claim` function for each data, passing the corresponding `ethValue`. However, it does not check if any art is minted during the process. This allows an attacker to bypass the minting verification by providing valid `encodeDatas` and `ethValue`, even if no art is minted.

The attacker only needs to have valid `encodeDatas` and `ethValue` that pass the initial checks in the `batchClaim` function.

Scenario:

* The attacker calls the `batchClaim` function with carefully crafted `encodeDatas` and `ethValue`.
* The function verifies that the lengths of `encodeDatas` and `ethValue` match and that the total `ethValue` is equal to the `msg.value` sent with the transaction.
* The function iterates over the `encodeData`s array and calls the `claim` function for each data.
* Even if no art is minted during the claiming process, the `batchClaim` function completes successfully without reverting.
* The attacker successfully claims multiple NFTs without meeting the required minting conditions, bypassing the intended verification process.

## Recommended Mitigation Steps
Should keep track of the minting status and ensure that at least one art is minted before completing the function. By introducing a flag variable `anyArtMinted` and checking the `numberMinted` of each art after calling the claim function, we can ensure that at least one art is minted during the batch claiming process. If no art is minted, the function will revert with a custom error `NoArtMinted()`.
```diff
function batchClaim(bytes[] calldata encodeDatas_, uint256[] calldata ethValue_) external payable {
    if (encodeDatas_.length != ethValue_.length) revert ArrayLengthMismatch();

    uint256 totalEthValue;
    for (uint256 i = 0; i < encodeDatas_.length; i++) {
        totalEthValue = totalEthValue + ethValue_[i];
    }
    if (msg.value != totalEthValue) revert InvalidEthValue();

+   bool anyArtMinted = false;
    for (uint256 i = 0; i < encodeDatas_.length; i++) {
        this.claim{ value: ethValue_[i] }(encodeDatas_[i]);
+       if (arts[abi.decode(encodeDatas_[i], (uint256))].numberMinted > 0) {
+           anyArtMinted = true;
+       }
    }
+   if (!anyArtMinted) revert NoArtMinted();
}
```
