# Vulnerability details

## Brief:
_addCredIdPerAddress (Cred.sol::Line 685) and _removeCredIdPerAddress (Cred.sol::Line 695) are functions that add or remove a cred id to an address' list. They are currently marked public but should be marked internal.

## Impact:
The vulnerability allows any user to modify cred id balances for a user without having to trade them or pay for them. This causes wrong accounting of creds as well as mispricing on the bonding curve for other users who want to purchase share creds.The functions should only be accessible from the internal function _updateCuratorShareBalance (Cred.sol::Line 666) which is called by _handleTrade (Cred.sol::Line 588).

## Solution:
Change the visibility for _removeCredIdPerAddress (Cred.sol::Line 695) and _addCredIdPerAddress (Cred.sol::Line 685) to be internal instead of public.
