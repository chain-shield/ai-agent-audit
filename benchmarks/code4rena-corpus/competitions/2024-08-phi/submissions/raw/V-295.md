# Vulnerability details

## Impact
Functions claim() and batchClaim() in PhiFactory.sol do not refund excess of value after execution, what could make caller pay more value than required if they do not know the exact amount. It is true that these functions call ```merkleClaim()``` and ```signatureClaim()```, and these do refund excess of value; but since they are called by using ```this.merkleClaim()``` and ```this.signatureClaim()```, msg.sender becomes PhiFactory contract, that value will remain there instead of returning to the caller of the function.

## Tools Used
Manual review
Remix testing

## Recommended Mitigation Steps
Both claim() and batchClaim() should have a mechanism that sends excess to function caller. In the case of batchClaim() it is necessary to know the excess of value for each operation, what makes it necessary to modify claim() so as to return that value. It is not sufficient to modify just the claim() function because batchClaim() calls ```this.claim()```, so that caller of claim() is the contract itself.
