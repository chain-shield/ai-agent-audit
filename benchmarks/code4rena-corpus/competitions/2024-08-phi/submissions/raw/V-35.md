# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Any sender can withdraw Ether from the contract account.
Arbitrary senders other than the contract creator can profitably extract Ether from the contract account. Verify the business logic carefully and make sure that appropriate security controls are in place to prevent unexpected loss of funds.

Contract: RewardControl
Function Name: withdraw(address to, uint256 amount)
PC Address: 3201
Estimated Gas Usage: 9609 - 64621

The withdraw function in the RewardControl contract lacks appropriate access control, allowing any sender to withdraw Ether from any account within the contract. This vulnerability can lead to an attacker depleting the contract’s Ether balance by performing unauthorized withdrawals, resulting in a significant loss of funds.

## Recommended Mitigation Steps

To mitigate this issue, implement an access control check to ensure that only the legitimate owner of the funds or a party authorized by the owner can initiate a withdrawal. One way to enforce this is by requiring that the caller (msg.sender) must be the same as the from address or an authorized operator. Here’s the coded mitigation:
```sol
function withdraw(address to, uint256 amount) external {
    require(msg.sender == to, "Unauthorized: Caller is not the recipient");
    _withdraw(msg.sender, to, amount);
}

function withdrawFor(address from, uint256 amount) external {
    require(msg.sender == from, "Unauthorized: Caller is not the sender");
    _withdraw(from, to, amount);
}

function withdrawWithSig(
    address from, 
    address to, 
    uint256 amount, 
    uint256 deadline, 
    bytes calldata sig
) 
    external 
{
    require(block.timestamp <= deadline, "Deadline expired");
    require(_verifySignature(from, to, amount, nonces[from], deadline, sig), "Invalid signature");
    require(msg.sender == from || msg.sender == to, "Unauthorized: Caller is not sender or recipient");

    unchecked {
        ++nonces[from];
    }

    _withdraw(from, to, amount);
}
```

The severity of this issue is classified as High because it directly leads to the loss of Ether from the contract. An attacker can exploit this vulnerability to drain the contract’s funds, which could lead to significant financial damage for the contract’s users.
