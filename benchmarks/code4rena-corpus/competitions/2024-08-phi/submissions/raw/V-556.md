# Vulnerability details

## Vulnerability details

When the `createArt` function is called in a `PhiFactory.sol `contract (usually artist) passes ETH. This function creates a new NFT and then either creates a new `PhiNFT1155` contract or adds it to an existing one (it all depends on `credChainId` and `credId`). The corresponding functions `_createNewNFTContract` and `_useExistingNFTContract` are called accordingly. In both of these functions, the low-level function `call` is used, which calls the `PhiNFT1155` contract function with the signature `createArtFromFactory` and passes the `ether` to it.
```solidity
(bool success_, bytes memory response) = newArt.call{ value: msg.value }(abi.encodeWithSignature("createArtFromFactory(uint256)", newArtId));
```
The **vulnerability** is that in this function, if the caller passes more `ether` than needed, the remaining ether **is returned back to the artist**, but in fact **it returns to the PhiFactory contract**.
https://github.com/code-423n4/2024-08-phi/blob/main/src/art/PhiNFT1155.sol#L151-L153
```solidity
//PhiNFT1155.sol:createArtFromFactory() 

if ((msg.value - artFee) > 0) {

_msgSender().safeTransferETH(msg.value - artFee);
}
```
