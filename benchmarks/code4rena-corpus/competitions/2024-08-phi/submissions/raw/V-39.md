# Vulnerability details

## Impact
While claiming art rewards, `PhiFactory::claim(...)` logic identifies the claim verification type and process the claiming of art rewards. Any excess reward if received is returned to the caller of the claim function.

But, due to change in context of the call, the excess ether will not be returned to the caller, instead it will be retained in the `PhiFactory` contract. The issue arises due to the calling convention used in the `PhiFactory::claim(...)` to trigger the `merkleClaim(...)` and `signatureClaim(...)` external function using `this`.

By doing this, the calling context, that is msg.sender switched from original caller to `PhiFactory`. As a result, any excess ether sent will remain in the `PhiFactory` contract. The protocol owner can withdraw such funds using `withdraw(...)`.

Excess funds should be returned back to the caller.

## Proof of Concept
When the `PhiFactory::claim(...)` is initiated by the caller, the function logic identifies the verification flow calls `merkleClaim(...)` or `signatureClaim(...)` function.

The issue arises in how the `merkleClaim(...)` or `signatureClaim(...)` are triggered. Note the below code snippet where one of the two functions will be triggered.  Here, since the trigger is via `this` and both of these functions are external, the `msg.sender` is switched from original caller to 'PhiFactory` contract instance. Hence, from this point onwards, the msg.sender is 'PhiFactory` contract.

```solidity
    if (art.verificationType.eq("MERKLE")) {
        ...
===>        this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
        } else if (art.verificationType.eq("SIGNATURE")) {
        ...
===>        this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
        } 
```
`merkleClaim(...)` or `signatureClaim(...)` function do their specific logic and calls `_processClaim(...)` internal function which returns any excess ether to the `msg.sender`, which in this case would be `PhiFactory` contract. 

Hence, the excess ether received will not be returned to the original caller. The ether will remain in `PhiFactory` contract.

```
   function _processClaim(
        uint256 artId_,
        address minter_,
        address ref_,
        address verifier_,
        uint256 quantity_,
        bytes32 data_,
        string memory imageURI_,
        uint256 etherValue_
    )
        private
    {
       ...
        // Handle refund
        uint256 mintFee = getArtMintFee(artId_, quantity_);
        if ((etherValue_ - mintFee) > 0) {
===>         _msgSender().safeTransferETH(etherValue_ - mintFee);
        }
        ...
    }
```

The owner of `PhiFactory` contract can withdraw the Ether to `protocolFeeDestination` address.

```
    function withdraw() external onlyOwner {
        protocolFeeDestination.safeTransferETH(address(this).balance);
    }
```

Hence, the excess ether goes to the protocol itself and not back to the original caller.
