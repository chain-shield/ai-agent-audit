# Vulnerability details

## Impact
Users can manipulate mappings which are integral to the Cred.sol and the protocol as a whole.

## Proof of Concept
_addCredIdPerAddress() and _removeCredIdPerAddress() **can be accessed by anyone.** 

I can basically add and remove keys from mapping from every single user without any restriction whatsoever, which is propagate to all functions that use those mappings, such as getPositionsForCurator() that uses _credIdsPerAddress mapping.


## Tools Used
Manual review

## Recommended Mitigation Steps
Change the modifier from public to internal, the syntax of the functions indicates that this has been intended, but as I see, it is not implemented.

Access Control
