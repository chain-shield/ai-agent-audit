# Vulnerability details

An incorrect royalty range check will cause the [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L271) function to revert for creators as they will be unable to set the maximum allowed royalty values for their creds.

**Root Cause**
In Cred.sol:158-160, there is an incorrect royalty range check: [Cred.sol#L269-L270](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L269-L271)
```solidity
if (buyShareRoyalty_ > MAX_ROYALTY_RANGE || sellShareRoyalty_ > MAX_ROYALTY_RANGE) {
    revert InvalidRoyaltyRange();
}
```
> The condition checks if either `buyShareRoyalty_` or `sellShareRoyalty_` is strictly greater than `MAX_ROYALTY_RANGE`. However, it doesn't allow the royalty values to be equal to `MAX_ROYALTY_RANG`E, which is a valid case.

## Impact
The creators cannot set the maximum allowed royalty values (`MAX_ROYALTY_RANGE`) for their creds. This limits the flexibility for creators to choose the highest possible royalty percentages, potentially affecting their incentives and rewards.

## Proof of Concept
1. [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L243) is called with the provided input values.
2. Inside [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L243), the [_recoverSigner](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L888-L890) function is called to verify the signature.
3. The recovered signer address matches the `phiSignerAddress`, so the signature verification passes.
4. The `buyShareRoyalty` and `sellShareRoyalty` values are checked against the `MAX_ROYALTY_RANGE` constant.
5. Since both `buyShareRoyalty` and `sellShareRoyalty` are equal to `MAX_ROYALTY_RANGE` (5000), the function reverts with the `InvalidRoyaltyRange` error.

**Internal pre-conditions:**

* The `MAX_ROYALTY_RANGE` constant is set to a specific value (e.g., 5000).

**Attack Path:**

* The creator calls the `createCred` function with `buyShareRoyalty_` and `sellShareRoyalty_` set to `MAX_ROYALTY_RANGE`.
* The function reaches the royalty range check condition in [Cred.sol:createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L271)
* Since both `buyShareRoyalty_` and `sellShareRoyalty_` are equal to `MAX_ROYALTY_RANGE`, the condition evaluates to `true`.
* The function reverts with the `InvalidRoyaltyRange` error, preventing the creation of the cred with the maximum allowed royalty values.

## Tools Used
Manual review

## Recommended Mitigation Steps
To fix the issue, modify the royalty range check condition in [Cred.sol:createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L271) to allow royalty values to be less than or equal to `MAX_ROYALTY_RANGE`. By changing the strict inequality (`>`) to a less than or equal to (`<=`) operator, the function will allow royalty values up to and including `MAX_ROYALTY_RANGE`, enabling creators to set the maximum allowed royalty for their creds.
```diff
- if (buyShareRoyalty_ > MAX_ROYALTY_RANGE || sellShareRoyalty_ > MAX_ROYALTY_RANGE) {
+ if (buyShareRoyalty_ <= MAX_ROYALTY_RANGE || sellShareRoyalty_ <= MAX_ROYALTY_RANGE) {
    revert InvalidRoyaltyRange();
}
```
