# Vulnerability details

## Impact

Contract `PhiNFT1155` allows to receive funds, but lacks any withdraw functions; as a result the funds will get stuck in the contract.

## Summary

Contract `PhiNFT1155` has the following [receive function](
https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L359-L361):


```solidity
receive() external payable {
    // This function is intentionally left empty to allow the contract to receive ETH
}
```

At the same time there is no corresponding `withdraw` function, as is e.g. in [PhiFactory](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L786-L788)

```solidity
function withdraw() external onlyOwner {
    protocolFeeDestination.safeTransferETH(address(this).balance);
}
```

As a result, the funds sent to `PhiNFT1155` will be stuck there. Notice that this is explicitly mentioned in [README](https://github.com/code-423n4/2024-08-phi/blob/main/README.md#attack-ideas-where-to-focus-for-bugs):

> Functional Reliability/Correctness Concerns
> - Is there any unnecessary accumulation of ETH in the contract

## Tools Used

Manual review

## Recommended Mitigation Steps

We recommend to implement the `withdraw` function in `PhiNFT1155` in the same vein as in [PhiFactory](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L786-L788) contract, as well as to add the corresponding `withdrawArtContract` functions to `PhiFactory`, similar to how [pauseArtContract/unpauseArtContract](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L170-L186) are implemented.
