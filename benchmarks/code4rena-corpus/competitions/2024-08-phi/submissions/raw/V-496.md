# Vulnerability details

## Description
`Cred::_addCredIdPerAddress()` & `Cred::_removeCredIdPerAddress()` are two public functions, whose main objective is to maintain the state of whole protocol as mentioned below :
- when a user/curator buys a share, a list is responsible to maintian that in record which is `_credIdsPerAddress`, that states the list of ids a single curator has bought the shares of.
- `_credIdsPerAddressCredIdIndex` is a list which stores the individual ids and there index stored in `credIdsPerAddress` per `curator`
- `_credIdsPerAddressArrLength` is a list of total number of ids per curator.
`Cred::_addCredIdPerAddress()` & `Cred::_removeCredIdPerAddress()` is responsible to add, update & delete the ids there index & length, when the curator either buys shares or sell shares.

Now being public funtions a malicious user could input any random id & the curator address & manipulate however they want.

## Impact
- manipulating it would cause discrepancy in the total supply of shares vs individual shares per address, so while selling or buying it can cause Denial of Service, as originally curator had X shares
but due to malicious user able to delete some shares, now curator has X-Y shares, which should have not happend. This would cause to profit less or no profit incase all ids are deleted.
