# Vulnerability details

## Impact
When creating an art, the function `PhiNFT1155#createArtFromFactory()` is called from `PhiFactory` contract with all `msg.value` sent by user. 
The function `PhiNFT1155#createArtFromFactory()` has the logics to [refund excess value back to `_msgSender()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L151-L153). In this execution step, `_msgSender()` is the contract `PhiFactory`, which is a proxy and will revert because it does not have `receive` or `fallback` in logic contract

## Proof of Concept
Update the test file `test/PhiFactory.t.sol` as below:
```diff
...
function test_createTokenId2() public {
        vm.startPrank(participant);
        string memory artId1 = "rL5L2H5BLDwyojZtOi-7TSCqFM7ISlsDOIlAfTUs5et";
        string memory artId2 = "7TSCqFM7ISlsDOIlAf-7TSCqFM7ISlsDOIlAfTUs5ts";
        _createArt(artId1);

+        uint excessValue = 1 ether;
+        NFT_ART_CREATE_FEE += excessValue; // @audit POC of PhiNFT refund fails due to lack of receive() on Factory
+        deal(participant, 1000 ether);
        _createArt(artId2);

        address artAddress = phiFactory.getArtAddress(1);
        address artAddress2 = phiFactory.getArtAddress(2);

        assertEq(artAddress, artAddress2, "artAddress is correct");
    }
...
```
Run the test `test_createTokenId2` and the console shows:
```bash
Failing tests:

[FAIL. Reason: CreateFailed()] test_createTokenId2() (gas: 1225443)
```

## Recommended Mitigation Steps
Add `receive()` to `PhiFactory` contract to receive ether and update the refund logics when creating an art
