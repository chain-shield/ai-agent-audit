# Vulnerability details

## Description
The _validateAndCalculateBatch function iterates over the credIds array to check for duplicate credential IDs. As the size of the credIds array increases, so does the number of comparisons required to identify duplicates. This results in increasing gas costs, especially for larger batches. Users with larger transactions may experience significantly higher gas costs, which could lead to transaction failures if the gas limit is exceeded.

Additionally, the higher gas cost creates a denial of service (DoS) risk, where users submitting larger batches might have their transactions fail due to gas exhaustion.

## Impact
The impact is two-fold:

Increased Gas Costs: The gas cost of the _validateAndCalculateBatch function increases greatly with the size of the credIds array, making transactions more expensive as the number of credentials processed increases.

DoS Risk: Users submitting large batches are at risk of transaction failure due to high gas consumption, effectively preventing them from completing their transaction.

## Recommended Mitigation Steps
1.Batch Size Limitation: If the batch size is expected to be large, consider implementing a limit on the maximum batch size to reduce the risk of DoS due to excessive gas consumption.

2.Use a Mapping: Instead of iterating through the array to check for duplicates, consider using a mapping to track whether a credential ID has been processed. This reduces the time complexity from O(n^2) to O(n), thereby reducing gas consumption.
```
mapping(uint256 => bool) processedCredIdsMap;
for (uint256 i = 0; i < length; ++i) {
    uint256 credId = credIds_[i];
    if (processedCredIdsMap[credId]) {
        revert DuplicateCredId();
    }
    processedCredIdsMap[credId] = true;
}

```
