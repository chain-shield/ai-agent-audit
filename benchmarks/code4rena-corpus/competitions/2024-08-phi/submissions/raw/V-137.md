# Vulnerability details

## Impact
The caller of the `batchSellShareCred` function will receive excess ETH that should not be transferred. This violates the expected behavior of the function and can lead to unintended consequences and potential vulnerabilities.

## Proof of Concept
The incorrect transfer of `totalPayout` to the caller in the `batchSellShareCred` function will cause the caller to receive excess ETH that should not be transferred. This violates the expected behavior of the function and can lead to unintended consequences and potential vulnerabilities.

In the `batchSellShareCred` function there is an incorrect transfer of `totalPayout` to the caller: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L213-L226
```solidity
function batchSellShareCred(
    uint256[] calldata credIds_,
    uint256[] calldata amounts_,
    uint256[] calldata minPrices_
)
    public
{
    // ...

    _msgSender().safeTransferETH(totalPayout);
}
```
The `totalPayout` amount is directly transferred to the caller using `safeTransferETH`. This transfer should not occur as it violates the expected behavior of the function and can lead to the caller receiving excess ETH.

All it takes is the caller needs to call the `batchSellShareCred` function with valid `credIds_`, `amounts_`, and `minPrices_` parameters.

**Attack Scenario**

* The caller calls the `batchSellShareCred` function with valid parameters.
* The function executes the batch sell operation and calculates the `totalPayout` amount.
* Instead of updating balances or emitting an event, the function directly transfers the `totalPayout` to the caller using `safeTransferETH`.
* The caller receives the excess ETH, which should not have been transferred.

## Tools Used
Manual review

## Recommended Mitigation Steps
The `batchSellShareCred` function should be modified to avoid directly transferring the `totalPayout` to the caller. Instead, the function should update the caller's balance or emit an event indicating the payout amount. The actual transfer of funds should be handled separately, either through a withdraw function or by letting the caller claim their payout.

```diff
function batchSellShareCred(
    uint256[] calldata credIds_,
    uint256[] calldata amounts_,
    uint256[] calldata minPrices_
)
    public
{
    // ...

-   _msgSender().safeTransferETH(totalPayout);
+   // Update caller's balance or emit an event indicating the payout amount
+   // Example: payoutBalances[_msgSender()] += totalPayout;
+   // Example: emit PayoutAvailable(_msgSender(), totalPayout);
}
```
