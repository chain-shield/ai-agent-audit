# Vulnerability details

In `PhiFactory.sol`, the [createArt](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L196-L213) function does not check if the provided `createConfig_.endTime` has already passed. This allows the creation of art with an expired signature, bypassing the intended time restrictions.
```solidity
    function createArt(
        bytes calldata signedData_,
        bytes calldata signature_,
        CreateConfig memory createConfig_
    )
        external
        payable
        nonReentrant
        whenNotPaused
        returns (address)
    {
        _validateArtCreationSignature(signedData_, signature_);
        (, string memory uri_, bytes memory credData) = abi.decode(signedData_, (uint256, string, bytes));
        ERC1155Data memory erc1155Data = _createERC1155Data(artIdCounter, createConfig_, uri_, credData);
        address artAddress = createERC1155Internal(artIdCounter, erc1155Data);
        artIdCounter++;
        return artAddress;
    }
```
## Impact
Users may unintentionally create art with expired signatures, leading to unexpected behavior and potential loss of funds due to the art creation fee. Malicious actors can exploit this vulnerability to create art that should not be allowed based on the specified time constraints.

## Proof of Concept
1. Admin sets the `artCreateFee` to a non-zero value using the [setArtCreatFee](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L430-L434) function.
2. A malicious actor calls the [createArt](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L196-L213) function with a `createConfig_.endTime` that has already passed.
3. The [createArt](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L196-L213) function executes successfully, creating art with an expired signature.
