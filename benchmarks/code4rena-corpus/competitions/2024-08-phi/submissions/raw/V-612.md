# Vulnerability details

## Summary:
 The phiRewards contract is vulnerable to a denial of service (DoS) attack and other potential issues due to its acceptance of zero-value deposits and withdrawals. This allows an attacker to repeatedly call the contract with zero-value transactions, potentially leading to a denial of service and other negative consequences.

## Detail of Vulnerability: 
The vulnerability arises from the fact that the contract does not validate or restrict transactions with a value of zero ether. This allows an attacker to repeatedly call the deposit and withdraw functions with a value of zero ether, potentially causing a denial of service and other issues.

## Impact
If exploited, 
- this vulnerability could lead to a denial of service, causing the contract to become unresponsive and potentially leading to financial losses for users.
- Additionally, the high gas consumption could also lead to increased costs for users and the network as a whole. 
- Other potential impacts include the ability for an attacker to flood the contract with transactions, potentially leading to other security issues or instability.

## Proof of Concept
```JavaScript
function testDoS() public {
        // Set up a large amount of ETH to deposit and withdraw
        uint256 largeAmount = 0 ether;
    
        // Deposit and withdraw repeatedly to attempt to cause a DoS
        for (uint256 i; i < 1000000; ++i) {   //Call as much as you want
            vm.deal(user1, largeAmount);
            vm.prank(user1);
            phiRewards.deposit{ value: largeAmount }(user1, bytes4(0), "test");
            assertEq(phiRewards.balanceOf(user1), largeAmount);
            assertEq(address(phiRewards).balance, largeAmount);
    
            vm.prank(user1);
            phiRewards.withdraw(user1, largeAmount);
            assertEq(user1.balance, largeAmount);
            assertEq(phiRewards.balanceOf(user1), 0);
            assertEq(address(phiRewards).balance, 0);
        }
```

## Recommended Mitigation Steps
To mitigate this vulnerability,
- it is recommended to add validation to the deposit and withdraw functions to reject transactions with a value of zero ether.
- This could be achieved by adding a simple check at the beginning of each function to revert the transaction if the value is zero.
