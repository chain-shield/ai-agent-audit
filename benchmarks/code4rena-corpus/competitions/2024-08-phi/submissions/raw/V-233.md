# Vulnerability details

## Impact
While creating art by calling createArt() function if the caller send more than `NFT_ART_CREATE_FEE` amount of ETH the transaction will always revert and user will loose GAS in this process.

## Proof of Concept
Whenever user wants to create new art by calling createArt() function if the caller send more than `NFT_ART_CREATE_FEE` amount of ETH the transaction will be reverted as while creating the art the IPhiNFT1155Ownable contract is deployed and createArtFromFactory() function is called and this function transfer back any excess ether to the caller that is sent into this function call but PhiFactory contract doesn't have any fallback or receive function resulting this transaction to be reverted.

Foundry test case to verify the same:

Save the test file into the PhiFactory.t.sol and run `forge test --mt test_send_excess_ether_revert -vvv`:
```
function test_send_excess_ether_revert() external {
        string memory artIdUrl_ = "sample-art-id";
        bytes memory credData = abi.encode(1, owner, "SIGNATURE", 31_337, bytes32(0));
        bytes memory signCreateData = abi.encode(expiresIn, artIdUrl_, credData);
        bytes32 createMsgHash = keccak256(signCreateData);
        bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
        (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
        if (cv != 27) cs = cs | bytes32(uint256(1) << 255);
        IPhiFactory.CreateConfig memory config =
            IPhiFactory.CreateConfig(artCreator, receiver, END_TIME, START_TIME, MAX_SUPPLY, MINT_FEE, false);
        vm.expectRevert();
        phiFactory.createArt{ value: NFT_ART_CREATE_FEE * 2 }(signCreateData, abi.encodePacked(cr, cs), config);
        console2.log("Create Art call Reverted For Missing Fallback / Return function");
    }
```
