# Vulnerability details

## Impact
The `PhiNFT1155` contract inherits from OpenZeppelin's `UUPSUpgradeable` but does not call `__UUPSUpgradeable_init()` in its `initialize` function. This omission can lead to the following issues:
-  **Incomplete Initialization**: The UUPS upgrade mechanism might not be properly initialized, which could result in the contract not functioning as intended with regard to upgrades.

-  **Upgrade Insecurity**: Without proper initialization, there may be a lack of safeguards against unauthorized upgrades, potentially allowing malicious actors to exploit the contract's upgradeability.


## Proof of Concept
Missing Initialization Call: The contract code lacks the call to `__UUPSUpgradeable_init()` in the `initialize` function.
```solidity
function initialize(
    uint256 credChainId_,
    uint256 credId_,
    string memory verificationType_,
    address protocolFeeDestination_
)
    external
    initializer
{
    __Ownable_init(msg.sender);
    __Pausable_init();
    __ReentrancyGuard_init();
    initializeRoyalties(protocolFeeDestination_);
    
    ///@audit Missing __UUPSUpgradeable_init() call
}
```
Without this initialization, the contract’s upgrade authorization mechanism may not be properly set up, which can lead to security issues during upgrades.

## Recommended Mitigation Steps
Add Initialization Call: Update the `initialize` function to include the call to `__UUPSUpgradeable_init()` to ensure proper setup of the UUPS upgrade mechanism:
```diff
function initialize(
    uint256 credChainId_,
    uint256 credId_,
    string memory verificationType_,
    address protocolFeeDestination_
)
    external
    initializer
{
    __Ownable_init(msg.sender);
    __Pausable_init();
    __ReentrancyGuard_init();
    initializeRoyalties(protocolFeeDestination_);
+   __UUPSUpgradeable_init(); // Add this line
}
```
