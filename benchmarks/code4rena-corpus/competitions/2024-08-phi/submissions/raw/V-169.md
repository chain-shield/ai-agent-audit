# Vulnerability details

## Impact

uint256 private locked;
/*//////////////////////////////////////////////////////////////
                              CONSTRUCTOR
    //////////////////////////////////////////////////////////////*/
    constructor(address _credContract, address _factoryContract) Ownable(msg.sender) {
        credContract = ICred(_credContract);
        factoryContract = IPhiFactory(_factoryContract);
    }

    /*//////////////////////////////////////////////////////////////
                               MODIFIERS
    //////////////////////////////////////////////////////////////*/
    modifier nonReentrant() virtual {
        if (locked != 1) revert Reentrancy();
        locked = 2;
        _;
        locked = 1;
    }

The nonReentrant modifier is implemented with a common reentrancy guard pattern (locked variable). However, it looks like locked is initialized to 0 by default, and in the modifier, you're checking if (locked != 1) revert Reentrancy();.
The locked variable should be initialized to 1 in the contract's constructor to avoid blocking the first call to a function that uses this modifier.

## Proof of Concept

As locked = 0 , if you add any function with the nonReentrant modifier, the function can not be running forever.

## Recommended Mitigation Steps

So you need to initialize the locked variable in constructor function.
constructor(address _credContract, address _factoryContract) Ownable(msg.sender) {
    credContract = ICred(_credContract);
    factoryContract = IPhiFactory(_factoryContract);
    locked = 1;  // Initialize the reentrancy guard
}
