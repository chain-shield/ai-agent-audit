# Vulnerability details

The incorrect incrementation of `credIdCounter` will cause an inconsistency between the `credId` emitted in the `CredCreated` event and the actual `credId` assigned to the new cred, leading to confusion and difficulty in tracking cred creation for users and external systems relying on the `CredCreated` event.

### Root Cause
In Cred.sol, the [_createCredInternal](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L572-L577) function incorrectly increments the `credIdCounter` after emitting the `CredCreated` event but before returning the new `credId`.
```solidity
function _createCredInternal(
    address creator_,
    string memory credURL_,
    string memory credType_,
    string memory verificationType_,
    address bondingCurve_,
    uint16 buyShareRoyalty_,
    uint16 sellShareRoyalty_
)
    internal
    whenNotPaused
    returns (uint256)
{
    // ...

    emit CredCreated(creator_, credIdCounter, credURL_, credType_, verificationType_);

    credIdCounter += 1;

    return credIdCounter - 1;
}
```
## Impact
The inconsistency between the emitted `credId` in the `CredCreated` event and the actual `credId` assigned to the new cred can lead to confusion and difficulty in tracking cred creation for users and external systems relying on the `CredCreated` event. This may result in incorrect associations between cred creation events and their corresponding `credId` values.

## Proof of Concept
* The [createCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L232-L280) function is called with valid parameters.
* The [_createCredInternal](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L544-L577) function is invoked internally.
* The `CredCreated` event is emitted with the current value of `credIdCounter`.
* The `credIdCounter` is incremented after the event emission.
* The incremented `credIdCounter - 1` is returned as the new `credId`.

As a result, the `credId` emitted in the `CredCreated` event will be one less than the actual credId assigned to the new cred.

Manual review

## Recommended Mitigation Steps
The `credIdCounter` should be incremented immediately after the `CredCreated` event emission and before returning the new `credId`. 
```diff
emit CredCreated(creator_, credIdCounter, credURL_, credType_, verificationType_);

+ uint256 newCredId = credIdCounter;
+ credIdCounter += 1;
- credIdCounter += 1;

- return credIdCounter - 1;
+ return newCredId;
```
