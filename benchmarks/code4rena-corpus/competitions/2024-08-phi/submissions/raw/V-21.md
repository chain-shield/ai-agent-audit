# Vulnerability details

## Impact
If a user sets a different address as `creator_` during creation, the created `credId` can never be updated.

## Proof of Concept
In `createCred()`, [`creator_`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L233) is a user supplied parameter.
```solidity
    function createCred(
>>      address creator_,
        ---SNIP---
    )
        public
        payable
        whenNotPaused
    {
        ---SNIP---

>>      if (sender != _msgSender()) revert Unauthorized();

        ---SNIP---
    }
```
The function then proceeds to perform [`sender` validation](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L256) by ensuring that it the caller (`_msgSender()`) but does not perfrom any validation on `creator_`.

[`_createCredInternal()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L273-L275) is then invoked to perfrom the configurations for the `credId` with `creator_` provided:
```solidity
        uint256 credId = _createCredInternal(
>>          creator_, credURL, credType, verificationType, bondingCurve, buyShareRoyalty_, sellShareRoyalty_
        );
```
This then [sets the provided `creator_` address as then `creator`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L561) for this new `credId`
```solidity
creds[credIdCounter].creator = creator_;
```

The problem however arises during [`updateCred()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L297-L299). This function requires that both the `creator` and `sender` of the `credId` being updated be the `_msgSender()`.
```solidity
    if (sender != _msgSender()) revert Unauthorized();

    if (creds[credId].creator != _msgSender()) revert Unauthorized();
```
However, this will not always be the case if during creation, the user provided a different address as `creator_` other than their own (`_msgSender()`).

**Scenario**
- `Bob` has two addresses: `0xBob1` and `0xBob2`
- During creation he calls the function with `0xBob1` as `_msgSender()` which also is the `sender` and provides `0xBob2` as `creator_`.
- Since `createCred()` does not enforce that `creator_` is `_msgSender()`, the creation proceeds setting `0xBob2` as `creator` for this `credId`.
- `Bob` later decides to update this `credId`. 
- He calls `updateCred()` with `0xBob1` as `_msgSender()` which also is the `sender`. This passes
- However, the `creator` was previously set to `0xBob2`. This then reverts since `0xBob2` is not `_msgSender()`

## Tools Used
Manual Review

## Recommended Mitigation Steps
Enforce that the `creator_` parameter is `_msgSender()` during creation.
```diff
    function createCred(
        address creator_,
        ---SNIP---
    )
        public
        payable
        whenNotPaused
    {
        ---SNIP---

        if (sender != _msgSender()) revert Unauthorized();
+       require(creator_ == _msgSender(), "Creator must be the caller");

        ---SNIP---
    }
```
