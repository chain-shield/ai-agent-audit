# Vulnerability details

 
## Description

The `Cred` contract manages user holdings of `credIds` through a complex system of mappings and arrays. The [`_removeCredIdPerAddress()` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L695-L730) is responsible for removing a `credId` from a user's list when they sell all their shares. However, this function fails to update the [`_credIdExistsPerAddress` mapping](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L51) , which is crucial for tracking whether a user holds a particular `credId`. This oversight can lead to significant inconsistencies in the contract's state and potentially disrupt core functionalities.

The contract uses several data structures to manage user holdings:
1. `_credIdsPerAddress`: An array that stores the list of `credIds` a user holds.
2. `_credIdExistsPerAddress`: A mapping that quickly checks if a user holds a specific `credId`.
3. `_credIdsPerAddressCredIdIndex`: A mapping that stores the index of each `credId` in the `_credIdsPerAddress` array.

The [`_removeCredIdPerAddress()` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L695-L729) is called when a user sells all their shares of a `credId`. It correctly updates the `_credIdsPerAddress` array and the `_credIdsPerAddressCredIdIndex` mapping, but fails to update the `_credIdExistsPerAddress` mapping. This creates a discrepancy between the actual state and the recorded state of user holdings.

The root cause of the issue is in the `_removeCredIdPerAddress()` function:

```solidity
function _removeCredIdPerAddress(uint256 credId_, address sender_) public {
    // ... (existing code)

    // Remove the last element (which is now a duplicate)
    _credIdsPerAddress[sender_].pop();

    // Remove the index mapping for the removed credId
    delete _credIdsPerAddressCredIdIndex[sender_][credIdToRemove];

    // Decrement the array length counter, if it's greater than 0
    if (_credIdsPerAddressArrLength[sender_] > 0) {
        _credIdsPerAddressArrLength[sender_]--;
    }

    // Missing: Update the _credIdExistsPerAddress mapping
    // _credIdExistsPerAddress[sender_][credId_] = false;
}
```

The highest impact scenario occurs when a user sells all their shares of a `credId` and then attempts to buy shares of the same `credId` again. The `_addCredIdPerAddress()` function, which is called when buying shares, checks the `_credIdExistsPerAddress` mapping to determine if the `credId` should be added to the user's list. Due to the inconsistent state, this function will incorrectly assume the user still holds the `credId`, leading to potential errors in share allocation and balance tracking.

## Impact
The failure to update the `_credIdExistsPerAddress` mapping in the `_removeCredIdPerAddress()` function can lead to severe inconsistencies in tracking user holdings. This can result in incorrect reporting of user balances, potential array out-of-bounds errors when accessing `_credIdsPerAddress`, and issues with re-adding `credIds` when users buy shares after selling all their previous holdings.


## Proof of Concept
1. Alice buys shares of `credId` 1.
   - `_addCredIdPerAddress(1, Alice)` is called.
   - `_credIdExistsPerAddress[Alice][1]` is set to `true`.
   - `1` is added to `_credIdsPerAddress[Alice]`.

2. Alice sells all her shares of `credId` 1.
   - `_removeCredIdPerAddress(1, Alice)` is called.
   - `1` is removed from `_credIdsPerAddress[Alice]`.
   - `_credIdExistsPerAddress[Alice][1]` remains `true` (bug).

3. Alice tries to buy shares of `credId` 1 again.
   - The contract checks `_credIdExistsPerAddress[Alice][1]`, which is `true`.
   - The contract assumes Alice still holds `credId` 1 and doesn't add it to `_credIdsPerAddress[Alice]`.
   - Alice's holdings are now inconsistent: the contract thinks she holds `credId` 1, but it's not in her `_credIdsPerAddress` array.

4. Subsequent operations on Alice's holdings of `credId` 1 may lead to errors or unexpected behavior.

Manual review

## Recommended Mitigation Steps
Update the `_removeCredIdPerAddress()` function to set `_credIdExistsPerAddress[sender_][credId_]` to `false`. This ensures that the mapping is correctly updated, maintaining consistency and preventing potential errors.
