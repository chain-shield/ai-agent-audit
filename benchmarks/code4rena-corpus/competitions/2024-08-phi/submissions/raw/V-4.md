# Vulnerability details

## Impact
The contract lacks methods to update the bonding curve for the existing creds, which could lead to issues if flaws are discovered in a bonding curve post-deployment.

The trading methods also do not check for whitelisted curves. The createCred() function checks if the bonding curve is whitelisted, but subsequent trading functions (buyShareCred(), sellShareCred(), etc.) do not re-verify this. This allows continued trading with curves which may have been removed from the whitelist.
Batch buy and sell operations also don't revalidate the whitelist status of bonding curves, potentially allowing large-scale trading using compromised curves.

The main issue is absence of any way to update bonding curves for existing creds. If a critical flaw is found in a bonding curve, there's no way to update affected creds to use a new, secure curve. 
These issues assume that once a cred is created with a valid bonding curve, that curve will always remain valid and secure. This assumption may not hold in practice, especially for long-lived contracts, as also evident by methods present to update whitelisted curves.
