# Vulnerability details

## Impact
The protocol and the creator will loss of fees when a user buys shares with insufficient `msg.value`. The user gains the ability to purchase shares without fully covering the price and associated fees.

## Proof of Concept
The `buyShareCred` function allows users to buy shares of a credential. However, there is insufficient validation of the `msg.value` sent by the user against the total cost (price + protocol fee + creator fee) of the purchase.

The issue lies in the `buyShareCred` function in [Cred.sol:L178-L180](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L178-L180)
```solidity
function buyShareCred(uint256 credId_, uint256 amount_, uint256 maxPrice_) public payable {
    _handleTrade(credId_, amount_, true, _msgSender(), maxPrice_);
}
```
The function calls `_handleTrade` without first verifying that the `msg.value` is sufficient to cover the total cost of the purchase.

In the [_handleTrade function:L611-L622](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L611-L622)
```solidity
(uint256 price, uint256 protocolFee, uint256 creatorFee) =
    IBondingCurve(cred.bondingCurve).getPriceData(credId_, supply, amount_, isBuy);

if (isBuy) {
    if (priceLimit != 0 && price + protocolFee + creatorFee > priceLimit) revert PriceExceedsLimit();
    if (supply + amount_ > MAX_SUPPLY) {
        revert MaxSupplyReached();
    }

    if (msg.value < price + protocolFee + creatorFee) {
        revert InsufficientPayment();
    }
}
```
The check `if (msg.value < price + protocolFee + creatorFee)` is performed after updating the share balance and supply, which means the transaction will revert after the updates have been made.

**Here's how an attacker could exploit this vulnerability:**

1. The attacker calls `buyShareCred` with a `credId_`, `amount_`, and `maxPrice_`, but sends a `msg.value` that is less than the total cost.
2. The `_handleTrade` function is called, which updates the share balance and supply.
3. The `if (msg.value < price + protocolFee + creatorFee)` check fails, causing the transaction to revert.
4. However, the share balance and supply have already been updated, leading to inconsistencies in the contract state.

## Tools Used
Manual review

Recommended Mitigation Steps
The validation of `msg.value` should be performed before any state updates in the `buyShareCred` function. 
```diff
function buyShareCred(uint256 credId_, uint256 amount_, uint256 maxPrice_) public payable {
+   (uint256 price, uint256 protocolFee, uint256 creatorFee) =
+       IBondingCurve(creds[credId_].bondingCurve).getPriceData(credId_, creds[credId_].currentSupply, amount_, true);
+   if (msg.value < price + protocolFee + creatorFee) {
+       revert InsufficientPayment();
+   }
    _handleTrade(credId_, amount_, true, _msgSender(), maxPrice_);
}
```
Now the function will revert before any state modifications if the msg.value is insufficient, preventing inconsistencies and ensuring the protocol and creator receive their expected fees.
