# Vulnerability details

### Summary
The `updateArtSettings` function in the `PhiFactory` contract allows artists to modify the minting fee (`mintFee`) associated with their art pieces. However, there is currently no mechanism to prevent significant increases in the `mintFee` while there may be pending minting claims in the `PhiNFT1155Ownable` contract. This lack of control can result in users facing unexpectedly high fees when their claims are processed.

### Code Snippets

**Function: `updateArtSettings`**
```solidity
function updateArtSettings( // ... other parameters
    uint256 mintFee_, // ...
) external onlyArtCreator(artId_) {
    // ... (Input validations - no restriction on mintFee_ increase)
    PhiArt storage art = arts[artId_];
    // ... 
    art.mintFee = mintFee_;
    // ...
}
```

**Function: `getArtMintFee`**
```solidity
function getArtMintFee(uint256 artId_, uint256 quantity_) public view returns (uint256) {
    return IPhiRewards(phiRewardsAddress).computeMintReward(quantity_, arts[artId_].mintFee) + quantity_ * mintProtocolFee;
}
```

**Function: `_processClaim`**
```solidity
function _processClaim( // ... other parameters) private {
    uint256 mintFee = getArtMintFee(artId_, quantity_); // Fetches the potentially updated mintFee
    // ...
    if (msg.value < mintFee) revert InvalidMintFee(); // Claim could fail if mintFee was increased significantly
    // ...
}
```

### Impact
**User Frustration & Abandoned Claims**: If the `mintFee` is significantly increased after a user initiates a claim, they may be surprised by the higher fee when their claim is processed. This could lead to user frustration, abandoned claims, or a perception of unfairness.

### Scenario
1. An artist creates an art piece with a `mintFee` of 0.1 ETH.
2. A user initiates a minting claim.
3. Before the claim is processed, the artist updates the art settings, increasing the `mintFee` to 0.5 ETH.
4. When the user's claim is processed, they are required to pay 0.5 ETH, five times the fee they expected.

### Fix Options
**Option 1: Notification Mechanism**  
Implement a notification system for users with pending claims about significant `mintFee` changes. This could involve:
- Storing pending claim information (including the expected `mintFee`) in the `PhiNFT1155Ownable` contract.
- Emitting an event whenever the `mintFee` is updated.
- Off-chain systems listening to these events and notifying affected users, allowing them to adjust their payment or cancel the claim if they wish.

**Option 2: Limit `mintFee` Increase**  
Add a validation in `updateArtSettings` to restrict the percentage by which `mintFee` can be increased in a single update. For example:
```solidity
if (mintFee_ > art.mintFee * 120 / 100) { // Limit increase to 20%
    revert MintFeeIncreaseTooHigh();
}
```

The choice between these options or a combination thereof depends on the desired balance between user experience and artist control.
