# Vulnerability details


## Description

The `PhiFactory` contract is responsible for managing the creation and claiming of art NFTs. The [`_processClaim` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L723-L758) handles the distribution of fees when an art claim is processed. However, there is a critical issue in the fee calculation and distribution logic.

### Summary of Functionalities

The `PhiFactory` contract includes several key functions and variables related to fee management:
- [`getArtMintFee(artId_, quantity_)`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L509-L512): Calculates the mint fee for a given art ID and quantity.
- [`_processClaim(artId_, minter_, ref_, verifier_, quantity_, data_, imageURI_, etherValue_)`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L723-L758): Handles the fee distribution and processes the art claim.

The [`initialize` function sets the `artCreateFee`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L147), which is intended to be a fee paid to the art creator for each mint. This fee can be modified by the [`setArtCreatFee` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L430-L434).

### Detailed Description

The `_processClaim` function is designed to:
1. Calculate the mint fee using `getArtMintFee(artId_, quantity_)`.
2. Handle any necessary refunds.
3. Distribute the protocol fee to `protocolFeeDestination`.
4. Send the remaining amount to the art contract.

However, the `getArtMintFee` function does not account for the `artCreateFee`, leading to an incorrect fee distribution. Specifically, the `artCreateFee` is not included in the total fee calculation, resulting in the art creator not receiving their due fees. The excess funds remain in the `PhiFactory` contract, which can be exploited.



## Impact

The incorrect fee distribution leads to financial loss for art creators, as they do not receive the fees they are entitled to. 

## Proof of Concept

1. The `getArtMintFee` function does not include the `artCreateFee`:
   ```solidity
   function getArtMintFee(uint256 artId_, uint256 quantity_) public view returns (uint256) {
       return IPhiRewards(phiRewardsAddress).computeMintReward(quantity_, arts[artId_].mintFee)
           + quantity_ * mintProtocolFee;
   }
   ```

2. The `_processClaim` function does not account for the `artCreateFee`:
   ```solidity
   function _processClaim(
       uint256 artId_,
       address minter_,
       address ref_,
       address verifier_,
       uint256 quantity_,
       bytes32 data_,
       string memory imageURI_,
       uint256 etherValue_
   )
       private
   {
       PhiArt storage art = arts[artId_];

       // Handle refund
       uint256 mintFee = getArtMintFee(artId_, quantity_);
       if ((etherValue_ - mintFee) > 0) {
           _msgSender().safeTransferETH(etherValue_ - mintFee);
       }
       protocolFeeDestination.safeTransferETH(mintProtocolFee * quantity_);

       (bool success_,) = art.artAddress.call{ value: mintFee - mintProtocolFee * quantity_ }(
           abi.encodeWithSignature(
               "claimFromFactory(uint256,address,address,address,uint256,bytes32,string)",
               artId_,
               minter_,
               ref_,
               verifier_,
               quantity_,
               data_,
               imageURI_
           )
       );

       if (!success_) revert ClaimFailed();
   }
   ```
