# Vulnerability details

## Impact

function `withdrawWithSig` doesn't revert when the block.timestamp is equal to signature.deadline.That may cause user could use an expired signature to withdraw. This goes against the original design intention of the function.

## Proof of Concept

The check logic doesn't consider the situation when `block.timestamp == deadline`.
Compared with other function in this contract, they will revert when `block.timestamp == deadline`
```
    function withdrawWithSig(address from, address to, uint256 amount, uint256 deadline, bytes calldata sig) external {
        if (block.timestamp > deadline) revert DeadlineExpired(); //[*]
        if (!_verifySignature(from, to, amount, nonces[from], deadline, sig)) revert InvalidSignature();

        unchecked {
            ++nonces[from];
        }

        _withdraw(from, to, amount);
    }
```
