# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Anyone who has a valid signed data by the `phiSignerAddress` can create art by calling `PhiFactory.createArt`.

During this process, the art data should be validated correctly. 
The following validations are inconsistent or missing:
- `art.receiver` is not checked against address(0) which can result in lost rewards when a claim is processed
- the `startTime` can be in the past, even tho this is a known issue in the audit description, it is only for `updateArtSettings` and not for create. 
Why it's important to validate on create is because these signatures can be signed at point t1 but someone submitting them at t1+1000 which can result in start time being in the past.
```solidity
if (createData_.endTime <= block.timestamp) revert EndTimeInPast();
if (createData_.endTime <= createData_.startTime) revert EndTimeLessThanOrEqualToStartTime();
```
- `credCreator` is not checked to be address(0), another important field which if it's address(0) will be reflected in `depositRewards` as `verifier`

```
if (receiver_ == address(0) || minter_ == address(0) || verifier_ == address(0)) {
    revert InvalidAddressZero();
}
```
If this is set to `address(0)` then all the claims will revert, this variable being immutable as well.
