# Vulnerability details

## Impact
The function `_updateCuratorShareBalance()` in `Cred.sol` updates the balance for the user, meaning it is called for every bought or sold Cred. Within this function there are two public functions `_addCredIdPerAddress()` and `_removeCredIdPerAddress()` that update some storage mappings for given user and credId, depending on if the user wants to buy or sell the credId. 

The `_removeCredIdPerAddress()` function does multiple checks and reverts on multiple places (e.g., if the array of credIds for given sender is empty, etc.). 

A malicious user can call this function for any sender and delete any or all of the credIds for this sender, causing the function to revert next time when it is called (through regular chain of calls). It's important to say that this will be possible if the user wants to sell all of his credId shares or the last one since `_removeCredIdPerAddress()` is only called in case of 

```solidity 
if ((currentNum - amount_) == 0) {
        _removeCredIdPerAddress(credId_, sender_);
        _credIdExistsPerAddress[sender_][credId_] = false;
}
```
The attacker can also find out which user is holding which credId and which amount of it by calling `getCuratorAddressesWithAmount()` which makes it even easier to know which credId to remove for which user. 

## Proof of Concept
Imagine following scenario: 

1. User A buys 100 shares of credId = 1
2. `_updateCuratorShareBalance()` increases the user's balance accordingly
3. A malicious user calls `_removeCredIdPerAddress()` with credId = 1 and user's 
   A address removing the credId from the users mapping with the following two 
   lines
   ` _credIdsPerAddress[sender_].pop();`
   ` delete _credIdsPerAddressCredIdIndex[sender_][credIdToRemove];`
4. After sometime, User A decides to batch sell all of his shares of credId = 1
5. This code block is executed as part of the `_updateCuratorShareBalance()`
   ```
    else {
          if ((currentNum - amount_) == 0) {
              _removeCredIdPerAddress(credId_, sender_);
              _credIdExistsPerAddress[sender_][credId_] = false;
          }
          shareBalance[credId_].set(sender_, currentNum - amount_);
     }
    ```
6. `_removeCredIdPerAddress()` is executed with the same credId and the same 
    user's A address
7. `_removeCredIdPerAddress()` reverts on the first line because the lenght of 
    the array is equal to 0
    `if (_credIdsPerAddress[sender_].length == 0) revert EmptyArray();`
8. User A is not able to sell his shares of credId = 1
