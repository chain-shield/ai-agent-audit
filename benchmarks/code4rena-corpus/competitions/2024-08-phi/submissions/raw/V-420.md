# Vulnerability details

## Impact
The current implementation of the art creation process in the PhiFactory and PhiNFT1155 contracts contains a critical flaw in the ETH refund mechanism. When a user creates art and sends excess ETH beyond the required art creation fee, the excess amount is incorrectly refunded to the PhiFactory contract instead of the original user. This results in a direct loss of funds for users who accidentally overpay during the art creation process. 

## Proof of Concept
In PhiFactory.sol:
```solidity
 createERC1155Internal(uint256 newArtId, ERC1155Data memory createData_) internal returns (address) {
    // ...
    (bool success_, bytes memory response) =
        newArt.call{ value: msg.value }(abi.encodeWithSignature("createArtFromFactory(uint256)", newArtId));
    // ...
}
```
The entire msg.value is forwarded to the PhiNFT1155 contract.
In PhiNFT1155.sol:
```solidity
function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
    // ...
    uint256 artFee = phiFactoryContract.artCreateFee();
    protocolFeeDestination.safeTransferETH(artFee);
    // ...
    if ((msg.value - artFee) > 0) {
        _msgSender().safeTransferETH(msg.value - artFee);
    }
    // ...
}
```
The excess ETH is refunded to _msgSender(), which is the PhiFactory contract, not the original user.
