# Vulnerability details

## Description
The flow of creating an art is as follows: `PhiFactory::createArt` -> `PhiFactory::createERC1155Internal` -> `PhiFactory::_createNewNFTContract` -> `PhiNFT1155::createArtFromFactory`

The following code is present in `PhiNFT1155::createArtFromFactory`:

```solidity
    function createArtFromFactory(uint256 artId_){
        ...
        if ((msg.value - artFee) > 0) {
@>          _msgSender().safeTransferETH(msg.value - artFee);
        }
        ...
    }
```
Indicating, if additional amount of ether is sent, return the difference to the `msg.sender`, here `msg.sender` of `PhiNFT1155::createArtFromFactory` is not `artist` but `PhiFactory` which is missing a `fallback` function
Thus cannot receive any ether amount. Causing it to revert everytime additonal ether is sent.

## Impact
The transaction is reverted, and fucntionality is DoS'ed.

## Proof of Concept
Go to the `_createArt` in `PhiFactory.t.sol` and just increase the value sent along in last line by `1`
This would start reverting.

## Tools Used
Manual Review

## Recommended Mitigation Steps
In `PhiFactoy::createArt` store the address of the caller in a variable, and pass it along to all the functions and finally in `PhiNFT1155::createArtFromFactory` make changes as below :

```diff
-    function createArtFromFactory(uint256 artId_){
+    function createArtFromFactory(uint256 artId_, address sender){
        ...
        if ((msg.value - artFee) > 0) {
-         _msgSender().safeTransferETH(msg.value - artFee);
+         sender..safeTransferETH(msg.value - artFee);
        }
        ...
    }
```
