# Vulnerability details

## Impact
In the Cred._handleTrade() function, the following condition is checked before trading:
https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L625-L629
if (block.timestamp <= lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD) {
revert ShareLockPeriodNotPassed(
block.timestamp, lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD
);
}

However, this condition can be used to permanently block trading.

## Proof of Concept
The attacker views the mempool. Sees a buy/sell transaction from the user. With increased gas, calls the buyShareCredFor() function (https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L186-L189) with the curator address from the mempool. Specifies the minimum value as amount. The attacker's transaction is executed before the user's transaction.

When the buyShareCredFor() function is executed, _handleTrade() is called. In the _handleTrade() function, the lastTradeTimestamp[credId_][curator_] = block.timestamp (https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L644) parameter is written for this curator. The user's transaction will not be executed because the condition will be revert.

if (block.timestamp <= lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD) {
revert ShareLockPeriodNotPassed(
block.timestamp, lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD
);
}
