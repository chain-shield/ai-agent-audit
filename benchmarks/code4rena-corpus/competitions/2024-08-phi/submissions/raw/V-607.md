# Vulnerability details

### Summary
The Cred contract utilizes inline assembly to resize arrays within the `getPositionsForCurator` and `_getCuratorData` functions. This approach bypasses Solidity's inherent safety checks, exposing the contract to critical vulnerabilities.

### Details
The contract's manual manipulation of array lengths using assembly can lead to severe security issues, including data corruption and denial of service.

#### Code Snippets
1. **In `getPositionsForCurator`:**
    ```solidity
    assembly {
        mstore(credIds, index)
        mstore(amounts, index)
    }
    ```

2. **In `_getCuratorData`:**
    ```solidity
    assembly {
        mstore(result, index)
    }
    ```

### Impact
This vulnerability can result in:

1. **Return of Incorrect Data:** An attacker may manipulate the contract state to set `index` larger than the actual number of valid elements, leading to the function returning an array filled with uninitialized or garbage data.
  
2. **Potential Out-of-Bounds Access:** If other contract functions assume the returned array length is accurate and iterate over it without additional checks, it could lead to accessing uninitialized memory or other unintended areas of contract memory.

3. **Possible Contract State Corruption:** If the manipulated array is utilized to update the contract state elsewhere, it could corrupt the contract's state with invalid data.

4. **Denial of Service:** By manipulating the contract to return excessively large arrays, an attacker could cause functions that process these arrays to run out of gas, effectively denying service.

### Exploitation Scenario
The exploitation scenario is more severe than initially suggested:

1. **Data Misrepresentation:** An attacker could set `index` to a value larger than the number of valid elements, resulting in an array with uninitialized data being returned.

2. **Out-of-Bounds Access:** Other parts of the contract may iterate over the returned array without proper checks, leading to potential memory access violations.

## Recommended Mitigation Steps
Avoid use of assembly all together.
