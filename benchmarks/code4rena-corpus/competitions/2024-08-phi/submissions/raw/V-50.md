# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Contract: RewardControl
Function name: `withdrawWithSig(address,address,uint256,uint256,bytes)`
PC address: 3174
Estimated Gas Usage: 23057 - 171401

The `withdrawWithSig` function in the `RewardControl` contract makes multiple external calls within the same transaction. Specifically, it relies on the `SignatureCheckerLib.isValidSignatureNowCalldata` function, which in turn makes a `staticcall` to verify the validity of a signature. This approach could lead to vulnerabilities if one of the external calls fails, causing the entire transaction to revert. A malicious callee could exploit this by intentionally causing a failure, preventing the execution of subsequent calls.

If an external call (e.g., signature verification) fails, the entire transaction could be reverted, which might result in denial of service (DoS). This issue becomes particularly severe if the transaction is critical, such as a withdrawal or transfer of funds. Attackers could exploit this to block legitimate withdrawals by causing signature verification to fail.

## Recommended Mitigation Steps
To mitigate this issue, refactor the `withdrawWithSig` function to minimize the reliance on external calls. One approach is to separate the signature verification process from the withdrawal logic, ensuring that the signature is verified before any state changes or external calls occur. Additionally, consider adding fail-safe mechanisms to handle scenarios where the signature verification fails without causing the entire transaction to revert.

**Mitigated Code:**

```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.25;

import { EIP712 } from "../../lib/solady/src/utils/EIP712.sol";
import { IRewards } from "../interfaces/IRewards.sol";
import { SignatureCheckerLib } from "../../lib/solady/src/utils/SignatureCheckerLib.sol";
import { SafeTransferLib } from "../../lib/solady/src/utils/SafeTransferLib.sol";

contract RewardControl is IRewards, EIP712 {
    using SafeTransferLib for address;

    uint256 private constant FULL_BALANCE = 0;
    bytes32 public constant WITHDRAW_TYPEHASH =
        keccak256("Withdraw(address from,address to,uint256 amount,uint256 nonce,uint256 deadline)");

    mapping(address => uint256) public nonces;
    mapping(address => uint256) public balanceOf;

    function withdraw(address to, uint256 amount) external {
        _withdraw(msg.sender, to, amount);
    }

    function withdrawFor(address from, uint256 amount) external {
        require(msg.sender == from, "Unauthorized: Caller must be the owner of the funds.");
        _withdraw(from, from, amount);
    }

    function withdrawWithSig(address from, address to, uint256 amount, uint256 deadline, bytes calldata sig) external {
        if (block.timestamp > deadline) revert DeadlineExpired();
        
        // Mitigation: First verify the signature and return a boolean to avoid state changes if it fails
        bool isValidSignature = _verifySignature(from, to, amount, nonces[from], deadline, sig);
        require(isValidSignature, "InvalidSignature");

        unchecked {
            ++nonces[from];
        }

        _withdraw(from, to, amount);
    }

    function _withdraw(address from, address to, uint256 amount) internal {
        if (to == address(0)) revert InvalidAddressZero();

        uint256 balance = balanceOf[from];
        if (amount == FULL_BALANCE) {
            amount = balance;
        }

        if (amount > balance) revert InvalidAmount();

        unchecked {
            balanceOf[from] = balance - amount;
        }

        to.safeTransferETH(amount);
        emit Withdraw(from, to, amount);
    }

    function _verifySignature(
        address from,
        address to,
        uint256 amount,
        uint256 nonce,
        uint256 deadline,
        bytes calldata sig
    )
        internal
        view
        returns (bool)
    {
        bytes32 structHash = keccak256(abi.encode(WITHDRAW_TYPEHASH, from, to, amount, nonce, deadline));
        bytes32 digest = _hashTypedData(structHash);
        return SignatureCheckerLib.isValidSignatureNowCalldata(from, digest, sig);
    }
}
```
To mitigate the risk associated with multiple calls in a single transaction, refactor the code to ensure that external calls, especially those that might fail (like signature verification), are handled separately from state-changing operations. By decoupling the signature verification from the withdrawal process, the contract can more robustly handle potential failure cases without risking a denial of service or unintended reverts.
