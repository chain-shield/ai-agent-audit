# Vulnerability details

## Impact
`PhiNFT1155` contract is designed to be upgradeable via the `UUPSUpgradeable` pattern. However, the current implementation lacks the necessary upgrade logic in the PhiFactory contract, which is the contract owner and only entity authorized to perform upgrades. As a result, the `PhiNFT1155` contract cannot be upgraded

## Proof of Concept

`PhiNFT1155` initialized by factory and PhiFactory became owner.

```solidity
    function initialize(
        uint256 credChainId_,
        uint256 credId_,
        string memory verificationType_,
        address protocolFeeDestination_
    )
        external
        initializer
    {
        __Ownable_init(msg.sender);
```
`onlyOwner` modifier restricts the upgradeability to the owner, which is set to `PhiFactory`. However, the PhiFactory contract does not implement any function to handle upgrades. As a result, even though PhiNFT1155 is theoretically upgradeable, it is practically impossible to upgrade it due to the lack of corresponding functionality in the PhiFactory contract.

```solidity
    function _authorizeUpgrade(address newImplementation) internal override onlyOwner {
        // This function is intentionally left empty to allow for upgrades
    }
```

## Recommended Mitigation Steps
Add necessary upgrade logic in the PhiFactory contract or give access to another entity to be able to perform upgrade.

``` solidity
function upgradePhiNFT1155(address newImplementation) external onlyOwner {
    PhiNFT1155.upgradeTo(newImplementation);
}
```
