# Vulnerability details

## Impact
No nonce is being used in the signature used in the `PhiFactory::claim` function, meaning signature can be replayed and anyone can call `claim` again with same parameters.

We categorize this vulnerability as MEDIUM as any attacker would still have to pay a sufficient amount to mint the art on behalf of the initial user.
Moreover, the attacker would have no interest in performing this attack if the initial signature being replayed contained the initial user as the `minter_`.

A serious case would be when the initial user signed a transaction to mint 1 NFT to another user and that other user replays the signature to mint more of the same NFT, which is an unlikely scenario.

## Proof of Concept

Let's have a look at the [`PhiFactory::claim`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L264-L304) function below

```javascript
    function claim(bytes calldata encodeData_) external payable {
        bytes memory encodedata_ = LibZip.cdDecompress(encodeData_);
        (uint256 artId) = abi.decode(encodedata_, (uint256));
        PhiArt storage art = arts[artId];
        uint256 tokenId = IPhiNFT1155Ownable(art.artAddress).getTokenIdFromFactoryArtId(artId);
        if (art.verificationType.eq("MERKLE")) {
            (
                ,
                address minter_,
                bytes32[] memory proof,
                address ref_,
                uint256 quantity_,
                bytes32 leafPart_,
                string memory imageURI_
            ) = abi.decode(encodedata_, (uint256, address, bytes32[], address, uint256, bytes32, string));

            bytes memory claimData = abi.encode(minter_, ref_, artId);
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
            this.merkleClaim{ value: mintFee }(proof, claimData, mintArgs, leafPart_);
        } else if (art.verificationType.eq("SIGNATURE")) {
            (
                ,
                address minter_,
                address ref_,
                address verifier_,
                uint256 expiresIn_,
                uint256 quantity_,
                bytes32 data_,
                string memory imageURI_,
                bytes memory signature_
            ) = abi.decode(encodedata_, (uint256, address, address, address, uint256, uint256, bytes32, string, bytes));

            bytes memory claimData = abi.encode(expiresIn_, minter_, ref_, verifier_, artId, block.chainid, data_);
            MintArgs memory mintArgs = MintArgs({ tokenId: tokenId, quantity: quantity_, imageURI: imageURI_ });
            uint256 mintFee = getArtMintFee(artId, quantity_);
            this.signatureClaim{ value: mintFee }(signature_, claimData, mintArgs);
        } else {
            revert InvalidVerificationType();
        }
    }
```

in the case where `art.verificationType.eq("SIGNATURE")`, this function in turns call [`PhiFactory::signatureClaim`](https://github.com/code-423n4/2024-08-phi/blob/main/src/PhiFactory.sol#L327-L346)

```javascript
    function signatureClaim(
        bytes calldata signature_,
        bytes calldata encodeData_,
        MintArgs calldata mintArgs_
    )
        external
        payable
        whenNotPaused
    {
        (uint256 expiresIn_, address minter_, address ref_, address verifier_, uint256 artId_,, bytes32 data_) =
            abi.decode(encodeData_, (uint256, address, address, address, uint256, uint256, bytes32));

        if (expiresIn_ <= block.timestamp) revert SignatureExpired();
        if (_recoverSigner(keccak256(encodeData_), signature_) != phiSignerAddress) revert AddressNotSigned();

        _validateAndUpdateClaimState(artId_, minter_, mintArgs_.quantity);
        _processClaim(artId_, minter_, ref_, verifier_, mintArgs_.quantity, data_, mintArgs_.imageURI, msg.value);

        emit ArtClaimedData(artId_, "SIGNATURE", minter_, ref_, verifier_, arts[artId_].artAddress, mintArgs_.quantity);
    }
```

we see in this function that no nonce is being used for signature verification, which means anyone can replay the transaction with the same signature.

the `claim` transaction was replayed by the attacker, in this specific case increasing his balance to `2` for the `tokenId=1`


## Tools Used

Manual Review / Foundry

## Recommended Mitigation Steps

Add a nonce to the signature to avoid replay attacks, like it is done in the `RewardControl` contract.


## Assessed type

Invalid Validation
