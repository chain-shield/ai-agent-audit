# Vulnerability details

## Impact
If the `curator_` parameter in the `buyShareCredFor` function is set to the contract's own address, it may lead to potential logical inconsistencies and operational risks in the contract. This situation can cause the contract itself to hold shares, which is not the intended behavior and may complicate the management of shares and funds within the contract. Although this does not result in direct economic gains or immediate security breaches, it introduces complexity and potential maintenance challenges for the project.

## Proof of Concept

https://github.com/code-423n4/2024-08-phi/blob/main/src/Cred.sol#L186

In the `buyShareCredFor` function, the `curator_` parameter is used to assign the ownership of shares. If this parameter is set to the contract's own address, the contract itself becomes the holder of the purchased shares. Here's the relevant code snippet:

```
function buyShareCredFor(uint256 credId_, uint256 amount_, address curator_, uint256 maxPrice_) public payable {
    if (curator_ == address(0)) revert InvalidAddressZero();
    _handleTrade(credId_, amount_, true, curator_, maxPrice_);
}
```

The `curator_` address is then passed to the `_handleTrade` function, which updates the share balance and manages the financial transactions. However, if `curator_` is the contract itself, the contract ends up holding shares, which can lead to logical inconsistencies in future operations.

## Recommended Mitigation Steps

Implement a check in the `buyShareCredFor` function to ensure that the `curator_` parameter cannot be set to the contract's own address. This can be done by adding a simple `require` statement to validate the input, ensuring that `curator_` is neither the zero address nor the contract address:

```
require(curator_ != address(this), "Curator cannot be the contract itself");
```
