# Vulnerability details

## Impact
Each time art is claimed and minted in `PhiFactory.sol`, the Phi team receives `mintProtocolFee`. Let's observe the fee calculation and transfer below  
```solidity
    function _processClaim(
        uint256 artId_,
        address minter_,
        address ref_,
        address verifier_,
        uint256 quantity_,
        bytes32 data_,
        string memory imageURI_,
        uint256 etherValue_
    )
        private
    {
        PhiArt storage art = arts[artId_];

        *** SOME CODE ***
       
        }
        protocolFeeDestination.safeTransferETH(mintProtocolFee * quantity_); // protocol fee calculated and sent here
    
```
We see that the protocolFee is calculated by multiplying the number of art NFTs being claimed and the `PhiFactory.sol` state variable `mintProtocolFee` and then sent to `protocolFeeDestination`. However this is wrong since `mintProtocolFee` is a variable denominated in basis points (at most 10_000) according to its' setter function and natspec.  

```solidity
    /// @notice Sets the protocol fee percentage.
    /// @param protocolFee_ The new protocol fee percentage (in basis points).
    function setProtocolFee(uint256 protocolFee_) external onlyOwner {
        if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
        mintProtocolFee = protocolFee_;
        emit ProtocolFeeSet(protocolFee_);
    }
```
The function multiplies basis points and quantity with expected output being ETH which severely undermines rewards to negligible values. Assuming max value for mintProtocolFee being set to 10_000 would result in 10_000 wei per NFT minted or 0.00000000000001 ETH protocol reward per NFT mint. Users will pay miniscule amounts to claim art on the back of the Phi team.
