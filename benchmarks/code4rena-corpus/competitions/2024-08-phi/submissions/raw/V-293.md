# Vulnerability details

## Summary

The PhiFactory contract utilizes Solady’s LibClone library, which is not compatible with the ZKsync chain due to the way contract deployment is handled on this network. Specifically, the create and create2 opcodes will not function correctly if the compiler is not provided with the deployed contract’s bytecode in advance.

## Vulnerability details
According to ZKsync documentation:
```
"On ZKsync Era, contract deployment is performed using the hash of the bytecode, and the factoryDeps field of EIP712 transactions contains the bytecode. The actual deployment occurs by providing the contract's hash to the ContractDeployer system contract. 
To guarantee that create/create2 functions operate correctly, the compiler must be aware of the bytecode of the deployed contract in advance. The compiler interprets the calldata arguments as incomplete input for ContractDeployer, as the remaining part is filled in by the compiler internally. The Yul datasize and dataoffset instructions have been adjusted to return the constant size and bytecode hash rather than the bytecode itself."
```
In the `PhiFactory::_createNewNFTContract` function, the cloneDeterministic method is called:
```
address payable newArt = payable(
    erc1155ArtAddress.cloneDeterministic(
        keccak256(abi.encodePacked(block.chainid, newArtId, credId))
    )
);
```
This method, as defined in LibClone, includes the following code:
```
    function cloneDeterministic(uint256 value, address implementation, bytes32 salt)
        internal
        returns (address instance)
    {
        /// @solidity memory-safe-assembly
        assembly {
            mstore(0x21, 0x5af43d3d93803e602a57fd5bf3)
            mstore(0x14, implementation)
            mstore(0x00, 0x602c3d8160093d39f33d3d3d3d363d3d37363d73)
@>            instance := create2(value, 0x0c, 0x35, salt)
            if iszero(instance) {
                mstore(0x00, 0x30116425) // `DeploymentFailed()`.
                revert(0x1c, 0x04)
            }
            mstore(0x21, 0) // Restore the overwritten part of the free memory pointer.
        }
    }
```

Since Phi Protocol plans to deploy on various chains, including Base, Optimism, BeraChain, and other EVM-compatible chains, it is at risk of malfunction if deployed on ZKsync. The create2 opcode will not work as expected, leading to the potential failure of new NFT contract deployments.

Note: this issue is inspired by <https://codehawks.cyfrin.io/c/2024-07-biconomy/s/40/> and https://github.com/sherlock-audit/2024-04-titles-judging/issues/91

## Impact
Deployments of the PhiFactory contracts will fail or result in faulty contracts on the ZKsync chain, rendering the protocol unusable on this network.

## Recommended Mitigation Steps
To ensure compatibility with the ZKsync chain, modify the deployment logic so that the compiler is aware of the bytecode beforehand. For example:
Example from zksync docs:
```
bytes memory bytecode = type(MyContract).creationCode;
assembly {
    addr := create2(0, add(bytecode, 32), mload(bytecode), salt)
}
```
This will allow the create2 function to operate correctly on the ZKsync chain by providing the required bytecode to the compiler in advance.
