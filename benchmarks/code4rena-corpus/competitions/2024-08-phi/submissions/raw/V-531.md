# Vulnerability details

 The `setProtocolFee` function in the contract incorrectly interprets basis points (bps) as a direct transfer amount when setting the mint fee. Basis points are a financial unit where 1% equals 100 bps. The current implementation allows setting `mintProtocolFee` up to a maximum of 10,000 bps, which is intended to represent 100%, but it mistakenly applies this value as a direct amount in wei during transactions, leading to incorrect fee calculations.

According to the documentation, the mint fee is supposed to be `0.00005 ETH`, equivalent to `50,000,000,000,000 wei`. However, the setter function currently only allows a maximum of `10,000 wei`, which is an incorrect calculation. The fee should be calculated as a percentage of some base value using basis points, but the current logic incorrectly uses the basis points as a direct transferable value.

## Impact
This issue results in incorrect fee calculations during the minting process. The fee may be significantly lower than intended, which could lead to financial discrepancies, under-collection of fees, and potential losses for the protocol. Additionally, this incorrect calculation could prevent the proper application of fees, affecting the overall functionality and financial integrity of the system.

## Proof of Concept
```
    /// @notice Sets the protocol fee percentage.
    /// @param protocolFee_ The new protocol fee percentage (in basis points).
    function setProtocolFee(uint256 protocolFee_) external onlyOwner 
        if (protocolFee_ > 10_000) revert ProtocolFeeTooHigh();
        mintProtocolFee = protocolFee_;
        emit ProtocolFeeSet(protocolFee_);
    }
```

## Recommended Mitigation Steps

To correct this issue, ensure that the `mintProtocolFee` is calculated and applied as a percentage of a specified value using basis points, rather than as a direct amount in wei. The fee calculation logic should be updated to reflect this change, ensuring accurate and consistent fee application across all relevant transactions. Implement proper validation and scaling mechanisms to handle basis points correctly during both initialization and updates.
