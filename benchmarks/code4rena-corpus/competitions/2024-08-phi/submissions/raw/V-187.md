# Vulnerability details

The `Cred::createCred()` function is vulnerable to replay attacks due to insufficient validation. As shown in the `@>` mark below, the function checks the signer's address and the expiration time of the signature, but does not contain any mechanism to prevent the same signature from being replayed. This means that a malicious user can reuse a valid signature to create multiple Creds without restriction.

## Impact
Malicious users can reuse valid signatures to repeatedly create multiple Creds, which can lead to serious problems such as unauthorized minting of assets, devaluation of artworks, or economic losses of the platform.

## Recommended Mitigation Steps
To mitigate this vulnerability, it's recommended to introduce `nonce` validation within the `signedData_` or use another mechanism that ensures the uniqueness of each signature. A `nonce` could be a timestamp, an incremental counter, or a similar unique value that is included in the signed data and validated during each transaction. This would ensure that a signature can only be used once, preventing replay attacks.
