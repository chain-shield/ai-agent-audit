# Vulnerability details

The functions `_removeCredIdPerAddress()` and `_addCredIdPerAddress()` are publicly accessible, allowing users to modify the `_credIdsPerAddress` list with arbitrary `credId_` and `sender_` values. This vulnerability enables attackers to:
1. **Empty a User’s _credIdsPerAddress List:** Attackers can remove all `credId_` entries associated with any user’s address, preventing the user from selling their Cred shares.
2. **Add Invalid or Duplicate IDs:** Users can populate the `_credIdsPerAddress` list with duplicate or nonexistent IDs by calling `_addCredIdPerAddress()`.

## Impact

The ability to manipulate the `_credIdsPerAddress` list can lead to users being unable to sell their shares, potentially resulting in a loss of funds.

Manual Review

## Recommended Mitigation Steps

To prevent unauthorized modifications, change the visibility of `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions from public to internal:

```diff
-    function _addCredIdPerAddress(uint256 credId_, address sender_) public {
+    function _addCredIdPerAddress(uint256 credId_, address sender_) internal {
        // Add the new credId to the array
        _credIdsPerAddress[sender_].push(credId_);
        // Store the index of the new credId
        _credIdsPerAddressCredIdIndex[sender_][credId_] = _credIdsPerAddressArrLength[sender_];
        // Increment the array length counter
        _credIdsPerAddressArrLength[sender_]++;
    }
```
