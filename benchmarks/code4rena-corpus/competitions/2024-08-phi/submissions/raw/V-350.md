# Vulnerability details

## Impact
Severity: High

Likelihood: High

Summary: A malicious user can exploit the underflow vulnerability in the `createArtFromFactory()` function to steal funds from the protocol. The exploit is highly probable since it can be carried out at any time by an attacker.

## Vulnerability details


The `createArtFromFactory()` function in the `PhiNFT1155.sol` contract lacks proper checks to prevent an underflow when calculating the difference between `msg.value` and `artFee`. Specifically, if `msg.value` is less than `artFee`, the subtraction will underflow which will bypassing the check, resulting in an unintended large amount being transferred to the `msg.sender`.

This occurs in the following section of the code:

Link: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L151

## Proof of Concept
An attacker can exploit this vulnerability by calling the createArtFromFactory() function with a msg.value less than artFee. This will cause the subtraction to underflow, and a large amount of ETH (due to the underflow wrapping around) will be transferred to the attacker’s address.

Manual Review, VsCode

## Recommended Mitigation Steps
To prevent this underflow, the condition should be modified to check if `msg.value` is greater than `artFee` before performing the subtraction and transfer. The updated code would look like this:

```solidity
function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
        _artIdToTokenId[artId_] = tokenIdCounter; 
        _tokenIdToArtId[tokenIdCounter] = artId_;

        uint256 artFee = phiFactoryContract.artCreateFee();

        console.log("artFee:", artFee);

        protocolFeeDestination.safeTransferETH(artFee); 
        emit ArtCreated(artId_, tokenIdCounter); 
        uint256 createdTokenId = tokenIdCounter;

        unchecked { 
            tokenIdCounter += 1; 
        } 
       
        -    if ((msg.value - artFee) > 0) {
        +    if (msg.value > artFee) { 
            _msgSender().safeTransferETH(msg.value - artFee);
        }

        return createdTokenId; 
    } 

```

By implementing this change, the underflow issue will be resolved, ensuring that only the correct amount of ETH is transferred back to the sender.
