# Vulnerability details

## Impact
The `createArt` function in the `PhiFactory` contract reverts whenever it is called with excess ETH. This issue arises because the `createArt` function calls `createArtFromFactory` in the `PhiNFT1155` contract. The `createArtFromFactory` function contains logic that attempts to refund any excess ETH to the `msg.sender`. However, since `msg.sender` in this context is `PhiFactory`, and `PhiFactory` lacks a receive or payable fallback function, the transaction reverts. Consequently, the function does not work as intended, preventing users from creating art if they send excess ETH.

```js
    function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
        _artIdToTokenId[artId_] = tokenIdCounter;
        _tokenIdToArtId[tokenIdCounter] = artId_;

        uint256 artFee = phiFactoryContract.artCreateFee();

        protocolFeeDestination.safeTransferETH(artFee);
        emit ArtCreated(artId_, tokenIdCounter);
        uint256 createdTokenId = tokenIdCounter;

        unchecked {
            tokenIdCounter += 1;
        }
        if ((msg.value - artFee) > 0) {
            _msgSender().safeTransferETH(msg.value - artFee); // @audit , this will revert all the time
        }

        return createdTokenId;
    }
```

## Proof of Concept
This POC demonstrates the issue by running a test case that verifies the reversion when excess ETH is sent during the `createArt` call.
1. Add the following test to the `TestPhiFactory` contract in `test/PhiFactory.t.sol`.
2. Run the test using `forge test --mt test_ExcessEth`.

```js
    function test_ExcessEth() public {
        bytes memory credData = abi.encode(1, owner, "SIGNATURE", 31_337, bytes32(0));
        bytes memory signCreateData = abi.encode(expiresIn, "abc", credData);
        bytes32 createMsgHash = keccak256(signCreateData);
        bytes32 createDigest = ECDSA.toEthSignedMessageHash(createMsgHash);
        (uint8 cv, bytes32 cr, bytes32 cs) = vm.sign(claimSignerPrivateKey, createDigest);
        if (cv != 27) cs = cs | bytes32(uint256(1) << 255);

        IPhiFactory.CreateConfig memory config =
                            IPhiFactory.CreateConfig(artCreator, receiver, END_TIME, START_TIME, MAX_SUPPLY, MINT_FEE, false);

        vm.prank(artCreator);
        vm.expectRevert(IPhiFactory.CreateFailed.selector);
        // it will revert because PhiFactory doesnt have receive or payable fallback function
        phiFactory.createArt{value: NFT_ART_CREATE_FEE + 1}(signCreateData, abi.encodePacked(cr, cs), config);
    }
```

## Recommended Mitigation Steps
To resolve this issue, it is recommended to modify the `_createNewNFTContract` and `_useExistingNFTContract` function in the `PhiFactory` contract to handle excess ETH:

1. **Send only the required amount**: Pass only the necessary ETH amount to the `createArtFromFactory` function.
2. **Refund any excess ETH**: If the caller sends more ETH than required, refund the excess ETH to the caller.
