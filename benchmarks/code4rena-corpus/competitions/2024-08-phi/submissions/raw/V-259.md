# Vulnerability details

## Impact
Without `credData` validation, mismatched data can lead to inconsistencies in the system, where the art's attributes do not accurately reflect accurate credentials.

## Proof of Concept
1.  **Credential Creation**

When a credential is created in [`createCred()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L273-L275), the [`_createCredInternal()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L561-L568) function is invoked. This function sets various attributes for a credential, such as:

These attributes are stored in a mapping, typically indexed by a unique `credId` as shown above.

2. **Encoding Data for Art Creation**

When a user wants to create art using a credential, they must provide `signedData_`. This data includes:
- credData: Encoded information about the credential, such as `credId`, `credCreator`, `verificationType`, `credChainId`, and possibly a `merkleRootHash`.
The user encodes this `data`, which is then signed by a trusted `signer`.

3. **Art Creation Process**

During art creation, the [`createArt()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L207-L210) function is called. This function:
- Decodes Data: Once the `signature` is validated, the function decodes the `signedData_` to extract the `credData` and other necessary information.
```solidity
    _validateArtCreationSignature(signedData_, signature_);
>>  (, string memory uri_, bytes memory credData) = abi.decode(signedData_, (uint256, string, bytes));
    ERC1155Data memory erc1155Data = _createERC1155Data(artIdCounter, createConfig_, uri_, credData);
>>  address artAddress = createERC1155Internal(artIdCounter, erc1155Data);
```
- Initializes Art: The [`createERC1155Internal()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L555) then calls  [`_initializePhiArt()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L595-L618) function with the decoded data to set up a new `PhiArt` object. This function assigns various attributes to the `PhiArt`, such as:
```solidity
    function _initializePhiArt(PhiArt storage art, ERC1155Data memory createData_) private {
        (
            uint256 credId,
            address credCreator,

        art.credCreator = credCreator;
        art.credChainId = credChainId;
        art.verificationType = verificationType;

        art.artist = createData_.artist;
        art.receiver = createData_.receiver;
        art.maxSupply = createData_.maxSupply;

        art.startTime = createData_.startTime;
        art.endTime = createData_.endTime;
        art.soulBounded = createData_.soulBounded;

        credMerkleRoot[credChainId][credId] = merkleRootHash;
    }
```

4. **Lack of Verification**

In the current implementation, the `_initializePhiArt()` function does not perform explicit verification to ensure that the decoded `credData` aligns with the expected values for the `credId`. This oversight can lead to several potential issues:

It is true that [`updateArtSettings()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L246-L252) allows for changes after the initial configuration. However, it does not offer means to change all `creadentials` but just a few.
```solidity

        uint256 mintFee_,

        uint256 endTime_,

        IPhiNFT1155Ownable.RoyaltyConfiguration memory configuration

        external
        onlyArtCreator(artId_)
    {
       ---SNIP---

        art.receiver = receiver_;
        art.maxSupply = maxSupply_;
        art.mintFee = mintFee_;
        art.startTime = startTime_;
        art.endTime = endTime_;
        art.soulBounded = soulBounded_;
        art.uri = url_;

        ---SNIP---
    }
```
As such, if incrorrect credentials were used during art initialization such as `merkleRootHash`, the impact would be dire. 
This is because, for [`merkleClaim()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L369-L375), the `merkleRootHash` will be validated before any claims are processed.
```solidity
        if (
            !MerkleProofLib.verifyCalldata(
                proof_, credMerkleRootHash, keccak256(bytes.concat(keccak256(abi.encode(minter_, leafPart_))))
            )
        ) {
            revert InvalidMerkleProof();
        }
``` 
However, if an incorrect `merkleRootHash` was set, all these claims will be reverted permanently.
