# Vulnerability details

## Impact
The depositBatch function is designed to facilitate the deposit of ETH for multiple recipients in a single transaction. The function allows for an optional comment and includes an array of reasons represented as bytes4 hashes for indexing purposes. However, a critical issue arises in how the function currently handles the reasons parameter, leading to a potential Denial of Service (DoS) vulnerability


## Proof of Concept
The function checks that the length of recipients, amounts, and reasons are all equal:

if (numRecipients != amounts.length || numRecipients != reasons.length) {
    revert ArrayLengthMismatch();
}

If the lengths do not match, the transaction is reverted with an ArrayLengthMismatch error. However, the parameter reasons is described as optional, but the function's current implementation does not reflect this. Instead, it mandates that the reasons array must have the same length as recipients and amounts. If a user does not provide a reason for some or all recipients, this length mismatch triggers an ArrayLengthMismatch revert, preventing the transaction from succeeding.

This mismatch requirement creates a Denial of Service (DoS) vulnerability, where the function fails to execute if users do not provide reasons for every recipient. 

## Tools Used
Manual analysis

## Recommended Mitigation Steps
Modify the condition that checks for array length mismatches to accommodate cases where reasons is empty or not complete.
