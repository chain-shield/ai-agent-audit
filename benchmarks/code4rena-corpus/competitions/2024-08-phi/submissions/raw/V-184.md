# Vulnerability details

## Impact
The lack of validation for the `merkleRootHash` during `art creation` can result in `failed claims` when users attempt to claim art using the `Merkle proof` mechanism. If the `Merkle root` is not set correctly (i.e., it remains `bytes32(0)`), any attempt to claim the art will revert, potentially blocking legitimate claims.

## Proof of Concept
In the `createArt()` process, the [`_initializePhiArt()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L601-L617) function retrieves the `merkleRootHash` from `createData_.credData` and assigns it to `credMerkleRoot[credChainId][credId]` without checking if it is `bytes32(0)`. 
```solidity
        (
            ---SNIP---
>>          bytes32 merkleRootHash
        ) = abi.decode(createData_.credData, (uint256, address, string, uint256, bytes32));
        ---SNIP---
>>      credMerkleRoot[credChainId][credId] = merkleRootHash;
```
This oversight can lead to issues later when claims are made using the `merkleClaim()` function. 

Specifically, [`merkleClaim()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L365-L368) will revert if it encounters a `credMerkleRootHash` that is `bytes32(0)`, indicating that the `Merkle root` was not properly set during `art creation`.
```solidity
        bytes32 credMerkleRootHash = credMerkleRoot[art.credChainId][art.credId];
>>      if (minter_ == address(0) || !art.verificationType.eq("MERKLE") || credMerkleRootHash == bytes32(0)) {
            revert InvalidMerkleProof();
        }
```
As such, legitimate claims will be blocked.

Additionally, since the [`updateArtSettings()`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L215-L257) function does not provide a mechanism to update the `Merkle root` once it is set, there is no way to correct this oversight after the fact.

Manual Review

## Recommended Mitigation Steps
Implement a check in `_initializePhiArt()` to ensure that the `merkleRootHash` is not `bytes32(0)` before assigning it to `credMerkleRoot[credChainId][credId]`.
```diff
        (
            ---SNIP---
            bytes32 merkleRootHash
        ) = abi.decode(createData_.credData, (uint256, address, string, uint256, bytes32));
        ---SNIP---
+       // Validate merkleRootHash
+       require(merkleRootHash != bytes32(0), "Invalid Merkle root hash");
        credMerkleRoot[credChainId][credId] = merkleRootHash;
```
