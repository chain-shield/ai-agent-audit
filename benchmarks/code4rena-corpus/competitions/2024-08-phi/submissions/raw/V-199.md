# Vulnerability details

## Impact
**`createCred()`** allows users to create new Cred. However, the issue is that the signature lacks a nonce, which means a user can create as many Cred as they want as long as they are within the allowed time range using the same signature.

## Proof of Concept
**`createCred()`** is implemented as follows.

As you can see, the function only checks if **`expiresIn`** is within the valid time range, but it doesn't include a nonce to ensure the signature hasn't been reused. This allows the user to create multiple Cred within the specified time range using the same signature.

To illustrate the issue, copy the following POC into **`Cred.t.sol`**.
```Solidity
function test_createCreds() public {
        vm.warp(START_TIME + 1);

        _createCred("BASIC", "SIGNATURE", 0x0);
        cred.isShareHolder(1, participant);
        _createCred("BASIC", "SIGNATURE", 0x0);
        cred.isShareHolder(2, participant);
        _createCred("BASIC", "SIGNATURE", 0x0);
        cred.isShareHolder(3, participant);

        assertEq(cred.isShareHolder(1, participant), true);
        assertEq(cred.isShareHolder(2, participant), true);
        assertEq(cred.isShareHolder(3, participant), true);
    }
```
As you can see, the user is able to create as many Cred as they want.
