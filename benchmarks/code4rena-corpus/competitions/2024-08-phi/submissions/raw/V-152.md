# Vulnerability details

## Impact 
In the `sellShareCred` function in [Cred.sol:L182-L183](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L182-L184)
```solidity
function sellShareCred(uint256 credId_, uint256 amount_, uint256 minPrice_) public {
    _handleTrade(credId_, amount_, false, _msgSender(), minPrice_);
}
```
This function calls the internal `_handleTrade` function, which handles the trade logic for buying and selling share cred.

In the `_handleTrade` function (Cred.sol:588-659), the issue lies in the following lines.
```solidity
if (isBuy) {
    curator_.safeTransferETH(price - protocolFee - creatorFee);
}
```
When selling share cred, the curator is transferred the price minus the protocol fee and creator fee. However, this does not take into account the actual amount of Ether received by the contract during the sell operation.

The curator suffers a loss when selling share cred due to receiving an incorrect amount of Ether. The amount of loss depends on the specific transaction and the difference between the expected and actual amount of Ether received by the curator.

## Proof of Concept
A flaw in the `_handleTrade` function will cause the curator to receive an incorrect amount of Ether when selling share cred. The function fails to properly calculate and transfer the expected amount of Ether to the curator based on the actual amount received by the contract during the sell operation.

The `_handleTrade` function handles the trade logic for buying and selling share cred. When selling share cred, the function transfers the price minus the protocol fee and creator fee to the curator: https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L638-L648
```solidity
if (isBuy) {
    curator_.safeTransferETH(price - protocolFee - creatorFee);
}
```
However, this calculation does not consider the actual amount of Ether received by the contract during the sell operation. As a result, the curator may receive an incorrect amount of Ether.

* The `sellShareCred` function needs to be called with valid parameters to initiate the sell operation.
* The `_handleTrade` function needs to be executed with the `isBuy` parameter set to `false` to trigger the sell logic.

**Attack Scenario**

* The curator calls the `sellShareCred` function, specifying the `credId_`, `amount_`, and `minPrice_` parameters.
* The `sellShareCred` function calls the internal `_handleTrade` function with `isBuy` set to false.
* Inside the` _handleTrade` function, the price, protocol fee, and creator fee are calculated based on the provided parameters.
* The function transfers the price minus the protocol fee and creator fee to the curator using `curator_.safeTransferETH(price - protocolFee - creatorFee)`.
* The curator receives an incorrect amount of Ether, which may be less than the expected amount based on the actual amount received by the contract during the sell operation.

## Recommended Mitigation Steps
`_handleTrade` function should be modified to calculate and transfer the correct amount of Ether to the curator based on the actual amount received by the contract during the sell operation.
```diff
 if (isBuy) {
-    curator_.safeTransferETH(price - protocolFee - creatorFee);
+    uint256 initialContractBalance = address(this).balance;
+    uint256 finalContractBalance = initialContractBalance + msg.value;
+    uint256 actualAmountReceived = finalContractBalance - initialContractBalance;
+    curator_.safeTransferETH(actualAmountReceived - protocolFee - creatorFee);
 }
```
By calculating the actual amount received by the contract during the sell operation and subtracting the protocol fee and creator fee from it, the curator will receive the correct amount of Ether.
