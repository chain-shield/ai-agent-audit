# Vulnerability details

### Summary

The `updateArtSettings` function in the `PhiFactory` contract allows modifications to the `endTime` of an art piece. However, there's no mechanism to prevent setting the `endTime` to a past timestamp while there might be pending minting claims in the `PhiNFT1155Ownable` contract. This can lead to valid claims being rejected unexpectedly.

### Code Snippets

### `PhiFactory.updateArtSettings`:

```solidity
function updateArtSettings(
    // ... other parameters
    uint256 endTime_,
    // ...
) external onlyArtCreator(artId_) {
    // ... (Input validations - allows endTime_ to be in the past)

    PhiArt storage art = arts[artId_];

    // ...

    if (endTime_ < block.timestamp) { // This only prevents setting endTime in the past during creation, not updates
        revert EndTimeInPast();
    }

    art.endTime = endTime_; 

    // ...
}
```

### `PhiFactory._processClaim`:

```solidity
function _processClaim(
    // ... other parameters
) private {
    // ...

    PhiArt storage art = arts[artId_];

    // ...

    if (block.timestamp > art.endTime) revert ArtEnded(); // Fetches endTime from storage, which might have been updated

    // ...
}
```

### Impact

- **Valid Claims Rejected**: If the `endTime` is set to the past while there are pending claims in `PhiNFT1155Ownable`, those claims will fail when processed, even if they were initiated within the original minting window. This leads to a loss of user funds and a negative user experience.

### Scenario

1. An artist creates an art piece with `endTime` set to a future date.
2. A user initiates a minting claim within the valid timeframe.
3. Before the claim is processed, the artist updates the art settings, setting `endTime` to a past timestamp.
4. When the user's claim is finally processed, it fails due to the `ArtEnded` revert, even though the claim was valid at the time of initiation.

### Fix

The fix can involve storing relevant art settings (including `endTime`) at the time of claim initiation in the `PhiNFT1155Ownable` contract. Then when processing the claim, validate against these stored settings instead of fetching them again from `PhiFactory`.
