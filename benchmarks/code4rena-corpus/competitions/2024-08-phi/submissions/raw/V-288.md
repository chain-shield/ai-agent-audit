# Vulnerability details

## Impact
Function ```_addCredIdPerAddress()``` is expected to be called by ```_updateCuratorShareBalance()``` if it is necessary to update ``` _credIdsPerAddress[], _credIdsPerAddressCredIdIndex[] and _credIdsPerAddressArrLength[]``` mappings. However, the function's visibility is 'public' and has no access control, so everyone can call it and arbitrarily modify these state variables (e.g. adding a user who is totally unrelated to credId to the mapping, for example). This does not put users' assets into risk but will make the system show incorrect data.

## Tools Used
Manual review

## Recommended Mitigation Steps
Make the function internal so that only ```_updateCuratorShareBalance()``` can call it, updating those mappings only when required.

```solidity
-function _addCredIdPerAddress(uint256 credId_, address sender_) public {
+function _addCredIdPerAddress(uint256 credId_, address sender_) internal {
        // Add the new credId to the array
        _credIdsPerAddress[sender_].push(credId_);
        // Store the index of the new credId
        _credIdsPerAddressCredIdIndex[sender_][credId_] = _credIdsPerAddressArrLength[sender_];
        // Increment the array length counter
        _credIdsPerAddressArrLength[sender_]++;
    }
```
