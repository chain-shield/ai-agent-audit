# Vulnerability details

The protocol is exposing two pitfalls in the way that the `createCred` signature is being handle. Firstable the signature allow for replays attacks and second one the library used for do the verification is not handling ECDA malleability.

With that being said let go straight what an attacker can do with this; see this scenario:

1. A malicious creator get a valid signature to create a cred.
2. A malicious creator then use the signature and replay 1 millions times and get basically shares for free because each time that a creator create a cred the contract is minting one share for him:

## Impact
A malicious creator can exploit the protocol by creating a creed replaying the signature and mint any share that he want then dump this shares in the same protocol when other users already buy more of that share. Also see that malicious creator don't pay any fees by doing this.
