# Vulnerability details

The bug occurs in the [sellShareCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L182-L184) function in Cred.sol:
```solidity
function sellShareCred(uint256 credId_, uint256 amount_, uint256 minPrice_) public {
    _handleTrade(credId_, amount_, false, _msgSender(), minPrice_);
}
```
The `_handleTrade` function is called with `isBuy` set to `false` for a sell operation. However, upon further inspection of the `_handleTrade` function, there is no update to the `lastTradeTimestamp` for the trader when selling shares:
```solidity
function _handleTrade(
    uint256 credId_,
    uint256 amount_,
    bool isBuy,
    address curator_,
    uint256 priceLimit
)
    internal
    whenNotPaused
{
    // ...

    if (isBuy) {
        // ...
        lastTradeTimestamp[credId_][curator_] = block.timestamp;
    } else {
        // ...
        curator_.safeTransferETH(price - protocolFee - creatorFee);
    }

    // ...
}
```
The `lastTradeTimestamp` is only updated during a buy operation, but not during a sell operation.

## Impact
Traders may experience an approximate loss of their share balance during sell operations because the protocol fails to accurately update the `lastTradeTimestamp` for traders when they sell their shares.

## Proof of Concept
The [_handleTrade](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L588-L659) function is responsible for handling both buy and sell operations for shares. However, there is a missing update to the `lastTradeTimestamp` mapping for the trader when selling shares.
```solidity
function _handleTrade(
    uint256 credId_,

    bool isBuy,
    address curator_,

```
The `lastTradeTimestamp` is updated only during a buy operation, but not during a sell operation. This inconsistency leads to incorrect share balance updates for traders.

**Cause**
The root cause of the issue lies in the missing update to the `lastTradeTimestamp` mapping during sell operations in the `_handleTrade` function of the `Cred.sol` contract.

**Here's a scenario that demonstrates the attack path:**

1. A trader buys shares of a cred using the `buyShareCred` function.
2. The trader's `lastTradeTimestamp` is updated correctly during the buy operation.
3. Later, the trader decides to sell their shares using the `sellShareCred` function.
4. The `_handleTrade` function is called with `isBuy` set to false for the sell operation.
5. The trader's share balance is decreased, but their `lastTradeTimestamp` is not updated.
6. The incorrect `lastTradeTimestamp` leads to discrepancies in the share balance updates for the trader.

## Recommended Mitigation Steps
The `_handleTrade` function in the `Cred.sol `contract should ensure that the `lastTradeTimestamp` is correctly set during both buy and sell operations.
```diff
function _handleTrade(
    uint256 credId_,
    uint256 amount_,
    bool isBuy,
    address curator_,
    uint256 priceLimit
)
    internal
    whenNotPaused
{
    // ...

    if (isBuy) {
        // ...
        lastTradeTimestamp[credId_][curator_] = block.timestamp;
    } else {
        // ...
        curator_.safeTransferETH(price - protocolFee - creatorFee);
+       lastTradeTimestamp[credId_][curator_] = block.timestamp; // Update lastTradeTimestamp for sell operation
    }

    // ...
}
```
The proposed change adds the missing update to the `lastTradeTimestamp` mapping during sell operations. By setting the `lastTradeTimestamp` to the current `block.timestamp` for both buy and sell operations, the share balance updates will be accurate and consistent for traders.
