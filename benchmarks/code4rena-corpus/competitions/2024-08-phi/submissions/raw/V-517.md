# Vulnerability details

## Impact

### DOS
The function `_executeBatchTrade` makes external calls to `safeTransferETH` and `deposit` in a loop to handle funds. If `protocolFeeDestination` or `phiRewardsAddress` is a malicious contract, it may intentionally fail or consume a large amount of gas, resulting in the failure of the entire transaction and causing a denial of service (DOS). 

### Gas optimization
If `credIds` is very large, such calls will also lead to excessive gas costs.

## Recommenden Migation Steps

- Using a 'pull-over-push pattern', remove transfer and deposit ETH 
- Add function `withdrawProtocolFees` and `withdrawCreatorFees`

```
contract ImprovedContract {
    mapping(address => uint256) public pendingProtocolFees;
    mapping(address => uint256) public pendingCreatorFees;

    function _executeBatchTrade(
        // ... 
    ) internal whenNotPaused nonReentrant {
        // ... 

        for (uint256 i = 0; i < credIds_.length; ++i) {
            uint256 credId = credIds_[i];

            pendingProtocolFees[protocolFeeDestination] += protocolFees[i];
            pendingCreatorFees[creds[credId].creator] += creatorFees[i];
            
            // ...
        }
    }

    function withdrawProtocolFees() external {
        uint256 amount = pendingProtocolFees[msg.sender];
        pendingProtocolFees[msg.sender] = 0;
        payable(msg.sender).transfer(amount);
    }

    function withdrawCreatorFees() external {
        uint256 amount = pendingCreatorFees[msg.sender];
        pendingCreatorFees[msg.sender] = 0;
        IPhiRewards(phiRewardsAddress).deposit{ value: amount }(
            msg.sender, bytes4(keccak256("CREATOR_ROYALTY_FEE")), ""
        );
    }
}
```
