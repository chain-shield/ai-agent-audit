# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The `withdrawRoyalty` is the fee that it's paid to the users who trigger `distribute` function. 
```solidity
function distribute(uint256 credId) external {
...
     uint256 royaltyfee = (totalBalance * withdrawRoyalty) / RATIO_BASE;
...
     _msgSender().safeTransferETH(royaltyfee + distributeAmount - actualDistributeAmount);
...
}

When this value is updated all undistributed credentials will take into account the new `withdrawRoyalty` which is unfair for the users as they are aware of the fee that it's paid when they deposit.

## Recommended Mitigation Steps
Unfortunately as we do not know how many deposits we have for what credential id, the fix is not straightforward.
A possible fix can be to run an offchain keeper who calls this function for all the credential ids that exists before updating the `withdrawRoyalty`.
