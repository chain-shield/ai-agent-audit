# Vulnerability details

## Impact
If the user calls the 'claim' function of the PhiFactory contract and msg.value is greater than mintFee, the remaining ether minus mintFee will not be returned.

PhiFactory.sol
_processClaim function
```
    function _processClaim(
        uint256 artId_,
        address minter_,
        address ref_,
        address verifier_,
        uint256 quantity_,
        bytes32 data_,
        string memory imageURI_,
        uint256 etherValue_
    )
        private
    {
        PhiArt storage art = arts[artId_];

        // Handle refund
        uint256 mintFee = getArtMintFee(artId_, quantity_);
        if ((etherValue_ - mintFee) > 0) {
            _msgSender().safeTransferETH(etherValue_ - mintFee);
        }
        protocolFeeDestination.safeTransferETH(mintProtocolFee * quantity_);

        (bool success_,) = art.artAddress.call{ value: mintFee - mintProtocolFee * quantity_ }(
            abi.encodeWithSignature(
                "claimFromFactory(uint256,address,address,address,uint256,bytes32,string)",
                artId_,
                minter_,
                ref_,
                verifier_,
                quantity_,
                data_,
                imageURI_
            )
        );

        if (!success_) revert ClaimFailed();
    }
```

The '_processClaim' function finalizes the claim by calling the claimFromFactory function of the PhiNFT1155 contract.

Here, before calling the claimFromFactory function, we send the remaining etherValue, excluding mintFee, to msg.sender.

However, when calling merkleClaim or signatureClaim in the claim function, the sent ether is fixed to `mintFee`, and when each Claim function is called, `msg.value` becomes `mintFee`.
Because the `etherValue_` argument in the `_processClaim` function is set to msg.value (msg.value = mintfee) of merkleClaim or signatureClaim,
```
if ((etherValue_ - mintFee) > 0) {
_msgSender().safeTransferETH(etherValue_ - mintFee);
}
```
The conditional statement always becomes false, so the remaining msg.value cannot be returned.


Summary 
Flow of msg.value when calling the claim function

1. call claim function (msg.value = msg.value)
2. call merkleClaim or signatureClaim function (msg.value = mintFee)
3. `etherValue_` argument of `_processClaim` function is always `mintFee`
4. if condition in `_processClaim` function is always false because `etherValue_` and `mintFee` is alway same value
5. Also, even if the if condition is true, the `claim` function is called as `this.merkleClaim`, so `_msgSender()` becomes the `PhiFactory` contract address, not the `user` address, and is not returned to the user.


For the same reason as above, the `batchClaim` function also has the same problem.
In the `batchClaim` function, when calling the `claim` function, it is called in the `this.claim` manner, so the `msg.sender` of the `claim` function becomes `PhiFactory contract address` instead of `user`.

The other problems are the same as those of the basic `claim` function.

```
    function batchClaim(bytes[] calldata encodeDatas_, uint256[] calldata ethValue_) external payable {
        if (encodeDatas_.length != ethValue_.length) revert ArrayLengthMismatch();

            /// problem
            this.claim{ value: ethValue_[i] }(encodeDatas_[i]);
        }
    }
```
