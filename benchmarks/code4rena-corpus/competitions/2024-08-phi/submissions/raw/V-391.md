# Vulnerability details

## Impact
_removeCredIdPerAddress array removal error leads to the wrong credId being removed which leads to a loss of profits for users and disrupts the fucntionality of handleTrade which is used by functions that invovles buying and selling share.

When a user sells his shares of one credId due to this error he might end up stilll having the credId of the shares that he sold and losing credId of shares he did not sold.



## Proof of Concept
    // Function to remove a credId from the address's list
    function _removeCredIdPerAddress(uint256 credId_, address sender_) public {
        // Check if the array is empty
        if (_credIdsPerAddress[sender_].length == 0) revert EmptyArray();

        // Get the index of the credId to remove
        uint256 indexToRemove = _credIdsPerAddressCredIdIndex[sender_][credId_];
        // Check if the index is valid
        if (indexToRemove >= _credIdsPerAddress[sender_].length) revert IndexOutofBounds();

        // Verify that the credId at the index matches the one we want to remove
        uint256 credIdToRemove = _credIdsPerAddress[sender_][indexToRemove];
        if (credId_ != credIdToRemove) revert WrongCredId();

        // Get the last element in the array
        uint256 lastIndex = _credIdsPerAddress[sender_].length - 1;
        uint256 lastCredId = _credIdsPerAddress[sender_][lastIndex];
        // Move the last element to the position of the element we're removing
        _credIdsPerAddress[sender_][indexToRemove] = lastCredId;

        // Update the index of the moved element, if it's not the one we're removing
        if (indexToRemove < lastIndex) {
            _credIdsPerAddressCredIdIndex[sender_][lastCredId] = indexToRemove;
        }

        // Remove the last element (which is now a duplicate)
        _credIdsPerAddress[sender_].pop();

        // Remove the index mapping for the removed credId
        delete _credIdsPerAddressCredIdIndex[sender_][credIdToRemove];

        // Decrement the array length counter, if it's greater than 0
        if (_credIdsPerAddressArrLength[sender_] > 0) {
            _credIdsPerAddressArrLength[sender_]--;
        }
    }

I think the issue is in the below code:
        _credIdsPerAddress[sender_][indexToRemove] = lastCredId;
It should be lastIndex instead of lastCredId.



Example:

Assume we have a user with the address 0x123...abc.
The user has the following credIds associated with their address:

_credIdsPerAddress[0x123...abc] = [13, 53, 69, 7, 10]


The index mapping is as follows:

_credIdsPerAddressCredIdIndex[0x123...abc][13] = 0
_credIdsPerAddressCredIdIndex[0x123...abc][53] = 1
_credIdsPerAddressCredIdIndex[0x123...abc][69] = 2
_credIdsPerAddressCredIdIndex[0x123...abc][7] = 3
_credIdsPerAddressCredIdIndex[0x123...abc][10] = 4

The length counter:
_credIdsPerAddressArrLength[0x123...abc] = 5


Now, the user wants to remove credId = 69:


Check if the Array is Empty:

        if (_credIdsPerAddress[sender_].length == 0) revert EmptyArray();
https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L697

- The array is not empty (length = 5), so it proceeds.

Get the Index of the credId to Remove:

        uint256 indexToRemove = _credIdsPerAddressCredIdIndex[sender_][credId_];

https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L700
- indexToRemove = _credIdsPerAddressCredIdIndex[0x123...abc][69] results in indexToRemove = 2.

Check if the Index is Valid:

        if (indexToRemove >= _credIdsPerAddress[sender_].length) revert IndexOutofBounds();

- The index 2 is valid since the length is 5.

Verify the credId at the Index:

        uint256 credIdToRemove = _credIdsPerAddress[sender_][indexToRemove];
        if (credId_ != credIdToRemove) revert WrongCredId();

https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L705

- credIdToRemove = _credIdsPerAddress[0x123...abc][2] results in credIdToRemove = 69, which matches credId_.

Get the Last Element in the Array:

        uint256 lastIndex = _credIdsPerAddress[sender_].length - 1;
        uint256 lastCredId = _credIdsPerAddress[sender_][lastIndex];

https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L709

- lastIndex = 4 and lastCredId = _credIdsPerAddress[0x123...abc][4] results in lastCredId = 10.

This is where we are supposed to move the credId that we want to remove to the last Index which is the position to remove but instead we move it to the number of lastCredId which does not even exist in this case and would lead to an array oob. 


Another issue that might happen is if the lastCredId is a number within the array, for example 1, _credIdsPerAddress[sender_][indexToRemove] would thus replace the credId in index position 1 and leading to 2 wrong credIds being deleted 

        // Move the last element to the position of the element we're removing
        _credIdsPerAddress[sender_][indexToRemove] = lastCredId;
