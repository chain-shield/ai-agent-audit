# Vulnerability details

Arrays in solidity(and in any blockchain) can not grow indefinitely because if a contract iterate that array the execution can run out of gas because the block gas limit size now 30 million gas. (basically there is a gas that can be execute in a block). 

In the Phi protocol there is a instance where an array can grow indefinitely, this could be intentional or not intentional.

See the `distribute`  function in the `CuratorRewardsDistributor.sol`:

```solidity

    function distribute(uint256 credId) external {
        if (!credContract.isExist(credId)) revert InvalidCredId();
        uint256 totalBalance = balanceOf[credId];
        if (totalBalance == 0) {
            revert NoBalanceToDistribute();
        }

        address[] memory distributeAddresses = credContract.getCuratorAddresses(credId, 0, 0); <-------

       ...
    
        for (uint256 i = 0; i < distributeAddresses.length; i++) { <------
            address user = distributeAddresses[i];

            uint256 userAmounts = credContract.getShareNumber(credId, user);
            uint256 userRewards = (distributeAmount * userAmounts) / totalNum;

            if (userRewards > 0) {
                amounts[i] = userRewards;
                actualDistributeAmount += userRewards;
            }
        }


```
[[Link]](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/reward/CuratorRewardsDistributor.sol#L84)

The `distributeAddresses` array can grow indefinitely therefore the execution can run out of gas and DoS the `distribute` function.

with that being say an attacker can create thousan of wallets buy just one wei of share with each wallet and DoS the distributions.

## Impact
The `distributeAddresses` array can grow indefinitely therefore the execution can run out of gas and DoS the `distribute` function which is distributing the fees among curators.

Note that this is mention in the code4arena phi audit page:

`Is it possible to intentionally target a halt when using loops?`

The `getCuratorAddresses` function is getting the whole array because the 0,0:

```solidity

 function getCuratorAddresses(
        uint256 credId_,
        uint256 start_,
        uint256 stop_
    )
        public
        view
        returns (address[] memory)
    {
        CuratorData[] memory curatorData = _getCuratorData(credId_, start_, stop_);
        address[] memory result = new address[](curatorData.length);

        for (uint256 i = 0; i < curatorData.length; i++) {
            result[i] = curatorData[i].curator;
        }

        return result;
    }


```

## Recommended Mitigation Steps
Two recommendations the first one make a minimum of shares that can be buy, This could prevent that this problem could happen by an attacker but the arrays can grow anyway exponentially if the cred become so popular.

To prevent this consider limit the array or do the distributions in two tx separately since the `getCuratorAddresses` allow that.
