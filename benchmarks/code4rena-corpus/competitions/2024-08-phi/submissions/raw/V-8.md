# Vulnerability details

## Impact
Anyone can trigger a withdrawal Eth from `PhiRewards` contract by calling `withdrawFor()` function and there by initiating the withdrawal of Eth from the `PhiRewards` contract without user's approval.

## Proof of Concept
`PhiRewards` contract is derived from `RewardControl` contract which  manages the rewards at each account level.

```solidity
  mapping(address account => uint256 balance) public balanceOf;
```

The `RewardControl` contract has `withdrawFor(...)` external function which allows anyone to call this function. Hence, anyone can initiate withdrawal for any account without the account owner's permission.

```solidity
    function withdrawFor(address from, uint256 amount) external {
 ==>       _withdraw(from, from, amount);
    }

    function _withdraw(address from, address to, uint256 amount) internal {
        if (to == address(0)) revert InvalidAddressZero();

        uint256 balance = balanceOf[from];
        if (amount == FULL_BALANCE) {
            amount = balance;
        }

        if (amount > balance) revert InvalidAmount();

        unchecked {
            balanceOf[from] = balance - amount;
        }

        emit Withdraw(from, to, amount);

        to.safeTransferETH(amount);
    }
```

Lets say, Alice has deposited 2 Ether into the `PhiRewards` contract. But, Eve can without any approval from Alice initiate a withdrawal for Alice by calling 
`withdrawFor(...)` function passing Alice account as `from` Address.

The funds will return back to Alice's account, but did not want or intend to make this withdrawal. Any one can initiate such transaction with out approvals. 

An attacker can potentially front run a signed withdraw transaction and send the funds back to the account owner.

Example, lets say, Alice signs a withdraw transaction to send the funds to Bob. She does so by calling `withdrawWithSig(...)` directing the funds to Bob as the recipient. But, Attacker can call `withdrawFor(...)` and send the funds back to Alice. 

Due to this front running, the signed transaction by Alice will revert due to lack of funds in the PhiRewards` contract.

## Tools Used
Manual review

## Recommended Mitigation Steps
The `withdrawFor()` should be callable only by the account holder or anyone who was approved to do so.
