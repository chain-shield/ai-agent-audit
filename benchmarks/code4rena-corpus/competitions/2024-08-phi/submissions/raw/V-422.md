# Vulnerability details

## Impact
When a user creates a new art through the factory, any excess `msg.value` sent is to be refunded but it is refunded incorrectly to the factory instead of to the user.

## Proof of Concept
Once a new art is created through the factory, a [call is made](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L640-L641) to the newly deployed `PhiNFT1155.sol` clone with an eth value.

```solidity
    (bool success_, bytes memory response) =
        newArt.call{ value: msg.value }(abi.encodeWithSignature("createArtFromFactory(uint256)", newArtId));
```

And if we look further we will see that [any excess is refunded](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/art/PhiNFT1155.sol#L151-L153).

```solidity
    if ((msg.value - artFee) > 0) {
        _msgSender().safeTransferETH(msg.value - artFee);
    }
```

But `msg.sender` in this case will be the address of the factory (enforced by `onlyPhiFactory` modifier) which made the call to the clone, and not the user creating the art. Excess is refunded incorrectly and there is no way for the user to retrieve it.  

## Tools Used
Manual review
## Recommended Mitigation Steps
Add an additional `address sender` parameter to `createArtFromFactory()` and refund to that address.
