# Vulnerability details

# When msg.value to be set greater than artFee and call createArt function, it always reverts.
## Impact
The createArt function is a function that is called when registering a specific art.
When calling this function, you must pay the artFee to register the art.

When msg.value is set to a value greater than artFee, it is always reverted, so art cannot be created for this condition.

When the createArt function is called, the _createNewNFTContract function is called, which calls the createArtFromFactory function of the PhiNTF1155.sol contract with msg.value to create art.

https://github.com/code-423n4/2024-08-phi/blob/main/src/art/PhiNFT1155.sol#L138-L156
PhiNFT1155.sol
```
    function createArtFromFactory(uint256 artId_) external payable onlyPhiFactory whenNotPaused returns (uint256) {
        _artIdToTokenId[artId_] = tokenIdCounter;
        _tokenIdToArtId[tokenIdCounter] = artId_;

        uint256 artFee = phiFactoryContract.artCreateFee();

        protocolFeeDestination.safeTransferETH(artFee);
        emit ArtCreated(artId_, tokenIdCounter);
        uint256 createdTokenId = tokenIdCounter;

        unchecked {
            tokenIdCounter += 1;
        }
        if ((msg.value - artFee) > 0) {
            _msgSender().safeTransferETH(msg.value - artFee);
        }

        return createdTokenId;
    }
```

In this function, there is an if statement that creates and registers art and sends the remaining msg.value to msg.sender.

At this time, msg.sender is the address of the PhiFactory contract, not the user.

Since the PhiFactory contract does not have a receive function or a fallback function, the result of the _msgSender().safeTransferETH(msg.value - artFee) code always becomes revert . Even if there is a receive function or a fallback function, the msg.value that should be returned does not go to the user but to the PhiFactory contract, which is also a problem.
