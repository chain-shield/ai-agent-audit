# Vulnerability details

## Impact
[_updateRoyalties ](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/CreatorRoyaltiesControl.sol#L58-L66) allows the artist to set the royalties configuration. This is the fee share of that NFT is BPS with a `ROYALTY_BPS_TO_PERCENT` of 10_000 [see](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/CreatorRoyaltiesControl.sol#L11). The function can be called by the artist by calling [updateArtSettings](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L215) on PhiFactory.sol, this calls [updateRoyalties](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L255). This function in the factory also does not do any checks for a max BPS. With that the artist can increase the fee to a multiple of the NFT price and i.e. by frontrunning a user tx maliciously earn a huge fee (depending on the users approvals). 

## Proof of Concept

The POC is a modification of the existing test [PhiFactory.t.sol](https://github.com/code-423n4/2024-08-phi/blob/main/test/PhiFactory.t.sol). By applying that diff below, the artist updates the fee to 5000%. The function should revert if the fee is higher as the max `ROYALTY_BPS_TO_PERCENT`.
