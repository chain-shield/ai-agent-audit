# Vulnerability details

## Impact

The signatureClaim function decodes the `expiresIn_` parameter from calldata but fails to verify if the current block timestamp surpasses this expiration time. Consequently, expired claims may still be processed, enabling unauthorized token minting. This flaw poses significant economic and security risks, as it could be exploited by malicious actors to mint tokens beyond the designated claim period.

## Recommended Mitigation Steps

To address the issue of processing expired claims in the `signatureClaim` function, you should implement a check to ensure that the current block timestamp does not exceed the `expiresIn_` parameter. Here's a recommendation to resolve this:  

Before proceeding with the claim, compare the current block timestamp with the `expiresIn_` parameter. If the current timestamp is greater than `expiresIn_`, revert the transaction to prevent unauthorized minting. Insert the following check at the beginning of the `signatureClaim` function:  

```
require(block.timestamp <= expiresIn_, "Claim has expired");
```  

By implementing this check, you ensure that only valid claims within the designated period are processed, mitigating the risk of unauthorized minting.
