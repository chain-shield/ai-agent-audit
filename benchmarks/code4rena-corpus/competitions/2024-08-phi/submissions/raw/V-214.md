# Vulnerability details

## Impact
The attacker gains the ability to create creds without a valid signature from the designated signer. Invalid `credType` value being passed in the `signedData_` parameter. Even though the signature is valid, the `createCred` function reverts due to the `InvalidCredType` error.

## Proof of Concept
A missing validation on the `credType` parameter will cause the signature verification to be bypassed for the `createCred` function as an attacker will provide an invalid `credType` value in the `signedData`.

There is a check on the `credType` parameter: [Cred.sol#L260-L262](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L260-L262)
```solidity
if (!credType.eq("BASIC") && !credType.eq("ADVANCED")) {
    revert InvalidCredType();
}
```
However, this check is performed after the signature verification: [Cred.sol#L243](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L243)
```solidity
if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
```
The choice to perform the `credType` validation after the signature verification is a mistake as it allows an attacker to bypass the signature verification by providing an invalid `credType` value.

When an attacker provides a `signedData` with an invalid `credTyp`e value other than "BASIC" or "ADVANCED".

**Attack Scenario**

* Attacker calls` createCred` with a `signedData` containing an invalid `credType` value.

* The signature verification passes since the `signedData` is signed by the attacker.

* The `credType` validation fails and reverts the transaction with `InvalidCredType` error.

* The attacker successfully bypasses the signature verification and creates a cred without a valid signature from the designated signer.

## Recommended Mitigation Steps
The `credType` validation should be performed before the signature verification.
```diff
- if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
  (
      uint256 expiresIn,
      address sender,
      ,
      address bondingCurve,
      string memory credURL,
      string memory credType,
      string memory verificationType,
      bytes32 merkleRoot_
  ) = abi.decode(signedData_, (uint256, address, uint256, address, string, string, string, bytes32));
  if (expiresIn <= block.timestamp) revert SignatureExpired();

  if (sender != _msgSender()) revert Unauthorized();

  if (!curatePriceWhitelist[bondingCurve]) revert Unauthorized();

+ if (!credType.eq("BASIC") && !credType.eq("ADVANCED")) {
+     revert InvalidCredType();
+ }
+ if (_recoverSigner(keccak256(signedData_), signature_) != phiSignerAddress) revert AddressNotSigned();
- if (!credType.eq("BASIC") && !credType.eq("ADVANCED")) {
-     revert InvalidCredType();
- }
```
By performing the `credType` validation before the signature verification, the function will revert early if an invalid `credType` is provided, preventing the attacker from bypassing the signature verification.
