# Vulnerability details

## Description


The `RewardControl` contract is designed to manage rewards, including depositing and withdrawing ETH for users. The [`withdrawFor` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/RewardControl.sol#L96-L98) allows an external caller to withdraw funds on behalf of any address without any permission checks. This function calls the internal [`_withdraw` function](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/abstract/RewardControl.sol#L122-L139), which performs the actual withdrawal logic. However, the lack of authorization checks in `withdrawFor` means that any external caller can withdraw funds from any address without the owner's consent.

The `withdrawFor` function is defined as follows:
```solidity
File: RewardControl.sol
96:     function withdrawFor(address from, uint256 amount) external {
97:         _withdraw(from, from, amount);
98:     }

```

The `_withdraw` function is defined as follows:
```solidity
File: RewardControl.sol
122:     function _withdraw(address from, address to, uint256 amount) internal {
123:         if (to == address(0)) revert InvalidAddressZero();
124: 
125:         uint256 balance = balanceOf[from];
126:         if (amount == FULL_BALANCE) {
127:             amount = balance;
128:         }
129: 
130:         if (amount > balance) revert InvalidAmount();
131: 
132:         unchecked {
133:             balanceOf[from] = balance - amount;
134:         }
135: 
136:         emit Withdraw(from, to, amount);
137: 
138:         to.safeTransferETH(amount);
139:     }

```

The `withdrawFor` function does not perform any authorization checks to ensure that the caller is allowed to withdraw funds on behalf of the `from` address. This means that any external caller can withdraw funds from any address without permission, which is a severe security vulnerability.

## Impact
This  allows unauthorized withdrawals, potentially disrupting users' financial plans, causing unexpected behavior, and incurring unwanted gas costs. In a worst-case scenario, if a user's address is a contract with vulnerable receive logic, this could lead to direct theft of funds.

## Proof of Concept
1. Alice deposits 10 ETH into the contract.
2. Bob, a malicious actor, calls `withdrawFor(alice, 10 ether)`.
3. The function executes without any checks, withdrawing all of Alice's funds to Alice's address.

## Tools Used
Manual review

## Recommended Mitigation Steps
To fix this issue, implement proper access control for the `withdrawFor` function.
