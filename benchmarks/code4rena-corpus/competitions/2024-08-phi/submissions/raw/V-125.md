# Vulnerability details

## Impact
The lack of return value checking for the external call to `curatorRewardsDistributor.deposit` can lead to unnoticed failures, potentially resulting in incorrect reward distribution. This can cause financial discrepancies and undermine the integrity of the reward system.

## Proof of Concept
1. Initial Conditions:
- The `curatorRewardsDistributor` contract has a `deposit` function that requires certain validations, such as validation of the `credId` or the amount of ETH sent.
- `curatorRewardsDistributor` is set up such that calls to `deposit` can fail if certain conditions are not met.
2. Failure Conditions:
- Suppose the given `credId` is invalid or does not exist in the `curatorRewardsDistributor` system.
- Or, the amount sent (`curateTotalReward_`) does not match what the `deposit` function expects.
3. Call Execution:
- The `depositRewards` function is called with the `credId` or amount that causes the `deposit` in `curatorRewardsDistributor` to fail.
- Since there is no check on the return value (`success`) of this call, the `PhiRewards` contract is unaware that the call failed.
