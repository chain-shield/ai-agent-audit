# Vulnerability details

## Impact

Calling `Cred::createCred` function will call the `_createCredInternal` function where the reentrancy can happen. This allow cred creator to buy multiple share at the same time they create the creds, front running other user and make the protocol not fair.

## Proof of Concept

The step of exploit:

1. participant1 wants to create a cred `credId=1`
2. participant1 use reentrancy to create and buy multiple early cheap shares
3. other participant see the newly created `credId=1`
4. other participant see the shares already sold many times
5. creating FOMO/fake statistic and other participant would eager to buy the shares
6. participant1 dump their shares

This exploit possible to happen because of the `_createCredInternal` does not follow CEI pattern:


`buyShareCred` is a function call `_handleTrade`, in the context of the function `_createCredInternal` it would automatically buy 1 share for the creator of the creds. In the above line of code, the `credIdCounter` is updated after the `buyShareCred` is called. If we inspect `_handleTrade` function then it would clearly be seen that it include ETH transfer:

## Recommended Mitigation Steps

there are multiple ways to mitigate this like add cooldown phase after each `createCred` call or after each buy function. there are extreme measure like prevent the creator to have more than 1 share. but it would change the overall logic of the protocol. so my suggestion is to change the `_createCredInternal` function to update the `credIdCounter` at earlier time:

`Cred.sol`:

```diff
    function _createCredInternal(
        address creator_,
        string memory credURL_,
        string memory credType_,
        string memory verificationType_,
        address bondingCurve_,
        uint16 buyShareRoyalty_,
        uint16 sellShareRoyalty_
    )
        internal
        whenNotPaused
        returns (uint256)
    {
        if (creator_ == address(0)) {
            revert InvalidAddressZero();
        }

        creds[credIdCounter].creator = creator_;
        creds[credIdCounter].credURL = credURL_;
        creds[credIdCounter].credType = credType_;
        creds[credIdCounter].verificationType = verificationType_;
        creds[credIdCounter].bondingCurve = bondingCurve_;
        creds[credIdCounter].createdAt = uint40(block.timestamp);
        creds[credIdCounter].buyShareRoyalty = buyShareRoyalty_;
        creds[credIdCounter].sellShareRoyalty = sellShareRoyalty_;

+       uint256 currentIdCounter = credIdCounter;
+       credIdCounter += 1;
+       buyShareCred(currentIdCounter, 1, 0);
-       buyShareCred(credIdCounter, 1, 0);

+       emit CredCreated(creator_, currentIdCounter, credURL_, credType_, verificationType_);
-       emit CredCreated(creator_, credIdCounter, credURL_, credType_, verificationType_);

-       credIdCounter += 1;

        return credIdCounter - 1;
    }
```
