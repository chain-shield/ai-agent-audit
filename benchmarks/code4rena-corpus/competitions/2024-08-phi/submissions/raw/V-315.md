# Vulnerability details

## Impact
The protocol and creators suffer a loss of expected fees during buy operations.

## Proof of Concept
The `_handleTrade` function performs an insufficient payment check after calling the bonding curve contract to retrieve the price data. [#L620-L622](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L620-L622)
```solidity
// Cred.sol
if (msg.value < price + protocolFee + creatorFee) {
    revert InsufficientPayment();
}
```
The issue arises when the `maxPrice_` parameter in the [buyShareCred](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L178-L180) function is set to 0. In this case, the following check is skipped: [#L615](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L615)
```solidity
// Cred.sol
if (priceLimit != 0 && price + protocolFee + creatorFee > priceLimit) revert PriceExceedsLimit();
```
This allows the execution to proceed even if the sent value (`msg.value`) is insufficient to cover the total fees (`protocolFee + creatorFee`).

The choice to rely solely on the `maxPrice_` parameter for the payment check is a mistake, as it allows users to bypass the fee payment by setting `maxPrice_` to 0.


**Scenario of how the attack would happen:**

1. The attacker calls the buyShareCred function with the following parameters:

   * `credId_`: The ID of the cred to buy shares for.
   * `amount_`: The amount of shares to buy.
   * `maxPrice_`: Set to 0 to bypass the price limit check.

2. The `_handleTrade` function in Cred.sol is called.

3. The bonding curve contract is called to retrieve the price data, including the `price`, `protocolFee`, and `creatorFe`e.

4. The `InsufficientPayment` check is performed, comparing `msg.value` with the sum of price, `protocolFee`, and `creatorFee`.

5. Since `maxPrice_` is set to 0, the `PriceExceedsLimit` check is skipped, allowing the execution to proceed even if `msg.value` is insufficient to cover the total fees.

6. The buy operation is completed, and the attacker receives the shares without paying the required fees to the protocol and creators.

## Tools Used
Manual review

## Recommended Mitigation Steps
Recommended to add an additional check in the `buyShareCred` function to ensure that the sent value (`msg.value`) is greater than or equal to the total fees (`protocolFee + creatorFee`) before proceeding with the buy operation.
```diff
// Cred.sol
function buyShareCred(uint256 credId_, uint256 amount_, uint256 maxPrice_) public payable {
+   (uint256 price, uint256 protocolFee, uint256 creatorFee) = IBondingCurve(creds[credId_].bondingCurve).getPriceData(credId_, creds[credId_].currentSupply, amount_, true);
+   require(msg.value >= protocolFee + creatorFee, "Insufficient payment for fees");
    _handleTrade(credId_, amount_, true, _msgSender(), maxPrice_);
}
```
