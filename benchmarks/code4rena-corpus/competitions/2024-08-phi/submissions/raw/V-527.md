# Vulnerability details

## Impact
In `Cred.sol` the `_addCredIdPerAddress` and `_removeCredIdPerAddress` functions are responsible for updating the `_credIdsPerAddress` mapping which stores the Cred IDs that a particular address owns. Currently both functions are `public`, allowing any external entity to call them. Both functions should be called only by the `_updateCuratorShareBalance` function.

## Proof of Concept
An attacker can call `_addCredIdPerAddress`, passing in arbitrary `credId_` values and `sender_` addresses, which would let the attacker manipulate the `_credIdsPerAddress` mapping.

An attacker can call `_removeCredIdPerAddress`, passing in any user's `credId_`, which would remove the `credId_` from the user's entry in the `_credIdsPerAddress` mapping.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Make `_addCredIdPerAddress` and `_removeCredIdPerAddress` private to restrict access to them, ensuring that only the contract's internal logic can invoke these functions.
