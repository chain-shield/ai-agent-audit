# Vulnerability details

## Impact
The `_initializePhiArt` function is missing appropriate access control measures, allowing any user to execute it and modify credentials, the Merkle root, and other critical data. This vulnerability could lead to unauthorized or repeated invocations, potentially compromising the integrity of the `PhiArt` structure.

## Proof of Concept
https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/PhiFactory.sol#L595

The '_initializePhiArt' function is a private function in a smart contract that is responsible for setting up or initializing a specific piece of data stored in a 'PhiArt' structure. This structure seems to represent some form of digital art or asset within the contract. The function takes input data and populates the fields of a 'PhiArt' storage variable with specific details.


'''
function initializeArt(ERC1155Data memory createData_) external {
    _initializePhiArt(art, createData_);
}
'''

if the 'initializeArt' function is external and lacks access control like 'onlyOwner', any user could call the function repeatedly, leading to '_initializePhiArt' being invoked. The malicious user could call 'initializeArt' with different data, reinitializing or corrupting the PhiArt object.

## Tools Used
Manual Review

## Recommended Mitigation
Implementing modifiers such as `onlyOwner` to restrict access to the contract owner and `initializer` to ensure the `_initializePhiArt` function is called only once.
