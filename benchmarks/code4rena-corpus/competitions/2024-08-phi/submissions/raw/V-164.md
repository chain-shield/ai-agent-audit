# Vulnerability details

## Impact
The public `_addCredIdPerAddress` function can be exploited by malicious actors to cause several detrimental effects:

1. State Pollution: An attacker can arbitrarily modify the contract's state by repeatedly calling this function with various `credId_` values, including those that don't exist yet.

2. Denial of Service (DOS): By adding a large number of `credId_` values to a single address, an attacker can cause extremely high gas consumption in functions that iterate over these arrays, potentially making them unusable due to block gas limits.

3. Data Integrity: The vulnerability allows the addition of non-existent `credId_` values, which could lead to incorrect data being returned by other functions like `getPositionsForCurator`.

4. UI Disruption: The inflated and potentially incorrect data will affect the user interface, possibly causing performance issues or displaying erroneous information.

These impacts collectively threaten the reliability, usability, and integrity of the Cred system, potentially leading to financial losses or system unavailability for legitimate users.

## Proof of Concept
The vulnerable function is:

```js
function _addCredIdPerAddress(uint256 credId_, address sender_) public {
    // Add the new credId to the array
    _credIdsPerAddress[sender_].push(credId_);
    // Store the index of the new credId
    _credIdsPerAddressCredIdIndex[sender_][credId_] = _credIdsPerAddressArrLength[sender_];
    // Increment the array length counter
    _credIdsPerAddressArrLength[sender_]++;
}
```

An attacker can exploit this by:

1. Calling the function repeatedly with different `credId_` values:
   ```js
   for (let i = 0; i < 1000; i++) {
     await credContract._addCredIdPerAddress(1, attackerAddress);
   }
   ```

2. This will add 1000 entries to `_credIdsPerAddress[attackerAddress]`.

3. Functions like `getPositionsForCurator` that iterate over this array will now consume significantly more gas, potentially exceeding block gas limits.

4. The contract's state is now polluted with incorrect data, affecting the accuracy of other functions and the UI.

## Recommended Mitigation Steps
Change the visibility of [`_addCredIdPerAddress`](https://github.com/code-423n4/2024-08-phi/blob/8c0985f7a10b231f916a51af5d506dd6b0c54120/src/Cred.sol#L685) from `public` to `internal`. This prevents direct external calls to this function.
