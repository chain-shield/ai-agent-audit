## Brief Summary

The protocol does not implement a proper validation to ensure there should be a gap between the `crOpening` at which borrowers are allowed to open a loan and the `crLiquidation` at which liquidation can be executed. This means that the protocol will accept the two values passed in even if there is no gap between them. In the worst scenario it allows the user to borrow at the very edge of liquidation and be liquidated with a slight price change. This is a super risky setup for regular protocol users.
