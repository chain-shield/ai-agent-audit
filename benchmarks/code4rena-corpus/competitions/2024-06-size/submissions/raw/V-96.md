# Vulnerability details

## Impact
Borrowers might not be able to withdraw their borrowed tokens due to a very insufficient check

## Proof of Concept
Upon lending and borrowing, there is a check that does not allow the operation to happen if there is not enough liquidity in Aave. This is because whenever someone deposits borrow tokens into the system (USDC), they are supplied into Aave for extra yield. So whenever a user borrows, he would usually want to immediately receive the tokens he borrowed by calling `withdraw()` and getting the tokens from Aave. The check essentially disallows the user to borrow whenever he will not be able to take out those tokens from Aave. This is the check responsible for that:
```solidity
function validateVariablePoolHasEnoughLiquidity(State storage state, uint256 amount) public view {
        uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(state.data.variablePool));
        if (liquidity < amount) {
            revert Errors.NOT_ENOUGH_BORROW_ATOKEN_LIQUIDITY(liquidity, amount);
        }
    }
```
This check is highly insufficient.
Imagine the following scenario:
1. There are 90 tokens in the Aave pool
2. Bob borrows 100 tokens which would not be possible as the check would revert
3. Alice frontruns him and supplies 10 tokens to Aave
4. Now, Bob's transaction will successfully execute as there are now 100 tokens in the Aave pool
5. Alice backruns him and withdraws her tokens from Aave
6. Now, Bob can't withdraw his tokens and the check was insufficient

This is only avoidable by the user batching his transactions but that is definitely not a typical user behavior and not likely for users to do unless they have solid coding skills and understanding.
## Tools Used
Manual Review
## Recommended Mitigation Steps
The fix is not trivial as this can always occur. The 2 options I can see is that you either accept that users won't be able to withdraw their USDC tokens in some cases and remove the check altogether or do not integrate Aave at all.
