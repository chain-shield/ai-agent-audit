# Vulnerability details

## Impact
Users will not be able to withdraw their USDC in some cases

## Proof of Concept
Whenever a user tries to withdraw from the protocol, there is this check:
```solidity
function validateUserIsNotBelowOpeningLimitBorrowCR(State storage state, address account) external view {
        uint256 openingLimitBorrowCR = Math.max(
            state.riskConfig.crOpening,
            state.data.users[account].openingLimitBorrowCR // 0 by default, or user-defined if SetUserConfiguration has been used
        );
        if (collateralRatio(state, account) < openingLimitBorrowCR) {
            revert Errors.CR_BELOW_OPENING_LIMIT_BORROW_CR(account, collateralRatio(state, account), openingLimitBorrowCR);
        }
}
```
The function's goal is to validate that the user is not leaving himself under the `crOpening`. For example, if a user tries to withdraw his collateral when he has borrowed some tokens, this function would revert as that makes his position insolvent. The issue is that this function is called upon withdrawing both USDC (the borrow token) and ETH (the collateral token):
```solidity
function withdraw(WithdrawParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateWithdraw(params);
        state.executeWithdraw(params);
        state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
    }
```
This disallows users who have USDC and are below the `crOpening` to withdraw. This creates a few possible issues.

Situation A: Alice has deposited 1 ETH (price of 1 ETH is 1500\$ for the example) and borrows 1000\$, now her collateral ratio is equal to `crOpening` (1.5e18 according to deployment scripts). Price of ETH drops to 1499.99\$ and she won't be able to withdraw due to the check.

Situation B: Alice has deposited 1 ETH and borrows 1000\$, she has also deposited USDC and has lent it out. A month later, she receives her USDC back with interest from the borrower and tries to withdraw it. In the meantime, her collateral ratio has dropped to 1.4e18 and she is not able to.

While this check is effective and should be there, it should not disallow users from withdrawing their USDC. It should only disallow users to withdraw their ETH as that is the token responsible for their collateral ratio.

Paste the following POC into `Withdraw.t.sol`:
```solidity
function testUserWillNotBeAbleToWithdrawUsdc() public {
        _setPrice(1e18);
        _deposit(bob, usdc, 1000e6);
        _deposit(alice, weth, 1500e18);

        _buyCreditLimit(bob, type(uint256).max, YieldCurveHelper.pointCurve(1 hours, 0));
        _sellCreditMarket(alice, bob, RESERVED_ID, 1000e6, 1 hours, true);

        _setPrice(1e18 - 1);
        
        vm.expectRevert(abi.encodeWithSelector(Errors.CR_BELOW_OPENING_LIMIT_BORROW_CR.selector, alice, size.collateralRatio(alice), 1.5e18));
        _withdraw(alice, usdc, 1000e6);
    }
```
