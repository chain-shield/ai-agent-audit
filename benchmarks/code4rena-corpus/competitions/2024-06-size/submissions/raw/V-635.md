# Vulnerability details

## Impact
The admin is able to update the swap fee apr through a call to `updateConfig`. The issue is that the function validates whether the value is above the maximum incorrectly. As a result the `swapFeeApr` cannot be above the minimum.

## Proof of Concept
Here is how the validation is implemented:
```solidity
if (params.value >= Math.mulDivDown(PERCENT, YEAR, state.riskConfig.maxTenor)) {
   revert Errors.VALUE_GREATER_THAN_MAX(
      params.value, Math.mulDivDown(PERCENT, YEAR, state.riskConfig.maxTenor)
   );
}
```
We can see that if `params.value` is more than `Math.mulDivDown(PERCENT, YEAR, state.riskConfig.maxTenor)` the call reverts. This is incorrect as, due to the division: `PERCENT * YEAR / MAX_TENOR`, the maximum value is reached not when dividing by the maximum tenor, but when dividing by the minimum tenor (the bigger the divisor, the smaller the result). By dividing by the maximum tenor we are actually getting a minimum limit (in the protocol implementation the minimum value for the swap fee apr is 0).

As a result, the swap fee apr will always be smaller than expected and will not actually be able to reach the values it is expected to reach.

Manual review

## Recommended Mitigation Steps
Divide by the `state.riskConfig.minTenor` in the validation above:
```solidity
if (params.value >= Math.mulDivDown(PERCENT, YEAR, state.riskConfig.minTenor)) {
   revert Errors.VALUE_GREATER_THAN_MAX(
      params.value, Math.mulDivDown(PERCENT, YEAR, state.riskConfig.maxTenor)
   );
}
```
