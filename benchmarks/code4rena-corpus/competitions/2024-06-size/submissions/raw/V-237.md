# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L198-L221

```solidity
    function repay(RepayParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateRepay(params);
        state.executeRepay(params);
    }


    function liquidate(LiquidateParams calldata params)
        external
        payable
        override(ISize)
        whenNotPaused
        returns (uint256 liquidatorProfitCollateralToken)
    {
        state.validateLiquidate(params);
        liquidatorProfitCollateralToken = state.executeLiquidate(params);
        state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
    }

```

These are the external functions that query both repay/ liquidate, evidently, these functions require the protocol to not be in a paused state, issue however is that while the protocol a user's debt position is going to keep on accruing more dept, and could even become liquidatable, even if they would like to make a repayment deposit, cause they can't considering the `whenNotPaused`.Also we can't expect the user to immediately repay the debt position once the protocol is unpaused, cause in this case the liquidator can just front run the users tx and ensure that the user loses out on his funds via liquidation.

## Impact

A user loses out on his position unfairly, considering even if they would like to deposit and repay, they can't due to the modifier when not paused modifier.

## Recommended Mitigation Steps

Consider removing the `whenNotPaused` modifier from repay(), alternatively, consider allowing a grace period on liquidations after the protocol gets unpaused.
