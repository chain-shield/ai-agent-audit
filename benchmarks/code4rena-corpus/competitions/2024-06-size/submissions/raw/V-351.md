# Vulnerability details

## Impact

When a creditPosition is transferred to a new lender when calling `compensate`, it is not ensured that the creditPosition is forSale which breaks the core protocol assumption that new creditPositions are by default for sale. This forces the new lender to make an additional function call to be able to sell the creditPosition transferred to him.

## Proof of Concept
 
In the SIZE protocol, a loan consists of one debtPosition and (at least) one creditPosition. The lender for the loan is recoded in the creditPosition and the borrower of the loan is recorded in the borrowPosition.

If a user is involved in two loans and is the lender / owns the creditPosition in loan1 (positive balance) and is the borrower / owns the borrowPosition in loan2 (negative balance), he can call the function `compensate` to reduce his borrowPosition for loan2 by up to the total credit amount / positive balance of his creditPosition in loan1.

If he uses the total credit amount of his creditPosition(loan1) to compensate his debtPosition(loan2), the debtPosition is reduced by the credit amount and the creditPosition is transferred to the lender in loan2. 

According to the team, the protocol design is such that by default all credit positions are for sale. If the lender want to opt out, they must take extra steps to do so, namely call `setUserConfiguration` and change the `forSale` flag of the creditPosition to false.

The issue arises from the fact that if a creditPosition is fully transferred from one lender to another when `compensate` is called, only the lender is changed but it is not ensured that the transferred creditPosition is forSale.

```java
if (exitCreditPosition.credit == credit) {
            exitCreditPosition.lender = lender;

            emit Events.UpdateCreditPosition(
                exitCreditPositionId, lender, exitCreditPosition.credit, exitCreditPosition.forSale
            );
}
```  

This means that if the previous lender of the creditPosition has set the forSale flag of the creditPosition to false, the position will not be forSale, even though it now has a new lender. This breaks the intended design of the protocol and additionally forces the new lender to explicitly call `setUserConfiguration` to change the forSale flag if he wants to sell his new position. 


## Recommended Mitigation Steps

When `compensate` is called and a creditPosition is fully transferred to a new lender, make sure to set the `forSale` flag of the creditPosition to true to comply with the protocol design:

```diff
     if (exitCreditPosition.credit == credit) {
  	exitCreditPosition.lender = lender;
+	exitCreditPosition.forSale = true;
              emit Events.UpdateCreditPosition(
                exitCreditPositionId, lender, exitCreditPosition.credit, exitCreditPosition.forSale
            );
        }
```
