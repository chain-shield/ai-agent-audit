# Vulnerability details

## Impact
In `debtTokenAmountToCollateralTokenAmount`, the issue is that the function is not correctly converting the `collateralTokenAmount` from the price feed's decimals to the collateral token's decimals. Currently, the function calculates [collateralTokenAmount as follows:#L32-L34](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L32-L34)
```solidity
collateralTokenAmount = Math.mulDivUp(
    debtTokenAmountWad, 10 ** state.oracle.priceFeed.decimals(), state.oracle.priceFeed.getPrice()
);
```
> However, this assumes that the collateral token has the same number of decimals as the price feed. The result will be incorrect if the collateral token has a different number of decimals. If the collateral token has a different number of decimals than the price feed, the calculated `collateralTokenAmount` will be incorrect.

## Proof of Concept
1. The `debtTokenAmountToCollateralTokenAmount` function is defined in the [AccountingLibrary.sol#L21-L35](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L21-L35)

2. The function takes two parameters:
   - `state`: The storage variable of type `State` holds the protocol's state.
   - `debtTokenAmount`: The amount of debt tokens converted to collateral tokens.

3. Inside the function, the `debtTokenAmount` is converted to a fixed-point representation (WAD) using the `amountToWad` function from the `Math library: [Math.sol#L27-L29](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/Math.sol#L27-L29)
   - The `amountToWad` function multiplies the `debtTokenAmount` by 10^18 and divides it by 10^(token decimals) to convert it to WAD format.

4. The `collateralTokenAmount` is then calculated using the `mulDivUp` function from the Math library: [Math.sol#L52-L54](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/Math.sol#L52-L54)
   - The `mulDivUp` function multiplies `debtTokenAmountWad` by 10^(price feed decimals) and divides it by the current price obtained from the price feed oracle.

5. However, the issue arises because the calculated `collateralTokenAmount` is not converted correctly from the price feed's decimals to the collateral token's decimals.

Assume the following:
    - Debt token decimals: 18
    - Collateral token decimals: 8
    - Price feed decimals: 18
    - Current price from the price feed: 2000000000000000000 (2 * 10^18)
    - Debt token amount: 1000000000000000000 (1 * 10^18)

Using the original buggy code:
```solidity
collateralTokenAmount = Math.mulDivUp(
    debtTokenAmountWad, 10 ** state.oracle.priceFeed.decimals(), state.oracle.priceFeed.getPrice()
);
```
The calculated `collateralTokenAmount` would be.
```solidity
collateralTokenAmount = (1 * 10^18) * (10^18) / (2 * 10^18)
                      = 0.5 * 10^18
                      = 500000000000000000
```
However, since the collateral token has 8 decimals, the actual expected `collateralTokenAmount` should be.
```solidity
collateralTokenAmount = (1 * 10^18) * (10^8) / (2 * 10^18)
                      = 0.5 * 10^8
                      = 50000000
```
As you can see, the original code overestimates the collateral amount by a factor of 10^10 (the difference in decimals between the price feed and the collateral token).

- Given:
  - Debt token decimals: 18
  - Collateral token decimals: 8
  - Price feed decimals: 18
  - Current price from the price feed: \(2 \times 10^{18}\) (equivalent to 2)
  - Debt token amount: \(1 \times 10^{18}\) (equivalent to 1 token in 18 decimals)

## Recommended Mitigation Steps
Before returning the value, convert the `collateralTokenAmount` from the price feed's decimals to the collateral token's decimals.
```solidity
uint256 collateralTokenAmountPriceFeedDecimals = Math.mulDivUp(
    debtTokenAmountWad, 10 ** state.oracle.priceFeed.decimals(), state.oracle.priceFeed.getPrice()
);
collateralTokenAmount = Math.convertDecimals(
    collateralTokenAmountPriceFeedDecimals, state.oracle.priceFeed.decimals(), state.data.underlyingCollateralToken.decimals()
);
```
The calculated `collateralTokenAmount` would be:
```solidity
collateralTokenAmountPriceFeedDecimals = (1 * 10^18) * (10^18) / (2 * 10^18)
                                       = 0.5 * 10^18
                                       = 500000000000000000

collateralTokenAmount = Math.convertDecimals(500000000000000000, 18, 8)
                      = 50000000
```
The corrected code accurately converts the collateral amount to the collateral token's decimals, providing the expected result of 50000000.
