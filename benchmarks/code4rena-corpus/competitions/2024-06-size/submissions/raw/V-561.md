# Vulnerability details

## Vulnerability details
Function `validateVariablePoolHasEnoughLiquidity` is used to check if there is enough liquidity in aave pool to withdraw or not:

    function validateVariablePoolHasEnoughLiquidity(State storage state, uint256 amount) public view {
        uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(state.data.variablePool));  // <---
        if (liquidity < amount) {
            revert Errors.NOT_ENOUGH_BORROW_ATOKEN_LIQUIDITY(liquidity, amount);
        }
    }
But in all functions that implement `validateVariablePoolHasEnoughLiquidity` function, token is not withdrawn outside of aave pool, especially in `buyCreditMarket()` function.

Attack scenario:
0, Attacker see that there is not enough token in aave pool.
1, Attacker deposit token to aave pool to make it enough to execute function later.
2, Attacker execute `buyCreditMarket()` function.
3, Attacker withdraw token from aave pool.

Which lead to attack are able to bypass checking condition in `validateVariablePoolHasEnoughLiquidity()` function

## Impact
Victim will have to pay interest on an unusable token.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Withdraw token from aave and transfer it to borrower when borrow offer is submited.
