# Vulnerability details

## Description
   - When a user (like Alice) wants to borrow money, she can submit a `sellCreditLimit`. This is essentially selling future cash flow in the form of credit.
   - When a user (like Bob) wants to exit a loan, he can also use `sellCreditLimit` to sell the credit he owns. This is crucial because the same function handles both borrowing new money and exiting existing loans, which could be a point of complexity and bugs, especially if the handling of these two scenarios diverges unexpectedly.

## Impact
At the [SellCreditMarketParams struct](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L17-L34) in `SellCreditMarket.sol`
```solidity
struct SellCreditMarketParams {
    // The lender
    address lender;
    // The credit position ID to sell
    // If RESERVED_ID, a new credit position will be created
    uint256 creditPositionId;
    // The amount of credit to sell
    uint256 amount;
    // The tenor of the loan
    // If creditPositionId is not RESERVED_ID, this value is ignored and the tenor of the existing loan is used
    uint256 tenor;
    // The deadline for the transaction
    uint256 deadline;
    // The maximum APR for the loan
    uint256 maxAPR;
    // Whether amount means credit or cash
    bool exactAmountIn;
}
```
The `creditPositionId` field differentiates between borrowing new money (when set to RESERVED_ID) and exiting an existing loan (when set to an existing credit position ID).

```solidity
function executeSellCreditMarket(State storage state, SellCreditMarketParams calldata params)
    external
    returns (uint256 cashAmountOut)
{
    // ...

    if (params.creditPositionId == RESERVED_ID) {
        // slither-disable-next-line unused-return
        state.createDebtAndCreditPositions({
            lender: msg.sender,
            borrower: msg.sender,
            futureValue: creditAmountIn,
            dueDate: block.timestamp + tenor
        });
    }

    state.createCreditPosition({
        exitCreditPositionId: params.creditPositionId == RESERVED_ID
            ? state.data.nextCreditPositionId - 1
            : params.creditPositionId,
        lender: params.lender,
        credit: creditAmountIn
    });

    // ...
}
```
The function checks if `creditPositionId` is `RESERVED_ID`. If it is, it creates a new debt and credit position pair using `createDebtAndCreditPositions`. If not, it assumes an existing credit position is being sold and updates it using `createCreditPosition`.

While this approach allows for code reuse, it can lead to potential issues:
