# Vulnerability details

## Description
In the `BuyCreditMarket` smart contract, there is a validation check designed to ensure that the amount involved in a credit transaction is not below the minimum credit amount set in the contract (`50e6` in this case). 

`state.riskConfig.minimumCreditBorrowAToken`

```
 // validate amount
        if (params.amount < state.riskConfig.minimumCreditBorrowAToken) {
            revert Errors.CREDIT_LOWER_THAN_MINIMUM_CREDIT(params.amount, state.riskConfig.minimumCreditBorrowAToken);
        }
```
This check is implemented to prevent transactions that don't meet the minimum required credit amount from proceeding. However, the validation does not distinguish between cases when the `exactAmountIn` flag is true, which implies the amount represents cash (the actual borrow amount) rather than credit (future value). 

When `exactAmountIn` is true, the amount specified by the lender represents the cash they are willing to lend, not the credit amount, which will include interest. Therefore, the validation should account for scenarios where the cash input is less than `50e6` but the resulting credit amount exceeds this threshold due to the addition of interest. The current implementation fails to make this distinction, which could unjustly block valid transactions where the cash input is low but the resultant credit is above the minimum.

## Impact
The existing validation logic might lead to potential usability issues and reduced flexibility for lenders. Lenders willing to provide cash amounts that would result in valid credit amounts post-interest might see their transactions reverted. This could restrict the utility of the platform, deter smaller lenders from participating.

## Recommended Mitigation Steps
1. **Adjust Validation Logic**: Modify the `validateBuyCreditMarket` function to differentiate between cash amounts and credit amounts when `exactAmountIn` is true. Specifically, the validation logic should calculate the expected credit amount (future value) based on the input cash amount and the interest rate applicable for the tenor selected. This calculated credit amount should then be compared against `state.riskConfig.minimumCreditBorrowAToken`.
