# Vulnerability details

Rounding is a tricky issue in smart contract that if it's not well handle can cause devastating bugs. In the case of the liquidation the collateral of the user to be liquidate  is rounding down (rounding again the protocol) instead of rounding up (against the user). In simple words the protocol is liquidating less collateral that the protocol should.

## Impact
Liquidation may not be profitable as it should be, in some cases the liquidation is not profitable see proof of concept.

Note that this problem is im `selfLiquidate` function too since is calling the `getCreditPositionProRataAssignedCollateral` function.
