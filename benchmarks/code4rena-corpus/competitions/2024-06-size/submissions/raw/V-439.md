# Vulnerability details

## Impact
When users compensate with `creditPositionToCompensateId = RESERVED_ID`, the contract makes a call to `createDebtAndCreditPositions`

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Compensate.sol#L120

In this function, there is a check for the `tenor`

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L87

Because of this check, the function will revert when then `tenor` less than `state.riskConfig.minTenor`.

As a result, users can not compensate with `creditPositionToCompensateId = RESERVED_ID` at the end of the loan, which also breaks the DOS invariant

> DOS: Functions should not revert if preconditions are met (Denial of Service)

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Add an parameter in `createDebtAndCreditPositions` to check if the call is from the compensate function or not

```diff
    function createDebtAndCreditPositions(
        State storage state,
        address lender,
        address borrower,
        uint256 futureValue,
        uint256 dueDate,
+       bool isCompensate
    ) external returns (CreditPosition memory creditPosition) {
        ...
+       if (!isCompensate) {
            state.validateTenor(dueDate - block.timestamp);
+       }
        ...
    }
```
