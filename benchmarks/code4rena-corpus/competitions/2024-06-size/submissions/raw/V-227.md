# Vulnerability details

## Impact

When a creditpositionid is opened for a user. By default  the creditpositionid forSale is true. User can make forSale false for individual creditpositionid or user can  disable  allCreditPositions Sale by calling the  function setUserConfiguration. But the problem is the user can’t make allCreditPositionsForSaleDisabled true if he has no creditpositionid.so when a creditpositionid is opened for the 1st time for a user, by default  forSale is true. If the user’s intention is not to sell the creditpositionid , he has to  make forSale  false/allCreditPositionsForSaleDisabled  true after opening the creditposition. But the attacker can frontrun and buy the creditposition before making it forSale - false. This may make users get less profit.

## Proof of Concept
1. Let’s assume, Alice creates borrow offer with 3 months(3% apr), 4 months(4% apr), 5 months(5% apr).

2. bob(lender) calls the function buyCreditMarket with alice as borrower and 3  months(3% apr) as tenor.this is bob’s 1st creditpositonid, so by default forSale is true. Bob’s intention is to make forSale false for this creditposition.

3. Before bob making forSale false for this creditposition, john frontruns and buy the creditpositionid

## Tools Used
manual review
## Recommended Mitigation Steps
Make sure that before creating any creditpositionid , the user can make allCreditPositionsForSaleDisabled true.
