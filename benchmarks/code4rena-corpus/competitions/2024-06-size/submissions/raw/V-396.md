# Vulnerability details

## Impact
The `deposit` function in Size.sol allows depositing collateral on behalf of any address without verifying if it's blacklisted. The `DepositParams` struct in `Deposit.sol` includes a to field, allowing deposits to be made to any address. This allows blacklisted addresses to receive tokens and open positions within the protocol, effectively bypassing restrictions implemented at the underlying token level.

This vulnerability allows blacklisted addresses to circumvent regulatory controls or sanctions implemented by the underlying token. Specifically:

Blacklisted addresses can receive and hold tokens within the Size protocol.

This could facilitate illicit financial activities by providing a way to move restricted funds.

The protocol may be in violation of compliance requirements related to the underlying tokens.

It exposes the protocol to potential legal and regulatory risks.

The protocol could also face positions that cannot be liquidated when sending the remaining amount of collateral USDC back to the blacklisted address(during liquidations) as the address may not be able to be to be sent USDC. This could lead to bad debt or insolvency

## Recommended Mitigation Steps
Modify the `Deposit.sol` contract to include a blacklist check.

Create an interface, modifier, or function for blacklist checking.

Update the `executeDeposit` function to use these blacklist checks

Add events for blacklist checks to improve transparency and auditability.
