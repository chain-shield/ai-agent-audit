# Vulnerability details

**Description:**

The `executeDeposit` function in the `Deposit` contract includes a line `amount = address(this).balance;` which sets the deposit amount to the contract’s current balance if `msg.value > 0`. This can be manipulated by an external party sending Ether to the contract after the initial check of msg.value and before the assignment to `amount`. This manipulation can lead to incorrect deposit amounts, potentially over-depositing Ether and converting it into WETH more than intended.

The primary issue is that the user loses control over their deposit. The user intends to deposit a specific amount of Ether, and any deviation from this intention, whether beneficial or not, is a loss of control and can lead to confusion or mistrust.

While it might seem beneficial in some cases, it can lead to unintended consequences where the user is involved in unintended financial operations. The user's financial planning and strategies might be disrupted by these unexpected changes.

**Impact:**

1. User Financial Loss: Users may unintentionally deposit more Ether than they intended, resulting in unexpected financial loss.
2. Protocol Integrity: The protocol's accounting and token balances could be disrupted due to discrepancies caused by manipulated deposit amounts.
3. Loss of User Trust: Users losing control over their deposits can lead to mistrust and reduced engagement with the protocol.
4. Exploit Opportunities: Exploitable patterns can lead to more sophisticated attacks, causing larger-scale financial drains from the protocol.

**Proof of Concept:**

1. Initial State:

- The contract has a balance of 1 ETH.
- A user calls executeDeposit intending to deposit 0.5 ETH with msg.value set to 0.5 ETH.

2. Attack Execution:

- Before the line amount = address(this).balance; is executed, an attacker sends an additional 1 ETH to the contract.
- This action changes the contract balance to 1.5 ETH.

3. Manipulation Outcome:

- The line amount = address(this).balance; sets amount to 1.5 ETH instead of the intended 0.5 ETH.
- The contract then converts 1.5 ETH to WETH, minting more WETH than intended.

4. User Impact:

- The user who intended to deposit 0.5 ETH ends up depositing 1.5 ETH, incurring a loss of 1 ETH.

**Tools Used:**

Manual Review

**Recommended Mitigation:**

1. Use msg.value Directly: Instead of using address(this).balance, use msg.value to ensure the deposit amount is exactly what the user sent in the current transaction.
2. Implement Reentrancy Guard: Use the ReentrancyGuard modifier to prevent reentrancy attacks that might exploit the timing of balance updates.
