# Vulnerability details

## Impact
A 1% fee removal from the user with an overdue loan should be enforced in repayment function, the protocol believes that once a loan is liquidatable it would be liquidated but the time during between liquidation and execution a user can repay and since the Overdue fee is not enforced in the repayment logic thus the protocol loses revenue. A user has all the time in the world to repay his loan not doing so on time attracts a fee BASED ON THE PROTOCOL IMPLEMENTATION AND DOCS if his/her position is not underwater and it is overdue.
The current loan repayment logic allows users to bypass the overdue fee by front-running the liquidation process. This issue arises because the protocol does not enforce the overdue fee when a user repays their loan after the due date even though it is not underwater but it is implemented only during the liquidation process. This leads to several problems:

1. **Protocol Revenue Loss**: The protocol loses potential revenue from overdue fees because users can repay overdue loans without incurring any penalties if they do so just before liquidation is triggered.

2. **Incentive Misalignment**: This loophole creates a misaligned incentive structure, allowing borrowers to exploit the system by delaying repayments without facing the financial consequences intended by the protocol for overdue payments for positions not underwater.

**2. Front-running Scenario**:

- **Step-by-Step Analysis**:
  1. Borrower delays repayment, allowing the loan to become overdue.
  2. Liquidator initiates a transaction to liquidate the overdue loan.
  3. Borrower front-runs the liquidation by repaying the loan with a higher gas fee without incurring the overdue fee.
  4. Liquidator's transaction reverts as the loan is now marked as repaid.
