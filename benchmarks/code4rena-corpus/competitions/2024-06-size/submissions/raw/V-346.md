# Vulnerability details

## Impact
Users can scam other users by frontrunning them, before they match their borrow/loan offers 

## Proof of Concept
The flow is as it follows:
1. User call sellCreditLimit/buyCreditLimit to create a borrow/loan offer, which is saved to the `USER` struct
2. Then, when someone match the borrow/loan offer by calling the buyCreditMarket/sellCreditMarket function, the first user frontruns him and changes the offer to one that suites his needs better, ultimately scamming the other user of giving him a better loan

This has some limitations, since the there are maxAPR and minAPR checks, but still is an exploitable scenario.

## Tools Used
Manual review
## Recommended Mitigation Steps
Add a mapping, which will store at what point in time the user made the borrow/loan offer and then check if the some amount of time, for example 1 day has passed. This way you will ensure that no user can frontrun and scam the other in this time period and at the same time you leave users freedom to change their borrow/loan offers every day if no one wants to match them or they don't want this loan anymore. This way of adding may be the easiest to assimilate:
