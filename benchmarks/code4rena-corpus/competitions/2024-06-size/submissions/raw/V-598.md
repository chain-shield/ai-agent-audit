# Vulnerability details

## Description
After any ```buyCreditMarket```, ```sellCreditMarket``` and ```liquidateWithReplacement``` function call, a check ```validateVariablePoolHasEnoughLiquidity``` is happening as can be seen here :
```solidity
    function buyCreditMarket(BuyCreditMarketParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateBuyCreditMarket(params);
        uint256 amount = state.executeBuyCreditMarket(params);

        if (params.creditPositionId == type(uint256).max) {
            state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
        }

@>        state.validateVariablePoolHasEnoughLiquidity(amount);
    }
```
```solidity
    function sellCreditMarket(SellCreditMarketParams memory params) external payable override(ISize) whenNotPaused {
        state.validateSellCreditMarket(params);
        uint256 amount = state.executeSellCreditMarket(params);

        if (params.creditPositionId == type(uint256).max) {
            state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
        }
@>        state.validateVariablePoolHasEnoughLiquidity(amount);
    }
```
```solidity
    function liquidateWithReplacement(LiquidateWithReplacementParams calldata params)
        external
        payable
        override(ISize)
        whenNotPaused
        onlyRole(KEEPER_ROLE)
        returns (uint256 liquidatorProfitCollateralToken, uint256 liquidatorProfitBorrowToken)
    {
        state.validateLiquidateWithReplacement(params);
        uint256 amount;
        (amount, liquidatorProfitCollateralToken, liquidatorProfitBorrowToken) = state.executeLiquidateWithReplacement(params);

        state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
        state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
@>        state.validateVariablePoolHasEnoughLiquidity(amount);
    }
```

If we look at the ```validateVariablePoolHasEnoughLiquidity``` function, we can see that a USDC ```balanceOf``` check is done on the ```variablePool``` address, so to ensure that there is sufficient liquidity in the Variable Pool to fulfill the transaction requirements :
```solidity
    function validateVariablePoolHasEnoughLiquidity(State storage state, uint256 amount) public view {
        uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(state.data.variablePool));
        if (liquidity < amount) {
            revert Errors.NOT_ENOUGH_BORROW_ATOKEN_LIQUIDITY(liquidity, amount);
        }
    }
```
[Link to code](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/CapsLibrary.sol#L67C5-L72C6)

However, the ```USDC``` tokens are stored in the ```aToken``` address (which is retrieved from ```variablePool.getReserveData()``` in other parts of the Size codebase), not in the ```variablePool``` address. So, the ```liquidity``` variable will be always zero and as a result, the ```validateVariablePoolHasEnoughLiquidity``` function will always revert.

## Proof of Concept
To understand better that during a ```supply``` call on an AAVE pool the tokens are stored in the ```aToken``` address, see the ```SupplyLogic``` contract :

Or, simply, query the ```balanceOf``` aToken address : 0x98C23E9d8f34FEFb1B7BD6a91B7FF122F4e16F5c and the ```balanceOf``` variablePool address : 0x87870Bca3F3fD6335C3F4ce8392D69350B4fA4E2 , in [USDC smart contract](https://etherscan.io/token/0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48#readProxyContract).

## Impact
The impact of this vulnerability is catastrophic for the protocol, since the two main functionalities of the protocol will be not working and every call on them will revert. Credit will be not able to be neither bought nor sold, so lending and borrowing will be impossible. As a result, the protocol will be unusable.

## Tools Used
Manual review, Etherscan

## Recommended Mitigation Steps
To mitigate this vulnerability, use ```aToken``` address instead of the ```variablePool``` address in the ```balanceOf``` check since all ```USDC``` are stored under the token address :
```diff
    function validateVariablePoolHasEnoughLiquidity(State storage state, uint256 amount) public view {
-        uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(state.data.variablePool));
+        IAToken aToken = IAToken(state.data.variablePool.getReserveData(address(state.data.underlyingBorrowToken)).aTokenAddress);
+        uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(aToken));
        if (liquidity < amount) {
            revert Errors.NOT_ENOUGH_BORROW_ATOKEN_LIQUIDITY(liquidity, amount);
        }
    }
```
