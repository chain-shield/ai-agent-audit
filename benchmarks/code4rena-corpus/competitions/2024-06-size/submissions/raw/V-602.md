# Vulnerability details

## Description
Users can call ```withdraw()``` function either because they want to get out their collateral ```szETH``` to ```WETH``` or because they want to withdraw the ```szaUSDC``` they borrowed and make them ```USDC``` so they can be indeed used in the broader Ethereum ecosystem. However, after every ```withdraw()``` call, there is a check that validates that the collateral ratio of the sender is not below the openingLimitBorrow CR which is by default 1.5 or bigger if user has set it. This check makes sense for ```szETH``` withdrawals since such a call will make user dangerously closer to liquidation. However, a user when he is borrow an amount of money should be able to withdraw them, so to actually use them if even if he is below the openeningLimitBorrow CR, as long as he is not liquidatable. In this way, the protocol prevents a healthy user from using the money he borrowed and payed fees for them for no reason.

## Impact
As a result of this vulnerability, healthy users can not withdraw the funds that they borrowed and actually use them, even if their collateral ratio is healthy.

## Proof of Concept
To understand this scenario better, consider the following example :
1. Alice has 1 szETH (3500 USDC) collateral and take a loan of 2300 szaUSDC (2400 USDC) so her collateral ratio is 1.52.
2. Some time pass and ETH loses value against USDC so the collateral ratio of Alice becomes 1.48.
3. Now, Alice tries to withdraw the szaUSDC she borrowed to make them USDC and use them for the reason she borrowed them but she can't, even if her collateral ratio is healthy and she is not liquidatable.
4. Now, Alice has to deposit more collateral szETH just to surpuss 1.5 or waits for an increase in the price of ETH against USDC.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider not allowing users withdrawing their ```szaUSDC``` only if they are liquidatable since they have to return them ASAP.
