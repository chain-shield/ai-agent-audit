# Vulnerability details

## Impact
The `executeSelfLiquidate()` function has been updated to include the repay fee calculation and charging, but the `getCreditPositionProRataAssignedCollateral()` function still needs to be modified to adjust the collateral amount by deducting the unpaid fees.

In the current implementation of `getCreditPositionProRataAssignedCollateral(),` the assigned collateral is calculated without considering the repayment fee. This means that the assigned collateral returned by this function needs to be adjusted for the unpaid fees, which can lead to the first creditor receiving more collateral than they should.

The bug's concept is that the assigned collateral needs to be adjusted for the unpaid fees, leading to an incorrect collateral distribution during the self-liquidation process. The first creditor who initiates the self-liquidation will receive more collateral than they should, while subsequent creditors will receive less collateral than they are entitled to.

The impact of the bug is as follows:
   - The first creditor benefits from the unpaid fees and receives a larger share of the collateral than intended.
   - Subsequent creditors suffer financial losses as they receive less collateral than they should.
   - The self-liquidation logic is violated, resulting in an unfair collateral distribution.
   - The bug can be exploited by malicious actors, exacerbating the financial losses for subsequent creditors.
   - It can lead to losing trust and reputation in the platform or protocol.

## Proof of Concept
The original [`getCreditPositionProRataAssignedCollateral()`#src/libraries/LoanLibrary.sol](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L170-L185)
```solidity
function getCreditPositionProRataAssignedCollateral(State storage state, CreditPosition memory creditPosition)
    public
    view
    returns (uint256)
{
    DebtPosition storage debtPosition = getDebtPosition(state, creditPosition.debtPositionId);

    uint256 debtPositionCollateral = getDebtPositionAssignedCollateral(state, debtPosition);
    uint256 creditPositionCredit = creditPosition.credit;
    uint256 debtPositionFutureValue = debtPosition.futureValue;

    if (debtPositionFutureValue != 0) {
        return Math.mulDivDown(debtPositionCollateral, creditPositionCredit, debtPositionFutureValue);
    } else {
        return 0;
    }
}
```
This implementation calculates the assigned collateral without considering the repayment fee. The function calculates the pro-rata collateral based on the credit position's credit and the debt position's future value.

The updated [`executeSelfLiquidate()`#src/libraries/fixed/actions/SelfLiquidate.sol](https://github.com/SizeCredit/size-solidity/blob/54b9da570c9435044cb7de9dc3ca07ee73949794/src/libraries/fixed/actions/SelfLiquidate.sol#L52-L73)
```solidity
function executeSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external {
    emit Events.SelfLiquidate(params.creditPositionId);

    CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

    uint256 credit = creditPosition.credit;
    uint256 repayFeeProRata = state.chargeRepayFeeInCollateral(debtPosition, credit);
    uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);

    (uint256 debtProRata, bool isFullRepayment) = debtPosition.getDebtProRata(credit, repayFeeProRata);
    state.data.debtToken.burn(debtPosition.borrower, debtProRata);

    debtPosition.updateRepayFee(credit, repayFeeProRata);

    if (isFullRepayment) {
        debtPosition.overdueLiquidatorReward = 0;
        debtPosition.liquidityIndexAtRepayment = state.borrowATokenLiquidityIndex();
    }

    creditPosition.credit = 0;
    state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
}
```
In the updated `executeSelfLiquidate()` function, the repay fee is calculated using `state.chargeRepayFeeInCollateral(debtPosition, credit`) and stored in the `repayFeeProRata` variable. The repayment fee is then used to calculate the debt pro rata and update the repayment fee for the debt position. However, the assigned collateral is still calculated using the original `getCreditPositionProRataAssignedCollateral()` function, which does not consider the repayment fee.

**Consider this scenario to demonstrate the bug and its impact**

Suppose we have the following state:
   - Debt Position:
     - Assigned Collateral: 1000 tokens
     - Future Value: 800 tokens
   - Credit Position 1:
     - Credit: 400 tokens
   - Credit Position 2:
     - Credit: 400 tokens
   - Repay Fee: 10% of the credit amount

In the current implementation, the following happens when a creditor (e.g., Credit Position 1) initiates a self-liquidation using the `executeSelfLiquidate()` function.
1. The repay fee for Credit Position 1 is calculated as follows:
     - Repay Fee for Credit Position 1 = 400 * 10% = 40 tokens
2. The assigned collateral for Credit Position 1 is calculated using the original `getCreditPositionProRataAssignedCollateral()` function
     - Assigned Collateral for Credit Position 1 = (1000 * 400) / 800 = 500 tokens
3. The debt and credit are reduced, and the repay fee is updated.
4. The assigned collateral (500 tokens) is transferred from the borrower to the creditor (Credit Position 1).

However, the assigned collateral is calculated considering the repayment fee, which leads to an incorrect collateral distribution.

**Now, let's consider what should happen if the `getCreditPositionProRataAssignedCollateral()` function is updated to adjust the collateral amount by deducting the unpaid fees**
1. The repay fee for Credit Position 1 is calculated as follows:
     - Repay Fee for Credit Position 1 = 400 * 10% = 40 tokens
2. The adjusted collateral is calculated by deducting the repay fee from the total assigned collateral:
     - Adjusted Collateral = 1000 - 40 = 960 tokens
3. The assigned collateral for Credit Position 1 is calculated using the adjusted collateral:
     - Assigned Collateral for Credit Position 1 = (960 * 400) / 800 = 480 tokens
4. The debt and credit are reduced, and the repay fee is updated.
5. The assigned collateral (480 tokens) is transferred from the borrower to the creditor (Credit Position 1).

In this scenario, Credit Position 1 receives 480 tokens as assigned collateral, which takes into account the repay fee. The remaining collateral (520 tokens) is available for other creditors (e.g., Credit Position 2) during their self-liquidation.

The bug's impact is that Credit Position 1 receives more collateral than it should (500 tokens instead of 480 tokens). In comparison, Credit Position 2 receives less collateral than it should when it performs self-liquidation later.

## Recommended Mitigation Steps
To fully fix the bug, the getCreditPositionProRataAssignedCollateral() function should be updated as follows
```solidity
function getCreditPositionProRataAssignedCollateral(State storage state, CreditPosition memory creditPosition)
    public
    view
    returns (uint256)
{
    DebtPosition storage debtPosition = getDebtPosition(state, creditPosition.debtPositionId);

    uint256 debtPositionCollateral = getDebtPositionAssignedCollateral(state, debtPosition);
    uint256 creditPositionCredit = creditPosition.credit;
    uint256 debtPositionFutureValue = debtPosition.futureValue;

    if (debtPositionFutureValue != 0) {
        uint256 repayFeeProRata = state.calculateRepayFeeInCollateral(debtPosition, creditPositionCredit);
        uint256 adjustedCollateral = debtPositionCollateral - repayFeeProRata;
        return Math.mulDivDown(adjustedCollateral, creditPositionCredit, debtPositionFutureValue);
    } else {
        return 0;
    }
}
```
In this updated version, the repay fee is calculated using `state.calculateRepayFeeInCollateral(debtPosition, creditPositionCredit)`, and the adjusted collateral is calculated by subtracting the repay fee from the debt position collateral. The adjusted collateral is then used to calculate the assigned collateral.
