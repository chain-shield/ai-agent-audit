# Vulnerability details

## Impact
`Size.sol` is a UUPSUpgradeable contract and methods depends on a single state variable with a `State struct` but it doesn't have gaps so is impossible to modify User, FeeConfig, RiskConfig and Oracle structs without corrupting the storage layout. Since Size protocol only relay in a single state variable, it's data structure is specially important and if get corrupted the protocol will be in a difficult situation.


| Contract | Has Gap | Store gap |
|----------|----------|----------|
| Size | `NO` | - |
| SizeView | `NO` | - |
| SizeStorage | `NO` | - |

## Recommended Mitigation Steps

I would add gaps to User, FeeConfig, RiskConfig and Oracle structs in `SizeStorage.sol`. For example:

```javascript
struct User {
    LoanOffer loanOffer;
    BorrowOffer borrowOffer;
    uint256 openingLimitBorrowCR;
    bool allCreditPositionsForSaleDisabled;

    // Storage gap for future potential upgrades
    uint256[45] private __gap;
}
```
