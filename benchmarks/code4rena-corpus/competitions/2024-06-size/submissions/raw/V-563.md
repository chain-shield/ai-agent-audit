# Vulnerability details

**Description:** The `setUserConfiguration` function is used to disable the `forsale` parameter of a creditPosition which is set to true when the creditPosition is created. The lender for a creditPosition who wants to update the creditPosition can be frontrunned by a lender who wants to buy the creditPosition.

Found in line [AccountingLibrary.sol#L118](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L118)

```solidity
   
            CreditPosition memory creditPosition =
                CreditPosition({lender: lender, credit: credit, debtPositionId: debtPositionId, forSale: true});
```

**Impact:** The original lender loses the credit position to another lender, Although this can only occur if a lender has an open sellCreditLimit, it is important to note that a lender can have other credit positions which they wish to sale, Hence opening a sellCreditLimit.

**Proof of Concept:**
- User A is a lender and he opens a creditPosition with a very profitable futureValue
- UserB is the frontrunner and he sees that user A has submitted a transaction to disable the `forSale` parameter
- User B can submit a transaction to buy the creditPosition from user A and get it to execute before user A transaction.

**Recommended Mitigation:** When creating a creditPosition set the `forSale` bool to `false`, the if a user wants to sell they can update to `true`
