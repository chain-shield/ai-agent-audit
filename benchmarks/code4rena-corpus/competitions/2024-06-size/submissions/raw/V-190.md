# Vulnerability details

## Impact
Upon liquidation, the protocol calculates the assigned collateral amount for the debt position that is being liquidated, this is done in `LoanLibrary::getDebtPositionAssignedCollateral`. That amount is being used to calculate the rewards of the liquidator and the protocol. This is being calculated by the following:
```
Math.mulDivDown(collateral, debtPosition.futureValue, debt);
```
Which is rounding down the amount. The protocol here favors the liquidated user instead of the liquidator and the protocol.

This affects the resulting liquidator and protocol liquidation rewards.

## Proof of Concept

1. Bob has multiple active loans from different lenders.
2. One of these loans becomes overdue.
3. Alice steps in to liquidate the overdue loan.
4. The `getDebtPositionAssignedCollateral` function calculates the "auto-assigned" collateral for that loan, rounding down the result.
5. Consequently, Alice and the protocol receive fewer profit, favoring the liquidated user.

## Recommended Mitigation Steps

Favor the liquidator when calculating the assigned collateral, i.e. round up in `getDebtPositionAssignedCollateral`. Something similar to:
```
return Math.min(collateral, Math.mulDivUp(collateral, debtPosition.futureValue, debt));
```
