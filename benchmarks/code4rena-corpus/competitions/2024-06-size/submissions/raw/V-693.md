# Vulnerability details


## Description
The `UpdateConfig.sol` contract for managing protocol configurations exhibits a significant limitation in the adjustment of the `crLiquidation` (Collateral Ratio for Liquidation) parameter. As per the current implementation, once the `crLiquidation` value is set, it can only be decreased and not increased. This restriction is enforced by a validation check that reverts any transaction where the new `crLiquidation` value is greater than the existing one. While this might initially help in maintaining a conservative approach to risk management by not allowing abrupt increases in the liquidation threshold, it also restricts the protocol's ability to respond adaptively to favorable market conditions where a higher `crLiquidation` might be justified.

### POC
The issue arises within the configuration update function, where the `crLiquidation` parameter is adjusted:
```solidity
else if (Strings.equal(params.key, "crLiquidation")) {
    //@audit admin won't be able to adjust crLiquidation once set higher
    if (params.value >= state.riskConfig.crLiquidation) {
        revert Errors.INVALID_COLLATERAL_RATIO(params.value);
    }
    state.riskConfig.crLiquidation = params.value;
}
```
This logic prevents the administrative adjustment of `crLiquidation` to a higher value once it has been set, which could potentially hinder the protocol's adaptability to improving market conditions.

## Impact
This limitation can adversely impact the protocol's flexibility and effectiveness in risk management:
- **Reduced Adaptability**: The inability to increase `crLiquidation` in response to changing market dynamics may prevent the protocol from optimizing its operations and capital efficiency.
- **Potential for Suboptimal Risk Management**: In scenarios where market conditions would justify a higher `crLiquidation` to safeguard against volatility, the protocol remains constrained by its lowest set point, potentially exposing it to higher risk or missed opportunities.

## Recommended Mitigation Steps
1. **Allow Bi-directional Adjustment**: Modify the validation logic to permit both increases and decreases of the `crLiquidation` value, subject to administrative review or automated guidelines based on market conditions.
