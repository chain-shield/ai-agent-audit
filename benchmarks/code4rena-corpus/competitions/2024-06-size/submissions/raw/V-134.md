# Vulnerability details

## Impact
lenders can exploit the self-liquidation mechanism to profit from liquidations even when the `debtInCollateralToken` does not exceed the total collateral allocated to the credit position. This violates the intended behavior of the self-liquidation process and can lead to unintended consequences, such as lenders taking advantage of the system and borrowers losing their collateral unfairly.

In the condition for allowing a self-liquidation. The current code checks if the collateral ratio of the borrower is below 100% (PERCENT) to allow a self-liquidation:
```solidity
if (state.collateralRatio(debtPosition.borrower) >= PERCENT) {
    revert Errors.LIQUIDATION_NOT_AT_LOSS(params.creditPositionId, state.collateralRatio(debtPosition.borrower));
}
```
However, according to the specification, the eligibility for a self-liquidation should be based on whether the `debtInCollateralToken` exceeds the total collateral allocated to the credit position. The current code considers the borrower's overall collateral ratio, which considers the total debt of the debt position, not just the `faceValue` of the debt position.

This means that a creditor could potentially self-liquidate and profit from the liquidation even if the `debtInCollateralToken` does not exceed the total collateral allocated to the credit position.

## Proof of Concept
1. Consider a scenario where a borrower has a debt position with the following values:
    - Debt Position ID: 1
    - Borrower: 0x5356...
    - Face Value: 1000 USDC
    - Future Value: 1100 USDC (assuming 10% interest)
    - Assigned Collateral: 1000 WETH (assuming a collateral ratio of 100%)

2. A lender has a credit position associated with the above debt position:
    - Credit Position ID: 1
    - Lender: 0x8193...
    - Debt Position ID: 1
    - Credit: 1000 USDC

3. The current market price of WETH is 1 USDC per WETH.
4. The lender calls the `selfLiquidate` function with the following parameters:
    - `params.creditPositionId`: 1

Inside the [`validateSelfLiquidate`#src/libraries/actions/SelfLiquidate.sol](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L34-L54)
```solidity
function validateSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external view {
    CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

    // validate creditPositionId
    if (!state.isCreditPositionSelfLiquidatable(params.creditPositionId)) {
        revert Errors.LOAN_NOT_SELF_LIQUIDATABLE(
            params.creditPositionId,
            state.collateralRatio(debtPosition.borrower),
            state.getLoanStatus(params.creditPositionId)
        );
    }
    if (state.collateralRatio(debtPosition.borrower) >= PERCENT) {
        revert Errors.LIQUIDATION_NOT_AT_LOSS(params.creditPositionId, state.collateralRatio(debtPosition.borrower));
    }

    // validate msg.sender
    if (msg.sender != creditPosition.lender) {
        revert Errors.LIQUIDATOR_IS_NOT_LENDER(msg.sender, creditPosition.lender);
    }
}
```
The `isCreditPositionSelfLiquidatable` function returns `true` because the borrower's collateral ratio is 100% below the liquidation threshold (assuming it's set to a value greater than 100%).

The condition `if (state.collateralRatio(debtPosition.borrower) >= PERCENT)` evaluates to `false` because the borrower's collateral ratio is 100%, which is not greater than or equal to `PERCENT` (assuming `PERCENT` is defined as 100%).

The `msg.sender` is the lender (0x8193...), so the validation passes. [src/libraries/actions/SelfLiquidate.sol#executeSelfLiquidate](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L59-L71)
```solidity
function executeSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external {
    emit Events.SelfLiquidate(params.creditPositionId);

    CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

    uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);

    // debt and credit reduction
    state.reduceDebtAndCredit(creditPosition.debtPositionId, params.creditPositionId, creditPosition.credit);

    // collateral transfer
    state.transferCollateral(debtPosition.borrower, creditPosition.lender, assignedCollateral);
}
```
The `assignedCollateral` is 1000 WETH, which is the total collateral allocated to the credit position.

The `reduceDebtAndCredit` function reduces the debt and credit by 1000 USDC.

The `transferCollateral` function transfers 1000 WETH from the borrower to the lender.

> After the self-liquidation, the lender receives 1000 WETH worth 1000 USDC at the current market price. However, the `debtInCollateralToken` (1100 USDC) exceeds the `assignedCollateral` (1000 WETH), meaning the lender profits from the liquidation even though the condition for a self-liquidation is not met according to the specification.

> This bug impacts lenders by allowing them to exploit the self-liquidation mechanism to profit from liquidations even when the `debtInCollateralToken` does not exceed the total collateral allocated to the credit position. This violates the self-liquidation process's intended behavior and can lead to unintended consequences, such as lenders taking advantage of the system and borrowers losing their collateral unfairly.

## Recommended Mitigation Steps
The `validateSelfLiquidate` function should be updated to compare the `debtInCollateralToken` with the `assignedCollateral` instead of relying on the borrower's overall collateral ratio.
