# Vulnerability details

## Description
To summarize the bug, basically the amount that is given to the `validateVariablePoolHasEnoughLiquidity()` to check if there are enough liquidity on aave is not the same between the two functions. In `sellCreditMarket()` the amount checked for **doesn't include the protocol fees**, in contrast the  amount checked for in the `buyCreditMarket()` where the amount passed to the `validateVariablePoolHasEnoughLiquidity()` includes the fee, this breaks a system invariant and leads to Dos on `buyCreditMarket()`.
As we can see in the `executeBuyCreditMarket()`, the `cashAmountIn` variable already includes the Protocol Fees and it i the amount returned from the `executeBuyCreditMarket()`
```solidity
function executeBuyCreditMarket(
        State storage state,
        BuyCreditMarketParams memory params
@>    ) external returns (uint256 cashAmountIn) {
@@@@
        state.data.borrowAToken.transferFrom(
            msg.sender,
            borrower,
@>            cashAmountIn - fees
        );
        state.data.borrowAToken.transferFrom(
            msg.sender,
            state.feeConfig.feeRecipient,
            fees
        );
    }
```
and this is how this variable is handled in `buyCreditMarket()` in `size.sol`


## Recomendation
To fix this we simply remove fees from cashAmountIn in `executeBuyCreditMarket()` before it is returned to the `buyCreditMarket()`
```diff
function executeBuyCreditMarket(
        State storage state,
        BuyCreditMarketParams memory params
    ) external returns (uint256 cashAmountIn) {
@@@@
+       cashAmountIn = cashAmountIn - fees
        state.data.borrowAToken.transferFrom(
            msg.sender,
            borrower,
-            cashAmountIn - fees
+            cashAmountIn
        );
        state.data.borrowAToken.transferFrom(
            msg.sender,
            state.feeConfig.feeRecipient,
            fees
        );
    }
```
