# Vulnerability details

## Impact
Users can end up with unwanted debt because there is no way to specify whether they want to do an early exit or a simple borrow.

## Proof of Concept
Whenever a user has a borrow offer set up, a lender can decide to lend to him by either using his credit position (early exit) or by doing a simple borrow. The lender specifies that by either specifying `creditPositionId` as `RESERVED_ID` (simple borrow) or as an actual ID of a credit position.

The issue is that the user who has a borrow offer set up does not have a way to specify whether he wants to do an early exit from his credit position or if he wants to do a simple borrow. Imagine the following 2 scenarios:

Scenario 1:
Bob has a credit position he wants to exit and he sets up a borrow offer. He has no collateral so he doesn't allow lenders to lend to him as a simple borrow. However, he sees that there is a liquidatable position and decides to liquidate it to earn some rewards. He liquidates it, gets collateral tokens as rewards and a lender uses his borrow offer to lend to him using his collateral (a simple borrow using `RESERVED_ID`). Now he has unwanted debt that he has to repay with interest.

Scenario 2:
A very similar scenario however instead of the user liquidating someone else, he self-liquidates himself and gains collateral that someone uses to lend to him.

There is also a very simple third scenario where the user has a borrow offer and also has collateral however if a user has a borrow offer and has deposited collateral into the system, then that can definitely be understood as the user wanting to do a simple borrow instead of an early exit.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Include a parameter in the borrow offer that allows borrowers to specify whether they want to do an early exit or a simple borrow.
