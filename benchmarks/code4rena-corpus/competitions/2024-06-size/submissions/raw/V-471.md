# Vulnerability details

## Impact
look at this:
```
   /// @notice Returns the current liquidity index of the variable pool
    /// @return The current liquidity index of the variable pool
    function liquidityIndex() public view returns (uint256) {
        return variablePool.getReserveNormalizedIncome(address(underlyingToken));
    }
```
The liquidityIndex value is based on ``liquidityIndex`` of underlyingToken in the AAVE pool.

Then what the issue?

Now, let's examine this:

```
  function executeRepay(State storage state, RepayParams calldata params) external {
        DebtPosition storage debtPosition = state.getDebtPosition(params.debtPositionId);

        state.data.borrowAToken.transferFrom(msg.sender, address(this), debtPosition.futureValue);
        debtPosition.liquidityIndexAtRepayment = state.data.borrowAToken.liquidityIndex();
        state.repayDebt(params.debtPositionId, debtPosition.futureValue);

        emit Events.Repay(params.debtPositionId);
    }
```
When the borrower repays a debt, the ``liquidityIndexAtRepayment`` variable will be initialized with the value of ``liquidityIndex`` at that time.

and then look at this:
```
  function executeClaim(State storage state, ClaimParams calldata params) external {
        CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
        DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

        uint256 claimAmount = Math.mulDivDown(
            creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
        );
        state.reduceCredit(params.creditPositionId, creditPosition.credit);
        state.data.borrowAToken.transferFrom(address(this), creditPosition.lender, claimAmount);

        emit Events.Claim(params.creditPositionId, creditPosition.debtPositionId);
    }
```
The variable ``claimAmount`` is calculated using ``creditPosition.credit, state.data.borrowAToken.liquidityIndex(), and debtPosition.liquidityIndexAtRepayment``. And look at that, there is no calculate how much ``borrowAToken`` in contract.

##### Q: So, What happen if ``state.data.borrowAToken.liquidityIndex()`` is higher than ``creditPosition.credit`` and ``debtPosition.liquidityIndexAtRepayment``?

##### A: The ``claimAmount`` will increase based on how much higher the ``liquidityIndex`` is compared to ``debtPosition.liquidityIndexAtRepayment``. 


So, an attacker can take advantage of this by depositing USDC directly into the AAVE pool to increase the ``liquidityIndex`` and then performing a ``claim``.

As a result, the attacker gets an increased ``borrowAToken`` from the funds repaid by others which is in the contract.

And other lenders cannot "claim" the funds they fund because there is no ``borrowAToken`` in the contract.

## Proof of Concept
Attack scheme:
- The attacker has two accounts: one as a lender and one as a borrower.
- They make loans and then repay them.
- After repaying, the attacker performs a ``supply`` on AAVE to increase the ``liquidityIndex``.
- Then the attacker performs a claim, which results in the attacker getting an incremental value of the ``borrowAToken`` due to the increased ``liquidityIndex``.
- As a result, the attacker ends up owning ``borrowAToken`` from the refunds of others in the contract.
- Thus, other lenders cannot "claim" the funds they fund because there is no ``borrowAToken`` in the contract.
