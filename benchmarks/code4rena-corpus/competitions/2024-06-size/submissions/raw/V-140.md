# Vulnerability details

The initial state of the protocol can be reInitialized
In the initialize contract the ```executeInitialize``` function is responsible for setting up the initial configuration of the Size protocol. It takes several parameters related to different of the protocols configuration:
- Fee config
- Risk config
- Oracle
- Data config

```
 function executeInitialize(
        State storage state,
        InitializeFeeConfigParams memory f,
        InitializeRiskConfigParams memory r,
        InitializeOracleParams memory o,
        InitializeDataParams memory d
    ) external {
        executeInitializeFeeConfig(state, f);
        executeInitializeRiskConfig(state, r);
        executeInitializeOracle(state, o);
        executeInitializeData(state, d);
        emit Events.Initialize(f, r, o, d);
    }
```

However, the same address can be used to reinitialize the configuration. From what I understand, initialization is a one-time setup to configure the initial state and parameters of the contract, but this function isn't doing that.

There may be changes in configurations that could impact the integrity or expected behavior of the contract and its initial state set during the first initialization.

This contract was used in the [Size.sol](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L93) contract, employing the initialized modifier. However, the bug could still occur because it's external and in the main Initialize contract if the owner, with malicious intent, resets these configurations.


## Tools Used
Manual review

## Recommended Mitigation Steps
There should be a mechanism to prevent reinitialization execution in the Initialize contract, probably a initializer modifier to check if the system has be initialized or not.

But before doing this, there will be need for you to always validate the initialize functions set before calling executeInitialize fucntion.
