# Vulnerability details

## Impact

According to documentation, when there is fractionalization of the credit, a fragmentation fee needs to be paid in the amount of 5e6 or 5 USDC. According to the documentation, the fee is fixed fee denominated in USDC taken upon partial exit by a lender. 

Depending on whether sellCreditmarket or buyCreditMarket there is a discrepancy since in some situations the fee is taken from the lender, and in others from the borrower.

## Proof of Concept

Let's look at two examples when it comes to the fractionalization of credit and the payment of the fragmentation fee, first the `buyCreditMarket`.

Let's imagine that the lender who is buying the credit from an already existing credit position (fulfilling a sellCreditLimit order) has set the `exactAmountIn` flag to `false`, so then `getCashAmountIn` will be invoked:

```
     function getCashAmountIn(
        State storage state,
        uint256 creditAmountOut,
        uint256 maxCredit,
        uint256 ratePerTenor,
        uint256 tenor
    ) internal view returns (uint256 cashAmountIn, uint256 fees) {
        if (creditAmountOut == maxCredit) {
            // no credit fractionalization


            cashAmountIn = Math.mulDivUp(maxCredit, PERCENT, PERCENT + ratePerTenor);
            fees = getSwapFee(state, cashAmountIn, tenor);
        } else if (creditAmountOut < maxCredit) {
            // credit fractionalization


            uint256 netCashAmountIn = Math.mulDivUp(creditAmountOut, PERCENT, PERCENT + ratePerTenor);
            cashAmountIn = netCashAmountIn + state.feeConfig.fragmentationFee;


            fees = getSwapFee(state, netCashAmountIn, tenor) + state.feeConfig.fragmentationFee;
        } else {
            revert Errors.NOT_ENOUGH_CREDIT(creditAmountOut, maxCredit);
        }


        if (fees > cashAmountIn) {
            revert Errors.NOT_ENOUGH_CASH(cashAmountIn, fees);
        }
    }
```

- From the logic above, we can see that the fragmentation fee is added on top of the net cash amount, so that if the `cashAmountIn` is 1000e6 for example, now it will be 1005e6, so when the following logic takes place:

```
        state.data.borrowAToken.transferFrom(msg.sender, borrower, cashAmountIn - fees);
        state.data.borrowAToken.transferFrom(msg.sender, state.feeConfig.feeRecipient, fees);
```
The fee is not taken out of the amount that should be received by the borrower and upon which the interest rate is calculated, but rather, the fee was added to that amount and later subtracted above so that the lender (who is buying the credit) pays the fee. And the swap fee is subtracted from the amount which should be received by the borrower (i.e. the borrower pays for the swap fee, as it should be as they are the receiver of the funds).

Conclusion: Lender pays the fragmentation fee.


When it comes to `sellCreditMarket`, the following scenario takes place, a borrower which would like to sell a part of their credit position calls `sellCreditMarket` in order to fulfill a `buyCreditLimit` order, for the sake of the example, let say that they've set their `exactAmountIn` flag to `true`:

```
        if (params.exactAmountIn) {
            creditAmountIn = params.amount;


            (cashAmountOut, fees) = state.getCashAmountOut({
                creditAmountIn: creditAmountIn,
                maxCredit: params.creditPositionId == RESERVED_ID ? creditAmountIn : creditPosition.credit,
                ratePerTenor: ratePerTenor,
                tenor: tenor
            });
```

Following the above, `getCashAmountOut` will be called:

```
    function getCashAmountOut(
        State storage state,
        uint256 creditAmountIn,
        uint256 maxCredit,
        uint256 ratePerTenor,
        uint256 tenor
    ) internal view returns (uint256 cashAmountOut, uint256 fees) {
        uint256 maxCashAmountOut = Math.mulDivDown(creditAmountIn, PERCENT, PERCENT + ratePerTenor);


        if (creditAmountIn == maxCredit) {
            // no credit fractionalization


            fees = getSwapFee(state, maxCashAmountOut, tenor);


            if (fees > maxCashAmountOut) {
                revert Errors.NOT_ENOUGH_CASH(maxCashAmountOut, fees);
            }


            cashAmountOut = maxCashAmountOut - fees;
        } else if (creditAmountIn < maxCredit) {
            // credit fractionalization


            fees = getSwapFee(state, maxCashAmountOut, tenor) + state.feeConfig.fragmentationFee;


            if (fees > maxCashAmountOut) {
                revert Errors.NOT_ENOUGH_CASH(maxCashAmountOut, fees);
            }


            cashAmountOut = maxCashAmountOut - fees;
        } else {
            revert Errors.NOT_ENOUGH_CREDIT(creditAmountIn, maxCredit);
        }
    }
```

Since the `cashAmountOut` is the amount that the user will receive, we can see that both the swap fees and the fragmentation fee are taken out of it, i.e. both of those fees will be paid for by the borrower who is selling their credit position:

```
        state.data.borrowAToken.transferFrom(params.lender, msg.sender, cashAmountOut);
        state.data.borrowAToken.transferFrom(params.lender, state.feeConfig.feeRecipient, fees);
```

This creates an inconsistency in terms of the fee payment, depending on which type of an order users choose they can either pay more or less fees, which should incline lenders to lean towards one type of orders, and borrowers to the other.
