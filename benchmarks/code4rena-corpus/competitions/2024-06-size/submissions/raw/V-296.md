# Vulnerability details

## Impact 
As it is the case, it is not possible for users to deposit native Eth and USDC in the same transaction using a multicall, as it will always revert.
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Deposit.sol#L64-L88
## Proof of Concept

Basically, the root cause of the bug, is that if msg.value is greater than 0, the from variable will be set to address(this), which is the address of the contract, and in this case the function validateDeposit() used to check the usdc deposit and will revert. This is the line that will cause the rever in validateDeposit()
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Deposit.sol#L36-L52
