# Vulnerability details

## Impact
`Payable` modifier is used to allow a function to receive Ether. Without this modifier, if you attempt to send Ether to a function, the transaction will be rejected and will fail.

Only functions that wants to receive Ether and account it should have payable modifier. But the size contract has the payable modifier attached to all most all the external functions of the contract, even though they dont process the received ether.

This is risky as when the caller sends funds, the processing logic should account the received ether and any excess funds received should be returned back to the caller.

But, all the functions except `deposit()` does not handle the received ether. If any ether was passed, it will get deposited into the contract and remain there as the funds are not being refunded if not used.


## Proof of Concept
All the functions with payable modifier except the `deposit()` function falls in the scope of this vulnerability.

```solidity
 function withdraw(WithdrawParams calldata params) external payable override(ISize) whenNotPaused {
```
## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove payable modifier for all the functions except deposit so that native tokens cannot be passed by the caller.
