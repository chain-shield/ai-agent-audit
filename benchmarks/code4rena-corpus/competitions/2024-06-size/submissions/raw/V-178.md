# Vulnerability details

## Impact
The logic for calculating `maxCashAmountOut` when `exactAmountIn` is false (borrower specifies cash amount).
[executeSellCreditMarket#173-175](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L173-L175)
```solidity
maxCashAmountOut: params.creditPositionId == RESERVED_ID
                    ? cashAmountOut
                    : Math.mulDivDown(creditPosition.credit, PERCENT - state.getSwapFeePercent(tenor), PERCENT + ratePerTenor),
```
* **`params.creditPositionId == RESERVED_ID`**: This branch is for new borrows and correctly sets `maxCashAmountOut` to the input `cashAmountOut`.
* **The else branch**: This is for lender exits (selling existing credit positions). The calculation aims to determine the maximum cash obtainable from selling `creditPosition.credit`, considering the swap fee and interest.
     - **The issue**: It uses `creditPosition.credit` directly, which represents the total credit of the position. However, in a lender exit, the user might want to sell only a portion of their credit position.

This prevents lenders from partially exiting their positions using the `SellCreditMarket` function when specifying the cash amount. They can only exit the entire position or nothing when using this flow.

**Example Scenario:**
* Alice is a lender with a CreditPosition of 1000 USDC.
* Bob wants to borrow 200 USDC.
* Alice wants to sell only 200 USDC of her CreditPosition.

**Current Behavior:**
* Alice calls `SellCreditMarket` with `cashAmountOut = 200 USDC` and her `creditPositionId`.
* The code calculates `maxCashAmountOut` based on her entire `creditPosition.credit` (1000 USDC), resulting in a much higher value than 200 USDC.
* The `getCreditAmountIn` function reverts because `cashAmountOut` (200 USDC) is lower than the incorrectly calculated `maxCashAmountOut`.

**Intended Behavior:**
* Alice should be able to specify `cashAmountOut = 200 USDC` to sell only a portion of her credit position.
* The code should calculate `maxCashAmountOut` based on the desired 200 USDC, considering fees and interest.
* The transaction should succeed, allowing Alice to partially exit her position.

## Proof of Concept
Let's assume:
* Alice has a `CreditPosition` of 1000 USDC (`creditPosition.credit = 1000e6`).
* She wants to sell 200 USDC (`cashAmountOut = 200e6`).
* `PERCENT = 1e18`
* `state.getSwapFeePercent(tenor) = 0.01e18` (1% fee)
* `ratePerTenor = 0.02e18` (2% interest)

**Walkthrough**
1. `SellCreditMarket` is called: Alice calls `SellCreditMarket` with her `creditPositionId` and `cashAmountOut = 200e6`.
2. `maxCashAmountOut` Calculation:
     - Since `params.creditPositionId` is not `RESERVED_ID`, the else branch is executed.
     - `maxCashAmountOut` is calculated as
       ```solidity
       Math.mulDivDown(1000e6, 1e18 - 0.01e18, 1e18 + 0.02e18) ≈ 970.87e6
       ```
* `getCreditAmountIn` Validation:
     - `getCreditAmountIn` is called with `cashAmountOut = 200e6` and `maxCashAmountOut ≈ 970.87e6`.
     - The function reverts because `cashAmountOut` (200e6) is lower than `maxCashAmountOut` (970.87e6), even though Alice has enough credit to cover the desired cash amount.

## Recommended Mitigation Steps
Instead of using `creditPosition.credit`, the code should use the desired amount of credit the lender wants to sell. This could be a new parameter or derived from the input `cashAmountOut` by reverse-calculating the corresponding credit amount.
