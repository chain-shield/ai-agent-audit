# Vulnerability details

## Description
`block.timestamp`s are used to calculate *tenor* values, *deadlines* and *stale prices*. This value can be known in advance and manipulated by bots and malicious validators. The `tenor` values are generated by subtracting the `block.timestamp` from the debt position due date, while `deadline`s are calculated by adding a `block.timestamp` to a `tenor`.

## Impact

A MEV bot or a miner can manipulate the `block.timestamp` to slightly increase or decrease tenor and deadline values. This can lead to the following issues:

1. **Validation manipulations**
   - The error `TENOR_OUT_OF_RANGE` can be easily induced during a *compensation validation* [L53](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Compensate.sol#L57) and *liquidation validation* [L66](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L66).
        ```js
        53 uint256 tenor = debtPositionToRepay.dueDate - block.timestamp;

           // validate tenor
           if (tenor < state.riskConfig.minTenor || tenor > state.riskConfig.maxTenor) {
                        revert Errors.TENOR_OUT_OF_RANGE(tenor, state.riskConfig.minTenor, state.riskConfig.maxTenor);
                    }
        ```
   -  MEV bots can also artificially raise `PAST_DEADLINE` during the validation of *sell/buy credit markets* [L96](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L96), [L103](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L103) and *liquidations* [L77](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L77). Additionally, a malicious miner can simulate the status of a loan to *overdue* by altering the the deadline value in `LoanLibrary::getLoanStatus` [L135](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L135) over a previously altered `debtPosition.dueDate` value (see following state inconsistencies).
   
        ```js
       135  } else if (block.timestamp > debtPosition.dueDate) {
        ```
2. **Calculation manipulations**
   - *Tenor manipulation* can cause the annual percentage rates (APR) to be altered in lines `BuyCreditMarket::validateBuyCreditMarket` [L80](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L80), [L141](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L141) and `LiquidateWithReplacement::executeLiquidateWithReplacement` [L129](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L129). Unexpected borrow/loan offer rates can also be generated from an incorrect tenor in line `SellCreditMarket::executeSellCreditMarket` [L144](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L144).
   
        ```js
        80    tenor = debtPosition.dueDate - block.timestamp;
        ```
   - *Deadlines adjustments*. Deadlines are calculated by adding the `block.timestamp` to the previously determined `tenor`. This allows extenal actor to further alter the deadline value, introducing another layer of potential exploitation. This can happen in `BuyCreditMarket::validateBuyCreditMarket`[L185](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L185) and `SellCreditMarket::executeSellCreditMarket`[L190](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L190). Here, an incorrect `dueDate` value is passed to the method `createDebtAndCreditPositions` and a `debtPosition` with a wrong due date will be created. The tenor then will be validated on that incorrect value, which can influence the outcome of further validations.

## Recommended Mitigation Steps

To ensure the integrity of time-sensitive operations, consider including a Time Drift Allowance for validations, which defines a permissible range for timestamp variations. Alternatively, information can also be determined off-chain or specified by the caller.

Example from `SellCreditMarket::validateSellCreditMarket` [L103](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L103):

```diff
+if (params.deadline < block.timestamp + ALLOWED_TIME_DRIFT)
+   revert Errors.PAST_DEADLINE(params.deadline);
+if (params.deadline < block.timestamp - ALLOWED_TIME_DRIFT)
-if (params.deadline < block.timestamp) {
    revert Errors.PAST_DEADLINE(params.deadline);
}
```
