# Vulnerability details

## Impact
The `sellCreditLimit` function in the Size protocol allows addresses blacklisted by USDC to create borrow offers, effectively initiating the process of borrowing USDC. This vulnerability stems from the function's lack of blacklist checks and the protocol's use of internal accounting and wrapper tokens, which do not enforce the blacklist restrictions present in the underlying USDC token contract.

This vulnerability undermines USDC's blacklist feature, which is crucial for regulatory compliance and anti-money laundering efforts. By allowing blacklisted addresses to create borrow offers, the Size protocol provides a pathway for these addresses to potentially access and use USDC, circumventing intended restrictions. This could facilitate illicit financial activities and expose the protocol to significant regulatory and legal risks.

This vulnerability allows blacklisted addresses to acquire credit positions within the Size protocol, effectively circumventing token-level (e.g., USDC) blacklist restrictions. As a result:

Blacklisted addresses can receive and hold credit positions.

Blacklisted addresses can potentially withdraw USDC funds from the protocol.

This could facilitate illicit financial activities by providing a way to move restricted funds.

The protocol may be in violation of compliance requirements related to the underlying tokens.

This undermines the effectiveness of compliance measures implemented at the token level, exposing the protocol to significant regulatory, legal, and reputational risks.

The protocol could also face positions that cannot be liquidated when sending the remaining amount of collateral back to the blacklisted address(during liquidations) as the address may not be able to be to be sent or send USDC. This could lead to bad debt or insolvency.

This test shows that a blacklisted address can:

1. Successfully call sellCreditLimit to create a borrow offer
2. Have this offer matched by a lender
3. Receive borrowed USDC in the Size protocol
4. Subsequently withdraw the USDC

The root cause of this vulnerability is that the `sellCreditLimit` function does not check if the caller is blacklisted in the USDC contract. This allows blacklisted addresses to initiate the borrowing process, which, when combined with the protocol's internal accounting, leads to a complete bypass of USDC's blacklist restrictions.

## Recommended Mitigation Steps
Implement blacklist checks in the `sellCreditLimit` function for USDC and other tokens that may have blacklist functionality.

Before allowing an address to create a borrow offer, query the USDC contract to check if the address is blacklisted.

Revert the transaction if the address is found to be blacklisted.
