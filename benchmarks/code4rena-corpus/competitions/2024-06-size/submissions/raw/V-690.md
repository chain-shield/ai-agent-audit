# Vulnerability details

## Impact
When specifying `cashAmountOut` during selling credit if it is equal to `maxCashAmountOutFragmentation` then the tx will revert and the user won't be able to sell credit
## Proof of Concept
In `SellCreditMarket` there is a bool flag to determine whether the input amount is the credit amount or if the user has specified the cash amount they want by setting the var `exactAmountIn` to true or false

now the issue is when this bool is false then `getCreditAmountIn` method is called which has this following natspec comment
```
// for maxCashAmountOutFragmentation < amountOut < maxCashAmountOut we are in an inconsistent situation
```
Which states the `maxCashAmountOutFragmentation == cashAmountOut` is not a inconsistent state and it should be considered as a valid state but it is not accounted for and hence the transaction will revert if that condition occurs

`maxCashAmountOutFragmentation` when non-zero is `maxCashAmountOut - state.feeConfig.fragmentationFee` & `cashAmountOut` as will <= `maxCashAmountOut` hence there is a possibility that it is equal to `maxCashAmountOutFragmentation` depending on the `state.feeConfig.fragmentationFee` value so this condition should be handled correctly.

## Tools Used
Manual Review
## Recommended Mitigation Steps
the condition `maxCashAmountOutFragmentation == cashAmountOut` should be handled by the if-else block to handle this scenario & prevent DOS
