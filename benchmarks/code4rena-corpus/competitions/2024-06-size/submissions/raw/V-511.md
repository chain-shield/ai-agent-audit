# Vulnerability details

## Impact
The `liquidateWithReplacement` function allows transferring debt positions to USDC blacklisted addresses, and these addresses can subsequently liquidate positions and withdraw funds. This allows blacklisted addresses to interact with the protocol and potentially circumvent sanctions or restrictions. 

This vulnerability severely undermines the effectiveness of compliance measures implemented at the token level (e.g., USDC blacklists). It allows sanctioned or restricted entities to:

Receive and hold USDC positions within the protocol

Participate in liquidations to receive USDC

Withdraw funds, effectively bypassing the underlying token's blacklist

This exposes the protocol to significant legal and regulatory risks, as it provides a mechanism for blacklisted entities to transact and move funds in ways that should be restricted.

The protocol could also face positions that cannot be liquidated when sending the remaining amount of collateral USDC back to the blacklisted address(during liquidations) as the address may not be able to be to be sent USDC. This could lead to bad debt or insolvency.

## Recommended Mitigation Steps
Implement blacklist checks in key functions, particularly:
1. `liquidateWithReplacement`: Check if the new borrower is blacklisted before transferring the debt position.

2. `liquidate`: Ensure the liquidator and the borrower are not blacklisted.

3. `withdraw`: Verify the recipient is not blacklisted before allowing withdrawals.


Add a global blacklist check function/modifier that integrates with the underlying token's (USDC) blacklist and use this function/modifier in all critical operations.
