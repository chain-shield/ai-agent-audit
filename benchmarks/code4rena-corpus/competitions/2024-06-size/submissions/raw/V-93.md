# Vulnerability details

## Impact
Some users will be required to borrow a higher amount of tokens than others. For example, with an APR of 20%, some users will be required to borrow 20% more tokens than others otherwise they wouldn't be able to borrow.

## Proof of Concept
Upon borrowing in `SellCreditMarket`, users specify an `amount` parameter. This parameter would either equal the amount of credits they have to pay to the lender or the amount of tokens they will receive for the borrow (depending on the `exactAmountIn` boolean parameter). Then, upon borrowing, we have this __require__:
```solidity
 if (params.amount < state.riskConfig.minimumCreditBorrowAToken) {
            revert Errors.CREDIT_LOWER_THAN_MINIMUM_CREDIT(params.amount, state.riskConfig.minimumCreditBorrowAToken);
        }

```
If the `amount` parameter is lower than the configured `minimumCreditBorrowAToken`, then the transaction will revert. The issue here is that the `amount` parameter doesn't necessarily equal the credit amount as explained above.

For example, if a user has specified `exactAmountIn` as false, then the `amount` parameter will equal `cashAmountOut` (the tokens he will receive). If the `tenor` is 1 year and the APR is 20% and he has specified 1000 tokens as the `amount` parameter and `exactAmountIn` as false, then he would have to repay 1200 tokens (this is the credit amount, also excluding fees for simplicity purposes). With that information, if the `minimumCreditBorrowAToken` is equal to 1200, this would have to successfully pass as the credit is also 1200. However, since the __require__ statement checks the `amount` parameter the same way regardless of the `exactAmountIn` parameter, then the scenario above would revert as the `amount` parameter is 1000. The user would have to borrow 20% more than the actual minimum and the credit amount would now equal 1440.

Any user who has specified the `amount` parameter as cash instead of credit, will have to pay more than the minimum.

A similar situation is also possible in `BuyCreditMarket` (lending).
## Tools Used
Manual Review
## Recommended Mitigation Steps
There are 2 options. Either incorporate the `exactAmountIn` boolean into the __require__ and properly check the credit amount or another option is to just remove that __require__ statement as the minimum is checked again during the `executeSellCreditMarket()` execution.
