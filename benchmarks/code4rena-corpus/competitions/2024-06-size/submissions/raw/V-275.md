# Vulnerability details

## Impact
When the searched value is not found in the array, the function should return the indices of the largest element less than or equal to the value and the smallest element greater than or equal to the value. However, due to the bug in the return statement, the function incorrectly returns `(high, low)` instead of `(low, high)`, can lead to incorrect results when using the `binarySearch` function in other parts of the codebase.
[Math.sol#L51-L68](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/Math.sol#L51-L68)
```solidity
function binarySearch(uint256[] memory array, uint256 value) internal pure returns (uint256 low, uint256 high) {
    low = 0;
    high = array.length - 1;
    if (value < array[low] || value > array[high]) {
        return (type(uint256).max, type(uint256).max);
    }
    while (low <= high) {
        uint256 mid = (low + high) / 2;
        if (array[mid] == value) {
            return (mid, mid);
        } else if (array[mid] < value) {
            low = mid + 1;
        } else {
            high = mid - 1;
        }
    }
    return (high, low); // This should be (low, high)
}
```
## Proof of Concept
The `RESERVED_ID` is used to represent a special case where a credit/debt pair is created and executed simultaneously. This is crucial for operations like lending, borrowing, or compensating without specifying an existing credit position ID.
```solidity
   buyCreditMarket(RESERVED_ID);  // For lending
   sellCreditMarket(RESERVED_ID); // For borrowing
   compensate(RESERVED_ID);       // For compensating
```
This functionality is explained in the FAQ section of the technical documentation from `docs.size.credit`.

The self-liquidation mechanism allows a lender to cancel an amount of debt equivalent to their credit in exchange for a proportional amount of collateral from the borrower reserves. This process is detailed in the `3.5-liquidations` documentation.
```
   lender forgives amount of credit = new debt
   receives collateral pro rata = new collateral
```
This mechanism is designed to limit the loss when the price of the collateral drops quickly, providing a proactive option for lenders.

The [Multicall.sol#L33-L35](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/Multicall.sol#L33-L35) library allows for multiple delegate calls within a single transaction, which is crucial for operations that need to perform several actions atomically. This is important in scenarios where state consistency must be maintained across multiple function calls.
```solidity
   for (uint i = 0; i < data.length; i++) {
       results[i] = Address.functionDelegateCall(address(this), data[i]);
   }
```
The claim functionality allows any user to claim on behalf of a lender, which is crucial for ensuring that lenders can earn yield from platforms like Aave even if they do not claim their repayments immediately.
```solidity
claim will only do an internal balance change from address(this) to creditPosition.lender
```
This is explained in the FAQ section, highlighting that the internal mechanics ensure that the lender's position and yield potential remain unaffected by the timing of the claim

**Proof of the bug**
- Consider an example array: `[10, 20, 30, 40, 50]`
    - If we search for the value `25`, which is not present in the array, the expected return values should be `(low = 1, high = 2)` because:
    - The largest element less than or equal to `25` is `20` at index `1`.
- The smallest element greater than or equal to `25` is `30` at index `2`.
- However, due to the bug in the return statement, the function will incorrectly return `(high = 1, low = 2)`.

**Impact on other parts of the codebase**

The `binarySearch` function is used in the [YieldCurveLibrary.sol#L124](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/YieldCurveLibrary.sol#L124) file to find the indices of the tenors in the yield curve.
```solidity
(uint256 low, uint256 high) = Math.binarySearch(curveRelativeTime.tenors, tenor);
```
If the `binarySearch` function returns incorrect indices, it can lead to incorrect calculations and results in the `YieldCurveLibrary`.

## Recommended Mitigation Steps
The correct return statement should be `return (low, high);` to reflect the intended functionality described in the documentation. This change ensures that the function returns the correct indices for the elements surrounding the search value when the exact value is not found in the array.
