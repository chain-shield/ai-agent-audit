# Vulnerability details

## Impact
`validateBorrowATokenIncreaseLteDebtTokenDecrease` function calculates the decrease in debt token supply and stores it in a variable named `debtATokenSupplyDecrease`. However, when comparing it with the increase in borrowing "aToken" supply, the error message uses the same variable name, `debtATokenSupplyDecrease.` This is incorrect because the function is comparing the increase in borrow "aToken" supply with the decrease in debt token supply, not the decrease in debt aToken supply.

## Proof of Concept
   1. CapsLibrary.sol: https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/CapsLibrary.sol#L19-L44

   2. Errors.sol: https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/Errors.sol

Let's consider an example scenario:

Suppose we have the following values.
    - `borrowATokenSupplyBefore` = 1000
    - `debtTokenSupplyBefore` = 800
    - `borrowATokenSupplyAfter` = 1200
    - `debtTokenSupplyAfter` = 700

In this case, the `validateBorrowATokenIncreaseLteDebtTokenDecrease` function will calculate:
    - `borrowATokenSupplyIncrease` = 1200 - 1000 = 200
    - `debtTokenSupplyDecrease` = 800 - 700 = 100

The function will compare `borrowATokenSupplyIncrease` (200) with `debtTokenSupplyDecrease` (100). Since 200 > 100, it means the increase in borrow aToken supply exceeds the decrease in debt token supply. Therefore, the function will revert with the `BORROW_ATOKEN_INCREASE_EXCEEDS_DEBT_TOKEN_DECREASE` error.

However, due to the bug in the variable naming, the error message will incorrectly display `debtATokenSupplyDecrease` instead of `debtTokenSupplyDecrease`, which can lead to confusion.

Here's how the error message looks with the incorrect variable name: https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/CapsLibrary.sol#L37-L39
```solidity
revert Errors.BORROW_ATOKEN_INCREASE_EXCEEDS_DEBT_TOKEN_DECREASE(
    borrowATokenSupplyIncrease, debtATokenSupplyDecrease
);
```
And here's how it should look with the corrected variable name:
```solidity
revert Errors.BORROW_ATOKEN_INCREASE_EXCEEDS_DEBT_TOKEN_DECREASE(
    borrowATokenSupplyIncrease, debtTokenSupplyDecrease
);
```
The error message will accurately reflect the comparison being made between the increase in borrow `aToken` supply and the decrease in debt token supply.

## Recommended Mitigation Steps
The variable name should be changed to `debtTokenSupplyDecrease` to accurately reflect what it represents. The error message should also be updated accordingly.
```solidity
uint256 debtTokenSupplyDecrease =
    debtTokenSupplyBefore > debtTokenSupplyAfter ? debtTokenSupplyBefore - debtTokenSupplyAfter : 0;

// and the supply increase is greater than the debt reduction
if (borrowATokenSupplyIncrease > debtTokenSupplyDecrease) {
    // revert
    revert Errors.BORROW_ATOKEN_INCREASE_EXCEEDS_DEBT_TOKEN_DECREASE(
        borrowATokenSupplyIncrease, debtTokenSupplyDecrease
    );
}
```
