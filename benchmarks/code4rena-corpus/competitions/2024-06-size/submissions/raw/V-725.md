# Vulnerability details

## Impact
Lenders can claim more tokens with the help of flash loans because of use of liquidity index.

## Proof of Concept
In `Claim.sol::executeClaim` , lenders can use flash loan to `deposit` right before claiming to increase the liquidity index of the pool. The increased liquidityIndex will result in `claimAmount` to increase and hence increased tokens can be claimed.
```solidity
    function executeClaim(State storage state, ClaimParams calldata params) external {
        CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
        DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

@>      uint256 claimAmount = Math.mulDivDown(
            creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
        );  //liquidityIndex can be increased by depositing right before claiming
        state.reduceCredit(params.creditPositionId, creditPosition.credit);
        state.data.borrowAToken.transferFrom(address(this), creditPosition.lender, claimAmount);

        emit Events.Claim(params.creditPositionId, creditPosition.debtPositionId);
    }
```
The process flow will be something like this :-
1. The borrower has repaid the loan and liquidity index at that time is captured (liquidityIndexAtRepayment).
2. The lender now deposits large amounts to the protocol (flashLoan) using `Size.sol::Deposit` function. This increases the liquidityIndex of the pool. 
3. The lender now calls `Size.sol::claim` which in turn calls `Claim.sol::executeClaim`. Since the liquidityIndex has now increased, the value of the following statement (claimAmount) will be far greater
`uint256 claimAmount = Math.mulDivDown(
            creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
        );`
4. Now value of claimAmount is very high and proportionate number of `BorrowATokens` will be transferred to the lender.
5. The lender now simply calls `Size.sol::withdraw` and repays his loan getting a large number of tokens in profit exploiting the protocol.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Introduce time delay check in deposit and withdraw functions.
