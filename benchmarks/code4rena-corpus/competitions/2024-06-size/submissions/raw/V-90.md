# Vulnerability details

## Impact
Using balance of Eth in the contract as a guard for multi-call is not effective. The multi-call transaction will only revert. There are two issues.

a) Since the Multi-call can potentially batch two deposits together, the ether passed as payable amount will show as balance for the context of the call. 

b) Ether deposited and left in the contract due to other functions can be consumed.

As Multi-call is a batch transaction, driven by a for loop, it is not valid to use either msg.value or address(this).balance as they still get accounted in the loop.

Actually using address(this).balance is even more damaging than using msg.value as there is risk of consuming funds not passed by the caller.[Funds deposited an were locked due to other interactions]


## Proof of Concept
If caller batches 3 deposits as below in a multicall() function. 

```
size.multiCall{value: 3 Ether}[{deposit, amt:1 Ether},{deposit, amt:1 Ether}, {deposit, amt:1 Ether}];
```

Refer to the below executeDeposit function, which uses contract's balance instead of the amount passed in the deposit instruction.

```
 amount = address(this).balance;
```

So, in the first deposit itself, all the 3 ether passed will be converted into WETH and process. Hence the subsequent 2 deposit calls will revert due to lack of available balance and hence revert the whole transaction.

```
    function executeDeposit(State storage state, DepositParams calldata params) public {
        address from = msg.sender;
        uint256 amount = params.amount;
 ===>   if (msg.value > 0) {

           state.data.weth.deposit{value: amount}();
           state.data.weth.forceApprove(address(this), amount);

```

## Recommended Mitigation Steps
1) Check if the native tokens passed covers the amount needed. 
In the size contract's multicall, there are a need to add validation logic that
extracts the call data instructions passed as a batch to verify if the amount of native tokens passed are sufficient to cover the net amount of native tokens required.

If they are not enough, revert and save gas for the caller. 


```
   function multicall(bytes[] calldata _data) // @audit - Ether received via 
     multicall, will it be locked ?
        public
        payable
        override(IMulticall)
        whenNotPaused
        returns (bytes[] memory results)
    {
==> Add validation logic to ensure that amount of Ether passed covers the net 
    amount required to process the transaction.
    
    As Multicall can accept all combination of exposed functions by the contract,
    the validation logic should account for each type of action and compute the 
    amount required to process the multicall successfully.    

    In the case amount is not enough, revert here.

        results = state.multicall(_data);
    }
```

2) use param.amount passed in the instruction for processing.
use param.amount instead of msg.value or contract balance while processing the transaction.
