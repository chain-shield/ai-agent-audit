# Vulnerability details

## Impact
What is maxDueDate ?
> maxDueDate is a protection for passive lenders, they can specify the timestamp at which their limit orders become invalid.

When the lenders submit a yield-curve/limit-order, they should define a maxDueDate, it means they should specify how long these rates/configurations/yield-curve are valid (because the market condition might change and the lenders don't want to issue unaffordable loans).
However this feature is not available in borrower's offers/limit-orders which can cause some significant issues for passive borrowers.
 
## Proof of Concept
Alice is a lender and submits a simple yield-curve/loan-offer/limit-order:
```solidity
10 days: 30% APR
20 days: 50% APR
30 days: 65% APR
```
When Alice submits this loanOffer, she can specify a maxDueDate:
```solidity
struct BuyCreditLimitParams {
    // The maximum due date of the loan offer
@>    uint256 maxDueDate;
    // The yield curve of the loan offer
    YieldCurve curveRelativeTime;
}
```
It means she can specify how long this loan-offer/limit-order is valid.
For example she may say these rates/APRs are valid until the next 2 months.
After 2 months the limit-order will become invalid and no one can take a loan from Alice with these rates until the Alice updates their limit-order:
```solidity
// validate tenor
        if (block.timestamp + tenor > loanOffer.maxDueDate) {
            revert Errors.DUE_DATE_GREATER_THAN_MAX_DUE_DATE(block.timestamp + tenor, loanOffer.maxDueDate);
        }
```
So we can say maxDueDate is protection for Alice (we assume Alice is a passive lender) to not issue unaffordable loans due to market changes.

However we don't see maxDueDate in borrow offers/limit-orders:
```solidity
struct SellCreditLimitParams {
    // The yield curve of the borrow offer
    YieldCurve curveRelativeTime; // @audit should include maxDueDate as well as the Buy limit orders
}
```
This means borrowers can't specify how long their borrow-offers are valid.
This will lead to significant losses for passive borrowers:
- Alice is passive borrower.
- Alice defines a borrow limit-order/offer.
- After 2 weeks the market condition changes.
- Due to that the Alice is a passive borrower and doesn't update their own borrow offer everyday and also due to that there is no functionality for Alice to define a maxDueDate, so a lender may fill the Alice's order and Alice will take undesirable/unaffordable loan.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Consider including `maxDueDate` in borrowers offer as well as the lenders offer.
