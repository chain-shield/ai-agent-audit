# Vulnerability details

## Impact
While performing transfers on ERC-20, it is essential to confirm that the transaction was successful. Due to the different version of implementation by ERC20 token owners, some `transfer/transferFrom` revert on failure while others return a boolean value making it difficult for other DeFi protocol using these tokens.

The problem is in the executeSelfLiquidate() function, where the logic does not check the return value for transferFrom() which could lead to incorrect accounting.

```
state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
```

## Proof of Concept
Refer to the below code snippet of `executeSelfLiquidate()` function which performs a transferFrom the borrower to sender, but does not check if the transfer was successful or failed. In case the transfer failed, as it was not checked, it would record in the the reduction in the debit and credit positions while the actual tokens did not move from the borrower to the target account. 

```
     function executeSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external {

        uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);
```

## Recommended Mitigation Steps

user `safeTransferFrom` wrapper function from openzeppelin SafeERC20 library.
