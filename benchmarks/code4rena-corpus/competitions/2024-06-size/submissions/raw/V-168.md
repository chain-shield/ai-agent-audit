# Vulnerability details

## Impact
**The Core Issue: Decimal Mismatch**

The current implementation assumes a fixed decimal representation for both collateral and debt tokens, optimized for the USDC (borrow) / WETH (collateral) market. In a reverse market, this assumption breaks down.
   - **`debtWad`** Calculation: The code converts debt (representing WETH in the reverse market) to debtWad by scaling it to 18 decimals. This is correct for WETH.
   - **Price Interpretation:** The `price` obtained from the oracle represents the exchange rate between WETH and USDC. In a reverse market, this price needs to be inverted to represent the USDC/WETH rate.
   - **Multiplication and Division**: The calculation `Math.mulDivDown(collateral, price, debtWad)` is where the core issue lies. You're multiplying USDC collateral (likely 6 decimals) by a price meant for the inverse market and then dividing by WETH debt scaled to 18 decimals. This results in a completely inaccurate collateral ratio.

**Impact**
* **Inaccurate Collateral Ratio:** The calculated collateral ratio will be significantly incorrect due to the mismatched decimals. This can lead to:
   - Users might be incorrectly identified as undercollateralized and liquidated, even if they are not.
   - Users might be able to borrow more than intended, potentially putting the protocol at risk.
* **Cascading Errors:** The incorrect collateral ratio can propagate to other parts of the protocol that rely on this value, causing further inconsistencies and unexpected behavior.

## Proof of Concept
[src/libraries/RiskLibrary.sol#collateralRatio](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/RiskLibrary.sol#L53-L64)
```solidity
function collateralRatio(State storage state, address account) public view returns (uint256) {
    uint256 collateral = state.data.collateralToken.balanceOf(account);
    uint256 debt = state.data.debtToken.balanceOf(account);
    uint256 debtWad = Math.amountToWad(debt, state.data.underlyingBorrowToken.decimals());
    uint256 price = state.oracle.priceFeed.getPrice();

    if (debt != 0) {
        return Math.mulDivDown(collateral, price, debtWad);
    } else {
        return type(uint256).max;
    }
}
```
  - `collateral:` Represents the user's collateral balance in USDC (6 decimals in a reverse market).
  - `debt:` Represents the user's debt balance in WETH (18 decimals).
  - `debtWad:` Scales the `debt` (WETH) to 18 decimals using `Math.amountToWad`.
  - `price:` Fetched from the oracle, representing the WETH/USDC price (assumed to be in 18 decimals).
  - `Calculation:` `Math.mulDivDown(collateral, price, debtWad)` aims to calculate the collateral ratio. However, it directly uses the `collateral` (USDC, 6 decimals) with the price (WETH/USDC, 18 decimals) and `debtWad` (WETH, 18 decimals), leading to a decimal mismatch.

**1. Assumptions**
* **Reverse Market:** WETH is the borrow token (18 decimals), and USDC is the collateral token (6 decimals).
* **User Balances:**
   - `collateral` (USDC): 1000 USDC (represented as `1000 * 10**6 = 1_000_000`)
   - `debt` (WETH): 2 WETH (represented as `2 * 10**18`)
* **Oracle Price:**
   - `price` (WETH/USDC): 1500 USDC per WETH (represented as `1500 * 10**18`)

**2. Calculation Breakdown**
1. `debtWad:` Already in 18 decimals (2 * 10**18).
2. **Multiplication:** `collateral * price` = `1_000_000 * 1500 * 10**18` = `1_500_000_000_000 * 10**18`.
3. **Division:** `(1_500_000_000_000 * 10**18) / (2 * 10**18)` = `750_000_000_000`.

**3. Corrected Calculation (Illustrative)**

To get the correct collateral ratio, we need to:
1. **Invert the Price:** Calculate the USDC/WETH price: `1 / (1500 * 10**18) = 0.000000666666666667 * 10**18`.
2. **Adjust for Decimals:** Either scale the USDC collateral to 18 decimals or adjust the calculation to account for the 12 decimal difference.

## Recommended Mitigation Steps
Introduce a mechanism to determine the market type (USDC/WETH or WETH/USDC). Based on the market type, adjust the decimal scaling and price inversion logic.
For example:
```solidity
uint256 collateralDecimals = state.data.collateralToken.decimals(); // Dynamically fetch decimals
uint256 debtDecimals = state.data.underlyingBorrowToken.decimals();

uint256 debtScaled = Math.amountToWad(debt, debtDecimals); 
uint256 price = state.oracle.priceFeed.getPrice();

if (marketType == REVERSE_MARKET) {
    price = Math.rayDiv(WadRayMath.RAY, price); // Invert the price
}

// Perform calculations using appropriate decimals
return Math.mulDivDown(
    Math.amountToWad(collateral, collateralDecimals), 
    price, 
    debtScaled
);
```
**Additional Considerations**
Parameters like `crOpening` and `crLiquidation` need to be adjusted for the reverse market to maintain the intended risk parameters.
