# Vulnerability details

Whenever someone wants to interact with a user's credit or debt position to buy/sell credit, compensate or liquidate either `getDebtPosition()`, `getCreditPosition()` or `getDebtPositionByCreditPositionId()` is called in most cases to get that user's position. If the id lies within the correct range, the position is returned else the call reverts.

The issue is that the function does not check for the most recently created debt and credit position & whenever anyone tries to access it, revert occurs.

*Setting the severity to High because both the debt & credit positions of a user are called in almost every function.*

## Proof of Concept
Inside `createDebtAndCreditPositions()`, when creating a new debit & credit position, the value of `nextDebtPositionId` is incremented & then is used to store the details of the new position.

```solidity
File: AccountingLibrary.sol

  function createDebtAndCreditPositions(
        State storage state,
        address lender,
        address borrower,
        uint256 futureValue,
        uint256 dueDate
    ) external returns (CreditPosition memory creditPosition) {
        DebtPosition memory debtPosition =
            DebtPosition({borrower: borrower, futureValue: futureValue, dueDate: dueDate, liquidityIndexAtRepayment: 0});

        uint256 debtPositionId = state.data.nextDebtPositionId++;      >@ - debt position id is incremented 
        state.data.debtPositions[debtPositionId] = debtPosition;

        emit Events.CreateDebtPosition(debtPositionId, borrower, lender, futureValue, dueDate);

        creditPosition = CreditPosition({
            lender: lender,
            credit: debtPosition.futureValue,
            debtPositionId: debtPositionId,
            forSale: true
        });

        uint256 creditPositionId = state.data.nextCreditPositionId++;    >@ - credit position id is incremented 
        state.data.creditPositions[creditPositionId] = creditPosition;
        state.validateMinimumCreditOpening(creditPosition.credit);
        state.validateTenor(dueDate - block.timestamp);

        emit Events.CreateCreditPosition(creditPositionId, lender, debtPositionId, RESERVED_ID, creditPosition.credit);

        state.data.debtToken.mint(borrower, futureValue);
    }
```

Now whenever `isDebtPositionId()` or `isCreditPositionId()` is called, it checks if the requested `positionId` lies in the correct range.
```solidity
File: LoanLibrary.sol

   function isDebtPositionId(State storage state, uint256 positionId) internal view returns (bool) {
        return positionId >= DEBT_POSITION_ID_START && positionId < state.data.nextDebtPositionId;       >@ - does not check the last position
   }

   function isCreditPositionId(State storage state, uint256 positionId) internal view returns (bool) {
        return positionId >= CREDIT_POSITION_ID_START && positionId < state.data.nextCreditPositionId;    >@ - does not check the last position
   }
```

The issue lies in the second part of this check when comparing the id with the next position id.

Scenario: (Taking only debt position into consideration here)
- The current value of `nextCreditPositionId` is `5`.
- A new debt position for Bob has to be created. `nextCreditPositionId` is incremented to `6`.
- The new debt position id for Bob is `6`.
```solidity
   uint256 debtPositionId = state.data.nextDebtPositionId++;      >@ - debt position id is incremented 
        state.data.debtPositions[debtPositionId] = debtPosition;
```
- After sometime Bob's collateral ratio has gone below the minimum & can be liquidated now.
*Note: No new debt position has been created after Bob's position.*
- `getDebtPositionByCreditPositionId()` is called to get Bob's debt position.
```solidity
   function validateLiquidate(State storage state, LiquidateParams calldata params) external view {
        DebtPosition storage debtPosition = state.getDebtPosition(params.debtPositionId);
        ...
```
- `isDebtPositionId()` is called internally.
```solidity
File: LoanLibrary.sol

   function isDebtPositionId(State storage state, uint256 positionId) internal view returns (bool) {
        return positionId >= DEBT_POSITION_ID_START && positionId < state.data.nextDebtPositionId;
   }
```
- Now, Bob's `positionId` = 6 & `nextDebtPositionId` = 6.
- The check `positionId < state.data.nextDebtPositionId` will return `false` & thereby the overall result is `false`. The function reverts because Bob's position is inaccessible & he cannot be liquidated.

The same issue occurs when creating a new credit position. The newly created position cannot be accessed.

## Impact
The last/newly created debt and credit position of a user is inaccessible.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the equality check in addition when comparing the user's position with nextDebtPositionId so that the newly created position is accessible.

```solidity
File: LoanLibrary.sol

   function isDebtPositionId(State storage state, uint256 positionId) internal view returns (bool) {
-       return positionId >= DEBT_POSITION_ID_START && positionId < state.data.nextDebtPositionId;
+       return positionId >= DEBT_POSITION_ID_START && positionId <= state.data.nextDebtPositionId;
   }

   function isCreditPositionId(State storage state, uint256 positionId) internal view returns (bool) {
-       return positionId >= CREDIT_POSITION_ID_START && positionId < state.data.nextCreditPositionId;
+       return positionId >= CREDIT_POSITION_ID_START && positionId <= state.data.nextCreditPositionId;
   }
```
