# Vulnerability details

## Impact
The logic for calculating `creditAmountOut` when `cashAmountIn < maxCashAmountIn` (credit fractionalization).

Currently, the code calculates `creditAmountOut` using `netCashAmountIn`, which is the cash amount after deducting the fragmentation fee. However, the swap fee is calculated separately on `netCashAmountIn` and added to the total fees. This results in the swap fee being applied twice when calculating the final `creditAmountOut`.

**Here's why this is incorrect**

The swap fee should be calculated on the total cash amount used to obtain the credit, not just the portion remaining after deducting the fragmentation fee.

This has a significant impact on the accuracy of credit calculations when fractionalization occurs.

**1. Inaccurate Credit Amount:**
   * **Buggy Code:** The current code calculates `creditAmountOut` based on `netCashAmountIn`, which has already deducted the swap fee. This leads to a lower `creditAmountOut` than what the user should receive. [AccountingLibrary.sol#294-296](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L294-L296)

   * **Example:** Let's say a user wants to get credit using 100 USDC (`cashAmountIn`). Assuming a 10% swap fee and a 5% fragmentation fee, the user should receive credit worth approximately 85.5 USDC after fees. However, the buggy code would result in a `creditAmountOut` of approximately 76.95 USDC (100 - 5 - 10% of 95), shortchanging the user by 8.55 USDC.

**2. Financial Disadvantage for Users:**
   * Users consistently receive less credit than they should for their cash, putting them at a financial disadvantage. This undermines the platform's fairness and transparency.

## Proof of Concept
**1. Simplified**
```solidity
pragma solidity ^0.8.0;

contract AccountingLibraryPOC {
    uint256 constant PERCENT = 1e18;

    struct FeeConfig {
        uint256 fragmentationFee;
        uint256 swapFeeAPR; // Annual Percentage Rate
    }

    FeeConfig public feeConfig;

    constructor(uint256 _fragmentationFee, uint256 _swapFeeAPR) {
        feeConfig = FeeConfig(_fragmentationFee, _swapFeeAPR);
    }

    // Simulates Math.mulDivDown for demonstration
    function mulDivDown(uint256 x, uint256 y, uint256 z) public pure returns (uint256) {
        return (x * y) / z;
    }

    // Simulates getSwapFee for demonstration
    function getSwapFee(uint256 cash, uint256 tenor) public view returns (uint256) {
        // Simplified swap fee calculation for demonstration
        return (cash * feeConfig.swapFeeAPR * tenor) / (PERCENT * 365 days);
    }

    // Buggy getCreditAmountOut function
    function getCreditAmountOut(
        uint256 cashAmountIn,
        uint256 maxCashAmountIn,
        uint256 maxCredit,
        uint256 ratePerTenor,
        uint256 tenor
    ) public view returns (uint256 creditAmountOut, uint256 fees) {
        if (cashAmountIn == maxCashAmountIn) {
            creditAmountOut = maxCredit;
            fees = getSwapFee(cashAmountIn, tenor);
        } else if (cashAmountIn < maxCashAmountIn) {
            if (feeConfig.fragmentationFee > cashAmountIn) {
                revert("Not enough cash");
            }

            uint256 netCashAmountIn = cashAmountIn - feeConfig.fragmentationFee;

            creditAmountOut = mulDivDown(netCashAmountIn, PERCENT + ratePerTenor, PERCENT);
            fees = getSwapFee(netCashAmountIn, tenor) + feeConfig.fragmentationFee;
        } else {
            revert("Not enough credit");
        }
    }
}
```

## Recommended Mitigation Steps
   1. Calculate the swap fee on the original `cashAmountIn` instead of `netCashAmountIn`.
   2. Subtract both the fragmentation fee and the swap fee from `cashAmountIn` to get the correct `netCashAmountIn` for calculating `creditAmountOut`.
```solidity

            // credit fractionalization

            if (state.feeConfig.fragmentationFee > cashAmountIn) {
                revert Errors.NOT_ENOUGH_CASH(state.feeConfig.fragmentationFee, cashAmountIn);

            // Calculate swap fee on the original cashAmountIn
            uint256 swapFee = getSwapFee(state, cashAmountIn, tenor);

            // Calculate netCashAmountIn after deducting both fees
            uint256 netCashAmountIn = cashAmountIn - state.feeConfig.fragmentationFee - swapFee;
```
