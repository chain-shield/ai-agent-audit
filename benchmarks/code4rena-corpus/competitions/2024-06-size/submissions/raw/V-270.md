# Vulnerability details

**Description:**

In the `UpdateConfig` contract the function `executeUpdateConfig` does not validate the variables `crOpening` and `crLiquidation`. Improper values for these collateral ratios can compromise the collateralization safety of the protocol, leading to potential insolvency or liquidation issues.

**Impact:**

- If crOpening is set too low or too high, it could allow under-collateralized loans, increasing the risk of defaults.
- If crLiquidation is set improperly, it could prevent timely liquidations, leading to potential losses for the protocol.
- This could significantly affect the risk parameters and overall security of the protocol.

**Proof of Concept:**

1. Call the executeUpdateConfig function with an invalid crOpening or crLiquidation value.
2. The function updates these values without validation, leading to potential risk parameter compromise.

**Tools Used:**

Manual Review

**Recommended Mitigation:**

1. Add explicit validation for crOpening to ensure it is within a reasonable range (e.g., 1 <= crOpening <= 10(for example)).
2. Validate crLiquidation to ensure it is within a reasonable range and less than crOpening.

```diff
if (Strings.equal(params.key, "crOpening")) {
+           if(params.value < 0 && params.value > 10 // for example) revert();
            state.riskConfig.crOpening = params.value;
            } else if (Strings.equal(params.key, "crLiquidation")) {
+           if (params.value >= state.riskConfig.crLiquidation || params.value < 0 || params.value > state.riskConfig.crOpening) {
                revert Errors.INVALID_COLLATERAL_RATIO(params.value);
            }
            state.riskConfig.crLiquidation = params.value;
```
