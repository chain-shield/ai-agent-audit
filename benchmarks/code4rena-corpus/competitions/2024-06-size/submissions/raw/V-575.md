# Vulnerability details

## Impact
The purpose of ```compensate()``` is to reduce the credit of a position either by using another credit position(that has a sooner due date) owned by the borrower or creating a new credit/debt position which can be paid immediately or sooner.

The issue with the validation check is the minTenor check done when params.creditPositionToCompensateId == RESERVED_ID. 

When a borrower attempts to create a new createDebtAndCreditPositions with a lower amount than the original creditPositionWithDebtToRepay.credit, with the intention to repay instantly with a multi-call, there will be a revert if  ```debtPositionToRepay.dueDate - block.timestamp < minTenor```(this defeats the purpose of the compensate function. 

Also there is no need for the check since the future value of the credit position will be a split of the entire ```creditPositionWithDebtToRepay```  credit and not dependent of lender's yeildCurve anymore.

Another confirmation is the fact that when params.creditPositionToCompensateId is not RESERVED_ID, the only check done is to ensure that debtPositionToRepay.dueDate is not < state.getDebtPositionByCreditPositionId(params.creditPositionToCompensateId).dueDate without checking if the duration is > minTenor.

## Proof of Concept
Let us consider an instance where Alice tries to compensate a credit position of 1,500,000 with params.creditPositionToCompensateId == RESERVED_ID and amount as 500,000 and instantly repay the new 500,000 debtPosition/creditPosition(Lender) 

```solidity
CreditPosition memory creditPositionToCompensate;
        if (params.creditPositionToCompensateId == RESERVED_ID) {
       @>       creditPositionToCompensate = state.createDebtAndCreditPositions({
                lender: msg.sender,
                borrower: msg.sender,
                futureValue: amountToCompensate,
                dueDate: debtPositionToRepay.dueDate
            });

...

 // credit emission
        state.createCreditPosition({
            exitCreditPositionId: params.creditPositionToCompensateId == RESERVED_ID
      @>        ? state.data.nextCreditPositionId - 1 //making the Lender of new credit position
                : params.creditPositionToCompensateId,
            lender: creditPositionWithDebtToRepay.lender,
            credit: amountToCompensate
        });
```
Transaction will revert because of the minTenor check. Also, note that it is not possible for the duration to exceed maxTenor since duration of an old debtPosition is lower than what it used to be and there has been a maxDuration check before the start of the loan, and time has passed.
