# Vulnerability details

## Summary
The `BuyCreditLimit` library lacks comprehensive validation for the `maxDueDate` parameter of a loan offer. The initial validation ensured that `maxDueDate` was non-zero and not in the past relative to the minimum tenor. However, it did not check if `maxDueDate` exceeded the maximum allowable tenor configured in the platform’s risk settings. This oversight could potentially allow the creation of loan offers with excessively long durations, posing a risk to the platform.
## Impact
Failing to validate that `maxDueDate` does not exceed the maximum tenor (`block.timestamp + state.riskConfig.maxTenor`) can lead to several issues:

- Increased Risk Exposure: Loan offers with excessively long due dates might not align with the platform’s risk tolerance, leading to higher-than-expected risk exposure.
- Economic Loss: If loan terms are extended beyond acceptable limits, it could lead to defaults or other economic impacts that the platform's risk models did not account for.
- Reputation Damage: Allowing users to create loan offers outside of predefined risk parameters could damage the platform's reputation for maintaining rigorous financial controls.

        LoanOffer memory loanOffer =
            LoanOffer({maxDueDate: params.maxDueDate, curveRelativeTime: params.curveRelativeTime});

        // a null offer mean clearing their limit order
        if (!loanOffer.isNull()) {
            // validate msg.sender
            // N/A

            // validate maxDueDate
            if (params.maxDueDate == 0) {
                revert Errors.NULL_MAX_DUE_DATE();
            }
            if (params.maxDueDate < block.timestamp + state.riskConfig.minTenor) {
                revert Errors.PAST_MAX_DUE_DATE(params.maxDueDate);
            }

            // validate curveRelativeTime
            YieldCurveLibrary.validateYieldCurve(
                params.curveRelativeTime, state.riskConfig.minTenor, state.riskConfig.maxTenor
            );
        }

## Recommended Mitigation
- Introduce a new error in `Errors.sol` to handle the scenario where `maxDueDate` exceeds the maximum tenor.
```
error EXCEEDS_MAX_TENOR(uint256 maxDueDate);
```
- Update the validation logic to include a check ensuring `maxDueDate` does not exceed `block.timestamp + state.riskConfig.maxTenor`
```
if (params.maxDueDate > block.timestamp + state.riskConfig.maxTenor) {
    revert Errors.EXCEEDS_MAX_TENOR(params.maxDueDate);
}
```
