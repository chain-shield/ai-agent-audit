# Vulnerability details

## Impact
According to the whitepaper, the fragmentationFee should be charged to the users who cause a creditPosition to be fragmented.  This is necessary as the protocol is expected to be deployed on mainet with high transaction cost and the lender is than required to mannually go through all of his creditPositions and claim Them.

Due to importance of allowing partial repayment, the protocol allowed users to use creditPostions to partially repay their debt. They also added a feature where they allowed the users to dynamically use their USDC deposits in the protocol to create creditPositions and  a debt postion associated with it to facilitate the repayment process, as users wouldn't be required to first create a CreditPosition and match it in the market with a debt Position. The goal was to allow the users  to do something like this to steamline partial repayment.
- Deposit USDC to the protocol
- compensate(500 USDC, RESERVED_ID)
- repay(newDebtPosition)

with this the users would effectively be able to repay their debt partially.

The problem however arises if **the users don't repay the newly created debt position**. In this case the borrowers, would have effectively fragmented the `creditPosition` of the lender, without paying any `fragmentationFee`.
This would allow also for the possibility of griefing and fragementing the creditPosition of the lender multiple times, without the need to even repay any debt or pay any fragementation fee
>N.B please also note size intends to automate the claiming process using bots, and for this reason the framenetation fee is used to cover the cost. Meaning such an attack will bring a huge loss to the size protocol as they will be forced to claim all positions using the bot, whitout actually geting paid any fees to cover the cost
## Proof of Concept
In the `compensate()` function the fragementation fee is only charged to the borrower, if he fragments his own creditPosition that he wants to repay his debt with, but doesn't pay any fragementation fee for fragmenting the creditPosition of the lender
```solidity
        if (exiterCreditRemaining > 0) {
            // charge the fragmentation fee in collateral tokens, capped by the user balance
            uint256 fragmentationFeeInCollateral = Math.min(
                state.debtTokenAmountToCollateralTokenAmount(state.feeConfig.fragmentationFee),
                state.data.collateralToken.balanceOf(msg.sender)
            );
            state.data.collateralToken.transferFrom(
                msg.sender, state.feeConfig.feeRecipient, fragmentationFeeInCollateral
            );
        }
```

## Recommendation
We would recomend charging a fee to the user if he when repaying the debt end up fragmeneting the position of the lender (partial repay).

As a side note, we think it is not intuitive enough to charge the borrower fragementation fee for fragementing his own creditPosition, we think this should be removed, and to only charge a fee for the borrower for fragementing the creditPosition of the lender
