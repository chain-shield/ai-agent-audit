# Vulnerability details

## Impact
The `executeClaim` function is currently facing a critical issue with rounding when calculating the `claimAmount`. This function, which is responsible for determining the amount to be claimed by the lender, uses 'Math. mulDivDown' for the calculation. However, this approach can lead to a significant problem-rounding down the claim amount. This could result in the lender receiving slightly less than what they are entitled to, which is a severe concern for the financial integrity of the system.
[Claim.sol:52-54](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Claim.sol#L52-L54)
```solidity
uint256 claimAmount = Math.mulDivDown(
    creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
);
```
To address this issue and ensure the lender receives the total amount owed, it is highly recommended that the use of `Math.mulDivDown` be replaced with 'Math. mulDivUp' in the 'executeClaim' function. This change will ensure that any rounding will favor the lender, guaranteeing they receive at least the amount they are entitled to. By using `Math.mulDivUp`, the `claimAmount` will be rounded up if necessary, thereby ensuring the lender receives the total amount they are owed based on the current liquidity index and the liquidity index at the time of repayment. This is a crucial step in maintaining the accuracy of lender payments.
```solidity
uint256 claimAmount = Math.mulDivUp(
    creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
);
```
## Proof of Concept
[Claim.sol:L48-L58](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Claim.sol#L48-L59)
```solidity
    function executeClaim(State storage state, ClaimParams calldata params) external {
        CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
        DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);


        uint256 claimAmount = Math.mulDivDown(
            creditPosition.credit, state.data.borrowAToken.liquidityIndex(), debtPosition.liquidityIndexAtRepayment
        );
        state.reduceCredit(params.creditPositionId, creditPosition.credit);
        state.data.borrowAToken.transferFrom(address(this), creditPosition.lender, claimAmount);


        emit Events.Claim(params.creditPositionId, creditPosition.debtPositionId);
    }
```
Suppose `creditPosition.credit` is 1000, `state.data.borrowAToken.liquidityIndex()` is 1.5e18, and `debtPosition.liquidityIndexAtRepayment` is 1e18. Using `Math.mulDivDown`, the calculated `claimAmount` would be.
```solidity
claimAmount = Math.mulDivDown(1000, 1.5e18, 1e18)
            = 1000 * 1.5e18 / 1e18
            = 1500
```
However, the lender should actually receive 1500 (1000 * 1.5) tokens, but due to rounding down, they would only receive 1500 tokens.

## Recommended Mitigation Steps
Using `Math.mulDivUp`, the calculated `claimAmount` would be
```yaml
claimAmount = Math.mulDivUp(1000, 1.5e18, 1e18)
            = (1000 * 1.5e18 + 1e18 - 1) / 1e18
            = 1500
```
