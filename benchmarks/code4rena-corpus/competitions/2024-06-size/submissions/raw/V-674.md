# Vulnerability details

## Description:
The PriceFeed smart contract, when deployed on BASE L2, does not account for the different deviation threshold of the ETH/USD price feed compared to Ethereum Mainnet. This discrepancy can lead to inaccurate price reporting and potential economic vulnerabilities in the system.

## Details:

**Current Implementation:**

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/oracle/PriceFeed.sol#L84

- File: PriceFeed.sol
- The contract uses Chainlink's ETH/USD price feed without any specific deviation threshold checks.
- The contract assumes a uniform behavior of price feeds across different networks.

**Network-Specific Behavior:**
- Ethereum Mainnet ETH/USD feed deviation threshold: 0.5% (0.005 in decimal form)
- BASE L2 ETH/USD feed deviation threshold: 0.15% (0.0015 in decimal form)

## Impact:
- The lower deviation threshold on BASE L2 means that price updates occur more frequently for smaller price movements.
- The contract, expecting Mainnet behavior, may consider some valid price updates on BASE L2 as insignificant, potentially using outdated prices.

## Code:

```solidity
function _getPrice(AggregatorV3Interface aggregator, uint256 stalePriceInterval) internal view returns (uint256) {
       (, int256 price,, uint256 updatedAt,) = aggregator.latestRoundData();
       if (price <= 0) revert Errors.INVALID_PRICE(address(aggregator), price);
       if (block.timestamp - updatedAt > stalePriceInterval) {
           revert Errors.STALE_PRICE(address(aggregator), updatedAt);
       }
       return SafeCast.toUint256(price);
   }
```

This function does not account for the different deviation thresholds across networks.

## Scenario:
- ETH price: $2000
- Price movement: 0.2% ($4)
- On Ethereum Mainnet: No price update (below 0.5% threshold)
- On BASE L2: Price update occurs (above 0.15% threshold)
- Result: Contract on BASE L2 might use an outdated price, potentially for an extended period

## Root Cause:
The contract does not implement network-specific logic to handle different deviation thresholds for price feeds. It assumes uniform behavior across all networks, which is not the case for the ETH/USD feed on BASE L2.

## Potential Risks:
1. Use of outdated prices in critical calculations.
2. Increased vulnerability to price manipulation within the lower threshold range.
3. Misalignment between on-chain prices and actual market prices, leading to potential economic exploits.
4. Reduced effectiveness of the price feed, especially during periods of low volatility.

## Recommended Fix:
1. Implement network-specific deviation checks:

```solidity
uint256 public constant MAINNET_DEVIATION_THRESHOLD = 5e15; // 0.5%
   uint256 public constant BASE_L2_DEVIATION_THRESHOLD = 15e14; // 0.15%
   uint256 public deviationThreshold;

   constructor(/* existing parameters */, uint256 _networkDeviationThreshold) {
       // ... existing initialization ...
       deviationThreshold = _networkDeviationThreshold;
   }

   function _getPrice(AggregatorV3Interface aggregator, uint256 stalePriceInterval) internal view returns (uint256) {
       (uint80 roundId, int256 price, , uint256 updatedAt, uint80 answeredInRound) = aggregator.latestRoundData();
       if (price <= 0) revert Errors.INVALID_PRICE(address(aggregator), price);
       if (block.timestamp - updatedAt > stalePriceInterval) {
           revert Errors.STALE_PRICE(address(aggregator), updatedAt);
       }
       
       // Check for round completeness
       if (answeredInRound < roundId) revert Errors.INCOMPLETE_ROUND(roundId, answeredInRound);
       
       // Implement deviation check
       (uint80 previousRoundId, int256 previousPrice,,,) = aggregator.getRoundData(roundId - 1);
       if (previousRoundId > 0) {
           uint256 priceDifference = uint256(abs(price - previousPrice));
           uint256 relativeDeviation = (priceDifference * 1e18) / uint256(abs(previousPrice));
           if (relativeDeviation < deviationThreshold) revert Errors.INSIGNIFICANT_PRICE_MOVEMENT(relativeDeviation);
       }

       return SafeCast.toUint256(price);
   }

   function abs(int256 x) internal pure returns (int256) {
       return x >= 0 ? x : -x;
   }
```

2. Update deployment scripts to set the correct deviation threshold based on the target network.

3. Add a function to allow updating the deviation threshold (with proper access control):

```solidity
function updateDeviationThreshold(uint256 _newThreshold) external onlyOwner {
       deviationThreshold = _newThreshold;
       emit DeviationThresholdUpdated(_newThreshold);
   }
```
