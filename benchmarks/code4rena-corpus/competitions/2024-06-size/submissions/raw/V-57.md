# Vulnerability details

## Impact
[getCreditAmountIn:L253-L255](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L253-L255)
```solidity
creditAmountIn = Math.mulDivUp(
    cashAmountOut + state.feeConfig.fragmentationFee, PERCENT + ratePerTenor, PERCENT - swapFeePercent
);
```
In the case where `cashAmountOut < maxCashAmountOutFragmentation`, the `creditAmountIn` calculation is incorrect. It should be.
```solidity
creditAmountIn = Math.mulDivUp(
    cashAmountOut, PERCENT + ratePerTenor, PERCENT - swapFeePercent
) + Math.mulDivUp(state.feeConfig.fragmentationFee, PERCENT + ratePerTenor, PERCENT);
```
The current implementation adds the `fragmentationFee` to `cashAmountOut` before calculating `creditAmountIn`, which is incorrect. The `fragmentationFee should be added separately to the `creditAmountIn` after the calculation.

The corrected formula ensures that the `creditAmountIn` is calculated based on the actual `cashAmountOut` (excluding the fragmentation fee) and then adds the fragmentation fee converted to credit terms.

**`Suppose we have the following values`**
    - `cashAmountOut` = 900
    - `maxCashAmountOut` = 1000
    - `state.feeConfig.fragmentationFee` = 100
    - `ratePerTenor` = 10 (10%)
    - `swapFeePercent` = 5 (5%)

In this case, `maxCashAmountOutFragmentation` would be 900 (1000 - 100).

Since `cashAmountOut` (900) equals `maxCashAmountOutFragmentation` (900), the code will enter the `else if` block in the `getCreditAmountIn` function.

With the current implementation, the `creditAmountIn` calculation would be: [creditAmountIn#L253-L255](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L253-L255)
```solidity
creditAmountIn = Math.mulDivUp(
    cashAmountOut + state.feeConfig.fragmentationFee, PERCENT + ratePerTenor, PERCENT - swapFeePercent
);
```
Plugging in the values.
```solidity
creditAmountIn = Math.mulDivUp(900 + 100, 100 + 10, 100 - 5);
               = Math.mulDivUp(1000, 110, 95);
               = 1158
```
However, this calculation is incorrect because it includes the fragmentation fee in the `cashAmountOut` before calculating the `creditAmountIn`.

The correct calculation should be:
```solidity
creditAmountIn = Math.mulDivUp(
    cashAmountOut, PERCENT + ratePerTenor, PERCENT - swapFeePercent
) + Math.mulDivUp(state.feeConfig.fragmentationFee, PERCENT + ratePerTenor, PERCENT);
```
Plugging in the values
```solidity
creditAmountIn = Math.mulDivUp(900, 100 + 10, 100 - 5) + Math.mulDivUp(100, 100 + 10, 100);
               = Math.mulDivUp(900, 110, 95) + Math.mulDivUp(100, 110, 100);
               = 1042 + 110;
               = 1152
```
This corrected calculation ensures that the `creditAmountIn` is based on the actual `cashAmountOut` (excluding the fragmentation fee) and then adds the fragmentation fee converted to credit terms separately.
