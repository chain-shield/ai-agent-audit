# Vulnerability details

## Impact
I noticed an issue in the `SellCreditMarket.executeSellCreditMarket()` function. When `exactAmountIn` is false, meaning the caller is specifying the exact cash amount they want to receive (`params.amount`), the function calculates the `creditAmountIn` and `fees` using: [SellCreditMarket.sol#171-181](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SellCreditMarket.sol#L171-L181)
```solidity
(creditAmountIn, fees) = state.getCreditAmountIn({
    cashAmountOut: cashAmountOut,
    maxCashAmountOut: params.creditPositionId == RESERVED_ID
        ? cashAmountOut
        : Math.mulDivDown(creditPosition.credit, PERCENT - state.getSwapFeePercent(tenor), PERCENT + ratePerTenor),
    maxCredit: params.creditPositionId == RESERVED_ID
        ? Math.mulDivUp(cashAmountOut, PERCENT + ratePerTenor, PERCENT - state.getSwapFeePercent(tenor))
        : creditPosition.credit,
    ratePerTenor: ratePerTenor,
    tenor: tenor
});
```
The issue is in the calculation of `maxCashAmountOut`. According to the technical docs, when selling credit and specifying an exact cash amount out, the maximum cash amount out should be calculated as follows:
```solidity
maxCashAmountOut = cashAmountOut
```
However, in the code, when `params.creditPositionId != RESERVED_ID`, it's calculated as:
```solidity
maxCashAmountOut = Math.mulDivDown(creditPosition.credit, PERCENT - state.getSwapFeePercent(tenor), PERCENT + ratePerTenor)
```
This calculation doesn't match the specification and could lead to incorrect fee calculations or credit amounts when selling credit from an existing credit position.

Specifically when `exactAmountIn` is false and `params.creditPositionId != RESERVED_ID`. This scenario corresponds to a user selling credit from an existing credit position and specifying the exact cash amount they want to receive.

## Proof of Concept
Suppose a user wants to sell credit from an existing credit position with the following parameters:
   - `creditPosition.credit` = 1000 USDC
   - `ratePerTenor` = 0.1 (10%)
   - `tenor` = 365 days
   - `state.getSwapFeePercent(tenor)` = 0.01 (1%)
   - `cashAmountOut` (specified by the user) = 900 USDC

With the current implementation, `maxCashAmountOut` would be calculated as:
```solidity
maxCashAmountOut = 1000 * (1 - 0.01) / (1 + 0.1) ≈ 900.90 USDC
```
However, according to the specification, `maxCashAmountOut` should equal `cashAmountOut`, which is 900 USDC.

**This discrepancy could lead to the following issues:**
1. The user may receive less cash than expected, as the calculated `maxCashAmountOut` is higher than the specified `cashAmountOut`.
2. The fees charged may be incorrect, as they are based on the difference between `creditAmountIn` and `cashAmountOut`, which are calculated using the wrong `maxCashAmountOut`.

## Recommended Mitigation Steps
The `maxCashAmountOut` calculation should be updated constantly to use `cashAmountOut` when `exactAmountIn` is false, regardless of the `creditPositionId`
```solidity
maxCashAmountOut: cashAmountOut,
```
