# Vulnerability details


## Summary
The `AccountingLibrary.sol` contract contains a critical in the [createCreditPosition()](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L103-L127) function that can lead to protocol insolvency. This function is responsible for creating new credit positions by exiting existing ones, which is a core functionality of the Size protocol as described in the **README[]**.
```solidity
function createCreditPosition(State storage state, uint256 exitCreditPositionId, address lender, uint256 credit)
    external
{
    CreditPosition storage exitCreditPosition = state.getCreditPosition(exitCreditPositionId);
    if (exitCreditPosition.credit == credit) {
        // ...
    } else {
        uint256 debtPositionId = exitCreditPosition.debtPositionId;

        reduceCredit(state, exitCreditPositionId, credit);

        CreditPosition memory creditPosition =
            CreditPosition({lender: lender, credit: credit, debtPositionId: debtPositionId, forSale: true});

        // ...
    }
}
```
The `reduceCredit()` function is called with the `credit` parameter, which represents the amount of credit for the new position. However, this should be the amount to reduce from the existing credit position. The correct amount to reduce should be `exitCreditPosition.credit - credit`.

## Impact
This vulnerability violates a key invariant of the system: `SOLVENCY_01: SUM(outstanding credit) == SUM(outstanding debt)`. The incorrect credit reduction can lead to:

1. The total credit in the system may exceed the total debt, creating unbacked credit positions.
2. Unfair advantage for malicious users: Attackers can exploit this to create credit positions with more value than they should have.
3. When the discrepancy is discovered, honest users may not be able to fully claim their credits.

## Proof of Concept
1. Alice has an existing credit position with 1000 tokens.
2. Alice calls `createCreditPosition()` with `credit = 800`, intending to exit 800 tokens to a new position.
4. A new credit position is created with 800 tokens.
5. The protocol now has 1800 tokens of credit (1000 original + 800 new) backed by only 1000 tokens of debt.

## Recommended Mitigation Steps
Modify the `createCreditPosition()` function to correctly calculate the amount to reduce:
```solidity
function createCreditPosition(State storage state, uint256 exitCreditPositionId, address lender, uint256 credit)
    external
{
    CreditPosition storage exitCreditPosition = state.getCreditPosition(exitCreditPositionId);
    if (exitCreditPosition.credit == credit) {
        // ... 
    } else {
        uint256 debtPositionId = exitCreditPosition.debtPositionId;

-       reduceCredit(state, exitCreditPositionId, credit);
+       reduceCredit(state, exitCreditPositionId, exitCreditPosition.credit - credit);

        CreditPosition memory creditPosition =
            CreditPosition({lender: lender, credit: credit, debtPositionId: debtPositionId, forSale: true});

        // ... 
    }
}
```
This change ensures that the correct amount is reduced from the existing credit position, maintaining the protocol's solvency and preserving the integrity of the credit-debt balance.
