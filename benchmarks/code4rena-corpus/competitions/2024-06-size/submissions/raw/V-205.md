# Vulnerability details

## Description
[LoanLibrary.sol#156-160](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L156-L160)
```solidity
if (debt != 0) {
    return Math.mulDivDown(collateral, debtPosition.futureValue, debt);
} else {
    return 0;
}
```
If the `debt` variable is zero, the code correctly handles the case by returning zero as the assigned collateral. However, if `debt` is zero and the code execution reaches the `Math.mulDivDown` function, it will attempt to perform a division by zero, which can cause the transaction to revert.

## Impact
The `getDebtPositionAssignedCollateral` function calculates the amount of collateral assigned to a specific debt position. It does this by proportionally distributing the borrower's total collateral based on the debt position's future value and the borrower's total debt.

## Proof of Concept
We have the `getDebtPositionAssignedCollateral` function: [LoanLibrary.sol#148-160](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L148-L161)
```solidity
function getDebtPositionAssignedCollateral(State storage state, DebtPosition memory debtPosition)
    public
    view
    returns (uint256)
{
    uint256 debt = state.data.debtToken.balanceOf(debtPosition.borrower);
    uint256 collateral = state.data.collateralToken.balanceOf(debtPosition.borrower);

    if (debt != 0) {
        return Math.mulDivDown(collateral, debtPosition.futureValue, debt);
    } else {
        return 0;
    }
}
```
Let's assume we have a test scenario where a borrower has collateral but no outstanding debt.
```solidity
// Test scenario setup
address borrower = 0xE859cC2311c88b5F661acfcF15F48A754cf9124t;
uint256 collateral = 1000;
uint256 debt = 0;
uint256 futureValue = 500;

// Update the state with the borrower's collateral and debt balances
state.data.collateralToken.setBalance(borrower, collateral);
state.data.debtToken.setBalance(borrower, debt);

// Create a DebtPosition struct for the borrower
DebtPosition memory debtPosition = DebtPosition({
    borrower: borrower,
    futureValue: futureValue,
    // Other fields omitted for brevity
});
```
When we call the `getDebtPositionAssignedCollateral` function with the above setup.
```solidity
uint256 assignedCollateral = LoanLibrary.getDebtPositionAssignedCollateral(state, debtPosition);
```
* The execution flow enters the `getDebtPositionAssignedCollateral` function
     - It retrieves the borrower's debt balance, which is zero (`debt = 0`).
     - It retrieves the borrower's collateral balance, which is non-zero (`collateral = 1000`).
     - The `if` condition `debt != 0` evaluates to `false`, so the execution proceeds to the `Math.mulDivDown` function call.

* Inside the `Math.mulDivDown` function
     - The `x` parameter is `collateral` (1000), the `y` parameter is `futureValue` (500), and the denominator parameter is `debt` (0).
     - The assembly code multiplies `x` and `y` and stores the result in `z` (`z = 1000 * 500 = 500000`).
     - The if condition checks if the `denominator` is zero or if (`x * y) / x` equals `y`. In this case, the `denominator` is zero, so the condition is evaluated as true.
     - The `revert(0, 0)` statement is executed, causing the transaction to revert due to a division by zero error.
     - The transaction reverts, and the `getDebtPositionAssignedCollateral` function fails to return a value.

## Recommended Mitigation Steps
Before performing the division, the code should check for a zero `debt` value. Moving the check for a zero `debt` value before the `Math.mulDivDown` function call avoids the division by zero scenarios.

    view
    returns (uint256)
