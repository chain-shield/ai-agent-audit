# Vulnerability details

## Title
Incorrect validation to determine if the liquidator receives the requested minimum profit for executing the validation.

## Impact
Liquidators could receive less than the expected minimum profit, or even worse, liquidate at a loss when they would not be willing to do it.

## Proof of Concept
When executing a liquidation, the liquidators can define a minimum profit they'd like to make for doing the liquidation, this serves as a protection against doing unprofitable liquidations (if they are not willing to do it).
The problem with the existing implementation is the variable that is used to check if the liquidator received the requested minimum profit or not.
- Currently, the [value that is used to validate the minimum profit is the `liquidatorProfitCollateralToken`](https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol#L218-L219), which represents the amount of debt covered by the collateral + the liquidatorRewards (if any), not only the liquidatorRewards.
  - For example, when liquidating an unprofitable liquidation, `liquidationRewards` is 0, or in other words, the profit of the liquidator is 0, it may even accrue a loss because it is liquidating an unprofitable position, meaning, the assigned collateral to the position it is not even enough to cover a 100% of the position's debt.
    - If the liquidator set a minimum profit of `0.0001 ETH` or any value specifying the minimum profit, the [`validateMinimumCollateralProfit() function`](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/actions/Liquidate.sol#L59-L69) will incorrectly determine that the liquidator indeed received the minimum requested profit, because **`liquidatorProfitCollateralToken` represents all the collateral transferred for doing the liquidation, not only the profit for the liquidation.**

```
> Liquidate.sol

function executeLiquidate(State storage state, LiquidateParams calldata params)
    external
    //@audit-issue => Doesn't return the real liquidator's profit!
    returns (uint256 liquidatorProfitCollateralToken)
{
    ...

    // profitable liquidation
    if (assignedCollateral > debtInCollateralToken) {
      //@audit => This is the real liquidator's profit!
        uint256 liquidatorReward = Math.min(
            assignedCollateral - debtInCollateralToken,
            Math.mulDivUp(debtPosition.futureValue, state.feeConfig.liquidationRewardPercent, PERCENT)
        );
        //@audit-issue => The liquidator's profit is mixed with the liquidated debt worth in collateral!
        liquidatorProfitCollateralToken = debtInCollateralToken + liquidatorReward;

        ...
    } else {
      //@audit-issue => liquidatorProfitCollateralToken doesn't represent the liquidator's profit.
        // unprofitable liquidation
        liquidatorProfitCollateralToken = assignedCollateral;
    }

    ...

    //@audit => Transfer the collateral that can be seized from the borrower to the liquidator.
    //@audit => If unprofitable liquidation, `liquidatorProfitCollateralToken` is less (in collateral's value) than the amount of borrowAToken paid by the liquidator
    state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, liquidatorProfitCollateralToken);
    ...
}

function validateMinimumCollateralProfit(
    State storage,
    LiquidateParams calldata params,
    uint256 liquidatorProfitCollateralToken
) external pure {
    //@audit => The remaining assigned collateral to cover the liquidated Debt. When unprofitable liquidation, `liquidatorProfitCollateralToken` is always < debtTokenInETH.
    //@audit-issue => This check will always pass, effectively not enforcing the minimum profit requested by the liquidator, and possing the risk of liquidating unprofitable liquidations.
    if (liquidatorProfitCollateralToken < params.minimumCollateralProfit) {
        revert Errors.LIQUIDATE_PROFIT_BELOW_MINIMUM_COLLATERAL_PROFIT(
            liquidatorProfitCollateralToken, params.minimumCollateralProfit
        );
    }
}
```

## Recommended Mitigation Steps
The most straightforward mitigation is to change the returned value from the [`executeLiquidate() function`](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/actions/Liquidate.sol#L75-L78), instead of returning the `liquidatorProfitCollateralToken` that represents the amount of debt covered by the collateral + the liquidatorRewards (if there were any), opt to **[return the `liquidatorReward`](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/actions/Liquidate.sol#L96-L99)**, this variable correctly **reflects the exact amount of profit made by the liquidator.**
- If executing an unprofitable liquidation, the `liquidatorReward` would be 0, so, if the liquidator is not willing to liquidate at a loss, the logic will now correctly revert the execution.

I'd suggest going one step further, and, instead of treating the `params.minimumCollateralProfit` as an amount of collateral, I'd recommend allowing liquidators to specify the amount of profit they want to make in terms of USDC (the same asset they are liquidating), and, as part of the liquidation logic, convert the value of the `liquidatorReward` to its equivalent in USDC to compare it against the requested minimum profit.
- This would ease and improve the liquidator's experience because they would only be concerned about the values of the same asset (USDC). For example, they are liquidating a DebtPosition with 1,000 debt, and they would like to make a profit of 5% (50 USDC).
