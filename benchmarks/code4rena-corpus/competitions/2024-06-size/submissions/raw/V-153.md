# Vulnerability details

## Impact
Collateral ratio of a user can stay the same after a liquidation causing him to be liquidatable again

## Proof of Concept
This is how the `liquidatorReward` gets computed upon a profitable liquidation:
```solidity
uint256 liquidatorReward = Math.min(
                assignedCollateral - debtInCollateralToken,
                Math.mulDivUp(debtPosition.futureValue, state.feeConfig.liquidationRewardPercent, PERCENT)
            );
```
If `liquidatorReward` gets the value of the first input of `Math.min()`, then the collateral ratio of the liquidated user will not change at all.

This is how `liquidatorProfitCollateralToken` gets computed (the collateral tokens amount sent to the liquidator from the liquidated borrower):
```solidity
liquidatorProfitCollateralToken = debtInCollateralToken + liquidatorReward;
```
This makes `liquidatorProfitCollateralToken` equal to `assignedCollateral` in the case explained above (`debtInCollateralToken + (assignedCollateral - debtInCollateralToken).

Then, these are the transfers occuring at the end of the function:
```solidity
state.data.borrowAToken.transferFrom(msg.sender, address(this), debtPosition.futureValue);
state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, liquidatorProfitCollateralToken);
state.repayDebt(params.debtPositionId, debtPosition.futureValue);
```
`debtPosition.futureValue` is removed from the liquidated user's debt and we transfer out `liquidatorProfitCollateralToken` worth of collateral which is equal to `assignedCollateral`. Doing that will not change the user's collateral at all as `debtPosition.futureValue` and `assignedCollateral` are equal to the same ratio as simply debt:collateral (unless the user doesn't have any other positions, in that case the collateral ratio would go to type(uint256).max).
