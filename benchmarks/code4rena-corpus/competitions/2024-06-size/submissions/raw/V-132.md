# Vulnerability details

## Impact
Transferring collateral tokens to the caller (`msg.sender`) at the end of the function.
```solidity
state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
```
In a self-liquidation scenario, the collateral should be transferred back to the borrower (`debtPosition.borrower`) rather than the caller (`msg.sender`). The current implementation allows anyone to call the `executeSelfLiquidate` function and receive the collateral tokens, even if they are not the borrower.

## Proof of Concept
The `executeSelfLiquidate` function in [SelfLiquidate.sol:executeSelfLiquidate](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L59-L72)

```solidity
    emit Events.SelfLiquidate(params.creditPositionId);

    CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

    uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);

    // debt and credit reduction
    state.reduceDebtAndCredit(creditPosition.debtPositionId, params.creditPositionId, creditPosition.credit);

@>  state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
}
```
1. An attacker can call the `executeSelfLiquidate` function with a valid `creditPositionId`, even if they are not the borrower of the associated debt position.
2. The function retrieves the `CreditPosition` and `DebtPosition` based on the provided `creditPositionId`.
3. The function calculates the `assignedCollateral` using the `getCreditPositionProRataAssignedCollateral` function, determining the pro-rata share of collateral assigned to the credit position.
4. The function reduces the debt and credit using the `reduceDebtAndCredit` function, updating the total debt and credit in the system.
5. Finally, the function transfers the `assignedCollateral` from the borrower's address (`debtPosition.borrower`) to the caller's address (`msg.sender`), allowing the attacker to receive the collateral tokens.

**Impact:**
  - The attacker can steal the collateral tokens associated with any credit position by calling the `executeSelfLiquidate` function, even if they are not the borrower.
  - This vulnerability allows unauthorized access to collateral tokens and can lead to financial losses for the borrowers.
