# Vulnerability details

## Description:
The PriceFeed smart contract allows for flexible configuration of stale price intervals. However, there's a risk of misconfiguration when deploying to networks with different Chainlink price feed update frequencies, particularly on BASE Mainnet L2.

## Poc

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/oracle/PriceFeed.sol#L32

The `stalePriceInterval` is passed as a parameter to the constructor.

```solidity
contract PriceFeed is IPriceFeed {
    uint256 public immutable baseStalePriceInterval;
    uint256 public immutable quoteStalePriceInterval;

    constructor(
        address _base,
        address _quote,
        address _sequencerUptimeFeed,
        uint256 _baseStalePriceInterval,
        uint256 _quoteStalePriceInterval
    ) {
        // ...
        baseStalePriceInterval = _baseStalePriceInterval;
        quoteStalePriceInterval = _quoteStalePriceInterval;
        // ...
    }

    function getPrice() external view returns (uint256) {
        // ...
        return Math.mulDivDown(
            *getPrice(base, baseStalePriceInterval), 10 ** decimals, *getPrice(quote, quoteStalePriceInterval)
        );
    }

    function _getPrice(AggregatorV3Interface aggregator, uint256 stalePriceInterval) internal view returns (uint256) {
        // ...
        if (block.timestamp - updatedAt > stalePriceInterval) {
            revert Errors.STALE_PRICE(address(aggregator), updatedAt);
        }
        // ...
    }
}
```

Based on this, we can see that:

1. `baseStalePriceInterval` and `quoteStalePriceInterval` are set in the constructor and are immutable.
2. These intervals are passed to the `_getPrice` function when it's called within `getPrice()`.

The actual issue is not with the contract's logic, but with how it's deployed and configured for different networks. The problem arises if the contract is deployed with an inappropriate `_baseStalePriceInterval` for the network it's on.

The contract correctly allows for custom `baseStalePriceInterval` and `quoteStalePriceInterval` to be set during deployment. These intervals are used to determine when a price is considered stale.

The contract's comments suggest using a `baseStalePriceInterval` of 3600 seconds, which is appropriate for Ethereum mainnet. On BASE Mainnet L2, the ETH/USD price feed updates approximately every 1200 seconds.

If the contract is deployed on BASE Mainnet L2 with `_baseStalePriceInterval` set to 3600 seconds (as per the comment suggestion), it would consider prices stale less frequently than they are actually updated. This could lead to using outdated prices in calculations.

## Impact:
If misconfigured, the contract might use older price data than necessary, potentially impacting the accuracy of derived prices.


## Recommended Actions:
1. Update the contract comments to highlight the need for network-specific configuration:

```solidity
/// @dev The price is calculated as `base / quote`. Configuration should be adjusted per network:
   ///      _baseStalePriceInterval: 
   ///        - Ethereum Mainnet: 3600 seconds (https://data.chain.link/ethereum/mainnet/crypto-usd/eth-usd)
   ///        - BASE Mainnet L2: 1200 seconds (verify current update frequency)
```

2. Create a deployment checklist that includes verifying the correct stale price intervals for the target network.

3. Consider adding a public function to allow querying of the current Chainlink feed's latest round data, to aid in verification:

```solidity
function getLatestRoundData() external view returns (uint80, int256, uint256, uint256, uint80) {
       return base.latestRoundData();
   }
```

4. Implement a contract upgrade mechanism or admin functions to allow adjustment of stale price intervals post-deployment, if needed.
