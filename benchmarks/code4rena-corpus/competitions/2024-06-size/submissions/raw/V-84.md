# Vulnerability details

## Impact
Ether passed to the `Size::withdraw()` function will be lost for the caller as it is accounted in the contract as balance but not consumed by the withdraw function logic. An abusive depositor can steal the ether by mocking a deposit and consume the deposited ether as collateral deposit amount while not providing any from his end.


## Proof of Concept
`Step 1:`
Lets say, account `0xAAA` is withdrawing tokens. But, he passed 1 ether as below.
(Considering the withdraw function is declared as payable, this is possible potential as user mistake).

Example call as below.
```
size.withdraw{value:1 ether}(WithdrawParams({token: address(weth), amount: 1e6, to: address(`0xAAA`)}));
```

The withdraw function will do its part of execution successfully. The 1 ether passed will remain in the Size contract after the execution was completed. 

`Step 2:`
A depositor can claim the available eth in the contract by calling deposit for collateral and use this available eth for collateral deposit while not providing from his end.

To achieve this abuse, the depositor has to ensure that he passes minimal native tokens to by-pass the below condition and qualify for the consumption of locked ether.

As long as msg.value is not 0, msg.value  is not equal to  params.amount and
params.token is weth, he should by-pass the below condition.

```
    if (msg.value != 0 && (msg.value != params.amount || params.token != address(state.data.weth))) {
            revert Errors.INVALID_MSG_VALUE(msg.value);
        }
```

and to consume the locked ether in the below flow. Since the contract using `address(this).balance`, the deposited amount is available for him to claim it as his.

```
    if (msg.value > 0) {
            // do not trust msg.value (see `Multicall.sol`)
            amount = address(this).balance;
            // slither-disable-next-line arbitrary-send-eth
            state.data.weth.deposit{value: amount}();
            state.data.weth.forceApprove(address(this), amount);
            from = address(this);
        }
```


The depositor will be able to consume the ether locked in the contract as contribution for his deposit for collateral and there by steal the deposited ETH.

Manual Review

## Recommended Mitigation Steps
Remove `payable modifier` from `Size::withdraw()` function. It is not required for withdraw() function.
