# Vulnerability details

## Impact
This could lead to immediate liquidations of otherwise healthy positions or prevent necessary risk parameter adjustments.

## Proof of Concept
The `executeUpdateConfig` function in the `UpdateConfig` has flaw in the validation of the `crLiquidation` parameter:
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/UpdateConfig.sol#L90

```solidity
} else if (Strings.equal(params.key, "crLiquidation")) {
    if (params.value >= state.riskConfig.crLiquidation) {
        revert Errors.INVALID_COLLATERAL_RATIO(params.value);
    }
    state.riskConfig.crLiquidation = params.value;
}
```

This implementation has two major issues:

1. It prevents increasing the liquidation ratio by reverting if the new value is greater than or equal to the current value.
2. It doesn't check if the new liquidation ratio is less than the opening ratio (`crOpening`).

In a lending protocol, the liquidation ratio should always be lower than the opening ratio to provide a safety buffer for borrowers. The current implementation allows setting a liquidation ratio higher than the opening ratio, which could lead to immediate liquidations.

Let's consider a scenario:
Suppose the current configuration is:
- `crOpening`: 150% (1.5 * 1e18)
- `crLiquidation`: 120% (1.2 * 1e18)

An admin could accidentally set `crLiquidation` to 160% (1.6 * 1e18). The current validation would allow this change. As a result:

1. All existing positions with a collateral ratio between 150% and 160% would become immediately liquidatable.
2. New positions couldn't be opened because the liquidation threshold is higher than the opening threshold.

This scenario could lead to a cascade of unnecessary liquidations, causing significant losses for borrowers and even destabilizing the entire protocol.

## Recommended Mitigation Steps
Update the validation check in the `executeUpdateConfig` function to ensure the new liquidation ratio is always less than the opening ratio:

```diff
} else if (Strings.equal(params.key, "crLiquidation")) {
-   if (params.value >= state.riskConfig.crLiquidation) {
+   if (params.value >= state.riskConfig.crOpening) {
        revert Errors.INVALID_COLLATERAL_RATIO(params.value);
    }
    state.riskConfig.crLiquidation = params.value;
}
```

This ensures that:
1. The liquidation ratio can be both increased and decreased as needed, providing flexibility in risk management.
2. The liquidation ratio always remains below the opening ratio, maintaining a safety buffer for borrowers and preventing illogical protocol states.
