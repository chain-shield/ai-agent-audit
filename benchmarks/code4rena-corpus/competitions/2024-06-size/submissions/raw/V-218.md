# Vulnerability details

## Impact
A lender’s creditpositionid can be bought by another lender. If the new apr is bigger than the previous apr when a new lender buys the previous lender’s creditpositionid, then the previous lender will lose some borrowAmount.

## Proof of Concept
1. Let’s assume, Alice(borrower) creates a borrow offer with 3 months(5% apr), 4 months(6% apr), 5 months(7% apr). bob(another user) also creates a borrow offer with 3 months(8% apr), 4 months(9% apr), 5 months(10% apr).

2. Now Bob calls the function buyCreditMarket with Alice as borrower,  5 months(7% apr) as tenor, amount 100e18,  exactAmountIn is  true on January 1st. 

3. Now a creditPositionId(assume id is 1) is created and its lender is bob,  borrower is alice, futureValue is 107  ,  dueDate is june 1 and forSale: true.

4. After 2 months , john calls the function buyCreditMarket with amount 99.07e18,  exactAmountIn is  true and creditPositionId is 1 to buy the creditPositionId.

5. See  function executeBuyCreditMarket, as here params.creditPositionId is not equal to  RESERVED_ID, so here  borrower = creditPosition.lender = bob, tenor = debtPosition.dueDate - block.timestamp = 3 months. Bob’s 3 months(tenor) apr is 8%(see bob’s borrow offer above).

6. As params.exactAmountIn is true, the getCreditAmountOut function is called with cashAmountIn = 99.07e18, maxCashAmountIn = 99.07e18, maxCredit = 107e18. getCreditAmountOut function, as cashAmountIn is equal to maxCashAmountIn, so the getCreditAmountOut returns creditAmountOut = 107e18. Now creditPositionId 1’s lender is john and credit is 107e18.

7.  The problem is the previous lender(Bob) gets 99.07e18(ignore fees) borrowAToken but Bob should get more than 100e18  borrowAToken with profit.


## Tools Used
manual review

## Recommended Mitigation Steps

Make sure apr should be bigger than previous lender’s apr when a  lender buy creditpositionid from another lender.
