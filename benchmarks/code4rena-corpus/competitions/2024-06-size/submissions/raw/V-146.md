# Vulnerability details

## Impact
`executeLiquidate()` when triggered by a caller and transfer funds into the size contract for borrowed tokens worth `futureValue`, the logic transfers the collateral from borrower's account to the caller's account. Like wise, a fee applicable is also transfer from Borrow's account to fee fee Recipient account.

The vulnerability is that the transfers are performed using `transferFrom` function which needs prior approval from the token owner to spend the tokens to be processed by the transaction. The issue is that liquidation will happen in future time period when circumstances arise. 

The token owner has the power to revoke the approvals granted at any time by passing the approved amount as 0. Subsequent to that, the parties will not be able to perform `transferFrom()` on owner account[`debtPosition.borrower` in this context].

As the tokens are being pulled at the time of liquidation, if the `debtPosition.borrower` revokes the approvals, then `transferFrom` will fail for both collateral and fees.

But the bigger problem is that, the `transferFrom's` return value is not being checked in the logic and hence it would look as if the transfer occurred. 

Pulling those tokens from the borrower at the time of liquidation is risky. Also not checking the return value of `transferFrom` is also equally risky. The transaction will not revert making the account record as if the borrowed position was closed while there is not actual settlement between the parties as transactions failed.

Essentially, the liquidation will fail.

## Proof of Concept
Refer to the below lines in `executeLiquidate()` function in `liquidate` action library.

```solidity
   state.data.borrowAToken.transferFrom(msg.sender, address(this), debtPosition.futureValue);
        state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, liquidatorProfitCollateralToken);
        state.data.collateralToken.transferFrom(
            debtPosition.borrower, state.feeConfig.feeRecipient, protocolProfitCollateralToken
        );
```

## Recommended Mitigation Steps
The tokens should be deposited in the current contract to perform the transfer when the liquidator attempts to close the debt position by depositing the future value of borrowed tokens. Having the tokens in the contract will ensure a smooth liquidation.
