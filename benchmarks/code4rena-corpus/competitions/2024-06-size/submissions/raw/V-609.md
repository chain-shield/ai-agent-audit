# Vulnerability details

## Description
As per [main invariants](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/README.md?plain=1#L289) of Size protocol, during a liquidation process the collaterals of the sender (liquidator) must increase. We can see it here at [LIQUIDATE_01](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/README.md?plain=1#L303C1-L303C58) :

```md
- LIQUIDATE_01: Liquidate increases the sender collateral
```

However, this is not always the case since the protocol let a user to liquidate his own ```DebtPosition``` if this position is liquidatable meaning he is underwater. So, in the case the liquidator is the same address with the borrower of the position, this will result to the collaterals of the sender to be, actually, decreased due to the ```protocolProfitCollateralToken``` which will be send to the protocol.

## Proof of Concept
To confirm this break of LIQUIDATE_01 invariant, add this test in ```Liquidate.t.sol``` and run ```forge test --mt test_Liquidate_broken_LIQUIDATE_01_invariant ``` :

```solidity
    function test_Liquidate_broken_LIQUIDATE_01_invariant() public {
        _setPrice(1e18);

        _deposit(alice, weth, 100e18);
        _deposit(alice, usdc, 100e6);
        _deposit(bob, weth, 100e18);
        _deposit(bob, usdc, 100e6);

        _buyCreditLimit(alice, block.timestamp + 365 days, YieldCurveHelper.pointCurve(365 days, 0.03e18));
        uint256 amount = 15e6;
        uint256 debtPositionId = _sellCreditMarket(bob, alice, RESERVED_ID, amount, 365 days, false);

        _setPrice(0.2e18);
        assertTrue(size.isDebtPositionLiquidatable(debtPositionId));

        uint256 collateralsBefore = size.getUserView(bob).collateralTokenBalance;
        
        _liquidate(bob, debtPositionId);

        uint256 collateralsAfter = size.getUserView(bob).collateralTokenBalance;

        assertTrue(collateralsBefore > collateralsAfter);
    }
```

## Impact
The finding reveals that the Size protocol allows self-liquidation, breaking the LIQUIDATE_01 invariant that mandates liquidator collateral must increase. Invariants are crucial for protocol integrity and must not be broken to ensure user trust and predictable outcomes

## Tools Used
Manual review, Foundry

## Recommended Mitigation Steps
Consider reviewing the invariants of the protocol or do not let the liquidator of a ```DebtPosition``` to be tha same with the borrowed of it.
