# Vulnerability details

## Impact
**Impact of Incorrect Collateral Allocation in `getDebtPositionAssignedCollateral`**
`getDebtPositionAssignedCollateral` can have significant downstream impacts on the Size protocol, particularly in scenarios involving:

   * Inaccurate collateral allocation can lead to incorrect determination of whether a debt position is eligible for liquidation. This could result in:
     - **Premature Liquidations:** A debt position with sufficient collateral might be incorrectly liquidated if the function underestimates its assigned collateral.
     - **Delayed Liquidations:** A risky debt position with insufficient collateral might not be liquidated on time if the function overestimates its assigned collateral.

   * The protocol relies on accurate collateralization ratios for risk assessment and parameter tuning. Incorrect collateral allocation can misrepresent the system's overall health

## Proof of Concept

**Scenario**

We'll simulate a scenario with two borrowers, each having two debt positions. We'll then analyze how the incorrect collateral allocation can lead to inaccurate liquidation calculations.

**Assumptions:**
   * **Borrower A:**
     - Debt Position 1: futureValue = 1000, dueDate = block.timestamp + 1 week
     - Debt Position 2: futureValue = 2000, dueDate = block.timestamp + 2 weeks
     - Total Collateral: 2500

   * **Borrower B:**
     - Debt Position 1: futureValue = 500, dueDate = block.timestamp + 1 week
     - Debt Position 2: futureValue = 1500, dueDate = block.timestamp + 2 weeks
     - Total Collateral: 1500

   * Liquidation Threshold: 150% (This means a debt position is eligible for liquidation if its collateral value drops below 150% of its debt value).

LoanLibrary.sol (with the bug): [src/libraries/LoanLibrary.sol#148-160](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L148-L161)
```solidity
function getDebtPositionAssignedCollateral(State storage state, DebtPosition memory debtPosition)
    public
    view
    returns (uint256)
{
    uint256 debt = state.data.debtToken.balanceOf(debtPosition.borrower); // **BUG:** Uses total borrower debt
    uint256 collateral = state.data.collateralToken.balanceOf(debtPosition.borrower); // **BUG:** Uses total borrower collateral

    if (debt != 0) {
        return Math.mulDivDown(collateral, debtPosition.futureValue, debt);
    } else {
        return 0;
    }
}
```
**Hypothetical Liquidation Logic (for demonstration)**
```solidity
function isLiquidatable(DebtPosition memory debtPosition) public view returns (bool) {
    uint256 assignedCollateral = getDebtPositionAssignedCollateral(state, debtPosition);
    // Assuming collateral value is equal to collateral amount for simplicity
    if (assignedCollateral * 100 < debtPosition.futureValue * 150) { 
        return true; // Liquidatable if collateral value is less than 150% of debt
    }
    return false;
}
```
**Analysis:**
1. Incorrect Collateral Allocation:
     - **Borrower A:**
       * Debt Position 1: (2500 * 1000) / 3000 = 833.33 (Incorrect)
       * Debt Position 2: (2500 * 2000) / 3000 = 1666.67 (Incorrect)
     - **Borrower B:**
Debt Position 1: (1500 * 500) / 2000 = 375 (Incorrect)
Debt Position 2: (1500 * 1500) / 2000 = 1125 (Incorrect)

2. Inaccurate Liquidation Determination:
     - **Borrower A:**
       * Debt Position 1: Even though the actual collateralization is above 150% (2500 > 1500), the function might incorrectly flag it for liquidation due to the underestimated assigned collateral (833.33 < 1500).

     - **Borrower B:**
       * Debt Position 2: The function might incorrectly consider it safe from liquidation due to the overestimated assigned collateral (1125 > 750), even though the actual collateralization is below 150% (1500 < 2250).

**Impact:**
This inaccurate liquidation determination can lead to:
   * Borrowers like Borrower A could be unfairly liquidated even if they have sufficient collateral.
   * Borrowers like Borrower B might not be liquidated on time, potentially leading to bad debt and protocol losses.

## Recommended Mitigation Steps
The function needs to be redesigned to track and use the debt and collateral associated with each individual debt position, rather than relying on the borrower's total balances.
