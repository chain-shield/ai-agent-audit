# Vulnerability details

## Impact
The `assignedCollateral` variable is not being used correctly. It is being assigned to the `state.data.collateralToken.transferFrom()`, but it should be passed as an argument instead.

## Proof of Concept
The use of the `assignedCollateral` variable in the `executeSelfLiquidate()` function. The bug is that the variable is not being used correctly, and it should be passed as an argument instead of being assigned to the `state.data.collateralToken.transferFrom()` function.

**Explanation of the finding:**
The `executeSelfLiquidate()` is responsible for executing the self-liquidation of a credit position. The function takes two parameters: `state` and `params`. The state parameter is an object that contains all the necessary data for the self-liquidation, while the `params` parameter is an object that contains the input parameters for the self-liquidation.

Inside the function, there is a line of code that assigns the value of the `assignedCollateral` variable to the `state.data.collateralToken.transferFrom()` function: [src/libraries/actions/SelfLiquidate.sol#L70](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L70)
```solidity
state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
```
However, this is not correct. The `assignedCollateral` variable should be passed as an argument to the transferFrom() function instead of being assigned to it.

```solidity
--- state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);

+++ state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, params.assignedCollateral);
```
