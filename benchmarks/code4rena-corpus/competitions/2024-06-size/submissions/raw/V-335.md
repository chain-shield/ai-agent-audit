# Vulnerability details

## Impact
In the `DepositTokenLibrary.sol` file, the `depositUnderlyingBorrowTokenToVariablePool` function makes external calls to the Variable Pool contract and the underlying borrow token contract. These calls can potentially return large amounts of data, which is automatically loaded into memory. This can lead to excessive gas consumption, especially if an attacker manipulates the contracts to return unnecessarily large amounts of data.

An attacker could potentially cause transactions to consume excessive amounts of gas, leading to transaction failures or unnecessarily high gas costs for users. In extreme cases, this could make certain functions in the protocol prohibitively expensive to use, effectively causing a denial of service.

An attacker could make functions in the contract prohibitively expensive to call by causing them to process large amounts of return data. This could effectively render parts of the contract unusable.

Economic Attacks:
Users might be charged extremely high gas fees for what should be simple operations. This could drain users' funds or make the protocol economically unviable to use. If this happens, users would not be able to repay their debt on time, and could get liquidated even when they are trying to add collateral.

The gas cost doesn't increase linearly with data size. There's a significant jump between 100,000 and 1,000,000 bytes, suggesting potential quadratic or worse scaling.

## Recommended Mitigation Steps
Implement a maximum size limit for returned data from external calls. This can be done using assembly to limit the amount of data copied to memory.

Use low-level calls instead of high-level calls for functions where you don't need to process the return data.

Consider implementing a two-step process where you first check the size of the return data before deciding to copy it to memory.
