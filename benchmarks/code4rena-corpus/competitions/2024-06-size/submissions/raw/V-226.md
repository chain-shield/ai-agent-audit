# Vulnerability details

`liquidateWithReplacement` is a access control function used to match a new borrower with a credit position id that his deb was liquidated.

To understand this we have to see the `validateLiquidateWithReplacement` function:

```solidity

  function validateLiquidateWithReplacement(State storage state, LiquidateWithReplacementParams calldata params)
        external
        view
    {
        DebtPosition storage debtPosition = state.getDebtPosition(params.debtPositionId);
        BorrowOffer storage borrowOffer = state.data.users[params.borrower].borrowOffer;

    ...
        // validate borrower
        if (borrowOffer.isNull()) { <------
            revert Errors.INVALID_BORROW_OFFER(params.borrower);
        }

```
[[Link]](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L72)

As you can see the function is checking is the `borrowOffer` exist. with that been said a malicious borrower can cancel his offer making revert the liquidation.


## Impact
A malicious borrower can cancel out the offer making revert the `liquidateWithReplacement` function, this normally will not be a medium severity but since this is a liquidation it may be, in time with high volatility that prices are dropping so hard a fail transaction may be the different between a not profitable liquidation and a profitable liquidation.

## Proof of Concept
As you can see in the arrow below a borrower can front run the `validateLiquidateWithReplacement` canceling out his offer in other tx sent it with higher gas.
