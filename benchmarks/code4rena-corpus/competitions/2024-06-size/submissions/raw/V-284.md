# Vulnerability details

## Impact 
repayment is a healthy operation, that should always be allowed as it improves the health of the protocol in general. In compensate howeveer the protocol checks the health factor of the position after compensation is done with `state.validateUserIsNotUnderwater(msg.sender);`, this check will always fail if the user is underwater (cr  < minCollateralisationRatio (either the one set by the user or the one set by the protocol (max))) after the compensation, and thus always preventing users from partially repaying their positions.

## Proof of concept

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L247-L251
```solidity
    function compensate(CompensateParams calldata params) external payable override(ISize) whenNotPaused {
            // * Compensate a borrower's debt with his credit in another loan
            // NOTE validate the enough credit (and healthy) and the owner of credditCompensate same as borrower of debtPositionToRepay
            state.validateCompensate(params);
            state.executeCompensate(params);
            // NOTE validate user is not underwater after the repayment
            // @audit-issue this will revert if the user position is still liquidatable after the repayment 
            state.validateUserIsNotUnderwater(msg.sender);
        }
```
In the compensate function transaction will always fail if the cr of the user is negative.
E.g:

- User owns multiple small Credit positions in the protocol and have set the minCollateralisationRatio to 150% and doesn't want his cr to go bellow it (protocol minCR= 130%)
- The user position Cr has dropped bellow 150% and the user will want to improve his health
- The user chooses to use his multiple creditPositions to repay his debt in a multicall to improve the health of his position
- all the compensate() call that the user will call will revert because neither of his small credit position will bring the health of his position up to 150% in one go
## recomendation
we should allways allow partial repayment as long as the repaid amount > fragemnetation fee, as it will improve the borrower health and protects the solvancy of the protocol. In the case if the params.creditPositionToCompensateId == RESRVED_ID we should also check for the health because there was no repayment done yet (only the debt Position is split)
