# Vulnerability details

## Impact
The function `Withdraw::executeWithdraw()` using a inaccurate amount of underlying tokens to be withdrawn from the AAVE pool, result in withdrawing less than the intended amount.

## Proof of Concept
The function `Withdraw::executeWithdraw()` withdraws the minimum amount of user input `params.amount` or aToken balance of `msg.sender`, [L56-L58](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Withdraw.sol#L55-L57):

```solidity
amount = Math.min(params.amount, state.data.borrowAToken.balanceOf(msg.sender));
if (amount > -1) {
	state.withdrawUnderlyingTokenFromVariablePool(msg.sender, params.to, amount);
}
```

Then, the function `withdrawUnderlyingTokenFromVariablePool()` withdraws this amount from AAVE pool, [L83](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/DepositTokenLibrary.sol#L83):

```solidity
state.data.variablePool.withdraw(address(state.data.underlyingBorrowToken), amount, to);
```

However, the `amount` parameter of AAVE pool `withdraw()` is the " underlying amount to be withdrawn".

https://github.com/aave/aave-v3-core/blob/master/contracts/interfaces/IPool.sol#L280:
```solidity
   * @param amount The underlying amount to be withdrawn
   *   - Send the value type(uint256).max in order to withdraw the whole aToken balance
   * @param to The address that will receive the underlying, same as msg.sender if the user
   *   wants to receive it on his own wallet, or a different address if the beneficiary is a
   *   different wallet
   * @return The final amount withdrawn
   */
  function withdraw(address asset, uint256 amount, address to) external returns (uint256);
```

The `amount` parameter for the AAVE pool `withdraw()` function represents the underlying token amount, not the aToken balance. This discrepancy can lead to inaccurate withdrawal amounts.

## Recommended Mitigation Steps
Remove [L55](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/actions/Withdraw.sol#L55) and correctly calculate the amount of underlying tokens.
