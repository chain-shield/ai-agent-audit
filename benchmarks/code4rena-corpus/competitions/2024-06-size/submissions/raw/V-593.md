# Vulnerability details

## Impact
The `liquidateWithReplacement` function liquidates a debt position with a replacement borrower. The issue is that the replacement borrower is not charged the necessary swap fee, that every borrower should pay when borrowing. As a result, borrowers gain a discount on their loans and the protocol's fee recipient suffers a loss of funds, due to not receiving the required swap fees.

## Proof of Concept
As we can see in `liquidateWithReplacement`, the cash that the borrower receives is calculated as follows:
```solidity
issuanceValue = Math.mulDivDown(debtPositionCopy.futureValue, PERCENT, PERCENT + ratePerTenor);
```
This, however, is wrong as the future credit value is always calculated in consideration of the swap fees:
(example from SellCreditMarket.executeSellCreditMarket)
```solidity
maxCredit: Math.mulDivUp(cashAmountOut, PERCENT + ratePerTenor, PERCENT - state.getSwapFeePercent(tenor))
```
We can see that it is intended for the cash, sent to the user, to be scaled by both the rate per tenor and the swap fee percent.

Therefore, when the `liquidateWithReplacement` is used, the replacement borrower receives an amount (`issuanceValue`) of cash that has not been scaled down by the swap fee percent. As a result, the borrower is transferred too much of the borrow token and the protocol suffers a loss of funds.

## Tools Used
Manual review

## Recommended Mitigation Steps
Scale down the `issuanceValue` bu the swap fee percent:
```solidity
issuanceValue = Math.mulDivDown(debtPositionCopy.futureValue, PERCENT - state.getSwapFeePercent(tenor), PERCENT + ratePerTenor);
```
