# Vulnerability details

## Impact
The `executeBuyCreditMarket` makes an incorrect assumption on the maximum amount of cash that can be provided when `params.creditPositionId != RESERVED_ID`. As a result, valid attempts to buy credit will fail.

## Proof of Concept
When `params.creditPositionId != RESERVED_ID` the `maxCashAmountIn` is set to:
```solidity
Math.mulDivUp(creditPosition.credit, PERCENT, PERCENT + ratePerTenor)
```
This however is lower than the actual maximum cash a credit position is worth.
This occurs because of the fragmentation fee which is NOT included when calculating the `creditAmountOut`:
```solidity
uint256 netCashAmountIn = cashAmountIn - state.feeConfig.fragmentationFee;


creditAmountOut = Math.mulDivDown(netCashAmountIn, PERCENT + ratePerTenor, PERCENT);
```
As we can see, the fragmentation fee is subtracted from `cashAmountIn` and after that `creditAmountOut` is calculated.

Therefore, the actual maximum cash that the position's credit is worth is actually greater than the current way of calculating `maxCashAmountIn` by an amount equal to the fragmentation fee.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider setting the `maxCashAmountIn` when `params.creditPositionId != RESERVED_ID` to:
```solidity
Math.mulDivUp(creditPosition.credit, PERCENT, PERCENT + ratePerTenor) + state.feeConfig.fragmentationFee
```
