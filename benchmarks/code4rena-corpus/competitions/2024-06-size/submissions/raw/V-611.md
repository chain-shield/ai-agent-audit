# Vulnerability details

## Impact
The `executeLiquidateWithReplacement` function in `LiquidateWithReplacement.sol` rounds in the wrong direction when calculating the issuance value, causing the borrower to receive less funds than expected and breaking the invariant that rounding should favour the 'maker'.

## Proof of Concept
Here is how `issuanceValue` is calculated in `executeLiquidateWithReplacement`:
```solidity
issuanceValue = Math.mulDivDown(debtPositionCopy.futureValue, PERCENT, PERCENT + ratePerTenor);
```
As we can see the value is rounded down, when it should be up, as in the case the 'maker' is the replacement borrower.

## Tools Used
Manual review

## Recommended Mitigation Steps
Round `issuanceValue` up:
```solidity
issuanceValue = Math.mulDivUp(debtPositionCopy.futureValue, PERCENT, PERCENT + ratePerTenor);
```
