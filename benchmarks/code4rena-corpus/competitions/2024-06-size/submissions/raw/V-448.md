# Vulnerability details

## Impact
If the `crOpening` is increased through the `executeUpdateConfig()` function, positions that could have been liquidated with replacement will no longer be eligible, preventing necessary liquidations and borrower replacements. The reason is that the `executeUpdateConfig()` function does not check whether it will put any existing users below the new collateral ratio. Thus, the `liquidateWithReplacement()` function that has the below check will revert:

```
state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
```

Additionally, increasing the `crOpening` can also mean that existing users will be prevented from withdrawing their tokens when calling the `withdraw()` function if they fall below the threshold.

The only way for these users to get their funds unstuck is to deposit new tokens to increase their CR to the new `crOpening`.

Although this scenario would only occur due to an admin misconfiguration, it is important to note that the `liquidateWithReplacement()` function is intended to work exactly like liquidate, with an added logic of replacing the borrower in storage, as per the `ISize.sol` developer comments.

The FAQ addresses the issue of admin misconfiguration for `crLiquidation`, explaining that an increase could instantly make borrowers liquidatable, and includes the following check to prevent this:

```
 if (params.value >= state.riskConfig.crLiquidation) { //@audit new liquidation value must be lower than current
                revert Errors.INVALID_COLLATERAL_RATIO(params.value);
            }
```

However, similar validation and consideration are missing for `crOpening`, suggesting that this check has been overlooked.

Manual Review.

## Recommended Mitigation Steps
Store the `crOpening`  in the `DebtPosition` struct at the time of a new debt position creation. Adding a field to the DebtPosition struct would prevent issues with withdrawing and liquidation with replacement if  `crOpening` is increased by the admin:
```
struct DebtPosition {
    // The borrower of the loan
    // Set on loan creation; 
... 

    // The liquidity index of the Variable Pool at the repayment
    // Set on full repayment
    uint256 liquidityIndexAtRepayment;
    // crOpening at the debtPosition creation
    uint256 crOpeningAtCreation //<= Add THIS TO THE STRUCT 
}
```
This `crOpeningAtCreation` would be checked when withdrawing and during liquidation with replacement.
