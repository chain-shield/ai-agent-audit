# Vulnerability details

## Impact
`validateInitializeRiskConfigParams()` validates the parameters for the risk configuration. This internal function ensures that `minimumCreditBorrowAToken` is greater than 0.
```
if (r.minimumCreditBorrowAToken == 0) {
            revert Errors.NULL_AMOUNT();
        }
```
`validateInitializeFeeConfigParams()` validates the parameters for the fee configuration, however, no validation is performed on `fragmentationFee` in this function or in the `executeUpdateConfig()` function. 

As a result, a `fragmentationFee` greater or equal to `minimumCreditBorrowAToken` is allowed. 
If `fragmentationFee` is set greater or equal to `minimumCreditBorrowAToken` and a user tries to buy an existing credit by calling buyCreditMarket() with an exact amount in equal to the `minimumCreditBorrowAToken`:
- The transaction will revert with `NOT_ENOUGH_CASH` error in the case of a `fragmentationFee` greater than `minimumCreditBorrowAToken`, 
- or with `CREDIT_LOWER_THAN_MINIMUM_CREDIT` error in the case of a `fragmentationFee` equal to `minimumCreditBorrowAToken`.

The configured parameters should ensure a good user experience, so user transactions should not revert as long as the required minimum amounts are met.

## Proof of Concept
Paste the following POC in `BuyCreditMarket.t.sol`
```
    function test_BuyCreditMarket_buyCreditMarket_Dos() public {
        _setPrice(1e18);

        // Lenders should be able to buy 4e6 credit
        _updateConfig("minimumCreditBorrowAToken", 4e6);

        _deposit(alice, usdc, 1000e6);
        _deposit(bob, weth, 1600e18);
        _deposit(james, weth, 1600e18);
        _deposit(james, usdc, 1000e6);

        _buyCreditLimit(alice, block.timestamp + 365 days, YieldCurveHelper.pointCurve(365 days, 1e18));
        _sellCreditLimit(alice, YieldCurveHelper.pointCurve(365 days, 1e18));

        uint256 debtPositionId1 = _sellCreditMarket(bob, alice, 100e6, 365 days, false);
        uint256 creditPositionId1_1 = size.getCreditPositionIdsByDebtPositionId(debtPositionId1)[0];

        // amountIn = minimumCreditBorrowAToken
        uint256 amountIn = 4e6;

        // DoS when amountIn < fragmentationFee
        vm.expectRevert(abi.encodeWithSelector(Errors.NOT_ENOUGH_CASH.selector, 5e6, 4e6));
        _buyCreditMarket(james, creditPositionId1_1, amountIn, true);

        // amountIn = fragmentationFee
        amountIn = 5e6;

        // DoS when amountIn = fragmentationFee
        vm.expectRevert(abi.encodeWithSelector(Errors.CREDIT_LOWER_THAN_MINIMUM_CREDIT_OPENING.selector, 0, 4e6));
        _buyCreditMarket(james, creditPositionId1_1, amountIn, true);
    }
```

## Recommended Mitigation Steps
In order to avoid such configuration, check that `minimumCreditBorrowAToken` is greater or equal than twice the amount of `fragmentationFee`
Add the following check in UpdateConfig.sol::executeUpdateConfig()
```
[...]
} else if (Strings.equal(params.key, "minimumCreditBorrowAToken")) {
    if (params.value <= (2 * state.feeConfig.fragmentationFee)) {
                revert Errors.INVALID_MIN_CREDIT_BORROW_TOKEN(params.value);
            }
            state.riskConfig.minimumCreditBorrowAToken = params.value;
[...]
} else if (Strings.equal(params.key, "fragmentationFee")) {
if ((params.value * 2) >= state.feeConfig.fragmentationFee) {
                revert Errors.INVALID_FRAGMENTATION_FEE(params.value);
            }
            state.feeConfig.fragmentationFee = params.value;
```
