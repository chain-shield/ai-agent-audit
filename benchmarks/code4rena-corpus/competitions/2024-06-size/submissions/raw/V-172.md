# Vulnerability details

## Impact
Impact of Incorrect Borrower Rate Calculation in `executeLiquidateWithReplacement` function calculates the `ratePerTenor` for the new borrower (`params.borrower`) using their `borrowOffer`. However, the liquidated debt position might have a different `dueDate` and therefore a different tenor than what the new borrower's `borrowOffer` is set up for. This bug has significant implications for the Size protocol, leading to financial losses and unfair advantages for malicious actors.

**1. Incorrect Interest Calculation**
**Code:** The `ratePerTenor` is calculated using the new borrower's `borrowOffer` [(src/libraries/actions/LiquidateWithReplacement.sol#lines 138-145)](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L138-L145)
```solidity
uint256 ratePerTenor = borrowOffer.getRatePerTenor(
    VariablePoolBorrowRateParams({
        variablePoolBorrowRate: state.oracle.variablePoolBorrowRate,
        variablePoolBorrowRateUpdatedAt: state.oracle.variablePoolBorrowRateUpdatedAt,
        variablePoolBorrowRateStaleRateInterval: state.oracle.variablePoolBorrowRateStaleRateInterval
    }),
    tenor
);
```
* **Problem**: This rate might not reflect the actual interest cost for the transferred debt. The original debt position's `dueDate` (and thus its tenor) could differ from what the new borrower's `borrowOffer` is configured for.

* **Example**: Imagine a debt position with a `dueDate` in 1 month, while the new borrower's `borrowOffer` is set for a 6-month tenor with a lower interest rate. The calculated `issuanceValue` will be higher (and `liquidatorProfitBorrowToken` lower) than it should be, as it's based on the 6-month rate instead of the actual 1-month rate.

**2. Potential for Exploitation:**
**Scenario**: A malicious liquidator identifies a debt position with a short remaining tenor and a high interest rate. They then find a new borrower with a borrowOffer configured for a longer tenor and a lower interest rate.

* **Exploitation**: Using executeLiquidateWithReplacement, the liquidator can exploit the rate discrepancy. They acquire the debt at a discounted price (due to the incorrect issuanceValue) and potentially pass on a less favorable rate to the new borrower.

* **Consequences**: This can lead to:
     - **Loss for the Protocol**: If the actual interest earned is less than what was accounted for, the protocol might experience a loss.
     - **Unfair Advantage for Liquidator**: The liquidator profits unfairly by exploiting the rate difference.
     - **Disgruntled Borrowers: New borrowers might pay a higher interest rate than anticipated based on their `borrowOffer`.

## Proof of Concept
The `liquidateWithReplacement` function is called the flawed [`executeLiquidateWithReplacement` function. src/Size.sol](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L229-L244)
```solidity
function liquidateWithReplacement(LiquidateWithReplacementParams calldata params)
    external
    payable
    override(ISize)
    whenNotPaused
    onlyRole(KEEPER_ROLE)
    returns (uint256 liquidatorProfitCollateralToken, uint256 liquidatorProfitBorrowToken)
{
    state.validateLiquidateWithReplacement(params);
    uint256 amount;
    (amount, liquidatorProfitCollateralToken, liquidatorProfitBorrowToken) =
        state.executeLiquidateWithReplacement(params);
    state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
    state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
    state.validateVariablePoolHasEnoughLiquidity(amount);
}
```
**Scenario:**
1. **Existing Debt Position**: A debt position exists with a `dueDate` in 1 month and a future value of 110 tokens (including a 10% interest rate for the month).
2. **New Borrower**: A new borrower has a `borrowOffer` configured for a 6-month tenor with a 5% interest rate per 6 months.
3. **Malicious Liquidator**: A liquidator identifies this opportunity and uses `executeLiquidateWithReplacement` to take over the debt, intending to exploit the rate difference.

Focus on rate calculation and issuance value
```solidity
function executeLiquidateWithReplacement(State storage state, LiquidateWithReplacementParams calldata params)
    external
    // ...
{
    // ...

    uint256 tenor = debtPositionCopy.dueDate - block.timestamp; // Tenor = 1 month

    // **BUG:** Using new borrower's borrowOffer for rate calculation
    uint256 ratePerTenor = borrowOffer.getRatePerTenor(
        // ... parameters ...
        tenor 
    ); 
    // Assume getRatePerTenor returns 5% (annualized) even for a 1-month tenor due to a bug

    issuanceValue = Math.mulDivDown(debtPositionCopy.futureValue, PERCENT, PERCENT + ratePerTenor); 
    // issuanceValue is calculated based on a 5% annualized rate, even though the remaining tenor is 1 month.

    // ...
}
```
**Impact**
   1. The `issuanceValue` will be calculated based on a 5% annualized rate, even though the remaining tenor is only 1 month. This results in a higher `issuanceValue` than it should be.
   2. The liquidator effectively acquires the debt at a discount, as they pay a lower price due to the inflated `issuanceValue`.
   3. The protocol or the new borrower might experience a loss, as the actual interest earned over the remaining 1 month will be lower than what was accounted for during the `issuanceValue` calculation.

**Proof**
Let's assume `PERCENT` is 100.

**1. Correct Calculation (1-month rate)**
    - The 1-month rate, extrapolated from the 10% interest for the entire loan term, would be approximately 0.83% (10% / 12 months).
    - `issuanceValue` should be calculated using this 0.83% rate.

**2. Incorrect Calculation (using 5% annualized rate)**
    - The code incorrectly uses the 5% annualized rate from the new borrower's `borrowOffer`.
    - This leads to a significantly higher `issuanceValue`, as the discount applied is much more significant than it should be for a 1-month tenor.

## Recommended Mitigation Steps
The `ratePerTenor` should be calculated based on the original debt position's `dueDate` and the current market rates, not the new borrower's `borrowOffer`. This ensures the interest calculation is accurate and reflects the actual cost of taking over the debt.
