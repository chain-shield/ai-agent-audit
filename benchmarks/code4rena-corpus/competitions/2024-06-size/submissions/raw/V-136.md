# Vulnerability details

## Description
According to the technical documentation, the self-liquidation process should allow lenders to liquidate their positions and recover their collateral without any fees being charged. However, the current implementation reduces the position's debt and credit before transferring the assigned collateral to the lender, which may result in an incorrect amount of collateral.

Now, the impact of reducing the debt and credit before transferring the collateral
1. The [`getCreditPositionProRataAssignedCollateral`](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/LoanLibrary.sol#L170-L185) calculates the assigned collateral based on the current credit position's credit amount:
```solidity
function getCreditPositionProRataAssignedCollateral(State storage state, CreditPosition storage creditPosition)
    external
    view
    returns (uint256)
{
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(creditPosition.id);
    return Math.mulDivDown(debtPosition.assignedCollateral, creditPosition.credit, debtPosition.faceValue);
}
```
2. If the debt and credit are reduced before transferring the collateral, the `assignedCollateral` value calculated earlier may not reflect the correct pro-rata share of the collateral based on the updated credit amount.

3. As a result, the lender may receive an incorrect amount of collateral, which could be less than what they are entitled to based on their credit position.

**To illustrate this, let's consider an example**
   - Suppose a debt position has a face value of 1000 tokens and an assigned collateral of 1500 tokens.
   - A credit position has a credit amount of 500 tokens.
   - The pro-rata assigned collateral for the credit position would be: (1500 * 500) / 1000 = 750 tokens.
   - If 500 tokens reduce the debt and credit before transferring the collateral, the debt position's face value becomes 500 tokens, and the credit position's credit becomes 0 tokens.
   - However, the `assignedCollateral` value calculated earlier remains at 750 tokens, more than the total assigned collateral of the debt position after the reduction.
   - Transferring 750 tokens to the lender would be incorrect, as it exceeds their pro-rata share based on the updated credit amount.

## Proof of Concept
First, let's define the relevant structs and functions
```js
struct DebtPosition {
    uint256 faceValue;
    uint256 assignedCollateral;
    // other fields
}

struct CreditPosition {
    uint256 id;
    uint256 credit;
    // other fields
}

function getCreditPositionProRataAssignedCollateral(State storage state, CreditPosition storage creditPosition)
    external
    view
    returns (uint256)
{
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(creditPosition.id);
    return Math.mulDivDown(debtPosition.assignedCollateral, creditPosition.credit, debtPosition.faceValue);
}

function reduceDebtAndCredit(
    State storage state,
    uint256 debtPositionId,
    uint256 creditPositionId,
    uint256 credit
) external {
    DebtPosition storage debtPosition = state.getDebtPosition(debtPositionId);
    CreditPosition storage creditPosition = state.getCreditPosition(creditPositionId);

    debtPosition.faceValue -= credit;
    creditPosition.credit -= credit;

    emit Events.ReduceDebtAndCredit(debtPositionId, creditPositionId, credit);
}
```
Now, a test case to demonstrate the bug
```solidity
function testSelfLiquidateBug() public {
    // Setup initial state
    DebtPosition storage debtPosition = state.createDebtPosition();
    debtPosition.faceValue = 1000;
    debtPosition.assignedCollateral = 1500;

    CreditPosition storage creditPosition = state.createCreditPosition();
    creditPosition.id = 1;
    creditPosition.credit = 500;

    // Calculate the expected pro-rata assigned collateral
    uint256 expectedAssignedCollateral = getCreditPositionProRataAssignedCollateral(state, creditPosition);
    assertEq(expectedAssignedCollateral, 750);

    // Simulate the buggy execution order
    reduceDebtAndCredit(state, debtPosition.id, creditPosition.id, creditPosition.credit);
    uint256 actualAssignedCollateral = getCreditPositionProRataAssignedCollateral(state, creditPosition);

    // Verify the bug
    assertEq(actualAssignedCollateral, 0);
    assertEq(debtPosition.faceValue, 500);
    assertEq(creditPosition.credit, 0);
}
```
We can see that reducing the debt and credit before calculating and transferring the assigned collateral leads to an incorrect result, where the lender receives 0 collateral instead of the expected 750.

## Recommended Mitigation Steps
I recommend moving the debt and credit reduction after the collateral transfer to ensure that the lender receives the correct amount of collateral. By making this change, the lender will receive the correct amount of collateral before the debt and credit are reduced, aligning the implementation with the intended behavior of the self-liquidation process.
```solidity
uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);

state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);

// debt and credit reduction
state.reduceDebtAndCredit(creditPosition.debtPositionId, params.creditPositionId, creditPosition.credit);
```
