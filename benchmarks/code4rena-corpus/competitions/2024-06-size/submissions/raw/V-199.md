# Vulnerability details

## Impact
The `executeSellCreditMarket()` function where the `cashAmountOut` is calculated based on the `creditAmountIn` and the `ratePerTenor`. However, the `cashAmountOut` is not updated when the `exactAmountIn` is set to false.

**Explanation:**

When `exactAmountIn` is false, the `cashAmountOut` is set to the input value. However, the `cashAmountOut` is not used in the calculation of the `creditAmountIn`. Therefore, the `creditAmountIn` is calculated based on the `cashAmountOut` set to the input value, which may not be the actual cash amount that can be obtained from selling credit.

## Proof of Concept
The bug could lead to incorrect cash amounts being credited to the borrower. If the `exactAmountIn` is set to `false`, the `cashAmountOut` is not updated correctly, which can result in the borrower receiving less cash than expected.

## Recommended Mitigation Steps
* Update `cashAmountOut` when `exactAmountIn` is false.
* Calculate `cashAmountOut` based on the contract.
* Set credit to `creditAmount`.
* Set `creditAmount` to the value in `creditPosition`.
* Ensure `creditAmount` is correctly set to the value in `creditAmountIn`.
