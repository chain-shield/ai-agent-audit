# Vulnerability details

## Impact

The method `BuyCreditLimit::validateBuyCreditLimit` does not correctly validate the `dueDate` because it uses `minTenor` instead of `maxTenor`. As a result, it allows the creation of a `LoanOffer` even if `block.timestamp + maxTenor` exceeds the maximum due date.

MaxTenor is used to mitigate risks such as pause events, which require the entire protocol to halt loans, and other potential threats, as indicated by its name "Risk Configuration." This situations could potentially disrupt the protocol's invariant and doesn't working as it should be.

## Proof of Concept

In the `BuyCreditLimit` library, the `validateBuyCreditLimit` function is intended to validate the input parameters for buying credit as a limit order. However, one of the validations is not functioning as intended. The function uses `state.riskConfig.minTenor` instead of `state.riskConfig.maxTenor`, which allows the possibility for a `LoanOffer` to exceed the maximum due date and breaks the protocol invariant.

```javascript
    if (params.maxDueDate < block.timestamp + state.riskConfig.minTenor) {
            revert Errors.PAST_MAX_DUE_DATE(params.maxDueDate);
    }
```
