# Vulnerability details

## Summary
The `SelfLiquidate` library contains a vulnerability in its `executeSelfLiquidate()` function that allows lenders to extract more collateral value than they are owed during a self-liquidation event. This violates a core invariant of the protocol and could lead to unfair outcomes for borrowers.

The [executeSelfLiquidate()](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L59-L71) function is designed to allow lenders to liquidate their credit positions when certain conditions are met. It calculates the amount of collateral assigned to the credit position and transfers it directly from the borrower to the lender:

```solidity
function executeSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external {
    // ...

    uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);

    // debt and credit reduction
    state.reduceDebtAndCredit(creditPosition.debtPositionId, params.creditPositionId, creditPosition.credit);

    state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, assignedCollateral);
}
```

The issue arises because the function transfers the entire `assignedCollateral` amount without considering the actual remaining debt or the current market value of the collateral. This can lead to scenarios where the lender receives more value than what they are owed, especially if the collateral's value has appreciated significantly since the loan was issued.

## Impact
This vulnerability violates a key invariant of the protocol as stated in the **README**: "_Lenders should not be able to extract more value than what they are owed._" The impact of this issue can be severe:

1. Borrowers may lose more collateral than necessary to cover their debt.
2. Lenders can potentially profit unfairly from self-liquidations, especially in volatile market conditions.
3. It undermines the fairness and economic balance of the protocol, potentially leading to loss of user trust and reduced adoption.

## Proof of Concept
Consider the following scenario:
1. Alice lends 100 USDC to Bob, who provides 1 ETH as collateral (worth 100 USDC at the time).
2. The price of ETH doubles to 200 USDC.
3. Bob's position becomes eligible for self-liquidation (e.g., due to accrued interest).
4. Alice calls `executeSelfLiquidate()`.
5. Alice receives the entire 1 ETH collateral, now worth 200 USDC, for her 100 USDC loan (plus interest).

In this scenario, Alice has extracted significantly more value than she was owed, at Bob's expense.

## Recommended Mitigation Steps
1. Calculate the current value of the debt owed.
2. Determine the amount of collateral needed to cover the debt based on current market prices.
3. Transfer only the necessary amount of collateral to cover the debt.
4. Return any excess collateral to the borrower.

```solidity
function executeSelfLiquidate(State storage state, SelfLiquidateParams calldata params) external {
    
    // ...
    uint256 debtValue = state.calculateCurrentDebtValue(creditPosition);
    uint256 collateralPrice = state.getCollateralPrice();
    uint256 collateralNeeded = (debtValue PRECISION) / collateralPrice;
    uint256 assignedCollateral = state.getCreditPositionProRataAssignedCollateral(creditPosition);
    uint256 collateralToTransfer = Math.min(assignedCollateral, collateralNeeded);
    
    // debt and credit reduction
    state.reduceDebtAndCredit(creditPosition.debtPositionId, params.creditPositionId, creditPosition.credit);

    // Transfer collateral to cover debt
    state.data.collateralToken.transferFrom(debtPosition.borrower, msg.sender, collateralToTransfer);
    
    // Return excess collateral to borrower if any
    if (assignedCollateral > collateralToTransfer) {
    uint256 excessCollateral = assignedCollateral - collateralToTransfer;
    
    state.data.collateralToken.transferFrom(debtPosition.borrower, debtPosition.borrower, excessCollateral);
    }
}
```
