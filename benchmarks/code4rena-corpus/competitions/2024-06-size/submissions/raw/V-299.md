# Vulnerability details

## Summary

The `executeSellCreditMarket` function in the `SellCreditMarket` contract fails to properly validate the Annual Percentage Rate (APR) returned by the `getAPRByTenor` function. This vulnerability can be exploited by manipulating the APR value, allowing attackers to cause the system to miscalculate cash amounts and fees, resulting in financial losses for the protocol.

## Vulnerability Detail

The `executeSellCreditMarket` function facilitates the selling of credit as a market order. During its execution, the APR for the specified tenor is fetched using the `getAPRByTenor` function. This APR is crucial as it influences the calculation of various financial parameters such as cash amounts and fees. However, the fetched APR is not validated to ensure it falls within realistic and acceptable bounds. This lack of validation creates a significant vulnerability, permitting manipulation of the APR value.

The function `executeSellCreditMarket` takes several parameters including `creditPositionId`, `tenor`, `amount`, and `exactAmountIn`. The following steps outline its logic:

1. **Event emission**: The function begins by emitting a `SellCreditMarket` event, capturing key parameters for logging purposes.
2. **Tenor calculation**: Depending on whether the `creditPositionId` is reserved, the function calculates the tenor. For non-reserved IDs, it computes the tenor based on the due date of the debt position relative to the current block timestamp.
3. **Rate per tenor calculation**: It then fetches the rate per tenor using the `getRatePerTenor` function, which utilizes parameters from the state such as `variablePoolBorrowRate` and its related timestamps.
4. **Cash and credit amount calculation**: Based on whether `exactAmountIn` is true, the function calculates the `cashAmountOut` and `fees` or the `creditAmountIn` and `fees` using internal methods `getCashAmountOut` and `getCreditAmountIn`.
5. **Debt and credit position management**: If the `creditPositionId` is reserved, the function creates new debt and credit positions.
6. **Token transfers**: Finally, it performs token transfers from the lender to the borrower and fee recipient.

The vulnerability stems from the following code snippet, which fetches the APR but does not validate it:

```solidity
uint256 ratePerTenor = state.data.users[params.lender].loanOffer.getRatePerTenor(
    VariablePoolBorrowRateParams({
        variablePoolBorrowRate: state.oracle.variablePoolBorrowRate,
        variablePoolBorrowRateUpdatedAt: state.oracle.variablePoolBorrowRateUpdatedAt,
        variablePoolBorrowRateStaleRateInterval: state.oracle.variablePoolBorrowRateStaleRateInterval
    }),
    tenor
);
```

This `ratePerTenor` is subsequently used in financial calculations without any bounds checking.

The full function logic is as follows:

```solidity
function executeSellCreditMarket(State storage state, SellCreditMarketParams calldata params)
    external
    returns (uint256 cashAmountOut)
{
    emit Events.SellCreditMarket(
        params.lender, params.creditPositionId, params.tenor, params.amount, params.tenor, params.exactAmountIn
    );

    uint256 tenor;
    if (params.creditPositionId == RESERVED_ID) {
        tenor = params.tenor;
    } else {
        DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);
        tenor = debtPosition.dueDate - block.timestamp;
    }

    uint256 ratePerTenor = state.data.users[params.lender].loanOffer.getRatePerTenor(
        VariablePoolBorrowRateParams({
            variablePoolBorrowRate: state.oracle.variablePoolBorrowRate,
            variablePoolBorrowRateUpdatedAt: state.oracle.variablePoolBorrowRateUpdatedAt,
            variablePoolBorrowRateStaleRateInterval: state.oracle.variablePoolBorrowRateStaleRateInterval
        }),
        tenor
    );

    uint256 creditAmountIn;
    uint256 fees;

    if (params.exactAmountIn) {
        creditAmountIn = params.amount;

        (cashAmountOut, fees) = state.getCashAmountOut({
            creditAmountIn: creditAmountIn,
            maxCredit: params.creditPositionId == RESERVED_ID ? creditAmountIn : creditPosition.credit,
            ratePerTenor: ratePerTenor,
            tenor: tenor
        });
    } else {
        cashAmountOut = params.amount;

        (creditAmountIn, fees) = state.getCreditAmountIn({
            cashAmountOut: cashAmountOut,
            maxCashAmountOut: params.creditPositionId == RESERVED_ID
                ? cashAmountOut
                : Math.mulDivDown(creditPosition.credit, PERCENT - state.getSwapFeePercent(tenor), PERCENT + ratePerTenor),
            maxCredit: params.creditPositionId == RESERVED_ID
                ? Math.mulDivUp(cashAmountOut, PERCENT + ratePerTenor, PERCENT - state.getSwapFeePercent(tenor))
                : creditPosition.credit,
            ratePerTenor: ratePerTenor,
            tenor: tenor
        });
    }

    if (params.creditPositionId == RESERVED_ID) {
        state.createDebtAndCreditPositions({
            lender: msg.sender,
            borrower: msg.sender,
            futureValue: creditAmountIn,
            dueDate: block.timestamp + tenor
        });
    }

    state.createCreditPosition({
        exitCreditPositionId: params.creditPositionId == RESERVED_ID
            ? state.data.nextCreditPositionId - 1
            : params.creditPositionId,
        lender: params.lender,
        credit: creditAmountIn
    });
    state.data.borrowAToken.transferFrom(params.lender, msg.sender, cashAmountOut);
    state.data.borrowAToken.transferFrom(params.lender, state.feeConfig.feeRecipient, fees);
}
```

## Impact

An attacker can exploit this vulnerability by manipulating the APR, causing the system to calculate incorrect cash amounts and fees. This can lead to significant financial losses for the protocol as the attacker can drain funds or gain undue financial benefits from transactions.

## Recommended Mitigation Steps

To mitigate this vulnerability, the APR value should be validated to ensure it falls within realistic and acceptable bounds before it is used in any calculations. Implement additional checks as shown below:

```solidity
uint256 ratePerTenor = state.data.users[params.lender].loanOffer.getRatePerTenor(
    VariablePoolBorrowRateParams({
        variablePoolBorrowRate: state.oracle.variablePoolBorrowRate,
        variablePoolBorrowRateUpdatedAt: state.oracle.variablePoolBorrowRateUpdatedAt,
        variablePoolBorrowRateStaleRateInterval: state.oracle.variablePoolBorrowRateStaleRateInterval
    }),
    tenor
);

// Validate the APR value
require(ratePerTenor <= MAX_APR, "APR exceeds maximum allowable value");
require(ratePerTenor >= MIN_APR, "APR is below minimum allowable value");
```
