# Vulnerability details

## Impact
Detailed description of the impact of this finding.

A critical vulnerability was identified in the updateConfig function of the Size.sol smart contract. The function is intended to be protected by a role check (onlyRole(DEFAULT_ADMIN_ROLE)), which is supposed to limit the execution of the function to users with the DEFAULT_ADMIN_ROLE. However, due to a misconfiguration or potential oversight in assigning or validating these roles, an unauthorised address could potentially invoke this function. This could lead to unauthorised changes in the contract's configuration settings, potentially affecting fee structures, operational parameters, or other critical settings. The pause function is also called by the unauthorised address.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

The updateConfig function is designed to update configuration parameters of the contract. Here is an example where an unauthorised address (0xbEEF) is able to call updateConfig due to incorrect role assignment or validation:

1. Deploy the Size contract and incorrectly set up the DEFAULT_ADMIN_ROLE or simulate an attack where DEFAULT_ADMIN_ROLE is compromised.
2. An unauthorised address (e.g., 0xbEEF) uses the vm.prank feature in a test environment to simulate calling from an admin address.
3. The unauthorised address calls updateConfig to change the swapFeeAPR configuration to an arbitrary value such as 999.
4. This change reflects in the contract state, proving that the protection mechanism is not effective.
