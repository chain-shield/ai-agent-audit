# Vulnerability details

## Description:
The `executeDeposit` function in the Deposit library contains a vulnerability in handling ETH deposits. Despite prior validation, the function incorrectly uses the contract's entire balance for deposits, which can lead to severe fund loss or manipulation.

## Code:

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Deposit.sol#L64

```solidity
function executeDeposit(State storage state, DepositParams calldata params) public {
    address from = msg.sender;
    uint256 amount = params.amount;
    if (msg.value > 0) {
        // do not trust msg.value (see `Multicall.sol`)
        amount = address(this).balance;
        state.data.weth.deposit{value: amount}();
        state.data.weth.forceApprove(address(this), amount);
        from = address(this);
    }
    // ... rest of the function
}
```


1. The function reassigns the `amount` variable to `address(this).balance` when `msg.value > 0`.
2. This occurs despite prior validation in `validateDeposit` ensuring `msg.value == params.amount`.
3. Using `address(this).balance` includes the entire contract balance in the deposit and approval, not just the intended deposit amount.

## Impact:

1. Unintended loss of funds: If the contract has a pre-existing balance, all of it will be deposited and approved, not just the intended amount.
2. Potential for exploitation: An attacker could manipulate the contract's balance before a legitimate transaction is processed, causing more funds to be deposited or approved than intended.
3. Inconsistency with user expectations: Users expect only their deposited amount to be processed, not the entire contract balance.

## Attack Scenario:
1. The contract has a balance of 10 ETH from previous operations.
2. A user initiates a deposit of 5 ETH.
3. The `executeDeposit` function is called.
4. Instead of depositing and approving 5 ETH, the function uses `address(this).balance`, which is now 15 ETH.
5. 15 ETH is deposited and approved, 10 ETH more than intended.

## Recommendation:
Modify the `executeDeposit` function to use `msg.value` directly:

```solidity
function executeDeposit(State storage state, DepositParams calldata params) public {
    address from = msg.sender;
    uint256 amount = params.amount;
    if (msg.value > 0) {
        require(msg.value == params.amount, "Amount mismatch");
        state.data.weth.deposit{value: msg.value}();
        state.data.weth.forceApprove(address(this), msg.value);
        from = address(this);
    }
    // ... rest of the function
}
```

This change ensures only the intended deposit amount is processed, maintaining consistency with the validated parameters and preventing unintended fund movements.
