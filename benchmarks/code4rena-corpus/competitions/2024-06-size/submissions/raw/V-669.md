# Vulnerability details

## Description:
The current implementation of the deposit functions in the Deposit library lacks slippage protection. This exposes users to potential losses from unexpected price movements or front-running attacks, particularly when depositing tokens into variable pools.

## Affected Components:
- DepositParams struct
- validateDeposit function
- executeDeposit function
- depositUnderlyingBorrowTokenToVariablePool function

## Key Issues:
1. No minimum output amount specified: Users cannot set a minimum amount of tokens they expect to receive after deposit.
2. No slippage check: The code doesn't verify if the received amount meets a minimum threshold.
3. Potential price manipulation: Without slippage protection, the deposit could be front-run, resulting in users receiving fewer tokens than expected.

## Mitigation

1. Update DepositParams struct to include a minAmountOut parameter:
```solidity
struct DepositParams {
    address token;
    uint256 amount;
    address to;
    uint256 minAmountOut;  // Add this line
}
```

2. Modify validateDeposit to check for valid minAmountOut:
```solidity
function validateDeposit(State storage state, DepositParams calldata params) external view {
    // ... existing checks ...
    if (params.minAmountOut == 0) {
        revert Errors.INVALID_MIN_AMOUNT_OUT();
    }
}
```

3. Update executeDeposit and depositUnderlyingBorrowTokenToVariablePool to check received amount against minAmountOut:
```solidity
function executeDeposit(State storage state, DepositParams calldata params) public {
    // ... existing code ...
    uint256 receivedAmount;
    if (params.token == address(state.data.underlyingBorrowToken)) {
        receivedAmount = state.depositUnderlyingBorrowTokenToVariablePool(from, params.to, amount, params.minAmountOut);
    } else {
        receivedAmount = state.depositUnderlyingCollateralToken(from, params.to, amount);
    }
    if (receivedAmount < params.minAmountOut) {
        revert Errors.SLIPPAGE_EXCEEDED(receivedAmount, params.minAmountOut);
    }
    // ... rest of the function ...
}
```

4. Modify depositUnderlyingBorrowTokenToVariablePool to return the actual received amount and check against minAmountOut:
```solidity
function depositUnderlyingBorrowTokenToVariablePool(State storage state, address from, address to, uint256 amount, uint256 minAmountOut) external returns (uint256) {

```

5. Add new error types to the Errors library:
