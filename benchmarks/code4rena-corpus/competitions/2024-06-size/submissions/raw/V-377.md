# Vulnerability details

## Impact
Protocol fails to take fragmentation fee, which is set at ```fragmentationFee: 5e6``` from the ```deploy.sol``` contract. 
Meaning for every compensate call with RESERVED_ID, the protocol fails to take 5 dollars from the caller who caused credit fractionalization.

Which means, not only the protocol fails to charge fees but also will be at loss from the [documentation on fragmentation fees](https://docs.size.credit/technical-docs/contracts/2.3-fees#:~:text=The%20Size%20team%20intends%20to%20run%20keeper%20bots%20to%20streamline%20the%20claim%20process%20and%20aggregate%20liquidity.%20However%2C%20this%20operation%20has%20some%20fixed%20costs%20in%20terms%20of%20gas%2C%20which%20is%20why%20a%20fixed%20fee%20is%20charged%20to%20the%20user%20causing%20the%20credit%20split.);
```
The Size team intends to run keeper bots to streamline the claim process and aggregate liquidity. However, this operation has some fixed costs in terms of gas, which is why a fixed fee is charged to the user causing the credit split.
```


## Proof of Concept
### The compensate function has two slightly different functionalities, but for the same purpose;

Lets look each functionality separately, 
```javascript
    function executeCompensate(State storage state, CompensateParams calldata params) external {
        emit Events.Compensate(
            params.creditPositionWithDebtToRepayId, params.creditPositionToCompensateId, params.amount
        );

        CreditPosition storage creditPositionWithDebtToRepay =
            state.getCreditPosition(params.creditPositionWithDebtToRepayId);
        DebtPosition storage debtPositionToRepay =
            state.getDebtPositionByCreditPositionId(params.creditPositionWithDebtToRepayId);

        uint256 amountToCompensate = Math.min(params.amount, creditPositionWithDebtToRepay.credit);

        CreditPosition memory creditPositionToCompensate;
        if (params.creditPositionToCompensateId == RESERVED_ID) {
            creditPositionToCompensate = state.createDebtAndCreditPositions({
                lender: msg.sender,
                borrower: msg.sender,
                futureValue: amountToCompensate,
                dueDate: debtPositionToRepay.dueDate
            });
        } else {
            creditPositionToCompensate = state.getCreditPosition(params.creditPositionToCompensateId);
            amountToCompensate = Math.min(amountToCompensate, creditPositionToCompensate.credit);
        }

        // debt and credit reduction
        state.reduceDebtAndCredit(
            creditPositionWithDebtToRepay.debtPositionId, params.creditPositionWithDebtToRepayId, amountToCompensate
        );

        uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;

        // credit emission
        state.createCreditPosition({
            exitCreditPositionId: params.creditPositionToCompensateId == RESERVED_ID
                ? state.data.nextCreditPositionId - 1
                : params.creditPositionToCompensateId,
            lender: creditPositionWithDebtToRepay.lender,
            credit: amountToCompensate
        });
        if (exiterCreditRemaining > 0) {
            // charge the fragmentation fee in collateral tokens, capped by the user balance
            uint256 fragmentationFeeInCollateral = Math.min(
                state.debtTokenAmountToCollateralTokenAmount(state.feeConfig.fragmentationFee),
                state.data.collateralToken.balanceOf(msg.sender)
            );
            state.data.collateralToken.transferFrom(
                msg.sender, state.feeConfig.feeRecipient, fragmentationFeeInCollateral
            );
        }
    }
```



### 1. When RESERVED_ID as ```params.creditPositionToCompensateId```. 
It means the borrower wants to repay ```params.amount``` by splitting the lender's creditPosition i.e. ```params.creditPositionWithDebtToRepayId``` into two creditPositions and repaying the newly created one with credit = ```params.amount``` and still borrowing the rest. 

So, to calculate the remaining credit we must deduct the ```repaid amount``` from the original lender's creditPosition, that way we know if the credit has be fractionalized or not. 

But we can see here;
```uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;```
that we deduct the amount from the newly created position, which is basically the same amount. So, this will always give us 0, even when there is remaining credit in the original creditPosition.

See here, ```creditPositionToCompensate.credit``` is the newly created position with credit the same as ```amountToCompensate``` ; 
```javascript
        uint256 amountToCompensate = Math.min(params.amount, creditPositionWithDebtToRepay.credit);

        CreditPosition memory creditPositionToCompensate;
        if (params.creditPositionToCompensateId == RESERVED_ID) {
            creditPositionToCompensate = state.createDebtAndCreditPositions({
                lender: msg.sender,
                borrower: msg.sender,
                futureValue: amountToCompensate, 
                //@audit this does, creditPosition.credit = futureValue, which means creditPosition.credit == amountToCompensate
                dueDate: debtPositionToRepay.dueDate
            });
```

Example:
```
Bob has a creditPosition with credit = 1000, and Alice is the borrower
Alice wants to repay 400 credit.
So Alice calls compensate with:
creditPositionWithDebtToRepay.credit = 1000
params.amount = 400


amountToCompensate = Math.min(400, 1000)
                       = 400.
if (params.creditPositionToCompensateId == RESERVED_ID) is true so, 
creditPositionToCompensate.credit = futureValue: amountToCompensate
                                  = 400

Now,
exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;
                      = 400 - 400 = 0


Therefore, the contract assumes there is no credit fractionalization and fails to take fees from Alice.
But,
At this point, alice has successfully split the original Bob's creditPosition into two:
___________________________________  ________________________________________
[original lender's creditPosition]|  | [new creditPosition with same lender] |
creditPositionWithDebtToRepay     |  |  creditPositionToCompensate           |
-----------------------------------  |---------------------------------------|
                                  |  |                                       |
   * lender = 0xbob               |  |   * lender = 0xbob                    |
   * credit = 1000 - 400          |  |   * credit = 400                      |
              = 600               |  |                                       |
   * debtPositionId = aliceID     |  |    * debtPositionId = aliceID         |
----------------------------------|  |---------------------------------------|
                                  

```





### 2. When passing an existing creditPositionId as ```params.creditPositionToCompensateId```.

Note: ```This section is not needed to understand the issue but it will help understanding the mitigation better.```

A borrower can also have a ```creditPosition``` and what ```Compensate``` does is it also allows the borrower to repay his debt using the credit from his creditPosition.

In this case, the function will deduct the credit from the lender's creditPosition and split the borrower's creditPosition into two by replacing the borrower's creditPosition.lender to the original lender.

Example, Bob is the lender, and Alice is the borrower, alice repays using credit. 

```
Initial state:
_____________________________________________________________________________
[Bob's creditPosition]             |             [Alice's creditPositon]    |
----------------------------------------------------------------------------|  
* lender = 0xbob                   |             * lender = 0xalice         |
* credit = 1000                    |             * credit = 700             |    
* debtPositionId = aliceId         |             * debtPositionId = 12345   |
                                   |                                        |
-----------------------------------------------------------------------------
                 

Alice wants to repay 400 credit to bob and calls compensate with params.creditPositionToCompensateId = Alice's creditPositionId

Bob's final state:
_____________________________
[Bob's creditPosition]      |     
----------------------------|
* lender = 0xbob            |      
* credit = 1000 - 400       |      
         = 600              |                            
* debtPositionId = aliceId  |      
                            |              
-----------------------------

Alice's final state:
split Alice's creditPosition into two and set the new one's lender to bob. So, Bob has two position now.
____________________________________        ___________________________________
[Alice's creditPosition]           |        | [new creditPosition]            |
-----------------------------------|        |---------------------------------|
* lender = 0xalice                 |        | * lender = 0xalice --to-->0xbob |
* credit = 700 - 400               |        | * credit = 300                  |
         = 300                     |        | * debtPositionId = 12345        |            
* debtPositionId = 12345           |        |                                 |
                                   |        |                                 |
------------------------------------        -----------------------------------

Now alice has only 300 and has sucessfully repaid 400 credit owed to bob so 12345 will now pay 400 to Bob and alice will pay the rest.

```
In this case makes sense to do ```uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;``` because, we are spliting Alice's creditPosition i.e. ```creditPositionToCompensate```.

But since the calculation will not be correct when a user compensate using RESERVED_ID we need to calculate ```exiterCreditRemaining``` separately for each use case as recomended in the mitigation section.
