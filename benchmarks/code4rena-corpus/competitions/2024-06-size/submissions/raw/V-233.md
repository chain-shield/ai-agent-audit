# Vulnerability details


## Impact
When update the value of `variablePoolBorrowRateStaleRateInterval`, lack of zero check can lead to system DOS due to revert.

## Proof of Concept
```solidity
function test_update_variablePoolBorrowRateStaleRateInterval() public {
    uint256 val = 0;
    size.updateConfig(UpdateConfigParams({key: "variablePoolBorrowRateStaleRateInterval", value: val}));

    assertTrue(size.oracle().variablePoolBorrowRateStaleRateInterval == val);
}
```

[YieldCurveLibrary.sol::getAdjustedAPR](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/YieldCurveLibrary.sol#L94-L101)
when user set `marketRateMultiplier` is greater than zero, if `params.variablePoolBorrowRateStaleRateInterval` == 0  is checked. when the value is zero whole transaction revert due to `STALE_RATE`.

```solidity
    function getAdjustedAPR(int256 apr, uint256 marketRateMultiplier, VariablePoolBorrowRateParams memory params)
        internal
        view
        returns (uint256)
    {
        if (marketRateMultiplier == 0) {
            return SafeCast.toUint256(apr);
        } else if (
            params.variablePoolBorrowRateStaleRateInterval == 0   <@
                || (
                    block.timestamp - params.variablePoolBorrowRateUpdatedAt
                        > params.variablePoolBorrowRateStaleRateInterval
                )
        ) {
            revert Errors.STALE_RATE(params.variablePoolBorrowRateUpdatedAt);
        } else {
            return SafeCast.toUint256(
                apr + SafeCast.toInt256(Math.mulDivDown(params.variablePoolBorrowRate, marketRateMultiplier, PERCENT))
            );
        }
    }
```
Thus we can see if `variablePoolBorrowRateStaleRateInterval` is set to zero can lead to system DOS.
