# Vulnerability details

## Impact
The calculation of `creditAmountOut` does not consider the swap fee when determining the credit amount out. It only considers the `ratePerTenor` and `PERCENT` values. [AccountingLibrary.sol#296](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L296)
```solidity
creditAmountOut = Math.mulDivDown(netCashAmountIn, PERCENT + ratePerTenor, PERCENT);
```
First, let's look at the code from the [AccountingLibrary.sol#getCreditAmountOut](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L274-L301)
```solidity
function getCreditAmountOut(
    State storage state,
    uint256 cashAmountIn,
    uint256 maxCashAmountIn,
    uint256 maxCredit,
    uint256 ratePerTenor,
    uint256 tenor
) internal view returns (uint256 creditAmountOut, uint256 fees) {
    if (cashAmountIn == maxCashAmountIn) {
        // no credit fractionalization

        creditAmountOut = maxCredit;
        fees = getSwapFee(state, cashAmountIn, tenor);
    } else if (cashAmountIn < maxCashAmountIn) {
        // credit fractionalization

        if (state.feeConfig.fragmentationFee > cashAmountIn) {
            revert Errors.NOT_ENOUGH_CASH(state.feeConfig.fragmentationFee, cashAmountIn);
        }

        uint256 netCashAmountIn = cashAmountIn - state.feeConfig.fragmentationFee;

        creditAmountOut = Math.mulDivDown(netCashAmountIn, PERCENT + ratePerTenor, PERCENT);
        fees = getSwapFee(state, netCashAmountIn, tenor) + state.feeConfig.fragmentationFee;
    } else {
        revert Errors.NOT_ENOUGH_CREDIT(maxCashAmountIn, cashAmountIn);
    }
}
```
The bug lies in calculating creditAmountOut in the case of credit fractionalization. The current implementation does not account for the swap fee when determining the credit amount out.

To understand the impact, let's consider an example scenario:
   * `cashAmountIn` = 1000 (in some token units)
   * `ratePerTenor` = 10% (0.1 in decimal form)
   * `swapFeePercent` = 2% (0.02 in decimal form)

The `creditAmountOut` would be calculated using the current implementation.
```solidity
creditAmountOut = Math.mulDivDown(1000, 1.1, 1) = 909 (rounded down)
```
However, this calculation does not consider the swap fee. The correct calculation should be
```solidity
creditAmountOut = Math.mulDivDown(1000, 1.1, 0.98) = 928 (rounded down)
```
As you can see, the current implementation underestimates the credit amount out by not accounting for the swap fee. This means that users would receive less credit than they should for a given cash amount in.

Look at the `getSwapFeePercent` function code: [#164-166](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L164-L166)
```solidity
function getSwapFeePercent(State storage state, uint256 tenor) internal view returns (uint256) {
    return Math.mulDivUp(state.feeConfig.swapFeeAPR, tenor, YEAR);
}
```
This calculates the swap fee percentage based on the swap fee APR and the tenor of the credit. The swap fee is an essential factor in determining the correct credit amount out, as it represents the cost of the swap operation.

The current implementation fails to account for this cost by not subtracting the swap fee percentage from the `PERCENT` value in the denominator of the `mulDivDown` calculation, leading to an incorrect credit amount.

The impact can be significant, especially when dealing with large amounts or high-value transactions. It can result in users receiving less credit than they are entitled to, potentially causing financial losses or discrepancies in the system.

## Recommended Mitigation Steps
The swap fee should be subtracted from the `PERCENT` value in the denominator of the `mulDivDown` calculation. By subtracting the swap fee percentage from the `PERCENT` value in the denominator, the calculation of `creditAmountOut` will correctly account for the swap fee, ensuring that the credit amount out is accurately determined based on the net cash amount in and the applicable swap fee.
```solidity
creditAmountOut = Math.mulDivDown(netCashAmountIn, PERCENT + ratePerTenor, PERCENT - getSwapFeePercent(state, tenor));
```
