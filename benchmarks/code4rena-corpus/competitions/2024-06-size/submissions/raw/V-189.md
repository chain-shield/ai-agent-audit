# Vulnerability details

## Impact
- The executeUpdateConfig function in the protocol's configuration update logic contains an incorrect validation logic when updating the crLiquidation parameter. - - The current check reverts if new crLiquidation value is greater than or equal to the existing crLiquidation value, which is not the intended behavior.
- According to the protocol's documentation, crLiquidation should always be less than crOpening to ensure proper risk management.
- The current check allows CR values that can cause instant liquidations of new loans whenever/if `crLiquidation` is greater than `crOpening`, which is possible.Hence such misconfigurations can adversely affect the protocol's liquidation mechanism.

## Proof of Concept
- https://docs.size.credit/technical-docs/contracts/3.5-liquidations
- above docs contain the details of having `pL(collateral ratio for a liquidation)<pO(the minimum collateral ratio for opening a new loan and)`

- Manual review

## Recommended Mitigation Steps
- In the `else if (Strings.equal(params.key, "crLiquidation")) {}`,
- Instead of `(params.value >= state.riskConfig.crLiquidation)`,  use `(params.value >= state.riskConfig.crOpening)`.
