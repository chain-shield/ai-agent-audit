# Vulnerability details

## Impact
The stale period of [baseStalePriceInterval](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/oracle/PriceFeed.sol#L19), which is 3600 seconds, and [quoteStalePriceInterval](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/oracle/PriceFeed.sol#L20), which is 86400 seconds, used for oracle price validation, is too short for tokens on certain chains. This could lead to the protocol consuming stale prices on these chains.

## Proof of Concept
In `PriceFeed`, the heartbeat period of `base` is set to 3600 seconds (1 hour), and the heartbeat period of `quote` is set to 86400 seconds (24 hours) in the constructor. The function `getPrice()` then passes `baseStalePriceInterval` and `quoteStalePriceInterval` as arguments to the internal `_getPrice()` function.
```solidity
function getPrice() external view returns (uint256) {
        if (address(sequencerUptimeFeed) != address(0)) {
            // slither-disable-next-line unused-return
            (, int256 answer, uint256 startedAt,,) = sequencerUptimeFeed.latestRoundData();

            if (answer == 1) {
                // sequencer is down
                revert Errors.SEQUENCER_DOWN();
            }

            if (block.timestamp - startedAt <= GRACE_PERIOD_TIME) {
                // time since up
                revert Errors.GRACE_PERIOD_NOT_OVER();
            }
        }

        return Math.mulDivDown(
            _getPrice(base, baseStalePriceInterval), 10 ** decimals, _getPrice(quote, quoteStalePriceInterval)
        );
    }
```
In the `_getPrice()` function, a validation check verifies if the price data fed by Chainlink’s price feed aggregators is stale, using the `stalePriceInterval`.

The issue is that, depending on the token and the chain, the same period can be considered either too short or too long.

Let’s consider the ETH/USD oracles on different chains:
  - On [Ethereum](https://data.chain.link/feeds/ethereum/mainnet/eth-usd), the oracle will update the price data every ~1 hour.
  - On [Base](https://data.chain.link/feeds/base/base/eth-usd), the oracle will update the price data every ~20 minutes.

This means that on Base, a 1 hour period can be a stale period, which will cause the function `getPrice()` to return stale data.

## Recommended Mitigation Steps
It is recommended to store a mapping that would record the hearbeat for the stale period of each token and for every different chain.
