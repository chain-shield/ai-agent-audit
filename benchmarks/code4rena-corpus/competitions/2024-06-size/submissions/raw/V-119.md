# Vulnerability details

## Impact
Unknown user could broke the protocol, because of a possible way to change core invariants without admin role

## Proof of Concept
Malicious actor could perform this scenario:
1. Build new contract with function which could take state's storage ref in Size contract through assembly
2. The function also should be able to make a call to Size's address with encoded data
3. The encoded data should include executing `UpdateConfig::executeUpdateConfig` with params that consists of `state's storage ref` and the `UpdateConfigParams`(key: minTenor and value: 0 for example)
4. Deploy the new contract and execute the malicious function to change protocol's configuration

## Tools Used

## Recommended Mitigation Steps
Change the function `UpdateConfig::executeUpdateConfig` from being external to internal, it will work the same way so far, without allowing third party callers
```diff
--- function executeUpdateConfig(State storage state, UpdateConfigParams calldata params) external {
+++ function executeUpdateConfig(State storage state, UpdateConfigParams calldata params) internal {
        
        .....

        }

```
