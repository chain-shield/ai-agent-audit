# Vulnerability details

## Impact
`getLoanStatus` assumes that if `positionId` is not a credit position ID, it must be a debt position ID. However, it doesn't properly handle the case where `positionId` is neither a valid debt position ID nor a valid credit position ID.

In the current implementation, if `positionId` is not a credit position ID, it directly accesses `state.data.debtPositions[positionId]` without checking if it is a valid debt position ID. If `positionId` is an invalid ID that doesn't exist in the `debtPositions` mapping, this will cause an exception and revert the transaction.

However, running the test will fail because the function directly accesses `state.data.debtPositions[invalidPositionId]`, causing an exception.

## Recommended Mitigation Steps
The recommended solution is to first verify if `positionId` is a valid debt position ID before accessing `state.data.debtPositions[positionId]`. If it is not a valid debt position ID or a valid credit position ID, the function should revert with the appropriate error message.
```solidity
function getLoanStatus(State storage state, uint256 positionId) public view returns (LoanStatus) {
    if (isCreditPositionId(state, positionId)) {
        // If `positionId` is a credit position id, get the corresponding debt position
        DebtPosition memory debtPosition = getDebtPositionByCreditPositionId(state, positionId);
        return getDebtPositionStatus(debtPosition);
    } else if (isDebtPositionId(state, positionId)) {
        // If `positionId` is a debt position id, get the debt position directly
        DebtPosition memory debtPosition = state.data.debtPositions[positionId];
        return getDebtPositionStatus(debtPosition);
    } else {
        // If `positionId` is neither a debt position id nor a credit position id, revert
        revert Errors.INVALID_POSITION_ID(positionId);
    }
}
```
