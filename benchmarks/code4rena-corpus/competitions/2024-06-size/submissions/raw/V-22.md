# Vulnerability details

## Impact
The logical vulnerability in the code is that the condition in the `validateMinimumCredit` function is incorrect. It checks if the remaining credit is greater than 0 and less than the minimum credit. However, it should be checking if the remaining credit is less than the minimum credit. As a result, the credit amount can be reduced below the minimum credit.

## Proof of Concept
1. Assume the `creditPosition.credit` is 100.
2. Call the `reduceCredit` function with `amount=100` such that the remaining credit after subtraction is equal to 0.
```solidity
function reduceCredit(State storage state, uint256 creditPositionId, uint256 amount) public {
        CreditPosition storage creditPosition = state.getCreditPosition(creditPositionId);
        creditPosition.credit -= amount;
        state.validateMinimumCredit(creditPosition.credit);

        emit Events.UpdateCreditPosition(
            creditPositionId, creditPosition.lender, creditPosition.credit, creditPosition.forSale
        );
    }
```
https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/AccountingLibrary.sol#L137-L145

3. The `reduceCredit` function will execute successfully without any errors.
4. The `validateMinimumCredit` function will not revert as expected because the condition `0 < credit && credit < state.riskConfig.minimumCreditBorrowAToken` is `0 < 0 && 0< state.riskConfig.minimumCreditBorrowAToken`. Since `0 < 0` is false, the if condition is not met.
```solidity
function validateMinimumCredit(State storage state, uint256 credit) public view {
        if (0 < credit && credit < state.riskConfig.minimumCreditBorrowAToken) {
            revert Errors.CREDIT_LOWER_THAN_MINIMUM_CREDIT(credit, state.riskConfig.minimumCreditBorrowAToken);
        }
    }
```
https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/RiskLibrary.sol#L21C5-L25C6

5. This means that the remaining credit is lower than the minimum credit, but the code does not detect it.
6. As a result, the credit position will be updated and the event will be emitted, even though the remaining credit is below the minimum required.

## Recommended Mitigation Steps
To fix this vulnerability, the condition in the `validateMinimumCredit` function should be changed to `credit < state.riskConfig.minimumCreditBorrowAToken`.
