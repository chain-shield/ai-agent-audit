# Vulnerability details

## Impact
The `validateMinimumCollateralProfit` function in `LiquidateWithReplacement.sol` relies on the `liquidatorProfitCollateralToken` value passed as an argument. However, this value is not calculated within the function itself. Instead, it is expected to be provided by the caller of the function. If the caller of the `liquidateWithReplacement` function passes an incorrect or manipulated value for `liquidatorProfitCollateralToken`, it could bypass the minimum collateral profit check in the `validateMinimumCollateralProfit` function. This could lead to a situation where the liquidator receives less profit than expected or intended.

Specifically, [lines 99-111](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/LiquidateWithReplacement.sol#L99-L111), the calculation of the minimum profit in collateral tokens expected by the liquidator.

The issue here is the function checks if the `collateralReceived` is less than `params.minimumCollateralProfit` and reverts if this condition is true. However, this check does not account for any additional costs or fees that might be incurred during the liquidation process, which could affect the actual profit received by the liquidator.

For example, if there are transaction fees, gas costs, or other deductions that reduce the net amount of collateral received, the liquidator might end up receiving less profit than expected, even if the `collateralReceived` initially appears to meet the `minimumCollateralProfit` requirement.

## Proof of Concept
```solidity
/// @notice Validates the minimum profit in collateral tokens expected by the liquidator
/// @param state The state
/// @param params The input parameters for liquidating a debt position with a replacement borrower
/// @param liquidatorProfitCollateralToken The profit in collateral tokens expected by the liquidator
function validateMinimumCollateralProfit(
    State storage state,
    LiquidateWithReplacementParams calldata params,
    uint256 liquidatorProfitCollateralToken
) external pure {
    Liquidate.validateMinimumCollateralProfit(
        state,
        LiquidateParams({
            debtPositionId: params.debtPositionId,
            minimumCollateralProfit: params.minimumCollateralProfit
        }),
        liquidatorProfitCollateralToken
    );
}
```
This is to ensure that the profit in collateral tokens expected by the liquidator meets a minimum threshold specified in the `params`. It does this by calling the `validateMinimumCollateralProfit` function from the `Liquidate.sol`, passing along the necessary parameters.

The issue here arise if the calculation of `liquidatorProfitCollateralToken` does not accurately reflect the actual profit in collateral tokens that the liquidator would receive from the liquidation process. This discrepancy could lead to situations where the liquidator either does not participate due to perceived insufficient profits or participates but ends up with a lower profit than expected, which could affect the incentive structure designed to encourage liquidations.

## Recommended Mitigation Steps
Advisability to adjust the calculation to account for all relevant costs and ensure that the net profit meets the liquidator's expectations. This involves modifying the condition to subtract any anticipated costs from `collateralReceived` before comparing it to `params.minimumCollateralProfit`.
