# Vulnerability details

## Impact
when liquidating with a replacement, low apr for a very low tenor time, will round down when calculating issuance value due to the protocol using mulDIvDown to calculate the issuance value, this means that liquidatorProfitBorrowToken will be zero which will make revert happen when it tries to send that amount to the fee recipient. Leading to a DOS of the function

## Proof of Concept
```solidity
uint256 ratePerTenor = borrowOffer.getRatePerTenor(
            VariablePoolBorrowRateParams({
                variablePoolBorrowRate: state.oracle.variablePoolBorrowRate,
                variablePoolBorrowRateUpdatedAt: state.oracle.variablePoolBorrowRateUpdatedAt,
                variablePoolBorrowRateStaleRateInterval: state.oracle.variablePoolBorrowRateStaleRateInterval
            }),
            tenor
        );
        issuanceValue = Math.mulDivDown(debtPositionCopy.futureValue, PERCENT, PERCENT + ratePerTenor);
        liquidatorProfitBorrowToken = debtPositionCopy.futureValue - issuanceValue;
```
Low apr for a very low tenor towards the end of the duration of the loan can make the calculation of issuance value round down to the same value

- When calculating liquidatorProfitBorrowToken, the value retunred from this scenario, will be zero, which will revert on the attempt to transfer it to the fee receiver as shown below 

```solidity
 state.data.borrowAToken.transferFrom(address(this), state.feeConfig.feeRecipient, liquidatorProfitBorrowToken);
``` 
Note: Since this liquidations are done by keepers and not humans this scenario is actually possible

## Recommended Mitigation Steps
A check for the value of the issuance value should be made to know if there would be a profit for the liquidator before attempting to make a transfer
