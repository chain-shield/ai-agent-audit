# Vulnerability details

## Impact
The original implementation of the `withdrawUnderlyingTokenFromVariablePool` function does not follow the Checks-Effects-Interactions pattern, which can lead to potential reentrancy vulnerabilities. Additionally, the calculation of the scaled amount after the withdrawal interaction may lead to incorrect burning of the borrowAToken. This can result in mismatches between the actual underlying tokens and the token balances, potentially leading to financial discrepancies in the protocol.

## Proof of Concept
```solidity
function withdrawUnderlyingTokenFromVariablePool(State storage state, address from, address to, uint256 amount) external {
    IAToken aToken = IAToken(state.data.variablePool.getReserveData(address(state.data.underlyingBorrowToken)).aTokenAddress);

    // Calculate the scaled amount based on the amount to withdraw
    uint256 scaledAmount = amount * aToken.scaledBalanceOf(address(this)) / aToken.balanceOf(address(this));
    require(scaledAmount > 0, "Scaled amount must be greater than 0");

    // Effects
    state.data.borrowAToken.burnScaled(from, scaledAmount);

    // Interactions
    state.data.variablePool.withdraw(address(state.data.underlyingBorrowToken), amount, to);
}
```

## Recommended Mitigation Steps
Ensure that the function first performs all necessary checks, then updates the state, and finally performs interactions with external contracts.
Calculate the scaled amount before performing any external interactions to ensure accuracy.
