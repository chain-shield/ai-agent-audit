# Vulnerability details

## Impact
Fragmentation fee is not applied during compensate if minting new credit.
This violates the main invariant `FEES_01`.
```
FEES_01: Fragmentation fees are applied whenever there is a credit fractionalization
```

## Proof of Concept
In `Compensate.sol#executeCompensate` function, fragmentation fee is applied only when the credit of `creditPositionToCompensate` is fractionalized, but not applied when the credit of `creditPositionWithDebtToRepay` is fractionalized.
```solidity

            params.creditPositionWithDebtToRepayId, params.creditPositionToCompensateId, params.amount

        CreditPosition storage creditPositionWithDebtToRepay =

        DebtPosition storage debtPositionToRepay =
            state.getDebtPositionByCreditPositionId(params.creditPositionWithDebtToRepayId);

116:    uint256 amountToCompensate = Math.min(params.amount, creditPositionWithDebtToRepay.credit);

```
Assume that `creditPositionWithDebtToRepay.credit > params.amount` in `L116`. Then `amountToCompensate = params.amount < creditPositionWithDebtToRepay.credit`.
If `params.creditPositionToCompensateId == RESERVED_ID`, by `L123`, we obtain `creditPositionToCompensate.credit = amountToCompensate` and `exiterCreditRemaining = 0` in `L136`.

Therefore the fragmentation fee is not applied in `L146`.
However the credit of `creditPositionWithDebtToRepay` is fractionalized into `creditPositionWithDebtToRepay` and `creditPositionToCompensate`.

This means that fragmentation fee is not applied during compensate if minting new credit.
