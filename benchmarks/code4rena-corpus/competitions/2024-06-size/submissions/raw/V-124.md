# Vulnerability details

Lender can sell his credit to another lender via `buyCreditMarket` passing a credit position id, this is with the purpose to get his money early. 

The `buyCreditMarket` is used to match a lender to a borrower offer to0. so in case of the msg.sender pass a credit position id in the input that mean that msg.sender is basically buying a credit position. in the logic used for this the `creditPosition.lender` is set it in the `borrower` memory variable (see first arrow below) :

```solidity

        address borrower;
        uint256 tenor;
           ...
        if (params.creditPositionId == RESERVED_ID) { ... }
        } else {
           ...

            borrower = creditPosition.lender;  <-------
            tenor = debtPosition.dueDate - block.timestamp; // positive since the credit position is transferrable, so the loan must be ACTIVE
        }

      // validate borrower
```

[[Link]](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L83)

The problem is that the contract is asking for a `borrowOffer` even is the `borrower` variable is a lender. this obligate a lender that want to exit early to have a `borrowOffer` . now if the lender create a `borrowOffer` there a possible way that the lender become a borrower too and that is not what a lender may want.

## Impact
Lenders are obligated to have a `borrowOffer` to early Exit which is wrong since lender may does not want that other lender create a position with his `borrowOffer` obligate to pay for the loan.
