# Vulnerability details

## Impact
Liquidators can either liquidate just one user position and make them not liquidatable anymore or they can liquidate 2 or more positions instead. That could be very problematic as 2 users having the exact same positions, collateral ratios and etc., can have 2 completely different outcomes based on the liquidator and his intent. If he has good intentions or is a friend of the user, he will liquidate just once or if he has bad intentions or has bad feelings towards the user, he can liquidate him a few times instead.

## Proof of Concept
Note that this issue is different than the liquidator simply choosing to liquidate a position that won't put the user over the threshold and then liquidating him again for another position. However, it can be used as a way to boost the issue below and liquidate even more user positions while still having the option to liquidate him just once depending on his intents.

Users/keepers can call `liquidate()` which then calls `executeLiquidation()` after validating the parameters. For a position to be liquidatable, it has to match the following conditions:
```solidity
function isDebtPositionLiquidatable(State storage state, uint256 debtPositionId) public view returns (bool) {
        DebtPosition storage debtPosition = state.data.debtPositions[debtPositionId];
        LoanStatus status = state.getLoanStatus(debtPositionId);
        // only DebtPositions can be liquidated
        return state.isDebtPositionId(debtPositionId)
        // case 1: if the user is underwater, only ACTIVE/OVERDUE DebtPositions can be liquidated
        && (
            (isUserUnderwater(state, debtPosition.borrower) && status != LoanStatus.REPAID)
            // case 2: overdue loans can always be liquidated regardless of the user's CR
            || status == LoanStatus.OVERDUE
        );
    }
```
User has to be underwater or his debt position has to be overdue. Let's say a user has 2 positions and is underwater. Liquidating either of those positions would put him above the underwater threshold and won't be liquidatable anymore. However, if one of the positions is overdue, then the liquidator can liquidate the other one and then, he will be able to liquidate the overdue one again, thus liquidating both of his positions. If the liquidator decided to liquidate the overdue one instead, the user will not be liquidatable anymore as his overdue loan got liquidated and it also put him above the threshold. 

This allows the liquidator to choose whether he wants the user to suffer greater or lesser losses. Liquidations can also happen using a keeper which could randomly choose which position to liquidate leading to him either causing greater or lesser losses for a user based on random factors.

If we also include the issue explained at the start of the section, a liquidator can even liquidate 3 positions instead of 1. If the user has 3 positions, `one is overdue and would put him above threshold if liquidated`, `one will put him above threshold if liquidated` and one `will not put him above the threshold if liquidated`, then the liquidator can first liquidate the third one, then the second one and then, the first one, thus liquidating all 3 of his positions. Instead, if he just liquidated the overdue position, then he would have been able to successfully make the user not liquidatable by just liquidating him once. This would be very unfair for users.

Paste the following POC into `Liquidate.t.sol`:
```solidity
function testCanLiquidateFewTimes() public {
        _updateConfig("crLiquidation", 1.2e18);
        _setPrice(1e18);

        _deposit(alice, usdc, 100e6);
        _deposit(bob, weth, 120e18);

        _buyCreditLimit(alice, block.timestamp + 365 days, [int256(0), int256(0)], [uint256(150 days), uint256(365 days)]);
        uint256 debtPositionId = _sellCreditMarket(bob, alice, RESERVED_ID, 39500000, 300 days, false);
        uint256 debtPositionId2 = _sellCreditMarket(bob, alice, RESERVED_ID, 39500000, 200 days, false);

        _deposit(liquidator, usdc, 100e6);

        console.log('Initial price:');
        console.log('Collateral ratio of Bob at initial price', size.collateralRatio(bob)); // 1513784598240810734
        console.log('Debt position 1 at initial price is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId)); // Position 1 not liquidatable
        console.log('Debt position 2 at initial price is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId2)); // Position 2 not liquidatable
        console.log('--------------------------------------------------------------');

        vm.warp(block.timestamp + 220 days); // Makes position 2 overdue
        _setPrice(0.79e18); // Setting price

        console.log('New price:');
        console.log('Collateral ratio of Bob at new price', size.collateralRatio(bob)); // 1193999983828101484, now liquidatable
        console.log('Debt position 1 at new price is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId)); // Liquidatable (low CR)
        console.log('Debt position 2 at new price is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId2)); // Liquidatable (overdue + low CR)
        console.log('----------------------------------------------------------------');

        _liquidate(liquidator, debtPositionId); // Liquidate position 1, now position 2 is also liquidatable

        console.log('After liquidation:');
        console.log('Collateral ratio of Bob after liquidation', size.collateralRatio(bob));
        console.log('Debt position 1 after liquidation is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId)); // Not liquidatable
        console.log('Debt position 2 after liquidation is liquidatable -', size.isDebtPositionLiquidatable(debtPositionId2)); // Liquidatable

        _liquidate(liquidator, debtPositionId2); // Can also liquidate position 2

        /*
         If we first liquidate position 2 instead of position 1, the liquidation will make both positions not liquidatable as the collateral ratio for the user would be recovered and there will not be an overdue position. However, if we do it like we did in the POC above, both positions will be liquidatable as first we fix the ratio and then we can still liquidate the overdue one.

         You can liquidate the second position instead of the first above in the first liquidation and comment out the second liquidation and see how both positions are not liquidatable anymore.
        */
    }
```
