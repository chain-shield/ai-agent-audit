# Vulnerability details

## Impact

High. The [buyCreditMarket()](https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol#L178) and [sellCreditMarket()](https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol#L188) functions in the [Size.sol](https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol) lack slippage protection, which could lead to significant financial losses for users due to front-running attacks and/or unexpected market movements.

## Proof of Concept

In `Size.sol`:

```solidity
function buyCreditMarket(BuyCreditMarketParams calldata params) external payable override(ISize) whenNotPaused {
    state.validateBuyCreditMarket(params);
    uint256 amount = state.executeBuyCreditMarket(params);
    if (params.creditPositionId == RESERVED_ID) {
        state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
    }
    state.validateVariablePoolHasEnoughLiquidity(amount);
}

function sellCreditMarket(SellCreditMarketParams memory params) external payable override(ISize) whenNotPaused {
    state.validateSellCreditMarket(params);
    uint256 amount = state.executeSellCreditMarket(params);
    if (params.creditPositionId == RESERVED_ID) {
        state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
    }
    state.validateVariablePoolHasEnoughLiquidity(amount);
}
```

These functions do not include any mechanism to protect users from executing trades at unfavourable rates. An attacker could exploit this by:

1. Observing a large `buyCreditMarket` or `sellCreditMarket` transaction in the mempool.
2. Front-running this transaction with their own transactions to manipulate the market price.
3. Allowing the victim's transaction to execute at the manipulated price, potentially causing significant losses.

## Recommended Mitigation Steps

1. Implement slippage protection by adding minimum/maximum amount parameters:

```solidity
function buyCreditMarket(BuyCreditMarketParams calldata params, uint256 minAmountOut) external payable {
    // ... existing code ...
    require(amount >= minAmountOut, "Slippage tolerance exceeded");
    // ... rest of the function ...
}

function sellCreditMarket(SellCreditMarketParams memory params, uint256 minAmountOut) external payable {
    // ... existing code ...
    require(amount >= minAmountOut, "Slippage tolerance exceeded");
    // ... rest of the function ...
}
```

2. Implement a price oracle that checks against expected prices.

3. Implement a commit-reveal scheme for large trades to prevent front-running.

These mitigations can significantly reduce the risk of users experiencing unexpected losses due to front-running or market manipulation games.
