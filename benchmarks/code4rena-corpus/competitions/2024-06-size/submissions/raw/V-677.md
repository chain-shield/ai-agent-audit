# Vulnerability details

## Description:
The Multicall library implementation contains a critical vulnerability in its delegatecall usage. The `multicall` function executes a series of delegatecalls without verifying the existence of the target contract, potentially leading to unexpected behavior and security risks.

The vulnerability stems from the assumption that `address(this)` always refers to a valid, existing contract, without explicit verification.

## Vulnerability Details:
1. The `multicall` function uses `Address.functionDelegateCall(address(this), data[i])` to execute each call in the batch.
2. There is no check to ensure that `address(this)` refers to an existing contract before performing the delegatecall.
3. If the contract at `address(this)` has been self-destructed or does not exist, the delegatecall will still succeed but return empty data.

## Impact:
1. Silent Failures: Delegatecalls to a non-existent contract will succeed without error, potentially leading to undetected issues in contract execution.
2. Unexpected State Changes: In the context of a non-existent contract, delegatecall behavior is undefined, which could result in unintended storage modifications.
3. Security Vulnerabilities: An attacker could potentially exploit this by manipulating the contract state or execution flow if a method to self-destruct the contract exists.
4. Violation of Best Practices: The current implementation does not adhere to the check-effects-interactions pattern, increasing the risk of reentrancy and other attack vectors.


## Reproduction Steps:
1. Deploy the contract containing the Multicall library.
2. If possible, trigger a self-destruct of the contract.
3. Call the `multicall` function with any data array.
4. Observe that the function executes without error, despite the contract no longer existing.
