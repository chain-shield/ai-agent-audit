# Vulnerability details

## Impact
    >>state.data.debtToken.burn(debtPosition.borrower, repayAmount);
    >>debtPosition.futureValue -= repayAmount;

The token is being burned without validation of the `repayAmount`. This poses a potential threat and could destroy all tokens in a dangerous case.

## Proof of Concept
Lack of Input Validation

## Tools Used
Manual review

## Recommended Mitigation Steps
Please Add the input validation
For example;

    function repayDebt(State storage state, uint256 debtPositionId, uint256 repayAmount) public {

    +++        require(repayAmount > 0, "repayAmount is greater than zero.");

        DebtPosition storage debtPosition = state.getDebtPosition(debtPositionId);

    +++        require(repayAmount <= debtPosition.futureValue, "Repay amount exceeds deptPosition value");

        state.data.debtToken.burn(debtPosition.borrower, repayAmount);
        debtPosition.futureValue -= repayAmount;

        emit Events.UpdateDebtPosition(
            debtPositionId, debtPosition.borrower, debtPosition.futureValue, debtPosition.liquidityIndexAtRepayment
        );
    }
