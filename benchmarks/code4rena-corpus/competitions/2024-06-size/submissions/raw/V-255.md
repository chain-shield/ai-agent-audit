# Vulnerability details

## Impact
Malicious borrower can make it harder for liquidators to work

## Proof of Concept

The [liquidate](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Liquidate.sol#L75) functions of the protocol allow liquidators to `liquidate` a position whenever its `underwater` or `overDue`.

the [validateLiquidate](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Liquidate.sol#L37) verifies whether a position is liquidatable or not:

```

        // validate debtPositionId
        if (!state.isDebtPositionLiquidatable(params.debtPositionId)) {
            revert Errors.LOAN_NOT_LIQUIDATABLE(
                params.debtPositionId,
                state.collateralRatio(debtPosition.borrower),
                state.getLoanStatus(params.debtPositionId)
            );
        }

        
```

from there we can see that the [isDebtPositionLiquidatable](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/RiskLibrary.sol#L104) is called, where the [isUnderWater](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/RiskLibrary.sol#L111)
 is also called, which then calls the [collateralRatio](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/RiskLibrary.sol#L53) func, to check for the `collateral ratio`:
```
function collateralRatio(State storage state, address account) public view returns (uint256) {
        uint256 collateral = state.data.collateralToken.balanceOf(account);
        uint256 debt = state.data.debtToken.balanceOf(account);
        uint256 debtWad = Math.amountToWad(debt, state.data.underlyingBorrowToken.decimals());
        uint256 price = state.oracle.priceFeed.getPrice();

        if (debt != 0) {
            return Math.mulDivDown(collateral, price, debtWad);
        } else {
            return type(uint256).max;
        }
    }
```

this part is where we are most interested in, we can see from here that the collateral ratio is being calculated here.

The issue here is that, a malicious borrower who's not so interested can abuse the lack of strict of the protocol and cause the liquidators to be loosing gas, this can happen when:
1. A malicious user is `underWater` and is eligible for liquidation.
2. Now this malicious user saw that there's a transaction to liquidate his position
3. This user then front-run the liquidators and add collateral via the [deposit](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Deposit.sol#L64) thats just needed to make his position healthy, like `1 dollar` > the liquidation threshold.

This malicious borrower can repeat this on and on again, and be making the liquidators lose gas cost.
 
This is due to the lack of minimum deposit amount for borrowers.
## Tools Used

manual review

## Recommended Mitigation Steps

Add a minimum deposit amount for borrowers with an `active` position to make sure that the amount they are adding is or should be more than 20-30% of their position value, this will effectively make it a little bit harder and that the position may at least last for some amount of time.
