# Vulnerability details

## Impact
"considering a credit maturing at T if it is liquidated at t < T and therefore it is claimable at t then if the credit is also available for sale somebody can buy it at a discount depending on T-t and claim it immediately, resulting in an arbitrage

for this reason, claimable credit is non-transferable." according to docs.

Claimable credit is transferable

The vulnerability arises when creditors hold unclaimed credit on a position while debtors, cleared in that context, are in liquidation elsewhere in the protocol. This exposes creditors to risks such as losing Aave token bearing interest and interest depending on the remaining tenor. The preconditions are that the credit should be claimable, the debtor should be in liquidation in any position in the protocol and the creditor should not have disabled credit transfer.

## Proof of Concept

The key issue is that the LoanStatus check is specific to the credit position, while the borrower's solvency is determined by their overall solvency within the entire protocol.


   /// @notice Check if a credit position is transferrable
    /// @dev A credit position is transferrable if the loan is ACTIVE and the related borrower is not underwater
    /// @param state The state
    /// @param creditPositionId The credit position ID
    /// @return True if the credit position is transferrable, false otherwise
    function isCreditPositionTransferrable(State storage state, uint256 creditPositionId)
        internal
        view
        returns (bool)
    {
        return state.getLoanStatus(creditPositionId) == LoanStatus.ACTIVE
            && !isUserUnderwater(state, state.getDebtPositionByCreditPositionId(creditPositionId).borrower);
    }


The conditional statement above does not correctly handle cases where a loan has been repaid, but the borrower is still underwater with another lender. In such cases, it returns true when, according to the documented notes, it should return false.

For example, Alice hasn't claimed her credit from Bob, who repaid early. Later, Bob goes into liquidation with Tom from another loan. During this period, Mike, an arbitrager, buys Alice's credit and profits from the interest between the tenor and Aave's interest-bearing token. Alice is unhappy because she lost some profit.

Alice.getLoanStatus(creditPositionId)==LoanStatus.Active ---> False 
!isUserUnderwater(Borrower=Bob, insolvent) ----> False

Therefore False && False == True
(As notes say and in practice true means credit is transferable)

## Recommended Mitigation Steps

Send Tokens straight to lender after repay or liquidation, instead of holding them in contract.
Mark creditPosition as not transferable during debt repayment or liquidation function as there is check if credit is transferable during validatBuyCreditMarket() function.
