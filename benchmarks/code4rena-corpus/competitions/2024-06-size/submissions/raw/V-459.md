# Vulnerability details



## Impact
Liquidator will be grieved when he provides minimumCollateralProfit = 0.Liquidator will end up in an unexpected loss after the liquidation.

## Proof of Concept

Lets take a case where liquidator is okay to liquidate if atleast he gets the equivalent collateralToken for the borrowAToken he is liquidating. So that he can hold those collateral expecting its value can increase.

Inorder to achieve that he provided `minimumCollateralProfit` = 0 and executed Liquidation tranasaction.

By the time transaction reaches the execution , `Collateral ratio` of the borrower of `debtPositionId` can go below 1 PERCENT. As per the document provided, it can happen when collaterals value downsurge suddenly or the borrower withdraws the collateral by frontrunning.

In this case,
`validateLiquidate` will go through since we are checking only  `isDebtPositionLiquidatable()`.
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Liquidate.sol#L37-L54.

> `assignedCollateral` < `debtInCollateralToken` since the `Collateral ratio` < `1 PERCENT.` where `assignedCollateral` is the share of total collateral assigned to that debtPosition which is to be liquidated

And in the `executeLiquidate` , the `liquidatorProfitCollateralToken` is calculated which is equal to `assignedCollateral` .
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Liquidate.sol#L75-L126

```solidity
function executeLiquidate(State storage state, LiquidateParams calldata params)
        external
        returns (uint256 liquidatorProfitCollateralToken)
        { ....
        if (assignedCollateral > debtInCollateralToken) {  
        ...
            } else {
                // unprofitable liquidation
    =>            liquidatorProfitCollateralToken = assignedCollateral;
            }
            ....
        }
 ```  

Finally `debtPosition.futureValue` is transferred from liquidator to protocol and `liquidatorProfitCollateralToken` is transferred to liquidator which is less than `debtPosition.futureValue` (converted in collaterals unit).
Hence liquidator is in a loss because  `assignedCollateral` < `debtPosition.futureValue`(converted in collaterals unit) .

state.data.collateralToken.transferFrom(

Now lets check the `validateMinimumCollateralProfit` , 
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Liquidate.sol#L59-L69
```solidity
function validateMinimumCollateralProfit(
        State storage,
        LiquidateParams calldata params,
        uint256 liquidatorProfitCollateralToken
    ) external pure {
        if (liquidatorProfitCollateralToken < params.minimumCollateralProfit) {
            revert Errors.LIQUIDATE_PROFIT_BELOW_MINIMUM_COLLATERAL_PROFIT(
                liquidatorProfitCollateralToken, params.minimumCollateralProfit
            );
        }
    }
```  

Here we are only checking whether the `liquidatorProfitCollateralToken < params.minimumCollateralProfit` which will return false since `liquidatorProfitCollateralToken` > `0`.
There is no check to find whether the liquidator is in loss.

## Recommended Mitigation Steps

Protocol can use the `liquidatorReward` to calculate the `validateMinimumCollateralProfit` instead of `liquidatorProfitCollateralToken` considering liquidatorReward and params.minimumCollateralProfit is type of  INT256 and liquidatorReward becomes less than 0 when liquidator is actually in a loss.
