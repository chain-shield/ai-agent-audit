# Vulnerability details

## Impact
The executeLiquidate function does not account for protocol fees when determining if a debt position is liquidatable. This oversight can lead to inaccurate assessments of liquidatability, resulting in unprofitable liquidations and rapid insolvency for users. This can cause significant financial losses for the protocol and severely impact the borrowers, pushing them into insolvency.

## Proof of Concept
### Location

  `validateLiquidate` and `executeLiquidate` function in the `Liquidate` library.

  ```solidity
  function liquidate(LiquidateParams calldata params)
        external
        payable
        override(ISize)
        whenNotPaused
        returns (uint256 liquidatorProfitCollateralToken)
    {
        state.validateLiquidate(params);
        liquidatorProfitCollateralToken = state.executeLiquidate(params);
        state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
    }


```

### Issue

The function checks if a debt position is **liquidatable** without considering the **protocol fees**. This can lead to scenarios where a position is deemed liquidatable but does not cover the protocol's costs after fees are applied.

```solidity
function isDebtPositionLiquidatable(
        State storage state,
        uint256 debtPositionId
    ) public view returns (bool) {
        DebtPosition storage debtPosition = state.data.debtPositions[
            debtPositionId
        ];
        LoanStatus status = state.getLoanStatus(debtPositionId);
        //Only DebtPositions can be liquidated
        return
            state.isDebtPositionId(debtPositionId) &&
            // case 1: if the user is underwater, only ACTIVE/OVERDUE DebtPositions can be liquidated
            ((isUserUnderwater(state, debtPosition.borrower) &&
                status != LoanStatus.REPAID) ||
                // case 2: overdue loans can always be liquidated regardless of the user's CR
                status == LoanStatus.OVERDUE);
    }

```

### Scenario

- A borrower has a debt position with an assigned **collateral** of **150 WETH**.
- The debt position's future value is **100 WETH**.
- The protocol deems the position liquidatable based on the collateral and debt amounts, using a **liquidation threshold (crLiquidation)** of **130% (1.3e18)**.
- Liquidation proceeds without considering protocol fees.
- The liquidation occurs, and the liquidator receives **100 WETH** to cover the debt and an additional **5 WETH** as a reward, based on a **liquidationRewardPercent** of **5% (0.05e18)**.
- The remaining collateral is **45 WETH**.
- The protocol fees, calculated as **1% (overdueCollateralProtocolPercent)** of the remaining collateral, amount to **0.45 WETH**.

After liquidation, the protocol realizes that the fees were not fully covered, resulting in a **financial shortfall**. The protocol expected to retain **0.45 WETH** as fees, but due to the oversight, these fees were not accounted for in the liquidatability assessment.

The borrower, who was already in a precarious financial position, now faces **rapid insolvency** due to the additional uncovered fees. The liquidation process, which was supposed to mitigate risk, instead exacerbates the borrower's financial distress.


## Tools Used
Manual code review
## Recommended Mitigation Steps
Modify the logic used to determine if a debt position is liquidatable to include fee calculations. Ensure that the potential protocol fees are considered when assessing liquidatability.
