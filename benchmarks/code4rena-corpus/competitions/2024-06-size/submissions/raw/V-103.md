# Vulnerability details

## Impact
`voteForNomineeWeights` uses `uint256` to store weights and slopes, essentially fixed-point numbers.
When performing calculations like `uint256(uint128(userSlope)) * weight / MAX_WEIGHT`, there is a risk of precision loss due to integer division. [VoteWeighting.sol:voteForNomineeWeights:515](https://github.com/code-423n4/2024-05-olas/blob/3ce502ec8b475885b90668e617f3983cea3ae29f/governance/contracts/VoteWeighting.sol#L515)
```solidity
slope: uint256(uint128(userSlope)) * weight / MAX_WEIGHT,
```
## Proof of Concept
- Suppose a user has a `userSlope` of 1000 and a `weight` of 500 (representing 5%).
- If the `MAX_WEIGHT` is set to 10000 (representing 100%), the calculation `uint256(uint128(userSlope)) * weight / MAX_WEIGHT` would result in 50.
- However, if there is an integer overflow in the multiplication, the resulting value could be incorrect and lead to an unexpected allocation of voting power.
- Similarly, if the `_getWeight function` calculates the weight differently, such as using a different formula or parameters, it could lead to inconsistencies between the expected and actual weights.

Manual Audit
## Recommended Mitigation Steps
Consider using fixed-point arithmetic or increasing the precision of calculations to minimize precision loss.
