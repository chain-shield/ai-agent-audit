# Vulnerability details

## Impact

A malicious user can decrease a victim's `position.credit` amount. This can be critical and cause significant losses for users.

## Proof of Concept

### Scenario:
1. A malicious actor observes the victim's transaction, which at some point calls the `createCreditPosition` function.
2. The malicious actor then creates a similar transaction using the same `exitCreditPositionId` but with a lower `credit` amount.
3. The attacker calculates the difference between the victim's credit and their own credit, ensuring that the remaining credit is greater than the minimum required credit to be successful to be sure this check will succeed `state.validateMinimumCredit(creditPosition.credit);`.
4. Finally, the attacker sends the transaction, which reduces the victim's `credit` by the amount the attacker specified in the function.

### Example:
1. Alice creates a position with `id = 1` and `credit = 100`.
2. Bob creates a position with `id = 1` and `credit = 90` (assuming the minimum credit is 10).
3. Bob's transaction reduces Alice's credit by 90, leaving Alice with a credit of 10.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add a check to ensure that `msg.sender` is also the credit lender:

```javascript
require(msg.sender == creditPosition.lender);
```
