# Vulnerability details

## Impact
Under certain conditions when calculating the liquidator reward during profitable liquidations, the protocol's profit fee, will be 0.

## Proof of Concept
During profitable liquidations, when the liquidator reward is calculated, there are two possible ways that the liquidator fee will be / can be calculated:

```
if (assignedCollateral > debtInCollateralToken) {
            uint256 liquidatorReward = Math.min(
                assignedCollateral - debtInCollateralToken, // 0.2e18
                Math.mulDivUp(debtPosition.futureValue, state.feeConfig.liquidationRewardPercent, PERCENT)
            );
```

From the above, the `liquidatorReward` can either be the difference between the `assignedCollateral` and the `debtInCollateralToken` or 5% of the future value of the loan, depending on which of these values is the lower one.

In case the liquidator reward is the difference between the assignedCollateral and the debtInCollateralToken, the protocol will receive 0:

```
        if (assignedCollateral > debtInCollateralToken) {
            uint256 liquidatorReward = Math.min(
                assignedCollateral - debtInCollateralToken, 
                Math.mulDivUp(debtPosition.futureValue, state.feeConfig.liquidationRewardPercent, PERCENT)
            );
            liquidatorProfitCollateralToken = debtInCollateralToken + liquidatorReward; 

            // split the remaining collateral between the protocol and the borrower, capped by the crLiquidation
            uint256 collateralRemainder = assignedCollateral - liquidatorProfitCollateralToken; 

            // cap the collateral remainder to the liquidation collateral ratio
            //   otherwise, the split for non-underwater overdue loans could be too much
            uint256 collateralRemainderCap =
                Math.mulDivDown(debtInCollateralToken, state.riskConfig.crLiquidation, PERCENT);

            collateralRemainder = Math.min(collateralRemainder, collateralRemainderCap); 

            protocolProfitCollateralToken = Math.mulDivDown(collateralRemainder, collateralProtocolPercent, PERCENT);
```
If the smaller value is the `assignedCollateral - debtInCollateralToken` and that is the liquidator reward, the `liquidatorProfitCollateralToken` will be:

```
liquidatorProfitCollateralToken = debtInCollateralToken + liquidatorReward;
```

Since the above will be the `assignedCollateral` value, as the liquidatorReward is the difference between the `debtInCollateralToken` and the `assignedCollateral`, the `liquidatorProfitCollateralToken` will be the same value as the `assignedCollateral`.

Following the above, the `collateralRemainder` will be 0, since we're basically subtracting the `assignedCollateral` from the `assignedCollateral`:

```
uint256 collateralRemainder = assignedCollateral - liquidatorProfitCollateralToken;
```

Since the `collateralRemainder` is 0, the protocol share will also be 0:

```
 uint256 collateralRemainderCap =
                Math.mulDivDown(debtInCollateralToken, state.riskConfig.crLiquidation, PERCENT);

            collateralRemainder = Math.min(collateralRemainder, collateralRemainderCap);

            protocolProfitCollateralToken = Math.mulDivDown(collateralRemainder, collateralProtocolPercent, PERCENT);
```
- As the smaller number between the remainder cap and the collateralRemainder will always be 0, and with that the subsequent calculation will also equal to 0.

Protocol will receive no fees from the liquidation and everything will go to the liquidator.
