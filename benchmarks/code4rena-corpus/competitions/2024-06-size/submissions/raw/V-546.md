# Vulnerability details

## Impact
It is impossible for users to fill orders via Size::sellCreditMarket and Size::buyCreditMarket

## Proof of Concept
```
 uint256 liquidity = state.data.underlyingBorrowToken.balanceOf(address(state.data.variablePool));
```
the affected line gets the balance (assuming usdc) of the aave pool contract using the ERC20 balanceOf method which would return the USDC balance of the pool, however USDC deposited into the pool is actually deposited into the aUSDC contract not the pool itself, hence this balance is very low, as of 11:30 (GMT + 1) 2nd july, the usdc balance of the pool is zero while the USDC balance of the aUSDC is > 167 million 
```
    if (liquidity < amount) {
            revert Errors.NOT_ENOUGH_BORROW_ATOKEN_LIQUIDITY(liquidity, amount);
        }
```
which the above check is done, it will always revert as the balance pool(liquidity) will be less than the amount deposited 

## Tools Used
manual analysis 

## Recommended Mitigation Steps
The balance of the aToken should be used instead of the balance of the pool as that gives more accurate information above the funds available on aave
