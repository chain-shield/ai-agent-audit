# Vulnerability details

## Impact
In ```Compensate::executeCompensate```, a user can split a credit in as many credits as he wants (as long as they are larger than the minimum credit opening) without paying fragmentation fee.
In accordance with the docs, the fragmentation fee is intended to pay for the gas costs associated to on-chain claims made by keeper bots when a credit is split since more calls have to be made to claim the credit. According to this definition, since the user is splitting the credit, the expected behaviour would be to charge him with the fragmentation fee.


## Proof of Concept
In this PoC, we will split a credit into 9 credits by invoking ```compensate```. We will be using ```multicall``` to invoke it 9 times more easily. It will be shown that the user calling ```multicall``` will not pay any fee after having completely split the credit into 9 credits.
Include this test into ```Compensate.t.sol```:
```solidity
function test_Compensate_compensate_multicall_multiple_credit_split_no_fragmentationFee() public {
        _setPrice(1e18);

        _deposit(alice, weth, 500e18);
        _deposit(alice, usdc, 500e6);
        // Deposit collateral to make sure Bob does not go under water
        _deposit(bob, weth, 1000e18);

        YieldCurve memory curve = YieldCurveHelper.pointCurve(365 days, 0.1e18);

        _buyCreditLimit(alice, block.timestamp + 365 days, curve);

        uint256 debtPositionId = _sellCreditMarket(bob, alice, RESERVED_ID, 450e6, 365 days, true);
        uint256 creditPosition1 = size.getCreditPositionIdsByDebtPositionId(debtPositionId)[0];

        uint256[] memory creditPos = new uint256[](1);
        creditPos[0] = creditPosition1;
        CreditPosition memory creditPosition = size.getCreditPositions(creditPos)[0];
        assertEq(creditPosition.credit, 450e6);

        uint256[] memory debtPos = new uint256[](1);
        debtPos[0] = debtPositionId;
        DebtPosition memory debtPosition = size.getDebtPositions(debtPos)[0];
        assertEq(debtPosition.futureValue, 450e6);

        // user is splitting the credit into 9 credits. This creates the data for multicall
        bytes[] memory data = new bytes[](9);
        for (uint8 i; i < data.length; i++) {
            data[i] = abi.encodeCall(
                size.compensate,
                (
                    CompensateParams({
                        creditPositionWithDebtToRepayId: creditPosition1,
                        creditPositionToCompensateId: type(uint256).max,
                        amount: 50e6
                    })
                )
            );
        }
        Vars memory _before = _state();

        vm.startPrank(bob);
        bytes[] memory results = size.multicall(data);

        Vars memory _after = _state();

        //checking that Bob's collateral balance is the same before and after splitting the credit hence no fragmentation fee has been paid
        assertEq(_before.bob.collateralTokenBalance, _after.bob.collateralTokenBalance);

        creditPosition = size.getCreditPositions(creditPos)[0];
        debtPosition = size.getDebtPositions(debtPos)[0];
        //Checking that the credit with debt to repay has been completely compensated so credit is zero and debt future value is also zero
        assertEq(creditPosition.credit, 0);
        assertEq(debtPosition.futureValue, 0);
    }
```

## Recommended Mitigation Steps
The mitigation would depend on the philosophy of the platform and when to charge a fragmentation fee. By looking at the docs, every time a credit is split, it should be charged.
That being the case, every time a new credit is created (i.e. when a user defines ```creditPositionToCompensateId == RESERVED_ID```), fragmentation fee should be charged.
For existing credits is not as straight forward since a user could sell several credits to himself and then use them to compensate. This way, fragmentation fee would also be avoided. The mitigation would require a much wider approach and reconsider how to implement this fee.
