# Vulnerability details

## Impact

This bug allows accounts with the KEEPER_ROLE to liquidate their own positions using the `liquidateWithReplacement` function, potentially bypassing normal liquidation rules.

## Proof of Concept

Take a look at the `liquidateWithReplacement`function: https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L229-L244

```solidity
function liquidateWithReplacement(LiquidateWithReplacementParams calldata params)
    external
    payable
    override(ISize)
    whenNotPaused
    onlyRole(KEEPER_ROLE)
    returns (uint256 liquidatorProfitCollateralToken, uint256 liquidatorProfitBorrowToken)
{
    state.validateLiquidateWithReplacement(params);
    uint256 amount;
    (amount, liquidatorProfitCollateralToken, liquidatorProfitBorrowToken) =
        state.executeLiquidateWithReplacement(params);
    state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
    state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
    state.validateVariablePoolHasEnoughLiquidity(amount);
}
```

This function doesn't check if the keeper (msg.sender) is the same as the borrower being liquidated (params.borrower).

Scenario:
1. Alice has the KEEPER_ROLE and also has a position in the system.
2. Market conditions change, and Alice's position is close to liquidation but not quite there.
3. Alice calls `liquidateWithReplacement` on her own position.
4. The function executes without checking if Alice is the borrower.
5. Alice potentially extracts more value than she would in a normal liquidation, or avoids penalties associated with regular liquidations.

This scenario could be costly because:
1. It undermines the fairness of the liquidation process.
2. It could allow keepers to extract more value than intended, potentially at the expense of the protocol or other users.
3. It might be used to avoid accumulated interest or fees that would normally be paid in a standard liquidation.

## Recommended Mitigation Steps

Add a check at the beginning of the `liquidateWithReplacement` function to ensure the keeper is not the borrower:

```diff
function liquidateWithReplacement(LiquidateWithReplacementParams calldata params)
    external
    payable
    override(ISize)
    whenNotPaused
    onlyRole(KEEPER_ROLE)
    returns (uint256 liquidatorProfitCollateralToken, uint256 liquidatorProfitBorrowToken)
{
+   require(msg.sender != params.borrower, "Keeper cannot liquidate own position");
    state.validateLiquidateWithReplacement(params);
    uint256 amount;
    (amount, liquidatorProfitCollateralToken, liquidatorProfitBorrowToken) =
        state.executeLiquidateWithReplacement(params);
    state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
    state.validateMinimumCollateralProfit(params, liquidatorProfitCollateralToken);
    state.validateVariablePoolHasEnoughLiquidity(amount);
}
```
