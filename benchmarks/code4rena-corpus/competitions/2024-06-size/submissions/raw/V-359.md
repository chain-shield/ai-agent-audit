# Vulnerability details

## Impact
Attacker can front-run a lender and buy the credit position before `forSale` flag is disabled.
This will lead to loss of credit positions that the lenders are not willing to sell.

## Proof of Concept
When someone lends to a borrower, then a credit position will be created for the lender and by looking at there, we will see that the `forSale` flag is `true` by default at creation of new credit positions:
```solidity
creditPosition = CreditPosition({
            lender: lender,
            credit: debtPosition.futureValue,
            debtPositionId: debtPositionId,
@>          forSale: true
        });
```
It means someone and buy the credit position from the original lender and become the lender of that loan.
If the lender doesn't want to sell any of the credit positions, he should simply disable `allCreditPositionsForSaleDisabled`:
```solidity
function executeSetUserConfiguration(State storage state, SetUserConfigurationParams calldata params) external {
        User storage user = state.data.users[msg.sender];

        user.openingLimitBorrowCR = params.openingLimitBorrowCR;
@>      user.allCreditPositionsForSaleDisabled = params.allCreditPositionsForSaleDisabled;
```
But if the lender is not willing to sell only for example 1 of the credit positions, then he should specify the credit position ID and disable only that credit position by disabling the `forSale` flag for that position:
```solidity
for (uint256 i = 0; i < params.creditPositionIds.length; i++) {
            CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionIds[i]);
@>          creditPosition.forSale = params.creditPositionIdsForSale;
            emit Events.UpdateCreditPosition(
                params.creditPositionIds[i], creditPosition.lender, creditPosition.credit, creditPosition.forSale
            );
        }
```
Then if the lender disables the `forSale` flag for that credit position, nobody can buy that position from the lender:
```solidity
if (user.allCreditPositionsForSaleDisabled || !creditPosition.forSale) {
     revert Errors.CREDIT_NOT_FOR_SALE(params.creditPositionId);
}
```
However attacker can front-run the lender transaction and buy the credit position (the position that the lender is not willing to sell) before the `forSale` flag is disabled (forSale = false).

Example Scenario:
- Bob has lent to 3 borrowers (Bob has 3 credit positions) and Bob is willing to sell all of these credit positions if there is any buyer (so Bob will not disable `allCreditPositionsForSaleDisabled`)
- Bob see there is a borrow offer from Alice which is very affordable with good rates and APRs 
- Bob lends to Alice and now Bob has 4 credit positions
- Because the Alice loan is very affordable to Bob, so Bob doesn't like to sell it and decides to call `setUserConfiguration` to disable the `forSale` flag for that credit position.
- Attacker see the Bob's transaction and front-runs the Bob transaction and buys the credit position from Bob.
- Bob has lost the credit position.

## Recommended Mitigation Steps
In my opinion the `forSale` flag should be set to `false` by default, then if a lender is willing to sell a credit position, so the lender can simply call `setUserConfiguration` and set it to true.
