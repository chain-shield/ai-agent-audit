# Vulnerability details

## Impact
The validation in `validateVariablePoolHasEnoughLiquidity` is inconsistent and as a result, calling `sellCreditMarket` and `buyCreditMarket` may revert unexpectedly.

## Proof of Concept
`validateVariablePoolHasEnoughLiquidity` makes sure that there is enough liquidity in the AAVE V3 pools, in order for the borrower to be able to withdraw their loan. The issue is that the function is provided differing input parameters in `sellCreditMarket` and `buyCreditMarket`.
In `sellCreditMarket` the value supplied to `validateVariablePoolHasEnoughLiquidity` is `cashAmountOut`, which is the amount of cash that the borrower is going to receive and does not include the swap fees, transferred to the fee recipient. On the other hand, in `buyCreditMarket`, it is 
`cashAmountIn`, that DOES include the swap fees.
Therefore, depending on what the protocol team intended `validateVariablePoolHasEnoughLiquidity` will either:
1/ likely cause an unnecessary revert in `buyCreditMarket`, when there is enough liquidity in the liquidity pool to cover the cash that the borrower can withdraw, but there is not enough once the swap fees are added to the borrower's cash.
2/ not revert when necessary in `sellCreditMarket`, as only the cash supplied to the borrower is validated, and there may not be enough liquidity for the swap fees.

Either way, the function has inconsistent behaviour and acts unexpectedly.

## Tools Used
Manual review

## Recommended Mitigation Steps
In `validateVariablePoolHasEnoughLiquidity` either supply only the cash that the borrower is going to receive when it is called in `buyCreditMarket`, or supply the swap fees as well when called in `sellCreditMarket`.
