# Vulnerability details

The [getCashAmountOut()](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L185-L217) function in the `AccountingLibrary.sol` may violate the `FEES_01: Fragmentation fees are applied whenever there is a credit fractionalization` invariant. This function is crucial for calculating the cash amount and fees for credit-to-cash operations, which is a core part of the new swap fee mechanism.
```solidity
function getCashAmountOut(
    State storage state,
    uint256 creditAmountIn,
    uint256 maxCredit,
    uint256 ratePerTenor,
    uint256 tenor
) internal view returns (uint256 cashAmountOut, uint256 fees) {
    uint256 maxCashAmountOut = Math.mulDivDown(creditAmountIn, PERCENT, PERCENT + ratePerTenor);

    if (creditAmountIn == maxCredit) {
        // no credit fractionalization
        fees = getSwapFee(state, maxCashAmountOut, tenor);
        if (fees > maxCashAmountOut) {
            revert Errors.NOT_ENOUGH_CASH(maxCashAmountOut, fees);
        }
        cashAmountOut = maxCashAmountOut - fees;
    } else if (creditAmountIn < maxCredit) {
        // credit fractionalization
        fees = getSwapFee(state, maxCashAmountOut, tenor) + state.feeConfig.fragmentationFee;
        if (fees > maxCashAmountOut) {
            revert Errors.NOT_ENOUGH_CASH(maxCashAmountOut, fees);
        }
        cashAmountOut = maxCashAmountOut - fees;
    } else {
        revert Errors.NOT_ENOUGH_CREDIT(creditAmountIn, maxCredit);
    }
}
```
## Impact
The fragmentation fee is only applied when `creditAmountIn < maxCredit`. However, there's a scenario where credit fractionalization could occur even when `creditAmountIn == maxCredit`, violating the `FEES_01` invariant.

This could happen if:

1. The swap fee is non-zero.
2. `creditAmountIn == maxCredit`.

In this case, the function will not apply the fragmentation fee, even though the resulting cash amount will be less than the initial credit amount due to the swap fee, effectively causing a credit fractionalization.

This could lead to:

1. Inconsistent fee application.
4. Loss of revenue for the protocol.
5. Unfair advantage for certain users who can structure their transactions to avoid the fragmentation fee.

## Proof of Concept
1. Alice has a credit position of 1000 tokens.
2. Alice calls a function that internally uses `getCashAmountOut()` with `creditAmountIn = maxCredit = 1000`.
3. The swap fee is calculated as 10 tokens.
6. The function returns `cashAmountOut = 990 and fees = 10`.
7. This effectively fractionalizes the credit (1000 in, 990 out), but the fragmentation fee is not applied.
