# Vulnerability details

## Description:
The PriceFeed contract in our system is vulnerable to returning incorrect prices when Chainlink aggregators hit their built-in minAnswer or maxAnswer thresholds. This can lead to significant mispricing of assets during extreme market events, potentially allowing users to borrow against overvalued collateral or repay loans with undervalued assets.

## Vulnerability Details:

1. The PriceFeed contract relies on Chainlink price feeds but does not account for the aggregator's circuit breaker mechanism.

2. When an asset's price falls below the minAnswer or rises above the maxAnswer set in the Chainlink aggregator, the feed will return these threshold values instead of the actual market price.

3. The current implementation of _getPrice() does not check for or handle these edge cases:

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/oracle/PriceFeed.sol#L84

```solidity
function _getPrice(AggregatorV3Interface aggregator, uint256 stalePriceInterval) internal view returns (uint256) {
    (, int256 price,, uint256 updatedAt,) = aggregator.latestRoundData();
    if (price <= 0) revert Errors.INVALID_PRICE(address(aggregator), price);
    if (block.timestamp - updatedAt > stalePriceInterval) {
        revert Errors.STALE_PRICE(address(aggregator), updatedAt);
    }
    return SafeCast.toUint256(price);
}
```

## Impact:
In the event of extreme market conditions:
1. Assets could be significantly overvalued, allowing users to borrow more than the true value of their collateral.
2. Conversely, assets could be undervalued, enabling users to repay loans at a fraction of their actual cost.
3. The protocol could accumulate bad debt, potentially leading to insolvency.

## Proof of Concept:
1. Assume ETH has a Chainlink minAnswer of $1000.
2. ETH market price crashes to $500.
3. PriceFeed continues to report $1000 for ETH.
4. Users can borrow against ETH as if it's worth $1000, effectively doubling their borrowing power.
