# Vulnerability details

When a lender want to match a `borrowOffer` he need to call `buyCreditMarket` this function first do some validation and then execute the loan. In this cases we going to check just the validation part since is what concern in this report:

[[Link]](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L91)

As you can see the arrow above is checking if the `amount` is min than the `minimumCreditBorrowAToken` which is the minimum amount that a credit can be open. the problem is that this amount can be no only the value that a credit can be open (`creditAmountOut`) but can be also the amount that the borrower gonna receive (`cashAmountIn`) that depend on the value passing in `param.exactAmountIn`.



## Impact
The problem with this is that since this check is been doing wrongly when `param.exactAmountIn` equal to true. users trying to do the loan in this way may experiment a minimum cash amount that is more than it should be.

Note that this issue is `sellCreditMartket` function too, but in this report is just showing the error in `BuyCreditMarket`.
