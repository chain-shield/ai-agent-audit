# Vulnerability details

## Impact
If ERC20 tokens and ETH are transferred at the same time, the mistakenly sent ETH will be locked.

Several functions could be affected and cause user funds to be locked:
-  `buyCreditMarket()`
-  `sellCreditMarket()`
-  `repay()`
-  `claim()`
-  `liquidate()`
-  `selfLiquidate()`
-  `liquidateWithReplacement()`
-  `compensate()`

## Proof of Concept
The functions mentioned above have different logic to handle ERC20 and ETH transfers. However, in these functions, mistakenly sent ETH will be ignored, causing it to be locked in the contract. There is no `msg.value` check in these functions, unlike in the `deposit()` function:
```solidity
  function validateDeposit(State storage state, DepositParams calldata params) external view {
       
        // validate msg.value
        if (msg.value != 0 && (msg.value != params.amount || params.token != address(state.data.weth))) {
            revert Errors.INVALID_MSG_VALUE(msg.value);
        }
   }
```
As seen above, the `deposit()` function validates `msg.value` via the `validateDeposit()` function. However, the functions mentioned above have the `payable` keyword and perform transfers without validating `msg.value`. If ERC20 tokens and ETH are transferred simultaneously, the mistakenly sent ETH will be locked in the contract.

## Tools Used
Manual Review

## Recommended Mitigation Steps
In the mentioned functions, add a check for `msg.value` to ensure no ETH is sent:
```solidity
    if (msg.value != 0) revert Errors.INVALID_MSG_VALUE(msg.value);

```
