# Vulnerability details

## Description:

The `Repay` library in the protocol allows users to repay their debt positions. However, it lacks a mechanism to impose penalty fees for repayments made after the due date of the loan. This oversight means that users can delay their repayments without facing any financial consequences, which can lead to liquidity issues and financial losses for the lending platform.

## Impact:

The absence of penalty fees for overdue loan repayments, despite the presence of a liquidation mechanism, can have several adverse effects on the lending platform:

1. **Financial Losses**: Without penalties, borrowers have no financial incentive to repay on time, leading to potential financial losses for the platform due to delayed funds.
2. **Increased Liquidations**: The protocol relies on liquidations to manage overdue loans, but this can be a costly and disruptive process. Encouraging timely repayments through penalties can reduce the need for frequent liquidations.
3. **Liquidity Issues**: Delayed repayments can cause liquidity problems, affecting the platform's ability to provide new loans or meet withdrawal requests.
4. **Increased Risk**: The overall risk profile of the platform increases as more loans become overdue, potentially affecting the platform's reputation and trust among users and investors.
5. **Operational Inefficiencies**: Frequent liquidations can lead to operational inefficiencies and increased costs for the platform, which can be mitigated by encouraging timely repayments through penalty fees.

## Proof of Concept:

1. Alice deposits 200 usdc into the protocol to mint BorrowAtoken.
2. Bob deposits 100 usdc and 100 weth into the protocol.
3. Alice creates a loan offer with a 365-day term and a 3% interest rate to lend.
4. Bob calls the `buyCreditMarket` function to buy the loan offer created by alice.
5. Bob now delays the repayment until the due date.
6. As there is no penality charged for the late repayment bob repays the loan without any penalty fees after the due date.

## Recommended Mitigation:

To address this issue, implement a check within the `executeRepay` function to determine if the repayment is overdue. If it is, impose a penalty fee that the borrower must pay along with the loan repayment. The penalty fee can be calculated based on the amount overdue and the length of the overdue period.

Here is an updated code snippet with the recommended mitigation:

```diff
function executeRepay(State storage state, RepayParams calldata params) external {
     DebtPosition storage debtPosition = state.getDebtPosition(params.debtPositionId);

+    // Check if the repayment is overdue
+    if (block.timestamp > debtPosition.dueDate) {
+        // Calculate penalty fee based on the overdue period
+        uint256 overdueDays = (block.timestamp - debtPosition.dueDate) / 1 days;
+        uint256 penaltyFee = calculatePenalty(debtPosition.futureValue, overdueDays);

+        // Transfer penalty fee along with the repayment amount
+        state.data.borrowAToken.transferFrom(msg.sender, address(this), debtPosition.futureValue + penaltyFee);

+        // Log the penalty fee event
+        emit Events.PenaltyFeeCharged(params.debtPositionId, penaltyFee);
+    } else {
+        // Transfer the repayment amount if not overdue
+        state.data.borrowAToken.transferFrom(msg.sender, address(this), debtPosition.futureValue);
+    }

     debtPosition.liquidityIndexAtRepayment = state.data.borrowAToken.liquidityIndex();
     state.repayDebt(params.debtPositionId, debtPosition.futureValue);

     emit Events.Repay(params.debtPositionId);
}

+function calculatePenalty(uint256 amount, uint256 overdueDays) internal pure returns (uint256) {
+    // Define a penalty rate, for example, 0.1% per day
+    uint256 penaltyRate = 1e16; // 0.1% in wei
+    return (amount * penaltyRate * overdueDays) / 1e18;
+}
```

In the updated code, the `executeRepay` function checks if the current timestamp is past the `dueDate` of the debt position. If so, it calculates a penalty fee based on the overdue period and transfers the total amount (repayment plus penalty) from the borrower. An event is also emitted to log the penalty fee charged. This ensures that borrowers are financially incentivized to repay their loans on time, thus reducing the reliance on the liquidation process and mitigating the associated risks and inefficiencies.
