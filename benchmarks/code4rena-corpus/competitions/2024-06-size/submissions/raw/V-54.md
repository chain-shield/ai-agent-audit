# Vulnerability details

## Impact
The `repayDebt` function subtracts the `repayAmount` from the `debtPosition.futureValue` without checking if the `repayAmount` is less than or equal to the `debtPosition.futureValue`. This can lead to an underflow if the `repayAmount` exceeds the `debtPosition.futureValue`.

## Proof of Concept
If a user tries to repay more than the outstanding debt, the `futureValue` of the debt position will become a positive number instead of being reduced to zero. This can have severe consequences for the accounting and integrity of the debt positions in the system.

**`Consider this scenario illustrating the bug`**

   1. Suppose a debt position has a `futureValue` of 100 tokens.
   2. If a user tries to repay 150 tokens (which is greater than the `futureValue`), the `repayDebt` function will subtract 150 from 100, resulting in an underflow.
   3. The `futureValue` will become a large positive number (e.g., 2^256 - 50) instead of being reduced to zero.

We can create a test case that attempts to repay more than the `futureValue` and observe the behavior.
```solidity
function testRepayAmountExceedsFutureValue() public {
    // Assuming the debt position has a futureValue of 100 tokens
    uint256 futureValue = 100;
    uint256 repayAmount = 150;

    // Call the repayDebt function with the repayAmount exceeding futureValue
    vm.expectRevert(Errors.RepayAmountExceedsFutureValue.selector);
    accountingLibrary.repayDebt(state, debtPositionId, repayAmount);

    // Check that the futureValue remains unchanged
    assertEq(debtPosition.futureValue, futureValue);
}
```
In this test, we expect the transaction to revert with the `RepayAmountExceedsFutureValue` error when the `repayAmount` is greater than the `futureValue`. We also assert that the `futureValue` remains unchanged after the failed repayment attempt.

## Recommended Mitigation Steps
Ensure that the `repayAmount` is less than or equal to the `debtPosition.futureValue` before subtracting.
```solidity
function repayDebt(State storage state, uint256 debtPositionId, uint256 repayAmount) public {
    DebtPosition storage debtPosition = state.getDebtPosition(debtPositionId);

    if (repayAmount > debtPosition.futureValue) {
        revert Errors.RepayAmountExceedsFutureValue();
    }

    state.data.debtToken.burn(debtPosition.borrower, repayAmount);
    debtPosition.futureValue -= repayAmount;

    emit Events.UpdateDebtPosition(
        debtPositionId, debtPosition.borrower, debtPosition.futureValue, debtPosition.liquidityIndexAtRepayment
    );
}
```
We add an `if` statement to check if the `repayAmount` is greater than the `debtPosition.futureValue`. If so, we revert the transaction with a custom error `Errors.RepayAmountExceedsFutureValue()`. This ensures that the `repayAmount` is always less than or equal to the `debtPosition.futureValue`, preventing an underflow.
