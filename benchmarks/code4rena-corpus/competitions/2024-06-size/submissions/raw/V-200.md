# Vulnerability details

## Impact
In the `executeBuyCreditMarket` function, when an existing `creditPositionId` is passed (not `RESERVED_ID`), the `borrower` variable is set to `creditPosition.lender` instead of the original borrower of the loan. This is incorrect because the borrower should remain the same throughout the loan, regardless of who owns the credit position.
[src/libraries/actions/BuyCreditMarket.sol](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L56-L81)
```solidity
if (params.creditPositionId == RESERVED_ID) {
    borrower = params.borrower;
    tenor = params.tenor;
} else {
    CreditPosition storage creditPosition = state.getCreditPosition(params.creditPositionId);
    DebtPosition storage debtPosition = state.getDebtPositionByCreditPositionId(params.creditPositionId);

    borrower = creditPosition.lender;
    tenor = debtPosition.dueDate - block.timestamp;
}
```
In the line `borrower = creditPosition.lender;`. Instead of setting the `borrower` to the current owner of the credit position (`creditPosition.lender`), it should be set to the original `borrower` of the loan, which can be obtained from the corresponding debt position.

**Proof**: The `DebtPosition` struct clearly defines the `borrower` field as the borrower's address to whom the loan was taken out. On the other hand, the `CreditPosition` struct represents the lender's stake in the loan and does not contain information about the borrower.

In the `executeBuyCreditMarket` function, when an existing `creditPositionId` is provided, the code incorrectly assigns the borrower variable to `creditPosition.lender`, the current owner of the credit position. However, the correct borrower address should be obtained from the corresponding `DebtPosition` using `debtPosition.borrowe`r.

## Proof of Concept
Consider a scenario where a borrower takes out a loan, and a lender buys the credit position. 
```solidity
// Borrower takes out a loan
uint256 debtPositionId = createDebtPosition(borrower, lender, futureValue, dueDate);

// Lender buys the credit position
uint256 creditPositionId = createCreditPosition(lender, debtPositionId);

// Another lender buys the credit position from the original lender
executeBuyCreditMarket(state, BuyCreditMarketParams({
    borrower: newLender,
    creditPositionId: creditPositionId,
    // ...
}));
```
In this scenario, when the new lender buys the credit position using `executeBuyCreditMarket`, the `borrower` variable will be incorrectly set to the original lender (`creditPosition.lender`) instead of the original borrower (`debtPosition.borrower`). This leads to an inconsistency where the loan borrower appears to be the original lender, even though the borrower has stayed the same.

## Recommended Mitigation Steps
Modifying the code to assign `borrower = debtPosition.borrower` instead of `borrower = creditPosition.lender` when an existing `creditPositionId` is provided.
```solidity
if (params.creditPositionId == RESERVED_ID) {
    borrower = params.borrower;
    tenor = params.tenor;
```
