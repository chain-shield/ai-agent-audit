# Vulnerability details

**Vulnerability Report**

**Subject**: Potential Reentrancy Attack on the `withdraw` function in the Size Smart Contract

**Report ID**: 2024-06-010-001


**Severity**: High (8.1/10) **Impact**
Detailed description of the impact of this finding:

- A reentrancy attack on the `withdraw` function could allow an attacker to repeatedly call the function in a single transaction, draining the contract balance and causing unintended behavior.
- This vulnerability could lead to a significant financial loss for the contract owner and users.

**Proof of Concept**
[Smart Contract Code](https://github.com/size-credit/size-smart-contracts/blob/main/contracts/Size.sol)

[withdraw function](https://github.com/size-credit/size-smart-contracts/blob/main/contracts/Size.sol#L316)

The following steps illustrate the potential attack:

1. An attacker initiates a transaction to withdraw funds.
2. The smart contract updates its internal state with the first `state.executeWithdraw(params)` call.
3. Before the smart contract validates the user's opening limit with `state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender)`, an external call is made, allowing the attacker to manipulate the contract's state.
4. The attacker repeatedly calls the `withdraw` function, draining the contract balance.

[Reentrancy Attack Demonstration Video](https://example.com/reentrancy-attack-demo.mp4)

**Recommended Mitigation Steps**

1. Implement the `ReentrancyGuard` modifier from OpenZeppelin to protect against reentrancy attacks.
2. Update the `withdraw` function as shown below:

```solidity
import "@openzeppelin/contracts-upgradeable/security/ReentrancyGuardUpgradeable.sol";

contract Size is ISize, SizeView, Initializable, AccessControlUpgradeable, PausableUpgradeable, UUPSUpgradeable, ReentrancyGuardUpgradeable {
    // ...

    function withdraw(WithdrawParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateWithdraw(params);
        _reentrancyGuard.enter();
        state.executeWithdraw(params);
        _reentrancyGuard.leave();
        state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
    }
}
```

3. Thoroughly test the smart contract to ensure it functions as intended after the mitigation steps have been implemented.
4. Continuously follow best practices in smart contract development, such as documenting the contract, testing its functionality, handling error cases, and ensuring modifiers are appropriate and secure.
