# Vulnerability details

In the Size protocol, a **debtPosition** can have multiple **creditPositions**, and it's impractical to **repay** all these credits when the borrower repays their debt. The mechanism used to solve this is:
1. The borrower repays their `debtPosition`, and the funds go to the SizeContract.
2. For a repayed `debtPosition`, any `creditPosition` of it can be claimed which sends funds from the SizeContract to the lender of that `creditPosition`.

- Fragmentation fees are essential for covering the gas costs associated with the `claim` process as the Size team intends to run keeper bots to streamline the `claim` process as stated in the docs:

> Since claiming means interacting with the blockchain in write mode, so consuming gas, each partial credit exit is charged a "fragmentation fee" so that the protocol can both:
> - fund its bots to do the housekeeping related to calling the Claim method to reduce the liquidity fragmentation and
> - later define an incentive for 3rd party claims on behalf of lenders

-  invariants from the [README](https://github.com/code-423n4/2024-06-size?tab=readme-ov-file#main-invariants) : 
> FEES_01: Fragmentation fees are applied whenever there is a credit fractionalization

-  However, a user can cause a credit split but doesn't get charged the fragmentation fees through the `compensate()` function. This can be intentional or unintentional by the user.

##### example : 
- A user calls the function `compensate()` basically to pay a portion of their `debtPosition`: 
  - **userX** has a `debtPosition1` with `futureValue = 1000`, **userY** has `creditPosition1` of this debt position with `credit = 1000`
  - **userX** wants to pay only `400` of their debt and since repaying debt partially isn't possible, they would call the `compensate()` function which will do the following (with `RESERVED_ID`):
    1. Create a `debtPosition2` with `futureValue = 400` and `creditPosition2` with `credit = 400`.
    2. Reduce both `debtPosition1` and `creditPosition1` by `400`, so we get `debtPosition1` with `futureValue = 600` and `creditPosition1` with `credit = 600`.
    3. Give **userY** the `creditPosition2`.
  - In the final state we have:
    - **userX** has: `debtPosition1` with `futureValue = 600` and `debtPosition2` with `futureValue = 400`.
    - **userY** has: `creditPosition1` with `credit = 600` and `creditPosition2` with `credit = 400`.
  - Notice that the debt of **userX** and the credit of **userY** didn't change, just got split, so **userX** can repay only `400` of their debt.
- The issue with that is that **userX** splits the credit so they can pay partially, but we didn't charge them any fragmentation fees see here 👇 : 
 ```js
        function executeCompensate(State storage state, CompensateParams calldata params) external {
         // some code  ...
        if (params.creditPositionToCompensateId == RESERVED_ID) {
   >>       creditPositionToCompensate = state.createDebtAndCreditPositions({lender: msg.sender, borrower: msg.sender, futureValue: amountToCompensate, dueDate:    debtPositionToRepay.dueDate});
        }

        // some code ...

    >>    uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;

    >>     if (exiterCreditRemaining > 0) {
            // charge the fragmentation fee in collateral tokens, capped by the user balance
            uint256 fragmentationFeeInCollateral = Math.min(state.debtTokenAmountToCollateralTokenAmount(state.feeConfig.fragmentationFee), state.data.collateralToken.balanceOf(msg.sender));
            state.data.collateralToken.transferFrom(msg.sender, state.feeConfig.feeRecipient, fragmentationFeeInCollateral);
        }
    }
 ```
 - Notice that the `amountToCompensate` equals `creditPositionToCompensate.credit` which is basically the new created credit (400), so `exiterCreditRemaining > 0` will be **False**, thus no fragmentation fees will be charged to the user. But we still get a credit split.
- When **userX** calls `compensate()` to pay a portion of their debt, it results in new `debtPosition` and `creditPosition` , `debtPosition` will be payed by the borrower , but the `creditPosition`   need to be claimed separately.
- A malicious user can exploit this by splitting a lender's credit into multiple smaller credits ([poc](#coded-poc)) without being charged fragmentation fees. This can also happen unintentionally with regular partial repayments. For example, a credit of 1000 can be split into 10 credits of 100, each associated with a different `debtPosition`.

##### Root Cause of the Issue

- The root cause of the issue is not charging fragmentation fees on the first-time credit creation. This can lead to economic issues where a user can make another user (or the protocol) pay more in terms of gas. For example, instead of selling a lender a credit of `10,000$`, a user can sell him `100 credits` of `100$` each. Since each credit is created for the first time, no fragmentation fees will be charged.This way, the protocol will incur higher costs for claiming all these credits.

- The reason to mention `compensate()` as the main issue is because the borrower benefits by paying their debt partially while harming the protocol and lender by splitting the credit (they pay more gas for claiming those credits) whithout get charged the fragmantation fees.

 ## Impact
 - The issue enables users to split credits into multiple smaller credits without incurring fragmentation fees, significantly increasing gas costs for the protocol (or lenders) when claiming these credits, ultimately leading to substantial financial losses for the protocol.
## Proof of Concept

- Here is a coded PoC that shows how Bob was able to split Alice's credit into 8 credits without getting charged the fragmentation fees. add this test [here](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/test/local/actions/Compensate.t.sol#L20) : 
 ```js
     function test_Poc_split_creditPosition_noFragmantionFees() public {
        _setPrice(1e18);
        // we set swapFee to 0 , so it doesn't effect the check for fragmantionFees
        _updateConfig("swapFeeAPR", 0);
        _deposit(alice, usdc, 200e6);
        _deposit(bob, weth, 400e18);
        _buyCreditLimit(alice, block.timestamp + 365 days, YieldCurveHelper.pointCurve(365 days, 0.5e18));
        // 1. bob borrows from alice 120e6 usdc
        uint256 debtPositionId = _sellCreditMarket(bob, alice, RESERVED_ID, 120e6, 365 days, false);
        // 1.1 we get the debt position where bob is the borrower
        uint256 creditPositionId = size.getCreditPositionIdsByDebtPositionId(debtPositionId)[0];
        NonTransferrableToken collateraltoken = size.data().collateralToken;
        // 1.2 get the feeReciepient address balance of collateral token to calculate the fragmantion fees charged after compensate :
        uint256 balanceBefore = collateraltoken.balanceOf(size.feeConfig().feeRecipient);
        // 1.3 make sure that we have a fragmentationFee set to 5 usdc
        assertEq(5e6, size.feeConfig().fragmentationFee);
        // 2.first create an array to get all new credit position created :
        uint256[] memory newCreditPositionCreatedIds = new uint256[](7);
        for (uint256 i = 0; i < 7; i++) {
            // 3. bob compensate to pay partially through multiple tx(multicall) with RESERVED_ID, so he create a debt position and credit position and pay with creadit position
            vm.prank(bob);
            size.compensate(CompensateParams({creditPositionWithDebtToRepayId: creditPositionId, creditPositionToCompensateId: RESERVED_ID, amount: 10e6}));
            newCreditPositionCreatedIds[i] = size.getCreditPositionIdsByDebtPositionId(debtPositionId + i + 1)[0];
        }
        //4. validate that 7 more credit position created with 10e6 as the futureValue in each , and alice is the lender of them :
        for (uint256 i = 0; i < 7; i++) {
            CreditPosition memory creditPosition = size.getCreditPosition(newCreditPositionCreatedIds[i]);
            assertEq(creditPosition.lender, alice);
            assertEq(creditPosition.credit, 10e6);
        }
        uint256 balanceAfter = collateraltoken.balanceOf(size.feeConfig().feeRecipient);
        // 5. check that no fragmantation fees charged to bob, even though he split alice credit to 8 parts , so claimer will pay for all 8 credit after due date
        assertEq(0, balanceAfter - balanceBefore);
        // 6. bob repays his debt (note he could repay all other debts also )
        _repay(bob, debtPositionId);
        assertEq(size.getUserView(bob).borrowATokenBalance, 120e6 - (180e6 - 70e6));
        assertEq(size.getUserView(bob).debtBalance, 70e6);
    }
 ```
