# Vulnerability details



## Impact
User can create a new credit-debt position by giving an invalid tenor.This happens when the ADMIN decided to update the `minTenor` or `maxTenor`.

## Proof of Concept
Lets take the issue from BuyCreditMarket.
In the `validateBuyCreditMarket()` ,
if the `params.creditPositionId == RESERVED_ID` we are checking whether the tenor comes under correct range.

But if the user passes actual `creditPositionId` as the parameter , then the resulting tenor is left unchecked before creating a new credit-debt Position.

So if the ADMIN has updated the `minTenor` or `maxTenor` , the `debtPosition` of the credit that the lender wants to buy has the old check done.

For the `new tenor`  which is equal to `debtPosition.dueDate - block.timestamp` ,
it will only satisfy the old condition and is not validated using updated tenor range. 


If the ADMIN updates `minTenor` and `maxTenor`  to new value prior to this txn ,the new `tenor` needs to be revalidated.
