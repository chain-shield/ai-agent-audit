# Vulnerability details

## Impact
The Size protocol allows borrowers to partially repay/reduce their debtPosition's by redirecting their future cash flow to their creditor or by creating a new credit/debt position via `compensate()` function. During this operation, credit fragmentation may occur, meaning there can be a split(reduction) in their existing credit. [According to the docs, in these cases, a fragmenation fee must be charged to the borrower.](https://docs.size.credit/technical-docs/contracts/3.4-repayment#:~:text=Observation%3A%20in,fee%20with%20collateral)
However, an issue in the implementation allows borrowers to avoid this fragmentation fee during debt compensation, leading to losses for the protocol.

## Proof of Concept
For example, let's conisder the borrower Bob who has a debtPosition, owing 10,000 USDC to his lender.
There are three main cases when the fragmentation fee must be charged:

1. Compensating a `debtPosition` by creating new credit/debt position. Bob calls `compensate()` with `RESERVED_ID` and `amount = 5000`. In this case, credit fractionalization occurs, because his `debtPositionWithCreditToRepay` is reduced from 10,000 to 5000, resulting in two positions of 5000 each. 
2. Compensating a `debtPosition` using an existing `creditPosition` with future value less than his `debtPosition.futureValue` (e.g., 5000 USDC). This will repay the half of the debt, resulting in credit fragmentation (the debt reduces from 10,000 to 5000).
3. Compensating a `debtPosition` using an existing `creditPosition` with future value greater than his `debtPosition.futureValue` (e.g., 15,000 USDC). This will fully repay his debt, but results in credit fragmentation to his `creditPosition` (the credit reduces from 15,000 to 5000). This case is somewhat tricky, but is closely related to the first two. As you can see in tests, to succeed Bob must receive help from the borrower of his credit position. The borrower will use the issue to first reduce his `debtPosition` to amount that satisfies Bob's needs. 

[In our code implementation we can see that `fragmetationFee` is charged only when `exiterCreditRemaining > 0`](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/Compensate.sol#L146-#154). However, we often don't enter this statement simply because `exiterCreditRemaining` is 0. It is calculated as follows:
```solidity
uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;
``` 
where:
* `creditPositionToCompensate.credit` represents the credit used to compensate the debt.
* `amountToCompensate` is the minimum of two values (e.g., 5000 and 10,000):
```solidity
uint256 amountToCompensate = Math.min(params.amount, creditPositionWithDebtToRepay.credit);
```
The issue arises because we are subtracting from `creditPositionToCompensate.credit`, which represents the credit used to compensate our debt.

Paste the following tests in `Compensate.t.sol`:
* Case 1:
```solidity
// case 1
    function test_Compensate_avoid_fragmentation_fees_when_reduce_credit()
        public
    {
        _setPrice(1000e18);
        _updateConfig("fragmentationFee", 5e6);

        _deposit(alice, usdc, 10000e6);
        _deposit(bob, weth, 15e18);

        _buyCreditLimit(alice, block.timestamp + 365 days, YieldCurveHelper.pointCurve(365 days, 0.05e18));

        uint256 debtPositionId = _sellCreditMarket(bob, alice, RESERVED_ID, 10000e6, 365 days, true);
        uint256 creditPositionId = size.getCreditPositionIdsByDebtPositionId(debtPositionId)[0];

        assertEq(size.getUserView(bob).borrowATokenBalance, 9476190475);
        assertEq(size.getUserView(bob).debtBalance, 10000e6);

        uint256 balanceOfCollateralBefore = size
            .getUserView(bob)
            .collateralTokenBalance;

        vm.startPrank(bob);
        size.compensate(
            CompensateParams({
                creditPositionWithDebtToRepayId: creditPositionId,
                creditPositionToCompensateId: RESERVED_ID,
                amount: 2000e6
            })
        );
        vm.stopPrank();

        uint256 balanceOfCollateralAfter = size.getUserView(bob).collateralTokenBalance;
        // No fragmentation fee was charged
        assertEq(balanceOfCollateralBefore, balanceOfCollateralAfter);
    }
```

## Recommended Mitigation Steps
In `Compensate.sol::executeCompensate()` you must apply two changes: 
1. For `exiterCreditRemaining` calculation, instead of using `creditPositionToCompensate.credit - amountToCompensate`, use the credit which we are compensating `creditPositionWithDebtToRepay.credit - amountToCompensate`. 
2. Move the calculation above credit and debt reduction, because once `debtPosition` is fully reduced a  `creditPositionToCompensate.credit` will be equal to 0:

```diff
    function executeCompensate(State storage state, CompensateParams calldata params) external {
        //code

+       uint256 exiterCreditRemaining = creditPositionWithDebtToRepay.credit - amountToCompensate;
        // debt and credit reduction
        state.reduceDebtAndCredit(
            creditPositionWithDebtToRepay.debtPositionId, params.creditPositionWithDebtToRepayId, amountToCompensate
        );

-       uint256 exiterCreditRemaining = creditPositionToCompensate.credit - amountToCompensate;
        //code
    }
```
