# Vulnerability details

## Summary
The [validateSelfLiquidate()](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L34-L54) function in the `SelfLiquidate` library contains a potential vulnerability in its collateral ratio check. This function is responsible for validating whether a credit position is eligible for self-liquidation, but its current implementation may allow for premature or unnecessary liquidations.

The function first checks if the credit position is self-liquidatable using `state.isCreditPositionSelfLiquidatable(params.creditPositionId)`. However, it then performs an additional check: [SelfLiquidate.sol#L46-L48](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/SelfLiquidate.sol#L46-L48)
```solidity
if (state.collateralRatio(debtPosition.borrower) >= PERCENT) {
    revert Errors.LIQUIDATION_NOT_AT_LOSS(params.creditPositionId, state.collateralRatio(debtPosition.borrower));
}
```
This check reverts if the collateral ratio is greater than or equal to `PERCENT` (which is likely 100%). The issue here is that this condition might be inconsistent with the criteria used in `isCreditPositionSelfLiquidatable()`, potentially leading to conflicting results.

## Impact
1. **Premature Liquidations:** Positions might be liquidated even when they have sufficient collateral, leading to unnecessary losses for borrowers.
2. **Blocked Legitimate Liquidations**: Conversely, some positions that should be liquidatable might be blocked if the conditions are misaligned.
3. **Confusion for Users**: Inconsistent liquidation criteria can lead to unpredictable behavior, eroding user trust in the protocol.

## Proof of Concept
Consider the following scenario:

1. A credit position becomes self-liquidatable according to `isCreditPositionSelfLiquidatable()`.
2. However, due to rapid market movements or other factors, the `collateralRatio` temporarily rises above `PERCENT`.
3. A lender attempts to self-liquidate, but the transaction reverts due to the `LIQUIDATION_NOT_AT_LOSS` error.
4. This leaves the position in a state where it's theoretically liquidatable but practically cannot be liquidated.
