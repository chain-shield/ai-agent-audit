# Vulnerability details

## Impact

The incorrect inclusion of the fragmentation fee in the `creditAmountIn` calculation results in borrowers overpaying interest, as they are charged interest on the fragmentation fee itself, leading to higher-than-expected repayment amounts.

## Proof of Concept
If a sell market order is being created with `cashAmountOut` as the input amount to fractionalize an existing credit position, the `creditAmountIn` in [`AccountingLibrary::getCreditAmountIn`](https://github.com/code-423n4/2024-06-size/blob/main/src/libraries/AccountingLibrary.sol#L253-L255) function is calculated as follows:
```solidity
creditAmountIn = Math.mulDivUp(
    cashAmountOut + state.feeConfig.fragmentationFee, PERCENT + ratePerTenor, PERCENT - swapFeePercent
);
```

From the calculation above we can see that the `fragmentationFee` is included in the `creditAmountIn` calculation, which means that interest is being charged on the `fragmentationFee` as well. 

This is incorrect, as the interest should only be charged on the `cashAmountOut`, and the `fragmentationFee` should be added to the `creditAmountIn` after the interest calculation.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the fragmentation fee to the `cashAmountOut` after the interest calculation. This will ensure that the `fragmentationFee` is not included in the interest calculation, and will be charged to the borrower as intended.
