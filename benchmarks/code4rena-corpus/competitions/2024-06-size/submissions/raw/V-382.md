# Vulnerability details

## Impact

Within the Size#`repay()`, the `whenNotPaused` modifier would be attached like this:
https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol#L198
```solidity
    /// @inheritdoc ISize
    function repay(RepayParams calldata params) external payable override(ISize) whenNotPaused { ///<------- @audit
        state.validateRepay(params);
        state.executeRepay(params);
    }
```

However, once a protocol admin would pause the Size protocol via the Size#`pause()`, a borrower can **not** repay their debt.
This is problematic because the interests of the debt position would keep being accrued even if it is during the Size protocol is paused.
As a result, the borrower's debt position can be moved to a liquidatable state during the Size protocol is paused.

Once the protocol admin would unpause the Size protocol via the Size#`unpause()`, the borrower may try to repay their debt, which is a liquidatable status, via the Size#`repay()`. 
However, if a liquidation bot (MEV bot) would monitor the protocol admin's TX of unpausing in the mempool, the a liquidation bot (MEV bot) can **front-run** the borrower's TX of the Size#`repay()` with calling the Size#`liquidate()` with the borrower's liqudiatable `account`.
As a result, the borrower's debt position can be liquidated - even though the borrower was willing to repay and the borrower had enough funds to repay for resuming their debt position to at least a healthy status (collateralization ratio >= liquidation threshold).

## Proof of Concept
Let's say Bob is a protocol admin and Alice is a borrower who has an existing debt position.

- 1/ Bob would call the Size#`pause()` to pause the Size protocol.
  - At this point, the Size#`repay()` would be paused because the `whenNotPaused` modifier is attached. Hence, any borrower can **not* repay via the Size#`repay()`

- 2/ However, during the phase of pausing the Size protocol, the interests of Alice's debt position would keep being accrued.

- 3/ Eventually, Alice's debt position would be moved to a liquidatable status (due to that her collateralization ratio dropped below the liquidation threshold (i.e. 130%)).

- 4/ Bob would call the Size#`unpause()` to unpause the Size protocol.

- 5/ Soon later the step 4/, Alice would call the Size#`repay()` to resume to a healthy status (her collateralization ratio >= liquidation threshold).

- 6/ A liquidation bot (MEV bot) would monitor the Bob's TX of step 4/ and the liquidation bot would call the Size#`repay()` with Alice's debt position, which is a liquidatable status.

- 7/ The liquidation bot's TX would be executed first.

- 8/ Alice's TX would be executed.

- 9/ Since the liquidation bot's TX was executed first, Alice's debt position has been liquidated. So, she lost her collateral.

## Recommended Mitigation Steps

Within the Size#`repay()`, consider removing the `whenNotPaused` modifier in order for a borrower to repay their debt even if it is during the paused-phase like this:
```diff
+   function repay(RepayParams calldata params) external payable override(ISize) {
-   function repay(RepayParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateRepay(params);
        state.executeRepay(params);
    }
```
