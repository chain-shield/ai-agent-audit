# Vulnerability details

## Impact

The current implementation of the `withdraw` function prevents users from withdrawing their underlying borrow tokens if their collateral ratio (CR) is below their opening collateral ratio, even when their actual CR is above the liquidation threshold. This lead to users being unable to withdraw their borrow tokens even if they have a safe actual CR (even with an unhealthy CR users should be able to withdraw their borrow tokens).

## Proof of Concept

- In the Size protocol, the main tokens for borrowing and collateral are **USDC** and **WETH**, which are converted into non-transferable ERC-20 tokens when deposited (`szaUSDC` and `szWETH`).
- `aszUSDC` is the borrow token that tracks `USDC` in the system, while `szWETH` is the collateral token that tracks `WETH` for all users.

- The withdrawal function is essential for managing user withdrawals in a secure and validated manner. Withdrawals of borrow tokens (`USDC`) request the amount from the **Variable Pool** (**Aave v3**), which is then sent to the user's wallet. Collateral tokens (`WETH`) are transferred from the **Size contract** directly.

- Users should always be able to withdraw their borrow tokens(`USDC`) without concerning themselves about the collateral ratio (CR), since the borrow token does not directly affect the CR. The CR is calculated based on the value of the collateral and the value of the debt.
```js
function collateralRatio(
        State storage state,
        address account
    ) public view returns (uint256) {
        uint256 collateral = state.data.collateralToken.balanceOf(account);
        uint256 debt = state.data.debtToken.balanceOf(account);
        uint256 debtWad = Math.amountToWad(
            debt,
            state.data.underlyingBorrowToken.decimals()
        );
        uint256 price = state.oracle.priceFeed.getPrice();

        if (debt != 0) {
            return Math.mulDivDown(collateral, price, debtWad);
        } else {
            return type(uint256).max;
        }
    }

```
- The issue arises when a user attempts to withdraw their underlying borrow tokens. If the user's CR is below their opening collateral ratio, the transaction will revert due to the `validateUserIsNotBelowOpeningLimitBorrowCR` check, even though the actual CR is above the liquidation threshold.
```js
 function withdraw(WithdrawParams calldata params) external payable override(ISize) whenNotPaused {
        state.validateWithdraw(params);
        state.executeWithdraw(params);
       // this check does not consider if is a borrow or collateral token 
   >>   state.validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
    }

```
- This check does not consider whether the withdrawal is for a borrow or collateral token, leading to incorrect reverts.

- **Example Scenario**:
  - Initial Setup:
    - User opening CR: 200%
    - System opening CR: 150%
    - Actual CR: 195% (due to market fluctuations)
  - The user attempts to withdraw their underlying borrow tokens.
  - The `validateUserIsNotBelowOpeningLimitBorrowCR` function is called.
  - It calculates the `openingLimitBorrowCR`, which is the maximum (200%).
  - The function then compares `collateralRatio(state, account)` (195%) with the `openingLimitBorrowCR` (200%) and reverts.
  - The user is prevented from withdrawing their borrow tokens despite having a safe actual CR.

> **Note:** This shows how users with healthy CR are prevented from withdrawing their borrow tokens. However the sponsor confirmed that users should always be able to withdraw their borrow tokens even when their CR is under the liquidation CR, which is logical.

 - the  `validateUserIsNotBelowOpeningLimitBorrowCR`  function in `withdraw` should only be called when the token the user want to withdraw is  **collterral token**

```diff

        state.executeWithdraw(params);
-       validateUserIsNotBelowOpeningLimitBorrowCR(msg.sender);
```
