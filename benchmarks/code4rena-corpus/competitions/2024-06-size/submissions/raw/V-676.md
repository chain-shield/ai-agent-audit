# Vulnerability details

## Description:
A bug has been identified in the getAPR function of the YieldCurveLibrary contract. The function incorrectly handles cases where the input tenor exactly matches a value in the yield curve's tenor array. This can lead to inaccurate APR calculations for these specific tenors.

## Details:
The getAPR function uses a binary search algorithm to locate the position of the input tenor within the yield curve's tenor array. When an exact match is found, the function should return the APR specifically defined for that tenor. However, the current implementation fails to do so.

The problematic code segment is as follows:

https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/YieldCurveLibrary.sol#L124

```solidity
(uint256 low, uint256 high) = Math.binarySearch(curveRelativeTime.tenors, tenor);
uint256 y0 = getAdjustedAPR(curveRelativeTime.aprs[low], curveRelativeTime.marketRateMultipliers[low], params);

if (low != high) {
    // Interpolation logic
} else {
    return y0;
}
```

When low == high (indicating an exact match), the function returns y0, which is calculated using the lower bound's APR and market rate multiplier. This approach disregards any specific rate that might be defined for the exact matching tenor.

## Impact:
This bug can result in incorrect APR calculations when querying rates for tenors that exactly match entries in the yield curve. The severity is considered medium because:

1. It affects the accuracy of APR calculations, which is crucial for financial operations.
2. The impact is limited to exact tenor matches and does not affect interpolated values.
3. The incorrect calculation could lead to under or overestimation of APRs, potentially impacting financial decisions or contract interactions relying on these values.

## Steps to Reproduce:
1. Deploy the YieldCurveLibrary contract.
2. Create a YieldCurve struct with at least one tenor that has a specific APR and market rate multiplier different from its adjacent tenors.
3. Call the getAPR function with a tenor that exactly matches one of the tenors in the YieldCurve.
4. Observe that the returned APR does not correspond to the specific rate defined for that exact tenor.

## Proposed Fix:
Modify the getAPR function to correctly handle exact tenor matches:

```solidity
(uint256 low, uint256 high) = Math.binarySearch(curveRelativeTime.tenors, tenor);

if (low == high) {
    return getAdjustedAPR(curveRelativeTime.aprs[low], curveRelativeTime.marketRateMultipliers[low], params);
} else {
    uint256 x0 = curveRelativeTime.tenors[low];
    uint256 x1 = curveRelativeTime.tenors[high];
    uint256 y0 = getAdjustedAPR(curveRelativeTime.aprs[low], curveRelativeTime.marketRateMultipliers[low], params);
    uint256 y1 = getAdjustedAPR(curveRelativeTime.aprs[high], curveRelativeTime.marketRateMultipliers[high], params);

    if (y1 >= y0) {
        return y0 + Math.mulDivDown(y1 - y0, tenor - x0, x1 - x0);
    } else {
        return y0 - Math.mulDivDown(y0 - y1, tenor - x0, x1 - x0);
    }
}
```

This modification ensures that when an exact match is found, the function returns the correct adjusted APR for that specific tenor, rather than potentially using the APR from a lower tenor.
