# Vulnerability details

## Summary

The `multicall` function within the `Multicall.sol` contract is susceptible to a denial of service (DoS) exploit. This vulnerability arises from the unbounded loop that processes the `_data` array. An attacker can exploit this by providing an excessively large array, causing the gas consumption to exceed the block gas limit. As a result, the transaction fails, rendering the contract unusable.

## Vulnerability Detail

The `multicall` function in the `Multicall.sol` contract is designed to execute multiple operations within a single transaction by iterating over the `_data` array. However, this function lacks a mechanism to limit the number of operations it can process. If an attacker supplies a very large `_data` array, the loop processing these operations will consume a significant amount of gas. Once the gas consumption surpasses the block gas limit, the transaction will fail. This scenario can be exploited to launch a DoS attack against the contract, making it inaccessible to legitimate users.

The primary logic of the `multicall` function is as follows:

```solidity
/// @inheritdoc IMulticall
function multicall(bytes[] calldata _data)
    public
    payable
    override(IMulticall)
    whenNotPaused
    returns (bytes[] memory results)
{
    results = state.multicall(_data);
}
```

Here, this function calls `state.multicall(_data)`, which iterates through the `_data` array and executes each operation. Without a limit on the size of the `_data` array, the function is vulnerable to excessive gas consumption.

## Impact

An attacker can exploit this vulnerability to perform a DoS attack, preventing legitimate users from interacting with the Size contract. This can disrupt the functionality of the protocol, leading to financial losses and decreased user trust in the platform.

## Proof of Concept

1. Create a large array of operations to pass to the `multicall` function.
2. Call the `multicall` function with the large array and observe the gas consumption and eventual failure of the transaction.

## Recommended Mitigation Steps

To mitigate this, it is recommended to implement a limit on the number of operations that can be processed in a single `multicall` transaction. This can be achieved by adding a check to ensure the length of the `_data` array does not exceed a reasonable threshold.

```solidity
uint256 constant MAX_MULTICALL_OPERATIONS = 100;

function multicall(bytes[] calldata _data)
    public
    payable
    override(IMulticall)
    whenNotPaused
    returns (bytes[] memory results)
{
    require(_data.length <= MAX_MULTICALL_OPERATIONS, "Too many operations");
    results = state.multicall(_data);
}
```
