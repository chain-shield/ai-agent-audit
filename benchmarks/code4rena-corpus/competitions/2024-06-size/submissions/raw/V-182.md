# Vulnerability details

## Impact
If the price feed returns value outside the expected range any subsequent calculations involving this price would be incorrect instead of reverting.

## Proof of Concept
We can see that the function is missing check for minPrice/maxPrice:
 In certain scenarios, an attacker might be able to manipulate the price feed to return an extreme value (either very high or very low). If the contract does not validate this value, the attacker could exploit this to their advantage
```solidity
    function _getPrice(AggregatorV3Interface aggregator, uint256 stalePriceInterval) internal view returns (uint256) {
        // slither-disable-next-line unused-return
        (, int256 price,, uint256 updatedAt,) = aggregator.latestRoundData();

        if (price <= 0) revert Errors.INVALID_PRICE(address(aggregator), price); //@audit this will never be true because of minAnswer
        if (block.timestamp - updatedAt > stalePriceInterval) {
            revert Errors.STALE_PRICE(address(aggregator), updatedAt);
        }

        return SafeCast.toUint256(price);
    }
}
```
* `Alice` (Malicious Actor): Attempts to manipulate the price of a token by submitting an extremely low value to a Chainlink Price Feed.
* Chainlink Aggregator Contract: Due to the missing price validation in the contract's `_getPrice` function, the abnormally low price is accepted and published by the Price Feed.
* `Bob` (Unsuspecting Trader): Relies on the Chainlink Price Feed to determine the value of the token. Unaware of the manipulation, Bob sells his tokens at the low price, incurring a significant loss.
* `Alice` (Malicious Actor): Profits by buying the tokens at the manipulated low price, knowing that the price will eventually correct.
## Tools Used
Mannual Review
## Recommended Mitigation Steps
Modify the `_getPrice` function to explicitly validate the returned price `answer` against the aggregator's `minPrice` and `maxPrice`. If the price falls outside this range, the function should revert
