# Vulnerability details

## Impact
Currently, the `buyCreditMarket` validates the input parameters, executes the buy credit market action, and validates that the user is not below the opening limit borrow CR and that the variable pool has enough liquidity. However, it does not transfer the tokens from the caller to the contract.

## Proof of Concept
If the tokens are not transferred from the caller to the contract, the caller may lose the tokens they intended to use for buying credit. The tokens would remain in the caller's account, but the credit position would be created without the corresponding transfer of funds.

Code from `Size.sol` that illustrates the concept: [@>/buyCreditMarket](https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L178-L185)
```solidity
function buyCreditMarket(BuyCreditMarketParams calldata params) external payable override(ISize) whenNotPaused {
    state.validateBuyCreditMarket(params);
    uint256 amount = state.executeBuyCreditMarket(params);
    if (params.creditPositionId == RESERVED_ID) {
        state.validateUserIsNotBelowOpeningLimitBorrowCR(params.borrower);
    }
    state.validateVariablePoolHasEnoughLiquidity(amount);
}
```
As shown in the code, the function executes the buy credit market action and validates certain conditions, it does not include the necessary token transfer logic to move the tokens from the caller to the contract.

Consider an example scenario.

   1. Alice calls the `buyCreditMarket` function to buy credit worth 100 tokens.
   2. The function executes the buy credit market action and creates a credit position for Alice.
   3. However, the 100 tokens are not transferred from Alice's account to the contract due to the missing token transfer logic.
   4. The contract's internal accounting now reflects a credit position for Alice, but the contract does not hold the corresponding tokens.
   5. Alice effectively obtained a credit position without providing the required payment, leading to a loss of funds for the contract and an inconsistent state.

## Recommended Mitigation Steps
Should include a token transfer mechanism to transfer the token amount from the caller to the contract by using the `transferFrom` function of the token contract or by using a library like `SafeERC20` to handle the token transfer safely.
```diff
    // Transfer the tokens from the caller to the contract
+   IERC20(state.aToken).safeTransferFrom(msg.sender, address(this), amount);
}
```
