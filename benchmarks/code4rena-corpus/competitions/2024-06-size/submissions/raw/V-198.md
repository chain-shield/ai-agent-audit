# Vulnerability details

## Impact
Multicall will not work as expected. 
## Proof of Concept
Multicall is a function where the user can perform batch operations. It should pass and allow users to do valid transactions in any sequence. except for the one where they try to deposit ETH twice in the same call. 

In this case if a user perform a operation to deposit ETH and USDC in same call then it should pass because it is valid user action but the transaction will revert because of this check 
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/Size.sol#L142
```solidity
if (msg.value != 0 && (msg.value != params.amount || params.token != address(state.data.weth))) {
revert Errors.INVALID_MSG_VALUE(msg.value);
```

Here msg.value will be same in every call because of that the check require the token to be strictly WETH but it may be possible that user want to deposit USDC in the same call

### POC

Paste this test in `Multicall.t.sol`. As you can see this is reverting because of the incorrect check.

```solidity
function test_Multicall_multicall_cannot_deposit_both() public {
        vm.startPrank(alice);
        uint256 amount = 1 wei;
        vm.deal(alice, 2 * amount);
        deal(address(usdc), alice, 2 * amount);

        bytes[] memory data = new bytes[](2);
        data[0] = abi.encodeCall(
            size.deposit,
            (DepositParams({token: address(weth), amount: amount, to: alice}))
        );
        data[1] = abi.encodeCall(
            size.deposit,
            (DepositParams({token: address(usdc), amount: amount, to: alice}))
        );
        vm.expectRevert(
            abi.encodeWithSelector(Errors.INVALID_MSG_VALUE.selector, 2)
        );
        size.multicall{value: 2 * amount}(data);
    }

```
