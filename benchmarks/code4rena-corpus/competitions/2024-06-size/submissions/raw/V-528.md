# Vulnerability details

## Impact
Liquidators are at the core of the health of the system because they guard it from bad debt. However, if `liquidationRewardPercent` is misconfigured, liquidator could be disincentivized to liquidate. 

`liquidationRewardPercent` must be set at a level that incentivizes liquidators to liquidate positions below the `crLiquidation` threshold. This level can be adjusted by the admin according to current market risks. The lower this level, the less motivated the liquidators will be to liquidate.

`liquidatorReward` is calculated in `executeLiquidate()` function: 
```
uint256 liquidatorReward = Math.min(
                assignedCollateral - debtInCollateralToken,
                Math.mulDivUp(debtPosition.futureValue, state.feeConfig.liquidationRewardPercent, PERCENT)
            );
```

Liquidators are supposed to get up to `liquidationRewardPercent` as a reward. However, liquidators will never receive this level of reward if (1e18 + `liquidationRewardPercent`) is lower than `crLiquidation`.  Borrowers will be subject to liquidation at a level where liquidators can receive a maximum of `assignedCollateral - debtInCollateralToken`

In addition, this would cause a revert of all calls to `liquidate()` and `liquidateWithReplacement()` with a `minimumCollateralProfit` parameter set to a level that can never be reached due to `validateMinimumCollateralProfit()` check.

Such a configuration is possible due to insufficient checks in `executeUpdateConfig()`.

## Recommended Mitigation Steps
Ensure  that liquidators could get the maximum reward when liquidating by adding the following checks in `executeUpdateConfig()`:
```
[...]
} else if (Strings.equal(params.key, "crLiquidation")) {
            if (params.value >= state.riskConfig.crLiquidation) || (params.value <= (1e18 + state.feeConfig.liquidationRewardPercent)) {
                revert Errors.INVALID_COLLATERAL_RATIO(params.value);
            }
[...]
```
