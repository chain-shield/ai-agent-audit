# Vulnerability details

## Impact
1)In both  Size::BuyCreditMarket and Size::SellCreditMarket functions,   createDebtAndCreditPositions and  createCreditPosition  functions are used to create new CreditPositions.
2)In createDebtAndCreditPositions function,
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L62-L92

    creditPosition = CreditPosition({
    lender: lender,
    credit: debtPosition.futureValue,
    debtPositionId: debtPositionId,
    forSale: true
    }); 


3)In createCreditPosition function,
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/AccountingLibrary.sol#L103-L127

   CreditPosition memory creditPosition =
    CreditPosition({lender: lender, credit: credit, debtPositionId: debtPositionId, forSale: true});

in both these functions forSale is set to true, so immediately after a CreditPosition is created it can be bought by a malicious user if the lender of the creditposition is until now not set user configuration or set allCreditPositionsForSaleDisabled as false. This credit position can be bought by a  malicious user until the lender changed forSale parameter of this CreditPosition as false.so even though lender buy this credit position and not wanted to  sell it, malicious user can buy this CreditPosition. so a malicious user who wanted to defame Size protocol can do this with multiple users and finally, users will lose trust in the Size protocol.And if APR for this tenor in BorrowOffer parameter of lender's User struct is higher then lender have to face loses.






## Proof of Concept
To buy a Credit Position using size::buyCreditMarket function, the current lender of that credit position should has a BorrowOffer in his User struct
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L83-L88
 and allCreditPositionsForSaleDisabled should be false for current lender  and forSale parameter of that CreditPosition should be true.
https://github.com/code-423n4/2024-06-size/blob/8850e25fb088898e9cf86f9be1c401ad155bea86/src/libraries/actions/BuyCreditMarket.sol#L75-L77
so if a new CreditPosition is created using size::buyCreditMatket or size::sellCreditMarket function then immediately after that a malicious user can buy this CreditPosition  because forSale parameter is set to true while creating that CreditPosition if current lender's User struct has a BorrowOffer and his allCreditPositionsForSaleDisabled parameter is set to false.

## Tools Used
manual review, vscode

## Recommended Mitigation Steps
set forSale parameter as false while creating a CreditPosition using createDebtAndCreditPositions and createCreditPosition functions.
As immediatley after creating a CreditPosition it is not supposed to be sale.If lender of that CreditPosition want it to be forsale then he change forSale parameter of that CreditPosition using setUserConfiguration function.
