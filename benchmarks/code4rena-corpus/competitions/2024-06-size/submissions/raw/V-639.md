# Vulnerability details

## Impact
Users can't withdraw borrow or collateral tokens if their collateral ratio is below opening ratio but above liquidation ratio.

[Size.withdraw()](https://github.com/code-423n4/2024-06-size/blob/main/src/Size.sol#L162) checks that user has collateral ratio above opening ratio. The problem is that:
1. Users potentially can't withdraw USDC if their `CR < openingCR`, even if `CR > liquidationCR`.
2. Arguably, collateral withdrawal should only be prevented if that pushes the user underwater.
3. Centralization risk of `updateConfig()` being used to increase `openingCR` and preventing all withdrawals.

## Proof of Concept

Following test case added to `Withdrawal.t.sol` fails.

```
    function test_Withdraw_user_can_withdraw_if_they_are_not_underwater() public {
        _setPrice(1e18);
        _deposit(alice, usdc, 150e6);
        _deposit(bob, usdc, 150e6);
        _deposit(bob, weth, 150e18);
        _buyCreditLimit(alice, block.timestamp + 12 days, YieldCurveHelper.pointCurve(12 days, 0));
        _sellCreditMarket(bob, alice, RESERVED_ID, 50e6, 12 days, false);

        _setPrice(1e18 / 2);
        assertLt(size.collateralRatio(bob), size.riskConfig().crOpening);
        assertTrue(!size.isUserUnderwater(bob));

        vm.startPrank(bob);
        size.withdraw(WithdrawParams({token: address(usdc), amount: 1, to: bob}));
    }
```

## Recommended Mitigation Steps
Use `liquidationCR` instead of `openingCR` as the threshold. Also, consider always allowing borrow token withdrawal.
