S-532
Linear discount is not calculated correctly
0xrex
69
Sufficient
383d ago
Finding description and impact

Token sellers can set up discounts for tokens being sold such as 10%. This would mean that the users would pay 10% less overall for the token sale. For the case of the linear discount, using the current calculation, the actual discount linearly will be 5% max not 10.

Proof of Concept
function _getDiscountedPrice(Listing storage listing, uint256 _amount) private view returns (uint256) {
        uint256 discountedPrice = listing.pricePerUnit;

        if (listing.discountType == DiscountType.LINEAR) {
            discountedPrice = (discountedPrice * (BASE - ((_amount * listing.discountPct) / listing.total))) / BASE;
        } else if (listing.discountType == DiscountType.FIX) {
            discountedPrice = (discountedPrice * (BASE - listing.discountPct)) / BASE;
        }
        return discountedPrice;
    }

Scenario:

100e18 tokens listed for sale, 10% linear discount applied, 1 USDC per unit of token, expected baseAmount at end of sale is 90 USDC. If 2 users buy 50% of the tokens each:

user 1 would pay 0.95 USDC per token. because:
discountedPrice = (1e6 * (10000 - ((50e18 * 1000) / 100e18))) / 10000; hence 47.5 USDC for 50 tokens. the second user would pay the same figure too. at the end of the sale, the total amount will be 95 USD.

This is the case because the linear calculation only keeps track of the tokens left unsold and doesn't keep track of how many tokens are sold so far.

Recommended mitigation steps

In order to reach e.g 10% linearly discount for a listing sale the protocol should keep track of the total amount of tokens sold and include that in the discount calculation
