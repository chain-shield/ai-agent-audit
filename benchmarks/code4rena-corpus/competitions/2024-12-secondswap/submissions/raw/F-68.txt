S-357
Inconsistent Fee Validation Logic
Mrxstrange
18
Sufficient
383d ago
Description
The following require statement contains a logical inconsistency between the condition and the accompanying error message:
require(_fee > -1 && _fee <= 5000, "SS_VestingManager: Seller fee cannot be less than 0");
The condition _fee > -1 is equivalent to _fee >= 0. However, the error message "Seller fee cannot be less than 0" suggests that _fee must indeed be non-negative (greater than or equal to 0). This creates confusion for both developers and auditors since _fee can technically be any value greater than -1, including negative values like -1 (if _fee is a decimal type).
Impact

This inconsistency can lead to:

Misleading Error Messages: Developers may misinterpret the actual requirements for _fee.
Potential Runtime Errors: If _fee is used in calculations assuming it is non-negative, allowing values close to -1 could result in unexpected behavior.
Steps to Reproduce
Set _fee = -1
Observe that the require condition passes, even though the error message implies such values are invalid.
Suggested Fix

To enforce consistent logic, ensure _fee is strictly non-negative (greater than or equal to 0) and less than or equal to 5000. Update the code as follows:

require(_fee > -1 && _fee <= 5000, "SS_VestingManager: Seller fee cannot be less than 0");
Updated Error Message:
"SS_VestingManager: Invalid seller fee": This message generalizes the error to accommodate special cases like _fee == -1.
