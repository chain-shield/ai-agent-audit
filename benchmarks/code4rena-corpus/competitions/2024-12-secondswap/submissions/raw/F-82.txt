S-568
Incomplete Function Existence Check
TheFabled
44
Sufficient
383d ago

Description:

The doesFunctionExist function aims to check if a target contract has a specific function. However, the implementation may not reliably determine the existence of the function.

function doesFunctionExist(address target, string memory functionSignature) public view returns (bool) {
    bytes4 selector = bytes4(keccak256(bytes(functionSignature)));
    (bool success, ) = target.staticcall(abi.encodeWithSelector(selector));
    return success;
}

Issue:

This method may return true even if the function does not exist but a fallback function is present. Additionally, it does not account for function input parameters.

Impact:

False Positives: The contract might assume a function exists when it does not, leading to unexpected behavior.
Security Risks: Relying on incorrect assumptions about a contract's interface can introduce vulnerabilities.

Recommendation:

Use Interface Checks: Use Solidity's interface support or try-catch statements to interact with external contracts safely.
Remove or Refine the Function: If not critical, consider removing the function or using established patterns for interface detection.

Not agree with the severity

TheFabled
OP

The doesFunctionExist function is supposed to check if a token contract has a decimals() function:

function doesFunctionExist(address target, string memory functionSignature) public view returns (bool) {
    bytes4 selector = bytes4(keccak256(bytes(functionSignature)));
    (bool success, ) = target.staticcall(abi.encodeWithSelector(selector));
    return success;
}

It's meant to ensure that the decimals() function exists before the contract proceeds to use it. Now, they use this function in listVesting like so:

require(
    doesFunctionExist(tokenAddress, "decimals()"),
    "SS_Marketplace: No decimals function"
);

But here's where things can go wrong. If a token contract doesn't have a decimals() function but has a fallback function that doesn't revert, the staticcall in doesFunctionExist will still return success = true. That means doesFunctionExist will incorrectly return true, thinking decimals() exists when it doesn't.

Then, when the contract tries to call decimals():

uint8 decimals = IERC20Extended(tokenAddress).decimals();

It might fail or return some garbage value. If decimals is wrong, any calculations using it will be off. For example:

uint256 baseAmount = (_amount * _price) / (10 ** decimals);

If decimals is zero or some unexpected number, baseAmount could be way too high or low. This can cause users to pay too much or too little, leading to losses or even allowing malicious actors to exploit the system.

So the impact here is that incorrect usage of decimals() can mess up price calculations, causing real monetary issues. That's why I think this issue isn't just a Low severity—it's got enough potential for harm to be considered Medium.

To fix this, they should probably avoid using doesFunctionExist and instead use a try-catch when calling decimals(): Because this flaw can lead to significant financial errors and potential exploitation, I believe it should be classified as Medium severity.
