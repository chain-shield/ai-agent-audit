S-1002
Token issuer referral reward manipulation through combined direct and market Transfers
Sabit
20
Sufficient
383d ago
Finding description and impact

The tokenIssuer can be used as a referrer in marketplace purchases, even after directly transferring tokens to the same buyer. This creates an unintended profit opportunity through referral rewards that undermines the marketplace's referral incentive system.

The vulnerability stems from insufficient referral validation in the spotPurchase function:

function spotPurchase(address _vestingPlan, uint256 _listingId, uint256 _amount, address _referral) external isFreeze {
    // Current validation only checks if buyer is not referrer
    _validatePurchase(listing, _amount, _referral);
}

function _validatePurchase(Listing storage listing, uint256 _amount, address _referral) private view {
    require(msg.sender != _referral, "SS_Marketplace: Invalid referral");
}


https://github.com/code-423n4/2024-12-secondswap/blob/214849c3517eb26b31fe194bceae65cb0f52d2c0/contracts/SecondSwap_Marketplace.sol#L513C6-L513C56

https://github.com/code-423n4/2024-12-secondswap/blob/214849c3517eb26b31fe194bceae65cb0f52d2c0/contracts/SecondSwap_Marketplace.sol#L389

This bug can occur where the tokenIssuer calls the transferVesting function to directly transfer some tokens to a beneficiary, and the beneficiary in turn buys some tokens through the spotPurchase and then include the tokenIssuer as the referral. It like a situation of "I scratch your back, you scratch my back".

https://github.com/code-423n4/2024-12-secondswap/blob/214849c3517eb26b31fe194bceae65cb0f52d2c0/contracts/SecondSwap_StepVesting.sol#L218

Proof of Concept

Here's a practical scenario:

TokenIssuer transfers 1000 tokens to Alice through direct vesting:
tokenIssuer.transferVesting(alice, 1000 tokens)

Alice spots a marketplace listing for 500 tokens

Alice purchases using tokenIssuer as referrer:
spotPurchase(vestingPlan, listingId, 500, tokenIssuer)

Result:

Alice receives 500 tokens
TokenIssuer receives referral reward
System allows this despite tokenIssuer's privileged role

The vulnerability creates a circular benefit where the tokenIssuer can:

Transfer tokens directly to users
Receive referral rewards when these users make marketplace purchases
Effectively double-dip on token distribution benefits
Recommended mitigation steps
function _validatePurchase(Listing storage listing, uint256 _amount, address _referral) private view {
    require(msg.sender != _referral, "SS_Marketplace: Invalid referral");
    require(_referral != tokenIssuer, "SS_Marketplace: TokenIssuer cannot be referrer");
}


This enhancement maintains clear separation between protocol administration and marketplace participation while preserving the intended purpose of the referral system.
