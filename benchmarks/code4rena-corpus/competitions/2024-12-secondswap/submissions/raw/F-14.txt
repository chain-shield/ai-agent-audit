S-279
Wrongly Set Penalty Fee
EPSec
88
Sufficient
383d ago
Finding description and impact

In SecondSwap_MarketplaceSetting the penaltyFee is set to 10 ether. This is 10e18. However, the penalty fee is paid with the USDT token. USDT token on all supported chains is a token with 6 decimals. Setting the penaltyFee to 10 ether will set it to 10e18 which is 10000000000000 USDT ~ 10000000000000 $.

The penaltyFee can be changed, however, this mistake renders a big part of the protocol useless until that is done by the owner. What is more, if a user theoretically has this amount of USDT and is using the given contract with an approval set to an equal or bigger number, they will lose funds thinking that the fee should be much less.

Proof of Concept

Add this test to the Marketplace.test.ts file and run it with npx hardhat test:

it("penaltyFee is too big", async function() {
	const { marketplaceSetting } = await loadFixture(deployProxyFixture);

	// Fetch penaltyFee from the settings contract
	var penaltyFee = await marketplaceSetting.read.penaltyFee();

	// USDT is a token with 6 decimals, so we divide by 1e6
	var USDTTokens = penaltyFee / BigInt(1e6);

	// This passes meaning that penalty fee is 10 trillion
	expect(USDTTokens).to.equal(BigInt(1e13));
});
Recommended Mitigation Steps

Change the penaltyFee to a real value that will not render the protocol useless. For example, 10e6 can be used which is ~ 10 $.
