S-349
Blockchain re-org may cause users to mistakenly purchase tokens at a higher price.
shaflow2
71
Sufficient
383d ago
Finding description and impact

The spotPurchase function uses the plan address and ID to distinguish different orders, but it lacks user protection against spending with the highest slippage control. If a blockchain reorganization occurs, it may swap the order IDs, causing users to mistakenly purchase tokens at a higher price.

Proof of Concept

The order IDs are incrementally generated at the time of creation.

    function listVesting(
        address _vestingPlan,
        uint256 _amount,
        uint256 _price,
        uint256 _discountPct,
        ListingType _listingType,
        DiscountType _discountType,
        uint256 _maxWhitelist,
        address _currency,
        uint256 _minPurchaseAmt,
        bool _isPrivate
    ) external isFreeze {
        ...

        uint256 listingId = nextListingId[_vestingPlan]++;
        address whitelistAddress;

        if (_isPrivate) {
            require(_maxWhitelist > 0, "SS_Marketplace: Minimum whitelist user cannot be 0");
            whitelistAddress = SecondSwap_WhitelistDeployer(IMarketplaceSetting(marketplaceSetting).whitelistDeployer())
                .deployWhitelist(_maxWhitelist, msg.sender);
            emit WhitelistCreated(_vestingPlan, listingId, whitelistAddress, msg.sender, _maxWhitelist);
        }

        listings[_vestingPlan][listingId] = Listing({
            seller: msg.sender,
            total: _amount,
            balance: _amount,
            pricePerUnit: _price,
            listingType: _listingType,
            discountType: _discountType,
            discountPct: _discountPct,
            listTime: block.timestamp,
            whitelist: whitelistAddress,
            currency: _currency,
            minPurchaseAmt: _minPurchaseAmt,
            status: Status.LIST,
            vestingPlan: _vestingPlan
        });
        emit Listed(_vestingPlan, listingId);
    }

Consider the following scenario:

User1 creates an order for _vestingPlan, selling 1000 locked tokens at a price of 1 USDT per unit, with Order ID = 1.
User2 creates an order for _vestingPlan, selling 1500 locked tokens at a price of 0.98 USDT per unit, with Order ID = 2.
User3 purchases 500 tokens from User2's order, providing Order ID = 2 as input.

After a blockchain reorganization, the transaction order changes to:
2 -> 1 -> 3.
As a result, User3 mistakenly buys 500 tokens from User1's order at 1 USDT per unit instead of the intended 0.98 USDT per unit.

Recommended mitigation steps

Consider adding slippage protection to the spotPurchase function by introducing a parameter for the maximum price the user is willing to tolerate, or creating a unique identifier for each order by combining order details and the creator's nonce, ensuring that the identifier is unique and never repeated.
