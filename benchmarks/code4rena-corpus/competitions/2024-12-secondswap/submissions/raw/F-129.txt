Lack of deadline checks in spotPurchase allows miners to manipulate execution timing for profit
bumbleb33
00
Sufficient
383d ago

Description: The spotPurchase function in SecondSwap_Marketplace.sol lacks a deadline parameter and slippage protection checks. This allows miners to intentionally delay transaction execution until market conditions are unfavorable for the buyer.

When a user submits a purchase transaction, miners can:

See the transaction in the mempool
Hold the transaction without including it in a block
Wait until the price moves unfavorably for the user
Include the transaction when it will result in the worst possible execution price

This is particularly dangerous because:

The marketplace deals with vested tokens which may have volatile prices
There's no way for users to specify maximum acceptable slippage
Users have no control over when their transaction will be executed
Miners can extract value through this timing manipulation
function spotPurchase(
    address _vestingPlan,
    uint256 _listingId,
    uint256 _amount,
    address _referral
) external isFreeze {
    // No deadline check
    // No slippage protection
    // Transaction can be held indefinitely by miners
}

Impact: HIGH. This vulnerability can lead to:

Direct loss of user funds through forced unfavorable execution
MEV extraction by miners
Users paying significantly more than intended for tokens
Inability to guarantee execution price
Loss of user trust in the platform

Proof of Concept:

User submits transaction to buy 1000 tokens at 1 USDC each
Price of token starts increasing
Miner holds transaction and doesn't include it in blocks
Price reaches 1.5 USDC per token
Miner includes transaction, forcing user to buy at 50% higher than intended
User loses 500 USDC due to delayed execution

Recommended Mitigation:
Add deadline and slippage protection parameters to the spotPurchase function:

function spotPurchase(
    address _vestingPlan,
    uint256 _listingId,
    uint256 _amount,
    address _referral,
    uint256 deadline
) external isFreeze {
    require(block.timestamp <= deadline, "SS_Marketplace: Transaction expired");
    
    Listing storage listing = listings[_vestingPlan][_listingId];
    uint256 finalPrice = _getDiscountedPrice(listing, _amount);
   
    
    // Rest of the function...
}

This ensures:

Transactions expire if not executed within user-specified timeframe
Users can specify maximum acceptable price
Miners cannot profit from intentionally delaying transactions
Users have control over their trade execution parameters
