# Vulnerability details

The `Whitelist::checkWhitelist` function has two significant issues. Firstly, it relies on the Uniswap oracle TWAP (time-weighted average price) to get the price, which can be manipulated. Secondly, the function allows users to bypass the `maxAddressCap` check if they use a small amount that results in `estimatedETHAmount` being zero, causing the cap check to always pass.

### Impact

1. **Price Manipulation via Uniswap Oracle TWAP:**

- Attackers can manipulate the TWAP by conducting large trades within a short time frame, influencing the reported price. This can lead to incorrect pricing, which may result in users being able to whitelist at unfavorable rates, causing financial loss or arbitrage opportunities. You should never relay on uniswap oracle price. It could lead to 
2. **Bypassing `maxAddressCap`:**

- Users can circumvent the `maxAddressCap` by using small amounts that result in `estimatedETHAmount` being zero. This means the check designed to limit the amount a single address can whitelist fails, allowing users to exceed the intended cap and potentially exploit the system for excessive allocation.

## Proof of concept

- **Price Manipulation:**

  An attacker can repeatedly trade a token pair on Uniswap within a short time window to skew the TWAP. For example, buying a large amount of ETH to spike the price and then selling it back can create an artificially high TWAP, which the `checkWhitelist` function uses, resulting in incorrect price calculations.
  
- **Bypassing `maxAddressCap`:**

  If `maxAddressCap` is set to a certain value and the user inputs a small amount that causes `estimatedETHAmount` to be zero, the check will pass everytime.

## Recommended mitigation steps

**Mitigate Price Manipulation:**

Use Chainlink Price Feeds as a reliable price oracle. Chainlink Price Feeds aggregate data from multiple sources and are resistant to manipulation.

**Prevent Bypassing `maxAddressCap`:**

Ensure that `estimatedETHAmount` accurately reflects small amounts and enforce a minimum amount requirement to prevent zero values.
