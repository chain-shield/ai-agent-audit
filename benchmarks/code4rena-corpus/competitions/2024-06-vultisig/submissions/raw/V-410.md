# Vulnerability details

## Impact
The initProject function deploys a uniV3Pool. If that pool is already associated with a project the transaction will revert. Thus, whenever an honest actor is initializing a project, anyone can frontrun their transaction with a call to initProject with the same params.saleToken, params.raiseToken and params.fee. This will deploy a pool at the same address and the honest user's transaction will revert. They will be then forced to deploy a new pool with a different params.fee.

A malicios party that wants to sabotage a launch can effectively DoS the deployer, frontrunning all of their transactions to init a project.

## Proof of Concept
The initProject() function will first get the `uniV3PoolAddress` from the _initUniV3PoolIfNecessary() function and then cache the project with the resulting address.

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L57
```js
    function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address uniV3PoolAddress) {
        uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;

        PoolAddress.PoolKey memory poolKey = PoolAddress.getPoolKey(params.saleToken, params.raiseToken, params.fee);
        uniV3PoolAddress = _initUniV3PoolIfNecessary(poolKey, params.initialPoolPriceX96);
        
        _cacheProject(uniV3PoolAddress, params.saleToken, params.raiseToken, params.fee, params.initialPoolPriceX96, params.launchTime, refundDeadline);
        emit ProjectCreated(uniV3PoolAddress, _cachedProject[uniV3PoolAddress]);
    }
```

The _initUniV3PoolIfNecessary() function will only initialze a pool if it is not present. The pool parameters are poolKey.token0, poolKey.token1 and poolKey.fee, so if these parameters have been passed in the function will return the initialized pool address.

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L109
```js
    function _initUniV3PoolIfNecessary(PoolAddress.PoolKey memory poolKey, uint160 sqrtPriceX96) internal returns (address pool) {
        pool = IUniswapV3Factory(UNIV3_FACTORY).getPool(poolKey.token0, poolKey.token1, poolKey.fee);
        if (pool == address(0)) {
            pool = IUniswapV3Factory(UNIV3_FACTORY).createPool(poolKey.token0, poolKey.token1, poolKey.fee);
            IUniswapV3Pool(pool).initialize(sqrtPriceX96);
        } else {
            // @audit supposedly the pool will not have any liquidity in it, thus the price will not change until after the launch
            (uint160 sqrtPriceX96Existing, , , , , , ) = IUniswapV3Pool(pool).slot0();
            if (sqrtPriceX96Existing == 0) {
                IUniswapV3Pool(pool).initialize(sqrtPriceX96);
            } else {
                // @audit can a malicios user frontrun this and set a different initial price?
                require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P");
            }
        }
    }
```

The cache project function will revert if the pool has already been assigned to a project. Thus if a malicios user frontruns an honest transaction they will be able to claim ownership of the project that uses this uniV3 pool.

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L124
```js
    function _cacheProject(
        address uniV3PoolAddress,
        address saleToken,
        address raiseToken,
        uint24 fee,
        uint160 initialPoolPriceX96,
        uint64 launchTime,
        uint64 refundDeadline
    ) internal {
        Project storage _project = _cachedProject[uniV3PoolAddress];
        require(_project.uniV3PoolAddress == address(0), "RE");
        
        //@audit everything is set apart from investorShares 
        _project.platformFee = PLATFORM_FEE;
        _project.performanceFee = PERFORMANCE_FEE;
        _project.admin = msg.sender;
        _project.saleToken = saleToken;
        _project.raiseToken = raiseToken;
        _project.fee = fee;
        _project.initialPoolPriceX96 = initialPoolPriceX96;
        _project.launchTime = launchTime;
        _project.refundDeadline = refundDeadline;
        _project.uniV3PoolAddress = uniV3PoolAddress;
        _project._cachedPoolKey = PoolAddress.getPoolKey(saleToken, raiseToken, fee);
    }
```

## Recommended Mitigation Steps
Require that the msg.sender has a non-zero balance of both tokens. This would require the token launcher to have a small amount of the launch token. Since there will be no other liqudity of that token in the market no-one else would be able to hijack their project.
