# Vulnerability details

## Proof of Concept

The `VultisigWhitelisted` contract overrides the `_beforeTokenTransfer` function to check whitelisting information. It is important to note that there is no validation on the input `amount`.


```solidity

    function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
            IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }

```

In the `Whitelist` contract, after validation, it calls the `oracle` to get the current TWAP price, adds it to the contribution, and then validates that the total should not exceed the allowed `_maxAddressCap`.

```solidity

    function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
        if (from == _pool && to != owner()) {
            // SNIP: VALIDATION

            // // Calculate rough ETH amount for VULT amount
            uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
@->         if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
                revert MaxAddressCapOverflow();
            }

            _contributed[to] += estimatedETHAmount;
        }
    }

```

An important point to note here is that `estimatedETHAmount = 0` is allowed.

If you see `peek` function closely:

```solidity

    function peek(uint256 baseAmount) external view returns (uint256) {
        uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
        uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
        int24 tick = OracleLibrary.consult(pool, period);
        uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
@->     return (quotedWETHAmount * baseAmount * 95) / 1e20;
    }

```

The `baseAmount` can be controlled by the user. Also, as per the docs:

> All of the initial raise of capital from external investors (tentatively USD \$2.4m) will be converted to ETH and placed in a liquidity pool for launch, together with 80m $VULT (80% of total supply).

This means 2.4M USD roughly equals `675 WETH` tokens (as per current price while reporting) versus 80M VULT tokens. Therefore, the `quotedWETHAmount` value is assumed to be a multiple of `1e14`.

This shows that the return value from `peek` can be rounded down to zero for smaller `baseAmount` as whole equation is divided by `1e20`. This allows Users to bypass `_maxAddressCap` check by getting smaller amount of tokens repeatedly multiple times.

## Impact

Users can bypass the invariant that they cannot exceed the `_maxAddressCap`.

## Recommended Mitigation Steps

Add a check in the `checkWhitelist` function as shown below to disallow zero value for `estimatedETHAmount`:

```diff

    function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
        if (from == _pool && to != owner()) {
            // SNIP: VALIDATION

            // // Calculate rough ETH amount for VULT amount
            uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
-           if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
+           if (_contributed[to] + estimatedETHAmount > _maxAddressCap || estimatedETHAmount == 0) {
                revert MaxAddressCapOverflow();
            }

            _contributed[to] += estimatedETHAmount;
        }
    }

```
