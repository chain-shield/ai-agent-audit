# Vulnerability details

## Impact
[Users](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L252) And [FeeTakers](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L259) may not be able to claim their amount

## Proof of Concept
Protocol is supposed to work with blacklisted tokens.
So if a user who is expecting to claim their tokens may see their transaction get revert if they have been blacklisted by the tokens, but we don't realy have a problem with that since they are the one's initiating the claiming process
The problem is when the transfer of the fees of the token amount to the FEETAKER
in here 
```
       address feeTaker = IILOManager(MANAGER).FEE_TAKER();
        // transfer fee to fee taker
        TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);
```
 fails due to they being blacklisted , since Vultisig deployers are supposed to set a feeTaker,They can unknowingly set a blacklisted user as [FEETaker](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L160)) 
```
 function setFeeTaker(address _feeTaker) external override onlyOwner() {
        FEE_TAKER = _feeTaker;
    }
```

## Tools Used
Manual Analysis

## Recommended Mitigation Steps
For transferring tokens to users have blacklisted check.
for `feeTaker` implement the push method in a try-catch block where if it fails send those fee amount to a escrow contract from where they can pull their funds from or set up a blacklisted check in the ILOManager where they are configured.
