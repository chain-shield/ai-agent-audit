# Vulnerability details

## Impact
The `Vultisig token` will initially have a whitelist period that allows only whitelisted addresses to transfer tokens, with a maximum cap of `VULT` tokens worth `3 ETH`.

The owner has the ability to set a self-whitelisting period, where users can whitelist themselves by sending ETH to the `Whitelist` contract, which will immediately return the ETH sent in addition to whitelisting the address.

Anyone can whitelist as many addresses as they own, therefore allowing them to bypass the maximum cap of `3 ETH`, breaking an invariant that users should not be able to transfer `VULT` worth more than `3 ETH`.

## Proof of Concept
[VultisigWhitelisted.sol#L28-L33](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/extensions/VultisigWhitelisted.sol#L28-L33)
```javascript
    function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
            IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }
```

Only whitelisted users are allowed to transfer `Vultisig tokens` during this period (when whitelistContract != address(0)).

[Whitelist.sol#L220-L226)](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L220-L226)
```javascript
    // // Calculate rough ETH amount for VULT amount
    uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
    if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
        revert MaxAddressCapOverflow();
    }

    _contributed[to] += estimatedETHAmount;
```

The `_maxAddressCap` is always set to `3 ETH`, if the amount the user has transferred so far exceeds this value for `VULT` tokens, then they can no longer transfer `VULT` tokens.

The owner can set a `self-whitelist period` by setting `_isSelfWhitelistDisabled = false`, which allows any user to whitelist themselves by sending ETH to the `Whitelist` contract.

[Whitelist.sol#L61-L74](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L61-L74)
```javascript
    /// @notice Self-whitelist using ETH transfer
    /// @dev reverts if whitelist is disabled
    /// @dev reverts if address is already blacklisted
    /// @dev ETH will be sent back to the sender
    receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        payable(_msgSender()).transfer(msg.value);
    }
```

Since the ETH amount sent by the user is refunded, a user can whitelist themselves on as many addresses as they like. 

If the `3 ETH` amount exceeds on one address, they can continue transferring that amount on a separate address. This can be repeated with many different addresses, allowing users to bypass the `3 ETH` limit.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider taking a small fee from the caller during self whitelist period, this will decentivize users from whitelisting themselves on multiple addresses to bypass whitelist limits.
