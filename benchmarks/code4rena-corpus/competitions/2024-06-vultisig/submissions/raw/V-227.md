# Vulnerability details

## Impact
In `ILOPool::buy` the solidity version of the contract is =0.7.6 which does NOT support automatic overflow/underflow protection as all the versions >=0.8.x do support.

```solidity
    _position.liquidity += liquidityDelta;
```

The `_position.liquidity` field is of type uint128 and by providing large enough number when we add up `liquidityDelta` to `_position.liquidity` an overflow is imminent resulting in totally incorrect _position.liquidity.


## Proof of Concept
1. Call the external function `ILOPool::buy` with a `raiseAmount` enough times (could take thousands) and an overflow occurs since there is no overflow protection.

## Tools Used
Solidity, Foundry

## Recommended Mitigation Steps

Two good options to fix this behavior are the following:

1. Use higher solidity version which is >= 0.8.0 because the overflow/underflow protection is automatically integrated in solidity and there is no need to explicitly use an external library or additing manual logic to protect from overflows/underflows.

2. Use OpenZeppelin SafeMath library to add the two variables 
Reference: https://github.com/ConsenSysMesh/openzeppelin-solidity/blob/master/contracts/math/SafeMath.sol
