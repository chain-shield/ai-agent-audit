# Vulnerability details

## Impact
The misconfiguration of access control for the `launch` function poses a significant security risk. According to the documentation, only the project admin should have the authority to launch the project, which involves launching all Initial Liquidity Offering (ILO) pools. The current implementation lacks proper restriction, allowing any user to potentially call this function. This could lead to unauthorized project launches, disruption of the intended project flow, and potential financial losses.

## Proof of Concept
The documentation specifies:

`ILO pool can only launch from the manager. Only project admin can launch project (aka launch all ILO pool).`

## Recommended Mitigation Steps
Ensure that the `launch` function in the project contract includes the `onlyProjectAdmin` modifier to restrict access to the project admin.

```solidity
function launch(address uniV3PoolAddress) external override onlyProjectAdmin {
    require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
    (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
    require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
    address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
    require(initializedPools.length > 0, "NP");
    for (uint256 i = 0; i < initializedPools.length; i++) {
        IILOPool(initializedPools[i]).launch();
    }

    emit ProjectLaunch(uniV3PoolAddress);
}
```
