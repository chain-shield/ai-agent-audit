# Vulnerability details

## Summary

**Context:**
The function [checkWhitelist()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204) is called from the [_beforeTokenTransferHook()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/extensions/VultisigWhitelisted.sol#L28) in the Vultisig token contract when a buy action call arrives from the univ3 pool.

**Root cause:**
The issue is that [checkWhitelist()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204) makes all the necessary checks [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L208) but it forgets to make the most basic check i.e. if _whitelistIndex[to] is 0 or not. If it is 0, the "to" address is not whitelisted but if it isn't 0, the address is whitelisted.

**Impact:**
Due to this, the whole point of the whitelist is defeated since the "to" address need not be whitelisted to perform a buy action from the univ3 pool.

## Proof of Concept

1. Buy action call arrives from the univ3 pool through the [_beforeTokenTransferHook()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/extensions/VultisigWhitelisted.sol#L28) in the Vultisig token contract. This calls the [checkWhitelist()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204) function on the Whitelist.sol contract.

2. In function [checkWhitelist()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204), it makes all security checks from Line 221 to 230 but forgets to make the most basic check i.e. checking if the "to" address is whitelisted or not. This is by checking the whitelist index of the "to" address to be zero or not. This breaks the whitelist mechanism and allows anyone to perform buy actions during the whitelist period.
