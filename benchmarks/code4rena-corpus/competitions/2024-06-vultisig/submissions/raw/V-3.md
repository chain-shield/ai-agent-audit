# Vulnerability details

## Impact
`Uniswap` math libraries rely on wrapping behavior for conducting arithmetic operations. Solidity version `0.8.0` introduced checked arithmetic by default where operations that cause an `overflow` would revert.

## Proof of Concept
The protocol uses FullMath library when fetching TWAP for 1 VULT for the last 30 mins via the [peek()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/oracles/uniswap/UniswapV3Oracle.sol#L38-L46) function:
```solidity
/// @notice Returns TWAP price for 1 VULT for the last 30 mins
    function peek(uint256 baseAmount) external view returns (uint256) {
        uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
        uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
        int24 tick = OracleLibrary.consult(pool, period);
>>      uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH); // @audit-issue FullMath may overflow
        // Apply 5% slippage
        return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
    }
```
This is then used to calculate rough ETH amount for VULT amount in [checkWhitelist()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L220-L221):
```solidity
      // Calculate rough ETH amount for VULT amount
>>    uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
```
All these calculation may overflow and break the sytem where they are needed.

Since the code was adapted from `Uniswap` and written in Solidity version `0.4.0`, these arithmetic operations should be wrapped in an `unchecked` block.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add an `unchecked` block to the following functions in `TickMath.sol` and `FullMath.sol`.
- `mulDiv()`
- `mulDivRoundingUp()`
- `getSqrtRatioAtTick()`
- `getTickAtSqrtRatio()`
