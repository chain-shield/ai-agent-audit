# Vulnerability details

## Impact

In the current implementation of `ILOPool` smart contract, when launching the pool, we call uniswapV3 `addLiquidity()` by providing different params including `amount0Min` and `amount1Min`. However, the function doesn't check if the the amount is bigger than these params after the function call.

## Proof of Concept

Let's look at the `addLiquidity()` function in `ILOPool`:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L296-303
```
  (amount0, amount1) = addLiquidity(AddLiquidityParams({
                pool: IUniswapV3Pool(uniV3PoolAddress),
                liquidity: liquidity,
                amount0Desired: amount0,
                amount1Desired: amount1,
                amount0Min: amount0Min,
                amount1Min: amount1Min
            }));
```

So it has params `amount0Min` and `amount1Min` that are needed to protect from slippage. However, the function doesn't check for `amount0` and `amount1` to be bigger than `amount0Min` and `amount1Min` that can lead to the different values being obtained other than those that were expected from the function call.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Add the checks:

```
require(amount0 >= amount0Min`, "")
require(amount1 >= amount1Min, "")
```
