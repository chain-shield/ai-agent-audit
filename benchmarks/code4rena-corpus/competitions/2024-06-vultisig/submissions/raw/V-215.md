# Vulnerability details

## Impact

The variables in the cloned pools will be different for every cloned pool.

## Proof of Concept

When initILOPool is called, it calls Clones.cloneDeterministic and clones the ILO_POOL_IMPLEMENTATION contract.

In the implementation contract itself, the initialize function is callable by anyone, and anyone can initalize the implementation contract. This will affect the variables in the future cloned pools.

```
    function initialize(InitPoolParams calldata params) external override whenNotInitialized() {
        _nextId = 1;
        // initialize imutable state
        MANAGER = msg.sender;
        IILOManager.Project memory _project = IILOManager(MANAGER).project(params.uniV3Pool);


        WETH9 = IILOManager(MANAGER).WETH9();
        RAISE_TOKEN = _project.raiseToken;
        SALE_TOKEN = _project.saleToken;
        _cachedUniV3PoolAddress = params.uniV3Pool;
        _cachedPoolKey = _project._cachedPoolKey;
        TICK_LOWER = params.tickLower;
        TICK_UPPER = params.tickUpper;
        SQRT_RATIO_LOWER_X96 = params.sqrtRatioLowerX96;
        SQRT_RATIO_UPPER_X96 = params.sqrtRatioUpperX96;
        SQRT_RATIO_X96 = _project.initialPoolPriceX96;
```


## Tools Used

VSCODE

## Recommended Mitigation Steps

Set the initialize() function in the ILOPool to internal, so that the variables of the implementation contract will not change.
