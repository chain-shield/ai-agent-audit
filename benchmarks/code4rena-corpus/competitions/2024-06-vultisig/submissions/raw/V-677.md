# Vulnerability details

## Impact

The function `claim` calls `TransferHelper.safeTransfer` at the end. This function sends funds externally and there is still a lot of code yet to be executed. 

Due to function call statements present after `safeTransfer`, there's a potential of reentrancy attack via those external calls.

## Proof of Concept
```solidity
    /// @inheritdoc IILOPool
    function claim(uint256 tokenId)
        external
        payable
        override
        isAuthorizedForToken(tokenId)
        returns (uint256 amount0, uint256 amount1)
    {
        ...
        ...
        // at this point the funds are sent to another contract or user
        TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amount1);

        ...
        ...
        
        // transfer fee to fee taker
        TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);
    }
```

## Recommended Mitigation Steps

It would be best to implement the Checks-Effects-Interactions pattern to prevent reentrancy attacks. Modify the `TransferHelper.safeTransfer` function calls in the `claim` function to be the last operations executed, ensuring that all other operations that update variables in the contract are completed before the function's external interactions are started.

A potential correction is as follows:
```solidity
    /// @inheritdoc IILOPool
    function claim(uint256 tokenId)
        external
        payable
        override
        isAuthorizedForToken(tokenId)
        returns (uint256 amount0, uint256 amount1)
    {
        ...
        ...
        // prepare the necessary variables for the external calls
        // store in local variables
        ...
        address tokenOwner = ownerOf(tokenId);
        ...

        // transfer funds at the end of the function
        TransferHelper.safeTransfer(_cachedPoolKey.token0, tokenOwner, amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, tokenOwner, amount1);
        ...
        // transfer fee to fee taker
        TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);
    }
```
