# Vulnerability details

## Description
The `ILOPool.buy(uint256, address)` function does not check if the whitelisted address has already bought the maximum amount of tokens allowed, in checks the amount of tokens associated to a token ID.

Therefore `maxCapPerUser` can be bypassed by transferring the ERC721 token to another address and then buying more tokens.

## Impact
* Whitelisted addresses can bypass the `maxCapPerUser` by transferring the ERC721 token to another address and buying more tokens.

## POC
1. Bob is whitelisted and buys the maximum amount of tokens allowed, reciving an NFT from ILOPool
2. Bob transfers the NFT to another controlled address
3. Bob buys more tokens from the controlled address.

If Bob has enough funds he can buy all remaining tokens.

            // Investor buy more
            // This should revert because investor already reach max cap per user, but it does not    
            (uint256 tokenId2,) = IILOPool(iloPool).buy(0.1 ether, INVESTOR);
            vm.stopPrank();
        }

## Recommended mitigation
### Option A
If the protocol wants to avoid the commercialization of these tokens in the secondary market, the ERC721 function can be overridden to prevent the transfer of these tokens, at least until launch time.

### Option B
If the protocol does not care about the commercialization of these tokens in the secondary market, simply create another mapping to track the amount of tokens bought by a whitelisted address.
