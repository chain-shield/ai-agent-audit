# Vulnerability details

## Impact
Based on `_isSelfWhitelistDisabled` value, either anyone can whitelist himself or only the owner can whitelist users. However on deploy this value by default is `false`, which means that anyone can whitelist himself.

## Proof of Concept
In Solidity, by default boolean values are set to `false`. The `_isSelfWhitelistDisabled` variable is used as flag and can be changed by the owner by calling `setIsSelfWhitelistDisabled` function. If we take a look at the `receive` function:

```solidity
    receive() external payable {
        if (_isSelfWhitelistDisabled) { // @audit false by default
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) { // @audit false by default
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        payable(_msgSender()).transfer(msg.value);
    }
```

We can see that the checks will pass as they are not configured yet. This means that anyone can call `receive` only paying the gas fees and be whitelisted. Later on owner can change the flag, but not notice that there are addresses that are whitelisted.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Either set the flag to `true` in the constructor or add parameter to constructor that will allow owners to choose the flag's value.
