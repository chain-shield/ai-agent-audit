# Vulnerability details

## Impact
`UniswapV3Oracle:peek` has a bug in the calculation of the returned value in the following line: [UniswapV3Oracle.sol#L45](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/oracles/uniswap/UniswapV3Oracle.sol#L45)
```solidity
return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
```
The comment suggests that a 5% slippage will be applied to the quoted WETH amount. However, the calculation is incorrect.

This should be corrected to:
```solidity
return (quotedWETHAmount * baseAmount * 95) / 100 / 1e18;
```
**Explanation**
   - `quotedWETHAmount` represents the quoted WETH amount for 1 VULT (1e18 base amount).
   - `baseAmount` is the input amount of VULT for which the price is being calculated.
   - To apply a 5% slippage, the quoted WETH amount should be multiplied by 0.95 (95% of the original amount).
   - The division by `1e20` in the original code is incorrect. It should be a division by `100` to convert the percentage to a decimal, followed by a division by `1e18` to adjust for the decimals of VULT.

**So, the corrected calculation should be**
   1. Multiply `quotedWETHAmount` by `baseAmount` to get the total WETH amount for the given `baseAmount` of VULT.
   2. Multiply the result by 95 to apply the 5% slippage.
   3. Divide the result by 100 to convert the percentage to a decimal.
   4. Divide the result by 1e18 to adjust for the decimals of VULT.

This will give the correct WETH amount with a 5% slippage applied.

## Proof of Concept
[UniswapV3Oracle.sol#L38-L46](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/oracles/uniswap/UniswapV3Oracle.sol#L38-L46)
```solidity
function peek(uint256 baseAmount) external view returns (uint256) {
    uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
    uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
    int24 tick = OracleLibrary.consult(pool, period);
    uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
    // Apply 5% slippage
    return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
}
```
The incorrect calculation [UniswapV3Oracle.sol#L46](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/oracles/uniswap/UniswapV3Oracle.sol#L45)
```solidity
return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
```

   - Suppose `quotedWETHAmount` is 0.01 WETH (10000000000000000 wei) for 1 VULT (1e18 base amount).
   - If `baseAmount` is 2e18 (2 VULT), the expected result with a 5% slippage would be 0.019 WETH (19000000000000000 wei).
With the incorrect calculation:

With the incorrect calculation
```solidity
(10000000000000000 * 2e18 * 95) / 1e20
= 1900000000000000000000 / 1e20
= 19 wei
```
With the corrected calculation
```solidity
(10000000000000000 * 2e18 * 95) / 100 / 1e18
= 1900000000000000000000 / 100 / 1e18
= 19000000000000000 wei
```
As you can see, the incorrect calculation results in a significantly undervalued amount (19 wei instead of 0.019 WETH), while the corrected calculation provides the expected result.
