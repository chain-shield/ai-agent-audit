# Vulnerability details

## Impact
ILOManager contract initializes and deploys the Uniswap V3 pools and ILOPools for the sale and vesting. For each univ3pool there can be one project admin, who initializes the project.

An attacker can frontrun a user and call the [`initProject()`](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L57) function to initialize the project and gain the ownership. Attacker can choose not to deploy the pools or deploy multiple ILOPools with invalid configurations.

An attacker could DOS attack the system and frontrun all calls to `initProject`.

## Proof of Concept
1. Alice wants to start a new project for their token sale token XYZ, raise token ABC, and fee 0.5%
2. Bob observes this txn in mempool, and frontruns Alice with the same project configuration.
3. Alice's transaction got reverted, and now it can never start a project for the same pool.
4. Bob takes advantage of this situation and initializes ILOPools with high fee. Bob could also start with pool with invalid configurations.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Allow a user to submit a hash of the pool key first, and then later verify it in their next transaction to initProject.
