# Vulnerability details

TWAP window in twap oracles reflect risk of an asset. Updating more frequently accurately prices an asset but increases capabilities of manipulation, whereas longer update periods prevent manipulation but does not accurately price assets (due to the time difference between updates). Volatility of an asset should be considered when determining TWAP query window, the TWAP window needs to make a balance between accuracy and manipulation resistance. However, in Vultisig's UniswapV3Oracle.sol no such considerations are made, the TWAP "Period" cannot be changed after deployment of the contract. This could lead to price manipulation or inadequate pricing of assets.

TWAP Window value should be changeable (and not constant) by the admin/owner.

## Impact

Inadequate TWAP window might lead to lagging TWAP prices, which can be used to acquire more VULT tokens (for eg. VULT price has suddenly gone up from 1 ETH to 2 ETH but the 30-minute TWAP might still lag and thus buyer will be allowed to buy more VULT tokens that deserved).

The usage of twap signals that the protocol does not want some addresses to become disproportionate holders of the VULT tokens, but the current protection is not sufficient to protect against this. 

## Proof of Concept

TWAP window "PERIOD" is a constant set to 30 minutes, but different market conditions and pool activity might require a different query window to accurately price VULT. In some cases, for e.g 30-minute twap might lag considerably in sudden movements leading to inaccurate pricing.

Since there is a allowed maxAddressCap of eth that could be used to buy VULT tokens, the protocol intends to limit the amount of VULT that can be acquired by any single whitelisted address, in the initial token sale. 

We do not know how long the whitelisted period will last, it can be days/weeks or even months. In such a case, the current TWAP window might be inadequate if the price becomes too volatile during this time.

Manual review

## Recommended Mitigation Steps

Make "PERIOD" a state variable and add the following function
```
function setTwapPeriod(uint256 newTwapPeriod) external onlyOwner {
    PERIOD = newTwapPeriod;
}
```
