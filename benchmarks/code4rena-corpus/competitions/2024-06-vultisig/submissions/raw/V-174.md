# Vulnerability details



## Impact
In `ILOManager.sol`, the `launch` function is using `UniswapV3.slot0` where it retrieves the current pool price `sqrtPriceX96`. However, the `sqrtPriceX96` is pulled from `Uniswap.slot0`, which is [the most recent data point](https://docs.uniswap.org/contracts/v3/reference/core/interfaces/pool/IUniswapV3PoolState#slot0) and this price can be manipulated by a malicious actor before the launch, potentially causing the project to fail launching a pool.

## Proof of Concept

`launch()` function:

```javascript
 function launch(address uniV3PoolAddress) external override {
    require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
@>  (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
    require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
    address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
    require(initializedPools.length > 0, "NP");
    for (uint256 i = 0; i < initializedPools.length; i++) {
        IILOPool(initializedPools[i]).launch();
    }

    emit ProjectLaunch(uniV3PoolAddress);
}
```
A malicious actor can observe a transaction attempting to call launch and front-run it by submitting a transaction with a manipulated `sqrtPriceX96` value just before the original transaction is mined. 

If an attacker successfully manipulates `sqrtPriceX96` to a value different from `_cachedProject[uniV3PoolAddress].initialPoolPriceX96`, they can prevent launching the pool. 
This manipulation could lead to failed launches/preventing the intended functionality.

## Tools Used
Manual review

## Recommended Mitigation Steps
Use the `TWAP` function instead of `slot0` to get the value of `sqrtPriceX96`.
