# Vulnerability details

## Impact
Malicious refunds can render the entire Pool completely unusable.

## Proof of Concept
If the user refunds after the refundDeadline, the entire ILOPool will become unusable because _refundTriggered becomes true (because there is no way to change _refundTriggered again). Therefore, if the project chooses to raise funds publicly (that is, open the whitelist to everyone), the attacker can buy a small amount of liquidity and choose to refund when the refundDeadline is reached. The entire ILOPool will become unusable because _refundTriggered becomes true.

## Tools Used
Manual Audit

## Recommended Mitigation Steps
Add a function that can change _refundTriggered and can only be called by the fundraising project party.
```solidity
function SetRefundTriggered(bool refundTriggered) external  OnlyManager() {
    _refundTriggered = refundTriggered;      
}
```
