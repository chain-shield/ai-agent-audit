# Vulnerability details

## Impact
The current implementation allows users to bypass the `maxCapPerUser` restriction by transferring their NFT position to another account. 

```solidity
        // if investor already have a position, just increase raise amount and liquidity
        // otherwise, mint new nft for investor and assign vesting schedules
        if (balanceOf(recipient) == 0) {    //@check what if transfer?
            _mint(recipient, (tokenId = _nextId++));
            _positionVests[tokenId].schedule = _vestingConfigs[0].schedule;
        } else {
            tokenId = tokenOfOwnerByIndex(recipient, 0);
        }

        Position storage _position = _positions[tokenId];
        require(raiseAmount <= saleInfo.maxCapPerUser - _position.raiseAmount, "UC");
```
This loophole enables users to repeatedly invest up to the maxCapPerUser limit by continually transferring their position and re-purchasing tokens. This behavior undermines the purpose of maxCapPerUser, which is to limit the total investment a single user can make. Additionally, it violates the restriction intended to ensure that each user holds only a single NFT position.
