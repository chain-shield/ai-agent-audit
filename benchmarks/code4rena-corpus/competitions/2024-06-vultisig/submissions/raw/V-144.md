# Vulnerability details

## Impact
The ILOManager.sol::initILOPool has an incorrect require condition: require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE"); This condition does not check whether the sqrtRatioUpperX96 is greater than the _project.initialPoolPriceX96 This creates an opportunity to create a pool that is out of range.

Users may buy from ILOPool that is out of range and lose potential profit or worse, struggle from impermanent loss

## Proof of Concept
Please, add the following test in ILOManager.t.sol:

```javascript
function testInitPoolOutOfRange() external {
    IILOManager.Project memory project = iloManager.project(projectId);

    int24 initialPriceTick = TickMath.getTickAtSqrtRatio(project.initialPoolPriceX96);
    int24 maxTick = initialPriceTick - 10;

    IILOManager.InitPoolParams memory params = _getInitPoolParams();
    params.tickUpper = maxTick;

    IILOPool iloPool = IILOPool(_initPool(PROJECT_OWNER, params));
    assertEq(iloPool.MANAGER(), address(iloManager));
    assertEq(iloPool.RAISE_TOKEN(), USDC);
    assertEq(iloPool.SALE_TOKEN(), SALE_TOKEN);
    assertEq(iloPool.TICK_LOWER(), MIN_TICK_500);
    assertEq(iloPool.TICK_UPPER(), maxTick);
    assertEq(iloPool.name(), "KRYSTAL ILOPool V1");
    assertEq(iloPool.symbol(), "KRYSTAL-ILO-V1");
    assert(iloPool.TICK_LOWER() < initialPriceTick && iloPool.TICK_UPPER() < initialPriceTick);
}
```
