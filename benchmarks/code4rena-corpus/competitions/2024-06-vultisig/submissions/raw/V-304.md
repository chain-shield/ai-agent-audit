# Vulnerability details

## Impact
The impact will be that the TWAP will be calculated for shorter timeframe which can lead to price manipulation 

## Proof of Concept
```solidity
       uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
    // @audit --> is it correct? it can take shorter than 30 mins period
        uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
        int24 tick = OracleLibrary.consult(pool, period);
```

here we can see that `longestPeriod` stores the number of seconds ago the latest observation was stored 

and if the `longestPeriod` happens to be recent value like 30 seconds then 
the value 30seconds is set to period and used in the `OracleLibrary.consult(pool,period)` which uses the period to as the past seconds to start calculating the TWAP price from and since its a small value recent fluctuations in the pools could lead to price manipulation

Manual Review, Foundry 

## Recommended Mitigation Steps
use the fixed constant time of 30 minutes rather than seeing when the most recent twap price updation
