# Vulnerability details

## Vulnerability Analysis

    `function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address uniV3PoolAddress) {}`


This function enables the initialization of a project's individual pool after the ILOPool itself have been initialized. However, it lacks the access control as to who can initialize the project after ILOPool contract has been initialized.

The `afterInitialize()` modifier only checks that this function is being called only after when the ILOManager contract has been initialized already. 

It does not restrict the caller of this function. It also does not check if the project has already been initialized, leading to re-initialization by a malicious attacker. 

Now, in this function, if the uniswap pool address already exists, it queries the `SqrtPriceX96` from the `slot0` function of the Uniswap pool address associated with this project. And then ensures that the queried existing `SqrtPriceX96` value matches with the new value in the initialization parameters. See the check below:

` require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P");`

However, this check can be bypassed as it is easily for an attacker to know the `sqrtPriceX96` of an existing uniswap pool. The attacker can just query the `slot0` function on uniswap Pool state contract of the project's pool address as that function has external visibility and callable by anyone with no safety checks whatsoever.


## Impact
Even if the project has already been initialized, a malicious attacker can update core parameters of this function. For example, a malicious attacker can change the `fee` parameter to a new value, harmfully destroying the project's reputation.
