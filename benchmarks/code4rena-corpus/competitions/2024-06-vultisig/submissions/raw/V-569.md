# Vulnerability details

## Proof of Concept

The `UniswapV3Oracle` contract specifies Solidity version `^0.8.24`.

```solidity
File: UniswapV3Oracle.sol

2:    pragma solidity ^0.8.24;

```

The `hardhat.config.ts` file confirms that the contract is deployed with Solidity version `0.8.24`.

```

@->   solidity: "0.8.24",

```

The `UniswapV3Oracle` contract uses functions from the `OracleLibrary`, which in turn uses functions from `FullMath` and `TickMath`.


The `FullMath` library supports Solidity version `>=0.4.0` and `TickMath` supports `>=0.5.0`. These libraries rely on arithmetic operations that wrap on overflow. However, starting with Solidity version `0.8.0`, arithmetic operations revert by default on overflow. Since the code was originally written for Solidity version `0.7.6`, these operations must be wrapped in an `unchecked` block when used in Solidity `>=0.8.0`.

Let's see how this issue affects the `peek` function with an example:

* The `getQuoteAtTick` function is used to get `quotedWETHAmount`.


* The `getSqrtRatioAtTick` function should be wrapped in an `unchecked` block for Solidity versions `>0.8.0`, as seen in [Uniswap's official implementation](https://github.com/Uniswap/v3-core/blob/0.8/contracts/libraries/TickMath.sol#L27). Without this, the function will revert in Solidity `>=0.8.0`.


## Impact

The `peek` function in `UniswapV3Oracle` will revert when a phantom overflows occurs, causing a DoS Scenario.

## Recommended Mitigation Steps

Wrap the arithmetic operations in `FullMath` and `TickMath` with `unchecked` blocks to ensure they function correctly in Solidity `>=0.8.0`.
