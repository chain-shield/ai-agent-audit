# Vulnerability details

## Impact
Owner can whitelist more addresses than allowed

## Proof of Concept
```
/// @notice Max index allowed
    uint256 private _allowedWhitelistIndex;
```

from this variable declaration we can tell there is a max number of allowed whitelists at a time.

Currently the only check that enforces this is in `checkWhitelist`
```
    function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
        if (from == _pool && to != owner()) {
            // We only add limitations for buy actions via uniswap v3 pool
            // Still need to ignore WL check if it's owner related actions
            if (_locked) {
                revert Locked();
            }

            if (_isBlacklisted[to]) {
                revert Blacklisted();
            }

@-->            if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }

            // // Calculate rough ETH amount for VULT amount
            uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
            if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
                revert MaxAddressCapOverflow();
            }

            _contributed[to] += estimatedETHAmount;
        }
    }
```

we can see there is an if statement that checks if `_whitelistIndex[to]` is still in bounds and reverts if not.

Here is the case that in `addWhitelistedAddress` and `addBatchWhitelist`

```
 function addWhitelistedAddress(address whitelisted) external onlyOwner {
        _addWhitelistedAddress(whitelisted);
    }

 function addBatchWhitelist(address[] calldata whitelisted) external onlyOwner {
        for (uint i = 0; i < whitelisted.length; i++) {
            _addWhitelistedAddress(whitelisted[i]);
        }
    }
```

there is no check to ensure that currently whitelisted address index is more than the allowed index.

so let's say owner already adds 5 addresses yet the `_allowedWhitelistIndex=8` and owner initiates a `addBatchWhitelist` adding another 5 addresses, it wont revert but rather add all the addresses and later when the `checkWhitelist` is being called, it will revert after the whitelist index is out of bounds eventhough they are whitelisted. 

Furthermore, the check will throw an error `notWhitelisted`  but if you check whether whitelisted from the `whitelistIndex` you'll see that the address is whitelisted, making the error probing weird.

## Tools Used
manual review
## Recommended Mitigation Steps
A max index check should be implemented in `addWhitelistedAddress` and `addBatchWhitelist`. So that the owner can either increase the max index allowed to enable all whitelisted indexes > max allowed index pass the `checkWhitelist` function check or initialize an array that won't revert
