# Vulnerability details

## Impact
ILOPool whitelist can be easily bypassed by transferring the minted nft token, because raise amount is usually capped, if many nft tokens are minted and transferred to non-whitelisted users, raise amount can be quickly used up and some qualified whitelisted users won't be able to buy ILO as expected.

## Proof of Concept
If [_openToAll](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/ILOWhitelist.sol#L9C18-L9C28) is set to `false`, only the whitelisted user can buy and owns ILO nft tokens.
```
    function buy(uint256 raiseAmount, address recipient)
        external override 
        returns (
            uint256 tokenId,
            uint128 liquidityDelta
        )
    {
@>      require(_isWhitelisted(recipient), "UA");
        ...
    {
```
However, the minted ILO nft token can be transferred without restriction, a whitelisted user may be bribed to mint many nft tokens and sell/transferred to non-whitelisted users, renders the whitelist mechanism basically useless.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Override ERC721's ___beforeTokenTransfer()__ and only allow nft tokens be transferred between whitelisted users.
```
    function _beforeTokenTransfer(address from, address to, uint256 tokenId) internal override {
        if (from != address(0) && to != address(0)) {
            require(_isWhitelisted(from) && _isWhitelisted(to), "UA");
        }
    }
```
