# Vulnerability details

## Impact
[Here ](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L106) we can see how the array  `_initializedILOPools[params.uniV3Pool]` is indiscriminately pushed into during initialization of new ILO pools via `initILOPool()` function . This array can grow in storage to become a very large number as project Admins which are also users can unknowingly create so many ILO pools for their projects such that it affects the exection of core protocol functions `launch()` and `claimRefund()`


## Proof of Concept
in [initILOPool()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L72C1-L107C6) we can see how a new ILO pool address is pushed into storage each time a new ILO pool is created. There is no limit on the number of ILO pools that can be made so it is possible that the array can grow to a very large length in storage. This is problematic for other functions which run for loops based on the length of this `_initializedILOPools[params.uniV3Pool]` array. Below is a snippet of how a new ILO pool address is saved in storage to the array each time after its initialization. 

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L105C1-L106C69
```solidity
        IILOPool(iloPoolAddress).initialize(initParams);
        _initializedILOPools[params.uniV3Pool].push(iloPoolAddress);
```


in `launch()` and `claimRefund()`, these functions have logic which depend on the array length `_initializedILOPools[params.uniV3Pool]`. If the array grows too large it will cause calls made to this functions to fail due to out of gas error. This means that 

- refunds of the `SALE_TOKEN` cannot be claimed, refunds get stuck in the ILO pool contract.
-  project will not eventually lauch as `launch` function will fail. 

These functions will become inacessible as there is no implementation to reduce the length of this array.  See the for loops which use the length of the array below. 

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L186C1-L198C6
```solidity
    /// @inheritdoc IILOManager
    function launch(address uniV3PoolAddress) external override {
        require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
        (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
        require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
        address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
        require(initializedPools.length > 0, "NP");
        for (uint256 i = 0; i < initializedPools.length; i++) {
            IILOPool(initializedPools[i]).launch();
        }

        emit ProjectLaunch(uniV3PoolAddress);
    }
```
