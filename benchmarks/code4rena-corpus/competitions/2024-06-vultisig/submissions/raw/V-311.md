# Vulnerability details


## Proof of Concept

First note that when  _initing_ a project, the properties of the project is set in the `_cacheProject()` function that gets called [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L63), looking at the implementation of the cacheProject() https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L123-L147

```solidity

        address uniV3PoolAddress,
        address saleToken,
        address raiseToken,
        uint24 fee,
        uint160 initialPoolPriceX96,
        uint64 launchTime,
        uint64 refundDeadline
    ) internal {
        Project storage _project = _cachedProject[uniV3PoolAddress];
        require(_project.uniV3PoolAddress == address(0), "RE");

        _project.platformFee = PLATFORM_FEE;
        _project.performanceFee = PERFORMANCE_FEE;

```

We can see that among other properties, both the platform fee and the performance fee is attached to the project.

Now going to the documentation, [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L154) & [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L149), we can see that there is an enforcal that the BPS value for the platform & performance fee must be uniform across all projects.

Now these values are updatable by the owner via these setter functions: https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L150-L157

```solidity
    function setPlatformFee(uint16 _platformFee) external onlyOwner() {
        PLATFORM_FEE = _platformFee;
    }

    function setPerformanceFee(uint16 _performanceFee) external onlyOwner() {
        PERFORMANCE_FEE = _performanceFee;
    }
```

Problem however is that this method is unsafe, cause it doesn't make updates to the already _inited_ projects and would have effect on only the projects to be inited in the future, that's to say using rough values: If the fees were both set to 1% previously, and some project pools were inited, after the owner updates the fee values to 2%, these previous pools are going to be stuck with the old value of `1%`, which not only breaks the immutability/unformity invariant, since some pools would now be attached with different fees, but this also translates to loss of funds for the `feeTaker` considering they would be getting only half of what they are now entitled to from the previously _inited_ project pools.


## Impact

## Recommended Mitigation Steps
When setting a new fee, route through previously _inited_ project pools and update both the platform and performance fees.
