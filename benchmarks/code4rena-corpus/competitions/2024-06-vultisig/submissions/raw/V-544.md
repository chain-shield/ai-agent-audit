# Vulnerability details

## Vulnerability Detail
Inside `IloManager.launch()` the following for loop takes place

```solidity
for (uint256 i = 0; i < initializedPools.length; i++) {  
            IILOPool(initializedPools[i]).launch();
        }
```

Note that users calling launch cannot control the size of the list so if it is large enough the Tx will revert due to running out of gas

A project admin can easily inflate the `initializedPools.length` by calling `initILOPool` multiple times

Another key point is that the attacker can ensure they are the projectAdmin by frontrunning `initProject()` for that uniswap pool


## Impact
`IloManager.launch()` is DOS for all ILO pools


## Proof of Concept
I have included a general POC for reverts due to large for loops. 

This POC shows how a large for loop uses > 1500000 GAS which is the block gas limit on Ethereum

Add the code to `POC3.t.sol`

Run `test__largeLoop` using the following command

```bash
forge test --mt test__largeLoop -vv
```

```solidity
// SPDX-License-Identifier: MIT 

pragma solidity =0.7.6;
pragma abicoder v2;

import "forge-std/Test.sol";

contract GasRevert is Test {

    function setUp() external {}

    // Function with a loop that will consume too much gas
    function test__largeLoop() public pure {
        uint256 sum = 0;
        for (uint256 i = 0; i < 220000; i++) { // Adjust the loop limit if necessary
            sum += i;
        }
    }
}
```

Console output

Note that in this POC each loop uses significantly less gas than what the loops in `IloManager.launch()` would use. So in reality the amount of ILO pools required for this issue is MAGNITUDES LOWER than what the POC shows.
