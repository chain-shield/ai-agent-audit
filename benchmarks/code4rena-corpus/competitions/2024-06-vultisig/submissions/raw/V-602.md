# Vulnerability details

## Impact
n the following lines: [ILOPool.sol#L331-L332](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L331-L332)
```solidity
// transfer back leftover sale tokens to project admin
_refundProject(_project.admin);
```
The `_refundProject()` is called after the liquidity has been added to the Uniswap pool and the vesting schedules have been assigned. However, this function transfers the contract's remaining `SALE_TOKEN` balance to the project admin.

The bug doesn't consider the scenario where the total raised amount (`totalRaised`) is more significant than the `softCap` but less than the amount required to provide the desired liquidity. In such a case, some `SALE_TOKEN` might be left in the contract after adding liquidity, which would be unintentionally sent to the project admin.

```solidity
function _refundProject(address projectAdmin) internal returns (uint256 refundAmount) {
    refundAmount = IERC20(SALE_TOKEN).balanceOf(address(this));
    if (refundAmount > 0) {
        TransferHelper.safeTransfer(SALE_TOKEN, projectAdmin, refundAmount);
        emit ProjectRefund(projectAdmin, refundAmount);
    }
}
```
After adding liquidity to the pool using the `addLiquidity()` function, the `launch()` function directly calls the `_refundProject()` function, passing the project admin address as an argument.

The `_refundProject()` function retrieves the remaining balance of the SALE_TOKEN in the contract using `IERC20(SALE_TOKEN).balanceOf(address(this))`. It then transfers this entire balance to the project admin using `TransferHelper.safeTransfer()`.

The bug arises when the total raised amount (totalRaised) is greater than the softCap but less than the amount required to provide the desired liquidity. In such a case, the contract might have some remaining SALE_TOKEN balance after adding liquidity.

However, the `_refundProject()` function transfers the entire remaining balance to the project admin without considering whether it is an expected leftover amount or not. This means that any unintentional leftover tokens will be sent to the project admin, which may not be the desired

## Recommended Mitigation Steps
We should consider adding a check to ensure that the remaining SALE_TOKEN balance is only transferred to the project admin if it exceeds a certain threshold or is an expected leftover amount based on the total raised and the liquidity provided.
```solidity
// calculate the expected leftover sale token amount
uint256 expectedLeftover = calculateExpectedLeftover(totalRaised, liquidity);

// transfer back leftover sale token to project admin if it exceeds the expected amount
if (IERC20(SALE_TOKEN).balanceOf(address(this)) > expectedLeftover) {
    _refundProject(_project.admin);
}
```
