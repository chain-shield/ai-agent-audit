# Vulnerability details

## Impact

The launch may fail because of gas limit errors.

## Proof of Concept

When it is time for the project to launch, it loops through clones of different pools created.

```
ILOManager.sol
        for (uint256 i = 0; i < initializedPools.length; i++) {
            IILOPool(initializedPools[i]).launch();
        }
```

In each pool, in the launch function, it mints an NFT to every recipient that participates in the buying of the sale token.

```
            // mint nft for recipient
            _mint(projectConfig.recipient, (tokenId = _nextId++));
            uint128 liquidityShares = uint128(FullMath.mulDiv(liquidity, projectConfig.shares, BPS));
```

Also, the `launch` function calls into several storage variables, which uses a lot of gas.

```
     Position storage _position = _positions[tokenId];
            _position.liquidity = liquidityShares;
            _positionVests[tokenId].totalLiquidity = liquidityShares;

            // assign vesting schedule
            LinearVest[] storage schedule = _positionVests[tokenId].schedule;
```

If there are many pools, and therefore many tokenIds created, the whole function will lead to an out of gas error.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Since liquidity is meant to enter the UniswapV3 pool at the same time, launching the pool one by one does not help.

A good way is to limit the number of recipients in every pool so that the whole function process will not ever reach the gas limit.
