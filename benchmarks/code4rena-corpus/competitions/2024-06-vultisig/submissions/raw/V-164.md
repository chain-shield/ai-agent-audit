# Vulnerability details

## Impact

In the `ILOPool:claim` function, there is no check to verify if `feeGrowthInside0LastX128` is zero. If it is zero, this subtraction can cause an underflow.

## Proof of Concept

Scenario:
1. A user attempts to claim.
2. `feeGrowthInside0LastX128` is less than `position.feeGrowthInside0LastX128`.
3. The value underflows and becomes the maximum value of `uint256`.
4. The code attempts to multiply `uint256` max with `positionLiquidity`.
5. This results in an overflow, producing incorrect results.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add checks to ensure `feeGrowthInside0LastX128` is greater than `position.feeGrowthInside0LastX128` to prevent underflow. Similarly, add a check for `feeGrowthInside1LastX128`.

```javascript
require(feeGrowthInside0LastX128 > position.feeGrowthInside0LastX128, "error");
require(feeGrowthInside1LastX128 > position.feeGrowthInside1LastX128, "error");
```

This ensures that the subtraction will not cause an underflow, thus maintaining the integrity of the calculations.
