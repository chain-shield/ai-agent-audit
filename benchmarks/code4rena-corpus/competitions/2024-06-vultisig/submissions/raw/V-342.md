# Vulnerability details

## Impact
Project admins can create multiple `ILOPools` for their project, which contains mechanism such as vesting, sale management, ERC721 integration, etc.

Users can earn rewards for the amount they invested by calling `ILOPool::claim()`. These rewards are calculated based off the `liquidity2claim`, which is the `amount of unlocked liquidity for the position`.

`IUniswapV3PoolActions::burn()` is called with the `liquidity2claim` amount, which burns the liquidity and returns tokens owed for the liquidity to the position, `amount0` and `amount1`, which represent the `RAISE_TOKEN` and `SALE_TOKEN`.

From the fees generated by the position, the `performanceFee` is deducted, and sent to the `feeTaker`.

When calculating how much `performanceFee` to deduct, the protocol utilizes `IUniswapV3PoolState::positions` to get the amount of fees earned from the `burn()` call.

The problem is the amount of fees collected is multiplied by the entire amount of liquidity of the position, rather than the liquidity that was claimed. This will give a greater fee value that is given to both the caller and the fee taker, which will take extra tokens from the pool, and may DoS due to insufficient tokens in some cases.

## Proof of Concept
[ILOPool.sol#L194-L195](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L194-L195)
```javascript
    // calculate amount of unlocked liquidity for the position
    uint128 liquidity2Claim = _claimableLiquidity(tokenId);
```

This amount of liquidity is burned from the `Uniswap V3 pool` and returns the amount of tokens owed from the amount burned.

[ILOPool.sol#L204-L205](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L204-L205)
```javascript
    // get amount of token0 and token1 that pool will return for us
    (amount0, amount1) = pool.burn(TICK_LOWER, TICK_UPPER, liquidity2Claim);
```

The function proceeds to calculate the fees owed to the `feeTaker`.

[ILOPool.sol#L212-L227)](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L212-L227)
```javascript
    // calculate amount of fees that position generated
    (, uint256 feeGrowthInside0LastX128, uint256 feeGrowthInside1LastX128, , ) = pool.positions(positionKey);
    uint256 fees0 = FullMath.mulDiv(
                        feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
                        positionLiquidity, //@audit should be liquidity2Claim
                        FixedPoint128.Q128
                    );
    
    uint256 fees1 = FullMath.mulDiv(
                        feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
                        positionLiquidity, //@audit should be liquidity2Claim
                        FixedPoint128.Q128
                    );

    // amount of fees after deduct performance fee
    (fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);
```

The problem is that the entire `positionLiquidity` is used to calculate `fees0` and `fees1`, rather than `liquidity2claim`. This is problematic, as the fees earned from `burn()` are calculated from the `liquidity2Claim`, so the fees calculate are overvalued in most cases, as `positionLiquidity >= liquidity2Claim`.

[ILOPool.sol#L201-L202](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L201-L202)
```javascript
    uint128 positionLiquidity = position.liquidity;
    require(positionLiquidity >= liquidity2Claim);
```

These fees are added to the amount to send to the user, and will send a portion of it to the `feeTaker`.

Since the token amounts are over-valued, this may DoS due to insufficient tokens, or users will lose funds as more pool tokens will be lost.

## Tools Used
Manual review

## Recommended Mitigation Steps
Make the following changes when calculating the fee owed

```diff
    uint256 fees0 = FullMath.mulDiv(
                        feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
-                       positionLiquidity,
+                       liquidity2Claim
                        FixedPoint128.Q128
                    );
    
    uint256 fees1 = FullMath.mulDiv(
                        feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
-                       positionLiquidity,
+                       liquidity2Claim
                        FixedPoint128.Q128
                    );
```
