# Vulnerability details

## Vulnerability details 
ILOManager::initProject() is used for onboarding projects for ILO. While onboarding, it checks for uniswap pool for the project token and if pool exists it requires the sqrtPriceX96 from slot0 to be equal to sqrtPriceX96 provied by project
```solidity
    function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address uniV3PoolAddress) {
    ....
     @>   uniV3PoolAddress = _initUniV3PoolIfNecessary(poolKey, params.initialPoolPriceX96);
        
    ....
    }
```
```solidity
       function _initUniV3PoolIfNecessary(PoolAddress.PoolKey memory poolKey, uint160 sqrtPriceX96) internal returns (address pool) {
      ...
         @>   (uint160 sqrtPriceX96Existing, , , , , , ) = IUniswapV3Pool(pool).slot0();
            if (sqrtPriceX96Existing == 0) {
                IUniswapV3Pool(pool).initialize(sqrtPriceX96);
            } else {
          @>      require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P");
            }
    }
```
Now the problem is an `attacker` can `frontrun` the initProject() of honest project by creating a uniswap pool and initializing it with different sqrtPriceX96

As result, honest project trx will revert due to above require statement

## Impact
Honest project's ILO/initProject() can be DoS
