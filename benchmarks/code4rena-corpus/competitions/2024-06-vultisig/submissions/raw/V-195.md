# Vulnerability details

## Impact

The files will be not be able to handle intentional over/underflow cases, especially when calculating sqrtRatio prices.

## Proof of Concept

The version of the oracle library that VultiSig uses is >=0.5.0.

```
pragma solidity >=0.5.0;
```

VultiSig FullMath library uses >=0.4.0.

```
pragma solidity >=0.4.0;
```

VultiSig TickMath library uses >=0.5.0.

```
pragma solidity >=0.5.0;
```

The project is compiled using the 0.8.24 version, which means 0.8.0 is supported in those files.

```
const config: HardhatUserConfig = {
  solidity: "0.8.24",
  paths: {
    sources: "./hardhat-vultisig/contracts",
    tests: "./hardhat-vultisig/test",
  },
```

Uniswap oracle and TickMath library uses `>=0.5.0 <0.8.0`.

```
pragma solidity >=0.5.0 <0.8.0;
```

https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol
https://github.com/Uniswap/v3-core/blob/main/contracts/libraries/TickMath.sol

Uniswap FullMath library uses `>=0.4.0 <0.8.0`.

```
pragma solidity >=0.4.0 <0.8.0;
```

https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/libraries/FullMath.sol#L2

UniswapV3 intentionally uses versions below 0.8.0 to allow for over/underflow calculations, for example, in the OracleLibrary.getQuoteAtTick function.

```
function getQuoteAtTick(
        int24 tick,
        uint128 baseAmount,
        address baseToken,
        address quoteToken
    ) internal pure returns (uint256 quoteAmount) {
        uint160 sqrtRatioX96 = TickMath.getSqrtRatioAtTick(tick);

        // Calculate quoteAmount with better precision if it doesn't overflow when multiplied by itself
        if (sqrtRatioX96 <= type(uint128).max) {
            uint256 ratioX192 = uint256(sqrtRatioX96) * sqrtRatioX96;
            quoteAmount = baseToken < quoteToken
                ? FullMath.mulDiv(ratioX192, baseAmount, 1 << 192)
                : FullMath.mulDiv(1 << 192, baseAmount, ratioX192);
        } else {
            uint256 ratioX128 = FullMath.mulDiv(sqrtRatioX96, sqrtRatioX96, 1 << 64);
            quoteAmount = baseToken < quoteToken
                ? FullMath.mulDiv(ratioX128, baseAmount, 1 << 128)
                : FullMath.mulDiv(1 << 128, baseAmount, ratioX128);
        }
    }
```

The desired overflow behaviour that UniswapV3 math desires will never be achieved as the current code will revert on overflows when it should not, breaking the contract's functionalities.

Another example is calculating fees using the FullMath library, where overflow may be met, especially when `position.feeGrowthInside0LastX128` is still 0:

```
            uint256 fees0 = FullMath.mulDiv(
                                feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
                                positionLiquidity,
                                FixedPoint128.Q128
                            );
```

## Recommended Mitigation Steps

Directly use UniswapV3 libraries instead to prevent any accidental errors. If needed be, fork the [UniswapV3 0.8.0 libraries](https://github.com/Uniswap/v3-core/tree/0.8/contracts/libraries) instead for better optimization.
