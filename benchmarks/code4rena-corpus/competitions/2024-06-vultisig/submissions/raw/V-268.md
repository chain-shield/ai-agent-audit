# Vulnerability details

## Impact
_unlockedLiquidity() function checks the unlocked liquidity by iterating over all the vesting schedules
```solidity
 function _unlockedLiquidity(uint256 tokenId) internal view override returns (uint128 liquidityUnlocked) {
        ....

     --->   for (uint256 index = 0; index < vestingSchedule.length; index++) {

            LinearVest storage vest = vestingSchedule[index];

            // if vest is not started, skip this vest and all following vest
        --->    if (block.timestamp < vest.start) {
                break;
            }

           ....
        }
    }
```
It assumes all the vesting schedule will be in increasing start time but this may not be the case.
Eg: it is possible that a vesting schedule is started first but in loop it comes later, which will be issue because that vested amount will not be included in liquidityUnlocked

Reason:- it uses break but it should use continue
