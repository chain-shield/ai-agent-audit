# Vulnerability details

# Summary
Function `ILOPool.claim()` will collect the token owed in uniswap pool. The token owed includes fees collected for the global liquidity (liquidity provided by `ILOPool`). The problem is all the fees will be collected at the first time when the `ILOPool.claim()` function is called.

```
(uint128 amountCollected0, uint128 amountCollected1) = pool.collect(
    address(this),
    TICK_LOWER,
    TICK_UPPER,
    type(uint128).max,
    type(uint128).max
);
```

Because all the fees are collected at the same time, the remaining fees will be sent to `FEE_TAKER` after deduction the amount received by claimer from amount collected.

The principal amount the user will receive calculated as : `principal amount in uniswap position * (1 - platform fee)`

The amount of fees collected for the given user is calculated as : `liquidity owned by user * (current gowth inside - last growth inside) * (1 - performance fee)`

The amount received by user : `principal amount + fees collected`

The amount received by `FEE_TAKER` : `amount collected from uniswap - amount received by user`.

The problem here is the amount received by `FEE_TAKER` contains fees that must be received by other users.

Assume there is no trading activity in the pool for the next few hours. The second user call `claim()` function.

Because there is no trading activity, the `current growth inside` will not change. Consequently, the `amount collected from uniswap` (`amountCollected0` and `amountCollected1`) will be same as `principal amount in uniswap position` (it is because the fees collected from uniswap was already collected by previous `claim()` called by first user).

Now, two condition might happen.

First, `amount collected from uniswap >= amount received by user`. If this is the case, the user still receive the tokens but lose fees.

Second, `amount collected from uniswap < amount received by user`. If this is the case, the operation will revert.

# Impact
The investor can lose fees, even could lead to revert operation.
