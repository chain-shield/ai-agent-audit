# Vulnerability details

## Impact

The setRefundDeadlineForProject() function is used to set a project's refund deadline to an abrupt value, and is only callable by the ILOManager owner. 

It doesn't make sense to allow ILOManager owner to change a project's refund deadline. This has a range of impacts :

1. Refund deadline can abruptly be changed to any time without the project's will
2. Since it is not callable by project admin, projects are forced to use the default deadline and can never change the deadline
3. Should have a check that new refund deadline is still > project.launchTime, otherwise it will mess up the whole timeline

4. The most serious impact is this : It can be used by the ILOManager owner to prevent projects and their investors from withdrawing their liquidity indefinitely. If the project is not launching, everyone depends on refund deadline to get their funds back. It can be changed anytime for any project, even just before it was supposed to end.

This is a serious problem because investors' funds might be withheld indefinitely and get stuck in the contract.


## Proof of Concept
Project can only claim refund if refund Deadline has passed : [ILOManager.claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L201)

Investors can also only claim after the refund deadline has passed : [ILOPool.claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L350)

## Tools Used
Manual review

## Recommended Mitigation Steps
The refund deadline should not be configurable by anyone after the project has been initialized once. Allow projects to set a custom refund deadline ( that is >= DEFAULT_DEADLINE_OFFSET) during initialization.
