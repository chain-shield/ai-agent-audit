# Vulnerability details

## Vulnerability details
Whenever a token is transfered, it calls checkWhitelist() on Whitelist.sol to check  if locked, not whitelisted, blacklisted or already contributed more than capped amount
```solidity
   /// @notice Before token transfer hook
    /// @dev It will call `checkWhitelist` function and if it's succsessful, it will transfer tokens, unless revert
    function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
   @>         IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }
```
```solidity
 function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
       ....

        @>    if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }

          ....
    }
```
To check 'to' is whitelisted, it checks its _whitelistIndex is less than _allowedWhitelistIndex or not. Now this is problem because non-whitelisted user returns '0', which will be always less than _allowedWhitelistIndex (if _allowedWhitelistIndex is set). As result this check will be easily bypassed by a non-whitelisted user


## Impact
Non-whitelisted user will be able to receive tokens
