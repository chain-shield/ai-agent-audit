# Vulnerability details

## Impact
The project launch process can be subjected to a Denial of Service (DoS) attack by manipulating the Uniswap pool price. Malicious actors can exploit the requirement that the cached price must equal the current token price, leading to the failure of the project launch transaction.

## Proof of Concept
The `ILOManager::launch()` function requires the cached price (`_cachedProject[uniV3PoolAddress].initialPoolPriceX96`) to match the current token price, [ILOManager::launch()#L189-L190](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L189-L190):

```solidity
        (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
        require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
```

An attacker can manipulate the token price by borrowing tokens and executing transactions to change the price. This can be done by sandwich attack.

The manipulated price causes the cached price check condition to fail, resulting in the transaction reverting.

After causing the transaction to fail, the attacker can back-running the transaction to return the borrowed tokens and restore the original price.
