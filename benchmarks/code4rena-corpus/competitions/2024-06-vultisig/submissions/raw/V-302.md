# Vulnerability details

## Impact
By IloManager design every new Project bounded to unique Uniswap V3 Pool(and vice versa) and only admin of such project can use this V3 Pool to create his own IloPools. 
Because of vulnerability it's possible to cause DoS attack by front-running new projects creation and acquire admin roles. 

Because amount of [Fee tiers](https://support.uniswap.org/hc/en-us/articles/20904283758349-What-are-fee-tiers) for V3 Pools is about four this vector of attack can be done without any extra steps to block all Pools for current pair.

## Proof of Concept
1) Project created with **initProject()** by User.
2) Attacker front-run transaction with similar params(to get same V3 Pool address)
```
        PoolAddress.PoolKey memory poolKey = PoolAddress.getPoolKey(params.saleToken, params.raiseToken, params.fee);
        uniV3PoolAddress = _initUniV3PoolIfNecessary(poolKey, params.initialPoolPriceX96);
```
3) Project and Pool created, Attacker becomes and admin of the project.
4) User's transaction get reverted because Project already exists by this V3 Pool address.
```
        Project storage _project = _cachedProject[uniV3PoolAddress];
        require(_project.uniV3PoolAddress == address(0), "RE");
```
5) All future **initProject()** calls with same saleToken,  raiseToken, fee and initialPoolPriceX96 will be blocked.

## Tools Used
Manual

## Recommended Mitigation Steps
Because concept of unique V3 Pool per Project is a main design concept, there two ways how to mitigate:
1) Create an option for Owner to cleanup blocked **_cachedProject[]** from malicious projects. 
2) Introduce Whitelist for IloManager.
