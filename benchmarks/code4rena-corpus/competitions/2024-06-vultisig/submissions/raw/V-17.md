# Vulnerability details

## Impact
The contract of `Vultisig` does not have any protection against the well-known “Multiple Withdrawal Attack” attack on the `approve` method of the `ERC20` standard.
Although this attack poses a limited risk in specific situations, it is worth mentioning to consider it for possible future operations.

## Proof of Concept
```solidity
function approveAndCall(address spender, uint256 amount, bytes calldata extraData) external returns (bool) {
        // Approve the spender to spend the tokens
>>      _approve(msg.sender, spender, amount); // @audit-issue can be frontrun

        // Call the receiveApproval function on the spender contract
        IApproveAndCallReceiver(spender).receiveApproval(msg.sender, amount, address(this), extraData); //! address(this) used as token

        return true;
    }
```
An approved `spender` may fron-run the `owner` and transfer the originally approved `amount` before the `owner` changes it to a new value and then transfer the new `amount` too.

Manual Review

## Recommended Mitigation Steps
There are solutions to mitigate this front running such as:
1. first reduce the `spender's allowance to 0` and set the desired value 
2. another solution could be the one that `OpenZeppelin` offers, where the non-standard `decreaseAllowance()` and `increaseAllowance()` functions have been added to mitigate the well-known issues involving setting allowances.
