# Vulnerability details

## Impact
The `initialize` function of ILOManager contract did not have any access control modifier that can prevent non owner from call it. An attacker can monitor the function call and front-run the transaction and change parameters he wants, making the contract useless to the original owner since the `initialize` function can only be called once.

## Proof of Concept
The below points describe how an attacker can front-run the transaction.
1. The contract was deployed and luckly enough an attacker monitors it.
2. The contract owner tries to call initialize function with his parameters.
3. The attack monitor the transaction in mempool and make a call to function with his own parameters and pay higher gas fee.
4. As transactions are mainly sorted in a way that those with higher gas fees will go first, he transaction will first succeed making the origin call's transaction fail because the function can only be called once.

## Tools Used
Manual review

## Recommended Mitigation Steps
Since in the constructor of the ILOManager contract `txt.origin` was made the owner of the contract `onlyOwner` modifier can be used to prevent non owners from calling the `initialize` function.
