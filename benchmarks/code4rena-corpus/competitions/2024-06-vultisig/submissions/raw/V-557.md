# Vulnerability details


The [ILOPool](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol) contract allows refunding of project to the  `Manager`  by calling `claimProjectRefund(address projectAdmin)` function  which returns a call to `_refundProject(address projectAdmin)`.
 The `refundAmount` amount is computed as [refundAmount = IERC20(SALE_TOKEN).balanceOf(address(this))](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L368). However , if multiple tokens with different prices are involved, simply summing their balances can result in significant discrepancies, either overpaying or underpaying the project admin

## Impact
Contract funds may be inaccurately refunded, potentially leading to significant financial discrepancies. If multiple tokens with different prices are involved, summing their balances can lead to incorrect refund amounts, resulting in either overpayment or underpayment to the project admin

## Proof of Concept
The issue arises in the following code snippet:
```solidity
function _refundProject(address projectAdmin) internal returns (uint256 refundAmount) {
@@--->   refundAmount = IERC20(SALE_TOKEN).balanceOf(address(this));
    if (refundAmount > 0) {
        TransferHelper.safeTransfer(SALE_TOKEN, projectAdmin, refundAmount);
        emit ProjectRefund(projectAdmin, refundAmount);
    }
}

```
As you can see the `balanceOf` function returns the total balance of `SALE_TOKEN` held by the contract, but it does not consider the value differences among various tokens. If multiple tokens with different prices are involved, summing their balances  can lead to incorrect refund amounts.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Always consider the price differences between tokens when calculating refund amounts
