# Vulnerability details


## Impact
There's no check to ensure that the `launchTime` is greater than the `block.timestamp` in the `initProject` function.
If launchTime is set to a value less than `block.timestamp`, the `refundDeadline` check becomes ineffective.
This vulnerability allows anyone to disrupt the project launch by calling the `buy` and `claimRefund` functions.

## Proof of Concept
The refundDeadline is calculated by adding the DEFAULT_DEADLINE_OFFSET (7 days) to the launchTime. [initProject](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L58)
User can call the `claimRefund` function after the `refundDeadline` passes. [claimRefund](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L342)
If the refundTriggered is true, the launch function will revert in both the `ILOPool` and `ILOManager` contract. [launch](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L272)

## Tools Used
Manual review

## Recommended Mitigation Steps
Add the validation for the `launchTime` to ensure that it is greater than the `block.timestamp` in the `initProject` function to prevent the project launch from failing.
