# Vulnerability details

## Impact
A malicious user can front-run the legitimate project initialization by calling initProject with the same uniV3PoolAddress (i.e same params.saleToken, params.raiseToken, params.fee) and sets themselves as the admin, they effectively "occupy" that pool address in the _cachedProject mapping. When the legitimate project later attempts to initialize with the same pool address the function _cacheProject checks ` require(_project.uniV3PoolAddress == address(0), "RE");`
```
function _cacheProject(
        address uniV3PoolAddress,
        address saleToken,
        address raiseToken,
        uint24 fee,
        uint160 initialPoolPriceX96,
        uint64 launchTime,
        uint64 refundDeadline
    ) internal {
        Project storage _project = _cachedProject[uniV3PoolAddress];
        require(_project.uniV3PoolAddress == address(0), "RE");

```
which checks if the pool address is already associated with a project, and if so, it prevents re-initialization, this check will cause a revert because _project.uniV3PoolAddress is no longer the zero address, having been set by the malicious user. thereby blocking the legitimate project from using that pool address rendering the legitimate project owner unable to use the ILO pool contract.
## Proof of Concept
- A malicious user monitors the network for transactions intending to call initProject.

- The malicious user calls initProject with the same parameters Or, if the attacker has params.initialPoolPriceX96, params.saleToken, params.raiseToken, and params.fee, they can simply call the function beforehand.

- The malicious user sets themselves as the admin of the project.

- The malicious user's call to initProject initializes the project and sets the project details in the _cachedProject mapping.

- The _cacheProject function is called, which sets the project details, including the admin and uniV3PoolAddress.

- When the legitimate project owner later calls initProject, the function attempts to initialize the project again.

- The function _cacheProject is called, which tries to cache the project details.

- The line Project storage _project = _cachedProject[uniV3PoolAddress]; retrieves the project details from the _cachedProject mapping.

- The check require(_project.uniV3PoolAddress == address(0), "RE"); fails because _project.uniV3PoolAddress is not the zero address; it has already been set by the malicious user rendering the legitimate project owner unable to use the ILO pool contract.

## Recommended Mitigation Steps
Using a nested mapping where the caller of initproject address is mapped to the Uniswap V3 pool address and then to the project details can help mitigate the front-running vulnerability.
```
 mapping(address => mapping(address => Project)) private _cachedProject;  //maps caller of initProject=> uniV3Pool => project


function _cacheProject(
        address uniV3PoolAddress,
        address saleToken,
        address raiseToken,
        uint24 fee,
        uint160 initialPoolPriceX96,
        uint64 launchTime,
        uint64 refundDeadline
    ) internal {
  +     Project storage _project = _cachedProject[msg.sender][uniV3PoolAddress];
        require(_project.uniV3PoolAddress == address(0), "RE");

```
This approach ensures that only the legitimate caller can initialize and manage their project.
