# Vulnerability details


## Proof of Concept
The vulnerability lies in the `addLiquidity` function within the `LiquidityManagement` contract, inherited by `ILOPool`, which fails to specify exact amounts of tokens [(`amount0Desired` and `amount1Desired`)](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/LiquidityManagement.sol#L34-L35) when adding liquidity to Uniswap V3 pools. This function is critical for minting liquidity tokens on Uniswap V3, yet it lacks essential checks and specific parameters that are crucial for ensuring precise liquidity management.
1. $$Insufficient Specification of Token Amounts$$: The `addLiquidity` function calls `params.pool.mint` to mint liquidity tokens in a Uniswap V3 pool. However, it only provides the `params.liquidity` parameter, which represents the amount of liquidity tokens to mint. It does not explicitly specify the exact amounts of `token0` and `token1` (represented as `amount0Desired` and `amount1Desired`) that the contract intends to add as liquidity.
```solidity
function addLiquidity(AddLiquidityParams memory params)
    internal
    returns (
        uint256 amount0,
        uint256 amount1
    )
{
    (amount0, amount1) = params.pool.mint(
        address(this),
        TICK_LOWER,
        TICK_UPPER,
        params.liquidity,
        ""
    );

    require(amount0 >= params.amount0Min && amount1 >= params.amount1Min, 'Price slippage check');
}
```
2. $$Lack of Exact Amount Checks$$: The function includes a require statement to check if the amounts `amount0` and `amount1` returned from the mint function meet minimum requirements (`params.amount0Min` and `params.amount1Min`). However, without explicitly setting `amount0Desired` and `amount1Desired`, there's no guarantee that the exact amounts of tokens added as liquidity will match the intentions of the contract.
## Impact
$$Price Slippage and Inaccurate Liquidity Provisioning$$: Without precise specification of `amount0Desired` and `amount1Desired`, there's a risk of price slippage during liquidity provision. This could lead to incorrect pricing of assets within the Uniswap V3 pool, affecting trading and liquidity provider returns.
$$Increased Attack Surface$$: Malicious actors could exploit the lack of exact amount checks to manipulate token prices or front-run transactions. This could result in financial losses for liquidity providers and traders using the affected Uniswap V3 pool.


## Tools Used
Manual
## Recommended Mitigation Steps
$$Explicitly Defining$$ `amount0Desired` and `amount1Desired`: Modify the `AddLiquidityParams` struct to include `amount0Desired` and `amount1Desired` parameters. These parameters should specify the exact amounts of `token0` and `token1` that the contract intends to add as liquidity.

$$Implementing Precise Checks$$: Ensure that the require statement verifies that `amount0` and `amount1` returned by the mint function exactly match `amount0Desired` and `amount1Desired`. This ensures accurate liquidity provisioning and guards against price manipulation.
