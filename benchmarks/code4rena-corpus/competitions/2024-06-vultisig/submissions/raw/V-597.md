# Vulnerability details

## Summary

**Context:**
The [initProject()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L57) function allows anyone to create a project. During this call, a function [initV3PoolIfNecessary()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L109) is called. This checks if a pool exists or not. If it does not, it creates a pool and initializes it. If it does, it ensures a price is initialized or the current price meets the existing price retrieved from slot0. 

**Root cause:**
The issue will be described in the POC but the root cause is the missing 0 value check for sqrtPriceX96 in the if condition [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L111).

**Impact:**
The impact of this issue would be that the admin of the project will not be able to set an initial price for pool (project) anymore or the prices would mismatch if initialized directly through the pool.

## Proof of Concept

The issue is presented in a specific scenario.

1. Let's assume the pool was not created before and the admin comes to create a project for the first time by calling the function [initProject()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L57). 

2. The above function calls [initV3PoolIfNecessary()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L109). Since the admin has not deployed a pool for the token pair and fee tier, it would deploy the contract as seen below on Line 118. On Line 119, the admin decides to initialize the price later on and uses the value 0.
