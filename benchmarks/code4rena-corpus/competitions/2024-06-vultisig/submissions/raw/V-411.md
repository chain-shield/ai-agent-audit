# Vulnerability details

## Impact

There can be users within the whitelist who are later banned. This poses a problem because `_allowedWhitelistIndex` remains constant. Depending on the low whitelist index of banned users, it could leave the whitelist virtually empty.

## Proof of Concept.

`_addWhitelistedAddress` only adds a user to the whitelist, incrementing whitelistCount.


```
function _addWhitelistedAddress(address whitelisted) private {
        if (_whitelistIndex[whitelisted] == 0) {
            _whitelistIndex[whitelisted] = ++_whitelistCount;
        }
    }
```

Meanwhile, the `blacklist` function only modifies `_isBlacklisted`:

```
function setBlacklisted(address blacklisted, bool flag) external onlyOwner {
        _isBlacklisted[blacklisted] = flag;
    }
```

And in `checkWhitelist`, it only verifies the index of the whitelist:

```
if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
}
```

## Tools Used

Manual

## Recommended Mitigation Steps

Modify `_allowedWhitelistIndex` appropriately within the `setBlacklisted` function, depending on the flag and the previous state. This ensures that the whitelist remains effective even when users are banned.
