# Vulnerability details

## Description
Given that gas is not capped when calling the line `IApproveAndCallReceiver(spender).receiveApproval(msg.sender, amount, address(this), extraData)`, if the spender is an upgradable contract, it can be upgraded to consume all attached gas without giving the user the option to limit the gas.

## Impact
* In the case of a batched transaction using this function, the whole batch would revert.
* A malicious upgrade can take advantage of using `tx.origin` in other contracts without the user noticing.

## Recommended mitigation
In extra data, force as first element one that specified transaction gas limit.
