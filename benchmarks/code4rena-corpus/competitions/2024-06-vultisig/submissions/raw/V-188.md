# Vulnerability details

## Description:

The `receive()` function is designed to automatically whitelist an address when it receives Ether, unless the address is blacklisted or self-whitelisting is disabled. However, the use of the `transfer()` function introduces a significant limitation due to its gas constraint of 2300 gas. This constraint can prevent certain addresses, particularly multisig wallets, from being successfully whitelisted.
For instance, it is not enough for Safes (such as [this one](https://etherscan.io/address/0xd1e6626310fd54eceb5b9a51da2ec329d6d4b68a)) to receive funds back from the whitelist contract, which require > 6k gas for the call to reach the implementation contract and emit an event.

## Impact:

The gas constraint imposed by the `transfer()` function can lead to failed transactions when interacting with multisig wallets or any contract that requires more than 2300 gas for receiving Ether. This failure prevents these addresses from being whitelisted, effectively excluding them from participating in the system's functionalities. This exclusion can lead to usability issues and potentially restrict the participation of legitimate users who manage their funds through multisig wallets.

## Code Snippet:

```javascript
receive() external payable {
    if (_isSelfWhitelistDisabled) {
        revert SelfWhitelistDisabled();
    }
    if (_isBlacklisted[_msgSender()]) {
        revert Blacklisted();
    }
    _addWhitelistedAddress(_msgSender());
    payable(_msgSender()).transfer(msg.value);
}
```

## Recommended Mitigation:

To resolve this issue, it is recommended to replace the `transfer()` function with the `call` method. The `call` method is more flexible and does not impose the 2300 gas limit, ensuring compatibility with multisig wallets and other contracts that require more gas to execute.

### Mitigated Code Snippet:

```diff
receive() external payable {
    if (_isSelfWhitelistDisabled) {
        revert SelfWhitelistDisabled();
    }
    if (_isBlacklisted[_msgSender()]) {
        revert Blacklisted();
    }
    _addWhitelistedAddress(_msgSender());
-   payable(_msgSender()).transfer(msg.value);
+   (bool success, ) = _msgSender().call{value: msg.value}("");
+   require(success, "Transfer failed");
}
```

By using `call`, the contract ensures that the transfer of Ether to the sender will succeed even if more gas is required, thus allowing multisig wallets and other complex contract addresses to be whitelisted successfully.
