# Vulnerability details

## Impact
Calling the following `buy` function should only mint an `ILOPool` NFT position to a recipient, who is whitelisted. However, after receiving such `ILOPool` NFT position, such whitelisted recipient can transfer it to another suspicious actor, who is not whitelisted, since the `ILOPool` contract has no way to revert such transfer. In this case, the whitelist requirement, which attempts to prevent non-whitelisted actors from owning `ILOPool` NFT positions, is bypassed and ineffective. As a result, non-whitelisted actors can obtain `ILOPool` NFT positions when they should not be allowed to.

## Proof of Concept
The following steps can occur for the described scenario.
1. Alice is whitelisted for obtaining an `ILOPool` NFT position.
2. Alice calls the `buy` function to mint an `ILOPool` NFT position to herself.
3. Alice transfers such `ILOPool` NFT position to Bob, who is not whitelisted.
4. Bob now owns such `ILOPool` NFT position when he should not be allowed to.

## Recommended Mitigation Steps
The `ILOPool` contract can add a `_beforeTokenTransfer` function that overrides the `_beforeTokenTransfer` function of OpenZeppelin's `ERC721` contract and reverts if `to` is not whitelisted.
