# Vulnerability details

## Impact
The statement `require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");` in `ILOManager.sol` is prone to fluctuations as `initialPoolPriceX96` and `sqrtPriceX96` can not be exactly same most of the time. If we use a strict require statement even a minor fluctuations in `sqrtPriceX96` can halt the launch.

## Proof of Concept
Contract `ILOManager.sol` :https://github.com/code-423n4/2024-06-vultisig/blob/7fb0da757c98116090f35810146ea742ca3b94da/src/ILOManager.sol#L1-L208

Function `launch()` : https://github.com/code-423n4/2024-06-vultisig/blob/7fb0da757c98116090f35810146ea742ca3b94da/src/ILOManager.sol#L188-L198

The function is shown below:

```
function launch(address uniV3PoolAddress) external override {
        require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT"); 
        (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0(); 
        require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P"); //vulnerable  
        address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
        require(initializedPools.length > 0, "NP");
        for (uint256 i = 0; i < initializedPools.length; i++) {
            IILOPool(initializedPools[i]).launch();
        }

        emit ProjectLaunch(uniV3PoolAddress);
    }
```

## Recommended Mitigation Steps

Instead of using a strict require statement, a particular threshold level can be set which would hold account for the fluctuations in the price fields of `sqrtPriceX96` and `initialPoolPriceX96`.
