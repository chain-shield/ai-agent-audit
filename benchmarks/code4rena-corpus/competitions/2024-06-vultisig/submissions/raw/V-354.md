# Vulnerability details

## Impact
- Admin Would be Denialed the power to Claim Project Refund at [L363](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L363) after refund has been called by user at [L350](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L350)
- User can also also be Denialed subsequent Refund claims as claim can be only done once due to oversight in refundable() modifier implementation
## Proof of Concept
```solidity
 modifier refundable() {
>>>        if (!_refundTriggered) {
            // if ilo pool is lauch sucessfully, we can not refund anymore
            require(!_launchSucceeded, "PL");
            IILOManager.Project memory _project = IILOManager(MANAGER).project(_cachedUniV3PoolAddress);
            require(block.timestamp >= _project.refundDeadline, "RFT");

>>>            _refundTriggered = true;
        }
        _;
    }
```
The code provided above shows the implementation for refundable() modifier, it is called by the two functions i.e [claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L350) & [claimProjectRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L363), The problem is that the refundable() can be only called once as can be noted by the pointer that _refundTriggered is set to true and would fall in subsequent calls due to the first validation in the first pointer. This would be a problem as more that one function is using a modifier that can be only called once, and also if the function is needed to be called more that once this would also be a problem as the modifier can be used only once. A look at the contract shows that there is no way to reset the value of _refundTriggered variable even by manager which makes it a permanent assigned value that cannot be adjusted for subsequent calls.

## Recommended Mitigation Steps
The protocol should consider giving the Admin or Manager the power to reset the value of _refundTriggered variable at [L40](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L40) back to false when there is need for subsequent refunds before Launch which would have been prevented by the one time possible call of refundable() modifier
```solidity
+++ setRefundTriggered(bool flag) external OnlyManager(){
+++  _refundTriggered = flag;
+++ }
```
