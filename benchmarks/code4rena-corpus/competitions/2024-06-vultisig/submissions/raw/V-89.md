# Vulnerability details


## Impact
There's no check to ensure that the `sqrtRatioUpperX96` is greater than the `initialPoolPriceX96` in the `initILOPool` function.
If `sqrtRatioUpperX96` is set to a value less than `initialPoolPriceX96`, the project launch will always fail.

## Proof of Concept
https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L90
```solidity
    require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE"); // @audit missing _project.initialPoolPriceX96 < sqrtRatioUpperX96
```
If the `initialPoolPriceX96` is not in the range of `sqrtRatioLowerX96` and `sqrtRatioUpperX96`, the `launch` function in the `ILOManager` contract will revert.
The liquidity/saleAmountNeeded calculation assumes that the `initialPoolPriceX96` is in the range of `sqrtRatioLowerX96` and `sqrtRatioUpperX96`.
An incorrect calculation can cause the price slippage check to revert. 
You can find the code for this check [launch](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L296) and [addLiquidity](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/base/LiquidityManagement#L56).

## Tools Used
Manual review

## Recommended Mitigation Steps
Add the validation for the `sqrtRatioUpperX96` to ensure that it is greater than the `initialPoolPriceX96` in the `initILOPool` function to prevent the project launch from failing.
