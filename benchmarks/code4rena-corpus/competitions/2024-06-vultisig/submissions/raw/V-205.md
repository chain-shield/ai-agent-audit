# Vulnerability details

## Impact

In the current implementation of the `buy()` function inside of the `ILOPool` smart contract, the liquidity for the position is changed based on the change of `liquidityDelta` parameter from the `getLiquidityForAmount0()` or `getLiquidityForAmount1()` function calls. However, the function `buy()` only checks whether `liquidityDelta` > 0 and misses minimum amount parameter for slippage protection.

## Proof of Concept

Let's take a look at the `buy()` function and how liquidity changes:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L155-159
```
  if (RAISE_TOKEN == _cachedPoolKey.token0) {
            liquidityDelta = LiquidityAmounts.getLiquidityForAmount0(SQRT_RATIO_X96, SQRT_RATIO_UPPER_X96, raiseAmount);
        } else {
            liquidityDelta = LiquidityAmounts.getLiquidityForAmount1(SQRT_RATIO_LOWER_X96, SQRT_RATIO_X96, raiseAmount);
        }
```

So we change the liquidity delta via `getLiquidityForAmount0()` and `getLiquidityForAmount1()` based on what is the raise token. After that there is a following check:


https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L161
```
 require(liquidityDelta > 0, "ZA");
```
And after that the liquidity delta is added to the position:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L167
```
_position.liquidity += liquidityDelta
```

So there is no any minimum parameter for `liquidityDelta` that is supplied by the caller of the function and therefore it opens up an attack vector where desired amount of liquidity delta cannot be added due to manipulations by other users via front-running.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Add minimum liquidity delta parameter to avoid front-running and liquidity manipulation.
