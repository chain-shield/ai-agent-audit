# Vulnerability details

## Impact
The `ILOPool::constructor()` calls `Initializable::_disableInitialize()`, which sets the `_initialized` to `true`, the `ILOPool::initialize()` has `whenNotInitialized` modifier that checks for `_initialized` to be false, it then executes the code and sets the `_initialized` to true, but the `_initialized` is already set to `true` causing `require(!_initialized);` check to fail and `ILOPool::initialize()` to revert
  
## Proof of Concept

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/base/Initializable.sol

```solidity
    src/base/Initializable.sol

    pragma solidity =0.7.6;

    abstract contract Initializable {
        bool private _initialized;
        /* @audit - this function is called in the constructor, and sets initialized to true */
        
        @> function _disableInitialize() internal {
            _initialized = true;
        }
        
        /* @audit - this modifier is used in ILOPool::initialize() to check if _initialized is set, but it is already set in the constructor causing the ILOPool::initialize() to revert */
        
        modifier whenNotInitialized() {
        @>    require(!_initialized);
            _;
            _initialized = true;
        }
        modifier afterInitialize() {
            require(_initialized);
            _;
        }
    }
```
