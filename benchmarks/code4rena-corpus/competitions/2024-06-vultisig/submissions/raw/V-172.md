# Vulnerability details

## Impact
The current implementation of the `checkWhitelist` function in the contract fails to enforce a cumulative check on contributions, potentially allowing addresses to `exceed` the `_maxAddressCap` limit over multiple transactions. 

_maxAddressCap exeeding the limit

Lack of cumulative checks undermines the intended control mechanisms, potentially compromising contract integrity. At the moment
Exceeding the `_maxAddressCap` could result in contractual breaches, impacting contract participants.
```javascript
if (_contributed[to] + estimatedETHAmount > _maxAddressCap) { //@udit
                revert MaxAddressCapOverflow();
            }
```

## Proof of Concept
Initial Contribution:

vultisig contributes 2 ETH to the contract, where `_maxAddressCap` is set to 3 ETH.
The function checkWhitelist validates and allows the transaction since 2 ETH is below 3 ETH.
_contributed[to] is updated to 2 ETH.
Subsequent Contributions:

3 additional transactions contributing 1 ETH each, totaling 3 more transactions.
Each time checkWhitelist is called, it checks against `_maxAddressCap` using `if (_contributed[to] + estimatedETHAmount > _maxAddressCap)`.
However,that is not properly accumulated across transactions, allowing vultsig to contribute a total of 5 ETH (2 ETH + 1 ETH + 1 ETH + 1 ETH) cumulatively, exceeding the 3 ETH cap.
Impact of Oversight:

Despite individual transactions being within the limit, cumulative contributions from repeated transactions now `exceed` `_maxAddressCap`.
The contract fails to revert transactions or enforce the cumulative limit, resulting in a breach of intended constraints.

## Recommended Mitigation Steps
To mitigate the risk associated with exceeding the `_maxAddressCap`, it is recommended to:

Implement Cumulative Contribution Tracking: Modify checkWhitelist to accumulate `_totalContributed[to]` across transactions and enforce the cumulative check against _maxAddressCap. This will make it easily to track the transaction each time some amount is added to never exeed the max.
Ensure that each transaction checks against both current and cumulative contributions to prevent unintended exceedances.
