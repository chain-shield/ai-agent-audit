# Vulnerability details

#### Vulnerability Details

**Summary:**
A critical vulnerability in the `Whitelist` contract allows attackers to bypass the maximum ETH contribution limit by exploiting the incorrect estimation of the ETH equivalent of VULT tokens.

**Affected Contracts:**
- `Whitelist.sol`
- `oracles/uniswap/UniswapV3Oracle.sol`

**Root Cause:**
The `checkWhitelist` function estimates the ETH equivalent of VULT tokens using the `peek` function from the `UniswapV3Oracle` contract. The slippage is incorrectly applied as a discount instead of a premium, leading to an underestimated ETH amount.

**Affected Code:**
In `Whitelist.sol`:
```solidity
uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
    revert MaxAddressCapOverflow();
}
_contributed[to] += estimatedETHAmount;
```

In `UniswapV3Oracle.sol`:
```solidity
uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
return (quotedWETHAmount * baseAmount * 95) / 1e20; // Incorrect slippage applied
```

**Impact:**
An attacker can exploit this to contribute more ETH than the allowed cap, acquiring a larger share of tokens than intended. This leads to financial losses for the project and genuine contributors, and damages the project's reputation.

**Proof of Concept:**
1. An attacker prepares to purchase VULT tokens, aware of the incorrect slippage calculation.
2. The attacker initiates a transaction to buy VULT tokens, exceeding the maximum ETH cap.
3. The `checkWhitelist` function calls the `peek` function, which underestimates the ETH amount.
4. The underestimated ETH amount allows the transaction to pass, bypassing the cap.

#### Tools Used
Manual code review and analysis

#### Recommended Mitigation Steps
1. Correct the slippage calculation in the `peek` function of the `UniswapV3Oracle` contract to:
```solidity
return (quotedWETHAmount * baseAmount * 105) / 1e20; // Correctly applying 5% slippage
```
2. Conduct a comprehensive review of all mathematical calculations in the `Whitelist` and `UniswapV3Oracle` contracts to ensure no other similar errors exist.
