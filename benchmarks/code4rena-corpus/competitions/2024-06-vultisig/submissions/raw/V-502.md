# Vulnerability details



## Impact

By failing to update the `totalRaised` state variable during refunds, the contract maintains an inaccurate representation of the funds currently held. This has the abiility to cause a cascade of issues:

The contract will continue to report an inflated total of raised funds, even after refunds have been processed. This could mislead potential investors and project stakeholders about the true state of the ILO.

Additionally, the `launch` function relies on the `totalRaised` value to determine if the soft cap has been reached. With an inaccurate `totalRaised`, the contract might erroneously allow or prevent the launch of the pool.

Also, If new purchases are allowed after refunds, the actual total of raised funds could exceed the hard cap, as the contract would not accurately track the current total. This could lead to over-allocation of tokens or liquidity.

## Proof of Concept

The vulnerability stems from the `claimRefund` function, which processes refunds without updating the `totalRaised` state variable. 

Take a look at this part of the code: https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L350-L360

```solidity
function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
    uint256 refundAmount = _positions[tokenId].raiseAmount;
    address tokenOwner = ownerOf(tokenId);

    delete _positions[tokenId];
    delete _positionVests[tokenId];
    _burn(tokenId);

    TransferHelper.safeTransfer(RAISE_TOKEN, tokenOwner, refundAmount);
    emit UserRefund(tokenOwner, tokenId,refundAmount);
}
```

Consider the following scenario:

1. The `ILO` has a hard cap of 1000 tokens and a soft cap of 500 tokens.
2. Initially, 800 tokens are raised from various investors.
3. Due to market conditions, some investors decide to claim refunds totaling 400 tokens.
4. After refunds, the actual raised amount should be 400 tokens, below the soft cap.
5. However, `totalRaised` still reports 800 tokens.

This impacts the functions: 

```solidity
function launch() external override OnlyManager() {
    // ...
    require(totalRaised >= saleInfo.softCap, "SC");
    // ...
}
```
The [`launch`](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L274) function would incorrectly allow the pool to launch, as it believes the soft cap (500) is still met, when in reality, it isn't.


Also, 
```solidity
function totalSold() public view override returns (uint256 _totalSold) {
    (_totalSold,) =_saleAmountNeeded(totalRaised);
}
```
[`totalSold`](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L376-L378) would report an inflated amount of tokens sold, as it bases its calculation on the inaccurate `totalRaised` value.


Also, if new purchases are allowed, the contract might accept new investments based on the inflated `totalRaised`, potentially exceeding the hard cap: https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L136

```solidity
function buy(uint256 raiseAmount, address recipient) external override returns (uint256 tokenId, uint128 liquidityDelta) {
    // ...
    require(saleInfo.hardCap - totalRaised >= raiseAmount, "HC");
    totalRaised += raiseAmount;
    // ...
}
```

In the scenario above, if a new investor tries to buy 300 tokens, the check would pass (1000 - 800 >= 300), even though it should fail (1000 - 400 < 300).

## Recommended Mitigation Steps

Update the `totalRaised` state variable whenever a refund is processed. 

```diff
function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
    uint256 refundAmount = _positions[tokenId].raiseAmount;
    address tokenOwner = ownerOf(tokenId);

    delete _positions[tokenId];
    delete _positionVests[tokenId];
    _burn(tokenId);

+   // Update totalRaised
+   if (totalRaised >= refundAmount) {
+       totalRaised -= refundAmount;
+   } else {
+       totalRaised = 0;
+   }

    TransferHelper.safeTransfer(RAISE_TOKEN, tokenOwner, refundAmount);
    emit UserRefund(tokenOwner, tokenId,refundAmount);
+   
+   // Emit an event for the updated totalRaised
+   emit TotalRaisedUpdated(totalRaised);
}

+ // Add a new event to track totalRaised updates
+ event TotalRaisedUpdated(uint256 newTotalRaised);
```
