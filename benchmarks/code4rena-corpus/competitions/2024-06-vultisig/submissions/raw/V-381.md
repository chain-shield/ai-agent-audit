# Vulnerability details

## Impact

The `peek(uint256 baseAmount)` function returns an incorrect value.

## Proof of Concept

```
function peek(uint256 baseAmount) external view returns (uint256) {
        uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
        uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
        int24 tick = OracleLibrary.consult(pool, period);
        uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
        // Apply 5% slippage
        return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
    }
```

We can see that the function multiplies both `BASE_AMOUNT` (1e18) and `baseAmount` (which is expected to be a number with 18 decimals). This can be verified by seeing that the function is used in `Whitelist.checkWhitelist`, which in turn is used in the function:

```
function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
            IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }
```

Indeed, we can see that amount is treated as a number with 18 decimals, thus the multiplication would return a number much greater than expected.
