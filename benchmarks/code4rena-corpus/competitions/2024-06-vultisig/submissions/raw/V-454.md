# Vulnerability details

## Impact
Project cannot be launched at launch time because of [require statement](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L188)

## Proof of Concept
```
function launch(address uniV3PoolAddress) external override {
@->        require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
     
        ...

        emit ProjectLaunch(uniV3PoolAddress);
    }
```

we can see that the require statements enforces the project to launch after `launchTime`.

This can lead to the complications in other functions for example if we have a look at `_validateVestSchedule` in `ILOVest.sol`

```
function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
@->        require(schedule[0].start >= launchTime, "VT");
        uint16 BPS = 10000;
        uint16 totalShares;
        uint64 lastEnd;
        
        ...

        require(totalShares == BPS, "VS");
    }
``
we can observe that the schedule starts right from the launch time`(>= launchTime)` 
meaning the project is launched at launch time instead of after.

    function launch(address uniV3PoolAddress) external override {
-        require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
+        require(block.timestamp >= _cachedProject[uniV3PoolAddress].launchTime, "LT");
        (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();

        address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];

        for (uint256 i = 0; i < initializedPools.length; i++) {

    }
