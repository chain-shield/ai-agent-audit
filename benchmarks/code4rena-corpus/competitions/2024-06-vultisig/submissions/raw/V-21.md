# Vulnerability details

## Impact
The current implementation of the contract contains a bug where the performanceFee is not correctly handled and remains inside the contract. This issue arises in the function call where the performance fees are supposed to be deducted:

```javascript
(fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);
```

In the code snippet provided, the _deductFees function is called to deduct the performance fees. However, after the fees are deducted, the performanceFee is not sent to project owner/ procol's feeTaker and instead stays within the contract. This can lead to funds being locked inside the contract and not being properly distributed as intended.

## Proof of Concept

Deducted performanceFee percent just stays inside ILOPool contract.

```javascript
  (fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);

            // fees is combined with liquidity token amount to return to the user
            amount0 += fees0;
            amount1 += fees1;

     //----
        address feeTaker = IILOManager(MANAGER).FEE_TAKER();
        // transfer fee to fee taker
        TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);

```
