# Vulnerability details

## Vulnerability details
A whitelisted investor can buy ILO by depositing raise token using ILOPool::buy(). Once the pool is launched, investor can claim their collected tokens using ILOPool::claim()
```solidity
function buy(uint256 raiseAmount, address recipient)
        external override 
        returns (
            uint256 tokenId,
            uint128 liquidityDelta
        )
    {
        require(_isWhitelisted(recipient), "UA");
        require(block.timestamp > saleInfo.start && block.timestamp < saleInfo.end, "ST");
        // check if raise amount over capacity
        require(saleInfo.hardCap - totalRaised >= raiseAmount, "HC");
        totalRaised += raiseAmount;

        require(totalSold() <= saleInfo.maxSaleAmount, "SA");

        ....
    }

```

Now the problem is, there is no check to prevent an investor from buying ILO after pool launch. As result late investor will also be able to buy ILO and claim tokens, which belongs to the early investors. 

Also those raise tokens(sent by late investor) will be locked forever in the contract as there is no way to recover it


## Impact
As result, raise token will be locked & some early investors will not be able to claim full tokens
