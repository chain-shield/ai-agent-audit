# Vulnerability details

# [H-01] Anyone Can Purchase Without Being Whitelisted Due to Incorrect Access Control
The `Whitelist::checkWhitelist` function is designed to verify if an address is whitelisted by comparing the `_whitelistIndex[to]` against the `_allowedWhitelistIndex`. However, due to a logical oversight, the condition fails to properly exclude non-whitelisted users because it does not account for addresses with a `_whitelistIndex` of zero. As a result, anyone can bypass the whitelist requirement and purchase without proper authorization.
The vulnerability arises from the following conditional check within the `checkWhitelist` function:
This condition incorrectly assumes that any address not explicitly whitelisted (i.e., those with a `_whitelistIndex` of zero) is automatically excluded. However, the absence of a check for `_whitelistIndex[to] == 0` means that non-whitelisted users can still pass the check.

## Impact 
This flaw renders the whitelist mechanism ineffective, allowing unrestricted access to purchasing functionalities. It undermines the security and integrity of the system, potentially enabling unauthorized users to exploit the contract.
