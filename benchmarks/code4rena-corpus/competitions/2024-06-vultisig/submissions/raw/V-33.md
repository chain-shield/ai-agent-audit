# Vulnerability details

## Impact
Malicious users can exploit the contribution tracking mechanism in the `VULT` token contract to inflate their contributed amount. By transferring `VULT` tokens to the Uniswap v2 pair pool and then calling `skim()`, they can retrieve their tokens while falsely increasing their contribution record.

## Proof of Concept

The function `VultisigWhitelisted::_beforeTokenTransfer()` calls `Whitelist::checkWhitelist()` to apply whitelist check feature if tokens are transferred from the pair, which updates the contributed amount to estimated ETH value for token buyers, [L204-L226](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204-L205):

```solidity
    function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
        if (from == _pool && to != owner()) {

            _contributed[to] += estimatedETHAmount;
...
```

However, tokens can be donated to the Uniswap pair pool, and then, call `skim()` to withdraw tokens from the pool to back to users. Consequently, the `checkWhitelist()` is applied during the process and the contributed amount is updated unexpectly.
