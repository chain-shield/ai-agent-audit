# Vulnerability details

## Proof of Concept
The `checkWhitelist` function in the Whitelist contract relies on the `UniswapV3Oracle` contract to obtain the TWAP (Time-Weighted Average Price) of the $VULT/ETH$ pair. The oracle's peek function is used to estimate the ETH value of a given amount of VULT tokens. If the oracle data is stale or invalid, it can lead to incorrect calculations, impacting the eligibility checks for whitelisting and contributions.

Here is the relevant portion of the `checkWhitelist` function:
```solidity
function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
    if (from == _pool && to != owner()) {
        if (_locked) {
            revert Locked();
        }

        if (_isBlacklisted[to]) {
            revert Blacklisted();
        }

        if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
            revert NotWhitelisted();
        }

        // Calculate rough ETH amount for VULT amount
        uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
        if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
            revert MaxAddressCapOverflow();
        }

        _contributed[to] += estimatedETHAmount;
    }
}

```
The `peek` function in the `UniswapV3Oracle` contract is responsible for fetching the TWAP and adding a 5% slippage:
```solidity
function peek(uint256 baseAmount) external view returns (uint256) {
    uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
    uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
    int24 tick = OracleLibrary.consult(pool, period);
    uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
    // Apply 5% slippage
    return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
}
```
If the TWAP data from the Uniswap V3 pool is outdated or manipulated, the `estimatedETHAmount` used in the `checkWhitelist` function will be incorrect, potentially leading to improper whitelisting decisions.

## Impact
The primary impact of using stale or invalid oracle data in the `checkWhitelist` function is that it may incorrectly allow or disallow contributions and transfers. For example, a user might be incorrectly whitelisted or blacklisted based on outdated or manipulated price information, leading to either unintended acceptance of contributions exceeding the cap or unwarranted rejection of valid contributions.

## Recommended Mitigation Steps
 Include additional checks to ensure the oracle data is both fresh and within an acceptable range. A fallback mechanism can be implemented to handle scenarios where the oracle data is unavailable or potentially incorrect.
