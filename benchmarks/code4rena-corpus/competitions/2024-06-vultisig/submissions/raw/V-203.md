# Vulnerability details

## Vulnerability Details

`Whitelist` contract allows users to self whitelist by sending any amount of ether (when selfWhitelistModeIsOn). For this `receive` function is used a fallback to execute that.
```solidity
 receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
@>        payable(_msgSender()).transfer(msg.value);
    }
```

If you see the highlighted code, it's using `transfer` method to refund ether to caller which makes it unusable for smart account or multisig wallet holder. Becasue transfer has limit 2300 gas which is not sufficient to send ether to multisig or smart accounts.

## Impact
smart accounts(contract based accounts) and multisig wallet  won't be able to use this function even if they wanted. This will create DOS for certain percentage of participants.

## Recommendation
use `call` to transfer funds rather using transfer.

```diff
+ error EthTransferFailed();
 receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
-       payable(_msgSender()).transfer(msg.value);
+ (bool sent,) = (_msgSender()).call{value: msg.value}("");
+ if (!sent) {revert EthTransferFailed();}
    }
```
