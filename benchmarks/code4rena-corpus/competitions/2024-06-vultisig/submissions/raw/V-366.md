# Vulnerability details

## Vulnerability Details
The function `ILOManager::initProject` allows anyone to initialize a project with a pair of raise and sale tokens. An UniswapV3 pool of the pair is also created in the process. The project owner can afterward create a `ILOPool` that sells liquidity position, locks and vests for each investor who buys it. The vesting configuration is also decided by the project owner when the `ILOPool` is created.

The function `ILOVest::_validateVestSchedule` is called during the pool initialization process. However, it only verifies if the vesting start date of the investor is well after the launch time and whether the vesting schedule does not overlap. However, it does not check the vesting end date towards the launch time for other project team recipients i.e. dev, treasury, etc.

In addition, when a user claims the raise token after the pool launch as depicted in `ILOPool::_unlockedLiquidity`, if the vesting period already ends, all the shares are unlocked. As a result, a project owner can create a pool where the vesting end date is actually before the pool launch time, and he'll be able to claim his part of the pool shares without having to wait for a vesting period.

## Impact

A malicious project team can create a pool with an unfair vesting schedule. They could rug pull a big part of the invested liquidity just after the pool launch, while the legitimate investors couldn't.

## Proof of Concept
Scenario:
- A malicious developer initializes a project where he sets the vesting end period to be before the launch time
- The project collects liquidity from investors during the sale period
- Right after the pool is launched, he withdraws his part of the liquidity


Please append the following test to the file `ILOPool.t.sol`:

```javascript
function testDevCreatePoolWithVestingEndBeforeLaunchStart() public {
```

## Recommended Mitigation Steps

It's recommended to verify the vesting end date towards the launch time of the pool.
We propose to make this change to the function `ILOVest::_validateVestSchedule`:

```diff

function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
        require(schedule[0].start >= launchTime, "VT");
        uint16 BPS = 10000;
        uint16 totalShares;
        uint64 lastEnd;
        uint256 scheduleLength = schedule.length;
        for (uint256 i = 0; i < scheduleLength; i++) {
            // vesting schedule must not overlap
            require(schedule[i].start >= lastEnd, "VT");
+           require(schedule[i].end >= launchTime && schedule[i].end >= schedule[i].start, "VT");
            lastEnd = schedule[i].end;
            // we need to subtract fist in order to avoid int overflow
            require(BPS - totalShares >= schedule[i].shares, "VS");
            totalShares += schedule[i].shares;
        }
        // total shares should be exactly equal BPS
        require(totalShares == BPS, "VS");
}
```
