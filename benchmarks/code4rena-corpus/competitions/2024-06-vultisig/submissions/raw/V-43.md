# Vulnerability details

## Vulnerability details
A whitelisted user can buy position in ILO using ILOPool::buy(), which mints a new nft and creates a vesting schedule for investor. To mint nft, it checks investor already have any position or not by checking balanceOf(recipient) 
```solidity
      // if investor already have a position, just increase raise amount and liquidity
        // otherwise, mint new nft for investor and assign vesting schedules
      @>  if (balanceOf(recipient) == 0) {
            _mint(recipient, (tokenId = _nextId++));
            _positionVests[tokenId].schedule = _vestingConfigs[0].schedule;
        } else {
            tokenId = tokenOfOwnerByIndex(recipient, 0);
        }

        Position storage _position = _positions[tokenId];
      @>  require(raiseAmount <= saleInfo.maxCapPerUser - _position.raiseAmount, "UC");
        _position.raiseAmount += raiseAmount

```
Now this is problem because, a malicious user can transfer his nft to a different address, which will set his balanceOf(recipient) = 0. And again malicious user can buy position which will mints new nft & creates a new vesting schedule

Also by doing this, investor can bypass the maxCapPerUser check(see above code)


## Impact
Multiple nft will be minted for same investor & maxCapPerUser will be bypassed
