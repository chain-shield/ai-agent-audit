# Vulnerability details

##  Description 


The `approveAndCall` function in the Vultisig contract makes an external call to the `receiveApproval` function of the spender contract without verifying the success of the call. Specifically, it does not check the return value of `receiveApproval` or handle any potential errors that may occur during the call. Consequently, even if `receiveApproval` fails (e.g., due to a revert), the `approveAndCall` function will still return true, misleading the caller into believing that the operation was successful.

## Impact

The unchecked external call to `receiveApproval` can result in unexpected behaviors and potential loss of funds. If `receiveApproval` fails, the transaction still returns true, misleading the caller into thinking the operation succeeded. This can lead to downstream issues where subsequent logic depends on the success of `receiveApproval`.

## Recommended Mitigation Steps
Use a try-catch block:
```js
function approveAndCall(address spender, uint256 amount, bytes calldata extraData) external returns (bool) {
    // Approve the spender to spend the tokens
    _approve(msg.sender, spender, amount);

    // Call the receiveApproval function on the spender contract
    try IApproveAndCallReceiver(spender).receiveApproval(msg.sender, amount, address(this), extraData) {
        return true;
    } catch {
        revert("receiveApproval failed");
    }
}
```
