# Vulnerability details

## Impact

The protocol `Vultisig` allows self-whitlisting. The problem here lies that if the project decision was to disable self-whitelisting on launching, users still will be able to whitelist themselves.

The variable `_isSelfWhitelistDisabled`, which is a critical variable that determines the process, is not set on constructor, so its default state will be false. Which will alow anyone to whitelist itself, once the protocol goes to mainnet.

[Whitelist.sol#L65-L74](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L65-L74)
```solidity
    receive() external payable {
        // @audit the variable left undeclared, which will make the check always passed 
@>      if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        // @audit-ok [submitted] `transfer()` instead of `call()`
        payable(_msgSender()).transfer(msg.value);
        // (bool success, ) = payable(_msgSender()).call{value: msg.value}("");
        // require(success, "WhiteList: Transfering ETH back failed");
    }
```

The problem lies that once the project gets launched on mainnet, anyone can whitelist himself before the protocol disables it.

One user can do a punch of transactions whitelisting a lot of his addresses, and the author either will not know, or even in the happy path, if he notices that, he will be forced to disable them one by one (greifying), and add them to the blocklists.

## Proof of Concept
- The protocol decision is to launch disabling self-whitelisting.
- This can only get fired after construction.
- Users wait for the project to get launched.
- Project launched successfully.
- Attackers just whitelisted themselves once the project goes live, and before disabling selfwhitelising (or Front-Running selfwhitelising).
- A lot of addresses escaped the Authorized whitelisting, and in case many addresses get whitelisted, the protocol will pay a lot for blocklisting all of these addresses.

## Recommended Mitigations
Set `_isSelfWhitelistDisabled` variable on construction.

```diff
-   constructor() {
+   constructor(bool isSelfWhitelistDisabled_) {
        _maxAddressCap = 3 ether;
        _locked = true; // Initially, liquidity will be locked
+       _isSelfWhitelistDisabled = isSelfWhitelistDisabled_;
    }
```
