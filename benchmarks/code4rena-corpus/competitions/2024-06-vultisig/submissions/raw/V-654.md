# Vulnerability details

## Impact
As the title suggests, the lack of a rebalance function makes an ILOPool miss out on potential fees from Uniswap.

## Proof of Concept
When an `ILOPool` has launched and added initial liquidity into the pool. A malicious user can make the initial position determined for the pool to move completely out of range, by donating a large amount of RAISE tokens. This would make the current tick move out of the [lower_tick, upper_tick) range that was initially set when the ILOPool was initialised. 

Due to this, the ILOPool would miss out on potential fees from the Uniswap pool when swaps happen in it eventually.

This need not be an attack. Even normal trading/swapping activities can move the position out of range. Hence, losing on potential fees.

All this happens because there is no function to rebalance the position.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a rebalance function to adjust the position.
