# Vulnerability details

## Impact
Not all the raised token (`totalRaised`) can be deposited into Uniswap V3 pool due to precision loss, it's possible that the amount required by Uniswap V3 pool is __1 wei__ less than `totalRaised`, results in project launch fail.

## Proof of Concept
When a ILOPool raised enough amount of raise token, it can be launched after launch time by calling [launch()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L187).

The [launch()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L269C14-L269C22) function in __ILOPool__ contract is then called, which calls [addLiquidity()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/LiquidityManagement.sol#L41) to add liquidity into Uniswap V3 pool.
```
        (amount0, amount1) = params.pool.mint(
            address(this),
            TICK_LOWER,
            TICK_UPPER,
            params.liquidity,
            ""
        );

        require(amount0 >= params.amount0Min && amount1 >= params.amount1Min, 'Price slippage check');
```
The require statement at the end of the function is to ensure that all the raised token are deposited into the pool. 

However, _this check may not pass due to precision loss and the transaction will fail_.

Let's assume a project's `initialPoolPriceX96` is `158456325028528675187087900672`, a ILPool is initialized with `tickLower` is `-887270` and `tickUpper` is `887270`

Say `RAISE_TOKEN` is token1, then `liquidity` is calculated as [below](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/libraries/LiquidityAmounts.sol#L40):
```
    function getLiquidityForAmount1(
        uint160 sqrtRatioAX96,
        uint160 sqrtRatioBX96,
        uint256 amount1
    ) internal pure returns (uint128 liquidity) {
        if (sqrtRatioAX96 > sqrtRatioBX96) (sqrtRatioAX96, sqrtRatioBX96) = (sqrtRatioBX96, sqrtRatioAX96);
        return toUint128(FullMath.mulDiv(amount1, FixedPoint96.Q96, sqrtRatioBX96 - sqrtRatioAX96));
    }
```
That is, `liquidity = raiseAmount * Q96 / (sqrtRatioBX96 - sqrtRatioAX96)`.
Assuming:
> raiseAmount = 1000e18
> sqrtRatioAX96 = 4295558252 (tickLower = -887270)
> sqrtRatioBX96 = 158456325028528675187087900672

Then `liquidity` is `500000000000000000013`.
> liquidity = 1000e18 * Q96 / (158456325028528675187087900672 - 4295558252) = 500000000000000000013

[https://etherscan.io/address/0x1f98431c8ad98523631ae4a59f267346ea31f984#code#F19#L182](https://etherscan.io/address/0x1f98431c8ad98523631ae4a59f267346ea31f984#code#F19#L182)
```
    function getAmount1Delta(
        uint160 sqrtRatioAX96,
        uint160 sqrtRatioBX96,
        uint128 liquidity,
        bool roundUp
    ) internal pure returns (uint256 amount1) {
        if (sqrtRatioAX96 > sqrtRatioBX96) (sqrtRatioAX96, sqrtRatioBX96) = (sqrtRatioBX96, sqrtRatioAX96);

        return
            roundUp
                ? FullMath.mulDivRoundingUp(liquidity, sqrtRatioBX96 - sqrtRatioAX96, FixedPoint96.Q96)
                : FullMath.mulDiv(liquidity, sqrtRatioBX96 - sqrtRatioAX96, FixedPoint96.Q96);
    }
```
That is, `amount1 = liquidity * (sqrtRatioBX96 - sqrtRatioAX96) / Q96`  (roundUp).

Remember we have
> liquidity = 500000000000000000013
> sqrtRatioAX96 = 4295558252 (tickLower = -887270)
> sqrtRatioBX96 = 158456325028528675187087900672

Then `amount1` is `999999999999999999999`
> amount1 = 500000000000000000013 * (158456325028528675187087900672 - 4295558252) / Q96 = 999999999999999999999 (roundUp)

Notice that the `amount1` (999999999999999999999) required by Uniswap V3 pool is 1 wei less than `totalRaised` (1000e18), this means not all the raise tokens can be deposited into the pool and this check will fail:
```
        require(amount0 >= params.amount0Min && amount1 >= params.amount1Min, 'Price slippage check');
```

## Recommended Mitigation Steps
The precision loss happens not every time but under certain circumstances (depending on the tick boundaries and liquidity), because the token amount required by Uniswap V3 pool can be 1 wei less than `totalRaised`, it is recommended to change `amount0Min` and `amount1Min` accordingly when launch the project:
```diff
    function launch() external override OnlyManager() {
            ...

            // calculate sale amount of tokens needed for launching pool
            if (token0Addr == RAISE_TOKEN) {
                amount0 = totalRaised;
-               amount0Min = totalRaised;
+               amount0Min = totalRaised - 1;
                (amount1, liquidity) = _saleAmountNeeded(totalRaised);
            } else {
                (amount0, liquidity) = _saleAmountNeeded(totalRaised);
                amount1 = totalRaised;
-               amount1Min = totalRaised;
+               amount1Min = totalRaised - 1;
            }

            ...
    }
```
