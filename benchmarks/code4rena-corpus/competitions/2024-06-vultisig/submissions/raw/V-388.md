# Vulnerability details

Investors buy shares to raise the pool liquidity and earn fees. This can only happen when the sale is started and not ended:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L134
```solidity
require(block.timestamp > saleInfo.start && block.timestamp < saleInfo.end, "ST");
```
However, the `buy` function does not check if the project has already been launched. This oversight allows for buying even after the project is launched, locking investors' funds in the contract without a way to withdraw them.

## Impact
Investors will lose their assets when buying into an already launched project. Funds will be added to `totalRaised` but won't be recoverable since the project has already been launched and refunds are not possible.

## Proof of Concept 
`buy` only checks if the `recipient` is whitelisted, if the sale is started and not ended, if the `hardCap` is reached, and the `maxSaleAmount`. It does not check if the project has already been launched. This results in the investor's assets being added to `totalRaised` without a way to retrieve them:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L126-L139
```solidity
function buy(uint256 raiseAmount, address recipient)
    external override 
    returns (
        uint256 tokenId,
        uint128 liquidityDelta
    )
{
    require(_isWhitelisted(recipient), "UA");
    require(block.timestamp > saleInfo.start && block.timestamp < saleInfo.end, "ST");
    // check if raise amount over capacity
    require(saleInfo.hardCap - totalRaised >= raiseAmount, "HC");
    totalRaised += raiseAmount;

    require(totalSold() <= saleInfo.maxSaleAmount, "SA");
    // Rest of function logic 
    ...
```

The project can only launch once, setting `_launchSucceeded` to true:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L269-L272

```solidity
function launch() external override OnlyManager() {
    require(!_launchSucceeded, "PL");
    // when refund triggered, we can not launch pool anymore
    require(!_refundTriggered, "IRF");
    ...
    _launchSucceeded = true;
}
```

The investor can't claim a refund either due to the `refundable` modifier, which reverts if `_launchSucceeded` is true:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L337-L347
```solidity
modifier refundable() {
    if (!_refundTriggered) {
        // if ILO pool is launched successfully, we can not refund anymore
        require(!_launchSucceeded, "PL");
        IILOManager.Project memory _project = IILOManager(MANAGER).project(_cachedUniV3PoolAddress);
        require(block.timestamp >= _project.refundDeadline, "RFT");

        _refundTriggered = true;
    }
    _;
}
```

This effectively locks the `totalRaised` amount in the contract.

Manual Review 

## Recommended Mitigation Steps 
Add a check in the `buy` function to ensure the project has not already been launched:

```solidity
require(!_launchSucceeded, "Project already launched");
```
