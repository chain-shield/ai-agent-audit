# Vulnerability details

## Impact
The `ILOManager` contract is deployed once (unlike `ILOPool` which is just implementation).
The contract sets the owner as the `tx.origin` in the constructor, however, a malicious user might frontrun `initialize`, which has no `ownerOnly` modifier, and can be called by anyone, to set a different admin to the contract, which might lead to unexpected results.

## Proof of Concept
The attack could unfold as follows:
1. protocol deploy the ILOManager contract.
2. the original caller will be the new owner of the contract
3. a malicious user will frontrun `initialize` function which does:
```javascript
    function initialize(
@>        address initialOwner,
        address _feeTaker,
        address iloPoolImplementation,
        address uniV3Factory,
        address weth9,
        uint16 platformFee,
        uint16 performanceFee
    ) external override whenNotInitialized {
        PLATFORM_FEE = platformFee;
        PERFORMANCE_FEE = performanceFee;
        FEE_TAKER = _feeTaker;
@>        transferOwnership(initialOwner);
        UNIV3_FACTORY = uniV3Factory;
        ILO_POOL_IMPLEMENTATION = iloPoolImplementation;
        WETH9 = weth9;
    }

```
and will take over the contract ownership.

## Tools Used
Manual review

## Recommended Mitigation Steps
add `onlyOwner` modifier so only the first owner will be able to initialize the contract.

Access Control
