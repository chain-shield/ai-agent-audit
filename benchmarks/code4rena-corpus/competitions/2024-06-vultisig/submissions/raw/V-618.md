# Vulnerability details

## Impact
Initializing an ILO pool after it is cloned in the ILOManager [initILOPool()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L72) function would permanently revert. 

## Proof of Concept

1. This issue occurs in [initILOPool()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L72) when the ILO pool is deployed [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L84).

```solidity
            iloPoolAddress = Clones.cloneDeterministic(ILO_POOL_IMPLEMENTATION, salt);
```

2. During deployment, it runs the constructor which runs the disableInitialize() [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L50). This sets the _initialized state variable to true in the Initializable.sol contract [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/Initializable.sol#L7).

```solidity
    constructor() ERC721('', '') {
        _disableInitialize();
    }
```

3. Now in the same execution context when the call reaches [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L105), it calls the [initialize()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L61) function on the ILO pool contract deployed. The function has the whenNotInitialized() modifier. This requires the initialized state variable [here](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/Initializable.sol#L11) to be false to continue. But since it was set to true in step 2, we revert.

```solidity
    modifier whenNotInitialized() {
        require(!_initialized);
        _;
        _initialized = true;
    }
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider removing the disableInitialize() call from the constructor. Another alternate solution would be to use [afterInitialize()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/Initializable.sol#L15) modifier on function initialize() in the ILOPool.sol contract.
