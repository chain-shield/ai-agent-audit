# Vulnerability details

## Impact
The `Whitelist::checkWhitelist` check intended to validate if an address is whitelisted can be bypassed by using addresses that were not initialized via `Whitelist::_addWhitelistedAddress` function. This allows non whitelisted users to swap VULT tokens from uniswap pool during IDO (after launch).

This can be very problematic as it can reduce VULT token liquidity for legitimate vestors. 



## Proof of Concept

To initialize a whitelist for an address :

```js
    function _addWhitelistedAddress(address whitelisted) private {
        if (_whitelistIndex[whitelisted] == 0) {
            _whitelistIndex[whitelisted] = ++_whitelistCount;
        }
    }
```

The mapping `_whitelistIndex` for an unlisted address defaults to 0. This allows non-whitelisted addresses to pass the whitelist check.

```js
            if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }
```

Non-whitelisted users can swap tokens from uniswap pool reducing the liquidity of the VULT token and increasing it's price. Legitimate vestors will get less VULT tokens as a result.
