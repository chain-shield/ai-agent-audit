# Vulnerability details

## Impact
The `initILOPool()` function creates an `iloPoolAddress` and appends it to the `_initializedILOPools[params.uniV3Pool]` array. When the `launch()` and `claimRefund()` functions are called, they loop through the entire `_initializedILOPools[params.uniV3Pool]` array to launch each pool and claim project refund for each pool respectively. 

If this array grows too large, the gas required to iterate over the array and launch each pool or claim project refund for each pool may exceed the block gas limit causing the transaction to fail.

## Vulnerability Details
As more `ILO` pools are initialized in [initILOPool()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L106), the `_initializedILOPools[params.uniV3Pool]` array grows in size. Each new pool added increases the length of the array.
```solidity
    bytes32 salt = keccak256(abi.encodePacked(
        ChainId.get(),
        params.uniV3Pool,
        _initializedILOPools[params.uniV3Pool].length
    ));
    iloPoolAddress = Clones.cloneDeterministic(ILO_POOL_IMPLEMENTATION, salt); // @audit Pool created
    //...
    _initializedILOPools[params.uniV3Pool].push(iloPoolAddress); //@audit Array grows
```
The [launch()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L191-L195) function then iterates over the entire `_initializedILOPools[params.uniV3Pool]` array.
For each pool in the array, it calls the `launch()` method on the `ILOPool` contract.
```solidity
    address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
    require(initializedPools.length > 0, "NP");
    for (uint256 i = 0; i < initializedPools.length; i++) { // @audit Loop entire array and launch each one
        IILOPool(initializedPools[i]).launch();
    }
```
The [claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L203-L206) function also iterates over the entire `_initializedILOPools[params.uniV3Pool]` array.
```solidity
        address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
        for (uint256 i = 0; i < initializedPools.length; i++) { // @audit Full iteration
            totalRefundAmount += IILOPool(initializedPools[i]).claimProjectRefund(_cachedProject[uniV3PoolAddress].admin);
        }
```

As the array grows, the number of iterations in the loop increases. Each iteration consumes gas, and the total gas required can exceed the block gas limit if the array is too large. This can lead to an Out-of-Gas (OOG) error, causing the transaction to revert.

## Tools Used
Manual Review

## Recommended mitigation steps
Implement batch processing to launch pools/claim project refund in smaller, manageable groups. This reduces the number of iterations per transaction, lowering the gas consumption.
