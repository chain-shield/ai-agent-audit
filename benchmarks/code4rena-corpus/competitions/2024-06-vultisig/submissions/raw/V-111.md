# Vulnerability details

## Impact
The original implementation of UniswapV3 as seen here:
https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol
restricts the deployment to be between version 0.5.0 and 0.8.0; in order to allow under/overflow, however the current version of the library allows deployment with version 0.8.0 and above.
That will impact all calculations that use the library, because their transactions will most likely revert. 


## Proof of Concept

The official documentation enables the calculation to over/underflow, however if we deply the library with solidity version 0.8.0 or higher, that property will break.

Inside the deployment script we can see, that Hardhat configurations are using:
solidity: "0.8.24"
https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat.config.ts#L6
Which will prevent the over/underflow features of the library once deployed. 

This will cause all functions that make calculations and use the library to revert when over/underflow is detected, however this is a desired action implemented by Uniswap, and will cause transactions to revert. 

## Tools Used
Foundry

## Recommended Mitigation Steps
Change the compiler version:

pragma solidity >=0.5.0;

to have an upper version, like originally implemented by UniswapV3

pragma solidity >=0.5.0 <0.8.0;

or use unchecked calculations
