# Vulnerability details

## Impact
The `initILOPool` function is using openzeppelin's cloneDeterministic function that uses create2 opcode to deploy a clone with a giving salt. Unfortunately the salt giving to the function can be determined by an attacker.
The salt was made using chainId, project's  uniswap pool address and the length of already initialized ILOPools as show in below code.
```
bytes32 salt = keccak256(abi.encodePacked(ChainId.get(), params.uniV3Pool, _initializedILOPools[params.uniV3Pool].length));
```

The attacker can read each value from the `ILOManager` contract using web3 as long as he knows its storage slot as shown below.
```
const value = await web3.eth.getStorageAt(CONTRACT_ADDRESS, STORAGE_SLOT);
```
The attack may add 1 to the length of already initialized ILOPools then generate new salt and call the openzeppelin's cloneDeterministic function with the values using his attack contract, Which will make the project owner unable to initiate new ILOPool because the salt was already used by the attacker. Clone can not be deploy at same address twice.

Below is how the attacker's function will look like.
```javascript
function attack(address _iloPoolImplementation ,uint256 _chainId, address _uniV3Pool, uint256 _initializedILOPoolsLength) public returns (address iloPoolAddress) {
   bytes32 salt = keccak256(abi.encodePacked(_chainId, _uniV3Pool, _initializedILOPoolsLength));
   iloPoolAddress = Clones.cloneDeterministic(_iloPoolImplementation, salt);
}
```

## Proof of Concept
Check the below scenario on how the attack can be.
1. A user initiate new project and below project owner. Now we have uniswap pool address.
2. As the project owner he initiate first ILOPool. Now the length of the already initializedILOPools is 1.
3. Attacker reads the storage slots and get the values and makes the attack.
4. The project manager tries to to initiate another ILOPool but the transaction revert because clone can not be deploy at same address twice.

## Recommended Mitigation Steps
Consider using commit-reveal method or add block.timestamp, address(this) and msg.sender to the salt for more security.
