# Vulnerability details

## Impact

The _unlockedLiquidity function in the ILOPool contract could consume excessive gas if there are a large number of vesting schedules, as the number of vesting schedules is unbounded and can be configured to any amount. The combination of iterating through numerous vesting schedules and performing complex calculations to determine withdrawable liquidity could cause transactions to exceed the block gas limit. This would make it impossible for users to withdraw their vested liquidity, effectively locking their funds within the contract in this edge case.

## Proof of Concept
- The _unlockedLiquidity function iterates over the entire vesting schedule array to calculate the unlocked liquidity.

- If the vesting schedule array is large, the gas required for the iteration can exceed the block gas limit.

- This would cause the transaction to revert, preventing users from claiming their vested liquidity.

## Tools Used.
manual review

## Recommended Mitigation Steps
1. Limit the Number of Vesting Schedules: Impose a cap on the number of vesting schedules that can be created per position
2. Paginate Withdrawals: Instead of processing all vested tokens in a single transaction, allow users to withdraw their tokens in multiple smaller transactions.
