# Vulnerability details

## Impact
Bricks the `claimRefund` functionality

## Proof of Concept
`uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;`
This is the line of code that defines the deadline

```
/// @dev when lauch successfully we can not refund anymore
    bool private _launchSucceeded;
```
And per these lines in `ILOPool` we can deduce an invariant that after launch, there should be no refunds.

`require(block.timestamp >= _project.refundDeadline, "RFT");`
`require(_cachedProject[uniV3PoolAddress].refundDeadline < block.timestamp, "RFT");;`

These lines of code enforces the mentioned invariant in both the modifier `refundable` in `ILOPool` and the function `claimRefund` in `ILOManager` respectively.

But from code analysis we can deduce that these require statements don't really enforce the invariant rather they do the opposite because the timestamp will pass the deadline anytime the statement is true and that bricks the refund functionality because 
1) the timestamp has passed the launchtime 
2) the deadline has also been passed therefore making it an ineffective deadline.  


## Tools Used
manual review

## Recommended Mitigation Steps
Implement an effective deadline logic
