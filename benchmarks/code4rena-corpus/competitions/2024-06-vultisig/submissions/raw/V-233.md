# Vulnerability details


## Impact

The `initialize` function of the pool contract fails to properly validate and initialize vesting schedules when the total shares are spread across multiple vesting configurations. This causes the function to revert when the vesting configuration index is greater than 0, making it impossible to initialize the pool as intended. 

1. **Initialization Failure**: The `initialize` function reverts during the validation of the vesting schedules, preventing the pool from being initialized.
2. **Misconfigured Vesting**: The reversion occurs because the `_validateVestSchedule` function incorrectly compares total shares against a fixed value (BPS) rather than considering the total shares across all vesting configurations.
3. **Blocked Pool Setup**: This issue prevents the proper setup and use of the pool, affecting the distribution and vesting of tokens as designed.

2. **_validateSharesAndVests Validation**: During initialization, the contract validates each vesting configuration.


```solidity
  function _validateSharesAndVests(uint64 launchTime, VestingConfig[] memory vestingConfigs) internal pure {
        uint16 totalShares;
        uint16 BPS = 10000;
        for (uint256 i = 0; i < vestingConfigs.length; i++) {
            if (i == 0) {
                require (vestingConfigs[i].recipient == address(0), "VR");
            } else {
                require(vestingConfigs[i].recipient != address(0), "VR");
            }
            // we need to subtract fist in order to avoid int overflow
            require(BPS - totalShares >= vestingConfigs[i].shares, "TS");
            _validateVestSchedule(launchTime, vestingConfigs[i].schedule);
            totalShares += vestingConfigs[i].shares;
        }
        // total shares should be exactly equal BPS
        require(totalShares == BPS, "TS");
    }
```

3. **Vesting Schedule Validation**: The `_validateVestSchedule` function erroneously compares total shares in each schedule to BPS.

```solidity
   function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
       require(schedule[0].start >= launchTime, "VT");
       uint16 BPS = 10000;
       uint16 totalShares;
       uint64 lastEnd;
       uint256 scheduleLength = schedule.length;
       for (uint256 i = 0; i < scheduleLength; i++) {
           require(schedule[i].start >= lastEnd, "VT");
           lastEnd = schedule[i].end;
           require(BPS - totalShares >= schedule[i].shares, "VS");
           totalShares += schedule[i].shares;
       }
       require(totalShares == BPS, "VS");
   }
 ```

 **Reversion**: From the first validation,
 This causes a reversion when total shares in the first configuration

```solidity
       }
       require(totalShares == BPS, "VS");
```

But note the total in index 0 , 1 and 2 will be 10000 and individual vesting shares cannot be equal to BPS.

## Recommended Mitigation Steps

To ensure proper validation and initialization of vesting schedules, update the `_validateVestSchedule` function to correctly validate shares relative to the vesting configuration and adjust the validation logic to prevent reversion.


 **Update `_validateVestSchedule` Function**:

   Modify `_validateVestSchedule` to take in `vestingShares` and compare `totalShares` against it rather than BPS.

   **Proposed Update**:

```solidity
   _validateVestSchedule(launchTime, vestingConfigs[i].shares, vestingConfigs[i].schedule);
```

   ```solidity
   function _validateVestSchedule(uint64 launchTime, uint16 configShares, LinearVest[] memory schedule) internal pure {
       require(schedule.length > 0, "VS"); // Ensure there's at least one schedule
        require(schedule[0].start >= launchTime, "VT");
        uint16 totalShares;
        uint64 lastEnd;
        for (uint256 i = 0; i < schedule.length; i++) {
            require(schedule[i].start >= lastEnd, "VT");
            lastEnd = schedule[i].end;
            require(configShares - totalShares >= schedule[i].shares, "VS");
            totalShares += schedule[i].shares;
        }
        require(totalShares == configShares, "VS"); // Should sum to config's shares, not BPS
    }
   ```
