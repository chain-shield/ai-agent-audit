# Vulnerability details

### Impact

The `ILOPool` constructor invokes the `_disableInitialize` function, which renders the contract uninitializable.

### Proof of Concept

1. The `ILOPool` constructor calls the `_disableInitialize` function, which sets the `_initialized` variable in the `Initializable` contract to true.
   ```solidity
   function _disableInitialize() internal {
       _initialized = true;
   }
   ```

2. When the contract deployer attempts to invoke the `initialize` function, they are unable to do so because the function has a `whenNotInitialized` modifier. This modifier checks if `_initialized` is true and reverts if it is.
   ```solidity
   modifier whenNotInitialized() {
       require(!_initialized);
       _;
       _initialized = true;
   }
   ```

### Tools Used

Manual Review

### Recommended Mitigation Steps

Avoid invoking `_disableInitialize` in the constructor.
