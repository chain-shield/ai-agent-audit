# Vulnerability details

## Impact
The vulnerability in the `Clones.cloneDeterministic` function within `ILOManager::initILOPool`, where the salt is generated using predictable values, poses a significant security risk. The predictability of the salt allows for frontrunning attacks, where a malicious user can use the next salt to create a contract at the same address. This can result in Denial of Service (DoS) and potential loss of funds for the protocol.

## Proof of Concept
Assume a protocol wants to create a new pool. Since the parameters used in the salt are predictable, a malicious user can use the same salt to create a contract at the same address. By using the `IILOManager` interface, they can initialize the contract with their own parameters. This can lead to two main issues:

Critical Issue: If the protocol sends tokens to this contract, a malicious user can, by using the `IILOManager` interface, initialize the contract with their own parameters, taking control of all the tokens sent to the contract. This can be especially valuable if it is not the first pool.
DoS: Since the parameters to create a pool are the same, the protocol will not be able to create any other pool in the future. The function will always revert, causing a Denial of Service.

## Tools Used
Manual review

## Recommended Mitigation Steps
It is recommended to use unpredictable salts, and, when possible to include the constructor arguments withing the salt, so even if a malicious user takeover the contract, it won't be owned by someone else.
