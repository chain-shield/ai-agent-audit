# Vulnerability details

## Impact
first element within vestingConfig would be skipped when lauching pool affecting claiming as recipients within these position in the config would not be minted a tokenId.

## Proof of Concept
when calling `initialize()` on `ILOPool.sol` it initialize vestingConfig starting at the index of zero. The issue is that when lauching pool the index of vestingConfig used starts at one and ends at `index < _vestingConfig.length` the consequence is that the first within vestingConfig would be skipped when lauching pool.
https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L92C9-L94C10
```solidity
// initialize vesting
        for (uint256 index = 0; index < params.vestingConfigs.length; index++) {
            _vestingConfigs.push(params.vestingConfigs[index]);
        }
```
https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L311
```solidity
for (uint256 index = 1; index < _vestingConfigs.length; index++) {
```
with this the first element would be skipped which would affect allocations during claim.
