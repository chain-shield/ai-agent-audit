# Vulnerability details

`ILOManager.sol:initILOPool` is used to initialize an ILO pool. Before it does so, according to one of the devs it checks that liquidity range is "in range" (lower price < initial price < upper price). However that is not the case:
```solidity
        uint160 sqrtRatioLowerX96 = TickMath.getSqrtRatioAtTick(params.tickLower);
        uint160 sqrtRatioUpperX96 = TickMath.getSqrtRatioAtTick(params.tickUpper);
        require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE");
```
It does not check if `_project.initialPoolPriceX96` is less than `sqrtRatioUpperX96`. The ticks from which the `sqrtRatioLowerX96` and `sqrtRatioUpperX96` are derived are project admin input. Project admins are not trusted which means they can set the liquidity to be out of range which can harm the users who buy.

## Impact
The investors won't get their appropriate liquidity assignment which will also affect the fees that they accrue. This can be loss of funds for the investors.

## Proof of Concept
When users call `buy()` they get an amount of liquidity associated with the amount of `RAISE_TOKEN` they give:
```solidity
        // get amount of liquidity associated with raise amount
        if (RAISE_TOKEN == _cachedPoolKey.token0) {
            liquidityDelta = LiquidityAmounts.getLiquidityForAmount0(SQRT_RATIO_X96, SQRT_RATIO_UPPER_X96, raiseAmount);
        } else {
            liquidityDelta = LiquidityAmounts.getLiquidityForAmount1(SQRT_RATIO_LOWER_X96, SQRT_RATIO_X96, raiseAmount);
        }

        require(liquidityDelta > 0, "ZA");

        // calculate amount of share liquidity investor recieve by INVESTOR_SHARES config
        liquidityDelta = uint128(FullMath.mulDiv(liquidityDelta, _vestingConfigs[0].shares, BPS));
        
        // increase investor's liquidity
        _position.liquidity += liquidityDelta;
```
As you can see the sqrt ratios are used to calculate `liquidityDelta` which is then added to the position liquidity of the investor.

The fees that investors accrue from their position are calculated using the position liquidity:
```solidity
            // calculate amount of fees that position generated
            (, uint256 feeGrowthInside0LastX128, uint256 feeGrowthInside1LastX128, , ) = pool.positions(positionKey);
            uint256 fees0 = FullMath.mulDiv(
                                feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
                                positionLiquidity,
                                FixedPoint128.Q128
                            );
            
            uint256 fees1 = FullMath.mulDiv(
                                feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
                                positionLiquidity,
                                FixedPoint128.Q128
                            );
```
Because the `SQRT_RATIO_X96` (initial price) is not between `SQRT_RATIO_LOWER_X96` and `SQRT_RATIO_UPPER_X96` the position that investors are given will be providing liquidity in the wrong range. If no trades are happening in this range they will not accrue any fees from the liqudity provision in the uniswap pool.
```
                                         Where they provide liquidity 
                                                      ↓
SQRT_RATIO_LOWER_X96----------SQRT_RATIO_UPPER_X96----------SQRT_RATIO_X96
```

## Recommended Mitigation Steps
```diff
- require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE");
+ require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && _project.initialPoolPriceX96 < sqrtRatioUpperX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE");
```
