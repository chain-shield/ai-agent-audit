# Vulnerability details

The `claimRefund` function allows users to refund their bought raised tokens. This function can only be called after the refund deadline has passed.

```javascript
require(block.timestamp >= _project.refundDeadline, "RFT");
```

However, once the launch is triggered, the `claimRefund` function is no longer available. During the `initProject`, we ensure that the `refundDeadline` is set appropriately.

```javascript
 function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address   uniV3PoolAddress) {
@>      uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;

        PoolAddress.PoolKey memory poolKey = PoolAddress.getPoolKey(params.saleToken, params.raiseToken, params.fee);
        uniV3PoolAddress = _initUniV3PoolIfNecessary(poolKey, params.initialPoolPriceX96);
        
        _cacheProject(uniV3PoolAddress, params.saleToken, params.raiseToken, params.fee, params.initialPoolPriceX96, params.launchTime, refundDeadline);
        emit ProjectCreated(uniV3PoolAddress, _cachedProject[uniV3PoolAddress]);
    }
```
So the problem is with the `params.launchTime`, which is the designated launch time for any project. Additionally, we add the `DEFAULT_DEADLINE_OFFSET` to the `refundDeadline`. This setup implies that the project will `launch` at that `launchTime` in the ILOPool.sol contract. Since we cannot `claimRefund` before the assigned deadline, we must wait until the `launchTime + DEFAULT_DEADLINE_OFFSET`. However, during this period, the `launch` would have already been triggered in the `ILOPool.sol` contract, and due to this `launch` being triggered, we will not be able to `claimRefund`.

## Impact
User will not able to `claimRefund` anymore.
