# Vulnerability details

## Impact
The `ILOPool::buy` function currently enforces a whitelisting check when an address attempts to buy into a liquidity pool by acquiring an NFT. However, this check can be bypassed by transferring or selling the NFT on secondary markets to non-whitelisted addresses. These non-whitelisted holders can then potentially claim vested tokens, which should have been restricted to whitelisted members only. These addresses can also call the `ILOPool::claimRefund` and completely halt the ILO launch process.

```js
function buy(uint256 raiseAmount, address recipient) external override returns (uint256 tokenId, uint128 liquidityDelta) {
    require(_isWhitelisted(recipient), "UA");
```

```js
    function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
```

## Proof of Concept
Consider the following scenario :
- Alice, who is whitelisted, purchases an NFT tied to specific liquidity within the pool.
- Alice sells or transfers the NFT to Bob, who is not whitelisted.
- Bob, now holding the NFT, engages with the contract to claim VULT token rewards.
- Bob can also if he wants to mess with the project call the `ILOPool::claimRefund` function to block the launch process.
