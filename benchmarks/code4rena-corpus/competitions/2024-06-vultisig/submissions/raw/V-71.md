# Vulnerability details

## Impact

Whitelist.sol allows users to whitelist themselves by sending ETH to the contract. The sent ETH is the attempted to be refunded back to the caller. This is done using the `transfer` function which forward a fixed amount of 2300 gas. However, the gas cost of EVM instructions may change significantly during hard forks which may break already deployed contract systems that make fixed assumptions about gas costs. For example. EIP 1884 broke several existing smart contracts due to a cost increase of the SLOAD instruction. Also, if the sender is a multisig or a contract a lot of which require > 2300 gas to receive ETH, attempts to whitelist by sending ETH will fail as the attempt to return the ETH to the contract/multisig sender will fail due to being out of gas. This will cause loss of funds for sender.

## Proof of Concept

1. Context 

To whitelist, a user has to send ETH to Whitelist.sol through the receive() function. After this is done, the sent ETH is automatically returned back to `_msgSender`. The ETH is sent back through the `transfer` function which forwards 2300 gas. If `_msgSender` is a multisig safe or a contract, 2300 gas might not enough to fully execute the ETH transfer. This can also fail if `_msgSender` implements a payable fallback function that needs less than 2300 gas units but is called through proxy as this also raises the call's gas usage above 2300. Also in case of gas price changes during hardforks and the likes, the gas price for ETH transfer might be increased, rendering the `transfer`'s 2300 fixed gas redundant, completely breaking the functionality.

2. Bug Location

As can be seen from the `receive` function, when self whitelisting is enabled, a user can send ETH to the contract, upon which the `msg.value` sent is attempted to be refunded back to the sender. This will fail for multisigs and contracts that require > 2300 gas.

```solidity
    receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        payable(_msgSender()).transfer(msg.value);
    }
```


3. Final effect

This will lead to a failure to whitelist multisigs and contracts, and potential loss of funds (albeit the amount lost can vary depending on how much `_msgSender` sends which can be as low as 1 wei)
