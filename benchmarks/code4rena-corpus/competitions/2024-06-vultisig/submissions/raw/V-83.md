# Vulnerability details

## Impact
The protocol supports all ERC20 tokens with normal behaviour. This includes `USDC`, `USDT`. However, these tokens have the `blacklist` functionality and therefore, an address would not transfer/receive tokens if it is blacklisted.

As such, since the `claimRefund()` relies on sending the `refundAmount` to the `tokenOwner` directly, this will fail if he is blacklisted resulting in stuck funds.

## Vulnerability details
The [claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L350-L360) sends the `refundAmount` directly to the `tokenOwner` :
```solidity
    function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
        uint256 refundAmount = _positions[tokenId].raiseAmount;
        address tokenOwner = ownerOf(tokenId);
        //...
>>      TransferHelper.safeTransfer(RAISE_TOKEN, tokenOwner, refundAmount); // @audit-issue Direct transfer
        //...
    }
```
As seen, there is no way to specify a receiving address and thus if this address is blacklisted, the `safeTransfer()` will revert.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Allow the function to accept a `recipient` address for the transfer and allow the `refundAmount` to be claimed by the `tokenOwner` himself and not an `approved` user.

```diff
-   function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
+   function claimRefund(uint256 tokenId, address to) external override refundable() {
        uint256 refundAmount = _positions[tokenId].raiseAmount;
        address tokenOwner = ownerOf(tokenId);
+       require(msg.sender == tokenOwner, "Caller not owner");
        //...
-       TransferHelper.safeTransfer(RAISE_TOKEN, tokenOwner, refundAmount);
+       TransferHelper.safeTransfer(RAISE_TOKEN, to, refundAmount);
        //...
    }
```
