# Vulnerability details

## Impact
In `ILOManager::initProject` the solidity version of the contract is =0.7.6 which does NOT support automatic overflow/underflow protection as all the versions >=0.8.x do support.

```solidity
    uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;
```

 The `params.launchTime` field is of type `uint64` and by providing large enough number when we add up params.launchTime and `DEFAULT_DEADLINE_OFFSET` the `refundDeadline` overflows resulting in totally incorrect refundDeadline.

## Proof of Concept

1. Call the external function `ILOManager::initProject` after the project was initialized with a value great enough to an overflow occurs, for instance:

Max value of uint64     = 18,446,744,073,709,551,615
DEFAULT_DEADLINE_OFFSET = 7 * 24 * 60 * 60 = 604,800

18,446,744,073,709,551,615 - 604,800 = 18,446,744,073,708,946,815

By passing as argument `launchTime` = (18,446,744,073,708,946,815 + 2) the refundDeadline overflows and the launchTime becomes 1

## Tools Used
Solidity, Foundry

## Recommended Mitigation Steps

Two good options to fix this incorrect behavior are the following:

1. Use higher solidity version which is >= 0.8.0 because the overflow/underflow protection is automatically integrated in solidity and there is no need to explicitly use an external library or additing manual logic to protect from overflows/underflows.

2. Use Openzeppelin SafeMath library to add the two variables 
Reference: https://github.com/ConsenSysMesh/openzeppelin-solidity/blob/master/contracts/math/SafeMath.sol
