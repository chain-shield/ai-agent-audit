# Vulnerability details

## Impact
In ILOManager.sol can be found initILOPool() that can be called from onlyProjectAdmin. This function is responsible for initialization of pools. We can see that there is a require that says ``` require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE"); ``` .This require can be bypassed by a pool which initial price is far more bigger than the lower tick and higher tick. In this case the pool will be invalid. As an impact since the price is outside the tick range, there will be no active liquidity available at the current price. This means that any swap attempts at this price will fail as there is no liquidity for the trade. Also the mentioned invariant from the sponsor: ``Once project inits, it inits a uniswap v3 pool. That pool address will be used as project id. You cannot change initial price after project is initialized``- means that liquidity will be temporary locked until the price goes to the expected tick ratio.

## Recommended Mitigation Steps
Update the require in order to not make it impossible to initialize invalid pool. For example:
```
require (sqrtRatioLowerX96 < _project.initialPoolPriceX96 && _project.initialPoolPriceX96 < sqrtRatioUpperX96 &&
 sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE");
```
