# Vulnerability details

## Impact
When another user opens a buy position for a given `recipient`, the `raiseAmount` is transferred from the user's account to the contract. However, when `claimRefund()` is called, all raise tokens are sent to the `recipient` i.e `tokenOwner`, not the user who supplied them.

## Vulnerability Details
In [buy()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L172-L173) the `raiseAmount` is transferred from the user's account (`msg.sender`) to the contract.
```solidity
        // transfer fund into contract
        TransferHelper.safeTransferFrom(RAISE_TOKEN, msg.sender, address(this), raiseAmount);
```
However, in [claimRefund()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L358), the refund amount is sent to the token owner (`recipient`), not the original user who supplied the `raiseAmount`.
```solidity
function claimRefund(uint256 tokenId) external override refundable() isAuthorizedForToken(tokenId) {
    uint256 refundAmount = _positions[tokenId].raiseAmount;
    address tokenOwner = ownerOf(tokenId);

    delete _positions[tokenId];
    delete _positionVests[tokenId];
    _burn(tokenId);

>>  TransferHelper.safeTransfer(RAISE_TOKEN, tokenOwner, refundAmount);
    emit UserRefund(tokenOwner, tokenId, refundAmount);
}
```
As such, the user who initially supplied the `raiseAmount` does not receive the refund.

## Tools Used
Manual Review

## Recommended mitigation steps
Track the original user who supplied the `raiseAmount` and ensure the refund is sent to them.
