# Vulnerability details

## Impact
The current implementation of the ILOPool contract prevents the initialize function from ever being called. This is due to the _disableInitialize() function being called in the constructor, which sets the _initialized flag to true during contract deployment.
```
  function _disableInitialize() internal {
        _initialized = true;
    }
```
As a result, the whenNotInitialized modifier will always fail because the modifier requires _initialized to be false to proceed.
```
modifier whenNotInitialized() {
        require(!_initialized);
        _;
        _initialized = true;
    }
```
making the initialize function unusable. This renders the contract unable to be properly initialized and configured, potentially leading to a complete failure of the contract's intended functionality.

## Proof of Concept
- The constructor calls _disableInitialize() during contract deployment setting _initialized to true.

- The whenNotInitialized modifier requires _initialized to be false to execute the initialize function.

- Since _initialized is set to true in the constructor, the initialize function will always fail the require(!_initialized) check during a post deployment call

## Tools Used
Manual

## Recommended Mitigation Steps
Remove _disableInitialize() from the constructor.
