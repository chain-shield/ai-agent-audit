# Vulnerability details

`VultisigWhitelisted.sol` implements a `_beforeTokenTransfer()` hook:
```solidity
    function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
            IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }
```
As you can see after the if statement it calls `super._beforeTokenTransfer()`. The issue is that this line will not actually do anything because of a missing override.

## Impact
Because `_beforeTokenTransfer()` implementation does not do anything except some checks with `checkWhitelist()` it cannot be used as a hook. It does not do any token transfers and it is not called before any.

## Proof of Concept
The super keyword is used to call `_beforeTokenTransfer()` that is implemented in one of the contracts that `VultisigWhitelisted` inherits from. `VultisigWhitelisted` inherits only from `Vultisig` but this contract does not have `_beforeTokenTransfer()` so we look at its parents which are `ERC20` and `Ownable`. `ERC20.sol` does have the function but its virtual and with no implementation:
```solidity
function _beforeTokenTransfer(address from, address to, uint256 amount) internal virtual { }
```
This means that `super._beforeTokenTransfer(from, to, amount);` will not do anything.

## Recommended Mitigation Steps
`Vultisig.sol` should override the `_beforeTokenTransfer()` from `ERC20.sol` and have its own implementation.
```solidity
contract Vultisig is ERC20, Ownable {
...
function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
      //code
  }
}
```

It is also possible that `super` was intended to call `transferFrom()` instead:
```
super.transferFrom(from, to, amount);
```
