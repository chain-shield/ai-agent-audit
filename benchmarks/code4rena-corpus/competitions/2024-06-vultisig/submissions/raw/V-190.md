# Vulnerability details

## Description:

The `launch` function in the `ILOManager` contract relies on the `slot0()` function from Uniswap V3 to obtain the `sqrtPriceX96` value and then compares it to a stored value using a strict `require` statement. The strict equality check (`require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P")`) can cause the function to revert frequently due to minor price variations, even in the absence of malicious activities. These minor variations can result from regular market movements or slight timing differences, causing valid project launches to fail unexpectedly.

## Impact:

The strict constraint in the `require` statement leads to frequent reversion of the `launch` function, hindering the deployment of valid projects. This can result in delays, increased transaction costs, and frustration among project stakeholders. Moreover, it undermines the reliability and usability of the contract, potentially reducing user confidence in the platform.

## Recommended Mitigation:

To mitigate this issue, consider implementing a tolerance range for the price comparison instead of a strict equality check. This approach allows for minor variations in the price without causing the function to revert, thereby increasing the robustness and reliability of the launch process.
