# Vulnerability details

## Impact
The `ILOManager` contract allows project admins control over the parameters of an `ILOPool`, including the ability to specify recipient addresses and the distribution of shares in the `vestingConfigs` struct. A bad actor can choose parameters that only rewards the admin by creating scam projects.

## Proof of Concept
The `vestingConfigs` struct can be intiated like this :

```js
        vestingConfigs = new IILOVest.VestingConfig[](4);
        vestingConfigs[0] = IILOVest.VestingConfig({
                    shares: 2000, // 20%
                    recipient: address(0),
                    schedule: _getLinearVesting()
            });
        vestingConfigs[1] = IILOVest.VestingConfig({
                    shares: 3000, // 30%
                    recipient: TREASURY_RECIPIENT,
                    schedule: _getLinearVesting()
            });
        vestingConfigs[2] = IILOVest.VestingConfig({
                    shares: 2000, // 20%
                    recipient: DEV_RECIPIENT,
                    schedule: _getLinearVesting()
            });
        vestingConfigs[3] = IILOVest.VestingConfig({
                    shares: 3000, // 30%
                    recipient: LIQUIDITY_RECIPIENT,
                    schedule: _getLinearVesting()
            });
    }

```

A malicious admin can choose the recipients of all the element fo the array as his address. By doing this, legitimate vestors will not be able to claim anything and all the vested amounts will go to him. Since anybody can become a project admin and create an `ILOPool`, nothing is stoping these "scam" pools from being created.

## Tools Used

Manual review

## Recommended Mitigation Steps

You can consider either of the following changes :
- Add a whitelist of trusted project admin addresses
- Hardcode some parameters that cannot be changed by the manager.
