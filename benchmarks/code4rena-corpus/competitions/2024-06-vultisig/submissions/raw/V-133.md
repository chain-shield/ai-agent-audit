# Vulnerability details

## Impact
The `lunch` function of ILOManager requires that the initialPoolPriceX96 which was used to create and initialize the uniswap pool most be equal to the current pool's squarePriceX96 which can be changed when some one add liquidity to the pool. An attacker can add single-sided liquidity to the pool that will change the squarePriceX96 of the pool using other means in order to make the `launch` function always fail.

The line where the vulnerability is was indicated using @> in the below code.
```javascript
function launch(address uniV3PoolAddress) external override {
   require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
   (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
@> require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
   address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
   require(initializedPools.length > 0, "NP");
   for (uint256 i = 0; i < initializedPools.length; i++) {
     IILOPool(initializedPools[i]).launch();
   }

   emit ProjectLaunch(uniV3PoolAddress);
```

## Proof of Concept
Below points decscribes how the attack can be made.
1. Project owner initiate a new project using correct parameters.
2. While initiating the new project uniswap pool was created and initialized, Its address saved in Project.uniV3PoolAddress struct.
3. An attacker can read the address from the struct field.
4. The attacker add single-sided liquidity to the pool that made changes to the squarePriceX96 value.
5. Now the project can not be launched due to the said require check in the `launch` function.

## Recommended Mitigation Steps
Its better to subtract squarePriceX96 return by slot0 from the initialPoolPriceX96 then use the result to calculate the tokens amount and liquidity.
