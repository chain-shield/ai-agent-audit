# Vulnerability details

## Impact
The issue here is that the FullMath.sol library, imported from UniswapV3 allows to be build with solidity v0.8.x, which has under/overflow protection. 
The library, however, makes use of these by design, so it won't work properly when compiled in v0.8.0 or later.

## Proof of Concept
The official library can be found here:
https://github.com/Uniswap/v3-core/blob/main/contracts/libraries/FullMath.sol

However it is specifically designed to allow under/overflow conditions, unlike the current version used by the protocol, it allows to be deployed with solidity 0.8.0 and above. This can prevent some of the calculations to revert.

Inside the deployment script we can see, that Hardhat conigurations are using:
solidity: "0.8.24"
https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat.config.ts#L6
Which will prevent the over/underflow features of the library once deployed. 

## Tools Used
Foundry

## Recommended Mitigation Steps
Change the compiler version:

pragma solidity >=0.4.0;

to have an upper version, like originally implemented by UniswapV3

pragma solidity >=0.4.0 <0.8.0;
