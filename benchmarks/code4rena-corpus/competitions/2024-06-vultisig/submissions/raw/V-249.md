# Vulnerability details

## Impact
The absence of encoded callback data in the mint function call within the addLiquidity function can lead to unauthorized Access to Liquidity, It should contain very important values like the `poolKey`, omitting this data might allow liquidity to be added without proper payment and validation. This could result in unauthorized access to liquidity and potential financial losses for the protocol.

Without the `callback` data, the mint function may not be able to verify that the correct payment has been made, allowing an attacker to add liquidity without transferring the necessary required tokens.

## Proof of Concept
The `addLiquidity` function currently calls the mint function without passing any encoded data

```javascript
 (amount0, amount1) = params.pool.mint(
        address(this),
        TICK_LOWER,
        TICK_UPPER,
        params.liquidity,
        ""
    );
```
the mint function call includes an empty byte string ("") for the callback data,  skipping critical payment handling and verification steps.

## Tools Used
Manual Review

## Recommended Mitigation Steps
update the addLiquidity function to include necessary encoded data in the mint function call. This ensures that all required operations, including payment verification and state updates, are correctly performed.

```javascript
struct MintCallbackData {
    bytes32 poolKey;
    address payer;
}
```

```javascript
 MintCallbackData memory callbackData = MintCallbackData({
        poolKey: keccak256(abi.encodePacked(address(params.pool), TICK_LOWER, TICK_UPPER)),
        payer: msg.sender
    });

    (amount0, amount1) = params.pool.mint(
        address(this),
        TICK_LOWER,
        TICK_UPPER,
        params.liquidity,
        abi.encode(callbackData)
    );
```
