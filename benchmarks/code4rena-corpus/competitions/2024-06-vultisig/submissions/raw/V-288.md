# Vulnerability details

The buy function in the ILOPool.sol contract is responsible for opening a position for the recipient by providing the raiseAmount, which is ultimately transferred into the contract. However, the function does not validate that raiseAmount should not be zero.

 TransferHelper.safeTransferFrom(RAISE_TOKEN, msg.sender, address(this), raiseAmount);
Any (all possible ERC20s) that complies with ERC20 token behaviors in scope

And casue the protocol intended to use all ERC20 tokens. So the problem is here that some ERC20 tokens (e.g. LEND) do not allow zero value transfers, reverting such attempts.

Impact
Some ERC20 tokens do not allow zero value transfers, reverting such attempts.
