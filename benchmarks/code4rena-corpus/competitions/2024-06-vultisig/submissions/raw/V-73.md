# Vulnerability details

## Impact
Since 2019 the recommended way to . The ETH transfer using `transfer()` in the `Whitelist::receive()` function will fail if the `msg.sender` is a smart contract with no fallback functionality, if it implements a fallback function using more than 2300 gas units or uses less than 2300 gas but is called through proxy, raising call's gas usage above 2300. 
## Proof of Concept
Read more about the deprecated usage of the `transfer()` function [here](https://solidity-by-example.org/sending-ether/).
## Tools Used
Manual review, Hardhat
## Recommended Mitigation Steps
Use `call()` instead of `transfer()`, reentrancy protection is unnecessary, because whitelisted address cannot be added to the whitelist more than once, so reentering the `receive()` function would simply increase the gas cost for the caller with no upside.
