# Vulnerability details

## Impact
When the whitelisted contract is set in `VultisigWhitelisted` contract and `_allowedWhitelistIndex` is set in the `Whitelist` contract to at least 1 or above, if tokens are sent to a non-whitelisted `to` address it doesn’t revert with error `NotWhitelisted()`.

## Proof of Concept
[TestShowingNonWhitelistedAddressRecievingTokens](https://github.com/c-n-o-t-e/2024-06-vultisig-audit/blob/main/hardhat-vultisig/test/unit/VultisigWhitelisted.ts#L65)


## Tools Used
Hardhat

## Recommended Mitigation Steps
In the third if statement in `checkWhitelist()` an additional check should be added that checks if `to` address is used as a key in `_whitelistIndex` mapping returns 0 it should revert as shown below.

```
 if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
    revert NotWhitelisted();
 }
```
