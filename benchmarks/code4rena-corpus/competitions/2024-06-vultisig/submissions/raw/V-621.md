# Vulnerability details

### **Finding Description**
The `initProject` is used to initialize a new project including all the details contained in the `InitProjectParams` such as the `saleToken` and the `raiseToken`.
The `saleToken` is an invariant which is meant to be always fixed as it is the core token of the protocol which is used to be used for vesting. 

<details><summary>Details</summary>

```solidity
    function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address uniV3PoolAddress) {
        uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;
        //@audit no sanity check to ensure users dont specify a different saleToken()
        PoolAddress.PoolKey memory poolKey = PoolAddress.getPoolKey(params.saleToken, params.raiseToken, params.fee);
        uniV3PoolAddress = _initUniV3PoolIfNecessary(poolKey, params.initialPoolPriceX96);
        
        _cacheProject(uniV3PoolAddress, params.saleToken, params.raiseToken, params.fee, params.initialPoolPriceX96, params.launchTime, refundDeadline);
        emit ProjectCreated(uniV3PoolAddress, _cachedProject[uniV3PoolAddress]);
    }
```

</details>

According to the documentation, the pool pairs are meant to be in the form of ERC20/Vaultsig which consist of a `raiseToken` and a `saleToken`. However, this invariant does'nt hold when a user specifies a totally different `saleToken` pair such as USDT/USDC etc.


### Impact Summary
This breaks the protocol invariant and logic

### Severity Explanation
This is Medium as this vulnerability breaks the protocol logic.

## **Recommendation**

Add a sanity check to ensure that users specify the correct salesToken otherwise should revert

- After declaring the VaultSig token address, add the below check;

```diff
function initProject(InitProjectParams calldata params) external override afterInitialize() returns(address uniV3PoolAddress) {
        uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;
+        require(params.saleToken == vaultSig, "incorrect saleToken")
```
