# Vulnerability details

## Impact
The current `_validateVestSchedule()` function does not check if `schedule[i].end` is in the future relative to the current `block.timestamp`. This can lead to potential issues where `vesting schedules` have end times in the past.

## Proof of Concept
The [_validateVestSchedule()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/base/ILOVest.sol#L35-L51) function currently performs several checks:
```solidity
function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
        require(schedule[0].start >= launchTime, "VT");
        //...
        uint256 scheduleLength = schedule.length;
        for (uint256 i = 0; i < scheduleLength; i++) {
            // vesting schedule must not overlap
            require(schedule[i].start >= lastEnd, "VT");
            lastEnd = schedule[i].end;
            //...
        }
        //...
    }
```
- Ensures the first schedule's `startTime` is greater than or equal to the `launchTime`.
- Ensures that each schedule's `startTime` is greater than or equal to the `endTime` of the previous schedule.

However, it does not check if the `endTime` of each schedule is in the future relative to the current `block.timestamp`.

### Past Vesting Schedules:
Issue: Schedules can have end times in the past.
---> Impact: This could lead to immediate vesting or vesting that has already completed, which might not be the intended behavior.

**Example Scenario**
Imagine a vesting schedule where:
- `schedule[0].start` = 1620000000 (a past timestamp)
- `schedule[0].end` = 1620003600 (also a past timestamp)

**Without the check**:
--> This schedule would be considered valid.
--> The vesting would be considered complete immediately, allowing the recipient to claim the vested tokens/liquidity right away.

## Recommended Mitigation Steps
Update `_validateVestSchedule()` to ensure `schedule[i].end` is in the future:
```diff
    function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
        require(schedule[0].start >= launchTime, "VT");
        //...
        uint256 scheduleLength = schedule.length;
        for (uint256 i = 0; i < scheduleLength; i++) {
            // vesting schedule must not overlap
            require(schedule[i].start >= lastEnd, "VT");
            lastEnd = schedule[i].end;
+           // Ensure end time is in the future
+           require(schedule[i].end > block.timestamp, "End time must be in the future");
            //...
        }
        //...
    }
```
