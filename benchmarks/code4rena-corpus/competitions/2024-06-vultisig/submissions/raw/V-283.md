# Vulnerability details

# Summary
The `Whitelist` contract implements mechanism to allow whitelisted addresses to buy `VULT` token from uniswap pool. The rules are ordered as follows:

1. Prevent blacklisted addresses
2. If the address is not blacklisted, only allow if it is whitelisted

Point `1` is addressed correctly. But for point `2`, the checking is using indexing where the whitelisted address will contain index less than `_allowedWhitelistIndex`. The problem is solidity assume the value of `_whitelistIndex[to]` is equal to 0 by default making the `_whitelistIndex[to] > _allowedWhitelistIndex` test evaluated to false so that any address which is not registered in `_whitelistIndex` will pass the check.

## Example case
There are three addresses: A, B and C and assume the contract is not locked and the expression `(from == _pool && to != owner())` is true.

First, register the address A and B to whitelist:

`whitelist.addBatchWhitelist([A, B])`

The `_whitelistIndex` map will be updated to:

```
_whitelistIndex[A] = 1
_whitelistIndex[B] = 2
```

Second, call `whitelist.setAllowedWhitelistIndex(1)` to allow whitelisted address with index up to `1`.

The value of `_allowedWhitelistIndex` state becomes `1`

Now, if we call `whitelist.checkWhitelist(pool, A, amount)` will succeed because address A is in `_allowedWhitelistIndex` range.

If we call `whitelist.checkWhitelist(pool, B, amount)`, the function will revert because the index of B is not in `_allowedWhitelistIndex` range.

Now if we call `whitelist.checkWhitelist(pool, C, amount)`, since we never blacklist and never register address C in whitelist, it must not pass because it is not in whitelist. But something doesn't work as expected, the expression `_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex` in if statement will be evaluated to `false` making the if statement will not be executed.

```
_allowedWhitelistIndex == 0 => 1 == 0 => false

_whitelistIndex[C] > _allowedWhitelistIndex
_whitelistIndex[C] equals to 0 by default
0 > 1 => false

so that, false || false => false
```

The address C successfully pass the `checkWhitelist()`

# Impact
Whitelist mechanism is broken, allowing any address which is not registered in `_whitelistIndex` to buy `VULT` token from uniswap pool as long as it is not in the blacklist.

# Proof of Concept
Here is the PoC:

Add the following code to unit testing in `hardhat-vultisig/test/unit/Whitelist.ts`
```typescript
describe("Whitelist", function () {
    ...
    describe("Checkwhitelist", function () {
        ...
        it("Will always allow the non whitelisted address to pass the `checkWhitelist()` check", async function () {
            const { whitelist, pool, otherAccount, batchedAccount, mockContract, mockOracleSuccess } = await loadFixture(deployWhitelistFixture);

            // emulate the whitelist
            await whitelist.setVultisig(mockContract);
            await whitelist.setOracle(mockOracleSuccess);
            await whitelist.setPool(pool);
            await whitelist.setLocked(false);

            // create instance of arbitrary address
            let addr = ethers.Wallet.createRandom();
            while ((addr.address == otherAccount.address) || (addr.address == batchedAccount.address)) {
                addr = ethers.Wallet.createRandom();
            }

            // add otherAccount and batchedAccount to the whitelist
            await whitelist.addBatchWhitelist([otherAccount, batchedAccount]);
            // allow only 1 address (otherAccount)
            await whitelist.setAllowedWhitelistIndex(1);

            // the otherAccount is allowed
            await expect(
                whitelist.connect(mockContract).checkWhitelist(pool, otherAccount, 0),
            ).not.to.be.reverted;

            // the batchedAccount will revert with `NonWhitelisted` because the batchedAccount index greater than `_allowedWhitelistIndex`.
            await expect(
                whitelist.connect(mockContract).checkWhitelist(pool, batchedAccount, 0),
            ).to.be.revertedWithCustomError(whitelist, "NotWhitelisted");

            // but arbitrary address doesn't revert as long as it is not blacklisted!
            await expect(
                whitelist.connect(mockContract).checkWhitelist(pool, addr, 0),
            ).not.to.be.reverted;

        });
    });
});

```

Run the test:
> $ npx hardhat test hardhat-vultisig/test/unit/Whitelist.ts

The test will pass. The `addr` will pass the `checkWhitelist()` beacause no revert operation is emitted.

# Recommended Mitigation
Add `_whitelistIndex[to] == 0` test to whitelist check to make sure non whitelisted address doesn't pass the check:

```diff
function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
    if (from == _pool && to != owner()) {
        // We only add limitations for buy actions via uniswap v3 pool
        // Still need to ignore WL check if it's owner related actions
        if (_locked) {
            revert Locked();
        }

        if (_isBlacklisted[to]) {
            revert Blacklisted();
        }

-        if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
+        if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex || _whitelistIndex[to] == 0) {
            revert NotWhitelisted();
        }

        // // Calculate rough ETH amount for VULT amount
        uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
        if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
            revert MaxAddressCapOverflow();
        }

        _contributed[to] += estimatedETHAmount;
    }
}

```
