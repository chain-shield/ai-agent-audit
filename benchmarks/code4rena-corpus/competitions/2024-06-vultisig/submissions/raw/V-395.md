# Vulnerability details

## Impact
A user that is not whitelisted may buy a liquidity position, if the admin introduces the whitelist after the start of the sale.
Imagine a scenario where there is initially no whitelist enabled. A user buys a liquidity position, and subsequently, the admin introduces a whitelist that does not include the buyer. There is no possibility for the admin to remove the buyer from the sale.

## Proof of Concept
The `ILOWhitelist::setOpenToAll` function does not check whether the sale has already started. Additionally, there is no mechanism to blacklist a buyer who purchased a liquidity position before the whitelist was implemented. See the following test that simulates the above-mentioned scenario:
```solidity
function testWhitelistAfterSaleStart() external {
    // disable whitelist
    vm.prank(PROJECT_OWNER);
    IILOWhitelist(iloPool).setOpenToAll(true);
    assertTrue(IILOWhitelist(iloPool).isOpenToAll());

    // buy position
    vm.prank(INVESTOR);
    IERC20(USDC).approve(iloPool, 1000000000 ether);
    _writeTokenBalance(USDC, INVESTOR, 1000000000 ether);
    _buy(SALE_START+1, 0.1 ether);
    
    // enable whitelist
    vm.startPrank(PROJECT_OWNER);
    IILOWhitelist(iloPool).setOpenToAll(false);

    // no way of removing `INVESTOR` from the sale
    assertFalse(IILOWhitelist(iloPool).isWhitelisted(INVESTOR));
    assertGt(IILOPool(iloPool).balanceOf(INVESTOR), 0);
}
```

## Tools Used
Manual review, foundry test

## Recommended Mitigation Steps
Check that the sale didn't start before toggling the whitelist 
```
function setOpenToAll(bool openToAll) external override onlyProjectAdmin{
    require(block.timestamp < saleInfo.start);
    _setOpenToAll(openToAll);
}
```
