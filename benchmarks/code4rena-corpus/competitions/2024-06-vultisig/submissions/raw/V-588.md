# Vulnerability details

## Impact
Inside the [`checkwhitelist()`](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L204) function in the Whitelist.sol contract, if the token transfer's `from == uniV3Pool` then it validates if the user's contributed amount of ETH to buy the Vultisig token is under the `_maxAddressCap`.

But in case a user adds liquidity to the same pool after buying the tokens and using their allowed buying limit to maximum, they will face an error when withdrawing the liquidity.

The user will have to wait till the [_whitelistContract](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/extensions/VultisigWhitelisted.sol#L23) is set to address(0) in the Vultisig token contract.

## Proof of Concept
1. Alice **buys the Vultisig token** from the uniswap pools for 3 ETH, i.e. they exhausted their allowed limit.
2. Alice **adds liquidity** to the same uniswap pool for the whole range, depositing ETH & Vultisig both.
3. Now they try to withdraw their added liquidity, but it fails with error [`MaxAddressCapOverflow`](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/hardhat-vultisig/contracts/Whitelist.sol#L223) because no more transfer of Vultisig token from pool to user is allowed.

Differentiate between liquidity withdrawals and token buy transactions.
