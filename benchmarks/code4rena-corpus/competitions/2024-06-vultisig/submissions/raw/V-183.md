# Vulnerability details

## Impact

The claim function in the contract does not verify whether the recipient (owner of the token ID) is blacklisted before transferring tokens. This omission can lead to transaction failures if the recipient is blacklisted, particularly when dealing with tokens like USDC that enforce blacklist policies. This can disrupt the claiming process and prevent legitimate users from accessing their tokens.

## Proof of Concept
Function Definition:

```javascript
TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amount0); 
TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amount1);
```
Risk Scenario:

Suppose ownerOf(tokenId) is a blacklisted address.
The transfer of USDC (or any token with a blacklist mechanism) will fail.
This failure will revert the entire claim transaction, blocking the legitimate claiming process.

## Recommendation
To prevent transaction failures due to blacklist policies, the claim function should include a check to check if the recipient is blacklisted before attempting the transfer.

OR allow the owner to add an `address _to` where the funds should be sent instead of sending directly to `ownerOf(tokenId)`
