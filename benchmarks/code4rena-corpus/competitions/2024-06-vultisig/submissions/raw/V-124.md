# Vulnerability details



## Impact
DOS. The pausing of tokens like USDC can block critical liquidity management functions causing failed transactions and disrupted operations. This can affect the `buy`, `claim`, and `launch` functionalities, potentially halting the entire workflow of the ILOPool. 

## Proof of Concept

### `buy` Function
The `buy` function involves transferring tokens to the contract and calculating liquidity based on the raised amount. If the token is paused, the transfer will fail, and the liquidity calculation will not proceed.
https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L173

```solidity
function buy(uint256 raiseAmount, address recipient)
    external override 
    returns (
        uint256 tokenId,
        uint128 liquidityDelta
    )
{
    // ... other code ...

    // transfer fund into contract
    TransferHelper.safeTransferFrom(RAISE_TOKEN, msg.sender, address(this), raiseAmount);

    emit Buy(recipient, tokenId, raiseAmount, liquidityDelta);
}
```
This function will fail if `RAISE_TOKEN` is USDC or USDT is paused because `TransferHelper.safeTransferFrom` will revert. This prevents users from participating in the ILO by buying tokens.

### `claim` Function
The `claim` function involves burning liquidity from the Uniswap V3 pool and transferring the resulting tokens to the user. If the token is paused, the transfer will fail, and the user will not receive their tokens.

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L259-L260

```solidity
function claim(uint256 tokenId)
    external
    payable
    override
    isAuthorizedForToken(tokenId)
    returns (uint256 amount0, uint256 amount1)
{
    // ... other code ...

    // transfer token for user
    TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amount0);
    TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amount1);

    emit Claim(ownerOf(tokenId), tokenId,liquidity2Claim, amount0, amount1, position.feeGrowthInside0LastX128, position.feeGrowthInside1LastX128);

    address feeTaker = IILOManager(MANAGER).FEE_TAKER();
    // transfer fee to fee taker
    TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
    TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);
}
```

This function will fail if `_cachedPoolKey.token0` or `_cachedPoolKey.token1` is paused because `TransferHelper.safeTransfer` will revert. This prevents users from claiming their tokens and liquidity.

### `launch` Function
The `launch` function takes care of adding liquidity to the Uniswap V3 pool. If the token is paused, the transfer of tokens to the pool will fail, and the liquidity addition will not proceed.

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L269-L347

```solidity

    // ... other code ...

    // actually deploy liquidity to uniswap pool
    (amount0, amount1) = addLiquidity(AddLiquidityParams({
        pool: IUniswapV3Pool(uniV3PoolAddress),
        liquidity: liquidity,
        amount0Desired: amount0,
        amount1Desired: amount1,
        amount0Min: amount0Min,

    }));

```
This will also fail if the tokens involved are paused because the transfer of tokens to the Uniswap pool will revert. This prevents the ILO from successfully launching and adding liquidity to the pool.

## Recommended Mitigation Step
Implement checks to ensure that the token is not paused before attempting any transfer, approval, or liquidity operation. Additionally, consider adding fallback mechanisms to handle paused tokens, such as queuing transactions.
