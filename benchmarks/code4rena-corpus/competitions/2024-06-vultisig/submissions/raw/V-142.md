# Vulnerability details

## Vulnerability details
When an investor claim his liquidity using ILOPool::claim(), which internally calls  _unlockedLiquidity(). This _unlockedLiquidity() returns amount of unlocked liquidity by looping over the vestingSchedule
```solidity
 function _unlockedLiquidity(uint256 tokenId) internal view override returns (uint128 liquidityUnlocked) {
        PositionVest storage _positionVest = _positionVests[tokenId];
        LinearVest[] storage vestingSchedule = _positionVest.schedule;
        uint128 totalLiquidity = _positionVest.totalLiquidity;

       @> for (uint256 index = 0; index < vestingSchedule.length; index++) {

            LinearVest storage vest = vestingSchedule[index];

            // if vest is not started, skip this vest and all following vest
         @>   if (block.timestamp < vest.start) {
                break;
            }

            // if vest already end, all the shares are unlocked
            // otherwise we calculate shares of unlocked times and get the unlocked share number
            // all vest after current unlocking vest is ignored
            if (vest.end < block.timestamp) {
                liquidityUnlocked += uint128(FullMath.mulDiv(
                    vest.shares, 
                    totalLiquidity, 
                    BPS
                ));
            } else {
                liquidityUnlocked += uint128(FullMath.mulDiv(
                    vest.shares * totalLiquidity, 
                    block.timestamp - vest.start, 
                    (vest.end - vest.start) * BPS
                ));
            }
        }
    }
```
While looping over vestingSchedule, it checks vest.start is greater than block.timestamp or not, if not then it terminates the whole loop. Now this is problem because if any vest that started earlier but is later or at last in the LinearVest[] array, will not be unlocked earlier even though it's completely vested

//How this works(simple example)
1. Suppose there are 3 vestingSchedule for an investor, starting at 1st Jan(2026), 1st Jan(2025) and 1st Jan(2024) respectively. All has vesting period of 1 year
2. After 1 year(1st Jan(2025), investor wanted to vest his unlocked liquidity(which was started in 2024) and call ILOPool::claim()
3. According to _unlockedLiquidity(), his unlockedLiquidity will be 0 even though one of his vesting has completed, because block.timestamp(1st Jan 2025) is less than 1st Jan 2026(1st vestingSchedule), as result whole loop will be terminated and will not loop on 3rd vestingSchedule
4. Investor will only be able to claim his liquidity after 1st Jan 2026


## Impact
Liquidity will not be claimed even though its completely vested

## Recommended Mitigation Steps
Instead of break, use continue because it doesn't terminate the whole loop, but pass the iteration which doesn't pass the check
```diff
- if (block.timestamp < vest.start) {
-        break;
-  }
+ if (block.timestamp < vest.start) {
+        continue;
+  }
