# Vulnerability details

The owner can  set platform and performance fees to any value without any validation. Specifically, the functions `setPlatformFee` and `setPerformanceFee` can set `PLATFORM_FEE` and `PERFORMANCE_FEE` to any value, including unreasonably high values such as 100% or more. This lack of validation could lead to severe financial impacts on users.

## Impact

If the fees are set to excessively high values:
- Users could lose all their generated profits or even a significant portion of their principal.
- High or unpredictable fees would deter users from using the platform, impacting its adoption and liquidity.

## Proof of Concept

The following setter functions for platform and performance fees:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOManager.sol#L150
```solidity
function setPlatformFee(uint16 _platformFee) external onlyOwner {
    PLATFORM_FEE = _platformFee;
}
```
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOManager.sol#L155
```solidity
function setPerformanceFee(uint16 _performanceFee) external onlyOwner {
    PERFORMANCE_FEE = _performanceFee;
}
```

There is no validation to ensure that `_platformFee` and `_performanceFee` are within reasonable bounds.


The `_deductFees` function is used to deduct fees based on the provided `feeBPS` (basis points):
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L438
```solidity
function _deductFees(uint256 amount0, uint256 amount1, uint16 feeBPS) internal pure 
    returns (uint256 amount0Left, uint256 amount1Left) {
    amount0Left = amount0 - FullMath.mulDiv(amount0, feeBPS, BPS);
    amount1Left = amount1 - FullMath.mulDiv(amount1, feeBPS, BPS);
}
```

When `feeBPS` is set to an excessively high value, such as 10000 (representing 100%), it results in:

```solidity
amount0Left = amount0 - FullMath.mulDiv(amount0, 10000, 10000); // amount0Left = amount0 - amount0 = 0
amount1Left = amount1 - FullMath.mulDiv(amount1, 10000, 10000); // amount1Left = amount1 - amount1 = 0
```

This means that after the deduction, `amount0Left` and `amount1Left` will both be 0. Consequently, the investor will receive no generated fees (profits).


Assume an investor's position has generated fees `fees0 = 100` and `fees1 = 50`:

- With `performanceFee = 10000` (100%):
  ```solidity
  (fees0, fees1) = _deductFees(100, 50, 10000); // results in (0, 0)
  ```

So, the investor would receive 0 for both `fees0` and `fees1`.


In the `claim` function, this can be seen as follows:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src%2FILOPool.sol#L212-L227
```solidity
// Calculate fees generated by position
uint256 fees0 = FullMath.mulDiv(
    feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
    positionLiquidity,
    FixedPoint128.Q128
);

uint256 fees1 = FullMath.mulDiv(
    feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
    positionLiquidity,
    FixedPoint128.Q128
);

// Amount of fees after deducting performance fee
(fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);

```

If `_project.performanceFee` is set to 10000, then `fees0` and `fees1` after deduction would be 0. Therefore, the investor gets no profit from the generated fees. The same case for `platformFee`

## Recommended Mitigation Steps

Define Maximum Fee Constants
    ```solidity
    uint16 constant MAX_PLATFORM_FEE_BPS = 5000; // 50%
    uint16 constant MAX_PERFORMANCE_FEE_BPS = 5000; // 50%
    ```

Implement Validation in Setter Functions
  ```solidity
    function setPlatformFee(uint16 _platformFee) external onlyOwner {
        require(_platformFee <= MAX_PLATFORM_FEE_BPS, "Platform fee must be <= 50%");
        PLATFORM_FEE = _platformFee;
    }
```
```solidity
    function setPerformanceFee(uint16 _performanceFee) external onlyOwner {
        require(_performanceFee <= MAX_PERFORMANCE_FEE_BPS, "Performance fee must be <= 50%");
        PERFORMANCE_FEE = _performanceFee;
    }
 ```
