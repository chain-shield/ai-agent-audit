# Vulnerability details

## Impact
An address can be blacklisted and whitelisted at the same time and in cases where only a whitelist check present the address can pass that check even though owner intended to blacklist the address

## Proof of Concept
if the owner calls `addWhitelistedAddress` with the address he wants to whitelist
```solidity
function addWhitelistedAddress(address whitelisted) external onlyOwner {
        _addWhitelistedAddress(whitelisted);
    }
```

we can see the above function goes on to call the private function `_addWhitelistedAddress(whitelisted);`
```solidity
    function _addWhitelistedAddress(address whitelisted) private {
        if (_whitelistIndex[whitelisted] == 0) {
            _whitelistIndex[whitelisted] = ++_whitelistCount;
        }
    }
```

Note this increases the `whitelistIndex` of the address to make it whitelisted

so let's say the owner wants to blacklist this address so he calls `setBlacklisted`
```solidity
function setBlacklisted(address blacklisted, bool flag) external onlyOwner {
        _isBlacklisted[blacklisted] = flag;
    }
```
we can see in the above function that the function only sets the `_isBlacklisted` flag to true but doesn't revoke it from being whitelisted

Alternatively,

if the  `setBlacklisted` is being called on an address and is later being whitelisted, there is no line of code that will revoke the address from the blacklist hence the double role.
this can lead to DOS in functions like `checkWhitelist` because the address will always revert at the blacklist check even though it is whitelisted.

manual review

## Recommended Mitigation Steps
There should be a blacklist check in `addWhitelistedAddress` functions
