# Vulnerability details

## Root of the Bug
The bug is arises from the incorrect operation when applying the 5% slippage in the peek function. the formula used for slippage id  divides the calculated amount by an incorrect factor (1e20), and this  leading to unintended precision loss and inaccurate results.
Here : 

```solidity
return (quotedWETHAmount * baseAmount * 95) / 1e20; // Incorrect division factor
```

The formula attempts to apply a 5% reduction by multiplying by 95 and then dividing by 1e20, and  the divisor 1e20 is incorrect for handling both the precision adjustment (typically 1e18 for 18 decimals) and the percentage reduction. It introduces an additional precision loss beyond what is necessary, leading to an unintended reduction in the final quoted amount, and the quotedWETHAmount is multiplied by baseAmount to scale the quote according to the specified amount.
The result is then multiplied by 95 to apply the 5% reduction.

The intended adjustment should divide by 1e18 (for decimal precision) and then by 100 for the percentage factor.
The current code divides by 1e20, combining both precision and percentage adjustments but with an incorrect total factor, causing an overly large réduction

## Impact
The incorrect application of slippage can lead to inaccurate price quotes for 1 VULT, potentially resulting in financial discrepancies.
