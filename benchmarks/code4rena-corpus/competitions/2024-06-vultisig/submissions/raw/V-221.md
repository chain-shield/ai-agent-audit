# Vulnerability details

## Impact

`Multicall::multicall` has delegatecall inside a loop in a payable function:
(success,result) = address(this).delegatecall(data[i]) (src/base/Multicall.sol#14)

Depending on which function are called from the `Multicall::multicall` the issues that can arise are multiple, to be more concise the rest of the info is in the references:

Reference 1: https://detectors.auditbase.com/loop-delegatecall-usage-solidity
Reference 2: https://blog.trailofbits.com/2021/12/16/detecting-miso-and-opyns-msg-value-reuse-vulnerability-with-slither/
Reference 3: https://samczsun.com/two-rights-might-make-a-wrong/
Reference 4: https://github.com/crytic/slither/wiki/Detector-Documentation/#payable-functions-using-delegatecall-inside-a-loop

## Proof of Concept
1. By calling the `Multicall::multicall` it can execute different functions and each time in a different order which may cause large spectre of issues.

## Tools Used
Solidity, Foundry

## Recommended Mitigation Steps

By removing the function `Multicall::multicall` the safety of the protocol would improve. Instead of calling multiple function via `Multicall::multicall` just call them individually.
