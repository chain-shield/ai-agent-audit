# Vulnerability details

## Impact
Lowering the _allowedWhitelistIndex without proper safeguards can potentially lead to unintended consequences within the contract's whitelist validation logic. Specifically, the checkWhitelist function might misidentify addresses as not whitelisted, causing legitimate transactions to fail.

```javascript
 function setAllowedWhitelistIndex(uint256 newIndex) external onlyOwner {
        _allowedWhitelistIndex = newIndex;
    }
```

## Proof of Concept
Example Scenario:
Current Setup:

_allowedWhitelistIndex is initially set to 10.
An address to is whitelisted with _whitelistIndex[to] = 7.
Sequence of Actions:

The contract owner executes setAllowedWhitelistIndex(6).
Impact on checkWhitelist:

Before the change, to was considered whitelisted because _whitelistIndex[to] <= 10.
After lowering _allowedWhitelistIndex to 6, to no longer meets the condition _whitelistIndex[to] > 6, causing transactions involving to to revert with NotWhitelisted.

Manual Review

## Recommended Mitigation Steps
 Implement a requirement in setAllowedWhitelistIndex to ensure that the new value is greater than the current 

```javascript
 require(newIndex > _allowedWhitelistIndex, "New index must be greater than current index");
```
