# Vulnerability details


## Impact
There is no validation to prevent the buy function from being called after the `launchSucceed` or the `refundTriggered`.
This can result in funds being locked in the contract if the buy function is called after the `launchSucceed`.
Additionally, the liquidity may be incorrectly added to the investor's position.

## Proof of Concept
The `buy` function can be called from the `saleInfo.start` to the `saleInfo.end`. [buy](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L134)
But the launch can be succeed before the `saleInfo.end` if `totalRaised` exceeds `softCap`. [launch](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L274)
After the `launchSucceed`, if the user invoke the `buy` function, the `RAISE_TOKEN` can not be used to add liquidity to the pool and the incorrect liquidity can be added to the investor's position. 
This unadded liquidity can still be claimed by the user. [claim](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L184)

## Tools Used
Manual review

## Recommended Mitigation Steps
Add validation to prevent the `buy` function from being called after `launchSucceed` or `refundTriggered`.
