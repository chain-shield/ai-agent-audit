# Vulnerability details

How can a malicios user abuse this?

## Impact
Anyone can create a project and then an ILOPool. The function initILOPool() only check that `sqrtRatioLowerX96 < initialPoolPriceX96` and `sqrtRatioLowerX96 < sqrtRatioUpperX96`, but not that the `initialPoolPriceX96 < sqrtRatioUpperX96`, allowing a user to create a pool with an initial price outside the liquidity price range. As a result users buying liqudity will have an incorrect liquidity calculation.

## Proof of Concept
Here we see that the upper range is not enforced:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOManager.sol#L90
```js
    uint160 sqrtRatioLowerX96 = TickMath.getSqrtRatioAtTick(params.tickLower);
    uint160 sqrtRatioUpperX96 = TickMath.getSqrtRatioAtTick(params.tickUpper);
    // @audit not validated that _project.initialPoolPriceX96 < sqrtRatioUpperX96
    require(sqrtRatioLowerX96 < _project.initialPoolPriceX96 && sqrtRatioLowerX96 < sqrtRatioUpperX96, "RANGE");
```

If an incorrect range is provided, then initial investors will have incorrect liquidity calculation, because the buy() function in the ILOPool contract relies on these being correct:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L155
```js
    if (RAISE_TOKEN == _cachedPoolKey.token0) {
        liquidityDelta = LiquidityAmounts.getLiquidityForAmount0(SQRT_RATIO_X96, SQRT_RATIO_UPPER_X96, raiseAmount);
    } else {
        liquidityDelta = LiquidityAmounts.getLiquidityForAmount1(SQRT_RATIO_LOWER_X96, SQRT_RATIO_X96, raiseAmount);
    }
```
