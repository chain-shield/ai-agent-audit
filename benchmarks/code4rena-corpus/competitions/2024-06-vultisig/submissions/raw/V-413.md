# Vulnerability details

## Impact
The `TickMath` library was adjusted to allow compilations for solidity version 0.8. This library relies on implicit overflow behavior to function correctly. The issue is that the contract `UniswapV3Oracle` is compiled with solidity 0.8 and indirectly uses the `TickMath` library via the `OracleLibrary`. Since this contract will be compiled with solidity 0.8, it could in the worst case scenario, make the library `TickMath` revert instead of implicitely overflowing as in the previous versions. This will lead to a revert in the `UniswapV3Oracle::peek` function which in turn will cause the `Whitelist::checkWhitelist` to revert.

## Proof of Concept
The `pragma solidity >=0.5.0;` instead of `pragma solidity >=0.5.0 <0.8.0;` adjustment has been made for the `TickMath` library :
```js
// SPDX-License-Identifier: GPL-2.0-or-later
pragma solidity >=0.5.0;
```

This allows it to be compiled with solidity 0.8 when the contract `UniswapV3Oracle` is compiled. This negates any overflow behavior in the library `TickMath` which by default relies on.

## Tools Used

Manual review

## Recommended Mitigation Steps

Consider using the [TickMath 0.8 official version](https://github.com/Uniswap/v3-core/blob/0.8/contracts/libraries/TickMath.sol#L27) which uses `unchecked` blocks for every function. Consider using  two different versions of this file, one for solidity versions <0.8 and one for 0.8 from the 0.8 branch.
