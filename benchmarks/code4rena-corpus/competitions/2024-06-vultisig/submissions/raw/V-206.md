# Vulnerability details

## Impact

In the current implementation of `ILOPool` smart contract, there is a `maxSaleAmount` parameter that represents maximum amount of `SALE` token that can be sold during the period of a sale. However, this parameter can be bypassed after `buy()` function call as the function doesn't check if the newly added amount exceeds `maxSaleAmount`.


## Proof of Concept

Let's look at the `buy()` function and the following check:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L139
```
 require(totalSold() <= saleInfo.maxSaleAmount, "SA");
```

The checks makes sure that the total sold amount of the `SALE` token is no more than `maxSaleAmount` that is configured when launching the pool:

https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L87
```
    maxSaleAmount: maxSaleAmount
```

The problem is that the `totalSold()` is only checked at the time of the call. So potentially the state after the current call can lead to a situation where `maxSaleAmount` is exceeded which breaks the invariant when it `totalSold()` cannot be bigger than `maxSaleAmount` parameter.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Check if the current `totalSold()` + sale amount after the `buy()` function call is no more than `maxSaleAmount` parameter.
