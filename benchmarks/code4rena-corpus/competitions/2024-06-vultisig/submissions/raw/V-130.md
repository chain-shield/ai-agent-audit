# Vulnerability details

## Impact
ILO pools are initialized calling `ILOManager::initILOPool`, among the paramaters to be passed it can be found the upper and lower bound as well as the starting price. The project admin is supposed to intialized the pool selecting an initial price falling in the range [`sqrtRatioLowerX96`, `sqrtRatioUpperX96`], however a missing check in the require statement in LOC 90 allows the admin to set a starting price bigger than `sqrtRatioUpperX96`, resulting in an incorrect pool initialization:

```javascript
...
        require(
            sqrtRatioLowerX96 < _project.initialPoolPriceX96 &&
                sqrtRatioLowerX96 < sqrtRatioUpperX96, 
            "RANGE"
        );
...
```
## Proof of Concept
To test this you can simply change the tick for the upper bound in `IntegrationTestBase::_getInitPoolParams` and set it for example to `MIN_TICK_500 + 1` which is well below the initial price in `Mock::mockProject`. Then run forge test --mt testInitPool removing the assert `assertEq(iloPool.TICK_UPPER(), -MIN_TICK_500);` and you will see that the rest of the asserts are met, hence the pool is being deployed with incorrect paramaters.

## Recommended Mitigation Steps
Replace the second condition in the require statement by the correct one:
```diff
...
        require(
            sqrtRatioLowerX96 < _project.initialPoolPriceX96 &&
-               sqrtRatioLowerX96 < sqrtRatioUpperX96, 
+               _project.initialPoolPriceX96<sqrtRatioUpperX96
            "RANGE"
        );
...
```
