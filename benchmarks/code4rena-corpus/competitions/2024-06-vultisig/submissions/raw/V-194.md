# Vulnerability details


## Impact
The project uses `transfer()` for sending ETH to the caller after determining the payout amount.

```javascript
IWETH9(WETH9).transfer(recipient, value);
```

However, use of `transfer()` has the risk that it will not work if the gas cost increases/decrease. The assumption that gas cost stays fixed no longer holds true since Istanbul hard fork. see https://swcregistry.io/docs/SWC-134/. When that happens, it will prevent the caller from receiving ETH payout.


## Proof of Concept

In the past `transfer()` was recommended to prevent re-entrancy attacks (i.e. via receive/fallback) as it limits forwarded gas to 2300. Now the security recommendation to prevent re-entrancy is to ensure Check-Effects-Interactions Pattern or use a Reentrancy guard.

The transfer method is used to send ether to a recipient. It is generally considered unsafe because it forwards a fixed amount of 2300 gas, which might not be enough for certain operations in the recipient's fallback or receive function. If the recipient is a contract that requires more than 2300 gas, the transaction will revert.

## Tools Used
Manual review

## Recommended Mitigation Steps
Instead of using `transfer`, it is recommended to use `call` to send ether, which allows specifying the amount of gas to forward.
