# Vulnerability details

# [M-02] Inaccurate Fee Calculation May Result in Overcharging or Undercharging

The `ILOPool::claim` function does the calculations for platform and performance fees. Here is the part of the code that does the calculations:
The code first burns the liquidity and gets `amount0` and `amount1` of tokens. It then deducts the platform fee and does the same for fee growth for `fees0` and `fees1`, deducting the performance fee there. It then collects the maximum amount of token0 and token1 and transfers `amountCollected0 - amount0` to the fee collector and `amount0` (note that `amount0` is corrected when fees are deducted) to the `tokenId` owner.
However, this is only correct if the `amountCollected0` is exactly equal to the original `amount0 + fees0`. If it is higher, the protocol has taken more than needed fees, and if it is lower, the protocol has taken less.

                address(pool)

            require(positionLiquidity >= liquidity2Claim);

            // get amount of token0 and token1 that pool will return for us
            (amount0, amount1) = pool.burn(TICK_LOWER,TICK_UPPER,liquidity2Claim);

            // get amount of token0 and token1 after deduct platform fee

            bytes32 positionKey = PositionKey.compute(
                address(this),
                TICK_LOWER,
                TICK_UPPER
            );

            // calculate amount of fees that position generated
            (
                ,
                uint256 feeGrowthInside0LastX128,
                uint256 feeGrowthInside1LastX128,
                ,

            ) = pool.positions(positionKey);
            uint256 fees0 = FullMath.mulDiv(
                feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
                positionLiquidity,
                FixedPoint128.Q128
            );

            uint256 fees1 = FullMath.mulDiv(
                feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
                positionLiquidity,
                FixedPoint128.Q128
            );

            // amount of fees after deduct performance fee
            (fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);

            // fees is combined with liquidity token amount to return to the user
            amount0 += fees0;
            amount1 += fees1;

            position.feeGrowthInside0LastX128 = feeGrowthInside0LastX128;
            position.feeGrowthInside1LastX128 = feeGrowthInside1LastX128;

            // subtraction is safe because we checked positionLiquidity is gte liquidity2Claim
            position.liquidity = positionLiquidity - liquidity2Claim;
            emit DecreaseLiquidity(tokenId, liquidity2Claim, amount0, amount1);
        }
        // real amount collected from uintswap pool
        (uint128 amountCollected0, uint128 amountCollected1) = pool.collect(
            address(this),
            TICK_LOWER,
            TICK_UPPER,
            type(uint128).max,
            type(uint128).max
        );
        emit Collect(
            tokenId,
            address(this),
            amountCollected0,
            amountCollected1
        );

        // transfer token for user
        TransferHelper.safeTransfer(
            _cachedPoolKey.token0,
            ownerOf(tokenId),
            amount0
        );
        TransferHelper.safeTransfer(
            _cachedPoolKey.token1,
            ownerOf(tokenId),
            amount1
        );

        emit Claim(
            ownerOf(tokenId),
            tokenId,

            amount0,
            amount1,

            position.feeGrowthInside1LastX128

            _cachedPoolKey.token1,
            feeTaker,
            amountCollected1 - amount1

## Impact
The protocol might collect more or less fees than intended, leading to potential financial discrepancies. If the collected amount is higher than calculated, users are overcharged, reducing their returns. If the collected amount is lower, the protocol loses out on fees, affecting its revenue.

## Proof of Concept
Consider a scenario where the actual collected amount (amountCollected0) differs from the expected amount (amount0 + fees0). The discrepancy will result in incorrect fee deductions:

- If amountCollected0 > amount0 + fees0, the fee collector receives more than intended.
- If amountCollected0 < amount0 + fees0, the fee collector receives less than intended.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Do the fee calculations after the collected amounts for token0 and token1 are calculated.
