# Vulnerability details

## Impact
The absence of a validation check to ensure that the `params.end` timestamp is in the `future` can lead to immediate sale expiration of the ILO pool upon initialization. This means that no sales will be possible as the `endTime` would have already passed.

## Vulnerability Details
The [initILOPool()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L76-L77) function is designed to initialize an  (ILO) pool with specific parameters provided by the project admin. These parameters include the `start` and `end` times for the sale.

The function performs several checks to ensure the validity of these parameters, such as verifying that the `start time` is before the `end time` and that the `end time` is before the project's `launch time`. 
```solidity
// validate time for sale start and end compared to launch time
require(params.start < params.end && params.end < _project.launchTime, "PT");
```
However, it lacks a crucial validation step to ensure that the `endTime` is in the future relative to the current timestamp.

The absence of a check to confirm that `params.end` is in the future can lead to significant issues. Specifically, if the `endTime` is set to a timestamp that has already passed,  the sale period  within the pool  will be considered expired immediately upon initialization. 

**Consider the requirement in the [buy()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L134) function**.
```solidity
require(block.timestamp > saleInfo.start && block.timestamp < saleInfo.end, "ST");
```
As seen, for a `buy` trade to be executed, `block.timestamp` must be less than `saleInfo.end`

---> If `params.end` is set to a timestamp before the current `block.timestamp`, the pool will close immediately, preventing any sales. This means that no participants will be able to contribute to the `sale`, rendering the pool ineffective for its intended purpose.

## Recommended mitigation steps
The `initILOPool()` function should ensure that the `params.end` is in the future relative to the current timestamp.
```diff
    // validate time for sale start and end compared to launch time
    require(params.start < params.end && params.end < _project.launchTime, "PT");
+   require(params.end > block.timestamp, "End time must be in the future");
```
