# Vulnerability details

## Impact
Project admins can create multiple `ILOPools` for their project, which contains mechanism such as vesting, sale management, ERC721 integration, etc.

The problem is that when the project is launched, the `ILOManager::launch` function loops through the entire list of `ILOPools`, calling `ILOPool::launch` in each iteration.

This is very gas intensive, as the functionality within `ILOPool::launch` is also complex, where there are nested `for loops` and external calls to `Uniswap V3`.

This may cause permanent DoS to project launches due to out of gas error. I am considering this a medium vulnerability since project admin and investors can still receive refunds if the project is unable to launch. However, the fact that the project will never be able to launch certainly warrants medium severity.

## Proof of Concept
Once the project `launch time` (set by the project admin during project initialization) has passed, anyone can launch the project.

This call is quite gas intensive, as there is an external call to `Uniswap V3`, in addition to a nested for loop with O(n^2) time complexity. This can DoS due to insufficient gas.

Since there is no other way for the project to launch other than looping through all of the initialized pools, and since pools can't be removed either, the project will never be able to launch.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Avoid looping through the entire list of `ILOPools` to launch a project. Consider creating a function call that allows project admins to launch a pool one at a time.
