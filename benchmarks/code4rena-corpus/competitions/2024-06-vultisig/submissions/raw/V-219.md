# Vulnerability details

## Impact
Users send ETH to `Whitelist` contract in an attempt to self-whitelist themselves and the contract send back the ETH to the users, But unfortunately the contract is using `transfer()` in `receive()` in order to send the ETH back to the users.
```
payable(_msgSender()).transfer(msg.value);
```
However, `transfer()` only forwards 2300 gas, So when user is using contract that has `receive()` or `fallback()` requiring more than 2300 gas the transaction will fail, user will loose his ETH and it will permanently get locked in `Whitelist` contract because there is no `withdraw()` in the contract.

## Proof of Concept
1. User transfer ETH to `Whitelist` contract from his contract or multisig wallet in order to get whitelisted and get his ETH back.
2. User lost his ETH because he is using contract or multisig wallet with `receive()` or `fallback()` requiring more than 2300 gas. 

## Tools Used
Manual review

## Recommended Mitigation Steps
Use `call()` instead of `transfer()` to send ETH.
```
(bool success, ) = payable(_msgSender()).call{value: msg.value}("");
```
