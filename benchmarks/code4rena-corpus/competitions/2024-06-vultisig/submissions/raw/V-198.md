# Vulnerability details

The `ILOPool.sol` constructor calls `_disableInitialize()` which would prevent any calls to the `initialize()` function.

## Impact
The contract cannot be initialized and thus the values for the state variables cannot be set. This makes the contract unusable because the uninitialized variables will make the functions in this contract revert.

## Proof of Concept
Here is the implementation for `Initializable.sol`:
```solidity
abstract contract Initializable {
    bool private _initialized;
    function _disableInitialize() internal {
        _initialized = true;
    }
    modifier whenNotInitialized() {
        require(!_initialized);
        _;
        _initialized = true;
    }
    modifier afterInitialize() {
        require(_initialized);
        _;
    }
}
```

The constructor in `ILOPool.sol` calls `_disableInitialize()` which sets `_initialized` to true. The `initialize()` function has the `whenNotInitialized()` modifier which requires `_initialized` to be false and thus will revert:

```solidity
    constructor() ERC721('', '') {
        _disableInitialize();
    }

    function initialize(InitPoolParams calldata params) external override whenNotInitialized() {
```

## Recommended Mitigation Steps
Remove `_disableInitialize()` from the constructor:
```diff
    constructor() ERC721('', '') {
-       _disableInitialize();
    }
```
