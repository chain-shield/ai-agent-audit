# Vulnerability details

## Proof of Concept
The `UniswapV3Oracle` contract is designed to calculate the time-weighted average price (TWAP) for the VULT/ETH trading pair over the last 30 minutes. This price calculation is used in other contracts to determine the amount of ETH required for transactions involving the VULT token. The `peek` function in this contract retrieves the TWAP price and then applies a hardcoded 5% slippage to the result. The relevant portion of the code is shown below:
```solidity
function peek(uint256 baseAmount) external view returns (uint256) {
    uint32 longestPeriod = OracleLibrary.getOldestObservationSecondsAgo(pool);
    uint32 period = PERIOD < longestPeriod ? PERIOD : longestPeriod;
    int24 tick = OracleLibrary.consult(pool, period);
    uint256 quotedWETHAmount = OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH);
    // Apply 5% slippage
    return (quotedWETHAmount * baseAmount * 95) / 1e20; // 100 / 1e18
}
```
- The function first determines the longest available observation period using `OracleLibrary.getOldestObservationSecondsAgo(pool)`.
- It then sets the period to either the constant PERIOD (30 minutes) or the longest available period, whichever is shorter.
- The TWAP tick value over this period is fetched using `OracleLibrary.consult(pool, period)`.
- Using the tick value, the quoted WETH amount for the `BASE_AMOUNT` (`1 VULT`) is obtained with `OracleLibrary.getQuoteAtTick(tick, BASE_AMOUNT, baseToken, WETH)`.
- The function then applies a hardcoded 5% slippage to the quoted amount by multiplying it by 95% $(95 / 100)$, which adjusts the quoted WETH amount downwards to account for slippage.

## Impact
- `Lack of Flexibility`: A fixed 5% slippage does not adapt to changing market conditions. Market volatility can vary significantly, and a static slippage percentage may not provide an accurate reflection of the current market state.
- `Inaccuracy in Pricing`: If the actual market slippage is higher or lower than 5%, the calculated amount of WETH will be inaccurate. For instance, during periods of high volatility, the actual slippage might exceed 5%, resulting in the user receiving less WETH than expected.
The purpose of the slippage is to account for potential price movement between the time the TWAP is calculated and the time the transaction is executed. However, because this value is hardcoded, it cannot be adjusted to reflect real-time market conditions, which undermines its effectiveness.
