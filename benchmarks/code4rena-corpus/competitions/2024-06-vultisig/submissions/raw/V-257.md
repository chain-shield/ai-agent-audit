# Vulnerability details

## Impact
There is no check to ensure that the end time of each schedule is after its start time. This could lead to scenarios where a vesting period is defined with an end time that is before its start time, resulting in an invalid schedule being validated.



## Proof of Concept

The `_validateVestSchedule` function is designed to validate the vesting schedule for an Initial Liquidity Offering (ILO). The function ensures that each vesting period starts after the previous one ends and that the total shares allocated for vesting match the expected basis points (`BPS`).

```javascript
  function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
        require(schedule[0].start >= launchTime, "VT");
        uint16 BPS = 10000;
        uint16 totalShares;
        uint64 lastEnd;
        uint256 scheduleLength = schedule.length;
        for (uint256 i = 0; i < scheduleLength; i++) {
            // vesting schedule must not overlap
@>          require(schedule[i].start >= lastEnd, "VT");
@>          lastEnd = schedule[i].end;
            // we need to subtract fist in order to avoid int overflow
            require(BPS - totalShares >= schedule[i].shares, "VS");
            totalShares += schedule[i].shares;
        }
        // total shares should be exactly equal BPS
        require(totalShares == BPS, "VS");
    }
```
Invalid vesting periods may cause unexpected behavior in the vesting logic, potentially allowing for claims outside of the intended vesting periods.

## Recommended Mitigation Steps
Add a check to ensure that the end time of each vesting period is greater than its start time.

```diff
  function _validateVestSchedule(uint64 launchTime, LinearVest[] memory schedule) internal pure {
        require(schedule[0].start >= launchTime, "VT");
        uint16 BPS = 10000;
        uint16 totalShares;
        uint64 lastEnd;
        uint256 scheduleLength = schedule.length;
        for (uint256 i = 0; i < scheduleLength; i++) {
            // vesting schedule must not overlap
+           require(schedule[i].end > schedule[i].start, "End time must be after start time");
            require(schedule[i].start >= lastEnd, "VT");
            lastEnd = schedule[i].end;
            // we need to subtract fist in order to avoid int overflow
            require(BPS - totalShares >= schedule[i].shares, "VS");
            totalShares += schedule[i].shares;
        }
        // total shares should be exactly equal BPS
        require(totalShares == BPS, "VS");
    }
    
```
This ensures that each vesting period has a valid duration where the end time is after the start time, preventing invalid vesting periods.
