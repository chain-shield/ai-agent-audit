# Vulnerability details

## Impact

The vulnerability allows blacklisted addresses to bypass restrictions by purchasing tokens for whitelisted addresses. This undermines the blacklist mechanism, leading to potential non-compliance with regulatory requirements and unauthorized participation in the sale. 

#### Description
The current implementation of the buy function allows blacklisted addresses to circumvent restrictions by purchasing tokens on behalf of whitelisted addresses. This flaw compromises the blacklist mechanism, resulting in potential non-compliance with regulatory requirements and unauthorized participation in the token sale.
ssue Demonstration:
The function only checks if the recipient is whitelisted, not the caller (msg.sender).
A blacklisted address can call this function and specify a whitelisted address as the recipient.
Proof:
A blacklisted address calls the buy function:
ILOPool.buy(raiseAmount, whitelistedAddress);
The function succeeds because whitelistedAddress is whitelisted, even though the caller is blacklisted.
#### Impact
This vulnerability undermines the integrity of the blacklist mechanism, leading to:

- Unauthorized entities participating in the token sale.

## Proof of Concept

```js

// SPDX-License-Identifier: BUSL-1.1
pragma solidity 0.8.0;

import "forge-std/Test.sol";
import "../hardhat-vultisig/contracts/Whitelist.sol";
import "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract ILOPoolTest is Test {
    ILOPool ilopool;
    address blacklistedAddress = address(0x1);
    address whitelistedAddress = address(0x2);
    address manager = address(0x3);
    address raiseToken = address(0x4);
    address saleToken = address(0x5);
    address uniV3Pool = address(0x6);

    function setUp() public {
        ilopool = new ILOPool();
        ilopool.initialize(ILOPool.InitPoolParams({
            uniV3Pool: uniV3Pool,
            tickLower: -887220,
            tickUpper: 887220,
            sqrtRatioLowerX96: 4295128739,
            sqrtRatioUpperX96: 1461446703485210103287273052203988822378723970342,
            hardCap: 1000 ether,
            softCap: 500 ether,
            maxCapPerUser: 100 ether,
            start: block.timestamp,
            end: block.timestamp + 1 days,
            vestingConfigs: new ILOPool.VestingConfig[](0)
        }));

        // Set up the manager and whitelist
        vm.prank(manager);
        ilopool.addWhitelist(whitelistedAddress);

        // Mint some raise tokens to the blacklisted address
        deal(raiseToken, blacklistedAddress, 100 ether);
    }

    function testBlacklistedAddressCanBuyForWhitelistedAddress() public {
        // Blacklisted address buys tokens for whitelisted address
        vm.prank(blacklistedAddress);
        IERC20(raiseToken).approve(address(ilopool), 10 ether);
        ilopool.buy(10 ether, whitelistedAddress);

        // Check if the whitelisted address received the position
        uint256 tokenId = ilopool.tokenOfOwnerByIndex(whitelistedAddress, 0);
        (uint128 liquidity, uint256 raiseAmount,,) = ilopool.positions(tokenId);

        assertEq(raiseAmount, 10 ether );
    }
}
```

## Recommended Mitigation Steps
To enhance the security of the `buy` function, we have incorporated a verification step to ensure both the caller and the recipient are whitelisted. Below is the revised function:

```solidity
function buy(uint256 raiseAmount, address recipient)
    external override 
    returns (
        uint256 tokenId,
        uint128 liquidityDelta
    )
{
    require(_isWhitelisted(msg.sender), "Unauthorized Access: Caller not whitelisted");
    require(_isWhitelisted(recipient), "Unauthorized Access: Recipient not whitelisted");
    // Additional checks and logic
}
```

This modification ensures that only authorized participants can execute the `buy` function, thereby enhancing the overall security of the smart contract.
