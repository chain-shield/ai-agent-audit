# Vulnerability details

## Impact
In the `claim()` function, the `amountCollected0` and `amountCollected1` are transferred to the `feeTaker` before they are transferred to the user.

## Proof of Concept
[ILOPool.sol#L250-L260](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOPool.sol#L251-L261)
```solidity
        // transfer token for the user
        TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amount1);


        emit Claim(ownerOf(tokenId), tokenId,liquidity2Claim, amount0, amount1, position.feeGrowthInside0LastX128, position.feeGrowthInside1LastX128);


        address feeTaker = IILOManager(MANAGER).FEE_TAKER();
        // transfer fee to fee taker
        TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0-amount0);
        TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1-amount1);
    }
```
**Scenario 1:**
   * User claims their tokens.
   * The `claim()` function correctly calculates the amount of tokens to be transferred to the user.
   * The `amountCollected0` and `amountCollected1` are transferred to the `feeTaker` before the `amount0` and `amount1` are transferred to the user.
   * The user receives only a portion of their tokens, equal to the difference between `amountCollected0` and `amount0`.

**Scenario 2:**
   * User claims their tokens.
   * The `claim()` function correctly calculates the amount of tokens to be transferred to the user.
   * The `amountCollected0` and `amountCollected1` are transferred to the `feeTaker` after the `amount0` and `amount1` are transferred to the user.
   * The user receives the total amount of tokens they were entitled to.

The bug in the `claim()` function caused the user to receive only a partial amount of their tokens due to the incorrect order of token transfers.

## Recommended Mitigation Steps
```solidity
// ...

// Transfer token for the user
TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amount0);
TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amount1);

// Transfer fee to fee taker
TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0 - amount0);
TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1 - amount1);

emit Claim(ownerOf(tokenId), tokenId, liquidity2Claim, amount0, amount1, position.feeGrowthInside0LastX128, position.feeGrowthInside1LastX128);

// ...
```
The corrected code ensures the user receives their tokens before the fees are transferred to the `feeTaker`. This prevents the user from receiving partial tokens due to the fee deduction.
