# Vulnerability details

## Impact
- Malicious users can bypass maximum cap per user set by project's admin.  
## Description
Project's owner can set a maximum cap for each user to buy in a position.  

In an open-to-all raising pool, it is practically impossible to enforce the maximum cap for each user because they can set a recipient to an unlimited number of EOAs that they own.  

In contrast, in whitelist-only raising pool, it should be expected that this safeguard works as you can limit the number of allowed recipient in a list.  

The maximum cap per user is being enforced in `buy` function.  
See: [ILOPool.sol#L126C14-L152](https://github.com/code-423n4/2024-06-vultisig/blob/main/src/ILOPool.sol#L126-L152)  
```solidity

            uint256 tokenId,
            uint128 liquidityDelta

    {

    totalRaised += raiseAmount;

    require(totalSold() <= saleInfo.maxSaleAmount, "SA");

    // if investor already have a position, just increase raise amount and liquidity
    // otherwise, mint new nft for investor and assign vesting schedules

        _positionVests[tokenId].schedule = _vestingConfigs[0].schedule;

        tokenId = tokenOfOwnerByIndex(recipient, 0);
    }

    @> Position storage _position = _positions[tokenId];
    @> require(raiseAmount <= saleInfo.maxCapPerUser - _position.raiseAmount, "UC");
    @> _position.raiseAmount += raiseAmount;
    ...
    ...
    ...
```
Here is how the mechanism works: 
- Checks `recipient` in whitelist
- If `recipient` already has position, it retrieves position's information from mapping variable.  
- Checks whether a total new raiseAmount exceeds maximum capacity for each user.  

This is the reason that this mechanism doesn't work in open-to-all ILO.  

However, it is not an effective measure in whitelist-only ILO too.  

As the position is hold in a form of NFT, and there is not check against whitelist within ERC721 layer.  

Anyone can bypass this maximum capacity by transferring their NFT to another address, and continue buying more position.  

## Proof-of-Concept
The test below does the following:  
- Init a new project.  
- Init a new pool with max cap at 20_000 ether.  
- Whitelist `INVESTOR` address  
- Demonstrate that max cap for each user can be bypassed by transferring NFT to another account not in the whitelist.

## Recommended Mitigations
- Consider checking against whitelist in `_beforeTokenTransfer` hook of ERC721

### Suggested fix
Implement this hook in `ILOPool.sol`
```solidity
function _beforeTokenTransfer(address from, address to, uint256 tokenId) internal override { 
    require(_isWhitelisted(to), "UA");
}
```
