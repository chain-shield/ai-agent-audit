# Vulnerability details

## Vulnerability details
When a project is initialized using `ILOManager::initProject()`, it takes `launchTime` as param and calculates the `refundDeadline` by adding `DEFAULT_DEADLINE_OFFSET` to `launchTime`
```solidity
      uint64 refundDeadline = params.launchTime + DEFAULT_DEADLINE_OFFSET;
```
The problem is there is `no check` to ensure `launchTime` is `greater` than `block.timestamp`. As result a malicious user can pass launchTime much `earlier` than block.timestamp, which will `offset` the DEFAULT_DEADLINE_OFFSET

//How this works
1. Suppose today is sunday(9th may) and a project wanted to onboard
2. Now, instead of passing launchTime greater than 9th May, it passes date before 2nd may ie a week earlier as there is no check
3. DEFAULT_DEADLINE_OFFSET is of 7 days, as result refundDeadline = 2nd may + 7 days ie 9th may 
 
## Impact
As result, project can claimRefund() as soon as it onboarded

## Recommended Mitigation Steps
Add a check to ensure launchTime is greater than or equal to block.timestamp
```diff
+  require(params.launchTime >= block.timestamp, 'NA');
```
