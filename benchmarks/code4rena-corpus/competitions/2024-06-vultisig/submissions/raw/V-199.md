# Vulnerability details

## Vulnerability details
When a project creates an ILOPool using ILOManager::initILOPool(), it deploys a clone with implementation & salt
```solidity
  bytes32 salt = keccak256(abi.encodePacked(
                ChainId.get(),
                params.uniV3Pool,
                _initializedILOPools[params.uniV3Pool].length
            ));
            iloPoolAddress = Clones.cloneDeterministic(ILO_POOL_IMPLEMENTATION, salt);
```
Now the problem is, salt is deterministic. A malicious actor can frontrun the pool creation by deploying the clone at the same address using implementation & salt(chainId = 1(ethereum), unipool address & pools.length can get from contract)

Using the same implementation and salt multiple time will revert, since the clones cannot be deployed twice at the same address.


## Impact
As result, honest pool creation will be DoS
