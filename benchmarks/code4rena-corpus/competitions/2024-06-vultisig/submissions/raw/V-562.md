# Vulnerability details

### **Relevant Context**
Arbitrary data can be passed into `extraData` leading to out of gas errors and DOS attack for legit users


### **Finding Description**
The `approveAndCall` does not check the length or limit the size of `extraData` being passed to the function, this can lead to gas griefing/DOS attacks by malicious actors when supplied with a very large data. 

**Attack Vector**

- An attacker can pass a very large extraData parameter.
- If IApproveAndCallReceiver(spender).receiveApproval processes or even just accepts extraData, it might cause the transaction to exceed the gas limit, resulting in an out-of-gas error.
- This can lead to denial-of-service (DoS) for legitimate users trying to call this function, as their transactions might also fail due to gas limits.

### Impact Summary
Denial of Services/ Gas griefing

### **Proof of Concept**

```solidity
    function approveAndCall(address spender, uint256 amount, bytes calldata extraData) external returns (bool) {
        // Approve the spender to spend the tokens
        _approve(msg.sender, spender, amount);

        // Call the receiveApproval function on the spender contract
        IApproveAndCallReceiver(spender).receiveApproval(msg.sender, amount, address(this), extraData);

        return true;
    }
```

## **Recommendation**
Perform a sanity check or cast the bytes down to `bytes32`.
