# Vulnerability details

The `checkWhitelist` method currently only enforces restrictions when tokens are sent from the pool. However, if a blacklisted user receives tokens from a source other than the pool, they could still acquire tokens, bypassing the blacklist restrictions. This loophole poses a significant risk, as blacklisted users may exploit it to participate in the token economy, potentially undermining the system's integrity and security.

## Impact

The current implementation of the `checkWhitelist` function has a critical flaw that can be exploited by blacklisted users. By only checking transactions originating from the pool, blacklisted users can receive tokens through other means and continue participating in the token ecosystem.

## Proof of Concept

The current implementation of the `checkWhitelist` function in the `Vultisig` contract has a critical flaw that allows a user to bypass blacklist checks when transferring tokens to a blacklisted recipient.
