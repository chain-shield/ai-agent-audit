# Vulnerability details

## Impact

Liquidity cannot be added to the uniswap pools.

## Proof of Concept

There is 0% slippage used for the RAISE_TOKEN when creating liquidity. If there are previous pools that have already created liquidity, and this current pool is adding liquidity, and if the lower and upper ticks are very close to each other, there is a possibility that the RAISE_TOKEN needed may be a little bit more than intended. 

```
            // calculate sale amount of tokens needed for launching pool
            if (token0Addr == RAISE_TOKEN) {
                amount0 = totalRaised;
                amount0Min = totalRaised;
                (amount1, liquidity) = _saleAmountNeeded(totalRaised);
            } else {
                (amount0, liquidity) = _saleAmountNeeded(totalRaised);
                amount1 = totalRaised;
                amount1Min = totalRaised;
            }

            // actually deploy liquidity to uniswap pool
            (amount0, amount1) = addLiquidity(AddLiquidityParams({
                pool: IUniswapV3Pool(uniV3PoolAddress),
                liquidity: liquidity,
                amount0Desired: amount0,
                amount1Desired: amount1,
                amount0Min: amount0Min,
                amount1Min: amount1Min
            }));

```

In that case, the liquidity cannot be added to the uniswap pool because the amountDesired will be equal to the amountMin for the RAISE_TOKEN, leaving no slippage.

## Tools Used

VSCODE

## Recommended Mitigation Steps

Have some slippage for the RAISE_TOKEN to make sure that liquidity can be added, especially when there are different pools with different tick ranges already added.


## Assessed type

Uniswap
