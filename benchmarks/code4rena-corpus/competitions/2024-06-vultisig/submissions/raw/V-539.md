# Vulnerability details

## Impact
Because slot0 price is directy read from the pool, an attacker can manipulate the pool  to make the functions `_initUniV3PoolIfNecessary()` and `launch()` not work as intended. 

## Proof of Concept
 ### 1.) for `_initUniV3PoolIfNecessary()`
   the function `_initUniV3PoolIfNecessary()` uses uniV3pool.slot0 price to compare thre given sqrt price at pool initialization against the current sqrt price in the pool if the pool is already existing. see Below 

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L109C1-L123C1
```solidity 
    function _initUniV3PoolIfNecessary(PoolAddress.PoolKey memory poolKey, uint160 sqrtPriceX96) internal returns (address pool) {
        pool = IUniswapV3Factory(UNIV3_FACTORY).getPool(poolKey.token0, poolKey.token1, poolKey.fee);
        if (pool == address(0)) {
            pool = IUniswapV3Factory(UNIV3_FACTORY).createPool(poolKey.token0, poolKey.token1, poolKey.fee);
            IUniswapV3Pool(pool).initialize(sqrtPriceX96);
        } else {
            (uint160 sqrtPriceX96Existing, , , , , , ) = IUniswapV3Pool(pool).slot0();
            if (sqrtPriceX96Existing == 0) {
                IUniswapV3Pool(pool).initialize(sqrtPriceX96);
            } else {
                require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P");
            }
        }
    }
```

if pool is already existing, it will require the current `sqrtPriceX96Existing` in the pool to be same as the `sqrtPriceX96` given as parameter. 
`_initUniV3PoolIfNecessary()`is called in [initProject()](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L61). An attacker can 
- watch the mempool for calls to `initProject()` 
 - extract the parameters to initProject() and generate the poolKey via `PoolAddress.getPoolKey()`
 - assert that the pool is existing and in a front runned tx manipulate its`sqrtPriceX96Existing` price to not be equal to the params.initialPoolPriceX96 value in the   `initProject()` parameters.
 - this then causes the call to `initProject()` which comes after to fail/revert. 


 ### 2.) for `launch()`
  the `launch(0` function compares the cached value `_cachedProject[uniV3PoolAddress].initialPoolPriceX96` against the current  sqrtPriceX96 price of the pool. Once again this can be front ran by an attacker to prevent launch of the project. 

https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L187C1-L198C6
```solidity
    function launch(address uniV3PoolAddress) external override {
        require(block.timestamp > _cachedProject[uniV3PoolAddress].launchTime, "LT");
        (uint160 sqrtPriceX96, , , , , , ) = IUniswapV3Pool(uniV3PoolAddress).slot0();
        require(_cachedProject[uniV3PoolAddress].initialPoolPriceX96 == sqrtPriceX96, "UV3P");
        address[] memory initializedPools = _initializedILOPools[uniV3PoolAddress];
        require(initializedPools.length > 0, "NP");
        for (uint256 i = 0; i < initializedPools.length; i++) {
            IILOPool(initializedPools[i]).launch();
        }

        emit ProjectLaunch(uniV3PoolAddress);
    }
```

The attacker will 
- watch the mempool for calls to `launch()` function
- extract the univ3 pool address from the function parameter, check the project's cached initialPoolPriceX96 value via a call to `ILOManager.project()`. 
- if cached value and current pool price value are the same price, then attacker will manipulate the univ3 pool in a front runned tx to make sure the sqrtPrice to be returned changes. 
- this will cause the `launch()` call which comes after to fail.
