# Vulnerability details

## Impact
A malicious whitelisted address can `buy` and transfer out NFT positions to non-whitelisted addresses.

`ILOPool::buy` has a check to see if the recipient address is whitelisted (or open-to-all) and if the address already has an NFT position. These checks ensure that only Whitelisted addresses can buy an NFT position (when not open-to-all) and if the address already has an NFT position then the position's `raiseAmount` and `liquidity` will be increased rather than minting a new NFT position for the addresses (i.e to avoid double or multiple minting of positions for an address).

However, a malicious whitelisted address can still buy multiple NFT positions for non-whitelisted addresses by transferring each NFT position bought at the time and bypassing this check `if (balanceOf(recipient) == 0)` to buy another position. 

This will impact the `ILO sales` whereby only a certain number of whitelisted addresses are allowed to participate in the sales (e.g. 1000 whitelists) for a particular period before opening to all. The malicious whitelisted address can then buy multiple NFT positions for non-whitelisted addresses thereby increasing the sales, and impacting the `totalRaised` (to near the capped amount of `raise tokens` allowed) which reduces NFT positions that could be bought and also defeats the whole idea of whitelist.

## Proof of Concept
Run `forge test --match-test test_multiple_NFT_positions -vvvv` in `ILOPool.t.sol`.

```javascript
    function test_multiple_NFT_positions() external {
        //for a whitelisted address
        _prepareBuy();

        //First NFT position (by malicious whitelisted address)
        (uint256 tokenId1, uint128 liquidity1) = _buy(SALE_START+1, 0.1 ether);

        //Transfer NFT position (to non-whitelisted address)
        vm.prank(INVESTOR);
        IERC721(iloPool).transferFrom(INVESTOR, DUMMY_ADDRESS, tokenId1);

        //Second NFT position (by malicious whitelisted address)
        (uint256 tokenId2, uint128 liquidity2) = _buy(SALE_START+1, 0.1 ether);

        //view NFT positions of both whitelisted and non-whitelisted
        IILOPool(iloPool).positions(tokenId1);
        IILOPool(iloPool).positions(tokenId2);

    }
```

## Tools Used
Manual and Foundry

## Recommended Mitigation Steps
* [short term] Make NFT positions non-transferable during the whitelist sale period. 
* [Long term] Create an internal accounting of the NFT positions for the recipients.
