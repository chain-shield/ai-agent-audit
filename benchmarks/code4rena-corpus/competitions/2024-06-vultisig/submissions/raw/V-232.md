# Vulnerability details


## Impact

The `claim` function of the pool contract improperly forwards all remaining tokens to the fee taker after paying the first user, leaving no tokens in the pool for subsequent claims. This leads to a situation where the entire liquidity pool is drained on the first claim, making it impossible for other users to claim their tokens.

1. **Drained Pool**: Once the first user claims their tokens, the contract forwards the maximum amount of tokens requested to the fee taker, leaving the pool empty.
2. **Inability to Claim**: Other users are unable to claim their tokens because the pool no longer has any liquidity after the first claim.


## Proof of Concept

 Scenario: Improper Token Distribution in `claim` Function

1. **Token Collection**: When a user initiates a claim, the contract collects the maximum amount of tokens from the Uniswap V3 pool.

 ```solidity
   (uint128 amountCollected0, uint128 amountCollected1) = pool.collect(
       address(this),
       TICK_LOWER,
       TICK_UPPER,
       type(uint128).max,
       type(uint128).max
   );
 ```

The code block below is executed on uniswapv3pool

   **Reference Code:**
   ```solidity
   // Uniswap V3 Pool collect function
   function collect(
       address recipient,
       int24 tickLower,
       int24 tickUpper,
       uint128 amount0Requested,
       uint128 amount1Requested
   ) external override lock returns (uint128 amount0, uint128 amount1) {
       Position.Info storage position = positions.get(msg.sender, tickLower, tickUpper);
       amount0 = amount0Requested > position.tokensOwed0 ? position.tokensOwed0 : amount0Requested;
       amount1 = amount1Requested > position.tokensOwed1 ? position.tokensOwed1 : amount1Requested;
       if (amount0 > 0) {
           position.tokensOwed0 -= amount0;
           TransferHelper.safeTransfer(token0, recipient, amount0);
       }
       if (amount1 > 0) {
           position.tokensOwed1 -= amount1;
           TransferHelper.safeTransfer(token1, recipient, amount1);
       }
       emit Collect(msg.sender, recipient, tickLower, tickUpper, amount0, amount1);
   }
   ```

2. **User Payment**: The contract then transfers the needed Amount from the collected tokens to the user:

 ```solidity
   TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amountCollected0);
   TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amountCollected1);
 ```

3. **Fee Taker Payment**: Instead of sending the fees to the feetaker and returning the remaining tokens to the pool, the contract transfers all the leftover tokens to the fee taker:

 ```solidity
   address feeTaker = IILOManager(MANAGER).FEE_TAKER();
   TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, amountCollected0 - amount0);
   TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, amountCollected1 - amount1);
 ```

   **Issue**: This action drains the pool and forwards all remaining tokens to the fee taker, instead of correctly distributing fee and returning liquidity.

## Recommended Mitigation Steps

To prevent the pool from being emptied on the first claim and ensure fair distribution of tokens, modify the `claim` function to properly calculate and distribute fees and return the remaining tokens to the pool.


1. **Update Claim Logic**:

   Modify the `claim` function to use local variables to track and calculate the fees, ensuring that only the appropriate fee amount is forwarded to the fee taker and the remaining tokens are returned to the pool.

   **Proposed Update**:

 ```solidity
   function claim(uint256 tokenId) external {
       (uint128 amountCollected0, uint128 amountCollected1) = pool.collect(
           address(this),
           TICK_LOWER,
           TICK_UPPER,
           type(uint128).max,
           type(uint128).max
       );

       uint128 feeAmount0 = calculateFee(amountCollected0);
       uint128 feeAmount1 = calculateFee(amountCollected1);

       // Pay the user
       TransferHelper.safeTransfer(_cachedPoolKey.token0, ownerOf(tokenId), amountCollected0 - feeAmount0);
       TransferHelper.safeTransfer(_cachedPoolKey.token1, ownerOf(tokenId), amountCollected1 - feeAmount1);

       // Transfer fee to fee taker
       address feeTaker = IILOManager(MANAGER).FEE_TAKER();
       TransferHelper.safeTransfer(_cachedPoolKey.token0, feeTaker, feeAmount0);
       TransferHelper.safeTransfer(_cachedPoolKey.token1, feeTaker, feeAmount1);

       // Return remaining tokens to the pool
       returnToPool(_cachedPoolKey.token0, amountCollected0 - feeAmount0 - amount0);
       returnToPool(_cachedPoolKey.token1, amountCollected1 - feeAmount1 - amount1);
   }

   function calculateFee(uint128 amount) internal view returns (uint128) {
       // Implement fee calculation logic
   }

   function returnToPool(address token, uint128 amount) internal {
       // Implement logic to add liquidity back to the pool
   }
 ```

2. **Implementation**:

   - Implement the `calculateFee` function to determine the fee amount based on the collected tokens.
   - Add a `returnToPool` function to add remaining tokens back to the pool, ensuring the pool retains sufficient liquidity for subsequent claims.
