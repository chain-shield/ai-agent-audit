# Vulnerability details

## Impact
Since the `claim` function does not have any deadline check, the `claim` transaction can be pending in the mempool for a considerable time. When the `claim` transaction is executed at a much later time, the price for the corresponding Uniswap v3 pool can become unexpectedly bad so the claimed token amounts can be much less than what they would be if such transaction could be executed within a recent time period.

## Proof of Concept
Unlike Uniswap's `decreaseLiquidity` function below that further calls the `checkDeadline` modifier below to ensure that the `decreaseLiquidity` transaction is executed within a specified time limit, the following `claim` function does not have any deadline check. Thus, the `claim` transaction can be pending in the mempool for a considerable period of time, and it is more likely that the price for the corresponding Uniswap V3 pool can become unexpectedly bad, such as due to a price manipulation or volatile market condition, when the `claim` transaction is executed at a much later time. Comparing to if the `claim` transaction could be executed within a recent time period, executing the `claim` transaction at a much later time can cause the investor to claim much lower token amounts.

            IILOManager.Project memory _project = IILOManager(MANAGER).project(address(pool));

            uint128 positionLiquidity = position.liquidity;
            require(positionLiquidity >= liquidity2Claim);

            // get amount of token0 and token1 that pool will return for us
            (amount0, amount1) = pool.burn(TICK_LOWER, TICK_UPPER, liquidity2Claim);

            // get amount of token0 and token1 after deduct platform fee

            bytes32 positionKey = PositionKey.compute(address(this), TICK_LOWER, TICK_UPPER);

            // calculate amount of fees that position generated
            (, uint256 feeGrowthInside0LastX128, uint256 feeGrowthInside1LastX128, , ) = pool.positions(positionKey);
            uint256 fees0 = FullMath.mulDiv(

                                positionLiquidity,
                                FixedPoint128.Q128
                            );

                                feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,

                                FixedPoint128.Q128
                            );

            (fees0, fees1) = _deductFees(fees0, fees1, _project.performanceFee);

            // subtraction is safe because we checked positionLiquidity is gte liquidity2Claim
            position.liquidity = positionLiquidity - liquidity2Claim;

        // real amount collected from uintswap pool
        (uint128 amountCollected0, uint128 amountCollected1) = pool.collect(

            type(uint128).max
        );
