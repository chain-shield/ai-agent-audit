# Vulnerability details

## Impact
Denial of Service (DoS) on creating Uniswap v3 pool. An attacker can monitor transactions in the mempool to create a Uniswap pool with the same token0, token1, and fees, but initialize the pool with a different `sqrtPriceX96`. This causes the transaction to revert when checking the condition `require(sqrtPriceX96Existing == sqrtPriceX96, "UV3P");` in the `_initUniV3PoolIfNecessary()` function. Repeating, the attacker can cause a DoS on the system.

## Proof of Concept
[Code](https://github.com/code-423n4/2024-06-vultisig/blob/cb72b1e9053c02a58d874ff376359a83dc3f0742/src/ILOManager.sol#L109-L122)

Steps: 
1. User submits the transaction for initializing project and hence creating the uniswap pool.
2, Attacker sees the transaction on mempool and try to frontrun the transaction and create the uniswap pool with same token0, token1 and fees value but using different sqrtPriceX96 value.
3. When original user's transaction check whether the same uniswap pool exists with the same parameters it also check whether the same `sqrtPriceX96` value of that existing pool.
4. On step 3 while checking the sqrtPriceX96 value it will revert. Hence DoS.

And as there is no transfer of tokens while initializing the uniswap pool it is possible to set any sqrtPriceX96.
