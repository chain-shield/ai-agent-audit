# Vulnerability details

## Impact
The checkWhitelist function is supposed to only allow whitelisted addresses to buy Vultisig tokens from the pool. Only whitelisted addresses should buy when _isSelfWhitelistDisabled == true. The checkWhitelist function allows anyone to buy, no matter if they are set as whitelisted by the owner. 

This happens because the [condition](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L216-L218) that allows whitelist functions checks if _allowedWhitelistIndex is set (above 0) and that the users list index is below that value. For non-whitelisted users, this value is always 0, thus the validation is incorrectly implemented and anyone can bypass it.

## Proof of Concept

- [function](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L204).
- [condition](https://github.com/code-423n4/2024-06-vultisig/blob/main/hardhat-vultisig/contracts/Whitelist.sol#L216).

- initial state: _allowedWhitelistIndex is set and above 0. _pool is the DEX pool used. _locked is false, to allow for whitelisted users trading. _maxAddressCap is above zero (3 eth).
- function arguments: The user can create any random address and trade into the pool. Then "from" will be the DEX address (buying), "to" the user address and amount any amount of tokens which worth is below 3eth.

code snippet

```
    function checkWhitelist(address from, address to, uint256 amount) external onlyVultisig {
        if (from == _pool && to != owner()) {
            // We only add limitations for buy actions via uniswap v3 pool
            // Still need to ignore WL check if it's owner related actions
            if (_locked) {
                revert Locked();
            }

            if (_isBlacklisted[to]) {
                revert Blacklisted();
            }

            // HERE _whitelistIndex[to] = 0 for any random address. _allowedWhitelistIndex is > 0, thus _whitelistIndex[to] > _allowedWhitelistIndex === false (not reverting)
            if (_allowedWhitelistIndex == 0 || _whitelistIndex[to] > _allowedWhitelistIndex) {
                revert NotWhitelisted();
            }

            // // Calculate rough ETH amount for VULT amount
            uint256 estimatedETHAmount = IOracle(_oracle).peek(amount);
            if (_contributed[to] + estimatedETHAmount > _maxAddressCap) {
                revert MaxAddressCapOverflow();
            }

            _contributed[to] += estimatedETHAmount;
        }
    }
```

## Recommended Mitigation Steps
change the logic of whitelisting into only allowing users where this condition holds: 1 < _whitelistIndex[msg.sender] <= _allowedWhitelistIndex. This way only whitelisted users with index above 1 can participate
