# Vulnerability details

## Impact
The `addLiquidity()` function in `LiquidityManagement` is trying to implement a price slippage check but it uses wrong logic which results in having no slippage check at all.

## Proof of Concept
The `amount0` and `amount1` returned from the uniswap pool `mint()` represent how much it costs to open a position with `params.liquidity`. To implement a slippage protection you need to have a value that represents the max that you are willing to give in order to provide this liquidity.
Currently it checks if `amount0`/`amount1` (the cost returned from uniswap) is gte
`params.amount0Min`/`params.amount1Min` (which is `totalRaised`).

Here is the require statement:
https://github.com/code-423n4/2024-06-vultisig/blob/main/src/base/LiquidityManagement.sol#L56
```solidity
require(amount0 >= params.amount0Min && amount1 >= params.amount1Min, "Price slippage check");
```
It checks if the `amount0` or `amount1` that represents the price that we are going to pay is gte our `totalRaise` token that we have, which does not make sense. We want to check if the `amount0` or `amount0` prices are in a range that we are willing to pay, not if they are gte the money that we have

## Tools Used
Manual Analysis
## Recommended Mitigation Steps
To implement a correct price slippage check you need to create max variable which represent the maximum amount of tokens that you are willing to give for the `params.liquidity`
