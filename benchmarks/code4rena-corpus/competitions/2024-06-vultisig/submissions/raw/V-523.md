# Vulnerability details

## Impact
Exploiting this vulnerability allows attackers to bypass the whitelist verification process entirely, resulting in unauthorized token transfers. This can lead to significant financial losses for users and the protocol itself. Additionally, it undermines the protocol's intended security measures, potentially causing loss of user trust.


## Proof of Concept
The protocol sets up a whitelist through its contract ``VultisigWhitelisted.sol``. To configure the whitelist, the protocol must call ``VultisigWhitelisted::setWhitelistContract``. Meanwhile, the _whitelistContract address is initially set to 0. This default address allows any token transfer or restricted action to bypass the whitelist verification until the owner sets the correct whitelist contract address. As a result, there is a period during which an attacker can transfer tokens or perform restricted actions without any whitelist checks.

## Recommended Mitigation Steps

To mitigate this vulnerability, ensure that the whitelist contract address is set immediately upon deployment by adding this code to VultisigWhitelisted.sol

```javascript
constructor(address whitelistContract) ERC20("Vultisig Token", "VULT") Ownable() {
    require(whitelistContract != address(0), "Whitelist contract address required");
    _whitelistContract = whitelistContract;
}
```
