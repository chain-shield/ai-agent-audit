# Vulnerability details

## Impact
Smart contract account with `receive` or `fallback` function that consume more than 2300 gas can not self-whitelist

Accounts like multisig wallets can also be blocked from self-whitelist

## Proof of Concept
To `self-whitelist`, ETH is directly sent to `Whitelist.sol` which will be refunded.

The issue is that `address.transfer(...)` function for returning the ETH. the native `address.transfer(...)` has a limit of maximum of 2300 gas that can be used to transfer ETH. If the account that sent the ETH to `self-whitelist` is a smart contract that with fallback function that consumes more than 2300gas, the transaction will revert.

This can block some accounts from self-whitelist. Accounts like multisig wallets can be blocked from self-whitelist

```solidity
File: Whitelist.sol
/// @notice Self-whitelist using ETH transfer
    /// @dev reverts if whitelist is disabled
    /// @dev reverts if address is already blacklisted
    /// @dev ETH will be sent back to the sender
    receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        payable(_msgSender()).transfer(msg.value);
    }
```

## Recommended Mitigation Steps
Consider using `address.call` function instead of `address.transfer(...)`. Better still you can consider using the [ExcessivelySafeCall](https://github.com/nomad-xyz/ExcessivelySafeCall) library to refund the ETH.
