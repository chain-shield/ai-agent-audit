# Vulnerability details

## Impact

Self-whitelist doesn't work if `msg.sender` is a contract

## Proof of Concept

The `whitelist.sol` contract has a self whitelist function by means of the receive function. In this way, users can register themselves on the whitelist if the whitelist is opened by sending any amount of `ETH` to the `whitelist.sol` contract.

```solidity
    receive() external payable {
        if (_isSelfWhitelistDisabled) {
            revert SelfWhitelistDisabled();
        }
        if (_isBlacklisted[_msgSender()]) {
            revert Blacklisted();
        }
        _addWhitelistedAddress(_msgSender());
        payable(_msgSender()).transfer(msg.value);
    }
```

As seen in the image above, in the receive function to carry out ETH transactions the `transfer()` function is used which has a limitation on the amount of gas used, 2300 gas.

If a user is a contract account like a multisig or smart contract wallet that has a `receive()` function requiring >2300 gas, their self whitelisting will always fail because not enough gas to execute the transactions.

## Tools Used

Manual review

## Recommended Mitigation Steps

use `call` instead of `transfer` and make sure any call on arbitrary address safe
