# Vulnerability details

## Impact
Whenever TWAP period is set to a constant or immutable, the inability to change it poses a risk after deployment.

## Proof of Concept
`uint32 public constant PERIOD = 30 minutes;`


The `PERIOD`, is set as a constant variable. `PERIOD` determines the update period for which TWAP oracles will allow a new price to be fetched. The inability to change this variable after deployment poses a risk. The `PERIOD` should be changeable to allow the owner to update it based on market conditions and manipulation risks.

[check 33auditor's write up for more info on this](https://33audits.hashnode.dev/twap-oracles-for-auditors#heading-twapinterval-is-set-as-an-immutable-value)

## Tools Used
Manual review 
## Recommended Mitigation Steps
Implement a dynamic TWAP `PERIOD` to be able to be adjusted to meet market conditions


## Assessed type

Uniswap
