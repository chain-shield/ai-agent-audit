# Vulnerability details

## Impact

It is possible to use FlashSwap functionality to farm the `Whitelist`, paying a small fee along the way but allowing users to reach the permitted user limit.

## Proof of Concept

```
function _beforeTokenTransfer(address from, address to, uint256 amount) internal override {
        if (_whitelistContract != address(0)) {
            IWhitelist(_whitelistContract).checkWhitelist(from, to, amount);
        }
        super._beforeTokenTransfer(from, to, amount);
    }
```

We can see that the whitelist verification is done before each transaction. Within `checkWhitelist`, the function checks where the tokens come from (from == pool), but it never considers FlashSwaps.


As long as the contract is in the whitelist, it is possible to perform a FlashSwap.

## Recommended Mitigation Steps

Locking the tokens for a sufficient number of blocks would prevent FlashSwaps.
