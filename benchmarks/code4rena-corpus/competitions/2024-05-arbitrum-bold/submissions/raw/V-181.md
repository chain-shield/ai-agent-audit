# Vulnerability details

## Impact
[_setMaxTimeVariation()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L867-L882) casts the input values to `uint64`, which can overflow if the values are too large. 

> The function does not handle integer overflow correctly. Casting the input values to `uint64` without checking for overflow can lead to unexpected behavior and potential exploits.:

- _If the input values are too large, the cast to uint64 will cause an overflow, resulting in an incorrect value being stored._

- _The incorrect value can lead to unexpected errors or crashes in the program._

**Exploits:** An attacker could exploit this bug by providing specially crafted input values that cause integer overflow and gain unauthorized access to the system.

## Proof of Concept
The following code demonstrates the vulnerability: [#L870-L877](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L870-L877)

```solidity
if (
    maxTimeVariation_.delayBlocks > type(uint64).max ||
    maxTimeVariation_.futureBlocks > type(uint64).max ||
    maxTimeVariation_.delaySeconds > type(uint64).max ||
    maxTimeVariation_.futureSeconds > type(uint64).max
) {
    revert BadMaxTimeVariation();
}
```
If the input values for `delayBlocks`, `futureBlocks`, `delaySeconds`, or `futureSeconds` are larger than the maximum value of `uint64`, the revert statement will not be executed, and the function will continue to execute with incorrect values.

## Recommended Mitigation Steps
Perform a range check or use a different data type that can handle larger values.

```solidity
// Check for integer overflow before casting
if (input < INT64_MAX) {
  uint64_t value = static_cast<uint64_t>(input);
  // Use the value
} else {
  // Handle overflow error
}
```
The size of the input values should be known or limited to prevent overflow.
