# Vulnerability details

## Impact
The `removeDelayAfterFork()` function in the SequencerInbox.sol contract is part of the smart contract which allows the sequencer to bypass time-delay security measures. 

However, this function is not protected by any authentication, potentially allowing any malicious actor to abuse this privilege.


## Proof of Concept
```solidity
    /// @inheritdoc ISequencerInbox
    function removeDelayAfterFork() external {
        if (!_chainIdChanged()) revert NotForked();
        delayBlocks = 1;
        futureBlocks = 1;
        delaySeconds = 1;
        futureSeconds = 1;
    }
```

## Tools Used

Manual Review

## Recommended Mitigation Steps


To mitigate this issue, It is recommended to add a rollup owner permission modifier like `onlyRollupOwner` to the function `removeDelayAfterFork()` to limit the access control.
Here is an example of how it can be done:

```solidity
    // Updated function with access control
    function removeDelayAfterFork() external onlyRollupOwner{
        if (!_chainIdChanged()) revert NotForked();
        delayBlocks = 1;
        futureBlocks = 1;
        delaySeconds = 1;
        futureSeconds = 1;
    }
```
