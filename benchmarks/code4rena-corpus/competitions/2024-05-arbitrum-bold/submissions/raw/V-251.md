# Vulnerability details

### Vulnerability 
The handling of the `currentInboxCount` in the following lines: [RollupAdminLogic.sol:71-75](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupAdminLogic.sol#L71-L75)
```solidity
uint256 currentInboxCount = bridge.sequencerMessageCount();
// ensure to move the inbox forward by at least one message
if (currentInboxCount == config.genesisInboxCount) {
    currentInboxCount += 1;
}
```
The code is trying to ensure that the `currentInboxCount` is always greater than `config.genesisInboxCount`. However, there is issue if `config.genesisInboxCount` is set to the maximum value of `uint256` (i.e., `2^256 - 1`).

In this case, when `currentInboxCount == config.genesisInboxCount`, the line `currentInboxCount += 1` will cause an integer overflow, resulting in `currentInboxCount` being set to 0 instead of the intended value of `config.genesisInboxCount + 1`.

This could lead to an incorrect state being created for the rollup, as the `nextInboxPosition` in the `configHash` would be set to 0 instead of the expected value.

## Impact
If `config.genesisInboxCount` is set to the maximum value of `uint256` (i.e., `2^256 - 1`), and the `currentInboxCount` from the bridge is equal to `config.genesisInboxCount`, the line `currentInboxCount += 1` will cause an integer overflow. This means that instead of setting `currentInboxCount` to `config.genesisInboxCount + 1`, it will be set to `0`.

This incorrect value of `currentInboxCount` will then be used to create the `configHash` for the initial assertion, as shown in the following code: [/RollupAdminLogic.sol76-83](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupAdminLogic.sol#L76-L85)

If `currentInboxCount` is `0`, the `nextInboxPosition` in the `configHash` will also be `0`, which is likely an incorrect value for the initial state of the rollup.

Let's consider an example where `config.genesisInboxCount` is set to the maximum value of `uint256`:
```solidity
uint256 maxValue = 2**256 - 1;
uint256 currentInboxCount = maxValue;

// Assuming config.genesisInboxCount is set to maxValue
if (currentInboxCount == config.genesisInboxCount) {
    currentInboxCount += 1; // This will cause an integer overflow
}

// currentInboxCount will now be 0 instead of maxValue + 1
```
`currentInboxCount` will be set to `0` instead of the expected value of `maxValue + 1`, which could lead to an incorrect state being created for the rollup.

## Recommended Mitigation Steps
Add a check to ensure that `config.genesisInboxCount` is not the maximum value of `uint256`. Alternatively, you could use a safe math library or OpenZeppelin's `SafeMath` library to handle the addition operation safely.
```solidity
import "@openzeppelin/contracts/utils/math/SafeMath.sol";

// ...

function initialize(Config calldata config, ContractDependencies calldata connectedContracts)
    external
    override
    onlyProxy
    initializer
{
    // ...

    uint256 currentInboxCount = bridge.sequencerMessageCount();
    // ensure to move the inbox forward by at least one message
    if (currentInboxCount == config.genesisInboxCount) {
        currentInboxCount = SafeMath.add(currentInboxCount, 1);
    }

    // ...
}
```
By using `SafeMath.add`, the addition operation will revert if an integer overflow occurs, preventing the creation of an incorrect state for the rollup.
