# Vulnerability details

## Impact
In [genesisAssertionHash](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L520-L530) function the way the `emptyAssertionState` is created.

The `AssertionState` struct is defined as follows: [src\rollup\AssertionState.sol:11-15](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/AssertionState.sol#L11-L15)
```solidity
struct AssertionState {
    GlobalState globalState;
    MachineStatus status;
    bytes32 machineHash;
}
```
In the `genesisAssertionHash` function, the `emptyAssertionState` is created like this: [src\rollup\RollupCore.sol:522](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L522)
```solidity
AssertionState memory emptyAssertionState = AssertionState(emptyGlobalState, MachineStatus.FINISHED, bytes32(0));
```
The problem is that the `emptyGlobalState` is a default-initialized `GlobalState` struct, which means that all its fields are set to their default values (e.g., `0` for `uint256` fields, `false` for `bool` fields, and `0x0` for `bytes32` fields).

However, the `GlobalState` struct likely contains fields that should not have their default values for the genesis assertion. For example, if the `GlobalState` struct contains a field that represents the total supply of a token, it should not be initialized to `0` for the genesis assertion.

## Proof of Concept
The `AssertionState` struct represents the state of an assertion in the `rollup` system. It contains three fields:

`globalState`: A `GlobalState` struct that represents the global state of the system after the assertion is applied.
`status`: A `MachineStatus` enum that represents the status of the execution machine after the assertion is applied.
`machineHash`: A `bytes32` value that represents the hash of the execution machine's state after the assertion is applied.

The `genesisAssertionHash` function is responsible for computing the hash of the initial assertion, also known as the genesis assertion. This hash is used as a starting point for the rollup system and serves as the parent assertion hash for the first valid assertion.

> The issue arises from the way the `emptyAssertionState` is created within the `genesisAssertionHash` function. Specifically, the `emptyGlobalState` is a default-initialized `GlobalState` struct, which means that all its fields are set to their default values (e.g., `0` for `uint256` fields, `false` for `bool` fields, and `0x0` for `bytes32` fields).

However, the `GlobalState` struct likely contains fields that represent important aspects of the system's initial state, such as the total supply of a token, the initial balances of accounts, or the initial configuration parameters. If these fields are incorrectly initialized to their default values, the resulting `emptyGlobalState` will not accurately represent the desired initial state of the system.

As a result, when the `emptyAssertionState` is created using the incorrect `emptyGlobalState`, the `genesisAssertionHash` function will produce an incorrect hash value for the genesis assertion. This incorrect hash value could potentially lead to inconsistencies or vulnerabilities in the rollup system, as the entire chain of assertions is built upon the genesis assertion hash.

Let's consider a simplified example of the `GlobalState` struct:
```solidity
struct GlobalState {
    uint256 totalSupply;
    mapping(address => uint256) balances;
}
```
In this example, if the `totalSupply` field is incorrectly initialized to `0` in the `emptyGlobalState`, the resulting `genesisAssertionHash` would be based on an incorrect initial state where the total supply of the token is zero. This could lead to inconsistencies when processing subsequent assertions that assume a non-zero total supply.

## Recommended Mitigation Steps
The `genesisAssertionHash` function should ensure that the `emptyGlobalState` is correctly initialized with the desired initial state of the system. This can be achieved by either defining a separate function or constant that returns the correctly initialized `GlobalState` struct for the genesis assertion, or by manually initializing the fields of the `GlobalState` struct within the `genesisAssertionHash` function itself.
