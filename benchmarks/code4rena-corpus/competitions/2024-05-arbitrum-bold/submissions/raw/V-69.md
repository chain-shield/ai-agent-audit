# Vulnerability details

## Impact
The contract `EdgeChallengeManager` (src/challengeV2/EdgeChallengeManager.sol) has a code size of 26651 bytes, which exceeds the limit of 24576 bytes introduced in the Ethereum hard fork "Spurious Dragon" (EIP-170). This limit was put in place to prevent certain types of denial-of-service (DoS) attacks on the Ethereum network.

Due to the contract code size exceeding the limit, the `EdgeChallengeManager` contract may not be deployable on the Ethereum Mainnet. This can lead to the following issues:

Inability to deploy the contract on the Mainnet, preventing the intended functionality from being available to users.

Increased gas costs for deployment, even if the contract is deployed on a test network or a private network.

Potential limitations in terms of contract upgradability and future maintenance.

## Proof of Concept
The developer attempts to deploy the `EdgeChallengeManager` contract on the Ethereum Mainnet.

The deployment fails due to the contract code size exceeding the limit of 24576 bytes.

The contract cannot be used on the Mainnet, and its functionality is not accessible to users.

If the contract is deployed on a test network or a private network, it may still incur higher gas costs due to the larger code size.

## Recommended Mitigation Steps
Enable the optimizer: Use the Solidity compiler's optimizer feature to reduce the bytecode size of the contract. Set a low "runs" value to optimize the contract for deployment.

Turn off revert strings: Remove or minimize the use of revert strings in the contract, as they can significantly increase the contract code size.

Use libraries: Move some of the contract's functionality to separate library contracts. This can help reduce the code size of the main contract and make it more modular.
