# Vulnerability details

### Vulnerability Details: Incorrect Number of Arguments in `safeTransferFrom` and `safeTransfer` Functions

#### Summary:
The `safeTransferFrom` and `safeTransfer` functions from OpenZeppelin's `SafeERC20` library are used incorrectly in the `ERC20Bridge` contract of the Arbitrum Foundation repository. The actual implementation of these functions in the OpenZeppelin library accepts four arguments for `safeTransferFrom` and three arguments for `safeTransfer`. However, the current usage incorrectly implies that the functions might accept three and two arguments, respectively, leading to potential issues in the contract's functionality.

#### Vulnerability Description:

The following lines in the `ERC20Bridge.sol` contract use the `safeTransferFrom` and `safeTransfer` functions from the `SafeERC20` library:

1. **Line 50:**
   ```solidity
   IERC20(nativeToken).safeTransferFrom(msg.sender, address(this), amount);
Issue: The safeTransferFrom function in OpenZeppelin's SafeERC20 library accepts four arguments: the token address, the sender address, and the recipient address, followed by the amount to be transferred.

function safeTransferFrom(IERC20 token, address from, address to, uint256 value) internal {
    _callOptionalReturn(token, abi.encodeCall(token.transferFrom, (from, to, value)));
}

Line 67:

IERC20(_nativeToken).safeTransfer(to, value);
Issue: The safeTransfer function in OpenZeppelin's SafeERC20 library accepts three arguments: the token address and the recipient address, followed by the amount to be transferred.

function safeTransfer(IERC20 token, address to, uint256 value) internal {
    _callOptionalReturn(token, abi.encodeCall(token.transfer, (to, value)));
}

### Impact:
Potential Contract Malfunction: If the functions are incorrectly assumed to accept a different number of arguments, this can lead to incorrect or failed token transfers, potentially halting the contract's intended operations.
Security Risks: Incorrect handling of token transfers can result in vulnerabilities where funds may be misallocated, lost, or sent to unintended addresses.

### Recommendations:
Verify Argument Count: Ensure that the correct number of arguments are passed to the safeTransferFrom and safeTransfer functions.
Update Code: Modify the contract code to correctly use the safeTransferFrom and safeTransfer functions from OpenZeppelin's SafeERC20 library.
