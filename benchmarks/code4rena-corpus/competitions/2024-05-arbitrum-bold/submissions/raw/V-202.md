# Vulnerability details

[In the confirmEdgeByOneStepProof function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L539-L569), the way the `ExecutionContext` struct is created and passed to the `confirmEdgeByOneStepProof` function in the `EdgeChallengeManagerLib` library.

```solidity
ExecutionContext memory execCtx = ExecutionContext({
    maxInboxMessagesRead: prevConfig.nextInboxPosition,
    bridge: assertionChain.bridge(),
    initialWasmModuleRoot: prevConfig.wasmModuleRoot
});
```
The bridge field in the `ExecutionContext` struct is expected to be an instance of the `IBridge` interface. However, in the code provided, the bridge field is assigned the value returned by `assertionChain.bridge()`, which is likely a contract address.

This could lead to issue when the `ExecutionContext` struct is used within the `confirmEdgeByOneStepProof` function in the `EdgeChallengeManagerLib` library, as it may expect an actual instance of the `IBridge` interface and not just the contract address.

## Impact
`ExecutionContext` struct is used as an input parameter for the `confirmEdgeByOneStepProof` function in the `EdgeChallengeManagerLib` library. This function is responsible for confirming an edge based on a one-step proof, which is a crucial operation in the challenge process.

The `bridge` field in the `ExecutionContext` struct is expected to be an instance of the `IBridge` interface, which likely defines a set of functions and properties related to the bridge contract. However, in the provided code, the bridge field is assigned the value returned by `assertionChain.bridge()`, which is likely just the contract address of the bridge contract.

When the `confirmEdgeByOneStepProof` function in the `EdgeChallengeManagerLib` library tries to interact with the bridge field of the `ExecutionContext` struct, it may expect an actual instance of the `IBridg` interface, with all its associated functions and properties. However, since the bridge field only contains a contract address, any attempt to call functions or access properties on this address will fail, leading to errors or unexpected behavior.

## Recommended Mitigation Steps
Ensure that `assertionChain.bridge()` returns an instance of the `IBridge` interface, or
Create an instance of the `IBridge` interface using the contract address returned by `assertionChain.bridge()`.

```solidity
import "@openzeppelin/contracts/utils/Address.sol";

// ...

ExecutionContext memory execCtx = ExecutionContext({
    maxInboxMessagesRead: prevConfig.nextInboxPosition,
    bridge: IBridge(Address.toImmutableAddress(assertionChain.bridge())),
    initialWasmModuleRoot: prevConfig.wasmModuleRoot
});
```
We use the `Address.toImmutableAddress` function from the OpenZeppelin library to create an instance of the `IBridge` interface using the contract address returned by `assertionChain.bridge()`.
