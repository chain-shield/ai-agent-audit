# Vulnerability details

## Description:
Reentrancy attacks occur when an external call to another contract is made before updating the state, allowing an attacker to recursively call the function and exploit the unprotected state.

## Impact:
Potential draining of funds or manipulation of contract state by repeatedly entering the vulnerable function.

## Proof of Concept:
In this contract, the `createBridge` function involves initializing multiple components, each potentially making external calls. If any of these calls lead to reentrant behavior, the contract's state could be compromised before all initializations are complete.

```solidity
frame.sequencerInbox.initialize(IBridge(frame.bridge), maxTimeVariation, bufferConfig);
frame.inbox.initialize(frame.bridge, frame.sequencerInbox);
frame.rollupEventInbox.initialize(frame.bridge);
frame.outbox.initialize(frame.bridge);
```

## Tools Used
Vs Code

## Recommended Mitigation Steps
Implement the "checks-effects-interactions" pattern and use ReentrancyGuard from OpenZeppelin for functions making external calls.
