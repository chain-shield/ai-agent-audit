# Vulnerability details

## Impact
If an assertion staking pool has a **zero** immutable `assertionHash`, then an attacker can consume the funds available in the pool to create an invalid assertion, leading to a loss of the staked amount.

## Proof of Concept
If an assertion staking pool contract with an expected assertion hash is deployed, it means that anyone can consume the available fund in this pool to create the expected assertion.

```solidity
        emit NewAssertionPoolCreated(_rollup, _assertionHash, address(assertionPool));
        return assertionPool;
    }
```

But, if an assertion staking pool contract with a **zero** assertion hash is deployed, it means that anyone can consume the available funds in this pool to create **any** assertion. This is because during the creation of the assertion, the hash of the newly created assertion is not enforced to be equal to the expected assertion hash if it is zero.
```solidity
    function newStakeOnNewAssertion(
        uint256 tokenAmount,
        AssertionInputs calldata assertion,
        bytes32 expectedAssertionHash,
        address withdrawalAddress
    ) public {
        require(withdrawalAddress != address(0), "EMPTY_WITHDRAWAL_ADDRESS");
        _newStake(tokenAmount, withdrawalAddress);
        stakeOnNewAssertion(assertion, expectedAssertionHash);
        /// @dev This is an external call, safe because it's at the end of the function
        receiveTokens(tokenAmount);
    }
```

So, this provides an opportunity for an attacker to call the function `createAssertion` with arbitrary parameter `assertionInputs` whenever the available funds in the pool meet the required stake. Since, the parameter is user input, the attacker can manipulate them to lead to the creation of an invalid assertion that for sure will be challenged and proved incorrect later. When this assertion loses the challenge, all the stakers in this pool will lose their funds. 

**This issue is because if the deployed assertion pool has an immutable `assertionHash` equal to zero, then the assertion hash of the newly created invalid assertion will not be enforced to be equal to the immutable `assertionHash`.**

## Recommended Mitigation Steps
It is recommended that if the `assertionHash` is zero during deploying the assertion staking pool, then an access control mechanism should be activated on the function `createAssertion`.

```solidity
    bool public immutable accessControlActivated;
    constructor(
        address _rollup,
        bytes32 _assertionHash
    ) AbsBoldStakingPool(IRollupCore(_rollup).stakeToken()) {
        //.....
        if(_assertionHash == 0){
            accessControlActivated = true;
        } else {
            accessControlActivated = false;
        }
    }

    function createAssertion(AssertionInputs calldata assertionInputs) external {
        if(accessControlActivated){
            require(msg.sender == admin, "not authorized to call this function");
        }
        //......
    }
```
