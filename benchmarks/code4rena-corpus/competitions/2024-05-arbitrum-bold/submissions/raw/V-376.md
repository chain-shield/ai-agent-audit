# Vulnerability details

## root of the bug 
The bug is from the logical conditions that is used in the function to determine if a validator is AFK, s the function independently checks two conditions using a logical or operator, which can lead to incorrect results here :
```solidity
if (latestConfirmedAssertion.firstChildBlock > 0) {
    return latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number;
}
return latestConfirmedAssertion.createdAtBlock + VALIDATOR_AFK_BLOCKS < block.number;

```
The _validatorIsAfk function is  checks if a validator is considered AFK by evaluating the block number of the last confirmed assertion and its first child block here The logic aims to return true if either condition is met:
- the first child block of the latest confirmed assertion is more than VALIDATOR_AFK_BLOCKS blocks ago.
- so if the creation block of the latest confirmed assertion is more than VALIDATOR_AFK_BLOCKS blocks ago.
the function uses a logical or approach, meaning if either condition independently is true, it will return true. This can incorrectly mark a validator as AFK if one of the conditions is met, but not both, which can lead to unintended removal of the validator whitelist.
and this affected this -->https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L70C2-L76C1 : 
```solidity 
function removeWhitelistAfterValidatorAfk() external {
    require(!validatorWhitelistDisabled, "WHITELIST_DISABLED");
    require(_validatorIsAfk(), "VALIDATOR_NOT_AFK");
    validatorWhitelistDisabled = true;
}
```
## Impact
The incorrect logic in the _validatorIsAfk function can lead to an  enabling of the validatorWhitelistDisabled flag If validators are incorrectly marked as AFK, the whitelist can be removed prematurely, potentially allowing unauthorized validators to participate in the validation process.
## Proof of Concept
here is a s scenario that show how the incorrect handling of conditions can lead to the premature marking of validators as AFK, which then allows the validator whitelist to be disabled incorrectly.
- lets say we have in the assumptions:
VALIDATOR_AFK_BLOCKS = 201600
Current block number (block.number) = 300000
- and in Latest Confirmed Assertion:
createdAtBlock = 100
firstChildBlock = 50
- so the Expected Behavior is tat the validator should not be considered AFK because neither firstChildBlock + VALIDATOR_AFK_BLOCKS nor createdAtBlock + VALIDATOR_AFK_BLOCKS should be less than block.number.
- so the validator is incorrectly marked as AFK.
- initialize the Assertion Storage:
```python 
assertion_storage = {
    1: {'createdAtBlock': 100, 'firstChildBlock': 50}
}
current_block_number = 300000
```
the _validatorIsAfk Function check :
```solidity
function _validatorIsAfk() internal view returns (bool) {
    AssertionNode memory latestConfirmedAssertion = getAssertionStorage(latestConfirmed());
    if (latestConfirmedAssertion.createdAtBlock == 0) return false;
    // We consider the validator is gone if the last known assertion is older than VALIDATOR_AFK_BLOCKS
    // Which is either the latest confirmed assertion or the first child of the latest confirmed assertion
    if (latestConfirmedAssertion.firstChildBlock > 0) {
        return latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number;
    }
    return latestConfirmedAssertion.createdAtBlock + VALIDATOR_AFK_BLOCKS < block.number;
}
```
here is retrieve the latest confirmed assertion:
```solidity
latestConfirmedAssertion = getAssertionStorage(latestConfirmed());
// latestConfirmedAssertion = { createdAtBlock: 100, firstChildBlock: 50 }
```
here is check if firstChildBlock is greater than 0:
```solidity
if (latestConfirmedAssertion.firstChildBlock > 0) {
    // true, because firstChildBlock = 50
    return latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number;
    // Evaluates to 50 + 201600 < 300000
    // 201650 < 300000 is true
}
```
condition is true, _validatorIsAfk returns true, incorrectly marking the validator as AFK.
the function removeWhitelistAfterValidatorAfk is called:
```solidity
function removeWhitelistAfterValidatorAfk() external {
    require(!validatorWhitelistDisabled, "WHITELIST_DISABLED");
    require(_validatorIsAfk(), "VALIDATOR_NOT_AFK");
    validatorWhitelistDisabled = true;
}
```
Since _validatorIsAfk() incorrectly returns true, the whitelist is disabled:
```solidity
validatorWhitelistDisabled = true;

```
