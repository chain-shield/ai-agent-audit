# Vulnerability details

## Impact
The `formBlobDataHash` function is responsible for calculating the gas cost associated with processing a set of blobs. This gas cost is then used for various purposes, such as fee calculation, gas reimbursement, or gas limit checks. The issue is in the calculation of the `blobCost` variable: [src\bridge\SequencerInbox.sol:742](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L742)
```solidity
uint256 blobCost = reader4844.getBlobBaseFee() * GAS_PER_BLOB * dataHashes.length;
```
The `blobCost` is calculated by multiplying the `getBlobBaseFee()` (which is likely a constant value representing the base fee for a single blob) with GAS_PER_BLOB (another constant) and the `dataHashes.length`.

However, the final line of the function: [src\bridge\SequencerInbox.sol:746](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L746)
```solidity
block.basefee > 0 ? blobCost / block.basefee : 0
```
divides the `blobCost` by the current `block.basefee`. This calculation assumes that the `blobCost` represents the total gas cost for processing all the blobs, which is not the case based on the previous calculation.

**The correct way to calculate the total gas cost would be:**
```solidity
uint256 blobCost = reader4844.getBlobBaseFee() * dataHashes.length;
return (
    keccak256(bytes.concat(header, DATA_BLOB_HEADER_FLAG, abi.encodePacked(dataHashes))),
    timeBounds,
    block.basefee > 0 ? (blobCost * GAS_PER_BLOB) / block.basefee : 0
);
```
By removing the multiplication with `GAS_PER_BLOB` from the `blobCost` calculation and instead multiplying it with `GAS_PER_BLOB` when calculating the final gas cost, the function should correctly compute the total gas cost for processing all the blobs.

## Proof of Concept
Assume `reader4844.getBlobBaseFee()` returns `100` (base fee for a single blob).
Assume `GAS_PER_BLOB` is `1000` (gas cost for processing a single blob).
Assume `dataHashes.length` is `5` (there are 5 blobs to process).
Assume `block.basefee` is `10` (the current base fee for the block).

In this scenario, the `blobCost` calculation would be:
```solidity
uint256 blobCost = reader4844.getBlobBaseFee() * GAS_PER_BLOB * dataHashes.length;
                 = 100 * 1000 * 5
                 = 500,000
```
However, the final gas cost calculation would be:
```solidity
block.basefee > 0 ? blobCost / block.basefee : 0
                 = 500,000 / 10
                 = 50,000
```
The expected gas cost for processing 5 blobs should be:
```solidity
(100 * 5) * 1000 = 500,000
```
But the function incorrectly calculates it as `50,000`, which is an order of magnitude lower than the expected value.

This clearly demonstrates how the bug in the `formBlobDataHash` function can lead to an incorrect calculation of the total gas cost for processing blobs, potentially causing issues with fee calculation, gas reimbursement, or gas limit violations within the protocol.
