## Impact

The issue is in the following line: [MerkleTreeLib.sol:340](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/libraries/MerkleTreeLib.sol#L340)
```solidity
assert(size <= postSize);
```
The `assert` statement is used to check if the `size` variable is less than or equal to the `postSize` parameter. However, the use of `assert` is not recommended, as it can lead to unexpected behavior and potential security vulnerabilities.

> According to the Solidity documentation, the `assert` function should only be used to check for internal errors and invariants. If an `assert` fails, it will consume all the remaining gas and revert the entire transaction, which can be problematic in certain scenarios.

Source: Solidity Documentation - [Assert](https://solidity.readthedocs.io/en/latest/control-structures.html?highlight=assert#assert)

## Proof of Concept
The behavior of `assert` can be unexpected, especially for users who are not familiar with its specific behavior. When an `assert` fails, the entire transaction is reverted, but the state changes made before the `assert` statement are not rolled back. This can lead to inconsistent or unexpected contract state, making it harder to reason about the contract's behavior.

Let's consider the following example
```solidity
function transferFunds(address recipient, uint256 amount) public {
    require(balances[msg.sender] >= amount, "Insufficient balance");
    balances[msg.sender] -= amount;
    // Some other operations...
    assert(amount > 0); // Assume this condition is violated
    balances[recipient] += amount;
}
```
In this example, if the `assert` statement fails, the transaction will revert, but the sender's balance will still be deducted. This can lead to an inconsistent state where funds are effectively lost or locked.

## Recommended Mitigation Steps
Instead of using assert, it would be better to use a `require` statement or a custom error to handle the condition where size exceeds `postSize`. This would allow for a more graceful error handling and provide better feedback to the caller.
```solidity
if (size > postSize) {
    revert("Size exceeds post size");
}
```
Or, using a custom error:
```solidity
error SizeExceedsPostSize();

if (size > postSize) {
    revert SizeExceedsPostSize();
}
```
By replacing the `assert` statement with a `require` or a custom error, the function will revert the transaction with a clear error message when the condition is not met, rather than consuming all the remaining gas
