# Vulnerability details

## Impact
The **createBridge** function in the **BridgeCreator** contract lacks proper access control, allowing any address to call it and create new bridge contracts. 

This vulnerability can lead to:

Unauthorized Bridge Creation: Malicious users can deploy unauthorized or potentially malicious bridge instances, compromising the integrity and security of the system.

Resource Exhaustion: An attacker can repeatedly invoke the function, leading to excessive consumption of network resources and gas.

Financial Loss: Unauthorized bridges might be used for fraudulent activities, resulting in significant financial losses.

Reputation Damage: The deployment of unauthorized or rogue bridge contracts could damage the project's reputation and erode user trust.

2. Call the createBridge function from any address without restrictions.
3. Observe that the function executes successfully, creating new bridge contracts without any authorization check.

## Recommended Mitigation Steps

To mitigate this vulnerability, the createBridge function should be restricted to the contract owner by adding the onlyOwner modifier. This ensures that only authorized users can call this function.

        address adminProxy,
        address rollup,
        address nativeToken,
        ISequencerInbox.MaxTimeVariation calldata maxTimeVariation,
        BufferConfig calldata bufferConfig
