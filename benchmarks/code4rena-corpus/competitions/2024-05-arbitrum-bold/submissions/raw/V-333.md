# Vulnerability details

## Impact

Reorg attacks causes users to deposit funds in the wrong contract.

## Proof of Concept

The createPool() function deploys a new EdgeStakingPool using create, where the address derivation depends solely on the EdgeStakingPool nonce.

```
    function createPool(
        address challengeManager,
        bytes32 edgeId
    ) external returns (IEdgeStakingPool) {
>       EdgeStakingPool pool = new EdgeStakingPool{salt: 0}(challengeManager, edgeId);
        emit NewEdgeStakingPoolCreated(challengeManager, edgeId);
        return pool;
    }
```

Since this contract is deployed on Ethereum, re-orgs can happen, like [here](https://decrypt.co/101390/ethereum-beacon-chain-blockchain-reorg): 

Imagine that Alice deploys a new EdgeStakingPool, and send funds to it. Bob sees that there is a reorg happening and calls createPool. Thus, it creates a EdgeStakingPool with an address to which Alice sends her funds. Alice transactions are executed and Alice transfers funds to Bob's controlled EdgeStakingPool. 

This is a Medium severity issue that has been referenced from below Code4rena reports:
https://code4rena.com/reports/2023-01-rabbithole/#m-01-questfactory-is-suspicious-of-the-reorg-attack
https://code4rena.com/reports/2023-04-frankencoin#m-14-re-org-attack-in-factory

## Tools Used

Manual Review

## Recommended Mitigation Steps

Deploy such contracts via create2 with salt that includes msg.sender.
