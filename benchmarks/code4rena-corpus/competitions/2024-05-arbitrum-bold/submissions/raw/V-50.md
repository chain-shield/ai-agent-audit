# Vulnerability details

## Impact
The `verifyInclusionProof` function in the `MerkleTreeLib` library accepts a zero hash as the `rootHash` parameter without proper validation. If the calculated root hash based on the provided proof and leaf matches the zero hash, the function considers the inclusion proof as valid, even if the proof is not actually valid. 

The vulnerability of accepting a zero hash as the root hash in the verifyInclusionProof function can have severe consequences for the integrity and security of the system. Attackers can exploit this vulnerability to fabricate proofs and claim inclusion of arbitrary leaves in the Merkle tree, even if those leaves are not actually present. This can lead to a wide range of malicious activities, such as:

Unauthorized access to resources or assets associated with the fabricated leaves.

Manipulation of the system's state, leading to inconsistencies and errors.

Disruption of the protocol's functionality and availability.

Loss of trust in the system, as users cannot rely on the integrity of the Merkle tree.

The impact of this vulnerability extends beyond just the immediate consequences of accepting invalid proofs. It undermines the fundamental purpose of using a Merkle tree for efficient and secure verification of data integrity. Attackers can exploit this vulnerability to bypass the security measures put in place by the Merkle tree and compromise the overall reliability and trustworthiness of the system.

## Proof of Concept
The attacker analyzes the `verifyInclusionProof` function and identifies that it accepts a zero hash as the `rootHash` parameter without proper validation.

The attacker constructs a malicious proof that, when processed by the function, results in a calculated root hash of zero. This can be achieved by carefully crafting the proof and leaf data to manipulate the Merkle tree calculations.

The attacker calls the `verifyInclusionProof` function, passing the malicious proof, a zero hash as the `rootHash`, and a chosen leaf and index.

The function processes the proof and calculates the root hash based on the provided proof and leaf.

The calculated root hash matches the provided zero hash, causing the function to incorrectly consider the proof as valid.

The attacker can now claim inclusion of the chosen leaf in the Merkle tree, even though it is not actually present.

The attacker can repeat this process with different fabricated proofs and leaves, effectively manipulating the system's state and bypassing the security measures of the Merkle tree.

The attacker can exploit this vulnerability to gain unauthorized access to resources, disrupt the protocol's functionality, or perform other malicious activities.
