# Vulnerability details

## Impact

The current functionality of `RollupUserLogic` and `RollupCore` smart contracts allows the users to create as many assertions as they want. Additionally, the users can create as many edges as they want that are related to the corresponding assertions (that claimed to be true). The problem is that such implementation where multiple assertions can be created opens up an attack vector where adversary can create multiple different assertions and therefore edges for them and it'll require another party (trust confirmer, for instance) that will be able to interfere into the process of disputing.

## Proof of Concept

Let's say the first user who is a malicious actor creates the first assertion A. His assertion will be assigned to the `block.number` at the time of creation:

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/challengeV2/EdgeChallengeManager.sol#L86-87
```    
if (self.firstChildBlock == 0) {
self.firstChildBlock = uint64(block.number);
```

Now let's say the second assertion is also created by the same malicious entity and it also contains incorrect information about the state:


https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/Assertion.sol#L88-89
```
 } else if (self.secondChildBlock == 0) {
 self.secondChildBlock = uint64(block.number);

```

Then the adversary can create a block level edge (also with an incorrect state) for each of his assertions making them rivals (with different `endHistoryRoot`). Once the first rival is added, any other rival edges will not be accounted for:

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/challengeV2/libraries/EdgeChallengeManagerLib.sol#L182-189
```
 if (firstRival == 0) {
            store.firstRivals[mutualId] = UNRIVALED;
        } else if (firstRival == UNRIVALED) {
            store.firstRivals[mutualId] = eId;
        } else {
            // after we've stored the first rival we dont need to keep a record of any
            // other rival edges - they will all have a zero time unrivaled
        }

```

And as time unrivaled is 0, it'll not be possible to confirm the honest edge by time, so this scenario would need some admin action involved.
