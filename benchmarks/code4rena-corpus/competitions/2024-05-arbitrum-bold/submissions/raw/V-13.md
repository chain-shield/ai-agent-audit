# Vulnerability details

## Impact
The absence of the logic to check for the existence of a pool and revert the transaction if it does not exist could lead to unintended behavior. Users might attempt to create or retrieve a pool that already exists, leading to potential confusion or misuse of the contract.

## Proof of Concept
The `IEdgeStakingPoolCreator` interface, located at [this link](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/interfaces/IEdgeStakingPoolCreator.sol#L24), specifies the creation and retrieval of staking pools. However, it mentions that the `IEdgeStakingPoolCreator::createPool` and `IEdgeStakingPoolCreator::getPool` functions should revert if a pool does not exist for the provided parameters. This expected behavior is documented but not implemented in the interface.

```
@>    function createPool(
        address challengeManager,
        bytes32 edgeId
    ) external returns (IEdgeStakingPool);

    /// @notice get staking pool deployed with provided inputs; reverts if pool contract doesn't exist.
    /// @param challengeManager EdgeChallengeManager contract
    /// @param edgeId The ID of the edge to be created (see ChallengeEdgeLib.id)
@>    function getPool(
        address challengeManager,
        bytes32 edgeId
    ) external view returns (IEdgeStakingPool);
```

The issue arises from the comments describing the behavior of the `createPool` and `getPool` functions, which indicate that the functions should revert if a pool does not exist. However, the actual implementation of these checks is not present in the provided code snippet.

## Recommended Mitigation Steps with Fix Code
To address this issue, the contract implementing the `IEdgeStakingPoolCreator` interface should include a mechanism to track the existence of pools. This could be achieved by using a mapping to store the addresses of created pools. Before creating a new pool, the contract should check if a pool already exists for the given parameters. If a pool exists, the transaction should be reverted. Here's an illustrative example of how this could be implemented:

```solidity
contract EdgeStakingPoolCreator is IEdgeStakingPoolCreator {
    mapping(bytes32 => address) private poolAddresses;

    function createPool(address challengeManager, bytes32 edgeId) external override returns (IEdgeStakingPool) {
        require(poolAddresses[edgeId] == address(0), "Pool already exists");
        // Logic to create the pool and store its address
        //...
        emit NewEdgeStakingPoolCreated(challengeManager, edgeId);
        return IEdgeStakingPool(poolAddresses[edgeId]);
    }

    function getPool(address challengeManager, bytes32 edgeId) external view override returns (IEdgeStakingPool) {
        require(poolAddresses[edgeId]!= address(0), "Pool does not exist");
        return IEdgeStakingPool(poolAddresses[edgeId]);
    }
}
```

This implementation ensures that the contract behaves as expected, preventing the creation of duplicate pools and allowing for the retrieval of existing pools based on the provided parameters.
