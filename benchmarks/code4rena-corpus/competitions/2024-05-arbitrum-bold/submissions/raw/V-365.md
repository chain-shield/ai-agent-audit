# Vulnerability details

## Impact

The `initialize` function in the `EdgeChallengeManager` contract ensures the `_stakeAmounts` array length matches `_numBigStepLevel + 2`. However, it doesn't verify that all values in `_stakeAmounts` are non-zero. This oversight can lead to significant issues in staking logic.

If any element in `_stakeAmounts` is zero, validators might create edges without staking any tokens. This bypasses the economic penalties designed to deter incorrect assertions or malicious behavior, undermining the protocol's economic security. For instance, if `_stakeAmounts[0]` is zero, a validator can create a zero-layer block edge without any financial stake, removing their incentive to act honestly.

The staking mechanism's purpose is to ensure validators have a financial commitment to the protocol. Zero staking amounts would allow validators to make arbitrary assertions without financial risk, flooding the system with invalid assertions and causing unnecessary disputes. This could overwhelm the challenge mechanism, leading to delays and increased operational costs.

Additionally, with zero stakes, malicious actors can create numerous assertions without cost, potentially resulting in a Denial of Service (DoS) attack. This would force honest validators to respond to each challenge, consuming significant computational resources and potentially halting the protocol's operations. This highlights the critical need for validating non-zero values in `_stakeAmounts` to maintain the protocol's security and functionality.

## Recommended Mitigation Steps

```solidity
     for (uint256 i = 0; i < _stakeAmounts.length; i++) {
         if (_stakeAmounts[i] == 0) {
             revert InvalidStakeAmount(i);
         }
     }
```
