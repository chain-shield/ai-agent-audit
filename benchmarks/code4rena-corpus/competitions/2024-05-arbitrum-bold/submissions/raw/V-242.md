# Vulnerability details

## Impact
The way the `executors` array is initialized and passed to the initialize function of the UpgradeExecutor contract.

The code creates an array `executors` with a length of 1 and assigns the `rollupOwner` address to the first element: [RollupCreator.sol:280-281](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L280-L281)
```solidity
address[] memory executors = new address[](1);
executors[0] = rollupOwner;
```
However, when the initialize function is called, the entire executors array is passed as an argument: [RollupCreator.sol:282](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L282)
```solidity
upgradeExecutor.initialize(address(upgradeExecutor), executors);
```
This means that if the `initialize` function expects an array of authorized executors, it will only receive a single address (`rollupOwner`). If the intention is to have multiple authorized executors, this code will not work as expected.

## Proof of Concept
The [_deployUpgradeExecutor](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L267) function is responsible for deploying and initializing the `UpgradeExecutor` contract, which is a crucial component of the system. The `UpgradeExecutor` contract is designed to allow authorized addresses (executors) to execute certain privileged operations, such as upgrading the contracts or performing administrative tasks.

The initialize function of the `UpgradeExecutor` contract is expected to receive an array of authorized executor addresses. However, the way the `executors` array is initialized in the `_deployUpgradeExecutor` function is incorrect: [RollupCreator.sol:280-282](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L280-L282)
```solidity
address[] memory executors = new address[](1);
executors[0] = rollupOwner;
upgradeExecutor.initialize(address(upgradeExecutor), executors);
```
By creating an array of length 1 and assigning the `rollupOwner` address to the first element, the code is effectively passing only a single authorized executor (`rollupOwner`) to the initialize function.

If the intention is to have multiple authorized executors, this code will not work as expected. The `UpgradeExecutor` contract will be initialized with only the `rollupOwner` address as the authorized executor, even if the system is designed to have multiple authorized executors.

**This can lead to several potential issues**

> If the system is designed to have multiple authorized executors for security and accountability purposes, having only a single authorized executor defeats that purpose. A malicious or compromised `rollupOwner` address would have complete control over the privileged operations, introducing a single point of failure.

> If the system requires multiple authorized executors to approve and execute upgrades or administrative tasks, the current implementation would prevent such operations from being performed as intended, potentially leading to a stuck or non-upgradeable system.

> If the system's security assumptions and design rely on having multiple authorized executors, the current implementation violates those assumptions, potentially introducing vulnerabilities and weakening the overall security of the system.

## Recommended Mitigation Steps
Either:

**_Ensure that the `initialize` function expects a single address as an argument_** If the initialize function is designed to accept a single address as an authorized executor, then the current code is correct.

**_Initialize the `executors` array with the correct number of addresses_** If the initialize function expects an array of authorized executors, you should initialize the executors array with the correct number of addresses. For example:
```solidity
address[] memory executors = new address[](2); // Assuming you want two authorized executors
executors[0] = rollupOwner;
executors[1] = anotherAuthorizedAddress; // Replace with the second authorized address
```
It's important to ensure that the `initialize` function of the `UpgradeExecutor` contract is designed to handle the expected input correctly, and that the `executors` array is initialized with the correct number and values of authorized executors.
