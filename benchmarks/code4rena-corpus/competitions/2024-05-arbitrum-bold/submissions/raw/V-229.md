# Vulnerability details

## Impact
An issue in the calculation of `amountWithdrawn` of [reduceStakeTo function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L300-L310). The function calculates `amountWithdrawn` as: [src\rollup\RollupCore.sol:305](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L305)
```solidity
uint256 amountWithdrawn = current - target;
```
This calculation assumes that target is always less than current. If target is greater than current, the subtraction will result in an underflow, leading to an incorrect value for amountWithdrawn.

**Incorrect Calculation of amountWithdrawn:**

If `target` is greater than `current`, the subtraction `current - target` will result in an underflow.
In Solidity, an underflow for an unsigned integer type (like `uint256`) will wrap around to a very large value instead of reverting or throwing an error.
For example, if `current` is 100 and `target` is 200, `amountWithdrawn` will be calculated as `100 - 200 = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFC60` (a very large value).

**Incorrect Update of Staker's Stake:**

The function updates the staker's stake to `target` without considering the case where `target` is greater than `current`.
If `target` is greater than c`urrent`, the staker's stake should be set to zero, but it will be incorrectly set to `target`.

**Incorrect Increase of Withdrawable Funds:**

The function calls `increaseWithdrawableFunds` with the incorrect `amountWithdrawn` value.
If `amountWithdrawn` is a very large value due to underflow, it will result in an excessive increase of `withdrawable` funds for the staker's withdrawal address.

## Proof of Concept
Consider the following scenario:
A staker has a current stake of 100 tokens.
The staker calls `reduceStakeTo` with `target` set to 200 (greater than the current stake).
The function will calculate `amountWithdrawn` as `100 - 200 = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFC60` (a very large value).
The staker's stake will be incorrectly updated to 200 instead of being set to zero.
The withdrawable funds for the staker's withdrawal address will be increased by the very large `amountWithdrawn` value, potentially leading to unintended token transfers or other security issues.

The impact of this issue is that it can lead to incorrect state updates, potentially allowing stakers to withdraw more funds than they should be entitled to or causing other unintended behavior in the contract. It's essential to handle the case where target is greater than current to ensure the correctness of the calculations and state updates.

## Recommended Mitigation Steps
he function should handle the case where `target` is greater than `current`. One way to do this is to add an additional check before calculating `amountWithdrawn`
```solidity
function reduceStakeTo(address stakerAddress, uint256 target) internal returns (uint256) {
    Staker storage staker = _stakerMap[stakerAddress];
    address withdrawalAddress = staker.withdrawalAddress;
    uint256 current = staker.amountStaked;
    require(target <= current, "TOO_LITTLE_STAKE");

    uint256 amountWithdrawn;
    if (target < current) {
        amountWithdrawn = current - target;
        staker.amountStaked = target;
    } else {
        amountWithdrawn = current;
        staker.amountStaked = 0;
    }

    increaseWithdrawableFunds(withdrawalAddress, amountWithdrawn);
    emit UserStakeUpdated(stakerAddress, withdrawalAddress, current, target);
    return amountWithdrawn;
}
```
If `target` is less than `current`, the function calculates `amountWithdrawn` as before and updates the staker's stake to `target`. If `target` is greater than or equal to `current`, the function sets `amountWithdrawn` to the entire current stake (`current`) and sets the staker's stake to zero.

By handling this edge case, the function ensures that `amountWithdrawn` is calculated correctly, and the staker's stake is updated appropriately, even when `target` is greater than or equal to `current`.
