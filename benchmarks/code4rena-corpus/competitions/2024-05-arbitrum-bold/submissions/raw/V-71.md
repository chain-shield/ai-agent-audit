# Vulnerability details

## Impact
If an edge has already been created and the function `createEdge` is called again, it will attempt to transfer the required stake tokens. If there are insufficient tokens in the `EdgeStakingPool`, the transfer will fail, causing the function to revert. This can disrupt the normal operation of the staking pool and potentially lock users out of their stakes.


## Proof of Concept
The `createEdge` function in the `EdgeStakingPool` contract might not handle the scenario where an edge has already been created. This can potentially lead to reversion issues during token transfers if the edge creation logic does not internally check for already existing edges. Below is the relevant code snippet from the EdgeStakingPool contract:
```solidity
function createEdge(CreateEdgeArgs calldata args) external {
    uint256 requiredStake = EdgeChallengeManager(challengeManager).stakeAmounts(args.level);
    IERC20(stakeToken).safeIncreaseAllowance(address(challengeManager), requiredStake);
    bytes32 newEdgeId = EdgeChallengeManager(challengeManager).createLayerZeroEdge(args);
    if (newEdgeId != edgeId) {
        revert IncorrectEdgeId(newEdgeId, edgeId);
    }
}

```
In this function:
1. The required stake amount is fetched.
2. The allowance for the `challengeManager` to transfer the stake is increased.
3. The `createLayerZeroEdge` function is called to create the edge.
4. The function checks if the newly created edge ID matches the expected `edgeId`.
The mock implementation of `EdgeChallengeManager.createLayerZeroEdge` does not account for edges that have already been created, leading to potential issues:
```solidity
function createLayerZeroEdge(CreateEdgeArgs calldata args) external returns (bytes32) {
    stakeToken.transferFrom(msg.sender, address(this), stakeAmounts(args.level));
    emit EdgeCreated(args);
    return keccak256(abi.encode(args));
}
```
This implementation transfers the required stake and returns an edge ID based on the input arguments without checking for pre-existing edges.

## Recommended Mitigation Steps
The `createEdge` function should be updated to check if an edge has already been created with the given arguments and revert if it has. This ensures that the `createEdge` function in the `EdgeStakingPool` does not proceed with token transfers for already existing edges.
