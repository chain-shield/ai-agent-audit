# Vulnerability details

## Impact
`refundStake` function is marked as public, anyone can call it and potentially refund the stake for any edge, which could lead to unauthorized refunds if the function is not properly guarded. Any external party can call the `refundStake` function and refund the stake for any edge, even if they are not the legitimate staker or an authorized party.

The [refundStake function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L572-L585) is marked as public, allowing anyone to call it without any access restrictions:

```solidity
function refundStake(bytes32 edgeId) public {
    ChallengeEdge storage edge = store.get(edgeId);
    // ...
}
```
This code snippet demonstrates the lack of access control, as there are no checks or restrictions on who can call this function and refund the stake for a given `edgeId`.

## Proof of Concept
Consider the following scenario:

Alice creates an edge and stakes 100 tokens as part of the challenge system.
Bob, a malicious actor, calls the `refundStake` function with Alice's `edgeId`, even though he is not the legitimate staker or an authorized party.
The `refundStake` function executes without any access control checks, allowing Bob to refund Alice's stake of 100 tokens to his own address.

In this scenario, Bob has successfully refunded Alice's stake without authorization, resulting in a financial loss for Alice and undermining the integrity of the challenge system.

## Recommended Mitigation Steps
It would be better to implement access control mechanisms such as restricting the `refundStake` function to be callable only by the edge staker or an authorized party.

```solidity
function refundStake(bytes32 edgeId) public onlyStaker(edgeId) {
    // ...
}

modifier onlyStaker(bytes32 edgeId) {
    ChallengeEdge storage edge = store.get(edgeId);
    require(msg.sender == edge.staker, "Only the staker can refund");
    _;
}
```
