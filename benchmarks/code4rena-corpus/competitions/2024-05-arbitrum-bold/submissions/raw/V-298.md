# Vulnerability details


## Cause

In the [`RollupCreator` contract, the `confirmPeriodBlocks` value from the rollup configuration, which is **related to assertions**, is incorrectly passed as the `_challengePeriodBlocks` parameter](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/RollupCreator.sol#L101), **related to edges**, when initializing the challenge manager.

Crucially, this does not appear to be intentional, as the `confirmPeriodBlocks` and `challangePeriodBlocks` values are separated correctly elsewhere:

- In [`RollupAdminLogic` that same Config struct's `confirmPeriodBlocks` value](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/RollupAdminLogic.sol#L47) is used to assign the right type of value.
- In[ `BOLDUpgradeAction`, `_challengePeriodBlocks` is set correctly](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/BOLDUpgradeAction.sol#L505) using [`CHALLENGE_PERIOD_BLOCKS`, which is distinct from `CONFIRM_PERIOD_BLOCKS`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/BOLDUpgradeAction.sol#L198-L199).


## Impact

If the `confirmPeriodBlocks` and `challengePeriodBlocks` values are intended to be set differently for some rollup created via the factory on L2, an incorrect value will be used for the challenge period. Depending on the direction of the mismatch this will have the following impacts:

1. If the resulting edge challenge period is too long, it can delay withdrawals unnecessarily, causing DoS. This is because the challenge period will be unnecessarily delayed.
2. If the resulting edge challenge period is too short, it may not allow enough time for censorship resistance, potentially allowing fraudulent withdrawals and loss of funds due to insufficient dispute game time. This is because the challenge period will be insufficiently short.

## Recommended Mitigation Steps

To fix this issue, add a separate `challengePeriodBlocks` field to the `Config` struct and use it when initializing the challenge manager:

```diff
# src/rollup/Config.sol

struct Config {
    uint64 confirmPeriodBlocks;
+    uint64 challengePeriodBlocks;
    address stakeToken;
    uint256 baseStake;

# src/rollup/RollupCreator.sol

        challengeManager.initialize({
            _assertionChain: IAssertionChain(rollupAddr),
-            _challengePeriodBlocks: config.confirmPeriodBlocks,
+            _challengePeriodBlocks: config.challengePeriodBlocks,
            _oneStepProofEntry: osp,
```
