# Vulnerability details

## Impact
Validators will be unable to add or reduce deposits after edge confirmations because the time window for executing these actions is too small.

## Proof of Concept
Validators can add or reduce deposits after the edge has been confirmed. The issue is that the timeframe for executing these actions is too small. It is almost impossible for a validator to time this small timeframe. If some time has passed since the edge confirmation (e.g a few seconds), there will be an assertion hash mismatch in validateAssertionHash() and the validator will be unable to add or reduce deposits. This breaks an important functionality of the protocol, which is that validators should be able to add and reduce deposits.

The tests below can be added to Rollup.t.sol to demonstrate the described scenario.

```
    function testCantReduceDepositAfter1SecondPasses() public {
        testSuccessConfirmEdgeByTime();
        vm.warp(block.timestamp + 1);
        vm.prank(validator1);
        userRollup.reduceDeposit(1);
    }

    function testCantAddDepositAfter1SecondPasses() public {
        testSuccessConfirmEdgeByTime();
        vm.warp(block.timestamp + 1);
        vm.prank(validator1);
        userRollup.addToDeposit(validator1, 1);
    }

```
## Tools Used
Manual Review

## Recommended Mitigation Steps
The protocol should add a sufficient time period for validators to be able to add and reduce deposits.
