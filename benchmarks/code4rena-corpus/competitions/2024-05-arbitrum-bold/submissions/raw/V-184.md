# Vulnerability details

```solidity
    function _validatorIsAfk() internal view returns (bool) {
        AssertionNode memory latestConfirmedAssertion = getAssertionStorage(latestConfirmed());
        if (latestConfirmedAssertion.createdAtBlock == 0) return false;
        // We consider the validator is gone if the last known assertion is older than VALIDATOR_AFK_BLOCKS
        // Which is either the latest confirmed assertion or the first child of the latest confirmed assertion
        if (latestConfirmedAssertion.firstChildBlock > 0) {
            return latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number;
        }
        return latestConfirmedAssertion.createdAtBlock + VALIDATOR_AFK_BLOCKS < block.number;
    }
```

There is a potential bug in the [_validatorIsAfk function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L51-L60). The issue lies in the condition for checking if the validator is considered AFK (away from the keyboard) when there is a first child block.

**The condition: [L56-L57](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L56-L58)**
```solidity
if (latestConfirmedAssertion.firstChildBlock > 0) {
    return latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number;
}
```
This condition assumes that if there is a first child block, the validator is considered **AFK** if the first child block number plus `VALIDATOR_AFK_BLOCKS` is less than the current block number. However, this logic seems flawed.

**The correct condition should likely be:**
```solidity
if (latestConfirmedAssertion.firstChildBlock > 0) {
    return block.number > latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS;
}
```
_This condition checks if the current block number is greater than the sum of the first child block number and `VALIDATOR_AFK_BLOCKS`. If this condition is true, it means that the validator has been inactive for too long (more than `VALIDATOR_AFK_BLOCKS` blocks) since the first child block, and therefore should be considered AFK._

> The original condition `latestConfirmedAssertion.firstChildBlock + VALIDATOR_AFK_BLOCKS < block.number` seems to be checking the opposite of what is intended, which could lead to incorrect results.

This function is likely used to identify validators who have been unresponsive or inactive for an extended period, which could be a crucial factor in various aspects of the system's operation, _such as consensus mechanisms, reward distribution, or validator rotation._
