# Vulnerability details

[src\rollup\RollupCore.sol:317-324 increaseWithdrawableFunds function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L317-L324) is called with the `withdrawalAddress` and the `initialStaked` amount. However, the `initialStaked` amount represents the total amount staked by the staker, which may not be the correct amount to add to the withdrawable funds.

If the staker has previously withdrawn or reduced their stake, the `initialStaked` amount would be higher than the actual remaining stake. In this case, adding the `initialStaked` amount to the withdrawable funds would result in an incorrect balance.

## Impact
If a staker has previously withdrawn or reduced their stake, the `initialStaked` amount stored in the `Staker` struct will be higher than the actual remaining stake amount. When the `withdrawStaker` function is called, it adds the `initialStaked` amount to the withdrawable funds of the `withdrawalAddress`. This means that the withdrawable funds will be inflated by the amount that the staker has already withdrawn or reduced from their stake.

For example, let's assume a staker initially staked 100 tokens (`initialStaked = 100`). Later, they withdrew 20 tokens, reducing their stake to 80 tokens. When the `withdrawStaker` function is called, it will add the `initialStaked` amount of 100 tokens to the withdrawable funds, instead of the actual remaining stake of 80 tokens. This results in an incorrect balance of withdrawable funds, potentially allowing the staker to withdraw more funds than they should be entitled to.

## Proof of Concept
Simplified example to illustrate the issue:
```solidity
pragma solidity ^0.8.0;

contract StakingContract {
    struct Staker {
        uint256 amountStaked;
        uint256 withdrawnAmount;
        address withdrawalAddress;
    }

    mapping(address => Staker) public _stakerMap;

    function stakeTokens(uint256 amount) external {
        _stakerMap[msg.sender].amountStaked = amount;
        _stakerMap[msg.sender].withdrawalAddress = msg.sender;
    }

    function withdrawStaker(address stakerAddress) internal {
        Staker storage staker = _stakerMap[stakerAddress];
        address withdrawalAddress = staker.withdrawalAddress;
        uint256 initialStaked = staker.amountStaked;
        increaseWithdrawableFunds(withdrawalAddress, initialStaked); // Incorrect, should use remaining stake
        deleteStaker(stakerAddress);
    }

    function increaseWithdrawableFunds(address account, uint256 amount) internal {
        // Simplified implementation for illustration purposes
        withdrawableFunds[account] += amount;
    }

    mapping(address => uint256) public withdrawableFunds;
}
```
In this example, if a staker stakes 100 tokens, withdraws 20 tokens, and then calls `withdrawStaker`, the `increaseWithdrawableFunds` function will be called with the `initialStaked` amount of 100 tokens, instead of the remaining stake of 80 tokens. This will result in an incorrect balance of withdrawable funds for the staker's withdrawal address.

## Recommended Mitigation Steps
The function should calculate the actual remaining stake amount before calling `increaseWithdrawableFunds`. One way to do this would be to subtract the `withdrawnAmount` from the `initialStaked` amount, like so:
```solidity
function withdrawStaker(address stakerAddress) internal {
    Staker storage staker = _stakerMap[stakerAddress];
    address withdrawalAddress = staker.withdrawalAddress;
    uint256 remainingStake = staker.amountStaked - staker.withdrawnAmount;   <@
    increaseWithdrawableFunds(withdrawalAddress, remainingStake);  <@
    deleteStaker(stakerAddress);
    emit UserStakeUpdated(stakerAddress, withdrawalAddress, staker.amountStaked, 0);
}
```
By calculating the `remainingStake` and using that value in the `increaseWithdrawableFunds` call, the function will correctly update the withdrawable funds with the actual remaining stake amount.
