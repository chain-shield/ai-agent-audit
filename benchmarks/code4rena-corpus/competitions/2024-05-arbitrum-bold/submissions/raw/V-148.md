# Vulnerability details

The `EdgeStakingPool` contract is a Trustless staking pool contract for creating layer zero edges. people stake in the contract to reach the stake amount to make an edge:

```solidity

function createEdge(CreateEdgeArgs calldata args) external {
        uint256 requiredStake = EdgeChallengeManager(challengeManager).stakeAmounts(args.level);
        IERC20(stakeToken).safeIncreaseAllowance(address(challengeManager), requiredStake);
        bytes32 newEdgeId = EdgeChallengeManager(challengeManager).createLayerZeroEdge(args);
        if (newEdgeId != edgeId) {
            revert IncorrectEdgeId(newEdgeId, edgeId);
        }
    }
```
https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/EdgeStakingPool.sol#L44

The problem is that is not implementing any access control, this is problematic because a malicious user can just call the function creating an false or fake edge in a assertion and make that all the honest user loss his money because the assertion never is going to be valid.



## Impact
Users that stake in the `EdgeStakingPool` contract may loss all his stake is a malicious user or attacker call the `createEdge` function with a false assertion.

## Proof of Concept

## Recommended Mitigation Steps
I think that there is not a easy recommendation for this but i let some options:

* Implement a single owner that is gonna call the createAssertion function, stakers now upfront which is the owner and they can decide if stake in that pool or not.
* Implement a enumerable set, and the createAssertion function can only be called by the address in the set.
* Implement a governance contract.
