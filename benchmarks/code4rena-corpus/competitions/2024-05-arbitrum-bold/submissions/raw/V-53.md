# Vulnerability details

## Impact
The `createRollup` function in the `RollupCreator` contract does not include explicit validations on the size of input data when performing low-level operations. This lack of input data size validation could potentially lead to unintended memory access or buffer overflow vulnerabilities.

The absence of proper validation on input data size in low-level operations can have a significant impact on the protocol's functionality, security, and reliability. Consequences include:

Unintended Memory Access: Without proper input data size validation, an attacker can craft malicious inputs that exceed the expected boundaries. This can lead to reading or writing data to unintended memory locations, potentially exposing sensitive information or corrupting critical data structures.

Buffer Overflow Vulnerabilities: Insufficient input data size validation can result in buffer overflow vulnerabilities. An attacker can exploit these vulnerabilities to overwrite adjacent memory, potentially executing arbitrary code or manipulating the contract's state in unintended ways.

Disruption of Protocol Functionality: Malicious inputs that trigger unintended memory access or buffer overflows can cause unexpected behavior in the protocol. This can lead to inconsistencies in the rollup creation process, such as incorrect data being processed, invalid state transitions, or premature termination of the function.

Denial of Service (DoS) Attacks: Attackers can exploit the lack of input data size validation to cause the contract to consume excessive gas or revert unexpectedly. By repeatedly invoking the vulnerable function with crafted inputs, attackers can disrupt the availability and functioning of the protocol.


## Proof of Concept
An attacker identifies the lack of input data size validation in the `createRollup` function.

The attacker crafts a malicious input with a carefully manipulated data size that exceeds the expected boundaries.

The attacker calls the `createRollup` function with the malicious input.

Due to the lack of input data size validation, the function performs low-level operations on the malicious input, potentially accessing unintended memory locations or causing a buffer overflow.

The unintended memory access or buffer overflow could lead to unexpected behavior, such as overwriting critical data, corrupting the contract's state, or causing the function to revert unexpectedly.

The attacker exploits this vulnerability to disrupt the rollup creation process, causing inconsistencies or unavailability in the protocol.

## Recommended Mitigation Steps
Implement explicit validations on the size of input data when performing low-level operations in the `createRollup` function. Ensure that the input data size is within the expected boundaries and reject any inputs that exceed the allowed size. Additionally, consider using safe arithmetic operations and bounds checking to prevent unintended memory access or buffer overflow vulnerabilities.
