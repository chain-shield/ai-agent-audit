# Vulnerability details

## Impact
The `initialize` function is declared as `external`, which means it can be called by any external account or contract. Without the `initializer` modifier, this function can be called multiple times throughout the contract's lifetime, potentially leading to unintended consequences and vulnerabilities.

If the initialize function is called multiple times with different parameters, it could lead to the following issues:

Overwriting of critical configuration parameters, such as the bridge address, time variation settings, and buffer configurations.

Inconsistent contract state and behavior due to multiple initializations.

Potential exploitation by malicious actors who could call the function with harmful parameters.

## Proof of Concept
An attacker can call the `initialize` function multiple times, effectively overriding the initial setup of the contract. This can be done by crafting a transaction that invokes the `initialize` function with malicious values.

## Tools Used
Manual Review 
## Recommended Mitigation Steps
Implementing a modifier, such as `onlyOwner` or `Initializer`, to restrict access to the function only to authorized entities.
