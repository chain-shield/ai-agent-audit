# Vulnerability details

## Impact
The `newStakeOnNewAssertion` function in the `RollupUserLogic` contract allows users to create a new stake with any amount of tokens. There is no explicit check for a minimum deposit amount, which could lead to dust transactions and associated issues. 

The absence of a minimum deposit amount check can have several impacts:

Dust transactions: Users can create stakes with very small amounts of tokens, leading to a large number of dust transactions. This can bloat the contract's storage and increase gas costs for processing these transactions.

Potential DoS: Malicious users could spam the contract with a large number of small stakes, causing congestion and potentially leading to a Denial-of-Service (DoS) condition. This can impact the contract's performance and availability.

Accounting issues: The presence of dust stakes can complicate the contract's accounting and lead to rounding errors or discrepancies. This can affect the accuracy of stake tracking and reward calculations.

## Proof of Concept
An attacker can create a large number of small stakes by calling the `newStakeOnNewAssertion` function repeatedly with minimal token amounts. This can be done programmatically or through a script that generates multiple transactions with dust amounts.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a minimum deposit amount check in the `newStakeOnNewAssertion` function. Reject stakes that do not meet the minimum required amount.
