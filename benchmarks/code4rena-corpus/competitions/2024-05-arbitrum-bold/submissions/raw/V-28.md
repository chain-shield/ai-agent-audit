# Vulnerability details

## Impact
The initialize function in `EdgeChallengeManager.sol` is missing the initializer modifier. Without this modifier, there is a risk that the initialization function can be called multiple times, leading to unintended behavior or vulnerabilities.

Attackers can exploit this vulnerability to reinitialize the contract, potentially modifying critical contract parameters such as `challengePeriodBlocks`, `assertionChain`, `oneStepProofEntry`, and others. This can disrupt the normal operation of the contract and compromise the integrity of the challenge management system.


## Proof of Concept
An attacker can call the `initialize` function multiple times with different parameters, effectively overriding the initial setup of the contract. This can be done by crafting a transaction that invokes the `initialize` function with malicious values.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implementing a modifier, such as `onlyOwner` or `Initializer`, to restrict access to the function only to authorized entities.
