# Vulnerability details

## Impact
In the `initialize` function the validation of the `_stakeAmounts` array length the code checks if the length of the `_stakeAmounts` array matches the expected length based on the `_numBigStepLevel` value: [File: EdgeChallengeManager.sol#L360-L361](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L360-L362)

```solidity
if (_numBigStepLevel + 2 != _stakeAmounts.length) {
    revert StakeAmountsMismatch(_stakeAmounts.length, _numBigStepLevel + 2);
}
```
However, this check assumes that there should be exactly `_numBigStepLevel + 2` elements in the `_stakeAmounts` array. This assumption may not hold true if there are additional levels or edge cases that need to be considered.

## Proof of Concept
The `_stakeAmounts` array is used to store the stake amounts required for different levels of the system. The code assumes that the length of this array should be equal to `_numBigStepLevel + 2`, where `_numBigStepLevel` represents the number of big step levels, and the additional two elements are presumably for the block level and small step level.

However, this assumption may not hold true in all cases, leading to potential issues:

Concept, consider the following example
```solidity
// Assuming _numBigStepLevel = 2
uint256[] memory _stakeAmounts = [100, 200, 300]; // Length is 3, but expected length is 4

if (_numBigStepLevel + 2 != _stakeAmounts.length) {
    revert StakeAmountsMismatch(_stakeAmounts.length, _numBigStepLevel + 2);
} else {
    // Proceed with initialization
    // ...
}
```
In this example, the `_stakeAmounts` array has a length of 3, but the expected length based on the `_numBigStepLevel` value is 4. The code will not revert, and the initialization process will proceed with incorrect stake amounts, potentially leading to issues mentioned above.

The `testInitializeWithInvalidParameters` function fails, indicating that the contract does not revert with the expected errors when given invalid parameters. ## Recommended Mitigation Steps
A safer approach would be to validate the length of the `_stakeAmounts` array based on the specific requirements of the system. For example, if there should be one stake amount for each level (including the block level and small step level), the check should be

```solidity
if (_stakeAmounts.length != _numBigStepLevel + 2) {
    revert StakeAmountsMismatch(_stakeAmounts.length, _numBigStepLevel + 2);
}
```
