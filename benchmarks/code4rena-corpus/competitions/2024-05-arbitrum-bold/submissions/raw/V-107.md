# Vulnerability details

## Impact
An attacker could potentially exploit the vulnerability by manipulating the strict equality check ksInfo.creationBlock == 0 in the SequencerInbox.getKeysetCreationBlock function. By providing a crafted input that results in ksInfo.creationBlock being set to 0, the attacker could bypass certain checks or gain unauthorized access within the system. This could lead to unexpected behavior or security breaches within the application.

## Recommended Mitigation Steps
The vulnerability to fix is that the function getKeysetCreationBlock in SequencerInbox.sol uses a dangerous strict equality check ksInfo.creationBlock == 0. This strict equality check can be manipulated by an attacker.

To rectify this vulnerability, it is recommended to avoid using strict equality checks for sensitive operations like determining if an account has enough Ether or tokens. Instead, use inequality checks to ensure safer and more robust code.

For Instance : 
/* BEFORE 
    function getKeysetCreationBlock(bytes32 ksHash) external view returns (uint256) {
        DasKeySetInfo memory ksInfo = dasKeySetInfo[ksHash];
        if (ksInfo.creationBlock == 0) revert NoSuchKeyset(ksHash);
        return uint256(ksInfo.creationBlock);
    }

*/ 

/* Recommendations */
    function getKeysetCreationBlock(bytes32 ksHash) external view returns (uint256) {
        DasKeySetInfo memory ksInfo = dasKeySetInfo[ksHash];
        if (ksInfo.creationBlock <= 0) revert NoSuchKeyset(ksHash);
        return uint256(ksInfo.creationBlock);
    }
