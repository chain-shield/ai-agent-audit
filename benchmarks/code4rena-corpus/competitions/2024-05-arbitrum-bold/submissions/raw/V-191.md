# Vulnerability details

In the [_createBridge function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BridgeCreator.sol#L63-L97), the way the `TransparentUpgradeableProxy` contracts are deployed. The third argument passed to the `TransparentUpgradeableProxy` constructor is the `data` parameter, which is expected to be the encoded function call that should be executed on the implementation contract after deployment. However, in this code, an empty string `""` is passed as the `data` argument, which means that no initialization function will be called on the implementation contracts after deployment.

This can lead to issues because many of the implementation contracts (e.g., `Bridge`, `SequencerInbox`, `Inbox`, `RollupEventInbox`, and `Outbox`) likely require initialization before they can be used correctly. If these contracts are not initialized properly, they may behave unexpectedly or fail to function as intended.

## Impact
Many contracts require initialization to set up their initial state correctly. Without proper initialization, the contract's state variables may be left in their default values, which can lead to unexpected behavior or vulnerabilities. For example, if an `owner` variable is not set during initialization, it may be left as the zero address, allowing anyone to perform privileged operations.

## Proof of Concept
In the context of proxy patterns like the `TransparentUpgradeableProxy`, skipping the initialization step can lead to issues during contract upgrades. The new implementation contract may expect certain state variables or conditions to be set up, which may not be the case if the initialization was skipped during the initial deployment.

## Recommended Mitigation Steps
The function should pass the appropriate encoded function call as the data argument when deploying the `TransparentUpgradeableProxy` contracts. This encoded function call should invoke the initialization function of the respective implementation contract, passing any required arguments.

For example, if the `Bridge` implementation contract has an `initialize` function that takes an `IOwnable` argument, the `data` argument for deploying the `Bridge` proxy should be:

```solidity
bytes memory initializeData = abi.encodeWithSignature("initialize(address)", rollup);
frame.bridge = IBridge(
    address(new TransparentUpgradeableProxy(address(templates.bridge), adminProxy, initializeData))
);
```
