# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L331-L343

```solidity
function newStakeOnNewAssertion(
  uint256 tokenAmount,
  AssertionInputs calldata assertion,
  bytes32 expectedAssertionHash,
  address withdrawalAddress
) public {
  require(withdrawalAddress != address(0), 'EMPTY_WITHDRAWAL_ADDRESS'); //@audit
  _newStake(tokenAmount, withdrawalAddress);
  stakeOnNewAssertion(assertion, expectedAssertionHash);
  /// @dev This is an external call, safe because it's at the end of the function
  receiveTokens(tokenAmount);
}

```

It's been documented that the underlying staking n token is allowed to be `ETH`, but only normal ERC20s are accepted when creating these stakes which would mean that users can't pass in a stake having `eth` as the withdrawal token.

## Impact

Core functionality of the protocol would be affected since stakes are not allowed to have ETH attached.

## Recommended Mitigation Steps

Reimplement the functionality to accept `ETH`
