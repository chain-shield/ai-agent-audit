# Vulnerability details

## Impact

The security issue arising from the use of inconsistent Solidity compiler versions across different contracts within the same project. Specifically, some contracts are compiled with `pragma solidity >=0.6.9 <0.9.0;`, while others use `pragma solidity ^0.8.0;`.

The primary impact of using different compiler versions is the potential exposure to vulnerabilities and behavioral differences between contracts. Older compiler versions may lack recent security patches and optimizations introduced in newer versions. Additionally, contracts compiled with different versions may exhibit different behaviors due to changes in language features and standards, leading to unpredictable outcomes and potential security loopholes.

## Proof of Concept
The inconsistency in compiler versions was identified in the following contracts:
- [DelayBufferTypes.sol](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/DelayBufferTypes.sol#L7)
- [ISequencerInbox.sol](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/ISequencerInbox.sol#L6)

```
pragma solidity >=0.6.9 <0.9.0;
```

The use of different compiler versions suggests that the contracts may not be uniformly tested or audited, increasing the risk of undetected vulnerabilities.

## Tools Used
The discovery of this issue was made through a manual review using Visual Studio Code, leveraging its built-in features for navigating and analyzing Solidity codebases.

## Recommended Mitigation Steps with Fix Code

### Step 1: Choose a Single Compiler Version
Select a single, stable compiler version that meets the project's requirements. This decision should consider the latest security patches and language features needed for the project.

### Step 2: Update Contract Files
Modify the `pragma solidity` directive in all contract files to match the selected compiler version. For example, if `^0.8.0` is chosen, update all contracts accordingly.

#### Before:
```solidity
pragma solidity >=0.6.9 <0.9.0;
```

#### After:
```solidity
pragma solidity ^0.8.0;
```

### Step 3: Conduct Comprehensive Testing
Implement thorough testing to ensure that the contracts behave as expected under the new compiler version. This includes unit tests and integration tests.
