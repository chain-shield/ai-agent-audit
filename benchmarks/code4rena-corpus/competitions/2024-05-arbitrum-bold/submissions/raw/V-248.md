# Vulnerability details

## Impact
The `setValidato` function is being called with a potentially invalid set of validators. If the validators array contains duplicate addresses, the `setValidator` function will treat them as separate validators, which may not be the intended behavior.

Code block: [BOLDUpgradeAction.sol:526-533](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L526-L533)
```solidity
if (validators.length != 0) {
    bool[] memory _vals = new bool[](validators.length);
    for (uint256 i = 0; i < validators.length; i++) {
        require(ROLLUP_READER.isValidator(validators[i]), "UNEXPECTED_NEW_VALIDATOR");

```
The problem is that this code assumes that all the addresses in the validators array are valid validators. However, it does not check if the `validators` array contains duplicate addresses. If there are duplicate addresses in the `validators` array, the `setValidator` function will be called with duplicate validators, which may lead to unexpected behavior or potential security issues.

In a worst-case scenario, the presence of duplicate validators could potentially be exploited by an attacker to gain undue influence or manipulate the system in an unintended way.

## Proof of Concept
Suppose the `validators` array contains the following addresses: `[0x1, 0x2, 0x3, 0x2]`. In this case, the address `0x2` is a duplicate.

When the `setValidator` function is called with this array and the corresponding `_vals` array [true, true, true, true], it will treat `0x2` as two separate validators, which may not be the intended behavior.

This could lead to inconsistencies in the validator set, incorrect calculations, or potential security vulnerabilities if an attacker can exploit the presence of duplicate validators.

## Recommended Mitigation Steps
Add a check to ensure that the `validators` array does not contain duplicate addresses before calling the `setValidator` function by using a mapping or a set data structure to keep track of the unique validators.

To handle duplicate validators:
```solidity
if (validators.length != 0) {
    mapping(address => bool) validatorMap;
    address[] memory uniqueValidators;
    bool[] memory _vals = new bool[](validators.length);

    for (uint256 i = 0; i < validators.length; i++) {
        address validator = validators[i];
        require(ROLLUP_READER.isValidator(validator), "UNEXPECTED_NEW_VALIDATOR");

        if (!validatorMap[validator]) {
            validatorMap[validator] = true;
            uniqueValidators.push(validator);
            _vals[uniqueValidators.length - 1] = true;
        }
    }

    IRollupAdmin(address(rollup)).setValidator(uniqueValidators, _vals);
}
```
We use a mapping `validatorMap` to keep track of unique validators. We iterate over the validators array and check if each validator is already present in the `validatorMap`. If not, we add it to the `validatorMap` and push it to the `uniqueValidators` array. We also set the corresponding value in the `_vals` array to `true`.

Finally, we call the `setValidator` function with the `uniqueValidators` array and the corresponding `_vals` array, ensuring that there are no duplicate validators.
