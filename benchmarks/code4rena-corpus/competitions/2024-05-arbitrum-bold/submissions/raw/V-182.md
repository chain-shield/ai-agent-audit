# Vulnerability details

## Impact
The `validateAssertionHash()` function incorrectly verifies the hash of the `prevAssertionHash` instead of the `afterState`. This issue can lead to the following potential risks:

  - The assertion hash is not correctly calculated, leading to incorrect validation of assertions.
  - Assertions that should be invalid may be accepted due to the incorrect hash verification.
  - Incorrectly verified assertions could potentially compromise the integrity of the rollup data.

## Proof of Concept
https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L540-L547

The assertion hash should be calculated based on the `afterState` of the transition, which represents the state of the rollup after the assertion has been processed.

**Corrected Code**
The corrected version of the function should be:

```solidity
require(assertionHash == RollupLib.assertionHash(prevAssertionHash, state.afterState, inboxAcc), "INVALID_ASSERTION_HASH");
```

## Recommended Mitigation Steps
The function is verifying the hash of the `prevAssertionHash` instead of the `afterState` in the assertion.

Incorrect Code: [RollupCore.sol#L546](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L546)
```solidity
require(assertionHash == RollupLib.assertionHash(prevAssertionHash, state, inboxAcc), "INVALID_ASSERTION_HASH");
```
The `assertionHash` is being verified against a hash calculated from the `prevAssertionHash`, the entire `state` struct, and the `inboxAcc`. However, this may not be the intended behavior, as the `assertionHash` should ideally be calculated based on the `afterState` of the transition, rather than the entire `state` struct.

Correct Code:
```solidity
require(assertionHash == RollupLib.assertionHash(prevAssertionHash, state.afterState, inboxAcc), "INVALID_ASSERTION_HASH");
```
The corrected version of the function correctly verifies the hash of the `afterState` in the assertion, as expected.
