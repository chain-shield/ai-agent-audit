# Vulnerability details

## Impact
The `getPool` function in the `StakingPoolCreatorUtils` library (src/assertionStakingPool/StakingPoolCreatorUtils.sol) uses `abi.encodePacked()` with dynamic types (`creationCode` and `args` of type `bytes`) when passing the result to the `keccak256()` hash function. This can lead to hash collisions and unintended behavior.

The use of `abi.encodePacked()` with dynamic types can have the following impacts:

Hash Collisions: Different sets of `creationCode` and `args` values could generate the same `bytecodeHash`, leading to the `getPool` function returning the same pool address for different input values. This can result in incorrect or unintended behavior in the contracts that rely on this function.

Unintended Contract Creation: An attacker might be able to find a set of `creationCode` and `args` values that produce the same `bytecodeHash` as an existing pool. This could allow the attacker to create a new contract at the same address as the existing pool, potentially manipulating or interfering with the pool's functionality.


## Proof of Concept
The attacker identifies a target pool address they want to manipulate or interfere with.

The attacker analyzes the `StakingPoolCreatorUtils` library and the `getPool` function.

The attacker searches for a combination of `creationCode` and `args` values that, when passed through `abi.encodePacked()` and `keccak256()`, generate the same `bytecodeHash` as the target pool.

Once the attacker finds a matching set of `creationCode` and `args` values, they can call the `getPool` function with these values.

The `getPool` function will return the same pool address as the target pool, even though the input values are different.

The attacker can then create a new contract at the same address as the target pool using the matching `creationCode` and `args` values.

By creating a contract at the same address, the attacker will be able to manipulate and/or interfere with the functionality of the target pool.

## Tools Used
Manual Review

## Recommended Mitigation Steps
To mitigate this vulnerability, it is recommended to use `abi.encode()` instead of `abi.encodePacked()` when passing dynamic types to the `keccak256()` hash function. `abi.encode()` pads the dynamic types to 32 bytes, preventing hash collisions.
