# Vulnerability details

## Impact
wrong logical operator use will cause buffer to be updateable if buffer is full or if buffer is synced.

## Proof of Concept
the function [DelayBuffer.isUpdateable()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/DelayBuffer.sol#L108C1-L113C6) has comments  which describe its intended behaviour as seen in the snippet below.

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/DelayBuffer.sol#L108C1-L113C6
```solidity
    function isUpdatable(BufferData storage self) internal view returns (bool) {
        // if synced, the buffer can't be depleted
        // if full, the buffer can't be replenished
        // if neither synced nor full, the buffer updatable (depletable / replenishable)
        return !isSynced(self) || self.bufferBlocks < self.max; 
    }
```
i believe the implementation doesnt fit with the behaviour described because 
-  if buffer is synced (isSynced() returns true) but  buffer blocks is not full/reached max yet (self.bufferBlocks < self.max = true), the function will return true because the condition will be `!true aka false || true`. This is not intended behaviour because if synced the buffer should'nt be depleted i.e not updated so function should return false
- if buffer blocks  is full but buffer isnt synced (isSynced() returns false), the function will return true because the condition will be `!false aka true  || false`. This is not intended behaviour because if full the buffer should'nt be replenished i.e not updated so function should return false.

 The function ought to return true if the buffer is neither synced nor full. meaning for it to return true, buffer must not be synced (isSynced() returns false) and  it must not be full. But in this current implementation (because of the **OR** logic operator)  it will return true if "not full but synced" and if "not synced but full".
 
The correct implementation would be to use the **AND** logic operator. If `&&` was used, both conditions need to be true for it to return true. so buffer not full but synced (`!true aka false && true`) or buffer not synced but full (`!false aka true && false`) will both return false while buffer not synced when buffer not full (`!false aka true && true`) will return true. 

`DelayBuffer.isUpdateable()` is an important function used in the logic of SequencerInbox's [delayProofImpl()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L605) and by extension [addSequencerL2BatchDelayProof()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L594), [addSequencerL2BatchFromBlobsDelayProof()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L420) and [addSequencerL2BatchFromOriginDelayProof()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L444) . So this behaviour will affect/cause incorrect behaviour or cause a buffer update at times when it should not be updated.

## Recommended Mitigation Steps
use AND operator instead. 

```solidity
        return !isSynced(self) && self.bufferBlocks < self.max; 
```
