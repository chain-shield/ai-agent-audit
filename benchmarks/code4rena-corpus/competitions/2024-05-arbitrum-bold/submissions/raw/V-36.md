# Vulnerability details

### Vulnerability Report

**Affected Code:** [AssertionStakingPool.sol](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/AssertionStakingPool.sol#L43)

**Vulnerability Description:**

The `safeIncreaseAllowance` function is called with only two arguments: `rollup` and `requiredStake`, whereas the `safeIncreaseAllowance` function defined in the `SafeERC20` library expects three arguments: `token`, `spender`, and `value`. This inconsistency in the number of arguments passed to the function can lead to unexpected behavior or even exploitation of the contract.

**Recommended Fix:**

Pass the correct number of arguments to the `safeIncreaseAllowance` function. It should be called with three arguments: the token, the spender, and the value to increase the allowance by. Make sure that `rollup` is the address of the spender and `requiredStake` is the value by which you want to increase the allowance of `stakeToken` for `rollup`.

You can fix it like this:

```solidity
IERC20.safeIncreaseAllowance(token, spender, value);
This ensures that the safeIncreaseAllowance function is called correctly, with all the necessary arguments provided.
