# Vulnerability details


## Impact
 If the networks block.basefee > 0 and  > blobCost, the blob batch poster may not get the refunds amount due to it. 

## Proof of Concept
[formBlobDataHash()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L725C1-L748C6) function is meant to returrn data about the blobs, part of the data returned is a normalized value for gas used in the blob posting. It is calculated as

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L746
```solidity
block.basefee > 0 ? blobCost / block.basefee : 0
```
 if the networks block.basefee > 0 and  is greater than than the blobCost's value ([a value whose size depends on the length of the blob data hash and network's BlobBaseFee](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L742)), the division `blobCost / block.basefee` will return 0. Lets look at a case where the division returns 0 and `formBlobDataHash()` returns 0 amount as blob gas.
`formBlobDataHash()` is used in [addSequencerL2BatchFromBlobsImpl()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L455) to get the [blobGas](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L464) variable and `blobGas` variable is used as the [extraGas](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L759) param for call to [submitBatchSpendingReport()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L508) at the end of the function logic, just to process refunds to batch poster for the blob postings.

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L462C1-L465C56
```solidity
        (
            bytes32 dataHash,
            IBridge.TimeBounds memory timeBounds,

```

https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L508
```solidity
            submitBatchSpendingReport(dataHash, seqMessageIndex, block.basefee, blobGas);
```
 In this case If `submitBatchSpendingReport()` is called with extraGas/blobGas as 0 value, this will mean a wrong spending report message will be[ crafted and submited](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L774C1-L786C11) to the bridge as in actuality there was gas spent during the blob posting and it wasnt free(0) But message sent to the bridge will have it as 0 gas instead. 

This will mean that the entity that produced the blob batch data wil not be getting its correct refunds amount so maybe using a normalized gas value is not ideal in this case as gas will always be spent for blobs posting and wont be 0.
