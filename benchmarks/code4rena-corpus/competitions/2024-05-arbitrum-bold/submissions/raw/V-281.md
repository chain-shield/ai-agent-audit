# Vulnerability details

## Impact
Complete Break of RollupAdminLogic Contract as no Validation is Present for all Functions 
## Proof of Concept
```solidity
   /**
     * Functions are only to reach this logic contract if the caller is the owner
     * so there is no need for a redundant onlyOwner check
     */
```
The comment above from [L109](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/rollup/RollupAdminLogic.sol#L109) of the RollupAdminLogic contract shows that Protocol is aware of this issue, but it is wrong to assume all the functions are fully protected as the contract would be vulnerable in situations where the linked proxy contract that checks if the caller is the owner is compromised. This could be as a result of Function Selector Collisions and Upgradability Issues which would be taken advantage of by an attacker with easy access to the RollupAdminLogic contract.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Protocol should ensure necessary validations in the RollupAdminLogic contract functions to ensure that as much as possible the contract is protected against fund Loss
