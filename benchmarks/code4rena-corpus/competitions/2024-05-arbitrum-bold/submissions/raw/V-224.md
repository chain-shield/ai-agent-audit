# Vulnerability details

## Impact
The calculation of the `extraGas` value when `hostChainIsArbitrum` is true. The code attempts to add the l1Fees to the `extraGa`s value, but the way it's done may lead to an incorrect result.

Code: [src\bridge\SequencerInbox.sol:L768-L772](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L768-L772)
```solidity
if (hostChainIsArbitrum) {
    // Include extra gas for the host chain's L1 gas charging
    uint256 l1Fees = ArbGasInfo(address(0x6c)).getCurrentTxL1GasFees();
    extraGas += l1Fees / block.basefee;
}
```
The problem is that the `l1Fees` value is divided by `block.basefee` before being added to extraGas. However, according to the [Arbitrum documentation](https://docs.arbitrum.io/how-arbitrum-works/l1-gas-pricing), the `l1Fees` value returned by `getCurrentTxL1GasFees()` is already denominated in Wei, and it should not be divided by the base fee.

## Proof of Concept
The `getCurrentTxL1GasFees()` function returns the L1 gas fees for the current transaction in Wei. By dividing this value by `block.basefee`, the code is effectively reducing the L1 gas fees, leading to an underestimation of the total gas cost.

>: If the total gas cost is underestimated, it could lead to situations where transactions fail due to insufficient gas. This could potentially be exploited by an attacker to cause a Denial of Service (DoS) attack on the rollup protocol by submitting transactions with intentionally low gas limits.

>: The `rollup` protocol relies on accurate gas cost calculations to update the state correctly. If the gas cost is underestimated, it could lead to incorrect state updates, potentially causing inconsistencies between the L1 and L2 chains.

Incorrect gas cost calculations can have broader security implications for the `rollup` protocol.

## Recommended Mitigation Steps
The line `extraGas += l1Fees / block.basefee;` should be replaced with `extraGas += l1Fees;`.

By dividing `l1Fees` by `block.basefee`, the code is effectively reducing the value of `l1Fees`, which could lead to an incorrect calculation of the total gas cost. This could potentially result in an underestimation of the gas cost, which could cause issues in the `rollup` protocol.
