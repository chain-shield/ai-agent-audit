# Vulnerability details

### Impact
The vulnerability allows a reentrancy attack, potentially compromising the security of the sequencer contract. By exploiting the low-level call in the `_executeLowLevelCall` function, a malicious contract could manipulate the transaction sequencing and batching, leading to scenarios such as double-spending, incorrect transaction execution, and manipulation of state variables.

### Proof of Concept
The vulnerable code snippets where the low-level call is used can be found here:

- [Bridge.sol, lines 42-49](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/Bridge.sol#L42-L49)
- [BridgeStub.sol, lines 144-151](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/mocks/BridgeStub.sol#L144-L151)

These code snippets show the vulnerable `_executeLowLevelCall` function where a low-level call is made without error handling, enabling the possibility of a reentrancy attack.

### Tools Used
Manual Review

### Recommended Mitigation Steps
1. **Implement Proper Error Handling:** Add proper error handling to `_executeLowLevelCall` (try-catch or bool success) and 'require' checks. Ensure that the transaction is reverted if the low-level call fails to avoid reentrancy vulnerabilities.

2. **Checks-Effects-Interactions:** Implement the Checks-Effects-Interactions pattern to ensure that all state updates are performed before making any external calls. This reduces the risk of reentrancy attacks.

3. **Use Reentrancy Guards (manual or 3rd party):** Consider using the `nonReentrant` modifier from OpenZeppelin's contract to avoid reentrancy attacks by banning multiple calls to the vulnerable functions while it's still executing.
