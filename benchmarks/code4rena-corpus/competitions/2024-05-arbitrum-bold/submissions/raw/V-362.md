# Vulnerability details

## Impact
Detailed description of the impact of this finding.
### Vulnerability: Incorrect Equality in `getKeysetCreationBlock` and `packHeader` Functions

#### Description:

**Location 1:**
- **Function:** `SequencerInbox.getKeysetCreationBlock(bytes32)`
- **File:** `src/bridge/SequencerInbox.sol`
- **Lines:** 957-961
- **Issue:** The function uses a strict equality check (`ksInfo.creationBlock == 0`) to determine if a keyset exists. This can be manipulated by an attacker, as a valid keyset might have a `creationBlock` of zero, especially on chains where block numbers start from zero.

**Location 2:**
- **Function:** `SequencerInbox.packHeader(uint256)`
- **File:** `src/bridge/SequencerInbox.sol`
- **Lines:** 637-653
- **Issue:** The function uses a strict equality check (`assert(bool)(header.length == HEADER_LENGTH)`) which can be manipulated by an attacker.

#### Impact:
1. **False Negative on Keyset Existence:** The `getKeysetCreationBlock` function may incorrectly determine that a keyset does not exist if its `creationBlock` is zero, leading to the invalidation of valid keysets and disrupting dependent functionalities.
2. **Potential Denial of Service:** On chains where the block number starts from zero, all keysets created at block zero will be considered non-existent, potentially causing a denial of service for operations dependent on these keysets.

#### Recommendation:
To address this vulnerability, modify the equality check to accurately identify the existence of a keyset. Instead of checking if `creationBlock` is zero, verify the `isValidKeyset` flag:

```solidity
function getKeysetCreationBlock(bytes32 ksHash) external view returns (uint256) {
    DasKeySetInfo memory ksInfo = dasKeySetInfo[ksHash];
    if (!ksInfo.isValidKeyset) revert NoSuchKeyset(ksHash);
    return uint256(ksInfo.creationBlock);
}
```

This change ensures that the function correctly determines the existence of a keyset based on the `isValidKeyset` flag, preventing false negatives and potential denial of service.

### Recommendation to Resolve the Issue

#### Issue Summary:
1. **False Negative on Keyset Existence:** The `getKeysetCreationBlock` function may incorrectly determine that a keyset does not exist if its `creationBlock` is zero, leading to the invalidation of valid keysets and disrupting dependent functionalities.
2. **Potential Denial of Service:** On chains where the block number starts from zero, all keysets created at block zero will be considered non-existent, potentially causing a denial of service for operations dependent on these keysets.

#### Recommended Fix:

Modify the equality check in the `getKeysetCreationBlock` function to verify the `isValidKeyset` flag instead of checking if `creationBlock` is zero.

#### Code Changes:

**Location 1:**
- **Function:** `SequencerInbox.getKeysetCreationBlock(bytes32)`
- **File:** `src/bridge/SequencerInbox.sol`
- **Lines:** 957-961


With the following code:
