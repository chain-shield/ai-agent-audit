# Vulnerability details

## Description:
The function `setValidator` in the provided contract allows the contract owner to set or modify the validator whitelist. However, the function lacks proper access control mechanisms, which might lead to potential misuse if the contract's ownership is compromised.

## Impact:

If the contract ownership is transferred maliciously or if the owner’s private key is compromised, an attacker could modify the validator whitelist, potentially enabling unauthorized validators. This could disrupt the rollup's validation process, allowing for unauthorized actions within the rollup.

## Proof of Concept:

The `setValidator` function does not implement additional access controls beyond being callable by the contract owner. While ownership control is generally sufficient, it can be risky if the ownership itself is compromised.

```solidity

function setValidator(address[] calldata _validator, bool[] calldata _val) external override {
    require(_validator.length > 0, "EMPTY_ARRAY");
    require(_validator.length == _val.length, "WRONG_LENGTH");

    for (uint256 i = 0; i < _validator.length; i++) {
        isValidator[_validator[i]] = _val[i];
    }
    emit OwnerFunctionCalled(6);
}
```

## Recommended Mitigation Steps:

Multi-Signature Wallet for Critical Functions: Instead of relying on a single owner, critical functions like `setValidator` should require approval from multiple trusted parties (e.g., a multi-signature wallet).

**Role-Based Access Control**: Implement role-based access control using a more granular access control mechanism like `OpenZeppelin's AccessControl`, ensuring that only specific roles can modify validators.

**Timelock Mechanism**: Implement a timelock for critical operations, providing a delay period before changes take effect, allowing for monitoring and potential intervention if unauthorized actions are detected.

#### Example mitigation using OpenZeppelin’s AccessControl:

```solidity

import "@openzeppelin/contracts/access/AccessControl.sol";

contract RollupAdminLogic is RollupCore, IRollupAdmin, DoubleLogicUUPSUpgradeable, AccessControl {
    bytes32 public constant ADMIN_ROLE = keccak256("ADMIN_ROLE");

    // Add the deployer to the admin role
    constructor() {
        _setupRole(ADMIN_ROLE, msg.sender);
    }

    // Modify setValidator to require the ADMIN_ROLE
    function setValidator(address[] calldata _validator, bool[] calldata _val) external override onlyRole(ADMIN_ROLE) {
        require(_validator.length > 0, "EMPTY_ARRAY");
        require(_validator.length == _val.length, "WRONG_LENGTH");

        for (uint256 i = 0; i < _validator.length; i++) {
            isValidator[_validator[i]] = _val[i];
        }
        emit OwnerFunctionCalled(6);
    }
}
```
By implementing these mitigations, the contract will have stronger defenses against unauthorized modifications to critical settings, ensuring better security and integrity of the rollup's operations.
