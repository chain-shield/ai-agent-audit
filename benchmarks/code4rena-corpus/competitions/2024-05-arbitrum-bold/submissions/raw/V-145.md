# Vulnerability details

## Impact
Early staker can withdraw the fund from the users that stakes later

In AssertionStakingPool, the contract inherits from AbsBoldStakingPool.sol

```solidity
contract AssertionStakingPool is AbsBoldStakingPool, IAssertionStakingPool {
```

and 

```solidity
function depositIntoPool(uint256 amount) external {
    if (amount == 0) {
        revert ZeroAmount();
    }

    depositBalance[msg.sender] += amount;
    IERC20(stakeToken).safeTransferFrom(msg.sender, address(this), amount);

    emit StakeDeposited(msg.sender, amount);
}

/// @inheritdoc IAbsBoldStakingPool
function withdrawFromPool(uint256 amount) public {
    if (amount == 0) {
        revert ZeroAmount();
    }
    uint256 balance = depositBalance[msg.sender];
    if (amount > balance) {
        revert AmountExceedsBalance(msg.sender, amount, balance);
    }

    depositBalance[msg.sender] = balance - amount;
    IERC20(stakeToken).safeTransfer(msg.sender, amount);
    
    emit StakeWithdrawn(msg.sender, amount);
}
```

user can call [depositIntoPool](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/AbsBoldStakingPool.sol#L29) to deposit fund any time,

user can call [withdrawFromPool](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/AbsBoldStakingPool.sol#L41) any time as well.

consider the case:

1. user A create an assertion pool and are looking for crowd source 1 WETH.
2. user Alice deposit 0.8 WETH. user bob deposit 0.6 WETH at the same time.
3. user A permissionlessly [create an assertion](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/AssertionStakingPool.sol#L40),

```solidity
   function createAssertion(AssertionInputs calldata assertionInputs) external {
        uint256 requiredStake = assertionInputs.beforeStateData.configData.requiredStake;
        // approve spending from rollup for newStakeOnNewAssertion call
        IERC20(stakeToken).safeIncreaseAllowance(rollup, requiredStake);
        // reverts if pool doesn't have enough stake and if assertion has already been asserted
        IRollupUser(rollup).newStakeOnNewAssertion(requiredStake, assertionInputs, assertionHash, address(this));
    }
```

4. assume the assertionInputs.beforeStateData.configData.requiredStake is 1 WETH.

the contract hold 0.8 WETH + 0.6 WETH = 1.4 WETH, and 1 WETH is transfered to rollup contract to create assertion.

5. user charlie deposit another 0.4 WETH to the assert pool contract, the assert pool hold 0.4 WETH + 0.4 WETH = 0.8 WETH again.

6. the user Alice withdraw stake immediately after charlie make a deposit.

charlie wants to make a deposit to create more assertion, while alice withdraw the fund directly when there are ongoing unresolved assertion.

while the expect regular follow is after the assertion is confirmed, the function below needs to be called:

```solidity
function makeStakeWithdrawableAndWithdrawBackIntoPool() external {
        makeStakeWithdrawable();
        withdrawStakeBackIntoPool();
    }
```

then each staker can withdraw their fund

but in fact, if there are staker that stake later after the assertion is created but not resolved yet,

Early staker can withdraw the fund from the users that stakes later.

Note: the EdgeStakingPool has this issue as well.

the expect flow is after the edge is resolved and confirmed, someone needs to call call [refundStake](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L572) first.

if there are staker that stake later after the is created but not resolved yet,

Early staker can withdraw the fund from the users that stakes later.
