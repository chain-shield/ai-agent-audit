# Vulnerability details

[The `bisectEdge` function is responsible for creating two new child edges (lower and upper) from an existing edge.](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L451-L488) If the lower child edge is newly created and happens to have an `edgeId` of `0`, the `lowerChildAlreadyExists` flag will be incorrectly set to true. This means that the contract will assume that the lower child edge already exists, even though it was just created.

When a new edge is created, the contract should emit an `EdgeAdded` event to notify other contracts or clients about the new edge. However, due to the incorrect `lowerChildAlreadyExists` flag, the `EdgeAdded` event will not be emitted for the newly created lower child edge if its `edgeId` is `0`.

## Impact
The code checks if `lowerChildAdded.edgeId` is `0` to determine if the lower child edge already exists. However, this check is not sufficient because the `edgeId` of a newly created edge could also be `0` by chance.

Here's the problematic line: [EdgeChallengeManager.sol#L458](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L458)
```solidity
bool lowerChildAlreadyExists = lowerChildAdded.edgeId == 0;
```
If a new lower child edge is created with an `edgeId` of `0`, the `lowerChildAlreadyExists` flag will be incorrectly set to true, and the `EdgeAdded` event will not be emitted for the new lower child edge.

## Proof of Concept
The code snippet that illustrates the issue: [EdgeChallengeManager.sol#455-L470](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L455-L472)

```solidity
(bytes32 lowerChildId, EdgeAddedData memory lowerChildAdded, EdgeAddedData memory upperChildAdded) =
    store.bisectEdge(edgeId, bisectionHistoryRoot, prefixProof);

bool lowerChildAlreadyExists = lowerChildAdded.edgeId == 0;
// the lower child might already exist, if it didnt then a new
// edge was added
if (!lowerChildAlreadyExists) {
    emit EdgeAdded(
        lowerChildAdded.edgeId,
        lowerChildAdded.mutualId,
        lowerChildAdded.originId,
        lowerChildAdded.claimId,
        lowerChildAdded.length,
        lowerChildAdded.level,
        lowerChildAdded.hasRival,
        lowerChildAdded.isLayerZero
    );
}
```
As shown in this code, the `lowerChildAlreadyExists` flag is set based on whether the `edgeId` of the `lowerChildAdded` `edge` is `0`. However, this check is not sufficient because a newly created edge can also have an `edgeId` of `0` by chance, leading to the incorrect assumption that the edge already exists.

The edge case is it can cause the contract to lose track of newly created edges and fail to emit important events, which can break the functionality of the contract and any other contracts or clients that rely on these events.

## Recommended Mitigation Steps
Consider returning a boolean flag from the `store.bisectEdge` function to indicate whether the lower child edge already existed or not, instead of relying on the `edgeId` value.
