# Vulnerability details

## Impact
In the calculation of `assertionBlocks` when `isBlockLevel` is true and `assertionChain.isFirstChild(topEdge.claimId)` is also true. In this case, the code attempts to calculate the time between the first and second child assertions by subtracting the creation block of the first child from the creation block of the second child.

However, there is no check to ensure that the `prevAssertionHash` provided in the `claimStateData` is indeed the parent assertion hash of `topEdge.claimId`. If the `prevAssertionHash` is not the correct parent assertion hash, the calculation of `assertionBlocks` will be incorrect.

**Incorrect Time Calculation:**
_If the `prevAssertionHash` provided in the `claimStateData` is not the correct parent assertion hash of `topEdge.claimId`, the calculation of `assertionBlocks` will be incorrect. This means that the time between the first and second child assertions will be miscalculated, leading to an inaccurate representation of the time the edge has spent unrivaled._

**Potential Incorrect Edge Confirmation:**
_The `assertionBlocks` value is added to the `totalTimeUnrivaledCache` of the edge to determine the total time the edge has spent unrivaled. If this value is incorrect due to the issue mentioned above, it could lead to edges being confirmed prematurely or not being confirmed when they should be, violating the protocol's rules and potentially affecting the integrity of the challenge resolution process._

## Proof of Concept
The issue is this could lead to incorrect calculations of the `assertionBlocks` value, which is used to determine the total time an edge has spent unrivaled. This value is crucial in the process of confirming edges and resolving challenges in the protocol.

If the issue is not addressed, it could potentially be exploited by malicious actors to manipulate the edge confirmation process and gain an unfair advantage in the challenge resolution mechanism.

Code that illustrates the concept: [EdgeChallengeManager.sol#L522-L530](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L522-L531)

We can see in this code, the `assertionBlocks` value is calculated based on the assumption that `claimStateData.prevAssertionHash` is the correct parent assertion hash of `topEdge.claimId`. However, there is no check to ensure this assumption is valid, which could lead to the issues mentioned above.

## Recommended Mitigation Steps
Check should be added to ensure that `prevAssertionHash` is the correct parent assertion hash of `topEdge.claimId`. Introduce a new function in the `assertionChain` contract that takes an assertion hash and returns its parent assertion hash. Then, in the `confirmEdgeByTime` function, call this new function with `topEdge.claimId` and compare the result with `claimStateData.prevAssertionHash`.

```solidity
if (isBlockLevel && assertionChain.isFirstChild(topEdge.claimId)) {
    bytes32 parentAssertionHash = assertionChain.getParentAssertionHash(topEdge.claimId);
    if (parentAssertionHash == claimStateData.prevAssertionHash) {
        assertionChain.validateAssertionHash(
            topEdge.claimId,
            claimStateData.assertionState,
            claimStateData.prevAssertionHash,
            claimStateData.inboxAcc
        );
        assertionBlocks = assertionChain.getSecondChildCreationBlock(claimStateData.prevAssertionHash)
            - assertionChain.getFirstChildCreationBlock(claimStateData.prevAssertionHash);
    } else {
        // Handle the case where prevAssertionHash is not the correct parent assertion hash
        // (e.g., revert with an appropriate error message)
    }
}
```
By adding the check, we can ensure that the `assertionBlocks` calculation is performed only when `prevAssertionHash` is the correct parent assertion hash of `topEdge.claimId`.

**Or**

Modify the function to correctly calculate `assertionBlocks` based on whether the assertion being claimed against is the first or subsequent child of its predecessor.

```solidity
bool isBlockLevel = ChallengeEdgeLib.levelToType(topEdge.level, NUM_BIGSTEP_LEVEL) == EdgeType.Block;
if (isBlockLevel) {
    assertionBlocks = assertionChain.getChildCreationBlock(claimStateData.prevAssertionHash)
        - assertionChain.getFirstChildCreationBlock(claimStateData.prevAssertionHash);
}
```
