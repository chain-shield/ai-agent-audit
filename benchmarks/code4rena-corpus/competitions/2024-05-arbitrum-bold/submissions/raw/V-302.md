# Vulnerability details

## Impact

Assertions cannot be created by a challenging party.

## Proof of Concept

When creating a rival assertion, `stakeOnNewAssertion()` is called. This function has the `onlyValidator` modifier but assume that it is disabled (validatorWhitelistDisabled is true).

```
    modifier onlyValidator() {
        require(isValidator[msg.sender] || validatorWhitelistDisabled, "NOT_VALIDATOR");
        _;
    }
```

An assertion is created for two reasons. First, the honest validator creates the assertion for normal usage, confirming data from L2 to L1. Second, a staker can create the assertion if he thinks that the validator's assertion is not correct.

Given a parent assertion 0x123, validator Alice calls a new assertion 0xabc.

Staker Bob thinks that 0xabc should not proceed from 0x123, and calls a rival assertion 0xdef.

Now, the parent (previous assertion) 0x123 has two claims, 0xabc and 0xdef. This is where the dispute game comes in.

When Bob calls a rival assertion with 0xdef as the `expectedAssertionHash` in the parameter, there is a bunch of checks in the function to ensure that the previous assertion is correct and the new assertion created is not duplicated.

One of the check is this:

```
   // Staker can create new assertion only if
        // a) its last staked assertion is the prev; or
        // b) its last staked assertion have a child
>       bytes32 lastAssertion = latestStakedAssertion(msg.sender);
        require(
            lastAssertion == prevAssertion || getAssertionStorage(lastAssertion).firstChildBlock > 0,
            "STAKED_ON_ANOTHER_BRANCH"
        );
```

When Bob creates the assertion for the first time, he does not have any `lastAssertion`. When the function queries `latestStakedAssertion(Bob)`, it returns zero.

```
    function latestStakedAssertion(address staker) public view override returns (bytes32) {
        return _stakerMap[staker].latestStakedAssertion;
    }
```

Note that a few lines down the checks, Bob's latest assertion is updated.

```
        (bytes32 newAssertionHash, bool overflowAssertion) =
            createNewAssertion(assertion, prevAssertion, expectedAssertionHash);
        _stakerMap[msg.sender].latestStakedAssertion = newAssertionHash;
```

Since Bob's latest assertion is null, this check `lastAssertion == prevAssertion` will fail. Next, the function checks `getAssertionStorage(lastAssertion).firstChildBlock > 0`, which will fail also, because `lastAssertion`, which is Bob's assertion, is zero. Therefore, the `firstChildBlock` will be zero.

Bob cannot create a rival assertion.

## Tools Used

## Recommended Mitigation Steps

If Bob is the rival assertion and therefore `lastAssertion != prevAssertion`, then the other check should pass. The other check should check the `prevAssertion` and whether it has a `firstChildBlock`. 

```
   // Staker can create new assertion only if
        // a) its last staked assertion is the prev; or
        // b) its last staked assertion have a child
        bytes32 lastAssertion = latestStakedAssertion(msg.sender);
        require(
>           lastAssertion == prevAssertion || getAssertionStorage(prevAssertion).firstChildBlock > 0,
            "STAKED_ON_ANOTHER_BRANCH"
        );
```

The previous assertion should have a `firstChildBlock` if a validator has created  an assertion.
