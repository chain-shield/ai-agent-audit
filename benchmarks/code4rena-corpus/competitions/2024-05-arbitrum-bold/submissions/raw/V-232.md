# Vulnerability details

## Impact
The `totalWithdrawableFunds` is incremented by the `amount` being added to the individual account's withdrawable funds, but it is not decremented when funds are withdrawn from an account.

This means that the `totalWithdrawableFunds` value will gradually become larger than the actual sum of withdrawable funds across all accounts, leading to an inconsistent state.

## Proof of Concept
Even if the inflated `totalWithdrawableFunds` value does not directly lead to any exploits, it represents an inconsistent state within the contract. This inconsistency can make it harder to reason about the contract's behavior and can potentially lead to other issues or bugs in the future.

In the `increaseWithdrawableFunds` function, the `totalWithdrawableFunds` is incremented by the amount being added to the individual account's withdrawable funds. However, in the `withdrawFunds` function, there is no corresponding decrement of `totalWithdrawableFunds` when funds are withdrawn from an account.

Over time, as funds are added and withdrawn from various accounts, the `totalWithdrawableFunds` value will gradually become larger than the actual sum of withdrawable funds across all accounts, leading to an inconsistent state.

## Recommended Mitigation Steps
The `totalWithdrawableFunds` should also be decremented in the `withdrawFunds` function (or any other function that decrements an account's withdrawable funds). 
```solidity
function withdrawFunds(address account) internal returns (uint256) {
    uint256 amount = _withdrawableFunds[account];
    _withdrawableFunds[account] = 0;
    totalWithdrawableFunds -= amount;  // Decrement totalWithdrawableFunds
    // Transfer funds to the account
    // ...
    return amount;
}
```
By decrementing `totalWithdrawableFunds` when withdrawing funds, the total will accurately reflect the sum of withdrawable funds across all accounts.
