## The Issue
The function `submitBatchSpendingReport` is being called with a `gasPrice` argument of `0` when the chain is not using a fee token `(!isUsingFeeToken`), which means it's using Ether (ETH) as the native currency.

**Ethereum Transaction Requirements:**
In the Ethereum network, every transaction requires a non-zero gas price to incentivize miners to include the transaction in a block. If the gas price is set to 0, the transaction is likely to be rejected or never mined, as miners have no incentive to process it.

## Impact
By setting the gas price to `0`, the `submitBatchSpendingReport` function will attempt to submit a transaction with a zero gas price. This transaction will likely be rejected or never mined by the Ethereum network, as miners have no incentive to include it in a block.

As a result, the batch spending report will not be recorded on the Ethereum blockchain, potentially leading to issues with tracking and accounting for the batch poster's spending.

## Proof of Concept
The Ethereum Yellow Paper, which defines the Ethereum protocol, specifies that a non-zero gas price is required for transactions to be processed. Specifically, section 4.3 "Transaction Execution" states:

> "The execution of a transaction begins with an account nonce check, followed by a gas payment check, and then the transaction is executed."

And section 4.3.1 "Gas Payment" further clarifies:

> "The gas price is a value set by the sender of the transaction, which represents the fee that the sender is willing to pay for each unit of gas consumed by the transaction."

This clearly indicates that a non-zero gas price is a fundamental requirement for transactions to be executed on the Ethereum network.

## Recommended Mitigation Steps
Pass a non-zero gas price value to the `submitBatchSpendingReport` function when `!isUsingFeeToken` is true, or
Remove the call to `submitBatchSpendingReport` if it's not intended to be used when the chain is using ETH as the native currency.

Alternatively, consider refactoring the code to handle the fee token and native currency cases separately, making the logic more explicit and easier to maintain.
