# Vulnerability details

In the [assertionHash function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupLib.sol#L23-L34), the recursive call within the `assertionHash` function will cause an infinite loop, leading to a stack overflow error. _This means that any contract or function that calls `assertionHash` will eventually run out of gas and fail to execute, effectively rendering the function unusable._

  - If the `assertionHash` function is called externally or by other contracts, the infinite loop and stack overflow can potentially be exploited to cause a Denial of Service (DoS) attack. An attacker could repeatedly call the function, consuming all available gas and preventing other transactions from being processed.

  - Even if the stack overflow is avoided, the recursive call will result in incorrect assertion hashes being computed. This can have severe consequences for the integrity of the system, as assertion hashes are likely used for verification, validation, or as identifiers in various parts of the codebase.

## Impact
The issue lies in the recursive call to `assertionHash` within the function itself: [#L29-L32](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupLib.sol#L29-L34)

```solidity
return assertionHash(
    parentAssertionHash,
    afterState.hash(),
    inboxAcc
);
```
This recursive call will cause an infinite loop, as the function will keep calling itself indefinitely without any termination condition.

The intended behavior of the function is likely to compute a hash value based on the provided `parentAssertionHash`, `afterState`, and `inboxAcc`. However, the recursive call will cause a stack overflow error, preventing the function from executing correctly.

## Recommended Mitigation Steps
The recursive call should be replaced with the appropriate hash computation logic. One possible solution could be to use the keccak256 hashing function directly, combining the input parameters in the desired order:

```solidity
function assertionHash(
    bytes32 parentAssertionHash,
    AssertionState memory afterState,
    bytes32 inboxAcc
) internal pure returns (bytes32) {
    // we can no longer have `hasSibling` in the assertion hash as it would allow identical assertions
    return keccak256(
        abi.encodePacked(
            parentAssertionHash,
            afterState.hash(),
            inboxAcc
        )
    );
}
```
Using `keccak256` and `abi.encodePacked`, the function can correctly compute the assertion hash without causing an infinite loop.
