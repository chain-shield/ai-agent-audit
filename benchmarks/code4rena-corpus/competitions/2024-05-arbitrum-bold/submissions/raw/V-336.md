# Vulnerability details



## Impact

An incorrect edge can be confirmed by a malicious party utilising fast confirming assertion by anyTrustFastConfirmer. This breaks a main invariant that only honest layer zero edges can be confirmed under the BoLD paper’s assumptions.

from README, Main invariants:
> Honest assertions / layer zero edges are always confirmed under the BoLD paper’s assumptions within 2 challenge periods

and under Attack ideas:
> Assuming there is at least one honest participant, no incorrect assertions or edges can be confirmed.


## Proof of Concept

#### Roles
**anyTrustFastConfirmer** => to fast confirm assertions
**anyAttacker** => a malicious party

#### Attack scenario:
- **anyTrustFastConfirmer** sends fast confirmation to create a new assertion and confirm it.
- **anyAttacker** who is monitoring the mempool, front-run the TX above by creating:
	- an incorrect assertion (first child of the prev assertion) with invalid endroot.
	- a correct assertion (second child of the prev assertion) with correct endroot.
	-  a challange (layer zero edge) for the incorrect assertion (possible since the assertion is pending and it is rivaled)
- Fast confirmation now is processed without creating the assertion (this is possible since it checks if the assertion exists skip creating it).
```solidity
        if (status == AssertionStatus.NoAssertion) {
            // If not exists, we create the new assertion
            (bytes32 newAssertionHash,) = createNewAssertion(assertion, prevAssertion, expectedAssertionHash);
```

- The correct assertion now is confirmed.
- A honest party (or anyone) can not create a challange for the correct assertion, because it is already confirmed. This check is done here

*Please note that confirming this incorrect assertion is not possible even though a winning edge belongs to the incorrect assertion. This is because `confirmAssertion` will revert in case the `prevAssertionHash` is not the latestConfirmed, and since the **anyTrustFastConfirmer** confirmed the assertion already, the `prevAssertionHash` is no longer the latestConfirmed.*

Note: due to the lack of time, I couldn't farther advance this attack. However, I believe it still has value since it breaks a fundamental  assumption of BoLD protocol.
