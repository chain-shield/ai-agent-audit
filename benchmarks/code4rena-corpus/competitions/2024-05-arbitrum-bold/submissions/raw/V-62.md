# Vulnerability details

## Impact
The `root` function in the `MerkleTreeLib` library performs arithmetic operations on `bytes32` values without explicit overflow checks. This can lead to unexpected behavior and potential vulnerabilities if the operations result in an overflow.

The lack of overflow checks in the `root` function can have severe consequences for the protocol. If it successfully triggers an overflow, it can lead to the calculation of incorrect merkle roots. This can compromise the integrity of the entire merkle tree, causing inconsistencies and making it difficult to verify the authenticity of the data. Incorrect merkle roots can lead to the acceptance of invalid transactions, the generation of incorrect proofs, and the potential manipulation of funds within the protocol. Moreover, the unexpected behavior resulting from overflows can cause the protocol to enter an inconsistent state, leading to further vulnerabilities and potential exploitation. This can indirectly impact the handling of funds and disrupt the protocol's functionality.


## Proof of Concept
Create a merkle expansion `me` with a large number of levels, close to the maximum allowed limit of 64 (defined by `MAX_LEVEL`)

Each level of the merkle expansion corresponds to a `bytes32` value in the me array.

In the `root` function, there is a loop that iterates over the levels of the merkle expansion and performs bitwise operations and hash calculations.

If the merkle expansion contains values that, when combined with the existing `accum` value, exceed the maximum value representable by `bytes32`, an overflow will occur.

The overflow will cause the resulting `accum` value to wrap around, leading to an incorrect merkle root calculation.

The incorrect merkle root can propagate throughout the protocol, causing inconsistencies and potential vulnerabilities.

When the `root` function processes these values with a large number of levels, close to the maximum allowed limit of 64, the `accum` variable will keep accumulating the hashed values. However, due to the lack of overflow checks, the `accum` value will eventually exceed the maximum value representable by `bytes32`, causing an overflow. The resulting `accum` value will be incorrect, leading to an incorrect merkle root calculation.

## Recommended Mitigation Steps
Use the SafeMath library or perform explicit overflow checks before performing arithmetic operations in the `root` function.

Validate and sanitize the input values to ensure they are within safe ranges and do not cause overflows.
