## Impact

However, it then updates the internal state of the contract by setting `_latestConfirmed = assertionHash` and `assertion.status = AssertionStatus.Confirmed`.

This order of operations can lead to a potential race condition or inconsistent state if the function is interrupted or reverted after updating the outbox contract but before updating the internal state.

## Proof of Concept
By updating the `sendRoot` in the outbox contract before updating the internal state (`_latestConfirmed` and `assertion.status`), the function introduces a potential race condition or inconsistent state issue.

The function calls `outbox.updateSendRoot(sendRoot, blockHash)`, which updates the state of the external outbox contract.

If the function execution is interrupted or reverted at this point (e.g., due to an out-of-gas error, an exception, or a malicious attack), the internal state of the contract (`_latestConfirmed` and `assertion.status`) remains unchanged.

However, the outbox contract's state has already been updated with the new `sendRoot`. This leads to an inconsistent state between the internal state of the contract and the external outbox contract.

If the function is retried or called again with the same parameters, it will fail because the internal state (`_latestConfirmed` and `assertion.status`) does not reflect the updated state of the outbox contract.

**This inconsistent state can lead to various issues, such as:**

Incorrect data being used in subsequent operations or calculations.
Potential security vulnerabilities, as the contract's internal state may not match the expected state based on external contract interactions.
Difficulty in debugging and maintaining the contract, as the state can become unpredictable.

## Recommended Mitigation Steps
Update the internal state first and then interact with external contracts. This way, if the function is interrupted or reverted, the internal state remains consistent and can be retried safely.
```solidity
function confirmAssertionInternal(
    bytes32 assertionHash,
    bytes32 parentAssertionHash,
    AssertionState calldata confirmState,
    bytes32 inboxAcc
) internal {
    AssertionNode storage assertion = getAssertionStorage(assertionHash);
    // Check that assertion is pending, this also checks that assertion exists
    require(assertion.status == AssertionStatus.Pending, "NOT_PENDING");

    // Authenticate data against assertionHash pre-image
    require(
        assertionHash
            == RollupLib.assertionHash({
                parentAssertionHash: parentAssertionHash,
                afterState: confirmState,
                inboxAcc: inboxAcc
            }),
        "CONFIRM_DATA"
    );

    bytes32 blockHash = confirmState.globalState.getBlockHash();
    bytes32 sendRoot = confirmState.globalState.getSendRoot();

    // Update internal state first
    _latestConfirmed = assertionHash;
    assertion.status = AssertionStatus.Confirmed;

    // Interact with external contract after updating internal state
    outbox.updateSendRoot(sendRoot, blockHash);

    emit AssertionConfirmed(assertionHash, blockHash, sendRoot);
}
```
By updating the internal state first and then interacting with the external outbox contract, the function ensures that the internal state remains consistent even if the external call fails or the function is interrupted.
