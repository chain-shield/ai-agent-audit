# Vulnerability details

### Summary
The `createEdge` function in `EdgeStakingPool.sol` of the Arbitrum Foundation repository does not properly restrict access, allowing any caller to potentially misuse this function, leading to unauthorized creation of edges in the system.

### Vulnerability
Type: Access Control Issue
Impact: High
Location:https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/assertionStakingPool/EdgeStakingPool.sol#L44-L51

### Description
The `createEdge` function lacks proper access control, which means that any external user can call this function. This can lead to unauthorized creation of edges and manipulation of the staking allowances.

### Potential Impact
Unauthorized Edge Creation: Any user can create an edge, leading to potential inconsistencies and unauthorized edges in the system.
Financial Loss: By manipulating the staking allowances, an attacker could potentially drain tokens or manipulate the staking mechanism for personal gain.
Recommended Mitigation Steps
Add Access Control: Implement a modifier to restrict access to authorized users only. For instance, use `onlyOwner` or similar role-based access control.
Review and Audit: Conduct a thorough review and audit of all functions to ensure proper access control is implemented.

### Example Fix
Add an access control modifier to the createEdge function:
// Assuming Ownable is used for access control
import "@openzeppelin/contracts/access/Ownable.sol";

contract EdgeStakingPool is AbsBoldStakingPool, IEdgeStakingPool, Ownable {}

function createEdge(CreateEdgeArgs calldata args) external onlyOwner {
    uint256 requiredStake = EdgeChallengeManager(challengeManager).stakeAmounts(args.level);
    IERC20(stakeToken).safeIncreaseAllowance(address(challengeManager), requiredStake);
    bytes32 newEdgeId = EdgeChallengeManager(challengeManager).createLayerZeroEdge(args);
    if (newEdgeId != edgeId) {
        revert IncorrectEdgeId(newEdgeId, edgeId);
    }
}
