# Vulnerability details

## Impact
In the following line: [#L122](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BridgeCreator.sol#L122)
```solidity
frame.sequencerInbox.initialize(IBridge(frame.bridge), maxTimeVariation, bufferConfig);
```
The `SequencerInbox` contract is initialized with the `maxTimeVariation` and `bufferConfig` arguments. However, the `SequencerInbox` contract also requires the `isUsingFeeToken` parameter to be set during initialization.

The `isUsingFeeToken` parameter determines whether the `SequencerInbox` contract should handle fee payments in the native token (e.g., ETH) or an ERC20 token. This parameter is crucial for the correct functioning of the `SequencerInbox` contract, as it affects how fees are processed and transferred.

By not setting the `isUsingFeeToken` parameter during initialization, the `SequencerInbox` contract may behave unexpectedly or fail to function correctly when handling fee payments.

## Proof of Concept
If the `SequencerInbox` contract attempts to transfer fees using the wrong token type, it may result in funds being sent to an incorrect address or becoming permanently locked and unrecoverable.

Supporting evidence from the provided code: [#L122](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BridgeCreator.sol#L122)
```solidity
frame.sequencerInbox.initialize(IBridge(frame.bridge), maxTimeVariation, bufferConfig);
```
In this line, the `initialize` function of the `SequencerInbox` contract is called without providing the `isUsingFeeToken` parameter, which is likely required for proper initialization.

The `createBridge` function determines whether to create an ETH-based bridge or an ERC20-based bridge based on the `nativeToken` parameter: [#L110-L114](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BridgeCreator.sol#L110-L114)

```solidity
BridgeContracts memory frame = _createBridge(
    adminProxy,
    nativeToken == address(0) ? ethBasedTemplates : erc20BasedTemplates,
    isDelayBufferable
);
```
However, this information about the fee token type is not passed to the `SequencerInbox` contract during initialization.

## Recommended Mitigation Steps
The function should pass the appropriate value for the `isUsingFeeToken` parameter when initializing the `SequencerInbox` contract. This value should be determined based on whether the `nativeToken` address is the zero address (for native token) or a valid ERC20 token address.

```solidity
frame.sequencerInbox.initialize(
    IBridge(frame.bridge),
    maxTimeVariation,
    bufferConfig,
    nativeToken == address(0) // isUsingFeeToken
);
```
By passing `nativeToken == address(0)` as the `isUsingFeeToken` parameter, the `SequencerInbox` contract will be correctly initialized to handle fees in the native token (if `nativeToken` is the zero address) or an ERC20 token (if `nativeToken` is a valid token address).

It's important to ensure that the initialize function of the `SequencerInbox` contract accepts the `isUsingFeeToken` parameter and handles it correctly. If the initialize function signature or implementation is different, the necessary adjustments should be made accordingly.
