# Vulnerability details

## Vulnerability Details

In the `EdgeStakingPool.sol` contract of the `2024-05-arbitrum-foundation` repository, there is a potentially problematic usage of the `SafeERC20` library. 

### The vulnerable line of code is as follows:

```solidity
IERC20(stakeToken).safeIncreaseAllowance(address(challengeManager), requiredStake);

This line appears to be attempting to increase the allowance of stakeToken for the challengeManager address by requiredStake amount. However, the safeIncreaseAllowance function in the SafeERC20 library expects three arguments: the IERC20 token instance, spender address, and value. In this usage, it only provides two arguments, which should result in a compilation error.

Additionally, it's worth noting that the IERC20 interface referenced in the type casting (IERC20(stakeToken)) is not being extended or implemented by the SafeERC20 library. The SafeERC20 library is a utility library for interacting with ERC-20 tokens, but it doesn't directly interact with the IERC20 interface.

### Recommendation:
The usage of SafeERC20 should adhere to its defined interface. Ensure that when calling safeIncreaseAllowance, all three required arguments are provided: the IERC20 token instance, spender address, and value. Additionally, verify that the token instance passed to safeIncreaseAllowance is indeed an instance of an ERC-20 token implementing the IERC20 interface.
