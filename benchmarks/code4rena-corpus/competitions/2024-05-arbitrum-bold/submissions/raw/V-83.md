# Vulnerability details

## Impact
The `fastConfirmNewAssertion` function in the `RollupUserLogic` contract lacks proper checks to ensure that only the designated `anyTrustFastConfirmer` can call it. This vulnerability allows any address to call the function, potentially leading to several critical issues:
* Unauthorized Access: Without verifying the caller, unauthorized entities can bypass the normal validation and staking processes, compromising the integrity of the rollup protocol.
* Security Check Bypass: Skipping essential security checks allows attackers to confirm assertions without proper validation, leading to potential exploits and inconsistencies in the contract state.

## Proof of Concept

## Recommended Mitigation Steps
Ensure that only the designated `anyTrustFastConfirmer` can call the `fastConfirmNewAssertion` function.

 `require(msg.sender == anyTrustFastConfirmer, "NOT_FAST_CONFIRMER");`
