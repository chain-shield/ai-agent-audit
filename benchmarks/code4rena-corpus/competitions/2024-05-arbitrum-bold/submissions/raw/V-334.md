# Vulnerability details

## Vulnerability Details
The vulnerability is from the calculation of assertionBlocks within the confirmEdgeByTime function, The difference between the blocks at which the first and second child assertions are created is used to calculate assertionBlocks. 
This value is then used to determine totalTimeUnrivaled and here is the vulnerable line :
```solidity
 bool isBlockLevel = ChallengeEdgeLib.levelToType(topEdge.level, NUM_BIGSTEP_LEVEL) == EdgeType.Block;
        if (isBlockLevel && assertionChain.isFirstChild(topEdge.claimId)) {
            assertionChain.validateAssertionHash(
                topEdge.claimId,
                claimStateData.assertionState,
                claimStateData.prevAssertionHash,
                claimStateData.inboxAcc
            );
            assertionBlocks = assertionChain.getSecondChildCreationBlock(claimStateData.prevAssertionHash)
                - assertionChain.getFirstChildCreationBlock(claimStateData.prevAssertionHash);
        }

        uint256 totalTimeUnrivaled = store.confirmEdgeByTime(edgeId, assertionBlocks, challengePeriodBlocks);
```
here the  function interacts with the assertion chain for creation blocks of the first and second child assertions.
 and the calculation of assertionBlocks relies on the timing between these blocks.
if an attacker delays the submission of the second child assertion, they can extend assertionBlocks.
## Proof of Concept
in scenario that show 
- in first child assertion submitted at block 1000.
- and in second child assertion delayed until block 1100.
- as result the assertionBlocks calculated as `1100−1000=100`.
- in scenario that show the Inflation
- At the First child assertion submitted at block 2000.
- at Second child assertion delayed until block 2200  inflated delay.
- as result assertionBlocks calculated as `2200−2000=200`.
- this show that the assertionBlocks calculation relies on the difference between the first and second child creation blocks. so If the second child assertion is delayed, itextends assertionBlocks.  and this value is used in the confirmEdgeByTime function to calculate totalTimeUnrivaled.
```python 
Scenario 1: With a 100 block delay, totalTimeUnrivaled is 100 blocks.
Scenario 2: With a 200 block delay, totalTimeUnrivaled is 200 blocks.
```

```solidity
class AssertionChain:
    def __init__(self):
        self.first_child_block = {}
        self.second_child_block = {}

    def getFirstChildCreationBlock(self, assertion_hash):
        return self.first_child_block.get(assertion_hash, 0)

    def getSecondChildCreationBlock(self, assertion_hash):
        return self.second_child_block.get(assertion_hash, 0)

    def createAssertion(self, assertion_hash, block_number):
        if assertion_hash not in self.first_child_block:
            self.first_child_block[assertion_hash] = block_number
        else:
            self.second_child_block[assertion_hash] = block_number

    def isFirstChild(self, assertion_hash):
        return assertion_hash in self.first_child_block


def confirmEdgeByTime(assertion_chain, edge_id, claim_id, claim_state_data):
    assertionBlocks = 0
    isBlockLevel = True  # Assume it is a block level edge for simplicity

    if isBlockLevel and assertion_chain.isFirstChild(claim_id):
        assertionBlocks = (assertion_chain.getSecondChildCreationBlock(claim_state_data['prevAssertionHash']) -
                           assertion_chain.getFirstChildCreationBlock(claim_state_data['prevAssertionHash']))

    totalTimeUnrivaled = assertionBlocks  # Simplified for this simulation
    return totalTimeUnrivaled
```
