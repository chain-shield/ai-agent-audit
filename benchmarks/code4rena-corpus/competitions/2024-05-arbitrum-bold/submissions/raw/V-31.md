# Vulnerability details

## Impact
This `initialize` function is missing the `initializer` modifier. Without this modifier, there is a risk that the initialization function can be called multiple times, leading to unintended behavior or vulnerabilities.

Attackers can exploit this vulnerability to reinitialize the contract, potentially modifying critical contract parameters and dependencies. This can disrupt the normal operation of the contract and compromise the integrity of the rollup system.

Malicious actors could call the `initialize` function multiple times with different configurations and dependencies, overwriting or corrupting the contract's state. This could lead to inconsistencies, unexpected behavior, and potential loss of funds or control over the contract.

## Proof of Concept
An attacker can call the `initialize` function multiple times with different `config` and `connectedContracts` parameters, effectively overriding the initial setup of the contract. This can be done by crafting transactions that invoke the initialize function with manipulated values.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Implementing a modifier, such as `onlyOwner` or `Initializer`, to restrict access to the function only to authorized entities.
