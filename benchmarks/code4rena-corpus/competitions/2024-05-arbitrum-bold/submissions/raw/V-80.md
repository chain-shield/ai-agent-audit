# Vulnerability details

## Impact
The issue identified in the `EdgeStakingPool` contract pertains to an incorrect attempt to instantiate the `EdgeChallengeManager` contract and call a non-existent `stakeAmounts` function. This mistake is present in the `createEdge` function, specifically at the line where `requiredStake` is calculated.

The incorrect instantiation and function call in the `EdgeStakingPool` contract could lead to failed transactions, increased gas costs, and potential security vulnerabilities. Specifically, the contract attempts to create a new instance of `EdgeChallengeManager` using an existing contract address, which is not feasible in Solidity. Additionally, the call to a non-existent `stakeAmounts` function would result in a runtime error, preventing the execution of the `createEdge` function as intended.

## Proof of Concept
The issue is located in the `EdgeStakingPool` contract, specifically at this line:
```solidity
uint256 requiredStake = EdgeChallengeManager(challengeManager).stakeAmounts(args.level);
```
This line incorrectly suggests that a new instance of `EdgeChallengeManager` is being created using the `challengeManager` address. This is not possible in Solidity, and the correct approach would involve directly interacting with the `EdgeChallengeManager` contract through its address.

## Recommended Mitigation Steps with Fix Code

Since the `stakeAmounts` function does not exist in the provided code snippets, the recommended mitigation involves directly accessing the `stakeAmounts` data if it is a public state variable in the `EdgeChallengeManager` contract. If `stakeAmounts` is not publicly accessible, consider adding a getter function in the `EdgeChallengeManager` contract to safely retrieve stake amounts based on the level.

Here's a corrected version of the `createEdge` function, assuming `stakeAmounts` is a public array in `EdgeChallengeManager`:
