# Vulnerability details

## Bug Description
In the `updateRollupAddress` function.
```solidity
    function updateRollupAddress() external {
        if (msg.sender != IOwnable(rollup).owner())
            revert NotOwner(msg.sender, IOwnable(rollup).owner());
        IOwnable newRollup = bridge.rollup();
        if (rollup == newRollup) revert RollupNotChanged();
        rollup = newRollup;
    }
````
The issue is that the function is checking if the `rollup` address has changed by comparing the current `rollup` address with the new `rollup` address returned by `bridge.rollup()`. However, this comparison is done using the `==` operator, which compares the reference of the contract instances, not the actual contract addresses.

In Solidity, contract instances are reference types, and the `==` operator compares the references, not the underlying contract addresses. This means that even if the new `rollup` address is different from the current `rollup` address, the `rollup == newRollup` condition may still evaluate to `true` if the two contract instances have the same reference.

## Impact

The primary impact of this issue is that the `rollup` address may not be updated correctly, even when the new `rollup` address returned by `bridge.rollup()` is different from the current `rollup` address. This could lead to the following consequences.

_If the `rollup` address is not updated correctly, the contract may operate with an outdated or incorrect `rollup` address. This could result in incorrect state transitions, data inconsistencies, or other unintended behavior._

_If the `rollup` address is not updated correctly, it could lead to a situation where the contract becomes unusable or stuck in an invalid state, effectively causing a denial of service._

## Proof of Concept
To better understand the issue, let's consider the following example.

```solidity
pragma solidity ^0.8.0;

contract RollupContract {
    address public rollupAddress;

    function setRollupAddress(address newRollupAddress) public {
        rollupAddress = newRollupAddress;
    }
}

contract BridgeContract {
    RollupContract public rollup;

    constructor(RollupContract _rollup) {
        rollup = _rollup;
    }

    function updateRollup(RollupContract newRollup) public {
        // Incorrect comparison using the `==` operator
        if (rollup == newRollup) {
            // This condition may be true even if the addresses are different
            revert("Rollup address not changed");
        }
        rollup = newRollup;
    }
}
```
We have a `BridgeContract` that manages a `RollupContract` instance. The `updateRollup` function in the `BridgeContract` is supposed to update the `rollup` instance with a new `RollupContract` instance. However, the comparison `rollup == newRollup` is done using the `==` operator, which compares the references of the contract instances, not the actual contract addresses.

**Let's illustrate this with an example scenario:**

Initially, we have a `RollupContract` instance at address `0x123...` and a `BridgeContract` instance that holds a reference to this `RollupContract` instance.
We create a new `RollupContract` instance at address `0x456....`
We call `updateRollup` in the `BridgeContract` with the new `RollupContract` instance.
Even though the new `RollupContract` instance has a different address (`0x456...`), the `rollup == newRollup` condition may still evaluate to true because the references of the contract instances are compared, not the actual addresses.
As a result, the `rollup` instance in the `BridgeContract` will not be updated, and the contract will continue to operate with the old `RollupContract` instance at address `0x123....`

## Recommended Mitigation Steps
We should compare the actual contract addresses instead of the contract instances by using the `address` type conversion.

```solidity
function updateRollupAddress() external {
    if (msg.sender != IOwnable(rollup).owner())
        revert NotOwner(msg.sender, IOwnable(rollup).owner());
>   address newRollupAddress = address(bridge.rollup());
>   if (address(rollup) == newRollupAddress) revert RollupNotChanged();
>   rollup = IOwnable(newRollupAddress);
 }
```
In this version, the `address(rollup)` and `address(bridge.rollup())` expressions convert the contract instances to their respective addresses, which are then compared using the `==` operator. This ensures that the comparison is done correctly, and the `rollup` address is only updated if the new address is different from the current one.

`rollup` is assigned an `IOwnable` instance created with the new address, which is more secure than assigning the raw address as in the first version [**Here**](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L208-L214)
