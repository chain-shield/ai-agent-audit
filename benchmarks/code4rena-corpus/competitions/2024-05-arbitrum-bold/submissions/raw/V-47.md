# Vulnerability details

## Impact
The `createRollup` function in the `RollupCreator` contract does not perform explicit checks to verify the existence of addresses before making external calls to various contracts, such as `Bridge`, `IInboxBase`, `IOutbox`, and `IEdgeChallengeManager`. When the function makes an external call to a non-existent address (i.e., a contract that has not been deployed or has been self-destructed), the call will still return success without reverting. This lack of address existence verification can lead to false assumptions about the success of the calls and subsequent actions based on those assumptions.

The lack of address existence verification in the `createRollup` function can contribute to unexpected behavior and potential exploits. An attacker could manipulate the input parameters to make the function call non-existent addresses, bypassing certain checks or assumptions made based on the success of those calls. This can lead to inconsistent state, improper rollup creation, or other unintended consequences that could disrupt the normal functioning of the protocol and potentially lead to further vulnerabilities.

## Proof of Concept
An attacker identifies the lack of address existence verification in the `createRollup` function.

The attacker manipulates the input parameters to include non-existent addresses for contracts like `Bridge`, `IInboxBase`, `IOutbox`, or `IEdgeChallengeManager`.

The `createRollup` function makes external calls to these non-existent addresses without verifying their existence.

The calls to the non-existent addresses return success without reverting, leading to false assumptions about the success of those interactions.

The function continues execution based on the false assumptions, potentially leading to inconsistent state, improper rollup creation, or other unexpected behavior.

The attacker can then exploit these inconsistencies or unexpected behaviors to perform further malicious actions or attacks on the protocol.

## Recommended Mitigation Steps
Implement proper checks in the `createRollup` function to verify the existence of addresses before making external calls. Handle the cases where the called contracts do not exist gracefully and ensure that the function's behavior remains consistent and predictable. Additionally, consider implementing fallback mechanisms or error handling to prevent unexpected behavior when interacting with external contracts.
