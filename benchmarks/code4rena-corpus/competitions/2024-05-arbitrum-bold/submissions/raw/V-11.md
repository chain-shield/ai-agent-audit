# Vulnerability details

## Impact

The primary impact of this issue is the inability to deploy the `EdgeChallengeManager` contract on the Ethereum mainnet. This limitation prevents the contract from being utilized in live scenarios, affecting the functionality and potential benefits of the system it is intended to support.

## Proof of Concept
The `EdgeChallengeManager` contract in the provided codebase exceeds the Ethereum mainnet's deployment limit of 24,576 bytes (24.576 KB). This issue arises due to the contract's compiled bytecode size being 26,651 bytes, which is beyond the acceptable threshold for deployment on the Ethereum mainnet.

The bytecode size issue was identified during a manual review of the contract using Visual Studio Code. The specific line of code where the issue was found is available at the following link:

[EdgeChallengeManager.sol Line 206](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/challengeV2/EdgeChallengeManager.sol#L206)

The proof of concept demonstrates that the contract's bytecode size exceeds the Ethereum mainnet's deployment limit, as evidenced by the output of the `forge build --sizes` command, which reported the contract's size as 26,651 bytes.

## Recommended Mitigation Steps with Fix Code

To mitigate this issue, the following steps are recommended:

1. **Review and Optimize Contract Logic**: Carefully review the contract's logic to identify any redundant or unnecessary code. Simplifying the logic can lead to smaller bytecode.

2. **Enable Compiler Optimizations**: Increase the number of optimizer runs in the Solidity compiler settings. This can sometimes yield better optimization results at the cost of slightly increased compilation time.

3. Consider enabling the optimizer (with a low "runs" value!), turning off revert strings, or using libraries.
