# Vulnerability details

## Impact
The atacker can reenter in `withdrawStaker` function and increase the withdraw founds many times before `stakerAddress` is deleted.


## Proof of Concept
https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L321-L322

First make external call `increaseWithdrawableFunds(withdrawalAddress, initialStaked);` then update the state `deleteStaker(stakerAddress);`

## Tools Used
Manual review
## Recommended Mitigation Steps

Implement the check-effects-interactions pattern. This involves doing as checks and state changes before making external calls. To implement this in the current context set `deleteStaker(stakerAddress) before making the `increaseWithdrawableFunds(withdrawalAddress, initialStaked);` call.

```solidity
 function withdrawStaker(address stakerAddress) internal {
        Staker storage staker = _stakerMap[stakerAddress];
        address withdrawalAddress = staker.withdrawalAddress;
        uint256 initialStaked = staker.amountStaked;
        deleteStaker(stakerAddress);
        increaseWithdrawableFunds(withdrawalAddress, initialStaked);
        emit UserStakeUpdated(stakerAddress, withdrawalAddress, initialStaked, 0);
    }
```
