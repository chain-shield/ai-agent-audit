# Vulnerability details

## Impact
The calculation of [bounds.minBlockNumber](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L228-L230) in [getTimeBounds() function](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/bridge/SequencerInbox.sol#L216-L233).

```solidity
if (block.number > delayBlocks_) {
    bounds.minBlockNumber = uint64(block.number) - delayBlocks_;
}
```
The issue here is that if `block.number` is less than or equal to `delayBlocks_`, `bounds.minBlockNumber` will not be assigned a value. This means that `bounds.minBlockNumber` could potentially be uninitialized, which could lead to unexpected behavior or errors when this value is used later in the code.

## Proof of Concept

getTimeBounds function is responsible for calculating the minimum and maximum block numbers and timestamps that are allowed for incoming messages to the Sequencer Inbox. These bounds are used to ensure that messages are not accepted too far in the past or future, which could potentially lead to security vulnerabilities or inconsistencies in the system.

The issue arises when the current block number (`block.number`) is less than or equal to the `delayBlocks_` value, which represents the minimum number of blocks that must have elapsed before a message can be accepted. In this case, the `bounds.minBlockNumber` variable is not assigned a value, leaving it uninitialized.

If `bounds.minBlockNumber` is left uninitialized, it could potentially contain a random or garbage value, depending on the memory layout and previous state of the contract. This uninitialized value could then be used in other parts of the contract or external contracts that rely on the `getTimeBounds` function, leading to unexpected and potentially harmful behavior.

For example, if the uninitialized `bounds.minBlockNumber` value is used in a comparison or calculation involving block numbers, it could result in incorrect decisions being made about whether to accept or reject incoming messages. This could potentially allow messages to be accepted or rejected incorrectly, violating the intended security and consistency guarantees of the system.

An example of how the uninitialized `bounds.minBlockNumber` could lead to issues:
```solidity
function processMessage(uint64 blockNumber, ...) external {
    IBridge.TimeBounds memory bounds = getTimeBounds();
    if (blockNumber < bounds.minBlockNumber) {
        // Reject message as too old
        revert("Message too old");
    }
    // Process message
    ...
}
```
In this hypothetical function, if `bounds.minBlockNumber` is uninitialized and contains a very large value (e.g., due to memory layout or previous state), it could cause valid messages with recent block numbers to be incorrectly rejected as "too old". Conversely, if `bounds.minBlockNumber` is uninitialized and contains a very small value, it could allow messages from the distant past to be accepted, potentially violating the intended security guarantees of the system.

## Recommended Mitigation Steps
Should initialize `bounds.minBlockNumber` to a default value, such as 0, before the `if` statement. This way, even if `block.number` is less than or equal to `delayBlocks_`, `bounds.minBlockNumber` will have a valid value.

```solidity
function getTimeBounds() internal view virtual returns (IBridge.TimeBounds memory) {
    IBridge.TimeBounds memory bounds;
    bounds.minBlockNumber = 0; // Initialize to a default value

    (
        uint64 delayBlocks_,
        uint64 futureBlocks_,
        uint64 delaySeconds_,
        uint64 futureSeconds_
    ) = maxTimeVariationInternal();

    if (block.timestamp > delaySeconds_) {
        bounds.minTimestamp = uint64(block.timestamp) - delaySeconds_;
    }
    bounds.maxTimestamp = uint64(block.timestamp) + futureSeconds_;

    if (block.number > delayBlocks_) {
        bounds.minBlockNumber = uint64(block.number) - delayBlocks_;
    }
    bounds.maxBlockNumber = uint64(block.number) + futureBlocks_;

    return bounds;
}
```
By initializing `bounds.minBlockNumber` to 0, you ensure that it always has a valid value, even if the `if` condition is not met.
