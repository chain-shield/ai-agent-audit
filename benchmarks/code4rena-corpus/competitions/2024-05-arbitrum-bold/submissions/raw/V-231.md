# Vulnerability details

The way the `totalWithdrawableFunds` variable is updated. The `line totalWithdrawableFunds -= amount;` subtracts the amount being withdrawn from the `totalWithdrawableFunds`, this operation assumes that the `totalWithdrawableFunds` is always greater than or equal to the amount being withdrawn. [src\rollup\RollupCore.sol:331-337](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L331-L337)

```solidity
    function withdrawFunds(address account) internal returns (uint256) {
        uint256 amount = _withdrawableFunds[account];
        _withdrawableFunds[account] = 0;
        totalWithdrawableFunds -= amount;
        emit UserWithdrawableFundsUpdated(account, amount, 0);
        return amount;
    }
```
If the `totalWithdrawableFunds` is less than the `amount` being withdrawn, this operation will result in an underflow, causing the `totalWithdrawableFunds` to become a very large value due to the way unsigned integers wrap around in Solidity.

## Impact
**Underflow Vulnerability**
The line `totalWithdrawableFunds -= amount;` assumes that `totalWithdrawableFunds` is always greater than or equal to the `amount` being withdrawn. However, if `totalWithdrawableFunds` is less than `amount`, the subtraction operation will result in an underflow.

**Unsigned Integer Wrap-around**
In Solidity, unsigned integers wrap around when they underflow or overflow. This means that if an underflow occurs, the value will wrap around to the maximum value of the data type instead of reverting or throwing an error.

For example, if `totalWithdrawableFunds` is `1`, and `amount` is 2, the subtraction `totalWithdrawableFunds -= amount` will result in an underflow. Instead of reverting or throwing an error, the value of `totalWithdrawableFunds` will wrap around to the maximum value of the `uint256` data type, which is `2^256 - 1` (approximately `1.157 * 10^77`).

_Incorrect State:_ The underflow and subsequent wrap-around will result in an incorrect state for the `totalWithdrawableFunds` variable. Instead of having a value close to zero (as expected after withdrawing funds), it will have an extremely large value, which can lead to further issues and unexpected behavior in the contract.

## Proof of Concept
See this example that illustrates the underflow and wrap-around behavior:
```solidity
pragma solidity ^0.8.0;

contract UnderflowExample {
    uint256 public totalWithdrawableFunds = 1;

    function withdrawFunds(uint256 amount) public {
        totalWithdrawableFunds -= amount;
    }
}
```
If we deploy this contract and call the `withdrawFunds` function with an `amount` of `2`, the value of `totalWithdrawableFunds` will wrap around to the maximum value of `uint256` (approximately `1.157 * 10^77`), which is clearly an incorrect state.

## Recommended Mitigation Steps
The code should check if the `totalWithdrawableFunds` is greater than or equal to the `amount` being withdrawn before performing the subtraction operation. 
```solidity
function withdrawFunds(address account) internal returns (uint256) {
    uint256 amount = _withdrawableFunds[account];
    _withdrawableFunds[account] = 0;
    
    if (totalWithdrawableFunds >= amount) {
        totalWithdrawableFunds -= amount;
    } else {
        // Handle the case where totalWithdrawableFunds is less than amount
        // (e.g., revert the transaction or set totalWithdrawableFunds to 0)
    }
    
    emit UserWithdrawableFundsUpdated(account, amount, 0);
    return amount;
}
```
By adding this check, the function will prevent the underflow issue and handle the case where the `totalWithdrawableFunds` is less than the `amount` being withdrawn in a more controlled manner.
