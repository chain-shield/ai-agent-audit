# Vulnerability details

## Impact
The setInbox, setValidatorWhitelistDisabled, setAnyTrustFastConfirmer, and setChallengeManager functions do not have any access control mechanisms, allowing anyone to call these functions. This can lead to significant security risks such as:

- Unauthorized Modification of Critical Addresses: An attacker could change the inbox address to a malicious contract, redirecting messages and potentially causing loss of funds or other unwanted behavior.
- Compromised Validator Whitelist: Disabling the validator whitelist without proper authorization could allow unauthorized or malicious validators to participate in the rollup, undermining the security and integrity of the rollup system.
- Malicious Fast Confirmation: Setting a new anyTrustFastConfirmer address to an attacker-controlled address could compromise the fast confirmation mechan

## Proof of Concept
1. Deploy the Contract:
```
RollupAdminLogic rollup = new RollupAdminLogic();
```
2. Attacker Modifies the Inbox Address:

```
address maliciousInbox = 0x123...; // Attacker's malicious inbox address
rollup.setInbox(maliciousInbox);
```
3. ttacker Disables Validator Whitelist:
```
rollup.setValidatorWhitelistDisabled(true);
```
4. Attacker Sets a Malicious AnyTrustFastConfirmer:
```
address maliciousConfirmer = 0x456...; // Attacker's malicious confirmer address
rollup.setAnyTrustFastConfirmer(maliciousConfirmer);
```
5. Attacker Changes the Challenge Manager:
```
address maliciousChallengeManager = 0x789...; // Attacker's malicious challenge manager address
rollup.setChallengeManager(maliciousChallengeManager);
```
