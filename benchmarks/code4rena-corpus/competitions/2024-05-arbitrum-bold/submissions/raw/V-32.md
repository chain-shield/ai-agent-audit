### Vulnerability Details

In the `EdgeChallengeManager.sol` contract of the 2024-05-arbitrum-foundation repository, there are calls to the `safeTransfer` and `safeTransferFrom` functions from the `SafeERC20` library provided by OpenZeppelin. However, there's a discrepancy between the number of arguments expected by these functions in the library and the number of arguments provided in the calls within the contract.

#### Issue 1: `safeTransfer`

In the SafeERC20 library ([SafeERC20.sol](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/ca2b85d786dfc07acfbf62de1893ff73363d614b/contracts/token/ERC20/utils/SafeERC20.sol#L36)), the `safeTransfer` function is defined as:

```solidity

However, in the EdgeChallengeManager.sol contract (EdgeChallengeManager.sol), the call is made with only two arguments:

st.safeTransfer(edge.staker, sa);


### Issue 2: safeTransferFrom
Similarly, in the SafeERC20 library (SafeERC20.sol), the safeTransferFrom function is defined as:


function safeTransferFrom(IERC20 token, address from, address to, uint256 value) internal {}
However, in the EdgeChallengeManager.sol contract (EdgeChallengeManager.sol), the call is made with only three arguments:


st.safeTransferFrom(msg.sender, receiver, sa);


### Impact
These discrepancies could potentially lead to runtime errors or unintended behavior, as the functions in the SafeERC20 library expect a different number of arguments than what is provided in the contract.

### Recommendations
Ensure that the calls to safeTransfer and safeTransferFrom in the EdgeChallengeManager.sol contract provide the correct number of arguments as per the definitions in the SafeERC20 library to prevent potential runtime errors and ensure the intended behavior of the contract.
