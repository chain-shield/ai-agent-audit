# Vulnerability details

## Impact

When calling [`BOLDUpgradeAction#perform`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L464) to initialize `challengeManager` contract, the function calculate the `expectedRollupAddress` by `Create2Upgradeable.computeAddress(rollupSalt, keccak256(type(RollupProxy).creationCode))`, internally call [`Create2Upgradeable#computeAddress`](https://github.com/OpenZeppelin/openzeppelin-contracts-upgradeable/blob/0a2cb9a445c365870ed7a8ab461b12acf3e27d63/contracts/utils/Create2Upgradeable.sol#L58-L65) function, so the new rollup address can be predicable. Such contracts will be deployed on ethereum mainnet, attackers can monitor the mempool, calculate the `expectedRollupAddress` based on `rollupSalt`, `RollupProxy.creationCode`, `BOLDUpgradeAction` address then create the address before `BOLDUpgradeAction#perform` tx, such that new bold upgrade action will revert.


[`RollupCreator#createRollup`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L188) has the same issue.
