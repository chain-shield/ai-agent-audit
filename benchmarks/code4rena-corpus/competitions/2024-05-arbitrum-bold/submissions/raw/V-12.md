# Vulnerability details

## Impact
The `signature replay` vulnerability in the `StateHashPreImageLookup` contract  allows an attacker to reuse a `valid signature` multiple times. Once an attacker acquires a valid signature for a specific update, they can repeatedly call the `set()` function with the same `signature` to modify the value multiple times. 

This unauthorized and unintended behavior occurs because the contract doesn’t have safeguards to prevent the reuse of the same `signature`.

## Proof of Concept
The contract uses the [stateHash()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L101-L104) function to generate a signature based on `executionState.globalState.hash(), inboxMaxCount & executionState.machineStatus`. 
```solidity
    function stateHash(ExecutionState calldata executionState, uint256 inboxMaxCount) public pure returns (bytes32) {
        return
            keccak256(abi.encodePacked(executionState.globalState.hash(), inboxMaxCount, executionState.machineStatus));
    }
```

This signature is then used in setting `preImages`. The [set()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L106-L110) function verifies if the signature, `h`, provided by the caller matches the valid signature generated by `stateHash()` above. If this condition is not met, the function reverts.
```solidity
    function set(bytes32 h, ExecutionState calldata executionState, uint256 inboxMaxCount) public {
        require(h == stateHash(executionState, inboxMaxCount), "Invalid hash");
        preImages[h] = abi.encode(executionState, inboxMaxCount);
        emit HashSet(h, executionState, inboxMaxCount);
    }
```

However, the contract does not have measures in place to prevent `signature replay`. This is so because as long a user provides a valid signature, `h`, the function allows them to modify the `preImage` without checking if the same `signature` has been used before.

## Recommended Mitigation Steps
To mitigate this vulnerability, it is crucial to implement measures such as `storing and tracking transaction hashes` to ensure the uniqueness and validity of each transaction, thereby preventing unauthorized replay attacks.

1. `By storing transaction hash`
We store the hash of each executed transaction and prevent re-execution of the same transaction. 

```solidity
    mapping(bytes32 => bool) public executedTransactions; // @audit Add a tracking mapping


    function stateHash(ExecutionState calldata executionState, uint256 inboxMaxCount) public pure returns (bytes32) {
        return
            keccak256(abi.encodePacked(executionState.globalState.hash(), inboxMaxCount, executionState.machineStatus));
    }


    function set(bytes32 h, ExecutionState calldata executionState, uint256 inboxMaxCount) public {
        require(h == stateHash(executionState, inboxMaxCount), "Invalid hash");

        // @audit Require that it has not been executed
        require(!_isTransactionExecuted(h), "Transaction has already been executed");
        preImages[h] = abi.encode(executionState, inboxMaxCount);
        
        // @audit Mark as executed
        _markTransactionExecuted(h);
        emit HashSet(h, executionState, inboxMaxCount);
    }

    // @audit Check if already executed
    function _isTransactionExecuted(bytes32 _h) private view returns (bool) {
        return executedTransactions[_h];
    }

    // @audit Mark as already executed
    function _markTransactionExecuted(bytes32 _h) private {
        executedTransactions[_h] = true;
    }
```
