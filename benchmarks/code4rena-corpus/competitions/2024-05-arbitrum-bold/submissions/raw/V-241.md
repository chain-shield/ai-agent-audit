# Vulnerability details

## Impact
The way the `_stakeAmounts` parameter is passed to the initialize function of the `ChallengeManager` contract. The `_stakeAmounts` parameter is expected to be an array of `uint256` values, but in the current implementation, it is being passed as a single `uint256` value (`config.miniStakeValues`).

This could lead to unexpected behavior or errors when the `ChallengeManager` contract tries to access or manipulate the `_stakeAmounts` array, as it would be treating a single value as an array.

_Edge Creation since the `_stakeAmounts` array is used to validate and process edge creation requests, an incorrect initialization could lead to validators being able to create edges at levels they should not be allowed to, or prevent them from creating edges at levels they should be able to. This could disrupt the intended functionality of the challenge game and potentially lead to invalid or malicious edges being created._

## Proof of Concept
The `ChallengeManager` contract expects `_stakeAmounts` to be an array of `uint256` values, where each value represents the minimum stake required for creating an edge at a specific level. However, the `createChallengeManager` function is passing a single `uint256` value (`config.miniStakeValues`) instead of an array. This means that the `ChallengeManager` contract will be initialized with an incorrect set of stake amounts, which could lead to unexpected behavior when validators attempt to create edges.

Here's how the bug could manifest in the code: [RollupCreator.sol:createChallengeManager](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCreator.sol#L99-L107)
```solidity
// ChallengeManager.sol
function createEdge(uint8 level, uint256 stake, ...) public {
    require(stake >= _stakeAmounts[level], "Insufficient stake");
    // ... (edge creation logic)
}

// RollupCreator.sol
challengeManager.initialize({
    // ...
    _stakeAmounts: config.miniStakeValues, // Incorrect initialization (single value instead of array)
});

// Validator attempts to create an edge at level 2
challengeManager.createEdge(2, 100 ether, ...);
// If _stakeAmounts was initialized as [100 ether], this would succeed
// But if _stakeAmounts was initialized as [100 ether, 200 ether, 300 ether, ...],
// this would fail because the required stake for level 2 is higher than 100 ether
```

## Recommended Mitigation Steps
We should ensure that `config.miniStakeValues` is indeed an array of `uint256` values, and not a single value. If it is a single value, we should either:

Convert it to an array before passing it to the initialize function, or
Update the `ChallengeManager` contract to accept a single `uint256` value for `_stakeAmounts` instead of an array.

An example of how we could convert `config.miniStakeValues` to an array before passing it to the initialize function:
```solidity
challengeManager.initialize({
    _assertionChain: IAssertionChain(rollupAddr),
    _challengePeriodBlocks: config.confirmPeriodBlocks,
    _oneStepProofEntry: osp,
    layerZeroBlockEdgeHeight: config.layerZeroBlockEdgeHeight,
    layerZeroBigStepEdgeHeight: config.layerZeroBigStepEdgeHeight,
    layerZeroSmallStepEdgeHeight: config.layerZeroSmallStepEdgeHeight,
    _stakeToken: IERC20(config.stakeToken),
    _stakeAmounts: [config.miniStakeValues], // Convert to an array
    _excessStakeReceiver: config.owner,
    _numBigStepLevel: config.numBigStepLevel
});
```
We can ensure that the `ChallengeManager` contract is initialized correctly and avoid potential errors or unexpected behavior.
