# Vulnerability details

## Impact

change of validatorWhitelistDisabled can make staker not withdraw their bond.

## Proof of Concept

the regular process to unbond and get the staked fund back is first calling

[the function reduceDeposit](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L241)

the function calls [reduceStakeTo to increase the withdrawal amount](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L307)

then the the withdrawal address needs to call [withdrawStakerFunds()](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L358)

the problem is that the reduceDeposit has the modifier [onlyValidator](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L20)

```solidity
 modifier onlyValidator() {
        require(isValidator[msg.sender] || validatorWhitelistDisabled, "NOT_VALIDATOR");
        _;
    }
```

if the validatorWhitelistDisabled is true, anyone can stake and create assertion,

as we can see, if validatorWhitelistDisabled is false (change from true to false)

only validator can call reduceDeposit,

but the problem is that the validator may not be staker, especially consider that there can be so many assertion pool created

```solidity
  function reduceDeposit(uint256 target) external onlyValidator whenNotPaused {
        requireInactiveStaker(msg.sender);
        // amount will be checked when creating an assertion
        reduceStakeTo(msg.sender, target);
    }
```

and we are calling [requireInactiveStaker](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupCore.sol#L565)

```solidity
 /**
     * @notice Verify that the given staker is not active
     * @param stakerAddress Address to check
     */
    function requireInactiveStaker(address stakerAddress) internal view {
        require(isStaked(stakerAddress), "NOT_STAKED");
        // A staker is inactive if
        // a) their last staked assertion is the latest confirmed assertion
        // b) their last staked assertion have a child
        bytes32 lastestAssertion = latestStakedAssertion(stakerAddress);
        bool isLatestConfirmed = lastestAssertion == latestConfirmed();
        bool haveChild = getAssertionStorage(lastestAssertion).firstChildBlock > 0;
        require(isLatestConfirmed || haveChild, "STAKE_ACTIVE");
    }
```

the validator may not even be stakers, and the validator cannot reduce the stake for other stakers (such as a lot of asesrtion pool),

then change of validatorWhitelistDisabled can make staker not withdraw their bond because neither the validator nor the staker can reduce the deposit first.

## Tools Used

Manual Review

## Recommended Mitigation Steps

the only way to release the fund of stakers (a lot of assertion pool that may have confirmed challange yet not call reduceDeposit to release the fund.) is admin pause the contract,

then forceRefund the staker one by one, which is not scalable and gas inefficient and not a expected way to handle the situation,

I think a recommendation is disable the staker create more assertion but let the staker reduce and withdraw their bond if they do not have active assertion.
