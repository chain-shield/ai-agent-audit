# Vulnerability details

## Impact
Contrary to the BOLD rollup design, validators cannot withdraw their stake when the BOLD `rollup` contract is paused. This breaks core protocol functionality.

## Proof of Concept
Validators can withdraw their staked funds from the BOLD `rollup` by calling the `RollupUserlogic::withdrawStakerFunds(...)` , however, when the BOLD `rollup` is paused, the withdrawal is impossible. This is not correct because as shown below,

- [`L229` to `L230`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L229-L230) shows that the old `RollupUserLogic` was patched and `whenNotPaused` modifier removed from withdrawal function to allow validators withdraw even when `rollup` is paused
- [`L361` to `L362`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/BOLDUpgradeAction.sol#L361-L362) clearly shows that the BOLD `rollup` implementation requires that withdrawals should  be enabled even when the `rollup` is paused

```solidity
File: BOLDUpgradeAction.sol
229:     // the old rollup, but with whenNotPaused protection removed from stake withdrawal functions
230:     address public immutable IMPL_PATCHED_OLD_ROLLUP_USER;

...

...       // @audit-ok
364:         // upgrade the rollup to one that allows validators to withdraw even whilst paused
365:         DoubleLogicUUPSUpgradeable(address(OLD_ROLLUP)).upgradeSecondaryTo(IMPL_PATCHED_OLD_ROLLUP_USER);

File: RollupUserLogic.sol
358: @>  function withdrawStakerFunds() external override whenNotPaused returns (uint256) {
359:         uint256 amount = withdrawFunds(msg.sender);
360:         require(amount > 0, "NO_FUNDS_TO_WITHDRAW");
361:         // This is safe because it occurs after all checks and effects
362:         IERC20(stakeToken).safeTransfer(msg.sender, amount);
363:         return amount;
364:     }

```

As you can see from the code snipet above, the new implementation of the rollup is patched to ensure validators can still withdraw even when the protocol is paused. But this is not implemented as seen [on `L358`](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/6f861c85b281a29f04daacfe17a2099d7dad5f8f/src/rollup/RollupUserLogic.sol#L358)

## Recommended Mitigation Steps
Remove the `wehnNotPaused` modifier from the withdraw function as shown below

```solidity
File: RollupUserLogic.sol

358:  -  function withdrawStakerFunds() external override whenNotPaused returns (uint256) {

358:  +  function withdrawStakerFunds() external override returns (uint256) {

359:         uint256 amount = withdrawFunds(msg.sender);
360:         require(amount > 0, "NO_FUNDS_TO_WITHDRAW");
361:         // This is safe because it occurs after all checks and effects
362:         IERC20(stakeToken).safeTransfer(msg.sender, amount);
363:         return amount;
364:     }
```
