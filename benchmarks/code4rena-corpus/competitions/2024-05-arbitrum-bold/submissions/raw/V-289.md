# Vulnerability details

## Impact
Allowing transactions that result in no change to the user's balance can lead to increased gas costs for users and the network, as unnecessary transactions consume resources. Additionally, it could encourage users to repeatedly send transactions that appear to interact with the contract but do not actually change any state, potentially triggering unintended behaviors or vulnerabilities within the contract.

## Proof of Concept
The `AbsBoldStakingPool::withdrawFromPool()` function in the contract lacks a check for zero withdrawal amounts when users intend to withdraw their entire balance. This oversight could lead to unnecessary transactions being processed, potentially increasing gas costs and network congestion without providing any benefit to the user or the contract's functionality.

The issue was identified in the `AbsBoldStakingPool` contract located at [this GitHub link](https://github.com/code-423n4/2024-05-arbitrum-foundation/blob/main/src/assertionStakingPool/AbsBoldStakingPool.sol#L57-L59). Specifically, the `withdrawFromPool()` function without parameters calls `withdrawFromPool(depositBalance[msg.sender])`, which could be zero if the user has not deposited anything. The original `withdrawFromPool(uint256 amount)` function includes a check for zero amounts, but this check is bypassed when the function is called with the user's balance as the argument.

```
    function withdrawFromPool() external {
        withdrawFromPool(depositBalance[msg.sender]);
    }
```

## Recommended Mitigation Steps with Fix Code

To address this issue, it's recommended to reintroduce a check for zero withdrawal amounts in the `withdrawFromPool()` function that is called without parameters. This can be achieved by modifying the function to either ignore zero amounts gracefully or revert the transaction with a clear error message, depending on the desired behavior. Below is an example of how to implement a graceful ignore for zero amounts:

```solidity
function withdrawFromPool() external {
    uint256 amount = depositBalance[msg.sender];
    if (amount == 0) {
        revert("Zero withdrawal amount");
    }
    withdrawFromPool(amount);
}
```

This modification ensures that the contract behaves predictably and discourages unnecessary transactions, thereby maintaining the integrity of the contract's logic and improving the overall user experience by providing clear feedback on the outcome of their actions.
