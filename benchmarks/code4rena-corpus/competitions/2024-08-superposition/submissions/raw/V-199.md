# Vulnerability details


### **Summary:**
The `emit_campaign_created` and `emit_campaign_updated` functions in the contract code use `unwrap()` to convert a `FixedBytes<8>` identifier into a byte array. This use of `unwrap()` is unsafe and can cause runtime panics if the conversion fails. This practice is risky and can lead to unexpected behavior or crashes, impacting the stability and reliability of the contract.

---

### **Vulnerability Detail:**
The functions `emit_campaign_created` and `emit_campaign_updated` rely on the `unwrap()` method to convert a `FixedBytes<8>` value into a byte array suitable for logging:

```rust
pub fn emit_campaign_created(
    identifier: FixedBytes<8>,
    pool: Address,
    token: Address,
    owner: Address,
    tick_lower: i32,
    tick_upper: i32,
    starting: u64,
    ending: u64,
) {
    evm::log(CampaignCreated {
        identifier: identifier.as_slice().try_into().unwrap(),
        pool,
        token,
        details: pack_details(tick_lower, tick_upper, owner),
        times: pack_times(starting, ending),
    });
}

pub fn emit_campaign_updated(
    identifier: FixedBytes<8>,
    pool: Address,
    per_second: U256,
    tick_lower: i32,
    tick_upper: i32,
    starting: u64,
    ending: u64,
) {
    evm::log(CampaignUpdated {
        identifier: identifier.as_slice().try_into().unwrap(),
        perSecond: per_second,
        pool,
        extras: pack_extras(tick_lower, tick_upper, starting, ending),
    });
}
```

#### **Issue:**
- **Unwrapping Risk**: The `unwrap()` function is used to extract the value from a `Result` or `Option`. If the conversion fails, `unwrap()` will panic and terminate the program. This is unsafe and can lead to unexpected crashes, as it doesn't provide a way to handle or recover from conversion errors.
- **Lack of Error Handling**: There is no graceful handling of potential errors from the `try_into()` conversion. This can cause the contract to fail silently or crash, which is undesirable in a production environment.

#### **Impact:**
- **Runtime Panics**: The use of `unwrap()` can lead to runtime panics if the conversion fails. This can cause the contract to terminate unexpectedly, leading to system instability or downtime.
- **User Experience**: Unexpected failures can degrade the user experience, especially in critical contract functions where reliability is paramount.
- **Security Vulnerabilities**: Panics can be exploited to disrupt the contract’s operations, potentially leading to denial of service or other security issues.
