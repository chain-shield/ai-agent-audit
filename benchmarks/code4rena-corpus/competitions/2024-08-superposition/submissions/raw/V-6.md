# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The approve function in the OwnershipNFTs contract incorrectly uses the _requireAuthorised function to check if the caller is authorized to manage the token (_tokenId). However, the approve function should allow only the owner of the token or an operator approved for all of the owner’s tokens to set an approved address for the specific token, not require broader authorization.

This issue restricts the legitimate owner of an NFT from setting an approved address unless they are authorized through the _requireAuthorised function. This unnecessarily complicates the approval process, potentially leading to failures in setting approval, which could hinder operations like transferring NFTs. It might confuse users who are otherwise accustomed to ERC721 behavior, where the owner has explicit rights to approve transfers.

## Proof of Concept

The following code demonstrates the issue:
```sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.16;

interface ISeawaterAMM {
    function positionOwnerD7878480(uint256 _tokenId) external view returns (address);
}

contract OwnershipNFTs {
    ISeawaterAMM immutable public SEAWATER;
    mapping(uint256 => address) public getApproved;
    mapping(address => mapping(address => bool)) public isApprovedForAll;

    constructor(ISeawaterAMM _seawater) {
        SEAWATER = _seawater;
    }

    function ownerOf(uint256 _tokenId) public view returns (address) {
        (bool ok, bytes memory rc) = address(SEAWATER).staticcall(abi.encodeWithSelector(
            SEAWATER.positionOwnerD7878480.selector,
            _tokenId
        ));
        require(ok, "position owner revert");
        (address owner) = abi.decode(rc, (address));
        return owner;
    }

    function _requireAuthorised(address _from, uint256 _tokenId) internal view {
        bool isAllowed =
            msg.sender == _from ||
            isApprovedForAll[_from][msg.sender] ||
            msg.sender == getApproved[_tokenId];
        require(isAllowed, "not allowed");
        require(ownerOf(_tokenId) == _from, "_from is not the owner!");
    }

    function approve(address _approved, uint256 _tokenId) external payable {
        _requireAuthorised(msg.sender, _tokenId);
        getApproved[_tokenId] = _approved;
    }
}

// Deployment and interaction in Remix IDE:
// 1. Deploy OwnershipNFTs with a mock SeawaterAMM contract.
// 2. Attempt to call approve as the token owner.
// 3. Observe that the approval fails unless _requireAuthorised conditions are met.
```

**Expected Behavior:**
The token owner should be able to set an approved address for the token without needing to pass additional authorization checks.

**Actual Behavior:**
The approve function unnecessarily checks for additional authorization, preventing the token owner from setting approval as expected.

## Recommended Mitigation Steps

To resolve this issue, modify the approve function to check that the caller is either the owner of the token or an operator approved to manage all of the owner’s tokens. This ensures that only the legitimate owner or their operator can set approval.
```sol
// SPDX-License-Identifier: MIT
pragma solidity 0.8.16;

import "./IERC721Metadata.sol";
import "./IERC721TokenReceiver.sol";

interface ISeawaterAMM {
    function positionOwnerD7878480(uint256 _tokenId) external view returns (address);
}

contract OwnershipNFTs {
    ISeawaterAMM immutable public SEAWATER;
    mapping(uint256 => address) public getApproved;
    mapping(address => mapping(address => bool)) public isApprovedForAll;

    constructor(ISeawaterAMM _seawater) {
        SEAWATER = _seawater;
    }

    function ownerOf(uint256 _tokenId) public view returns (address) {
        (bool ok, bytes memory rc) = address(SEAWATER).staticcall(abi.encodeWithSelector(
            SEAWATER.positionOwnerD7878480.selector,
            _tokenId
        ));
        require(ok, "position owner revert");
        (address owner) = abi.decode(rc, (address));
        return owner;
    }

    function approve(address _approved, uint256 _tokenId) external payable {
        require(
            ownerOf(_tokenId) == msg.sender || isApprovedForAll[ownerOf(_tokenId)][msg.sender], 
            "Not authorized"
        );
        getApproved[_tokenId] = _approved;
        emit Approval(ownerOf(_tokenId), _approved, _tokenId);
    }

    event Approval(address indexed owner, address indexed approved, uint256 indexed tokenId);
}

// Deployment and interaction in Remix IDE:
// 1. Deploy OwnershipNFTs with a mock SeawaterAMM contract.
// 2. Use the approve function as the token owner or an operator.
// 3. Observe that the approval is successful.
```

The proposed mitigation ensures that the approve function behaves according to the expected ERC721 standards, allowing the rightful token owner or an authorized operator to manage approvals. This change improves the usability and reliability of the NFT system.
