# Vulnerability details

## Impact
The contract uses delegatecall in multiple places to proxy execution to various executors, such as in the directDelegate() function and other swap/position functions. This introduces a major risk, as the delegatecall will execute the code in the context of the calling contract, meaning that the called contracts could modify the SeawaterAMM contract’s state.


## Proof of Concept
If one of the executor contracts (e.g., _getExecutorSwap()) is compromised or contains a bug, a malicious attacker could exploit it to overwrite storage in the SeawaterAMM contract, potentially resulting in loss of funds or control over critical functions.

```
function swap904369BE(
    address pool,
    bool zeroForOne,
    int256 amount,
    uint256 priceLimit
) external returns (int256, int256) {
    directDelegate(_getExecutorSwap());
}
```
Here, the swap904369BE function uses delegatecall to call the swap executor. If the swap executor contains malicious code, it can modify the state of SeawaterAMM, possibly transferring funds or modifying other storage variables.


## Tools Used
Manual

## Recommended Mitigation Steps
 Delegatecall should be avoided unless necessary. If proxying is essential, ensure that all executors are thoroughly audited and that only trusted addresses can be set for the executors. Additionally, consider using call instead of delegatecall to avoid executing external code in the context of the SeawaterAMM contract.

Furthermore, access control or reentrancy protection should be implemented to guard against attacks that modify the executors via reentrancy.

```
modifier onlyTrustedExecutor(address executor) {
    require(executor == _getExecutorSwap() || executor == _getExecutorAdmin(), "Untrusted executor");
    _;
}
```
