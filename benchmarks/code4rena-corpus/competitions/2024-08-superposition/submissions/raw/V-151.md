# Vulnerability details

## Impact

In the current implementation of the `SeawaterAMM` smart contract, users are able to call swap functions and the calls will be delegated to the corresponding "feature" in the implementation "feature". The problem is that the contract sets slippage protection to be `type(uint256).max` effectively meaning there is no slippage when implementing the function. Therefore, the tx can simply revert multiple times as user's tx will be subject to MEV and `minOut` amount will not be reached.

## Proof of Concept

Take a look at these functions:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L281-294
```
 function swapInPermit2CEAAB576(address token, uint256 amountIn, uint256 minOut, uint256 nonce, uint256 deadline, uint256 maxAmount, bytes memory sig) external returns (int256, int256) {
        (bool success, bytes memory data) = _getExecutorSwapPermit2().delegatecall(abi.encodeCall(
            ISeawaterExecutorSwapPermit2.swapPermit2EE84AD91,
            (
                token,
                true,
                int256(amountIn),
                type(uint256).max,
                nonce,
                deadline,
                maxAmount,
                sig
            )
        ));
```

function swapIn32502CA71(address token, uint256 amountIn, uint256 minOut) external returns (int256, int256) {

As you can see here, the slippage is set to `type(uint256).max` effectively meaning there is no any slippage protection and this is an incorrect way to implement it for a single swap:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L144-151
```
  pub fn swap_internal(
        pools: &mut Pools,
        pool: Address,
        zero_for_one: bool,
        amount: I256,
        price_limit_x96: U256,
        permit2: Option<Permit2Args>,
    ) 

```

`price_limit_x96` here is used for slippage and it has to be set by the user to avoid his tx being subjected to MEV and reverted.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Introduce user-provided `price_limit_x96` slippage protection.
