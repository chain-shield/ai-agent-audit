# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Title: OwnershipNFTs contract has Unchecked Return Value of onERC721Received function.
Contract: OwnershipNFTs.sol.
Functions: _onTransferReceived() & X2 safeTransferFrom(). 
Severity: Medium.
Issue Type: Unchecked return value in safeTransferFrom.

The internal function _onTransferReceived has an unchecked IERC function called IERC721TokenReceiver(_to).onERC721Received(_sender, _from, _tokenId, "") which in turn calls 2 duplicate external safeTransferFrom functions.

The safeTransferFrom function calls the internal _onTransferReceived function to handle transferring NFTs to a contract. However, the return value of the onERC721Received function call is not properly checked. Instead of verifying that the returned value matches the expected selector (IERC721TokenReceiver.onERC721Received.selector), the current code logic treats any value not matching the selector as a valid response, resulting in a logic error.

This unchecked return value can allow contracts that are not compliant with ERC-721 to receive NFTs without correctly implementing the onERC721Received function. This could lead to the NFTs being locked in a contract that is unable to return them or interact with them correctly. Malicious contracts could exploit this by falsely claiming compatibility with the ERC-721 interface.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

A malicious contract could declare a different selector in the onERC721Received function, bypassing the check and receiving NFTs even though it doesn’t fully comply with ERC-721.
```sol
contract MaliciousContract {
    // Malicious contract that returns a wrong selector
    function onERC721Received(
        address, 
        address, 
        uint256, 
        bytes memory
    ) external pure returns (bytes4) {
        // Return a wrong selector intentionally
        return bytes4(keccak256("wrongSelector()"));
    }
}

function _onTransferReceived(
        address _sender,
        address _from,
        address _to,
        uint256 _tokenId
    ) internal {
        // only call the callback if the receiver is a contract
        if (_to.code.length == 0) return;


        bytes4 data = IERC721TokenReceiver(_to).onERC721Received(
            _sender,
            _from,
            _tokenId,


            // this is empty byte data that can be optionally passed to
            // the contract we're confirming is able to receive NFTs
            ""
        );

      // @debo != instead of ==
        require(
            data != IERC721TokenReceiver.onERC721Received.selector,
            "bad nft transfer received data"
        );
    }

function safeTransferFrom(
        address _from,
        address _to,
        uint256 _tokenId
    ) external payable {
        _transfer(_from, _to, _tokenId);
        _onTransferReceived(msg.sender, _from, _to, _tokenId);
    }

    /// @inheritdoc IERC721Metadata
function safeTransferFrom(
        address _from,
        address _to,
        uint256 _tokenId,
        bytes calldata /* _data */
    ) external payable {
        _transfer(_from, _to, _tokenId);
        _onTransferReceived(msg.sender, _from, _to, _tokenId);
    }
```
In the current logic of OwnershipNFTs, the NFT transfer will succeed even though this contract is not compliant.

## Recommended Mitigation Steps

To ensure that the receiving contract is ERC-721 compliant, the return value of onERC721Received should be checked to match the expected selector IERC721TokenReceiver.onERC721Received.selector.
So, use ```==``` not ```!=```
```sol
function _onTransferReceived(
    address _sender,
    address _from,
    address _to,
    uint256 _tokenId
) internal {
    // only call the callback if the receiver is a contract
    if (_to.code.length == 0) return;

    bytes4 data = IERC721TokenReceiver(_to).onERC721Received(
        _sender,
        _from,
        _tokenId,
        ""
    );

    // Ensure the return value matches the expected selector
    require(
        data == IERC721TokenReceiver.onERC721Received.selector,
        "Invalid onERC721Received return value"
    );
}
```
This change ensures that the receiving contract must return the correct selector to confirm its compatibility with the ERC-721 standard, mitigating the risk of sending NFTs to non-compliant or malicious contracts.
