# Vulnerability details

## Impact
The current implementation allows for the creation of positions with invalid tick ranges, potentially leading to logical errors in pool operations and unexpected behavior.

## Proof of Concept
In the create_position function, the validation of the low and up ticks is incomplete. While it checks that both ticks are within the valid range, it fails to ensure that the lower tick is strictly less than the upper tick.

Vulnerable Code
```
pub fn create_position(&mut self, id: U256, low: i32, up: i32) -> Result<(), Revert> {
    // ... (earlier code omitted for brevity)
    
    let min_tick = tick_math::get_min_tick(spacing);
    let max_tick = tick_math::get_max_tick(spacing);
    
    assert_or!(low >= min_tick && low <= max_tick, Error::InvalidTick);<@=
    assert_or!(up >= min_tick && up <= max_tick, Error::InvalidTick);<@=
    
    self.positions.new(id, low, up);
    Ok(())
}
```

The current implementation only checks if both low and up are within the valid tick range but doesn't enforce the correct ordering between them. This could lead to the creation of invalid positions, potentially causing issues in other parts of the system that assume a valid tick range (lower < upper).
By adding the assert_or!(low < up, Error::InvalidTickOrder) check, we ensure that positions can only be created with a valid tick range where the lower tick is strictly less than the upper tick.

With the current implementation, it's possible to create a position where low is equal to or greater than up. For example:
```
create_position(id, 1000, 1000)  // This would be allowed
create_position(id, 2000, 1000)  // This would also be allowed
```
Both of these calls would succeed, despite representing invalid position ranges.

## Recommended Mitigation Steps
change to this
```
pub fn create_position(&mut self, id: U256, low: i32, up: i32) -> Result<(), Revert> {
    // ... (earlier code remains the same)
    
    assert_or!(low >= min_tick && low <= max_tick, Error::InvalidTick);
    assert_or!(up >= min_tick && up <= max_tick, Error::InvalidTick);
    assert_or!(low < up, Error::InvalidTickOrder);  // Add this line
    
    self.positions.new(id, low, up);
    Ok(())
}
```
