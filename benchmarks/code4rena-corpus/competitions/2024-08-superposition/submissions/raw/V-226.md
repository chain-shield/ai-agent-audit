# Vulnerability details

## Impact

The position of a user can be manipulated by anyone.

## Proof of Concept

A user creates a position of a pool by calling `mint_position`. This calls `create_position()` in the pool contract

```
   pub fn mint_position_B_C5_B086_D(
        &mut self,
        pool: Address,
        lower: i32,
        upper: i32,
    ) -> Result<U256, Revert> {
        let id = self.next_position_id.get();
        self.pools.setter(pool).create_position(id, lower, upper)?;

        self.next_position_id.set(id + U256::one());

        let owner = msg::sender();

        self.grant_position(owner, id);

        #[cfg(feature = "log-events")]
        evm::log(events::MintPosition {
            id,
            owner,
            pool,
            lower,
            upper,
        });

        Ok(id)
    }
```

To adjust their position, the user will call `adjust_position_internal()` in the lib.rs contract and transfer tokens in/out which calls `adjust_position()` in the pools contract. Note that in `adjust_position_internal()`, there is a check to make sure the caller is the position owner.

```

        giving: bool,
        permit2: Option<(Permit2Args, Permit2Args)>,
    ) -> Result<(U256, U256), Revert> {
>       assert_eq_or!(

>       let (amount_0, amount_1) = self.pools.setter(pool).adjust_position(
```

However, there is no access control in the `adjust_position()` function in pools.rs itself. Anybody can call this and not risk any tokens while manipulating the position. Same goes for manipulating the position fees and the admin fees.

## Recommended Mitigation Steps
