# Vulnerability details

## Impact

In the current implementation of `OwnershipNFTs`, `setApprovalForAll()` deviates from the standard IERC721Metadata implementation as it does not check for the operator to be != address(0).

## Proof of Concept

The current implementation:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/OwnershipNFTs.sol#L166-168
```
function setApprovalForAll(address _operator, bool _approved) external {
        isApprovedForAll[msg.sender][_operator] = _approved;
    }
```

Now in the standard implementation there is a check for operator to be not equal to address(0):

https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/ERC721.sol#L427-441
```
  /**
     * @dev Approve `operator` to operate on all of `owner` tokens
     *
     * Requirements:
     * - operator can't be the address zero.
     *
     * Emits an {ApprovalForAll} event.
     */
    function _setApprovalForAll(address owner, address operator, bool approved) internal virtual {
        if (operator == address(0)) {
            revert ERC721InvalidOperator(operator);
        }
        _operatorApprovals[owner][operator] = approved;
        emit ApprovalForAll(owner, operator, approved);
    }
```

Now note that `operator can't be the address zero.` is set as a requirement.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Implement address(0) check for an operator to now allow setting zero address operator.
