# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Issue Type: Signature Replay

Signature-based functions, especially with Permit2Args, could be susceptible to signature replay attacks if proper nonce or expiration checks are not in place. Attackers may reuse signatures, leading to unauthorized actions or token transfers.

## Recommended Mitigation Steps

Ensure that signatures are validated with nonces and expiry checks. Nonces must be incremented after each use, and expired signatures should be rejected.
```rust
// Example mitigation with nonce and expiration checks
fn validate_signature(permit: &Permit2Args) -> Result<(), Revert> {
    // Check that the nonce has not been used
    assert!(permit.nonce > get_nonce(permit.owner), "Replay attack detected");

    // Ensure the deadline has not passed
    assert!(permit.deadline >= block.timestamp, "Permit has expired");

    Ok(())
}
```
