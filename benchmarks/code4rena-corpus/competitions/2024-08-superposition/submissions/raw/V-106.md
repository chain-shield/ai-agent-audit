# Vulnerability details

## Impact

Users that burns their position or have their position transferred without retrieving their liquidity and fees will result in funds stuck in contract.

## Proof of Concept

In lib.rs, `burn_position_AE401070()` removes the position from the owner without checking that the position has 0 liquidity and fees:

```
  /// Burns a position. Only usable by the position owner.
    ///
>   /// Calling this function leaves any liquidity or fees left in the position inaccessible.
    ///
    /// # Errors
    /// Requires the position be owned by the caller. Requires the pool to be enabled.
    #[allow(non_snake_case)]
    pub fn burn_position_AE401070(&mut self, id: U256) -> Result<(), Revert> {
        let owner = msg::sender();
        assert_eq_or!(
            self.position_owners.get(id),
            owner,
            Error::PositionOwnerOnly
        );

>       self.remove_position(owner, id);

        #[cfg(feature = "log-events")]
        evm::log(events::BurnPosition { owner, id });

        Ok(())
    }
```

Also, the NFT manager can transfer the position's ownership from one address to another, which will remove the position of the `from` address without collecting the liquidity and fees from that position.

```
 #[allow(non_snake_case)]
    pub fn transfer_position_E_E_C7_A3_C_D(
        &mut self,
        id: U256,
        from: Address,
        to: Address,
    ) -> Result<(), Revert> {
        assert_eq_or!(msg::sender(), self.nft_manager.get(), Error::NftManagerOnly);

>       self.remove_position(from, id);
        self.grant_position(to, id);

        #[cfg(feature = "log-events")]
        evm::log(events::TransferPosition { from, to, id });

        Ok(())
    }
```

Once the position is removed, it cannot be set again, leaving liquidity and fees that are uncollected stuck in the contract.

```
  /// Removes the user as the owner of a position. The position must have an owner.
    fn remove_position(&mut self, owner: Address, id: U256) {
        // remove owner
        self.position_owners.setter(id).erase();

        // decrement count
        let owned_positions_count = self.owned_positions.get(owner) - U256::one();
        self.owned_positions
            .setter(owner)
            .set(owned_positions_count);
    }
```

The fund manager may not know that the user has not yet remove their liquidity before transferring positions.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Inside the `remove_position()` function, have a check to make sure that the position has no pending liquidity or fees before removing the position.
