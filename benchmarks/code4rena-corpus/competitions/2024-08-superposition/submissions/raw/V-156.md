# Vulnerability details

## Impact
The _onTransferReceived() function calls the onERC721Received() function on the recipient address without checking whether the external call was successful. If the recipient contract reverts or fails for any reason, the failure is ignored, which could result in NFTs being "stuck" or lost.

## Proof of Concept
The following code does not check whether the external call was successful.
```
function _onTransferReceived(
    address _sender,
    address _from,
    address _to,
    uint256 _tokenId
) internal {
    if (_to.code.length == 0) return;

    bytes4 data = IERC721TokenReceiver(_to).onERC721Received(
        _sender,
        _from,
        _tokenId,
        ""
    );

    require(data != IERC721TokenReceiver.onERC721Received.selector, "bad nft transfer received data");
}
```
If the onERC721Received() function on the recipient contract fails, this code will still consider the transfer valid, potentially resulting in lost NFTs.

## Tools Used
Manual

## Recommended Mitigation Steps
Add a check to ensure that the external call to onERC721Received() was successful.
```
function _onTransferReceived(
    address _sender,
    address _from,
    address _to,
    uint256 _tokenId
) internal {
    if (_to.code.length == 0) return;

    (bool success, bytes memory data) = _to.call(abi.encodeWithSelector(
        IERC721TokenReceiver.onERC721Received.selector,
        _sender,
        _from,
        _tokenId,
        ""
    ));

    require(success && abi.decode(data, (bytes4)) == IERC721TokenReceiver.onERC721Received.selector, "ERC721: transfer rejected");
}
This ensures that the transfer is only considered successful if the recipient contract properly implements the ERC721 receiver interface.
```
