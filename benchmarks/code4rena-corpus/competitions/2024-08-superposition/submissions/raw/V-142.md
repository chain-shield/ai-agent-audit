# Vulnerability details

## Impact

In the current version of `SeawaterAMM` smart contract, the proxies for calling different "faucets" are set at the constructor level. The problem is that currently there is no slot for migrations faucet even though it has to be present. This will not allow calling any functions related to the `migrations` feature in the Rust implementation.

## Proof of Concept

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L81-90
```
  _setProxyAdmin(_proxyAdmin);
        _setProxies(
            _executorSwap,
            _executorSwapPermit2,
            _executorQuote,
            _executorPosition,
            _executorUpdatePosition,
            _executorAdmin,
            _executorFallback
        );

```

As you can see, there is no currently any proxy storage slot reserved for "migrations" feature:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L92-94
```
compile_error!(
        "Either `swaps` or `swap_permit2` or `quotes` or `positions` or `update_positions`, `admin`, or `migrations` must be enabled when building for wasm."
    );

```

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L1206-1208
```
///! Migrations code that should only be used in a testing environment, or in a rescue
///! situation. These functions will break the internal state of the pool most likely.
#[cfg_attr(feature = "migrations", external)]

```

So, in the case of the rescue situation, these functions will not be called.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Integrate the "migrations" feature into the Solidity proxy contract.
