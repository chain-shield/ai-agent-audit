# Vulnerability details

## Overview
The protocol provides a facility to the Seawater admin to update the emergency council address:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L207

```solidity
    function updateEmergencyCouncil7D0C1C58(address /* council */) external {
        directDelegate(_getExecutorAdmin());
    }
```

This delegate calls a function in lib.rs:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L1111

```rust
    #[allow(non_snake_case)]
    pub fn update_emergency_council_7_D_0_C_1_C_58(
        &mut self,
        manager: Address,
    ) -> Result<(), Revert> {
        assert_eq_or!(
            msg::sender(),
            self.seawater_admin.get(),
            Error::SeawaterAdminOnly
        );

        self.nft_manager.set(manager);

        Ok(())
    }
```

However, as can be seen, the function wrongly updates the nft_manager and not the emergency council address. PoC has not been provided as the issue is obvious.

## Severity
If the emergency council address gets malicious, there would be no way for the seawater admin to change it. Moreover, if the admin calls the above function unknowingly, he would end up making the nft_manager malicious as well. 

Since, the seawater admin faces a loss of functionality that prevents him from updating the emergency council address, this issue is of Medium severity.

Manual review

Replace the following in the ```update_emergency_council_7_D_0_C_1_C_58()``` function:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L1111

