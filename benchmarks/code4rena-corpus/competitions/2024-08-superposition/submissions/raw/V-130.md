# Vulnerability details


The [`get_fee_growth_inside` function](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/tick.rs#L125-L246) in the `StorageTicks` struct is responsible for calculating the fee growth inside a given tick range. This function is crucial for determining the fees accrued within a specific range of ticks, which is essential for liquidity providers in a decentralized exchange or automated market maker (AMM) protocol.

The function calculates the fee growth inside the range by subtracting the fee growth outside the range from the global fee growth. However, there is a logical error in how it handles the fee growth calculations when the current tick (`cur_tick`) is outside the given range (`lower_tick` to `upper_tick`). This can lead to incorrect fee growth calculations, potentially resulting in financial discrepancies for liquidity providers.

The issue arises in the following part of the code:

```rust
let (fee_growth_below_0, fee_growth_below_1) = if cur_tick >= lower_tick {
    (
        lower.fee_growth_outside_0.get(),
        lower.fee_growth_outside_1.get(),
    )
} else {
    (
        fee_growth_global_0
            .checked_sub(lower.fee_growth_outside_0.get())
            .ok_or(Error::FeeGrowthSubTick)?,
        fee_growth_global_1
            .checked_sub(lower.fee_growth_outside_1.get())
            .ok_or(Error::FeeGrowthSubTick)?,
    )
};

let (fee_growth_above_0, fee_growth_above_1) = if cur_tick < upper_tick {
    (
        upper.fee_growth_outside_0.get(),
        upper.fee_growth_outside_1.get(),
    )
} else {
    (
        fee_growth_global_0
            .checked_sub(upper.fee_growth_outside_0.get())
            .ok_or(Error::FeeGrowthSubTick)?,
        fee_growth_global_1
            .checked_sub(upper.fee_growth_outside_1.get())
            .ok_or(Error::FeeGrowthSubTick)?,
    )
};

Ok((
    fee_growth_global_0
        .checked_sub(fee_growth_below_0)
        .and_then(|x| x.checked_sub(fee_growth_above_0))
        .ok_or(Error::FeeGrowthSubTick)?,
    fee_growth_global_1
        .checked_sub(fee_growth_below_1)
        .and_then(|x| x.checked_sub(fee_growth_above_1))
        .ok_or(Error::FeeGrowthSubTick)?,
))
```

The final calculation subtracts both `fee_growth_below` and `fee_growth_above` from the global fee growth, which can lead to double subtraction when `cur_tick` is outside the range.

## Impact

Liquidity providers may receive incorrect fee amounts, leading to potential financial losses or gains. The overall economics of the liquidity pool may be disrupted, affecting the protocol's stability and reliability. Other parts of the system that rely on accurate fee growth calculations may exhibit unexpected behavior.

## Proof of Concept
Consider the following scenarios to illustrate the bug:

1. **Scenario 1: `cur_tick < lower_tick`**
   - **Initial Values**:
     - `fee_growth_global_0 = 1000`
     - `lower.fee_growth_outside_0 = 200`
     - `upper.fee_growth_outside_0 = 300`
     - `cur_tick = 50`
     - `lower_tick = 100`
     - `upper_tick = 200`
   - **Calculation**:
     - Since `cur_tick < lower_tick`, the function calculates `fee_growth_below_0` as:
       ```rust
       fee_growth_below_0 = fee_growth_global_0 - lower.fee_growth_outside_0 = 1000 - 200 = 800
       ```
     - The function calculates `fee_growth_above_0` as:
       ```rust
       fee_growth_above_0 = upper.fee_growth_outside_0 = 300
       ```
   - **Final Calculation**:
     - The function calculates `fee_growth_inside_0` as:
       ```rust
       fee_growth_inside_0 = fee_growth_global_0 - fee_growth_below_0 - fee_growth_above_0
       fee_growth_inside_0 = 1000 - 800 - 300 = -100
       ```
   - This results in an incorrect and negative fee growth inside the range.

2. **Scenario 2: `cur_tick >= upper_tick`**
   - **Initial Values**:
     - `fee_growth_global_0 = 1000`
     - `lower.fee_growth_outside_0 = 200`
     - `upper.fee_growth_outside_0 = 300`
     - `cur_tick = 250`
     - `lower_tick = 100`
     - `upper_tick = 200`
   - **Calculation**:
     - Since `cur_tick >= upper_tick`, the function calculates `fee_growth_below_0` as:
       ```rust
       fee_growth_below_0 = lower.fee_growth_outside_0 = 200
       ```
     - The function calculates `fee_growth_above_0` as:
       ```rust
       fee_growth_above_0 = fee_growth_global_0 - upper.fee_growth_outside_0 = 1000 - 300 = 700
       ```
   - **Final Calculation**:
     - The function calculates `fee_growth_inside_0` as:
       ```rust
       fee_growth_inside_0 = fee_growth_global_0 - fee_growth_below_0 - fee_growth_above_0
       fee_growth_inside_0 = 1000 - 200 - 700 = 100
       ```
   - This results in an incorrect fee growth inside the range.

In both scenarios, the final calculation is incorrect because it leads to double subtraction of the fee growth outside the range.
