# Vulnerability details

## Impact
Protocol fees can't be collected

## Vulnerability Details

The current implementation contains a function, `collect_protocol`, which allows the Seawater admin to withdraw protocol fees from a specified pool. However, there is an error in the parameter order when calling the `erc20::transfer_to_addr` function. The `transfer_to_addr` function uses the second and third parameters as arguments to invoke the `transfer` function implemented by the address given as the first parameter. In the current implementation, the recipient is incorrectly passed as the first parameter.

This mistake not only prevents the transfer from occurring but could also lead to unintended behavior if the recipient has implemented their own `transfer` function.

## Recommended Mitigation Steps

```diff
-        erc20::transfer_to_addr(recipient, pool, U256::from(token_0))?;
+        erc20::transfer_to_addr(pool, recipient, U256::from(token_0))?;
-        erc20::transfer_to_addr(recipient, FUSDC_ADDR, U256::from(token_1))?;
+        erc20::transfer_to_addr(FUSDC_ADDR, recipient, U256::from(token_1))?;
```
