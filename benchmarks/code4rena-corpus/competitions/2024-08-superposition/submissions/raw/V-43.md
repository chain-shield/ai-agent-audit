# Vulnerability details

## Impact
In case both prices passed to the function are 0, there will be division by 0

## Proof of Concept
This case is not highly likely to happen, however there are no checks if sqrt_ratio_b_x_96 is not 0 before it is used as a denominator in https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/maths/sqrt_price_math.rs#L162 .This check https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/maths/sqrt_price_math.rs#L150-L152 will handle the cases where ratioA is a bigger number and ratioB is 0 as their places will be changed and there is a check if ratioA is 0. However if both prices passed are 0 there is no such check for priceB before it is used as a divisor.

manual review

## Recommended Mitigation Steps
Add a non zero check for sqrt_ratio_b_x_96 before using it as a denominator.
