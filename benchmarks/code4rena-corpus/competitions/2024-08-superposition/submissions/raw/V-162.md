# Vulnerability details

The `OwnershipNFTs` contract implements the ERC721 standard for non-fungible tokens. One of the key features of ERC721 is the ability to safely transfer tokens to contracts by calling the `onERC721Received()` function on the receiving contract. However, the current implementation in the `_onTransferReceived()` function incorrectly validates the return value from this call.

In the `_onTransferReceived()` function, after calling `onERC721Received()` on the recipient contract, the function checks if the returned data is not equal to the `onERC721Received` selector:

``
require(
    data != IERC721TokenReceiver.onERC721Received.selector,
    "bad nft transfer received data"
);
``

This check is the opposite of what it should be. According to the ERC721 standard, the `onERC721Received()` function should return the function selector of `onERC721Received` to indicate that the contract is willing to accept the token transfer. The current implementation will revert when it receives a correct response and allow transfers when it receives an incorrect one.

## Impact
This issue has consequences such as:

1. Valid token transfers to contracts implementing ERC721 correctly will always fail.
2. Invalid transfers to contracts not properly implementing ERC721 might succeed, potentially leading to locked or lost tokens.


## Proof of Concept
1. Alice attempts to safely transfer her NFT to a contract that correctly implements `onERC721Received()`.
2. The receiving contract returns the correct selector (`IERC721TokenReceiver.onERC721Received.selector`).
3. The `_onTransferReceived()` function in `OwnershipNFTs` checks this return value.
4. The check incorrectly requires the return value to not equal the selector.
5. The transaction reverts with the error message "bad nft transfer received data".
6. Alice's valid transfer fails, even though the receiving contract is fully compliant with ERC721.

Manual review

## Recommended Mitigation Steps
The condition in the `require` statement should be changed to check for equality instead of inequality.
