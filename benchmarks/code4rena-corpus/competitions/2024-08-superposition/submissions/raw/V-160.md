# Vulnerability details

## Impact

In the current implementation of the `burn_position_AE401070()` function, the position id is erased and the owner count is decreased. The problem is that the position may hold unclaimed `tokensOwed0`, `tokensOwed1` and may as well have liquidity. All these amounts will be lost and the liquidity will still be enabled which is an unexpected behavior as the position is burnt.

## Proof of Concept

`burn_position_AE401070()` functionality:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L529-543
```
 pub fn burn_position_AE401070(&mut self, id: U256) -> Result<(), Revert> {
        let owner = msg::sender();
        assert_eq_or!(
            self.position_owners.get(id),
            owner,
            Error::PositionOwnerOnly
        );

        self.remove_position(owner, id);

        #[cfg(feature = "log-events")]
        evm::log(events::BurnPosition { owner, id });

        Ok(())
    }

```

So the position is just burnt without any checks being done:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L475-484
```
   fn remove_position(&mut self, owner: Address, id: U256) {
        // remove owner
        self.position_owners.setter(id).erase();

        // decrement count
        let owned_positions_count = self.owned_positions.get(owner) - U256::one();
        self.owned_positions
            .setter(owner)
            .set(owned_positions_count);
    }

```

The position can remain with liquidity and the tokens owed will be unclaimed possibly resulting in calculation errors as when liquidity is removed from a position, `update_position()` functionality is called and there are several parameters that are updated there. Moreover, token fees will be unclaimed.

## Recommended Mitigation Steps

This can be mitigated by implemented similar functionality as can be seen in the Uniswap `NonfungiblePositionManager` functionality:

https://github.com/Uniswap/v3-periphery/blob/main/contracts/NonfungiblePositionManager.sol#L377-382
```

function burn(uint256 tokenId) external payable override isAuthorizedForToken(tokenId) {
        Position storage position = _positions[tokenId];
        require(position.liquidity == 0 && position.tokensOwed0 == 0 && position.tokensOwed1 == 0, 'Not cleared');
        delete _positions[tokenId];
        _burn(tokenId);
    }


```
