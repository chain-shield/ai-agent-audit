# Vulnerability details

### Impact

The `_onTransferReceived` is improperly implemented, as a result NFT transfers to contracts inheriting the `onERC721Received` interface will fail, while transfers to contracts lacking the interface will succeed potentially leading to NFT loss.


### Proof of Concept

1. Context

To confirm that a receiver can receive NFTs through the `safeTransferFrom` method, the function is required to call a hook which checks for the `onERC721Received` hook in the function. This hook helps the sender ensure that the reciever can actually support ERC721 tokens as the EIP721 standard enforces this rule on every contract that aims to handle NFTs. The check for this hook can be found in the two `safeTransferFrom` functions, which both, after calling the `_transfer` method, calls the `_onTransferReceived` hook.

```solidity
    function safeTransferFrom(
        address _from,
        address _to,
        uint256 _tokenId,
        bytes calldata /* _data */
    ) external payable {
        _transfer(_from, _to, _tokenId);
        _onTransferReceived(msg.sender, _from, _to, _tokenId);
    }
```

2. Bug Location

The `_onTransferReceived` hook, however is not properly implemented. First the function the queries the `onERC721Received` in the receiving contract, and returns the selector code as data. It then compares the data with the expected `onERC721Received.selector`. However, as can be seen from the @audit tag below, due to an invalid validation, the function actually "requires" that the selector returned by the the receiver contract not match the expected selector, which is incorrect.

```solidity
    function _onTransferReceived(
        address _sender,
        address _from,
        address _to,
        uint256 _tokenId
    ) internal {
        // only call the callback if the receiver is a contract
        if (_to.code.length == 0) return;

        bytes4 data = IERC721TokenReceiver(_to).onERC721Received(
            _sender,
            _from,
            _tokenId,

            // this is empty byte data that can be optionally passed to
            // the contract we're confirming is able to receive NFTs
            ""
        );

        require(
            data != IERC721TokenReceiver.onERC721Received.selector, //@audit
            "bad nft transfer received data"
        );
    }
```
3. Final Effect
 
Due to this incorrect validation, any contract that accurately returns the expected selector, i.e a contract equipped to handle NFT, will be rejected and as such cannot receive the NFTs upon safe transfer. On the other hand, a contract that may not be equipped to handle NFTs, i.e lacking the expected selector will be incorrectly passed on, and allowed to receive the NFT. This will cause a loss of the NFT.

### Tools Used
Manual code review
 
### Recommended Mitigation Steps

Change the check to ==
```diff
//...
        require(
-            data != IERC721TokenReceiver.onERC721Received.selector,
+            data == IERC721TokenReceiver.onERC721Received.selector,
            "bad nft transfer received data"
        );
    }
```
