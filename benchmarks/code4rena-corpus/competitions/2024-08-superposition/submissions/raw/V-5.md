# Vulnerability details

## Impact
Hackers could transfer victims‘ tokens away.

## Proof of Concept
In function OwnershipNFTs.sol:_transfer(), _requireAuthorised(_from, _tokenId) should return True, in order to check if the caller is authorised. 
However, callers could easily make the function OwnershipNFTs.sol:_requireAuthorised() to return True by making getApproved[_tokenId] to be hacker addr.

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/OwnershipNFTs.sol#L98-L107

    function _requireAuthorised(address _from, uint256 _tokenId) internal view {
        // revert if the sender is not authorised or the owner
        bool isAllowed =
            msg.sender == _from ||
            isApprovedForAll[_from][msg.sender] ||
            msg.sender == getApproved[_tokenId];

        require(isAllowed, "not allowed");
        require(ownerOf(_tokenId) == _from, "_from is not the owner!");
    }

If getApproved[_tokenId] == msg.sender, _requireAuthorised will return True.  Hackers could easily make getApproved[_tokenId] to be the hacker addr, by OwnershipNFTs.sol:approve(), input the parameter "_approved" to be the hacker addr, since msg.sender == _from, _requireAuthorised() is True, then getApproved[_tokenId] will be set to hacker addr.

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/OwnershipNFTs.sol#L160-L163

    function approve(address _approved, uint256 _tokenId) external payable {
        _requireAuthorised(msg.sender, _tokenId);
        getApproved[_tokenId] = _approved;
    }


POC steps:
1, hackers get the tokenId, call approve(hacker addr, tokenId), here msg.sender == hacker-addr, getApproved[tokenId] will be set to hacker addr.
2, call transferFrom(_from,_to,tokenId), tokenId will be transferred.

## Tools Used
manually reviewed

## Recommended Mitigation Steps
function approve(address _approved, uint256 _tokenId) should check if msg.sender is the owner of the given _tokenId.
