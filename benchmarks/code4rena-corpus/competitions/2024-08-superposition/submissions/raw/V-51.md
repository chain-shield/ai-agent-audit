# Vulnerability details

## Impact
If an address shares multiple roles (`authorised_enablers` and `emergency_council`) they won't be able to enable a pool even if their role has permission to do so.

## Proof of Concept

`authorised_enablers` and `admins` are roles that have permission to enable a pool. `emergency_council` can only disable a pool.

An address may share multiple roles, but if the same address has both `authorised_enablers` and `emergency_council`, they won't be able to enable a pool:

```rust
    #[allow(non_snake_case)]
    pub fn enable_pool_579_D_A658(&mut self, pool: Address, enabled: bool) -> Result<(), Revert> {
        assert_or!(
            self.seawater_admin.get() == msg::sender()
                || self.emergency_council.get() == msg::sender()
                || self.authorised_enablers.get(msg::sender()),
            Error::SeawaterAdminOnly
        );

->      if self.emergency_council.get() == msg::sender()
            && self.seawater_admin.get() != msg::sender()
            && enabled
        {
            // Emergency council can only disable!
            return Err(Error::SeawaterEmergencyOnlyDisable.into());
        }

        self.pools.setter(pool).set_enabled(enabled);
        Ok(())
    }
```
