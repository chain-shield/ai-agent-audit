# Vulnerability details

## Summary
The `swapOut5E08A399` function in the SeawaterAMM contract is designed to perform a token swap where the user specifies the desired output amount. However, there's a critical issue with how the function handles slippage protection.

The function incorrectly uses the `amountIn` parameter as both the maximum input amount and the exact input amount for the swap. This can lead to unexpected behavior and potential loss of funds for users.

## Code Snippet

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L304

```solidity
function swapOut5E08A399(address token, uint256 amountIn, uint256 minOut) external returns (int256, int256) {
    (bool success, bytes memory data) = _getExecutorSwap().delegatecall(abi.encodeCall(
        ISeawaterExecutorSwap.swap904369BE,
        (
            token,
            false,
            int256(amountIn),
            type(uint256).max
        )
    ));
    require(success, string(data));

    (int256 swapAmountIn, int256 swapAmountOut) = abi.decode(data, (int256, int256));
    require(swapAmountOut >= int256(minOut), "min out not reached!");
    return (swapAmountIn, swapAmountOut);
}
```

## Impact
1. Slippage Protection Failure: The function doesn't properly implement slippage protection for the input amount. It uses `amountIn` as an exact amount rather than a maximum.
2. Potential Overpayment: Users might end up spending more input tokens than necessary to receive their desired output amount.
3. Inconsistent Behavior: The function behaves differently from what users might expect from a "swap out" function, potentially leading to confusion and errors in integration.

## Scenario
Alice wants to swap out 100 USDC for at least 0.05 ETH. She calls `swapOut5E08A399` with:
- `token`: ETH address
- `amountIn`: 100 USDC
- `minOut`: 0.05 ETH

The current market rate is 1 ETH = 2000 USDC. Alice expects to receive about 0.05 ETH for her 100 USDC. However, due to the bug, the function will try to swap exactly 100 USDC, potentially giving Alice more ETH than she expected (about 0.0625 ETH) and not respecting her maximum input amount.

## Fix
The function should be modified to use `amountIn` as a maximum input amount rather than an exact amount.

```solidity
function swapOut5E08A399(address token, uint256 maxAmountIn, uint256 minOut) external returns (int256, int256) {
    (bool success, bytes memory data) = _getExecutorSwap().delegatecall(abi.encodeCall(
        ISeawaterExecutorSwap.swap904369BE,
        (
            token,
            false,
            -int256(minOut), // Negative amount for exact output swap
            type(uint256).max
        )
    ));
    require(success, string(data));

    (int256 swapAmountIn, int256 swapAmountOut) = abi.decode(data, (int256, int256));
    require(swapAmountOut >= int256(minOut), "min out not reached!");
    require(-swapAmountIn <= int256(maxAmountIn), "max in exceeded!");
    return (swapAmountIn, swapAmountOut);
}
```
