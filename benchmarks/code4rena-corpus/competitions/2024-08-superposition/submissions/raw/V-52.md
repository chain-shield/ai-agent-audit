# Vulnerability details

## Impact
It's impossible to set protocol fees (which are a fraction of swap fees that go to the protocol instead of the liquidity providers), so any potential revenue from it will always be zero.

## Proof of Concept
Each pool has a `fee_protocol` parameter that indicates how much percentage of the swap fee is taken on withdrawal:
https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/pool.rs#L31

The issue is that this parameter is not set anywhere (and it can't be set afterward), so it will default to zero.

Like Uniswap, this is a way the protocol would earn a stream of revenue; but since it's hard set to zero, the protocol would earn nothing from it.

By searching for `fee_protocol` usage, it can be easily seen that it is only read, as it's never set anywhere:

https://github.com/search?q=repo%3Acode-423n4%2F2024-08-superposition+fee_protocol&type=code

Essentially, the project is currently missing a function to set the `fee_protocol`.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider implementing a function like Uniswap's `setFeeProtocol` so it's possible to set the protocol fees:

```solidity
    function setFeeProtocol(uint8 feeProtocol0, uint8 feeProtocol1) external override lock onlyFactoryOwner {
        require(
            (feeProtocol0 == 0 || (feeProtocol0 >= 4 && feeProtocol0 <= 10)) &&
                (feeProtocol1 == 0 || (feeProtocol1 >= 4 && feeProtocol1 <= 10))
        );
        uint8 feeProtocolOld = slot0.feeProtocol;
        slot0.feeProtocol = feeProtocol0 + (feeProtocol1 << 4);
        emit SetFeeProtocol(feeProtocolOld % 16, feeProtocolOld >> 4, feeProtocol0, feeProtocol1);
    }
```
