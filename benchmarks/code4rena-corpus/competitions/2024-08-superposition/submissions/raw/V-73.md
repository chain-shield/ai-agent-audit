# Vulnerability details

## Impact

`OwnershipNFTs` smart contract is used for the NFT owners to manage their positions by using the standard ERC-721 functionality (transfers, approvals, etc.). But when it comes to the transfers, it has incorrect check in `_requireAuthorised()` function making it deviating from the standard ERC-721 specification.

## Proof of Concept

Currenty `_requireAuthorised()` has the following implementation:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/OwnershipNFTs.sol#L98-107
```
 function _requireAuthorised(address _from, uint256 _tokenId) internal view {
        // revert if the sender is not authorised or the owner
        bool isAllowed =
            msg.sender == _from ||
            isApprovedForAll[_from][msg.sender] ||
            msg.sender == getApproved[_tokenId];

        require(isAllowed, "not allowed");
        require(ownerOf(_tokenId) == _from, "_from is not the owner!");
    }

```

Now take a look at the standard ERC-721 implementation:

https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/ERC721.sol#L189-194
```
     */
    function _isAuthorized(address owner, address spender, uint256 tokenId) internal view virtual returns (bool) {
        return
            spender != address(0) &&
            (owner == spender || isApprovedForAll(owner, spender) || _getApproved(tokenId) == spender);
    }
```

The current implementation requires for the `from` address to be the owner of the NFT while in the standard implementation it checks for authorization from owner to the spender. So, for example, if we take `isApprovedForAll()` check it only checks for the approval from `_from` to the `msg.sender` address but the problem is that the `_from()` is `msg.sender` and the owner as well. So it does not check for the spender as `_from` address is supposed to be the owner. Additionally, `spender` address is not checked to be != 0.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Change the implementation of `_requireAuthorised()` to make the contract ERC-721 compliant.
