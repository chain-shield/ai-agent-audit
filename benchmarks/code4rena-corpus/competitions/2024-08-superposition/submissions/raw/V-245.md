# Vulnerability details

 

## Proof of Concept

Take a look at https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/pool.rs#L561-L566

```rust

    pub fn collect(&mut self, id: U256) -> Result<(u128, u128), Revert> {
        assert_or!(self.enabled.get(), Error::PoolDisabled);
        Ok(self.positions.collect_fees(id))
    }

```

This function is used to collects fees earned by a liquidity provider, ti does this with help of querying https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/position.rs#L107-L121

```rust
    pub fn collect_fees(&mut self, id: U256) -> (u128, u128) {
        let mut position = self.positions.setter(id);

        let amount_0 = position.token_owed_0.get().sys();
        let amount_1 = position.token_owed_1.get().sys();

        if amount_0 > 0 {
            position.token_owed_0.set(U128::ZERO);
        }
        if amount_1 > 0 {
            position.token_owed_1.set(U128::ZERO);
        }

        (amount_0, amount_1)
    }
```

Issue however is that these functionalities do not actually collect any fees and instead the amount owed for both `token0` & `token1` are just reset to `0`.

Note that the intentional flow is to get this function called from `collect_single_to_6_D_76575_F()` in order to ensure [the tokens accumulated as fees get transferred](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/lib.rs#L634-L638) which is used to [trigger fluid LP rewards](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/lib.rs#L665), but since one can directly call `collect_fees` or `collect` this has been broken.

## Impact

Leak of value cause the fees are never really collected, additionally there is expected to be a check when collecting fees to ensure correct access control is applied where if the caller is not the position owner it should revert, this however is not applied in either of `collect_fees` or `collect` which allows anyone to reset the amount of fees.

## Recommended Mitigation Steps

Implement the access control to ensure only the position owner can come collect the fees and that these fees should be transferred, if at all the flow must follow through contracts then an access control should be applied the right contracts are calling this function, in our case that would be both seawater's `pool.rs` & `lib.rs`.

See Uniswap's `collect()` for more info: https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/UniswapV3Pool.sol#L490.
