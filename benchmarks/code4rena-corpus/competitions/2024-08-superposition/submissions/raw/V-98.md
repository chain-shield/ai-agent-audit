# Vulnerability details

## Impact

The current implementation of `mulDivRoundingUp()` deviates from the one specified in the Uniswap code. This makes the code behave unexpectedly in comparison with the Uniswap implementation.

## Proof of Concept

`full_math` library implements `mulDivRoundingUp()` the following way:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/maths/full_math.rs#L59-71
```
pub fn mul_div_rounding_up(a: U256, b: U256, denominator: U256) -> Result<U256, Error> {
    let (result, rem) = _mul_div(a, b, denominator)?;

    if rem {
        if result == U256::MAX {
            Err(Error::ResultIsU256MAX)
        } else {
            Ok(result + U256::one())
        }
    } else {
        Ok(result)
    }
}
```

However, UniV3 library is implemented slightly differently:

https://github.com/Uniswap/v3-core/blob/main/contracts/libraries/FullMath.sol#L113-123
```
    function mulDivRoundingUp(
        uint256 a,
        uint256 b,
        uint256 denominator
    ) internal pure returns (uint256 result) {
        result = mulDiv(a, b, denominator);
        if (mulmod(a, b, denominator) > 0) {
            require(result < type(uint256).max);
            result++;
        }
    }

```

It checks for the `mulmod` operation to be > 0 before comparing the result with type(uint256).max which is not done in the current code of the protocol's library.

## Recommended Mitigation Steps

Deviation from the Uniswap's library implementation can result in an unexpected behavior when dealing with the actual code of the core functionality.
