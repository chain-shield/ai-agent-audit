# Vulnerability details

## Impact
Negating i128::MIN would result in an overflow error

## Proof of Concept
There are no checks if liquidity is i128::MIN before negating it in get_amount_0_delta and get_amount_1_delta. In such case the program will fail even though a cast to u128 is used because in rust first the result is negated and after that casted. This can be easily tested:
```
let liquidity: i128 = i128::MIN;
println!("{}", -liquidity as u128);
```
the following code returns:
```
ERROR!
error: this arithmetic operation will overflow
 --> /tmp/dtOBFz9lJ6/main.rs:6:20
  |
6 |     println!("{}", -liquidity as u128);
  |                    ^^^^^^^^^^ attempt to negate `i128::MIN`, which would overflow
  |
```

## Tools Used
manual review

## Recommended Mitigation Steps
consider adding a check if liquidity is equal to i128::MIN and handle as per the requirements
