# Vulnerability details

## Impact
NFTs won't be sent to contracts that have the correct implementation to handle them and will be sent to ones that don't have the necessary methods implemented thus resulting in NFTs being permanently blocked.

## Proof of Concept
The comment on the _onTransferReceived function states that if the callback doesn't return the selector for onERC721Received then we should revert - https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/sol/OwnershipNFTs.sol#L65-L67 .The same is mentioned in the IERC721TokenReceiver's doc - https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/sol/IERC721TokenReceiver.sol#L6-L9 , however when the callback is finished, in the require statement we expect that the data returned is not equal to the onERC721Received selector which will result in a revert in the wrong case - https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/sol/OwnershipNFTs.sol#L92-L95
