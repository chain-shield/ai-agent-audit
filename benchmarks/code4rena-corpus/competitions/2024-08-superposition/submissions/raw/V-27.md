# Vulnerability details

## Impact
When one NFT is transferred, the NFT token's `getApproved` still take effect. This will cause the previous NFT token approval can still work and transfer this NFT.

## Proof of Concept
When someone wants to transfer one NFT, msg.sender's permission will be checked. Only NFT's owner, owner's operators, and this NFT token's approved address can transfer this NFT. 
The problem is that after we transfer one NFT to new owner, this NFT's token's previous approved address can still transfer this NFT.

For example:
- Alice owns one NFT and Alice approve herself to this NFT.
- Alice transfers the NFT to Bob.
- Alice can still transfer this NFT because `getApproved[NFT]` equals Alice's address. 
```javascript
    function _transfer(
        address _from,
        address _to,
        uint256 _tokenId
    ) internal {
        _requireAuthorised(_from, _tokenId);
        SEAWATER.transferPositionEEC7A3CD(_tokenId, _from, _to);
    }
    function _requireAuthorised(address _from, uint256 _tokenId) internal view {
        // revert if the sender is not authorised or the owner
        bool isAllowed =
            msg.sender == _from ||
            isApprovedForAll[_from][msg.sender] ||
            msg.sender == getApproved[_tokenId];

        require(isAllowed, "not allowed");
        require(ownerOf(_tokenId) == _from, "_from is not the owner!");
    }
```

Manual

## Recommended Mitigation Steps
When we transfer one NFT, clear the previous `getApproved`.
