# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Severity: Medium
Issue Type: Denial of Service (DoS)

In the swap function, there is a while loop that continues iterating as long as there is remaining amount to swap and the pool’s price hasn’t hit the limit. This loop can potentially run into the block gas limit, especially if there are many iterations due to a large liquidity pool or a small price difference between ticks.

```rust
while !state.amount_remaining.is_zero() && state.price != price_limit {
    iters += 1;
    debug_assert!(iters < 500);  // Safeguard check for too many iterations.
    // (rest of the loop logic)
}
```

This issue can lead to a Denial of Service (DoS) attack where an attacker could cause the transaction to fail by forcing the swap function to exceed the block gas limit. This could block swaps for users and prevent them from interacting with the pool effectively, leading to disruptions in trading and liquidity provision.

## Recommended Mitigation Steps

Introduce a maximum iteration limit in the loop to prevent the swap function from running indefinitely. If the iteration limit is reached, the transaction should revert or return partial success.
