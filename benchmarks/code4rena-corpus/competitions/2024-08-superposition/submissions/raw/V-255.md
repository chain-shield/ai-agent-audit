# Vulnerability details

## Impact

Pool creation contains access control, preventing users from creating a new pool, which is against the intention of the protocol.

## Proof of Concept

Pools can be created only from the `Seawater` admin which will limit the usability of the protocol and will make it highly centralized. Although it should be a fork of `UniswapV3`, where pool creation is permissionless and everyone can create a pool, here the modifier is not removed and will prevent users who are not owners from creating new pools:

[lib.rs](https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L999C4-L1011C11)

```rust
 pub fn create_pool_D650_E2_D0(
        &mut self,
        pool: Address,
        price: U256,
        fee: u32,
        tick_spacing: u8,
        max_liquidity_per_tick: u128,
    ) -> Result<(), Revert> {
        assert_eq_or!(
            msg::sender(),
            self.seawater_admin.get(),
            Error::SeawaterAdminOnly
        ); 
```

Nowhere in the README it is mentioned that the pool creation is only for the owner, quite the opposite it mentions that `It is possible for someone to grief the protocol by creating a pool with bad configuration.`, also the sponsor has confirmed that everyone should be able to create new pool. From these evidences we can conclude that this is a serious flaw in the protocol, because of the architecture that is used, single contract to hold the entire liquidity. Since new pools can't be created, migration will be needed which involves users facing unstable liquidity conditions caused by the rapid withdrawals from the protocol.

Furthermore, this AMM is the core of the Superposition chain and is expected to be one of the biggest protocols there, users expecting from it to be able to create various pools, similar to Uniswap, something that is not possible.
