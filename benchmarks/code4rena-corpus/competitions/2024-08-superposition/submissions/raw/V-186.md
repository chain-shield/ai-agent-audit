# Vulnerability details

User can sell/transfer nft to a buyer. 
However it is possible for the user to steal back the nft from the buyer because the approvals are not deleted/removed after transfer.

## Proof of Concept
The token ID can be approved by anyone as long as the conditions inside `_requireAuthorised()` are fulfilled.

```solidity
File: OwnershipNFTs.sol

   function approve(address _approved, uint256 _tokenId) external payable {
        _requireAuthorised(msg.sender, _tokenId);
        getApproved[_tokenId] = _approved;
    }

   function _requireAuthorised(address _from, uint256 _tokenId) internal view {
        // revert if the sender is not authorised or the owner
        bool isAllowed =
            msg.sender == _from ||
            isApprovedForAll[_from][msg.sender] ||
            msg.sender == getApproved[_tokenId];

        require(isAllowed, "not allowed");
        require(ownerOf(_tokenId) == _from, "_from is not the owner!");
    }
```

### Scenario
- Alice owns a nft with token Id `1`.
- Alice calls the `approve()` setting `getApproved` to her own address.
- Alice sells the nft to Bob. The nft is successfully transferred & now the owner of the nft is Bob.
- Alice again calls transfer/safeTransferFrom function which internally calls the `_requireAuthorised()`.
- Because the `getApproved` for that tokenId `1` is still set to Alice's address, the checks pass & the nft is transferred back to Alice.

## Impact
Buyer will lose both the nft & funds paid.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Reset/remove all the approvals after a nft is transferred.
