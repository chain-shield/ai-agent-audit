# Vulnerability details

## Impact

In the current implementation of `liquidity_math` library, the function `add_delta()` makes incorrect checks when adding delta. This can lead to both calculation errors and it makes the protocol not compatible with UniswapV3 Math (as it must be according to the specification).

## Proof of Concept

`add_delta()` current implementation:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/maths/liquidity_math.rs#L7-24
```
pub fn add_delta(x: u128, y: i128) -> Result<u128, Error> {
    if y < 0 {
        let z = x.overflowing_sub(-y as u128);

        if z.1 {
            Err(Error::LiquiditySub)
        } else {
            Ok(z.0)
        }
    } else {
        let z = x.overflowing_add(y as u128);
        if z.0 < x {
            Err(Error::LiquidityAdd)
        } else {
            Ok(z.0)
        }
    }
}

```

Now let's take a look on UniV3 `add_delta()`:

```
library LiquidityMath {
    /// @notice Add a signed liquidity delta to liquidity and revert if it overflows or underflows
    /// @param x The liquidity before change
    /// @param y The delta by which liquidity should be changed
    /// @return z The liquidity delta
    function addDelta(uint128 x, int128 y) internal pure returns (uint128 z) {
        if (y < 0) {
            require((z = x - uint128(-y)) < x, 'LS');
        } else {
            require((z = x + uint128(y)) >= x, 'LA');
        }
    }
}

```

As you can see, in the first condition statement it's checked whether the value < x while in the implementation provided by the protocol is different: it checks whether the value < 0 only in the else-statement and skips the check in the if-statement. This makes the contract not following UniswapV3 Math as stated by the spec:

```
We should follow Uniswap V3's math faithfully.
```

Moreover, the function uses `overflowing_sub()` and `overflowing_add()` that are not reverted in the case of underflow / overflow that are supposed to (according to the UniV3 implementation).

## Recommended Mitigation Steps

Change the implementation of `add_delta()` to be compatible with UniV3 `LiquidityMath` library.
