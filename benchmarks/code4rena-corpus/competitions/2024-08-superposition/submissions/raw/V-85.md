# Vulnerability details

The clear() function in the contract deletes a tick from storage without validating whether it is safe to do so. This can lead to the loss of state or orphaned data tied to the tick, potentially causing unintended consequences in systems that rely on the tick's data for financial calculations or tracking liquidity.

The clear() function removes a tick entry from the storage map

The clear() function in the provided code does not explicitly check if the tick is fully cleared or safe to delete before removing it from storage.

Here are the potential issues arising from this:

Incomplete Clearing: The function might delete a tick while it still has associated liquidity or fee information. This could lead to inconsistencies in the contract's state and potentially incorrect calculations.


There is no validation to check if the tick's state is still necessary or if there are dependent contracts or functions that require the tick’s data for accurate operations. This deletion may:

Orphan associated data tied to the tick (such as liquidity or fee growth).
Result in loss of historical data critical for financial calculations.
Cause issues when the tick is relied upon for liquidity adjustments, fee accruals, or state transitions.
For instance, if other functions depend on the tick for fee calculations, such as cross() or update(), deleting it could lead to inconsistent state, or even revert errors if the missing data is critical for calculations. Additionally, any operations on liquidity or fee growth that reference the cleared tick may behave unpredictably or result in errors.

Exploit Scenario:
A user or external actor triggers the clear() function on a tick that still holds liquidity or other relevant data.
The contract or external systems attempt to access the tick's liquidity or fee growth data, leading to failed transactions, incorrect fee distribution, or liquidity imbalances.
This may cause financial loss to users, the contract itself, or destabilize the pool’s operations.

Impacts:
The lack of validation in clear() introduces a critical vulnerability that could destabilize the contract's liquidity tracking, fee distribution mechanisms, or other dependent systems, potentially leading to significant financial losses or operational failure.

Recommendations:
Add validation checks: Ensure the tick is safe to delete by verifying that it no longer holds any relevant data such as liquidity or fee growth.

For example, add a condition that checks if the tick’s liquidity has been fully drained, and that no fee accruals are pending.




pub fn clear(&mut self, tick: i32) -> Result<(), Error> {
    let info = self.ticks.get(tick);
    if info.liquidity_gross.get() > 0 {
        return Err(Error::TickStillActive);
    }
    self.ticks.delete(tick);
    Ok(())
}
