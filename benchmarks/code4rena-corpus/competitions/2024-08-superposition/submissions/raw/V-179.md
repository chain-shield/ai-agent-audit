# Vulnerability details

## Impact

In the current functionality of the `SeawaterAMM` smart contract, the users can call `burnPositionAE401070()` that will burn the position by delegating the call to the implementation. The problem is that the actual ERC721 token is burnt meaning the position is not fully burnt but just the owner is removed in the Rust implementation code.

## Proof of Concept

Take a look at the `burnPositionAE401070()` functionality inside of the implementation contract:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L529-543
```
  pub fn burn_position_AE401070(&mut self, id: U256) -> Result<(), Revert> {
        let owner = msg::sender();
        assert_eq_or!(
            self.position_owners.get(id),
            owner,
            Error::PositionOwnerOnly
        );

        self.remove_position(owner, id);

        #[cfg(feature = "log-events")]
        evm::log(events::BurnPosition { owner, id });

        Ok(())
    }

```

So it just removes the owner of the id but there is no any logic for burning the actual ERC721 token in the `SeawaterAMM`:

https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L351-353
```
   function burnPositionAE401070(uint256 /* id */) external {
        directDelegate(_getExecutorPosition());
    }

```
