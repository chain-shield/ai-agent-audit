# Vulnerability details

## Impact

Currently the contract realizes Diamond-like faucet pattern for upgradeable contracts as stated by the spec:

```
Diamond-like proxy for dispatch: A Solidity contract is used to delegatecall to different facets of the contract.
Links
```

This pattern is used to update the logic for different facets if needed. However, in the current version of the `SeawaterAMM`, there is no any function to actually update the logic of the facets but the function to upgrade all the facets at once.


## Proof of Concept

The `SeawaterAMM` uses the combination of OZ `Proxy` contract and Diamond proxy pattern:


https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/sol/SeawaterAMM.sol#L132-155
```

  function directDelegate(address to) internal {
        assembly {
            // Copy msg.data. We take full control of memory in this inline assembly
            // block because it will not return to Solidity code. We overwrite the
            // Solidity scratch pad at memory position 0.
            calldatacopy(0, 0, calldatasize())

            // Call the implementation.
            // out and outsize are 0 because we don't know the size yet.
            let result := delegatecall(gas(), to, 0, calldatasize(), 0, 0)

            // Copy the returned data.
            returndatacopy(0, 0, returndatasize())

            switch result
            // delegatecall returns 0 on error.
            case 0 {
                revert(0, returndatasize())
            }
            default {
                return(0, returndatasize())
            }
        }
    }

```

The function `directDelegate()` is used to delegate calls to the "features" contracts (different facets). But there is no actually the function that allows update the logic of a single facet making such upgradeability pattern useless.

## Recommended Mitigation Steps

Implement `diamondCut()` like functionality to add / replace / remove selectors for different facets. It's better to stick to ERC-2535 Diamond Proxy implementation
