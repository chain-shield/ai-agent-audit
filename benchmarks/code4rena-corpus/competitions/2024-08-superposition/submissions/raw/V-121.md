# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Severity: Medium
Issue Type: Improper Input Validation

In the take_permit2 function, the system relies on signature verification but does not include any checks to ensure that the signature provided is properly validated by comparing it to the correct data (e.g., the token holder’s address). If signatures are not properly validated, an attacker could submit a forged or invalid signature to steal tokens.

pub fn take_permit2(
    token: Address,
    transfer_amount: U256,
    details: Permit2Args,
) -> Result<(), Error> {
    let data = encode_permit2(
        token,
        details.max_amount,
        details.nonce,
        details.deadline,
        contract::address(),
        transfer_amount,
        msg::sender(),
        details.sig,
    );

    match RawCall::new().call(PERMIT2_ADDR, &data) {
        Ok(_) => Ok(()),
        Err(v) => Err(Error::Erc20Revert(v)),
    }
}

## Recommended Mitigation Steps

The mitigation is to include proper signature validation by checking that the recovered address from the signature matches the token holder’s address. The code above implements this check by verifying the signature with verify_signature before executing the token transfer.
```rust
pub fn verify_signature(from: Address, details: &Permit2Args, data_hash: [u8; 32]) -> Result<bool, Error> {
    let recovered_address = recover_address_from_signature(details.sig, data_hash)?;
    if recovered_address == from {
        Ok(true)
    } else {
        Err(Error::InvalidSignature)
    }
}
```
By ensuring that the signature is valid before transferring tokens, we can prevent forged signatures from being used.
