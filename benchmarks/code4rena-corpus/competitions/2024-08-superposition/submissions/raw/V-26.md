# Vulnerability details

## Impact
When one NFT is transferred to one contract, the function `_onTransferReceived()` will be reverted because of the incorrect require statement. 

## Proof of Concept
When one NFT is transferred to one contract via safeTransferFrom(), we will try to call `to` contract's `onERC721Received()` callback and check the return value's validation. The return value should be expected to `IERC721Receiver.onERC721Received.selector`. 

But in function `_onTransferReceived()`, the require makes mistakes. This will cause most contracts which support ERC721 callback will be reverted when one NFT is safeTransferFrom to one contract.

```javascript
    function _onTransferReceived(
        address _sender,
        address _from,
        address _to,
        uint256 _tokenId
    ) internal {
        // only call the callback if the receiver is a contract
        if (_to.code.length == 0) return;

        bytes4 data = IERC721TokenReceiver(_to).onERC721Received(
            _sender,
            _from,
            _tokenId,

            // this is empty byte data that can be optionally passed to
            // the contract we're confirming is able to receive NFTs
            ""
        );

        require(
@>            data != IERC721TokenReceiver.onERC721Received.selector,
            "bad nft transfer received data"
        );
    }
```
