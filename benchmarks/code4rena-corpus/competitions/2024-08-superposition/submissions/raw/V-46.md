# Vulnerability details

## Impact
User is unable to perform a swap even though liquidity is sufficient in both pools involved in the swap for the `min_out` amount to be outputted.

## Proof of Concept
Let's have a look at the [`swap_2_internal`](https://github.com/code-423n4/2024-08-superposition/blob/main/pkg/seawater/src/lib.rs#L198-L251) function below

```javascript
    fn swap_2_internal(
        pools: &mut Pools,
        from: Address,
        to: Address,
        amount: U256,
        min_out: U256,
    ) -> Result<(U256, U256, U256, I256, i32, i32), Revert> {
        let original_amount = amount;

        let amount = I256::try_from(amount).map_err(|_| Error::SwapResultTooHigh)?;

        // swap in -> usdc
        let (amount_in, interim_usdc_out, final_tick_in) = pools.pools.setter(from).swap(
            true,
            amount,
            // swap with no price limit, since we use min_out instead
            tick_math::MIN_SQRT_RATIO + U256::one(),
        )?;

        // make this positive for exact in
        let interim_usdc_out = interim_usdc_out
            .checked_neg()
            .ok_or(Error::InterimSwapPositive)?;

        // swap usdc -> out
        let (amount_out, interim_usdc_in, final_tick_out) = pools.pools.setter(to).swap(
            false,
            interim_usdc_out,
            tick_math::MAX_SQRT_RATIO - U256::one(),
        )?;

        let amount_in = amount_in.abs_pos()?;
        let amount_out = amount_out.abs_neg()?;

        #[cfg(feature = "testing-dbg")]
        dbg!((
            "inside swap_2_internal",
            interim_usdc_out,
            interim_usdc_in,
            amount_out.to_string(),
            min_out.to_string()
        ));

        assert_eq_or!(interim_usdc_out, interim_usdc_in, Error::InterimSwapNotEq);
        assert_or!(amount_out >= min_out, Error::MinOutNotReached);
        Ok((
            original_amount,
            amount_in,
            amount_out,
            interim_usdc_out,
            final_tick_in,
            final_tick_out,
        ))
    }
```

this function performs a 2-step swap by swapping the `from` token to `usdc` and then `usdc` to the `to` token, given a `min_out` amount inputted by the user and corresponding to the minimum amount the user is willing to receive from this swap.

we notice the assertion on line 241

```javascript
        assert_eq_or!(interim_usdc_out, interim_usdc_in, Error::InterimSwapNotEq);
```

which intends to check that the whole out usdc amount from the first swap (`interim_usdc_out`) is being used entirely by the swap into the other pool, hence equal to the input amount `interim_usdc_in`.
However, this need not be the case as long as the `min_out` amount chosen by the user is met.

Note that this is the reason for the `ethers_suite_orchestrated_uniswap_two` test to fail as the second liqudity pool does not have enough liqudity to absorb the whole `interim_usdc_out` and we will reach the lowest tick before having used the whole amount. Increasing the liqudity to say `30000` instead of `20000` makes this test pass. Removing the assertion also makes it pass correctly.

```diff
-            contract
-                .update_position_C_7_F_1_F_740(token1, U256::one(), 20000)
-                .unwrap();
+            contract
+                .update_position_C_7_F_1_F_740(token1, U256::one(), 30000)
+                .unwrap();
```

## Recommended Mitigation Steps

To mitigate this issue and allow these swaps to go through, just remove the assertion from the `swap_2_internal` as below

```diff
-         assert_eq_or!(interim_usdc_out, interim_usdc_in, Error::InterimSwapNotEq);
```
