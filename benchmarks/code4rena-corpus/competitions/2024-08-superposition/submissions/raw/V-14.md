# Vulnerability details

## Impact
NFTs transferred to non-compliant contracts may become permanently inaccessible, effectively locking them away.

## Proof of Concept
The [`transferFrom()`](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/sol/OwnershipNFTs.sol#L118-L126) functions in the `OwnershipNFTs` contract do not invoke the `_onTransferReceived()` function. This function is crucial for verifying whether the `recipient` address is a contract that can handle `ERC721` tokens.
```solidity
    function transferFrom(
        address _from,
        address _to,
        uint256 _tokenId,
        bytes calldata /* _data */
    ) external payable {
        // checks that the user is authorised
        _transfer(_from, _to, _tokenId);
    }
```
[`_onTransferReceived()`](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/sol/OwnershipNFTs.sol#L73-L96) function is crucial for verifying whether the `recipient` address is a contract that can handle `ERC721` tokens. 
```solidity
// @notice _onTransferReceived by calling the callback `onERC721Received` in the recipient if they have codesize > 0. if the callback doesn't return the selector, revert!
```
When an `NFT` is sent to a contract without this implementation, the contract may not have the logic to handle the token, leading to the token being locked within the contract. This is because the contract may not have any functionality to transfer or manage the `NFT` once received.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Since there are already safe transfer methods already implemented, it would be more sound to remove these unsafe ones from the contract.
