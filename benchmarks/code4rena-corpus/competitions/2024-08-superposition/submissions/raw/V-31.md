# Vulnerability details

## Impact
Lack of slippage control for function update_position_C_7_F_1_F_740(). LP holders may increase/decrease liquidity with one unexpected price.

## Proof of Concept
In lib.rs, users can increase/decrease liquidity via function `update_position_C_7_F_1_F_740`. 
The problem is that we don't set one users' expected token amount for this delta liquidity. When the pool's current tick is away from the user's expected tick, users have to increase/decrease liquidity with one unexpected price.

When we go through Uniswap v3, there is one similar function mint() in UniswapV3Pool. The pool's mint() function is also unsafe, and don't suggest users to use this function directly. Instead, uniswap v3 has its own wrapper contract. In wrapper contract NonfungiblePositionManager, we will have the slippage check.
