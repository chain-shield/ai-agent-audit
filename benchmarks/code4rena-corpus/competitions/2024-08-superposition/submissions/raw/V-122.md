# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Severity: Medium
Issue Type: Replay Attack Vulnerability

The contract uses signatures for authorization without checking the nonce properly. This creates the risk of replay attacks, where an attacker can reuse a valid signature multiple times, leading to unauthorized token transfers.

## Recommended Mitigation Steps

To prevent replay attacks, the nonce must be properly validated and incremented after each signature use. The following code adds proper nonce validation:
```rust
pub fn take_permit2(token: Address, transfer_amount: U256, details: Permit2Args) -> Result<(), Error> {
    // Ensure that the nonce has not been used
    if !is_nonce_used(details.from, details.nonce)? {
        return Err(Error::NonceAlreadyUsed);
    }

    let data_hash = keccak256_hash_of_data(token, transfer_amount, &details);

    // Verify the signature before proceeding with the transfer
    if verify_signature(details.from, &details, data_hash)? {
        let data = encode_permit2(
            token,
            details.max_amount,
            details.nonce,
            details.deadline,
            contract::address(),
            transfer_amount,
            msg::sender(),
            details.sig,
        );

        // Mark nonce as used
        mark_nonce_used(details.from, details.nonce)?;

        match RawCall::new().call(PERMIT2_ADDR, &data) {
            Ok(_) => Ok(()),
            Err(v) => Err(Error::Erc20Revert(v)),
        }
    } else {
        Err(Error::InvalidSignature)
    }
}
```
The mark_nonce_used function ensures that each nonce is only used once. This change mitigates replay attacks by tracking and invalidating used nonces.
