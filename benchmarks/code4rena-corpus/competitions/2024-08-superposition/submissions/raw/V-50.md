# Vulnerability details

## Impact
The `emergency_council` role should be mutable, but the setter function is wrongly implemented; thus it's impossible to change it after initialization.

Moreover, the new manager will receive the `nft_manager` permission instead of the intended `emergency_council`, i.e. they would technically be able to steal the assets, while normally they would be only able to disable a pool.


## Proof of Concept

`update_emergency_council` wrongly updates the `nft_manager` instead of the `emergency_council`:

```rust
    #[allow(non_snake_case)]
    pub fn update_emergency_council_7_D_0_C_1_C_58(
        &mut self,
        manager: Address,
    ) -> Result<(), Revert> {
        assert_eq_or!(
            msg::sender(),
            self.seawater_admin.get(),
            Error::SeawaterAdminOnly
        );

->      self.nft_manager.set(manager);

        Ok(())
    }
```
