# Vulnerability details

The comment for the `update_position_internal` function in `lib.rs` states that the pool should allow liquidity removal, even when disabled:

```rust
    /// position owner. Requires the pool to be enabled unless removing liquidity.
    pub fn update_position_internal(
```
[lib.rs#L687-L688](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/lib.rs#L687-L688)

However, when updating a position in the pool, there is a requirement that only pools with enabled status can be updated:

```rust
    /// Updates a position in this pool, refreshing fees earned and updating liquidity.
    pub fn update_position(&mut self, id: U256, delta: i128) -Result<(I256, I256), Revert{
        // the pool must be enabled
        assert_or!(self.enabled.get(), Error::PoolDisabled);
```
[pool.rs#L91-L92](https://github.com/code-423n4/2024-08-superposition/blob/4528c9d2dbe1550d2660dac903a8246076044905/pkg/seawater/src/pool.rs#L91-L92)

This leads to a revert if the pool is disabled, regardless of whether the`delta`parameter is positive or negative (i.e., whether liquidity is being added or removed). Therefore,**liquidity cannot be removed if the pool is disabled**, as the`update_position`function will revert the transaction in that case.

## Impact

In case a pool with added liquidity gets disabled, all users’ funds will remain locked as long as the pool is not enabled again by the seawater admin.

## Tools Used

Manual review.

## Recommended Mitigation Steps

To mitigate this, in`update_position`, only check the pool status if the user wants to add liquidity. This would allow removal of liquidity regardless of the pool status. The`delta`parameter should be utilized to determine this. For instance, in`pool.rs`, replace:

```rust
    pub fn update_position(&mut self, id: U256, delta: i128) -Result<(I256, I256), Revert{
        // the pool must be enabled
        assert_or!(self.enabled.get(), Error::PoolDisabled);
```
