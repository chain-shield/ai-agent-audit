# Vulnerability details

## Impact
The function `depositWithExpiry()` reverts due to a missing asset spending allowance, caused by not calling the `asset.approve()` function.


## Proof of Concept
The function [depositWithExpiry()](https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/ethereum/contracts/THORChain_Router.sol#L131-L140) calls the internal [_deposit()](https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/ethereum/contracts/THORChain_Router.sol#L143-L160) function, which transfers the asset from `msg.sender` to the `THORChain_Router` via the function `safeTransferFrom()`.
```solidity
  function safeTransferFrom(
    address _asset,
    uint _amount
  ) internal returns (uint amount) {
    uint _startBal = iERC20(_asset).balanceOf(address(this));
    (bool success, bytes memory data) = _asset.call(
      abi.encodeWithSignature(
        "transferFrom(address,address,uint256)",
        msg.sender,
        address(this),
        _amount
      )
    );
    require(success && (data.length == 0 || abi.decode(data, (bool))));
    return (iERC20(_asset).balanceOf(address(this)) - _startBal);
  }
```

However, the required `_asset` spending allowance for the `THORChain_Router` contract is missing. This leads to a revert due to insufficient allowance.

## Recommended Mitigation Steps
Consider setting the appropriate token approvals for the appropriate amounts within the [safeTransferFrom()](https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/ethereum/contracts/THORChain_Router.sol#L438-L453) function to allow it to operate as intended.
