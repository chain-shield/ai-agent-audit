# Vulnerability details

## Impact
In the Solidity function depositWithExpiry, there is a potential vulnerability if an attacker can manipulate the block.timestamp to their advantage. 


## Proof of Concept
An attacker can manipulate the block.timestamp and call depositWithExpiry function to deposit when the router has expired.
https://github.com/crytic/slither/wiki/Detector-Documentation#block-timestamp

In depositWithExpiry function.

    require(block.timestamp < expiration, "THORChain_Router: expired");

1.Router expires
2.Almost at the same time the attacker reduces the block.timestamp by 15 seconds 
3.The attacker calls depositWithExpiry and can deposit when the router has expired.


## Tools Used
Manual review


## Recommended Mitigation Steps
Adding a 15-second buffer to the block.timestamp check can mitigate minor manipulations by miners.

    function depositWithExpiry(
    address payable vault,
    address asset,
    uint256 amount,
    string memory memo,
    uint256 expiration
    ) external payable {
    // Adding a reasonable buffer time to account for block.timestamp manipulation
    require(block.timestamp + 15 seconds < expiration, "THORChain_Router: expired");
    _deposit(vault, asset, amount, memo);
    }
