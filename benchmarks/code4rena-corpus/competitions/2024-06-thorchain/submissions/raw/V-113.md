# Vulnerability details

## Impact
Missing check allows entities to send native currency to the router contract and by abusing the same logic to steal any native currency from the same contract.

## Proof of Concept
In the readme and in code comments it is stated that `THORChain_Router.sol` should not be able to hold native currency and that all is sent to other recipients (vaults).

The functions that call `_transferOutV5()` however, do not check whether msg.value is equal TransferOutData.amount when TransferOutData.asset is address(0) (indicating native asset transfer).

The following scenario could unfold without any reverts (either by mistake or intentionally):
1. `transferOutV5()` is called with msg.value being 1 ETH and amount argument being 0.5 ETH
2. The call does not revert and contract sends 0.5 ETH to the recipient.
3. The rest 0.5 ETH remains in the contract.
4. Event emits transferOut with amount being 0.5 ETH

With the same logic anybody can send to himself all the ETH present in the contract by:
1. Calling `transferOutV5()` with msg.value being 0 and amount argument being the balance of native currency of the contract and recipient being any arbitrary address.
2. An attacker successfully transferred all native currency from the router contract to himself.

## Tools Used

Manual Review

## Recommended Mitigation Steps
All functions that use `_transferOutV5()` have to validate if msg.value is equal the amount argument.

In the case of `batchTransferOutV5()` we should check if the sum of all amount arguments is equal msg.value.

This way we can ensure that the native currency that is sent by the caller is always the same as the defined amount argument.
