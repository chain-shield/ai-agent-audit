# Vulnerability details

## Impact
This `_deposit` function is supposed to forward ETH directly to the provided vault address, but it currently only does so if the `asset` is the zero address (indicating ETH). For ERC-20 tokens, it transfers the tokens to the router contract itself and updates the `_vaultAllowance` mapping.
```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        _vaultAllowance[vault][asset] += safeAmount; // Credit to chosen vault
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```
1. Incorrect Asset Handling:
    - The function correctly forwards ETH to the provided vault address when the `asset` is the zero address.
    - For ERC-20 tokens, the function transfers the tokens to the router contract itself and updates the `_vaultAllowance` mapping instead of forwarding the tokens directly to the vault address.

2. Potential Issues:
    - The ERC-20 tokens are not forwarded to the vault address as intended. Instead, they remain in the router contract, which could lead to asset mismanagement.
    - The need to manage allowances and balances within the router contract adds unnecessary complexity and potential points of failure.
    - Holding ERC-20 tokens in the router contract increases the attack surface and potential for exploits.

## Recommended Mitigation Steps
If the goal is to always forward ETH directly to the provided vault address, regardless of whether the asset is ETH or an ERC-20 token, we should modify the function to handle both cases appropriately. 
```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success, "Failed to send ETH to vault");
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        bool success = IERC20(asset).transfer(vault, safeAmount); // Forward ERC-20 tokens to vault
        require(success, "Failed to transfer ERC-20 tokens to vault");
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```
