# Vulnerability details

## Impact
The `.send()` and `.transfer()` function intends to transfer an ETH amount with a fixed amount of 2300 gas. This has some notable shortcomings when the recipient is a smart contract, if the recipient implements a fallback function containing some sort of logic, this may inevitably revert, meaning the vault and owner of the contract will never be able to call certain sensitive functions. Additionally, using higher than 2300 gas might be mandatory for some multisig wallets.

## Proof of Concept
The Receiver contract includes a fallback function that consumes more than 2300 gas by performing an operation like a loop.

```javascript
// SPDX-License-Identifier: MIT
pragma solidity 0.8.22;

contract Receiver {
    // Fallback function that consumes more than 2300 gas
    fallback() external payable {
        for (uint256 i = 0; i < 300; i++) {
            // Some expensive operations
        }
    }
}

```
The THORChain_Router contract uses the .send() and .transfer() function to transfer Ether to the Receiver. It is expected to fail due to the high gas consumption in the Receiver's fallback function.

## Tools Used
Manual review

## Recommended Mitigation Steps
Using call with its returned boolean checked in combination with re-entrancy guard is highly recommended
