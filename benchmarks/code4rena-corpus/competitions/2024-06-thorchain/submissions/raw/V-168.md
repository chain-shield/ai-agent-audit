# Vulnerability details

### Summary

In the current implementation of `THORChain_Router::transferOut`, if a vault sends Ether during the transfer of an ERC20 token, this Ether will be stuck in the contract.

### Proof of concept

The `transferOut` function allows for the transfer of either Ether or ERC20 tokens. However, there is no check to prevent Ether from being sent along with an ERC20 token transfer. When transferring ERC20 tokens, if Ether is inadvertently sent along with the transaction, the Ether will remain trapped in the contract because it is not handled or forwarded to the intended recipient.

### Code Snippet

```solidity
function transferOut(
    address payable to,
    address asset,
    uint amount,
    string memory memo
) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = to.send(safeAmount); // Send ETH.
        if (!success) {
            payable(address(msg.sender)).transfer(safeAmount); // For failure, bounce back to vault & continue.
        }
    } else {
        _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
        (bool success, bytes memory data) = asset.call(
            abi.encodeWithSignature("transfer(address,uint256)", to, amount)
        );
        require(success && (data.length == 0 || abi.decode(data, (bool)))); // ok
        safeAmount = amount;
    }
    emit TransferOut(msg.sender, to, asset, safeAmount, memo);
}
```

### Impact

- **Ether Loss**: If Ether is sent along with an ERC20 token transfer, it will become stuck in the contract and cannot be withdrawn or recovered.
- **User Confusion**: Users may accidentally send Ether along with ERC20 transfers, leading to loss of funds and potential confusion or frustration.

### Tools Used

- Manual review

### Recommended Mitigation Steps

To prevent this issue, the function should revert if Ether is sent during an ERC20 token transfer. This can be done by adding a check to ensure that `msg.value` is zero when transferring ERC20 tokens.

### Updated Code Snippet

Below is the updated code snippet with the recommended changes:

```solidity
function transferOut(
    address payable to,
    address asset,
    uint amount,
    string memory memo
) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = to.send(safeAmount); // Send ETH.
        if (!success) {
            payable(address(msg.sender)).transfer(safeAmount); // For failure, bounce back to vault & continue.
        }
    } else {
        require(msg.value == 0, "Ether sent with ERC20 transfer"); // Revert if Ether is sent during ERC20 transfer
        _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
        (bool success, bytes memory data) = asset.call(
            abi.encodeWithSignature("transfer(address,uint256)", to, amount)
        );
        require(success && (data.length == 0 || abi.decode(data, (bool)))); // ok
        safeAmount = amount;
    }
    emit TransferOut(msg.sender, to, asset, safeAmount, memo);
}
```

By implementing this check, the function will ensure that Ether is not sent with ERC20 token transfers, preventing the Ether from getting stuck in the contract.
