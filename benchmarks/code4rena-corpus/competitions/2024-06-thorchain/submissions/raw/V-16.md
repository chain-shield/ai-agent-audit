# Vulnerability details

## Impact
The absence of an allowance check before attempting the ERC20 transfer could lead to unauthorized transfers from the Router. Without verifying if `msg.sender` has the appropriate allowance stored in the `_vaultAllowances` mapping, there is a risk of transferring more assets than permitted. This could result in significant financial losses for users and compromise the integrity and security of the contract.

## Recommended Mitigation Steps
Add an allowance check before attempting the ERC20 transfer to ensure that `msg.sender` has enough allowance for the asset. This can be done by including a require statement to verify the allowance before proceeding with the transfer. Here is the updated code:

```
require(_vaultAllowance[msg.sender][asset] >= amount, "Insufficient allowance");
(bool success, bytes memory data) = asset.call(
    abi.encodeWithSignature("transfer(address,uint256)", to, amount)
);
require(success && (data.length == 0 || abi.decode(data, (bool))), "ERC20 transfer failed");

// Reduce allowance only after successful transfer
_vaultAllowance[msg.sender][asset] -= amount;
```
