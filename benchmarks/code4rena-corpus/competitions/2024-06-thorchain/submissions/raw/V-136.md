# Vulnerability details

## Impact

In the `_transferOutAndCallV5` function, when aggregationPayload.fromAsset = address(0), the code assumes that msg.value is always equal to `aggregationPayload.fromAmount` and emits the `msg.value` as the event parameter.


If however, the function is called with values msg.value =! aggregationPayload.fromAmount, the broadcasted event and the actual swap would be different. This can have severe consequences since events are a critical part of the ThorChain system. 


## Proof of Concept

`aggregationPayload.fromAmount` stems from `TransferOutAndCallData calldata aggregationPayload`, which is passed as an input parameter on `_transferOutAndCallV5`

```solidity
        abi.encodeWithSignature(
          "swapOutV5(address,uint256,address,address,uint256,bytes,string)",
          aggregationPayload.fromAsset,
          aggregationPayload.fromAmount,
          aggregationPayload.toAsset,
          aggregationPayload.recipient,
          aggregationPayload.amountOutMin,
          aggregationPayload.payload,
          aggregationPayload.originAddress
        )
```

In the swapOut call,`aggregationPayload.fromAmount` is correctly used. 

Yet in the event emission,`msg.value` is used.

```solidity
      emit TransferOutAndCallV5(
        msg.sender,
        aggregationPayload.target,
        msg.value,
        aggregationPayload.toAsset,
        aggregationPayload.recipient,
        aggregationPayload.amountOutMin,
        aggregationPayload.memo,
        aggregationPayload.payload,
        aggregationPayload.originAddress
      );
```

There is no check to ensure `msg.value` == `aggregationPayload.fromAmount`, so whenever someone (vault or person) uses this function and intentionally or accidentally does not use the exact same values, the swap and event will have different values.
 
## Tools Used

## Recommended Mitigation Steps

Implement a check to ensure that `msg.value` == `aggregationPayload.fromAmount`
