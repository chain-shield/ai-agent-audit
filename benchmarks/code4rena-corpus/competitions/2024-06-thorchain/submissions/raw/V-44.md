# Vulnerability details

Thorchain has a whitelist of tokens it will use and among those are STA and PAXG which are fee on transfer tokens:
https://gitlab.com/thorchain/thornode/-/blob/develop/common/tokenlist/ethtokens/eth_mainnet_latest.json?ref_type=heads#L1942
https://gitlab.com/thorchain/thornode/-/blob/develop/common/tokenlist/ethtokens/eth_mainnet_latest.json?ref_type=heads#L1870

The `THORChain_Router.sol` correctly handles fee on transfer tokens in its `depositWithExpiry()` but it doesn't do so in `_transferOutAndCallV5()`.
The purpose of this function is that it allows a vault to send an asset (ERC20 or ETH) and swap it for another asset which will be sent to the recipient. It does so by transferring the asset to an aggregator which then initiates a transaction on a 3rd party protocol to do the swap.

However this will not work with fee on transfer tokens.


## Impact
Fee on transfer tokens will not work for `_transferOutAndCallV5()` as they will make it revert when the aggregator attempts to swap tokens using the swap router.

## Proof of Concept
Let's look at the portion of the `_transferOutAndCallV5()` that handles swaps from ERC20 to another ERC20. First we transfer a `fromAmount` amount of asset to the aggregator:
```solidity
      // send ERC20 to aggregator contract so it can do its thing
      (bool transferSuccess, bytes memory data) = aggregationPayload
        .fromAsset
        .call(
          abi.encodeWithSignature(
            "transfer(address,uint256)",
            aggregationPayload.target,
            aggregationPayload.fromAmount
          )
        );
```
Then we call the `swapOutV5()` function on the aggregator with the same `fromAmount`:
```solidity
      (bool _dexAggSuccess, ) = aggregationPayload.target.call{value: 0}(
        abi.encodeWithSignature(
          "swapOutV5(address,uint256,address,address,uint256,bytes,string)",
          aggregationPayload.fromAsset,
          aggregationPayload.fromAmount,
...
        )
      );
```
In the audit repo there is an example contract of an aggregator and there we can see that `swapOutV5()` just calls `swapExactTokensForETH()` on a swap router (for example Uniswap)
```solidity
        (bool aggSuccess, ) = address(swapRouter).call(
          abi.encodeWithSignature(
            "swapExactTokensForETH(uint256,uint256,address[],address,uint256)",
            fromAmount,
```

Here is how fee on transfer tokens will cause issues:
1. Vault wants to swap 5 STA for DOGE so it calls `_transferOutAndCallV5()`.
2. Only 4.9 STA gets transfered to the aggregator because there was a 0.1 STA transfer fee.
3. The aggregator had no STA at first and now has 4.9 STA.
4. The aggregator calls `swapExactTokensForETH()` with 5 STA but doesn't have enough balance so the transaction reverts.

Manual Review

## Recommended Mitigation Steps
To prevent this you can implement the same mitigation that `depositWithExpiry()` has. That is checking how much token was transferred using `balanceOf()`.
