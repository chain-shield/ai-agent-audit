# Vulnerability details

## Impact
According to the requirement, when depositing an ERC20 token, the tokens should stay in the router contract, and the vault allowance should be updated. However, the current implementation function `"_deposit"` transfers the tokens from the user to the router contract using `safeTransferFrom`, but it doesn't ensure that the tokens stay in the router contract. [chain/ethereum/contracts/THORChain_Router.sol#_deposit](https://github.com/code-423n4/2024-06-thorchain/blob/e5ae503d0dc2394a82242be6860eb538345152a1/chain/ethereum/contracts/THORChain_Router.sol#L143-L160)
```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        _vaultAllowance[vault][asset] += safeAmount; // Credit to chosen vault
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```
The issue is that after transferring the ERC20 tokens to the router contract using `safeTransferFrom`, the function immediately updates the vault allowance with `_vaultAllowance[vault][asset] += safeAmount;`. This allows the vault to spend the tokens, but it doesn't guarantee that the tokens will stay in the router contract.

## Proof of Concept
The line [_vaultAllowance[vault][asset] += safeAmount;](https://github.com/code-423n4/2024-06-thorchain/blob/e5ae503d0dc2394a82242be6860eb538345152a1/chain/ethereum/contracts/THORChain_Router.sol#L157) updates the vault allowance immediately after transferring the tokens to the router contract using `safeTransferFrom`. This allows the vault to spend the tokens without proper authorization from the router contract.

## Recommended Mitigation Steps
remove the line that updates the vault allowance and instead emit an event or update a separate mapping to track the deposited amounts for each vault.
```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        // Track the deposited amount for the vault
        _vaultDeposits[vault][asset] += safeAmount;
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```
Instead of updating the vault allowance directly, we introduce a new mapping `_vaultDeposits` to track the deposited amounts for each vault and asset. This ensures that the ERC20 tokens stay in the router contract, and the vault's deposited amounts are recorded separately.

Remember to declare the _vaultDeposits mapping at the contract level:
```solidity
mapping(address => mapping(address => uint)) private _vaultDeposits;
```
The router contract will hold the deposited ERC20 tokens, and the vault's deposited amounts will be tracked separately, fulfilling the requirement of keeping the tokens in the router contract.
