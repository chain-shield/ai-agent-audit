# Vulnerability details

## Summary

The current implementation of transfer operations uses `transferFrom` or `transfer`, which may lead to issues due to non-compliance of some ERC20 tokens with the EIP20 standard.

## Proof of Concept

#### Issue with ERC20 Token Compliance

Not all ERC20 tokens strictly adhere to the EIP20 standard. Specifically, some tokens:
- Do not return a boolean flag indicating success or failure.
- Do not revert on failure, causing the transaction to proceed without indication of an issue.

These deviations can cause failures or unexpected behavior in contracts relying on these tokens.

#### Proposed Solution

To address these issues, use OpenZeppelin's `SafeERC20` library, which provides `safeTransfer` and `safeTransferFrom` functions. These functions handle:
- Return value checks.
- Compatibility with non-standard-compliant tokens.

#### Example of Vulnerable Implementation

The following snippet demonstrates a current implementation that is vulnerable because it doesn't check if `transferOutPayload.asset` is a contract:

```solidity
(bool success, bytes memory data) = transferOutPayload.asset.call(
    abi.encodeWithSignature("transfer(address,uint256)", transferOutPayload.to, transferOutPayload.amount)
);
```

If `transferOutPayload.asset` is not a contract (i.e., it has no bytecode), the call will succeed regardless of the actual transfer status, potentially leading to incorrect assumptions about the success of the transfer.

## Impact

The impact of the vulnerability involves:

**Financial Risk:** Loss of funds due to failed transfers.
**Operational Instability:** Inconsistent contract state from unchecked transfers.
**Contract Dysfunction:** Risk of contract failure and unintended behavior.

## Tools Used
Manual review

## Recommended Mitigation Steps

Using OpenZeppelin's `SafeERC20`, the above code can be improved as follows:

```solidity
IERC20 transferOutPayloadAsset = IERC20(transferOutPayload.asset);
transferOutPayloadAsset.safeTransfer(transferOutPayload.to, transferOutPayload.amount);
```

This ensures that the transfer operation is performed safely, with checks for compliance with the EIP20 standard and handling of non-standard tokens.
