# Vulnerability details

## Root of the bug 

The  issue is occur from the absence of validation  the vault in the depositWithExpiry function cause This function is calls the _deposit function without checking if the provided vault address is an authorized THORChain vault and this is  allowing an attacker to claim and manipulate funds
## Vulnerability details 

The vulnerability is in the _deposit function, this function  is called by depositWithExpiry. And there is an absence of validation on vault address. 
This deficiency allows an attacker to specify any address as a vault, and potentially including an address under their control. As a result, the attacker can manipulate the deposits and the allowances, leading to unauthorized transfers of ERC20 tokens or ETH from the Router to an attacker controlled address.
- here is the Vulnerable Function:
```solidity

function depositWithExpiry(
    address payable vault,
    address asset,
    uint amount,
    string memory memo,
    uint expiration
) external payable {
    require(block.timestamp < expiration, "THORChain_Router: expired");
    _deposit(vault, asset, amount, memo);
}

```

```solidity 

function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth");
        safeAmount = safeTransferFrom(asset, amount);
        _vaultAllowance[vault][asset] += safeAmount;
    }
    emit Deposit(vault, asset, safeAmount, memo);
}

```

## Impact

An attacker can redirect deposits to addresses they control, allowing unauthorized withdrawal of funds

## Proof of Concept
As scenario of attack : 
- An attacker can deploys a contract that control and specifies it as the vault in the depositWithExpiry function.
- Then calls the depositWithExpiry with the malicious vault address and an asset or ETH.
- The _vaultAllowance mapping is updated for the attacker's vault address.
- as result the  attacker can now use functions like transferOut to withdraw funds from the Router, and  exploiting the inflated allowance.

    function testUnauthorizedVaultAddress() public {

        router.depositWithExpiry{value: amount}(payable(maliciousVault), address(0), amount, memo, expiration);

        uint allowance = router.vaultAllowance(maliciousVault, address(0));

        // Further assertions can be added to check the unauthorized withdrawal, etc.
    }

contract MaliciousVault {

contract ERC20Token {
    mapping(address => uint256) private _balances;

    constructor() {
        _balances[msg.sender] = 1000 ether;
    }

    function balanceOf(address account) public view returns (uint256) {
        return _balances[account];

        _balances[from] -= amount;
