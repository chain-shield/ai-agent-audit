# Vulnerability details

The `transferOut` function allow users to transfer assets to any recipient. However the function checks that if asset is ETH then trasfer asset via `send` method to any receiver. So the problem is here that if receiver is any contract and cause `send()` only forwards 2300 gas, which is not enough for the contract recipient to execute any non-trivial logic in a receive() or fallback function.

Now if a user calls `transferOut()` and passes recipient as a contract account like a multisig or smart contract wallet that has a receive() function requiring >2300 gas, then these transferred assets will just back to that caller.


## Impact
Assets cannot be transfered to the contract recipient.

## Recommended Mitigation Steps
Use call() instead of send() to send ETH in `transferOut()`:

```diff
-     bool success = to.send(safeAmount); // Send ETH.
+     (bool success, ) = to.call{value: safeAmount}("");

```
