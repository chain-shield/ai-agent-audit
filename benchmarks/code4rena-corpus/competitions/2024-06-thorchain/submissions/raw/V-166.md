# Vulnerability details

### Summary

The vulnerability lies in the usage of `transfer()` and `send()` functions for value transfers within the contract code. These functions forward a fixed amount of gas (2300 gas), which can lead to unexpected behavior due to changes in gas costs during hard forks or variations across different chains. The usage of these functions with `aggregationPayload.target`, which is a contract, introduces potential risks. 

### Proof of concept

The `transfer()` and `send()` functions are traditionally recommended for value transfers to prevent reentrancy attacks. However, their fixed gas assumptions can become problematic during hard forks, such as the case with EIP 1884, which increased the cost of the SLOAD instruction and caused smart contracts relying on fixed gas assumptions to break. Moreover, using `transfer()` and `send()` with `aggregationPayload.target`, which is a contract, could potentially introduce vulnerabilities.

```solidity
bool sendSuccess = payable(aggregationPayload.target).send(msg.value)
```

### Impact

This vulnerability presents a risk as it could lead to contract malfunction or failure if not addressed. Changes in gas costs and contract usage patterns may result in unexpected behavior, including failure of value transfers or exploitation by malicious actors.

### Tools Used

Manual review

### Recommendation Mitigation Steps

To mitigate this issue, it is advised to replace `transfer()` and `send()` functions with `call()` for value transfers. Using `call()` provides greater flexibility and resilience to changes in gas costs and contract usage patterns.
