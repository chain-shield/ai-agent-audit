# Vulnerability details

### Summary

The function `THORChain_Router::transferOutAndCallV5` calls `THORChain_Router::_transferOutAndCallV5`. However, during an ether transfer, it does not assert that `msg.value` is the same as the `amount`.

### Proof of concept

The `THORChain_Router::TransferOutAndCallData` struct is passed as a parameter to `THORChain_Router::_transferOutAndCallV5`, and the `fromAmount` variable is part of this struct. This `fromAmount` is used as the swap amount. If the swap involves ether and another token, the `fromAmount` is not asserted to be equal to `msg.value`. This can lead to two potential issues:

1. If `msg.value` is more than `fromAmount`, the excess ether (`msg.value - fromAmount`) will be stuck in the contract.
2. If `msg.value` is less than `fromAmount`, the swap could fail, potentially leading to unexpected behaviour.

### Impact

The lack of assertion for `msg.value` to equal `fromAmount` can result in ether being locked in the contract, making it inaccessible. Additionally, it may cause swap operations to fail, which can disrupt the expected contract behaviour and affect users' transactions.

### Recommendation Mitigation Step

I recommend adding the following line of code in `THORChain_Router::transferOutAndCallV5` to prevent these issues:

```diff
function transferOutAndCallV5(TransferOutAndCallData calldata aggregationPayload
) external payable nonReentrant {

+       require(msg.value == aggregationPayload.fromAmount, "Msg.value is not equal to fromAmount"); 
        _transferOutAndCallV5(aggregationPayload);

}
```
