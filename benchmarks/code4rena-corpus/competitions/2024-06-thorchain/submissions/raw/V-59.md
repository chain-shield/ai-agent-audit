# Vulnerability details

The transferOut functions are supposse to be called by the thor vaults when a user call the `depositWithExpiry` function. 

This functions are  expected to be called by the thor vaults but those function are permissionless.

with that been say, See:
```solidity
 function _transferOutV5(TransferOutData memory transferOutPayload) private {
    if (transferOutPayload.asset == address(0)) {
      bool success = transferOutPayload.to.send(transferOutPayload.amount); // Send ETH. <-----
      if (!success) {
        payable(address(msg.sender)).transfer(transferOutPayload.amount); // For failure, bounce back to vault & continue.
      }
    } else {...}
...
}
```
[[Link]](https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/chain/ethereum/contracts/THORChain_Router.sol#L209C2-L215C13)

The problem is that the in _transferOutV5 function the value used for the `send` or `transfer` is a input value. so in case that the router has some eth, those eth can be completely draining just passing the amount and the receiver.

This is not the case for the old version which is used the same msg.value forwarde with the function call.

```solidity
  function transferOut(
    address payable to,
    address asset,
    uint amount,
    string memory memo
  ) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
      safeAmount = msg.value;
      bool success = to.send(safeAmount); // Send ETH.
      if (!success) {
        payable(address(msg.sender)).transfer(safeAmount); // For failure, bounce back to vault & continue.
      } else {...}
...
```
[[Link]](https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/chain/ethereum/contracts/THORChain_Router.sol#L185C1-L197C8)

Note that the router contract is not intended to hold any ether. but in case that this contract get ethers it can be completely drained instantly

## Impact
The router contract can be drained.
