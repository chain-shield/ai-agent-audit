# Vulnerability details

## Impact
A malicious vault admin can call the transferAllowance function and transfer the vault allowance to an invalid address, causing a permanent loss of funds. This is particularly concerning in a protocol where no role is trusted(as stated in the contest page)

## Proof of Concept
The relevant part of the code is as follows:
```
function transferAllowance(
    address router,
    address newVault,
    address asset,
    uint amount,
    string memory memo
) external nonReentrant {
    if (router == address(this)) {
        _adjustAllowances(newVault, asset, amount);
        emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
    } else {
        _routerDeposit(router, newVault, asset, amount, memo);
    }
}
```
A malicious admin can call this function and specify an invalid newVault address, causing the funds to be transferred to an address where they cannot be recovered.

## Tools Used
Manual

## Recommended Mitigation Steps
Implement validation checks to ensure that the newVault address is valid and authorized.
