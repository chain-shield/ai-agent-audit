# Vulnerability details

## Impact
The `THORChain_Router::depositWithExpiry()` is used to deposit asset to vault. The parameter `expiration` is used to provide a timestamp along the transaction at which point to revert the transaction if it takes too long while depositing. The problem occurs at `THORChain_Router::_routerDeposit()` when calling the `depositWithExpiry()` we set the expiration timestamp to be `type(uint).max` which means transaction can stay at the mempool to a close infinite timestamp not reverting the transaction at an expiration timestamp basically breaking the intended behavior of the function `depositWithExpiry()`.

## Proof of Concept
Using the function [THORChain_Router::transferAllowance()](https://github.com/code-423n4/2024-06-thorchain/blob/main/chain/ethereum/contracts/THORChain_Router.sol#L165) we call the `_routerDeposit()` function if `router != address(this)` here:

```solidity
  function transferAllowance(
    address router,
    address newVault,
    address asset,
    uint amount,
    string memory memo
  ) external nonReentrant {
    if (router == address(this)) {
      _adjustAllowances(newVault, asset, amount);

      emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
    } else {
@>     _routerDeposit(router, newVault, asset, amount, memo);
    }
  }

```
After decreasing the `_vaultAllowance` of `msg.sender` [THORChain_Router::_routerDeposit()](https://github.com/code-423n4/2024-06-thorchain/blob/main/chain/ethereum/contracts/THORChain_Router.sol#L476) function proceeds to deposit the amount with the function `depositWithExpiry()` but as we can see the expiration time is set to be `type(uint).max` instead of user defined timestamp.

```solidity
  function _routerDeposit(
    address _router,
    address _vault,
    address _asset,
    uint _amount,
    string memory _memo
  ) internal {
    _vaultAllowance[msg.sender][_asset] -= _amount;
    safeApprove(_asset, _router, _amount);

    iROUTER(_router).depositWithExpiry(
      _vault,
      _asset,
      _amount,
      _memo,
@>    type(uint).max
    ); // Transfer by depositing
    // @audit while transferring the deposit, user can't set the expiry
  }
```
