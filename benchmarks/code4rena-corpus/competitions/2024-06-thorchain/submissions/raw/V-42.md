# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The depositWithExpiry function is callable by anyone due to the absence of a modifier restricting access. This vulnerability can lead to unauthorised deposits being made on behalf of the contract, potentially causing unexpected behaviours and financial loss.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

The depositWithExpiry function in the THORChain_Router contract does not include any access control mechanisms, making it possible for any external actor to call this function. Here is the relevant code snippet:

```sol
interface iROUTER {
  function depositWithExpiry(
    address,
    address,
    uint,
    string calldata,
    uint
  ) external;
}
```

In the THORChain_Router contract, the depositWithExpiry function can be called without any restrictions:
```sol
  function depositWithExpiry(
    address payable vault,
    address asset,
    uint amount,
    string memory memo,
    uint expiration
  ) external payable {
    require(block.timestamp < expiration, "THORChain_Router: expired");
    _deposit(vault, asset, amount, memo);
  }
```

Because there is no access control modifier, any user can call this function and execute deposits, potentially draining funds or disrupting the intended functionality. POC follows.

        mockERC20 = new MockERC20();
        mockRouter = new MockRouter();

        // Mint some tokens for testing
        mockERC20.mint(address(this), 1000);
    }


    function testDepositWithExpiry() public {
        // Check initial balance
        uint256 amount = 500;
        address asset = address(mockERC20);
        string memory memo = "Test deposit";
        uint256 expiry = block.timestamp + 1 hours;

        // Expect the deposit event
        vm.expectEmit(true, true, false, true);
        emit MockRouter.Deposit(address(this), asset, amount, memo);

        // Make the deposit
        vm.startPrank(address(0xbEEF));
        mockRouter.depositWithExpiry(address(this), asset, amount, memo, expiry);
        vm.stopPrank();
    }

}

## Recommended Mitigation Steps

To prevent unauthorised access, it is crucial to implement access control modifiers such as onlyOwner or custom access control logic. Here is an example of how to mitigate this issue:

Define an access control modifier:
```sol
modifier onlyOwner() {
    require(msg.sender == owner, "Caller is not the owner");
    _;
}
```
Apply the modifier to the depositWithExpiry function:
```sol
function depositWithExpiry(
    address _to,
    address _asset,
    uint _amount,
    string calldata _memo,
    uint _expiry
) external onlyOwner {
    // function logic
}
```
