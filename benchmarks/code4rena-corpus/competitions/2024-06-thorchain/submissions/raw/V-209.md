# Vulnerability details

## Impact
User-defined expiry settings that are too short can cause the `depositWithExpiry` function to revert due to network delays or miner manipulation of `block.timestamp`. This can lead to failed deposits, causing inconvenience and user frustration.

## Proof of Concept
The `depositWithExpiry` function currently allows users to set any expiry time. If the expiry time is set too close to the current block timestamp, network delays or miner manipulation can cause the transaction to revert.

### LoC

```solidity
function depositWithExpiry(address payable vault, address asset, uint amount, string memory memo, uint expiration) external payable {
    require(block.timestamp < expiration, "THORChain_Router: expired");
    deposit(vault, asset, amount, memo);
}
```

## Tools Used
Manual


## Recommended Mitigation Steps
Enforce a minimum default expiry time to ensure there is sufficient time for the transaction to be included in a block, even with potential network delays or miner manipulation.

```solidity
uint256 private constant MIN_EXPIRY_TIME = 300; // Minimum expiry time in seconds (e.g., 5 minutes)

function depositWithExpiry(address payable vault, address asset, uint amount, string memory memo, uint expiration) external payable {
    require(block.timestamp + MIN_EXPIRY_TIME < expiration, "THORChain_Router: expiry time too short");
    deposit(vault, asset, amount, memo);
}
```
