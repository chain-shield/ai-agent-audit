# Vulnerability details

## Impact
Deadline parameter set to `type(uint256).max` in `_routerDeposit()` allows for unfavorable terms

## Proof of Concept
Upon calling `transferAllowance()` with the goal of changing the router completely, then `_routerDeposit()` is called which calls `depositWithExpiry()` with `type(uint256).max` as the deadline parameter. This allows for the router to receive very unfavorable terms if the transaction is delayed.
```solidity
function transferAllowance(
    address router,
    address newVault,
    address asset,
    uint amount,
    string memory memo
  ) external nonReentrant {
    if (router == address(this)) {
      _adjustAllowances(newVault, asset, amount);
      emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
    } else {
      _routerDeposit(router, newVault, asset, amount, memo);
    }
  }
```
```solidity
function _routerDeposit(
    address _router,
    address _vault,
    address _asset,
    uint _amount,
    string memory _memo
  ) internal {
    _vaultAllowance[msg.sender][_asset] -= _amount;
    safeApprove(_asset, _router, _amount);

    iROUTER(_router).depositWithExpiry(
      _vault,
      _asset,
      _amount,
      _memo,
      type(uint).max
    );
  }
```
