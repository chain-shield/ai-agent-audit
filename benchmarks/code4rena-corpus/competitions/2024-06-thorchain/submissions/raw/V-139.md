# Vulnerability details

## Impact

The `expiration` variable in `depositWithExpiry` is used to ensure that no one will deposit in an expired THORChain_Router. 

However, if a user want to transfer funds to another router, the underlying code calls `depositWithExpiry` but sets the  `expiration` variable to type(uint).max, thereby fully invalidating the require check.

This can allow for cases where users end up moving funds in expired routers and losing/locking the funds.  

## Proof of Concept

In `depositWithExpiry`, a user is obliged to use an expiration variable to make sure he does not move funds into an expired router.
```solidity
  // Deposit with Expiry (preferred)
  function depositWithExpiry(
    address payable vault,
    address asset,
    uint amount,
    string memory memo,
    uint expiration
  ) external payable {
    require(block.timestamp < expiration, "THORChain_Router: expired");
    _deposit(vault, asset, amount, memo);
  }
```
Yet, when the user calls `transferAllowance`, `_routerDeposit` is called which, in turn, calls `depositWithExpiry`
   
```solidity
  function transferAllowance(
    address router,
    address newVault,
    address asset,
    uint amount,
    string memory memo
  ) external nonReentrant {
    if (router == address(this)) {
      _adjustAllowances(newVault, asset, amount);
      emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
    } else {
      _routerDeposit(router, newVault, asset, amount, memo);
    }
  }
```
```solidity
  // Adjust allowance and forwards funds to new router, credits allowance to desired vault
  function _routerDeposit(
    address _router,
    address _vault,
    address _asset,
    uint _amount,
    string memory _memo
  ) internal {
    _vaultAllowance[msg.sender][_asset] -= _amount;
    safeApprove(_asset, _router, _amount);


    iROUTER(_router).depositWithExpiry(
      _vault,
      _asset,
      _amount,
      _memo,
      type(uint).max << can never expire?
    ); // Transfer by depositing
  }
```
Thereby assuming the router cannot be expired. Which is clearly wrong.
