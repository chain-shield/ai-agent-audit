# Vulnerability details

## Root of the bug 
The bug is the sequence of operations within the _transferOutAndCallV5 function, where the allowance is reduced before confirming the success of the ERC20 token transfer.
and this preemptive reduction does not account for the possibility of transfer failure, which can result in an allowance that does not accurately reflect the vault's actual balance.
here is where the Allowance Reduction :
```solidity
_vaultAllowance[msg.sender][aggregationPayload.fromAsset] -= aggregationPayload.fromAmount;
```
- and here The function attempts to transfer the ERC20 tokens but does not ensure that the transfer is successful before adjusting the allowanceThe function attempts to transfer the ERC20 tokens but does not ensure that the transfer is successful before adjusting the allowance
```solidity
(bool transferSuccess, bytes memory data) = aggregationPayload.fromAsset.call(
    abi.encodeWithSignature("transfer(address,uint256)", aggregationPayload.target, aggregationPayload.fromAmount)
);

```
- and here If the transfer fails, the transaction is reverted, but the allowance has already been decremented, leading to an inaccurate allowance.

```solidity 
require(transferSuccess && (data.length == 0 || abi.decode(data, (bool))), "Failed to transfer token before dex agg call");

```
## Impact
Malicious users Can exploit this to reduce allowances and prevent valid transfers, leading to potential denial of service.
## Proof of Concept
as Scenario : 
- let's say we have 
Vault Address: 0xVault
ERC20 Token: 0xToken
Initial Allowance: 1000 tokens
Token Balance in Vault: 300 tokens
- and user is Attempt to transfer 500 tokens using the _transferOutAndCallV5 function as follow :
```solidity
// Transfer 500 tokens from the vault
_transferOutAndCallV5(
    TransferOutAndCallData({
        target: 0xTarget,
        fromAsset: 0xToken,
        fromAmount: 500,
        toAsset: 0xToken,
        recipient: 0xRecipient,
        amountOutMin: 450,
        memo: "transfer",
        payload: "0x",
        originAddress: "0xOrigin"
    })
);
```
- now the New Allowance is  500 tokens (reduced from 1000).
- as result he transfer fails due to insufficient balance (only 300 tokens available).
- The actual allowance is inaccurately recorded as 500 tokens, even though no tokens were transferred.
- and The vault’s allowance is reduced by 500 tokens despite the transfer failure, leaving an incorrect allowance that does not reflect the actual token state.
here is a test 
```solidity
// SPDX-License-Identifier: MIT
pragma solidity 0.8.22;

import "forge-std/Test.sol";
import "../THORChain_Router.sol";
import "../MockERC20.sol";

contract THORChainRouterTest is Test {
    THORChain_Router private router;
    MockERC20 private token;

    address private vault = address(0x1234);
    address private target = address(0x5678);

    function setUp() public {
        router = new THORChain_Router();
        token = new MockERC20("TestToken", "TST", 18, 1000 ether);

        // Mint tokens to the vault address
        token.mint(vault, 1000 ether);
    }

    function testTransferOutAndCall() public {
        uint256 initialVaultAllowance = 1000 ether;
        uint256 transferAmount = 500 ether;

        // Set the initial allowance
        router._adjustAllowances(vault, address(token), initialVaultAllowance);

        // Check initial allowance
        uint256 allowanceBefore = router.vaultAllowance(vault, address(token));
        assertEq(allowanceBefore, initialVaultAllowance);

        // Call the transferOutAndCallV5 function
        router.transferOutAndCallV5(
            THORChain_Router.TransferOutAndCallData({
                target: payable(target),
                fromAsset: address(token),
                fromAmount: transferAmount,
                toAsset: address(token),
                recipient: address(this),
                amountOutMin: transferAmount,
                memo: "Test Transfer",
                payload: "",
                originAddress: ""
            })
        );

        // Check allowance after transfer
        uint256 allowanceAfter = router.vaultAllowance(vault, address(token));
        assertEq(allowanceAfter, initialVaultAllowance - transferAmount);

        // Check balance of target to confirm transfer
        uint256 targetBalance = token.balanceOf(target);
        assertEq(targetBalance, transferAmount);

        // Check remaining token balance in the vault
        uint256 vaultBalance = token.balanceOf(vault);
        assertEq(vaultBalance, initialVaultAllowance - transferAmount);
    }
}

```
