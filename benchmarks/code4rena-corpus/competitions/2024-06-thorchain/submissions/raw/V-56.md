# Vulnerability details

## Impact
Disclaimer: this report is succinct, because I am not using ChatGPT to write it.
When Fraud actor tries to call `transferOutV5` and `batchTransferOutV5` functions with incorrect `transferOutPayload.amount` and native currency `transferOutPayload.asset` actor can drain contract by settings all contact ETH amount - gas fee 

Similar idea goes  `batchTransferOutAndCallV5`. But the vulnerability is different -  fraud actor let's sat can send 1 wei and array with 10 items. And contract with send msg.value * items.length.
POC attached with 2 tests that shows incorrect value behaviour.

## Recommended Mitigation Steps
Add validation that msg.value is <= transferOutPayload.amount

```
    function transferOutV5(
        TransferOutData calldata transferOutPayload
    ) public payable nonReentrant {
        require(
            msg.value <= transferOutPayload.amount,
            "msg.value exceeds transfer amount"
        );
        _transferOutV5(transferOutPayload);
    }

    // bifrost to budget gas limits, no more than 50% than L1 gas limit
    function batchTransferOutV5(
        TransferOutData[] calldata transferOutPayload
    ) external payable nonReentrant {
        uint totalAmount = 0;
        for (uint i = 0; i < transferOutPayload.length; ++i) {
            totalAmount += transferOutPayload[i].amount;
            _transferOutV5(transferOutPayload[i]);
        }
        require(
            msg.value >= totalAmount,
            "Insufficient msg.value for transfer amounts"
        );
    }

  function batchTransferOutAndCallV5(
    TransferOutAndCallData[] calldata aggregationPayloads
  ) external payable nonReentrant {
    uint totalAmount = 0;
    for (uint i = 0; i < aggregationPayloads.length; ++i) {
        totalAmount += transferOutPayload[i].fromAmount;
      _transferOutAndCallV5(aggregationPayloads[i]); //@audit amount can be different
    }
    require(msg.value >= totalAmount, "Insufficient msg.value for transfer amounts");
  }
  
```
