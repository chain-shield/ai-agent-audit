# Vulnerability details

## Impact
The `_deposit` function in the contract uses the `send()` function to transfer Ether (ETH) to a specified vault address. If the receiving contract requires more gas to execute its logic, the transaction will fail, causing a Denial of Service (DoS) vulnerability.

## Proof of Concept
Using send() to transfer ETH poses a risk because it only forwards 2300 gas to the recipient, which may not be sufficient for the recipient's operations. This can cause the transaction to fail if the receiving contract has logic that requires more gas. Consequently, this introduces a potential DoS vulnerability where users may be unable to deposit ETH into the vault if the vault contract requires more than 2300 gas to process the deposit.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Replace `send()` with `call()` which is allowing us to forward unlimited gas or a specific amount that we choose 
```java
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;

    // Handling Ether (ETH) Deposits
    if (asset == address(0)) {
        safeAmount = msg.value;

        // Use call() instead of send() to forward all available gas
        (bool success, ) = vault.call{value: safeAmount}("");
        require(success, "ETH transfer failed");
    } else {
        // Handling Token Deposits
        require(msg.value == 0, "unexpected eth"); // Protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        _vaultAllowance[vault][asset] += safeAmount; // Credit to chosen vault
    }

    // Emit Deposit Event
    emit Deposit(vault, asset, safeAmount, memo);
}

```
