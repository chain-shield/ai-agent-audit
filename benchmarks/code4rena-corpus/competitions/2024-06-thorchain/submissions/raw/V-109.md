# Vulnerability details

## Description

The `THORChain_Router.sol` serves as both the entry and exit point for EVM-based gas assets and ERC20 tokens. Users deposit assets using the router's depositWithExpiry function. The Router contract holds the network’s ERC20 tokens and manages allowances for each active vault, while gas assets are forwarded to and from the contract and the active vaults.
Users call `depositWithExpiry()` to deposit assets into the network, and the Router contract forwards the assets to the active vaults. THORChain vault will call the `transferOut()` function to sends gas assets or ERC20s to fulfill an EVM outbound.

However, `send()` only forwards 2300 gas, which is not enough for the recipient to execute any non-trivial logic in a receive() or fallback function. For instance, it is not enough for Safes (such as [this one](https://etherscan.io/address/0xd1e6626310fd54eceb5b9a51da2ec329d6d4b68a)) to receive funds, which require > 6k gas for the call to reach the implementation contract and emit an event.

If a `transferOut()` from a contract account like a multisig or smart contract wallet that has a receive() function requiring >2300 gas, their subsequent claim() call will fail permanently. The withdrawn ETH will be locked in the WithdrawQueue contract forever, leading to loss of funds.

## Impact

When a `transferOut()` function is called with a gas asset to a contract account like a multisig or smart contract wallet that has a `receive()` function requiring >2300 gas, their subsequent `transferOut` call will fail permanently. The withdrawn ETH will be locked in the ThorChain Vault contract forever, leading to loss of funds.

## Proof Of Concept

1. Multisig contract deposits ETH to the vault using `depositWithExpiry()` function.
2. THORChain's validators monitor the emitted events from this function to determine the appropriate actions, such as swaps, savings, or loan initiation.
3. ThorChain vault sends ETH to a multisig contract using the `transferOut()` function.
4. The multisig contract fails to receive the ETH due to `send()` gas constraints, causing the ETH to be locked in the ThorChain Vault contract.

Here is commands to run the POC:

```bash
forge test --mt test_VaultCannotSendEthToMultiSigs -vvvv
```

## Recommendation

We recommend that the ThorChain team update the `transferOut()` function to handle the case where the recipient contract requires more than 2300 gas to execute its receive() function. This can be done by using the `call()` function with a gas stipend of 2300 gas or more.

Here is the recommended mitigation:
