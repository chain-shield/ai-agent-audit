# Vulnerability details

## Impact
ETH can get Locked forever in the THORchain Router contract if `transferOutPayload.amount` is less than the msg.value sent.
Also another user can take use of this balance by specifying `transferOutPayload.amount` greater than his deserved balance.

## Proof of Concept
The vulnerability lies in `_transferOutV5(TransferOutData)` function where `transferOutPayload` is passed as an input parameter.
`transferOutPayload` is a struct which contains `amount` specified by the caller and will send the amount to the `to` address.

https://github.com/code-423n4/2024-06-thorchain/blob/e3fd3c75ff994dce50d6eb66eb290d467bd494f5/ethereum/contracts/THORChain_Router.sol#L209-L229
```solidity
function _transferOutV5(TransferOutData memory transferOutPayload) private {
    if (transferOutPayload.asset == address(0)) {
      bool success = transferOutPayload.to.send(transferOutPayload.amount); // Send ETH. 
      if (!success) {
        payable(address(msg.sender)).transfer(transferOutPayload.amount); // For failure, bounce back to vault & continue.
      }
      ...
    }
}```
this private function is called `transferOutV5`

```solidity
function transferOutV5(
    TransferOutData calldata transferOutPayload
  ) public payable nonReentrant {
    _transferOutV5(transferOutPayload);  
  }
```

If the `amount` passed is less than the msg.value (actual ether caller has sent) it can cause the ETH to be locked forever in the Router since it doesnt have a withdraw function.


## Tools Used
Manual review.

## Recommended Mitigation Steps
Need a proper check to find msg.value == transferOutPayload.amount or
revert if  balance of router is not 0 at the end of the execution.
