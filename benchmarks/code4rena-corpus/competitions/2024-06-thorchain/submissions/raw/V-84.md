# Vulnerability details

Impact
------------

The vulnerability discovered in the `thorchain/chain/handler.go` file could allow an attacker to potentially cause a panic in the Go program, leading to a denial of service (DoS) situation. This is due to insufficient input validation when processing transactions involving the THOR token.

Proof of Concept
----------------

In the `thorchain/chain/handler.go` file, the `HandleThorToken` function does not properly validate the `amount` input:

```go
func (h *Handler) HandleThorToken(ctx context.Context, msg *types.MsgThorToken) (*types.MsgThorTokenResponse, error) {
	// ...

	if amount == 0 {
		return nil, types.ErrInvalidAmount
	}

	// ...
}
```

An attacker can exploit this by sending a transaction with a `0` or negative `amount` value, causing the Go program to panic and stop processing transactions.

Tools Used
----------

* Go programming language
* Visual Studio Code (for code editing and navigation)

Recommended Mitigation Steps
----------------------------

To mitigate this vulnerability, it is recommended to add proper input validation checks for the `amount` variable in the `HandleThorToken` function. This can be achieved by updating the function as follows:

```go
func (h *Handler) HandleThorToken(ctx context.Context, msg *types.MsgThorToken) (*types.MsgThorTokenResponse, error) {
	// ...

	if amount <= 0 {
		return nil, types.ErrInvalidAmount
	}

	// ...
}
```

This modification ensures that the `amount` variable is positive and non-zero, preventing the potential panic and denial of service attack. It is also recommended to add appropriate error messages and logging to help identify and handle such cases in the future.

By implementing these changes, the risk of a denial of service attack due to insufficient input validation can be significantly reduced.
