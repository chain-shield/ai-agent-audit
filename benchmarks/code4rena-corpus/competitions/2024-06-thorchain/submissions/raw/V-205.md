# Vulnerability details

## Impact
Allowing an authorized party to set or use max/infinite allowances poses a significant security risk. A malicious authorized party could exploit these allowances to drain the user's tokens without their explicit consent, leading to potential loss of funds.

## Proof of Concept
In the `THORChain_Router` contract, the `_routerDeposit` function allows setting max allowances, which can be exploited.

### Lines of Code

```solidity
function _routerDeposit(address _router, address _vault, address _asset, uint _amount, string memory _memo) internal {
    _vaultAllowance[msg.sender][_asset] -= _amount;
    (bool success,) = _asset.call(abi.encodeWithSignature("approve(address,uint256)", _router, _amount)); // Approve to transfer
    require(success);
    iROUTER(_router).depositWithExpiry(_vault, _asset, _amount, _memo, type(uint).max); // Transfer by depositing
}
```
