# Vulnerability details

## Description

In the `THORChain_Router.sol` contract, the `transferOut()` function is used to facilitate the transfer of funds from a sender to a receiver. This function is payable, meaning the sender must send some ETH as msg.value when calling it. There are two scenarios to consider:

1. If the asset parameter is equal to the zero address, the msg.value is transferred from the sender to the receiver.
2. If the asset parameter is not equal to the zero address, the specified amount is transferred from the sender to the receiver.

## Impact

A potential issue arises when the sender mistakenly passes a non-zero address as the asset parameter and simultaneously sends ETH as msg.value because the function is payable. In this case, there is no mechanism to return the ETH sent as msg.value, leading to the sender's extra ETH being locked in the contract indefinitely.

## Code Snippet

```javascript
function transferOut(address payable to,address asset,uint amount,string memory memo ) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
      safeAmount = msg.value;
      bool success = to.send(safeAmount); // Send ETH.
      if (!success) {
        safeAmount = 0;
        payable(address(msg.sender)).transfer(msg.value); // For failure, bounce back to vault & continue.
    }
    } else {
      _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
```
