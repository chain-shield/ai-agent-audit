# Vulnerability details

## Impact
In the `transferOut` function again. The function allows transferring ETH directly using `msg.value`, but for ERC20 tokens, it does not properly check if `msg.sender` has a sufficient allowance in the `_vaultAllowance` mapping before performing the transfer. [chain/ethereum/contracts/THORChain_Router.sol#L199-205](https://github.com/code-423n4/2024-06-thorchain/blob/e5ae503d0dc2394a82242be6860eb538345152a1/chain/ethereum/contracts/THORChain_Router.sol#L199-L205)
```solidity
} else {
  _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
  (bool success, bytes memory data) = asset.call(
    abi.encodeWithSignature("transfer(address,uint256)", to, amount)
  );
  require(success && (data.length == 0 || abi.decode(data, (bool))));
  safeAmount = amount;
}
```
The issue is that the code directly subtracts the `amount` from the `_vaultAllowance` mapping without first checking if `msg.sender` has a sufficient allowance. This means that even if `msg.sender` doesn't have enough allowance, the transfer will still be executed, and the allowance will become negative.

## Proof of Concept
In the referenced code, the `_vaultAllowance` mapping is directly updated by subtracting the amount without first checking if `msg.sender` has a sufficient allowance. This allows unauthorized transfers and leads to negative allowance balances.
```solidity
} else {
  _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
  (bool success, bytes memory data) = asset.call(
    abi.encodeWithSignature("transfer(address,uint256)", to, amount)
  );
  require(success && (data.length == 0 || abi.decode(data, (bool))));
  safeAmount = amount;
}
```
It allows unauthorized transfers of ERC20 tokens from the THORChain_Router contract. The `transferOut` function is intended to allow vaults to transfer assets (ETH or ERC20 tokens) to a specified recipient, up to the `amount` of allowance they have been granted. However, the current implementation has a flaw that enables vaults to transfer ERC20 tokens even if they don't have sufficient allowance.

_Unauthorized ERC20 token transfers._ as it allows any vault (identified by `msg.sender`) to transfer ERC20 tokens from the `THORChain_Router` contract to a specified recipient.
However, the function does not check if the vault has a sufficient allowance for the ERC20 token before executing the transfer.
This means that a vault can transfer ERC20 tokens even if their allowance is less than the transfer amount or if they have no allowance at all.

## Recommended Mitigation Steps
Should add a check to ensure that `msg.sender` has a sufficient allowance before performing the transfer and updating the allowance. By adding the `require` statement to check if `_vaultAllowance[msg.sender][asset]` is greater than or equal to the `amount`, it ensures that the transfer is only executed if `msg.sender` has a sufficient allowance for the ERC20 token.
```solidity
} else {
  require(_vaultAllowance[msg.sender][asset] >= amount, "Insufficient allowance");
  _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance
  (bool success, bytes memory data) = asset.call(
    abi.encodeWithSignature("transfer(address,uint256)", to, amount)
  );
  require(success && (data.length == 0 || abi.decode(data, (bool))));
  safeAmount = amount;
}
```
