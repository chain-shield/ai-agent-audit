# Vulnerability details

## Impact
The `transferOut` function should only update the `_vaultAllowance` mapping if the ERC20 transfer was successful. Currently, the allowance is decremented before the transfer is attempted, which could lead to inconsistencies if the transfer fails. This bug can lead to inconsistencies in the `_vaultAllowance` mapping. Specifically, if the ERC20 transfer fails, the allowance is still decremented, which means that the vault's allowance is reduced even though the transfer did not occur.

## Proof of Concept
Referenced Code: [@>/THORChain_Router.sol(transferOut)](https://github.com/code-423n4/2024-06-thorchain/blob/e5ae503d0dc2394a82242be6860eb538345152a1/chain/ethereum/contracts/THORChain_Router.sol#L143-L160)
```solidity
function transferOut(
    address payable to,
    address asset,
    uint amount,
    string memory memo
) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = to.send(safeAmount); // Send ETH.
        if (!success) {
            payable(address(msg.sender)).transfer(safeAmount); // For failure, bounce back to vault & continue.
        }
    } else {
        _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance before transfer
        (bool success, bytes memory data) = asset.call(
            abi.encodeWithSignature("transfer(address,uint256)", to, amount)
        );
        require(success && (data.length == 0 || abi.decode(data, (bool))));
        safeAmount = amount;
    }
    emit TransferOut(msg.sender, to, asset, safeAmount, memo);
}
```
To illustrate the impact of the bug, consider the following scenario:

  1. The vault has an allowance of 100 tokens for a specific ERC20 asset.
  2. The transferOut function is called to transfer 50 tokens to a recipient.
  3. The ERC20 transfer fails for some reason (e.g., insufficient balance, transfer restrictions).
  4. Despite the transfer failure, the _vaultAllowance is decremented by 50 tokens.
  5. The vault now incorrectly believes it has an allowance of 50 tokens, even though no transfer occurred.

We can see this scenario demonstrated with the following test case.
```solidity
function testTransferOutFailure() public {
    // Set up initial allowance
    _vaultAllowance[msg.sender][address(erc20)] = 100;

    // Attempt to transfer 50 tokens (this transfer will fail)
    try this.transferOut(payable(address(0xE930927711C6Dd0e2f0Cab8ef4036121BeF4dc45)), address(erc20), 50, "Test Memo") {
        // This should not be reached
        assert(false);
    } catch {
        // Check that the allowance has not been decremented
        assert(_vaultAllowance[msg.sender][address(erc20)] == 100);
    }
}
```
The transfer is expected to fail, and the allowance should remain unchanged at 100 tokens. If the bug is present, the allowance would incorrectly be reduced to 50 tokens, demonstrating the inconsistency.

## Recommended Mitigation Steps
It should be corrected like the `_vaultAllowance` mapping is only updated after the ERC20 transfer is confirmed to be successful. This ensures that the allowance is only decremented if the transfer occurs, maintaining consistency in the contract's state.
```solidity
function transferOut(
    address payable to,
    address asset,
    uint amount,
    string memory memo
) public payable nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = to.send(safeAmount); // Send ETH.
        if (!success) {
            payable(address(msg.sender)).transfer(safeAmount); // For failure, bounce back to vault & continue.
        }
    } else {
        (bool success, bytes memory data) = asset.call(
            abi.encodeWithSignature("transfer(address,uint256)", to, amount)
        );
        require(success && (data.length == 0 || abi.decode(data, (bool))), "ERC20 transfer failed");
        _vaultAllowance[msg.sender][asset] -= amount; // Reduce allowance only if transfer is successful
        safeAmount = amount;
    }
    emit TransferOut(msg.sender, to, asset, safeAmount, memo);
}
```
