# Vulnerability details

## Impact
The old `THORChain_Router` contract will continue to have ERC20 token approvals, even allowances and funds forwarded to the new router, so it can continue to spend the tokens when this is not the protocol's intention.

## Proof of Concept
The function `transferAllowance()` calls the internal `_routerDeposit()` function when the `router` parameter is not `address(this)`.
```solidity
  function transferAllowance(
    address router,
    address newVault,
    address asset,
    uint amount,
    string memory memo
  ) external nonReentrant {
    if (router == address(this)) {
      _adjustAllowances(newVault, asset, amount);
      emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
    } else {
      _routerDeposit(router, newVault, asset, amount, memo);
    }
  }

```

The `_routerDeposit()` function only removes the allowance of the vault and asset, not the router. Then, it adjusts allowances and forwards funds to the new router without removing the ERC20 token allowances of the old router.
```solidity
  function _routerDeposit(
    address _router,
    address _vault,
    address _asset,
    uint _amount,
    string memory _memo
  ) internal {
    _vaultAllowance[msg.sender][_asset] -= _amount;
    safeApprove(_asset, _router, _amount);

    iROUTER(_router).depositWithExpiry(
      _vault,
      _asset,
      _amount,
      _memo,
      type(uint).max
    ); // Transfer by depositing
  }
```
