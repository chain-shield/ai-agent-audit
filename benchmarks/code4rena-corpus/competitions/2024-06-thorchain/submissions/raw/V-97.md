# Vulnerability details

## Impact
The contract currently allows deposits with very small or zero amounts, which can result in inflated event logs without significant economic activity. Specifically, the `Deposit` event is crucial because when it is emitted, Bifrost will observe and post a `MsgObservedTxIn` transaction to THORChain to initiate the action. Allowing zero-value deposits can lead to:

1. Users could make deposits of zero or negligible amounts, leading to a large number of `Deposit` events with little to no actual economic activity.
2. Each `Deposit` event triggers Bifrost to post a `MsgObservedTxIn` transaction, causing unnecessary transactions on THORChain, which increases network load and gas costs.
3. Malicious actors could exploit this to spam the network with meaningless transactions, cluttering the blockchain with irrelevant data and potentially affecting the performance and reliability of the network.

## Proof of Concept
The problem code is located in the `_deposit` function of the `THORChain_Router` contract. The `amount` parameter is not validated to ensure it is greater than zero.

**Code Snippet:**
```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        _vaultAllowance[vault][asset] += safeAmount; // Credit to chosen vault
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```

**Event Declaration:**
```solidity
event Deposit(
    address indexed to,
    address indexed asset,
    uint amount,
    string memo
);
```

Without any validation, a user could call the `_deposit` function with a zero amount:
```solidity
thcRouter.depositWithExpiry(vault, asset, 0, "Test memo", expiration);
```

This would result in the emission of a `Deposit` event with an amount of zero, triggering Bifrost to post unnecessary `MsgObservedTxIn` transactions to THORChain.

## Recommended Mitigation Steps
Add a requirement to ensure that the deposit amount is greater than zero. This will prevent zero-value deposits and ensure that only meaningful transactions are recorded in the event logs.

```solidity
function _deposit(
    address payable vault,
    address asset,
    uint amount,
    string memory memo
) private nonReentrant {
    require(amount > 0, "Deposit amount must be greater than zero"); // Add this validation
    uint safeAmount;
    if (asset == address(0)) {
        safeAmount = msg.value;
        bool success = vault.send(safeAmount);
        require(success);
    } else {
        require(msg.value == 0, "unexpected eth"); // protect user from accidentally locking up eth
        safeAmount = safeTransferFrom(asset, amount); // Transfer asset
        _vaultAllowance[vault][asset] += safeAmount; // Credit to chosen vault
    }
    emit Deposit(vault, asset, safeAmount, memo);
}
```
