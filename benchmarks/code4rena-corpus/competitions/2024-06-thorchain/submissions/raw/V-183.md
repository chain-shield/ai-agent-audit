# Vulnerability details

The `transfer()` and `send()` functions allocate a fixed amount of 2300 gas. These functions have previously been recommended for value transfers to protect against reentrancy attacks. However, the gas cost of EVM instructions can change significantly during hard forks, potentially disrupting existing contract systems that rely on fixed gas cost assumptions. For instance, EIP 1884 led to the malfunction of several existing smart contracts due to an increase in the cost of the SLOAD instruction.

## Impact

The deprecated `transfer()` function will cause the transaction to fail in the following scenarios:

- When the claimer smart contract does not implement a payable function.
- When the claimer smart contract implements a payable fallback function that uses more than 2300 gas units.
- When the claimer smart contract has a payable fallback function that requires less than 2300 gas units, but the function is called through a proxy, increasing the call's gas usage above 2300.
- In some cases, multisig wallets may require the use of more than 2300 gas.

## Recommended Mitigation Steps

Rather than using `transfer()` or `send()`, use `call()`. However, ensure that you follow the Check-Effects-Interaction pattern and/or include re-entrancy guards.
