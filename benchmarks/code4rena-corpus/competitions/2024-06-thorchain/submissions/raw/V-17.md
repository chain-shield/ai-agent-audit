# Vulnerability details

## Impact
Failing to verify the existing allowance of `msg.sender` before updating the `_vaultAllowances` mapping in the `transferAllowance` function could lead to unauthorized adjustments of allowances. This poses a security risk, as it could allow an entity to manipulate allowances without having the requisite permissions, potentially resulting in unauthorized asset transfers and financial losses.
## Proof of Concept
```
function transferAllowance(
  address router,
  address newVault,
  address asset,
  uint amount,
  string memory memo
) external nonReentrant {
  if (router == address(this)) {
    _adjustAllowances(newVault, asset, amount);
    emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
  } else {
    _routerDeposit(router, newVault, asset, amount, memo);
  }
}
```
## Tools Used

## Recommended Mitigation Steps
Add an allowance check to ensure that `msg.sender` has the appropriate allowance for the asset before adjusting it. This can be done by including a require statement to verify the allowance before proceeding with the adjustment. Here is the updated code:

```
function transferAllowance(
  address router,
  address newVault,
  address asset,
  uint amount,
  string memory memo
) external nonReentrant {
  if (router == address(this)) {
    require(_vaultAllowance[msg.sender][asset] >= amount, "Insufficient allowance");
    _adjustAllowances(newVault, asset, amount);
    emit TransferAllowance(msg.sender, newVault, asset, amount, memo);
  } else {
    _routerDeposit(router, newVault, asset, amount, memo);
  }
}
```
