# Vulnerability details

## Impact
Malicious miners can manipulate `block.timestamp` within a certain range, potentially allowing them to selectively include or exclude transactions based on timing conditions. This manipulation can affect the behavior of time-sensitive functions, leading to potential exploitation or unintended contract behavior.

## Proof of Concept
In the `THORChain_Router` contract, the `depositWithExpiry` function relies on `block.timestamp` for expiry checks. A miner could manipulate the `block.timestamp` to cause the function to revert or succeed inappropriately.

### LoC

```
function depositWithExpiry(address payable vault, address asset, uint amount, string memory memo, uint expiration) external payable {
    require(block.timestamp < expiration, "THORChain_Router: expired");
    deposit(vault, asset, amount, memo);
}
```

## Tools Used
Manual

## Recommended Mitigation Steps
Use `block.number` for time-based checks to reduce the impact of timestamp manipulation
