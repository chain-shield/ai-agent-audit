# Vulnerability details

## Impact
Disclaimer: this report is succinct, because I am not using ChatGPT to write it.
When ACTOR calling function `depositWithExpiry`, if `vault` parameter is passed and this is non-existed address, when ACTOR tries to deposit ETH, `bool success = vault.send(safeAmount);` will return true to success flag, which is incorrect.
Actor will loose their money.
Issue is happening 2 times in code. The same idea goes with all places where `.send` method is used

## Proof of Concept
```
// SPDX-License-Identifier: GPL-2.0
pragma solidity ^0.8.0;

import {Test} from "forge-std/Test.sol";

import {THORChain_Router} from "../chain/ethereum/contracts/THORChain_Router.sol";

contract Attacker {
    receive() external payable {
        revert("jackpot");
    }
}

contract RouterTest is Test {
    THORChain_Router public router;
    constructor() {
        router = new THORChain_Router();
    }

    function testDepositToNonExistVault() public {
        Attacker attacker = new Attacker();

        vm.deal(address(attacker), 1e18);
        vm.startPrank(address(attacker));

        router.depositWithExpiry{value: 1e18}(
            payable(address(0xBAD)),
            address(0),
            1,
            "0x",
            block.timestamp + 1
        );
    }

    receive() external payable {
        revert("jackpot");
    }
}
```

## Recommended Mitigation Steps
Use low-level call for this operation

```
// Attempt to send Ether using low-level call
(bool success, ) = vault.call{value: safeAmount}("");

if (!success) {
    // Ether transfer failed, convert to WETH and send
    IWETH(WETH).deposit{value: safeAmount}();
    require(IWETH(WETH).transfer(vault, safeAmount), "WETH transfer failed");
} 
```
