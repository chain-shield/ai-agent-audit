# Vulnerability details


## Impact

The `transferOutAndCall` function is designed to allow a user to send ETH to an aggregator for a token swap. If the swap fails, the function attempts to send the ETH directly to the recipient or back to the sender. However, when the asset is ETH, the function using the low-level `transfer()` function:

```solidity
payable(address(msg.sender)).transfer(_safeAmount);
```

However, `transfer()` only forwards 2300 gas, which is not enough for the recipient to execute any non-trivial logic in a `receive()` or `fallback` function. For instance, it is not enough for Safes (such as [this one](https://etherscan.io/address/0xd1e6626310fd54eceb5b9a51da2ec329d6d4b68a) in use by the protocol) to receive funds, which require > 6k gas for the call to reach the implementation contract and emit an event:

If a user calls `transferOutAndCall()` from a contract account (like a multisig or smart contract wallet) that has a `receive()` function requiring more than 2300 gas, and if `ethSuccess` fails, this will lead to ETH being stuck in the `THORChain_Router` contract.

```solidity
  function transferOutAndCall(
    address payable aggregator,
    address finalToken,
    address to,
    uint256 amountOutMin,
    string memory memo
  ) public payable nonReentrant {
    uint256 _safeAmount = msg.value;
    (bool erc20Success, ) = aggregator.call{value: _safeAmount}(
      abi.encodeWithSignature(
        "swapOut(address,address,uint256)",
        finalToken,
        to,
        amountOutMin
      )
    );
    if (!erc20Success) {
      bool ethSuccess = payable(to).send(_safeAmount); // If can't swap, just send the recipient the ETH
      if (!ethSuccess) {
        payable(address(msg.sender)).transfer(_safeAmount); // For failure, bounce back to vault & continue.
      }
    }
```

## Proof of Concept

1. Alice calls `transferOutAndCall()` from her multisig wallet contract to an aggregator.

2. The aggregator attempts to perform a token swap but fails.

3. The function tries to send the ETH to the recipient, which is a contract requiring more than 2300 gas to execute its `receive()` function.

4. If the recipient contract also fails for some reason, the fallback mechanism tries to return the ETH to Alice's multisig wallet using the `transfer()` method, which fails as well, causing the ETH to be stuck.

## Recommended Mitigation Steps

Use `call()` instead of `transfer()` to send ETH if `ethSuccess` is fail.

```diff
    if (!erc20Success) {
      bool ethSuccess = payable(to).send(_safeAmount); // If can't swap, just send the recipient the ETH
      if (!ethSuccess) {
-        payable(address(msg.sender)).transfer(_safeAmount); // For failure, bounce back to vault & continue.
+        (bool success, ) = payable(msg.sender).call{value: _safeAmount}("");
+        require(success, "ETH transfer failed");
      }
```

This forwards all available gas and allows contract recipients to execute arbitrary logic.
