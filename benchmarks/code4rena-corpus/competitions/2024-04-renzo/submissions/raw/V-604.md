# Vulnerability details

## Impact
`ezETH` can only be minted when the `paused` flag is set to `true` 

- `ezETH` will not be minted to users who make deposits into the `RestakeManager::deposit(...)`  leading to loss of funds as they cannot withdraw their collateral
- this breaks protocol functionality as tokens cannot be minted when the token contract is not paused.

## Proof of Concept
When [`EzETHToken::mint(...)`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/token/EzEthToken.sol#L41-L43) is called to mint ezETH to a user after making deposit into the `RestakeManager` contract, the function makes an internal calls to the `ERC20Upgradable::_mint(...)` function which in turn calls the [`EzETHToken::_beforeTokenTransfer(...)`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/token/EzEthToken.sol#L56-L72) hook. 

The problem is that the `EzETHToken::_beforeTokenTransfer(...)` hooks returns and ends execution on `L67` of the `EzETHToken.sol` contract (shown below) when the `EzETHToken.sol` contract is NOT paused without [minting token to the user](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L571-L572) who has made a deposit

This is contrary to normal behaviour when functions are restricted only when a contract is paused.

`EzETHToken::mint(...)` is used as a receipt token for users who deposit using the [`RestakeManager::deposit(...)`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L571-L572) contract and as such users will not get any token in exchange for their deposit leading to a loss of funds as the mint function will be called without increasing the balance of the `account` making the deposit.

The sponsor makes it clear that only transfers are paused initially, not burning and minting
