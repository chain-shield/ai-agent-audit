# Vulnerability details

`OperatorDelegator::getStakedETHBalance()` returns the ETH balance of an operator delegator which includes `current podOwner shares` + `stakedButNotVerified ETH` + `queued withdraw shares`
```solidity
    function getStakedETHBalance() external view returns (uint256) {
        // accounts for current podOwner shares + stakedButNotVerified ETH + queued withdraw shares
      @>  int256 podOwnerShares = eigenPodManager.podOwnerShares(address(this));
        return
           podOwnerShares < 0
              @>   ? queuedShares[IS_NATIVE] + stakedButNotVerifiedEth - uint256(-podOwnerShares)
                : queuedShares[IS_NATIVE] + stakedButNotVerifiedEth + uint256(podOwnerShares);
    }
```
`podOwnerShares` can be negative due to `share deficit`(when pod owner's ETH shares decreases between the time they queue and complete the withdrawal) 

Now the problem is, when `podOwnerShares` is negative enough(which is possible) and added to `queuedShares[IS_NATIVE]` will result in negative, which will revert the tx.(given stakedButNotVerifiedETH of that operator is 0) 
```solidity
queuedShares[IS_NATIVE] + stakedButNotVerifiedEth - uint256(-podOwnerShares)
```

## Impact
`getStakedETHBalance` has been used in `RestakeManager::calculateTVLs` and if this reverts, it will break all the core functions of the protocol like `deposit`, `withdraw` etc
