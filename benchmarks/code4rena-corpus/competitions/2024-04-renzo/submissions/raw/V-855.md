# Vulnerability details

The `EzEthToken` contract's `_beforeTokenTransfer` function does not prevent transfers to the zero address when the contract is paused, potentially allowing for unintended token burns and bypassing transfer restrictions.

## Impact
This issue could lead to the permanent loss of tokens if users inadvertently transfer to the zero address while the contract is paused. The impact is heightened by the expectation that all non-authorized transfers should be halted during a pause, which is not currently enforced for transfers to the zero address.

## Proof of Concept
The following code snippet from the `_beforeTokenTransfer` function shows the lack of checks for transfers to the zero address during a pause:

```solidity
function _beforeTokenTransfer(
    address from,
    address to,
    uint256 amount
) internal virtual override {
    super._beforeTokenTransfer(from, to, amount);

    // If not paused return success
    if (!paused) {
        return;
    }

    // If paused, only minting and burning should be allowed
    if (from != address(0) && to != address(0)) {
        revert ContractPaused();
    }
}
```

## Recommended Mitigation Steps
Modify the `_beforeTokenTransfer` function to include an explicit check that prevents transfers to the zero address during a pause state, unless it's an authorized burn operation. The updated function should look something like this:

```solidity
    function _beforeTokenTransfer(
        address from,
        address to,
        uint256 amount
    ) internal virtual override {
        super._beforeTokenTransfer(from, to, amount);

        if (paused) {
            // Allow minting (from == address(0)) and burning (to == address(0)) by authorized roles
            bool isMinting = from == address(0);
            bool isBurning = to == address(0) && roleManager.isEzETHMinterBurner(msg.sender);
            if (!isMinting && !isBurning) {
                revert ContractPaused();
            }
        }
    }
```
