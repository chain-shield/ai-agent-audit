# Vulnerability details

## Vulnerability details
When a user deposits their LST into Renzo using the `RestakeManager.deposit()` function, it first sends a portion to the `withdrawQueue` to fill the buffer, then deposits the remaining amount into the operatorDelegator.


```
        if (bufferToFill > 0) {
            bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
            // update amount to send to the operator Delegator
            _amount -= bufferToFill;

            // safe Approve for depositQueue
            _collateralToken.safeApprove(address(depositQueue), bufferToFill);

            // fill Withdraw Buffer via depositQueue
            depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
        }
```
If the deposit amount does not exceed the buffer deficit for this LST in the `withdrawQueue`, the entire passed-in `_amount` is used to fill the `withdrawQueue` buffer via `depositQueue.fillERC20withdrawBuffer`.

```
        // Call deposit on the operator delegator
        operatorDelegator.deposit(_collateralToken, _amount);
```
The function then calls `operatorDelegator.deposit()`, passing in zero as the `_amount`.

```
    function deposit(
        IERC20 token,
        uint256 tokenAmount
    ) external nonReentrant onlyRestakeManager returns (uint256 shares) {
        if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
            revert InvalidZeroInput();
```
However, operatorDelegator.deposit() does not allow a tokenAmount of zero, thus the whole transaction will fail.

In summary, users are unable to deposit LST into Renzo unless the deposit amount exceeds the buffer deficit in the withdrawQueue.

What's worse, the buffer deficit can be increased by users, up to the limit of `withdrawalBufferTarget[_asset]`. When a user calls `WithdrawQueue.withdraw()`, it increases the claimReserve[_asset], which in turn increases the return value from getBufferDeficit().

## Impact
The inability to deposit LST into Renzo unless the deposit surpasses the buffer deficit in withdrawQueue restricts participation. Only those with LST holdings exceeding the buffer deficit can deposit their LST into Renzo. This limitation prevents users with smaller funds from participating, potentially harming the growth of the protocol.

I believe the issue is high for the following reasons:

1. Upon deployment and activation of the withdrawQueue, the buffer is initially empty. This could result in a substantial buffer deficit, setting a high threshold for minimum user deposits. Users may be frustrated to discover they can only deposit LST above a certain limit when the withdrawQueue functions are live.  
2. User deposits are one of three methods to replenish the buffer in withdrawQueue. However, a large buffer deficit can obstruct user deposits, triggering a downward spiral. The remaining two methods - daily rewards from the protocol and manual withdrawal from EigenLayer - are less efficient in terms of funds and time, respectively.
3. The buffer deficit can be increased by malicious users. They can deposit native ETH into the restakeManager to obtain ezETH, and then redeem ezETH for LST using `WithdrawQueue.withdraw()`. This action increases the buffer deficit for LST. This also opens a griefing attack vector - malicious users could front-run another user's LST deposit, increase the buffer deficit, and cause the user's LST deposit to fail.

## Proof of Concept
```
// SPDX-License-Identifier: Unlicense
pragma solidity 0.8.19;

import "forge-std/Test.sol";
import "../contracts/RestakeManager.sol";
import "../contracts/Oracle/RenzoOracle.sol";
import "../contracts/Deposits/DepositQueue.sol";
import "../contracts/Withdraw/WithdrawQueue.sol";
import "../contracts/Permissions/RoleManager.sol";
import "../contracts/token/EzEthToken.sol";
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";

contract PoC is Test {
    RestakeManager restakeManager = RestakeManager(0x74a09653A083691711cF8215a6ab074BB4e99ef5);
    address restakeManagerAdmin = 0xD1e6626310fD54Eceb5b9a51dA2eC329D6D4B68A;

    IRoleManager roleManager;
    IRenzoOracle renzoOracle;

    DepositQueue depositQueue;
    WithdrawQueue withdrawQueue;

    IERC20 ezETH = IERC20(0xbf5495Efe5DB9ce00f80364C8B423567e58d2110);
    IERC20 wBETH = IERC20(0xa2E3356610840701BDf5611a53974510Ae27E2e1);
    IERC20 stETH = IERC20(0xae7ab96520DE3A18E5e111B5EaAb095312D7fE84);

    address alice = makeAddr("alice1");

    // parameters for TokenWithdrawBuffer in WithdrawQueue
    address asset = address(stETH);
    uint256 bufferAmount = 1_000_000 ether;

    function setUp() public {
        vm.createSelectFork("ETH_RPC_URL", 19775681);
        vm.label(address(restakeManager), "RestakeManager");

        depositQueue = DepositQueue(payable(address(restakeManager.depositQueue())));
        vm.label(address(depositQueue), "depositQueue");

        roleManager = restakeManager.roleManager();
        renzoOracle = restakeManager.renzoOracle();

        {
            _upgradeTo(address(restakeManager), address(new RestakeManager()));
        }
        {
            _upgradeTo(address(depositQueue), address(new DepositQueue()));
            _deployWithdrawQueue();
            vm.prank(restakeManagerAdmin);
            depositQueue.setWithdrawQueue(IWithdrawQueue(address(withdrawQueue)));
        }
    }


    function test_depositLessThanBufferDeficit() public {
        uint256 amount = 1 ether;
        {  // give alice some stETH to begin with
            address tokenHolder = 0xB671e841a8e6DB528358Ed385983892552EF422f;
            vm.prank(tokenHolder);
            stETH.transfer(alice, amount);
        }
        vm.startPrank(alice);
        stETH.approve(address(restakeManager), amount);
        restakeManager.deposit(stETH, amount);
        vm.stopPrank();
    }

    function _upgradeTo(address proxy, address newImpl) internal {
        bytes32 adminBytes = vm.load(proxy, bytes32(uint256(keccak256("eip1967.proxy.admin")) - 1));
        address admin = address(bytes20(uint160(uint256(adminBytes))));
        vm.startPrank(admin);
        ITransparentUpgradeableProxy(proxy).upgradeTo(newImpl);
        vm.stopPrank();
    }

    function _deployWithdrawQueue() internal {
        WithdrawQueue impl = new WithdrawQueue();
        WithdrawQueue.TokenWithdrawBuffer[] memory withdrawBuffer = new WithdrawQueue.TokenWithdrawBuffer[](1);
        withdrawBuffer[0].asset = asset;
        withdrawBuffer[0].bufferAmount = bufferAmount;
        bytes memory data = abi.encodeCall(
            WithdrawQueue.initialize,
            (
                roleManager,
                IRestakeManager(address(restakeManager)),
                IEzEthToken(address(ezETH)),
                renzoOracle,
                7 days,
                withdrawBuffer
            )
        );
        TransparentUpgradeableProxy proxy = new TransparentUpgradeableProxy(address(impl), restakeManagerAdmin, data);
        withdrawQueue = WithdrawQueue(address(proxy));
    }
}
```
The above PoC adds the `withdrawQueue` into the system in the setUp().
The `test_depositLessThanBufferDeficit()` case examines a user's deposit of stETH into the `restakeManager` when the deposit amount is smaller than the buffer deficit in the withdrawQueue.

Running `forge test` will yield a result of `[FAIL. Reason: InvalidZeroInput()] test_depositLessThanBufferDeficit()`. If you adjust the test case to have the deposit amount exceed the buffer deficit, the test case will succeed. This confirms our point that users cannot deposit LST into Renzo unless the deposit amount surpasses the buffer deficit in the withdrawQueue.

## Recommended Mitigation Steps
In the `RestakeManager.deposit()` function, skip the deposit into `operatorDelegator` if the remaining `_amount` becomes zero after filling the buffer in `withdrawQueue`.
```diff
+   if (_amount > 0) {
        // Approve the tokens to the operator delegator
        _collateralToken.safeApprove(address(operatorDelegator), _amount);

        // Call deposit on the operator delegator
        operatorDelegator.deposit(_collateralToken, _amount);
+   }
```
