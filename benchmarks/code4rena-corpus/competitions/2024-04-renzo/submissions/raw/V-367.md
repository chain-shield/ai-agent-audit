# Vulnerability details

## Vulnerability Detail
Within `RestakeManager.calculateTVL()`, it intends to calculate the value held by the `WithdrawalQueue` for each token.

The issue is that it passes `collateralTokens[i]` rather than `collateralTokens[j]` for the first parameter of `RenzoOracle.lookupTokenValue(IERC20 token, uint256 balance)`

```solidity
if (!withdrawQueueTokenBalanceRecorded) {
    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
        collateralTokens[i], //@audit this should be 'j'
        collateralTokens[j].balanceOf(withdrawQueue)
    );
}
```
Since this block of code will only execute in the first iteration of the outer loop, `i` would be `0`. So the value of all collateral tokens will be calculated using a price corresponding to `collateralTokens[0]`. 

## Impact
This leads to an incorrect TVL calculation within `RestakeManager.calculateTVL()`, leading to incorrect pricing of `ezETH`.

## Recommended Mitigation Steps
Use `collateralTokens[j]` to ensure that the correct prices are used to calculate the total value stored in the withdrawalQueue.

```diff
if (!withdrawQueueTokenBalanceRecorded) {
    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
-       collateralTokens[i],
+       collateralTokens[j],
        collateralTokens[j].balanceOf(withdrawQueue)
    );
}
```
