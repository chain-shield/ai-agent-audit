# Vulnerability details

### Description

1. From the protocol docs[https://docs.renzoprotocol.com/docs/integrations/l2-native-restaking], we can refer the following points.

	- _If user deposits 1 ETH, slippage is incurred to convert the `ETH/wETH` to `nextWETH`_
	- _A fee of 0.0005 ETH (5 basis points) is deducted to pay `bridge fee`._
	- _An additional 5 basis points bridge gas fee or .0005 ETH will be deducted_- 
	- _This fee is used to pay `the bridging gas fees` to deposit on the `L1`._

2.  xRenzorDeposit#`depositETH()` and xRenzorDeposit#`deposit()
	- has only zero check for `msg.value` or `_amountIn`. 
	- has no minimum validation check for `msg.value` or `_amountIn'.
	- has no any check logic for `_minout`.
	
```
function depositETH(
	uint256 _minOut,
	uint256 _deadline
) external payable nonReentrant returns (uint256) {

	if (msg.value == 0) {
		revert InvalidZeroInput();
	}

	uint256 depositBalanceBefore = depositToken.balanceOf(address(this));

	IWeth(address(depositToken)).deposit{ value: msg.value }();
	uint256 wrappedAmount = depositToken.balanceOf(address(this)) - depositBalanceBefore;

	if (wrappedAmount == 0) {
		revert InvalidZeroOutput();
	}

	return _deposit(wrappedAmount, _minOut, _deadline);
}

function deposit(
	uint256 _amountIn,
	uint256 _minOut,
	uint256 _deadline
) external nonReentrant returns (uint256) {

	if (_amountIn == 0) {
		revert InvalidZeroInput();
	}

	depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);
	return _deposit(_amountIn, _minOut, _deadline);
}
```
	
3.  xRenzorDeposit#`_deposit()`
	- calls xRenzorDeposit#`getBridgeFeeShare()` to get `bridgeFee`. 
	- subtract from `_amountIn` and add to `bridgeFeeCollected`.

```
function _deposit(
	uint256 _amountIn,
	uint256 _minOut,
	uint256 _deadline
) internal returns (uint256) {

	uint256 bridgeFee = getBridgeFeeShare(_amountIn); //<------------ @audit
	
	_amountIn -= bridgeFee;  //<------------------ @audit
	bridgeFeeCollected += bridgeFee;
	
	uint256 amountOut = _trade(_amountIn, _deadline);
	if (amountOut == 0) {
		revert InvalidZeroOutput();
	}
	...
}
```

3. But xRenzorDeposit#`getBridgeFeeShare() will return zero if `_amountIn` is too small.

```
function getBridgeFeeShare(uint256 _amountIn) public view returns (uint256) {
	if (_amountIn < sweepBatchSize) {
		//<------------------ @audit	
		return (_amountIn * bridgeFeeShare) / FEE_BASIS;
	} else {
		return (sweepBatchSize * bridgeFeeShare) / FEE_BASIS;
	}
}
```

4. But xRenzorDeposit#`_trade() will return zero if `amountNextWETH` is too small.

```
function _trade(uint256 _amountIn, uint256 _deadline) internal returns (uint256) {
	...
	uint256 amountNextWETH = connext.swapExact(
		swapKey,
		_amountIn,
		address(depositToken),
		address(collateralToken),
		minOut,
		_deadline
	);

	// Subtract the bridge router fee
	if (bridgeRouterFeeBps > 0) {
		uint256 fee = (amountNextWETH * bridgeRouterFeeBps) / 10_000; //<---- @audit
		amountNextWETH -= fee;
	}

	return amountNextWETH;
}
```

## Impact

If users deposit small amount of token to Bridge with the small `_minOut`, the protocol can't receive any fee.

### Proof of Concept

1. User `Bob` deposits `_amountIn` as `1` through  xRenzorDeposit#`deposit()` with `_minOut` as zero.  
2. Since `bridgeFeeShare` is 5 and `FEE_BASIS` is 10000 by default, xRenzorDeposit#`getBridgeFeeShare()` will return zero.
3. And since `bridgeRouterFeeShare` is 5, `fee`will be zero on xRenzorDeposit#`_trade()`.
4. So the protocol can't receive any fee.
