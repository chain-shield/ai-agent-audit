# Vulnerability details

## Impact
WithdrawQueue#getAvailableToWithdraw returns the difference between WithdrawQueue's balance and total pending amount of the token requested for withdrawal:
 
```solidity
    function getAvailableToWithdraw(address _asset) public view returns (uint256) {
        if (_asset != IS_NATIVE) {
            return IERC20(_asset).balanceOf(address(this)) - claimReserve[_asset];
        } else {
            return address(this).balance - claimReserve[_asset];
        }
    }
```  

However, there can be more tokens requested that the totalBalance of WithdrawQueue. As long as this is true, getAvailableWithdraw would panic. As it is used from `RestakeManager#deposit`, this wil DoS deposits, until enough requested withdrawals from EigenLayer are processed.

## Proof of Concept
1. Alice deposits withdrawalBufferTarget of wbETH
2. Alice requests a withdrawal of the same amount of wbETH
3. Bob tries to deposit wbETH. Transaction fails because wbETH balance is zero, and claimReserve(wbETH) is not.
