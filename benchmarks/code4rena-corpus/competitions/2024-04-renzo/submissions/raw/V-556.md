# Vulnerability details

## Description
On the supported L2's, a user can call one of the two `deposit` functions to deposit either `native ETH` or a supported `ERC20` token to mint `xezETH`.

```javascript
    function deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) external nonReentrant returns (uint256) {
        //.. ommitted code
    }

    function depositETH(
        uint256 _minOut,
        uint256 _deadline
    ) external payable nonReentrant returns (uint256) {
        //.. ommitted code
    }
```

During the `deposit` flow, `getMintRate()` gets called:
```javascript
    function _deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) internal returns (uint256) {
        // Fetch price and timestamp of ezETH from the configured price feed
        (uint256 _lastPrice, uint256 _lastPriceTimestamp) = getMintRate();
    }
```

The problem here is a timing issue inside `getMintRate()`:
```javascript
    function getMintRate() public view returns (uint256, uint256) {
        // revert if PriceFeedNotAvailable
        if (receiver == address(0) && address(oracle) == address(0)) revert PriceFeedNotAvailable();
        if (address(oracle) != address(0)) {
->          (uint256 oraclePrice, uint256 oracleTimestamp) = oracle.getMintRate();
->          return
->              oracleTimestamp > lastPriceTimestamp
->                  ? (oraclePrice, oracleTimestamp)
->                  : (lastPrice, lastPriceTimestamp);
        } else {
            return (lastPrice, lastPriceTimestamp);
        }
    }
```

`lastPrice` and `lastPriceTimestamp` can be updated by a `CCIP call` from `L1` inside `_updatePrice`:
```javascript
    // Call made by `receiver`
    function updatePrice(uint256 _price, uint256 _timestamp) external override {
        if (msg.sender != receiver) revert InvalidSender(receiver, msg.sender);
        _updatePrice(_price, _timestamp);
    }
    
    // Call made by owner
    function updatePriceByOwner(uint256 price) external onlyOwner {
        return _updatePrice(price, block.timestamp);
    }

    function _updatePrice(uint256 _price, uint256 _timestamp) internal {
        //.. ommitted code
        lastPrice = _price;
        lastPriceTimestamp = _timestamp;
        //.. ommitted code
    }
```

When `lastPrice` gets updated, it does not get checked if the exchange rate is less than `1 ether`, as done in `RenzoOracleL2.getMintRate()`:
```javascript
    function getMintRate() public view returns (uint256, uint256) {
        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        // scale the price to have 18 decimals
        uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
->      if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
    }
```

This means that, if the `lastPriceTimestamp` set by the `CCIP call` from `L1` is more recent than the  `oracle.latestRoundData()` **or** if the `lastPriceTimestamp` is equal to the `timestamp` returned from the `oracle.latestRoundData()`, then the values of `RenzoOracleL2.getMintRate()` will be disregarded due
to this check:
```javascript
    function getMintRate() public view returns (uint256, uint256) {
        //.. ommitted code
            (uint256 oraclePrice, uint256 oracleTimestamp) = oracle.getMintRate();
            return
                oracleTimestamp > lastPriceTimestamp
                    ? (oraclePrice, oracleTimestamp)
                    : (lastPrice, lastPriceTimestamp);
            //.. ommitted code
        }
    }
```
`lastPriceTimestamp` will be more recent due to the more recent `CCIP call` from `L1`, which can result into an `exchangeRate` of less than `1 to 1`, which explicitly gets checked inside `RenzoOracleL2.getMintRate()`.
Moreover, during the update made from a `CCIP call` from `L1`, inside `_updatePrice()`, the exchange rate is allowed to deviate up to `10%`:
```javascript
    function _updatePrice(uint256 _price, uint256 _timestamp) internal {
        //.. ommitted code

        // Check for price divergence - more than 10%
        if (
->          (_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
->          (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))
        ) {
            revert InvalidOraclePrice();
        }
        //.. ommitted code
    }
```
This means a deviation of up to `10%` is expected, but there are no checks to ensure the exchange rate is less than `1:1`.
## Proof of Concept
- Alice wants to mint `xEZETH` at a ratio of less than `1:1`.
- Alice waits on a `CCIP call` from `L1` that sets the `lastPrice` to less than `1 ether`.
- Alice calls either one of the deposit functions and since the `lastPriceTimestamp` is more recent
than the `oracle.latestRoundData()`, the `lastPrice` set by the `CCIP call` will be used, resulting in
Alice minting `xEZETH` at a cheaper rate.

Note that `Alice` can ensure to always mint with the `CCIP call` price by submitting her tx in the same block as the `CCIP call` is received.
## Tools used
Manual review
## Recommended Mitigation Steps
Use the same check as used inside `RenzoOracleL2.getMintRate()`.
