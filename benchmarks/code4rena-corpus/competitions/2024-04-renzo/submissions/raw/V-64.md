# Vulnerability details

## Impact
The `stakeEthFromQueueMulti` function in the `DepositQueue` contract contains an unbounded loop that iterates over dynamic arrays without any explicit upper bound. This can lead to transactions exceeding the block gas limit if a large number of OperatorDelegator instances are passed as input.

If an attacker calls the `stakeEthFromQueueMulti` function with a large number of OperatorDelegator instances, it can cause the transaction to exceed the block gas limit and fail. This can result in a denial of service (DoS) situation, preventing legitimate users from successfully calling the function and staking their ETH.

Even if the transactions does not exceed the block gas limit, the unbounded loop in this function can lead still to Denial of Service (DoS) attacks. An attacker could call this function with a very large array of `OperatorDelegators`, `pubkeys`, `signatures`, and `depositDataRoots`, causing the transaction to take an extremely long time to execute and preventing other users from interacting with the contract.

Plus, the `stakeEthFromQueueMulti` function is a critical part of the protocol's functionality, meaning that the DoS vulnerability can have a significant impact on the overall usability and reliability of the system.

Finally, the unbounded loop vulnerability can cause unexpected behavior in the contract and the protocol as a whole. If the `stakeEthFromQueueMulti` function fails due to exceeding the block gas limit, it may leave the contract in an inconsistent state or cause downstream operations to fail. This can lead to confusion among users and erode trust in the protocol's reliability and correctness.

## Proof of Concept
Bob, the attacker, creates a very large array of `OperatorDelegators`, `pubkeys`, `signatures`, and `depositDataRoots`.

Bob calls the `stakeEthFromQueueMulti` function with the large array, causing the transaction to consume a large amount of gas and preventing other users from successfully calling the function.

## Recommended Mitigation Steps
Implement one or more of the following measures:

Implement a maximum array size limit for the `operatorDelegators`, `pubkeys`, `signatures`, and `depositDataRoots` arrays to prevent the unbounded loop from consuming too much gas.

Consider splitting the functionality of the stakeEthFromQueueMulti function into multiple smaller transactions to reduce the gas cost and execution time.

Optimize the gas usage of the `stakeEthFromQueueMulti` function by reducing the number of iterations or using more gas-efficient data structures and algorithms.
