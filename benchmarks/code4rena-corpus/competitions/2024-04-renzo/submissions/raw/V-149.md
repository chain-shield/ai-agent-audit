# Vulnerability details


## Impact

Users may be unable to retrieve their funds from multiple strategies if a single strategy in the batch fails during the withdrawal process. This can lead to a complete lock of all funds involved in the transaction, significantly impacting user trust and the usability of the platform.

## Proof of Concept

The problem lies in the fact that the `completeQueuedWithdrawal` function attempts to complete the withdrawal for all strategies and tokens in a single transaction. It does this by calling `delegationManager.completeQueuedWithdrawal` with the entire `withdrawal`, `tokens`, and `middlewareTimesIndex`.

If any of the strategies in the withdrawal.strategies array fails or reverts during the completeQueuedWithdrawal call, it will cause the entire transaction to revert. This means that if one strategy is paused, hacked, or fails, the user will not be able to complete the withdrawal for any of the other strategies in the same queued withdrawal.

Let's say a user has queued a withdrawal for three strategies: `StrategyA`, `StrategyB`, and `StrategyC`. If `StrategyB` is compromised or fails during the `completeQueuedWithdrawal` call, the entire transaction will revert, preventing the user from completing the withdrawal for `StrategyA` and `StrategyC` as well.

This can lead to a situation where user funds are locked in the contract if one of the strategies in their queued withdrawal becomes unavailable or fails.

```solidity
function completeQueuedWithdrawal(
    IDelegationManager.Withdrawal calldata withdrawal,
    IERC20[] calldata tokens,
    uint256 middlewareTimesIndex
) external nonReentrant onlyNativeEthRestakeAdmin {
    uint256 gasBefore = gasleft();
    if (tokens.length != withdrawal.strategies.length) revert MismatchedArrayLengths();

    // Attempt to complete the withdrawal for all strategies
    delegationManager.completeQueuedWithdrawal(withdrawal, tokens, middlewareTimesIndex, true);

    // Further processing assuming all withdrawals were successful
    for (uint256 i; i < tokens.length; ) {
        // Logic to handle successful withdrawal
        unchecked {
            ++i;
        }
    }

    // Additional logic...
}
```

Here, `delegationManager.completeQueuedWithdrawal` is called with all strategies and tokens. If this call fails for any reason related to one of the strategies, it causes the entire function to revert, thus not processing any successful withdrawals for other strategies.

## Recommended Mitigation Steps:

Maybe the `completeQueuedWithdrawal` function should handle each strategy withdrawal individually. And it will be better to allow only withdrawals with 1 strategy per withdrawal.
