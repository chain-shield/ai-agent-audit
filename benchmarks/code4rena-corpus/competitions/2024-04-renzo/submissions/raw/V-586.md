# Vulnerability details

## Impact
ETH that was sent directly to the EigenPod cannot currently be recovered by an `OperatorDelegator`

## Vulnerability details
The `OperatorDelegator` contract is used for all interactions with EigenLayer in Renzo. Each operator is the owner of an `EigenPod`, granting it the ability to stake, queue/execute withdraws, recover tokens etc.

There are generally 2 types of assets stored in the EigenPod - assets from validator staking - those are withdrawable through the withdraw mechanism of EL, which the operator already implements.

Additionally there are the funds that are not related to staking, like rewards or accidentally sent funds to the Pod. All of those funds are stored in a [separate variable inside the EigenPod called `nonBeaconChainETHBalanceWei`](https://github.com/Layr-Labs/eigenlayer-contracts/blob/dbfa12128a41341b936f3e8da5d6da58c6233877/src/contracts/pods/EigenPod.sol#L92) and can be [withdrawn through the `EigenPod ::withdrawNonBeaconChainETHBalanceWei` function by the podOwner (Operator)](https://github.com/Layr-Labs/eigenlayer-contracts/blob/dev/docs/core/EigenPodManager.md#eigenpodwithdrawnonbeaconchainethbalancewei):

https://github.com/Layr-Labs/eigenlayer-contracts/blob/dbfa12128a41341b936f3e8da5d6da58c6233877/src/contracts/pods/EigenPod.sol#L351
```solidity
function withdrawNonBeaconChainETHBalanceWei(
        address recipient,
        uint256 amountToWithdraw
    ) external onlyEigenPodOwner onlyWhenNotPaused(PAUSED_NON_PROOF_WITHDRAWALS) {
        require(
            amountToWithdraw <= nonBeaconChainETHBalanceWei,
            "EigenPod.withdrawnonBeaconChainETHBalanceWei: amountToWithdraw is greater than nonBeaconChainETHBalanceWei"
        );
        nonBeaconChainETHBalanceWei -= amountToWithdraw;
        emit NonBeaconChainETHWithdrawn(recipient, amountToWithdraw);
        _sendETH_AsDelayedWithdrawal(recipient, amountToWithdraw);
    }
```

Renzos `OperatorDelegator` [contract already implements a `recoverTokens()` function to recover any tokens sent directly to the Pod](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L446):

```solidity
function recoverTokens(
        IERC20[] memory tokenList,
        uint256[] memory amountsToWithdraw,
        address recipient
    ) external onlyNativeEthRestakeAdmin {
        eigenPod.recoverTokens(tokenList, amountsToWithdraw, recipient);
    }
```

However it does not implement the `EigenPod::withdrawNonBeaconChainETHBalanceWei` from above to also allow recovery of ETH.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the following function so that not only tokens but also ETH can be recovered from the pod by `OperatorDelegator`:

```solidity
function recoverETH(
        address recipient,
        uint256 memory amountToWithdraw
    ) external onlyNativeEthRestakeAdmin {
        eigenPod.withdrawNonBeaconChainETHBalanceWei(recipient,amountToWithdraw);
    }
```
