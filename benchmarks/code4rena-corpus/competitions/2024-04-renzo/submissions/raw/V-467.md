# Vulnerability details

## Impact
If the `_receiver` address is not checked and is accidentally set to the zero address, any funds sent to this address would be permanently lost, as there is no private key associated with the zero address.

## Proof of Concept
```sol
// Verify valid non zero values
if (
    _currentPrice == 0 ||
    address(_xezETH) == address(0) ||
    address(_depositToken) == address(0) ||
    address(_collateralToken) == address(0) ||
    address(_connext) == address(0) ||
    _swapKey == 0 ||
    _bridgeDestinationDomain == 0 ||
    _bridgeTargetAddress == address(0) ||
    _receiver == address(0)  // This check was missing in the initial version
) {
    revert InvalidZeroInput();
}
```

## Tools Used

## Recommended Mitigation Steps
Always validate user inputs and ensure that Ethereum addresses are not the zero address before performing operations that involve transferring funds. The code has been updated to include a check for the `_receiver` address, which should prevent this issue from occurring.
