# Vulnerability details

## Impact
Token approvals in smart contracts pose security risks if not managed properly. Failure to revoke approvals can lead to unauthorized spending and potential exploits by malicious actors. In particular, leaving approvals open indefinitely could result in significant financial loss or disruption of contract functionality if the contract is compromised.

## Proof of Concept
```javascript
// Approve the lockbox to spend the ezETH
        ezETH.safeApprove(address(xezETHLockbox), ezETHAmount);

        // Get the xezETH balance before the deposit
        uint256 xezETHBalanceBeforeDeposit = xezETH.balanceOf(address(this));

        // Send to the lockbox to be wrapped into xezETH
        xezETHLockbox.deposit(ezETHAmount);

```

If An attacker deploys a malicious contract that exploits the vulnerable contract's approval mechanism, The contract's token balance could be drained due to unauthorized token transfers.

## Tools Used
Manual Review

## Recommended Mitigation Steps
implement approval revocation as part of the contract's logic. Revoking approvals after they are used ensures that approved spenders have access to tokens only when necessary, reducing the attack surface and mitigating the risk of unauthorized spending.

```javascript
// After the deposit is done, revoke the approval
ezETH.safeApprove(address(xezETHLockbox), 0);

```
