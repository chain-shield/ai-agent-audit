# Vulnerability details

## Impact
Already deployed Renzo contracts on mainnet cannot be upgraded to the new version

## Vulnerability details
Renzo implements the upgradeability pattern from OZ for its contracts. More specifically they inherit the `Initializable.sol` contract from OZ which provides the `initializer` modifier that is added to the `initialize()` function.

The `initialize()` function is called by the proxy of every upgradeable contract to initialize the state. Due to the `initializer` modifier applied to it, `initialize()` can only be called once. [This is how the modifier is defined](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/52c36d412e8681053975396223d0ea39687fe33b/contracts/proxy/utils/Initializable.sol#L104):

```solidity

 modifier initializer() {
        ....

        // Allowed calls:
        // - initialSetup: the contract is not in the initializing state and no previous version was
        //                 initialized
        // - construction: the contract is initialized at version 1 (no reininitialization) and the
        //                 current contract is just being deployed
        bool initialSetup = initialized == 0 && isTopLevelCall;

        ....

        if (!initialSetup && !construction) {
            revert InvalidInitialization();
        }
        $._initialized = 1;

        ....
    }
```

It checks if the `_initialized ` storage variable is set to 1, meaning contract has previously been initialized and if not allows the call and sets  `_initialized=1`. As a result the `initializer()` function cannot be called a second time once the `_initialized` variable inside the proxy was set.

Renzo has the initial versions of the contracts already deployed. Problem is that  they have already been initialized, meaning that they won't upgrade to the new versions of the implementation contracts that include the `withdraw logic`.

The contracts that have been deployed and also have new versions to be applied are:

- `DepositQueue.sol`
    - The deployed version -> [link](https://etherscan.io/address/0x3e0053d211b501732e999d6399b7e79610f7550b#code) -> It uses the `DepositQueueStorageV1`. It currently holds 10.14 ETH (32+K $), so it's logical it should be upgraded with the new withdraw flow
    - The latest version is at `DepositQueueStorageV2` -> [link](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Deposits/DepositQueue.sol#L10) -> it adds the `withdrawQueue` variable along with some functions related to the withdraw flow

- `OperatorDelegator.sol`
   - The deployed version -> [link](https://etherscan.io/address/0x0683c3cc018fb76874fdcc8620d15c4e467e34ca#code) -> It uses `OperatorDelegatorStorageV3`. Calling `getStakedEthBalance()` on the Proxy returns `268064` ETH. Since this contract is already the owner of those funds in the EigenPod it should be upgraded
   - The latest version is at `DepositQueueStorageV4` -> [link](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L20) -> It adds the withdrawal interactions with EigenPod

- `RestakeManager.sol`
  - The deployed version -> [link](https://etherscan.io/address/0xbaacd5f849024dcc80520baa952f11adfc59f9d0#code) 
  - The latest version -> [link](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L26) ->  adds logic related to the withdraw flow

## Proof of Concept
I've coded a POC that tries upgrading the currently deployed `OperatorDelegator.sol` to the latest version in the repo and fails just as explained above.

I've used foundry, installed all necissary dependencies using - `forge install` &  `npm install`. Then I created a test file and folder like so `contracts/tests/tests.sol`.

Replace the free RPC url with your own if not working and run `forge test --mt test_upgrade_operatorDelegator -vvvv`

```solidity
import "@openzeppelin/contracts/proxy/transparent/TransparentUpgradeableProxy.sol";
import "forge-std/Test.sol";
import "../Delegation/OperatorDelegator.sol";
import "../Permissions/IRoleManager.sol";
import "../EigenLayer/interfaces/IDelegationManager.sol";
import "../EigenLayer/interfaces/ISignatureUtils.sol";

contract TestContract is Test {
    uint256 chainFork;

    function setUp() public {
        // this is a free RPC endpoint, change it if not working
        chainFork = vm.createFork("https://rpc.ankr.com/eth");
    }

    function test_upgrade_operatorDelegator() public {
        // forking mainnet
        vm.selectFork(chainFork);

        // Get the deployed proxy on mainnet
        ITransparentUpgradeableProxy delegatorProxy = ITransparentUpgradeableProxy(
            payable(0xbAf5f3A05BD7Af6f3a0BBA207803bf77e2657c8F)
        );

        // Impersonate admin
        address _admin = address(0x91625601e2BbBEb7171C40c79FadBCFbFf6A1982);
        vm.startPrank(_admin);

        // make sure we are the admin
        address actualAdmin = delegatorProxy.admin();
        assert(_admin == actualAdmin);

        // deploy latest version of OperatoDelgator
        OperatorDelegator delegatorImplementation = new OperatorDelegator();

        // some address
        address _adress = address(101);
        // encode initialize function
        bytes memory initializeData = abi.encodeCall(
            OperatorDelegator.initialize,
            (
                IRoleManager(_adress),
                IStrategyManager(_adress),
                IRestakeManager(_adress),
                IDelegationManager(_adress),
                IEigenPodManager(_adress)
            )
        );

        //update fails
        vm.expectRevert("Initializable: contract is already initialized");
        delegatorProxy.upgradeToAndCall(address(delegatorImplementation), initializeData);
    }
}

```

## Recommended Mitigation Steps

When new state has to be initialized on a contract that has been initialized before another modifier has to be used called `reinitializer` [which is explained quite well in the OZ doc](https://docs.openzeppelin.com/contracts/5.x/api/proxy#Initializable-reinitializer-uint64-):

In the scenario of Renzo it could be something like this:

```solidity
contract DepositQueue{

// add the reinitialzier modifier
function initialize(IRoleManager _roleManager) public reinitializer(2) {
       .....
}

}

```
