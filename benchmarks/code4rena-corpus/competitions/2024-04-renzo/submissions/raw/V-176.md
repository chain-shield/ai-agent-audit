# Vulnerability details

## Impact
The `deposit` function in `RestakeManager.sol` does not have any mechanisms in place to protect against replay attacks. Replay attacks occur when a valid transaction is maliciously repeated or copied to perform unauthorized actions. This vulnerability could allow an attacker to steal funds by replaying a victim's failed transactions.

Without proper replay attack protection, an attacker could potentially replay a victim's failed transactions to siphon funds from the protocol. This could lead to significant financial losses for the victims and undermine the overall security of the protocol.

## Proof of Concept

The attacker observes Alice, the victim, attempting to deposit tokens into the protocol using the `deposit()` function.

The attacker intercepts Alice's failed transaction and obtains the transaction data.

The attacker waits for a brief period, then resubmits the same transaction data to the `deposit()` function.

Since the protocol does not have any mechanisms to prevent replay attacks, the protocol will execute the transaction again, effectively draining Alice's funds.

The attacker can repeat this process until Alice's entire balance is drained from the protocol.

The attacker can do this over and over to any and all users.

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement nonce-based or other mechanisms to ensure that each transaction can only be executed once, preventing replay attacks.
