# Vulnerability details

## Summary

`RestakeManager.calculateTVLs()` incorrectly accounts the WithdrawQueue's value into the totalTVL, due to the use of the wrong index.

## Impact

This leads to:
- incorrect valuation of the total TVL in `RestakeManager.calculateTVLs`
  
Incorrect valuation of the total TVL then leads to:
- bypass of the `maxDepositTVL` and `collateralTokenTvlLimits` during deposits
- over/under valuation of the `ezETH` amount to mint to the user
- over/under valuation of the value to withdraw to the user


## Proof of Concept
### Vulnerability

The vulnerability lies in the accounting of the `WithdrawQueue` contract [in the `RestakeManager.calculateTVLs` function](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L316-L321).

```solidity
    /// @dev This function calculates the TVLs for each operator delegator by individual token, total for each OD, and total for the protocol.
    /// @return operatorDelegatorTokenTVLs Each OD's TVL indexed by operatorDelegators array by collateralTokens array
    /// @return operatorDelegatorTVLs Each OD's Total TVL in order of operatorDelegators array
    /// @return totalTVL The total TVL across all operator delegators.
    function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
        // ...

        // flag for withdrawal queue balance set
        bool withdrawQueueTokenBalanceRecorded = false;
        
        // ...

        for (uint256 i = 0; i < odLength; ) {
            // ...

            for (uint256 j = 0; j < tokenLength; ) {
                // ...

                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {// @POC: Due to this condition, the withdrawQueue value is accounted on first loop round
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i],// @POC: Index is `i`, always ZERO
                        collateralTokens[j].balanceOf(withdrawQueue) // @POC: Index is `j`, incrementing in j's loop
                    );
                }

                unchecked {
                    ++j;
                }
            }

            // ...

            // Set withdrawQueueTokenBalanceRecorded flag to true
            withdrawQueueTokenBalanceRecorded = true;// @POC: This avoid accounting withdrawQueue's value more than once

            unchecked {
                ++i;
            }
        }
        
        // ...

        // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
        totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue); // @POC: incorrect `totalWithdrawalQueueValue` added to totalTVL

        return (operatorDelegatorTokenTVLs, operatorDelegatorTVLs, totalTVL);
    }
```

As we can see, the oracle is called to lookup the token value by using the `collateralTokens[i]` as token with the balance of `collateralTokens[j]` token. **NOTE `i` and `j`**.

By the way the function is built, the variable `i` will always be `i = 0` when retrieving the WithdrawQueue balance value.

### Scenario

Let's say that:

```solidity
    collateralTokens  = [ ETH, stETH, wBETH ]
    priceTokens       = [   1,   1.1,   1.05]
    balanceTokens     = [ 100,   100,   100 ]
```

Then, with the current implementation, the WithdrawQueue value will be accounted as:
```solidity
    withdrawQueueValue = priceTokens[0] * balanceTokens[0] + priceTokens[0] * balanceTokens[1] + priceTokens[0] * balanceTokens[2]
    withdrawQueueValue = 1 * 100 + 1 * 100 + 1 * 100
    withdrawQueueValue = 300
```

The expected value is:
```solidity
    withdrawQueueValue = priceTokens[0] * balanceTokens[0] + priceTokens[1] * balanceTokens[1] + priceTokens[2] * balanceTokens[2]
    withdrawQueueValue = 1 * 100 + 1.1 * 100 + 1.05 * 100
    withdrawQueueValue = 315
```

## Recommended Mitigation Steps

Consider fixing the index used for the `collateralTokens` in [the `calculateTVLs` function](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L316-L321).

The following patch implements such a fix:

```diff
diff --git a/contracts/RestakeManager.sol b/contracts/RestakeManager.sol
index 8c754e6..ceb32d0 100644
--- a/contracts/RestakeManager.sol
+++ b/contracts/RestakeManager.sol
@@ -315,7 +315,7 @@ contract RestakeManager is Initializable, ReentrancyGuardUpgradeable, RestakeMan
                 // record token value of withdraw queue
                 if (!withdrawQueueTokenBalanceRecorded) {
                     totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
-                        collateralTokens[i],
+                        collateralTokens[j],
                         collateralTokens[j].balanceOf(withdrawQueue)
                     );
                 }
```

*Note: The patch can be applied with `git apply`.*
