# Vulnerability details

## Impact
`OptimismMintableXERC20` tokens deployed by `OptimismMintableXERC20Factory` will fail to be deployed due to a variable not initialized correctly.

## Proof of Concept
If we take a look at `OptimismMintableXERC20Factory`, we can see that there is a `constructor`, `deployOptimismMintableXERC20` public function and `_deployOptimismMintableXERC20` internal function. This contract is upgradeable and inherits `XERC20Factory`.

In that parent contract the function `initialize` looks like this:

```solidity
    function initialize(
        address _lockboxImplementation,
        address _xerc20Implementation
    ) public initializer {
        lockboxImplementation = _lockboxImplementation;
        xerc20Implementation = _xerc20Implementation;
    }
```

As can be seen, here 2 state variables are set. When deploying OptimismMintableXERC20, the bytecode will consist of `_creation`, `xerc20Implementation`, `_proxyAdmin` and `initializeBytecode`, which will be packed.

```solidity
        // Constructor in Proxy takes (logic, admin, data)
        bytes memory _bytecode = abi.encodePacked(
            _creation,
            abi.encode(xerc20Implementation, _proxyAdmin, initializeBytecode)
        );

        _xerc20 = CREATE3.deploy(_salt, _bytecode, 0);
```

However here `xerc20Implementation` is address(0), because this variable is not initialized due to the constructor.

```solidity
    /// @dev Prevents implementation contract from being initialized.
    /// @custom:oz-upgrades-unsafe-allow constructor
    constructor() {
        _disableInitializers();
    }
```

To verify, we can test with the normal factory, but set the token implementation to address(0). This can be done by changing [this line](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/test/mockTests/Scripts/setup.ts#L491) to `ethers.ZeroAddress`.

Next, create `Factory.ts` [file](https://gist.github.com/Pavel2202/8f347eda79debf41a52b38ed0a2eb607) to test the function.

Run `yarn test`. The test will pass and revert message is the same as [this one](https://github.com/transmissions11/solmate/blob/c892309933b25c03d32b1b0d674df7ae292ba925/src/utils/CREATE3.sol#L55) in Solmate's CREATE3 contract.

## Tools Used
Manual Review, Hardhat

## Recommended Mitigation Steps
Rewrite the `XERC20Factory` to look like this:

```diff
    function initialize(
        address _lockboxImplementation,
        address _xerc20Implementation
    ) public initializer {
-       lockboxImplementation = _lockboxImplementation;
-       xerc20Implementation = _xerc20Implementation;
+       __XERC20Factory_init(_lockboxImplementation, _xerc20Implementation);
    }

+   function __XERC20Factory_init(
+       address _lockboxImplementation,
+       address _xerc20Implementation
+   ) internal onlyInitializing {
+       lockboxImplementation = _lockboxImplementation;
+       xerc20Implementation = _xerc20Implementation;
+   }
```

And `OptimismMintableXERC20Factory` should look like this:

```diff
    constructor() {
        _disableInitializers();
    }

+   function initialize(
+       address _lockboxImplementation,
+       address _xerc20Implementation
+   ) public initializer {
+       __XERC20Factory_init(_lockboxImplementation, _xerc20Implementation);
+   }
```
