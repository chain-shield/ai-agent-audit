# Vulnerability details

## Impact
If strategy for token is changed by `onlyOperatorDelegatorAdmin` in `setTokenStrategy`

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L106

```
function setTokenStrategy(
        IERC20 _token,
        IStrategy _strategy
    ) external nonReentrant onlyOperatorDelegatorAdmin {
        if (address(_token) == address(0x0)) revert InvalidZeroInput();

        tokenStrategyMapping[_token] = _strategy;
        emit TokenStrategyUpdated(_token, _strategy);
    }
```

TVL accounting will show incorrect values, failing to include deposits to previous strategy. 


## Proof of Concept
Users deposit tokens using some strategy in `OperatorDelegator`. 
`onlyOperatorDelegatorAdmin` then changes the strategy. 


Then
```
function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
            queuedShares[address(this)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this))
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView(
                        queuedShares[address(token)]
                    );
    }
```
returns token balance only for current strategy, failing to account for previous one. 

Return value of this function is later used in TVL calc

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L302

leading to incorrect TVL balance and new users having share price than lower value

Also see https://github.com/code-423n4/2023-11-kelp-findings/issues/197 for similar problem and discussion
