# Vulnerability details

## Impact
The `initialize()` function in the `xRenzoBridge` contract is marked as public, which allows any account to call this function before the intended deployer.

An attacker can potentially front-run the intended deployer and call the `initialize()` function first. This would allow the attacker to set the initial state of the `xRenzoBridge` contract to their advantage, including:

Manipulation of Admin Functions:

The `xRenzoBridge` contract has the following functions that are restricted to the "bridge admin" role:

recoverNative(uint256 _amount, address _to): The attacker can call this function to withdraw an arbitrary amount of ETH from the contract, effectively draining the protocol's funds.

recoverERC20(address _token, uint256 _amount, address _to): The attacker can call this function to withdraw an arbitrary amount of ERC20 tokens to the contract, effectively draining the protocol's funds.

Disruption of Cross-chain Functionality:

The attacker can manipulate the initial configuration of tokens, contracts, and other parameters in the `initialize()` function, effectively hijacking the core cross-chain transfer and pricing mechanisms of the `xRenzoBridge` contract.

This includes setting the `_ezETH`, `_xezETH`, `_wETH`, `_xezETHLockbox`, `_restakeManager`, `_connext`, `_linkRouterClient`, `_rateProvider`, `_linkToken`, and `_roleManager` parameters to addresses they control. By controlling these critical components, the attacker can disrupt the cross-chain transfer functionality, manipulate pricing mechanisms, and potentially divert user funds.

## Proof of Concept
The attacker observes the deployment of the xRenzoBridge contract and quickly calls the `initialize()` function before the intended deployer.

The attacker sets the contract addresses and other parameters to values they control, such as setting the `_ezETH`, `_xezETH`, `_wETH`, `_xezETHLockbox`, `_restakeManager`, `_connext`, `_linkRouterClient`, `_rateProvider`, `_linkToken`, and `_roleManager` to addresses they own.

The attacker can now call the admin-only functions, such as `recoverNative()` and `recoverERC20()`, to withdraw any sent funds from the contract, effectively draining the protocol's assets.

The attacker can also manipulate the cross-chain transfer and pricing mechanisms by controlling the critical contract addresses set in the `initialize()` function, disrupting the overall functionality of the `xRenzoBridge` contract.

Users attempting to utilize the `xRenzoBridge` contract for cross-chain transfers will be subject to the attacker's manipulations, potentially leading to financial losses or disruption of their expected interactions.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Use the factory pattern to allow only the factory to call the initializer or ensure it is not front-runnable by calling `initialize` directly in the deploy script.
