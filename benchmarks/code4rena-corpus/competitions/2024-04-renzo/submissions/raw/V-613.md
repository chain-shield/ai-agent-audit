# Vulnerability details

## Impact
When updating price in xRenzoDeposit there is a check to help protect the protocol against manipulation/sudden price swings. However if the price has a large swing and doesn't recover to within 10% of the last update the price will never be able to be updated and will remain stale. 

## Proof of Concept
Currently the ezETH/ETH price is 1.017. If the lastPrice is set to that and there is a black swan where the price drops dramatically and then recovers to only 85% of the initial price, when either the admin of receiver attempts to update the price the following check will always fail.
```solidity
if (
        (_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
        (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))
) {
        revert InvalidOraclePrice();
}
```
While this is a good safeguard to have while the market is turbulent once price stabilizes if the price is still > 10% away from the initial price the check still fails and it will result in the lastPrice being stale. Recommend allowing the admin to still updatePrice once price has stabilized even if the difference is > 10%.

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Allow an admin to update the price and modify the _updatePrice function to not include the check if msg.sender == owner. 
```diff
+    if (msg.sender != _owner) {
         if (
             (_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
             (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))
         ) {
             revert InvalidOraclePrice();
         }
+    }
```
