# Vulnerability details

While calculating TVLs in `RestakeManager::calculateTVLs()`, `totalWithdrawalQueueValue` stores the value of collateralToken present in `withdrawQueue` and to covert collateralToken into underlying asset, it uses `renzoOracle.lookupTokenValue()`
```solidity
   if (!withdrawQueueTokenBalanceRecorded) {
                @>    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                  @>      collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }
```

Now the problem is, instead of sending current token ie `collateralTokens[j]`, its sending same token again-again ie `collateralTokens[i]`(see above code). This will lead to converting same collateralToken again with diff tokens value. And `totalWithdrawalQueueValue` is getting added to `totalTVL`
```solidity
 // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
       @> totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);
```

## Impact
Leads to wrong `TVL` calculation, which will break core functions like `deposit`, `depositETH` etc
