# Vulnerability details

## Impact
Using the `burn()` function of `EzEthToken`, an address with `onlyMinterBurner` can burn an arbitrary `amount` of tokens from any address.
This is unnecessary and poses a serious centralization risk.

## Proof of Concept
> [burn()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/token/EzEthToken.sol#L45-L48)
```solidity
    /// @dev Allows minter/burner to burn ezETH tokens from an address
    function burn(address from, uint256 amount) external onlyMinterBurner {
        _burn(from, amount);
    }
```
The `burn()` function reduces the total supply of `ezETH` tokens and decreases the balance of the user from whom the tokens are burned.

If an admin burns a user's `ezETH` without user consent, it can have significant negative impacts:

- `Loss of collateral claim`: Users may lose their claim to the underlying collateral (e.g., `stETH`) without compensation.
- `Financial loss`: Users could suffer a financial loss if the burned `ezETH` cannot be redeemed for the original collateral.

###### Expoit scenario
1. Bob deposits `10 stETH` as collateral to mint `10 ezETH`.
2. Admin burns `5 ezETH` from the Bob's balance without Bob's action.
2. Bob's `ezETH` balance is now `5`, and they've effectively lost access to `5 stETH` worth of value.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Update `burn()` function for only owner can burn his tokens.
```solidity
    function burn(uint256 amount) external {
        _burn(msg.sender, amount);
    }
```
