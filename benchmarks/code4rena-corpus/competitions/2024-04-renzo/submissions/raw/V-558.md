# Vulnerability details

## Impact
The user will not be able to sweep ERC20 tokens if feeBasisPoints is 10000 and will result in DoS.
## Proof of Concept
The `DepositQueue` contract allow the reward admin to sweep erc20 tokens. For sweeping the contract allow to deduct the fee from token amount being swiped. The Issue here is that when user configeured the Fee the Protocol allows maximum of `10000` fee basis points:
```solidity
        if (_feeBasisPoints > 10000) revert OverMaxBasisPoints();
```
Assume here that the `_feeBasisPoints= 10000`. So when user tries to sweep the token He will call `sweepERC20` function :
```solidity
/contracts/Deposits/DepositQueue.sol:254
254:     function sweepERC20(IERC20 token) external onlyERC20RewardsAdmin {
255:         uint256 balance = IERC20(token).balanceOf(address(this));
256:         if (balance > 0) {
257:             uint256 feeAmount = 0;
258: 
259:             // Sweep fees if configured
260:             if (feeAddress != address(0x0) && feeBasisPoints > 0) {
261:  @1>               feeAmount = (balance * feeBasisPoints) / 10000;
262:                 IERC20(token).safeTransfer(feeAddress, feeAmount);
263: 
264:                 emit ProtocolFeesPaid(token, feeAmount, feeAddress);
265:             }
266: 
267:             // Approve and deposit the rewards
268:             token.approve(address(restakeManager), balance - feeAmount);
269:  @2>           restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount); 
270: 
271:             // Add to the total earned
272:             totalEarned[address(token)] = totalEarned[address(token)] + balance - feeAmount;
273: 
274:             // Emit the rewards event
275:             emit RewardsDeposited(IERC20(address(token)), balance - feeAmount);
276:         }
277:     }

```
The above function will first deduct the feeAmount from contract token balance using `@1>` in our case All the amount will be deducted in fee due to `feeBasisPoint=10000`.
i.e We have 100 tokens in this contract the formula : `(100 * 10000)/10000` will return 100, so the `FeeAmount` here will be 100 which is the total balance we have. after deducting Fee there will be 0 amount left for deposit.
`@2>` Without checking the remaining amount we calls `depositTokenRewardsFromProtocol` to deposit the remaining amount which is 0 in our case. The `depositTokenRewardsFromProtocol` calls `operatorDelegator.deposit`
```solidity
/contracts/Delegation/OperatorDelegator.sol:143
143:     function deposit(
144:         IERC20 token,
145:         uint256 tokenAmount
146:     ) external nonReentrant onlyRestakeManager returns (uint256 shares) {
147:  @3>       if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0) 
148:             revert InvalidZeroInput();
149: 
150:         // Move the tokens into this contract
151:         token.safeTransferFrom(msg.sender, address(this), tokenAmount);
152: 
153:         return _deposit(token, tokenAmount);
154:     }

```
`@3>` Here the Deposit function check that if `tokenAmount==0` it will through error.
So the Admin will not be able to sweep token due to this error and we are not handling the case where the remaining amount is 0.
