        if (_amountIn == 0) {

        }

        // Transfer deposit tokens from user to this contract
        depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);

        return _deposit(_amountIn, _minOut, _deadline);
    }

```
  function _deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) internal returns (uint256) {
        // calculate bridgeFee for deposit amount
        uint256 bridgeFee = getBridgeFeeShare(_amountIn);
        // subtract from _amountIn and add to bridgeFeeCollected
        _amountIn -= bridgeFee;
        bridgeFeeCollected += bridgeFee;

        // Trade deposit tokens for nextWETH
        uint256 amountOut = _trade(_amountIn, _deadline);
        if (amountOut == 0) {
            revert InvalidZeroOutput();
        }

        // Fetch price and timestamp of ezETH from the configured price feed
        (uint256 _lastPrice, uint256 _lastPriceTimestamp) = getMintRate();

        // Verify the price is not stale
        if (block.timestamp > _lastPriceTimestamp + 1 days) {
            revert OraclePriceExpired();
        }

        // Calculate the amount of xezETH to mint - assumes 18 decimals for price and token
        uint256 xezETHAmount = (1e18 * amountOut) / _lastPrice;
```
The updatePrice function is used to update the price of the asset in the xRenzoDeposit contract, which is crucial for calculating the correct amount of xezETH to mint in exchange for the deposited assets. This price update mechanism ensures that the minting process is based on the most current and accurate market value, which is essential for maintaining the integrity and fairness of the token exchange process within the contract.

Given the design of the system, it is crucial that the price is updated frequently and reliably to prevent issues such as price manipulation or outdated pricing affecting the minting process.

The updated price is used to determine the amount of xezETH that should be minted when a deposit is made but this was never done.

Here what happens, in the deposit function a user decides to deposit $100 ETH it wraps to WETH.
- // calculate bridgeFee for deposit amount
-  // Trade deposit tokens for nextWETH
- // Fetch price and timestamp of ezETH from the configured price feed

 formula representation of the xezETH minting calculation:
\[ \text{xezETH Amount} = \frac{( \text{Amount of nextWETH} - \text{Trading Fees} ) \times 10^{18}}{\text{ezETH Price}} \]

Amount of nextWETH = 100WETH
Trading Fees = 0.05% of amount of nextWETH = 0.05?/100 * 100 = 0.05 WETH
eZWETH = 0.9821 WETH
      

xezETH Amount = (100-0.05)x10^18/0.9821

xezETH Amount = 99.95x10^18/0.9821

 Amount == 1.0171x10^20; this is the amount when the updatePrice is called from the context L1.

The getMintRate doesn't function as intended where it uses ether against 
```
 function getMintRate() public view returns (uint256, uint256) {
        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        // scale the price to have 18 decimals
        uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
        if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
    }
```
If there is high demand for ezETH, its price relative to ETH may increase, causing slippage for traders (i.e. swapExact). They will experience larger price differences between the expected and executed price, especially for larger transactions.

### Impact                           
When users deposit ETH/WETH to mint xzETH, an incorrect price is given, which is not fair.

>updatePrice: It plays a critical supporting role by ensuring that the pricing information used by the deposit process is up to date.
