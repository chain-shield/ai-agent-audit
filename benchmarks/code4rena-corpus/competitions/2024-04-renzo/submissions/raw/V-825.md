# Vulnerability details

## Impact
In the `RestakeManager::deposit` function there is a limit when it comes to the max collateral tvl that can be deposited in each
operator delegator. A wrong value update allows this limit to be easily surpassed.

This means the user will break the protocol rules potentially increasing the risks of the restaking and leading to any issue
related to having an unlimited TVL.

## Proof of Concept

The check happens [here](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L529). It requires that the current operator delegator tvl + deposit amount does not surpass the limit.But 
the operator delegator TVL is not correctly calculated in the `calculateTVLs` method, since it always returns 0.
