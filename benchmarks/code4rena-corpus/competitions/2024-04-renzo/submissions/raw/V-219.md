# Vulnerability details

## Impact

Incorrrect token pricing, price manipulations, arbitrage, and so on.

## Proof of Concept

WBETHShim.sol uses the `_getWBETHData` function to provide current exhange rate of wBETH to ETH. This value is used as the `answer` parameter when the `latestRoundData` function is called, potentially functioning as the chainlink equivalent of wBETH oracle to be used in RenzoOracle. 

The issue with using this that the [oracle](https://etherscan.io/address/0x81720695e43A39C52557Ce6386feB3FAAC215f06) that [updates](https://etherscan.io/address/0xfe928a7d8be9c8cece7e97f0ed5704f4fa2cb42a#code#F22#L205) the exchange rate, does so once every 24 hours according to the transaction logs, with no deviation checks (only confirming that price update is [more than 0](https://etherscan.io/address/0x81720695e43A39C52557Ce6386feB3FAAC215f06#code#F1#L92)). 

What this means is that the returned exchange rate, which is used to calculate [price](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Oracle/RenzoOracle.sol#L77) will not accurate reflect current market conditions. That is, the actual price of wBETH will not be reflected in the oracle. This opens up the protocol to serious arbitrage risks especially in cases of extreme price movements, as users will be able to use the stale exchange rates to gain unfair advantages.

For a bit of context, as at time of writing this report, etherscan shows an [exchange rate](https://etherscan.io/token/0xa2E3356610840701BDf5611a53974510Ae27E2e1#readProxyContract#F15) of about 1,0382 while [coingecko](https://www.coingecko.com/en/coins/wrapped-beacon-eth/eth) and coinmarketcap show a price of 1,0375, but the showing a deviation of about 0,06%, which for now is quite low, indicating price has fallen a bit lower from the time price has updated. Evidently, this is probabaly a short time update, but in more dire case, e.g crash or extreme rise, protocol will be working with stale prices rather than current market prices.

The price provided by the function will not reflect the true value of the wBETH. It might be overvalued or undervalued depending on current market conditions and functions requiring asset prices will be severly affected. Functions actively depending on this is the [`lookupTokenValue`](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Oracle/RenzoOracle.sol#L77) and [`lookupTokenAmountFromValue`](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Oracle/RenzoOracle.sol#L92) functions which are used extensively in the codebase to [calculate tvls](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L307), [reward prices](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L688), [deposit prices](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L507) and [withdrawal amounts](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Withdraw/WithdrawQueue.sol#L229).


## Tools Used
Manual code review

## Recommended Mitigation Steps

Consider introducing another oracle source with more frequent updates, with which returned prices can be compared. A certain deviation width can be introduced to handle extreme price changes.
