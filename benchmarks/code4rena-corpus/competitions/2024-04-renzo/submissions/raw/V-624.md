# Vulnerability details

## Impact

The function `OperatorDelegator.completeQueuedWithdrawal()` is reverted due to the double calling the modifier `nonReentrant` at the functions `completeQueuedWithdrawal()` and `receive()`.

## Proof of Concept

Let's follow the function `OperatorDelegator.completeQueuedWithdrawal()`. When this function is invoked, the modifier `nonReentrant` is called. At `L274`, `delegationManager` sends all withdrawed tokens to this `OperatorDelegator` contract, and there are some ETH. When ETH is received, the `receive()` function is invoked. However, since the `receive()` function also has the modifier `nonReentrant`, it is regarded as a reentrancy, consequently the whole transaction is reverted.

```solidity
    function completeQueuedWithdrawal(
        IDelegationManager.Withdrawal calldata withdrawal,
        IERC20[] calldata tokens,
        uint256 middlewareTimesIndex
    ) external nonReentrant onlyNativeEthRestakeAdmin {
        uint256 gasBefore = gasleft();
        if (tokens.length != withdrawal.strategies.length) revert MismatchedArrayLengths();

274     delegationManager.completeQueuedWithdrawal(withdrawal, tokens, middlewareTimesIndex, true);

        [...]
    }
```
