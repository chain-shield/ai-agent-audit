# Vulnerability details

## Impact
The contract does not check the return value of the `transfer` function when transferring ERC20 tokens. This could lead to silent transfer failures, where a transfer that should have failed is incorrectly assumed to have succeeded. This could result in loss of funds or other unintended behavior.

## Proof of Concept
The vulnerability is present in the `claim` function of the `WithdrawQueue` contract:
```solidity
305                 IERC20(_withdrawRequest.collateralToken).transfer(
306                     msg.sender,
307                     _withdrawRequest.amountToRedeem
308                 );
```
If the `transfer` function fails for any reason (e.g., insufficient balance, transfer limits, etc.), the transaction will not be reverted and the failure will go unnoticed.

## Tools Used
Manual code review.

## Recommended Mitigation Steps
The contract should check the return value of the `transfer` function and handle the case where it returns `false`. This can be done by adding a `require` statement after the `transfer` call, as shown below:
```solidity
bool success = IERC20(_withdrawRequest.collateralToken).transfer(
    msg.sender,
    _withdrawRequest.amountToRedeem
);
require(success, "Token transfer failed");
```
This will ensure that the transaction is reverted if the `transfer` function fails, preventing silent transfer failures.
