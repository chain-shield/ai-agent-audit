# Vulnerability details

## Impact
The lack of consideration for TVL in the minting function could lead to misalignment between the minted ezETH tokens and the actual protocol value. This discrepancy may result in an inaccurate representation of the value locked in the protocol and could potentially undermine the stability and integrity of the system.


## Proof of Concept
The `calculateMintAmount` function, responsible for determining the amount of ezETH tokens to mint based on the current protocol value, new value added, and existing ezETH supply, lacks consideration for Total Value Locked (TVL) in the protocol, contrary to the documented requirement. The function calculates the mint amount solely based on the current protocol value and new value added, potentially leading to discrepancies between minted tokens and the actual protocol value.
```solidity
function calculateMintAmount(
    uint256 _currentValueInProtocol,
    uint256 _newValueAdded,
    uint256 _existingEzETHSupply
) external pure returns (uint256) {
    // For first mint, just return the new value added.
    if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
        return _newValueAdded;
    }

    uint256 inflationPercentage = (SCALE_FACTOR * _newValueAdded) /
        (_currentValueInProtocol + _newValueAdded);

    uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
        (SCALE_FACTOR - inflationPercentage);

    uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

    if (mintAmount == 0) revert InvalidTokenAmount();

    return mintAmount;
}

```
