# Vulnerability details

## Impact
When making swaps, some validation needs to be checked to protect the contract from being sandwiched or prone to slippage attacks. Every deposit in both deposit and depositETH made will be prone to slippage attacks because of no check for that.

## Proof of Concept

Slippage refers to the difference between the expected price of a trade and the actual price at which the trade is executed. It can occur due to market volatility, liquidity issues, or delays in transaction processing.

Moreover, in the comment [above the code snippet](https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Bridge/L2/xRenzoDeposit.sol#L371), it mentions that "The caller of this function should verify the amount meets minimums." This suggests that the caller of the function is responsible for ensuring that the output amount (amountNextWETH) meets its minimum acceptable threshold to avoid significant slippage.

- The question now is, was it done as instructed?
>***No***

***In the code itself, the variable [minOut is set to 0](https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Bridge/L2/xRenzoDeposit.sol#L372), indicating that there is no specified minimum output amount. This means that the swapExact function will execute the trade regardless of the output amount, which will potentially lead to slippage if the market conditions change significantly between the time the trade is initiated and executed.***

This will cause a loss of precision because users will never get the exact amount they hoped for.

This will affect the [deposit](https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Bridge/L2/xRenzoDeposit.sol#L204) and [depositETH](https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Bridge/L2/xRenzoDeposit.sol#L168) functions

## Recommended Mitigation Steps
Introduce a mechanism where the minOut is calculated first, if the minOut is set to Zero it still wouldn't work when you do something like this;
```
// Check for slippage
require(amountNextWETH >= minOut, "Slippage too high");
```
meaning amountNexWETH can be 0 too

So calculate the minOut and use the value to check for this
```
// Check for slippage
require(amountNextWETH >= minOut, "Slippage too high");
```
