# Vulnerability details

## Impact
User will not be able to withdraw from the protocol

## Vulnerability details
The contest docs have a special section called `ezETH Transfer Restrictions`, which states that:
> When the protocol launches, it is intended to not have ezETH be transferrable.... If the withdrawal flow is enabled, they can still withdraw from the protocol (token can be minted and burned by RestakeManager, even if transfers are restricted).

This creates the assumptions that the transfer restriction on ezETH should not affect withdraws, however this is not true.

First let's take a look how the transfer restriction is enforced in the `EzEthToken.sol` contract:

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/token/EzEthToken.sol#L56-L72
```solidity

function _beforeTokenTransfer(
        address from,
        address to,
        uint256 amount
    ) internal virtual override {
        super._beforeTokenTransfer(from, to, amount);

        // If not paused return success
        if (!paused) {
            return;
        }

        // If paused, only minting and burning should be allowed
        if (from != address(0) && to != address(0)) {
            revert ContractPaused();
        }
    }

```

If the token is paused only burning and minting is allowed and all other transfers would revert.

Now lets see the `withdraw flow`.

Depositors in the Renzo protocol get minted `ezETH` that acts as shares, which can later be burned to withdraw assets.

Withdrawing happens through the `WithdrawQueue.withdraw()` function:

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L206-L263

The problem here is quite evident. The withdraw function requires that the ezETH holder approves the contract so that it can call `transferFrom()`. Since this is still a transfer it will trigger the `_beforeTokenTransfer()` hook of `ezETH` token which will revert because of the paused transfers.

As a result withdraws will always fail and prevent users from withdrawing any funds. Which is not the expected behavior outlined in the docs.
