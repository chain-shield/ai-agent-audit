# Vulnerability details

## Impact
Due to a check that the scaled price of ezETH can not be less than 1 ether (1e18), if ezETH is ever worth more than ETH (which has occured in the past) the getMintRate() function call will always revert and users will be unable to call deposit or depositETH in the xRenzoDeposit contract.

## Proof of Concept
If ezETH price recovers and stabilizes around the 1 ETH price as it has in the past and a user attempts to make a deposit when the current ezETH/ETH price = 1.0008. i.e. 
1. Bob wishes to deposit 1 ETH using xRenzoDeposit#depositETH. 
2. _deposit will then attempt to fetch the price of ezETH by calling getMintRate()
```solidity
(uint256 _lastPrice, uint256 _lastPriceTimestamp) = getMintRate();
```
3. getMintRate will then include a call to oracle.getMintRate().
```solidity
(uint256 oraclePrice, uint256 oracleTimestamp) = oracle.getMintRate();
```
4. oracle.getMintRate() is called which will fetch the price of ezETH denominated in ETH.
```solidity
(, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
```
5. Which will return 0.999 or 9.99e17
6. Which will fail the check:
```solidity
if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
```
7. As a result the deposit will fail.

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Instead of using a check of < 1 ether consider adding an allowable amount of slippage so that if the ezETH price recovers and stabilizes to the ETH price like it has in the past users are still able to deposit.
