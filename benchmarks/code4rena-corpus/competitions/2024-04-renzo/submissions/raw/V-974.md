# Vulnerability details

## Bug Description
[WithdrawQueue](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L11) contract inherits [PausableUpgradeable](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L13) & [ReentrancyGuardUpgradeable](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L14) upgradable contracts and it's invoking only [PausableUpgradeable](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L13) initializer in its own initiliaztion but does not invoke [ReentrancyGuardUpgradeable](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L14) initializer. And because of that, `ReentrancyUpgradeable` remain uninitialized.

However, in contrast, Other contracts i.e [DepositQueue](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Deposits/DepositQueue.sol#L10) properly inherit and initialize inherited Contract.

## Proof of Concept
The WithdrawQueue contract is inheriting OZ's `ReentrancyGuardUpgradeable`

[WithdrawQueue.sol#L11-L16](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L11-L16)

```solidity
contract WithdrawQueue is
    Initializable,
    PausableUpgradeable,
    ReentrancyGuardUpgradeable,
    WithdrawQueueStorageV1
{
```

In [initalize()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L64) function `__ReentrancyGuard_init()` is never called. The `__ReentrancyGuard_init()` is used to initialize `ReentrancyUpgradeable` contract.Further, It calls the __ReentrancyGuard_init_unchained() function which sets `_status` to `_NOT_ENTERED`, initializing the guard to a safe state.

```solidity
    function __ReentrancyGuard_init() internal onlyInitializing {
        __ReentrancyGuard_init_unchained();
    }

    function __ReentrancyGuard_init_unchained() internal onlyInitializing {
        _status = _NOT_ENTERED;
    }
```

However, when [WithdrawQueue](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L11) will be deployed and initialized, guard will not be set to safe state `_NOT_ENTERED`.

And there's a very informative discussion on [OpenZepplin Forum](https://forum.openzeppelin.com/t/why-keep-ownable-init-beside-ownable-init-unchained/25579/12) about `Why it's important to initialize contracts`

## Impact 

Hence, it's breaking the core functionality of upgradeable contracts. However,  `__ReentrancyGuard_init()` is never called, all the reentrancy protection used in contract will be broken as well and might even brick the contract functionality.
