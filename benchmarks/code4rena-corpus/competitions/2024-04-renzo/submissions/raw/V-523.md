# Vulnerability details

## Title
`xRenzoBridge::_updatePrice()` can't handle ezETH sharp deviation more less 10% and can reject valid price update.

## Line of code
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L338C1-L339C76

## Impact
In case the price of ezETH drops sharply such that it is more than 10 % of `lastPrice`, [xRenzoBridge::_updatePrice()]() doesn't allow to accept the price in L2 chains. 

From this [reference](https://twitter.com/WazzCrypto/status/1782963673624961274), ezETH price can be depegged to very low as half as the ETH price in the past.

https://twitter.com/WazzCrypto/status/1782963673624961274

If the protocol doesn't allow such price variations, the [xRenzoBridge::updatePrice()]() which is used to receive the price feed and timestamp from the L1 through CCIPReceiver middleware contract will be reverted and reject valid price update.

If `xRenzoBridge::_updatePrice()` is not updated the `xRenzoBridge::getMintRate()` will use the old lastPrice as we can't update the lastPrice because of more than 10% percent deviation of ezETH price.

Ultimately, as `getMintRate()` is used in  `xRenzoBridge::_deposit()` to calculate the amount of xezETH to be minted on the deposit of tokens, the function will mint the xezETH at an old price of ezETH.

## Proof of Concept
The function [_updatePrice()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L338C1-L339C76) here implements a check 

```solidity
    if (
            (_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
            (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))
        ) {
            revert InvalidOraclePrice();
        }
```
so that deviation can't be less than 10%.
    
Now we see the function [getMintRate()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L289) it uses the lastPrice which is being updated by `_updatePrice`

```solidity
    function getMintRate() public view returns (uint256, uint256) {
        // revert if PriceFeedNotAvailable
        if (receiver == address(0) && address(oracle) == address(0)) revert PriceFeedNotAvailable();
        if (address(oracle) != address(0)) {
            (uint256 oraclePrice, uint256 oracleTimestamp) = oracle.getMintRate();
            return
                oracleTimestamp > lastPriceTimestamp
                    ? (oraclePrice, oracleTimestamp)
                    : (lastPrice, lastPriceTimestamp);
        } else {
            return (lastPrice, lastPriceTimestamp);
        }
    }
```
Now if we look at [xRenzoBridge::_deposit](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L245) the mint rate is used to to calculate the amount of xezETH to be minted on the deposit of tokens.

```solidity
function _deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) internal returns (uint256) {
        
@>      (uint256 _lastPrice, uint256 _lastPriceTimestamp) = getMintRate();

        // Verify the price is not stale
        if (block.timestamp > _lastPriceTimestamp + 1 days) {
            revert OraclePriceExpired();
        } 

        // Calculate the amount of xezETH to mint - assumes 18 decimals for price and token
        uint256 xezETHAmount = (1e18 * amountOut) / _lastPrice;

        // Mint xezETH to the user
        IXERC20(address(xezETH)).mint(msg.sender, xezETHAmount);

        ...
        ...

    }

```
If we unable to update the `_lastPrice` with `_update()`function,  `_deposit()` will mint the xezETH at an old price of ezETH due to mentioned vulnerability.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Allow accepting less deviation than 10% in `_update()` function and made the hardcoded 10% price deviation check configurable.
