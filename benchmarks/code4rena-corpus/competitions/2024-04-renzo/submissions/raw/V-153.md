# Vulnerability details

## Impact
Tokens that ezETH can be redeemed to is determined in withdraw queue by setting the  `withdrawalBufferTarget` for the corresponding underlying token. However, there is no way to off board an asset from withdrawing. For example if DAO decides to make ezETH -> wBETH withdrawals stop, it won't be possible due to the "!= 0" check in the code. Also, if the collateral token is entirely removed from the restaking manager withdraw queue will not be able to remove the token from its contract storage and will allow users to redeem their ezETH for the deprecated underlying token.

## Proof of Concept
Every token that ezETH can be withdrawn to has to set `withdrawalBufferTarget` to a value as we can see here:
```
function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        .
        // check if provided assetOut is supported
        -> if (withdrawalBufferTarget[_assetOut] == 0) revert UnsupportedWithdrawAsset();
        .
        .
        .
        .
    }
```

If the asset is deprecated completely or only deprecated from withdraw queue the `withdrawalBufferTarget` should be set to "0" so that the withdrawals are not possible further. 
However, as we can see in the update function setting the `withdrawalBufferTarget` value to "0" value is forbidden!
```solidity
function updateWithdrawBufferTarget(
        TokenWithdrawBuffer[] calldata _newBufferTarget
    ) external onlyWithdrawQueueAdmin {
        .
        for (uint256 i = 0; i < _newBufferTarget.length; ) {
            -> if (_newBufferTarget[i].asset == address(0) || _newBufferTarget[i].bufferAmount == 0)
                revert InvalidZeroInput();
            .
            .
            .
        }
    }
```

Hence, removing the asset is impossible once set. Though this is contradictory with the other functionalities that Renzo has such as:
1- [Complete off boarding of an underlying asset](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L244-L263)
2- Off boarding an asset only from the withdraw queue


## Tools Used

## Recommended Mitigation Steps
Allow the `withdrawalBufferTarget` to bet set to "0" in the `updateWithdrawBufferTarget` function.
