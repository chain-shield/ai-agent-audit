# Vulnerability details

The function [WithdrawQueue::claim()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L279) transfers either ETH or a supported token to the caller:

```solidity
if (_withdrawRequest.collateralToken == IS_NATIVE) {
    payable(msg.sender).transfer(_withdrawRequest.amountToRedeem);
} else {
    IERC20(_withdrawRequest.collateralToken).transfer(
        msg.sender,
        _withdrawRequest.amountToRedeem
    );
}
```

Both operations are not performed safely:

- Using `transfer()` to transfer ETH makes the whole call revert if the amount of gas used by the target is greater than 2300. This is fine for EOA, but a smart contract calling [WithdrawQueue::claim()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L279) that has a `receive()` function consuming more than 2300 gas will never be able to withdraw his funds.
- Using `transfer()` to transfer tokens without ensuring `true` is returned might lead to the call succeeding but the tokens being stuck in the `WithdrawQueue`, losing funds. It's also possible that the token that's being transferred doesn't return a boolean at all, in which case the function will revert making it impossible for users to claim the asset.

## Impact

- It could be impossible for a smart contract to claim his `ETH` because [WithdrawQueue::claim()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L279) reverts in case the `receive()` function of the caller consumes more than 2300 gas. Important to note that the function always (and only) transfers ETH to the caller.
- Transferring a token that return `false` on failures instead of reverting might lead to tokens being stuck.

## Recommended Mitigation Steps

Use `call()` to transfer `ETH` and use `safeTransfer()` to transfer tokens:

```solidity
if (_withdrawRequest.collateralToken == IS_NATIVE) {
    payable(msg.sender).call{value: _withdrawRequest.amountToRedeem]("");
} else {
    IERC20(_withdrawRequest.collateralToken).safeTransfer(
        msg.sender,
        _withdrawRequest.amountToRedeem
    );
}
```
