# Vulnerability details

## Vulnerability details
```
contract WithdrawQueue is
    Initializable,
    PausableUpgradeable,
    ReentrancyGuardUpgradeable,
    WithdrawQueueStorageV1
```
```
    function pause() external onlyWithdrawQueueAdmin {
        _pause();
    }
```
```
    function unpause() external onlyWithdrawQueueAdmin {
        _unpause();
    }
```
The `WithdrawQueue` contract inherits from `PausableUpgradeable` and defines the external `pause()` and `unpause()` functions. 

This suggests that the intention is to be able to pause withdrawals during emergencies.

```
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
```
```
    function claim(uint256 withdrawRequestIndex) external nonReentrant {
```

However, the `withdraw()` and `claim()` functions within the `WithdrawQueue` contract lack the `whenNotPaused` modifier. This means that the pause mechanism isn't correctly implemented in the `WithdrawQueue` contract.

## Impact
In the event of an emergency, such as a hack, where further withdrawals could lead to losses for users and the protocol, the protocol team won't be able to pause the `withdraw()` and `claim()` functions.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add the `whenNotPaused` modifier to the `withdraw()` and `claim()` functions.
