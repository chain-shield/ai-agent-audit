# Vulnerability details

In `OperatorDelegator.sol` , users can donate ether which triggers the `receive()` function. Within the function there are gas implementation for the users. The if statements is written specifically for the donors. However since we know that donors will never interact with this state variable `adminGasSpentInWei[tx.origin]`, it will always skip this if statement, causing the excess gas to not be send back to users.

```solidity
    receive() external payable nonReentrant {
        // check if sender contract is EigenPod. forward full withdrawal eth received
        if (msg.sender == address(eigenPod)) {
            restakeManager.depositQueue().forwardFullWithdrawalETH{ value: msg.value }();
        } else {
            // considered as protocol reward
            uint256 gasRefunded = 0;
            uint256 remainingAmount = msg.value;
            //@audit-issue Med will not be executed for donators. because adminGasSpentInWei[tx.origin] will always be 0
            if (adminGasSpentInWei[tx.origin] > 0) {
                gasRefunded = _refundGas();
                // update the remaining amount
                remainingAmount -= gasRefunded;
                // If no funds left, return
                if (remainingAmount == 0) {
                    return;
                }
            }
            // Forward remaining balance to the deposit queue
            address destination = address(restakeManager.depositQueue());
            (bool success, ) = destination.call{ value: remainingAmount }("");
            if (!success) revert TransferFailed();

            emit RewardsForwarded(destination, remainingAmount);
        }
    }
```

## Impact
Excess gas ether are not sent back to users.


## Tools Used
Manual Review
## Recommended Mitigation Steps
Implement logic that tracks all donors gas fees instead of only admin. OR 
Completely remove that logic and specify in documentation, all fess are forwarded hence no excess gas ether refund.
