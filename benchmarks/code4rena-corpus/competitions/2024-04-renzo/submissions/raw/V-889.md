# Vulnerability details

## Impact
When the buffer to fill value is queried from the `withdrawQueue` contract to get the amount of deficit of the token being deposited, the function checks if that value is greater than zero, if it is it subtracts from the just transferred tokens and sends it to the `withdrawQueue` contract, but in a particular situation when the amount is less than or equal to the buffer to fill, the buffer to fill becomes that amount using the whole deposit to fill the buffer, this is alright, but what followed after the if block was a deviation from the blueprint of the rest of the protocol code, where after a subtraction of tokens a check was implemented to see if they are tokens left, but in this function that check was not implemented, which will lead to a DOS when the deposit function is called in the `OperatorDelegator`. 

## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L539C9-L563C1

```solidity
// Transfer the collateral token to this address
        _collateralToken.safeTransferFrom(msg.sender, address(this), _amount);

        // Check the withdraw buffer and fill if below buffer target
        uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(
            address(_collateralToken)
        );
        if (bufferToFill > 0) {
            bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
            // update amount to send to the operator Delegator
            _amount -= bufferToFill;

            // safe Approve for depositQueue
            _collateralToken.safeApprove(address(depositQueue), bufferToFill);

            // fill Withdraw Buffer via depositQueue
            depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
        }

        // Approve the tokens to the operator delegator
        _collateralToken.safeApprove(address(operatorDelegator), _amount);

        // Call deposit on the operator delegator
        operatorDelegator.deposit(_collateralToken, _amount);
//@audit This call here will revert, as the deposit function does not allow zero value deposits
```
This is fairly straight forward issue without the zero check if the amount being sent as being reduced to zero due to filling the buffer the `OperatorDelegator` contract will revert every time in that scenario
