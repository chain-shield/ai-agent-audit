# Vulnerability details

## Impact
Under specific conditions, user deposits will always revert.

## Proof of Concept
When a user deposits funds through `RestakeManager`, the function checks the withdraw buffer and fill it if it is below the buffer target determined by `bufferToFill`. 

If it needs to be filled, line [RestakeManager#L547](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L547) checks whether the transferred `_amount` is less than or equal to `bufferToFill`.
```solidity
bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
```
The case where `_amount` is equal to `bufferToFill` is incorrectly handled as after subtraction the `_amount` value will be 0 [RestakeManager#L549](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L549C13-L549C37).
```solidity
_amount -= bufferToFill;
```
That leads to a revert during `operatorDelegator.deposit` line [RestakeManager#L562](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L562), as it will not be able to pass the requirement for `tokenAmount` in [OperatorDelegator#L147](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L147)
```solidity
        if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Handle separately the case in which the entire `_amount` goes towards filling the `bufferToFill` (`_amount == bufferToFill`). If the amount equals 0 after paying `bufferToFill`, do not try to deposit it to `operatorDelegator`, allocate the appropriate amount of tokens to the user.
