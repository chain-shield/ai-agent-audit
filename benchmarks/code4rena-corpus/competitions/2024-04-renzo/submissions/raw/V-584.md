# Vulnerability details

## Impact

`XERC20` and `OptimismMintableXERC20` lack access control on `mint()` and `burn()`, allowing anyone to access those functions

## Proof of Concept

The `XERC20` and `OptimismMintableXERC20` contracts currently do not have any access control for important functions such as `mint()` and `burn()`. This allows any actor to come in and maliciously use those functions to manipulate the supply and price of the deployed tokens.

```
function mint(address _user, uint256 _amount) public virtual {
    _mintWithCaller(msg.sender, _user, _amount);
}

function burn(address _user, uint256 _amount) public virtual {
    if (msg.sender != _user) {
        _spendAllowance(_user, msg.sender, _amount);
    }

    _burnWithCaller(msg.sender, _user, _amount);
}

```

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add access control so only authorized parties can access those functions
