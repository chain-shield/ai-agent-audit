# Vulnerability details

## Impact
All nonreetrant modifiers will be vulnerable to reentrant attacks and cross-reentrant attacks because it wasn't initialized in the initialize function.

## Proof of Concept

In the absence of this proper implementation, all functions that rely on or have assumed there is a check against reentrancy attack will not be true unfortunately

Attackers can create a vulnerability by exploiting the non-reentrant modifier in every function.

## Tools Used
Manual review, githublens

## Recommended Mitigation Steps
Implement the upgradeable reentrancy guard properly like this;

```
 __ReentrancyGuard_init();
```

Upgradable
