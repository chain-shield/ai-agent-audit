# Vulnerability details

## Impact
If `OperatorDelegator::receive()` is called with a small msg.value then the call will revert due to an underflow. This will disrupt protocol functionality.

## Proof of Concept

[OperatorDelegator::receive()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L501-L525)
```solidity
    receive() external payable nonReentrant {
        // check if sender contract is EigenPod. forward full withdrawal eth received
        if (msg.sender == address(eigenPod)) {
            restakeManager.depositQueue().forwardFullWithdrawalETH{ value: msg.value }();
        } else {
            // considered as protocol reward
            uint256 gasRefunded = 0;
            uint256 remainingAmount = msg.value;
            if (adminGasSpentInWei[tx.origin] > 0) {
                gasRefunded = _refundGas();
                // update the remaining amount
                remainingAmount -= gasRefunded;
                // If no funds left, return
                if (remainingAmount == 0) {
                    return;
                }
            }
            // Forward remaining balance to the deposit queue
            address destination = address(restakeManager.depositQueue());
            (bool success, ) = destination.call{ value: remainingAmount }("");
            if (!success) revert TransferFailed();

            emit RewardsForwarded(destination, remainingAmount);
        }
    }
```
If the `msg.value` of the call is less than `address(this)` including the added `msg.value` from the call, and is less than `adminGasSpentInWei[tx.origin]` then the amount of gas refunded will be more than `msg.value` (as long as the admin has some stored gas refund funds allocated).

```solidity
            uint256 remainingAmount = msg.value;
            if (adminGasSpentInWei[tx.origin] > 0) {
                gasRefunded = _refundGas();
                // update the remaining amount
                remainingAmount -= gasRefunded;
```
As seen above, `remainingAmount -= gasRefunded` can underflow if `gasRefunded` is greater than the `msg.value` as outlined previously. This will cause the call to erroneously revert.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Check if `gasRefunded` is greater than `msg.value` if so then set `remainingAmount` to 0 rather than subtracting. This will solve the underflow revert issue.


## Assessed type

Under/Overflow
