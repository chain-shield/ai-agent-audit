# Vulnerability details

## Impact
The `withdraw` function in the `withdrawQueue` has a 0 check on withdraws, which is a good first step, but the contract does not enforce a minimum transaction amount for withdrawals. This lack of minimum amount check can be exploited by attackers to perform a dust attack, clogging the network with numerous small transactions.

Attackers can spam the network with a large number of small withdrawal transactions, causing congestion and potentially leading to a denial of service. This can disrupt the normal functioning of the protocol and negatively impact the user experience.

## Proof of Concept
Bob notices that the `withdraw` function in the `withdrawQueue` contract does not enforce a minimum transaction amount.

Bob creates a script that automatically sends a large number of withdrawal requests with very small amounts (dust transactions) to the `withdraw` function.

The `withdrawQueue` contract processes these numerous small withdrawal requests, consuming gas and clogging the network.

Alice and other users experience delays and increased transaction costs when attempting to interact with the protocol due to the network congestion caused by Bob's dust attack.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a minimum transaction amount check in the withdraw function. Reject withdrawal requests that fall below a certain threshold to prevent spam and dust attacks.
