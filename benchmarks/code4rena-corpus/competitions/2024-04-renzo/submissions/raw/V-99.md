# Vulnerability details

## Summary
`RewardHandler::forwardRewards()` lacks `payable` modifier. If `value` is not zero, it could always revert.

## Proof of Concept
[RewardHandler::forwardRewards()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Rewards/RewardHandler.sol#L56-L60) lacks payable. The caller cannot send the `value`.
```solidity
    /// @dev Forwards all native ETH rewards to the DepositQueue contract
    /// Handle ETH sent to this contract from validator nodes that do not trigger contract execution - e.g. rewards
    function forwardRewards() external nonReentrant onlyNativeEthRestakeAdmin {
        _forwardETH();
    }
```
This function calls [_forwardETH()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Rewards/RewardHandler.sol#L62-L70) which is not payable as well.
```solidity
    function _forwardETH() internal {
        uint256 balance = address(this).balance;
        if (balance == 0) {
            return;
        }


        (bool success, ) = rewardDestination.call{ value: balance }("");
        if (!success) revert TransferFailed();
    }
```

## Impact
`RewardHandler::forwardRewards()` cannot work if `value != 0`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a `payable` modifier.

```solidity
    function forwardRewards() external nonReentrant payable onlyNativeEthRestakeAdmin {
        _forwardETH();
    }
```
