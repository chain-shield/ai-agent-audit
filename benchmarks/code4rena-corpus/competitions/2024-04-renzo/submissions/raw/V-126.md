# Vulnerability details

## Impact
The deposit function trades the `amountIn` tokens given by the 

the user  using its `_trade` method , fetches the price of the ezETH from oracle 

and calculates the amount of xezETH to be minted.

This should be calculated as `amountOut/_lastPrice`

because both are 18 decimals as given by the comments and 

clear from the swap function `_trade`.

```solidity

        // Calculate the amount of xezETH to mint - assumes 18 decimals for price and token
        uint256 xezETHAmount = (1e18 * amountOut) / _lastPrice;

```
However, the protocol incorrectly scales the amount Out by 1e18 which is

incorrect because both price and token `amountOut` has 18 decimals

so this "scaling" will effectively result in 1e18 times more ezETH to be minted 

than it actually need to which will be a huge loss.


## Proof of Concept
For example suppose 
price of xezETH is 3000$.

and users pass in the amountIn of deposit token worth one eth.

What this function will do is it will mint 1e18 eth = `1e9 Billion xezETH `
Approx `1e12 Billion USD` worth of eth instead of `3k USD`.

Due to `amountOut` being multiplied by 1e18.

## Tools Used
Manual review 
## Recommended Mitigation Steps
Remove the incorrect 1e18 multiplication 

and calculate the price as follows

```solidity

        // Calculate the amount of xezETH to mint - assumes 18 decimals for price and token
        uint256 xezETHAmount = amountOut / _lastPrice;

```
