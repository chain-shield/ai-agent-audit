# Vulnerability details

The `depositTokenRewardsFromProtocol()` function  in `RestakeManager` contract does not enforce the maximum Total Value Locked (TVL) limit for individual tokens when depositing ERC20 token rewards, potentially allowing the TVL to exceed predefined limits.

## Impact
Failing to check against `MaxTokenTVLReached` could lead to an imbalance in the protocol's risk profile by allowing excessive concentration in a single token. This oversight may result in the protocol's TVL exceeding the risk management parameters set by the protocol administrators.

## Proof of Concept
The function in question is designed to deposit ERC20 token rewards and is only callable by the depositQueue:

```solidity
    function depositTokenRewardsFromProtocol(
        IERC20 _token,
        uint256 _amount
    ) external onlyDepositQueue {
        // Get the TVLs for each operator delegator and the total TVL
        (, uint256[] memory operatorDelegatorTVLs, uint256 totalTVL) = calculateTVLs();

        // Determine which operator delegator to use
        IOperatorDelegator operatorDelegator = chooseOperatorDelegatorForDeposit(
            operatorDelegatorTVLs,
            totalTVL
        );

        // Transfer the tokens to this address
        _token.safeTransferFrom(msg.sender, address(this), _amount);

        // Approve the tokens to the operator delegator
        _token.safeApprove(address(operatorDelegator), _amount);

        // Deposit the tokens into EigenLayer
        operatorDelegator.deposit(_token, _amount);
    }
```

Unlike the `deposit()` function, `depositTokenRewardsFromProtocol()` does not include a check for `collateralTokenTvlLimits` to ensure the deposit does not exceed the maximum allowable TVL for the token being deposited.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a check within `depositTokenRewardsFromProtocol()` similar to the one in the `deposit()` function to verify that the deposit will not cause the TVL for the token to surpass its limit.

Before the actual deposit logic, this check should be performed to ensure compliance with the protocol's risk parameters. Additionally, consider emitting an event for successful reward deposits for enhanced transparency and tracking.
