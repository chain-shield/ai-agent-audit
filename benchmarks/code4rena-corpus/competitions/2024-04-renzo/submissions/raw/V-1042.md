# Vulnerability details

## Impact
The contract contains functions that check for zero addresses (_newXRenzoBridgeL1, _newChainSelector, _newXRenzoDeposit) before updating certain important variables (xRenzoBridgeL1, ccipEthChainSelector, xRenzoDeposit). 

However, these functions do not check if the new address values have already been set. 
This might lead to unexpected results, especially when the new address values are already in use. 

## Proof of Concept
The example of the issue can be seen in the below functions:

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/PriceFeed/CCIPReceiver.sol#L96-L100

```solidity
function updateXRenzoBridgeL1(address _newXRenzoBridgeL1) external onlyOwner {
    if (_newXRenzoBridgeL1 == address(0)) revert InvalidZeroInput();
    emit XRenzoBridgeL1Updated(_newXRenzoBridgeL1, xRenzoBridgeL1);
    xRenzoBridgeL1 = _newXRenzoBridgeL1;
}

function setRenzoDeposit(address _newXRenzoDeposit) external onlyOwner {

In the above functions, the contract correctly checks that the new addresses are not zero. However, it fails to verify that the new address is different from the current address.

## Recommended Mitigation Steps

In addition to checking for zero addresses, these functions should include a check to verify that the new addresses are not the same as the previous ones. This can prevent accidental override of these values and ensure the contract behaves as expected.

For example:

```solidity
function updateXRenzoBridgeL1(address _newXRenzoBridgeL1) external onlyOwner {
    if (_newXRenzoBridgeL1 == address(0) || _newXRenzoBridgeL1 == xRenzoBridgeL1) revert InvalidInput();
    emit XRenzoBridgeL1Updated(_newXRenzoBridgeL1, xRenzoBridgeL1);
    xRenzoBridgeL1 = _newXRenzoBridgeL1;
}
```
In the above function, we have added `|| _newXRenzoBridgeL1 == xRenzoBridgeL1` in the `if` condition to check for same addresses. Similar changes should be made to the `updateCCIPEthChainSelector` and `setRenzoDeposit` functions as well.
