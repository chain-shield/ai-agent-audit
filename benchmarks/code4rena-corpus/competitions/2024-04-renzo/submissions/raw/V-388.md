# Vulnerability details

## Impact
The absence of a sequencer health check in the [getMintRate](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/L2/Oracle/RenzoOracleL2.sol#L50) function could lead to the smart contract using outdated or incorrect price data. This can result in incorrect minting rates for tokens, potentially leading to financial losses for users and undermining the integrity of the system.

## Proof of Concept
The `getMintRate` function in the `RenzoOracleL2` contract does not account for potential downtime of the L2 sequencer.
```javascript
    function getMintRate() public view returns (uint256, uint256) {
        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        // @c4-audit no check for Sequencer(L2)
        uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
        if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
    }
```
If the sequencer goes down, the index oracles may have stale prices, since L2-submitted transactions (i.e. by the aggregating oracles) will not be processed. [Read here](https://docs.chain.link/data-feeds/l2-sequencer-feeds)

function isSequencerActive() internal view returns (bool) {
    (, int256 answer, uint256 startedAt,,) = sequencer.latestRoundData();
    if (block.timestamp - startedAt <= GRACE_PERIOD_TIME || answer == 1)
        return false;
    return true;
}
