# Vulnerability details

## Impact
The `deposit` and `depositTokenRewardsFromProtocol` functions in the `RestakeManager` contract ignore the return values of the `operatorDelegator.deposit()` calls.

Incorrect Tracking of User Deposits:

If the deposit function ignores a failed `operatorDelegator.deposit()` call, the protocol could incorrectly track the user's deposit, leading to discrepancies in the user's balances and the protocol's overall TVL.

This could result in the protocol minting an incorrect amount of ezETH tokens for the user or updating the TVL incorrectly.

Incorrect Tracking of Rewards:

In the case of the `depositTokenRewardsFromProtocol` function, ignoring a failed `operatorDelegator.deposit()` call could lead to incorrect tracking of the protocol's rewards.

The protocol might update the "total rewards earned" value or the user's reward balances incorrectly, leading to inconsistencies and potential issues with reward distribution.

Loss of Funds:

If the `deposit` or `depositTokenRewardsFromProtocol` functions ignore a failed `operatorDelegator.deposit()` call, the user's funds or the protocol's rewards could potentially be lost or unaccounted for.

This could result in financial losses for users or the protocol, affecting the overall integrity and trust in the system.

## Proof of Concept
An Admin calls the deposit function on the `OperatorDelegator` contract, attempting to make a deposit with a large amount of tokens, but the deposit fails due to some reason (e.g., insufficient funds, token contract reverts, network congestion, etc.).

Admin calls the `depositTokenRewardsFromProtocol` function, passing in the same token and amount as the failed `OperatorDelegator` deposit.

The `RestakeManager::depositTokenRewardsFromProtocol` function calls `operatorDelegator.deposit`(_token, _amount) but ignores the return value of this call. Since the `OperatorDelegator` deposit failed, the `RestakeManager` will still proceed to the next steps, potentially updating the protocol's rewards tracking incorrectly.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Update the `depositTokenRewardsFromProtocol` function to check the return value of the `operatorDelegator.deposit()` call and handle any failures appropriately, such as by reverting the transaction or logging an error.

Consider using the recommended `OpenZeppelin SafeERC20` library to handle ERC20 token interactions, which provides a safe wrapper around the transfer and transferFrom functions and checks the return values.
