# Vulnerability details

## Summary
The `_mintWithCaller()` function does not mint tokens for non-lockbox callers due to a missing `_mint()` call.

## Proof of Concept
The [mint()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20.sol#L96-L98) function is used to mint tokens for a user.
```solidity
    // @notice Mints tokens for a user
    function mint(address _user, uint256 _amount) public virtual {
        _mintWithCaller(msg.sender, _user, _amount);
    }
```
This internally calls [_mintWithCaller()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20.sol#L352-L356) which then checks if the caller is not the `lockbox`. For non-lockbox callers, it retrieves the current minting limit, checks if it's sufficient, and updates it by calling [_useMinterLimits()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20.sol#L205-L209).
```solidity
        if (_caller != lockbox) {
            uint256 _currentLimit = mintingCurrentLimitOf(_caller);
            if (_currentLimit < _amount) revert IXERC20_NotHighEnoughLimits();
            _useMinterLimits(_caller, _amount);
        }
```
> [_useMinterLimits()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20.sol#L205-L209)
```solidity
    function _useMinterLimits(address _bridge, uint256 _change) internal {
        uint256 _currentLimit = mintingCurrentLimitOf(_bridge);
        bridges[_bridge].minterParams.timestamp = block.timestamp;
        bridges[_bridge].minterParams.currentLimit = _currentLimit - _change;
    }
```
This function updates a bridge's minting limit by:

- Fetching the bridge's `_currentLimit`  limit.
- Setting the bridge's last operation timestamp to the current `block.timestamp`.
- Decreasing the bridge's `_currentLimit`  by the amount minted.

The issue in the provided code is that after `_useMinterLimits()` is called to update the bridge's minting limit, there is no subsequent call to the `_mint()` function to actually create and allocate the tokens to the `_user`.
The missing `_mint()` call should occur regardless of whether the caller is the `lockbox` or another address, as long as the minting limit allows it.

## Impact
The bridge's minting capacity is reduced as if tokens were minted, but no tokens are actually minted for the user

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the missing `_mint()` function call within `_mintWithCaller()` after the limit check and update.

```solidity
        if (_caller != lockbox) {
            uint256 _currentLimit = mintingCurrentLimitOf(_caller);
            if (_currentLimit < _amount) revert IXERC20_NotHighEnoughLimits();
            _useMinterLimits(_caller, _amount);
            _mint(_user, _amount); // @ audit Add this line to mint tokens
        }
```
