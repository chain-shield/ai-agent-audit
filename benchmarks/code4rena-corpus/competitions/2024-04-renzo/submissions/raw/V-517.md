# Vulnerability details

## Impact
the `xRenzoBridge` code has a `sendPrice()` function which uses chainlink ccip to send messages across chain. Before sending, it checks the cost price for the cross chain message request via `ccipRouter.getFee()`. This function can return 0 if message to be sent is invalid as seen [here](https://docs.chain.link/ccip/api-reference/i-router-client#getfee). In the event where an invalid message is to be sent, the `sendPrice()`  function wont revert but instead emit the `MessageSent` event even though its a bad message and it will never be delivered on the destination chain.

## Proof of Concept
 ` sendPrice()` calls `linkRouterClient.getFee()` as seen [here](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/L1/xRenzoBridge.sol#L232) to get the fees. `linkRouterClient.getFee()` can return 0 value. in [`linkRouterClient.getFee()`](https://github.com/smartcontractkit/ccip/blob/a3d9577c2540473731fff1e677fbc1442e72d97e/contracts/src/v0.8/ccip/Router.sol#L77C1-L89C4) code, we can see a call to the `IEVM2AnyOnRamp.getFee()` function after some sanitization checks.  


```
  /// @inheritdoc IRouterClient
  function getFee(
    uint64 destinationChainSelector,
    Client.EVM2AnyMessage memory message
  ) external view returns (uint256 fee) {
    if (message.feeToken == address(0)) {
      // For empty feeToken return native quote.
      message.feeToken = address(s_wrappedNative);
    }
    address onRamp = s_onRamps[destinationChainSelector];
    if (onRamp == address(0)) revert UnsupportedDestinationChain(destinationChainSelector);
    return IEVM2AnyOnRamp(onRamp).getFee(destinationChainSelector, message);
  }
```
`IEVM2AnyOnRamp(onRamp).getFee(destinationChainSelector, message);` code is seen [here](https://github.com/smartcontractkit/ccip/blob/b4081768c24ce30cd74930255662bb5d4eaa5369/contracts/src/v0.8/ccip/onRamp/EVM2EVMOnRamp.sol#L472C2-L533C4) and the math can return 0 as [described in the docs](https://docs.chain.link/ccip/api-reference/i-router-client#getfee) 


after fees is gotten in `sendPrice()`, the 0 amount is then used in the token approval process before `CCIPRouter.ccipSend()` is called. 

in `CCIPRouter.ccipSend()` logic, `IEVM2AnyOnRamp(onRamp).getFee(destinationChainSelector, message);` is called again as seen below

Aftet this a [Transfer of the tokens to the token pools](https://github.com/smartcontractkit/ccip/blob/b4081768c24ce30cd74930255662bb5d4eaa5369/contracts/src/v0.8/ccip/Router.sol#L134C1-L142C6) is the next step in logic but that is skipped in this case as there are no tokens to be transferred.
