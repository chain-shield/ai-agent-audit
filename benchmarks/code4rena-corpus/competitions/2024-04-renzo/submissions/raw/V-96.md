# Vulnerability details

## Impact
`RenzoOracleL2::getMintRate()` retrieves the price of `ezETH` in `ETH`, however if the price of `ezETH` is less than `1 ETH` the function will revert. The price of `1 ezETH` can be less than `1 ETH` due to market forces. 

At the time of writing, the [chainlink ezeth-eth](https://data.chain.link/feeds/ethereum/mainnet/ezeth-eth) oracle states that `1 ezETH` is worth `0.9868 Ether`. Meaning in the current code, the function would revert incorrectly.

## Proof of Concept
[RenzoOracleL2::getMintRate()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/Oracle/RenzoOracleL2.sol#L46-L57)
```solidity
    /**
     * @notice Pulls the price of ezETH
     * @dev reverts if price is less than 1 Ether
     */
    function getMintRate() public view returns (uint256, uint256) {
        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        // scale the price to have 18 decimals
        uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
        if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
    }
```
Currently `getMintRate()` will revert if _`scaledPrice` is less than 1 ether, this is because it is assumed that `ezETH` should always be worth more than 1 ether as it accumulates rewards.

However it is possible for the actual rate of `ezETH` to be less than `ETH` due to issues with the protocol, bad press, long redemption queues, etc 

## Tools Used

Manual Review

## Recommended Mitigation Steps

Change the check to check for 0 price to avoid erronoues responses. If the protocol is worried about erroneous prices from the oracle, consider using 2 oracles and averaging the price.
