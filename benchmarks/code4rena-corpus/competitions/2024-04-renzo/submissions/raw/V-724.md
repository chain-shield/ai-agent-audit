# Vulnerability details

## Impact
The ``OperatorDelegator.activateRestaking()`` and ``OperatorDelegator.startDelayedWithdrawUnstakedETH()`` will always revert when called. This is due to a clause in the ``eigenPod`` contract which enables restaking by default during initialization. 

The eigenpod manager initializes the pod, which inturn sets ``eigenpod.hasRestaked`` to true. Which is checked in both `` eigenPod.activateRestaking();`` and ``eigenPod.withdrawBeforeRestaking();``. 
Therefore withdrawBeforeRestaking can't  be used to sweep eth from the Pod contract.

## Proof of Concept
The eigenpod contract can be found in: https://github.com/Layr-Labs/eigenlayer-contracts?tab=readme-ov-file#eigenpods-1 
The modifier below causes the restrictions
```solidity
    modifier hasNeverRestaked() {
        require(!hasRestaked, "EigenPod.hasNeverRestaked: restaking is enabled");
        _;
    }
```

## Recommended Mitigation Steps
Remove both functions from the contract completely as withdrawals cannot be made through them
