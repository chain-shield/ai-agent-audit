# Vulnerability details

## Impact
In xRenzoDEposit.sol users can deposit both NATIVEETH in `depositETH` which is wrapped into WETH  or directly deposit WETH as the collateral token in `deposit` and mints xezETH.
The problem lies in the 2nd deposit function because of WETH compatibility in different chains.

## Proof of Concept
```
   function deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) external nonReentrant returns (uint256) {
        if (_amountIn == 0) {
            revert InvalidZeroInput();
        }

        // Transfer deposit tokens from user to this contract
        depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);

        return _deposit(_amountIn, _minOut, _deadline);
    }
```
However, the transfer done using `weth.safeTransferFrom`  This works fine on most chains (Ethereum, Optimism, Polygon, BSC) which uses the standard WETH9 contract that handles the case  when src == msg.sender:
But for chains like Fantom/Arbitrum/Blast it has a different implementation

## Tools Used
Manual Review

## Recommended Mitigation Steps
Use safeTransfer instead of safeTransferFrom
