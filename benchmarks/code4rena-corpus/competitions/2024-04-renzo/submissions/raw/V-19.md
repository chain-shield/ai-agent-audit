# Vulnerability details

The implementation of `WBETHShim.sol` and `METHShim.sol` is update time is hardcoded and doesn't check with Coinbase heartbeat latest update. The `int256(wBETHToken.exchangeRate())` utilized the wBETH created by coinbase, but there isn't a check if price is updated or staled.

## Impact
Heartbeat hardcoded update timestamp guarantees staled data

## Proof of Concept
It is known that the wBETH is not in Chainlink surprisingly. This function gets the price of 1 wBETH in ETH from the wBETH staking contract with 18 decimal precision
```solidity
    function _getWBETHData()
        internal
        view
        returns (
            uint80 roundId,
            int256 answer,
            uint256 startedAt,
            uint256 updatedAt,
            uint80 answeredInRound
        )
    {
        return (0, int256(wBETHToken.exchangeRate()), 0, block. Timestamp, 0);
    }
```
```solidity
//METHShim.sol
    function _getMETHData()
```

## Recommended Mitigation Steps
Read more mitigation here: https://docs.cdp.coinbase.com/exchange/docs/websocket-channels#heartbeat-channel

Subscribe to the heartbeats channel to receive heartbeats messages for specific products every second. Heartbeats include a heartbeat_counter which verifies that no messages were missed.
