# Vulnerability details

Updating the token strategy with `setTokenStrategy` while funds are deposited can lead to locked funds, inconsistent contract state, and accounting errors.

## Impact
Funds deposited in the previous strategy may not be accounted for or accessible after the strategy update, potentially resulting in loss of funds and inaccurate tracking of user balances.

## Proof of Concept
The `setTokenStrategy` function is located [here](#https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L106C1-L114C6).

```solidity
    function setTokenStrategy(
        IERC20 _token,
        IStrategy _strategy
    ) external nonReentrant onlyOperatorDelegatorAdmin {
        if (address(_token) == address(0x0)) revert InvalidZeroInput();

        tokenStrategyMapping[_token] = _strategy;
        emit TokenStrategyUpdated(_token, _strategy);
    }
```
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L106C1-L114C6

The `tokenStrategyMapping` update is performed without checking for existing deposits, which can be seen line 112.

## Tools Used
Manual Review

## Recommended Mitigation Steps
- Implement a check within `setTokenStrategy` to prevent strategy updates if there are existing deposits.
- Create a migration function to safely transfer funds from the old strategy to the new one before updating the mapping.
