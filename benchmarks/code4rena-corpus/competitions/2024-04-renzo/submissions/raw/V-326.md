# Vulnerability details

## Impact
Loss of fees.

## Proof of Concept
The issue lies in the fact that there is no check to prevent the feeAddress from being set to zero when feeBasisPoints is zero. 

This means that an authorized caller (e.g., onlyRestakeManagerAdmin) can set both feeAddress and feeBasisPoints to zero, effectively disabling fee collection or redirecting fees to an unintended address (zero address).

## Tools Used
Manual review

## Recommended Mitigation Steps
Add an additional check to ensure that feeAddress cannot be set to zero when feeBasisPoints is zero or guard against setting feeBasisPoints to zero.
