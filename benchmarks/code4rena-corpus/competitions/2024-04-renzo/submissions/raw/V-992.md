# Vulnerability details

## Summary

The function stakeManager:calculateTVLs plays a critical role in determining the Total Value Locked (TVL) within the protocol, influencing the amount of ezETH users receive for their deposits and the valuation of their withdrawals. a flaw in the price oracle integration leads to inaccurate TVL reporting, which could result in significant financial discrepancies for users.

## Vulnerability Detail

The stakeManager:calculateTVLs function is designed to aggregate the TVL from various sources within the protocol, including operator delegators, deposit queues, and withdrawal queues. The calculation for the withdrawal queue is particularly problematic:

```solidity=316
if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
=>                        collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }
```

This code segment attempts to determine the value of assets held in the withdrawal queue by querying the balance of each supported token (collateralTokens[j]) and evaluating its worth in terms of ETH. However, due to a critical oversight, the oracle fetches the price using collateralTokens[i] as the reference token instead of collateralTokens[j]. This misalignment between the queried token and the token for which the balance is checked results in a value calculation based on the wrong price.

The error in using collateralTokens[i] for collateralTokens[j]'s value could lead to the TVL being reported as either overvalued or undervalued, depending on the relative prices of the tokens involved. For instance, if the price of collateralTokens[i] is higher than that of collateralTokens[j], the computed TVL will be undervalued, and vice versa.

## Proof Of Concept

This flaw in the TVL calculation leads to potential financial imbalances and can be exploited as demonstrated in the following scenario:

- Attack Scenario
    - assumptions:
        - stETH/ETH = 1:1
        - wbETH/stETH = 2:1 (just for easy calculations)
        - the collateralTokens array = [stETH,wbETH]
        - withdrawal queue is empty 
        - there are 2 depositers each deposited 10e18 stETH and have 10e18 ezETH
    1. Alice comes and deposits 10e18 wbETH, she gets 20e18 ezETH, but the withdrawal buffer is empty so 10wbETH goes to the withdrawal queue
    2. Bob deposits after alice 10e18 stETH , the tvl calculation is 20ETH + renzoOracle.lookupTokenValue(
                       collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    ) = lookupTokenValue(stETH,10) = 10ETH = 30ETH
    3. so bob gets 10 * totalSupply(ezETH)/tvl = 10*40/30 = 13.3333e18 
    4. as we can see bob gets more than the first two depositers although he gave the ame amount effectively stealing from other users.


## Impact

The incorrect calculation of TVL due to the bug directly impacts the fair distribution of ezETH among users, leading to potential losses for some while unfairly benefiting others. This flaw undermines the protocol's integrity, causing trust issues and financial discrepancies that can deter user participation and investment.
