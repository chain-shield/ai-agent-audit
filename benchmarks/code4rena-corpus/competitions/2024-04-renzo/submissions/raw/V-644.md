# Vulnerability details

## Impact
The following `RenzoOracle.lookupTokenValue` and `RenzoOracle.lookupTokenAmountFromValue` functions rely on the `price` returned by `oracle.latestRoundData()`. When the market condition becomes volatile, such `price` can become significantly different from its value under normal market condition.

https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Oracle/RenzoOracle.sol#L71-L81
```solidity
    function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
        AggregatorV3Interface oracle = tokenOracleLookup[_token];
        if (address(oracle) == address(0x0)) revert OracleNotFound();

        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        if (price <= 0) revert InvalidOraclePrice();

        // Price is times 10**18 ensure value amount is scaled
        return (uint256(price) * _balance) / SCALE_FACTOR;
    }
```

```solidity
    function lookupTokenAmountFromValue(
        IERC20 _token,
        uint256 _value
    ) external view returns (uint256) {
        AggregatorV3Interface oracle = tokenOracleLookup[_token];
        if (address(oracle) == address(0x0)) revert OracleNotFound();

        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        if (price <= 0) revert InvalidOraclePrice();

        // Price is times 10**18 ensure token amount is scaled
        return (_value * SCALE_FACTOR) / uint256(price);
    }
```

Since the following `RestakeManager.deposit` function calls the `RenzoOracle.lookupTokenValue` function for determining the value of the collateral token amount to be deposited, calling the `RestakeManager.deposit` function can cause the user's deposited collateral token amount to be worth much less and the user to mint much less ezETH than the expected values under normal market condition when the user's `RestakeManager.deposit` transaction is executed at a time that the market suddenly becomes volatile and the corresponding price drops significantly.

Similarly, because the `WithdrawQueue.withdraw` function below calls the `RenzoOracle.lookupTokenAmountFromValue` function for determining the collateral token amount to be redeemed, calling the `WithdrawQueue.withdraw` function can cause the user's sent ezETH amount to be worth much less and the user to redeem a much less collateral token amount than the expected values under normal market condition when the user's `WithdrawQueue.withdraw` transaction is executed at a time that the market suddenly becomes volatile and the corresponding price increases significantly.

Because both `RestakeManager.deposit` and `WithdrawQueue.withdraw` functions have no slippage controls for respectively specifying the minimum ezETH amount to be minted and the minimum collateral token amount to be redeemed, the user cannot revert her or his `RestakeManager.deposit` and `WithdrawQueue.withdraw` transactions when the market suddenly becomes volatile and the corresponding price changes significantly. Such user is forced to accept these unexpectedly lower minted ezETH amount and unexpectedly lower redeemed collateral token amount.

## Proof of Concept
Please add the following test file. Using `forge`, this `test_mintLessEzETHThanExpectedWhenPriceDropsInVolatileMarketCondition` test will pass to demonstrate the described scenario for the case associated with the `RestakeManager.deposit` function. The case for the `WithdrawQueue.withdraw` function can be similar.

```solidity
// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.19;

import { Test } from "forge-std/Test.sol"; // solhint-disable-line no-unused-import

contract C4Test3 is Test {
  uint256 SCALE_FACTOR = 10 ** 18;

  // mock function for RenzoOracle.lookupTokenValue
  function lookupTokenValueMock(uint256 _balance, uint256 price) public view returns (uint256) {
      // Price is times 10**18 ensure value amount is scaled
      return (uint256(price) * _balance) / SCALE_FACTOR;
  }

  // mock function for RenzoOracle.calculateMintAmount
  function calculateMintAmountMock(
      uint256 _newValueAdded
  ) public view returns (uint256) {
    // simulate current value in protocol and existing ezETH supply
    uint256 _currentValueInProtocol = 1_000_000e18;
    uint256 _existingEzETHSupply = 1_000_000e18;

    // Calculate the percentage of value after the deposit
    uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
        (_currentValueInProtocol + _newValueAdded);

    // Calculate the new supply
    uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
        (SCALE_FACTOR - inflationPercentaage);

    // Subtract the old supply from the new supply to get the amount to mint
    uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

    // Sanity check
    require(mintAmount > 0, "InvalidTokenAmount");

    return mintAmount;
  }

  function test_mintLessEzETHThanExpectedWhenPriceDropsInVolatileMarketCondition() external {
    // simulate amount of collateral token to be deposited
    uint256 _amount = 100_000e18;

    // price if market is in normal condition
    uint256 price = 999606190990312300;

    // user would mint ezETHToMintExpected ezETH
    //   if user's RestakeManager.deposit transaction can be executed when market is in normal condition
    uint256 collateralTokenValue = lookupTokenValueMock(_amount, price);
    uint256 ezETHToMintExpected = calculateMintAmountMock(collateralTokenValue);

    // simulate that user's RestakeManager.deposit transaction is executed
    //   at a time that market suddenly becomes volatile and price drops significantly
    price = price * 4 / 5;

    // in this case, ezETHToMintActual ezETH is minted to user since RestakeManager.deposit function has no slippage control
    collateralTokenValue = lookupTokenValueMock(_amount, price);
    uint256 ezETHToMintActual = calculateMintAmountMock(collateralTokenValue);

    // hence, for same current value in protocol and existing ezETH supply,
    //   depositing same amount of collateral token would mint much lower ezETH to user than expected
    assertGt(ezETHToMintExpected - ezETHToMintActual, 10_000e18);
  }
}
```

## Recommended Mitigation Steps
The `RestakeManager.deposit` and `WithdrawQueue.withdraw` functions can be updated to include inputs for respectively specifying the minimum ezETH amount to be minted and the minimum collateral token amount to be redeemed. If the actual minted ezETH amount or the actual redeemed collateral token amount is lower than the corresponding minimum, calling the `RestakeManager.deposit` or `WithdrawQueue.withdraw` function should revert.
