# Vulnerability details

## Description
`OperatorDelegator._refundGas()` uses `send` to send ETH to the `tx.origin`. Although tx.origin is always an EOA, given that static analyzer reported this as a bug, this is expected to be changed to `msg.sender` which now can open to refund being stuck because of `send` implicit gas limit of 2300 gas units depending on implementation of receive function in the caller contract.


## Impact
Impossibility of performing gas refund for smart contracts that consume more than 2300 gas units in their receive function.

## Recommended mitigation
Simply use call instead of send

```diff
    function _refundGas() internal returns (uint256) {
-       uint256 gasRefund = address(this).balance >= adminGasSpentInWei[tx.origin]
-           ? adminGasSpentInWei[tx.origin]
+       uint256 gasRefund = address(this).balance >= adminGasSpentInWei[msg.sender]
+           ? adminGasSpentInWei[msg.sender]
            : address(this).balance;
-       bool success = payable(tx.origin).send(gasRefund);
+       bool success = payable(msg.sender).call(gasRefund);
        if (!success) revert TransferFailed();

        // reset gas spent by admin
-       adminGasSpentInWei[tx.origin] -= gasRefund;
-       emit GasRefunded(tx.origin, gasRefund);
+       adminGasSpentInWei[msg.sender] -= gasRefund;
+       emit GasRefunded(msg.sender, gasRefund);
        return gasRefund;
    }
```
