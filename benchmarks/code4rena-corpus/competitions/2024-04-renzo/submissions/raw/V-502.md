# Vulnerability details

## Impact

The protocol uses Connext to accept deposits from L2 to L1 and then finally deposits it the Renzo protocol. 

For Blast there is a LockboxAdapterBlast that allows users to mint xerc20 and send it to the Blast chain. 

However, Connext does **not** support Blast nor does it have any immediate plans to offer support (https://www.connext.network/ scroll down to supported chains). 

Since the L1 xRenzoBridge will only accept calls from the Connext contract, users that have locked up eth to send xerc20 to blast cannot unlock their eth.  


## Proof of Concept

Alice sends 10 eth to Blast using `LockboxAdapterBlast :: bridgeTo`

```solidity
    function bridgeTo(
        address _to,
        address _erc20,
        address _remoteToken,
        uint256 _amount,
        uint32 _minGasLimit,
        bytes calldata _extraData
    ) external {
        // Sanity check
        if (_amount <= 0) {
            revert AmountLessThanZero();
        }

        address xerc20 = IXERC20Registry(registry).getXERC20(_erc20);
        address lockbox = IXERC20Registry(registry).getLockbox(xerc20);

        // Sanity check
        if (xerc20 == address(0) || lockbox == address(0)) {
            revert InvalidAddress();
        }

        // If using xERC20, the assumption is that the contract should be deployed at same address
        // on both networks.
        if (xerc20 != _remoteToken) {
            revert InvalidRemoteToken(_remoteToken);
        }

        SafeERC20.safeTransferFrom(IERC20(_erc20), msg.sender, address(this), _amount);
        SafeERC20.safeApprove(IERC20(_erc20), lockbox, _amount);
        IXERC20Lockbox(lockbox).deposit(_amount);
        SafeERC20.safeApprove(IERC20(xerc20), blastStandardBridge, _amount);
        L1StandardBridge(blastStandardBridge).bridgeERC20To( 
            xerc20,
            _remoteToken,
            _to,
            _amount,
            _minGasLimit,
            _extraData
        );
    }
```

After some time, Alice wants to retrieve her xerc20 and deposit it in the Renzo protocol. 

However, Connext does not support Blast so there is no way to send the coins back over Connext. 

Supported chains from Connext Documentation: https://docs.connext.network/resources/supported-chains
 
Alice tries to send call xReceive directly but this revert since only the Connext contract is allowed to call the function. 

```solidity
    function xReceive(
        bytes32 _transferId,
        uint256 _amount,
        address _asset,
        address _originSender,
        uint32 _origin,
        bytes memory
    ) external nonReentrant returns (bytes memory) {
        // Only allow incoming messages from the Connext contract
        if (msg.sender != address(connext)) {
            revert InvalidSender(address(connext), msg.sender);
        }
```

As a result, Alice's ETH is stuck on Blast as xerc20 tokens.
