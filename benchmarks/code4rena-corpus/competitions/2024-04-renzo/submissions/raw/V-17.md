# Vulnerability details

## Impact
The use of `.send()` in Solidity for transferring Ether has a gas limitation of 2300, which may not be enough to execute any code in the recipient contract beyond a simple event emission. This can cause unexpected failures if the recipient is a contract.

## Proof of Concept
I have created a test contract to demonstrate the gas limitation of `.send()` and how it can cause unexpected failures. The test contract simply logs the gas remaining after receiving Ether via `.send()` and `.call{value: _amount}("")` methods.

Test contract:
```
contract Test {
    event LogGas(uint256 gas);

    receive() external payable {
        emit LogGas(gasleft());
    }
}
```
The test contract was deployed and Ether was sent to it using both `.send()` and `.call{value: _amount}("")` methods. The results showed that `.send()` consistently resulted in a gas remaining of around 2200, while `.call{value: _amount}("")` resulted in a gas remaining of around 22000.


## Tools Used
Solidity, Truffle, Ganache

## Recommended Mitigation Steps
It is recommended to use the `.call{value: _amount}("")` method instead of `.send()` for transferring Ether to a payable address. This method forwards all available gas and returns a boolean value to indicate success or failure. This will ensure that the transfer does not fail unexpectedly due to gas limitations and will allow for more complex functionality to be invoked in the recipient contract if necessary. The code snippet in the `OperatorDelegator.sol` contract should be updated as follows:
```
(bool success, ) = payable(tx.origin).call{value: gasRefund}("");
```
It is also recommended to add proper error handling to check the return value of the `.call` method and handle potential errors.
