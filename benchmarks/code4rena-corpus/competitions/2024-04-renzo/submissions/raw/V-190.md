# Vulnerability details

## Impact

The `burn` function in OptimismMintableXERC20.sol burns from `_from` and not `msg.sender` which causes that malicious users can burn any tokens in the contract or from other users that have any unspent allowance in the contract.

## Proof of Concept

The `burn` function in OptimismMintableXERC20.sol inherits the implementation from XERC20.sol without adding any access control checks. This creates a vulnerability where any user can potentially burn tokens from either the OptimismMintableXERC20 contract or from other users who have any for of unspent allowance in the contract.

Breakdown: 

OptimismMintableXERC20.sol holds the burn function, which lacks any form of access control and calling the function calls `XERC20.burn(_from, _amount)`. This means anyone can pass in any address of their choice. 

```solidity
    function burn(address _from, uint256 _amount) public override(XERC20, IOptimismMintableERC20) {
        XERC20.burn(_from, _amount);
    }
```

`XERC20.burn` checks if the burner - msg.sender (i.e OptimismMintableXERC20) is the same as the passed in address. If they are not the same, the function calls `_spendAllowance` to verify if the passed in address had granted OptimismMintableXERC20 an allowance to spend that amount.

```solidity
    function burn(address _user, uint256 _amount) public virtual {
        if (msg.sender != _user) {
            _spendAllowance(_user, msg.sender, _amount);
        }

        _burnWithCaller(msg.sender, _user, _amount);
    }
```

What this causes is that any tokens in the OptimismMintableXERC20 contract can be burned by malicious users, as the `if (msg.sender != _user)` check will be bypassed as `msg.sender` will be the `from` or from any user who has any unspent allowance in the OptimismMintableXERC20 contract as the allowance will be spent to burn the tokens.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Two ways to fix this
1. Burn directly from `msg.sender`
```
    function burn(uint256 _amount) public override(XERC20, IOptimismMintableERC20) {
        XERC20.burn(msg,sender, _amount);
    }
```
2. Introduce a form of access control, a burner role that can burn tokens from accounts.
