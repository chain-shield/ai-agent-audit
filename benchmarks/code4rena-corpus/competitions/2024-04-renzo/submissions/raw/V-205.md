# Vulnerability details

## Impact

Chainlink aggregators have a built in circuit breaker if the price of an asset goes outside of a predetermined price band. The result is that if an asset experiences a huge drop in value (i.e. LUNA crash) the price of the oracle will continue to return the minPrice instead of the actual price of the asset. This situation can lead users to continue interacting with the protocol using the asset at an incorrect price, potentially resulting in loss of funds or exploitation of the protocol. This is exactly what happened to [Venus on BSC when LUNA imploded](https://rekt.news/venus-blizz-rekt/).

## Proof of Concept

[RenzoOracle](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Oracle/RenzoOracle.sol) uses Chainlink's price feed to obtain the price of the requested token

```solidity
function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
        AggregatorV3Interface oracle = tokenOracleLookup[_token];
        if (address(oracle) == address(0x0)) revert OracleNotFound();

        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        if (price <= 0) revert InvalidOraclePrice();

        // Price is times 10**18 ensure value amount is scaled
        return (uint256(price) * _balance) / SCALE_FACTOR;
    }
```

However as we mentioned above ChainlinkAggregators have minPrice and maxPrice circuit breakers built into them. This means that if the price of the asset drops below the minPrice, the protocol will continue to value the token at minPrice instead of it's actual value. This situation can lead users to execute transactions at incorrect prices, potentially resulting in loss of funds, or the protocol itself may incur losses.

Example:
TokenA has a minPrice of \$1. The price of TokenA drops to \$0.10. The aggregator still returns \$1 allowing the user perform transactions with TokenA as if it is \$1 which is 10x it's actual value.

## Recommended Mitigation Steps

Protocol should check the returned price against the minPrice/maxPrice and revert if the price is outside of the bounds:

```solidity
    (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
    if (price >= maxPrice or price <= minPrice) revert();
```
