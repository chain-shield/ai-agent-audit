# Vulnerability details

EigenLayer Strategies can be updated, that's why Renzo have a `setTokenStrategy()` function, which allows setting & updating of the strategies:
```solidity
    function setTokenStrategy(IERC20 _token, IStrategy _strategy) external nonReentrant onlyOperatorDelegatorAdmin {
        if (address(_token) == address(0x0)) revert InvalidZeroInput();
        tokenStrategyMapping[_token] = _strategy;
        emit TokenStrategyUpdated(_token, _strategy);
    }
```
While updating the strategy, previous strategy's balance is not recorded. If there is update in strategy, `getTokenBalanceFromStrategy()` will reduce for the updated strategy's asset.  And as the `getTokenBalanceFromStrategy()` is used in the calculation of TVLs, the TotalTVL value will be decreased which will increase the ezETHAmountToMint.

## Proof of Concept
I'll use the `calculateMintAmount()` formula to proof the concept.
Consider this:
- Total TVL = 10_000 ethers (8000 ethers and 2000 stETH Tokens)
- NewValueAdded = 10
- ezETH TotalSupply = 9500
- ezETHMintAmount will be = `9499999999999999990`

But now admin updates the stETH strategy, 2000 stETH balance gone:
- Total TVL = 8000 ethers
- NewValueAdded = 10
- ezETH TotalSupply = 9500
- ezETHMintAmount will be = `11874999999999993353`

As the TVL drops, ezETHMintAmount increases.

I would encourage you to copy-paste this code in remix and play with different values to understand the depth of the issue:
```solidity
contract Calculate {
    uint256 constant SCALE_FACTOR = 10 ** 18;
    function calculateMintAmount(uint256 _currentValueInProtocol, uint256 _newValueAdded, uint256 _existingEzETHSupply) external pure returns (uint256) {
        uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded * 10 ** 18) / (_currentValueInProtocol * 10 ** 18 + _newValueAdded * 10 ** 18);
        uint256 newEzETHSupply = (_existingEzETHSupply * 10 ** 18 * SCALE_FACTOR) / (SCALE_FACTOR - inflationPercentaage);
        uint256 mintAmount = newEzETHSupply - _existingEzETHSupply * 10 ** 18;
        return mintAmount;
    }
} 
```

## Impact
Wrong Calculation of `ezETH` minting amount

## Tools Used
[Shaheen's Jurat-e-Rayindana](https://twitter.com/0x_Shaheen/status/1722664258142650806)

## Recommended Mitigation Steps
Whenever the strategy for the asset is being updated, the previous deposited amount for that strategy should be stored and taken into account while calculating `ezETH`'s amount to mint.
