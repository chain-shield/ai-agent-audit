# Vulnerability details

According to Connext [Doc](#https://docs.connext.network/developers/guides/authentication#checking-origin-data), the `xReceive` function should be authenticated. But the `xReceive` implementation lacks checks to validate the origin domain and source contract, potentially allowing unauthorized transfers.

## Impact
Without proper validation, the contract may process unauthorized or malicious transfers, leading to potential asset loss or manipulation of contract state.

## Proof of Concept
The `xReceive` function is intended to accept only authorized transfers from a specific origin domain and source contract through Connext. However, it only verifies that the caller is the Connext contract and does not validate the origin domain or source contract.

Here is the relevant code snippet from the provided contract:

```solidity
    function xReceive(
        bytes32 _transferId,
        uint256 _amount,
        address _asset,
        address _originSender,
        uint32 _origin,
        bytes memory
    ) external nonReentrant returns (bytes memory) {
        // Only allow incoming messages from the Connext contract
        if (msg.sender != address(connext)) {
            revert InvalidSender(address(connext), msg.sender);
        }
```

The function should also check `_origin` against an expected value and possibly verify the source contract address.

## Recommended Mitigation Steps
Implement additional checks within the xReceive function:

Validate the _origin parameter against a list of trusted origin domains.
Introduce a mechanism to verify the source contract address if necessary.
Add tests to ensure these checks are effective and do not disrupt legitimate transfers.
