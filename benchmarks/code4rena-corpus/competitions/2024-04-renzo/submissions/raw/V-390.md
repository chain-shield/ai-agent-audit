# Vulnerability details

## Impact
In the depositETH function, there was a logic that checked the balance before and after the update. However, this check was missing in the [deposit](https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Bridge/L2/xRenzoDeposit.sol#L204) function, which is an essential update that needs to be made. This check ensures that the xRenzoDeposit function's address has been updated after a safe transfer.

## Proof of Concept
```
 */
    function deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) external nonReentrant returns (uint256) {
        if (_amountIn == 0) {
            revert InvalidZeroInput();
        }

        // Transfer deposit tokens from the user to this contract
        depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);

        return _deposit(_amountIn, _minOut, _deadline);
    }
```
There is no logic in updating the balance of address(this) which holds the WETH values when a user calls either depositETH function or deposit function.

- The depositETH function allows the user to deposit ETH which will be wrapped to WETH and uses the balance update to calculate the price of ETH/WETH and WETH/ETH then xzETH will be minted to the user.

- The deposit function allows users to directly deposit WETH with no mechanism of wrapping, then mints xzETH.

Since no update logic means WETH will never be incremented if your try to get the balance of WETH after the;
```
  depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);
```

## Tools Used
Manual review.

## Recommended Mitigation Steps
Update the balance of the address(this) to ensure there was a transfer made.
