# Vulnerability details

The `LockboxAdapterBlast` contract is intended to streamline the bridging of assets from Ethereum mainnet to the Blast network by combining a deposit into a lockbox and a bridge transfer in a single transaction.

## Impact
The contract contains a critical discrepancy in the use of the `IXERC20Registry` interface which may result in the contract interacting with the registry in an unintended manner, potentially leading to failed transactions or incorrect processing of the bridging operation.

## Proof of Concept
The code in is located in the `bridgeTo` function of the contract:

```solidity
address xerc20 = IXERC20Registry(registry).getXERC20(_erc20);
address lockbox = IXERC20Registry(registry).getLockbox(xerc20);
```
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/Connext/integration/LockboxAdapterBlast.sol#L69C1-L70C72

The `getLockbox` function is being passed an xerc20 address, whereas the interface definition suggests it should be passed an erc20 address. This can be cross-referenced with the interface definition in the contract code 

```solidity
    function getLockbox(address erc20) external view returns (address xerc20);
```

## Recommended Mitigation Steps
Modify the contract to ensure that the getLockbox function is passed the correct erc20 address as per the interface definition. This may involve updating the interface or the contract logic to align with the expected parameters and ensure correct functionality.
