# Vulnerability details

## Impact

Withdraw requests lack expiration and can stay forever if the user doesn’t call `claim()`, causing the withdraw buffer to be lower which forces withdraws from EigenLayer.

## Proof of Concept

The `WithdrawRequest` struct has no expiration parameter, so when someone requests a withdrawal and then doesn't claim it, the `claimReserve` will be larger, causing `getAvailableToWithdraw()` to return less, which will force withdrawals from EigenLayer or mostly any a future withdraw request to revert in `withdraw()` with `NotEnoughWithdrawBuffer`.

```solidity
function getAvailableToWithdraw(address _asset) public view returns (uint256) {
    if (_asset != IS_NATIVE) {
        return IERC20(_asset).balanceOf(address(this)) - claimReserve[_asset];
    } else {
        return address(this).balance - claimReserve[_asset];
    }
}
```

## Recommended Mitigation Steps

Implement withdrawal request expiration logic, as it is unacceptable to allow users to leave their withdrawal request indefinitely. It can be implemented by allowing a certain `maximumClaimDays` and if the user doesn't claim by then, to not being able to claim for that `withdrawRequestIndex` at all, and then periodically admin will reject all requests that are in that state.
