# Vulnerability details

Implementation should not use hardcoded decimals of 1e18. It's possible in the future that collateral to not be 1e18.

```solidity
        // Calculate the amount of xezETH to mint - assumes 18 decimals for price and token
        uint256 xezETHAmount = (1e18 * amountOut) / _lastPrice; //@audit-issue hardcoded decimals
```

## Impact
Unfair tokens minted due to hardcoded decimals

## Tools Used
Manual Review
## Recommended Mitigation Steps
Do not include hardcoded decimals into implementation. Allow mutable variable
