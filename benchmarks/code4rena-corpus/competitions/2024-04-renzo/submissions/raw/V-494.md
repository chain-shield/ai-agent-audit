# Vulnerability details

## Impact
The `_refundGas` function refund the gas to `msg.sender` which is the admin account, but actually it should be refunded to `tx.origin`. If the admin account is non-EOA, this could lead to fund being locked.

## Proof of Concept
The `_refundGas` function refund the gas to `msg.sender` which is the admin account.

```solidity
        (bool success, ) = payable(msg.sender).call{ value: gasRefund }("");
```

The problem is that it may not be the `msg.sender` that pays the gas. If the `msg.sender` is non-EOA, the gas is wrongly refunded to `msg.sender`. In real case, it should always be refunded to `tx.origin`.

If the `msg.sender` is a contract and has no way to retrieve ETH, the refund is forever locked in the contract.

## Tools Used
Manual

## Recommended Mitigation Steps
Refund to `tx.origin` instead of `msg.sender`
