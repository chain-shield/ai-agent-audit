# Vulnerability details

## Impact
The use of `transfer()` function with `IERC20` tokens in the `WithdrawQueue` contract can result in potential loss of funds and transaction failure. Some tokens do not fully comply with the ERC20 standard, such as Tether (USDT) on L1, and their `transfer()` function does not return a boolean value as required by the specification. When these tokens are cast to `IERC20` and the `transfer()` function is called, the function signatures do not match and the call reverts. This can lead to a denial of service and loss of funds for users who are trying to withdraw tokens.

## Proof of Concept
The vulnerable code is located in the `claim()` function of the `WithdrawQueue` contract at lines 305-308 in the file `contracts/Withdraw/WithdrawQueue.sol`. The code uses the `transfer()` function to send tokens to the user.

A specific example of the issue can be seen in this test case: <https://gist.github.com/IllIllI000/2b00a32e8f0559e8f386ea4f1800abc5>

## Tools Used
Manual review

## Recommended Mitigation Steps
To mitigate this vulnerability, it is recommended to use OpenZeppelin's `SafeERC20` library and replace the `transfer()` function with `safeTransfer()`. This will ensure that the function signatures match and the transfer is executed safely, regardless of whether the token fully complies with the ERC20 standard or not. This change will prevent any unexpected behavior and ensure that users can safely withdraw their tokens.
