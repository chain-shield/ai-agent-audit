# Vulnerability details

## Impact
Any additional ETH sent directly to `DepositQueue.sol` via a call to [the payable function forwardFullWithdrawalETH()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L152-L155) is never accounted for inside the `totalEarned` variable as it is done [inside the receive() function](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L179). This approach is taken primarily because `forwardFullWithdrawalETH()` is meant to be called [from inside OperatorDelegator's receive() function](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L504). The fact remains however that ETH can find it's way into the contract & remain there if `forwardFullWithdrawalETH()` is called by someone and the `msg.value` is greater than `withdrawQueue.getBufferDeficit(IS_NATIVE)`, as is clear from the [logic implemented inside the _checkAndFillETHWithdrawBuffer()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L294-L306) function. (_Note that `_checkAndFillETHWithdrawBuffer()` is called whenever [forwardFullWithdrawalETH() is called](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L154)_).<br>
Additionally, **_the protocol has no seperate function either which can sweep/rescue any extra ETH donated_** via `forwardFullWithdrawalETH()` and add it to the `totalEarned[adress(0x0)]` variable. As a result, these ETH remain stuck in the contract.
<br>

What this means is that while the ETH remains unutilized & stuck in the contract, **_the `totalTVL` value is artificially inflated_**. This is because any balance inside `DepositQueue.sol` is considered to be part of `totalTVL` as per the logic [here](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L352) inside `calculateTVLs()`.

## Recommended Mitigation Steps
One or both of these steps can be taken:
1. Check that if the `forwardFullWithdrawalETH()` function has not been called by the OperatorDelegator contract, then the `msg.value` needs to be considered as part of rewards or `totalEarned[address(0x0)]`.
2. Add an admin accessible `sweepSurplusETH()` function inside `DepositQueue.sol`.
