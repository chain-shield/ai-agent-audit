# Vulnerability details


## Impact
When depositing the collateral token into the protocol, it cheks the bufferToFill and fills ERC20 tokens into the withdrawQueue if it's needed.
If bufferToFill is greater than the deposit amount, all deposited tokens are sent to the withdrawQueue and _amount is set to 0.
After that, it tries to deposit the remaining tokens into the [operatorDelegator](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L143~L154) .
But the `OperatorDelegator`'s `deposit` function does not allow the `0` token amount.
This bug effectively prevents users from depositing collateral tokens when the `bufferToFill` is higher than their deposit amount.

## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L542~L562
```solidity
    // Check the withdraw buffer and fill if below buffer target
    uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(
        address(_collateralToken)
    );
    if (bufferToFill > 0) {
        bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
        // update amount to send to the operator Delegator
        _amount -= bufferToFill; // @audit _amount can be 0 here

        // safe Approve for depositQueue
        _collateralToken.safeApprove(address(depositQueue), bufferToFill);

        // fill Withdraw Buffer via depositQueue
        depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
    }
    // Approve the tokens to the operator delegator
    _collateralToken.safeApprove(address(operatorDelegator), _amount); // @audit _amount == 0?

    // Call deposit on the operator delegator
    operatorDelegator.deposit(_collateralToken, _amount); // @audit reverts if _amount == 0

```

```solidity
    function deposit(
        IERC20 token,
        uint256 tokenAmount
    ) external nonReentrant onlyRestakeManager returns (uint256 shares) {
        if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0) // @audit reverts if tokenAmount == 0
            revert InvalidZeroInput();

        // Move the tokens into this contract
        token.safeTransferFrom(msg.sender, address(this), tokenAmount);

        return _deposit(token, tokenAmount);
    }
```

## Recommended Mitigation Steps
It's recommended to add a check if _amount != 0 before calling the `operatorDelegator.deposit`.
```solidity
    // Check the withdraw buffer and fill if below buffer target
    uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(
        address(_collateralToken)
    );
```
