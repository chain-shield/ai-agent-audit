# Vulnerability details

## Impact
Project uses chainlink price feeds to look up token value amount that will be used to redeem/withdraw. So if any such chainlink issues happen it will disrupt the users flow.

## Proof of Concept
The number of issues arising due to chainlink:
* 1. Missing L2 sequencer check [more information here](https://solodit.xyz/issues/m-5-getpricefromchainlink-doesnt-check-if-arbitrum-sequencer-is-down-in-chainlink-feeds-sherlock-none-iron-bank-git) 
> In L2 chains like arbitrium it is important to ensure that the prices fetched  are fresh even when the sequencer is down 
* 2. updateAt refers to the timestamp of the round. This value isn’t checked to make sure it is recent. More importantly a 24hrs  `MAX_TIME_WINDOW` is huge
> Additionally, it is important to be aware of the minAnswer and maxAnswer of the Chainlink oracle, these values are not allowed to be reached or surpassed. See [Chainlink API reference](https://docs.chain.link/docs/price-feeds-api-reference/#variables-and-functions-in-accesscontrolledoffchainaggregator) for documentation on minAnswer and maxAnswer
* 3. Chainlink's multisigs can immediately block access to price feeds at will.



## Tools Used
Manual Analysis

## Recommended Mitigation Steps
1. Check for if sequencer is down
2.* Consider having off-chain monitoring to identify when the market price moves out of [minAnswer, maxAnswer] range
* better to decrease the heartbeat i.e  MAX_TIME_WINDOW 
3. Wrap chainlink answer in a try/catch block
