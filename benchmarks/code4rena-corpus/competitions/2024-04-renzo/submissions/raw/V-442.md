# Vulnerability details

## Impact
If a user attempts to deposit an amount to restakeManager that is less than the current withdrawal buffer the function will revert when it calls operatorDelegator.deposit() due to an amount != 0 check.

## Proof of Concept
When a user calls restakeManager.deposit() their tokens will first be sent to fill up the withdrawalBuffer if it is not at it's limit.
```solidity
uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(address(_collateralToken));
if (bufferToFill > 0) {
    bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
    
    // update amount to send to the operator Delegator
    _amount -= bufferToFill;
    
    // safe Approve for depositQueue
    _collateralToken.safeApprove(address(depositQueue), bufferToFill);
    
    // fill Withdraw Buffer via depositQueue
    depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
}
```
As seen above if the users desired deposit amount is less than the bufferToFill then all the tokens will be sent to depositQueue and amount will have it's value set to 0. 

This will then cause a problem later in the function when operatorDelegator.deposit() is called as it includes a check to prevent amounts of 0.
```solidity
operatorDelegator.deposit(_collateralToken, _amount);
```
```solidity
if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
            revert InvalidZeroInput();
```

## Recommended Mitigation Steps
Add a check to only call operatorDelegator.deposit() if amount > 0.
```diff
+ if (_amount > 0) {
     operatorDelegator.deposit(_collateralToken, _amount);
+ }
```
