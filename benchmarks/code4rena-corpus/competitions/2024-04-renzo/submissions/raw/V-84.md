# Vulnerability details

## Description
 The getMintRate function in the RenzoOracleL2 contract is intended to revert if the price of ezETH is less than 1 ether. However, due to the scaling implementation, when the oracle's reported price is exactly 1 ether and the oracle has a non-zero decimal count, the _scaledPrice calculation results in a value less than 1 ether. This triggers the InvalidOraclePrice revert condition even though the actual price is 1 ether.



## Function(s) Affected
 getMintRate

## Code Snippet

    uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
    if (_scaledPrice < 1 ether) revert InvalidOraclePrice();

## Proof of Concept (PoC)

1. Deploy an oracle with decimals() returning a value greater than 0 (e.g., 8).
2. Set the oracle price to exactly 1 ether (e.g., price = 10**8 to represent 1 ether with 8 decimals).
3. Call getMintRate.
4. Observe that _scaledPrice becomes 10**(18 - 8), which is less than 1 ether.
5. The condition if (_scaledPrice < 1 ether) is met, and the transaction reverts with InvalidOraclePrice.

## Impact
 This bug can prevent valid price feeds from being accepted, potentially halting operations that rely on the getMintRate function.

## Recommendation
 Adjust the scaling logic to ensure that a reported price of exactly 1 ether does not result in a scaled price less than 1 ether. One possible solution is to add a conditional check for this edge case or modify the scaling formula.
