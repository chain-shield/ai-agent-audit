# Vulnerability details

## Impact

The TVL will be incorrectly calculated, leading to incorrect conversion of collateral:ezETH.

## Proof of Concept

When `restakeManager.calculateTVL()` is called, there are three types of TVLs to be calculated. Firstly, it calculates the TVL of each of the collateral of each operator, then it calculates the TVL of each operator, then it calculates the TVL of every operator.

Let's say there are two operators, A and B. A has cbETH, stETH, ETH staked and B has mETH and ETH staked.

The calculateTVL function will get the stake of each of the collateral that A and B has, then the total value of A and B, then the combined total value.

At the end, the function also adds in the total value in the `withdrawQueue`. Note `withdrawQueueTokenBalanceRecorded` is set to false for the first i loop. This means that for the j loop (loop through all collateralTokens involved in the protocol), the j loop will loop through the different collateral tokens in the `withdrawQueue`. 

```
  for (uint256 j = 0; j < tokenLength; ) {
                // Get the value of this token

                uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                    collateralTokens[j]
                );

                // Set the value in the array for this OD
                operatorValues[j] = renzoOracle.lookupTokenValue(
                    collateralTokens[j],
                    operatorBalance
                );

                // Add it to the total TVL for this OD
                operatorTVL += operatorValues[j];

                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {
>                   totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }

                unchecked {
                    ++j;
                }
            }
           ...
        // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
        totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);
```

The issue is that `lookupTokenValue` has `collateralTokens[i]` and `collateralTokens[j]`, when it should both be `collateralTokens[j]`. 

```
>                   totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
```

Let's say there are 3 collateral tokens, rETH, stETH, cbETH. The `withdrawQueue` looks up the value of rETH only with the balance of rETH, stETH, cbETH. Instead, it should look up the value of rETH with the balance of rETH, and stETH with the balance of stETH. 

Since the price of LST is different as some LST is rebasing and some is not, it will affect the TVL calculation which will affect the conversion rate.

## Recommended Mitigation Steps

Change the loop value.

```
                   totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
>                        collateralTokens[j],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
```
