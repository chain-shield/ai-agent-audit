# Vulnerability details

## Impact
The current implementation of the ezETH price update mechanism on L2 is susceptible to incremental price manipulation. An attacker could potentially exploit the 10% price divergence check by consistently manipulating the price by just under 10% with each update. Over time, this could lead to significant deviations from the actual market value of ezETH, leading to financial losses for users and the protocol.


## Proof of Concept

The vulnerability stems from the way the price update validation checks are structured in the `xRenzoDeposit::_updatePrice` function. The function only rejects price updates that diverge by more than 10% from the last updated price, not from the actual market price or a more stable reference price. This mechanism can be exploited through front-running, where an attacker observes the `xRenzoBridge::sendPrice` transaction on L1 and quickly executes transactions that alter the price in a way that the subsequent update on L2 falls within the allowed 10% divergence.

```js
    function _updatePrice(uint256 _price, uint256 _timestamp) internal {
        // Check for 0
        if (_price == 0) {
            revert InvalidZeroInput();
        }

        // Check for price divergence - more than 10%
        if (
            (_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
            (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))
        ) {
            revert InvalidOraclePrice();
        }
```
Here is how the attacker can gradually manipulate the price:

1- Attacker front-runs the function `xRenzoBridge::sendPrice` and manipulates the price returned by the function `rateProvider.getRate()` in a way that it is almost 10% (but slighly less) different than the last recorded price.
2- The priceFeed sender executes `xRenzoBridge::sendPrice`
3- The `CCIPReceiver::_ccipReceive` is executed and calls `xRenzoDeposit.updatePrice(_price, _timestamp);` to update the price on L2

This can be repeated each time the `xRenzoBridge::sendPrice` is being executed. Over time, this could lead to significant deviations from the actual market value of ezETH.

After a certain period, when `xRenzoBridge::sendPrice` runs with the correct update, the tx might constantly revert because now the price recorded on L2 is too far from the correct market price.

## Recommended Mitigation Steps

Consider a reliable price reference for ezETH on L2. This reference price should be used to validate incoming price updates from L1.
