# Vulnerability details

## Impact
Missing accumulation of individual token TVLs for each operator delegator in `RestakeManager::calculateTVLs` Function

## Proof of Concept

In the function calculateTVLs(), there is a logic bug in the accumulation of individual token TVLs for each operator delegator in the `operatorDelegatorTokenTVLs` array.

During each iteration of the outer loop (for each operator delegator), a new `operatorValues` array is created and populated with the individual token TVLs for that operator delegator. However, before assigning the `operatorValues` to the corresponding position in the `operatorDelegatorTokenTVLs` array, the outer loop iterates again, and a new operatorValues array is created and populated for the next operator delegator. This causes the previously calculated individual token TVLs to be overwritten and lost.

The `operatorDelegatorTokenTVLs[i]` array is only updated once per operator delegator, after the inner loop completes. However, since the operatorValues array is reinitialized for each operator delegator, the previous operator delegator's individual token TVLs are lost.

This can result in incorrect individual token TVLs for the operator delegator in the operatorDelegatorTokenTVLs array, as the values are not being accumulated correctly.

By updating the operatorDelegatorTokenTVLs[i] array with the current operatorValues array at the end of each iteration of the inner loop, the individual token TVLs for the operator delegator will be accurately accumulated and stored in the operatorDelegatorTokenTVLs array.
