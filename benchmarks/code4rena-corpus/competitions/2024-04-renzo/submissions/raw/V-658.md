# Vulnerability details


## Impact
When calculating the TVL of the protocol in the ``calculateTVLs()``, the RestakeManager contract iterates over all the operatorDelegators, and also all the ``collateralTokens`` in the ``withdrawQueue`` contract. However there is a bug here that causes the function to return a false TVL due to passing in the wrong token and balance pair to the Oracle.

## Proof of Concept
Consider the code snippet below:
```solidity
        for (uint256 i = 0; i < odLength; ) {
            // Track the TVL for this OD
            uint256 operatorTVL = 0;

            // Track the individual token TVLs for this OD - native ETH will be last item in the array
            uint256[] memory operatorValues = new uint256[](collateralTokens.length + 1);
            operatorDelegatorTokenTVLs[i] = operatorValues; 

            // Iterate through the tokens and get the value of each
            uint256 tokenLength = collateralTokens.length;
            for (uint256 j = 0; j < tokenLength; ) {
                // Get the value of this token

                uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                    collateralTokens[j]
                );

                // Set the value in the array for this OD
                operatorValues[j] = renzoOracle.lookupTokenValue(
                    collateralTokens[j],
                    operatorBalance
                );

                // Add it to the total TVL for this OD
                operatorTVL += operatorValues[j];

                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i], //@audit mismatch for price - HIGH 2
                        collateralTokens[j].balanceOf(withdrawQueue) 
                    );
                }
```


In the function above, ``i`` is used to track the ``operatorDelegators`` array, while ``j`` is used to track the ``collateralTokens`` array. 
Therefore, when fetching the price, only the first collateral token address is used to get prices for all other collateral token balances.
Kindly note that the snippet below is only run once, therefore the first token in the array will always be used to get the price for other token balances.
```solidity
            for (uint256 j = 0; j < tokenLength; ) {
                // Get the value of this token

                uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                    collateralTokens[j]
                );

                // Set the value in the array for this OD
                operatorValues[j] = renzoOracle.lookupTokenValue(
                    collateralTokens[j],
                    operatorBalance
                );

                // Add it to the total TVL for this OD
                operatorTVL += operatorValues[j];

                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i], //@audit mismatch for price - HIGH 2
                        collateralTokens[j].balanceOf(withdrawQueue) 
                    );
                }

                unchecked {
                    ++j;
                }
            }
```
This function affects core functions such as :
- ``RestakeManager.deposit``
- ``RestakeManager.depositETH``
- ``RestakeManager.depositTokenRewardsFromProtocol``
- ``BalancerRateProvider.getRate``
- ``WithdrawQueue.withdraw``

## Tools Used

Manual Review, Josephdara

## Recommended Mitigation Steps
Make sure to iterate with the right index ``j`` instead of ``i``. See change below

```solidity

                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[j], //@audit change occured here 
                        collateralTokens[j].balanceOf(withdrawQueue) 
                    );
                }
```
