# Vulnerability details

## Impact
DepositETH wrongly calculated the wrapped amount of ETH-WETH leading to revert due to the sanity check.

## Proof of Concept
```
  function depositETH(
        uint256 _minOut,
        uint256 _deadline
    ) external payable nonReentrant returns (uint256) {
        if (msg.value == 0) {
            revert InvalidZeroInput();
        }

        // Get the deposit token balance before
        uint256 depositBalanceBefore = depositToken.balanceOf(address(this));

        // Wrap the deposit ETH to WETH
        IWeth(address(depositToken)).deposit{ value: msg.value }();

        // Get the amount of tokens that were wrapped
        uint256 wrappedAmount = depositToken.balanceOf(address(this)) - depositBalanceBefore; <----@audit wrong calc

        // Sanity check for 0
        if (wrappedAmount == 0) {
            revert InvalidZeroOutput();
        }

        return _deposit(wrappedAmount, _minOut, _deadline);
    }
```
DepositETH will fail, lets see how.

***Scenario:*** Alice wants to deposit 1 ETH into the contract to receive wrapped tokens (WETH).

***Input Validation:*** The function checks if the amount of ETH sent with the transaction is non-zero. If it's zero, indicating an invalid transaction, the function reverts with an error message.

***ETH Wrapping:*** Assuming Alice sends 1 ETH, the function wraps this ETH into WETH using the deposit function of the WETH contract. This converts Alice's 1 ETH into 1 WETH, adding it to the contract's balance.

***Balance Calculation:*** The function calculates the amount of ETH that was successfully wrapped into WETH by subtracting the balance of WETH tokens before wrapping from the balance after wrapping.

***Sanity Check:*** It ensures that the amount of wrapped ETH is not zero. If it's zero, indicating a failed wrapping process, the function reverts with an error message.

***Further Processing:*** Assuming the wrapping process was successful, the function calls the _deposit function to handle additional processing. This could include minting tokens or updating balances based on the provided parameters.
Return: Finally, the function returns the result of the _deposit function call, which could be the amount of tokens minted or another relevant value related to the deposit process.

>***Vulnerability:*** In the balance calculation the balance of the xRezoDeposit the balance after the deposit wasn't gotten. Meaning it just does

BalanceBefore = 100 WETH, alice convert 1 ETH to WETH so the WTH should be reduced.
WrappedAmount = 100 WETH - 100 WETH == 0 as illsutrated in the code above.

Therefore makinig the sanity check revert
```
  if (wrappedAmount == 0) {
            revert InvalidZeroOutput();
        }
```

## Recommended Mitigation Steps
```
 function depositETH(
        uint256 _minOut,
        uint256 _deadline
    ) external payable nonReentrant returns (uint256) {
        if (msg.value == 0) {
            revert InvalidZeroInput();
        }

       require(_deadline >= block.timestamp, "Deposit window has expired");

        // Get the deposit token balance before
        uint256 depositBalanceBefore = depositToken.balanceOf(address(this));

        // Wrap the deposit ETH to WETH
        IWeth(address(depositToken)).deposit{ value: msg.value }();

        // get the amount token balance after deposit ETH
        uint256 depositBalanceAfter = depositToken.balanceOf(address(this));

        // Get the amount of ETH that were wrapped
        uint256 wrappedAmount = depositBalanceAfter - depositBalanceBefore;

        // Remove the sanity check, since wrappedamount will always hold.

        return _deposit(wrappedAmount, _minOut, _deadline);
    }
```
