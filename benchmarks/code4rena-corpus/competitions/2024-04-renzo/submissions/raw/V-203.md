# Vulnerability details

## Impact

feeAddress will not be able to receive 100% of the swept erc20 rewards, if that is desired.

## Proof of Concept

DepositQueue.sol allows setting fee configuration to 100% indicating that that protocol may desire that the all of the swept erc20 tokens be sent to the feeAddress. Doing this however will not be possible as there's a 0 token amount check in the `depost` function in OperatorDelegator.sol which will cause the entire function to revert.

From DepositQueue.sol, the RestakeManagerAdmin can set the `_feeBasisPoints` to any amount including 10_000 i.e 100%, which indicates that such a behaviour is potentially desired (Judging also from the comment above the check for >10_000). Hence, when the `_feeBasisPoints` is set to 10_000, it means the `feeAddress` is desired to receive all of the `sweptERC20` functions.

```solidity
    function setFeeConfig(
        address _feeAddress,
        uint256 _feeBasisPoints
    ) external onlyRestakeManagerAdmin {
        // Verify address is set if basis points are non-zero
        if (_feeBasisPoints > 0) {
            if (_feeAddress == address(0x0)) revert InvalidZeroInput();
        }

        // Verify basis points are not over 100%
        if (_feeBasisPoints > 10000) revert OverMaxBasisPoints();

        feeAddress = _feeAddress;
        feeBasisPoints = _feeBasisPoints;

        emit FeeConfigUpdated(_feeAddress, _feeBasisPoints);
    }
```

Now, when the ERC20RewardsAdmin calls the `sweepERC20` function to potentially sweep any accumulated ERC20 tokens contract to the !RestakeManager (in this case, the feeAddress since 10_000 bps). The `feeAmount` calculated will be the `balance * feeBasisPoints / 10000`, in this case, the `feeAmount` == `balance`. The `feeAmount` will be transferred to the `feeAddress`. The contract then approves the `restakeManager` to spend `balance - feeAmount`, i.e approving 0. The function then calls the `depositTokenRewardsFromProtocol` function in the restakeManager.

```solidity
    function sweepERC20(IERC20 token) external onlyERC20RewardsAdmin {
        uint256 balance = IERC20(token).balanceOf(address(this));
        if (balance > 0) {
            uint256 feeAmount = 0;

            // Sweep fees if configured
            if (feeAddress != address(0x0) && feeBasisPoints > 0) {
                feeAmount = (balance * feeBasisPoints) / 10000;
                IERC20(token).safeTransfer(feeAddress, feeAmount);

                emit ProtocolFeesPaid(token, feeAmount, feeAddress);
            }

            // Approve and deposit the rewards
            token.approve(address(restakeManager), balance - feeAmount);
            restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount);

            // Add to the total earned
            totalEarned[address(token)] = totalEarned[address(token)] + balance - feeAmount;

            // Emit the rewards event
            emit RewardsDeposited(IERC20(address(token)), balance - feeAmount);
        }
    }
```
The `depositTokenRewardsFromProtocol` performs the required calculations, and transfers the 0 `balance - feeAmount` to the restakeManager. OperatorDelegator.sol will then be approved to spend the 0 tokens, and the `deposit` function is called in it.

```solidity
    function depositTokenRewardsFromProtocol(
        IERC20 _token,
        uint256 _amount
    ) external onlyDepositQueue {
        // Get the TVLs for each operator delegator and the total TVL
        (, uint256[] memory operatorDelegatorTVLs, uint256 totalTVL) = calculateTVLs();

        // Determine which operator delegator to use
        IOperatorDelegator operatorDelegator = chooseOperatorDelegatorForDeposit(
            operatorDelegatorTVLs,
            totalTVL
        );

        // Transfer the tokens to this address
        _token.safeTransferFrom(msg.sender, address(this), _amount);

        // Approve the tokens to the operator delegator
        _token.safeApprove(address(operatorDelegator), _amount);

        // Deposit the tokens into EigenLayer
        operatorDelegator.deposit(_token, _amount);
    }
```
The `deposit` function in OperatorDelegator.sol checks if `tokenAmount` is 0, which if it is, will revert, causing the `sweepERC20` function to revert, causing that the feeAddress to not be able to receive 100 percent of the swept ERC20 tokens.

```solidity
    function deposit(
        IERC20 token,
        uint256 tokenAmount
    ) external nonReentrant onlyRestakeManager returns (uint256 shares) {
        if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
            revert InvalidZeroInput();

        // Move the tokens into this contract
        token.safeTransferFrom(msg.sender, address(this), tokenAmount);

        return _deposit(token, tokenAmount);
    }
```

Manual code review

## Recommended Mitigation Steps
Introduce a check for `balance - feeAmount > 0`, and skip reward deposit if its 0.

```solidity
    function sweepERC20(IERC20 token) external onlyERC20RewardsAdmin {
        uint256 balance = IERC20(token).balanceOf(address(this));
        if (balance > 0) {
            uint256 feeAmount = 0;

            // Sweep fees if configured
            if (feeAddress != address(0x0) && feeBasisPoints > 0) {
                feeAmount = (balance * feeBasisPoints) / 10000;
                IERC20(token).safeTransfer(feeAddress, feeAmount);

                emit ProtocolFeesPaid(token, feeAmount, feeAddress);
            }

            if (balance - feeAmount > 0) {
            // Approve and deposit the rewards
            token.approve(address(restakeManager), balance - feeAmount);
            restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount);

            // Add to the total earned
            totalEarned[address(token)] = totalEarned[address(token)] + balance - feeAmount;
            }
            // Emit the rewards event
            emit RewardsDeposited(IERC20(address(token)), balance - feeAmount);
        }
    }
```
