# Vulnerability details

## Impact
Before Users can Mint on L2 chains, the `xRenzoDeposit` contract uses the rate of ezETH to ETH to know how much of xezETH to mint to the user. Without this they would be no way to Mint tokens to L2 users, this is what exactly happens when they have being no mint on the L1 or TotalValue Locked is zero, this situations will lead to the `getRate` function call to revert which will halt the cross-chain message of the price to the L2 chain

## Proof of Concept
This Issue is very easy to describe, when they are no mints of ezETH on the L1 chain or the Total value of the Protocol is Equal to zero the process of sending the price to the L2 chains will be halted

- This function tries to get the rate using the `getRate` function, which will revert if the condition described before hand in this report are true 

```solidity
function getRate() external view returns (uint256) {
        // Get the total TVL priced in ETH from restakeManager
        (, , uint256 totalTVL) = restakeManager.calculateTVLs();

        // Get the total supply of the ezETH token
        uint256 totalSupply = ezETHToken.totalSupply();

        // Sanity check
        if (totalSupply == 0 || totalTVL == 0) revert InvalidZeroInput();

        // Return the rate
        return (10 ** 18 * totalTVL) / totalSupply;
    }
```
- If one of these conditions are true, this method will revert which will prevent the L2 users from minting tokens to depositors
