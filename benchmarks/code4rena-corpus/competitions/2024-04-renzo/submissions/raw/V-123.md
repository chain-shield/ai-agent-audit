# Vulnerability details

## Impact
The gas limit concern in native token transfers within the withdraw function can lead to failed transactions, disrupting the withdrawal process. Users may experience inconvenience due to failed withdrawals, and the contract could be susceptible to denial-of-service attacks by malicious actors exploiting gas limit vulnerabilities.


## Proof of Concept
The issue arises within the `_withdraw` function, where native tokens are transferred to a recipient using a low-level call (`payable(_to).call{ value: _amount }("")`). This method forwards all available gas to the recipient, which can pose a risk. Let's focus on the relevant part of the `_withdraw` function:
```solidity
function _withdraw(address _to, uint256 _amount) internal {
    emit Withdraw(_to, _amount);

    XERC20.burn(msg.sender, _amount);

    if (IS_NATIVE) {
        (bool _success, ) = payable(_to).call{ value: _amount }("");
        if (!_success) revert IXERC20Lockbox_WithdrawFailed();
    } else {
        ERC20.safeTransfer(_to, _amount);
    }
}

```
When withdrawing native tokens, `_withdraw` transfers tokens to the recipient using `payable(_to).call{ value: _amount }("")`. This external call forwards all gas to the recipient, potentially leading to gas limit issues if the recipient is a contract with a fallback function that consumes excessive gas. This could result in out-of-gas errors and failed transactions.

## Tools Used
Manual
## Recommended Mitigation Steps
 Implement a withdrawal pattern that ensures gas usage is controlled and does not rely solely on external calls with unlimited gas forwarding. One approach could involve using withdrawal queues or batching withdrawals to limit the gas consumption per transaction.
