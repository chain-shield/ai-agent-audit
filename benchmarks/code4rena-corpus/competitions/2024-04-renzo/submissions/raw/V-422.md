# Vulnerability details

## Impact
[OperatorDelegator::getTokenBalanceFromStrategy](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L327-L335) is intended to be called to get the amount of the underlying token in the token EigenLayer strategy, plus the queued shares, that is if there are any queued shares due to queued withdrawals.

The problem here is that, this functionality will always return the wrong token balance due to checking the queued shares of the `OperatorDelegator` contract instead of the token.
```solidity
    function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
            queuedShares[address(this)] == 0 //@audit-issue Intended to check the token's queued shares
                ? tokenStrategyMapping[token].userUnderlyingView(address(this))
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView(
                        queuedShares[address(token)]
                    );
    }

```
Since the `OperatorDelegator` contract's shares are never set and thus always zero, the functionality will always return the token's `OperatorDelegator` Strategy balance, omitting the queued shares.

 **IMPACT**:

This functionality is called when calculating the total value locked in [RestakeManager::calculateTVLs](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L274-L358), to get the token balance in the strategy contract, which will subsequently be added to the TVL. Due to this error, whenever a token withdrawal is queued, the TVL will be wrongly reduced. This can be taken advantage of by a malicious user/attacker to extract value, by front-running and then back-running the [OperatorDelegator::completeQueuedWithdrawal](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L265-L324) function to extract value.

+ To Illustrate:

To best explain this issue, we will be assuming there is only one user in the system and no staking reward realized yet.

Note that, when [EigenLayer::queueWithdrawals](https://github.com/Layr-Labs/eigenlayer-contracts/blob/90a0f6aee79b4a38e1b63b32f9627f21b1162fbb/src/contracts/core/DelegationManager.sol#L267-L290) is called, the operatorDelegator shares are reduced by the queued value. This amount is intended to be accounted for using `queuedShares`, to avoid this exploit.

Let's assume our user is Alice, If Alice had deposited 10 stETH:
 Alice ezETH balance = 10e18
current ezETH supply = 10e18
current protocol TVL = 10 ether

If the Restake admin queues 5 stETH for withdrawal:
current protocol TVL = 5 ether
current ezETH supply = 10e18

If Bob deposits 5 stETH via a call to [RestakeManager::deposit](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L491-L576) function, the amount Bob receives is calculated at [RenzoOracle::calculateMintAmount](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L123-L149) function.
Where:
inflationPercentaage = 1e18 * 5e18 / 5e18 + 5e18 ==> 5e17
newEzETHSupply = 10e18 * 1e18 / 1e18 - 5e17 ==> 20e18

Bob Receives = newEzETHSupply - currentEzETHSupply
 ==> 20e18 - 10e18 --> 10e18 ezETH

STATE:
current ezETH Supply = 20e18
current TVL = 10 ether

When the Restake admin completes the withdrawal via [OperatorDelegator::completeQueuedWithdrawal](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L265-L324) function, the Operator delegator contract is credited 5 stETH. The new state will now be:

current ezETH Supply = 20e18
current TVL = 15 ether

If Bob then makes a withdrawal request via a call to [WithdrawQueue::withdraw](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L206-L264) function, to burn all of his ezETH for ether.
The amount of ether Bob receives is calculated [here](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L152-L164), as:

redeem amount = current TVL * ezTH to burn / ezETH supply 
 = 15e18 * 10e18 / 20e18 ==> 7.5 ether

Bob gets 7.5 ether, thus stealing an additional 2.5 ether from the protocol users(Alice).
Current State: 
current TVL = 7.5 ether
ezETH supply = 10e18

If Alice is to burn all of her ezETH for ether, she will now only receive:
 = 7.5e18 * 10e18 / 10e18 ==> 7.5 ether
