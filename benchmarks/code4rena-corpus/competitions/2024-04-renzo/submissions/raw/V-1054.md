# Vulnerability details

## Impact
In the Solidity contract, when dealing with ERC20 tokens, the function `deposit()` uses the `safeApprove()` method from the OpenZeppeling's SafeERC20 library to approve the `strategyManager` to spend the `tokenAmount`.

The `safeApprove()` function grants unlimited allowance if the previous allowance is not zero. This can lead to an unsafe scenario where, if an attacker can front-run the transaction(s) or get approval, they could drain all the tokens.

Also, in the `_deposit()` function, the approval is unnecessary as the tokens are already held by the smart contract itself.

## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L164

```solidity
function deposit( IERC20 token, uint256 tokenAmount ) external nonReentrant onlyRestakeManager returns (uint256 shares) { 
    if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0) revert InvalidZeroInput(); 
    // Move the tokens into this contract 
    token.safeTransferFrom(msg.sender, address(this), tokenAmount); 
    return _deposit(token, tokenAmount); 
}

function _deposit(IERC20 _token, uint256 _tokenAmount) internal returns (uint256 shares) { 
    // Approve the strategy manager to spend the tokens 
    _token.safeApprove(address(strategyManager), _tokenAmount); 
    // Deposit the tokens via the strategy manager 
    return strategyManager.depositIntoStrategy(tokenStrategyMapping[_token], _token, _tokenAmount); 
}
```
The `safeApprove()` function could allow for an unlimited spend.

## Recommended Mitigation Steps

Instead of setting an unlimited spend allowance, it's best to limit it by setting only the exact amount necessary. Alternatively, you could include conditions within the `deposit()` function to limit the approval amount by using the `increaseAllowance()` or `decreaseAllowance()` functions instead. 

Before approving any new allowances, it is a good practice to check against the current total allowance and decrease it to zero (which clears any existing approval) before setting a new amount.
