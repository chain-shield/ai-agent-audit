# Vulnerability details

## Summary

The `calculateTVL` function is very important function in the system used to calculate the total value Locked in the protocol denominated in ETH. As part of this it also needs to calculate the value of tokens in ETH present in the `WithdrawQueue` contract. The value of the tokens in ETH is gotten through the `RenzoOracle` contract in the `lookupTokenValue` function.

The inputs given to this function is wrong and results in the wrong calculation of the TVL.



## Impact

This results in the wrong calculation of the `operatorDelegatorTokenTVLs`, `operatorDelegatorTVLs` and the `totalTVL`.

As `calculateTVL` is used across the protocol to determine the [amount to mint](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L566) and [amount to redeem](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L223) ezETH tokens and depositing and withdrawing from Eigen Layer. 

## Proof of Concept

The `lookupTokenValue` function in the `RenzoOracle` takes the ERC20 interface of the token and the amount of tokens as input, while returning the value of that amount of the token in ETH. This happens in [line 317](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L317) in the `RestakeManager` contract.

```solidity

totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i], //Token in index i is given
                        collateralTokens[j].balanceOf(withdrawQueue) // but balance is of token in index j
);
```
As you can see from the code snippet above, the token in index i is given as the token but the balance of token in index j is given as the amount to calculate the price in ETH.
