# Vulnerability details

## Impact
`xRenzoDeposit::getBridgeFeeShare()` only calculates the bridge fee up to a deposit of `sweepBatchSize` which will be some value above `32 ETH`, this means that any large deposits will not be charged the full bridging fee, losing funds for the protocol.

## Proof of Concept
[xRenzoDeposit::getBridgeFeeShare()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L277-L284)
```solidity
    /**
     * @notice Function returns bridge fee share for deposit
     * @param _amountIn deposit amount in terms of ETH
     */
    function getBridgeFeeShare(uint256 _amountIn) public view returns (uint256) {
        // deduct bridge Fee share
        if (_amountIn < sweepBatchSize) {
            return (_amountIn * bridgeFeeShare) / FEE_BASIS;
        } else {
            return (sweepBatchSize * bridgeFeeShare) / FEE_BASIS;
        }
    }
```
If `_amountIn` is greater than `sweepBatchSize` then the fee will be capped at:
`(sweepBatchSize * bridgeFeeShare) / FEE_BASIS`
rather than
`(_amountIn * bridgeFeeShare) / FEE_BASIS`

The [Renzo docs](https://docs.renzoprotocol.com/docs/integrations/l2-native-restaking#heres-how-it-works) state that bridge fees are 5 basis points, and mention no cap amount. Therefore the code clearly deviates from the intended fee logic.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Either clearly state in the code and docs that fees are only charged up to the `sweepBatchSize` deposit amount, or change the function to charge the bridge fee on the full deposit amount.
