# Vulnerability details

The `_recordGas` and `_refundGas` functions in `OperatorDelegator` contract are not fully compatible with multisig or contract wallets, potentially leading to refunds being sent to unintended recipients.

## Impact
Multisig or contract wallets interacting with these functions may experience incorrect refund behavior, with gas costs being refunded to the external account that initiated the transaction rather than the wallet contract itself.

## Proof of Concept
- The `_recordGas` function is designed to record gas costs for the address that executes the transaction (`msg.sender`), which works correctly for both EOA and contract wallets.

```solidity
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
@-->    adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```

Please see the above code, the `gasSpent` is added for `msg.sender`

- The `_refundGas` function sends the refund to `tx.origin`, which refers to the original initiator of the transaction. In the case of a multisig or contract wallet, this would be the EOA that initiated the transaction, not the wallet contract.

```solidity
    function _refundGas() internal returns (uint256) {
@-->    uint256 gasRefund = address(this).balance >= adminGasSpentInWei[tx.origin]
            ? adminGasSpentInWei[tx.origin]
            : address(this).balance;
@-->    bool success = payable(tx.origin).send(gasRefund);
        if (!success) revert TransferFailed();

        // reset gas spent by admin
@-->    adminGasSpentInWei[tx.origin] -= gasRefund;

        emit GasRefunded(tx.origin, gasRefund);
        return gasRefund;
    }
```

## Recommended Mitigation Steps
- Modify the `_refundGas` function to allow refunds to be sent to the contract wallet rather than the initiating EOA, or enable the setting of a refund address. And use `msg.sender` in `receive` function to get the gas spent.
