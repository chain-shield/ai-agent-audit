# Vulnerability details

The `queuedShares[address(this)]` check appears to be a coding error, as there is no logic present in the `OperatorDelegator` contract that updates the `queuedShares` mapping using the contract's own address as a key.

## Impact
The check could lead to incorrect behavior or calculations within the contract, as it may always evaluate to false, potentially causing the contract to ignore queued shares for withdrawals leading to wrong TVL calculation in `RestakeManager` contract.

## Proof of Concept
- The `getTokenBalanceFromStrategy` function contains the check `queuedShares[address(this)] == 0`, which can be seen [here](#https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L329).
- There is no corresponding code that updates `queuedShares` using `address(this)` as a key, indicating a potential logic flaw.

```solidity
    function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
@-->        queuedShares[address(this)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this))
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView(
                        queuedShares[address(token)]
                    );
    }
```
