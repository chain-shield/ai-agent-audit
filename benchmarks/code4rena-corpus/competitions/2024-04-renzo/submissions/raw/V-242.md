# Vulnerability details

## Impact
This will cause inaccuracies in the TVL calculation, resulting in errors in calculations such as ezETH mint amount.

## Proof of Concept
In the `calculateTVLs` function of the `RestakeManager` contract, the `totalWithdrawalQueueValue` is used to calculate the value of tokens stored in the `WithdrawQueue` contract.

`i` represents the loop index for all operator delegators, and `j` represents the loop index for all collateral ERC20 tokens.

[RestakeManager.sol#L289](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L289)

```solidity
uint256 odLength = operatorDelegators.length;
// ...
for (uint256 i = 0; i < odLength; ) {
```

[RestakeManager.sol#L298-L299](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L298-L299)

```solidity
uint256 tokenLength = collateralTokens.length;
for (uint256 j = 0; j < tokenLength; ) {
```

The calculation of `totalWithdrawalQueueValue` is as follows:

[RestakeManager.sol#L316-L321](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L316-L321)

```solidity
 if (!withdrawQueueTokenBalanceRecorded) {
    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
        collateralTokens[i],
        collateralTokens[j].balanceOf(withdrawQueue)
    );
}
```

The definition of the `lookupTokenValue` function:

[RenzoOracle.sol#L71](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Oracle/RenzoOracle.sol#L71)

```solidity
function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
```

It can be seen that in the calculation of `totalWithdrawalQueueValue`, the first parameter `_token` address and the second parameter `_balance` are inconsistent.

For example, assuming there are two tokens in `collateralTokens`:
`stETH` (j=0) and `WBETH` (j=1).

When `i=0`, the calculation is:

```
totalWithdrawalQueueValue =
lookupTokenValue(stETH, stETH.balanceOf(withdrawQueue)) +
lookupTokenValue(stETH, wBETH.balanceOf(withdrawQueue)) 
```

However, the correct calculation should be:

```
totalWithdrawalQueueValue =
lookupTokenValue(stETH, stETH.balanceOf(withdrawQueue)) +
lookupTokenValue(wBETH, wBETH.balanceOf(withdrawQueue)) 
```
