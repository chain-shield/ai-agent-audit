# Vulnerability details

`RestakeManager`'s `deposit` function will take user deposits and if there is a buffer deficit use it to fill the withdraw buffer. The issue arises when the amount user wants to deposit is smaller than or equal to `bufferToFill`, as after buffer filling operations, `deposit` function tries to deposit an amount of 0 to `operatorDelegator`, leading to a revert.

## Impact
Users won't be able to deposit when the amount they want to deposit is smaller than buffer to fill.

## Tools Used
Manual review
## Recommended Mitigation Steps
Add a check so that if amount is 0 after filling the buffer, contract does not try to deposit 0 amount to `operatorDelegator`.
