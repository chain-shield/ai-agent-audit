# Vulnerability details

## Impact
`OperatorDelegator.completeQueuedWithdrawal()` perform an external call to [delegationManager](https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/core/DelegationManager.sol#L305) contract which finalize any queued withdrawals initiated by the operatorDelegator. This function passes `receiveAsToken` parameter `true`, so the podOwnerShares in EigenPodManager/StrategyManager will be redeemable for the underlying token. 

If the withdrawal is from the [beaconChainETHStrategy](https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/core/DelegationManager.sol#L750-L755), it processes a transfer of the amount of beacon chain ETH to the `withdrawer`(i.e. operatorDelegator), which causes the `nonReentrant` check to be triggered for the [second time](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L501). The txn reverts and any queued withdrawal from the stategies cannot be completed further. 

## Proof of Concept
Step-by-step execution flow,
1. NativeEthRestakeAdmin call `OperatorDelegator.queueWithdrawals()` making a full or partial withdrawal from the beacon chain, note the `withdrawer` is the OperatorDelegator itself
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L228-L229

2. Before the withdrawal can be completed, podOwner call the permissionless `EigenPod.verifyAndProcessWithdrawal` function to prove that a withdrawal occured on the beacon chain, 
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L414

3. After the delay has been passed, the nativeEthRestakeAdmin call `completeQueuedWithdrawal()` to finalize the withdrawal, also where the first time reentrancy guard activates(marks `_status = _ENTERED`) 

```solidity
        // complete the queued withdrawal from EigenLayer with receiveAsToken set to true
        delegationManager.completeQueuedWithdrawal(withdrawal, tokens, middlewareTimesIndex, true);
```
4. Since the `receiveAsTokens==true`, the delegationManager `withdrawSharesAsTokens` via the `EigenPodManager`,
https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/core/DelegationManager.sol#L751

5. `EigenPodManager` checks for any ETH deficit, and updates the amount accordingly. Finally, the `EigenPod.withdrawRestakedBeaconChainETH()` is called, to `_sendETH` to the `withdrawer` address. 
https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/pods/EigenPod.sol#L424C14-L424C44

6. `receive()` function on the `withdrawer`(i.e. OperatorDelegator) will be triggered to the ETH transfer. Since this function is also guarded by the `nonReentrant` modifier, the _status won't be `_NOT_ENTERED` anymore. 

Consequently, the entire withdrawal transaction will revert due to a unexpected reentrancy.

## Tools Used
Manual review
## Recommended Mitigation Steps
Remove `nonReentrant` modifer from the `receive()` function.
