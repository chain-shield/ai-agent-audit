# Vulnerability details

## Impact

`RestakeManager::deposit()` and `RestakeManager::depositETH()` calculate amounts to be minted differently. The first one uses the price of the deposited asset whereas the second one the amount of ether sent. This can lead to incorrect accounting when the price of `ezETH` is not aligned with `ETH`.

## Proof of Concept

`RestakeManager::deposit()` uses `RenzoOracle::lookupTokenValue()` to get the price of the collateral deposited and based on that decides how much `ezETH` to mint to the depositor:

```solidity
function deposit(
    IERC20 _collateralToken,
    uint256 _amount,
    uint256 _referralId
) public nonReentrant notPaused {
    // Verify collateral token is in the list - call will revert if not found
    uint256 tokenIndex = getCollateralTokenIndex(_collateralToken);

    // Get the TVLs for each operator delegator and the total TVL
    (
        uint256[][] memory operatorDelegatorTokenTVLs,
        uint256[] memory operatorDelegatorTVLs,
        uint256 totalTVL
    ) = calculateTVLs();

    // Get the value of the collateral token being deposited
    uint256 collateralTokenValue = renzoOracle.lookupTokenValue(_collateralToken, _amount);

    // ...

    // Calculate how much ezETH to mint
    uint256 ezETHToMint = renzoOracle.calculateMintAmount(
        totalTVL,
        collateralTokenValue,
        ezETH.totalSupply()
    );

    // Mint the ezETH
    ezETH.mint(msg.sender, ezETHToMint);
}
```

As can be seen above, `collateralTokenValue` is the price of the deposited asset that is fetched from the oracle and then used to calculate and mint the respective `ezETH` amount.

If we look at the `depositETH()` function, we'll see a difference:

```solidity
function depositETH(uint256 _referralId) public payable nonReentrant notPaused {
    // Get the total TVL
    (, , uint256 totalTVL) = calculateTVLs();

    // Enforce TVL limit if set
    if (maxDepositTVL != 0 && totalTVL + msg.value > maxDepositTVL) {
        revert MaxTVLReached();
    }

    // Deposit the remaining ETH into the DepositQueue
    depositQueue.depositETHFromProtocol{ value: msg.value }();

    // Calculate how much ezETH to mint
    uint256 ezETHToMint = renzoOracle.calculateMintAmount(
        totalTVL,
        msg.value,
        ezETH.totalSupply()
    );

    // Mint the ezETH
    ezETH.mint(msg.sender, ezETHToMint);
}
```

The calculation is based on the `msg.value` sent, rather than the price of Ether. The code assumes that `ezETH` will always maintain a 1:1 peg with `ETH`. A deviation in the price of `ezETH`, however, can cause a discrepancy in the accounting here that may cause more or less `ezETH` to be minted when it happens.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Reach out to the oracle to grab the price of `ETH` and use that representation to calculate `ezETHToMint` in `RestakeManager::depositETH()`.
