# Vulnerability details

When a user deposits funds into the Renzo protocol, if the withdraw buffer isn't full, it's filled first. Any remaining amount is then deposited or queued for deposit into the Eigen Layer. However, if the entire deposited amount is used to fill the withdraw buffer, the `operatorDelegator.deposit` function is called with a zero amount, triggering a revert due to the zero amount check in the deposit function.

```solidity
    function deposit(
        IERC20 token,
        uint256 tokenAmount
    ) external nonReentrant onlyRestakeManager returns (uint256 shares) {
        // audit-issue This will revert if tokenAmount is zero
        if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
            revert InvalidZeroInput();

        // Move the tokens into this contract
        token.safeTransferFrom(msg.sender, address(this), tokenAmount);

        return _deposit(token, tokenAmount);
    }
```

Similarly, if the buffer is already full, bufferToFill is calculated to be zero. This results in depositQueue.fillERC20withdrawBuffer reverting due to the zero amount check as well. 

```solidity
        if (bufferToFill > 0) {
            bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
            // update amount to send to the operator Delegator
            _amount -= bufferToFill;

            // safe Approve for depositQueue
            _collateralToken.safeApprove(address(depositQueue), bufferToFill);

            // fill Withdraw Buffer via depositQueue
            // @audit-issue this will revert if bufferToFill is zero
            depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
        }
```

The same issue occurs in OperatorDelegator when filling the buffer.


## Impact
Deposit function will revert almost every case

## Proof of Concept
1. Let's say the stETH collateral token has a buffer deficit of 5 tokens.
2. A user tried to deposit 5 stETH to the protocol so all of his funds will be used to fill the buffer itself.
3. So `operatorDelegator.deposit` will be called with zero amount which will revert due to zero amount check.



## Recommended Mitigation Steps
Only call `fillERC20withdrawBuffer` and `deposit` functions if the amount is greater than zero.

```diff
        if (bufferToFill > 0) {
            bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
            // update amount to send to the operator Delegator
            _amount -= bufferToFill;

            // safe Approve for depositQueue
            // @audit-issue safe approve shouldn't be used

-            depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
```
