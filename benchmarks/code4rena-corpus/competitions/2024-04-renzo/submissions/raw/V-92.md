# Vulnerability details

## Impact
A user/bridge holding xERC20 tokens could burn their tokens via the burn() function. If the caller is not the lockbox contract, it is required that the caller does not burn more than their current limit. However, the caller could simply work around this if they want to burn more than the current limit.

This could be done by granting approval to another address. Since the `_burnWithCaller()` always checks the `_caller` burning limits instead of the `_user` of which he burning the tokens, the approved address could burn on behalf of the owner to let the owner wish fulfilled. 
```solidity
    function _burnWithCaller(address _caller, address _user, uint256 _amount) internal {
        // Do not allow 0 value burns
        if (_amount == 0) revert IXERC20_INVALID_0_VALUE();

        if (_caller != lockbox) {
            uint256 _currentLimit = burningCurrentLimitOf(_caller);
            if (_currentLimit < _amount) revert IXERC20_NotHighEnoughLimits();
            _useBurnerLimits(_caller, _amount); // <@
        }
        _burn(_user, _amount);
    }
```
