# Vulnerability details

## Issue Description

The `calculateTVLs()` function shown in the code snippet below is used by the `RestakeManager` and other protocol contracts to calculate the TVL of the entire protocol denominated in ETH. The function is supposed to return 3 pieces of information as stated in the function Natspec:

```solidity
/// @dev This function calculates the TVLs for each operator delegator by individual token, total for each OD, and total for the protocol.
/// @return operatorDelegatorTokenTVLs Each OD's TVL indexed by operatorDelegators array by collateralTokens array
/// @return operatorDelegatorTVLs Each OD's Total TVL in order of operatorDelegators array
/// @return totalTVL The total TVL across all operator delegators.
```

The function does calculate the last two values (`operatorDelegatorTVLs` and `totalTVL`) correctly, but for the first one `operatorDelegatorTokenTVLs`, there is an error in its calculation. `operatorDelegatorTokenTVLs` represents each OD's TVL indexed by operatorDelegators and by collateral tokens. As it can be seen below, its value is initially set equal to the empty array `operatorValues` (an array of zeros), and the function doesn't update it after that and returns it as an array of zeros.

```solidity
function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
    uint256[][] memory operatorDelegatorTokenTVLs = new uint256[][](operatorDelegators.length);
    uint256[] memory operatorDelegatorTVLs = new uint256[](operatorDelegators.length);
    uint256 totalTVL = 0;

    // Iterate through the ODs
    uint256 odLength = operatorDelegators.length;

    // flag for withdrawal queue balance set
    bool withdrawQueueTokenBalanceRecorded = false;
    address withdrawQueue = address(depositQueue.withdrawQueue());

    // withdrawalQueue total value
    uint256 totalWithdrawalQueueValue = 0;

    for (uint256 i = 0; i < odLength; ) {
        // Track the TVL for this OD
        uint256 operatorTVL = 0;

        // Track the individual token TVLs for this OD - native ETH will be the last item in the array
        uint256[] memory operatorValues = new uint256[](collateralTokens.length + 1);
        //@audit will always be an array of zero values
        operatorDelegatorTokenTVLs[i] = operatorValues; 

        // Iterate through the tokens and get the value of each
        uint256 tokenLength = collateralTokens.length;

            // Get the value of this token

            uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                collateralTokens[j]
            );

            // Set the value in the array for this OD
            operatorValues[j] = renzoOracle.lookupTokenValue(
                collateralTokens[j],
                operatorBalance
            );

            // Add it to the total TVL for this OD

                    collateralTokens[i],

            }

            }
        }
```

This error will have an impact if the protocol tries to enforce the individual token TVL limit within the `deposit` function as shown below:

```solidity

    IERC20 _collateralToken,
    uint256 _amount,
    uint256 _referralId
) public nonReentrant notPaused {

    // Get the TVLs for each operator delegator and the total TVL
    (
        uint256[][] memory operatorDelegatorTokenTVLs,
        uint256[] memory operatorDelegatorTVLs,
        uint256 totalTVL

    // Enforce TVL limit if set, 0 means the check is not enabled
    if (maxDepositTVL != 0 && totalTVL + collateralTokenValue > maxDepositTVL) {
        revert MaxTVLReached();
    }

    // Enforce individual token TVL limit if set, 0 means the check is not enabled
    if (collateralTokenTvlLimits[_collateralToken] != 0) {
        // Track the current token's TVL
        uint256 currentTokenTVL = 0;

        // For each OD, add up the token TVLs

        for (uint256 i = 0; i < odLength; ) {
            currentTokenTVL += operatorDelegatorTokenTVLs[i][tokenIndex];
            unchecked {
                ++i;
            }
        }

        //@audit will also pass because currentTokenTVL == 0 
        // Check if it is over the limit

            revert MaxTokenTVLReached();

```

The function uses the `operatorDelegatorTokenTVLs` array returned by `calculateTVLs()` to calculate the individual ERC20 token TVL. But as we've demonstrated earlier, this array is always filled with zeros and not the actual token values. So, the calculated token TVL `currentTokenTVL` will be equal to 0, thus the max TVL limit check will always be bypassed.

This issue will basically prevent the protocol from correctly applying the individual token TVL limit. The only way to do so is for the protocol team to actively monitor the current token TVL and set `collateralTokenTvlLimits[_collateralToken]` to a very small value (1 wei for example) when it reaches the desired limit values. This must be done for each collateral token, which is not ideal. Add to that that when users later withdraw some of a given token TVL, that `collateralTokenTvlLimits[_collateralToken]` must be reset again to allow additional deposits.

The result of this issue is that the individual collateral token TVL limit will be hard to implement.

## Impact

The wrong calculation of OD's TVL indexed by operatorDelegators and by collateral tokens `operatorDelegatorTokenTVLs` in `calculateTVLs()` will prevent the individual token TVL limit from being correctly applied.
