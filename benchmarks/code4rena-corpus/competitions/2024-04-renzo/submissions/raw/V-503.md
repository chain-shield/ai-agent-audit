# Vulnerability details

## Impact

When there are `OperatorDelegators` that support various assets, deposits can experience temporary DOS, due to the `chooseOperatorDelegatorForDeposit`.

## Proof of Concept

Looking at the `OperatorDelegatorStorage` contract we can conclude that not all the OperatorDelegators will have the same supported assets:

[OperatorDelegatorStorage.sol#L26-L28](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegatorStorage.sol#L26-L28)

```solidity
  /// @dev The mapping of supported token addresses to their respective strategy addresses
    /// This will control which tokens are supported by the protocol
    mapping(IERC20 => IStrategy) public tokenStrategyMapping;
```

Let’s suppose that there are 2 `OperatorDelegators` in the `RestakeManager` :

- One that has `stETH` and `ETH`.
- One **only** with `wBETH`.

Due to the high interest for `stETH` and `ETH` staking, this OperatorDelegator surpasses the threshold and now all the subsequent deposits will **be sent to the second operator which doesn’t support these tokens** because `chooseOperatorDelegatorForDeposit` is checking only the amounts and not whether this `OperatorDelegator` actually supports the token that is being deposited:

[RestakeManager.sol#L360-L393](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L360-L393)

```solidity
/// @dev Picks the OperatorDelegator with the TVL below the threshold or returns the first one in the list
/// @return The OperatorDelegator to use
function chooseOperatorDelegatorForDeposit(
    uint256[] memory tvls,
    uint256 totalTVL
) public view returns (IOperatorDelegator) {
    // Ensure OperatorDelegator list is not empty
    if (operatorDelegators.length == 0) revert NotFound();

    // If there is only one operator delegator, return it
    if (operatorDelegators.length == 1) {
        return operatorDelegators[0];
    }

    // Otherwise, find the operator delegator with TVL below the threshold
    uint256 tvlLength = tvls.length;
    for (uint256 i = 0; i < tvlLength; ) {
        if (
            tvls[i] <
            (operatorDelegatorAllocations[operatorDelegators[i]] * totalTVL) /
                BASIS_POINTS /
                BASIS_POINTS
        ) {
            return operatorDelegators[i];
        }

        unchecked {
            ++i;
        }
    }

    // Default to the first operator delegator
    return operatorDelegators[0];
}
```

Now, all deposits with tokens different from `wBETH` will revert because of `chooseOperatorDelegatorForDeposit` **returning the second** `OperatorDelegator` and this check inside the `OperatorDelegator::deposit`, which validates that there is a strategy using this particular token:

## Recommended Mitigation Steps

Modify the `chooseOperatorDelegatorForDeposit` function to validate whether the chosen `OperatorDelegator` supports the desired token, and return the first `OD` that has this token or revert with `NotFound`, instead of simply returning the one at zero index.
