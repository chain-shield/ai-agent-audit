# Vulnerability details

## Impact:
The use of the `transfer` function in the WithdrawQueue contract can result in transaction failures if the recipient contract has a fallback function that requires more than 2300 gas. This can cause unexpected behavior, such as the inability to withdraw funds, and potentially result in lost funds if the recipient contract is unable to process the Ether transfer.

## Proof of Concept:

* To illustrate this issue, we can create a contract with a fallback function that requires more than 2300 gas. We can then attempt to withdraw Ether from the WithdrawQueue contract to this recipient contract. The `transfer` function will fail, and the transaction will be reverted.

Tools Used:

* Solidity documentation
* OpenZeppelin Solidity library documentation
* Remix IDE for Solidity contract deployment and testing

## Recommended Mitigation Steps:

* Replace the `transfer` function with the `call` function to forward all available gas and allow for more complex functionality in the recipient contract.
* Implement proper error handling to check the return value of the `call` function and handle potential errors.

## Example of recommended code change:
```scss
(bool success, ) = payable(msg.sender).call{value: _withdrawRequest.amountToRedeem}("");
require(success, "Transfer failed");
```
This change will ensure that the recipient contract receives enough gas to perform its fallback function and that any errors are properly handled, preventing unexpected behavior and potential loss of funds.
