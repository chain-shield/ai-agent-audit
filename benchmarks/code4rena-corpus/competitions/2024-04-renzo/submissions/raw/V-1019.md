# Vulnerability details

## Impact
When The Protocol receives rewards for staking it is sent to the `DepositQueue`, and it is used to stake back in the operator delegator, but the problem here is that the rewards sent to the contract are different ERC20 tokens that may have strategies on the eigen layer, but may not have being added to the collateral token list in the `RestakeManager`, which means Temporary DOS for any process that involves those tokens on the `RestakeManager`

## Proof of Concept
- When sweepERC20 is called, it calculates the fees and stakes the remaning thorugh the operator delegator, as shown below 

```solidity
 function sweepERC20(IERC20 token) external onlyERC20RewardsAdmin {
        uint256 balance = IERC20(token).balanceOf(address(this));
        if (balance > 0) {
            uint256 feeAmount = 0;

            // Sweep fees if configured
            if (feeAddress != address(0x0) && feeBasisPoints > 0) {
                feeAmount = (balance * feeBasisPoints) / 10000;
                IERC20(token).safeTransfer(feeAddress, feeAmount);

                emit ProtocolFeesPaid(token, feeAmount, feeAddress);
            }

            // Approve and deposit the rewards
            token.approve(address(restakeManager), balance - feeAmount);
            restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount);

            // Add to the total earned
            totalEarned[address(token)] = totalEarned[address(token)] + balance - feeAmount;

            // Emit the rewards event
            emit RewardsDeposited(IERC20(address(token)), balance - feeAmount);
        }
    }
```

- This Function stakes the token for the protocol but does not check if the Restake manager has the token in the list of collateral token

This lack of check will prevent any action that involves the token in the protocol as most action require a check of if the token actually is in the collateral tokens array.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a check in the `DepositQueue` in the sweepERC20 function, that asserts that the token is added to the collateral token list to compel the admins too add the tokens to the list of collateral tokens, to give the user more options in interactions with the token on the RestakeManager.
