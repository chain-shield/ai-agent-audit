# Vulnerability details

### Description

1. On `Eigenlayer`'s StrategyManager#`depositIntoStrategy()`,
	- the `number of shares` received is calculated by the `strategy` using an internal exchange rate that depends on the previous number of tokens deposited.[https://github.com/Layr-Labs/eigenlayer-contracts/blob/dev/docs/core/StrategyManager.md?plain=1#L64]
	- the `number of shares` received can be smaller than expected by inflation with griefing attack, but it has only zero check, no minimum check. [https://github.com/Layr-Labs/eigenlayer-contracts/blob/dev/src/contracts/strategies/StrategyBase.sol#L118]

2. OperatorDelegator#`_deposit()` 
	- deposits the tokens via the strategy manager to `Eigenlayer`.
	- takes the `number of shares` returned from strategyManager#`depositIntoStrategy()` back.
	- pass it over without any checking such as minimum check or transaction time gap delay. 
	
```
function _deposit(IERC20 _token, uint256 _tokenAmount) 
	internal returns (uint256 shares) {

	_token.safeApprove(address(strategyManager), _tokenAmount);

	//<------------- @audit
	return strategyManager.depositIntoStrategy(
		tokenStrategyMapping[_token], _token, _tokenAmount
	);
}	
```

3. The following functions does not check if the `number of shares` was affected by inflation.
	- OperatorDelegator#`deposit()`[https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L143-L154]

	```
	function deposit(
		IERC20 token,
		uint256 tokenAmount
	) external nonReentrant onlyRestakeManager returns (uint256 shares) {
		...
		//<------------ @audit
		return _deposit(token, tokenAmount);
	}
	```

	- RestakeManager#`deposit(IERC20,uint256,uint256)`[https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L562]
	
	```
	function deposit(
		IERC20 _collateralToken,
		uint256 _amount,
		uint256 _referralId
	) public nonReentrant notPaused {
		...
		_collateralToken.safeApprove(address(operatorDelegator), _amount);
		
		operatorDelegator.deposit(_collateralToken, _amount); //<---- @audit

		// Calculate how much ezETH to mint
		...
	}
	```
	
## Impact

- `EigenLayer` share rate can be massively inflated by griefing attacks.
- It might result in OperatorDelegator receiving fewer shares than expected.


### Proof of Concept

1. User `Alice` deposits `_amountIn` as `100` through  RestakeManager#`deposit()`.   
2. `EigenLayer` share rate is massively inflated by griefing attacks.
3. OperatorDelegator will receive few shares than normal case.

### Recommended Mitigation Steps

1. Please define `MIN_SHARE_AMOUNT` constant on `OperatorDelegator.sol`, for example.

```diff
	uint256 internal constant GWEI_TO_WEI = 1e9;
++	uint256 internal constant MIN_SHARE_AMOUNT = 50;
	address public constant IS_NATIVE = 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE;
```

2. Please update OperatorDelegator#`_deposit()` as following.

```diff
function _deposit(IERC20 _token, uint256 _tokenAmount) 
	internal returns (uint256 shares) {

	_token.safeApprove(address(strategyManager), _tokenAmount);
```
