# Vulnerability details

## Impact
The `xRenzoDeposit::sweep()` function ignores the return value of the `connext.xcall()` call, which sends a cross-chain message to the destination chain.

Ignoring the return value of the `connext.xcall()` call means that the function will continue executing even if the message sending fails. This could lead to the following issues:

Inconsistent Protocol State: If the cross-chain message fails to be delivered, the protocol's state may become inconsistent, as the `xRenzoDeposit` contract would have processed the sweep operation locally, but the corresponding action may not have been executed on the destination chain.

Loss of User Funds: If the cross-chain message fails, the user's deposited funds could be trapped in the `xRenzoDeposit` contract, as the intended bridging operation would not have been completed.

## Proof of Concept
Bob observes the `xRenzoDeposit::sweep()` function, which is responsible for bridging the user-deposited collateral tokens (nextWETH) to the L1 Renzo Protocol.

Bob identifies that the function ignores the return value of the `connext.xcall()` call, which sends the cross-chain message.

Bob decides to take advantage of this vulnerability by performing the following attack:

Bob waits for a user to deposit a large amount of nextWETH tokens into the `xRenzoDeposit` contract.
Bob then quickly calls the `xRenzoDeposit::sweep()` function, but he intentionally reverts the `connext.xcall()` transaction, causing the cross-chain message to fail.

Since the function ignores the return value of `connext.xcall()`, it will continue executing, 
trapping the user's deposited funds in the `xRenzoDeposit` contract.


As a result, the user's funds will be stuck in the xRenzoDeposit contract, and the protocol will be unable to bridge them to the L1 Renzo Protocol as intended.

## Recommended Mitigation Steps
`xRenzoDeposit::sweep()` function should properly handle the return value of the `connext.xcall()` call. This can be done by:

Storing the return value in a local variable and adding appropriate error handling logic.
Reverting the transaction if the `connext.xcall()` call fails, to ensure that the protocol's state remains consistent and user funds are not trapped.
