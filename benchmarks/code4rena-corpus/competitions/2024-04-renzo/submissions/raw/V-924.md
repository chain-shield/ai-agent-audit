# Vulnerability details

* To withdraw the underlying assets from the system, user has to first request the withdrawal, then claim it, when the `coolDownPeriod` ends. In order to claim a requested withdrawal, the index has to be supplied, however, for some reason an index has to be less than an amount of requested withdrawals. Since, the index is not tied to a specific user, this invariant does not make sense.

## Impact
* User is unable to claim the withdrawal, if the `withdrawalRequestIndex >= withdrawRequests[msg.sender].length`

## Recommended Mitigation Steps
- Short term: 
  ```diff
        function claim(uint256 withdrawRequestIndex) external nonReentrant { 
            // check if provided withdrawRequest Index is valid
  -            if (withdrawRequestIndex >= withdrawRequests[msg.sender].length) 
  -            revert InvalidWithdrawIndex();

            WithdrawRequest memory _withdrawRequest = withdrawRequests[msg.sender][
                withdrawRequestIndex
            ];
            //...
    ```
  
- Long term:
  - Consider implementing the nonce for a specific user.
