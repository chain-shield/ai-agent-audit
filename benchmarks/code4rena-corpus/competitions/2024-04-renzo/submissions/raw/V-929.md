# Vulnerability details

OperatorDelegator would revert on zero deposits
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L147
```solidity
function deposit(
    IERC20 token,
    uint256 tokenAmount
) external nonReentrant onlyRestakeManager returns (uint256 shares) {
    if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
        revert InvalidZeroInput();

    // Move the tokens into this contract
    token.safeTransferFrom(msg.sender, address(this), tokenAmount);

    return _deposit(token, tokenAmount);
}
```

Let's take a look at [RestakeManager.deposit](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L539-L562)
```solidity
// Transfer the collateral token to this address
_collateralToken.safeTransferFrom(msg.sender, address(this), _amount);

// Check the withdraw buffer and fill if below buffer target
uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(
    address(_collateralToken)
);
if (bufferToFill > 0) {
    bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
    // update amount to send to the operator Delegator
    _amount -= bufferToFill;

    // safe Approve for depositQueue
    _collateralToken.safeApprove(address(depositQueue), bufferToFill);

    // fill Withdraw Buffer via depositQueue
    depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
}

// Approve the tokens to the operator delegator
_collateralToken.safeApprove(address(operatorDelegator), _amount);

// Call deposit on the operator delegator
operatorDelegator.deposit(_collateralToken, _amount);
```

If bufferToFill is greater than the amount transferred from user, the amount called in `operatorDelegator.deposit` would be 0 (amount-amount). This means that deposits that are less than bufferToFill would be reverted.

## Impact
`bufferToFill` depends on `withdrawalBufferTarget` which would be a large number to allow users to easily withdraw. This means that the most important functionality of the protocol would be unavailable for most users. This DoS would be frequent and last longing.

## Proof of Concept
When user calls deposit with amount < bufferToFill
* bufferToFill is greater than 0
* bufferToFill would be set to amount
* amount would be reduced by bufferToFill (which is the amount itself)
* amount is 0
* operatorDelegator.deposit would revert

Manual review

## Recommended Mitigation Steps
Skip `_collateralToken.safeApprove` and `operatorDelegator.deposit` if `_amount` is zero.
```diff
-   // Approve the tokens to the operator delegator
-   _collateralToken.safeApprove(address(operatorDelegator), _amount);
-   
-   // Call deposit on the operator delegator
-   operatorDelegator.deposit(_collateralToken, _amount);

+   if (_amount > 0) {
+       // Approve the tokens to the operator delegator
+       _collateralToken.safeApprove(address(operatorDelegator), _amount);
+   
+       // Call deposit on the operator delegator
+       operatorDelegator.deposit(_collateralToken, _amount);
+   }
```
