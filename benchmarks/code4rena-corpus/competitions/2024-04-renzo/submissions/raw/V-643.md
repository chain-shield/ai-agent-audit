# Vulnerability details

## Impact
`mintAmount` returned by the following `RenzoOracle.calculateMintAmount` function is the ezETH amount to be minted.

https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Oracle/RenzoOracle.sol#L123-L149
```solidity
    function calculateMintAmount(
        uint256 _currentValueInProtocol,
        uint256 _newValueAdded,
        uint256 _existingEzETHSupply
    ) external pure returns (uint256) {
        ...

        // Calculate the percentage of value after the deposit
        uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded);

        // Calculate the new supply
        uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
            (SCALE_FACTOR - inflationPercentaage);

        // Subtract the old supply from the new supply to get the amount to mint
        uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

        ...

        return mintAmount;
    }
```

Such `mintAmount` would be evaluated to `_existingEzETHSupply * _newValueAdded / _currentValueInProtocol` according to the following proof. Thus, such `mintAmount` and `_existingEzETHSupply * _newValueAdded / _currentValueInProtocol` should be equivalent after taking into account rounding errors. However, the rounding errors in the calculation of `mintAmount` in the `RenzoOracle.calculateMintAmount` function can cause such `mintAmount` to be substantially lower than `_existingEzETHSupply * _newValueAdded / _currentValueInProtocol`.

```solidity
        // Calculate the percentage of value after the deposit
        inflationPercentaage = (SCALE_FACTOR * _newValueAdded) / (_currentValueInProtocol + _newValueAdded)

        // Calculate the new supply
        newEzETHSupply
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR - inflationPercentaage)
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR - (SCALE_FACTOR * _newValueAdded) / (_currentValueInProtocol + _newValueAdded))
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR * (_currentValueInProtocol + _newValueAdded) / (_currentValueInProtocol + _newValueAdded) - SCALE_FACTOR * _newValueAdded / (_currentValueInProtocol + _newValueAdded))
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR * ((_currentValueInProtocol + _newValueAdded) / (_currentValueInProtocol + _newValueAdded) - _newValueAdded / (_currentValueInProtocol + _newValueAdded)))
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR * (_currentValueInProtocol + _newValueAdded - _newValueAdded) / (_currentValueInProtocol + _newValueAdded))
        = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR * _currentValueInProtocol / (_currentValueInProtocol + _newValueAdded))
        = _existingEzETHSupply / (_currentValueInProtocol / (_currentValueInProtocol + _newValueAdded))
        = _existingEzETHSupply * (_currentValueInProtocol + _newValueAdded) / _currentValueInProtocol

        // Subtract the old supply from the new supply to get the amount to mint
        mintAmount
        = newEzETHSupply - _existingEzETHSupply
        = _existingEzETHSupply * (_currentValueInProtocol + _newValueAdded) / _currentValueInProtocol - _existingEzETHSupply
        = _existingEzETHSupply * ((_currentValueInProtocol + _newValueAdded) / _currentValueInProtocol - 1)
        = _existingEzETHSupply * ((_currentValueInProtocol + _newValueAdded) / _currentValueInProtocol - (_currentValueInProtocol / _currentValueInProtocol))
        = _existingEzETHSupply * ((_currentValueInProtocol + _newValueAdded - _currentValueInProtocol) / _currentValueInProtocol)
        = _existingEzETHSupply * _newValueAdded / _currentValueInProtocol
```

Because the `mintAmount` returned by the `RenzoOracle.calculateMintAmount` function is used as the ezETH amount to be minted when calling the following `RestakeManager.deposit` and `RestakeManager.depositETH` functions, the amount of ezETH minted to `msg.sender` is lower than what it should be. Hence, for depositing the same collateral token or ETH amount, the ezETH amount minted to `msg.sender` is lower than what `msg.sender` is entitled to, which is the expected ezETH amount to be minted that equals `_existingEzETHSupply * _newValueAdded / _currentValueInProtocol`.

## Proof of Concept
Please add the following test file. Using `forge`, this `test_actualEzETHAmtToBeMintedIsLessThanExpected` test will pass to demonstrate the described scenario.

```solidity
// SPDX-License-Identifier: BUSL-1.1
pragma solidity ^0.8.19;

import { Test } from "forge-std/Test.sol"; // solhint-disable-line no-unused-import

contract C4Test1 is Test {
  function test_actualEzETHAmtToBeMintedIsLessThanExpected() external {
    uint256 SCALE_FACTOR = 10 ** 18;

    uint256 _currentValueInProtocol = 1655585866666645023308474963495614966789;
    uint256 _existingEzETHSupply = 1655585866666645023308474963495614966789;
    uint256 _newValueAdded = 474622573299943436776128191208;

    // following code simulate RenzoOracle.calculateMintAmount function

    // Calculate the percentage of value after the deposit
    uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
        (_currentValueInProtocol + _newValueAdded);

    // Calculate the new supply
    uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
        (SCALE_FACTOR - inflationPercentaage);

    // Subtract the old supply from the new supply to get the amount to mint
    uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

    //////

    // mintAmount returned by RenzoOracle.calculateMintAmount function would be evaluated to _existingEzETHSupply * _newValueAdded / _currentValueInProtocol
    uint256 expectedMintAmount = _existingEzETHSupply * _newValueAdded / _currentValueInProtocol;

    // actual ezETH amount to be minted returned by RenzoOracle.calculateMintAmount function
    //   is lower than expected ezETH amount to be minted according to _existingEzETHSupply * _newValueAdded / _currentValueInProtocol
    assertGt(expectedMintAmount - mintAmount, 1000e18);
  }
}
```

## Recommended Mitigation Steps
https://github.com/code-423n4/2024-04-renzo/blob/549f774626b71dd13a427561d4743535a9cc0dca/contracts/Oracle/RenzoOracle.sol#L123-L149 can be updated to the following code.

```solidity
    function calculateMintAmount(
        uint256 _currentValueInProtocol,
        uint256 _newValueAdded,
        uint256 _existingEzETHSupply
    ) external pure returns (uint256) {
        // For first mint, just return the new value added.
        // Checking both current value and existing supply to guard against gaming the initial mint
        if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
            return _newValueAdded; // value is priced in base units, so divide by scale factor
        }

        uint256 mintAmount = _existingEzETHSupply * _newValueAdded / _currentValueInProtocol;

        // Sanity check
        if (mintAmount == 0) revert InvalidTokenAmount();

        return mintAmount;
    }
```
