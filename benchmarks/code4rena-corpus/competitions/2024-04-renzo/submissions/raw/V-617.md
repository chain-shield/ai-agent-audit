# Vulnerability details

## Impact
If the chainLink update the Oracle address in `AggregatorV3Interface` the decimals can also be changed from 18 decimals. it will break all the calculation of prices. this will impact `lookupTokenAmountFromValue` and `lookupTokenValue` function. I have explain it for `lookupTokenValue` but it can be apllied in a same way for `lookupTokenAmountFromValue`.

## Proof of Concept
Whenever there is new oracle added the check that if decimals of oracle are not 18 then it will not allow the oracle to be used in the system and throw error.

At line 61 it check if decimals are not 18 then throw error. after addition all the operation for calculating price are done on this assumption. However the chainLink aggregator can be changed to point to new oracle if they change some thing i.e decimals. 
```solidity
  function proposeAggregator(address _aggregator)
    external
    onlyOwner()
  {
    proposedAggregator = AggregatorV2V3Interface(_aggregator);
  }

  /**
   * @notice Allows the owner to confirm and change the address
   * to the proposed aggregator
   * @dev Reverts if the given address doesn't match what was previously
   * proposed
   * @param _aggregator The new address for the aggregator contract
   */
  function confirmAggregator(address _aggregator)
    external
    onlyOwner()
  {
    require(_aggregator == address(proposedAggregator), "Invalid proposed aggregator");
    delete proposedAggregator;
    setAggregator(_aggregator);
  }
``` 
It can be observed from above code that the aggregator address can be chnaged.
let assume the changed the aggregator address and the new chainlink oracle have 8 decimals instead of 18 the price return will be wrong as it can be seen from below calculations:
The code use following fommula to convert the price :
`        return (uint256(price) * _balance) / SCALE_FACTOR; // @audit : in case aggragtor got updated then the price value will be effected?
`
lets plug some test value let the price is 1 with 18 decimals, SCALE_FACTOR=1e18, and balance is 1 ether:
it will return ((1e18 * 1 ether)/ 1e18) = 1 ether.
now test with 8 decimals 
it will return ((1e8 * 1 ether)/ 1e18) = 0.0000000001 ether
There will be a significant lose of value .
