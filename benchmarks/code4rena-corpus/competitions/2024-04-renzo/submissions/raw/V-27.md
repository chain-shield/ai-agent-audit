# Vulnerability details

`RestakeManager::calculateTVLs()` function calculates the TVLs for each operator delegator by individual token, total for each OD, and total for the protocol.
Within the function it calls `OperatorDelegator::getStakedETHBalance()` which gets the amount of ETH staked in the EigenLayer.

`mapping(address => int256) public podOwnerShares` keeps track of the actively restaked beacon chain ETH for each Staker. Since balances on the consensus layer are stored only in Gwei amounts, the EigenPodManager enforces the invariant that podOwnerShares is always a whole Gwei amount for every staker, i.e. podOwnerShares[staker] % 1e9 == 0 always.
[Reference](https://github.com/Layr-Labs/eigenlayer-contracts/blob/dev/docs/core/EigenPodManager.md#important-state-variables)

In the implementation, the podOwnerShares return value is in `Gwei amount` instead of 1e18. This means that the Native Ether balanced return is not normalized to 1e18 for calculation.
```solidity
    function getStakedETHBalance() external view returns (uint256) {
        // accounts for current podOwner shares + stakedButNotVerified ETH + queued withdraw shares
        int256 podOwnerShares = eigenPodManager.podOwnerShares(address(this));
        return
            podOwnerShares < 0
                ? queuedShares[IS_NATIVE] + stakedButNotVerifiedEth - uint256(-podOwnerShares)
                : queuedShares[IS_NATIVE] + stakedButNotVerifiedEth + uint256(podOwnerShares);
    }
```

Returning to `RestakeManager::calculateTVLs()`, it becomes evident that the total TVL added is inaccurate, leading to inaccuracies in calculating withdrawals.
```solidity
    function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
            -- SNIP --
            uint256 operatorEthBalance = operatorDelegators[i].getStakedETHBalance();

            // Save it to the array for the OD
            // Will reset after each OD
            operatorValues[operatorValues.length - 1] = operatorEthBalance;

            // Add it to the total TVL for this OD
            operatorTVL += operatorEthBalance;

            // Add it to the total TVL for the protocol
            totalTVL += operatorTVL;
```

## Impact
Inaccurate TVL is used causing inflated wrong calculation
