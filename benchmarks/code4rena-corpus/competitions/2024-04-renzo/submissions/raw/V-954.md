# Vulnerability details

There are two fees charged by connext:
1. Relayer fee which is native token
2. Router fee which is 5bp of transferred token

The relayer fee is compulsory but the router fee is optional. It is charged for `xcall` that goes through the `fast path`. This is an excerpt from the [docs](https://docs.connext.network/developers/guides/estimating-fees)
```
If an xcall goes through the 'slow path' (authenticated), then users do not pay the router fee.
```

For a transaction to go through `fast path`, it needs to fulfill some [requirements](https://docs.connext.network/concepts/how-it-works/transaction-lifecycle#requirements)
```
For a cross-chain message to travel through the fast path, it must abide by BOTH of these requirements:

1. The transaction is bridging tokens only (no calldata) OR the calldata included is unauthenticated (anyone is allowed to call the function on the target contract).

AND

2. Routers are providing sufficient liquidity of the bridged token on the destination domain. We sometimes refer to this as the availability of "fast liquidity". If fast liquidity is not available, then the message will go through the slow path.
```

There's only an instance of `connext.xcall` in xRenzoDeposit and it used for transferring collateralToken to L1 in [sweep function](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L431-L441).
```solidity
// Need to send some calldata so it triggers xReceive on the target
bytes memory bridgeCallData = abi.encode(balance);

connext.xcall{ value: msg.value }(
    bridgeDestinationDomain,
    bridgeTargetAddress,
    address(collateralToken),
    msg.sender,
    balance,
    0, // Asset is already nextWETH, so no slippage will be incurred
    bridgeCallData
);
```

As can be seen above, xcall includes calldata. This means that it fails the requirements of `fast path` and would have to go through `slow path`.

The issue is that it charged users 5bp on their deposits for bridge router fee.
```solidity
// INITIALIZE FUNCTION
// Connext router fee is 5 basis points
bridgeRouterFeeBps = 5;


// _TRADE FUNCTION
// Subtract the bridge router fee
if (bridgeRouterFeeBps > 0) {
    uint256 fee = (amountNextWETH * bridgeRouterFeeBps) / 10_000;
    amountNextWETH -= fee;
}
```

## Impact
The protocol charges users 5bp on their deposits for a router fee that doesn't exist. This means that users are losing 5bp on all of their deposits.

## Proof of Concept
When users call deposit, depositToken is converted to collateralToken. Instead of minting xezETH for the full amount converted. They are shortchanged by 5%.

```solidity
// Swap the tokens
uint256 amountNextWETH = connext.swapExact(
    swapKey,
    _amountIn,
    address(depositToken),
    address(collateralToken),
    minOut,
    _deadline
);

// Subtract the bridge router fee
if (bridgeRouterFeeBps > 0) {
    uint256 fee = (amountNextWETH * bridgeRouterFeeBps) / 10_000;
    amountNextWETH -= fee;
}

return amountNextWETH;
```

## Recommended Mitigation Steps
Remove the fee charge

```diff
-   // Subtract the bridge router fee
-   if (bridgeRouterFeeBps > 0) {
-       uint256 fee = (amountNextWETH * bridgeRouterFeeBps) / 10_000;
-       amountNextWETH -= fee;
-   }
```

Alternatively, you might want to create a function to set bridgeRouterFeeBps to zero or any reasonable value. That way, there might not be need for upgrade if connext charge router fee for data transaction. This is an excerpt from their [docs](https://docs.connext.network/routers/routers-intro#business-model)
```
Routers currently do not take a fee for relaying data itself. There are future plans to implement an EIP-1559-style tip, that can supplement router income for data-only transactions.
```
