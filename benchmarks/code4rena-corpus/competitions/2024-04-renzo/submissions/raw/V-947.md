# Vulnerability details

## Summary

The protocol uses the restakeManager for depositing funds and minting ezETH in a manner similar to ERC4626 vaults. However, it lacks protections against flashloan attacks, allowing early depositors to manipulate exchange rates and effectively steal funds from later depositors.

## Vulnerability Detail

The stakeManager:deposit function facilitates the deposit of a supported LST (liquid staking token) in exchange for ezETH, calculating the mint amount based on the protocol's current value, new contributions, and existing ezETH supply. The formula used mirrors that of an ERC4626 vault, determining mint amounts proportionally to the contributed value relative to the total assets under management:
```solidity=123
function calculateMintAmount(
        uint256 _currentValueInProtocol,
        uint256 _newValueAdded,
        uint256 _existingEzETHSupply
    ) external pure returns (uint256) {
        // For first mint, just return the new value added.
        // Checking both current value and existing supply to guard against gaming the initial mint
        if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
            return _newValueAdded; // value is priced in base units, so divide by scale factor
        }

        // Calculate the percentage of value after the deposit
        uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded);

        // Calculate the new supply
        uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
            (SCALE_FACTOR - inflationPercentaage);

        // Subtract the old supply from the new supply to get the amount to mint
        uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

        // Sanity check
        if (mintAmount == 0) revert InvalidTokenAmount();

        return mintAmount;
    }
```

This mechanism, though standard, is susceptible to manipulation by malicious actors who can inflate the _currentValueInProtocol. This value is derived from the calculateTVL function, which aggregates the value of assets held by operator delegators, plus those in the deposit and withdrawal queues:

```solidity=355
totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);
```

A malicious user can exploit this by donating assets to the withdrawal queue, thereby inflating the totalTVL. and in doing so infaltes the price of ezETH to make next users deposits round down in favor of him.

## Proof Of Concept

- assumptions:
    - their are no funds in the protocol , totalTVL = 0
    - steth is a supported LST
    - Bob is a malicious user and he sees Alice transaction to deposit 10 stETH
- attack scenario:
    1. Bob frontruns alice by calling `stakeManager:Deposit` and deposits 1 wei of stETH
    2. according to the calculation in `renzoOracle:calculateMintAmount` he will get minted 1 wei of ezETH
    3. Bob sends 5.1e18 stETH to the withdrawalQueue which gets added to the totalTVL .
    4. now the exchange rate of ezETH/stETH = totalTVL/totalSupply(ezETH) = 5.1e18 + 1/1 = 5.1e18 stETH for 1 wei of ezETH
    5. Alice transaction goes through, and this is how much she will be minted: 
        - inflationPercentaage = (1e18 * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded) = 10e18*1e18/(10e18+1+5.1e18) = 0.621e18
        - newEzETHSupply = (1 * 1e18) /
            (1e18 - 0.66e18) =  2.6392.639 = 2 (rounds down)
        - mintAmount = newEzETHSupply - _existingEzETHSupply = 2 - 1 = 1
    6. so alice gets minted 1 wei ezETH.
    7. Bob and alice hold the same amount of ezETH so they each own 50% of the tvl in the protocol. tvl = 5.1e18 + 1 + 10e18 = 15.1e18 + 1.
    8. bob owns = 7.55 stETH and alice holds 7.55stETH
    9. so bob stole from alice 2.45 stETH

## Impact

early depositor would be able to steal funds from later depositers.

## Tool used

Manual Review

## Recommendation

- Implement slippage controls that allow users to specify a minimum amount of ezETH they expect to receive for their deposit.
- Set a minimum deposit value to reduce the impact of small, manipulative deposits.
- Seed new stakeManagers with an initial TVL to stabilize the initial exchange rates and prevent manipulation by the first few depositors.
