# Vulnerability details

Malicious actor can `frontrun` the deposits of an early user to `steal` his funds through `inflation attack`

//How this works(early stage)
1. Suppose a user is going to deposit `10 ether` in protocol
2. Malicious actor saw & `frontrun` this tx and `deposited` 1 wei, thus ezETHTotalSupply = 1 wei, totalTVL = 1 wei
```solidity
  if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
            return _newValueAdded; // value is priced in base units, so divide by scale factor
        }
```
3. Again malicious actor `directly` deposited 5 ether to depositQueue.sol, thus ezETHTotalSupply = 1 wei, totalTVL = 5 ether + 1(exclude the fee for simple)
4. Honest user `deposited` 10 ether, but got `only` 1 share[(10e18 * 1)/(5e18 + 1)] because of inflated TVL
```solidity
     uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded);

        // Calculate the new supply
        uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
            (SCALE_FACTOR - inflationPercentaage);

        // Subtract the old supply from the new supply to get the amount to mint
        uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;
```
5. Malicious actor `withdraw` his 1 share, which gave him `~7.5 ether` ie `50%` extra than he deposited
```solidity
  uint256 redeemAmount = (_currentValueInProtocol * _ezETHBeingBurned) / _existingEzETHSupply;
```
## Impact
`Loss` of funds to early depositors
