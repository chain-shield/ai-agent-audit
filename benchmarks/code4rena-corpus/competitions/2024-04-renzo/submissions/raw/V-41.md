# Vulnerability details

Users have the option to donate Ether through the `OperatorDelegator::receive()` function, and these contributions will be allocated as rewards. The Ether is then forwarded to the `DepositQueue.sol`, initiating the execution of the `DepositQueue::receive()` function.
```solidity
// OperatorDelegator.sol
receive() external payable nonReentrant {
            address destination = address(restakeManager.depositQueue());
            (bool success, ) = destination.call{ value: remainingAmount }("");
}
```
The Ether is sent to the `feeAddress` to cover the fee, and the remaining amount is set as the variable `remainingRewards`. The function `_checkAndFillETHWithdrawBuffer` checks if additional Ether needs to be added to `WithdrawalQueue.sol` to cover withdrawals after 7 days. 

However, the Ether sent to `WithdrawalQueue` is not subtracted from `remainingRewards`, causing inaccuracies in the `totalEarned` variable, which represents the actual earnings of the protocol.

```solidity
// `DepositQueue.sol`
    receive() external payable nonReentrant {
        uint256 feeAmount = 0;
        // Take protocol cut of rewards if enabled
        if (feeAddress != address(0x0) && feeBasisPoints > 0) {
            feeAmount = (msg.value * feeBasisPoints) / 10000;
            (bool success, ) = feeAddress.call{ value: feeAmount }("");
            if (!success) revert TransferFailed();

            emit ProtocolFeesPaid(IERC20(address(0x0)), feeAmount, feeAddress);
        }
        // update remaining rewards
        uint256 remainingRewards = msg.value - feeAmount; //@audit-issue
        // Check and fill ETH withdraw buffer if required
        //@audit-issue , totalEarned is not accurate, sending tokens to fill withdrawalQueue buffer deficit is not accounted for. Hence totalEarned adds the old remainingRewards that is not accurate
        _checkAndFillETHWithdrawBuffer(remainingRewards);
    
        // Add to the total earned
        totalEarned[address(0x0)] = totalEarned[address(0x0)] + remainingRewards;

        // Emit the rewards event
        emit RewardsDeposited(IERC20(address(0x0)), remainingRewards);
    }
```

## Impact
Rewards earned does not reflect the true value in the contract.

## Recommended Mitigation Steps
