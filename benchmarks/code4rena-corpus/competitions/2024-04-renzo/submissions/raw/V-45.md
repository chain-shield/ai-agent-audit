# Vulnerability details

Users can deposit funds into various chains, with the Chainlink price feed for ezETH/ETH being used to convert Ether to ezETH. The `RenzoOracleL2::getMintRate()` function retrieves the price of ezETH, which is then utilized to determine the minting rate in `xRenzoDeposit::_deposit`. However, a problem arises if the price feed for ezETH/ETH returns a value less than 1e18, as this will always cause the transaction to revert. 

The price of 1 ezETH in ETH will never remain constantly pegged for 24 hours; it will fluctuate, either being higher or lower at different times.

Currently, the price feed for Base Mainnet returns a value of [0.9833670506](https://data.chain.link/feeds/base/base/ezeth-eth) for ezETH/ETH. This means that no one can get the ezETH LRT due the revert denial, affecting business development.

P.S. In the README.md there any elaboration of what type of price feed is used, hence the submission.
## Impact
Inability to execute the deposit function will result in protocol failure and loss of bridge fees. This issue will also impact the ezETH LRT price by hindering the conversion of ETH to ezETH across different chains, which is crucial for the LRT's value.

## Proof of Concept
```solidity
    function getMintRate() public view returns (uint256, uint256) {
        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        // scale the price to have 18 decimals
        
        uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
        //@audit-issue Hardcoded revert, if ether returns back to the old days
        if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
    }
```
