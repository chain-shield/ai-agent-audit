# Vulnerability details

## Impact
`Proposer/Executor/Canceller` roles can never be revoked due to missing default admin implementation. The `DEFAULT_ADMIN_ROLE` which is the default role is admin to all the roles, and the real contract owner should own this role. 

Since it is not granted, the owner cannot govern the other roles.

## Proof of Concept
> [TimelockController::constructor()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/TimelockController.sol#L87-L119)
```solidity
    constructor(
        uint256 minDelay,
        address[] memory proposers,
        address[] memory executors,
        address admin
    ) {
        _setRoleAdmin(TIMELOCK_ADMIN_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(PROPOSER_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(EXECUTOR_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(CANCELLER_ROLE, TIMELOCK_ADMIN_ROLE);


        //...
        
    }
```
As it can be seen from above, the `DEFAULT_ADMIN_ROLE` is not granted to the owner (`TIMELOCK_ADMIN_ROLE`) address.



From [Openzeppelin::AccessControl](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/ecd2ca2cd7cac116f7a37d0e474bbb3d7d5e1c4d/contracts/access/AccessControl.sol#L40-L47)

```solidity
    * By default, the admin role for all roles is `DEFAULT_ADMIN_ROLE`, which means
    * that only accounts with this role will be able to grant or revoke other
    * roles. More complex role relationships can be created by using
    * {_setRoleAdmin}.
    *
    * WARNING: The `DEFAULT_ADMIN_ROLE` is also its own admin: it has permission to
    * grant and revoke this role. Extra precautions should be taken to secure
    * accounts that have been granted it.
    */
```
From the TimelockController [comments](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/TimelockController.sol#L17-L21):
```solidity
 * By default, this contract is self administered, meaning administration tasks
 * have to go through the timelock process. The proposer (resp executor) role
 * is in charge of proposing (resp executing) operations. A common use case is
 * to position this {TimelockController} as the owner of a smart contract, with
 * a multisig or a DAO as the sole proposer.
```
We can deduce that the `TimelockController` i.e `TIMELOCK_ADMIN_ROLE` is the one assuming the overall ownership role and as such, should be in a position to manage the other roles.

Since it is not granted, the owner cannot govern the other roles.

Manual Review

## Recommended Mitigation Steps
Modify the `constructor()` on `TimelockController.sol` to grant default admin role to owner.

```solidity
    constructor(
        uint256 minDelay,
        address[] memory proposers,
        address[] memory executors,
        address admin
    ) {
        _setRoleAdmin(TIMELOCK_ADMIN_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(PROPOSER_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(EXECUTOR_ROLE, TIMELOCK_ADMIN_ROLE);
        _setRoleAdmin(CANCELLER_ROLE, TIMELOCK_ADMIN_ROLE);
        _grantRole(DEFAULT_ADMIN_ROLE, TIMELOCK_ADMIN_ROLE); // @audit Role granted.

        //...
      }
```
