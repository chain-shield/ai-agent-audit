# Vulnerability details

## Impact
`OperatorDelegator.setDelegateAddress()` function delegate it shares to the choosen operator to receive additional rewards from the restaking. Since the function is callable only once, if the operator choose to undelegate themselves from the `OperatorDelegator` address, the OD contract won't be able to redelegate to another operator. 

As a result, any subsequent deposit to the EigenLayer via this `OperatorDelegator` won't accrue any further rewards. This is big deal to Renzo, since a large portion of TVL may left completely unused considering this OperatorDelegator holds the majority of `allocationBasisPoints` in the RestakeManager.

## Proof of Concept
It can clearly seen here, the function won't allow `delegationManager.delegateTo()` from the `OperatorDelegator` again, https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Delegation/OperatorDelegator.sol#L123-L125

## Recommended Mitigation Steps

The EigenLayer delegationManager won't allow `delegateTo` to another operator if it already delegated. It makes no sense for Renzo to add this additional check, also restricting the OD from redelegating to another operator. Make the following changes in OD, 

```diff
    function setDelegateAddress(
        address _delegateAddress, // operator
        ISignatureUtils.SignatureWithExpiry memory approverSignatureAndExpiry,
        bytes32 approverSalt
    ) external nonReentrant onlyOperatorDelegatorAdmin {
        if (address(_delegateAddress) == address(0x0)) revert InvalidZeroInput();
-       if (address(delegateAddress) != address(0x0)) revert DelegateAddressAlreadySet();

-       delegateAddress = _delegateAddress;

        delegationManager.delegateTo(delegateAddress, approverSignatureAndExpiry, approverSalt);

        emit DelegationAddressUpdated(_delegateAddress);
    }
```
