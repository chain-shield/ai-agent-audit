# Vulnerability details

## Description
The `recoverNative` function in the `xRenzoBridge` contract is not checking whether the `_amount` or `_to` is valid or not. This absence of validation may expose sweeping of `ETH` to potential vulnerabilities or unintended consequences, as it does not verify the legitimacy or correctness of the destination address before transferring native assets.
## Impact
As `transfer` function is used here which doesn't revert on zero address or amount. The main issue with using just transfer function is that it can fail silently without reverting. 

Without validation of the params, the contract may inadvertently transfer native assets to unintended or incorrect addresses, resulting in the loss of funds or misappropriation. Like if it sends ETH to zero address, or incorrect address. The funds can be lost forever. 

## Proof of Concept
See the following code:

```
 /**
     * @notice  Sweeps accidental ETH value sent to the contract
     * @dev     Restricted to be called by the bridge admin only.
     * @param   _amount  amount of native asset
     * @param   _to  destination address
     */
    function recoverNative(uint256 _amount, address _to) external onlyBridgeAdmin 
    {
        payable(_to).transfer(_amount);
    }
```

## Tools Used
Manual Review
## Recommended Mitigation Steps
Do some basic validation of the function params like zero address, or zero amount. Also use `SafeTransfer` to avoid some of the common issues too.
