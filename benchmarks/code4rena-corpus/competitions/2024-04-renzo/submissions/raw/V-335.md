# Vulnerability details

## Summary
`RestakeManager` contract contains two functions, `removeCollateralToken()` and `getTotalRewardsEarned()`, which together leads to an inaccurate calculation of the protocol's `total rewards`.

## Proof of Concept
The [removeCollateralToken()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L243-L263) function allows an `admin` to remove a collateral token from the active list, but it does not address any `rewards` that may have been accrued for that token.

```solidity
    /// @dev Allows restake manager to remove a collateral token
    function removeCollateralToken(
        IERC20 _collateralTokenToRemove
    ) external onlyRestakeManagerAdmin {
        // Remove it from the list
        uint256 tokenLength = collateralTokens.length;
        for (uint256 i = 0; i < tokenLength; ) {
            if (address(collateralTokens[i]) == address(_collateralTokenToRemove)) {
                collateralTokens[i] = collateralTokens[collateralTokens.length - 1];
                collateralTokens.pop();
                emit CollateralTokenRemoved(_collateralTokenToRemove);
                return;
            }
            unchecked {
                ++i;
            }
        }


        // If the item was not found, throw an error
        revert NotFound();
    }
```

Consequently, when [getTotalRewardsEarned()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L675-L693) is called, it calculates the `totalRewards` based only on the current list of `collateralTokens`, potentially omitting `rewards` from recently removed tokens. 
```solidity
    function getTotalRewardsEarned() external view returns (uint256) {
        uint256 totalRewards = 0;


        // First get the ETH rewards tracked in the deposit queue
        totalRewards += depositQueue.totalEarned(address(0x0));


        // For each token, get the total rewards earned from the deposit queue and price it in ETH
        uint256 tokenLength = collateralTokens.length;
        for (uint256 i = 0; i < tokenLength; ) {
            // Get the amount
            uint256 tokenRewardAmount = depositQueue.totalEarned(address(collateralTokens[i]));


            // Convert via the price oracle
            totalRewards += renzoOracle.lookupTokenValue(collateralTokens[i], tokenRewardAmount);


            unchecked {
                ++i;
            }
        }
        //... 
    } 
```
The potential issue arises when a `collateralToken` is removed from the `collateralTokens` array using `removeCollateralToken()`. If this happens, any `rewards` that have been accrued for that token will not be included in future calculations by `getTotalRewardsEarned()` because the token is no longer part of the array that the function iterates over.
 
This means that the function may underreport the `total rewards` if it does not account for rewards associated with tokens that have been removed.

###### Scenario
1. Initial State: 
Assume the protocol starts with `10 collateral tokens`, each with an accrued reward of `10 ETH` worth of value. The total rewards would be `10 tokens * 10 ETH/token = 100 ETH` for these `ERC20 tokens`.
2. Token Removal: 
Now, let's say `removeCollateralToken()` is called to remove one of these tokens (`Token X`).

3. Accrued Rewards for `Token X`: 
Before removal, Token `X` had accrued rewards of `10 ETH`.

4. Post-Removal State: 
After removal, the `collateralTokens` array has `9` tokens.

5. Future Reward Calculation: 
When `getTotalRewardsEarned()` is called after the removal, it only iterates over the remaining `9` tokens. Assuming each of the remaining tokens still has `10 ETH` worth of `rewards`, the function will calculate `9 tokens * 10 ETH/token = 90 ETH`.

6. Omitted Rewards: 
The `10 ETH` worth of rewards from the removed Token `X` are not included in this calculation.
7. Underreported Total Rewards: 
The actual `total rewards` should be `100 ETH` (including the rewards from Token X), but the function reports only `90 ETH` due to the omission.

## Impact
This oversight could result in an underreporting of the protocol's total rewards. 

## Tools Used
Manual Review

## Recommended Mitigation Steps
To ensure accuracy, the protocol would need to implement a strategy to handle the rewards of removed tokens, such as:

- Keeping a separate historical record of rewards for removed tokens that continues to be included in the total rewards calculation.
- Having a mechanism to claim or burn the accrued rewards for a token at the time of its removal.

Without such a mechanism, the `getTotalRewardsEarned()` function may not reflect the true total rewards earned by the protocol, particularly after the removal of one or more collateral tokens.
