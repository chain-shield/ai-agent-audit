# Vulnerability details

## Title
`WithdrawQueue::withdraw()` is missing slippage control with redeeming the amount in ETH.


## Impact
The function `WithdrawQueue::withdraw()` is used to create withdraw request for users. It calculates the `amountToRedeem` using the `calculateRedeemAmount` function which is dependent on `calculateTVLs()` function. 

Due to not enforcing any slippage control while requesting withdraw by users, it might `amountToRedeem` might return unexpected too low value causing users loss of ETH to claim if `totalTVL` is impacted by the oracle price inconsistencies.

```solidity
    function withdraw(uint256 _amount, address _assetOut)   external nonReentrant {
        ...
        ...
        // Calculate amount to Redeem in ETH
        uint256 amountToRedeem = renzoOracle.calculateRedeemAmount(
            _amount,
            ezETH.totalSupply(),
            totalTVL
        );
        ...
        ...
    }
```

From the above function, we can see that there is no slippage control to handle the `amountToRedeem` which is being indirectly related to oracle price.

Impact: High (as user might face loss of ETH)
Likelihood: Low 
Severity: Medium

We can see that `totalTVL` is dependent on oracle price return and depends on the withdrawal queue token amount, as oracle price fluctuates the trade can be impacted while requesting for a withdrawal, which will ultimately result in loss of funds for users.

```solidity
    function calculateRedeemAmount(
        uint256 _ezETHBeingBurned,
        uint256 _existingEzETHSupply,
        uint256 _currentValueInProtocol
    ) external pure returns (uint256) {
        // This is just returning the percentage of TVL that matches the percentage of ezETH being burned
        uint256 redeemAmount = (_currentValueInProtocol * _ezETHBeingBurned) / _existingEzETHSupply;

        // Sanity check
        if (redeemAmount == 0) revert InvalidTokenAmount();

        return redeemAmount;
    }
```

as we can see, the redeem Amount is computed:


assume _ezETHBeingBurned is a constant,

change in oracle price , (especially oracle price drop, can decrease user's redeem amount), usre cannot control the oracle price or when oracle rate are updatd 

increase / inflation of the _existingEzETHSupply, can  decrease user's redeem amount, user cannot control how much ezETH token other people minted.

## Recommended Mitigation Steps

We recommend to implement a check so that user can specify the min amount of ETH they will get when requesting for a withdrawal otherwise revert.

```solidity
    function withdraw(uint256 _amount, address _assetOut, uint256 minAssetOut)   external nonReentrant {
        ...
        ...
        // Calculate amount to Redeem in ETH
        uint256 amountToRedeem = renzoOracle.calculateRedeemAmount(
            _amount,
            ezETH.totalSupply(),
            totalTVL
        );

        // slippage contorl here.
        if(minAssetOut < _amount) {
            revert("too few token redeemed")
```
