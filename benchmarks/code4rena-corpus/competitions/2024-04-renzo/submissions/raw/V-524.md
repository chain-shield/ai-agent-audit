# Vulnerability details

## Title
Withdraw queue TVL should be excluded when deposit calculating deposit limit.

## Line of code
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L529C13-L530C45

## Impact
When users deposit using the function `RestakeManage::deposit` it checks the collateral token amount is not greater than `maxDepositTVL` set by `onlyRestakeManagerAdmin`. 

```solidity
    if (maxDepositTVL != 0 && totalTVL + collateralTokenValue > maxDepositTVL) {
            revert MaxTVLReached();
        }
```
Here the `totalTVL` is calculated from `calculateTVLs()` function. We can see, when calculated TVL we include the withdrawal queque amount also. The issue here with the check
`totalTVL + collateralTokenValue > maxDepositTVL` is that `totalTVL` is added with `collateralTokenValue` to check if it is greater than `maxDepositTVL`. Withdraw queue balance is meant to let user withdraw and should not block user deposit via RestakingManager.

## Proof of Concept
We can see this [deposit](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L529C13-L530C45) function of RestakeManager, we can see it checks the if `maxDepositTVL` is reached against `totalTVL + collateralTokenValue`. The `totalTVL` is calculated via `calculateTVLs()`.

Now if we look at [RestakeManager::calculateTVLs()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L274), the `totalWithdrawalQueueValue` is added to the `(address(withdrawQueue).balance` to get the `totalTVL`. 

```solidity
function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
        uint256[][] memory operatorDelegatorTokenTVLs = new uint256[][](operatorDelegators.length);

        uint256[] memory operatorDelegatorTVLs = new uint256[](operatorDelegators.length);

        uint256 totalTVL = 0;

        // Iterate through the ODs
        uint256 odLength = operatorDelegators.length;

        // withdrawalQueue total value
        uint256 totalWithdrawalQueueValue = 0;

        for (uint256 i = 0; i < odLength; ) {
            // Track the TVL for this OD
            uint256 operatorTVL = 0;

            // Track the individual token TVLs for this OD - native ETH will be last item in the array
            uint256[] memory operatorValues = new uint256[](collateralTokens.length + 1);

            operatorDelegatorTokenTVLs[i] = operatorValues;

            // Iterate through the tokens and get the value of each
            uint256 tokenLength = collateralTokens.length;

            for (uint256 j = 0; j < tokenLength; ) {
                // Get the value of this token

                uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                    collateralTokens[j]
                );

                // Set the value in the array for this OD
                operatorValues[j] = renzoOracle.lookupTokenValue(
                    collateralTokens[j],
                    operatorBalance
                );

                // Add it to the total TVL for this OD
                operatorTVL += operatorValues[j];

                // record token value of withdraw queue
@>               if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i],
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }

                unchecked {
                    ++j;
                }
            }

            // Get the value of native ETH staked for the OD
            uint256 operatorEthBalance = operatorDelegators[i].getStakedETHBalance();

            // Save it to the array for the OD
            operatorValues[operatorValues.length - 1] = operatorEthBalance;

            // Add it to the total TVL for this OD
            operatorTVL += operatorEthBalance;

            // Add it to the total TVL for the protocol
            totalTVL += operatorTVL;

            // Save the TVL for this OD
            operatorDelegatorTVLs[i] = operatorTVL;

            // Set withdrawQueueTokenBalanceRecorded flag to true
            withdrawQueueTokenBalanceRecorded = true;

            unchecked {
                ++i;
            }
        }

        // Get the value of native ETH held in the deposit queue and add it to the total TVL
        totalTVL += address(depositQueue).balance;

        // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
@>      totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);

        return (operatorDelegatorTokenTVLs, operatorDelegatorTVLs, totalTVL);
    }

```
Because of adding withdrawal queue balance, it is an issue because it should not block users from depositing by impacting on the check: `totalTVL + collateralTokenValue > maxDepositTVL` on deposit function.

Consider the case if the maxDepositTVL is 10000 ETH,

there are 3000 ETH in withdrawal queue, and user does not withdraw those 3000 ETH, 

the max amount user can deposit is 7000 ETH and those 3000 ETH in withdraw queue incorrectly block user from deposit.

## Tools Used
Manual Review
## Recommended Mitigation Steps
We recommend to remove the withdrawal queue part from the `maxDepositTVL` check.
