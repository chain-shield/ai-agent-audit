# Vulnerability details

## **Vulnerability Details:**

The protocol docs [state](https://code4rena.com/audits/2024-04-renzo#top:~:text=ERC20%20rewards%20earned%20in%20EigenLayer%20will%20be%20sent%20to%20the%20DepositQueue%20address.%20The%20protocol%20can%20then%20sweep%20the%20ERC20%20fee%20percentage%20to%20the%20target%20address%20and%20deposit%20the%20remaining%20ERC20%20tokens%20into%20the%20protocol%20through%20an%20Operator%20Delegator.):

- ERC20 rewards earned in EigenLayer will be sent to the DepositQueue address. The protocol can then sweep the ERC20 fee percentage to the target address and deposit the remaining ERC20 tokens into the protocol through an Operator Delegator.

The **[depositTokenRewardsFromProtocol](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L647)** function in the **RestakeManager** contract deposits ERC20 token rewards from the **DepositQueue** contract to Renzo. This is done by the **ERC20RewardsAdmin** calling the **[sweepERC20](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Deposits/DepositQueue.sol#L254)** function in the **DepositQueue** contract. However, these rewards are not currently accounted for in the protocol's TVL, meaning the deposit into Renzo can be sandwiched to extract instant value from the protocol.

```solidity
    function sweepERC20(IERC20 token) external onlyERC20RewardsAdmin {
        uint256 balance = IERC20(token).balanceOf(address(this));
        if (balance > 0) {
            uint256 feeAmount = 0;

            // Sweep fees if configured
            if (feeAddress != address(0x0) && feeBasisPoints > 0) {
                feeAmount = (balance * feeBasisPoints) / 10000;
                IERC20(token).safeTransfer(feeAddress, feeAmount);

                emit ProtocolFeesPaid(token, feeAmount, feeAddress);
            }

            // Approve and deposit the rewards
            token.approve(address(restakeManager), balance - feeAmount);
            restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount);

            // Add to the total earned
            totalEarned[address(token)] = totalEarned[address(token)] + balance - feeAmount;

            // Emit the rewards event
            emit RewardsDeposited(IERC20(address(token)), balance - feeAmount);
        }
    }
```

To avoid the value being sandwiched, the **[calculateTVLs](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L274)** function should include the collateral tokens in the deposit queue contract, as done correctly for ETH rewards sent to the deposit queue. 

Furthermore, the **depositTokenRewardsFromProtocol** function does not check the TVL limit nor the individual token TVL limits, meaning they can both be bypassed through this function.

```solidity
    function depositTokenRewardsFromProtocol(IERC20 _token, uint256 _amount) external onlyDepositQueue {
        // Get the TVLs for each operator delegator and the total TVL
        (, uint256[] memory operatorDelegatorTVLs, uint256 totalTVL) = calculateTVLs();

        // Determine which operator delegator to use
        IOperatorDelegator operatorDelegator = chooseOperatorDelegatorForDeposit(operatorDelegatorTVLs, totalTVL);

        // Transfer the tokens to this address
        _token.safeTransferFrom(msg.sender, address(this), _amount);

        // Approve the tokens to the operator delegator
        _token.safeApprove(address(operatorDelegator), _amount);

        // Deposit the tokens into EigenLayer
        operatorDelegator.deposit(_token, _amount);
    }
```

## **Impact:**

- Severity: Medium. This allows for sandwich attacks, leading to losses for stakers. Additionally, the lack of TVL limit checks in the **depositTokenRewardsFromProtocol** function means that limits can be bypassed.
- Likelihood: Medium. The likelihood will depend on how often rewards are sent to the **DepositQueue** contract.

## **Tools Used:**

- Manual analysis

## **Recommendation:**

To mitigate this issue, modify the **calculateTVLs** function to include collateral tokens in the deposit queue contract. Additionally, ensure that the **depositTokenRewardsFromProtocol** function checks the TVL limit and individual token TVL limits to prevent bypassing these limits.
