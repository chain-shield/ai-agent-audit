# Vulnerability details

## Impact
The current implementation of the `removeOperatorDelegator()` function in the RestakeManager contract does not properly handle the removal of an OperatorDelegator. When an `OperatorDelegator` is removed,this can cause the entire staked tokens to be lost.

## Proof of Concept

If RestakeManager is initialized the OperatorDelegator it has a depoled a new EigenPod.

```solidity
   /// @dev Initializes the contract with initial vars
    function initialize(
        IRoleManager _roleManager,
        IStrategyManager _strategyManager,
        IRestakeManager _restakeManager,
        IDelegationManager _delegationManager,
        IEigenPodManager _eigenPodManager
    ) external initializer {

         //...
        __ReentrancyGuard_init();

        roleManager = _roleManager;
        strategyManager = _strategyManager;
        restakeManager = _restakeManager;
        delegationManager = _delegationManager;
        eigenPodManager = _eigenPodManager;

        // Deploy new EigenPod
        eigenPod = IEigenPod(eigenPodManager.createPod());
    }
```

in EL there is a mapping that track the operatorDelegator address that has the owner of the pod.

```solidity

mapping(address => IEigenPod) public ownerToPod;

// store the pod in the mapping
ownerToPod[msg.sender] = pod;
```

So When removing OperatorDelegator in `RestakeManager.removeOperatorDelegator()` it doesn't checks any of these scenario.

When an OperatorDelegator is removed, this can cause the entire staked tokens to be lost in the EL.

- Update Delegation: The operator delegator would need to be removed from EigenLayer via an `Undelegate` function call for a specific Operator

- Update Strategies: The strategies associated with the operator delegator would need to be updated to point to the new operator delegator or removed if no longer needed or it will lost all the assets for a specific OperatorDelegator.

- Transfer Tokens: Any tokens currently held by the operator delegator would need to be transferred to a new operator delegator or back to the RestakeManager.

```solidity
tokenStrategyMapping[token].userUnderlyingView(address(this))
```

Withdraw Staked ETH: Any staked ETH associated with the operator delegator would need to be withdrawn from EigenLayer and transferred to the new operator delegator or the RestakeManager.

```solidity
    function removeOperatorDelegator(
        IOperatorDelegator _operatorDelegatorToRemove
    ) external onlyRestakeManagerAdmin {
        // Remove it from the list
        uint256 odLength = operatorDelegators.length;
        for (uint256 i = 0; i < odLength; ) {
            if (address(operatorDelegators[i]) == address(_operatorDelegatorToRemove)) {
                // Clear the allocation
                operatorDelegatorAllocations[_operatorDelegatorToRemove] = 0;
                emit OperatorDelegatorAllocationUpdated(_operatorDelegatorToRemove, 0);

                // Remove from list
                operatorDelegators[i] = operatorDelegators[operatorDelegators.length - 1];
                operatorDelegators.pop();
                emit OperatorDelegatorRemoved(_operatorDelegatorToRemove);
                return;
            }
            unchecked {
                ++i;
            }
        }

        // If the item was not found, throw an error
        revert NotFound();
    }
```

So if a `removeOperatorDelegator` is removed in the `RestakeManager`, it doesn't check any of these scenarios.

## Tools Used
Manual Review

## Recommended Mitigation Steps

Modify the `removeOperatorDelegator()` function to include the necessary steps for handling the removal of an OperatorDelegator. This should include updating the delegation, updating strategies, transferring tokens, and withdrawing staked ETH associated with the operator delegator.
