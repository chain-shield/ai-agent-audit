# Vulnerability details

## Impact
The OperatorDelegator contract relies on individual admin accounts calling it to fulfill its various functions. The contract implements a mechanism to refund gas spent on these maintenance transactions to the admins. However, an admin can submit a transaction with exceptionally high gas price, then fulfill it with his own miner and then siphon the abnormally large gas refund from the protocol. Since the gas paid by this admin for unsuccessfully mining the transaction will be refunded by the protocol anyway there is basically 0 risk for the attacker, and at the very least, this is a griefing attack vector, that can escalate to a theft of funds.

## Proof of Concept
The OperatorDelegator contract has a mechanism to keep track of gas refunds. This is done in the _recordGas() function:

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L481
```js
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
        adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```

This accounting function is called in [queueWithdrawals()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L253), [completeQueuedWithdrawal()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L323), [verifyWithdrawalCredentials()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L391) [and verifyAndProcessWithdrawals()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L423). These are all admin managed functions. Protocol admins spent gas on these functions and are expected to receive a refund for the gas spent.

However, as we can see the gasSpent is calculated by multiplying the expended gas by the tx.gasprice, which can be manipulated. It is possible for a malicios admin to submit a transaction with exceptionally high tx.gasprice, have his own miner execute the transaction and then request a refund for the large gas refund

Refunds are requested through the overriden `receive()` function, which sends part of the received native tokens to the admin and the rest is forwardede to the depositQueue:

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L501
```js
    receive() external payable nonReentrant {
        // check if sender contract is EigenPod. forward full withdrawal eth received
        if (msg.sender == address(eigenPod)) {
            restakeManager.depositQueue().forwardFullWithdrawalETH{ value: msg.value }();
        } else {
            // considered as protocol reward
            uint256 gasRefunded = 0;
            uint256 remainingAmount = msg.value;
            if (adminGasSpentInWei[tx.origin] > 0) {
                gasRefunded = _refundGas();
                // update the remaining amount
                remainingAmount -= gasRefunded;
                // If no funds left, return
                if (remainingAmount == 0) {
                    return;
                }
            }
            // Forward remaining balance to the deposit queue
            address destination = address(restakeManager.depositQueue());
            (bool success, ) = destination.call{ value: remainingAmount }("");
            if (!success) revert TransferFailed();

            emit RewardsForwarded(destination, remainingAmount);
        }
    }
```

Actual refund is done in the _refundGas() transaction. Refund is done to the tx.origin, because the actual funds to be refunded do not come from the admin but from a 3rd contract in the middle, that is supposed to hold funds for the refund. This middle contract will the target to siphon the native tokens from:

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L481
```js
    function _refundGas() internal returns (uint256) {
        uint256 gasRefund = address(this).balance >= adminGasSpentInWei[tx.origin]
            ? adminGasSpentInWei[tx.origin]
            : address(this).balance;
        bool success = payable(tx.origin).send(gasRefund);
        if (!success) revert TransferFailed();

        // reset gas spent by admin
        adminGasSpentInWei[tx.origin] -= gasRefund;

        emit GasRefunded(tx.origin, gasRefund);
        return gasRefund;
    }
```

While this may be difficult to execute, it is a possible attack vector, that if done can lead to major loss of funds.
