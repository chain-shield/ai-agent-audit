# Vulnerability details

## Impact

1. Exchange rate is calculated incorrectly.
2. Rewards is distributed unfairly.
3. Some user lose their own funds.

## Proof of Concept

When `ezETH` tokens are withdrawn, they are not burned. They are transferred to `withdrawQueue`, so the `totalSupply` of `ezETH` is not changed. Also, the `amountToRedeem` is calculated based on the current exchange rate.

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L206-L263

```solidity

    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        [...]
        // transfer ezETH tokens to this address
@>      IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);

        // calculate totalTVL
        (, , uint256 totalTVL) = restakeManager.calculateTVLs();

        // Calculate amount to Redeem in ETH
@>      uint256 amountToRedeem = renzoOracle.calculateRedeemAmount(
            _amount,
            ezETH.totalSupply(),
            totalTVL
        );

            // Get ERC20 asset equivalent amount
@>          amountToRedeem = renzoOracle.lookupTokenAmountFromValue(
                IERC20(_assetOut),
                amountToRedeem

        }
        [...]

```

When claiming, the withdrawn ezETH is burned, and the pre-calculted amount of tokens is transferred to the user.

```solidity
    function claim(uint256 withdrawRequestIndex) external nonReentrant {
        [...]
        // burn ezETH locked for withdraw request
@>      ezETH.burn(address(this), _withdrawRequest.ezETHLocked);

        // send selected redeem asset to user
        if (_withdrawRequest.collateralToken == IS_NATIVE) {
@>          payable(msg.sender).transfer(_withdrawRequest.amountToRedeem);
        } else {
            IERC20(_withdrawRequest.collateralToken).transfer(
                msg.sender,
@>              _withdrawRequest.amountToRedeem
            );
        }
        // emit the event
        emit WithdrawRequestClaimed(_withdrawRequest);
    }

```

However, the total amount of all withdrawn tokens are added to `TVL`. As a result, claiming or not claiming may affect the exchange rate. This can lead to errors in the calculation of the exchange rate.

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L274-L358

```solidity

    function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
        [...]
        // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
@>      totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);

        return (operatorDelegatorTokenTVLs, operatorDelegatorTVLs, totalTVL);
    }

```

Consider the following scenarios:

- The first scenario.
1. Suppose that TVL == 3001, totalSupply == 3001 and there are only ethers in the protocol. 
2. Alice, Bob, and Charlie each have 1000 ezETH, while David has only 1 ezETH.
3. Alice withdraws 1000 ezETH and can claim 1000 ETH in return. TVL == 3001, totalSupply == 3001.
4. Bob withdraws 1000 ezETH and can claim 1000 ETH in return, too. TVL == 3001, totalSupply == 3001.
5. After some time has passed, 300 Eth is given as rewards. TVL == 3301, totalSupply == 3001.

As the result of the above scenario:
i. Before Alice and Bob claim their withdrawn ETH, Charlie can only receive 1000*3301/3001=1099ETH.
ii. After Alice and Bob claim their withdrawn ETH, Charlie can receive 1000*1301/1001=1299ETH.

This is very unreasonable. The reward 300Eth should be given to Charlie. However, he cannot take all them before Alice and Bob claim their funds. 

Furthermore, after Charlie claims his funds in the case of (i), David can receive 3301 - 2000 - 1099 = 202 ETH with only 1 ezETH.

-The second scenario.
1. The price of stETH is 1. 

The following users deposit tokens and receives exETH tokens.
    Alice       100stETH    100ezETH
    Bob         91   ETH    91ezETH
    Charlie     9    ETH    9ezETH    

2. Alice withdraws 100ezETH and can claim 100stETH, but she does not claim. TVL = 100 * 1 + 100 = 200, totalSupply = 200.
3. The price of stETH increases to 1.2. TVL = 100 * 1.2 + 100 = 220, totalSupply = 200.
Bob withdraw 91ezETH and can claim 220 * 91 /200 = 100ETH. 
4. Alice claims 100stETH and Bob claims 100ETH.
5. Now TVL = 0, totalSupply = 9. Charlie can claim nothing.

## Recommended Mitigation Steps

The `ezETH` tokens should be immediately burned in `withdrawal()`.

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol

```diff

    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        [...]
-       IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);
+       ezETH.burn(msg.sender, _amount);
        [...]
    }

    function claim(uint256 withdrawRequestIndex) external nonReentrant {
        [...]
-       // burn ezETH locked for withdraw request
-       ezETH.burn(address(this), _withdrawRequest.ezETHLocked);
        [...]
    }

```
