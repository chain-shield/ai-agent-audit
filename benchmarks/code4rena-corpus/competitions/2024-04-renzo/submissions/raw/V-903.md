# Vulnerability details

## Impact
Due to wrong `underlying token amount` return from each `OperatorDelegator.getTokenBalanceFromStrategy()`, `calculated TVL` will be less than actual locked value, which is a crucial part of the protocol.

For Detailed info refer `Description` part

## Descripion
So The bug exists like following
For TVL calculation in `RestakeManager.sol` `calculateTVLs()` called, its works as following 
- loop over all operatorDelegators
     - for each operatorDelegator it loop over all available collateral tokens and 
       call
```solidity
                uint256 operatorBalance = operatorDelegators[i].getTokenBalanceFromStrategy(
                    collateralTokens[j]
                );
```      
The implementation for `getTokenBalanceFromStrategy()` as follows where it `intended` to returns `underlying token amount from the amount of shares + queued withdrawal shares`

```solidity
    /// @dev Gets the underlying token amount from the amount of shares + queued withdrawal shares
    function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
            queuedShares[address(this)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this)) 
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView( 
                        queuedShares[address(token)] 
                    );
    }
```
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L327-L335

Here main point to give attetion is `queued withdrawal shares` i.e `queuedShares[address(token)]`

So basically `queuedShares` is `mapping of token shares in withdraw queue of EigenLayer`
```solidity
 mapping(address => uint256) public queuedShares;
```
This mapping for a token changes in 2 places `queueWithdrawals()` & `completeQueuedWithdrawal()`

So basically `queuedShares` mapping tracking the tokens present in withdrawal Queue

But when `getTokenBalanceFromStrategy()` called for `operatorDelegator` it has following ternary operator
```solidity
            queuedShares[address(this)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this)) 
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView( 
                        queuedShares[address(token)] 
```
So here `queuedShares[address(this)] == 0` always going to be `TRUE`
cause value stored for `address(this)` in `queuedShares` is `default i.e 0` as i mentioned `queuedShares` only tracks `collateralTokens`. So here always first condition will run(i.e never going to consider `queuedShares` for that token).

So in end result underlying amount returned by `getTokenBalanceFromStrategy()`  is wrong(less) when there is `queued withdrawal shares` present for the token in `queuedShares` mapping.

## Recommended Mitigation Steps
In ternary operation check it should be `queuedShares[address(token)] == 0` as follows

`queuedShares mapping check` should present for `token` not for `address(this)`

```solidity
    function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
-           queuedShares[address(this)] == 0
+           queuedShares[address(token)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this)) 
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView( 
                        queuedShares[address(token)] 
                    );
    }
```
