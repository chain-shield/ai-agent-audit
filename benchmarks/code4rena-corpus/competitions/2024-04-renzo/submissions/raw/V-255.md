# Vulnerability details

## Impact

When a user attempts to deposit ERC20 tokens and the amount is less than the remaining buffer amount for the corresponding token in the `WithdrawQueue`, the deposit operation will revert.

The withdraw buffer amount is typically a large amount, as it needs to accommodate the withdrawal demands of many users concurrently. Therefore, this error could lead to a significant DOS vulnerability with a wide impact range.

## Proof of Concept

When a user deposits ERC20 tokens, the remaining withdraw buffer amount for that token will be obtained through the `WithdrawQueue`. 

[RestakeManager.sol#L543-L549](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L543-L549)

```solidity
uint256 bufferToFill = depositQueue.withdrawQueue().getBufferDeficit(
    address(_collateralToken)
);
    if (bufferToFill > 0) {
        bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
        // update amount to send to the operator Delegator
        _amount -= bufferToFill;
```

If `_amount` is less than `bufferToFill`, it means that all tokens deposited by the user will be placed in the buffer of the `WithdrawQueue`. Then, `_amount` will be reduced to **0**.

Subsequently, an attempt is made to deposit 0 tokens into the `operatorDelegator`.

[RestakeManager.sol#L558-L562](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L558-L562)

```solidity
// Approve the tokens to the operator delegator
_collateralToken.safeApprove(address(operatorDelegator), _amount);

// Call deposit on the operator delegator
operatorDelegator.deposit(_collateralToken, _amount);
```

However, in the `deposit` function of the `operatorDelegator`, attempting to deposit 0 tokens will result in a revert.

[OperatorDelegator.sol#L143-L148](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L143-L148)

```solidity
function deposit(
    IERC20 token,
    uint256 tokenAmount
) external nonReentrant onlyRestakeManager returns (uint256 shares) {
    if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
        revert InvalidZeroInput();
```

## Recommended Mitigation Steps

Add a conditional check to deposit into the `operatorDelegator` only if there is still remaining `_amount` after filling the buffer of the `WithdrawQueue`.

```diff
+ if (_amount > 0) {
    // Approve the tokens to the operator delegator
    _collateralToken.safeApprove(address(operatorDelegator), _amount);

    // Call deposit on the operator delegator
    operatorDelegator.deposit(_collateralToken, _amount);
+ }
```
