# Vulnerability details

## Summary
The `fillEthWithdrawBuffer()` function in `WithdrawQueue.sol` is used to `fill Eth WithdrawBuffer from RestakeManager deposits`. As such, according to the comment, this should be a permissioned call (`onlyRestakeManager`).

However, the implementation uses the `onlyDepositQueue` modifier, which restricts access to the `DepositQueue`.

## Proof of Concept
> [fillEthWithdrawBuffer()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L179-L184)
```solidity
     * @notice  fill Eth WithdrawBuffer from RestakeManager deposits
     * @dev     permissioned call (onlyRestakeManager)
     */
    function fillEthWithdrawBuffer() external payable nonReentrant onlyDepositQueue { // @audit Wrong modifier used here (onlyDepositQueue)
        emit EthBufferFilled(msg.value);
    }
```
If the `fillEthWithdrawBuffer()` function is intended to be called only by the `RestakeManager` but is instead accessible by the `DepositQueue` due to the wrong modifier, it could lead to several issues:

1. Unauthorized Access: 
If the `DepositQueue` is not supposed to have the ability to call this function, this opens up a vector for unauthorized actions.
2. Funds Risk: 
Since the function deals with transferring `ETH`, incorrect access control could put funds at risk.

###### Note:
The `WithdrawQueue` contract defines the `onlyRestakeManager` modifier but none of the functions within it are decorated with it. 
From this, I can confidently conclude that the Developer's comment on this function is correct but it is its implementation that is incorrect and hence the vulnerability. 

## Impact
The function may be executed by an unintended entity, potentially leading to unauthorized operations or worse.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The `fillEthWithdrawBuffer()` function should use this `onlyRestakeManager` modifier instead of `onlyDepositQueue` to match the intended access control:

```solidity
function fillEthWithdrawBuffer() external payable nonReentrant onlyRestakeManager { // @audit Correct modifier used
    // function implementation
}
```

This change will ensure that only the `RestakeManager` can call the `fillEthWithdrawBuffer()` function, aligning the implementation with the comment and the intended access control policy.
