# Vulnerability details

## Impact

The `RestakeManager::calculateTVLs` function is designed to compute TVL for each Operator Delegator and by individual token. However, there's a critical flaw in the implementation where the `operatorDelegatorTokenTVLs` array is assigned to `operatorValues` before the latter has been populated with actual TVL data. This leads to scenarios where functions relying on `calculateTVLs` like `RestakeManager::deposit` to receive uninitialized TVL data. This can cause a check supposed to revert when the maximum amount TVL to deposit is reached to be bypassed in the `RestakeManager::deposit` function.


## Proof of Concept
The issue occurs in the `calculateTVLs` function, where `operatorDelegatorTokenTVLs[i]` is prematurely set to `operatorValues` before it is populated as shown in the code below :

```js
    function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
    ...
            uint256[] memory operatorValues = new uint256[](collateralTokens.length + 1);
            operatorDelegatorTokenTVLs[i] = operatorValues; //operatorValues is empty at this point
```

The array `operatorValues` is populated later on :

```js
                operatorValues[j] = renzoOracle.lookupTokenValue(
                    collateralTokens[j],
                    operatorBalance
                );
```

The problem is that the `RestakeManager::deposit` calls this function and uses the `operatorDelegatorTokenTVLs` array values to get the total TVL per token. 
```js
  // Function deposit

        // Get the TVLs for each operator delegator and the total TVL
        (
            uint256[][] memory operatorDelegatorTokenTVLs,
            uint256[] memory operatorDelegatorTVLs,
            uint256 totalTVL
        ) = calculateTVLs();

   ...

            uint256 odLength = operatorDelegatorTokenTVLs.length;
            for (uint256 i = 0; i < odLength; ) {
                currentTokenTVL += operatorDelegatorTokenTVLs[i][tokenIndex];
                unchecked {
                    ++i;
                }
            }
```
Since `operatorDelegatorTokenTVLs` array values are set to 0, the `currentTokenTVL` sum will also be 0.

This `currentTokenTVL` amount is then used to check if this total plus the `collateralTokenValue` i.e the value of the amount to deposit is over the limit :

```js
            // Check if it is over the limit
            if (currentTokenTVL + collateralTokenValue > collateralTokenTvlLimits[_collateralToken])
                revert MaxTokenTVLReached();
        }
```

However, currentTokenTVL will always be 0. This means that in most cases where this check should revert the tx it will still pass.

## Recommended Mitigation Steps

Consider updating the `operatorDelegatorTokenTVLs` after the `j` loop has ended.
