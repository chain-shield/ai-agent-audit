# Vulnerability details

## Impact

The contract xRenzoDeposit.sol does not re-set allowance before setting a new one in the function _trade().
 This can potentially make the contract vulnerable to an "Infinite Approval Attack". 

An infinite approval means setting the allowance to the maximum possible uint256 value. The issue with infinite approvals is that while they require less gas (and thus less fees for users), they can potentially be unsafe. If an attacker is able to manipulate the token contract or if the spender is malicious, they can potentially steal an unlimited amount of tokens from the user.

Here's a simple example of how an infinite approval attack might work:
1. The contract approves a transfer of `N` tokens to another (malicious) address or contract.
2. The malicious contract transfers `N` tokens from the contract.
3. The malicious contract then increments its allowance by `M`, effectively increasing its total allowance to `N + M`.
4. This process can be repeated indefinitely to drain funds from the contract.

## Recommended Mitigation Steps

To mitigate this potential risk, the contract should call the `approve` function to set the allowance to 0 before setting it to another value. Here is an example of how to safely approve tokens:
```solidity
depositToken.safeApprove(address(connext), 0);
depositToken.safeApprove(address(connext), _amountIn);
``` 
Or the contract can ensure that the current allowance is 0 before setting a new one:
```solidity
uint256 currentAllowance = token.allowance(address(this), spender);
require(currentAllowance == 0, "ERC20: must first reset approval amount to zero before setting a new one");
depositToken.safeApprove(address(connext), _amountIn);
