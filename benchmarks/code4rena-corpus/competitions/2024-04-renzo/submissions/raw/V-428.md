# Vulnerability details

## Description
The `deployXERC20` function in the `XERC20Factory` contract lacks access control, allowing anyone to deploy new `XERC20` tokens without any restrictions. This function should ideally be restricted to authorized entities to prevent potential abuse and security vulnerabilities.
## Impact
It can cause several type of issues: 
- Any user can deploy new XERC20 tokens using this function, which can lead to a rapid increase in high number of unauthorized tokens on the platform.
- Malicious actors could deploy malicious unathorized or fraudulent. Unauthorized tokens could manipulate protocol, perform rug pulls, or engage in other economic attacks, resulting in financial losses for users. Which will ultimately damage the reputation of the platform and undermine trust among users.
- Attacker could deploy a large number of tokens, flooding the platform with unnecessary or harmful tokens, leading to DOS attacks on the platform.
## Proof of Concept
See the following code below:
```
 function deployXERC20(
        string memory _name,
        string memory _symbol,
        uint256[] memory _minterLimits,
        uint256[] memory _burnerLimits,
        address[] memory _bridges,
        address _proxyAdmin
    ) external returns (address _xerc20) {
        _xerc20 = _deployXERC20(
            _name,
            _symbol,
            _minterLimits,
            _burnerLimits,
            _bridges,
            _proxyAdmin
        );

        emit XERC20Deployed(_xerc20);
    }
```

## Recommended Mitigation Steps
Implement access control mechanisms to restrict the `deployXERC20` function to authorized entities only. This can be achieved by using modifiers with specific role to ensure that only designated accounts or contracts can deploy new `XERC20` tokens. Also limit number of token deployments per approved address. 

Additionally, consider implementing a governance mechanism to manage token deployment approvals and ensure compliance with regulatory requirements.
