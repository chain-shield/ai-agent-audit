# Vulnerability details

## Impact
The `XERC20Lockbox:_withdraw` allows users to withdraw ERC20 tokens from the lockbox. But it does not verify the `_amount` parameter, allowing users to withdraw any amount without validation. This poses a security risk as users could potentially withdraw more tokens than they deserve or manipulate the contract's state.

This function is  called from 2 external functions `withdraw` & `withdrawTo`. There isn't any validation on them too. Also no access control implemented anywhere. Lack of verification for the withdrawal amount enables users to withdraw arbitrary amounts, potentially exceeding their entitlement or the available balance in the lockbox.

Attckers could easily exploit this vulnerability to drain the lockbox's funds, leading to financial losses for legitimate users and disrupting the contract's operations.

## Proof of Concept
See the following code:

```
 /**
     * @notice Withdraw tokens from the lockbox
     *
     * @param _to The user to withdraw to
     * @param _amount The amount of tokens to withdraw
     */

    function _withdraw(address _to, uint256 _amount) internal {
        emit Withdraw(_to, _amount);

        XERC20.burn(msg.sender, _amount);

        if (IS_NATIVE) {
            (bool _success, ) = payable(_to).call{ value: _amount }("");
            if (!_success) revert IXERC20Lockbox_WithdrawFailed();
        } else {
            ERC20.safeTransfer(_to, _amount);
        }
    }
```

## Recommended Mitigation Steps
First verify if the user calling this function has amount to withdraw or not, then also check if the amount user requested is within the user's claimable range or not. Also implement some access control if needed.
