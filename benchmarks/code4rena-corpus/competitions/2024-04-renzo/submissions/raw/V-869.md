# Vulnerability details

## Impact
The receive function is triggered every time there is an eth transfer and we see in this receive function below, the `_forwardETH` is called both in the receive function and `forwardRewards`. The function `forwardRewards` possess the modifier check, which will be easily bypassed by transferring 1wei to the contract.

The impact of this is anyone can trigger the native ETH staking instead of only the whitelisted address with just 1 wei.

## Proof of Concept
The same implementation for both receive and forwardEth is done but access control is different

```solidity
receive() external payable nonReentrant {
        _forwardETH();
    }
```
and

```solidity
function forwardRewards() external nonReentrant onlyNativeEthRestakeAdmin {
        _forwardETH();
    }
```


## Tools Used

Manual Review

## Recommended Mitigation Steps
Add an internal function say `_onlyRestakeAdmins` that reverts if array or mappings of whitelisted addresses do not include the msg.sender.
