# Vulnerability details

The `ezETH` token is supposed to be non-transferrable in early stages of the protocol, but [WithdrawQueue::withdraw()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L214) tries to transfer `ezETH` from the user to the `WithdrawQueue` contract:
```solidity
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        ...SNIP...
        IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);
        ...SNIP...
    }
```

this will always revert when `ezETH` is non-transferrable.

## Impact

Users can't redeem their `ezETH` for tokens/ETH when `ezETH` transfers are not enabled. This is not supposed to be the case:
> When the protocol launches, it is intended to not have ezETH be transferrable. A user will deposit and get ezETH minted to their account, but they will not be able to transfer it out of their account until the protocol is ready to allow it. If the withdrawal flow is enabled, they can still withdraw from the protocol (token can be minted and burned by RestakeManager, even if transfers are restricted).

## Recommended Mitigation Steps

Change the [EzEthToken::_beforeTokenTransfer()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/token/EzEthToken.sol#L56) function to always allow the `WithdrawQueue` contract to transfer `ezETH`:

```solidity
...SNIP
if (from != address(0) && to != address(0) && msg.sender != withdrawQueue) {
    revert ContractPaused();
}
...SNIP
```
