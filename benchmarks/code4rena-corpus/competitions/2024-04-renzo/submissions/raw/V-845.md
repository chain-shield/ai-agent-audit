# Vulnerability details

## Description
`collateralTokens` track the tokens that can be used as collateral for Renzo protocol. If this array grows large enough, the `getCollateralTokenIndex(IERC20)` function can consume a lot of gas and potentially revert the transaction due to block gas limit. As a consequence multiple functions that depend on this function can suffer from DOS.

## Impact
DOS of 
* `RestakeManager.setTokenTvlLimit(IERC20,uint256)`
* `RestakeManager.deposit(IERC20,uint256,uint256)`

## POC
```solidity
    function getCollateralTokenIndex(IERC20 _collateralToken) public view returns (uint256) {
        // Find the token index
        uint256 tokenLength = collateralTokens.length;
        for (uint256 i = 0; i < tokenLength; ) {
            if (collateralTokens[i] == _collateralToken) { // @audit If token ID is at the back of the array and the array is enough large this function can revert due to block gas limit
                return i;
            }

            unchecked {
                ++i;
            }
        }

        revert NotFound();
    }
```

## Recommended mitigation
Opt for a better data struct like [Enumerable set from OZ](https://docs.openzeppelin.com/contracts/3.x/api/utils#EnumerableSet) to track collateral tokens
