# Vulnerability details

## Impact
The protocol assumes that the oracle decimals are 18 but that is not always the case. The `RestakeManager::calculateTVLs` function aggregates token values returned from an oracle in oracle decimals and native ETH values in 18 decimals without normalizing their decimal places. This can result in a TVL that is  mathematically incorrect. Such discrepancies can lead to severe issues including:

- Incorrect valuation of deposits, leading to errors in minting of protocol tokens.
- Erroneous withdrawal calculations, potentially allowing users to withdraw more/less value than entitled.
- Miscalculated reward distributions.


## Proof of Concept
The `RestakeManager::calculateTVLs` function integrates TVL calculations from multiple sources with differing decimal precisions. First it calls the `RenzoOracle::lookupTokenValue`, which always return price in oracle decimals, to calculate the return values :

```js
    function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
...

        return (uint256(price) * _balance) / SCALE_FACTOR;//@note supposedly balance is always in 10**18 decimals this should always return in oracle decimals
    }
```

```js
...
// Renzo Oracle returns values in oracle decimals 
operatorValues[j] = renzoOracle.lookupTokenValue(
    collateralTokens[j], operatorBalance
);
operatorTVL += operatorValues[j]; // Adding token values in oracle decimals
```

Then adds eth value using `getStakedETHBalance` which will always be in 18 decimals (since `stakedButNotVerifiedEth += msg.value;` represents the eth value):

```js
...

// Code segment showing mixed decimal calculations
uint256 operatorEthBalance = operatorDelegators[i].getStakedETHBalance();
operatorValues[operatorValues.length - 1] = operatorEthBalance;
operatorTVL += operatorEthBalance;  // Adding ETH value in 18 decimals directly

```

In cases where oracle decimals is different from 18 it can lead to a wrong total TVL.

## Tools Used

Manual review

## Recommended Mitigation Steps

Consider normalizing the decimal values in the function `RenzoOracle::lookupTokenValue` using the `decimals` function of the `AggregatorV3Interface`.
