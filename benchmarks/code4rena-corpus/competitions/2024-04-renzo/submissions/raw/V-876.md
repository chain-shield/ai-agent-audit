# Vulnerability details

## Impact
The calculated **TVL** would be incorrect.
This incorrect calculation would have spillover effect in following places.

Below is the called places and how the TVL is used.

RestakeManager - [deposit](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L499-L504) -- Determine which operator delegator to use. Also Calculate how much ezETH to mint.

RestakeManager - [depositETH](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L592-L595) - Enforce TVL limit if set and Calculate how much ezETH to mint.

BalancerRateProvider- [getRate](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RateProvider/BalancerRateProvider.sol#L29-L32) - to calculate the current rate of ezETH in ETH.

WithdrawQue - [withdraw](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L216-L218) - Calculate amount to Redeem in ETH

Since the TVL value is incorrect, this would be used in above places which again would lead to invalid result.

## Proof of Concept

Lets see, how the function is [calculateTVLs](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L274-L278) calculating the TVL.

-- iterates through operator delegators.
For each delegator, it calculates TVL for each token they hold:
-- gets the balance of each token.
-- uses an Oracle contract (renzoOracle) to fetch the token's value and calculates the TVL for the token.
-- accumulates the TVL for all tokens held by the delegator.
-- calculates the TVL for native ETH held by each delegator and accumulates it.
-- accumulates the total TVL for the protocol.
-- calculates the TVL of native ETH held in the deposit queue and adds it to the total TVL.
-- calculates the TVL of native ETH held in the withdrawal queue and adds it to the total TVL.

and the bug is in below part of the codes.

```solidity
if (!withdrawQueueTokenBalanceRecorded) {
    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
        collateralTokens[i], ------>> @@ audit find .
        collateralTokens[j].balanceOf(withdrawQueue)
    );
}
```
In this part of the code, `collateralTokens[i]` is used instead of `collateralTokens[j]` when looking up the token value. This could lead to incorrect token values being fetched, as i is the iterator for operator delegators, not tokens.
