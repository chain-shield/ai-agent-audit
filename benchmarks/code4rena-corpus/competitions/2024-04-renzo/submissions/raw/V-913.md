# Vulnerability details

## Impact
any one can mint to any address or burn from any address with no authorization leading to 
- Devaluation of xezETH: Unlimited minting of xezETH without corresponding deposits of ETH or other assets would inflate the supply of xezETH, potentially leading to its devaluation. This is because the value of xezETH is supposed to be backed by actual assets, and minting without backing would dilute the value of each xezETH in the case of minting edge case
- lose of victim funds in case of burn edge case

## Proof of Concept
for simplicity iam gonna explain 1 edge case which is minting and same root cause gonna be for burning,
in [`OptimismMintableXERC20` contract](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/xERC20/contracts/optimism/OptimismMintableXERC20.sol) it has a function called [`mint()`](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/xERC20/contracts/optimism/OptimismMintableXERC20.sol#L64-L66)
```solidity
    function mint(address _to, uint256 _amount) public override(XERC20, IOptimismMintableERC20) { 
        XERC20.mint(_to, _amount);
    }
```
that calls [`xERC20::mint()`](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/xERC20/contracts/XERC20.sol#L96-L98) (mint function in xezETH contract) here
```solidity
    function mint(address _user, uint256 _amount) public virtual {
        _mintWithCaller(msg.sender, _user, _amount);
    }
```
this function then calls `_mintWithCaller` with `msg.sender` as the `OptimismMintableXERC20` contract
this function as follows has the following
```solidity
    function _mintWithCaller(address _caller, address _user, uint256 _amount) internal {
        // Do not allow 0 value mints
        if (_amount == 0) revert IXERC20_INVALID_0_VALUE();

        if (_caller != lockbox) {
            uint256 _currentLimit = mintingCurrentLimitOf(_caller);
            if (_currentLimit < _amount) revert IXERC20_NotHighEnoughLimits();
            _useMinterLimits(_caller, _amount);
        }
        _mint(_user, _amount);
    }
```
if the the caller isn't `lockbox` then it checks the limits of the bridge minting capacity if its enough to mint it will call internal `_mint` function of the ERC20 implementation thus 
- giving the ability to any arbitrary caller to mint any amount he wants as long as it doesn't exceeds the limits of the bridge without anything for exchange or any access control
