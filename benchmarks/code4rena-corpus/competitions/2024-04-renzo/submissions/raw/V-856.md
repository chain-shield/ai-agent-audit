# Vulnerability details

## Summary

the function `WithdrawQueue:claim` is responsible for completing withdrawals and sending users their funds,the function uses transfer() to send ether to the user instead of call. There are a number of issues with using transfer(), as it can fail for a number of reasons , and if it fails it will make the user's funds locked.

## Vulnerability Detail

the function `claim` uses transfer instead of call:
```solidity=302
if (_withdrawRequest.collateralToken == IS_NATIVE) {
            payable(msg.sender).transfer(_withdrawRequest.amountToRedeem);
        }
```

which could fail for a number of reasons but most important of which are any changes or forks in ethereum that result in higher gas fees than transfer provides will make the function revert.

the revert will basically lock the user's eth in the contract unable to be withdrawn because calls to it would revert in the transfer call.

## Tool used

Manual Review

## Recommendation

use call instead of transfer in `claim`:

```solidity=302
if (_withdrawRequest.collateralToken == IS_NATIVE) {
    (bool success, ) = payable(msg.sender).call{value : _withdrawRequest.amountToRedeem}("");
    require(success, "error");
        }
```
