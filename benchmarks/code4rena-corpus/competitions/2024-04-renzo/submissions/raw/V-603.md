# Vulnerability details

## Summarize
The _forwardETH function in the RewardHandler contract uses the low-level .call method to transfer ETH to the rewardDestination address. This method does not check the return value of the .call, which can lead to a subtle vulnerability. If the rewardDestination contract has a fallback function that reverts, the transaction will still succeed, and the ETH will be lost. This is because the .call method returns a boolean indicating success or failure, but the contract does not check this return value.

## Impact
The impact of this vulnerability is that it allows for a loss of funds without any immediate indication of failure. This could lead to significant financial loss if the rewardDestination contract's fallback function reverts for any reason. The vulnerability is subtle because it does not cause an immediate failure of the transaction but rather a silent loss of funds.

## Proof of Concept
To illustrate this vulnerability, consider the following scenario:

The RewardHandler contract receives ETH.
The _forwardETH function is called to forward the ETH to the rewardDestination.
The rewardDestination contract's fallback function reverts for any reason (e.g., due to a require statement not being met).
The .call method in the _forwardETH function does not check the return value, so the transaction is considered successful, and the ETH is lost.

## Recommended Mitigation Steps
Check Return Values:
Modify the _forwardETH function to check the return value of the .call method. If the call fails, revert the transaction to prevent the loss of funds.
Use Safe Transfer Functions: 
Consider using Solidity's transfer or send functions for value transfers, as they have a limited gas stipend and will revert the transaction if the call fails.
Audit External Contracts: 
Ensure that the rewardDestination contract is secure and does not have fallback functions that can revert unexpectedly.
