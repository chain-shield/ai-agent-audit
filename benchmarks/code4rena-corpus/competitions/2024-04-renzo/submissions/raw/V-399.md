# Vulnerability details

## Impact
`RestakeManager::depositETH()` allows for the passing of a `_referralId` that is meant to provide the referrer 10% of points earned by the new user. However currently `RestakeManager::depositETH()` does not utilise or store `_referralId` anywhere, and only utilises it to emit a `Deposit` event.

This deviates from the intended behaviour outlined in the [Renzo docs](https://docs.renzoprotocol.com/docs/product/renzo-ezpoints), and leads to a loss of points to referrers.

## Proof of Concept
[RestakeManager::depositETH()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L592-L616)
```solidity
    function depositETH(uint256 _referralId) public payable nonReentrant notPaused {
        // Get the total TVL
        (, , uint256 totalTVL) = calculateTVLs();

        // Enforce TVL limit if set
        if (maxDepositTVL != 0 && totalTVL + msg.value > maxDepositTVL) {
            revert MaxTVLReached();
        }

        // Deposit the remaining ETH into the DepositQueue
        depositQueue.depositETHFromProtocol{ value: msg.value }();

        // Calculate how much ezETH to mint
        uint256 ezETHToMint = renzoOracle.calculateMintAmount(
            totalTVL,
            msg.value,
            ezETH.totalSupply()
        );

        // Mint the ezETH
        ezETH.mint(msg.sender, ezETHToMint);

        // Emit the deposit event
        emit Deposit(msg.sender, IERC20(address(0x0)), msg.value, ezETHToMint, _referralId);
    }
```
`_referralId` is passed as a parameter, however it is not utilised within the function to grant any rewards to the referrer.It is only utilised to emit a `Deposit` event.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Implement the referral system to provide the outlined 10% of earned points that referrers are entitled to. Or update the docs and code comments to state that referrals are not yet implemented on-chain.
