# Vulnerability details

## Impact
If ezETH transfer is paused, funds cannot be withdrawn from the protocol.

## Proof of Concept
The `WithdrawQueue.sol#withdraw()` function used to creates a withdraw request for user.
```solidity
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        // check for 0 values
        if (_amount == 0 || _assetOut == address(0)) revert InvalidZeroInput();

        // check if provided assetOut is supported
        if (withdrawalBufferTarget[_assetOut] == 0) revert UnsupportedWithdrawAsset();

        // transfer ezETH tokens to this address
214:    IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);

        SNIP...
    }
```
As you can see in #L214, the ezETH token to be burned is sent to `WithdrawQueue`.
@openzeppelin is implemented so that the _beforeTokenTransfer() function is called first when transmitting an ERC20 token (i.e. mint, burn, transfer).
The `EzEthToken.sol#_beforeTokenTransfer()` function is as follows.
```solidity
    function _beforeTokenTransfer(
        address from,
        address to,
        uint256 amount
    ) internal virtual override {
        super._beforeTokenTransfer(from, to, amount);

        // If not paused return success
        if (!paused) {
            return;
        }

        // If paused, only minting and burning should be allowed
69:     if (from != address(0) && to != address(0)) {
70:         revert ContractPaused();
71:     }
    }
```
As you can see, when the ezETH token is paused, only minting and burning is possible.
As a result, `safeTransferFrom()` function is reverted in #L214.
However, in C4's Renzo ReadME, it is mentioned that even if ezETH transfer is restricted, withdrawals can be made from the protocol if the withdrawal flow is activated.

Code4Rena ReadME:
>When the protocol launches, it is intended to not have ezETH be transferrable. A user will deposit and get ezETH minted to their account, but they will not be able to transfer it out of their account until the protocol is ready to allow it. If the withdrawal flow is enabled, they can still withdraw from the protocol (token can be minted and burned by RestakeManager, even if transfers are restricted).

In other words, the characteristics of the protocol are destroyed.

## Recommended Mitigation Steps
Modify the `WithdrawQueue.sol#withdraw()` function as follows.
```solidity
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        SNIP...

        // transfer ezETH tokens to this address
---     IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);

+++     ezETH.burn(msg.sender, _amount);
+++     ezETH.mint(address(this), _amount);

        SNIP...
    }
```
