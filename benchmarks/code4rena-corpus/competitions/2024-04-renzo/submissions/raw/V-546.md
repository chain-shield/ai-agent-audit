# Vulnerability details

## Impact
The oracle uses MAX_TIME_WINDOW which is 24 hours + 60 seconds which is a longer timeframe. This 24+ hour check is just stale for financial transactions. During high volatility periods, the price will be stale which will lead to losses for the protocol or users.

## Proof of Concept
    `function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
        AggregatorV3Interface oracle = tokenOracleLookup[_token];
        if (address(oracle) == address(0x0)) revert OracleNotFound();


        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        if (price <= 0) revert InvalidOraclePrice();


        // Price is times 10**18 ensure value amount is scaled
        return (uint256(price) * _balance) / SCALE_FACTOR;
    }`
You want to give fresh data for price calculations and the 24+ hour check is too long which leads to staleness.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Change the oracle staleness window from 24hours + 60 seconds to a standard lower timeframe like 15 mins
