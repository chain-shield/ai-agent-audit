# Vulnerability details

## Impact
Protocol `totalTVL` accounting will be broken and and funds will be stuck in the Eigenpod.

## Proof of Concept
Eigenlayer allows an operator to remove a staker's delegation to himself via [`DelegationManager::undelegate(...)`](https://github.com/Layr-Labs/eigenlayer-contracts/blob/6de01c6c16d6df44af15f0b06809dc160eac0ebf/src/contracts/core/DelegationManager.sol#L211), this is not taken in consideration by the protocol and will create inconsistencies when tracking balances.

An operator can call `DelegationManager::undelegate()` by passing as input the address of the `OperatorDelegator` that delegated his stake to him. This function will:
- Instantly reduce the number of Eigenlayer strategies shares owned by the `OperatorDelegator` instance
- Queue a withdrawal of the undelegated funds with the withdrawer parameter set to the `OperatorDelegator` instance

The funds queued for withdrawal are stuck without a way to withdraw them because, in order withdrawn Renzo protocol will need to call the [`DelegationManager::completeQueuedWithdrawal()`](https://github.com/Layr-Labs/eigenlayer-contracts/blob/v0.2.1-goerli-m2/src/contracts/core/DelegationManager.sol#L305) function but the Renzo protocol does not implement this functionality. 

In summary, the tokens would be going to the `OperatorDelegator` contract but it has no functionality to access these funds. In case of ETH, the passed amount will be seen as reward and split accordingly.
As stated earlier, this would break the shares accounting as these shares are no longer available and are stuck without a means of withdrawal.
