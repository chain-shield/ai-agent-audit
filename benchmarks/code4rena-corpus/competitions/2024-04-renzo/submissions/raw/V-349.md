# Vulnerability details

## Impact
The deposit and _deposit functions in the xRenzoDeposit contract show discrepancies in the recorded and actual amounts of tokens handled. The issue arises because the `Deposit` event logs the original amount of tokens transferred (`_amountIn`) prior to the deduction of the bridge fee, meaning that the event logs do not accurately reflect the actual token amount that influences the minting of xezETH. As a result, users reviewing transaction logs are misled about the amount of tokens actually used for operations.


## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/L2/xRenzoDeposit.sol#L204C10-L271C1

The deposit function transfers tokens from the user's address to the contract using:
 
   depositToken.safeTransferFrom(msg.sender, address(this), _amountIn);

 This operation transfers _amountIn tokens from the user to the contract.

 Inside the _deposit` function, a bridge fee is deducted from `_amountIn`:
 
   uint256 bridgeFee = getBridgeFeeShare(_amountIn);
   _amountIn -= bridgeFee;
   bridgeFeeCollected += bridgeFee;

Here, the bridge fee is subtracted from _amountIn, which reduces the amount available for further processing.

The `Deposit` event logs the original transferred amount rather than the net amount after fee deduction:
 
   emit Deposit(msg.sender, _amountIn, xezETHAmount);

The event inaccurately logs the initial amount, not considering the fee deduction, thus not reflecting the true amount used for minting xezETH.

Users and auditors analyzing the transaction logs will see the original amount sent (_amountIn) as logged in the `Deposit` event, which does not match the actual net amount used after deducting the bridge fee. 

## Tools Used
Visual Studio Code
Manual Inspection

## Recommended Mitigation Steps
Modify the `Deposit` event to log the net amount of tokens after deducting the bridge fee. 

 emit Deposit(msg.sender, _amountIn - bridgeFee, xezETHAmount);
