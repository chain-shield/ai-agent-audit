# Vulnerability details

In the `RestakeManager` contract's `deposit` function, there is a mechanism to fill the withdraw buffer if it is below buffer target, and there is an edge case where deposit in `OperatorDelegator` contract will revert if `amount` is reduced to zero after filling the withdraw buffer.

## Impact
If the entire deposit amount equals the buffer to fill, the remaining amount to deposit becomes zero. This can cause the transaction to revert due to the `OperatorDelegator`'s `deposit` function does not handle a zero-value deposit, leading to a failed deposit transaction for the user.

## Proof of Concept
The issue occurs in the following code block within the `deposit` function of the `RestakeManager` contract:

```solidity
File: contracts/RestakeManager.sol

    // Check the withdraw buffer and fill if below buffer target

        address(_collateralToken)
    );
    if (bufferToFill > 0) {
        bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
        // update amount to send to the operator Delegator
@-->    _amount -= bufferToFill; // @audit if _amount == bufferToFill, then _amount become 0

        depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);

    // Call deposit on the operator delegator
@--> operatorDelegator.deposit(_collateralToken, _amount); // @audit This line will revert if _amount is 0
```

## Recommended Mitigation Steps
Implement a check before calling the `deposit` function on the `operatorDelegator` to ensure that `_amount` is greater than zero:

```solidity
if (_amount > 0) {
    operatorDelegator.deposit(_collateralToken, _amount);
}
```
