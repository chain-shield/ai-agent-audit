# Vulnerability details


## Proof of Concept
Protocol uses Connext's `xcall()` to send data to the receiver, this can be seen from [xRenzoDeposit#sweep()](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/L2/xRenzoDeposit.sol#L434-L442) and [xRenzoBridge#sendPrice()](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/L1/xRenzoBridge.sol#L264-L274), issue however is with the latter implementation and it's integration with the `relayerFee`.

Take a look at https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/L1/xRenzoBridge.sol#L264-L274

```solidity
    function sendPrice(
        CCIPDestinationParam[] calldata _destinationParam,
        ConnextDestinationParam[] calldata _connextDestinationParam
    ) external payable onlyPriceFeedSender nonReentrant {

        //(...snip)
        for (uint256 i = 0; i < _connextDestinationParam.length; ) {
            connext.xcall{ value: _connextDestinationParam[i].relayerFee }(
                _connextDestinationParam[i].destinationDomainId,
                _connextDestinationParam[i]._renzoReceiver,
                address(0),
                msg.sender,
                0,
                0,
                _callData
            );
        //(...snip)
        }

```

We can see that the `relayerFee` is being used, however it's wrongly being attached as if it's a native token.

Now going to the interface used to query Connext's functionality we can see that [two xcall functions exists](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/Connext/core/IConnext.sol#L14-L34) and the one that includes `relayerFee` actually expects it as an argument passed on to the function call, this can also be confirmed by going to the official documentation of Connext here: https://docs.connext.network/developers/reference/contracts/calls#xcall, we can see that the `relayerFee` is an optional parameter to only be considered for an overloaded `xcall` but if it's included then this value is to be taken from the `asset` and not the native token, i.e quoting them:

```markdown
 | _relayerFee | `uint256` |(Optional) This is available in an overloaded xcall. If provided, the relayer fee will be taken in `_asset` rather than the native asset. 
```

This then means that in the above instance where protocol attempts to query `xcall()` it doesn't do it as expected.

## Impact
Protocol's core functionality is flawed when considering it's integration with Connext, cause when the `PRICE_FEED_SENDER` is calling `Connext#xcall()` it instead passes in the `relayerFee` as is if it's a native value instead of passing it as an argument to the function, which then causes the context in Connext to not know that the `xcall` with the `relayerFee` integration is actually the one being queried breaking the integration.
## Recommended Mitigation Steps
Consider correctly querying  `Connext#xcall()` when  passing the `relayerFee`.
