# Vulnerability details

The function [RestakeManager::deposit()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L546-L556) checks if the `WithdrawQueue` has a buffer deficit, and sends tokens to it when necessary:

```solidity
if (bufferToFill > 0) {
    bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;
    // update amount to send to the operator Delegator
    _amount -= bufferToFill;

    // safe Approve for depositQueue
    _collateralToken.safeApprove(address(depositQueue), bufferToFill);

    // fill Withdraw Buffer via depositQueue
    depositQueue.fillERC20withdrawBuffer(address(_collateralToken), bufferToFill);
}
```

When the `WithdrawQueue` buffer deficit is bigger (or equal) to the amount of assets being deposited all of the deposit will be transferred to the `WithdrawQueue` and because there are no assets left, the variable `_amount` will be set to `0`.

After this the function tries to deposit `0` tokens in the `OperatorDelegator`:

```solidity
..SNIP..
// Approve the tokens to the operator delegator
_collateralToken.safeApprove(address(operatorDelegator), _amount);

// Call deposit on the operator delegator
operatorDelegator.deposit(_collateralToken, _amount);
..SNIP..
```

but the call to [OperatorDelegator::deposit()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L147) will revert when the amount that is being deposited is `0`:

```solidity
if (address(tokenStrategyMapping[token]) == address(0x0) || tokenAmount == 0)
    revert InvalidZeroInput();
```

## Impact

It's impossible to deposit token amounts that are smaller or equal to the current `WithdrawQueue` buffer deficit.

## Recommended Mitigation Steps

Don't perform the deposit to the operator delegator when the amount to be deposited is `0`:

```solidity
if(_amount > 0) {
    // Approve the tokens to the operator delegator
    _collateralToken.safeApprove(address(operatorDelegator), _amount);

    // Call deposit on the operator delegator
    operatorDelegator.deposit(_collateralToken, _amount);
}
``` 

[RestakeManager.sol#L558-L562](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L558-L562)

Keep in mind that deposits being `0` is not the only issue here, small amounts of deposit might also revert on Eigenlayer side if the [amount of shares minted from the deposit are `0`](https://github.com/Layr-Labs/eigenlayer-contracts/blob/mainnet/src/contracts/strategies/StrategyBase.sol#L118).
