# Vulnerability details

## **Vulnerability Details:**

The **OperatorDelegator** contract uses the **[_recordGas](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Delegation/OperatorDelegator.sol#L470)** function to record the amount of gas spent by an address on a specific function call. More specifically, the **_recordGas** function records the amount of gas spent in the **adminGasSpentInWei** mapping with the **msg.sender** address as the key.

```solidity
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
        adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```

To refund the gas, the **[_refundGas](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Delegation/OperatorDelegator.sol#L481)** function is utilized. Here, the function first checks if the amount to refund is available in the contract. If it is, the user is fully refunded; if not, they are refunded the amount available for now.

The problem is that in the **_refundGas** function, the **tx.origin** is used to retrieve a user's refund amount, whereas in the **_recordGas** function, the **msg.sender** is used.

```solidity
    function _refundGas() internal returns (uint256) {
        uint256 gasRefund = address(this).balance >= adminGasSpentInWei[tx.origin]
            ? adminGasSpentInWei[tx.origin]
            : address(this).balance;
        bool success = payable(tx.origin).send(gasRefund);
        if (!success) revert TransferFailed();

        // reset gas spent by admin
        adminGasSpentInWei[tx.origin] -= gasRefund;

        emit GasRefunded(tx.origin, gasRefund);
        return gasRefund;
    }
```

### Consider the following scenario:

- A multi-sig contract is used to call the relevant function to perform updates and gas spent is recorded accordingly.
    - **msg.sender** here will be the multi-sig contract.
- When the multi-sig contract interacts with the **_refundGas** function, the function checks **adminGasSpentInWei[tx.origin]** to see how much gas was used.
    - However, since **tx.origin** will be the user calling the multi-sig contract, this value will be empty and no gas will be refunded.

## **Impact:**

- Severity: Medium. The current implementation could lead to users not receiving gas refunds as expected, potentially causing losses for users.
- Likelihood: Medium. The likelihood will depend on whether a contract is used to make the call or not.

## **Tools Used:**

- Manual analysis

## **Recommendation:**

Ensure that the **_recordGas** and **_refundGas** functions use the same address retrieval method. Since the gas was recorded using **msg.sender**, the refund should also be based on **msg.sender** to ensure consistency.
