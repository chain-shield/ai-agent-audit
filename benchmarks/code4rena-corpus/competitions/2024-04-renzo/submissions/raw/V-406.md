# Vulnerability details

## Impact
In the WithdrawQueue.sol#claim function, there is incorrect logic that may prevent user from claiming their completed withdrawal.

## Proof of Concept
In the [claim](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L279) function, there is check as follows:
```solidity
    if (withdrawRequestIndex >= withdrawRequests[msg.sender].length)
    revert InvalidWithdrawIndex();
```
This validation has to be done by ">" instead of ">=".Otherwise The last user will not be able to claim even if enough time has passed.
Consider a scenario:
Let's say  cooldownPeriod=2 days,
There are 5 withdrawal requests waiting the cooldown period.After 2 days passed,No other withdrawal request is initiated and Bob(the owner of last withdrawal request) calls claim function with withdrawRequestIndex=5, assuming the other 4 persons that made withdrawal request have not claimed yet,Bob will not be able to claim even if enough time has passed. He won't be able to do that because the others haven't claimed yet and the arrays length still stays same,which potentially may cause Bob losing some profit based on how late he will be able to do the claim.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Use ">" instead of ">="
