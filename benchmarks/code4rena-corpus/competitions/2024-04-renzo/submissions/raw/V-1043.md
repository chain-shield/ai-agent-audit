# Vulnerability details

## Impact
The `RenzoOracleL2` contract relies on the Chainlink oracle for retrieving the price of ezETH. However, the current implementation of the `getMintRate` function does not include proper checks for the minimum and maximum acceptable price thresholds. This vulnerability could lead to the contract consuming stale or invalid prices in case the Chainlink oracle encounters issues or the underlying asset experiences extreme price fluctuations. Consequently, this could result in incorrect minting rates, potentially causing financial losses for users and disrupting the stability of the system.

## Issue Description
The `getMintRate` function in the `RenzoOracleL2` contract retrieves the price from the Chainlink oracle using `oracle.latestRoundData()`. While it checks if the price is less than 1 ether, it does not include checks for the minimum and maximum price thresholds provided by the Chainlink Aggregator. This lack of proper price validation leaves the contract vulnerable to consuming stale or invalid prices when the Chainlink oracle freezes or the price falls outside the acceptable range.

## Proof of Concept

```solidity
function getMintRate() public view returns (uint256, uint256) {
    (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
    if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();

    // scale the price to have 18 decimals
    uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
    if (_scaledPrice < 1 ether) revert InvalidOraclePrice();

    return (_scaledPrice, timestamp);
}
```

As shown in the code above, the function lacks checks for the minimum and maximum price thresholds. If the Chainlink oracle returns a price that is outside the acceptable range, the function will still return that price without any validation.

## Mitigation Code
The `getMintRate` function should be updated to include a circuit breaker mechanism that checks the price against the `minAnswer` and `maxAnswer` values provided by the Chainlink Aggregator. Here's the updated code:

```solidity
function getMintRate() public view returns (uint256, uint256) {
    (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
    if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();

    // scale the price to have 18 decimals
    uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
    
    // Retrieve minAnswer and maxAnswer from the Chainlink Aggregator
    (, , , , int192 minAnswer, int192 maxAnswer) = oracle.latestRoundData();
    
    // Check if the price is within the acceptable range
    if (_scaledPrice < uint256(minAnswer)) revert PriceBelowMinimumThreshold();
    if (_scaledPrice > uint256(maxAnswer)) revert PriceAboveMaximumThreshold();

    return (_scaledPrice, timestamp);
}
```
