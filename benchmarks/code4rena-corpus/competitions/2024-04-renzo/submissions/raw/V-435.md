# Vulnerability details

## Impact

The sweepERC20 function will not run properly.

## Proof of Concept

If `feeBasisPoints` is set to 10000, then sweepERC20 will not run properly because `restakeManager.depositTokenRewardsFromProtocol` calls `operatorDelegator.deposit`, which does not accept a `tokenAmount` parameter with a value of 0, causing the entire transaction to revert.

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Deposits/DepositQueue.sol#L252-L277


Although administrators can set feeBasisPoints to a value other than 10000 to avoid this situation, a feeBasisPoints value of 10000 is acceptable. However, within the acceptable range, it affects the normal functioning of the contract. The relevant code is as follows:

https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Deposits/DepositQueue.sol#L92-L109

Due to incorrect settings, important functions of the contract cannot operate normally, so the vulnerability level is: medium

## Tools Used

Manual Review

## Recommended Mitigation Steps

Disable feeBasisPoints set to 10000
