# Vulnerability details

## Impact
xERC20 wrapper contains entity "bridge" that can freemint wrapper xERC20 tokens using admin-set limit. This entity can then use Lockbox contact to redeem those freeminted tokens for "real" tokens. 

Entity "bridge" is not contained in list of "trusted" entities in audit specification. There were "rugpull" incidents by bridges before anyway. 

"bridge" can use this limit to pull funds out of xERC20 wrapper instantly or accumulate the position sequentially as limit replenishes, and then cashout. 

Freemint/burn by bridges can also lead to inability of user to withdraw funds to due undercollaterization in the wrapper protocol even without foul play. 


## Proof of Concept
"bridge" with set limit uses mint functionality to mint additional tokens within this limit. 
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20.sol#L96

"bridge" then uses "burn" in `Lockbox` contract, withdrawing "real tokens" in exchange of freeminted ones
