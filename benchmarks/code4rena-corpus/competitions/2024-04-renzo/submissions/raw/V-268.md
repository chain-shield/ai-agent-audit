# Vulnerability details

The`sweep`()  is called by a `sweeper` to move the collaterals (`nextWETH `) from L2 to L1 through the connext bridge. The `sweeper` earns the `bridgeFeeShare` for sweeping the collateral to L1. When a user deposits the` bridgeFee` is calculated based on the amount the user deposits  if the `amountIn ` is less than the `sweepBatchSize`( 32ETH or more) , `amountIn` is used to calculate the `bridgeFee` of the `amountIn` is greater or equal to `sweepBatchSize` the `sweepBatchSize` is used to calculate the the `bridgeFee`.
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts%2FBridge%2FL2%2FxRenzoDeposit.sol#L277
```solidity
function getBridgeFeeShare(uint256 _amountIn) public view returns (uint256) {
        // deduct bridge Fee share
        if (_amountIn < sweepBatchSize) {
            return (_amountIn * bridgeFeeShare) / FEE_BASIS;
        } else {
            return (sweepBatchSize * bridgeFeeShare) / FEE_BASIS;
        }
    }
```
The issue here is that the `sweepBatchSize` is meant to be a threshold for the sweeper to call `sweep` from the above logic a user can deposit any amount and it gets traded and registered in the contract as `nextWETH`.  the `sweep` function however can be called at anytime with any deposit amount as long as the contract balance isn't zero.
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts%2FBridge%2FL2%2FxRenzoDeposit.sol#L414-L426
```solidity
function sweep() public payable nonReentrant {
        // Verify the caller is whitelisted
        if (!allowedBridgeSweepers[msg.sender]) {
            revert UnauthorizedBridgeSweeper();
        }

        // Get the balance of nextWETH in the contract
        uint256 balance = collateralToken.balanceOf(address(this));

        // If there is no balance, return
        if (balance == 0) {
            revert InvalidZeroOutput();
        }
```

This allows for random `sweep` calls that can lead to network congestion and low latency 

## Impact
Allowing `sweepers` call `sweep` on any amount of collateral left in the contract at anytime will congest the network slowing down the protocol effectively because `sweepers` are mainly bots that monitor the contract balance.
