# Vulnerability details

If any of the validators run by the Renzo protocol are slashed, or if AVS operators delegated to are slashed, the slashing losses should be borne by all ezETH token holders. However, it takes time for the slashing losses to reflect in the TVL, as validator slashes need to be proven in Eigen Pod first using a beacon chain state root. During this time, users can front-run the TVL changes and withdraw their funds from Renzo to avoid losses.

To address this issue, a withdrawal delay was introduced. However, the `amountToRedeem` is currently calculated during the withdrawal initiation itself instead of calculating it in the claim function. So users can still avoid losses by front-running TVL updates.

## Proof of Concept

1. Current TVL of the protocol is 100 ETH and there are 100 ezETH in supply.
2. So current exchange rate is 1 ETH/ezETH.
3. Now one of the validator gets slashed by 20 ETH.
4. So current TVL is 8O ETH and exchange rate is 0.8 ETH/ezETH.
5. But the current TVL is still reported to be 100 ETH as it takes time for EigenPodManager to update the podShares of OperatorDelegator as it only reduces podShares once someone proves to the EigenPod that the validator is slashed on beacon chain using beacon state root.
6. So the users can exit the protocol at a higher exchange rate than intended exchange rate.

This creates a race condition, where users capable of exiting earlier can do so without incurring losses.

## Impact
Users can avoid validator and AVS slashing losses
