# Vulnerability details

## Impact

The contract DepositQueue.sol lacks proper input sanitization in the function `stakeEthFromQueueMulti`, where arrays of input values are used. The contract trusts the caller to provide appropriate inputs, which can lead to unintended behavior if incorrect data is supplied.

In the function `stakeEthFromQueueMulti`, the contract processes multiple calls to `stakeEthInOperatorDelegator` by iterating through the arrays of `operatorDelegators`, `pubkeys`, `signatures`, and `depositDataRoots` and passing each index's values to the stake function. However, it contains no validation to confirm whether the supplied data is appropriate, leading to potential risks if the data is incorrect or malicious.


## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L211-L246


'''solidity
function stakeEthFromQueueMulti( IOperatorDelegator[] calldata operatorDelegators, bytes[] calldata pubkeys, bytes[] calldata signatures, bytes32[] calldata depositDataRoots ) external onlyNativeEthRestakeAdmin nonReentrant {
  // Verify all arrays are the same length
  if ( operatorDelegators.length != pubkeys.length || operatorDelegators.length != signatures.length || operatorDelegators.length != depositDataRoots.length )
    revert MismatchedArrayLengths();
  // Iterate through the arrays and stake each one
  uint256 arrayLength = operatorDelegators.length;
  for (uint256 i = 0; i < arrayLength; ) {
    // Send the ETH and the params through to the restake manager
    restakeManager.stakeEthInOperatorDelegator{ value: 32 ether }(
      operatorDelegators[i],
      pubkeys[i],
      signatures[i],
      depositDataRoots[i]
    );
    emit ETHStakedFromQueue(
      operatorDelegators[i],
      pubkeys[i],
      32 ether,
      address(this).balance
    );   
    unchecked {
      ++i;
    }
  }
} 
'''
For the above code snippet, there's no validation of the input parameters which can lead to potential risk.

## Recommended Mitigation Steps

The contract should validate the supplied `operatorDelegator`, `pubkeys`, `signatures`, and `depositDataRoots` arrays before processing them in each stake function call. Each piece of stake data should be individually validated using checks as appropriate to the type of data (e.g., ensuring the `operatorDelegator` address is a valid address, the `pubkeys` and `signatures` are of appropriate lengths, etc.). This can help protect the contract from incorrect or malicious stake data.
