# Vulnerability details

## Bug description

Renzo’s [C4 details page](https://code4rena.com/audits/2024-04-renzo#top) has an “**ezETH Transfer Restrictions**” section where it is stated that “*When the protocol launches, it is intended to not have ezETH be transferrable. … If the withdrawal flow is enabled, they can still withdraw from the protocol*”.

The Renzo team assumes that having ezETH not being transferrable will still allow withdrawals from the protocol to take place. However, this is not possible.

Checking ezETH’s code, we can see that if it is paused, only minting and burning will be allowed. This logic is performed inside `_beforeTokenTransfer`, which is a function that will be triggered in every ezETH token transfer:

```solidity
File: EzEthToken.sol

function _beforeTokenTransfer(
        address from,
        address to,
        uint256 amount
    ) internal virtual override {
        super._beforeTokenTransfer(from, to, amount);

        // If not paused return success
        if (!paused) {
            return;
        }

        // If paused, only minting and burning should be allowed
        if (from != address(0) && to != address(0)) {         <----
            revert ContractPaused();
        }
    }
```

The problem is that the `withdraw` function inside the `WithdrawalQueue` contract will try to transfer the user’s `ezETH` tokens so that the withdrawal can be queued:

```solidity
File: WithdrawQueue.sol

function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        ...

        // transfer ezETH tokens to this address
        IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount); 

        ...

}
```

If `ezETH` token is paused (which is the intended behavior on deployment as per Renzo team’s details for the contest), then withdrawals will never work and the transaction will always revert with `ContractPaused()` reason.

## Impact

High. A core functionality, withdrawing assets from the protocol, will never work, making user’s funds remain locked in the contract until pausing is disabled in `ezETH`.

## Recommended Mitigation

Allow the withdraw queue to perform transfers of ezETH even if the token is paused:

```diff
File: EzEthToken.sol

contract EzEthToken is Initializable, ERC20Upgradeable, IEzEthToken, EzEthTokenStorageV1 {

+ address public withdrawQueue;

...

function _beforeTokenTransfer(
        address from,
        address to,
        uint256 amount
    ) internal virtual override {
        super._beforeTokenTransfer(from, to, amount);

        // If not paused return success
        if (!paused) {
            return;
        }

        // If paused, only minting and burning should be allowed
-        if (from != address(0) && to != address(0)) {
+        if (from != address(0) && to != address(0) && msg.sender != withdrawQueue) {
            revert ContractPaused();
        }
    }
    
    
+ function setWithdrawQueue(address _withdrawQueue) external onnlyTokenAdmin {
+ 
+	 withdrawQueue = _withdrawQueue;
+
+ }
```
