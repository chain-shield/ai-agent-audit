# Vulnerability details

## Impact
The updatePrice function in the xRenzoDeposit contract plays a critical role in determining the price of `ezETH`, which subsequently influences the minting rate of the `xezETH` tokens. The function currently checks for price deviations greater than 10% compared to the last updated price. While this check intends to safeguard against drastic fluctuations and potential manipulations, it might not work in a highly volatile market or against sophisticated manipulation tactics. 
Sophisticated attackers might exploit this threshold by structuring price manipulations in increments just below 10%, gradually but consistently pushing the price to an erroneous value. Over time, these small, "acceptable" changes could accumulate, significantly deviating from the true market price without ever triggering the safeguard.

Here's a breakdown of the specific components within the code that relate to the vulnerability:


   function updatePrice(uint256 _price, uint256 _timestamp) external override {
       if (msg.sender != receiver) revert InvalidSender(receiver, msg.sender);
       _updatePrice(_price, _timestamp);
   }


   function _updatePrice(uint256 _price, uint256 _timestamp) internal {
       if (_price == 0) {
           revert InvalidZeroInput();
       }

       // Check for price divergence - more than 10%
       if ((_price > lastPrice && (_price - lastPrice) > (lastPrice / 10)) ||
           (_price < lastPrice && (lastPrice - _price) > (lastPrice / 10))) {
           revert InvalidOraclePrice();
       }

       if (_timestamp <= lastPriceTimestamp) {
           revert InvalidTimestamp(_timestamp);
       }

       if (_timestamp > block.timestamp) {
           revert InvalidTimestamp(_timestamp);
       }

       lastPrice = _price;
       lastPriceTimestamp = _timestamp;
       emit PriceUpdated(_price, _timestamp);
   }


The function checks if the new price `_price` is zero, which correctly prevents disruptive zero pricing. It then validates the price against a fixed 10% deviation threshold, which might not suit all market conditions.

## Recommended Mitigation Steps
Introduce a dynamic deviation threshold based on historical volatility data or a moving average of past price updates. This approach allows the contract to adjust its sensitivity based on market conditions.
