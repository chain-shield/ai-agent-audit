# Vulnerability details

## Impact
- Elements that fail to be added will not be present in the expected set.
- It could lead to unexpected behavior in code that assumes the element was added.

## Proof of Concept
Here's the EnumerableUpgradeable add function:

```
   /**
     * @dev Add a value to a set. O(1).
     *
     * Returns true if the value was added to the set, that is if it was not
     * already present.
     */
    function add(Bytes32Set storage set, bytes32 value) internal returns (bool) {
        return _add(set._inner, value);
    }


  /**
     * @dev Add a value to a set. O(1).
     *
     * Returns true if the value was added to the set, that is if it was not
     * already present.
     */
    function _add(Set storage set, bytes32 value) private returns (bool) {
        if (!_contains(set, value)) {
            set._values.push(value);
            // The value is stored at length-1, but we add 1 to all indexes
            // and use 0 as a sentinel value
            set._indexes[value] = set._values.length;
            return true;
        } else {
            return false;
        }
    }
```

The above shows that add function returns either true or false.

XERC20Factory.sol imported the EnumerableSetUpgradeable library. However, functions such as _deployLockbox and _deployXERC20, in XERC20Factory, use the add function from EnumerableUpgradeable without checking the return value. 

```
 EnumerableSetUpgradeable.add(_xerc20RegistryArray, _xerc20);

 EnumerableSetUpgradeable.add(_lockboxRegistryArray, _lockbox);

```

The two functions assume the add function returns true. What if it returns false? There's no check for this.

## Recommended Mitigation Steps
To mitigate this, it's important to use require statement to ensure the success or failure of this operation. For example:

require(EnumerableSetUpgradeable.add(_xerc20RegistryArray, _xerc20), "Already exist");

require(EnumerableSetUpgradeable.add(_lockboxRegistryArray, _lockbox), "Already exist");
