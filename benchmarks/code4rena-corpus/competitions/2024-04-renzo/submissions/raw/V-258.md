# Vulnerability details

## Impact
Both `OperatorDelegator.sol` and `DepositQueue.sol` refund admins for used gas when calling certain functions, however the implementation of the gas refund calculation differs between the two contracts.

`OperatorDelegator.sol` contains an additional parameter `baseGasAmountSpent` that increases the gas refund that will be received by the admins. Meaning that admins will not receive as big of a gas refund for calling function in `DepositQueue.sol` when comparing to `OperatorDelegator.sol`.

This firstly leads to less incentives for admins to perform their admin functions, and also causes admins to receive a smaller refund amount leading to a small loss of funds.

## Proof of Concept
[OperatorDelegator::_recordGas()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L470-L474)
```solidity
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
        adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```

[DepositQueue::_refundGas](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L283-L289)
```solidity
    function _refundGas(uint256 initialGas) internal {
        uint256 gasUsed = (initialGas - gasleft()) * tx.gasprice;
        uint256 gasRefund = address(this).balance >= gasUsed ? gasUsed : address(this).balance;
        (bool success, ) = payable(msg.sender).call{ value: gasRefund }("");
        if (!success) revert TransferFailed();
        emit GasRefunded(msg.sender, gasRefund);
    }
```
When comparing the two different gas refunds from both contracts, it can be seen that they are not the same. `OperatorDelegator` adds a `baseGasAmountSpent` before multiplying by `tx.gasprice` whilst `DepositQueue` misses the usage of `baseGasAmountSpent`.

It is not clear from the code comments what `baseGasAmountSpent` is being utilised for, and the project docs also do not mention this value. However the fact that gas calculations differ between the two contracts is clearly a design mistake and should be resolved, as it leads to admins receiving a smaller refund or the protocol over refunding funds if `baseGasAmountSpent` is not meant to be included.

## Recommended Mitigation Steps

Check the logic in both contracts and decide which model for gas refund calculations should be utilised, and ensure the same model is utilised across all contracts.
