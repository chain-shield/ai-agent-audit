# Vulnerability details

The operator can [undelegate](https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/core/DelegationManager.sol#L240-L254) in Eigenlayer to remove and queue withdrawals for all its staker's strategy shares.
```solidity
function undelegate(address staker) external onlyWhenNotPaused(PAUSED_ENTER_WITHDRAWAL_QUEUE) returns (bytes32[] memory withdrawalRoots) {
    // ... snip ...
    } else {
        withdrawalRoots = new bytes32[](strategies.length);
        for (uint256 i = 0; i < strategies.length; i++) {
            IStrategy[] memory singleStrategy = new IStrategy[](1);
            uint256[] memory singleShare = new uint256[](1);
            singleStrategy[0] = strategies[i];
            singleShare[0] = shares[i];

            withdrawalRoots[i] = _removeSharesAndQueueWithdrawal({
                staker: staker,
                operator: operator,
                withdrawer: staker,
                strategies: singleStrategy,
                shares: singleShare
            });
        }
    }

    return withdrawalRoots;
}
```

Note that the operator can be set with [`setDelegateAddress()`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L127) in the Operator Delegator.

When an operator undelegates, it zeroes out all of the Operator Delegator's shares in all its active strategies but does not update the `queuedShares`. In `queueWithdrawals()`, the [`queuedShares` is updated]( https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L232) with the withdrawal amount. This is important since this is how Renzo counts the total value of queued withdrawals when calculating the protocol TVL.

## Impact
The total [TVL is calculated](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L302-L304) as:
```
totalTVL = sum(operatorTVL) + DepositQueue ETH Balance + WithdrawQueue TVL
```

Undelegation can cause a sharp drop in the protocol TVL since an Operator's Eigenlayer strategy shares will become 0. Withdrawal amounts are directly correlated with TVL and mint amounts are inversely correlated with TVL. A sharp drop in TVL will cause the following:
- Mint amounts will be bloated while the withdrawals are queued.
- Withdrawal amounts will be greatly discounted while the withdrawals are queued.

Hence, users will be incentivized to mint as much as possible during this time. Any gains these minters make come at the expense of earlier depositors.

## Proof of Concept
Consider the following scenario:
1. A malicious or unwitting Operator undelegates in Eigenlayer with `DelegationManager.undelegate()` which causes a drop in TVL.
2. Once the [delayed withdrawal](https://github.com/Layr-Labs/eigenlayer-contracts/blob/15b679b08e7a3589ff83a5e84076ca4e0a00ec0b/src/contracts/pods/DelayedWithdrawalRouter.sol#L100-L105) can be claimed, a user can do the following:
  - Deposit tokens to mint as much ezETH as possible.
  - Claim the delayed withdrawal in the Delayed Withdrawal Router.
  - [Withdraw](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L206) and eventually [claim](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L279) using as much ezETH as possible.

## Tools Used
Foundry, Manual Review

## Recommended Mitigation Steps
Consider removing the ability to `setDelegateAddress()` and add a function in Operator Delegator that calls `DelegationManager.undelegate()` in Eigenlayer. This added function will account for any shares withdrawn by adding them to the `queuedShares[]` mapping.
