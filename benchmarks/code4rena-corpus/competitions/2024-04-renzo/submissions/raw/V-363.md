# Vulnerability details

## Impact
When there's a limit on the Total Value Locked (TVL) of a specific token, the protocol doesn't consider the balance of that token in the `WithdrawQueue`. This oversight allows deposits higher than the TVL limit of a token.

## Proof of Concept
During ERC20 token deposits, the protocol enforces both the total TVL limit and individual token TVL limit if they're set. However, while enforcing the total TVL limit, the protocol considers the ERC20 balance of the `WithdrawQueue`. But when enforcing the individual token TVL limit, it only considers the token TVL of operator delegators and ignores the ERC20 balance of the `WithdrawQueue`.

## Recommended Mitigation Steps
To resolve this issue, include the ERC20 token balance of the `WithdrawQueue` when enforcing the individual token TVL limit. This ensures that deposits cannot exceed the TVL limit of a token by considering the total token value in both the operator delegators and the `WithdrawQueue`.
Modify the deposit function to consider the ERC20 token balance of the `WithdrawQueue` when enforcing the individual token TVL limit:
```solidity
function deposit(
    IERC20 _collateralToken,
    uint256 _amount,
    uint256 _referralId
) public nonReentrant notPaused {
    //....

    // Enforce individual token TVL limit if set, 0 means the check is not enabled
    if (collateralTokenTvlLimits[_collateralToken] != 0) {
        // Track the current token's TVL
        uint256 currentTokenTVL = 0;

        // For each OD, add up the token TVLs
        uint256 odLength = operatorDelegatorTokenTVLs.length;
        for (uint256 i = 0; i < odLength; ) {
            currentTokenTVL += operatorDelegatorTokenTVLs[i][tokenIndex];
            unchecked {
                ++i;
            }
        }

        // Add the ERC20 token balance of the WithdrawQueue
        currentTokenTVL += renzoOracle.lookupTokenValue(
            _collateralToken,
            _collateralToken.balanceOf(withdrawQueue)
        );

        // Check if it is over the limit
        if (currentTokenTVL + collateralTokenValue > collateralTokenTvlLimits[_collateralToken])
            revert MaxTokenTVLReached();
    }

}
```
