# Vulnerability details

## Impact
Incomplete Gas Refund in DepositQueue as baseGasAmountSpent is not refunded to caller
## Proof of Concept
```solidity
    function _recordGas(uint256 initialGas) internal {
>>>        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
        adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```
The recordGas function above from the OperatorDelegator contract shows how gas spent is calculated it can be noted that baseGasAmountSpent was also used in the calculation however a look at the _refundGas(...) function from the DepositQueue contract shows that baseGasAmountSpent  was wrongly exempted as noted from the pointer below in gas Used calculation
```solidity
    function _refundGas(uint256 initialGas) internal {
>>>        uint256 gasUsed = (initialGas - gasleft()) * tx.gasprice;
        uint256 gasRefund = address(this).balance >= gasUsed ? gasUsed : address(this).balance;
        (bool success, ) = payable(msg.sender).call{ value: gasRefund }("");
        if (!success) revert TransferFailed();
        emit GasRefunded(msg.sender, gasRefund);
    }
```
## Tools Used
Manual Review
## Recommended Mitigation Steps
Protocol should put baseGasAmountSpent in consideration when refunding gas to caller
