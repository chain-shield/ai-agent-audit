# Vulnerability details

## Impact

The first deposit can block all future deposits by transferring any collateralToken to `WithdrawQueue.sol` and based on how much they transferred, it will become the minimum deposit amount for future users.

## Proof of Concept

When user deposits, it will calculate how much `ezETH` he will receive in `calculateMintAmount()`, based on `lockedTVL` and `ezETH.totalSupply()`.

**The steps to block all future deposits are as follows:**

1. The first depositor deposits **`1 wei`** collateral and in return he will receive **`1 ezETH`** (**1:1 ratio**, due to the first if statement - first depositor logic)
2. He then transfers whatever amount he wants to set as a minimum of the same collateral to the `WithdrawQueue` contract
3. When a next user tries to deposit with the same collateral token, but under `collateralToken.balanceOf(withdrawQueue)`, the mint amount will be **0** because it will be rounded down to 0, which causes the function to revert here - `if (mintAmount == 0) revert InvalidTokenAmount();`
4. All future deposits will only be available when depositing more than the locked tvl of this token.

Some math examples:

- Attacker deposits `1wei`
- Attacker transfers `10stETH`
- User tries to deposit `5stETH`

Calculations when a user tries to deposit:

- `_newValueAdded` is the deposited 5 stETH in ETH - at the time of writing this is `4997299282579770000 ≈ 4.99e18`
- `inflationPercentaage` = `(1e18 * 4997299282579770000) / ((10e18 + 1) + 4997299282579770000) = 333213279832617728 ≈ 0.33e18`
- `newEzETHSupply` = `(1 * 1e18) / (1e18 - 333213279832617728) = 1` **(no decimals)**
- `mintAmount` = `1 - 1 = 0`

and the function will revert. Only deposit above that `10stETH + 1 wei` will be available because then the `newEzETHSupply` will be 2 and the user will get 1 wei of `ezETH`.

```solidity
function calculateMintAmount(
    uint256 _currentValueInProtocol,
    uint256 _newValueAdded,
    uint256 _existingEzETHSupply
) external pure returns (uint256) {
    // For first mint, just return the new value added.
    // Checking both current value and existing supply to guard against gaming the initial mint
    if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
        return _newValueAdded; // value is priced in base units, so divide by scale factor
    }

    // Calculate the percentage of value after the deposit
    uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
        (_currentValueInProtocol + _newValueAdded);

    // Calculate the new supply
    uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
        (SCALE_FACTOR - inflationPercentaage);

    // Subtract the old supply from the new supply to get the amount to mint
    uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

    // Sanity check
    if (mintAmount == 0) revert InvalidTokenAmount();

    return mintAmount;
}
```
