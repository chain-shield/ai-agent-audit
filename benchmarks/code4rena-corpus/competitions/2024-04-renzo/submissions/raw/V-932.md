# Vulnerability details

## Impact
* Users can loose value if the price of the collateral goes down compared to what it was when they initiated their withdawal. They are in control though, so they can wait until the price goes up to claim, in which case the protocol looses value instead.
* Users can sandwich collateral oracle price updates when price goes down to mint free `ezETH` tokens without risks.

## Proof of Concept
```solidity
// ...

    Initializable,
    PausableUpgradeable,
    ReentrancyGuardUpgradeable,
    WithdrawQueueStorageV1

    // ...
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {

            _amount,
            ezETH.totalSupply(),
            totalTVL
        );

        // update amount in claim asset, if claim asset is not ETH
        if (_assetOut != IS_NATIVE) {

            amountToRedeem = renzoOracle.lookupTokenAmountFromValue( // <==== Audit
                IERC20(_assetOut),
                amountToRedeem
            );
        }

        // revert if amount to redeem is greater than withdrawBufferTarget
        if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();

        // increment the withdrawRequestNonce
        withdrawRequestNonce++;

        // add withdraw request for msg.sender
        withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem, // <==== Audit
                _amount,
                block.timestamp
            )
        );

        // add redeem amount to claimReserve of claim asset
        claimReserve[_assetOut] += amountToRedeem;

        // ...
    }

    function claim(uint256 withdrawRequestIndex) external nonReentrant {
        // ...
        // send selected redeem asset to user
        if (_withdrawRequest.collateralToken == IS_NATIVE) {
            payable(msg.sender).transfer(_withdrawRequest.amountToRedeem);
        } else {
            IERC20(_withdrawRequest.collateralToken).transfer(
                msg.sender,
                _withdrawRequest.amountToRedeem // <==== Audit
            );
        }
        // ...
    }
    // ...
}
```

### Root Cause
The redeem amount is calculated and locked in when initiating a withdrawal.

For non native withdrawals, the final redeem amount is based on the price of the requested collateral token at that time.

This means that if the price of is different at claim time, either the user or the protocol loose value.

It also means, that users can lock in a specific price allowing riskless oracle price updates sandwich attacks.

### Scenarios
#### Regular withdrawal
Assuming a starting price of 1 STETH / ETH :
* Bob deposits `1 ether` of STETH and gets back X amount of `ezETH`
* Bob initiates a withdrawal for X amount of `ezETH`
* The price is still the same, so the redeem amount will be locked in at `1 ether` of STETH
* A week goes by, so Bob can now claim his withdrawal. The price changed in the meantime but Bob is still getting `1 ether` of STETH even if :
  * Price is now 1.01 STETH / ETH : Protocol looses value as Bob should only get around `0.99 ether` of STETH
  * Price is now 0.99 STETH / ETH : Bob looses value as he should get around `1.01 ether` of STETH 

#### Oracle update sandwich
Assuming an incoming oracle update to decrease the price :

* Bob deposits X amount of `stETH` and gets back Y amount of `ezETH` before the update
* After the price update, Bob only needs to initiate a withdraw with Z amount of `ezETH` to get his initial X amount of `stETH` (after a week that is), leaving him with Y - Z amount of `ezETH`.

The amount of left over `ezETH` scales with Bob's available capital and how much the price decreases.

* `testLossWhenPriceChangesInWithdrawCooldownPeriod` tests the first scenario.

```solidity
    function testOraclePriceUpdateSandwich() public {
        WithdrawQueueStorageV1.TokenWithdrawBuffer[]
            memory withdrawalBufferTarget = new WithdrawQueueStorageV1.TokenWithdrawBuffer[](2);

        withdrawalBufferTarget[0] = WithdrawQueueStorageV1.TokenWithdrawBuffer(
```
