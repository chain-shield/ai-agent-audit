# Vulnerability details

## Vulnerability Detail
In `OperatorDelegator.completeQueuedWithdrawal()`, whenever there is a `bufferToFill` in the withdrawQueue, the following block of code is executed:
```solidity
// fill Withdraw Buffer via depositQueue
restakeManager.depositQueue().fillERC20withdrawBuffer( //@audit this will fail.. function allows onlyRestakeManager
    address(tokens[i]),
    bufferToFill
);
```

The issue is that `DepositQueue.fillERC20withdrawBuffer()` is a permissioned function that can only be called by the `RestakeManager` contract. This is evident here:
```solidity
function fillERC20withdrawBuffer(
        address _asset,
        uint256 _amount
    ) external nonReentrant onlyRestakeManager // <--- access limited to `RestakeManager`
```

## Impact
As a result, the `OperatorDelegator.completeQueuedWithdrawal()` function call will revert whenever it tries to fill the buffer in the `WithdrawalQueue`.

This is a major disruption to the protocol's functionality.
