# Vulnerability details

## Impact
The `bridgeTo` function of the `LockboxAdapterBlast.sol` contract performs token transfers and approvals without checking the return values of the `SafeERC20.safeTransferFrom` and `SafeERC20.safeApprove` functions. Also, the `bridgeTo` function calls the deposit function on the Lockbox contract interface without proper checks on the return value. 
This oversight can lead to incomplete transactions, failed interactions with other contracts, and internal state inconsistencies, resulting in potential loss of user funds and unexpected contract behavior.

## Proof of Concept
The vulnerability arises in the `bridgeTo` function of the `LockboxAdapterBlast.sol` contract. Below are the relevant lines of code:

```
 SafeERC20.safeTransferFrom(IERC20(_erc20), msg.sender, address(this), _amount);
 SafeERC20.safeApprove(IERC20(_erc20), lockbox, _amount);
 IXERC20Lockbox(lockbox).deposit(_amount);
 SafeERC20.safeApprove(IERC20(xerc20), blastStandardBridge, _amount);
```
In all cases, the return values of the `safeTransferFrom`,`safeApprove` and `deposit` functions are not checked for success. This can lead to loss of funds if the token transfer or approval fails

## Tools Used
 Manual code review
## Recommended Mitigation Steps
To mitigate this vulnerability, the following steps are recommended:

- Check Return Values: Ensure that return values of token transfer and approval functions are properly checked for success before proceeding with further actions.
- Implement Error Handling: Implement appropriate error handling mechanisms to revert the transaction or take corrective actions in case of failure.
