# Vulnerability details

The `removeCollateralToken()` function in `RestakeManager` contract allows for the removal of a collateral token from the protocol's accepted list without considering the token's existing deposits or its impact on the protocol's operations.

## Impact
Removing a collateral token that has existing deposits can lead to several issues:
- Users may be unable to withdraw their deposited tokens, leading to loss of access to their funds.
- The protocol's Total Value Locked (TVL) calculations may become inaccurate if they do not account for the removed token's existing balance.

## Proof of Concept
The issue arises in the `removeCollateralToken()` function, which is responsible for removing a token from the `collateralTokens` array:

```solidity
    function removeCollateralToken(
        IERC20 _collateralTokenToRemove
    ) external onlyRestakeManagerAdmin {
        // Remove it from the list
        uint256 tokenLength = collateralTokens.length;
        for (uint256 i = 0; i < tokenLength; ) {
            if (address(collateralTokens[i]) == address(_collateralTokenToRemove)) {
                collateralTokens[i] = collateralTokens[collateralTokens.length - 1];
                collateralTokens.pop();
                emit CollateralTokenRemoved(_collateralTokenToRemove);
                return;
            }
            unchecked {
                ++i;
            }
        }

        // If the item was not found, throw an error
        revert NotFound();
    }
}
```

## Recommended Mitigation Steps
Before removing a collateral token, the following steps should be taken:

1. Check for Active Deposits: Implement a check to ensure there are no active deposits for the token before allowing its removal.
2. Grace Period: Introduce a grace period for users to withdraw their funds before the token is officially removed.
