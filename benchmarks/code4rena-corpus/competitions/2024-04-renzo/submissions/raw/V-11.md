# Vulnerability details

## Impact
If the `approve()` function of an ERC20 token fails, the DepositQueue contract does not revert the transaction and does not indicate the failure in any way. This could lead to silent failures in the approval process, which could result in the restakeManager not receiving the expected token allowance. As a result, subsequent operations that rely on this allowance may fail unexpectedly, potentially causing loss of funds or other unintended consequences.

## Proof of Concept
The vulnerability can be found in the `sweepERC20()` function of the DepositQueue contract.
The `approve()` function is called on line 268, but its return value is not checked:
```solidity
token.approve(address(restakeManager), balance - feeAmount);
```
If the `approve()` function fails, the transaction will continue executing without any indication of the failure. This could lead to unexpected behavior in subsequent operations that rely on the token allowance.

## Tools Used

* Solidity compiler
* Manual code review

## Recommended Mitigation Steps
It is recommended to check the return value of the `approve()` function to ensure that the approval was successful. If the `approve()` function returns `false`, the transaction should be reverted to indicate the failure. The updated code could look like this:
```solidity
bool success = token.approve(address(restakeManager), balance - feeAmount);
require(success, "Approval failed");
```
This will ensure that any failures in the approval process are properly indicated and handled, preventing unexpected behavior and potential loss of funds.
