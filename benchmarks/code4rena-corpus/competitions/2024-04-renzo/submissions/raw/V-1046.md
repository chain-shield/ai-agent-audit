# Vulnerability details

## Impact
Any function that does not validate its inputs can represent a vulnerability in the smart contract system. 

In this case, the '_withdraw' function does not check whether the caller has enough balance of XERC20 tokens to burn. 

## Proof of Concept
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/xERC20/contracts/XERC20Lockbox.sol#L125-L135


```solidity
function _withdraw(address _to, uint256 _amount) internal {
    emit Withdraw(_to, _amount);
    XERC20.burn(msg.sender, _amount);
    if (IS_NATIVE) {
        (bool _success, ) = payable(_to).call{ value: _amount }("");
        if (!_success) revert IXERC20Lockbox_WithdrawFailed();
    } else {
        ERC20.safeTransfer(_to, _amount);
    }
}
```

## Recommended Mitigation Steps

You need to include an explicit check that the caller (msg.sender) has enough balance of XERC20 tokens to burn. This can be implemented by inserting a require statement checking the user's balance before the 'XERC20.burn()' function call. It could be something like this:

```solidity 
require(XERC20.balanceOf(msg.sender) >= _amount, "Insufficient balance");
XERC20.burn(msg.sender, _amount);
```

This check ensures that the burn operation is valid.
