# Vulnerability details

## Vulnerability Detail
Currently the Renzo protocol allows users to deposit one type of LST to mint ezETH, then redeem that ezETH for another LST

Since they calculate the value of an LST via a chainlink oracle that has a set deviation threshold this opens them up to a simple arbitrage opportunity described in the following steps

1. Identify an LST that has dropped in price but is still within the chainlink deviation threshold
2. deposit that LST and mint ezETH using the inflated oracle price
3. immediately redeem the ezETH for ETH or an LST that has increased in price but is within it's deviation threshold
4. The result will be a profit for the attacker, they can do this using a bot and simulating the Tx to ensure they only execute when profitable therefore they have made a profit with 0 risk.

## Impact
Attacker comes out with a profit, while taking 0 risk by extracting value from other protocol users

## Proof of Concept
see vulnerability detail

## Tools Used
Manual Review

## Recommended Mitigation Steps
Not easy to fix, setting a delay between deposit and withdrawals may work to reduce the occurrence of these attacks

Another mitigation would be to restrict users to withdraw the LST they deposited
