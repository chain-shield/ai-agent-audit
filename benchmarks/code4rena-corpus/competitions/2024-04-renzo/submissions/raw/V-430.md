# Vulnerability details

## Description
The `RoleManager` and `xRenzoBrigdge` contracts have a flaw related to role setting, where the roles are defined in the contract but are not initialized or assigned to any addresses during deployment or initialization. Also there is no explicit access controlled (i.e OnlyOwner) function to assign addresses to these roles later. This issue makes the role-based access control (RBAC) mechanism ineffective, as no accounts are granted the necessary roles to perform specific actions. 
## Impact
Without proper role assignments, all functions guarded by role-based access controls become inaccessible, leading to a protocol that is either entirely locked down or open to unauthorized access, leading to potential exploits or disruptions. 

If it is open to unauthorized access then attckers could exploit the lack of role assignments to gain access to sensitive functionalities, such as minting tokens, updating configurations, or pausing operations, without proper authorization. Ultimately causing financial loss for the protocol and users.

In scenarios where all functions are inaccessible due to the lack of role assignments, legitimate users would be denied access to essential protocol functionalities, leading to a DoS attack. Which will cause a loss of user trust, leading to a loss of confidence and adoption.


## Proof of Concept
See the follow code:

RoleManager.sol
```
  /// @dev initializer to call after deployment, can only be called once
    function initialize(address roleManagerAdmin) public initializer {
        if (address(roleManagerAdmin) == address(0x0)) revert InvalidZeroInput();

        __AccessControl_init();

        _grantRole(DEFAULT_ADMIN_ROLE, roleManagerAdmin);
    }
```

xRenzoBridge.sol
```

    function initialize(
        IERC20 _ezETH,
        IERC20 _xezETH,
        IRestakeManager _restakeManager,
        IERC20 _wETH,
        IXERC20Lockbox _xezETHLockbox,
        IConnext _connext,
        IRouterClient _linkRouterClient,
        IRateProvider _rateProvider,

        // Verify non-zero addresses on inputs
        if (
            address(_ezETH) == address(0) ||
            address(_xezETH) == address(0) ||
            address(_restakeManager) == address(0) ||
            address(_wETH) == address(0) ||
            address(_xezETHLockbox) == address(0) ||
            address(_connext) == address(0) ||
            address(_linkRouterClient) == address(0) ||
            address(_rateProvider) == address(0) ||
            address(_linkToken) == address(0) ||
            address(_roleManager) == address(0)
        ) {
            revert InvalidZeroInput();
        }

        // Verify all tokens have 18 decimals
        uint8 decimals = IERC20MetadataUpgradeable(address(_ezETH)).decimals();
        if (decimals != EXPECTED_DECIMALS) {
            revert InvalidTokenDecimals(EXPECTED_DECIMALS, decimals);
        }
        decimals = IERC20MetadataUpgradeable(address(_xezETH)).decimals();
        if (decimals != EXPECTED_DECIMALS) {
            revert InvalidTokenDecimals(EXPECTED_DECIMALS, decimals);
        }
        decimals = IERC20MetadataUpgradeable(address(_wETH)).decimals();
        if (decimals != EXPECTED_DECIMALS) {

        }

        if (decimals != EXPECTED_DECIMALS) {
            revert InvalidTokenDecimals(EXPECTED_DECIMALS, decimals);
        }

        // Save off inputs
        ezETH = _ezETH;
        xezETH = _xezETH;

        wETH = _wETH;
```

## Recommended Mitigation Steps
During deployment or initialization, ensure that roles are assigned to appropriate addresses based on the protocol's requirements. This can be achieved by calling functions such as grantRole to assign roles to designated administrators or other privileged accounts.
