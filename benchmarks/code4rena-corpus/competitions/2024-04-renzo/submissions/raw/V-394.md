# Vulnerability details

## Impact
`RestakeManager::chooseOperatorDelegatorForDeposit()` contains a `uint256[] memory tvls` parameter that is passed into the function, this parameter is then utilised to initiate a for loop that will itterate over `tvls` and `operatorDelegators` using `tvls.length` for how many itterations should be conducted.

The issue lies in the fact that the function does not check that `tvls` is the same length (or less than) `operatorDelegators`. This can lead to an out-of-bounds array access revert.

The interaction with `chooseOperatorDelegatorForDeposit()` within `RestakeManager.sol` passes the `tvls` parameter within bounds as the passed array is set to be the same length as `operatorDelegators`. However `chooseOperatorDelegatorForDeposit()` is a public function, meaning that it is expected to be accessed by entities outside of the Renzo protocol, therefore there should be an array length check within the function.

## Proof of Concept
[RestakeManager::chooseOperatorDelegatorForDeposit()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L360-L393)
```solidity
    function chooseOperatorDelegatorForDeposit(
        uint256[] memory tvls,
        uint256 totalTVL
    ) public view returns (IOperatorDelegator) {
        // Ensure OperatorDelegator list is not empty
        if (operatorDelegators.length == 0) revert NotFound();

        // If there is only one operator delegator, return it
        if (operatorDelegators.length == 1) {
            return operatorDelegators[0];
        }

        // Otherwise, find the operator delegator with TVL below the threshold
        uint256 tvlLength = tvls.length;
        for (uint256 i = 0; i < tvlLength; ) {
            if (
                tvls[i] <
                (operatorDelegatorAllocations[operatorDelegators[i]] * totalTVL)/
                    BASIS_POINTS /
                    BASIS_POINTS
            ) {
                return operatorDelegators[i];
            }

            unchecked {
                ++i;
            }
        }
```
There is no check to ensure that `tvls` parameter is equal to or shorter than `operatorDelegators` which can lead to reverts due to accessing index that is out of bounds when trying to access `operatorDelegators[i]` where `i > operatorDelegators.length`.

[RestakeManager::depositTokenRewardsFromProtocol()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L647-L658)

The outlined issue only occurs for callers outside of the contract, and as the function is marked as public then it is expected to be called by external entities.

## Recommended Mitigation Steps

Add a check to [RestakeManager::chooseOperatorDelegatorForDeposit()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L360-L393) that ensures that `tvls.length == operatorDelegators.length`. 

Or mark the function as internal if it is only intended to be accessed within the contract, and then the require check won't be necessary as all calls to the function will be with an array that is always of the same length as `operatorDelegators`.
