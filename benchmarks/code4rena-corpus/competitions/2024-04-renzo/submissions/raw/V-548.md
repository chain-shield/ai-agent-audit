# Vulnerability details

## Title
Too few ezETH tokens are minted because of `inflationPercentage` is heavily rounding down as `_currentValueInProtocol ` increases and minting lack slippage control

## Line of code
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L592

## Impact
The function `restakeManager::depositETH` is used to deposit ether by users and mint the ezETH tokens back. As we can see the `ezETHToMint` is being calculated from  `renzoOracle::calculateMintAmount`, now in the `renzoOracle::calculateMintAmount` the `inflationPercentage` is calculated to mint the amount of `ezETH` like this:

```solidity
   uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded);
```
Now problem of round down in this formula occurs when `_currentValueInProtocol` increases with more and more depositing. After a certain limit of `_currentValueInProtocol`, user will get a very low amount of ezETH in depositing ETH.

We have tested the `inflationPercentage` formula with different value of `_currentValueInProtocol`:

```python

ETH = 10 ** 18
currentValueInProtocol = 10 * ETH
new_value_added = 2000 * ETH
SCALE_FACTOR = 10 ** 18

def calculate_inflation_percentage(currentValueInProtocol, new_value_added):
    return (SCALE_FACTOR * new_value_added) / (currentValueInProtocol + new_value_added)

val1 = calculate_inflation_percentage(10 * ETH, 20 * ETH)
val2 = calculate_inflation_percentage(20 * ETH, 20 * ETH)
val3 = calculate_inflation_percentage(1000 * ETH, 20 * ETH)

print(val1)
print(val2)
print(val3)

```
Output:
```bash
6.666666666666666e+17
5e+17
1.96078431372549e+16
```
As seen from the output the `inflationPercentage` is highly rounded down as the `_currentValueInProtocol` increases in the protocol. 

##### Why is this problematic?
At a point where The `_currentValueInProtocol` of protocol increases to a certain amount(like in test setup, 1000 * 10 ** 18) of ETH, minting of ezETH for depositing ETH is too low. Now as the `_currentValueInProtocol` increases to a huge amount, the users will just get a minute amount of ezETH in exchange of the ETH they deposit. 

## Proof of Concept
The [restakeManager::depositETH](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L592) is used to depositETH by the users and gets the ezETH minted back. This function calls [RenzoOracle::calculateMintAmount](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Oracle/RenzoOracle.sol#L123)

```solidity
    function depositETH(uint256 _referralId) public payable nonReentrant notPaused {
        ...

        // Calculate how much ezETH to mint
@>        uint256 ezETHToMint = renzoOracle.calculateMintAmount(
            totalTVL,
            msg.value,
            ezETH.totalSupply()
        );

        // Mint the ezETH
        ezETH.mint(msg.sender, ezETHToMint);
        ...
    }
```
Now in this function, we can see that `inflationPercentaage` is used to calculate the amount of `mintAmount`. As the `inflationPercentaage` decreases the `mintAmount` also decreases.

```solidity
function calculateMintAmount(
        uint256 _currentValueInProtocol,
        uint256 _newValueAdded,
        uint256 _existingEzETHSupply
    ) external pure returns (uint256) {
        ...
        // Calculate the percentage of value after the deposit
@>      uint256 inflationPercentaage = (SCALE_FACTOR * _newValueAdded) /
            (_currentValueInProtocol + _newValueAdded);

        // Calculate the new supply
        uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) /
            (SCALE_FACTOR - inflationPercentaage);

        // Subtract the old supply from the new supply to get the amount to mint
        uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

        // Sanity check
        if (mintAmount == 0) revert InvalidTokenAmount();

        return mintAmount;
    }
```

## Recommended Mitigation Steps
We recommend to use some slippage control to avoid such situations of minting less amount of ezETH.

```solidity
    function depositETH(uint256 _referralId, uint256 minTokenOut) public payable nonReentrant notPaused {
        ...

        // Calculate how much ezETH to mint
@>        uint256 ezETHToMint = renzoOracle.calculateMintAmount(
            totalTVL,
            msg.value,
            ezETH.totalSupply()
        );

        // Mint the ezETH
        if (ezETHToMint < minTokenOut) {
            revert("too few token minted");
        }
        ezETH.mint(msg.sender, ezETHToMint);
        ...
    }
```
