# Vulnerability details

## **Vulnerability Details:**

The **[calculateTVL](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L274)** function in the **RestakeManager** contract calculates the TVLs for each operator delegator by individual token, total for each OD, and total for the protocol. However, there is an edge case where it can incorrectly calculate the TVLs.

As seen below in the function, the collateral tokens in the withdrawQueue are only calculated inside the operatorDelegators loop. This means that if there are no operators in the system, the withdrawQueue tokens will be skipped even if there are currently collateral tokens there.

```solidity
    function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
        uint256[][] memory operatorDelegatorTokenTVLs = new uint256[][](operatorDelegators.length);
        uint256[] memory operatorDelegatorTVLs = new uint256[](operatorDelegators.length);
        uint256 totalTVL = 0;
	...
        for (uint256 i = 0; i < odLength;) {
            ...
                // record token value of withdraw queue
                if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue +=
                        renzoOracle.lookupTokenValue(collateralTokens[i], collateralTokens[j].balanceOf(withdrawQueue));
                }
                unchecked {
                    ++j;
                }
            }
	    ...
            unchecked {
                ++i;
            }
        }
        // Get the value of native ETH held in the deposit queue and add it to the total TVL
        totalTVL += address(depositQueue).balance;
        // Add native ETH help in withdraw Queue and totalWithdrawalQueueValue to totalTVL
        totalTVL += (address(withdrawQueue).balance + totalWithdrawalQueueValue);
        return (operatorDelegatorTokenTVLs, operatorDelegatorTVLs, totalTVL);
    }
```

The ETH balance in the withdraw Queue is accurately calculated at the end of the function, regardless of the operator delegator loop. Similarly, the collateral token balance of the withdraw Queue should be calculated in the same manner.

The **RestakeManager** contract includes the functionality to remove all operators using the **[removeOperatorDelegator](https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/RestakeManager.sol#L160)** function. While this might seem like an edge case, it is indeed possible. In this scenario, if all operators are removed, funds will remain in the WithdrawQueue contract, available for withdrawal, with the TVL used to determine the withdrawal amounts.

## **Impact:**

- Severity: Medium. The incorrect calculation of TVLs could lead to inaccurate reporting of the protocol's total value locked, potentially affecting withdrawal amounts.
- Likelihood: Low. This issue is an edge case that may not occur frequently but could have significant consequences if it does.

## **Tools Used:**

- Manual analysis

## **Recommendation:**

Modify the **calculateTVL** function to calculate the collateral token balance of the **WithdrawQueue** contract outside the operator delegator loop, similar to how the ETH balance in the **WithdrawQueue** is calculated. This will ensure that the TVL is accurately calculated even when there are no operators in the system or when all operators are removed.
