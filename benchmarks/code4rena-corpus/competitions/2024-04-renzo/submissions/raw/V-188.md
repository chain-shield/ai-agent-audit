# Vulnerability details

## Impact
The TVL calculation of RestakeManager contract will result in incorrect TVL value if the operatorDelegators list is update without checking if there was any value locked with the delegator.



## Proof of Concept
Refer to the below code snippet where the delegator is removed from the operatorDelegators list without check if any value is locked with the operatorDelegators for any of the tokens in the collateral Token list.

As this check is missing, the admin could remove the operator Delegator leading to under account of TVL.


```
   function removeOperatorDelegator(
        IOperatorDelegator _operatorDelegatorToRemove
    ) external onlyRestakeManagerAdmin {
        // Remove it from the list
        uint256 odLength = operatorDelegators.length;
        for (uint256 i = 0; i < odLength; ) {
            if (address(operatorDelegators[i]) == address(_operatorDelegatorToRemove)) {
                // Clear the allocation
                operatorDelegatorAllocations[_operatorDelegatorToRemove] = 0;
                emit OperatorDelegatorAllocationUpdated(_operatorDelegatorToRemove, 0);

                // Remove from list
                operatorDelegators[i] = operatorDelegators[operatorDelegators.length - 1];
                operatorDelegators.pop();
                emit OperatorDelegatorRemoved(_operatorDelegatorToRemove);
                return;
            }
            unchecked {
                ++i;
            }
        }

        // If the item was not found, throw an error
        revert NotFound();
    }

```

## Tools Used
Manual

## Recommended Mitigation Steps
In the removeOperatorDelegator() function, the logic should first check if the operator being removes has any value locked against the configured collateral tokens. Only in the case when there was no value locked in any of the configured tokens, the operator can be removed, else the transaction should be reverted.
