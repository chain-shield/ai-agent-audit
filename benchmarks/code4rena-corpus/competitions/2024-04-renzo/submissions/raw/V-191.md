# Vulnerability details

        uint64 oracleTimestamp,

     @>   eigenPod.verifyAndProcessWithdrawals(

Now the problem is, when `verifying ETH` is greater than `withdrawal ETH` then `stakedButNotVerifiedEth` should be reduced

//How this works(very simple example)
1. Suppose an operator have 64 ETH staked but not verified, thus stakedButNotVerifiedEth = 64 ETH
2. There is a withdrawal of 32 ETH
3. `OperatorDelegator::verifyAndProcessWithdrawals()` is used to verify those 64 ETH as well as withdraw 32 ETH
4. Effective shares that operator delegator will get is 32 ETH due to 
```solidity
   if (withdrawalSummary.sharesDeltaGwei != 0) {
        @>    eigenPodManager.recordBeaconChainETHBalanceUpdate(podOwner, withdrawalSummary.sharesDeltaGwei * int256(GWEI_TO_WEI));
        }
```
5. Now stakedButNotVerifiedEth should be reduced but its not

## Impact
`stakedButNotVerifiedEth` is used in calculating `TVL`, as a result wrong TVL will be calculated
