# Vulnerability details


## Cause

In the `OperatorDelegator` contract, [the `baseGasAmountSpent`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L470-L471) value is applied to all admin gas refunds recorded for `queueWithdrawals`, `completeQueuedWithdrawal`, `verifyWithdrawalCredentials`, and `verifyAndProcessWithdrawals`. However, the initial cost of transactions, which mostly depends on calldata size, is not the same for these methods.

Currently, `baseGasAmountSpent` is [set to 1,350,000 gas](https://etherscan.io/address/0xbAf5f3A05BD7Af6f3a0BBA207803bf77e2657c8F#readProxyContract), which matches the base cost of `verifyAndProcessWithdrawals` (e.g., see gas profiling for [an example transaction](https://app.blocksec.com/explorer/tx/eth/0xd98f085430513f1b96f541c6ff830fa19817f70752f14927066ec787c855267e)). This example transaction has 101,952 bytes of calldata and pays 1,330,000 gas in initial costs, which matches `baseGasAmountSpent`. If this periodic transaction is to properly be refunded, it must continue using the same value.

However, when `queueWithdrawals` and `completeQueuedWithdrawal` methods are added, and will be called periodically to process withdrawals, they will have a much lower initial gas cost. Yet, their gas expense is [recorded](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L253) using the [same](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L323) code with the large `baseGasAmountSpent` value, causing the admin gas refunds for these methods to be overestimated. The `gasSpent` will be inflated by almost 1.3M gas for each transaction. 

## Impact

This will result in refunds being [over-refunded](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L481-L482) from the received rewards, resulting in a loss of yield for ezETH holders, since the refunds are [deducted from the incoming rewards](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L508-L512). 

Calculating the real base cost for `queueWithdrawals`:

- With intrinsic and calldata gas priced at `21000 + countNonZeroBytesInCalldata * 16 + countZeroBytesInCalldata * 4` and adding 20K gas for [`nonReentrant` and `onlyNativeEthRestakeAdmin` that are called](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L196) before `gasleft()` (requiring two storage reads, two cold access address loads, and two non-zero storage writes for `adminGasSpentInWei` and reentrancy status), we get with an input of `4 + 5*32 + 5*32` bytes (selector + two arrays of 2 elements for each of the 3 supported tokens), only 324 bytes of calldata. With roughly 128 bytes of non-zero data (addresses, amounts, selector) it results in only 2,784 calldata gas cost. Together with 20K for modifiers and 21K for intrinsic cost, the correct `baseGasAmountSpent` should be 44,000 instead of the much larger 1,350,000.
- At 200 gwei gas prices, and 10 withdrawals per day (20 daily transactions), this translates to a loss of yield of 1898 ETH, or 6.3% of the total yield.

Similarly, `completeQueuedWithdrawal` also requires a different `baseGasAmountSpent`, which is also much lower than currently set. Its calldata length is roughly 676 bytes, which is also two orders of magnitude shorter than the cost for `verifyAndProcessWithdrawals` (at around 100,000 bytes).

This is also true for `verifyWithdrawalCredentials`, but it is unlikely to be called periodically, so it is not as important.

## Proof of Concept

1. With intrinsic gas priced at 21,000 and calldata priced at `countNonZeroBytesInCalldata * 16 + countZeroBytesInCalldata * 4`, for `queueWithdrawals` with an input of `4 + 5*32 + 5*32` bytes (selector + two arrays of 2 elements for each of the 3 supported tokens), we get 324 bytes of calldata, with roughly 128 bytes of non-zero data (addresses, amounts, selector). This results in only 2,784 calldata costs.
2. There's also 20K gas for [`nonReentrant` and `onlyNativeEthRestakeAdmin` that are called](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L196) before `gasleft()` (requiring two storage reads, two cold access address loads, and two non-zero storage writes for `adminGasSpentInWei` and reentrancy status).
3. Together with 20K for modifiers, 21K for intrinsic costs, and 2,784 for calldata cost, the correct `baseGasAmountSpent` should be 44,000 instead of the much larger 1,350,000.
4. At 200 gwei gas prices, each transaction will over-refund 0.26 ETH. Assuming 10 withdrawals per day (20 daily transactions), this translates to a loss of yield of 1898 ETH.
5. With the current 3% yield on 1M ETH equalling 30000 ETH, this results in loss of nearly 6.3% of the total yield.

## Recommended Mitigation Steps

The simplest way to fix this is to remove the use of `baseGasAmountSpent` in the calculation for `queueWithdrawals` and `completeQueuedWithdrawal`, but keep it for the `verifyAndProcessWithdrawals` that has expensive intrinsic costs. This will be somewhat similar to how this logic [is already used in `DepositQueue`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L283-L284).

```diff

+    uint256 internal constant NOMINAL_GAS_BASE_COST = 50_000;

-    function _recordGas(uint256 initialGas) internal {
-		uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
+    function _recordGas(uint256 initialGas, uint256 baseGas) internal {
+        uint256 gasSpent = (initialGas - gasleft() + baseGas) * tx.gasprice;

..

		..

..

		..
```
