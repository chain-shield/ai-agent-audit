# Vulnerability details

## Impact
`OperatorDelegator::_recordGas()` uses `msg.sender` to track how much gas is utilised, however the `receive()` function checks the amount of gas that is owed to `tx.origin` and refunds however much is owed. As the utilised `msg.sender` could be a smart contract that is calling the functions within `OperatorDelegator.sol`, then the gas refund will be incorrectly attributed to the calling contract. However that calling contract will never be able to be the `tx.origin` of a transaction, meaning any funds attributed to it will be unredeemable.

This will lead to admins losing out on their gas refund, which is a loss of funds and deincentivises the frequent calling of important protocol functions through other contracts.

## Proof of Concept
[OperatorDelegator::_recordGas()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L470-L474)
```solidity
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
        adminGasSpentInWei[msg.sender] += gasSpent;
        emit GasSpent(msg.sender, gasSpent);
    }
```
`_recordGas` utilises `msg.sender` when recording gas, however it should utilise `tx.origin` as it's tracking the user who is initating the transaction:

[OperatorDelegator::_refundGas()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L481-L493)
```solidity
    function _refundGas() internal returns (uint256) {
        uint256 gasRefund = address(this).balance >= adminGasSpentInWei[tx.origin]
            ? adminGasSpentInWei[tx.origin]
            : address(this).balance;
        bool success = payable(tx.origin).send(gasRefund);
        if (!success) revert TransferFailed();

        // reset gas spent by admin
        adminGasSpentInWei[tx.origin] -= gasRefund;

        emit GasRefunded(tx.origin, gasRefund);
        return gasRefund;
    }
```
As can be seen in `_refundGas()` it utilises `tx.origin` to check how much gas should be refunded to the transaction initializer.

## Recommended Mitigation Steps

Change `msg.sender` to `tx.origin` to avoid incorrectly attributing gas refunds to contracts that will be unable to retrieve the funds:
[OperatorDelegator::_recordGas()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L470-L474)
```diff
    function _recordGas(uint256 initialGas) internal {
        uint256 gasSpent = (initialGas - gasleft() + baseGasAmountSpent) * tx.gasprice;
-        adminGasSpentInWei[msg.sender] += gasSpent;
+        adminGasSpentInWei[tx.origin] += gasSpent;
-        emit GasSpent(msg.sender, gasSpent);
+        emit GasSpent(tx.origin, gasSpent);
    }
```
