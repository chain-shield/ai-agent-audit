# Vulnerability details

## Impact
The `getStrategyIndex` function in the contract is designed to retrieve the index of a specific strategy in the staker's strategy list. While the function generally works as intended, it lacks complete handling for scenarios where strategies have been deleted from the list.

```javascript
/// @dev Gets the index of the specific strategy in EigenLayer in the staker's strategy list
    function getStrategyIndex(IStrategy _strategy) public view returns (uint256) {
        // Get the length of the strategy list for this contract
        uint256 strategyLength = strategyManager.stakerStrategyListLength(address(this));

        for (uint256 i = 0; i < strategyLength; i++) {
            if (strategyManager.stakerStrategyList(address(this), i) == _strategy) {
                return i;
            }
        }

        // Not found
        revert NotFound();
    }
```

## Proof of Concept
When a strategy is deleted from the staker's strategy list, the index of other strategies may change, potentially leading to incorrect indices being returned by the `getStrategyIndex` function.
This can result in unexpected behavior or even errors in contract execution if the returned index is used incorrectly.

## Recommended Mitigation Steps
To address this issue and ensure the reliability of the function, consider the following steps:

 Instead of removing strategies from the list entirely, mark them as inactive. This ensures that their indices remain consistent and prevents out-of-bounds access.
Alternatively, Maintain a mapping of strategies to their indices to enable constant-time lookup. This approach eliminates the need for looping through the entire list and provides efficient index retrieval. You can just check if the strategy exists in a mapping and revert if it does not
Bounds Checking: Add checks to ensure that the returned index is within the bounds of the strategy list before using it. This helps prevent errors resulting from invalid indices.
