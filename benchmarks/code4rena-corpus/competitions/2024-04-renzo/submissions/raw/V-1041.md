# Vulnerability details

## Impact
The function `getMintRate` reads the price from an oracle and scales it to a value with 18 decimal places. This operation to adjust the decimals involves a multiplication of the price with `10 ** (18 - oracle.decimals())`, which could cause numerical overflow if not properly safeguarded.

An overflow occurs when an operation tries to create a number that is outside the maximum limit that can be held by the data type. In Solidity, a `uint256` has a maximum limit of 2^256 - 1, and any calculation that exceeds this value will result in an overflow and the value will loop around to zero.

## Recommended Mitigation Steps

In order to prevent this potential overflow issue, a best practice would be to use an open-source library like OpenZeppelin's SafeMath for all arithmetic operations which will throw an error and halt execution when an overflow or underflow condition is encountered. You can see an example on how to integrate SafeMath below:

```solidity
import "@openzeppelin/contracts/utils/math/SafeMath.sol";
...
using SafeMath for uint256;
...

function getMintRate() public view returns (uint256, uint256) {
    (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
    if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
    // scale the price to have 18 decimals
    uint256 _scaledPrice = (uint256(price)).mul(10 ** (18 - oracle.decimals()));
    if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
    return (_scaledPrice, timestamp);
}
```

By doing so, inside the `getMintRate` method where the scaling occurs, the `*` operator is replaced with `.mul`, effectively making the multiplication operation checked for overflow. Thus, if an overflow condition occurs, it will not be unnoticed, and will revert the transaction, preventing any further potential damage.
