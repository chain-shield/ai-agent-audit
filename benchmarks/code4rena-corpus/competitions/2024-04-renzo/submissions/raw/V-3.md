# Vulnerability details

## Impact
The xReceive function in the xRenzoBridge.sol contract is critical for handling the conversion of WETH to ETH and subsequently managing the interactions with the contract's financial operations. A lack of rigorous validation after unwrapping WETH to ensure the correct amount of ETH has been received poses a risk. If the WETH contract is compromised, behaves unexpectedly, or if there's a bug that doesn't cause a revert but leads to incorrect ETH amounts being unwrapped, it could result in financial discrepancies. These could manifest as errors in token balances or operations, leading to financial loss or the corruption of financial data integrity within the platform.

## Proof of Concept
The xReceive function is responsible for unwrapping WETH to ETH. This operation is based on the assumption that the WETH contract behaves correctly and that WETH.withdraw(amount) indeed releases the equivalent amount of ETH.

Let's suppose the WETH contract has been compromised or a bug exists in its implementation that does not properly ensure that the ETH amount released matches the WETH amount intended to be unwrapped. Here’s a breakdown of how this might impact the system:

Scenario A: The WETH contract is compromised to allow a withdraw call to pass without actually releasing any ETH, or releasing less ETH than requested. If no ETH is released or less than expected, the subsequent operations in xReceive that depend on the ETH amount (like funding operations or minting tokens) will proceed with incorrect values. This could lead to under-minting of the platform’s tokens, disrupting the balance and integrity of the financial operations within the platform.

Scenario B: The WETH contract could be exploited to release more ETH than it should based on the WETH balance provided. If more ETH than expected is released, it could lead to over-minting of tokens, thus inflating the supply improperly and potentially leading to financial loss for the token holders or the platform due to value dilution.

### Execution of the Attack
An attacker who gains control over the WETH contract or discovers a vulnerability could manipulate the contract’s behavior during the withdraw operation. By triggering this behavior when xReceive is called, the attacker could cause the xRenzoBridge contract to operate with incorrect financial assumptions, leading to the aforementioned issues.

1. WETH is sent to the contract and is intended to be unwrapped.
2. The xReceive function unwraps WETH but does not verify the actual amount of ETH received post-unwrapping.
3. The actual amount of unwrapped ETH differs from the amount expected.
4. The subsequent financial operations in xReceive proceed with incorrect ETH values, leading to potential token over-minting or under-minting.

Code snippet to highlight the area without verification:
```
xRenzoBridge.sol

function xReceive(bytes32 _transferId, uint256 _amount, address _asset, address _originSender, uint32 _origin, bytes memory) external nonReentrant returns (bytes memory) {
```

## Recommended Mitigation Steps
### Add Post-Unwrap Verification
Implement a check after the WETH unwrap to verify that the actual ETH amount received matches the expected amount unwrapped. If not, revert the transaction. Here's an example:
```
xRenzoBridge.sol

function xReceive(bytes32 _transferId, uint256 _amount, address _asset, address _originSender, uint32 _origin, bytes memory) external nonReentrant returns (bytes memory) {
...
    // Get the balance of ETH before the withdraw
    uint256 ethBalanceBeforeWithdraw = address(this).balance;

    // Unwrap the WETH
    IWeth(address(wETH)).withdraw(_amount);

    // Verify the actual amount of ETH received
    uint256 ethAmount = address(this).balance - ethBalanceBeforeWithdraw;
    if (ethAmount != _amount) {
        revert("UnwrapMismatch");
    }
}
...
```
It's critical to implement a verification check immediately after converting WETH to ETH. Start by capturing the smart contract’s ETH balance before executing the withdraw operation from the WETH contract. This initial balance will serve as a reference to verify the success of the unwrapping process. After unwrapping, compare the new ETH balance of the contract with the pre-unwrap balance to determine the actual amount of ETH received. If this amount does not match the expected amount of WETH unwrapped, the transaction should be reverted to prevent potential discrepancies that could lead to financial errors.
