# Vulnerability details

## Impact
The `deposit` function in `xRenzoDeposit.sol` does not have any mechanisms in place to prevent the replay of user signatures across different chains. This vulnerability could allow an attacker to steal funds by replaying a victim's signature on a different chain.

This vulnerability allows an attacker to directly steal user funds by replaying the victim's failed transactions. The financial impact can be significant, as an attacker can potentially steal large amounts of user funds by exploiting this vulnerability across multiple victims.

## Proof of Concept
The attacker observes Alice, the victim, attempting to deposit ETH into the protocol using the `deposit()` function.

The attacker intercepts Alice's failed transaction and obtains the transaction data, including the `_amountIn`, `_minOut` and `_deadline` parameters.

The attacker waits for a brief period, then resubmits the same transaction data to the `deposit()` function.

Since the `deposit` function does not have any mechanisms to prevent replay attacks, the protocol will execute the transaction again, effectively draining Alice's ETH.

The attacker can repeat this process until Alice's entire ETH balance is drained from the protocol.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement nonce-based or other mechanisms to ensure that each transaction can only be executed once, preventing replay attacks.
