# Vulnerability details

## Impact
The unbounded loops in `chooseOperatorDelegatorForWithdraw` function can lead to Denial of Service (DoS) attacks. An attacker could call this function with a very large number of `OperatorDelegators`, causing the transaction to take an extremely long time to execute and preventing other users from withdrawing their funds.

## Proof of Concept
Obtain a large number of `OperatorDelegator` addresses, for example, by creating many accounts and deploying `OperatorDelegator` contracts.

Call the `chooseOperatorDelegatorForWithdraw` function with a large array of `OperatorDelegators`. This will cause the function to iterate through the entire `operatorDelegatorTVLs` and `operatorDelegators` arrays, consuming a large amount of gas.

Repeat step 2 to prevent other users from successfully withdrawing their funds.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a maximum array size limit for the `operatorDelegatorTVLs` and `operatorDelegators` arrays to prevent the unbounded loops from consuming too much gas.

Consider using a more efficient data structure, such as a mapping, to store the `OperatorDelegatorTVLs` and `OperatorDelegators` instead of arrays.

Consider implementing additional checks or throttling mechanisms to limit the number of `OperatorDelegators` that can be used for withdrawals within a certain time frame for each user.
