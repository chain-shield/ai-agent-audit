# Vulnerability details

## Root of the bug and details 

The bug is arise from the incorrect division by BASIS_POINTS twice in the allocation calculations within the functions chooseOperatorDelegatorForDeposit and chooseOperatorDelegatorForWithdraw. 
This incorrect handling leads to significantly smaller values than intended for the threshold comparisons.
here in function chooseOperatorDelegatorForDeposit
```solidity 
 if (
                tvls[i] <
                (operatorDelegatorAllocations[operatorDelegators[i]] * totalTVL) /
                    BASIS_POINTS /
                    BASIS_POINTS
            ) {
                return operatorDelegators[i];
            }

```
and in the function chooseOperatorDelegatorForWithdraw
```solidity
 if (
                operatorDelegatorTVLs[i] >
                (operatorDelegatorAllocations[operatorDelegators[i]] * totalTVL) /
                    BASIS_POINTS /
                    BASIS_POINTS &&
                operatorDelegatorTokenTVLs[i][tokenIndex] >= ezETHValue
            ) {
                return operatorDelegators[i];
            }
```
in this functions the calculations of the threshold for TVL comparison is incorrect due to double division by BASIS_POINTS and this incorrect calculation significantly reduces the threshold value, making it nearly impossible for any operator delegator to have a TVL below this value.

## Impact
Deposits might not be allocated to the correct operator delegator, leading to imbalanced TVLs.
and Withdrawals might fail unnecessarily because the  logic not find a suitable operator delegator due to incorrect threshold calculations.


## Proof of Concept
i test with this scenario let's say taht : 
- BASIS_POINTS is 100.
- operatorDelegatorAllocations[operatorDelegator] is 50 (representing 50%).
- totalTVL is 1000.
- TVL of an operator delegator (tvls[i]) is 400.

in the function chooseOperatorDelegatorForDeposit the calculation is Simplifies :
```solidity 
tvls[i] < (50 * 1000) / 100 / 100
// tvls[i] < 5
```
- here the result is incorrect Threshold: 5
and in chooseOperatorDelegatorForWithdraw function the calculation is Simplifies :
```solidity 
tvls[i] < (50 * 1000) / 100
// tvls[i] < 500
```
- the result is Correct Threshold: 500

## Recommended Mitigation Steps
The logic should only divide by BASIS_POINTS once to correctly compute the allocation threshold
