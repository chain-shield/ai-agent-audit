# Vulnerability details

## Impact
In the `xRenzoDeposit:depositETH` & `xRenzoBridge:xReceive`, there's a section of code where the amount of wrapped tokens (WETH) received as a result of wrapping deposited ETH is calculated. 

However, there's a potential issue where if there's another balance increase between the retrieval of the deposit token balance before wrapping and the calculation of the wrapped amount, it will result in an incorrect calculation of the wrapped amount. This could lead to inaccuracies in the deposit process and potentially affect user balances and protocol operations.

If there's a balance increase between the two points mentioned above, the calculation of the wrapped amount will include additional tokens not related to the current deposit. This could result in loss of funds for users and also incorrect minting of `xezETH` tokens, leading to discrepancies in user balances and potentially disrupting the protocol's operations. 
## Proof of Concept
To demonstrate the potential issue, we can create a scenario where there's a balance increase between the retrieval of the deposit token balance before wrapping and the calculation of the wrapped amount. Here's a simplified version of the scenario:

- Suppose the `depositETH` function is called with a certain amount of ETH to be deposited.
- Before wrapping the deposited ETH to WETH, the current balance of the deposit token (WETH) in the contract is retrieved as `depositBalanceBefore`.
- The ETH is then wrapped to WETH.
- Another transaction occurs on the blockchain, resulting in an increase in the contract's balance of the deposit token.
- The calculation of the wrapped amount is performed using the difference between the current balance of the deposit token (`depositBalanceAfter`) and the balance before wrapping (`depositBalanceBefore`).

If there's an increase in the deposit token balance during step 4, it will not be accounted for in the calculation of the wrapped amount, leading to inaccuracies in the deposit process.

xRenzoDeposit:depositETH
```
function depositETH(
        uint256 _minOut,
        uint256 _deadline
    ) external payable nonReentrant returns (uint256) {
        if (msg.value == 0) {
            revert InvalidZeroInput();
        }

        // Get the deposit token balance before
        uint256 depositBalanceBefore = depositToken.balanceOf(address(this));

        // Wrap the deposit ETH to WETH
        IWeth(address(depositToken)).deposit{ value: msg.value }();

        // Get the amount of tokens that were wrapped
        uint256 wrappedAmount = depositToken.balanceOf(address(this)) - depositBalanceBefore;

        // Sanity check for 0
        if (wrappedAmount == 0) {
            revert InvalidZeroOutput();
        }

        return _deposit(wrappedAmount, _minOut, _deadline);
    }
```

xRenzoBridge:xReceive
```
 function xReceive(
        bytes32 _transferId,
        uint256 _amount,
        address _asset,
        address _originSender,
        uint32 _origin,
        bytes memory
    ) external nonReentrant returns (bytes memory) {
        // Only allow incoming messages from the Connext contract
        if (msg.sender != address(connext)) {
            revert InvalidSender(address(connext), msg.sender);
        }

        // Check that the token received is wETH
        if (_asset != address(wETH)) {
            revert InvalidTokenReceived();
        }

        // Check that the amount sent is greater than 0
        if (_amount == 0) {
            revert InvalidZeroInput();
        }

        // Get the balance of ETH before the withdraw
        uint256 ethBalanceBeforeWithdraw = address(this).balance;

        // Unwrap the WETH
        IWeth(address(wETH)).withdraw(_amount);

        // Get the amount of ETH
        uint256 ethAmount = address(this).balance - ethBalanceBeforeWithdraw;

        // Get the amonut of ezETH before the deposit
        uint256 ezETHBalanceBeforeDeposit = ezETH.balanceOf(address(this));

        // Deposit it into Renzo RestakeManager
        restakeManager.depositETH{ value: ethAmount }();

        // Get the amount of ezETH that was minted
        uint256 ezETHAmount = ezETH.balanceOf(address(this)) - ezETHBalanceBeforeDeposit;

        // Approve the lockbox to spend the ezETH
        ezETH.safeApprove(address(xezETHLockbox), ezETHAmount);

        // Get the xezETH balance before the deposit
        uint256 xezETHBalanceBeforeDeposit = xezETH.balanceOf(address(this));

        // Send to the lockbox to be wrapped into xezETH
        xezETHLockbox.deposit(ezETHAmount);

        // Get the amount of xezETH that was minted
        uint256 xezETHAmount = xezETH.balanceOf(address(this)) - xezETHBalanceBeforeDeposit;

        // Burn it - it was already minted on the L2
        IXERC20(address(xezETH)).burn(address(this), xezETHAmount);

        // Emit the event
        emit EzETHMinted(_transferId, _amount, _origin, _originSender, ezETHAmount);

        // Return 0 for success
        bytes memory returnData = new bytes(0);
        return returnData;
    }
```

## Recommended Mitigation Steps
Instead of calculating the wrapped amount based on the difference in balances before and after wrapping, the contract could maintain a mapping of deposited ETH amounts per user. When a user deposits ETH, their deposit amount is recorded in this mapping. Then, upon withdrawal, the recorded deposit amount is used to determine the amount of `xezETH` to mint. This approach eliminates the need to calculate the wrapped amount based on balance differences, thus mitigating the risk of interference from balance increases during the deposit process.
