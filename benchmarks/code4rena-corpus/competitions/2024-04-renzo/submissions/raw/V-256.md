# Vulnerability details

## Impact
When `OperatorDelegator::getStakedETHBalance()` calculates the total staked eth balance of the protocol, it is possible for the retrieved `podOwnerShares` value to be negative due to how EigenLayer withdrawal queue works. The current code will negate a negative value, meaning it will be turned into a positive value and added to the total staked ETH.

This will lead to double accounting of staked ETH, which will cause the TVL to be inflated causing `RestakeManager::calculateTVLs()` to return an inflated value. This will lead to `BalancerRateProvider::getRate()` to return a higher price in terms of `ETH`. This will cause users to be minted less `ezETH` for their deposits causing them to lose funds.

## Proof of Concept
[OperatorDelegator::getStakedETHBalance()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L337-L345)
```solidity
    /// @dev Gets the amount of ETH staked in the EigenLayer
    function getStakedETHBalance() external view returns (uint256) {
        // accounts for current podOwner shares + stakedButNotVerified ETH + queued withdraw shares
        int256 podOwnerShares = eigenPodManager.podOwnerShares(address(this));
        return
            podOwnerShares < 0
                ? queuedShares[IS_NATIVE] + stakedButNotVerifiedEth - uint256(-podOwnerShares)
                : queuedShares[IS_NATIVE] + stakedButNotVerifiedEth + uint256(podOwnerShares);
    }
```
It can be seen that if `podOwnerShares` is negative, this balance is added to the total by negating the negative. However this should not be negated.

[EigenPodManagerStorage.sol#L57-L66](https://github.com/Layr-Labs/eigenlayer-contracts/blob/dev/src/contracts/pods/EigenPodManagerStorage.sol#L57-L66)
```solidity
    // BEGIN STORAGE VARIABLES ADDED AFTER MAINNET DEPLOYMENT -- DO NOT SUGGEST REORDERING TO CONVENTIONAL ORDER
    /**
     * @notice Mapping from Pod owner owner to the number of shares they have in the virtual beacon chain ETH strategy.
     * @dev The share amount can become negative. This is necessary to accommodate the fact that a pod owner's virtual beacon chain ETH shares can
     * decrease between the pod owner queuing and completing a withdrawal.
     * When the pod owner's shares would otherwise increase, this "deficit" is decreased first _instead_.
     * Likewise, when a withdrawal is completed, this "deficit" is decreased and the withdrawal amount is decreased; We can think of this
     * as the withdrawal "paying off the deficit".
     */
    mapping(address => int256) public podOwnerShares;
```
As the notice above states, when queueing withdrawals the shares are removed from `podOwnerShares` which can make `podOwnerShares` become temporarily negative until a withdrawal is completed. Note that the shares are already added by `queuedShares`, therefore if the negative of `podOwnedShares` is negated, it will be added to the total for a 2nd time, which will lead to double accounting and inflation of the stakedETHBalance that is returned.

[BalancerRateProvider::getRate()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RateProvider/BalancerRateProvider.sol#L28-L41)
```solidity
    /// @dev Returns the current rate of ezETH in ETH
    function getRate() external view returns (uint256) {
        // Get the total TVL priced in ETH from restakeManager
        (, , uint256 totalTVL) = restakeManager.calculateTVLs();

        // Get the total supply of the ezETH token
        uint256 totalSupply = ezETHToken.totalSupply();

        // Sanity check
        if (totalSupply == 0 || totalTVL == 0) revert InvalidZeroInput();

        // Return the rate
        return (10 ** 18 * totalTVL) / totalSupply;
    }
```
As seen above `totalTVL` is obtained by calling [RestakeManager.sol#L328-L329](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RestakeManager.sol#L328-L329):
```solidity
            // Get the value of native ETH staked for the OD
            uint256 operatorEthBalance = operatorDelegators[i].getStakedETHBalance();
```
Which relies on the value returned from `getStakedETHBalance()`.

This means that the price returned from [BalancerRateProvider::getRate()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/RateProvider/BalancerRateProvider.sol#L28-L41) will be inflated, causing `ezETH` to be worth more than it is in reality.
