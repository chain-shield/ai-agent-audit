# Vulnerability details

## Impact
If the token send fails, the user may loss ezETH token

## Proof of Concept
OpenZeppelin’s IERC20 interface are expected to return a bool value after a successful transfer:

openzeppelin/contracts/token/ERC20/IERC20.sol
```solidity
    function transfer ( address to , uint256 amount ) external returns ( bool );
```
However, the `WithdrawQueue.sol#claim()` function does not check the return value if token send fails.
```solidity
    function claim(uint256 withdrawRequestIndex) external nonReentrant {
        SNIP...

        // burn ezETH locked for withdraw request
299:    ezETH.burn(address(this), _withdrawRequest.ezETHLocked);

        // send selected redeem asset to user
        if (_withdrawRequest.collateralToken == IS_NATIVE) {
            payable(msg.sender).transfer(_withdrawRequest.amountToRedeem);
        } else {
305:        IERC20(_withdrawRequest.collateralToken).transfer(
306:            msg.sender,
307:            _withdrawRequest.amountToRedeem
308:        );
        }
        // emit the event
        emit WithdrawRequestClaimed(_withdrawRequest);
    }
```
Some ERC20 tokens are not reverted when token send fails and return a bool value, so the `claim()` function is not reverted.
Therefore, if token send fails, the user losses ezETH by #L299.
