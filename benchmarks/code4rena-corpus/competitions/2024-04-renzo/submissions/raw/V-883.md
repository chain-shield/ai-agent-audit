# Vulnerability details

## Impact
There is an unprotected call to a function sending Ether to an arbitrary address, this line [(bool _success, ) = payable(_to).call{ value: _amount }("");](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20Lockbox.sol#L131) sends Ether to the address specified by the `_to` variable, which is not validated or checked in any way. An attacker could potentially drain the contract's funds by calling the `_withdraw` function with a malicious address.

### Vulnerability & Description
The function takes two inputs:

 * `_to`: the address to which the funds will be sent
 * `_amount`: the amount of funds to be sent

It performs the following steps:

1. Emits a Withdraw event with the `_to` address and `_amount`
2. Burns the specified `_amount` of tokens from the sender's balance using `XERC20.burn(msg.sender, _amount)`
3. If `IS_NATIVE` is true, sends Ether to the `_to` address using `payable(_to).call{ value: _amount }("")`
4. If `IS_NATIVE` is false, transfers ERC20 tokens to the `_to` address using `ERC20.safeTransfer(_to, _amount)`

The [(bool _success, ) = payable(_to).call{ value: _amount }("");](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20Lockbox.sol#L131), which sends Ether to the `_to` address without any validation or checks allows an attacker to drain the contract's funds by calling the `_withdraw` function with a malicious address.

The call function is used to send Ether to the `_to` address, which can lead to a reentrancy attack. If the `_to` address is a contract, it can execute a fallback function, which can call the `_withdraw` function, potentially draining the contract's funds.

## Proof of Concept
The function's behavior deviates from the expected outcome, as it allows an attacker to manipulate the `_to` address and drain the contract's funds.

## Recommended Mitigation Steps
Use the **transfer** function instead of **call** to send Ether, as it includes additional security measures to prevent reentrancy attacks. Validate and sanitize the `_to` address to ensure it is a legitimate recipient.

Use the address **payable** type instead of **address** to ensure that the `_to` address is a payable address.

```solidity
// Vulnerable code
(bool _success, ) = payable(_to).call{ value: _amount }("");

// Mitigated code
_to.transfer(_amount);
```
