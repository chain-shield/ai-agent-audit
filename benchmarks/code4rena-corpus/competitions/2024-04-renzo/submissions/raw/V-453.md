# Vulnerability details

## Vulnerability Details

Renzo's withdraw flow is a two-step process:

1. The user initiates a withdraw request by calling `WithdrawQueue.withdraw()`.
2. After a certain cool-down period, the user completes the withdraw by calling `WithdrawQueue.claim()`.


```
// revert if amount to redeem is greater than withdrawBufferTarget
if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();
```
When making a withdraw request, the withdraw amount cannot exceed the available-to-withdraw amount in the `WithdrawQueue`.

```
    function getAvailableToWithdraw(address _asset) public view returns (uint256) {
        if (_asset != IS_NATIVE) {
            return IERC20(_asset).balanceOf(address(this)) - claimReserve[_asset];
        } else {
            return address(this).balance - claimReserve[_asset];
        }
    }
```
The available-to-withdraw amount is determined by the contract balance, subtracting the `claimReserve[_asset]` value. The `claimReserve[_asset]` value is increased in `WithdrawQueue.withdraw()` and decreased in `WithdrawQueue.claim()`.

A whale can exploit this by making a large deposit, and then calling `WithdrawQueue.withdraw()` to deplete the available withdrawn amount in the WithdrawQueue. This would prevent other users from making withdraw requests. The cost for the whale is minimal, as they can retrieve their funds from `WithdrawQueue.claim()` after the cool-down period. Moreover, they can choose not to claim the assets after the cool-down period, thereby extending the attack.

However, the team would need to manually unstake assets from EigenLayer and refill the `WithdrawQueue`, which takes about a week. This leaves the `WithdrawQueue` with insufficient available withdrawn amounts during this period.

New deposits from users and protocol rewards to fill the `WithdrawQueue` can alleviate the situation, but only to a limited extent.

## Impact
Whales can deplete the available withdrawn amount in the `WithdrawQueue`, preventing other users from making satisfactory withdraw requests during the time it takes for the team to complete the withdraw from EigenLayer and refill the `WithdrawQueue` (about 1 week).

## Tools Used
Manual review

## Recommended Mitigation Steps
Set an upper limit per user in the `claimReserve`, so that if a user wants to withdraw more, they need to first claim to leave some room in `claimReserve` for new withdraw requests.


## Assessed type

DoS
