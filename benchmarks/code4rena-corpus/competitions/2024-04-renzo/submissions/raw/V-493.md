# Vulnerability details

## Impact
The usage of `payable(address).transfer()` forwards only 2300 gas and if the receiver is a smart contract that depends on executing logic in its receive function this can result in permanent DOS and the funds being locked.

## Proof of Concept
`Transfer()` is used in three places:
1. [`WithdrawQueue.sol:claim()`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L303)
2. [`xRenzoDeposit.sol:recoverNative()`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/L2/xRenzoDeposit.sol#L478-L480)
3. [`xRenzoBridge.sol:recoverNative()`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/L1/xRenzoBridge.sol#L294-L296)

In cases the receiver is an EOA this is not an issue but a protocol could build integrations with Renzo and their logic could use the `receive()` to make calculations or state changes, just like Renzo does in some contracts. In the latter case 2300 gas will not be enough and the transaction will always revert.

This is especially bad in the situation where [`WithdrawQueue.sol:claim()`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Withdraw/WithdrawQueue.sol#L303) is called, the funds will not be recoverable and all attempts to claim the funds will result in a revert.


## Tools Used
Manual Review

## Recommended Mitigation Steps
Use `call` instead of `transfer` for native currency transfers. Call forwards all gas and receive functions will not be limited by 2300 gas. Make a note that call does not revert if the call fails, instead it returns a boolean and return data.
