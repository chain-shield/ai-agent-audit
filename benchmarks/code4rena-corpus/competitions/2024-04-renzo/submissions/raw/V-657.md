# Vulnerability details

## Impact
Missing circuit breaker checks in `RenzoOracle.sol::lookupTokenValue()` for Chainlink's price feed. Without such a mechanism, the contract could operate based on incorrect prices, which could lead to an over- or under-representation of the asset's value, potentially causing significant harm to the protocol.


## Proof of Concept
The return values from latestRoundData() are validated as such:
[RenzoOracle.sol::line71-81](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L71-L81)
```js
    function lookupTokenValue(IERC20 _token, uint256 _balance) public view returns (uint256) {
        AggregatorV3Interface oracle = tokenOracleLookup[_token];
        if (address(oracle) == address(0x0)) revert OracleNotFound();


        (, int256 price, , uint256 timestamp, ) = oracle.latestRoundData();
        if (timestamp < block.timestamp - MAX_TIME_WINDOW) revert OraclePriceExpired();
        if (price <= 0) revert InvalidOraclePrice();


        // Price is times 10**18 ensure value amount is scaled
        return (uint256(price) * _balance) / SCALE_FACTOR;
    }
```
As seen from above, there is no check to ensure that price does not go below or above a certain price. Chainlink aggregators have a built in circuit breaker if the price of an asset goes outside of a predetermined price band. Theresore, if the `_token's` market price plummets below `minAnswer` or skyrockets above `maxAnswer`, the returned price will still be `minAnswer` or `maxAnswer`, respectively, rather than the actual market price. This could potentially lead to an exploitation scenario where the protocol interacts with the `_token` using incorrect price information.

This is problematic as `lookupTokenValue()` used to determine the price of the `_collateralTokens` and calculate total and individual operator's `tvls`.

Furthermore, `_collateralToken's` price is used to calculate the amount of `ezETH` to mint to users whenever they call `deposit()`:
[RestakeManager.sol::L507](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L507)

```js
        uint256 collateralTokenValue = renzoOracle.lookupTokenValue(_collateralToken, _amount);
```

If `_collateralToken` experiences a flash crash, `lookupTokenValue` will return a price higher than the actual price of `_collateralToken`. Should this occur, an attacker can call `deposit()` to receive a huge amount of `ezEth` as it uses an incorrect `_collateralToken` price.

This would lead to a loss of funds for previous depositors, as the attacker would hold a majority of `ezEth's` total supply and can withdraw most of the protocol's TVL.

## Recommended Mitigation Steps
Consider validating that the price returned by Chainlink's price feed does not go below/above a minimum/maximum price:
This ensures that an incorrect price will never be used should `_collateralToken` experience a flash crash, thereby protecting the assets of existing depositors.
