# Vulnerability details

## Impact
The `lookupTokenValue` function in the RenzoOracle contract uses the `OraclePriceExpired()` and `InvalidOraclePrice()` error codes to handle certain oracle-related issues. However, it does not have a comprehensive mechanism to gracefully handle all potential oracle reverts. If the oracle unexpectedly reverts or returns invalid data, it could lead to a Denial-of-Service situation, disrupting the protocol's functionality.


## Proof of Concept
The Chainlink oracle used by the RenzoOracle contract experiences an unexpected issue, causing it to revert or return invalid data when the `latestRoundData()` function is called. As a result, the `lookupTokenValue` function in the RenzoOracle contract consistently reverts, making it impossible for users to retrieve token prices. Alice attempts to interact with the protocol that relies on the RenzoOracle contract, but her transactions consistently fail due to the oracle reverts. This leads to a Denial-of-Service situation, preventing Alice and other users from using the protocol's functionality.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a more robust error handling mechanism to gracefully handle potential oracle reverts. This could include using try-catch blocks to catch and handle specific oracle errors, implementing fallback mechanisms such as using alternative price feeds or default values when the primary oracle fails, and providing meaningful error messages to users when oracle-related issues occur.
