# Vulnerability details

## Impact
The `OptimismMintableXERC20` contract lacks proper contract initialization, there is no import from openzeppelin initialize which violates the principles of the upgradeable pattern and may lead to unexpected behavior as contract will not be initializable.

## Proof of Concept
While the function is meant to be initializable  it is not inheriting from openzeppelin initializable.

Although `OptimismMintableXERC20` inherits from `XERC20`, which implements Initializable, the contract itself does not directly initialize its state variables.

To ensure proper contract initialization according to the upgradeable pattern, 

Each upgradeable contract should implement the initialize function from `Initializable`. Which initializes the contract's state variables when it is deployed or upgraded.

```javascript
contract OptimismMintableXERC20 is ERC165Upgradeable, XERC20, IOptimismMintableERC20 {
    // Contract code...
}
```

import { Initializable } from "@openzeppelin/contracts-upgradeable/proxy/utils/Initializable.sol";
