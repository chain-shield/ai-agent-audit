# Vulnerability details

## Impact
The `sweepERC20` function in the `DepositQueue` contract ignores the return value of the `token.approve(address(restakeManager), balance - feeAmount)` call.

By ignoring the return value of the approve function call, the contract is unable to verify if the approval was successful. This could lead to issues if the approval fails, as the protocol might not be able to deposit the rewards into the `RestakeManager` contract as intended.

## Proof of Concept
The admin, who has the `ERC20RewardsAdmin` privileges, obtains control of an ERC20 token that the `DepositQueue` contract is designed to sweep.

The admin calls the approve function on the ERC20 token, attempting to grant the `DepositQueue` contract approval to transfer a large amount of tokens (e.g., the maximum uint256 value).

The admin calls the `sweepERC20` function on the `DepositQueue` contract, passing in the ERC20 token that they control.

The `sweepERC20` function calls `token.approve(address(restakeManager), balance - feeAmount)`, but ignores the return value of this call. If the call fails for any reason(e.g. network congestion) the function will still proceed to the next steps.

Since the approval failed, the subsequent call to `restakeManager.depositTokenRewardsFromProtocol(token, balance - feeAmount)` will also fail, preventing the protocol from depositing the rewards as intended.

By preventing the protocol from depositing the rewards, this vulnerability can disrupt the overall functionality of the protocol and potentially impact the users' ability to interact with the system.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Update the `sweepERC20` function to check the return value of the approve call and handle any failures appropriately, such as by reverting the transaction or logging an error.

Consider using the recommended `OpenZeppelin SafeERC20` library to handle ERC20 token interactions, which provides a safe wrapper around the approve function and checks the return value.
