# Vulnerability details


## Impact

Fees are taken twice from users, bypassing the 1% limit for fees.

## Proof of Concept

During the deposit workflow in `xRenzoDeposit`, fees are taken twice.

The [first fee is taken in `xRenzoDeposit._deposit`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L232-L236).
The [second fee is taken in `xRenzoDeposit._trade`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Bridge/L2/xRenzoDeposit.sol#L385-L388) even if no trade is made.

```solidity
    function _deposit(
        uint256 _amountIn,
        uint256 _minOut,
        uint256 _deadline
    ) internal returns (uint256) {
        // calculate bridgeFee for deposit amount
        uint256 bridgeFee = getBridgeFeeShare(_amountIn);
        // subtract from _amountIn and add to bridgeFeeCollected
        _amountIn -= bridgeFee;// @POC: First fee taken
        bridgeFeeCollected += bridgeFee;

        // Trade deposit tokens for nextWETH
        uint256 amountOut = _trade(_amountIn, _deadline);
        if (amountOut == 0) {
            revert InvalidZeroOutput();
        }

        // ...
    }


    function _trade(uint256 _amountIn, uint256 _deadline) internal returns (uint256) {
        // ...

        // Subtract the bridge router fee
        if (bridgeRouterFeeBps > 0) {
            uint256 fee = (amountNextWETH * bridgeRouterFeeBps) / 10_000;
            amountNextWETH -= fee;// @POC: Second fee taken
        }

        return amountNextWETH;
    }
```

## Tools Used
Manual review

## Recommended Mitigation Steps

Consider deleting one of these two fees or charging a fee on trade if and only if a trade is executed.
