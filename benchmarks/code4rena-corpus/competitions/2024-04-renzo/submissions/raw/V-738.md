# Vulnerability details

When creating a `withdrawRequest ` a struct is created with the necessary information to be used when claiming, 
```solidity
   withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem,
                _amount,
                block.timestamp
            )
        );
```
This struct contains information such as the `_assetOut` `withdrawRequesutNonce` `amountToRedeem` _`amount` `block.timestamp`. 
The issue here is that when claiming the request creation time wasn't assigned to `createdAt` which is used to compare the cool down 
```solidity
if (block.timestamp - _withdrawRequest.createdAt < coolDownPeriod) revert EarlyClaim();
```
`createdAt` will default to zero allowing user withdraw immediately after the creation of withdraw request.

## Impact
Users are able to bypass coolDown allowing them to withdraw at anytime.

## Proof of Concept
Users that want to withdraw calls `witdraw` in the `witdrawQueue` contract which creates a withdrawal index for the user with a struct containing the time of creation which will later be used to compare the cool down, however the `block.timestamp` when the request index is created is not assigned to `createdAt`, the struct saves the time with the default `block.timestamp` .

```solidity
   withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem,
                _amount,
                block.timestamp
            )
        );
```
But when `claim` is called it compares the time with `createdAt` which doesn't belong in the struct and is effectively zero allowing the bypass of the cool down period
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts%2FWithdraw%2FWithdrawQueue.sol#L287
```solidity
if (block.timestamp - _withdrawRequest.createdAt < coolDownPeriod) revert EarlyClaim();
```
 because `createdAt` is zero, while `block.timestamp` will always be greater than `coolDownPeriod` 
```solidity
if (block.timestamp  < coolDownPeriod) revert EarlyClaim();
```
`createdAt` is zero, the cooldown period effectively gets bypassed, allowing users to withdraw immediately without waiting for any cooldown period.

## Recommended Mitigation Steps
Assign `createdAt` to `block.timestamp` when the withdraw Request is created.
