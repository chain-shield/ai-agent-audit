# Vulnerability details

## Impact
The contract `OperatorDelegator` is designed to interact with Eigenlayer, with the intention that only the `RestakeManager` should be allowed to interact with it.
```
/// Only the RestakeManager should be interacting with this contract for EL interactions.
``` 

```javascript
/// @dev Allows only the RestakeManager address to call functions
    modifier onlyRestakeManager() {
        if (msg.sender != address(restakeManager)) revert NotRestakeManager();
        _;
    }
```

However, there is a lack of explicit access control in the initialize function, which poses a risk of unauthorized access during initialization.

Without proper access control, there is a potential for unauthorized parties to interact with the contract during initialization. This could lead to unexpected changes in the contract state or exploitation of sensitive functions, jeopardizing the security and integrity of the system.

## Proof of Concept
Consider the initialize function:

```javascript
function initialize(
    IRoleManager _roleManager,
    IStrategyManager _strategyManager,
    IRestakeManager _restakeManager,
    IDelegationManager _delegationManager,
    IEigenPodManager _eigenPodManager
) external initializer {
    // No access control implemented
    // Risk of unauthorized access during initialization
    
}

## Recommended Mitigation Steps
Implement access control in the initialize function to restrict access to authorized accounts only in our case `onlyRestakeManager`. This ensures that only designated entities, such as the RestakeManager, can interact with the contract during initialization, mitigating the risk of unauthorized access and potential exploits.

```javascript
function initialize(
        IRoleManager _roleManager,
        IStrategyManager _strategyManager,
        IRestakeManager _restakeManager,
        IDelegationManager _delegationManager,
        IEigenPodManager _eigenPodManager
    ) external initializer `onlyRestakeManager` {
```
