# Vulnerability details

## Impact
Validators could be staked using duplicated signatures

## Proof of Concept
Staking multiple validators in stakeEthFromQueueMulti does not check for duplicate signatures across validators. This allows the same signature to be reused for different pubkeys.

Steps to Reproduce

Call stakeEthFromQueueMulti with:

An array of 2 different operatorDelegator addresses
2 different pubkey values
An array of 2 identical signature values
2 depositDataRoot values
The contract will stake both validators without error, reusing the same signature for both pubkeys



## Tools Used
Manual review

## Recommended Mitigation Steps
The contract should check that each signature in the array is unique and reject the transaction if a duplicate is found. Signatures should have a 1-to-1 mapping with pubkeys.
