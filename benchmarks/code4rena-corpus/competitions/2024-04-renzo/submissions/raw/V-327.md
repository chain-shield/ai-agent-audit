# Vulnerability details

`xRenzoDeposit::sweep` function will take the balance of nextWETH in the contract and bridge it down to the L1. The L1 contract will unwrap, deposit in Renzo, and lock up the ezETH in the lockbox on L1. This function should only be callable by permissioned accounts. The caller will estimate and pay the gas for the bridge call

Within that function `xRenzoDeposit::_recoverBridgeFee()` is called to send collected bridge fee to sweeper. The whole function will never work because within the `xRenzoDeposit` contract, it converts Ether to WETH whenever user deposit ether. It also accepts the deposit of other ERC20 tokens.

Within the deposits function the internal function `xRenzoDeposit::_deposit` is called, which calls the `xRenzoDeposit::getBridgeFeeShare`. All the assets deposited are not in their native tokens. Meaning this contract `balanceBefore` will always be 0. 
```solidity
    function _recoverBridgeFee() internal {
        uint256 feeCollected = bridgeFeeCollected; //@audit-issue not in Ether
        bridgeFeeCollected = 0;
        // transfer collected fee to bridgeSweeper
        uint256 balanceBefore = address(this).balance; // will always be 0
        IWeth(address(depositToken)).withdraw(feeCollected);
        feeCollected = address(this).balance - balanceBefore;
        (bool success, ) = payable(msg.sender).call{ value: feeCollected }("");
        if (!success) revert TransferFailed();
        emit SweeperBridgeFeeCollected(msg.sender, feeCollected);
    }
```
        
## Impact
Excess bridge fee will in contract and not be collected by the sweeper.
