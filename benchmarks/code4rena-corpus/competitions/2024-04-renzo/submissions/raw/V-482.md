# Vulnerability details

## Impact
In the `setTokenTvlLimit` function of the `RestakeManager` contract, there's a section of code where the TVL limit for a collateral token is set. However, there's a potential issue where the TVL limit `_limit` can be set to `zero (0)`. Setting the TVL limit to zero could lead to unintended consequences, such as effectively disabling deposits for the specified token or causing unexpected behavior in the protocol's TVL management.

If the `collateralTokenTvlLimits[_token]` is unintentionally set to zero, it could result in the affected collateral token being effectively disabled for deposits, which could disrupt the protocol's operations and user experience. Additionally, it might lead to confusion among users and other stakeholders regarding the functionality of the protocol.
## Proof of Concept
See the following code:

```
function setTokenTvlLimit(IERC20 _token, uint256 _limit) external onlyRestakeManagerAdmin {
        // Verify collateral token is in the list - call will revert if not found
        getCollateralTokenIndex(_token);

        // Set the limit
        collateralTokenTvlLimits[_token] = _limit;

        emit CollateralTokenTvlUpdated(_token, _limit);
    }
```

## Tools Used
Manual Review
## Recommended Mitigation Steps
It's essential to implement a check to ensure that the `_limit` is not zero (0) when calling the setTokenTvlLimit function.
