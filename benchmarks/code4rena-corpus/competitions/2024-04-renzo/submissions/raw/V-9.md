# Vulnerability details

## Impact
The use of ERC20 `transfer()` in the `WithdrawQueue` contract can result in potential loss of funds and transaction reversion. Some tokens do not fully comply with the ERC20 standard and their `transfer()` function may not return a boolean value, causing the call to revert. This can lead to a denial of service and loss of funds for users who are trying to withdraw tokens.

## Proof of Concept
The vulnerable code is located in the `claim()` function of the `WithdrawQueue` contract at lines 305-308 in the file `contracts/Withdraw/WithdrawQueue.sol`. The code uses the `transfer()` function to send tokens to the user.

A specific example of a token that does not return a boolean value in its `transfer()` function is Tether (USDT) on L1. If a user tries to withdraw USDT from the `WithdrawQueue` contract, the transaction will revert and the user will not receive their funds.

## Tools Used
Manual Review

## Recommended Mitigation Steps
To mitigate this vulnerability, it is recommended to use OpenZeppelin's `SafeERC20` library and replace the `transfer()` function with `safeTransfer()`. This will add a require statement to check the return value of the transfer and ensure that the transfer was successful. This change will prevent any unexpected behavior and ensure that users can safely withdraw their tokens.
