# Vulnerability details

## Impact
Not incrementing `withdrawRequestNonce` parameter under `WithdrawQueue.withdraw` function can lead to dos.

## Proof of Concept
`WithdrawQueue.withdraw` creates a withdraw request for user. In certain cases this function could be called with the same `withdrawRequestNonce` and makes the function prone to DOS attack.
As we can see in the below code snippet,
```solidity
WithdrawQueue.sol#L235-L250
 // revert if amount to redeem is greater than withdrawBufferTarget
        if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();

        // increment the withdrawRequestNonce
        withdrawRequestNonce++;

        // add withdraw request for msg.sender
        withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem,
                _amount,
                block.timestamp
            )
        );
```
`withdrawRequestNonce` parameter get updated after checking the if condition make it to true, but if it get false the `withdrawRequestNonce` would not get updated which makes the same user to call the function again n again that leads to a situation of dos, hence the function get dos and the withdrawRequestNonce will never get updated therefore users will unable to claim withdraw request that makes the claim function always revert due to a condition that checks if the withdrawRequestIndex is greater than the length but due to not updated `withdrawRequestNonce` it makes the claim function always revert.
https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L281
```solidity
WithdrawQueue.sol#L281
if (withdrawRequestIndex >= withdrawRequests[msg.sender].length)
            revert InvalidWithdrawIndex();
```

## Tools Used
Manual

## Recommended Mitigation Steps
Increment `withdrawRequestNonce` before checking if condition.
```diff
- if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();
- withdrawRequestNonce++;

+ withdrawRequestNonce++;
+ if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();
```









## Assessed type

DoS
