# Vulnerability details

## Impact
When calling `OperatorDelegator::completeQueuedWithdrawal()` if any of the token's passed into the function have a balance of 0 for the `OperatorDelegator.sol` contract and there is a buffer to fill, then `fillERC20WithdrawBuffer()` will be called passing a `0` amount, which will revert the whole queue withdrawal transaction.

## Proof of Concept
[OperatorDelegator.sol#L289-L303](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L289-L303)
```solidity
                uint256 balanceOfToken = tokens[i].balanceOf(address(this));
                if (bufferToFill > 0) {
                    bufferToFill = (balanceOfToken <= bufferToFill) ? balanceOfToken : bufferToFill;

                    // update amount to send to the operator Delegator
                    balanceOfToken -= bufferToFill;

                    // safe Approve for depositQueue
                    tokens[i].safeApprove(address(restakeManager.depositQueue()), bufferToFill);

                    // fill Withdraw Buffer via depositQueue
                    restakeManager.depositQueue().fillERC20withdrawBuffer(
                        address(tokens[i]),
                        bufferToFill
                    );
```
If `fillERC20withdrawBuffer()` is called where the `tokens` array contains a token that the `OperatorDelegator.sol` contract has no balance for, and there is a buffer to fill for the token then:
```solidity
restakeManager.depositQueue().fillERC20withdrawBuffer(address(tokens[i]),bufferToFill);
```
This will be called with `bufferToFill = 0`, which will lead to the whole transaction being reverted:
[DepositQueue::fillERC20withdrawBuffer()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L134-L138)
```solidity
    function fillERC20withdrawBuffer(
        address _asset,
        uint256 _amount
    ) external nonReentrant onlyRestakeManager {
        if (_amount == 0 || _asset == address(0)) revert InvalidZeroInput();
```

## Recommended Mitigation Steps

Add a check for the case that `OperatorDelegator.sol` has a 0 balance of one of the passed tokens which will skip the current itteration of the for loop to avoid calling function with 0 values:

[OperatorDelegator::completeQueuedWithdrawal()](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L265-L314)
