# Vulnerability details

## Impact
The current implementation of the [`deposit`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L491-L576) and [`depositETH`](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L592-L616) functions in the `RestakeManager.sol` makes use of a stale `totalTVL` value when calculating the amount of `ezETH` to mint for a depositor. This stale value does not include the value of the assets being deposited in the current transaction. As a result, the amount of `ezETH` minted for the depositor may be less than what they are rightfully entitled to based on their contribution to the total pool. This can lead to discrepancies in token distribution, affecting the fairness and accuracy of the protocol's token economics.


As per the [README](https://github.com/code-423n4/2024-04-renzo/blob/main/README.md#main-invariants), 
> ezETH should be minted or redeemed based on current supply and TVL.

Hence, I marked this as High severity

### `calculateMintAmount` Function in `RenzoOracle.sol`
https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Oracle/RenzoOracle.sol#L123-L149

```solidity
function calculateMintAmount(
    uint256 _currentValueInProtocol,
    uint256 _newValueAdded,
    uint256 _existingEzETHSupply
) external pure returns (uint256) {
    if (_currentValueInProtocol == 0 || _existingEzETHSupply == 0) {
        return _newValueAdded;
    }

    uint256 inflationPercentage = (SCALE_FACTOR * _newValueAdded) / (_currentValueInProtocol + _newValueAdded);
    uint256 newEzETHSupply = (_existingEzETHSupply * SCALE_FACTOR) / (SCALE_FACTOR - inflationPercentage);
    uint256 mintAmount = newEzETHSupply - _existingEzETHSupply;

    if (mintAmount == 0) revert InvalidTokenAmount();

    return mintAmount;
}
```

Assume the `totalTVL` before a deposit is 1,000 ETH. A user deposits an additional 100 ETH worth of a collateral token. The `calculateMintAmount` function uses the old `totalTVL` (1,000 ETH) instead of the updated `totalTVL` (1,100 ETH). This results in fewer `ezETH` being minted than should be, as the calculation underestimates the depositor's share of the total pool.

## Recommended Mitigation Steps
The `totalTVL` should be updated to include the value of the current deposit before the minting calculation is performed so as to ensure that the minting of `ezETH` accurately reflects the depositor's contribution relative to the total value locked in the system after their deposit. Here is a proposed change in the `deposit` function:

```diff
+       // Update the total TVL to include the current deposit
+       uint256 updatedTotalTVL = totalTVL + collateralTokenValue;



         // Calculate how much ezETH to mint
         uint256 ezETHToMint = renzoOracle.calculateMintAmount(
+        updatedTotalTVL,
         collateralTokenValue,
          ezETH.totalSupply()
        );
```
