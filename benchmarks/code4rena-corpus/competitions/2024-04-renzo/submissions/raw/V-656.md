# Vulnerability details

## Impact
Permanent loss of user funds if users deposit ERC20 tokens into the contract and then attempt to withdraw them using the withdraw function. 

## Proof of Concept
The withdraw and _withdraw functions in the XERC20Lockbox contract do not have a mechanism to distinguish between the native tokens and the non-native ERC20 tokens deposited by a user. 

As a result, when a user attempts to withdraw tokens using the withdraw function, the contract will always burn the user's XERC20 tokens, regardless of whether the user had deposited native tokens or ERC20 tokens.

Specifically, in the _withdraw function:

```
 function _withdraw(address _to, uint256 _amount) internal {
        emit Withdraw(_to, _amount);

        XERC20.burn(msg.sender, _amount);

        if (IS_NATIVE) {
            (bool _success, ) = payable(_to).call{ value: _amount }("");
            if (!_success) revert IXERC20Lockbox_WithdrawFailed();
        } else {
            ERC20.safeTransfer(_to, _amount);
        }
    }

```
The function always burns the XERC20 tokens from the msg.sender for the specified _amount, even if the user had previously deposited ERC20 tokens using the deposit function.

If the user tries to withdraw their previously deposited ERC20 tokens, the contract will burn their XERC20 tokens without transferring the ERC20 tokens back to the user, effectively preventing the withdrawal of deposited ERC20 tokens.

Note that IS_NATIVE would have been set to true in the initialize function:

```
 function initialize(address _xerc20, address _erc20, bool _isNative) public initializer {
        XERC20 = IXERC20(_xerc20);
        ERC20 = IERC20(_erc20);
        IS_NATIVE = _isNative;
    }
```

So, when the withdraw function is called to withdraw back the deposited erc20 tokens and burn the minted XERC20 tokens, XERC20 tokens will be burnt and the if block below will run without getting to the else block:

```
if (IS_NATIVE) {
            (bool _success, ) = payable(_to).call{ value: _amount }("");
            if (!_success) revert IXERC20Lockbox_WithdrawFailed();
        } else {
            ERC20.safeTransfer(_to, _amount);
        }
```

Also note that there is no way of distinguishing between a native token and a non-native token.

## Tools Used
Manual review

## Recommended Mitigation Steps

To address this issue, the contract should maintain separate balances or mappings for the native tokens and the non-native ERC20 tokens deposited by each user. The withdraw and _withdraw functions should use these separate balances or mappings to determine which token the user intends to withdraw and perform the appropriate token transfer or burn operation.

Alternatively, the contract could have separate withdrawal functions for the native tokens and the non-native ERC20 tokens, ensuring that the correct token is withdrawn based on the function called by the user.
