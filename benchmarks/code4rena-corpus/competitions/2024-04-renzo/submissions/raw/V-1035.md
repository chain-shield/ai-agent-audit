# Vulnerability details

## Impact 
Loss of monetary value for protocol as they miss out on all USDB, WETH, GAS yields

## Proof of Concept

First would be key to note that existing L2s like Optimism and Arbitrum keep sequencer fees for themselves, but Blast redirects sequencer fees to the dapps that induced them, allowing smart contract developers to have an additional source of revenue. In order to claim gas fees, a contract must set its gas mode to Claimable, asides the native gas fees, Blast also has the USDB/WETH yields that it supplies to, however Renzo fails to configure any of these yields as claimable for all its contracts/modules to be deployed on blast resulting in a loss of revenue for the protocol.

Now from the readMe, this has been stated https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/README.md#L298-L306

```markdown

| Chains the protocol will be deployed on | Ethereum Mainnet <br> L2-Specific-contracts deployed on: Base, Arbitrum, Linea, BSC, Mode <br> xERC20 only: Blast |
```

Evidently, protocol plans on deploying to the blast network, i.e the `xERC20.sol` contract, would be key to note that despite not been written the OptimismMintableXERC20 (xezETH contract on Blast) is also to be used in Blast, however no yield is configured as claimable for any of these contracts for the network as can be seen in https://github.com/code-423n4/2024-04-renzo/blob/1c7cc4e632564349b204b4b5e5f494c9b0bc631d/contracts/Bridge/xERC20/contracts/XERC20.sol#L16-L359, from the Gas, Weth & USDB, which then means that protocol would miss out on the redirected fees from the sequencer and any yield whatsoever.

## Recommendation

This report is trying to hint that there should be like an implementation of say a `BlastXGas` contract which can then be inherited on the contracts to be deployed in Blast so as to get access to the yield... the XERC20, however does not implement this, i.e `contract XERC20 is XX, BlastGas {`

So consider creating a contract like the below and inheriting within the xERC20 & OptimismMintableXERC20 (xezETH contract on Blast) , and potentially any other contract that's to get deployed on blast in the future.

```solidity
abstract contract BlastGas {

    constructor(address parent_) {
      IBlast(0x029290c564Ef921c56a784AA16C97E930dAF7372).configureClaimableGas();
        IBlast(0x029290c564Ef921c56a784AA16C97E930dAF7372).configureGovernor(parent_);
        //Then do the same for the USDB/WETH addresses
    }
}
```

So the idea would be to set the parent* as the governor and then claim the rewards via the parent*. Note that inorder to claim the gas rewards, one must first configure the rewards to be claimable. This must be done so the rewards can be claimed for the modules.

Now do note that for the USDB/WETH, unlike ETH where contracts have `Disabled` yield by default, WETH and USDB accounts have `Automatic yield` by default for both EOAs and smart contracts, so this also needs to be explicitly set as "YieldMode.CLAIMAIBLE" as seen in the offficial docs: https://docs.blast.io/building/guides/weth-yield .*******
