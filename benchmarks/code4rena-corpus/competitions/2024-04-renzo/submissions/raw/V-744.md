# Vulnerability details

## Impact
Mistakes made on one chain can be re-applied to a new chain

There is no `chain.id` in the data.

## Proof of Concept
The [deployXERC20()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/xERC20/contracts/XERC20Factory.sol#L74-L92) function in the `XERC20Factory` contract allows a user to deploy a new `XERC20` token with a specified `name, symbol, minter and burner limits, bridges, and a proxy admin address`.
```solidity
    function deployXERC20(
        string memory _name,
        string memory _symbol,
        uint256[] memory _minterLimits,
        uint256[] memory _burnerLimits,
        address[] memory _bridges,
        address _proxyAdmin
    ) external returns (address _xerc20) {
        _xerc20 = _deployXERC20(
            _name,
            _symbol,
            _minterLimits,
            _burnerLimits,
            _bridges,
            _proxyAdmin
        );
```
This calls [_deployXERC20()]() internally.
```solidity
function _deployXERC20(
    string memory _name,
    string memory _symbol,
    address _proxyAdmin
) internal returns (address _xerc20) {
    // Generate a salt for deterministic deployment
    bytes32 _salt = keccak256(abi.encodePacked(_name, _symbol, msg.sender));

    // Deploy the XERC20 token using CREATE3 and the salt
    _xerc20 = CREATE3.deploy(_salt, /* deployment bytecode */, 0);

    // Transfer ownership to the deployer
    XERC20(_xerc20).transferOwnership(msg.sender);

    return _xerc20;
}
```
Without including the chain ID in the salt used for `CREATE3`, the same parameters (token name, symbol, and sender address) on different chains could generate the same salt and, consequently, the same deterministic address for the `XERC20` token.

```solidity
// Generate a salt for deterministic deployment
    bytes32 _salt = keccak256(abi.encodePacked(_name, _symbol, msg.sender));
```
If a user does `deployXERC20` using the wrong network, an attacker can replay the action on the correct chain, and steal the funds via the `wintermute` gnosis safe attack, where the attacker can create the same address that the user tried to, and steal the funds from there.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Include the chain ID, `chain.id` in the salt calculation to ensure that the address generated by `CREATE3` is unique per chain.
