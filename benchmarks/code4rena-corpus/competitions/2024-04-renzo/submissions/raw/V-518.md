# Vulnerability details

## Vulnerability Details 

The function _deposit is to mint xezETH tokens based on the current price of ezETH obtained from a price oracle. and this is critical part of this function that  checks if the price data is older than one day:
```solidity
(uint256 _lastPrice, uint256 _lastPriceTimestamp) = getMintRate();

if (block.timestamp > _lastPriceTimestamp + 1 days) {
    revert OraclePriceExpired();
}
```
This check to ensure that the price data used for minting the tokens is not stale., given the high volatility of cryptocurrency markets, even a day-old price can be significantly outdated, leading to substantial financial discrepancies in the minting process.

## The Root Of the bug :
The root cause of the vulnerability is the inadequate handling of the price data freshness in a highly volatile market environment. The 24-hour threshold for price staleness is too lenient for cryptocurrency standards.

## Impact
The reliance on stale price data can lead Users can receive more or fewer tokens than they should based on the true current market value of the deposited assets. leading to financial loss

def _trade(amount_in, deadline):
    # Assuming a 1:1 trade for simplicity
    return amount_in

def getMintRate():
    return (lastPrice, lastPriceTimestamp)

# Main function to test
def _deposit(amount_in, min_out, deadline):
    global bridgeFeeCollected, lastPrice, lastPriceTimestamp

    # Calculate bridge fee
    bridge_fee = getBridgeFeeShare(amount_in)
    amount_in -= bridge_fee
    bridgeFeeCollected += bridge_fee

    # Trade tokens
    amount_out = _trade(amount_in, deadline)

        raise Exception("InvalidZeroOutput")

    if time.time() > _last_price_timestamp + DAY_IN_SECONDS:
        raise Exception("OraclePriceExpired")
