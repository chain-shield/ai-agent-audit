# Vulnerability details

## Impact
The `queueWithdrawals` function in the `OperatorDelegator` contract contains an unbounded loop that iterates through the entire array of tokens and token amounts. If the array is large, it can consume a significant amount of gas, which can lead to a Denial-of-Service (DoS) condition.

An attacker can provide a large array of tokens and token amounts when calling the `queueWithdrawals` function, causing the transaction to consume an excessive amount of gas. This can result in the transaction exceeding the block gas limit and reverting, making the contract unusable or blocking other transactions from being processed. As a result, the protocol's functionality and availability can be disrupted.

## Proof of Concept
Bob, the attacker, creates a very large array of tokens and `tokenAmounts`.

Bob calls the `queueWithdrawals` function with the large array, causing the transaction to consume a large amount of gas and potentially exceed the block gas limit.

The transaction reverts, making the contract unusable or blocking other users, from successfully calling the `queueWithdrawals` function.

## Recommended Mitigation Steps
Consider implementing pagination or batching mechanisms to limit the number of tokens and token amounts processed in a single transaction. This can be achieved by accepting a maximum limit parameter and processing the tokens in smaller batches. Additionally, consider implementing gas optimization techniques to reduce the gas consumption of the `queueWithdrawals` function.
