# Vulnerability details

## Summary
When depositing `ERC20 collateral token` into the protocol via `deposit()` to mint `ezETH`, the function verifies that the collateral token is in the list otherwise the call will revert if not found. However `depositTokenRewardsFromProtocol()` does not verify if the `ERC20 token rewards` from the Deposit Queue is in the list.

## Proof of Concept
> [deposit()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L496-L497)
This is the relevant part of the function:
```solidity
        // Verify collateral token is in the list - call will revert if not found
        uint256 tokenIndex = getCollateralTokenIndex(_collateralToken);
```
This calls [getCollateralTokenIndex()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L449-L465) which finds the index of the collateral token in the list.
```solidity
    /// @dev Finds the index of the collateral token in the list
    /// Reverts if the token is not found in the list
    function getCollateralTokenIndex(IERC20 _collateralToken) public view returns (uint256) {
        // Find the token index
        uint256 tokenLength = collateralTokens.length;
        for (uint256 i = 0; i < tokenLength; ) {
            if (collateralTokens[i] == _collateralToken) {
                return i;
            }


            unchecked {
                ++i;
            }
        }


        revert NotFound();
    }
```
This check ensures that only accepted `ERC20` tokens can be deposited in the protocol.

However, the [depositTokenRewardsFromProtocol()](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/RestakeManager.sol#L645-L668) does not verify if the ERC20 token rewards from the Deposit Queue is in the list.
```solidity
    /// @dev Deposit ERC20 token rewards from the Deposit Queue
    /// Only callable by the deposit queue
    function depositTokenRewardsFromProtocol(
        IERC20 _token,
        uint256 _amount
    ) external onlyDepositQueue {
        //...

        // @audit no validation for tokens

        // Transfer the tokens to this address
        _token.safeTransferFrom(msg.sender, address(this), _amount);

        //...
    }
```

## Impact
Without the check, unwhitelisted `ERC20` tokens maybe deposited into the protocol.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Enforce a check to verify that the incoming `ERC20 tokens` actually exist in the list and revert otherwise.

```solidity
    /// @dev Deposit ERC20 token rewards from the Deposit Queue
    /// Only callable by the deposit queue
    function depositTokenRewardsFromProtocol(
        IERC20 _token,
        uint256 _amount
    ) external onlyDepositQueue {
        //...

        // @audit Verify collateral token is in the list - call will revert if not found
        uint256 tokenIndex = getCollateralTokenIndex(_token);

        // Transfer the tokens to this address
        _token.safeTransferFrom(msg.sender, address(this), _amount);

        //...
    }
```
