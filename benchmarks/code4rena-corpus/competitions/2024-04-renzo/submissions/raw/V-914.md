# Vulnerability details

## Impact
Incorrect calculation of the total tvl of the protocol, leading to too much or too little ezETH or assets received.

## Proof of Concept
In `RestakeManager::calculateTVLs()`, the balance of the withdrawal queue for each token is calculated:
```solidity
function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
...
if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[i], //@audit this should be j
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }
...
}
```
As can be seen it selects `collateralTokens[i]` to get the price of the respective balance, which is incorrect and index `j` should be used.

## Tools Used

Vscode

## Recommended Mitigation Steps

Change `RestakeManager::calculateTVLs()` to accomodate the correct index, as follows: 
```solidity
function calculateTVLs() public view returns (uint256[][] memory, uint256[] memory, uint256) {
...
if (!withdrawQueueTokenBalanceRecorded) {
                    totalWithdrawalQueueValue += renzoOracle.lookupTokenValue(
                        collateralTokens[j], //@audit this should be j
                        collateralTokens[j].balanceOf(withdrawQueue)
                    );
                }
...
}
```
