# Vulnerability details

## Description
A user can initiate a withdraw by calling the `withdraw()` function:
[WithdrawQueue.sol#L206-L263](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L206-L263)
```javascript
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
//..
}
```

In this function, the user transfers their `ezETH` to the `WithdrawQueue.sol` contract and populates the `withdrawRequests` with their `WithdrawRequest`:
[WithdrawQueue.sol#L242-L250](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Withdraw/WithdrawQueue.sol#L242-L250)
```javascript
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
//..
       withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem,
                _amount,
                block.timestamp
            )
        );
//..
}
```
The problem is that the user will lose rewards due to the minimum waiting period time not being accounted for.
## Proof of Concept
Let:
- `Alice` holds `1000e18 ezETH`
- `Alice` calls `withdraw(1000 ezETH, nativeETH)`
- The `amountToRedeem` gets calculated, that's what `Alice` will receive:
```javascript
uint256 amountToRedeem = renzoOracle.calculateRedeemAmount(
	_amount,
	ezETH.totalSupply(),
	totalTVL
);
```
- Let's assume `amountToRedeem` is some arbitrary value `X`
- Given that `ezETH` is reward bearing and given that the withdraw period is **at minimum 7 days**, the `amountToRedeem` of `Alice` should be `X + min_7_days_rewards`, especially since the `withdraw()` function does not modify any balances except the transfer from `Alice` to `WithdrawQueue.sol`.
- 30 days have passed, `Alice` calls `claim()` to complete her withdraw, missing out on `30 days` of rewards.
