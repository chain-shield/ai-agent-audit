# Vulnerability details

## Impact
The lack of nonce verification exposes the withdrawal mechanism to replay attacks. An attacker could repeatedly submit the same withdrawal request with the same nonce, resulting in duplicate or unauthorized withdrawals.


## Proof of Concept
The contract maintains a `withdrawRequestNonce` variable to track the number of withdrawal requests created. However, it lacks a mechanism to verify the uniqueness of each nonce, leaving the withdrawal requests vulnerable to replay attacks.

In the withdraw function, a new withdrawal request is created, and the `withdrawRequestNonce` is incremented without any validation of whether the nonce has been used before. This means that an attacker could potentially replay a previous withdrawal request with the same nonce, leading to unintended consequences.
```solidity
// Incrementing withdrawRequestNonce without nonce verification
withdrawRequestNonce++;
```
## Tools Used
Manual
## Recommended Mitigation Steps
Implement nonce verification to ensure the uniqueness of each withdrawal request nonce. Maintain a mapping of used nonces and check whether the nonce has been used before processing a new withdrawal request. By verifying nonces, the contract can prevent replay attacks and ensure the integrity of the withdrawal queue.

```solidity
// Implement nonce verification in the withdraw function
function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
    // Check if the nonce has been used before
    require(!usedNonces[msg.sender][withdrawRequestNonce], "Nonce already used");
    
    // Other code for withdrawal request creation
    
    // Mark the nonce as used
    usedNonces[msg.sender][withdrawRequestNonce] = true;

    // Increment withdrawRequestNonce
    withdrawRequestNonce++;
}

```
