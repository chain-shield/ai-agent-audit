# Vulnerability details

## Impact
When users deposit ETH using depositETH(), the RestakingManager fills the withdraw buffer using the deposit queue. The contracts use msg.value as the amount to be deposited, however no where is the msg.value amount checked. A user can send 0 eth repeatedly to fill the buffer causing the buffer to be filled with 0 eth deposits that will block the contract.

## Proof of Concept
Lets follow the sequence of execution. 

1. Attacker calls deposit() with 0 eth.
```
function depositETH() external payable {
        depositETH(0);
}
```

2. depositETH() calls depositETH(0) and depositETH(0) calls the deposit queue
```
    function depositETH(uint256 _referralId) public payable nonReentrant notPaused {
        // Get the total TVL
        (, , uint256 totalTVL) = calculateTVLs();

        // Enforce TVL limit if set
        if (maxDepositTVL != 0 && totalTVL + msg.value > maxDepositTVL) {
            revert MaxTVLReached();
        }

        // Deposit the remaining ETH into the DepositQueue
        depositQueue.depositETHFromProtocol{ value: msg.value }();

        // Calculate how much ezETH to mint
        uint256 ezETHToMint = renzoOracle.calculateMintAmount(
            totalTVL,
            msg.value,
            ezETH.totalSupply()
        );

        // Mint the ezETH
        ezETH.mint(msg.sender, ezETHToMint);

        // Emit the deposit event
        emit Deposit(msg.sender, IERC20(address(0x0)), msg.value, ezETHToMint, _referralId);
    }
```
Notice that so far none of the functions have performed a checked for msg.value == 0 and if no TVL limit is set the call will not revert.

3. The Deposit Queue function that fills the withdraw buffer looks like this 
```
    function _checkAndFillETHWithdrawBuffer(uint256 _amount) internal {
        // Check the withdraw buffer and fill if below buffer target
        uint256 bufferToFill = withdrawQueue.getBufferDeficit(IS_NATIVE);

        if (bufferToFill > 0) {
            bufferToFill = (_amount <= bufferToFill) ? _amount : bufferToFill;

            // fill withdraw buffer from received ETH
            withdrawQueue.fillEthWithdrawBuffer{ value: bufferToFill }();

            emit BufferFilled(IS_NATIVE, bufferToFill);
        }
    }
```
The only check so far is bufferToFill > 0 which will be true as long as no claims have been made.

4. Last step along the path is WihdrawQueue contarct.
```
    function fillEthWithdrawBuffer() external payable nonReentrant onlyDepositQueue {
        emit EthBufferFilled(msg.value);
    }
```
Which again lack 0 value check.
