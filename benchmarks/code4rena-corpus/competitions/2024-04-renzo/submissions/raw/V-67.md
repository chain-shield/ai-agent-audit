# Vulnerability details

## Impact
The `setDelegateAddress` function in the `OperatorDelegator` contract does not perform any signature verification on the provided `approverSignatureAndExpiry` and `approverSalt` parameters. While this function is restricted to the `OperatorDelegatorAdmin`, the lack of signature verification could still be indirectly exploited.

Although regular users cannot directly call the `setDelegateAddress` function due to the `onlyOperatorDelegatorAdmin` modifier, the lack of signature verification in this function could still be exploited indirectly.
Other functions in the protocol that rely on the `delegateAddress` and all future functions that will be added to the protocol that rely on the `delegateAddress`, an attacker could potentially exploit the vulnerability by:

Creating a malicious `delegateAddress` under their control.

Calling the `setDelegateAddress` function with the malicious `delegateAddress` and a forged `approverSignatureAndExpiry` and `approverSalt`.

Exploiting the other protocol functions that use the delegateAddress`, potentially performing unauthorized actions or draining funds.

## Proof of Concept

The attacker creates a malicious `delegateAddress` under their control.

The attacker calls the `setDelegateAddress` function, passing in the malicious `delegateAddress`, a forged `approverSignatureAndExpiry`, and a valid `approverSalt`.

Since the `setDelegateAddress` function does not verify the provided signature, it accepts the malicious `delegateAddress` as the new delegate address.
The attacker then calls other protocol functions that rely on the `delegateAddress` without proper access controls, performing unauthorized actions or draining funds.

## Recommended Mitigation Steps
Implement proper signature verification in the `OperatorDelegator::setDelegateAddress` function. Ensure that the signature is properly validated against the expected signer's address before setting the delegate address. Use a secure signature scheme and include necessary checks such as expiration time and nonce to prevent replay attacks.
