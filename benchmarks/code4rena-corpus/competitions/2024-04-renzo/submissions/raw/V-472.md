# Vulnerability details

## Impact

Stuck funds in the WithdrawQueue contract. Users will get lesser amount back than intended. It will also affect the TVL calculation.

## Proof of Concept

When withdrawing collateral, users must deposit their ezETH in exchange for the collateral they want, eg stETH. The function checks that they have enough collateral in the contract to exchange for the ezETH, and add to the withdrawRequest of the user.

The function transfers ezETH into the WithdrawQueue contract.

```
    function withdraw(uint256 _amount, address _assetOut) external nonReentrant {
        // check for 0 values
        if (_amount == 0 || _assetOut == address(0)) revert InvalidZeroInput();

        // check if provided assetOut is supported
        if (withdrawalBufferTarget[_assetOut] == 0) revert UnsupportedWithdrawAsset();

        // transfer ezETH tokens to this address
        IERC20(address(ezETH)).safeTransferFrom(msg.sender, address(this), _amount);

```

The function calculates the TVL and calculates the redeem amount in ETH.

```

        // calculate totalTVL
        (, , uint256 totalTVL) = restakeManager.calculateTVLs();

        // Calculate amount to Redeem in ETH
        uint256 amountToRedeem = renzoOracle.calculateRedeemAmount(
            _amount,
            ezETH.totalSupply(),
            totalTVL
        );
```

The function then converts the ETH amount to the collateral amount

```
        // update amount in claim asset, if claim asset is not ETH
        if (_assetOut != IS_NATIVE) {
            // Get ERC20 asset equivalent amount
            amountToRedeem = renzoOracle.lookupTokenAmountFromValue(
                IERC20(_assetOut),
                amountToRedeem
            );
        }

        // revert if amount to redeem is greater than withdrawBufferTarget
        if (amountToRedeem > getAvailableToWithdraw(_assetOut)) revert NotEnoughWithdrawBuffer();

```
The function lastly adds to the withdrawRequests.
```
        // increment the withdrawRequestNonce
        withdrawRequestNonce++;

        // add withdraw request for msg.sender
        withdrawRequests[msg.sender].push(
            WithdrawRequest(
                _assetOut,
                withdrawRequestNonce,
                amountToRedeem,
                _amount,
                block.timestamp
            )
        );

        // add redeem amount to claimReserve of claim asset
        claimReserve[_assetOut] += amountToRedeem;

        emit WithdrawRequestCreated(
            withdrawRequestNonce,
            msg.sender,
            _assetOut,
            amountToRedeem,
            _amount,
            withdrawRequests[msg.sender].length - 1
        );
    }
```

The user then waits for 7 days before they can claim their collateral amount.

The issue is that some LST are rebasing, meaning the amount of tokens goes up but the value doesn't. An example is stETH.

In the 7 days of waiting, the LST that is supposed to be withdrawn will go up in amount, but the user will not be able to withdraw this extra rebase for the 7 days.

For example, if a user intends to withdraw 10 stETH for x ezETH, he has to wait 7 days. In 7 days, 10 stETH will become 10.05 stETH, but the user can only claim 10 stETH, leaving 0.05 stETH stuck in the contract.

This extra funds will affect the calculation of the TVL since it also gets the value from the withdrawQueue as part of the total TVL.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Suggest performing the conversion calculation (collateral:ezETH) only when `claim()` is called, so that the full collateral amount will be given back.
