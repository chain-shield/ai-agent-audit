# Vulnerability details

## Impact
The `verifyWithdrawalCredentials` function in the `OperatorDelegator` contract handles a substantial number of withdrawal credentials and executes intricate operations on the given data. When dealing with extensive arrays of validator indices, withdrawal credential proofs, and validator fields, this process can demand a considerable amount of gas. This scenario may give rise to a Denial-of-Service (DoS) condition.

An admin can provide large arrays of validator indices, withdrawal credential proofs, and validator fields when calling the `verifyWithdrawalCredentials` function, causing the transaction to consume an excessive amount of gas. This can result in the transaction exceeding the block gas limit and reverting, making the contract unusable or preventing other transactions from being processed. As a result, the protocol's functionality and availability can be disrupted.

The Admin does not have to be malicious, an admin can be benevolent and still accidently trigger the Denial of service if the arrays added are large.


## Proof of Concept
The admin, who has the `NativeEthRestakeAdmin` privileges, creates large arrays of validator indices, withdrawal credential proofs, and validator fields.

The admin calls the `verifyWithdrawalCredentials` function with the large input arrays.
The unbounded loop in the function is triggered, consuming a significant amount of gas and potentially exceeding the block gas limit.

The transaction reverts, causing a Denial of Service condition and disrupting the protocol's functionality.

## Recommended Mitigation Steps
To manage the processing of a large number of withdrawal credentials efficiently, I recommended to implement pagination or batching mechanisms. These methods can help limit the number of credentials processed in a single transaction by accepting a maximum limit parameter and handling the credentials in smaller batches. Additionally, optimizing the gas consumption of the `verifyWithdrawalCredentials` function can be achieved by streamlining the operations performed on the provided data.
