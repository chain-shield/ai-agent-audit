# Vulnerability details

## Impact

The `TVL` is calculated less than the actual value. This may lead to loss of funds for users.

## Proof of Concept

The `OperatorDelegator.getTokenBalanceFromStrategy()` function returns the token balance of the `operatorDelegator`. It also includes the amount of the tokens in the withdrawl queue of the eigen layer. However, `queuedShares[address(this)]` is used instead of `queuedShares[address(token)]` in the following code. 
`queuedShares[address(this)]` is always 0, so the amount of the tokens in the withdrawl queue of the eigen layer is never added. 

https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Delegation/OperatorDelegator.sol#L327-L335

```solidity
    function getTokenBalanceFromStrategy(IERC20 token) external view returns (uint256) {
        return
@>          queuedShares[address(this)] == 0
                ? tokenStrategyMapping[token].userUnderlyingView(address(this))
                : tokenStrategyMapping[token].userUnderlyingView(address(this)) +
                    tokenStrategyMapping[token].sharesToUnderlyingView(
                        queuedShares[address(token)]
                    );
    }
```

As a result, the `TVL` is calculated less than the actual value. This leads to loss of fund for withdrawing users, when there are many tokens in the withdrawl queue of the eigen layer.
