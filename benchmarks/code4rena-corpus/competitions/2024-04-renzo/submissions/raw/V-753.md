# Vulnerability details

## Impact
The main impact is that the RenzoOracleL2.sol contract will out of service permanently if the Chainlink aggregator returns a price that is less than
1 ETH, even though the price is not stale. Precisely the getMintRate function contains an unnecessary check on the returned price, which could leave the oracle in a state of Denied Service. 

## Proof of Concept

Consider the following block [excerpt](https://github.com/code-423n4/2024-04-renzo/blob/519e518f2d8dec9acf6482b84a181e403070d22d/contracts/Bridge/L2/Oracle/RenzoOracleL2.sol#L50) from the getMintRate() function.

```
uint256 _scaledPrice = (uint256(price)) * 10 ** (18 - oracle.decimals());
        if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
        return (_scaledPrice, timestamp);
```

Now ezETH Token contains 18 decimals.

So if a call to the aggregatorV3 interface returns a price of 0.99 ETH

price = 990_000_000_000_000_000 Wei

scaled price becomes

uint256 _scaledPrice = price * 10 ** (18 - 18)

_scaledPrice = price

Therefore

the conditional

```
if (_scaledPrice < 1 ether) revert InvalidOraclePrice();
```

will revert since the _scaledPrice is less than 1 ETH and the oracle will not be able to return an answer and remain is a DOS state until the price increases.


## Tools Used

Manual Review

## Recommended Mitigation Steps

I would Recommend the scaled price check be removed, a check for stale price is sufficient.
