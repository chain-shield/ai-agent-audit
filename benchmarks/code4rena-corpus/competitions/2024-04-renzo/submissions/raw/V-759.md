# Vulnerability details


## Cause

Immediately after an upgrade, and [until `setWithdrawQueue` is called](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L87) by the `RestakeManagerAdmin` EOA to set the `withdrawQueue`'s address, [the `withdrawQueue` is set to the zero address](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L74-L80). However, [because `withdrawQueue` is called](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L296-L302) [during `receive()`](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Deposits/DepositQueue.sol#L176), any ETH transfers to the deposit queue during that time will fail.

The native ETH validators registered with the EigenPod have their fee recipient configured to the [deposit queue or to the RewardHandler](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Rewards/RewardHandler.sol#L12-L13) ([which forwards to the deposit queue](https://github.com/code-423n4/2024-04-renzo/blob/main/contracts/Rewards/RewardHandler.sol#L50-L54)). This means that MEV payments (direct transfers to `block.coinbase`) to these validators, included in MEV transaction bundles, will fail.

## Impact

This, in turn, means that these bundles will not be included (since failing bundles are not included in mev-boost), and the validators will lose all MEV and transaction fees that are part of those transactions.

The loss depends on the duration between the upgrade transaction and the admin's call to set the address, but because MEV income is of comparable size to the staking yield, this loss is comparable to loss of staking yield. 

Additionally, since Renzo is a restaking protocol, the point of which is to earn staking yield - the validators' ability to earn MEV income is core functionality which this bug breaks.

## Proof of Concept

1. After the upgrade, and before the EOA `RestakeManagerAdmin` sets the withdraw queue address, Renzo's operators' validators will be selected to propose blocks.
2. The MEV bundles will fail for these blocks, which will result in not including them in the final executed block.
3. The MEV and transaction fees income from these bundles will be lost to ezETH stakers.

## Recommended Mitigation Steps

During `receive()`, check that the address of `withdrawQueue` is not zero, and if it is, avoid calling it.

```diff
    function _checkAndFillETHWithdrawBuffer(uint256 _amount) internal {
+	    if (address(withdrawQueue) == address(0)) {
+		    return;
+	    }
	    ...
```
