# Vulnerability details

## Impact
The xReceive function in the xRenzoBridge contract currently does not have checks to limit the maximum amount of assets that can be processed. This oversight allows for the possibility of handling potentially unlimited quantities of Wrapped Ethereum (WETH). When this WETH is converted to Ethereum (ETH) and subsequently minted into ezETH, it could significantly strain the platform's liquidity and disrupt the economic equilibrium. Such a scenario could escalate transaction costs due to increased operational demands, create opportunities for market manipulation, and lead to potential instability within the platform. 

## Proof of Concept
The following code demonstrates the process of unwrapping WETH to ETH and subsequently converting ETH to ezETH without any checks on the quantity being processed, except for the non-zero condition. Here's the relevant code:
// Check that the amount sent is greater than 0
if (_amount == 0) {
    revert InvalidZeroInput();
}

// Unwrap the WETH
IWeth(address(wETH)).withdraw(_amount);

// Deposit it into Renzo RestakeManager
restakeManager.depositETH{ value: ethAmount }();

// Get the amount of ezETH that was minted
uint256 ezETHAmount = ezETH.balanceOf(address(this)) - ezETHBalanceBeforeDeposit;

The function converts all received WETH into ETH and then deposits that ETH to mint ezETH without any constraint on the upper limit of the amount processed. Consequently, an attacker could exploit this by using large volumes of WETH, possibly obtained through a flash loan, to disrupt the platform's economics by flooding the market with ezETH, manipulating its price.

## Recommended Mitigation Steps
To implement a mechanism for limiting the maximum transaction size in the xReceive function you can introduce a new variable maxTransactionLimit which is adjustable by governance mechanisms. 
Add a new state variable to store the maximum transaction limit and create a modifier to check whether the incoming transaction exceeds this limit.
Also add a function to adjust the maxTransactionLimit, ensuring only authorized users  can change it.

 // State variable to store the maximum transaction limit
    uint256 public maxTransactionLimit;
event MaxTransactionLimitChanged(uint256 newLimit);

  /// @notice Admin function to adjust the maximum transaction limit
    /// @dev Can only be called by the owner of the contract
    /// @param _newLimit The new transaction limit


    function setMaxTransactionLimit(uint256 _newLimit) external onlyOwner {
        require(_newLimit > 0, "Transaction limit must be positive");
        maxTransactionLimit = _newLimit;
        emit MaxTransactionLimitChanged(_newLimit);
    }

    function xReceive(
        bytes32 _transferId,
        uint256 _amount,
        address _asset,
        address _originSender,
        uint32 _origin,
        bytes memory
    ) external nonReentrant withinTransactionLimit(_amount) returns (bytes memory) {
