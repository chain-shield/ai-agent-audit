# Vulnerability details

## Impact
The owner can set upgrade able contract as `lpETH` , and upgrade it to Malicious contract after withdrawal window and stop users from claiming their tokens.
## Proof of Concept
The Normal flow of protocol is that the owner of `PrelaunchPoints` contract can set the loop addresses and after 7 days windows calls the `convertAllETH` function.after this the user can claim and stake their assets. The `lpETH` contract is in complete control of owner . There is possibility of following hack 
1. Owner launch the `PrelaunchPoints` campaign,
2. User deposits their tokens.
3. The Owner sets the contract with right contract in `setLoopAddresses`.
4. After the withdraw window , The Owner upgrade the `lpETH` contract to malicious version.
5. The malicious contract transfer all the `ETH` to some other contract and `_mint` 0 `lpETH` tokens.
6. The user could not withdraw nor claim there tokens now as all the `ETH` are withdrawn by the Malicious contract and `lpETH` balance is 0. 
## Tools Used
Manual Review
## Recommended Mitigation Steps
Use single lpETH contract which is already deploy and not upgrade able. Allow `PrelaunchPoints` to only use predefine `lpETH` contract.
