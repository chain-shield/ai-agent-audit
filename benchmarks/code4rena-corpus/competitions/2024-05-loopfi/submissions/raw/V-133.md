# Vulnerability details

## Impact
The owner of the contract will not be able to get their tokens back if that token is specified when the contract is deployed and transfers tokens to the contract.

## Proof of Concept
For example user deployed a contract with allowed ERC20 tokens (For example wrapped tokens A,B,C) and the constructor set it ```isTokenAllowed[_allowedTokens[i]] = true.```
https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L106-L108
```solidity
constructor(address _exchangeProxy, address _wethAddress, address[] memory _allowedTokens) {
...
 uint256 length = _allowedTokens.length;
         for (uint256 i = 0; i < length;)  {
            isTokenAllowed[_allowedTokens[i]] = true;
            unchecked {
                i++;
            }
        }
        isTokenAllowed[_wethAddress] = true;
    }
```
Then the owner of the contract, sent token X to this contract not through the contract function, but by the address of the contract. The owner wants to return his token X, but he cannot do it anymore. 

For example, the contract owner will try to use  ```recoverERC20() ``` , but it will not work because ```isTokenAllowed[tokenAddress]```  will be set to ```TRUE``` on this token. 
https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L380-L381
```solidity
 function recoverERC20(address tokenAddress, uint256 tokenAmount) external onlyAuthorized {
        if (tokenAddress == address(lpETH) || isTokenAllowed[tokenAddress]) {
            revert NotValidToken();
        }
        IERC20(tokenAddress).safeTransfer(owner, tokenAmount);

        emit Recovered(tokenAddress, tokenAmount);
    }
```

He can try to use  ```withdraw() ``` , but he won't succeed either, because  ```balances[msg.sender][_token] ``` will show 0, and the check will fail, because when the contract owner sent tokens to the address, the balances variable was not incremented. 
https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L284-L287
```solidity
  function withdraw(address _token) external {
        if (!emergencyMode) {
            if (block.timestamp <= loopActivation) {
                revert CurrentlyNotPossible();
            }
            if (block.timestamp >= startClaimDate) {
                revert NoLongerPossible();
            }
        }

        uint256 lockedAmount = balances[msg.sender][_token];
        balances[msg.sender][_token] = 0;

        if (lockedAmount == 0) {
            revert CannotWithdrawZero();
        }
...
```

However, if token X had not originally been specified at initialization (constructor), the contract owner would have been able to recover their tokens via the recoverERC20 function because ```isTokenAllowed[tokenAddress]``` would not have been ```TRUE```.

## Recommended Mitigation Steps

Think about better contract logic, so that the owner of the contract can set ```false```  in the ```allowToken()```  function on a certain token.
