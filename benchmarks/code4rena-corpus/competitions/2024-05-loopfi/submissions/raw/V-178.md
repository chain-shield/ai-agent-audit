# Vulnerability details

## Impact
Sending ETH directly to the contract locks it forever, with no option for a user to get his/her ETH back it if sent by mistake. This can lead to potential loss of funds.

## Proof of Concept
The contract includes a receive() function which allows ETH to be sent dirent to the contract but no way to get it out professionally. that locks any ETH sent to the contract forever. or other users in the protocol could take another users money because of a mistake that could be avoided if handled properly.

There is no function provided to withdraw mistakenly sent ETH from the contract.
Users may accidentally send ETH to the contract, expecting it to be used differently.

```javascript
 /**
     * Enable receive ETH
     * @dev ETH sent to this contract directly will be locked forever.
     */
    receive() external payable {}
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a function in the contract that allows authorized users to withdraw ETH sent to the contract by mistake. This will prevent potential loss of funds and improve user experience.

```javascript
 /**
     * @notice  Sweeps accidental ETH value sent to the contract
     * @dev     Restricted to be called by the Owner only.
     * @param   _amount  amount of native asset
     * @param   _to  destination address
     */
    function recoverNative(uint256 _amount, address _to) external onlyAuthorized {
        payable(_to).transfer(_amount);
    }
```
