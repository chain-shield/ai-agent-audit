# Vulnerability details

## Impact
When users lock WETH, their deposits are stored as ETH in the ```_processLock``` function. If they try to claim their lpETH with the WETH address as an input, they will get the error "NothingToClaim". However, they can claim if they provide ETH as the token address. Latter can only be the case if the user knows the contract code or there is a public disclosure by the protocol. Also, users can't withdraw since ```uint256 lockedAmount = balances[msg.sender][WETH];``` will always be 0.

## Proof of Concept

The ```_processLock``` function has the following if condition:

``` if (_token == address(WETH)) {
                WETH.withdraw(_amount);
                totalSupply = totalSupply + _amount;
                balances[_receiver][ETH] += _amount;
```

It basically stores WETH deposit balances of user as an ETH. This leads to 2 issues. First one is that users will not be able claim if they input WETH address as a token address in function ```claim```. They can only claim if they put ETH as the token address. Second issue is similar to the above case with that users can only be able to withdraw if they input the token address as the ETH address. This will be issue for the regular users if they are not warned about it.
