# Vulnerability details

## Issue Description
When users attempt to withdraw tokens in emergency mode under specific conditions related to `block.timestamp`, a transaction may revert due to frontrunners altering the transaction order after the emergency mode is deactivated. This occurs because the `withdraw` function's conditions rely on the `block.timestamp` value, which frontrunners can manipulate during transaction sequencing.

```java
function withdraw(address _token) external {
        if (!emergencyMode) {
            if (block.timestamp <= loopActivation) {
                revert CurrentlyNotPossible();
            }
            if (block.timestamp >= startClaimDate) {
                revert NoLongerPossible();
            }
        }
        // ...
}
```
```java
  function setEmergencyMode(bool _mode) external onlyAuthorized {
        emergencyMode = _mode;
    }
```


## Impact
This issue affects users attempting to withdraw tokens during an emergency mode period, potentially resulting in failed transactions when frontrunners manipulate transaction orders.

## Proof of Concept
Here is the scenario:
1. Emergency mode is active, and Bob initiates a token withdrawal using the `withdraw` function, meeting the conditions `block.timestamp <= loopActivation` or `block.timestamp >= startClaimDate`. The transaction should be successful due to the false result of the first if statement
2. While Bob's transaction is pending in the mempool, the owner disables emergency mode using `setEmergencyMode`.
3. Frontrunners alter the transaction order, causing Bob's transaction to revert due to the changed `block.timestamp` conditions post-emergency mode deactivation. Now the withdraw function checks the timestamp and sees it is no longer within the expected timeframe.



## Tools Used
Manual review

## Recommended Mitigation Steps
create a space for users to request a withdrawal and Let the owner call an authorized function that loops over each withdrawal request of users in every mode including emergency mode.
Before the owner turns the emergency mode back off, the owner should ensure that all pending withdrawal requests have been processed successfully by calling the authorized function.
After confirming the success of the withdrawals, the owner can safely deactivate the emergency mode by calling the `setEmergencyMode(false)` function
