# Vulnerability details

## Impact
The contract currently handles adjustments to the totalSupply differently in the withdraw and claim functions, which could lead to inconsistency in accounting.

```javascript
/**
     * @dev Claim logic. If necessary converts token to ETH before depositing into lpETH contract.
     */
    function _claim(address _token, address _receiver, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        internal
        returns (uint256 claimedAmount)
    {
        uint256 userStake = balances[msg.sender][_token];
        if (userStake == 0) {
            revert NothingToClaim();
        }
        if (_token == ETH) {
            claimedAmount = userStake.mulDiv(totalLpETH, totalSupply);
            balances[msg.sender][_token] = 0;
            lpETH.safeTransfer(_receiver, claimedAmount);
        } else {
            uint256 userClaim = userStake * _percentage / 100;
            _validateData(_token, userClaim, _exchange, _data);
            balances[msg.sender][_token] = userStake - userClaim;

            // At this point there should not be any ETH in the contract
            // Swap token to ETH
            _fillQuote(IERC20(_token), userClaim, _data);

            // Convert swapped ETH to lpETH (1 to 1 conversion)
            claimedAmount = address(this).balance;
            lpETH.deposit{value: claimedAmount}(_receiver);
        }
        emit Claimed(msg.sender, _token, claimedAmount);
    }
```

## Proof of Concept
In the withdraw function, when the token is ETH and the startClaimDate has passed, at this time when a user tries to withdraw, it will send them to use claim instead instead of directly withdrawing ETH.

```javascript
if (_token == ETH) {
            if (block.timestamp >= startClaimDate){
                revert UseClaimInstead();
            }
```

If the `block.timestamp` is okay the function will proceed and begin adjusting the `totalSupply` accordingly.

However, in the claim function, there is no adjustment made to the totalSupply when claiming. This inconsistency could lead to confusion for users and result in inaccurate accounting, potentially undermining the protocol's integrity.

## Tools Used
Manual Review

## Recommended Mitigation Steps
To ensure consistency and accurate accounting, adjust the claim function to also update the total supply when users claim ETH.
