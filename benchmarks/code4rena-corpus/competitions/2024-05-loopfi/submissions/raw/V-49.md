# Vulnerability details

## Impact
The mistakenly transferred WETH will remain locked in the contract indefinitely.

## Proof of Concept
The function recoverERC20 is used to:
```solidity
    /**
     * @dev Allows the owner to recover other ERC20s mistakingly sent to this contract
     */
```
When WETH is deposited into the contract via the lock mechanism, it will be converted to ETH and locked in the contract. Therefore, under normal circumstances, there is no WETH in the contract.  
WETH itself does not participate in the protocol's calculations.  
github:[https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L183C13-L192C15](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L183C13-L192C15)
```solidity
            if (!isTokenAllowed[_token]) {
                revert TokenNotAllowed();
            }
            IERC20(_token).safeTransferFrom(msg.sender, address(this), _amount);

            if (_token == address(WETH)) {
                WETH.withdraw(_amount);
                totalSupply = totalSupply + _amount;
                balances[_receiver][ETH] += _amount;
            } 
``` 
So, the recoverERC20 function should be able to withdraw mistakenly transferred WETH into the contract.  
But the current recoverERC20 function cannot achieve this functionality because WETH is present in the isTokenAllowed mapping. 

The following test function is for forking testing, add PrelaunchPoints.t.sol:
```solidity
    function testRecoverERC20() public {
        prelaunchPoints.allowToken(WETH);
        deal(WETH, address(this), 1e18);
        //mistakenly transfer to the contract WETH
        IERC20(WETH).transfer(address(prelaunchPoints), 1e18);
        vm.expectRevert();
        prelaunchPoints.recoverERC20(WETH, 1e18);
    }
```
