# Vulnerability details

## Impact
The current implementation does not adequately manage the return values from external contract interactions, specifically with the functions ``` `approve`, `stake`, and `deposit` ``` on the `lpETH` and `lpETHVault` contracts
## Proof of Concept
```PrelaunchPoints.claimAndStake(address,uint8,PrelaunchPoints.Exchange,bytes) (src/PrelaunchPoints.sol#232-241) ignores return value by lpETH.approve(address(lpETHVault),claimedAmount) (src/PrelaunchPoints.sol#237)
PrelaunchPoints.claimAndStake(address,uint8,PrelaunchPoints.Exchange,bytes) (src/PrelaunchPoints.sol#232-241) ignores return value by lpETHVault.stake(claimedAmount,msg.sender) (src/PrelaunchPoints.sol#238)
PrelaunchPoints._claim(address,address,uint8,PrelaunchPoints.Exchange,bytes) (src/PrelaunchPoints.sol#246-272) ignores return value by lpETH.deposit{value: claimedAmount}(_receiver) (src/PrelaunchPoints.sol#269)
PrelaunchPoints.convertAllETH() (src/PrelaunchPoints.sol#324-339) ignores return value by lpETH.deposit{value: totalBalance}(address(this)) (src/PrelaunchPoints.sol#331)
Reference: https://github.com/crytic/slither/wiki/Detector-Documentation#unused-return```

## Recommended Mitigation Steps


To address the issue of not handling return values from external contract calls, it is recommended to check the return value of each call and handle any false returns appropriately. This is crucial because, according to the ERC20 standard, the `approve` function should return a boolean value indicating success. Similarly, custom implementations of `stake` and `deposit` functions in external contracts might also return a success indicator.

Here is how you can modify the code to handle the return values:

1. For the `approve` function call in the `claimAndStake` method:

```solidity
bool approveSuccess = lpETH.approve(address(lpETHVault), claimedAmount);
require(approveSuccess, "lpETH approval failed");
```

2. For the `stake` function call in the `claimAndStake` method, if the `stake` function in the `ILpETHVault` contract returns a boolean:

```solidity
bool stakeSuccess = lpETHVault.stake(claimedAmount, msg.sender);
require(stakeSuccess, "Staking in lpETHVault failed");
```

3. For the `deposit` function call in the `convertAllETH` method, if the `deposit` function in the `ILpETH` contract returns a boolean:

```solidity
bool depositSuccess = lpETH.deposit{value: totalBalance}(address(this));
require(depositSuccess, "Deposit to lpETH failed");
```

Please ensure that the external contracts' `stake` and `deposit` functions are designed to return a boolean value indicating success. If they do not currently return a value, you may need to update their interfaces and implementations to include this feature.

By implementing these changes, the contract will be more secure and reliable, as it will be able to handle unsuccessful external calls and prevent further execution in such cases.
