# Vulnerability details

## Impact
as there is no `buyAmount` or minOutput amount here 0x api sets a default slippage of 1%, there is a substantial risk that price fluctuations exceed this threshold, leading to a high rate of transaction reversions. This not only frustrates users but also results in wasted gas fees.,
Negative slippage could lead to receiving significantly less of the output token than anticipated(attached 0x research report below), directly impacting the user's financial position.


## Proof of Concept
The PrelaunchPoints smart contract utilizes the 0x API for token swaps within its claim and claimAndStake functions, where swap data 1 is passed to execute trades. This data includes parameters for executing swaps on decentralized exchanges, crucially without explicitly specifying the buyAmount. The 0x API defaults to a slippage tolerance of 1% when the buyAmount is not provided.

https://0x.org/docs/0x-swap-api/api-references/get-swap-v1-quote#:~:text=(Optional%2C%20default%20is,percentage%20is%201%25.

Given the volatile nature of cryptocurrency markets, the default slippage setting might not be sufficient to accommodate price movements between the initiation and execution of a trade.
 
A specific case discussed on Ethereum Stack Exchange involved a reverted transaction when using the 0x API. The issue was related to the minimum output token amount being less than expected due to slippage, causing the transaction to revert. This highlights the importance of setting appropriate slippage tolerances
https://ethereum.stackexchange.com/questions/121671/reverted-transaction-from-quote
https://ethereum.stackexchange.com/questions/143726/slight-mev-eth-transaction

and if volatile tokens were allowed in future this can significantly affect users

The current handling of slippage could lead to a high rate of transaction failures and negative user experiences.

## Tools Used

## Recommended Mitigation Steps
consider Implement functionality allowing users to specify their desired slippage tolerance when initiating a swap. This adjustment would enable users to make more informed decisions based on their risk appetite and market conditions.
