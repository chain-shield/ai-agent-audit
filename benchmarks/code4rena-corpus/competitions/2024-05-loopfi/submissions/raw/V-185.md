# Vulnerability details

## Impact

When calling the functions `claim` and / or `claimAndStake`, an user put an arbitrary value for the `_percentage` value in order to possibly claim only a percentage and not the whole value.

This value is then passed and processed by the internal `_claim` function. The `_percentage` value will be needed in case the user wants to request a token other than ETH and has a positive balance for it.

The `_claim` function lacks a check to verify that this value is equal to or less than `100` allowing an user to claim more than 100% of the funds leading to the theft of the funds present in the protocol for the particular ERC20 claimed.

Note that `_percentace` is an `uint8` value. This means that can contains any number from 0 to 255.

## Proof of Concept

As you can see from the code of the function `_claim`, `_percentage` is used to calculate the `userClaim` with the formula `uint256 userClaim = userStake * _percentage / 100;`.

```Solidity
            uint256 userClaim = userStake * _percentage / 100;
            _validateData(_token, userClaim, _exchange, _data);
            balances[msg.sender][_token] = userStake - userClaim;

            // At this point there should not be any ETH in the contract
            // Swap token to ETH
            _fillQuote(IERC20(_token), userClaim, _data);

            // Convert swapped ETH to lpETH (1 to 1 conversion)
            claimedAmount = address(this).balance;
            lpETH.deposit{value: claimedAmount}(_receiver);
```

Let's say that user1 has 10 WETH and puts 255 as a percentage, he will be able to claim 25.5 WETH worth of lpETH: `userClaim = 10 WETH * 255 / 100 = 25.5`.

## Recommended Mitigation Steps

It is advisable to implement a check on the value of the input `_percentage` in the internal function `_claim`. An example of the modified function:

