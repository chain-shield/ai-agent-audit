# Vulnerability details

## Summary

A user mistakenly locks an amount of ETH for `address(0)` via `PrelaunchPoints::lockETHFor` will lose such amount forever

## Vulnerability Details
The function `lockETHFor` allows a user to lock ETH for a given address. Such addresses are expected to claim their vested lpETH later.

```javascript

function lockETHFor(address _for, bytes32 _referral) external payable {
       _processLock(ETH, msg.value, _for, _referral);
}

```

However, the function `_processLock` accepts any value for parameter `_for`.
Add the following test case to the end of the file `PrelaunchPoints.t.sol`, and run it with `forge test --mt testLockETHForAddressZero`, the result has proven that it's possible to lock ETH for the `address(0)`.

<details>

<summary>Code</summary>

```javascript

function testLockETHForAddressZero(uint256 lockAmount) public {
       vm.assume(lockAmount > 0);
       address recipient = address(0);

       vm.deal(address(this), lockAmount);
       prelaunchPoints.lockETHFor{value: lockAmount}(recipient, referral);

       assertEq(prelaunchPoints.balances(recipient, ETH), lockAmount);
       assertEq(prelaunchPoints.totalSupply(), lockAmount);
}

```

## Impact

If a user accidentally locks ETH for a valid address, he might be able to recover his funds by contacting the owner of the address.
However, in this case, the locked ETH amount is lost forever.

## Proof of Concept

In the protocol, the only way to recover the vested lpETH from a locked ETH is to call `claim` or `claimAndStake`.
However, we can see that in both functions, the caller is hardcoded as `msg.sender`, which is always different from `address(0)`

```javascript

function claim(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data)
       external
       onlyAfterDate(startClaimDate) // qa technically no one can claim? => anyone can claim after the startClaimDate

```

## Recommended Mitigation Steps

Consider adding this check in the function `lockETHFor` to eliminate such risk for the end user.

```diff

  function lockETHFor(address _for, bytes32 _referral) external payable {
+      if (_for == address(0)) {
+           revert WrongRecipient(_for);
+      }
       _processLock(ETH, msg.value, _for, _referral);
   }

```
