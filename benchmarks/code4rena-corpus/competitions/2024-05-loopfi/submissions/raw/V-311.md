# Vulnerability details

## Impact

In my previous submission [H-1], I have reported a similar issue. The scenario is the same, where a user directly sends `ETHER` to `PrelaunchPoints` smart contract, but the root cause of the bug is different this time.

In this case the LRT locker is trying to claim. To compute the `claimedAmount` we have used `address(this).balance`, this could result in extra amount of lpETH tokens transferred to receiver using this line `lpETH.deposit{value: claimedAmount}(_receiver)`.

[Source](https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L262C1-L263C60)

Code

```solidity
function _claim(address _token, address _receiver, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        internal
        returns (uint256 claimedAmount)
    {
        ...
        if (_token == ETH) {
            ...
        } else {
            ...
@>          claimedAmount = address(this).balance;
@>          lpETH.deposit{value: claimedAmount}(_receiver);
        }
        ...

```

### Actual Impact
A malicious actor can perform the attack intentionally by back-running the transaction or a lucky claimer/receiver can have the extra funds unintentionally. In any case there is a flaw in the logic and can be exploited.

## Proof of Concept
Attacker locks `1 wei` of whitelisted LRT. Epoch1 is lapsed and Epoch2 starts. Attacker observes and waits for some anonymous direct `ETHER` transfers to `PrelaunchPoints` smart contract. By mistake an innocent user sends `ETHER` directly to `PrelaunchPoints` smart contract. Attacker immmediately back-runs the `PrelaunchPoints::claim` transaction and steals the extra deposited funds. Even in this case the extra funds are supposed to stay in the protocol.

## Recommended Mitigation Steps
Below changes are required to be done in `PrelauncPoints::_claim` function. By applying below mitigation, the receiver will only receive the amount of `lpETH` tokens that he is entitled to.

Diff

```diff
function _claim(address _token, address _receiver, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        internal
        returns (uint256 claimedAmount)
    {
        ...
        if (_token == ETH) {
            ...
        } else {
            ...
+           uint256 balanceBeforeSwap = address(this).balance;
            _fillQuote(IERC20(_token), userClaim, _data);
-           claimedAmount = address(this).balance;
+           claimedAmount = address(this).balance - balanceBeforeSwap;
            lpETH.deposit{value: claimedAmount}(_receiver);
        }
        ...
}
```

Below changes are required to be done in `PrelauncPoints::receive` callback function.

```diff
receive() external payable {
+   _processLock(ETH, msg.value, msg.sender, keccak256("1"));
}
```

After implementing the `PrelaunchPoints::receive` function this way, sending of `ether` directly to `PrelaunchPoints` will revert if is sent after `loopActivation` otherwise sent `ether` will be processed normally using `PrelaunchPoints::_processLock` function.
