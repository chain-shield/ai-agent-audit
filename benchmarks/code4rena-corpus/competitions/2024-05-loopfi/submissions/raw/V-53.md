# Vulnerability details

## Impact
During contract exchange where input tokens are converted to WETH using UniSwap, the current contract fails to withdraw the WETH to ETH, potentially resulting in WETH becoming stuck within the contract.

## Proof of Concept
The issue can be observed in the code snippet provided at [this GitHub link](https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L418). In this specific line of code, the contract is designed to check the type of token, expecting it to be WETH. However, this logic could inadvertently lead to WETH becoming trapped within the contract.

## Tools Used
The identification of this issue relied on manual review.

## Recommended Mitigation Steps
To address this issue, it is advisable to implement a mechanism within the `PrelaunchPoints::_fillQuote` function to withdraw the token if its type is identified as WETH. By incorporating this mitigation step, the risk of WETH becoming stuck within the contract can be significantly reduced.
