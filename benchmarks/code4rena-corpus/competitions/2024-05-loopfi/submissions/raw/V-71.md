# Vulnerability details

## Impact
The `_fillQuote` function lacks a check to ensure the amount returned from the swap transaction is greater than or meets the `minBuyAmount` specified for the swap for users redeeming `lpETH` with their `LRT` tokens.

## Proof of Concept

```solidity
function _fillQuote(IERC20 _sellToken, uint256 _amount, bytes calldata _swapCallData) internal {
        // Track our balance of the buyToken to determine how much we've bought.
        uint256 boughtETHAmount = address(this).balance;

        require(_sellToken.approve(exchangeProxy, _amount));

        (bool success,) = payable(exchangeProxy).call{value: 0}(_swapCallData);
        if (!success) {
            revert SwapCallFailed();
        }

        // Use our current buyToken balance to determine how much we've bought.
        boughtETHAmount = address(this).balance - boughtETHAmount;
        emit SwappedTokens(address(_sellToken), _amount, boughtETHAmount);
    }
```

In the `_fillQuote` function above, the `_swapCallData` contains encoded data of the swap call to uniswap whose function is `sellTokenForEthToUniswapV3(bytes encodedPath, uint256 sellAmount, uint256 minBuyAmount, address recipient)`. So when we enter the `call` below, the `sellTokenForEthToUniswapV3()` will be executed

```solidity
(bool success,) = payable(exchangeProxy).call{value: 0}(_swapCallData);
        if (!success) {
            revert SwapCallFailed();
        }
```

But there is no check that `boughtETHAmount` meets the `minBuyAmount` after `0x Exchange Proxy` swap success and the transfer of ether back into the `PrelaunchPoints` contract

```solidity
boughtETHAmount = address(this).balance - boughtETHAmount; // @audit so what if boughtETHAmount doesn't meet the `minBuyAmount` argument for the swap? user loses value
```

This leads to a case where the `minBuyAmount` was 1 ether but the amount of ether transferred from the swap by `0x` is 0.89 ether which results in the user losing 0.11 ether of value. Notice, there is no malicious user swap data crafting for this to occur. The swap data will be correctly crafted but its requirement of meeting `minBuyAmount` will not be checked by the LoopFi protocol before proceeding to mint `lpETH` to the user.

An example transaction of the `sellTokenForEthToUniswapV3` Uniswap call can be seen in this transaction below on-chain:
[sellTokenForEthToUniswapV3](https://etherscan.io/tx/0xa4330014d7156327896053692c867fbe2362768d296570e147902272652c28ed)

Please scroll to the `More Details` section and click `+ Click to show more` to read the function argument and encoded swap data.

## Tools Used
Manual review

## Recommended Mitigation Steps
The `_swapCallData` inside the `_fillQuote` function contains a `minBuyAmount` that can be decoded by the LoopFi protocol and checking the resulting delta of ether in the contract against to make sure it is in fact met before proceeding to mint `lpETH` to the user.
