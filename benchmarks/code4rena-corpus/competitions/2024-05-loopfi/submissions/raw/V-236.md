# Vulnerability details

## Background
Users can lock ETH, WETH and wrapped LRTs into the PrelaunchPoints contract with the purpose of earning points and getting lpETH in return. This lpETH can also be staked to earn additional rewards.

After the users deposit their assets, they also have a choice to withdraw as long as it is within 7 days after the lpeth address and staking contract are set. This is for allowance just in case they change their mind.

### The Issue
There is only one problem with the withdrawal function. It gives the user a choice what type of asset they want to withdraw (see line 274). If that is the case, arbitrage opportunity is very likely because a malicious user can deposit a lower valued asset in order to withdraw a higher valued asset. As per current market condition, native eth and LRTs have different pricing in terms of USD.

## Impact
Economic losses to depositors of higher valued LRT assets.

## Proof of Concept
This could be the scenario of exploit.
1. User A deposit LRT token with value of 3,100 usd
2. Seeing the User A transaction, User B immediately deposit native ETH with value of 3,000 usd
3. Protocol admin setup the necessary addresses of lpETH and staking contract. Depositing asset is no longer allowed.
4. User B immediately withdraw the asset using the LRT token address but in same number of token. This token could be traded immediately to exchanges and gain a profit of 100 usd.

## Tools Used
Manual Review

## Recommended Mitigation Steps
The protocol should only allow withdrawal of assets originally deposited by the  user.
