# Vulnerability details

## Impact
Withdrawal invariant is not working as stated in `Main Invariant` section of the protocol document, it can be result in users' misunderstanding.

- `Withdrawals are only active on emergency mode or during 7 days after loopActivation is set.`

If owner delays executing `convertAllEth` due to some problems, users may think there is an error in the protocol and can withdraw their locked funds breaking the invariant.  

  
## Proof of Concept
Owner can convert all eth to lpETH since 7 days after `loopActivation` set.

```solidity
function convertAllETH() external onlyAuthorized onlyBeforeDate(startClaimDate) {
@>      if (block.timestamp - loopActivation <= TIMELOCK) {
            revert LoopNotActivated();
        }

        // deposits all the ETH to lpETH contract. Receives lpETH back
        uint256 totalBalance = address(this).balance;
        lpETH.deposit{value: totalBalance}(address(this));

        totalLpETH = lpETH.balanceOf(address(this));

        // Claims of lpETH can start immediately after conversion.
@>      startClaimDate = uint32(block.timestamp);

        emit Converted(totalBalance, totalLpETH);      
}
```
It doesn't say that `startClaimDate` exactly equals `loopActivation + 7 days`.
Meanwhile, `withdraw` function blocks user's withdrawal only if block timestamp is after `startClaimDate`.
```solidity
function withdraw(address _token) external {
        if (!emergencyMode) {
            if (block.timestamp <= loopActivation) {
                revert CurrentlyNotPossible();
            }
@>          if (block.timestamp >= startClaimDate) { 
                revert NoLongerPossible();
            }
        }

        __SNIP__
}
```
Therefore, if owner runs `convertAllEth` on 8 days (example case) after `loopActivation` set, users can withdraw for 8 days.
in real world, users can think if there is a problem in the protocol at that time, so they can withdraw their funds.

## Recommended Mitigation Steps
It is important for the protocol team to clarify the purpose of this invariant to clear up any possible misunderstandings.
If purpose is to block users' withdrawal after startClaimDate, please update documentation about the main invariants.
If not, block users' withdrawal since 7 days after `loopActivation` set.
```solidity
function withdraw(address _token) external {
        if (!emergencyMode) {
            if (block.timestamp <= loopActivation) {
                revert CurrentlyNotPossible();
            }
--          if (block.timestamp >= startClaimDate) { 
++          if (block.timestamp >= loopActivation + TIMELOCK) { 
                revert NoLongerPossible();
            }
        }

        __SNIP__
}
```
