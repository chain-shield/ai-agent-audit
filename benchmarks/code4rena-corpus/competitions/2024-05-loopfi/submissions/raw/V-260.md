# Vulnerability details

## Impact
loss of funds.
when a user calls the `claim` function to get their `ETH` they deposits they can get less or nothing of their deposits. This breaks the invariant test and users can get DOS if they try to withdraw `ETH`.

## Proof of Concept

1.user A deposits 10 ETH and `totalSupply` is updated to 10
2. user B deposits 10000 WETH and `totalSupply` is updated to  10010
3. user A calls the `claim` function to claim eth
4. The `claim`  function calculate how eth must be transfered to user A
https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L249

5. Calculation :
                 `claimedAmount = userStake.mulDiv(totalLpETH, totalSupply)`
                         
                 10 * 10 = 100
                 100 / 10010 = 0.000999000999000 eth

6. user A `balance` state variable will be updated to zero 
  `balances[msg.sender][_token] = 0`
7. User A get Transfered  0.000999000999000 eth not 10 eth they deposited

this is the function that updates `totalSupply` for both `ETH` and `WETH`

https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L172
