# Vulnerability details

**Description**:
The `PrelaunchPoints` smart contract records a `bytes32` referral code during certain user actions and emits it as part of an event:

```solidity
event Locked(address indexed user, uint256 amount, address token, bytes32 indexed referral);
```

This `bytes32` field is intended to represent referral information and is expected to be processed by off-chain systems such as a frontend interface or server-side tracking software. However, there is no on-chain validation or sanitation mechanism in place, making it entirely reliant on the consuming application to handle this data correctly.

**Impact**:
If an attacker realizes that the off-chain system does not adequately sanitize or escape the referral code before inserting it into the application's HTML/JavaScript context, they can craft malicious input that, when processed by the frontend, could result in:

- Cross-Site Scripting (XSS) attacks if the data is rendered in the HTML without proper escaping.
- Command injection if the data is used in system commands without proper sanitation.
- SQL injection if the data is used in database queries without proper parameterization.
- Phishing, redirect, or defacement attacks by manipulating the displayed content or behavior of the webpage.

**Reproduction** _(Hypothetical Example)_:
1. An attacker crafts a malicious transaction calling `lock(...)`, including a `bytes32` referral code that contains a script snippet or SQL command fragment.
2. The transaction results in the `Locked` event being emitted with the malicious payload in the `referral` field.
3. The off-chain system retrieves the event log and uses the referral code within the application context without sanitizing the input, embedding it in the webpage rendered to end-users.
4. The script or command executes within the context of the affected user's environment, leading to the consequences mentioned above.

**Recommendation**:
Implement the following best practices to mitigate this risk:
- On-chain, use specific data types for intended content (like an Ethereum address or UUID for referral codes), enabling appropriate validation and reducing the potential for arbitrary data.
- Off-chain, rigorously sanitize and escape any data from the blockchain before rendering it in the frontend application or using it in any backend processes to prevent injection attacks.
