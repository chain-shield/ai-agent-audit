# Vulnerability details

## Impact
The function `_claim` lacks proper slippage protection and deadline parameter for transactions routed through Uniswap V3, making it susceptible to sandwich attacks. This vulnerability arises because the `_data` parameter, used within the `_claim` function to conduct token swaps, does not contain a slippage parameter or a deadline.


## Proof of Concept
The vulnerability is evident in the way the `_validateData` and `_fillQuote` functions are structured and invoked from the `_claim` function. The `_data` parameter, expected to be supplied externally, lacks some useful parameters for slippage protection. This is also evident when looking at all the parameters available in the API : https://0x.org/docs/0x-swap-api/api-references/get-swap-v1-quote. Nowhere can we see a slippage protection or a deadline.

All the parameters are returned by the function `_decodeUniswapV3Data`:

```js
    function _validateData(address _token, uint256 _amount, Exchange _exchange, bytes calldata _data) internal view {
...
            (inputToken, outputToken, inputTokenAmount, recipient, selector) = _decodeUniswapV3Data(_data);
```
This can lead to unfavorable swaps and users getting way less lpETH.

## Tools Used
Manual review
## Recommended Mitigation Steps

Update the api to introduce parameters for the min amount to receive and the deadline. These should also get validated by the function before applying the swap.
