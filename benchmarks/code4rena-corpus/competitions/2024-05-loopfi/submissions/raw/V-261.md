# Vulnerability details

## Impact
Detailed description of the impact of this finding.

This vulnerability in the PrelaunchPoints contract allows malicious actors who participated in the locking period to steal all claimable Ether, including funds from other participants. The attacker achieves this by calling one of the following functions with a malicious payload :

function claim(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data) and function claimAndStake(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data)

These functions allow users to claim their rewards or restake their rewards after claiming them when the locking period is over. However, due to the vulnerability, an attacker can inject malicious code within the _data parameter, enabling them to steal all claimable Ether from the contract.

Breakdown of Potential Impact:

Complete Loss of Funds: Attackers could steal all claimable Ether, including funds from other participants who locked funds in the PrelaunchPoints contract.
Contract Inoperability: A successful exploit could potentially render the contract unusable until a fix is implemented and deployed.

## Recommended Mitigation Steps   
This vulnerability can be fixed by making two seperate versions of claim and claimAndStake functions as the following example demonstrates with claim function :  `function claim(address _token, uint8 _percentage, Exchange _exchange)
        external
        onlyAfterDate(startClaimDate)` and `function claim(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        internal
        onlyAfterDate(startClaimDate)`
In order to call the internal function users should interact with 0xapi by calling a new implemented function because it will submit some bytes returned by 0xapi.However on the other hand,external function will submit only empty bytes and never get any bytes parameter.
