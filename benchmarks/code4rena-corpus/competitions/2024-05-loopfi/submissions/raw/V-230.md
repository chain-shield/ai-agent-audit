# Vulnerability details

The protocol allows contracts to lock
- ETH via `PrelaunchPoints::lockETH`, and 
- WETH via `Prelaunchpoints::lock`
for themselves.

Similarly, the protocol allows users with EOAs to lock ETH and WETH for contracts via `PrelaunchPoints::lockETHFor` and `Prelaunchpoints::lockFor`, respectively.

However, the protocol does not account for the possibility that the contract such funds are being locked for may be unprepared to receive Ether.

## Impact

Contracts not prepared to receive Ether are not able to withdraw Ether (via `PrelaunchPoints::withdraw`).

Similarly, they cannot withdraw from WETH locks either: the protocol does not have internal accounting for WETH locks, but instead instantenously unwraps all locked WETH to ETH in `PrelaunchPoints::_processLock`.

Notably, if the protocol owner never calls `PrelaunchPoints::convertAllETH`, contracts that could not withdraw ETH will not be able to claim their lpETH either, such funds will be lost forever.

## Proof of Concept
The following piece of code demonstrates that a contract locks WETH in the protocol, but then is unable to withdraw as 1) WETH has been converted to ETH by the protocol, and 2) the contract is not able to receive Ether.

Test:

```javascript
function test_contractCannotWithdrawWETH() public {
        // setting up a Loop contract that uses mockWETH which has a withdraw method
        MockWETH mockWETH = new MockWETH();
        address mockWETHAddress = address(mockWETH);
        // WETH contract has to have ether
        vm.deal(mockWETHAddress, INITIAL_SUPPLY);
        address[] storage allowedTokens_ = allowedTokens;
        allowedTokens_.push(address(lrt));
        PrelaunchPoints prelaunchPoints_b = new PrelaunchPoints(EXCHANGE_PROXY, mockWETHAddress, allowedTokens_);

        // then deploy a contract that cannot handle ETH
        WethDepositor wethDepositor = new WethDepositor(payable(address(prelaunchPoints_b)));
        // give 1 WETH to the depositor contract
        uint256 initialBalance = 1e18;
        deal(mockWETHAddress, address(wethDepositor), initialBalance);
        assertEq(IERC20(mockWETHAddress).balanceOf(address(wethDepositor)), initialBalance);
        // contract locks WETH to the protocol, and protocol instantenously swaps it to ETH
        wethDepositor.lock(mockWETHAddress, initialBalance, referral);

        // loop contracts are set
        prelaunchPoints_b.setLoopAddresses(address(lpETH), address(lpETHVault));
        vm.warp(block.timestamp + 1);

        // contract tries to withdraw WETH, but cant because it was converted to ETH
        vm.expectRevert(PrelaunchPoints.CannotWithdrawZero.selector);
        wethDepositor.withdraw(mockWETHAddress);

        // contract tries to withdraw ETH, but is unable to accept
        vm.expectRevert(PrelaunchPoints.FailedToSendEther.selector);
        wethDepositor.withdraw(ETH);
    }
```

Contract for locking WETH, unprepared to handle Ether:

```javascriptcontract WethDepositor {
    address payable prelaunchPointAddress;
    PrelaunchPoints public prelaunchPoints;
    address immutable i_owner;

    error WethDepositor__NotOwner();

    modifier onlyOwner() {
        if (msg.sender != i_owner) {
            revert WethDepositor__NotOwner();
        }
        _;
    }

    constructor(address payable _prelaunchPointAddress) {
        i_owner = msg.sender;
        prelaunchPointAddress = _prelaunchPointAddress;
        prelaunchPoints = PrelaunchPoints(prelaunchPointAddress);
    }

    function lock(address _tokenAddress, uint256 _amount, bytes32 _referral) external onlyOwner {
        IERC20(_tokenAddress).approve(prelaunchPointAddress, _amount); // providing approval
        prelaunchPoints.lock(_tokenAddress, _amount, _referral);
    }

    function withdraw(address _tokenAddress) external onlyOwner {
        prelaunchPoints.withdraw(_tokenAddress);
    }
}
```

## Recommended Mitigation Steps
Consider the following options:

1. When ETH is being locked: check whether the address the funds are being locked for is a contract, and 

        a) either revert if it is a contract, OR

        b) perform a test ETH transfer with 1 wei to check whether the contract 
           can accept Ether. If it can, proceed with the lock.

2. When WETH is being locked:

        a) either do the same as described in point 1), OR
        b) redesign the protocol so that it handles WETH as all the other 
           portocol-allowed ERC20 tokens (i.e. account it separately from ETH 
           locks, and do not automatically unwrap it to ETH).
