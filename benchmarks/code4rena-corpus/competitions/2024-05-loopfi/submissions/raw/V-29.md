# Vulnerability details

## Description
The `_claim` function within the smart contract is intended to allow users to claim a proportion of their staked assets by swapping another token for ETH. However, there is an issue with the `_fillQuote` function where it permits execution of token swaps that could result in sending the swapped ETH to the zero address (`address(0)`).

## Impact
If the `_data` parameter used for the token swap specifies `address(0)` as the recipient, the `_fillQuote` function would allow the transaction to process, leading to the ETH being sent to the zero address. This would effectively burn the swapped ETH, as the zero address is an unowned address from which funds cannot be recovered. Such a loss is irreversible and affects both user trust and the integrity of the contract's logic.

## Proof of Concept
The issue lies in the following code segments:

1. The `_validateData` function, which does not revert the transaction when the recipient is the zero address. 
```solidity
if (recipient != address(this) && recipient != address(0)) { 
    revert WrongRecipient(recipient);
}
```

2. The `_fillQuote` function executes the swap without verifying that the recipient of the swapped funds is the contract itself. 
```solidity
(bool success,) = payable(exchangeProxy).call{value: 0}(_swapCallData);
...
// Use our current buyToken balance to determine how much we've bought.
boughtETHAmount = address(this).balance - boughtETHAmount;
...
emit SwappedTokens(address(_sellToken), _amount, boughtETHAmount);
```

By analyzing the flow of execution and the lack of a check on `boughtETHAmount`, we can determine that it is possible for this value to end up being zero, which should typically not occur under normal operation.

## Recommended Mitigation Steps
The development team should take the following actions to mitigate this issue:

1. Modify the condition check within `_validateData` to ensure it reverts if the recipient is the zero address.

2. Add a post-swap check in the `_fillQuote` function to confirm that the contract's balance of ETH has increased by the expected swap amount, and if not, revert the transaction.
