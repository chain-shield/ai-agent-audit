# Vulnerability details

## Impact
The vulnerability has severe implications for users who have deposited ETH into the contract. If users attempt to claim their deposited ETH and the contract uses a different address (not the ETH constant) to track ETH balances, they may not be able to claim their ETH correctly. This inconsistency could lead to loss of funds for affected users
## Proof of Concept
In the `_claim` function of the smart contract, the code accesses the user's stake using the mapping `balances[msg.sender][_token]`. However, when the `_token` parameter is ETH, instead of using the `ETH` constant, the code uses the `_token` variable. This inconsistency could result in incorrect balance calculations and prevent users from claiming their deposited ETH

## Tools Used
Manual Review

## Recommended Mitigation Steps
Ensure consistent usage of the ETH constant when dealing with ETH balances in the smart contract.Specifically, use `balances[msg.sender][ETH]` when accessing or manipulating ETH balances, regardless of the `_token` parameter
