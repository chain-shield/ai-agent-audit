# Vulnerability details

The ``_processLock`` function is responsible for locking tokens in the contract ,we can see that transfer is called only in else statement i.e ``token !=ETH``.so contract wont receive any ETH it only updates total supply and balance of the  user.
```solidity
  if (_token == ETH) {
            totalSupply = totalSupply + _amount;
            balances[_receiver][ETH] += _amount;
        } else {
            if (!isTokenAllowed[_token]) {
                revert TokenNotAllowed();
            }
//here
            IERC20(_token).safeTransferFrom(msg.sender, address(this), _amount);

            if (_token == address(WETH)) {
                WETH.withdraw(_amount);
                totalSupply = totalSupply + _amount;
                balances[_receiver][ETH] += _amount;
            } else {
                balances[_receiver][_token] += _amount;
            }
        }
```
## Impact
loss of funds for users because user who set their set tokens to ETH will receive free LpETH whereas when the contract becomes empty the user who deposited different tokens will receive nothing. 

## Proof of Concept
1. malicious user set token to eth and deposit large amount of eth without having large amount
2. wait for timelock to pass 
3. claim the token deposited  for free.
