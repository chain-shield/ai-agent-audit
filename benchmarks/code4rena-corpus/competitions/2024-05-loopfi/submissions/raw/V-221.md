# Vulnerability details

## Impact
In the `PrelaunchPoints::_claim` internal function that is called by other external claim functions, Whenever a user wants to claim his token that is not ETH he can specify the percentage of the balance of the token he wants to withdraw.

However, this percentage computation leads to precision loss which can result in a zero return value

## Proof of Concept
this is the responsible for the amount of tokens the user can take 
```solidity
            uint256 userStake = balances[msg.sender][_token];
            ...

            uint256 userClaim = userStake * _percentage / 100;
```

Example
`userStake` = 9 tokens
`_percentage` = 10%

`userClaim` = 9 * 10/100 = 0.9

solidity does not take into account decimals

Therefore making the `userClaim` 0


## Tools Used
Manual Analysis with Vs Code.

## Recommended Mitigation Steps
It is recommended to implement a check that reverts when `userClaim` is 0
