# Vulnerability details

### Impact 
The contract does not appear to have a mechanism to track whether tokens have already been claimed. The _claim function resets the user's balance for the claimed token to zero for ETH claims but does not for other tokens, which could lead to double claiming `balances[msg.sender][_token] = 0;` Since _claim is an internal function, its direct exposure to external calls is limited. However, it's called by public functions `claim` and `claimAndStake`, which means the missing claim tracking for non-ETH tokens can still be exploited through these public entry points. The vulnerability arises because the `_claim` function does not account for the total amount of non-ETH tokens that have been converted to lpETH and claimed by the user. 
 ## Proof of Concept 

``` 
function testClaim50Percent(uint256 lockAmount) public {
        lockAmount = bound(lockAmount, 1, 1e36); // Ensure lockAmount is within reasonable bounds
        vm.deal(address(this), lockAmount); // Provide this contract with enough ETH to lock
        
    
        // Lock ETH in the PrelaunchPoints contract
        prelaunchPoints.lockETH{value: lockAmount}(referral);
    
        // Set Loop Contracts and Convert to lpETH
        prelaunchPoints.setLoopAddresses(address(lpETH), address(lpETHVault));
        vm.warp(prelaunchPoints.loopActivation() + prelaunchPoints.TIMELOCK() + 1);
        prelaunchPoints.convertAllETH(); // Convert all locked ETH to lpETH
    
        // Warp to a time after startClaimDate to allow claiming
        vm.warp(prelaunchPoints.startClaimDate() + 1);
    
        // Claim 50% of the locked ETH
        prelaunchPoints.claim(ETH, 50, PrelaunchPoints.Exchange.UniswapV3, emptydata);
    
        // Calculate expected lpETH balance after claiming 50%
        uint256 expectedLpETHBalance = prelaunchPoints.totalLpETH() * lockAmount / prelaunchPoints.totalSupply() / 2;
    
        // Check that only 50% of the ETH was claimed
        uint256 remainingEthBalance = prelaunchPoints.balances(address(this), ETH);
        uint256 claimedLpETHBalance = lpETH.balanceOf(address(this));
    
        // Assertions to verify the correct amounts are claimed and remaining
        assertEq(remainingEthBalance, lockAmount / 2, "50% of the ETH should remain locked after claiming 50%");
        assertEq(claimedLpETHBalance, expectedLpETHBalance, "lpETH balance should reflect 50% of the initial stake");
    }
```

 ## Recommended Mitigation Steps
the contract should track the total amount of `lpETH` that has been claimed against each user's non-ETH token stake. This could be done by introducing a new mapping to store the amount of lpETH claimed per user per token. The `_claim` function should then be updated to check against this mapping to ensure that users cannot claim more lpETH than their stake entitles them to
