# Vulnerability details

## Impact
User Can claim More lpEth than they deposited.

## Proof of Concept
User A locks 1 ether into the protocol. 
balance of ether in the protocol is 1 ether.

User B locks 1 ether into the protocol.
balance of ether in the protocol is 2 ether.

user C locks  1 ether token of  X into the protocol.

once it is time to claim. 

User C front-runs  `convertAllETH` function and claims before other users because, when the token user C locked in the protocol is swapped the ether balance in the contract increases. 

The whole balance in the contract is then assigned to user C.

```solidity
 else {
            
            uint256 userClaim = userStake * _percentage / 100;
            _validateData(_token, userClaim, _exchange, _data);
            balances[msg.sender][_token] = userStake - userClaim;

          
            _fillQuote(IERC20(_token), userClaim, _data);

        
            claimedAmount = address(this).balance;
            // @audit attacker owns all the balance and stakes all
            lpETH.deposit{value: claimedAmount}(_receiver);
        }
```
user C would end up minting 2 ether plus of lpETh. after depositing 1 ether worth of token X.
