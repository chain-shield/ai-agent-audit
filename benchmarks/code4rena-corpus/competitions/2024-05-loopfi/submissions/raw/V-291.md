# Vulnerability details

## Impact

A user's claim amount might be way lesser than what it was supposed to be since there is no slippage protection while claiming.

## Proof of Concept

1.) Alice tries to claim her lpETH using the claim() function for an ERC-20 token , 
an exchange and a percentage , _claim() is called ,

2.) Since the token is an ERC-20 the code reaches here https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L254 where data is validated.

3.) The swap takes place at https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L259 and the function _fillQuote executes a swap but there was no minimum amount out provided with the call . 

4.) This means it is possible that the tx was sandwiched and the output token (ETH) comes out to be way less than expected resulting in loss of lpETH for the user.

## Tools Used

Manual analysis

## Recommended Mitigation Steps

Have a slippage control parameter while swapping so that user does not get sandwiched and lose on lpETH rewards.
