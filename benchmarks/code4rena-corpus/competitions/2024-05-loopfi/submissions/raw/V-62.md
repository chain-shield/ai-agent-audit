# Vulnerability details

## Summary
The contract's `receive()` function allows the permanent locking of Ether without a method to retrieve it.
## Vulnerability Details
The smart contract includes a `receive()` function that accepts Ether transactions. However, there is no corresponding functionality provided within the contract to withdraw or reclaim this Ether once received, leading to permanently locked funds.
## Impact
Users who send ETH directly could unintentionally lose access to their funds if they are not aware that this action is irreversible. This can lead to financial loss and negatively impact user trust in the protocol.

## Proof of Concept
```
// Enable receive ETH with no mechanism for retrieval.
// ETH sent here will be irretrievable, effectively locked forever.
receive() external payable {}
```
Since this behavior is by design (for users intentionally locking their ether), test case logs would only demonstrate normal operation as intended—locking ether without reclaim options—and are thus not applicable in demonstrating unintended consequences or errors.
