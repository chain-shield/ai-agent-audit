# Vulnerability details

# Impact

The presence of the setEmergencyMode function without adequate safeguards allows for the toggling of emergency mode by an authorized entity. The specific impact of this function being misused includes:

    Change in Contract Behavior: The contract may behave differently when in emergency mode, which could affect all users interacting with it.
    Alteration of Normal Operations: If emergency mode changes the contract’s operations, such as enabling otherwise restricted actions, it could disrupt normal contract functionality.
    Direct Influence on User Transactions: Depending on the contract’s logic, entering or exiting emergency mode could directly impact user transactions, potentially leading to unexpected outcomes for users.


# Proof of Concept

The setEmergencyMode function is designed to toggle a critical operational mode of the contract. The vulnerability arises from the lack of stringent checks within the onlyAuthorized modifier, potentially allowing misuse by an authorized entity. Here’s a step-by-step demonstration of how this vulnerability could be exploited:

    Initial Setup: An authorized entity, which has the permission to call setEmergencyMode, is identified.
    Triggering the Vulnerability: The authorized entity calls setEmergencyMode(true), activating emergency mode.
    Observing the Effects: Once emergency mode is active, we observe the contract’s behavior. If the contract allows actions like unrestricted withdrawals, we document these changes.
    Exploiting the Emergency Mode: We demonstrate how an authorized entity could perform actions that would otherwise be restricted, such as withdrawing funds without the usual checks.
    Deactivating Emergency Mode: The authorized entity calls setEmergencyMode(false), and we observe whether the contract reverts to its normal operational mode.

// Example of an authorized entity exploiting the emergency mode
contract AuthorizedEntity {
    VulnerableContract public vulnerableContract;

    constructor(address _vulnerableContractAddress) {
        vulnerableContract = VulnerableContract(_vulnerableContractAddress);
    }

    function toggleEmergencyMode(bool _mode) external {
        vulnerableContract.setEmergencyMode(_mode);
    }
}



# Recommended Mitigation Steps


To address the “Emergency Mode Misuse” vulnerability, the following steps are recommended:

  -  Enhanced Governance: Implement a multi-signature or DAO-based governance process for toggling emergency mode.
  -  Justification Requirement: Require a clear on-chain justification for activating or deactivating emergency mode.
  -  Time-bound Emergency Mode: Introduce a time limit for emergency mode, after which it must be reviewed and re-authorized if necessary.
