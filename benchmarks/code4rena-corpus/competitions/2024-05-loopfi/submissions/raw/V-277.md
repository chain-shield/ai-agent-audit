# Vulnerability details

## Impact
In the _validateData function, the check verifies if the recipient is either the PrelaunchPoints contract address or the zero address. This allows ETH to be burned  when using UniswapV3 instead of being sent to the contract which is then sent to the user.

```javascript
  if (recipient != address(this) && recipient != address(0)) {
     revert WrongRecipient(recipient);
  }
```

## Recommended Mitigation Steps
To address this issue, remove the check for the zero address and only validate the recipient when using UniswapV3.
