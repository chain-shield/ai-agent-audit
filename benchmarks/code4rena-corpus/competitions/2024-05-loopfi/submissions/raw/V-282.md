# Vulnerability details

## Impact
Users' ETH could be locked if the contract owner fails to execute the `convertAllETH()` function, for example, due to the loss of the private key.

Although the loss of the owner's private key is rare, considering the severity of locking user's funds, it is better to fix the contract to prevent any potential risk.

## Proof of Concept
The variable `startClaimDate` is initialized with a default value set to '2106-02-07 14:28:15', which acts as a restriction on when users can claim lpETH. If it does not been updated by the `convertAllETH()` function, users' ETHs will be locked until '2106-02-07 14:28:15' because they can only claim tokens after that date:

```solidity
    function claim(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        external
        onlyAfterDate(startClaimDate)
```

Unlike users staking ERC20 tokens, who can still call the `withdraw()` function after 120 days (`loopActivation`), users staking ETH/WETH can not withdraw their tokens due to the check on [L291](https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L291):

```solidity
if (block.timestamp >= startClaimDate){
    revert UseClaimInstead();
}
```

## Recommended Mitigation Steps
It is recommended to default the `startClaimDate` to `loopActivation + TIMELOCK`.
