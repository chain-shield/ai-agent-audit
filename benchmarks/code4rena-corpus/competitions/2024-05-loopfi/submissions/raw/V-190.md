# Vulnerability details

## Impact
The current implementation of the ETH transfer in the contract's `withdraw` function may lead to unexpected behavior causing the withdraw function to revert. The function attempts to send Ether using `msg.sender.call{value: lockedAmount}(""),` but this approach is incorrect because msg.sender should be payable. This could result in ETH not being sent as expected, leading to potential loss of funds for users.

Attempting to send Ether to an address that is not marked as `payable` will result in a failure of the transaction. The call function is a low-level function that allows you to send Ether to any address, but it does not inherently check if the recipient address is capable of receiving Ether. The payable modifier is what explicitly allows an address to receive Ether.

If you attempt to send Ether to an address that is not marked as payable, the call function will still execute without throwing an error, but the Ether will not be received by the address. The call function will return false for the sent variable, indicating that the Ether transfer was not successful.

## Recommended Mitigation Steps
To properly handle ETH transfers, use `payable` instead of `msg.sender.call{value: amount}("")`. This ensures that the transfer is made to a payable address and will revert if the transfer fails, preventing any potential loss of funds.

```javascript
(bool success, ) = payable(msg.sender).call{ value: lockedAmount }("");
if (!success) {
    revert FailedToSendEther();
}
```
