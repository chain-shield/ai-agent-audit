# Vulnerability details


## Impact
The current implementation of the `withdraw` function in the contract violates one of the main variants outlined in the documentation. This violation allows users to withdraw their tokens after the 7-day period following the loop activation, extending the withdrawal window beyond the intended timeframe specified in the project documentation. 

docs >>  Withdrawals are only active on emergency mode or during 7 days after loopActivation is set

## Proof of Concept
The flaw in the `withdraw` function can be identified in the following code snippet:

```solidity
function withdraw(address _token) external {
    if (!emergencyMode) {
        if (block.timestamp <= loopActivation) {
            revert CurrentlyNotPossible();
        }
        if (block.timestamp >= startClaimDate) {
            revert NoLongerPossible();
        }
    }
}
```

The second conditional check `if (block.timestamp >= startClaimDate)` incorrectly restricts withdrawals based solely on the `startClaimDate`, disregarding the intended withdrawal window defined by the loop activation and a grace period of TIMELOCK. 

```solidity

function convertAllETH() external onlyAuthorized onlyBeforeDate(startClaimDate) {
        if (block.timestamp - loopActivation <= TIMELOCK) {
            revert LoopNotActivated();
        }

        // deposits all the ETH to lpETH contract. Receives lpETH back
        uint256 totalBalance = address(this).balance;
        lpETH.deposit{value: totalBalance}(address(this));

        totalLpETH = lpETH.balanceOf(address(this));

        // Claims of lpETH can start immediately after conversion.
        startClaimDate = uint32(block.timestamp);

```
This oversight allows users to withdraw tokens even after the intended withdrawal window has elapsed(More than 7 days as long as admin is yet to call the covertall function).

## Recommended Mitigation Steps
To rectify the variant violation and enforce the withdrawal window as specified in the project documentation, the following mitigation steps are recommended:

 **Update Withdrawal Condition**: Modify the withdrawal condition to accurately enforce the intended withdrawal window based on both the `startClaimDate` and the `loopActivation` with a grace period of TIMELOCK.

   ```solidity
   function withdraw(address _token) external {
       if (!emergencyMode) {
           if (block.timestamp <= loopActivation ) {
               revert CurrentlyNotPossible();
           }
           if (block.timestamp >= startClaimDate|| block.timestamp > loopActivation + TIMELOCK) {
               revert NoLongerPossible();
           }
       }
   }
   ```
