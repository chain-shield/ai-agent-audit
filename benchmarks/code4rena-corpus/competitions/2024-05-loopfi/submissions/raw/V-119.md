# Vulnerability details

## Impact
The conversion for LRTs happens on each claim by using 0x API. The function `sellTokenForEthToUniswapV3` or `transformERC20 ` will be called to perform a swap. However, no `deadline` is specified from the input, potentially leading to sub-optimal swap.

## Proof of Concept
The conversion for LRTs happens on each claim by using 0x API. The function `sellTokenForEthToUniswapV3` or `transformERC20 ` will be called to perform a swap.

However, no `deadline` is specified from the input but the swap has been performed.

```solidity
    function claim(address _token, uint8 _percentage, Exchange _exchange, bytes calldata _data)
        external
        onlyAfterDate(startClaimDate)
```

```solidity
        (bool success,) = payable(exchangeProxy).call{value: 0}(_swapCallData);

```

This could lead to sub-optimal situation: allowing outdated slippage and pending transaction being executed unexpectedly.



## Tools Used

Manual

## Recommended Mitigation Steps

Add `deadline` parameter from user input.
