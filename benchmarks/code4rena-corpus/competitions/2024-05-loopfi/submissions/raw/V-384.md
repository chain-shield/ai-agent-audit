# Vulnerability details

## Impact
The `PrelaunchPoints` contract is designed to interact with specific API structures to decode transaction data for operations like token swaps via Uniswap. The fixed structure of the contract makes it non-upgradeable. However, API changes, such as modifications in data format or additional required parameters, cannot be accommodated by a non-upgradeable contract. This inflexibility could lead to compatibility issues, potentially rendering the contract obsolete or dysfunctional, thereby affecting its reliability and security.


## Proof of Concept
The contract uses assembly to decode data for executing swaps, relying on the structure of the `_data` input derived from an API. Changes in the API structure cannot be reflected in the contract due to its non-upgradeable design. Here's an example of how the contract reads the `_data`:

```js
function _decodeUniswapV3Data(bytes calldata _data)
    internal
    pure
    returns (address inputToken, address outputToken, uint256 inputTokenAmount, address recipient, bytes4 selector)
{
    assembly {
        // Assembly block for decoding omitted for brevity
        recipient := calldataload(add(p, 64)) // Potential issue if API changes the data structure
    }
}
```

This assembly logic assumes a fixed data layout which, if altered due to an API update, would not be correctly interpreted by the contract, leading to failures or incorrect executions.

The current specific API call has the following structure: https://0x.org/docs/0x-swap-api/api-references/get-swap-v1-quote


If the API changes for example, altering the byte order or adding new fields, the current contract setup cannot adapt, leading to potential errors.
