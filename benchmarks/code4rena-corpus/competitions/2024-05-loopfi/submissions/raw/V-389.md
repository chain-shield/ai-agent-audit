# Vulnerability details

## Impact
The protocol's backend will be DoSed by flooding it with a huge amount of events  coming from [emit events](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L197) in _processLock method.

## Proof of Concept
According to the sponsor, the points that can be earned will be calculated on [emit Locked](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L197) events and on [emit Withdrawn](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L305).

Now Users use [lock](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L143) to lock an amount of ETH or ERC20 token in PrelaunchPoints contract, The amount obviosity is flexible as users can lock big or small amounts.

The issue occur when a user make fractions deposits with really small amount to cause emit events going out to the backend, that seems fine until a malicious person use this exploit to send a lot of events to the backend, as a result, a DoS is done using [_processLock](https://github.com/code-423n4/2024-05-loop/blob/0dc8467ccff27230e7c0530b619524cc8401e22a/src/PrelaunchPoints.sol#L172) . This is possible by depositing just 1 WEI each time for thousands of small deposits,  this eventually will reflect negatively on the backend.




## Tools Used
Manual Review

## Recommended Mitigation Steps
Set a Minimum amount in _processLock method to protect from dust deposits that overload the backend



## Assessed type

DoS
