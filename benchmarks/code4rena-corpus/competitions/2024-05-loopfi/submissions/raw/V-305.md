# Vulnerability details

## Impact
- Loss of Ether or Tokens.
- unsuccessful fund withdrawal

## Proof of Concept
In the withdraw function at line 285, the user's balance for a specific token (_token) is set to zero (0) using the following code: 

```
285:     balances[msg.sender][_token] = 0;
```
Now, consider the scenario where `_token` is `ETH` and a specific condition check (`if (block.timestamp >= startClaimDate)`) becomes true, the function will revert with the reason `UseClaimInstead()`. However, the user's balance has already been set to zero (0) in the previous line (`balances[msg.sender][_token] = 0;`).
```
290:        if (_token == ETH) {
291:              if (block.timestamp >= startClaimDate){
292:                    revert UseClaimInstead();    <@
293:            }
```

which means the user's balance is incorrectly updated even though the transaction eventually reverts.

## Tools Used
VS Code
## Recommended Mitigation Steps

ensures that the user's balance is only set to zero after all conditions for a successful withdrawal are verified, preventing the balance from being zeroed out prematurely.
