# Vulnerability details

## Impact
Breaking the invariant listed on Readme
From https://github.com/code-423n4/2024-05-loop#main-invariants

```md
    Main invariants
        - Only the owner can set new accepted LRTs, change mode to emergency mode on failure of 0x integration, and set a new owner
        - Deposits are active up to the lpETH contract and lpETHVault contract are set
        - Withdrawals are only active on emergency mode or during 7 days after loopActivation is set
 >>>    - Users that deposit ETH/WETH get the correct amount of lpETH on claim (1 to 1 conversion)
        - Users that deposit LRTs get the correct amount assuming a favorable swap to ETH
```

**Issue:**
Look at L249 above,

1. The amount of `lpETH` a claimer receives when his ETH is claimed, is dependent on `totalLpETH`, `totalSupply` which are subject to change.
2. If they change the 1:1 ratio listed on invariant is broken.
3. So don't make the `claimedAmount` when ETH claims dependent on `totalLpETH` and `totalSupply`. Look at `Recommended Mitigation Steps`
