# Vulnerability details

## Vulnerability Details 
The `_claim` function calls `_fillQuote` to swap the claimed token for ETH using the provided `_swapCallData`. However, there's no reentrancy protection mechanism in place, leaving the contract vulnerable to a reentrant attack during the swap.

A malicious attacker could exploit this by setting up a fallback function that calls `_claim` again after the initial token swap. This reentrant call could manipulate the contract's state before the `lpETH.deposit` (or `lpETH.safeTransfer` for ETH claims) completes, potentially allowing the attacker to:

Claim more tokens than they are entitled to by manipulating the balance mapping.
Disrupt the claim process for other users by interfering with state variables.

## Impact
Loss of user funds: An attacker could exploit the reentrancy vulnerability to steal tokens from other users claiming their rewards.
Denial-of-service (DoS) attack: The attacker could disrupt the claim process for legitimate users by manipulating the contract's state during reentrancy.

## Proof of Concept
Attacker calls claim with a valid token and swap data.
The contract converts the claimed token to ETH using _fillQuote.
Before lpETH.deposit completes, the attacker's fallback function is triggered due to reentrancy.
The attacker's fallback function manipulates balances to claim additional tokens.

## Tools Used
Manual

## Recommended Mitigation Steps
Implement a reentrancy protection mechanism like the `NonReentrant` modifier from OpenZeppelin Contracts. This ensures only one instance of _claim can execute at a time, preventing reentrant attacks.
