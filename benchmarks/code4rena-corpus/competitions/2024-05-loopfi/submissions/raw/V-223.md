# Vulnerability details

## Impact
The staker could loose the claimable rewards due to usage of stale state variable when the token is ETH.

This vulnerability arise due usage of totalLpETH variable that is updated only during convertAllETH() function called by owner. If the owner does not timely called the convertAllEth(), then totalLpETH variable becomes stale and does not track the balance in the actual token contract.

This impact the claimable rewards as totalLpETH is used as basis for computing the portion of user claimable tokens.

## Proof of Concept
Refer to the lockFor() functions where the totalSupply state variable is updated when the token is ETH/WETH. Hence every time there is a lockFor() call to stake tokens, then total supply variable is updated if the token is ETH.

On the other hand, totalLpETH is updated only when convertAllETH() function is called by the owner of the contact. So, there is every chance that there is an activity for lockFor() the staker and claim by another staker() when the convertAllETH() is not called by owner.

So, when the claim amount is computed as below.

```
 claimedAmount = userstake * totalLpETH / totalSupply
```

If the totalLpETH is not tracked while the totalSupply is inflated via new locks, the claimedAmount will be lesser that what is actually qualified for the user.

## Recommended Mitigation Steps
a) change totalLpETH state variable to a local variable to be used for computation during claim.

b) Fetch the balance from token contract as below.

```
 lpETH.balanceOf(address(this));
```
