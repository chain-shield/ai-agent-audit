# Vulnerability details

## Impact
The impact of this finding is a discrepancy between the totalSupply of the contract and the actual amount of WETH stored in the contract. When users lock WETH tokens, the totalSupply increases accordingly. However, when users withdraw their WETH tokens, the totalSupply is not decreased. This inconsistency could lead to incorrect calculations elsewhere in the contract.
## Proof of Concept
https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L188-L191

```sol
            if (_token == address(WETH)) {
                WETH.withdraw(_amount);
                totalSupply = totalSupply + _amount;
                balances[_receiver][ETH] += _amount;
```
When the user locks WETH, the totalSupply in the PrelaunchPoints contract will increase. In other words, WETH is considered to be the supply by default.

https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L290-L303

```sol
        if (_token == ETH) {
            if (block.timestamp >= startClaimDate){
                revert UseClaimInstead();
            }
            totalSupply = totalSupply - lockedAmount;

            (bool sent,) = msg.sender.call{value: lockedAmount}("");

            if (!sent) {
                revert FailedToSendEther();
            }
        } else {
            IERC20(_token).safeTransfer(msg.sender, lockedAmount);
        }
```

However, in the withdraw function, the decrease in the supply of WETH is not considered. When the user withdraws WETH, the totalSupply will not change.


https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L249
```sol
            claimedAmount = userStake.mulDiv(totalLpETH, totalSupply);
            balances[msg.sender][_token] = 0;
            lpETH.safeTransfer(_receiver, claimedAmount);
```
Assume that the current total is 100e18, of which 50e18 is ETH and 50e18 is WETH. If a user holding WETH calls the withdraw function, it will not cause the totalSupply to be reduced. This will affect the calculation of claimedAmount of users holding ETH because claimedAmount is related to totalSupply.

## Recommended Mitigation Steps
Add the following code in the withdraw function
```sol
 else if(_token == address(WETH)){
            totalSupply = totalSupply - lockedAmount;
            bool sent=WETH.transfer(msg.sender, lockedAmount);
            require(sent);
        }
```
