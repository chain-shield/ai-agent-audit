# Vulnerability details


## Impact
The identified vulnerability in the withdraw functionality of the contract poses a significant risk to users attempting to withdraw their WETH tokens deposited before the loop activation period. During the grace period of 7 days following activation, if a user tries to withdraw their WETH tokens, the transaction will revert. 
## Proof of Concept
The vulnerability stems from the following code snippet:
1. No update for weth balance eventhough he makes a deposit. Eth balance is updated instead.
```solidity
  if (_token == address(WETH)) {
                WETH.withdraw(_amount);
                totalSupply = totalSupply + _amount;
                balances[_receiver][ETH] += _amount;
            } 
```
2. User tries to withdraw within the grace period - tries to withdraw weth

```solidity
uint256 lockedAmount = balances[msg.sender][_token];
balances[msg.sender][_token] = 0;

if (lockedAmount == 0) {
    revert CannotWithdrawZero();
}
```
uint256 lockedAmount = balances[msg.sender][WETH] will be zero.
Due to the conditional check `if (lockedAmount == 0)`, the withdrawal transaction will revert if `lockedAmount` is zero. However, `balances[msg.sender][weth]` will always be zero because it is not updated during the deposit or lock process. This creates a denial-of-service (DOS) vulnerability for users attempting to withdraw WETH tokens.
