# Vulnerability details

## Impact
No deadline check for the UniswapV3 call can result in transactions being maliciously executed 

## Proof of Concept

https://github.com/code-423n4/2024-05-loop/blob/40167e469edde09969643b6808c57e25d1b9c203/src/PrelaunchPoints.sol#L412-L419

```
     if (_exchange == Exchange.UniswapV3) {
            (inputToken, outputToken, inputTokenAmount, recipient, selector) = _decodeUniswapV3Data(_data);
            if (selector != UNI_SELECTOR) {
                revert WrongSelector(selector);
            }
            // UniswapV3Feature.sellTokenForEthToUniswapV3(encodedPath, sellAmount, minBuyAmount, recipient) requires `encodedPath` to be a Uniswap-encoded path, where the last token is WETH, and sends the NATIVE token to `recipient`
            if (outputToken != address(WETH)) {
                revert WrongDataTokens(inputToken, outputToken);
            }
```

The function validatedata, validates the data sent to 0x api. If the exchange entered is uniswap V3, it then calls the function UniswapV3Feature.sellTokenForEthToUniswapV3.

https://github.com/0xProject/protocol/blob/e66307ba319e8c3e2a456767403298b576abc85e/contracts/zero-ex/contracts/src/features/UniswapV3Feature.sol#L101-L126


When looking at the function UniswapV3Feature.sellTokenForEthToUniswapV3, there is a check for slippage but there is no check for the deadline. When using an AMM, there should always be a deadline check to make sure that users are protected in times of high volatility as well as prevent transactions from being maliciously executed where users are swapping at bad prices.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add a deadline check in the _validatedata function

Uniswap
