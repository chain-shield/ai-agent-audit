# Vulnerability details

## Vulnerability Description
The PrelaunchPoints contract does not restrict which 0x transformers can be used for token exchanges, potentially allowing any newly created transformer to be employed. Since transformers can be added to the 0x protocol without the LoopFi Protocol's oversight, there is a risk of introducing transformers that could perform harmful or unexpected actions.

This issue arises from the contract's unchecked reliance on 0x's `transformERC20()` function, where assets are transferred to the transformers along with transformation calldata.

Although the 0x protocol performs its checks to ensure only valid transformers are executed, the wide range of possible transformer behaviors means that a new transformer could introduce functions that the LoopFi Protocol is unprepared to handle.

## Scenario
Consider a hypothetical new transformer that allows for setting additional approvals or interacts with accounts in a way that deviates significantly from the current transformer behaviors. Utilizing such a transformer without explicit LoopFi Protocol oversight could lead to asset mismanagement or unexpected re-entrancy behaviors.

## Recommendation
Implement a whitelist mechanism to allow only pre-approved transformers to be used. This approach would require LoopFi to manually verify and approve each transformer based on thorough security assessments. This not only mitigates the risk of unexpected transformer behavior but also ensures that only transformers relevant to LoopFi's operations are utilized.
