# Vulnerability details

## Impact
There is no restriction on the input bytes32 `_referral` check, as a result, it is possible for a user to perform self-referral and get the event emitted.

## Proof of Concept
In the lock-related function, the user can input `_referral` as he wishes.

```solidity
    function lockETH(bytes32 _referral) external payable {
        _processLock(ETH, msg.value, msg.sender, _referral);
    }
```

However, there is no way to prevent the self-referral. The user could use his own referral code and lock his assets.

Even though this could be handled in backend, this behavior should be properly handled before the transaction takes effect.

## Tools Used
Manual, VSCode

## Recommended Mitigation Steps
Use a mapping to store the  `referral code` for each user, and put restriction on the input value `_referral`.
