# Vulnerability details

## Impact

The [lockETHFor()](https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L133C4-L135C6) function in the contract is marked as external, allowing anyone to call it. This function takes an `address _for` parameter, specifying the user whose ETH will be locked.

However, the function lacks proper authorization checks. It calls the [_processLock()](https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L172C4-L198C6) function to process the lock without requiring permission from the `address _for` (the intended recipient of the locked ETH).

This vulnerability allows a malicious user to call lockETHFor() with any address, effectively locking that user's ETH within the contract without their consent.


The same vulnerability exists in the [lockFor](https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L157-L162) function, which allows locking any ERC20 token used by the protocol, but not ETH, as [lockETHFor()](https://github.com/code-423n4/2024-05-loop/blob/main/src/PrelaunchPoints.sol#L133C4-L135C6) it lacks proper authorization checks and takes an `address _for` parameter specifying the user whose tokens will be locked.
