# Vulnerability details

## Impact
```_loopAddress``` and ```_vaultAddress``` can be set more than once by calling the ```setLoopAddresses``` function again and again before 120 days have passed from deployment. This breaks the invariant that :

```solidity
     * @param _loopAddress address of the lpETH contract
     * @dev Can only be set once before 120 days have passed from deployment.
```

## Proof of Concept
In the below code, there is no check if the ```setLoopAddresses``` is being called for one time or more than one time.

```solidity
    function setLoopAddresses(address _loopAddress, address _vaultAddress)
        external
        onlyAuthorized
        onlyBeforeDate(loopActivation)
    {
        lpETH = ILpETH(_loopAddress);
        lpETHVault = ILpETHVault(_vaultAddress);
        loopActivation = uint32(block.timestamp);

        emit LoopAddressesUpdated(_loopAddress, _vaultAddress);
    }
```
Even though owner is a trusted entity and is supposed to call the ```setLoopAddresses``` only once but still this invariant can be broken due to lack of proper checks.

## Tools Used
Manual review

## Recommended Mitigation Steps
Create a variable named ```flag``` of type ```bool``` and set it to ```true``` initially. Also, create a custom error named ```canOnlyBeCalledOnce```.

Then use the below code:
```solidity
    function setLoopAddresses(address _loopAddress, address _vaultAddress)
        external
        onlyAuthorized
        onlyBeforeDate(loopActivation)
    {
         if (flag == false) {
            revert canOnlyBeCalledOnce();
        }
        lpETH = ILpETH(_loopAddress);
        lpETHVault = ILpETHVault(_vaultAddress);
        loopActivation = uint32(block.timestamp);
        flag = false;
        emit LoopAddressesUpdated(_loopAddress, _vaultAddress);
    }
```
