S-207
Farm Creation Fee Can Be Ineffective in Preventing LP Token Denial of Service
Lambda
00
Sufficient
383d ago
Finding description and impact

The current farm creation fee is a fixed value. According to the deployment script, it is a flat 10 OM, which is insufficient to prevent malicious actors from performing a denial of service attack on specific LP tokens. Due to the max_concurrent_farms limit of 7 per LP token, an attacker can create farms with minimal emission rates that run for very long periods, effectively blocking legitimate users from creating farms for that LP token.

For only 70 OM total (7 farms * 10 OM fee), plus minimal amounts of farming tokens to ensure positive emission rates, an attacker can lock out farming capabilities for specific LP tokens for extended periods (years), causing significant disruption to the protocol's incentive mechanisms.

This is particularly concerning as competitors could use this as a way to make certain LP pools in the protocol unattractive by preventing any meaningful farming rewards.

Proof of Concept

The issue stems from these components:

Fixed farm creation fee:
https://github.com/code-423n4/2024-11-mantra-dex/blob/26714ea59dab7ecfafca9db1138d60adcf513588/contracts/farm-manager/src/manager/commands.rs#L92

Farm emission rate calculation that allows very small rates:
https://github.com/code-423n4/2024-11-mantra-dex/blob/26714ea59dab7ecfafca9db1138d60adcf513588/contracts/farm-manager/src/manager/commands.rs#L133-L136

Attack scenario:

Attacker creates 7 farms for a target LP token
Total cost:
Farm creation fees: 7 * 10 OM = 70 OM
Farm assets: 7 * 1000 LP microtokens (their smallest denomination) with preliminary_end_epoch set years in the future (i.e. effectively zero)
Results in tiny emission rate but keeps farms active
These farms block legitimate farming for that LP token until they expire
Total cost is minimal compared to potential competitive damage caused
Recommended mitigation steps
Implement a minimum emission rate per farm:
const MIN_EMISSION_RATE: Uint128 = Uint128::new(10000000); // Set appropriate value

ensure!(
    emission_rate >= MIN_EMISSION_RATE,
    ContractError::EmissionRateTooLow { min: MIN_EMISSION_RATE }
);
Consider making farm creation fees proportional to the farm duration:
let duration = farm.preliminary_end_epoch.saturating_sub(farm.start_epoch);
let farm_fee = config.base_farm_fee + (config.fee_per_epoch * duration);

Allow users to top up existing farms even if they aren't the original creator. This prevents farm slots from being wasted on minimal farms, but would require a redesign.

Implement a maximum farm duration to prevent extremely long-running minimal farms.

These changes would make DoS attacks prohibitively expensive while maintaining the system's utility for legitimate users.
