Incorrect farm asset validation results in creation failures due to lack of coin aggregation
Tigerfrake
19
Sufficient
383d ago
Finding description and impact

The assert_farm_asset() function validates the number of assets sent by comparing the length of info.funds with expected values. However, info.funds may contain multiple entries of the same denomination due to how funds are handled in transactions. This leads to incorrect validation because only one entry is taken into account.

If duplicate entries of the same denomination are sent, the validation erroneously rejects the transaction (due insufficient funds) when in reality there are enough funds to complete the transaction.

Issue Scenario:

A user sends a total of 1050 units of a farm asset split into two entries of 1000 units and 50 units (1000 as params.farm_asset.amount and 50 as farm_creation_fee.amount), as follows:
    info.funds = vec![
        Coin { denom: "farm_token".to_string(), amount: Uint128::from(1000u128) },
        Coin { denom: "farm_token".to_string(), amount: Uint128::from(50u128) },
    ];
In the current implementation, sent coins are retrieved as follows:
    let coin_sent = info
        .funds
        .iter()
>>      .find(|sent| sent.denom == params.farm_asset.denom) // @audit-info Only fetches the first instance
        .ok_or(ContractError::AssetMismatch)?;

The find() function will match one entry (the first one), yet the other instance that matches the same denom will be ignored, causing the transaction to fail, even though the total amount sent matches the requirement.

NOTE❗:
Notice how this is utilized correctly when providing liquidity by first merging the funds and then checking deposits length:

>>  let deposits = aggregate_coins(info.funds.clone())?; // @audit-info Merged first

>>  let is_single_asset_provision = deposits.len() == 1usize; // @audit-info Then check length

This function first merges the transacted funds by summing up the relevant funds from the info structure. This takes into account possibility of having multiple instances of the same coin denomination in the funds vector. This yields accurate length check.

Recommended mitigation steps
Aggregate the info.funds list before performing validation to ensure that duplicate entries of the same denomination are merged into a single entry with the correct total amount.
Use an aggregation function like the aggregate_coins():
