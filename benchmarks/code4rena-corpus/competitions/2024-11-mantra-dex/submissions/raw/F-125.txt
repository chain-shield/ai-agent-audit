S-209
Funds stuck in FeeCollector contract due to missing withdrawal functionality
Lambda
00
Sufficient
383d ago

The FeeCollector contract is designed to collect various protocol fees including farm creation fees, emergency withdrawal penalties, etc. However, the contract lacks any functionality to withdraw or transfer the collected fees, effectively locking them in the contract forever.

Proof of Concept

The FeeCollector contract only implements ownership management functionality:

#[entry_point]
pub fn execute(
    deps: DepsMut,
    env: Env,
    info: MessageInfo,
    msg: ExecuteMsg,
) -> Result<Response, ContractError> {
    match msg {
        ExecuteMsg::UpdateOwnership(action) => {
            cw_utils::nonpayable(&info)?;
            mantra_utils::ownership::update_ownership(deps, env, info, action).map_err(Into::into)
        }
    }
}

The contract receives fees from multiple sources:

Farm creation fees (source)
Emergency withdrawal penalty fees (source)

However, there is no functionality implemented to withdraw these accumulated fees, meaning they will be permanently locked in the contract.

Recommended mitigation steps

Add withdrawal functionality to the FeeCollector contract that allows the owner to withdraw accumulated fees. For example:

#[derive(Serialize, Deserialize, Clone, Debug, PartialEq, JsonSchema)]
#[serde(rename_all = "snake_case")]
pub enum ExecuteMsg {
    UpdateOwnership(Action),
    WithdrawFees {
        denom: String,
        amount: Option<Uint128>,
        recipient: String,
    },
}

The withdrawal function should:

Only be callable by the owner
Allow withdrawing specific amounts or all funds for a given denom
Include proper access controls and input validation
Emit appropriate events for tracking

This will allow the protocol to actually utilize the collected fees rather than having them permanently locked in the contract.
