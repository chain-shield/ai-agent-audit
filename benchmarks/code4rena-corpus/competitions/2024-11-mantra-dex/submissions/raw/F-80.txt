Users can extend their farms expiry time by expanding farm with 0 amount
0xcb90f054
00
Sufficient
383d ago
Finding description and impact

expand_farm allows the user to expand the farm with given parameters. The function requires that the reward amount to be added to the total asset amount must be a multiple of the farm's emission rate upon which the preliminary_end_epoch which is used to get expiry time is set. But the issue is that the function doesn't check that the reward amount is 0, giving users the ability to extend their farm expiry without actually adding any reward amount.

Proof of Concept

In the expand_farm function, we can see the the function ensures that the reward amount is a multiple of the farm emission rate. It does this by using the "%" operator. However, the operator also returns 0 if the dividend is 0 (since the remainder will be 0). Then the farm asset amount will be increased by 0, while the additional epoch will calculated and added to the previous preliminary end epoch, the sum of which is set as the new preliminary end epoch.

    // make sure the expansion is a multiple of the emission rate
@>  ensure!(
        reward.amount % farm.emission_rate == Uint128::zero(),
        ContractError::InvalidExpansionAmount {
            emission_rate: farm.emission_rate
        }
    );

    // increase the total amount of the farm
@>  farm.farm_asset.amount = farm.farm_asset.amount.checked_add(reward.amount)?;

@>  let additional_epochs = params.farm_asset.amount.checked_div(farm.emission_rate)?;

    // adjust the preliminary end_epoch
    farm.preliminary_end_epoch = farm
        .preliminary_end_epoch
        .checked_add(Uint64::try_from(additional_epochs)?.u64())
        .ok_or(ContractError::InvalidEpoch {
            which: "end".to_string(),
        })?;

    FARMS.save(deps.storage, &farm.identifier, &farm)?;

    Ok(Response::default().add_attributes(vec![
        ("action", "expand_farm".to_string()),
        ("farm_identifier", farm.identifier),
        ("expanded_by", params.farm_asset.to_string()),
        ("total_farm", farm.farm_asset.to_string()),
    ]))
}

As can be seen in the is_farm_expired function, the current preliminary end epoch is used to calculate the farm expiry period. Therefore, by expanding with zero reward, users can maliciously extend their expiry time.

Recommended mitigation steps

Add a check for 0 reward amount in the expand_farm function.
