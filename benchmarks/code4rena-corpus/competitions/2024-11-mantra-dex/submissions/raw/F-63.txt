Incorrect fee processing logic potentially prevents farm creation even with sufficient funds
Tigerfrake
19
Sufficient
383d ago
Finding description and impact

The current implementation of process_farm_creation_fee() uses .iter().find(...) to locate the first instance of a coin in the info.funds vector that matches the required fee's denomination (farm_creation_fee.denom). However, this approach does not account for cases where the same coin denomination appears multiple times in the info.funds vector.

If the user provides the correct total fee spread across multiple instances of the same coin denomination, the function may incorrectly determine that the fee has not been paid in full. This can result in erroneous reversion.

Proof of Concept

During farm creation, fee is processed if farm_creation_fee.amount is set:

    if farm_creation_fee.amount != Uint128::zero() {
        // @audit-info verify the fee to create a farm is being paid
>>      messages.append(&mut process_farm_creation_fee(&config, &info, &params)?);
    }

Here is process_farm_creation_fee():

    let paid_fee_amount = info
        .funds
        .iter()
>>      .find(|coin| coin.denom == farm_creation_fee.denom) // @audit-info Only picks the first instance
        .ok_or(ContractError::FarmFeeMissing)?
        .amount;

    match paid_fee_amount.cmp(&farm_creation_fee.amount) {
        Ordering::Equal => (), 
>>      Ordering::Less => { // @audit-info This May result in a revert
            return Err(ContractError::FarmFeeNotPaid {
                paid_amount: paid_fee_amount,
                required_amount: farm_creation_fee.amount,
            });
        },
        Ordering::Greater => { /* Refund logic */ }
    }

The .find() method only considers the first instance of the matching denomination. Any additional amounts in subsequent instances are ignored, leading to incorrect calculations and potential reverts.

NOTE ❗:
Notice how this is utilized correctly when providing liquidity:

>>  let deposits = aggregate_coins(info.funds.clone())?; //@audit-info Merged first

    ensure!(!deposits.is_empty(), ContractError::EmptyAssets);

This function first merges the transacted funds by summing up the relevant funds from the info structure. This takes into account possibility of having multiple instances of the same coin denomination in the funds vector.

Recommended mitigation steps
Aggregate the info.funds list before performing validation to ensure that duplicate entries of the same denomination are merged into a single entry with the correct total amount.
Use an aggregation function like the aggregate_coins():
-   use amm::coin::{get_factory_token_creator, is_factory_token};
