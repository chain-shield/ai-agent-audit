Incorrect test logic for divide_by_zero edge case, causing invalid test results
oakcobalt
68
Sufficient
383d ago
Finding description and impact

Tests are in scope according to readme. In contracts/farm-manager/tests/integration.rs, unit test test_query_rewards_divide_by_zero is intended to test that division by zero revert in reward claiming cases have been mitigated by current contract implementation.

However, the test result is not valid due to an incorrect test logic. And the impacts of division by zero causing reward claiming DOS persists.

Vulnerability: test_query_rewards_divide_by_zero only creats one position, which doesn't validate the common cases where a user have multiple positions in various farms.

The only reason the current test passes is because the user only opened one position in the test, so the last_claimed_epoch value is cleared for the user when the only position is closed. When a new position opened later on in the test, the claim -> calculate_rewards flow will only start iterating epochs from after the new position, skipping prior zero contract weights in the iteration.
(flows: close_position -> reconcile_user_state (last_claimed_epoch value is cleared). claim -> calculate_rewards -> compute_start_from_epoch_for_address -> get_earliest_address_lp_weight )

Proof of Concept

A vulnerable case that will cause the test to fail:

Bob opens two positions - one in Lp-denom1, the other in Lp-denom2.
Bob closes the position in Lp-denom1. The other position is still open.
After a few epochs, Bob opens a new position in Lp-denom1.
Bob claim / query_rewards will be DOSsed due to division by zero error.
