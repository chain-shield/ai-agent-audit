Operational issues due to inability to manage individual pools
19
Sufficient
383d ago
Finding description and impact

The current implementation of the liquidity pool management system utilizes a universal config.feature_toggle that governs the ability to enable or disable swaps, deposits, and withdrawals across all pools. This design choice introduces significant operational complexities, as it lacks the flexibility to manage individual pools based on their specific conditions or requirements.

When a single toggle controls all pools, it can lead to unintended operation issues.

Proof of Concept

Currently the config settings control all pools:

    /// Pool feature toggle, can control whether swaps, deposits, and withdrawals are enabled.
    #[cw_serde]
    pub struct FeatureToggle {
        /// Whether or not swaps are enabled
        pub withdrawals_enabled: bool,
        /// Whether or not deposits are enabled
        pub deposits_enabled: bool,
        /// Whether or not swaps are enabled
        pub swaps_enabled: bool,
    }
Scenario:

Consider a scenario where a Pool A is experiencing some issues, prompting the need to disable withdrawals temporarily. If the universal toggle is activated, all pools will be affected, including those that are stable and functioning well. This can lead to:

Users in unaffected pools being unable to withdraw liquidity, resulting in frustration.
A stable pool becoming less useful to users due to the inability to perform transactions.

    use amm::pool_manager::FeatureToggle;
#[test]
fn withdrawal_fails_in_pool_1_when_disabled_for_pool_2() {
    let mut suite = TestingSuite::default_with_balances(
        vec![
            coin(1_000_000u128, "uwhale".to_string()),
            coin(1_000_000u128, "uluna".to_string()),
            coin(1_000_000u128, "uusd".to_string()),
            coin(10_000u128, "uom".to_string()),
        ],
        StargateMock::new("uom".to_string(), "8888".to_string()),
    );
    let creator = suite.creator();
    let alice = suite.senders[1].clone();
    let bob = suite.senders[2].clone();
    let charlie = suite.senders[3].clone();

    // Asset denoms 
    let asset_denoms_1 = vec!["uwhale".to_string(), "uluna".to_string()];
    let asset_denoms_2 = vec!["uluna".to_string(), "uusd".to_string()];

    let pool_fees = PoolFee {
        protocol_fee: Fee {
            share: Decimal::zero(),
        },
        swap_fee: Fee {
            share: Decimal::zero(),
        },
        burn_fee: Fee {
            share: Decimal::zero(),
        },
        extra_fees: vec![],
    };

    // Creator and Charlie create two pools
    suite.instantiate_default().add_one_epoch().create_pool(
        &creator,
        asset_denoms_1,
        vec![6u8, 6u8],
        pool_fees.clone(),
        PoolType::ConstantProduct,
        Some("whale.uluna".to_string()),
        vec![coin(1000, "uusd"), coin(8888, "uom")],
        |result| {
            result.unwrap();
        },
    )
    .create_pool(
        &charlie,
        asset_denoms_2,
        vec![6u8, 6u8],
        pool_fees.clone(),
        PoolType::ConstantProduct,
        Some("uluna.uusd".to_string()),
        vec![coin(1000, "uusd"), coin(8888, "uom")],
        |result| {
            result.unwrap();
        },
    );

    // let contract_addr = suite.pool_manager_addr.clone();
    let lp_denom_1 = suite.get_lp_denom("o.whale.uluna".to_string());
    let lp_denom_2 = suite.get_lp_denom("o.uluna.uusd".to_string());

    // Alice then adds liquidity to `uwhale-uluna` pool 
    suite
        .provide_liquidity(
            &alice,
            "o.whale.uluna".to_string(),
            None,
            None,
            None,
            None,
            vec![
                Coin {
                    denom: "uwhale".to_string(),
                    amount: Uint128::from(1_000_000u128),

                Coin {
                    denom: "uluna".to_string(),
                    amount: Uint128::from(1_000_000u128),
                },

            |result| {

                    event.attributes.iter().any(|attr| {
                        attr.key == "share"
                            && attr.value
                                == (Uint128::from(1_000_000u128) - MINIMUM_LIQUIDITY_AMOUNT)
                                    .to_string()
                    })
                }));
            },
        )
        // alice should have 999_000 LP shares (1M - MINIMUM_LIQUIDITY_AMOUNT)
        .query_all_balances(&alice.to_string(), |result| {
            let balances = result.unwrap();

            assert!(balances.iter().any(|coin| {
                coin.denom == lp_denom_1 && coin.amount == Uint128::from(999_000u128)
            }));
        });

    
    // Bob then adds liquidity to `uluna-uusd` pool 
    suite
        .provide_liquidity(
            &bob,
            "o.uluna.uusd".to_string(),
            None,
            None,
            None,
            None,

                Coin {
                    denom: "uluna".to_string(),
                    amount: Uint128::from(1_000_000u128),
                },
                Coin {
                    denom: "uusd".to_string(),
                    amount: Uint128::from(1_000_000u128),
                },
            ],
            |result| {
                // Ensure we got 999_000 in the response which is 1_000_000 less the initial liquidity amount
                assert!(result.unwrap().events.iter().any(|event| {
                    event.attributes.iter().any(|attr| {
                        attr.key == "share"
                            && attr.value
                                == (Uint128::from(1_000_000u128) - MINIMUM_LIQUIDITY_AMOUNT)

                    })
                }));
            },

        // bob should have 999_000 LP shares (1M - MINIMUM_LIQUIDITY_AMOUNT)
        .query_all_balances(&bob.to_string(), |result| {
            let balances = result.unwrap();

            assert!(balances.iter().any(|coin| {
                coin.denom == lp_denom_2 && coin.amount == Uint128::from(999_000u128)

    // As such, `withdrawals_enabled` flag is set to `false`

            None,
            None,
            None,

                deposits_enabled: true,
                swaps_enabled: true,

                res.unwrap();
            },

    suite
        .withdraw_liquidity(
            &alice,

                denom: lp_denom_1.clone(),

                    ContractError::OperationDisabled { .. } => {} // Operation fails here yet theres no issue with this pool at all

Recommended mitigation steps

Develop a mechanism that allows for enabling or disabling of swaps, deposits, and withdrawals on a per-pool basis. This would provide the flexibility needed to manage each pool according to its specific conditions.
