S-289
preliminary_end_epoch can allow setting extensive durations that can result in zero emission rates
Evo
52
Sufficient
383d ago
Impact

Users who set large preliminary_end_epoch values may unintentionally create farms with zero emission rates, effectively freezing farm rewards, as the emission rate calculation divides the total farm amount by the duration (preliminary_end_epoch - start_epoch).

Proof of Concept

When a user creates a farm through the fill_farm function, they can specify a preliminary_end_epoch in the FarmParams. The issue arises in the create_farm function where the emission rate is calculated:

let emission_rate = params
    .farm_asset
    .amount
    .checked_div_floor((preliminary_end_epoch.saturating_sub(start_epoch), 1u64))?;

The validate_farm_epochs function only checks that the preliminary_end_epoch is greater than the start_epoch and current_epoch, but does not set any upper bounds:

ensure!(
    start_epoch < preliminary_end_epoch,
    ContractError::FarmStartTimeAfterEndTime
);

ensure!(
    preliminary_end_epoch > current_epoch,
    ContractError::FarmEndsInPast
);

how this can lead to zero emissions:

User calls fill_farm with params:

farm_asset.amount = 1000 tokens
start_epoch = 100
preliminary_end_epoch = 1_100_000

The validation passes since preliminary_end_epoch > start_epoch, but the emission rate is calculated as:

emission_rate = 1000 / (1_100_000 - 100)
emission_rate = 1000 / 1_099_900
Due to floor division, emission_rate = 0

The farm is created with zero emission rate, No rewards can be distributed despite having deposited farm_asset.amount tokens.

The issue is exacerbated because:

The contract validates MIN_FARM_AMOUNT but not minimum emission rate
Users may not understand that increasing duration decreases rewards per epoch
The floor division means any rate < 1 becomes zero
Tools Used

Manual Review

Recommended Mitigation Steps

Add validation to ensure preliminary_end_epoch does not result in an emission rate below 1 token per epoch by checking that farm_asset.amount / (preliminary_end_epoch - start_epoch) >= 1.

I understand the validator suggests or believes creating a farm with such a long duration that results in zero emissions isn't a realistic scenario, by comparing this to natural reward dilution when many users participate in a farm, as the validator suggests that admin intervention as a mitigation.

However, A bad actor can create seemingly legitimate but non-functional farms, attracting users to lock LP tokens with promises of rewards that can never materialize due to the zero emission rate.

While natural reward dilution happens gradually and transparently allowing user exit, zero-emission farms are technically broken from inception, invisible to users until funds are locked, and represent deliberate exploitation rather than market dynamics.

Finally the admin mitigation introduces delays between farm creation and detection, allowing non-functional farms to exist where funds are deposited but zero rewards can be distributed due to the emission rate calculation, effectively freezing the farm's reward mechanism despite having sufficient farm_asset.amount tokens.

This represents a technical vulnerability that can be weaponized for user harm, causing immediate farm dysfunction and requiring admin intervention, while fundamentally undermining protocol trust - making it more severe than a simple economic inefficiency. suggesting to leave it as submitted medium.

Mitigation:

// Add to state.rs or constants
pub const MIN_EMISSION_RATE: Uint128 = Uint128::new(1);
pub const MAX_FARM_DURATION: u64 = 52 * 7 * 24; // Example: max 1 year in epochs

// In helpers.rs validate_farm_epochs function
pub(crate) fn validate_farm_epochs(
    params: &FarmParams,
    current_epoch: u64,
    max_farm_epoch_buffer: u64,
) -> Result<(u64, u64), ContractError> {
    // ... existing validations ...

    let duration = preliminary_end_epoch.saturating_sub(start_epoch);
    
    // Validate duration isn't too long
    ensure!(
        duration <= MAX_FARM_DURATION,
        ContractError::FarmDurationTooLong {
            max: MAX_FARM_DURATION,
            provided: duration
        }
    );

    // Validate emission rate won't be zero
    let emission_rate = params
        .farm_asset
        .amount
        .checked_div_floor((duration, 1u64))?;

    ensure!(
        emission_rate >= MIN_EMISSION_RATE,
        ContractError::EmissionRateTooLow { 
            min_rate: MIN_EMISSION_RATE,
            calculated_rate: emission_rate,
            duration
        }
    );

    Ok((start_epoch, preliminary_end_epoch))
}

This validation enforces a minimum emission rate and maximum farm duration, preventing zero-emission scenarios while maintaining the protocol's ability to support sustainable long-term farming operations.

Note: The mitigation provided is a suggested approach - the protocol team should carefully review and adjust the constants (MIN_EMISSION_RATE, MAX_FARM_DURATION) based on their specific requirements and economic model.
