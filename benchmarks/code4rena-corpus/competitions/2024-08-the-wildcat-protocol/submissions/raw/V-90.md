# Vulnerability details

## Summary
During the review of the updateSphereXEngineOnRegisteredContracts function, it was identified that the address(0) placeholder is used in the addAllowedSenderOnChainCalldata construction. This usage seems incorrect and may lead to misconfiguration or security issues in adding authorized senders.

## Vulnerability Details
The bug stems from the line where abi.encodeWithSelector is used to encode the call to ISphereXEngine.addAllowedSenderOnChain.selector. Instead of passing engineAddress as the parameter, address(0) is used. This would result in trying to add a sender to a non-existent engine address, which could prevent proper function execution. Essentially, the authorization of senders on the SphereX Engine would be skipped, and this could lead to system vulnerabilities or incorrect configurations.

## Impact
If left uncorrected, the system may fail to add the intended addresses to the list of allowed senders on the SphereX Engine. As a result, contracts that rely on the proper authorization of senders will not function as expected, potentially allowing unauthorized transactions or preventing legitimate ones from being processed. This could disrupt the security mechanisms of the protocol.

## Proof of Concept
In the current code:
solidity
Copy code
if (engineAddress != address(0)) {
  addAllowedSenderOnChainCalldata = abi.encodeWithSelector(
    ISphereXEngine.addAllowedSenderOnChain.selector,
    address(0)
  );
}
The issue lies in the address(0) parameter. When executed, it will try to add a non-existent address, resulting in faulty authorization. Replacing address(0) with engineAddress resolves this issue.

•	Manual code review and analysis.

## Recommended Mitigation Steps
Replace address(0) with engineAddress in the line that constructs the addAllowedSenderOnChainCalldata variable. The updated code should look like this:
solidity
Copy code
if (engineAddress != address(0)) {
  addAllowedSenderOnChainCalldata = abi.encodeWithSelector(
    ISphereXEngine.addAllowedSenderOnChain.selector,
    engineAddress
  );
}
This will ensure that the correct engineAddress is used when adding authorized senders to the SphereX Engine.
