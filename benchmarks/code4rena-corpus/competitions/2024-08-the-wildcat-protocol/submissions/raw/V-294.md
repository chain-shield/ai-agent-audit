# Vulnerability details

## Summary

The Wildcat protocol uses a custom ERC20 implementation for its market tokens, defined in the WildcatMarketToken contract. This contract implements the standard ERC20 functions like transfer, transferFrom, and approve. The transferFrom function allows a spender, approved by the token owner, to transfer tokens on their behalf.

The transferFrom function in the WildcatMarketToken contract does not update the scaled balance of the sender's account correctly. This enables a malicious spender to drain the sender's balance over multiple transactions, effectively duplicating the market tokens.

## Details

The _transfer function in WildcatMarketToken handles both transfer and transferFrom calls. The function scales the transfer amount using the market's current scale factor, obtained from the _getUpdatedState() function. This ensures that the transfer amount reflects the accrued interest.

In the case of transferFrom, the function correctly reduces the spender's (msg.sender) scaled balance but fails to reduce the sender's (the from address in transferFrom) scaled balance. This oversight allows the sender's scaled balance to remain inflated, even after tokens have been transferred from their account.

A malicious spender, with a sufficient allowance, can repeatedly call transferFrom to drain the sender's funds, as the sender's scaled balance remains artificially high.

## Impact

Malicious spender can steal market tokens from unsuspecting users who have granted them an allowance.

## Scenario

- A user approves a malicious spender to spend a certain amount of their market tokens.
- The malicious spender calls the transferFrom function multiple times, transferring small amounts of tokens to their own account.
- Due to the bug, the sender's scaled balance is not reduced after each transfer, allowing the malicious spender to transfer more tokens than their approved allowance.
- The malicious spender repeats this process, potentially draining a significant portion, or even all, of the sender's market tokens.

## Fix

To resolve this vulnerability, the _transfer function needs to correctly update the sender's scaled balance in the context of a transferFrom call. This can be achieved by adding a condition that specifically targets transferFrom calls and updates the sender's balance accordingly.

```solidity
// WildcatMarketToken.sol

function _transfer(address from, address to, uint256 amount, uint baseCalldataSize) internal virtual {
  // ... Existing code ...

  // For transferFrom, reduce the sender's scaled balance
  if (from != msg.sender) {
      fromAccount.scaledBalance -= scaledAmount;
      _accounts[from] = fromAccount;
  }

  // ... Existing code ...
}
```
