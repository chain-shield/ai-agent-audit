# Vulnerability details

## Impact

'originalReserveRatioBips' is cast to 'uint16', meaning that if it exceeds 65,535 bips (which is 655.35%), it will be truncated.

'boundRelativeDiff' is similarly cast, so if the value of boundRelativeDiff exceeds 65,535, it will also be truncated.

If the values of the reserve ratios or the differences in interest rates can reasonably be expected to exceed 65,535, this downcasting can introduce significant risks to the accuracy and correctness of the function's logic.

## Proof of Concept

A uint256 can hold values up to 2256−12256−1, while a uint16 can only hold values up to 216−1216−1 (i.e., 65,535). If any of the values you're trying to assign to temporaryReserveRatioBips exceed this limit (65,535), the values will wrap around, leading to unexpected behavior. For instance, if the calculated value for originalReserveRatioBips or MathUtils.max(boundRelativeDiff, originalReserveRatioBips) exceeds 65,535, it will overflow, and only the least significant 16 bits of the number will be kept. This could lead to incorrect values being returned.

            originalAnnualInterestBips,

## Recommended Mitigation Steps

Implement The SafeCast library from OpenZeppelin to provides safe casting functions for converting between different unsigned integer types. 

Use the 'SafeCast.toUint16' for safe downcasting to 'uint16'

This method will revert the transaction with a helpful error message if 'originalReserveRatioBips' exceeds the 'uint16' range, preventing unexpected behavior
