# Vulnerability details

## Proof of Concept
In the `LibStoredInitCode` library, the bytecode used for deploying contracts includes the PUSH0 opcode. This opcode is intended to push the constant value 0 onto the stack during the contract creation process. Here is a relevant [snippet](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/libraries/LibStoredInitCode.sol#L32) from the contract:
```solidity
mstore(data, or(shl(64, add(size, 1)), 0x6100005f81600a5f39f300))
```
In the bytecode `0x6100005f81600a5f39f300`:
- `5f` represents the `PUSH0` opcode, which pushes the constant `0` onto the stack.
- This usage is crucial for the initialization code as it modifies how the code is constructed and deployed.
The purpose of this code is to prepend certain instructions to the contract's bytecode to facilitate deployment with the `create` opcode, ensuring the deployed code cannot be executed directly.

[Polygon zkEVM](https://support.polygon.technology/support/solutions/articles/82000902446-does-polygon-zkevm-support-the-push0-opcode-and-are-there-any-other-opcodes-different-from-ethereu), and possibly other Layer 2 networks, does not support the `PUSH0` opcode. This lack of support means that any contract deployment that includes this opcode will fail, as the network cannot interpret or handle the instruction correctly.
The likelihood of this issue occurring is high if deploying the contract on unsupported networks, like Polygon zkEVM. Given that the contract is expected to run across multiple networks, this is a critical compatibility issue that should be addressed to avoid deployment failures.
## Impact
The primary impact of this issue is that the contract may fail to deploy on networks like Polygon where the PUSH0 opcode is unsupported. This failure can prevent the contract from being created and utilized, leading to potential disruptions in the intended functionality of the protocol.

## Tools Used
Manual
## Recommended Mitigation Steps
Use an older Solidity compiler version that does not include the `PUSH0` opcode in the compiled bytecode, such as Solidity version `0.8.19`.
