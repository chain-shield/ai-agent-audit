# Vulnerability details

## Impact
A malicious actor who is both a borrower and lender in their own market can abuse the escrow mechanism designed for sanctioned accounts, by cycling funds through the market and into escrow repeatedly, as a dangerous impact behind this it enables money laundering.

## Proof of Concept
The vulnerability stems from the interaction between the market's withdrawal process, the sanctions escrow mechanism, and the borrower's ability to override sanctions. 

**Scenario of the issue:**
- A malicious actor deploys a market with a very short or zero withdrawal batch duration [L213](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarketBase.sol#L213)
- The actor lends a significant amount to their own market.
- They borrow from the market.
- The actor gets their lender address sanctioned (or uses an already sanctioned address).
- The `nukeFromOrbit` function is called, triggering the escrow mechanism.

[L82-L88](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarketConfig.sol#L82-L88)
```Solidity
function nukeFromOrbit(address accountAddress) external nonReentrant sphereXGuardExternal {
  if (!_isSanctioned(accountAddress)) revert_BadLaunchCode();
  MarketState memory state = _getUpdatedState();
  hooks.onNukeFromOrbit(accountAddress, state);
  _blockAccount(state, accountAddress);
  _writeState(state);
}
```

The `_blockAccount` function queues a withdrawal for the sanctioned account:
[L292-L315](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarket.sol#L292-L315)
```Solidity
  function _blockAccount(MarketState memory state, address accountAddress) internal override {
    Account memory account = _accounts[accountAddress];
    if (account.scaledBalance > 0) {
      uint104 scaledAmount = account.scaledBalance;

      uint256 normalizedAmount = state.normalizeAmount(scaledAmount);

      uint32 expiry = _queueWithdrawal(
        state,
        account,
        accountAddress,
        scaledAmount,
        normalizedAmount,
        msg.data.length
      );

      emit_SanctionedAccountAssetsQueuedForWithdrawal(
        accountAddress,
        expiry,
        scaledAmount,
        normalizedAmount
      );
    }
  }
```

Due to the short/zero withdrawal batch duration, the withdrawal can be executed immediately, moving assets to the escrow contract.
The actor, as the borrower, overrides the sanction status:
`overrideSanction` [L96](https://github.com/code-423n4/2024-08-wildcat/blob/main/src/WildcatSanctionsSentinel.sol#L96)
```Solidity
function overrideSanction(address account) public override {
  sanctionOverrides[msg.sender][account] = true;
  emit SanctionOverride(msg.sender, account);
}
```

They then release the assets from escrow:


## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a mandatory cooldown period after a sanction override before funds can be released from escrow. This cooldown should be at least as long as the market's normal withdrawal batch duration.
