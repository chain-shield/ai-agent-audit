# Vulnerability details

## Proof of Concept
The HooksFactory.deployHooksInstance() function deploys a hooks instance for an approved template with constructor args. However, calling this function may cause a DOS.

The HooksFactory.deployHooksInstance() function calls the _deployHooksInstance() function, which deploys the hookInstance contract to the hooksInstance address. This is done using the create function:
https://github.com/code-423n4/2024-08-wildcat/blob/main/src/HooksFactory.sol#L319
hooksInstance := create(0, initCodePointer, initCodeSizeWithArgs)

The parameters to the create function are known in advance.

An attacker can see a transaction with the HooksFactory.deployHooksInstance() function in the mempool and calculate the hooksInstance address in advance. The attacker can create a contract at the future hooksInstance address. The user will receive an error when calling the deployHooksInstance() function.

## Recommended Mitigation Steps
Add msg.sender parameter to salt
