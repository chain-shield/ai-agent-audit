# Vulnerability details

## Summary
The `rescueTokens` function in the `WildcatMarket.sol` contract allows only the borrower to rescue tokens that are mistakenly sent to the contract. However, the check on which tokens can be rescued only prevents the contract's own tokens and the `asset` token from being transferred, leaving the function susceptible to misuse. Attackers could rescue any other token from the contract, which may include protocol-integrated tokens or tokens with critical functionality.

## Impact
This vulnerability allows an authorized user (the borrower) to transfer arbitrary tokens from the contract to themselves. In protocols that interact with multiple tokens, including governance or staking tokens, this can result in the unintended loss of funds or disruption of the protocol’s tokenomics. Critical assets stored in the contract, aside from the `asset` token, are not adequately protected from unauthorized transfers.

If the borrower has enough authority, they could exploit this flaw to drain important protocol assets, leading to significant financial loss and potential denial of service (DoS) for other users.

## Proof of Concept
1. Deploy the `WildcatMarket.sol` contract.
2. Send an arbitrary token (e.g., a governance token) to the contract.
3. Call the `rescueTokens` function as the borrower with the governance token address.
4. Observe that the token is transferred to the borrower's address.

```solidity
// Example exploit scenario
IERC20 governanceToken = IERC20(governanceTokenAddress);
wildcatMarket.rescueTokens(address(governanceToken));

// Token is transferred to the borrower, leading to potential loss of funds
```

## Tools Used

## Recommended Mitigation Steps
- **Enhance access control**: Modify the `rescueTokens` function to allow only an admin or multisig to call the function. This will ensure that the process of rescuing tokens is tightly controlled and cannot be abused by the borrower.

- **Add a whitelist of tokens**: Implement a whitelist of tokens that can be rescued. Only tokens that are not critical to the protocol's operation should be allowed for rescue.

```solidity
function rescueTokens(address token) external onlyAdmin {
// Prevent rescue of protocol-integrated tokens
require(!isProtectedToken(token), "Protected token cannot be rescued");
token.safeTransferAll(msg.sender);
}
```
