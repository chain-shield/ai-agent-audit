# Vulnerability details

## Details

The `AccessControlHooks` allows for address `deployer` to be provided manually during its deployment in its constructor.

Problem with this is that there is no check with the `ArchController` that the passed in `deployer` address is indeed a registered `borrower` since this provided `deployer` address is assigned as the `borrower` address.

Now in `AccessControlHooks::setMinimumDeposit` it is assumed that a legitimate `borrower` would like to reset the `minimumDeposit` for any of his markets. Issue here is that any `borrower`, or any person generally, can reset the `minimumDeposit` for any hooked market which can be freely gotten via `AccessControlHooks::getHookedMarket`. There is no check that `borrower` owns the hooked `market`.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Verify `deployer` eligibility via `WildcatArchController::isRegisteredBorrower` before assigning as `borrower`. Also include checks to ensure `borrower` can only exact changes on his hooked markets only.
