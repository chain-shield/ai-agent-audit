# Vulnerability details

## Impact
Interest, along with protocol fees, can be accrued twice within the same transaction.

## Description
When a `lender` intends to deposit into the market, they call the [depositUpTo](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarket.sol#L55) function. During this process, the `_getUpdatedState()` function is invoked to retrieve the current state of the market:
```solidity
58    // Get current state
59    MarketState memory state = _getUpdatedState();
```

This call returns the `MarketState` after accruing interest, if any has accumulated.

The `_getUpdatedState` function first checks for any expired withdrawals and then attempts to accrue the [interest](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarketBase.sol#L416):
```solidity
  // Handle expired withdrawal batch
    if (state.hasPendingExpiredBatch()) {
      uint256 expiry = state.pendingWithdrawalExpiry;
      // Only accrue interest if time has passed since last update.
      // This will only be false if withdrawalBatchDuration is 0.
      uint32 lastInterestAccruedTimestamp = state.lastInterestAccruedTimestamp;
      if (expiry != lastInterestAccruedTimestamp) {
        (uint256 baseInterestRay, uint256 delinquencyFeeRay, uint256 protocolFee) = state
          .updateScaleFactorAndFees(
            delinquencyFeeBips,
            delinquencyGracePeriod,
            expiry
          );
```

Interest is then accrued again if `block.timestamp != lastInterestAccruedTimestamp`:
```solidity
// Apply interest and fees accrued since last update (expiry or previous tx)
    if (block.timestamp != lastInterestAccruedTimestamp) {
      (uint256 baseInterestRay, uint256 delinquencyFeeRay, uint256 protocolFee) = state
        .updateScaleFactorAndFees(
          delinquencyFeeBips,
          delinquencyGracePeriod,
          block.timestamp
        );
```


### The Problem:

In the current implementation, interest can be accrued twice in the same transaction.

Consider this scenario:

- Assume there's an expired withdrawal with an expiry of `lastInterestAccruedTimestamp - (expiry - 10)` (just enough for it to be less than the expiry, meeting the condition to trigger the `if` statement).
- Interest is accrued, and `state.lastInterestAccruedTimestamp` is updated to the `expiry`. The expired withdrawal is then processed.

At this point, the second `if` statement:

```solidity
// Apply interest and fees accrued since last update (expiry or previous transaction)     if (block.timestamp != lastInterestAccruedTimestamp) {`

```
will return `true` if the lender calls the `depositUpTo` function at a `timestamp` that is different from the `expiry`. This results in interest being accrued a second time, causing it to be applied twice in the same transaction.
## Tools Used

Manual review

## Recommended Mitigation Steps

Ensure that interest is calculated only once within the same transaction (or block), or implement a mechanism to ensure that multiple calculations have no impact on the final interest accrued or the protocol's overall state
