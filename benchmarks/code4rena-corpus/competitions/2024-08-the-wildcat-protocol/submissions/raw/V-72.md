# Vulnerability details

## Proof of Concept
In the `WildcatSanctionsSentinel` contract, the `createEscrow` function allows any user to deploy an escrow contract for any borrower and subsequently modify the `sanctionOverrides` mapping for that borrower. Here’s how it works:
```solidity
  function createEscrow(
    address borrower,
    address account,
    address asset
  ) public override returns (address escrowContract) {
    escrowContract = getEscrowAddress(borrower, account, asset);

    // Skip creation if the address code size is non-zero
    if (escrowContract.code.length != 0) return escrowContract;

    tmpEscrowParams = TmpEscrowParams(borrower, account, asset);

    new WildcatSanctionsEscrow{ salt: _deriveSalt(borrower, account, asset) }();

    emit NewSanctionsEscrow(borrower, account, asset);

    sanctionOverrides[borrower][escrowContract] = true;

    emit SanctionOverride(borrower, escrowContract);

    _resetTmpEscrowParams();
  }
```
Escrow Address Calculation: The function calculates the escrow contract address using the `getEscrowAddress` function.
This function computes the address where the escrow contract will be deployed using the CREATE2 opcode, but it does not validate if `msg.sender` is the specified borrower:
```solidity
function getEscrowAddress(
    address borrower,
    address account,
    address asset
  ) public view override returns (address escrowAddress) {
    bytes32 salt = _deriveSalt(borrower, account, asset);
    bytes32 initCodeHash = WildcatSanctionsEscrowInitcodeHash;
    assembly {
      // Cache the free memory pointer so it can be restored at the end
      let freeMemoryPointer := mload(0x40)

      // Write 0xff + address(this) to bytes 11:32
      mstore(0x00, or(0xff0000000000000000000000000000000000000000, address()))

      // Write salt to bytes 32:64
      mstore(0x20, salt)

      // Write initcode hash to bytes 64:96
      mstore(0x40, initCodeHash)

      // Calculate create2 hash
      escrowAddress := and(keccak256(0x0b, 0x55), 0xffffffffffffffffffffffffffffffffffffffff)

      // Restore the free memory pointer
      mstore(0x40, freeMemoryPointer)
    }
  }
```
Sanction Override Impact: After creating the escrow contract, the function updates the `sanctionOverrides` mapping to mark the newly created escrow address as an override:
```solidity
sanctionOverrides[borrower][escrowContract] = true;
```
This means the created escrow contract is now considered an exception to the sanction rules for the borrower.
No Borrower Validation: The function does not check if `msg.sender` is the same as the borrower parameter. Thus, any user can call this function with arbitrary borrower addresses. The `sanctionOverrides` mapping will then be updated based on the provided borrower, not the caller's identity.
## Impact
This design flaw allows any user to create an escrow contract for any borrower and modify the `sanctionOverrides` mapping to bypass sanctions. For example, a malicious user could deploy an escrow contract for a borrower they do not control and override the sanctions that would normally apply to the actual borrower. This could result in unauthorized changes to sanction status, potentially allowing a sanctioned borrower to evade restrictions.
## Tools Used
Manual
## Recommended Mitigation Steps
Add a validation check to ensure that `msg.sender` is indeed the borrower.
