# Vulnerability details

## Summary:
In the AccessControlHooks.sol contract, the onlyBorrower modifier is used for critical functions. If the borrower's account is compromised, it could lead to significant risks since sensitive functions like blockFromDeposits and addRoleProvider rely solely on this account's control.

## Vulnerability Details:
The onlyBorrower modifier restricts critical operations to a single account. If this account is compromised, an attacker can block/unblock deposits or modify roles, impacting key aspects of the market. The borrower typically has a single account, so there's no additional protection beyond this.
## Impact:
Compromising the borrower account could give an attacker full control over critical functions, such as managing deposits and roles, leading to potentially harmful actions like blocking valid users or manipulating market behavior.

## Proof of Concept:

Functions like blockFromDeposits and unblockFromDeposits use the onlyBorrower modifier:
function blockFromDeposits(address account) external onlyBorrower {
    LenderStatus memory status = _lenderStatus[account];
    status.isBlockedFromDeposits = true;
    _lenderStatus[account] = status;
    emit AccountBlockedFromDeposits(account);
}
function blockFromDeposits(address account) external onlyBorrower {
    LenderStatus memory status = _lenderStatus[account];
    if (status.hasCredential()) {
      status.unsetCredential();
      emit AccountAccessRevoked(account);
    }
    status.isBlockedFromDeposits = true;
    _lenderStatus[account] = status;
    emit AccountBlockedFromDeposits(account);
  }

## Recommended Mitigation Steps:
Introduce a mandatory multi-signature (multisig) wallet or role-based access control (RBAC) to improve security. This would allow the borrower to authorize multiple accounts, ensuring that critical actions require approvals from multiple parties, reducing the risk from a compromised single account.
Or
Introduce role-based access control (RBAC), enforcing multiple authorized accounts (e.g., onlyAuthorized) to approve actions . Instead of relying on a single borrower, this approach makes it mandatory to have multiple authorizers. You may force an additional account for the borrowers without forcing the use of multi-sig wallet 
Here's a simple example:
mapping(address => bool) public authorizedAddresses;

modifier onlyAuthorized() {
    require(authorizedAddresses[msg.sender], "Not authorized");
    _;
}
function blockFromDeposits(address account) external onlyAuthorized {
    // Critical logic
}
This solution ensures that multiple approvals are required for sensitive functions, improving overall security.
