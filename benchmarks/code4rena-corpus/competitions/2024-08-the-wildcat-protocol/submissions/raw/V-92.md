# Vulnerability details

## Summary
The current asset blacklist management in Wildcat Protocol presents a context inconsistency. While borrower registration is correctly market-specific, blacklisting of entities should be shared across the entire Wildcat ecosystem. Both the protocol owner and individual market owners should be able to manage blacklisted entities to ensure comprehensive risk management.
## Vulnerability Details
The Wildcat Protocol allows only the onlyOwner to manage blacklisted entities, centralizing the process. However, both the protocol owner and market owners should have the authority to blacklist entities, as certain blacklisted entities might pose risks across multiple markets. Centralizing the blacklist could result in delayed responses from market owners who have critical information about specific risks that should be mitigated immediately.
## Impact
If only the onlyOwner has the authority to manage blacklisted entities, it could slow down the reaction to security threats and limit market autonomy. Markets may have immediate risks that require blacklisting entities without relying on the protocol owner’s intervention, potentially exposing the entire ecosystem to risks.
## Proof of Concept
The following code centralizes the blacklist process under onlyOwner:
solidity
function addBlacklist(address asset) external onlyOwner {
    if (!_assetBlacklist.add(asset)) {
        revert AssetAlreadyBlacklisted();
    }
    emit AssetBlacklisted(asset);
}

function removeBlacklist(address asset) external onlyOwner {
    if (!_assetBlacklist.remove(asset)) {
        revert AssetNotBlacklisted();
    }
    emit AssetPermitted(asset);
}
This prevents market owners from acting on potential threats immediately.

## Recommended Mitigation Steps
Allow both the protocol owner and market owners to manage blacklisted entities. This can be achieved by modifying the addBlacklist and removeBlacklist functions to enable market-specific blacklists while ensuring that blacklists are shared across the entire Wildcat ecosystem when necessary. Here’s a suggested approach:
solidity
function addBlacklist(address asset) external onlyOwnerOrMarketOwner {
    if (!_assetBlacklist.add(asset)) {
        revert AssetAlreadyBlacklisted();
    }
    emit AssetBlacklisted(asset);
}
This way, both owners and market owners can add entities to the blacklist, ensuring more comprehensive and responsive risk management across the protocol.
