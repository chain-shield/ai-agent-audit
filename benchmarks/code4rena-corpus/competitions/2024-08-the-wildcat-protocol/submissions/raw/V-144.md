# Vulnerability details

## Impact
Detailed description of the impact of this finding.

In the LenderStatus struct, the contract stores information such as the lastApprovalTimestamp, lastProvider, and canRefresh status. While this data is not sensitive like private keys or personal identifiers, it may still be considered sensitive depending on the application. Storing such information on-chain makes it publicly accessible, which could expose the lender’s status and interaction history to anyone. This could potentially be exploited for profiling users or identifying patterns in their on-chain activity.

## Proof of Concept

The following data stored on-chain can be publicly read by anyone:
```sol
struct LenderStatus {
  bool isBlockedFromDeposits;
  address lastProvider;
  bool canRefresh;
  uint32 lastApprovalTimestamp;
}
```

Any user can retrieve this data through publicly accessible functions or by directly querying the blockchain, exposing lender credential information to the public:
```sol
LenderStatus lenderStatus = lenderStatuses[someLenderAddress];
```

## Recommended Mitigation Steps

While encrypting data on-chain is complex due to the public nature of the blockchain, you can minimize exposure by only storing essential data on-chain and moving sensitive data off-chain. For example, sensitive information like lastApprovalTimestamp could be hashed, and the actual value could be stored off-chain. Additionally, you could use zero-knowledge proofs (ZKPs) or other privacy-preserving techniques.
Example mitigation (hashed sensitive data):
```sol
struct LenderStatus {
  bool isBlockedFromDeposits;
  address lastProvider;
  bool canRefresh;
  bytes32 hashedApprovalData;
}

function setCredential(LenderStatus memory status, uint256 approvalTimestamp) internal pure {
  status.hashedApprovalData = keccak256(abi.encodePacked(approvalTimestamp));
}

function verifyApprovalData(LenderStatus memory status, uint256 approvalTimestamp) internal view returns (bool) {
  return status.hashedApprovalData == keccak256(abi.encodePacked(approvalTimestamp));
}
```
