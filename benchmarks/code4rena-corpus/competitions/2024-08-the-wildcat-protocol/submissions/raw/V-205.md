# Vulnerability details

## Proof of Concept

In the WildcatMarketWithdrawals contract, there's a critical vulnerability in the _isSanctioned function inherited from WildcatMarketBase. The issue arises from incorrect construction of calldata in inline assembly, leading to a misaligned function selector and arguments. This misalignment causes the sanction check to fail, allowing sanctioned addresses to interact with the contract.

-> The problem here come in some way from "WildcatMarketBase/_isSanctioned" (My other finding)

Issue Explanation:

Function Selector Misalignment:
The function selector 0x06e74444 is stored at memory address 0x00 using mstore(0, 0x06e74444).
Since mstore writes 32 bytes and the selector is only 4 bytes, it occupies the most significant 4 bytes, leaving the least significant 28 bytes as zeros.
This misalignment causes the sentinel contract to receive incorrect calldata.
Incorrect Calldata Construction:
The arguments are stored at 0x20 and 0x40, but the staticcall uses an offset (0x1c) and length (0x44) that don't align properly with the calldata structure.
According to the Ethereum ABI, the function selector should be in the first 4 bytes, immediately followed by the arguments.
Impact:

Due to the malformed calldata:

The sentinel contract may fail to recognize the function call properly.
The sanction check might return a default value or fail silently.
Sanctioned addresses can bypass the check and interact with the contract.

## Recommended Mitigation Steps

- Correctly Align the Function Selector:
Shift the function selector to occupy the least significant 4 bytes.

- Adjust staticcall Parameters maybe too :
Update the offset and length to match the correctly constructed calldata as that "let success := staticcall(
    gas(),
    _sentinel,
    ptr,    // Calldata starts at `ptr`
    68,     // Total length: 4 + 32 + 32 bytes
    ptr,
    32
)"
