# Vulnerability details

## Impact
- Inconsistent Key Size: If the contract's logic elsewhere relies on the `expiry` value being of type `uint256`, using a `uint32` here could lead to mismatches or incorrect accesses, as there could be a disparity between the actual stored keys and the key being used to retrieve data.
- Limited Range: A `uint32` can represent values from `0` to `4_294_967_295`. If there's a possibility that `expiry` should represent a larger value, the `uint32` type will truncate the value, potentially leading to incorrect behavior.

## Proof of Concept
Here is the mapping variable declared in the `Withdraw.sol` library: `mapping(uint256 => mapping(address => AccountWithdrawalStatus)) accountStatuses;`. the first key is on type `uint256`. But while calling this mapping in the `WildcatMarketWidrawals::getAccountWithdrawalStatus` function, the provided key has the type `uint32`. The same in the `WildcatMarketWidrawals::getAvailableWithdrawalAmount`, `WildcatMarketWidrawals::_queueWithdrawal` and `WildcatMarketWidrawals::_executeWithdrawal` functions

```solidity
   function getAccountWithdrawalStatus(
    address accountAddress,
@>  uint32 expiry
  ) external view nonReentrantView returns (AccountWithdrawalStatus memory status) {
@>  AccountWithdrawalStatus storage _status = _withdrawalData.accountStatuses[expiry][
      accountAddress
    ];
    status.scaledAmount = _status.scaledAmount;
    status.normalizedAmountWithdrawn = _status.normalizedAmountWithdrawn;
  }
```

## Recommended Mitigation Steps
- Use Consistent Types: If the key in `accountStatuses` is intended to be a `uint256`, it's safer to also use `uint256` for expiry in the `getAccountWithdrawalStatus` function.
- Explicit Casting: If for some reason you must use a `uint32` and you are sure that all `expiry` values fit within `uint32`, you can explicitly cast the key when storing and retrieving values, but this is generally not recommended due to the risk of overflow.
- Document the Range: If the expiry is truly intended to be within the range of a uint32, ensure that this is well-documented, and other parts of the contract adhere to this limitation.
