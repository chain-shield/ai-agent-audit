# Vulnerability details

## Proof of Concept
From the observation of the function using the link below, we can see that the function doesn't implement any restriction to prevent only certain authorised entity to access it. Therefore this can lead to various attack path by a malicious user.

1. Bypassing Sanctions
Sanction Override: Once a user creates an escrow contract for a borrower, that contract becomes a sanction override for that borrower. This means the user can interact with the borrower without restrictions.
Frequent Interactions: The user could engage in multiple transactions with the borrower, effectively bypassing any restrictions intended to prevent such interactions. 
This means that once the contract is created, it can be marked as exempt from any sanctions that would otherwise apply to the borrower's address.

Users could effectively bypass sanctions intended to restrict their financial activities. This could undermine the purpose of the sanctioning mechanism, as the contract they create would be shielded from being blocked or restricted.
Potential Legal Issues:

The integrity of the sanctioning mechanism relies on trust and the ability to enforce restrictions. If users can easily circumvent these rules, it could lead to broader distrust in the platform.

Conclusion
In summary, the ability to create an escrow contract that acts as a sanction override could indeed allow users to interact with other functions in the protocol without the typical restrictions. This highlights the critical need for access controls and proper governance mechanisms to prevent misuse and maintain the integrity of the system.
