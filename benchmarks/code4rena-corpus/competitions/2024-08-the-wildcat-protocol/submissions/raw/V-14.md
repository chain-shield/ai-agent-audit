# Vulnerability details

## Impact
The `repay` function in the contract performs the state check to determine if the market is closed after transferring funds from the caller. This results in the following issues:
1. If the market is closed and the function allows transfers, the funds may be incorrectly handled.
2. Users incur gas costs for transferring assets before the function checks if the market is closed, leading to wasted gas fees if the transaction reverts

## Proof of Concept
1. Call the `repay` function with a non-zero amount when the market is closed.
2. Observe that the function will revert after transferring funds, wasting gas and resulting in a poor user experience.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Refactor the `repay` function to check if the market is closed **before** transferring funds from the caller.

**Updated Function:**

```solidity
function repay(uint256 amount) external nonReentrant sphereXGuardExternal {
    if (amount == 0) revert_NullRepayAmount();

    MarketState memory state = _getUpdatedState();
    if (state.isClosed) revert_RepayToClosedMarket();

    asset.safeTransferFrom(msg.sender, address(this), amount);
    emit_DebtRepaid(msg.sender, amount);

    // Execute repay hook if enabled
    hooks.onRepay(amount, state, _runtimeConstant(0x24));

    _writeState(state);
}
```

**Explanation:**
 By checking the market state before performing the asset transfer, the function avoids unnecessary gas costs and improves efficiency.
