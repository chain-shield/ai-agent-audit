# Vulnerability details

## Vulnerability details
The `totalSupply` function in `MarketStateLib` does not subtract `scaledPendingWithdrawals` when calculating the total circulating supply of market tokens. This results in the function overestimating the actual supply by the amount of pending withdrawals that have not been processed yet. 

As a result, functions that rely on `totalSupply` such as `maximumDeposit`, `borrowableAssets`, and `liquidityRequired` will also overestimate the available liquidity in the market. This could allow a malicious borrower to withdraw excess funds, potentially causing losses for lenders.

## Impact
A malicious borrower could exploit the inflated `totalSupply` value to:
1. Deposit more than the intended maximum, as `maximumDeposit` will return a higher value
2. Borrow more than the actual available liquidity, since `borrowableAssets` will be overestimated  
3. Avoid being marked as delinquent when they should be, because `liquidityRequired` will be calculated using the inflated supply

This could result in the market becoming undercollateralized and lenders losing funds if the excess borrows are not repaid. The impact is High severity as it could lead to direct financial losses.

## Proof of Concept
Consider a market with the following state:
- `scaledTotalSupply` = 1,000,000e27 
- `scaledPendingWithdrawals` = 100,000e27
- `scaleFactor` = 1e27
- Other parameters are negligible for this example

The current `totalSupply` function will return:
`1,000,000e27 / 1e27 = 1,000,000`

However, the actual circulating supply is: 
`(1,000,000e27 - 100,000e27) / 1e27 = 900,000`

The borrower could use this difference of 100,000 tokens to deposit or borrow more than they should be allowed to.

## Recommended Mitigation Steps
Update the `totalSupply` function to subtract `scaledPendingWithdrawals` before normalizing the result:

```solidity
function totalSupply(MarketState memory state) internal pure returns (uint256) {
    return state.normalizeAmount(state.scaledTotalSupply - state.scaledPendingWithdrawals);
}
```

Additionally, the normalization and subtraction can be moved directly into `maximumDeposit` to save a small amount of gas:

```solidity
function maximumDeposit(MarketState memory state) internal pure returns (uint256) { 
    // Combine normalization and subtraction in one step
    return uint256(state.maxTotalSupply).satSub(
        state.normalizeAmount(state.scaledTotalSupply)
        .satSub(state.normalizeAmount(state.scaledPendingWithdrawals))
    );
}
```

This avoids an extra subtraction when `maximumDeposit` is called.
