# Vulnerability details

## Overview
The [addHooksTemplate](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/HooksFactory.sol#L120-L151) function in the `HooksFactory` contract currently permits `address(0)` as a valid hooks template address. This behavior introduces potential risks and inconsistencies, as `address(0)` should not be considered a valid hooks template.

## Description
If an attacker sends `address(0)` as `hooksTemplate` to the function [addHooksTemplate](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/HooksFactory.sol#L120-L151), function will considered `address(0)` a valid hooks template. This lack of validation can lead to unintended behavior, such as bypassing expected checks or compromising the contract's functionality.

## Impact
Allowing `address(0)` as a valid hooks template address introduces the following risks:
1. **Invalid State:** The contract may enter an inconsistent or invalid state if `address(0)` is considered a valid hooks template, as `address(0)` does not correspond to any actual template or implementation.
2. **Security Risks:** Other components or contracts interacting with HooksFactory may assume that a valid hooks template address is always provided. `address(0)` could potentially be exploited to bypass checks or create unintended behaviors.
3. **Functional Inconsistencies:** If the contract is designed to handle hooks templates, allowing `address(0)` violates the expected functionality and design, leading to unreliable or erroneous behavior in dependent systems.
4. **Event Emission Misleading:** Events emitted with `address(0)` could mislead other components or users into believing that a valid template was added when it was not.
