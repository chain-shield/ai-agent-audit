# Vulnerability details

## Proof of Concept
The logic of updating protocol fees is potentially harmful because of unbounded loops in functions `pushProtocolFeeBipsUpdates()` and `pushProtocolFeeBipsUpdates()`. 

These loops go through all markets associated with a given hooks template and update the protocol fee in each of them. 

Given a large number of markets, these loops could consume all available gas, making the functions impossible to execute. 

This could result in unwanted scenarios, e.g., if an admin or anyone else anticipates updating such fees but can't do it due to gas overflow.

For example:

https://github.com/code-423n4/2024-08-wildcat/blob/main/src/HooksFactory.sol#L577-L585


```solidity
	for (uint256 i = 0; i < count; i++) {
      address market = markets[marketStartIndex + i];
      assembly {
        if iszero(call(gas(), market, 0, setProtocolFeeBipsCalldataPointer, 0x24, 0, 0)) {
          // Equivalent to `revert SetProtocolFeeBipsFailed()`
          mstore(0, 0x4484a4a9)
          revert(0x1c, 0x04)
        }
      }
    }
```

## Recommended Mitigation Steps

Handle this situation by introducing a limit on the number of iterations that can be made at once. It would be essential to divide the entire operation into manageable batches. 

Alternatively, you can program the process to automatically continue from where it last stopped each time the operation is started. This way, no matter how extensive the process is, it will eventually complete without consuming excessively high gas.
