# Vulnerability details

The rescueTokens function allows the borrower to transfer the entire balance of any token from the contract, except for the main asset. However, the function does not check the amount or context in which tokens are being transferred. This results in the following critical issues:

No Limit on Token Amounts:

The function transfers all of the specified token's balance in the contract without any limit or restriction on the amount. Any auxiliary tokens (e.g., governance tokens, reward tokens) could be completely drained by the borrower, even if they are essential for the contract's operation.
Risk of Mistaken or Malicious Token Transfer:

Since no additional validation is performed on the token type or its role within the system, any token, apart from the main asset, can be inadvertently or maliciously transferred out. This includes tokens that may be integral to the contract's governance or reward system.
No Role-Based Permissions Beyond Borrower:

The borrower is the only entity with access to this function, but without additional role-based permissions or limits on specific tokens, this privilege could be abused or result in unintended loss of tokens critical for the platform's functionality.



## Proof of Concept
const { expect } = require("chai");

describe("VulnerableContract PoC", function () {
  let owner, user, token, rewardToken, contract;

  beforeEach(async function () {
    [owner, user] = await ethers.getSigners();

    // Deploy mock ERC20 tokens for asset and rewardToken
    const Token = await ethers.getContractFactory("MockERC20");
    token = await Token.deploy("Asset Token", "ASSET", 1000);
    rewardToken = await Token.deploy("Reward Token", "RWRD", 500);

    // Deploy the vulnerable contract
    const VulnerableContract = await ethers.getContractFactory("VulnerableContract");
    contract = await VulnerableContract.deploy(token.address, rewardToken.address);

    // Transfer tokens to the user
    await token.transfer(user.address, 100);
    await rewardToken.transfer(user.address, 50);

    // User approves the contract to spend their tokens
    await token.connect(user).approve(contract.address, 100);
    await rewardToken.connect(user).approve(contract.address, 50);

    // User deposits tokens into the contract
    await contract.connect(user).deposit(token.address, 100);
    await contract.connect(user).deposit(rewardToken.address, 50);
  });

  it("should allow the borrower to rescue all reward tokens", async function () {
    // Check initial contract balances
    expect(await rewardToken.balanceOf(contract.address)).to.equal(50);
    expect(await token.balanceOf(contract.address)).to.equal(100);

    // Borrower rescues reward tokens
    await contract.connect(owner).rescueTokens(rewardToken.address);

    // Verify that all reward tokens are transferred to the borrower
    expect(await rewardToken.balanceOf(owner.address)).to.equal(50);
    expect(await rewardToken.balanceOf(contract.address)).to.equal(0);
  });

  it("should not allow the borrower to rescue the main asset", async function () {
    // Attempt to rescue the main asset, expect it to fail
    await expect(
      contract.connect(owner).rescueTokens(token.address)
    ).to.be.revertedWith("Cannot rescue main asset");
  });
});


## Recommended Mitigation Steps
Limit Token Amounts:

Introduce an additional parameter for specifying the amount of tokens to be transferred, instead of transferring the entire balance. This prevents unintended draining of large quantities of tokens.

function rescueTokens(address token, uint256 amount) external onlyBorrower {
    if (token == address(asset)) revert_BadRescueAsset();
    IERC20(token).transfer(msg.sender, amount);
}
