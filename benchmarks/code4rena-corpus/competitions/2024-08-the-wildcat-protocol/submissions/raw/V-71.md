# Vulnerability details

## Proof of Concept
In the contract, the `registerController` function allows controllers to be registered by a `ControllerFactory`, while the `removeController` function enables the contract owner to remove any registered controller. However, the owner can remove a controller immediately after it is registered, potentially leading to its premature removal.

Here’s the flow:
1.*Controller Registration*: The `registerController` function is designed to allow the `onlyControllerFactory` to register a controller by adding its address to the `_controllers` set. This function also sets the controller as an allowed sender on-chain and emits a `ControllerAdded` event.
```solidity
function registerController(address controller) external onlyControllerFactory {
    if (!_controllers.add(controller)) {
        revert ControllerAlreadyExists();
    }
    _addAllowedSenderOnChain(controller);
    emit ControllerAdded(msg.sender, controller);
}
```
The purpose of this function is to enable the system to register new controllers who can execute specific actions or manage the protocol. Once added, these controllers are expected to remain active unless removed deliberately for a valid reason.
2. *Controller Removal*: The `removeController` function allows the contract owner to remove any registered controller from the `_controllers` set. The function requires the `onlyOwner` modifier, meaning it can be called at any time by the contract owner, regardless of the controller's recent registration.

```solidity
function removeController(address controller) external onlyOwner {
    if (!_controllers.remove(controller)) {
        revert ControllerDoesNotExist();
    }
    emit ControllerRemoved(controller);
}
```
Since there is no restriction on when a controller can be removed after being added, the contract owner could potentially remove a controller immediately after it was registered. This premature removal undermines the purpose of allowing controllers to be registered by the factory, as they can be deactivated without having sufficient time to perform their designated tasks.


## Impact
A recently registered controller can be removed before it has a chance to perform its intended operations, which could disrupt the system's functionality. If a legitimate controller is prematurely removed, critical actions it was supposed to execute might not occur, leading to protocol inefficiencies or unexpected behavior.

Manual
## Recommended Mitigation Steps
Introduce a time-lock mechanism that enforces a minimum duration between the registration of a controller and its possible removal. This would ensure that a controller remains active for a specified period before the owner is allowed to remove it.
