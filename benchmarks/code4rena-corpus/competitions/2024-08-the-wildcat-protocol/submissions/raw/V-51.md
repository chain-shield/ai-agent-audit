# Vulnerability details

## Impact
- Incompatibility Between Contracts
- Increased Complexity in Maintenance
- Different Compiler Behaviors can provoke conflicts between libraries and interfaces used within contracts

## Proof of Concept
The version `solc="0.8.25"` is specify in the `foundry.toml` config file but in some contract some other version was used like `pragma solidity >=0.8.20` in the `WildcatMarketConfig` contract, `pragma solidity >=0.8.25` in the `TransientBytesArray` contract and `pragma solidity >=0.8.24;` in the `LibStoredInitCode` library.

## Recommended Mitigation Steps
- Use a Single Solidity Version: It is generally recommended to standardize on a single Solidity version across your entire project. This ensures consistency in behavior, simplifies deployment and maintenance, and reduces the risk of introducing bugs due to compiler differences.
- Specify an Exact Version: Instead of using pragma solidity >=0.8.20;, specify the exact version you intend to use, such as pragma solidity 0.8.25;. This ensures that all contracts are compiled with the exact same compiler, avoiding issues related to version discrepancies.
