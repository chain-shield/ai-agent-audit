# Vulnerability details

## Summary

The _executeWithdrawal function in WildcatMarketWithdrawals allows a user to withdraw funds from an expired withdrawal batch. The function takes a baseCalldataSize argument, which is intended to indicate the size of the calldata that should be passed to the onExecuteWithdrawal hook.

The function incorrectly uses msg.data.length as the baseCalldataSize when processing withdrawals in a loop with the executeWithdrawals function, which always passes empty extraData. This prevents any calldata from being passed to the onExecuteWithdrawal hook.

## Details

The _executeWithdrawal function in WildcatMarketWithdrawals uses the baseCalldataSize parameter to determine how much calldata to pass to the onExecuteWithdrawal hook.

The executeWithdrawals function calls _executeWithdrawal for each withdrawal request in a loop, using msg.data.length as the baseCalldataSize.

When executeWithdrawals is called, it does not pass any additional data beyond the array arguments, meaning msg.data.length will be equal to the size of the calldata required to encode the two address arrays. This will result in the onExecuteWithdrawal hook being called with empty extraData.

## Impact
This bug prevents hooks from accessing any additional data that may be necessary for their logic when processing withdrawals in a batch.

## Scenario

- A hook contract is deployed that requires additional data to be passed to onExecuteWithdrawal.
- A user calls executeWithdrawals to process multiple withdrawal requests.
- The hook's onExecuteWithdrawal function is called without the necessary data, potentially causing the hook to revert or behave unexpectedly.

## Fix

Modify the executeWithdrawals function to use a constant value of 0x44 for baseCalldataSize when calling _executeWithdrawal, as this is the base size of the calldata required by the hook.


```solidity
// WildcatMarketWithdrawals.sol
 function executeWithdrawals(
        address[] calldata accountAddresses,
        uint32[] calldata expiries
    ) external nonReentrant sphereXGuardExternal returns (uint256[] memory amounts) {
        if (accountAddresses.length != expiries.length) revert_InvalidArrayLength();
        amounts = new uint256[](accountAddresses.length);
        MarketState memory state = _getUpdatedState();
        for (uint256 i = 0; i < accountAddresses.length; i++) {
            // Use 0x44 for baseCalldataSize to ensure extraData is passed to the hook
            amounts[i] = _executeWithdrawal(state, accountAddresses[i], expiries[i], 0x44);
        }
        // Update stored state
        _writeState(state);
        return amounts;
    }
```
