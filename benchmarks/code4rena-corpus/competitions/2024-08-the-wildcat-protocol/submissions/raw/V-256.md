# Vulnerability details

## Proof of Concept
In several functions like onBorrow, onRepay, and onDeposit, the contract manually constructs calldata using assembly when calling external hook contracts. The issue arises from improper placement of the function selector and incorrect calculation of offsets, leading to misalignment of the calldata.

Example in the onBorrow function : 
- mstore(ptr, onBorrowSelector) stores the 4-byte onBorrowSelector in the most significant 4 bytes of the 32-byte word at ptr, which are bytes ptr + 0 to ptr + 3.
- The least significant 28 bytes (bytes ptr + 4 to ptr + 31) are zeros.

-> The external call uses an offset of add(ptr, 0x1c), which is ptr + 28.
This means the calldata sent to the external contract starts at ptr + 28.
-> This misplacement can lead to the external contract receiving an incorrect function selector.

-> Since the function selector is incorrectly placed in the last 4 bytes of the first 32-byte word, starting the call at this offset misaligns the calldata.


Note : The size of the calldata (size) is calculated incorrectly using RepayHook_Base_Size instead of BorrowHook_Base_Size (Fow now, it is not a problem because it is initialized with the same value).

-> Since the function selector is at ptr + 0 to ptr + 3, starting the calldata at ptr + 28 skips the function selector entirely and starts in the padded area.
-> As a result, the external contract can not receive the function selector, which is essential for identifying which function to execute for exemple.



## Recommended Mitigation Steps

Shift the function selector to occupy the most significant 4 bytes of the 32-byte word (28 to 31).
