# Vulnerability details

## Impact

Unprotected initializer in 'deployInitCode', 'createWithStoredInitCode', 'create2WithStoredInitCode', and their overloads.

None of these functions implement access control, which means any contract or address interacting with this library could potentially call these functions and deploy contracts. This is dangerous in contexts where arbitrary contract deployment should be restricted.

Without proper access control, these deployment functions pose significant risks to the security and stability of the entire contract. It is critical to ensure that only authorized parties can invoke them to prevent malicious deployments, resource exhaustion, or unintended interactions with other contracts.

## Proof of Concept

Attackers could supply specially crafted initialization code, which could either contain malicious logic or drain resources by creating inefficient or infinite loops.

The 'create2' opcode allows attackers to precompute and predict the address of the contract being deployed. If they can influence the deployment, they could create addresses that clash with existing contracts or even target specific addresses with malicious contracts.

// SPDX-License-Identifier: Apache-2.0
pragma solidity >=0.8.24;

import "forge-std/Test.sol";
import "../src/LibStoredInitCode.sol";

contract LibStoredInitCodeTest is Test {
    using LibStoredInitCode for bytes;

    function testDeployInitCodeVulnerability() public {
        // Craft malicious init code
        bytes memory maliciousInitCode = hex"600a600c600039600a6000f3602a60205260206020f3"; // Simple contract that stores 42 at storage slot 0

        // Deploy the malicious contract
        address deployedAddress = maliciousInitCode.deployInitCode();

        // Verify the contract was deployed
        assert(deployedAddress != address(0));

        // Check if the deployed contract behaves as expected
        (bool success, bytes memory data) = deployedAddress.staticcall(abi.encodeWithSignature("get()"));
        assert(success);
        assert(abi.decode(data, (uint256)) == 42);
    }

    function testCreateWithStoredInitCodeVulnerability() public {
        // Craft malicious init code
        bytes memory maliciousInitCode = hex"600a600c600039600a6000f3602a60205260206020f3"; // Simple contract that stores 42 at storage slot 0

        // Deploy the malicious contract
        address initCodeStorage = maliciousInitCode.deployInitCode();
        address deployedAddress = LibStoredInitCode.createWithStoredInitCode(initCodeStorage);

        // Verify the contract was deployed
        assert(deployedAddress != address(0));

        // Check if the deployed contract behaves as expected
        (bool success, bytes memory data) = deployedAddress.staticcall(abi.encodeWithSignature("get()"));
        assert(success);
        assert(abi.decode(data, (uint256)) == 42);
    }

    function testCreate2WithStoredInitCodeVulnerability() public {
        // Craft malicious init code
        bytes memory maliciousInitCode = hex"600a600c600039600a6000f3602a60205260206020f3"; // Simple contract that stores 42 at storage slot 0

        // Deploy the malicious contract
        address initCodeStorage = maliciousInitCode.deployInitCode();
        bytes32 salt = keccak256(abi.encodePacked("malicious_salt"));
        address deployedAddress = LibStoredInitCode.create2WithStoredInitCode(initCodeStorage, salt);

        // Verify the contract was deployed
        assert(deployedAddress != address(0));

        // Check if the deployed contract behaves as expected
        (bool success, bytes memory data) = deployedAddress.staticcall(abi.encodeWithSignature("get()"));
        assert(success);
        assert(abi.decode(data, (uint256)) == 42);
    }
}

## Recommended Mitigation Steps

Implement access control mechanisms (like 'onlyOwner' or 'onlyAuthorized') to ensure that only trusted users can deploy contracts through these functions.
