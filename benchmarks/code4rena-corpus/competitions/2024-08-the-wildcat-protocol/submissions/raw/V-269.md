# Vulnerability details

## Impact
Sanctions can be bypassed, potentially allowing sanctioned lenders to withdraw their assets without going through the escrow process.
## Description

Users or lenders can request to withdraw their **expired withdrawal** by calling the **`executeWithdrawal`** function.

https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarketWithdrawals.sol#L194-L210
```solidity
function executeWithdrawal(
    address accountAddress,
    uint32 expiry
  ) public nonReentrant sphereXGuardExternal returns (uint256) {
    MarketState memory state = _getUpdatedState();
    // Use an obfuscated constant for the base calldata size to prevent solc
    // function specialization.
    uint256 normalizedAmountWithdrawn = _executeWithdrawal(
      state,
      accountAddress,
      expiry,
      _runtimeConstant(0x44)
    );
    // Update stored state
    _writeState(state);
    return normalizedAmountWithdrawn;
  }
```

When this function is called, assets will be transferred to the lender. However, if the account is sanctioned by **Chainalysis**, the assets will be transferred to an escrow contract. These assets can only be withdrawn if the sanction is lifted or overridden by the borrower.

A potential issue arises where a lender can bypass this restriction and withdraw their assets immediately. This can be done by utilizing the [createEscrow](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/WildcatSanctionsSentinel.sol#L121) function to override the sanction status, meaning an override from the borrower is not required.

https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/WildcatSanctionsSentinel.sol#L121-L142
```solidity
  function createEscrow(
    address borrower,
    address account,
    address asset
  ) public override returns (address escrowContract) {
     escrowContract = getEscrowAddress(borrower, account, asset);

     // Skip creation if the address code size is non-zero
     if (escrowContract.code.length != 0) return escrowContract;

     tmpEscrowParams = TmpEscrowParams(borrower, account, asset);

     new WildcatSanctionsEscrow{ salt: _deriveSalt(borrower, account, asset) }();

     emit NewSanctionsEscrow(borrower, account, asset);

>    sanctionOverrides[borrower][escrowContract] = true;

     emit SanctionOverride(borrower, escrowContract);

     _resetTmpEscrowParams();
  }
```

Here, the `sanctionOverrides` mapping is set to **`true`**, which essentially marks the account as **not sanctioned** in the [isSanctioned](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/WildcatSanctionsSentinel.sol#L85C2-L87C4) function.

This scenario can unfold as follows:

1. A lender has a withdrawal in the queue and expects to be sanctioned soon.
2. Before the sanction is applied, the lender calls `createEscrow` to override the sanction status.
3. The lender gets sanctioned by **Chainalysis** but, due to the override, the sanction no longer applies.
4. The lender then calls `executeWithdrawal` to withdraw the assets, bypassing the sanction.

By utilizing this method, a sanctioned lender can still withdraw their assets because the `_isSanctioned(accountAddress)` check will return **`false`** after the override.

## Recommended Mitigation Steps

The issue can be mitigated by implementing the following measures:

1. **Make the function internal** so that it can only be called internally or
2. **Keep it external but add modifiers** since external contract may call it , the modifiers will ensure that only the authorized contracts can call it
