# Vulnerability details

## Impact
Detailed description of the impact of this finding.
Title: HooksConfig contract has mcopy function Not Found
•	Severity: High
•	Impact: This will prevent the contract from compiling, making the project unusable until the error is resolved.
•	Status: Unresolved
•	File: HooksConfig.sol
•	Lines Affected: 283

The function mcopy is used multiple times within the HooksConfig.sol file but is not declared anywhere in the codebase, leading to DeclarationError during compilation. This will prevent the contract from compiling, making the project unusable until the error is resolved.

This error impacts the core hook functionalities related to deposits, withdrawals, transfers, borrowing, and repayments, effectively preventing these functions from being executed properly in the deployed system.

The Solidity compiler (solc) reports multiple DeclarationError instances because the mcopy function is not declared anywhere in the source code. This impacts several key hook functions where the mcopy function is used for memory copying purposes.

## Recommended Mitigation Steps
To resolve this issue, the mcopy function needs to be defined. Below is a potential implementation of mcopy, based on its assumed purpose of copying memory from one location to another:
```sol
// Define mcopy to handle memory copying
function mcopy(uint dest, uint src, uint len) internal pure {
    for (; len >= 32; len -= 32) {
        assembly {
            mstore(dest, mload(src)) // copy 32 bytes from src to dest
        }
        dest += 32;
        src += 32;
    }
    if (len > 0) {
        // Copy remaining bytes less than 32
        uint mask = 256 ** (32 - len) - 1;
        assembly {
            let srcpart := and(mload(src), not(mask))
            let destpart := and(mload(dest), mask)
            mstore(dest, or(destpart, srcpart))
        }
    }
}
```
This implementation will copy a block of memory from src to dest, handling both full 32-byte chunks and any leftover bytes.

For instance, in the affected code at line 283:
```sol
mcopy(add(headPointer, DepositHook_State_Offset), state, MarketStateSize);
```
It would remain unchanged, but now that the mcopy function is defined, it would work as expected.
