# Vulnerability details

## Proof of Concept
Observing the code snippet below 
```javascript
function overrideSanction(address account) public override {
    sanctionOverrides[msg.sender][account] = true;
    emit SanctionOverride(msg.sender, account);
  }
```


 We can see that any address can call this function to override an account's sanction status for the msg.sender. Here's why:

1. The function is public, meaning anyone can call it.
2. It uses msg.sender as the key in the sanctionOverrides mapping.
It doesn't check if msg.sender is a registered borrower.
This means:

Any address can call this function.
They can override sanctions for any account they want.
The override applies specifically to the msg.sender, regardless of whether they're actually a borrower or have authority to make such overrides.
This approach lacks proper access control. It assumes that the caller knows their own identity (msg.sender) and is trusted to make decisions about sanctions for themselves.

However, it's important to note that this implicit trust model has some vulnerabilities:

1. Anyone can override sanctions for anyone else, potentially leading to abuse, in which a user who have been previously sanctioned can just override their status by calling this function.
2. There's no mechanism to verify if the msg.sender is actually authorised to make such overrides.
3. It relies on the integrity of the blockchain state, assuming that msg.sender hasn't been manipulated.
For a secure implementation, you'd want to add explicit checks or role-based access control mechanisms to ensure that only authorised borrowers can call this function and modify sanction statuses appropriately.

## Recommended Mitigation Steps
The function can be modified to implement the approach below
```javascript
// Mapping to store borrower identities
mapping(address => bool) public borrowers;

// Modifier to check if the caller is a registered borrower
modifier onlyBorrowers() {
    if (msg.sender != borrower) revert CallerNotBorrower();
    _;
}

// Modified overrideSanction function
function overrideSanction(address account) public onlyBorrowers {
    require(borrowers[msg.sender], "Caller is not a registered borrower");
    
    // Ensure the account exists in the borrowers mapping
    require(borrowers[account], "Account is not a registered borrower");
    
    sanctionOverrides[borrowers[msg.sender]][account] = true;
    emit SanctionOverride(borrowers[msg.sender], account);
}
```

This approach can also be used for the `removeSanctionOverride()` for proper access control implementation
