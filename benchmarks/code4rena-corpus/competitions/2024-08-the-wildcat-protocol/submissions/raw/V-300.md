# Vulnerability details

## Summary

The Wildcat protocol allows for customized market logic through the use of hooks. These hooks are essentially callbacks into user-defined contracts that can enforce specific rules or behaviors within the market's lifecycle. Examples of such hooks include actions like depositing, withdrawing, transferring tokens, or even modifying the market's interest rates.

The HooksConfig type is used to store the configuration of which hooks are enabled for a market and the address of the contract that implements them.

While the Wildcat protocol allows for the customization of various market behaviors through hooks, there is a significant gap in its implementation regarding the enforcement of protocol fee changes. 

Currently, when the protocol fee is updated for a specific hooksTemplate, the protocol attempts to push these changes to all associated markets using the pushProtocolFeeBipsUpdates function. However, this function only makes a call to the setProtocolFeeBips function on the market contract without any mechanism to verify if the protocol fee was actually updated. 

This oversight allows markets to disregard protocol fee updates, potentially leading to a discrepancy between the expected and actual fees collected.

## Details

### Hooks Templates and Market Deployment:

The Wildcat protocol uses Hooks Templates to define a set of hooks and their configurations that can be applied to multiple markets. This approach promotes reusability and consistency in market behavior.

When a borrower wants to deploy a new market, they can either choose an existing Hooks Template or deploy a new instance with custom parameters. The chosen template dictates the market's hooks configuration.

### Protocol Fee Updates and Propagation:

The protocol allows for updates to the protocol fee associated with a Hooks Template. These updates are intended to apply to all new markets created using the template, as well as existing markets.

The pushProtocolFeeBipsUpdates function is used to propagate these changes to existing markets. It iterates through all markets associated with a particular Hooks Template and calls the setProtocolFeeBips function on each market contract.

### Lack of Enforcement Mechanism:

The current implementation of the pushProtocolFeeBipsUpdates function simply makes a call to the setProtocolFeeBips function on each market.

There is no mechanism in place to verify if the market contract actually updates the protocol fee. The function assumes that the call is successful and the protocol fee is updated, without any checks or error handling.

## Impact

The lack of enforcement for protocol fee updates has several implications:

Markets that disregard protocol fee updates will effectively collect lower fees than intended, leading to potential revenue loss for the protocol.

The absence of a robust enforcement mechanism can result in an inconsistent fee structure across markets using the same Hooks Template. This inconsistency might create confusion among lenders and borrowers and could be perceived as unfair.

If borrowers become aware of this loophole, they might intentionally deploy markets using templates with outdated protocol fees, exploiting the system for their benefit. This behavior can erode trust in the protocol's governance and fairness.

## Scenario

- A borrower deploys a Wildcat market using a Hooks Template with a protocol fee of 1%.
- The protocol governance decides to increase the protocol fee for that template to 2%.
- The pushProtocolFeeBipsUpdates function is called to update the protocol fee on existing markets, including the one deployed in step 1.
- The market contract receives the setProtocolFeeBips call but does not update the protocol fee, either intentionally or due to a bug in its implementation.
- The market continues to operate with the old protocol fee of 1%, resulting in a discrepancy between the expected and actual fees.

## Fix

To address this issue, a robust enforcement mechanism needs to be implemented to ensure that markets adhere to protocol fee updates. One approach is to:

Modify the Market Contract Interface: Introduce a new function in the IMarketEventsAndErrors interface, tentatively named validateProtocolFeeBips, that takes the updated protocol fee as input and returns a boolean indicating whether the update was successful.

```solidity
// IMarketEventsAndErrors.sol

interface IMarketEventsAndErrors {
    // ... Existing interface functions ...

    /**
    * @dev Validates and applies the updated protocol fee.
    * @param newProtocolFeeBips The updated protocol fee in basis points.
    * @return True if the protocol fee was successfully updated, false otherwise.
    */
    function validateProtocolFeeBips(uint16 newProtocolFeeBips) external returns (bool);
}
```

Implement Validation in Market Contracts: Implement the validateProtocolFeeBips function in all market contracts (WildcatMarketBase). This function will check if the received newProtocolFeeBips matches the fee stored in the market's state. If they match, it means the protocol fee is already up to date, and the function returns true. If they don't match, the function updates the market's protocol fee and returns true.

```solidity
// WildcatMarketBase.sol

function validateProtocolFeeBips(uint16 newProtocolFeeBips) external nonReentrant sphereXGuardExternal returns (bool) {
    if (msg.sender != factory) revert_NotFactory();

    MarketState memory state = _getUpdatedState();
    if (state.isClosed) revert_ProtocolFeeChangeOnClosedMarket();

    // Check if the protocol fee needs to be updated
    if (newProtocolFeeBips != state.protocolFeeBips) {
        hooks.onSetProtocolFeeBips(newProtocolFeeBips, state);

        state.protocolFeeBips = newProtocolFeeBips;
        emit ProtocolFeeBipsUpdated(newProtocolFeeBips);
        _writeState(state);
    }

    return true;
}
```

Update pushProtocolFeeBipsUpdates: Modify the pushProtocolFeeBipsUpdates function in the HooksFactory contract to call the new validateProtocolFeeBips function instead of directly calling setProtocolFeeBips. After the call, check the return value. If the market returns false, it indicates that the protocol fee update was not successful, and the pushProtocolFeeBipsUpdates function should revert to prevent further issues.

```solidity
// HooksFactory.sol
```
