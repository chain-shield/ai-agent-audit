# Vulnerability details

## Proof of Concept
The function onDeposit and others use calldatacopy to copy additional calldata (extraCalldataBytes) into memory without properly validating its size. This creates a vulnerability where an attacker could send calldata that is larger than expected, resulting in memory corruption as below :
 
let extraCalldataBytes := sub(calldatasize(), DepositCalldataSize);
calldatacopy(
    add(headPointer, DepositHook_ExtraData_TailOffset),
    DepositCalldataSize,
    extraCalldataBytes
);

If extraCalldataBytes is larger than the allocated memory for storing the extra data, it can overwrite critical variables in memory.
For instance, an attacker could send calldata with an excessive payload that overwrites the address of the recipient or modifies other important variables.

Since the code directly interacts with memory at a low level, if extraCalldataBytes is larger than expected, it could overwrite critical variables in memory.

For example, an attacker can send calldata with an oversized payload, leading to an overwrite of sensitive data such as the recipient's address or important state variables.

## Recommended Mitigation Steps

Add a validation step to ensure that extraCalldataBytes does not exceed a reasonable size before copying it into memory :
uint256 MAX_EXTRA_DATA_SIZE = 256; // Define a safe maximum size for extra calldata
require(extraCalldataBytes <= MAX_EXTRA_DATA_SIZE, "extraCalldataBytes exceeds maximum allowed size");
