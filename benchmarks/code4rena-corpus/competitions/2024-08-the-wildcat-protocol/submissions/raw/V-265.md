# Vulnerability details

## Proof of Concept
The _blockAccount function in the protocol allows a borrower to queue the assets of an account for withdrawal. However, there is no verification to confirm if the account is indeed sanctioned before queuing the assets, which opens up the possibility of arbitrary asset freezes. Even accounts that are not listed on external sanctions (e.g., Chainalysis) can have their assets locked if the borrower triggers the function. This could lead to:
- Borrowers arbitrarily freezing the assets of accounts not on any sanctions list.
- Undermining the intent of the sanctions mechanism, which should only affect sanctioned accounts.

### Vulnerable Code:
The `_blockAccount` function does not check if the borrower’s sanction override is being misused or that the account is even sanctioned at all before queuing an account's assets for withdrawal.
Code link: https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarket.sol#L292-L315
Exploit Scenario:
1. Borrower calls `_blockAccount`, arbitrarily queuing the account’s assets for withdrawal, even though the account is not sanctioned.
2. Financial losses for account holders, as their assets would no longer earn interest while they are queued for withdrawal against their will.
3. Unjust freezing of yield: Even though the account is not sanctioned, it could be prevented from earning the returns it would normally be entitled to (considering the fact that the borrower may no longer needs the credit).

## Recommended Mitigation Steps
1. Add Sanction Verification Before Queuing Withdrawals: The `_blockAccount` function should include a step to check if the account is actually sanctioned, either by external lists or internal rules, before queuing assets for withdrawal. This check should apply regardless of whether the borrower overrides the sanction or not. If no sanctions apply, the account’s assets should not be queued.

2. Add an Appeal or Release Mechanism: Allow users whose accounts have been frozen via `_blockAccount` to appeal the decision or initiate a release request. This would provide protection for innocent users who are unfairly affected.
