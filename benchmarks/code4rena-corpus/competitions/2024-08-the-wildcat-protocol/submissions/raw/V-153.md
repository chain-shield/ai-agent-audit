# Vulnerability details

## Proof of Concept
The HooksFactory.deployMarket() function deploys a contract market. The function calculates the name/symbol parameters for the market. This is done taking into account that Name/Symbol are strings. However, not all ERC20 tokens have Name/Symbol as a string. The function will not work for these assets.

The description at https://code4rena.com/audits/2024-08-the-wildcat-protocol in the "General Questions" tab states:
Question: "ERC20 used by the protocol"
Answer: "ERC-20s used as underlying assets for markets require no fee on transfer, totalSupply to be not at all close to 2^128, arbitrary mint/burn must not be possible, and name, symbol and decimals must all return valid results (for name and symbol, either bytes32 or a string). Creating markets for rebasing tokens breaks the underlying interest rate model."

However, there is no bytes support for Name/Symbol.

Proof:
https://github.com/d-xo/weird-erc20?tab=readme-ov-file#non-string-metadata

## Recommended Mitigation Steps
Take into account in the function that not all ERC20 tokens have string metadata.
