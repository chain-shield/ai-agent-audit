# Vulnerability details

## Proof of Concept
The `approve` function in the `WildcatMarketToken` contract currently allows any address to set an allowance for any spender. This is due to the absence of a check to ensure that only the token owner (i.e., msg.sender) can authorize allowances.

Here is the relevant code snippet from the approve function:

```solidity
  function approve(
    address spender,
    uint256 amount
  ) external virtual nonReentrant sphereXGuardExternal returns (bool) {
    _approve(msg.sender, spender, amount);
    return true;
  }
```
In this implementation, `msg.sender` is used to set allowances but there's no validation to ensure that the `spender` address matches the caller. Therefore, any user can call this function and set allowances for any address, which might not be intended.

## Impact
The primary impact of this issue is that any user can set an allowance for any address, effectively allowing unauthorized third parties to withdraw tokens from an account. For example, if Alice accidentally or maliciously approves a `spender` address controlled by Bob, Bob can then use the `transferFrom` function to withdraw tokens from Alice's account, potentially draining it of tokens.
## Tools Used
Manual
## Recommended Mitigation Steps
Include a check in the `approve` function to ensure that the `spender` address is the same as the `msg.sender`.
