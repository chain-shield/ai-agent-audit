# Vulnerability details

## Proof of Concept

In the _updateSphereXEngineOnRegisteredContractsInSet function, the contract checks whether a given address (account) is contained within a specific EnumerableSet.AddressSet (set). If the address is not present, it attempts to revert using a specific error selector provided by notInSetErrorSelectorBytes.

The mstore(0, notInSetErrorSelector) stores the 4-byte error selector at memory address 0x00, in the most significant bytes of the 32-byte word.
The Ethereum Virtual Machine (EVM) stores values in big-endian format when using mstore, meaning the value occupies the highest-order bytes.
As a result, the error selector occupies bytes 0x00 to 0x03, and bytes 0x04 to 0x1f (up to byte 31) are zero-filled.

The revert(0x1c, 0x04) statement attempts to revert using 4 bytes of data starting from memory offset 0x1c (decimal 28).
However, since the error selector is stored at memory addresses 0x00 to 0x03, the memory from 0x1c to 0x1f contains zeros, not the error selector.

##Impacts 

-> External contracts or applications interacting with WildcatArchController will not receive the intended error selector upon revert and can lead to incorrect application logic or security issues.




## Recommended Mitigation Steps

Store the error selector at memory offset 0x1c (28 bytes), matching the offset used in the revert statement.
