# Vulnerability details

## Summary:
The releaseEscrow() function in the WildcatSanctionsEscrow contract can be called by anyone once the sanctions are lifted. This opens the potential for unauthorized parties to trigger fund releases without proper authorization.
## Vulnerability Details:
The releaseEscrow() function does not have any access control modifiers, allowing any external party to release the escrowed funds once the account is no longer sanctioned. This could lead to security risks where someone other than the account owner or an authorized admin releases the funds.

## Impact:
Without proper access control, unauthorized users may release funds prematurely or inappropriately, potentially leading to unintended fund transfers.
## Proof of Concept:
function releaseEscrow() public {
    if (!canReleaseEscrow()) revert CanNotReleaseEscrow();
    asset.safeTransfer(account, balance());
}

## Tools Used:
•	Manual code review.

## Recommended Mitigation Steps:
Implement an access control modifier (e.g., onlyAccountOwner) to restrict the calling of releaseEscrow() to the account owner or another authorized party:
modifier onlyAccountOwner() {
    require(msg.sender == account, "Only account owner can release escrow");
    _;
}
