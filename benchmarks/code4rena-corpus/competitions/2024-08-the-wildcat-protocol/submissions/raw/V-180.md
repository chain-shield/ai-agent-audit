# Vulnerability details

## Description:

The `nukeFromOrbit` function in the `WildcatMarketConfig` contract can be called by anyone to block lenders from interacting with the market and queueing their withdrawals when they are sanctioned by Chainalysis. However, the borrower has the ability to override this sanction and allow the lender to interact with the market. This introduces a vulnerability as the `nukeFromOrbit` call can be front-run by bots, blocking a lender from performing legitimate actions even after the borrower attempts to override the sanction.

This vulnerability arises because the Ethereum mainnet operates on a first-in, first-out (FIFO) basis. Malicious actors can observe the borrower's override transaction in the mempool and quickly execute a `nukeFromOrbit` function call, effectively front-running the override and blocking the lender before the legitimate transaction is processed.

## Code Snippet:

The vulnerable `nukeFromOrbit` function is defined in the `WildcatMarketConfig` contract as follows:

```javascript
@-> function nukeFromOrbit(address accountAddress) external nonReentrant sphereXGuardExternal {
        if (!_isSanctioned(accountAddress)) revert_BadLaunchCode();
        MarketState memory state = _getUpdatedState();
        hooks.onNukeFromOrbit(accountAddress, state);
        _blockAccount(state, accountAddress);
        _writeState(state);
    }
```

## Impact:

Impacts of front-running attacks on the `nukeFromOrbit` function include:

1. Prevent authorized lenders from interacting with the market.
2. Force lenders to unnecessarily wait for their funds to be queued for withdrawal.
3. Exploit legitimate interactions by allowing malicious actors to halt the market’s functionality for certain users by constantly front-running the borrower’s override attempts.

This can cause serious disruptions in the market’s operation, degrade trust among lenders, and enable adversaries to leverage the protocol for malicious intent.

## Proof of Concept (PoC):

### Example Scenario:

1. Assume that a lender (Lender A) is initially sanctioned by Chainalysis.
2. The borrower sees that Lender A is falsely sanctioned and initiates a transaction to override the sanction, allowing Lender A to interact with the market again.
3. A malicious bot monitoring the Ethereum mempool detects the override transaction and immediately submits a `nukeFromOrbit` call to front-run the borrower’s transaction.
4. The bot’s `nukeFromOrbit` call is executed first, re-blocking Lender A before the borrower’s override transaction is processed.
5. Lender A is unable to perform any further actions on the platform despite the borrower’s approval.

## Recommendations:

To mitigate this front-running vulnerability, we propose the following solutions:

```diff
- function nukeFromOrbit(address accountAddress) external nonReentrant sphereXGuardExternal {
+ function nukeFromOrbit(address accountAddress) external nonReentrant sphereXGuardExternal onlyBorrower {
        if (!_isSanctioned(accountAddress)) revert_BadLaunchCode();
        MarketState memory state = _getUpdatedState();
        hooks.onNukeFromOrbit(accountAddress, state);
        _blockAccount(state, accountAddress);
        _writeState(state);
    }
```
