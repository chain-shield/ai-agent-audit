# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The call to getLenderStatus function which is via the _tryGetCredential function, a staticcall is made to check a provider’s credential for a user. However, the return value of the staticcall is not properly checked, meaning if the staticcall fails, the contract proceeds as if it succeeded. This could lead to incorrect access being granted or denied based on incomplete or incorrect data.

Issue Type: Unchecked Call Return Value

## Recommended Mitigation Steps
This mitigation ensures that the success of the staticcall is properly checked and handled. If the call fails or returns invalid data, the function will return false, preventing incorrect access validation.

Suggested Solidity Mitigation:
```sol
function _tryGetCredential(
    LenderStatus memory status,
    RoleProvider provider,
    address accountAddress
) internal view returns (bool isApproved) {
    address providerAddress = provider.providerAddress();
    uint32 credentialTimestamp;
    uint getCredentialSelector = uint32(IRoleProvider.getCredential.selector);

    // Perform a staticcall and check the return value properly
    (bool success, bytes memory returnData) = providerAddress.staticcall(
        abi.encodeWithSelector(getCredentialSelector, accountAddress)
    );
    
    // If the call fails, return false
    if (!success || returnData.length < 32) {
        return false;
    }

    credentialTimestamp = abi.decode(returnData, (uint32));

    if (provider.calculateExpiry(credentialTimestamp) < block.timestamp) {
        return false;
    }

    status.setCredential(provider, credentialTimestamp);
    return true;
}
```
