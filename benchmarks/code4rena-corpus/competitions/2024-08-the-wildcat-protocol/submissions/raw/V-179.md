# Vulnerability details

## POC

In the function `FixedTermLoanHooks::revokeRole` a provider who is removed can still revoke the role of a lender.

Here's a Proof of Code to prove it:

```solidity

function test_removedProviderCanRevokeCredential() external {
    // add provider
    hooks.addRoleProvider(address(mockProvider1), 1);

    // grant lender role
    vm.startPrank(address(mockProvider1));
    hooks.grantRole(address(1), uint32(block.timestamp));
    vm.stopPrank();

    // remove a role provider
    hooks.removeRoleProvider(address(mockProvider1));
    expectedRoleProviders.pop();
    _validateRoleProviders();

    // revoke lender role
    vm.startPrank(address(mockProvider1));
    vm.expectEmit(address(hooks));
    emit FixedTermLoanHooks.AccountAccessRevoked(address(1));
    hooks.revokeRole(address(1));
    vm.stopPrank();
  }

```

## Impact

System flaw, unauthorized role providers will still take part in revoking lender's roles.

## Recommended mitigation

When a role provider is removed the lender assigned to that role provider should be assigned to another role provider.
