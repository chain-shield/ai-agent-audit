# Vulnerability details

## Proof of Concept
The _tryValidateAccess function is used in the onTransfer, onDeposit, and onQueueWithdrawal hooks to validate access for transferring, depositing, and queuing withdrawals. However, the borrower has control over the access control providers. The borrower can manipulate these providers, adding many or removing them to force the _tryValidateAccess function into a situation where it consumes a lot of gas. This can lead to an out-of-gas error, causing the onTransfer and onDeposit functions to revert, thus blocking users' ability to perform transfers or deposits.

This behavior can be used maliciously by a borrower to prevent other users from withdrawing their tokens. In markets where debt tokens are often transferred on a secondary market, this could result in preventing all withdrawals by forcing out-of-gas errors. A malicious borrower can thereby avoid paying delinquency fees while blocking the withdrawal of users who have been transferred debt tokens.

```
function _tryValidateAccess() internal {
   // Borrower can manipulate push providers to cause out-of-gas reverts
   for (uint256 i = 0; i < pushProviders.length; i++) {
      if (pushProviders[i].hasAccess()) {
         return;
      }
   }
   revert_NoAccess();
}
```
Borrower can force out-of-gas conditions by adding providers that consume a lot of gas. Transfers via secondary markets are at risk due to this vulnerability.

## Recommended Mitigation Steps
Limit the Number of Providers: Set a limit on the maximum number of push providers allowed to avoid excessive loops.
Introduce Gas Checks: Implement a gas check to skip providers if insufficient gas is available to complete the call.
Queue Withdrawals for Transferred Tokens: Allow users who receive debt tokens via transfers to queue withdrawals without requiring additional validation to prevent blocking.
