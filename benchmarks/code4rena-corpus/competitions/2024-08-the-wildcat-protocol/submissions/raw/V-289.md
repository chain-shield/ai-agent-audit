# Vulnerability details

## Summary

The Wildcat V2 protocol incorporates a sanctions enforcement mechanism to prevent sanctioned accounts from interacting with markets. However, a potential vulnerability exists in the interaction between the onExecuteWithdrawal hook and the core withdrawal logic, allowing malicious hooks to bypass the escrow transfer for sanctioned accounts.

A malicious hook could manipulate the execution flow or memory during the onExecuteWithdrawal hook call to circumvent the sanctions check (_isSanctioned(accountAddress)) and enable a sanctioned account to withdraw funds directly, bypassing the intended escrow transfer.

The _executeWithdrawal function in the Wildcat Market contracts executes a withdrawal, calling the onExecuteWithdrawal hook before performing the sanction check and escrow transfer. This vulnerability allows a malicious hook to circumvent the intended security measures by manipulating the execution flow.

## Code

```solidity

// In WildcatMarketWithdrawals contract
function _executeWithdrawal(
    // ... parameters
) internal returns (uint256) {
    // ...

    hooks.onExecuteWithdrawal(accountAddress, normalizedAmountWithdrawn, state, baseCalldataSize);

    // Vulnerable: Sanctions check after the hook call
    if (_isSanctioned(accountAddress)) {
        // ... escrow transfer logic ...
    } else {
        asset.safeTransfer(accountAddress, normalizedAmountWithdrawn); 
    }

    // ...
}
```


## Impact

A malicious hook could modify the status.normalizedAmountWithdrawn value during the onExecuteWithdrawal hook call, directing the safeTransfer to the sanctioned account instead of the escrow.
 
## Scenario

- A malicious actor deploys a contract implementing the IHooks interface.
- The malicious hook overrides the status.normalizedAmountWithdrawn value to reflect the entire withdrawal amount.
- The _executeWithdrawal function calls the malicious onExecuteWithdrawal hook.
- The _isSanctioned function checks the account's status, finding it sanctioned, but the safeTransfer is executed to the user's account, bypassing the escrow transfer.


## Fix

Prioritize Sanctions Check: Move the sanctions check and escrow transfer logic before the onExecuteWithdrawal hook call. This ensures that even if the hook attempts to manipulate the _isSanctioned result, the core sanctions enforcement will still be executed first.

```solidity

// In WildcatMarketWithdrawals contract (fixed)
function _executeWithdrawal(
    // ... parameters
) internal returns (uint256) {
    // ...

    // Sanctions check and escrow transfer BEFORE the hook call
    if (_isSanctioned(accountAddress)) {
        // ... escrow transfer logic ...
    } else {
        // Proceed with normal withdrawal only if not sanctioned
        hooks.onExecuteWithdrawal(accountAddress, normalizedAmountWithdrawn, state, baseCalldataSize);
        asset.safeTransfer(accountAddress, normalizedAmountWithdrawn); 
    }

    // ...
}
```
