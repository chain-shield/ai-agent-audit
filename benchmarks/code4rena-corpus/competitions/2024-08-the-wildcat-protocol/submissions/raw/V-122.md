# Vulnerability details

## Impact
Detailed description of the impact of this finding.

	•	Severity: Medium
	•	Issue Type: Timing
	•	Location: MarketStateLib.hasPendingExpiredBatch function in MarketState
	•	Vulnerable line: result := and(gt(expiry, 0), gt(timestamp(), expiry))
The function MarketState.hasPendingExpiredBatch uses block.timestamp to determine whether a pending withdrawal batch has expired. Miners can manipulate block.timestamp slightly, within a margin of approximately 15 seconds. This manipulation could impact processes that depend on precise timing, like batch withdrawal expiration.

## Proof of Concept

Vulnerable code
```sol
  function hasPendingExpiredBatch(MarketState memory state) internal view returns (bool result) {
    uint256 expiry = state.pendingWithdrawalExpiry;
    assembly {
      // Equivalent to expiry > 0 && expiry < block.timestamp
      result := and(gt(expiry, 0), gt(timestamp(), expiry))
    }
  }
```

	•	A miner might manipulate the timestamp to prematurely expire or extend the validity of a pending withdrawal batch, depending on whether the manipulation benefits them.
	•	In a scenario where batch expiration is crucial for user fairness or system security, this vulnerability could be exploited.

## Recommended Mitigation Steps

This mitigation assumes that you have access to a Chainlink oracle that provides the current time. Chainlink allows you to fetch off-chain data, and in this case, we’ll fetch the current timestamp using a Chainlink oracle.

First, you’ll need to import Chainlink’s contracts and set up the Chainlink functionality in your contract.
```sol
// SPDX-License-Identifier: Apache-2.0
pragma solidity ^0.8.20;

import "@chainlink/contracts/src/v0.8/interfaces/AggregatorV3Interface.sol";

struct MarketState {
    uint32 pendingWithdrawalExpiry;  // Expiry timestamp for pending withdrawals
}

contract MarketStateContract {
    AggregatorV3Interface internal timeFeed;

    // Set the Chainlink time oracle feed (example address used here)
    constructor(address _timeFeed) {
        timeFeed = AggregatorV3Interface(_timeFeed);
    }

    /**
     * @dev Gets the current time from the Chainlink Oracle
     */
    function getCurrentTime() public view returns (uint256) {
        (, int256 answer, , , ) = timeFeed.latestRoundData();
        require(answer > 0, "Invalid time data from oracle");
        return uint256(answer);
    }

    /**
     * @dev Check if the pending withdrawal batch has expired using the Chainlink Oracle time
     */
    function hasPendingExpiredBatch(MarketState memory state) internal view returns (bool result) {
        uint256 currentTime = getCurrentTime();
        uint256 expiry = state.pendingWithdrawalExpiry;

        assembly {
            // Equivalent to expiry > 0 && expiry < currentTime
            result := and(gt(expiry, 0), gt(currentTime, expiry))
        }
    }
}
```
1.	Chainlink Oracle Integration:
	•	The AggregatorV3Interface from Chainlink is used to connect to an external time oracle that provides a reliable timestamp. This ensures that the time is not dependent on block.timestamp and cannot be manipulated by miners.
	•	In the getCurrentTime function, we fetch the current time from the Chainlink oracle.
2.	hasPendingExpiredBatch using Chainlink Oracle:
	•	The hasPendingExpiredBatch function now uses getCurrentTime to fetch the time from the Chainlink oracle instead of using block.timestamp.
	•	It compares the fetched time with pendingWithdrawalExpiry to determine if the batch has expired.
3.	Error Handling:
	•	The code checks that the time received from Chainlink is valid (i.e., answer > 0). If the oracle provides invalid data, the function reverts.
