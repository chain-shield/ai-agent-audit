# Vulnerability details

### Impact

Protocol plans to support all ERC20 tokens, including those with special names and symbols, but wil not be able to do so for tokens that do not return a string parameter as their name or symbol which will cause market deployment with such assets to always fail.

### Proof of Concept

From the provided informaton in the [readme](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/README.md#general-questions), it can be inferred that all token types are supported. A specific interest is also shown in tokens that return either a bytes32 or a string as their name and symbols. 

> ERC20 used by the protocol	ERC-20s used as underlying assets for markets require no fee on transfer, totalSupply to be not at all close to 2^128, arbitrary mint/burn must not be possible, and name, symbol and decimals must all return valid results (for name and symbol, either bytes32 or a string). Creating markets for rebasing tokens breaks the underlying interest rate model.


However, in HooksFactory.sol, when the `_deployMarket` function is called, the asset's decimal, symbol and name is queried. The name and symbol is then attempted to be concatenated as a string with the name and symbol prefixes. But due to the different parameter types (string prefixes and bytes32 name/symbols), and the attempt to concatenate both as a string, an EVM error will occur, causing the transaction to fail. 

```solidity
    uint8 decimals = parameters.asset.decimals();

    string memory name = string.concat(parameters.namePrefix, parameters.asset.name());
    string memory symbol = string.concat(parameters.symbolPrefix, parameters.asset.symbol());

```

Since a number of tokens including MKR, return a bytes32 name and symbol instead of a string, creating markets for these tokens will always fail going against the protocol's requirements.

### Tools Used

Manual code review
 
### Recommended Mitigation Steps

Fixing this might require using a try-catch to initially query the asset name/symbol, converting the non-string ones to string, before concatenating it with the prefixes.
