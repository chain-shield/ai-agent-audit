# Vulnerability details

## Proof of Concept
In the `WildcatSanctionsSentinel` contract, the function `createEscrow` is vulnerable to reentrancy attack. 

After creating a new `WildcatSanctionsEscrow` contract (which could be corrupted or malicious), the function emits an event (`SanctionOverride`), which could potentially allow the execution of state-changing operations in a fallback function in the external contract.

In case of an attack, an attacker could manipulate the state of `sanctionOverrides` mapping which could lead to unforeseen consequences regarding the sanction overrides.

### Example
```solidity
function createEscrow(
    address borrower,
    address account, 
    address asset
) public override returns (address escrowContract) {
    // ... omitted
    new WildcatSanctionsEscrow{ salt: _deriveSalt(borrower, account, asset) }();
    // ... omitted
    sanctionOverrides[borrower][escrowContract] = true;
    emit SanctionOverride(borrower, escrowContract);
    // ... omitted
}
```

## Recommended Mitigation Steps
To prevent reentrancy, it's suggested to follow the Checks-Effects-Interactions pattern in Solidity. That means, external contract calls should be the last operations in a function.

In `createEscrow` you can emit `SanctionOverride` event before calling 
`new WildcatSanctionsEscrow{ salt: _deriveSalt(borrower, account, asset) }();`
 This way, we ensure that the state of the current contract is not modified by an external contract call.
