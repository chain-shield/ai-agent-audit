# Vulnerability details

## Summary
When an escrow contract is created, the `sanctionOverrides[borrower][escrowContract]` is set to true.
If for any reason the borrower decide to remove the `sanctionOverrides` flag for an escrow contract, anyone can set back the override on behalf of the borrower.

## Vulnerability details
The `WildcatSanctionsSentinel::createEscrow` is called by `_createEscrowForUnderlyingAsset` during the [execution of a withdrawal if the account executing the withdrawal is sanctionned](https://github.com/code-423n4/2024-08-wildcat/blob/main/src/market/WildcatMarketWithdrawals.sol#L260-L264).
That function sets `sanctionOverrides[borrower][escrowContract] = true` after deploying the escrow contract.

As borrower as free to set or unset sanctionOverrides on any address of their market, they might want to remove the override on that particular escrow contract.

But because `createEscrow` is public with no access control, and can be called on [an already deployed contract](https://github.com/code-423n4/2024-08-wildcat/blob/main/src/WildcatSanctionsSentinel.sol#L126), this allow anyone to set the flag back to true.

That entry of the mapping at the borrower key shouldn't be accessible to other users, as [`overrideSanction` and `removeSanctionOverride` is restricted to `msg.sender`](https://github.com/code-423n4/2024-08-wildcat/blob/main/src/WildcatSanctionsSentinel.sol#L96-L107)

## Impact
Unauthorized access to `sanctionOverrides[borrower][escrowContract]` which is a borrower parameter. 


## Tools Used
Manual review

## Recommended Mitigation Steps
Restrict `WildcatSanctionsSentinel::createEscrow` access to only borrower and market adresses.
