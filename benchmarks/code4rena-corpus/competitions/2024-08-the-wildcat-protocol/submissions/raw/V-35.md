# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Function Name: withdrawableProtocolFees()
Contract Name: WildcatMarketBase

Severity: Medium
Issue Type: Block Timestamp Manipulation / Environment Variable Predictability

In the function withdrawableProtocolFees(), the contract uses the block.timestamp environment variable to make a control flow decision. Specifically, the following line of code introduces the issue:
```sol
if (state.lastInterestAccruedTimestamp != block.timestamp) {
    state.updateScaleFactorAndFees(
      delinquencyFeeBips,
      delinquencyGracePeriod,
      block.timestamp
    );
}
```
The reliance on block.timestamp for determining if interest should be accrued creates a potential vulnerability. While block.timestamp is often seen as a reliable indicator of time, it can be influenced by miners within a 15-second range. This small window of predictability might allow an attacker (specifically, a miner) to manipulate the timestamp and influence how often interest or fees are accrued, leading to incorrect protocol fee calculations or interest accrual manipulations.

An attacker with control over block timestamp (e.g., a miner) could manipulate the block.timestamp to either delay or expedite interest and fee accruals. This could allow them to:

Prevent the protocol from accruing fees or interest when it should.

Cause premature accrual of fees or interest, impacting the profitability of the protocol or harming the accuracy of withdrawal-related calculations.

## Recommended Mitigation Steps

To mitigate the risk of block.timestamp manipulation by miners, we can integrate an off-chain time oracle (such as Chainlink) to provide secure and tamper-resistant timestamps. This ensures that critical time-based operations such as fee and interest accrual are based on reliable time data rather than a manipulable on-chain variable like block.timestamp.
```sol
// SPDX-License-Identifier: MIT
pragma solidity >=0.8.20;

interface ITimeOracle {
    function getTime() external view returns (uint256);
}

contract WildcatMarketBase {
    ITimeOracle public timeOracle;

    // Assume the oracle contract address is passed in during deployment
    constructor(address _timeOracleAddress) {
        timeOracle = ITimeOracle(_timeOracleAddress);
    }

    function withdrawableProtocolFees() external view returns (uint256) {
        // Fetch the current secure time from the time oracle
        uint256 currentTime = timeOracle.getTime();

        // Continue with the fee accrual logic using `currentTime` instead of `block.timestamp`
        if (state.lastInterestAccruedTimestamp != currentTime) {
            state.updateScaleFactorAndFees(
                delinquencyFeeBips,
                delinquencyGracePeriod,
                currentTime
            );
        }

        // Return protocol fees (example logic)
        return state.accruedProtocolFees;
    }
}
```
Time Oracle Integration:
	•	The contract now depends on a time oracle (represented by the ITimeOracle interface) to get a secure and tamper-proof timestamp. The oracle will provide reliable time data without the risk of miner manipulation.
	•	In the constructor, the address of the time oracle contract is passed and stored in the timeOracle variable.

getTime() Function:
	•	The getTime() function is called from the oracle in the withdrawableProtocolFees() function to get the current secure time.
	•	This time is then used to decide whether the interest and fees should be accrued instead of using the potentially manipulable block.timestamp.


Deploy or use an existing reliable time oracle service, such as Chainlink’s Time Oracle.

Replace the on-chain timestamp logic with calls to the time oracle in the contract’s time-sensitive functions.
