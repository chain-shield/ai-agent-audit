# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Title: AccessControlHooks contract has Unchecked Function Call in status.setCredential in _setCredentialAndEmitAccessGranted function.
Severity: Medium
Impact: Incorrect Credential Updates
Issue Type: Unchecked Function Call
Status: Unmitigated
Functions: _setCredentialAndEmitAccessGranted() & _grantRole().

In the function _setCredentialAndEmitAccessGranted, the line status.setCredential(provider, credentialTimestamp) calls the setCredential function, which updates the lender’s status. This call is unchecked, meaning there is no validation of its success, and the contract proceeds without ensuring the status update is correct.

Unchecked function calls can result in silent failures. If setCredential fails or behaves unexpectedly (due to internal logic, external interactions, or other contract states), the contract could continue without making the necessary updates. This could lead to issues where lender credentials are not updated properly, while the contract assumes they have been.

_setCredentialAndEmitAccessGranted
```sol
function _setCredentialAndEmitAccessGranted(
  LenderStatus memory status,
  RoleProvider provider,
  address accountAddress,
  uint32 credentialTimestamp
) internal {
  // Update the account's status with the new credential in memory
  status.setCredential(provider, credentialTimestamp);  // Unchecked call
  // Update the account's status in storage
  _lenderStatus[accountAddress] = status;
  emit AccountAccessGranted(provider.providerAddress(), accountAddress, credentialTimestamp);
}
```

```sol
function _grantRole(
  RoleProvider callingProvider,
  address account,
  uint32 roleGrantedTimestamp
) internal {
  LenderStatus memory status = _lenderStatus[account];

  uint256 newExpiry = callingProvider.calculateExpiry(roleGrantedTimestamp);

  if (newExpiry < block.timestamp) revert GrantedCredentialExpired();

  if (status.hasCredential()) {
    RoleProvider lastProvider = _roleProviders[status.lastProvider];

    if (!lastProvider.isNull()) {
      uint256 oldExpiry = lastProvider.calculateExpiry(status.lastApprovalTimestamp);

      if (!((status.lastProvider == msg.sender).or(newExpiry > oldExpiry))) {
        revert ProviderCanNotReplaceCredential();
      }
    }
  }

  _setCredentialAndEmitAccessGranted(status, callingProvider, account, roleGrantedTimestamp);
}
```

## Recommended Mitigation Steps
Ensure the setCredential function call is verified for its expected behavior. One way to do this is to validate the state after calling setCredential to ensure the credential was updated correctly.

Add checks after the setCredential call to confirm that the credential update was successful by comparing the expected timestamp with the actual one.

In _setCredentialAndEmitAccessGranted, modify it as follows:
```sol
function _setCredentialAndEmitAccessGranted(
  address accountAddress,
  RoleProvider provider,
  uint32 credentialTimestamp
) internal {
  // Access storage reference directly for status
  LenderStatus storage status = _lenderStatus[accountAddress];
  
  // Call the setCredential function and then verify the update
  require(status.setCredential(provider, credentialTimestamp), "Error ...");

  // Ensure the credential was actually updated
  require(status.lastApprovalTimestamp == credentialTimestamp, "Failed to update credential");

  emit AccountAccessGranted(provider.providerAddress(), accountAddress, credentialTimestamp);
}
```

In _grantRole, modify it as follows:

```sol
function _grantRole(
```
