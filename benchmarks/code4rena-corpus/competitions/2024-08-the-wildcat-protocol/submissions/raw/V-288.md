# Vulnerability details

## Impact
The impact is severe. Users who are incorrectly flagged as sanctioned by the Chainalysis oracle may permanently lose access to their funds if the borrower never overrides the sanction. This creates a single point of failure where both the oracle and the borrower must act correctly for funds to be released. The lack of alternative release mechanisms could lead to irretrievable loss of user assets, severely damaging user trust and potentially exposing the protocol to legal challenges.

## Proof of Concept
The issue stems from the interaction between the sanction checking mechanism, withdrawal process, and escrow system. Here's a breakdown of the relevant code and process flow:

Sanction checking in [L85](https://github.com/code-423n4/2024-08-wildcat/blob/main/src/WildcatSanctionsSentinel.sol#L85):

```solidity
function isSanctioned(address borrower, address account) public view override returns (bool) {
    return !sanctionOverrides[borrower][account] && isFlaggedByChainalysis(account);
}
```

Withdrawal process for sanctioned accounts in [L260-L273](https://github.com/code-423n4/2024-08-wildcat/blob/fe746cc0fbedc4447a981a50e6ba4c95f98b9fe1/src/market/WildcatMarketWithdrawals.sol#L260-L273):

```solidity
    return !IWildcatSanctionsSentinel(sentinel).isSanctioned(borrower, account);
}

function releaseEscrow() public override {
    if (!canReleaseEscrow()) revert CanNotReleaseEscrow();
    
    // ... (transfer assets to account)
}
```

issue flow:
- A user is incorrectly flagged as sanctioned by the Chainalysis oracle.
- The user attempts to withdraw funds, which are automatically sent to an escrow contract.
- The escrow can only release funds if the sanction is lifted or overridden by the borrower.
- If the oracle never corrects the flag and the borrower never overrides, the funds remain locked indefinitely.
- There is no alternative mechanism for releasing the funds, resulting in permanent loss of access.

This creates a scenario where user funds could become permanently inaccessible due to errors or inaction, with no recourse available to the affected users.

```solidity
function testFundsStuckInEscrowForIncorrectlySanctionedUser() public {
    address borrower = address(1);
    address account = address(2);

    MockChainalysis(address(SanctionsList)).sanction(account);

    vm.expectRevert(IWildcatSanctionsEscrow.CanNotReleaseEscrow.selector);

    assertEq(escrow.balance(), 0, "Escrow should be empty after release");
}
```

## Recommended Mitigation Steps
Implement a time-based release mechanism for escrow contracts. After a predetermined period (e.g., 6 months), allow the user to initiate a release process that includes additional verification steps. This maintains compliance with sanctions while providing a safety net for incorrectly flagged accounts.
