# Vulnerability details

## Impact
The functions `WildcatArchController::registerControllerFactory`, `WildcatArchController::registerController` and `WildcatArchController::registerMarket` all present in the `WildcatController.sol` contract, all emit events before making an external call to the `SpherexConfig` contract using the `addAllowedSenderOnChain` function. The state of the `WildcatArchController` contract may not be fully updated. If the external call trigers another function that calls back into the the main contract, it can use the contract to reenter the function.

## Tools Used
slither and manual review

## Recommended Mitigation Steps
# The `WildcatArchController` or `ShereXConfig` contract should implement the `ReentrancyGuard.sol` contract from `src/ReentrancyGuard.sol` which is never used in the codebase. and use the `nonreentrant` modifier on the `addAllowedSenderOnChain` funcction. You can also follow the Checks, Effects,Interractions approach of function implementation, Check(First execute require statements, if/else statements), Effects(Update all state variables including event emission) and you finally do interraction(make any external call outside the current contract).
