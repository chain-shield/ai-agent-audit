# Vulnerability details

## Impact
The root of the issue lies in the fact that the create and create2 opcodes return the address where a contract would be deployed based on the input parameters (nonce for create and salt for create2). However, the contract at that address may not contain any code if the deployment failed.

Checking only whether the address is zero is not sufficient to verify a successful contract deployment. A contract can fail to deploy properly, resulting in an address without any code. The appropriate way to verify contract deployment is to check the code size at the deployed address using the extcodesize opcode.

## Proof of Concept

Consider the following function:

function deployInitCode(bytes memory data) internal returns (address initCodeStorage) {
  assembly {
    let size := mload(data)
    let createSize := add(size, 0x0b)
    mstore(data, or(shl(64, add(size, 1)), 0x6100005f81600a5f39f300))
    initCodeStorage := create(0, add(data, 21), createSize)
    if iszero(initCodeStorage) {
      mstore(0, 0x11c8c3c0)
      revert(0x1c, 0x04)
    }
    mstore(data, size)
  }
}


In this function, if the create opcode returns a non-zero address, the contract deployment is assumed to be successful. However, if the contract contains no bytecode (i.e., extcodesize(initCodeStorage) == 0), it indicates that the deployment has failed, even though the address is non-zero.

## Recommended Mitigation Steps

To ensure the contract is deployed correctly, especially for create2 where an address is determined before deployment,it means there will never be a revert for zero address. Therefore it is necessary to add a check for the extcodesize of the deployed address. This check should be done after the address is returned by create or create2.

The following change can be applied to affected functions:

Replace:
if iszero(initCodeStorage) { ... }
With:
if iszero(extcodesize(initCodeStorage)) { ... }
