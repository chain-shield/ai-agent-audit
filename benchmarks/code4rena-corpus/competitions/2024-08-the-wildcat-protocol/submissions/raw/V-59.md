# Vulnerability details

According to the documentation, the protocol monitors for addresses that are flagged by the Chainalysis oracle as being placed on a sanctions list and bars them from interacting with markets. This is part of the security measures taken to maintain the integrity and legality of the operations within the protocol.

However only the borrowers are required to kyc before interacting with the protocol for lenders the borrower must include an `onDeposit` hook which checks for the requires kyc.
a malicious borrower can create multiple accounts, and as the borrower can override the sanctions they deem wrong even if flagged by chainalysis, this allows them to override the sanctions layed on the lender.

the borrower can open a different account as a lender get who is sanctioned then overide the sanction on the lender address they control

## Impact
malicious borrowers will/can open a different account as lenders with flagged addresses for being malicious, override the sanction and operate in the protocol. 


## Proof of Concept
```
Condition 1: !sanctionOverrides[borrower][account] evaluates to false (overridden).
Condition 2: isFlaggedByChainalysis(account) evaluates to true (flagged).
Outcome: Returns false (not sanctioned).
```
```
 function isSanctioned(address borrower, address account) public view override returns (bool) {
    return !sanctionOverrides[borrower][account] && isFlaggedByChainalysis(account);
  }
```

```
  function queueWithdrawal(
    uint256 amount
  ) external nonReentrant sphereXGuardExternal returns (uint32 expiry) {
    MarketState memory state = _getUpdatedState();

    uint104 scaledAmount = state.scaleAmount(amount).toUint104();
    if (scaledAmount == 0) revert_NullBurnAmount();

    // Cache account data
    Account memory account = _getAccount(msg.sender);

    return
      _queueWithdrawal(state, account, msg.sender, scaledAmount, amount, _runtimeConstant(0x24));
  }

```
`queueWithdrawal()` is first called by the lender to start the witdraawal process. `_getAccount` checks if the account is sanctioned then reverts if it is.

## Recommended Mitigation Steps

 Just as borrowers are required to undergo KYC (Know Your Customer) checks, lenders should also be subject to similar requirements before interacting with the protocol. This would prevent malicious actors from creating new lender accounts with sanctioned addresses.
