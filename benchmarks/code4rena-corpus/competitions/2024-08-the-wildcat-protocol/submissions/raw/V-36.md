# Vulnerability details

## Proof of Concept
In the `_onCreateMarket` function, the `minimumDeposit` value is extracted from the `hooksData` calldata and then cast to `uint128`. However, this casting operation is unsafe, as it directly truncates a 256-bit word to a 128-bit value without validation.

The code responsible for this is as follows:
```solidity
uint256 minimumDeposit;
if (hooksData.length == 64) {
    assembly {
        minimumDeposit := calldataload(add(hooksData.offset, 0x20))
    }
    emit MinimumDepositUpdated(marketAddress, uint128(minimumDeposit));
}
```
- `calldataload` retrieves 32 bytes (256 bits) from the calldata, which means it can hold a much larger value than `uint128`.
- The cast from `uint256` to `uint128` happens without validation:
```solidity
uint128(minimumDeposit)
```
This casting truncates the upper 128 bits of the value, leading to potential data loss if the extracted `minimumDeposit` exceeds the range of `uint128`.
This casting operation truncates the upper 128 bits of the 256-bit word. When the `minimumDeposit` value exceeds the `uint128` range, the casting will drop the upper 128 bits, storing only the lower 128 bits. This results in an incorrect and unintended value being stored for `minimumDeposit`, which could lead to misconfigurations in the market’s deposit limit.
## Impact
If a value exceeding uint128 is provided for minimumDeposit, the truncation may lead to an unintended, smaller deposit limit being set. This could potentially allow users to deposit less than the intended minimum, affecting the overall market's deposit security and financial parameters.


## Tools Used
Manual
## Recommended Mitigation Steps
Use OpenZeppelin's SafeCast library to ensure the value is safely downcast to uint128 with proper validation. This way, if the value exceeds the allowed range for uint128, the transaction will revert instead of silently failing.
