# Vulnerability details

## Summary

The `errors.cairo` contract defines various errors using inconsistent formats, such as plain strings, decimal, and hexadecimal representations of ASCII strings. For instance, `evm.cairo` uses both string and hexadecimal formats, while `Interpreter.cairo` uses a mix of decimal and string formats. Although decimal and hexadecimal differ only in how data is represented, this inconsistency can cause parsing errors, debugging challenges, and compatibility issues during data exchange. The recommendation is to standardize error definitions, preferably using hexadecimal, or at least maintain uniformity within the same file.

## Proof of Concept

In the `errors.cairo` contract, functions are used to define various types of errors. The issue arises from the fact that some errors are defined as plain strings, while others are defined using the decimal or hexadecimal representations of ASCII strings. Additionally, the same contract contains different formats for defining ASCII strings. For example, the `evm.cairo` contract includes the errors `eth_validation_failed` and `outOfGas`, which are defined using hexadecimal and string formats, respectively. Similarly, the `Interpreter.cairo` contract includes the errors `unknownOpcode`, `stackOverflow`, `stackUnderflow`, `balanceError`, `addressCollision`, `outOfGas`, and `nonceIsMax`, where the first three are defined in decimal and the last four in plain strings.

The difference between decimal and hexadecimal is merely in how the data is represented, as the underlying ASCII codes and strings are the same. Decimal is typically more readable and suited for display purposes, whereas hexadecimal is more commonly used in programming, network transmission, and encryption scenarios.

**Potential Issues**:

1. **Error Parsing**: If an application expects decimal input but receives hexadecimal input, it could lead to data parsing errors. For example, "41" might be interpreted as the decimal value 41 (representing the character ")") instead of the character 'A'.

2. **Debugging and Compatibility**: Using different formats for representing data can create debugging or compatibility issues when exchanging data between systems. Ensuring a consistent encoding format is important for seamless data transmission.
