# Vulnerability details

## Description
There are two possible ways of sending a transaction in Kakarot EVM. One way is calling the `eth_send_raw_unsigned_tx`:
```
@external
func eth_send_raw_unsigned_tx{
    syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr, bitwise_ptr: BitwiseBuiltin*
}(tx_data_len: felt, tx_data: felt*) -> (
    return_data_len: felt, return_data: felt*, success: felt, gas_used: felt
) {
...
...
}
```

This function takes the raw transaction data and runs various checks on the transaction and the caller. One of the checks is making sure the sender has enough [balance to run the transaction](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/eth_rpc.cairo#L300):
```
    let (is_balance_enough) = uint256_le(tx_cost, balance);
    with_attr error_message("Not enough ETH to pay msg.value + max gas fees") {
        assert is_balance_enough = TRUE;
    }
```

Another way to send a transaction in Kakarot is via L1 -> L2 messages. These messages are consumed by [the handle_l1_message function](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/kakarot.cairo#L370):
```
@l1_handler
func handle_l1_message{
    syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr, bitwise_ptr: BitwiseBuiltin*
}(from_address: felt, l1_sender: felt, to_address: felt, value: felt, data_len: felt, data: felt*) {
```

The problem is the above function doesn't actually run any checks on the sent messages. It just calls the `handle_l1_message` function [in the library.cairo](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L435) which then calls the `eth_call` [function](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L78).

After `eth_call` is called the transaction is basically executed via `execute` function in [interpreter.cairo](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L820).

In L1 -> L2 messages there are no validations done on the transaction or the sender's balance. This leads to underflow in the `execute` function of the `interpreter.cairo` [when the fee is substracted from the sender's balance](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L950):
```
        let max_fee = gas_limit * env.gas_price;
        let (fee_high, fee_low) = split_felt(max_fee);
        let max_fee_u256 = Uint256(low=fee_low, high=fee_high);

        with state {
            let sender = State.get_account(env.origin);
            let (local new_balance) = uint256_sub([sender.balance], max_fee_u256);
            let sender = Account.set_balance(sender, &new_balance);
```

In the above function, `let (local new_balance) = uint256_sub([sender.balance], max_fee_u256);` line leads to underflow. This is because `sender.balance` will be 0 given there are no STRK tokens in the L1 sender account. So the `new_balance` value will actually hold a really large value. ## Impact

One of the impacts I have found is being able to execute transactions in Kakarot without actually paying for any gas fees. This is due to following faulty check in the `execute` function of the [interpreter.cairo](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L1035):

```
        with state {
            State.add_transfer(transfer);
            State.finalize();
        }

```

In the above function, `State.add_transfer` function will return 0 (failed transfer / no success) but this return value is not checked which allows the state to finalize. Due to the combination of lack of validation on L1 -> L2 messages and lack of check on the return value of the `add_transfer` function, a sender with 0 balance can execute transactions without actually paying for the fee.

Note that the above exploit only works with L1 -> L2 messages because txs sent via `eth_send_raw_unsigned_tx` function will check if the sender has enough balance to cover for the gas fees.

## Remediation

The first fix should be adding the extra validations done in the `eth_send_raw_unsigned_tx` to the `handle_l1_message` function. This would make sure the transaction goes through the same validations before it's executed.

Second fix would be checking the return value of the `add_transfer` function in the `interpreter.cairo`. This would prevent the finalizing the state if the fee transfer fails.
