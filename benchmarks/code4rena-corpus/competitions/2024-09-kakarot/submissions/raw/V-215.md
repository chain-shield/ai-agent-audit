# Vulnerability details

## Title
No overflow prevention in `interpreter::execute()` leading to attacker bypassing execution gas cost

## Links to affected code
https://github.com/kkrt-labs/kakarot/blob/b8f5f2a20bd733cc8885c010291885e1df7dc50e/cairo_zero/kakarot/interpreter.cairo#L846C2-L848C61

## Impact 
The function [interpreter::execute()](https://github.com/kkrt-labs/kakarot/blob/b8f5f2a20bd733cc8885c010291885e1df7dc50e/cairo_zero/kakarot/interpreter.cairo#L846C2-L848C61) is used to execute the given bytecode with the given calldata and parameters and it returns the required amount of gas by the transaction to successfully execute. 

The issue arises here because the block:

```rust
        let count = count_not_zero(calldata_len, calldata);
        let zeroes = calldata_len - count; // @audit attacker can overflow and make the transaction free

        let calldata_gas = zeroes * 4 + count * 16;
        let intrinsic_gas = Gas.TX_BASE_COST + calldata_gas;
```
Due to not implementing any overflow check in computing the intrinsic gas usage, Attacker can craft calldata such as the `let calldata_gas = zeroes * 4 + count * 16;` overflows and become zero which will clearly bypass the computation of intrinsic gas usage by the transaction execution or at worst can DOS the execution of the function. 

The issue is mitigated in the geth implementation by implementing the overflow check here:
https://github.com/ethereum/go-ethereum/blob/3e567b8b2901611f004b5a6070a9b6d286be128d/core/state_transition.go#L70
