# Vulnerability details

During transaction validation in `execute_from_outside()`, the Kakarot chain id is correctly used to calculate `v`, effectively preventing replay attacks. However, even though it is not explicitly specified in EIP-155, Ethereum nodes such as go-ethereum also verify that the chainId field in the RLP-encoded transaction data matches the expected value, while Kakarot ignores the value. 

This might allow for scenarios where users are tricked into signing a transaction with an apparent different chainID that would however execute in Kakarot.

## Proof of Concept

The following test demonstrates this issue.

```
from eth_account.account import Account, SignedTransaction
from eth_account._utils.signing import sign_transaction_hash
from eth_account._utils.legacy_transactions import (
    serializable_unsigned_transaction_from_dict,
    encode_transaction
)
from eth_utils import keccak

class TestChainId:
        def test_chainid_ignored(
            self, cairo_run
        ):
            transaction = {
                "to": "0xF0109fC8DF283027b6285cc889F5aA624EaC1F55",
                "value": 1_000_000_000,
                "gas": 2_000_000,
                "gasPrice": 234567897654321,
                "nonce": 0,
                "chainId": 0x1337,
                "data": b"",
            }
            tx_data = list(rlp_encode_signed_data(transaction))
            private_key = generate_random_private_key()
            address = int(private_key.public_key.to_checksum_address(), 16)

            account = Account.from_key(private_key)

            unsigned_transaction = serializable_unsigned_transaction_from_dict(
                transaction, blobs=None
            )

            transaction_hash = unsigned_transaction.hash()

            (v, r, s) = sign_transaction_hash(account._key_obj, transaction_hash, CHAIN_ID)

            encoded_transaction = encode_transaction(unsigned_transaction, vrs=(v, r, s))

            transaction_hash = keccak(encoded_transaction)

            signed = SignedTransaction(
                raw_transaction=HexBytes(encoded_transaction),
                hash=HexBytes(transaction_hash),
                r=r,
                s=s,
                v=v,
            )

            signature = [*int_to_uint256(signed.r), *int_to_uint256(signed.s), signed.v]

            with (
                SyscallHandler.patch("Account_evm_address", address),
                # Will fail during eth_call / *after* transaction validation
                cairo_error(message="Got an exception while executing a hint."),
            ):
                cairo_run(
                    "test__execute_from_outside",
                    tx_data=tx_data,
                    signature=signature,
                    chain_id=CHAIN_ID,
                )
```

## Recommended Mitigation Steps

Validate that the `chainId` field in the decoded transaction matches the expected value.
