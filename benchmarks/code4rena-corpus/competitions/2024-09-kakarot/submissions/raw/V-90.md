# Vulnerability details

The function `decode()` in `eth_transaction.cairo` is responsible for selecting the correct decoder for the given transaction type. It uses the `tx_type` item of the RLP-decoded transaction data as an offset into a jump table.

The provided type is validated using the following assertion:

```
        let is_supported = is_nn(2 - tx_type);
        with_attr error_message("Kakarot: transaction type not supported") {
            assert is_supported = TRUE;
        }
```

While `tx_data` is supposed to be a bytes array, there is no guarantee that the felt elements in the `tx_data` array provided to `eth_send_raw_unsigned_tx` (when called directly) are in the range 0..255. As a result, many of the assumptions in the transaction decoder are broken. 

Most of the time, this is not a problem since only account contracts created by Kakarot can successfully execute this function (otherwise, the transaction will revert during `eth_send_transaction()` / `safe_get_evm_address()`. This case is an exception since execution never reaches the sender address check in `safe_get_evm_address()`.

If `tx_type` is set to a value near `FIELD_PRIME`, the calculation `2 - tx_type` will underflow into a value within the expected bounds and the `is_nn()` check will pass.

As a result, the calculated offset will point into uninitialized memory, potentially allowing a malicious prover to craft/prove a transaction that executes arbitrary Cairo code. Note that whether actual code execution is possible depends on the underlying Cairo VM.

Note that this issue was previously reported by Zellic ([audit report](https://github.com/kkrt-labs/kakarot/blob/main/audits/cairo_zero/Kakarot%20EVM%20-%20Zellic%20Audit%20Report.pdf) chapter 3.25) and fixed by KKRT labs but the fix is insufficient.


## Proof of Concept

We can demonstrate this issue by modifying a line in the `helpers.py` test utility:

```
FIELD_PRIME = 2**251 + 17 * 2**192 + 1

def rlp_encode_signed_data(tx: dict) -> bytes:
    if "type" in tx:
        typed_transaction = TypedTransaction.from_dict(tx)

        sanitized_transaction = transaction_rpc_to_rlp_structure(
            typed_transaction.transaction.dictionary
        )

        # RPC-structured transaction to rlp-structured transaction
        rlp_serializer = (
            typed_transaction.transaction.__class__._unsigned_transaction_serializer
        )
        encoded_unsigned_tx = [
            FIELD_PRIME - 1,
            # typed_transaction.transaction_type,
            *rlp.encode(rlp_serializer.from_dict(sanitized_transaction)),
```

With this modified code, we run any of the `test__eth_send_raw_unsigned_tx` tests. The invalid chain id will not be detected. Instead, we will reach the `jmp rel offset` instruction:

```
Error at pc=0:25127:

Could not complete computation jmp rel of non pure value: 3:2.
        jmp rel offset;
        ^************^

```
