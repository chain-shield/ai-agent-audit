Issue Type: Under/Overflow

1. Vulnerability Details

The code contains potential vulnerabilities related to arithmetic, specifically in functions utilizing subtraction and division which may lead to underflow or overflow conditions.

**Affected Code Sections:**

Function**: `saturated_sub`
- **Description**: This function performs subtraction where the result can potentially be negative. The function currently returns 0 in such a case, which may lead to unintended behavior if the subtraction is not handled correctly. In deeper contexts (e.g. external contract calls that utilize this function), this can cause loss of funds.
  
2. Proof of Concept

To illustrate the vulnerability, consider the following scenario where an arithmetic operation leads to underflow:

```python
let res = saturated_sub(10, 20);  // Should be an underflow but returns 0 instead
```

In this case, the expected behavior would be to notify that the operation is invalid, but it silently returns 0. This can be exploited by calling this function with carefully crafted inputs, resulting in losses or unexpected states.

**Additional Example:**

Suppose an attacker can continuously call `saturated_sub` with values leading to negative results, thereby draining a contract's balance inadvertently over several transactions.

3. Recommendations for Mitigation Steps

- **Input Validation**: Implement strict input validation within `saturated_sub` to ensure that inputs conform to expected ranges before performing subtraction.
  
- **Error Handling**: Instead of returning `0` on underflow, it’s crucial to revert the transaction or return a specific error message indicating that an underflow has occurred. This will ensure that all unexpected conditions are handled appropriately.
  
- **Use Safe Math Libraries**: Incorporate a safe math library that automatically handles overflow/underflow checking for all arithmetic operations.
