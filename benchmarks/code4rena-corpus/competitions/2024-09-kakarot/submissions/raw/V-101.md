# Vulnerability details

Issue Summary:
The deploy function in the Starknet contract uses Kakarot_uninitialized_account_class_hash to deploy an account. However, there is no validation to ensure that this class hash corresponds to a legitimate contract. This opens up a vulnerability where a malicious actor can manipulate the class_hash and deploy untrusted or malicious contracts instead of the intended ones.

let (
    uninitialized_account_class_hash: felt
) = Kakarot_uninitialized_account_class_hash.read();
let (constructor_calldata_len, constructor_calldata) = Account.get_constructor_calldata(
    evm_address
);
let (starknet_address) = deploy_syscall(
    uninitialized_account_class_hash,
    contract_address_salt=evm_address,
    constructor_calldata_size=constructor_calldata_len,
    constructor_calldata=constructor_calldata,
    deploy_from_zero=FALSE,
);

Proof of Concept:
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/backend/starknet.cairo#L179
In the above code, the Kakarot_uninitialized_account_class_hash is read and used for deployment without any validation.
If an attacker gains access to manipulate the class_hash, they could deploy a malicious or unauthorized contract instead of the legitimate one.
This would allow them to compromise the integrity of the system by gaining control of contracts or deploying harmful contracts.


Impact:
By exploiting this vulnerability, an attacker could:
Deploy a malicious contract instead of the intended one.
Take control of contracts and manipulate their behavior.
Compromise the entire system, leading to unauthorized operations or loss of funds.

Recommended Mitigation Steps:
Validate the Class Hash: Ensure that the class hash corresponds to an authorized and legitimate contract before deployment. Add a validation step, such as:
if class_hash != AUTHORIZED_CLASS_HASH:
    raise ValueError("Invalid class hash")
Signature or Hash Checks:
Implement cryptographic signature checks or hash-based verification to ensure only approved contracts can be deployed using the class_hash.

Proof of Concept:
Vulnerability Overview:
In the Starknet contract, the deploy function leverages the Kakarot_uninitialized_account_class_hash to create new accounts. The issue arises because there is no validation step to ensure that this class hash is legitimate. Without this validation, an attacker could potentially manipulate the class_hash and deploy a malicious contract instead of an intended, authorized contract.

Vulnerable Code Snippet:
Here is the code section in starknet.cairo that directly references the use of Kakarot_uninitialized_account_class_hash:

let (uninitialized_account_class_hash: felt) = Kakarot_uninitialized_account_class_hash.read();
let (constructor_calldata_len, constructor_calldata) = Account.get_constructor_calldata(evm_address);
let (starknet_address) = deploy_syscall(
    uninitialized_account_class_hash,
    contract_address_salt=evm_address,
    constructor_calldata_size=constructor_calldata_len,
    constructor_calldata=constructor_calldata,
    deploy_from_zero=FALSE,
);


In the above code, the uninitialized_account_class_hash is read from storage and then used directly in the deploy_syscall. However, there is no validation mechanism to check whether the class_hash corresponds to a legitimate, authorized contract.

Exploit Example:
If an attacker gains access to modify or influence the value of Kakarot_uninitialized_account_class_hash, they could deploy a malicious contract. For example, they could point this class hash to a contract that allows unauthorized fund transfers or manipulates governance logic.

Steps to Reproduce:
Attacker Influence on class_hash: By manipulating the value of Kakarot_uninitialized_account_class_hash to a malicious contract's class hash.

Contract Deployment: The Starknet.deploy function will then deploy the malicious contract instead of the intended legitimate contract.

Exploit Outcome: The attacker gains control over the deployed contract and can use it to perform unauthorized actions, such as accessing funds or executing harmful logic.


Execution Logs: Assuming you have control over modifying Kakarot_uninitialized_account_class_hash, the execution logs would show the successful deployment of a contract that was not originally intended.
