# Vulnerability details

The get_tx_type function checks if tx_data_len is zero, but it does not explicitly check whether the tx_data pointer is null. If tx_data_len is non-zero but tx_data points to a null or invalid memory address, dereferencing it can lead to undefined behavior, crashes, or worse, contract compromise.

Impact: Dereferencing a null or invalid pointer can result in the execution of unintended code or unexpected contract behavior, potentially allowing attackers to cause contract failure or exploit other vulnerabilities caused by undefined behavior.

Exploit Scenario:

An attacker provides input where tx_data_len is non-zero, but tx_data is set to 0 (null). Since the contract does not check for null pointers, when it dereferences tx_data, it causes the contract to behave unpredictably, possibly leading to denial of service (DoS) by causing the contract to revert or fail.

Recommendation:

Add a check to ensure that tx_data is not null before dereferencing it. For example:

if tx_data == 0 {
    with_attr error_message("tx_data pointer is null") {
        assert false;
    }
}
