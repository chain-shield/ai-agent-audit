# Vulnerability details

The `read_storage` function in `account.cairo` implements account storage read and writes for Kakarot smart contract accounts. The account class stores a pointer to a dict that contains the data of "warm" storage slots. The `dict` module from the common Starknet library is used.

The `dict_read()` function returns the value of an existing dictionary key. However, `dict_read()` by itself does not verify the consistency of the returned values. From the [Cairo 0 documentation](https://docs.cairo-lang.org/reference/common_library.html#dict-read):

```
Note that the consistency of the returned value from dict_read() is only verified at the hint level (technically, dict_read() appends one DictAccess instruction to the dictionary).
To make sure that a malicious prover won’t be able to return a different value one must eventually call dict_squash().
```

Since `dict_squash()` is never called on the storage dict, a malicious prover can return arbitrary values whenever warm storage slots are read. This breaks the integrity of smart contract execution on Kakarot.


## Proof of Concept

It is challenging to provide an end-to-end proof-of-concept for this issue because we would have to use modified versions of both the Starknet core libraries and Katana (as the hint code must match exactly). We can however demonstrate the issue with unit tests and a modified `cairo-lang` package.

First, we modify the code in `starkware/common/dict.cairo` in our `cairo-lang-0.13.1` Python library. We change the hint in `dict_read` to return `0` instead of the actual value:

```
// Reads a value from the dictionary and returns the result.
func dict_read{dict_ptr: DictAccess*}(key: felt) -> (value: felt) {
    alloc_locals;
    local value;
    %{
        dict_tracker = __dict_manager.get_tracker(ids.dict_ptr)
        dict_tracker.current_ptr += ids.DictAccess.SIZE
        # ids.value = dict_tracker.data[ids.key]
        ids.value = 0
    %}
    dict_ptr.key = key;
    dict_ptr.prev_value = value;
    dict_ptr.new_value = value;
    let dict_ptr = dict_ptr + DictAccess.SIZE;
    return (value=value);
}
```

## Recommended Mitigation Steps

Make sure to finalize all account storage dicts with `default_dict_finalize()`.
