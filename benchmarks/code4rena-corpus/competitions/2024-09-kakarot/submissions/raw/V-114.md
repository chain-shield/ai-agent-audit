# Vulnerability details

## Impact

May cause problems with double spending

## Proof of Concept
When the evm transaction is executed, the `eth_send_raw_unsigned_tx` function verifies whether `tx.chain_id` is the same as the current `chain_id`.

But the problem is, if `chain_id` is empty, `chain_id` will not be validated:

The problem is that an attacker or malicious user can set the signature type to `eip155` but use an empty `chain_id` so that the `chain_id` check can be skipped.

When `tx_type` is 0 and tx data is parsed using the `decode_legacy_tx` function, an attacker can set the chain id to null (is_some = false):

If the chain id is not verified, this can cause problems with double spending, 
where a malicious user keeps using the empty chain id for transactions, and when the chain is hard forked, the attacker can use the previous signature to make the transaction execute again.
