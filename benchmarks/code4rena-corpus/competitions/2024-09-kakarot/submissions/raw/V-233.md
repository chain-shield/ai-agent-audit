# Vulnerability details

## Description

The sendMessageToL1 function in CairoLib lacks payload size validation, creating a vulnerability where arbitrarily large messages can be sent from L2 to L1. This exposes both layers to gas exhaustion risks through uncontrolled memory expansion during message processing. Without proper bounds, the function could consume excessive gas on L2 and potentially create unprocessable messages on L1, affecting the reliability of the cross-layer messaging system.

## Code Snippet

```solidity
function sendMessageToL1(bytes memory payload) internal {
    (bool success,) = CAIRO_MESSAGE_PRECOMPILE.call(payload);
    require(success, "CairoLib: sendMessageToL1 failed");
}
```

This current implementation makes a direct call to `CAIRO_MESSAGE_PRECOMPILE` (0x0000000000000000000000000000000000075002) with an unbounded payload. The precompile is responsible for handling the cross-layer message passing between Starknet (L2) and Ethereum (L1). However, without size validation, this creates several critical issues in the messaging system:

1. Quadratic gas scaling with payload size
2. Unpredictable memory expansion costs
3. Potential for gas exhaustion attacks
4. Risk of creating unprocessable L1 messages

When the function processes a message, all payload data must be loaded into memory. The EVM charges gas for memory expansion quadratically, making large payloads exponentially more expensive. The lack of a size bound means the gas cost could unexpectedly spike based on payload size.

## Proposed Fix
A safer implementation would be:

```solidity
library CairoLib {
    // Conservative limit based on typical L1/L2 message processing constraints
    uint256 private constant MAX_MESSAGE_SIZE = 128 * 1024; // 128KB 

    function sendMessageToL1(bytes memory payload) internal {
        uint256 size = payload.length;
        require(size > 0, "CairoLib: empty message");
        require(
            size <= MAX_MESSAGE_SIZE,
            "CairoLib: message size exceeds maximum allowed"
        );

        // Calculate memory expansion cost
        uint256 words = (size + 31) / 32;
        uint256 memoryGas = (words * 3) + (words * words / 512);
        require(
            gasleft() > memoryGas * 2,
            "CairoLib: insufficient gas for memory expansion"
        );

        (bool success, bytes memory result) = CAIRO_MESSAGE_PRECOMPILE.call(payload);
        if (!success) {
            assembly {
                revert(add(32, result), mload(result))
            }
        }
    }
}
```

The fix introduces several crucial safety mechanisms while staying within the library's context:
- Static size limit based on practical L1/L2 message processing constraints
- Memory expansion gas calculation and validation
- Proper error propagation from the precompile
- Empty message check to prevent wasteful operations
