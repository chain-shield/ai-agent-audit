This function is used to commit the account to the storage backend at given address, now it's been hinted that this should follow `EIP-6780`, issue however is that in this case if the contract is selfdestructed and then [funds are sent **after**, the funds are then burnt](https://github.com/kkrt-labs/kakarot/blob/6496ee1d18380dae5b069c27b3129d82ae282419/cairo_zero/backend/starknet.cairo#L159), this goes against both the EIP and also classic EVM implementation considering.

Considering funds can actually be sent to any address be it it has smart contract code or not.

Also going to the implementation of the [EIP](https://eips.ethereum.org/EIPS/eip-6780), we can see the below hinted whenever selfdestruct is called in the same tx as the creation:

> 2. When `SELFDESTRUCT` is executed in the same transaction as the contract was created:

> - `SELFDESTRUCT` continues to behave as it did prior to this EIP, this includes the following actions
>   - The current execution frame halts.
>   - `SELFDESTRUCT` deletes data as previously specified.
>   - `SELFDESTRUCT` transfers the entire account balance to the target
> - The account balance of the contact calling `SELFDESTRUCT` is set to `0`.
> - Note that if the target is the same as the contract calling `SELFDESTRUCT` that Ether will be burnt.
> - Note that no refund is given since [EIP-3529](./eip-3529.md).
> - Note that the rules of [EIP-2929](./eip-2929.md) regarding `SELFDESTRUCT` remain unchanged. there are no implications that the funds at the contract should be burnt if sent after the contract has been self destructed, in our case this then means that if a user:

But as shown above in Kakarot's case the funds are never sent to the `target` after self destructing which means that user's funds are lost.

## Impact

Un-equivalence with the EVM's `SELFDESTRUCT` and in this case would mean users always losing their funds whenever they attempt this since their funds are burnt instead of being sent to the `target`.

## Recommended Mitigation Steps

Query for a `target` for the `SELFDESTRUCT` and then instead of burning the funds, send them to the target post `SELFDESTRUCT`.
