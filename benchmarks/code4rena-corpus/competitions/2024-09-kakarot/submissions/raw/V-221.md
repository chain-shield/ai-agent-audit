# Vulnerability details

## Proof of Concept

Currently, there are 2 functions that interact with transient storage - in particular, it's `read_transient_storage()` and `write_transient_storage()`:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/state.cairo#L314-340
```
  // @notice Reads the transient storage of an account at the given key.
    // @param evm_address The EVM address of the account to read.
    // @param key The key of the storage slot to read.
    // @return The value of the storage slot.
    func read_transient_storage{
        syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr, state: model.State*
    }(evm_address: felt, key: Uint256*) -> Uint256* {
        alloc_locals;
        let account = get_account(evm_address);
        let (account, value) = Account.read_transient_storage(account, key);
        update_account(account);
        return value;
    }

    // @notice Updates the transient storage of an account at the given key with the given value.
    // @param evm_address The EVM address of the account to update.
    // @param key The key of the storage slot to update.
    // @param value The new value of the storage slot.
    func write_transient_storage{
        syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr, state: model.State*
    }(evm_address: felt, key: Uint256*, value: Uint256*) {
        alloc_locals;
        let account = get_account(evm_address);
        let account = Account.write_transient_storage(account, key, value);
        update_account(account);
        return ();
    }
```

The problem is that the transient storage has to be reset at the beginning of the transaction execution but the current version of `interpreter` fails to do so. According to the geth execution client implementation:

https://github.com/ethereum/go-ethereum/blob/master/core/state/statedb.go#L1346
```
// Reset transient storage at the beginning of transaction execution
	s.transientStorage = newTransientStorage()
```

This makes the current VM version incompatible with EIP-1153 even though it has to be as it has the functionality to interact with transient storage inside of `state.cairo`:

https://eips.ethereum.org/EIPS/eip-1153

## Recommended Mitigation Steps

Reset the transient storage at the beginning of the transaction execution.
