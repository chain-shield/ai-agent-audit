# Vulnerability details

## Proof of Concept
The compute_code_hash function does not validate the length of the code or check if the input size exceeds safe limits. This opens the function up to potential integer overflows when handling unusually large input sizes. Without input validation, an attacker could submit inputs that are either too large or malformed, causing the system to behave unexpectedly.
```
func compute_code_hash{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    code_len: felt, code: felt*
) -> Uint256 {
    alloc_locals;
    if (code_len == 0) {
        ...
    }
    ...
}
```


Impact: If the function processes a large or malformed bytecode length, it could cause an overflow, which might result in incorrect code hash computation. This could lead to mismatched bytecode verification and even denial of service if the input causes the function to consume too many resources.

PoC:

Call the compute_code_hash function with an oversized byte array or length exceeding the maximum limit.
Observe how the function handles the large input, potentially causing an overflow or incorrect code hash computation.


```

An attacker provides an unusually large input to compute_code_hash, which results in an overflow and incorrect computation of the hash. This could either lead to a denial of service or incorrect verification of smart contract bytecode.

Implement strict input validation on the code_len parameter to ensure it does not exceed safe limits. Set an upper bound on the maximum size of input and reject anything larger.

    code_len: felt, code: felt*

    require(code_len <= MAX_CODE_SIZE, "Code length exceeds maximum allowed size");

```
