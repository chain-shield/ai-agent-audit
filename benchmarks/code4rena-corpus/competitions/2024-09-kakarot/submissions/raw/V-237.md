# Vulnerability details

## Vulnerability Details:
The protocol relies on function [verify_eth_signature_uint256()](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/utils/signature.cairo#L10-L35) to verify that the provided signature is valid, 
with help of starkware library it does checks that the value  of r and s is in the range [1,N) 
and that the limbs of value are in the range [0,Base).

However due to insufficient checks inside func verify_eth_signature_uint256() it allows signature malleability. 

Example:
If the library generates a signature such as s-values is in the upper range, we can calculate a new 
s-value with 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141 - s1 
and flip v from 27 to 28 or vise versa to accept this malleable signature as well.

## Impact:

When a signature is malleable, it means that another valid signature can be created for the same message.
An attacker could maipulate and intercepted signature to create another valid signature that the function would still verify as correct leading to unauthorized actions such as performing operations or access rights reserved to original signer.

## Recommended Mitigation:
Consider applying a check on s-value of the signature to ensure is it in valid range to avoid signature malleability.

if (s_bigint > 0x7FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF5D576E7357A4501DDFE92F46681B20A0)
{
	 return();
}
