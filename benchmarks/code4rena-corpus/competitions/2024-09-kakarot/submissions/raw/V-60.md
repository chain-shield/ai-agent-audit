# Vulnerability details

## Summary

The `load_word()` function in `crates/utils/src/helpers.cairo` loads a sequence of bytes into a single u256 in big-endian format. Although it includes a constraint on the number of bytes to load, it lacks additional checks necessary to ensure the function operates correctly. 

## Vulnerability details 

As mentioned earlier, the `load_word()` function converts a sequence of bytes (words) of length len into a `u256` integer, and proper validation of input parameters is crucial, given its widespread use in the codebase.

While the function handles the case when `len == 0`, there is no check for empty or null `words` Span. This could cause runtime errors if `words` is an empty slice but `len` is non-zero.

Additionally, the function does not check if variable `counter` exceeds the bounds of `words`. If `len` is greater than the actual length of `words`, this could lead to out-of-bounds memory access, which is an important security concern. It could result in undefined behavior, including crashes or potential exploitation.

```rust
pub fn load_word(mut len: usize, words: Span<u8>) -> u256 {
    if len == 0 {
        return 0;
    }
    
    let mut current: u256 = 0;
    let mut counter = 0;

    while len != 0 {
        let loaded: u8 = *words[counter];
        let tmp = current * 256;
        current = tmp + loaded.into();
        len -= 1;
        counter += 1;
    };

    current
}

```

The `test_load_word` test does not account for the edge cases mentioned above. Other critical checks, such as handling null or empty spans when len is non-zero and preventing out-of-bounds memory access, are missing from the test.

## Impact 

If the function attempts to access elements in words beyond its allocated memory, it may lead to undefined behavior due to an out-of-bounds access. This could result in a denial-of-service by attempting to dereference an invalid pointer or access a non-existent element in words, causing a crash, especially since the function is used in multiple parts of the codebase.

## Recommended Mitigation Steps

1. Add a check to ensure that `counter` never exceeds `words.len()`.

```
if counter >= words.len() {
    // Handle error or break the loop
}
```
2. Add a check that `words` is not empty when `len > 0`.
