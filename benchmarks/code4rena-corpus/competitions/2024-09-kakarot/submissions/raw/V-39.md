## [M] Arbitrary Nonce Setting in set_nonce May Lead to Replay Attacks
	•	Severity: Medium
	•	Issue Type: EVM equivalence issues
	•	Location: Lines 
	
## Impact: 
Allowing the nonce to be set to an arbitrary value can enable replay attacks or nonce manipulation, which is inconsistent with EVM behavior.
```Cairo
@external
func set_nonce{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(nonce: felt) {
    // Access control check.
    Ownable.assert_only_owner();
    return AccountContract.set_nonce(nonce);
}
```

## Description: 
The set_nonce function allows the contract owner to set the nonce to any arbitrary value. In the EVM, the nonce should only increment by 1 with each transaction. Allowing arbitrary nonce values may cause inconsistencies with EVM behavior and could lead to replay attacks if the nonce is set to a lower value.

## Proof of Concept (PoC):
The contract owner could reset the nonce to a previous value, enabling the replay of old transactions or disrupting the transaction ordering.

## Recommended Mitigation Steps
Enforce that the new nonce must be greater than or equal to the current nonce.
```Cairo
let (current_nonce) = AccountContract.get_nonce();
with_attr error_message("Nonce must be greater than or equal to current nonce") {
    assert_le(current_nonce, nonce);
}
```
