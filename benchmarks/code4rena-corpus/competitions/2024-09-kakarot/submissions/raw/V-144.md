# Vulnerability details

## Proof of Concept

Currently, message call gas is computed using the following functionality:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/gas.cairo#L190-205
```
 func compute_message_call_gas{range_check_ptr}(gas_param: Uint256, gas_left: felt) -> felt {
        alloc_locals;
        let (quotient, _) = unsigned_div_rem(gas_left, 64);
        tempvar max_allowed_gas = gas_left - quotient;
        let (max_allowed_high, max_allowed_low) = split_felt(max_allowed_gas);
        tempvar max_allowed = Uint256(low=max_allowed_low, high=max_allowed_high);
        let (is_gas_param_lower) = uint256_lt(gas_param, max_allowed);

        // The message gas is the minimum between the gas param and the remaining gas left.
        if (is_gas_param_lower != FALSE) {
            // If gas is lower, it means that it fits in a felt and this is safe
            tempvar gas = gas_param.low + 2 ** 128 * gas_param.high;
            return gas;
        }
        return max_allowed.low;
    }

```

The problem lies in these lines:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/gas.cairo#L199-203
```
 if (is_gas_param_lower != FALSE) {
            // If gas is lower, it means that it fits in a felt and this is safe
            tempvar gas = gas_param.low + 2 ** 128 * gas_param.high;
            return gas;
        }

```

It's assumed by the protocol that if the `gas_param` < `max_allowed` then it's definitely fits into felt type. However, here `tempvar gas = gas_param.low + 2 ** 128 * gas_param.high;` it's not exactly true that this value can 100% fit into felt type. Felt is a type that is defined within this range:

https://book.cairo-lang.org/ch02-02-data-types.html
```
0≤x<P , where P
 is a very large prime number currently equal to 2251+17⋅2192+1
```

However, when we compare `gas_param` with `max_allowed`, we compare two uint256 values and it does not mean that one of the values is < felt252 if it's lower than the other number. Therefore, it can result in an overflow of the `gas` parameter.

## Recommended Mitigation Steps

Protect against overflow when computing the gas.
