# Vulnerability details

## Summary
The `execute_from_outside()` does not check if an account instance has been initialised, hence the `Account_evm_address` storage_var defaults to `0`, which when read by `execute_from_outside()` would default to `0x0...`, which is the Ethereum `zero/burn` address, therefore an attacker can successfully submit transactions made by the Ethereum `zero/burn` address.


## Vulnerability details
Kakarot privides a mechanism for validating and executing Ethereum transactions through the `execute_from_outside()` functions present in both `src/kakarot/accounts/account_contract.cairo` and `src/kakarot/accounts/library.cairo` (core logic), These functions contains a series of validation checks and verifications such as signature verification but does not check to see if the account instance initiating the function call has been initialised. This can prove a serious issue since cairo0 which kakarot is built on defaults `@storage_var` values to 0 which in address format would be `0x00...` (the Ethereum zero address). Hence an attacker can pass in valid transaction details `(tx_data_len: felt, tx_data: felt*, signature_len: felt, signature: felt*, chain_id: felt)` made by the Ethereum zero address and it will succesfully pass all checks and validation by `execute_from_outside()`

```cairo

            msg_hash=msg_hash,
```

The above snippet is from `execute_from_outside()` (src/kakarot/accounts/library.cairo), `Account_evm_address.read()` is called on an uninitialized account instance and thus it default to 0 which is assigned to `(address)` which is the subsiquently passed as an argument to `Signature.verify_eth_signature_uint256()` as `eth_address=address` therefore everything would check out and the verification will be passed.
This can prove `highly severe` as an attacker can do this with multiple uninitalised accounts for a single valid `eth_zero` transaction.

It's also worth of `note` that contrary to what most people think, eth_zero (0x0.... or address(0)) address does make transactions and isn't just used as a plain burn address, as you can see here https://etherscan.io/address/0x0000000000000000000000000000000000000000#tokentxns.

##  Impact
This issue can lead to Kakarot VM validate and execute Ethereum zero/burn address transactions for an attackers account instance before initialisation with acutal evm address 

## Recommended Mitigation Steps
Require `execute_from_outside()` to assert `Account_is_initialized.read() = 1` before the rest of the transaction life cycle.
