# Vulnerability details

## Proof of Concept

Currently `eth_rpc.cairo` is serves as a place where validation of the transaction happens after which it's sent to the Karakot. The problem is that there is a nonce validation where a nonce of the caller is compared to the nonce of the signer of the transaction resulting in an error if the caller is the relayer address.

Take a look at the `eth_send_raw_unsigned_tx()` function implementation:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/eth_rpc.cairo#L260-263
```
let (account_nonce) = IAccount.get_nonce(contract_address=caller_address);
    with_attr error_message("Invalid nonce") {
        assert tx.signer_nonce = account_nonce;
    }
```

As you can see here, the nonce of the `caller_address` is derived and then compared to the `tx.signer_nonce`. And as Karakot allows to use paymaster mechanism which means that the Starknet transaction that will lead to the execution of the EVM transaction can be submitted by external relayer. Therefore, it will result to incorrect nonce verification and an error as the nonce of the user who signed the tx will differ from the nonce from the relayer contract address that actually sent the tx.

## Recommended Mitigation Steps

Check the nonce of the actual sender (add additional field) and not the caller address to avoid situation where relayer will invoke `execute_from_outside()` functionality.
