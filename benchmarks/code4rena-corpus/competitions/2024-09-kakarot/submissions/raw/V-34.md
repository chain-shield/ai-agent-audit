## [M3] Data Packing/Unpacking Issue in split_felt(max_gas_fee)

Severity: Medium
Issue Type: Data Serialization/Deserialization Error

Impact: 
If max_gas_fee exceeds the size of a felt, the split_felt function will not correctly split the value into high and low parts, leading to incorrect computations of transaction costs and potential security vulnerabilities.

Location: eth_send_raw_unsigned_tx function, when splitting max_gas_fee.
```Cairo
let (max_fee_high, max_fee_low) = split_felt(max_gas_fee);
```

Description:

The split_felt function is intended to split a felt into two 128-bit values (high and low). However, if max_gas_fee exceeds the size of a felt (251 bits), the splitting will not correctly represent the original value. This incorrect representation affects subsequent calculations, such as computing tx_cost, potentially allowing transactions to proceed with incorrect fees.

Proof of Concept:
```Cairo
If max_gas_fee is larger than 2**251 - 1, the split will not capture the full value:

// Assuming max_gas_fee > 2**251 - 1
let (max_fee_high, max_fee_low) = split_felt(max_gas_fee);
// max_fee_high and max_fee_low do not represent the correct value
```

## Recommended Mitigation Steps
Ensure that max_gas_fee fits within 256 bits before splitting, as per previous mitigation steps. Use multi-felt arithmetic for handling larger numbers:
```Cairo
// Use a function that correctly handles splitting of large numbers
let (max_gas_fee_high, max_gas_fee_low, carry) = uint256_mul(tx.gas_limit, tx.max_fee_per_gas);
```
