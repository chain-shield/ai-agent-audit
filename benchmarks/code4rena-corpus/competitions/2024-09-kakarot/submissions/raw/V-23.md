# Vulnerability details

## Summary

If the `compute_message_call_gas` function returns a gas value (`max_allowed.low`) smaller than the actual allowed `max_allowed` value, it may result in insufficient gas being allocated in the `exec_call`, `exec_staticcall`, `exec_callcode`, and `exec_delegatecall`function. This could cause the function to fail, lead to unintended rollbacks, or even introduce potential security risks. It is crucial to ensure that both the high and low parts of the `max_allowed` value are properly considered and returned, ensuring that the correct amount of gas is allocated for the message call.

## Proof of Concept

In the `System_operations.cairo` contract, functions such as `exec_call`, `exec_staticcall`, `exec_callcode`, and `exec_delegatecall` call the `compute_message_call_gas` function (from the `gas.cairo` contract) to calculate the base gas for a message call. The purpose of this function is to determine the minimum value between the `gas_param` and `gas_left` to ensure that the gas consumed by the call does not exceed the available gas.

However, if the function only returns the lower portion of the `max_allowed` value (i.e., `max_allowed.low`), while the full `max_allowed` is larger, this may lead to the following issues:

1. **Insufficient Gas Allocation**:
   Since `max_allowed.low` only represents the lower part of the full gas value, the resulting gas limit may be much lower than the actual allowed gas. If only the smaller value is returned, it can result in the function being executed with insufficient gas, leading to premature **Out of Gas** errors.

2. **Potential Security Risks**:
   A lower-than-expected gas limit can be exploited by attackers. For example, an attacker could manipulate gas parameters to trigger errors or halt execution, forcing the contract into an unintended state. This could compromise system stability or expose vulnerabilities.

```cairo
            // @notice Computes the base gas of a message call.
            // @dev This should be called after having withdrawn the gas relative to the
            // memory expansion and eventual extra gas costs.
            // @param gas_param The gas parameter of the message call, from the Stack.
            // @param gas_left The gas left in the current execution frame.
            // @return gas The base gas of the message call.
            func compute_message_call_gas{range_check_ptr}(gas_param: Uint256, gas_left: felt) -> felt {
                alloc_locals;
                let (quotient, _) = unsigned_div_rem(gas_left, 64);
                tempvar max_allowed_gas = gas_left - quotient;
                let (max_allowed_high, max_allowed_low) = split_felt(max_allowed_gas);
                tempvar max_allowed = Uint256(low=max_allowed_low, high=max_allowed_high);
                let (is_gas_param_lower) = uint256_lt(gas_param, max_allowed);

                // The message gas is the minimum between the gas param and the remaining gas left.
                if (is_gas_param_lower != FALSE) {
                    // If gas is lower, it means that it fits in a felt and this is safe
                    tempvar gas = gas_param.low + 2 ** 128 * gas_param.high;
                    return gas;
                }
@audit=>        return max_allowed.low;
            }
```

## Recommended Mitigation Steps

It is recommended that when the `gas_param` exceeds the remaining gas left, the `compute_message_call_gas` function should return the full `max_allowed` value instead of just `max_allowed.low`. This will ensure that the message call has the correct gas allocation to proceed without unnecessary failures or security concerns.
