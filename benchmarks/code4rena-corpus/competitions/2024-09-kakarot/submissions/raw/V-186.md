# Vulnerability details

## Description
When a contract is being created the `create` function is invoked. Inside it after a couple of checks the caller's nonce will be incremented by 1 and then a snapshot of the stateDB is taken: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/vm/evm.go#L449-L486
This means that even in the event that the code size exceeds the limit, after the reversion `revertToSnapshot` will revert back to the state where the caller's nonce is still incremented: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/vm/evm.go#L518-L539
However `exec_create` will not increment the caller's nonce in the case that the initcode exceeds the size limit: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/instructions/system_operations.cairo#L144-L153 instead it will simply push a 0 to the stack and return back to the caller.
This deviates from the EVM specification and can cause state divergence.

## Recommended Mitigation Steps
Remove the codesize check as it is superfluous since the returndata check in `finalize_parent` should be sufficient anyway,
