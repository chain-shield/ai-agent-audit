# Vulnerability details

## Description

The CairoLib's implementation of Cairo contract calls lacks proper existence checks for both precompile contracts on L1 and target contracts on L2 Starknet. Due to EVM's behavior of returning success for calls to non-existent contracts, this could lead to silent failures in cross-chain communication.

## Code Snippets

```solidity
function staticcallCairo(
    uint256 contractAddress, 
    uint256 functionSelector, 
    uint256[] memory data
) internal view returns (bytes memory) {
    bytes memory callData = abi.encode(contractAddress, functionSelector, data);
    
    (bool success, bytes memory result) = CAIRO_CALL_PRECOMPILE.staticcall(callData);
    require(success, string(abi.encodePacked("CairoLib: cairo static call failed with: ", result)));
    
    return result;
}
```


### L1 Precompile Existence

The library uses three precompiled contracts:

```solidity
address constant CAIRO_MESSAGE_PRECOMPILE = 0x0000000000000000000000000000000000075002;
address constant CAIRO_MULTICALL_PRECOMPILE = 0x0000000000000000000000000000000000075003;
address constant CAIRO_CALL_PRECOMPILE = 0x0000000000000000000000000000000000075004;
```

None of these precompiles are checked for existence before making calls. If a precompile is not deployed, calls will return success but fail to execute any cross-chain communication.

### L2 Contract Verification

The library accepts Cairo contract addresses without verifying their existence on Starknet. The `CairoCall` struct accepts any uint256 as a contract address:
```solidity
struct CairoCall {
    uint256 contractAddress;  // No validation
    uint256 functionSelector;
    uint256[] data;
}
```

## Impact

### Scenario: Undeployed Precompile

```solidity
function queryL2State() external view returns (bytes memory) {
    // If CAIRO_CALL_PRECOMPILE is not deployed:
    return staticcallCairo(
        VALID_L2_ADDRESS,
        "get_state",
        new uint256[](0)
    ); // Returns success but no actual L2 interaction
}
```


### Risks
1. Silent failures in cross-chain communication
2. False success reports for failed operations
3. Potential state inconsistencies between L1 and L2
4. Batch operation atomicity violations
5. Incorrect balance or state reads from L2

## Recommended Fix

### 1. Add Precompile Verification
```solidity
modifier validatePrecompile(address precompile) {
    require(precompile.code.length > 0, "CairoLib: precompile not deployed");
    _;
}
```

### 2. Add L2 Contract Verification
```solidity
function verifyL2Contract(uint256 l2ContractAddress) internal view returns (bool) {
    bytes memory verificationCall = abi.encode(
        l2ContractAddress,
        uint256(keccak256("get_contract_status")) % 2**250,
        new uint256[](0)
    );
    
    (bool success, bytes memory result) = CAIRO_CALL_PRECOMPILE.staticcall(verificationCall);
    if (!success || result.length == 0) return false;
    return true;
}
```

### 3. Secure Implementation
```solidity
function staticcallCairoSafe(
    uint256 contractAddress,
    uint256 functionSelector,
    uint256[] memory data
) internal view validatePrecompile(CAIRO_CALL_PRECOMPILE) returns (bytes memory) {
    require(verifyL2Contract(contractAddress), "CairoLib: L2 contract not deployed");
    
    bytes memory callData = abi.encode(contractAddress, functionSelector, data);
    (bool success, bytes memory result) = CAIRO_CALL_PRECOMPILE.staticcall(callData);
    
    require(success && result.length > 0, "CairoLib: invalid response from L2");
    return result;
}
```
