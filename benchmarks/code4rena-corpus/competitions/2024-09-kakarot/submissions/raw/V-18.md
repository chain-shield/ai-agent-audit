# Vulnerability details

The func felt_to_bytes_little writes directly to memory.

"memory[ids.output] = res;"


This means the function assumes that ids.output (the location in memory where the result is stored) is a valid memory location. However, without validation of this pointer, an attacker could manipulate the pointer to access unintended memory regions, potentially leading to memory corruption or even arbitrary code execution.
While Cairo's memory itself cannot be directly modified, pointers can be used to reference different memory locations. If an attacker can manipulate a pointer to point to an unintended location, they can effectively modify the memory at that location, even though the original memory content remains immutable.


Exploitation Example: Memory Corruption
Consider an attacker who manages to manipulate the dst (which impacts ids.output) so that it points to an address in memory where critical contract data or other function variables reside. By writing to this location, the attacker could overwrite data in memory, leading to various consequences:

Overwriting sensitive data: If the attacker writes over a function pointer, variable, or stored value in the contract, they could corrupt the contract’s logic. For example, the attacker might overwrite the return address of a function or a stored variable, causing it to return incorrect data.


func sensitive_function{...}(dst: felt*) {
    let secret_value = 0x1234;  // A critical piece of data
    // Malicious dst could be manipulated here to point to `secret_value`
    memory[dst] = 0xdeadbeef;  // Overwrite secret_value
    return secret_value;
}

In this case, the value of secret_value has been overwritten to 0xdeadbeef. This could lead to unauthorized access to protected contract functions or incorrect contract behavior.
Scenario:
The attacker manipulates dst so that memory[ids.output] writes to a function's return address.
They replace the return address with the location of their malicious code.
When the function returns, instead of continuing normal execution, it jumps to the malicious code, potentially allowing unauthorized operations like transferring funds from the contract.
