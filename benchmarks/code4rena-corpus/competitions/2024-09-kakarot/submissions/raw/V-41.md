# [Medium] Missing Range Check on base_fee in set_base_fee Allows Setting Unintended Values

### Impact
The set_base_fee function allows the owner to set the base_fee parameter without any range checks to ensure that base_fee is within an acceptable range (e.g., non-negative). This could allow the owner—or an attacker who gains control over the owner’s account—to set base_fee to an excessively large value, disrupting the system’s functionality and affecting gas calculations.

    •    File: Kakarot.Cairo
    •    Line: 123-126

func set_base_fee{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(base_fee: felt) {

}

### Proof of Concept (PoC)
An attacker with ownership privileges could call set_base_fee with a negative or excessively large base_fee:
```Cairo
// Potential malicious call with excessively large base_fee
await kakarot_contract.set_base_fee(2**250)
```
## Recommended Mitigation Steps
### Recommended Mitigation Steps
Add a range check to ensure that base_fee is within acceptable limits.
```Cairo
@external
func set_base_fee{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(base_fee: felt) {
    Ownable.assert_only_owner();
    // set an upper limit
    // assert base_fee <= MAX_BASE_FEE, 'base_fee exceeds maximum limit';
    return Kakarot.set_base_fee(base_fee);
}
```
Define MAX_BASE_FEE as appropriate for the application’s context.
