# Vulnerability details

## Proof of Concept
The fetch_or_create function does not place any restrictions on the size of the code it processes or the amount of gas it consumes. This leaves the function vulnerable to gas exhaustion attacks, where an attacker submits overly complex data that forces the contract to consume excessive gas, preventing other users from interacting with it.

```
func fetch_or_create{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    evm_address: felt
) -> model.Account* {
    ...
    let account = Account.init(
        address=address,
        code_len=bytecode_len,
        code=bytecode,
        ...
    );
    return account;
}
```

Impact: If the function processes excessively large code lengths or bytecode, it could consume more gas than allowed, leading to denial of service. Attackers could use this vulnerability to lock the system, preventing other legitimate transactions from being processed.

PoC:
invoke the fetch_or_create function with a very large code length.
Observe how the function consumes excessive gas, leading to failure in execution.

```
def test_gas_exhaustion():
    oversized_code = create_large_code(MAX_UINT256)
    account = fetch_or_create(malicious_address, oversized_code)
    assert gas_used(account) > gas_limit  # Should have exhausted gas
```



## Recommended Mitigation Steps
Introduce gas usage checks and code length limits within fetch_or_create. Ensure that only code lengths below a certain threshold are accepted and that gas consumption is tracked.

```
func fetch_or_create{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    evm_address: felt
) -> model.Account* {
    require(code_len <= MAX_ALLOWED_CODE_SIZE, "Code size too large");
    ...
}
```
