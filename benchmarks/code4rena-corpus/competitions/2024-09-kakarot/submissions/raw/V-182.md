# Vulnerability details

#### Summary

The `verify_signature_secp256r1()` function from cairo1_helpers.cairo (https://github.com/kkrt-labs/kakarot-ssj/blob/d4a7873d6f071813165ca7c7adb2f029287d14ca/crates/contracts/src/cairo1_helpers.cairo#L206) does not explicitly verify whether the provided `x` and `y` coordinates represent a valid point on the secp256r1 elliptic curve before the syscall. This omission could lead to potential issues if invalid public key coordinates are used during the verification process.

#### Description

In the function `verify_signature_secp256r1()`, the public key is constructed using the `x` and `y` coordinates provided as inputs. However, there is no explicit check to verify that these coordinates form a valid point on the secp256r1 elliptic curve before proceeding with the signature verification, potentially causing the signature verification process to return incorrect results or be vulnerable to specific attack vectors.

This differs from `p256verify.cairo`, where the same process of public key generation and invocation of `is_valid_signature` occurs. However, in `p256verify.cairo`, the `exec()` function first verifies whether the `x` and `y` coordinates form a valid elliptic curve point before passing them into the `secp256_ec_new_syscall()` function. This additional check ensures that only valid points are used in the signature verification process


It is important to emphasize that even though `public_key` handles a potential error scenario, the validation of the `x` and `y` points still takes place before passing it through the syscall, something that `verify_signature_secp256r1()` is not doing as shown below:

```
fn verify_signature_secp256r1(
            self: @TContractState, msg_hash: u256, r: u256, s: u256, x: u256, y: u256
        ) -> bool {
            let maybe_public_key: Option<Secp256r1Point> = Secp256Trait::secp256_ec_new_syscall(
                x, y
            )
                .unwrap_syscall();
            let public_key = match maybe_public_key {
                Option::Some(public_key) => public_key,
                Option::None => { return false; }
            };

            return is_valid_signature(msg_hash, r, s, public_key);
        }

```

This ensures that even in cases where an invalid public key is detected, the process of verifying the `x` and `y` coordinates is completed before returning a result.

#### Recommendation

To mitigate this issue, implement a validation check that ensures the `x` and `y` coordinates form a valid point on the secp256r1 elliptic curve before proceeding with the signature verification. This can be done by adding the same verification used in the `exec()` function shown above.
