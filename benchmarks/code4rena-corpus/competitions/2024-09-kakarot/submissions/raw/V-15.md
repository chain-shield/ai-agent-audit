## Impact
The selfdestruct function within the Account namespace lacks proper access controls. Malicious actors can invoke this function to mark any account for destruction without authorization. This can lead to denial of service, loss of contract functionality, and potential loss of funds associated with the account. The selfdestruct function does not verify the caller’s identity or permissions before marking an account for destruction. Without restricting access to this function, any user can trigger it, adversely affecting the contract’s integrity and availability.

**Proof of Concept (PoC)**
An attacker can invoke the selfdestruct function on any account without restrictions:
```Cairo
// Attacker's code to destruct a target account
let (target_account) = Account.fetch_or_create(evm_address=TARGET_EVM_ADDRESS);
let (destructed_account) = Account.selfdestruct(self=target_account);
```
This code allows any user to fetch an account and call selfdestruct on it, marking it for destruction without any authorization checks.
