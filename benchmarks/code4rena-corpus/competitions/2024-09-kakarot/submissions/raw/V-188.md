# Vulnerability details


## Proof of Concept

Take a look at the `pow` function implementation in the `ExponentiationImpl` trait https://github.com/kkrt-labs/kakarot/blob/b8f5f2a20bd733cc8885c010291885e1df7dc50e/cairo/kakarot-ssj/crates/utils/src/math.cairo#L26-L62:

```rust
impl ExponentiationImpl<
    T,
    +Zero<T>,
    +One<T>,
    +Add<T>,
    +Sub<T>,
    +Mul<T>,
    +Div<T>,
    +BitAnd<T>,
    +PartialEq<T>,
    +Copy<T>,
    +Drop<T>
> of Exponentiation<T> {
    fn pow(self: T, mut exponent: T) -> T {
        let zero = Zero::zero();
        if self.is_zero() {
            return zero;
        }
        let one = One::one();
        let mut result = one;
        let mut base = self;
        let two = one + one;

        loop {
            if exponent & one == one {
                result = result * base;
            }

            exponent = exponent / two;
            if exponent == zero {
                break result;
            }

            base = base * base;
        }
    }
}
```

The function immediately returns zero if the base is zero, without considering the exponent. This leads to an incorrect result for the case of 0^0.

To demonstrate:

If `result = 0_u32.pow(0);`, result would be `1`.

### Coded POC

## Impact

This implementation leads to unexpected behavior and breaks mathematical calculations that rely on this exponentiation function. The case of `0^0` is mathematically undefined, and different systems handle it differently. In many programming languages and mathematical libraries, 0^0 is defined to be 1, which aligns [with certain mathematical conventions](https://cs.uwaterloo.ca/~alopez-o/math-faq/mathtext/node14.html).

The current implementation returning 0 for 0^0 easily breaks algorithms that expect 0^0 to be 1, potentially leading to incorrect results or unexpected program behavior. This is especially problematic in financial or scientific calculations where precision is crucial.

## Recommended Mitigation Steps

Explicitly handle the case of 0^0:

```rust
fn pow(self: T, exponent: T) -> T {
    let zero = Zero::zero();
    let one = One::one();

    if self.is_zero() {
        if exponent.is_zero() {
            return one; // Define 0^0 as 1
        }
        return zero;
    }

    // ... snip
}
```

Alternatively, if you want to emphasise the undefined nature of 0^0, you could return a Result type:

```rust
fn pow(self: T, exponent: T) -> Result<T, PowerError> {
    if self.is_zero() && exponent.is_zero() {
        return Err(PowerError::UndefinedZeroPower);
    }

    // ... snip
}
```
