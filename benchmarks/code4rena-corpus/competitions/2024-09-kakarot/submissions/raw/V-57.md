# Vulnerability details

## Summary

The **Kakarot-ssj** precompiled files perform elliptic curve operations for  **BN254**, using the `is_on_the_curve` function to validate points. However, this function lacks an important check for small subgroups. To enhance security, it is essential to verify that points belong to the main subgroup by ensuring that multiplying a point by the curve's order results in the point at infinity. This validation is vital for cryptographic integrity.


## Vulnerability Details

In **Kakarot-ssj**, the precompiled files handle elliptic curve cryptography operations, particularly for the **BN254**. These operations include `ec_mul` and `ec_add`, which are utilized for elliptic curve multiplication and addition, respectively. Both operations validate whether the supplied parameters (i.e., points on the curve) are indeed on the curve by invoking the function `is_on_the_curve()`. This function returns a boolean value indicating the validity of the given point on the elliptic curve.

The `is_on_the_curve()` function essentially performs two checks:

- It verifies that the provided point lies on the BN254 curve.
- It ensures that the x and y coordinates of the point do not correspond to the point at infinity (0,0).

Also, within the `ec_mul()` and `ec_add()` functions, there's another important check for elliptic curves ensuring that any point with an x or y coordinate greater than the modulus is considered invalid:

```
if x1 >= BN254_PRIME || y1 >= BN254_PRIME {
        return Option::None;
    }

```

However, one important validation is missing to confirm that the point is a valid point on the curve: the check for **small subgroups**. This check involves verifying that any point (or multiple points) used in cryptographic operations belongs to the main subgroup defined by the elliptic curve's order.

It is true that BN254 is a pairing-friendly curve because it has a cofactor of 1 for its prime-order subgroup, but this does not automatically guarantee that subgroup checks can be ignored in all scenarios.

For example, in certain situations where inputs are received from untrusted parties, subgroup checks still offer additional safety since a malicious party supplies points that do not belong to the intended curve or subgroup.


## Impact

Failure to implement the small subgroup check in **Kakarot-ssj** elliptic curve operations undermines the validity of points used in `is_on_curve()` function, affecting the elliptic curve operations. Furthermore, the lack of this check may result in lack of integrity on the input processed by this function dimishing the protocol's cryptographic reliability. 

Also, BN254 curve’s cofactor is small (1 for G₁ and 12 for G₂), making checks efficient. The extra cost of checking whether points belong to the correct subgroup is minimal compared to the potential security risks of not doing so.

## Recommended Mitigation Steps

### Steps to Perform Subgroup Checks

1. For the BN254 curve, a defined group order is represented as **BN254_ORDER** (which is already declared in a constant under `ec_operations.cairo`). This order indicates the total number of points in the main subgroup utilized for cryptographic purposes.

2. Multiply the point \( P = (x,y) \) by the group order. The outcome of this operation should yield the point at infinity. It might be possible to use `ec_mul` or `ec_mul_inner` depending on the implementation. 

3. After performing the multiplication, compare the result to the point at infinity. If the result is the point at infinity, it means that the original point \( (x,y) \) lies within the correct subgroup. Conversely, if it is not the point at infinity, then the point is either invalid or belongs to a small subgroup.

The following snippet, which integrates the subgroup check into the `is_on_curve` function, illustrates this concept. In this example we are reusing the function `ec_mul()` (which is not necessarily mandatory, but it performs the scalar multiplication we require) and declares the variable `POINT_AT_INFINITY`, which is not defined in the provided code but serve to clarify the concept of Infinity in the validations outlined from the steps above:

```rust
pub fn is_on_curve(x: u384, y: u384) -> bool {
    let (b, _x, _y) = (CE::<CI<0>> {}, CE::<CI<1>> {}, CE::<CI<2>> {});

    // Compute (y^2 - (x^3 + b)) % p_bn254
    let x2 = circuit_mul(_x, _x);
    let x3 = circuit_mul(x2, _x);
    let y2 = circuit_mul(_y, _y);
    let rhs = circuit_add(x3, b);
    let check = circuit_sub(y2, rhs);

    let modulus = TryInto::<_, CircuitModulus>::try_into(BN254_PRIME_LIMBS).unwrap(); // BN254 prime field modulus

    // Subgroup check
    let order = BN254_ORDER; // Order of the elliptic curve
    // Perform scalar multiplication of the point (x,y) by the group order
    let point_after_order_mul = ec_mul((x, y), order);
    
    if point_after_order_mul == POINT_AT_INFINITY { 
        // Compare with the point at infinity      
        println!("Point is valid and lies in the correct subgroup"); 
    } else { 
        println!("Invalid point, lies in a small subgroup"); 
        return false; // Point not in the correct subgroup
    }

    let mut circuit_inputs = (check,).new_inputs();
    // Prefill constants:
    circuit_inputs = circuit_inputs.next_2([3, 0, 0, 0]);
    // Fill inputs:
    circuit_inputs = circuit_inputs.next_2(x);
    circuit_inputs = circuit_inputs.next_2(y);

    let outputs = circuit_inputs.done_2().eval(modulus).unwrap();
    let zero_check: u384 = outputs.get_output(check);
    return zero_check.is_zero();
}
```

### Importance of this check

1. **Security Against Small Subgroup Attacks**:
   - Small subgroups may enable attackers to exploit weaknesses in cryptographic protocols. If a point lies within a small subgroup, recovering private keys or forging signatures may become significantly easier. More information on https://www.nccgroup.com/es/research-blog/an-illustrated-guide-to-elliptic-curve-cryptography-validation/

2. **Integrity of Cryptographic Protocols**:
   - Ensuring that only points from the main subgroup are employed in cryptographic operations helps preserve the security given by the mathematical properties of the elliptic curve.

3. **Validation of Inputs**:
   - By implementing this check, the protocol can check that the inputs of the elliptic curve operations are valid, thereby preventing unexpected behaviors or vulnerabilities during cryptographic processes.
