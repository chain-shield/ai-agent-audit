# Vulnerability details

## Description
When invoking Kakarot from L1, we first call the following function: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/solidity_contracts/src/L1L2Messaging/L1KakarotMessaging.sol#L26-L45
notice that the value is not checked as the comment indicates it will be taken from the L2 address. Then the following `l1_handler` function is called: 
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/kakarot.cairo#L370-L385
This will then call `handle_l1_message`: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L421-L438 which has no checks on the gas limit sent, as it is hardcoded to 2100000000.
Then eth_call is invoked: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L78-L120
Which eventually hits this line in the interpreter: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L941-L952
However since in this flow we never called `eth_send_raw_unsigned_tx`, the following fee deduction from the origin account will underflow if the origin account has less than 2100000000 wei. This creates a balance overflow and essentially mints ether to the sender. 
## Recommended Mitigation Steps
Perform the check that the user's balance is greater than the gas limit inside the `handle_l1_message` function.
