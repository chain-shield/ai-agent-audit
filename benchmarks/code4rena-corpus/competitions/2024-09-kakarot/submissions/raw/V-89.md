# Vulnerability details

## Proof of Concept

At the moment `handle_l1_message()` uses incorrect hard-coded values to send the call:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L435-437
```
 return eth_call(
            0, l1_sender, to, 2100000000, 1, value_u256, data_len, data, 0, access_list
        );
```

It has `nonce` parameter that's equal to 0, `gasLimit` == 2100000000 and `gasPrice` == 1:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/library.cairo#L435-437
```
   func eth_call{
        syscall_ptr: felt*,
        pedersen_ptr: HashBuiltin*,
        range_check_ptr,
        bitwise_ptr: BitwiseBuiltin*,
    }(
        nonce: felt,
        origin: felt,
        to: model.Option,
        gas_limit: felt,
        gas_price: felt,
        value: Uint256*,
        data_len: felt,
        data: felt*,
        access_list_len: felt,
        access_list: felt*,
```

Nonce is always increased upon the transaction execution and cannot be equal always to 1 (for an account), gas limit that's set to 21e8 is highly unrealistic and will exceed the block limit of the transaction that's approximately 5e6 for the Starknet and about 30e6 for Ethereum. Gas price is also set to 1 but it has to be calculated using `priority_fee_per_gas + block_base_fee` as for other transactions.

## Recommended Mitigation Steps

Use different values (ideally, not hardcoded and calculated based on the inputs) for the `eth_call()` parameters.
