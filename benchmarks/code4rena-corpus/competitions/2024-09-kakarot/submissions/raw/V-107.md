# Vulnerability details

## Impact
The memory_cost function calculates the gas cost based on the length of memory words (words_len). 
```Cairo
// https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/gas.cairo#L73

        let memory_cost = 512 * q0 * q0 + 2 * q0 * r0 + q1 + (MEMORY * words_len);
```
However, the computation directly above does not impose sufficient constraints on the input words_len. If words_len is provided with a very large value, the calculations can lead to unintended gas cost behaviors.

## Proof of Concept
An malicious user can supply a large words_len value to cause the memory_cost computation to produce incorrect gas costs.

## Recommended Mitigation Steps
To mitigate this issue, impose strict upper bounds on the words_len parameter to ensure it does not exceed a safe limit.

Updated memory_cost Function with Constraints
```Cairo
namespace Gas {
    const MAX_WORDS_LEN = 0x1_0000  # Example maximum limit (adjust as needed)

    func memory_cost{range_check_ptr}(words_len: felt) -> felt {
        # Enforce maximum words_len constraint
        assert words_len <= MAX_WORDS_LEN, "words_len exceeds maximum allowed limit"

        let (q0, r0) = unsigned_div_rem(words_len, 512)
        let (q1, r1) = unsigned_div_rem(r0 * r0, 512)

        # Perform safe arithmetic operations with overflow checks
        let term1 = 512 * q0 * q0
        let term2 = 2 * q0 * r0
        let term3 = q1
        let term4 = MEMORY * words_len

        # Ensure no overflow occurs in any term
        assert term1 >= 0, "Overflow in term1"
        assert term2 >= 0, "Overflow in term2"
        assert term3 >= 0, "Overflow in term3"
        assert term4 >= 0, "Overflow in term4"

        let memory_cost = term1 + term2 + term3 + term4
        return memory_cost
    }
}
```
