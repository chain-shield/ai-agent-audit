# Vulnerability details

# Summary
The load_bytecode function in the kakarot project is underconstrained due to critical computations being performed within hints without sufficient accompanying constraints. This vulnerability allows a malicious prover to manipulate the hint execution to produce incorrect proofs that would still be accepted by the verifier. Specifically, the prover can provide incorrect bytecode while passing all the assertions in the code, potentially leading to execution of malicious or unintended code.
Affected Code

The vulnerability is present in the load_bytecode function defined in the Cairo contract. The critical computations are performed within a hint that is underconstrained.
Code Snippet

```
%{
    memory[ids.output] = res = (int(ids.value) % PRIME) % ids.base
    assert res < ids.bound, f'split_int(): Limb {res} is out of range.'
%}
tempvar a = [output];
%{
    from starkware.cairo.common.math_utils import assert_integer
    assert_integer(ids.a)
    assert 0 <= ids.a % PRIME < range_check_builtin.bound, f'a = {ids.a} is out of range.'
%}
assert a = [range_check_ptr];
```


# Demonstration Using Test Case

To illustrate the vulnerability, consider the following test case where the hint is modified to manipulate the extracted bytes:

```

@given(bytecode=binary(min_size=1, max_size=400))
@settings(max_examples=5)
def test_should_raise_when_read_bytecode_zellic_issue_1279(
    self, cairo_program, cairo_run, bytecode
):  
    modified_hint = (
        "value_mod_prime = int(ids.value) % PRIME\n"
        "if value_mod_prime > ids.base:\n"
        "    res = (value_mod_prime - 1) % ids.base\n"
        "else:\n"
        "    res = value_mod_prime % ids.base\n"
        "memory[ids.output] = res\n"
        "assert res < ids.bound, f'split_int(): Limb {res} is out of range.'"
    )
                        
    with (
        patch_hint(
            cairo_program,
            "memory[ids.output] = res = (int(ids.value) % PRIME) % ids.base\n"
            "assert res < ids.bound, f'split_int(): Limb {res} is out of range.'",
            modified_hint,
        ),
        patch.object(
            SyscallHandler, "mock_storage", side_effect=self.storage(bytecode)
        ),
    ):
        with cairo_error(message="Value is not empty"):
            output_len, output = cairo_run("test__bytecode")
```


# Explanation of the Proof of Concept

* Test Execution:
        The test runs the load_bytecode function with the modified hint.
        It uses patch_hint to replace the original hint with the modified one.
        The bytecode input is generated using Hypothesis, allowing for various bytecode values to be tested.

* Expected Behavior:
        The assertion assert value == 0 should fail when the value is incorrectly updated due to manipulated res values.
        An exception with the message "Value is not empty" should be raised.

* Actual Behavior:
        The test fails because the expected exception is not raised.
        This indicates that the assertion assert value == 0 is passing, even though the res values are manipulated.

# Demonstration of Bypassing the Assertion value = 0

* Manipulating res and value:
        The prover adjusts res through the modified hint.
        By carefully choosing res and updating value, the prover ensures that value becomes zero at the end, passing the assertion.

* Assertion Bypassed:
        The assertion assert value == 0 does not detect the manipulation because the mathematical relationship between value, res, and base is not enforced by constraints.

* Test Output:
        The test fails with the message Failed: DID NOT RAISE <class 'Exception'>, indicating that the assertion did not fail as expected.


    Impact:
        This demonstrates that the assertion can be bypassed while manipulating the data.
        The prover can provide incorrect bytecode without being detected, leading to potential security breaches.

# Recommended Mitigation Steps

To address this vulnerability, the following steps are recommended:

*   Move Critical Computations from Hints to Cairo Code:
    Implement byte extraction and value updates within Cairo code instead of relying on hints.
    Example:

    ```
    // Extract least significant byte
    let res = value % base;
    // Update value for next iteration
    let value = value / base;
    ```
* Enforce Mathematical Relationships with Assertions:
    Add assertions to ensure the correctness of computations.
    Example:
    ```
    // Ensure the extracted byte and updated value are consistent
    assert prev_value == value * base + res;
    ```
