# Vulnerability details

The _commit_account function does not check if the code hash has changed before updating it. This could result in unnecessary updates to the storage and waste gas.

The function directly updates the code hash using IAccount.set_code_hash(starknet_address, [self.code_hash]) without any prior validation.

Exploitation Example:
An attacker or user could repeatedly call the function to update the code hash, even if it hasn’t changed. This would lead to excessive gas consumption, making the contract more expensive to use and creating a potential attack vector for gas griefing.

This could potentially lead to inconsistencies if the code has not been modified but the code hash has changed due to other factors (e.g., recompilation or external influences). If the code hash is updated incorrectly, it could affect the contract's execution and behavior.

To address this potential issue, you could consider adding a check to compare the current code hash with the newly calculated code hash before updating it. This would ensure that the code hash is only updated if the code has actually changed.
