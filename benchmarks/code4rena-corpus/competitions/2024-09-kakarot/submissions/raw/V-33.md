## [M2] Missing Range Checks on tx.gas_limit and tx.max_fee_per_gas

Severity: Medium
Issue Type: Missing Input Validation

Impact: Without upper bounds on tx.gas_limit and tx.max_fee_per_gas, attackers can input excessively large values, leading to overflows in subsequent computations or exceeding protocol-defined limits, potentially causing denial of service or unexpected behavior.

Location: eth_send_raw_unsigned_tx function, before computing max_gas_fee.
```txt
https://github.com/kkrt-labs/kakarot/blob/697100af34444b3931c18596cec56c454caf28ed/src/kakarot/eth_rpc.cairo#L239-L325
```

Description:

The code lacks upper bounds on tx.gas_limit and tx.max_fee_per_gas. While there are some checks (e.g., ensuring tx.gas_limit is less than 2**64 - 1), these may not be sufficient to prevent overflows when these values are multiplied. This omission can lead to the overflow issue described in the previous finding and allows transactions that exceed reasonable gas limits.

Proof of Concept:

An attacker can set tx.gas_limit and tx.max_fee_per_gas to maximum felt values:
```Cairo
// Attacker sets values to maximum felts
let tx.gas_limit = 2**251 - 1;
let tx.max_fee_per_gas = 2**251 - 1;

// Without range checks, these values are accepted and used
```

## Recommended Mitigation Steps
Introduce strict upper bounds on tx.gas_limit and tx.max_fee_per_gas:
```Cairo
// Define maximum acceptable values
const MAX_GAS_LIMIT = 2**64 - 1; // As per protocol limits
const MAX_MAX_FEE_PER_GAS = 2**128 - 1; // Adjust as needed

// Apply range checks
with_attr error_message("tx.gas_limit exceeds maximum allowed") {
    assert_le(tx.gas_limit, MAX_GAS_LIMIT);
}
with_attr error_message("tx.max_fee_per_gas exceeds maximum allowed") {
    assert_le(tx.max_fee_per_gas, MAX_MAX_FEE_PER_GAS);
}
```
