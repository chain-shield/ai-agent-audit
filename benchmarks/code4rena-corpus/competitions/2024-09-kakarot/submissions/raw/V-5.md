# Vulnerability details

## Summary 
The `increment_program_counter` function in the evm.cairo contract lacks range checking, which creates a security risk by allowing malicious users to manipulate input values and force the program counter to jump to unsafe code segments. Adding `{range_check_ptr}` range checking is recommended to safeguard the function's execution.

## Proof of Concept
In the evm.cairo contract, the `increment_program_counter` function is responsible for incrementing the program counter and returning a new instance of `model.EVM`, representing the updated execution state. This involves a computation like `program_counter = self.program_counter + inc_value`, but lacks a range check using `{range_check_ptr}`.

The `{range_check_ptr}` is a pointer used for range checking, ensuring that certain values (typically integers or array indices) remain within valid limits during execution. Without range checking, if the `program_counter` value exceeds its allowable range after adding `inc_value` , it may result in the program jumping to invalid memory addresses, causing undefined behavior or program crashes.

The absence of range checking in this context could make the code vulnerable to attacks. For instance, a malicious user could manipulate input values to cause the program counter to jump to an unsafe code segment, leading to security breaches.
