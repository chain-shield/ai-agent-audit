# Vulnerability details

The function decode_raw recursively decodes RLP data, but lacks a clear termination condition, making it vulnerable to stack overflow. If an attacker provides RLP-encoded data with deeply nested structures, the recursion could run indefinitely until the call stack exceeds its limit, causing a stack overflow.

AFFECTED LINES OF CODES:
            let sub_items_len = decode_raw(items=sub_items, data_len=len, data=data + offset);

The root cause of the vulnerability lies in the lack of a termination condition or depth limit within the recursive decode_raw function. This allows the function to recurse indefinitely, potentially consuming excessive stack resources.

The decode_raw function is designed to decode RLP data by making recursive calls to itself. Specifically:

When the rlp_type is TYPE_LIST, the function recursively decodes the nested list items by calling itself without any explicit depth limit.
After decoding the current data segment, it recursively processes the remaining data, again without depth constraints.

Exploit Scenario:
Scenario 1: Stack Overflow Attack

An attacker submits a maliciously crafted RLP-encoded transaction with deeply nested structures.
The decode_raw function is called recursively without bound, eventually leading to a stack overflow.
As a result, the contract crashes, denying service to legitimate users.
Scenario 2: Resource Exhaustion

By repeatedly invoking the vulnerable function with inputs that trigger deep recursion, an attacker could consume excessive computational resources, slowing down the entire contract execution.

Mitigation:
Recursion Depth Limit: Introduce a depth counter to track the number of recursive calls and enforce a maximum depth limit to prevent unbounded recursion.
