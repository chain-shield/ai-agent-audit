# Vulnerability details

## Proof of Concept

Currently `eth_rpc.cairo` is serves as a place where validation of the transaction happens after which it's sent to the Karakot. The problem is that there is a nonce validation where a nonce of the caller is compared to the nonce of the signer of the transaction resulting in an error if the caller is the relayer address.

Take a look at the `eth_send_transaction()` function implementation:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/eth_rpc.cairo#L203-204
```
 let (local starknet_caller_address) = get_caller_address();
 let (local origin) = Kakarot.safe_get_evm_address(starknet_caller_address);
```

As you can see here, the function assigns the origin to the caller address. However, `origin` signifies the following:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/eth_rpc.cairo#L122
```
The address the transaction is sent from.
```

And as Karakot allows to use paymaster mechanism which means that the Starknet transaction that will lead to the execution of the EVM transaction can be submitted by external relayer. Therefore, it will result to incorrect account being represented as the origin in the case if a user uses sending through relayer option.

## Recommended Mitigation Steps

Set the origin to the contract that actually sent the transaction in the case if paymaster mechanism is used.
