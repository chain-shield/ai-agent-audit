# Vulnerability details

## Summary

In the provided `ec_mul` function, there is no check to ensure that the scalar `s` is valid within the context of elliptic curve operations. The function only checks whether `s = 0` or `s = 1`, but no check is done to ensure `s` is smaller than the group order of the BN254 curve.

## Vulnerability details

Exceeding the group order in elliptic curve cryptography occurs when a scalar s used in scalar multiplication is greater than or equal to the curve’s group order. 

The group order n is the number of points in the elliptic curve’s main subgroup, which includes all the points used in secure cryptographic operations. The group is cyclic, meaning that after multiplying any point P by the group order n, the result is the point at infinity.

What Happens If the Scalar Exceeds the Group Order?

If the scalar s is larger than the group order, the multiplication will essentially "wrap around." This is because as we implied, the elliptic curve behaves in a cyclic way. It means that the result of multiplying a point by s is the same as multiplying it by s mod n (i.e., the remainder when s is divided by n).

## Impact

Exceeding the group order increases vulnerability to small subgroup attacks. Also, invalid outputs, such as the point at infinity, can disrupt application logic, potentially resulting in Denial of Service (DoS) scenarios. Furthermore, failure to handle such issues can dimish protocol's trust since they do not implement strict checks on their crypto functions, in this case on scalar values to ensure they remain within the safe bounds defined by the group order.

## Recommendations

To prevent potential security issues, you should add a check to ensure that the scalar s is within the range 0≤ s < BN254_ORDER. This can be done with a simple comparison before proceeding with the scalar multiplication:

```
fn ec_mul(x1: u256, y1: u256, s: u256) -> Option<(u256, u256)> {
    if x1 >= BN254_PRIME || y1 >= BN254_PRIME {
        return Option::None;
    }
    if x1 == 0 && y1 == 0 {
        // Input point is at infinity, return it
        return Option::Some((x1, y1));
    } 
    
    // Check if scalar s is within the valid range
    if s >= BN254_ORDER {
        // Scalar is invalid (greater than or equal to the group order)
        println!("Invalid scalar: exceeds the group order");
        return Option::None;
    }
    // Remaining code
```
