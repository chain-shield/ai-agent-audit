# Vulnerability details

## Proof of Concept
The contract does not validate evm_address in critical functions like deploy_externally_owned_account, register_account, and write_account_bytecode. An invalid or zero address could lead to incorrect account deployments or unauthorized modifications.

```
@external
func deploy_externally_owned_account{
    syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr
}(evm_address: felt) -> (starknet_contract_address: felt) {
    Pausable.assert_not_paused();
    return Kakarot.deploy_externally_owned_account(evm_address);
}
```

If a malicious or invalid evm_address is passed, an incorrect StarkNet account could be deployed or registered, potentially leading to loss of assets or account hijacking.

Impact:

Invalid account deployments or registration could result in loss of funds or control over user accounts.



## Recommended Mitigation Steps
Validate the evm_address to ensure it is non-zero and follows the correct address format:
```
@external
func deploy_externally_owned_account{
    syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr
}(evm_address: felt) -> (starknet_contract_address: felt) {
    Pausable.assert_not_paused();
    assert evm_address != 0; // Add validation here
    return Kakarot.deploy_externally_owned_account(evm_address);
}
```
