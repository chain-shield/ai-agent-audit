# Vulnerability details

### **Summary**  
The `transfer_ownership()` function facilitates the transfer of ownership for the Kakarot protocol. This function relies on the `Ownable.transfer_ownership()` implementation from the OpenZeppelin library, which directly assigns a new owner in a single step. However, the version 0.6.1 of the OpenZeppelin contracts, utilized in Kakarot, lacks support for a two-step ownership transfer mechanism. This one-step transfer process introduces potential issues.  

### **Vulnerability Details**  
The contract does not implement a two-step ownership transfer, which limits the ability to properly validate the new owner's address. While the basic check ensuring the new address is not the zero address is absent, the more critical issue arises when ownership is transferred to an **inaccessible or incorrect address**, rendering the system misconfigured or inoperable.  

### **Vulnerable Scenario**  
- The current owner of Kakarot calls `transfer_ownership()`.  
- An incorrect or invalid address is provided as the new owner.  
- As a result, ownership is irreversibly assigned to the wrong address, causing a permanent misconfiguration of the protocol.  

### **Recommendation**  
To mitigate this risk, implement a **two-step ownership transfer process**. In this approach:  
1. The current owner proposes the new owner's address.  
2. The proposed new owner must explicitly accept the role by calling a function to finalize the transfer.  

This ensures proper validation, reduces the risk of misconfiguration, and enhances the security of the ownership transfer process.
