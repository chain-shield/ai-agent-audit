# Vulnerability details


## Proof of Concept

NB: This bug case affects both the implementations of `ec_add.cairo` & `ec_mul.cairo`, however this report would only focus on the former which is `ec_add.cairo`.

Now [EIP-196](https://eips.ethereum.org/EIPS/eip-196) is the EIP that defines the ECADD/ECMUL precompiles, and it explicitly states that both precompiles **"Fails on invalid input and consumes all gas provided."**, quote on quote:

> ADD
> Input: two curve points (x, y). Output: curve point x + y, where + is point addition on the elliptic curve alt_bn128 specified above. Fails on invalid input and consumes all gas provided.

> MUL
> Input: curve point and scalar (x, s). Output: curve point s _ x, where _ is the scalar multiplication on the elliptic curve alt_bn128 specified above. Fails on invalid input and consumes all gas.

This implementation however is not followed by Kakarot.

Note that using a similar context as an example, we can see how zkSync implemented their ECADD, where we have the call burn all of the gas when invalid inputs are passed, see [zksync/precompiles/EcAdd.yul#L1-L440](https://github.com/code-423n4/2023-10-zksync/blob/1fb4649b612fac7b4ee613df6f6b7d921ddd6b0d/code/system-contracts/contracts/precompiles/EcAdd.yul#L1-L440) most especially [EcAdd.yul#L53-L60](https://github.com/code-423n4/2023-10-zksync/blob/1fb4649b612fac7b4ee613df6f6b7d921ddd6b0d/code/system-contracts/contracts/precompiles/EcAdd.yul#L53-L60)

To pass a call to the precompile and execute we need to call https://github.com/kkrt-labs/kakarot-ssj/blob/d4a7873d6f071813165ca7c7adb2f029287d14ca/crates/contracts/src/cairo1_helpers.cairo#L131-L149:

```cairo
        fn exec_precompile(
            self: @TContractState, address: felt252, data: Span<u8>
        ) -> (bool, u64, Span<u8>) {
            let result = match address {
                0 => Result::Err(EVMError::NotImplemented),
                1 => Result::Err(EVMError::NotImplemented),
                2 => Sha256::exec(data),
                3 | 4 => Result::Err(EVMError::NotImplemented),
                5 => Result::Err(EVMError::NotImplemented),
                6 => EcAdd::exec(data),
                7 => EcMul::exec(data),
                _ => Result::Err(EVMError::NotImplemented),
            };
            match result {
                Result::Ok((gas, output)) => (true, gas, output),//@audit gas is only returned if the transaction is successful which should not be the case.
                Result::Err(_) => (false, 0, [].span())
            }
        }
```

However in Kakarot's case this is not done, going to the implementation of ecadd.cairo, in the case where an invalid input is passed, the query just stops and the `None` option gets returned, not using up all the gas, for eg see https://github.com/kkrt-labs/kakarot-ssj/blob/d4a7873d6f071813165ca7c7adb2f029287d14ca/crates/evm/src/precompiles/ec_operations/ec_add.cairo#L28-L63:

As hinted by the `@audit` tags, if invalid parameters are passed, the execution gracefully returns an error and only when the datas are valid do we get to the flow of `return Result::Ok((gas, result_bytes.span()));`, however regardless of the data being valid or not the `BASE_COST` should still be charged.

As hinted earlier this is the same case with `ec_mul#exec()` see [ec_mul.cairo#L54-L87](https://github.com/kkrt-labs/kakarot-ssj/blob/d4a7873d6f071813165ca7c7adb2f029287d14ca/crates/evm/src/precompiles/ec_operations/ec_mul.cairo#L54-L87)

## Impact

ECADD/ECMUL deviates from EIP 196 and is not equivalent to the Ethereum VM. Since in the case the tx to call the precompile fails the gas cost is [assumed to be zero](https://github.com/kkrt-labs/kakarot-ssj/blob/d4a7873d6f071813165ca7c7adb2f029287d14ca/crates/contracts/src/cairo1_helpers.cairo#L142-L149) whereas it should still be paid in full.

## Recommended Mitigation Steps

Burn all the gas even if there is an invalid entry to align with the native EVM implementation.
