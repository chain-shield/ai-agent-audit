# Vulnerability details

Vulnerability Details
The code lacks explicit access control mechanisms, allowing any function, such as write_storage, to be invoked by arbitrary users. For example, in the write_storage function:
func write_storage{
    syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr, state: model.State*
}(evm_address: felt, key: Uint256*, value: Uint256*) {
    // No access control
    let account = get_account(evm_address);
    let account = Account.write_storage(account, key, value);
    update_account(account);
}
This function allows users to write to any account's storage without restrictions. Without proper checks, malicious actors could call this function and modify the storage or state of arbitrary accounts, leading to unauthorized data manipulation and potential theft of funds.

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/state.cairo#L304-L312

Potential Impact:
An attacker could exploit this vulnerability to overwrite critical data in any account's storage, effectively gaining control over user accounts or altering contract behavior. This could lead to unauthorized fund transfers, data corruption, and a complete compromise of the contract's integrity. For instance, if an attacker calls write_storage with parameters targeting a victim's account, they could potentially drain funds or change contract logic to their advantage.

Recommended Mitigation Steps
Introduce role-based access control using techniques such as:
Multi-signature wallets: Require multiple approvals for critical actions to prevent unauthorized access.
Owner validation: Implement checks to ensure that only designated users or the contract owner can invoke sensitive functions like write_storage.
Admin checks: Utilize an admin role to manage permissions for functions that modify the contract state, ensuring that only authorized personnel can make changes to critical data.
