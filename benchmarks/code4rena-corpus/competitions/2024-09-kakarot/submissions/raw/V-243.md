# Vulnerability details



## Impact
Any contract can bypass signature validation by directly calling `eth_send_raw_unsigned_tx`, allowing unauthorized execution of EVM transactions. This breaks the fundamental security model where transactions must be signed by the account owner.

The allows:
- Execution of transactions without valid signatures
- Impersonation of any EVM address as long as nonce matches

## Proof of Concept
`eth_send_raw_unsigned_tx` in Kakarot's main contract lacks validation that the caller is a registered account contract.

The function is marked as `@external` and performs basic transaction validations but misses account contract verification:

```cairo

    let tx = EthTransaction.decode(tx_data_len, tx_data);
```

The intended secure flow is:
1. User signs transaction with their private key
2. Transaction is submitted to Account Contract 
3. Account Contract verifies signature
```cairo
let (address) = Account_evm_address.read();
	Signature.verify_eth_signature_uint256(
		msg_hash=msg_hash,
		r=r,
		s=s,
		v=y_parity,
		eth_address=address,
		helpers_class=helpers_class,
	);
```

4. If valid, Account Contract calls `eth_send_raw_unsigned_tx`
```cairo
 // Send tx to Kakarot
        let (return_data_len, return_data, success, gas_used) = IKakarot.eth_send_raw_unsigned_tx(
            contract_address=kakarot_address, tx_data_len=tx_data_len, tx_data=tx_data
        );
```
[accounts/library.cairo:L217](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/accounts/library.cairo#L217)

However, due to missing caller validation, an attacker can:
- Deploy a malicious contract (on Starknet)
- Read target account's current nonce 
- Directly call `eth_send_raw_unsigned_tx` with a crafted transaction:
   - Set `msg.sender` as target account
   - Match the target's nonce
   - Include arbitrary calldata

The transaction will execute successfully since only the nonce is validated, completely bypassing signature verification.

Manual Review

## Recommended Mitigation Steps

Ensure`eth_send_raw_unsigned_tx` can only be called through the proper Account Contract flow where signatures are verified.
