# Vulnerability details

## Proof of Concept

The graph of the memory_cost function is not similar to EVM's implementation, and even has a jump. Calculating the memory_cost for expanding memory can overflow.

Here is the memory_cost function:

```
func memory_cost{range_check_ptr}(words_len: felt) -> felt {
    let (q0, r0) = unsigned_div_rem(words_len, 512);
    let (q1, r1) = unsigned_div_rem(r0 * r0, 512);

    let memory_cost = 512 * q0 * q0 + 2 * q0 * r0 + q1 + (MEMORY * words_len);
    return memory_cost;
}
```

Here is the graph of the function(memory_cost against words_len) in Kakarot:

![Kakarot_memory_cost](https://github.com/user-attachments/assets/42d2aa64-94a4-48fd-8889-67719b177f5b)


In comparison, here is EVM's implementation:

![Geth_memory_cost](https://github.com/user-attachments/assets/ced9624b-5b3f-46a2-b6c3-0496422a70d1)

From the graph, we can see that the curve is not strictly increasing(and is not continuous), therefore, memory_cost of words_len x can be greater than memory_cost of words_len x+y.

An overflow can happen in the `calculate_gas_extend_memory` function:

```
    func calculate_gas_extend_memory{range_check_ptr}(
        words_len: felt, max_offset: felt
    ) -> model.MemoryExpansion {
        ...
        let prev_cost = memory_cost(words_len);
        let (new_words_len, _) = unsigned_div_rem(max_offset + 31, 32);
        let new_cost = memory_cost(new_words_len);

++++    let expansion_cost = new_cost - prev_cost;
        ...
    }
```

For example:
memory_cost for words_len of 500.6=3459
memory_cost for words_len of 566.6=2453.5

calculating the cost for expanding from 500.6 to 566.6 will overflow

In comparison with EVM implementation:
memory_cost for words_len of 500.3=1989.9
memory_cost for words_len of 566.6=2327


## Recommendation

Modify the memory_cost function, ensuring that the curve is strictly increasing, and does not contain jumps
