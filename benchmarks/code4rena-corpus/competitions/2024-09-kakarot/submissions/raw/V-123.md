# Vulnerability details

In `kakarot evm`, the `exec_create` instruction generates the `CREATE` and `CREATE2` operations.
The standard EIP `CREATE2` instruction is designed to allow redeployment to a deleted address (an address that has undergone `selfdestruct`).
However, in `kakarot evm`, redeployment using `CREATE2` is not possible in the `exec_create` instruction.

In the `exec_create` function, the `target address` is calculated, and then the `has_code_or_nonce` function checks whether the `target address account` has any collision.

The `has_code_or_nonce` function is defined as follows:
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/account.cairo#L582-L587

```
func has_code_or_nonce(self: model.Account*) -> felt {
    if (self.nonce + self.code_len != 0) {
        return TRUE;
    }
    return FALSE;
}

```
If the `nonce` and `code_len` of the account are 0, it returns `TRUE`, otherwise, it returns `FALSE`.
An account that has undergone `selfdestruct` will still return `TRUE` because its `nonce` is not reset to 0, even though `code_len` is 0.

```
    let is_collision = Account.has_code_or_nonce(target_account);
    if (is_collision != 0) {
```

When `TRUE` is returned, the execution enters the conditional `if (is_collision != 0)`, and the `evm return` is executed, halting the operation.

As a result, redeployment through `CREATE2` is impossible even if desired.

## Recommended Mitigation Steps
Modify the collision check for `CREATE` and `CREATE2` to be different.
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/instructions/system_operations.cairo#L136-L142
