# Vulnerability details

## Proof of Concept
Reentrancy occurs when a contract calls an external contract, and the external contract makes a recursive call back into the original contract before the first invocation is finished. This can lead to the original contract's state being manipulated multiple times in an unsafe manner.
Functions like callCairo and delegatecallCairo make external contract calls without protecting against reentrancy, which can lead to exploitation if the external contract reenters the original contract.

Severe Impact: Reentrancy attacks have been used in high-profile hacks (e.g., the DAO hack). If the library is used to handle important assets or cross-chain messaging, an attacker could drain funds or disrupt operations.

## Recommended Mitigation Steps
Consider using reentrancy guards (like nonReentrant from OpenZeppelin) if the contract's state could be affected by reentrant calls.

an example of a mitigation:
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract MyContract is ReentrancyGuard {
    function sensitiveFunction() external nonReentrant {
        // your logic
    }
}
