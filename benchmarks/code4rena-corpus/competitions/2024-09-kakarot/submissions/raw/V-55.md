# Vulnerability details

In the exec_balance function, a 256-bit value (address_uint256) is popped from the stack and converted to a 160-bit Ethereum address. However, the function does not perform any checks to ensure that the higher-order bits (161 to 256) of the 256-bit address are zero, as required for valid Ethereum addresses (which are 160-bit).
The function assumes that the input (address_uint256) is always a valid Ethereum address, without verifying that the higher-order bits are zero. If the input contains non-zero values in those higher-order bits, the conversion will truncate those bits, potentially creating an incorrect or unintended address.


Reproduction Example:
An attacker could pass a value like 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00000000000000000000000000000001 as address_uint256. After truncating it to 160 bits, the address would be 0x0000000000000000000000000000000000000001, leading the function to interact with this unintended address.




Impact:
Unexpected Address Interaction: Without validation, the function could interact with unintended addresses, potentially leading to incorrect account balances being fetched or manipulated.


Recommendation:
Add a validation step to check whether the upper 96 bits of address_uint256 are zero before converting it to a 160-bit address.
