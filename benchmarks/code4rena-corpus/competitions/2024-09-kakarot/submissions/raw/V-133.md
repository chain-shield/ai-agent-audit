# Vulnerability details

Proof of Concept
Scenario 1: External Call Fails Silently
In the function execute_starknet_call, an external contract call is made via the provided address (to). The function includes a success return value, but this return value is not checked to ensure the external call was successful. Without proper validation, if the call fails, the contract continues execution, potentially leading to an incorrect or inconsistent state.
Code Example:
func execute_starknet_call(
    to: felt,
    function_selector: felt,
    calldata_len: felt,
    calldata: felt*
) -> (retdata_len: felt, retdata: felt*, success: felt) {
The function does not check whether success == 1 after the external call is made. If success == 0 (indicating a failure), the contract logic will proceed as if the call succeeded, which can lead to unexpected behavior.

Proof of Impact:
If the external call fails but this is not handled, the state changes that depend on the success of the call could be incorrect. This could also allow external entities to exploit the failure by continuing actions that depend on the success of the call, leading to the possibility of draining contract funds, incorrect state transitions, or other unintended consequences.

Scenario 2: Reentrancy Attack
In the exec_precompile function, an external contract is invoked with the possibility of passing arbitrary data (data_len, data). If the external contract is malicious, it can trigger a reentrancy attack by calling back into the original contract before the original function finishes execution. Since there are no reentrancy guards in place, this could allow the attacker to exploit the contract by draining funds or manipulating state.
Code Example:

func exec_precompile(
    address: felt,
    data_len: felt,
    data: felt*
) -> (success: felt, gas: felt, return_data_len: felt, return_data: felt*) {
Here, success is returned but not validated. If the external contract re-enters before the original function completes, it could cause the contract to behave incorrectly, leading to a reentrancy attack.

Proof of Impact:
Without reentrancy protection, an external contract could exploit the lack of validation and reenter the original contract during execution. This could result in the attacker executing actions multiple times within the same transaction context, potentially draining funds or causing other financial damage.

Recommended Mitigation Steps
Check External Call Results:
After making external calls in both execute_starknet_call and exec_precompile, always check if the success flag is set before proceeding with further operations.
Mitigation Example:
if success == 0:
    return (0, [], 0)  # Handle failure case, revert or stop execution
By ensuring the success flag is validated, you can prevent the contract from continuing if the external call fails, ensuring that state changes only happen if the external call was successful.
Implement Reentrancy Guards:

Introduce a reentrancy guard mechanism to prevent reentrant calls during external function execution.
Mitigation Example:
let is_locked = 0
if is_locked == 1:
    revert()  # Prevent reentrancy
is_locked = 1  # Set guard before external call
Using a reentrancy guard ensures that the contract cannot be reentered until the original function finishes execution, mitigating the risk of reentrancy attacks.

Improve Error Handling:
In both functions, implement proper error-handling mechanisms to revert or halt execution if the external call fails. This includes reverting the transaction if the success flag is not set, ensuring the state is not modified in case of failure.
Mitigation Example:
if success == 0:
    revert("External call failed")
