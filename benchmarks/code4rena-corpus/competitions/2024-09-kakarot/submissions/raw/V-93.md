# Vulnerability details

The Cairo precompile eventually calls `execute_starknet_call()` in the account contract associated with the calling L2 smart contract. This function has a reentrancy check that prevents callers from re-entering the Kakarot smart contract. It is however possible to call `execute_from_outside()` in any account contract. A malicious Starknet contract called via precompile can leverage this to replay any L2 transactions that invoke it. For example, a transaction that transfers native tokens could be replayed multiple times.

The attack is mitigated by the fact that Cairo precompile callers must be whitelisted. 

## Proof of Concept
Since the impact of this attack is limited and the execution rather complex I am providing a sketch of the attack rather than a full proof-of-concept.

1. The attacker observes the incoming transaction in the mempool (possibly they control a sequencer). They store the entire transaction data including the signature in the malicious Starknet contract.
2. Once the Starknet transaction is included and the attacker's precompile is executed, the attacker the precompile calls into the malicious Cairo contract which re-submits the previously stored transaction via the `execute_from_outside` function in the sender's account contract. Note that the execution will still see the previous nonce since the outer execution context has not yet committed the updated nonce to storage.
4. Repeat the process multiple times as required.
5. All nested transactions should run successfully and the nonce (increased by 1) is committed to the sender account.

## Recommended Mitigation Steps

Add a check to `execute_starknet_call()` in `account_contract.cairo` that prevents the selector for `execute_from_outside()` from being called.
