Severity: High
Type: Missing Input Validation / Range Checks
Location:
- pop: Lines 86-95
- pop_n: Lines 70-81
- peek: Lines 102-112
- swap_i: Lines 118-133
- Internals._read_n: Lines 121-137

The functions pop, pop_n, peek, swap_i, and Internals._read_n lack necessary range checks to ensure that stack indices and sizes are within valid bounds. This omission can lead to stack underflow, negative indices, and out-of-bounds memory access, potentially causing memory corruption or unexpected behavior.

In pop, if stack.size is 0, subtracting 1 results in -1, an invalid index.
In pop_n, there’s no check to ensure n <= stack.size.
In peek, if stack_index >= stack.size, it results in a negative index.
In swap_i, if i >= stack.size, it accesses invalid memory.
In Internals._read_n, recursive calls decrement index without ensuring it’s non-negative.

Security Risk: 
Unchecked operations can lead to memory corruption, crashes, or unintended behaviour.

Functional Discrepancy: 
Deviates from expected EVM behaviour, which throws exceptions on stack underflows.

*Proof of Concept*
```Cairo
MAX_VALUE = P/2;
MIN_VALUE = 0;
pop(MAX_VALUE+1);
pop(MIN_VALUE-1);
```
## Recommended Mitigation Steps
Add range checks in all stack manipulation functions.
```Cairo
assert (element> 0);
assert (stack_index > 0);
```
