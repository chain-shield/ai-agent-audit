# Vulnerability details


## Impact
`handle_l1_message` fail to execute. However, the ETH of the user has been deducted from l1, resulting in a loss of user funds.

## Proof of Concept

`handle_l1_message` When an evm transaction is executed, the sender is a contract on l1. If the sender's address does not have a corresponding starkware account, the corresponding account will be deployed.

The problem is that when the account is deployed, the initialize method is not called, so the account's native token is not authorized to the core contract (kakarot_address):

