# Vulnerability details

Vulnerability Details:
The store and store_n functions in the Memory namespace accept parameters for element and offset, but lack any validation on the offset value. This omission can lead to serious vulnerabilities, including:

Out-of-Bounds Memory Access:
If the offset is manipulated, it can cause the contract to write to unintended memory locations, leading to data corruption or unexpected behaviors.

Possible Overflow or Underflow Conditions:
The calculations for offset_in_chunk using unsigned_div_rem(offset, 16) can result in overflow or underflow if the offset is not properly constrained.

Risk of Exploitation:
Malicious actors can exploit this vulnerability to manipulate the offset, enabling them to store data outside intended bounds, leading to corruption, unintended behavior, or other security vulnerabilities.

Code References:
Direct Links to Affected Functions:

store function:
func store{range_check_ptr, memory: model.Memory*}(element: Uint256, offset: felt) {
    let word_dict = memory.word_dict;

    // Check alignment of offset to 16B chunks.
    let (chunk_index, offset_in_chunk) = unsigned_div_rem(offset, 16);
    // No validation on offset value
}

Proof of Concept:
Direct Impact:
If a malicious actor provides a very large offset value (e.g., 2^256 - 1), it could lead to an attempt to write to a memory location that is not allocated, corrupting data or causing the contract to behave unpredictably.

Example Call:
Memory.store_n(128, [0x1234, 0x5678], 2^256 - 1); // Invalid offset

Illustration of Potential Impact:
Memory Corruption: If the offset points to a location beyond allocated memory, the written data could overwrite critical state variables or other important data.
Contract State Manipulation: An attacker could manipulate contract state by writing to unintended memory locations, leading to unauthorized access or manipulation of contract functions.

Recommended Mitigation Steps:
Input Validation:
Implement bounds checking for the offset to ensure it is within a safe range before any memory operations are performed. This could be done using a require statement:
require(offset >= 0 && offset + element_len <= max_memory_size, "Invalid memory offset");

Range Checking:
Ensure that the offset and the element_len do not exceed the allocated memory space. This helps to prevent overflows and ensures safe memory access.

Error Handling:
Provide clear error messages when invalid offsets are detected, which aids in debugging and provides feedback for contract interactions.
