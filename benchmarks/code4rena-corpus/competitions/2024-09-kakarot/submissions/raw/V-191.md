# Vulnerability details

## Description
When a precompile is called, gas is not charged immediately and instead is only charged if the call to the precompile is successful: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L94-L100 However instead of reverting with no returndata if there is not enough gas, `EVM.stop` is invoked which updates the returndata to the value given by the precompile. Because this is an exceptional revert it will be caught and the returndata will be set to 0 if invoked from any contract however if an EOA invokes a precompile (i.e the context is root) then the returndata will still be returned: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L762-L779
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L1039
This directly violates the EVM specification since precompiles that go out of gas do not have any returndata
## Recommended Mitigation Steps
It might be better to charge gas directly in the precompile like how geth does instead of at the end of execution, or just ensure that `EXEPTIONAL_REVERT`s in the root ctx have no returndata
