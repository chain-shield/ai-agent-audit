# Vulnerability details

## Description
If a create tx fails in the root context (for reasons like nonce overflow or more practically the balance being sent is more than allowed) then geth refunds all gas: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/vm/evm.go#L442-L444
(Notice the entire gas is set to `st.GasRemaining`: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/state_transition.go#L454-L461 which is then refunded in `refundGas`: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/state_transition.go#L491-L518)
However Kakarot will consider this an `EXCEPTIONAL_HALT` and thus set the gas_left and gas_refund to 0: 
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L983-L992
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L762-L779
As a result the user who incorrectly submitted such a tx will lose any refunds, this also does not conform to the specification as well. 
## Recommended Mitigation Steps
Do not consider nonce overflows or transferring more than is allowed an exceptional revert, or alternatively just refund the gas for these specific cases before reverting.
