# Vulnerability details

## Proof of Concept
The function compute_starknet_address in the Account namespace uses the input evm_address to compute a Starknet address without validating the input. If an attacker provides a malformed or malicious evm_address, it could lead to incorrect Starknet addresses, which might be used for malicious purposes or cause the system to misbehave.

```
func compute_starknet_address{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    evm_address: felt
) -> felt {
    ...
    let (hash_state_ptr) = hash_update_single{hash_ptr=pedersen_ptr}(
        hash_state_ptr=hash_state_ptr, item=evm_address
    );
    ...
}
```

Impact: This vulnerability could allow an attacker to bypass expected account computation mechanisms and create non-standard or incorrect addresses, leading to transaction failures or unauthorized contract deployment.

(PoC):
```
def test_invalid_evm_address():
    invalid_address = -1  # Invalid input for evm_address
    result = compute_starknet_address(invalid_address)
    assert result == 0  # Expected failure for invalid input

```

## Recommended Mitigation Steps
Add input validation for the evm_address to ensure it is within the valid address range.
```
if evm_address < MIN_ADDRESS or evm_address > MAX_ADDRESS {
    // Handle error
}
```
