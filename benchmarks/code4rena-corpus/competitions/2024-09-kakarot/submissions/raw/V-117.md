# Vulnerability details

## Proof of Concept
In `Interpreter::execute` namespace, the function incorrectly increments the nonce for failed transactions and leaves it unchanged for successful ones. This is the reverse of what is intended.


https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L1019-L1026

```cairo
with state {
    let sender = State.get_account(env.origin);
    uint256_add([sender.balance], paid_fee_u256);
    let (ap_val) = get_ap();
    let sender = Account.set_balance(sender, cast(ap_val - 3, Uint256*));
@>  let sender = Account.set_nonce(sender, sender.nonce + is_reverted);
    State.update_account(sender);
}
```

This line is intended to revert the nonce increment if the transaction fails. But, the logic is incorrect:

1. `is_reverted` is set to 1 if the transaction reverts, and 0 if it succeeds.
2. The current logic increments the nonce by 1 if the transaction reverts, and doesn't change it if the transaction succeeds.

This is the opposite of what should happen. The nonce should be incremented for successful transactions and remain unchanged for reverted transactions.

## Impact
As a result, successful transactions can be replayed because their nonce isn't incremented, leading to double-spending.
Also, after a failed transaction, the account's nonce is incorrectly incremented stopping any further valid transactions from that account until the nonce issue is manually resolved.

## Recommended Mitigation Steps
Consider reversing the nonce increment logic. to make sure that for successful transactions (`is_reverted = 0`), the nonce is incremented by 1 and for failed transactions (`is_reverted = 1`), the nonce remains unchanged.

```diff
- let sender = Account.set_nonce(sender, sender.nonce + is_reverted);
+ let sender = Account.set_nonce(sender, sender.nonce + (1 - is_reverted));
```
