# Vulnerability details

## Proof of Concept

`starknet.cairo` does not fully remove the bytecode of a contract when `selfdestruct` is called. This is evident in the `_commit_account` function:

[LINK:](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/backend/starknet.cairo#L191-L200)

```cairo
let is_created_selfdestructed = self.created * self.selfdestruct;
if (is_created_selfdestructed != 0) {
    let starknet_address = Account.compute_starknet_address(Constants.BURN_ADDRESS);
    tempvar burn_address = new model.Address(
        starknet=starknet_address, evm=Constants.BURN_ADDRESS
    );
    let transfer = model.Transfer(self.address, burn_address, [self.balance]);
    State.add_transfer(transfer);
    return ();
}
```
Here, the contract only treats the case where an account is created and immediately self-destructed. It transfers the balance to a burn address but does not remove the `bytecode`.

For existing accounts that call `selfdestruct`, the [bytecode remains unchanged](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/backend/starknet.cairo#L214-L221):


```cairo
if (self.created != FALSE) {
    IAccount.write_bytecode(starknet_address, self.code_len, self.code);
    Internals._save_valid_jumpdests(
        starknet_address, self.valid_jumpdests_start, self.valid_jumpdests
    );
    IAccount.set_code_hash(starknet_address, [self.code_hash]);
    return ();
}
```

This code only updates bytecode for newly created accounts, not for existing ones that might have called `selfdestruct`.

As a result, the bytecode of self-destructed contracts remains accessible allowing users to interact with what they believe to be a valid contract instance. This could be exploited ands used for phishing purposes too.


## Further Reading
https://eips.ethereum.org/EIPS/eip-6780#specification

## Recommended Mitigation Steps

Consider implementing a way to remove or nullify the bytecode when `selfdestruct` is called on an existing account. Maybe by setting the bytecode length to zero and clearing the code hash.
Contracts created and self-destructed in the same transaction, all data (including bytecode and storage) is properly deleted
 Also risks for using `selfDestruct` should be acknowledged.
