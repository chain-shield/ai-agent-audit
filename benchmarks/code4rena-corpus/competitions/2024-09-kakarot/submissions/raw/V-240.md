# Vulnerability details



## Impact
When executing the SDIV opcode, Kakarot performs both division and modulo calculations internally, even though only the division result is needed. While the gas cost (GAS.LOW = 5) correctly matches Ethereum's specification, the implementation is computationally inefficient as it performs ~2x more computation than necessary. This results in:

- Computational overhead for every SDIV operation
- Reduced throughput for transactions using SDIV operations (Since Cairo steps are increased due to additional unnecessary logic)

*Note: the same applies for SMOD and other opcode that uses `uint256_unsigned_div_rem` function*

## Proof of Concept

SDIV => `uint256_signed_div_rem` => `uint256_unsigned_div_rem`

Step-by-step explanation:

- When a contract has SDIV:
	```solidity
	int256 result = a / b;  // SDIV opcode
	```

- Kakarot processes this by:
  - Loading operands `a` and `b`
  - Calling `uint256_signed_div_rem(a, b)`
  - Computing full signed division algorithm
  - Computing full modulo algorithm
  - Discarding modulo result
  - Returning only quotient
  - Charges correct gas (GAS.LOW)

- The modulo computation is completely unused but still performed for every SDIV operation.

This can be demonstrated with a simple contract:

```solidity
contract SDIVHeavy {
    function performManyDivisions() public pure returns (int256) {
        int256 a = type(int256).max;
        int256 b = 7;
        
        // Each SDIV performs unnecessary modulo calculation
        for(uint i = 0; i < 1000; i++) {
            a = a / b;  // SDIV opcode
        }
        return a;
    }
}
```

When this contract runs on Kakarot:
- Each SDIV operation performs both division and modulo calculations
- ~50% of the computation time is spent on calculating modulo results that are discarded
- Gas charged remains correct per spec, but execution takes more Cairo steps which has a cost for the paymaster.

## Recommended Mitigation Steps
Create a function that only computes the quotient for SDIV operations, avoiding the unnecessary modulo calculation.
