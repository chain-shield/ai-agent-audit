# Vulnerability details

## Proof of Concept
Multiple critical functions, such as upgrade, transfer_ownership, pause, unpause, and set_native_token, are missing protection against reentrancy attacks. These functions change the contract state without any checks to prevent recursive calls during their execution.

```

@external
func upgrade{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    new_class_hash: felt
) {
    Ownable.assert_only_owner();
    replace_class(new_class_hash);
    kakarot_upgraded.emit(new_class_hash);
    return ();
}
```

```

@external
func transfer_ownership{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    new_owner: felt
) {
    Ownable.transfer_ownership(new_owner);
    return ();
}
```

An attacker could exploit these functions by calling them recursively before the state changes are finalized. For example, an attacker could repeatedly replace the class in upgrade, or transfer ownership multiple times in quick succession, leading to unintended contract states or control loss.

Impact:

Repeated upgrades or ownership transfers could result in a contract being in an inconsistent or vulnerable state.
Loss of administrative control due to repeated ownership transfers.


## Recommended Mitigation Steps
Implement a reentrancy guard to prevent multiple calls during the same transaction. Here’s an example with a simple lock mechanism:

```
let lock = 0; // Initial state
@external
func upgrade{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    new_class_hash: felt
) {
    if (lock != 0) {
        return (); // Reentrancy protection
    }
    lock = 1;
    Ownable.assert_only_owner();
    replace_class(new_class_hash);
    kakarot_upgraded.emit(new_class_hash);
    lock = 0;
    return ();
}
```
