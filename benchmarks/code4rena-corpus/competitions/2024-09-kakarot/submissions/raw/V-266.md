# Vulnerability details

## Proof of Concept
In a recursive function, each call allocates a new frame on the stack. When keys_list_len is large, the recursive call depth will become very large, resulting in a stack overflow error.
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/utils/eth_transaction.cairo#L313-L329
```cairo
    func parse_storage_keys{range_check_ptr}(
        parsed_keys: felt*, keys_list_len: felt, keys_list: RLP.Item*
    ) {
        alloc_locals;
        if (keys_list_len == 0) {
            return ();
        }

        let key = Helpers.bytes32_to_uint256(keys_list.data);
        assert [parsed_keys] = key.low;
        assert [parsed_keys + 1] = key.high;

        parse_storage_keys(
            parsed_keys + Uint256.SIZE, keys_list_len - 1, keys_list + RLP.Item.SIZE
        );
        return ();
    }
```


## Recommended Mitigation Steps
Converting the original recursive parse_storage_keys function to an iterative form can effectively avoid stack overflow and other potential problems.
```cairo
func parse_storage_keys{range_check_ptr}(
    parsed_keys: felt*, keys_list_len: felt, keys_list: RLP.Item*
) {
    alloc_locals;
    let mut i = 0;
    while (i < keys_list_len) {
        let key = Helpers.bytes32_to_uint256(keys_list[i].data);

        assert [parsed_keys + (i * 2)] = key.low;  
        assert [parsed_keys + (i * 2 + 1)] = key.high;  

        i += 1;
    }
    return ();
}
```
