# Vulnerability details

## Description
Ethereum clients will first buy gas after checking some conditions: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/state_transition.go#L379-L393
Then if the transaction is a contract creation transaction, they will proceed to check the init code length is not greater than the maximum size allowed by the Shanghai hardfork: 
https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/state_transition.go#L432-L435
However the Kakarot interpreter will error out first if the init code length exceeds the max specified before buying gas: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L941-L961
This deviates from the EVM specification and it means that create transactions will not be charged any gas
## Recommended Mitigation Steps
Charge gas in the same order geth does
