# Vulnerability details

In the `L1KakarotMessaging.sol` contract there is a `sendMessageToL2()` function, which sends a message to a contract on L2. This function must be called with a value sufficient to pay for the L1 message fee. Then that value is used to call `starknetMessaging.sendMessageToL2()`:

```solidity
        // Send the converted data to L2
        starknetMessaging.sendMessageToL2{value: msg.value}(kakarotAddress, HANDLE_L1_MESSAGE_SELECTOR, convertedData);
```

In the `StarknetMessaging.sol` contract, the ether sent with the `sendMessageToL2()` function is neither utilized nor returned to the sender, resulting in a permanent lock of ether within the contract:

```solidity
    function sendMessageToL2(
        uint256 toAddress,
        uint256 selector,
        uint256[] calldata payload
    ) external payable override returns (bytes32, uint256) {
        require(msg.value > 0, "L1_MSG_FEE_MUST_BE_GREATER_THAN_0");
        require(msg.value <= getMaxL1MsgFee(), "MAX_L1_MSG_FEE_EXCEEDED");
        uint256 nonce = l1ToL2MessageNonce();
        NamedStorage.setUintValue(L1L2_MESSAGE_NONCE_TAG, nonce + 1);
        emit LogMessageToL2(msg.sender, toAddress, selector, payload, nonce, msg.value);
        bytes32 msgHash = getL1ToL2MsgHash(toAddress, selector, payload, nonce);
        // Note that the inclusion of the unique nonce in the message hash implies that
        // l1ToL2Messages()[msgHash] was not accessed before.
        l1ToL2Messages()[msgHash] = msg.value + 1;
        return (msgHash, nonce);
    }
```

Additionally, there is no mechanism to refund ether when the message is canceled, leading to potential loss of funds.

## Impact

The `sendMessageToL2()` function requires users to send `msg.value` as a fee for relaying messages from L1 to L2. However, the contract does not utilize the ether in any way, nor does it include a refund mechanism for unused or canceled messages. This leads to scenarios where the sent ether remains locked in the contract and if a message is canceled: `cancelL1ToL2Message()`, the ether sent with the message remains locked in the contract without any refund mechanism.

## Proof of Concept

Calling the `sendMessageToL2()` function e.g. with 1 `wei`:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/solidity_contracts/src/L1L2Messaging/L1KakarotMessaging.sol#L32-L45

```solidity
    function sendMessageToL2(address to, uint248 value, bytes calldata data) external payable {
        uint256 totalLength = data.length + 4;
        uint256[] memory convertedData = new uint256[](totalLength);
        convertedData[0] = uint256(uint160(AddressAliasHelper.applyL1ToL2Alias(msg.sender)));
        convertedData[1] = uint256(uint160(to));
        convertedData[2] = uint256(value);
        convertedData[3] = data.length;
        for (uint256 i = 4; i < totalLength; ++i) {
            convertedData[i] = uint256(uint8(data[i - 4]));
        }

        // Send the converted data to L2
        starknetMessaging.sendMessageToL2{value: msg.value}(kakarotAddress, HANDLE_L1_MESSAGE_SELECTOR, convertedData);
    }
```

so the `StarknetMessaging.sol` contract will have that 1 wei and a mapping with:

```solidity
l1ToL2Messages()[msgHash] = msg.value + 1;
```

The mapping is for then be used and that fees to be transferred to the e.g. Kakarot, but the functionality to use that value is missing. 

## Recommended Mitigation Steps

Ensure that the `msg.value` being sent covers the required message fee. If `msg.value` is not enough, the transaction should revert. Introduce logic that uses `msg.value` to pay for gas fees or operations on L2. Implement a mechanism to refund unused ether when a message is canceled or if the message fee is overpaid.
