# [Medium] Missing Length Validation in write_account_bytecode Could Lead to Storage Corruption

### Impact
The write_account_bytecode function accepts bytecode_len and bytecode as parameters but does not validate that bytecode_len corresponds to the actual length of bytecode provided. This could lead to underflow or overflow when writing the bytecode to storage, potentially causing storage corruption or unintended behavior in account execution.

### Location

    •    Function: write_account_bytecode
    •    File: Kakarot.Cairo

func write_account_bytecode{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    evm_address: felt, bytecode_len: felt, bytecode: felt*

### Proof of Concept (PoC)
An attacker could call write_account_bytecode with a mismatched bytecode_len:
```Cairo
// Provide incorrect bytecode_len
await kakarot_contract.write_account_bytecode(evm_address, 1000, actual_bytecode)
```
If actual_bytecode is shorter than bytecode_len, this could cause reading uninitialized memory or writing garbage data to storage.
## Recommended Mitigation Steps
Add a check to ensure that bytecode_len matches the actual length of bytecode. Alternatively, compute bytecode_len from bytecode:
```Cairo
func write_account_bytecode{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    evm_address: felt, bytecode_len: felt, bytecode: felt*
) {
    Ownable.assert_only_owner();
    let actual_len = bytecode.end - bytecode.start;
    assert bytecode_len == actual_len, 'bytecode_len does not match actual bytecode length';
    return Kakarot.write_account_bytecode(evm_address, bytecode_len, bytecode);
}
```
