# Vulnerability details

## Description
Description: When calculating the refunds for `SSTORE`, there is an underflow in the following code: 
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/instructions/memory_operations.cairo#L364-L379
The computation of `gas_refund` can underflow in the following scenario:
 current_value = 0, new_value != 0, original_value !=0, new_value = original value.
This will cause the `gas_refund` value to be equal to `-5000`, which means if the current `evm.gas_refund` is lower than 5000, the addition will underflow.

Then in `Interpreter.execute` the gas refund is computed: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L1007-L1015,
However the following `is_nn` check is bypassed because the gas refund is definitely larger than the max range check bound of 2**128: https://github.com/starkware-libs/cairo-lang/blob/a86e92bfde9c171c0856d7b46580c66e004922f3/src/starkware/cairo/common/math_cmp.cairo#L15-L18
Thus `is_max_refund_le_gas_refund` will return 0 and `gas_refund` will  be set to `evm.gas_refund`. This will cause the `total_gas_used` variable to underflow as well, and thus when `State.add_transfer` is called it will return `success = 0` due to the balance check: 
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/state.cairo#L380-L385
However this means that no gas will be deducted from the user's balance and thus a user can perform calls for free. 

## Recommended Mitigation Steps
 The following line should probably be (1 - is_current_zero) * is_new_zero + is_current_zero instead
(1 - is_current_zero) * is_new_zero - is_current_zero

Under/Overflow
