# Vulnerability details

The decode_raw function from the RLP namespace fail to properly halt execution or revert the contract state when an error is encountered, specifically when the RLP data is shorter than the declared length. Instead, the error is logged using with_attr error_message, but execution continues, which could lead to data inconsistencies or further unintended consequences.

AFFECTED CODE:
 "with_attr error_message("RLP data too short for declared length")"

The vulnerability arises from the lack of state reversion or proper termination when the data length mismatch is detected. The with_attr error_message logs the issue but allows the function to continue processing. This can result in further function calls working on invalid data, causing downstream logic to malfunction.

This issue can lead to incorrect RLP decoding, which might result in contract state inconsistencies or other more severe vulnerabilities.
mpact:
Incorrect Decoding: If an RLP data length mismatch occurs, the function proceeds without halting, potentially resulting in invalidly decoded data being passed to other functions.


To effectively halt or revert the execution when an error occurs, you should use the assert_eq or assert_not_eq instructions instead of relying solely on the error_message attribute. These instructions will cause the Cairo VM to halt and revert the transaction if the specified condition is not met.
