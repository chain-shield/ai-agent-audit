## [M] Missing Range Checks on call_array.data_offset and calldata in execute_from_outside

	•	Severity: Medium
	•	Issue Type: Missing range checks
	•	Location: Lines 96-149

## Impact: 
An attacker can cause the contract to read or write memory out of bounds, potentially leading to arbitrary code execution or data corruption.
```Cairo
let packed_tx_data_len = [call_array].data_len;
assert_not_zero(packed_tx_data_len);
assert [range_check_ptr] = packed_tx_data_len;
let range_check_ptr = range_check_ptr + 1;

let packed_tx_data = calldata + [call_array].data_offset;
let tx_data_len = [packed_tx_data];
assert [range_check_ptr] = tx_data_len;
let range_check_ptr = range_check_ptr + 1;
```

## Description: 
In the execute_from_outside function, packed_tx_data is calculated by adding [call_array].data_offset to calldata. There is no check to ensure that [call_array].data_offset is within the bounds of calldata_len. This omission can lead to reading memory outside of the allocated calldata array, potentially causing undefined behavior or security vulnerabilities.

## Proof of Concept (PoC):
An attacker can craft a call_array with a data_offset that exceeds calldata_len, causing packed_tx_data to point to memory beyond calldata. This can result in arbitrary memory read or write operations.
## Recommended Mitigation Steps
Add range checks to ensure that [call_array].data_offset does not exceed calldata_len.
```Cairo
with_attr error_message("Execute from outside: data_offset out of range") {
    assert_le([call_array].data_offset + packed_tx_data_len, calldata_len);
}
```
