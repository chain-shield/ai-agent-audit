# Vulnerability details

## Summary
The `eth_send_raw_unsigned_tx` and `execute_from_outside` function in the Cairo contract is vulnerable due to improper verification of the `caller_address` using the `get_caller_address()` function. According to the Cairo documentation, when a contract is called directly (rather than through another contract), `get_caller_address()` returns `0`. This can lead to transactions being executed without proper authorization or verification, creating a significant security risk. The issue is also present in other audited and non-audited contracts. To address this, it is recommended to refactor the logic into an internal function and ensure that an external function(with `@external` ) calls it, preventing unauthorized execution and verification failure.

## Proof of Concept
The function `eth_send_raw_unsigned_tx` in the `eth_rpc.cairo` contract is responsible for processing unsigned transaction data. However, there is a potential security issue arising from the use of the `get_caller_address()` function. According to the official [Cairo documentation](https://docs.cairo-lang.org/hello_starknet/user_auth.html#), when a contract is called directly (without an intermediary contract), `get_caller_address()` returns `0`. This could lead to serious security risks if the transaction is executed without proper verification.

In `eth_send_raw_unsigned_tx`, the `caller_address` is used to retrieve the nonce of the account and validate the transaction. If `caller_address` returns `0`, this could allow transactions to be executed without proper verification, which may lead to unauthorized transactions. This could allow bypassing of certain permission checks or cause failed authentication, as many contracts assume the caller address is non-zero. If the caller verification fails due to the zero address, subsequent validation might not be properly executed.

            assert tx.chain_id.value = chain_id;

    let (caller_address) = get_caller_address();

        assert tx.signer_nonce = account_nonce;
    }

    // Validate gas
    with_attr error_message("Gas limit too high") {
        assert [range_check_ptr] = tx.gas_limit;
        let range_check_ptr = range_check_ptr + 1;
        assert_le(tx.gas_limit, 2 ** 64 - 1);
    }

    }

    let (block_gas_limit) = Kakarot.get_block_gas_limit();

        assert_nn(tx.max_fee_per_gas - block_base_fee);
    }

        assert [range_check_ptr] = tx.max_priority_fee_per_gas;

    assert carry = 0;
    let (is_balance_enough) = uint256_le(tx_cost, balance);

        assert is_balance_enough = TRUE;

    let priority_fee_is_max_priority_fee = is_nn(
        possible_priority_fee - tx.max_priority_fee_per_gas
    );

        data=tx.payload,

        access_list=tx.access_list,

The issue is found not only in the audited contracts but also in unaudited ones like `Counter.cairo` and `EVM.cairo`, which may also be vulnerable to similar problems.

## Recommended Mitigation Steps
To mitigate this issue, it is recommended to refactor the logic of `eth_send_raw_unsigned_tx` into an internal function that handles the core logic. Then, introduce an external function (decorated with the `@external` modifier) that calls this internal function. This approach ensures that the `get_caller_address()` correctly retrieves the address of the caller, preventing unauthorized access or manipulation by ensuring proper validation of the caller.

This approach should also be considered for other contracts where `get_caller_address()` is used, ensuring that all external calls are properly handled and validated.
