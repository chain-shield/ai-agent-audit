# Vulnerability details

## Description
Geth will charge 1/64th of the current gas before executing the `create` function here: https://github.com/ethereum/go-ethereum/blob/65e5ca7d8126f7a8c708f8affb64f16c22cc63c0/core/vm/instructions.go#L676-L678
This function will return an error if the nonce overflows, if the stack depth is greater than the max allowed limit, or if the balance is incorrect: 
https://github.com/ethereum/go-ethereum/blob/f8f5609b8eced8421110a9193bbd6cefee40b4af/core/vm/evm.go#L430-L449
However the associated kakarot function does not deduct the 1/64th of gas from the caller until after this check is done: https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/instructions/system_operations.cairo#L134-L139
This means that in the event that the call reverts, excess gas is given back to the user when it shouldn't be. In addition, this is a divergence from appropriate EVM behavior.
## Recommended Mitigation Steps
Ensure that the 1/64th gas is deducted before the corresponding checks so that it is not refunded back to the user in the event that contract creation fails.
