# Vulnerability details

## Proof of Concept

At the moment `execute_starknet_call()` functionality is used to perform a starknet call and it's used when executing a cairo precompile. The problem is that the result of the call has to be checked to be either 0 or 1 but it's not done in the current implementation always returning TRUE:

https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/accounts/account_contract.cairo#L333#L347-348
```
let (retdata_len, retdata) = call_contract(to, function_selector, calldata_len, calldata);
return (retdata_len, retdata, TRUE);

```

As you can see here, first it uses `call_contract()` that performs the actual call and in the next line `retdata_len, retdata, TRUE` are returned. `TRUE` corresponds to the `success` from the parameters for this function meaning the call is always set to SUCCESS not actually checking the success of the call.

## Recommended Mitigation Steps

Set the call success status depending on the result of the call.
