# Vulnerability details

In the Kakarot EVM, there are two types of transactions:
1. Transactions that deploy an EVM address.
2. All other transactions.

Among these, in case of sending a transaction of type 2, if the transaction is a simple one that sends `value` to a `to` address, rather than containing Kakarot EVM instruction bytecode that increments the `nonce`, the `nonce` of the `evm.address account` of the `sender` does not increase.

## Proof of Concept
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L948-L974

```
    with state {
        let sender = State.get_account(env.origin);
        let (local new_balance) = uint256_sub([sender.balance], max_fee_u256);
        let sender = Account.set_balance(sender, &new_balance);
        // Check that the sender nonce cannot overflow MAX_64
        if (sender.nonce == 2 ** 64 - 1) {
            let (revert_reason_len, revert_reason) = Errors.nonceIsMax();
            let evm = EVM.stop(evm, revert_reason_len, revert_reason, Errors.EXCEPTIONAL_HALT);
            State.finalize();
            return (evm, stack, memory, state, 0, 0);
        }
        let sender = Account.set_nonce(sender, sender.nonce + 1);
        State.update_account(sender);

        let transfer = model.Transfer(sender.address, address, [value]);
        let success = State.add_transfer(transfer);

        // Check collision
        let account = State.get_account(address.evm);
        let code_or_nonce = Account.has_code_or_nonce(account);
        let is_collision = code_or_nonce * is_deploy_tx;
        // Nonce is set to 1 in case of deploy_tx and account is marked as created
        let nonce = account.nonce * (1 - is_deploy_tx) + is_deploy_tx;
        let account = Account.set_nonce(account, nonce);
        let account = Account.set_created(account, is_deploy_tx);
        State.update_account(account);
    }
```

The above code is part of the `interpreter.execute` function. The flow of the function is roughly as follows:
1. It increments the `nonce` of the `sender`.
2. It transfers `value` to the `address` (which is `address.evm`).
3. It checks if the `address.evm` has already been deployed using `Account.has_code_or_nonce`.
4. Depending on whether it is a `deploy transaction` (`is_deploy_tx`), the `nonce` is calculated as `nonce = account.nonce * (1 - is_deploy_tx) + is_deploy_tx`, and the `nonce` and `created` flag of the `address.evm account` are set.

The key part to focus on here is the `nonce` calculation.
If `is_deploy_tx = 1`, the result of the `nonce` calculation is as follows:
`account.nonce * (1 - 1) + 1 = 1`
Thus, in the case of a deploy transaction, the `nonce` of the deployed `address.evm account` is set to 1.

If `is_deploy_tx = 0`, the result of the `nonce` calculation is as follows:
`account.nonce * (1 - 0) + 0 = account.nonce`
In the case of a non-deploy transaction, the `nonce` of the `address.evm account` is not incremented and remains the same.

However, after this part of the code in the `interpreter.execute` function, there is no code that increments the `nonce` of the `address.evm account`.

In conclusion, while the `nonce` of `env.origin (sender)` increases, the `nonce` of `address.evm` does not.

## Recommended Mitigation Steps
https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/src/kakarot/interpreter.cairo#L970-L973
Modify the nonce calculation as follows:

```
        // let nonce = account.nonce * (1 - is_deploy_tx) + is_deploy_tx;
        let nonce = account.nonce * (1 - is_deploy_tx) + 1; // fixed
        let account = Account.set_nonce(account, nonce);
        let account = Account.set_created(account, is_deploy_tx);
        State.update_account(account);
```

By modifying the code as shown, when `is_deploy_tx = 1`, the `account nonce` is set to 1, and when `is_deploy_tx = 0`, the `account.nonce + 1` is calculated to increment the `nonce`.
