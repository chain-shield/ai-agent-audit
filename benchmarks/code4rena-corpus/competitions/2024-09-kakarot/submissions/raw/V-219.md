# Vulnerability details

## Title
Execution gas price is fixed.
## Links to affected code
https://github.com/kkrt-labs/kakarot/blob/b8f5f2a20bd733cc8885c010291885e1df7dc50e/cairo_zero/kakarot/library.cairo#L436
## Impact 
The geth implementation has `TxData .gas()` field to put different gas values for a transaction here:
https://github.com/ethereum/go-ethereum/blob/24c5493becc5f39df501d2b02989801471abdafa/core/types/transaction.go#L81 

But the kakarot implementation is providing the fixed amount of gas which is 2100000000 in the function `library::handle_l1_message()`. By providing a fix amount of gas the execution will fail if the sudden spike in the gas price and the value provided is too low or if the calldata is larger then user can't set the gas price for execution.

There is no way to set the gas value for transaction execution.
## Proof of Concept
If we look at the function [library::handle_l1_message()](https://github.com/kkrt-labs/kakarot/blob/b8f5f2a20bd733cc8885c010291885e1df7dc50e/cairo_zero/kakarot/library.cairo#L436) we can see it passes 2100000000 wei for the `eth_call()` function as execution gas cost.
