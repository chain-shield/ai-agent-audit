## bytes Cairo has DoS through infinite loops

### Impact

The functions `felt_to_ascii`, `felt_to_bytes_little`, and `bytes_to_bytes8_little_endian` contain loops that can iterate a large number of times based on input values. A hacker can manipulate this by pasting large input values, that force high gas consumption.

### Location

- **`felt_to_ascii`**: Loop starting at label `body:`.
- **`felt_to_bytes_little`**: Loop starting at label `body:`.
- **`bytes_to_bytes8_little_endian`**: Loop starting at label `body:`.

### Proof of Concept (PoC)

A hacker calls `felt_to_bytes_little` with a very large `value`:

```cairo
let large_value = 2 ** 248 - 1;  // Maximum allowed value
let bytes_len = felt_to_bytes_little(dst, large_value);
```

This causes the loop to run many times. Using up a lot of gas.
## Recommended Mitigation Steps
Use input validation to limit the size of input values and avoid big incremental traversals. Apply reasonable maximum values for inputs. Use a maximum incremental count for loops.

### Code Fix

```cairo
const MAX_ITERATIONS = 32;

func felt_to_bytes_little{range_check_ptr}(dst: felt*, value: felt) -> felt {
    alloc_locals;
    with_attr error_message("Input value too large") {
        assert_le_felt(value, 2 ** 248 - 1);
    }

    tempvar range_check_ptr = range_check_ptr;
    tempvar value = value;
    tempvar bytes_len = 0;
    tempvar iterations = 0;

    body:
    with_attr error_message("Exceeded maximum iterations") {
        assert_le_felt(iterations, MAX_ITERATIONS);
    }
    // Existing loop code...
    tempvar iterations = iterations + 1;
    jmp body if value != 0;

}
```
