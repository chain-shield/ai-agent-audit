# [Medium] Missing Range Check on gas_limit_ in set_block_gas_limit Allows Setting Unintended Values

### Impact
The set_block_gas_limit function allows the owner to set the gas_limit_ parameter without any range checks to ensure that it is within an acceptable range (e.g., positive and not exceeding the maximum block gas limit). This could allow the owner—or an attacker who gains control over the owner’s account—to set gas_limit_ to zero or an excessively large value, potentially disrupting network operations and affecting transaction processing.

### Location
    •    Function: set_block_gas_limit
    •    File: Kakarot.Cairo

func set_block_gas_limit{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(

### Proof of Concept (PoC)
An attacker could set gas_limit_ to an unintended value:
```Cairo
// Setting gas_limit_ to zero
await kakarot_contract.set_block_gas_limit(0)

// Setting gas_limit_ to an excessively large value
await kakarot_contract.set_block_gas_limit(2**250)
```
## Recommended Mitigation Steps
Add range checks to ensure that gas_limit_ is positive and within acceptable limits:
```Cairo
@external
func set_block_gas_limit{syscall_ptr: felt*, pedersen_ptr: HashBuiltin*, range_check_ptr}(
    gas_limit_: felt
) {
    Ownable.assert_only_owner();
    assert (gas_limit_ > 0, 'gas_limit_ must be positive');
    // Optionally, set an upper limit
    // assert (gas_limit_ <= MAX_BLOCK_GAS_LIMIT, 'gas_limit_ exceeds maximum limit');
    return Kakarot.set_block_gas_limit(gas_limit_);
}
```
Define MAX_BLOCK_GAS_LIMIT as appropriate.
