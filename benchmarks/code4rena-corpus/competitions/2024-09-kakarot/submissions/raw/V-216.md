# Vulnerability details

## Title
Cross-chain `sendMessageToL2` using bridge might fail due to not checking the `msg.value` passed by the users.

## Vulnerability Details
EVM contracts send messages from L1 to L2 using a bridge. However, it is not guaranteed that the message will be processed by the sequencer. For instance, a message can fail to be processed if there is a sudden spike in the gas price and the value provided is too low.

If we look at [L1L2Messaging::sendMessageToL2](https://github.com/kkrt-labs/kakarot/blob/7411a5520e8a00be6f5243a50c160e66ad285563/solidity_contracts/src/L1L2Messaging/L1KakarotMessaging.sol#L32C14-L32C29) the function doesn't verify whether user has provided enough gas to cover bridge fees to complete the transaction.

If an L1 message is never processed by the sequencer, users will never receive their deposits in either L1 or L2, and they need a way to cancel the message.

## Impact
If the `msg.value` is not properly checked and estimated, users may lose their funds due to unprocessed `sendMessageToL2()`. This can lead to significant financial losses and a lack of trust in the system. Additionally, the inability to retrieve or cancel the message can result in funds being locked indefinitely, causing further inconvenience and potential financial damage to users.

Reference: https://github.com/crytic/building-secure-contracts/tree/master/not-so-smart-contracts/cairo/l1_to_l2_message_failure
## Tools Used
Manual Review

## Recommendation
When sending a message from L1 to L2, it is essential to consider the possibility that a message may never be processed by the sequencer. This can block either the contract from reaching a certain state or users from retrieving their funds. If needed, allow the use of `startL1ToL2MessageCancellation()` and `cancelL1ToL2Message()` to cancel ongoing messages.
