# Vulnerability details

## Proof of Concept
Shift Overflow Risk: The shift operations in most_significant_bit and least_significant_bit assume that x will be non-zero. However, as the bit shifts reduce x, repeated shifts may lead to unwanted behavior, especially if U256 changes or other data types are used.

Proof of Concept:
let mut x = U256::from(1);
x.shr_assign(256); // Shifting beyond 255 bits could yield unexpected results or panic.

Impact: In contexts where U256 could represent values larger than 255 bits, excessive shifts may cause unexpected results or runtime panics

## Recommended Mitigation Steps
Check if x is non-zero and within bounds before each shift operation, or rewrite the logic using a loop that adjusts the shift amount based on x dynamically.
Example Fix:
if x.is_zero() || x < uint!(0x100_U256) {
    return Ok(r);
}
