# Vulnerability details

## Impact

Users can't fully withdraw their position's liquidity, as some funds will be stuck inside the contract.

## Proof of Concept

`decr_position_09293696` function was removed entirely. The only way for users to withdraw funds is by calling [`update_position_C_7_F_1_F_740`](https://github.com/code-423n4/2024-10-superposition/blob/7ad51104a8514d46e5c3d756264564426f2927fe/pkg/seawater/src/lib.rs#L749) with negative delta.

The issue is that delta highly depends on the current price of assets. Delta is calculated in this way:

```rust
        let sqrt_ratio_x_96 = self.sqrt_price.get();
        let sqrt_ratio_a_x_96 = tick_math::get_sqrt_ratio_at_tick(position.lower.get().sys())?;
        let sqrt_ratio_b_x_96 = tick_math::get_sqrt_ratio_at_tick(position.upper.get().sys())?;

        let delta = sqrt_price_math::get_liquidity_for_amounts(
            sqrt_ratio_x_96,   // cur_tick
            sqrt_ratio_a_x_96, // lower_tick
            sqrt_ratio_b_x_96, // upper_tick
            amount_0,          // amount_0
            amount_1,          // amount_1
        )
        .to_i128()
        .ok_or(Error::LiquidityAmountTooWide)?;

        // [update_position] should also ensure that we don't do this on a pool that's not currently
        // running

        self.update_position(id, delta) 
```

So users have to guess the delta based on the current price to withdraw their funds. This will lead to either a revert when the delta is too high, or some funds locked in inside the contract when the delta is too low.

## Recommended mitigation steps

Users should be able to ask for a specific amount of tokens to withdraw instead of providing a delta for the full liquidity.
