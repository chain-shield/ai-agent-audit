# Vulnerability details

## Impact
`getApproved` throws instead of returning the zero address when a token is not approved, breaking EIP721 compatibility.

## Proof of Concept

`getApproved` checks the approved address instead of the owner:

```solidity
    function getApproved(uint256 _tokenId) external view returns (address) {
        address approved = getApproved_[_tokenId];
        require(approved != address(0), "not existing"); //@audit-issue should check owner, not approved
        return approved;
    }
```

But it should check that instead:
https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/ERC721.sol#L115

## Recommended Mitigation Steps

Consider the following change:

```diff
    function getApproved(uint256 _tokenId) external view returns (address) {
        address approved = getApproved_[_tokenId];
-       require(approved != address(0), "not existing");
+       require(ownerOf(_tokenId) != address(0), "not existing");
        return approved;
    }
```
