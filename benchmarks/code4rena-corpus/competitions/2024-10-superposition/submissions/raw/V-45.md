# Vulnerability details

## Finding description and impact
The add_delta function in liquidity_math.rs doesn’t handle the edge case of y = -2^127 (0x8000 0000 0000 0000 0000 0000 0000 0000) resulting in panic which is not desirable. All gas allocated to the transaction is consumed in the process leading to loss of funds to the liquidity providers. 

Mathematically, the code is unsafe.


Refer to the code between Line #7 and #10 in pkg/seawater/src/maths/liquidity_math.rs
```
pub fn add_delta(x: u128, y: i128) -> Result<u128, Error> {
    if y < 0 {
        let z = x.overflowing_sub(-y as u128);
```
Case A: causes panic with y = (-2^127)

Here y is of type i128 and thus the minimum value it can hold is (-2^127). This value is thereafter used in the computation of z, using it as (-y as u128). Even though -y as u128 appears to be comfortable (as (-(-2^127)) = +2^127 can be represented in u128), it is not really so. When this value of y(-2^127) is used , the program will PANIC showing erratic behaviour after that.

So, when y = -2^127 (0x8000 0000 0000 0000 0000 0000 0000 0000)
-y evaluates to -2^127 itself (instead of expected +2^127 because +2^127 can not be represented by type i128.

y = 	0x8000 0000 0000 0000 0000 0000 0000 0000
then
-y = 2’s complement of y 
      = 2’s complement of 0x8000 0000 0000 0000 0000 0000 0000 0000
      = 0x8000 0000 0000 0000 0000 0000 0000 0000
Note that in this case both y  and  -y have the same representation.
This causes panic, which will occur before using the output (-y) as u128. 

Normally, 0x8000 0000 0000 0000 0000 0000 0000 0000 when considered as a number of u128 type, is a valid +2^127 number. So, no error would have been expected by developers when using (-y as u128). 
This function is mainly used to get the updated liquidity by adding delta/ liquidity_delta to the existing liquidity and is being called from 
ticks.rs 	StorageTicks.update,  
pool.rs   	StoragePool.update_position and swap
position.rs   	update

Valid only for the case when y = -2^127  (0x8000 0000 0000 0000 0000 0000 0000 0000).
