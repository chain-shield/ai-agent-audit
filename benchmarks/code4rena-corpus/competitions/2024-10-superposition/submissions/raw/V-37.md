# Vulnerability details

## Proof of Concept
Improper Error Handling with unwrap() Usage: The use of unwrap() can lead to panics if the value is None or an error is encountered unexpectedly. This is dangerous in production environments, where panics could lead to application crashes.

Impact: A panic could halt the execution of a transaction, leaving the system in an inconsistent state or exposing it to DoS.
Proof of Concept: In this example, unwrap() is used in a test scenario without error handling:
let amount_remaining_less_fee = mul_div(amount_remaining, 1e6 - fee_pips, 1e6).unwrap();

If mul_div returns None (e.g., due to an overflow), the unwrap() will cause a panic.
## Recommended Mitigation Steps
Instead of unwrap(), propagate errors using ? and handle them appropriately, ensuring graceful degradation.
Example Fix:
let amount_remaining_less_fee = mul_div(amount_remaining, 1e6 - fee_pips, 1e6)
    .ok_or(Error::CalculationError)?;
