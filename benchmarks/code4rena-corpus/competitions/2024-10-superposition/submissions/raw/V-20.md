# Vulnerability details

## Impact
Disabling a pool won't have any effects, as users can still add and remove liquidity.

## Proof of Concept
The previous issue wasn't fixed properly:
https://github.com/code-423n4/2024-08-superposition-findings/issues/31

With the current code, users can add liquidity even if the pool is disabled, but they should be able only to remove liquidity when the pool is not enabled:
https://github.com/code-423n4/2024-10-superposition/blob/main/pkg/seawater/src/pool.rs#L86

They can do so by calling:
`incr_position_E_2437399 > adjust_position_internal > adjust_position > update_position`

as none of these functions will revert if the pool is disabled.


## Recommended Mitigation Steps
Consider reimplementing the previous check, but only when the delta is positive:

```diff
    pub fn update_position(&mut self, id: U256, delta: i128) -> Result<(I256, I256), Revert> {
+       if delta > 0 {
+           assert_or!(self.enabled.get(), Error::PoolDisabled);
+       }
        let position = self.positions.positions.get(id);
        let lower = position.lower.get().sys();
        let upper = position.upper.get().sys();

```
