# Vulnerability details

## Proof of Concept
Non-Constant Time Execution (Timing Attack): The functions most_significant_bit and least_significant_bit have variable execution times based on the position of the MSB or LSB. This could be exploitable in scenarios where timing information could be leveraged, such as cryptographic contexts.

Proof of Concept: In a cryptographic setting, variable timing based on bit position might expose sensitive information.
let sensitive_value = U256::from(1) << 200; // Significant delay compared to smaller numbers.
let _ = most_significant_bit(sensitive_value);

Impact: An attacker could exploit timing differences to infer sensitive data, especially if the function is used in cryptographic code.
## Recommended Mitigation Steps
Use a constant-time algorithm that examines all bits regardless of their value. This could involve looping over a fixed number of iterations.

Example Fix:
pub fn most_significant_bit(mut x: U256) -> Result<u8, Error> {
    let mut r = 0;
    for i in (0..=255).rev() {
        if x & (U256::one() << i) > U256::zero() {
            r = i;
            break;
        }
    }
    Ok(r)
}
