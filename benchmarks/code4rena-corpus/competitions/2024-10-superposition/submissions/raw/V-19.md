# Vulnerability details

## Proof of Concept
The pool contracts initialisation function lacks range checks on some of its parameters.

Namely:
```Rust
u256 price;
u8 tick_spacing;
u128 max_liquidity_per_tick;
```

An erroneous call can be made by passing unchecked parameters. With values that would error and revert without sufficient information.

Erroneous Call
```Rust
pool.init(
        115792089237316195423570985008687907853269984665640564039457584007913129639935,
        16,
        255,
        340282366920938463463374607431768211455,
    );
```

The result of this is an unstable initialise function. Resulting in unpredictable behaviour if invalid inputs were entered erroneously.

## Recommended Mitigation Steps
Add checks to the parameters so that errors and reverts would be handled gracefully.
```Rust
assert_or!(!self.initialised.get(), Error::PoolAlreadyInitialised);
assert_or!(fee <= 10000, Error::BadFee);
+ assert_or!(price <= 100000, Error::BadPrice);
+ assert_or!(tick_spacing <= 20, Error::BadTickSpacing);
+ assert_or!(max_liquidity_per_tick <= 1000000, Error::BadMaxLiquidityPerTick);
```
