# Vulnerability details

## Finding description and impact

The Rust function get_max_tick is designed to calculate a “maximum tick” based on an input spacing parameter. 
Where spacing is given as an 8-bit unsigned integer (u8). 

## Proof of Concept
Code Explanation
```Rust
pub fn get_max_tick(spacing: u8) -> i32 {
    let spacing = spacing as i32;
    (MAX_TICK / spacing) * spacing
}
```
	1.	Parameter Conversion:
	•	The function takes spacing as a u8 but immediately casts it to i32 for use in the calculations.
	2.	Calculation:
	•	The function attempts to calculate (MAX_TICK / spacing) * spacing. Here, MAX_TICK is presumably a constant defined elsewhere in the program as an i32.
	•	The expression first divides MAX_TICK by spacing, then multiplies the result by spacing. This effectively gives the largest multiple of spacing that is less than or equal to MAX_TICK.

Setting spacing to 0

When spacing is set to 0, we encounter a problem:

	•	Division by Zero: In the expression (MAX_TICK / spacing) * spacing, setting spacing to 0 results in a division by zero in (MAX_TICK / spacing).
	•	Runtime Error: In Rust, dividing by zero on integer types triggers a runtime panic, as it is undefined behaviour. The Rust runtime will terminate the program with an error message if this occurs.

Expected Output or Error

If spacing is set to 0, running this function will result in a panic at runtime with an error message similar to:
```Rusr
thread 'main' panicked at 'attempt to divide by zero'
```

## Recommended mitigation steps
How to Prevent the Error

To handle cases where spacing might be zero, you could add a check at the beginning of the function:
```Rust
pub fn get_max_tick(spacing: u8) -> i32 {
    if spacing == 0 {
        panic!("Spacing cannot be zero");
    }
    let spacing = spacing as i32;
    (MAX_TICK / spacing) * spacing
}
```
Alternatively, you could return a specific error value, or use Option<i32> or Result<i32, String> to handle the potential error gracefully.
