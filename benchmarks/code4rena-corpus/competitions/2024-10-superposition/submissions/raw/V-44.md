# Vulnerability details

## Impact

A compilation flag has the wrong logic and will never be active in production. This may cause the deployment of Longtail with some missing modules.

## Proof of Concept

Compilation for modules was disabled on the testing environment, but now it's also disabled in production:

```rust
        mod shim {
->          #[cfg(all(not(target_arch = "wasm32"), not(feature = "testing")))]
            compile_error!(
                "Either `swaps` or `swap_permit2_a` or `quotes` or `positions` or `update_positions`, `admin`, `migrations`, `adjust_positions` or `swap_permit2_b` must be enabled when building for wasm."
            );
            #[stylus_sdk::prelude::public]
            impl crate::Pools {}
        }
```

The expected behavior should be disabled while testing and enabled in production.

## Recommended mitigation steps

Consider enabling the compilation check when the code will be deployed in production:

```rust
        mod shim {
-          #[cfg(all(not(target_arch = "wasm32"), not(feature = "testing")))]
+          #[cfg(all(target_arch = "wasm32", not(feature = "testing")))]
            compile_error!(
                "Either `swaps` or `swap_permit2_a` or `quotes` or `positions` or `update_positions`, `admin`, `migrations`, `adjust_positions` or `swap_permit2_b` must be enabled when building for wasm."
            );
            #[stylus_sdk::prelude::public]
            impl crate::Pools {}
        }
```
