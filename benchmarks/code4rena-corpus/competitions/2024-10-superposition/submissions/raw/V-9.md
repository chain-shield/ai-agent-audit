# Vulnerability details

The compute_swap_step function is calculating how much tokens are being swapped, and part of that calculation includes charging a fee (like how you pay a small percentage when exchanging currency at a bank). The amount of the fee is determined by the fee_pips value, which is provided as input when the function is called.

fee_pips: This represents the fee rate. It's usually expressed in basis points. One basis point (bps) is 0.01%. So, if fee_pips is 100, it means a 1% fee. If it's 3000, that’s a 3% fee.

In the code:
"let amount_remaining_less_fee = mul_div(
    amount_remaining.into_raw(),
    U256::from(1e6 as u32 - fee_pips), // 1e6 - fee_pips
    U256::from(1e6 as u32),            // 1e6
)?;"
This part is subtracting the fee from amount_remaining. But if someone manipulate the value of fee_pips, they can change how much fee is taken.

The Risk
The risk is that there's no rule checking the value of fee_pips, a user could exploit this.  In the function compute_swap_step, the fee is calculated using the parameter fee_pips, which represents the fee rate. This fee is applied to the remaining amount of tokens (amount_remaining) during a swap.
Since the fee is applied to amount_remaining, the user might attempt to manipulate this input amount to minimize the impact of the fee.

Example: A user could split a large swap into smaller steps, each minimizing the fee, instead of conducting a single larger swap where the fee would have been higher.

Why This is Dangerous
Bypassing Fees: If a user can manipulate fee_pips to be zero or a very low value, the calculation for the fee might result in very small or no fees. For example, if fee_pips = 0, then 1e6 - fee_pips equals 1e6, meaning the amount remaining is not reduced at all (no fee is charged).
Excessive Fees: If fee_pips is set to an extremely high value, such as 999,999, the resulting fee would consume almost all of amount_remaining, potentially causing logic errors or resulting in an unexpected swap outcome.

Imagine that a decentralized exchange charges a fee of 0.3% on each swap, represented by fee_pips = 3000 (3000 basis points = 0.3%). If a malicious user sets fee_pips to 0, the swap would proceed without charging any fee, allowing the user to bypass paying the exchange fee altogether.

To prevent users from manipulating the fee by giving a bad value for fee_pips, you should add a check to make sure that fee_pips is within a reasonable range.
