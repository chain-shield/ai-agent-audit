S-290
Unprofitable swaps for tokens with greater than 8 decimals price feeds
zanderbyte
100
Sufficient
383d ago
Finding description and impact

Before executing a swap, the checkUpkeep function is invoked to ensure that the swap will be profitable by verifying that the current USD value of the asset meets the minimum swap size usd value (availableAssetUsdValue >= swapParams.minSwapSizeUsd * assetUnit).

However, the SwapParams struct defines that minSwapSizeUsd will be in 8 decimals, while some Chainlink price feeds for token/USD use 18 decimals (For example AMPL/USD on Mainnet, BONK/USD and PEPE/USD on Optimism, etc.). This can result in incorrect comparisons when determining whether a swap is profitable.

A malicious actor (or inadvertently, through dust amounts) could exploit this by sending tokens associated with an 18-decimal price feed. This would cause the protocol to incorrectly perceive a sufficient USD value and trigger unprofitable swaps.

Proof of Concept

The relevant part of the checkUpkeep function performs a comparison to decide whether a swap should proceed:

      // 1) Get the current asset value in USD available in the FeeAggregator
      uint256 availableAssetUsdValue = IERC20(asset).balanceOf(address(s_feeAggregator)) * assetPrice;

      // 2) Don't swap asset if the asset's current USD balance on this FeeAggregator is
      // below the minimum swap amount or if insufficient time has elapsed since the last swap
      if (
        availableAssetUsdValue >= swapParams.minSwapSizeUsd * assetUnit
          && block.timestamp - s_latestSwapTimestamp[asset] >= swapParams.swapInterval
      ) {

Consider the following scenario:

AMPL has a current price of $1.20 and the token itself has 9 decimals.
Swapping 1 AMPL for LINK, at the time of writing, would result in 0.04 LINK, worth $0.97, while transaction cost is $11.97.
The swapParams.minSwapSizeUsd is set to 20e8 ($20), representing the minimum USD value required for a swap to be deemed profitable.
AMPL token balance = 1e9
USD value from AMPL/USD price feed, at the time of writing is 1.245e18
Using the calculations in the contract: availableAssetUsdValue = 1e9 * 1.245e18 = 1.245e27
The check proceeds as follows: if (1.245e27 >= 20e8 * 1e9) { ... }

Despite the actual USD value of 1 AMPL being far below the required $20 threshold, the swap is approved due to the mismatch in decimal handling.

Recommended mitigation steps

Ensure that the minSwapSizeUsd value is appropriately scaled to match the decimals of the associated price feed. This can be achieved also by normalizing the availableAssetUsdValue and swapParams.minSwapSizeUsd to the same decimal precision before performing the comparison.
