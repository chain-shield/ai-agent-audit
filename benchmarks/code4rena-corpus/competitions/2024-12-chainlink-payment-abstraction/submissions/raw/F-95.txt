S-390
`SwapAutomator._getAssetPrice()` doesn't validate returned price against `minAnswer` & `maxAnswer`
hals
35
Sufficient
383d ago
Finding description and impact
SwapAutomator._getValidatedAssetPrice() function is used to fetch the assets prices from chainlink price feeds, and used in:
chekUpkeep() : to check if there is any asset passing the minimum swap size and price is within an acceptable slippage and can be swapped into $LINK token.
performUpkeep() : when the assets are swapped into $LINK tokens via UniswapV3 router.
  function _getValidatedAssetPrice(
    AggregatorV3Interface oracle
  ) private view returns (uint256 assetPrice) {
    (uint256 answer, uint256 updatedAt) = _getAssetPrice(oracle);

    if (answer == 0) revert Errors.ZeroOracleData();
    if (updatedAt < block.timestamp - STALENESS_THRESHOLD) {
      revert Errors.StaleOracleData();
    }

    return answer;
  }

where _getAssetPrice():

  function _getAssetPrice(
    AggregatorV3Interface oracle
  ) private view returns (uint256 assetPrice, uint256 updatedAtTimestamp) {
    (, int256 answer,, uint256 updatedAt,) = oracle.latestRoundData();
    return (answer.toUint256(), updatedAt);
  }
Knowing that some chainlink aggregators still have a built in circuit breaker if the price is below minAnswer or above maxAnswer, where it will return the minAnswer if the asset price crashes below the minAnswer, and the contract will consume this minAnswer price when the asset price falls below it.
But as can be noticed; _getAssetPrice() doesn't validate the returned price against min/max price (to be set for each asset).

Impact:

This will result in using an invalid price to execute the swap transaction when the asset price crashes, resulting in a loss of the received link tokens from the swap, hence less funds available to be allocated for the the service providers.

Proof of Concept

SwapAutomator._getValidatedAssetPrice()

  function _getValidatedAssetPrice(
    AggregatorV3Interface oracle
  ) private view returns (uint256 assetPrice) {
    (uint256 answer, uint256 updatedAt) = _getAssetPrice(oracle);


    if (answer == 0) revert Errors.ZeroOracleData();
    if (updatedAt < block.timestamp - STALENESS_THRESHOLD) {
      revert Errors.StaleOracleData();
    }


    return answer;
  }

SwapAutomator._getAssetPrice()

    function _getAssetPrice(
        AggregatorV3Interface oracle
    ) private view returns (uint256 assetPrice, uint256 updatedAtTimestamp) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        return (answer.toUint256(), updatedAt);
    }

Recommended mitigation steps

Update _getAssetPrice() to check against min/max answer of the chailink price feed before consuming the price (bounds set for each allowlisted asset).

0xsomeone

The submission revolves around the enforcement of minimum/maximum price measurements on the Chainlink system directly, and the lack of any on-chain security guards for when an asset's price closes in towards the maximum/minimum permitted.

Akin to my response regarding the 24-hour data threshold, the maximum impact of this exhibit would be that the minimum price is achieved but AMMs have reduced even further (thereby preventing swaps) or that the maximum price has been achieved and the system utilizes the higher output of the AMM swap, thereby operating properly.

I do not believe that this is a valid HM concern, however, I do not agree that off-chain safeguards are the main mechanism to detect this issue as on-chain security measures such as permitted time-based price deltas coupled with the price approaching either end can adequately be built on-chain.

As such, I believe a severity rating of QA (L) is appropriate.
