When trackBeforeSend is out-of-gas, the user pays less gas fee.
p0wd3r
67
Sufficient
383d ago
Finding description and impact

In send hook, GasMeter is not updated during trackBeforeSend out-of-gas, which causes the gas value used to calculate the fee to be smaller than the actual value, resulting in undercharging.

Proof of Concept

In callBeforeSendListener, the GasMeter will only update when the hook returns normally, it will not update if it returns an error or triggers a panic through out-of-gas.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/keeper/before_send.go#L143

	defer func() {
		if r := recover(); r != nil {
			err = types.ErrTrackBeforeSendOutOfGas
		}
	}()
    ...
				childCtx := c.WithGasMeter(types2.NewGasMeter(types.TrackBeforeSendGasLimit))
				_, err = k.contractKeeper.Sudo(childCtx, cwAddr, msgBz)
				if err != nil {
					return errorsmod.Wrapf(err, "failed to call before send hook for denom %s", coin.Denom)
				}

				// consume gas used for calling contract to the parent ctx
				c.GasMeter().ConsumeGas(childCtx.GasMeter().GasConsumed(), "track before send gas")

The fee to be paid in xfeemarket will be calculated based on the GasMeter.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/xfeemarket/post/fee.go#L112
https://github.com/skip-mev/feemarket/blob/main/x/feemarket/ante/fee.go#L240

		// Determine the required fees by multiplying each required minimum gas
		// price by the gas, where fee = ceil(minGasPrice * gas).
		gasConsumed := int64(ctx.GasMeter().GasConsumed())
		gcDec := sdkmath.LegacyNewDec(gasConsumed)
		glDec := sdkmath.LegacyNewDec(feeGas)

		consumedFeeAmount := gasPrice.Amount.Mul(gcDec)
		limitFee := gasPrice.Amount.Mul(glDec)

		consumedFee = sdk.NewCoin(gasPrice.Denom, consumedFeeAmount.Ceil().RoundInt())
		requiredFee = sdk.NewCoin(gasPrice.Denom, limitFee.Ceil().RoundInt())

Therefore, when an error or out-of-gas is triggered in the contract of trackBeforeSend, the value in GasMeter is less than the actual consumed value, ultimately leading to undercharging.

Recommended mitigation steps

When handling errors and panics, also call c.GasMeter().ConsumeGas.

In the ideal case, this is not intended behavior as we should charge as close to actual consumed gas as possible. However that is not done in implementation either due to the complexities or other reasons. The impact is very small as gas is still charged for the non contract part of the transaction while the transaction is not executed so the user is still disincentived to trigger this intentionally, even if they do so at scale there is limited impact on the chain.
