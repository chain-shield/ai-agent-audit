S-176
Mint and burn functions are unusable from the CLI
0xAlix2
82
Sufficient
383d ago
Finding description and impact

Token factory allows users to create custom denoms. When a user makes a denom, he automatically becomes the admin of that denom, this will enable him to mint/burn/transfer tokens to/from/between users, this is mentioned in the docs:

Once a denom is created, the original creator is given "admin" privileges over the asset. This allows them to:

Mint their denom to any account
Burn their denom from any account

The mint message has the following type:

type MsgMint struct {
	Sender        string     `protobuf:"bytes,1,opt,name=sender,proto3" json:"sender,omitempty" yaml:"sender"`
	Amount        types.Coin `protobuf:"bytes,2,opt,name=amount,proto3" json:"amount" yaml:"amount"`
	MintToAddress string     `protobuf:"bytes,3,opt,name=mintToAddress,proto3" json:"mintToAddress,omitempty" yaml:"mint_to_address"`
}

The burn message has the following type:

type MsgBurn struct {
	Sender          string     `protobuf:"bytes,1,opt,name=sender,proto3" json:"sender,omitempty" yaml:"sender"`
	Amount          types.Coin `protobuf:"bytes,2,opt,name=amount,proto3" json:"amount" yaml:"amount"`
	BurnFromAddress string     `protobuf:"bytes,3,opt,name=burnFromAddress,proto3" json:"burnFromAddress,omitempty" yaml:"burn_from_address"`
}

As seen, the mint msg contains mintToAddress which refers to the address the tokens should be minted to, and the burn msg also contains burnFromAddress which refers to the address that the tokens should be burnt from.

On the other hand, there are 2 helper functions for each message that helps construct each message. For mint messages, we have NewMsgMint and NewMsgMintTo, https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/types/msgs.go#L60-L73. For burn messages, we have NewMsgBurn and NewMsgBurnFrom, https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/types/msgs.go#L107-L121.

The issue here is that for the CLI client that allows users to fire transactions from the CLI, the protocol is using both NewMsgMint and NewMsgBurn, without allowing users to input either mintToAddress or burnFromAddress.

// NewMintCmd broadcast MsgMint
func NewMintCmd() *cobra.Command {
	cmd := &cobra.Command{
@>	    Use:   "mint [amount] [flags]",
		Short: "Mint a denom to an address. Must have admin authority to do so.",
		Args:  cobra.ExactArgs(1),
		RunE: func(cmd *cobra.Command, args []string) error {
			// ...

@>	        msg := types.NewMsgMint(
				clientCtx.GetFromAddress().String(),
				amount,
			)

			// ...		},
	}

	flags.AddTxFlagsToCmd(cmd)
	return cmd
}

// NewBurnCmd broadcast MsgBurn
func NewBurnCmd() *cobra.Command {
	cmd := &cobra.Command{
@>	    Use:   "burn [amount] [flags]",
		Short: "Burn tokens from an address. Must have admin authority to do so.",
		Args:  cobra.ExactArgs(1),
		RunE: func(cmd *cobra.Command, args []string) error {
			// ...

@>	        msg := types.NewMsgBurn(
				clientCtx.GetFromAddress().String(),
				amount,
			)

			// ...
		},
	}

	flags.AddTxFlagsToCmd(cmd)
	return cmd
}

When not provided, both MintToAddress and BurnFromAddress are set to the msg sender, here and here.

This makes both mint and burn functionalities useless from the CLI, as they only allow "self" mints and burns, breaking the core functionality that allows admins to mint/burn tokens to/from users.

Recommended mitigation steps

Reconstruct both NewMintCmd and NewBurnCmd to accept a MintToAddress/BurnFromAddress and to use NewMsgMintTo/NewMsgBurnFrom instead of NewMsgMint/NewMsgBurn.
