S-136
Unbounded query in TokenFactory's `DenomsFromCreator` endpoint creates DoS vector
Rhaydden
30
Sufficient
383d ago
Finding description and impact

The TokenFactory module has an unbounded query endpoint DenomsFromCreator that retrieves all denoms associated with a creator address without any pagination limits. This creates a DOS vector where an attacker could:

Create many token denoms associatted with an address (within transaction/gas limits)
When querying these denoms through the GRPC endpoint, the protocool will attempt to load and return all denoms at once
Cause memory bloat and potential node crashes due to out-of-memory errors

The root cause is in the getDenomsFromCreator keeper function which performs an unbounded iteration over all denoms, combined with its exposure through an unpaginated gRPC query endpoint.

Impact

Potential node crashes from memory exhaustion. Also, as no gas costs are associated with queries, this allows unlimited exploitation. this could be used to degrade network performance at scale.

Proof of Concept

The vulnerability exists in three interconnected components:

The underlying keeper function in creators.go:
https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/tokenfactory/keeper/creators.go#L13-L24
func (k Keeper) getDenomsFromCreator(ctx sdk.Context, creator string) []string {
    store := k.GetCreatorPrefixStore(ctx, creator)
    iterator := store.Iterator(nil, nil)
    defer iterator.Close()

    denoms := []string{}
    for ; iterator.Valid(); iterator.Next() {
        denoms = append(denoms, string(iterator.Key()))
    }
    return denoms
}
The exposed gRPC endpoint in grpc_query.go:
https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/tokenfactory/keeper/grpc_query.go#L32-L36
func (k Keeper) DenomsFromCreator(ctx context.Context, req *types.QueryDenomsFromCreatorRequest) (*types.QueryDenomsFromCreatorResponse, error) {
    sdkCtx := sdk.UnwrapSDKContext(ctx)
    denoms := k.getDenomsFromCreator(sdkCtx, req.GetCreator())
    return &types.QueryDenomsFromCreatorResponse{Denoms: denoms}, nil
}
The protobuf definition that lacks pagination:
https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/proto/osmosis/tokenfactory/v1beta1/query.proto#L71-L81
message QueryDenomsFromCreatorRequest {
    string creator = 1 [ (gogoproto.moretags) = "yaml:\"creator\"" ];
}

message QueryDenomsFromCreatorResponse {
    repeated string denoms = 1 [ (gogoproto.moretags) = "yaml:\"denoms\"" ];
}
Attack flow:
Attacker creates numerous token denoms (e.g., 10,000+) using their creator address
Attacker repeatedly queries DenomsFromCreator for their address
Each query forces the node to:
Iterate through all denoms
Load them into memory
Serialize them into the response
Multiple concurrent requests can amplify the impact
Node resources become exhausted, affecting service availability
Recommendations
Implement pagination in the protobuf definition:
import "cosmos/base/query/v1beta1/pagination.proto";

message QueryDenomsFromCreatorRequest {
    string creator = 1 [ (gogoproto.moretags) = "yaml:\"creator\"" ];
    cosmos.base.query.v1beta1.PageRequest pagination = 2;
}

message QueryDenomsFromCreatorResponse {
    repeated string denoms = 1 [ (gogoproto.moretags) = "yaml:\"denoms\"" ];
    cosmos.base.query.v1beta1.PageResponse pagination = 2;
}
Modify the keeper function to support pagination:
func (k Keeper) getPaginatedDenomsFromCreator(
    ctx sdk.Context,
    creator string,
    pagination *query.PageRequest,
) ([]string, *query.PageResponse, error) {
    store := k.GetCreatorPrefixStore(ctx, creator)
    
    // Use standard SDK pagination
    pageRes, err := query.Paginate(store, pagination, func(key []byte, _ []byte) error {
        denoms = append(denoms, string(key))
        return nil
    })
    
    return denoms, pageRes, err
}
Update the GRPC handler to use the paginated function:
func (k Keeper) DenomsFromCreator(ctx context.Context, req *types.QueryDenomsFromCreatorRequest) (*types.QueryDenomsFromCreatorResponse, error) {
    sdkCtx := sdk.UnwrapSDKContext(ctx)
    denoms, pageRes, err := k.getPaginatedDenomsFromCreator(sdkCtx, req.GetCreator(), req.Pagination)
    if err != nil {
        return nil, err
    }
    return &types.QueryDenomsFromCreatorResponse{
        Denoms: denoms,
        Pagination: pageRes,
    }, nil
}
