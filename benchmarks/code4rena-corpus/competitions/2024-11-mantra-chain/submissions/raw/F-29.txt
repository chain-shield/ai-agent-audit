Unsafe oracle client initialization with uncontrolled goroutine
Rhaydden
30
Sufficient
383d ago
Finding Description and Impact

The oracle client initialization in the client connection is established in an uncontrolled goroutine without proper synchronization. This causes issues like:

Race Conditions because the function returns an oracle client that may not be fully initialized, as the connection process happens asynchronously.
Connection failures result in a panic in a separate goroutine, which may not be properly caught by the application's error handling.
The application might proceed with an unconnected oracle client, potentially causing failed price updates or invalid vote extensions.

The impact is severe as the oracle client is used for vote extension, price data aggregation and to block proposal validation

Proof of Concept

https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/app/oracle.go#L47-L54

go func() {
    app.Logger().Info("attempting to start oracle client...", "address", cfg.OracleAddress)
    if err := oracleClient.Start(context.Background()); err != nil {
        app.Logger().Error("failed to start oracle client", "err", err)
        panic(err)
    }
}()

return oracleClient, oracleMetrics, nil

To demonstrate the issue:

The function returns immediately while the connection is still being established
Subsequent code might attempt to use the oracle client before it's ready:
For example, in app.go
// oracle initialization
	client, metrics, err := app.initializeOracle(appOpts)
>>>	if err != nil {  // This error check won't catch connection failures!
		panic(fmt.Errorf("failed to initialize oracle client and metrics: %w", err))
	}

	app.MarketMapKeeper.SetHooks(app.OracleKeeper.Hooks())


// This might execute before the client is connected
	app.initializeABCIExtensions(client, metrics)
If the connection fails, the panic occurs in a separate goroutine:
panic: connection refused // This panic might be lost or improperly handled
Recommended Mitigation Steps

Consider implementing proper synchronization using a context with timeout and error handling:

func (app *App) initializeOracle(appOpts types.AppOptions) (oracleclient.OracleClient, servicemetrics.Metrics, error) {
     // Read general config from app-opts, and construct oracle service.
     cfg, err := oracleconfig.ReadConfigFromAppOpts(appOpts)
     if err != nil {
         return nil, nil, err
     }

     oracleMetrics, err := servicemetrics.NewMetricsFromConfig(cfg, app.ChainID())
     if err != nil {
         return nil, nil, err
     }

     oracleClient, err := oracleclient.NewPriceDaemonClientFromConfig(
         cfg,
         app.Logger().With("client", "oracle"),
         oracleMetrics,
     )
     if err != nil {
         return nil, nil, err
     }

-    go func() {
-        app.Logger().Info("attempting to start oracle client...", "address", cfg.OracleAddress)
-        if err := oracleClient.Start(context.Background()); err != nil {
-            app.Logger().Error("failed to start oracle client", "err", err)
-            panic(err)
-        }
-    }()
+    // Create context with timeout
+    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
+    defer cancel()
+
+    // Start the oracle client synchronously with timeout
+    app.Logger().Info("attempting to start oracle client...", "address", cfg.OracleAddress)
+    if err := oracleClient.Start(ctx); err != nil {
+        app.Logger().Error("failed to start oracle client", "err", err)
+        return nil, nil, fmt.Errorf("failed to start oracle client: %w", err)
+    }

     return oracleClient, oracleMetrics, nil
 }
