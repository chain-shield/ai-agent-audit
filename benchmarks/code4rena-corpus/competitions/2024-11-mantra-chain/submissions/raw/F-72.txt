Tokens Starting with IBC Not Checked During Genesis Validation
gxh191
00
Sufficient
383d ago

This function is responsible for performing basic validation of parameters and tokens (Denom) in the genesis state, ensuring that the system starts in a consistent and secure state. Below is a detailed, section-by-section analysis of the function.

It calls the validateDenom function to validate each token individually.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/types/genesis.go#L30

// Validate performs basic genesis state validation returning an error upon any
// failure.
func (gs GenesisState) Validate() error {
    err := gs.Params.Validate()
    if err != nil {
        return err
    }

    seenDenoms := make(map[string]bool)

    for _, denom := range gs.GetFactoryDenoms() {
        if err := validateDenom(denom, seenDenoms); err != nil { // <----------
            return err
        }
    }

    return nil
}

The validateDenom function is responsible for verifying the legality and correctness of each token identifier (Denom) in the genesis state.

It further validates the structure and legality of the token identifier using the DeconstructDenom function.

However, both the validateDenom and DeconstructDenom functions fail to check tokens that start with the IBC prefix. This oversight allows malicious users to inject tokens prefixed with IBC into the Genesis file, potentially leading to security vulnerabilities in cross-chain token management.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/types/genesis.go#L55

// validateDenom validates a single denom in the genesis state.
func validateDenom(denom GenesisDenom, seenDenoms map[string]bool) error {
    switch {
    case seenDenoms[denom.GetDenom()]:
        return errorsmod.Wrapf(ErrInvalidGenesis, "duplicate denom: %s", denom.GetDenom())
    case denom.AuthorityMetadata.Admin != "":
        if _, err := sdk.AccAddressFromBech32(denom.AuthorityMetadata.Admin); err != nil {
            return errorsmod.Wrapf(ErrInvalidAuthorityMetadata, "invalid admin address: %s", err)
        }
    case denom.HookContractAddress != "":
        if _, err := sdk.AccAddressFromBech32(denom.HookContractAddress); err != nil {
            return errorsmod.Wrapf(ErrInvalidHookContractAddress, "invalid hook contract address: %s", err)
        }
    }

    seenDenoms[denom.GetDenom()] = true

    if _, _, err := DeconstructDenom(denom.GetDenom()); // <-------------
    err != nil {
        return err
    }

    return nil
}

In the validateCreateDenom function, there are restrictions imposed on IBC tokens. However, during the genesis validation process, IBC tokens are not checked.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/keeper/createdenom.go#L58

func (k Keeper) validateCreateDenom(ctx sdk.Context, creatorAddr, subdenom string) (newTokenDenom string, err error) {
    // Temporary check until IBC bug is sorted out
    if k.bankKeeper.HasSupply(ctx, subdenom) { // <------------
        return "", fmt.Errorf("temporary error until IBC bug is sorted out, " +
            "can't create subdenoms that are the same as a native denom")
    }

    denom, err := types.GetTokenDenom(creatorAddr, subdenom)
    if err != nil {
        return "", err
    }

    _, found := k.bankKeeper.GetDenomMetaData(ctx, denom)
    if found {
        return "", types.ErrDenomExists
    }

    return denom, nil
}
Impact

This issue introduces several IBC vulnerabilities.

System Instability

Allowing unrestricted IBC tokens to be injected into the genesis file can lead to errors and inconsistencies during cross-chain interactions. This may result in chaotic network token management, frequent transaction failures, or interruptions in inter-chain communication. Such instability not only affects users' normal transaction experiences but can also reduce the network's operational efficiency, ultimately compromising the overall reliability of the blockchain system and diminishing user trust.

Data Consistency Issues

Unverified IBC tokens can cause inconsistencies in on-chain data, disrupting the proper functioning of the system's state machine. This may lead to chaotic transaction records and incorrect ledger states. Data inconsistencies not only impair users' transaction experiences and the normal operation of system functionalities but can also prevent the blockchain network from correctly processing transactions. This reduces the system's reliability and efficiency and may even cause network forks or crashes, severely impacting the stable operation of the entire blockchain ecosystem.

Permission Abuse

Attackers could create forged IBC tokens, thereby bypassing the system's permission control mechanisms. This can result in unauthorized actions such as token transfers or privilege escalations. Such abuse can severely compromise the system's security, allowing attackers to manipulate assets or access sensitive information, posing significant security risks to the entire blockchain ecosystem.

Recommendations for Fixing

Add IBC-related checks similar to those in the validateCreateDenom function.

func (k Keeper) validateCreateDenom(ctx sdk.Context, creatorAddr, subdenom string) (newTokenDenom string, err error) {
    // Temporary check until IBC bug is sorted out
    if k.bankKeeper.HasSupply(ctx, subdenom) { // <------------
        return "", fmt.Errorf("temporary error until IBC bug is sorted out, " +
            "can't create subdenoms that are the same as a native denom")
    }

    denom, err := types.GetTokenDenom(creatorAddr, subdenom)
    if err != nil {
        return "", err
    }

    _, found := k.bankKeeper.GetDenomMetaData(ctx, denom)
    if found {
        return "", types.ErrDenomExists
    }

    return denom, nil
}

To address the identified vulnerabilities, implement additional checks in the validateDenom and DeconstructDenom functions to ensure that tokens starting with the IBC prefix are properly validated. This will prevent malicious users from injecting IBC-prefixed tokens into the genesis file, thereby enhancing the security and stability of cross-chain token management.

sed -i.bak -e "s/^minimum-gas-prices *=.*/minimum-gas-prices = \"0.001stake\"/g" ~/.mantrachain/config/app.toml

Enable the chain's API interface to facilitate interaction with the node using REST APIs.

sed -i.bak '/\[api\]/,+3 s/enable = false/enable = true/' ~/.mantrachain/config/app.toml

Create an account named validator in the local keyring to issue transactions.

mantrachaind keys add validator
