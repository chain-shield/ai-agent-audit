Valid transactions fail for some tx signers due to the hardcoded tip refund logic

Proof of Concept

In the fee market module, transaction fees are processed in the PostHandle function where excess fees are refunded as tips back to the fee payer:

https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/xfeemarket/post/fee.go#L38-L146

func (dfd FeeMarketDeductDecorator) PostHandle(ctx sdk.Context, tx sdk.Tx, simulate, success bool, next sdk.PostHandler) (sdk.Context, error) {
    // ...
    if !simulate {
        payCoin, tip, err = ante.CheckTxFee(ctx, minGasPrice, payCoin, feeGas, false)
        if err != nil {
            return ctx, err
        }
    }

    feePayer := feeTx.FeePayer()
    if err := dfd.BurnFeeAndRefund(ctx, payCoin, tip, feePayer, params.FeeDenom); err != nil {
        return ctx, err
    }
    // ...
}

The BurnFeeAndRefund function attempts to refund any excess fees (tips) back to the fee payer:

https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/xfeemarket/post/fee.go#L147-L181

func (dfd FeeMarketDeductDecorator) BurnFeeAndRefund(ctx sdk.Context, fee, tip sdk.Coin, feePayer sdk.AccAddress, defaultFeeDenom string) error {
    // ...
    if !tip.IsNil() && !tip.IsZero() {
        err := RefundTip(dfd.bankKeeper, ctx, feePayer, sdk.NewCoins(tip))
        if err != nil {
            return err
        }
    }
    // ...
}

The issue arises when sending the refund via SendCoinsFromModuleToAccount:

https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/xfeemarket/post/fee.go#L191-L199

func RefundTip(bankKeeper BankKeeper, ctx sdk.Context, feePayer sdk.AccAddress, coins sdk.Coins) error {
    err := bankKeeper.SendCoinsFromModuleToAccount(ctx, feemarkettypes.FeeCollectorName, feePayer, coins)
    if err != nil {
        return err
    }
    return nil
}

This fails if the fee payer's address is blocked:

// SendCoinsFromModuleToAccount transfers coins from a ModuleAccount to an AccAddress.
// It will panic if the module account does not exist. An error is returned if
// the recipient address is black-listed or if sending the tokens fails.
func (k BaseKeeper) SendCoinsFromModuleToAccount(
	ctx context.Context, senderModule string, recipientAddr sdk.AccAddress, amt sdk.Coins,
) error {
	senderAddr := k.ak.GetModuleAddress(senderModule)
	if senderAddr == nil {
		panic(errorsmod.Wrapf(sdkerrors.ErrUnknownAddress, "module account %s does not exist", senderModule))
	}

	if k.BlockedAddr(recipientAddr) {
|>		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", recipientAddr)
	}

	return k.SendCoins(ctx, senderAddr, recipientAddr, amt)
}
Impact
Valid transactions fail when the fee payer's address is blocked from receiving funds
This is particularly problematic since:
It's common practice in Cosmos chains to overpay gas fees due to gas price multipliers to ensure their tx is successful (i.e something like baseFee * gasMultiplier)
In Mantra's case, the excess fees must be refunded as tips.
However as shown above, in our case depending on the signer of the tx (fee payer) the refund will fail if the fee payer is blocked in sendCoinsFromModuleToAccount
Users with blocked addresses cannot process transactions even if they are willing to forgo the tip refund breaking the integration with core clients
Recommended Mitigation Steps

Allow transaction signers / fee payers to specify a separate refund address for receiving tips. This can be done by:

Adding a refundAddress field to the transaction interface
Modifying the fee market module to use this address for tip refunds instead of always using the fee payer's address
Making the refund address optional - defaulting to the fee payer if not specified

This allows users with blocked addresses to still process transactions by specifying an alternative address for receiving refunds.
