Proof of Concept

The BeginBlocker function is called at the start of each block. Its main purpose is to check and allocate MCA tax at the beginning of every block.

It calls the AllocateMcaTax function:

Link to code

// BeginBlocker sets the proposer for determining distribution during endblock
// and distributes rewards for the previous block.
func BeginBlocker(ctx sdk.Context, k keeper.Keeper) error {
	...
	if err := k.AllocateMcaTax // <--------
		(ctx, params.McaTax, McaAddress); err != nil {
		return err
	}
	return nil
}

The AllocateMcaTax function is responsible for allocating a portion of the collected fees based on a given MCA tax rate (mcaTax) to a specified address (mcaAddress).

Link to code

func (k Keeper) AllocateMcaTax(ctx context.Context, mcaTax math.LegacyDec, mcaAddress sdk.AccAddress) error {
	feeCollector := k.authKeeper.GetModuleAccount(ctx, k.feeCollectorName)
	feesCollectedInt := k.bankKeeper.GetAllBalances(ctx, feeCollector.GetAddress())
	...
}

The function k.authKeeper.GetModuleAccount retrieves a module account by the provided feeCollectorName. This account is used to collect all the system fees.

The function k.bankKeeper.GetAllBalances fetches the total balance of the feeCollector account, representing all the collected fees. This balance includes all the tokens.

The implementation of GetAllBalances iterates through the balances of all tokens in the specified account:

// GetAllBalances returns all the account balances for the given account address.
func (k BaseViewKeeper) GetAllBalances(ctx context.Context, addr sdk.AccAddress) sdk.Coins {
	balances := sdk.NewCoins()
	k.IterateAccountBalances(ctx, addr, func(balance sdk.Coin) bool {
		balances = balances.Add(balance)
		return false
	})

	return balances.Sort()
}

The CreateDenom operation is used to create a new token. Performing this operation incurs a fee paid by the creator.

The fee for creating a token is handled by the chargeForCreateDenom function, which transfers the token fee from the creator's account to the feeCollectorAddr account.

Link to code

func (k Keeper) chargeForCreateDenom(ctx sdk.Context, creatorAddr string) (err error) {
	params := k.GetParams(ctx)

	if len(params.DenomCreationFee) != 0 {
		...

		feeCollectorAddr, err := sdk.AccAddressFromBech32(params.FeeCollectorAddress)
		if err != nil {
			return errors.Wrapf(err, "wrong fee collector address: %v", err)
		}

		err = k.bankKeeper.SendCoins(
			ctx,
			accAddr, feeCollectorAddr, // <-------
			params.DenomCreationFee,
		)
		...
}

An attacker can repeatedly perform the CreateDenom operation, which causes an unlimited accumulation of coins in the feeCollectorAddr account. This will make the GetAllBalances function slow or even halt the chain during its iteration, leading to a Denial-of-Service issue.

Exploitation Strategy:

An attacker can repeatedly execute the tokenfactory create-denom operation, causing an unlimited accumulation of coins in the feeCollectorAddr. This will cause the BeginBlocker function to call GetAllBalances and iterate through the coins, severely slowing down the blockchain or even halting it, resulting in a Denial-of-Service issue.

Additional Explanation

On the Code4rena platform, the Scope explicitly includes files related to the tokenfactory module. Moreover, the Attack Ideas (where to focus for bugs) provided by Code4rena also emphasize the tokenfactory module as a key focus area.

Therefore, I believe that vulnerabilities in the tokenfactory module should be acknowledged.

Additionally, MANTRA Chain includes the tokenfactory module in its transaction commands:

➜  2024-11-mantra git:(main) mantrachaind tx
Transactions subcommands

Usage:
  mantrachaind tx [flags]
  mantrachaind tx [command]

Available Commands:
...
  tax                 Transactions commands for the tax module
  tokenfactory        tokenfactory transactions subcommands
...

This indicates that all users can access and utilize all functionalities within the tokenfactory module.

According to the information provided in x/tokenfactory/README.md, the tokenfactory module allows any account to create a new token. Once a token is created, the original creator automatically gains "admin" rights over the asset. This means that regular users can perform any actions within this module.
