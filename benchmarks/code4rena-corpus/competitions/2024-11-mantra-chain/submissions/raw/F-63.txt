Oracle will fail to post prices to Mantrachain due to missing vote extensions enable height
crypticdefense
39
Sufficient
383d ago
Finding description and impact

Mantrachain currently registers the skip-mev connect oracle within the application:

app.go#L144-L146

	oracle "github.com/skip-mev/connect/v2/x/oracle"
	oraclekeeper "github.com/skip-mev/connect/v2/x/oracle/keeper"
	oracletypes "github.com/skip-mev/connect/v2/x/oracle/types"

app.go#L585-L590

	oracleKeeper := oraclekeeper.NewKeeper(runtime.NewKVStoreService(keys[oracletypes.StoreKey]),
		appCodec,
		app.MarketMapKeeper,
		authtypes.NewModuleAddress(govtypes.ModuleName))
	app.OracleKeeper = &oracleKeeper
	oracleModule := oracle.NewAppModule(appCodec, *app.OracleKeeper)

Both Cosmos sdk and Connect docs explain that Vote Extension (enable height) must be enabled for the oracle to post prices to the chain, otherwise the oracle usage will fail. Users and validators will not be able to confirm the price of off-chain assets, which contradicts the purpose of the Mantrachain project (tokenization and trading of real-world assets). Users can simply use any price to tokenize real-world assets and trade them at unfair prices, which will result in less participation overall and defeat the core purpose of Mantrachain if no oracle is utilized.

Proof of Concept

There a few ways to enable vote extensions so that connect oracle will begin to read prices from that block height, such as setting the consensus parameter in init chainer within app.go:

    consensusParams.Params.Abci = &types.ABCIParams{
            VoteExtensionsEnableHeight: 5, // must be greater than 1
    }

Connect docs give more examples here.

Currently, Mantrachain does not configure this, thus Connect will not be able to post prices to the chain (as explained in the documentation linked).

Despite registering the oracle module in the application, Mantrachain will not be able to properly utilize this.

Coded PoC:

After following the steps in the contest page on how to run tests, proceed to execute the following command:

make build-and-run-single-node

While the node is running, open another terminal and run the following command:

./build/mantrachaind query consensus params --node http://127.0.0.1:26657

This will query the consensus parameters, and display the following output:

params:
  abci: {}
  block:
    max_bytes: "22020096"
    max_gas: "-1"
  evidence:
    max_age_duration: 48h0m0s
    max_age_num_blocks: "100000"
    max_bytes: "1048576"
  validator:
    pub_key_types:
    - ed25519
  version: {}

We can see that vote_extensions_enable_height is non-existent. I compared with this Neutron Network, which uses the same oracle as Mantrachain, and ran the same commands above. The following output was displayed:

params:
  abci:
    vote_extensions_enable_height: "1"
  block:
    max_bytes: "22020096"
    max_gas: "1000000000"
  evidence:
    max_age_duration: 48h0m0s
    max_age_num_blocks: "100000"
    max_bytes: "1048576"
  validator:
    pub_key_types:
    - ed25519
  version: {}

We can see in Neutron Network that the vote extension height is correctly enabled, as required by the Connect oracle. (As a side note the connect oracle is a major feature of the Neutron Network, where Mantrachain has forked the same tokenfactory module. Here is further proof that Mantrachain intend to use a working version of this oracle).

Recommended mitigation steps

Follow the Connect documentation to enable vote extension and specify the height in which connect oracle will begin to read prices.
