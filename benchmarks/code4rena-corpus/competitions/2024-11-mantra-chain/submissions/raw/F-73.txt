Genesis Export Validation Failure Due to Incomplete Field Initialization in the TokenFactory Module
gxh191
00
Sufficient
383d ago

I have decided to escalate this vulnerability to High severity instead of Medium because the inability to restart the chain in other projects is considered Critical.

The primary function of createDenomAfterValidation is to execute the logic for creating a denom after completing the fee and denom validation. This function is designed to be used as the second function during the genesis initialization process.

However, while creating the Metadata, not all required fields are being set properly.

https://github.com/code-423n4/2024-11-mantra/blob/main/x/tokenfactory/keeper/createdenom.go#L33

func (k Keeper) createDenomAfterValidation(ctx sdk.Context, creatorAddr, denom string) (err error) {
	_, exists := k.bankKeeper.GetDenomMetaData(ctx, denom)
	if !exists {
		denomMetaData := banktypes.Metadata{ // <------------
			DenomUnits: []*banktypes.DenomUnit{{
				Denom:    denom,
				Exponent: 0,
			}},
			Base: denom,
		}

		k.bankKeeper.SetDenomMetaData(ctx, denomMetaData)
	}

	// Other logic

	return nil
}

The Metadata structure is as follows. For instance, the Name field is not being set:

https://github.com/cosmos/cosmos-sdk/blob/v0.50.10/x/bank/types/bank.pb.go#L347

// Metadata represents a struct that describes
// a basic token.
type Metadata struct {
	Description string `protobuf:"bytes,1,opt,name=description,proto3" json:"description,omitempty"`
	// denom_units represents the list of DenomUnit's for a given coin
	DenomUnits []*DenomUnit `protobuf:"bytes,2,rep,name=denom_units,json=denomUnits,proto3" json:"denom_units,omitempty"`
	// base represents the base denom (should be the DenomUnit with exponent = 0).
	Base string `protobuf:"bytes,3,opt,name=base,proto3" json:"base,omitempty"`
	// display indicates the suggested denom that should be
	// displayed in clients.
	Display string `protobuf:"bytes,4,opt,name=display,proto3" json:"display,omitempty"`
	// name defines the name of the token (eg: Cosmos Atom)
	//
	// Since: cosmos-sdk 0.43
	Name string `protobuf:"bytes,5,opt,name=name,proto3" json:"name,omitempty"`
	// symbol is the token symbol usually shown on exchanges (eg: ATOM). This can
	// be the same as the display.
	//
	// Since: cosmos-sdk 0.43
	Symbol string `protobuf:"bytes,6,opt,name=symbol,proto3" json:"symbol,omitempty"`
	// URI to a document (on or off-chain) that contains additional information. Optional.
	//
	// Since: cosmos-sdk 0.46
	URI string `protobuf:"bytes,7,opt,name=uri,proto3" json:"uri,omitempty"`
	// URIHash is a sha256 hash of a document pointed by URI. It's used to verify that
	// the document didn't change. Optional.
	//
	// Since: cosmos-sdk 0.46
	URIHash string `protobuf:"bytes,8,opt,name=uri_hash,json=uriHash,proto3" json:"uri_hash,omitempty"`
}


This omission causes the genesis export validation to fail, rendering genesis.json unusable. When the chain encounters a severe interruption, it requires a fix and a restart, which leads to the unexpected loss of all states, making the chain unrestartable.

Impact

When the chain encounters a severe interruption, it requires a fix and a restart. This leads to the unexpected loss of all states, making the chain unrestartable.

1. Hindrances to Genesis File Export and Import
Genesis File Export Failure: Due to the missing critical metadata fields, the mantrachaind export command fails to generate a valid Genesis file, causing the export process to terminate with validation errors.
Genesis File Import Failure: Even if a partial Genesis file is exported, attempting to import it on a new node will fail due to the missing metadata fields, preventing the node from starting and disrupting the chain's normal operation or upgrade process.
2. Token Display and Identification Issues
Wallet and Block Explorer Display Errors: The absence of the name and symbol fields will cause wallets, block explorers, and other frontend applications to display incorrect or incomplete token information. This will make it difficult for users to identify and distinguish between different tokens.
Deteriorated User Experience: Users may experience confusion or make mistakes during transactions or asset management due to incomplete or misrepresented token information. This impacts the overall user experience and could potentially cause trust issues.
3. Increased Complexity in Chain Upgrades and Maintenance
Obstacles to Upgrades: The failure to validate the Genesis file prevents any upgrades or migration operations involving Genesis files from being carried out, thereby increasing the complexity of maintenance and upgrades.
High Error Fixing Costs: If incomplete token metadata persists on-chain, the repair process may require complex data migrations and on-chain state modifications, which increases both the technical and time costs.
Proof of Concept

Initialize the Node

mantrachaind init gxh191 --chain-id mantra-1

Set Minimum Gas Price

sed -i.bak -e "s/^minimum-gas-prices *=.*/minimum-gas-prices = \"0.001stake\"/g" ~/.mantrachain/config/app.toml

Enable API Module

sed -i.bak '/\[api\]/,+3 s/enable = false/enable = true/' ~/.mantrachain/config/app.toml

Add Validator Key

mantrachaind keys add validator

Configure Validator Account

mantrachaind genesis add-genesis-account validator 1000000000stake

Generate Validator Transaction (gentx)

mantrachaind genesis gentx validator 100000000stake --chain-id mantra-1

Collect gentx and Generate Final Genesis File

mantrachaind genesis collect-gentxs

Validate Genesis File

mantrachaind genesis validate

Start Node

mantrachaind start

Create New Denom

mantrachaind tx tokenfactory create-denom mytoken1 --from validator --fees 200000stake --chain-id mantra-1

At this point, stop mantrachaind to prepare for exporting the Genesis file.

Export Genesis File

mantrachaind export --home /Users/gxh/.mantrachain --output-document genesis.json

Validate Exported Genesis File

Validate the exported Genesis file's integrity. Since the Denom "mytoken1" is missing the name field, an error is expected:

mantrachaind genesis validate-genesis ./genesis.json
Fix Recommendation

To resolve the issue, simply initialize the missing fields in the Metadata structure.
