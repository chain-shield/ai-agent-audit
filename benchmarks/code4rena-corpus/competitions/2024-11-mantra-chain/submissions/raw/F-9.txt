Unhandled panics in Tax Module Genesis and GRPC Operations bricks Mantra
Bauchibred
27
Sufficient
383d ago
Finding Description and Impact

The tax module's InitGenesis, ExportGenesis, and RegisterGRPCGatewayRoutes functions use unhandled panics for error handling. This is particularly dangerous as these panics cannot be recovered by standard error handling mechanisms, potentially leading to chain halts or service disruptions.

The use of MustUnmarshalJSON and direct panics in critical chain operations like genesis initialization creates significant reliability risks, especially during chain upgrades or network restarts.

Proof of Concept

Take a look at https://github.com/code-423n4/2024-11-mantra/blob/37dedf312c3ea161792b8e1278978db23bb5a8b0/x/tax/module/module.go#L118-L127

func (am AppModule) InitGenesis(ctx sdk.Context, cdc codec.JSONCodec, gs json.RawMessage) {
    var genState types.GenesisState
    // Critical: Uses MustUnmarshalJSON which panics on error
    cdc.MustUnmarshalJSON(gs, &genState)

    if err := InitGenesis(ctx, am.keeper, genState); err != nil {
        // @audit no error handling
        panic(err)
    }
}

func (am AppModule) ExportGenesis(ctx sdk.Context, cdc codec.JSONCodec) json.RawMessage {
    genState, err := ExportGenesis(ctx, am.keeper)
    if err != nil {
        // @audit no error handling
        panic(err)
    }
    return cdc.MustMarshalJSON(genState)
}

func (AppModuleBasic) RegisterGRPCGatewayRoutes(clientCtx client.Context, mux *runtime.ServeMux) {
    if err := types.RegisterQueryHandlerClient(context.Background(), mux, types.NewQueryClient(clientCtx)); err != nil {
        // @audit no error handling
        panic(err)
    }
}

The use of panic in these critical functions means that:

Genesis operations can fail catastrophically without proper error recovery
GRPC service registration failures can bring down the entire node
Export operations for chain upgrades or state export can fail without graceful degradation
Impact

With go codebases we should be having graceful error handling in place, considering panicking easily causes for case like a chain halt, considering one of the functionalities is when initing the genesis state.

Also export genesis panics could disrupt planned network upgrades.

Recommended Mitigation Steps

Gracefully handle errors and provide error recovery mechanisms, pseudo code could be:

For InitGenesis:
func (am AppModule) InitGenesis(ctx sdk.Context, cdc codec.JSONCodec, gs json.RawMessage) error {
    var genState types.GenesisState
    if err := cdc.UnmarshalJSON(gs, &genState); err != nil {
        return fmt.Errorf("failed to unmarshal genesis state: %w", err)
    }

    if err := InitGenesis(ctx, am.keeper, genState); err != nil {
        return fmt.Errorf("failed to initialize genesis state: %w", err)
    }
    return nil
}
For ExportGenesis:
func (am AppModule) ExportGenesis(ctx sdk.Context, cdc codec.JSONCodec) (json.RawMessage, error) {
    genState, err := ExportGenesis(ctx, am.keeper)
    if err != nil {
        return nil, fmt.Errorf("failed to export genesis state: %w", err)
    }

    bz, err := cdc.MarshalJSON(genState)
    if err != nil {
        return nil, fmt.Errorf("failed to marshal genesis state: %w", err)
    }
    return bz, nil
}
For GRPC Registration:
func (AppModuleBasic) RegisterGRPCGatewayRoutes(clientCtx client.Context, mux *runtime.ServeMux) error {
    if err := types.RegisterQueryHandlerClient(context.Background(), mux, types.NewQueryClient(clientCtx)); err != nil {
        return fmt.Errorf("failed to register grpc gateway routes: %w", err)
    }
    return nil
}
