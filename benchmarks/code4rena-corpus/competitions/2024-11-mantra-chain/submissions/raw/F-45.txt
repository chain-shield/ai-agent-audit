Permanent freezing of escrowed fees due to post-handler execution failure
OakSecurity
00
Sufficient
383d ago
Description

The post-handler is designed to refund excessive fees escrowed during the ante-handler phase. While this mechanism works under normal circumstances, an issue arises when the transaction’s gas consumption reaches the maxUtilization limit. In such cases, the post-handler returns an error, and the escrowed fees are not refunded.

This issue arises due to how the Cosmos SDK’s BaseApp manages state commits across different transaction phases. Specifically:

Fee deduction in ante-handler:

During the ante-handler phase, fees are deducted and written to the cacheContext. After this phase, a new cacheContext is created for runTxMsg and the post-handler.

State Commit behavior in post-handler:

The BaseApp only commits the latest cacheContext if all phases, including the post-handler, execute successfully. If the post-handler returns an error, the cacheContext created for runTxMsg and the post-handler is discarded (state is not committed). As a result, the state after the ante-handler persists, meaning the excessive fees escrowed during the ante-handler phase are retained, but any refund logic in the post-handler is not applied.

Example Scenario
The system is configured with default maxBlockUtilization set to 30M and maxBlockGas set to 100M.
The transactions in the block have already consumed 29M gas.
A new transaction arrives with a gasLimit of 2M, and the 2M fee is escrowed during the ante-handler phase.
The new transaction begins execution and consumes 2M gas during the runMsgTx phase.
After consuming 2M gas, the post-handler is executed.
During the post-handler, an error occurs at the state.Update step because the total gas consumption exceeds the maxUtilization threshold (30M).

Side Note: Even if the maxBlockUtilization and maxBlockGas were set to the same value, runMsgTx would return an error (because the block’s gas meter is out of gas). The post-handler would still run and would also error out due to the gasConsumed exceeding the maxUtilization.

Impact

The impact is that users typically attach excessive gas fees due to the challenges in accurately estimating gas consumption in Cosmos-based systems. If the post-handler fails, these excessive fees are not refunded, causing the user’s escrowed funds to remain unreversed (intended design: refund the excessive gas).

Proof of Concept

This proof of concept demonstrates the “excessive fee is not returned if the postHandler fails”.

Setup and Calibration

Before starting the POC, we will run the chain with the default parameters and send a token creation transaction to observe the gas consumption. Based on the observed gas usage, we will adjust the maxBlockUtilization parameter in the genesis.json file to simulate a scenario where the block is near full utilization.

Run the chain with default parameters:
Send a token creation transaction and observe gas consumption.
Based on the observed gas consumption, adjust the maxBlockUtilization value (eg: 92997) in the genesis.json file to simulate the block reaching its utilization limit.
Modify the genesis.json file:
Update the maxBlockUtilization parameter according to the observed gas usage.
Proof of Concept Steps

The following steps guide the execution of the proof of concept once the calibration is done.

Add the following contents to Makefile:

poc:
	@echo "starting POC..."

	# clear port 26657 if old process still running
	@if lsof -i :26657; then \
		kill -9 $$(lsof -t -i :26657) || echo "cannot kill process"; \
	fi

	# remove old setup and init new one
	@rm -rf .mantrapoc
	@mkdir -p .mantrapoc

	# Initialize the chain
	./build/mantrachaind init poc-test --chain-id test-chain --home .mantrapoc

	# Add validator and validator2 keys
	./build/mantrachaind keys add validator --keyring-backend test --home .mantrapoc
	./build/mantrachaind keys add validator2 --keyring-backend test --home .mantrapoc

	# Create alice and bob account
	./build/mantrachaind keys add alice --keyring-backend test --home .mantrapoc
	./build/mantrachaind keys add bob --keyring-backend test --home .mantrapoc

	# Add genesis accounts for validator, validator2, alice, and bob
	./build/mantrachaind genesis add-genesis-account $$(./build/mantrachaind keys show validator -a --keyring-backend test --home .mantrapoc) 500000000000stake --home .mantrapoc
	./build/mantrachaind genesis add-genesis-account $$(./build/mantrachaind keys show validator2 -a --keyring-backend test --home .mantrapoc) 500000000000stake --home .mantrapoc
	./build/mantrachaind genesis add-genesis-account $$(./build/mantrachaind keys show alice -a --keyring-backend test --home .mantrapoc) 500000000000stake --home .mantrapoc
	./build/mantrachaind genesis add-genesis-account $$(./build/mantrachaind keys show bob -a --keyring-backend test --home .mantrapoc) 500000000000stake --home .mantrapoc

	# Generate gentx for validator
	./build/mantrachaind genesis gentx validator 100000000stake --chain-id test-chain --keyring-backend test --home .mantrapoc

	# Collect gentxs
	./build/mantrachaind genesis collect-gentxs --home .mantrapoc

	# Modify genesis.json to set max_block_utilization to 3 using jq
	@echo "Setting max_block_utilization to 92997(gas required for tx tokenfactory create-denom) in genesis.json"
	jq '.app_state.feemarket.params.max_block_utilization = 92997' .mantrapoc/config/genesis.json > .mantrapoc/config/genesis_tmp.json; \
	mv .mantrapoc/config/genesis_tmp.json .mantrapoc/config/genesis.json

	# Start the chain
	./build/mantrachaind start --home .mantrapoc --minimum-gas-prices 0stake


Create the poc.sh file: The shell script is used to adjust the maxBlockUtilization parameter and run the proof of concept.

#!/bin/bash

# Set variables
export ALICE=`./build/mantrachaind keys show alice --keyring-backend test --home .mantrapoc -a`
export BOB=`./build/mantrachaind keys show bob --keyring-backend test --home .mantrapoc -a`
export VAL_BECH32=`./build/mantrachaind keys show validator --keyring-backend test --home .mantrapoc -a`

# Get the denom for the `reta` token
export DENOM="reta2"
export NATIVE_DENOM="stake"

# Step 1: Check Alice's balance before token creation
echo "Checking Alice's balance before creating $DENOM token..."
BALANCE_BEFORE=$(./build/mantrachaind q bank balance $ALICE $NATIVE_DENOM --home .mantrapoc)

echo "Balance before: $BALANCE_BEFORE"

# Step 2: Create the `reta` token using tokenfactory
echo "Creating $DENOM token from Alice with excessive fee..."
TX_RESPONSE=$(
  ./build/mantrachaind tx tokenfactory create-denom $DENOM --from alice --keyring-backend test --home .mantrapoc --chain-id test-chain -y --fees 4000001stake --gas 2000000 --output json
)

# Extract the transaction fee from the response (if any)
TX_FEE=$(echo $TX_RESPONSE | jq -r '.fee.amount[0].amount')

echo "Transaction fee consumed: $TX_FEE"
sleep 2

# Step 3: Check Alice's balance after token creation
echo "Checking Alice's balance after creating $DENOM token..."
BALANCE_AFTER=$(./build/mantrachaind q bank balance $ALICE $NATIVE_DENOM --home .mantrapoc)

echo "Balance after: $BALANCE_AFTER"

# 92997 (gas consumption)
