# Vulnerability details

## Proof of Concept

When we update the tick based on amount of `liquidityDelta`, there is a vulnerability of underflow.
(line 108-110)

```
92    function update(
        ...
104    ) internal returns (bool flipped) {
           ...

107        uint128 liquidityGrossBefore = info.liquidityGross;
108        uint128 liquidityGrossAfter = liquidityDelta < 0
109            ? liquidityGrossBefore - uint128(-liquidityDelta)
110            : liquidityGrossBefore + uint128(liquidityDelta);
111
112        if (liquidityGrossAfter > maxLiquidity) revert LO();
```

Since the current `Tick.sol` library doesn't have a validation part, the `liquidityGrossAfter` can be updated wrongly and it can lead wrong tick value.
For example when owner tries to burn tokens more than he minted or before mint, underflow might occur and the owner can gain more tokens.

## Recommended Mitigation Steps
We can add validation code before we update tick. (Tick.sol / line 108)
```
if(liquidityDelta < 0 && liquidityGrossBefore < uint128(-liquidityDelta)) revert ExceedLiquidityGross;
if(liquidityDelta > 0 && liquidityGrossBefore > type(uint128).max - uint128(liquidityDelta)) revert ExceedLiquidityGross;
```
