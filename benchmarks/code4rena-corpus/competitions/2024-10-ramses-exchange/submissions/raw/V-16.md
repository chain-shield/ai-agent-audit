# Vulnerability details

## Proof of Concept

At the moment `periodSecondsInsideX96` is calculated using `liquidity` value:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/core/libraries/Position.sol#L261
```
periodSecondsInsideX96 = FullMath.mulDiv(liquidity, secondsPerLiquidityInsideX128, FixedPoint32.Q32);
```

This results in a situation where time related value is derived in relation to the quantity value that will lead to a mistaken value being obtained. It's later compared to 1 week:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/core/libraries/Position.sol#L273-275
```
 if (periodSecondsInsideX96 > 1 weeks * FixedPoint96.Q96) {
            periodSecondsInsideX96 = 0;
        }
```

As the value is dependent on the `liquidity`, it will potentially be always bigger than `1 weeks * FixedPoint96.Q96` eventually ending up nullified.

## Recommended Mitigation Steps

Don't use `liquidity` parameter to calculate period seconds inside X96.
