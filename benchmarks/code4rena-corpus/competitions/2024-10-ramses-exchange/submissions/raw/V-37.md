# Vulnerability details

## Summary
The [left()](https://github.com/code-423n4/2024-10-ramses-exchange-test-coverage/blob/9da1c98ab902b2dbcb1e121542de28022099b1e7/contracts/CL/gauge/GaugeV3.sol#L114) function in GaugeV3.sol will always return the full `tokenTotalSupplyByPeriod`. The issue occurs since the `remainingTime` variable calculation is incorrect and will always return 1 WEEK.

Due to this, since the left() function is utilized in the Voter.sol contract's [_distribute()](https://github.com/code-423n4/2024-10-ramses-exchange-test-coverage/blob/9da1c98ab902b2dbcb1e121542de28022099b1e7/contracts/Voter.sol#L819) function, the distribution logic executed would be incorrect.

## Proof of Concept
Let's understand the issue and impact here:

1. Let's say a call arrives from the Voter.sol's internal _distribute() function to the left() function. In the left() function below, let's substitute `period` in `remainingTime`, which leads to:
 - `remainingTime = ((_blockTimestamp() / WEEK + 1) * WEEK) - _blockTimestamp()`
 - Taking LCM in the innermost brackets
 - `remainingTime = (_blockTimestamp() + WEEK / WEEK) * WEEK - _blockTimestamp()`
 - Cancel out WEEK from the denominator and numerator
 - `remainingTime = _blockTimestamp() + WEEK - _blockTimestamp()`
 - `remainingTime = WEEK`
```solidity
    function left(address token) external view override returns (uint256) {
        uint256 period = _blockTimestamp() / WEEK;
        uint256 remainingTime = ((period + 1) * WEEK) - _blockTimestamp();
        return (tokenTotalSupplyByPeriod[period][token] * remainingTime) / WEEK;
    }
```

2. Since `remainingTime` is always a WEEK, the returned value would always be the full tokenTotalSupplyByPeriod in that period.

3. Due to this, when the amount is returned to the _distribute() function in Voter.sol, the distribution might be incorrect. What I mean by this is that:
 - If `_claimable` is 9e18 and the amount returned from left() is 10e18 even after we've passed halfway through the period (i.e. when the amount returned should've actually been 10e18/2 = 5e18), the `canDistribute` would be set to false always in such a scenario and the amount won't be distributed.

```solidity
           if (_claimable > 0) {
                if (
                    _claimable / DURATION == 0 ||
                    _claimable < IGauge(_gauge).left(emissionsToken) //@audit here
                ) {
                    canDistribute = false;
                }
            }
```


## Recommended Mitigation Steps
Implement `block.timestamp - currentPeriodStart * WEEK`. In this case, we will need to track a new storage variable currentPeriodStart. Note that in this case, the amount returned would be increasing as the period passes, so we need to subtract the amount we get from `tokenTotalSupplyByPeriod` as shown below. 

````solidity
    function left(address token) external view override returns (uint256) {
        uint256 remainingTime = block.timestamp - currentPeriodStart * WEEK;
        return tokenTotalSupplyByPeriod[period][token] - ((tokenTotalSupplyByPeriod[period][token] * remainingTime) / WEEK);
    }
````
