# Vulnerability details

## Proof of Concept

Currently `_getAllRewards()` functionality is used to calculate the rewards for all the missed epochs (until the current one). The problem lies in a way of how the `lastClaimByToken` value is updated:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L514-530
```
  for (
                uint256 period = lastClaim;
                period <= currentPeriod;
                ++period
            ) {
                _getReward(
                    period,
                    tokens[i],
                    owner,
                    index,
                    tickLower,
                    tickUpper,
                    _positionHash,
                    receiver
                );
            }
            lastClaimByToken[tokens[i]][_positionHash] = currentPeriod - 1;

```

The loop stops when the period > current period meaning the users can claim rewards for the current period as well. But the `lastClaimByToken` value is updated to the period that was before the current one resulting in a situation where users can claim rewards in the current period but this period will not be marked as claimed. The amounts are not written for the current epoch as well:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L311-316
```
  if (period < _blockTimestamp() / WEEK && caching) {
                periodAmountsWritten[period][_positionHash] = true;
                periodNfpSecondsX96[period][
                    _positionHash
                ] = periodSecondsInsideX96;
            }
```

## Recommended Mitigation Steps

Update the value `lastClaimByToken` so it reflects the correct period value.
