# Vulnerability details

## Proof of Concept
 Re-entrancy Concerns in Pool Creation: The createPool function interacts with IRamsesV3PoolDeployer and potentially IRamsesV3Pool during pool creation, which could enable re-entrancy attacks if either external contract is compromised.

Impact: A re-entrancy attack could manipulate the pool creation process, possibly allowing an attacker to drain or modify liquidity. This could lead to severe financial loss and compromise the integrity of all pools managed by this factory.

## Recommended Mitigation Steps
Use the checks-effects-interactions pattern and nonReentrant modifier to prevent re-entrancy. Ensure that any external call happens only after necessary internal state changes are applied.
example:
function createPool(...) external override nonReentrant { ... }
