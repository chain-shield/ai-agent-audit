# Vulnerability details

## Proof of Concept
Lack of Complete Access Control: Several functions in the contract (e.g., setTreasury, setTreasuryFees, setIsLive) rely on the onlyTreasury modifier, which restricts their access to the treasury address. However, there is no mechanism to ensure that this address is managed securely, such as by a multi-signature wallet, leaving control vulnerable if a single private key is compromised.
An attacker with access to the treasury address can invoke restricted functions and change contract parameters. For instance, they could set arbitrary treasury fees to siphon off funds:
// Attacker code snippet
feeCollector.setTreasuryFees(10000); // Set fees to 100% of collected funds

Impact: If the treasury account’s private key is compromised, a malicious actor could change the treasury fees, redirect funds, or alter contract states (e.g., isTokenLive), disrupting protocol revenue streams and potentially resulting in significant financial loss.

## Recommended Mitigation Steps
1. Use a multi-signature wallet (e.g., Gnosis Safe) for the treasury address to ensure that any change requires multiple approvals.
2. Add an emergency pause mechanism to disable sensitive functions if the treasury address is compromised.
