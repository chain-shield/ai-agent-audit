### Impact
The swap function in RamsesV3Pool.sol lacks the lock modifier. 
Which is used throughout the contract to provide access control protection. 
Without this modifier, the function is vulnerable to swap calls by a malicious hacker.

The function should never be successfully called in the first place.

	RamsesV3Pool public ramsesv3pool;

    function setUp() public {
     	ramsesv3pool = RamsesV3Pool(address(ramsesv3pool));
     	vm.deal(address(ramsesv3pool), 10 ether);
    }
    
    // @Debo Swap should have access control lock.
    function testSwap() external {
    	vm.startPrank(address(0xbEEF));
    	address recipient = address(0xbEEF);
        bool zeroForOne = bool(true);
        int256 amountSpecified = int256(1);
        uint160 sqrtPriceLimitX96 = uint160(1);
        bytes memory data = bytes("0x1");
        ramsesv3pool.swap(
        	recipient,
        	zeroForOne,
        	amountSpecified,
        	sqrtPriceLimitX96,
        	data
    		);
    	vm.stopPrank(); 
        }
    	
}

## Recommended Mitigation Steps
Add the lock modifier to the swap function to enforce reentrancy protection, as is done with other state-changing functions in the contract.
### Updated Code with Mitigation
```Solidity
function swap(
    address recipient,
    bool zeroForOne,
    int256 amountSpecified,
    uint160 sqrtPriceLimitX96,
    bytes calldata data
) external override lock returns (int256 amount0, int256 amount1) {
    // Function body with lock modifier for reentrancy protection
}
```
By adding the lock modifier, the function will now be protected against malicious swap calls.
