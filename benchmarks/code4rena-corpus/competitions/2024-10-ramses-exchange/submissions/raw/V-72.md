# Vulnerability details

** Description**:
The `swap` function in the RamsesV3Pool contract allows users to perform token swaps without explicitly specifying a minimum amount of tokens they expect to receive. While the function does include a `sqrtPriceLimitX96` parameter, which provides some price protection, it doesn't directly translate to a minimum output amount, which is what most users would expect for slippage protection.

**Vulnerable Code**:
```solidity
function swap(
    address recipient,
    bool zeroForOne,
    int256 amountSpecified,
    uint160 sqrtPriceX96,
    bytes calldata data
) external override returns (int256 amount0, int256 amount1) {
    // ... (swap logic)
    if (zeroForOne) {
        if (amount1 < 0) TransferHelper.safeTransfer(token1, recipient, uint256(-amount1));
    } else {
        if (amount0 < 0) TransferHelper.safeTransfer(token0, recipient, uint256(-amount0));
    }
    // ... (more logic)
}
```

**Impact**:
1. In volatile market conditions, users might receive significantly fewer tokens than expected.
2. This could lead to substantial financial losses, especially for large trades.
3. It makes the pool vulnerable to MEV (Miner Extractable Value) attacks, where miners or other actors could manipulate the transaction order to the detriment of users.

** Recommendation**:
 Add a `minAmountOut` parameter to the `swap` function and Implement a check before finalizing the swap
