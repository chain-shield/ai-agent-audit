# Vulnerability details

## Proof of Concept

The initializeSecondsStart function lacks access control, allowing it to be called multiple times or by unauthorized users. This function is intended to be executed only once during the initialization phase of a contract.

**Impact** 
If called multiple times, this can lead to state corruption, as it may reset or incorrectly modify state variables, resulting in unintended contract behavior. Additionally, unauthorized users could manipulate the contract state, leading to potential loss of funds or exploitative behavior.

**Attack Scenario**
An attacker can repeatedly call the initializeSecondsStart function, altering the state of the PositionInfo struct and potentially causing financial discrepancies.
 
## Recommended Mitigation Steps

Add an access control modifier to the initializeSecondsStart function, such as:
* OnlyOwner Modifier: Restrict access to the contract owner or designated admin.
* Initialized Check: Use a boolean flag to ensure the function can only be executed once.
