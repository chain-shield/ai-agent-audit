# Vulnerability details

## Description

The current implementation in the `NonfungiblePositionManager` contract has a critical issue that can potentially block users from exiting their positions. This problem stems from the discrepancy between actual collected amounts and recorded amounts in the `collect` function, which directly impacts the `burn` function.

## Code Snippet

```solidity
function collect(
    CollectParams calldata params
) external payable override isAuthorizedForToken(params.tokenId) returns (uint256 amount0, uint256 amount1) {
    // ... (earlier part of the function)

    (amount0, amount1) = pool.collect(
        recipient,
        params.tokenId,
        position.tickLower,
        position.tickUpper,
        amount0Collect,
        amount1Collect
    );

    unchecked {
        (position.tokensOwed0, position.tokensOwed1) = (tokensOwed0 - amount0Collect, tokensOwed1 - amount1Collect);
    }

    // ...
}
```

The contract subtracts the expected amount (`amount0Collect`, `amount1Collect`) instead of the actual collected amount (`amount0`, `amount1`). This can lead to a situation where `position.tokensOwed0` or `position.tokensOwed1` never reach zero due to rounding errors.


Now, let's look at the `burn` function:

```solidity
function burn(uint256 tokenId) external payable override isAuthorizedForToken(tokenId) {
    Position storage position = _positions[tokenId];
    if (position.liquidity > 0 || position.tokensOwed0 > 0 || position.tokensOwed1 > 0) revert NotCleared();
    delete _positions[tokenId];
    _burn(tokenId);
}
```

The critical line is:

```solidity
if (position.liquidity > 0 || position.tokensOwed0 > 0 || position.tokensOwed1 > 0) revert NotCleared();
```

This check ensures that a position can only be burned if it has no liquidity and no tokens owed. However, due to the accounting issue in `collect`, `tokensOwed0` or `tokensOwed1` might never reach zero, even if all actual fees have been collected.

## poc

```solidity
contract PositionExitSimulator {
    struct Position {
        uint128 liquidity;
        uint128 tokensOwed0;
        uint128 tokensOwed1;
    }

    mapping(uint256 => Position) public positions;

    function simulateCollect(uint256 tokenId, uint128 amount0Collect, uint128 amount1Collect) public {
        Position storage position = positions[tokenId];

        // Simulate core contract returning slightly less due to rounding
        uint256 actualCollected0 = amount0Collect > 0 ? amount0Collect - 1 : 0;
        uint256 actualCollected1 = amount1Collect > 0 ? amount1Collect - 1 : 0;

        // Problematic update
        position.tokensOwed0 -= amount0Collect;
        position.tokensOwed1 -= amount1Collect;

        // Actual tokens collected (not used in update)
        emit Collect(tokenId, actualCollected0, actualCollected1);
    }

    function simulateBurn(uint256 tokenId) public {
        Position storage position = positions[tokenId];
        require(position.liquidity == 0 && position.tokensOwed0 == 0 && position.tokensOwed1 == 0, "Position not cleared");
        delete positions[tokenId];
        emit Burn(tokenId);
    }

    event Collect(uint256 tokenId, uint256 amount0, uint256 amount1);
    event Burn(uint256 tokenId);
}
```

## Scenario:

```solidity
PositionExitSimulator simulator = new PositionExitSimulator();

// Set initial state
simulator.positions(1) = Position(0, 100, 100);  // No liquidity, but some fees owed

// User tries to collect all fees
simulator.simulateCollect(1, 100, 100);
// Actual collected: 99, 99
// Position state after: tokensOwed0 = 0, tokensOwed1 = 0 (but should be 1, 1)

// User tries to burn the position
simulator.simulateBurn(1);  // This will succeed, but it shouldn't

// In the real contract, the position would still have tokensOwed0 = 1, tokensOwed1 = 1
// So the burn operation would fail with "Position not cleared" error
```

## Impact

- Users may be unable to burn their positions even after they believe they've collected all their fees.
- This could lead to "stuck" positions, where users can't exit or redeploy their capital.
- It may cause confusion and frustration among users who can't understand why they can't close their positions.

## Fix

Update the `collect` function to use the actual collected amounts:

```solidity
unchecked {
    (position.tokensOwed0, position.tokensOwed1) = (tokensOwed0 - uint128(amount0), tokensOwed1 - uint128(amount1));
}
```

This change ensures that the contract's internal state accurately reflects the actual collected amounts, allowing users to fully exit their positions when all fees have been collected.

By addressing this issue, we remove a potential blocker that could prevent users from exiting their positions, ensuring a smoother and more predictable user experience in the protocol.
