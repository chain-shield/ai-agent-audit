# Vulnerability details

## Impact
The [setPoolFeeProtocolBatch](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L137-L146) function in the smart contract fails to validate the addresses provided in the pools array. This oversight can lead to denial of service (DoS) attacks, where an attacker can cause legitimate transactions to revert by including invalid addresses, preventing users from successfully updating the fee protocols for their pools.

There two clear issues here;

1. Transaction Reversion: Any invalid address in the pools array will cause the entire transaction to revert. This prevents updates for all pools in that batch, even if most are valid.
2. Exploitation Potential: Malicious actors could intentionally include invalid addresses in batch updates to disrupt service, thereby denying legitimate users the ability to manage their pools effectively.


```solidity
function setPoolFeeProtocolBatch(address[] calldata pools, uint8[] calldata _feeProtocols) external restricted {
        /// @dev AL = Array Length
        require(pools.length == _feeProtocols.length, 'AL');
        for (uint i; i < pools.length; i++) {
            /// @dev fee cannot exceed 100%
            require(_feeProtocols[i] <= 100, FTL());
            uint8 feeProtocolOld = poolFeeProtocol(pools[i]);
            _poolFeeProtocol[pools[i]] = _feeProtocols[i];
            emit SetPoolFeeProtocol(pools[i], feeProtocolOld, _feeProtocols[i] == 0 ? feeProtocol : _feeProtocols[i]);

            IRamsesV3Pool(pools[i]).setFeeProtocol();
        }
    }
```

Scenario
    1. Deploy the contract containing the setPoolFeeProtocolBatch function.
    2. Prepare a list of pool addresses, ensuring that one or more are invalid (e.g., zero address or non-pool contracts).
    3. The transaction begins to execute.
    4. The transaction reverts due to the invalid pool address, preventing the update of fee protocols for valid pools.

## Recommended Mitigation Steps
