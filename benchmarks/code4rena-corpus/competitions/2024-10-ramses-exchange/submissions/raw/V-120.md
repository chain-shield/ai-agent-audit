# Vulnerability details

## Proof of Concept
The `ticks` function in the `RamsesV3Pool` contract lacks validation to ensure that the input `tick` is within the valid range defined by `TickMath.MIN_TICK` and `TickMath.MAX_TICK`. This oversight allows for the possibility of accessing uninitialized or invalid tick data, which can lead to misleading results and potentially erroneous application behavior.
```

        liquidityNet = tickData.liquidityNet;

        feeGrowthOutside1X128 = tickData.feeGrowthOutside1X128;

        secondsPerLiquidityOutsideX128 = tickData.secondsPerLiquidityOutsideX128;

```
Scenario:
1. A user or application calls the `ticks` function with a `tick` value of `1000000`, which is outside the valid range.
2. The function accesses the storage slot corresponding to this invalid tick, which has not been initialized.
3. The function returns default or zero values ​​for all tick-related data, such as `liquidityGross` and `liquidityNet`.
4. Applications relying on this data will incorrectly assume that there is no liquidity at this tick, leading to incorrect decision making or analysis.

## Recommended Mitigation Steps
Implement a validation check to ensure the `tick` parameter is within the valid range before accessing the storage.
```

    int24 tick
) external view override returns (
    uint128 liquidityGross,
    int128 liquidityNet,
```
