# Vulnerability details

Proof of Concept:

An attacker could create a malicious ERC20 token that reverts in specific situations within its transfer function.
They could then use this token to create a pool, providing a sqrtPriceX96 value that triggers the malicious token's revert condition during the initialize call.
This would cause the entire createPool transaction to revert, preventing the pool from being initialized.

Recommended Mitigation:

Careful Pool Implementation: Ensure that the initialize function in the RamsesV3Pool contract is robust and cannot be exploited to cause a DoS. This might involve limiting external calls within initialize or implementing safeguards against malicious tokens.
Consider Asynchronous Initialization: Explore alternative pool initialization mechanisms that don't rely on synchronous calls within createPool. This could involve a separate initialization step triggered by the pool creator or a time-delayed initialization.
