# Vulnerability details

`getReward` function in the GaugeV3 contract has an incorrect access control check that allows non-owners of an NFT position to claim rewards for that position. The function's require statement checks if the caller is either the owner, the approved operator, or an account that has been granted "approved for all" status by the owner: [GaugeV3.sol#L436-L441](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/gauge/GaugeV3.sol#L436-L441)
```solidity
require(
    msg.sender == owner ||
        msg.sender == operator ||
        _nfpManager.isApprovedForAll(owner, msg.sender),
    "Not authorized"
);
```
However, the intended behavior is that only the direct owner of an NFT position should be able to claim rewards for that position. Allowing operators and approved accounts to claim rewards violates this expectation and can lead to unintended distribution of rewards.

This check allows the following accounts to claim rewards for an NFT position:

1. The owner of the NFT
2. The approved operator of the NFT
3. Any account that the owner has set as "approved for all"

However, the `onlyOwnerCanClaim` rule specifies that only the direct owner should be able to claim rewards. Allowing operators and approved accounts to claim is unintended behavior.

## Impact
Owners may lose out on rewards if a non-owner claims the rewards before the owner does.

## Proof of Concept
The bug will occur whenever a non-owner account that is either the approved operator or "approved for all" for an NFT position calls getReward for that position.

While this requires specific access permissions, it's not uncommon for NFT owners to grant operator or "approved for all" status to other accounts (e.g., marketplaces, wallets, etc.). Therefore, the likelihood of this bug being exploited in the wild is relatively high.

Demonstrating the bug
```solidity
// 1. Deploy GaugeV3
GaugeV3 gauge = new GaugeV3(...);

// 2. Mint an NFT position with ID 1 to Alice
INonfungiblePositionManager nfpManager = gauge.nfpManager();
nfpManager.mint(Alice, 1, ...);

// 3. Alice approves Bob as an operator for the NFT
nfpManager.approve(Bob, 1);

// 4. Bob claims rewards for Alice's NFT
address[] memory tokens = new address[](2);
tokens[0] = gauge.token0();
tokens[1] = gauge.token1();
gauge.getReward(1, tokens);

// Bob successfully claims rewards for Alice's NFT, violating the onlyOwnerCanClaim rule
```

## Recommended Mitigation Steps
Update the access control check in the getReward function to only allow the direct owner of an NFT position to claim rewards
```diff
- require(
-     msg.sender == owner ||
-         msg.sender == operator ||
-         _nfpManager.isApprovedForAll(owner, msg.sender),
-     "Not authorized"
- );
+ require(msg.sender == owner, "Only owner can claim");
```
