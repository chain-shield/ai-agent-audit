# Vulnerability details

## Proof of Concept

In the `RamsesV3Pool` contract, the `initialize` function is critical as it sets up the initial state of the pool, including its price and tick parameters. The lack of proper access control mechanisms allows any user to call this function, potentially leading to the manipulation of the pool's state.

**[Code Snippet](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L152-L174):**
```solidity
/// @dev init
function initialize(uint160 sqrtPriceX96) external {
    PoolStorage.PoolState storage $ = PoolStorage.getStorage();

    if ($.slot0.sqrtPriceX96 != 0) revert AI();

    int24 tick = TickMath.getTickAtSqrtRatio(sqrtPriceX96);

    (uint16 cardinality, uint16 cardinalityNext) = Oracle.initialize($.observations, 0);

    _advancePeriod();

    $.slot0 = Slot0({
        sqrtPriceX96: sqrtPriceX96,
        tick: tick,
        observationIndex: 0,
        observationCardinality: cardinality,
        observationCardinalityNext: cardinalityNext,
        feeProtocol: 0,
        unlocked: true
    });

    emit Initialize(sqrtPriceX96, tick);
}
```

#### Impact
The absence of access control allows any malicious actor to call the `initialize` function, effectively resetting the pool with arbitrary parameters. This could lead to significant financial losses for users, as the pool's state would be altered without proper oversight. For instance, a bad actor could set a highly favorable `sqrtPriceX96` to manipulate liquidity positions or exploit price discrepancies.


#### Bug Overview
- **What Causes It**: The `initialize` function is marked as `external`, meaning anyone can call it, regardless of their privileges or intentions.
- **Likelihood of Occurrence**: High, as any user can trigger the function without restrictions.
- **Impact**: Potential financial losses for users due to unauthorized manipulation of the pool's parameters.

## Recommended Mitigation Steps
Implement access control using `onlyOwner` or a more granular ( `initializer` )approach with role-based permissions to restrict access to critical functions. This ensures that only authorized personnel can modify the pool's state, preserving the integrity and security of the contract.
