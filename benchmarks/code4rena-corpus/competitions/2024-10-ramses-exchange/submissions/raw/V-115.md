# Vulnerability details

## Summary
Redundant storage writes and event emissions.

## Proof of Concept
When changing a `feeCollector` account using the `RamsesV3Factory::setFeeCollector` function, no validation has been done to check whether the account we want to add already exists or not. So, if the `feeCollector` already exists, the transaction will continues to process the assignment and charge for storage access and emits the `FeeCollectorChanged` event.  While the gas cost may not be as high as writing a new value, it will still cost gas and emetting event is also a gas-costly operation, as it involves writing logs to the blockchain:
```solidity
    function setFeeCollector(address _feeCollector) external override restricted {
        // @audit lack of existing check
        emit FeeCollectorChanged(feeCollector, _feeCollector);
        feeCollector = _feeCollector;
    }
```

## Recommended Mitigation Steps
```diff
    function setFeeCollector(address _feeCollector) external override restricted {
+       require(feeCollector != _feeCollector, "Already exist!");
        emit FeeCollectorChanged(feeCollector, _feeCollector);
        feeCollector = _feeCollector;
    }
```
