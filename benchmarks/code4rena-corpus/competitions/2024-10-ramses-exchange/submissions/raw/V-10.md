# Vulnerability details

The `notifyRewardAmount` function calculates the current period based on the timestamp at the beginning of the function execution. However, it doesn't recheck this period before adding rewards. If a new weekly period starts during the function's execution, rewards may be incorrectly added to the previous period, leading to inconsistent reward rates.

```solidity
function notifyRewardAmount(
    address token,
    uint256 amount
) external override pushFees lock {
    require(isReward[token], "!Whitelisted");
    IRamsesV3Pool(pool)._advancePeriod();
    // @audit Vuln: period calculation
    uint256 period = _blockTimestamp() / WEEK;

    uint256 balanceBefore = IERC20(token).balanceOf(address(this));
    IERC20(token).safeTransferFrom(msg.sender, address(this), amount);
    uint256 balanceAfter = IERC20(token).balanceOf(address(this));

    amount = balanceAfter - balanceBefore;
    // @audit Vuln: reward addition without rechecking period
    tokenTotalSupplyByPeriod[period][token] += amount;
    emit NotifyReward(msg.sender, token, amount, period);
}
```
## Impact
Can lead to rewards being added to an outdated period, causing inconsistencies in reward distribution and potentially reducing the reward rate for users in the current period.

## Proof of Concept
1. Near the end of a weekly period, call `rewardRate(token)` and store the result.
2. Wait for the weekly period to change.
3. Immediately call `notifyRewardAmount(token, amount)` with a significant amount.
4. Call `rewardRate(token)` again.

_**Expected**_: The new reward rate should be higher than the previous one.
_**Actual**_: The new reward rate might be lower or unchanged, as the rewards were added to the previous period.

## Recommended Mitigation Steps
1. Recalculate the period right before adding the reward
```diff
function notifyRewardAmount(
    address token,
    uint256 amount
) external override pushFees lock {
    require(isReward[token], "!Whitelisted");
    IRamsesV3Pool(pool)._advancePeriod();
-   uint256 period = _blockTimestamp() / WEEK;

    // ... (transfer logic)

+   uint256 period = _blockTimestamp() / WEEK;
    tokenTotalSupplyByPeriod[period][token] += amount;
    emit NotifyReward(msg.sender, token, amount, period);
}
```
2. Implement a mechanism to carry over rewards to the next period if a period change is detected
```diff
function notifyRewardAmount(
    address token,
    uint256 amount
) external override pushFees lock {
    require(isReward[token], "!Whitelisted");
    IRamsesV3Pool(pool)._advancePeriod();
    uint256 initialPeriod = _blockTimestamp() / WEEK;

    // ... (transfer logic)

+   uint256 currentPeriod = _blockTimestamp() / WEEK;
+   if (currentPeriod > initialPeriod) {
+       tokenTotalSupplyByPeriod[currentPeriod][token] += amount;
+   } else {
        tokenTotalSupplyByPeriod[initialPeriod][token] += amount;
+   }
    emit NotifyReward(msg.sender, token, amount, currentPeriod);
}
```
