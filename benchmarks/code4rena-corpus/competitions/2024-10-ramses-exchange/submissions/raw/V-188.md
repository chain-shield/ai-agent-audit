# Vulnerability details

## Proof of Concept

1. Rewards can be notified for the current period using the function [notifyRewardAmount()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L147) and they can be notified for future periods using the functions [notifyRewardAmountNextPeriod()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L165) and [notifyRewardForPeriod](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L182)

2. When a reward is notified, a common state change that occurs in all the three functions is the increment of totalTokenSupplyByPeriod[period][token] by the amount that was notified and transferred.

```solidity
tokenTotalSupplyByPeriod[period][token] += amount;
```

3. When a particular period's token rewards are claimed by the users, the calculation occurs as follows in function [cachePeriodEarned()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L321C1-L325C11), which is used by function [_getPeriodReward()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L534):

```solidity
        amount = FullMath.mulDiv(
            tokenTotalSupplyByPeriod[period][token],
            periodSecondsInsideX96,
            WEEK << 96
        );
```

4. Following this, we transfer it to users in [_getPeriodReward()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L534) as shown below:

```solidity
        uint256 _reward = cachePeriodEarned(
            period,
            token,
            owner,
            index,
            tickLower,
            tickUpper,
            true
        );

        if (_reward > 0) {
            periodClaimedAmount[period][_positionHash][token] += _reward;

            IERC20(token).safeTransfer(receiver, _reward);
            emit ClaimRewards(period, _positionHash, receiver, token, _reward);
        }
```

5. The issue is that although the tokens are transferred out from the contract and the amount of tokens now available for that period and token are lesser, the totalTokenSupplyByPeriod[period][token] still stores the full amount and is not decremented. What could happen due to this is that other users claiming rewards of that specific token in that same period would start tapping into existing past or future periods' allocated rewards stored in the contract. These rewards were notified and transferred into the GaugeV3 contract for the totalTokenSupply of other periods but would now be unintentionally or intentionally stolen by the current period's reward claimants.

## Recommended Mitigation Steps
In function [_getReward()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L534), consider decrementing totalTokenSupplyByPeriod[period][token] under this statement [here](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L555).
