# Vulnerability details

## Proof of Concept
Exposure of Sensitive Information via tokenURI: The tokenURI function reveals metadata about tokens. If this metadata includes sensitive information (like specific transaction histories or positions), it could lead to deanonymization of users or exposure of trading strategies.

Proof of Concept: An attacker could repeatedly query tokenURI to gather details about position ranges, potentially using this information to front-run or game the system.

Impact: Revealing detailed position data could enable front-running, diminishing user returns or revealing user behavior that can be exploited.

## Recommended Mitigation Steps
1. Limit Information in Metadata: Ensure sensitive details, such as specific tick ranges, are not directly exposed in metadata.
2. Implement Access Control for Metadata: Allow only specific, authenticated users to access metadata if it’s essential for position management.

Example Code with Fix
Limit metadata exposure by using controlled access to tokenURI:
function tokenURI(uint256 tokenId) public view override(ERC721, IERC721Metadata) returns (string memory) {
    require(msg.sender == ownerOf(tokenId), "Only owner can access metadata");
    return INonfungibleTokenPositionDescriptor(_tokenDescriptor).tokenURI(this, tokenId);
}
