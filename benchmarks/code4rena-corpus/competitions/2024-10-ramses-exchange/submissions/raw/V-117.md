## Description:
In the `setPoolFeeProtocolBatch` functions, there are no checks to prevent empty arrays from being passed as arguments. This lack of input validation could result in the function executing unnecessarily when empty arrays are provided, leading to wasted gas and potential logic issues in batch operations.

## Impact:
Passing empty arrays as arguments (e.g., `[]`) would still cause the function to execute, consuming gas without performing any meaningful operations. This could result in higher costs for users and inefficient use of network resources. Additionally, empty input might lead to unintended behavior, as the loop still processes without any actual data, which could introduce subtle logic errors.

## Proof of Concept:
By passing empty arrays to the function, gas is consumed even though no valid operations occur:

```solidity
// Example POC
setPoolFeeProtocolBatch([], []); 
// Function will execute and consume gas, despite no pools or protocols being updated.
```
