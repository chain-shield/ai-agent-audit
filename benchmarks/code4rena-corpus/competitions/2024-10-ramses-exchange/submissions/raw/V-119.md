# Vulnerability details

## Description:
The `mint` function does not verify if `params.token0` and `params.token1` are valid `ERC20` tokens prior to liquidity addition. If invalid addresses are provided, this could lead to unexpected behavior or compromise the contract's state.

## Impact:
Exploiting this vulnerability can result in the contract attempting to interact with `non-ERC20 `tokens, leading to failures during liquidity provisioning or unintended contract states. This could significantly disrupt normal operations and harm user trust.

## Proof of Concept:
An attacker can invoke the `mint` function with invalid token addresses. This could cause the contract to malfunction, allowing the attacker to disrupt liquidity provision or manipulate the contract's state.

## Tool Used:
Manual Review

## Recommended Mitigation:
Implement validation checks to confirm that `params.token0` and `params.token1` are legitimate `ERC20` tokens before executing any operations with them. This can be achieved by using the ERC20 interface to call the `balanceOf` or `transfer` functions on the token addresses to verify their validity.
