# Vulnerability details

## Proof of Concept
Unchecked Access Control: Functions with restricted access control (e.g., initialize, createPool, setFeeProtocol) control sensitive data but assume proper authorization from AccessManaged. If the access control mechanism is compromised or misconfigured, unauthorized actors may modify protocol fees, tick spacings, and pool-specific parameters.

Impact: Unauthorized access to these functions could lead to an attacker modifying fees, tick spacings, or even setting the feeCollector address to divert protocol funds. This can cause significant financial losses and operational disruptions.

## Recommended Mitigation Steps
Verify that AccessManaged implements and enforces robust access control, allowing only privileged users (e.g., multisig addresses) to execute sensitive functions. Additionally, adding a delay or requiring multisig approval for high-impact functions can mitigate risks from compromised accounts.
example:
// Example pseudocode for multi-sig or time-locked transactions
modifier restricted() {
    require(isAuthorized(msg.sender), "Not authorized");
    _;
}

function setFeeProtocol(uint8 _feeProtocol) external restricted timeLocked { ... }
