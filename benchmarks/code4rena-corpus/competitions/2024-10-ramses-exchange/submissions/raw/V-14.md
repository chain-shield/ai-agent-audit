# Vulnerability details

## Proof of Concept

In the current implementation of the `GaugeV3` smart contract, `cachePeriodEarned` is called from the `_getReward()` before transferring rewards to the user:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L544-552
```
  uint256 _reward = cachePeriodEarned(
            period,
            token,
            owner,
            index,
            tickLower,
            tickUpper,
            true
        );
```

`cachePeriodEarned()` calculates the amount that can be claimed the following way:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L321-332
```
   amount = FullMath.mulDiv(
            tokenTotalSupplyByPeriod[period][token],
            periodSecondsInsideX96,
            WEEK << 96
        );

        uint256 claimed = periodClaimedAmount[period][_positionHash][token];
        if (amount >= claimed) {
            amount -= claimed;
        } else {
            amount = 0;
        }

```

As you can see here if the amount < already claimed amount for the period, it's nullified. Let's imagine a scenario where user first claimed the majority of the tokens that he was eligible to after 5 days of the week (a period is equal to 7 days) and then tries to claim the remaining amount at the end of the period. But if the claimed amount > amount, amount will be assigned to 0 meaning user is not able to claim any funds anymore.

## Recommended Mitigation Steps

Change the logic of how amount that can be claimed is calculated.
