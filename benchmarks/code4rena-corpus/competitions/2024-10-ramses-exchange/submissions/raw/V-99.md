# Vulnerability details

## Proof of Concept
The `Position.sol` library has a function called `update`, which is used to add accumulated fees to a position. Ramses implements the logic of this function based on Uniswap V3's approach. However, the problem arises in the following code (https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/libraries/Position.sol#L98-L100):

```
  unchecked {
...
       /// @dev overflow is acceptable, user must withdraw before they hit type(uint128).max fees
       self.tokensOwed0 += tokensOwed0;
       self.tokensOwed1 += tokensOwed1;
...
}
```

Because this expression is wrapped in an `unchecked` block, if a user's fees overflow `uint128`, their fees would reset to 0 without giving any error. While overflows are rare, they are acknowledged in Uniswap's comments: 'overflow is acceptable, user must withdraw before they hit type(uint128).max fees.' However, in Uniswap's original code, the transaction would simply revert if this happens. The same behavior cannot be expected from Ramses' implementation of this function.

## Recommended Mitigation Steps
Remove the potentially dangerous `unchecked` block to avoid the risk of overflow.
