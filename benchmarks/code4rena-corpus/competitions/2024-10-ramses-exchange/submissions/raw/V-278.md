You must calculate the `feeProtocol` based on `zeroForOne`.

The `zeroForOne` flag is crucial for determining the correct direction of the swap and for calculating the appropriate `price` and fee `adjustments`. By using this flag, the code can efficiently handle both types of swaps within a single function.

* When `zeroForOne` is `true`, it means the swap is exchanging `token 0 `(e.g., ETH) for `token 1` (e.g., USDC).
* When `zeroForOne` is `false`, it means the swap is exchanging `token 1` for `token 0`.

#### On the `UniswapV3Pool` swap  function it implemented `feeProtocol` based on the `zeroForOne`.
* [see on this line of the code of Uniswap](https://github.com/Uniswap/v3-core/blob/main/contracts/UniswapV3Pool.sol#L621)

```solidity
SwapCache memory cache =

        liquidityStart: liquidity,
        blockTimestamp: _blockTimestamp(),
@->     feeProtocol: zeroForOne ? (slot0Start.feeProtocol % 16) : (slot0Start.feeProtocol >> 4),
        secondsPerLiquidityCumulativeX128: 0,
        tickCumulative: 0,
        computedLatestObservation: false
    });
```

## Recommended Mitigation Steps
Use recommended feeProtocol calculation based on the `zeroForOne` value.
```diff
-    feeProtocol: slot0Start.feeProtocol,
+    feeProtocol: zeroForOne ? (slot0Start.feeProtocol % 16) : (slot0Start.feeProtocol >> 4),
```

here on `(slot0Start.feeProtocol % 16)` and `(slot0Start.feeProtocol >> 4)` use `Rameses's` actual fee calculation.
