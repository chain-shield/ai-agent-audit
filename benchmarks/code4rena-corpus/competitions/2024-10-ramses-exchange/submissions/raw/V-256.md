# Vulnerability details

## Description
In the collectProtocolFees function of the FeeCollector.sol contract, there is a vulnerability related to gauge redirection. When a gauge is either not alive or missing, the function attempts to find an alternative gauge by redirecting to another pool. However, this logic does not account for scenarios where the redirected pool itself may point to yet another gauge, leading to potential infinite loops or unresolved states if multiple redirections occur.

**IMPACT:**
This vulnerability can lead to several critical issues:
- Infinite Loop Risk: If multiple pools continuously redirect to one another, it could result in an infinite loop during execution. This would cause the transaction to run out of gas, reverting the operation and potentially locking funds.
- Unresolved States: The function may enter an unresolved state where it cannot properly determine the correct gauge to collect fees from, leading to loss of functionality or the inability to collect fees correctly.

# Proof of Concept
To demonstrate the vulnerability, consider the following scenario:

- Gauge A is not alive, and the contract redirects to Pool B.
- Pool B is configured to redirect back to Gauge A or another pool (Pool C).
- This circular or multi-layer redirection can cause the collectProtocolFees function to endlessly chase gauges, never resolving the correct target.

## Recommended Mitigation Steps
Limit Redirections: Introduce a counter or a maximum limit on the number of redirection checks allowed within a single execution of the collectProtocolFees function. If this limit is exceeded, revert the transaction with an appropriate error message.
