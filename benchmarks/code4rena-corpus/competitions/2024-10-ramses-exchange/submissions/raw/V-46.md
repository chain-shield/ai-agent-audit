# Vulnerability details

## Proof of Concept
The FeeCollector contract approves tokens to the fee distributor without resetting the allowance after each distribution, potentially allowing the fee distributor to spend more tokens than intended in future transactions.
```
if (amount0 > 0) {
    token0.approve(address(feeDist), amount0);
    feeDist.notifyRewardAmount(address(token0), amount0);
}
if (amount1 > 0) {
    token1.approve(address(feeDist), amount1);
    feeDist.notifyRewardAmount(address(token1), amount1);
}
```
Potential impact:

Accumulated allowances over multiple calls to collectProtocolFees.
If the fee distributor contract is compromised or upgraded maliciously, it could potentially drain more tokens than intended from the FeeCollector contract.
Violates the principle of least privilege by granting more allowance than necessary.


## Recommended Mitigation Steps
Reset the allowance to zero after each distribution:
```
if (amount0 > 0) {
    token0.approve(address(feeDist), amount0);
    feeDist.notifyRewardAmount(address(token0), amount0);
    token0.approve(address(feeDist), 0);
}
if (amount1 > 0) {
    token1.approve(address(feeDist), amount1);
    feeDist.notifyRewardAmount(address(token1), amount1);
    token1.approve(address(feeDist), 0);
}
```
