# Vulnerability details

## Summary

The ClGaugeFactory implements a single-signer authorization model where the voter address has unrestricted power to deploy new gauges. If this key is compromised, an attacker gains complete control over gauge deployment, potentially leading to system-wide manipulation of liquidity incentives and rewards distribution.


```solidity
contract ClGaugeFactory {
    address public immutable override voter;

    function createGauge(
        address pool
    ) external override returns (address gauge) {
        require(msg.sender == voter, "AUTH");
        require(getGauge[pool] == address(0), "GE");
        gauge = address(new GaugeV3(voter, nfpManager, feeCollector, pool));
        getGauge[pool] = gauge;
        emit GaugeCreated(pool, gauge);
    }
}
```

## Impact

This seemingly simple authorization check, `require(msg.sender == voter, "AUTH")`, opens up a dangerous security hole that's exacerbated by multiple design decisions. Not only does the contract trust this single address for all gauge deployments, but it also executes these deployments instantly without any safety checks or cooling periods. An attacker who compromises the voter's private key gains immediate, unrestricted power to deploy gauges.

What makes this particularly dangerous is the lack of any rate limiting or validation mechanisms. The compromised voter could deploy hundreds of gauges pointing to malicious contracts in a single transaction:

```solidity
// Example of how an attacker could exploit multiple vulnerabilities
contract AttackVector {
    function exploit(ClGaugeFactory factory) external {
        for (uint i = 0; i < 100; i++) {
            // Deploy malicious contract
            MaliciousContract fake = new MaliciousContract();
            
            // Create gauge immediately - no delay
            factory.createGauge(address(fake));
            // No rate limiting stops this loop
            // No pool validation checks if fake is legitimate
            // No timelock prevents instant execution
        }
    }
}
```

The situation becomes even more severe when you consider the immutable nature of the voter address. Once the factory is deployed, the voter address is permanently set. This means that even if the protocol team discovers the voter key has been compromised, they have no recourse to shut down gauge creation or transfer authority to a new secure address. The damage becomes irreversible:

```solidity
// No possible remediation
function emergencyShutdown() external {
    // Can't change voter address - it's immutable
    // Can't pause gauge creation - no pause mechanism
    // Can't invalidate existing gauges - they're permanent
    // Can't verify pool authenticity - no validation
    
    // Only option: Deploy new factory and abandon this one
    // But existing gauges remain vulnerable
}
```

In a real-world scenario, this could play out devastatingly fast:
1. Attacker compromises voter key
2. Immediately deploys multiple gauges pointing to malicious contracts
3. These gauges are created instantly - no timelock to stop them
4. Can deploy unlimited gauges - no rate limiting
5. Gauges can point to any address - no pool validation
6. Protocol team can't intervene - voter address is immutable

The only solution would be to deploy a new factory entirely, but this creates its own set of problems - existing gauges would still be tied to the compromised factory, and all protocol integrations would need to be updated to point to the new factory.



## Fix

Add Time-lock Mechanism:
```solidity
contract TimelockedGaugeFactory {
    uint256 public constant TIMELOCK_PERIOD = 2 days;
    mapping(bytes32 => uint256) public proposalTimestamps;
    
    function proposeGauge(address pool) external {
        require(msg.sender == voter, "AUTH");
        bytes32 proposalId = keccak256(abi.encodePacked(pool));
        proposalTimestamps[proposalId] = block.timestamp;
    }
    
    function executeGaugeCreation(address pool) external {
        bytes32 proposalId = keccak256(abi.encodePacked(pool));
        require(block.timestamp >= proposalTimestamps[proposalId] + TIMELOCK_PERIOD, "TIMELOCK");
        _createGauge(pool);
    }
}
```
