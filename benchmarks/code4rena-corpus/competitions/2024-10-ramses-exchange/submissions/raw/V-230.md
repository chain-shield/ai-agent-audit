# Vulnerability details

## Description:
In the `RamseyV3Factory constructor`, there are several errors in the basis points (bps) calculations for `tickSpacingInitialFee` settings:

`tickSpacingInitialFee`: The basis points values assigned to various fee options are incorrect. For example:
- 1 bps is documented as a 0.01% fee, yet it is set to 100 bps (1%), which is a magnitude higher than intended.
- Similar miscalculations apply to other fees, such as 0.025%, 0.05%, 0.3%, and 1.00%.
## Impact:
- Incorrect bps calculations can have significant financial and operational consequences: Inaccurate Fee Distribution: The incorrectly calculated `tickSpacingInitialFee` values could lead to unintended fee settings, affecting user costs and potentially causing loss of funds for liquidity providers or the protocol itself.

## Proof of Concept
- Incorrect tickSpacingInitialFee:
```
tickSpacingInitialFee[1] = 100; // Intended as 0.01% (1 bps), but set to 100 bps (1%)
tickSpacingInitialFee[5] = 250; // Intended as 0.025%, but set to 250 bps
```
because 100% = 10 000 bps

## Recommended Mitigation Steps
Correct the Basis Points Calculations: Ensure each basis points setting reflects the correct values. Examples:
```
tickSpacingInitialFee[1] = 1; // for 0.01%
tickSpacingInitialFee[5] = 25; // for 0.025%
....
```
Continue adjusting for other fees similarly.
