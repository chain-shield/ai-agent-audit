# Vulnerability details

## Description:
In the `enableTickSpacing` function within `RamseyV3Factory` contract , there is a severe miscalculation in the maximum allowable value for `initialFee`. The function permits an `initialFee` of up to `1,000,000` basis points (bps), which translates to `1,000%` rather than the intended `100%` (10,000 bps).
```
require(initialFee < 1_000_000, FTL()); // Incorrect limit, as 1,000,000 bps = 10000% instead of 100%

```
## Impact:
This issue introduces significant financial and functional risks:

-Potential for Arbitrary Fee Settings: With an allowance of up to 10,000%, pools could set initial fees far exceeding what is practical or secure. This could result in extreme transaction costs, discouraging user interaction with the protocol.
- Operational Instability: Allowing such high fees might destabilize the protocol’s liquidity mechanisms, eroding trust and damaging the protocol's reputation among users.
## Proof of Concept
Set initialFee to an excessively high value:
```
enableTickSpacing(500, 1_000_000); // sets an initial fee of 1000%, causing excessive charges on trades
```
Verify fee application within the pool, resulting in an unreasonable and unexpected drain on user funds.

## Recommended Mitigation Steps
Limit `initialFee` to a Maximum of 10,000 bps: Update the condition to `require(initialFee <= 10_000, FTL());` to cap initialFee at 100%, preventing the setting of unrealistic and exploitable fee values.
