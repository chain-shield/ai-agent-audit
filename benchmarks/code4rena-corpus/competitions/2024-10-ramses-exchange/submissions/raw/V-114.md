# Vulnerability details

## Sommary
In the `RamsesV3Factory::setFee` function, `_fee` param can take `zero` value.

## Proof of Concept
When defining a new fee with the `RamsesV3Factory::setFee` function, no validation has been done to check the value passed to the `_fee` parameter, so any value can be passed, even `zero`. However, if the protocol fee is `zero`, this makes no sense and the protocol will not work as expected.
```solidity
    function setFee(address _pool, uint24 _fee) external override restricted {
        // @audit lack of zero check
        IRamsesV3Pool(_pool).setFee(_fee);
        emit FeeAdjustment(_pool, _fee);
    }
```

## Impact
Unexpected behavior and all those who are supposed to be remunerated thanks to these fees will receive nothing at the end of the day.

## Recommended Mitigation Steps
```diff
    function setFee(address _pool, uint24 _fee) external override restricted {
+       require( _fee != 0; "Fee can not be 0");
        IRamsesV3Pool(_pool).setFee(_fee);
        emit FeeAdjustment(_pool, _fee);
    }
```
