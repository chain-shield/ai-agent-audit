# Vulnerability details

## Description
[setFee](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L175-L180) function in RamsesV3Factory sets the fee for a pool by making an external call to [setFee](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L744-L746) function in RamsesV3Pool as seen below;

```solidity
 function setFee(address _pool, uint24 _fee) external override restricted {
        IRamsesV3Pool(_pool).setFee(_fee);

        emit FeeAdjustment(_pool, _fee);
    }
}
```

This is the [setFee](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L744-L746) function in RamsesV3Pool;

```solidity
function setFee(uint24 _fee) external override lock {
        ProtocolActions.setFee(_fee, factory);
    }
```

You would observe that the [setFee](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L744-L746) function in RamsesV3Pool makes another external call to [setFee](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/libraries/ProtocolActions.sol#L75-L83) function in ProtocolAction.sol.

Here is the code;
```solidity
function setFee(uint24 _fee, address factory) external {
        PoolStorage.PoolState storage $ = PoolStorage.getStorage();
        if (msg.sender != factory) revert Unauthorized();
        if (_fee > 100000) revert InvalidFee();
        uint24 _oldFee = $.fee;
        $.fee = _fee;
        emit FeeAdjustment(_oldFee, _fee);
    }
}
```

The issue is that there is a check;
```solidity
        if (msg.sender != factory) revert Unauthorized();

```
This is a good check which is supposed to allow only authorized users to set or update the fee. However, the msg.sender in this case is the RamsesV3Pool contract as it is the contract that called this function. Hence, the check will alaways fail and the user will not be able to update or set the fee.
## Impact
Users will be unable to set fee for a pool. This will compromise the purpose of the protocol and reduce trust of the users. This unintentionally leads to denial of service.

## Recommended Mitigation Steps

Implement an accurate chec. For instance:
```solidity
if (msg.sender != Pool) revert Unauthorized();
```

Because it is the pool that is calling this contract.
