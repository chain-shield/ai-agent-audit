# Vulnerability details

## Proof of Concept

At the moment the function `getPeriodReward()` is used by the users to get all the rewards for the specific. However, the problem is that the function calls internal `_getReward()` and provides `msg.sender` as the owner address:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L394-400
```
  require(msg.sender == owner, "Not authorized");
        bytes32 _positionHash = positionHash(
            owner,
            index,
            tickLower,
            tickUpper
        );

```

As you can see here, `msg.sender` is required to be the owner that's provided in the params. In comparison, other functions that are used in the contract derive `_positionHash` by providing `nfpManager` as the owner address:

https://github.com/code-423n4/2024-10-ramses-exchange/blob/main/contracts/CL/gauge/GaugeV3.sol#L208-213
```
  bytes32 _positionHash = positionHash(
            address(_nfpManager),
            tokenId,
            tickLower,
            tickUpper
        );

```

The problem is that there is no `getPeriodReward()` function inside of the `NonfungiblePositionManager` contract meaning it could not be possibly be `msg.sender` when calling the `getPeriodReward()` function. This results in a situation where user will not be able to use the function to derive the rewards for the period as the position hash will be incorrectly calculated.

## Recommended Mitigation Steps

Remove the deviations between the functions by calculating the position hash similarly everywhere.
