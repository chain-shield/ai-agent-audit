### Impact
The earned function in the GaugeV3 contract incorrectly includes the current ongoing period when calculating the rewards. 
This results in the inclusion of incomplete reward data, leading to users potentially receiving inaccurate reward amounts.
Users may receive either inflated or deflated reward amounts.

### Vulnerable Code
```Solidity
// https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L199-L230

    /// @inheritdoc IGaugeV3
    function earned(
        address token,
        uint256 tokenId
    ) external view returns (uint256 reward) {
        INonfungiblePositionManager _nfpManager = nfpManager;
        (, , , int24 tickLower, int24 tickUpper, , , , , ) = _nfpManager
            .positions(tokenId);


        bytes32 _positionHash = positionHash(
            address(_nfpManager),
            tokenId,
            tickLower,
            tickUpper
        );


        uint256 lastClaim = Math.max(
            lastClaimByToken[token][_positionHash],
            firstPeriod
        );
        uint256 currentPeriod = _blockTimestamp() / WEEK;
        for (uint256 period = lastClaim; period <= currentPeriod; ++period) {
            reward += periodEarned(
                period,
                token,
                address(_nfpManager),
                tokenId,
                tickLower,
                tickUpper
            );
        }
    }
```

### Proof of Concept (PoC):
A user calls the earned function during an ongoing period. 
Since the loop includes currentPeriod (period <= currentPeriod), it attempts to calculate rewards for a period that hasn’t fully elapsed, leading to inaccurate reward computation.
```Solidity
// Assume currentPeriod is 11, and lastClaim is 9
// The loop runs for periods 9 and 11
// Period 11 is ongoing, so periodEarned for period 11 may return incomplete or zero rewards

uint256 rewards = gaugeV3.earned(tokenAddress, tokenId);
// rewards = rewardForPeriod10 + rewardForPeriod11 (incomplete)
```

## Recommended Mitigation Steps
Adjust the loop condition to exclude the ongoing period by iterating only up to currentPeriod - 1. 
This ensures that only completed periods are considered in the reward calculation.
```Solidity
        +for (uint256 period = lastClaim; period < currentPeriod; ++period) {
        -for (uint256 period = lastClaim; period <= currentPeriod; ++period) {
            reward += periodEarned(
                period,
                token,
                address(_nfpManager),
                tokenId,
                tickLower,
                tickUpper
            );
        }
```
