# Vulnerability details

## Impact
The absence of a check to ensure that blockTimestamp is equal to or greater than last.blockTimestamp presents a critical vulnerability that an attacker can exploit in [transform](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/libraries/Oracle.sol#L24-L41) function. By providing a blockTimestamp that is less than last.blockTimestamp, an attacker can trigger an underflow in the calculation of delta. This manipulation can lead to inflated cumulative values (tickCumulative and secondsPerLiquidityCumulativeX128), allowing the attacker to misrepresent liquidity and price mechanisms for financial gain.

```solidity
function transform(
        Observation memory last,
        uint32 blockTimestamp,
        int24 tick,
        uint128 liquidity
    ) private pure returns (Observation memory) {
        unchecked {
            uint32 delta = blockTimestamp - last.blockTimestamp;
            return
                Observation({
                    blockTimestamp: blockTimestamp,
                    tickCumulative: last.tickCumulative + int56(tick) * int56(uint56(delta)),
                    secondsPerLiquidityCumulativeX128: last.secondsPerLiquidityCumulativeX128 +
                        ((uint160(delta) << 128) / (liquidity > 0 ? liquidity : 1)),
                    initialized: true
                });
        }
    }
```

This leads to underflow when last.blockTimestamp is greater than blockTimestamp

```solidity
uint32 delta = blockTimestamp - last.blockTimestamp;
```

Attack Scenario
    
1. Preparation: The attacker deploys the vulnerable contract with an Observation initialized with a valid blockTimestamp.
    
2. Attack Execution: when the transform function is executed using a blockTimestamp that is intentionally set lower than the last.blockTimestamp. 
    
3. Exploitation:
  ◦ The underflow leads to a large positive value for delta, resulting in exaggerated updates to tickCumulative and secondsPerLiquidityCumulativeX128.

  ◦ With manipulated cumulative values, the attacker can:
            
▪ Influence Pricing: Use the incorrect prices to execute profitable trades or arbitrage opportunities.
            

▪ Manipulate Liquidity Pools: Withdraw or leverage liquidity based on misleading information, potentially draining funds from the contract.

## Tools Used
Vscode, Manual Review

## Recommended Mitigation Steps

Add a require statement at the beginning of the transform function to enforce that blockTimestamp is always greater than or equal to last.blockTimestamp:
       
```solidity
       require(blockTimestamp >= last.blockTimestamp, "Invalid blockTimestamp");
```
