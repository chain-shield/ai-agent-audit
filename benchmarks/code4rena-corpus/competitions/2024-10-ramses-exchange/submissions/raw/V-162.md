# Vulnerability details

## Proof of Concept
Token Approval Race Condition: In the collectProtocolFees() function, tokens are approved for transfer to the feeDist address immediately before calling feeDist.notifyRewardAmount. This creates a potential race condition where a reentrancy attack could exploit approvals.
An attacker could initiate a reentrant call that intercepts approvals and repeatedly withdraws funds:
// Simulated attack exploiting reentrancy on token approval
token0.approve(address(feeDist), amount0);
feeDist.notifyRewardAmount(address(token0), amount0);

Impact: This issue could allow an attacker to execute multiple approvals before resetting them, leading to unintended token distribution.

## Recommended Mitigation Steps
1. Approve only the exact amount needed or use approve(0) to reset approvals before each new call.
2. Consider using safeApprove() functions or requiring tokens to have a zero approval state before setting a new amount.
