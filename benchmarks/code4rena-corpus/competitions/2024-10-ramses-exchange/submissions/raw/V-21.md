# Vulnerability details

## Description
In the [createPool](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L71) function, the current implementation checks if the fee retrieved from the tickSpacingInitialFee mapping is non-zero but does not validate whether the fee falls within an acceptable range. Additionally, there are no checks to ensure that the tickSpacing parameter is within a predefined set of acceptable values. This oversight allows for the possibility of creating pools with:

1. Fees that are too low: This could undermine the economic sustainability of the pools.
2. Fees that are too high: This could deter users from participating in the pool, leading to low liquidity.
3. Invalid or unexpected tick spacings: This could lead to inconsistent behavior across the contract and affect trading strategies.

```solidity
function createPool(
        address tokenA,
        address tokenB,
        int24 tickSpacing,
        uint160 sqrtPriceX96
    ) external override returns (address pool) {
        require(tokenA != tokenB, IT());
        (address token0, address token1) = tokenA < tokenB ? (tokenA, tokenB) : (tokenB, tokenA);
        require(token0 != address(0), A0());
        uint24 fee = tickSpacingInitialFee[tickSpacing];
        require(fee != 0, F0());
        require(getPool[token0][token1][tickSpacing] == address(0), PE());
```
## Impact
The absence of checks for minimum and maximum fee values and tick spacing limits in the [createPool](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L71) function can lead to significant issues, including the creation of liquidity pools with unreasonable or exploitative fee structures. 

Allowing for fees that are too low could result in pools that do not generate sufficient revenue to cover operational costs.

## Proof of Concept
Proof of Concept (PoC)

1. Deploy the Contract: Deploy the contract with the constructor as provided, ensuring it initializes the tickSpacingInitialFee mapping.
2. Invoke createPool with Unsupported Values:
Call the createPool function with a tickSpacing that is not predefined (e.g., 3, which is not in the mapping).
Call the createPool function with an exceedingly high tickSpacing (e.g., 1000).
Call the createPool function with a low tickSpacing that is not defined (e.g., 0).
3. The function will not revert for unsupported tickSpacing values, allowing the creation of a pool that may have unmanageable fees or configurations.
