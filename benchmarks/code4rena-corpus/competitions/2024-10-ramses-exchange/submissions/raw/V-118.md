# Vulnerability details

```solidity
            amount0Treasury = (amount0 * _treasuryFees) / BASIS;
```

## Description:
In the fee calculation for `amount0Treasury`, there is a risk of arithmetic overflow when multiplying `amount0` and `_treasuryFees`. If these values are sufficiently large, the multiplication could exceed the maximum limit of a uint256, resulting in an overflow. This could lead to incorrect fee calculations and financial discrepancies.

## Impact:
An overflow in the fee calculation may result in significant errors in fee distribution, potentially causing loss of funds or incorrect allocation to treasury accounts. This issue can undermine the financial integrity of the contract and erode trust among users.

## Proof of Concept:
By setting `amount0` to a high value (e.g, near the uint256 limit) and `_treasuryFees` to a high value, the multiplication could cause an overflow:

```solidity
// Example POC
uint256 amount0 = type(uint256).max; // Maximum uint256 value
uint256 _treasuryFees = 2; // High fee
amount0Treasury = (amount0 * _treasuryFees) / BASIS; 
// This may result in an overflow and produce an incorrect amount0Treasury.
```
## Tools Used:
Manul Review

## Recommended Mitigation:
To prevent potential overflows, utilize the `SafeMath` library for arithmetic operations, or ensure that the contract is updated to Solidity version 0.8.0 or later, where built-in overflow checks are provided.
 For example:using Solidity 0.8.0 or later:  Using SafeMath 

```solidity
using SafeMath for uint256;

amount0Treasury = (amount0 * _treasuryFees) / BASIS; // Safe in Solidity 0.8.0+

```
This will ensure that any arithmetic operations are checked for overflow and underflow, maintaining the correctness of fee calculations.
