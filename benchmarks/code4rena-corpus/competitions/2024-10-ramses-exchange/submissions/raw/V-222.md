# Vulnerability details

## Proof of Concept

 RamesV3Factory uses setFeeProtocol, setPoolFeeProtocol, setPoolFeeProtocolBatch (two versions) to change the feeProtocol for a pool. These functions change the default ```feeProtocol``` and the ```feeProtocol``` for each pool in the following data structures:

```javascsript
/// @dev pool specific fee protocol if set
    mapping(address pool => uint8 feeProtocol) _poolFeeProtocol;

    /// @inheritdoc IRamsesV3Factory
    uint8 public override feeProtocol;
```

The interpretation is: if ```_poolFeeProtocol[pool] = 0```, then its ```feeProtocol``` will use the default value set in ```feeProtocol```, otherwise, it will use the non-zero ```_poolFeeProtocol[pool]```. 


Such interpretation is implemented by the following function:

```javascript

function poolFeeProtocol(address pool) public view override returns (uint8 __poolFeeProtocol) {
        return (_poolFeeProtocol[pool] == 0 ? feeProtocol : _poolFeeProtocol[pool]);
    }
```

However, the REAL feeProtocol that is used for each pool is actually stored in ```$.slot0.feeProtocol```. Unfortunately, none of the above functions will propogate``` _poolFeeProtocol``` in RamesV3Factory to ```$.slot0.feeProtocol```. A manual propogation has to be performed by calling RamesV3Pool.setFeeProtocol(). However, there is no guarantee that when RamesV3Pool.setFeeProtocol() will be called or will be called at all.

For example, for poolA, suppose the initial feeProtocol = 80, and now RamesV3Factory.setFeeProtocol() is called to intend to change it to 85. However, such change will not have impact immediately, the old feeProtocol 80 will continue to be used. Similarly, if one changes the default ```feeProtocol``` in RamesV3Factory to 78, supposedly, all the pools that have _poolFeeProtocol[pool] = 0 should be updated with this new default feeProtocol. However, none of these will immediate impact either, the old values will be used instead, until someone calls RamesV3Pool.setFeeProtocol() for these pools.

But which pools use the default feeProtocol? There is no data structure to support that, and 
```_poolFeeProtocol``` is a private variable in the RamsesV3Factory contract, so there is no easy to identify the pools that use the default feeProtocol so that one can call RamesV3Pool.setFeeProtocol() when the default feeProtocol is changed. 


Such delayed updates or NO updates could impact the fee collection structure. The protocol will either loss or gain fees due to this, not a correct accounting of the protocol fees. 

## Recommended Mitigation Steps
1. Call ```RamesV3Pool.setFeeProtocol()``` automatically when the feeProtocol is changed by one of the functions. 

2. Maintain a list of pools that use the default feeProtocol, and when the default feeProtocol is changed, call ```RamesV3Pool.setFeeProtocol()``` for each pool in the list.
