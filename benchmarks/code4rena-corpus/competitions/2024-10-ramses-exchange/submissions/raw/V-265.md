# Vulnerability details

## Proof of Concept


There is a delegate call injection vulnerability.  The line `IGaugeV3 gauge = IGaugeV3(IVoter(voter).gaugeForPool(PoolAddress.computeAddress(deployer, poolKey)));` constructs the address of the `IGaugeV3` contract to be called using `DelegateCall`. An attacker could manipulate the `voter` input, leading them to control the address ultimately called via `DelegateCall`. This allows an attacker to execute arbitrary code on a different contract than intended.

## Recommended Mitigation Steps

a.  To protect against delegate call injection, remove delegate calls where unnecessary.  This means, that if the delegatecall isn’t essential, absolutely have devs replace it with call. Unlike delegatecall, call doesn’t execute the called contract’s code in the context of the calling contract, which prevents unintended access to internal states.

b.  Make explicit contract address checks.   For cases where delegatecall is absolutely necessary, implement strict checks to ensure that the target address (voter in this context) is a verified contract address. Use a whitelist/specific address registry contract that holds addresses allowed to be targeted by delegate calls. This reduces the risk of malicious contract injection.  One way to do this is as follows: 
```
require(isValidVoterAddress(voter), "Invalid voter address");

```
c.  User an onlyAdmin modifier.  Restrict critical functions that involve delegate calls to admin-only access.  Even if the delegate call functionality is required, it should only be executed by trusted accounts.  For example, 

modifier onlyAdmin() {
    require(msg.sender == admin, "Admin access only");
    _;
}

d.  Implement a proxy pattern.   That is, use a separate proxy contract for delegate calls, ensuring that the primary contract's intneral state is isolated and immutable. 

They can configure any delegate call operations to a contained environment, minimizing exposure to the main contract's storage. 

e . Use solidity's ```Checks-Effects-Interactions Pattern.  Always perform ALL necessary checks before executing ANY internal calls.  Also make sure devs handle state changes (effects) prior to the interactions to avoid reentrancy, or unexpected behavior.
