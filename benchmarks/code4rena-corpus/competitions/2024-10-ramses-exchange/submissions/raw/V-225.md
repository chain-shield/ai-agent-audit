# Vulnerability details

## Proof of Concept

A user might call GaugeV3.getPeriodReward() claim rewards from a period, where previous periods have not been claimed, leading to possible loss of rewards. 


A user might call GaugeV3.getPeriodReward() to get rewards for a particular period, let's say 100:

[https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L385-L418](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L385-L418)


There will be a problem when previous periods have not been claimed, let's say lastClaimByToken[tokens[i]][_positionHash] = 97. In other words, periods 98 and 99 have not been claimed yet.

However, GaugeV3.getPeriodReward() will skip periods 98 and 99 and modify lastClaimByToken[tokens[i]][_positionHash] = 100. See below:

```javascript
 if (period < _blockTimestamp() / WEEK) {
                lastClaimByToken[tokens[i]][_positionHash] = period;
            }
```

On the otherhand, function earned() will calculate the earning from ```lastClaimByToken[tokens[i]][_positionHash]```, leaving periods 98 and 99 unaccounted. earned() will return the WRONG result. 

[https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L200-L230](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L200-L230)

As a result, a user might skip periods 98 and 99 and loss these funds when he calls getReward() to get all rewwards. The function calls ```_getAllRewards()```, which claims rewards from period lastClaimByToken[tokens[i]][_positionHash], skipping the unclaimed periods 98 and 99. Loss of funds for the user. 

[https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L493-L532](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L493-L532)


## Recommended Mitigation Steps
To address this, the contract could be modified so that lastClaimByToken is updated sequentially or incrementally, ensuring no periods are skipped unintentionally. Here are two potential solutions:

Sequential Claim Requirement: Enforce a rule that getPeriodReward can only be called for the next sequential unclaimed period, preventing users from skipping any periods when claiming rewards. This way, periods are claimed in order.

Track Claimed Periods Individually: Instead of using lastClaimByToken to record the latest claimed period, track each period individually. A mapping could be used to flag each claimed period, e.g., claimedPeriods[period][_positionHash][token]. Then, earned can iterate over all relevant periods, checking each period’s claimed status.
