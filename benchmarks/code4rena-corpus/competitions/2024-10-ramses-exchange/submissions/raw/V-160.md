# Vulnerability details

## Proof of Concept
 Reentrancy Risk: The createGauge function does not have any built-in protection against reentrancy attacks. If GaugeV3 interacts with another contract that calls back into the factory, it could potentially lead to reentrant calls.
Example: If GaugeV3 calls back to the ClGaugeFactory and re-enters the createGauge function, it could bypass checks and create additional gauges unintentionally.

Impact: This could allow an attacker to manipulate the state of the contract during the gauge creation process, potentially draining funds or creating multiple gauges unintentionally.

## Recommended Mitigation Steps
1. Implement a reentrancy guard using the ReentrancyGuard modifier from OpenZeppelin or a similar pattern.
2. Ensure that all external calls are made after state changes are completed.
