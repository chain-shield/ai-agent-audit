# Vulnerability details

## Proof of Concept

The initialize function is unprotected, allowing it to be called multiple times or by unauthorized users. This function is intended to set up the initial state of the Observation array, which is crucial for the functionality of the oracle.

**Impact**
If the function can be called repeatedly, it may lead to state corruption, overwriting existing data in the Observation array. This could result in incorrect values and compromise the oracle's behavior. Additionally, unauthorized access could manipulate the contract's initial state, leading to potential security breaches.

**Attack Scenario**
An attacker could repeatedly invoke the initialize function, altering the first entry of the Observation array and disrupting the expected contract behavior.

## Recommended Mitigation Steps
Implement an access control mechanism, such as:
* OnlyOwner Modifier: Limit access to the contract owner or an authorized address.
* Initialized Check: Use a boolean flag to ensure the function can only be executed once.

This finding underscores the critical need for protecting initializer functions in smart contracts to avoid unintended state changes or unauthorized access. Implementing proper access controls can significantly enhance the contract's security and integrity during the initialization process.
