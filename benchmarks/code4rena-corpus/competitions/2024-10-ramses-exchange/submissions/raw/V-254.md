# Vulnerability details

## Proof of Concept 
 - Collision Risk with abi.encodePacked:
 The use of `abi.encodePacked` can lead to hash collisions if certain types of data are not distinctively packed. Specifically, two different data inputs could produce the same packed output.
Example: If owner is an address that happens to be 0x1234567890abcdef1234567890abcdef12345678, and index is 0, tickLower is 0, and tickUpper is 1, it can potentially collide with another input if the parameters are not carefully chosen.
```javascript
positionHash(0x1234567890abcdef1234567890abcdef12345678, 0, 0, 1); 
positionHash(0x1234567890abcdef1234567890abcdef12345678, 1, -1, 0);
```
The above two calls could yield the same packed byte string if not enough padding is added.
## Recommended Mitigation Steps
 To avoid this, it’s safer to use abi.encode instead:
```javascript
return keccak256(abi.encode(owner, index, tickLower, tickUpper));
```
