# Vulnerability details

## Proof of Concept
The `periodCumulativesInside` function in the `Oracle` library lacks proper input validation for the parameters `tickLower`, `tickUpper`, and `period`. This absence of validation can lead to incorrect calculations, logical errors, or even contract failures when these parameters are outside their expected ranges.

Root Cause: The function does not check if `tickLower` and `tickUpper` are within valid bounds defined by `TickMath.MIN_TICK` and `TickMath.MAX_TICK`, nor does it ensure that `period` is greater than zero.

## Impact
- The absence of validation can result in incorrect fee and liquidity calculations.
- Accessing invalid tick data can lead to runtime errors, potentially causing the contract to revert or behave unexpectedly.

## Recommended Mitigation Steps
Implement input validation checks at the beginning of the `periodCumulativesInside` function to ensure that `tickLower`, `tickUpper`, and `period` are within valid ranges.
```
function periodCumulativesInside(
    uint32 period,
    int24 tickLower,
    int24 tickUpper,
    uint32 _blockTimestamp
) external view returns (uint160 secondsPerLiquidityInsideX128) {
+   require(tickLower >= TickMath.MIN_TICK && tickLower <= TickMath.MAX_TICK, "TickLower out of range");

+   require(period > 0, "Period must be greater than 0");
```
