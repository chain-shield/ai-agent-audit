# Vulnerability details

## Proof of Concept
While several operations use unchecked blocks, not all scenarios guarantee that overflow or underflow is impossible. Specifically, the unchecked math in the update() function involves large numbers and relies on external input for liquidity deltas.
```
unchecked {
    tokensOwed0 = uint128(
        FullMath.mulDiv(feeGrowthInside0X128 - self.feeGrowthInside0LastX128, liquidity, FixedPoint128.Q128)
    );
    tokensOwed1 = uint128(
        FullMath.mulDiv(feeGrowthInside1X128 - self.feeGrowthInside1LastX128, liquidity, FixedPoint128.Q128)
    );
    ...
}

```
While unchecked operations save gas, they risk overflow or underflow if inputs or intermediary results grow too large.
## Recommended Mitigation Steps
Unchecked Arithmetic: The unchecked keyword disables overflow/underflow checks on arithmetic operations. If the input values for liquidity or fee growth are large and unexpected edge cases arise, this could theoretically cause overflow/underflow issues.

Liquidity Delta: The liquidityDelta input, which can either increase or decrease the position's liquidity, comes from an external source. While checks like liquidityDelta > 0 and liquidityDelta < 0 are in place, they should ensure that no unsafe values are passed to the unchecked block.

Fee Growth Calculations: The fee growth calculations involve subtracting self.feeGrowthInside0LastX128 and self.feeGrowthInside1LastX128 from external inputs. If these values are improperly handled, it could theoretically lead to unexpected results in the unchecked block.


Ensure all unchecked operations are wrapped with explicit validation checks to guarantee that overflow or underflow cannot occur. Consider reverting to checked math in critical areas where large number operations can happen.
