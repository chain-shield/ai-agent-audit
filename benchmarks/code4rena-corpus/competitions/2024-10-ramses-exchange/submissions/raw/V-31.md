# Vulnerability details

## Vulnerability Detail
The RamsesV3Pool contract contains a critical vulnerability in its liquidity adjustment mechanism due to unsafe casting operations. This can lead to incorrect liquidity management.

## Root Cause
The vulnerability arises from the unsafe casting of large values into smaller data types without proper checks.
```
    function mint(
        address recipient,
        uint256 index,
        int24 tickLower,
        int24 tickUpper,
        uint128 amount,
        bytes calldata data
    ) external override lock advancePeriod returns (uint256 amount0, uint256 amount1) {
        require(amount > 0);
        (, int256 amount0Int, int256 amount1Int) = _modifyPosition(
            ModifyPositionParams({
                owner: recipient,
                index: index,
                tickLower: tickLower,
                tickUpper: tickUpper,
@=>             liquidityDelta: int256(uint256(amount)).toInt128()
            })
        );
/// Another Logics

    function burn(
        uint256 index,
        int24 tickLower,
        int24 tickUpper,
        uint128 amount
    ) external override lock advancePeriod returns (uint256 amount0, uint256 amount1) {
        unchecked {
            (PositionInfo storage position, int256 amount0Int, int256 amount1Int) = _modifyPosition(
                ModifyPositionParams({
                    owner: msg.sender,
                    index: index,
                    tickLower: tickLower,
                    tickUpper: tickUpper,
@=>                 liquidityDelta: -int256(uint256(amount)).toInt128()
                })
            );
/// Another Logics
```
This casting operation is used in the `_modifyPosition` function when adjusting liquidity, particularly in operations such as mint and burn.

Initial Conditions:
- The `_modifyPosition` function that controls the liquidity changes in the pool.
- `amount` is the value we want to add or subtract from the liquidity, and the loss is very large, for example `amount = 2^130`.

Scenario: 
1. Data Type Conversion: - The function tries to convert `amount` from `uint256` to `int128` with the following operation: `int256(uint256(amount)).toInt128()` 
2. Issues that arise: - `amount = 2^130` is a value that is greater than the maximum limit of `int128`, which is `2^127 – 1`.
- When the conversion is performed, the value `2^130` cannot be represented correctly in `int128`.
3. Conversion Result: - Since `int128` cannot hold such large values, the conversion result may turn out to be a negative number or a much smaller value.

## Impact
- If this incorrect value is used to adjust liquidity or to add liquidity, then the added liquidity may be much smaller than it should be or even reduced.
- Pool liquidity becomes inaccurate, which can cause problems in swap calculations, fee distribution.

## Recommended Mitigation Steps
Implement safe casting operations and add checks to ensure that values being cast do not exceed the limits of the target data type.
