# Vulnerability details

## Summary

**Context:**
The RamsesV3Factory allows updating the fee collector address using the function [setFeeCollector()](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/core/RamsesV3Factory.sol#L169). According the sponsor team, the setter function is provided in case there is a need to change how fees are distributed or if there’s a new version of the fee collector.

**Issue:**
The issue is that the ClGaugeFactory and all the deployed GaugeV3 instances continue using the old feeCollector contract and do not upgrade to using the new one dynamically. This occurs because in the ClGaugeFactory [here](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/ClGaugeFactory.sol#L20) and GaugeV3 [here](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/gauge/GaugeV3.sol#L28), the feeCollector storage variables are marked as immutable. This means the feeCollector on the existing or even the future GaugeV3 instances will be the old one and not the new one.

Due to this, the team is never able to implement a new version of the fee collector contract and use it in the system to change how the fees are distributed.

## Proof of Concept

1. ClGaugeFactory is deployed with the feeCollector as immutable.

```solidity
    address public immutable override feeCollector;

    constructor(
        address _nfpManager,
        address _votingEscrow,
        address _voter,
        address _feeCollector
    ) {
        nfpManager = _nfpManager;
        votingEscrow = _votingEscrow;
        voter = _voter;
        feeCollector = _feeCollector;

        emit OwnerChanged(address(0), msg.sender);
    }
```

2. During the deployment of a GaugeV3 contract instance through the ClGaugeFactory, we use the immutable feeCollector address always.

```solidity
    function createGauge(
        address pool
    ) external override returns (address gauge) {
        require(msg.sender == voter, "AUTH");
        require(getGauge[pool] == address(0), "GE");
        gauge = address(new GaugeV3(voter, nfpManager, feeCollector, pool));
        getGauge[pool] = gauge;
        emit GaugeCreated(pool, gauge);
    }
```

3. The feeCollector gets stored in an immutable variable in the GaugeV3.sol contract as well.

```solidity
    IFeeCollector public immutable feeCollector;    

    constructor(
        address _voter,
        address _nfpManager,
        address _feeCollector,
        address _pool
    ) {
        _unlocked = true;

        voter = _voter;
        feeCollector = IFeeCollector(_feeCollector);
```

4. The team's multisig or the decentralized governance model over time (as mentioned in README regarding accessManager), decides to update the feeCollector contract. 

```solidity
 function setFeeCollector(address _feeCollector) external override restricted {
        emit FeeCollectorChanged(feeCollector, _feeCollector);
        feeCollector = _feeCollector;
    }
```

5. Now although the contract was updated, the ClGaugeFactory and existing + future GaugveV3 instances would continue using the old feeCollector address. Due to this, the team is never able to implement a new version of the fee collector contract and use it in the system to change how the fees are distributed.

## Recommended Mitigation Steps
Instead of marking the feeCollector variable as immutable in ClGaugeFactory and GaugeV3, consider allowing them to be updatable. For ClGaugeFactory, consider making the value updatable as done in the RamsesV3Factory using a restricted setter. For GaugeV3 instances, dynamically retrieve the feeCollector value from the ClGaugeFactory.
