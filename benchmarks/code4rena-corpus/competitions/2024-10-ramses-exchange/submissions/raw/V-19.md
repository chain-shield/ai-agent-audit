# Vulnerability details

## Description
The function [setPoolFeeProtocol](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L127-L134) and [setPoolFeeProtocolBatch](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Factory.sol#L137-L146) makes an external call to [RamsesV3Pool](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L728-L730) in order to set the fee of the protocol respectively as seen;

```solidity
IRamsesV3Pool(pool).setFeeProtocol();
```

```solidity
IRamsesV3Pool(pools[i]).setFeeProtocol();
```
This is the [setFeeProtocol](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L728-L730) function in RamsesV3Pool
```solidity
 function setFeeProtocol() external override lock {
        ProtocolActions.setFeeProtocol(factory);
    }

```
As seen, this function in turn calls another function in ProtocolAction, [setFeeProtocol](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/libraries/ProtocolActions.sol#L29-L40).
This is the setFeeProtocol in ProtocolActions
```solidity
function setFeeProtocol(address factory) external {
        PoolStorage.PoolState storage $ = PoolStorage.getStorage();

        uint8 feeProtocolOld = $.slot0.feeProtocol;

        uint8 feeProtocol = IRamsesV3Factory(factory).poolFeeProtocol(address(this));

        if (feeProtocol != feeProtocolOld) {
            $.slot0.feeProtocol = feeProtocol;
            emit SetFeeProtocol(feeProtocolOld, feeProtocol);
        }
    }
```

As seen, this last functions has no access control and can be called by anyone. This oversight gives an attacker the freedom to call this external function and set the fee to any value which could create havoc for the protocol.

Also, this shows that an attacker can bypass the access control in RamsesV3factory and RamsesV3Pool to set the protocol fee to a malicious value.
## Impact
This can lead to unauthorized changes in the fee structure, potentially resulting in financial losses for users and destabilization of the pool’s economic model. An attacker could exploit this vulnerability to set the fee protocol to a malicious value, adversely affecting users who interact with the pool.

An attacker can bypass the access control in RamsesV3factory and RamsesV3Pool.
