# Vulnerability details

Proof of Concept:

Imagine a batch update with 5 pools.
The first 3 pools are processed successfully.
The 4th pool's setFeeProtocol call reverts due to an unexpected error in the pool's implementation.
The transaction reverts, but it's unclear whether the fee protocol changes for the first 3 pools are also reverted.

Recommended Mitigation: Implement clear error handling to ensure consistency:

Atomic Updates: Consider using a mechanism to make the batch update atomic, so either all pools are updated successfully, or the entire transaction reverts with no changes applied.

Partial Success Handling: If atomic updates are not feasible, provide a way to track which pools were successfully updated before the error occurred. This could involve emitting events for each successful update or using a separate data structure to record the status of each pool in the batch.
