# Vulnerability details

## Proof of Concept
The `swap` function doesn't have a `lock` modifier yet.
This means it can accept multiple swap requests at once.
And it gets the current tick info at the beginning of the swap and updates it at the end after the swap.
This gives attackers a chance to make extra profit.

An exchanger can divide the tokens he wants to swap into smaller amounts and call `swap` several times at once. These calls will execute the swap function, and each swap will proceed at the tick value of the first step.

In the case of a large amount exchange, the difference between the first tick and the next can lead to a large amount of extra profit.


## Recommended Mitigation Steps
- By adding `lock` modifier to `swap` function, we can stop such vulnerability.
https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/core/RamsesV3Pool.sol#L426
This can slow down the performance of the platform if a large number of people are trying to exchange at the same time.

- We can introduce another modifier to check if swap transaction is already in progress from the same account.
By doing this we can allow simultaneous swap actions from several accounts at the same time, and prevent reentrancy from one account.
