# Vulnerability details

## Proof of Concept
Improper Authorization Check in burn Function: The burn function checks if the token owner is authorized, but the authorization check could be bypassed if an attacker manipulates token ownership data, potentially burning tokens without permission.

Proof of Concept: If the isAuthorizedForToken modifier can be circumvented, an attacker may trigger the burn operation without actual ownership, causing loss for legitimate token holders.

Impact: Unauthorized token burns could lead to unintended financial losses for users, as they may find their tokens permanently removed.

## Recommended Mitigation Steps
1. Strengthen Ownership Verification: Ensure the ownership check involves both _checkAuthorized and _ownerOf.
2. Use Access Control Libraries: Consider libraries like OpenZeppelin’s Ownable for consistent owner checks.
Example Code with Fix
Make sure the authorization check is robust:
modifier isAuthorizedForToken(uint256 tokenId) {
    require(_ownerOf(tokenId) == msg.sender || _checkAuthorized(_ownerOf(tokenId), msg.sender, tokenId),
            "Not authorized");
    _;
}
