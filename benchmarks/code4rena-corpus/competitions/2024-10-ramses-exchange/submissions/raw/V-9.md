# Vulnerability details

`periodEarned` and `cachePeriodEarned` functions in GaugeV3.sol can return different values for the same input parameters due to inconsistent caching behavior.

From the different ways `cachePeriodEarned` is called throughout the contract

1. In `periodEarned`, it's called via a static call with `caching` set to false: [GaugeV3.sol#L262-L267](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/gauge/GaugeV3.sol#L262-L267)
```solidity
(bool success, bytes memory data) = address(this).staticcall(
    abi.encodeCall(
        this.cachePeriodEarned,
        (period, token, owner, index, tickLower, tickUpper, false)
    )
);

// @audit: Vulnerability here - staticcall with caching set to false
```

2. In other functions like `_getReward`, it's called directly with `caching` set to true: [GaugeV3.sol#L544-L560](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/gauge/GaugeV3.sol#L544-L560)

When `caching` is true, it updates storage variables, which can affect subsequent calls. When false, these updates are not made, potentially leading to different results.

## Impact
This inconsistency can result in users receiving incorrect reward amounts. The impact is high as it affects the core functionality of the contract - reward calculation and distribution. All users interacting with the gauge for reward claims are potentially affected.

## Proof of Concept
When `caching` is true, it updates storage variables, which can affect subsequent calls. When false, these updates are not made, potentially leading to different results.
