# Vulnerability details

## Proof of Concept
During creation of pools, the fee set for the pool is based upon the tick spacing specified by the pool creator as well as whether that specified tick spacing has an avialable fee structure in the `tickSpacingInitialFee` mapping. An example is such as this `tickSpacingInitialFee[1] = 100;`

There is a bounds limit set upon creating new tick spacing and fee structure as can be seen below:

```solidity
function enableTickSpacing(int24 tickSpacing, uint24 initialFee) external override restricted {
        require(initialFee < 1_000_000, FTL()); // @note making sure we don't go over this bound for fee
        require(tickSpacing > 0 && tickSpacing < 16384, 'TS');
        require(tickSpacingInitialFee[tickSpacing] == 0, 'TS!0'); // @audit allowing the fee to tick spacing being setup
        tickSpacingInitialFee[tickSpacing] = initialFee; // @note write
        emit TickSpacingEnabled(tickSpacing, initialFee);
    }
```

Once such tick & spacing structure has been created, it can then be used to deploy pools with such as can be seen in the `createPool` function below of the `RamsesV3Factory` contract:

```solidity
function createPool(
        address tokenA,
        address tokenB,
        int24 tickSpacing,
        uint160 sqrtPriceX96
    ) external override returns (address pool) {
        ...

@>        uint24 fee = tickSpacingInitialFee[tickSpacing];
        require(fee != 0, F0());
        ...

        parameters = Parameters({
            factory: address(this),
            token0: token0,
            token1: token1,
            fee: fee,
            tickSpacing: tickSpacing
        });
        pool = IRamsesV3PoolDeployer(ramsesV3PoolDeployer).deploy(token0, token1, tickSpacing);
        delete parameters;

        ...
    }
```

The issue is that a pool could be deployed with the following fee structure and tick spacing that is allowed:

```solidity
tickSpacingInitialFee[16383] = 999_999; @note rough example that keeps us beneath upper bounds for initialFee and tickSpacing
```

When such pools have been deployed however, its fee structure cannot go below 89% when trying to do so because of the if statement check below in `setFee` function of the RamsesV3Pool contract (snipped from the library ProtocolActions.sol):

```solidity
FILE: RamsesV3Pool.sol

function setFee(uint24 _fee) external override lock {
        ProtocolActions.setFee(_fee, factory);
    }
```

```solidity
FILE: ProtocolActions.sol

function setFee(uint24 _fee, address factory) external {
        PoolStorage.PoolState storage $ = PoolStorage.getStorage();
        if (msg.sender != factory) revert Unauthorized();
@>        if (_fee > 100000) revert InvalidFee();
        uint24 _oldFee = $.fee;
        $.fee = _fee;
        emit FeeAdjustment(_oldFee, _fee);
    }
```

For such pools, the fee cannot be reduced by say 80%. Also, once the reduction of over 90% happens to pass the > 100_000 check, such as 90000. It cannot go over even though such pool should be able to use the fee structure up to 1_000_000.

## Recommended Mitigation Steps
The diff below should replace the current `if` check of the pool:

```diff
+ if (_fee >= 1_000_000) revert InvalidFee();
- if (_fee > 100_000) revert InvalidFee();
```
