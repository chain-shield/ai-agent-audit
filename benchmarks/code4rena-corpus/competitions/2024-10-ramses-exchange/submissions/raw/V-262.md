Integer Overflow

Summary:
```solidity
    unchecked {
        position.tokensOwed0 += uint128(
            FullMath.mulDiv(
                feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
                position.liquidity,
                FixedPoint128.Q128
            )
        );
        position.tokensOwed1 += uint128(
            FullMath.mulDiv(
                feeGrowthInside1LastX128 - position.feeGrowthInside1LastX128,
                position.liquidity,
                FixedPoint128.Q128
            )
        );
    }
```

The code snippet demonstrates an integer overflow vulnerability. 

The `FullMath.mulDiv` function calculates the result of multiplying two numbers and then dividing by another number. 

If the product of `feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128` and `position.liquidity` exceeds the maximum value that can be represented by a `uint128`, an integer overflow will occur. This can lead to unexpected behavior, such as incorrect calculations or denial-of-service attacks.

The use of `unchecked` blocks prevents Solidity from performing bounds checks on arithmetic operations, increasing the risk of overflows.

The `FullMath.mulDiv` operation can result in a product exceeding the maximum value representable by `uint128`, leading to an overflow if the unchecked block prevents Solidity from performing bounds checks.




## Recommended Mitigation Steps
Some recommendations that would help to mitigate this vulnerability at the source code level: 


--Avoid the use of the `unchecked` blocks when performing arithmetic that could lead to overflows...In the case of the vulnerable source code above, remove the unchecked block to allow Solidity’s default overflow checks, like so:

```solidity
position.tokensOwed0 += uint128(
    FullMath.mulDiv(
        feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
        position.liquidity,
        FixedPoint128.Q128
    )
);
```
--Implement explicit checks to ensure that the result of FullMath.mulDiv does not exceed the maximum value of uint128. Advise devs that they can/should perform this check before casting the result, like so: 

```solidity
uint256 result = FullMath.mulDiv(
    feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,
    position.liquidity,
    FixedPoint128.Q128
);

require(result <= type(uint128).max, "Overflow detected");
position.tokensOwed0 += uint128(result);
```

--Use SafeMath libraries for performing arithmetic operations in Solidity. This library automatically checks for overflows and underflows. Advise devs to use these libraries like so, as an example: 

```solidity 
using SafeMath for uint256;

uint256 result = feeGrowthInside0LastX128.sub(position.feeGrowthInside0LastX128).mul(position.liquidity).div(FixedPoint128.Q128);
position.tokensOwed0 = position.tokensOwed0.add(uint128(result));
```

--Limiting liquidity inputs ....So, devs can also add validation checks for the liquidity parameter to ensure it doesn't exceed reasonable thresholds that might make overflow possible:

one example of this is as follows: 

```solidity
require(position.liquidity <= MAX_LIQUIDITY, "Liquidity too high");
```

finally, it is a good idea to also regularly audit any arithmetic operations on the blockchain looking for making sure the corner cases are covered and do not lead to integer overflows...
