# Vulnerability details

## Summary

The `increaseLiquidity` function in the Ramses V3 Position Manager contains a critical security oversight in its position validation logic. The issue stems from how the contract handles position retrieval and state modifications without verifying the existence of the underlying position.

## Code Snippet

```solidity
function increaseLiquidity(
    IncreaseLiquidityParams calldata params
) external payable override checkDeadline(params.deadline) returns (uint128 liquidity, uint256 amount0, uint256 amount1) {
    Position storage position = _positions[params.tokenId];  // bug: No existence check
    
    PoolAddress.PoolKey memory poolKey = _poolIdToPoolKey[position.poolId];

    IRamsesV3Pool pool;
    (liquidity, amount0, amount1, pool) = addLiquidity(/* params */);
}
```

The issue lies in how Solidity handles storage mappings. When accessing `_positions[params.tokenId]`, if the position doesn't exist, we get a default-initialized Position struct:

```solidity
struct Position {
    uint80 poolId;           // defaults to 0
    int24 tickLower;         // defaults to 0
    int24 tickUpper;         // defaults to 0
    uint128 liquidity;       // defaults to 0
    uint256 feeGrowthInside0LastX128;  // defaults to 0
    uint256 feeGrowthInside1LastX128;  // defaults to 0
    uint128 tokensOwed0;     // defaults to 0
    uint128 tokensOwed1;     // defaults to 0
}
```

## Impact

1. This becomes particularly dangerous when we look at how the contract uses this position data. Consider the pool key retrieval:

```solidity
PoolAddress.PoolKey memory poolKey = _poolIdToPoolKey[position.poolId];  // poolId is 0
```

For a non-existent position, `poolId` is 0, which could either:
- Retrieve an unrelated pool key if pool ID 0 exists
- Get a default pool key, leading to undefined behavior

2. Incorrect liquidity addition and fee calculation logic:

```solidity
bytes32 positionKey = PositionKey.compute(
    address(this),
    params.tokenId,
    position.tickLower,  // Using default 0
    position.tickUpper   // Using default 0
);

(, uint256 feeGrowthInside0LastX128, uint256 feeGrowthInside1LastX128, , ) = pool.positions(positionKey);

unchecked {
    position.tokensOwed0 += uint128(
        FullMath.mulDiv(
            feeGrowthInside0LastX128 - position.feeGrowthInside0LastX128,  // Using default 0
            position.liquidity,  // Using default 0
            FixedPoint128.Q128
        )
    );
}
```

3. State modifications that shouldn't be allowed on non-existent positions:

```solidity
unchecked {
    position.liquidity += liquidity;  // Modifying state of non-existent position
}

emit IncreaseLiquidity(params.tokenId, liquidity, amount0, amount1);
```

Looking at how other functions in the contract handle position validation, we see inconsistency. For example, the `positions` function properly checks existence:

```solidity
function positions(uint256 tokenId) external view returns (...) {
    Position memory position = _positions[tokenId];
    if (position.poolId == 0) revert InvalidTokenId(tokenId);  // Proper check
    // ...
}
```

And `decreaseLiquidity` implicitly checks through the authorization modifier:

```solidity
function decreaseLiquidity(
    DecreaseLiquidityParams calldata params
) external payable override isAuthorizedForToken(params.tokenId) {  // Includes ownership check
    Position storage position = _positions[params.tokenId];
    // ...
}
```

The vulnerability allows interaction with non-existent positions, potentially leading to:
- Storage corruption
- Incorrect pool interactions
- Invalid fee calculations
- Misleading events emission

## Fix

The proper fix requires adding position validation:

```solidity
function increaseLiquidity(
    IncreaseLiquidityParams calldata params
) external payable override checkDeadline(params.deadline) returns (uint128 liquidity, uint256 amount0, uint256 amount1) {
    Position storage position = _positions[params.tokenId];
    if (position.poolId == 0) revert InvalidTokenId(params.tokenId);
    
    // Proceed with existing logic
    PoolAddress.PoolKey memory poolKey = _poolIdToPoolKey[position.poolId];
    // ...
}
```
