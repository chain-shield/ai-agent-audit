# Vulnerability details

## Proof of Concept
Lack of Input Validation on Constructor Parameters: In the constructor function, several protocol fees and tick spacing values are set, which could lead to unforeseen consequences if invalid values are mistakenly assigned by the contract deployer.
code snippet:
constructor(address accessManager) AccessManaged(accessManager) { 
    tickSpacingInitialFee[1] = 100;
    ...
}


Impact: If an invalid fee or tick spacing value is set, it could result in pools with unexpected behavior. Incorrect tick spacing could also cause liquidity pools to behave unpredictably, affecting users’ ability to perform trades efficiently and possibly causing liquidity provider losses.

## Recommended Mitigation Steps
Implement input validation in the constructor to ensure all tick spacings and fees adhere to reasonable limits. Limit tick spacings to values that align with the liquidity pool’s intended usage

example:
// Example fix in the constructor:
constructor(address accessManager) AccessManaged(accessManager) { 
    require(accessManager != address(0), "Invalid Access Manager");
    tickSpacingInitialFee[1] = 100; // Safe value
    ...
}
