### Impact
The burn function in the RamsesV3Pool contract is vulnerable to a reentrancy attack due to the advancePeriod modifier calling a public function _advancePeriod(). 
Since _advancePeriod() is marked as public, it can be called externally, allowing an attacker to re-enter the burn function before the reentrancy guard (lock modifier) is activated. 
This can lead to inconsistent state changes, double spending, or loss of funds.

### Vulnerable Code
```Solidity
// https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/core/RamsesV3Pool.sol#L331-L361

    /// @inheritdoc IRamsesV3PoolActions
    function burn(
        uint256 index,
        int24 tickLower,
        int24 tickUpper,
        uint128 amount
    ) external override lock advancePeriod returns (uint256 amount0, uint256 amount1) {
        unchecked {
            (PositionInfo storage position, int256 amount0Int, int256 amount1Int) = _modifyPosition(
                ModifyPositionParams({
                    owner: msg.sender,
                    index: index,
                    tickLower: tickLower,
                    tickUpper: tickUpper,
                    liquidityDelta: -int256(uint256(amount)).toInt128()
                })
            );


            amount0 = uint256(-amount0Int);
            amount1 = uint256(-amount1Int);


            if (amount0 > 0 || amount1 > 0) {
                (position.tokensOwed0, position.tokensOwed1) = (
                    position.tokensOwed0 + uint128(amount0),
                    position.tokensOwed1 + uint128(amount1)
                );
            }


            emit Burn(msg.sender, tickLower, tickUpper, amount, amount0, amount1);
        }
    }
```

In the RamsesV3Pool contract, the burn function is protected by a lock modifier to prevent reentrancy.
However, the burn function also uses the advancePeriod modifier.
The _advancePeriod function inside the advancePeriod modifier is marked as public.
Because _advancePeriod() is public, it can be called externally. 
When burn is called, the advancePeriod modifier executes _advancePeriod() before the lock modifier activates the reentrancy guard. 
An attacker can exploit this by re-entering the burn function through an external call to _advancePeriod(), bypassing the reentrancy protection and potentially causing state inconsistencies or draining funds.

### Proof of Concept
