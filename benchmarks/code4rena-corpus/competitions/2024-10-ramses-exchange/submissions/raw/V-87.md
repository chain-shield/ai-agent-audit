# Vulnerability details

## Impact
The function `_modifyPosition` relies on the current price and tick from `slot0` to determine whether liquidity adjustments are required for a given position in a Uniswap V3-like liquidity pool. However, the `slot0` price is susceptible to manipulation by external actors, allowing them to force unnecessary liquidity adjustments. This can result in misallocation of tokens (either token0 or token1) and yield losses for the protocol, as the pool’s liquidity is incorrectly managed based on an artificially influenced price. If an attacker controls the tick, they can deliberately disrupt the liquidity distribution and reduce the protocol's efficiency.

## Proof of Concept

### Affected Code
The relevant function is `_modifyPosition`, which is responsible for making adjustments to the LP position based on the current tick fetched from `slot0`.

```solidity
Slot0 memory _slot0 = $.slot0;
```

The `_slot0.tick` value is used to check whether the current tick is inside or outside the liquidity range. This comparison determines whether more token0 or token1 needs to be allocated or withdrawn:

```solidity
if (_slot0.tick < params.tickLower) {
    amount0 = SqrtPriceMath.getAmount0Delta(
        TickMath.getSqrtRatioAtTick(params.tickLower),
        TickMath.getSqrtRatioAtTick(params.tickUpper),
        params.liquidityDelta
    );
} else if (_slot0.tick < params.tickUpper) {
    amount0 = SqrtPriceMath.getAmount0Delta(
        _slot0.sqrtPriceX96,
        TickMath.getSqrtRatioAtTick(params.tickUpper),
        params.liquidityDelta
    );
    amount1 = SqrtPriceMath.getAmount1Delta(
        TickMath.getSqrtRatioAtTick(params.tickLower),
        _slot0.sqrtPriceX96,
        params.liquidityDelta
    );
}
```

### Manipulation Scenario
An attacker could manipulate the `slot0` price through large trades or flash loans to push the tick out of range, forcing the protocol to reallocate liquidity. By influencing the tick to an extreme value, the attacker could trigger unnecessary liquidity adjustments. This would cause the protocol to demand excessive token0 or token1, leading to yield inefficiencies, higher gas costs, and potential losses.

### PoC Example
The `_modifyPosition` function first retrieves the current tick from `slot0`. If this value has been manipulated, the liquidity range check could falsely assume that the position is out of range, resulting in misallocated liquidity:

```solidity
if (_slot0.tick < params.tickLower) { // Manipulated value
    // The position is incorrectly assumed to be out of range
    amount0 = SqrtPriceMath.getAmount0Delta(
        TickMath.getSqrtRatioAtTick(params.tickLower),
        TickMath.getSqrtRatioAtTick(params.tickUpper),
        params.liquidityDelta
    );
}
```

## Recommended Mitigation Steps
 **Use TWAP Price**: Instead of relying on the current tick from `slot0`, use a Time-Weighted Average Price (TWAP) to smooth out short-term fluctuations and protect against price manipulation.
