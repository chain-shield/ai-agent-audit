# Vulnerability details

In the `Oracle.write` function, the condition `if (cardinalityNext > cardinality && index == (cardinality - 1))` allows for unchecked expansion of `cardinality` when `cardinalityNext` exceeds `cardinality + 1`. This behavior can lead to unexpected increments in `cardinality`, potentially causing observation data overwrites or unintended data gaps, depending on how `cardinalityNext` is set.

The issue arises because the condition allows for any value of `cardinalityNext` greater than `cardinality`, without restricting it to exactly `cardinality + 1`. As a result, the `cardinality` expansion could behave unpredictably, which can lead to errors in the observation data that is stored and subsequently queried.

```solidity
if (cardinalityNext > cardinality && index == (cardinality - 1)) {
    cardinalityUpdated = cardinalityNext;
} else {
    cardinalityUpdated = cardinality;
}
```

## Proof of Concept

The following scenario demonstrates the issue:

1. Assume `cardinality = 5`, `index = 4`, and `cardinalityNext = 7`.
2. The condition `cardinalityNext > cardinality && index == (cardinality - 1)` is true, so `cardinalityUpdated` is set to `cardinalityNext`, which is `7`.
3. The `indexUpdated` variable is then calculated as `(index + 1) % cardinalityUpdated`, wrapping around and potentially overwriting prior data or skipping expected data entries.

If `cardinalityNext` is not incrementally aligned with `cardinality`, this setup risks data integrity, as it could lead to overwriting or gaps in observation data due to unexpected increments in `cardinality`.

## Recommended Mitigation

To ensure that `cardinality` expands predictably without causing abnormal jumps or needing additional reverts, we suggest updating the condition to enforce an incremental increase to `cardinality + 1` whenever `cardinalityNext` exceeds `cardinality`. This adjustment corrects any unintended jumps by setting `cardinalityUpdated` to `cardinality + 1` rather than directly to `cardinalityNext`, preventing unexpected growth and maintaining smooth execution.

The mitigation would look as follows:

```solidity
if (cardinalityNext > cardinality && index == (cardinality - 1)) {
    cardinalityUpdated = cardinality + 1;
} else {
    cardinalityUpdated = cardinality;
}
```

This approach ensures controlled growth of `cardinality`, preserving data integrity and avoiding unexpected gaps or overwrites without requiring a revert.
