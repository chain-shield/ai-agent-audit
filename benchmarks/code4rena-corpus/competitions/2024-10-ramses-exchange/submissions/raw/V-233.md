# Vulnerability details

## Description:
The `setFee` function in `RamsesV3Factory` calls the `setFee` function in `ProtocolActions.sol` to adjust the fee for a specific pool. However, the implementation of `setFee` in `ProtocolActions.sol` includes a restriction: if `_fee > 100000`, it triggers a revert with `InvalidFee()`. The limit of `100000` basis points represents `1000%`, which is excessively high and will likely result in frequent reverts, as valid fee adjustments are usually well below this threshold.
## Impact:
This restriction effectively makes it impossible to set fees over `1000%`, causing the `setFee` function in `RamsesV3Factory` to revert every time such a fee is attempted. This not only makes certain fee adjustments unachievable but also restricts the system from implementing potentially valid configurations.
## Proof of Concept
-The following call will revert if _fee is set to any value above 100000:
```
function setFee(address _pool, uint24 _fee) external override restricted {
    IRamsesV3Pool(_pool).setFee(_fee);
    emit FeeAdjustment(_pool, _fee);
}
```
- The implementation in `ProtocolActions.sol` will fail as follows:
```
function setFee(uint24 _fee, address factory) external {
    if (_fee > 100000) revert InvalidFee();  // Reverts if fee is set above 100000 basis points (1000%)
    // Additional logic...
}
```

## Recommended Mitigation Steps
- Clarify or Adjust Fee Limits: Define a more realistic upper limit for `_fee` in `ProtocolActions.sol` or explicitly document the current restriction, clarifying permissible values for the `setFee` function.
