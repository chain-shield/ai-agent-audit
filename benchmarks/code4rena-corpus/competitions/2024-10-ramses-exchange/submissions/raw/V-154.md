# Vulnerability details

## Proof of Concept
 Lack of Reentrancy Protection: The deploy function does not guard against reentrancy attacks. If an external contract calls deploy and then re-enters it before the initial execution completes, it could manipulate state changes unexpectedly.
affected code: function deploy(address token0, address token1, int24 tickSpacing) external returns (address pool) {

Impact: An attacker could manipulate the pool deployment process, potentially creating multiple pools or draining funds from legitimate transactions. This could lead to the disruption of the liquidity pool creation mechanism.

## Recommended Mitigation Steps
Use the ReentrancyGuard pattern from OpenZeppelin or implement a simple state variable to prevent reentrant calls.
