# Vulnerability details

## Proof of Concept
Reentrancy Vulnerability: Reentrancy occurs when an external call is made to an untrusted contract that could recursively call back into the vulnerable contract before the initial function call completes.

Proof of Concept: An attacker can exploit this by creating a malicious contract that calls back into the SwapRouter during the pay execution.

Example: The pay() function, called within the uniswapV3SwapCallback function, could potentially introduce reentrancy risks if it interacts with an external contract, especially if it does not follow reentrancy safeguards.

Impact: Malicious actors could exploit this to call the function multiple times, draining funds or causing unexpected behavior.

## Recommended Mitigation Steps
1. Use the Checks-Effects-Interactions pattern.
2. Implement a reentrancy guard (e.g., using nonReentrant modifier).
