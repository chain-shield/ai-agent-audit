# Vulnerability details

## Vulnerability Detail
The `_modifyPosition` function contains a critical vulnerability in its liquidity adjustment mechanism. Arithmetic operations used to adjust liquidity can result in incorrect status updates.

## Root Cause
The vulnerability is rooted in the unsafe arithmetic operations when adjusting liquidity. The arithmetic operations on these lines can lead to invalid calculations.
```
$.liquidity = params.liquidityDelta < 0
    ? liquidityBefore - uint128(-params.liquidityDelta)
    : liquidityBefore + uint128(params.liquidityDelta);
```
Scenario:
Condition 1:
- `liquidityBefore`: 100
- `params.liquidityDelta`: -150

Operation:
- Since `params.liquidityDelta` is negative, we calculate:
`uint128(-params.liquidityDelta) = 150`
- Then, the operation performed is:
`liquidityBefore - uint128(-params.liquidityDelta) = 100 – 150`
- The result is -50, which cannot be represented in the `uint128` data type.

Condition 2:
- `liquidityBefore`: 2^128 - 1 (maximum value for `uint128`)
- `params.liquidityDelta`: 1

Operation:
- Since `params.liquidityDelta` is positive, we calculate:
- `liquidityBefore + uint128(params.liquidityDelta) = (2^128 - 1) + 1`
- The result is 2^128, which exceeds the maximum limit of `uint128`.

## Impact
The pool's liquidity state can become corrupted, leading to incorrect calculations for swaps, fees, and other operations.

## Recommended Mitigation Steps
Implement checks to ensure that arithmetic operations do not exceed the bounds of `uint128`.
