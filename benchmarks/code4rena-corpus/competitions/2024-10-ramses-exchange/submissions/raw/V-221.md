# Vulnerability details

## Proof of Concept

NonfungiblePositionManager.mint() allows a user to mint a liquidity position. In particular, a user can send ETH to the  ```NonfungiblePositionManager``` contract to pay for token0/token1 when it is WETH9. 

[https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/periphery/NonfungiblePositionManager.sol#L130-L182](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/periphery/NonfungiblePositionManager.sol#L130-L182)

However, since it is hard to exactly send the amount of ETH to cover such payments for token0/token1 as such amount is calcualted during the call of mint(). The user will likely leave some refund ETH In the contract after the completion of the mint() call. 


Unfortunately, the mint() function does not return the extra ETH to the user automatically. Although a user can call refundETH() to retrieve it, this call might be front-run by another user. who steals such refund ETH. There is no document for this function that a user must call refundETH (within one transaction) to prevent such stealing and lose.


## Recommended Mitigation Steps
Add refundETH() as the last line of the mint() function.
