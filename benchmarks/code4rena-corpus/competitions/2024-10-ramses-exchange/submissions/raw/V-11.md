# Vulnerability details

The `cachePeriodEarned` function checks if the period data has been written to storage using the `periodAmountsWritten` mapping. If it hasn't been written and `caching` is `false`, it calculates the amount but doesn't store it. This leads to inconsistencies between cached and actual earned rewards.

[GaugeV3.sol#cachePeriodEarned](https://github.com/code-423n4/2024-10-ramses-exchange/blob/236e9e9e0cf452828ab82620b6c36c1e6c7bb441/contracts/CL/gauge/GaugeV3.sol#L278-L335)
```solidity
        /// @dev get seconds from pool if not already written into storage
        if (!periodAmountsWritten[period][_positionHash]) {
            (bool success, bytes memory data) = address(pool).staticcall(
                abi.encodeCall(
                    IRamsesV3PoolState.positionPeriodSecondsInRange,
                    (period, owner, index, tickLower, tickUpper)
                )
            );

            if (!success) {
                return 0;
            }

            (periodSecondsInsideX96) = abi.decode(data, (uint256));

            if (period < _blockTimestamp() / WEEK && caching) {
                periodAmountsWritten[period][_positionHash] = true;
                periodNfpSecondsX96[period][
                    _positionHash
                ] = periodSecondsInsideX96;
            }
        } else {
            periodSecondsInsideX96 = periodNfpSecondsX96[period][_positionHash];
        }

        // @audit The following code calculates and returns an amount even when caching is false and the period data hasn't been written to storage.
        amount = FullMath.mulDiv(
            tokenTotalSupplyByPeriod[period][token],
            periodSecondsInsideX96,
            WEEK << 96
        );

        uint256 claimed = periodClaimedAmount[period][_positionHash][token];
        if (amount >= claimed) {
            amount -= claimed;
        } else {
            amount = 0;
        }

        return amount;
    }
```
The fact that the function proceeds to calculate and return an amount even when `caching` is false and the period data hasn't been written to storage. This can lead to inconsistencies between cached and actual earned rewards.

## Impact
Users may receive incorrect reward amounts when calling the `cachePeriodEarned` function with `caching` set to `false` for periods that haven't been written to storage.

## Proof of Concept
Call `cachePeriodEarned` with `caching` set to `false` for a period that hasn't been written to storage. Then call `periodEarned` for the same parameters. The results will differ.

Here's an example to demonstrate the bug:

1. Assume a user has a position with `owner` address, `index`, `tickLower`, and `tickUpper` values.
2. The user calls the `cachePeriodEarned` function with the following parameters:

   * `period`: A period that hasn't been written to storage yet
   * `token`: The reward token address
   * `owner`: The user's address
   * `index`, `tickLower`, `tickUpper`: The user's position details
   * `caching`: Set to `false`

3. The function will enter the `if` block since `periodAmountsWritten[period][_positionHash]` is `false`.
4. It will calculate `periodSecondsInsideX96` but won't store it because `caching` is `false`.
5. The function will then proceed to calculate `amount` using the `tokenTotalSupplyByPeriod` and `periodSecondsInsideX96` values.
6. Finally, it will return the calculated `amount`, even though the period data hasn't been written to storage and caching was not requested.

## Recommended Mitigation Steps
Adding an `else if` block to check if `caching` is `false` and returning 0 in that case, the function will ensure that no amount is calculated and returned when the period data hasn't been written to storage and caching is not requested.
