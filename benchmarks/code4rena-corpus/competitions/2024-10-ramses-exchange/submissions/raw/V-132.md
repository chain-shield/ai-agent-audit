### Impact
The ternary operator sets the fee to the feeProtocol variable value of 80 when the address is zero (or when _poolFeeProtocol[pool] returns 0 instead of setting the fee to 0.
This behaviour leads to unintended fee configurations.
The poolFeeProtocol function is intended to return the fee protocol specific to a pool.
However, when a pool’s _poolFeeProtocol is set to zero, indicating that the pool should have no fee protocol, the function incorrectly returns the global feeProtocol value (of 80) instead of zero.
This behaviour prevents pools from having a zero fee protocol (where N/A) and enforces the global fee protocol unintentionally.

***Affected Function***

### Proof of Concept (PoC)
The following Solidity code demonstrates how the poolFeeProtocol function fails to return zero when a pool’s fee protocol is explicitly set to zero.
```Solidity
// SPDX-License-Identifier: GPL-2.0-or-later
pragma solidity ^0.8.20;

import "RamsesV3Factory.sol";

contract TestRamsesV3Factory {
    RamsesV3Factory factory;

    constructor(RamsesV3Factory factory) {
        factory = RamsesV3Factory(factory);
    }

    function testPoolFeeProtocolZero() public {
        uint8 feeProtocol = 80;
        checkDebo = factory.poolFeeProtocol(address(0));
        require(checkDebo == uint8(0), "Value does not equate to zer(0)");
    }
}
```

***Expected Behaviour***
After setting a pool’s fee protocol to zero, calling poolFeeProtocol(pool) should return 0.

***Actual Behaviour***
The function returns the global feeProtocol value of 80 instead of 0.

## Recommended Mitigation Steps
Within the function, set feeProtocol to zero.
```Solidity

        uint8 feeProtocol = 0;
        return (_poolFeeProtocol[pool] == 0 ? feeProtocol : _poolFeeProtocol[pool]);
```
