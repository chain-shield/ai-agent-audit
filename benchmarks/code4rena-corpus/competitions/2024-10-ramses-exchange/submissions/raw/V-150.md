# Vulnerability details

## Proof of Concept
No Safeguards for feeProtocol and feeCollector Changes: The functions setFeeProtocol and setFeeCollector allow direct modification of global values that impact fee distribution without requiring a delay, multisig, or voter approval. If restricted access is compromised, an attacker could reroute or manipulate protocol funds.

Impact: Abrupt changes to the fee structure or fee collector could significantly impact revenue, diverting fees to an attacker or away from intended stakeholders. This would result in direct financial losses.

## Recommended Mitigation Steps
Implement a delay or require approval from multiple privileged accounts before changes to the feeProtocol or feeCollector. Consider multisig or a decentralized governance mechanism for added security.
Example:
function setFeeCollector(address _feeCollector) external restricted timeLocked { ... }
