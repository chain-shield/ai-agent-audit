# Vulnerability details

## Description:
The `setTreasuryFees` function in the Ramses contract allows the treasury fee to be adjusted within a range of `0-100%`, despite the documentation specifying a fixed treasury fee of `8%`. Additionally, the `setTreasury` function enables the owner to change the treasury address at any time, meaning a malicious or compromised owner could redirect all funds by setting `treasuryFees` to `100%` and assigning the treasury address to their own wallet. This mismatch between the documented fee structure and the contract implementation allows for unauthorized fund redirection.
## Impact:
This vulnerability enables a malicious owner to:

Set `treasuryFees` to `100%`, redirecting all protocol-generated revenue to the treasury.
Change the treasury address to an arbitrary address, allowing them to siphon all fee revenues.
This manipulation results in veRAM holders forfeiting their 72% share, effectively allowing all funds to be drained from the protocol and creating potential for significant user losses and reputational damage to Ramses.

## Proof of Concept
- Setting Treasury Fee to `100%`:
In the `setTreasuryFees` function:
```
require(_treasuryFees <= BASIS, FTL());  // BASIS is set to 10 000 which is 100%
```
This allows treasuryFees to be any value from 0% to 100%.

- Changing Treasury Address:
In the setTreasury function:
```
 function setTreasury(address _treasury) external override onlyTreasury {  
        emit TreasuryChanged(treasury, _treasury);     
        treasury = _treasury;                    
    }
```
This enables the owner to change the treasury address, allowing funds to be redirected to any arbitrary address.

- Attack Scenario:
A malicious owner could call setTreasury to set the treasury address to their wallet, then set treasuryFees to 100%, thereby redirecting all revenue to themselves, in direct contradiction to the protocol’s documented fee distribution.
## Recommended Mitigation:
-Enforce Hard-Coded Treasury Fee Limit:
Limit the treasury fee to a maximum of 8% in setTreasuryFees, aligning with the documented structure and preventing unauthorized fund diversion.
```diff
- require(_treasuryFees <= BASIS, FTL());  // BASIS is set to 10 000 which is 100%
+ require(_treasuryFees == 800 , "Treasury fee must remain 8%");
```
