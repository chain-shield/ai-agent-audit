# Vulnerability details

The  [swap( )](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/core/RamsesV3Pool.sol#L363) function is broken due to mismatch parameters 
## Proof of Concept
The  swap function uses [SwapCache](https://github.com/code-423n4/2024-10-ramses-exchange/blob/4a40eba36bc47eba8179d4f6203a4b84561a4415/contracts/CL/core/RamsesV3Pool.sol#L469) to store cache data. 

```solidity
    struct SwapCache {
        uint8 feeProtocol,
        uint128 liquidityStart;
        uint32 blockTimestamp;
        int56 tickCumulative;
        uint160 secondsPerLiquidityCumulativeX128;
        bool computedLatestObservation;
        uint32 previousPeriod;
    }
```

Its implementation in the function.

```solidity

        address recipient,

// @audit-issue   mismatch parameter

            feeProtocol: slot0Start.feeProtocol,

```
 As you can see, there's a clear mismatch between the `SwapCache` struct definition and its implementation in the swap function. The order of parameters in the initialization doesn't correspond to the order in the struct definition. This misalignment can lead to incorrect data assignments and potential runtime errors.



## Recommended Mitigation Steps
Change values to align with the order in the struct
```solidity
SwapCache memory cache = SwapCache({
    feeProtocol: slot0Start.feeProtocol,
    liquidityStart: $.liquidity,
    blockTimestamp: _blockTimestamp(),
    tickCumulative: 0,
    secondsPerLiquidityCumulativeX128: 0,

});

```
