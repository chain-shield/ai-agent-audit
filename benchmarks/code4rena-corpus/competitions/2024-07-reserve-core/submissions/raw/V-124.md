# Vulnerability details

## Impact
The protocol suffers from an inconsistent asset registry size, which can lead to incorrect accounting and potential issues with the BasketHandler contract that relies on the asset registry.

## Proof of Concept
`_registerIgnoringCollisions()` function which is called by `_register()`, adds the asset's ERC20 address to the `_erc20s` set even if the asset is already registered. This behavior leads to an incorrect increase in the size of the asset registry when registering an already registered asset. The inconsistent asset registration process will cause an incorrect asset registry size for the protocol, as the `_registerIgnoringCollisions()` function will add duplicate ERC20 addresses to the `_erc20s` set when an already registered asset is re-registered.

https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/AssetRegistry.sol#L232-L238
```solidity
function _registerIgnoringCollisions(IAsset asset) private returns (bool swapped) {
    // ...

    IERC20Metadata erc20 = asset.erc20();
    if (_erc20s.contains(address(erc20))) {
        if (assets[erc20] == asset) return false;
        else emit AssetUnregistered(erc20, assets[erc20]);
    } else {
        _erc20s.add(address(erc20));
    }

    // ...
}
```

The `_registerIgnoringCollisions()` function adds the asset's ERC20 address to the `_erc20s` set using `_erc20s.add(address(erc20))` even if the asset is already registered. This causes the size of the registry to increase incorrectly when an already registered asset is re-registered.

## Recommended Mitigation Steps
The `_registerIgnoringCollisions()` function should be modified to avoid adding the asset's ERC20 address to the `_erc20s` set if it's already present.
```solidity
function _registerIgnoringCollisions(IAsset asset) private returns (bool swapped) {
    // ...

    IERC20Metadata erc20 = asset.erc20();
    if (_erc20s.contains(address(erc20))) {
        if (assets[erc20] == asset) return false;
        else emit AssetUnregistered(erc20, assets[erc20]);
-   } else {
-       _erc20s.add(address(erc20));
    }
+   _erc20s.add(address(erc20));

    // ...
}
```
By moving the `_erc20s.add(address(erc20))` line outside the `if` statement, the size of the registry will only increase when a new asset is registered, and it will remain unchanged when registering an already registered asset.
