# Vulnerability details

## Impact

Users can't withdraw due to wrong validation in **RecollateralizationLib.sol** contract 

## Proof of Concept

- Wrong validation in **RecollateralizationLib.sol** library in **prepareRecollateralizationTrade** function.
- There is assert to make sure doTrade is always true revert otherwise.
[assert(doTrade)](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/mixins/RecollateralizationLib.sol#L75)
```solidity

     function prepareRecollateralizationTrade(

// At this point doTrade _must_ be true, otherwise nextTradePair assumptions are broken
 >>>	assert(doTrade); 

		return (doTrade, req, trade.prices);
}
```

- Now looking were this function is used,
- This function is called in the **BackingManager.sol** contract in **rebalance** function.
- First reading the comment and the intended behavior.
- Incase we run out of capital and still undercollateralized we do a haircut
[backingManager:rebalance-line-135](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BackingManager.sol#L135-L146)
```solidity

/*

* Recollateralization
* 
* Strategy: iteratively move the system on a forgiving path towards collateralization
* through a narrowing BU price band. The initial large spread reflects the
* uncertainty associated with the market price of defaulted/volatile collateral, as
* well as potential losses due to trading slippage. In the absence of further
* collateral default, the size of the BU price band should decrease with each trade
* until it is 0, at which point collateralization is restored.
*
* If we run out of capital and are still undercollateralized, we compromise
* rToken.basketsNeeded to the current basket holdings. Haircut time.
*/
```
- In-order to do a haircut when we run out of capital and still undercollateralized,
- We enter else in if else statement 
- First the first if checks if doTrade is true which always true
- Due to previous call to **prepareRecollateralizationTrade** in line 153 its always true 
- Other wise it reverts.
[backingManager:rebalance-line-148](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BackingManager.sol#L148-L172)

- For that we never enter else statement in the **rebalance** function,
- We will never be able to do a haircut and never compromise the **rToken.basketsNeeded**.  
- In this case will always be undercollateralized.
- Impact of being undercollateralized arise in 
	-  **StRSR.sol** contract in the **withdraw** function which require to be **fullyCollateralized** in this case it isn't 
	- We can never withdraw.
