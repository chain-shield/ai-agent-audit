# Vulnerability details

## Vulnerability Details
The `swapRegistered` function in the AssetRegistryP1 contract is designed to replace an existing registered asset with a new one. It relies on the `quantity` function from the BasketHandler to determine if the basket should be disabled.

The vulnerability stems from the `quantity` function's behavior, which can return non-zero values or potentially revert under certain conditions. This behavior can be exploited to force the basket to be disabled, disrupting the system's normal operation.

## Code Snippets
1. Vulnerable part in `swapRegistered`:
```solidity
try basketHandler.quantity{ gas: _reserveGas() }(asset.erc20()) returns (uint192 quantity) {
    if (quantity != 0) basketHandler.disableBasket(); // not an interaction
} catch {
    basketHandler.disableBasket();
}
```

2. `quantity` function implementation:
```solidity
function quantity(IERC20 erc20) public view returns (uint192) {
    try assetRegistry.toColl(erc20) returns (ICollateral coll) {
        return _quantity(erc20, coll, CEIL);
    } catch {
        return FIX_ZERO;
    }
}

function _quantity(
    IERC20 erc20,
    ICollateral coll,
    RoundingMode rounding
) internal view returns (uint192) {
    uint192 refPerTok = coll.refPerTok();
    if (refPerTok == 0) return FIX_MAX;
    return basket.refAmts[erc20].div(refPerTok, rounding);
}
```

## Impact
An attacker can exploit this vulnerability to force the basket to be disabled frequently, causing:
1. Disruption of normal system operations
2. Increased gas costs for legitimate users
3. Potential loss of trust in the system

## Scenario
1. An attacker identifies a collateral token where `refPerTok` can be manipulated to return 0.
2. The attacker waits for a legitimate governance action to swap an asset.
3. Just before the swap, the attacker manipulates the collateral token to make `refPerTok` return 0.
4. When `swapRegistered` is called, `quantity` returns FIX_MAX (non-zero).
5. The basket is automatically disabled, disrupting the system.

## Fix
Instead of automatically disabling the basket, implement a more graceful approach:

```solidity
function swapRegistered(IAsset asset) external governance returns (bool swapped) {
    require(_erc20s.contains(address(asset.erc20())), "no ERC20 collision");

    bool basketNeedsReview = false;
    try basketHandler.quantity{ gas: _reserveGas() }(asset.erc20()) returns (uint192 quantity) {
        if (quantity == FIX_MAX) {
            basketNeedsReview = true;
        }
    } catch {
        basketNeedsReview = true;
    }

    swapped = _registerIgnoringCollisions(asset);

    if (basketNeedsReview) {
        emit BasketNeedsReview(asset.erc20());
    }
}
```

This fix:
1. Only flags the basket for review instead of disabling it.
2. Specifically checks for FIX_MAX, which indicates a potential issue with `refPerTok`.
3. Allows the swap to proceed while alerting governance to review the basket.
