# Vulnerability details

## Description

The `BackingManagerP1` contract is responsible for managing the backing of an RToken, including handling trades and rebalancing the collateral. The [`rebalance()` function](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BackingManager.sol#L107-L172) is a critical part of this process, ensuring that the system remains properly collateralized by executing trades when necessary. However, there is an issue in the `rebalance()` function related to the improper management of the `tradesOpen` variable and the `tradeEnd` timestamp.

The [`rebalance()` function checks if `tradesOpen` is zero ](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BackingManager.sol#L120) and if the `tradeEnd` timestamp for the given `TradeKind` is less than the current block timestamp. However, the function does not properly manage the state of `tradesOpen` during the execution of trades. Specifically, it fails to increment `tradesOpen` before executing a trade and decrement it afterward. This can lead to incorrect state management, where multiple trades might be considered open simultaneously, violating the `require(tradesOpen == 0, "trade open");` check.

## Impact
The improper management of the `tradesOpen` variable can lead to incorrect state management, where multiple trades might be considered open simultaneously. This can cause logical errors in the contract's operation, potentially leading to incorrect collateralization states and other unintended behaviors. 

## Proof of Concept
1. A user calls the `rebalance()` function.
2. The function checks if `tradesOpen` is zero and proceeds with the trade execution.
3. The function does not increment `tradesOpen` before executing the trade.
4. Another call to `rebalance()` is made while the first trade is still open.
5. The second call incorrectly assumes that no trades are open, leading to potential state inconsistencies.

## Recommended Mitigation Steps
To fix this issue, ensure that `tradesOpen` is properly managed by incrementing it before executing a trade and decrementing it afterward. Here is the recommended fix:

```diff
function rebalance(TradeKind kind) external nonReentrant {
    requireNotTradingPausedOrFrozen();

    // == Refresh ==
    assetRegistry.refresh();

    // DoS prevention:
    // unless caller is self, require that the next auction is not in same block
    require(
        _msgSender() == address(this) || tradeEnd[kind] < block.timestamp,
        "already rebalancing"
    );

    require(tradesOpen == 0, "trade open");
    require(basketHandler.isReady(), "basket not ready");
    require(block.timestamp >= basketHandler.timestamp() + tradingDelay, "trading delayed");

    BasketRange memory basketsHeld = basketHandler.basketsHeldBy(address(this));
    require(basketsHeld.bottom < rToken.basketsNeeded(), "already collateralized");

    // First dissolve any held RToken balance (above Distributor-dust)
    uint256 balance = rToken.balanceOf(address(this));
    if (balance >= MAX_DISTRIBUTION * MAX_DESTINATIONS) rToken.dissolve(balance);
    if (basketsHeld.bottom >= rToken.basketsNeeded()) return; // return if now capitalized

    (TradingContext memory ctx, Registry memory reg) = tradingContext(basketsHeld);
    (
        bool doTrade,
        TradeRequest memory req,
        TradePrices memory prices
    ) = RecollateralizationLibP1.prepareRecollateralizationTrade(ctx, reg);

    if (doTrade) {
        IERC20 sellERC20 = req.sell.erc20();

        // Seize RSR if needed
        if (sellERC20 == rsr) {
            uint256 bal = sellERC20.balanceOf(address(this));
            if (req.sellAmount > bal) stRSR.seizeRSR(req.sellAmount - bal);
        }

        // Execute Trade
+       tradesOpen += 1; // Increment tradesOpen before executing the trade
        ITrade trade = tryTrade(kind, req, prices);
        tradeEnd[kind] = trade.endTime(); // {s}
        tokensOut[sellERC20] = trade.sellAmount(); // {tok}
+       tradesOpen -= 1; // Decrement tradesOpen after executing the trade
    } else {
        // Haircut time
        compromiseBasketsNeeded(basketsHeld.bottom);
    }
}
```
