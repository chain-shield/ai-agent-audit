# Vulnerability details

`settleTrade` function is being called by the `DutchTrade` auction contract when someone make a bid but also can be called in the `backingManager` bassicly deleting the trade and sending the token to 0 address which is a waste of money of loss of money for the project.

The problem is that this allow attacker to front run the `bid` tx settle the trade in the `backingManager`  manager diracly making the project loss money.


Note that this is always true when the  `block.timestamp > endTime`

## Impact
Reserve protocol could loss money because in case that the `block.timestamp > endTime` and not bidder yet an attacker can just front run a bid tx or simple call `settleTrade` in the `BackingManager` sending this tokens to 0 address in the `settle` function in the DutchTrade.

Note: this just apply for `DutchTrade.sol` auction

## Proof of Concept
```solidity

 function settleTrade(IERC20 sell) public override(ITrading, TradingP1) returns (ITrade trade) {
        delete tokensOut[sell];
        trade = super.settleTrade(sell); // nonReentrant

        // if the settler is the trade contract itself, try chaining with another rebalance()
        if (_msgSender() == address(trade)) {
            // solhint-disable-next-line no-empty-blocks
            try this.rebalance(trade.KIND()) {} catch (bytes memory errData) {
                // prevent MEV searchers from providing less gas on purpose by reverting if OOG
                // untested:
                //     OOG pattern tested in other contracts, cost to test here is high
                // see: docs/solidity-style.md#Catching-Empty-Data
                if (errData.length == 0) revert(); // solhint-disable-line reason-string
            }
        }
    }
```
