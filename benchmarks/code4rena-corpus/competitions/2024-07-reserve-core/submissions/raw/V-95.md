# Vulnerability details

## Where is the bug

[issueTo()](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/p1/RToken.sol#L105) of [RToken.sol](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/p1/RToken.sol#L105). This function allows for the minting of `RTokens` without assertively checking or updating token allowances before transferring the tokens from the issuer to the backing manager. I place this as a medium risk given `notIssuancePausedOrFrozen` modifier allows for pausing issuance, but still the bug needs attention and is not hard to mitigate.

## Impact

So the issue is that it allows users to mint `RTokens` without effective allowance checks, opening:

1. Opening up unauthorized minting of `RTokens` beyond approved amounts.
2. Inflationary vectors of the `RToken` supply without adequate collateral backing.

## Recommended Mitigation Steps

1. Make sure to do explicit allowance checks in `issueTo`, as so:

```solidity
function issueTo(address recipient, uint256 amount) public notIssuancePausedOrFrozen {
    // this part same

    (address[] memory erc20s, uint256[] memory deposits) = basketHandler.quote(
        amtBaskets,
        true,
        CEIL
    );

    // Check allowances before any transfers
    for (uint256 i = 0; i < erc20s.length; ++i) {
        require(
            IERC20Upgradeable(erc20s[i]).allowance(issuer, address(this)) >= deposits[i],
            "RToken: insufficient allowance"
        );
    }

    // Perform transfers
    _scaleUp(recipient, amtBaskets, supply);
    for (uint256 i = 0; i < erc20s.length; ++i) {
        IERC20Upgradeable(erc20s[i]).safeTransferFrom(
            issuer,
            address(backingManager),
            deposits[i]
        );
    }
}
```

Above mitigation is done so that all required allowances are checked before any transfers occur, preventing partial issuance in case of insufficient allowances.
