# Vulnerability details

## Impact
Owners can deprecate old versions if there is a critical bug in old versions that can hurt users ,if a version have been deprecated ,deployers still can use that version 
## Proof of Concept
**Textual PoC:**
let's assume 
1-Admin calls [`VersionRegsitry::deprecateVersion(1)`](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/registry/VersionRegistry.sol#L59),hence isDeprecated[1] will be true

2-Admin deploys new deployer contract
3-Admin calls [`VersionRegsitry::registerVersion(new deployer)`](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/registry/VersionRegistry.sol#L37) to register new version
3-Alice calls `oldDeployer::deploy()` function and deploy new rToken base on old deployer contract version

## Tools Used
Manually 

## Recommended Mitigation Steps

Deployer cantract should have access to versionRegsitry and for every deploy rToken that has to check version for deprecated or not
