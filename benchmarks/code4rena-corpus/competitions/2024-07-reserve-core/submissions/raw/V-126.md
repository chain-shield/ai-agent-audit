# Vulnerability details

## Impact
The `freezeShort()` function in the `Auth.sol` contract currently revokes the SHORT_FREEZER role before applying the system freeze. This implementation deviates from the intention described in the docs:

1. If the freeze application fails after the role revocation, the system will be left in a vulnerable state without the SHORT_FREEZER's ability to take action.
2. The premature loss of the SHORT_FREEZER role reduces the system's resilience and capacity to respond swiftly to emergencies.


## Proof of Concept
The [documentation](https://reserve.org/protocol/smart_contracts/#system-states-and-roles) clearly states the expected behavior:
> When the SHORT_FREEZER call freezeShort(), they relinquish their SHORT_FREEZER role, and can only be re-granted the role by the OWNER (governance).

Take a look at the [`Auth.sol`](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/mixins/Auth.sol#L124-L128):

```solidity
function freezeShort() external onlyRole(SHORT_FREEZER) {
    // Revoke short freezer role after one use
    _revokeRole(SHORT_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + shortFreeze);
}
```

The sequence of operations in this implementation is a problem. The SHORT_FREEZER role is revoked before invoking the `freezeUntil()` function. If `freezeUntil()` encounters an exception and reverts (e.g., due to the new freeze time being less than or equal to the current `unfreezeAt`), the SHORT_FREEZER will lose their role without successfully freezing the system.

This leads to a situation where the system remains unfrozen, but the SHORT_FREEZER no longer possesses the necessary privileges to take corrective action, leaving the system exposed to potential threats.

## Recommended Mitigation Steps
To allign with the docs, modify the `freezeShort()` function as follows:

```diff
function freezeShort() external onlyRole(SHORT_FREEZER) {
-   // Revoke short freezer role after one use
-   _revokeRole(SHORT_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + shortFreeze);
+   // Revoke short freezer role after successful freeze
+   _revokeRole(SHORT_FREEZER, _msgSender());
}
```

By applying the freeze before revoking the SHORT_FREEZER role, we guarantee that the system enters the frozen state as intended. Only after the successful execution of `freezeUntil()` should the role be revoked, ensuring that the SHORT_FREEZER's capabilities are preserved until the system is securely frozen.
