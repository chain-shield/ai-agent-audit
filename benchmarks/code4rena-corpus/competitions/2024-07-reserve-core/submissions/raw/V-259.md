# Vulnerability details

## Impact
An important consideration when dealing with nonces in smart contracts (which are necessary for keeping a track of changes or transactions in a system) is verifying their validity. 

In BasketHandler.sol, there doesn't appear to be a sufficient check for nonexistent basket nonces. Specifically, in the `getHistoricalBasket` function, the basket nonce is used to retrieve a historical basket based on it. 

However, there is no check to determine if a basket with that nonce doesn't exist, which could lead to an unexpected behavior or errors.

## Proof of Concept

Here's the code snippet that does not check for a nonexistent basket nonce:

https://github.com/reserve-protocol/protocol/blob/master/contracts/p1/BasketHandler.sol#L648-L653

```solidity
function getHistoricalBasket(uint48 basketNonce) external view returns (IERC20[] memory erc20s, uint256[] memory quantities) {
    Basket storage b = basketHistory[basketNonce];
    ...
}
```
Removing this validation makes the code vulnerable to access and requests by unauthorized users, which might cause unexpected behavior or increase the attack surface of the smart contract.


## Tools Used

## Recommended Mitigation Steps

To fix this vulnerability, it is recommended to add a check that verifies the existence of the provided nonce in the `basketHistory` mapping before performing any operations.

An example of how to implement such a check could be as follows:
```solidity
function getHistoricalBasket(uint48 basketNonce) external view returns (IERC20[] memory erc20s, uint256[] memory quantities) {
    require(basketHistory[basketNonce].exists, "Basket nonce not exist");
    Basket storage b = basketHistory[basketNonce];
    ...
}
```
In this adjusted code, the function checks if the requested basket nonce exists before returning the corresponding basket. 

If the basket nonce does not exist, an error is triggered.
