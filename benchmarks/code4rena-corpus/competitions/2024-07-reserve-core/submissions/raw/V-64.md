# Vulnerability details

## Description

The `BasketHandlerP1` contract implements a custom redemption mechanism through its [`quoteCustomRedemption()` function.](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BasketHandler.sol#L521-L602) This function allows users to redeem tokens based on a linear combination of historical basket configurations. It takes two key parameters: `basketNonces` (representing historical basket states) and `portions` (representing the proportion of each basket to be used in the redemption).

The function iterates through the provided `basketNonces`, calculating a linear combination of historical baskets based on the corresponding `portions`. However, a critical oversight in the implementation is the lack of validation to ensure that the sum of `portions` equals 1 (or `FIX_ONE` in fixed-point arithmetic).

The relevant part of the code is as follows:

```solidity
function quoteCustomRedemption(
    uint48[] memory basketNonces,
    uint192[] memory portions,
    uint192 amount
) external view returns (address[] memory erc20s, uint256[] memory quantities) {
    require(basketNonces.length == portions.length, "invalid lengths");

    // ... (code omitted for brevity)

    for (uint48 i = 0; i < basketNonces.length; ++i) {
        require(
            basketNonces[i] >= lastCollateralized && basketNonces[i] <= nonce,
            "invalid basketNonce"
        );
        
        // ... (calculation of linear combination)
    }

    // ... (calculation of redemption quantities)
}
```

This oversight allows malicious users to manipulate the redemption process by providing `portions` that sum to values other than 1. This can lead to two primary attack vectors:

1. Inflation Attack: By providing `portions` that sum to more than 1, an attacker can artificially inflate the redemption value, receiving more tokens than they are entitled to.
2. Deflation Attack: Conversely, by providing `portions` that sum to less than 1, an attacker can potentially game the system in certain market conditions, redeeming fewer tokens than required.

The highest impact scenario would be an inflation attack where an attacker could significantly increase their redemption value, potentially draining excess tokens from the protocol.

## Impact

The lack of portion sum validation in the `quoteCustomRedemption` function can lead to significant financial losses and undermine the trust in the protocol. Exploiting this bug can result in users redeeming more or fewer tokens than they are entitled to, leading to an uneven distribution of assets and potential manipulation of the redemption process.


## Proof of Concept

Consider the following scenario:

1. Alice, a malicious user, identifies the vulnerability in `quoteCustomRedemption()`.
2. Alice prepares a transaction to `quoteCustomRedemption()` with the following parameters:
   - `basketNonces`: [100, 101, 102] (assuming these are valid historical basket nonces)
   - `portions`: [0.5, 0.5, 0.5] (note that these sum to 1.5, which is greater than 1)
   - `amount`: 100 (arbitrary redemption amount)
3. Alice submits the transaction.
4. The `quoteCustomRedemption()` function processes the request without validating the sum of `portions`.
5. The function calculates the redemption quantities based on the inflated portions, resulting in Alice receiving 50% more tokens than she should.
6. Alice successfully redeems an inflated amount of tokens, draining excess assets from the protocol.

## Recommended Mitigation Steps

To mitigate this vulnerability, implement a check to ensure that the sum of `portions` equals 1 (or `FIX_ONE` in fixed-point arithmetic) before processing the redemption. Here's a recommended fix:

```diff
function quoteCustomRedemption(
    uint48[] memory basketNonces,
    uint192[] memory portions,
    uint192 amount
) external view returns (address[] memory erc20s, uint256[] memory quantities) {
    require(basketNonces.length == portions.length, "invalid lengths");

+   // Validate that the sum of portions equals 1
+   uint192 totalPortion = FIX_ZERO;
+   for (uint48 i = 0; i < portions.length; ++i) {
+       totalPortion = totalPortion.plus(portions[i]);
+   }
+   require(totalPortion == FIX_ONE, "portions must sum to 1");

    // ... (rest of the function remains unchanged)
}
```
