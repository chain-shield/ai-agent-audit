# Vulnerability details

## Impact

In the contract Auth.sol, the functions `freezeShort()` and `freezeLong()` are designed to apply a freeze to the contract for a certain duration, depending on the function used. 

However, after the freeze duration has been set, the caller's role is revoked using `_revokeRole()`, but this operation may not complete if there are failures in the external calls, permitting the user to re-enter the function.

An attacker can exploit re-entrancy vulnerabilities by beginning a function call and then, before the function call is completed, calling the function again (re-entering it). If the function's state is not updated until the end of the function, an attacker could potentially continue to re-enter and exploit the function. 

This is especially critical as it affects a consequential aspect of the contract: freezing its functionality, hence, potentially allowing for system-wide misuse.

## Proof of Concept


```solidity
function freezeShort() external onlyRole(SHORT_FREEZER) {
    _revokeRole(SHORT_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + shortFreeze);
}

function freezeLong() external onlyRole(LONG_FREEZER) {
    longFreezes[_msgSender()] -= 1;
    if (longFreezes[_msgSender()] == 0) _revokeRole(LONG_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + longFreeze);
}
```
In both of these cases, the `revokeRole` operation should be the last operation in the function to prevent re-entrancy attacks.

## Recommended Mitigation Steps

The issue can be mitigated by performing state-changing operations (like decrementing values or revoking roles) at the end of the function. 

Alternatively, implementing a mutex (or re-entrancy guard) could provide protection. A mutex is a flag that signifies if some function is currently executing. 

By checking and setting a mutex in each publicly accessible function, it is possible to ensure that once a function is executing, no other function that checks this mutex will be able to execute.

Here's a simple mutex implementation:

```solidity
bool internal locked;
modifier noReentrancy() {
    require(!locked, "Reentrant call.");
    locked = true;
    _;
    locked = false;
}
```
Then apply this modifier to the affected functions:

```solidity
function freezeShort() external noReentrancy onlyRole(SHORT_FREEZER) {
    _revokeRole(SHORT_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + shortFreeze);
}

function freezeLong() external noReentrancy onlyRole(LONG_FREEZER) {
    longFreezes[_msgSender()] -= 1;
    if (longFreezes[_msgSender()] == 0) _revokeRole(LONG_FREEZER, _msgSender());
    freezeUntil(uint48(block.timestamp) + longFreeze);
}
```
This mechanism prevents recursive calling of these functions, hence mitigating potential re-entrancy issues.
