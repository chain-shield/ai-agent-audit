# Vulnerability details

## Vulnerability Details
The `DistributorP1` contract manages the distribution of revenue (RSR and RToken) to various destinations. The `_setDistribution` function is a core internal function used to set or update these distributions.

The `_setDistribution` function lacks a crucial check to ensure that the total distribution across all destinations remains valid after each update.

While the function checks individual distribution shares against `MAX_DISTRIBUTION`, it doesn't verify that the sum of all distributions remains within acceptable bounds after an update. This could lead to a situation where the total distribution exceeds 100% or falls below the required minimum.

Code Snippet
```solidity
function _setDistribution(address dest, RevenueShare memory share) internal {
    // ... (existing checks)

    require(share.rsrDist <= MAX_DISTRIBUTION, "RSR distribution too high");
    require(share.rTokenDist <= MAX_DISTRIBUTION, "RToken distribution too high");

    if (share.rsrDist == 0 && share.rTokenDist == 0) {
        destinations.remove(dest);
    } else {
        destinations.add(dest);
        require(destinations.length() <= MAX_DESTINATIONS_ALLOWED, "Too many destinations");
    }

    distribution[dest] = share;
    emit DistributionSet(dest, share.rTokenDist, share.rsrDist);

    // Missing: Check total distribution after update
}
```

## Impact
This vulnerability could allow an attacker (if they gain governance rights) to:
1. Set distributions that collectively exceed 100%, leading to over-allocation of funds.
2. Reduce the total distribution below the required minimum, potentially breaking system invariants.
3. Manipulate distributions to favor certain destinations unfairly.

## Scenario
1. The current total distribution is at 100%.
2. An attacker calls `setDistribution` to increase a destination's share without decreasing others.
3. The total distribution now exceeds 100%, but the contract fails to detect this.

## Fix
Add a check after updating the distribution to ensure the total remains valid:

```solidity
function _setDistribution(address dest, RevenueShare memory share) internal {
    // ... (existing code)

    distribution[dest] = share;
    emit DistributionSet(dest, share.rTokenDist, share.rsrDist);

    // Add this check
    RevenueTotals memory revTotals = totals();
    _ensureSufficientTotal(revTotals.rTokenTotal, revTotals.rsrTotal);
    require(
        uint256(revTotals.rTokenTotal) + uint256(revTotals.rsrTotal) <= MAX_DISTRIBUTION * 2,
        "Total distribution too high"
    );
}
```

This fix ensures that after each update:
1. The total distribution doesn't fall below the minimum (using existing `_ensureSufficientTotal`).
2. The total distribution doesn't exceed the maximum allowed (100% for RSR and 100% for RToken).
