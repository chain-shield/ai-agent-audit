# Vulnerability details

## Impact
issue() either reverts or forces users to take more damage than desired.
## Proof of Concept
[issueTo](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/RToken.sol#L98-L105) requires that users first call basketHandler.quote()  to know how much they need to approve to get specified amount of rToken as it lacks a inbuilt slippage protection mechanism

quote() calls [issuancePremium(coll)](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/BasketHandler.sol#L500) on each collateral but there is a catch in issuancePremium() function i.e 
```solidity
function issuancePremium(ICollateral coll) public view returns (uint192) {
        // `coll` does not need validation
        if (!enableIssuancePremium || coll.lastSave() != block.timestamp) return FIX_ONE;        ///@audit < doesn't apply premium

        // Use try-catch for safety since `savedPegPrice()` was only added in 4.0.0 to ICollateral
        try coll.savedPegPrice() returns (uint192 pegPrice) {
            if (pegPrice == 0) return FIX_ONE;
            uint192 targetPerRef = coll.targetPerRef(); // {target/ref}
            if (pegPrice >= targetPerRef) return FIX_ONE;

            // {1} = {target/ref} / {target/ref}
            return targetPerRef.safeDiv(pegPrice, CEIL);
        /// @audit ^ 1/0.9997 > 1
        } catch {
            // if savedPegPrice() does not exist on the collateral the error bytes are 0 len
            return FIX_ONE;
        }
    }
```
coll.lastSave() is only updated when assetRegistry.refresh() is called, which is called when tokens move in or out of the system or **simply said coll.lastSave() == block.timestamp iff someone called redeem or issue or forwardRevenue in the same block before user** 
Otherwise it will return with FIX_ONE (1e18) meaning no issuance premium.

Now consider the following scenario-
A rToken has USDC as underlying 
At block time 10, alice issues some rTokens, coll.lastSave() = 10

At block time 11, bob calls quote(), issuancePremium=1e18 due to above conditional & let's assume quote returns 'x' amount of USDC required to mint 'y' BUs & bob approves 'x' amt

At block time 12, bob calls issue(), which first and foremost call [assetRegistry.refresh()](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/RToken.sol#L110) making coll.lastSave() = 12 == block.timesamp. So now FIX_ONE will not be returned instead the try catch block will be executed. 

 peg price of USDC is never equal 1$ exact in [chainlink feeds](https://data.chain.link/feeds/ethereum/mainnet/usdc-usd), its something like 0.9997 almost all time but in fiatCollateral targetPerRef() is [hardcoded](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/plugins/assets/FiatCollateral.sol#L214) to 1e18 which will be greater than pegPrice

so now issuancePremium will return a value **> FIX_ONE** leading a spike in quote increasing the quote amount to be **> 'x'** but bob only has approvals of 'x' leading to a revert.

It is important to note that **bob can always give infinite approvals but that would cause him a loss of funds due to slippage.** So, as stated in the inline docs, infinite approvals must never be used while issuing rTokens. hence bob will either not be able to issue or loose more funds than desired due to slippage . 

So in a nutshell when bob quote for approval the basketHandler.quote() said - no issuancePremium, but when calling issue() the basketHandler said- give issuancePremium, which leads to revert if not using infinite approval. **Leading to quote() giving less amount in quantities[] when user calls it but more when rToken calls it.**

## Recommended Mitigation Steps

The fix is simple-
```diff
    function issuancePremium(ICollateral coll) public view returns (uint192) {
        // `coll` does not need validation
--        if (!enableIssuancePremium || coll.lastSave() != block.timestamp) return FIX_ONE;
++        if(!enableIssuancePremium) return FIX_ONE;
```
this will lead to quote returning a better estimate of tokens to give approvals to.
