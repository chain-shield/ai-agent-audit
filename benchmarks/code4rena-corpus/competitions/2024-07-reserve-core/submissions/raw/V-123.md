# Vulnerability details

## Vulnerability details
When a collateral token defaults, the protocol needs to quickly and efficiently recapitalize to ensure the stability and redeemability of the RToken. This is done by selling off the defaulted collateral through auctions and using the proceeds to purchase predefined emergency collateral. On that occasion gnosis auction model is used to auction the default collateral. But when initiating gnoiss auction its reverted . Due to gnosis auction model is failed to start ,  protocol is going to a insolvent state. 

## Proof of Concept
Its defined `status`  as a `TradeStatus.CLOSED` in the [constructor](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/plugins/trading/GnosisTrade.sol#L66C5-L68C6). It casused the failling to start gnosis auction. 

```solidity

     constructor() {
            status = TradeStatus.CLOSED;
        }
```

due to this calling [init](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/plugins/trading/GnosisTrade.sol#L90) function is reverted.

```solidity

     function init(
            IBroker broker_,
            address origin_,
            IGnosis gnosis_,
            uint48 batchAuctionLength,
            TradeRequest calldata req
        ) external stateTransition(TradeStatus.NOT_STARTED, TradeStatus.OPEN) {

```
Since [stateTransition](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/plugins/trading/GnosisTrade.sol#L59) modifier checking the TradeStatus.CLOSED == TradeStatus.NOT_STARTED . So its reverted .

```solidity
      modifier stateTransition(TradeStatus begin, TradeStatus end) {
            require(status == begin, "Invalid trade state");
            status = TradeStatus.PENDING;
            _;
            assert(status == TradeStatus.PENDING);
            status = end;
        }
```

## Impact
Its unable to start the gnosis auction due to revert `init` calling transaction. So Protocol is going to insolvent state due to unable to initiate the gnosis auction.
