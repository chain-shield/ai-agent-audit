# Vulnerability details

## Impact
Detailed description of the impact of this finding.

Contract: FurnaceP1
Function name: setRatio(uint192)
PC address: 2499
Estimated Gas Usage: 30644 - 164314

Multiple calls are executed in the same transaction

The failure of a call within the setRatio(uint192) function can halt the transaction, preventing subsequent operations from executing. 

This could lead to:

	•	Disrupted contract logic, affecting the stability and reliability of the contract.
	•	Potential exploitation by attackers to prevent the contract from executing as intended.
	•	Financial loss or disruption of contract services.

This call is executed following another call within the same transaction. 

It is possible that the call never gets executed if a prior call fails permanently. 

This might be caused by mistake by a trusted party or intentionally by a malicious callee. 

The issue arises from the following sequence:
```solidity
rToken.balanceOf(address(this)); // External call in setRatio
```

Given that the function relies on multiple external calls, the failure of one can cascade, preventing other critical operations from being executed. 

If the failing call is made by an attacker, this could be exploited to intentionally disrupt the execution of the contract.

## Recommended Mitigation Steps

To mitigate this issue, consider the following approaches:

1. Refactor the Code:
Refactor the setRatio(uint192) function to ensure that each transaction only executes one external call. This reduces the risk of a failed call preventing the execution of subsequent logic.

2. Use Try-Catch:
Implement a try-catch block around external calls to handle failures gracefully, ensuring that critical operations can still proceed even if a call fails.

```solidity
try rToken.balanceOf(address(this)) returns (uint256 balance) {
    // Continue with logic if call succeeds
} catch {
    // Handle failure, possibly re-throw or proceed with alternative logic
}
```

By implementing these mitigations, the risk of transaction failure due to multiple external calls in setRatio(uint192) can be significantly reduced, improving the contract’s resilience and reliability.
