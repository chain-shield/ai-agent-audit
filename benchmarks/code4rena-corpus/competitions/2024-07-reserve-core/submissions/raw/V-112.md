# Vulnerability details

## Where is the bug

So there is a bug is in [redeemCustom()](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/p1/RToken.sol#L253) function of the [RToken.sol](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/p1/RToken.sol) contract. Current logic is not correctly distributing the underlying tokens during the redemption process, currently distributing vastly different amounts of tokens being returned to the user.

## Impact

- Users redeeming `RTokens` receive drastically different amounts of underlying tokens, with some tokens being severely underrepresented.
- Financial losses for users redeeming `RTokens`.
- It currently undermines the fundamental principle of the `RToken` system, which should maintain a consistent backing ratio.
4. Exploiters could extract more value from certain tokens, therefore you get imbalances in the protocol's reserves.

it('Show incorrectly differing token distribution during redemption', async () => {
  const issueAmount: BigNumber = ethers.utils.parseUnits('1000', 18)
  await token0.connect(addr1).approve(rToken.address, issueAmount)
  await token1.connect(addr1).approve(rToken.address, issueAmount)
  await token2.connect(addr1).approve(rToken.address, issueAmount)
  await token3.connect(addr1).approve(rToken.address, issueAmount)

  // Issue RTokens
  await rToken.connect(addr1).issue(issueAmount)

  // Record initial balances
  const initialBalance0 = await token0.balanceOf(addr1.address)
  const initialBalance1 = await token1.balanceOf(addr1.address)
  const initialBalance2 = await token2.balanceOf(addr1.address)
  const initialBalance3 = await token3.balanceOf(addr1.address)

  // Perform a single large redemption
  await rToken.connect(addr1).redeemCustom(
    addr1.address,
    issueAmount,
    [1], // basket nonce
    [fp('1')], // portions
    [token0.address, token1.address, token2.address, token3.address],
    [0, 0, 0, 0] // min amounts, set to 0 to allow any amount
  )

  // Check final balances
  const finalBalance0 = await token0.balanceOf(addr1.address)
  const finalBalance1 = await token1.balanceOf(addr1.address)
  const finalBalance2 = await token2.balanceOf(addr1.address)
  const finalBalance3 = await token3.balanceOf(addr1.address)

  const received0 = finalBalance0.sub(initialBalance0)
  const received1 = finalBalance1.sub(initialBalance1)
  const received2 = finalBalance2.sub(initialBalance2)
  const received3 = finalBalance3.sub(initialBalance3)

  console.log('Token0 received:', ethers.utils.formatUnits(received0, 18))
  console.log('Token1 received:', ethers.utils.formatUnits(received1, 18))
  console.log('Token2 received:', ethers.utils.formatUnits(received2, 18))
  console.log('Token3 received:', ethers.utils.formatUnits(received3, 18))

  // Check if there's a significant discrepancy between received amounts
  const expectedRedemption = issueAmount.div(4) // For equal distribution among 4 tokens
  const tolerance = expectedRedemption.div(100) // 1% tolerance

  expect(received0).to.be.closeTo(expectedRedemption, tolerance)
  expect(received1).to.be.closeTo(expectedRedemption, tolerance)
  expect(received2).to.be.closeTo(expectedRedemption, tolerance)
  expect(received3).to.be.closeTo(expectedRedemption, tolerance)
})

## Recommended Mitigation Steps

- Fix the token distribution logic in the [redeemCustom()](https://github.com/code-423n4/2024-07-reserve/blob/main/contracts/p1/RToken.sol#L253):

```solidity
function redeemCustom(
    address recipient,
    uint256 amount,
    uint48[] memory basketNonces,
    uint192[] memory portions,
    address[] memory expectedERC20sOut,
    uint256[] memory minAmounts
) external notFrozen {
    // here is safe

    (address[] memory erc20s, uint256[] memory amounts) = basketHandler.quoteCustomRedemption(
        basketNonces,
        portions,
        baskets
    );

    // fix to make sure of consistent distribution
    uint256 totalSupply = totalSupply();
    for (uint256 i = 0; i < erc20s.length; ++i) {
        amounts[i] = IERC20(erc20s[i]).balanceOf(address(backingManager)).mul(amount).div(totalSupply);
    }

    // then transfer is good logic
}
```
Adjust to make sure of fair distribution of all underlying tokens.
