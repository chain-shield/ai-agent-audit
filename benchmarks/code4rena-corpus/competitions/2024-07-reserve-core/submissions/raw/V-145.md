# Vulnerability details

## Impact
The `resetStakes()` function is designed as a safety mechanism to reset all stakes and advance the era when the `stakeRate` is deemed unsafe. However, the function also resets the draft era by calling `beginDraftEra()` even when the `draftRate` is healthy. This action negatively impacts users who are withdrawing their `RSR` (already unstaked), as it forces a reset of their draft records. Consequently, users who have requested unstaking or are ready to fully withdraw their `RSR` (`availableAt` passed) will face losses, as their draft records will be reset/wiped out.

## Proof of Concept
In the `resetStakes()` function:
https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/StRSR.sol#L492-L499
```ruby
//check to ensure the current stakeRate is unsafe (either too high or too low)
require(
stakeRate <= MIN_SAFE_STAKE_RATE || stakeRate >= MAX_SAFE_STAKE_RATE,
"rate still safe"
);
// reset stakes and begin new era 
beginEra();
// reset draft and begin new draft era
@> beginDraftEra(); // This line resets the draft era even if draftRate is healthy
```
This snippet shows that the draft era is reset regardless of the condition of the `draftRate`, affecting users already in process of withdrawing their `RSR`.

Therefore, whenever the `stakeRate` is deemed unsafe and the governance voted for a reset, this always affect the draft even if the `draftRate` is healthy which either leads to loss of funds for users or governance will not be able to reset the stakes knowing users could loss their funds in the draft (i.e. DOS).

## Tools Used
Manual

## Recommended Mitigation Steps
Modify the `resetStakes()` function to only reset the draft era when the `draftRate` is also unsafe. This can be achieved by adding a conditional check similar to the one used for `stakeRate`. For example:

```ruby
if (stakeRate <= MIN_SAFE_STAKE_RATE || stakeRate >= MAX_SAFE_STAKE_RATE) {
    beginEra();
}

if (draftRate <= MIN_SAFE_DRAFT_RATE || draftRate >= MAX_SAFE_DRAFT_RATE) {
    beginDraftEra();
}
```
This change ensures that the draft era is only reset when necessary, preventing any unseen losses for users withdrawing their `RSR`.
