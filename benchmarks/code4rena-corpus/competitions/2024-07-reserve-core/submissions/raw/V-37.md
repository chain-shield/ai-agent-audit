# Vulnerability details

## Impact
Denial Of Services. A malicious user can overload the system by calling function `AssetRegistry::refresh` again and again to the point where the system becomes unusable for other users.

## Proof of Concept
The vulnerability lies in the `AssetRegistry::refresh` function, which update the state of all assets by making an external call to `trackStatus` before updating the contract state.

```solidiy
    function refresh() public {
        uint256 length = _erc20s.length();
        for (uint256 i = 0; i < length; ++i) {
            assets[IERC20(_erc20s.at(i))].refresh();
        }
        // External call
@>      basketHandler.trackStatus(); 

        // State change
@>      lastRefresh = uint48(block.timestamp); 
    }
```

## Tools Used
Manual analysis.

## Recommended Mitigation Steps
* **Implement Reentrancy Guard:** Add the `nonReentrant` modifier to the `AssetRegistry::refresh` function to prevent reentrancy attacks.
* **Reorder State Updates and External Calls:** Ensure that all state updates occur before any external calls to mitigate the risk of reentrancy.
