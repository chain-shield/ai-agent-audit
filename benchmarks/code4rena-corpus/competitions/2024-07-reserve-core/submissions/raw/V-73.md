# Vulnerability details

## Description

The `AssetRegistryP1` contract manages the registration and unregistration of assets in the Reserve Protocol. The [`unregister()` function](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/AssetRegistry.sol#L108-L121) is responsible for removing an asset from the registry. During this process, it calls [`basketHandler.quantity()`](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/AssetRegistry.sol#L112) with a reserved amount of gas to check the quantity of the asset in the basket. If this call fails or returns a non-zero quantity, the basket is disabled by calling [`basketHandler.disableBasket()`](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/AssetRegistry.sol#L113).

The issue lies in the [`_reserveGas()` function](https://github.com/code-423n4/2024-07-reserve/blob/3f133997e186465f4904553b0f8e86ecb7bbacbf/contracts/p1/AssetRegistry.sol#L253-L264), which is supposed to ensure sufficient gas for the `basketHandler.quantity()` call:

```solidity
function _reserveGas() private view returns (uint256) {
    uint256 gas = gasleft();
    require(
        gas > (64 * GAS_FOR_BH_QTY) / 63 + GAS_FOR_DISABLE_BASKET,
        "not enough gas to unregister safely"
    );
    return GAS_FOR_BH_QTY;
}
```

This function does not account for the minimum gas needed for the actual execution of `basketHandler.quantity()`. An attacker can exploit this by providing just enough gas to pass the requirement check but not enough for the actual execution, causing the call to fail and the basket to be disabled unnecessarily.

The issue is particularly concerning in the `unregister()` function:

```solidity
function unregister(IAsset asset) external governance {
    // ... (previous checks)
    try basketHandler.quantity{ gas: _reserveGas() }(asset.erc20()) returns (uint192 quantity) {
        if (quantity != 0) basketHandler.disableBasket();
    } catch {
        basketHandler.disableBasket();
    }
    // ... (asset unregistration logic)
}
```

An attacker can craft a transaction with precisely calculated gas to trigger the basket disabling, potentially disrupting protocol operations and causing unnecessary trades.

## Impact

An attacker can manipulate the gas provided to the `basketHandler.quantity()` call, causing it to revert and triggering the basket to be disabled unnecessarily. This can disrupt normal operations, requiring a basket refresh and potentially leading to unnecessary trades. These trades may incur slippage and result in financial losses for the protocol.


## Proof of Concept

1. Attacker observes the current gas prices and the gas required for a normal `unregister()` call.
2. Attacker crafts a transaction to call `unregister()` with gas just above the threshold required by `_reserveGas()`:
   `gas = (64 * GAS_FOR_BH_QTY) / 63 + GAS_FOR_DISABLE_BASKET + 1`
3. The transaction passes the check in `_reserveGas()` but fails during the actual `basketHandler.quantity()` call.
4. The `catch` block is executed, calling `basketHandler.disableBasket()`.
5. The basket is disabled, triggering a refresh and potential unnecessary trades.

## Recommended Mitigation Steps

To mitigate this issue, the `_reserveGas()` function should be updated to ensure sufficient gas for both the check and the execution of `basketHandler.quantity()`. Here's the suggested fix:

```diff
function _reserveGas() private view returns (uint256) {
    uint256 gas = gasleft();
+   uint256 MIN_EXECUTION_GAS = 20000; // Adjust based on actual gas requirements
    require(
-       gas > (64 * GAS_FOR_BH_QTY) / 63 + GAS_FOR_DISABLE_BASKET,
+       gas >= (64 * GAS_FOR_BH_QTY) / 63 + GAS_FOR_DISABLE_BASKET + MIN_EXECUTION_GAS,
        "not enough gas to unregister safely"
    );
    return GAS_FOR_BH_QTY;
}
```
