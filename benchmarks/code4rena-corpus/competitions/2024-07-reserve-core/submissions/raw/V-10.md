# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-reserve/blob/825e5a98a8c94a7b4458b3b359a507edb9e662ba/contracts/p1/RToken.sol#L94-L96

```solidity
function issue(uint256 amount) public {
  issueTo(_msgSender(), amount);
}

```

This function allows users to issue new RTokens.

Issue however is that issuance of new RTokens are allowed even even when the protocol is uncollateralized.

This should not be accepted however, this is because when the protocol is uncollateralized, new issuers face significant risks:

1. Best case scenario: They have to wait for [recollateralization to finish before they can fully redeem](https://github.com/code-423n4/2024-07-reserve/blob/825e5a98a8c94a7b4458b3b359a507edb9e662ba/contracts/p1/RToken.sol#L193), hoping the process goes well.
2. Worst case scenario: They could lose all their underlying collateral.

Now whereas the issuance premium logic could reduce this a bit, it still doesn't curb the bug case considering [some collaterals would not have the `savedPegPrice()`](https://github.com/code-423n4/2024-07-reserve/blob/825e5a98a8c94a7b4458b3b359a507edb9e662ba/contracts/p1/BasketHandler.sol#L379) existing on them and as such the premium issuance is always going to be sidestepped on these collaterals.

> NB: _savedPegPrice_ was only added on this update to collaterals, see `contracts/plugins/assets/AppreciatingFiatCollateral.sol` from https://github.com/reserve-protocol/protocol/pull/1127/files?file-filters%5B%5D=.sol&show-viewed-files=true.

## Impact

This situation is unfair to new issuers, as they are exposed to risks they didn't create and cannot control having it be possible for them to lose all their assets in the worst case scenario which may discourage participation in the protocol during critical periods when new issuance could be beneficial for recollateralization, i.e the RToken users will bear all the losses for the depeg, whereas the RSR stakers might even emerge unscathed.

## Recommended Mitigation Steps

Consider disallowing issuance of new RTokens during recollateralization (when not fully collateralized), i.e

```diff
    function issue(uint256 amount) public {
+        require(basketHandler.fullyCollateralized(), "partial redemption; use redeemCustom");
        issueTo(_msgSender(), amount);
    }
```
