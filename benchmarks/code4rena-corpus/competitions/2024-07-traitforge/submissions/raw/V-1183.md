# Vulnerability details

## Impact
`Block.number` should be avoided being used for randomness. It is used for the creation of "random" entropies in the batch writing functions. Using this weak source of randomness miners can manipulate and predict what NFT's they will get and gain an unfair advantage over regular users (for example getting the Golden God: "999999")

## Proof of Concept
```solidity
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Use a better source of randomness like Chainlink VRF for example
