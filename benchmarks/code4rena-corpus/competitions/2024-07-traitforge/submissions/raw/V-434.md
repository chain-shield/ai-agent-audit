# Vulnerability details

## Impact
mintWithBudget() will be DOS'ed whenever users mint/forge more than 10_000 tokens
This is happening due to the while cycle's condition _tokenIds < maxTokensPerGen. _tokenIds is getting incremented on every mint/forge, this will result in
tokenIds constantly above 10_000. Whenever this occurs the mintWithBudget will be DOS'ed for the lifetime of the protocol. 

```solidity
function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice(); 
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) { //@audit - high after reaching 10000 tokens, _tokenIds will dos the mintWithBudget function
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```
Impact - medium (minting could proceed with mintTokens, but functionality is dos'ed)
Likelihood - high (10_000 tokens will be reached in the future)
Overall - high

## Proof of Concept

Let's look at the following scenario.
Alice is a whitelisted user.

1. Alice mints with budget around 200 tokens
2. Other whitelisted users proceed to mint more tokens
3. tokenIds reaches 10_000
4. Alice tries to mintWithBudget() around 200 tokens again but the protocol is refunding her money and no mints are initiated
5. mintWithBudget() is DOS'ed
