# Vulnerability details

## Impact
The current implementation of the writeEntropyBatch1 and writeEntropyBatch2 functions attempts to prevent the generation of the value 999999 by using require( pseudoRandomValue != 999999, 'Invalid value, retry.');. However, this check is ineffective because the generated pseudo-random value is a 78-digit number. This approach fails to prevent 999999 from appearing within any part of the 78-digit number. Consequently, the entropy value can still contain 999999 despite the check, potentially leading to vulnerabilities if 999999 should be avoided in any part of the entropy value.

## Proof of Concept

Ineffective Check for 999999:

As the % 10 **78 results in value which is of size 78 number.
 
The check require( pseudoRandomValue != 999999, 'Invalid value, retry.'); is insufficient as it verifies the entire 78-digit number, which will never detect whether it have 999999 value as check will always pass. The entropy value may still contain 999999 in any of its segments, which the current implementation does not detect. 
It breaks the main invariant of code as they wanted 999999 value to occur between slots[512-769].

## Recommended Mitigation Steps
Implement a robust validation check that can detect if any segment of the generated 78-digit number includes 999999,can implement similar functionality like `getnextEntropy` function which can provide Specific entropy of wanted slot and Index
