# Vulnerability details

## Impact
Forgers can forge 1 more time than their complimentary counterparts - mergers, due to a miss-matched updates to `forgingCounts`.

## Proof of Concept
[listForForging](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L67) and [forgeWithListed](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L102) are used to forge 2 NFTs together go get 1 from the next gen. However when we look into how [forgeWithListed](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L133-L139) updates `forgingCounts` we can see an issue:

```solidity
   //@audit updated after `mergerForgePotential` check
   forgingCounts[forgerTokenId]++;

   ...
   //@audit updated before `mergerForgePotential` check
   forgingCounts[mergerTokenId]++; 
        
   require(
      mergerForgePotential > 0 && forgingCounts[mergerTokenId] <= mergerForgePotential, 
      "forgePotential insufficient"
   );
```

The issue above is that `forgingCounts` for the forger is checked inside [listForForging](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L87-L90) before listing the NFT and updated in [forgeWithListed](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L133). However the opposite is true when it comes to our merger's `forgingCounts` - updated before comparing it to `mergerForgePotential`.

This will lead to the forger being able to forge 1 more NFT:

Example using `require(forgingCounts[userNFT] <= mergerForgePotential)`
1. Forger NFT with `mergerForgePotential` 1 can forge 2 times:
**first list -** `0 <= 1`, then merges increasing `forgingCounts` to 1
**second list -** `1 <= 1`, then merges increasing `forgingCounts` to 2

2. Merger NFT with `mergerForgePotential` 1 can forge 1 time:
**first merge -** increases `forgingCounts` to 1, `1 <= 1`, then merges
**second merge -** increases `forgingCounts` to 2, `2 <= 1` -> reverts

## Tools Used
Manual review

## Recommended Mitigation Steps
Either update forgers before checking for `forgingCounts` (make sure to reduce it when un-listing), or mergers after. This will equalize both parties.
