# Vulnerability details

## Impact
The protocol describes that the maximum generation of the NFT collections should be 10. However, due to a missing check in direct minting, it is possible to create an 11th generation.

## Proof of Concept
Forging has a check that verifies that newGeneration <= maxGeneration, ensuring the generation limit cannot be bypassed.
```solidity
  function forge(
    address newOwner,
    uint256 parent1Id,
    uint256 parent2Id,
    string memory
  ) external whenNotPaused nonReentrant returns (uint256) {
    require(
      msg.sender == address(entityForgingContract),
      'unauthorized caller'
    );
    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

    /// Check new generation is not over maxGeneration
@>> require(newGeneration <= maxGeneration, "can't be over max generation");

    // Calculate the new entity's entropy
    (uint256 forgerEntropy, uint256 mergerEntropy) = getEntropiesForTokens(
      parent1Id,
      parent2Id
    );
```

But , for the `mintToken()` and `mintWithBudget()` functions, which are both calling `_mintInternal()`, no check for ensuring maxGeneration limit cannot be exceeded exists.
```solidity
 function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
  ```
  This would allow us, when the 10th generation's limit of 10k NFTs is reached, to trigger `_incrementGeneration()`
  Which is called in the `_mintInternal()` function.
