# Vulnerability details

## Impact
Players are able to forge tokens multiple times based on the Forge Potential of their entity, which is determined by the fifth digit of the entity's entropy. Once an entity has used its Forge Potential, it should not forge again until the Forge Potential is reset. However, the `listForForging` function in the [EntityForging::listForForging](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L67-L100) checks for Forge Potential but does not correctly update the forging count for the forger.
```solidity
function listForForging(
    uint256 tokenId,
    uint256 fee
) public whenNotPaused nonReentrant {
    // ...
     _resetForgingCountIfNeeded(tokenId);

    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );

    bool isForger = (entropy % 3) == 0; // Determine if the token is a forger based on entropy
    require(isForger, 'Only forgers can list for forging');

    ++listingCount;
    listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
    listedTokenIds[tokenId] = listingCount;

    // @audit Notice that `forgingCounts[tokenId]` is not updated
    emit ListedForForging(tokenId, fee);
}
```
The `forgingCounts` is not incremented in the `listForForging` function, allowing a forger to list an unlimited number of tokens for forge, bypassing their Forge Potential. Although `forgingCounts` is indeed [incremented in `forgeWithListed`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L133) after the merge happens, there is no check to ensure the forger hasn't exceeded their Forge Potential.

## Proof of Concept
Consider the following example:
- Player `A` has a token with tokenId `1` and a Forge Potential of `3`.
- Player `A` lists his token for forging `5` times, exceeding the Forge Potential. The calls to `listForForging` do not revert because `forgingCounts[1]` is not incremented.
- Player `B`, a merger, with a token tokenId `2` and a Forge Potential of `6`, attempts to merge all tokens listed by Player `A`. He calls `forgeWithListed` `5` times, and all calls succeed because `forgingCounts[1]` for Player A's token is not checked against the Forge Potential even if it is incremented.

As a result, Player `A` is able to forge their token `5` times, **exceeding the allowed Forge Potential of `3`**.

## Recommended Mitigation Steps
The easiest mitigation is to move the [increment of `forgingCounts[forgerTokenId]`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L133) from `forgeWithListed` to `listForForging`. Below is a suggestion for updated code:
