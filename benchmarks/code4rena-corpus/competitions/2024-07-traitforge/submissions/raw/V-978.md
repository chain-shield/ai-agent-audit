# Vulnerability details

## Details
- The vulnerability is present in the `mintToken` and `mintWithBudget` function where they involves checking the current mint price before incrementing the generation (if required).
- If in case a generation needs to be incremented it will only be incremented after validating the mint price, and increment happens after which results in user being charged for the generation's `10000 + 1` entity price, but the correct charge should be on the basis of count of next generation entity.


## Impact
- For the case when all entities for a generation are minted, then the user minting new NFT is charged incorrect amount for the mint of next generation entity, due to calculation of mint price before incrementing the generation, as price will be calculated in accordance with the previous generation next mint.
- As this pattern is followed in both `mintToken` and `mintWithBudget` function, therefore both function suffers from this vulnerability.

## Proof of Concept
- The mint price calculation occurs before increment of generation.
- Let's say for `x` generation all NFTs are minted, and a user calls for mint of an entity, now it is expected that the user should be charged for the NFT count on the basis of the next generation as current generation is full, but as mint price is calculated before incrementing the generation, thus user will get charged incorrectly.
- Thus, user gets charged for minting the previous generation's 10,001 NFT instead of the current generation NFT mint.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Increment the generation before calculating the mint price for both functions: `mintToken` and `mintWithBudget`.
