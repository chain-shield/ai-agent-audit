# Vulnerability details

## Impact
- The protocol loses expected revenue from the tax cut, which is intended to be contributed to the NukeFund.
- Users can artificially inflate NFT prices across generations without any financial penalty, undermining the protocol's economic model.

## Summary

The `EntityTrading` contract allows users to list and buy NFTs. However, there is a vulnerability that allows users to repeatedly buy their own NFTs at **low prices, resulting in zero contributions to the protocol's NukeFund.** This can lead to financial loss for the protocol, as users can manipulate the NFT prices across generations without paying the intended tax cut.

## Vulnerability Details

The issue lies in the calculation of the `nukeFundContribution` in the `buyNFT` function of the `EntityTrading` contract. The calculation uses integer division, which truncates the result towards zero. 

If the `listing.price` is less than `taxCut`, the contribution to the `NukeFund` becomes zero.

```solidity
uint256 nukeFundContribution = msg.value / taxCut;
uint256 sellerProceeds = msg.value - nukeFundContribution;
transferToNukeFund(nukeFundContribution); // transfer contribution to nukeFund
...
...
function transferToNukeFund(uint256 amount) private {
  require(nukeFundAddress != address(0), 'NukeFund address not set');
  (bool success, ) = nukeFundAddress.call{ value: amount }('');
  require(success, 'Failed to send Ether to NukeFund');
  emit NukeFundContribution(address(this), amount);
}
```

**Simple exploit scenario in four steps**

- 1. A user mints an NFT in the TraitForgeNft contract.
- 2. The user lists the NFT for a minimal price (e.g., 9 wei).
- 3. The same user buys the NFT. Here, msg.value is 9 wei.( nukeFundContribution = 9 / 10 = 0 (due to integer division))
- 4. The user can repeat this process, **increasing the NFT price incrementally without any contribution to the protocol's fund, effectively bypassing the tax cut mechanism.**

**Result:** The transferToNukeFund(0) does not revert, resulting in no funds being contributed to the protocol.

## Recommended Mitigation Steps

1. Ensure that the listing price is above a certain threshold to avoid zero tax contributions.
2. Add a check to ensure `nukeFundContribution` is greater than zero before making the transfer.

Example:

```diff
function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {
    Listing memory listing = listings[listedTokenIds[tokenId]];
    require(
        msg.value == listing.price,
        'ETH sent does not match the listing price'
    );
    require(listing.seller != address(0), 'NFT is not listed for sale.');
+   require(listing.price >= 10, 'Listing price too low to cover tax.');

    uint256 nukeFundContribution = msg.value / taxCut;
+   require(nukeFundContribution > 0, 'NukeFund contribution must be greater than zero.');
    uint256 sellerProceeds = msg.value - nukeFundContribution;
    transferToNukeFund(nukeFundContribution); // transfer contribution to nukeFund

    (bool success, ) = payable(listing.seller).call{ value: sellerProceeds }('');
    require(success, 'Failed to send to seller');
    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer NFT to the buyer

    delete listings[listedTokenIds[tokenId]]; // remove listing

    emit NFTSold(
        tokenId,
        listing.seller,
        msg.sender,
        msg.value,
        nukeFundContribution
    ); // emit an event for the sale
}
```
