# Vulnerability details

## Vulnerability details:-
The `NukeFund.sol::calculateAge` function will calculate a `performanceFactor` of zero if the last digit of the entropy is zero due to the following calculation:

```
      uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;
```
Applying a modulo 10 operation to the entropy value within the `NukeFund.sol::calculateAge` function will result in a `performanceFactor` of zero if the entropy's last digit is zero because the entropy is a random number.

```
function calculateAge(uint256 tokenId) public view returns (uint256) {
        require(nftContract.ownerOf(tokenId) != address(0), "Token does not exist");
        uint256 daysOld = (block.timestamp - nftContract.getTokenCreationTimestamp(tokenId)) / 60 / 60 / 24;

@>        uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;

@>        uint256 age = (daysOld * perfomanceFactor * MAX_DENOMINATOR * ageMultiplier) / 365; // add 5 digits for decimals
@>        return age;
    }
```
The `performanceFactor` is calculated as zero due to the entropy's last digit being zero, the `NukeFund.sol::calculateAge` function will return an `age` of zero. This incorrect age calculation will result in the token's age being undervalued, depriving the user of the intended token value within the contract.

## Impact:-
Due to the incorrect calculation of age for entropy values ending in zero, users will experience significant loss in token value because the age is calculated as  0.

## Proof of Concept:-
```
function calculateAge(uint256 tokenId) public view returns (uint256) {
        require(nftContract.ownerOf(tokenId) != address(0), "Token does not exist");
        
        uint256 daysOld = (block.timestamp - nftContract.getTokenCreationTimestamp(tokenId)) / 60 / 60 / 24;
        uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;

        uint256 age = (daysOld * perfomanceFactor * MAX_DENOMINATOR * ageMultiplier) / 365; // add 5 digits for decimals

        return age;
    }
```
Lets take an example for the same
```
let the `nftContract.getTokenEntropy(tokenId)` return a number 542160 which is then modulus with 10.
542160 % 10 = 0.

age = (daysOld * 0 * MAX_DENOMINATOR * ageMultiplier) / 365
age=0 

``` 
The function will always return an age of 0 for any entropy value ending in zero, regardless of the values of other variables.

## Recommended Mitigation Steps :-
The contract can implement two solutions to prevent the issue of zero age calculations.

1. A require statement can be implemented to revert the transaction if the calculated performance factor is zero.

2. A require check can be implemented to discard entropy values with a last digit of zero either during entropy generation or at the time of token storage.
