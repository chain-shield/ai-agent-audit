# Vulnerability details

### Impact  

The `mintToken` function calculates the mint price before calling the `_mintInternal` function. In scenarios where the `_mintInternal` function increments the `currentGeneration`—due to reaching the maximum token limit for the current generation—the mint price, calculated before the generation increment, becomes inaccurate. This can result in users overpaying or underpaying for minting tokens, thereby disrupting the economic balance of the NFT ecosystem and potentially causing user dissatisfaction.  

### Explanation  

Here's the problematic code sequence:  

1. **Calculate Mint Price**:  
    ```solidity  
    uint256 mintPrice = calculateMintPrice();  
    ```  

2. **Mint Internal Logic**:  
    ```solidity  
    _mintInternal(msg.sender, mintPrice);  
    ```  

The `_mintInternal` function can increment the `currentGeneration` if the mint count exceeds the generation limit, leading to an outdated `mintPrice`.  

### Proof of Concept  

**Issue Scenario:**  

- Current generation is `1` and has `9999` tokens.  
- The next mint will trigger generation increment to `2`.  
- `mintPrice` calculated before calling `_mintInternal` applies to generation `1`.  
- Generation increment changes the parameters for `mintPrice` calculation.  

**Current Code:**  
```solidity  
function mintToken(  
    bytes32[] calldata proof  
)  
    public  
    payable  
    whenNotPaused  
    nonReentrant  
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))  
{  
    uint256 mintPrice = calculateMintPrice();  
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');  

    _mintInternal(msg.sender, mintPrice);  

    uint256 excessPayment = msg.value - mintPrice;  
    if (excessPayment > 0) {  
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');  
      require(refundSuccess, 'Refund of excess payment failed.');  
    }  
}
```

## Recommended Mitigation Steps
1. Calculate Mint Price After Potential Generation Change:
Ensure that the mint price is recalculated after the internal minting logic, as this logic can modify the currentGeneration.
2. Order of Operations:
Change the order of operations so that the mint price is calculated after the _mintInternal function to reflect the correct generation.

Example Mitigation Code:

The corrected code sequence ensures that the mint price calculation considers the updated generation:
```solidity
function mintToken(  
    bytes32[] calldata proof  
)  
    public  
    payable  
    whenNotPaused  
    nonReentrant  
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))  
{  
    _mintInternal(msg.sender); // Mint internals, may update generation  

    uint256 mintPrice = calculateMintPrice(); // Calculate price after potential generation change  
    require(msg.value >= mintPrice, 'Insufficient ETH sent for minting.');  

    uint256 excessPayment = msg.value - mintPrice;  
    if (excessPayment > 0) {  
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');  
      require(refundSuccess, 'Refund of excess payment failed.');  
    }  
}
```
