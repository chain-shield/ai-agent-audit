# Vulnerability details

## Impact

Airdrop of `Trait` token is to given to all the holders of `TraitForgeNft` when the airdrop starts.
However, only the original minters and forgers will receive the airdrop share.
This is because if `TraitForgeNft` tokens are transferred to another user, then the new user would loose the airdrop share and the original minter of the `TraitForgeNft` would receive the airdrop.


## Proof of Concept

Even though the Airdrop contract is OOS, the root cause exist in an in-scope contract.
The vulnerability exist because of incorrect implementation of `TraitForgeNft::_beforeTokenTransfer` function, where on transferring the NFT to another user, their airdrop share is not added and the original minter still holds their airdrop share.

```javascript
  function _beforeTokenTransfer(
    address from,
    address to,
    uint256 firstTokenId,
    uint256 batchSize
  ) internal virtual override {
    super._beforeTokenTransfer(from, to, firstTokenId, batchSize);

    uint listedId = entityForgingContract.getListedTokenIds(firstTokenId);
    /// @dev don't update the transferred timestamp if from and to address are same
    if (from != to) {
      lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }

    if (listedId > 0) {
      IEntityForging.Listing memory listing = entityForgingContract.getListings(
        listedId
      );
      if (
        listing.tokenId == firstTokenId &&
        listing.account == from &&
        listing.isListed
      ) {
        entityForgingContract.cancelListingForForging(firstTokenId);
      }
    }

    require(!paused(), 'ERC721Pausable: token transfer while paused');
  }
```
