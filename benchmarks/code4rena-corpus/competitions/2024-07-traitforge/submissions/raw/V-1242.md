# Vulnerability details

## Impact
When NFT is forged via `forgeWithListed()`, which is called by the User who has a Merger NFT in EntityForging.sol, the Forger gets a fee, however, this results in a contract call to an arbitrary address, i.e., the User who put up his NFT Forge NFT. Currently the User who tried to call `forgeWithListed()` is not protected from overspending gas.

## Proof of Concept
User story: 
User `A` who has a Forger NFT decides to put up his NFT for forging, and random User `B` who has Merger NFT decides to forge with it. 
However, the User `A` who has the Forger NFT could be malicious.

Step 1: User `A` lists his NFT via `listNFTForSale()` in EntityForging contract.

Step 2: User `B`, or the "victim" calls `forgeWithListed()` in EntityForging.sol. 
However, due to missing gas limit set on the call which pays the fees to the User `A`, a malicious User `A`, can have code in its `receive();` function which's goal is to just increase gas spent, until OOG hits. 
For User `B`  this will exhausts the whole gas for its transaction, and as well stop the forge action itself, making him overpay.

## Recommendation Steps
Set the gas limit to `23,000`, to have some buffer above 21,000.
Its also recommended to extract this value as field and add setter, as in the future, its not impossible that base intrinsic gas could change.
