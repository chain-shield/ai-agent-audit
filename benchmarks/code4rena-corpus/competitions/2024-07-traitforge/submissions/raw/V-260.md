# Vulnerability details

## Impact

Impact: Medium
Likelihood: Low

When you use _mint, the function directly assigns a new token to the specified address without verifying if the recipient is a contract capable of handling ERC721 tokens. If the recipient is a contract that does not implement the IERC721Receiver interface, the tokens might be permanently locked in an address that cannot manage or transfer them.

## Proof of Concept
By calling any of the functions:
1. `TraitForgeNft::_mintInternal`
2. `TraitForgeNft::_mintNewEntity`
If the receiver address is not checked whether it can receive ERC721 then the ERC721s may be permanently lost.


## Tools Used
Solidity, VSCode

## Recommended Mitigation Steps
Use `safeTransferFrom` instead of `transferFrom`.

In `TraitForgeNft::_mintInternal`:
```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
  ...
+  _safeMint(to, newItemId);
-  _mint(to, newItemId);
  ...
}
```

In `TraitForgeNft::_mintNewEntity`:

```solidity
 function _mintNewEntity(
    address newOwner,
    uint256 entropy,
    uint256 gen
  ) private returns (uint256) {
    ...
+    _safeMint(newOwner, newTokenId);
-    _mint(newOwner, newTokenId);
    ...
  }
```
