# Vulnerability details

## Description 

The `listNFTForSale` function doesn't verify whether a `tokenId` is already associated with an active listing. This can potentially result in the same NFT being listed multiple times.


## Impact

Allowing multiple active listings for the same NFT can lead to issues with managing sales, cancellations, and ownership. It could potentially allow the same NFT to be sold more than once, causing a loss of funds.

a user could intentionally or unintentionally list the same NFT multiple times, confusing buyers and potentially leading to disputes over the rightful owner of the NFT.




## Proof of Concept

1. A user lists an NFT with a specific tokenId for sale, and a unique listingCount ID is assigned.

2. Without canceling the existing listing, the user attempts to list the same NFT (tokenId) again.

3. The contract doesn't check if the NFT is already listed, resulting in multiple listings with different listingCount IDs for the same NFT.

## Recommended Mitigation Steps
```
function listNFTForSale(uint256 tokenId, uint256 price) public whenNotPaused nonReentrant {
    require(price > 0, 'Price must be greater than zero');
    require(nftContract.ownerOf(tokenId) == msg.sender, 'Sender must be the NFT owner.');
    require(
        nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
        'Contract must be approved to transfer the NFT.'
    );

    // Check if the token is already listed
    uint256 currentListingId = listedTokenIds[tokenId];
    require(currentListingId == 0 || !listings[currentListingId].isActive, 'NFT is already listed.');

    nftContract.transferFrom(msg.sender, address(this), tokenId); // Transfer NFT to contract

    listingCount++;
    listings[listingCount] = Listing(msg.sender, tokenId, price, true);
    listedTokenIds[tokenId] = listingCount;

    emit NFTListed(tokenId, msg.sender, price);
}

```
