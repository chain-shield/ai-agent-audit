# Vulnerability details

## Impact

Lost NFTs due to the contract [EntityTrading](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityTrading/EntityTrading.sol) not implementing the interface [IERC721Receiver](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721Receiver.sol).

## Proof of Concept

The current implementation of the contract has just one function [listNFTForSale](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityTrading/EntityTrading.sol#L38-L60), in which a NFT is being transferred from the user to the contract. However, the contract doesn’t implement neither [onERC721Received](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721Receiver.sol#L22-L27), nor does it inherit the interface [ERC721TokenReceiver](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721Receiver.sol). This will lead to all NFTs transferred to the contract via [safeTransferFrom](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721.sol#L55-L73) by the users, to revert. The likelihood of this happening is very high, because the suggested way of transferring tokens is to use the safe version of transfer and the receiver has to implement [IERC721Receiver and onERC721Received](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721.sol#L50-L51), which in this case is the `EntityTrading` contract, otherwise the transfer will never succeed.

## Tools Used

Manual Review

## Recommended Mitigation Steps

The issue can be mitigated by implementing [OpenZeppelin’s IERC721Receiver](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/token/ERC721/IERC721Receiver.sol)
