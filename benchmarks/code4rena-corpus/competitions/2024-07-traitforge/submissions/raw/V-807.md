# Vulnerability details


 ### Impact: 

    In the traitForgeNft::_incrementGeneration() functions is responsible for incrementing the generation when the time is right now inside this internal function there is this perticular line entropyGenerator.initializeAlphaIndices();  this is a function from EntropyGenerator.sol in this function it is set that it can only be called by onlyOwner and the sponsors plan was for their multisig wallet to be the owner of EntropyGenerator.sol so when this happens then TraitForge.sol won't be able to call that function because is not the owner of the contract
    protocol will be unable to start next generation after the first generation is done



### Proof of Concept:
**Follow this scenario:**
The protocol deploys `EntropyGenerator.sol` using their Multisig wallet.
The mintToken() function is called for the first time. This triggers a chain of function calls:

`mintToken()` calls `_mintInternal()`
`_mintInternal()` calls `_incrementGeneration()`
`_incrementGeneration()` calls `initializeAlphaIndices()`


For the first few times this sequence of functions is called, nothing significant will happen. This is due to a check inside _mintInternal().
```javascript
if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
    _incrementGeneration();
```

* Once this check passes and `_incrementGeneration()` is called, the function will revert.
The reversion occurs because `_incrementGeneration()` calls a function in another contract that is restricted to onlyOwner.
The issue arises because the owner of `EntropyGenerator` is not set to `TraitForge.sol`.


### Recommended Mitigation:
To resolve this issue, ensure that `TraitForge.sol` is set as the owner of `EntropyGenerator` when deploying. This will allow `TraitForge.sol` to call the necessary functions when required, preventing the reversion in `_incrementGeneration()`.
