# Vulnerability details

## Impact
The `setNukeFundContract()` function expects a `payable address`, but the `nukeFundAddress` variable is declared as a `regular address`. This discrepancy can cause issues when trying to send funds to `nukeFundAddress`.

## Proof of Concept
In Solidity, an `address type` is used to store `Ethereum addresses`. However, there are two types of `addresses`:
1. `address`: A regular address that cannot receive Ether.
2. `address payable`: A special type of address that can receive Ether.

In the [`setNukeFundContract()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L67) function, the parameter `_nukeFundAddress` is of type `address payable`, which means `it can receive Ether`.
```solidity
>>  function setNukeFundContract(address payable _nukeFundAddress) external onlyOwner { //@audit-info Payable address
        nukeFundAddress = _nukeFundAddress;
        emit NukeFundContractUpdated(_nukeFundAddress);
    }
```

However, the state variable [`nukeFundAddress` is declared as a `regular address`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L30), which `cannot receive Ether`. This inconsistency can lead to issues when trying to send `Ether` to `nukeFundAddress`.
```solidity
>>  address public nukeFundAddress; //@audit-info Regular address
```
**Type Mismatch**: Assigning a `payable address` to a `non-payable address`.

**Potential Errors**: When trying to send `Ether` to `nukeFundAddress`, it will fail because address cannot receive Ether.

*Consider [`_distributeFunds()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L361):*
```solidity
    function _distributeFunds(uint256 totalAmount) private {
      require(address(this).balance >= totalAmount, 'Insufficient balance');

>>    (bool success, ) = nukeFundAddress.call{ value: totalAmount }('');
      require(success, 'ETH send failed');

      emit FundsDistributedToNukeFund(nukeFundAddress, totalAmount);
    }
```
As seen, the function does not use `payable(nukeFundAddress).call()` because it expects that this `nukeFundAddress` is already a `payable address` but this is not the case as seen above.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Declare `nukeFundAddress` as a `payable` address.
```diff
-   address public nukeFundAddress;
+   address payable public nukeFundAddress;
```
