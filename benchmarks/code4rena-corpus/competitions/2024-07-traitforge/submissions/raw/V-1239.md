# Vulnerability details

**Impact**
Users must pay a fee when calling `forgeWithListed` and the code includes the following check:
`require(msg.value >= forgingFee, 'Insufficient fee for forging');`
This check ensures that `msg.value` is at least `forgingFee` however in the event that too large a fee is sent, nothing is done with any excess ether meaning it's locked permanently in the contract.

**Recommended Mitigation**
As `forgingFee` is not possible to change once it has been set, the check should be a strict `require(msg.value == forgingFee)`.
Alternatively, when calculating the fee the following could be done to ensure no ether is stuck in the contract:
```diff
-   uint256 devFee = forgingFee / taxCut;
-   uint256 forgerShare = forgingFee - devFee;
+   uint256 devFee = msg.value / taxCut;
+   uint256 forgerShare = msg.value - devFee;
```
