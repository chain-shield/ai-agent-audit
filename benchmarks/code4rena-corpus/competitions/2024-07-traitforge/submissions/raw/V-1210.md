# Vulnerability details

## Impact

In `EntropyGenerator` smart contract, the slots with 78 digits number (13 concatenated entropies) should be initialized for each generation (total number of 10). And as there are the total of 10000 tokens per generation, 770 slots are therefore needed. The problem is that there is no any initialization of slots and new entropies for the next generations - it's only done for the first one.

## Proof of Concept

There are 3 functions that fill the 770 slots with entropies:


https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L47

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L64

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L84

The only thing is called when the generation is incremented inside of `TraitForgeNft` smart contract, it's `initializeAlphaIndices()` which creates a slot index and number index for the special entropy - `999999`:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L345-355
```
 function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

This leaves all the contract with only 10000 entropies initialized and without entropies for the future generations and it can be considered as unexpected behavior.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Check if new entropies are initialized for new generations as well.
