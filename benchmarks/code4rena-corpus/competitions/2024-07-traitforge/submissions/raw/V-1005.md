# Vulnerability details

## Vulnerability Details
`writeEntropyBatch1()`, `writeEntropyBatch2()`, `writeEntropyBatch3()` functions are used for initalizing entropy values inbatches to spread gas cost over multiple transcations. The main problem is in the `unchecked` block of code in the functions:

```javascript
unchecked {
    for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
@>      uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, "Invalid value, retry.");
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array
    }
}
```

Here is how the value of `pseudoRandomValue` is calculated:
1. `Keccak256` the value of the `block.number` and the index from the for-loop and cast it to `uint256`.
2. Modulo by `uint256(10)`, so we can get the last digit.
3. Bring the value to the power of 78.

However, this line of code will always overflow, because the first in the order of calculation is the power and `uint256(10) ** 78` will always overflow.

## Impact
Breaking core functionality of contract in three functions.

## Proof of Concept
You can test this line of code by substituting `i` with any number, which is casted to `uint256` and it will always overflow.

```javascript
uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78;
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
What you can do is to add parentheses in the equation like this:

```diff
-   uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78;
+   uint256 pseudoRandomValue = uint256(uint256(keccak256(abi.encodePacked(block.number, i)))) % uint256(10) ** 78;
```
