# Vulnerability details

## Impact
According to the [docs](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit#heading=h.ttpauotgke9o):
> the next generation is minted with the genesis entropy off-by-one

However, [`EntropyGenerator::getNextEntropy`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L101-L117) and [`EntropyGenerator::getEntropy`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L164-L185) methods do not take in account of the generation it is minting. This causes them to return same entropy which has been previously used.

It is also possible that 2 NFTs of same generation get the God Entropy value i.e. 999999 (one due to bit stuffing, and the other due to `slotIndexSelectionPoint` and `numberIndexSelectionPoint` set by `EntropyGenerator::initializeAlphaIndices`), when only a maximum of one per generation should be present.

## Proof of Concept

When new NFTs are minted, [`TraitForgeNft::_mintInternal`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-L309) function calls the `EntropyGenerator::getNextEntropy` function which returns the entropy based on the storage slot and index it has already parsed. However, this entropy value stored in the the storage slots is never changed, so further generation NFTs would have repeated entropies which are already used by the previous generations.

```javascript
  function getEntropy(
    uint256 slotIndex,
    uint256 numberIndex
  ) private view returns (uint256) {
    require(slotIndex <= maxSlotIndex, 'Slot index out of bounds.');

    if (
      slotIndex == slotIndexSelectionPoint &&
      numberIndex == numberIndexSelectionPoint
    ) {
      return 999999;
    }

    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

    return paddedEntropy; // return the caculated entropy value
  }
```

## Recommended Mitigation Steps

Randomise the bit stuffing values after every generation, or use the currentGeneration value to randomise the entropy.
