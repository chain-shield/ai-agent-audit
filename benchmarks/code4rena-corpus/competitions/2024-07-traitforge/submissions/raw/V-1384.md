# Vulnerability details

## Impact
When an NFT is bought via buyNFT in EntityTrading.sol, the seller gets a fee. However, this results in a contract call to an arbitrary address, i.e., the seller. The seller can permanently DoS the buy operation, as we require that the call is successful, so this would result in the NFT just being publicly listed on the TraitForge DAPP but never being possible to be bought.

## Proof of Concept
User story: A seller decides to put up his NFT for sale, and a buyer decides to buy it. However, the seller is malicious.

Step 1: The seller lists his NFT via `listNFTForSale()` in the EntityTrading contract.

Step 2: The buyer calls `buyNFT()` in EntityTrading.sol. However, due to the fact that we require the success status of the call, the seller can forcefully cause a revert in its receive() function, which would lead to the call failing, thus DoSing the operation.

```solidity
  function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {

      'ETH sent does not match the listing price'
    );
    require(listing.seller != address(0), 'NFT is not listed for sale.');
```  

```solidity
        // For this test, we want to have deterministic forger and a merger, so we mock the entropies.

        skip(25 hours);

        assertEq(nftContract.ownerOf(1), NFT_FORGER_OWNER);

        if (msg.value != 0.18 ether || !shouldWeExploit) return; // We track for 0.18 as 10% goes to the NukeFund
```

## Recommendation Steps
Add a check which requires a certain gas `gasNeededForOperation` to be left so the operation can finish. This value would have to be tested with the final version of the code, so we can verify how much gas the operation would cost. A buffer is also recommended.

The only condition for the fee transfer to succeed should be enough gas; that's why we check for that. If it fails for other reasons, it should be the seller's fault.
