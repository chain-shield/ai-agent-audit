# Vulnerability details

## Impact
This error can lead to all the eth being transferred to burn address during minting process if `nukeFundAddress` is not set.

## Proof of Concept
```solidity
TraitForgeNFT.sol 22:  IEntityForging public entityForgingContract;
TraitForgeNFT.sol 23:  IEntropyGenerator public entropyGenerator;
TraitForgeNFT.sol 24:  IAirdrop public airdropContract;
TraitForgeNFT.sol 25:  address public nukeFundAddress;
```
All contract addresses are left uninitialised, plus the constructor also doesn't set any value for the same.

```solidity
  constructor() ERC721('TraitForgeNft', 'TFGNFT') {
    whitelistEndTime = block.timestamp + 24 hours;
  }
```

As the white sale starts as soon as the contract is deployed, a lot of important arguments, all the contract mentioned above plus merkleroot, etc. are default, which may cause failed transactions for users, plus eth burned for the project as all the eth is transferred to `nukeFundAddress` which is burn address, unless initialised.

## Recommended Mitigation Steps
Either all these important variables should be initialised where they are declared or they should be all set properly in constructor, with checks to make sure that zero values are not sent for the same.
