# Vulnerability details

## Impact

The `EntropyGenerator.writeEntropyBatch3` function is used to calculate the `last batch` of entropy values. The `entropy value` calculations in the `writeEntropyBatch3` does not check for the `entropy value 999999`. This may be due to the fact that the `999,999` is expected to set in the last batch (from the slotIndex 512 - 769). 

But actually the `entropy value 999999` is set in the last batch during the `EntropyGenerator.initializeAlphaIndices` function execution which happens when the `EntropyGenerator` contract is deployed and when new NFT generation is incremented.

Since we don't explicitly check for the `999,999` value in the `EntropyGenerator.writeEntropyBatch3` function, this enables the `999,999` entropy value (Golden God NFT) to be included in `multiple numberIndexes` in the slot index range from 512 - 769. This is not the intended behavior of the protocol since only one `Golden God (entropy value 999999)` is expected to be minted per Generation.

## Recommended Mitigation Steps

Hence it is recommended to check for the `entropy value 999999` in each `numberIndex` in each of the `slotIndexes` in the `entropy batch 3` inside the `EntropyGenerator.writeEntropyBatch3` function. The `writeEntropyBatch3` transaction should revert if any of the entropy values == 999999 since the `999999` has already being set in the last batch (slot index 512 - 769) via the `EntropyGenerator.initializeAlphaIndices` function call.
