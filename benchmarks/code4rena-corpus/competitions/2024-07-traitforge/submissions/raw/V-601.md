# Vulnerability details

## Impact

`_incrementGeneration` is intended to be called every time a generation is fully minted and the protocol needs to start a new generation. Each time this happens, `_incrementGeneration` will internally call `initializeAlphaIndices` to select the index point associated with the 999999 entropy for the new generation. The issue with the current implementation is that `initializeAlphaIndices` can only be called by the `EntropyGenerator` contract's owner due to the `onlyOwner` modifier. Then, unless this role is assigned to the `TraitForgeNft` contract (which is unlikely, as it would mean losing the ability to transfer ownership or pause the contract), the function call will always revert. As a result, the protocol will be limited to directly minting only gen1 tokens, with tokens of gen2 and beyond only accessible through breeding rather than direct minting.

```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    
    // @> Lack of access in the following call will cause it to always revert
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

```solidity
  //select index points for 999999, triggered each gen-increment
  // @> Any calls from TraitForgeNft::_incrementGeneration will revert due to lack of access permissions
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```

## Proof of Concept

Add the following test to `TraitForgeNft.test.ts`:

In this test, `user2` mints 10,000 tokens using the `mintToken` function. When `user2` then attempts to mint an additional token (prompting the protocol to increment to a new generation), the `mintToken` function should revert due to insufficient access permissions for the `initializeAlphaIndices` function.

```solidty
  describe('mintToken', () => {
      it.only('reverts when trying to increment a generation', async () => {
      fastForward(24 * 60 * 60 + 1);

      // Mint 10_000 gen1 tokens in batches of 1_000 tokens
      const batchSize = 1_000;
      const batchCount = 10;
      const batch = new Array(batchSize).fill(0);
      const proof = merkleInfo.whitelist[1].proof;

      for (let b = 0; b < batchCount; b++) {
        const promises = batch.map(() =>
          nft.connect(user2).mintToken(proof, {
            value: ethers.parseEther('1'),
          })
        );

        await Promise.all(promises);
        console.log({ tokensMinted: (b + 1) * batchSize });
      }

      // Expect the user to own 10_000 tokens
      expect(await nft.balanceOf(user2.address)).to.be.eq(
        batchCount * batchSize
      );

      expect(await nft.currentGeneration()).to.be.eq(1);

      // Calculate the mint price for the next token
      const mintPrice = await nft.calculateMintPrice();

      // The mintToken function reverts when internally calling
      // initializeAlphaIndices due to lack of access
      await expect(
        nft.connect(user2).mintToken(proof, {
          value: mintPrice,
        })
      ).to.be.revertedWith('Ownable: caller is not the owner');
    });
  });
```

## Recommended Mitigation Steps

1. Move the implementation of the `initializeAlphaIndices` function to a new internal function, let's call it `_initializeAlphaIndices`:

```solidity
  function _initializeAlphaIndices() internal {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```

2. Call `_initializeAlphaIndices` from the `EntropyGenerator` constructor instead of `initializeAlphaIndices`.

3. Replace the `onlyOwner` modifier in the original `initializeAlphaIndices` implementation with a new modifier that restricts calls to be only from the `TraitForgeNft` contract.

```solidity
  function initializeAlphaIndices() public whenNotPaused onlyTraitForgeNft {
    _initializeAlphaIndices();
  }
```

4. Add necessary logic to set and update the `onlyTraitForgeNft` modifier.
