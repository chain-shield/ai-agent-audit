# Vulnerability details

## Impact

The initializeAlphaIndices function in the EntropyGenerator contract is restricted to the contract owner, preventing the TraitForgeNft contract from calling it during generation increments. This misalignment of permissions can lead to system-wide failures, including the inability to progress beyond the first generation of NFTs, creating a centralization risk and potentially halting the entire NFT ecosystem.

The `_incrementGeneration` function in TraitForgeNft attempts to call `initializeAlphaIndices` on the EntropyGenerator contract:


   ```solidity
   function _incrementGeneration() private {
     require(
       generationMintCounts[currentGeneration] >= maxTokensPerGen,
       'Generation limit not yet reached'
     );
     currentGeneration++;
     generationMintCounts[currentGeneration] = 0;
     priceIncrement = priceIncrement + priceIncrementByGen;
     entropyGenerator.initializeAlphaIndices();
     emit GenerationIncremented(currentGeneration);
   }
```
This function is called when the current generation reaches its token limit. It attempts to initialize new entropy values for the next generation by calling initializeAlphaIndices.

The entropyGenerator is set in the contract, but it doesn't have special permissions:

```solidity
IEntityForging public entityForgingContract;
IEntropyGenerator public entropyGenerator;
IAirdrop public airdropContract;
```
The setEntropyGenerator function only sets the address without granting any permissions:
```solidity
function setEntropyGenerator(
  address entropyGeneratorAddress_
) external onlyOwner {
  require(entropyGeneratorAddress_ != address(0), 'Invalid address');
  entropyGenerator = IEntropyGenerator(entropyGeneratorAddress_);
}
```
Even though the `EntropyGenerator.sol` contract contains the following logic to bypass this issue. 
```solidity
  // Modifier to restrict certain functions to the allowed caller
  modifier onlyAllowedCaller() {
    require(msg.sender == allowedCaller, 'Caller is not allowed');
    _;
  }

  constructor(address _traitForgetNft) {
    allowedCaller = _traitForgetNft;
    initializeAlphaIndices();
  }
``` 
The issue persists as you can see from the result of the following test

```
function testGenerationManagement() public {
        bytes32[] memory proof;
        vm.deal(player1, 10001 ether);
        vm.deal(ownerAddr, 1 ether);

        // Ensure TraitForgeNft is set as the allowed caller for EntropyGenerator
        vm.prank(ownerAddr);
        entropyGenerator.setAllowedCaller(address(traitForgeNft));

        // Mint max tokens for the first generation
        for (uint256 i = 0; i < 10000; i++) {
            vm.prank(player1);
            traitForgeNft.mintToken{value: 1 ether}(proof);
        }

        // Mint the 10,001st token as the contract owner to trigger generation increment
        vm.prank(ownerAddr);
        traitForgeNft.mintToken{value: 1 ether}(proof);

        assertEq(traitForgeNft.getGeneration(), 2, "Generation should have incremented");

        // Verify that EntropyGenerator's allowed caller is still TraitForgeNft
        assertEq(
            entropyGenerator.getAllowedCaller(),
            address(traitForgeNft),
            "TraitForgeNft should still be the allowed caller"
        );
```

Even though the TraitForgeNft contract is set as the allowed caller for the EntropyGenerator, it still cannot bypass the ownlyOwner modifier to call initializeAlphaIndices. When the generation increment occurs and TraitForgeNft tries to call initializeAlphaIndices, it fails due to the onlyOwner restriction in the EntropyGenerator contract.

This mismatch in permissions prevents the proper progression of generations and entropy updates, potentially halting the entire NFT minting process after the first generation is completed.

## Recommended Mitigation Steps

1. In the EntropyGenerator contract, change the initializeAlphaIndices function to use the onlyAllowedCaller modifier:

```solidity
   function initializeAlphaIndices() public whenNotPaused onlyAllowedCaller {
     
   }
```

2. Ensure that the TraitForgeNft contract is set as the allowed caller during deployment or initialization:

```solidity
entropyGenerator.setAllowedCaller(address(traitForgeNft));

```
