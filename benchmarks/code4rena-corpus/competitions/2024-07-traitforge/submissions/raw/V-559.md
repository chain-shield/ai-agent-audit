# Vulnerability details

## Impact
When Ether is received into `DevFund` contract, the logic checks for allocation ratio among the configured users.Intention is,if there is any balance left after allocation to the configured users will be routed to the contract owner.

But, the calculation has a logic flaw leading to accounting only a single portion of weight from the received funds as `totalRewardDebt`. The remaining is left in the contract and is not retrievable. Such ether is permanently locked in the contact.

## Proof of Concept
In the below logic, the `amountPerWeight` is computed for the received amount. The remaining amount is balance left after allocating the received funds to the users, which is `amountPerWeight * totalDevWeight`.

The problem is in the logic where `totalRewardDebt` is assigned only one portion of the weight from the received amount.

This results in incorrect calculation of the funds available for pending rewards. The ether balance will remain in the contract, but it is not correctly accounted in `totalRewardDebt`, such balance will remain locked.

Refer to the code snippet below.

```
  receive() external payable {
    if (totalDevWeight > 0) {
      uint256 amountPerWeight = msg.value / totalDevWeight;
      uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
 ===> totalRewardDebt += amountPerWeight;
      if (remaining > 0) {
        (bool success, ) = payable(owner()).call{ value: remaining }('');
        require(success, 'Failed to send Ether to owner');
      }
    } else {
      (bool success, ) = payable(owner()).call{ value: msg.value }('');
      require(success, 'Failed to send Ether to owner');
    }
    emit FundReceived(msg.sender, msg.value);
  }
```

Lets demonstrate with an example.

```
msg.value = 1000000000000000000
totalDevWeight = 40 // Four users(10 + 10 + 10 +10)
totalRewardDebt = 0 // First deposit

// Computation of Amount per Weight
uint256 amountPerWeight = msg.value / totalDevWeight;
                        = 1000000000000000000 / 40
                        = 25000000000000000

// Remaining Amount
uint256 remaining  = msg.value - (amountPerWeight * totalDevWeight);
                   = 1000000000000000000 - (25000000000000000 * 40);
                   = 1000000000000000000 - 1000000000000000000;
                   = 0;

// Amount allocated for Distribution
 totalRewardDebt   += amountPerWeight;
                    = 25000000000000000;
``` 

While 1 Ether was received for reward allocation, due to error in the logic, only 0.25 ether is allocated for totalRewardDebt. 0.75  Ether is not accounted for any allocation and will remain locked in the contract.

When the pending rewards are computed, they are computed against `totalRewardDebt`, user's rewardDebt and weight. Hence, the rewards are being distributed from 0.25 ether only. 0.75 ether will remain locked.

```
     info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
```
Hence each user will be allocated the pending rewards as below.

```
   info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
                       += (0.25 ether - 0) * 10;
                      
```

## Recommended Mitigation Steps
The logic in the receive function should be revised as below.

```
receive() external payable {
    if (totalDevWeight > 0) {
      uint256 amountPerWeight = msg.value / totalDevWeight;
      uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
-     totalRewardDebt += amountPerWeight;
+     totalRewardDebt += msg.value - remaining;// allocated for distribution (amountPerWeight * totalDevWeight);
      if (remaining > 0) {
        (bool success, ) = payable(owner()).call{ value: remaining }('');
        require(success, 'Failed to send Ether to owner');
      }
    } else {
      (bool success, ) = payable(owner()).call{ value: msg.value }('');
      require(success, 'Failed to send Ether to owner');
    }
    emit FundReceived(msg.sender, msg.value);
  }
```
