# Vulnerability details

## Summary
The listNFTForSale function does not check if the NFT is already listed, leading to potential issues with duplicate listings and inconsistencies.

## Vulnerability Details
Lack of Listing Check: The EntityTrading::ListNftForSale  function does not verify if the NFT is already listed before listing it again. This can lead to multiple listings for the same NFT, causing confusion. 

```solidity
function listNFTForSale(uint256 tokenId, uint256 price) public whenNotPaused nonReentrant {
    require(price > 0, 'Price must be greater than zero');
    require(nftContract.ownerOf(tokenId) == msg.sender, 'Sender must be the NFT owner.');
    require(
        nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
        'Contract must be approved to transfer the NFT.'
    );
    
    // @audit missing check if NFT is already listed
    nftContract.transferFrom(msg.sender, address(this), tokenId); // transfer NFT to contract
    ++listingCount;
    listings[listingCount] = Listing(msg.sender, tokenId, price, true);
    listedTokenIds[tokenId] = listingCount;

    emit NFTListed(tokenId, msg.sender, price);
}
```

## impact 
 - If an NFT is listed multiple times without verification, it could create inconsistencies and potential disputes over ownership and listing status.
 - Cause confusion among buyers, as there would be multiple listings for the same NFT with potentially different prices.
 - Lead to disputes over which listing is valid if there are multiple active listings for the same NFT.
 - Result in unnecessary gas costs for users who attempt to list an already listed NFT.

## Tools Used
Manual Code Review

## Recommendations
Check Existing Listings: Implement a check to verify if the NFT is already listed before proceeding with a new listing. This can be achieved by checking the listedTokenIds mapping.

```
require(listedTokenIds[tokenId] == 0, 'NFT is already listed');
```
