# Vulnerability details

## Impact
Calculations in `EntropyGenerator::getEntropy()` 6-digit slices of 78-digit number leads to wrong NFT stats distribution
Consider 78-digit number and calculate entropy at `numberIndex=12` (last 6 digits)
`123456...009876`
with calculation in code:
```solidity
//@audit numberIndex==12, position ==72
    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');
//@audit slotValue == `123456...009876`
    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
//@audit entropy == 9876
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
//@audit paddedEntropy == 987600
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
```
6-digit slice of this number at `numberIndex=12` is 009876. Above code recalculates this value to `paddedEntropy=987600`. Much more numbers than expected will have 0 digit at the end
