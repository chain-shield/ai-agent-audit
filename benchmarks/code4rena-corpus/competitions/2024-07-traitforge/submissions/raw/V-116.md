# Vulnerability details

## Impact 
In the `mintWithBudget` function of the `TraitForgeNft.sol` contract, one of the minting conditions is `_tokenIds < maxTokensPerGen`. The issue is that the `_tokenIds` state variable continually increases with calls to `_mintInternal` and `_mintNewEntity`. According to the whitepaper, ["The game is capped at 10 Generations for now. Generations can only forge with each other and up to a max of 10000 for each generation."](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit). The `_tokenIds` can continuously increase up to 10 * 10000, while `maxTokensPerGen` is only 10000. This discrepancy will prevent minting of NFTs greater than 10000 using the `mintWithBudget` function. It is recommended to change `_tokenIds < maxTokensPerGen` to `generationMintCounts[currentGeneration] < maxTokensPerGen`, or remove the check, as `mintWithBudget` calls the `_mintInternal` function, which handles the `generationMintCounts[currentGeneration] >= maxTokensPerGen` condition.
