# Vulnerability details

## Impact
[_mintInternal](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-L283) will mint the first NFT of each generation for the price of the last NFT from the last generation, skyrocketing it's price.

## Proof of Concept
[mintToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L181) is used by users to mint their NFTs. That function invokes [_mintInternal](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-L283) with the `msg.sender` and `mintPrice`, where the mint price is calculated with [calculateMintPrice](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L227-L232) based on:
```markdown
minted NFTs from this generation * price increment per NFT + starting price
```

```solidity
   function calculateMintPrice() public view returns (uint256) {
      // startPrice + generationMintCounts[currentGeneration] * priceIncrement
      uint256 currentGenMintCount = generationMintCounts[currentGeneration];
      uint256 priceIncrease = priceIncrement * currentGenMintCount;
      uint256 price = startPrice + priceIncrease;
      return price;
   }
```

Where the last NFT will have the highest price, as it's `10000 * priceIncrement + startPrice`, and the NFT after that will be from the next generation, using the much lower (or even reset) `generationMintCounts`, getting a lower price.

With the above in mind we can see that [mintToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L181) will first calculate the price and then call [_mintInternal](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280):

```solidity
   uint256 mintPrice = calculateMintPrice();
   require(msg.value >= mintPrice, "Insufficient ETH send for minting.");

   _mintInternal(msg.sender, mintPrice);
```

However if `generationMintCounts[currentGeneration] >= maxTokensPerGen` then [_mintInternal](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L281-L283) will first trigger [_incrementGeneration](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355) increasing the generation and then it will mint the NFT. This will cause the first NFT of the next gen to be priced at the last NFT from the last gen.

```solidity
    function _mintInternal(address to, uint256 mintPrice) internal {
        if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
            _incrementGeneration();
        }

        _tokenIds++;
        uint256 newItemId = _tokenIds;
        _mint(to, newItemId);
```

## Recommended Mitigation Steps
A good solution is to move the `if` before calculating the price, do this in [mintToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L181) and [mintWithBudget](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L202):

```diff
   function mintToken(bytes32[] calldata proof) ... {
+     if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
+        _incrementGeneration();
+     }
      uint256 mintPrice = calculateMintPrice();
      require(msg.value >= mintPrice, "Insufficient ETH send for minting.");
```
