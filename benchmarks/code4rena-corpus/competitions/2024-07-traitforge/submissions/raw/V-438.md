# Vulnerability details

The `listNFTForSale()` function transfers the NFT token from the seller to the `EntityTrading` contract using [nftContract.transferFrom(msg.sender, address(this), tokenId)](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L53). It then creates a new listing with the seller's address (`msg.sender`) as the original owner. However, it does not prevent the token from being transferred again externally.

If an external `transferFrom()` call is made to transfer a listed token, the actual ownership of the token will change, but the listing and the `tokenOriginalOwner` mapping will still point to the original seller. This violates the `consistentOriginalOwner` invariant because the original owner in the ghost mapping will no longer match the actual owner of the token.

1. **Line 53**: [nftContract.transferFrom(msg.sender, address(this), tokenId);](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L53) - transfers the NFT from the seller to the contract when listing an NFT for sale.

2. **Line 81**: [nftContract.transferFrom(address(this), msg.sender, tokenId);](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L81) - transfers the NFT from the contract to the buyer when an NFT is purchased.

3. **Line 104**: [nftContract.transferFrom(address(this), msg.sender, tokenId);](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L104) - transfers the NFT from the contract back to the seller when a listing is canceled.

## Impact
1. The original seller may no longer have control over the listed token, but the listing will still indicate them as the seller.
2. The new owner of the token may not be able to cancel the listing or receive the proceeds from the sale.
3. The [buyNFT()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L63-L92) function may transfer the token to the buyer but send the payment to the original seller instead of the current owner.

## Proof of Concept
1. Alice lists her NFT token with ID 1 using the `listNFTForSale()` function.
2. The token is transferred to the `EntityTrading` contract, and a new listing is created with Alice as the seller.
3. Alice approves Bob to transfer the token using the NFT contract's `approve()` function.
5. Bob calls the NFT contract's `transferFrom()` function to transfer the token from the `EntityTrading` contract to himself.
6. The token ownership is now changed to Bob, but the listing and the `tokenOriginalOwner` mapping still indicate Alice as the seller.
7. The `consistentOriginalOwner` invariant is violated because the original owner in the ghost mapping (Alice) no longer matches the actual owner of the token (Bob).

## Recommended Mitigation Steps
Consider adding check in the `transferFrom()` function of the NFT contract to prevent the transfer of listed tokens. This can be done by:

1. Keeping track of the listed tokens in the `EntityTrading` contract, either by storing them in a separate mapping or by checking the `listedTokenIds` mapping.
2. Modifying the NFT contract's `transferFrom()` function to check if the token being transferred is listed in the `EntityTrading` contract.
3. If the token is listed, the `transferFrom()` function should revert the transaction to prevent the transfer.
