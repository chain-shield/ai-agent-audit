# Vulnerability details

## Impact
The document the forge potential as the 5th digit of entropy: Entropy[4] = colour1 && forgePotential. But in EntropyGenerator::deriveTokenParameters the forge potential was calculated as the first digit of entropy.
According to the document, 10% of the population is infertile from birth, which means 10% of the forgePotential should be zero. Owing to the padding strategy below, if the first digit was chosen as forgePotential, the probability of getting a zero is 0, which was wrong. Still if the fifth digit was chosen, the probability of it being zero is actually (90%+9%)*10%+(1-99%)=10.9% (90% for not having to pad, 9% for having to pad one digit).

```solidity
// EntropyGenerator.sol : 52
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array

// EntropyGenerator.sol : 180
    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
```
