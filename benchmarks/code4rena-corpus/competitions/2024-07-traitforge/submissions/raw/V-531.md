# Vulnerability details

## Vulnerability Details
Entropy is a key component in trait forge game mechanism. Based on the documentation it's specified in specific range [100000,999999]. It's generated using 78 digits numbers and slots. 
```solidity
    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

    return paddedEntropy; // return the caculated entropy value
```
It's generated using 2 values numberIndex and slotIndex. 78 digits number is retrieved using slot index and then it cut six digit from specific point using numberIndex variable. If cutted number is lower than six digits number ( because it can cut something like this 001234 ). It uses padding with zero method for the remaining digits. ( eg: 123400 ).

There are 2 ways to mint 0 entropy NFT in this implementation and I decided to open a report for both of those problems and the problem can be solved easily.

### First possibility

As I described before, it uses padding method for lower than six digits number but if the cutted number is 000000, padding doesn't work in this situation. 


### Second possibility

Before starting to minting NFTs, random value slots should be initialized with following functions:

writeEntropyBatch1()
writeEntropyBatch2()
writeEntropyBatch3()

if it's not initialized, the entropy values will be 0 again and it's not checked in any line

## Impact
Main functionality problems
This NFT can't use forge feature and nuking function, because it doesn't have value.
