# Vulnerability details

`mintWithBudget()` is used to mint nfts in batches proportional to the funds sent by the user. The excess funds are sent back to the user.

However inside the while loop, there is a check which will always return `false` after **generation 1** has completed minting.

## Proof of Concept

Inside the `while` loop, the nfts are minted till the user's funds exceed the minting price for that nft and if `_tokenIds < maxTokensPerGen`.
```solidity
File: TraitForgeNft.sol

   function mintWithBudget(
   ...
>    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
       _mintInternal(msg.sender, mintPrice);
       amountMinted++;
       budgetLeft -= mintPrice;
       mintPrice = calculateMintPrice();
     }
    ...
```
The issue is in the second check because `_tokenIds` is incremented whenever a nft is minted. So when all the nfts are minted for **generation 1**, that is `10,000`, the value of `_tokenIds` will be `10,000`.
The value of `maxTokensPerGen` is set to `10,000`.

So now when the 1st nft of **generation 2** is about to be minted, the value of `_tokenIds` is `10,000` which is not reset (& shouldn't be). 

```solidity
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
```
If either `mintToken()` of `forge()` is used, `_tokenIds` becomes greater than `10,000`. Thus the above loop will never be executed. 
All the fund sent when calling this function will simply be returned back to the user.

## Impact
DoS when calling `mintWithBudget()` after generation 1

Manual Review

Use `generationMintCounts` for the current generation instead of `_tokenIds`.
