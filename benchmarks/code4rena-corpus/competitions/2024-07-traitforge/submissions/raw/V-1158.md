# Vulnerability details

## Impact
`EntityTrading::listNFTForSale` [approval](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L47-L51) check will not work

## Proof of Concept
In `EnitityTrading::listNFTForSale()` there is a require check on the approved addresses of the tokenId
```soldiity
    require(
      nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
      'Contract must be approved to transfer the NFT.'
    );
```
However, this check is ineffective because if you check within the [`ITraitForgeNft`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/ITraitForgeNft.sol#L6), which `nftContract` is of type, You will not see `getApproved()` or `isApprovedForAll()` which is used in the require check above.

Therefore resulting in the ineffectiveness of the check  

## Tools Used
Manual review (Vs Code)

## Recommended Mitigation Steps
use `isApprovedOrOwner` instead of `isApprovedForAll` and `getApproved`, because it can be found in the interface inherited by the `nftContract`

```diff
function listNFTForSale(
    uint256 tokenId,
    uint256 price
  ) public whenNotPaused nonReentrant {
    require(price > 0, 'Price must be greater than zero');
    require(
      nftContract.ownerOf(tokenId) == msg.sender,
      'Sender must be the NFT owner.'
    );

-    require(
      nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
      'Contract must be approved to transfer the NFT.'
    );
+    require( nftContract.isApprovedOrOwner(address(this), tokenId),
      'Contract must be approved to transfer the NFT.'
    );               
...
}
```
