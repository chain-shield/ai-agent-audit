# Vulnerability details

## Impact
User could list their max generation forgerTokenId but no one could merge with it. If someone try to merge with it, it will revert.

## Proof of Concept
1. User with a max generation forgerTokenId could list it by `EntityForging::listForForging() function because there's no check that the forgerTokenId is at max generation.
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L67-L100
2. Then no one could merge with it including the mergerTokenId with the same generation with it.

Firstly, it could revert here in EntityForging if mergerTokenId < forgerTokenId:
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L119-L123
```solidity
 require(
      nftContract.getTokenGeneration(mergerTokenId) ==
        nftContract.getTokenGeneration(forgerTokenId),
      'Invalid token generation'
    );
```
Secondly, it could revert even with mergerTokenId = forgerTokenId
Calling forge() function here
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L150-L155
```solidity
 uint256 newTokenId = nftContract.forge(
      msg.sender,
      forgerTokenId,
      mergerTokenId,
      ''
    );
```

And then check and revert here in TraitForgeNft
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L163-L166
```solidity
 uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

  /// Check new generation is not over maxGeneration
  require(newGeneration <= maxGeneration, "can't be over max generation");
```

## Recommended Mitigation Steps
Adding a check in EntityForging::listForForging() to ensure the token is not at max generation.
