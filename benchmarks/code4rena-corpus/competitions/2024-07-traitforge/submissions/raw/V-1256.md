# Vulnerability details

## Impact
New generation of NFT minting is impossible thus halting the game permanently after all nfts from the first generation has been minted

## Proof of Concept
When all tokens from the first generation are minted, the next NFT mint transaction is meant to call a number of functions to change the current generation to the next generation, amongst these functions is the *_incrementGeneration()* function which in turn calls *entropyGenerator.initializeAlphaIndices();*. Calling this function will however always revert due to the onlyOwner restriction put on it.

```
function testNewGen() public {
        vm.warp(block.timestamp + 25 hours);
        vm.roll(1);
        vm.deal(alice, 10e18);
        vm.deal(bob, 1e18);
        vm.deal(owner, 1e18);

        vm.prank(owner);
        entropyGenerator.writeEntropyBatch1();

        bytes32[] memory proof;

        //maxTokens per gen has been modified for  testing purposes
        //mint all tokens from the first generation
        vm.prank(alice);
        traitForgeNft.mintWithBudget{value: 0.6e18}(proof);

        uint256 mintPrice = traitForgeNft.calculateMintPrice();
        //mint new token which is meant to be from the next generation
        //Call will always revert due to "Ownable: caller is not the owner" error 
        //due to 
        //EntropyGenerator::initializeAlphaIndices being called by the 
        //traitForgeNft contract
        vm.expectRevert();
        vm.prank(bob);
        traitForgeNft.mintToken{value : mintPrice}(proof);
    }
```
The above demonstrates that initializing token minting from the next generation always fails when called by the NFT minting contract.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider making the *EntropyGenerator::initializeAlphaIndices* callable by both the owner and allowedCaller addresses.
