# Vulnerability details

## Impact
- Whenever max NFT token has been minted for generation, the generation gets incremented through `_incrementGeneration()`
- Inside the function `generationMintCounts[currentGeneration] = 0;` has been set to zero which is where problem arises.
- Let's take an example where user `forge` NFT and gets minted new generation NFT (current generation + 1) through `forgeWithListed` and `_mintNewEntity()`.
- Let's suppose the above steps gets done by other 100 user.
- So now there is already 100 NFT minted of second generation.
- Now when 10,000 NFTs of first generation gets minted after that the generation gets incremented. During incrementing `generationMintCounts[currentGeneration] = 0;` has been set to zero.
- So now another 10000 NFTs of second generation can be minted excluding 100 NFTs which were minted through `forgeWithListed` and `_mintNewEntity()`.
- This violated as per protocol and leading to loss for protocol.
