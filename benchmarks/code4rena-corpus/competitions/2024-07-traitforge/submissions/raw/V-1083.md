# Vulnerability details

## Description
The `EntropyGenerator` contract uses a three-stage process to initialize entropy values stored in the `entropySlots` array. The entropy values are generated using pseudo-random numbers based on the block number and slot index, then stored in the contract. This process results in predictable entropy values since the array is accessible on the blockchain. Users can leverage this predictability to time their minting actions to obtain NFTs with desirable traits.

## Impact
The predictability of entropy values has significant implications:
1. Minting Exploitation: Users can predict future entropy values based on the current index and slot, allowing them to mint NFTs when the entropy value aligns with their desired traits.
2. Unfair Advantage: This predictability undermines the fairness of the minting process, as users can only mint NFTs when the entropy values are favorable, giving them an undue advantage.
3. Integrity of Entropy: The method of generating entropy values may lead to predictable outcomes, impacting the randomness and uniqueness of NFTs.

## Proof of Concept
The entropy values are generated using `(uint256(keccak256(abi.encodePacked(block.number, i))) % 10^78)`, and the entropy values are stored in the `entropySlots` array. Anyone can retrieve the entropy value for each index, calculate the current and future entropy values, and predict when favorable traits will be available for minting.

Users can track the current entropy index and predict the values for future slots, allowing them to strategically mint NFTs with desired traits when the entropy is advantageous (for example : entropy with high `ForgePotential` and `performanceFactor` values).

## Recommended Mitigation Steps
1. Generate Random Entropy on Minting: Instead of using a predictable process, generate a new random entropy value during each mint action. This ensures that entropy values cannot be predicted in advance.
2. Store Entropy in a Mapping: Implement a mapping in the `TraitForgeNFT` contract to store entropy values associated with each token ID. This mapping should be updated with the randomly generated entropy value at the time of minting.
3. Remove Predictable Logic: Eliminate the current method of generating entropy in predictable batches. Ensure that the entropy values are securely generated and stored, making it impossible for users to anticipate future values.
