# Vulnerability details

## Impact
The `mintWithBudget` function uses an incorrect condition to check the maximum number of tokens per generation. This can lead to incorrect behavior when the generation changes within the loop, potentially allowing more tokens to be minted than intended for a given generation. 

## Proof of Concept
Looking at the [`mintWithBudget` function](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225), it uses the global `_tokenIds` counter to check if the maximum number of tokens per generation has been reached:

```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
    _mintInternal(msg.sender, mintPrice);
    amountMinted++;
    budgetLeft -= mintPrice;
    mintPrice = calculateMintPrice();
}
```

This is incorrect because `_tokenIds` is a global counter and not specific to the current generation. The correct condition should use the `generationMintCounts` mapping to check the number of tokens minted in the current generation.

- Manual code review


## Recommended Mitigation Steps
Update the condition in the `while` loop to use the `generationMintCounts` mapping instead of the global `_tokenIds` counter.

```solidity
function mintWithBudget(
    bytes32[] calldata proof
)
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
{
    uint256 initialGeneration = currentGeneration;
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    while (budgetLeft >= mintPrice && generationMintCounts[currentGeneration] < maxTokensPerGen) {
        _mintInternal(msg.sender, mintPrice);
        amountMinted++;
        budgetLeft -= mintPrice;

        // Recalculate mint price only if the generation hasn't changed
        if (currentGeneration == initialGeneration) {
            mintPrice = calculateMintPrice();
        } else {
            // If generation has changed, update initialGeneration and recalculate mint price
            initialGeneration = currentGeneration;
            mintPrice = calculateMintPrice();
        }
    }
    if (budgetLeft > 0) {
        (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
        require(refundSuccess, 'Refund failed.');
    }
}
```

This will ensure that the loop correctly checks the number of tokens minted in the current generation, preventing the minting of more tokens than intended for a given generation.
