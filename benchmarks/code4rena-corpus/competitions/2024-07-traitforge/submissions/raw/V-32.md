# Vulnerability details

## Impact
When the contract NukeFund.sol is deployed, the `ageMultiplier` state variable is automatically initialized to 0. 
This variable is used to calculate the age of an entity, which is a part of the formula that calculates the total amount that can be nuked/claimed from the total pot. If `ageMultiplier` is not set to a non-null value, the total amount to be claimed will always be 0, and the NFT is also destroyed in the claiming process, creating a loss of funds for the users.

## Proof of Concept

The age multiplier is used when computing the age of an Entity in the `calculateAge` function:
```solidity
uint256 age = (daysOld *
  perfomanceFactor *
  MAX_DENOMINATOR *
  ageMultiplier) / 365; // add 5 digits for decimals
return age;
```
As `ageMultiplier` is 0, this function will also return 0.

The age is used in `calculateNukeFactor` to produce the nuke factor:
```solidity
uint256 adjustedAge = calculateAge(tokenId);

uint256 initialNukeFactor = entropy / 40;

uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;

return finalNukeFactor;
```
This function will also return 0. This function is called inside `nuke`, to find out the amount to be claimed:

```solidity
uint256 finalNukeFactor = calculateNukeFactor(tokenId);
uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR;

..    

uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
      ? maxAllowedClaimAmount
      : potentialClaimAmount; 

fund -= claimAmount; 

nftContract.burn(tokenId); // Burn the token
(bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
require(success, 'Failed to send Ether');
```

Since `finalNukeFactor` is 0, the claimAmount will also be 0; The function ends by burning the NFT and sending 0 ETH to the user. Sending 0 ETH is possible, so the next state will not cause a revert; The NFT will be burned and the user will not be able to recover his assets.

## Recommended Mitigation Steps

The issue can be mitigated by assigning the variable a non-zero value at construction, just as for the other `public uint256` vars in the contract:
`uint256 public ageMultiplier = 1;`

The issue can also be mitigated by ensuring that the `setAgeMultiplier` function is called after deploying the contract, but before the first `nuke` call. However, it's not safe to assume that this will be done. By looking in the `scripts` directory in the repository (`deployTasks.ts`), it seems that this function is not called anywhere. Doing a `grep -r setAgeMultiplier` call in the entire repository indicates that currently, there is no planned intention to perform this call post deployment, and severity rules instruct not to speculate on future actions or code changes. Consequently, within the current context, I'll label this issue as a high severity.
