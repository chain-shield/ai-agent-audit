# Vulnerability details

## Impact
The `initializeAlphaIndices` is responsilbe to set the "Golden God" entropy of the next gen. it is being called from `TraitForgeNft` in `TraitForgeNft::_incrementGeneration` function. 
```
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    @> entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
however, the the `initializeAlphaIndices` has `onlyOwner` modifier, which only allow the owner of the contract call this function, thus, the next Generations can not be ever minted, and this might cause DoS of the entire protocol.

## Proof of Concept
when GEN1 is sold out, and `mintToken` is being called in `TraitForgeNft` contract, it will call the `_incrementGeneration` function.
this function will call `initializeAlphaIndices` in the entropyGenerator, which allows only the owner of the contract to call this function.
the NFT contract is not the contract owner, and therefore, this function will always revert, rendering the minting functions unusable.

* one might say, that we can just transfer ownership of the contract to the NFT contract, and therefore it is not a high. however, since the NFT contract is NOT the owner and can not call `onlyOwner` functions, and there's the `allowedCaller`, `modifier onlyAllowedCaller` which is set to the `TraitForgeNft` address, it is a wrong access control.
