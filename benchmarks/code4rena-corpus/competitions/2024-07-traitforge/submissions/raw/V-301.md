# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L177-L191

```solidity
  function cancelListingForForging(
    uint256 tokenId
  ) external whenNotPaused nonReentrant {
    require(
      nftContract.ownerOf(tokenId) == msg.sender ||
        msg.sender == address(nftContract),
      'Caller must own the token'
    );
    require(
      listings[listedTokenIds[tokenId]].isListed,
      'Token not listed for forging'
    );

    _cancelListingForForging(tokenId);
  }
```

This function is used for canceling previous lists for forging, however it has a `whenNotPaused` modifier.

When an NFT owner lists for forge and sequencer goes down or the protocol gets put in a paused state they cannot cancel their listings due to the modifier or the downtime since protocol is going to be deployed on the Base network which is an Optimistic rollup.

Now issue here is the fact that whenever the protocol is removed from the paused state, there is no grace period being given to the owner of the NFT to cancel their listing for forging which could unfairly cost them their NFTs, since a forger can even MEV their tx.

## Impact

Evidently when the protocol is unpaused there is no assurance that the owner has ample time to cancel their intentions on forging which could cause them to lose out on their tokens, also this bug case can also happen due to the chain being down considering deployment is going to be on an optimistic rollup the sequencer could be down which could also cause for the owner not to be able to cancel.

## Recommended Mitigation Steps

Consider removing the `whenNotPaused` from https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L177-L191
