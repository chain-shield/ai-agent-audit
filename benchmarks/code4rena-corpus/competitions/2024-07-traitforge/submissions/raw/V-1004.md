# Vulnerability details

## Impact

EntropyGenerator's `initializeAlphaIndices` uses wrong modifier, it should not be `onlyOwner` but `onlyAllowedCaller`.
The modifier error causes the minting process to be interrupted. This problem will not be discovered after deployment, but after minting 10000 nfts.

## Proof of Concept

```solidity
  modifier onlyAllowedCaller() {
    require(msg.sender == allowedCaller, 'Caller is not allowed');
    _;
  }

  constructor(address _traitForgetNft) {
    allowedCaller = _traitForgetNft;
    initializeAlphaIndices();
  }

  function getNextEntropy() public onlyAllowedCaller returns (uint256) {}

  function initializeAlphaIndices() public whenNotPaused onlyOwner {}
```

Both `getNextEntropy` and `initializeAlphaIndices` can only be called by `TraitForgeNft`, but the modifiers used by the two are inconsistent.
It can be seen from the code that `onlyAllowedCaller` points to `TraitForgeNft`, and `onlyOwner` points to the EOA of the deployed contract. Therefore `onlyAllowedCaller` should be used here.

It is worth mentioning that I did not find in the test file that calling `gen.transferOwnership(address(nft))`; but explicitly called `airdrop.transferOwnership(address(nft))`.
And since the default `maxTokensPerGen` is 10000, this error was not found in the test file, so I think this is a usage error rather than intentional.
