# Vulnerability details

## Bug description
The traits and parameters per NFT are derived from “Entropy” a 6-digit random number. Entropy is set into uint256 slots, with each slot able to contain a 78-digit number - or 13 concatenated entropies. Thus 770 slots are needed to contain 10,000 entropies. 
There is a certain entropy, “999999” which is referred to as “the Golden God” since it has perfect parameters. When the game is first deployed, `initializeAlphaIndices()` is called to set `slotIndexSelectionPoint` and `numberIndexSelectionPoint` variables that are responsible for determining which NFT is going to be a "Golden God".

[EntropyGenerator.sol#L206-L216](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L206-L216)
```solidity
function initializeAlphaIndices() public whenNotPaused onlyOwner {
  uint256 hashValue = uint256(
    keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
  );
  uint256 slotIndexSelection = (hashValue % 258) + 512;
  uint256 numberIndexSelection = hashValue % 13;
  slotIndexSelectionPoint = slotIndexSelection;
  numberIndexSelectionPoint = numberIndexSelection;
}
```

When NFT is minted the entropy for the NFT is requested from the EntropyGenerator.

```solidity
function getNextEntropy() public onlyAllowedCaller returns (uint256) {
    require(currentSlotIndex <= maxSlotIndex, 'Max slot index reached.');
    uint256 entropy = getEntropy(currentSlotIndex, currentNumberIndex);
    if (currentNumberIndex >= maxNumberIndex - 1) {
        currentNumberIndex = 0;
        if (currentSlotIndex >= maxSlotIndex - 1) {
            currentSlotIndex = 0;
        } else {
            currentSlotIndex++;
        }
    } else {
        currentNumberIndex++;
    }
```
As can be seen the entropy is requested based on the `currentSlotIndex` and `currentNumberIndex` which are incremented after to account for a newly minted NFT.

If `currentSlotIndex` and `currentNumberIndex` appear to be values set during the call to `initializeAlphaIndices()`, that NFT will get the best entropy in the game.

The problem arises due to how forging is handled in the system. When two NFTs are forged, the entity for the new NFT is calculated as the average of both parent's entropies.

[TraitForgeNft.sol#L173](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L173)
```solidity
uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;
```
Because EntityGenerator contract is not used during forging to determine the entropy for a new NFT, both `currentSlotIndex` and `currentNumberIndex` values are not updated to account for a newly minted NFT.

Now assume a scenario where `slotIndexSelectionPoint` is set to 769 and `numberIndexSelectionPoint` is set to 0. To mint a `Golden God` NFT (assuming there was no forging) you would need to call `mintToken()` after there have already been 9997 NFTs minted, since 769 * 13 = 9997 entropies in 769 slots.
Now if at least 3 NFTs were minted due to forging, only 9997 NFTs would be left to mint until generation is incremented. So the biggest value `slotIndexSelectionPoint` could take would be 768 and the biggest value `numberIndexSelectionPoint` could take would be 12, which would correspond to an NFT with a number 9997, while the `Golden God` is an NFT with a number 9998.
## Impact
The `Golden God` NFT might never be minted in a generation.

## Recommended Mitigation
When an NFT is minted because of forging, you would need to update the `currentSlotIndex` and `currentNumberIndex` to account for a newly minted NFT.

[TraitForgeNft.sol#L168-L179](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L168-L179)
```diff
    // Calculate the new entity's entropy
    (uint256 forgerEntropy, uint256 mergerEntropy) = getEntropiesForTokens(
        parent1Id,
        parent2Id
    );
-   uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;

+   uint256 newEntropy = entropyGenerator.getNextEntropy();
+   if (newEntropy != 999999) {
+       newEntropy = (forgerEntropy + mergerEntropy) / 2;
+   }

    uint256 newTokenId = _mintNewEntity(
        newOwner,
        newEntropy,
        newGeneration
    );
    return newTokenId;
}
```

This way both indices would be updated and the `Golden God` will always be minted.
