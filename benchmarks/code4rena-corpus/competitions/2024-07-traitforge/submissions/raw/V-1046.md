# Vulnerability details


## Impact
Impact: High, as methods include the whenNotPaused modifier but the contract cannot be paused.

Likelihood: High, as the contracts lack the necessary external functions to pause and unpause, making it certain that the contract can't be paused at all.

## Description
All relevant smart contracts inherit from OpenZeppelin's Pausable contract. However, the _pause and _unpause methods are not exposed externally and thus cannot be called. This results in a situation where methods that use the whenNotPaused modifier cannot actually be paused. This misapplication of the Pausable contract could lead to a false sense of security, as it appears the contracts can be paused, but they cannot.

The affected contracts and their functions are as follows:

`TraitForgeNft.sol` - `startAirdrop()`, `burn()`, `forge()`, `mintToken()`, `mintWithBudget()`

`EntrophyGenerator.sol` - `initializeAlphaIndices()`

`EntityForging.sol` - `listForForging()`, `forgeWithListed()`, `cancelListingForForging()`

`EntityTrading.sol` - `listNFTForSale()`, `buyNFT()`, `cancelListing()`

`DevFund.sol` - `claim()`

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add simple external functions for pausing and unpausing in these contracts, callable by the owner. Below is an example implementation:

```solidity

function pause() external onlyOwner {
    _pause();
}

function unpause() external onlyOwner {
    _unpause();
}

```

By implementing these changes, the contracts can properly utilize the Pausable functionality provided by OpenZeppelin, allowing the owner to pause and unpause contract operations as needed.
