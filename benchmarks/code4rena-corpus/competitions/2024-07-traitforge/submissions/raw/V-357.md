# Vulnerability details

In a generation a maximum of 10,000 nfts can be minted.
When the `generationMintCounts` for the current generation reaches the limit, `_incrementGeneration()` is called & the minted token count is reset to zero.

## Proof of Concept

### Normal Scenario:
- Suppose the current generation is **2**. Lets say that **1000** nfts have been minted in this generation & no forging has ever taken place in the previous generation. The current value of `generationMintCounts` is **1000**.
- Let say that **500** nfts are forged from **generation 1**. This sets `generationMintCounts` to **1500** (because 500 new nfts are minted) for **generation 2**.
- Thus now only **8,500** (10,000 - 1,500) nfts can be minted for **generation 2**.. 
- Meaning that the nfts generated through forging are also counted in addition to the directly minted nfts.

### Buggy Scenario:
- Suppose the current generation is **1**. Lets say that **5000** nfts have been minted in this generation & no forging has ever taken place. The current value of `generationMintCounts` is `5000`.
- Lets say **1000** nfts are forged in the current generation. This sets `generationMintCounts` for **generation 2** to `1000` (because 1000 new nfts are minted for **generation 2**).
- Note that `generationMintCounts` for `generation 1` is `5000` & for `generation 2` is `1000`.
- Now lets say that `generationMintCounts` for **generation 1** has reached `maxTokensPerGen`.
- `_incrementGeneration` will be triggered whenever the next nft is minted.
```solidity
File: TraitForgeNft.sol

  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
>   currentGeneration++;
>   generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
- Here we can see that `currentGeneration` is incremented & the `generationMintCounts` for the next generation is set to `0`.
- Taking the above situation, `generationMintCounts` for **generation 2** which was earlier set to `1000` because of the forged nfts, is now reset to `0`.
- Because of this reset, now **10,000** nfts can be again minted for **generation 2**. 
- Now if anyone forges from **generation 1**, both the forged & directly minted are takin into account inside `generationMintCounts`.
- This means that **11,000** nfts can be minted for **generation 2** which is above the `maxTokensPerGen`.

Another drawback is that the price for minting the nft is also reset in `calculateMintPrice()` because `generationMintCounts` has been reset to `0`.

```solidity
File: TraitForgeNft.sol

  function calculateMintPrice() public view returns (uint256) {
>    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
>    uint256 priceIncrease = priceIncrement * currentGenMintCount;
>    uint256 price = startPrice + priceIncrease;
    return price;
  }
```
This would allow the protocol to gain more funds than intended. Taking the above scenario, the protocol would get **extra funds for 1,000** nfts (11,000 - 10,000).

*Note - Setting the severity to High because of double impact & that the likelihood of this happening is 100%*

## Impact
`maxTokensPerGen` can be bypassed resulting in incorrect number of nfts that can be generated for a given generation. 
Protocol gains extra funds than intended.
