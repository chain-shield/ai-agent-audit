# Vulnerability details

## Impact
A user can mint a higher generation NFT through forging. When the current generation is incremented, it will reset the higher generation's mint count. That will reset the available tokens for that generation to 10,000. Effectively that means you can mint more than 10,000 tokens per generation. That breaks on of the core invariants

## Proof of Concept
When a NFT is minted through forging, it increments the generation's mint count:

```sol
  function _mintNewEntity(
    address newOwner,
    uint256 entropy,
    uint256 gen
  ) private returns (uint256) {
    require(
      generationMintCounts[gen] < maxTokensPerGen,
      'Exceeds maxTokensPerGen'
    );

    _tokenIds++;
    uint256 newTokenId = _tokenIds;
    _mint(newOwner, newTokenId);

    tokenCreationTimestamps[newTokenId] = block.timestamp;
    tokenEntropy[newTokenId] = entropy;
    tokenGenerations[newTokenId] = gen;
    generationMintCounts[gen]++;
    initialOwners[newTokenId] = newOwner;
    // ...
}
```

When the current gen is incremented, `generationMintCounts` is set to 0:

```sol
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

`generationMintCounts` is used to determine when to increment to the next gen:

```sol
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

## Recommended Mitigation Steps
`_incrementGeneration()` shouldn't reset `generationMintCounts`.
