# Vulnerability details

## Impact
`mintWithBudget` function won't work after _tokenIds will be more than 10,000, so users couldn't use batch minting. 

## Proof of Concept
```solidity
uint256 public maxTokensPerGen = 10000;

while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
        _mintInternal(msg.sender, mintPrice);
        amountMinted++;
        budgetLeft -= mintPrice;
        mintPrice = calculateMintPrice();
}
```
Minting is available if `_tokenIds` is less than 10,000. However, every mint inside `_mintInternal` increases `_tokenIds`. When the number of minted tokens for the current generation equals `maxTokensPerGen`, the generation is incremented using `_incrementGeneration`.

After the first generation, when `_tokenIds` exceeds 10,000, `mintWithBudget` will no longer work for users. 
Transaction will not fail, users get his funds back but no tokens minted, so user still lose money on gas and function if denial of service.
