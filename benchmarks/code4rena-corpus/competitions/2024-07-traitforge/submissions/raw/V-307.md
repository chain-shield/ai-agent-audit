# Vulnerability details

## Impact
The calculation of pending rewards in `DevFund` contract is incorrect. The logic does not take into consideration the `totalDevWeight` while allocating the pending rewards. As such incorrect/excess proportion of rewards are being allocated to the user.

Due to this incorrect allocation, there will not be enough records to claim for the users.

## Proof of Concept
The contract has `totalDevWeight` to track the total weightage given as well as it tracks the weightage given to each individual user. The `totalDevWeight` is updated every time the user is added, removed or updated.

But, the error is in the calculation of rewards. When the pending rewards are allocated for the user, the logic does not apportion the `totalRewardDebt` in accordance with the weightages.

To demonstrate with an example,

Lets say, 

```           
totalRewardDebt = 10000
totalDevWeight = 70

The total Dev weight is distributed among the below 4 users.
UserA = 20
UserB = 20
UserC = 20
UserD = 10

```
If this was the first allocation of 10000 rewards, the current computation will be. In this case, only `UserD` will be able to claim the rewards.

#### Current Implementation
```
 
info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;

UserA  =  0 + (10000-0) * 20
       =  20000

UserB  = 0 + (10000-0) * 20   
       = 20000

UserC  = 0 + (10000-0) * 20
       = 20000

UserD = 0 + (10000-10)* 10
      = 10000
```  

#### Correct Implementation
The correct computation should be to allocate the additional deposits in proportion to their weight as below.

``` 
=> info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight/totalDevWeight;

UserA  =  0 + (10000-0) * 20/70
       =  20000/70 = 2857

UserB  = 0 + (10000-0) * 20   
       =  20000/70 = 2857

UserC  = 0 + (10000-0) * 20
        =  20000/70 = 2857

UserD = 0 + (10000-10)* 10
       =  10000/70 = 1428
```   

Since 10000 was available for distribution, the sum should tally now
   
```
  Total Pending Rewards to Allocate =  2857 + 2857 + 2857 + 1428 
                                    =  9999
```
Ignoring the rounding truncation, the revised logic will allocate the rewards correctly between the accounts based on the weight-age allocated.

## Recommended Mitigation Steps
In order to fix the error, update the `pendingRewards` formulae as below.

```
info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight/totalDevWeight;
```

All the below functions should be fixed.

```
  function updateDev(address user, uint256 weight) external onlyOwner {
    DevInfo storage info = devInfo[user];
    require(weight > 0, 'Invalid weight');
    require(info.weight > 0, 'Not dev address');
    totalDevWeight = totalDevWeight - info.weight + weight;
-   info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
+   info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight/totalDevWeight;
    info.rewardDebt = totalRewardDebt;
    info.weight = weight;
    emit UpdateDev(user, weight);
  }

  function removeDev(address user) external onlyOwner {
    DevInfo storage info = devInfo[user];
    require(info.weight > 0, 'Not dev address');
    totalDevWeight -= info.weight;
-    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
+    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight/totalDevWeight;
    info.rewardDebt = totalRewardDebt;
    info.weight = 0;
    emit RemoveDev(user);
  }

  function claim() external whenNotPaused nonReentrant {
    DevInfo storage info = devInfo[msg.sender];

 -   uint256 pending = info.pendingRewards +
      (totalRewardDebt - info.rewardDebt) *
      info.weight;
 +   uint256 pending = info.pendingRewards +
      (totalRewardDebt - info.rewardDebt) *
      info.weight/totalDevWeight;

    if (pending > 0) {
      uint256 claimedAmount = safeRewardTransfer(msg.sender, pending);
      info.pendingRewards = pending - claimedAmount;
      emit Claim(msg.sender, claimedAmount);
    }

    info.rewardDebt = totalRewardDebt;
  }

  function pendingRewards(address user) external view returns (uint256) {
    DevInfo storage info = devInfo[user];
    return
-      info.pendingRewards + (totalRewardDebt - info.rewardDebt) * info.weight;
+      info.pendingRewards + (totalRewardDebt - info.rewardDebt) * info.weight/totalDevWeight;
  }
```
