# Vulnerability details

## Impact
`mintWithBudget` doesn't work with next generation, only works with the first generation.

## Proof of Concept
In `mintWithBudget`, it requires `_tokenIds < maxTokensPerGen`.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L215-L220
```solidity
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```

The problem here is that `tokenId` keeps increasing and does not reset with the generation of a new generation, meaning that if `maxTokensPerGen` is 10, then the first `tokenId` of the second generation will be 10 and will continue to increase, no longer satisfying `tokenId < maxTokensPerGen`.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L285-L287
```solidity
    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
```

## Recommended Mitigation Steps
I don't know what the intent behind the requirement `_tokenIds < maxTokensPerGen` is. If you only want to limit the tokens to a single generation, you can achieve that by validating `currentGeneration`.
