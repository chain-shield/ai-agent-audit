# Vulnerability details

## Impact
When minting NFTs, if next mintable token is from the next generation, there is a drop in price for the first token being minted due to error in the logic.

As a result, the new NFT will be minted at start price, which is `0.005 ether` every time, a new generation is started.

## Proof of Concept
Lets say, a user is  mining multiple tokens using `mintWithBudget(...)` function.
While minting these multiple NFT tokens, if the current generation reaches the max limit, leading to new generation, the first token minted will be at start price.

Refer to the below code snippet in which the tokens are being minted in a loop by calling the `_mintInternal(...)` function.

```
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```
In the `_mintInternal(...)`, if the `currentGeneration` count reaches `maxTokensPerGen`, the generation is increment in `_incrementGeneration` function as below.

```
    function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
```
Refer to the `_incrementGeneration(...)` function, which sets the `generationMintCounts[currentGeneration]` to 0.

```
    function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
 ===>   generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }

```

With this understanding, lets look at the `calculateMintPrice(...)` function.
Since the `generationMintCounts[currentGeneration]` is set as 0 in the `_incrementGeneration(...)` function, it effects the net increase in price, which is effectively set as 0.

```
    function calculateMintPrice() public view returns (uint256) {
==>    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
==>    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```

```
  // since currentGenMintCount is 0, it impacts the pirceIncrease as below.
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
                          = priceIncrement * 0
                          = 0

  // hence the price for the mint is startPrice, which is 0.005 ether
    uint256 price = startPrice + priceIncrease;
```
As a result, every time, where is an increment in generation, the first minted token will be priced as `0.005 ether`, which is incorrect.
