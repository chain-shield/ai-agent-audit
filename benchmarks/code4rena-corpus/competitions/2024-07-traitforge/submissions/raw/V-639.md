# Vulnerability details

## Impact
There should be one `999999` entropy per generation, but for every next generation there is a small range of indexes that will be unreachable.
 
There is total 10010 possible 6-digit entropy values (770 entropy slots with 78 digit numbers, 770*78/6=10010. Maximum number of NFT's per generation is 10000.

However, when entering new generation, incrementation of entropy generation goes on until reaching 10010. This means that indexes will be shifted and with each generation there is range of unreachable indexes.

## Proof of Concept
We assume that other problems with calculating `999999` entropy position are fixed. It should be written in third batch and be in indexes range 6667-10000.
1. First generation use entropy indexes 0-10000. Everything ok, 'GoldenGod' in range
2. Second generation at first use indexes 10000-10010, then 0-9990. Indexes 9990-10000 will be not used in this generation, but `GoldenGod` can appear there.
3. Third generation uses indexes 9990-10010, then 0-9980. Indexes 9980-9990 will be not used in this generation, but `GoldenGod` can appear there.
4. Etc...
With each generation there is small unreachable range of indexes where `GoldenGod` can appear.

## Recommended Mitigation Steps
Reset entropy indexes at new generation start
1. Add function to `EntropyGenerator.sol`
```
  function resetEntropyIndexes() public whenNotPaused{
    require(msg.sender == owner() || msg.sender == allowedCaller, "Not allowed caller");

    currentSlotIndex = 0;
    currentNumberIndex = 0;
  }
```
2. Call function in `TraitForgeNft::_incrementGeneration()`
