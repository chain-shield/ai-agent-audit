# Vulnerability details

`mintWithBudget()` function in the `TraitForgeNft` contract allows users to mint tokens within a specified budget. It calculates the mint price using the `calculateMintPrice()` function and mints tokens in a loop until the remaining budget is insufficient or the maximum tokens per generation (`maxTokensPerGen`) is reached. After the minting process, any excess budget should be refunded to the caller.

> The root cause of this issue is in the calculation of the `budgetLeft` variable and the refund process. After each token is minted, the `budgetLeft` is reduced by the current `mintPrice`. However, the `mintPrice` is then recalculated using `calculateMintPrice()` for the next iteration. This recalculation may result in a different `mintPrice` value, leading to an incorrect calculation of the remaining budget.

As a result, the refund amount may not accurately reflect the excess budget, leading to incorrect refunds to the caller. In the worst-case scenario, the caller may receive less than the expected refund amount, effectively losing funds. [TraitForgeNft.sol#L215-L224](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L215-L224)
```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
  _mintInternal(msg.sender, mintPrice);
  amountMinted++;
  budgetLeft -= mintPrice;
  mintPrice = calculateMintPrice();
}
if (budgetLeft > 0) {
  (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
  require(refundSuccess, 'Refund failed.');
}
```

## Impact
Incorrect refund of excess budget in the `mintWithBudget()` function can lead to users receiving less than the expected refund amount. May result in financial losses for users who mint tokens using the `mintWithBudget()` function.

## Proof of Concept
1. User calls the `mintWithBudget()` function with a budget of 1 ETH.
2. The initial `mintPrice` is calculated using `calculateMintPrice()`, let's say it's 0.1 ETH.
3. The function enters the minting loop and mints a token using `_mintInternal()`.
4. The `budgetLeft` is reduced by the current `mintPrice` (0.1 ETH), resulting in a remaining budget of 0.9 ETH.
5. The `mintPrice` is recalculated using `calculateMintPrice()` for the next iteration, let's say it increases to 0.15 ETH.
6. The loop continues until the remaining budget is insufficient or the maximum tokens per generation is reached.
7. After the loop, the `budgetLeft` is used to refund the excess budget to the user.
8. However, due to the recalculation of `mintPrice` in each iteration, the `budgetLeft` may not accurately reflect the actual excess budget.
9. As a result, the user may receive less than the expected refund amount.

## Recommended Mitigation Steps
Instead of recalculating the `mintPrice` in each iteration, calculate the total mint cost based on the number of tokens minted and the initial `mintPrice`.

Subtract the total mint cost from the initial budget to determine the excess budget accurately.

Refund the excess budget to the caller.
```diff

+ uint256 initialMintPrice = calculateMintPrice();
  uint256 amountMinted = 0;
  uint256 budgetLeft = msg.value;

- while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
+ while (budgetLeft >= initialMintPrice && _tokenIds < maxTokensPerGen) {
-   _mintInternal(msg.sender, mintPrice);
+   _mintInternal(msg.sender, initialMintPrice);
    amountMinted++;
-   budgetLeft -= mintPrice;
-   mintPrice = calculateMintPrice();
+   budgetLeft -= initialMintPrice;
  }
+ uint256 totalMintCost = amountMinted * initialMintPrice;
+ uint256 excessBudget = msg.value - totalMintCost;
- if (budgetLeft > 0) {
+ if (excessBudget > 0) {
-   (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
+   (bool refundSuccess, ) = msg.sender.call{ value: excessBudget }('');
    require(refundSuccess, 'Refund failed.');
  }
```
