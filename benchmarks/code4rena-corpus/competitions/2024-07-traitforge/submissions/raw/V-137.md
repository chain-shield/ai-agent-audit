# Vulnerability details

## Impact
The contract owner can add a developer with the zero address. This will have an impact on the distribution of funds to developers, as part of the funds will be "reserved" for the developer with the zero address. When a developer wants to claim his funds, he will therefore receive less money than he is supposed to.

## Proof of Concept
https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/DevFund/DevFund.sol#L30
A check is missing in the AddDev function to ensure that the user address does not correspond to the zero address.


```typescript
import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';
import { expect } from 'chai';
import { ethers } from 'hardhat';
import { DevFund } from '../typechain-types';

describe('Add a dev with the ZeroAddress', function () {
    let owner: HardhatEthersSigner;
    let devFund: DevFund;

    before(async () => {
        // Obtenez le signataire par défaut
        [owner] = await ethers.getSigners();

        // Déployez le contrat DevFund
        devFund = await ethers.deployContract('DevFund');
    });

    it('should add a dev successfully', async () => {
        // Test pour ajouter un développeur avec l'adresse zéro
        await expect(devFund.addDev(ethers.ZeroAddress, 5))
            .to.emit(devFund, 'AddDev')
            .withArgs(ethers.ZeroAddress, 5);
    });
});

## Recommended Mitigation Steps
Use a require in the DevFund.sol::addDev(address user, uint256 weight) function to check that the address is not the zero address

require(user != address(0), "Address cannot be zero");

Note that the removeDev function also lacks zero address verification, which means (for the time being) that these funds are not lost forever.
