# Vulnerability details

## Impact
A user i supposed to increase his airdrop record by minting and reducing it by nuking. If a user sells his nft and the new owner nukes it, then the user loses his airdrop balance.

## Proof of Concept
Add this test at the end of NukeFund.test.ts.

This test mints an NFT, thus the user airdrop balance is increased. Then sells that nft to another user, that other user nukes the nft. The end result is the airdrop balance of the initial user to decrease, and since he can't claim when the airdrop has not started, he can do nothing once the nft is sold.

The expected behavior is only increasing/decreasing oneself balance on mint/burn. This case breaks that invariant.

```typescript
  it.only('AUDIT: to mint gen 1 is needed way more ether than expected', async () => {
    const tokenId = 2;

    expect(await airdrop.userInfo(user1)).to.be.eq(0);

    await nft.connect(user1).mintToken(merkleInfo.whitelist[1].proof, {
      value: ethers.parseEther('1'),
    });
    const entropy = await nft.getTokenEntropy(tokenId);
    console.log(entropy);

    // now it increases
    expect(await airdrop.userInfo(user1)).to.be.eq(entropy);

    //selling nft
    await nft.connect(user1).approve(entityTrading, tokenId);
    await entityTrading
      .connect(user1)
      .listNFTForSale(tokenId, ethers.parseEther('0.1'));

    //buying nft
    await entityTrading
      .connect(owner)
      .buyNFT(tokenId, {value: ethers.parseEther('0.1')});

    await nft.connect(owner).approve(await nukeFund.getAddress(), tokenId);
    await nukeFund.connect(owner).nuke(tokenId);

    //now it decreases to previous balance
    expect(await airdrop.userInfo(user1)).to.be.eq(0);
  });
```
