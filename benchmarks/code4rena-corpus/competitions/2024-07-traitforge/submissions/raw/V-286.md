# Vulnerability details

## Impact
When listing your NFT for forging in `EntityForging.sol` a USER A can supply fee amount to receive when his/her NFT is chosen for merging (see `listForForging()`). In the same contract there is a function `forgeWithListed()` where USER B can forge his/her NFT with the one that is already listed for forging. In this process USEB B has to pay a FORGING_FEE, set by the USER A. However, this line in the funtion `forgeWithListed()` checks if the `msg.value` is equal or greater than FORGING_FEE. 
`require(msg.value >= forgingFee, 'Insufficient fee for forging');`. In case that USER B sends more than FORGING_FEE, this amount will be lost and locked in the contract forever, since there is no mechanism in the contract to withdraw excess funds or to refund to the user, like there are in other contracts. 

## Proof of Concept
Run this test that checks the balance of the contract after the forge (with more funds being sent for forging_fee)
``` solidity 
it('should lock excess funds in the contract', async () => {
      const forgerTokenId = FORGER_TOKEN_ID;
      const mergerTokenId = MERGER_TOKEN_ID;

      const contractBalance = await ethers.provider.getBalance(await entityForging.getAddress());
      console.log("Initial contract balance: ", contractBalance);

      const forgerEntropy = await nft.getTokenEntropy(forgerTokenId);
      const mergerEntrypy = await nft.getTokenEntropy(mergerTokenId);
      /// The new token id will be forger token id + 1, cause it's the last item
      const expectedTokenId = FORGER_TOKEN_ID + 1;
      await expect(
        entityForging
          .connect(user1)
          .forgeWithListed(forgerTokenId, mergerTokenId, {
            value:  ethers.parseEther('3.0'),
          })
      )
        .to.emit(entityForging, 'EntityForged')
        .withArgs(
          expectedTokenId,
          forgerTokenId,
          mergerTokenId,
          (forgerEntropy + mergerEntrypy) / 2n,
          FORGING_FEE
        )
        .to.emit(nft, 'NewEntityMinted')
        .withArgs(
          await user1.getAddress(),
          expectedTokenId,
          2,
          (forgerEntropy + mergerEntrypy) / 2n
        );

      const contractBalanceAfterForging = await ethers.provider.getBalance(await entityForging.getAddress());
      console.log("Contract balance after forge: ", contractBalanceAfterForging);

      const listingInfo = await entityForging.listings(forgerTokenId);

      expect(listingInfo.isListed).to.be.eq(false);
    });
```

## Recommended Mitigation Steps
Either use strict equality when checking the amount that user has sent like this 
```require(msg.value == forgingFee, 'Wrong amount of fee for forging');```
or use the mechanism to refund the user like you do in other contracts. However, if you want users to be able to sent more, and you want to keep the change, then you need to implement the `withdraw()` function to get excess fees out of the contract
