# Vulnerability details

## Impact
The currentGeneration can exceed the maxGeneration, thus breaking core functionality.

## Proof of Concept
Assume the following scenario where: 
currentGeneration = 10,
generationMintCounts[10] = 10,000,
and maxGeneration = 10.
If a user calls the mintToken() function (works similarly with mintWithBudget() and the forge() function too) :

1. _mintInternal() function is called which has the following check which gets triggered (since generationMintCounts = 10,000):
(https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L281-L283)
`if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {`
      `_incrementGeneration();`
    `}`

2. In the _incrementGeneration() function (https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355):
the `currentGeneration` is incremented to 11 which is greater than the `maxGeneration` value.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the following checks at line 349 (in the _incrementGeneration() function):
`if(currentGeneration >= maxGeneration) revert MaxGenerationAchieved();`
