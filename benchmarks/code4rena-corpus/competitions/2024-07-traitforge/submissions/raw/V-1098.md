# Vulnerability details

## Description
In the `EntityForging` contract, the `forgeWithListed` function requires users to pay a fee `(forgingFee)` to forge entities. The function checks if the provided fee `(msg.value)` is greater than or equal to the required `forgingFee`. However, the comparison operator used is `>=` rather than `=`. This can lead to scenarios where user funds might be unintentionally locked in the contract if the exact fee is not provided.


## Impact
Users might unintentionally lock their funds in the contract if the provided `msg.value` is greater than the required `forgingFee`, as the contract does not refund excess funds.

## Proof of Concept
If a user sends more than `forgingFee`, the excess amount is not refunded or handled. The function will proceed with the forging process but the additional funds are locked in the contract.
## Tools Used
Manual Review
## Recommended Mitigation Steps
- Refund Excess Funds: Implement logic to refund any excess funds sent by the user if `msg.value` exceeds the `forgingFee`. This ensures that users only pay the exact amount required and any extra funds are returned.
- Handle Exact Payment: Modify the requirement to ensure that users are either required to send exactly `forgingFee` or the contract includes a refund mechanism for any overpayment.
