# Vulnerability details

## Impact
The `EntityForging` contract allows users to forge new tokens by combining two existing tokens. Excess funds are left directly in the `EntityForging` contract instead of being sent to the `NukeFundAddress` or the forger token owner. There is currently no way to sweep this contract, thus excess funds are completely lost and must be recovered through some functionality outside of the scope of this audit.

The following snippet shows how rewards are split:

```

    uint256 devFee = forgingFee / taxCut;
    uint256 forgerShare = forgingFee - devFee;
    address payable forgerOwner = payable(nftContract.ownerOf(forgerTokenId));


    // require(devFee+forgerShare == msg.value, "funds are lost");
    (bool success, ) = nukeFundAddress.call{ value: devFee }('');
    require(success, 'Failed to send to NukeFund');
    (bool success_forge, ) = forgerOwner.call{ value: forgerShare }('');
    require(success_forge, 'Failed to send to Forge Owner');

```

However, it is possible to have excess value where `forgingFee - devFee < msg.value`. In this case, the remaining funds are left in the `EntityForging` contract.


## Proof of Concept
A snapshot of the test that reproduces this issue is located below. For full test suite and setup please go to the [following repository](https://github.com/kamensec/2024-07-traitforge/blob/34a683e9953fe15c8074a4a7249bd1361b7aa13f/test-forge/test/EntityForging.t.sol#L239-L269).

The command to run the test is `forge test --match-test testFailRoundingDuringForgeWithListedLosesEth`

```
    function testFailRoundingDuringForgeWithListedLosesEth() public {
        // Setup
        vm.startPrank(owner);
        traitForgeNft.setEntropyGenerator(address(this));
        traitForgeNft.setEntityForgingContract(address(entityForging));
        vm.stopPrank();

        uint256 initialDevFundBalance = address(entityForging.nukeFundAddress()).balance;

        // Mint tokens
        uint256 forgerTokenId = _helperMintToken(user1, 1, 30);
        uint256 mergerTokenId = _helperMintToken(user2, 2, 31);
        uint256 initialForgingFee = 0.1 ether;
        uint256 finalForgeMsgValue = 0.5 ether;

        vm.deal(user2, 100 ether);

        // List forger NFT for forging
        _helperListForForging(user1, forgerTokenId, initialForgingFee);

        // Forge with the new higher fee
        
        uint256 initialEntityForgingBalance = address(entityForging).balance;
        vm.prank(user2);
        entityForging.forgeWithListed{value: finalForgeMsgValue}(forgerTokenId, mergerTokenId);
        uint256 finalEntityForgingBalance = address(entityForging).balance;

        // @audit - There is no way to recover eth from the EntityForging contract, therefore it shouldn't have balances remaining.
        // @audit - This is a loss of funds for the users and the protocol.
        assertEq(finalEntityForgingBalance, initialEntityForgingBalance, "EntityForging shouldn't hold eth");    
    }
```

## Tools Used
Manual Review, Forge/Foundry

## Recommended Mitigation Steps

The development team should consider adding a function to sweep the remaining funds in the `EntityForging` contract.
