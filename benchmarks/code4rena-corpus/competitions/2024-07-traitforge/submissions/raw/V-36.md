# Vulnerability details

## Impact
The `EntityForging` contract has a vulnerability allowing the forging limit to be exceeded.

## Proof of Concept
[`EntityForging::listForForging()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L87-L90) requires that `forgePotential` for a given `tokenId` is not exceeded. However this is implemented as follows:
```solidity
    require(
>>    forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );
```
As seen, the `<=` operator allows listing even when the `forging count` is already equal to the `forgePotential`. 

This count is again incremented in [`EntityForging::forgeWithListed()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L131-L133), as shown here:
```solidity
    // Check forger's breed count increment but do not check forge potential here
    // as it is already checked in listForForging for the forger
>>  forgingCounts[forgerTokenId]++;
```
Therefore, the limit is exceeded.

### Example Scenario:
**Initial State**:
- `forgePotential` = 5
- `forgingCounts[tokenId]` = 5 --> This means that this `tokenId` has been forged `5 times` already

**listForForging()**:
- `Bob` calls this function and the condition passes since (`5 <= 5`).
- This `tokenId` is then listed for forging.

**forgeWithListed()**
- During forging, `forgingCounts[tokenId]` is again incremented
- New `forgingCounts[tokenId] = 6`. ---> This exceeds the `forgePotential`  since this is the `6th time forging` but the function just allows it.

As seen, `forgePotential` is exceeded: 
---> Users can forge more than the intended limit and still [receive `forgerShare`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L158-L159).
```solidity
    address payable forgerOwner = payable(nftContract.ownerOf(forgerTokenId));
>>  (bool success_forge, ) = forgerOwner.call{ value: forgerShare }(''); // @udit-info forgerShare sent to user
    require(success_forge, 'Failed to send to Forge Owner');
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Adjust Condition in `listForForging()` as follows:
```diff
    require(
-     forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
+     forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
      'Entity has reached its forging limit'
    );
```
The use of the `<` operator ensures that the token can only be listed if `forgingCounts[tokenId]` is strictly less than `forgePotential`. This is so that if the current `forgingCounts[tokenId] = 4`, there is only one last chance to forge this `tokenId` meaning that when `forgeWithListed()` is called, the `forgingCounts[tokenId]` will be incremented to `5`.
Any further attempt to list this `tokenId` for forging will therefore revert as the limit is already reached.
