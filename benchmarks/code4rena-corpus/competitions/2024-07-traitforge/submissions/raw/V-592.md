# Vulnerability details

## Impact
`EntityForging` contract's `fetchListings(...)` function loops through the mapping using `listingCount` variable.

The `listingCount` increments on every listing done via `listForForging(...)` function, but it never decrements even when the listing is cancelled. This means, the  `listingCount` will continue to increment over time and could be a very large number.

Also, when a listing is cancelled, the entity for the listing is removed from the mapping, but `listingCount` is not adjusted.

As a result, when calling  `fetchListings(...)`, the function will return all the records including those that were cancelled.

The `fetchListings(...)` function should return only valid records. The current implementation does not handle the cancelled records correctly in this context.


## Proof of Concept
- When Listing
When `listForForging(...)` is called, the token is listed and `listingCount` is incremented as in the below code snippet.

```
 function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    Listing memory _listingInfo = listings[listedTokenIds[tokenId]];
    ...
 ==>   ++listingCount;
 ==>   listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
 ==>   listedTokenIds[tokenId] = listingCount;

    emit ListedForForging(tokenId, fee);
  }
```

- When cancelling or forging
When the listing is cancelled or forged, the `_cancelListingForForging(...)` is called that deletes the entry from the mapping.

```
  function _cancelListingForForging(uint256 tokenId) internal {
 ==>  delete listings[listedTokenIds[tokenId]];

   emit CancelledListingForForging(tokenId); // Emitting with 0 fee to denote cancellation
  }
```

But, at the time of `fetchListings(...)`, the function loops over the mapping using `listingCount` as a reference. As such, it will loop over all the records, those that were listed as well as those that are already cancelled.

This function result set will not give a good user experience for front ends.

## Recommended Mitigation Steps
The recommendation is to return only the forge listing that is valid. Revise the 
`fetchListings()` as below.
```
   function fetchListings() external view returns (Listing[] memory _listings) {
+    uint256 arraySize = 0; 
+    for (uint256 i = 1; i <= listingCount; ++i) {
+       if(listings[i].isListed){
+         arraySize++;
+       }
+    }

-    _listings = new Listing[](listingCount + 1);
+    _listings = new Listing[](arraySize + 1);
    for (uint256 i = 1; i <= listingCount; ++i) {
+       if(listings[i].isListed){
        _listings[i] = listings[i];
      }
    }
  }
```
