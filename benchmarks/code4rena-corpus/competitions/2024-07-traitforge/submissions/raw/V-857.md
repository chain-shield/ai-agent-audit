# Vulnerability details

## Impact
The `_beforeTokenTransfer` function in the TraitForgeNft contract makes external calls to the `entityForgingContract`. These calls are made after certain state changes but before others. If these external contracts are not secured against reentrancy, this can potentially allow a malicious contract to re-enter the `_beforeTokenTransfer` function and manipulate the contract state.

## Proof of Concept
Here’s a snippet of the vulnerable code:
```
function _beforeTokenTransfer(
    address from,
    address to,
    uint256 firstTokenId,
    uint256 batchSize
) internal virtual override {
    require(!paused(), 'ERC721Pausable: token transfer while paused');
    
    super._beforeTokenTransfer(from, to, firstTokenId, batchSize);

    uint listedId = entityForgingContract.getListedTokenIds(firstTokenId);
    /// @dev don't update the transferred timestamp if from and to address are same
    if (from != to) {
        lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }

    if (listedId > 0) {
        IEntityForging.Listing memory listing = entityForgingContract.getListings(listedId);
        if (
            listing.tokenId == firstTokenId &&
            listing.account == from &&
            listing.isListed
        ) {
            entityForgingContract.cancelListingForForging(firstTokenId);
        }
    }
}

```
If `entityForgingContract.getListedTokenIds` or `entityForgingContract.cancelListingForForging` allows reentrancy, the state changes like `lastTokenTransferredTimestamp[firstTokenId] = block.timestamp` could be reverted or manipulated.

## Tools Used

## Recommended Mitigation Steps

To mitigate the reentrancy risk, state changes should be made before external calls. Here’s the revised code with the mitigation applied:
```
function _beforeTokenTransfer(
    address from,
    address to,
    uint256 firstTokenId,
    uint256 batchSize
) internal virtual override {
    require(!paused(), 'ERC721Pausable: token transfer while paused');
    
    // Update the transferred timestamp first to prevent reentrancy issues
    if (from != to) {
        lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }
    
    // Now call the parent hook
    super._beforeTokenTransfer(from, to, firstTokenId, batchSize);

    uint listedId = entityForgingContract.getListedTokenIds(firstTokenId);
    if (listedId > 0) {
        IEntityForging.Listing memory listing = entityForgingContract.getListings(listedId);
        if (
            listing.tokenId == firstTokenId &&
            listing.account == from &&
            listing.isListed
        ) {
            entityForgingContract.cancelListingForForging(firstTokenId);
        }
    }
}
```
