# Vulnerability details

## Impact

When a `TraitForgeNft` is nuked by calling the `NukeFund.nuke` function, the `claimAmount` of the `nukeFund` is calculated based on the `finalNukeFactor`. Hence any error introduced in the `finalNukeFactor` calculation will result in erroneous `claimAmount` transferred to the `msg.sender`. 

The `finalNukeFactor` is calculated in the `NukeFund.calculateNukeFactor` as shown below:

```solidity
    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) / //@audit-info - defaultNukeFactorIncrease = 250;
      MAX_DENOMINATOR) + initialNukeFactor;
```

The `adjustedAge` variable of the above formulae is calculated in the `NukeFund.calculateAge` as follows:

```solidity
    uint256 daysOld = (block.timestamp -
      nftContract.getTokenCreationTimestamp(tokenId)) /
      60 /
      60 /
      24;
    uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;

    uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals
    return age;
```

The issue here is that `daysOld` parameter which is used to calculate the `age` is calculated by executing multiple division operations `(60 / 60/ 24)`. Each of these division operations introduces rounding error which adds on each subsequent division operation. Hence the `60/60/24` division operation can be replaced by a single division of `86400` value. This will reduce the rounding error and will result in more accurate `age` value.

Further to the above due to the division of `nft creation timestamp value` by `seconds per day` this could introduce a rounding error up to a maximum of `1 day` in the `age` calculation. When this `error of 1 day` is multiplied by the `perfomanceFactor` value (where maximum value of `perfomanceFactor` is `9`) the maximum error in the `age` calculation will be upto `9 days`.

When the `finalNukeFactor` is calculated by using the above `age` value the maximum error in the `finalNukeFactor` calculation will be upto `((((1 * 9 * 10^5) / 365) * 250) / (10^5)) + initialNukeFactor = (9*250 / 365) + initialNukeFactor = 6.16 + initialNukeFactor`. Hence the maximum `finalNukeFactor` error introduced is `6.16`.

This error of `6.16` in `finalNukeFactor` could introduce loss of funds to the `msg.sender` of the `nuke` transaction since his calculated `finalNukeFactor` is less by `6.16` due to above rounding error. Hence his claimed fund amount will be less than what he deserves.
Furthermore due to this rounding error the result of the `finalNukeFactor > nukeFactorMaxParam` conditional check in the `NukeFund.nuke` function could also return the wrong output, thus resulting in loss of funds to the `msg.sender` of the `nuke` transaction.

## Recommended Mitigation Steps

Hence it is recommended to modify the `age` value calculation in the `NukeFund.calculateAge` function as shown below to avoid the rounding error:

```solidity
    uint256 timestampDifference = block.timestamp -
      nftContract.getTokenCreationTimestamp(tokenId)

    uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;

    uint256 age = (timestampDifference *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / (365 * 86400); // add 5 digits for decimals
    return age;
```

In the above code snippet the division is executed after all the multiplication operations are executed. This will reduce the rounding error and will result in more accurate `age` value. Thus in turn will result in more accurate `finalNukeFactor` value. This will reduce the error in the `claimAmount` calculation and will result in more accurate `claimAmount` value thus letting the `msg.sender` of the `nuke` transaction to claim the correct amount of funds.
