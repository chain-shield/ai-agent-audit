# Vulnerability details

## Impact

The vulnerability lies in the minting function of the contract, where the mint price is calculated based on the current generation. However, if the minting of the current generation reaches its maximum limit `(generationMintCounts[currentGeneration] >= maxTokensPerGen)`, the function proceeds to mint a new generation token without recalculating the mint price for the new generation. This discrepancy can cause users to overpay for their tokens, as they are charged the mint price for the previous generation while receiving a token from the new generation. 

## Proof of Concept

In this scenario, if the condition `generationMintCounts[currentGeneration] >= maxTokensPerGen` is true, the `_incrementGeneration()` function is called, which mints new generation token. However, the mintPrice is calculated for previous generation token, leading to a mismatch in the expected and actual mint prices.

```solidity
function mintToken( bytes32[] calldata proof)
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    //@audit price calculated before mint
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');
    _mintInternal(msg.sender, mintPrice);
```
