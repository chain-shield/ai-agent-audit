# Vulnerability details

## Impact
The public access to the `writeEntropyBatch1`, `writeEntropyBatch2`, and `writeEntropyBatch3` functions in the `EntropyGenerator` contract make anyone can call these functions to manipulate entropy values before the project team call them, thus affecting the traits and parameters of specific entities.

## Proof of Concept
In the EntropyGenerator contract, there are three functions—`writeEntropyBatch1`, `writeEntropyBatch2`, and `writeEntropyBatch3`—used to initialize `entropySlots`, where each slot contains a 78-digit number, or 13 concatenated entropies, which are crucial for determining the traits and parameters per entity.

Here’s the code:

```solidity
function writeEntropyBatch1() public {
    require(lastInitializedIndex < batchSize1, "Batch 1 already initialized.");

    uint256 endIndex = lastInitializedIndex + batchSize1; // calculate the end index for the batch
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, "Invalid value, retry.");
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array
      }
    }
    lastInitializedIndex = endIndex;
  }

  // second batch initialization
  function writeEntropyBatch2() public {
    require(
      lastInitializedIndex >= batchSize1 && lastInitializedIndex < batchSize2,
      "Batch 2 not ready or already initialized."
    );

    uint256 endIndex = lastInitializedIndex + batchSize1;
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        require(pseudoRandomValue != 999999, "Invalid value, retry.");
        entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = endIndex;
  }

  // allows setting a specific entropy slot with a value
  function writeEntropyBatch3() public {
    require(
      lastInitializedIndex >= batchSize2 && lastInitializedIndex < maxSlotIndex,
      "Batch 3 not ready or already completed."
    );
    unchecked {
      for (uint256 i = lastInitializedIndex; i < maxSlotIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = maxSlotIndex;
  }
```

However, all three functions are `public`, lacking any access control, which means anyone can call these functions. This creates a potential time window before the project team call them, allowing an attacker to manipulate specific slot values based on the contract’s entropy calculation method (`uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78;`). This manipulation could affect the traits and parameters of specific entities.
﻿
For example, an attacker might aim to compromise the first entity by ensuring that its traits and parameters are bad (e.g., a very low `initialNukeFactor`). By pre-computing the entropy values for each block, the attacker could call the `writeEntropyBatch1` function when they observe that the entropy for the first slot is favorable for their intended attack, thereby gaining control over this slot's value.
﻿
It is important to note that even if the team calls `writeEntropyBatch1`, `writeEntropyBatch2`, and `writeEntropyBatch3` immediately in succession after deploying the contract (although the deployment script now does not call them immediately), this manipulation attack could still be possible. On one hand, network delays between transactions could create attack windows between each batch call. Additionally, since `Batch1` and `Batch2` cannot contain entropy values of 999999 (which would cause the transaction to revert), this scenario could also create an opportunity for manipulation attack if such values were encountered.
