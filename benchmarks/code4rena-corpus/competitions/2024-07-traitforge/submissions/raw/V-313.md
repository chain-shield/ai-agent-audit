# Vulnerability details

## Impact
There can be an NFT with 0 entropy, making it dead and useless.

## Proof of Concept
[getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L164-L185) cycles trough `entropySlots` and their positions to return a 6 digit number referred as entropy. Every digit of this number assigns a special trait, and because of it this number needs to be 6 digits and not start with 0. That is why [getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L164-L185) implements some checks and if the number is 5 or less digits it multiplies to get it up to 6.

```solidity
        uint256 position = numberIndex * 6;
        require(position <= 72, "Position calculation error");

        uint256 slotValue = entropySlots[slotIndex];
        uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000;

        uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
        return paddedEntropy;
```

Example is if entropy is `001234`, then `getEntropy` will multiply it by 100 during it's padding and return `123400` as entropy.

However that would not be the case if we get entropy of `000000`. Then the current checks will fail and [getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L164-L185) will return an entropy of 0.

That NFT would be useless at it won't be good for anything.

## Tools Used
Manual review

## Recommended Mitigation Steps
Have an `if` that will returns some value if entropy is 0.
