# Vulnerability details

## Impact
When the max entities have been minted for the current generation, the contract will fail to increment to the next generation due to an access control issue. This will cause all subsequent minting attempts to fail, effectively halting the minting process for new generations.
This Leads the owner of `EntropyGenerator` to have to transfer contract ownership to `TraitForgeNft`.

The root cause is that `TraitForgeNft` calls `EntropyGenerator::initializeAlphaIndices` during `_incrementGeneration`, but lacks the necessary permissions to do so as `TraitForgeNft` is set as `allowedCaller` in `EntropyGenerator`, not `owner` causing the `onlyOwner` modifier to revert.
```
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
    // ... [other code] ...

```

## Proof of Concept
Change `_incrementGeneration` to public and comment out the requirement just to make it run:

  function _incrementGeneration() public {

## Recommended Mitigation Steps
1. Add a new modifier that only allows `owner` or `allowedCaller` like so:
```diff
+  modifier onlyOwnerOrAllowedCaller() {
+    require(
+      msg.sender == owner() || msg.sender == allowedCaller,
+      'Caller is not allowed'
+    );
+    _;
+  }
```
2. Change the access control on `initializeAlphaIndices`:
```diff
-  function initializeAlphaIndices() public whenNotPaused onlyOwner {

+  function initializeAlphaIndices() public whenNotPaused onlyOwnerOrAllowedCaller {
```
