# Vulnerability details

## Impact
The nuke function in the smart contract contains critical security flaws related to the validation of the caller and the transfer of funds. Specifically:

Improper Validation of Caller:

The function checks if the caller is either the owner or an approved operator of the token but does not ensure that the caller is the actual owner before transferring funds. This can lead to scenarios where an operator can initiate the nuke process and receive funds, which contradicts the intended logic described in the documentation.
Incorrect Fund Transfer Logic:

According to the documentation, the funds should be transferred to the owner of the entity. However, the current implementation transfers the funds to the msg.sender, which could be an approved operator instead of the owner. This flaw allows operators to exploit the function and claim a significant portion of the fund, potentially up to 50% of the pool, depending on the luck factor.

## Proof of Concept

Security Risk:

An approved operator can initiate the nuke function and receive the claim amount instead of the token owner. This can lead to unauthorized fund transfers and potential exploitation by malicious operators.
Deviation from Documentation:

The actual implementation deviates from the intended behavior as described in the documentation, which states that the funds should be transferred to the entity owner.

//steps
-An operator, who is approved for the token, calls the nuke function.
-The funds are transferred to the operator (msg.sender) instead of the token owner.
-The operator receives a significant portion of the pool, contrary to the intended design.

## Recommended Mitigation Steps
Ensure Caller is the Owner:
Modify the function to ensure that only the token owner can call the nuke function and receive the funds.

Correct Fund Transfer Logic:
Transfer the claim amount to the token owner instead of the msg.sender
