# Vulnerability details

## Impact
There is a whitelist time, in which users are able to mint tokens. It's first set to 24 hours in the constructor, and later the owner can set it again if needed. The problem is it is set incorrectly in the `setWhiteListEndTime` function.

## Proof of Concept
In `TraitForge.sol::setWhiteListEndTime`, `endTime_` is passed and the `whitelistEndTime` is set to be the `endTime_` value. If the owner wants to give 24 hours again to the users, he will pass `endTime_ = 24 hours`.  The problem is the `whitelistEndTime` is set without accounting for the current time (block.timestamp).

```solidity
   function setWhitelistEndTime(uint256 endTime_) external onlyOwner {
        whitelistEndTime = endTime_;
    }
```
## Tools Used
Manual Review

## Recommended Mitigation Steps
Add the endTime_ to the block.timestamp

```diff
   function setWhitelistEndTime(uint256 endTime_) external onlyOwner {
-        whitelistEndTime = endTime_;
+        whitelistEndTime = block.timestamp + endTime_;
    }
```
