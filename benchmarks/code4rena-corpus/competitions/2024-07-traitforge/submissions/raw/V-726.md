# Vulnerability details

## Impact

Seller can control the NFT selling by using the function `buyNFT` when the ETH is transferred to the seller.

## Proof of Concept

NFT can be traded by using the function `listNFTForSale - buyNFT ` Seller can fix the selling price and list it for sale. 

This NFT can not be bought smoothly since it is controlled by the seller in various method.

The issue arise due to the nature of the implementation `listNFTForSale` , `buyNFT` or `cancelListing`.

These functions can be executed in any time. There is no freeze time between the `listNFTForSale` and `cancelListing`.

once the NFT is listed, it can be canceled at any time.

The other point to note, the `buyNFT` function which can be reverted when the seller receive the ETH.

- The issue we observe here is,

 -- Alice list the NFT

 -- After some time Alice notices, the demand for NFT increase, they can immediately call the `cancelListing` to cancel the selling.

- The other issue is,

 -- Alice list the NFT

 -- Alice would be smart contract which would have custom function to revert when it receive the ETH.

 -- Alice would use this block the selling of their NFT when they observe that the NFT price will be increasing.

In above both cases, the buyer would be unfairly affected as they can not buy the NFT as listed.

## Tools Used

Manual review.

## Recommended Mitigation Steps

We would suggest to implement the freeze time between `listNFTForSale` and `cancelListing` functions.
when the seller list their NFT, they have to pass through this freeze duration to cancel.

Regarding forcefully revert, instead of push based fund transfer, implement, pull based fund transfer. so that the seller can call and withdraw the ETH.
