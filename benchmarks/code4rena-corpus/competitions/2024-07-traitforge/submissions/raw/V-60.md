# Vulnerability details

## Impact
There is one invariant `maxTokensPerGen`. Each generation can have maximum `maxTokensPerGen`. But this invariant can be broken.

## Proof of Concept
There're two vulnerabilities that can cause the broken invariant `maxTokensPerGen`. I have already submitted the first vulnerability via 
https://code4rena.com/audits/2024-07-traitforge/submit?issue=I_kwDOMbZW6c6RXn-Y.

The following description is based on we have fixed the first problem, don't reset the `generationMintCounts` in _incrementGeneration().

When whitelist wants to mint NFT and current generation's mint count reaches the cap, we will increase the generation and take the newly NFT belong to the next generation. The problem is that it's possible that the next generation's mint count has already reaches cap. If we add this newly NFT in the next generation, the next generation's mint count will exceed the `maxTokensPerGen`.
Considering the below scenario:
- Alice, Bob and some other whitelist mint NFT tokens in generation 0.
- Alice and Bob try to list lots of forger NFT and forge some new NFT. These generated/forged NFT will belong to generation 1. Considering that some forger NFT has a very high forger potential(9, maximum), it's possible that forged NFT's amount will reach the mint cap `maxTokensPerGen` in generation 1.
- Now Alice wants to mint one NFT in generation 0 and generation 0's mint account reaches mint cap `maxTokensPerGen`. And the newly NFT will be added in generation 1. However, the generation 1's mint amount has already reaches the cap. This will cause the generation 1's mint amount will break the invariant `maxTokensPerGen`.
