# Vulnerability details

## Impact

Minor loss of funds for the protocol (maximum of 9 NFTs not minted by users) and lack of availability.

A maximum of 9 NFTs will not be available to mint by the users, or the protocol will be blocked. When 10,000 are minted, the protocol will not allow minting any more NFTs because only the owner can increment the generation.

A secondary, more theoretical, risk exists:
If the owner of the protocol uses a script to automatically increment the generation, there is a risk of determinism. A malicious attacker can mint some NFTs to acquire the 999999th NFT just after the script executes.

## Proof of Concept

First Risk,

The initializeAlphaIndices is only callable by the owner. As so, the owner need to call _mintNewEntity to unlock the protocol. An NFT will be minted by the owner and not an user.

Second Risk:

The function initializeAlphaIndices uses hashValue, which is based on the block.number and block.timestamp. A malicious attacker could determine the number of blocks required for the script to react, determine the right block.number and block.timestamp to get faster the perfect 999999 entity, and try to get it using the mintWithBudget function.

## Tools Used
Foundry

## Recommended Mitigation Steps

Delete the modifier onlyOwner from the function initializeAlphaIndices() and use a better randomness generator ( chainlink for example).
