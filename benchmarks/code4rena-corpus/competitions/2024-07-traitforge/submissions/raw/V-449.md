# Vulnerability details

## Impact
Based on the `TraitForge` [documentation](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit), it is specified that the maximum number of generations is `10`:

> Gen 1’s produce Gen 2’s, Gen 2’s can produce Gen 3’s etc. The game is capped at 10 Generations for now.

This, however, is not properly enforced, as when minting new NFTs, users can easily go beyond the `10` generation cap.

## Proof of Concept
When users mint new NFTs, the `TraitForgeNft.sol` contract keeps count of how many entities are minted per generation, and when they reach `10_000` a new generation is started:

```solidity
  function _incrementGeneration() private {
    require(
@>      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
@>    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

As per the protocol docs, the maximum generation count is capped at `10`. This is properly enforced when users `forge` their NFTs:

```solidity
function forge(
    address newOwner,
    uint256 parent1Id,
    uint256 parent2Id,
    string memory
  ) external whenNotPaused nonReentrant returns (uint256) {
__SNIP__
    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

    /// Check new generation is not over maxGeneration
@>    require(newGeneration <= maxGeneration, "can't be over max generation");
__SNIP__
  }
```

However, no such check is added when users mint new NFTs, allowing them to go well beyond the `10` generations limit.

For the following tests I have used Foundry following HardHat's foundry [integration](https://hardhat.org/hardhat-runner/docs/advanced/hardhat-and-foundry) guide. The following tests can be run with `forge test --mt testMintingExceedsGenerationCap`.

_NB: All of the below tests use the same set-up shown in the `Set up` details tab. For the next coded PoC, I have properly set the owner of the Airdrop and EntropyGenerator to be the NFT contract so that there are no owner issues, as described in one of my issues._
