# Vulnerability details

## Impact
In ```Airdrop.sol```, ```traitToken``` is the ERC20 token being airdropped. Owner can change this token contract with ```setTraitToken()``` function and set the claimable amount for each user as long as the airdrop has not started.

However, it should not be possible for the ERC20 token to be changed if the airdrop has started, as this would prevent users from claiming their allocated tokens. It makes no sense to let the token be changed after starting the airdrop as no more allocation modifications are allowed.

Take into account that ```claim()``` uses the current ```traitToken```:

```solidity
function claim() external whenNotPaused nonReentrant {
    require(started, 'Not started');
    require(userInfo[msg.sender] > 0, 'Not eligible');

    uint256 amount = (totalTokenAmount * userInfo[msg.sender]) / totalValue;
    traitToken.transfer(msg.sender, amount);
    userInfo[msg.sender] = 0;
  }
```


## Tools Used

Manual review

## Recommended Mitigation Steps
Prevent ```traitToken``` from being changed if airdrop has started.

```solidity
function setTraitToken(address _traitToken) external onlyOwner {
+   require(!started, 'Cannot change token if airdrop has started');
    traitToken = IERC20(_traitToken);
  }
```
