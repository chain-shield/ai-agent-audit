# Vulnerability details

## Impact
Miss slippage protection for `amountMinted` in `mintWithBudget`.

User may get less amount than they expected.

## Proof of Concept
In `mintWithBudget`, only the total payment amount `msg.value` is specified, and the desired mint quantity is not specified.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225
```solidity
  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```

Due to the constantly rising price of mint, the same `msg.value` executed at different times may result in receiving different quantities of NFTs.

For example, at the beginning when it was cheap, 1 ETH could buy 5 NFT, but later as the mint price rose, 1 ETH could only buy 2 NFT. The user cannot know how much the mint price will rise before their transaction is executed. If the user cannot set the expected number to be obtained, he may end up spending the same amount of money to buy fewer NFTs than expected.

## Recommended Mitigation Steps
Add `minAmountMinted` in `mintWithBudget` and check with `amountMinted`.
