# Vulnerability details

`listNFTForSale()` function does not check if the token being listed is already listed for sale. This means that a user can list the same token multiple times, creating multiple listings for the same token.

[listNFTForSale() function](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L38-L60)
```solidity
// EntityTrading.sol:38-60
function listNFTForSale(
    uint256 tokenId,
    uint256 price
) public whenNotPaused nonReentrant {
    require(price > 0, 'Price must be greater than zero');
    require(
        nftContract.ownerOf(tokenId) == msg.sender,
        'Sender must be the NFT owner.'
    );
    require(
        nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
        'Contract must be approved to transfer the NFT.'
    );

    nftContract.transferFrom(msg.sender, address(this), tokenId); // transfer NFT to contract

    // Error: No check if the token is already listed
    ++listingCount;
    listings[listingCount] = Listing(msg.sender, tokenId, price, true);
    listedTokenIds[tokenId] = listingCount;

    emit NFTListed(tokenId, msg.sender, price);
}
```
The function increments the `listingCount`, creates a new `Listing` struct with the provided details, and maps the `tokenId` to the `listingCount` in the `listedTokenIds` mapping. However, it does not check if the `tokenId` is already present in the `listedTokenIds` mapping, indicating that the token is already listed.

If a token is listed multiple times, it will create multiple entries in the listings mapping, each with a different listingCount.

[EntityTrading.sol:16-20](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L16-L20)
```solidity
// EntityTrading.sol:16-20
uint256 public listingCount = 0;
/// @dev tokenid -> listings index
// Error: Inconsistency if a token is listed multiple times
mapping(uint256 => uint256) public listedTokenIds;
/// @dev index -> listing info
mapping(uint256 => Listing) public listings;
```
The `listedTokenIds` mapping can become inconsistent if a token is listed multiple times because it will only store the latest `listingCount` for a given `tokenId`. This can lead to issues when trying to retrieve or manage the listings for a specific token.

Similarly, the `listings` mapping will contain multiple entries for the same token if it is listed multiple times, each with a different `listingCount`. This can cause confusion and inconsistencies when interacting with the listings.

## Impact
Multiple listings can be created for the same token, leading to duplicate entries and confusion when retrieving or managing listings.

If a token has multiple active listings, canceling or managing those listings becomes more complex and error-prone.

Malicious users can intentionally list the same token multiple times to manipulate the market or exploit any vulnerabilities related to multiple listings.

## Proof of Concept
1. User A calls `listNFTForSale()` with `tokenId` 1 and `price` 1 ETH.
2. The token is transferred to the contract, and a new listing is created with `listingCount` 1.
3. User A calls `listNFTForSale()` again with the same tokenId 1 and price 2 ETH.
4. The token is already in the contract, so the transfer succeeds.
5. A new listing is created with `listingCount` 2, and the `listedTokenIds` mapping now points to the new listing.
6. The token now has two active listings with different prices and `listingCount` values.

## Recommended Mitigation Steps
Check in the `listNFTForSale()` function to verify if the token is already listed. This can be done by checking the `listedTokenIds` mapping before creating a new listing.
