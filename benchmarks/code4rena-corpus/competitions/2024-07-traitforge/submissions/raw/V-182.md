# Vulnerability details

## Impact
The use of block.timestamp and block.number for generating pseudo-random values introduces a vulnerability because these values are predictable. Miners or attackers with knowledge of the blockchain's state can influence or predict the values returned by functions using these variables. This predictability undermines the integrity of randomness within the contract, potentially allowing an attacker to predict the outcome of entropy-related operations such as slotIndexSelectionPoint, numberIndexSelectionPoint, and values in entropySlots.

## Proof of Concept
These are directly referenced code sections using block.timestamp and block.number.

    uint256 pseudoRandomValue = uint256(
      keccak256(abi.encodePacked(block.number, i))
    ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index

    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

## Tools Used
Manual code review

## Recommended Mitigation Steps
Integrate a more secure randomness source like Chainlink VRF (Verifiable Random Function) or similar decentralized randomness solutions that are resistant to manipulation.
