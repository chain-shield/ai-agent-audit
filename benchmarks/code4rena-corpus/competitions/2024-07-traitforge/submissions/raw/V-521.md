# Vulnerability details

## Impact
The `TraitForgeNft` contract has a potential vulnerability where the generation limit (`maxGeneration`) is not enforced properly. Specifically, when `_incrementGeneration()` is invoked, it does not check that the new `currentGeneration` after incrementing does not exceed `maxGeneration`.

This inconsistency can lead to the `currentGeneration` being incremented beyond the `maxGeneration` limit.

## Proof of Concept
1. [`mintToken()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L193) and [`mintWithBudget()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L216) Functions:
These functions call [`_mintInternal()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L281-L283), which in turn calls `_incrementGeneration()` if the current generation's mint count exceeds `maxTokensPerGen`.
```solidity
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
>>    _incrementGeneration();
    }
```
However, [`_incrementGeneration()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355) does not check if `currentGeneration` exceeds `maxGeneration`.
```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
>>  currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
This function increments `currentGeneration` without verifying if it has reached the `maxGeneration` limit.

## Scenario
- `maxGeneration` = 10
- `currentGeneration` = 10
- In `mintToken()` and `mintWithBudget()`, when  `maxTokensPerGen` for this `generation 10` is reached, `_incrementGeneration()` will be called setting  `currentGeneration` to `11` but will not check if `maxGeneration` is respected after incrementing this.
- Simply like that, `maxGeneration` limit is exceeded.

2. [`forge()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L163-L166) Function: 
Includes a check to ensure `newGeneration` does not exceed `maxGeneration`.
```solidity
  uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

  /// Check new generation is not over maxGeneration
  require(newGeneration <= maxGeneration, "can't be over max generation");
```
This function then calls [`_mintNewEntity()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L175-L176) which performs this [check](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L331-L335):
```solidity
    if (
      generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration
    ) {
      _incrementGeneration();
    }
```
In other words, if while minting the `newTokenId` the `maxTokensPerGen` for the `newGeneration` is reached and that `newGeneration` happens to be the `currentGeneration`, `_incrementGeneration()` will be invoked to increment the `currentGeneration`. This may also exceed the `maxGeneration`

## Scenario
- `maxGeneration` = 10
- `currentGeneration` = 10
- `Bob` has a `generation 9` token and decides to forge it. The `newGeneration` for the `newTokenId` will `10` which also is the `currentGeneration`.
- While minting this `newTokenId`, the `generationMintCounts[10]` reaches `maxTokensPerGen`.
- Therefore, the check above will be performed. Since both conditions are met, `_incrementGeneration()` wil be invoked setting  `currentGeneration` to `11`.
- Simply like that, `maxGeneration` limit is exceeded.

---> **Unbounded Generation Increment**:
The `currentGeneration` can be incremented beyond the `maxGeneration` limit, leading to potential logical inconsistencies.

## Tools Used
Manual Review

## Recommended Mitigation Steps
`_incrementGeneration()` function should include a check to verify that `currentGeneration` does not exceed `maxGeneration`.
```diff
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
+   // @audit Check new generation is not over maxGeneration
+   require(currentGeneration <= maxGeneration, "can't be over max generation");

    //...snip...
  }
```
