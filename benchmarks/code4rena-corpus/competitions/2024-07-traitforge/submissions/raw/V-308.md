# Vulnerability details

Users are required to pay a forging fee when they want to forge with a listed id.

It is possible for a user to accidentally overpay the forging fee during `forgeWithListed()`.

## Impact
Any funds paid for in excess of the fee will be remain stuck in the contract.

## Proof of Concept

`forgeWithListed()` allows `msg.value` to be greater than  `forgingFee`
```solidity
File: EntityForging.sol

102:    function forgeWithListed(
        ...
125:      uint256 forgingFee = _forgerListingInfo.fee;
126:      require(msg.value >= forgingFee, 'Insufficient fee for forging');
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider modifying the check such that the `msg.value` is exactly equal to the required `forgingFee`.
```solidity
File: EntityForging.sol

  102:    function forgeWithListed(
        ...
  125:      uint256 forgingFee = _forgerListingInfo.fee;
- 126:      require(msg.value >= forgingFee, 'Insufficient fee for forging');
+ 126:      require(msg.value == forgingFee, 'Insufficient fee for forging');
```
