# Vulnerability details

## Impact

In the `TraitForgeNft` contract, when a user mints a token using the `mintToken` function, the mint price is calculated for the current generation before checking and incrementing the generation if necessary. If the last token of a generation is minted, the generation is incremented after the price calculation, causing the user to pay the higher price of the last token of the previous generation for the first token of the new generation. This results in users overpaying for tokens, especially significant in the transition to the last generation.

## Proof of Concept

### Minting the last token of generation 9:
    - User calculates the price based on the last token of generation 9.
    - Generation is incremented to 10 after price calculation.
    - User ends up paying the higher price intended for the last token of generation 9 for the first token of generation 10.

### Example:
    - Last token price in generation 9: 0.7 ETH
    - First token price in generation 10: 0.005 ETH
    - User overpays by 0.695 ETH.

## Recommended Mitigation Steps

The mint price should be calculated after checking and incrementing the generation if necessary, ensuring the correct price for the token being minted.

### Suggested Fix

Adjust the `mintToken` function to check and increment the generation before calculating the mint price:

```solidity
File: contracts/TraitForgeNft/TraitForgeNft.sol

181:   function mintToken(
182:     bytes32[] calldata proof
183:   )
184:     public
185:     payable
186:     whenNotPaused
187:     nonReentrant
188:     onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
189:   {
190:     // Check and increment generation first
191:     if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
192:       _incrementGeneration();
193:     }
194:
195:     uint256 mintPrice = calculateMintPrice(); // Calculate price for current generation
196:     require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');
197: 
198:     _mintInternal(msg.sender, mintPrice); // Mint token
199: 
200:     uint256 excessPayment = msg.value - mintPrice;
201:     if (excessPayment > 0) {
202:       (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
203:       require(refundSuccess, 'Refund of excess payment failed.');
204:     }
205:   }
```

This ensures that the mint price is always calculated for the correct generation, preventing users from overpaying when minting tokens.
