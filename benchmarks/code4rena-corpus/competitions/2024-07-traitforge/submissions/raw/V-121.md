# Vulnerability details

## Impact
A forger with a `forgePotential` of `x` should be able to forge only `x` times within a year. The required condition to list a forger in `EntityForging::listForForging` is incorrect and allows a forger to list for forging even if they have already forged x times:

```javascript
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );
```

## Proof of Concept

`forgingCounts[tokenId]` starts at 0 and increments when the forging is completed. If the `forgingCounts[tokenId]` reaches `forgePotential`, it shouldn't be able to forge anymore. However this incorrect check allows it to be listed one more time to forge.


## Tools Used
Manual Review

## Recommended Mitigation Steps

Change `<=` to a strict `<`:
```diff
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
-     forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
+     forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
      'Entity has reached its forging limit'
    );
```
