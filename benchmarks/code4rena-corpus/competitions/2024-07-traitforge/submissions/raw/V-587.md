# Vulnerability details


## summary
During forging, a token is minted and upgraded to next generation after the current parent (`forgeId`) generation. 

If the genaration of the parent is the current generation, the token will be minted to the next generation in the future. 

A problem arises when the max number of tokens (`maxTokensPerGen`) for the current generation reaches the maximum and `_incrementGeneration()` is called which resets the `generationMintCounts` of the next generation( the new current generation) back to zero hence all the tokens/entities minted before during forging for this new generation won't be counted.

## Vulnerability Details
In `EntityForging.sol` the function `TraitForgeNft::forge` is called to mint a new entity in the next generation of the parent (`forgeTokenId`).

```Solidity
    uint256 newTokenId = nftContract.forge(
      msg.sender,
      forgerTokenId,
      mergerTokenId,
      ''
    );
```
- https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L150

The count for entities in the next generation are incremented in `TraitForgeNft::forge` to keep count of how many token they are and checked if it does not go beyond the maximum amount of `generationMintCountsPerGen`.

```Solidity

    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

    /// Check new generation is not over maxGeneration
    require(newGeneration <= maxGeneration, "can't be over max generation");
```
- https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L163


In `TraitForgeNft::_mintNewEntity` :

```Solidity
if (
      generationMintCounts[gen] >= maxTokensPerGen
    ) {
      _incrementGeneration();
    }
```
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L331

But consider a scenario where we are on the first generation and we want to forge new entities, our entities will be of the second generation. A problem arises when the first generation is full. 

We have been minting entities to the second generation and now since the first generation(current generation)is full we have to go to the next generation.

 During minting of new tokens, the check in `TraitForgeNft::mintInternal` will call `TraitForgeNft::_incrementGeneration()`.


A problem arises in `TraitForgeNft::_incrementGeneration()` which resets the `generationMintCounts` for the second genaration to zero making making all entinties minted during forging non accounted for.

```Solidity
function _incrementGeneration() private {
    ...code..
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    ...code..
}
```

- https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L351

## Impact
The contract will loose count of the real number of entities in the game and it goes against the core logic of the contract.

## Tools Used
Manual Review

## Recommended Mitigation
Instead of setting `generationMintCounts` to zero consider setting it to it's current count in the contract.

```diff
function _incrementGeneration() private {
    ...code..
    currentGeneration++;
--> //remove the  line below.  generationMintCounts[currentGeneration] = 0;
    ...code..
}
```
