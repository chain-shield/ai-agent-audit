# Vulnerability details

## Impact

The "nuke" function of the NukeFund contract is vulnerable to re-entrancy attacks. 
Whilst there is nonReentrant modifier in place, it is possible to perform potential re-entrancy attacks due to external calls, specifically the call which sends Ether to the msg.sender.

A re-entrancy attack can occur when a contract calls external contracts and makes state changes after the external call. If the called contract is malicious and implements a fallback function, it can re-enter the caller contract before the state changes have been committed, leading to potential exploits. 

In this function, an amount of fund is deducted and a token is burnt after making an external call to transfer Ether. If the payable external address is a contract that has a fallback function, it could re-enter the "nuke" function and repeatedly claim funds, before the state changes (i.e., token burn and fund deduction) of the initial call are actually committed to the blockchain.

## Proof of Concept

In the "nuke" function, the following code snippet is especially vulnerable:

```solidity
(bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
require(success, 'Failed to send Ether');
fund -= claimAmount; // Deduct the claim amount from the fund
nftContract.burn(tokenId); // Burn the token
```

A malicious contract with the payable fallback function can re-enter the "nuke" function in the line where Ether is being transferred to `msg.sender`.


## Tools Used

## Recommended Mitigation Steps

To mitigate this, you should follow the Checks-Effects-Interactions pattern which recommends performing any external calls as the very last operation in your function. Additionally, you can use the OpenZeppelin library's `SafeMath` module for state-changing operations to mitigate re-entrancy vulnerabilities. The `nonReentrant` modifier from OpenZeppelin's `ReentrancyGuard` can also be used to prevent recursive calls. 

So, moving state changes before external interaction would look like:

```solidity
fund -= claimAmount;
nftContract.burn(tokenId);
(bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
require(success, 'Failed to send Ether');
```

Note that even though the contract already employs a `nonReentrant` modifier, it wouldn't be effective in its current placement. It is best practice to place the `nonReentrant` modifier where re-entrance could happen, in this case, it should be placed at the function with the external payable call.
