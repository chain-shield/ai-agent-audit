# Vulnerability details

## Impact
EntityForging - forgeWithListed : excess ETH neither utilized not refunded.
over a period of time, the accumulated ETH will be locked inside the contract.

## Proof of Concept

`forgeWithListed` function does the following.

- Retrieve forger listing information.
- Check if forger's entity is listed for forging.
- Verify that the caller owns the merger token.
- Verify that the caller does not own the forger token.
- Ensure both tokens are of the same generation.
- Validate sufficient fee for forging.
- Reset forging counts for forger and merger tokens if needed.
- Increment forger's forging count.
- Validate and increment merger's forging count and forge potential.
- Calculate and distribute the developer fee and forger owner's share.
- Forge a new token with the given forger and merger tokens.
- Send developer fee to the specified address.
- Send forger's share to the forger owner.
- Cancel the forger token's listing for forging.
- Emit the EntityForged event with relevant details.
- Return the new token ID.

when checking the msg.value, below check is seen.

So, if the msg.value is > forgeFee, some portion of ETH will be left inside the contract itself. This neither refunded not recovered.

- Refund the excess ETH to the caller.
- Use the total msg.value for fee and dev share calculation.
