# Vulnerability details

## Impact
- In `mintWithBudget` function, there is a while statement in which it checks that `_tokenIds` must less than `maxTokensPerGen` to mint token in while loop logic.
- `maxTokensPerGen` is 10000 but `_tokenIds` can be more than 10000 because when 1st generation's 10000 NFTs minted then in 2nd and further generation variable `_tokenIds` will always increment. 
- And even in forge NFT `_tokenIds` will increment so that means after 1st generation this check will always fail and not NFT will be minted by using `mintWithBudget` function.
- it means that after 10000 NFTs minted there will be DoS in `mintWithBudget` function.

## Recommended Mitigation Steps
- Instead of `_tokenIds` variable, there must be `generationMintCounts[currentGeneration]` used.
- So generationMintCount for currentGeneration cannot excced 10000 that means in `mintWithBudget` function while loop check will work properly and NFTs will be minted as intended.
