# Vulnerability details

## Impact

The `EntityForging.forgeWithListed` function is called by the `merger` to `forge` a new NFT entity by providing `msg.value >= forgingFee`. The `forgingFee` is then shared between the `forgerOwner` and the `NukeFund`.

But the issue here is since the `EntityForging.forgeWithListed` functions allows the `merger` to supply more funds to the `EntityForging.forgeWithListed` function, more than the `forgingFee` (since msg.value >= forgingFee state is allowed) the excessive `msg.value` (msg.value - forgingFee) is not refunded to the `merger (msg.sender)`. There is no logic implemented in the `EntityForging.forgeWithListed` function to refund the `excessive msg.value` to the `merger (msg.sender)`.

Hence this is loss of funds to the `merger (msg.sender)`.

## Recommended Mitigation Steps

Hence it is recommended implement logic in the `EntityForging.forgeWithListed` function to enable the refunding of the `excessive msg.value` to the `merger (msg.sender)` in the event `merger (msg.sender)` supplies more funds (msg.value > forgingFee) to the `EntityForging.forgeWithListed` function than the `forgingFee`. 

Or else it is recommended only allow the `merger (msg.sender)` to supply the `forgingFee` to the `EntityForging.forgeWithListed` function by changing the `msg.value >= forgingFee` conditional check to `msg.value == forgingFee` in the `require` statement in the `EntityForging.forgeWithListed` function.
