# Vulnerability details

## Impact 
The `to` address in the contract can be either a smart contract or an Externally Owned Account (EOA).

Assume `to` is an EOA. When a low-level call is performed against an EOA, the call will always succeed because EOAs do not have any associated code. The call will simply return without executing any contract code. In this scenario, the `success` variable will be set to `true`, indicating that the call itself was successful.

This can lead to a false conclusion that the `to` address (an EOA) supports the interface and implements the necessary function.

## Recommended Mitigation Steps
To address this issue, consider checking if the `to` address is an EOA or a smart contract. The function can exit immediately if the `to` address is not a smart contract.
