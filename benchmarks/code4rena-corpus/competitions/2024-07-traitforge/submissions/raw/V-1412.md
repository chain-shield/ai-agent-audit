# Vulnerability details

## Impact
The protocol is inteanded to mint 10k Nfts per generation and users can `forge` their current Generation Nfts to get the next Generation Nfts. If users forge their Nfts of Gen1 10k times they will get 10K Nfts of Gen2 then the Generation count will increase and user will never be able to mint the remaining Nfts of Generation 1.

## Proof of Concept
lets assume `currentGeneration` is 1 and users have minted a total of 5K NFTs of Gen1

When the users forge its NFTs using `EntityForging::forgeWithListed` function, the function will call `TraitForgeNft::forge` function, which will call `TraitForgeNft::_mintNewEntity` function.

In `TraitForgeNft::_mintNewEntity` we are calling `_incrementGeneration` function if `generationMintCounts[gen] >= maxTokensPerGen` ie if the number of tokens in the next generation(2) reaches the max limit then it will increase the generation.

```javascript
    function _mintNewEntity(address newOwner, uint256 entropy, uint256 gen) private returns (uint256) {
        .
        .
        .
        // NOTE: if condition below has another bug which prevents it from incrementing the generation correctly, to understand this bug we need to assume that the if condition works properly and is doing what it was intended to do.
        if (generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration) {
@>          _incrementGeneration();
        }
        .
        .
        .
    }
```

Now let's assume Gen1 Nfts has forged 10k times to get 10k Gen2 Nfts.
Inside `_incrementGeneration` function we are increasing the `currentGeneration`, means the `currentGeneration` becomes 2. So when the user tries to mint the Nfts they won't be able to mint from Gen1 because `currentGeneration` is 2. When they call `mintToken` function to mint they will get the token of Gen3 as there are already 10k tokens of Gen2(from forging). So the `currentGeneration` becomes 3.

Gen1 -> 5k
Gen2 -> 10K
Gen3 -> currentGeneration

we can see that there is not way to mint the remaining NFTs of Gen1.

```javascript
    function _incrementGeneration() private {
        require(generationMintCounts[currentGeneration] >= maxTokensPerGen, "Generation limit not yet reached");
@>      currentGeneration++;
        .
        .
        .
    }
```

## Recommended Mitigation Steps

1. I think the codebase need to change the design of the `_incrementGeneration` function. And need to check for multiple conditions whether the it is begin called by `forgeWithListed` function or by any other functions like `mintToken` or `mintWithBudget`.

2. Protocol need to add another map to actually track the number of tokens minted in each generation. If the previous generation is not minted completely then the protocol should not increment the generation.
