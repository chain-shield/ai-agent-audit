# Vulnerability details

## Impact
Users can avoid paying high minting fees by consciously minting forger/merger role tokenids(users can observe advance a token’s forger/merger role before minting from the  contract EntropyGenerator and mint forger/merger role tokenids) and forge tokenids(mint token in new generation) by paying less fee i.e 0.01 ether which is less than minting fees(from gen2 to gen10).


## Proof of Concept
1. As per docs, every generation’s/every token’s mint price will increase than previous token/generation minting price.Gen1 mint price start from 0.25 eth, Gen2 mint price start from 0.30 eth, Gen3 mint price start from 0.35 eth, Gen4 mint price start from 0.4 eth. Anyone can observe advance a token’s forger/merger role before minting from the  contract EntropyGenerator( function deriveTokenParameters, function getEntropy).  

2. Let’s assume, currently currentgeneration = 2, generation 2’s mint price starts from 0.25 eth. alice(a user) mints generation 2’s 5 forger role tokenids in account1 and 5 merger role tokenids in account2 by advance knowing tokenid’s merger and forger role from   contract EntropyGenerator.

3. Now alice calls function listForForging with a forger tokenid and minimumListFee = 0.01 ether from account1 and list the tokenid.

4. Now Alice calls the function forgeWithListed with the listed forger tokenid and a merger tokenid(minted through account2). The new tokenid is minted in generation 3 with fee 0.01 ether. If Alice mints tokenid in generation 3 by calling the  function mintToken,she has to pay above 0.30 ether.

5. But Alice can avoid paying high minting fee by consciously minting forger/merger role tokenids and forge tokenids(mint token in new generation) by paying less fee i.e 0.01 ether as fees.

manual review
## Recommended Mitigation Steps
Implement a mechanism so that anyone can’t know a tokenid’s forger/merger role and entropy advance before minting.
