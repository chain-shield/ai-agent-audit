# Vulnerability details

## Impact
1. Owner of the Nft cannot approve the contract to transfer nft because there is no function to facilitate that.
2. There is no line of code that revokes the approval after nft has been transferred

## Proof of Concept
When a user is listing his nft for sale there is no line of code that approves the contract going to initiate the transfer neither is there a function in the [contract](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L11) that the owner of the nft can call to approve an address, the only thing will find is a [check](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L65-L68) to find out whether caller is approved or not.

Again, In an assumption that an Nft has been sold, it can be observed that in the [listNFTForSale()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L38) and [buyNFT()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L63) there's no line of code that revokes the previous approval on the Nft that is sold.

## Tools Used
Manual review

## Recommended Mitigation Steps
implement logics that help caller approve contracts and also add some implementation to revoke the approval after the nft has been transferred.
