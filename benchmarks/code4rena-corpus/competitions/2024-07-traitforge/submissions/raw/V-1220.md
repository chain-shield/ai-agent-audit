# Vulnerability details

## Impact
The Age of an Entity is crucial when dealing with nuking, it basically determines how matured the entity is, which in turn increases their nukeFactor, which makes them entitled to more of the nukeFund, but a rounding error will occur when calculating the age which will cause a reduction of the amount they can claim from the nuke fund, which in turn will cause loss of funds for the user

## Proof of Concept
```solidity
// Calculate the age of a token based on its creation timestamp and current time
  function calculateAge(uint256 tokenId) public view returns (uint256) {
    require(nftContract.ownerOf(tokenId) != address(0), 'Token does not exist');

    uint256 daysOld = (block.timestamp -
      nftContract.getTokenCreationTimestamp(tokenId)) /
      60 /
      60 /
      24;
    uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;
    uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals
    return age;
  }
```
This function calulates the age of the entity, by calculating how many days since the entity has been created, then it calculates the age using the `perfomanceFactor`, which determines how fast a entity ages, a higher performanceFactor indicates a fast maturing entity. 

But the main issue is when calculating the daysOld variable, the daysOld can result in a operation that rounds the value down and does not truly reflect how long the entity has been around for
 Lets Explore an example to truly show the impact of this and the difference in the output age 


Wrong Calculations caused by rounding

block.timestamp - nftContract.getTokenCreationTimestamp(tokenId) = 5 days, 23 hours, 59 minutes, and 40 seconds
518380 seconds / 60 = 8639.6667 minutes
8639.6667 minutes / 60 = 143.99445 hours
143.99445 hours / 24 = 5.99977 days, but daysOld = 5 days 

let ageMultiplier = 1000
performanceFactor = 9
age = 5 * 9 * 100000 * 1000 /365 = 12328767
correct age = 5.99977 * 9 * 100000 * 1000 /365 = 14793953

Their is Huge difference between the correct calculations and the rounded down version, this difference will greatly impact the nukeFactor being calculated below as it utilizes the adjustedAge for its calculations

```solidity
function calculateNukeFactor(uint256 tokenId) public view returns (uint256) {
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );

    uint256 entropy = nftContract.getTokenEntropy(tokenId);
    uint256 adjustedAge = calculateAge(tokenId);

    uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits

    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;

    return finalNukeFactor;
  }
```
This will result in lower `nukeFactor` than it should leading to less funds claim from the nuke funds
