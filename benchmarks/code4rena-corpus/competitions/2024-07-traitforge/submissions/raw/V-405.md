# Vulnerability details

## Impact
The `forgeWithListed` function attempts to send the `forgerShare` to the owner of the forger token. If the owner is a contract that does not implement the `receive()` or `fallback()` function to handle ETH transfers, the transaction will fail. This failure can cause the `forgeWithListed` function to revert, thereby blocking the forging process. As a result, attackers could exploit this by listing forger entities without them being forged.

## Proof of Concept
This is a contract that does not have a receive() or fallback() function.

    contract UserContract {
      ITraitForgeNft public nft;
      IEntityForging public entityForging;

      constructor(address _nft, address _entityForging) {

        require(success, "list for forging failed");
      }
    }

## Recommended Mitigation Steps
Using `transfer` or `send` for ETH Transfers can solve the issue. Replace call with `transfer` or `send` where appropriate to avoid the potential pitfalls of low-level calls.
