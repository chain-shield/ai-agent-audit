# Vulnerability details

## Impact
`_incrementGeneration()` function can increment the `currentGeneration` beyond the `maxGeneration` limit. Specifically, it contradicts checks in other parts of the contract (e.g., the `forge()` function) that assume `currentGeneration` never exceeds `maxGeneration`. This could allow minting of tokens in non-existent generations.

## Proof of Concept
Look at the `_incrementGeneration()` function: https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355

```solidity
345:   function _incrementGeneration() private {
346:     require(
347:       generationMintCounts[currentGeneration] >= maxTokensPerGen,
348:       'Generation limit not yet reached'
349:     );
350:     currentGeneration++;
351:     generationMintCounts[currentGeneration] = 0;
352:     priceIncrement = priceIncrement + priceIncrementByGen;
353:     entropyGenerator.initializeAlphaIndices();
354:     emit GenerationIncremented(currentGeneration);

```

This function increments `currentGeneration` without checking if it has reached `maxGeneration`. In contrast, other parts of the contract, such as the [`forge()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L153-L179) function, assume that `currentGeneration` never exceeds `maxGeneration`:

```solidity
153:   function forge(
154:     address newOwner,
155:     uint256 parent1Id,
156:     uint256 parent2Id,
157:     string memory
158:   ) external whenNotPaused nonReentrant returns (uint256) {
159:     require(
160:       msg.sender == address(entityForgingContract),
161:       'unauthorized caller'
162:     );
163:     uint256 newGeneration = getTokenGeneration(parent1Id) + 1;    ❌ 
164: 
165:     /// Check new generation is not over maxGeneration
166:     require(newGeneration <= maxGeneration, "can't be over max generation"); ❌ 
167: 
168:     // Calculate the new entity's entropy
169:     (uint256 forgerEntropy, uint256 mergerEntropy) = getEntropiesForTokens(
170:       parent1Id,
171:       parent2Id
172:     );
173:     uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;
174: 
175:     // Mint the new entity
176:     uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);
177: 
178:     return newTokenId;
179:   }
```

This could can lead to a state where `currentGeneration > maxGeneration`, violating the contract's intended behavior.

## Recommended Mitigation Steps
Add a check in the `_incrementGeneration()` function to ensure that `currentGeneration` does not exceed `maxGeneration`. 

```diff
function _incrementGeneration() private {
    require(
        generationMintCounts[currentGeneration] >= maxTokensPerGen,
        'Generation limit not yet reached'
    );
+   require(
+       currentGeneration < maxGeneration,
+       'Max generation reached'
+   );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
}
```
