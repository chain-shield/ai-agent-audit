# Vulnerability details

[H-2] TITLE `TraitForgeNft::_mintNewEntity:: _incrementGeneration(); will never run doing forging,

### Vulnerability Details
In the forge function, a new generation is calculated and passed to the _mintNewEntity function, The _mintNewEntity function contains the following critical section:
```javascript
function _mintNewEntity(address newOwner, uint256 entropy, uint256 gen) private returns (uint256) {
    // ... [other code]
@>    if (generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration) {
        _incrementGeneration();
    }
    // ... [other code]
}
```
which will cause the validation to always be false due to the fact that gen will never be equal to  currentGeneration because of the incrementation that happened inside the forge function.

### Proof of Concept
Assume currentGeneration is 1.
A forge operation is initiated with parent1Id from generation 1.
newGeneration is calculated as 2 (1 + 1).
_mintNewEntity is called with gen = 2.
The check gen == currentGeneration fails (2 != 1).
_incrementGeneration() is never called, leaving currentGeneration at 1.

### Impact
generation will never be incremented while forging , meaning that when genCounts is equal to maxGenCount  the generation won't still be able to move to the next generation because the _incrementGeneration() function will never run
