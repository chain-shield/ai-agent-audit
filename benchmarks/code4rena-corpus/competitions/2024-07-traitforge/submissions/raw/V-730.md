# Vulnerability details

## Impact

The contract `EntropyGenerator` calculates entropies for the tokens and write them in the batches. There is a separate function - `initializeAlphaIndices` that allows to write the special entropy for every generation with parameters `999999`. However, the function currently has `onlyOwner` modifier which is not correct as the caller should be `TraitForgeNft` contract when the generation is incremented.

## Proof of Concept

Take a look at `initializeAlphaIndices()`:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206
```
 function initializeAlphaIndices() public whenNotPaused onlyOwner
```

It currently has `onlyOwner` modifier. The contract has the following modifier as well that checks whether the caller is `TraitForgeNft` contract:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L25-28
```
  modifier onlyAllowedCaller() {
    require(msg.sender == allowedCaller, 'Caller is not allowed');
    _;
  }
```

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L30-33
```
constructor(address _traitForgetNft) {
    allowedCaller = _traitForgetNft;
    initializeAlphaIndices();
  }
```

The function is called when incrementing generation in `TraitForgeNft`:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L353
```
 entropyGenerator.initializeAlphaIndices();
```

This would lead to tx revert as the caller is not the one that's expected.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Use `onlyAllowedCaller()` modifier instead of `onlyOwner()`.
