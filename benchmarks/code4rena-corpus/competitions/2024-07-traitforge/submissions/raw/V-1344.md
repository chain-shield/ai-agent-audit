# Vulnerability details

## Impact
A zero value in `performanceFactor` will result in the age calculation being zero affecting all subsequent calculations that depend on the token's age such as `calculateNukeFactor` and `nuke` function's claim Amount.

## Proof of Concept
The `calculateAge` function calculates the age of a token using its creation timestamp and current time. The `performanceFactor` is derived using a modulus operation `(nftContract.getTokenEntropy(tokenId) % 10)`, which can result in `zero`. This zero value leads to the age being calculated as zero regardless of the actual age of the token. This issue impacts other functions such as `calculateNukeFactor` where a zero age will result in the nuke factor being solely based on the initialNukeFactor, ignoring any time-based increase. In the nuke function a  very low nuke factor could lead to an extremely low claim amounts

Consindering how critical the Age and Nuke factors are to the system the bug could potentially disadvantage users whose token IDs are a multiple of 10 as time-based increase aspect will be completely ignored.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Ensure performanceFactor is within a valid range (e.g., 1-9) or handle the zero case explicitly.
