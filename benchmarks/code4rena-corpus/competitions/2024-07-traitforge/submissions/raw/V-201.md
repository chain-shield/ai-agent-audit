# Vulnerability details

## Impact
Users have no choice but to pay more to mint the first NFT of the next generation.

## Proof of Concept
In `mintToken`, the price is calculated first, then `_mintInternal` is called.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L190-L193
```solidity
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);
```

`calculateMintPrice` calculates directly based on the current `generationMintCounts`, and does not judge whether the upcoming mint is for the next generation.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L227-L232
```solidity
  function calculateMintPrice() public view returns (uint256) {
    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```

The `_mintInternal` function first checks if the current generation has reached its maximum quantity, and if so, it initiates the next generation.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-L283
```solidity
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

Therefore, the vulnerability here lies in the fact that `calculateMintPrice` calculates the price of the last one +1 in the previous generation , while `mintInternal` actually mints the first one of the next generation. The first price of each generation is the same, and the last price of the previous generation is much higher than the first price of the next generation, so users have to pay more to mint the first one of the next generation.

For example:

1. Suppose `maxTokensPerGen` is 10
2. Alice, as the 11th mint, should normally mint the first one of the next generation at `startPrice`.
3. However, `calculateMintPrice` is executed before minting and increasing generation, and the returned price is `startPrice + 10*priceIncrement`, which is much higher than `startPrice`.

vscode
## Recommended Mitigation Steps
If `currentGenMintCount` is greater than or equal to `maxTokensPerGen`, return `startPrice` in `calculateMintPrice`.
