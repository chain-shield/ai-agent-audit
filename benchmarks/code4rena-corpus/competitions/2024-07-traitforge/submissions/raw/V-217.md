# Vulnerability details

## Impact
Users would be able to control at which slot the god NFT will land. This can enable them to delete or replace other entropy values.

## Proof of Concept
[initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206) is used to set `numberIndexSelectionPoint` and `slotIndexSelectionPoint`, where if both values match a god entropy will be returned, minting a god NFT. However it's method of randomness will not generate a random hash, but a fully predictable and even controllable one.

```solidity
   uint256 hashValue = uint256(keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp)));
```

[initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206) is triggered inside [_incrementGeneration](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L282) when we move to the next generation. Meaning that users can control when to move to other generations and when not to.

Example:
1. NFT with id 9999 is minted, the next one will move the gen up
2. Alice calculates that the god NFT will land on ID 9500
3. She waits another block and calculates again that it will land on ID 6656 and it will replace an entropy of 000_000
4. She mints one NFT, moving the gen and setting the god NFT to the ID she wants.

Enabling users to control when the most powerful NFT can be minted would not be a good idea as it enable them to configure it the way that they want.
