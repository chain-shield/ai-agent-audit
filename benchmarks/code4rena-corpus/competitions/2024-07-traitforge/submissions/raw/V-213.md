# Vulnerability details

## Impact
TraitForgeNft contract would not be able to set `traitToken` for the airdrop.

## Proof of Concept
TraitForgeNft is the owner of Airdrop, as seen by [startAirdrop](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L96-L98) function call, where TraitForgeNft is the only one that can start the airdrop.

```solidity
    function startAirdrop(uint256 amount) external whenNotPaused onlyOwner {
        airdropContract.startAirdrop(amount);
    }
```

However the same is not true for [setTraitToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/Airdrop/Airdrop.sol#L20-L22) as TraitForgeNft lacks a function to set the token and since TraitForgeNft is the owner and [setTraitToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/Airdrop/Airdrop.sol#L20-L22) has `onlyOwner` modifier the token will never be set.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add another function to call [setTraitToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/Airdrop/Airdrop.sol#L20-L22).

```diff
    function startAirdrop(uint256 amount) external whenNotPaused onlyOwner {
        airdropContract.startAirdrop(amount);
    }

+   function setTraitToken(address token) external whenNotPaused onlyOwner {
+        airdropContract.setTraitToken(token);
+   }
```
