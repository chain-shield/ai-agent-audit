# Vulnerability details

## Impact
When mintWithbudget is called, following while loop is called.

```js
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
}
```
The whileloop run till the budgetLeft is greater than "mintPrice" and "_tokenIds < maxTokensPerGen" , maxTokensPerGen is defined as 10000 and is unchangable. _tokenIds will increment upon each mint. When the Generation 1 end the _tokenIds will become > 10001 , in that case the mintWithbudget() will never work.

## Proof of Concept
1. Users mint all of the tokens of the first generation. Each minting will increase _tokenId variable in the contract. 
2. When its time for next generation the _tokenId will start from 10,001 effectively bypassing the check and returning the funds back to the user, making the functionality ineffective.

## Recommended Mitigation Steps
It is recommended to adjust the while loop condition to the following.
```js
while (budgetLeft >= mintPrice && generationTokenCount[currentGeneration] < maxTokensPerGen) {
   // Code skipiped
}
```
