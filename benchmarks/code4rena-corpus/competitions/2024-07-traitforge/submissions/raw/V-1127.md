# Vulnerability details

**Description:** 
The `EntityForging::forgeWithListed()` function can be only called by merger. Due to the checks in the function. This open up the attack vector where Forger can gas grief the Merger because later in the function it is making external call to Forger address.

Here this code of line is sending forger share to forger address and caller of this function is merger.
```solidity
(bool success_forge, ) = forgerOwner.call{ value: forgerShare }('');
```

1. As you can see above Forger can't be caller of this function only merger can call this.
2. And later it is making external call to forger address to send it's share. 
3. Now (bool success, ) is actually the same as writing (bool success, bytes memory data) which basically means that even though the data is omitted it doesn’t mean that the contract does not handle it. Actually, the way it works is the bytes data that was returned from the forger will be copied to memory.
4. Memory allocation becomes very costly if the payload is big, so this means that if a forger implements a fallback function that returns a huge payload, then the msg.sender of the transaction, in our case the merger, will have to pay a huge amount of gas for copying this payload to memory.

**Impact:**
Malicious actor can launch a gas griefing attack on a merger.

**Recommended Mitigation:** 
Use a low-level assembly call since it does not automatically copy return data to memory.
```solidity
bool success_forge;
assembly {
    success_forge := call(forgerOwner, forgerShare, 0, 0, 0, 0)
}
```
