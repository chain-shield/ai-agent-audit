# Vulnerability details

## Impact
After the airdrop the DAO won't receive any profits from Nuking of NFTs and it's code won't function.

## Proof of Concept
It's stated in the [docs](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit#heading=h.g7dgt2kibh7m) that after the airdrop the system converts to DAO owned.

> When the AirDrop (explained below) is called, the game converts from Dev-controlled to DAO-controlled.

However there is a flaw in [NukeFund](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L50-L53) that will prevent the DAO from generating any revenue after the airdrop is started. That is because after it's start the first if will always trigger, sending the funds to the developers.

```solidity
        if (!airdropContract.airdropStarted()) {
            (bool success,) = devAddress.call{value: devShare}("");
            require(success, "ETH send failed");
            emit DevShareDistributed(devShare);

        } else if (!airdropContract.daoFundAllowed()) {
            (bool success,) = payable(owner()).call{value: devShare}("");
            require(success, "ETH send failed");

        } else {
            (bool success,) = daoAddress.call{value: devShare}("");
            require(success, "ETH send failed");
            emit DevShareDistributed(devShare);
        }
```

This might be wanted as the developers should still receive proceeds, however if the DAO doesn't receive any of that then it's code ([which relies on ETH being sent](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/DAOFund/DAOFund.sol#L16)) will not work and there won't be any transition.

## Tools Used
Manual review

## Recommended Mitigation Steps
Split the fees between the DAO and devs, or use a variable to periodically change who is getting the fees.
