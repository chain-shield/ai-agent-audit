# Vulnerability details

## Impact
In the `forgeWithListed()` function of EntityForging.sol, users can potentially pay more than required - `require(msg.value >= forgingFee, 'Insufficient fee for forging')` . However, the function does not handle this overpayment scenario and the excess amount is not returned to the user. This could lead to loss of funds for the user.

## Proof of Concept
In the current implementation, there is no mechanism to refund the excess payment made by the user. Here's an example of the potential issue:

Assume the forging fee (forgingFee) is set to 1 ether.
A user calls the forgeWithListed() function and sends 1.5 ether.
The excess payment of 0.5 ether is not refunded, leading to a loss for the user.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Modify the `forgeWithListed()` function to return any excess payment to the user.
```
uint256 excessPayment = msg.value - forgingFee;
if (excessPayment > 0) {
  (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
  require(refundSuccess, 'Refund of excess payment failed.');
}
```
