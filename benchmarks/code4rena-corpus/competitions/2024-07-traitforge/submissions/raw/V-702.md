# Vulnerability details

## Impact

All the contracts under review inherit the `Pausable` contract from OpenZeppelin, which provides a mechanism to temporarily halt certain functions during critical periods (e.g., in case of a bug or security issue). The `Pausable` contract includes the `whenNotPaused` modifier, which ensures that functions can only be executed when the contract is not paused.

However, in the contracts under consideration, the `whenNotPaused` modifier is used, but the contracts lack the necessary public functions to actually trigger the pause and unpause states. Without these public functions, the contracts can't be paused or unpaused by an administrator, rendering the `whenNotPaused` modifier effectively useless. This creates a false sense of security because it suggests that the contract has the ability to be paused in emergencies when, in reality, it does not.

The key risk here is that if an issue arises that requires the contract to be paused (e.g., to prevent further damage from a discovered vulnerability), the absence of public pause/unpause functions means the contract cannot be paused, leaving the system vulnerable to ongoing exploitation.

## Proof of Concept

Here is the used `Pausable` contract by the protocol:

```solidity
abstract contract Pausable is Context {
    event Paused(address account);
    event Unpaused(address account);

    bool private _paused;

    constructor() {
        _paused = false;
    }

    modifier whenNotPaused() {
        _requireNotPaused();
        _;
    }

    modifier whenPaused() {
        _requirePaused();
        _;
    }

    function paused() public view virtual returns (bool) {
        return _paused;
    }

    function _requireNotPaused() internal view virtual {
        require(!paused(), "Pausable: paused");
    }

    function _requirePaused() internal view virtual {
        require(paused(), "Pausable: not paused");
    }

    function _pause() internal virtual whenNotPaused {
        _paused = true;
        emit Paused(_msgSender());
    }

    function _unpause() internal virtual whenPaused {
        _paused = false;
        emit Unpaused(_msgSender());
    }
}
```

We can clearly see that the only functions which allow pausing/unpausing are internal, which means that only the contracts that inherit this one can call this functions, however if we look at all of the contracts in scope, they do not call this functions anywhere(`_pause()/_unpause()`), meaning the pausablity can never happen.

Thus the impact is that none of the contracts in-scope can be paused.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add a way to pause/unpause the contracts by adding restricted public functions to all of the contracts in-scope and in these functions use OpenZeppelin's `_pause`/`_unpause` functions.
