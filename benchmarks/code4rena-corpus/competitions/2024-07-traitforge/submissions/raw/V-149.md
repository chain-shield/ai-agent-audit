# Vulnerability details

## Impact
Forging a new entity will always be DoSed if there are already 9999 nfts minted in the current generation and the forged nft is the 10000th nft that will be minted.

## Proof of Concept
We know that maxTokensPerGen is 10000 NFTs.When a merger calls EntutyForging.forgeWithListed() to create a new entity based on the forger and merger NFT traits, the EntityForging.sol contract calls TraitForgeNft.forge() which in turn calls TraitForgeNft._mintNewEntity() to mint the new entity. Inside TraitForgeNft._mintNewEntity() there is this check to ensure that the new entity tokenId does not exceed the maxTokenPerGen (10000).
``` solidity
require(
      generationMintCounts[gen] < maxTokensPerGen,
      'Exceeds maxTokensPerGen'
    );
```
However, this check is wrong because it's using < and not <=.
Consider a scenario where 9999 nfts from the current gen have already been minted and the new forged nft is the 10000th to be minted, The call will revert because 9999 < 10000 effectivelly DoSing the NFT to be forged in the current Generation.

## Tools Used
Manual review

## Recommended Mitigation Steps
Change the require statement inside _mintNewEntity to match this:
``` diff
require(
      -generationMintCounts[gen] < maxTokensPerGen,'Exceeds maxTokensPerGen'
      +generationMintCounts[gen] <= maxTokensPerGen,'Exceeds maxTokensPerGen'
    );
```
