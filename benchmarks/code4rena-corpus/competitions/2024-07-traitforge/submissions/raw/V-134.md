# Vulnerability details

## Impact
Users could claim funds much earlier than intended, potentially draining the fund rapidly

## Proof of Concept
When an NFT is bought by calling buyNFT(), NFT is transferred to a new owner.

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L63-L92

However, the new owner can immediately call "nuke()" and by pass the minimum days check required for a user to call nuke(). 

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L153C3-L195C2

This is possible because token transfer timestamp is not tracked when NFT is sold and bought by a new owner. Immediately after buying NFT, new owner can call nuke() to get a share of the nukefund wihout holding for the required minimum number of time.

This leads to a "race to the bottom" where users try to nuke tokens as fast as possible, potentially draining funds rapidly and destabilizing the entire ecosystem.

## Tools Used
Manual review

## Recommended Mitigation Steps
getTokenLastTransferredTimestamp() should be called when buyNFT() is called so as to track tokenId transfers.


## Assessed type

Access Control
