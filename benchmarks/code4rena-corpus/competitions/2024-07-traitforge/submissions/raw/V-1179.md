# Vulnerability details

## Impact
The current implementation could allow for one extra forging operation per token

## Proof of Concept

In the `EntityForging` contract, there's a boundary condition issue in the `listForForging` function that could allow tokens to be forged one more time than intended. The current check:
```
forgePotential > 0 && forgingCounts[tokenId] <= forgePotential
```

allows listing when `forgingCounts[tokenId]` is equal to `forgePotential`. However, in the `forgeWithListed` function, forgingCounts is incremented:

```
forgingCounts[forgerTokenId]++;
```

This can result in forgingCounts exceeding forgePotential by 1.

For example, Let's say a token has a forgePotential of 3.

- Initially, forgingCounts[tokenId] = 0
- The token is forged 3 times, so now forgingCounts[tokenId] = 3
- At this point, forgingCounts[tokenId] <= forgePotential is still true (3 <= 3)
- The token can be listed for forging again
- When forgeWithListed is called, forgingCounts[tokenId]++ will make it 4

## Tools Used
Manual

## Recommended Mitigation Steps
```diff
- forgePotential > 0 && forgingCounts[tokenId] <= forgePotential
+ forgePotential > 0 && forgingCounts[tokenId] < forgePotential
```
