# Vulnerability details

The EntropyGenerator contract stores all generated entropy values in private state variables:

```
  uint256[770] private entropySlots; // Array to store entropy values
```

These values are visible to anyone who can read the blockchain state.

## Impact
The visibility of entropy values on-chain defeats the purpose of randomness in the system. This could lead to:

Predictability of outcomes in any system relying on this entropy.
Unfair advantages for users who can read and analyze the blockchain data.
Potential for front-running or other exploits in connected systems.

This vulnerability undermines the core functionality of the randomness mechanism and any features dependent on it.

## Proof of Concept
Any user can:

View the entropy values by viewing the state changes for the transactions involving `writeEntropyBatch1`, `writeEntropyBatch2` and `writeEntropyBatch3`.

Use these known values to predict outcomes in any system using this entropy.

eg `writeEntropyBatch1` transaction on testnet:
https://sepolia.etherscan.io/tx/0xee80e2f94b377507fc38072b80f5e5f123c0085c8209b69cb4175228f4f5a4f5#statechange

Just expand the down arrow on `0x49a461Ab...E58B98c65` and anyone can view all the entropy values.

## Tools Used
Manual review


## Recommended Mitigation Steps
Implement a commit-reveal scheme where the actual entropy values are not stored on-chain.
Use a verifiable random function (VRF) from an oracle service like Chainlink.
If on-chain storage is necessary, consider encrypting the values before storage and implement a secure decryption mechanism.
Redesign the system to use ephemeral, non-stored randomness that cannot be predicted from on-chain data.
