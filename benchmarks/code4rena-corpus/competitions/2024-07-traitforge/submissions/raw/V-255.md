# Vulnerability details

## Impact
Check the following places in the `TraitForgeNft` contract where `Airdrop` contract is used:
1. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L97
2. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L148
3. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L297
4. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L338

All of the methods above are based on the assumption that `TraitForgeNft` is an owner of `Airdrop`. But if `TraitForgeNft` is an owner of the `Airdrop` contract then the following methods become unreachable (because there are no corresponding calls in the `TraitForgeNft` contract):
- https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/Airdrop/Airdrop.sol#L20
- https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/Airdrop/Airdrop.sol#L38

## Tools Used

Manual review

## Recommended Mitigation Steps

Make sure that all `Airdrop` contract methods protected by the `onlyOwner` modifier can be called from the `TraitForgeNft` contract.
