# Vulnerability details

## Impact
 lead to stale or incorrect references in listedTokenIds, which do not accurately reflect the current state of listings.

## Proof of Concept
 When a token is listed for sale and then removed (either through cancellation or completion of the sale), the corresponding entry in the listedTokenIds mapping should ideally be updated to reflect this change.
```
function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant {
    Listing storage listing = listings[listedTokenIds[tokenId]];
    require(listing.seller == msg.sender, 'Only the seller can cancel the listing.');
    require(listing.isActive, 'Listing is not active.');
    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer the NFT back to seller
@>    delete listings[listedTokenIds[tokenId]]; // mark the listing as inactive or delete it
    emit ListingCanceled(tokenId, msg.sender);
}
```

In this function, while `listings[listedTokenIds[tokenId]] `is deleted, there is no line of code that sets` listedTokenIds[tokenId] `to a default or null value, which would be necessary to fully clear the listing reference.
