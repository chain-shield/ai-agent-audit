# Vulnerability details

## Impact
In TraitForgeNft.sol maxGeneration can be bypassed and a token can be minted outside of the required range of generations.

## Proof of Concept
Lets say for example: 
maxTokensPerGen=10000;
maxGeneration=10; 
currentGeneration=10;
generationMintCounts[currentGeneration]=10000;

When user wants to mint token, two functions can be used:

1. mintToken()
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L181-L200

2. mintWithBudget()
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225

Both of them are calling  _mintInternal() in which following check is presented:

```
 if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

If the statement is true, currentGeneration will be incremented via _incrementGeneration().
In this case currentGeneration will become 11 and will bypass maxGeneration that is 10. New token will be minted in generation that is not supposed to exist.


## Tools Used
Manual review

## Recommended Mitigation Steps
Implement a require statement in _incrementGeneration() that prevents this issue. For example:
```
function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
+   require(currentGeneration <= maxGeneration, 'Generation limit is reached')
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
