# Vulnerability details

## Impact
From  [forgeWithListed](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L102) function, the line `forgingCounts[mergerTokenId]++` increases the forging count for the merger token before the check `require(forgingCounts[mergerTokenId] <= mergerForgePotential, 'forgePotential insufficient');`. This sequence can cause a situation where the incremented count exceeds the token's forge potential, even if it was valid before the increment. As a result, a valid operation might inadvertently trigger an error, preventing users from forging merger tokens.

## Proof of Concept
Suppose the `mergerForgePotential` is 3, and the `forgingCounts[mergerTokenId]` is currently 2. 
If the function increments the count first, it becomes 3, which is within the limit. 
However, if the function were called again, the count would increment to 4, now exceeding the potential, and the function would revert.

Below [EntityForging.sol:forgeWithListed#139](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L139)

## Recommended Mitigation Steps

increment operation should occur only after confirming that the count is within the allowed limits.
```diff
 -- forgingCounts[mergerTokenId]++;
require(
  mergerForgePotential > 0 &&
  forgingCounts[mergerTokenId] < mergerForgePotential,
  'forgePotential insufficient'
);
 ++ forgingCounts[mergerTokenId]++;

```
