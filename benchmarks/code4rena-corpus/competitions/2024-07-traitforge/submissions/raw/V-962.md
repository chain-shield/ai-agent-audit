# Vulnerability details

## Impact
The `writeEntropyBatch3` function in the `EntropyGenerator.sol` contract cannot ensure the generation of a pseudoRandomValue of 999999 and its index. However, the whitepaper explicitly states that 999999 must be generated in Batch 3—["The Golden God is scanned for and is kept out of the first 2 passes, but is deliberately set in the final pass (at some random point)."]. (https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit). And the `initializeAlphaIndices` and `getEntropy` functions also outline conditions for the index of 999999. 
## Proof of Concept
According to the whitepaper, generating 10,000 entropy values requires 770 slots. These 770 slots are divided into 3 batches: the first two batches have 256 slots each, and the remaining slots make up the 3rd batch. The "Golden God" of 999999 will be generated in the third batch. The issue is that the pseudoRandomValue in the `writeEntropyBatch3` function is randomly generated, and it cannot guarantee the generation of 999999 and its index.
[contracts/EntropyGenerator/EntropyGenerator.sol:writeEntropyBatch3_L83-L98](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L83C1-L98C4)
```solidity
  // allows setting a specific entropy slot with a value
  function writeEntropyBatch3() public {
    require(
      lastInitializedIndex >= batchSize2 && lastInitializedIndex < maxSlotIndex,
      'Batch 3 not ready or already completed.'
    );
    unchecked {
     for (uint256 i = lastInitializedIndex; i < maxSlotIndex; i++) {
@audit=>  uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = maxSlotIndex;
  }
```

## Recommended Mitigation Steps
It is recommended to add a check such that if the `writeEntropyBatch3` function does not generate a pseudoRandomValue of 999999, it should continue executing the for loop. Alternatively, directly set the `numberIndexSelectionPoint` in the `initializeAlphaIndices` function for the pseudoRandomValue of 999999.
