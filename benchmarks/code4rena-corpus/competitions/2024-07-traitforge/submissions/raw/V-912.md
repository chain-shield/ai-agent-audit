# Vulnerability details

## Bug description
For every sale or forging 10% (set as default) of the proceeds goes to the NukeFund. In both cases, the fee is taken from the share of the user who listed their NFT.

[EntityTrading.sol#L72-L73](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L72-L73)
```solidity
uint256 nukeFundContribution = msg.value / taxCut;
uint256 sellerProceeds = msg.value - nukeFundContribution;
```

[EntityForging.sol#L146-L147](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L146-L147)
```solidity
uint256 devFee = forgingFee / taxCut;
uint256 forgerShare = forgingFee - devFee;
```

This approach is acceptable if the fee is fixed, OR if the seller is the taker so they can do the math and agree to the `taxCut` when fulfilling the counterparty's maker order. 
However, that's not the case with the current implementation since `taxCut` can be changed effective immediately and applies to all existing orders.

[EntityForging.sol#L36-L38](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L36-L38)
```solidity
function setTaxCut(uint256 _taxCut) external onlyOwner {
    taxCut = _taxCut;
}
```

When the `taxCut` is updated to a higher rate, say from 10% to 50%, a seller order placed before this update, can be fulfilled by a buyer, while the buyer pays the same amount, the seller (maker) will receive 40% less than initial sell order amount.

## Impact
A user listing their NFT for forging or selling can suffer a loss of funds.

## Recommended Mitigation
Consider making `taxCut` a constant value. Alternatively, make the taker (buyer) pay the fees.
