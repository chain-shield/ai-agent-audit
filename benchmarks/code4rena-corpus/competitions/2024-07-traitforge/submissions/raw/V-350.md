# Vulnerability details


### Impact

The `mintWithBudget` function in the `TraitForgeNft` contract becomes ineffective once the total number of minted NFTs reaches `maxTokensPerGen` (presumably 10,000 based on documantation context). This limitation prevents users from utilizing the budget minting feature for subsequent generations, disrupting the intended game mechanics and user experience. It effectively restricts the budget minting feature to only the first generation of entities, contradicting the multi-generational design of the game.

### Proof of Concept

In the `mintWithBudget` function, the minting loop is controlled by the following condition:

```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen)
```

The `_tokenIds` variable appears to be a global counter for all minted tokens across all generations. Once `_tokenIds` reaches or exceeds `maxTokensPerGen`, this condition will always evaluate to false, causing the loop to be skipped entirely. As a result:

1. No new tokens with budget will be minted, regardless of the provided budget.
2. The entire budget will be returned to the sender (via the refund mechanism at the end of the function).
3. Users will be unable to participate in budget minting for any generation after the first.

This behavior contradicts the game's design of having multiple generations of entities.

Manual Review

### Recommended Mitigation Steps

To align the functionality with the intended multi-generational design, replace the `_tokenIds` check with a generation-specific counter. This can be achieved by:

``` diff
+    while (budgetLeft >= mintPrice && generationMintCount[currentGeneration] < maxTokensPerGen) 
```
