# Vulnerability details

## Impact
`mintWithBudget()` is a function in `TraitForgeNft.sol` that is intended to allow a user to mint as many NFTs as he can using a set budget. The issue is that this function will not work after the first generation.

## Proof of Concept
The problem occurs in the while statement of the function:
```solidity
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```
As you can see the second check in the while statement is `_tokenIds < maxTokensPerGen`. This is used to ensure that the mint cap per gen is not exceeded. The issue is that instead of checking that the tokens minted in the current gen don't excceed the cap, it checks that all tokens in TOTAL don't exceed it. This is a problem as `maxTokensPerGen` is set to 10_000 but `_tokenIds` can go beyond 10_000 as it does not reset on gen incrementation. The function will simply revert after the first 10_000 tokens have been minted.

This check is unnecessary as the `_mintInternal()` function will automatically increment the generation after `maxTokensPerGen` has been reached. It will also adjust NFT prices accordingly.


## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove the `_tokenIds < maxTokensPerGen` check.
