# Vulnerability details

[H-2]  Generation Increment Failure Due to Misaligned Ownership

#### Overview
The TraitForgeNft contract contains a critical vulnerability that prevents it from incrementing to the next generation due to a permission mismatch between TraitForgeNft and EntropyGenerator contracts.

### Detailed Description
##### Contract Interaction

* In the TraitForgeNft contract, the _incrementGeneration() function is responsible for advancing to the next generation. This function includes a crucial call:

entropyGenerator.initializeAlphaIndices();


* The initializeAlphaIndices() function in EntropyGenerator.sol is restricted to onlyOwner. However, the current design intends for a multisig wallet to be the owner of EntropyGenerator, not the TraitForgeNft contract.

##### Execution Flow
mintToken() is called
_mintInternal() is invoked
When conditions are met, _incrementGeneration() is triggered
initializeAlphaIndices() is called, but fails due to incorrect ownership

#### Impact
The protocol will be unable to progress beyond the first generation.
Minting process will be halted after reaching the maximum tokens for the initial generation.

#### Proof of Concept

* To demonstrate this vulnerability, consider the following scenario:

1. Initial Setup:
EntropyGenerator.sol is deployed with the multisig wallet set as the owner.
TraitForgeNft.sol is deployed and linked to the EntropyGenerator contract.

2. Normal Minting Phase:
Users mint tokens through the TraitForgeNft contract.
The generationMintCounts[currentGeneration] increases with each mint.

3. Reaching Generation Limit:
Minting continues until generationMintCounts[currentGeneration] equals maxTokensPerGen.
The next mint operation triggers the following code in _mintInternal():

 ```javascript    
     if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
         _incrementGeneration(); 
     }
 ```    

4. Generation Increment Attempt:
The _incrementGeneration() function is called, which includes:

 ```javascript    
     function _incrementGeneration() private {
         // ... other code ...
         entropyGenerator.initializeAlphaIndices();
         // ... other code ...
     }
 ```    


5. Failure Point:
The initializeAlphaIndices() call fails because:
a. It's restricted by the onlyOwner modifier in EntropyGenerator.sol.
b. The owner is set to the multisig wallet, not the TraitForgeNft contract.

6. Result:
The _incrementGeneration() function reverts.
The current generation remains unchanged.
Further minting in the current generation is blocked due to the maxTokensPerGen limit.

### tool used
manual

#### Recommended Mitigation
To resolve this issue, implement one of the following solutions:

1. Ownership Transfer:
Make TraitForgeNft.sol the owner of EntropyGenerator.sol.

2. Permission Adjustment:
Modify EntropyGenerator.sol to allow TraitForgeNft.sol to call initializeAlphaIndices(), possibly through a new role
