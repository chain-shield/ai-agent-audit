# Vulnerability details

## Impact
In [TraitForgeNft.sol](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L35) On deploying ` maxGenerations ` is being set to value of `10 ` showing how many  generations can exist. There is a `setMaxGeneration()` that allows the contract owner to change the value of `maxGenerations` at any time. 

`_mintInternal()` is internal function and is responsible for minting the NFT to the `to` address and updating the state of the protocol.

```solidity
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }


    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();


    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;


    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
    }


    emit Minted(
      msg.sender,
      newItemId,
      currentGeneration,
      entropyValue,
      mintPrice
    );


    _distributeFunds(mintPrice);
  }
```
The function is used in two public functions called [mintWithBudget](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225) and [mintToken](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L181-L200) . `_mintInternal()` checks if the current mint counts are equal or bigger than `maxTokensPerGen` and if so it calls `_incrementGeneration` but the problem is that before doing that incrementing it doesnt check if the `currentGeneration ` is not equal or bigger than the `maxGeneration` which allows the `maxGeneration` to be exceeded which can break on of the main invariants of the protocol and eventually this can inflate the price of all NFTs because minting new NFTs and incrementing new generations can not be stoppped by the protocol owners if they don't redeploy the fixed contract.
 
## Proof of Concept

1. currentGeneration = 10, maxGeneration = 10 , generationMintCounts[currentGeneration] = 10_000 which should be the last NFT minted in the last 10th generation
2. Alice calls `mintToken()` which call the internal `_mintInternal()`
3. Because generationMintCounts[currentGeneration] >= maxGeneration the `_incrementGeneration` will be called and go to the next generation which will be ` 11 ` allowing Alice to get minted the NFT;
