# Vulnerability details

## Impact
fetchListings() will get progressively more gas inefficient and may result in UI complications.

The fetchListing() function will be used in the UI. The function returns every listing at the moment. The problem is that it cycles through every listing count created.
That means that if there were 10_000 listing created from the depolyment of the protocol it will cycle through every single one of them. There is no decrement for listingCount
in any part of the code. If there are enough listinCounts this will result in the dos of the functionality.

Impact - low(it will break UI)
Likelihood - high
Overall - medium

## Proof of Concept

```solidity
function fetchListings() external view returns (Listing[] memory _listings) {
    _listings = new Listing[](listingCount + 1);
    for (uint256 i = 1; i <= listingCount; ++i) { //@audit with the progressive increment of listingCount, we will get more more gas inneficent resulting in dos of the function
      _listings[i] = listings[i];
    }
  }
```
