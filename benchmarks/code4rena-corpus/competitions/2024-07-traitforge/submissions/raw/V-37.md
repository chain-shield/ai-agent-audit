# Vulnerability details

## Impact
DevFund.sol has a **`receive()`** function, allowing it to accept Ether. A portion of the received ether is intended to be sent to the **`owner()`**. However, due to an incorrect calculation, the amount of ether that should be sent to the owner always ends up being 0.
## Proof of Concept
**`receive()`** is implemented as follows:
```Solidity
receive() external payable {
    if (totalDevWeight > 0) {
      uint256 amountPerWeight = msg.value / totalDevWeight;
      uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);

      totalRewardDebt += amountPerWeight;
      if (remaining > 0) {
        (bool success, ) = payable(owner()).call{ value: remaining }('');
        require(success, 'Failed to send Ether to owner');
      }
    } else {
      (bool success, ) = payable(owner()).call{ value: msg.value }('');
      require(success, 'Failed to send Ether to owner');
    }
    emit FundReceived(msg.sender, msg.value);
  }
```
As you can see, if **`totalDevWeight > 0`**, it attempts to calculate the remaining ether to be sent to the owner. However, this amount always ends up being 0 because:

**`amountPerWeight = msg.value / totalDevWeight`**
**`remaining = msg.value - (amountPerWeight * totalDevWeight)`**

Consequently, **`remaining`** will be:

**`remaining = msg.value - (( msg.value / totalDevWeight) * totalDevWeight) = msg.value - msg.value = 0`**

As you can see, the **`remaining`** amount will always be 0 because **`totalDevWeight`** is both multiplied and divided in the calculation, effectively canceling itself out.
 
As a result, the owner will never receive any ether because the funds are stuck in the contract.
 
This is because the **`totalRewardDebt`** is calculated as **`msg.value / totalDevWeight`**. If the **`remaining`** is 0 it mean the surplus funds are not sent to the owner and remain stuck in the contract. The contract lacks any function to withdraw these funds, resulting in a loss of funds.

## Recommended Mitigation Steps
I imagine the developers intend to retain the ether corresponding to **`totalDevWeight`** within the contract and send the remainder to the owner. 

However, achieving this requires a clear reference point, as **`totalDevWeight`** represents the cumulative value for all developers. The team needs to devise a system to determine the percentage that **`totalDevWeight`** represents, and then calculates the remaining amount that needs to be sent to the owner.
