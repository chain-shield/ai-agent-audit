# Vulnerability details

## Impact
Hidden division before multiplication will cause rounding issues

## Proof of Concept
Users can call `nuke()` to nuke their NFTs in return of ETH. There, we calculate their claim amount based on multiple factors. Firstly, we calculate the age:
```solidity
uint256 age = (daysOld * perfomanceFactor * MAX_DENOMINATOR * ageMultiplier) / 365;
```
Then, using the age, we calculate the `finalNukeFactor`:
```solidity
uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) / MAX_DENOMINATOR) + initialNukeFactor;
```
Then, using the `finalNukeFactor`, we calculate the claimable amount:
```solidity
uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR;
```
In the snippets above, there are 2 cases of hidden division before multiplication. Firstly, the age is divided by 365 which is then multiplied with `defaultNukeFactorIncrease` and divided by `MAX_DENOMINATOR`. This was the first case of division before multiplication as the age was first divided by 365 and then multiplied to the default factor increase.

Then, we use the `finalNukeFactor` to multiply with `fund` and then divide with `MAX_DENOMINATOR` which is the other case of division before multiplication as `finalNukeFactor` was already divided by `MAX_DENOMINATOR` before multiplying.

Both these 2 cases combined can cause significant rounding issues.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Do not divide before multiplying to avoid the rounding issues
