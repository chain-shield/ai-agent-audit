# Vulnerability details

## Impact

The `TraitForgeNft` contract has a critical flaw in its generation transition mechanism that leads to the loss of forged entity counts. This issue occurs in the `_incrementGeneration()` function, which is called when the current generation reaches its minting limit. The function resets the `generationMintCounts` for the new generation to zero, effectively erasing any entities that were forged for the upcoming generation.

The impact of this issue is severe:

1. Inaccurate tracking of minted entities: The contract may allow more than the intended `maxTokensPerGen` to be created for a generation, as forged entities for the next generation are not accounted for when transitioning.

2. Potential economic exploit: Users could potentially mint more tokens than intended for a generation, leading to an unfair advantage or economic imbalance in the ecosystem.

3. Inconsistent state: The actual number of entities per generation will not match the recorded count, potentially causing issues with other contract functionalities or external systems relying on this data.

4. Game mechanics disruption: If the number of entities per generation is crucial for game balance or mechanics, this bug could significantly impact gameplay and fairness.

## Proof of Concept

The issue occurs in the `_incrementGeneration()` function:

```solidity
function _incrementGeneration() private {
  require(
    generationMintCounts[currentGeneration] >= maxTokensPerGen,
    'Generation limit not yet reached'
  );
  currentGeneration++; 
  generationMintCounts[currentGeneration] = 0; // This line resets the count
  priceIncrement = priceIncrement + priceIncrementByGen;
  entropyGenerator.initializeAlphaIndices();
  emit GenerationIncremented(currentGeneration);
}
```

When this function is called, it resets the count for the new generation, ignoring any entities that may have been forged for this upcoming generation.

## Recommended Mitigation Steps

1. Implement a check in the `_mintNewEntity()` function to ensure the total number of entities (minted + forged) for a generation doesn't exceed `maxTokensPerGen`:

```solidity
require(
  generationMintCounts[gen] < maxTokensPerGen,
  'Exceeds maxTokensPerGen'
);
```

2. Consider adding a separate tracking mechanism for forged entities to provide clearer distinction and easier auditing of minted vs. forged entities per generation.
