# Vulnerability details



## Vulnerability Details

The `TraitForgeNft:forge()` function, which can only be called by the `EntityForgingContract`, is responsible for minting a new entity using two other entities. The newly minted entity will belong to the next generation of the current generation.

During execution, the function calls `TraitForgeNft:_mintNewEntity()`, which mints a new token in the next generation and updates the state as follows:
```solidity
generationMintCounts[gen]++;
```

When a new generation starts, the `TraitForgeNft:_incrementGeneration()` function is invoked. This function updates state variables as follows:
```solidity
currentGeneration++;
generationMintCounts[currentGeneration] = 0;
```

This resets the `generationMintCounts` of the next generation to zero, effectively disregarding the count of entities minted through forging. As a result, the number of tokens per generation can exceed the maximum limit.

### Explanation of the Vulnerability

1. **Minting New Entities**:
   - The `forge()` function mints new entities and increments the `generationMintCounts` for the respective generation.

2. **Incrementing Generations**:
   - When the generation increments via `_incrementGeneration()`, it sets the `generationMintCounts` for the new generation to zero.

3. **Count Discrepancy**:
   - This reset overlooks the entities that were minted through forging, causing the `generationMintCounts` to inaccurately reflect the actual number of entities minted in that generation.

4. **Exceeding Maximum Limits**:
   - Due to this reset, it is possible for the number of tokens in a generation to exceed the intended maximum limit, leading to potential overflows and inconsistencies in the generation-based minting logic.

## Impact

The vulnerability could allow more tokens to be minted than intended for a given generation, disrupting the balance and integrity of the token distribution system. This can lead to inflation of the token supply, potential economic impacts, and loss of trust among users.

## Recommended Mitigation Steps
Don't reset `generationMintCounts[currentGeneration] ` to zero.
