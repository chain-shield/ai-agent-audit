# Vulnerability details

## Impact
The forgeWithListed function in the EntityForging.sol contract lacks a refund mechanism for users who send more Ether than the required forgingFee. This oversight means that if a user sends an amount greater than the specified fee, the surplus funds will be stuck in the contract.

## Proof of Concept
```solidity
require(msg.value >= forgingFee, 'Insufficient fee for forging');

// Distribution of fees
(uint256 devFee = forgingFee / taxCut;
uint256 forgerShare = forgingFee - devFee;
```
If the forgingFee is set to 1 ETH and a user sends 1.5 ETH:
- The contract only processes 1 ETH for the forging operation.
- The remaining 0.5 ETH is not refunded and remains stuck in the contract.

## Tools Used

## Recommended Mitigation Steps
Implement a refund mechanism to handle any excess payment sent by users.
