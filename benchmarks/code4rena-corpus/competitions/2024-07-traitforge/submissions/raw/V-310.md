# Vulnerability details

## Impact
After some time (probably a few days after the start), [fetchListings](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L48-L53) will become unusable. This will prevent anyone (front-end, integrations...) from querying any of the listed tokens.

## Proof of Concept
[fetchListings](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L48-L53) will run out of gas after a while because the function tries to iterate over all listings, even the empty ones.

```solidity
function fetchListings() external view returns (Listing[] memory _listings) {
    _listings = new Listing[](listingCount + 1);
    for (uint256 i = 1; i <= listingCount; ++i) {
        _listings[i] = listings[i];
    }
}
```

With every [list](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L67-L100), `listingCount` increases, even if the user unlists the NFT later. This causes `listingCount` to quickly expand and consume more gas than there is in a block when calling `fetchListings`.

```solidity
++listingCount;
listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
listedTokenIds[tokenId] = listingCount;
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Add `start` and `count` variables to enable the querying of specific listings. Example code:

```solidity
function fetchListings(uint256 start, uint256 count) external view returns (Listing[] memory _listings) {
    uint256 end = start + count;
    if (end > listingCount) {
        end = listingCount;
    }

    _listings = new Listing[](count);
    for (uint256 i = start; i <= end; ++i) {
        _listings[i] = listings[i];
    }
}
```
