# Vulnerability details

## Impact

In certain edge cases, the `tokenEntropy` calculation for a token can result in a value of zero. This will lead to `finalNukeFactor` also being zero, causing the user to burn their NFT without receiving any ETH in return.

## Proof of Concept

Let's break down the flow:

In `NukeFund::nuke(tokenId)`

```solidity
  function nuke(uint256 tokenId) public whenNotPaused nonReentrant {
    /// ...
    // finalNukeFactor will be zero
@>  uint256 finalNukeFactor = calculateNukeFactor(tokenId);
    // potentialClaimAmount =  (fund * 0) / MAX_DENOMINATOR == 0
    uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR;
    uint256 maxAllowedClaimAmount = fund / maxAllowedClaimDivisor;
    // finalNukeFactor > nukeFactorMaxParam == false => claimAmount == potentialClaimAmount == 0
    uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
      ? maxAllowedClaimAmount
      : potentialClaimAmount;

    fund -= claimAmount;

    nftContract.burn(tokenId); // Burn the token
    (bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
    require(success, 'Failed to send Ether');
    //...
  }
```

If `calculateNukeFactor` returns zero, then `potentialClaimAmount` and `claimAmount` will also be zero. The token will still be burned, but no ETH will be sent to the user.

Looking at `calculateNukeFactor`:

```solidity
  function calculateNukeFactor(uint256 tokenId) public view returns (uint256) {

  // getTokenEntropy(tokenId) can return `zero` in edge cases
  // entropy == 0
  uint256 entropy = nftContract.getTokenEntropy(tokenId);
  // calculateAge(tokenId) will return zero if getTokenEntropy(tokenId) == 0
  uint256 adjustedAge = calculateAge(tokenId);
  // initialNukeFactor = 0 /40 == 0
  uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits
  // finalNukeFactor = ((0 * defaultNukeFactorIncrease) / MAX_DENOMINATOR) + 0 == 0
  uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
    MAX_DENOMINATOR) + initialNukeFactor;
  return finalNukeFactor;
}
```

If `getTokenEntropy` returns zero for the token, then `initialNukeFactor` and `finalNukeFactor` will also be zero.

In `TraitForgeNft`, we can see that `tokenEntropy` is set when minting a new token:

The entropy value comes from `EntropyGenerator.getNextEntropy()`.

Looking at that function:

```solidity
  function getNextEntropy() public onlyAllowedCaller returns (uint256) {
    require(currentSlotIndex <= maxSlotIndex, 'Max slot index reached.');
@>  uint256 entropy = getEntropy(currentSlotIndex, currentNumberIndex);
    // ...
    return entropy;
  }

  // private function to calculate the entropy value based on slot and number index
  function getEntropy(
    uint256 slotIndex,
    uint256 numberIndex
  ) private view returns (uint256) {
    require(slotIndex <= maxSlotIndex, 'Slot index out of bounds.');

    if (
      slotIndex == slotIndexSelectionPoint &&
      numberIndex == numberIndexSelectionPoint
    ) {
      return 999999;
    }

    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

    return paddedEntropy; // return the caculated entropy value
  }
```

Depending on the values in `entropySlots` and the `slotIndex` and `numberIndex`, it's possible for `getEntropy` to return zero.

In summary:

- When minting a token, there's a chance it gets assigned a `tokenEntropy` value of `zero`
- If a token with zero entropy is nuked, `calculateNukeFactor` will return `zero`
- This results in the token being burned without any ETH being sent to the user
