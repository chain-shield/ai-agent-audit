# Vulnerability details

## Impact
The `TraitForgeNft` contract allows minting of NFTs beyond the intended 10 generations due to lacking of verification during direct minting. This flaw lets users create more NFTs than expected.

## Proof of Concept
According to the current design, the NFT contract is supposed to have 10 generations, with 10,000 NFTs per generation. The maximum generation value is controlled by the `maxGeneration` variable in the TraitForgeNft contract. It is initialized to 10.

```solidity
  /// @dev generation limit
  uint256 public maxGeneration = 10;
```

However, in practice, `maxGeneration` does not effectively enforce a limit, allowing users to mint NFTs beyond the 10th generation, such as the 11th or 12th generation.

This issue arises because the contract only limits the next generation during the `forge` function. It ensures that the next generation does not exceed `maxGeneration` when forging.

```solidity
/// Check new generation is not over maxGeneration
    require(newGeneration <= maxGeneration, "can't be over max generation");
```

However, there is no restriction in the direct minting process (see code below), which allows continuous minting.

```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();

    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;

    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
    }

    emit Minted(
      msg.sender,
      newItemId,
      currentGeneration,
      entropyValue,
      mintPrice
    );

    _distributeFunds(mintPrice);
  }
```

This omission allows minting to continue indefinitely, exceeding the expected 10 generations.

```typescript
    it('could mint more than 10 generations', async () => {
```

For testing convenience, `maxTokensPerGen` has been set to 2 (fixing the `initializeAlphaIndices` functions's modifier as well). The output confirms that through direct minting, it is possible to generate NFTs beyond the expected `maxGeneration`.

## Recommended Mitigation Steps
Add check logic below:

```diff
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
+    require(currentGeneration <= maxGeneration, 'Max generation reached');
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
