# Vulnerability details

## Summary

The TraitForge Ecosystem allows players to list their entities for forging, but a malicious forger can prevent others from merging with their entity by merging with their own merger token in a single Transaction. That is they list the token for forgeing and merge with it in a single transaction.

## Vulnerability Details

Trait Forge prevents a forger from merging with their own merger token, so the forger and the owner can't be owned by the same address. The problem here is that the forger can simply store the merger token in another address and merge. But this is worst because they can do it in a single transaction. Doing this in a single transaction prevent other mergers for trying to forge with the Listed Forger token.

## Impact

1. Self-Forging: A malicious forger can list their desirable token at the minimum listing fee forge with it in the same transaction, thus prevent everyone from having a chance to forge with the Entity, by doing this they will receive 90% of the fee back, allowing them to forge at a significantly reduced cost. 

E.g 

The minimum listing fee is (0.01 eth), since the minimum cost of minting an Entity is (0.005 eth), and 90% of the fee is going back to them and the new Entity will have desirable traits, this becomes very profitable as they would spend around 0.001 ether.

10% of 0.01 eth to mint this new entity, this is about 5 times less than the amount that they will spend to mint a new Entity. It becomes more profitable to do something like this when the price of minting Entities increases, e.g 5000 Entities have been minted the minting price would be: 0.005 + 0.0000245 * 5000 = 0.1275 eth at this price more people with merger token would rather forge than mint new Entities and the listing price would be close to 0.1275 eth, but because the lister knows that they can list and be the only one allowed to merge with the Entity, they will list at the minimum price of 0.01 ether and merge with themselves. Which is poor market logic, and also the protocol losing funds in dev fees. 



2. Preventing Others from Merging: By Listing and Merging in the same transaction is like have close or private sales at a very cheap price, which prevent others from participating in the forge listing market.

## Recommendation

Do not allow listing and forging in the same transaction, this can be achieved by waiting a few blocks into the future before allowing forging with a listed token.

Add activeBlockNumber to the Listing Struct

```diff
interface IEntityForging {
    struct Listing {
    address account;
    uint256 tokenId;
    bool isListed;
    uint256 fee;
+   uint256 activeBlockNumber;
  }
```

set `activeBlockNumber` = `block.number + 10`, to make it a block number in the future when listing tokens.

```diff
  function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    ...
-    listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
+    listings[listingCount] = Listing(msg.sender, tokenId, true, fee, block.number + 10);
    listedTokenIds[tokenId] = listingCount;
```

Check if block number is greater than the active block number before forging

