# Vulnerability details

**Description**
The `transferFrom()` and `_mint()` methods are used instead of `safeTransferFrom()` and `_safeMint()`, presumably to save gas. I however argue that this isn’t recommended because:

[OpenZeppelin’s documentation](https://docs.openzeppelin.com/contracts/4.x/api/token/erc721#IERC721-transferFrom-address-address-uint256-) discourages the use of `transferFrom()` and `_mint()`, use `safeTransferFrom()` and `_safeMint()` whenever possible.


If the `to` argument in the [TraitForgeNft::_mintInternal()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L280) is a contract address, that does not support ERC721, the NFT will be frozen in the contract.

As per the documentation of EIP-721:
> A wallet/broker/auction application MUST implement the wallet interface if it will accept safe transfers.

**Impact**

Users possibly lose their NFTs

**Recommended mitigation**

Use `safeTransferFrom()` and `_safeMint()` instead of `transferFrom()` and `_mint()`.
