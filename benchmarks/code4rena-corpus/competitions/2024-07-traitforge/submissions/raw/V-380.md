# Vulnerability details

## Vulnerability Details

Every entity has features, details of which is found in the 6 digit number generated for each entity by `EntityGenerator`. Additionally, according to the [Docs](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit), there is a unique number that is regarded as the perfect number, or `The Golden God` as it is called and this number is 999999 and just one of this shoould exist in each generation. However, as explained here, there are instances where more than one Golden God exists with the game. 

In [`EntropyGenerator::writeEntropyBatch1()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L56C8-L56C71), you would find the check below that ensures that the number 999999 isnt generated by the pseudo-random number generator. There's a similar one in [EntropyGenerator::writeEntropyBatch2()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L76).

```solidity
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```
This check exists to ensure that the Golden God is found in the 3rd batch of entropy generation to incentivize users to participate in the game.

The function accounted for the generation of the number 999999 for the slot value but it didnt account for the number (10 ** 78) - 1 which in itself is a Golden God. This value when converted into the entropy in [`EntropyGenerator::getEntropy()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L181) will result in a Golden God entity.

## Impact
The existence of more than one Golden God per generation. Put simply, there will more than one entity that matures faster than others and can lay claim to 50% of the nukeFund faster than the other entities. This is a medium because for this vulnerability to manifest, the generator has to generate a (10 ** 78) - 1 value and it has to be generated for a numberIndex of 12 (12th position).

## Proof of Concept
1. `EntropyGenerator::writeEntropyBatch1()`,`EntropyGenerator::writeEntropyBatch2()`, and `EntropyGenerator::writeEntropyBatch3()` are called to generate the slot values which is used to compute the entropy values.
2. If (10 ** 78) - 1 is generated, any user who mints the entity whose entropy corresponds to (10 ** 78) - 1 will now possess the Golden God features.

```solidity
  function writeEntropyBatch1() public {
    require(lastInitializedIndex < batchSize1, 'Batch 1 already initialized.');

    uint256 endIndex = lastInitializedIndex + batchSize1; // calculate the end index for the batch
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array
      }
    }
    lastInitializedIndex = endIndex;
  }
```
