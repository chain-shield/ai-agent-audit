# Vulnerability details

## Vulnerability Details:

The function `EntropyGenerator::initializeAlphaIndices` is used for selecting index points for the 999999 Entropy, which is the "Golder God" entity. The function looks as follows:

``` js
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```

The function sets `slotIndexSelectionPoint` and `numberIndexSelectionPoint`, which are later used in `EntropyGenerator::getEntropy`:

``` javascript
function getEntropy(
    uint256 slotIndex,
    uint256 numberIndex
) private view returns (uint256) {
    require(slotIndex <= maxSlotIndex, 'Slot index out of bounds.');

    if (
@>    slotIndex == slotIndexSelectionPoint &&
@>    numberIndex == numberIndexSelectionPoint
    ) {
      return 999999;
    }

    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

    return paddedEntropy; // return the caculated entropy value
}
```

These parameters are important as they set exactly when a "Golden God" is going to be minted. The first issue is that these variables are set as public in the `EntropyGenerator`.

```js
contract EntropyGenerator is IEntropyGenerator, Ownable, Pausable {
  ...
@>uint256 public slotIndexSelectionPoint;
@>uint256 public numberIndexSelectionPoint;
    ...
}
```

This would allow any user to wait and mint only the "Golden God".

Further, `EntropyGenerator::initializeAlphaIndices` uses the block number and timestamp to calculate a `keccak256` hash, used as a "random" variable in the calculation of `slotIndexSelectionPoint` and `numberIndexSelectionPoint`. Hash functions are not random and any user can infer the values of `slotIndexSelectionPoint` and `numberIndexSelectionPoint` from the block number and timestamp. This again allows any user to wait and mint only the "Golden God".

```js
uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );
```

## Impact

This finding impacts the minting of the Rare "Golden God" and any user can wait and mint it at the appropriate time.


## Recommended Mitigation
Change the visibility modifier of `slotIndexSelectionPoint` and `numberIndexSelectionPoint` to internal.

```diff
contract EntropyGenerator is IEntropyGenerator, Ownable, Pausable {
  ...
- uint256 public slotIndexSelectionPoint;
- uint256 public numberIndexSelectionPoint;
+ uint256 internal slotIndexSelectionPoint;
+ uint256 internal numberIndexSelectionPoint;
    ...
}
```

Further, the generation of `slotIndexSelectionPoint` and `numberIndexSelectionPoint` should be changed to use Pseudo Random generation that is harder to track instead of the hash function. For example, use Chainlink VRF.
