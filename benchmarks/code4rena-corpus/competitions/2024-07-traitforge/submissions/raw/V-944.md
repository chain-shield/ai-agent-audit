# Vulnerability details

## Impact

`NukeFund` contract has a functionality to nuke ERC721 token and get some other tokens using `NukeFund::nuke` function. To get new tokens, ERC721 token need to be burn. `NukeFund::nuke` function call `nftContract::burn` function to burn the token. Next, `nftContract::burn` function call `airdropContract::subUserAmount` function which has `onlyOwner` modifier, and it will revert beacuse the call is from `TraitForgeNft` contract which is not the owner.

```javascript
function burn(uint256 tokenId) external whenNotPaused nonReentrant {
```

## Recommended Mitigation Steps

Give access to `Airdrop::startAirdrop` function for `owner` and `TraitForgeNft` contract.

Example how to solve this problem:

Use a modifier which allows to call function `Airdrop::startAidrop` by the owner of the `Airdrop` contract and as well by the `TraitForgeNft` contract.

```diff
+   import "../TraitForgeNft/ITraitForgeNft.sol";

+   ITraitForgeNft public traitForgeNft

+   function setTraitForgeNftContract(address traitForgeNft_) external onlyOwner {
+        require(traitForgeNft_ != address(0), "Invalid address");
+        traitForgeNft = ITraitForgeNft(traitForgeNft_);
+    }

+   modifier onlyOwnerAndTraitForgeNft {
+       require(owner() == msg.sender || traitForgeNft == msg.sender, "not the owner");
+       _;
+   }

-    function startAirdrop(uint256 amount) external whenNotPaused nonReentrant onlyOwner {
+    function startAirdrop(uint256 amount) external whenNotPaused nonReentrant onlyOwnerAndTraitForgeNft {
```
