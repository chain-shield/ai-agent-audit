# Vulnerability details

In the `EntropyGenerator` contract, forge potential is calculated using the first digit of the entropy:
```
 forgePotential = getFirstDigit(entropy);
```
However, in the `EntityForging` contract, it uses the fifth digit
```
uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
```

Similar issue is also found in the nukeFactor calculations
nukeFactor calculation in EntropyGenerator contract (will always be 0):
```
    nukeFactor = entropy / 4000000;
```
nukeFactor calculation in NukeFund contract:
```
    uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits
```

## Impact
This inconsistency could lead to several issues:

User Confusion: Players may be confused if the forge potential they expect (based on the EntropyGenerator logic) differs from what they can actually use in the EntityForging contract.

System Integrity: The inconsistency raises questions about which implementation is correct, potentially indicating deeper design or implementation issues.

## Proof of Concept
Generate an entropy value for a new entity: "123456"

In EntropyGenerator, the forge potential would be 1 (first digit)

In EntityForging, the forge potential would be 5 (fifth digit)

## Tools Used
Manual review

## Recommended Mitigation Steps
Decide on the correct implementation for forge potential calculation and apply it consistently across all contracts.
