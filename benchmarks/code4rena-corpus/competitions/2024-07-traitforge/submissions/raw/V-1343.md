# Vulnerability details

## Description 
In the `TraitForgeNft::mintWithBudget` function, there is the following condition in the while loop:

```javascript
  function mintWithBudget( bytes32[] calldata proof)
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
                      ...

@>  while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) { 
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
                      ...
  }

```
The second condition is satisfied while `_tokenIds` is less than `maxTokensPerGen`, whose value is 10_000.

However, as the NFT ID (`_tokenIds`) is obtained by simple incrementation, starting from 1, we notice that after 10_000 minted tokens, the value of the variable `_tokenIds` will always be >= `maxTokensPerGen`. Therefore, this condition will never be satisfied after that.

## Impact 
After 10_000 minted tokens, this function becomes unusable.


## Proof of Concept

Place the following test into TraitForgeNft.test.ts:

```javascript
  it("can`t use mintWithBudget after 10000 minted NFTs", async function() {
    this.timeout(0); // Disable timeout for this test
    let maxTokens = await nft.maxTokensPerGen();

    for (let i = 0; i < maxTokens; i++) {
    await nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, { value: ethers.parseEther('1') });
    }
    
    let gen1Counter = await nft.generationMintCounts(1);
    expect(gen1Counter).to.be.equal(maxTokens);


    const ownerBalanceBefore = await ethers.provider.getBalance(owner.address);
    console.log("Owner balance before mintWithBudget:", ethers.formatEther(ownerBalanceBefore), "ETH");
    nft.connect(owner).mintWithBudget(merkleInfo.whitelist[0].proof, { value: ethers.parseEther('10') });
    const ownerBalanceAfter = await ethers.provider.getBalance(owner.address);
    console.log("Owner balance after mintWithBudget:", ethers.formatEther(ownerBalanceAfter), "ETH");

    expect(ownerBalanceBefore).be.equal(ownerBalanceAfter); //we expect that balances are the same, because we didn`t mint any token with mintWithBudget function
  });
```

## Recommended Mitigation Steps

1. Remove the second condition in the while loop definition, since it is unnecessary and already exists in the `_mintInternal` funcion.
2. If you want to keep the check, another possible solution would be to check if `generationMintCounts[currentGeneration]` is less than `maxTokensPerGen`:
```diff
  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

-   while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
+   while (budgetLeft >= mintPrice && generationMintCounts[currentGeneration] <= maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice); 
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }

```
