# Vulnerability details

## Impact

The `EntropyGenerator.writeEntropyBatch1` function is used to initialize the first batch of entropy values. In the `writeEntropyBatch1` function during the `initialization` of the entropy values there is a logic which does not allow the `entropy value == 999999` as shown below:

```solidity
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```

This is performed to ensure that the entropy value of `999999` is deliberately set in the `final batch (where the slot index is from 512 - 769)`. But the above conditional check is wrong since it assumes that the `pseudoRandomValue` has only one `entropy value`. But the `pseudoRandomValue` consists of 78 digits and it has `13 entropy values` concatenated into a single `pseudoRandomValue`. 

Hence the above check of `pseudoRandomValue != 999999` is erroneous. Due to this error if any of the `entropyValues` of a particular `numberIndex` inside a particular `slotIndex` has `999999` value it will not be checked and that `entropy value (999999)` will be stored in the `EntropyGenerator.entropySlots` array belonging to the `first batch of entropy values`. 

This is not the expected behavior of the protocol since protocol documentation clearly states that the `999999` entropy value should be deliberately set in the (slot index 512 - 769). 

Furthermore the above issue will enable multiple `999999` entropy values to be stored in the `EntropyGenerator.entropySlots` array for a single generation. Thus allowing multiple `Golden God` NFTs to be minted in a single generation. This is also not the expected behavior since single generation is expected to have only one `999999` entropy value (Only one Golden God NFT) in it.

      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {

## Recommended Mitigation Steps

Hence it is recommended to divide the `pseudoRandomValue` (which consists of 78 digits) in to `13 separate 6 digit numbers` and then check whether each of these `13 numbers` match the value of `999,999` in a loop, for each iteration of the `slot index`. If any of the above `13 number` matches the `999,999` the transaction should revert and the `EntropyGenerator.writeEntropyBatch1` should be called again, till the `EntropyGenerator.entropySlots` array is filled with entropy values which does not contain a single `999,999` entropy value.

The same issue is prevalent in the `EntropyGenerator.writeEntropyBatch2` function as well.
