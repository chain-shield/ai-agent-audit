# Vulnerability details

## Impact
The `listForForging` function currently allows listing an NFT entity even when its `forgingCounts` is equal to the `forgePotential`. This creates a potential inconsistency because such entities can't forge any further. Hence, they shouldn't be listable for forging, leading to a dead listing being present that can't be forged with.
## Proof of Concept
Affected Code: `listForForging`
```solidity
function listForForging(uint256 tokenId, uint256 fee) public whenNotPaused nonReentrant {  
    Listing memory _listingInfo = listings[listedTokenIds[tokenId]];  

    require(!_listingInfo.isListed, 'Token is already listed for forging');  
    require(  
        nftContract.ownerOf(tokenId) == msg.sender,  
        'Caller must own the token'  
    );  
    require(  
        fee >= minimumListFee,  
        'Fee should be higher than minimum listing fee'  
    );  

    _resetForgingCountIfNeeded(tokenId);  

    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId  
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy  
    require(  
@>        forgePotential > 0 && forgingCounts[tokenId] <= forgePotential, // Bug: this should be <  
        'Entity has reached its forging limit'  
    );  

    bool isForger = (entropy % 3) == 0; // Determine if the token is a forger based on entropy  
    require(isForger, 'Only forgers can list for forging');  

    ++listingCount;  
    listings[listingCount] = Listing(msg.sender, tokenId, true, fee);  
    listedTokenIds[tokenId] = listingCount;  

    emit ListedForForging(tokenId, fee);  
}
```
Correction
Modify the line to:
```solidity
require(  
    forgePotential > 0 && forgingCounts[tokenId] < forgePotential, // Fixed: enforce strict less-than condition  
    'Entity has reached its forging limit'  
);
```

## Recommended Mitigation Steps
1. Update the condition in the `listForForging` function to ensure that entities with `forgingCounts` equal to `forgePotential` are not allowed to be listed.
2. This ensures alignment with the intent that only entities capable of forging at least one more time can be listed, thereby preventing dead listings.
