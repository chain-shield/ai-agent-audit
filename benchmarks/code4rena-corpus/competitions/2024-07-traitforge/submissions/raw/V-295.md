# Vulnerability details

## Impact
Forge potential is wrongly calculated inside `deriveTokenParameters`, which can potentially lead to integration errors.

## Proof of Concept
[deriveTokenParameters](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L152-L154) calculates `forgePotential` as the first digit of the entropy value. For example, if the entropy is `123456`, the current forge potential would be `1`.

```solidity
    nukeFactor = entropy / 4000000;
    forgePotential = getFirstDigit(entropy);
    performanceFactor = entropy % 10;
```

However, this is incorrect. In the `EntityForging` contract, where the actual forging takes place, `forgePotential` is derived from the 5th digit of the entropy value. Using the same example `123456`, the correct `forgePotential` would be `5`.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L86
```solidity
    uint8 forgePotential = uint8((entropy / 10) % 10);
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Calculate `forgePotential` the same way it is done in `EntityForging`:

```diff
    nukeFactor = entropy / 4000000;
-   forgePotential = getFirstDigit(entropy);
+   forgePotential = (entropy / 10) % 10;
    performanceFactor = entropy % 10;
```
