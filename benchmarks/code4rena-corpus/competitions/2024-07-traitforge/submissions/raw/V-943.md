# Vulnerability details

## Impact

In the `NukeFund` contract, `calculateNukeFactor()` implementation is incorrect and does not generate results according to the specification. More precisely, the calculation generates nuke factor values that are **growing 100 times slower than expected** due to incorrect `defaultNukeFactorIncrease` parameter value.

The incorrect factor calculation results in the following issues:

1. **Unfair distribution**: It takes 100 times longer then intended to reach the maximum claimable amount from the fund. This leads to an unfair distribution of funds, disadvantaging token holders.
2. **Reduced incentives**: The extended period required to reach significant claimable amounts reduces the incentives for users to participate, potentially diminishing the contract's usage and overall engagement.
3. **Economic imbalance**: The extended claim period can cause an economic imbalance within the system, affecting the expected financial flows and rewards distribution.


## Proof of Concept

According to the [specification](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit?pli=1), NFT with the best characteristics (entropy of 999_999) should reach the maximum `nukeFactor` of 50% in about 30 to 40 days.

> The maximum total Nuke Factor is 50% - ie, a single nuke can claim 50% of all ETH in the Fund. Entities move from their initial Nuke Factor (set randomly) towards the maximum with a speed dictated by Performance Factor (set randomly). Some mature faster than others, with the fastest maturing in around 30 days, and slowest 600 days.

Following is the function used to calculate the `nukeFactor`:

```javascript  
  function calculateNukeFactor(uint256 tokenId) public view returns (uint256) {
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );

    uint256 entropy = nftContract.getTokenEntropy(tokenId);
    uint256 adjustedAge = calculateAge(tokenId);

    uint256 initialNukeFactor = entropy / 40; // calculate initialNukeFactor based on entropy, 5 digits

@>    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;

    return finalNukeFactor;
  }
```

If we assume the NFT is 40 days old with max entropy of 999_999, the value of adjustedAge is 98_630, the `initialNukeFactor` is 24_999. Based on the obtained values, the `finalNukeFactor` will be 25_245. According to the specifications, this represents a little over 25%, which is far less than the expected ~50000 or 50%.

## Recommended Mitigation Steps

**Recommended Mitigation:**

1. Update the `defaultNukeFactorIncrease` value to 25_000.

Now, after changes suggested above the `finalNukeFactor` in case of the `Golden God` entropy (999_999) after 40 days is:
- `adjustedAge` = 98_630
- `initialNukeFactor` = 24_999
- `finalNukeFactor` = (98_630 * 25_000) / 100_000 + 24_999 = 24_657 + 24_999 = 49_656

So it matches the intended value of the `finalNukeFactor`.
