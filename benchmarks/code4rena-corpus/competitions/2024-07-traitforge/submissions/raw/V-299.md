# Vulnerability details

## Description
There is a bug in `NukeFund::receive` when the contract is receiving ETH. 10% of the funds goes to the Dev or Dao contract(tax cut) but there are scenarios where this might not be set which will essentially burn this value (as sending it to address(0)), which is unexpected and seems to warrant `Medium` severity. This would usually be High severity, but since this is fully controlled by the owner, severity is reduced. 

The root cause is due to the fact that `receive` is simply not checking if Dev contract or Dao contract has been set or not. So the contract could be deployed with empty contract or without calling `setDevAddress/setDaoAddress` or the owner could actually call these with address(0) and those would results in the problematics scenarios.

```solidity
  // Fallback function to receive ETH and update fund balance
  receive() external payable {
    uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
    uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund

    fund += remainingFund; // Update the fund balance

    if (!airdropContract.airdropStarted()) {
      (bool success, ) = devAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    } else if (!airdropContract.daoFundAllowed()) {
      (bool success, ) = payable(owner()).call{ value: devShare }('');
      require(success, 'ETH send failed');
    } else {
      (bool success, ) = daoAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    }

    emit FundReceived(msg.sender, msg.value); // Log the received funds
    emit FundBalanceUpdated(fund); // Update the fund balance
  }
```  

## Impact
Dev/Dao would incur a `fund loss` when nuke contract is receiving funds and those corresponding contract are not set as the dev cut (taxCut) will be `burned` instead of being sent to those contract.

## PoC
This is `very similar` to my other PoC issue `Forging when nuke contract is not set will cause the dev cut to be burned`, so the proof has been proven in that other issue, there is no difference here, the funds would be sent to address(0), so burned.

Manual review, Hardhat test
