# Vulnerability details

## Impact
In `TraitForgeNft.sol` ,`maxTokensPerGen` variable is responsible for not exceeding the max possible minted NFTs per generation. Its value is being set to `10_000` on deploying. When the current generation mint counts is equal or greater than `maxTokensPerGen` , [_incrementGeneration()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L349) function is being called to increment to the next generation and start counting the mints of the currentGeneration from `0`.

```solidity
function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;  <<@audit
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

When a user wants to forge a NFT it calls `EntityForging::forgeWithListed()` which calls `TraitForgeNft::forge()` which calls the internal `_mintNewEntity()`.
The important thing here in [forge()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L153-L179) is that for `newTokenId` = [_mintNewEntity()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L311-L343) we are passing the `incremented currentGeneration` which will be the new one after `generationMintCounts[currentGeneration]` >= `maxTokensPerGen` condition is met .

```solidity 
function forge(...) external whenNotPaused nonReentrant returns (uint256) {
    ....
    uint256 newGeneration = getTokenGeneration(parent1Id) + 1; <<<@
    ....

    // Mint the new entity
    uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);

    return newTokenId;
  }
```

```solidity
 function _mintNewEntity() private returns (uint256) {
    ....
    ....

    _tokenIds++;
    uint256 newTokenId = _tokenIds;
    _mint(newOwner, newTokenId);

    tokenCreationTimestamps[newTokenId] = block.timestamp;
    tokenEntropy[newTokenId] = entropy;
    tokenGenerations[newTokenId] = gen;
    generationMintCounts[gen]++;       <<<@audit
    initialOwners[newTokenId] = newOwner;

    ....
    ....

    emit NewEntityMinted(newOwner, newTokenId, gen, entropy);
    return newTokenId;
  }
```

In `_mintNewEntity()` the newly forged NFT is being minted in the next generation if it  doesn't exceed or is equal the `maxTokensPerGen` value which is `10_000`.
The problem is that if the forged NFT is minted in the next generation, and when  `generationMintCounts[currentGeneration]` >= `maxTokensPerGen` the `_incrementGeneration()` function will be called and it will set generationMintCounts[currentGeneration] to `0` when indeed we have minted the forged NFT and incremented `generationMintCounts` before that , making the minted NFTs of the currentGeneration being more than `maxTokensPerGen` which is breaking one of the main invariants of the protocol.
 
## Proof of Concept
Lets see the following example:
1. Current generation is `1`.

2. Alice forges a NFT and it will be saved in the mapping of `generationMintCounts[newGeneration]++;` which will be `generation = 2` with value of 1 minted NFT token because the forged NFT is saved in the nextGeneration.

3. Bob forges 2 NFTs and now generationMintCounts[newGeneration]++ will have a value of `3` ( We have 3 minted forged NFTs)

4. After certain time all of the `generation 1 `, ` 10_000 NFTs ` are minted,`_incrementGeneration()` will be called and the protocol will move to the next generation which is `generation = 2` and the mapping of the `generationMintCounts[currentGeneration]` will be set to `0` when we should have the three forged NFTs counted in.

5. Alice and Bob forged NFTs will not be counted for minted in currentGeneration = 2 ` because of setting the value to ` 0 ` in step 4 , later allowing the mapping to exceed the `maxTokensPerGen`

## Recommended Mitigation Steps
Remove the whole line of [generationMintCounts[currentGeneration]](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L351) in ` _incrementGeneration() ` since in case of no forged NFTs the value for the newGeneration in `generationMintCounts` mapping will be `0` anyway and in case there are forged NFTs saved it will continue from the last record.
