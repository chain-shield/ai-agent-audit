# Vulnerability details

## Impact
An approved party can cancel a listing despite the require statement

## Proof of Concept
After an NFT owner creates a listing to forge his NFT, he can decide to cancel the listing:
```solidity
function cancelListingForForging(
    uint256 tokenId
  ) external whenNotPaused nonReentrant {
    require(nftContract.ownerOf(tokenId) == msg.sender || msg.sender == address(nftContract), 'Caller must own the token');
    require(listings[listedTokenIds[tokenId]].isListed, 'Token not listed for forging');

    _cancelListingForForging(tokenId);
  }
```
We can see that only the owner of the NFT and the `nftContract` address are allowed to cancel the listing. However, if an address has been approved for that NFT, he can also cancel the listing despite the __require__ statement not allowing it. Whenever an NFT is transferred, we call the `_beforeTokenTransfer()` hook:
```solidity
  function _beforeTokenTransfer(
    address from,
    address to,
    uint256 firstTokenId,
    uint256 batchSize
  ) internal virtual override {
    super._beforeTokenTransfer(from, to, firstTokenId, batchSize);

    uint listedId = entityForgingContract.getListedTokenIds(firstTokenId);
    /// @dev don't update the transferred timestamp if from and to address are same
    if (from != to) {
      lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }

    if (listedId > 0) {
      IEntityForging.Listing memory listing = entityForgingContract.getListings(listedId);
      if (listing.tokenId == firstTokenId && listing.account == from && listing.isListed) {
        entityForgingContract.cancelListingForForging(firstTokenId);
      }
    }

    require(!paused(), 'ERC721Pausable: token transfer while paused');
  }
```
We can see that if there is a listing, it will get cancelled. The approved address can simply transfer the NFT using the owner address as both the `from` and `to` addresses and the listing will be cancelled.

While the approved address is trusted, it is only supposed to be trusted for certain actions. The code makes an NFT owner believe that the approved address will not be able to cancel his listings however that is bypassable, thus the approved address is allowed more stuff than he actually should be.
## Tools Used
Manual Review

## Recommended Mitigation Steps
Do not cancel the listing if the `from` is equal to the `to` address. Of course, the approved address would still be able to cancel the listing by transferring to someone else however that would be acceptable as he is doing a normal transfer and cancelling the listing is needed to avoid other types of bugs
