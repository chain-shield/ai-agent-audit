# Vulnerability details

## Details
- The protocol mentions to have limit on the generations for the NFT.
- When maximum NFTs are minted for a generation, the generation is incremented.
- As there is a maximum limit on the maximum generation that are possible, therefore if the generation exceed the maximum limit, the function call should fail.
- But no such check is implemented in `_incrementGeneration` function as a result of which there is no limit on generations, thus exceeding the max generation limit.

## Impact
No check in `_incrementGeneration` for the incremented generation to be in the max limit, allows generations to be more than what was expected.

## Proof of Concept
```
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
@>  currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
- This is the function which increments the current generation when maximum entities are minted for a generation, and it can be clearly seen that the `currentGeneration` is incremented without checking it with the `maxGeneration` limit
- Thus allowing generations to be more than the limit.

Manual Review

## Recommended Mitigation Steps
Check that the incremented `currentGeneration` doesn't exceed the `maxGeneration` limit.
```diff
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
+   require(currentGeneration <= maxGeneration, "Generation limit reached");
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
