# Vulnerability details

## Impact
Eth can get stuck on the DevFund. This happens when a dev with assigned reward doesnt claim and is removed from the DevFund

## Explanation
The DevFund allow devs to claim a portion proportional of their weight. Dev can only get rewards sent AFTER they are added.

If the following conditions are met then ETH can get stuck on the contract:

- dev is added
- dev has rewards that can be claimed
- dev is removed before claiming rewards

Since no devs can claim other devs rewards, no one can withdraw it. And since devs can only claim rewards that are created after they are added, adding the dev again wont work.

## Proof of Concept

Add this test at the end of [DevFund.test.ts](https://github.com/code-423n4/2024-07-traitforge/blob/main/test/DevFund.test.ts).

```typescript
  it('AUDIT: reward stuck when not claiming before removal', async () => {
    await devFund.addDev(user1, 100);
    await devFund.addDev(user2, 100);

    // user1 and 2 corresponds 0.5 ether
    await user3.sendTransaction({
      to: await devFund.getAddress(),
      value: ethers.parseEther('1'),
    });

    await devFund.removeDev(user2);

    //user1 has already claim everything he can
    await devFund.connect(user1).claim();
    const finalBal = await user1.provider.getBalance(devFund);

    //nobody else can claim since new added ppl can only claim next rewards
    expect(finalBal).to.be.eq(ethers.parseEther('0.5'));
  });
```

On that test, the only dev is user1, and he already claimed his reward. The user2 cannot claim since he was removed. Any other added dev cannot claim ether, thus the rewards are stuck.

## Tools Used
Manual review

## Recommended Mitigation Steps
When removing a dev, check if he has rewards claimable and transfer them to his address. Or also they can be redistributed into the contract by sending it again to the contract.
