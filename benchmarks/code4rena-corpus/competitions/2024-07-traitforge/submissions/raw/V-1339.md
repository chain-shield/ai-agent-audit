# Vulnerability details

## Vulnerability Details

The nuke functionality burn the Entity and send ether base on the nukeFactor of the Entity and the balance of the nuke fund, the problem is that the person that nukes their token first get's more reward than the next and subsequent persons to nuke their token.

This because the first person to nuke get a percent of the total nuke `fund`, that percentage is subtracted from the total nuke fund `fund -= claimAmount`, so for subsequent users the nuke fund reduces so they get less even with thesame or more nuke factor.


```sol
  function nuke(uint256 tokenId) public whenNotPaused nonReentrant {
    ...
    uint256 finalNukeFactor = calculateNukeFactor(tokenId); // finalNukeFactor has 5 digits
@->    uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR; // Calculate the potential claim amount based on the finalNukeFactor
    uint256 maxAllowedClaimAmount = fund / maxAllowedClaimDivisor; // Define a maximum allowed claim amount as 50% of the current fund size

    // Directly assign the value to claimAmount based on the condition, removing the redeclaration
@->    uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
      ? maxAllowedClaimAmount
      : potentialClaimAmount;

@->    fund -= claimAmount; // Deduct the claim amount from the fund
    ...
  }
```


## Proof of Concept

1. Bob and Alice both have a nuke factor of 20000
2. The current nuke fund balance is 100 ether
3. Bob nukes his token, he will claim 100 * 20000 / 100000 = 20 ether
4. The current nuke fund is now 100 - 20 = 80 ether
5. Alice nukes her token, she will get 80 * 20000 / 100000 =  16 ether

Alice got 4 ether less than Bob despite having the same nuke factor because Bob nuked first


## Impact

1. Loss of funds to subsequent nukers, which is unfair to them
2. This will encourage people to nuke on time thus making the game not enjoyable
