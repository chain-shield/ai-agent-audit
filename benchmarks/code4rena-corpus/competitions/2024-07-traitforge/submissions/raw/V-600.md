# Vulnerability details

## Impact
Due to the erroneous calculation of the golden god indices, there could be 0 golden gods in a generation.

## Proof of Concept
The entropySlots variable can contain a maximum of 770 * 13 = 10010 entropies(each 6 digit). This would mean that for the first generation the last 10 number indices (entropySlots[769] -> 3,4,..12) will remain unused. This corresponds to the last 60 digits in the entropySlots[769].
(https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L10)

Therefore in the initializeAlphaIndices() function, if the slotIndexSelection = 769, and the numberIndexSelection = [3,12]. The golden god wont be present in the first generation.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Make sure that in the initializeAlphaIndices() function, the slotIndexSelection = 769, and the numberIndexSelection = [3,12] never occurs. This can be done by adding this at line 213:
(https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L206-L216)

`uint256 slotIndexSelection = (hashValue % 258) + 512;`
`uint256 numberIndexSelection = hashValue % 13;`

`if(slotIndexSelection == 769 && numberIndexSelection >= 3)` // added check
`numberIndexSelection = hashValue % 3;`
`// rest of the function`
