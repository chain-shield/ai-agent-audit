# Vulnerability details

## Impact

`writeEntropyBatch` functions are not secured, and the values can be predictable. 

Pseudo-random values generated using block data can potentially be influenced by miners or validators, leading to predictability. An attacker with enough control over block mining or validation could manipulate the outcome, undermining the fairness and security of the system.

## Proof of Concept

The `EntropyGenerator` contract generate and manage pseudo-random values, referred to as "entropy," for use in other contracts. This contract features several functionalities, including generating entropy values in batches.

Here we have three `writeEntropyBatch` functions:
```solidity
  // Functions to initalize entropy values inbatches to spread gas cost over multiple transcations
  function writeEntropyBatch1() public {
    require(lastInitializedIndex < batchSize1, 'Batch 1 already initialized.');

    uint256 endIndex = lastInitializedIndex + batchSize1; // calculate the end index for the batch
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array
      }
    }
    lastInitializedIndex = endIndex;
  }

  // second batch initialization
  function writeEntropyBatch2() public {
    require(
      lastInitializedIndex >= batchSize1 && lastInitializedIndex < batchSize2,
      'Batch 2 not ready or already initialized.'
    );

    uint256 endIndex = lastInitializedIndex + batchSize1;
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = endIndex;
  }

  // allows setting a specific entropy slot with a value
  function writeEntropyBatch3() public {
    require(
      lastInitializedIndex >= batchSize2 && lastInitializedIndex < maxSlotIndex,
      'Batch 3 not ready or already completed.'
    );
    unchecked {
      for (uint256 i = lastInitializedIndex; i < maxSlotIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = maxSlotIndex;
  }
```

- **`writeEntropyBatch1`**: Initializes the first batch of entropy slots. This function uses block data and an index to generate pseudo-random values and store them in the `entropySlots` array.
- **`writeEntropyBatch2`**: Initializes the second batch of entropy slots, similar to the first batch but only after the first batch has been completed.
- **`writeEntropyBatch3`**: Finalizes the initialization of entropy slots, filling the remaining slots.

The current implementation uses `keccak256` and block data, which can be predicted or manipulated to some extent. This method provides pseudo-randomness but is not entirely secure against determined adversaries who can influence the block hash.

## Recommended Mitigation Steps

The current implementation of `writeEntropyBatch1` relies on a pseudo-random approach that can be improved by integrating Chainlink VRF. Using Chainlink VRF would provide stronger security guarantees and verifiable randomness, which is essential for maintaining trust and fairness in decentralized applications.
