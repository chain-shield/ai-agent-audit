# Vulnerability details

The initial limit for the number of generations that can exist is **10** which can be changed by calling the `setMaxGeneration()`.

However missing check when during generation increment allows to mint nfts beyond the desired threshold.

## Proof of Concept

The required check is present when nfts are minted through forging.

```solidity
File: TraitForgeNft.sol

       /// Check new generation is not over maxGeneration
166:   require(newGeneration <= maxGeneration, "can't be over max generation");
```

However when the nft is minted directly & all the generations have hit their maximum limit, the process still keeps on going by incrementing the generation count.

In the `_mintInternal()` we only find the check to see whether the mint count hits **maxTokensPerGen**

```solidity
File: TraitForgeNft.sol

  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
  ...
```
Inside `_incrementGeneration` there is no check for `maxGeneration` to stop the value of `currentGeneration` going over the limit.
 
```solidity

  function _incrementGeneration() private {

      generationMintCounts[currentGeneration] >= maxTokensPerGen,
```

## Impact
Nfts can be minted past the max generation limit
