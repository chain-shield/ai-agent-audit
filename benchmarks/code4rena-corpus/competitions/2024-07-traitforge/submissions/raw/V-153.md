# Vulnerability details

## Impact
**`nuke()`** is designed to burn an NFT in exchange for a share of the ETH in the fund. However, the issue is that when the token is minted, the **`lastTokenTransferredTimestamp`** mapping is not updated. This oversight allows users to instantly nuke the NFT without waiting the required 3-day maturity period.

## Proof of Concept
**`_mintInternal()`** is an internal function responsible for minting an NFT and recording all relevant data associated with it.
```Solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();

    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;

    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
    }

    emit Minted(
      msg.sender,
      newItemId,
      currentGeneration,
      entropyValue,
      mintPrice
    );

    _distributeFunds(mintPrice);
  }
```
As you can see, the **`lastTokenTransferredTimestamp`** mapping is not set anywhere in the code. This is problematic because the default value of a uint256 is 0. When a user attempts to nuke an NFT, the contract checks if the 3-day maturity period has passed; if it hasn't, the transaction should revert. **`nuke()`** calls **`canTokenBeNuked()`** to determine if the token can be burned. However, without the timestamp being set, this check can be bypassed.
```Solidity
unction canTokenBeNuked(uint256 tokenId) public view returns (bool) {
    // Ensure the token exists
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );
    uint256 tokenAgeInSeconds = block.timestamp -
      nftContract.getTokenLastTransferredTimestamp(tokenId); 
    // Assuming tokenAgeInSeconds is the age of the token since it's holding the nft, check if it's over minimum days held
    return tokenAgeInSeconds >= minimumDaysHeld;
  }
```
In this scenario, **`getTokenLastTransferredTimestamp()`** will return 0 because the timestamp is not set when the NFT is minted. As a result, **`tokenAgeInSeconds = block.timestamp - 0`**, causing the condition **`tokenAgeInSeconds >= minimumDaysHeld`** to evaluate as true. This allows users to nuke their NFT immediately after minting, bypassing the intended waiting period.

The documentation clearly states that there is a required maturity period of 3 days before an NFT can be nuked.
> The Nuke Fund accumulates ETH from new mints and economic activity. After a 3-day maturity period, anyone can nuke their entity (forever burn) to claim a share of the ETH in the Fund.

Copy the following POC into **`NukeFund.test.ts`** to observe the issue.
```Solidity
it('token can be nuked instantaneity', async function () {

    // Mint a token
    await nft.connect(user1).mintToken(merkleInfo.whitelist[1].proof, {
      value: ethers.parseEther('1'),
    });

    //token can be nuked instantaneity
    expect(await nukeFund.canTokenBeNuked(1)).to.be.true;
  });
```

## Recommended Mitigation Steps
To resolve the issue, modify **`_mintNewEntity()`** and **`_mintInternal()`** as outlined below.
```diff
unction _mintNewEntity(
    address newOwner,
    uint256 entropy,
    uint256 gen
  ) private returns (uint256) {
    require(
      generationMintCounts[gen] < maxTokensPerGen,
      'Exceeds maxTokensPerGen'
    );

    _tokenIds++;
    uint256 newTokenId = _tokenIds;
    _mint(newOwner, newTokenId);

    tokenCreationTimestamps[newTokenId] = block.timestamp;
    tokenEntropy[newTokenId] = entropy;
    tokenGenerations[newTokenId] = gen;
    generationMintCounts[gen]++;
    initialOwners[newTokenId] = newOwner;
+   lastTokenTransferredTimestamp [newTokenId] = block.timestamp;

    if (
      generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration
    ) {
      _incrementGeneration();
    }

    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(newOwner, entropy);
    }

    emit NewEntityMinted(newOwner, newTokenId, gen, entropy);
    return newTokenId;
  }
```
