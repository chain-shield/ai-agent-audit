# Vulnerability details

## Impact
The [initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206) function in the `EntropyGenerator` contract can cause the god NFT to be assigned an ID that exceeds the `maxTokensPerGen` limit of 10,000. This results in some generations not having a god NFT.

## Proof of Concept
The [initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206) function does not account for the fact that 770 slots with 13 storage spaces each can result in 10,010 possible positions. If `slotIndexSelection` is 769 and `numberIndexSelection` is between 4 and 12, the god NFT will have an ID greater than `maxTokensPerGen`.

```markdown
769 * 13 + 4 = 10_001
```

When users mint NFTs and the generation ID reaches 10,000, [_incrementGeneration](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L281-L283) will be triggered, moving to the next generation and setting new values for the god NFT, thereby skipping the current generation's god NFT.

```solidity
if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
    _incrementGeneration();
}
```

Since users can control when [initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355) is called by choosing when to mint the new gen first NFT and can predict the "randomness", a malicious user could set up a generation without a god NFT.

## Tools Used
Manual review

## Recommended Mitigation Steps
Limit `slotIndexSelection` to 1 less, ensuring the god NFT ID stays between 6656 and 9997.

```diff
   uint256 hashValue = uint256(keccak(abi.encodePacked(blockhash(block.number - 1), block.timestamp)));
-  uint256 slotIndexSelection = (hashValue % 258) + 512;
+  uint256 slotIndexSelection = (hashValue % 257) + 512;
   uint256 numberIndexSelection = hashValue % 13;
```
