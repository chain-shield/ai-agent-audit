# Vulnerability details

**Description**

As per the [documentation](), the final generation should be 10th. But in the [TraitForgeNft::_incrementGeneration](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345), which is called by [TraitForgeNft::_mintInternal()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L280) there is no check if the final generation is reached. Thus allowing for infinite generations to be created.

**Impact**

More than 10 generations can be created, allowing users to mint more NFTs than specified in the documentation.

**Proof of Concepts**

For simplicity of the PoC, a new setter have been added to the `TraitForgeNft`:

```javascript
function setMaxTokensPerGen(uint256 maxTokensPerGen_) external onlyOwner {
    maxTokensPerGen = maxTokensPerGen_;
}
```

```javascript
it('should allow infinite increase of generations', async () => {
  const maxTokensPerGen = 10;
  const expectedMaxGen = 10;

  let currentGen = await nft.currentGeneration();

  // Set max tokens per generation for simplicity
  await nft.setMaxTokensPerGen(maxTokensPerGen);

  // Mint all possible NFTs
  for (let i = 0; i < expectedMaxGen * maxTokensPerGen; i++) {
    await nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, {
      value: ethers.parseEther('1'),
    });
  }

  currentGen = await nft.currentGeneration();
  expect(currentGen).to.be.eq(expectedMaxGen);

  // Mint one more NFT
  expect(await nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, {
    value: ethers.parseEther('1'),
  })).not.to.be.reverted;

  currentGen = await nft.currentGeneration();
  expect(currentGen).to.be.eq(expectedMaxGen + 1);
});
```
