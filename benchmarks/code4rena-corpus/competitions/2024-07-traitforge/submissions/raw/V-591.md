# Vulnerability details

## Impact

In the current implementation of `TraitForgeNft`, users are able to directly mint entities via `mintToken()` and `mintWithBudget()` and by forging two tokenIds (merger's and forger's). So when it's a direct minting, the `generationMintCounts` is increased for current generation. And if the max tokens per generation state is reached, it's incremented to the next generation. In comparison, with forging, the tokenId of the new entity is in the next generation. The problem is that when we update the generation with direct minting via `_incrementGeneration()`, `generationMintCounts` is nullified and it does not account for already existing entities resulted from forging.

## Proof of Concept

Take a look at this part of `_mintInternal()` and `incrementGeneration()`:


https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-283
```
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L345-351
```
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
```

In comparison, when user wants to forge and create a new entity via it, `generationMintCounts` is incremented for the next generation:


https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L328
```
generationMintCounts[gen]++;
```

So imagine there are already new entities that are derived from forging in the new generation. The `generationMintCounts` is correctly increased for them the first time. But when the generation is changed through direct minting, the variable is simply nullified and it reflects the incorrect value. This would put the contract in an unexpected state where the number of the variable does not correspond to reality.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Check for already existing tokens from forging when updating generation in `_incrementGeneration()`.
