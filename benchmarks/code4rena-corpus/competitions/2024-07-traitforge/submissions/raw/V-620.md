# Vulnerability details

## Description
The `receive()` function in the NukeFund contract uses integer division to calculate the developer's share of incoming funds. This can lead to rounding errors, potentially causing slight discrepancies in fund distribution over time. These small discrepancies could accumulate and result in a non-trivial difference between intended and actual fund allocation.

## Impact
1. Slight underpayment to the developer for most transactions.
2. Over time, these rounding errors could accumulate, leading to a noticeable discrepancy between intended and actual fund allocation.
3. In rare cases where `msg.value < taxCut`, the developer would receive nothing, contradicting the intended behavior.

## Proof of Concept

[Link to code](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L40-L44)

```
receive() external payable {
    uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
    uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund

    fund += remainingFund; // Update the fund balance

    // ... (rest of the function)
}
```

Consider a scenario where:
1. taxCut = 10 (meaning 10% should go to the developer)
2. msg.value = 101 wei

The calculation would be:
devShare = 101 / 10 = 10 wei
remainingFund = 101 - 10 = 91 wei

In this case, the developer receives 9.9% instead of 10%, and the fund receives 90.1% instead of 90%.

## Recommended Mitigation Steps

1. Use percentage-based calculations instead of integer division:
```
receive() external payable {
    uint256 devShare = (msg.value * taxCut) / 100; // Calculate developer's share (taxCut%)
    uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund

    fund += remainingFund; // Update the fund balance

    // ... (rest of the function)
}
```

2. Consider using a fixed-point arithmetic library for more precise calculations:

```
import "@openzeppelin/contracts/utils/math/SafeMath.sol";

contract NukeFund is INukeFund, ReentrancyGuard, Ownable, Pausable {
    using SafeMath for uint256;

    // ... (rest of the contract)

    receive() external payable {
        uint256 devShare = msg.value.mul(taxCut).div(100); // Calculate developer's share (taxCut%)
        uint256 remainingFund = msg.value.sub(devShare); // Calculate remaining funds to add to the fund

        fund = fund.add(remainingFund); // Update the fund balance

        // ... (rest of the function)
    }
}
```

3. Implement a minimum transaction value to ensure the developer always receives a share:

```
receive() external payable {
    require(msg.value >= taxCut, "Transaction value too low");
    // ... (rest of the function)
}
```

4. Consider accumulating small remainders and distributing them when they reach a significant amount:

```
uint256 public devShareRemainder;

receive() external payable {
    uint256 devShare = (msg.value * taxCut) / 100;
    devShareRemainder += (msg.value * taxCut) % 100;
    
    if (devShareRemainder >= 100) {
        devShare += devShareRemainder / 100;
        devShareRemainder = devShareRemainder % 100;
    }

    uint256 remainingFund = msg.value - devShare;
    fund += remainingFund;

    // ... (rest of the function)
}
```
