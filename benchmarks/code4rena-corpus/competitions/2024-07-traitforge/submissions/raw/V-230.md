# Vulnerability details

## Impact
The bug prevents the contract from reaching its intended maximum token supply for each generation. Users will always be unable to mint the last token of each generation.

## Proof of Concept
There is a critical bug in the mintWithBudget function that prevents users from minting the maximum number of tokens allowed per generation (maxTokensPerGen). The issue lies in the condition of the while loop that controls the minting process.

```
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
    // Minting logic
}
```

The condition _tokenIds < maxTokensPerGen incorrectly limits the minting process. This check ensures that the total number of tokens minted across all users is less than maxTokensPerGen. However, this prevents the last token from being minted when _tokenIds equals maxTokensPerGen - 1.

For example, if maxTokensPerGen is set to 1000, the loop will stop when _tokenIds reaches 999, making it impossible to mint the 1000th token.

## Tools Used
Manual review

## Recommended Mitigation Steps
To resolve this issue, the condition should be changed to allow minting when _tokenIds is less than or equal to maxTokensPerGen. The corrected while loop condition should be:

while (budgetLeft >= mintPrice && _tokenIds <= maxTokensPerGen) {
    // Minting logic
}
