# Vulnerability details

## Impact
The remaining amount of ETH is lost in the contract, since the contract doesn't even have an function implemented to retrieve the excess amount of ETH sent by merger while calling the afore mentioned function. 

## Proof of Concept
https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L126-L158 

The function calculates the devFee (10% of the forgingFee) and the remaining amount to be send to the forge (forgerShare) using the `Listing.fee` value. So in that case, the `msg.value - Listing.fee` will be lost.

## Tools Used
Manual Analysis

## Recommended Mitigation Steps
1. This can be mitigated by implementing a mapping from `forgerAddress` to the `excessAmountClaimable` by each. With a function implemented to follow *pull over push funds model*, to retrieve their excess ETH.

(OR)

2. Modify the `require()` statement in the following way:
```diff
- require(msg.value >= forgingFee, 'Insufficient fee for forging');
+ require(msg.value == forgingFee, 'Incorrect fee for forging');
```
 
(OR)

3. Implement a function allowing the `owner()` to retrieve the excess balance lying in the contract due to such scenarios, at least the funds doesn't get lost in the contract forever.
