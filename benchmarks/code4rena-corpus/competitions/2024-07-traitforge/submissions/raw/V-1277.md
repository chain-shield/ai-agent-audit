# Vulnerability details

In the `EntropyGenerator` contract, the `initializeAlphaIndices` function is responsible for selecting index points for the special 6-digit entropy number of 999999. This function is called during the contract’s construction and is triggered again once the current NFT generation is fully minted, transitioning to the next generation.

It is currently protected by an `onlyOwner` access modifier, which restricts its calling only to the owner of the `EntropyGenerator` contract.

`EntropyGenerator::initializeAlphaIndices`
```solidity
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512; 
    uint256 numberIndexSelection = hashValue % 13; 

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection; 
  }
```
However, the `initializeAlphaIndices` function is also being called from the `TraitForgeNft` contract inside the `_incrementGeneration` function, whenever a user wants to mint a new NFT and the `generationMintCounts` for the current generation is greater than `maxTokensPerGen`. This external call from `TraitForgeNft` will always revert due to the `onlyOwner` modifier restricting the caller of the `initializeAlphaIndices` to the deployer of the `EntropyGenerator` contract.

`TraitForgeNft::_incrementGeneration`
```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
@>  entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

## Impact
The current design leads to a critical issue where the transition to a new NFT generation in the `TraitForgeNft` contract will always fail. This failure occurs because the `initializeAlphaIndices` function in the `EntropyGenerator` contract can only be called by the contract owner, due to the `onlyOwner` modifier. As a result, the `_incrementGeneration` function in `TraitForgeNft` will revert, blocking the progression to the next NFT generation.

## Proof of Concept
1. A user calls the `mintToken` function in the `TraitForgeNft` contract, which internally invokes `_mintInternal` to handle the minting process.
```solidity
        function mintToken(
          bytes32[] calldata proof
        )
          public
          payable
          whenNotPaused
          nonReentrant
          onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
        {
          uint256 mintPrice = calculateMintPrice();
          require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

  @>    _mintInternal(msg.sender, mintPrice);

          uint256 excessPayment = msg.value - mintPrice;
          if (excessPayment > 0) {
            (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
            require(refundSuccess, 'Refund of excess payment failed.');
          }
        }
```

2. The `_mintInternal` function checks if the current generation has reached its minting limit (`maxTokensPerGen`, set to 10,000 NFTs) and, if so, calls `_incrementGeneration` to transition to the next generation.

```solidity
        function _mintInternal(address to, uint256 mintPrice) internal {
          if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
  @>    _incrementGeneration();
          }
                ...
        }
```

3. The `_incrementGeneration` transitions to the next generation and calls `entropyGenerator::initializeAlphaIndices` to initialize new index points for the new generation.
```solidity
        function _incrementGeneration() private {
          require(
            generationMintCounts[currentGeneration] >= maxTokensPerGen,
            'Generation limit not yet reached'
          );
          currentGeneration++;
          generationMintCounts[currentGeneration] = 0;
          priceIncrement = priceIncrement + priceIncrementByGen;
  @>    entropyGenerator.initializeAlphaIndices();
          emit GenerationIncremented(currentGeneration);
        }
```
4. However, the `initializeAlphaIndices` function is restricted by the `onlyOwner` modifier, allowing only the deployer of the `EntropyGenerator` contract to call it. This restriction causes the transaction to revert, preventing the transition to the next generation.

## Recommended Mitigation Steps
In addition to the `onlyOwner` access modifier, consider adding the `onlyAllowedCaller` modifier to the `initializeAlphaIndices` function to authorize calls from specific contracts like `TraitForgeNft`.

```solidity
  modifier onlyAllowedCaller() {
    require(msg.sender == allowedCaller, 'Caller is not allowed'); 
    _;
  }
```

- function initializeAlphaIndices() public whenNotPaused onlyOwner {
