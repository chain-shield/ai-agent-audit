# Vulnerability details

## Impact
Function `mintWithBudget()` in `TraitForgeNft.sol` is supposed to mint as many NFTs as possible for provided amount of Ether (`msg.value`) and to refund the change to the user. However inside the `while` loop there is a following condition: `(budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen)` that checks the remaining budget against the current `mintPrice`, but it also checks if the `_tokenIds` is smaller than `maxTokensPerGen`. The storage variable `maxTokensPerGen` is set to 10,000 and is never changed. Furthermore, the storage variable `_tokenIds` is set to 0 in the beginning and it keeps getting incremented during mint and forge actions (it is never resetted). This means that after a 10,000 NFTs are minted, users will not be able to call `mintWithBudget()` function anymoe since the condition inside the loop will not be satisfied. 

## Proof of Concept
In order to skip the mint of 10,000 NFTs, a setter method for `_tokenIds` inside `TraitForgeNft.sol` is created

```
function setTokenId (uint256 tokenId) external {
    _tokenIds = tokenId;
  }
```

Add this test to `TraitForgeNft.test.sol`

```
it('should be possible to mintWithBudget after 10,000 minted nfts', async() => {
      fastForward(24 * 60 * 60 + 1);
      const mintPrice = await nft.calculateMintPrice();
      console.log("Mint price: ", await ethers.formatEther(mintPrice));
      const user2_balance_before = await nft.balanceOf(user2.address);
      console.log("User 2 nft balance before mint: ", user2_balance_before);

      // set tokenIds to 10,000
      await nft.setTokenId(10000);
      await nft.connect(user2).mintWithBudget(merkleInfo.whitelist[1].proof, {
        value: ethers.parseEther('1'),
      });

      // no nft minted because tokenIds == maxTokensPerGen (10,000)
      expect(await nft.balanceOf(user2.address)).not.to.be.eq(user2_balance_before);
    });
```

## Recommended Mitigation Steps
The two recommendations can be made based on different assumptions what the client wanted to achieve: 

1. If you want to limit one user from minting more than 10,000 NFTs at once, than you need to replace `_tokenIds` with `amountMinted`, and thus having the following condition `while (budgetLeft >= mintPrice && amountMinted < maxTokensPerGen)` in place instead of the current one.

2. Remove the check `_tokenIds < maxTokensPerGen` from the while loop completely, since the generation check and increment is already implemented as part of the `mintInternal()` function.
