# Vulnerability details

## Impact
Incorrect updation of `forgingCounts` leads to entities being allowed to forge more than intended.

## Proof of Concept
Assume a forger entity (with forgingPotential = 1) lists for forging.

1. Here line 87 (https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L87-L90) check passes since, `forgingCounts[tokenId] <= forgePotential` (0 <= 1)

2. When a merger entity decides to forge with this entity by calling the forgeWithListed() function : forgingCounts is incremented without any further checks. (https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L133)

3. Again the same token lists for forging and at line 87 the check still passes:
`forgingCounts[tokenId] <= forgePotential` (1 <= 1)

4. When a merger entity decides to forge with it again, the forgingCounts is incremented and no check is done here.

Thus allowing the forger to forge 2 times with a forgePotential of just 1.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Modify line 87 as follows:
`require(
      forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
      'Entity has reached its forging limit'
    );`
