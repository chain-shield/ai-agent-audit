# Vulnerability details

The owner can set maxAllowedClaimDivisor to 1 and nukeFactorMaxParam to 1, ensuring that the condition finalNukeFactor > nukeFactorMaxParam is always true.
This forces the claimAmount to always be the maxAllowedClaimAmount, which will be equal to the fund size due to change in `maxAllowedClaimDivisor`, effectively allowing the owner to claim the funds.
The owner can drain the funds from the protocol under the guise of legitimate claims, leading to a rug-pull scenario. 

On the contrary to this, owner can set above mentioned values to a bit on a higher end & this transaction gets executed before the Nuke function call via token Owner's, leading to unexpectedly less Nuke fund for the token Owner's
Giving the owner this much control over critical parameters without adequate checks and balances exposes the protocol to significant risks of abuse

Impact
- Rug pull situation
- Permanent Loss of funds from NukeFund contract
-
Tools Used
- Manual Review

Recommended Mitigation Steps
- Implement multi-signature governance for changing critical parameters like maxAllowedClaimDivisor and nukeFactorMaxParam.
```diff
 function setMaxAllowedClaimDivisor(uint256 value) external onlyOwner {
 + require(_divisor > 1, "Divisor must be greater than 1");
    maxAllowedClaimDivisor = value;
  }

  function setNukeFactorMaxParam(uint256 value) external onlyOwner {
  +  require(_param < MAX_DENOMINATOR, "Param must be less than MAX_DENOMINATOR");
    nukeFactorMaxParam = value;
  }
```
