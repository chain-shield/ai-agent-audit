# Vulnerability details

## Vulnerability Details

Entities have unique characteristics based on their entropy when they are minted, this entropy is based on pseudo-random numbers that are generated on-chain the `entropyGenerator.getNextEntropy()` function generates the entropy. The problem is that the blockchain is a deterministic environment and the entropy can be predicted before the Entity is minted.

The generated entropy is based on `currentSlotIndex` and `currentNumberIndex` though these variables are private they can be read directly from the blockchain.

```sol
uint256 private currentSlotIndex = 0;
uint256 private currentNumberIndex = 0;
```

Using the `deriveTokenParameters()` function a user can easily get the traits of the Entity they want and if it is not desirable they won't simply mint the Entity. If this becomes common knowledge people will be reluctant to mint Entities when they know that it doesn't have the desired traits that they want.

## Proof of Concepts

  it('POC entropy', async function () {

    await entropyGenerator.writeEntropyBatch1();

## Impact

1. Because entropy is not truly random users will know the properties of the token before minting them.
2. A user who is looking for a forger will knowingly wait for two other people to mint before they will mint to get the forger token.
3. Since some Entities have traits that are more desirable than others it will lead to users not willing to mint the less desirable Entity. Making the protocol to be unused.

## Recommendation

Because the blockchain is deterministic, randomness cannot be generated on-chain, but services like Chainlink and Gelato provide VRF (Verified Random Function) that can be generated through randomness on-chain.

The following are two approaches that I recommend.

1. When someone mints a new Entity the Gelato VRF should determine the entropy. This might be more expensive since users have to pay for the cost of randomness with each Entity mint.
2. Batch the minting of Entities so whenever a user mints an Entity it gets sent to a queue that can be called by a keeper that delivers the random numbers from a VRF provider. So, the minting of entities can be done every 1 to 24hrs.
