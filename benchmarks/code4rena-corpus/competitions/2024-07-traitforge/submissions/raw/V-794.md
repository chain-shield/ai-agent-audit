# Vulnerability details

## Impact
The contract currently uses `_tokenIds`, a global counter, to compare with `maxTokensPerGen`, which is intended to limit the number of tokens per generation. This leads to incorrect logic as `_tokenIds` always increases and does not reset with each new generation. This causes the comparison to fail after the first generation, preventing proper generation management and minting.
## Proof of Concept
In the mintWithBudget function:
```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {  // Incorrect
```
The comparison should instead track the number of tokens minted in the current generation to ensure proper functionality.

Manual code review
## Recommended Mitigation Steps
```diff
-    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
+    while (budgetLeft >= mintPrice && generationMintCounts[currentGeneration] < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```
