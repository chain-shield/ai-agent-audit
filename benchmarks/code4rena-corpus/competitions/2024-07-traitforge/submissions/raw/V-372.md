# Vulnerability details

## Impact
Users can abuse the code and benefit from a lower wait time until their forging count is reset

## Proof of Concept
Users can list their NFT for forging using `listForForging()`. There, we have the following function call:
```solidity
_resetForgingCountIfNeeded(tokenId);
```
Which calls this:
```solidity
  function _resetForgingCountIfNeeded(uint256 tokenId) private {
    uint256 oneYear = oneYearInDays;
    if (lastForgeResetTimestamp[tokenId] == 0) {
      lastForgeResetTimestamp[tokenId] = block.timestamp;
    } else if (block.timestamp >= lastForgeResetTimestamp[tokenId] + oneYear) { 
      forgingCounts[tokenId] = 0; // Reset to the forge potential
      lastForgeResetTimestamp[tokenId] = block.timestamp;
    }
  }
```
If the user has set his NFT for forging for the first time, we set the `lastForgeResetTimestamp` to the current `block.timestamp`. Then, when a year after that point passes, the forging counts will reset to 0 which allows the user to continue forging his NFTs and receive fees for that (each forger NFT has a forging potential which limits the amount of forges we can do).

Since the forging does not actually occur upon someone creating a listing, the following can happen:
1. Bob does not want to forge his NFTs yet but will want to do so in the future
2. He decides to abuse the code by creating a listing for his NFT and immediately cancelling it
3. Now, the one year timer has successfully started running
4. Whenever Bob decides he wants to actually forge his NFTs, he will be able to reset his forging counts a lot sooner as he initialized `lastForgeResetTimestamp` at a lot earlier point of time

While calling `_resetForgingCountIfNeeded()` is needed to reset the forging counts for users that have already waited a year, it should not actually start the one year timer (or in other words initializing `lastForgeResetTimestamp`) for users who have only listed their NFT as they can immediately cancel afterwards. ` lastForgeResetTimestamp` should only be initialized when the actual forging occurs. This puts users with knowledge of this trick at a big advantage over others that are not aware.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Include a boolean input value called `shouldStartTimer` (for example) in `_resetForgingCountIfNeeded()` and only put it as true when an actual forging occurs. If that value is set to true, initialize `lastForgeResetTimestamp`, otherwise do not.
