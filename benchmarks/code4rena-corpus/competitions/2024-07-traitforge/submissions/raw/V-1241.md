# Vulnerability details

## Impact
The `TraitForgeNft` contract has an owner accessible function `setMaxGeneration` that can be used to set the maximum allowed generation of NFTs.

However, this function does not take into account the NFTs minted via the forging process. The current implementation only considers the `currentGeneration` when setting the maximum generation, which means entities generated via forging (which can increase their generation beyond `currentGeneration`) are not properly constrained by this limit.

The current validation:

```javascript
function setMaxGeneration(uint maxGeneration_) external onlyOwner {
    require(maxGeneration_ >= currentGeneration, "can't be below current generation");
    maxGeneration = maxGeneration_;
}
```

This incomplete validation leads to situations where NFTs with generations exceeding the intended maximum exist. This would violate the design constraints and could potentially allow for an unfair distribution of powerful entities or unbalance the game mechanics.

## Recommended Mitigation Steps

To ensure that the maximum generation limit is correctly enforced, the contract should also consider the highest generation that is reached through forging.

Here is an example of how the check can be improved:

```javascript
function setMaxGeneration(uint maxGeneration_) external onlyOwner {
    uint256 highestGeneration = currentGeneration;
    for (uint256 i = currentGeneration; i <= maxGeneration; i++) {
        if (generationMintCounts[i] > 0) {
            highestGeneration = i;
        }
    }
    require(maxGeneration_ >= highestGeneration, "can't be below highest existing generation");
    maxGeneration = maxGeneration_;
}
```
This ensures that the maximum generation cannot be set below the highest generation of any existing NFT, including those produced via forging.
