# Vulnerability details

## Impact
The refund mechanism in the `mintToken` and `mintWithBudget` functions, which sends excess funds back to the `msg.sender`, can be exploited by malicious users. Specifically, users can intentionally trigger the `refund` process and revert the transaction within the `receive/fallback` function if the generated entropy does not meet their desired criteria. This creates an unfair advantage and can be used to manipulate the minting process.

## Proof of Concept
The refund mechanism in the `mintToken` and `mintWithBudget` functions sends excess funds back to `msg.sender`:

```solidity
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
```

A malicious user can exploit this mechanism by:
1. Deploying a contract.
2. Calling `mintToken` or `mintWithBudget` through the contract, sending slightly more than the `mintPrice` to trigger the refund.
3. In the `receive/fallback` function of their contract, checking the generated entropy.
4. Reverting the transaction if the entropy is not favorable.

This allows the user to repeatedly attempt minting until they achieve the desired entropy, giving them an unfair advantage.
## Tools Used

Manual

## Recommended Mitigation Steps

Ensure that only externally owned accounts (EOAs) can call the minting functions and receive refunds. This can be done by `require(tx.origin == msg.sender, "Caller must be an EOA");`
