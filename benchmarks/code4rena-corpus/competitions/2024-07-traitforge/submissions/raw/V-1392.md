# Vulnerability details

## Impact
There is no limit set for weight that can be assigned to a dev user. This can lead to unfair distribution weight where an owner is biased, thereby causing a dev claiming most of the eth claimable in the DevFund contract

For fairness in eth distribution for dev claims, a fixed limit for weight should be set for which weights assigned to a dev would be within the limit predetermined.

## Proof of Concept
The hardhat test PoC below depicts the situation where a dev is assigned an extremely high weight than others

```
import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';
import { expect } from 'chai';
import { ethers } from 'hardhat';
import { DevFund } from '../typechain-types';

describe('DevFund', function () {
  let owner: HardhatEthersSigner;
  let user1: HardhatEthersSigner;
  let user2: HardhatEthersSigner;
  let user3: HardhatEthersSigner;
  let user4: HardhatEthersSigner;
  let devFund: DevFund;

  before(async () => {
    [owner, user1, user2, user3, user4] = await ethers.getSigners();

    devFund = await ethers.deployContract('DevFund');
  });

  

  it('add dev with really high weight', async () => {
    await devFund.addDev(user2.address, 5);
    await devFund.addDev(user3.address, 1);
    await devFund.addDev(user4.address, 1000000);

    const prevBalance = await ethers.provider.getBalance(owner.address);
    await user1.sendTransaction({
      to: await devFund.getAddress(),
      value: '1000000000000000000',
    });


    expect(await devFund.pendingRewards(user2.address)).to.eq('4999970000175');
    expect(await devFund.pendingRewards(user3.address)).to.eq('999994000035');
    expect(await devFund.pendingRewards(user4.address)).to.eq('999994000035000000');
  });
});
```

## Recommended Mitigation Steps
Add a state variable for weight limit and always check the `weight` parameter in `addDev()` and `updateDev()` falls within the weight limit
