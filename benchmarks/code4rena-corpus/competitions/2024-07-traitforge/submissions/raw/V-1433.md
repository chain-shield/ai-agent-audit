# Vulnerability details

## Impact
The contract allows resetting of the forge potential (limit) arbitrarily within its `forgeWithListed` function. This can lead to potential abuse of the system.

The `_resetForgingCountIfNeeded` function is intended to reset a NFT's forge potential if a year has passed since the last reset. However, this function is called in the `listForForging` and `forgeWithListed` functions for both the forger token and merger token. 

This can lead to an unintended resetting of the forge potential if these functions are called within the `forgeWithListed` function.

## Proof of Concept

Here is a code snippet from the `forgeWithListed` function where it calls the `_resetForgingCountIfNeeded` function:

```solidity
_resetForgingCountIfNeeded(forgerTokenId); // Reset for forger if needed
_resetForgingCountIfNeeded(mergerTokenId); // Reset for merger if needed
```

And here is the `_resetForgingCountIfNeeded` function itself:

```solidity
function _resetForgingCountIfNeeded(uint256 tokenId) private {
    uint256 oneYear = oneYearInDays;
    if (lastForgeResetTimestamp[tokenId] == 0) {
        lastForgeResetTimestamp[tokenId] = block.timestamp;
    } else if (block.timestamp >= lastForgeResetTimestamp[tokenId] + oneYear) {
        forgingCounts[tokenId] = 0; // Reset to the forge potential
        lastForgeResetTimestamp[tokenId] = block.timestamp;
    }
}
```

## Recommended Mitigation Steps

To prevent unintended resetting of the forge potential, the call to `_resetForgingCountIfNeeded` in the `forgeWithListed` function could be removed or carefully controlled. Analyse the code and decide the suitable function that needs the call to `_resetForgingCountIfNeeded`. 
As a suggestion, it can be best to reset the forge potential when owners list their tokens for forging by using the `listForForging` method.
