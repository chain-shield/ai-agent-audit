# Vulnerability details

## Vulnerability Details

According the documentation, there will be 10 generation at max and 10000 entities for each generation

```solidity
  uint256 public maxGeneration = 10;
```
While minting operation, if it reachs max entity for generation limit, it increments the generation and continue from that point.

```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
The problem arise in this implementation because this function doesn't check the current generation whether passed the limit or not.

## Impact
Wrong main functionality

## Proof of Concept

Player will call mintToken() in order to mint a new entity while current generation is 10 and generation mint count was 10000. 

```solidity
function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
```

After checking the price part it will call _mintInternal function

```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

Now this if statement will be trigered and it will increment the generation to 11.
