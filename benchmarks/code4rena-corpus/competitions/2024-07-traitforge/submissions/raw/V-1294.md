# Vulnerability details

## Impact
An argument can be made that the current implementation of the `EntityTrading` contract, which does not allow for listing update is a inefficient way to handle a marketplace for nfts, this oversight can make users loose funds and sell nft at lower price than they should, some reasons are below 
- The capacity of a entity increases everyday, with more maturity and performance factor results into higher nuke factor, and also the ability to earn more from the nukeFund, Hence the higher the value of the entity 
- A whole marketplace can form from the trading platform, where prices being sold by other users may be more and a user might be selling their entity at a loss

## Proof of Concept
The Main point here is to create a function that updates the price and status of the entity being sold, `EntityTrading` already has a way to list and buy and cancel,

```solidity
function listNFTForSale(
    uint256 tokenId,
    uint256 price
  ) public whenNotPaused nonReentrant {
``` 
```solidity
 function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {
``` 
```solidity
  function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant {
``` 
But we can both agree that to cancel and relist is a more inefficient system and slower than a simple updateListing function, that updates the price,

Clarification: This cost loss of funds in both value/price and gas used for canceling and relisting, hereby the medium assigned severity

## Recommended Mitigation Steps
An example of a updateListing the protocol can consider to use 
```solidity
 function updateListing(uint256 tokenId, uint256 newPrice) public whenNotPaused nonReentrant {
    Listing storage listing = listings[listedTokenIds[tokenId]];

    // check if caller is the seller and listing is active
    require(listing.seller == msg.sender, 'Only the seller can update the 
    listing.');
    require(listing.isActive, 'Listing is not active.');
    require(newPrice > 0, 'Price must be greater than zero.');

    // Update the price and the listing timestamp
    listing.price = newPrice;
    listing.listingTimestamp = block.timestamp;
    //adding a time based potential system with a timestamp here to the listing 
    struct would protect the buyer from the seller frontrunning them, this should 
    be set when listing and checked when buying to prevent frontrunning. This 
    would involve setting a minimum interval that must pass before a purchase can 
    be made after a listing update.

    emit NFTListed(tokenId, msg.sender, newPrice);
  }
```
