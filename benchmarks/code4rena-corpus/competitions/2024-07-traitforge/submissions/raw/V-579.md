# Vulnerability details

## Impact

`mintWithBudget` is intended to mint tokens in bulk based on a given budget. The function should mint tokens independently of the number of tokens minted so far. Tokens can be minted either directly via the `mintToken` function or through breeding. However, once the total number of minted tokens reaches 10,000, the `mintWithBudget` function will no longer mint new tokens. Instead, it will use the allocated gas for execution and return the budget amount as-is without minting any additional tokens.

```solidity
  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    // @> after 10_000 mints the while loop condition is no longer satisfied.
    // The condition '_tokenIds < maxTokensPerGen' always returns 'false'.
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```

## Proof of Concept

Add the following test to `TraitForgeNft.test.ts`:

In the test below, `user2` mints 10,000 tokens using the `mintToken` function (a similar result could be achieved by minting some tokens and breeding some others until reaching 10,000 minted tokens). After that, the `mintPrice` for the next token is calculated, and `user2` calls `mintWithBudget` with the calculated `mintPrice`. As a result, we would expect `user2` to own 10,001 tokens, which is not the case.


Notice: To run this test, I'm temporarily removing the `onlyOwner` modifier from `EntropyGenerator::initializeAlphaIndices` because it otherwise reverts due to a lack of access control, which is a separate issue.
 
```
  describe('mintWithBudget', () => {
    it('stops minting once the first 10_000 tokens have been minted', async () => {
      fastForward(24 * 60 * 60 + 1);

      // Mint 10_000 tokens in batches of 1_000 tokens
      const batchSize = 1_000;
      const batchCount = 10;
      const batch = new Array(batchSize).fill(0);
      const proof = merkleInfo.whitelist[1].proof;

      for (let b = 0; b < batchCount; b++) {
        const promises = batch.map(() =>
          nft.connect(user2).mintToken(proof, {
            value: ethers.parseEther('1'),
          })
        );

        await Promise.all(promises);
        console.log({ tokensMinted: (b + 1) * batchSize });
      }

      // Expect the user to own 10_000 tokens
      expect(await nft.balanceOf(user2.address)).to.be.eq(
        batchCount * batchSize
      );

      // Calculate the mint price for the next token
      const mintPrice = await nft.calculateMintPrice();
      console.log({ mintPrice: ethers.formatUnits(mintPrice) });

      // We would expect to be able to mint exactly one extra token via budget
      // but this is not the case. The function completes but doesn't mint
      // any new tokens.
      await nft.connect(user2).mintWithBudget(proof, {
        value: mintPrice,
      });

      // The user still owns 10_000 tokens
      expect(await nft.balanceOf(user2.address)).to.be.eq(
        batchCount * batchSize
      );
    });
  });
```
