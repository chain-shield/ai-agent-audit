# Vulnerability details

## Impact
Minting functions after 10,000 mints func calls `TraitForgeNft.sol:_incrementGeneration()` -> `EntropyGenerator.initializeAlphaIndices()` which have modifier `onlyOwner`.
But caller is TraitForgeNft address.

## Proof of Concept
Add to TraitForgeNft.test.ts:
```javascript
    it('try to increment generation after 10,000 minted NFT', async () => {
      // mint 10k nft to make _tokenIds == 10,000.
      for (let i = 0; i < 10000; i++) {
        await nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, {
          value: ethers.parseEther('0.25'),
        });
      }
      expect(await nft.balanceOf(owner.address)).to.be.eq(10000);


      await expect(
        nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, {
          value: ethers.parseEther('1'),
        })
      ).to.be.revertedWith('Ownable: caller is not the owner');
    });
```

After 10,000 minted nft, function tries to increment generation and calls `initializeAlphaIndices`. but msg.sender inside EntropyGenerator == TraitForgeNft. 

## Tools Used
Manual review, Hardhat

## Recommended Mitigation Steps
Change modifier of `EntropyGenerator.initializeAlphaIndices()` from onlyOwner to onlyAllowedCaller and inside constructor change way of calling `initializeAlphaIndices()`.

```diff
- function initializeAlphaIndices() public whenNotPaused onlyOwner {
+ function initializeAlphaIndices() public whenNotPaused onlyAllowedCaller {
```
