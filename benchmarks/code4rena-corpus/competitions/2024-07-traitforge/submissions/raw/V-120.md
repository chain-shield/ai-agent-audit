# Vulnerability details

## Impact
[mintWithBudget](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L202), a function that allows users to mint 2 or more NFTs at a time, will not work past the first generation.

## Proof of Concept
[mintWithBudget](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L202) is the same as [mintToken](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L181), with one caveat - it can mint 2 or more NFTs in 1 TX. 

```solidity
   while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
   }
```

However there is an issue inside it's while loop. The while will mint only if `_tokenIds < maxTokensPerGen`, restricting `_tokenIds` to 10k. However `_tokenIds` is one variable for all generations, meaning that first gen will mint from 0 to 10k, 2nd gen from 10k to 20k, and so on.

This restriction will make this function usable only for the first generation and once the second gen starts `_tokenIds >= maxTokensPerGen` and the while will not trigger.

## Tools Used
Manual review

## Recommended Mitigation Steps
You can remove this part from the while `_tokenIds < maxTokensPerGen`, as [_mintInternal](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L281-L283) will just move to the next gen when that one has minted all of it's tokens. 

```diff
-  while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
+  while (budgetLeft >= mintPrice) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
   }
```
