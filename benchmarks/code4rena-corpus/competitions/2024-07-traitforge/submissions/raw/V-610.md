# Vulnerability details

## Impact
A generation can have more than the maximum of 10_000 NFTs which is a core protocol invariant

## Proof of Concept
Each generation must have at most 10_000 NFTs minted:
```solidity
uint256 public maxTokensPerGen = 10000;
```
If that limit is reached, we increment the generation and start minting NFTs in that new generation:
```solidity
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```
Users also have the option to forge their NFTs. Forging allows 2 NFTs from the same generation to forge and mint a third one in the next generation. For example, if these 2 NFTs are in the 1st generation, the newly minted NFT will be in the 2nd generation:
```solidity
uint256 newGeneration = getTokenGeneration(parent1Id) + 1;
```
The issue that can occur is the following:
1. `NFT_A` from generation 1 forges with `NFT_B` from generation 1 and `NFT_C` is minted in the second generation
2. The minted NFTs for the second generation increase in `_mintNewEntity()`:
```solidity
generationMintCounts[gen]++;
```
3. The protocol keeps functioning until UserA mints himself the last allowed NFT from generation 1, thus we increment the generation:
```solidity
  function _incrementGeneration() private {
    require(generationMintCounts[currentGeneration] >= maxTokensPerGen, 'Generation limit not yet reached');
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
4. The __require__ statement passes as we reached the maximum for the current generation, we increment the generation to the second one and then, we set the mint count of the second generation to 0
5. Now, the mint count is incorrect as we actually already have an NFT minted in it

Not only this breaks core invariant and severely damages the integrity of the protocol, it also allows other invariants to be broken such as 1 999999 NFT per generation. Also note that the reset doesn't have to be from 1 to 0, it can be from a much larger value to 0, this was just a simple example I gave.

Manual Review

## Recommended Mitigation Steps
```diff
-generationMintCounts[currentGeneration] = 0;
```
