# Vulnerability details

## Impact

`NukeFund` smart contract allows the user to claim some part of the nuke fund in accordance with his nuke factor value (of the entity). In the documentation it's said that the full maturity should be after 30 days for the fastest entities and for the slowest entities it's 2 years. The problem is that the full maturity basically means that the user's nuke factor make him eligible to claim 50% (maximum  possible value) and the final nuke factor is determined completely random without significant connection to the perfomance factor.

## Proof of Concept

Take a look at how `finalNukeFactor` is determined:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L147-148
```
    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;

    return finalNukeFactor;
  }
```

`adjustedAge` value is obtained like this:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L128-131
```
uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals

```

So we get some random number represented as age and then we just add `initialNukeFactor` at the end which is just the addition of two random numbers. It makes it a deviation from the spec as there is no any relation to perfomance factor and actual maturity as it's just used as a value for multiplication. The tokens that can nuke 50% of the funds have completely random nuke factors that does not depend on perfomance factor as described in the spec.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Change the way nuke factor is calculated and make it the way it's described in the docs.
