# Vulnerability details

## Impact
The `NukeFund` contract allows users to "nuke" their NFTs to claim a portion of the fund. 
According to [Docs](https://github.com/TraitForge/GitBook/blob/main/GamePlay/Nuke%20Fund.md):
```solidity
Eligibility for Nuking:
- An entity must be at least three days old to be eligible for nuking. This rule prevents immediate claims after acquisition and encourages longer-term holding.
```

However, if the `owner` increases the `minimumDaysHeld` parameter, tokens that were previously eligible for `nuking` may become ineligible, causing unexpected reverts for users attempting to nuke their tokens.

## Proof of Concept
Checking Token Eligibility for Nuking:
In [`nuke()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L163), this is required:
```solidity
require(canTokenBeNuked(tokenId), 'Token is not mature yet');
```
Here is the [`canTokenBeNuked()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L184-L194) function.
```solidity
`function canTokenBeNuked(uint256 tokenId) public view returns (bool) {
    // Ensure the token exists
    //..
    uint256 tokenAgeInSeconds = block.timestamp -
      nftContract.getTokenLastTransferredTimestamp(tokenId);
    // Assuming tokenAgeInSeconds is the age of the token since it's holding the nft, check if it's over minimum days held
    return tokenAgeInSeconds >= minimumDaysHeld;
  }
```
This function requires that the tokenId`s `tokenAgeInSeconds` be greater than or equal to the set `minimumDaysHeld`.

The vulnerability arises from the dynamic nature of the `minimumDaysHeld` parameter. The contract `owner` has the authority to update this parameter at any time using the [`setMinimumDaysHeld()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L67-L69) function.
```solidity
  function setMinimumDaysHeld(uint256 value) external onlyOwner {
    minimumDaysHeld = value;
  }
```
When this parameter is increased, tokens that were previously `eligible for nuking` (i.e., tokens that have been held for at least the old `minimumDaysHeld` duration) may no longer meet the new requirement. As a result, users who attempt to `nuke` their tokens after the parameter change will face unexpected reverts.

### Scenario
- `Bob`'s NFT has matured after 3days.
- He then submits a transaction to nuke his token
- At the same time, the `owner` queues another transaction to update the `minimumDaysHeld` to `7 days`
- However, by the nature of transaction exections in the blockchain, the `owner`'s transaction is executed before `Bob`'s.
- `Bob`'s transaction then fails with `'Token is not mature yet'` error and therefore has to wait for another 4days.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Introduce a `grace period` during which the `old minimumDaysHeld` value is still effective for tokens that were already eligible based on the `old value`.
