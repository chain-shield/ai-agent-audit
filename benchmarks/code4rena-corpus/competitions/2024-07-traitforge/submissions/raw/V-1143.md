# Vulnerability details

## Impact

When the last token of a generation is minted and tokens are already present in the next generation due to forging, the `generationMintCounts` variable for the new generation is incorrectly reset to 0. This allows players to mint more tokens than intended, exceeding the 10,000-token limit per generation and potentially surpassing the overall limit of 100,000 tokens.

The `_incrementGeneration` function, which is invoked whenever a new generation token is minted via the `Forge`, `mintToken`, and `mintWithBudget` functions, resets the generation whenever the first token of a new generation is minted according to this logic:
```javascript
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
```

This issue arises due to reseting the `generationMintCounts` variable for each new generation. Every time a new entity is forged, the generation count for the new token is updated accordingly.

According to the protocol, strategy of keeping a limited number of tokens in each generation and overall is aimed at maintaining stable and upward prices and value for the NFT tokens. Allowing more than 10,000 tokens per generation and exceeding the total cap of 100,000 tokens disrupts the intended scarcity, potentially reducing the value of the NFTs and adversely affecting the protocol's effectiveness.

## Proof of Concept
Consider this scenario:

1. Players have forged 500 tokens for generation 4 (`generationMintCounts[4] = 500`).
2. A different player mints the last token of generation 3.
3. Subsequently, the player mints a token from generation 4.
4. During this process, the `generationMintCounts` variable for generation 4 is incorrectly reset to 0.
5. This reset allows for an additional 50 tokens to be minted in generation 4.
6. As a result, generation 4 ends up with a total of 10,500 tokens, exceeding the 10,000-token limit set by the protocol.
