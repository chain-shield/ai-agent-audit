# Vulnerability details

## Vulnerability details

Even though the airdrop contract itself is out of scope for this audit,
the fairness of airdrop distribution still relies on the
NFT ownership/transfer logic of the 'TraitForgeNft' contract.

1. Everytime an user mints or forges a new NFT, 
they get added to the airdrop contract thru the `_mintInternal` and `_mintNewEntity` functions 

2. Everytime an NFT is burned the 'initial owner' is removed from the airdrop contract. 

The above operations happen as long as the airdrop distribution hasn't started.

```
if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
}
```
Similarly, in the context of airdrops,
when NFTs are transferred / bought thru secondary sales,
it is important to ensure that the current owners are added to the airdrop contract.

It could be argued that every current owner is an active partcipant of the protocol, 
and is more entitled to the governance token (aka airdrop) than the previous owner. 
 
By not updating the latest owners to the airdrop contract, 
new owners might miss out on their rewards, 
and previous owners might receive rewards they are no longer eligible for.

## Impact

Mishandled ownership updates to Airdrop contract results in 
1. current NFT owners are left with no airdrop rewards.
2. Initial minters are unfairly allocated airdrop rewards even after selling their NFTs.

## Recommended Mitigation Steps

Although the airdrop distribution logic is out of scope, 
considering fairness of distribution,
Either of the following 2 methods could be adapted.

Method 1 :
   Time-weighted distributed based on the time an user held an NFT.
   (or) 
   
Method 2 :
    Add the current NFT owners to the airdrop allocation 
	  and remove previous owners during transfers.

Considering the later method is simpler to adapt based on the current implementation,
the following changes could be made.

1. The `_beforeTokenTransfer` hook could be modified 
   to add the 'new owner', 
   and remove the 'previous owner' from the airdrop contract.
   
```
if (!airdropContract.airdropStarted()) {

   if (from != address(0)) {
       airdropContract.subUserAmount(from, entropy);
   }

   if (to != address(0)) {
       airdropContract.addParticipant(to, entropy);
   }
}            
```   
   
2. Remove the `airdropContract.subUserAmount` call from the 'burn',
   and `airdropContract.addUserAmount` calls from the 
   `_mintInternal`, & `_mintNewEntity` functions respectively.
   as these are handled inside the `_beforeTokenTransfer` hook.
