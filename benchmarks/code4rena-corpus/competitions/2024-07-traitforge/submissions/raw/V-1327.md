# Vulnerability details

## Impact
In `TraitForgeNft.sol`, whenever an entity is minted, the mint count is stored in the `generationMintCounts` mapping for that generation:
```
mapping(uint256 => uint256) public generationMintCounts;
```
There is a variable called `maxTokensPerGen`, which is the maximum number of tokens that can be minted per generation:
```solidity
uint256 public maxTokensPerGen = 10000;
```
The current generation is tracked using the `currentGeneration` variable:
```solidity
uint256 public currentGeneration = 1;
```
Entities can be minted in three ways: by calling `mintToken()`, `mintWithBudget()`, or by forging through `forge()`.

#### Example Scenario
- Suppose `maxTokensPerGen` is set to 30.
- Bob and Alice each mint 15 entities, reaching the limit for Generation 1.
- They then forge together 3 times, creating 3 new entities for Generation 2. Thus, querying `generationMintCounts` for Generation 2 will return 3.
- A third user named Tim comes along and decides to mint a token using `mintToken()`, which calls the internal function `_mintInternal()`. Since Generation 1 has reached its limit, the `_incrementGeneration()` function is called in `_mintInternal` :
```solidity
function mintToken()
      public
      payable
      whenNotPaused
      nonReentrant
  {
      uint256 mintPrice = calculateMintPrice();
      require(msg.value >= mintPrice, 'Insufficient ETH sent for minting.');
      _mintInternal(msg.sender, mintPrice); <-- HERE
      uint256 excessPayment = msg.value - mintPrice;
      if (excessPayment > 0) {
          (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
          require(refundSuccess, 'Refund of excess payment failed.');
      }
  }

  function _mintInternal(address to, uint256 mintPrice) internal {
      if (generationMintCounts[currentGeneration] >= maxTokensPerGen) { <-- HERE
          _incrementGeneration(); <-- HERE
      }
      _tokenIds++;
      uint256 newItemId = _tokenIds;
      _mint(to, newItemId);
      uint256 entropyValue = entropyGenerator.getNextEntropy();
      tokenCreationTimestamps[newItemId] = block.timestamp;
      tokenEntropy[newItemId] = entropyValue;
      tokenGenerations[newItemId] = currentGeneration;
      generationMintCounts[currentGeneration]++;  
      initialOwners[newItemId] = to;
      if (!airdropContract.airdropStarted()) {
          airdropContract.addUserAmount(to, entropyValue);
      }
      emit Minted(
          msg.sender,
          newItemId,
          currentGeneration,
          entropyValue,
          mintPrice
      );
      _distributeFunds(mintPrice);
  }
```
The problematic part of `_incrementGeneration()`:
```solidity
  function _incrementGeneration() private {
      require(
          generationMintCounts[currentGeneration] >= maxTokensPerGen,
          'Generation limit not yet reached'
      );
      currentGeneration++;
      generationMintCounts[currentGeneration] = 0; <-- HERE
      priceIncrement += priceIncrementByGen;
      entropyGenerator.initializeAlphaIndices();
      emit GenerationIncremented(currentGeneration);
  }
```

When `_incrementGeneration()` is called:
- `currentGeneration` is incremented from 1 to 2.
- `generationMintCounts[currentGeneration]` is set to 0 for Generation 2.

After `_incrementGeneration()`, `generationMintCounts[currentGeneration]` is incremented in `_mintInternal()`:
```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
        _incrementGeneration();
    }
    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();
    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;  <-- Here
    initialOwners[newItemId] = to;
    if (!airdropContract.airdropStarted()) {
        airdropContract.addUserAmount(to, entropyValue);
    }
    emit Minted(
        msg.sender,
        newItemId,
        currentGeneration,
        entropyValue,
        mintPrice
    );
    _distributeFunds(mintPrice);
}
```
This results in the mint count for Generation 2 being 1 instead of the expected 4 (3 from forging and 1 from the new mint).

## Proof of Concept
#### Setup
- In `foundry.toml` add `verbosity = 4`  or set it to 4 to view the logs.
- Change `maxTokensPerGen` to 30 in `TraitForgeNft.sol` for the demonstration.
```solidity
uint256 public maxTokensPerGen = 30;
```

- Comment out `bytes32[] calldata proof` and `onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender))` in`TraitForgeNft.sol:mintToken()`:

`TraitForgeNft.sol`
```solidity
function mintToken(
    //bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    //onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');
    _mintInternal(msg.sender, mintPrice);
    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
```

- Comment out `function mintToken(bytes32[] calldata proof) external payable;` in `ITraitForgeNft.sol`

`ITraitForgeNft.sol`
```solidity
// function mintToken(bytes32[] calldata proof) external payable;
```

- I also removed the `onlyOwner` modifier from `EntropyGenerator.sol: initializeAlphaIndices()`  and `Airdrop.sol:addUserAmount()` for this demonstration because this modifier will prevent a user from minting when the `maxTokensPerGen` for a generation is reached. The modifiers were only removed to facilitate testing and is not a proper fix.
