# Vulnerability details

## Impact

`TraitForgeNft::_incrementGeneration()` doesn't check if the incremented `currentGeneration` is <= than `maxGeneration`. This allows `currentGeneration > maxGeneration` which breaks the maximum generations invariant.
Currently the `maxGeneration` variable is set to 10, meaning the protocol allows a max of 10 generation of NFT tokens, however `TraitForgeNft` can have many more because of this missing check.

## Proof of Concept

```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
@->    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

If we look at the `_incrementGeneration` function we can clearly see that there is no check to make sure that the `currentGeneration` doesn't become higher than the maximum allowed generation. This allows infinite minting of NFTs which will make them worth way little than they should be as scarcity determines price.

## Recommended Mitigation Steps

Add the following line in `TraitForgeNft::_incrementGeneration()`:

```diff
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
+   require(currentGeneration <= maxGeneration, 'Current generation exceeds max generation')
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
