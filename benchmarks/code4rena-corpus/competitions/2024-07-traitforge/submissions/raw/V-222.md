# Vulnerability details

**Description:** 
There is read only reentrancy in `DevFund::claim` function because it is not following CEI pattern. And making external calls before updating the `info.pendingRewards`. The callee can perform read only reentrancy by calling `pendingRewards` function in it's `receive` or `fallback` function and can see `pendingRewards` is not being updated.

**Impact:** 
 The `info.pendingRewards` is not updated before making any external call which leads to incorrect function returns. It could be combined with other bugs in the contract to cause problems like incorrect reward calculations, unintended behaviors, or even potential loss of funds.

**Proof of Concept:**

```solidity
  function claim() external whenNotPaused nonReentrant {
    DevInfo storage info = devInfo[msg.sender];

    uint256 pending = info.pendingRewards +
      (totalRewardDebt - info.rewardDebt) *
      info.weight; //@Question this will be also 0

  }
```

```solidity
 function pendingRewards(address user) external view returns (uint256) {
    DevInfo storage info = devInfo[user];
    return
      info.pendingRewards + (totalRewardDebt - info.rewardDebt) * info.weight; //@Question this will also be 0? //Answer NO

```
1. An attacker calls the `claim()` function to initiate the claim process.
2. Before the `info.pendingRewards` state is updated , the contract makes an external call via `safeRewardTransfer()`.
3. The attacker, via a reentrancy attack, calls `pendingRewards()` and observes that their pendingRewards value has not been updated yet, as the state change happens after the external call.
4. This leads to incorrect return of data which opens the door for potential vulnerabilities.

**Recommended Mitigation:** 
The recommended mitigation is to follow CEI pattern and calculate `claimedAmount` and update `info.pendingRewards` before making external call.
