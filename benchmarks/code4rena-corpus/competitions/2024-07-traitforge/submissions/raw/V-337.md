# Vulnerability details

## Impact: 
In the `TraitForgeNft` contract, any address that has been granted approval for a specific NFT can call the burn function and destroy that NFT. This functionality is facilitated by checking if the caller is either an owner or an approved spender using `_isApprovedOrOwner`. However, this introduces a vulnerability where if an approved spender’s account becomes compromised, they could maliciously burn all NFTs they have approval for without further check and this could lead to the following:
1: Loss of Assets: Owners may lose valuable and irreplaceable NFTs.
2: Security Risk: Compromised accounts with burning privileges can cause irreversible damage.
3: User Trust: Users' trust in platform security might be significantly eroded.

## Proof of Concept:
The test written in foundry simulates the scenario where a whitelisted Owner Mints and creates an approved spender that has the ability to Burn NFTs and attempts to burn an NFT. The test then verifies that the approved spender can indeed burn the NFT.

```javascript

import "forge-std/Test.sol";
import { TraitForge } from  "../TraitForgeNft.sol";
import "@openzeppelin/contracts/token/ERC721/IERC721.sol";
import "@openzeppelin/contracts/utils/cryptography/MerkleProof.sol";

contract TraitForgeNftTest is Test {
    TraitForgeNft traitForgeNft;
    address owner = address(0x1);
    address approvedSpender = address(0x2);
    bytes32[] proof;
    bytes32 rootHash;

    function setUp() public {
        traitForgeNft = new TraitForgeNft();

        // Set the root hash for whitelist
        rootHash = keccak256(abi.encodePacked(owner));
        traitForgeNft.setRootHash(rootHash);

        // Set the whitelist end time to a future time
        traitForgeNft.setWhitelistEndTime(block.timestamp + 1 days);

        // Set the nuke fund address to a valid address
        traitForgeNft.setNukeFundContract(payable(address(0x3)));
        traitForgeNft.setEntropyGenerator(address(0x4));

        traitForgeNft.setAirdropContract(address(0x5));

        // Whitelist the owner
        proof.push(keccak256(abi.encodePacked(owner)));
    }

    function testApprovedSpenderCanBurnNFT() public {
        // Mint an NFT to the owner
        vm.startPrank(owner);
        traitForgeNft.mintToken{value: traitForgeNft.calculateMintPrice()}(proof);
        vm.stopPrank();

        uint256 tokenId = traitForgeNft.tokenOfOwnerByIndex(owner, 0);

        // Approve the approvedSpender to manage this token
        vm.prank(owner);
        traitForgeNft.approve(approvedSpender, tokenId);

        // Attempt to burn the NFT by the approved spender
        vm.prank(approvedSpender);
        traitForgeNft.burn(tokenId);

        // Verify that the token no longer exists
        assertEq(traitForgeNft.ownerOf(tokenId), address(0));
    }
}

```

## Tools Used: Manual Review

## Recommended Mitigation Steps: Below are some Mitigations to resolve the above exploit.
1. Restrict Burning to Owners Only: Modify the burn function to allow only owners (not just any authorized user) to execute it.
2. Add Whitelist Check (Optional): Add whitelist verification similar to mint functions as an additional protection layer.
3. User Education: Inform users about the risks associated with approving spenders who can burn NFTs.
