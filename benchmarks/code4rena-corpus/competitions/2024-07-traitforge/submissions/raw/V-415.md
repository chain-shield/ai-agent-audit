# Vulnerability details

## Impact

`nukeFactor` will always be zero since it is truncated to zero.

## Proof of Concept

When `deriveTokenParameters()` is called, `nukeFactor` is calculated as such:

```
 nukeFactor = entropy / 4000000;
```

The issue is that entropy is a 6 digit number, and it is being divided by a 7 digit number which causes truncation to zero. All queries for `deriveTokenParameters()` will be incorrect.

Impact is high because calculation is wrong, but since it is a view function, setting as medium severity because other players/contracts/protocols may build on top of this protocol and call `deriveTokenParameters` without knowing the mistake and causing confusion.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Should divide by 40 instead of 4 million, as how the NukeFund.sol contract calculates the `initialNukeFactor`.

```
 uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits
```
