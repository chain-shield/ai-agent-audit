# Vulnerability details

The `TraitForgeNft` contract begins with generation 1 and supports up to 10 generations, each allowing the minting of 10,000 NFTs. When a generation's 10,000 NFTs [are minted](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L281), the contract should [increment](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L282) to the next generation and start minting again. This transition is handled by the [`_incrementGeneration`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345) function.

In addition to incrementing the generation, the [`_incrementGeneration`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345) function calls the [`EntropyGenerator.initializeAlphaIndices`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L206) function. However, this function is protected by the `onlyOwner` modifier, which restricts access to the contract deployer. Attempting to call this function from `TraitForgeNft` during the generation transition will result in a revert, blocking the minting and forging of future generations.

## Impact

Once the first generation of NFTs is depleted, transitioning to the next generation will not be possible.

- As the generation cannot be successfully incremented, the `TraitForgeNft` remains stuck at the limit of the first 10,000 NFTs. According to the whitepaper, it should have 10 generations of 10,000 NFTs each.
- Users are unable to mint or forge new NFTs beyond the first generation, rendering the `TraitForgeNft` unusable for future generations.

## Proof of Concept

The issue happens during the transition between generation one and two when the maximum number of NFTs for the current generation is reached.

1. A user calls the `mintToken` function, where the `_mintInternal` is called to handle the minting
    
```solidity
    	function mintToken(
    	  bytes32[] calldata proof
    	)
    	  public
    	  payable
    	  whenNotPaused
    	  nonReentrant
    	  onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
    	{
    	  uint256 mintPrice = calculateMintPrice();
    	  require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');
    	
    @>    _mintInternal(msg.sender, mintPrice);
    	
    	  uint256 excessPayment = msg.value - mintPrice;
    	  if (excessPayment > 0) {
    	    (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
    	    require(refundSuccess, 'Refund of excess payment failed.');
    	  }
    	}
```
    
2. The `_mintInternal` checks if the number of minted NFTs has reached `maxTokensPerGen` (10,000 NFTs) and calls `_incrementGeneration` to transition to the next generation.
    
```solidity
    	function _mintInternal(address to, uint256 mintPrice) internal {
    	  if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
    @>    _incrementGeneration();
    	  }
    		...
    	}
```
    
3. The `_incrementGeneration` transition to the next generation and calls `entropyGenerator.initializeAlphaIndices()` to initialize new indices for the new generation.
    
```solidity
    	function _incrementGeneration() private {
    	  require(
    	    generationMintCounts[currentGeneration] >= maxTokensPerGen,
    	    'Generation limit not yet reached'
    	  );
    	  currentGeneration++;
    	  generationMintCounts[currentGeneration] = 0;
    	  priceIncrement = priceIncrement + priceIncrementByGen;
    @>    entropyGenerator.initializeAlphaIndices();
    	  emit GenerationIncremented(currentGeneration);
    	}
```
    
4. However, the `initializeAlphaIndices` function is protected by the `onlyOwner` modifier, allowing only the `EntropyGenerator` deployer to call it. This restriction leads to the revert of the entire transaction, preventing the generation transition.
    
```solidity
      function initializeAlphaIndices() public whenNotPaused onlyOwner {
        uint256 hashValue = uint256(
          keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
        );
    
        uint256 slotIndexSelection = (hashValue % 258) + 512;
        uint256 numberIndexSelection = hashValue % 13;
    
        slotIndexSelectionPoint = slotIndexSelection;
        numberIndexSelectionPoint = numberIndexSelection;
      }
```

## Recommended Mitigation Steps

Replace the `onlyOwner` modifier with [`onlyAllowedCaller`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L25-L28), which allows the function to be called only by the `TrairForgeNft` contract.

```diff
- function initializeAlphaIndices() public whenNotPaused onlyOwner {
+ function initializeAlphaIndices() public whenNotPaused onlyAllowedCaller {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
}
```
