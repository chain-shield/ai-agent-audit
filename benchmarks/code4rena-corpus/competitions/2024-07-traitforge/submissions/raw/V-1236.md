# Vulnerability details

## Description & Impact
In the `TraitForgeNFT` contract, consider these logics:

```solidity
File: ./contracts/TraitForgeNft/TraitForgeNft.sol::mintToken (line: 193)

_mintInternal(msg.sender, mintPrice);
```

```solidity
File: ./contracts/TraitForgeNft/TraitForgeNft.sol::_mintInternal (line: 281)

if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
    _incrementGeneration();
}
```

```solidity
File: ./contracts/TraitForgeNft/TraitForgeNft.sol::_incrementGeneration (line: 350)

currentGeneration++;
generationMintCounts[currentGeneration] = 0;
```

This means that before minting a token through the `TraitForgeNft::mintToken` function, if the `generationMintCounts` of `currentGeneration` is greater or equal to the `maxTokensPerGen = 10000`, this will call the `_incrementGeneration` function. In this function, after incrementing the `currentGeneration` number, it will zero the value of tokens minted with this generation.

Now, consider that after the start of the game, 9000 tokens of generation 1 have been minted, and they start to forge with each other. Thus, the new tokens minted through the forging process belong to generation 2, so `generationMintCounts[2]` will increase. If another 1000 tokens are minted through the `TraitForgeNft::mintToken` process, because `generationMintCounts[1]` becomes equal to `maxTokensPerGen = 10000`, the `_incrementGeneration` function will execute. It first increments the `currentGeneration` to 2 and then resets the value of `generationMintCounts[2]`. So, besides the NFTs minted with `tokenGenerations[newTokenId] = 2`, we can still mint 10000 tokens with `tokenGenerations[newTokenId] = 2`.

Thus, the `maxTokensPerGen` invariant functionality breaks, and the number of tokens minted in generation 2 can reach up to 20,000.

This will cause the game to stall in the generations twice. Also, with statistical calculations, it can be estimated that in each generation, the sum of all forgers' `forgePotential` is approximately 15,000, and for mergers, 30,000. This problem allows the generation of 20,000 tokens, 15,000 of which can be generated through the forging process. Generation of this volume of tokens through the forging process in each generation can lead to the number of tokens growing at a much higher rate than the balance of the pool, causing an imbalance in the `NukeFund` contract during the nuke process.

By analyzing the result of the code above, we can say that in each generation, the sum of all forgers' `forgePotential` is approximately 15,000, and for mergers, 30,000. So before the end of minting generation 1 tokens, it is possible to mint 10000 generation 2 tokens through the forging process, and after that, call `TraitForgeNft::mintToken` again until the generation 1 tokens reach 10000. Then, the function `TraitForgeNft::_incrementGeneration` is called, and the `generationMintCounts[2]` resets, allowing another 10000 tokens to be minted in generation 2.

- Hardhat

## Recommended Mitigation Steps

Delete `generationMintCounts[currentGeneration] = 0;` in `TraitForgeNft::_incrementGeneration`:

```diff
File: ./contracts/TraitForgeNft/TraitForgeNft.sol::_incrementGeneration (line: 350)

currentGeneration++;
- generationMintCounts[currentGeneration] = 0;
```

By implementing this change, the `generationMintCounts` for each generation will not be reset, ensuring that the maximum number of tokens per generation remains within the intended limit of 10000.
