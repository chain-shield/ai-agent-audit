# Vulnerability details

## Impact

The functions in ERC721URIStorage is not used.

## Proof of Concept

ERC721URIStorage in EntityTrading is imported but not inherited, which means that all the functionality inside ERC721URIStorage cannot be tapped on, like `_setTokenURI()`. 

> ERC721URIStorage extension provides storage for token URIs which means that uris are stored on-chain. Without this extension, URIs are NOT going to be stored on-chain.

> The extension enables this by storing each tokenURI on chain, instead of generating the tokenURIs dynamically by concatenating the baseURI + tokenId.

```
> import '@openzeppelin/contracts/token/ERC721/extensions/ERC721URIStorage.sol';
import '@openzeppelin/contracts/security/ReentrancyGuard.sol';
import '@openzeppelin/contracts/access/Ownable.sol';
import '@openzeppelin/contracts/security/Pausable.sol';
import './IEntityTrading.sol';
import '../TraitForgeNft/ITraitForgeNft.sol';

> contract EntityTrading is IEntityTrading, ReentrancyGuard, Ownable, Pausable {
```

## Tools Used

Manual Review

## Recommended Mitigation Steps

If the protocol wants to use URIStorage, inherit ERC721URIStorage as well,

```
contract EntityTrading is IEntityTrading, ReentrancyGuard, Ownable, Pausable, ERC721URIStorage {
```

like how TraitForgeNFT inherits ERC721Enumerable:

```
contract TraitForgeNft is
  ITraitForgeNft,
  ERC721Enumerable,
  ReentrancyGuard,
  Ownable,
  Pausable
{
```
