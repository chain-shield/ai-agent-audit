# Vulnerability details

## Impact

In the current implementation of `EntityTrading` smart contract, there is an operation of transferring NFT token from the user to the owner when listing NFT on sale. The problem is that the contract does not implement onERC721Received() function which makes it unable to receive ERC721 tokens.

## Proof of Concept

Take a look at the `listNFTForSale()` functionality:


https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityTrading/EntityTrading.sol#L53
```
nftContract.transferFrom(msg.sender, address(this), tokenId); // trasnfer NFT to contract
```

The contract transfers the token from `msg.sender` to `address(this)`. The problem is that the contract does not implement `onERC721Received()` that's necessary to obtain NFT tokens in a smart contract. Moreover, the contract uses `transferFrom()` instead of `safeTransferFrom()` which is necessary for safe NFT transfers (it checks if the contract implements `onERC721Received()`):

https://docs.openzeppelin.com/contracts/3.x/api/token/erc721#IERC721-safeTransferFrom-address-address-uint256-bytes-
```
If to refers to a smart contract, it must implement IERC721Receiver.onERC721Received, which is called upon a safe transfer.

```

## Tools Used

Manual review.

## Recommended Mitigation Steps

Implement onERC721Received() and use `safeTransferFrom()` instead of `transferFrom()` for ERC721 token transfer.
