# Vulnerability details

## Impact
In the EntityForging contract, there are multiple scenarios where a listed forger can potentially cause a Denial of Service (DoS) attack against a merger during the forging process. The forger can exploit several vectors to prevent the forging process from completing, such as:
1. Reverting When Funds are Sent: If the forger’s address is a contract with a fallback function that reverts when receiving funds, it can cause the transaction to fail.
2. Canceling Beforehand: The forger can monitor the blockchain for a merger’s transaction and cancel the listing before it completes.
3. Burning the Token: The forger can burn their token, which will cancel the listing.
4. Transferring the Token: The forger can transfer their token to another address, which automatically cancels the listing.

## Proof of Concept
1. The forger lists a token for forging.
2. A merger initiates the forging process by calling forgeWithListed.
3. The forger can use one of the aforementioned methods to cause the transaction to fail, leading to a denial of service for the merger.

## Recommended Mitigation Steps
Implement a claim mechanism where the forger can withdraw their fees rather than transferring them immediately. This can be done by maintaining a mapping of forgers to their owed fees. Forgers can claim their fees through the claimFee function.
```js
mapping(address => uint256) public pendingFees;
function claimFees() external nonReentrant {
    uint256 amount = pendingFees[msg.sender];
    require(amount > 0, "No fees to claim");

    pendingWithdrawals[msg.sender] = 0;

    (bool success, ) = msg.sender.call{ value: amount }("");
    require(success, "Claim failed");

    emit FeesClaimed(msg.sender, amount);
}
```
