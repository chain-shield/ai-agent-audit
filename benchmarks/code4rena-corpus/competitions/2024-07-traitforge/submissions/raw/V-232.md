# Vulnerability details

## Impact
The `uint256 daysOld` variable is calculated by substracting the current `block.timestamp` with the previously recorded `nftContract.getTokenCreationTimestamp(tokenId)` and then divisions are made in order to get the day value (Seconds old / 60 seconds / 60 minutes / 24hrs). However, Solidity uses fixed point arithmetic, that mean it doesn't support decimal value. As a result, any non-integer value is truncated downward. This characteristic of Solidity can lead to precision loss.

## Proof of Concept
Alice has forged a token almost 3 days ago. Now she wants to calculate the age of her token in order to know if it can be nuked for funds. She calls the `calculateAge` function. We assume that the date she calls the function is `August 2, 2024` which means that `block.timestamp` is `1722587319` and `nftContract.getTokenCreationTimestamp(tokenId)` is `1722331719` (2 days and 23 hours ago). `1722587319` - `1722331719` = `255600` / 60 / 60 / 24 = `2.9583333333...` As mentioned above in the report, Solidity uses fixed point arithmetic and it will round the number down to 2.
