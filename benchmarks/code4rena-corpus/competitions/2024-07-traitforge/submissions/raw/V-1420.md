# Vulnerability details

## Impact

A potential reentrancy vulnerability arises in this smart contract. In the `claim` function, there is a state modification after external calls.

Reentrancy attacks can occur when a contract calls external contracts and then proceeds to make changes to its state. An attacker can recursively call back into the vulnerable function, leading to the condition that the state changes apply to outdated data.


## Proof of Concept

The following code snippets show the external call followed by state modification:

```solidity
uint256 claimedAmount = safeRewardTransfer(msg.sender, pending);  // external call
info.pendingRewards = pending - claimedAmount;  // state modification
```

## Tools Used

Manual Review

## Recommended Mitigation Steps

To avoid potential reentrancy attacks, checks-effects-interactions (CEI) pattern should always be followed. This pattern suggests to first make all the internal work (checks and state changes) and eventually call the external functions and transfer ethers (interactions).
