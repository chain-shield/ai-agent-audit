# Vulnerability details

## Bug description
`mintWithBudget()` allows users to mint multiple NFTs in batches. This is achieved by a loop that keeps minting NFTs until the `msg.value` provided is depleted or `maxTokensPerGen` is reached.

[TraitForgeNft.sol#L215-L220](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L215-L220)
```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
    _mintInternal(msg.sender, mintPrice);
    amountMinted++;
    budgetLeft -= mintPrice;
    mintPrice = calculateMintPrice();
}
```

Because `_tokenIds` variable, which represents the total amount of NFTs minted, is used to determine if the maximum amount of tokens per generation has been reached, the function will stop working after 10_000 NFTs have been minted. 

## Impact
DoS of the `mintWithBudget()` function.

## Recommended Mitigation
Remove `_tokenIds < maxTokensPerGen` from the check, since `_mintInternal()` will take care of incrementing the generation if max has been reached or instead of `_tokenIds` use `generationMintCounts[currentGeneration]`.

[TraitForgeNft.sol#L215-L220](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L215-L220)
```diff
- while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
+ while (budgetLeft >= mintPrice && generationMintCounts[currentGeneration] < maxTokensPerGen) {
    _mintInternal(msg.sender, mintPrice);
    amountMinted++;
    budgetLeft -= mintPrice;
    mintPrice = calculateMintPrice();
}
```
