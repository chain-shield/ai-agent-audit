# Vulnerability details

### Summary

The fallback function for receiving ETH does not properly handle fund allocation based on the airdrop status. Specifically, if the airdrop has not started, it inappropriately attempts to allocate funds based on the `daoFundAllowed` status, leading to potential fund misallocation.

### Vulnerability Details
  The fallback function interacts with the `airdropContract` to determine how to distribute developer's share of the received ETH:

1. **If the airdrop has not started (`!airdropStarted()` returns `true`):** The function attempts to send the developer's share to `devAddress`, which is appropriate.
2. **If the airdrop has started but `daoFundAllowed()` returns `false`:** The function attempts to send the developer's share to the contract owner. This is problematic because `daoFundAllowed()` should not be true if the airdrop has not started.
3. **If the airdrop has started and `daoFundAllowed()` is true:** The function correctly sends the developer's share to `daoAddress`.

The potential issue is that if the airdrop has not started, and `daoFundAllowed()` is `false`, the fallback function attempts to set `daoAllowed` which is not possible as `daoAllowed` can only be set to `true` after the airdrop has started.

    ```solidity
    receive() external payable {
      uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
      uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund
    
      fund += remainingFund; // Update the fund balance
    
      if (!airdropContract.airdropStarted()) {
        (bool success, ) = devAddress.call{ value: devShare }('');
        require(success, 'ETH send failed');
        emit DevShareDistributed(devShare);
      } else if (!airdropContract.daoFundAllowed()) {
        (bool success, ) = payable(owner()).call{ value: devShare }('');
        require(success, 'ETH send failed');
      } else {
        (bool success, ) = daoAddress.call{ value: devShare }('');
        require(success, 'ETH send failed');
        emit DevShareDistributed(devShare);
      }
    
      emit FundReceived(msg.sender, msg.value); // Log the received funds
      emit FundBalanceUpdated(fund); // Update the fund balance
    }
    
    ```
    
### Impact
If the airdrop has not started or if the DAO fund allowance is not set, funds may not be distributed correctly. This could lead to misallocation of funds, failed transactions, and wasted gas fees.

### Tools Used

Manual code review.

### Recommendations

Ensure that the fallback function correctly aligns with the conditions set in the airdrop contract and does not attempt to make decisions based on invalid or inconsistent states. Specifically:

 **Check Airdrop Status:** Ensure that the airdrop status conditions are correctly handled. For example, `daoFundAllowed` should only be checked if `airdropStarted()` returns `true`.
