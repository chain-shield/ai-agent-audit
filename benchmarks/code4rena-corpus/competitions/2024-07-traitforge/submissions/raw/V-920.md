# Vulnerability details

## Description & Impact
According to the [Official Whitepaper](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit) of the TraitForge project, the `nukeFactor` should be calculated as `entropy / 40`. This same logic is correctly implemented in `NukeFund.sol`:

```
File: ./contracts/NukeFund/NukeFund.sol::calculateNukeFactor (line: 145)

uint256 initialNukeFactor = entropy / 40; // calculate initialNukeFactor based on entropy, 5 digits
```

However, in `EntropyGenerator::deriveTokenParameters`, the `nukeFactor` is calculated incorrectly:

```
File: ./contracts/EntropyGenerator/EntropyGenerator.sol::deriveTokenParameters (line: 152)

nukeFactor = entropy / 4000000;
```

Because `entropy` is a 6-digit number, dividing it by 4000000 will always return zero. This causes all future smart contracts and applications that use this function to get `nukeFactor`, `forgePotential`, `performanceFactor`, and `isForger` to receive the wrong value for `nukeFactor`.

Ensuring the correct calculation of `nukeFactor` according to the whitepaper's formula guarantees consistency and reliability throughout the project, preventing potential logical errors and unintended consequences in dependent contracts and applications.

## Proof of Concept
Create a test file in the test directory of the project (`$ touch test/auditNukeFactor.test.ts`), paste the code below, and run `npx hardhat test test/auditNukeFactor.test.ts`:

```javascript
  import { EntropyGenerator } from '../typechain-types';
  import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';

  const { expect } = require('chai');
  const { ethers } = require('hardhat');

  describe('EntropyGenerator', () => {
    let entropyGenerator: EntropyGenerator;
    let owner: HardhatEthersSigner;

    before(async () => {
      [owner] = await ethers.getSigners();

      // Deploy EntropyGenerator contract
      const EntropyGenerator = await ethers.getContractFactory(
        'EntropyGenerator'
      );
      entropyGenerator = (await EntropyGenerator.deploy(
        owner.address
      )) as EntropyGenerator;

      await entropyGenerator.writeEntropyBatch1();
      await entropyGenerator.writeEntropyBatch2();
      await entropyGenerator.writeEntropyBatch3();
    });

    describe('getParams', () => {
      it('check nukeFactor', async () => {
        for (let i = 0; i < 770; i++) {
          for (let j = 0; j < 13; j++) {
            let entropy = await entropyGenerator.getPublicEntropy(i, j);
            let tokenParams = await entropyGenerator.deriveTokenParameters(i, j);

            // nukeFactor is always zero
            expect(tokenParams[0]).to.equal(0);

            console.log(
              'entropy', entropy,
              'nukeFactor', tokenParams[0],
              'forgePotential', tokenParams[1],
              'performanceFactor', tokenParams[2],
              'isForger', tokenParams[3]
            );
          }
        }
      });
    });
  });
```

The test passes, indicating that all `nukeFactor` values returned are zero. Additionally, uncommenting the `console.log()` in the test shows that other values are correct, but `nukeFactor` is zero for all entropy values.

## Recommended Mitigation Steps

```diff
File: ./contracts/EntropyGenerator/EntropyGenerator.sol::deriveTokenParameters (line: 152)

-    nukeFactor = entropy / 4000000;
+    nukeFactor = entropy / 40;
```

By implementing this change, the calculation will align with the whitepaper and ensure the correct `nukeFactor` value is used in all related computations.
