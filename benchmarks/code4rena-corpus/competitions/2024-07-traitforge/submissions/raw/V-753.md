# Vulnerability details

## Impact 
maxTokenPerGeneration can be bypassed and more tokens than the required can be minted.


## Proof of Concept

Lets say that Bob calls forge(). The currentGeneration is 5 and with 
```uint256 newGeneration = getTokenGeneration(parent1Id) + 1;``` the newGeneration becomes 6. Then the execution proceeds to _mintNewEntity.
Since the newGeneration contains 0 tokens it continues execution and mints new token. It does not create new generation because _incrementGeneration is bypassed with currentGeneration=5 and gen=6 
``` 
if (
      generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration
    ) {
      _incrementGeneration();
    }
 ```
New token is minted for generation 6.

The next time that _incrementGeneration is called to make the current generation from 5 to 6 it will reset the count because of
```
 generationMintCounts[currentGeneration] = 0;
```

In this scenario the count of tokens is not going to be correct since the total tokens count will be one more that is stored in generationMintCounts.
