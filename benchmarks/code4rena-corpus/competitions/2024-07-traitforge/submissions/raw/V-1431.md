# Vulnerability details

## Description 
The `EntropyGenerator` contract uses block-related data (`block.number`) as a source of randomness in its entropy generation process. This method of generating random numbers is vulnerable to manipulation and prediction, potentially compromising the integrity of the entire system that relies on this contract for randomness.

Specifically, the contract uses the following method to generate pseudo-random values:
```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
```
This approach is used in the public functions `writeEntropyBatch1()`, `writeEntropyBatch2()`, and `writeEntropyBatch3()`, which are responsible for initializing the entropy pool.
## Impact
- Fairness Compromise: Attackers could potentially predict or manipulate the generated entropy values, leading to unfair advantages in the game or NFT minting process.
- Economic Exploitation: In a game economy relying on this randomness, predictable outcomes could be exploited for economic gain, potentially destabilizing the in-game economy.
## Proof of concept
An attacker could exploit this vulnerability using the following method:

- Monitor the blockchain for the deployment of the `EntropyGenerator` contract.
- Predict the `block.number` that will be used in the next call to `writeEntropyBatch1()`.
- Prepare a transaction that calls `writeEntropyBatch1()` with a specific gas price to ensure it's mined in the predicted block.
- By doing this, the attacker can influence the initial state of the entropy pool.
Here's a simplified example of how an attacker might predict the outcome:
```
const predictedBlockNumber = await web3.eth.getBlockNumber() + 1;
const predictedEntropy = web3.utils.soliditySha3(
  {type: 'uint256', value: predictedBlockNumber},
  {type: 'uint256', value: 0} // First index in the batch
);
console.log("Predicted first entropy value:", web3.utils.toBN(predictedEntropy).mod(web3.utils.toBN(10).pow(web3.utils.toBN(78))).toString());
```
## Tools Used
Manual code review

## Recommended Mitigation Steps
Implement Chainlink VRF or a similar service to provide provably fair and verifiable randomness.
