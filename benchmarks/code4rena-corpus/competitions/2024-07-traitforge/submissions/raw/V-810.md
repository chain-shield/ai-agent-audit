# Vulnerability details

## Impact
There can exist two golden gods (nft with 999999 as entropy) per generation. A system invariant is only having one.

## Proof of Concept

The functions writeEntropyBatch1/2/3 create a hash that is inserted in the current entropy slot as a uin256. Each of these values hold 13 entropy values, the problem arises when one of these values is 999999. Theres a check that is made to avoid the value 999999 o writeEntropyBatch1/2 but is useless since the hash is always bigger.

The actual golden god should be given when [initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206C12-L206C34) initializes the index where the nft [entropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L170-L175) should fall into.

When [getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L164) is called for the next nft in generation x, there can be one (or more) slots with 999999 and also this [condition](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L170-L175) will return another 999999. 

This can happen only if the block number of the block used when initializing a batch of slots is such that the hash of its number and the current slot index has nine 9 consecutive in some slot section. [code](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L54).

POC: add the following lines into (at the end) [EntropyGenerator.test.ts](https://github.com/code-423n4/2024-07-traitforge/blob/main/test/EntropyGenerator.test.ts)

```typescript
  it.only('AUDIT: two 999999 can exists', async function () {
    // mine 132 blocks
    await send('hardhat_mine', ['0x84']);

    //must be 134 on hardhat network to work. nxt tx will be 136
    await entropyGenerator.writeEntropyBatch1();
    await entropyGenerator.writeEntropyBatch2();
    await entropyGenerator.writeEntropyBatch3();

    const slotIndex = await entropyGenerator.slotIndexSelectionPoint();
    const numberIndex = await entropyGenerator.numberIndexSelectionPoint();

    const god1 = await entropyGenerator.getPublicEntropy(
      slotIndex,
      numberIndex
    );
    const god2 = await entropyGenerator.getPublicEntropy(186, 12);

    expect(god1).to.be.eq(999999);
    expect(god2).to.be.eq(999999);
  });
```

The function "getPublicEntropy" is used to get the entropy without creating a transaction and moving the indexes. Two combinations of slot and number with the same entropy with value 999999 means there will exist 2 golden gods.

## Tools Used
Manual review

## Recommended Mitigation Steps
When creating entropy slots, create a stronger validation over the whole hash to check for any 999999. The validation should check for every part of the hash that forms an entropy value.
