# Vulnerability details

 Unintended Overpayments in EntityForging::forgeWithListed resulting to players distrust

### Vulnerability Details
Users consistently overpay due to lack of refund mechanism leading to Accumulation of excess funds in the contract, distorting the intended economic model.

### Impact
Users are frequently overcharged because there is no mechanism to refund any excess payment.
this  require statement happens to be the cause of this issue
require(msg.value >= forgingFee, "Insufficient fee for forging");
This above checks allows for payments greater than the required fee without returning the surplus to the user.
This results in financial imbalances and diminishes user trust in the platform.
Implementing a refund mechanism for excess payments would enhance user trust and ensure financial transparency.

### Proof of Concept
* this below is the vulnerable line
* require(msg.value >= forgingFee, "Insufficient fee for forging");
* which if you examine the rest of the  there is no where the protocol accounts for exccess in the `forgeWithListed` function

Recommended Mitigation
* Account for exccess like you did in mintToken function in TraitForge
