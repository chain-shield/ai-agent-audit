# Vulnerability details

In the `forgeWithListed` function, the following require statement is used.
```
  require(msg.value >= forgingFee, 'Insufficient fee for forging');
```

and then the dev fee is calculated using a fixed `forgingFee` value instead of the actual `msg.value`:
```
uint256 devFee = forgingFee / taxCut;
```
This calculation doesn't account for cases where `msg.value` might be greater than `forgingFee`.

## Impact
Incorrect fee distribution: 
If a user sends more ETH than the required `forgingFee`, the excess amount will not be factored into the fee calculation, resulting in a lower percentage going to the dev fund than intended.

## Proof of Concept
Assume `forgingFee` is set to 1 ETH and `taxCut` is 10 (10% fee).

A user calls `forgeWithListed` with `msg.value` of 2 ETH.

The dev fee is calculated as: devFee = 1 ETH / 10 = 0.1 ETH

The forger receives: 2 ETH - 0.1 ETH = 1.9 ETH

The actual fee percentage is: (0.1 ETH / 2 ETH) * 100 = 5%, instead of the intended 10%

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the fee calculation to use `msg.value` instead of `forgingFee`.
```
uint256 devFee = msg.value / taxCut;
```
