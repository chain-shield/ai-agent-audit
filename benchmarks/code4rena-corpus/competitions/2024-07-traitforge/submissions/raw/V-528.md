# Vulnerability details

## Impact
There is a `golden god` for every generation which means an NFT with 999999 entropy. This entropy will be in the third batch of entropies and this is ensured by the `EntropyGenerator.initializeAlphaIndices` method. This method is called in `EntropyGenerator's` constructor alongside with setting the `allowedCaller` to the `TraitForgeNft` address.

```solidity
constructor(address _traitForgetNft) {
allowedCaller = _traitForgetNft;
initializeAlphaIndices();
```

Let's take a look at `initializeAlphaIndices()`
```solidity
function  initializeAlphaIndices() public whenNotPaused onlyOwner {
uint256 hashValue =  uint256(
keccak256(abi.encodePacked(blockhash(block.number -  1), block.timestamp))
);
uint256 slotIndexSelection = (hashValue % 258) +  512; 
uint256 numberIndexSelection = hashValue % 13;  
slotIndexSelectionPoint = slotIndexSelection;
numberIndexSelectionPoint = numberIndexSelection;
```
Except for `EntropyGenerator's` constructor this function is called from within `TraitForgeNft._incrementGeneration`. 

```solidity
function  _incrementGeneration() private {
require(
generationMintCounts[currentGeneration] >= maxTokensPerGen,
"Generation limit not yet reached"
);
currentGeneration++;
generationMintCounts[currentGeneration] =  0;
priceIncrement = priceIncrement + priceIncrementByGen;
entropyGenerator.initializeAlphaIndices(); //here
emit  GenerationIncremented(currentGeneration);
}
```

`incrementGeneration` is called in `mintNewEntity`(when forging) and `mintInternal`(when minting directly). `incrementGeneration` is private meaning it can only be called from within the contract it is declared, that being `TraitForgeNft`.

When a user mint directly he will call `TraitForgeNft.mintToken` or `mintWithBudget`. Lets follow the `mintToken` flow. After calculating the price of the NFT, `mintToken` calls `mintInternal`. In `mintInternal` msg.sender is the player who wants to mint. Before minting and incrementing `tokenIds`, `mintInternal` checks if the generation mint counts for the current generation are at 10_000. If they are, it calls `incrementGeneration`. 

```solidity
function  _mintInternal(address to, uint256 mintPrice) internal { 
if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
_incrementGeneration(); //here
_tokenIds++;
uint256 newItemId = _tokenIds;
_mint(to, newItemId);
```

As I mentioned above `incrementGeneration` is private, so msg.sender in its context is the `TraitForgeNft` contract itself. So when `incrementGeneration` attempts to call `entropyGenerator.initializeAlphaIndices();` the whole transaction will be reverted because `initializeAlphaIndices` has the `onlyOwner` modifier. The owner of `EntropyGenerator` is the deployer and not the nft contract. The nft contract is the allowed caller, but the owner and allowed caller are two different entities. 

This means that when first generation of tokens is fully minted the protocol can never go to second generation and will be stuck at generation 1 and some tokens minted from generation 2 from forging.

## Recommended Mitigation Steps
Create a `onlyAllowedCallerOrOwner` modifier like this:
```solidity
odifier  onlyAllowedCaller() {
require(msg.sender  == allowedCaller || msg.sender == owner, "Caller is not allowed nor owner");
_;
}
```
and attach it to `initializeAlphaIndices` instead of `onlyOwner`
