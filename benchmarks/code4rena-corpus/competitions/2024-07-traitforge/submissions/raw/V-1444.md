# Vulnerability details

## Impact
This bugs allows for a transaction to go through that does not do any state change, emit events or return any data, wasting users gas in that case.

## Proof of Concept
In the function `claim()` of `DevFund.sol`
```solidity
  function claim() external whenNotPaused nonReentrant {
    DevInfo storage info = devInfo[msg.sender];

    uint256 pending = info.pendingRewards +
      (totalRewardDebt - info.rewardDebt) *
      info.weight;

    if (pending > 0) {
      uint256 claimedAmount = safeRewardTransfer(msg.sender, pending);
      info.pendingRewards = pending - claimedAmount;
      emit Claim(msg.sender, claimedAmount);
    }

    info.rewardDebt = totalRewardDebt;
  }
```
the function calculates `pending` amount to be sent for the `msg.sender` but does not revert it when `pending == 0`, as otherwise this function does nothing other than transferring calculated `pending` eth to the sender and updating that value to storage. When pending is 0, the transaction should be reverted to save users gas. It says makes up for better UX for user as user knows they don't have anything pending when they see reverting transaction on metamask.

## Recommended Mitigation Steps
Instead of using an `if` statement to decide it, use `require` to revert back in case `pending == 0`, otherwise send the eth.
