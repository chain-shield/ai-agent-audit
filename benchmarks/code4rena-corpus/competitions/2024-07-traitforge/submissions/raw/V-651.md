# Vulnerability details

## Impact
Having no golden god is against the protocol team's intention and game logic.

## Proof of Concept
If an entire generation(gen >= 2) is forged, there would be no golden god in that generation. Since the best child that a forging can make is:
parent1 = 999999
parent2 = 999998
child = 999998
Note: The sponsor has confirmed(in discord) that every generation must have a golden god. Therefore this is against the protocol teams' intention and game logic.

Note that this doesn't need the entire 10,000 tokens to be forged:
assume that the golden god is set at slot = 769, numberindex = 2,
Then this scenario would just need 1 forge to not have a golden god in that particular generation.

## Tools Used
Manual Review

## Recommended Mitigation Steps
After each forge, make sure that the golden god index is reachable. And that all the tokens in a generation can't be made by forging.
Code changes in the initializeAlphaIndices() function(https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L206-L216):

    ITraitForgeNft public nftContract = ITraitForgeNft(allowedCaller);
    uint256 slotUpperLimit = (10,000 - nftContract.generationMintCounts[nftContract.currentGeneration])/13
    uint256 slotIndexSelection = ((hashValue % 258) + 512) % slotUpperLimit;
    uint256 numberIndexSelection = hashValue % 13;

This would make sure that the golden god is always within reach by minting in a generation.
