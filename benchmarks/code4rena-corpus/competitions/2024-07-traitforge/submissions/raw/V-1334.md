# Vulnerability details

## Vulnerability details

Even though the issue is listed as a 'Low' severity in the 4naly3er report, 
it doesnt mention the scenario by which `taxCut` could be set to 0.

The `taxCut` state variable is used to set the percentage share in the following 3 contracts

1. EntityForging
2. EntityTrading
3. NukeFund

Currently 'taxCut' is set to 10%.
However all 3 contracts have a function to change the 'taxCut' if required
```
function setTaxCut(uint256 _taxCut) external onlyOwner {
    taxCut = _taxCut;
}
```

When the protocol eventually goes into DAO governance in the future,
the community could propose 'taxCut' of 0 in certain contracts.

It is common for projects to operate at 0% royalties in some circumstances. 

But the current implementation is not designed to handle a 'taxCut' value of 0,
as it will cause a panic revert.


## Impact

When the DAO proposes to set the `taxCut` to 0, in the above mentioned contracts
the calculations will cause a panic revert due to division by zero.

## Proof of Concept

1. Initial State of NukeFund contract
   taxCut = 10

2. In order to promote nuking strategy, the community proposes to allocate 
   100% of the ETH received towards Honeypot share 
   meaning 0% goes towards Dev or Dao share.

3. This requires setting taxCut to 0, which is currently not possible.



## Recommended Mitigation Steps

The following code is designed for NukeFund contract.
Similar logic could be added for the EntityForging & EntityTrading contracts as well.

```
if (taxCut > 0) {
    devShare =  msg.value / taxCut;
    remainingFund = msg.value - devShare ;
} else {
    devShare = 0;
    remainingFund = msg.value;
}

fund += remainingFund;
```
