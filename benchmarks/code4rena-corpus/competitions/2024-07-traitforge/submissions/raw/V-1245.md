# Vulnerability details

## Impact
- `_incrementGeneration` function is called when maximum token per generation is minted and need to start minting new generation token.
- Here `maxTokensPerGen` is 10000 that means every generation has 10000 NFTs to mint and after that new generation is start.
- But when user forge the NFT of 1st generation then user will get NFT of 2nd generation.
- That means when 1st generation NFTs are minted in normal mint at the same time there will be some NFTs of 2nd generation by forging of NFT of 1st gen.
- Now, when 1st gen's 10000 NFTs will be minted, `_incrementGeneration` function will be called which sets `generationMintCounts[currentGeneration] = 0`.
- That means 2nd gen count will start from 0 but in actual case there are already other NFTs are minted by forging 1st gen NFTs.
- Due to which every gen has 10000 NFTs to mint statement will be proven wrong and every gen can have more NFTs than 10000.

## Recommended Mitigation Steps
- In `_incrementGeneration` function, `generationMintCounts[currentGeneration]` mapping should not be set as 0.
- Protocol have to consider those NFTs which are minted through forging and make sure that there will not be more than 10000 NFTs per generation.
