# Vulnerability details

## Impact
The use of the <= operator allows users to forge up to and including the forgePotential value. This could result in users being able to forge one more entity than the actual intended limit, as the condition permits exactly forgePotential number of forges. For instance, if forgePotential is set to 5, the current logic allows for a total of 6 forge operations before hitting the limit.

## Proof of Concept
```solidity
require(
  forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
  'Entity has reached its forging limit'
);
```

## Tools Used

## Recommended Mitigation Steps
Modify the condition to use the < operator instead of <= to strictly enforce the forging limit.
