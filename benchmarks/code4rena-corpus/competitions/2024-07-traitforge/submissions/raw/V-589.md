# Vulnerability details


## Impact

The 'GoldenGod' Entity, characterized by an entropy value of '999999', is designed to be the most valuable and unique Entity in the game. According to the documentation, there should only be one 'GoldenGod', deliberately set in the final pass of entropy generation. However, the current implementation allows for the possibility of multiple 'GoldenGod' Entities to exist, which severely undermines the intended rarity and value of this special Entity.

The issue stems from the entropy generation and validation process in the `writeEntropyBatch1` and `writeEntropyBatch2` functions of the `EntropyGenerator` contract. While these functions attempt to prevent the creation of 'GoldenGod' Entities, the check is ineffective due to a mismatch in the comparison of generated values.

This vulnerability could lead to:

1. Multiple 'GoldenGod' Entities existing in the game ecosystem.
2. Devaluation of the intended unique 'GoldenGod' Entity.
3. Potential imbalance in gameplay and economy, as more players than intended could possess entities with perfect parameters.

## Proof of Concept

The `writeEntropyBatch1` and `writeEntropyBatch2` functions generate pseudo-random values using:

```solidity
uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78;
```

These functions then attempt to prevent 'GoldenGod' Entities with:

```solidity
require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```

However, this check is flawed because:

1. `pseudoRandomValue` is a 78-digit number, capable of storing 13 concatenated 6-digit entropies.
2. The comparison `pseudoRandomValue != 999999` only checks if the entire 78-digit number equals 999999, not if it contains 999999.

For example, consider the following `pseudoRandomValue`:

```
123456999999123456789098765432123456789098765432123456789098765432123456789004
```

This value would pass the current check because it's not equal to 999999 as a whole. However, it contains the 'GoldenGod' entropy (999999) as its second Entity entropy.

To verify:

1. Open a Solidity REPL (like ChiSel).
2. Run the following command:
   ```solidity
   123456_999999_123456_789098_765432_123456_789098_765432_123456_789098_765432_123456_789004 == 999999
   ```
3. This returns `false`, allowing the value to pass the check.

However, when `getPublicEntropy` is called with `slotIndex = 0` and `numberIndex = 1`, it would return the 'GoldenGod' entropy of 999999.

Manual Review, Foundry (`cast` command)

1. Implement a more thorough checking mechanism that examines each 6-digit segment within the 78-digit `pseudoRandomValue`.
