# Vulnerability details

## Impact
`TraitForgeNft.sol:mintWithBudget` is meant to mint entities until the budget becomes insufficient. This function will deny its service once the current generation increases or entities are forged and `_tokenIds` becomes more than `maxTokensPerGen`. This will happen because of the following condition:

```javascript
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen)
```

The `_tokenIds < maxTokensPerGen` will always be false since `_tokenIds` will become greater than `maxTokensPerGen` as soon as the generation increases or when people start forging entities.

Denial of service of `TraitForgeNft.sol:mintWithBudget` preventing minting entities with a predefined budget

## Proof of Concept
Because of another issue, the first thing to do is to remove the `onlyOwner` modifier of `EntropyGenerator.sol:initializeAlphaIndices`.

! To speed up the test change the `maxTokensPerGen` in `TraitForgeNft.sol` to `10`

Now open `TraitForgeNft.test.ts` and paste this test along with its describe block:

```javascript
describe('POC', () => {
  it('should not be able to mint with budget after gen 1', async () => {
    let generationOneCount = await nft.generationMintCounts(1);
    let currentGeneration = await nft.currentGeneration();
    let user2Balance = await nft.balanceOf(user2.address);
    console.log(`Generation one minted: ${generationOneCount}`);
    console.log(`Current generation: ${currentGeneration}`);
    console.log(`User 2 initial balance: ${user2Balance} \n`);

    await nft.connect(user2).mintWithBudget([], {
      value: ethers.parseEther('1'), // Mint the whole generation 1
    });

    // Assert that the whole generation 1 has been minted
    expect(await nft.generationMintCounts(1)).to.be.eq(
      await nft.maxTokensPerGen()
    );

    await nft.connect(user2).mintToken([], {
      value: ethers.parseEther('1'), // Increase generation
    });

    // Assert that the current generation has been increased
    expect(await nft.currentGeneration()).to.be.eq(2);

    const user2BalanceBeforeMint = await nft.balanceOf(user2.address);
    console.log(
      `User 2 balance before mintWithBudget on gen 2: ${user2BalanceBeforeMint}`
    );

    await nft.connect(user2).mintWithBudget([], {
      value: ethers.parseEther('1'), // Mint entities from gen 2 with budget
    });

    user2Balance = await nft.balanceOf(user2.address);
    console.log(
      `User 2 balance after mintWithBudget on gen 2: ${user2Balance}`
    );

    expect(user2BalanceBeforeMint).to.be.eq(user2Balance); // Assert that user 2 has not minted any entities
  });
});
```

Manual Review

## Recommended Mitigation Steps
Remove the `_tokenIds < maxTokensPerGen` part from the condition to allow minting NFTs after increasing the generation or replace `_tokenIds` with `generationMintCounts[currentGeneration]` to prevent minting multiple generations with one call
