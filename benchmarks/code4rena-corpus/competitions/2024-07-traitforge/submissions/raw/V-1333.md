# Vulnerability details

## Description 
The contract generates random numbers using modulo operations (`%`), which can introduce bias, particularly in smaller ranges.
```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
```
## Impact
1.Non-Uniform Distribution: The use of modulo can lead to a biased distribution of generated values.
2.Uneven Trait Generation: Some traits or characteristics may appear more frequently than intended.
3.Exploitation Risk: Savvy players may exploit the bias, potentially disrupting the balance of the game economy.

## Proof of Concept
When applying `x % n` where `x` is a random number and `n` is not a power of 2, the lower remainders are slightly more likely if `x` is not a multiple of `n`.



## Tools Used
 Manual Review
## Recommended Mitigation Steps
1. Adopt Rejection Sampling:
Implement a method to avoid bias:
```
function unbiasedRandom(uint256 upperBound) internal view returns (uint256) {
    uint256 max = type(uint256).max - type(uint256).max % upperBound;
    uint256 result;
    do {
        result = uint256(keccak256(abi.encodePacked(block.timestamp, msg.sender, nonce++)));
    } while (result >= max);
    return result % upperBound;
}
```
2. Minimize Bias with Large Dividends:
If modulo operations are necessary, ensure that the dividend is significantly larger than the divisor to reduce the potential for bias.
