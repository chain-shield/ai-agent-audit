# Vulnerability details

## Impact

The `EntityForging.forgeWithListed` function is used to forge a new `TraitForgeNft` by combining a forger NFT and a merger NFT. After the new NFT has been forged, the `forgerOwner` is paid the `forgerShare` amount by transferring the `forgerShare` amount from the `EntityForging` contract via the low-level call function (This will call the receive function if the forgerOwner is a contract), to the `forgerOwner` address.

The issue is a malicious `forgerOwner cotract` can list his `forgerTokenId` NFT for `forging` and when this forger NFT is forged he can revert the transaction in the `receive` function implemented in the `forgerOwner` contract. As a result the `mergerTokenId owner` will not be able to `forge` the token thus losing his transaction gas fees thus incurring loss of funds to him. 

The `malicious forgerOwner contract` can revert this `forging operation multiple times` by keeping his `forgerTokenId` in the `forge listings mapping`.

## Recommended Mitigation Steps

Hence it is recommended to store the `forgerShare` amount in the `EntityForging` contract let the `forgerOwner` contract pull his `forgerShare` amount from the `EntityForging` contract. In nutshell use the pull strategy (not the push strategy) to send the funds to the `forgerOwner`.

The same issue is prevalent in the `EntityTrading.buyNFT` function where the `NFT seller contract` can revert the transaction inside the `receive` function implemented in the `NFT seller contract`. Hence it is recommended to implement the pull strategy (not the push strategy) to send the `sellerProceeds` funds to the `NFT seller contract`.
