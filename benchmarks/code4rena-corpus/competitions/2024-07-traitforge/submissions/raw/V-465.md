# Vulnerability details

In a particular generation, the price to mint a nft increases linearly depending on the count of the token being minted. Thus by the end of a generation, the last couple of nfts contribute a major portion to the funds being received to the protocol. When the generation count is incremented, the price of an nft is slightly incremented from the actual start point. 
Meaning the last nft of a generation is way more than the starting nft of the next generation.

When forging with a listed nft, the user calling the `forgeWithListed()` has to pay a forging fee. If the conditions are met & the new nft is minted, the user only has to pay the forging fee & not any additional cost. 


## Proof of Concept

- Assume the attacker (Bob) uses two different account for minting or mints from one account & transfers to the other.
- Bob holds **100** `generation 1` nfts of which some nft have forge potential greater than 4 (just for that sake that he can use the same nft multiple times for forging).
- Assume the current `generation 2` is going on & `9,900` nfts have been minted.
- That means **100** nfts are remaining to be minted until `generation 3` starts.
- If directly minted, the cost for the remaining **100** nfts will be `29.851025 ether`. Approximately `~30 ether`
- Bob lists his nft for for forging by calling the `listForForging()` with the forging fee set to `0.01 ether` (`minimumListFee`).
- From his other account, Bob calls the `forgeWithListed()` thereby minting an nft.
- All the checks pass & Bob has to only pay the **10%** tax on each call. The remaining amount is sent back to the forger id owner which is owned by Bob himself.
- Bob continues until he has minted **100** nfts through this process.
- Given the minimum fee to be `0.01 ether` & the number of nfts minted is `100`, the total cost for minting by forging would be `1 ether`.
- Since Bob owns both account, he only ends up paying 10% i.e. `0.1 ether` to the protocol. The remaining `0.9 ether` is sent back to him.

Taking the above scenario, had the minting process being carried out **without forging**, the protocol would have earned approx `30 ether`.
Because of Bob's tactics, the protocol earned only `0.1 ether`.
Loss to the protocol = `30 ether - 0.1 ether` = `29.9 ether` which is a huge amount.

## Impact
Loss of funds to the protocol

## Tools Used
Manual Review

## Recommended Mitigation Steps
As of now I can only think that to reduce the impact of this issue, the protocol should stop forging nfts close to the maximum number of tokens that can be generated in a particular generation. Like if the limit is 10,000 for a generation, stop the forging when the minted nft count reached 9,000. Because the majority of the funds for a generation are received near the end of the generation.
