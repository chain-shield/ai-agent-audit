# Vulnerability details

## Impact
In the EntropyGenerator:`initializeAlphaIndices` an `onlyOwner` modifier was used instead of an `onlyAllowedCaller` this means that whenever a generation increment is to occur the transaction would revert, stopping users from minting into new generations.

## Proof of Concept
This is basically caused by the wrong usage of modifier in the EntropyGenerator`initializeAlphaIndices` function, so when the max entities per generation has been reached, minting into a new generation would revert because the initializeAlphaIndices is expecting the deployer instead of the `traitForgeNftContract`.

POC written in foundry

```solidity
    function test__MintingReverts_DueToWrongModifierUsageIn_IntitalizeAlphaIndices() public {
        uint256 maxTokensPerGen = 10000;

        vm.startPrank(userOne);
        for (uint256 i = 1; i <= maxTokensPerGen; i++) {
            traitForgeNft.mintToken{value: traitForgeNft.calculateMintPrice()}(emptyProof);
        }
        vm.stopPrank();

        vm.startPrank(userTwo);
        // THIS CALL REVERTS!!!!
        // I cant use the `vm.expectRevert()` because it reverts in the EntropyGenerator:`initializeAlphaIndices()`
        // rather than the mintToken itself
        traitForgeNft.mintToken{value: traitForgeNft.calculateMintPrice()}(emptyProof);
        vm.stopPrank();
    }
```


## Recommended Mitigation Steps
Transfer Ownership from the deployer to the TraitForgeNft contract or make use of the `onlyAllowedCaller` modifier setting the allowed caller to the traitForgeNft contract address.
