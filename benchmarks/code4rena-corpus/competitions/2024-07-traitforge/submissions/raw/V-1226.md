# Vulnerability details

**Impact**
When a user calls `forgeWithListed` they must send a fee in ether which is then sent to the `forgerOwner` in the following logic:
```solidity
    (bool success, ) = nukeFundAddress.call{ value: devFee }('');
    require(success, 'Failed to send to NukeFund');
```
This is problematic becuase the `forgerOwner` could be a contract with a malicious fallback function which forces the original caller to consume a large amount of the transaction's gas forcing the user to pay significantly more gas for a transaction than would otherwise be necessary.

The same issue exists in the `EntityTrading::buyNFT` function when transferring sale value from the buyer to the seller.

**Recommended Mitigation**
It would be advisable in situations such as this to make users call separate `withdraw` function to redeem any earned fees rather than making a raw call to an artbirary address. This avoids the `forgerOwner`'s ability to grief potential mergers. Alternatively if the project wishes to keep the current control flow to improve user experience they should consider setting an explicit maximum gas limit that the call to `forgerOwner` can use, like so:
```solidity
    (bool success, ) = nukeFundAddress.call{ value: devFee, gas: 100_000 }('');
```
