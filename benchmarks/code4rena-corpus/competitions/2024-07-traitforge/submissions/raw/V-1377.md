# Vulnerability details

## Impact
- In `calculateAge` function, there are two instances where rounding down nature of solidity can cause to user in age calculation.
- If user holds NFT for 23 hours even then it will round down to 0 days which is loss for user.
- in `age` variable also there is possibility of rounding down because it is didvided by 365.

## Proof of Concept
```solidity
function calculateAge(uint256 tokenId) public view returns (uint256) {
    require(nftContract.ownerOf(tokenId) != address(0), 'Token does not exist');

@>    uint256 daysOld = (block.timestamp -
      nftContract.getTokenCreationTimestamp(tokenId)) /
      60 /
      60 /
      24;
    uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;

@>    uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals
    return age;
  }
```

## Recommended Mitigation Steps
- Protocol should make sure that there will be no rounding down loss in `calculateAge` function so no user will get loss of age.
