# Vulnerability details

## Impact
The `EntityTrading()` contract allows users list NFTs for sale , cancel the listing and purchase NFTs. However the `buyNft()` function is vulnerable to cross function reentrancy(even though the function has a nonReentrant modifier) because it doesn't follow the CEI pattern

## Proof of Concept
The `buyNFT()` function uses the `call()` to send ETH to the owner of the NFT then continues to transfer the NFT to the buyer and at the end removes the NFT from the sales list.
 
```javescript
 // transfer NFT from contract to buyer
    (bool success, ) = payable(listing.seller).call{ value: sellerProceeds }(
      ''
    );
    require(success, 'Failed to send to seller');
    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer NFT to the buyer

    delete listings[listedTokenIds[tokenId]]; // remove listing

```
The function does not follow the CEI Pattern and that leaves the `EntityTrading` vulnerable to cross-function Reentrancy where a malicious contract(being the owner of the NFT on sale) can reenter the `cancelList()` with the use of  `fallback()`/`receive()` 
```javascript
function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant {
    Listing storage listing = listings[listedTokenIds[tokenId]];

    // check if caller is the seller and listing is acivte
    require(
      listing.seller == msg.sender,
      'Only the seller can canel the listing.'
    );
    require(listing.isActive, 'Listing is not active.');

    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer the nft back to seller

    delete listings[listedTokenIds[tokenId]]; // mark the listing as inactive or delete it

    emit ListingCanceled(tokenId, msg.sender);
  }
``` 
Imagine this scenario:
 Step 1: An attacker lists an NFT for sale using a malicious 
  contract as the seller.
 Step 2: A buyer calls the buyNFT() function to purchase the NFT
 Step 3:The buyNFT() function transfers ETH to the malicious contract using the 
 `call()` and that triggers the `fallback()`/`receive()` function which calls
 `cancelListing()` function on the `EntityTrading` and `setApprovalForAll()` to 
 remove the `_operatorApprovals` from the `TraitForgeNFT` contract
 Step 4:`cancelListing()` transfer back the NFT to the malicious contract and 
 deletes the listings mapping
Step 6:The `buyNFT()` attempts to transfer the NFT to the buyer but the NFT is already transferred back to the attacker so the transfer fails
