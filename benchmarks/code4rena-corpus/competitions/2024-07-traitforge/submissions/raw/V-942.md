# Vulnerability details

The `nuke` function in the `NukeFund` contract calculates rewards based on the current contract balance:

```
function nuke() public {
    require(block.timestamp >= lastNukeTime + nukeCooldown, "Nuke cooldown not over");
    
    uint256 nukeReward = address(this).balance * nukeFactor / 100;
    uint256 devReward = nukeReward * devShare / 100;
    uint256 daoReward = nukeReward - devReward;
    
    // ... reward distribution logic ...
    
    lastNukeTime = block.timestamp;
    emit Nuked(msg.sender, nukeReward, devReward, daoReward);
}
```

This design makes the function susceptible to front-running attacks.

## Impact
The vulnerability could lead to loss of user trust in the fairness of the system
due to receiving lower rewards than anticipated.

## Proof of Concept
An attacker monitors the mempool for incoming nuke transactions.

When a legitimate nuke transaction is observed, the attacker quickly submits their own nuke transaction with a higher gas price.

The attacker's transaction is processed first, allowing them to claim the nuke rewards based on the current balance.

The legitimate user's transaction processes after, potentially with a lower reward due to the reduced balance.

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement a commit-reveal scheme for nuke operations.
