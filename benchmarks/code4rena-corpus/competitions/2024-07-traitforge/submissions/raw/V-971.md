# Vulnerability details

## Impact
Missing the “the Golden God” entropy value of a generation could undermine the goal of the game and fail to prompt users to mint out the generation. As a result, a generation of 10,000 NFTs might mint out without including an NFT that contains the entropy value of 999,999. This would affect the rarity and value distribution intended by the game mechanics.


## Proof of Concept
To illustrate this issue, consider the following:

1. The total number of `maxSlotIndex` is equal to 770, and the `currentNumberIndex` is equal to 13. This produces a total of `770 x 13 = 10,010` total number of entropies.
2. This means that the `getNextEntropy` will produce 10,010 entropies before resetting instead of 10,000.
3. Since the `initializeAlphaIndices` function sets the slot of the 999,999 value, if that slot is set to the last 10 indices, then that entropy will never be utilized within the generation.
4. `initializeAlphaIndices` is called, which sets the `slotIndexSelection` equal to 769 and `numberIndexSelection` equal to 12.
5. The entropy is stored in the last element in the index 10,010 of the `entropySlots` array. As a result, it will be set to the next generation since each generation can have a maximum of 10,000 mints.


## Tools Used
Manual review

## Recommended Mitigation Steps
It is recommended to utilize a total of 10,000 slots instead of 10,010 to ensure that each entropy value accurately reflects the minting of the current generation. Additionally, modify the slot that stores the 999,999 value so that it is not greater than the 10,000th index of the entropies array.
