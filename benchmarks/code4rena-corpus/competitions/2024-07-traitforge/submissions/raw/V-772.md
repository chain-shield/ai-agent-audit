# Vulnerability details

## Impact

For an entity which has role as a forger, the number of times it should ideally be able to forge equals the forgePotential of that entity. But the listForForging() and forgeWithListed() functions allows the entity to forge more than its forgePotential.  

## Proof of Concept

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L87

In the function listForForging() , the check for forgingCounts of the entity is as follows:

```Solidity
    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );

```

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L133

and in the forging function forgeWithListed() , the forgingcount is incremented:

```Solidity
forgingCounts[forgerTokenId]++;
```

Suppose the entropy of the forger entity is 286659 , the forgePotential = 5 so the entity should be able to forge 5 times ideally.

First call to listForForging():
   forgingCounts[tokenId] = 0 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 1

Second call to listForForging():
   forgingCounts[tokenId] = 1 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 2

Third call to listForForging():
   forgingCounts[tokenId] = 2 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 3

Forth call to listForForging():
   forgingCounts[tokenId] = 3 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 4

Fifth call to listForForging():
   forgingCounts[tokenId] = 4 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 5

Sixth call to listForForging():
   forgingCounts[tokenId] = 5 <= forgePotential => check in listForForging() passed
   On successfully forging in forgeWithListed() => forgingCounts[forgerTokenId]++;
   Now forgingCounts[tokenId] = 6

Only on the seventh call will the listForForging() fail for the entity

So the forger entity will be able to forge 6 times even though the forgePotential = 5

## Recommended Mitigation Steps

The check in listForForging should be modified to this:
```Solidity
 require(
      forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
      'Entity has reached its forging limit'
    );
```
