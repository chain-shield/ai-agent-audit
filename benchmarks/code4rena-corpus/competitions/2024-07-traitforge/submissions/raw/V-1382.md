# Vulnerability details

## Impact
The main invarient of the protocol is that user cannot mint more than 10000 NFTs in a generation, but using `EntityForging::forgeWithListed` function users can get more than 10000 NFTs in a generation, which is a violation of the main invarient of the protocol and a complete disruption of the game dynamics.

## Proof of Concept
lets assume `currentGeneration` is 1.

When the user forge its NFT using `EntityForging::forgeWithListed` function, the function will call `TraitForgeNft::forge` function, which will call `TraitForgeNft::_mintNewEntity` function.

In `TraitForgeNft::_mintNewEntity` we are calling `_incrementGeneration` function if `generationMintCounts[gen] >= maxTokensPerGen` ie if the number of tokens in the next generation(2) reaches the max limit then it will increase the generation.

```javascript
    function _mintNewEntity(address newOwner, uint256 entropy, uint256 gen) private returns (uint256) {
        .
        .
        .
        if (generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration) {
@>          _incrementGeneration();
        }
        .
        .
        .
    }
```

Inside `_incrementGeneration` function we are increasing the `currentGeneration`, means the `currentGeneration` becomes 2 and then we are setting the `generationMintCounts[currentGeneration]` to 0.
But this is a problem because we saw in the above that generation(2) already reached the max limit, but here it is again setting it to 0 means user can now mint another 10000 NFTs in the generation(2).
And this cycles continues for all the generations

## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove the line `generationMintCounts[currentGeneration] = 0;` from `_incrementGeneration` function. This will prevent users from minting more than 10000 NFTs in a generation.
