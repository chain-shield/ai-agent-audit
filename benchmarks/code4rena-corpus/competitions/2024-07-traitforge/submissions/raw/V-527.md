# Vulnerability details

## Summary

The `TraitForgeNft` contract is intended to serve as the owner of the `Airdrop` contract. Therefore, it should include mechanisms to allow all the administrative functions of the `Airdrop` contract to be executed. These functions have an `onlyOwner` modifier to restrict access to them, however since `TraitForgeNft` doens't call certain functions that have this modifier they will remain unusable which then can break other functionalitites.

## Vulnerability Details

If we look at `deployTasks.ts` we can clearly see that the ownership of the `Airdrop` contract belongs to `TraitForgeNft`. If we examine `TraitForgeNft` carefully, we can see that not all of the Airdrop's `onlyOwner` functions are being called.
For example:
`Airdrop::allowDaoFund()` is never called in `TraitForgeNft` which means there is no way to call this function. It is a crucial function, because if dao is not allowed, then it cannot receive any funds from `NukeFund` contract:

This is `NukeFund`'s receive function:

```solidity
    //...
    if (!airdropContract.airdropStarted()) {
      (bool success, ) = devAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    } else if (!airdropContract.daoFundAllowed()) {
      (bool success, ) = payable(owner()).call{ value: devShare }('');
      require(success, 'ETH send failed');
    } else {
      (bool success, ) = daoAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    }
    //...
```

The other function that is not called by the `TraitForgeNft` is `Airdrop::setTraitToken()`. Since this function is called in the deploy script it doesn't pose such risk, but still if the implementation of the token changes and needs to be updated, there is no possible way to do that.

## Proof of Concept

We can clearly see that `Airdrop::allowDaoFund()` function has an `onlyOwner` modifier:

```solidity
  function allowDaoFund() external onlyOwner {
    require(started, 'Not started');
    require(!daoAllowed, 'Already allowed');
    daoAllowed = true;
  }
```

Then go to the `TraitForgeNft` - https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol

and search for the call of this function. You can see that it is not being called anywhere.

## Impact

`TraitForgeNft` contract doesn't implement all of Airdrop's `onlyOwner` functions which makes them unusable. It misses the implementation for `Airdrop::allowDaoFund()` which makes it unusable and restricts the DAO of receiving any funds from the `NukeFund`.

## Tools Used

Manual Review

## Recommended Mitigation Steps

In `TraitForgeNft` add a way for the dao to be allowed:

```solidity
+  function allowDao() external whenNotPaused onlyOwner {
+    airdropContract.allowDaoFund();
  }
```

Also if you think the trait token contract may change, add a function to allow that.
