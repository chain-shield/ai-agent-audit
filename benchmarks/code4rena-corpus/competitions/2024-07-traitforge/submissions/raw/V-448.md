# Vulnerability details

## Impact
If a player has an approved operator for all his NFTs and he approves the `nukeFund` for a specific tokenId he wants to nuke, it is possible that the operator nukes and receives the funds. This is possible because of the second require statement - the check on line 158 in `nuke()`
```solidity
function  nuke(uint256 tokenId) public whenNotPaused nonReentrant {
require(
nftContract.isApprovedOrOwner(msg.sender, tokenId), //@audit
'ERC721: caller is not token owner or approved'
);
require( @audit
nftContract.getApproved(tokenId) ==  address(this) ||
nftContract.isApprovedForAll(msg.sender, address(this)),
'Contract must be approved to transfer the NFT.'
);
```

`isApprovedOrOwner` checks if msg.sender is owner of the NFT or an approved operator. The second require statement checks approval of the `nukeFund` contract because later the contract burns the nuked NFT. If a player has an approved operator and he gives approval to `nukeFund` for the specific `tokenId` to be nuked, the operator can call `nuke` and will receive the funds.
