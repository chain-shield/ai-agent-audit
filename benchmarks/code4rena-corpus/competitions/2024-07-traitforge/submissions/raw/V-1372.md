# Vulnerability details

## Impact
When executing `EntropyGenerator::writeEntropyBatch1()`, a list of entropy values for NFTs is generated in the array `uint256[770] private entropySlots`. In this case, when the function is called, values from 0 to `uint256 batchSize1 = 256` are saved in storage.

```solidity
// Functions to initialize entropy values in batches to spread gas cost over multiple transactions
function writeEntropyBatch1() public {
    require(lastInitializedIndex < batchSize1, 'Batch 1 already initialized.');

    uint256 endIndex = lastInitializedIndex + batchSize1; // Calculate the end index for the batch
    unchecked {
        for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
            uint256 pseudoRandomValue = uint256(
                keccak256(abi.encodePacked(block.number, i))
            ) % uint256(10) ** 78; // Generate a pseudo-random value using block number and index
            require(pseudoRandomValue != 999999, 'Invalid value, retry.');
            entropySlots[i] = pseudoRandomValue; // Store the value in the slots array
        }
    }
    lastInitializedIndex = endIndex;
}
```

This also happens in:

- `EntropyGenerator::writeEntropyBatch2()`
- `EntropyGenerator::writeEntropyBatch3()`

Users with more skills can read the entire array of entropy values, and then call `TraitForgeNft::mintWithBudget` or `TraitForgeNft::mintToken()` on the right moment to get the nfts with better entropy values.

This can lead to less skilled users at a disadvantage in the game and undermine confidence in the project.

## Recommended Mitigation Steps

It is recommended to replace the mechanism of writing entropies in batches with a single generation of entropy during the NFT minting process. To ensure true randomness, replace predictable semi-random values like block.number with a reliable oracle, such as Chainlink VRF.
