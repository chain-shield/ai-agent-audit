# Vulnerability details

## Impact
`maxGeneration` a global varaible and invariant in `TraitForgeNft.sol` can get by passed under normal protocol condition considering there are checks across the contract which checks for if `currentGeneration < maxGeneration` and `(generationMintCounts[currentGeneration] =< maxTokensPerGen` this should be a medium. Also considering when `maxGeneration` is by-passed, miting of new entities is possible and will keep going on but `forging` a crucial part of the project which is supposed to go hand in hand with minting is DOS'd(2nd link/code snippet above).

## Proof of Concept
During minting or forging in `TraitForgeNft.sol`, when max tokens per generation is reached this private function is called inside the both mint functions and a new generation is created
`
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;`
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L344C1-L355, the problem is that it does not check when `maxGeneration` is reached so minting can pause and devs can decide if they want to increase generation or not, but since it is not implemented minting continues and forging is disabled (2nd link/code snippet above).

Add a check that ensures when `maxGeneration` is reached, minting is paused.
