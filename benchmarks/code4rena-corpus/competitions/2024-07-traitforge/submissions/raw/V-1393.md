# Vulnerability details

## Impact
If there is a first generation active, users can forge, and by forge they increase `generationMintCounts[gen]++` for second generation. But after we minted 10000 tokens of the first generation, and switch to second generation to be active, we call `_incrementGeneration` function. This function increases generation number (from 1 to 2 in our case), and reset count to zero: `generationMintCounts[currentGeneration] = 0`. 

It means all previously forged tokens will be reset to zero. New generation mints count should start not from zero, but from the number of previously forged tokens
