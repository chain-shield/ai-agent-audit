# Vulnerability details


## Description & Impact
According to the [Official Whitepaper](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit) of the TraitForge project, the `forgePotential` should be the tens digit of the entropy number (`Entropy[4] = colour1 && forgePotential`). This logic is correctly implemented in the `EntityForging` contract:

```solidity
File: ./contracts/EntityForging/EntityForging.sol::listForForging

86   uint8 forgePotential = uint8((entropy / 10) % 10);
```

```solidity
File: ./contracts/EntityForging/EntityForging.sol::forgeWithListed

138   uint8 mergerForgePotential = uint8((mergerEntropy / 10) % 10);
```

However, in `EntropyGenerator::deriveTokenParameters`, the `forgePotential` is calculated incorrectly:

```solidity
File: ./contracts/EntropyGenerator/EntropyGenerator.sol::deriveTokenParameters

153    forgePotential = getFirstDigit(entropy);
```

```solidity
File: ./contracts/EntropyGenerator/EntropyGenerator.sol

198   function getFirstDigit(uint256 number) private pure returns (uint256) {
          while (number >= 10) {
              number /= 10;
          }
          return number;
      }
```
Miscalculating `forgePotential` leads to inconsistencies and potential errors in external smart contracts and applications that rely on this parameter for proper functioning. Ensuring the accurate computation of `forgePotential` guarantees the integrity and reliability of the forging process.

## Proof of Concept
Create a test file in the test directory of the project (`$ touch test/auditForgePotential.test.ts`), paste the code below, and run `npx hardhat test test/auditForgePotential.test.ts`:

```javascript
    import { EntropyGenerator } from '../typechain-types';
    import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';

    const { expect } = require('chai');
    const { ethers } = require('hardhat');

    describe('EntropyGenerator', () => {
      let entropyGenerator: EntropyGenerator;
      let owner: HardhatEthersSigner;

      before(async () => {
        [owner] = await ethers.getSigners();

        // Deploy EntropyGenerator contract
        const EntropyGenerator = await ethers.getContractFactory(
          'EntropyGenerator'
        );
        entropyGenerator = (await EntropyGenerator.deploy(
          owner.address
        )) as EntropyGenerator;

        await entropyGenerator.writeEntropyBatch1();
        await entropyGenerator.writeEntropyBatch2();
        await entropyGenerator.writeEntropyBatch3();
      });

      describe('getParams', () => {
        it('check forgePotential', async () => {
          for (let i = 0; i < 770; i++) {
            for (let j = 0; j < 13; j++) {
              let entropy = await entropyGenerator.getPublicEntropy(i, j);
              let tokenParams = await entropyGenerator.deriveTokenParameters(i, j);

              let correctForgePotential = Math.floor(Number(entropy) / 10) % 10
              
              console.log(
                'entropy', entropy,
                'forgePotential', tokenParams[1],
                "correctForgePotential", correctForgePotential
              );
            }
          }
        })
      })
    })
```

## Recommended Mitigation Steps

```diff
File: ./contracts/EntropyGenerator/EntropyGenerator.sol::deriveTokenParameters (line: 153)

-   forgePotential = getFirstDigit(entropy);
+   forgePotential = (entropy / 10) % 10;
```

By implementing this change, the calculation will align with the whitepaper and ensure the correct `forgePotential` value is used in all related computations.
