# Vulnerability details

## Impact
The contracts within the codebase are supposed to be `pausable`. However, they do not correctly exposes the `_pause()` and `_unpause()` internal functions through access restricted external functions.

Therefore, there will be no mechanism to `pause/unpause` the contracts as required.

## Proof of Concept
Let`s use [DevFund](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/DevFund/DevFund.sol#L9) contract for example:
```solidity
import '@openzeppelin/contracts/security/Pausable.sol';
contract DevFund is IDevFund, Ownable, ReentrancyGuard, Pausable {
```
A seen this contract is `pausable`.

The issue here however is that the contract does not exposes the `_pause()` and `_unpause()` `internal` functions through access restricted `external` functions.
In [Pausable.sol](https://github.com/smiley159/f2p/blob/master/node_modules/@openzeppelin/contracts/security/Pausable.sol), the pause functionalities are all `internal` functions with `whenNotPaused` and `whenPaused` modifiers:
```solidity
    function _pause() internal virtual whenNotPaused {
        _paused = true;
        emit Paused(_msgSender());
    }

    function _unpause() internal virtual whenPaused {
        _paused = false;
        emit Unpaused(_msgSender());
    }
```
But to actually enable these functionalities, there has to be an `external/public` functions configured for it which is missing in this case.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement `external/public` functions with access control for these functionalities.
```diff
+   function pause() external onlyOwner {
+       _pause();
+   }

+   function unpause() external onlyOwner {
+       _unpause();
+   }
```
