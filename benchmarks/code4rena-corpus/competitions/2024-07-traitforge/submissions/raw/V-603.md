# Vulnerability details

## Description
When a user calls `buyNFT()` function with the desired `tokenId` and the correct `msg.value` matching the listing price, the function transfers the NFT from the contract to the buyer and distributes the proceeds between the seller and the `NukeFund`.

However, there is a potential issue in the calculation of the `nukeFundContribution` and `sellerProceeds`. The `buyNFT()` function uses the `taxCut` variable to determine the portion of the sale price that should be allocated to the `NukeFund`. The `nukeFundContribution` is calculated by dividing `msg.value` by `taxCut`: [#Lines 72-73](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L72-L73)

```solidity
uint256 nukeFundContribution = msg.value / taxCut;
uint256 sellerProceeds = msg.value - nukeFundContribution;
```

The issue arises when `taxCut` is set to zero. If `taxCut` is zero, it will cause a division by zero error when calculating `nukeFundContribution`, leading to the transaction reverting.

The `taxCut` variable is set using the `setTaxCut()` function, which is restricted to the contract owner: [#Lines 33](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L33-L35)

```solidity
function setTaxCut(uint256 _taxCut) external onlyOwner {
    taxCut = _taxCut;
}
```

However, the `setTaxCut()` function does not include any validation to ensure that `_taxCut` is greater than zero. This means that the contract owner can inadvertently or maliciously set `taxCut` to zero, causing the `buyNFT()` function to always revert due to the division by zero error.

## Impact

If the `taxCut` variable is set to zero, any attempt to purchase an NFT using the `buyNFT()` function will result in a division by zero error, causing the transaction to revert. This effectively renders the NFT trading functionality unusable until `taxCut` is set to a non-zero value.

## Proof of Concept

1. The contract owner calls the `setTaxCut()` function with a value of zero:
   ```solidity
   setTaxCut(0);
   ```
2. A user attempts to purchase an NFT by calling the `buyNFT()` function with the correct `tokenId` and `msg.value`.

3. Inside the `buyNFT()` function, the calculation of `nukeFundContribution` is performed: [#Line 72](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L72)
   ```solidity
   uint256 nukeFundContribution = msg.value / taxCut;
   ```
4. Since `taxCut` is zero, a division by zero error occurs, causing the transaction to revert.

5. The user's transaction fails, and they are unable to purchase the NFT.

## Tools Used
Manual review

## Recommended Mitigation Steps
add a validation check in the `setTaxCut()` function to ensure that `_taxCut` is always greater than zero:
```solidity
function setTaxCut(uint256 _taxCut) external onlyOwner {
+   require(_taxCut > 0, "Tax cut must be greater than zero");
    taxCut = _taxCut;
}
```
