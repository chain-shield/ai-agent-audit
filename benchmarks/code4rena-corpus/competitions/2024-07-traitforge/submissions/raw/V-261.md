# Vulnerability details

## Impact

When a function is internal this means that everyone can call the function if they inherit the contract the function is in and have a function which calls the parent function. In this vulnerability the case is the same as the function `DevFund::safeRewardTransfer` is just internal.

Impact: High
Likelihood: High

## Proof of Concept
1. Deploy all contracts in the project. 
2. Attacker waits for the project to be unpaused and everything starts working normally.
3. Attacker creates a new contract X which inherits `DevFund.sol`
4. Attacker creates a function inside the contract X which calls `DevFund::safeRewardTransfer` of its parent contract with `to` address as their own and an arbitrary `amount`.
   
## Tools Used
Solidity, VSCode

## Recommended Mitigation Steps

Just change the function from `internal` to `private`:
```solidity
  function safeRewardTransfer(
    address to,
    uint256 amount
+  ) private returns (uint256) {
-  ) internal returns (uint256) {
    uint256 _rewardBalance = payable(address(this)).balance;
    if (amount > _rewardBalance) amount = _rewardBalance;
    (bool success, ) = payable(to).call{ value: amount }('');
    require(success, 'Failed to send Reward');
    return amount;
  }
```

An alternative is to add access control, but provided that the function is used only in `DevFund::claim` making it `private` would fix this bug.
