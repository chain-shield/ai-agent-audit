# Vulnerability details

## Impact
Golden god can be generated in the first 2 entropy batch writings. This is contradictory to the documentation.

## Proof of Concept
The check `require(pseudoRandomValue != 999999, 'Invalid value, retry.'); `(https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L56) does not prevent a golden god to be written in the entropySlots variable.

For example:
assume that pseudoRandomValue = 99..999 (78 9's)
the check would fail since 99..999 (78 9's) != 999999.
This would cause 13 golden gods to be written, thus invalidating the check.

This is contradictory to the documentation:
(https://github.com/TraitForge/GitBook/blob/4b5c7835e65f8862e94675d2f04ccd3664aba905/GamePlay/Entropy.md?plain=1#L19)
`The Golden God is scanned for and is kept out of the first 2 passes, but is deliberately set in the final pass (at some random point)`

## Tools Used
Manual Review 

## Recommended Mitigation 
The check should rather be made for each of the 6 digits present in the pseudoRandomValue. This would require major code changes.
