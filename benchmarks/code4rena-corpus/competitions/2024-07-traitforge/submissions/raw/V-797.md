# Vulnerability details

## Impact
In the `calculateMintPrice` function, the price is incorrectly calculated as `startPrice` because `currentGeneration` exceeds `maxGeneration`.

## Proof of Concept
Within the forge function, if `newGeneration` equals `maxGeneration` and `generationMintCounts[newGeneration]` reaches `maxTokensPerGen`, the following code will execute.

```solidity
 function forge(
    address newOwner,
    uint256 parent1Id,
    uint256 parent2Id,
    string memory
  ) external whenNotPaused nonReentrant returns (uint256) {
    [...]
    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;

    [...]
@>  uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);

    return newTokenId;
  }
```
As a result, `currentGeneration` increments and becomes `maxGeneration + 1` in `_mintNewEntity`.
```solidity
    if (
      generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration
    ) {
@>    _incrementGeneration();
    }
```
Subsequently, when calling `calculateMintPrice`, the result is incorrectly set to `startPrice` because `generationMintCounts[currentGeneration]` is zero.
```solidity
  function calculateMintPrice() public view returns (uint256) {
@>  uint256 currentGenMintCount = generationMintCounts[currentGeneration];
@>  uint256 priceIncrease = priceIncrement * currentGenMintCount; //currentGenMintCount = 0
@>  uint256 price = startPrice + priceIncrease; //priceIncrease = 0
    return price;
  }
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Correct `calculateMintPrice` function as follows.
```solidity
  function calculateMintPrice() public view returns (uint256) {
    uint256 _currentGeneration = min(currentGeneration, maxGeneration);
    uint256 currentGenMintCount = generationMintCounts[_currentGeneration];
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```
