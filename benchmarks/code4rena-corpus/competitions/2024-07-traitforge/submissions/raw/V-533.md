# Vulnerability details

## Vulnerability Details
Entropy values should be random values and it needs to be hard to predict. The current implementation calculates the slot values using block number which is public for everyone. 

```solidity
uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue;
```

## Impact
Slots will be really easy to predict, so people easily compute their entropy values.
These slots are really important in the game mechanism because it defines the value of minted NFTs.

## Proof of Concept
Scenario:

After deployment and initializing the slots, Alice takes the block number of the transaction and she executes the same code for this block number. Now, she know all the slot values. She always tracks the minted NFT numbers using token id and calculates the position of best entropy values in the slots and she mints new NFTs and she always gets really valuable NFTs.

## Recommended Mitigation Steps
Random number generation was always a big consideration in blockchain. There are many approaches which generate good results. VRF ( Verifiable Random Function ) is one of them. It provides a off-chain solution for it. Chainlink has a service for VRF but it has costs. Some other methods can also appliable but using block number is definitely worst way to do that.
