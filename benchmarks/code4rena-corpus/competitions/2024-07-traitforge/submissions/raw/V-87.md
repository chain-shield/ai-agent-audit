# Vulnerability details

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/DevFund/DevFund.sol#L16

## Summary
10% of all income to the Nuke Fund is streamed to `DevFund`. `DevFund` contract is accountable for calculating the accumulated Ether and then it distributes the amount to the devs. 

## Impact
Any remaining Ether after integer division is permanently locked within the contract as there is no mechanism for the owner to extract these funds.
The Ether, intended for developer distribution, is stuck in the contract.

## Proof of Concept
The current implementation lacks a method for handling accumulated remainders from integer division and it is not accounting any precission loss from line 16.

```javascript 
DevFund.sol
14:   receive() external payable {
15:     if (totalDevWeight > 0) {
16:       uint256 amountPerWeight = msg.value / totalDevWeight; // @audit - precission loss. What if msg.value = 10000000 gwei and totalDevWeight = 300?
17:       uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
18:       totalRewardDebt += amountPerWeight;
19:       if (remaining > 0) {
20:         (bool success, ) = payable(owner()).call{ value: remaining }('');
21:         require(success, 'Failed to send Ether to owner');
22:       }
23:     } else {
24:       (bool success, ) = payable(owner()).call{ value: msg.value }('');
25:       require(success, 'Failed to send Ether to owner');
26:     }
27:     emit FundReceived(msg.sender, msg.value);
28:   }
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Use SafeMath and add a function in the contract that allows the owner to withdraw any Ether remaining in the contract, ensuring that leftover funds due to division truncation can be managed effectively.
