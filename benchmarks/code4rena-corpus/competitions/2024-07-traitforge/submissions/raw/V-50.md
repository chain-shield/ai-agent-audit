# Vulnerability details

## Impact
The forger NFT can be listed once more time after it has already been forged `forgePotential` times, leading to exceeded NFT forge.

## Proof of Concept
The function `listForForging()` does not correctly account for the current forge count during the listing process. If `forgingCounts[tokenId]` of a forger NFT reaches `forgePotential`, it can still be listed for forging (L88), allowing the NFT to be listed even when it has already been forged `forgePotential` times. The actual forge count is only incremented in the `forgeWithListed()` function (line 133), after the listing process.

```solidity
File: EntityForging.sol
67:   function listForForging(
	...
87:     require(
88:>      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
89:       'Entity has reached its forging limit'
90:     );

102:   function forgeWithListed(
	...
131:     // Check forger's breed count increment but do not check forge potential here
132:     // as it is already checked in listForForging for the forger
133:>    forgingCounts[forgerTokenId]++;
```

For example, given

- `forgePotential` of NFT = 1

The 1st time forge: `forgingCounts[tokenId]` = 0 when `listForForging()`, forge succeed.
The 2nd time forge: as `forgingCounts[tokenId]` = `forgePotential` = 1 when `listForForging()`, the NFT can still be `listForForging()`, forge succeed.
