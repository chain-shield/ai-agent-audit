# Vulnerability details

## Impact

The validator of the generated entropy slots is not correct, resulting in a small chance of generating a invalid entropy set.

## Description 
Based on the [WhitePaper](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit) there should not be a "Golden God" (entropy: 999999). It also states "he Golden God is scanned for and is kept out of the first 2 passes".

This is done in [writeEntropyBatch1](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L56) and [writeEntropyBatch2](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L76):
```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
require(pseudoRandomValue != 999999, 'Invalid value, retry.');
entropySlots[i] = pseudoRandomValue;
```

This check does not work, the pseudoRandomValue is a large uint256. The entropy is a 6 digit part of this larger number. It is read form the larger number in [getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L164-L185). Therefor each 6-digit block needs to be checked for the special number 999999.

## Proof of Concept

This bug only happens if the functions `writeEntropyBatch1` or `writeEntropyBatch2` is called at a specific time. This POC describes one of those examples:

The poc deploys `TraitForgeNft` and `EntropyGenerator`. The blocknumber does not matter. It starts writes the entropy for the first batch. Now we need to roll to one of the blocks where we encounter the bug. In this POC we use block 56. Now write the entropy for the second batch. The blocknumber for the third batch is not important.

If we now call `getPublicEntropy` with 418 and 3, we get the entropy stored in the slot 418 and the numberIndex 3. This entropy is 999999.

The POC produces the following logs:
- slotIndex:  418
- numberIndex:  3
- entropy:  57 999999


Full POC in foundry:
```
pragma solidity ^0.8.20;

import {Test, console} from "forge-std/Test.sol";
import {TraitForgeNft} from "../contracts/TraitForgeNft/TraitForgeNft.sol";
import {EntropyGenerator} from "../contracts/EntropyGenerator/EntropyGenerator.sol";


contract Test_POC is Test {
    function test_POC() public {
        // deploy and seed contracts
        TraitForgeNft nft = new TraitForgeNft();
        EntropyGenerator generator = new EntropyGenerator(address(nft));
        generator.writeEntropyBatch1();
        
        // set block to 56
        vm.roll(56);
        generator.writeEntropyBatch2();

        // assume this is called in the next block
        vm.roll(57); 
        generator.writeEntropyBatch3();

        // lookup slot 418 and number 3
        console.log("entropy: ", block.number, generator.getPublicEntropy(418, 3));
    }
}
```

## Probability

As this only happens at specific blocknumbers, lets look at the probability of this happening in real:

The chance for a 6-digit part in a entropy slot is: 
$$(1/10)^6$$

The probability that a slot is not 999999 is therefor: 
$$1 - (1/10)^6$$

The contract generates 512 slots in block one and two, with 13 entropy entries each. The probability for no 6-digit number in the first 512 slots is: 
$$(1 - (1/10)^6)^(512 * 13) = 0.993366$$

We are looking for when this is not the case:
$$1 - 0.99387483271 = 0.006634$$

So there is a 0.66 percent probability of creating a broken entropy map.

## Recommended Mitigation Steps

To verify the generated entropy, each number of the new slot should be checked individually:

```
for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
  uint256 pseudoRandomValue = uint256(
    keccak256(abi.encodePacked(block.number, i))
  ) % uint256(10) ** 78;
        
  for (uint256 numIndex = 0; numIndex < maxNumberIndex; numIndex++) {
    uint256 entropy = (pseudoRandomValue / (10 ** (72 - numIndex * 6))) % 1000000;
    require(entropy != 999999, 'Invalid value, retry.');
  }
        
  entropySlots[i] = pseudoRandomValue;
}
```

Notice: This will increase the gas used from an average of 5_782_237 to an average of 6_812_666.
