# Vulnerability details

## Impact
Check the `EntropyGenerator.initializeAlphaIndices()` method with the `onlyOwner` modifier: https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L206

This method is called in 2 places:
1. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L32
2. https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L353

When `initializeAlphaIndices()` is called from the `TraitForgeNft` contract the call will always revert because `TraitForgeNft` is not the owner of the `EntropyGenerator` contract thus blocking NFT forging.

Even if initial `EntropyGenerator` contract's owner transfers ownership to the `TraitForgeNft` contract then nobody will be able to call `EntropyGenerator.setAllowedCaller()` at https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L36 because there is no such call in the `TraitForgeNft` contract.

## Tools Used

Manual review

## Recommended Mitigation Steps

1. Add a new internal method `_initializeAlphaIndices()` which is called inside `EntropyGenerator.initializeAlphaIndices()`.
2. Remove `onlyOwner` modifier from `EntropyGenerator.initializeAlphaIndices()` and add `onlyAllowedCaller` modifier.
3. [Here](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L32) call the internal method `_initializeAlphaIndices()`.

This way `TraitForgeNft` will be able to call `EntropyGenerator.initializeAlphaIndices()` and "alpha indices" will be also set on `EntropyGenerator` contract creation.
