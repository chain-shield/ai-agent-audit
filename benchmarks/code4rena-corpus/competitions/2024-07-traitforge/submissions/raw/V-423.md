# Vulnerability details

## Impact

Malicious user can list NFT for sale on third-party marketplaces and list it for forging at the same time. They frontrun the buyer's transaction to forge with that NFT causing its value to decrease. That will cause the buyer to pay more for a less valuable token.


## Proof of Concept
When a NFT is listed for forging, it will leave the token with the owner. That allows them to execute any other transaction with that NFT. To prevent someone from selling a NFT that's listed for forging, the TraitForgeNFT contract overrides `beforeTokenTransfer()` to cancel any forging listings. When the user lists the NFT on the trading contract, it will transfer it to that contract triggering the `beforeTokenTransfer()` hook.

But, the user can also sell the NFT through 3rd party marketplaces that don't use immediate transfers when listing a token, e.g. OpenSea. There, you sign a message to list your token and only when the token is sold, it is transferred from your wallet to the buyer's. Thus, you can list your NFT for trading and at the same time also list it for forging.

A malicious user can then frontrun the buyer's transaction with another wallet and forge the NFT before it is sold. If that causes the NFT to surpass its forge potential, the NFT looses significant value because you can only forge again after a year.

1. Alice owns valuable NFT X which can forge one more time this year
2. Alice lists the token for sale on OpenSea
3. Bob buys the token because he wants to list it for forging and publishes the transaction to the mempool
4. Alice frontruns Bob's transaction to list the NFT for forging, and, using another wallet, forges with it.
5. Now, Alice's NFT can't be forged for another year, leaving Bob with a significantly less valuable NFT

None

## Recommended Mitigation Steps
Listing a token for forging should transfer that token to the EntityForging contract just like EntitiyTrading.
