# Vulnerability details

## Description
The whitepaper specifies a 2:1 ratio for Mergers to Forgers, but the contract uses `entropy % 3 == 0` for Forgers, which gives a 1:2 ratio instead.

## Impact
1. The ratio of Forgers to Mergers in the game will be inverted from what's intended.
2. This could significantly impact game balance and economy.
3. It may lead to unexpected gameplay dynamics not accounted for in the game design.

## Proof of Concept
With the current implementation:

* For entropy values 0, 3, 6, 9, ...: isForger = true
* For entropy values 1, 2, 4, 5, 7, 8, ...: isForger = false

This results in approximately 33% Forgers and 67% Mergers, inverse of the intended ratio.

## Tools Used

## Recommended Mitigation Steps
1. Adjust the role assignment logic to match the intended 2:1 Merger to Forger ratio:
```
uint256 role = entropy % 3;
isForger = role == 2;
```

2. Alternatively, use a different method to achieve the desired ratio, such as:
```
isForger = entropy % 3 < 1;
```
