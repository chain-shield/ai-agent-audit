# Vulnerability details

### Impact  

According to the original documentation, `ForgePotential` is determined by the 5th digit from the entropy. For instance, an entropy of `123456` means `ForgePotential` should be `5x`. However, in the current code implementation, `performanceFactor` is calculated using `entropy % 10`, which extracts the last digit instead of the 5th digit.  

This misimplementation causes the `ForgePotential` to be incorrectly determined, leading to entities being assigned inaccurate potential levels. This can disrupt the overall game balance and player strategy, as the intended entity capabilities are not represented accurately.  

### Proof of Concept  

Consider the following segment of code from the `deriveTokenParameters` function  and the `getFirstDigit` function:  

```solidity  
function deriveTokenParameters(  
    uint256 slotIndex,  
    uint256 numberIndex  
)  
  public  
  view  
  returns (  
    uint256 initialNukeFactor,  
    uint256 forgePotential,  
    uint256 performanceFactor,  
    bool isForger  
  )  
{  
  uint256 entropy = getEntropy(slotIndex, numberIndex);  

  // Incorrect calculation of ForgePotential  
@>  forgePotential = getFirstDigit(entropy); // This should be replaced with a method to get the 5th digit  
  
  performanceFactor = entropy % 10;  

  uint256 role = entropy % 3;  
  isForger = role == 0;  

  return (initialNukeFactor, forgePotential, performanceFactor, isForger); // return derived parameters  
}  

function getFirstDigit(uint256 number) private pure returns (uint256) {  
  while (number >= 10) {  
    number /= 10;  
  }  
  return number;  
}
```
Example Calculation Steps:
- Given entropy: 123456
- Documentation states: ForgePotential is the 5th digit
  Expected calculation for 123456: ForgePotential = 5
- Current code extracts the last digit:
  Current calculation: performanceFactor = 123456 % 10 = 6 (incorrect)
