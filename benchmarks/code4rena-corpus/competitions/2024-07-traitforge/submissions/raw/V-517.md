# Vulnerability details

## Impact
A generation might have more than 1 NFT with an entropy of 999999

## Proof of Concept
Each generation must have precisely 1 NFT with an entropy of 999999. For that to happen, the following check must be true:
```solidity
if (slotIndex == slotIndexSelectionPoint && numberIndex == numberIndexSelectionPoint) {
      return 999999;
    }
```
As seen in the code above, if we end up in that __if__ check, we will return out of the function and won't continue further down. If we do not end up in that case, we calculate the entropy like this:
```solidity
    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

    return paddedEntropy; // return the caculated entropy value
```
`paddedEntropy` is a 6-digit entropy an NFT will have in every case where we don't end up in the 999999 entropy NFT check (or the entropy == 0 edge case).

With that in mind, we can see that if we don't end up in the __if__ check for the 999999 entropy NFT, there is still a chance we get such an entropy from the code afterwards. Obviously, that would be very bad as each generation can have just 1 such NFT. The developer has thought about that and has implemented the following check:
```solidity
uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, i))) % uint256(10) ** 78;
require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```
The issue here is that this check is at a completely wrong place and checks for a completely wrong value. Firstly, the `pseudoRandomValue` is not actually the entropy but is used to compute the entropy, thus the check is completely ineffective and the case the developer has tried to handled, will not actually be handled leading to potentially multiple NFTs with an entropy of 999999.

## Recommended Mitigation Steps
Remove the checks for `pseudoRandomValue` and instead put the following in `getEntropy()`:
```solidity
...
uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
require(paddedEntropy != 999_999, "lol");
return paddedEntropy;
```
