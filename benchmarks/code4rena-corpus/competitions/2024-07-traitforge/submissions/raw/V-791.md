# Vulnerability details

## Description
There is a bug in `EntropyGenerator::getNextEntropy` which allow the player to continue minting even if EntropyGenerator is paused which seems to warrant `Medium`. 

The root cause is due to the fact that `getNextEntropy` is lacking `whenNotPaused` modifier which will allow players to continue minting as long as `TraitForgeNft` (and also Airdrop) is not paused even if EntropyGenerator is paused. The function should be guarded with the modifier since it's modifiying state function, similar to `initializeAlphaIndices` which is properly guarded.

## Impact
Player `still able to mint` even thought EntropyGenerator is `paused`.

## PoC
Add the following changes `TraitForgeNft.test.ts` and run `yarn test`
The test will pass prooving the impact validity.

## Recommended Mitigation Steps
Apply the following patch to resolve the issue.

```diff
  // function to retrieve the next entropy value, accessible only by the allowed caller
- function getNextEntropy() public onlyAllowedCaller returns (uint256) {
+ function getNextEntropy() public onlyAllowedCaller whenNotPaused returns (uint256) {
    require(currentSlotIndex <= maxSlotIndex, 'Max slot index reached.'); //@audit (L) should be currentSlotIndex < maxSlotIndex
    uint256 entropy = getEntropy(currentSlotIndex, currentNumberIndex);

    if (currentNumberIndex >= maxNumberIndex - 1) {
      currentNumberIndex = 0;
      if (currentSlotIndex >= maxSlotIndex - 1) {
        currentSlotIndex = 0;
      } else {
        currentSlotIndex++;
      }
    } else {
      currentNumberIndex++;
    }

    // Emit the event with the retrieved entropy value
    emit EntropyRetrieved(entropy);

    return entropy;
  }
```
