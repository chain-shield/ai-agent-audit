# Vulnerability details

There is an issue when calculating token age, which impact the finalNukeFactor to be a lower number as intended, which results in less claimable amount from the honeypot. 

The issue exists in the `calculateAge` method in the `NukeFund` contract, this function is called when a user will nuke its NFT and claim a portion of the funds in the contract. 

## Impact

Because the age is wrongly calculated it results in a less claimable amount the user can claim from the contract, resulting in less rewards for a user.

## Proof of Concept

add the following unit test to the `NukeFund.test.ts` 

```tsx

 it('should calculate the age of a token', async function () {
    const tokenId = 1;

    // verify token is minted and owner is owner of the token.
    const ownerOfTokenId = await nft.ownerOf(tokenId);
    expect(ownerOfTokenId).to.be.eq(owner.address);

    const age = await nukeFund.calculateAge(tokenId);
    expect(age).to.be.eq(0);

    // fast forward 1 year
    await fastForward(31556927); 

    const ageAfter = await nukeFund.calculateAge(tokenId);
    expect(ageAfter).to.be.eq(1); // still 0 years
 });
```

There are several reasons why the age results in 0. First the `ageMultiplier` is never set at deployment, so it will always result in 0 when calculating age

The other issue is from the `perfomanceFactor`, which returns the remainder of a division operation. In this case, it calculates `getTokenEntropy(tokenId) % 10`

The result of this operation will be between 0 and 9, when the result is 0, the age will always be 0, even if its 1 year or older.

```tsx
    uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10; 
    
    uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals
```

When the `adjustedAge` results in 0 the finelNukeFactor is impacted and results in a lower result

```tsx
uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;
```

The final result will be initialNukeFactor, which is basically just entropy result divided by 40

```tsx
uint256 initialNukeFactor = entropy / 40;
```

## Recommended mitigation steps

Implement validation based on the calculations parameter as ageMultiplier and perfomanceFactor, when the daysOld results in higher than 365, this way once an NFT is old enough the age impacts the nukeFactor and the user has motivation to hold the NFT longer. Otherwise users with a high entropy can just nuke their token and claim a higher portion from the contract.

```tsx
if (daysOld > 365) {
	if (perfomanceFactor == 0) {
	  perfomanceFactor = 1;
	}
	
	require(ageMultiplier > 0, "age multiplier not set");
}
```
