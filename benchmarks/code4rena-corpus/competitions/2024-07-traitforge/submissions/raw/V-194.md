# Vulnerability details

## Impact
Entropy values are stored in the entropySlot[770] private variable. Although being a private variable, Ethereum is a public blockchain, which means that any value or variable can be searched by looking at a smart contract's storage slots.

Users can look at the current value to be used and decide whether it is worth making an operation which involves getEntropy() or not, if the see a convenient value near. This incentivizes users to wait for the moment until that value comes and then try to get that value for them, which completely breaks the randomness the system is expected to have.

## Tools Used
Manual review

## Recommended Mitigation Steps
The recommended mitigation for this issue would involve a complete change in the system: if true randomness is required, entropy values should be calculated in real time by using a decentralized oracle like Chainlink.

Other possible and easier to implement solutions are to calculate values in real time the same way it is done in the current version of the contract (even though we should take into account that this is a deterministic way, so we could predict the outcome if we know the value of ```block.number```, which destroys randomess) or use a variable that sets a waiting time for a user why requests an entropy value, although this would make the system much slower.
