# Vulnerability details

## Description

The `EntityForging` contract implements a forging system where tokens have a limited number of times they can be forged, determined by their forge potential. This potential is derived from the token's entropy and is intended to restrict the number of forging operations per token. The contract includes a reset mechanism, implemented in the `_resetForgingCountIfNeeded()` function, which is designed to reset the forging count after a specified period (one year by default).

However, the current implementation of `_resetForgingCountIfNeeded()` contains a critical flaw. Instead of resetting the forging count to the token's forge potential, it resets it to zero. This allows users to bypass the intended forging limits, as they can forge a token up to its potential, wait for the reset period, and then forge again, repeating this process indefinitely.

## Impact
Tokens can be forged indefinitely over time, bypassing the intended forge potential limit. This undermines the intended forging limits and could lead to an imbalance in the token ecosystem, as tokens that should have limited forging potential can be forged repeatedly.


## Proof of Concept
1. Alice owns a token with a forge potential of 3.
2. Alice forges her token 3 times, reaching the forging limit.
3. Alice waits for one year to pass.
4. The `_resetForgingCountIfNeeded()` function is called (e.g., during a forging attempt), resetting the forging count to 0.
5. Alice can now forge her token 3 more times, despite having already reached the intended lifetime limit.
6. This process can be repeated indefinitely, allowing Alice to forge her token far beyond its intended limit.

## Recommended Mitigation Steps
Modify the `_resetForgingCountIfNeeded()` function to reset the forging count to the token's forge potential instead of zero. This ensures that the forging limit is properly maintained even after resets.

Here's the recommended fix:

```diff
function _resetForgingCountIfNeeded(uint256 tokenId) private {
    uint256 oneYear = oneYearInDays;
    if (lastForgeResetTimestamp[tokenId] == 0) {
        lastForgeResetTimestamp[tokenId] = block.timestamp;
    } else if (block.timestamp >= lastForgeResetTimestamp[tokenId] + oneYear) {
-       forgingCounts[tokenId] = 0; // Incorrect reset
+       uint256 entropy = nftContract.getTokenEntropy(tokenId);
+       uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
+       forgingCounts[tokenId] = forgePotential; // Reset to the forge potential
        lastForgeResetTimestamp[tokenId] = block.timestamp;
    }
}
```

This change ensures that the forging count is reset to the token's forge potential, maintaining the intended forging limits even after the reset period.
