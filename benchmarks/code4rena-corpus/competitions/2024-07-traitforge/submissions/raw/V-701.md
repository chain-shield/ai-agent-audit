# Vulnerability details

## Impact
The `TraitForge` protocol centers its operation around the idea of allowing users to mint unique NFTs, where each token should be one-of-a-kind and have distinct characteristics. However, this invariant can easily be broken as the protocol allows users to generate identical NFTs by using the game's unique `forging` mechanism.

## Proof of Concept
Players can acquire new tokens through minting and `forging`.When players mint, the NFTs' characteristics (governed by the term `entropy`) are randomly generated, thus producing different tokens. Forging, on the other hand, allows two users to combine their NFTs and produce a new generation token. However, this approach does not produce a random `entropy` as with minting but averages the entropies of the parent tokens.

Because of this, when the same `forger` and `merger` interact they will always produce the same offspring NFT, thus being able to flood the environment with identical tokens. To make matters even worse, the newly generated tokens can then be forged with other identical tokens, thus producing duplicates across multiple generations.

For the following tests I have used Foundry following HardHat's foundry [integration](https://hardhat.org/hardhat-runner/docs/advanced/hardhat-and-foundry) guide. The following tests can be run with `forge test --mt testForgingProducesIdenticalEntites`.

_NB: All of the below tests use the same set-up shown in the `Set up` details tab. For the next coded PoC, I have properly set the owner of the Airdrop and EntityGenerator to be the NFT contract, to remove any owner issues, as described in one of my issues._

 function testForgingProducesIdenticalEntites() public {
        vm.startPrank(naruto);
        nftContract.mintToken{value: nftContract.calculateMintPrice()}(proof); // 1
        vm.stopPrank();

        vm.startPrank(naruto);
        nftContract.mintToken{value: nftContract.calculateMintPrice()}(proof); // 2
        vm.stopPrank();

        vm.startPrank(naruto);
        nftContract.mintToken{value: nftContract.calculateMintPrice()}(proof); // 3
        vm.stopPrank();

        vm.startPrank(sasuke);
        nftContract.mintToken{value: nftContract.calculateMintPrice()}(proof); // 4
        vm.stopPrank();

        vm.startPrank(naruto);
        nftContract.mintToken{value: nftContract.calculateMintPrice()}(proof); // 5
        vm.stopPrank();

        uint8 narutoForgePotential = uint8((nftContract.getTokenEntropy(5) / 10) % 10);
        uint8 sasukeForgePotential = uint8((nftContract.getTokenEntropy(4) / 10) % 10);

        // Forger with forging potential
        assertTrue(nftContract.isForger(5));
        assertGt(narutoForgePotential, 0);

        // Merger with no forging potential
        assertFalse(nftContract.isForger(4));
        assertGt(sasukeForgePotential, 0);

        vm.startPrank(naruto);
        entityForging.listForForging(5, 0.01 ether);
        vm.stopPrank();

        vm.startPrank(sasuke);
        uint256 offspringA = entityForging.forgeWithListed{value: 0.01 ether}(5, 4); // 6
        vm.stopPrank();

        vm.startPrank(naruto);
        entityForging.listForForging(5, 0.01 ether);
        vm.stopPrank();

        vm.startPrank(sasuke);
        uint256 offspringB = entityForging.forgeWithListed{value: 0.01 ether}(5, 4); // 7
        vm.stopPrank();

        // Check that new forged entites have identical entropies
        assertEq(nftContract.getTokenEntropy(offspringA), nftContract.getTokenEntropy(offspringB));
    }

## Recommended Mitigation Steps

The easiest solution will be to disallow the same `forger` and `merger` to forge more than once, however, this does not guard from the case where we have a `forger` and `merger` with the sum of entropies A and a different set of `forger` and `merger` where the sum of entropies is A again. Another thing could be to not average the entropy but instead use the random generation as with minting. One final thought can be to add a way of storing the current occupied entropies and revert on forges that will produce an already existing one.
