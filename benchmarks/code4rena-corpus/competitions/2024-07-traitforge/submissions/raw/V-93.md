# Vulnerability details

## Impact
The `_taxCut` parameter in the `EntityTrading` contract can be set to `0`, which causes a division by zero vulnerability in the `buyNFT` function. 

This can have several impacts:

1. The calculation for distributing funds involves dividing the sale price by `_taxCut`. If `_taxCut` is `0`, this results in a division by zero error, causing the transaction to fail and potentially halting the contract's operation.
2. If the contract encounters a division by zero error, it may lead to transaction failures, impacting the availability of the contract for trading operations.
3. If the contract fails to distribute funds properly due to the division by zero, it could lead to unintended losses or mishandling of funds, affecting both buyers and sellers.

## Proof of Concept

1. Deploy the `EntityTrading` contract with `_taxCut` set to `0`.
2. List an NFT for sale with a specified price.
3. Attempt to buy the NFT by sending the required ETH.
4. The transaction will fail due to the division by zero error in the `buyNFT` function when trying to calculate `nukeFundContribution`.

## Tools Used
Manual Testing

## Recommended Mitigation Steps

Update the setter function for `_taxCut` to include a check that prevents setting it to `0`.

**Updated Function**

```solidity
function setTaxCut(uint256 _taxCut) external onlyOwner {
    require(_taxCut > 0, "Tax cut must be greater than zero");
    taxCut = _taxCut;
}
```

**Explanation:**
- The updated implementation ensures that `_taxCut` cannot be set to `0`, preventing division by zero errors.
- The check ensures that `_taxCut` has a meaningful value, maintaining proper functionality of the contract.
