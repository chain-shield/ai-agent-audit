# Vulnerability details

## Impact

In `EntropyGenerator` implementation, there is a function `getNextEntropy()` that's  used by `TraitForgeNft` contract to get the entropy of the next tokenId that's about to be minted to the user. The problem is that the slot index is reassigned to 0 after the final slot is reached and it allows to override and mint the same entropy to several users.

## Proof of Concept

`getNextEntropy()` nullifies the current slot index if the maximum slot is reached which allows to create the same entropy for some users:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L105-109
```
 if (currentNumberIndex >= maxNumberIndex - 1) {
      currentNumberIndex = 0;
      if (currentSlotIndex >= maxSlotIndex - 1) {
        currentSlotIndex = 0;
      }
```



## Tools Used

Manual review.

## Recommended Mitigation Steps

Don't update current slot index and just break the counter by changing generation.
