# Vulnerability details

**Summary:** 

The `updateDev` function in `DevFund.sol` allows the owner to arbitrarily manipulate user rewards by temporarily increasing a user's weight, potentially leading to unfair reward distribution and drainage of contract funds.

**Vulnerability Details:**

The `updateDev` function allows the contract owner to change a user's weight without restrictions. This can be exploited by:
- Temporarily increasing a user's weight
- Allowing rewards to accumulate at the higher rate
- Decreasing the weight back to its original value
- The accumulated rewards are not adjusted when the weight is decreased, allowing users to retain unfairly earned rewards.

**Impact:**

This vulnerability can lead to:

- Unfair distribution of rewards
- Potential draining of contract funds faster than intended
- Loss of trust in the reward system

**Recommended Mitigation:**

There are a few strategies below  that can add an extra layer of protection against extreme weight manipulations. They can be used individually or in combination, depending on the specific needs and risk tolerance of the protocol;

1. Implement a cooldown period in the `DevFund.sol` between weight updates (7 days is probably overkill, but it's an example):

  uint256 public totalDevWeight;
  uint256 public totalRewardDebt;

+  uint256 public constant WEIGHT_UPDATE_COOLDOWN = 7 days;
+  mapping(address => uint256) public lastWeightUpdateTime;

  receive() external payable {
    if (totalDevWeight > 0) {
      uint256 amountPerWeight = msg.value / totalDevWeight;

+  uint256 public constant CONFIRMATION_PERIOD = 3 days;
+  
+  struct PendingChange {
+    uint256 proposedWeight;
+    uint256 proposalTime;
+  }
+  
+  mapping(address => PendingChange) public pendingSignificantChanges;

+  function proposeSignificantWeightChange(address user, uint256 newWeight) external onlyOwner {
+    DevInfo storage info = devInfo[user];
+    uint256 changePercentage = (newWeight > info.weight) ?
+        ((newWeight - info.weight) * 100 / info.weight) :
+        ((info.weight - newWeight) * 100 / info.weight);

+    PendingChange storage change = pendingSignificantChanges[user];
+    require(change.proposalTime > 0, "No pending significant change");
+    require(block.timestamp >= change.proposalTime + CONFIRMATION_PERIOD, "Confirmation period not elapsed");

+    updateDev(user, change.proposedWeight);
+    delete pendingSignificantChanges[user];
+  }

These additions implement a two-step process for significant weight changes, requiring the owner to propose the change and then confirm it after a set period. This helps prevent accidental large changes and gives time for review or intervention if needed.
