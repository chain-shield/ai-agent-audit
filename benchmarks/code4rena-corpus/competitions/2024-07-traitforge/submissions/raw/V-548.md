# Vulnerability details

## Vulnerability Details
999999 value is a specific value which should be prevented while initialization in writeBatchEntropy() functions, because it's externally stored at random point in slots in following lines:

```solidity
function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    // slotIndex is between 512 to 769
    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```
```solidity
function getEntropy(
    uint256 slotIndex,
    uint256 numberIndex
  ) private view returns (uint256) {
    require(slotIndex <= maxSlotIndex, 'Slot index out of bounds.');

    if (
      slotIndex == slotIndexSelectionPoint &&
      numberIndex == numberIndexSelectionPoint
    ) {
      return 999999;
    }
```

This is why it's prevented while initialization:

```solidity
function writeEntropyBatch1() public {
    require(lastInitializedIndex < batchSize1, 'Batch 1 already initialized.');

    uint256 endIndex = lastInitializedIndex + batchSize1; // calculate the end index for the batch
    unchecked {
      for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78; // generate a  pseudo-random value using block number and index
        require(pseudoRandomValue != 999999, 'Invalid value, retry.');
        entropySlots[i] = pseudoRandomValue; // store the value in the slots array
      }
    }
    lastInitializedIndex = endIndex;
  }
```

The problem is 999999 value is not correctly prevented in 'require' line.

Entropy values are determined by specific position in specific slot index using slotIndex, numberIndex variables. Each slot has 78 digits numbers and those 78 digits is divided 6 by 6 in order to generate entropy values. But following line isn't checking those 13 amounts of 6 digits numbers.

```solidity
require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```

## Impact
- We can see sequential 999999 values in slots because of wrong checking ( low probability but it's possible )

## Tools Used
Manual Review

## Recommended Mitigation Steps
In order to check 999999 values in initialized slots we can use following code:

```solidity
uint256 position = 0;
while(position < 13){
    require(pseudoRandomValue / (10 ** (position * 6)) % 1000000 != 999999, 'Invalid value, retry.');
    position++;
}
```

In this implementation, we basicly check all, 6 digits numbers in pseudoRandomValue
