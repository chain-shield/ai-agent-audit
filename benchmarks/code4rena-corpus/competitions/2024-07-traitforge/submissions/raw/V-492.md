# Vulnerability details

## Impact
User can forge the same entropy twice deeming the entropy attribute not unique. Whenever a new forge is initiated there is a chance that an nft is going to be duplicate which is not supposed to happen per protocol specifics.
There is 2 ways an user can duplicate nft:

In forge() we have : uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;

1. forging the same merger token with the same forger token twice.
2. the sum of entropies is the same (sum / 2 will be equal to the same entropy, even sum - 1 if sum is an even number)

Impact - high (breaking a game mechanic, duplicating nft's)
Likelihood - high (it could happen two ways which both are quite likely to happen)
Overall - high

## Proof of Concept

Lets have Alice and Bob:

1st scenario:
1. Alice lists tokenId1 for forging with entropy 111_333
2. Bob accepts the forge with his merger tokenId2 with entropy 111_444
3. Bob gets the new tokenId3 with entropy 111_389 Alice gets the fee
4. Repeat 
5. Bob again gets the same nft with different tokenId4 but the entropy is again 111_389

2nd scenario:
Lets have Alice, Bob, James, Kyle

1. Alice lists tokenId1 for forging with entropy 111_333
2. Bob accepts the forge with his merger tokenId2 with entropy 111_444
3. Bob gets the new tokenId3 with entropy 111_389 Alice gets the fee
4. James lists tokenId4 for forging with entropy 111_233
5. Kyle accepts the forge with his merger tokenId5 with entropy 111_544
6. Kyle gets the same tokenId6 == tokenId with entropy 111_389
