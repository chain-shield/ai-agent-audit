# Vulnerability details

## Impact
The `receive()` function in `NukeFund.sol` calculates the developer's share `devShare` as `msg.value / taxCut`, where `taxCut` is typically set to `10` (representing a 10% share). If the incoming value `msg.value` is less than `taxCut` wei (e.g., less than 10 wei), `devShare` will be `zero` due to precession loss. As a result, the developer will not receive any funds, and the entire `msg.value` will be added to the fund balance.

## Proof of Concept
Consider the following scenario where the taxCut is 10:

1. **Incoming Payment:** A user sends 5 wei to the contract.
2. **Developer's Share Calculation:** devShare = 5 / 10 = 0 (integer division truncates the value to zero).
3. **Remaining Funds:** remainingFund = 5 - 0 = 5 (the entire payment is added to fund).

In this case, the developer's share is zero, and no funds are sent to the developer, although the entire amount is added to the fund.

```solidity
receive() external payable {
@>  uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
    uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund

    ...
}
```
