# Vulnerability details

## Impact
This bug allows a user to list an NFT that can never be purchased. By setting the fallback function of their smart contract to always revert, any Ether sent to their address as proceeds from the sale will fail. Consequently, the entire transaction to buy the NFT reverts, preventing any successful purchases. This leads to false listings on the website and clutters the marketplace.

## Proof of Concept
1. **Listing the NFT:** A user lists their NFT for sale on the platform.

2. **Manipulating the Fallback Function:** The user sets their fallback function in their smart contract to always revert, ensuring that any Ether sent to their address will fail. Example code for the fallback function:

```solidity
fallback() external payable {
    revert();
}
```

3. **Attempting to Buy the NFT:** Another user tries to purchase the listed NFT using the buyNFT function.

4. **Transaction Failure:** During the purchase process, the contract tries to transfer the proceeds to the seller (the user who listed the NFT) using the following code:

context: [here](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L77C1-L80C50)

```solidity
(bool success, ) = payable(listing.seller).call{ value: sellerProceeds }('');
require(success, 'Failed to send to seller');
```

Since the seller's fallback function always reverts, the transfer fails and the entire transaction is reverted.

5. **NFT Remains Listed:** The NFT remains listed on the platform and all attempts to buy it will fail due to the fallback function.




## Tools Used
foundry, vscode

## Recommended Mitigation Steps
Instead of sending Ether directly within the buyNFT function, update the contract to use a pull payment mechanism where the seller must withdraw the funds themselves.
