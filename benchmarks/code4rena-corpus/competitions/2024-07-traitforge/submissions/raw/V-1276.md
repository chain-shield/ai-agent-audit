# Vulnerability details

## Impact
- User can `nuke` NFT after holding it more than `minimumDaysHeld` period which is set as 3 days.
- It is checked by `canTokenBeNuked` function where it checks `uint256 tokenAgeInSeconds = block.timestamp -
      nftContract.getTokenLastTransferredTimestamp(tokenId)`.
- But when user list NFT for sale by `listNFTForSale` and then cancel listing by `cancelListing` function, in that `transferFrom` function is called and in which `_beforeTokenTransfer` is called.
- Now, in `_beforeTokenTransfer`, this mapping is updated to block.timestamp `lastTokenTransferredTimestamp[firstTokenId] = block.timestamp`.
- After this if user want to `nuke` NFT then user has to wait again for 3 days because mapping `lastTokenTransferredTimestamp` is reset to block.timestamp.

## Recommended Mitigation Steps
- Protocol has to make sure that if user list NFT for sale and then cancel it and now if user wants to nuke the NFT then user does not need to wait again for `minimumDaysHeld`.
- User can be nuke NFT after `minimumDaysHeld` period passed after minting NFT.
