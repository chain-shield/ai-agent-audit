# Vulnerability details

## Impact
The `nuke()` function assumes `maxAllowedClaimDivisor` will always be `2`, which may cause the `claimAmount` to exceed `maxAllowedClaimAmount` when the divisor is set to other values.

## Proof of Concept
In [`NukeFund::nuke()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L165-L172), `claimAmount` is determined as follows:
```solidity
    uint256 finalNukeFactor = calculateNukeFactor(tokenId); // finalNukeFactor has 5 digits
    uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR; // Calculate the potential claim amount based on the finalNukeFactor
    uint256 maxAllowedClaimAmount = fund / maxAllowedClaimDivisor; // Define a maximum allowed claim amount as 50% of the current fund size

    // Directly assign the value to claimAmount based on the condition, removing the redeclaration
>>  uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
      ? maxAllowedClaimAmount
      : potentialClaimAmount;
```
As seen above, `maxAllowedClaimAmount` defines a `maximum allowed claim amount of the current fund size`. Then, if `finalNukeFactor` is greater than `nukeFactorMaxParam`, `claimAmount` will be given as `maxAllowedClaimAmount` and viseversa otherwise.


#### SCENARIO 1: (*`maxAllowedClaimDivisor` = 2*)
**Given Values**:
- `fund` = 300 ETH
- `MAX_DENOMINATOR` = 100000
- `nukeFactorMaxParam` = 50000
- `defaultNukeFactorIncrease` = 250
- `finalNukeFactor` = 40000 // @audit-info finalNukeFactor < nukeFactorMaxParam
- `potentialClaimAmount` = (300 ETH * 40000) / 100000 = 120 ETH
- `maxAllowedClaimAmount` = 300 ETH / 2 = 150 ETH

**Result**:
- Since `finalNukeFactor <= nukeFactorMaxParam`, `claimAmount` should be `potentialClaimAmount`.
- `claimAmount = 120 ETH` (which is less than maxAllowedClaimAmount of 150 ETH).

**Effect**:
Consistency: `claimAmount` does not exceed `maxAllowedClaimAmount`. Claims are within the expected range, maintaining fund stability.

#### SCENARIO 2: (*`maxAllowedClaimDivisor` = 3*)
**Given Values**:
- `fund` = 300 ETH
- `MAX_DENOMINATOR` = 100000
- `nukeFactorMaxParam` = 50000
- `defaultNukeFactorIncrease` = 250
- `finalNukeFactor` = 40000 // @audit-info finalNukeFactor < nukeFactorMaxParam
- `potentialClaimAmount` = (300 ETH * 40000) / 100000 = 120 ETH
- `maxAllowedClaimAmount` = 300 ETH / 3 = 100 ETH

**Result**:
- Since `finalNukeFactor <= nukeFactorMaxParam`, `claimAmount` should be `potentialClaimAmount`.
- `claimAmount = 120 ETH` (which exceeds maxAllowedClaimAmount of 100 ETH).

**Effect**:
Inconsistency: `claimAmount` exceeds `maxAllowedClaimAmount`, breaking the intended cap.

As seen, `claimAmount` (120 ETH) is correctly capped by `maxAllowedClaimAmount` (150 ETH) only  with `maxAllowedClaimDivisor = 2`.

In other words, when:
- `maxAllowedClaimDivisor` = `2` ---> `maxAllowedClaimAmount` = `50%` of Nuke fund
- When `maxAllowedClaimDivisor` = `3` ---> `maxAllowedClaimAmount` = `33% `of Nuke fund

However, this value can always be changed by the `owner` via [`setMaxAllowedClaimDivisor()`]():
```solidity
  function setMaxAllowedClaimDivisor(uint256 value) external onlyOwner {
    maxAllowedClaimDivisor = value;
  }
```
Therefore, `maxAllowedClaimDivisor` can be set to any other value which can lead to `claimAmount` exceeding `maxAllowedClaimAmount` for that period. This can result in excessive claims.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Ensure `claimAmount` never exceeds `maxAllowedClaimAmount` by adjusting the logic accordingly:
```diff
-   uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
-     ? maxAllowedClaimAmount
-     : potentialClaimAmount;

+   uint256 claimAmount = potentialClaimAmount > maxAllowedClaimAmount
+     ? maxAllowedClaimAmount
+     : potentialClaimAmount;
```
