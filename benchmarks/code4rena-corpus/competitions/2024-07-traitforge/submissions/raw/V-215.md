# Vulnerability details

## Impact
A token can be forged more times than its `forgePotential`.

## Proof of Concept
In `listForForging`, it will require `forgingCounts[tokenId] <= forgePotential`.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L85-L90
```solidity
    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );
```

In `forgeWithListed`, `forgingCounts[forgerTokenId]` will be incremented without checking if `forgingCounts[tokenId] <= forgePotential`.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L131-L133
```solidity
    // Check forger's breed count increment but do not check forge potential here
    // as it is already checked in listForForging for the forger
    forgingCounts[forgerTokenId]++;
```

Due to `listForForging` being executed before `forgeWithListed`, this leads to being able to list and forge again even if `forgingCounts[tokenId] == forgePotential`.

For example:
1. Suppose `forgePotential` is 1
2. The first time list, `forgingCounts[tokenId]` is 0, passed the check.
3. Execute `forgeWithListed` to make `forgingCounts[tokenId]++`
4. Execute list again, `forgingCounts[tokenId]` is 1, still passed the check.
5. Since there is no check in `forgeWithListed`, it can be forged once more.
6. Finally, when `forgePotential` is 1, list and forge are executed 2 times.

When calculating potential for `mergeToken`, the approach of adding first and then checking is correct.

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityForging/EntityForging.sol#L139-L144
```solidity
    forgingCounts[mergerTokenId]++;
    require(
      mergerForgePotential > 0 &&
        forgingCounts[mergerTokenId] <= mergerForgePotential,
      'forgePotential insufficient'
    );
```
