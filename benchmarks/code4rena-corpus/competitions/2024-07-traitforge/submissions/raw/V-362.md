# Vulnerability details

## Impact
Users pay the wrong amount of ETH when minting an NFT in a certain case

## Proof of Concept
Users can call `mintToken()` to mint an NFT. There, we calculate the mint price like this:
```solidity
uint256 mintPrice = calculateMintPrice();
```
```solidity
function calculateMintPrice() public view returns (uint256) {
        uint256 currentGenMintCount = generationMintCounts[currentGeneration]; // How many minted tokens for current gen
        uint256 priceIncrease = priceIncrement * currentGenMintCount; // 0.0000245 ether * x
        uint256 price = startPrice + priceIncrease; // 0.005 ether + x
        return price;
      }
```
We use the amount of NFTs minted for the current generation and multiply that with the `priceIncrement`. Then, we add that to `startPrice`. Then, we call `_mintInternal()` to mint the NFT:
```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();

    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;
    
    ...
  }
```
There, we can see the following `if` check:
```solidity
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```
If the minted tokens for this generation are already at the max, we increment the generation. Then, we mint the NFT and update the following 2 mappings:
```solidity
tokenGenerations[newItemId] = currentGeneration;
generationMintCounts[currentGeneration]++;
```
We can clearly see that the minted NFT is based on that newly incremented generation (if we were at the max). However, the price we paid earlier was based on the previous generation and the price is significantly higher as the `currentGenMintCount` variable in `calculateMintPrice()` is equal to the maximum (10,000). 

Since the code allows users to provide `msg.value` of higher value than the mint price and then, get refunded for the excess, it is expected for users to pay more than required as they will get the excess refunded anyway, that way they don't face any unexpected reverts. However, this mistake will let them pay a lot more than required and they might even be minted an NFT from the generation they didn't actually want.

## Tools Used
Manual Review

## Recommended Mitigation Steps
I believe calling `_mintInternal()` before `calculateMintPrice()` would solve the issue.
