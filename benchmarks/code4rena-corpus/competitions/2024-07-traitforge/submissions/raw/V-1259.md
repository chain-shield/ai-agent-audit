# Vulnerability details

## Impact
- `_incrementGeneration()` would never work while calling mintNewEntity
- This happens due to wrong condition
`generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration`
- _mintNewEntity() gets called while `forge()` and inside the `forge()` 
`uint256 newGeneration = getTokenGeneration(parent1Id) + 1;` has been set to next upcoming generation.
- And this is passed inside _mintNewEntity as argument .
- Now putting this in equation 
`generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration`
here let's suppose currentGeneration = 1 ; and `gen` is coming from argument of _mintNewEntity which is set as  `uint256 newGeneration = getTokenGeneration(parent1Id) + 1;` which means `gen` would be equal to  2.
Hence 2==1 which is false so `_incrementGeneration()` never gets called  even if max tokens has been minted for a given generation.
