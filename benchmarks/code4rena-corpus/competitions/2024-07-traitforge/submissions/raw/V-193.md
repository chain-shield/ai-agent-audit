# Vulnerability details

`TraitForgeNft` contract allows users to mint new tokens, with a limit of `maxTokensPerGen` tokens per generation. When the limit for the current generation is reached, the `_incrementGeneration()` function is called to increment the `currentGeneration` and reset the `generationMintCounts` for the new generation.

So, there is an issue in the way the generation is incremented, which allows minting more tokens than intended in a generation. The [_incrementGeneration()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355) function is a private function that is called from within the [_mintInternal()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L280-L309) function.

```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
        _incrementGeneration();
    }
    // ...
}
```
The fact that `_incrementGeneration()` can be called multiple times within the same transaction if `_mintInternal()` is called repeatedly. This can happen when a user calls the [mintWithBudget()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225) function, which allows minting multiple tokens in a single transaction until the provided budget is exhausted.

As a result, the `currentGeneration` can be incremented by more than 1 in a single transaction, effectively skipping generations and allowing more tokens to be minted in the skipped generations.

## Impact
This issue allows minting more tokens than the intended [maxTokensPerGen](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L22) limit per generation. An attacker can exploit this by calling [mintWithBudget()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202-L225) with a large enough budget to trigger multiple generation increments in a single transaction.

As a result, the attacker can mint a large number of tokens in the skipped generations, exceeding the intended limits and potentially gaining an unfair advantage in the ecosystem.

## Proof of Concept
1. Assume the current state is:

    - `currentGeneration` is 0
    - `generationMintCounts[0]` is 9999 (one token away from the limit)
    - `maxTokensPerGen` is 10000

2. Attacker calls `mintWithBudget()` with a budget sufficient to mint 3 tokens.

3. Inside `mintWithBudget()`, the first call to `_mintInternal()` mints one token, increasing `generationMintCounts[0]` to 10000 and triggering a call to `_incrementGeneration()`.

4. `_incrementGeneration()` increments `currentGeneration` to 1 and resets `generationMintCounts[1]` to 0.

5. The next call to `_mintInternal()` mints another token, increasing generationMintCounts[1] to 1. Since the budget still allows minting one more token, `_mintInternal()` is called again.

6. The third call to `_mintInternal()` mints the last token, increasing `generationMintCounts[1]` to 2. However, this also triggers another call to `_incrementGeneration()`, which increments `currentGeneration` to 2 and resets `generationMintCounts[2]` to 0.

7. As a result, the attacker managed to mint:

    - 1 token in generation 0
    - 2 tokens in generation 1
    - Skipped generation 2 entirely

## Recommended Mitigation Steps
ensure that `_incrementGeneration()` is called only once per transaction, even if `_mintInternal()` is called multiple times by adding a flag to track whether the generation has already been incremented in the current transaction.
```diff
+  bool private _generationIncremented;

  function _mintInternal(address to, uint256 mintPrice) internal {
      if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
+         if (!_generationIncremented) {
              _incrementGeneration();
+             _generationIncremented = true;
+         }
      }
      // ... rest of the minting logic
  }

+  function _beforeTokenTransfer(...) internal virtual override {
+     _generationIncremented = false;
+     super._beforeTokenTransfer(...);
+  }
```
