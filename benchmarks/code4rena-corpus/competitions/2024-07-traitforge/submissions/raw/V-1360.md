# Vulnerability details

## Impact
The `mintWithBudget` function will be blocked after 1000 NFTs are minted. Before calling the `_mintInternal` function in the while loop, one of the required checks that should be true is `_tokenIds < maxTokensPerGen`. The variable `_tokenIds` stores how many tokens are minted, while `maxTokensPerGen` is the maximum number of tokens that can be minted per generation.

After minting the first generation and starting the minting of the second generation, if users try to mint some NFTs in one transaction using `mintWithBudget`, the transaction will fail because `_tokenIds < maxTokensPerGen` will always be false.

```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);

      amountMinted++;
      budgetLeft -= mintPrice;

      mintPrice = calculateMintPrice();
    }
```


```solidity
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
```

## Recommended Mitigation Steps
Remove this check, or if you want to limit the minting of tokens to the same generation, replace `_tokenIds < maxTokensPerGen` with `generationMintCounts[currentGeneration] < maxTokensPerGen`.
