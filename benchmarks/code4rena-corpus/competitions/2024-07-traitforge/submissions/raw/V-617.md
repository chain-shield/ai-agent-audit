# Vulnerability details

## Impact
Incorrect check logic allows Forger entities to forge one more time than their `forgePotential` value, while Merger entities are limited to exactly their `forgePotential` number of forges. This discrepancy creates an unfair advantage for Forger entities.

## Proof of Concept
The 5th digit of the `entropy` determines the `forgePotential` of an NFT. The related check logic is in the `EntityForging` contract, as follows:

```solidity
function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    // skip

    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );

    // skip
  }

function forgeWithListed(
    uint256 forgerTokenId,
    uint256 mergerTokenId
  ) external payable whenNotPaused nonReentrant returns (uint256) {
    // skip

    // Check forger's breed count increment but do not check forge potential here
    // as it is already checked in listForForging for the forger
    forgingCounts[forgerTokenId]++;

    // Check and update for merger token's forge potential
    uint256 mergerEntropy = nftContract.getTokenEntropy(mergerTokenId);
    require(mergerEntropy % 3 != 0, 'Not merger');
    uint8 mergerForgePotential = uint8((mergerEntropy / 10) % 10); // Extract the 5th digit from the entropy
    forgingCounts[mergerTokenId]++;
    require(
      mergerForgePotential > 0 &&
        forgingCounts[mergerTokenId] <= mergerForgePotential,
      'forgePotential insufficient'
    );
    
    // skip
  }
```

Clearly, for the Merger, the check logic in `forgeWithListed` is: if the forgePotential is `N`, it can forge with the Forger `N` times. However, for the Forger, the check logic in `listForForging` is: if the forgePotential is `N`, it can forge with the Merger `N + 1` times. This is evidently illogical and will result in the Forger being able to forge more times than the Merger when the `forgePotential` is the same (excluding 0 which represents infertile).

## Recommended Mitigation Steps
Change the `listForForging` to code below:
```diff
function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    // skip

    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
-      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
+      forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
      'Entity has reached its forging limit'
    );

    // skip
  }
```
