# Vulnerability details

## Impact
By using block.number and block.timestamp to generate randomness, players can check the results of the random draw beforehand and decide to execute the transaction only when it is favorable to them. This grants some players who are exploiting this an unfair advantage.

## Proof of Concept

The pseudorandom value for token entropy generated in the getEntropy function is used to define a token's nukeFactor and forge potential, so players can mint a token whenever the pseudorandom value is an advantage for them.

Similar to this issue:
https://solodit.xyz/issues/m-06-bad-source-of-randomness-code4rena-holograph-holograph-contest-git

## Tools Used
Manual Review

## Recommended Mitigation Steps

Consider using a decentralized oracle such as Chainlink VRF to generate random values.
