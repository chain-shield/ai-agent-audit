# Vulnerability details

## Impact

_incrementGeneration() increases the currentGeneration and then sets the ```generationMintCounts[currentGeneration] = 0 ```, but this results in losing track of the number of forged tokens in that generation, which then causes more than the maxTokensPerGen number of tokens to be present in each generations and also affect the mintPrice of the other users.

## Proof of Concept

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L351
```Solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

Suppose the currentGeneration = 1, generationMintCounts[1] = 9999 and say around 5000 forge operations have been performed , which sets generationMintCounts[2]=5000
and then one user mints and the generationMintCounts[1] = 10000 and then _incrementGeneration() is called which sets currentGeneration =2 and generationMintCounts[2]=0 
This results in losing track of the forged entities and results in more than 10000 entities in the each generations. This greatly affects many calculations and also the mintPrice will also be worngly calculated.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Either _incrementGeneration() should not set the generationMintCounts of the next generation to 0 or the count of entities for forged entities should be handled separately.
