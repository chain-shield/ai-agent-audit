# Vulnerability details

## Impact
The`writeEntropyBatch2` function uses an incorrect calculation for the `endIndex`, which could lead to the function not being able to initialize all intended slots in the second batch or the function may attempt to initialize more slots than necessary, leading to higher gas consumption.


## Proof of Concept
The `endIndex` in the [`writeEntropyBatch2` function](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntropyGenerator/EntropyGenerator.sol#L64-L81) is calculated like this`:

```solidity
uint256 endIndex = lastInitializedIndex + batchSize1;
```

This calculation is incorrect because `lastInitializedIndex` is already at 256 after the first batch and `batchSize1` is 256. While this would result in a correct `endIndex` being set to 512 in this context, but let's assume `batchSize1` is changed to 128 change, only 256 would be initialized in `writeEntropyBatch2` instead of the intended 512 slots.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Replace the current line:

```solidity
uint256 endIndex = lastInitializedIndex + batchSize1;
```

with:

```solidity
uint256 endIndex = batchSize2;
```

This will ensure that the second batch correctly initializes slots up to the 512th slot (index 511), regardless of the value of `lastInitializedIndex`.
