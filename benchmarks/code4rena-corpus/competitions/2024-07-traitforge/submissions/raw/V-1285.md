# Vulnerability details

## vulnerability summary
Forging potential determines the number of times 
a token can forge in an year.

When forging new NFTs thru `forgeWithListed` function,
It is required that both parents belong to the same generation.

```
require(
      nftContract.getTokenGeneration(mergerTokenId) ==
        nftContract.getTokenGeneration(forgerTokenId),
      'Invalid token generation'
      );
```
The following statement calculates the generation of the new entity, 
which is one more than the generation of the parent1 (forger).

```
uint256 newGeneration = getTokenGeneration(parent1Id) + 1;
```

After which the `_mintNewEntity` function has the following condition 
to restrict minting new entities 
beyond the allowed `maxTokensPerGen` which is set to 10000.

```

require(
      generationMintCounts[gen] < maxTokensPerGen,
      'Exceeds maxTokensPerGen'
       );
```
However, when the calculated `newGeneration` is less than the `currentGeneration`,   
the `newGeneration` would already be at full capacity of 10000 tokens.

In such cases, Even if the parentIDs have Forging potential, 
all forging attempts will be reverted forever.

## Impact

Further forging attempts from parent IDs of older generations 
could be blocked even if they have forging potential.

## Proof of Concept

1. Initial State
```
currentGeneration = 3
Generation 1 has 10,000 tokens (at max capacity)
Generation 2 has 10,000 tokens (at max capacity)
Generation 3 has 5,000 tokens.
```
2. Forging Scenario

Assume an attempt to forge a new entity thru `forgeWithListed`
using `forgerTokenId` and `mergerTokenId`, both of which belong to Generation 1.

The function attempts to mint a new NFT in Generation 2. 

Since `generationMintCounts[2] = 10000`, 
which is already at the maximum token limit for Generation 2, 
the require statement in `_mintNewEntity` reverts 
```

require(
      generationMintCounts[gen] < maxTokensPerGen,
      'Exceeds maxTokensPerGen'
       );
```

## Tools Used

Foundry

## Recommended Mitigation Steps

To address this, 
we need to ensure that forging can occur 
without hitting the token limit of intermediate generations. 

```
while (generationMintCounts[newGeneration] >= maxTokensPerGen) {       
	        newGeneration++;
	}
    
require(newGeneration <= maxGeneration, "can't be over max generation");    
```

One approach is to modify the `newGeneration` calculation inside the `forge` function
to ensure that if the `newGeneration` is already full, 
it increments the `newGeneration` until it finds 
an available slot in subsequent generations without exceeding the `maxGeneration`.
