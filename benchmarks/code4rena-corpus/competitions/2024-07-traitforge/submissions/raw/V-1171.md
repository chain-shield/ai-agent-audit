# Vulnerability details

## Impact

In `EntityForging::listForForging()` on [L88](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L88), the method checks how many times a token can be forged using the `forgingCounts` mapping. However, the incorrect equality operator `<=` is used instead of `<`, which inadvertently allows a token to be forged one more time than intended.

```solidity
function listForForging(
    uint256 tokenId,
    uint256 fee
) public whenNotPaused nonReentrant {
    ....

    uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
    uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
    require(
@-->    forgePotential > 0 && forgingCounts[tokenId] <= forgePotential, // @audit <= should be <
        'Entity has reached its forging limit'
    );

    ...
}
```

### Proof of Concept

1. Alice has a token with entropy 245319, allowing her to forge it 1 time.
2. Alice forges the token.
3. Alice tries to forge the token again, but the contract incorrectly allows it.

## Recommended Mitigation Steps

Change line [L88] as follows:

```solidity
require(
-   forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
+   forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
    'Entity has reached its forging limit'
);
```
