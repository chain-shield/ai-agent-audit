# Vulnerability details

## Description
In the EntityTrading contract, specifically within the buyNFT function, there is an oversight where the listedTokenIds mapping is not deleted after a token is purchased and its corresponding listing is removed from the listings mapping. This results in stale data persisting in the listedTokenIds mapping, which could lead to inconsistencies and potential logical errors in the contract's state management.

## Impact
The impact of this issue is primarily related to data integrity and contract cleanliness. While it may not directly lead to financial loss, the presence of invalid data could cause confusion, lead to incorrect assumptions in future contract interactions, and potentially be exploited in unforeseen ways if other parts of the contract or external contracts interact with these mappings. Additionally, it wastes gas for users and storage space on the Ethereum network, as the contract state is larger than necessary.

## Recommended Mitigation Steps
To resolve this issue, the listedTokenIds entry for the token should be deleted whenever a listing is removed. This can be achieved by adding a line of code in the buyNFT function to delete the entry after the listing is deleted. Here is the suggested code modification:

    Listing memory listing = listings[listedTokenIds[tokenId]];
    require(msg.value == listing.price, 'ETH sent does not match the listing price');
