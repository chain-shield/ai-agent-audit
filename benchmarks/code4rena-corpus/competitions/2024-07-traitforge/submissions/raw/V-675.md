# Vulnerability details

## Impact
The current implementation of `_incrementGeneration` function sets `generationMintCounts[currentGeneration]` to zero without properly incrementing the generation count, which can lead to incorrect mint counts for the next generation. This could potentially result in lost tokens and unexpected behavior in the minting process.

## Proof of Concept
When `generationMintCounts[currentGeneration]` reaches `maxTokensPerGen`, the `_incrementGeneration` function is called. This function sets `generationMintCounts[currentGeneration]` to zero, which can inadvertently reset the mint count for the next generation if it has already started minting tokens.
