# Vulnerability details

### Impact  

The `forge` function and `mintToken` function handle the initialization of `generationMintCounts` inconsistently. When a new generation starts from `mintToken`, `generationMintCounts[currentGeneration]` is reset to `0`. However, when starting a new generation through the `forge` function, `generationMintCounts` can be set directly without such reinitialization. This can lead to incorrect counts being stored, affecting the maximum tokens per generation limit and token distribution economics.  

### Proof of Concept  

Consider the following flow:  

1. **mintToken**:  
    - Calls `_mintInternal`, which increments `currentGeneration` and sets `generationMintCounts[currentGeneration]` to `0` if the token limit is exceeded.  
  
2. **forge**:  
    - Directly increments `generationMintCounts[gen]` without reinitializing.  

**Code Snippet Extract:**  

```solidity  
function forge(  
    address newOwner,  
    uint256 parent1Id,  
    uint256 parent2Id,  
    string memory  
) external whenNotPaused nonReentrant returns (uint256) {  
    require(  
        msg.sender == address(entityForgingContract),  
        'unauthorized caller'  
    );  
    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;  

    // Check new generation is not over maxGeneration  
    require(newGeneration <= maxGeneration, "can't be over max generation");  

    // Calculate the new entity's entropy  
    (uint256 forgerEntropy, uint256 mergerEntropy) = getEntropiesForTokens(parent1Id, parent2Id);  
    uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;  

    // Mint the new entity  
    uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);  

    return newTokenId;  
}  

function _incrementGeneration() private {  
    require(  
        generationMintCounts[currentGeneration] >= maxTokensPerGen,  
        'Generation limit not yet reached'  
    );  
    currentGeneration++;  
    generationMintCounts[currentGeneration] = 0;  
    priceIncrement = priceIncrement + priceIncrementByGen;  
    entropyGenerator.initializeAlphaIndices();  
    emit GenerationIncremented(currentGeneration);  
}
```

## Recommended Mitigation Steps
1. Remove the Line: Remove generationMintCounts[currentGeneration] = 0; from the _incrementGeneration function.
2. Ensure Consistent Generation Incrementation: Make sure that both minting and forging use the same logic to increment the generation, leveraging the _incrementGeneration function when necessary.

Example Mitigation Code:
Refactor the code to use a unified incrementGeneration function:
```diff
function _incrementGeneration() private {  
    require(  
        generationMintCounts[currentGeneration] >= maxTokensPerGen,
```
