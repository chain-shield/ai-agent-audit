# Vulnerability details

## Impact
Users will not be able to use `mintWithBudget()` after the first generation

## Proof of Concept
Users can call `mintWithBudget()` to continuously mint NFTs according to their set budget:
```solidity
  function mintWithBudget(bytes32[] calldata proof)
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```
We use a `while` loop with a set condition that if we break, we exit out of the loop:
```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen)
```
The issue is that the check is not correct. It allows minting while `_tokenIds` is less than `maxTokensPerGen`. `_tokenIds` is essentially the total NFTs minted as that value is only incremented upon mints. `_maxTokensPerGen` is the maximum amount of NFTs that can be minted for a particular generation. These 2 values are not really related, the check essentially disallows users to mint when the NFTs minted are more than the maximum for a particular generation which means that if we are in the second generation, using `mintWithBudget()` would not be possible as the minted NFTs would be more than the amount allowed in a single generation.

## Tools Used
Manual Review

## Recommended Mitigation Steps
I assume the check is supposed to check whether the NFTs minted in this generation are less than the maximum allowed for a generation, that way users don't end up accidentally minting for the next generation when they didn't mean to. If that's the case, use `generationMintCounts[currentGeneration]` instead.
