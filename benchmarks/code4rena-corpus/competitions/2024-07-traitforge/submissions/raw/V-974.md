# Vulnerability details

## Impact
In order to mint new NFT's, users can potentially pay way less than the actual mint price. 

The same person could mint (with one or more differents accounts) a forger NFT and a merger NFT, if this happens, the user may list the forger NFT and buy it with the merger NFT, paying only 10% (because 90% returns to himself and 10% are fees). 

By doing this he can mint almost for free (only paying the 10 % of the forger list) new NFT's. 

Let's imagine a scenario when minting an NFT costs 0.01 ETH, the user can list his forger NFT at 0.01 ETH and instantly (maybe also in the same transaction) buy it with a merger NFT. 
Result: He will be able to mint a new NFT only by paying 0.001 ETH (10% tax).

This may have an high impact on the game, since by doing this continuosly, users can mint NFT's paying almost nothing, and then they may nuke them in order to receive some eth. 

The problem is that by doing this they may get a large portion of the NukeFund balance, and all others NFTs will lose their values when nuking.

vm.startPrank(owner); 
//Here the owner sets all the contracts 
traitForgeNft.setEntityForgingContract(address(entityForging));
traitForgeNft.setAirdropContract(address(airdropContract));

address user1Account1 = address(123); 
address user1Account2 = address(124); 
//Assigning 1 ether to account 1 and account 2
deal(user1Account1, 1 ether); 
deal(user1Account2, 1 ether); 

skip(2 days);
bytes32[] memory proof = new bytes32[](1); 
proof[0] = keccak256(abi.encode("Hi")); 

vm.startPrank(user1Account2); 
//Here the account 2 mint 4 NFTs
traitForgeNft.mintToken{value: 0.005 ether}(proof);
traitForgeNft.mintToken{value: 0.005 ether + 0.0000245 ether}(proof);
traitForgeNft.mintToken{value: 0.005 ether + (0.0000245 ether * 2)}(proof);

//Here account 1 lists his forger NFT
entityForging.listForForging(5, forgingFee);

assertEq(traitForgeNft.ownerOf(6), user1Account2); //After, Account 2 has also the new minted nft
}

Manual review / Foundry
 
## Recommended Mitigation Steps
In order to avoid this, consider changing the listing forge fee logic, increase the ninimal fee required to list, or add a logic that ensures that the listing fee is always proportional to the current mint price.
