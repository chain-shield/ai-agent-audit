# Vulnerability details

**Impact**
The function `intializeAlphaIndices` in the `TraitForgeNft::_incrementGeneration` function, however the function has the `onlyOwner` modifier which will make it impossible for the `TraitForgeNft` contract to call it. While it is possible for the team to transfer ownership to the `TraitForgeNft` contract to allow it to successfully call this function, it would mean they are no longer able to call `EntropyGenerator::setAllowedCaller` as the `TraitForgeNft` contract has no logic to allow it to do this. On top of this it would also be impossible to transfer the ownership back from the contract as it also lacks the logic to do this.

**Recommended Mitigation**
The key issue when mitigating this issue is that the function is called once in the constructor of `EntropyGenerator` and then in future by the `TraitForgeNft` contract. This means that simply changing the modifier from `onlyOwner` to `onlyAllowedCaller` would not be sufficient and would result in the call during the constructor failing. The recommended remedy to this would be to add an internal `_initializeAlphaIndices` function, which can be called in the constructor, and then also be called by the existing `initializeAlphaIndices` function but with the correct modifier like so:
```diff
    --- Snip
    
    constructor(address _traitForgetNft) {
      allowedCaller = _traitForgetNft;
-     initializeAlphaIndices();
+     _initializeAlphaIndices();
    }
```
```solidity

  function initializeAlphaIndices() public whenNotPaused onlyAllowedCaller {
    _initializeAlphaIndices();
  }

  function _initializeAlphaIndices() internal {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```
