# Vulnerability details

## Impact
In the EntityTrading contract, there are multiple scenarios where an NFT buyer can potentially cause a Denial of Service (DoS) attack against the seller during the buyNFT process. The buyer can exploit several vectors to prevent the transaction from completing, such as:
1. Reverting When Funds are Sent: If the sellers address is a contract with a fallback function that reverts when receiving funds, it can cause the transaction to fail.
2. Canceling Beforehand: The seller can monitor the blockchain for the transaction and cancel it before it completes.

## Proof of Concept
1. The seller lists an NFT for sale by calling listNFTForSale().
2. A buyer initiates the purchase process by calling buyNFT().
3. The seller can use one of the aforementioned methods to cause the transaction to fail, leading to a denial of service for the buyer.

Manual Code Review

## Recommended Mitigation Steps
The issue can be addressed by allowing the seller to claim their funds instead of transferring them immediately.It can be implemented in the following way.

1. Tracking Pending Withdrawals: Add a mapping to store the funds owed to each seller.
```js
mapping(address => uint256) public pendingWithdrawals;
```
2. Updating the Buy Function: Modify the buyNFT function to update the pending withdrawals rather than transferring the funds immediately.
```js
// Add the seller's proceeds to the pending withdrawals
pendingWithdrawals[listing.seller] += sellerProceeds; 
```
3. Implementing a Claim Function: Add a function that allows buyers to claim their pending funds.
```js
function claimFunds() external nonReentrant {
    uint256 amount = pendingWithdrawals[msg.sender];
    require(amount > 0, "No funds to claim");

    pendingWithdrawals[msg.sender] = 0;

    (bool success, ) = msg.sender.call{ value: amount }('');
    require(success, "Claim failed");

    emit FundsClaimed(msg.sender, amount);
}
```
