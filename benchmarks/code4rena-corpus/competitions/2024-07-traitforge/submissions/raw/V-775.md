# Vulnerability details

The calculation for the nuke factor is incorrect, as it would take decades for an **unlucky entity** to reach 50% as a Nuke Factor, and for a lucky entity, it would still take more than a decade.

According to the rules of "common sense," this is unexpected behavior. The docs also confirm that this is incorrect, as mentioned [here](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit).
>  Entities move from their initial Nuke Factor (set randomly) towards the maximum with a speed dictated by Performance Factor (set randomly). Some mature faster than others, with the fastest maturing in around 30 days, and slowest 600 days.

## Vulnerability details

Defining "**unlucky entity**." **Unlucky entity** refers to an entity with an entropy value close to the minimum entropy (i.e., `100,000`), being non-zero, with a low, but non-zero, performanceFactor.
The performanceFactor is determined by the following equation: `entropy % 10`, i.e., the last digit of the 6-digit entropy.
Lucky entity, is the oposite, i.e., high entropy, high performanceFactor, like 999999.

The current implementation incorrectly uses the wrong denominator in the `calculateAge()` function in NukeFund.sol, according to these [docs](https://github.com/TraitForge/GitBook/blob/main/TraitForger%20Entity/Nuke%20Factor.md).

> AgeInDays is calculated separately and represents how long the token has been "alive" or active since its creation. The calculation ageInDays * 250 / 10000 effectively scales the age to have a proportionate impact on the NukeFactor (2.5% increase), ensuring that older entity's can have a potentially higher influence or value.

But, in the code for [calculateNukeFactor](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L147-L148) we use 100,000 as Denominator instead of 10,000, as its mentioned.

However, in reality, a denominator of 10,000 would still be inaccurate because, with entropy 999999, for 30 days we would gain only about 1.8%. To get closer to the idea of about 30 days for 50%, we would have to use a denominator of 1000 or even less, like 800-900.

This issue converts to a loss of capital, due to a loss of yield.

import {Test} from "forge-std/Test.sol";

import {DevFund} from "../contracts/DevFund/DevFund.sol";
import {EntityTrading} from "../contracts/EntityTrading/EntityTrading.sol";
import {EntropyGenerator} from "../contracts/EntropyGenerator/EntropyGenerator.sol";

contract FoundryTest is StdInvariant, Test {
    /* Main Contracts */
    EntropyGenerator public entropyGeneratorContract;
    EntityTrading public entityTradingContract;
    EntityForging public entityForgingContract;
    TraitForgeNft public nftContract;
    NukeFund public nukeFundContract;

    /* Misc Contracts */
    Airdrop public airdropContract;
    DevFund public devFundContract;

    /* User Addresses */
    address NFT_OWNER = makeAddr("nftOwner");

    function setUp() public {
        /* Create contracts */
        airdropContract = new Airdrop();
        devFundContract = new DevFund();
        nftContract = new TraitForgeNft();
        entityTradingContract = new EntityTrading(address(nftContract));
        entityForgingContract = new EntityForging(address(nftContract));
        entropyGeneratorContract = new EntropyGenerator(address(nftContract));
        nukeFundContract = new NukeFund(
            address(nftContract),
            address(airdropContract),
            payable(address(devFundContract)),
            payable(address(devFundContract))
        );

        /* Link contracts via setters */
        nftContract.setEntropyGenerator(address(entropyGeneratorContract));
        nftContract.setEntityForgingContract(address(entityForgingContract));
        nftContract.setAirdropContract(address(airdropContract));
        nftContract.setNukeFundContract(payable(address(nukeFundContract)));
        entityTradingContract.setNukeFundAddress(payable(address(nukeFundContract)));
        entityForgingContract.setNukeFundAddress(payable(address(nukeFundContract)));
        devFundContract.addDev(address(this), 1);

        /* Generate FIXED entropies */
        // For this test, we want to have deterministic entropy so we mock it.
        uint256[] memory fixedEntropies = new uint256[](1);
        fixedEntropies[0] = 111171111111 * 1e65; // Set slot 0 -> 1st and second entropy others are 0
        entropyGeneratorContract.writeFixedEntropy(fixedEntropies);

        // Skip the "24hrs mint whitelist period" for TraitForgeNft, to avoid overloading test with merkle proofs
        skip(25 hours);
    }

    function test_wrongNukeFactor() public {
        vm.warp(18e6); // Start at realistic timestamp

        // Mint NFT Entity
        hoax(NFT_OWNER, 1 ether);
        nftContract.mintToken{value: 0.1 ether}(new bytes32[](0));
        assertEq(nftContract.ownerOf(1), NFT_OWNER);

        // Mint NFT Entity with performanceFactor of 1
        hoax(NFT_OWNER, 1 ether);
        nftContract.mintToken{value: 0.1 ether}(new bytes32[](0));
        assertEq(nftContract.ownerOf(2), NFT_OWNER);
        assertTrue(calcPerformanceFactor(2) == 1);

        // Save the initial nukeFactor
        uint256 initialNukeFactor = nukeFundContract.calculateNukeFactor(2);
        assertEq(initialNukeFactor, 2777);

        skip(3000 days); // Should be more than enough to reach 50% with lowest performance factor.
        uint256 nukeFactorAfter = nukeFundContract.calculateNukeFactor(2);

        // assert that nukeFactor is less than 5% in TOTAL, after 8 years
        // Which is incorect regarding the documentation.
        assertTrue(nukeFactorAfter < 5000);
    }

    function calcPerformanceFactor(uint256 tokenId) public view returns (uint256) {
        //Calculation is copied from calculateAge() in NukeFund.sol
        return nftContract.getTokenEntropy(tokenId) % 10;
    }
}
