# Vulnerability details

## Description & Impact
The documentation specifies that the `nukeFactor` increases over time at a rate of 2.5% per year, multiplied by the `performanceFactor`:

```
https://github.com/TraitForge/docs/blob/main/user-actions/nuking.md

Nuke Factor: Each entity has a unique nukeFactor that determines the percentage of the HoneyPot you can claim. nukeFactor increases over time (2.5% per year * performanceFactor).
```

When a user burns an entity to receive funds, the `NukeFund::nuke` function is invoked. One of the crucial sub-functions called during this process is `NukeFund::calculateAge`, which returns the age of an entity. This age is critical in determining the `nukeFactor` and, consequently, the amount the user receives:

```
File: ./contracts/NukeFund/NukeFund.sol::calculateAge (line 128)

    uint256 age = (daysOld *
    performanceFactor *
    MAX_DENOMINATOR *
    ageMultiplier) / 365;
```

The `ageMultiplier` directly impacts the final value of the age. If `ageMultiplier` is not set, the age of the entity defaults to zero. This zero value negates the impact of the `nukeFactor`, significantly reducing the payout to users. Consequently, users are deprived of the documented growth rate of 2.5% per year.

This issue was not detected in the tests found in `./test/NukeFund.test.ts`. In these tests, the `NukeFund::minimumDaysHeld` value is set to zero using the `NukeFund::setMinimumDaysHeld` function, allowing entities to be nuked immediately after minting. Therefore, the impact of the age on the final amount transferred to the user was not evident.

## Proof of Concept
Create a test file in `./test` directory and run the test by `npx hardhat test test/auditNukeFund.test.ts`:

```javascript
import { HardhatEthersSigner } from '@nomicfoundation/hardhat-ethers/signers';
import { expect } from 'chai';
import { ethers } from 'hardhat';
import {
  DevFund,
  NukeFund,
  TraitForgeNft,
  Airdrop,
  EntropyGenerator,
  EntityForging,
  EntityTrading,
} from '../typechain-types';
import generateMerkleTree from '../scripts/genMerkleTreeLib';
import { fastForward } from '../utils/evm';

describe('NukeFund', function () {
  let owner: HardhatEthersSigner,
    user1: HardhatEthersSigner,
    nukeFund: NukeFund,
    nft: TraitForgeNft,
    devFund: DevFund,
    airdrop: Airdrop,
    entityForging: EntityForging,
    merkleInfo: any,
    entityTrading: EntityTrading;
  beforeEach(async function () {
    [owner, user1] = await ethers.getSigners();

    const TraitForgeNft = await ethers.getContractFactory('TraitForgeNft');
    nft = (await TraitForgeNft.deploy()) as TraitForgeNft;
    await nft.waitForDeployment();

    devFund = await ethers.deployContract('DevFund');
    await devFund.waitForDeployment();

    await devFund.addDev(owner.address, 1);

    airdrop = await ethers.deployContract('Airdrop');
    await airdrop.waitForDeployment();

    await nft.setAirdropContract(await airdrop.getAddress());
    await airdrop.transferOwnership(await nft.getAddress());

    const NukeFund = await ethers.getContractFactory('NukeFund');

    nukeFund = (await NukeFund.deploy(
      await nft.getAddress(),
      await airdrop.getAddress(),
      await devFund.getAddress(),
      owner.address
    )) as NukeFund;
    await nukeFund.waitForDeployment();

    await nft.setNukeFundContract(await nukeFund.getAddress());

    // Deploy EntropyGenerator contract
    const EntropyGenerator = await ethers.getContractFactory(
      'EntropyGenerator'
    );
    const entropyGenerator = (await EntropyGenerator.deploy(
      await nft.getAddress()
    )) as EntropyGenerator;

    await entropyGenerator.writeEntropyBatch1();

    await nft.setEntropyGenerator(await entropyGenerator.getAddress());

    // Deploy EntityForging contract
    const EntityForging = await ethers.getContractFactory('EntityForging');
    entityForging = (await EntityForging.deploy(
      await nft.getAddress()
    )) as EntityForging;
    await nft.setEntityForgingContract(await entityForging.getAddress());

    merkleInfo = generateMerkleTree([owner.address, user1.address]);

    await nft.setRootHash(merkleInfo.rootHash);

    entityTrading = await ethers.deployContract('EntityTrading', [
      await nft.getAddress(),
    ]);

    await entityTrading.setNukeFundAddress(await nukeFund.getAddress());

    await nft.connect(owner).mintToken(merkleInfo.whitelist[0].proof, {
      value: ethers.parseEther('1'),
    });
  });

  it('should calculate the age of a token', async function () {
    const tokenId = 1;

    let age = await nukeFund.calculateAge(tokenId);
    expect(age).to.be.eq(0);
    console.log("Age of token before fastForward is zero");

    const oneYearInSeconds = 365 * 24 * 60 * 60

    await fastForward(oneYearInSeconds);

    age = await nukeFund.calculateAge(tokenId);
    expect(age).to.be.eq(0);
    console.log("Age of token after 1 year fastForward is still zero: Bug");
  });
});

```

Therefore, the age value remains unchanged even after shifting the time forward by one year. This directly impacts the amount transferred to the user when the `NukeFund::nuke` function is invoked.

## Recommended Mitigation Steps

To address this issue, add a `require` statement in the `NukeFund::calculateAge` or `NukeFund::calculateNukeFactor` function to ensure that `NukeFund::ageMultiplier` is set:

```solidity
require(ageMultiplier > 0, "ageMultiplier isn't set");
```

or declare a virable `isAgeMultiplierSet`:
```solidity
require(isAgeMultiplierSet > 0, "ageMultiplier isn't set");
```
