# Vulnerability details

## Impact
If more than 10,000 NFTs are generated per generation, there will be an oversupply of NFTs, which exceeds the intended cap for each generation. This undermines the game's intended functionality and the value of NFTs by allowing an uncapped number of NFTs to be minted per generation.

## Proof of Concept
To illustrate this issue, consider the following scenario:

1. Minting starts and `generationMintCounts[1]` is incremented as the mints of generation 1 occur.
2. The `forgeWithListed` function is called using two NFTs of generation 1, producing an NFT of generation 2. As a result, `generationMintCounts[2]` is incremented to track the total mints of generation 2.
3. 10,000 NFTs of generation 1 are minted, and the `_incrementGeneration` function is called. This function performs the following changes:

   `
   currentGeneration++;
   generationMintCounts[currentGeneration] = 0;
   `
4. This resets the `generationMintCounts` of generation 2 to zero, effectively ignoring all previously minted NFTs of generation 2.

As a result, all NFTs that were forged and minted as generation 2 are not taken into consideration, leading to an oversupply of NFTs beyond the intended 10,000 cap per generation.

## Tools Used
Manual review

## Recommended Mitigation Steps
When resetting to the next generation, the code should take into consideration the total mints that have already occurred in the current generation. Ensure that the `generationMintCounts` accurately reflect the number of NFTs minted and forged to prevent oversupply.
