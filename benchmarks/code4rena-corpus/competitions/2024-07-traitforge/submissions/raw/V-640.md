# Vulnerability details

## Impact
In the current `nuke` function logic, the ETH reward after nuking the NFT is sent to `msg.sender` (the owner or the approved operator of this NFT). In case the ETH recipient is the approved operator, if the owner has no way to contact (on-chain or off-chain) that approved operator, he will not be able to get his ETH reward.

## Proof of Concept
Observe the `nuke` function:
```solidity
function nuke(uint256 tokenId) public whenNotPaused nonReentrant {
    require(
      nftContract.isApprovedOrOwner(msg.sender, tokenId),
      'ERC721: caller is not token owner or approved'
    );

    // ...

    nftContract.burn(tokenId); // Burn the token
    (bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
    require(success, 'Failed to send Ether');

    // ...
}

```
In the above function, `claimAmount` is sent to `msg.sender` after the NFT is burned. But `msg.sender` is not necessarily the owner of that NFT, so that `claimAmount` ETH is not guaranteed to be sent to that owner.

## Tools Used
Manually Review

## Recommended Mitigation Steps
Solution 1: Force the `msg.sender` must be the owner of the NFT with the given `tokenId`
Fix the conditional in the require statement as:

```solidity
    require(
      nftContract.ownerOf(tokenId) == msg.sender,
      'Sender must be the NFT owner.'
    );
```

Solution 2: If the NFT's approved operator is still allowed to nuke it by the project business logic, the `claimAmount` (ETH) should be transferred directly to the NFT's owner, not the `msg.sender`

```solidity
    (bool success, ) = payable(nftContract.ownerOf(tokenId)).call{ value: claimAmount }('');
```
