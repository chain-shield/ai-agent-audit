# Vulnerability details

## Impact
Fully minting a generation would prevent forging for all NFTs from the previous generation.

## Proof of Concept
[_mintNewEntity](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L311-L343) is used to forge NFTs and ascend them to the next generation. This function always checks if the generation is already minted, i.e., if `generationMintCounts` is greater than `maxTokensPerGen` (10k). If so, it reverts.

```solidity
function _mintNewEntity(address newOwner, uint256 entropy, uint256 gen) private returns (uint256) {
    require(generationMintCounts[gen] < maxTokensPerGen, "Exceeds maxTokensPerGen");
```

This check prevents forging if the next generation is fully minted. For example, to forge two Gen2 NFTs to get one Gen3 NFT, if Gen3 is fully minted, [_mintNewEntity](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L311-L343) would revert.

Example:
1. Gen 5 just got fully minted, and now the first NFT from Gen 6 is minted.
2. Because of the require statement, all NFTs from Gen 4 and below are unable to be forged, essentially making them useless in terms of forging.

This will likely cause the forging potential for low-generation NFTs (1, 2, and probably 3) to be used only once. After a year gen 1 and 2 forging potential would reset, but if Gen 3 is fully minted, then they will not be forgeable.

## Tools Used
Manual review

## Recommended Mitigation Steps
Either allow forging NFTs beyond the 10k mark or implement a custom mechanic that would enable them to ascend to the current generation.
