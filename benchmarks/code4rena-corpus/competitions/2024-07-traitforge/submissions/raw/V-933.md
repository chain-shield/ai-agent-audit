# Vulnerability details


## Impact

The absence of public pause/unpause functions in contracts inheriting from `Pausable` renders the `Pausable` functionality inoperable. This is a severe issue as it undermines the ability to pause and unpause contract operations, which can be crucial for managing and securing the protocol during unforeseen events or emergencies.

## Proof of Concept

The root cause of the vulnerability is that OpenZeppelin's `Pausable` contract is inherited by multiple contracts, but the Pausable library only provides a set of modifiers and view functions, while the necessary state mutation functions are provided as internal `_pause` and `_unpause` functions. The required public endpoints to pause and unpause the contracts are not implemented. This results in the `Pausable` functionality being rendered ineffective. This means all functions with the `whenNotPaused` modifier become unprotected since the contracts cannot be paused in case of emergency.

Let us walk through the issue with the following scenario:

1. Alice, the contract owner, wants to pause the contract due to a detected vulnerability.
2. The contract does not have a public function to pause its operations.
3. As a result, Alice cannot pause the contract, leaving the protocol exposed to potential exploits.

## Recommended Mitigation Steps

Implement public `pause` and `unpause` functions with proper access control to call the internal `_pause` and `_unpause` functions from the `Pausable` contract.

```solidity
function pause() external onlyOwner {
    _pause();
}

function unpause() external onlyOwner {
    _unpause();
}
```
