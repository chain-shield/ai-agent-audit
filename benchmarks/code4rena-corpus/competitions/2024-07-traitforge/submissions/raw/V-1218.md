# Vulnerability details

## Impact

Without slippage check, If the price of the tokens changes significantly during the withdraw, it could result in a large slippage, causing users to lose a significant amount of funds.

## Proof of Concept

The `DAOFund` contract is a simple smart contract designed to manage Ethereum (ETH) funds received by the contract and convert them into a specific ERC-20 token using the Uniswap decentralized exchange.

The main function here is `receive()`:

```solidity
  receive() external payable {
    require(msg.value > 0, 'No ETH sent');

    address[] memory path = new address[](2);
    path[0] = uniswapV2Router.WETH();
    path[1] = address(token);

    uniswapV2Router.swapExactETHForTokens{ value: msg.value }(
      0,
      path,
      address(this),
      block.timestamp
    );

    require(
      token.burn(token.balanceOf(address(this))) == true,
      'Token burn failed'
    );
  }
```

This function is a special function in Solidity that allows the contract to accept ETH directly. It is triggered whenever ETH is sent to the contract. 

The problem here is that the function calls `swapExactETHForTokens`, a function of the Uniswap router, to swap the received ETH for the specified token. 

The first param is `amountOutMin` and is set to zero. Setting it to 0 means the function will accept any amount of tokens. This means the function doesn't have slippage protection.
## Tools Used

Visual Studio Code

## Recommended Mitigation Steps

Do not hardcode `amountOutMin` to 0.
