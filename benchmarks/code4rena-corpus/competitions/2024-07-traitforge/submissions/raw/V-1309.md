# Vulnerability details

## Impact
The `mintWithBudget` function can be permanently disabled (DoS) once the _tokenIds variable reaches a certain threshold (e.g., 10,000), making it impossible for users to mint tokens using this function. This is due to an incorrect check against `maxTokensPerGen`.

## Proof of Concept
Incorrect maxTokensPerGen Check:

1.The function incorrectly uses _tokenIds to check against maxTokensPerGen.
Since _tokenIds can increase through both normal minting and forging, it can quickly reach the `maxTokensPerGen` limit, leading to a DoS condition.

2.Functions such as forging can also increase _tokenIds, leading to an early and unintended DoS condition for the mintWithBudget function.

3.This issue can arise even during the first generation, blocking further minting operations prematurely.

Example Scenario:
1.Assume `maxTokensPerGen` is set to 10,000.
2.If _tokenIds reaches 10,000 due to a combination of normal minting and forging, `mintWithBudget` will stop working, even if there are tokens still available for minting.
3.Attempt to use `mintWithBudget` and observe that the function stops working once _tokenIds reaches 10,000
