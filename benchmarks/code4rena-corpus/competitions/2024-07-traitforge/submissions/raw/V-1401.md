# Vulnerability details

## Impact
This crucial function named `_incrementGeneration()` are also used to increment generations in most important contract functions like `_mintInternal`, `mintToken`, `forge` meaning that the protocol will be unable to start the next generation after the first generation is completed, halting the minting process and preventing the progression of the contract's intended functionality.

## Proof of Concept
The `TraitForgeNft::_incrementGeneration()` function is responsible for incrementing the generation when certain conditions are met. and the condition neccesary for this generation Advancement was for `generationMintCounts[currentGeneration] >= maxTokensPerGen` , then couple lines below this check there is a call to `entropyGenerator.initializeAlphaIndices()`, a function from `EntropyGenerator.sol`. This function is restricted by the onlyOwner modifier, meaning it can only be called by the owner of the `EntropyGenerator` contract. The sponsors plan is for their multisig wallet to be the owner of `EntropyGenerator.sol`. Consequently, `TraitForgeNft` will be unable to execute `initializeAlphaIndices()` because it is not the owner of the contract and the funtion will revert.

This below is the `_incrementGeneration()` showing the call to an onlyOwner function in `EntropyGenerator.sol`

## Recommended Mitigation Steps
To resolve this issue, implement a new modifier which check the caller of the function should be the owner of the `EntropyGenerator` `OR` the caller should be `TraitForgeNft` contract.

```diff
+ modifier onlyOwnerORonlyAllowedCaller() {
+   if (msg.sender != allowedCaller && msg.sender != owner()) {
+       revert;
+   }
+   _;
+ }

-    function initializeAlphaIndices() public whenNotPaused onlyOwner {
+    function initializeAlphaIndices() public whenNotPaused onlyOwnerORonlyAllowedCaller {
```
