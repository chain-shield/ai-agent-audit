# Vulnerability details

## Impact
**`buyNFT()`** allows users to purchase a listed NFT. However, there is an issue with the calculation of the **`nukeFundContribution`**, which represents the funds sent to the Nuke Fund. Due to this miscalculation, the fees intended to fund the project are incorrect.
## Proof of Concept
**`buyNFT()`** is implemented as follows:
```Solidity
function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {
    Listing memory listing = listings[listedTokenIds[tokenId]];
    require(
      msg.value == listing.price,
      'ETH sent does not match the listing price'
    );
    require(listing.seller != address(0), 'NFT is not listed for sale.');

    //transfer eth to seller (distribute to nukefund)
@>  uint256 nukeFundContribution = msg.value / taxCut;
    uint256 sellerProceeds = msg.value - nukeFundContribution;
    transferToNukeFund(nukeFundContribution); // transfer contribution to nukeFund

    // transfer NFT from contract to buyer
    (bool success, ) = payable(listing.seller).call{ value: sellerProceeds }(
      ''
    );
    require(success, 'Failed to send to seller');
    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer NFT to the buyer

    delete listings[listedTokenIds[tokenId]]; // remove listing

    emit NFTSold(
      tokenId,
      listing.seller,
      msg.sender,
      msg.value,
      nukeFundContribution
    ); // emit an event for the sale
  }
```
As it stands, the calculation **`nukeFundContribution = msg.value / taxCut`** is incorrect because **`taxCut`** represents a percentage and cannot be used directly as a divisor. While this approach works in first instance because **`taxCut`** is hardcoded to 10% (as indicated in the documentation), it becomes problematic when **`taxCut`** is modified using the **`setTaxCut()`**.
```Solidity
function setTaxCut(uint256 _taxCut) external onlyOwner {
    taxCut = _taxCut;
  }
```
If **`taxCut`** is changed to a percentage other than 10%, the calculation will become incorrect. For instance, let’s consider two examples: one with a **`taxCut`** of 10% and another with 20%.


1. 10% Example

**`taxCut = 10%`**
**`msg.value = 1e18`**

**`nukeFundContribution = msg.value / taxCut =  1e18 / 10 = 1e17`**
**`Percentatge = (1e17 / 1e18) * 100 = 10%`**

In this case is correct, **`taxCut == Percentatge`**.

2. 20% Example

**`taxCut = 20%`**
**`msg.value = 1e18`**

**`nukeFundContribution = msg.value / taxCut =  1e18 / 20 = 5e16`**
**`Percentatge = (5e16 / 1e18) * 100 = 5%`**

As you can see, **`taxCut`** is not equal **`Percentage`** (20% != 5%), in this case is incorrect. This cause the protocol to receive less funding than intended.
