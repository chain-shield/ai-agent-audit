# Vulnerability details

## Impact
According to [Documentation](https://github.com/TraitForge/docs):
```solidity
Dev & DAO Funds: 10% of all Nuke Fund income streams to the Dev/DAO Fund.
```
However, this will not always be the case.

## Proof of Concept
The [current implementation](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L46-L57) does not always ensure that `10%` of all `Nuke Fund income streams` go to the `Dev/DAO Fund`. 
```solidity
    if (!airdropContract.airdropStarted()) {
      (bool success, ) = devAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    } else if (!airdropContract.daoFundAllowed()) {
>>    (bool success, ) = payable(owner()).call{ value: devShare }(''); //@audit-info Dev/DAO do not get a share
      require(success, 'ETH send failed');
    } else {
      (bool success, ) = daoAddress.call{ value: devShare }('');
      require(success, 'ETH send failed');
      emit DevShareDistributed(devShare);
    }
```

*Airdrop Not Started*:
- 10% goes to devAddress.
- Remaining 90% goes to the fund.

*Airdrop Started but DAO Fund Not Allowed*:
- 10% goes to the contract owner.
- Remaining 90% goes to the fund.

*Airdrop Started and DAO Fund Allowed*:
- 10% goes to daoAddress.
- Remaining 90% goes to the fund.

As seen, when *Airdrop Started but DAO Fund Not Allowed*, 10% goes to the contract owner and as such, the  Dev/DAO Fund receives nothing.
