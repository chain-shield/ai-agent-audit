# Vulnerability details


## Impact

The vulnerability in the `TraitForgeNft::_incrementGeneration` function allows the generation mint count to be reset to zero despite having a non-zero count from forging activities. This could result in exceeding the 10,000 token hard cap per generation, potentially doubling the total token count within the same generation and impacting the game economy by undermining gameplay and core protocol functionality.

## Proof of Concept

The root cause of the vulnerability is that the `_incrementGeneration` function resets `generationMintCounts[currentGeneration]` to zero without considering any positive counts from forging activities.

## Recommended Mitigation Steps

Do not reset `generationMintCounts`. If `generationMintCounts` at `generation + 1` has reached `maxTokensPerGen`, proceeds to set up `priceIncrement` and then invoke `_incrementGeneration` again to skip minting for this generation.

```patch

345:  function _incrementGeneration() private {
    ...
    currentGeneration++;
-    generationMintCounts[currentGeneration] = 0; 
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
+    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
+      _incrementGeneration();
+    }
}
```
