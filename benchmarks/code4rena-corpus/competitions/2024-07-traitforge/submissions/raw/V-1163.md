# Vulnerability details

## Impact

A user can mint the “the Golden God” NFT with 999999 entropy without any difficulty.

## Proof of Concept

Whenever a new NFT is minted, the [next available](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L288) entropy is assigned to it, from which its traits and parameters are derived. There are `10000` entropies created per generation, 13 of which get concatenated and stored in a single storage slot. The entire process revolves around the users getting a random entropy for their NFT, in order for the protocol’s fairness to remain consistent across all generations, for all users. The best entropy a user’s NFT can get assigned is `999999`, which would mean that all of its stats are the highest that one could get. It can be achieved only when the specific slot and index within that slot are matched with the parameters [slotIndexSelection](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L19) and [numberIndexSelection](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L20) (assigned upon deployment of [EntropyGenerator](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol) by calling [initializeAlphaIndices](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206-L216))

A problem arises when a user can mint “the Golden God” without going through any hurdles. As the selected slot index and number index are stored in state variables in [EntropyGenerator](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol), a user can read the current values of [slotIndexSelection](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L19) and [numberIndexSelection](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L20) and then call the function [getPublicEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L123-L128) with them passed as an argument. The returned result from the function will confirm that the user can get their NFT minted with 999999 entropy, if they mint an NFT at that specific slot and number.

An additional source that can help with their timing, are the parameters [currentSlotIndex](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L12) and [currentNumberIndex](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L13) which can be read using the function [getStorage](https://web3js.readthedocs.io/en/v1.2.11/web3-eth.html#getstorageat) at from web3js (an [example](https://solidity-by-example.org/hacks/accessing-private-data/) of how that works). Using the information stated so far, a malicious user can time their mint perfectly, ensuring that they receive “the Golden God” NFT, or they can front-run any other user who would’ve got “the Golden God” using pure luck.

## Recommended Mitigation Steps

One possible reccomendation may be instead of setting the `slotIndexSelection` and `numberIndexSelection` variables in the [`initializeAlphaIndices()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206) function, remove it and let the user randomly get the "Golden God” NFT using pure luck.
