# Vulnerability details

## Impact
In the `EntityForging::listForForging()` and `EntityForging::forgeWithListed()` functions the downcasting of entropy from uint256 to uint8 without proper checks can cause an overflow for values greater than 255. 


## Proof of Concept
In the functions [EntityForging::listForForging()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L85-L86) and [EntityForging::forgeWithListed()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L136-L138), the token entropy is retrieved by `nftContract.getTokenEntropy()` and then cached in a local variable of type `uint256`. This variable is unsafely downcasted into a `uint8`, which has a maximum value of `255`. As a result, any values greater than `255` will overflow.
```solidity

    }
```

The token's entropy is calculated in the `EntropyGenerator::getEntropy()` as follows:
```solidity

@>    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
```

The entropy variable in the `getEntropy()` function adjusts the entropy value based on the number of digits, which can be greater than `255`:
```solidity
uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; 
```
Thus, the functions `EntityForging::listForForging()` and `EntityForging::forgeWithListed()` will overflow.

## Recommended Mitigation Steps
Change the [forgePotential](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L86) and [mergerForgePotential](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L138) types to `uint256` or revert if `entropy > 255`.
