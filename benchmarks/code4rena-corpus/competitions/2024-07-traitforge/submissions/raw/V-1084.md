# Vulnerability details

## Description of Issue

The EntropyGenerator contract uses `block.number` and a counter to generate pseudo-random values. This method is vulnerable to miner manipulation and is predictable.

```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
```

## Impact
This vulnerability could allow attackers to predict or manipulate the entropy values, potentially:

1. Gaming the NFT generation process to obtain NFTs with desired traits.
2. Exploiting the game mechanics, especially in critical operations like forging or nuking.
3. Undermining the fairness and integrity of the entire TraitForge ecosystem.

## Proof of Concept
An attacker could:

1. Observe the contract state and current block number.
2. Calculate the next entropy values offline.
3. Time their transactions to coincide with favorable entropy values.

## Tools Used
manual review + vscode

## Recommended Mitigation Steps
1. Implement a verifiable random function (VRF) like Chainlink VRF.
2. Use a commit-reveal scheme for entropy generation.
3. Incorporate external sources of randomness, such as block hash of a future block.
