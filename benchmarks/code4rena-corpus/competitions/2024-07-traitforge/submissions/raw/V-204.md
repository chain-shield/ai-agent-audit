# Vulnerability details

## Impact
The require statement used to validate the `pseudoRandomValue` can cause transactions to revert if the value is `999999`. This can lead to inefficient initialization and higher gas costs. This approach might also cause transactions to fail unnecessarily, affecting the overall reliability of the entropy generation process. Instead of reverting, the function could use a continue statement to skip over invalid values and proceed with the initialization. This change would improve the efficiency of the contract and reduce the likelihood of failed transactions.

## Proof of Concept
This is the code.

    unchecked {
        for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
            uint256 pseudoRandomValue = uint256(
                keccak256(abi.encodePacked(block.number, i))
            ) % uint256(10) ** 78;
            require(pseudoRandomValue != 999999, 'Invalid value, retry.');    // <= revert
            entropySlots[i] = pseudoRandomValue;
        }
    }

In this code, if `pseudoRandomValue` is `999999`, the transaction will revert, which is inefficient.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Change the require statement to a continue statement in the loops for writeEntropyBatch1 and writeEntropyBatch2. This will skip invalid values instead of reverting the entire transaction.

    for (uint256 i = lastInitializedIndex; i < endIndex; i++) {
        uint256 pseudoRandomValue = uint256(
            keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
        if (pseudoRandomValue == 999999) {
            i--;
            continue; // Skip invalid value
        }
        entropySlots[i] = pseudoRandomValue;
    }
