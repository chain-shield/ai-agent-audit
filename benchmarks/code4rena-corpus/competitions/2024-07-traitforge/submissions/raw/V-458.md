# Vulnerability details

## Impact
As `perforamanceFactor` is calculated by a modulus of 10, any number that is divisible by 10 will return a performance factor of 0 having it so the token can never increment in age, resulting in a loss of funds for any token holder trying to nuke their NFT.

## Proof of Concept
The `performanceFactor` calculated here:
```
uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10;
```
is then multipled here:
```
    uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365; // add 5 digits for decimals
    return age;
```

any token entropy divisible by 10 will now always have an age of 0.

this is then used in the `calculateNukeFactor` function:
```
uint256 adjustedAge = calculateAge(tokenId);

    uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits

    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;
```

meaning this tokens nuke factor will never increase more than the initial nuke factor, despite aging.

## Recommended Mitigation Steps

Implement a way to avoid using 0 as a performance factor.
this can be achieved in a few ways:

1. add a minimum of 1 when calculating the performance factor:
```
uint256 performanceFactor = (entropy % 10) + 1;
```

2. Use a different range for the performance factor:
You could use a range that doesn't include 0:
```
uint256 performanceFactor = (entropy % 9) + 1;
```
