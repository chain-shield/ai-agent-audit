# Vulnerability details

## Impact
User can potentially see his call to mintWithBudget() get reverted and lose gas fees when the transaction runs out of gas.

## Proof of Concept
User can freely choose to mint multiple NFT in a single transaction by calling mintWithBudget() with enough msg.value to cover minting fees. However there is no protection against the possibility of the transaction running out of gas. This being said in current configurations as seen in tests, when i simulate call to mintWithBudget() with a budget less than 0.7 ether, the transaction complete just before running out of gas. For any bidget >= 0.7 ether, the transaction runs out of gas and revert, this consume gas sent by user while the transaction did not suceed.This will always happens with any call to mintWithBudget() with msg.value >= 0.7 ether.

This is ambigus because the tx runing out of gas also depend on the price of the nfts and the msg.value ? For instance if we start minting with 0.7 ether the tx will run out of gas. But if someone mint let's say 0.6 ether worth of tokens before we start minting , then a call with 0.7 ether won't run out of gas but a call with 1 ether will.

To illustrate copy these tests cases and place it inside TraitForgeNFT.test.ts describe('listForForging') block. They are two separate tests
```solidity
it('This call runs out of gas', async () => {
       console.log("Processing a transaction with 0.7 ether that will run out of gas");
       await nft.connect(owner).mintWithBudget(merkleInfo.whitelist[0].proof, {
         value: ethers.parseEther('0.7'),
      });
```
```solidity
 it('This call runs out of gas with 1 ether', async () => {
      // This transaction with 0.6 ether will succedd
      console.log("this tx will suceed with 0.6 ether");
       await nft.connect(owner).mintWithBudget(merkleInfo.whitelist[0].proof, {
         value: ethers.parseEther('0.6'),
       });
       // This transaction with 0.7 ether will fail
       console.log("Processing a transaction with 1 ether that will run out of gas");
       await nft.connect(owner).mintWithBudget(merkleInfo.whitelist[0].proof, {
         value: ethers.parseEther('1'),
      });
```
and run the test:
```
yarn test test/TraitForgeNft.test.ts
```

## Recommended Mitigation Steps
I propose to set a Cap of NFT one can mint in a single transaction. If the cap is reached then exit the while loop and refund the remaining budget.
