# Vulnerability details

## Details
- Along with normal minting entities there are entities which are minted via forging, and it is also possible that forging entities can fill up the maximum limit of entities for future generations.
- For any current generation, which is incremented to next generation then for the above discussed case the next incremented generation can be fully filled with only forged NFTs, but as the function doesn't ensure that the subsequent newly incremented generations are full will result in minting of the entity even if the maximum minting quota for a generation is reached.

## Impact
Extra entity can be minted for a generation having maximum entities, due to not checking maximum entity reached for all subsequent incremented generation.


## Proof of Concept
1. Suppose that current generation is x, and generation y has all `10,000` forged entitites. (here, generation y occurs just after x)
2. Now, consider for generation x, maximum entity limit has reached.
3. When a user calls `mintToken` function, then it calls `_mintInternal` function where it performs generation increment as current generation x was fully filled, and shifts the current generation to `y`.
4. Then it continues to mint the entity with generation `y` even though generation `y` was fully filled, resulting in a violation of maximum entity being minted for a generation.

But, it would have not occurred if every incremented generation is checked with maximum entity mint reached.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Instead of checking and incrementing generation for the current generation only in `_mintInternal`, do it for every incremented generation until a generation is reached for which maximum mint limit has not reached.
