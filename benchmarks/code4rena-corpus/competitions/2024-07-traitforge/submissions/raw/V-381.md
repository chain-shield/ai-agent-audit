# Vulnerability details

[H-1] Inability to Increment Generation even when generationMintCounts[gen] >= maxTokensPerGen During Forging Process in TraitForgeNft Contract
### Description
in the TraitForgeNft contract doing forging, the _incrementGeneration() function will never be called during the forging process,  even when this (generationMintCounts[gen] >= maxTokensPerGen is true. potentially leading to a stagnation in generation progression.

### Detailed Description

### Forging Process
In the forge function, a new generation is calculated and passed to _mintNewEntity:

function forge(address newOwner, uint256 parent1Id, uint256 parent2Id, string memory)
    external
    whenNotPaused
    nonReentrant
    returns (uint256)
{
    // ... [other code]
@>    uint256 newGeneration = getTokenGeneration(parent1Id) + 1;
    // ... [other code]
@>    uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);
    // ... [other code]
}


### Minting Process
Inside _mintNewEntity, there's a check intended to increment the generation when certain conditions are met.

function _mintNewEntity(address newOwner, uint256 entropy, uint256 gen) private returns (uint256) {
    // ... [other code]
@>    if (generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration) {
        _incrementGeneration();
    }
    // ... [other code]
}


### Logical Flaw
The condition gen == currentGeneration will always be false during forging because:
gen is set to newGeneration, which is already incremented.

This means _incrementGeneration() will never be called during the forging process even when this (generationMintCounts[gen] >= maxTokensPerGen is true.

### Impact
Generation progression is halted during forging when generationMintCounts[gen] >= maxTokensPerGen.
Potential disruption of game mechanics or token economics tied to generation progression.

### Root Cause
The root cause is a validation issues  in the condition for calling _incrementGeneration(). The condition doesn't account for the fact that gen is already incremented in the forge function before being passed to _mintNewEntity.

### Recommended Mitigation
To address this issue, consider removing the vulnerable check gen == currentGeneration
