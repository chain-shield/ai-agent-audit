# Vulnerability details

## Details
- The protocol mentions to have exactly one Golden God (999999) per gen via having only `999999` value set at the 3rd batch slot by setting it up through `initializeAlphaIndices`.
- So, `initializeAlphaIndices` is responsible to set up a single Golden God for the slot of the 3rd batch. Therefore, that ensures that there would be 1 Golden God in the 3rd batch, and 1 Golden God per gen.
- But while setting up the slot values via the `writeEntropyBatch3` it doesn't check if the random value generated have the Golden God (999999), thus allowing multiple Golden God to exist in the 3rd batch, and thus more than 1 Golden God per generation.


## Impact
For the 3rd batch, as `initializeAlphaIndices` deliberately sets up Golden God, and as Golden God will also be possible in the 3rd batches slot as they are not monitored for `999999`, allowing more than 1 Golden God to exist in 3rd batch, and ultimately leading to more than 1 Golden God per generation.

## Proof of Concept
```solidity
  function writeEntropyBatch3() public {
    require(
      lastInitializedIndex >= batchSize2 && lastInitializedIndex < maxSlotIndex,
      'Batch 3 not ready or already completed.'
    );
    unchecked {
      for (uint256 i = lastInitializedIndex; i < maxSlotIndex; i++) {
@>      uint256 pseudoRandomValue = uint256(
          keccak256(abi.encodePacked(block.number, i))
        ) % uint256(10) ** 78;
@>      entropySlots[i] = pseudoRandomValue;
      }
    }
    lastInitializedIndex = maxSlotIndex;
  }
```
- Here, as we can clearly see that the generated `pseudoRandomValue` is directly assigned to the entropy slots without monitoring for the Golden God (999999) in there.
- As well as 1 Golden God is deliberately set which is intended functionality.
- Thus, allowing multiple Golden God in the 3rd batch, and thus more than 1 Golden God per generation.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Add a check to monitor for Golden God existing in the 3rd batch during entropy assignments to slot, and revert in the case if any Golden God exist.

Before assigning `pseudoRandomValue` to `entropySlots[i]` add the below check in `writeEntropyBatch3` function.
```
for (uint256 j = 0; j <= 12; ++j) {
  uint256 position = j * 6;
  uint256 entropy = (pseudoRandomValue / (10 ** (72 - position))) % 1000000; 
  require(entropy != 999999, 'Invalid value, retry.');
}
```
