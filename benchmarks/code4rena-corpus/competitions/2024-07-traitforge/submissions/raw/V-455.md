# Vulnerability details

## Impact
Medium as users will not want to participate in the protocol which may lead to serious reducing in the overall experience of the protocol


## Proof of Concept
As stated by the developers of the protocol, `entropy` can be equal to 0 , as being `part of the game. But what will be the outcome of this. And a user can always check the entropy he will get on his NFT with the `getPublicEntropy` function in EntropyGenerator.sol contract.

First of all an owner of such NFT will not be able to list it for forging preventing him from accumulating fees as we can see in the `listForForging` function:
```
 uint256 entropy = nftContract.getTokenEntropy(tokenId); // Retrieve entropy for tokenId
        uint8 forgePotential = uint8((entropy / 10) % 10); // Extract the 5th digit from the entropy
        require(forgePotential > 0 && forgingCounts[tokenId] <= forgePotential, "Entity has reached its forging limit");
```

Second he will not be able to merge it as well looking at the `forgeWithListed` function:
```
        uint256 mergerEntropy = nftContract.getTokenEntropy(mergerTokenId);
        require(mergerEntropy % 3 != 0, "Not merger");
```

Third
An owner of such NFT will not gain anything from nuking it as well looking at `calculateNukeFactor` function.
```
  uint256 entropy = nftContract.getTokenEntropy(tokenId);
        uint256 adjustedAge = calculateAge(tokenId); //!Can be 0

        uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits

        uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) / MAX_DENOMINATOR) + initialNukeFactor;
```
`finalNukeFactor` will be zero because `adjustedAge` = 0 , because `calculateAge` function also uses entropy to calculate age.
All of these are used to calculate `claimAmount` when a user `nuke`'s his NFT and burns it to claim back funds.

Manual review
## Recommended Mitigation Steps
Exclude possibility of 0 entropy as it will discourage users to participate in the protocol.
