# Vulnerability details

## Impact
The current approach to handle pseudo-random values by excluding 999999 is insufficient and may result in ineffective validation. If 999999 is generated, it is excluded, but there is no comprehensive mechanism to validate the entropy values more robustly. This could lead to a situation where valid entropy values are inappropriately discarded or the system may not handle other invalid values appropriately.
Relying solely on the exclusion of the value 999999 for validating entropy can be problematic. It does not ensure the integrity of entropy values nor does it account for other potential invalid values. Furthermore, the absence of a comprehensive validation function means that other potential invalid values or edge cases are not handled.

## Proof of Concept
Here is an example.
Imagine that `999,999,999,999,999,999,999,999,999,999,999,999,999,999,999,999,999
,999,999,999,999,999,999,999,000,000` is generated for pseudoRandomValue when `i == 0`.
This value is not `999999` so it is set to `entropySlots[0]`.
But in fact, there will be 12 of `999999` entropy in data.

## Recommended Mitigation Steps
Create a dedicated function to comprehensively validate entropy values to ensure they meet the required criteria and handle all edge cases and use it to checking.

    function check(    // @audit-ok
      uint256 value
    ) private pure returns (bool) {

      for(uint i = 0; i < 13; i++) {
        uint256 entropy = (value / (10 ** (72 - i * 6))) % 1000000; // adjust the entropy value based on the number of digits
        uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));

        if(paddedEntropy == 999999) return false;
      }

      return true; // return the caculated entropy value
    }

    require(check(pseudoRandomValue), 'Invalid value, retry.');
