# Vulnerability details

## Description
The contract uses modulo operations (%) to generate bounded random numbers, which can introduce bias, especially for small ranges.

```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
```

## Impact
1. The distribution of generated values may not be uniform, leading to biased trait generation.
2. Certain traits or characteristics may appear more frequently than intended.
3. This bias could be exploited by savvy players, potentially unbalancing the game economy.

## Proof of Concept
When using `x % n` where `x` is a random number and `n` is not a power of `2`, the lower remainders are slightly more likely if the range of `x` is not a multiple of `n`.

## Recommended Mitigation Steps
1. Use a method that doesn't introduce bias, such as rejection sampling:
```
function unbiasedRandom(uint256 upperBound) internal view returns (uint256) {
    uint256 max = type(uint256).max - type(uint256).max % upperBound;
    uint256 result;
    do {
        result = uint256(keccak256(abi.encodePacked(block.timestamp, msg.sender, nonce++)));
    } while (result >= max);
    return result % upperBound;
}
```

2. If using modulo is necessary, ensure the dividend is much larger than the divisor to minimize bias.
