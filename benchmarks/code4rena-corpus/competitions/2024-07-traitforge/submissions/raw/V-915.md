# Vulnerability details

The `EntropyGenerator` contract uses `block.number` and other on-chain data to generate entropy values. This method of randomness generation is predictable and can be manipulated by miners or other actors who can influence block production.
For example, in the `writeEntropyBatch1` function:


``` solidity

uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, block.timestamp, msg.sender)));

```

Similar patterns are used in `writeEntropyBatch2` and `writeEntropyBatch3`.

## Impact
The predictability of the randomness severely undermines the security and fairness of any system relying on this entropy. Malicious actors could potentially:

Predict future entropy values, giving them an unfair advantage in any randomness-dependent features.
Manipulate the entropy by timing their transactions or colluding with miners.
Exploit this predictability in connected systems like NFT trait generation or forging mechanics.

This vulnerability could lead to significant economic impacts and undermine user trust in the system.

## Proof of Concept
A malicious actor could:

Observe the current block number and timestamp.
Calculate the next block's number and approximate timestamp.
Predict the entropy value that will be generated.
Time their transactions to take advantage of favorable entropy values.

## Tools Used
Manual review

## Recommended Mitigation Steps
Use a verifiable random function (VRF) provided by oracles like Chainlink for true randomness.
Implement a commit-reveal scheme where users submit a hash of their secret and the contract's random value, then reveal it in a separate transaction.
Use multiple sources of entropy and combine them in a way that's difficult to predict or manipulate.
Consider using future block hashes as a source of randomness, although this method still has some limitations.
