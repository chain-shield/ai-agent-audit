# Vulnerability details

## Impact

When function _incrementGeneration is called, the new generation’s previous minting tokenids(minted by forging) is not accounted and new generation’s generationMintCounts[currentGeneration] is set to 0.as a result, after 1st generation, 
After the 1st generation, every generation’s(2 to 10) generationMintCounts will be greater than  maxTokensPerGen.

## Proof of Concept
1. Let’s assume, currently currentGeneration = 1 and generationMintCounts = 10000( maxTokensPerGen is reached) for generation 1.

2. When   function forgeWithListed(contract EntityForging) is called, this function calls TraitForgeNft’s function forge which calls _mintNewEntity function which creates new tokenids of  currentGeneration’s  nextgeneration and increase next generation’s token mint counts.

3. During generation 1, 50 new tokenid is minted(by forging) for next generation i.e generation 2.

4. Now function mintToken is called, which calls _mintInternal function, see _mintInternal function, as currentgeneration 1 generationMintCounts = 10000 is equal to  maxTokensPerGen(10000), so _mintInternal function calls function _incrementGeneration.

5. See function _incrementGeneration, now generation is incremented to 2 and generation 2’s   generationMintCounts is updated to 0 i.e generationMintCounts[currentGeneration] = 0;. 

6. Now generation 2’s   generationMintCounts will start from 0 . but it should start from 51 as previously 50 tokenid was minted by forging(_mintNewEntity function)  for generation 2.

7. Generation 2 will have 50 extra tokenids i.e 10050(bigger than maxtokenpergen), similarly afterwards, generation’s  generationMintCounts will be greater than maxTokensPerGen which is unintentional for the protocol.

manual review
## Recommended Mitigation Steps
When function _incrementGeneration is called, account the previous mint token counts for the new generation and update generationMintCounts[currentGeneration] accordingly.
