# Vulnerability details

## Impact

In the contract EntityTrading.sol, there exists a vulnerability that could be exploited to perform a reentrancy attack. 

A reentrancy attack occurs when an external contract hijacks the control flow, during a pending payment or state change, and reenters the calling contract before the said change has been completed.

In this case, the vulnerability lies with the `buyNFT` function. The contract first calls an external contract (`transferToNukeFund(nukeFundContribution);`), and then later, it changes the state of the contract. 

This allows the called contract to make calls back into the original contract and alter the state in unexpected ways before it's settled.


## Proof of Concept

Reentrancy Attack code can be identified in the `buyNFT` function:

```solidity
function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {
  ...
  transferToNukeFund(nukeFundContribution); // Facilitates potential for reentrancy attack
  ...
  nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer NFT to the buyer
  delete listings[listedTokenIds[tokenId]]; // remove listing
  ...
}
```

## Recommended Mitigation Steps

The quick fix would be to follow the "Checks-Effects-Interactions" pattern in Solidity. 

This means to first make all of the state changes in the contract before calling external contracts.
