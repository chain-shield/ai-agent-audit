# Vulnerability details

**Description:** 
The `EntityTrading::buyNFT()` function is transferring NFT which is listed for selling. This function is transferring NFT to buyer and sellerProceeds in ETH to the seller. This open up the attack vector where Seller can gas grief the buyer because this function is called by buyer to buy the NFT and it also make external call to seller address to send it's share.

Here this code of line is sending sellerProceeds to seller address and caller of this function is buyer.
```solidity
(bool success, ) = payable(listing.seller).call{ value: sellerProceeds }('');
```

**Proof of Concept:**
Function buyNft():
```solidity
   function buyNFT(uint256 tokenId) external payable whenNotPaused nonReentrant {
    Listing memory listing = listings[listedTokenIds[tokenId]];
    require(
      msg.value == listing.price,
      'ETH sent does not match the listing price'
    );
    require(listing.seller != address(0), 'NFT is not listed for sale.');

    //transfer eth to seller (distribute to nukefund)
    uint256 nukeFundContribution = msg.value / taxCut;
    uint256 sellerProceeds = msg.value - nukeFundContribution;
    transferToNukeFund(nukeFundContribution); // transfer contribution to nukeFund

    // transfer NFT from contract to buyer
    (bool success, ) = payable(listing.seller).call{ value: sellerProceeds }('');
    require(success, 'Failed to send to seller');
    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer NFT to the buyer
    delete listings[listedTokenIds[tokenId]]; // remove listing

    emit NFTSold(
      tokenId,
      listing.seller,
      msg.sender,
      msg.value,
      nukeFundContribution
    ); // emit an event for the sale
  }
```
1. As you can see above buyer is callinf this function to buy the listed NFT.
2. And later it is making external call to seller address to send it's share. 
3. Now (bool success, ) is actually the same as writing (bool success, bytes memory data) which basically means that even though the data is omitted it doesn’t mean that the contract does not handle it. Actually, the way it works is the bytes data that was returned from the seller will be copied to memory.
4. Memory allocation becomes very costly if the payload is big, so this means that if a seller implements a fallback function that returns a huge payload, then the msg.sender of the transaction, in our case the buyer, will have to pay a huge amount of gas for copying this payload to memory.

**Impact:**
Malicious actor can launch a gas griefing attack on a buyer.

**Recommended Mitigation:** 
Use a low-level assembly call since it does not automatically copy return data to memory.
```solidity
bool success;
assembly {
    success := call(listing.seller, sellerProceeds, 0, 0, 0, 0)
}
```
