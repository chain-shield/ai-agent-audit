# Vulnerability details

## Impact
In the shown code snippet, we can see that _tokenIds must be smaller then maxTokensPerGen, but after minting of the first generation, no one would be able to mint the second, third, etc.

## Proof of Concept
_tokenIds is a uint256 variable manipulated only in two places.

First place is the _mintNewEntity() that's called during forging ->

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L311-L343

Second place is the _mintInternal() that's called during minting ->

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280C12-L309

The issue stems from the following: After minting the entire generation 1, the _tokenIds will be 10 000 (or more if there were forging, which is very very likely).

This will make it unable for the minting to continue from the 2nd generation onwards all others and break the purpose of the game.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Remove _tokenIds < maxTokensPerGen
