# Vulnerability details

## Vulnerability Details

Entities minted to every user have some set of properties and included is the forgePotential which determines how many times a forger's entity can forge with any merger's entity to mint an entity in the next generation with even stronger properties. In simple terms, if an entity's forge potential is 2, then it can forge with another entity at most 2 times but if the forger is able to forge more than 2 times, this becomes a vulnerability.

In [`EntityForging::listForForging()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L87C5-L90C7), the check as to whether the forgePotential is not 0 and hasn't been exceeded precedes incrementing the forgingCounts which enables the forger to list one more time than he should be allowed to. The increment happened much later when a merger has initiated the merging. The proper way is found in [`EntityForging::forgeWithListed()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L139C5-L144C7) but on the merging side. A forgePotential of 2 will be able to forge 3 times and a forgePotential of 4 will be able to forge 5 times.

## Impact
Forger is able to game the protocol into earning extra which the merger has to pay for.

## Proof of Concept
Assume that there is a forger, BOB with a forge potential of 2 and 2 mergers, ALICE and KEN.

```solidity
  function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    ..........
    require(
      forgePotential > 0 && forgingCounts[tokenId] <= forgePotential,
      'Entity has reached its forging limit'
    );
    ..........
  }
```
1. BOB lists his entity when forgingCounts is 0. `listForForging()` checks if 0 <= 2.
2. ALICE merges which increases the forgingCount to 1.
3. BOB lists again when forgingCounts is 1. `listForForging()` checks if 1 <= 2.
3. KEN merges to increase the forgingCounts to 2.
4. At forgingCounts = 2, BOB lists his entity once more when he shouldnt be able to. `listForForging()` checks if 2 <= 2. and allows the listing.
5. ALICE merges again and forgingCount increases to 3.

From the Proof of Concept above, it is clear that BOB is able to list 3 times, one more time than he should be able to.


## Tools Used
Manual Review

## Recommended Mitigation Steps
Increment the forgingCount for the forger tokenID before checking if the forge potential has been exceeded.
