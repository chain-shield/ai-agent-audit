# Vulnerability details

## Summary

The `nuke` function which allows users to Nuke their NFTs strategically in order to claim ETH based on the Entity’s nuke factor can be temporarily DOSed or breaks the contracts logic

## Description

The `nuke` function is meant to allow players to "nuke" (destroy) their Entity in exchange for ETH. However, according the logic and implementation of the contract, users should only be able to nuke when a Token has been matured i.e the token Last Transferred Timestamp is greater than than the minimum Days in which the token has been Held for and This is strictly checked with the following code logic:

- `require(canTokenBeNuked(tokenId), 'Token is not mature yet');`

And the `canTokenBeNuked` is implemented as follows

```solidity
    function canTokenBeNuked(uint256 tokenId) public view returns (bool) {
    // Ensure the token exists
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );
    uint256 tokenAgeInSeconds = block.timestamp -
      nftContract.getTokenLastTransferredTimestamp(tokenId);
    // Assuming tokenAgeInSeconds is the age of the token since it's holding the nft, check if it's over minimum days held
    return tokenAgeInSeconds >= minimumDaysHeld;
  }
```

The above function only returns `true` if the `tokenAgeInSeconds` which is basically the `lastTokenTransferredTimestamp` variable is >= `minimumDaysHeld` which in this case was set to 3 days.

The `lastTokenTransferredTimestamp` is defined as the last time in which a transfer of a particular tokenId was being made and this is being monitored by an ERC721 hook. This means the protocol intends to allow for a cool down period of at least 3 days for every token that has recently been transfered to other users before they can be nuked.

**ERC721 Hook implementation**

```solidity
    function _beforeTokenTransfer(
    address from,
    address to,
    uint256 firstTokenId,
    uint256 batchSize
  ) internal virtual override {
    super._beforeTokenTransfer(from, to, firstTokenId, batchSize);

    uint listedId = entityForgingContract.getListedTokenIds(firstTokenId);
    /// @dev don't update the transferred timestamp if from and to address are same
    // @audit
    if (from != to) {
      lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }

    if (listedId > 0) {
      IEntityForging.Listing memory listing = entityForgingContract.getListings(
        listedId
      );
      if (
        listing.tokenId == firstTokenId &&
        listing.account == from &&
        listing.isListed
      ) {
        entityForgingContract.cancelListingForForging(firstTokenId);
      }
    }

    require(!paused(), 'ERC721Pausable: token transfer while paused');
  }
```

From the above hook implementation, the protocol only updates the `lastTokenTransferredTimestamp` when the `from != to`, i.e the sender is not equal to the receiver.

Furthermore, the protocol allows users(sellers) to not only list their NFTs for sale, but to also un list their NFTs with the following function:

```solidity
    function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant { //@audit
        Listing storage listing = listings[listedTokenIds[tokenId]];

        // check if caller is the seller and listing is acivte
        require(
        listing.seller == msg.sender,
        'Only the seller can canel the listing.'
        );
        require(listing.isActive, 'Listing is not active.');

        nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer the nft back to seller -@audit the seller wont  nuke because the `getTokenLastTransferredTimestamp` timestamp will be updated, hence a temporary DOS

        delete listings[listedTokenIds[tokenId]]; // mark the listing as inactive or delete it

        emit ListingCanceled(tokenId, msg.sender);
    }
```

The `cancelListing` is also going to utilize the hook since it also calls `transferFrom`. And By doing so, it updates the `lastTokenTransferredTimestamp`

- This is possible because the `from` is the contract address while the `to` is the seller, hence this check will pass.
```solidity
    if (from != to) {
      lastTokenTransferredTimestamp[firstTokenId] = block.timestamp;
    }
```

Which means users who un list their NFTs are going to be temporarily bricked and will have to wait for another 3 days before they are being able to `nuke` even though the protocol only assumes to update the `lastTokenTransferredTimestamp` only when an NFT has recently been transferred.

## POC

```solidity
    function nuke(uint256 tokenId) public whenNotPaused nonReentrant {
    require(
      nftContract.isApprovedOrOwner(msg.sender, tokenId),
      'ERC721: caller is not token owner or approved'
    );
    require(
      nftContract.getApproved(tokenId) == address(this) ||
        nftContract.isApprovedForAll(msg.sender, address(this)),
      'Contract must be approved to transfer the NFT.'
    );
    require(canTokenBeNuked(tokenId), 'Token is not mature yet');

    uint256 finalNukeFactor = calculateNukeFactor(tokenId); // finalNukeFactor has 5 digits
    uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR; // Calculate the potential claim amount based on the finalNukeFactor
    uint256 maxAllowedClaimAmount = fund / maxAllowedClaimDivisor; // Define a maximum allowed claim amount as 50% of the current fund size

    // Directly assign the value to claimAmount based on the condition, removing the redeclaration
    uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
      ? maxAllowedClaimAmount
      : potentialClaimAmount;

    fund -= claimAmount; // Deduct the claim amount from the fund

    nftContract.burn(tokenId); // Burn the token
    (bool success, ) = payable(msg.sender).call{ value: claimAmount }('');
    require(success, 'Failed to send Ether');

    emit Nuked(msg.sender, tokenId, claimAmount); // Emit the event with the actual claim amount
    emit FundBalanceUpdated(fund); // Update the fund balance
  }
```

## Mitigation

Rather than checking `from != to` in the hook, you should Check against the owner of the tokenId, that is check `to != ownerOf(tokenId)`.
