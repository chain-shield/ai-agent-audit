# Vulnerability details

## Vulnerability details
The `EntityForging` contract allows users to `forge` tokens based on their `Forge Potential`, which is set randomly on Gen 1 mint. According to the protocol documentation, "the Forge Potential determines the number of times an entity can forge before becoming infertile." However, there is an off-by-one error in the `listForForging` function due to the use of the `<=` operator instead of `<`. This allows users to forge one additional time beyond their stated `Forge Potential`.

## Impact
Users can exploit this off-by-one error to forge one additional time per entity than intended. This results in entities being able to forge one more time than their Forge Potential, potentially leading to an imbalance in the game's mechanics and the overall token economy.

## Proof of Concept
Consider an entity with a Forge Potential of 5. According to the protocol documentation, this entity should be able to forge exactly 5 times within a year. However, the current implementation allows it to forge 6 times due to the <= operator.

Iterations to illustrate the bug:
`forgePotential = 5`
Forge 1st time: `forgingCounts[tokenId] = 0 (Check: 0 <= 5, passes)` 

Forge 2nd time: `forgingCounts[tokenId] = 1 (Check: 1 <= 5, passes)`

Forge 3rd time: `forgingCounts[tokenId] = 2 (Check: 2 <= 5, passes)`

Forge 4th time: `forgingCounts[tokenId] = 3 (Check: 3 <= 5, passes)`

Forge 5th time: `forgingCounts[tokenId] = 4 (Check: 4 <= 5, passes)`

Forge 6th time: `forgingCounts[tokenId] = 5 (Check: 5 <= 5, passes)`

## Recommended Mitigation Steps
Replace the `<=` operator with the `<` operator to correctly enforce the Forge Potential limit
```solidity
require(
  forgePotential > 0 && forgingCounts[tokenId] < forgePotential,
  'Entity has reached its forging limit'
);
```
