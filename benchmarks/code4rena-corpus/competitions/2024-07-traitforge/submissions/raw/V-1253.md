# Vulnerability details

## Impact

The `NukeFund::calculateAge()` function is tasked with computing the age of a token, taking into account its `performanceFactor`, which can be maximum value of `9` (entropy being 999999). Additionally, the `ageMultiplier` is currently set to `1`, a value expected to be deprecated following the audit, according to team plans. Documentation states that top-performing tokens (with entropy being 999999) should mature fastest, approximately within 30 days. However, the function’s maximum output is calculated as `30 (days) * 9 (performance factor) * 100,000 (MAX_DENOMINATOR) * 1 (ageMultiplier) / 365 = 73,972`. Subsequently, when the `NukeFund::calculateNukeFactor()` computes the `finalNukeFactor` on [L147](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L147), the result is `((73,972 (adjustedAge) * 250 (defaultNukeFactorIncrease)) / 100,000 (MAX_DENOMINATOR)) + 24,999 (initialNukeFactor = entropy / 40 = 999,999 / 40) = 25,183`. During the `NukeFund::nuke()` process, the `calculateNukeFactor()` is invoked to verify if a token’s nuke factor surpasses the `nukeFactorMaxParam`, which is `MAX_DENOMINATOR / 2 = 50,000`—nearly twice the size of the computed `finalNukeFactor`. This discrepancy suggests that the maturation period for the highest-performing tokens is not the intended 30 days, but closer to 60 days.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Consider revising the `defaultNukeFactorIncrease` to `500` or not removing `ageMultiplier` being `2` to align the maturation time of top-performing tokens with the documented 30 days.
