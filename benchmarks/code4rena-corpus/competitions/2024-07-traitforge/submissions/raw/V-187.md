# Vulnerability details

## Impact
In the current implementation, the `writeEntropyBatch3` function generates pseudo-random values for the `entropySlots` array. However, there is no validation to check if the generated value equals `999999`, which is a reserved or special value. This oversight can lead to multiple slots containing this special value, which might disrupt the expected randomness and integrity of the entropy values.

## Proof of Concept
This is the `writeEntropyBatch3` function.

    function writeEntropyBatch3() public {
        require(
            lastInitializedIndex >= batchSize2 && lastInitializedIndex < maxSlotIndex,
            'Batch 3 not ready or already completed.'
        );
        unchecked {
            for (uint256 i = lastInitializedIndex; i < maxSlotIndex; i++) {
                uint256 pseudoRandomValue = uint256(
                    keccak256(abi.encodePacked(block.number, i))
                ) % uint256(10) ** 78;
                entropySlots[i] = pseudoRandomValue; // No check for the special value
            }
        }
        lastInitializedIndex = maxSlotIndex;
    }

Here, the function does not check `pseudoRandomValue` before storing the value.

## Tools Used
Manual code review

## Recommended Mitigation Steps
To prevent the generation of duplicate special entropy values, update the `writeEntropyBatch3` function to include validation for the special value `999999`.
