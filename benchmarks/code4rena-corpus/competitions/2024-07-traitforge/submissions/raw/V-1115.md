# Vulnerability details

Rewards are not distributed to the developers when msg.value is less than totalDevWeight. This could lead to a loss of small contributions that should have been distributed to the developers.

## code
```solidity
receive() external payable {
  if (totalDevWeight > 0) {
    uint256 amountPerWeight = msg.value / totalDevWeight;
    uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
    totalRewardDebt += amountPerWeight;
    if (remaining > 0) {
      (bool success, ) = payable(owner()).call{ value: remaining }('');
      require(success, 'Failed to send Ether to owner');
    }
  } else {
    (bool success, ) = payable(owner()).call{ value: msg.value }('');
    require(success, 'Failed to send Ether to owner');
  }
  emit FundReceived(msg.sender, msg.value);
}
```

- When `msg.value` is less than `totalDevWeight`, `amountPerWeight` becomes 0 due to integer division. 

- However, `remaining` is calculated as `msg.value - (amountPerWeight * totalDevWeight)`, which in this case would be `999 - (0 * 1000) = 999`.

- The contract would then attempt to send this `remaining` amount (999) to the owner.

- `totalRewardDebt` would be increased by 0 (since `amountPerWeight` is 0).


## Mitigation


Implement a more precise calculation method that ensures fair distribution of funds, even for small contributions. Here's a potential mitigation strategy:

1. Use a percentage-based approach instead of direct division.
2. Implement a minimum contribution threshold if necessary.
3. Ensure all funds are accounted for and distributed appropriately.

Example:

```solidity
receive() external payable {
    if (totalDevWeight > 0) {
        uint256 amountForDevs = msg.value * 9999 / 10000; // 99.99% for devs
        uint256 amountPerWeight = amountForDevs / totalDevWeight;
        uint256 remaining = msg.value - amountForDevs;
        
        if (amountPerWeight > 0) {
            totalRewardDebt += amountPerWeight;
        }
        
        if (remaining > 0) {
            (bool success, ) = payable(owner()).call{value: remaining}("");
            require(success, "Failed to send Ether to owner");
        }
    } else {
        (bool success, ) = payable(owner()).call{value: msg.value}("");
        require(success, "Failed to send Ether to owner");
    }
    emit FundReceived(msg.sender, msg.value);
}
```

This approach ensures that:
1. A fixed high percentage (99.99% in this example) goes to the dev fund.
2. Even small contributions increase the `totalRewardDebt`.
3. Any remaining amount (including potential rounding errors) goes to the owner.

This solution provides a more equitable distribution of funds and prevents the loss of small contributions.

```javascript
it("should demonstrate the issue in receive function", async function () {
  // Set totalDevWeight to a non-zero value
  await devFund.setTotalDevWeight(1000);


  const initialContractBalance = await devFund.getBalance();
  const initialOwnerBalance = await ethers.provider.getBalance(owner.address);
  const initialTotalRewardDebt = await devFund.totalRewardDebt();


  const sendAmount = 999;
  await addr1.sendTransaction({
    to: devFund.address,
    value: sendAmount
  });

  // Check contract balance
  const contractBalance = await devFund.getBalance();
  expect(contractBalance).to.equal(initialContractBalance);

  // Check totalRewardDebt (should not have changed)
  const totalRewardDebt = await devFund.totalRewardDebt();
  expect(totalRewardDebt).to.equal(initialTotalRewardDebt);

  // Check owner balance change (should have received the full amount)
  const ownerBalance = await ethers.provider.getBalance(owner.address);
  expect(ownerBalance.sub(initialOwnerBalance)).to.equal(sendAmount);
});
```

This PoC demonstrates that when `msg.value` is less than `totalDevWeight`:
1. The contract's balance doesn't increase.
2. The `totalRewardDebt` doesn't increase.
3. The entire amount is sent to the owner.
