# Vulnerability details

## Impact
There could be multiple NFT with `999999` as their `entropy`, The protocol intended to generate only 1 NFT with `999999` as its `entropy` in each Generation, but there could be more than 1 NFT with `999999` as its `entropy` resulting in misbalance of game balance and dynamics.

we are generating the `pseudoRandomValue` using `keccak256` and `%` it with `10 ** 78` which gives us a 78 digit number. but the `require` statement is only checking for `999999` which will not prevent if the `pseudoRandomValue` has consicutive `999999` in its 78 digits or not.

later we are getting `entropy` based on the `slotValue` which is pseudoRandomValue and `numberIndex`.
Now let's assume we got `slotValue` as any 78 digit number but end with 6 consecutive 9's. Eg:- 123...999999 and `position` is 72. So `entropy` will be `slotValue % 1000000` which is the last 6 digit numbers, ie six 9's (999999).

Manual Review

## Recommended Mitigation Steps
when getting the `entropy` using `getEntropy()` function, check at the end if the `entropy` is 999999 or not, if it's 999999 then run the function again to get another entropy which is not 999999.
