# Vulnerability details

## Impact
The `updateDev` function has a logic error that can result in incorrect calculation of pending rewards when a developer's weight is updated. This issue can lead to overpayment or underpayment of rewards, depending on whether the weight is increased or decreased. As a result, the distribution of rewards among developers becomes unfair.

## Proof of Concept
Take a look at `updateDev` function: https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/DevFund/DevFund.sol#L40-L49

```solidity
40:   function updateDev(address user, uint256 weight) external onlyOwner {
41:     DevInfo storage info = devInfo[user];
42:     require(weight > 0, 'Invalid weight');
43:     require(info.weight > 0, 'Not dev address');
44:     totalDevWeight = totalDevWeight - info.weight + weight;
45:     info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
46:     info.rewardDebt = totalRewardDebt;
47:     info.weight = weight;
48:     emit UpdateDev(user, weight);
49:   }

```

The issue is specifically on line 45: 
```solidity
45:    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
```

The problem with this line is that it uses the old weight value to calculate the pending rewards before updating the weight. This can lead to incorrect calculations of pending rewards when a developer's weight is changed.

Here's why this is an issue:

1. The function calculates pending rewards based on the old weight.
2. It then updates the weight to the new value.
3. Future calculations will use the new weight, but the rewards accumulated up to this point were calculated using the old weight.

The function calculates pending rewards using the old weight, updates the weight, and then sets the `rewardDebt` to the current `totalRewardDebt`. This sequence of operations can lead to incorrect reward calculations in future claims.

Scenario:
1. A developer initially has a weight of 100.
2. The `totalRewardDebt` increases by 1 ETH per weight unit.
3. The owner calls `updateDev` to change the developer's weight to 200.
4. The function calculates pending rewards based on the old weight (100), resulting in 100 ETH of pending rewards.
5. The weight is updated to 200, and `rewardDebt` is set to the current `totalRewardDebt`.
6. In the next reward distribution, the developer will receive rewards as if they had a weight of 200 all along, effectively doubling their rewards for the period before the weight update.

This scenario results in an overpayment to the developer, while a decrease in weight would result in an underpayment.

## Recommended Mitigation Steps
Consider modifying the `updateDev` function to calculate pending rewards using the old weight, update the weight, and then set the `rewardDebt` to the current `totalRewardDebt`. 

```diff
function updateDev(address user, uint256 weight) external onlyOwner {
    DevInfo storage info = devInfo[user];
    require(weight > 0, 'Invalid weight');
    require(info.weight > 0, 'Not dev address');
-   totalDevWeight = totalDevWeight - info.weight + weight;
    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
+   totalDevWeight = totalDevWeight - info.weight + weight;
+   info.weight = weight;
    info.rewardDebt = totalRewardDebt;
-   info.weight = weight;
    emit UpdateDev(user, weight);
}
```
