# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L67-L97

```solidity
function listForForging(
  uint256 tokenId,
  uint256 fee
) public whenNotPaused nonReentrant {
  Listing memory _listingInfo = listings[listedTokenIds[tokenId]];

  require(!_listingInfo.isListed, 'Token is already listed for forging');
  require(
    nftContract.ownerOf(tokenId) == msg.sender,
    'Caller must own the token'
  );
  require(
    fee >= minimumListFee,
    'Fee should be higher than minimum listing fee'
  );

  // ... sni0

  ++listingCount;
  listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
  listedTokenIds[tokenId] = listingCount;

  emit ListedForForging(tokenId, fee);
}
```

This function allows users to list their tokens for forging with a _fee_ of their choice, as long as it's above the `minimumListFee`. However, there's no upper limit on said fee.

A malicious actor could exploit this by:

1. Minting a large number of tokens.
2. Listing these tokens for forging with extremely high fees.

it.only('Audit: Allows listing with extremely high fees', async () => {

## Impact

This vulnerability can severely disrupt the game's economy and user experience:

By flooding the market with high-fee listings, the attacker can artificially inflate the average forging cost.

Legitimate players who want to list their tokens for reasonable fees may find their listings buried under the inflated ones, and due to that also inflate their own _fees_, which would mean lesser _forging_ would occur since less people would want to forge when the fee is high.

As per the TraitForge overview from the readMe, players can "nuke" (burn) their NFTs to claim ETH from the nuke-fund. If forging becomes too expensive, it might incentivise more players to nuke their tokens instead of forging, which could imbalance the game's intended dynamics.

5. Competitive Aspect Undermined: The TraitForge overview emphasizes competition "in every aspect of the game". However, this vulnerability allows a malicious actor to dominate the forging market unfairly, undermining the competitive spirit of the game.

## Recommended Mitigation Steps

Add an upper bound for the forging fee.

```solidity
uint256 public maximumListFee = 1 ether; // Example value

function listForForging(uint256 tokenId, uint256 fee) public whenNotPaused nonReentrant {
  // ... existing checks ...
  require(fee <= maximumListFee, "Fee exceeds maximum allowed");
  // ... rest of the function ...
}
```

Alternatively, implement a dynamic fee cap based on recent forging activities. For example, limit the fee to no more than 200% of the average fee from the last 10 forgings.
