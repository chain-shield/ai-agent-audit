# Vulnerability details

## Impact
This will lead to a wrong `listingCount` value and further complications

## Proof of Concept
```solidity
function listForForging(
    uint256 tokenId,
    uint256 fee
  ) public whenNotPaused nonReentrant {
    Listing memory _listingInfo = listings[listedTokenIds[tokenId]];

    require(!_listingInfo.isListed, 'Token is already listed for forging');

...

    ++listingCount;
    listings[listingCount] = Listing(msg.sender, tokenId, true, fee);
    listedTokenIds[tokenId] = listingCount;

    emit ListedForForging(tokenId, fee);
  }
```
we can observe that from the code above anytime a token is being listed for forging the `listingCount` value is increased by 1 but from the code below when a user wants to cancel calls `cancelListingForForging` he doesn't want to submit that tokenid for forging again, therefore it should be deleted from the list. However whenever it is deleted the storage variable `listingCount` that is increased when adding to list is not decreased when removing.

```solidity
function cancelListingForForging(
    uint256 tokenId
  ) external whenNotPaused nonReentrant {
    require(
      nftContract.ownerOf(tokenId) == msg.sender ||
        msg.sender == address(nftContract),
      'Caller must own the token'
    );
    require(
      listings[listedTokenIds[tokenId]].isListed,
      'Token not listed for forging'
    );

    _cancelListingForForging(tokenId);
  }
```
