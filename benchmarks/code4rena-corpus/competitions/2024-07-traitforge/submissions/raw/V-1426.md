# Vulnerability details

## Impact
The `buyNFT` method is used to buy a listed NFT. The `nukeFundContribution` value needs to be calculated for contribution when purchasing.

1. `nukeFundContribution` is calculated as follows:

```
uint256 nukeFundContribution = msg.value / taxCut;
```

Here, `msg.value` is the amount of ETH sent by the user when purchasing the NFT, and `taxCut` is a pre-set value used to calculate the fee ratio contributed to `nukeFund`.

2. `sellerProceeds` is the final amount received by the seller, calculated as follows:

```
uint256 sellerProceeds = msg.value - nukeFundContribution;
```

The problems here are:

- **Rounding down due to integer division**: Since Solidity's integer division rounds down, `nukeFundContribution` may be calculated as zero when `msg.value` is small or `taxCut` is large. For example, if `msg.value` is 9 and `taxCut` is 10, then `nukeFundContribution` will be calculated as 0.
- **Bypassing `nukeFundContribution`**: If `nukeFundContribution` is calculated as zero, the seller's `sellerProceeds` will be equal to the entire `msg.value`, which will completely bypass the contribution fee paid to `nukeFund`. Specifically, the seller sets `msg.value` to 9, and `taxCut` is 10. Then `nukeFundContribution` will be calculated as 0. This completely bypasses the contribution fee paid to `nukeFund`.

## Proof of Concept

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntityTrading/EntityTrading.sol#L73


The seller calls the `listNFTForSale` method to set `msg.value` to 9. When the buyer purchases through the `buyNFT` method, `taxCut` is 10, so after the calculation `uint256 nukeFundContribution = msg.value / taxCut;`, `nukeFundContribution` will be calculated as 0. This completely bypasses the contribution fee paid to `nukeFund`.

Similarly, if taxCut is set to a larger value, bypassing may occur.

## Recommended Mitigation Steps

To prevent `nukeFundContribution` from being bypassed, you can fix it in the following ways:

1. **Set minimum contribution**: After calculating `nukeFundContribution`, force a minimum contribution value. For example:

```
uint256 nukeFundContribution = msg.value / taxCut;
if (nukeFundContribution == 0 && msg.value > 0) {
nukeFundContribution = 1; // Force minimum contribution value to 1 wei
}
```

2. **Check `nukeFundContribution`**: Before making payments and transfers, add additional checks to ensure that `nukeFundContribution` is not zero or meets the expected minimum contribution value.
