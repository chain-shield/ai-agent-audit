# Vulnerability details

## Impact
Missing slippage check when a user calls the `nuke` function in the `NukeFund` contract.

Every user who holds an NFT and passes all requirements for claiming a portion of the fund in the `NukeFund` contract can call the `nuke` function. The maximum reward a user can claim is 50% of the received fund in the contract.

When a user sends their transaction to claim 50% of the funds, he can easily be front-run as another user can claim 50% or less of the held funds in the contract. This can result in the user receiving less ethers than expected.

Attack vector: For the example below `fund = 10 eth`:
1. Bob calls the `nuke` function to claim `50%` of the funds.
2. Alice front-runs Bob's transaction and claims `40%` of the funds.
3. As a result, Alice will receive `4` eth, and Bob will receive `3` eth, as he expected to receive at least `5` eth.

The current economics of the protocol incentivize users to wait until the funds held in the contract are as large as possible so they can claim as much ether as possible. Therefore, if a user or MEV bot detects that a new transaction is in the mempool, which will claim a larger portion of the funds, the MEV bot can easily front-run the transaction.

## Recommended Mitigation Steps
Add an input parameter `minAmountOut` to the `nuke` function so users can set the minimum amount they expect to receive. If the amount is less than this, the transaction should revert.
