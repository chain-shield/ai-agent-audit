# Vulnerability details

## Impact

There are actually 2 vulnerabilities here that can be fixed in a similar way.

According to the [documentation](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit#heading=h.45lywoxkn9oi):
> There is a certain entropy, “999999” which is referred to as “the Golden God”, since it has perfect parameters and will exceed all other entities if played correctly. The Golden God is scanned for and is kept out of the first 2 passes, but is deliberately set in the final pass (at some random point). The Golden God should be the most valuable entity. 

But the check for 999999 is implemented incorrectly, which allows it to be in the 1.2-second batch.

From developer comment in [discord public contest channel](https://discordapp.com/channels/810916927919620096/1266325696079466609/1269284729094672426):
> [16:06]D_Auditor: @ManPeach.0x how many Golden God should exist at a time for every generation?
> 
> [16:24]ManPeach.0x: 1 per gen

But the lack of checks allows the Golden God to be present several times per generation and even several times per batch.


## Proof of Concept

First I had to fuzz test it to make sure this situation was even possible:

```solidity
function testFuzz_God(uint256 _timestamp, uint256 _block) public {
    vm.warp(_timestamp);
    vm.roll(_block);
    entropyGenerator.writeEntropyBatch1();
    entropyGenerator.writeEntropyBatch2();
    entropyGenerator.writeEntropyBatch3();

    uint256 maxSlotIndex = 770;
    uint256 maxNumberIndex = 13;
    uint256 god_count = 0;
    for (uint256 currentSlotIndex = 0; currentSlotIndex < maxSlotIndex; currentSlotIndex++) {
        for (uint256 currentNumberIndex = 0; currentNumberIndex < maxNumberIndex; currentNumberIndex++) {
            uint256 e = entropyGenerator.getPublicEntropy(currentSlotIndex, currentNumberIndex);

            if (e == 999999) {
                god_count++;
            }
        }
    }

    assert(god_count == 1);
}
```

From this fuzz I get timestamp: 8737, block: 137369981099426463035573095195, You can get completely different values, because there are definitely multiple of them

- Only `testHigh_wrongRandom` is the PoC, the rest is setup
- You can use different values ​​from the fuzz to tune this PoC
- In the log section you can see that Golden God occurs twice, and even in the second batch
