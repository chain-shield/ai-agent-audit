# Vulnerability details

## Impact
From the documentation, the `TFGNFT` should be capped at `maxGeneration`, which is 10. But users still can use `TraitForgeNft#mintToken` to mint `TFGNFT` over `maxGeneration`.

After the first 24 hours of the deployment of `TraitForgeNft`, users can bypass the `onlyWhitelisted` modifier of `mintToken`

```solidity
  modifier onlyWhitelisted(bytes32[] calldata proof, bytes32 leaf) {
    if (block.timestamp <= whitelistEndTime) {
      require(
        MerkleProof.verify(proof, rootHash, leaf),
        'Not whitelisted user'
      );
    }
    _;
  }

  constructor() ERC721('TraitForgeNft', 'TFGNFT') {
    whitelistEndTime = block.timestamp + 24 hours;
  }
```

Since there is not validation to cap the `currentGeneration` at `maxGeneration` in `mintToken`, `_mintInternal`, and `_incrementGeneration`, users still can mint `TFGNFT` over `maxGeneration` using `mintToken`.

## Tools Used
Manual Review.

## Recommended Mitigation Steps

Add a validation in `TraitForgeNft#mintToken` to ensure that `TFGNFT` can not be minted over `maxGeneration`.

```diff
  function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
+   require(currentGeneration <= maxGeneration);
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
```
