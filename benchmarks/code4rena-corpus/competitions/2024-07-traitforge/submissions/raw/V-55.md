# Vulnerability details

## Impact
Invariant maxTokensPerGen might be broken. One generation might have more than maxTokensPerGen NFTs.

## Proof of Concept
When whitelist mints NFT tokens, we will check whether current generation's nft amount equals to `maxTokensPerGen`. If current generation's amount equals to or is larger than `maxTokensPerGen`, we will move to the next generation, and the newly NFT will be added into the next generation.
This logic will be true based on one assumption that `generationMintCounts` for next generation is less than `maxTokensPerGen`. But this assumption is not always true considering that users can forge NFTs in the next generation.
Considering the below scenario:
1. Alice and Bob mint lots of NFTs in generation 0.
2. Alice and Bob list for forging and forge in generation 1. For example, we mint 100 NFT in generation 1.
3. When Cathy as one whitelist wants to mint the 10001th NFT in generation 0, we will increase generation and reset the new generation's `generationMintCounts`.

The actual mint count in generation 1 might be larger than `maxTokensPerGen`.

## Recommended Mitigation Steps
When we increase the generation, don't reset `generationMintCounts` because there might be some valid NFTs in the newly generation.
