# Vulnerability details

## Impact
This `TraitForge` protocol is intended to be operated by an owner, There are some functions that should always remain decentralized or immutable but the owner can change them either without emitting any event or without anyone knowing about it or the owner can easily manipulate the protocol functionality to his advantage even if there are fair awards. They too can manipulate the owner or there is no need to give so much power to the owner, it should not be the intended behavior of smart contracts.
some of those protocol functionalities are given below:

- In the `DevFund.sol` contract, There should be a maximum weight in the `DevFund::addDev` function that the owner cannot give more weight than the maximum weight to any dev.
- In `EntityForging.sol` and `EntityTrading.sol` contracts, There should be a maximum `taxCut` in `EntityForging::forgeWithListed` function that the owner cannot manipulate forgerShare and give more devFee than 10% of the `forgingFee`. According to docs, it should be 10% why this owner can change this?
- In `NukeFund.sol`, An owner can reset `MaxallowedclainDivisor` and `nukefactorMaxParam` but these are intended that `MaxallowedclainDivisor` should be 2 and `nukefactorMaxParam` should be MAX_DENOMINATOR/2 according to documentation. This protocol is over-owned the owner can also manipulate participant's awards. It can ruin the protocol.

  }
