# Vulnerability details

The `taxCut` calculation in the `EntityForging`, `EntityTrading`, and `NukeFund` contracts is incorrect. For instance, consider the `devShare` calculation in the `receive` function of the `NukeFund` contract. If the owner sets a `taxCut` value of 2, the calculation incorrectly allocates 50% of the received funds to the developer instead of the intended 2%. This deviation from the intended behavior needs to be addressed.

## Impact
1. This issue can lead to an incorrect and potentially wrong allocation of funds to the developer address if the `taxCut` is set to a different value in the `NukeFund` contract.

2. The seller and `NukeFund` contract will receive the wrong amount instead of the intended amount when someone purchases the listed NFT.

3. The developer and `NFT` contract will receive the wrong amount instead of the intended amount when someone forges the listed NFT.

## Proof of Concept
Lets take `devShare` calculation in the `receive` function of the `NukeFund` contract as an example.

The `receive()` function calculates the developer's share (`devShare`) based on the `taxCut` value. The current calculation is as follows:

```solidity
    receive() external payable {
@>>   uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
      uint256 remainingFund = msg.value - devShare; // Calculate remaining funds to add to the fund
```

The calculation `devShare = msg.value / taxCut` is correct for the default `taxCut`, which is 10. However, if the owner changes the `taxCut` to another value using `setTaxCut()`, the calculation of `devShare` becomes incorrect.

For example, if the owner sets the `taxCut` value to 2, the formula will allocate 50% of the funds to the developer, which is not intended.

Consider the following scenario:

If the owner changes the `taxCut` to `2` and `msg.value` is `100`, then the `devShare` calculation becomes:

`devShare = msg.value / taxCut` => `devShare = 100 / 2` => `50`

This means 50% of the `msg.value` is transferred to `devAddress` instead of 2%.

## Recommended Mitigation Steps
Ensures that the `taxCut` value is treated as a percentage to prevent wrong allocation of funds.

```solidity
    uint256 devShare = (msg.value * taxCut) / 100; // Calculate developer's share as a percentage
```
```solidity
    uint256 devFee = (forgingFee * taxCut) / 100;
```
```solidity
    uint256 nukeFundContribution = (msg.value * taxCut) / 100;
```
