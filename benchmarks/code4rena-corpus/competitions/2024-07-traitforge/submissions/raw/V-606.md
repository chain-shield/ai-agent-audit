# Vulnerability details

## Description

The `EntityForging` contract allows users to list and cancel listings for forging without any enforced cooldown period. This lack of a cooldown mechanism means that users can repeatedly list, cancel, and re-list tokens without restrictions, 


## Impact

1. Market manipulation: users can rapidly list and delist tokens, potentially manipulating the market or disrupting other players' forging. This could lead to unfair advantages and undermine the integrity of the forging feature.

2. potential denial of service: the ability to perform repeated actions without cooldown can lead to network congestion or increased gas fees. This could potentially deny access for other users trying to forge their NFTs interacting with the contract.



## Proof of Concept

```
const { expect } = require("chai");
const { ethers } = require("hardhat");

describe("EntityForging Contract", function () {
  let EntityForging, entityForging, owner, addr1, nftContract;

  beforeEach(async function () {
    [owner, addr1, ...addrs] = await ethers.getSigners();
    const NFTContract = await ethers.getContractFactory("MockNFTContract");
    nftContract = await NFTContract.deploy();
    await nftContract.deployed();

    EntityForging = await ethers.getContractFactory("EntityForging");
    entityForging = await EntityForging.deploy(nftContract.address);
    await entityForging.deployed();
  });

  it("Should allow immediate cancellation and re-listing", async function () {
    const tokenId = 1;
    const listingFee = ethers.utils.parseEther("0.01");

    // Mint a token to addr1
    await nftContract.mint(addr1.address, tokenId);

    // Approve the EntityForging contract to manage the token
    await nftContract.connect(addr1).approve(entityForging.address, tokenId);

    // List the token for forging
    await entityForging.connect(addr1).listForForging(tokenId, listingFee);

    // Cancel the listing
    await entityForging.connect(addr1).cancelListingForForging(tokenId);

    // Re-list the token for forging
    await entityForging.connect(addr1).listForForging(tokenId, listingFee);

    // Assert that the token is listed again
    const listing = await entityForging.getListings(tokenId);
    expect(listing.isListed).to.be.true;
  });
});


```

## Recommended Mitigation Steps


1. Implementing a cooldown mechanism that prevents users from listing or delisting tokens immediately. 

```
mapping(uint256 => uint256) private lastActionTimestamp;
uint256 public constant COOLDOWN_PERIOD = 1 hours; // Adjustable

function listForForging(uint256 tokenId, uint256 fee) external {
    require(block.timestamp >= lastActionTimestamp[tokenId] + COOLDOWN_PERIOD, "Cooldown period not elapsed");
    // Existing listing logic...
    lastActionTimestamp[tokenId] = block.timestamp;
}

function cancelListingForForging(uint256 tokenId) external {
    require(block.timestamp >= lastActionTimestamp[tokenId] + COOLDOWN_PERIOD, "Cooldown period not elapsed");
    // Existing cancellation logic...
    lastActionTimestamp[tokenId] = block.timestamp;
}
```
2. Implementing a progressive cooldown for more flexibility, a progressive cooldown where the waiting period increases with frequent actions and gradually decreases over time.

```
mapping(uint256 => uint256) private lastActionTimestamp;
mapping(uint256 => uint256) private actionCount;
uint256 public constant BASE_COOLDOWN = 1 hours;
uint256 public constant MAX_COOLDOWN = 24 hours;

function getCooldownPeriod(uint256 tokenId) private view returns (uint256) {
    uint256 cooldown = BASE_COOLDOWN * (2 ** actionCount[tokenId]);
    return cooldown > MAX_COOLDOWN ? MAX_COOLDOWN : cooldown;
}

function listForForging(uint256 tokenId, uint256 fee) external {
    require(block.timestamp >= lastActionTimestamp[tokenId] + getCooldownPeriod(tokenId), "Cooldown period not done yet");
    // Existing listing logic...
    lastActionTimestamp[tokenId] = block.timestamp;
    actionCount[tokenId]++;
}

// the same logic applies for `cancelListingForForging` function


```
