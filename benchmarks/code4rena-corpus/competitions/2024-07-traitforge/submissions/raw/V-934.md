# Vulnerability details

The `EntropyGenerator` contract allows batch writing of entropy values, but lacks mechanisms to ensure all batches are properly initialized, potentially leading to uninitialized or partially initialized entropy.

The `EntropyGenerator` contract uses three separate functions to initialize entropy batches:

```
function writeEntropyBatch1() public {
    require(lastInitializedIndex == 0, 'Batch 1 already initialized.');
    // ... initialization logic ...
}

function writeEntropyBatch2() public {
    require(lastInitializedIndex == batchSize1, 'Batch 2 already initialized.');
    // ... initialization logic ...
}

function writeEntropyBatch3() public {
    require(lastInitializedIndex == batchSize1 + batchSize2, 'Batch 3 already initialized.');
    // ... initialization logic ...
}
```

However, there's no mechanism to ensure these functions are called in order or that all batches are fully initialized before the system becomes operational.

## Impact
The potential for incomplete initialization could lead to:

Partial or incomplete entropy data, resulting in biased or predictable randomness.
System malfunction if entropy is requested from uninitialized slots.
Inconsistent behavior across different parts of the system that rely on entropy.
Difficulty in determining whether the system is fully initialized and ready for use.

These issues could compromise the integrity and fairness of any features dependent on the entropy generator, potentially affecting the entire ecosystem built around this randomness source.

## Proof of Concept
Deploy the `EntropyGenerator` contract.
Call `writeEntropyBatch1()` to initialize the first batch.
Skip calling `writeEntropyBatch2()`.
Call `writeEntropyBatch3()`. This will fail due to the require statement, but there's no way to know if batch 2 was initialized without checking the contract state manually.
The system is now in a partially initialized state, with no clear indication of this fact to users or dependent contracts.

## Tools Used
Manual review

## Recommended Mitigation Steps
Implement a state machine to track the initialization process:

```
enum InitializationState { NotStarted, Batch1Done, Batch2Done, Completed }
InitializationState public initState = InitializationState.NotStarted;
```
