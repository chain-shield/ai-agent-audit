# Vulnerability details

In the `writeEntropyBatch1`, `writeEntropyBatch2` and `writeEntropyBatch3`  functions, there's a require statement that checks if pseudoRandomValue is equal to 999999:

```
require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```

However, `pseudoRandomValue` is a 78-digit number, making it practically impossible for this condition to ever be true.

## Impact
Increased Gas Costs: The unnecessary require statement is executed in a loop, consuming additional gas for each iteration. This leads to higher transaction costs for users.

This is also the reason why setting entropy values cannot be set during contract initialization in a single transaction and has to be done in 3 batches due to contract & block size limits.

## Proof of Concept
The `pseudoRandomValue` is generated as follows:
```
uint256 pseudoRandomValue = uint256(keccak256(abi.encodePacked(block.number, block.timestamp, msg.sender)));
```
This generates a 78-digit number.
The check pseudoRandomValue != 999999 will always be true, as 999999 is only a 6-digit number.

## Tools Used
Manual review

## Recommended Mitigation Steps
Remove the unnecessary require statement:
``` 
- require(pseudoRandomValue != 999999, 'Invalid value, retry.');
```
