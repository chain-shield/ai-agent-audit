# Vulnerability details

## Impact
Attacker can cause loss of funds for a user by frontrunning a forge. 

## Proof of Concept
Assume the following scenario:
1. Attacker lists an entity for forging with a fee = 2ETH

2. A user wants to forge with this entity so, puts msg.value = 2ETH and calls the forgeWithListed() function.

3. The attacker frontruns this transaction, by cancelling the list and putting up a new forging for the same entity with fee = 1 ETH.

4. When the users transaction goes through, the function only checks if msg.value >= forgingFee (2ETH >= 1ETH) (https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L126)

The remaining 1 ETH is not given back to the user and also not given to the nukeFund. Thus causing a loss of funds for the innocent user.

## Tools Used
Manual Review 

## Recommended Mitigation Steps
Change the line 126 by changing `>=` to `==`:
`require(msg.value == forgingFee, 'Insufficient fee for forging');`
