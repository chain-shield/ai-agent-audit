# Vulnerability details

## Impact
Users can nuke tokens immediately after minting, completely bypassing the intended holding period.

## Proof of Concept
Users can nuke tokens immediately after minting, bypassing the intended holding period. This issue stems from the lastTokenTransferredTimestamp not being initialized during the minting process, leading to a miscalculation of the token's age in the canTokenBeNuked() function.

The vulnerability originates from the minting process not calling the _beforeTokenTransfer() function, which is responsible for setting the lastTokenTransferredTimestamp. As a result, this timestamp remains at its default value of 0 for newly minted tokens.

In the _mintInternal() function, we see:

```
function _mintInternal(address to, uint256 mintPrice) internal {
    // ... other code ...
    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    // ... other code ...
}

```
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L285-L287

Notably absent is a call to _beforeTokenTransfer(), which should set the lastTokenTransferredTimestamp.

The canTokenBeNuked() function contains the vulnerable logic as the getTokenLastTransferredTimestamp() function returns the uninitialized value:

```
function canTokenBeNuked(uint256 tokenId) public view returns (bool) {
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );
    uint256 tokenAgeInSeconds = block.timestamp -
      nftContract.getTokenLastTransferredTimestamp(tokenId);
    return tokenAgeInSeconds >= minimumDaysHeld;
}

function getTokenLastTransferredTimestamp(uint256 tokenId) public view returns (uint256) {
    require(
      ownerOf(tokenId) != address(0),
      'ERC721: query for nonexistent token'
    );
    return lastTokenTransferredTimestamp[tokenId];
}

```

Let's assume minimumDaysHeld is set to 3 days (259,200 seconds).

Scenario:

- User mints a token at block.timestamp 1000000000.
- lastTokenTransferredTimestamp is 0 (uninitialized).
- User attempts to nuke the token immediately:

tokenAgeInSeconds = 1000000000 - 0 = 1000000000
1000000000 >= 259200 (3 days) is true

- The token can be nuked immediately.

Manual review

## Recommended Mitigation Steps
Modify _mintInternal() to call _beforeTokenTransfer()
