# Vulnerability details

## Impact
forgeWithListed() is susceptible to frontrun if msg.value > forgingFee.
This is possible becuase the check for msg.value is (msg.value >= forgingFee). That makes it so if a user sends more eth in order to forge, a malicous forger may observe the mempool see that his listing
is going to be merged with this user and up the forgingFee with listForForging, frontrunning the forging event and getting all the msg.value. 

Even if there is not a frontrun the contract should refund any amount that is more than the forging fee.

Impact - high 
Likelihood - low 
Overall - medium

## Proof of Concept

Let's have Alice and Bob

1. Alice listForForging (tokenId = 9999, fee = 1eth)
2. Bob sees the listing of tokenId 9999 and now wants to merge with it
3. Bob calls forgeWithListed(tokenId = 9999) with 1.5 eth
4. Alice observing the mempool sees that and frontruns with listForForging (tokenId = 9999, fee = 1eth).
5. Alice takes all the msg.value

```solidity
uint256 forgingFee = _forgerListingInfo.fee;
require(msg.value >= forgingFee, 'Insufficient fee for forging');
```

Manual review

## Recommended Mitigation Steps
Make the statement require(msg.value == forgingFee, 'Insufficient fee for forging');
