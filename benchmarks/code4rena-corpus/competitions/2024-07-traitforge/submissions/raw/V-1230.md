# Vulnerability details

## Impact
The `TraitForgeNft` contract has functions `burn()`, `_mintInternal()`, `_incrementGeneration`, which have call functions from another contract. The [`burn()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L141-L151) function calls the [`subUserAmount`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/Airdrop/Airdrop.sol#L57C2-L65C4) function of the `Airdrop.sol` contract.

  The [`_incrementGeneration()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L345-L355) function calls the [`initialiseAlphaIndices()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L206-L216) function of the `EnropyGenerator.sol` contract.

TraitForgeNft.sol::_incrementGeneration()
  */
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;

  /**
EnropyGenerator.sol::initialiseAlphaIndices()
  */
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }

The vulnerability is that calls to internal functions will be returned with an error and will completely cancel the function call and return an unchanged state. This happens because internal functions have the `onlyOwner` modifier. Accordingly, to call these functions `msg.sender==owner()` but when calling internal functions `msg.sender ==address(TraitForgeNft)`. Because of this, when calling the `burn()` function, if the **airdrop starts**, the player cannot burn his token, also, the burn function is called from the `NukeFund` contract in the [`nuke()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L176) function, thus the player cannot get his reward.  When calling the external functions [`mintToken`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L193) and [`mintWithBudget`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L216), the internal function `_mintInternal()` is called, which in turn calls `_incrementGeneration()` if the number of entities in the current generation has reached its maximum and if an airdrop has started, it calls `addUserAmount` of the `Airdrop` contract, which increases the entropy of the user, which affects the **"winnings"**.
Since all these functions are essential to the proper functioning of the protocol, failure to invoke them is a high degree of vulnerability.

## Recommended Mitigation Steps
You should consider adding a modifier `onlyOwnerAndTraitForgeNft` to the `Airdrop` and `EntropyGenerator`  contract
For example:
```solidity
modifier onlyOwnerAndTraitForgeNft() {
    require(msg.sender == address(traitForgeNft) || msg.sender==owner(), 'Caller is not contract or owner'); 
    _;
}
```
