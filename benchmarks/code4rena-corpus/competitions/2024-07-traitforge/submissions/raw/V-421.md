# Vulnerability details

## Impact

The owner gets the fund instead of the devs.

## Proof of Concept

A percentage of the proceeds of the protocol will go to the devFund. When it goes to the devFund contract, the `receive()` fallback function will be invoked:

```
  receive() external payable {
    if (totalDevWeight > 0) {
      uint256 amountPerWeight = msg.value / totalDevWeight;
      uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
      totalRewardDebt += amountPerWeight;
      if (remaining > 0) {
>       (bool success, ) = payable(owner()).call{ value: remaining }('');
        require(success, 'Failed to send Ether to owner');
      }
    } else {
>     (bool success, ) = payable(owner()).call{ value: msg.value }('');
      require(success, 'Failed to send Ether to owner');
    }
    emit FundReceived(msg.sender, msg.value);
  }
```

This function calcaultes the amountPerWeight and attempts to distribute the fund evenly to all the devs that is added.

If there is a remainder, the remaining funds go to the owner. Else, the funds also goes to the owner, which is incorrect as the fund should stay in the contract.

Let's say `msg.value` is 101, `totalDevWeight` is 100. 

```
      uint256 amountPerWeight = msg.value / totalDevWeight;
      uint256 remaining = msg.value - (amountPerWeight * totalDevWeight);
```

The `amountPerWeight` is 1, and the remaining is 1. This 1 wei `remaining` will got to the owner, and the rest of the 100 wei will be left in the contract, which is correct since the devs can call `claim()` to claim their appropriate funds in the contract.

now, let's say `msg.value` is 1e18, `totalDevWeight` is 100.

The `amountPerWeight` is 100e16, and remaining is 0 (divided evenly). Since remaining is 0, the entire `msg.value` go to the owner, which is incorrect.

The owner then has to deposit the funds back to the contract for the dev to receive, but by then it will affect the `amountPerWeight` and the funds still ultimately go back to the owner.

The owner has to manually calculate the proportion of every fund receive to every owner, which is not ideal.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Recommend removing the else clause in the receive() fallback function.
