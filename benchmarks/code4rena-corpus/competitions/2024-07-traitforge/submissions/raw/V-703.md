# Vulnerability details

## Impact
The `entropy` value in the mintToken function, which determines the traits of an NFT, is not dependent on the `msg.sender`. This makes it possible for users to monitor transactions and front-run others if the generated `entropy` is favorable to them. This creates an unfair advantage for certain users, particularly those employing MEV bots, leading to an unfair playing field.

## Proof of Concept

In the `mintToken` function, the `entropy` is determined using `entropyGenerator.getNextEntropy()`, which does not take `msg.sender` into account:

```solidity
    uint256 entropyValue = entropyGenerator.getNextEntropy();
```

Since the `entropyValue` determines important traits of an NFT, it becomes a target for front-running. A user can monitor pending transactions, evaluate the entropy, and decide to front-run the transaction if the entropy is favorable. This behavior can especially benefit MEV bots, creating an unfair situation for regular users.

Given that the contract is intended to be deployed on the `Base` chain, any future decentralization of the sequencer would exacerbate this issue.
## Tools Used
Manual
## Recommended Mitigation Steps
- Add a mechanism to detect and blacklist MEV bots or other malicious actors. 
- Modify the entropy generation to include msg.sender in the calculation.
