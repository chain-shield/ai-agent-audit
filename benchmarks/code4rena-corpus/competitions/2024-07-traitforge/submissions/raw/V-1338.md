# Vulnerability details

## Impact
`calculateMintPrice()` returns the mint price for a nft. The problem is there, every time the next generation should be updated `calculateMintPrice()` function is called before generations get updated leaving the user to pay for the first nft of a new generation, but with the price of the last one in the previous generation.

## Proof of Concept
```Solidity
  function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender))) 
  {
    uint256 mintPrice = calculateMintPrice(); //@a get mint price 
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.'); 
    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice; 
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }(''); //@a possible contract reentrancy but CEI pattern followed
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
```
In the code above, mint price is calculated before updating generations leaving the user paying a higher price for the first nft of the new generation. Generation gets updated in `_mintInternal` function which gets called after.

```Solidity
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration(); 
    }
```
This if statement is from the `_mintInternal` function and aims to determine if a new generation should be incremented. The issue comes from there this check is done after calculating the mint price leaving the user to pay a higher price than he should resulting in a loss of funds for the user.

## Tools Used
Manual review

## Recommended Mitigation Steps
```Solidity
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration(); 
    }
```
Add this check before calculating the mint price for nft.
