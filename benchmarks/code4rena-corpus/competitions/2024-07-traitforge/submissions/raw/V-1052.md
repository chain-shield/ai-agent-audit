# Vulnerability details

In the `forgeWithListed` function, the new forged entity is assigned the next available token ID, while its generation is calculated based on its parent entities.

This can lead to scenarios where token IDs and generations don't align intuitively.

## Impact
User Confusion: 
Players may expect token IDs to correlate with generations, leading to misunderstandings about entity lineage and age.

## Proof of Concept
Consider the following scenario:

Entities with token IDs 20 (gen 1) and 4 (gen 1) are forged.
The current total supply is 25.
The new forged entity receives token ID 26 but is of generation 2.
Later, a new gen 1 entity is minted with ID 27.

This results in:

Token ID 26: Generation 2
Token ID 27: Generation 1

Which is counterintuitive and potentially confusing for users and systems interacting with these entities.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider implementing a more intuitive ID system that incorporates generation information
Eg getting next tokenIDs using:

```
maxTokensPerGen * (newGeneration - 1) + generationMintCounts + 1;
```

This will create the following system:
Gen 1 - TokenID's 1 - 10000,
Gen 2 - TokenID's 10001 - 20000
and so on
