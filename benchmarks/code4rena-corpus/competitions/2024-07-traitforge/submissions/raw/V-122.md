# Vulnerability details

## Impact
Minting will halt after 10000 NFTs of Gen-1 are minted, the next generation can't be minted any further due to `onlyOwner` access modifier.

## Proof of Concept
The `owner` of the `EntropyGenerator` contract is the team's multisig. `EntropyGenerator::initializeAlphaIndices` would be called in the constructor, as it will be an internal call and `msg.sender` is the deployer, i.e. the owner.

```javascript
  function initializeAlphaIndices() public whenNotPaused onlyOwner {
```

However, the `TraitForgeNft::_incrementGeneration` function calls `EntropyGenerator::initializeAlphaIndices`. This is an external call, and `msg.sender` would be the `TraitForgeNft` contract.
```javascript
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```

## Recommended Mitigation Steps

Simply changing `onlyOwner` to `onlyAllowedCaller` modifier would cause the constructor to fail.

It'll be better to create a new modifier:

```diff
+   modifier onlyOwnerOrAllowedCaller() {
+       require(msg.sender == allowedCaller || msg.sender == owner(), 'Caller is not owner or allowed');
+      _;
+   }
```
