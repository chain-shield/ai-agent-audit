# Vulnerability details

## Impact
Not setting the owner of the EntropyGenerator contract to the TraitForgeNft contract will result in the `_incrementGeneration` function always reverting, effectively halting the generation increment process. Conversely, setting the owner to TraitForgeNft will restrict future calls to the `setAllowedCaller` function in the EntropyGenerator contract, limiting its flexibility and control.

## Proof of Concept
After deploying the EntropyGenerator contract, the Owner will be the developer's EOA account. According to the deployment script deployTasks, the owner of this contract will not be changed subsequently.

The `initializeAlphaIndices` function of the EntropyGenerator contract has an `onlyOwner` modifier, which means that only the owner of the contract can call it.
```solidity
function initializeAlphaIndices() public whenNotPaused onlyOwner {
    uint256 hashValue = uint256(
        keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
}
```

However, this function is also called in the TraitForgeNft contract.
```solidity
function _incrementGeneration() private {
    require(
        generationMintCounts[currentGeneration] >= maxTokensPerGen,
        'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
}
```

This means that if the owner is not set to the TraitForgeNft contract subsequently, the call to its `_incrementGeneration` function will always revert. Conversely, if the owner is set to the TraitForgeNft contract, it will prevent future calls to the `setAllowedCaller` function of the EntropyGenerator contract.

```solidity
  function setAllowedCaller(address _allowedCaller) external onlyOwner {
    allowedCaller = _allowedCaller;
    emit AllowedCallerUpdated(_allowedCaller); // Emit an event for this update.
  }
```

## Recommended Mitigation Steps
A feasible solution is to modify the access control of the `initializeAlphaIndices` function from `onlyOwner` to `onlyAllowedCaller`, and change the constructor as follows:
```solidity
constructor(address _traitForgetNft) {
    allowedCaller = msg.sender;
    initializeAlphaIndices();
    allowedCaller = _traitForgetNft;
}
```
