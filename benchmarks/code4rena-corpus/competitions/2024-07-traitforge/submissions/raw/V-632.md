# Vulnerability details

## Impact
There is total 10010 possible 6-digit entropy values (770 entropy slots with 78 digit numbers, 770*78/6=10010. Maximum number of NFT's per generation is 10000. 
According to code `GoldenGod` entropy is placed in `512 <= entropySlots <= 769`, Indexing start from 0 so index 512 is 513th value in array and index 769 is 770th value in array.
`GoldenGod` can be in range `513*78/6 <= index <= 770*78/6` == `6669 <= index <= 10010`
This means it can be outside range of 10000 NFT's per generation and it will be impossible to get this special entropy

```solidity
  function initializeAlphaIndices() public whenNotPaused onlyOwner{
    uint256 hashValue = uint256(
      keccak256(abi.encodePacked(blockhash(block.number - 1), block.timestamp))
    );

    uint256 slotIndexSelection = (hashValue % 258) + 512;
    uint256 numberIndexSelection = hashValue % 13;

    slotIndexSelectionPoint = slotIndexSelection;
    numberIndexSelectionPoint = numberIndexSelection;
  }
```

## Proof of Concept
When function `EntropyGenerator::initializeAlphaIndices()` return values are
`slotIndexSelectionPoint=769`
`3 <= numberIndexSelectionPoint <= 12`
Then `GoldenGod` entropy will have index that is impossible to get in current generation
