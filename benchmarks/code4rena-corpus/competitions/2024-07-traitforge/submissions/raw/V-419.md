# Vulnerability details

## Impact
The `forgeWithListed()` function in the `EntityForging` contract does not account for scenarios where `mergers` send more `ether` than the required `forgingFee`. This oversight can lead to users unintentionally losing funds, as any `excess ether` sent is not refunded.

## Proof of Concept
In [`mintToken()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L196-L199) and [`mintWithBudget()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L221-L224), if a user makes excess payment beyond the required `mintPrice`, this `excess ether` is refunded to them as shown here:
```solidity
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
```

However, `forgeWithListed()` does not handle cases where the amount sent exceeds the required fee. The function includes a [check](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L125-L126) to ensure that the `ether` sent (`msg.value`) is at least equal to the `forgingFee`.
```solidity
uint256 forgingFee = _forgerListingInfo.fee;
require(msg.value >= forgingFee, 'Insufficient fee for forging');
```
In the above code, the require statement ensures that the sent `ether` is not less than the `forgingFee`.

This supplied value is then [divided and distributed](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L146-L159) as follows:
```solidity
    uint256 devFee = forgingFee / taxCut;
    uint256 forgerShare = forgingFee - devFee;
    address payable forgerOwner = payable(nftContract.ownerOf(forgerTokenId));

    //..
    (bool success, ) = nukeFundAddress.call{ value: devFee }('');
    require(success, 'Failed to send to NukeFund');
    (bool success_forge, ) = forgerOwner.call{ value: forgerShare }('');
    require(success_forge, 'Failed to send to Forge Owner');
```
As seen, `forgingFee` is split into `devFee` which is transfered to the `nukeFundAddress` and `forgerShare` transfrered to `forgerOwner`.

However, there is no subsequent logic to `refund` any `excess ether` that might have been sent.

**Financial Loss**: 
Users who send more ether than the required `forgingFee` will lose the excess amount. This can be particularly problematic if users are unaware of the exact fee or make an error in the transaction amount.

## Recommended Mitigation Steps
The [`forgeWithListed()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L102-L175) function should be modified to calculate and refund any `excess ether` sent by the `merger`.
```diff
  function forgeWithListed(
    uint256 forgerTokenId,
    uint256 mergerTokenId
  ) external payable whenNotPaused nonReentrant returns (uint256) {
    Listing memory _forgerListingInfo = listings[listedTokenIds[forgerTokenId]];

    //...snip...

    uint256 forgingFee = _forgerListingInfo.fee;
    require(msg.value >= forgingFee, 'Insufficient fee for forging');

    //...snip...

+   uint256 excess = msg.value - forgingFee; // @audit Determine excess ether
    uint256 devFee = forgingFee / taxCut;
    uint256 forgerShare = forgingFee - devFee;
    address payable forgerOwner = payable(nftContract.ownerOf(forgerTokenId));

    //...
    (bool success, ) = nukeFundAddress.call{ value: devFee }('');
    require(success, 'Failed to send to NukeFund');
    (bool success_forge, ) = forgerOwner.call{ value: forgerShare }('');
    require(success_forge, 'Failed to send to Forge Owner');

+   if (excess > 0) { // @audit Refund any excess ether
+     (bool refundSuccess, ) = payable(msg.sender).call{ value: excess }('');
+     require(refundSuccess, 'Failed to refund excess ether');
+   }

  }
```
