# Vulnerability details

## Impact
**- DESCRIPTION -**

Entropy in the game defines each entity's traits and characteristics. It determines crucial gameplay attributes, and the randomness of the generation is crucial to the integrity of the game. However, the user can choose to revert the minting process if the entropy value is unfavorable to him/her. 

**- DETAILS -**

The problem is that the `entropyValue` is determined and set within the same transaction. If a user employs a smart contract wallet, they can intentionally revert the transaction if the `entropyValue` is not favorable and then attempt to mint again until they achieve the desired result.

Here's the [`TraitForge::mintToken()`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L181-L200) function, which invokes `_mintInternal()`.

**- ATTACK SCENARIO -**
1. Call `mintToken()`
2. Call `getTokenEntropy()` with `tokenId` as the parameter.
3. If the return value of `getTokenEntropy()` is not favorable, `revert`
4. Call `mintToken()` again until the entropy value is favorable.

Note that steps 1-3 occur within a single atomic transaction. Since transactions are in the mempool, it's difficult to predict the entropyValue you will get even if you time the transactions precisely. This is why reverting the transaction becomes a viable solution for an attacker.

**- IMPACT -**
The integrity of the game is at risk, which could threaten its existence.

## Recommended Mitigation Steps
Token minting and entropy generation (and setting) should not occur in the same atomic transaction. Token minting should be in a separate transaction, while entropy generation and setting should be done by an admin on another transaction.
