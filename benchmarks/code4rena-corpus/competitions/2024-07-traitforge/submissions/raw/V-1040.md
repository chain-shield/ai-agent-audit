# Vulnerability details

## Impact

In the game, competitors try to have more fun and get more benefits from the game by having multiple NFTs instead of just one. In this respect, the mintWithBudget function is more convenient than minting them one by one. However, this function is designed to stop working after the 10000th NFT is minted. This makes it inconvenient for players to participate in the game and they have no choice but to mint them one by one. This reduces the appeal of the game, and especially since the mintWithBudget function does not work, it can cause users to be disappointed in the game.

## Vulnerability Details

There is _tokenIds variable to reflect the total amount of NFTs in the TraitForgeNft contract. In the mintWithBudget of TraitForgeNft contract, _tokenIds can increased by only maxTokensPerGen. The maxTokensPerGen is constant value that equals to 10000.

## Proof of Concept

This POC shows mintWithBudget function doesn’t work after 10000th NFT

1. Add 3 public functions that can set current generation, set mint counts of the special generation and set token numbers
2. Add mintWithBudget testing code when the total amount of NFTs is 9998 and the amount of first generation’s NFTs is 9998 in the TraitForgeNft.test.ts file
3. Run “npx hardhat test ./test/TraitForgeNft.test.ts”

## Recommended Mitigation Steps
The game logic includes total 10 generation. Each generation has 10000 NFTs so maxTokensPerGen should be replaced with 10 * maxTokensPerGen in the mintWithBudget function
