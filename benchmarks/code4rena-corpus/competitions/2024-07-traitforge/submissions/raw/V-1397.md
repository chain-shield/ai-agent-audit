# Vulnerability details

## Impact
The current implementation of the token forging and minting processes in the contract can lead to inconsistent and incorrect management of generation counts. This inconsistency arises due to the way the generation counts are reset during the `_incrementGeneration` function, break invariant of minting 10,000 token per generation.

## Proof of Concept
```javascript
function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
}

 ```
Scenario:
-Assume `currentGeneration` is 1.
-7,000 tokens are minted in generation 1.
-50 tokens are forged and minted in generation 2 (newGeneration).
-No further tokens are forged.
-Generation 1 reaches 10,000 tokens through normal minting.
-`_incrementGeneration` is called, setting `currentGeneration` to 2 and `generationMintCounts[currentGeneration]` to 0.
-This reset disregards the 50 tokens already minted in generation 2, leading to inaccurate generation counts, leads to generation of more number of NFT in second generation.

At the end which break the protocol main invariant of minting only 10,000 per generations.

## Tools Used
Manual code review

## Recommended Mitigation Steps
Ensure that the generation count for a new generation accurately reflects any tokens already minted through forging. Do not reset the count to zero if there are tokens already minted in the new generation.
