# Vulnerability details


### Vulnerability details
In the forge function, the generation is incremented before calling `_mintNewEntity()`. Specifically, the line `uint256 newGeneration = getTokenGeneration(parent1Id) + 1;` sets newGeneration to the next generation. This incremented newGeneration is then passed as the gen parameter to `_mintNewEntity()`, as shown below

* In the above  `_mintNewEntity` function, there's a critical logical flaw in the condition for calling `_incrementGeneration()`. the condition is marked with`@>` in the above function
* now lets focus on the second condition which is `gen == currentGeneration`  This condition will never be satisfied during the forging process due to the following reasons

* In the forge function, `newGeneration` is calculated as `getTokenGeneration(parent1Id) + 1`, which is essentially `currentGeneration + 1`.
* This newGeneration value is then passed as the gen parameter to `_mintNewEntity`.
* Consequently, within `_mintNewEntity`, gen is always one generation ahead of `currentGeneration`.
* The condition `gen == currentGeneration` will evaluate to false during forging, as gen (the new generation) is always greater than currentGeneration.
* As a result, the _incrementGeneration() function will never be invoked during the forging process.

### Impact
* The `_incrementGeneration()` function will never be invoked during the forging process, resulting in a halt in generation advancement doing forging

### Proof of Concept
* Call the forge function with valid parameters.
* Observe that newGeneration is incremented before calling `_mintNewEntity`.
* Inside `_mintNewEntity`, the gen parameter is set to the incremented generation.
* The condition `if (generationMintCounts[gen] >= maxTokensPerGen && gen == currentGeneration)` will always fail because gen is not equal to currentGeneration.
* As a result, _incrementGeneration() is never called during the forging process.


### Recommended Mitigation
* To ensure `_incrementGeneration()` is called appropriately during forging, modify the logic to correctly handle generation increments. One possible solution is to adjust the condition to account for the next generation
