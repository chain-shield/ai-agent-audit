# Vulnerability details

## Description 
The EntropyGenerator contract uses block.number and an incremental counter to create pseudo-random values. This approach is susceptible to miner manipulation and can be predictable.
```
uint256 pseudoRandomValue = uint256(
  keccak256(abi.encodePacked(block.number, i))
) % uint256(10) ** 78;
```
## Impact
This vulnerability allows potential attackers to predict or manipulate entropy values, leading to:

1.Manipulated NFT Generation: Attackers could influence the generation process to obtain NFTs with specific traits.
2.Exploited Game Mechanics: Critical operations like forging or nuking could be compromised.
3.Eroded Fairness: The integrity and fairness of the TraitForge ecosystem could be significantly undermined.

## Proof of Concept
An attacker could:

1. Monitor the contract state and the current block number.
2. Pre-calculate possible entropy values based on known inputs.
3. Time their interactions with the contract to exploit predictable entropy values.

## Tools Used
Manual Review

## Recommended Mitigation Steps
1.Implement a Verifiable Random Function (VRF):
Use services like Chainlink VRF to ensure cryptographic security and unpredictability in random number generation.

2.Adopt a Commit-Reveal Scheme:
Introduce a commit-reveal process where initial values are committed to and then revealed in a separate step, making it harder for attackers to predict outcomes.

3.Leverage External Randomness Sources:
Incorporate additional randomness sources, such as the block hash of a future block, to enhance unpredictability.
