# Vulnerability details

## Impact
Since TraitForgeNft isn't the owner of EntropyGenerator every `TraitForgeNft:_incrementGeneration()` will revert.

Effectively making the game not-playable after the first generation has ended.

## Proof of Concept
When the `maxTokensPerGen` is reached, `_incrementGeneration()` is called:

```js
function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
}
```

Which also calls `EntropyGenerator:initializeAlphaIndices()` which will always revert at this point since `TraitForgeNft` isn't the owner of `EntropyGenerator`.


First change TraitForgeNft:maxTokensPerGen to 10, only for this test to run faster, and then add the following into 'test/TraitForgeNft.test.ts':

```js
it.only('impossible to increment generation', async () => {
    // mint maxTokensPerGen + 1 tokens      
    for(let i = 0; i < 11; i++) {
        await nft.connect(user1).mintToken(merkleInfo.whitelist[1].proof, {
          value: ethers.parseEther('1'),
        });
      }
    })
```

## Recommended Mitigation Steps

Make `initializeAlphaIndices()` callable by:
- the owner, so it doesn't revert in the constructor
- the allowedCaller, so `TraitForgeNft` can correctly increment generation

-function initializeAlphaIndices() public whenNotPaused onlyOwner {
