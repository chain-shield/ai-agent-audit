# Vulnerability details

## Impact
Entropy for every NFT is known before the start, which enables users to front-run each other for better NFTs. This can even stagnate the system if a series of bad NFTs line up. Everyone will try to mint the ones after them and no-one will want to mint the bad ones.

## Proof of Concept
Entropy is generated on batches before minting starts. This means that it's fully known the entropy of every newly minted NFT. 

That will enable users to look trough the whole stack and find an find the nearest good entropy. After that they will just wait for the NFTs before that to get minted and front-run the last user and mint their NFT.

Example:
1. Current minting ID is 20
2. Alice knows that NFT with ID 31 is 899_999 - a really good NFT.
3. She waits till ID 30 is minted
4. Bob now tries to mint NFT with ID 31
5. Alice front-runs him and mints the NFT herself

In the above example, although sounding simple, it allows users to purposefully pick their NFT "power".

Note that the same is true even for the god NFT, as it will depend on already known variables - `slotIndexSelectionPoint` and `numberIndexSelectionPoint`.

## Tools Used
Manual review

## Recommended Mitigation Steps
Given the current design there would be no simple solutions. My suggestion would be to move to a VRF and wait for a full batch of users (13) to request for minting. Then get a truly random and unpredictable entropy and divide it across the batch.
