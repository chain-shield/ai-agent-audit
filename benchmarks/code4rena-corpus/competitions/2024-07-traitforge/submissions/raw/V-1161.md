# Vulnerability details

## Impact
The protocol has a max amount of generation that can be minted, which is evident by the check in the `TraitForgeNft::forge` function where it checked the newGeneration against the max top prevent over minting, but in `mintToken` this check does not exist before increasing the current gen it allows continuous minting even after the max gen have being reached, allowing the illegally minted nft to have access to Nuking, selling and Forging and Merging 

## Proof of Concept
When users mint new tokens they call `mintToken` which calculates the price and calls, the `_mintInternal` function as seen below both function has no checks that if they were increasing the currentGen the gen should be <= the max gen

```solidity
function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }
``` 
