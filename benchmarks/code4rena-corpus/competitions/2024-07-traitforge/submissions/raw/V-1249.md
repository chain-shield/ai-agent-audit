# Vulnerability details

## Impact

In `TraitForgeNft` smart contract, `mintToken()` function is used to mint new entities. The problem is that it calls `_mintInternal()` later than `calculateMintPrice()` and if the generation is updated in `_mintInternal()`, user mints with incorrect mint price.

## Proof of Concept

Take a look at the `mintToken()` functionality:

```
  function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');

    _mintInternal(msg.sender, mintPrice);

    uint256 excessPayment = msg.value - mintPrice;
    if (excessPayment > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: excessPayment }('');
      require(refundSuccess, 'Refund of excess payment failed.');
    }
  }


```

First, `calculateMintPrice()` is called:

```
  function calculateMintPrice() public view returns (uint256) {
    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```

If generationMintCounts >= maxTokensPerGen (which should not be the case as there are only 10000 tokenIds are allowed), mint price is calculated using generationMintCounts of the current generation and the price for the tokenId will be therefore much bigger if it's just minting from the new generation where there will be no price increase and the user will only pay price increment:

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L280-283
```
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```

As you can see, generation is incremented in the `_mintInternal()` that's called after calling `calculateMintPrice()` which should not be the case as the price can be unfairly greater than it should be.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Update the generation (if needed) before calculating the mint price.
