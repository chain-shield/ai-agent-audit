# Vulnerability details

## Description
There is a bug in `TraitForgeNft::_incrementGeneration` when minting and forging mix togerther (which will happen for sure, that's the point of the game) which will allow players to mint beyond the 10k generation limit which seems to warrant `High` severity.

The root cause is due to the fact that `_incrementGeneration` is reseting `generationMintCounts` on the new generation, which is wrong as `overwriting all the forging` counts that would have happen earlier.

Take the following simple example (see PoC).
Consider a `maxTokensPerGen of only 5 NFT`. 
```
1) Alice and Bob play the game.
2) Alice mint 2 NFT and Bob mint 3 NFT, Gen1 is now fully minted.
3) Bob list his forger NFT.
4) Alice forge a Gen2 by using her merger and Bob's listed forger. Gen2 has now one NFT.
5) Bob decide to mint another NFT. Since Gen1 is fully minted, that will mint in Gen2 and call _incrementGeneration which will `reset Gen2 count to zero`, which effectivally will allow to mint one more token in Gen2 (so 6 instead of 5).
```
```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;      // <-----------------------------
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();  
    emit GenerationIncremented(currentGeneration);
  }
```  

## Impact
Player is able to mint beyond `maxTokensPerGen` limit since `generation increment` will reset the generation count and by doing so will "soft-discard/not consider" all the forged NFT in the next generation. Those forged NFT will be still valid, but not considered in the total of the `maxTokensPerGen`. This means if we assume 30% of forger per generation, there is a potential to forge a lot of NFT in for the next generation which would make the total of NFT much bigger than maxTokensPerGen.

## Recommended Mitigation Steps
Apply the following patch to resolve this issue. You don't need to reset the counter as otherwise you cause the bug described in this report and by default it already start at 0 anyway.

```diff
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
-   generationMintCounts[currentGeneration] = 0;
```
