# Vulnerability details

## Impact
If the owner changes the `taxCut` to a number which doesn't return a percentage value when a number gets divided by it then the calculation for nuke fund and dev fee will be incorrect.

## Proof of Concept
According to the docs:
> 10% of Forge Fees and Sales goes into the Nuke Fund

Let's look at how that is implemented in code (`EntityTrading.sol: buyNFT()`):
```solidity
uint256 nukeFundContribution = msg.value / taxCut;
```
As you can see it doesn't calculate the nuke fund fee as a percentage and instead divides by `taxCut`. 
For the current value `taxCut = 10` the calculation is fine because dividing by 10 gives us 10% of a number. However if we change the `taxCut` to 20 for example it will not calculate 20%. Here is an example if the nft costs 600 wei:
> 600 / 20 = 300 (50% - incorrect)
600 * 20 / 100 = 120 (20% - correct)

You may argue that the nuke fund fee will always be 10% but the function `setTaxCut()` allows the owner to change the value. If he expects it to work as a percentage then the calculation will be incorrect.

This bug also occurs in `NukeFund.sol` and `EntityForging.sol`:
```solidity
uint256 devShare = msg.value / taxCut; // Calculate developer's share (10%)
```
```solidity
uint256 devFee = forgingFee / taxCut;
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
```diff
-uint256 nukeFundContribution = msg.value / taxCut;
+uint256 nukeFundContribution = (msg.value * taxCut) / 100;
```
The same fix applies for all instances.
