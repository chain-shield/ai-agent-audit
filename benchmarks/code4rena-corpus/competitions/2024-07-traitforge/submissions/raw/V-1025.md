# Vulnerability details

## Impact
if the ´nukeFundAddress´ isn't set:
in EntityForging::forgeWithListed() the `devFee` will be sended to the 0 address,
in TraitForgeNft::_mintInternal() the `mintPrice` passed in will be sended to the 0 address.

## Proof of Concept
1) When a user call `forgeWithListed()`, if all checks pass, there is no check that make sure that `nukeFundAddress != address(0)`.
ref: https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L156
2) Similarly, when a user call `mintToken()` or `mintWithBudget()`, these functions call `_mintInternal()` and pass `msg.sender` and the `mintPrice`.
`_mintInternal()` then calls `_distributeFunds()` and pass the `mintPrice` to be send to the `nukeFundAddress`, Again, there is no check that make sure that `nukeFundAddress != address(0)`.
ref: https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L361

## Tools Used
manual review.

## Recommended Mitigation Steps
in `forgeWithListed()` and `_distributeFunds()` add a require statement that make sure the `nukeFundAddress != address(0)`.
similar to this check:
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L113
