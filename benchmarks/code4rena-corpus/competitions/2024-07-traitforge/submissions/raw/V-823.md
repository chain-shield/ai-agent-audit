# Vulnerability details

## Impact
The function `deriveTokenParameters` should represent decoded trait values based on entropy value, but calculation for `nukeFactor` parameter is wrong, according to whitepaper:

```
Entropy: 123456
...
Entropy /40 = initalNukeFactor // HERE
...
Entropy % 3 ? 0 == Role
```
We should divide entropy to 40, but in code it's divided to 4_000_000 which in result will show incorrect trait value and that could affect users strategy choice, because they would think that their `nukeFactor` is always 0.

## Proof of Concept

Here's the affected code: https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L152

As we can see:
```solidity
    nukeFactor = entropy / 4000000;
```
But it should be:
```solidity
nukeFactor = entropy / 40;
```

## Tools Used
Manual review.

## Recommended Mitigation Steps
Update nukeFactor calculation formula to this one:
```solidity
    nukeFactor = entropy / 40;
```
