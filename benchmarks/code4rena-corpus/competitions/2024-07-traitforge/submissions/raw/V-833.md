# Vulnerability details

The [`EntropyGenerator::deriveTokenParameters()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L136) function is used to display the different traits on the frontend, it returns 4 values: `nukeFactor`, `forgePotential`, `performanceFactor` and `isForger`.
The value we will be focusing on is `forgePotential`. Forge Potential dictates how many times an Entity can forge before becoming infertile for the rest of the year (10% of the population is infertile from birth). An entity with `forgePotential` of 0 is infertile and will never be able to forge.

As can be seen from the [whitepaper](https://docs.google.com/document/d/1pihtkKyyxobFWdaNU4YfAy56Q7WIMbFJjSHUAfRm6BA/edit) in the **Entropy** section, the `forgePotential` is positionated on the 5th digit if we start counting from 1:

![forgePotential docs image](https://gist.github.com/user-attachments/assets/29290b3e-457e-480a-9aaf-729f13f735b3)

## Impact

The incorrectly extracted forgePotential used to display the different traits on the frontend could cause users to mistakenly think that with specific parameters they will obtain an entropy with the forgePotential that the function has shown them. Instead, when they mint, they get a completely different one.

## Proof of Concept

If we take a look at [`EntropyGenerator::deriveTokenParameters()`](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L136), we can see that the `forgePotential` is obtained by extracting the first digit of `entropy`, which is completely wrong because the first digit represents physicalTrait1. As mentioned previously, the `forgePotential` is positioned on the 5th digit if we start counting from 1. This could cause users to mistakenly think that with specific parameters they will obtain an entropy with the `forgePotential` that the function has shown them. Instead, when they mint, they get a completely different one. For example, as can be seen in the Coded PoC, it can show 9 as forgePotential, while actually it's 0, which means that the entity is infertile.
