# Vulnerability details

### Description

The `updateDev` function in the DevFund contract contains a logical error in the order of operations, leading to potential miscalculation of pending rewards when updating a developer's weight.

### Affected Code

```solidity
function updateDev(address user, uint256 weight) external onlyOwner {
    DevInfo storage info = devInfo[user];
    require(weight > 0, 'Invalid weight');
    require(info.weight > 0, 'Not dev address');
    totalDevWeight = totalDevWeight - info.weight + weight;
    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
    info.rewardDebt = totalRewardDebt;
    info.weight = weight;
    emit UpdateDev(user, weight);
}
```

### Details

1. The function updates `totalDevWeight` before calculating `pendingRewards`.
2. `pendingRewards` calculation uses the old `info.weight`, but after `totalDevWeight` has been modified.
3. If `totalRewardDebt` has changed since the last update, this leads to an incorrect reward calculation.

### Impact

- Incorrect distribution of rewards to developers.
- Potential loss or excess of funds for individual developers.
- Inconsistency between actual and expected reward distributions.

### Proof of Concept
Consider the following scenario:
1. Initial state: `totalDevWeight = 100`, `dev1.weight = 50`, `totalRewardDebt = 1000`, `dev1.rewardDebt = 900`
2. Update `dev1` weight to 60
3. Current function would calculate: 
   `pendingRewards += (1000 - 900) * 50 = 5000`
4. Correct calculation should be: 
   `pendingRewards += (1000 - 900) * 60 = 6000`

### Fix
Reorder the operations to calculate pending rewards before updating weights:

```solidity
function updateDev(address user, uint256 weight) external onlyOwner {
    DevInfo storage info = devInfo[user];
    require(weight > 0, 'Invalid weight');
    require(info.weight > 0, 'Not dev address');
    
    info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
    totalDevWeight = totalDevWeight - info.weight + weight;
    info.weight = weight;
    info.rewardDebt = totalRewardDebt;
    
    emit UpdateDev(user, weight);
}
```

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "forge-std/Test.sol";
import "../src/DevFund/DevFund.sol";

contract DevFundTest is Test {
    DevFund public devFund;
    address public owner;
    address public dev1;
    address public dev2;

    function setUp() public {
        owner = address(this);
        dev1 = address(0x1);
        dev2 = address(0x2);
        devFund = new DevFund();
    }

    function testUpdateDevRewardCalculationIssue() public {
        devFund.addDev(dev1, 50);
        devFund.addDev(dev2, 50);
        assertEq(devFund.totalDevWeight(), 100);

        vm.deal(address(this), 1 ether);
        (bool success, ) = address(devFund).call{value: 1 ether}("");
        require(success, "Failed to send Ether");

        assertEq(devFund.totalRewardDebt(), 0.01 ether);
        assertEq(devFund.pendingRewards(dev1), 0.5 ether);
        assertEq(devFund.pendingRewards(dev2), 0.5 ether);

        devFund.updateDev(dev1, 60);

        assertEq(devFund.totalDevWeight(), 110);
        
        uint256 dev1Rewards = devFund.pendingRewards(dev1);
        assertEq(dev1Rewards, 0.5 ether, "Dev1 rewards calculated incorrectly");

        vm.deal(address(this), 1.1 ether);
        (success, ) = address(devFund).call{value: 1.1 ether}("");
        require(success, "Failed to send Ether");

        uint256 dev1FinalRewards = devFund.pendingRewards(dev1);
        uint256 dev2FinalRewards = devFund.pendingRewards(dev2);
        
        console.log("Dev1 final rewards:", dev1FinalRewards);
        console.log("Dev2 final rewards:", dev2FinalRewards);
        
        assertEq(dev1FinalRewards, 1.1 ether, "Dev1 should have 1.1 ether in rewards");
        assertEq(dev2FinalRewards, 0.5 ether, "Dev2 should have 0.5 ether in rewards");
    }
}
```

This PoC is doing the following

1. It sets up a `DevFund` contract with two developers, each with a weight of 50.
2. It simulates some initial rewards (1 ether) being sent to the contract.
3. It updates dev1's weight from 50 to 60.
4. It checks the pending rewards for dev1, which should remain unchanged at 0.5 ether, but may be calculated incorrectly due to the bug.
5. It simulates more rewards (1.1 ether) being sent to the contract.
6. Finally, it checks the final rewards for both developers.

The bug manifests in two ways:
1. After updating dev1's weight, their pending rewards may be calculated incorrectly.
2. After receiving more rewards, the distribution between dev1 and dev2 will be incorrect.
