# Vulnerability details

## Impact

priceIncrement in each generations is not handled properly , which makes minting towards the end of each generations highly unfeasible and unfair for the users.

## Proof of Concept

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L227-L232

```Solidity
 function calculateMintPrice() public view returns (uint256) {
    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L24

```Solidity
  uint256 public startPrice = 0.005 ether;
  uint256 public priceIncrement = 0.0000245 ether;
  uint256 public priceIncrementByGen = 0.000005 ether;
```

The priceIncrement in each generation is set as 0.0000245 ether and priceIncrease calculated by :
`uint256 priceIncrease = priceIncrement * currentGenMintCount;`

Towards, the end of the generation, say generationMintCounts[currentGeneration] = 9999 , priceIncrease will be 0.0000245 * 9999 = 0.2449 ether 
price = 0.005+0.2449 =0.2499 ether

This is a very high mint price and the user can just wait till the start of the next generation to mint as then the price will be:

price = 0.005 + (0.0000245 + 0.000005) * generationMintCounts[nextGeneration]

say generationMintCounts[nextGeneration] =1

then price = 0.0050295 ether 

This is approx 50 times lesser mint price

So minting towards the end of each generations is highly unfeasible and unfair for the users


## Tools Used

Manual Review

## Recommended Mitigation Steps

Handle the priceIncrease in each generations so that the user wont suffer huge loss . Make the priceIncrement much smaller.
