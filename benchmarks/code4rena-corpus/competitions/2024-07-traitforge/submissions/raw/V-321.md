# Vulnerability details

## Impact
In `TraitForgeNft.sol` function `mintWithBudget()` allows the msg.sender to specify a budged with which he can mint as many NFTs as he can and untill `generationMintCounts` does not exceeded or equal to `maxTokensPerGen`.

In the `while loop `, for checking if the current minted token doesnt exceed or is not equal to `maxTokensPerGen` , the variable `_tokenIds` is used which is actually global variable and its job is to count all the minted tokens in the protocol throughout all generations till the last one meaning its value at the end of `generation 10` will be `100_000`. The issue is that after `generation = 1` ends the protocol moves to the second generation and when new NFTs are minted `_tokenIds` will be incremented and will have the value ` > ` ` maxTokensPerGen which is set to 10_000 ` making the `mintWithBudget()` being unable to mint new NFTs because one of the while loop conditions `_tokenIds < maxTokensPerGen` will not be met. By this being said no one will be able to mint tokens through `mintWithBudget()` after generation one ends which is one of the main functions of the protocol.

## Proof of Concept
Lets see the following example:

1. The currentGeneration is `2 ` , all the minted NFTs are 10_005 making `_tokenIds = 10_005 `.

2. Alice try to  calls `mintWithBudget()` but nothing will happen and her budget will be send back because `_tokenIds will be >  maxTokensPerGen`.

## Recommended Mitigation Steps

Replace `_tokenIds` with `generationMintCounts[currentGeneration]`.
