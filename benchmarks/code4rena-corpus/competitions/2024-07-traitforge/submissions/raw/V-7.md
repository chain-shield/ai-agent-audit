# Vulnerability details

## Impact
The [TraitForgeNft contract inherits OpenZeppelin's Pausable](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L19), and defines various functions which cannot be called while the contract is paused (for example: [this](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L141), and [this](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L394)). Yet it does not define a function that can actually trigger the pausing of the contract (by calling the _pause function available from the OpenZeppelin Pausable inherited). This means the contract can never be paused, and the entire logic for pausing the contract can never be reached - so in an emergency, or cases when the owner would find it appropriate or necessary to pause the contract, it will be impossible to do so.

Note that I have mentioned here only the instances where pausablity is expected in TraitForgeNft, but the same issue exists also in Airdrop, DevFund, EntityForging, EntityTrading, EntropyGenerator, NukeFund, and Trait (the latter inherits ERC20Pausable which inherits Pauseable, but none have a externally exposed function that could trigger the paused state of the contract).

## Proof of Concept
You can see that there is no function that changes the state of the defined _paused state variable, except the _pause and _unpause functions defined by OpenZeppelin, but these are internal and not used in the contract, so cannot be used by the owner (or anyone for that matter).

## Tools Used
Code review

## Recommended Mitigation Steps
Add externally callable pause() and unpause() functions which have an onlyOwner modifier for their access control, like so:

```
function pause() external onlyOwner {
  _pause();
}

function unpause() external onlyOwner {
  _unpause();
}
```
