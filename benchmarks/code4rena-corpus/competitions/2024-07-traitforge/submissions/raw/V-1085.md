# Vulnerability details

## Impact
`mintWithBudget` will stop functioning and will be permanently DOSd if tokenId reaches 10000 this is as a result of the incorrect implementation of the while loop in the function, the implementation does not take into account
- `_tokenIds` is a global variable that is updated per mint regardless of generation, it is also updated in forge operations 
- `maxTokensPerGen` is also a global variable and fixed used to make sure the token limit have not being met
Both factors leads to a situation where the `_tokenIds` will sooner be greater than the `maxTokensPerGen` and make this function unable to work

## Proof of Concept
```solidity
 uint256 private _tokenIds;
 uint256 public maxTokensPerGen = 10000;
```
Both variables are global variables, and only `_tokenIds` increases during mint operations as shown below 

_mintInternal and _mintNewEntity Both increases the variable regardless of the gen being minted

```solidity
_tokenIds++;
```
Which makes this check for the while loop inevitably permanently DOS

```solidity
while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```

## Recommended Mitigation Steps
If the check is meant to prevent Minting past to another gen then it should be implemented to check the difference between the `generationMintCounts` and the `maxTokensPerGen` this will effectively allow the loop to run.
