# Vulnerability details

## Description
The `calculateNukeFactor` function in the NukeFund contract is at risk of integer overflow, particularly in the calculation of finalNukeFactor. This could occur if adjustedAge or defaultNukeFactorIncrease are very large, potentially leading to incorrect nuke factor calculations and compromising the entire nuking mechanism.


## Impact
1. Incorrect calculation of nuke factors for tokens with very high adjusted ages.
2. Potential undervaluation of mature tokens, leading to unfair fund distribution when nuking.
3. Possible exploitation by malicious actors who could manipulate the system to their advantage.

## Proof of Concept

[Link to code](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L136-L151)

```
  // Calculate the nuke factor of a token, which affects the claimable amount from the fund
  function calculateNukeFactor(uint256 tokenId) public view returns (uint256) {
    require(
      nftContract.ownerOf(tokenId) != address(0),
      'ERC721: operator query for nonexistent token'
    );

    uint256 entropy = nftContract.getTokenEntropy(tokenId);
    uint256 adjustedAge = calculateAge(tokenId);

    uint256 initialNukeFactor = entropy / 40; // calcualte initalNukeFactor based on entropy, 5 digits

    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;

    return finalNukeFactor;
  }
```

Consider a scenario where:
1. adjustedAge is very large (close to type(uint256).max)
2. defaultNukeFactorIncrease is also set to a large value

The calculation (adjustedAge * defaultNukeFactorIncrease) could overflow, wrapping around to a much smaller number before the division by MAX_DENOMINATOR occurs. This would result in an incorrectly small finalNukeFactor.

Example:
Let adjustedAge = 2^255 (a very large number, but still valid)
Let defaultNukeFactorIncrease = 2^10 = 1024
MAX_DENOMINATOR = 100000

adjustedAge * defaultNukeFactorIncrease = 2^255 * 2^10 = 2^265
This overflows uint256, potentially wrapping to a much smaller number.

## Recommended Mitigation Steps

1. Implement additional checks to prevent unreasonably large inputs:
```
function calculateNukeFactor(uint256 tokenId) public view returns (uint256) {
    require(
        nftContract.ownerOf(tokenId) != address(0),
        'ERC721: operator query for nonexistent token'
    );

    uint256 entropy = nftContract.getTokenEntropy(tokenId);
    uint256 adjustedAge = calculateAge(tokenId);

    uint256 initialNukeFactor = entropy / 40; // calculate initialNukeFactor based on entropy, 5 digits

    // Check for potential overflow
    require(adjustedAge <= type(uint256).max / defaultNukeFactorIncrease, "Overflow risk in nuke factor calculation");

    uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) / MAX_DENOMINATOR) + initialNukeFactor;

    return finalNukeFactor;
}
```
2. Consider using a fixed-point arithmetic library for more precise calculations and to avoid overflow issues.

3. Implement upper bounds for adjustedAge and defaultNukeFactorIncrease to prevent them from reaching values that could cause overflow:
```
function setDefaultNukeFactorIncrease(uint256 value) external onlyOwner {
    require(value <= MAX_NUKE_FACTOR_INCREASE, "Value exceeds maximum allowed");
    defaultNukeFactorIncrease = value;
}
```
