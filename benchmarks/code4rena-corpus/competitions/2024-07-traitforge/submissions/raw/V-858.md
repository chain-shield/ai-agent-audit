# Vulnerability details

The [`MintWithBudget`](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L202) function is designed to mint NFTs for a user based on their specified budget. The function is very gas-expensive due to the while loop, which modifies storage variables on each iteration and makes several internal and external calls. However, the function currently lacks a restriction on the maximum budget allowed. 

Consider a scenario where a user wants to spend 1 ether to mint NFTs, expecting to receive 147 NFTs. This situation is problematic because the Ethereum block gas limit is capped at 30 million. If the transaction exceeds this gas limit, it will revert, causing the user to lose a substantial amount of gas fees without successfully minting any NFTs.

## Impact

When users try to `mintWithBudget` with more than 0.6 ETH, they will spend a lot of gas, and the transaction will revert without minting the NFTs.

## Proof of Concept

Place the test in the `TraitForgeNft.test.ts` file.

```jsx
  describe('POC', () => {
    it('mint with budget', async () => {
      await nft.connect(owner).mintWithBudget(merkleInfo.whitelist[0].proof, {
        value: ethers.parseEther('1'),
      });

      expect(await nft.balanceOf(owner.address)).to.be.eq(147);
    });
  });
```

## Recommended Mitigation Steps

Add a limit on the maximum budget that users can use.

