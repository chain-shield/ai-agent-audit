## Impact

The code above shows how minting with budget is implemented in the TraitForgeNft contract, it can be noted from the pointer that minting is done by ensuring that
1. budget Left can handle the Mint Price for the current mint loop 
2. Token Id is within the maximum allowed.
The problem is that the second criteria that checks the token id is wrong. To understand why this is an error, it should be noted that token Id is generally a unique value no matter the Generation it is being minted from as can be noted at [L285](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L285) & [L321](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L321), but it was compared to maxTokensPerGen i.e the maximum minted token of a single Gen not the general Gen value, the implication of this is that no matter the generation that is to be minted TokenId that can be minted with budget can never go above the maxTokensPerGen of the first Gen alone.
#### Scenario Proof
Assuming
Gen 1 = 10000 mints, i.e token ID is between 1 to 10,000
Gen 2 = 10000 mints, i.e token ID is between 10,000 to 20,000
Gen 3 = 10000 mints, i.e token ID is between 20,000 to 30,000
Assuming caller is trying to mint for Gen 4 using budget, meaning the expected token ids would start from 30,001.
However the code would fail, as the loop in the mintWithBudget(...) function expects tokenID to be below maxTokensPerGen or 10,000 before minting would proceed, causing Denial of Service
