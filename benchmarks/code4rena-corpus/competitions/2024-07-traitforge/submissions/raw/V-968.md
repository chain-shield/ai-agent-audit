# Vulnerability details

## Impact
The inability to execute the `forgeWithListed` and `buyNFT` functions can disrupt the normal flow of the game, leading to financial and operational impacts for users. This vulnerability can result in loss of funds, as users are unable to complete transactions, and it can also undermine the trust and reliability of the platform.

## Proof of Concept
Both the `forgeWithListed` function in the `EntityForging.sol` contract and the `buyNFT` function in the `EntityTrading.sol` contract send funds to the `forgerOwner` or `listing.seller` using the `.call` method and require the success result to be true. However, there is the possibility that the `forgerOwner` or `listing.seller` is a malicious contract that will revert the transaction when the funds are sent, in case the resulting output of the forge or sale is not to its advantage based on the current state of the game. This behavior effectively blocks legitimate transactions, causing financial loss and frustration for users.

To illustrate this issue, consider the following scenario:

1. A malicious contract is set as the `forgerOwner` or `listing.seller`.
2. This malicious contract overrides the fallback or receive function to revert any transaction unless certain game conditions are met.
3. When a user calls the `forgeWithListed` or `buyNFT` functions, the funds are sent to this malicious contract.
4. The malicious contract checks the state of the game. If the conditions are not favorable, it reverts the transaction.
5. The `.call` method fails, and the `require` statement in the `forgeWithListed` or `buyNFT` function causes the entire transaction to revert.

This behavior effectively makes it impossible to execute the `forgeWithListed` or `buyNFT` functions under these conditions, disrupting the normal flow of the game.
## Tools Used
Manual review

## Recommended Mitigation Steps


The contract should tolerate potential reverts from the underlying contracts since this interaction is part of the main transfer flow. This can be achieved by implementing a try/catch mechanism or by handling the revert gracefully within the main contract logic.
