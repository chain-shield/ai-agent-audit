# Vulnerability details

## Impact
The `mintWithBudget` function in the `TraitForgeNft` contract malfunctions for generations beyond the first.

After the last token of the 1st generation is minted, the `_tokenIds` variable reaches 10,000, which matches the `maxTokenPerGen` value for that generation. Consequently, the while loop in the `mintWithBudget` function fails to execute for tokens in subsequent generations due to this condition:
```javascript
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
```

This issue renders the function ineffective for minting tokens in newer generations. Additionally, players are unable to mint tokens for a new generation using `mintWithBudget` function if the maximum token amount for the previous generation has been reached, which contradicts the protocol's intended behavior.

## Proof of Concept

Foundry is used in the Proof of Concept (PoC). You can set up the Foundry environment by following the instructions provided here: https://hardhat.org/hardhat-runner/docs/advanced/hardhat-and-foundry

Copy the test file to run the test using: `forge test --match-test testmintWithBudget -vv`

## Recommended Mitigation Steps
Remove the _tokenId condition in while loop as new generation transition and minting process is handled by `_mintInternal` function automatically:
```javascript
--    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
++    while (budgetLeft >= mintPrice) {
```
