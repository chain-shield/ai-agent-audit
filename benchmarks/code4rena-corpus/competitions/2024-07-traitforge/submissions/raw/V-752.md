# Vulnerability details

## Impact
The `TraitForgeNft.sol` contract allows the minting of tokens beyond the intended maximum of 10 generations. This could lead to an unlimited number of generations being created. It also contradicts the specifications outlined in the documentation, which clearly states a cap of 10 generations.

## Proof of Concept
In the `TraitForgeNft.sol` contract, the minting functions (`mintToken` and `mintWithBudget`) and the `_mintInternal` and `_incrementGeneration` functions do not check if the current generation has reached the maximum limit:

https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L181C3-L200C4

The `maxGeneration` state which represents the maximum generation allowed, is only checked in the forging process, and nowhere else.

Manual review

## Recommended Mitigation Steps
Add a check in the `_incrementGeneration` function to ensure the current generation doesn't exceed the maximum:
```diff
function _incrementGeneration() private {
    require(
        generationMintCounts[currentGeneration] >= maxTokensPerGen,
        'Generation limit not yet reached'
    );
+    require(
+        currentGeneration < maxGeneration,
+        'Maximum generation limit reached'
+    );
    currentGeneration++;
    // ... rest of the function
}
```
