# Vulnerability details

## Impact
`EntropyGenerator::entropySlots` are not always 78-digit numbers. Calculations of entropy will lead to not equal NFT stats distribution.
`EntropyGenerator::entropySlots` lower than 72-digit number can make `EntropyGenerator::getEntropy` to return 0 as division in this line can result with 0:
```solidity
uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000;
```

How this change entropy calculations?
Consider we have 76-digit number:
`__`1234...654321 where `_` represents missing digits to have equal 6-digits slices
Slices looks like this:
1234 for `numberIndex=0`
...
...
654321 for `numberIndex=12`


The most affected entropies are those at `numberIndex==0`, calculations in code:
```solidity
@audit in above scenario numberIndex==0, position == 0
    uint256 position = numberIndex * 6; // calculate the position for slicing the entropy value
    require(position <= 72, 'Position calculation error');

    uint256 slotValue = entropySlots[slotIndex]; // slice the required [art of the entropy value
@audit in above scenario for number `__`1234...654321, entropy == 1234
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits 
@audit paddedEntropy adds zeros at the end of number to match 6-digit slices
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
@audit paddedEntropy == 123400
    return paddedEntropy; // return the caculated entropy value
```
As we can see in the example above, for non-78-digit numbers ``EntropyGenerator::getEntropy`` will add zeros at the end of certain slices. 
NFT stats are calculated from entropy digits. `PerformanceFactor` is 6th digit and adding zeros at the end of some numbers will lead to bad distribution

Add this test to script above:
```solidity
    function test_wrongNFTStatsDistribution() public{
        uint256 numberOfPerformanceFactorZero = 0;
        uint256 numberOfPerformanceFactorNonZero = 0;
        uint256 entropy = 0; 
        uint256 performanceFactor = 0;
        for(uint256 i = 0; i < 770; i++){
            entropy = entropyGenerator.getPublicEntropy(i,0);
            performanceFactor = entropy % 10;
            if(performanceFactor == 0){
                numberOfPerformanceFactorZero++;
            } else{
                numberOfPerformanceFactorNonZero++;
            }
        }
        console.log(numberOfPerformanceFactorZero);
        console.log(numberOfPerformanceFactorNonZero);
    }
```
run `forge test --mt test_wrongNFTStatsDistribution -vvv`
result log:
```

```

At all slots with `numberIndex==0` we get 100% NFT with `performanceFactor==0` where it should be around 10%. This also affects forgers:mergers ratio and other stats.
