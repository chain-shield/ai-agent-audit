# Vulnerability details

## Impact
Price calculations is a critical part of the protocol, it determines the price at which the current entity will be minted based on the count of previous minted entity, but in a situation where we are crossing a gen to another gen then an issue occurs due to the fact that the price is calculated before then `_incrementGeneration` is made using the high price to mint the first token of the new generation which would be incorrect and lead to loss of funds for users minting.

## Proof of Concept
In the `mintToken` the price is calculated shown below and a call to `_mintInternal` is made to actually mint the token to the user
https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L181C1-L191C75
```solidity 
  function mintToken(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    require(msg.value >= mintPrice, 'Insufficient ETH send for minting.');
```
Inside the `_mintInternal` called with the price parameter are shown below 
```solidity
function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();

    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;

    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
    }
    _distributeFunds(mintPrice);
  }
```
Now The logic of calculating the price before the `_mintInternal` is sound if you are minting in the same generation, but once you move to another gen then you would be using the wrong price, as shown in the `calculatePrice` 

```solidity
 function calculateMintPrice() public view returns (uint256) {
    uint256 currentGenMintCount = generationMintCounts[currentGeneration];
    uint256 priceIncrease = priceIncrement * currentGenMintCount;
    uint256 price = startPrice + priceIncrease;
    return price;
  }
```
Now Lets create an example scenario to explain this better
- Minting the last token of a generation lets say gen 1 (10k), the price is gotten like this 
```
pricIncrease = 0.0000245 ether * 9999 = 0.2449755 ether
price = 0.005 ether + 0.2449755 ether = 0.2499755 ether
```
And this check inside `_mintInternal` will not make it increment the gen 
```solidity
 if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
      _incrementGeneration();
    }
```
since it would be `9999 >= 10000`, but it will set the generationMintCounts to 10000
- Now The next mint will go like this, it will get the price before even considering checking to increase the gen, resulting to using the wrong `generationMintCounts` and the wrong `priceIncrease` to calculate the price as shown below
 
```
priceIncrease = 0.0000245 ether * 10000 = 0.245 ether
price = 0.005 ether + 0.2449755 ether = 0.25 ether
``` 
This is wrong because of the factors listed above but more importantly when a new generation is started, the `priceIncrement` variable is increased by `priceIncrementByGen` as shown below 
```solidity
function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
```
This means that the price should be re-calculated if a generation increase was carried out and it should done as 
```
startPrice + priceIncrease //priceIncrease has now being increased by the priceIncrementByGen making it accurate
```

Manual Review

## Recommended Mitigation Steps
The price should be recalculated whenever a change of gen occurs to correctly reflect the price of the new gen tokens
