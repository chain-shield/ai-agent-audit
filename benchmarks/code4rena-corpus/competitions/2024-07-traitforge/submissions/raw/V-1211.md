# Vulnerability details

## Impact

The `TraitForgeNft::_incrementGeneration()` function is designed to increase the generation number once the maximum number of tokens per generation has been minted. However, it lacks a check to enforce the maximum allowable generations, potentially allowing more than the intended 10 generations to be minted. This function is triggered within `TraitForgeNft::_mintInternal()`, which is subsequently called by public functions such as `TraitForgeNft::mintToken()` and `TraitForgeNft::mintWithBudget()`, accessible to whitelisted users. This loophole enables the minting of additional generations, which could disrupt the designed game mechanics.

```solidity
function _incrementGeneration() private {
// @audit no check for maxGeneration
require(
    generationMintCounts[currentGeneration] >= maxTokensPerGen,
    'Generation limit not yet reached'
);
...
}
```

## Recommended Mitigation Steps

Introduce a check in `TraitForgeNft::_incrementGeneration()` to prevent exceeding the maximum number of generations, aligning with the check already implemented in `TraitForgeNft::_mintNewEntity()` on [L317](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L317):

```solidity
function _incrementGeneration() private {
+ require(
+   currentGeneration < maxGenerations,
+   'Maximum generations reached'
+ );

require(
    generationMintCounts[currentGeneration] >= maxTokensPerGen,
    'Generation limit not yet reached'
);

...
}
```
