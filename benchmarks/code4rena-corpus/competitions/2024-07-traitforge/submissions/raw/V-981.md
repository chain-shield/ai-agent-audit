# Vulnerability details

## Impact

Competitors can mint 10,000 NFTs in the first generation and after that, they cannot mint second-generation NFTs using the pure minting function. Then, from the second generation, they can be minted using forging between the first-generation NFTs. This means that competitors with first-generation NFTs can continue the game, but there will be no new competitors after the first generation. Also, even if they are minted using forging, if 10,000 NFTs of the first generation are already minted, the resulting next-generation NFT will not be created in the case of forging between first-generation NFTs, which will lead to disappointment in the game.

## Vulnerability Details

EntropyGenerator has initializeAlphaIndices function which can be called by only owner. The initializeAlphaIndices is called by it's constructor. There is no problem. Also it is called by _incrementGeneration function of TraitForgeNft contract. But TraitForgeNft instance is not an owner of EntropyGeneration contract. As you can guess, _incrementGeneration is called when the generation is up to the next generation. So NFTs over the second generation can't be minted by pure mint function.

## Proof of Concept

This POC shows current generation can’t be to 2nd generation

1. Add 3 public functions that can set current generation, set mint counts of the special generation and set token numbers
2. Add mint testing code when the total amount of NFTs is 10000 and the amount of first generation’s NFTs is 10000 in the TraitForgeNft.test.ts file
3. Run “npx hardhat test ./test/TraitForgeNft.test.ts”

## Recommended Mitigation Steps

Here’s a suggestion on how this could be solved. The idea is to add a modifier that allows the owner and nft contract to call initializeAlphaIndices in the EntropyGenerator contract. Also the onlyOwner modifier should be replaced with the new modifier in the initializeAlphaIndices function.
