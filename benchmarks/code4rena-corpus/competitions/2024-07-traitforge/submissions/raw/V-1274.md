# Vulnerability details

## Impact
`TraitForgeNft.mintWithBudget()` cannot mint new NFTs after `_tokenIds` reaches `maxTokensPerGen`.

## Proof of Concept
The while loop in `mintWithBudget()` checks that `_tokenIds` is less than `maxTokensPerGen`.

```
    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
```
[Link](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L215-L220)

The problem with this is that `_tokenIds` is incremented on every mint [here](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L285), and `maxTokensPerGen` is a constant declared [here](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L22).

So, after some time this function will stop being able to mint new NFTs.

## Recommended Mitigation Steps
`_mintInternal()` already deals with `maxTokensPerGen` limit correctly. So, it should be safe to remove `_tokenIds < maxTokensPerGen` check.
