# Vulnerability details

https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/DevFund/DevFund.sol#L40-L49

## Summary
Developers might receive rewards based on outdated weight calculations, resulting in potential financial discrepancies. Significant reward misallocations could arise, particularly if the weight adjustment is substantial or if the contract operates at a large scale with frequent transactions.

## Impact
When updating a developer's `weight` using the `updateDev` function, the contract does not trigger a reward `claim` for the developer. This can lead to inconsistencies in reward allocation, as the rewards accrued under the previous weight are not immediately distributed. If a developer's `weight` is increased or decreased, the rewards already earned with the old weight are not claimed before the update, potentially leading to a misalignment between expected and actual rewards.

## Proof of Concept
Consider a scenario where a developer (Bob) with a weight of 100 has accrued rewards based on this weight. If Bob's weight is updated to 200 without claiming the pending rewards, the contract will calculate future rewards using the new weight, leaving the previous rewards based on the old weight unclaimed. This results in a mismatch between Bob's actual pending rewards and what he might expect to claim.


```javascript
DevFund.sol
40:   function updateDev(address user, uint256 weight) external onlyOwner {
41:     DevInfo storage info = devInfo[user];
42:     require(weight > 0, 'Invalid weight');
43:     require(info.weight > 0, 'Not dev address');
44:     totalDevWeight = totalDevWeight - info.weight + weight;
45:     info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
46:     info.rewardDebt = totalRewardDebt;
47:     info.weight = weight;
48:     emit UpdateDev(user, weight);
49:   }
```

In this code snippet, the calculation: updates the `pendingRewards` without considering the immediate claim of existing rewards. 

```javascript
info.pendingRewards += (totalRewardDebt - info.rewardDebt) * info.weight;
```

The subsequent line:

```javascript
info.rewardDebt = totalRewardDebt;
```
sets the `rewardDebt` to the current `totalRewardDebt`, effectively resetting the developer's reward tracking to the new weight without settling the accumulated rewards.


## Example Scenario:

> **Initial state:**
> Bob's Weight: 100
> Pending Rewards: 0

> **Deposit to `DevFund` is made**
> Bob's reward is calculated to 5,000

> **Before update:**
> Pending reward: 5,000 at weight 100.

> **After weight update:**
> Bob's Weight: 200
> Pending reward: 10,000 now incorrectly accumulated at weight 200.

> **After Further Deposit:**
> Pending reward continues to grow based on unclaimed discrepancies.


Opposite scenario applies when dev's weight is reduced.

## Tools Used
Manual review

## Recommended Mitigation Steps
To address this issue and ensure consistent reward distribution, the contract should claim any pending rewards and transfer it to the developer before updating the `weight`. This will maintain reward accuracy and align expectations. Modify the `updateDev` function to include a reward claim process before updating the weight.
