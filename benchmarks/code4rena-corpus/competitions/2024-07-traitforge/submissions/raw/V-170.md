# Vulnerability details

## Impact
[deriveTokenParameters](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L152) will always return a nuke factor of 0, causing issue with integrations and queering .

## Proof of Concept
[deriveTokenParameters](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L152) calculates it's return variables based on entropy.

```solidity
    //@audit entropy is max `1e6 - 1`
    nukeFactor = entropy / 4000000; // entropy / 4e6
    forgePotential = getFirstDigit(entropy);
    performanceFactor = entropy % 10;

```

However the function doesn't take into account that solidity works with only whole numbers and it always rounds down. In the case of `nukeFactor` it will always return 0, since `entropy < 1e6`, while we are dividing it by `4e6`. We know `entropy < 1e6` because it's verified inside [getEntropy](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/EntropyGenerator/EntropyGenerator.sol#L180-L182) to be less than 1e6:

```solidity
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; 
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
    return paddedEntropy; 
```



## Tools Used
Manual review

## Recommended Mitigation Steps
Calculate `nukeFactor` percentage, by dividing it by 4e4 instead of 4e6. This will return a percentage from 0% to 25% based on it's entropy.
