# Vulnerability details

## Impact
Break of Protocol Functionality as Token Generation can go above the Maximum allowed in the TraitForgeNft contract during Internal Minting
## Proof of Concept
```solidity
  /// @dev generation limit
  uint256 public maxGeneration = 10;
```
As can be noted from the variable above, it shows the maximum generation allowed in contract
```solidity
  function _mintInternal(address to, uint256 mintPrice) internal {
    if (generationMintCounts[currentGeneration] >= maxTokensPerGen) {
>>>      _incrementGeneration();
    }

    _tokenIds++;
    uint256 newItemId = _tokenIds;
    _mint(to, newItemId);
    uint256 entropyValue = entropyGenerator.getNextEntropy();

    tokenCreationTimestamps[newItemId] = block.timestamp;
    tokenEntropy[newItemId] = entropyValue;
    tokenGenerations[newItemId] = currentGeneration;
    generationMintCounts[currentGeneration]++;
    initialOwners[newItemId] = to;

    if (!airdropContract.airdropStarted()) {
      airdropContract.addUserAmount(to, entropyValue);
    }

    emit Minted(
      msg.sender,
      newItemId,
      currentGeneration,
      entropyValue,
      mintPrice
    );

    _distributeFunds(mintPrice);
  }
```
The code provided above shows how internal minting is implemented in contract, it can be noted that when the generationMintCounts for the currentGeneration is filled up, a Generation increment is done by calling _incrementGeneration() function as provided below.
```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
The problem is that right from the external functions calling _mintInternal(...) function down to the increment of Generation when necessary, there is an oversight as no implementation was done to ensure Generation does not go beyond the maximum allowed.
To understand the sensitivity of this error, a look at [L166](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L166) of the forge(...) function shows that a validation was done to ensure Generation can never cross the max allowed before _mintNewEntity(...) function was later called with this validated generation value, this is not the case for functions calling _mintInternal(...) at [L216](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L216) & [L193](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/TraitForgeNft/TraitForgeNft.sol#L193) of the contract, at no point was this necessary validation done which would allow Generation going above the limit set by contract

## Recommended Mitigation Steps
One way to correct this issue is to ensure validation is done in the _mintInternal(...) function to ensure current generation to be minted never goes above the maximum allowed another way to do this as adjusted below is to ensure currentGeneration variable increment is only possible when it is within the limit of the max generation set in contract.
```solidity
  function _incrementGeneration() private {
    require(
      generationMintCounts[currentGeneration] >= maxTokensPerGen,
      'Generation limit not yet reached'
    );
+++ require(currentGeneration <= maxGeneration);
    currentGeneration++;
    generationMintCounts[currentGeneration] = 0;
    priceIncrement = priceIncrement + priceIncrementByGen;
    entropyGenerator.initializeAlphaIndices();
    emit GenerationIncremented(currentGeneration);
  }
```
