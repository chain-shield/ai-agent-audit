# Vulnerability details

## Impact
A user can maximize his profits by front-running other nuke transactions

## Proof of Concept

Let's assume that there are currently 1000 active entities, out of which a portion can be nuked. Until time T, all users are waiting for their entities to mature more and produce better profits. At time T, a user X decides to nuke his entity and withdraw a part of the honeypot. With an average nuke factor of ~14% (calculated from the average entropy, 555555), this nuke would eliminate the contribution of the last 86 minted entities, and would require 79 new ones to bring back the pot to the same value.

A malicious user can decide to front-run the transaction of user X and withdraw first, therefore getting a bigger chunk of the reward pool. Two average entities nuking - user X and the malicious user - would remove ~4 out of ~15.5 ETH from the pot. If a second malicious user attempts the same thing, it would already remove ~5.5 out of the 15.5 ETH.

If more than one user shares the same strategy, this could potentially hurt the protocol. If this triggers around 4% of the player base to nuke their entities, a nuke would not even be profitable anymore and would most likely cause all users to attempt to recover what they can from the investment and kill the game.

## Tools Used
Manual inspection

## Recommended Mitigation Steps
Use flashbots to hide user intentions and prevent front-running.
