# Vulnerability details

#### Description:
The `startAirdrop` function in the `Airdrop` contract uses an arbitrary address for the `from` parameter in the `transferFrom` call, specifically `tx.origin`.

## Impact
Using `tx.origin` instead of `msg.sender` allows for the possibility of unauthorized token transfers. An attacker can exploit this by initiating a transaction from another contract, leading to tokens being transferred from an unintended account. This vulnerability can result in significant financial loss and undermines the trust in the contract's security.

#### Steps to Reproduce:
1. Deploy the `Airdrop` contract.
2. Initiate a transaction to the `startAirdrop` function from another contract, not directly from an external account.
3. Observe that the `transferFrom` call uses the original external account (`tx.origin`), potentially transferring tokens from an unintended address.

## Tools Used
Solidity, Hardhat, OpenZeppelin Contracts

## Recommended Mitigation Steps
Replace `tx.origin` with `msg.sender` in the `transferFrom` call to ensure that the function transfers tokens from the immediate caller, preventing unauthorized token transfers.

### Exploit Contract
A malicious contract that initiates the `startAirdrop` function on the `Airdrop` contract using `tx.origin` demonstrating how an attacker can exploit the use of `tx.origin` to transfer tokens from an unintended account.

```javascript
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import '@openzeppelin/contracts/token/ERC20/IERC20.sol';
import './Airdrop.sol';

contract MaliciousContract {
    Airdrop public airdropContract;
    IERC20 public traitToken;

    constructor(address _airdropContract, address _traitToken) {
        airdropContract = Airdrop(_airdropContract);
        traitToken = IERC20(_traitToken);
    }

    function initiateAirdrop(uint256 amount) external {
        // Transfer tokens to this contract
        traitToken.transferFrom(msg.sender, address(this), amount);

        // Approve the Airdrop contract to spend tokens on behalf of this contract
        traitToken.approve(address(airdropContract), amount);

        // Call startAirdrop on the Airdrop contract
        airdropContract.startAirdrop(amount);
    }
}
```

### Steps to Deploy and Test the Exploit

1. **Deploy the Contracts:**
   - Deploy the `TraitToken` contract (if not already deployed).
   - Deploy the `Airdrop` contract, providing the address of the `TraitToken`.
   - Deploy the `MaliciousContract`, providing the addresses of the `Airdrop` contract and the `TraitToken`.

2. **Fund the Malicious Contract:**
   - Transfer tokens to the `MaliciousContract` from an external account.

3. **Exploit the Airdrop Contract:**
   - Call the `initiateAirdrop` function on the `MaliciousContract` from an external account.
   - Observe that the `startAirdrop` function in the `Airdrop` contract uses `tx.origin`, leading to the tokens being transferred from the external account that initiated the transaction rather than the `MaliciousContract`.

### Exploit Scenario Explanation

1. **Transfer Tokens:**
   - The `initiateAirdrop` function first transfers tokens from the external account to the `MaliciousContract`.

2. **Approve Tokens:**
   - The `MaliciousContract` then approves the `Airdrop` contract to spend the tokens on its behalf.

3. **Call startAirdrop:**
   - The `MaliciousContract` calls `startAirdrop` on the `Airdrop` contract.
   - Due to the use of `tx.origin` in the `Airdrop` contract, the tokens are transferred from the original external account (`tx.origin`) instead of the `MaliciousContract`.

This exploit demonstrates how the use of `tx.origin` can lead to unintended token transfers from an external account. To prevent this, the `Airdrop` contract should use `msg.sender` instead.

### Recommended Mitigation Steps

Replace `tx.origin` with `msg.sender` in the `transferFrom` call to ensure that the function transfers tokens from the immediate caller, preventing unauthorized token transfers.

#### Mitigation Code:
```javascript
traitToken.transferFrom(msg.sender, address(this), amount);
```

Updated `startAirdrop` function:
```javascript
function startAirdrop(uint256 amount) external whenNotPaused nonReentrant onlyOwner {
    require(!started, 'Already started');
    require(amount > 0, 'Invalid amount');
    traitToken.transferFrom(msg.sender, address(this), amount);
    started = true;
    totalTokenAmount = amount;
}
```
