# Vulnerability details

## Impact
The function `EntityForging::forgeWithListed` allows users to send more ETH than required to forge, but it lacks a mechanism to return the excess ETH back to the sender causing direct loss of funds. Furthermore, the contract has no implementation to withdraw these funds, so they will be locked in the contract indefinitely.

Inside the function `forgeWithListed` the following line is what checks the message value sent and the transfer amounts -

```
    require(msg.value >= forgingFee, 'Insufficient fee for forging');

    // ... [other code] ...

    (bool success, ) = nukeFundAddress.call{ value: devFee }('');
    require(success, 'Failed to send to NukeFund');
    (bool success_forge, ) = forgerOwner.call{ value: forgerShare }('');
    require(success_forge, 'Failed to send to Forge Owner');
```

## Recommended Mitigation Steps
You can choose to either require that the `msg.value` being sent is equal to the fee, or you can implement a transfer of excess back to the sender.

1. Change the require statement to ensure exact payment: 

```diff
-    require(msg.value >= forgingFee, 'Insufficient fee for forging');
+    require(msg.value == forgingFee, 'Insufficient fee for forging');
```

2. Implement transfer of excess eth back to sender.
```diff
      // ... [other code] ...

+    }
```
