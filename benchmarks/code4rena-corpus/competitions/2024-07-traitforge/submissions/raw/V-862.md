# Vulnerability details

## Impact
Multiple contracts are using Openzeppelin's `Pausable` module via inheritance, and in those contracts the relevant modifiers like `whenNotPaused` are used, indicating that the dev planned to implement an emergency stop mechanism by using this `Pausable` module. However, the inherited `Pausable` module itself only contains `_pause` and `unpause` internal functions which need to be called by a public/external function (with access control, of course) defined in the child contract. The contracts in this protocol didn't define such functions, so that the whole `Pausable` functionality will not work. Such a discrepancy in the design makes it an Medium severity issue.

## Proof of Concept
Openzeppelin contracts added warnings regarding how to use the `Pausable` module correctly in this [PR#4007](https://github.com/OpenZeppelin/openzeppelin-contracts/pull/4007/files). 

The mistake in this protocol is exactly what those warnings are referring to. Quoted as below:
```
 * IMPORTANT: This contract does not include public pause and unpause functions. In
 * addition to inheriting this contract, you must define both functions, invoking the
 * {Pausable-_pause} and {Pausable-_unpause} internal functions, with appropriate
 * access control, e.g. using {AccessControl} or {Ownable}. Not doing so will
 * make the contract unpausable.
```

## Tools Used
Manual review

## Recommended Mitigation Steps
Define a public/external callable function with access control to correctly use the `Pausable` module.
