# Vulnerability details

## Impact
When configured tax rate (`taxCut`) is different than 10%, tax fee calculation across codebase at multiple places is incorrect causing charged fee to be radically different than expected value.


## Proof of Concept

In the following functions tax fee calculation assumes that the taxCut is hardcoded at 10%.  

* [EntityForging.forgeWithListed()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityForging/EntityForging.sol#L146)

* [EntityTrading.buyNFT()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L72)

* [NukeFund.receive()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/NukeFund/NukeFund.sol#L41)

However, setTaxCut() accessible to the owner is present in each of these 3 contracts. Using setTaxCut() owner may change taxCut to values different than 10 (which represents 10% tax rate). When this happens tax fee charged would be unexpected as in case when taxCut is set to 2 effective tax rate will be 50%.


Place the following test code into EntityTrading.test.ts:

```javascript
it('should charge and send correct tax fee to NukeFund', async function () {
    await entityTrading.connect(owner).setTaxCut(5);
    await nft
      .connect(buyer)
      .approve(await entityTrading.getAddress(), TOKEN_ID);
    await entityTrading.connect(buyer).listNFTForSale(TOKEN_ID, LISTING_PRICE);

    const initialNukeFundBalance = await ethers.provider.getBalance(
      nukeFund.address
    );
    await expect(entityTrading.buyNFT(TOKEN_ID, { value: LISTING_PRICE }))
      .to.emit(entityTrading, 'NukeFundContribution')
      .withArgs(await entityTrading.getAddress(), LISTING_PRICE / 5n);

    // Check the NukeFund balance after the purchase
    const finalNukeFundBalance = await ethers.provider.getBalance(
      nukeFund.address
    );
    // @audit - should equal 5% but is not and it fails here
    expect(finalNukeFundBalance - initialNukeFundBalance).to.equal(
      LISTING_PRICE * 5n / 100n
    );
  });
```

## Tools Used
Manual review / Hardhat tests

## Recommended Mitigation Steps

To avoid this issue consider the following:

1. Immutable 10% tax cut: Make the `taxCut` parameter immutable by setting it only once and removing the `setTaxCut` function. This ensures the current fee calculation that works with hardcoded 10% rate is correct whenever used.

2. Replace the current tax fee calculation to:

```javascript
uint256 public constant HUNDRED_PERCENT_PRECISION = 100
...
fee = (value * taxCut) / HUNDRED_PERCENT_PRECISION;
```
