# Vulnerability details

## Impact

A vulnerability exists in the `forgeWithListed` function within the `EntityForging.sol` contract. The function fails to handle situations where the user sends additional `msg.value` (ether) exceeding the required amount for forging. This leads to user funds becoming locked indefinitely within the contract, inaccessible by the user, other entities, or even the contract owner. This can result in permanent financial loss for users as retrieving the excess funds becomes impossible.

## Proof of Concept

1. **Forging Listing:** A forger is listed with a price of 0.1 ETH.
2. **Excess Payment:** A user selects this forger to forge with but sends 0.3 ETH instead of the required 0.1 ETH.
3. **Unhandled Excess:** The `forgeWithListed` function only processes the necessary 0.1 ETH for forging. However, the remaining 0.2 ETH remains trapped within the contract.


The `forgeWithListed` function lacks the logic to manage excess `msg.value` provided by users. This additional value isn't refunded or returned to the user, leading to their funds being locked indefinitely.

## Tools Used
Manual review

## Recommended Mitigation Steps
To mitigate this risk, it's imperative to implement logic within the `forgeWithListed` function that handles potential excess `msg.value`. This can be achieved by:

1. **Calculating Excess:** Determine the difference between the received `msg.value` and the actual forging cost.
2. **Refunding Excess:** Utilize a mechanism like `.call` or a secure alternative to transfer the calculated excess amount back to the user's address.

By implementing this solution, the `forgeWithListed` function ensures that only the required amount for forging is used, while any additional funds are safely returned to the user, preventing unintended fund locking.
