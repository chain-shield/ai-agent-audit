# Vulnerability details

## Impact

The generation incrementing process is not functioning as expected due to incorrect access control in the `EntropyGenerator.initializeAlphaIndices()` function. Specifically, the `onlyOwner` modifier restricts access, causing the call to revert when `msg.sender` is the `TraitForgeNft` contract.

As a result, NFTs cannot be minted beyond the first generation, capping the total number of NFTs at 10,000. Additionally, any operation (e.g., forging) that triggers the `_incrementGeneration()` function will fail, impeding the contract's intended functionality and limiting the platform's capability to evolve NFTs over multiple generations.

## Proof of Concept

## Recommended Mitigation Steps

To resolve the access control issue, modify the access modifier for the `initializeAlphaIndices()` function to allow both the owner and the `TraitForgeNft` contract to call it. Here is the recommended change:

```diff
diff --git a/contracts/EntropyGenerator/EntropyGenerator.sol b/contracts/EntropyGenerator/EntropyGenerator.sol
index 3c10979..49ebf83 100644
--- a/contracts/EntropyGenerator/EntropyGenerator.sol

+  modifier onlyOwnerOrAllowedCaller() {
+    require(
+      msg.sender == owner() || msg.sender == allowedCaller,
+      'Caller is not allowed'
+    );
+    _;
+  }
```

- **New Modifier:** A new modifier, `onlyOwnerOrAllowedCaller`, is added to allow calls from both the contract owner and the specified `allowedCaller`.
- **Access Control Adjustment:** The `initializeAlphaIndices()` function now uses the new modifier to ensure both the owner and the designated NFT contract can invoke it. This change enables proper generation incrementing and ensures the system can support more than one generation of NFTs. 

Implementing these changes will allow the `TraitForgeNft` contract to increment the generation correctly, enabling the minting of NFTs beyond the first generation and ensuring seamless operation of all related processes.
