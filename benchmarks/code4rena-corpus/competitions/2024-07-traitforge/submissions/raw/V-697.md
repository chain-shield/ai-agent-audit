# Vulnerability details

## Impact
The `mintWithBudget` function incorrectly limits minting to `maxTokensPerGen` (10,000) tokens. Once `_tokenIds` reaches 10,000, the function will not work.

## Proof of Concept
The NFT contract contains the `mintWithBudget` function, which is used to mint multiple NFTs in one transaction. Here is the function code:

```solidity
  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

    while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```

Note that there is a limit in the loop condition: `_tokenIds < maxTokensPerGen`. According to the current design, `maxTokensPerGen` is set to 10000, and `maxGeneration` is set to 10. Therefore, the expected maximum tokenId should be `maxTokensPerGen * maxGeneration` (100000). However, the check in the function limits the maximum tokenId to `maxTokensPerGen` (10000). This means that when the tokenId is greater than or equal to 10000 (for example, when reaching the third generation), the `mintWithBudget` function will not work. Consequently, users will not be able to mint multiple NFTs at once when the tokenId exceeds 10000.
