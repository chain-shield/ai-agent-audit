# Vulnerability details

## Impact and Proof of Concept
This value was fetched using chisel computing the same way the `writeEntropyBatches()` does:
```solidity
uint256 slotValue = 94561650817225871469484233276892978976240601015329700164327880431188089465104;
uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000;
// for position = numberIndex * 6
// numberIndex = 0

➜ uint256 entropy = (slotValue / (10 ** (72 - 0 ))) % 1000000;
➜ entropy
Type: uint256
├ Hex: 0x17161
├ Hex (full word): 0x17161
└ Decimal: 94561

uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
//pe = 94561 * (10^(6-5))
//pe = 94651 * 10
paddedEntropy = 946510
```
`NukeFund::calculateAge()` calculates daysOld and the `performanceFactor = nftContract.getTokenEntropy(tokenId) % 10`
for above example: `946510 % 10` returns 0.

`uint256 age = (daysOld *
      perfomanceFactor *
      MAX_DENOMINATOR *
      ageMultiplier) / 365;` // add 5 digits for decimals
age = 15 * 0 * 100000 * ageMultiplier / 365
Hence the value of age = 0

This value will be used in `calculateNukeFactor()` 
`uint256 adjustedAge = calculateAge(tokenId);`
`uint256 finalNukeFactor = ((adjustedAge * defaultNukeFactorIncrease) /
      MAX_DENOMINATOR) + initialNukeFactor;`

effectively making the `finalNukeFactor` value the same as `initialNukeFactor`.

This leads to decreased `claimAmount` for the user that calls `nuke(tokenId)`

## Tools Used
Manual

## Recommended Mitigation Steps
The logic needs to be updates such that the users with such entropies has a value of age `minimumAge` associated while calculating their `nukeFactor` in turn calculating `claimAmount`
