# Vulnerability details

## Impact
When using [MerkleProof.sol](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/utils/cryptography/MerkleProof.sol)  avoid using leaf values that are 64 bytes long prior to hashing. However proof in `onlyWhitelisted` modifier in  `TraitForgeNft` contract uses leaf values that are exactly 64 bytes long. An attacker can bypass the merkle-tree proof  and exploit  the `onlyWhitelisted` modifier to mint tokens.


## Proof of Concept
As stated in the [Natspec](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/e3786e63e6def6f3b71ce7b4b30906123bffe67c/contracts/utils/cryptography/MerkleProof.sol#L16) of [MerkleProof.sol](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/master/contracts/utils/cryptography/MerkleProof.sol) :

```console
 * WARNING: You should avoid using leaf values that are 64 bytes long prior to
 * hashing, or use a hash function other than keccak256 for hashing leaves.
 * This is because the concatenation of a sorted pair of internal nodes in
 * the Merkle tree could be reinterpreted as a leaf value.
            //                 //             //
```
The leaf value in `onlyWhitelisted` modifier are exactly 64 bytes long (uint256 + uint256 = 32 bytes + 32 bytes = 64 bytes).


The merkle-tree proof could be bypassed when the leaf values are 64 bytes long. The following links can help you understand the details.
https://github.com/OpenZeppelin/openzeppelin-contracts/issues/3091
https://blog.openzeppelin.com/zksync-layer-1-audit/#merkle-library-verifies-intermediate-inputs

The modifier  [TraitForgeNft.sol#L51](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L51) :


```
  modifier onlyWhitelisted(bytes32[] calldata proof, bytes32 leaf) {
    if (block.timestamp <= whitelistEndTime) {
      require(
        MerkleProof.verify(proof, rootHash, leaf),
        'Not whitelisted user'
      );
    }
    _;
  }

```


How its been used in the functions  [mintToken()](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/TraitForgeNft/TraitForgeNft.sol#L188)

Attacker can abuse merkle tree collisions to bypass the `onlyWhitelisted` modifier and mint tokens.

Manual
## Recommended Mitigation Steps
1. Don’t use leaf values that are 64 bytes long
2. Use [@openzeppelin/merkle-tree](https://github.com/OpenZeppelin/merkle-tree) instead.
