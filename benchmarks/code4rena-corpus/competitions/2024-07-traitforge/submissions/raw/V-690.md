# Vulnerability details

## Impact
NFT owner's airdrop amount is unfairly deducted due to burning by the new owner

## Proof of Concept
```
function testAirdropWronglyDeducted() public {
        vm.warp(block.timestamp + 25 hours);
        vm.roll(1);
        vm.deal(alice, 10e18);
        vm.deal(bob, 2e18);

        vm.prank(owner);
        entropyGenerator.writeEntropyBatch1();
        
        bytes32[] memory proof;
        uint256 mintPrice = traitForgeNft.calculateMintPrice();

        //alice mints nft
        vm.startPrank(alice);
        traitForgeNft.mintToken{value : mintPrice}(proof);

        mintPrice = traitForgeNft.calculateMintPrice();

        traitForgeNft.mintToken{value : mintPrice}(proof);

        console.log(airdrop.userInfo(alice)); //862495

        traitForgeNft.approve(address(entityTrading), 1);

        entityTrading.listNFTForSale(1, 1e18);
        vm.stopPrank();

        mintPrice = traitForgeNft.calculateMintPrice();
        vm.prank(bob);
        traitForgeNft.mintToken{value : mintPrice}(proof);

        //bob buys and NFT from alice
        vm.prank(bob);
        entityTrading.buyNFT{value: 1e18}(1);

        //bob decided to burn or nuke the nft
        vm.prank(bob);  
        traitForgeNft.burn(1);


        //alice's airdrop amount is reduced by the entropy of the burnt NFT
        console.log(airdrop.userInfo(alice)); //374695
        console.log(airdrop.userInfo(bob)); //574474
    }
```

The above POC shows how burning/nuking an NFT reduces the airdrop amount of the seller not the buyer.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Consider setting the "to" address as the initialOwner in _beforeTokenTransfer or recalculate airdrop balances for the "from" and "to" address in _beforeTokenTransfer and deduct the airdrop balance of the NFT's "ownerOf" whenever a burn or nuke is initiated.
