# Vulnerability details

## Impact
The claimable nuke fund could exceed the `maxAllowedClaimAmount`, leading to users claiming more than intended rewards.

## Proof of Concept
In the `NukeFund` contract, the `nuke()` function calculates the claimable amount of nuke funds for an NFT based on its `finalNukeFactor`. The issue arises when the `finalNukeFactor <= nukeFactorMaxParam`. In such cases, the claimable amount is set to `potentialClaimAmount`, which can exceed the `maxAllowedClaimAmount`.

If `finalNukeFactor <= nukeFactorMaxParam`, the code assigns `potentialClaimAmount` to `claimAmount` without ensuring that it does not exceed `maxAllowedClaimAmount`:

```solidity
File: NukeFund.sol
166:     uint256 potentialClaimAmount = (fund * finalNukeFactor) / MAX_DENOMINATOR; // Calculate the potential claim amount based on the finalNukeFactor
167:     uint256 maxAllowedClaimAmount = fund / maxAllowedClaimDivisor; // Define a maximum allowed claim amount as 50% of the current fund size
168: 
169:     // Directly assign the value to claimAmount based on the condition, removing the redeclaration
170:     uint256 claimAmount = finalNukeFactor > nukeFactorMaxParam
171:       ? maxAllowedClaimAmount
172:       : potentialClaimAmount;
```

For intance, given

- `finalNukeFactor` = 1000
- `nukeFactorMaxParam` = 1000
- `potentialClaimAmount` = 0.5 ether
- `maxAllowedClaimAmount` = 0.2 ether

As `finalNukeFactor == nukeFactorMaxParam`, the claimable amount is 0.5 ether, which exceeds `maxAllowedClaimAmount`.
