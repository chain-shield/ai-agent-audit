# Vulnerability details

## Impact
In the `EntityForging` contract, the `listForForging()` function contains an inappropriate limit validation for the forging. 

The problematic code is as follows:

```solidity
require(forgePotential > 0 &&
  forgingCounts[tokenId] <= forgePotential, 'Entity has reached its forging limit');
```

This bug effectively permits one extra forge beyond the intended limit, since `forgingCounts[tokenId]` is incremented in the `forgeWithListed()` function. This occurs due to an off-by-one error in the condition checking the `forgingCounts` against the `forgePotential`.

Possible scenario:

1. Bob lists his NFT with `forgePotential` = 1 for forging.
2. Forging is done and now `forgingCounts[tokenId]` is equal to 1.
3. Bob lists the same NFT again, since `forgingCounts[tokenId]` = `forgePotential`, even tough he should not be able to do that until reseting the `forgingCounts[tokenId]`.

## Proof of Concept

Place the following test into EntityForging.test.ts:

```javascript

it('should allow forging with a listed token 2', async () => {
      const forgerTokenId = FORGER_TOKEN_ID;
      const mergerTokenId = MERGER_TOKEN_ID;

      const forgerEntropy = await nft.getTokenEntropy(forgerTokenId);
      const mergerEntrypy = await nft.getTokenEntropy(mergerTokenId);
      
      let mergePotential = mergerEntrypy / 10n % 10n;
      let forgePotential = forgerEntropy / 10n % 10n;
      console.log("Forge potential", forgePotential);
      console.log("Merge potential", mergePotential);
      let forgingCount = 0;
      await entityForging.connect(owner).listForForging(forgerTokenId, FORGING_FEE);
      for(let i=0; i<forgePotential; i++){
        await entityForging.connect(user1).forgeWithListed(forgerTokenId, mergerTokenId, { value: FORGING_FEE,});
        await entityForging.connect(owner).listForForging(forgerTokenId, FORGING_FEE);
        forgingCount += 1;
      }
      await entityForging.connect(user1).forgeWithListed(forgerTokenId, mergerTokenId, { value: FORGING_FEE,});
      forgingCount += 1;

      console.log("Total Times Froged: ", forgingCount);
      expect(forgingCount-1).to.be.equal(forgePotential);
    });
```

## Recommended Mitigation Steps

To address this issue, the condition in the `listForForging()` function should be modified to strictly enforce the forging limit. The corrected check should be:

```javascript
require(forgePotential > 0 &&
  forgingCounts[tokenId] <
    forgePotential, 'Entity has reached its forging limit');
```

By changing <= to <, we ensure that the forgingCounts can never reach the value of `forgePotential`, thus preventing the extra forge. This change will align the contract's behavior with the intended design, maintaining the integrity of the forging mechanic and ensuring fair gameplay for all participants.
