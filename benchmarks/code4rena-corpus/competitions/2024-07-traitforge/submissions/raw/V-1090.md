# Vulnerability details

The entropy generation mechanism in `EntropyGenerator.sol` involves slicing a large pseudo-random number into smaller 6-digit chunks. 
```
    uint256 entropy = (slotValue / (10 ** (72 - position))) % 1000000; // adjust the entropy value based on the number of digits
    uint256 paddedEntropy = entropy * (10 ** (6 - numberOfDigits(entropy)));
```

If the large number has fewer than 78 digits, the resulting number / 10^72 will give a number with less than 6 digits.

Then the paddedEntropy will add a 0's at the end to get 6 digit number.

Similar thing happens when 1st digit in any of the 6 digit slices is 0. 

Since performanceFactor is calculated as entropy % 10, it has a high chance of being 0.

## Impact
This issue significantly impacts the randomness and distribution of the performance factor. 

A zero performance factor can lead to entities that do not age, creating an imbalance in the game mechanics and potentially leading to unforeseen advantages or disadvantages for certain players. 

This undermines the fairness and unpredictability that are crucial for a competitive game environment.

## Tools Used
Manual review

## Recommended Mitigation Steps
Using digits 3 or 4 in the 6 digit value returned is much more reliable.
