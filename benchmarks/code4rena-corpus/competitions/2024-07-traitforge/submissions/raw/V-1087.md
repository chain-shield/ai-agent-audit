# Vulnerability details

## Impact

In the game, competitors try to have more fun and get more benefits from the game by having multiple NFTs instead of just one. In this respect, the mintWithBudget function is more convenient than minting them one by one. However, this function will trigger "out of gas" problem if ethers is greater than the value to mint more than somewhat NFTs. This makes it inconvenient for players to participate in the game and they have to divide the ether value to use mintWithBudget function. This reduces the appeal of the game.

## Vulnerability Details

There is a while code block to mint batch NFTs with ethers. This code block mints until sent ethers are consumed all. So _mintInternal function will be called so many times. This produces a gas problem.

```solidity

  ITraitForgeNft,
  ERC721Enumerable,
  ReentrancyGuard,
  Ownable,
  Pausable
{

  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

  @>while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
  @>    _mintInternal(msg.sender, mintPrice);
  @>    amountMinted++;
  @>    budgetLeft -= mintPrice;
  @>    mintPrice = calculateMintPrice();
  @>  }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }  
...
}
```

## Recommended Mitigation Steps

The problem is that there is no batch mint feature in the smart contract. So the suggestion is to use ERC721A not ERC721 to implement TraitForgeNft contract. ERC721A has a batch minting function.
And all variables related to mint should be calculated at a time not one by one.
