# Vulnerability details

## Impact
The pseudorandom numbers representing the 13 concatenated entropies obtained in the batch write process are calculated as the remainder of the `keccak256` hash divided by `uint256(10)**78`. Since this number will overflow, the actual value used as the divisor is `73663286101470436611432119930496737173840122674875487684339327936694962880512`, which is 77 digits long. Because the remainder will be strictly less than this number, the entropy slots will consist of a maximum of 77 digits. Consequently, the entropy at index 0 will always be 5 digits long.

```javascript
uint256 pseudoRandomValue = uint256(
                    keccak256(abi.encodePacked(block.number, i))
                ) % uint256(10) ** 78;
```
## Proof of Concept
Look at the following example on Chisel:

```javascript
➜ uint256[] memory arr = new uint256[](1);
        uint256 num;
        unchecked {
            arr[0] = (type(uint256).max) % uint256(10) ** 78;
            num = uint256(10) ** 78;
        }
```

The first slot of array `arr` contains the entropies derived using the highest possible dividend. `num` represents the divisor, it can be seen that the divisor is smaller than the max uint256:

It is oberved that `num` and `arr[0]` both have 77 decimals, therefore the entropy at the frist index will only have 5 digits:

## Recommended Mitigation Steps
Use `type(uint256).max` as the divisor. Note that this will not guarantee a completely balanced distribution of entropies as index 0 will be capped at 199999, you can also consider keeping the system as is now and simply randomize the first element by adding the amount `100000*x` where x is an integer such that `0<=x<8`.
