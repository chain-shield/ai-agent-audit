# Vulnerability details

Devs can be added, updated or removed by the owner. Devs can claim a portion of the  total reward debt depending on their `weight` parameter. The higher the weight, the more rewards can be claimed.

However the scenario is not the same for the devs even having the same value of `weight` to other devs.

## Proof of Concept

When adding a dev, the `info.rewardDebt` is set to the amount that's stored in the `totalRewardDebt`. 
```solidity

    DevInfo storage info = devInfo[user];
    require(weight > 0, 'Invalid weight');
    require(info.weight == 0, 'Already registered');
>   info.rewardDebt = totalRewardDebt;
    info.weight = weight;
    totalDevWeight += weight;
    emit AddDev(user, weight);
  }
```
When claiming the rewards `info.rewardDebt` is subtracted from the current `totalRewardDebt`.

```solidity
File: DevFund.sol

  function claim() external whenNotPaused nonReentrant {
    DevInfo storage info = devInfo[msg.sender];

    uint256 pending = info.pendingRewards +
>     (totalRewardDebt - info.rewardDebt) *
      info.weight;

    if (pending > 0) {
      uint256 claimedAmount = safeRewardTransfer(msg.sender, pending);
      info.pendingRewards = pending - claimedAmount;
      emit Claim(msg.sender, claimedAmount);
    }

    info.rewardDebt = totalRewardDebt;
  }
```
### Scenario:
- Lets say there are three devs Alice, Bob & Chris. They are to be added with a `weight` = `5`.
- The owner adds Alice & Bob early on when `totalRewardDebt` is `0`. So their `rewardDebt` is also `0` at this point.
- Funds are added & `totalRewardDebt` becomes `5` & the contract balance `100`.
- Chris is added at this point by the owner. So his `rewardDebt` is `5` at this point.
- Funds are again added & `totalRewardDebt` becomes `10` & the contract balance `200`.
- All three devs call the `claim()`.

*Note - The weight of all the devs is same*
```solidity
   uint256 pending = info.pendingRewards +
     (totalRewardDebt - info.rewardDebt) *
      info.weight;
```
- The reward calculated for Alice & Bob is -> `0 + (10 - 0) * 5` = `50`.
- The reward calculated for Chris -> `0 + (10 - 5) * 5` = `25`.

Here we can see that Chris earned half the reward compared to Alice & Bob.

## Impact
Early Devs get more funds than devs added at a later period.

## Tools Used
Manual Review

## Recommended Mitigation Steps
A recommendation might be to add a new function which claims the rewards for all the devs whenever a new dev is added so that the `totalRewardDebt` is same for all.
