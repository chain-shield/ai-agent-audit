# Vulnerability details

## Impact
In the `TraitForgeNft` contract, when NFT tokens transition from an older generation to a newer one, the contract calls the `_incrementGeneration` function. This function attempts to invoke `initializeAlphaIndices` in the `EntropyGenerator` contract to update and randomize `999999` entropy slots and index locations. However, this call always reverts.

This occurs because `initializeAlphaIndices` is restricted to the `EntropyGenerator` contract’s owner by the `onlyOwner` modifier. Since the owner is a multisig wallet rather than the `TraitForgeNft` contract, the call fails.

As a result, new generations cannot be created once the maximum limit is reached. This issue prevents the protocol from advancing beyond the 1st generation, despite the intended design to support up to 10 generations. Consequently, only 10,000 tokens can be minted instead of the required 100,000, impacting the protocol's functionality.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Change the modifier of `initializeAlphaIndices` function in `EntropyGenerator` contract from `onlyOwner` to `onlyAllowedCaller`.
