# Vulnerability details

## Description
The function `_mintNewEntity` is called when forging a new NFT, for that it's necessary to use a forgerToken and a mergerToken, which is checked to see if both belong to the same generation, and for that reason I think it was not intended. When a tokens it's forged, it is minted to the parent's generation + 1, that means, if it's from the current generation it will be from the next generation, if it's from the previous generation, it will be from the current generation, and if it's from before the previous generation, it will revert because there is a limit to the number of NFTs per generation and that generation will already be at the limit.

## Impact
High or medium, NFTs from before the previous generation won't be able to be used for forging

## Recommended Mitigation Steps
Mint to the current generation if it's from before the previous generation

```diff
function forge(
    address newOwner,
    uint256 parent1Id,
    uint256 parent2Id,
    string memory
  ) external whenNotPaused nonReentrant returns (uint256) {
    require(
      msg.sender == address(entityForgingContract),
      'unauthorized caller'
    );
+    uint256 newGeneration = getTokenGeneration(parent1Id) < currentGeneration - 1 ? currentGeneration : getTokenGeneration(parent1Id) + 1;

    /// Check new generation is not over maxGeneration
    require(newGeneration <= maxGeneration, "can't be over max generation");

    // Calculate the new entity's entropy
    (uint256 forgerEntropy, uint256 mergerEntropy) = getEntropiesForTokens(
      parent1Id,
      parent2Id
    );
    uint256 newEntropy = (forgerEntropy + mergerEntropy) / 2;

    // Mint the new entity
    uint256 newTokenId = _mintNewEntity(newOwner, newEntropy, newGeneration);

    return newTokenId;
  }
```
