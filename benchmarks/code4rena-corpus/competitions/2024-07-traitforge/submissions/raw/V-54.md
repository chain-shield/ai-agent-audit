# Vulnerability details

## Impact
The age of NFT could constantly being zero, results in smaller nuke factor and nuke less funds.

## Proof of Concept
The NFT age could be constantly zero, as the `perfomanceFactor` in `calculateAge()` function is zero if last digit of token entropy is zero:

```solidity
File: contracts\NukeFund\NukeFund.sol
118:   function calculateAge(uint256 tokenId) public view returns (uint256) {
     ...
126:     uint256 perfomanceFactor = nftContract.getTokenEntropy(tokenId) % 10; // <= perfomanceFactor could be zero
127: 
128:     uint256 age = (daysOld *
129:       perfomanceFactor *
130:       MAX_DENOMINATOR *
131:       ageMultiplier) / 365; // add 5 digits for decimals
132:     return age;
133:   }
```

The `perfomanceFactor` is derived from the last digit of the token entropy, which can be zero. This results in the `age` being calculated as zero, regardless of how long the user holds NFT.

Therefore, the calculated nuke factor is smaller than intended because it can not be adjusted [based on the NFT age](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L147-L148).

As the claimable funds is calculated [based on the nuke factor](https://github.com/code-423n4/2024-07-traitforge/blob/main/contracts/NukeFund/NukeFund.sol#L166-L167), users receive less funds.
