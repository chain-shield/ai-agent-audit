# Vulnerability details



### Vulnerability details 
The `TraitForgeNft::_incrementGeneration()` function is responsible for incrementing the generation when certain conditions are met. and the condition neccesary for this generation Advancement was for  `generationMintCounts[currentGeneration] >= maxTokensPerGen` , then couple lines below this check there is a call to `entropyGenerator.initializeAlphaIndices()`, a function from `EntropyGenerator.sol`. This function is restricted by the onlyOwner modifier, meaning it can only be called by the owner of the `EntropyGenerator` contract. The sponsor's plan is for their multisig wallet to be the owner of EntropyGenerator.sol. Consequently, TraitForgeNft will be unable to call `initializeAlphaIndices()` because it is not the owner of the contract.

### Impact
* This crucial function named `_incrementGeneration()` are also used to increment generations in most important contract functions like `_mintInternal, mintToken, forge` meaning that the  protocol will be unable to start the next generation after the first generation is completed, halting the minting process and preventing the progression of the contract's intended functionality.

### Proof of Concept
* Deploy EntropyGenerator.sol with the sponsor's multisig wallet as the owner.
* Call `mintToken()` to mint tokens, which internally calls `_mintInternal()`.
* `_mintInternal()` checks if the current generation has reached `maxTokensPerGen` and calls `_incrementGeneration()` if true.
* `_incrementGeneration()` attempts to call `initializeAlphaIndices()` in EntropyGenerator.sol.
* The call to `initializeAlphaIndices()` fails because `TraitForgeNft` is not the owner of EntropyGenerator.sol.
* The transaction reverts, and the currentGeneration remains unchanged.

### Tool Used
* manual review


### Recommended Mitigation
To resolve this issue, implement one of the following solutions

1. Make `TraitForgeNft.sol` the owner of `EntropyGenerator.sol`. or 
2. use `onlyAllowedCaller()` modifier instead of `onlyOwner` modifier which is already designed to be callable only by `TraitForgeNft`.
