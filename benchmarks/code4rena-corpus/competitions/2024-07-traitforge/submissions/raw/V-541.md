# Vulnerability details

## Impact
`EntropyGenerator::writeEntropyBatch1` and `EntropyGenerator::writeEntropyBatch2` check if `pseudoRandomValue` is not 999999, but don't check if `pseudoRandomValue` contain 999999. the `pseudoRandomValue` can have up to 78 digits, If six of them are consecutive nines, and the extracted entropy coincides with this 999999 number, a user will have “the Golden God”, which is not desirable as it should be only one "Golden God" per generation, and it's giving in `getEntropy` function if `slotIndex` and `numberIndex` match with `slotIndexSelectionPoint` and `numberIndexSelectionPoint` respectively.

## Proof of Concept
In `EntropyGenerator.sol`, the `writeEntropyBatch1` and `writeEntropyBatch2` functions check:
```
require(pseudoRandomValue != 999999, "Invalid random value");
```
This check revert only if pseudoRandomValue = 999999
However, this check doesn't prevent `pseudoRandomValue` from containing 999999 within its digits.
For example pseudoRandomValue = 34857349583275982375928752983475823947582347582347583947583947589347999999;
Then when we get the entropy via `getEntropy` function it will extract the "999999" number.

## Recommended Mitigation Steps
1. Implement a more robust check in `writeEntropyBatch1` and `writeEntropyBatch2`:
```
require(!_contains999999(pseudoRandomValue), "Invalid random value");
```
2. Add a helper function to check for 999999 within the number:
```
function _contains999999(uint256 value) internal pure returns (bool) {
   //Add logic here
}
```
