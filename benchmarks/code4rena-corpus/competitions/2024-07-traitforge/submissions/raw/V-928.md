# Vulnerability details

The contract uses `transferFrom` instead of `safeTransferFrom` for ERC721 transfers, which may cause issues with certain NFT implementations.

## Impact
Using `transferFrom` instead of `safeTransferFrom` can lead to:

Tokens being sent to contracts that don't support ERC721, potentially causing permanent loss of NFTs.
Incompatibility with certain NFT implementations that expect `safeTransferFrom` to be used.
Bypassing of important checks and hooks that are part of the `safeTransferFrom` flow.

This could result in financial losses for users if their NFTs become inaccessible or are sent to incompatible addresses.

## Proof of Concept
If an NFT is transferred to a contract address that doesn't implement `onERC721Received`:

The transfer will succeed using `transferFrom`.
The receiving contract won't be able to handle or transfer the NFT.
The NFT could become permanently stuck or lost.

## Tools Used
Manual review

## Recommended Mitigation Steps
Replace all instances of `transferFrom` with `safeTransferFrom` for ERC721 transfers.
Ensure that the contract handles the return value of `safeTransferFrom` correctly.
If there's a specific reason to use `transferFrom`, document it clearly and ensure that the risks are mitigated through other means.
