# Vulnerability details

## Impact

A vulnerability exists in the `TraitForgeNft` contract. Forging NFTs with the same parent ID can be exploited by malicious users to trigger multiple invocations of the `nuke` function, leading to repeated withdrawals from the `NukeFund.sol` contract. This poses a significant risk of draining the `NukeFund` and disrupting the game's economic balance.

## Proof of Concept

1. **Preparation for Exploit:** A malicious user acquires multiple NFTs using different accounts.
2. **Repeated Forging:** The attacker uses these NFTs to forge new ones repeatedly across their accounts until reaching the maximum `ForgePotential`.
3. **Shared Nuke Factor:** Since the forgings utilize the same parent IDs, the resulting NFTs share the same `NukeFactor`.
4. **Exploiting Cooldown:** After the minimum holding period for the NFTs passes, the attacker can "nuke" (withdraw funds) from all NFTs concurrently due to their identical `NukeFactor`.

This coordinated action triggers numerous withdrawals from the `NukeFund.sol` contract. Depending on the number of forged NFTs, this exploit can potentially deplete the entire `NukeFund`.


The current system allows forging NFTs with identical parent IDs. This enables attackers to exploit the shared `NukeFactor` and trigger repeated withdrawals, jeopardizing the financial stability of the `NukeFund.sol` contract.

## Tools Used
Manual review

## Recommended Mitigation Steps
To mitigate this risk, it's essential to implement one or both of the following measures:

1. **Prevent Duplicate Forging:** Implement a mechanism to prevent the forging of NFTs with the same parent IDs. This ensures variation and prevents malicious exploitation of shared `NukeFactor` values.
2. **Cooldown on Parent IDs:** Introduce a cooldown period after forging an NFT with a specific parent ID. This cooldown restricts the ability to re-forge using that parent ID within a designated timeframe, making it harder for attackers to rapidly exploit the system.

By implementing these recommendations, the vulnerability is addressed, and the risk of draining the `NukeFund.sol` contract through repetitive forging with the same parent IDs is mitigated.
