# Vulnerability details

## Details
The `mintWithBudget` is used to mint multiple entities at a time with the given amount provided by the user, but the function can be used only for generation 1, and once generation changes to > 1, it can't be used due to an irrelevant check - `_tokenIds < maxTokensPerGen`

## Impact
Users will face a DoS calling the `mintWithBudget` function for the generation > 1, due to the irrelevant check.

## Proof of Concept
The function is as below:
```solidity
  function mintWithBudget(
    bytes32[] calldata proof
  )
    public
    payable
    whenNotPaused
    nonReentrant
    onlyWhitelisted(proof, keccak256(abi.encodePacked(msg.sender)))
  {
    uint256 mintPrice = calculateMintPrice();
    uint256 amountMinted = 0;
    uint256 budgetLeft = msg.value;

@>  while (budgetLeft >= mintPrice && _tokenIds < maxTokensPerGen) {
      _mintInternal(msg.sender, mintPrice);
      amountMinted++;
      budgetLeft -= mintPrice;
      mintPrice = calculateMintPrice();
    }
    if (budgetLeft > 0) {
      (bool refundSuccess, ) = msg.sender.call{ value: budgetLeft }('');
      require(refundSuccess, 'Refund failed.');
    }
  }
```
- Here, there is a while loop check, where it will continue to mint as long as the budget left covers the mint price, and along with that it checks that the current token id is less than mag token per generation.
- But here max token per generation is `10,000`, and as soon as token id reaches 10,000 which will occur at the end of Gen 1, resulting in a DoS to `mintWithBudget` when it is called any generation after Gen 1.
- As for every generation `x` (x > 1), the tokenId will be `>=` maxTokensPerGen, resulting in a DoS to `mintWithBudget` for every generation other than 1st.

## Recommended Mitigation Steps
Remove the irrelevant check - `_tokenIds < maxTokensPerGen`
