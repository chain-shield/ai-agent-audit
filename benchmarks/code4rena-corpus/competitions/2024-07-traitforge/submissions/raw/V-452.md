# Vulnerability details

## Impact
A generation might not have a single NFT with entropy of 999999

## Proof of Concept
Each generation must have a single NFT with an entropy of 999999. This is the scenario where we get that entropy:
```solidity
if (slotIndex == slotIndexSelectionPoint && numberIndex == numberIndexSelectionPoint) {
      return 999999;
    }
```
The selection points are computed like this:
```solidity
uint256 slotIndexSelection = (hashValue % 258) + 512;
uint256 numberIndexSelection = hashValue % 13;
```
We will ignore the hash value as there is nothing of significance we can see there. However, we can see that the maximum value for `slotIndexSelectionPoint` is 769 (hashValue % 258 will equal at most 257 due to how the modulo operator works) and the maximum value of `numberIndexSelection` will be 12.

There are slot indexes and number indexes. We can imagine that each slot index has multiple number indexes. We go over each number index for a slot and afterwards, we proceed to the next slot index:
```solidity
    if (currentNumberIndex >= maxNumberIndex - 1) {
      currentNumberIndex = 0;
      if (currentSlotIndex >= maxSlotIndex - 1) {
        currentSlotIndex = 0;
      } else {
        currentSlotIndex++;
      }
    } else {
      currentNumberIndex++;
    }
```
We do 13 number index passes for each slot index (0 to 12) and there are 770 slots (0 to 769). Thus, the total iterations we do are $770 * 13 = 10010$. The issue is that a generation can only have 10000 NFTs. Thus, if the iterations we have to do to reach the selection points are more than 10000, we won't be able to reach them for that generation, thus no 999999 entropy NFT. 

From earlier, we saw that the maximum number and slot selection indexes are 769 and 12. These selection points would be more than enough to do over 10000 iterations, 10010 in this case which is the maximum amount of iterations we can do (note that for 769 and 12 indexes, we do 770 * 13 iterations, that's how we achieve 10010).

Thus, if the slot selection index is the maximum of 769 and the number index is 3 and over, we get over 10000 iterations and there won't be a 999999 entropy NFT.

For the POC, I have created a Foundry project, changed some variables from private to public and most importantly, created a function to set the selection points as they are otherwise pseudo random and would be hard to set. Here is that function, created in `EntropyGenerator.sol`:
```solidity
  function setIndices(uint256 a, uint256 b) public {
    slotIndexSelectionPoint = a;
    numberIndexSelectionPoint = b;
  }
```

import { Test, console } from '../lib/forge-std/src/Test.sol';

  DevFund public devFund;
  Airdrop public airdrop;
  TraitForgeNft public traitForgeNft;
  EntityForging public entityForging;

  uint256[] public tokenIdsWith99999Entropy;

    vm.startPrank(owner);
    devFund = new DevFund();
    entropyGenerator = new EntropyGenerator(owner);

    traitForgeNft.setEntropyGenerator(address(entropyGenerator));
    entropyGenerator.setAllowedCaller(address(traitForgeNft));
    traitForgeNft.setAirdropContract(address(airdrop));

    deal(minter, 100000000000000000000000000000000000000000000e18);

    entropyGenerator.writeEntropyBatch1();
    entropyGenerator.writeEntropyBatch2();
    entropyGenerator.writeEntropyBatch3();

    bytes32[] memory proof = new bytes32[](1);
    vm.warp(block.timestamp + 1 weeks);

    entropyGenerator.setIndices(769, 3); // Custom made function to set the selection points as they are pseudo random otherwise

    vm.startPrank(minter);

        if (i == 10000)  assertEq(traitForgeNft.currentGeneration(), 1); // First gen

        if (i == 10001) assertEq(traitForgeNft.currentGeneration(), 2); // We successfully minted all tokens for the first gen, now we are at 2nd

        traitForgeNft.mintToken{ value: minter.balance }(proof);

        if (traitForgeNft.getTokenEntropy(traitForgeNft._tokenIds()) == 999999) tokenIdsWith99999Entropy.push(traitForgeNft._tokenIds()); // Push if 999_999
    }
    vm.stopPrank();

    assertEq(tokenIdsWith99999Entropy.length, 0); // Still no tokens with 999_999 entropy
  }

## Recommended Mitigation Steps
I believe the developer has in mind what went wrong here. My suggestion would be to never do more iterations that the maximum NFTs per generation, this would fix the issue.
