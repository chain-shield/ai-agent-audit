# Vulnerability details

## Impact
When a listing is canceled, the corresponding entry in the `listedTokenIds` mapping is not removed. This can cause problems if the same token is listed again or if other functions rely on the `listedTokenIds` mapping. 

## Proof of Concept
The [`cancelListing` function](https://github.com/code-423n4/2024-07-traitforge/blob/279b2887e3d38bc219a05d332cbcb0655b2dc644/contracts/EntityTrading/EntityTrading.sol#L94-L109) looks like this:

```solidity
function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant {
    Listing storage listing = listings[listedTokenIds[tokenId]];

    // check if caller is the seller and listing is active
    require(
        listing.seller == msg.sender,
        'Only the seller can cancel the listing.'
    );
    require(listing.isActive, 'Listing is not active.');

    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer the nft back to seller

    delete listings[listedTokenIds[tokenId]]; // mark the listing as inactive or delete it

    emit ListingCanceled(tokenId, msg.sender);
}
```

Here, the `listedTokenIds` mapping is not updated when a listing is canceled, leading to an inconsistent state.

## Recommended Mitigation Steps
Update the `cancelListing` function to also remove the entry from the `listedTokenIds` mapping when a listing is canceled.
```solidity
function cancelListing(uint256 tokenId) public whenNotPaused nonReentrant {
    uint256 listingIndex = listedTokenIds[tokenId];
    Listing storage listing = listings[listingIndex];

    // check if caller is the seller and listing is active
    require(
        listing.seller == msg.sender,
        'Only the seller can cancel the listing.'
    );
    require(listing.isActive, 'Listing is not active.');

    nftContract.transferFrom(address(this), msg.sender, tokenId); // transfer the nft back to seller

    delete listings[listingIndex]; // mark the listing as inactive or delete it
    delete listedTokenIds[tokenId]; // remove the entry from listedTokenIds mapping

    emit ListingCanceled(tokenId, msg.sender);
}
```

This will ensure that both the `listings` and `listedTokenIds` mappings are properly updated when a listing is cancelled.
