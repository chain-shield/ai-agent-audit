# Vulnerability details

## Issue
The _delegateCall() function is called with basic validation on leverParams.auxAction.args.length, ensuring that the call is not made with empty data. However, there is still a risk of an arbitrary jump if the target address (poolAction) or the data being passed can be manipulated, even with a success/failure check present. While the function handles failed calls properly, it does not fully mitigate the risk of arbitrary code execution or jumps to unintended contract functions.

## Proof of Concept
In the following code, delegatecall is used to execute code in the context of the calling contract, and although auxAction.args.length is checked, the target address and data passed could still be manipulated:


if (leverParams.auxAction.args.length != 0) {
    _delegateCall(address(poolAction), abi.encodeWithSelector(poolAction.join.selector, leverParams.auxAction));
}
While success is checked in the function, there is no comprehensive validation of the target address (poolAction) or the function being called.

## Mitigation
Add stricter validation to ensure that the target address (poolAction) is trusted and that the data being passed is from a verified, known source.
