# Vulnerability details

## Issue
The _updateRewardIndex() function can be called multiple times externally, and it performs several critical operations, including external calls to redeemRewards() and balance updates in rewardState. However, there is no reentrancy protection in place, making the function vulnerable to potential reentrancy attacks. Since this function handles significant state changes and external interactions, it presents a considerable risk if exploited.

## Proof of Concept
External Call: The function calls market.redeemRewards(address(vault)), an external contract interaction that could be exploited to reenter the contract if called again before state changes are completed.
State Changes: The function modifies critical contract state variables like rewardState and lastBalance after performing the external call, which makes it vulnerable to manipulation during a reentrancy attack.
Potential Attack: A malicious contract could call _updateRewardIndex() recursively via the external call, exploiting the lack of reentrancy protection to manipulate state changes and potentially claim excess rewards.

## Mitigation
Implement a ReentrancyGuard to ensure that the function cannot be called recursively.
Use the Checks-Effects-Interactions pattern to prevent reentrancy vulnerabilities by applying state changes before external calls.
