# Vulnerability details

### Overview

The SwapAction contract contains a payable function (`transferAndSwap`) without a corresponding withdraw or sweep function, potentially leading to locked Ether in the contract.

### Description

The `transferAndSwap` function in the `SwapAction` contract is marked as `payable`, allowing it to receive Ether. However, the contract lacks a mechanism to withdraw or sweep any Ether sent to this function. The `SwapAction` contract is designed to facilitate token swaps on various decentralized exchange protocols directly from within the contract. It supports multiple protocols such as Balancer, Uniswap V3, Pendle, and Kyber, allowing users to perform token swaps using these platforms through a single interface,  but it doesn't seem to utilize the received Ether in its core logic. This design could lead to Ether becoming permanently locked in the contract if sent accidentally or intentionally.

### Code Location

File: `SwapAction.sol`
Function: `transferAndSwap`
```solidity
function transferAndSwap(
    address from,
    PermitParams calldata permitParams,
    SwapParams calldata swapParams
) external payable returns (uint256)
```

### Impact

The presence of a payable function without a withdraw mechanism in this swap contract creates a  risk of permanent Eth loss. Any funds sent to `transferAndSwap`, whether by mistake or intentionally, become locked in the contract. The lack of Ether-handling error checks or refund mechanisms exacerbates the issue. 
## Recommended Mitigations

1.  Withdraw Mechanism Implementation

   - Implement a withdraw function to allow authorized parties to retrieve Ether from the contract.
   - Example:
     ```solidity
     function withdrawEther(address payable recipient, uint256 amount) external onlyOwner {
         require(address(this).balance >= amount, "Insufficient balance");
         recipient.transfer(amount);
     }
     ```
   - Ensure to implement proper access control (e.g., `onlyOwner` modifier) on the withdraw function.

The presence of a payable function without a withdraw mechanism in the SwapAction contract represents a potential risk of locking Eth, implement a withdraw function that can mitigate the risk of this issue.
