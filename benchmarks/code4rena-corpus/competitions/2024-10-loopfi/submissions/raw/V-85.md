# Vulnerability details

## Proof of Concept
In the modifyCollateralAndDebt() function, deltaCollateral is scaled using tokenScale before adjusting the user's collateral balance. However, the scaling logic may cause a precision loss in certain cases, especially when tokenScale and the decimals of the token differ, or when dealing with large amounts.

```
if (deltaCollateral > 0) {
    uint256 amount = wmul(deltaCollateral.toUint256(), tokenScale);
    token.safeTransferFrom(collateralizer, address(this), amount);
} else if (deltaCollateral < 0) {
    uint256 amount = wmul(abs(deltaCollateral), tokenScale);
    token.safeTransfer(collateralizer, amount);
}

```
When deltaCollateral is multiplied by tokenScale, it introduces potential precision mismatches that could inaccurately adjust a user's collateral balance. This can result in under-collateralized positions or improper handling of liquidations, which could destabilize the entire vault system.

The problem is magnified in scenarios with fractional collateral adjustments, leading to accumulated imbalances over time.


## Recommended Mitigation Steps
Implement more precise handling for deltaCollateral to ensure that the scaling mechanism maintains accuracy across all use cases.
Add validation checks or rounding mechanisms to ensure that no significant precision is lost during collateral adjustments.
Consider adding unit tests to verify collateral scaling in various edge cases, such as large token amounts or low-decimal tokens.
