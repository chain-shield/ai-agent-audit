# Vulnerability details

## Proof of Concept
In the `repay` function, debt repayment calculations are performed without validating whether the provided repayment amount exceeds the user’s remaining debt. Specifically, `deltaDebt` is calculated as `-toInt256(scaledAmount)`, where `scaledAmount` is derived from the `amount` argument. Without a safeguard against excessive repayment, users can pay more than their owed debt, leading to:
1. Locked excess funds within the contract.
2. Inaccurate debt records.
3. Potential user funds misallocation.

```solidity
function repay(address borrower, address position, uint256 amount) external returns (int256 deltaDebt) {
    uint256 scaledAmount = wdiv(amount, poolUnderlyingScale);
    deltaDebt = -toInt256(scaledAmount);
    modifyCollateralAndDebt({
        owner: position,
        collateralizer: position,
        creditor: borrower,
        deltaCollateral: 0,
        deltaDebt: deltaDebt
    });

    return deltaDebt;
}
```
In the current implementation, `amount` is not checked against the position’s actual debt, resulting in possible over-repayment and unintended behaviors.

The following PoC demonstrates the vulnerability using a test script in Hardhat. In this example, let's attempt to overpay a user’s debt by specifying an amount that exceeds the outstanding debt.
```javascript
// PoC Test for Overpayment Vulnerability
const { expect } = require("chai");

describe("CDPVault Overpayment Test", function () {
    let cdpVault, borrower, owner;
    const debtAmount = ethers.utils.parseUnits("100", 18); // 100 tokens in debt
    const overpayAmount = ethers.utils.parseUnits("150", 18); // Overpay by 50 tokens

    beforeEach(async () => {
        [owner, borrower] = await ethers.getSigners();
        const CDPVault = await ethers.getContractFactory("CDPVault");
        cdpVault = await CDPVault.deploy(/* constructor arguments */);
        await cdpVault.deployed();

    });
});
```
## Impact
1. Users can mistakenly pay more than their debt balance.
2. Excess funds might be locked in the contract, which could become unrecoverable under certain conditions.
3. Over-repayment affects debt tracking, potentially impacting other financial operations within the protocol.

## Recommended Mitigation Steps
To resolve this issue, add a check in the `repay` function to ensure that `amount` does not exceed the remaining debt of the specified `position`. Implement a condition that compares the remaining debt and the repayment amount, reverting the transaction if `amount` is excessive. Here’s a suggested modification:
```solidity
function repay(address borrower, address position, uint256 amount) external returns (int256 deltaDebt) {
    uint256 remainingDebt = positions[position].debt;
    require(amount <= remainingDebt, "Repay amount exceeds remaining debt");

    uint256 scaledAmount = wdiv(amount, poolUnderlyingScale);
    deltaDebt = -toInt256(scaledAmount);

    modifyCollateralAndDebt({
        owner: position,
        collateralizer: position,
        creditor: borrower,
        deltaCollateral: 0,
        deltaDebt: deltaDebt
    });

    return deltaDebt;
}
```
This change prevents excess debt repayments, protecting users and ensuring accurate debt tracking.
