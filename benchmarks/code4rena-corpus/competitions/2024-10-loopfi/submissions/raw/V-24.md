# Vulnerability details

### Proof of Concept

When conducting swaps, the option to swap through Kyber MetaAggregationRouterV2 is made available by the `SwapProtocol.KYBER` enum. When the swap is conducted, `kyberSwap` is called, with the asset, amount and payload passed in. However, external/public functions in kyberRouter return two uint256 parameters, but the decoded result only attempts to return one, which will cause an error upon decoding.

As can be seen from the [router](https://etherscan.io/address/0x6131b5fae19ea4f9d964eac0408e4408b66337b5#code) on etherscan, the swap functions, regardless of the payload in use, always return two uint256 parameters, `returnAmount` and `gasUsed`.

```solidity
  function swapGeneric(SwapExecutionParams calldata execution)
    external
    payable
    returns (uint256 returnAmount, uint256 gasUsed)
  {
```

```solidity
  function swap(SwapExecutionParams calldata execution)
    external
    payable
    returns (uint256 returnAmount, uint256 gasUsed)
  {
```

```solidity
  function swapSimpleMode(
    IAggregationExecutor caller,
    SwapDescriptionV2 memory desc,
    bytes calldata executorData,
    bytes calldata clientData
  ) public returns (uint256 returnAmount, uint256 gasUsed) {
```

So when `kyberSwap` is called, the `result` data is attempted to be decoded but being that two parameters are returned, instead of the expected one, the decoding fails, reverting the entire transaction.

```solidity
    function kyberSwap(address assetIn, uint256 amountIn, bytes memory payload) internal returns (uint256) {
        IERC20(assetIn).forceApprove(address(kyberRouter), amountIn);
        (bool success, bytes memory result) = kyberRouter.call(payload);
        if (!success) _revertBytes(result);
        return abi.decode(result, (uint256)); // @audit
    } 
```
### Recommended Mitigation Steps

Decode the parameters properly.
