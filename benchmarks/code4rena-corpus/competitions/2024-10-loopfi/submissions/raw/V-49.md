# Vulnerability details

## Proof of Concept
The `RewardManagerAbstract` contract manages the reward distribution for users based on their collateral amounts and associated reward indices. The method `_distributeRewardsPrivate` is responsible for distributing rewards to users based on the reward indices for various tokens. However, the logic does not adequately check whether the `userShares` are zero, which can lead to issues in reward calculation.

The following code snippet from the `_distributeRewardsPrivate` function illustrates the vulnerability:
https://github.com/code-423n4/2024-10-loopfi/blob/d219f0132005b00a68f505edc22b34f9a8b49766/src/pendle-rewards/RewardManagerAbstract.sol#L52-L79
```solidity
function _distributeRewardsPrivate(
    address user,
    uint256 collateralAmountBefore,
    address[] memory tokens,
    uint256[] memory indexes
) private {
    assert(user != address(0) && user != address(this));

    uint256 userShares = collateralAmountBefore; // Potentially zero
    for (uint256 i = 0; i < tokens.length; ++i) {
        address token = tokens[i];
        uint256 index = indexes[i];
        uint256 userIndex = userReward[token][user].index;

        if (userIndex == 0) {
            userIndex = INITIAL_REWARD_INDEX.Uint128();
        }

        if (userIndex == index) continue;

        uint256 deltaIndex = index - userIndex;

        uint256 rewardDelta = userShares.mulDown(deltaIndex); // Potentially leads to incorrect reward
        uint256 rewardAccrued = userReward[token][user].accrued + rewardDelta;
        userReward[token][user] = UserReward({index: index.Uint128(), accrued: rewardAccrued.Uint128()});
    }
}
```
To demonstrate the vulnerability, let's create a test scenario using Hardhat. The test will involve invoking the `_distributeRewardsPrivate` function with a `collateralAmountBefore` of zero, which should ideally prevent reward calculations but does not due to the lack of validation.
```javascript
const { expect } = require("chai");
const { ethers } = require("hardhat");

describe("RewardManagerAbstract Tests", function () {
    let RewardManager, rewardManager, user;

    beforeEach(async () => {
        const RewardManagerFactory = await ethers.getContractFactory("RewardManagerAbstract");
        rewardManager = await RewardManagerFactory.deploy();
        await rewardManager.deployed();
        
        [user] = await ethers.getSigners();
    });

    it("should incorrectly calculate rewards when collateralAmountBefore is zero", async () => {
        const tokens = ["0xToken1", "0xToken2"];
        const indexes = [1, 2];

        // Assume initial state with zero shares
        await rewardManager._distributeRewardsPrivate(user.address, 0, tokens, indexes);

        // Check user rewards - it should not have changed but can have side effects
        const userReward1 = await rewardManager.userReward(tokens[0], user.address);
        const userReward2 = await rewardManager.userReward(tokens[1], user.address);
        
        // Validate that accrued rewards should remain unchanged
        expect(userReward1.accrued).to.equal(0);
        expect(userReward2.accrued).to.equal(0);
    });
});
```
Users may receive inaccurate rewards due to the lack of checks when `collateralAmountBefore` is zero.
An attacker could exploit this vulnerability by manipulating conditions to prevent other users from receiving accurate rewards, effectively hindering the reward distribution system.

## Recommended Mitigation Steps
Add checks in the `_distributeRewardsPrivate` function to ensure `collateralAmountBefore` is greater than zero before proceeding with reward calculations.
```solidity
require(collateralAmountBefore > 0, "Collateral amount must be greater than zero");
```
