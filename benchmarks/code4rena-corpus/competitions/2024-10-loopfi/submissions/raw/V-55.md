# Vulnerability details

## Proof of Concept
In the test_moveFunds_erc20_no_balance test, the call to moveFunds with a zero balance did not revert, even though the test expected a revert.

The issue lies in the _moveFunds() function in the Treasury contract. This function doesn’t check if the token balance is zero before attempting a transfer. Consequently, it emits an event (Treasury__moveFunds) without reverting, even when there are no tokens to transfer.

test_moveFunds_erc20_no_balance test function used added to the Treasury.t.sol contract:

function test_moveFunds_erc20_no_balance() public {
    // Set the balance of the treasury to zero
    uint256 amount = 0;  // Edge case: no balance in the treasury
    address newTreasury = vm.addr(4);
    // Ensure the balance is indeed zero before we proceed
    assertEq(mockWETH.balanceOf(address(treasury)), amount);
    // Set fundAdmin as the caller
    vm.prank(fundAdmin);
    // Expect revert since there are no funds to move
    vm.expectRevert("Treasury: no tokens to transfer");
        // Attempt to move funds (this should revert)
    treasury.moveFunds(newTreasury, IERC20(address(mockWETH)));
    // Ensure that the new treasury received no funds and the balance remains zero
    assertEq(mockWETH.balanceOf(newTreasury), 0);
    assertEq(mockWETH.balanceOf(address(treasury)), 0);
}

Explanation:
This test explicitly ensures that moveFunds fails when trying to transfer a zero balance, matching the expected behavior of the ERC20 transfer function, which reverts if the transfer amount exceeds the balance.

The failure in your test_moveFunds_erc20_no_balance test indicates that the function call to moveFunds with a zero balance did not revert, even though we expected it to revert with the error "ERC20: transfer amount exceeds balance".

The _moveFunds function in the Treasury contract does not actually trigger a revert if there's no balance to transfer. The contract emits an event and continues executing, even with a zero balance.
## Recommended Mitigation Steps
How to address this:
1. Add a Zero Balance Check in the Treasury Contract: 
If you want moveFunds to revert when there is no balance, you can modify the Treasury contract to check the balance before attempting the transfer.

Modify the Treasury Contract to Revert on Zero Balance add a balance check to moveFunds:
require(amount > 0, "Treasury: no tokens to transfer"); // Add this check

function _moveFunds(address treasury, IERC20 token) internal {
    uint256 amount = token.balanceOf(address(this));
    require(amount > 0, "Treasury: no tokens to transfer"); // Add this check to line 70
    if (amount > 0) {
        SafeERC20.safeTransfer(token, treasury, amount);
    }
}

By adding the require statement, the function will revert if there are no tokens available to transfer, preventing unnecessary events and calls.
