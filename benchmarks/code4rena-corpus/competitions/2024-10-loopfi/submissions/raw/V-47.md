# Vulnerability details

```solidity
function unstake(address receiver) external {
    UserCooldown storage userCooldown = cooldowns[msg.sender];
    uint256 assets = userCooldown.underlyingAmount;

    if (block.timestamp >= userCooldown.cooldownEnd || cooldownDuration == 0) {
        userCooldown.cooldownEnd = 0;
        userCooldown.underlyingAmount = 0;
        silo.withdraw(receiver, assets);
    } else {
        revert InvalidCooldown();
    }
}
```
## Description:
The `unstake` function allows a user to bypass the `cooldown` period if the cooldown duration is set to `0`. This essentially nullifies the security and staking logic that the cooldown is supposed to enforce. Attackers or misconfigured users could withdraw their assets prematurely, defeating the purpose of a cooldown period.

## Impact:
If the cooldown duration is set to zero, users can unstake their tokens immediately, violating staking and vesting rules, and increasing the risk of gaming the system by withdrawing tokens without any delay.

## Proof Of Concept:
A user triggers the cooldown but finds that cooldown duration is set to 0.
They can call `unstake()` and withdraw assets immediately, bypassing any intended locking period.
This allows them to unstake and re-stake at will, nullifying the security provided by the cooldown.

## Tool used:
Manual Review.

## Recommended mitigation:
Do not allow the cooldown duration to be set to `0` unless the entire cooldown feature is disabled and carefully documented. Alternatively, implement stricter conditions in `unstake()` that prevent withdrawal until a sufficient cooldown period has passed.
