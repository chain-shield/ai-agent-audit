# Vulnerability details

## Proof of Concept
In Solidity, precision loss occurs when integer division results in fractional values that are truncated. The vulnerability arises in the code involving `RAY` and `SECONDS_PER_YEAR`, where small values are divided, resulting in a loss of precision. The contract assumes that the high precision afforded by `RAY` (1e27) would mitigate these issues, but in certain edge cases, particularly when the numerator is small, significant precision can still be lost.

```solidity
uint192 constant RAY_DIVIDED_BY_PERCENTAGE = uint192(RAY / PERCENTAGE_FACTOR);

function cumulativeIndexSince(
    uint192 cumulativeIndexLU,
    uint16 rate,
    uint256 lastQuotaRateUpdate
) internal view returns (uint192) {
    return
        uint192(
            uint256(cumulativeIndexLU) +
                (RAY_DIVIDED_BY_PERCENTAGE * (block.timestamp - lastQuotaRateUpdate) * rate) /
                SECONDS_PER_YEAR
        ); // U:[QL-1]
}
```
The division involving `RAY_DIVIDED_BY_PERCENTAGE` and `SECONDS_PER_YEAR (31536000 for a non-leap year) can result in significant truncation when the values being multiplied, such as (`block.timestamp - lastQuotaRateUpdate`) or `rate`, are small. This leads to a loss of precision in interest accrual.
The following code provides a minimal reproducible example demonstrating the precision loss vulnerability. It shows how interest accrual over small periods leads to precision loss when dividing by large constants like `RAY`.
```solidity
// Vulnerable interest accrual calculation
function calcInterestAccrual(
    uint192 cumulativeIndexLU,
    uint16 rate,
    uint256 lastUpdate
) public view returns (uint192) {
    return cumulativeIndexSince(cumulativeIndexLU, rate, lastUpdate);
}
```
Let's create a test in Hardhat to prove the vulnerability. The test simulates a scenario where the rate and time delta are small enough to cause significant precision loss.
```javascript
const { expect } = require("chai");
const { ethers } = require("hardhat");

describe("Precision Loss Vulnerability Test", function () {
  let contract;

  before(async function () {
    const QuotaContract = await ethers.getContractFactory("QuotaContract");
    contract = await QuotaContract.deploy();
  });

  it("Should lose precision for small rate and time deltas", async function () {
    const initialIndex = ethers.BigNumber.from("1000000000000000000000000000"); // 1 RAY
    const rate = 1; // Small rate
    const lastUpdate = (await ethers.provider.getBlock()).timestamp - 1; // 1 second ago

    // Call the vulnerable function
    const newIndex = await contract.calcInterestAccrual(initialIndex, rate, lastUpdate);

    console.log("Old Index:", initialIndex.toString());
    console.log("New Index:", newIndex.toString());

    expect(newIndex).to.be.equal(initialIndex); // Precision lost, no noticeable change
  });
});
```

In the test, even though a small rate and a 1-second time delta were used, the cumulative index (`newIndex`) remained unchanged. This demonstrates that the division by large constants like `RAY` and `SECONDS_PER_YEAR` causes truncation, leading to precision loss, particularly in cases with small numerators.

The inaccuracy in cumulative index calculation could result in incorrect interest accrual, potentially leading to losses or overestimations for users.
For systems relying on quota revenue, the imprecision in interest updates could cause a mismatch in the expected versus actual revenue.
Users might experience discrepancies between expected and actual returns, leading to a loss of trust in the contract.
This vulnerability could lead to financial inaccuracies, especially in contracts dealing with long-term interest accrual or small interest rates. However, the severity is rated as medium because it typically only affects edge cases where small values are involved.

## Recommended Mitigation Steps
Multiply the numerator before performing the division. This can help maintain precision by minimizing the loss caused by truncation.
```solidity
function cumulativeIndexSince(
    uint192 cumulativeIndexLU,
    uint16 rate,
    uint256 lastQuotaRateUpdate
) internal view returns (uint192) {
    return
        uint192(
            uint256(cumulativeIndexLU) +
                ((RAY_DIVIDED_BY_PERCENTAGE * (block.timestamp - lastQuotaRateUpdate) * rate * 1e9) /
                (SECONDS_PER_YEAR * 1e9)) // Extra multiplication
        );
}
```
