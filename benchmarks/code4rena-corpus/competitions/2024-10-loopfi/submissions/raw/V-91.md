# Vulnerability details


## Impact
The `RewardManager` contract fails to verify that the token balance has decreased after claiming rewards. This oversight could allow malicious actors to manipulate the reward distribution, potentially leading to inflated reward calculations and unfair distribution of rewards among users.

## Proof of Concept
The vulnerability is present in the [`_updateRewardIndex`](https://github.com/code-423n4/2024-10-loopfi/blob/main/src/pendle-rewards/RewardManager.sol#L53-L86) function of the RewardManager contract:

```solidity
function _updateRewardIndex()
    internal
    virtual
    override
    returns (address[] memory tokens, uint256[] memory indexes)
{
    tokens = market.getRewardTokens();
    indexes = new uint256[](tokens.length);

    if (tokens.length == 0) return (tokens, indexes);

    if (lastRewardBlock != block.number) {
        // if we have not yet update the index for this block
        lastRewardBlock = block.number;

        uint256 totalShares = _rewardSharesTotal();
        // Claim external rewards on Market
        market.redeemRewards(address(vault));

        for (uint256 i = 0; i < tokens.length; ++i) {
            address token = tokens[i];

            // the entire token balance of the contract must be the rewards of the contract

            RewardState memory _state = rewardState[token];
            (uint256 lastBalance, uint256 index) = (_state.lastBalance, _state.index);

            uint256 accrued = IERC20(tokens[i]).balanceOf(vault) - lastBalance;

            if (index == 0) index = INITIAL_REWARD_INDEX;
            if (totalShares != 0) index += accrued.divDown(totalShares);

            rewardState[token] = RewardState({
                index: index.Uint128(),
                lastBalance: (lastBalance + accrued).Uint128()
            });

            indexes[i] = index;
        }
    } else {
        for (uint256 i = 0; i < tokens.length; i++) {
            indexes[i] = rewardState[tokens[i]].index;
        }
    }
}
```

The issue lies in the calculation of the `accrued` rewards:

```solidity
uint256 accrued = IERC20(tokens[i]).balanceOf(vault) - lastBalance;
```

This calculation assumes that the current balance will always be greater than or equal to the `lastBalance`. However, there's no check to ensure that the balance has actually increased after claiming rewards. 

A malicious actor could potentially exploit this by manipulating the token balance of the vault before the `_updateRewardIndex` function is called, leading to incorrect `accrued` values and consequently affecting the reward index calculations.
