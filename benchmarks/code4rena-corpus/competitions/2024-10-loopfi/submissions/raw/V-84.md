# Vulnerability details

## Proof of Concept
The _getTokenPrice() function retrieves token prices based on the index (0, 1, 2), corresponding to token0, token1, and token2. However, it doesn't properly validate the token addresses, and if the chainlinkOracle.spot(token) call is mishandled or returns the same price for any token, this could result in faulty price calculations.

```
function _getTokenPrice(uint256 index) internal view returns (uint256 price) {
    address token;
    if (index == 0) token = token0;
    else if (index == 1) token = token1;
    else if (index == 2) token = token2;
    else revert BalancerOracle__getTokenPrice_invalidIndex();

    return chainlinkOracle.spot(token);
}

```
The code does not ensure that the token addresses are correctly validated, which can lead to price mismatches or incorrect price feeds being used for different tokens.

This can have a severe impact on the system, especially in cases where incorrect prices are used to determine collateralization or liquidation thresholds, potentially allowing users to manipulate the protocol.

## Recommended Mitigation Steps
Implement strict validation of the token addresses when calling the external oracle to ensure that the correct price is returned for each token.
Add fallback mechanisms to ensure that incorrect or stale prices do not lead to faulty calculations in the liquidation process.
Consider adding unit tests to simulate edge cases where incorrect prices are returned to ensure the protocol handles these gracefully.
