# Vulnerability details

### **Summary**:
A front-running vulnerability exists in the `_updateBaseInterest()` function due to the improper reliance on `block.timestamp` for determining when to update the `lastBaseInterestUpdate` variable. An attacker can exploit this by calling the function just before the victim, preventing the victim’s transaction from executing the interest update logic.


### **Affected Function**: PoolV3.sol#L694

```solidity
function _updateBaseInterest(
  ...
) internal {
   ...
    uint256 lastBaseInterestUpdate_ = lastBaseInterestUpdate;
 ->   if (block.timestamp != lastBaseInterestUpdate_) {  // @audit-issue  Front-running
        _baseInterestIndexLU = _calcBaseInterestIndex(lastBaseInterestUpdate_).toUint128();
        lastBaseInterestUpdate = uint40(block.timestamp);
    }

   ...
}
```

### **Description**:

* The function relies on the condition `if (block.timestamp != lastBaseInterestUpdate_)` to determine whether to update the base interest. However, because `block.timestamp` remains the same within the same block, an attacker can front-run the victim's transaction by calling the function in the same block. This will update the `lastBaseInterestUpdate` to the current `block.timestamp`.

* As a result, when the victim’s transaction is processed within the same block, the condition `block.timestamp != lastBaseInterestUpdate_` will be `false`, and the interest update logic will be skipped, causing a failure to correctly update the base interest for the victim.

### **Steps to Reproduce**:
1. Attacker monitors for when a victim is about to call the `_updateBaseInterest()` function.
2. Attacker sends a transaction calling `_updateBaseInterest()` just before the victim's transaction is mined.
3. The attacker's transaction updates `lastBaseInterestUpdate` to the current `block.timestamp`.
4. The victim’s transaction is mined within the same block, but the `block.timestamp != lastBaseInterestUpdate_` condition fails.
5. As a result, the victim’s transaction skips the interest update logic.

### **Impact**:
- The victim’s transaction does not correctly update the base interest, potentially leading to incorrect interest rates and unfair financial outcomes.
- The attacker can repeatedly front-run the contract and prevent other users from updating the base interest, gaining an unfair advantage.
