# Vulnerability details

#### **Summary**
The `_amountWithWithdrawalFee` function has two critical issues:
1. **Division by Zero**: When `withdrawFee` equals `PERCENTAGE_FACTOR`, the denominator becomes zero, causing a transaction revert.
2. **Withdraw Fee Boundaries**: A high `withdrawFee` (close to `PERCENTAGE_FACTOR`) results in an abnormally large withdrawal amount, which may lead to unintended behavior.

#### Affected code:  PoolV3.sol#L929

```
    function _amountWithWithdrawalFee(uint256 amount) internal view returns (uint256) {
        return (amount * PERCENTAGE_FACTOR) / (PERCENTAGE_FACTOR - withdrawFee);
    }

```


#### **Impact**
- **Division by Zero**: Causes transaction failure.
- **Boundary Issue**: Allows abnormally large withdrawals, posing a risk to the contract’s balance.

#### **Proposed Fix**
1. Prevent division by zero:
   ```solidity
   require(withdrawFee < PERCENTAGE_FACTOR, "Withdraw fee exceeds or equals percentage factor");
   ```

2. Enforce maximum fee limits:
   ```solidity
   uint256 constant MAX_WITHDRAW_FEE = PERCENTAGE_FACTOR / 10; // 10% max fee
   require(withdrawFee <= MAX_WITHDRAW_FEE, "Withdraw fee exceeds maximum allowable value");
   ```
