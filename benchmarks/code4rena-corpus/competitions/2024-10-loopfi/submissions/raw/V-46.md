# Vulnerability details

```solidity
function moveFunds(address treasury, IERC20[] calldata tokens) external onlyRole(FUNDS_ADMINISTRATOR_ROLE) {
    uint256 len = tokens.length;
    for (uint256 i = 0; i < len; i++) {
        _moveFunds(treasury, tokens[i]);
    }
}
```

## Description:
The `moveFunds` function iterates over an arbitrary number of `ERC20` tokens provided in the tokens array and transfers each token to a new treasury address. If the array contains a large number of tokens, the function could become gas-intensive, potentially exceeding the block's gas limit. As a result, the transaction may fail, making it impossible to move funds when dealing with a significant number of tokens in a single call.

## Impact:
If the tokens array is excessively large, the gas required to complete the transaction will exceed the gas limit, resulting in a failed transaction. This could render the `moveFunds` function unusable for large sets of tokens, effectively causing a denial of service for transferring funds in bulk. The treasury might be left unable to move funds, increasing the risk of operational issues or disruptions.

## Proof of Concept (PoC):
A large number of `ERC20 `tokens (e.g., hundreds or thousands) are passed to `moveFunds`.
The contract loops through each token in the array.
Due to the gas cost of handling so many tokens, the transaction fails, and no funds are moved.

## Tool Used:
Manual Review.

## Recommended Mitigation:
 Introduce a mechanism to process tokens in batches, limiting the number of tokens transferred in a single transaction to avoid exceeding the gas limit.
 Refactor the loop to optimize gas consumption, for instance, by reducing unnecessary operations or combining multiple actions into one where possible.
 Consider moving token list handling off-chain to reduce the amount of on-chain computation required for fund transfers.
