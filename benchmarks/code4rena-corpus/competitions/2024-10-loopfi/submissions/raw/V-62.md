# Vulnerability details

## Overview

The `deposit` function in the Locking contract does not verify the actual amount of tokens transferred, leading to potential discrepancies between recorded deposits and actual token balances when interacting with certain ERC20 tokens.

## Description

The current implementation of the `deposit` function in the Locking contract assumes that the amount of tokens specified in the function call is always the amount actually transferred. However, some ERC20 tokens (like cUSDCv3) have special transfer logic where using `type(uint256).max` as the transfer amount results in transferring the entire balance of the sender.

This can lead to a situation where the contract records a deposit of `type(uint256).max` tokens, while only receiving a much smaller amount (the actual balance of the user). This discrepancy can potentially be exploited to withdraw more tokens than actually deposited, or cause other issues due to the inconsistent state of the contract.

Function: `deposit`

```solidity
function deposit(uint256 _amount) external {
    if (_amount == 0) revert AmountIsZero();

    deposits[msg.sender].amount += _amount;
    token.safeTransferFrom(msg.sender, address(this), _amount);

    emit Deposited(msg.sender, _amount);
}
```

## Impact

This vulnerability could potentially allow users to:

1. Withdraw more tokens than they actually deposited, leading to a drain of the contract's funds.
2. Cause an inconsistent state in the contract where the sum of recorded deposits doesn't match the actual token balance.
3. Interfere with other contract logic that relies on accurate deposit records.

    function transferFrom(address from, address to, uint256 amount) public virtual override returns (bool) {

## Recommended Mitigations

1. Implement a check to verify the actual amount of tokens transferred:

```solidity
function deposit(uint256 _amount) external {
    if (_amount == 0) revert AmountIsZero();
    if (_amount == type(uint256).max) revert AmountTooLarge();

    uint256 balanceBefore = token.balanceOf(address(this));
    token.safeTransferFrom(msg.sender, address(this), _amount);
    uint256 actualDeposit = token.balanceOf(address(this)) - balanceBefore;

    deposits[msg.sender].amount += actualDeposit;

    emit Deposited(msg.sender, actualDeposit);
}
```

2. Consider implementing a maximum deposit limit to prevent extreme values.

The deposit function in the Locking contract is vulnerable to potential exploitation, particularly when used with tokens like cUSDCv3 that have special transfer logic. This vulnerability could lead to inflated deposit records and potential fund drainage.
