# Vulnerability details

## Impact
The uninitialized mapping access in the RewardManagerAbstract contract can lead to incorrect reward calculations, allowing attackers to exploit the reward distribution system. When a user who has never received rewards before interacts with the system, the default values of the userReward mapping will result in unintended behavior:

1. Unauthorized Reward Accrual: An attacker can manipulate their interaction with the contract to receive rewards without a valid stake or contribution.
2. Financial Loss: Honest users may find their rewards diluted or incorrect, leading to potential financial losses due to erroneous distributions.

## Proof of Concept
https://github.com/code-423n4/2024-10-loopfi/blob/d219f0132005b00a68f505edc22b34f9a8b49766/src/pendle-rewards/RewardManagerAbstract.sol#L65-L65

Here is how an attacker can exploit this vulnerability;

1. Setup:

An attacker deploys a contract that interacts with the vulnerable RewardManagerAbstract.
They ensure that their address has never received rewards before.

2. Triggering the Vulnerability:

The attacker calls a function that leads to [_distributeRewardsPrivate](https://github.com/code-423n4/2024-10-loopfi/blob/d219f0132005b00a68f505edc22b34f9a8b49766/src/pendle-rewards/RewardManagerAbstract.sol#L52C5-L79C6) being executed.
In _distributeRewardsPrivate, the following line is executed:
```solidity
uint256 userIndex = userReward[token][user].index; // Returns 0 for uninitialized mapping
```
3. Exploit Mechanics:

Since userIndex is 0, the following calculations in the function will proceed incorrectly:
```solidity
uint256 deltaIndex = index - userIndex; // If index > 0, deltaIndex > 0
```

This results in a positive deltaIndex, allowing the attacker to calculate rewardDelta based on a non-zero delta:
```solidity
uint256 rewardDelta = userShares.mulDown(deltaIndex);
```

4. Outcome:

The attacker receives rewardDelta without having contributed any collateral or having any prior reward accumulation.
This could lead to the attacker accruing significant rewards simply by exploiting the mapping's default behavior.

## Tools Used
Vscode, Manual Analysis

## Recommended Mitigation Steps

1. Initialize Mappings: Ensure that when a user first interacts with the reward system, their mapping entry is initialized with default values:

```solidity
userReward[token][user] = UserReward({index: INITIAL_REWARD_INDEX.Uint128(), accrued: 0});
```

2. Use Require Statements: Before accessing user reward mappings, implement checks to ensure users have valid entries:

```solidity
require(userReward[token][user].index != 0, "User not initialized");
```
