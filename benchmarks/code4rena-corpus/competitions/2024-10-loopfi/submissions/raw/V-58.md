# Vulnerability details

## Issue
The Checks-Effects-Interactions (CEI) pattern is not followed in the _onDecreaseLever() function, where external calls are made before the state changes are finalized. This leaves the function open to reentrancy attacks, where malicious contracts could exploit the contract's state by reentering it before the final state changes are completed.

## Proof of Concept
In the following code, external calls such as withdraw, redeem, and delegatecall are made before any internal state changes:


uint256 withdrawnCollateral = ICDPVault(leverParams.vault).withdraw(leverParams.position, subCollateral);
tokenOut = IERC4626(leverParams.collateralToken).redeem(withdrawnCollateral, address(this), address(this));
_delegateCall(address(poolAction), abi.encodeWithSelector(poolAction.exit.selector, leverParams.auxAction));

## Mitigation
Refactor the function to follow the Checks-Effects-Interactions pattern, ensuring that state changes are performed before making any external calls.

## Risk Level
High – Improper state management could lead to reentrancy attacks, which could result in loss of funds or manipulation of contract states.
