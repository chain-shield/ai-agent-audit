# Vulnerability details

## Impact
The decodeWellData function contains an erroneous check for the second decimal value, which incorrectly checks decimal0 again instead of decimal1. This logic flaw can lead to unintended behavior in functions relying on accurate decimal values, such as calcLpTokenSupply and others. Specifically, this mistake can cause the function to incorrectly assume the decimal places for tokens, potentially leading to inaccurate calculations and overflows in the LP token supply calculations.
