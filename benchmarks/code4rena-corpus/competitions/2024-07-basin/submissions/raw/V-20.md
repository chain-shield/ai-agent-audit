# Vulnerability details

## Impact
There are several issues with the current `_authorizeUpgrade` function which will prevent any upgradeable Well from being upgraded.

## Proof of Concept
Here is the current `_authorizeUpgrade` function:
```solidity
    function _authorizeUpgrade(address newImplmentation) internal view override {
        // verify the function is called through a delegatecall.
        require(address(this) != ___self, "Function must be called through delegatecall");


        // verify the function is called through an active proxy bored by an aquifer.
        address aquifer = aquifer();
        address activeProxy = IAquifer(aquifer).wellImplementation(_getImplementation());
        require(activeProxy == ___self, "Function must be called through active proxy bored by an aquifer");


        // verify the new implmentation is a well bored by an aquifier.
        require(
            IAquifer(aquifer).wellImplementation(newImplmentation) != address(0),
            "New implementation must be a well implmentation"
        );


        // verify the new implmentation is a valid ERC-1967 implmentation.
        require(
            UUPSUpgradeable(newImplmentation).proxiableUUID() == _IMPLEMENTATION_SLOT,
            "New implementation must be a valid ERC-1967 implmentation"
        );
    }
````

As we can see `IAquifer(aquifer).wellImplementation` is invoked several times. The issue is that it is being called incorrectly.
`IAquifer(aquifer).wellImplementation` is a mapping of wells pointing to their implementation contracts. When calling `IAquifer(aquifer).wellImplementation`, in order for it to work properly the address of a Well needs to be passed in as the parameter of the call, and the return value will be the address of the Well's implementation. Implementation contracts do not hold the actual protocol state, but are instead used only through delegatecalls.

In the `_authorizeUpgrade` function, whenever `IAquifer(aquifer).wellImplementation` is called, it is always passed an implementation contract as the parameter, not the address of a well. As a result, the return address of the call will most likely be `address(0)`, causing the function to revert.

Here is the `wellImplementation` mapping in the `Aquifer` contract, where we can see that it is a mapping of `well proxies => well implementations`:
```solidity
    // A mapping of Well address to the Well implementation addresses
    // Mapping gets set on Well deployment
    mapping(address => address) public wellImplementation;
```
Thus, the proper way of querying `wellImplementation` is by supplying the address of a well, not an implementation.

Manual review

## Recommended Mitigation Steps
The `_authorizeUpgrade` function must be entirely reworked to work as expected.
