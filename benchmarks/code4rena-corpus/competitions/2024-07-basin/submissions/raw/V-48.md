# Vulnerability details

## Impact
The Stable2.sol#decodeWellData() function returns incorrect decimal values ​​for tokens, which causes incorrect calculations in critical functions of the contract. This is a critical issue.

## Proof of Concept
The `Stable2.sol#decodeWellData()` function returns a decimal array of tokens from well based on encoded input data.
```solidity
    function decodeWellData(bytes memory data) public view virtual returns (uint256[] memory decimals) {
        (uint256 decimal0, uint256 decimal1) = abi.decode(data, (uint256, uint256));

        // if well data returns 0, assume 18 decimals.
        if (decimal0 == 0) {
            decimal0 = 18;
        }

        if (decimal0 > 18 || decimal1 > 18) revert InvalidTokenDecimals();

        decimals[0] = decimal0;
        decimals[1] = decimal1;
    }
```
As you can see, when well data returns 0, the decimal of token1 is determined by `decimal0`, not `decimal1`.
Therefore, even if `decimal1` is not 0, if `decimal0` is 0, `decimal1` is determined as 18.
