# Vulnerability details

## Vulnerability Details

The `getBandC` function is used to calculate the intermediate values `b` and `c` that are used in the `_calcReserve` function, which is part of the core logic for calculating the amount of LP tokens given reserves, and for calculating the reserve given a target price ratio. The function doesn't properly handle the edge cases of zero reserves or zero LP token supply, which could lead to several issues.

## Code

```solidity
function getBandC(
        uint256 Ann,
        uint256 lpTokenSupply,
        uint256 reserves
    ) private pure returns (uint256 c, uint256 b) {
        c = lpTokenSupply * lpTokenSupply / (reserves * N) * lpTokenSupply * A_PRECISION / (Ann * N);
        b = reserves + (lpTokenSupply * A_PRECISION / Ann);
    }
```

## Impact
1. The `calcReserve`, `calcReserveAtRatioSwap`, and `calcReserveAtRatioLiquidity` functions all rely on the correct calculation of `b` and `c` from `getBandC`. If these values are incorrect, the reserve calculations will be inaccurate, which could lead to incorrect pricing of the well's tokens.

2. If the `getBandC` function encounters a division by zero error due to zero reserves or zero LP token supply, the entire transaction will revert, potentially causing issues for users interacting with the well.

## Poc

```solidity
function test_getBandC_zeroReservesOrLpTokenSupply() public {
    uint256 Ann = 1;
    uint256 lpTokenSupply = 0;
    uint256 reserves = 0;

    uint256 c;
    uint256 b;

    (c, b) = Stable2(address(_function)).getBandC(Ann, lpTokenSupply, reserves);
    assertEq(c, 0);
    assertEq(b, 0);

    reserves = 1e18;
    (c, b) = Stable2(address(_function)).getBandC(Ann, lpTokenSupply, reserves);
    assertEq(c, 0);
    assertEq(b, 0);
}
```

## Mitigation

Handle the edge case of zero reserves or zero LP token supply.
