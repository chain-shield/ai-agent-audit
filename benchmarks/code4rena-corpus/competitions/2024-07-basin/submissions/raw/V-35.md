# Vulnerability details

## Impact
Detailed description of the impact of this finding.

***Title***: Reserve should be greater than 0 on the calcReserve function in the Stable2 contract.

Ensuring Positive Reserves in calcReserve Function of Stable2 Contract
	•	Contract: Stable2
	•	Function: calcReserve
        •	Severity: Medium

***Issue: Reserve Should Be Greater Than Zero***
The calcReserve function should ensure that the returned reserve value is strictly greater than zero to maintain logical consistency and prevent errors in subsequent operations relying on non-zero reserve values.

Impact: If the reserve is zero, it could lead to incorrect or unexpected behaviour in financial operations, such as liquidity calculations or swaps. This may result in division by zero errors or lead to incorrect assumptions in other parts of the code, potentially affecting protocol reliability.

The calcReserve function lacks proper validation to ensure that the calculated reserve value is greater than zero before it is returned. This lack of validation can result in logical errors, where subsequent operations might proceed under incorrect assumptions that the reserve is non-zero.

## Recommended Mitigation Steps
To address this issue, ensure that the reserve is greater than zero before returning it. The recommended code change is as follows:
***Code before correction**
```sol
            if (reserve > prevReserve) {
                if (reserve - prevReserve <= 1) {
                    return reserve / (10 ** (18 - decimals[j]));
                }
            } else {
                if (prevReserve - reserve <= 1) {
                    return reserve / (10 ** (18 - decimals[j]));
                }
            }
```
***Code after correction***
```sol
            if (reserve > prevReserve) {
                if (reserve - prevReserve <= 1) {
```
