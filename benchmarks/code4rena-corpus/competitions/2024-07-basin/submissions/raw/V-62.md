# Vulnerability details

### Description

The `calcReserve()` function in `Stable2.sol` uses incorrect token precision values due to a bug in the `decodeWellData()` function. This issue leads to inaccurate scaling of reserves, which can result in incorrect calculations and potential downstream errors.

### Affected Code

The problem arises from the incorrect handling of token decimal values in the `decodeWellData()` function:

```solidity
// Stable2.sol#L310-L325

function decodeWellData(bytes memory data) public view virtual returns (uint256[] memory decimals) {
    (uint256 decimal0, uint256 decimal1) = abi.decode(data, (uint256, uint256));

    // If well data returns 0, assume 18 decimals.
    if (decimal0 == 0) {
        decimal0 = 18;
    }
    if (decimal0 == 0) {  // This should check decimal1 instead of decimal0.
        decimal1 = 18;
    }
    if (decimal0 > 18 || decimal1 > 18) revert InvalidTokenDecimals();

    decimals = new uint256 ;
    decimals[0] = decimal0;
    decimals[1] = decimal1;
}
```

This incorrect check can cause the `calcReserve()` function to use an inaccurate decimal value when performing calculations:

```solidity
// Stable2.sol#L128-L142

function calcReserve(
    uint256[] memory reserves,
    uint256 j,
    uint256 lpTokenSupply,
    bytes memory data
) public view returns (uint256 reserve) {
    uint256[] memory decimals = decodeWellData(data);
    uint256[] memory scaledReserves = getScaledReserves(reserves, decimals);

    // Other logic...

    for (uint256 i; i < 255; ++i) {
        uint256 prevReserve = reserve;
        reserve = _calcReserve(reserve, b, c, lpTokenSupply);

        // Scale reserve down to original precision
        if (reserve > prevReserve) {
            if (reserve - prevReserve <= 1) {
                return reserve / (10 ** (18 - decimals[j]));
            }
        } else {
            if (prevReserve - reserve <= 1) {
                return reserve / (10 ** (18 - decimals[j]));
            }
        }
    }

    revert("Convergence not found after 255 iterations");
}
```

### Recommended Mitigation

The `decodeWellData()` function should correctly check and apply the token's precision. Specifically, the check for `decimal1` should be corrected:

```solidity
if (decimal0 == 0) {
    decimal0 = 18;
}
if (decimal1 == 0) {  // Corrected check for decimal1.
    decimal1 = 18;
}
```

Additionally, ensure that `calcReserve()` scales the amounts down to the collateral token's native precision before performing any operations that depend on these values.
