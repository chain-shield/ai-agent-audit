# Vulnerability details

## Impact

The Stable2 smart contract has a significant issue in its iterative functions (calcReserve, calcReserveAtRatioLiquidity, and calcReserveAtRatioSwap). These functions, designed to converge within a set 255 iterations, fail to do so under certain conditions. When the convergence is not achieved, it causes transaction reverts, leading to potential operational disruptions. Users might experience failed transactions, which interrupts the normal functionality of the contract and could render essential features unreliable.

These tests simulate situations with imbalanced reserves and extreme ratios causing the functions to fail to converge within 255 iterations. The successful catch of the revert demonstrates the presence of non-convergence scenarios.

## Tools Used

Foundry: For writing and running Solidity tests.
Solidity: For smart contract implementation and testing logic.

## Recommended Mitigation Steps

Increasing Iteration Limits: Consider allowing more iterations to improve convergence chances in edge cases. Ensure this does not significantly impact gas costs.

Better Fallback Mechanism: Implement a fallback to handle non-convergence gracefully without reverting the transaction, such as returning a reasonable estimate.

Improved Input Validation: Validate inputs to avoid scenarios that lead to non-convergence early in the function logic.
