# Vulnerability details

## Vulnerability Summary
Issue Type: Unchecked External Call

Affected Contract: Stable2


## Description
The `calcRate` function calls an external contract to fetch data. If this external contract is compromised or behaves unexpectedly, it could return incorrect data or fail, potentially causing unintended behavior in the `calcRate` function. This is due to the unchecked nature of the external call.

## Proof of Concept (PoC)
Here is a simplified PoC to demonstrate the risk of an unchecked external call:

```
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "forge-std/Test.sol";
import "../src/Stable2.sol";

contract ExternalCallTest is Test {
    Stable2 stable2;

    address constant LOOKUP_TABLE_ADDRESS = 0x...; // Replace with the appropriate lookupTable address

    function setUp() public {
        stable2 = new Stable2(LOOKUP_TABLE_ADDRESS);
    }

    function testUncheckedExternalCall() public {
        uint256[] memory reserves = new uint256[](2);
        reserves[0] = 1000 * 10 ** 18;
        reserves[1] = 1000 * 10 ** 18;

        bytes memory data = abi.encode(18, 18);

        // Call function that depends on external contract
        stable2.calcRate(reserves, 0, 1, data);
    }
}
```
## Impact
An unchecked external call can lead to the contract relying on potentially faulty or malicious data from the external contract. This could compromise the integrity of the contract's operations, leading to incorrect results or vulnerabilities.

## Recommendations
To mitigate this issue:

1-`Check Results from External Calls`: Always validate the results received from external contracts to ensure they are as expected.

```
(bool success, bytes memory data) = externalContract.call(abi.encodeWithSignature("getRates()"));
require(success, "External call failed");
```
2-`Use Interfaces`: Define interfaces for interacting with external contracts and ensure the external contracts implement these interfaces correctly.

3-`Implement Fallback Mechanisms`: Use fallback mechanisms to handle cases where external calls fail or return unexpected results.

4-`Test with Different Scenarios`: Conduct extensive testing with various scenarios, including potential edge cases, to ensure that your contract handles external call failures gracefully.
