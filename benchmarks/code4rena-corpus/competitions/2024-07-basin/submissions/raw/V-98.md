# Vulnerability details

## Vulnerability Details

In the `calcRate` function, the `lpTokenSupply` is calculated using the `calcLpTokenSupply` function, which takes the `scaledReserves` as input. However, the `scaledReserves` are calculated using the `getScaledReserves` function, which scales the reserves based on the token decimals provided in the `data` parameter.

The problem is that the `calcLpTokenSupply` function expects the token decimals to be 18 for both tokens. This means that if the token decimals are not 18, the `lpTokenSupply` calculation will not be accurate, which can lead to incorrect rate calculations.

## Code

```solidity
function calcRate(
        uint256[] memory reserves,
        uint256 i,
        uint256 j,
        bytes memory data
    ) public view returns (uint256 rate) {
        uint256[] memory decimals = decodeWellData(data);
        uint256[] memory scaledReserves = getScaledReserves(reserves, decimals);

        // calc lp token supply (note: `scaledReserves` is scaled up, and does not require bytes).
        uint256 lpTokenSupply = calcLpTokenSupply(scaledReserves, abi.encode(18, 18));

        rate = _calcRate(scaledReserves, i, j, lpTokenSupply);
    }
```

## Impact

1. If the calcRate function is not accurately calculating the rates, the lookup table data will be flawed, leading to incorrect price estimates in the calcReserveAtRatioSwap function.

2. The calcRate function is crucial for providing accurate pricing information to the wider system. If the rates calculated by calcRate are inaccurate, it can lead to suboptimal pricing and trading decisions, potentially causing significant financial losses for users.


## Poc

```solidity
function test_calcRate_with_different_decimals() public {
    uint256[] memory reserves = new uint256[](2);
    reserves[0] = 10_000 * 1e6; // 10,000 with 6 decimals
    reserves[1] = 10 * 1e18; // 10 with 18 decimals
    _data = abi.encode(6, 18);

    uint256 rate = _function.calcRate(reserves, 0, 1, _data);
    assertEq(rate, 1e6); // Expected rate should be 1:1 (10,000:10)
}
```

## Mitigation

Modify the `calcRate` function to pass the correct token decimals to the `calcLpTokenSupply` function, instead of using the default 18 decimals. This ensures that the `lpTokenSupply` calculation will be accurate, and the `calcRate` function will provide the correct rate.

```solidity
function calcRate(
    uint256[] memory reserves,
    uint256 i,
    uint256 j,
    bytes memory data
) public view returns (uint256 rate) {
    uint256[] memory decimals = decodeWellData(data);
    uint256[] memory scaledReserves = getScaledReserves(reserves, decimals);

    // calc lp token supply with the correct token decimals
    uint256 lpTokenSupply = calcLpTokenSupply(scaledReserves, abi.encode(decimals[0], decimals[1]));

    rate = _calcRate(scaledReserves, i, j, lpTokenSupply);
}
```
