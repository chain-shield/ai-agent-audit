# Vulnerability details

## Impact
The accuracy of the calculation is not correct because `calcLpTokenSupply()` does not revert even though it has not converged.

## Proof of Concept
According to sponsor team:
> the assumption is that if the function has not converged within 255, then the value is invalid. It may certainly be close, but given that in most cases it should converge within 4 loops, we prefer it to break rather than return an inaccurate value.

However, as a result of multiple simulations, we can see that `calcLpTokenSupply()` does not converge in many cases.
https://github.com/code-423n4/2024-07-basin/blob/main/src/functions/Stable2.sol#L74-L103

>in case (reserve0, reserve1) = (600, 800), result is that: i = 254, return value = 1.3952e+21
>in case (reserve0, reserve1) = (700, 800), result is that: i = 254, return value = 1.4989e+21

But there exists `revert()` in `calcReserve()`.
