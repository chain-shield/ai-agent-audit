# Vulnerability details

The `WellUpgradeable.sol` contract is a upgradeable version of `Well` contract , and it uses two function `upgradeTo` & `upgradeToAndCall` .The `upgradeTo` function is used to upgrade the implementation of the proxy to a new version , where the `upgradeToAndCall` function is similar to `upgradeTo` but includes additional functionality to execute a function call on the new implementation immediately after upgrading.  However both functions lack `onlyOwner` modifier and along with that the `onlyOwner` modifier is not also adjusted in `_authorizeUpgrade` function, which means that these actions can be performed by anyone, not just the contract owner.

## Impact
Now the anybody has ownership they are able to perform an upgrade of the implementation contract's logic contract.

The modifier is also missing in the `_authorizeUpgrade` function , which does not satisfy UUPSUpgradeable proxy pattern.

```javascript
 function _authorizeUpgrade(address newImplmentation) internal view override {
        // verify the function is called through a delegatecall.
        require(address(this) != ___self, "Function must be called through delegatecall");

        // verify the function is called through an active proxy bored by an aquifer.
        address aquifer = aquifer();
        address activeProxy = IAquifer(aquifer).wellImplementation(_getImplementation());
        require(activeProxy == ___self, "Function must be called through active proxy bored by an aquifer");

        // verify the new implmentation is a well bored by an aquifier.
        require(
            IAquifer(aquifer).wellImplementation(newImplmentation) != address(0),
            "New implementation must be a well implmentation"
        );

        // verify the new implmentation is a valid ERC-1967 implmentation.
        require(
            UUPSUpgradeable(newImplmentation).proxiableUUID() == _IMPLEMENTATION_SLOT,
            "New implementation must be a valid ERC-1967 implmentation"
        );
    }
```

You can check here - [_authorizeUpgrade](https://docs.openzeppelin.com/contracts/4.x/api/proxy#UUPSUpgradeable-_authorizeUpgrade-address-)

## Recommended Mitigation Steps
Consider adding `onlyOwner` modifier on both functions. Or adding modifier on `_authorizeUpgrade` function.
