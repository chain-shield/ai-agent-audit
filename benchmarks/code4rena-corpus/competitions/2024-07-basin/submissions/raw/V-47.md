# Vulnerability details

## Impact
The `decodeWellData` function in the `Stable2.sol` contract contains an error that could lead to incorrect handling of token decimals. This function is very vital as it decodes the decimal information for the tokens in the well, which is used throughout the contracts such as `getScaledReserves`, `calcRate`, and others for various calculations.


## Proof of Concept
The error is located in the [`decodeWellData`](https://github.com/code-423n4/2024-07-basin/blob/7d5aacbb144d0ba0bc358dfde6e0cc913d25310e/src/functions/Stable2.sol#L310-L325) function:

```solidity
function decodeWellData(bytes memory data) public view virtual returns (uint256[] memory decimals) {
    (uint256 decimal0, uint256 decimal1) = abi.decode(data, (uint256, uint256));

    // if well data returns 0, assume 18 decimals.
    if (decimal0 == 0) {
        decimal0 = 18;
    }
    if (decimal0 == 0) {  // This should be checking decimal1
        decimal1 = 18;
    }
    // ... rest of the function
}
```

The second conditional statement incorrectly checks `decimal0` again instead of `decimal1`. As a result, `decimal1` is never set to 18 when it's 0, leading to potential mishandling of token decimals.

## Recommended Mitigation Steps
Modify the `decodeWellData` function as follows:

```solidity
function decodeWellData(bytes memory data) public view virtual returns (uint256[] memory decimals) {
    (uint256 decimal0, uint256 decimal1) = abi.decode(data, (uint256, uint256));

    // if well data returns 0, assume 18 decimals.
    if (decimal0 == 0) {
        decimal0 = 18;
    }
    if (decimal1 == 0) {  // Changed from decimal0 to decimal1
        decimal1 = 18;
    }
    if (decimal0 > 18 || decimal1 > 18) revert InvalidTokenDecimals();

    decimals = new uint256[](2);
    decimals[0] = decimal0;
    decimals[1] = decimal1;
}
```

This change ensures that both `decimal0` and `decimal1` are correctly set to 18 if their original values are 0.
After implementing this fix, thoroughly test the contract with various token decimal configurations to ensure correct behavior across all scenarios.
