# Vulnerability details

## Description
In the `decodeWellData` function, there is a logic error where `decimal1` is assigned to 18 based on the condition of `decimal0` being zero.

```soldity
if (decimal0 == 0) {
    decimal0 = 18;
}
if (decimal0 == 0) {
    decimal1 = 18;
}
```


## Impact
This can lead to incorrect handling of token decimals, causing miscalculations in scaling reserves and potentially affecting the accuracy of price and liquidity calculations.

## Proof of Concept
To demonstrate the issue with the incorrect decoding logic in the `decodeWellData` function of the `Stable2` contract, use the following test case:

1.Declare and Initialize the Test Data:
```solidity
uint256 decimal0 = 0;  // Set decimal0 to 0 to trigger faulty logic
uint256 decimal1 = 5;  // Set decimal1 to a non-zero value
bytes memory data = abi.encode(decimal0, decimal1);
```
2.Invoke the Vulnerable Function and Observe Behavior:
```solidity
try stable2.decodeWellData(data) returns (uint256[] memory decimals) {

```
Expected Outcome:
The function should incorrectly decode `decimal0 as 18, but it should correctly decode `decimal`1 as 5. The output should be [18, 18] instead of [18, 5], demonstrating the flawed logic in setting the decimal values.
