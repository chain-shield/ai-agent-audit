# Vulnerability details

## Description

The `Stable2` contract implements a stable swap pricing function for wells with two tokens, using a formula similar to Curve's stableswap AMM. The contract relies on accurate reserve values for its calculations, such as in the [`calcLpTokenSupply()`](https://github.com/code-423n4/2024-07-basin/blob/7d5aacbb144d0ba0bc358dfde6e0cc913d25310e/src/functions/Stable2.sol#L74-L103) and [`calcReserve()`](https://github.com/code-423n4/2024-07-basin/blob/7d5aacbb144d0ba0bc358dfde6e0cc913d25310e/src/functions/Stable2.sol#L114-L144) functions. These functions take the current reserves as input and perform calculations to determine the LP token supply and individual token reserves, respectively.

However, the contract does not account for direct transfers of ERC-20 tokens to its address. Direct transfers can alter the token balances without the contract being aware of these changes, leading to discrepancies between the actual token balances and the values used in the contract’s calculations. This can result in incorrect LP token supply or reserve calculations.

For example, if a user directly transfers ERC-20 tokens to the contract, the internal state of the contract will not be updated to reflect these changes. Subsequent calls to `calcLpTokenSupply()` or `calcReserve()` will use outdated reserve values, leading to incorrect results. This issue can be exploited by malicious actors to manipulate the contract’s behavior, potentially leading to financial losses for users or the protocol.

## Impact
Direct transfers of ERC-20 tokens to the `Stable2` contract can alter the token balances without the contract being aware of these changes, leading to potential discrepancies in the reserve values used for calculations. This can result in incorrect LP token supply or reserve calculations, making it a significant issue that needs to be addressed. Malicious actors could exploit this discrepancy to manipulate the contract’s behavior, potentially leading to financial losses for users or the protocol.

## Proof of Concept
1. A user directly transfers ERC-20 tokens to the `Stable2` contract’s address, altering the token balances.
2. The contract’s functions, such as `calcLpTokenSupply()` and `calcReserve()`, are not aware of this transfer and continue to use outdated reserve values.
3. This leads to incorrect calculations for LP token supply or reserve values, potentially resulting in financial discrepancies.

## Recommended Mitigation Steps
To mitigate this issue, it is important to ensure that the contract is aware of any changes to the token balances. This can be achieved by:

1. **Disabling Direct ERC-20 Token Transfers**:
   Implement guards to prevent direct ERC-20 token transfers to the contract’s address.

2. **Ensuring Accurate Reserve Values**:
   Ensure that any changes to the token balances are reflected in the contract’s internal state and calculations.
