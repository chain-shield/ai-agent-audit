# Vulnerability details

## Impact
The `decodeWellData` function in the `Stable2` contract contains a critical bug where it mistakenly checks `decimal0` twice instead of checking both `decimal0` and `decimal1`. This oversight means that if `decimal1` is `0`, it won't be correctly set to `18`, potentially leading to incorrect scaling of token reserves.

This error affects the scaling of token reserves, which is crucial for accurate calculations throughout the contract. Functions like `calcLpTokenSupply`, `calcReserve`, and `calcRate` depend on correctly scaled reserves. An error in scaling could lead to incorrect LP token supply, miscalculated reserves, and unfair exchange rates, destabilizing the pool and putting user funds at risk.
