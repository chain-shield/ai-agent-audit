# Vulnerability details

## Impact
The `decodeWellData` function is intended to correctly set the decimals for tokens. The function has logic to set default decimal values for tokens (18), if the provided data shows 0 for any of the tokens. However, the implementation contains a mistake in its conditional checks for default values. The function incorrectly rechecks `decimal0` instead of `decimal1`, which prevents `decimal1` from being set to 18 if it is initially 0. This results in `decimal1` potentially remaining 0, leading to incorrect decimal values being used in further operations or calculations.
## Proof of concept
Paste the following test into `Stable2.t.sol`:
```solidity
function test_incorrectAssignDefaultDecimals() public {

        address lut = address(new Stable2LUT1());
        Stable2 stable2 = new Stable2(address(lut));
  
        uint256[] memory decimals = stable2.decodeWellData(abi.encode(0, 0));

        assertEq(decimals[0], 18);
        assertEq(decimals[1], 0);
    }
```
## Recommended mitigation steps
Update the code as follows, to ensure that both `decimal0` and `decimal1` are correctly set to 18 if they are initially 0:
```diff
function decodeWellData(bytes memory data) public view virtual returns (uint256[] memory decimals) {
        (uint256 decimal0, uint256 decimal1) = abi.decode(data, (uint256, uint256));

        // if well data returns 0, assume 18 decimals.
        if (decimal0 == 0) {
            decimal0 = 18;
        }
-       if (decimal0 == 0) {
+       if (decimal1 == 0) {
            decimal1 = 18;
        }
        if (decimal0 > 18 || decimal1 > 18) revert InvalidTokenDecimals();

        decimals = new uint256[](2);
        decimals[0] = decimal0;
        decimals[1] = decimal1;
    }
```
