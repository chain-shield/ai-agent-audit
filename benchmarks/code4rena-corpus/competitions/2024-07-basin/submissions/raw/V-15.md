# Vulnerability details

The vulnerability is identified in the init function, which performs a nested loop to check for duplicate tokens.

The WellUpgradeable contract is vulnerable to gas griefing due to an inefficient duplicate token check in its init function. This function uses a nested loop with a time complexity of O(n)^2  to identify duplicate tokens, causing the gas consumption to increase quadratically with the number of tokens. This can lead to excessive gas usage and potential denial of service when the number of tokens is large, as transactions may exceed the block gas limit and fail.
Impact: Denial of service due to gas limit exhaustion, making the contract unusable when initializing with a large number of tokens.
In the init function of the WellUpgradeable contract, the items being iterated over are the tokens stored in the _tokens array. Specifically, the function performs the following actions:

Retrieve Tokens: It retrieves the array of IERC20 tokens by calling the tokens() function.
Nested Loop: It then uses a nested loop to iterate over this array to check for duplicate tokens.

A test was conducted using Foundry to simulate the initialization of the WellUpgradeable contract with a large number of tokens. The initial test with 200 tokens showed high gas usage but did not revert.Increasing the token count further confirmed the potential for gas limit exhaustion.
Test Results:

Test with Increased Tokens (e.g., 500):  also passed with high gas usage (261,444,857) units


Explanation of the Test Contract
Set Up: Deploys the WellUpgradeable contract in the setUp function.
Creating Mock Tokens: Creates an array of MockERC20 tokens with a specified tokenCount.(The purpose of the Mock ERC20 Token Contract in the test is to simulate the behavior of ERC20 tokens without relying on actual token contracts deployed on the blockchain.)
Logging Gas Usage: Measures and logs the gas usage of the init function to observe how it scales with the number of tokens.
Try-Catch Block: Uses a try-catch block to handle potential reverts due to gas limits and logs the event if it occurs.

Recommendation
To mitigate the gas griefing vulnerability, refactor the duplicate token check using a mapping. This approach ensures efficient handling of larger token arrays.


function init(string memory _name, string memory _symbol) external override reinitializer(2) {
    __ERC20Permit_init(_name);
    __ERC20_init(_name, _symbol);
    __ReentrancyGuard_init();
    __UUPSUpgradeable_init();
    __Ownable_init();

    IERC20[] memory _tokens = tokens();
    uint256 tokensLength = _tokens.length;
    mapping(address => bool) tokenSeen;

    for (uint256 i = 0; i < tokensLength; ++i) {
        address tokenAddress = address(_tokens[i]);
        if (tokenSeen[tokenAddress]) {
            revert DuplicateTokens(_tokens[i]);
        }
        tokenSeen[tokenAddress] = true;
    }
}
