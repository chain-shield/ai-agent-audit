# Vulnerability details

## Impact
The current implementation of the `init` function initializes the reentrancy guard after other initializations, which leaves a window where reentrancy attacks could occur. 

By prioritizing the initialization of the reentrancy guard, you can ensure that the contract is protected from reentrancy attacks from the start.

## Proof of Concept
The `init` function currently initializes the reentrancy guard after other initializations:

```
function init(string memory _name, string memory _symbol) external override reinitializer(2) {
    __ERC20Permit_init(_name);
    __ERC20_init(_name, _symbol);
    __ReentrancyGuard_init(); // Reentrancy guard is initialized here
    __UUPSUpgradeable_init();
    __Ownable_init();

    IERC20[] memory _tokens = tokens();
    uint256 tokensLength = _tokens.length;
    for (uint256 i; i < tokensLength - 1; ++i) {
        for (uint256 j = i + 1; j < tokensLength; ++j) {
            if (_tokens[i] == _tokens[j]) {
                revert DuplicateTokens(_tokens[i]);
            }
        }
    }
}
```

By moving the `__ReentrancyGuard_init()` call to the beginning of the function, we can ensure reentrancy protection is established first:

```
function init(string memory _name, string memory _symbol) external override reinitializer(2) {
    __ReentrancyGuard_init(); // Reentrancy guard initialized first
    __ERC20Permit_init(_name);
    __ERC20_init(_name, _symbol);
    __UUPSUpgradeable_init();
    __Ownable_init();

    IERC20[] memory _tokens = tokens();
    uint256 tokensLength = _tokens.length;
    mapping(address => bool) tokenMap;
    for (uint256 i; i < tokensLength; ++i) {
        if (tokenMap[address(_tokens[i])]) {
            revert DuplicateTokens(_tokens[i]);
        }
        tokenMap[address(_tokens[i])] = true;
    }
}
```

## Recommended Mitigation Steps
Reorder the initializations in the `init` function to call `__ReentrancyGuard_init()` first, ensuring reentrancy protection is established at the earliest possible point in the function. 

This change reduces the risk of reentrancy attacks during contract initialization
