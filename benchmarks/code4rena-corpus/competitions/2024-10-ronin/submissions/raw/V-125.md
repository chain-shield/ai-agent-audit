# Vulnerability details


## Issue Overview:
In the swap function of the KatanaV3Pool contract, there is a potential downcasting issue in the line:

```solidity
state.protocolFee += uint128(delta);
```

## Technical Details:
Calculation: delta is computed using `FullMath.mulDiv(step.feeAmount, cache.feeProtocolNum, cache.feeProtocolDen)`, which returns a uint256.
Downcasting: The result is cast to uint128 before being added to `state.protocolFee`.

## Potential Risks:
Data Loss: If delta exceeds the maximum value of uint128 (i.e., (2^{128} - 1)), the downcasting operation will truncate the value, leading to incorrect protocol fee accumulation.
Financial Impact: This could result in under-collection of protocol fees, impacting revenue and potentially leading to discrepancies in financial reporting.

## Recommended Mitigation:
Bounds Check: Implement a check to ensure delta is within the uint128 range before downcasting:
`require(delta <= type(uint128).max, "Delta exceeds uint128");`
Audit and Testing: Conduct thorough testing and audits to ensure that all calculations involving delta are safe and accurate.
