# Vulnerability details

`flash` function does not include a check to verify that the caller (`msg.sender`) is the position manager. As a result, any address can call the function and initiate a flash loan, bypassing the intended access control mechanism.

[#L747-L748](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L747-L748)
```solidity
/// @inheritdoc IKatanaV3PoolActions
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) external override lock {
    require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");
    // FOUND: Missing authorization check to ensure only the position manager can call flash
    // ...
}
```
It is part of the `IKatanaV3PoolActions` interface, which defines the actions that can be performed on the pool. The function is responsible for initiating flash loans, allowing users to borrow tokens from the pool and repay them within the same transaction.

## Proof of Concept
1. Alice deploys the `KatanaV3Pool` contract with the vulnerable `flash` function.
2. Bob, an attacker, calls the `flash` function from his address (not the position manager) with the following parameters:

   * `recipient`: Bob's address or any other address he controls.
   * `amount0`: A valid amount of token0 to borrow.
   * `amount1`: A valid amount of token1 to borrow.
   * `data`: Any arbitrary data to pass to the callback function.

3. The flash function executes successfully without reverting, allowing Bob to borrow tokens from the pool without authorization.
4. Bob can then perform any desired actions with the borrowed tokens within the same  transaction, such as:

   * Manipulating prices by executing trades that influence the pool's price oracle.
   * Exploiting other vulnerabilities in the system, such as reentrancy attacks or price oracle manipulations.
   * Transferring the borrowed tokens to another address for personal gain.

5. Bob repays the borrowed tokens plus fees within the same transaction to avoid detection and complete the flash loan.

By following these steps, Bob successfully exploits the vulnerability and initiates unauthorized flash loans, potentially causing harm to the pool and its users.

## Recommended Mitigation Steps
Should include an additional check to ensure that the caller is the position manager
