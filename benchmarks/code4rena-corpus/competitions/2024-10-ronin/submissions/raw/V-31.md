# Vulnerability details

KatanaV3Pool contract contains vulnerability in its fee growth accounting mechanism within the swap function. This issue leads to inconsistent fee tracking, causing incorrect fee distributions to liquidity providers and compromising the economic integrity of the protocol.

The bug occurred due to an oversimplified update of the fee growth global variables in the swap function. The current implementation only updates one of the fee growth variables based on the swap direction (`zeroForOne`), without considering that fees might accrue for both tokens in a single swap operation.

In [KatanaV3Pool.sol#L714-L740](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L714-L740)
```solidity
// update fee growth global
if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128;
else feeGrowthGlobal1X128 = state.feeGrowthGlobalX128; // <= @audit

(amount0, amount1) = zeroForOne == exactInput
  ? (amountSpecified - state.amountSpecifiedRemaining, state.amountCalculated)
  : (state.amountCalculated, amountSpecified - state.amountSpecifiedRemaining);

// do the transfers and collect payment
if (zeroForOne) {
  if (amount1 < 0) TransferHelper.safeTransfer(tokenOut, recipient, uint256(-amount1));

  uint256 balance0Before = balance0();
  IKatanaV3SwapCallback(msg.sender).katanaV3SwapCallback(amount0, amount1, data);
  require(balance0Before.add(uint256(amount0)) <= balance0(), "IIA");
} else {
  if (amount0 < 0) TransferHelper.safeTransfer(tokenOut, recipient, uint256(-amount0));

  uint256 balance1Before = balance1();
  IKatanaV3SwapCallback(msg.sender).katanaV3SwapCallback(amount0, amount1, data);
  require(balance1Before.add(uint256(amount1)) <= balance1(), "IIA");
}

// transfer protocol fees to the treasury
if (state.protocolFee > 0) {
  TransferHelper.safeTransfer(tokenIn, IKatanaV3Factory(factory).treasury(), state.protocolFee);
}
```
This approach fails to accurately track fee growth for both tokens, as it overwrites the fee growth of one token without considering potential fee accrual for that token during the swap.

let's say you

1. Initialize a `KatanaV3Pool` with some liquidity.
2. Perform a swap from `token0` to `token1` (`zeroForOne = true`) that generates fees.
3. Immediately after, perform a swap from `token1` to `token0` (`zeroForOne = false`) that also generates fees.
4. Check the values of `feeGrowthGlobal0X128` and `feeGrowthGlobal1X128`.

You'll notice that after step 3, `feeGrowthGlobal1X128` will be overwritten with the value of `state.feeGrowthGlobalX128`, effectively erasing any fee growth for `token1` that occurred in step 2.

## Impact
Liquidity providers may receive inaccurate fee amounts, leading to unfair distribution of rewards.

## Proof of Concept
1. Alice initializes a `KatanaV3Pool` with some liquidity for `token0` and `token1`.
2. performs a swap from `token0` to `token1` (`zeroForOne = true`), generating fees.
3. Charlie immediately performs a swap from `token1` to `token0` (`zeroForOne = false`), also generating fees.
4. The pool's `feeGrowthGlobal1X128` is now incorrect, as it has been overwritten by Charlie's swap without accounting for the fees generated in Bob's swap.

Illustration.
```solidity
// After Bob's swap
uint256 feeGrowth0 = pool.feeGrowthGlobal0X128();
uint256 feeGrowth1 = pool.feeGrowthGlobal1X128();

// Charlie's swap
pool.swap(recipient, false, amountSpecified, sqrtPriceLimitX96, data);

// After Charlie's swap
uint256 newFeeGrowth0 = pool.feeGrowthGlobal0X128();
uint256 newFeeGrowth1 = pool.feeGrowthGlobal1X128();

// newFeeGrowth1 has been overwritten, losing the fees from Bob's swap
assert(newFeeGrowth1 > feeGrowth1); // This assertion may fail
```

## Recommended Mitigation Steps
Consider implementing the following changes

```diff
- if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128;
- else feeGrowthGlobal1X128 = state.feeGrowthGlobalX128;
+ uint256 feeDelta0 = zeroForOne ? state.feeGrowthGlobalX128 - feeGrowthGlobal0X128 : 0;
+ uint256 feeDelta1 = zeroForOne ? 0 : state.feeGrowthGlobalX128 - feeGrowthGlobal1X128;
+ feeGrowthGlobal0X128 += feeDelta0;
+ feeGrowthGlobal1X128 += feeDelta1;
```
