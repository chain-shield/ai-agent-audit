# Vulnerability details

## Proof of Concept
Solmate's safeTransfer() function doesn't check if the token address actually contains contract code.  This vulnerability makes transactions succeed as if transfers have been successfully made and balances are correctly updated, but that's not the case when the address does not exist(either by calling self-destruct in a token or making an ERC20 honeypot attack)
The AggregateRouter will interact with arbitrary recipient addresses in order to pay with this malicious token.

## Recommended Mitigation Steps
Use Openzeppelin library instead or check address whether it is valid.
