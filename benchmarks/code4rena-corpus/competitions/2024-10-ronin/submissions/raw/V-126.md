# Vulnerability details

## Impact
The contracts in scope are using low-level calls along with inline assembly in Solidity versions prior to 0.8.14, which introduces an optimizer bug. This bug can lead the optimizer to incorrectly identify certain memory operations as "dead" and remove them. Consequently, later operations that depend on these memory operations may read stale or incorrect values, resulting in unpredictable behavior, state inconsistencies, and potential vulnerabilities, such as improper state transitions or incorrect calculations.

## Proof of Concept
The affected code utilizes low-level calls and inline assembly, which are prone to this bug when compiled with Solidity versions below 0.8.14. The optimizer may discard necessary memory operations, leading to incorrect state reads later in the contract's execution.

- **Affected Code Reference**: [MixedRouteQuoterV1.sol](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/lens/MixedRouteQuoterV1.sol#L53-L76)
  
For example, in the `katanaV3SwapCallback` function, inline assembly is used to handle outputs from swaps:

```solidity
assembly {
    let ptr := mload(0x40)
    mstore(ptr, amountReceived)
    mstore(add(ptr, 0x20), v3SqrtPriceX96After)
    mstore(add(ptr, 0x40), tickAfter)
    revert(ptr, 0x60)
}
```

In this case, if the optimizer mistakenly removes memory operations deemed unnecessary, subsequent calls relying on these values may operate on outdated data, potentially leading to erroneous behavior or exploits.

## Recommended Mitigation Steps
1. **Upgrade the Solidity Compiler**: Upgrade to version 0.8.14 or later to eliminate the optimizer bug.
2. **Disable Optimizations**: If an immediate upgrade is not feasible, disable the optimizer for affected contracts to ensure memory operations remain intact, albeit at the cost of increased gas consumption.
