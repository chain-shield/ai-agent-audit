# Vulnerability details

# Proof of concepts

Authorization check for [NonfungiblePositionManager.sol#mint](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungiblePositionManager.sol#L181) can be bypassed.

```solidity
  function mint(MintParams calldata params)
    external
    payable
    override
    checkDeadline(params.deadline)
    returns (uint256 tokenId, uint128 liquidity, uint256 amount0, uint256 amount1)
  {
    AuthorizationLib.checkPair(governance, params.token0, params.token1);
```

the check [AuthorizationLib.checkPair](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/external/libraries/AuthorizationLib.sol#L7) ensure that the governance can enforce only certain address can call mint the token out if the permission check is enabled.

```solidity
library AuthorizationLib {
  function checkPair(address governance, address token0, address token1) internal view {
    address[] memory tokens = new address[](2);
    tokens[0] = token0;
    tokens[1] = token1;
    require(IKatanaGovernance(governance).isAuthorized(tokens, msg.sender), "UA");
  }
}
```

However, even a user is restricted and cannot call [NonfungiblePositionManager.sol#mint](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungiblePositionManager.sol#L181)

he can bypass this restriction by:

- acquire some v2 liquidity.
- migrate v2 liquidity to v3 liquidity.
- the position v3 nft is minted to an unauthorized user.

we can check the [migration code](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/V3Migrator.sol#L53).


```solidity
 // mint v3 position
```

in the [NonfungiblePositionManager.sol#mint](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungiblePositionManager.sol#L181) authorization check, the msg.sender will be the migration contract, not the original msg.sender that mint the nft via migration.

unless the governance blocklist the migration contract,

the restricted user can abuse the migration to bypass the authorization check in [NonfungiblePositionManager.sol#mint](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungiblePositionManager.sol#L181)

# Recommendation

add the check in the [migration](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/V3Migrator.sol#L36) as well.

```solidity
  function migrate(MigrateParams calldata params) external override {
    AuthorizationLib.checkPair(governance, token0, token1); // @audit added check
    require(params.percentageToMigrate > 0, "Percentage too small");
    require(params.percentageToMigrate <= 100, "Percentage too large");

    // burn v2 liquidity to this address
```
