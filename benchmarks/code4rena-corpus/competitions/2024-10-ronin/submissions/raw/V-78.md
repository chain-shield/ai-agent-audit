# Vulnerability details

## Impact
`katanaV3SwapCallback` never checks whether the pool is deployed by the pool factory which can lead to address collision and stolen funds. Using computed pool addresses to verify the callback function callers is collision attack prone and can be abused in order to steal all token allowances.

## Proof of Concept
With the current state of the `V3SwapRouter` contract implementation, the `katanaV3SwapCallback` uses the `computePoolAddress` function in order to verify that the address that called it is a Katana pool deployed by the `KatanaV3Factory` attached to the router. This is done by computing the CREATE2 pool address using the `KATANA_V3_FACTORY`, `KATANA_V3_POOL_INIT_CODE_HASH` and underlying values passed in to the callbacks as arguments and the comparing that address to the `msg.sender`.

However, this method of verifying the caller address is collision prone, as the computation of the Create2 address is done by truncating a 256 bit keccak256 hash to 160 bits, meaning that for each address there are 2^96 possible hashes that will result in it after being truncated. Furthermore, what this means is that if a combination that results in an address controlled by a malicious user is found, all token allowances given to the `V3SwapRouter` contract can be stolen.

This issue can be found outside the contest's scope: `CallbackValidation::verifyCallback` and all of its usages.

In this [article](https://mystenlabs.com/blog/ambush-attacks-on-160bit-objectids-addresses) and this [report](https://github.com/sherlock-audit/2023-07-kyber-swap-judging/issues/90) from a past Sherlock contest, it is shown that this vulnerability will likely cost a few million dollars as of today, but due to the rapid advancement in computing capabilities, it is likely that it will cost much less a few years down the line.

Such issue was also found a valid Medium [here](https://solodit.cyfrin.io/issues/m-12-the-pool-verification-in-napierrouter-is-prone-to-collision-attacks-sherlock-napier-git)

## Recommended Mitigation Steps
In the `KatanaV3Factory` contract, create a function that verifies that a given pool address has been deployed by it using the `getPool` mapping. Example implementation:

```diff
contract KatanaV3Factory is IKatanaV3Factory, KatanaV3PoolDeployer {
    ...
	/// @inheritdoc IKatanaV3Factory
	mapping(address => mapping(address => mapping(uint24 => address))) public override getPool;
    ...
    
+	function isFactoryDeployedPool(
+	address tokenA, 
+	address tokenB, 
+	uint24 fee, 
+	address pool
+	) external view returns (bool) {
+		address fetchedPool = getPool[tokenA][tokenB][fee];
+	    return fetchedPool == pool;
+	}
}
```

And then use it when verifying the pool address both in `V3SwapRouter::katanaV3SwapCallback` and `CallbackValidation::verifyCallback`.
