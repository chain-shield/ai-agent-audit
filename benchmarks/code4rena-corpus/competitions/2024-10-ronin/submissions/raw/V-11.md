# Vulnerability details

## Proof of Concept
The token URI generation in `NonfungibleTokenPositionDescriptor` contract is buggy due to logical error.

Refer to the below `nativeCurrencyLabel` function used in the generation of `tokenURI` for the NFT Position. 

```
function nativeCurrencyLabel() public view returns (string memory) {
    uint256 len = 0;
    while (len < 32 && nativeCurrencyLabelBytes[len] != 0) {
      len++;
    }
    bytes memory b = new bytes(len);
    for (uint256 i = 0; i < len; i++) {
      b[i] = nativeCurrencyLabelBytes[i];
    }
    return string(b);
  }
```

The issue is in the logic of the function.

Lets say, `nativeCurrencyLabelBytes` array contains [a,b,c,d,e]
In the while loop, the `len` variable will increment to 4.

Hence the number of bytes allocated will only be 4 while the actual number of elements in the array was 5.

As a result, last element is being ignored due to this buggy logic while generate the base or quote symbol names when generate the tokenURI.

## Recommended Mitigation Steps

When allocating memory and copying over the elements, revise the logic as below.
```
   bytes memory b = new bytes(len + 1);
     for (uint256 i = 0; i <= len; i++) {
      b[i] = nativeCurrencyLabelBytes[i];
    }
```
