# Vulnerability details

## Impact
The `PoolInitializer` contract initializes katana V3 pools using `sqrtPriceX96`, which is obtained from the `slot0` state variable of the pool. This reliance on `slot0` exposes the contract to price manipulation attacks via MEV bots and flash loans. Since `slot0` reflects the most recent price data, malicious actors can exploit this by executing sandwich attacks, temporarily altering prices to their advantage. If other contracts depend on the initialized prices for liquidity provisioning or swaps, it can lead to incorrect pricing, financial losses, or liquidity issues in the protocol.

## Proof of Concept
In the `PoolInitializer` contract, the following code initializes a pool with a given `sqrtPriceX96`:

```solidity
pool = IKatanaV3Factory(factory).getPool(token0, token1, fee);
if (pool == address(0)) {
    pool = IKatanaV3Factory(factory).createPool(token0, token1, fee);
    IKatanaV3Pool(pool).initialize(sqrtPriceX96);
}
```

The initialization process can be exploited by an attacker who manipulates `slot0` before the `createAndInitializePoolIfNecessary` function is called. If the price is artificially altered, subsequent transactions that depend on this initialized pool may be executed based on misleading price data, leading to potential losses for users interacting with the protocol.

For reference, you can view the relevant code [here](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/base/PoolInitializer.sol#L15-L35).

## Recommended Mitigation Steps
1. **Implement TWAP for Price Initialization**: Utilize a Time-Weighted Average Price (TWAP) mechanism to determine `sqrtPriceX96` for pool initialization, thereby reducing the risk of manipulation from transient price changes.
  
2. **Add Slippage Checks**: Introduce slippage detection mechanisms during pool initialization that prevent the pool from being created or initialized if the price deviates significantly from a historical average.
