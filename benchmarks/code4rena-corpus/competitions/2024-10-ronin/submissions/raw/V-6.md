# Vulnerability details

## Impact
Affects the accuracy of the `totalPools` count, which is supposed to represent the total number of pools created by the factory. If a user attempts to create a pool with an existing token pair and fee, the function will return the existing pool address without incrementing the `totalPools` count. 

1. Assume the factory contract has already created a pool with token pair (TokenA, TokenB) and fee 3000.
2. The current `totalPools` count is 1.
3. A user calls the `createPool` function with the same token pair (TokenA, TokenB) and fee 3000.
4. The function checks the `getPool` mapping and finds that a pool with the same token pair and fee already exists.
5. The function returns the existing pool address without creating a new pool.
6. The `totalPools` count remains unchanged at 1, even though the user expected it to increase to 2.

## Proof of Concept
`createPool` function is responsible for creating new pools with unique token pairs and fees. However, the function has a flaw in its logic. It first checks if a pool with the same token pair and fee already exists using the `getPool` mapping. If a pool exists, the function returns the existing pool address without creating a new pool. The issue arises because the `totalPools` count is not incremented in this case.

[KatanaV3Factory.sol#L85-L90](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Factory.sol#L85-L91)
```solidity
require(getPool[token0][token1][fee] == address(0)); // <= @audit
pool = deploy(address(this), token0, token1, fee, tickSpacing);
getPool[token0][token1][fee] = pool;
getPool[token1][token0][fee] = pool;
emit PoolCreated(token0, token1, fee, tickSpacing, pool);
```
**Assume this Scenario**

1. Alice calls the `createPool` function with token pair (TokenA, TokenB) and fee 3000. The factory creates a new pool and increments the `totalPools` count to 1.

2. Later, Bob attempts to create a pool with the same token pair (TokenA, TokenB) and fee 3000.

3. The `createPool` function checks the `getPool` mapping and finds that a pool with the same token pair and fee already exists.

4. The function returns the existing pool address to Bob without creating a new pool.

5. However, the `totalPools` count remains unchanged at 1, even though Bob expected it to increase to 2.

## Recommended Mitigation Steps
By incrementing the `totalPools` count regardless of whether a new pool is created or an existing one is returned, the count will accurately reflect the number of pools created by the factory.
```diff
  function createPool(address tokenA, address tokenB, uint24 fee) external override returns (address pool) {
    // ...
-   require(getPool[token0][token1][fee] == address(0));
-   pool = deploy(address(this), token0, token1, fee, tickSpacing);
-   getPool[token0][token1][fee] = pool;
-   getPool[token1][token0][fee] = pool;
-   emit PoolCreated(token0, token1, fee, tickSpacing, pool);
+   pool = getPool[token0][token1][fee];
+   if (pool == address(0)) {
+     pool = deploy(address(this), token0, token1, fee, tickSpacing);
+     getPool[token0][token1][fee] = pool;
+     getPool[token1][token0][fee] = pool;
+     emit PoolCreated(token0, token1, fee, tickSpacing, pool);
+   }
+   totalPools++;
  }
```
