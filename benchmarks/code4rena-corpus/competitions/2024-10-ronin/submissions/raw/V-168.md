# Vulnerability details

## Summary
The `KatanaV3PoolBeacon` contract defines a constant for the initialization code hash of the pool proxy, referred to as `POOL_PROXY_INIT_CODE_HASH`. However, this constant is mismatched with the corresponding hash present in the `PoolAddress` library. This inconsistency poses a risk, as it can lead to incorrect contract deployment and functionality if the initialization code hash is not aligned with the actual implementation of the `KatanaV3PoolProxy`.

## Vulnerability Details
The vulnerability is the mismatch between the `POOL_PROXY_INIT_CODE_HASH` defined in the `PoolAddress` library and the hash of the actual creation code of `KatanaV3PoolProxy`. This mismatch suggests that either the creation code has changed, or the stored hash in the `PoolAddress` library is outdated. 

The relevant code snippets are as follows:

### In `PoolAddress`:
```javascript
bytes32 internal constant POOL_PROXY_INIT_CODE_HASH =
    0xb381dabeb6037396a764deb39e57a4a3f75b641ce3e9944b1e4b18d036e322e1;
```
### In `KatanaV3PoolProxy`:
```javascript
bytes public constant POOL_PROXY_INIT_CODE = type(KatanaV3PoolProxy).creationCode;
bytes32 public constant POOL_PROXY_INIT_CODE_HASH = keccak256(POOL_PROXY_INIT_CODE);
```
### `Test Failure`:
```javascript

```

## Recommendations

**Update Hash**: Ensure that the `POOL_PROXY_INIT_CODE_HASH` in `PoolAddress` reflects the latest creation code hash of `KatanaV3PoolProxy`. This can be done by recalculating the hash using the current creation code.
**Documentation**: Maintain proper documentation for any changes made to contract implementations and their corresponding initialization hashes to prevent future mismatches.
