# Vulnerability details

## Proof of Concept

In NonfungiblePositionManager.sol, the mint() function uses checkPair() to validate account permissions. Within checkPair(), the isAuthorized function checks if the calling account is authorized to interact with the tokens. However, within _isAuthorized, the following code introduces a potential vulnerability:

```  
    if (expiry == AUTHORIZED || block.timestamp > expiry) return true;
```

This line allows accounts with expired permissions to automatically be authorized, bypassing the $.allowed[account] whitelist check if block.timestamp > expiry.

Scenario:
1. Assume a user, userAccount, is initially added to the whitelist with an whitelistUntil is set to a future timestamp (e.g., expiry = block.timestamp + 1 week). This allows userAccount to interact with mint() function that check for authorization.
2. After a week, the expiry timestamp for userAccount passes. Normally, the expectation is that userAccount should no longer be authorized, and any further access should be restricted unless it’s re-whitelisted.
3. However, when mint() is called by userAccount:
checkPair() calls isAuthorized(), which in turn calls _isAuthorized(). _isAuthorized() checks block.timestamp > expiry, and since expiry has passed, userAccount is now unintentionally authorized because block.timestamp > expiry returns true. userAccount bypasses the $allowed[account] check and receives authorization due to the  block.timestamp > expiry condition.

## Recommended Mitigation Steps
Modify the _isAuthorized function to explicitly disallow accounts whose expiry date has passed. For example:

```
 
  function _isAuthorized(Permission storage $, address account) private view returns (bool) {
    uint256 expiry = $.whitelistUntil;
 -   if (expiry == UNAUTHORIZED) return false;
 -   if (expiry == AUTHORIZED || block.timestamp > expiry) return true;

 +   if (expiry == UNAUTHORIZED || block.timestamp > expiry) return false;
 +   if (expiry == AUTHORIZED) return true;
 
    return $.allowed[account];
  }
```
