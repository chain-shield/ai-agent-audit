# Vulnerability details

## Proof of Concept
Reentrancy Vulnerability: Reentrancy occurs when a contract allows an external contract to call back into the original function before the first invocation completes. This is particularly risky in functions that involve token transfers or external calls, as it may allow an attacker to repeatedly drain funds.

Proof of Concept: If an attacker implements a malicious contract and calls v3SwapExactInput or any other function involving a transfer, they can potentially reenter the contract before the state is updated.
Attacker initiates a swap by calling the contract.
The contract transfers funds as part of the swap.
The malicious contract reenters the function by calling back into dispatch.
The attacker drains more funds than initially intended.

Impact:Reentrancy can lead to substantial financial loss as the attacker could drain all assets available for the contract.

## Recommended Mitigation Steps
1. Use the Checks-Effects-Interactions pattern.
2. Consider using the ReentrancyGuard from OpenZeppelin to prevent multiple entries into sensitive functions.
3. Ensure that external calls occur only after all contract state modifications are completed.

Example:The DAO hack in 2016 exploited a reentrancy vulnerability, resulting in over $60 million in ETH being stolen.
