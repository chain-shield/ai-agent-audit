# Vulnerability details

## Summary
The `AggregateRouter` contract is designed to execute commands and handle ETH transactions. It includes mechanisms to receive ETH directly and execute commands that may involve ETH. However, initially, it lacked a mechanism to withdraw ETH, which could lead to funds being stuck in the contract.

## Vulnerability Details
The `AggregateRouter` contract did not include a function to `withdraw` ETH, which could result in funds being permanently locked within the contract. This is a significant issue as it restricts the contract's ability to manage its ETH balance effectively.

The contract includes a receive function, which allows it to accept `ETH` directly. While this is useful for receiving funds, without a corresponding withdrawal mechanism, any ETH sent to the contract could become irretrievable.

## Impact
Without a `withdrawal` function, any `ETH` sent to the contract, either directly through the receive function or through command execution, would be irretrievable. This could lead to a loss of funds if the contract accumulates ETH over time.

## Tools Used
Manual Review

## Recommendations
Implement a function that allows the contract owner to withdraw ETH. This function should include proper access control to ensure only authorized parties can execute it.
