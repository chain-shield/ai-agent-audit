# Vulnerability details

## Proof of Concept
ETH Address (address(0)) Flagging Issue
Vulnerability Explanation:
ETH is defined as address(0), which represents the native currency on most Ethereum-based systems (e.g., ETH on Ethereum). However, address(0) is often used as a burn address. If functions use ETH without correctly handling it as a reference rather than a real address, transactions could inadvertently burn tokens by sending them to address(0).

Proof of Concept (PoC):
Suppose there’s a function that checks the recipient address to determine whether to send tokens or native currency. Without explicit checks, the function may send tokens to address(0) instead of using it as an indicator of ETH:
function withdraw(uint256 amount, address recipient) external {
    if (recipient == Constants.ETH) {
        payable(msg.sender).transfer(amount);
    } else {
        token.transfer(recipient, amount);
    }
}
In this example, if recipient is misinterpreted as address(0), it will send tokens to address(0), effectively burning them rather than transferring to a valid user address.

Impact: This can lead to accidental loss of tokens if address(0) is misused, and could be catastrophic if large transfers occur to this address.

## Recommended Mitigation Steps
Ensure that ETH is only used in specific conditions for native token transfers. Implement separate logic to handle ETH transfers instead of allowing address(0) to be misused as a destination address.
