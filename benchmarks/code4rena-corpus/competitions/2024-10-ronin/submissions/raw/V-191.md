# Vulnerability details

## Proof of Concept
Visibility of Internal State Variables: The lockedBy variable is marked as internal, which means it can be accessed by any derived contracts. This can expose the lock mechanism to manipulation.

Proof of Concept: A derived contract can modify the lockedBy state directly, bypassing the intended lock mechanism.
contract Derived is LockAndMsgSender {
    function exploit() external {
        lockedBy = msg.sender; // Directly modifying lockedBy
    }
}
Impact: This could allow derived contracts to bypass the lock, leading to unauthorized actions.

## Recommended Mitigation Steps
1. Change the visibility of lockedBy to private if it should not be accessible to derived contracts.
2. Carefully control the inheritance of sensitive state variables.
