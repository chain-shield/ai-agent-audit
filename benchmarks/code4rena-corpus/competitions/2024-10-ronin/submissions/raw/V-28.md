# Vulnerability details

In the fee growth accumulation logic within the swap function, instead of accumulating fees, the current implementation overwrites the previous fee growth values, potentially leading to a decrease in the total fee growth.

Because the swap function uses an assignment operation instead of addition when updating the fee growth variables. Specifically: [KatanaV3Pool.sol#L715-L716](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L714-L716)
```solidity
    // update fee growth global
    if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128; // <= @audit
    else feeGrowthGlobal1X128 = state.feeGrowthGlobalX128; // <= @audit
```
This code directly assigns the new fee growth value to the global variable, overwriting any previously accumulated fees. The correct behavior should be to add the new fee growth to the existing value.

## Impact
Liquidity providers may receive fewer fees than they are entitled to, resulting in financial losses. 

## Proof of Concept
Assume the following scenario:

   * The pool is initialized with `feeGrowthGlobal0X128 = 100`.
   * A swap occurs with `zeroForOne = true` and `state.feeGrowthGlobalX128 = 50`.
   * After the swap, `feeGrowthGlobal0X128` becomes 50, which is less than its initial value.

This sequence clearly demonstrates that the fee growth can decrease, violating the core invariant of the protocol that fee growth should always increase or remain the same.

[KatanaV3Pool.sol#L714-L735](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L714-L735)

```solidity
if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128; // <= @audit

(amount0, amount1) = zeroForOne == exactInput

// do the transfers and collect payment
if (zeroForOne) {

  require(balance0Before.add(uint256(amount0)) <= balance0(), "IIA");
} else {
  if (amount0 < 0) TransferHelper.safeTransfer(tokenOut, recipient, uint256(-amount0));

  uint256 balance1Before = balance1();
  IKatanaV3SwapCallback(msg.sender).katanaV3SwapCallback(amount0, amount1, data);
  require(balance1Before.add(uint256(amount1)) <= balance1(), "IIA");
}
```
Instead of accumulating the fees, the code is overwriting the previous values.

## Recommended Mitigation Steps
The fee growth accumulation logic should be changed to add the new fee growth to the existing value instead of overwriting it. 
```diff
- if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128;
- else feeGrowthGlobal1X128 = state.feeGrowthGlobalX128;
+ if (zeroForOne) feeGrowthGlobal0X128 += state.feeGrowthGlobalX128;
+ else feeGrowthGlobal1X128 += state.feeGrowthGlobalX128;
```
