# Vulnerability details

## Proof of Concept
In the `NonfungiblePositionManager::mint` function, the token id to be minted is based on the state level variable `_nextId`.

So, every time a new NFT position is created, the token Id is internally generated in the `mint` function logic by incrementing the `_nextId`. 

But, the vulnerability lies in the data type of  `_nextId` variable.

Refer to the below code snippet, where the position mapping is capable of supporting positions upto max of uint256, the tokenId only supports upto uint176.
 

```
  mapping(uint256 => Position) private _positions;

  uint176 private _nextId = 1;
```
Data type  Max value
uint176 -> 95780971304118053647396689196894323976171195136475135
uint256 -> 115792089237316195423570985008687907853269984665640564039457584007913129639935

Hence, the position manager can only support up to max of uint176 - 1.
Once the _nextId reaches its max supported value, the transaction will start to revert preventing the minting of NFT position tokens.

After that point onwards, the new positions cannot be minted by the contract.

## Recommended Mitigation Steps
redefine the `_nextId` as uint256
 uint256 private _nextId = 1;
