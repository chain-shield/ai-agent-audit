# Vulnerability details

## Proof of Concept

In KatanaV3Pool.sol the burn function can potentially be called directly, bypassing critical validation checks and operational steps normally enforced in decreaseLiquidity(). Specifically, the checks for token authorization (isAuthorizedForToken) and deadline (checkDeadline) are skipped if burn is invoked directly. These validations are crucial for ensuring that only the authorized token owner can burn the position and that the operation is performed within a valid timeframe.

When decreaseLiquidity is called, it performs several essential actions:

1. Position Eligibility Checks
Ensures that the parameters are valid, minimum liquidity requirements are met, and the user's position aligns with the pool’s current state.

2. Fee Calculation and Distribution
Accumulates or distributes fees to the position before liquidity is removed, ensuring accurate fee accounting.

3. Internal State Updates
Reduces active liquidity and updates position records to reflect the actual amount of liquidity removed.

If burn is called directly and these steps are skipped, the following issues may arise:

1. Incorrect fee calculation or distribution 
Fees may not be properly distributed, resulting in potential losses for either the user or the pool.

2. Pool state inconsistency 
Missing liquidity updates may cause discrepancies between real and recorded liquidity amounts.

3. Locked funds 
If burn bypasses necessary checks, the contract state could end up inconsistent, potentially leading to locked or inaccessible funds for legitimate users.

Scenario:
1. Alice creates a position
2. She calls burn function
3. The burn function will executed and there will be inconsistency between the data recorded in the KatanaV3Pool and NonfungiblePositionManager

Consider restricting direct access to burn by requiring that only the positionManager can invoke it. For example:

```

    external
    override
    lock

  {

+   if (msg.sender != positionManager) {

+   }

      ModifyPositionParams({
        owner: msg.sender,
        tickLower: tickLower,
        tickUpper: tickUpper,
        liquidityDelta: -int256(amount).toInt128()
      })
    );

    amount0 = uint256(-amount0Int);
    amount1 = uint256(-amount1Int);

    if (amount0 > 0 || amount1 > 0) {
      (position.tokensOwed0, position.tokensOwed1) =
        (position.tokensOwed0 + uint128(amount0), position.tokensOwed1 + uint128(amount1));
    }

    emit Burn(msg.sender, tickLower, tickUpper, amount, amount0, amount1);
  }
```
