# Vulnerability details

## Proof of Concept
The `flash` function in the `KatanaV3Pool` contract is vulnerable to a reentrancy attack. 
the contract makes an external call (`katanaV3FlashCallback`) **before** updating its state (specifically, `feeGrowthGlobal0X128`, `feeGrowthGlobal1X128`, and transferring protocol fees).
```
      IKatanaV3FlashCallback(msg.sender).katanaV3FlashCallback(fee0, fee1, data);//@audit 

      uint256 balance0After = balance0();
      uint256 balance1After = balance1();
      address treasury = IKatanaV3Factory(factory).treasury();

      // ... (State updates and transfers happen after the external call)

```

## Attack Scenario:

1. Malicious Contract: An attacker deploys a malicious contract (AttackerContract) that implements the IKatanaV3FlashCallback interface. This contract will house a malicious implementation of the katanaV3FlashCallback function.

2. Initiating the Attack: The attacker calls the flash function on the KatanaV3Pool contract, providing a small initial flash loan amount (just enough to cover fees).

3. Reentrancy Exploitation:
The KatanaV3Pool contract sends the initial flash loan to the AttackerContract.
The pool then invokes the katanaV3FlashCallback function on the AttackerContract.
Critical Point: Inside the malicious katanaV3FlashCallback, the attacker recursively calls the flash function on the KatanaV3Pool contract again before the pool has a chance to update its state or receive the initial loan back. This is possible because the lock modifier, intended as a reentrancy guard, is bypassed due to the external call occurring before state updates.
4. Recursive Draining:

The pool, oblivious to the ongoing attack, processes the reentrant flash calls as new, legitimate requests.
The attacker can repeat this process numerous times within a single transaction, effectively draining the pool's liquidity.
6. Transferring Stolen Funds:

Once the recursive calls reach a certain depth (or the pool is drained), the attacker's contract transfers the stolen tokens from itself to an address controlled by the attacker.
