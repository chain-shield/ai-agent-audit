# Vulnerability details

## Proof of Concept

The [execute](https://github.com/ronin-chain/katana-operation-contracts/blob/27f9d28e00958bf3494fa405a8a5acdcd5ecdc5d/src/aggregate-router/AggregateRouter.sol#L49) function enables the execution of multiple swap operations within a single transaction, such as swapping ETH for ERC20 tokens. When selling ETH, users must send the full amount upfront. However, there are scenarios where only part of the ETH is spent during the swaps, and the remaining unspent ETH is not refunded. These scenarios include:

1.When `sqrtPriceLimitX96` is set, the swap can stop early if the limit price is reached, leaving some ETH unspent.

2.Positive slippage can result in more favorable swap rates, causing exact output swaps to use less ETH than expected, leaving some unspent.

3.A swap may be interrupted if there is insufficient liquidity in the pool, leading to unspent ETH.

```solidity
function execute(bytes calldata commands, bytes[] calldata inputs) public payable override isNotLocked {
    bool success;
    bytes memory output;
    uint256 numCommands = commands.length;
    if (inputs.length != numCommands) revert LengthMismatch();

    // loop through all given commands, execute them and pass along outputs as defined
    for (uint256 commandIndex = 0; commandIndex < numCommands;) {
      bytes1 command = commands[commandIndex];

      bytes calldata input = inputs[commandIndex];

      (success, output) = dispatch(command, input);

      if (!success && successRequired(command)) {
        revert ExecutionFailed({ commandIndex: commandIndex, message: output });
      }

      unchecked {
        commandIndex++;
      }
    }
  }

```
The [v2SwapExactOutput](https://github.com/ronin-chain/katana-operation-contracts/blob/27f9d28e00958bf3494fa405a8a5acdcd5ecdc5d/src/aggregate-router/modules/katana/v2/V2SwapRouter.sol#L83C1-L96C4) function does not include a method to return unspent ETH.

```solidity
  function v2SwapExactOutput(
    address recipient,
    uint256 amountOut,
    uint256 amountInMaximum,
    address[] calldata path,
    address payer
  ) internal {
    (uint256 amountIn, address firstPair) =
      KatanaV2Library.getAmountInMultihop(KATANA_V2_FACTORY, KATANA_V2_PAIR_INIT_CODE_HASH, amountOut, path);
    if (amountIn > amountInMaximum) revert V2TooMuchRequested();

    payOrPermit2Transfer(path[0], payer, firstPair, amountIn);
    _v2Swap(path, recipient, firstPair);
  }
```

## Impact
User not received unspent ETH after swapping.
 

## Tools Used

Manual Auditing

## Recommended Mitigation Steps
Consider returning unspent ETH to the caller at the end of the `v3SwapExactInput`, `v3SwapExactOutput`, `v2SwapExactInput`, and `v2SwapExactOutput` functions. This can be achieved using `PeripheryPayments.refundETH()`.
