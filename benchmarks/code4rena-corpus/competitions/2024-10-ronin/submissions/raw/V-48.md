# Vulnerability details

The `swap` function logic correctly updates the `feeGrowthGlobal0X128` and `feeGrowthGlobal1X128` variables based on the swap direction (`zeroForOne`). However, it fails to make the corresponding updates to the `totalFeeGrowth0` and `totalFeeGrowth1` variables. This results in the total fee growth variables falling out of sync with the actual fee growth.

```solidity
// update fee growth global
if (zeroForOne) feeGrowthGlobal0X128 = state.feeGrowthGlobalX128; // <= FOUND
else feeGrowthGlobal1X128 = state.feeGrowthGlobalX128; // <= FOUND
```

See below for the key steps are:

1. The `initialize` function is called with `sqrtPriceX96 = 79228162514264337593543950336`.
2. The `mint` function is called with `recipient = 0`, `tickLower = -887272`, `tickUpper = 887272`, `amount = 1`, and some `data`.
3. The `swap` function is called with `recipient = 1`, `zeroForOne = true`, `amountSpecified = 100`, `sqrtPriceLimitX96 = 4295128739`, and some data.

After these function calls, the `feeGrowthGlobal0X128` variable has a value of `340282366920938463463374607431768211` while the `totalFeeGrowth0` variable remains at its initial value of 0.

## Proof of Concept
1. Alice initializes the pool with a valid `sqrtPriceX96` value.
2.  Bob mints some liquidity in the pool by calling the `mint` function with appropriate parameters.
3. Alice performs a swap by calling the `swap` function with valid parameters, such as `zeroForOne = true`, `amountSpecified = 100`, and `sqrtPriceLimitX96 = 4295128739`.
4. After the swap, check the values of `feeGrowthGlobal0X128`, `feeGrowthGlobal1X128`, `totalFeeGrowth0`, and `totalFeeGrowth1`.

If you observe, `feeGrowthGlobal0X128` has been updated based on the swap, but `totalFeeGrowth0` remains unchanged.

## Recommended Mitigation Steps
Update the `totalFeeGrowth0` and `totalFeeGrowth1` variables whenever the corresponding `feeGrowthGlobal0X128` and `feeGrowthGlobal1X128` variables are updated.
