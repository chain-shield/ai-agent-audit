# Vulnerability details

## Proof of Concept
`flash` loan function lacks validation for zero amounts. The function processes the entire flash loan flow, including fee calculations and callback execution, even when no actual value transfer occurs. This happens because the only validations performed are for flash loan enablement and pool liquidity:

```solidity
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) {
    require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");
    uint128 _liquidity = liquidity;
    require(_liquidity > 0, "L");
    // Continues execution even with amount0 = amount1 = 0
}
```
Root cause: Missing validation allowing flash loans with both amount0 and amount1 set to zero.

Referenced code paths in [KatanaV3Pool.sol.flash#L747-L766](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L747-L766)
```solidity
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) external override lock {
    // @Issue: No validation for zero amounts
    require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");
    
    uint128 _liquidity = liquidity;
    require(_liquidity > 0, "L");
    
    // @Issue: Processes zero amounts
    uint256 fee0 = FullMath.mulDivRoundingUp(amount0, fee, 1e6);
    uint256 fee1 = FullMath.mulDivRoundingUp(amount1, fee, 1e6);
    
    // @Issue: Executes transfers for zero amounts
    if (amount0 > 0) TransferHelper.safeTransfer(_token0, recipient, amount0);
    if (amount1 > 0) TransferHelper.safeTransfer(_token1, recipient, amount1);
```

**Impact**
1. Unnecessary computation and storage operations
2. Potential spam vector through zero-value transactions
3. Processing meaningless flash loans
4. Wasted computational resources on the blockchain

* High likelihood due to lack of prevention
* Low direct financial impact
* Significant operational impact through resource waste

## Recommended Mitigation Steps
This ensures that at least one token amount must be non-zero for the flash loan to proceed, preventing unnecessary transactions and resource consumption.
```diff
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) external override lock {
+   require(amount0 > 0 || amount1 > 0, "Zero amounts");
    require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");
    // ...
}
```
