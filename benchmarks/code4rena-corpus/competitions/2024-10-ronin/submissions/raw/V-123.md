# Vulnerability details

## Proof of Concept
According to the [ReadMe](https://github.com/code-423n4/2024-10-ronin#scope):
>If you discover a bug in any contract or library outside of the files listed above that impact following contracts, we will consider the issue valid:
>
> - KatanaGovernance
>- AggregateRouter
>- KatanaV3Factory
>- NonfungiblePositionManager
>- V3Migrator
>- KatanaV3PoolBeacon
>- KatanaV3Pool

This issue directly affects the `NonFungiblePositionManager` contract.

If we take a look at `NFTDescriptor.sol`, it handles token symbols in SVG generation (via `generateSVGImage()` function. The symbols are used directly in text elements within the SVG but there is only basic escaping of quotes via `escapeQuotes()` function, but no other sanitization.

Most especially, 

In [`generateName()`](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/libraries/NFTDescriptor.sol#L148-L180), where token symbols are used directly:
```solidity
string(
  abi.encodePacked(
    "Katana - ",
    feeTier,
    " - ",
    escapeQuotes(params.quoteTokenSymbol),
    "/", 
    escapeQuotes(params.baseTokenSymbol),
    ...
  )
);
```

Also in [`generateDescriptionPartOne()`](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/libraries/NFTDescriptor.sol#L102-L121), where symbols are used:
```solidity
string(
  abi.encodePacked(
    "This NFT represents a liquidity position in a Katana V3 ",
    quoteTokenSymbol,
    "-",
    baseTokenSymbol,
    ...
  )
);
```

The [`escapeQuotes()`](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/libraries/NFTDescriptor.sol#L80-L101) function only handles double quotes but does not prevent other special characters that could be used for XSS attacks, such as:

- `<script>` tags
- `<img>` tags with onerror handlers 
- JavaScript event handlers
- External script references

An attacker could create a token with a malicious symbol like:
```
<script href=//malicious.com></script>
```
or
```
<img src=x onerror=alert(1)>
```

And this would be directly inserted into the SVG, executing malicious JavaScript when the NFT is viewed on marketplaces or other platforms.

But most importantly,  if we take a look at [`NonfungibleTokenPositionDescriptor.sol`](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungibleTokenPositionDescriptor.sol#L46-L86):

```solidity
function tokenURI(INonfungiblePositionManager positionManager, uint256 tokenId)
    external
    view
    override
    returns (string memory)
{
    // Get position details including token addresses
    (,, address token0, address token1, uint24 fee, int24 tickLower, int24 tickUpper,,,,,) =
        positionManager.positions(tokenId);

    // Get token symbols directly from the token contracts
    string memory quoteTokenSymbol = quoteTokenAddress == WRON 
        ? nativeCurrencyLabel()
        : SafeERC20Namer.tokenSymbol(quoteTokenAddress);
    string memory baseTokenSymbol = baseTokenAddress == WRON 
        ? nativeCurrencyLabel() 
        : SafeERC20Namer.tokenSymbol(baseTokenAddress);

    // These potentially malicious symbols are passed into NFTDescriptor
    return NFTDescriptor.constructTokenURI(
        NFTDescriptor.ConstructTokenURIParams({
            quoteTokenSymbol: quoteTokenSymbol, // Potentially malicious
            baseTokenSymbol: baseTokenSymbol,   // Potentially malicious
            // ... SNIP
        })
    );
}
```

The issue starts here because token symbols are fetched directly from token contracts without sanitization. An attacker could deploy a malicious token with an XSS payload as its symbol. These symbols are passed directly to `NFTDescriptor`

Then in [`NonfungiblePositionManager.sol`](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/periphery/NonfungiblePositionManager.sol#L237-L240):

```solidity
function tokenURI(uint256 tokenId) public view override(ERC721, IERC721Metadata) returns (string memory) {
    require(_exists(tokenId));
    // Calls the vulnerable tokenURI function in NonfungibleTokenPositionDescriptor
    return INonfungibleTokenPositionDescriptor(_tokenDescriptor).tokenURI(this, tokenId);
}
```

`NonFungiblePositionManager.sol` is the main entry point for NFT metadata retrieval. When NFT marketplaces or other platforms request an NFT's metadata, they call this `tokenURI` function. The function delegates to the vulnerable `NonfungibleTokenPositionDescriptor`

The attack flow would be:

1. Attacker deploys a malicious token with an XSS payload as its symbol:
```solidity
contract MaliciousToken {
    function symbol() public pure returns (string memory) {
        return "<script href=//malicious.com></script>";
    }
}
```

2. Attacker creates a position in NonfungiblePositionManager using their malicious token

3. When the NFT is viewed on marketplaces:
- `tokenURI()` is called on NonfungiblePositionManager
- This calls `tokenURI()` on NonfungibleTokenPositionDescriptor
- The malicious symbol is embedded in the SVG
- The XSS payload executes in users' browsers
