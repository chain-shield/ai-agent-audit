# Vulnerability details

## Proof of Concept
When a user calls ```NonfungibleManager.mint()``` to provide liquidity to a pool, the following ```pay``` function is called inside the ```LiquidityManagement.katanaV3MintCallback()``` function to transfer the payments of token0 and token1 from the user to the pool: 

```javascript
function pay(address token, address payer, address recipient, uint256 value) internal {
    if (token == WETH9 && address(this).balance >= value) {
      IWETH9(WETH9).deposit{ value: value }(); // wrap only what is needed to pay
      IWETH9(WETH9).transfer(recipient, value);
    } else if (payer == address(this)) {
      // pay with tokens already in the contract (for the exact input multihop case)
      TransferHelper.safeTransfer(token, recipient, value);
    } else {
      // pull payment
      TransferHelper.safeTransferFrom(token, payer, recipient, value);
    }
  }
```

However, when one of the tokens is WETH9, the user can send ETH instead and the first branch of the pay function will be executed, which swaps ETH for WETH9. Since it is hard for the user to know how much ETH he needs to send since the actual amounts of token0 and token1 will be calculated during the call based on tick range and current tick, there is very likely a chance that leftover ETH will be in the ```NonfungiblePositionManager``` contract.

Such leftover ETH can be stolen by another liquidity provider in two ways: 
1) call ```NonfungibleManager.mint()``` to use the leftover ETH to pay for the liquidity;
2) simply call ```NonfungibleManager.refundETH()``` to steal it.

Of course, the first user can write another function to wrap the ```NonfungibleManager.mint()``` and 
```NonfungibleManager.refundETH()``` into one transaction. However, no such document is provided in the source code and in my opinion, such refund should be done  as part of the functionality of 
```NonfungibleManager.mint()``` as suggested below.

## Recommended Mitigation Steps
add ```refundETH()``` as the last line for ```NonfungibleManager.mint()``` so that there is no leftover ETH In the ```NonfungiblePositionManager```.
