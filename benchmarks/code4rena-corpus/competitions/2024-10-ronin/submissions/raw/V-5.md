# Vulnerability details

`createPool` function takes three parameters. `tokenA`, `tokenB`, and `fee`. It is responsible for creating a new pool with the given token pair and fee. However, the function does not validate that both `tokenA` and `tokenB` are non-zero addresses.

The bug happens because the function only checks if `token0` is not the zero address after sorting `tokenA` and `tokenB` based on their addresses. It does not check if `token1` is also a non-zero address. This allows the creation of a pool where one of the token addresses is zero. [KatanaV3Factory.sol#L77-L89](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Factory.sol#L77-L91)
```solidity
  function createPool(address tokenA, address tokenB, uint24 fee) external override returns (address pool) {
    require(msg.sender == IKatanaGovernance(owner).getPositionManager(), "KatanaV3Factory: INVALID_POSITION_MANAGER");

    require(tokenA != tokenB);
    (address token0, address token1) = tokenA < tokenB ? (tokenA, tokenB) : (tokenB, tokenA);
    require(token0 != address(0)); // <= @audit Only checks token0 for zero address, allows token1 to be zero
    int24 tickSpacing = feeAmountTickSpacing[fee];
    require(tickSpacing != 0);
    require(getPool[token0][token1][fee] == address(0));
    pool = deploy(address(this), token0, token1, fee, tickSpacing);
    getPool[token0][token1][fee] = pool; // <= @audit Allows creating a pool with token1 as zero address
    // populate mapping in the reverse direction, deliberate choice to avoid the cost of comparing addresses
    getPool[token1][token0][fee] = pool; // <= @audit Allows creating a pool with token1 as zero address
    emit PoolCreated(token0, token1, fee, tickSpacing, pool);
  }
```
To reproduce the issue:

1. Call `createPool` with `tokenA = 0`, `tokenB = non-zero address`, and a valid `fee`.
2. The function will create a pool with `token0 = 0` and `token1 = non-zero address`.
3. The `getPool` mapping will be updated with the pool address for `(0, token)` pair.

## Impact
Users interacting with such pools may encounter issues such as the inability to trade, add liquidity, or perform other pool-related operations correctly. It can lead to unexpected behavior and inconsistencies in the `getPool` mapping.

Moreover, the existence of pools with zero token addresses can cause confusion and make it difficult for users to identify and interact with legitimate pools. It may also open up possibilities for attackers to exploit these invalid pools for malicious purposes.

## Proof of Concept
This vulnerability allows the creation of a pool with one of the token addresses being the zero address (0x0). As a result, it violates the assumption that pools should only be created with valid, non-zero token addresses.

Consider this scenario

1. Alice, an attacker, calls the `createPool` function with the following parameters:

   * `tokenA`: `0x0000000000000000000000000000000000000000` (zero address)
   * `tokenB`: `0x968760/08226d280f3343beb0764f445ce03e7f837` (a valid non-zero address)
   * `fee`: `3000` (a valid fee amount)

2. The `createPool` function executes without reverting because it only checks if `token0` is not the zero address after sorting `tokenA` and `tokenB` ([KatanaV3Factory.sol#L82](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Factory.sol#L82)).

3. A new pool is created with the following token addresses:

   * `token0`: `0x0000000000000000000000000000000000000000` (zero address)
   * `token1`: `0x968760/08226d280f3343beb0764f445ce03e7f837` (the valid non-zero address)

4. The `getPool` mapping is updated with the pool address for both (token0, token1) and (token1, token0) pairs ([KatanaV3Factory.sol#L87-L89](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Factory.sol#L87-L89)), allowing the pool with a zero token address to be accessible.

## Recommended Mitigation Steps
Check in the `createPool` function to ensure that both `tokenA` and `tokenB` are non-zero addresses before creating the pool.
```diff
function createPool(address tokenA, address tokenB, uint24 fee) external override returns (address pool) {
    require(msg.sender == IKatanaGovernance(owner).getPositionManager(), "KatanaV3Factory: INVALID_POSITION_MANAGER");

    require(tokenA != tokenB);
+   require(tokenA != address(0) && tokenB != address(0), "KatanaV3Factory: ZERO_ADDRESS");
    (address token0, address token1) = tokenA < tokenB ? (tokenA, tokenB) : (tokenB, tokenA);
-   require(token0 != address(0));
    int24 tickSpacing = feeAmountTickSpacing[fee];

    // ...
}
```
