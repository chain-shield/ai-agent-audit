# Vulnerability details

## Proof of Concept

For context, the vulnerable function is here: 


```solidity
function tokenRatioPriority(address token, uint256 chainId) public view returns (int256) {
    if (token == WRON) {
      return TokenRatioSortOrder.DENOMINATOR;
    }
    if (chainId == 2020) {
      if (token == USDC) {
        return TokenRatioSortOrder.NUMERATOR_MOST;
      } else if (token == WETH) {
        return TokenRatioSortOrder.NUMERATOR_MORE;
      } else if (token == WBTC) {
        return TokenRatioSortOrder.DENOMINATOR_MOST;
      } else {
        return 0;
      }
    }
    return 0;
  }
```

The `tokenRatioPriority` function uses `int256` to store the priority value. If a large enough value is passed into the function, it causes an integer overflow. For example, if `TokenRatioSortOrder.NUMERATOR_MOST` is a very large number, and `chainId` is also large, the sum of these values could exceed the maximum value that can be stored in an `int256`. This can lead to unexpected behavior, and other vulnerabilities.

The use of `int256` and the possibility of large values being passed into the function, particularly `TokenRatioSortOrder.NUMERATOR_MOST`, create a risk of overflow--if not carefully handled.
