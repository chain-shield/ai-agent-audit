# Vulnerability details

## Proof of Concept
In the `KatanaGovernance::createPair` function, no validation was done to check that the correct pair was passed to the function, so anything can be supplied even an `address(0)` or a pair of tokens with the same addresses. Having both tokens be the same would create an invalid or nonsensical pair. A pair between the same token address makes no sense because there is no reason to swap between identical tokens. It would also make liquidity provision, pricing, and other mechanics irrelevant or broken.
```solidity
    function createPair(address tokenA, address tokenB) external returns (address pair) {
        address sender = _msgSender();
        address[] memory tokens = new address[](2);
        // @audit lack of tokens check
        tokens[0] = tokenA;
        tokens[1] = tokenB;
        if (!isAuthorized(tokens, sender)) revert Unauthorized();

        pair = _v2Factory.createPair(tokenA, tokenB);
    }
```

## Impact
- Invalid Pairs: If the factory creates a pair with the same tokens, the pair would be useless and could confuse both users and the system.
- Wasted Gas: The user would spend gas to create a pair that cannot be utilized.
- Potential for System Errors: Subsequent functions interacting with such a pair might not handle it properly, leading to errors or unexpected behavior in the system.

## Recommended Mitigation Steps
```diff
    function createPair(address tokenA, address tokenB) external returns (address pair) {
        address sender = _msgSender();
+       if (tokenA == tokenB) {
+           revert("Tokens must be different");
+       }
```
