# Vulnerability details

The use of `slot0` in getting important parameters like the `sqrtPricex96`, `tickBefore` and `tickAfter` is risky since slot0 is highly manipulatable

## Proof of Concept
Multiple places in this contract use `slot0` fro getting values of variables

for instance let's look at this function in the `PoolInitializer.sol`
```solidity
function createAndInitializePoolIfNecessary(address token0, address token1, uint24 fee, uint160 sqrtPriceX96)
    external
    payable
    override
    returns (address pool)
  {
...
      //@audit
      (uint160 sqrtPriceX96Existing,,,,,,,) = IKatanaV3Pool(pool).slot0();
      if (sqrtPriceX96Existing == 0) {
        IKatanaV3Pool(pool).initialize(sqrtPriceX96);
...
}
``` 
from the code above we can see that the pool is being intialized with a `sqrtPriceX96` from slot0 which is highly manipulable and as a result not advised.

## Recommended Mitigation Steps
use a TWAP to get these values.
