# Vulnerability details


### Summary
The `multicall` function in `Multicall.sol` is vulnerable to reentrancy attacks due to the use of `delegatecall` with untrusted user input and the absence of reentrancy protection. Malicious contracts can exploit this to manipulate contract state or execute unauthorized operations.

---

### Vulnerability Location
- **Contract:** `Multicall.sol`
- **Function:** `multicall`
- **Code Snippet:**
    ```solidity
    (bool success, bytes memory result) = address(this).delegatecall(data[i]);
    ```

---

### Proof of Concept

1. **Delegatecall Vulnerability:**  
   `delegatecall` executes code in the context of the calling contract, and using untrusted input (`data[i]`) makes the function susceptible to reentrancy.
   
2. **Reentrancy Risk:**  
   The absence of reentrancy guards allows attackers to re-enter the contract and execute multiple calls, which can manipulate the contract state.

---

### Recommended Mitigation Steps

1. **Use `ReentrancyGuard`:**  
   Add OpenZeppelin’s `ReentrancyGuard` to prevent reentrancy.

2. **Avoid `delegatecall` with Untrusted Input:**  
   If possible, avoid using `delegatecall` with user-provided data. Ensure functions called are protected from reentrancy.

3. **Implement Access Control:**  
   Restrict access to critical functions via `delegatecall` to authorized users.

4. **Checks-Effects-Interactions Pattern:**  
   Update contract state before making external calls to minimize reentrancy risks.

---

### Conclusion
The vulnerability in the `multicall` function presents a significant reentrancy risk, requiring immediate mitigation.
