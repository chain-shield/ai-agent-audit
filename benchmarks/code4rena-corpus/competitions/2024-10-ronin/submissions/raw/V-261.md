# Vulnerability details

## Summary
The `quoteExactInput` function in MixedRouteQuoterV1 has a critical index tracking issue that causes array out-of-bounds errors or incorrect data storage when handling mixed routes containing both V2 and V3 pools.

The `quoteExactInput` function is designed to provide quotes for routes that can contain both V2 and V3 pools. It tracks V3-specific data (prices and tick crossings) in arrays. However, the index counter `i` is incremented for both V2 and V3 pools, while the arrays are only sized for V3 pools.

## Current Implementation
```solidity
function quoteExactInput(bytes memory path, uint256 amountIn) public returns (
    uint256 amountOut,
    uint160[] memory v3SqrtPriceX96AfterList,
    uint32[] memory v3InitializedTicksCrossedList,
    uint256 v3SwapGasEstimate
) {
    v3SqrtPriceX96AfterList = new uint160[](path.numPools());
    v3InitializedTicksCrossedList = new uint32[](path.numPools());

    uint256 i = 0;
    while (true) {
        (address tokenIn, address tokenOut, uint24 fee) = path.decodeFirstPool();

        if (fee & flagBitmask != 0) {
            amountIn = quoteExactInputSingleV2(...);
        } else {
            (uint256 _amountOut, uint160 _sqrtPriceX96After, ...) = quoteExactInputSingleV3(...);
            v3SqrtPriceX96AfterList[i] = _sqrtPriceX96After;  // Potential out of bounds
            v3InitializedTicksCrossedList[i] = _initializedTicksCrossed;  // Potential out of bounds
            amountIn = _amountOut;
        }
        i++;  // Bug: Incremented for both V2 and V3 pools
        // ...
    }
}
```

## Impact
1. **Array Out of Bounds**: When the path contains V2 pools, the arrays are sized only for V3 pools but the index `i` is incremented for all pools, potentially causing array access out of bounds.
2. **Data Corruption**: V3 pool data may be stored at incorrect indices, leading to corrupted price and tick data.
3. **Failed Transactions**: Transactions will revert when attempting to access array indices beyond the allocated size.

## Scenario Demonstration
Consider a path with 4 pools in order: V2 → V3 → V2 → V3

Current behavior:
```solidity
// Arrays sized for 2 V3 pools: length = 2

// Attempts to write second V3 data at i=3 (out of bounds)
```

## Code Fix
```solidity
function quoteExactInput(bytes memory path, uint256 amountIn) public returns (
    uint256 amountOut,
    uint160[] memory v3SqrtPriceX96AfterList,
    uint32[] memory v3InitializedTicksCrossedList,
    uint256 v3SwapGasEstimate
) {
    // Count only V3 pools for array sizing
    uint256 v3PoolCount = 0;
    bytes memory pathCopy = path;
    while (pathCopy.hasMultiplePools()) {
        (,, uint24 fee) = pathCopy.decodeFirstPool();
        if (fee & flagBitmask == 0) v3PoolCount++;
        pathCopy = pathCopy.skipToken();
    }
    (, , uint24 lastFee) = pathCopy.decodeFirstPool();
    if (lastFee & flagBitmask == 0) v3PoolCount++;

    v3SqrtPriceX96AfterList = new uint160[](v3PoolCount);
    v3InitializedTicksCrossedList = new uint32[](v3PoolCount);

    uint256 v3PoolIndex = 0;
    while (true) {
        (address tokenIn, address tokenOut, uint24 fee) = path.decodeFirstPool();

        if (fee & flagBitmask != 0) {
            amountIn = quoteExactInputSingleV2(...);
        } else {
            (uint256 _amountOut, uint160 _sqrtPriceX96After, uint32 _initializedTicksCrossed, uint256 _gasEstimate) = 
                quoteExactInputSingleV3(...);
            v3SqrtPriceX96AfterList[v3PoolIndex] = _sqrtPriceX96After;
            v3InitializedTicksCrossedList[v3PoolIndex] = _initializedTicksCrossed;
            v3SwapGasEstimate += _gasEstimate;
            amountIn = _amountOut;
            v3PoolIndex++;
        }

        if (path.hasMultiplePools()) {
            path = path.skipToken();
        } else {
            return (amountIn, v3SqrtPriceX96AfterList, v3InitializedTicksCrossedList, v3SwapGasEstimate);
        }
    }
}
```

```solidity
function testMixedRouteQuoting() public {
    // Setup tokens and pools
    address token1 = address(new TestERC20("Token1", "T1"));
    address token2 = address(new TestERC20("Token2", "T2"));
    address token3 = address(new TestERC20("Token3", "T3"));
    
    // Create mixed path: V2 -> V3 -> V2
    // Fee 0x800000 indicates V2 pool
    bytes memory path = encodePath(
        [token1, token2, token3],
        [0x800000, 3000, 0x800000]
    );
    
    uint256 amountIn = 1e18;
    
    // Get quote
    (
        uint256 amountOut,
        uint160[] memory v3SqrtPriceX96AfterList,
        uint32[] memory v3InitializedTicksCrossedList,
        uint256 v3SwapGasEstimate
    ) = quoter.quoteExactInput(path, amountIn);
    
    // Assert array lengths match V3 pool count
    assertEq(v3SqrtPriceX96AfterList.length, 1);
    assertEq(v3InitializedTicksCrossedList.length, 1);
    
    // Assert valid data for V3 pool
    assertTrue(v3SqrtPriceX96AfterList[0] > 0);
    assertTrue(v3InitializedTicksCrossedList[0] >= 0);
}
```

## Fix Summary
1. Adds initial path traversal to count V3 pools accurately
2. Sizes arrays based on actual V3 pool count
3. Uses separate index counter for V3 pool data
4. Maintains correct data alignment for V3 pool information

The fix ensures that array sizes match exactly the number of V3 pools in the path and that V3 data is stored at correct indices, preventing out-of-bounds errors and data corruption.
