# Vulnerability details

## Proof of Concept
In the `KatanaV3Pool::constructor`, the factory variable is initialised with address(1). 

```
  constructor() {
    // disable immutables initialization
    factory = address(1);
  }
```
At this point the state variables are not yet initialized. 

example: The below two state variables are not yet initialized. 

```
 address public override governance;
 address public override positionManager;

```

But, these variables are initialized via `initializeImmutables` function as below.

```
 function initializeImmutables(address factory_, address token0_, address token1_, uint24 fee_, int24 tickSpacing_)
    public
    virtual
    override
  {
    require(factory == address(0), "AII");

    (factory, token0, token1, fee, tickSpacing) = (factory_, token0_, token1_, fee_, tickSpacing_);

    // cache these immutable addresses for gas savings when swaps, mints, or burns are performed
==>    governance = IKatanaV3Factory(factory_).owner();
==>    positionManager = IKatanaGovernance(governance).getPositionManager();

    maxLiquidityPerTick = Tick.tickSpacingToMaxLiquidityPerTick(tickSpacing_);
  }
```

But, the initialise function is disabled because of the require validation in the function that expects the factory address to be address(0), while the factory was assigned adddress(1) in the constructor,

As as result the `initializeImmutables` function will not work as expected and would revert.

## Recommended Mitigation Steps

In the constructor, initialise the factory as zero address.
 factory = address(0);
