# Vulnerability details

## Proof of Concept
The finding is in file Oracle, however, it has impact to KatanaV3Pool.sol,  it is valid according to "If you discover a bug in any contract or library outside of the files listed above that impact following contracts, we will consider the issue valid".


First, we notice that the following function has a divide-before-multiplication precision loss at L263: 

```javascript

Oracle.sol

 function observeSingle(
    Observation[65535] storage self,
    uint32 time,
    uint32 secondsAgo,
    int24 tick,
    uint16 index,
    uint128 liquidity,
    uint16 cardinality
  ) internal view returns (int56 tickCumulative, uint160 secondsPerLiquidityCumulativeX128) {
    if (secondsAgo == 0) {
      Observation memory last = self[index];
      if (last.blockTimestamp != time) last = transform(last, time, tick, liquidity);
      return (last.tickCumulative, last.secondsPerLiquidityCumulativeX128);
    }

    uint32 target = time - secondsAgo;

    (Observation memory beforeOrAt, Observation memory atOrAfter) =
      getSurroundingObservations(self, time, target, tick, index, liquidity, cardinality);

    if (target == beforeOrAt.blockTimestamp) {
      // we're at the left boundary
      return (beforeOrAt.tickCumulative, beforeOrAt.secondsPerLiquidityCumulativeX128);
    } else if (target == atOrAfter.blockTimestamp) {
      // we're at the right boundary
      return (atOrAfter.tickCumulative, atOrAfter.secondsPerLiquidityCumulativeX128);
    } else {
      // we're in the middle
      uint32 observationTimeDelta = atOrAfter.blockTimestamp - beforeOrAt.blockTimestamp;
      uint32 targetDelta = target - beforeOrAt.blockTimestamp;
      return (
        beforeOrAt.tickCumulative
          + ((atOrAfter.tickCumulative - beforeOrAt.tickCumulative) / observationTimeDelta) * targetDelta,
        beforeOrAt.secondsPerLiquidityCumulativeX128
          + uint160(
            (
              uint256(atOrAfter.secondsPerLiquidityCumulativeX128 - beforeOrAt.secondsPerLiquidityCumulativeX128)
                * targetDelta
            ) / observationTimeDelta
          )
      );
    }
  }

```

POC: the following code shows the precision loss: 

```javascript

 function testDifference() public {

        uint beforeOrAtTickCumulative = 212844;
        uint atOrAfterTickCumulative = 617233;
        uint observationTimeDelta = 562311;
        uint targetDelta = 524799;

        uint tickCumulative_current = beforeOrAtTickCumulative + (((atOrAfterTickCumulative - beforeOrAtTickCumulative) / observationTimeDelta) * (targetDelta));
        uint tickCumulative_better = beforeOrAtTickCumulative + (((atOrAfterTickCumulative - beforeOrAtTickCumulative) * targetDelta) / (observationTimeDelta));
        
        console.log("Current Implementation: ", tickCumulative_current);
        console.log("Better Implementation: ", tickCumulative_better);
    }
```

We have the output: 
 Current Implementation:  212844
 Better Implementation:  590256

The big difference lies that if division first, the change is zero, and the tickCummulative remains 212844, while if we perform multiplication before division, the tickCummulative becomes 590256, a big difference. 


The ```observeSingle``` funnction is called by multiple functions in CatanaV3Pool contract including snapshotCumulativesInside(), _updatePosition(), and swap(), therefore, this error has impacts on the CatanaV3Pool contract.

## Recommended Mitigation Steps
Perform multiplication before division inside observeSingle function:
