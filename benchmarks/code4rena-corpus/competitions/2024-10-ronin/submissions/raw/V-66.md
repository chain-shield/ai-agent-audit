# Vulnerability details

## Issue Description: The KatanaV3PoolProxy.sol uses proxy logic to delegate calls, but the fallback function does not validate the incoming data before execution, only default fallback function is used without validation. This makes it susceptible to malicious contracts hijacking the proxy’s functionality.

## Proof of State: The fallback function in the contract lacks any form of authentication or input validation:

fallback() external payable {
    _delegate(poolImplementation);
}
Attackers can craft specific calldata to force the contract to execute unintended functionality.

## Mitigation: Implement a whitelist of allowed methods or rigorous input validation for the proxy delegation. Use access control to limit which contracts can invoke critical functions via the proxy.
