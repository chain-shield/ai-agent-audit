# Vulnerability details

## Summary

Katana V3 allows the creation of liquidity pools with no minimum liquidity requirements. This makes it possible for users to interact with pools that are highly susceptible to price manipulation, potentially leading to financial losses.

The absence of liquidity thresholds in `KatanaV3Factory.createPool` enables the creation of pools with very low liquidity. Attackers can exploit these pools by making large trades to artificially inflate or deflate token prices.

## Code Snippet

```solidity
function createPool(address tokenA, address tokenB, uint24 fee) external override returns (address pool) {
    require(msg.sender == IKatanaGovernance(owner).getPositionManager(), "KatanaV3Factory: INVALID_POSITION_MANAGER");

    require(tokenA != tokenB);
    (address token0, address token1) = tokenA < tokenB ? (tokenA, tokenB) : (tokenB, tokenA);
    require(token0 != address(0));
    int24 tickSpacing = feeAmountTickSpacing[fee];
    require(tickSpacing != 0);
    require(getPool[token0][token1][fee] == address(0));
    pool = deploy(address(this), token0, token1, fee, tickSpacing);
    getPool[token0][token1][fee] = pool;
    // populate mapping in the reverse direction, deliberate choice to avoid the cost of comparing addresses
    getPool[token1][token0][fee] = pool;
    emit PoolCreated(token0, token1, fee, tickSpacing, pool);
  }
```

## Impact

Users who unknowingly interact with these manipulated pools may experience significant slippage, resulting in unfavorable trade executions and financial losses. Additionally, protocols relying on Katana V3 pools as price oracles could receive inaccurate data, leading to flawed decisions.

## Steps to Reproduce
1. Deploy the Katana V3 contracts.
2. Create a pool with a very low amount of liquidity for a specific token pair.
3. Execute a large trade to significantly shift the pool's price.
4. Observe the impact on subsequent trades and/or price oracle readings.

## Recommendation

Implement a mechanism to mitigate the risk of price manipulation in low-liquidity pools. Possible solutions include:

* **Minimum Liquidity Threshold:**  Enforce a minimum liquidity requirement in `KatanaV3Factory.createPool` to prevent the creation of pools with insufficient liquidity.
* **Implement Pool Whitelist:**  A whitelist allows for a curated selection of pools that have met certain criteria, such as minimum liquidity requirements, established history, or reputable creators. This helps ensure that users interact with more reliable pools.
