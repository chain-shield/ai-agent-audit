# Vulnerability details

## Summary
The pairFor function in the `KatanaV2Library` lacks a fee parameter, which is essential for calculating pair addresses in exchanges with varying fee tiers.

## Vulnerability Details
Does not account for fee tiers, potentially leading to incorrect pair address calculations.
```javascript
     17   // calculates the CREATE2 address for a pair without making any external calls
    //@audit lack of fee param
     18   function pairFor(address factory, address tokenA, address tokenB) internal pure returns (address pair) {
     19     (address token0, address token1) = sortTokens(tokenA, tokenB);
     20     pair = address(
     21       uint256(
     22         keccak256(
     23           abi.encodePacked(
     24             hex"ff",
     25             factory,
     26             keccak256(abi.encodePacked(token0, token1)),
     27             hex"e85772d2fe4ad93037659afaee57751696456eb5dd99987e43f3cf11c6e255a2" // init code hash
     28           )
     29         )
     30       )
     31     );
     32   }
```

## Impact
Without a fee parameter, the function may generate incorrect addresses for pairs with different fee structures.

## Tools Used
Manual Review

## Recommendations
Modify the pairFor function to include a fee parameter.
