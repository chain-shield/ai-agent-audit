# Vulnerability details


Lines of code:
```
(zeroForOne ? step.sqrtPriceNextX96 < sqrtPriceLimitX96 : step.sqrtPriceNextX96 > sqrtPriceLimitX96)

```

Description:

The issue lies in the swap function's logic that determines when the swap process should stop based on the price limit. When swapping token1 for token0 `(zeroForOne == false)`, the comparison incorrectly checks if the price goes up rather than down towards the limit. This faulty condition results in prematurely stopping the swap process before reaching the intended price limit.

Impact:
- For swaps of token1 to token0: The swap process might terminate early because it incorrectly compares the price against the limit in the wrong direction. This can lead to incomplete or inaccurate swaps, where the desired output amount is not achieved.
- For swaps of token0 to token1: The logic works correctly, so no immediate impact is observed for this case.

Proof of Concept:

If a user attempts to swap token1 for token0 with a specific price limit, the swap process may stop prematurely. For example, if `sqrtPriceLimitX96` is set to a lower value and the function expects the price to decrease, the wrong comparison will cause the swap to halt before it reaches the lower limit, potentially leaving some liquidity unswapped.

Recommended Mitigation:

Modify the comparison logic to ensure the price moves in the correct direction depending on the swap type:

```
(zeroForOne ? step.sqrtPriceNextX96 < sqrtPriceLimitX96 : step.sqrtPriceNextX96 < sqrtPriceLimitX96)

```
