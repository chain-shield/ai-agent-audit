# Vulnerability details

## Vulnerability details

When deploying a pool via `KatanaV3Factory::createPool()` subsequently the function `KatanaV3PoolDeployer::deploy()` is being called, which is suspicious of the reorg attack.

The `salt` that is used to deploy a `pool` is created by hashing `token0`, `token1` and `fee` (line 37 KatanaV3PoolDeployer.sol), which a malicious actor can abuse.

A victim may create a `pool` and transfers funds to that address, which is controlled by the malicious actor, and as a result, losing their funds due to the reorg.

Since the created `pool` is a `KatanaV3PoolProxy` proxy (see KatanaV3PoolBeacon.sol line 13), the attacker has full control over setting the proxy implementation for the pool.

## Recommended Mitigation Steps

Use `msg.sender` to create the `salt` inside `KatanaV3PoolDeployer::deploy()`:

```solidity
37    bytes32 salt = keccak256(abi.encode(token0, token1, fee, msg.sender));
```
