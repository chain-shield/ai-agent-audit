# Vulnerability details

## Summary
The `createAndInitializePoolIfNecessary` function in the `PoolInitializer` contract attempts to create and initialize a new pool if one does not already exist for a given pair of tokens and fee tier. However, it lacks a sufficient validation check for the pool address returned by `createPool`.
The absence of the check could lead to unexpected behavior if createPool fails to return a valid pool address, potentially resulting in further calls to an uninitialized pool.

## Vulnerability Details
The vulnerability stems from the absence of a validation check on the return value of `createPool`. In scenarios where `createPool` fails and returns the zero address, the function proceeds to initialize a non-existent pool, which could lead to unexpected contract behavior or revert due to failed calls. The line `require(pool != address(0));` should be added after calling createPool to enforce that a valid 
address is returned.

## Tools Used
Manual code review

## Recommended Mitigation Steps

Add a validation check immediately after the `createPool` function call to ensure the pool address is valid:
```diff
 function createAndInitializePoolIfNecessary(address token0, address token1, uint24 fee, uint160 sqrtPriceX96)
    external
    payable
    override
    returns (address pool)
  {
    AuthorizationLib.checkPair(governance, token0, token1);

    require(token0 < token1);
    pool = IKatanaV3Factory(factory).getPool(token0, token1, fee);

    if (pool == address(0)) {
      pool = IKatanaV3Factory(factory).createPool(token0, token1, fee);
+      require(pool != address(0), "Pool creation failed");
      IKatanaV3Pool(pool).initialize(sqrtPriceX96);
    } else {
      (uint160 sqrtPriceX96Existing,,,,,,,) = IKatanaV3Pool(pool).slot0();
      if (sqrtPriceX96Existing == 0) {
        IKatanaV3Pool(pool).initialize(sqrtPriceX96);
      }
    }
  }
```
