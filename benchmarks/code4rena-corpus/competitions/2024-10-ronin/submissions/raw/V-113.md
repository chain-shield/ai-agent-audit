# Vulnerability details

## Proof of Concept
The `KatanaV3Factory::_enableFeeAmount` function sets the `fee` parameters and emits an event, but potentially missing input validation to ensure that `fee` is in a valid range. Without validation, unintended or invalid values could be set, which could disrupt the functionality of the contract. For example, the `fee` parameter could be assigned the value zero.
```solidity
    function _enableFeeAmount(uint24 fee, int24 tickSpacing, uint8 feeProtocolNum, uint8 feeProtocolDen) private {
        // @audit lack of non-zero check
        feeAmountTickSpacing[fee] = tickSpacing;
        feeAmountProtocol[fee] = Fraction(feeProtocolNum, feeProtocolDen);
        emit FeeAmountEnabled(fee, tickSpacing, feeProtocolNum, feeProtocolDen);
    }
```

## Impact
- Unexpected Zero-Fee Transactions: Since the fee amount is zero, transactions or pools using this fee setting might execute without any fees. This could result in lost revenue, particularly if the contract is intended to generate income through these fees.

- Economic Exploits and Arbitrage: A zero fee could attract bots or traders exploiting arbitrage opportunities without any cost, potentially draining liquidity from pools and destabilizing markets linked to the contract.

## Recommended Mitigation Steps
```diff
    function _enableFeeAmount(uint24 fee, int24 tickSpacing, uint8 feeProtocolNum, uint8 feeProtocolDen) private {

    }
```
