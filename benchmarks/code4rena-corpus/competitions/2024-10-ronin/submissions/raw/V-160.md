# Vulnerability details

## Proof of Concept

```solidity
  /// @inheritdoc Dispatcher
  function execute(bytes calldata commands, bytes[] calldata inputs) public payable override isNotLocked {
    bool success;
    bytes memory output;
    uint256 numCommands = commands.length;
    if (inputs.length != numCommands) revert LengthMismatch();

    // loop through all given commands, execute them and pass along outputs as defined
    for (uint256 commandIndex = 0; commandIndex < numCommands;) {
      bytes1 command = commands[commandIndex];

      bytes calldata input = inputs[commandIndex];

      (success, output) = dispatch(command, input);

      if (!success && successRequired(command)) {
        revert ExecutionFailed({ commandIndex: commandIndex, message: output });
      }

      unchecked {
        commandIndex++;
      }
    }
  }
```

In AggregateRouter.sol, we can call execute in put in commands of our liking due to the it being public.


Here are some examples where the commands could be run and lead to loss of funds:


Example 1 SWEEP command:
User calls execute with SWEEP command
Parameters needed:
token: Address of token to sweep (or Constants.ETH for ETH)
recipient: Address to receive the funds
amountMin: Minimum amount expected

For example passing in the SWEEP command can

```solidity
// Could drain tokens from the contract
{
    command: SWEEP,
    inputs: [
        tokenAddress,  // Any token address
        attackerAddress, // Attacker's address
        0  // Minimum amount (set to 0 to sweep all)
    ]
}
```


The attacker crafts a transaction to call execute with the SWEEP command, specifying:
token: The address of the token they want to sweep (or Constants.ETH for ETH).
recipient: The attacker's own address.
amountMin: A small value (e.g., 1 wei) to ensure the sweep proceeds.

Resulting Loss:
The sweep function is executed, transferring all of the specified token or ETH from the contract to the attacker's address.
If the contract held significant balances, these are now entirely in the attacker's control.



Example 2 TRANSFER Command:

The attacker prepares a transaction to call the execute function with the TRANSFER command.
They specify the following inputs:
token: The address of the token they want to drain.
recipient: The attacker's own address.
value: A large amount, potentially the entire balance of the token in the contract.
The attacker sends the transaction to the contract.

The execute function processes the command and calls the TRANSFER command logic.
Transfer Execution:
Inside the TRANSFER command logic, the contract transfers the specified amount of tokens from its balance to the attacker's address.
If the contract holds a significant balance of the token, this results in a substantial loss of funds.

## Recommended Mitigation Steps
Do not make the execute command public or make some authentication check to ensure maybe only router or certain contracts can call execute.
