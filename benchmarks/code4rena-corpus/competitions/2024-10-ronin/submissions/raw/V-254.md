# Vulnerability details

## Summary

An issue was identified in the `collect` function of the `NonfungiblePositionManager` contract. Specifically, a missing check for the owed token amounts `(tokensOwed0 and tokensOwed1)` before deleting the position could result in uncollected tokens being permanently lost. This issue affects the implementation of the `collect` function, where the contract may inadvertently delete a position with outstanding tokens owed,

## Vulnerability
In the `collect` function, the following line of code deletes a position when `liquidity == 0`:

```javascript
if (position.liquidity == 0) {
    delete _positions[params.tokenId];
    _burn(params.tokenId);
}

```

However, there is no check to verify if the position’s tokens owed `(tokensOwed0 and tokensOwed1)` have been fully collected. As a result, if a position has zero liquidity but still has outstanding token balances in `tokensOwed0` or `tokensOwed`1, these owed tokens may not be properly collected and will be lost when the position is deleted.

## Root Cause
The absence of a check for `tokensOwed0 == 0` && `tokensOwed1 == 0` before deleting the position introduces a vulnerability, as it can allow unclaimed tokens to be permanently inaccessible.

## Impact
Users may lose unclaimed token balances if their position is deleted without collecting the owed tokens. This could lead to potential financial losses for users who expect their tokens to be fully collectible when their position is closed.

## Tools Used
Manual code review
Comparison with `UbiswapV3's NonfungiblePositionManagercollect` and `burn` implementations

## Recommendations

Add Token Owed Checks Before Deletion: Update the collect function to include checks for both `tokensOwed0 == 0` and `tokensOwed1 == 0` along with the liquidity check. This ensures the position is only deleted when both liquidity and owed tokens are cleared:

```solidity
if (position.liquidity == 0 && position.tokensOwed0 == 0 && position.tokensOwed1 == 0) {
    delete _positions[params.tokenId];
    _burn(params.tokenId);
}

```

Consider Explicit `burn` Function Usage:
separate the `collect` and `burn` processes to ensure tokens are only burned when all conditions are met, allowing for more controlled position management.
