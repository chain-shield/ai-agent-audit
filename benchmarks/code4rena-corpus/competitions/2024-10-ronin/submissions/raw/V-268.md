# Vulnerability details

## Proof of Concept

The Parameters are mostly not checked for the initializeImmutables function.

Namely:
```Solidity
address token0_ parameter is not checked.
address token1_ parameter is not checked.
uint24 fee_ parameter is not checked.
int24 tickSpacing_ is not checked.
```

The impact this could cause is out of range bound errors when invalid values are entered for these variables. And having reverts that do not have sufficient information on what went wrong. Making the function calls unstable.

Vulnerable Function
```Solidity
  function initializeImmutables(address factory_, address token0_, address token1_, uint24 fee_, int24 tickSpacing_)
    public
    virtual
    override
  {
    require(factory == address(0), "AII");


    (factory, token0, token1, fee, tickSpacing) = (factory_, token0_, token1_, fee_, tickSpacing_);


    // cache these immutable addresses for gas savings when swaps, mints, or burns are performed
    governance = IKatanaV3Factory(factory_).owner();
    positionManager = IKatanaGovernance(governance).getPositionManager();


    maxLiquidityPerTick = Tick.tickSpacingToMaxLiquidityPerTick(tickSpacing_);
  }
```

Erroneous Call
```Solidity
katanav3pool.initializeImmutables(address(0), address(type(uint256).max), address(type(uint256).max), uint24(type(uint24).max), int24(type(int24).max));
```

## Recommended Mitigation Steps
A checks for these unchecked parameters.
```Solidity
function initializeImmutables(address factory_, address token0_, address token1_, uint24 fee_, int24 tickSpacing_)
    public
    virtual
    override
  {
    require(factory_ == address(0), "AII");
+   require(token0_ != address(0), "Zero Address");
+   require(token1_ != address(0), "Zero Address");
+   require(fee_ > 0 && fee_ <= MAX_FEE, "More Money");
+   require(tickSpacing_ > 0 && <= MAX_TICKSPACING, "More Money");
  ...
  }
```
