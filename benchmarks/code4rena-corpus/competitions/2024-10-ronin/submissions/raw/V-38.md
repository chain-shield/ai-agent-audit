# Vulnerability details

`burn` function in KatanaV3Pool.sol allows users to burn more liquidity than what's available in the pool. The reason is that in the `burn` function, directly proceed to modify the position without verifying if the requested burn amount is valid. The function calculates `amount0` and `amount1` based on the requested burn amount, regardless of whether this amount exceeds the available liquidity. This calculation is done in the [_modifyPosition](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L284-L335) function, which doesn't have built-in checks for this scenario.

## Impact
Users could potentially extract more tokens than they should be entitled to, leading to an imbalance in the pool's reserves. This could result in other users being unable to withdraw their rightful share of liquidity, effectively stealing value from other liquidity providers.

## Proof of Concept
The bug is caused by the absence of a crucial check at the beginning of the burn function. The function directly proceeds to modify the position without verifying if the requested burn amount is valid.

1. Alice provides 100 tokens of liquidity to the pool.
2. Bob, noticing the lack of checks, calls the `burn` function with an amount of 200 tokens.
3. The `burn` function processes this request without reverting.
4. Bob receives more tokens than he should be entitled to, effectively draining excess liquidity from the pool.

This scenario can lead to a significant economic exploit.
```solidity
function testExcessiveBurn() public {
    // Setup
    int24 tickLower = -100;
    int24 tickUpper = 100;
    uint128 initialLiquidity = 100;
    uint128 excessiveBurnAmount = 200;

    // Provide initial liquidity
    pool.mint(address(this), tickLower, tickUpper, initialLiquidity, "");

    // Attempt to burn more than available
    (uint256 amount0, uint256 amount1) = pool.burn(tickLower, tickUpper, excessiveBurnAmount);

    // This should revert, but it doesn't
    // Instead, amount0 and amount1 will be calculated based on the excessive burn amount
    assert(amount0 > 0 || amount1 > 0);
}
```

## Recommended Mitigation Steps
Add a check at the beginning of the `burn` function to ensure that the amount to burn is not greater than the available liquidity
