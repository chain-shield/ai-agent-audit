# Vulnerability details

## Proof of Concept
Misuse of Constants.CONTRACT_BALANCE as Input: The code uses Constants.CONTRACT_BALANCE to signal when the contract’s current balance should be used as the value (value == Constants.CONTRACT_BALANCE). An external user could intentionally pass this constant as the value, leading the contract to treat it as if the full balance should be sent. If mishandled, this could result in sending unintended amounts, especially if CONTRACT_BALANCE is used for other tokens or purposes outside its intended context.

PoC: Call the pay function with value = Constants.CONTRACT_BALANCE and an ERC20 token address.
The function may send the entire balance instead of the intended amount, as the CONTRACT_BALANCE flag is misinterpreted.
Impact: Misinterpretation of amounts or sending unintended amounts can cause undesired fund flows and contract misbehavior.

## Recommended Mitigation Steps
1. Add validation logic to ensure that Constants.CONTRACT_BALANCE is only used internally and cannot be set externally.
2. Consider using different internal constants or flags to avoid ambiguity, ensuring no overlap between user input and control constants.
