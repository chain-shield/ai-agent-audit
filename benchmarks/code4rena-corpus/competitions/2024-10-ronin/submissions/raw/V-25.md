# Vulnerability details


## Vulnerability Details
The `collect` function in the NonfungiblePositionManager contract has an issue in how it handles the accounting of collected fees and burned liquidity. This issue can lead to the loss of tokens owed from burned liquidity if users perform partial collections.

This issue arises from two main aspects of the implementation:

 The  `burnedLiquidityOwed` amount is subtracted from the collected amounts (`amount0` and `amount1`) before adding to the fees, regardless of how much is actually collected.
 The `burnedLiquidityOwed` values are set to zero after each collection, even if not all owed tokens were collected.

This approach can cause incorrect accounting and potential loss of funds in certain scenarios.

In a case like this:

 Initial state:
   - A user has a position with 100 token0 and 200 token1 owed from burned liquidity.
   - Current fees: 0 token0, 0 token1

 First partial collection:
   - User collects 60 token0 and 150 token1
   - The transaction reverts due to underflow, preventing the collection.

 Alternate scenario (if underflow didn't cause revert):
   - User collects 60 token0 and 150 token1
   - Result: User receives 60 token0 and 150 token1, but loses the remaining 40 token0 and 50 token1 owed from burned liquidity.

 Subsequent collections:
   - Since `burnedLiquidityOwed` is zeroed out, any further collections will not account for the remaining owed tokens from burned liquidity.

This can significantly impact users who might want to collect their owed tokens over multiple transactions, leading to unexpected loss of funds or inability to collect partial amounts.

## Recommended Mitigation Steps

Consider implementing these changes:

1. Modify the fee calculation logic to handle partial collections correctly:

```solidity
uint256 collectedFromBurned0 = amount0 > burnedLiquidityOwed.token0 ? burnedLiquidityOwed.token0 : amount0;
uint256 collectedFromBurned1 = amount1 > burnedLiquidityOwed.token1 ? burnedLiquidityOwed.token1 : amount1;

fees.token0 += amount0 - collectedFromBurned0;
fees.token1 += amount1 - collectedFromBurned1;

burnedLiquidityOwed.token0 -= collectedFromBurned0;
burnedLiquidityOwed.token1 -= collectedFromBurned1;
```

 Remove the line that zeroes out `burnedLiquidityOwed`:

```solidity
// Remove this line
// (burnedLiquidityOwed.token0, burnedLiquidityOwed.token1) = (0, 0);
```
