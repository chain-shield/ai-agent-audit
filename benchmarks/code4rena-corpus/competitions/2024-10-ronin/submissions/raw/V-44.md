# Vulnerability details

## Proof of Concept
There is a lack of proper validation for the `tickSpacing_` parameter passed to the function. This allows the `tickSpacing` state variable to be set to invalid values.

The `initializeImmutables` function is responsible for initializing the immutable state variables of the KatanaV3Pool contract, including `tickSpacing`. The function takes the `tickSpacing_` parameter as input and directly assigns it to the `tickSpacing` state variable without any validation.

If `tickSpacing` is set to 0, it can cause division by zero errors in functions like `snapshotCumulativesInside`, leading to transaction reverts and disrupting the normal operation of the contract.

If `tickSpacing` is set to a value greater than 16384, it can result in incorrect tick calculations, affecting the accuracy of liquidity provisioning, swap pricing, and other critical operations of the contract. [KatanaV3Pool.sol#L124](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L124)

```solidity
  function initializeImmutables(address factory_, address token0_, address token1_, uint24 fee_, int24 tickSpacing_)
    public
    virtual
    override
  {
    require(factory == address(0), "AII");

    (factory, token0, token1, fee, tickSpacing) = (factory_, token0_, token1_, fee_, tickSpacing_); // <= FOUND

    // cache these immutable addresses for gas savings when swaps, mints, or burns are performed
    governance = IKatanaV3Factory(factory_).owner();
    positionManager = IKatanaGovernance(governance).getPositionManager();

    maxLiquidityPerTick = Tick.tickSpacingToMaxLiquidityPerTick(tickSpacing_);
  }
```
As seen above, the `tickSpacing_` parameter is directly assigned to the `tickSpacing` state variable without any validation checks. This allows an attacker or a contract deployer to set `tickSpacing` to any arbitrary value, including 0 or values greater than 16384, which can lead to unexpected behavior and potential exploits.

For example.

1. Alice deploys the KatanaV3Pool contract.
2. Alice calls the `initializeImmutables` function with the following parameters

   * `factory_`: Address of the factory contract
   * `token0_`: Address of token0
   * `token1_`: Address of token1
   * `fee_`: Valid fee value
   * `tickSpacing_`: 0 (invalid value)

3. The `tickSpacing` state variable is set to 0.
4. Bob interacts with the KatanaV3Pool contract and calls the `snapshotCumulativesInside` function, which relies on `tickSpacing` for calculations.
5. The `snapshotCumulativesInside` function encounters a division by zero error due to the invalid `tickSpacing` value, causing the transaction to revert and potentially disrupting the contract's functionality.

## Recommended Mitigation Steps
```solidity

    virtual
    override

}
```
