# Vulnerability details

## Proof of Concept
`initialization` function accepts any `uint160` price value without validating against valid price bounds. When extreme prices are used, the tick calculation produces values outside the valid range, but these invalid values are still stored in the pool's state. When calling `TickMath.getTickAtSqrtRatio()` with these extreme values, it could result in ticks outside the valid range, this could lead to unexpected behavior in price calculations and tick transitions.
[KatanaV3Pool.sol.initialize#L246-L264](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L246-L267)
```solidity
function initialize(uint160 sqrtPriceX96) external override {
    require(slot0.sqrtPriceX96 == 0, "AI"); // <@Issue: Missing validation of sqrtPriceX96 bounds

    int24 tick = TickMath.getTickAtSqrtRatio(sqrtPriceX96); // <@Issue: Can produce invalid ticks with extreme prices

    (uint16 cardinality, uint16 cardinalityNext) = observations.initialize(_blockTimestamp());

    (uint8 feeProtocolNum, uint8 feeProtocolDen) = IKatanaV3Factory(factory).feeAmountProtocol(fee);

    slot0 = Slot0({
        sqrtPriceX96: sqrtPriceX96, // <@Issue: Storing potentially unsafe price
        tick: tick, // <@Issue: Storing potentially invalid tick
        observationIndex: 0,
        observationCardinality: cardinality,
        observationCardinalityNext: cardinalityNext,
        feeProtocolNum: feeProtocolNum,
        feeProtocolDen: feeProtocolDen,
        unlocked: true
    });

    emit Initialize(sqrtPriceX96, tick);
}
```
The invalid state propagates through the system since core functions like `swap()` and `mint()` depend on valid tick/price relationships.

**The core issues are:-**
* No validation of input price bounds before initialization
* Potential for extreme prices to cause invalid tick calculations
* Storage of unsafe price and tick values in pool state
* Missing checks against `TickMath.MIN_SQRT_RATIO` and `TickMath.MAX_SQRT_RATIO`

This creates a path where extreme price values can compromise the pool's price/tick mechanics and affect core functionality like swaps and liquidity management.

**For reproduction:-**
1. Call `initialize()` with `minSqrtPrice` (4295128739)
2. The extremely low price causes issues with tick calculations
3. Same issue occurs with `maxSqrtPrice`
```solidity
function testExtremeInitialize() public {
    uint160 minPrice = 4295128739;
    uint160 maxPrice = 1461446703485210103287273052203988822378723970342;
    
    // Both calls succeed but create invalid state
    pool.initialize(minPrice); 
    pool.initialize(maxPrice);
    
    // Pool operations now break due to invalid ticks
    vm.expectRevert();
    pool.swap(...);
}
```
Connects to all price/tick dependent functions in KatanaV3Pool.sol, creating a systemic risk to the entire pool's operation.

## Recommended Mitigation Steps
validation in the initialize function ensures:-
* Tick calculations remain within bounds
* Pool state maintains integrity
* Core functions operate as intended
```diff
function initialize(uint160 sqrtPriceX96) external override {
    require(slot0.sqrtPriceX96 == 0, "AI");
+   require(sqrtPriceX96 >= TickMath.MIN_SQRT_RATIO, "Price too low");
+   require(sqrtPriceX96 <= TickMath.MAX_SQRT_RATIO, "Price too high");
    
    int24 tick = TickMath.getTickAtSqrtRatio(sqrtPriceX96);
    //...
}
```
