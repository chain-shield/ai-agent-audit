# Vulnerability details

The `flash` function does not check if the requested amounts (`amount0` and `amount1`) are less than or equal to the pool's current balances before transferring the tokens. The function only verifies that the pool's liquidity is greater than zero, but fails to compare the requested amounts with the actual token balances in the pool.

This oversight allows users to borrow more tokens than are available
```solidity
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) external override lock {
  require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");

  uint128 _liquidity = liquidity;
  require(_liquidity > 0, "L");

  uint256 paid0;
  uint256 paid1;

  // scope to avoid stack too deep error
  {
    address _token0 = token0;
    address _token1 = token1;
    uint256 fee0 = FullMath.mulDivRoundingUp(amount0, fee, 1e6);
    uint256 fee1 = FullMath.mulDivRoundingUp(amount1, fee, 1e6);
    uint256 balance0Before = balance0();
    uint256 balance1Before = balance1();

    if (amount0 > 0) TransferHelper.safeTransfer(_token0, recipient, amount0); // <= @audit
    if (amount1 > 0) TransferHelper.safeTransfer(_token1, recipient, amount1); // <= @audit

    IKatanaV3FlashCallback(msg.sender).katanaV3FlashCallback(fee0, fee1, data);

    uint256 balance0After = balance0();
    uint256 balance1After = balance1();
    address treasury = IKatanaV3Factory(factory).treasury();

    require(balance0Before.add(fee0) <= balance0After, "F0");
    require(balance1Before.add(fee1) <= balance1After, "F1");

    // ...
  }

  emit Flash(msg.sender, recipient, amount0, amount1, paid0, paid1);
}
```

## Impact
If borrowers don't repay the excess amount, the pool becomes insolvent, unable to meet its obligations to liquidity providers.

## Proof of Concept
1. Alice deploys a KatanaV3Pool contract with an initial liquidity of 100 tokens for both `token0` and `token1`.

2. Bob calls the `flash` function with the following parameters

   * `recipient`: Bob's address
   * `amount0`: 150 (more than the pool's balance)
   * `amount1`: 0
   * `data`: Valid callback data

3. The `flash` function executes without reverting, despite Bob requesting more tokens than available: [KatanaV3Pool.sol#L765-L766](https://github.com/ronin-chain/katana-v3-contracts/blob/03c80179e04f40d96f06c451ea494bb18f2a58fc/src/core/KatanaV3Pool.sol#L765-L766)
```solidity
      if (amount0 > 0) TransferHelper.safeTransfer(_token0, recipient, amount0);
      if (amount1 > 0) TransferHelper.safeTransfer(_token1, recipient, amount1);
```
4. In the callback function, Bob repays only 100 tokens (the actual balance of the pool).

5. The transaction completes successfully, leaving the pool with a deficit of 50 tokens.

The root cause is the absence of balance checks at the beginning of the `flash` function. The function only checks if the liquidity is greater than 0, but doesn't compare the requested amounts with the actual token balances in the pool.

## Recommended Mitigation Steps
```diff
function flash(address recipient, uint256 amount0, uint256 amount1, bytes calldata data) external override lock {
  require(IKatanaV3Factory(factory).flashLoanEnabled(), "FD");

  uint128 _liquidity = liquidity;
  require(_liquidity > 0, "L");

+ require(amount0 <= balance0(), "Insufficient balance0");
+ require(amount1 <= balance1(), "Insufficient balance1");

  // ...
}
```
