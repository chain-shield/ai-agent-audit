# Vulnerability details

## Proof of Concept
 Locked State Bypass: The isNotLocked modifier allows a function to bypass the lock if msg.sender is address(this), which can be problematic. If a function calls another internal function that also uses this modifier, the lock can be bypassed.

Proof of Concept: If a function, say functionA, uses isNotLocked and calls functionB, which also uses isNotLocked, an attacker can lock the contract and then invoke functionB through functionA, bypassing the lock.
contract Test is LockAndMsgSender {
    function functionA() external isNotLocked {
        // Some logic
        functionB(); // Calls another function that also uses isNotLocked
    }

    function functionB() external isNotLocked {
        // This can be executed without being locked due to the call from functionA
    }
}
Impact: This could allow unauthorized actions to be performed, defeating the purpose of the lock mechanism.
## Recommended Mitigation Steps
1. Restrict internal calls: Review the use of locks to ensure that internal function calls do not bypass security measures.
2. Refactor the locking mechanism to be more robust against internal calls.
