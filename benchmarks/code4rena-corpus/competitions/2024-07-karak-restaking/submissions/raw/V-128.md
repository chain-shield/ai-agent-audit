# Vulnerability details

## Impact
The `decimals()` function in the [Vault.sol](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L277) returns the decimal precision from `_config().decimals`. However, the fallback default value `_DEFAULT_UNDERLYING_DECIMALS` was not explicitly set to a specific value during contract initialization.
 
## Proof of Concept
```
function decimals() public view override(ERC4626, IKarakBaseVault) returns (uint8) {
    return _config().decimals;
}
```
- The `_DEFAULT_UNDERLYING_DECIMALS` constant was intended to provide a fallback value for decimal precision when `_tryGetAssetDecimals` fails to retrieve the asset's decimals.

`
```
  function initialize(
        address _owner,
        address _operator,
        address _depositToken,
        string memory _name,
        string memory _symbol,
        bytes memory _extraData
    ) external initializer {
        _initializeOwner(_owner);
        __Pauser_init();

        (bool decimalsSuccess, uint8 result) = _tryGetAssetDecimals(address(_depositToken));
        VaultLib.Config storage config = _config();

        config.asset = _depositToken;
        config.name = _name;
        config.symbol = _symbol;
        config.decimals = decimalsSuccess ? result : _DEFAULT_UNDERLYING_DECIMALS;     <---- Was never set
        config.operator = _operator;
        config.extraData = _extraData;
    }
```
- However, `_DEFAULT_UNDERLYING_DECIMALS` was not explicitly set to a concrete value (e.g., 18) in the contract's initialization or configuration.

- This oversight means that if `_tryGetAssetDecimals` fails and the fallback value is used, the resulting decimal precision may be incorrect or default to a non-intended value.

`_DEFAULT_UNDERLYING_DECIMALS` was not set, the fallback value used in _config().decimals may be incorrect. This misconfiguration will affect any calculations that rely on the token's decimal precision.
e.g:
[Decimal](https://github.com/OpenZeppelin/openzeppelin-contracts/blob/659f3063f82422cef820de746444e6f6cba6ca7c/contracts/token/ERC20/extensions/ERC4626.sol#L99C4-L108C6)

For example, a token expected to have 18 decimals might be incorrectly treated as having 0 or another incorrect number of decimals, leading to significant discrepancies in transactions.

The contract was deployed without `_DEFAULT_UNDERLYING_DECIMALS` being set to a concrete value.

`_tryGetAssetDecimals` fails for a token due to it being non-standard, and `_DEFAULT_UNDERLYING_DECIMALS` was not properly initialized

Make sure a default of 18 is used to represent the underlying asset's decimals
