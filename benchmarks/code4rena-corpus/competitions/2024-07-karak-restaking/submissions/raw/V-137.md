# Vulnerability details

## Impact
In order to prevent users to front run slashing events with a withdraw, requests to redeem the shares for the underlying assets, have to be queued for 9 days.
After the queue time has expired anyone can finalize the withdraw request, making sure that at all time there are no withdraw request that could be exercised, to front run a slash.

A malicious user can create a withdraw request that can only be finalized by them, enabling them to have a mature withdraw request ready to be completed at all time. 
Which can be used to front run slashing events

## Proof of Concept
After the *MIN_WITHDRAWAL_DELAY* has passed, users can finalize their withdraw using the [finishWithdrawal](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L262) function of the [NativeVault](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L25C10-L25C21) contract, this function will call the [withdraw](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeNode.sol#L39) from the [NativeNode](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeNode.sol#L17C10-L17C20) contract to send the ETH (to the receiver specified in [startWithdrawal(address to, uint256 weiAmount)](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L228C14-L228C60)):
```
        uint256 withdrawableAssets = withdrawableWei(startedWithdrawal.nodeOwner);
        if (startedWithdrawal.assets > withdrawableAssets) {
            startedWithdrawal.assets = withdrawableAssets;
        }
        _decreaseBalance(startedWithdrawal.nodeOwner, startedWithdrawal.assets);
        INativeNode(node.nodeAddress).withdraw(startedWithdrawal.to, startedWithdrawal.assets);
        node.withdrawableCreditedNodeETH -= startedWithdrawal.assets;
```
The [withdraw](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeNode.sol#L39) function, simply send the ETH to the specified address.

A malicious user can poi their withdraw request to a smart contract that will revert (or consume all the gas available), upon receiving any ETH, until they them self decide to withdraw, eg:
```
contract modalWithdraw {

    bool locked = true;

    function unlock() external {
        locked = false;
    }

    receive() external payable {
        if(locked){
            revert();
        }
    }
}
```

This means that the withdraw request will stay stuck in the withdraw queue until a slashing event occur, at which point they can unlock the contract and finalize the withdraw, saving their assets, while maintaining their share up to the slashing event.
Also if the owner where to discover such behavior, any attempt at slashing/pausing the functions of the malicious user's node, they can simply front run it by finalizing the withdraw
