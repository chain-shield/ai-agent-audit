# Vulnerability details

## Impact
>DSSs have the right to slash vaults if it feels that an operator had failed to perform its tasks adequately.

Operators are at will to include and stake in any DSS of choice, this means terms and conditions must have been agreed to. In the case where a DSS terms to the operator include slashing all staked vaults of the operator when it has acted maliciously or performed inadequately, it is possible for an operator to DOS finalization of the DSS slashing process by staking vault with an empty asset.

The root cause is in the validation check of ```SlashHandler.handleSlashing()```
```solidity
    function handleSlashing(IERC20 token, uint256 amount) external {
@>      if (amount == 0) revert ZeroAmount();
        if (!_config().supportedAssets[token]) revert UnsupportedAsset();

        SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
        // Below is where custom logic for each asset lives
        SafeTransferLib.safeTransfer(address(token), address(0), amount);
    }
```

## Proof of Concept
### Instance
1. According to the rule of this DSS, an operator is due for slashing, and the slashing function of the DSS(which could be in any form) loops through and adds all staked vaults of the operator to create a slash request. 
2. An operator who is aware of this fact then deploys a vault and stakes it to the DSS without any asset made available. ```totalAsset = 0```
3. When DSS sends a slash request, ```earmarkedStakes``` is computed for each vault, and due to calculations, the value can never be zero even when ```totalAsset``` is zero.
```solidity
  earmarkedStakes = new uint256[](slashingMetadata.vaults.length);
        for (uint256 i = 0; i < slashingMetadata.vaults.length; ++i) {
  @>>          earmarkedStakes[i] = Math.mulDiv(
                slashingMetadata.slashPercentagesWad[i],
                IKarakBaseVault(slashingMetadata.vaults[i]).totalAssets(),
                Constants.MAX_SLASHING_PERCENT_WAD
            )
```
4. It should be noted that, an operator is doing this to protect other vaults with assets.
5. After veto window has passed, an attempt to finalize the slash.
6. The ```finalizeSlashing()``` iterates through the slash request vaults and makes call to ```Vault.slashAssets()```
```solidity
 for (uint256 i = 0; i < queuedSlashing.vaults.length; i++) {
            IKarakBaseVault(queuedSlashing.vaults[i]).slashAssets(
                queuedSlashing.earmarkedStakes[i],
                self.assetSlashingHandlers[IKarakBaseVault(queuedSlashing.vaults[i]).asset()]
            );
        }
```
7. In ```Vault.slashAssets()```, in an attempt to prevent slashing an amount that is greater than the ```totalAsset``` of the vault, ```transferAmount``` is set to be the minimum value between ```totalAsset``` and ```totalAssetsToSlash```, in this case, ```min(0, 1)```
```solidity
 function slashAssets(uint256 totalAssetsToSlash, address slashingHandler)
        external
        onlyCore
        returns (uint256 transferAmount)
    {
@>>     transferAmount = Math.min(totalAssets(), totalAssetsToSlash);

        // Approve to the handler and then call the handler which will draw the funds
        SafeTransferLib.safeApproveWithRetry(asset(), slashingHandler, transferAmount);
        ISlashingHandler(slashingHandler).handleSlashing(IERC20(asset()), transferAmount);

        emit Slashed(transferAmount);
    }
```
8. When flow gets to ```SlashingHandler.handleSlashing()```, zero check makes the entire function to revert
```solidity
 if (amount == 0) revert ZeroAmount();
```

## Recommended Mitigation Steps
```return``` is a better option in this context, so other vault slash will succeed.
```solidity
 function handleSlashing(IERC20 token, uint256 amount) external {
---     if (amount == 0) revert ZeroAmount();
+++     if (amount == 0) return;
        if (!_config().supportedAssets[token]) revert UnsupportedAsset();

        SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
        // Below is where custom logic for each asset lives

    }
```
