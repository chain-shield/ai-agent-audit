# Vulnerability details

## Impact
The `_startSnapshot` function in the NativeNode contract is responsible for initiating a new snapshot for a node. However, the function currently updates only the `currentSnapshotTimestamp` and neglects to update the `lastSnapshotTimestamp`. 


## Proof of Concept
The [function]() checks for incomplete snapshots and calculates the node balance correctly. However, while creating a new snapshot, it only updates the `currentSnapshotTimestamp`:

```solidity
node.currentSnapshotTimestamp = uint64(block.timestamp);
```
The `lastSnapshotTimestamp` remains outdated, causing the system to potentially misinterpret the snapshot's validity period.
***Example for step to reproduce:***
Initialize the NativeNode contract with no active snapshot (`currentSnapshotTimestamp` is 0).
Set the lastSnapshotTimestamp to a historical value (e.g., Jan 1, 2021).
Call the _startSnapshot function to start a new snapshot.
Observe that `currentSnapshotTimestamp` is updated to the current `block.timestamp`, but `lastSnapshotTimestamp` remains unchanged.
>HENCE

Both `currentSnapshotTimestamp` and `lastSnapshotTimestamp` should be updated to the current block timestamp when a new snapshot is initiated.

However, The system may consider an old timestamp as the most recent snapshot, leading to decisions based on outdated data.

The last snapshot timestamp helps determine when the most recent snapshot was taken. This ensures that snapshots are updated regularly and do not become stale

Only `currentSnapshotTimestamp` was updated, leaving `lastSnapshotTimestamp` unchanged.

## Tools Used

## Recommended Mitigation Steps
The last snapshot timestamp helps determine when the most recent snapshot was taken meaning it should be updated to the current snapshot timestamp when a recent snapshot was taken. This ensures that snapshots are updated regularly and do not become stale.
