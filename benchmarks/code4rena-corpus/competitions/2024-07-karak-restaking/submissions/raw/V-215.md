# Vulnerability details

The `Vault.sol` contract's `deposit()` function has a version that includes a `minSharesOut` parameter to prevent malicious front-running in ERC4626. However, the `mint()` function lacks a similar mechanism for slippage protection. Specifically, the mint function should have a `maxAssetsOut` parameter to ensure that users do not receive fewer assets than expected.

## Impact

The lack of slippage protection in the `mint()` function exposes users to front-running attacks, resulting in potential financial losses.

## Proof of Concept
```solidity
    function mint(uint256 shares, address to) //@audit add mint() with maxAssetsOut
        public
        override(ERC4626, IVault)
        whenFunctionNotPaused(Constants.PAUSE_VAULT_MINT)
        nonReentrant
        returns (uint256 assets)
    {
        if (shares == 0) revert ZeroShares();
        assets = super.mint(shares, to);
    }
```

## Tools Used
Manual review.

## Recommended Mitigation Steps
Implement a new `mint()` function with `maxAssetsOut` parameter in the function to provide slippage protection, similar to the `minSharesOut` parameter in the deposit function.
