# Vulnerability details

The `registerOperatorToDSS()` fails to respect the paused state, allowing operators to register with a Decentralized Staking Service (DSS) even when the function should be paused. This stems from an issue with the [whenFunctionNotPaused](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L99) modifier or the function's internal logic not properly checking or respecting the paused state.

The Core contract manages the registration of operators to various DSS instances. The `registerOperatorToDSS()` function ([lines 97-107](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L97-L107)) is designed to allow operators to register with a DSS, enabling them to allocate assets delegated by stakers.

The current implementation fails to properly enforce the pause mechanism, potentially allowing unauthorized registrations during critical periods when the function should be inaccessible.

## Impact
1. Unauthorized operator registrations during emergency situations or maintenance periods.
2. Undermining of the contract's security measures and administrative controls.
3. Disruption of the protocol's intended operational flow and security assumptions.

## Proof of Concept
The issue was identified through a formal verification process using the Certora Prover, which revealed that the function does not revert as expected when in a paused state. This violates the specified rule `cannotRegisterWhenPaused`, which asserts that the function should revert when paused.
