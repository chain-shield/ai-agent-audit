# Vulnerability details

## Impact
Under the right circumstances the [slashAssets](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L193C14-L193C25) function might slash the total assets available in the vault. Meaning that the [finalizeSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L248C14-L248C30) function can slash more than the maximum percentage, since slashing total assets, obviously means to slash the 100% of tokens available, which will be more than *dssMaxSlashablePercentage* for any DSS that has a *dssMaxSlashablePercentage* lower than 100% (*It can be argued that at the time of [requestSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L220C14-L220C29) the *dssMaxSlashablePercentage* cannot be surpassed and that technically the amount of tokens being slashed is actually smaller, but what may matter more to the end users is the actual % of tokens being slashed to them, and not what is being queued. EG: A staker may expects a maximum Slashable Percentage 50% per period, and then sees 100% of their deposited assets being slashed in 1 single event. So even tough the amount being slashed might be smaller than anticipated, the effect to the end user will be greater*).
On top of breaking one of the main invariants of the protocol ("*A DSS should be able to slash up to the set percentage per slashing request. Afterwards, they have to wait a cooldown period before a subsequent request.*"), this is an issue, as depositors will stake their tokens in a vault under the assumption that only up to *dssMaxSlashablePercentage* amount of their deposit can be slashed per cooldown period while, due to this issue, they might see 100% of their deposit being slashed in a single call (as explained in the example above, and shown in the coded PoC).

## Proof of Concept
The [slashAssets](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L193C14-L193C25) function of the [Vault](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L29C10-L29C15) contract, called by [finalizeSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L248C14-L248C30) when slashing an operator, will check that there are enough tokens in the vault and than slash *totalAsset()* if that is not the case:
```
        transferAmount = Math.min(totalAssets(), totalAssetsToSlash);

        // Approve to the handler and then call the handler which will draw the funds
        SafeTransferLib.safeApproveWithRetry(asset(), slashingHandler, transferAmount);
        ISlashingHandler(slashingHandler).handleSlashing(IERC20(asset()), transferAmount);
```
This means that regardless of the % of tokens that the DSS is trying to slash, the [slashAssets](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L193C14-L193C25) function will slash 100% of the tokens if there is not enough liquidity available, bypassing any check performed while queuing the slash request.

The amount of tokens to be slashed is computed during [requestSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L220C14-L220C29) as a percentage of the total assets available in the vault, by the [fetchEarmarkedStakes](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/SlasherLib.sol#L79C14-L79C34) function:
```
        earmarkedStakes = new uint256[](slashingMetadata.vaults.length);
        for (uint256 i = 0; i < slashingMetadata.vaults.length; ++i) {
            earmarkedStakes[i] = Math.mulDiv(
                slashingMetadata.slashPercentagesWad[i],
                IKarakBaseVault(slashingMetadata.vaults[i]).totalAssets(),
                Constants.MAX_SLASHING_PERCENT_WAD
            );
        }
```

This can be an issue due to the asynchronous nature of the redeem process, because the amount of tokens present in the vault can decrease during the *SLASHING_VETO_WINDOW*, if there is a redeem request queued that can be withdrawn between [requestSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L220C14-L220C29) and [finalizeSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L248C14-L248C30), that is large enough to make the *totalAssets()* at the time of [finalizeSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L248C14-L248C30) being larger than the % of tokens computed by [requestSlashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L220C14-L220C29), causing the vault to slash 100% of the assets available.

EG: Let's suppose that a DSS has a 50% *dssMaxSlashablePercentage*.
User1 deposit 60 tokens in a vault connected to the DSS.
User2 deposit 40 tokens in the same vault.
User1 queues a redeem for the full 60 tokens
After 7+ days a slash request of 50% is queued, with a slash amount of 50.
User1 complete the redeem process, withdrawing their 60 tokens, before the slash is executed.
When the slashing process gets completed, there are only 40 tokens in the vault, meaning that [slashAssets](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Vault.sol#L193C14-L193C25) will slash the full amount available.

As a result User2 will see 100% of their deposit being slashed in a single cooldown period. Breaking an invariant of the protocol, and any assumptions on the risks they where taking, when staking their assets in the protocol.

Here is a foundry script that implements the scenario above.
Place it in the `/test/core/` folder, to preserve dependencies:
```
// SPDX-License-Identifier: SEE LICENSE IN LICENSE
pragma solidity ^0.8.25;

import "forge-std/Test.sol";
import "forge-std/console.sol";

import "solady/src/utils/SafeTransferLib.sol";

import "../../src/Core.sol";
import "../../src/Vault.sol";
import "../../src/entities/VaultLib.sol";
import "../../src/entities/Operator.sol";
import "../../src/entities/Withdraw.sol";
import "../../src/interfaces/Errors.sol";
import "../../src/interfaces/IVault.sol";
import "../helpers/ProxyDeployment.sol";
import "../../src/interfaces/Constants.sol";
import "../helpers/contracts/ERC20Mintable.sol";
import "../helpers/OperatorHelper.sol";



import "../../src/SlashingHandler.sol";
import "../../src/Querier.sol";

import "./../helpers/ProxyDeployment.sol";
import "./../helpers/contracts/ERC20Mintable.sol";
import "./../helpers/contracts/MockDSS.sol";
import "./../helpers/OperatorContract.sol";

contract VaultTest is Test {
    Vault vault;
    Core core;
    IDSS dss = IDSS(address(new MockDSS()));
    ERC20Mintable depositToken;

    address manager = address(11);
    address notOwner = address(12);
    address operator = address(13);
    address proxyAdmin = address(14);
    address beneficiary = address(15);
    address slashingHandler = address(16);
    address slashingVetoCommittee = address(17);

    function setUp() public {
        uint32 hookCallGasLimit = 500_000;
        uint32 hookGasBuffer = 40_000;
        uint32 supportsInterfaceGasLimit = 20_000;
        // Setup core
        depositToken = new ERC20Mintable();
        depositToken.initialize("Test", "TST", 18);
        address vaultImpl = address(new Vault());
        core = Core(ProxyDeployment.factoryDeploy(address(new Core()), proxyAdmin));
        core.initialize(
            vaultImpl, manager, slashingVetoCommittee, hookCallGasLimit, supportsInterfaceGasLimit, hookGasBuffer
        );

        // Allowlist asset
        address[] memory assets = new address[](1);
        assets[0] = address(depositToken);

        // Slashing Handler for the asset
        IERC20[] memory supportedAssets = new IERC20[](1);
        supportedAssets[0] = IERC20(address(depositToken));
        slashingHandler = ProxyDeployment.deployTransparentUpgradeable(address(new SlashingHandler()), proxyAdmin);
        ISlashingHandler(slashingHandler).initialize(proxyAdmin, supportedAssets);


        address[] memory slashingHandlers = new address[](1);
        slashingHandlers[0] = slashingHandler;
        core.allowlistAssets(assets, slashingHandlers);

        // Deploy Vaults
        VaultLib.Config[] memory vaultConfigs = new VaultLib.Config[](1);
        vaultConfigs[0] = VaultLib.Config({
            asset: address(depositToken),
            decimals: 18,
            operator: operator,
            name: "TestVault",
            symbol: "TV",
            extraData: bytes("")
        });


        vm.prank(address(dss));
        
        //Max slashable: 50%
        core.registerDSS(50 * Constants.ONE_WAD);

        vm.startPrank(operator);
        IKarakBaseVault[] memory vaults = core.deployVaults(vaultConfigs, address(0));
        vault = Vault(address(vaults[0]));
        core.registerOperatorToDSS(dss, "");

        Operator.StakeUpdateRequest memory req = Operator.StakeUpdateRequest(address(vault), dss, true);
        Operator.QueuedStakeUpdate memory queued = core.requestUpdateVaultStakeInDSS(req);
        vm.warp(block.timestamp + Constants.MIN_STAKE_UPDATE_DELAY + 1);
        core.finalizeUpdateVaultStakeInDSS(queued);

        vm.stopPrank();
    }

    function mintAndDepositFor(uint256 amount, address user) public returns (uint256 shares) {
        vm.startPrank(user);
        depositToken.mint(user, amount);
        depositToken.approve(address(vault), amount);
        uint256 expectedShares = vault.convertToShares(amount);
        shares = vault.deposit(amount, user, expectedShares);
        vm.stopPrank();
    }

    function test_redeem() public {
 

        address depositor0 = address(0x123);
        address depositor1 = address(0x456);


        address[] memory  vaultsAdd  = new address[](1);
        vaultsAdd[0] = address(vault);

        uint96[] memory  percentage  = new uint96[](1);
        percentage[0] = uint96(50 * Constants.ONE_WAD);

        mintAndDepositFor(6000, depositor0);
        mintAndDepositFor(4000, depositor1);


        vm.startPrank(depositor0);
        vault.approve(address(vault), 6000);
        bytes32 withdrawalKey = vault.startRedeem(6000, depositor0);
        vm.stopPrank();


        vm.warp(block.timestamp + 7 days);


        vm.startPrank(address(dss));
        SlasherLib.SlashRequest memory slashingReq = SlasherLib.SlashRequest({
            operator: operator,
            slashPercentagesWad: percentage,
            vaults: vaultsAdd
        });
        

        SlasherLib.QueuedSlashing memory queuedSlashing = core.requestSlashing(slashingReq);

        vm.warp(block.timestamp + Constants.SLASHING_VETO_WINDOW + 1);
        vm.stopPrank();


        vault.finishRedeem(withdrawalKey);


        assertGt(depositToken.balanceOf(address(vault)), 0);

        core.finalizeSlashing(queuedSlashing);
        
        //Altough the maximum slashable amount is 50%, 100% of assets available have been slashed
        assertEq(core.getDssMaxSlashablePercentageWad(dss), 50 * Constants.ONE_WAD);
        assertEq(depositToken.balanceOf(address(vault)), 0);  
    }


}
``` 

## Recommended Mitigation Steps
The actual amount being slashed, might be computed at the time of slashing and not when queuing the request, with only the % being check while queuing.
