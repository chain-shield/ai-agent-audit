# Vulnerability details

## Details
- The `finalizeUpdateVaultStakeInDSS` function calls the `validateAndUpdateVaultStakeInDSS` function to perform the updations related to finalize the staking of the vault to the DSS and it calls the hook function `finishUpdateStakeHook` on DSS.
- The `finishUpdateStakeHook` function takes in operator as parameter and `msg.sender` is passed to it considering that only operator would call it.
- But as the `finalizeUpdateVaultStakeInDSS` function is allowed to be called by anyone, therefore it would result in passing incorrect operator to the DSS via the `finishUpdateStakeHook` function as it passes the `msg.sender` which would not be the operator in case anyone other than actual operator calls it.

## Impact
Incorrect data is sent to DSS through the `finishUpdateStakeHook` function as `msg.sender` will not always the operator which would result in incorrect accounting on the operator and even result in severe destruction of the DSS.


## Proof of Concept
- As the `finalizeUpdateVaultStakeInDSS` function can be called by anyone, therefore `msg.sender` will not always be the operator.

## Recommended Mitigation Steps
Either make the `finalizeUpdateVaultStakeInDSS` function to be called only by respective operator who created a request related to the updation of their vaults or replace msg.sender by the actual operator, i.e. `queuedStakeUpdate.operator`.
