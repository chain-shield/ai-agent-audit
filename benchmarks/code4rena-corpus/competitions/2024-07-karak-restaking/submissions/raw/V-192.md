# Vulnerability details

## Impact
Let's look at this using the Core.sol.registerDSS() function as an example:

The Core.sol.registerDSS() function allows the caller to register as a DSS and set the max slashable percentage. The function receives the maxSlashablePercentageWad parameter,
which means "The max slashable percent, in the form of wad, that the DSS can slash per cooldown period". This parameter is set for
DSS msg.sender:

IDSS dss = IDSS(msg.sender);
https://github.com/code-423n4/2024-07-karak/blob/main/src/Core.sol#L263

However, this can be bypassed. You can set the DSS for any address to any maxSlashablePercentageWad value. You can also change the maxSlashablePercentageWad
for an existing DSS.

## Proof of Concept
You can call the SlasherLib.setDSSMaxSlashablePercentageWad() function directly with your parameters:
CoreLib.Storage storage self,
IDSS dss,
uint256 dssMaxSlashablePercentageWad
The SlasherLib.setDSSMaxSlashablePercentageWad() function does not check that the calling address msg.sender owns this DSS.

The same applies to the functions:
Core.requestUpdateVaultStakeInDSS() and Operator.requestUpdateVaultStakeInDSS();
Core.registerOperatorToDSS() and Operator.registerOperatorToDSS();
Core.unregisterOperatorFromDSS() and Operator.unregisterOperatorFromDSS();
Core.cancelSlashing() and SlasherLib.cancelSlashing().

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a check to the SlasherLib.setDSSMaxSlashablePercentageWad() function that the calling address msg.sender owns this DSS. Similarly, for the functions:
Core.requestUpdateVaultStakeInDSS() and Operator.requestUpdateVaultStakeInDSS();
Core.registerOperatorToDSS() and Operator.registerOperatorToDSS();
Core.unregisterOperatorFromDSS() and Operator.unregisterOperatorFromDSS();
Core.cancelSlashing() and SlasherLib.cancelSlashing().
