# Vulnerability details

Registering DSS can choose not to slash operators vault , however if the operators become malicious in then future or instantly due to no slashing the Slashable percent can't be updated to counter that. 

## Proof of Concept
https://github.com/code-423n4/2024-07-karak/blob/main/src%2FCore.sol#L262-L267

```solidity
function registerDSS(uint256 maxSlashablePercentageWad) external {
        IDSS dss = IDSS(msg.sender);
        if (!address(dss).isSmartContract()) revert NotSmartContract();
        _self().setDSSMaxSlashablePercentageWad(dss, maxSlashablePercentageWad);
        emit DSSRegistered(msg.sender, maxSlashablePercentageWad);
    }
```
https://github.com/code-423n4/2024-07-karak/blob/main/src%2Fentities%2FSlasherLib.sol#L174
```solidity
function setDSSMaxSlashablePercentageWad(
        CoreLib.Storage storage self,
        IDSS dss,
        uint256 dssMaxSlashablePercentageWad
    ) public {
        uint256 currentSlashablePercentageWad = self.dssMaxSlashablePercentageWad[dss];
        if (currentSlashablePercentageWad != 0) revert DSSAlreadyRegistered();
        if (dssMaxSlashablePercentageWad == 0) revert ZeroSlashPercentageWad();
        if (dssMaxSlashablePercentageWad > Constants.MAX_SLASHING_PERCENT_WAD) revert MaxSlashPercentageWadBreached();
        self.dssMaxSlashablePercentageWad[dss] = dssMaxSlashablePercentageWad;
    }
}
```

Once the Slashable percent is set when creating the DSS it can't be updated, in cases where operators become malicious increamenting  the slashing percent will be needed to bring back the honest work. However since the operators vaults can't be slashed they will continue to validate nodes.

## Impact
`maxSlashablePercentageWad` can't be updated allowing malicious operators to continue their actives.

## Tools Used
Manual Review 

## Recommended Mitigation Steps
Add a function to update the `maxSlashablePercentageWad` when needed.
