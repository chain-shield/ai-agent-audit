# Vulnerability details

## Impact
The getNextWithdrawNonce function does not perform as expected based on its name. Instead of returning the next nonce value for a given `nodeOwner`, it returns the current nonce value from the `nodeOwnerToWithdrawNonce` mapping. 

## Proof of Concept
```
function getNextWithdrawNonce(address nodeOwner) public view returns (uint256) {
    return _state().nodeOwnerToWithdrawNonce[nodeOwner];
}
```
- The function name suggests that it should return the "next" withdrawal nonce for a given nodeOwner.
- The next nonce typically means the current nonce value plus one.

> The function returns the current nonce value from the nodeOwnerToWithdrawNonce mapping, not the next nonce.

`nodeOwnerToWithdrawNonce[nodeOwner]`is set to 5.
`getNextWithdrawNonce(nodeOwner)`.
- Returns 5.
 >Should return 6, as the "next" nonce should be the current nonce value plus one.

Manual review

## Recommended Mitigation Steps
Update the function to return the current nonce value plus one to accurately reflect the "next" nonce.
```
function getNextWithdrawNonce(address nodeOwner) public view returns (uint256) {
    return _state().nodeOwnerToWithdrawNonce[nodeOwner] + 1;
}
```
