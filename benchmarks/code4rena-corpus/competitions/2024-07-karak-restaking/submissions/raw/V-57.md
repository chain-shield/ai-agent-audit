# Vulnerability details

## Impact

Operators can bypass slashing.

## Proof of Concept

When DSS requests slashing, it checks whether the vault is staked to the DSS.

```
  function validateVaultsAndSlashPercentages(
        CoreLib.Storage storage self,
        SlashRequest memory slashingRequest,
        IDSS dss
    ) internal view {
        if (slashingRequest.vaults.hasDuplicates()) revert DuplicateSlashingVaults();

        uint256 maxSlashPercentageWad = getDSSMaxSlashablePercentageWad(self, dss);
        for (uint256 i = 0; i < slashingRequest.vaults.length; i++) {
>            if (!self.operatorState[slashingRequest.operator].isVaultStakeToDSS(dss, slashingRequest.vaults[i])) {
                revert VaultNotStakedToDSS();
            }
            if (slashingRequest.slashPercentagesWad[i] == 0) revert ZeroSlashPercentageWad();
            if (slashingRequest.slashPercentagesWad[i] > maxSlashPercentageWad) revert MaxSlashPercentageWadBreached();
        }
    }
```

What the operator can do is submit many `requestUpdateVaultStakeInDSS()`, and when the time comes to be slashed, the operator can frontrun the slashing by withdrawing the vault from DSS.

The `updateVaultStakeInDSS()` function doesn't check the return value of adding or removing the vault to the Enumerable Set, so even if the vault is already added, the function will not fail, but will simply return false.

Example, every couple hours or so, especially during the moments when the operator suspects that it is about to be slashed, the operator can submit multiple `requestUpdateVaultStakeInDSS()`, one adding the vault to the DSS and one removing the vault from the DSS.

T1: Operator requests for the vault to be removed
T2: Operator requests for the vault to be added
T3: Operator requests for the vault to be removed
T4: Operator requests for the vault to be added

In the event that the operator is not slashed yet, then the vault can be added back.

Set as medium severity as anyone can finalize the update by calling `finalizeUpdateVaultStakeInDSS()`, so that means that the operator has to keep submitting transactions to get ahead of the potential slashing.



## Tools Used

## Recommended Mitigation Steps

Make sure the operator can only call `requestUpdateVaultStakeInDSS()` once per vault, and it is either to add or remove the vault. If the vault is not added yet, the operator only can call `requestUpdateVaultStakeInDSS()` with `toStake == true`. Otherwise, the vault can only call `toStake == false`.
