# Vulnerability details

## Impact
Time sensitive slashing for the Operator wouldn't be possible for the DSS, as the finalize slashing method has to wait for 2 days before the next request slashing is approved 

## Proof of Concept
The request slashing method in slasher lib, allows to request the slashing of an operator, but the return value and success boolean of the request to DSS is ignored.

In the case where the transaction is reverted. Slashing requests cannot be made and the finalize slashing method will fail silently and the request would have to be made again in 2 days. 

```solidity
        HookLib.callHookIfInterfaceImplemented({
            dss: dss,
            data: abi.encodeWithSelector(
                dss.requestSlashingHook.selector, slashingMetadata.operator, slashingMetadata.slashPercentagesWad
            ),
            interfaceId: dss.requestSlashingHook.selector,
            //@audit
@>            ignoreFailure: true,
            hookCallGasLimit: self.hookCallGasLimit,
            supportsInterfaceGasLimit: self.supportsInterfaceGasLimit,
            hookGasBuffer: self.hookGasBuffer
        });

        HookLib.callHookIfInterfaceImplemented({
            dss: dss,
            data: abi.encodeWithSelector(dss.finishSlashingHook.selector, queuedSlashing.operator),
            interfaceId: dss.finishSlashingHook.selector,
            //@audit
@>            ignoreFailure: true,
            hookCallGasLimit: self.hookCallGasLimit,
            supportsInterfaceGasLimit: self.supportsInterfaceGasLimit,
            hookGasBuffer: self.hookGasBuffer
        });
```
This delay would give the operator more time to grief the protocol.

Manual analysis

## Recommended Mitigation Steps
Set the ignore failure in request Slashing to false.
