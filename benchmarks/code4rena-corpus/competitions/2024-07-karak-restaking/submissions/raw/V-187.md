# Vulnerability details

## Impact
the ```validateSnapshotProof``` function calculates ```balanceDeltaWei``` as the difference between ```newBalanceWei``` and ```prevBalanceWei```, both of which are uint256. The calculation is performed using int256 to handle the possibility of a negative difference.
## Proof of Concept
Consider the following scenario:
```prevBalanceWei``` is a uint256 with a value of (2^{255}) (which is within the valid range for uint256).
```newBalanceWei``` is also a uint256 and has a value slightly higher, say (2^{255} + 100).

When these values are converted to int256:
```int256(prevBalanceWei)``` will convert (2^{255}) correctly since it's the boundary value.
```int256(newBalanceWei)``` will overflow because (2^{255} + 100) exceeds the maximum positive value for an int256.
The overflow turns the value into a negative number in the int256 representation, which is not the intended behavior and can lead to incorrect calculations of balanceDeltaWei.
