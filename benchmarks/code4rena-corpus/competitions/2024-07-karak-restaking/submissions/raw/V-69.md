# Vulnerability details

## Impact
**`handleSlashing()`** is designed to slash a specified amount of a token. However, it has a issue, it sends the slashed amount to the **`address(0)`**. Some tokens revert when attempting to send to this address, causing the transaction to always revert. As a result, these tokens can never be slashed.

## Proof of Concept
**`handleSlashing()`** is implemented as follows:
```Solidity
function handleSlashing(IERC20 token, uint256 amount) external {
        if (amount == 0) revert ZeroAmount();
        if (!_config().supportedAssets[token]) revert UnsupportedAsset();

        SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
        // Below is where custom logic for each asset lives
@>      SafeTransferLib.safeTransfer(address(token), address(0), amount);
    }
```
As you can see, the final step involves sending the slashed amount to the **`address(0)`** to burn it. However, the issue is that some ERC20 tokens revert when attempting to send an amount to the **`address(0)`**.

For example, UNI reverts when the amount is sent to **`address(0)`**. 

The following internal function is the one that UNI uses to transfer the tokens:

```Solidity
function _transferTokens(address src, address dst, uint96 amount) internal {
        require(src != address(0), "Uni::_transferTokens: cannot transfer from the zero address");
@>      require(dst != address(0), "Uni::_transferTokens: cannot transfer to the zero address");

        balances[src] = sub96(balances[src], amount, "Uni::_transferTokens: transfer amount exceeds balance");
        balances[dst] = add96(balances[dst], amount, "Uni::_transferTokens: transfer amount overflows");
        emit Transfer(src, dst, amount);

        _moveDelegates(delegates[src], delegates[dst], amount);
    }
```
As you can see, it reverts if the destination is **`address(0)`**.

Source: https://etherscan.io/token/0x1f9840a85d5af5bf1d1762f925bdaddc4201f984#code#L520

In the ERC20 token behaivious "Revert on transfer to the zero address" is in scope and any ERC20 can be used in the protocol. The UNI token is one example of this.


This issue causes some tokens to never be slashed, leading to a denial of service (DOS) and malfunctioning of the protocol.

## Recommended Mitigation Steps
One solution could be to avoid sending the tokens to the **`address(0)`**. Instead, use the **`SlashingHandler.sol`** contract as the burn address, as it does not contain any function to withdraw tokens, effectively serving as a burning address.
