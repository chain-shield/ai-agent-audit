# Vulnerability details

## Impact
The `hasDuplicates` function in the `CommonUtils` library fails to correctly identify duplicates in all cases, potentially leading to false negatives. The root cause is that the function assumes duplicates will always be adjacent after sorting, which is not guaranteed due to the sorting algorithm's implementation.

## Proof of Concept
The vulnerable code is located in the `CommonUtils.sol` file:

https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/utils/CommonUtils.sol#L39-L45

```solidity
function hasDuplicates(address[] memory arr) external pure returns (bool) {
    sortArr(arr);
    if (arr.length == 0) return false;
    for (uint256 i = 0; i < arr.length - 1; i++) {
        if (arr[i] == arr[i + 1]) return true;
    }
    return false;
}
```

The issue is that this function assumes that after sorting, all duplicates will be adjacent to each other. However, this assumption is incorrect. The sorting function (sortArr) uses the <= operator in its comparisons:

```solidity
if (arr[i] <= arr[pivot]) {
    // ...
} 
```

This means that elements equal to the pivot can end up on either side of the pivot after partitioning. As a result, duplicates might not be adjacent in the final sorted array

To demonstrate the vulnerability, consider the following input array:
`[0x1111...1111, 0x2222...2222, 0x1111...1111, 0x3333...3333]`

After sorting, this could potentially become:
`[0x1111...1111, 0x2222...2222, 0x1111...1111, 0x3333...3333]`

In this case, the duplicates (0x1111...1111) are not adjacent, and the function would incorrectly return `false`, indicating no duplicates were found.

## Recommended Mitigation Steps
There are several ways to address this vulnerability:

1. Modify the `hasDuplicates` function to check all pairs, not just adjacent ones:

```solidity
function hasDuplicates(address[] memory arr) external pure returns (bool) {
    sortArr(arr);
    if (arr.length == 0) return false;
    for (uint256 i = 0; i < arr.length - 1; i++) {
        for (uint256 j = i + 1; j < arr.length; j++) {
            if (arr[i] == arr[j]) return true;
        }
    }
    return false;
}
```

This solution is thorough but increases time complexity to O(n^2).

2. Use a mapping to track seen addresses, which is more efficient:

```solidity
function hasDuplicates(address[] memory arr) external pure returns (bool) {
    mapping(address => bool) seen;
    for (uint256 i = 0; i < arr.length; i++) {
        if (seen[arr[i]]) return true;
        seen[arr[i]] = true;
    }
    return false;
}
```

This approach has O(n) time complexity and doesn't modify the original array.
