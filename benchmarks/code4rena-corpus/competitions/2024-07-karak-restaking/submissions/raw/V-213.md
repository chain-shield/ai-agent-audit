# Vulnerability details

## Impact
Any User can stop the "slashed assets" from being transferred from their nativenode to the `slashstore`. This would cause a loss of funds for the contract.

## Proof of Concept
In Native Restaking, any user (having >0 active validators) can start a snapshot which will update the `node.currentSnapshotTimestamp` of the user. Following this the users assets cannot be transferred out of the `native.node`. Even if the `validateExpiredSnapshot()` function is called by someone, it calls the `_startSnapshot()` function which has the following checks:

`if (node.currentSnapshotTimestamp != 0) revert PendingIncompleteSnapshot();`

Since the user has started a snapshot and not ended it (which he is not compelled to do), this check will cause the `_startSnapshot()` function to always revert. 

Since the slashedAsset transfer and calculation for a user is done inside the `_startSnapshot()` function, this makes it impossible for the nativeVault contract to transfer funds of the nativenode to the slashstore. And since the `withdraw()` function in the nativenode contract can be called only by the nativevault, the funds can never be transferred to the slashstore, thus causing a loss of funds for the contract.

## Tools Used
Manual

## Recommended Mitigation Steps
One way to mitigate this is to keep a time limit on how long a snapshot can remain open.
for example adding this check in the `_startSnapshot()` function:

`if (node.currentSnapshotTimestamp !=0 && node.currentSnapshotTimestamp + MAX_SNAPSHOT_TIME_PERIOD < block.timestamp)` // Added check
`{`
    `delete node.currentSnapshotTimestamp;`
    `delete node.currentSnapshot;`
`}`
`if (node.currentSnapshotTimestamp != 0) revert PendingIncompleteSnapshot();` // existing check
