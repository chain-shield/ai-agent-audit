# Vulnerability details

## Impact
The `getNodeOwner` function does not perform an existence check to ensure that the provided node address corresponds to a valid owner as other functions like [getValidatorDetails](), [lastSnapshotTimestamp](), [currentSnapshotTimestamp]()[startSnapshot](), [validateSnapshotProofs](), [validateWithdrawalCredentials](), [validateExpiredSnapshot](), [startWithdrawal](), [withdrawableWei](), [activeValidatorCount]().

## Proof of Concept
```

    function getNodeOwner(address node) external view returns (address) {
        return _state().nodeToOwner[node];
    }
```
The function should verify that the provided node address corresponds to an existing node before returning the owner's address.
If the node does not exist, the function should revert with an appropriate error.
The function returns the `owner` address without checking if the node exists.
If the node address does not exist in the `nodeToOwner` mapping, it returns the zero address (address(0)), which may not be the intended behavior.


## Tools Used

## Recommended Mitigation Steps
Update the `getNodeOwner` function to include a check that verifies the node address exists before returning the owner address. This can be achieved by using a modifier or including the check directly in the function.
```
modifier nodeAddressExists(address nodeAddress) {
    if (_state().nodeToOwner[nodeAddress] == address(0)) revert NotNodeAddress();
    _;
}
```
Updated `getNodeOwner` Function Using the Modifier
```

function getNodeOwner(address node) external view nodeAddressExists(node) returns (address) {
    return _state().nodeToOwner[node];
}
```
