# Vulnerability details

## Impact
DSS will receive incorrect operator address in `dss.finishUpdateStakeHook()` hook.

## Proof of Concept

After a stake vault update request is made, the `Core::finalizeUpdateVaultStakeInDSS()` function must be called to finalize the request, and the protocol allows anyone to call this function.

So in the function calling, `msg.sender` may or may not be an operator. When calling `HookLib.callHookIfInterfaceImplemented()` in the `validateAndUpdateVaultStakeInDSS()` function, `msg.sender` is passed along with `dss.finishUpdateStakeHook.selector`.

```solidity
    function validateAndUpdateVaultStakeInDSS(CoreLib.Storage storage self, QueuedStakeUpdate memory queuedStakeUpdate)
        external
    {
        ... ...
        HookLib.callHookIfInterfaceImplemented({
            dss: dss,
            data: abi.encodeWithSelector(dss.finishUpdateStakeHook.selector, msg.sender), // @audit --> `msg.sender` is passed
            interfaceId: dss.finishUpdateStakeHook.selector,
            ignoreFailure: true,
            hookCallGasLimit: self.hookCallGasLimit,
            supportsInterfaceGasLimit: self.supportsInterfaceGasLimit,
            hookGasBuffer: self.hookGasBuffer
        });
    }
```

Therefore, the DSS may receive an incorrect address as an operator (or potentially a malicious hacker) and proceed with further operations using this address.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Just pass `queuedStakeUpdate.operator` instead of `msg.sender`.
