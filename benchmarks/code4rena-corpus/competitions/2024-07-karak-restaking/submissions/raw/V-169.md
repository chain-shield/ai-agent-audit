# Vulnerability details

## Impact

In the `HookLib.sol` the function `callHookIfInterfaceImplemented()` checks whether the `gasLeft()` is bigger than `(supportsInterfaceGasLimit * 64 / 63 + hookGasBuffer)`. However, the problem is that the check only multiplies gas limit for the function on 64/63 instead of multiplying the whole part along with the `hookGasBuffer`. The low-level call is performed with at most 63/64th of
the gas that the caller context has available. `hookGasBuffer` is as well gas available so not multiplying it by 64/63 means that the function doesn't make sure that the call is performed with at least gas available equal to gas limit plus gas buffer. 


## Proof of Concept

1. EIP-150 states that only 63/64th of the gas that the caller has forwarded for the call. 

2. In the current implementation of the hook functionality, only gas limit is multiplied by 64/63 not including the `gasBuffer` that is also included in the available gas for the call.

3. This leads to the check not being implemented correctly as it does not make sure that the function call is performed with 63/64th of the gas available. It only multiplies `supportsInterfaceGasLimit` and does not include `hookGasBuffer`.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Change the check on:

```
  if (gasleft() < (supportsInterfaceGasLimit + hookGasBuffer) * 64 / 63 ) {
            revert NotEnoughGas();
        }
```
