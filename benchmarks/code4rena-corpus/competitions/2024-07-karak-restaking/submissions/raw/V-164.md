# Vulnerability details

## Impact
NativeVault implements the changeNodeImplementation function in NativeVault.sol, which is restricted to calls from the owner or an address with the manager role. However, the core contract fails to implement a corresponding changeNodeImplementation function, resulting in a potential denial-of-service (DoS) vulnerability

## Proof of Concept
From [CoreLib.sol::createVault](https://github.com/code-423n4/2024-07-karak/blob/main/src/entities/CoreLib.sol#L89-L116) we can see the owner of the new vault is address(this)/Core.sol.

From [NativeVault.sol::changeNodeImplementation](https://github.com/code-423n4/2024-07-karak/blob/main/src/NativeVault.sol#L83-L92) we can see only owner or manager role can change the NodeImplementation address
```solidity
    function changeNodeImplementation(address newNodeImplementation)
        external
        onlyOwnerOrRoles(Constants.MANAGER_ROLE)
        whenFunctionNotPaused(Constants.PAUSE_NATIVEVAULT_NODE_IMPLEMENTATION)
    {
        if (newNodeImplementation == address(0)) revert ZeroAddress();

        _state().nodeImpl = newNodeImplementation;
        emit UpgradedAllNodes(newNodeImplementation);
    }
```

However, the core contract fails to implement a corresponding changeNodeImplementation function, resulting in a potential denial-of-service (DoS) vulnerability
