# Vulnerability details

## Impact
In the `Querier.sol` contract, the `fetchVaultsQueuedForExit` function first retrieves `slots`, and then iterates through the elements in `slots` (including `bytes32(0)` elements) using the `core.extSloads(slots)` function to get `results`. Afterward, the `bytes32(0)` elements are removed from `results`. This process causes `core.extSloads(slots)` to perform unnecessary iterations over `bytes32(0)` elements.

## Proof of Concept
The function currently obtains the `slots` array by calling `CoreStorageSlots.vaultPendingStakeUpdateSlot(operator, stakedVaults[i])`, and then uses `core.extSloads(slots)` to iterate through `slots` (including `bytes32(0)` elements) to get `results`. Finally, it removes the `bytes32(0)` elements from `results` to return the addresses of vaults queued for withdrawal. This leads to `extSloads` iterating over superfluous `bytes32(0)` elements.

## Recommended Mitigation Steps
Therefore, it is recommended to first remove the `bytes32(0)` elements from `slots` and then use the `core.extSloads(slots)` function to iterate through the cleaned `slots` array to obtain `results`.
