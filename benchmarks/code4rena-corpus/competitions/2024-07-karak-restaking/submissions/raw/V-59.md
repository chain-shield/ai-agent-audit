# Vulnerability details

## Impact

If one slashing fail, it affects all the other slashing since the function is in a loop.

The problem is that when the slashing fails, the operator will have more time to remove all the vaults affected to bypass the slashing.

## Proof of Concept

When the DSS intends to slash an operator, he can slash multiple vaults at once, to a maximum of 100%. The DSS calls `requestSlashing()` and if the slash is not vetoed, then anyone can call `finalizeSlashing()` to slash the assets in the operator's vaults.

Slashing happens in a loop:

```
    function finalizeSlashing(CoreLib.Storage storage self, QueuedSlashing memory queuedSlashing) external {
        bytes32 slashRoot = calculateRoot(queuedSlashing);
        if (!self.slashingRequests[slashRoot]) revert InvalidSlashingParams();
        if (queuedSlashing.timestamp + Constants.SLASHING_VETO_WINDOW > block.timestamp) {
            revert MinSlashingDelayNotPassed();
        }
        delete self.slashingRequests[slashRoot];

>            IKarakBaseVault(queuedSlashing.vaults[i]).slashAssets(
>                queuedSlashing.earmarkedStakes[i],
                self.assetSlashingHandlers[IKarakBaseVault(queuedSlashing.vaults[i]).asset()]

```

There are two main reasons why the slashing might fail. First, if the slashing percentage is way too high and second, if the protocol fails to check that the asset cannot be transferred to address(0).

If the percentage is too high, eg slashing by 80%, there is a chance that there may not be enough assets in the vault anymore once the veto period is up.  

Imagine operator Alice is doing an extremely poor job in all of the vaults she maintains. The DSS intends to slash all vaults as a punishment, so vault A,B,C,D are all slashed by 80%.

Vault A has 1000 tokens, so 800 tokens is expected to be taken away. Before the veto period, users that deposited in vault A withdraws their funds (they have called request withdraw a long time prior, not knowing that the vault will be slashed), and now Vault A has 700 tokens left.

When finalize slashing is called, it will fail because it attempts to take 800 tokens from Vault A, which only has 700 tokens. Also, the other vaults cannot be slashed because the whole function will fail.

The DSS will then have to repeat the whole slashing process. This gives time for Alice to unstake all their vaults and bypass the slashing.

## Recommended Mitigation Steps

If the slashing amount is greater than the vault amount, then sweep the vault amount instead. Also, put the slashing in a try/catch block so that even if one vault fails to be slashed, the other vaults can still be slashed, preventing possible bypassing scenarios.
