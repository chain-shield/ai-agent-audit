# Vulnerability details

## Impact
The `cancelSlashing` function in the contract allows the Veto Committee to cancel slashing requests. However, the function does not check whether the veto window has passed before allowing a cancellation. This issue can lead to slashing requests being cancelled even after the designated veto window has expired, undermining the integrity of the slashing process and allowing potentially malicious cancellations.

Security Breach: Slashing requests can be unjustifiably cancelled after the veto period, enabling malicious actors to avoid penalties.

Once the `requestslashing` is made there is time for committee to cancel the slashing within the 2 days after the request is made. If `finalizeslashing` is not called which check that the cool down time is passed or not, but the issue is if DSS entity or any-one forgot to finalize the slashing after the cooldown end, requested slashing request can be cancelled even after the committee slahing_veto_Commite = 2 days is passed because committee can still execute the cancel slashing as there is no time check for that or bound on cancel slashing function.
