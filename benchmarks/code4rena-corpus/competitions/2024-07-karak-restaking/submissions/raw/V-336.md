# Vulnerability details

vulnerability details
 
a user can withdraw after the withdrawal delay has passed but slashing can prevent users from withdrawing even if the withdrawal delay has passed.
when request slashing is called for a user which will trigger

               uint256 public constant SLASHING_WINDOW = 7 days;
              uint256 public constant SLASHING_VETO_WINDOW = 2 days;

now since the request slashing function has no access modifier anyone can request slashing which will prevent users from withdrawing until the slashing window and slashing window veto is passed also since there is no access modifier a malicious user can call the request slashing again and again which will prevent users from withdrawing which can cause complete dos of the withdrawal function


impact

users wont be able to withdraw 


proof of concept

*a users request withdrawal
*when the withdrawal delay passes and the user is just about to withdraw
*a malicious user calls requestslashing which wont let user withdraw 


Recommended Mitigation Steps

restrict access for request slashing
