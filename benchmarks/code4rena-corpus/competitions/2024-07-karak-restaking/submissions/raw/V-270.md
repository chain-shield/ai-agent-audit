# Vulnerability details

## Impact
The `registerDSS` function currently uses `dss` which is casting msg.sender to IDSS interface the dss address and msg.sender address will be same, and check if the caller is a smart contract by inspecting the bytecode size. This method fails if the function is called from within a constructor because the bytecode hasn't been deployed yet. To mitigate this issue, the function should accept an address parameter and perform the check on this address. 
https://www.rareskills.io/post/solidity-code-length

## Proof of Concept

```solidity
contract DSS {
    function registerDSS(address dssAddress, uint256 maxSlashablePercentageWad) external {
        if (!address(dssAddress).isSmartContract()) revert NotSmartContract();
        _self().setDSSMaxSlashablePercentageWad(IDSS(dssAddress), maxSlashablePercentageWad);
        emit DSSRegistered(dssAddress, maxSlashablePercentageWad);
    }

    function isSmartContract(address addr) public view returns (bool) {
        uint256 size;
        assembly {
            size := extcodesize(addr)
        }
        return size > 0;
    }
}
```

## Recommended Mitigation Steps
Modify the `registerDSS` function to accept an address parameter and check the code length for that address, rather than relying on msg.sender directly. Here is the revised code:
```javascript
contract DSS {
    function registerDSS(address dssAddress, uint256 maxSlashablePercentageWad) external {
        require(dssAddress == msg.sender,"msg.sender and dssAddress are not same");
        if (!address(dssAddress).isSmartContract()) revert NotSmartContract();
        _self().setDSSMaxSlashablePercentageWad(IDSS(dssAddress), maxSlashablePercentageWad);
        emit DSSRegistered(dssAddress, maxSlashablePercentageWad);
    }

    function isSmartContract(address addr) public view returns (bool) {
        uint256 size;
        assembly {
            size := extcodesize(addr)
        }
        return size > 0;
    }
}
```
