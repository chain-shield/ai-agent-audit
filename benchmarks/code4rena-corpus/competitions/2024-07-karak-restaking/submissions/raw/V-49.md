# Vulnerability details

## Impact
The `finishUpdateStakeHook()` selector from the `IDSS` interface, indicates that the incoming address parameter is supposed to be the `operator` address. However, the `Core::finalizeUpdateVaultStakeInDSS()` function can be called by any user. Because of this `msg.sender` is propagated to `Operator::validateAndUpdateVaultStakeInDSS()`, where it is finally sent as an `operator` parameter to `finishUpdateStakeHook()` in `abi.encodeWithSelector(dss.finishUpdateStakeHook.selector, msg.sender)`. Because of this, any arbitrary user will be treated as an operator which allows malicious users to execute the associated logic, which could involve something like registering the address to receive rewards.

This issue was reported in a previous [audit](https://code4rena.com/reports/2024-06-karak-pro-league) of Karak, made by Code4Arena. Both the auditing team and the protocol have confirmed that it should be fixed, however, it appears to be still valid.

## Proof of Concept

1. An operator initiates `requestUpdateVaultStakeInDSS()`, which goes through successfully and emits the updated stake information -> `emit RequestedStakeUpdate(updatedStake)`
2. Alice intercepts this emission and then calls `finalizeUpdateVaultStakeInDSS()` with the operator's `queuedStake`. This in turn will send Alice's address as an operator's address in the `finishUpdateStakeHook()` function, incorrectly allowing her to do malicious actions to the protocol.

## Recommended Mitigation Steps

If `Core::requestUpdateVaultStakeInDSS()` is meant to be callable by anyone, then change which address is being sent in the `HookLib.callHookIfInterfaceImplemented()` function in `Operator::validateAndUpdateVaultStakeInDSS()` from `msg.sender` to `queuedStakeUpdate.operator`

```diff
diff --git a/src/entities/Operator.sol b/src/entities/Operator.sol
index 31a3964..7425cf1 100644
--- a/src/entities/Operator.sol
+++ b/src/entities/Operator.sol
@@ -123,7 +123,7 @@ library Operator {
         IDSS dss = queuedStakeUpdate.updateRequest.dss;
         HookLib.callHookIfInterfaceImplemented({
             dss: dss,
-            data: abi.encodeWithSelector(dss.finishUpdateStakeHook.selector, msg.sender),
+            data: abi.encodeWithSelector(dss.finishUpdateStakeHook.selector, queuedStakeUpdate.operator),
             interfaceId: dss.finishUpdateStakeHook.selector,
             ignoreFailure: true,
             hookCallGasLimit: self.hookCallGasLimit,
```
