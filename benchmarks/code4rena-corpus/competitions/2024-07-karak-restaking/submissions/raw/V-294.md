# Vulnerability details

## Impact
When executing some functions in the Operator.sol contract ([requestUpdateVaultStakeInDSS](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L61C4-L87C6), [validateAndUpdateVaultStakeInDSS](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L111C5-L134C1), [registerOperatorToDSS](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L150C5-L171C6), [unregisterOperatorFromDSS](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L181C4-L203C6)), a low-level call is made at the end of these functions using the HookLib contract's [callHookIfInterfaceImplemented](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/HookLib.sol#L78C5-L103C6) function.

The call fails and emits an event indicating that DSS does not support the IDSS interface **InterfaceNotSupported()**.

This function is also used in 3 functions of the [SlasherLib](https://github.com/code-423n4/2024-07-karak/blob/main/src/entities/SlasherLib.sol) contract which also cause the same problem: [requestSlashing#L113-123](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/SlasherLib.sol#L113C9-L123C12), [finalizeSlashing#L142-150](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/SlasherLib.sol#L142C9-L150C12) and [cancelSlashing#L159-167](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/SlasherLib.sol#L159C9-L167C12).

To run the POC and view the error, type the following command:

```bash
$ forge test --match-contract OperatorTest -vvvvv
```

The error in the HookLib contract's callHookIfInterfaceImplemented function is found in a condition between line 97-101:

```bash
if (!success || result == bytes32(0)) {
            // Either call failed or interface isn't implemented
            emit InterfaceNotSupported();
            return false;
        }
```

The condition checks whether the call has failed or whether the return value **result** is equal to bytes32(0). In the latter case, it emits the InterfaceNotSupported() event and returns false, but according to the IDSS interface, no function returns a value, so the low-level call won't go all the way, and the result will always return bytes32(0), the function will always emit the InterfaceNotSupported() event and return false.

## Tools Used
Foundry

## Recommended Mitigation Steps
In order for the low-level call to go all the way, part of the condition "**result == bytes32(0)**" should be removed:

```bash
if (!success) {
     // Either call failed or interface isn't implemented
     emit InterfaceNotSupported();
     return false;
}
```
