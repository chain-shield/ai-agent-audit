# Vulnerability details

vulnerability details

the snapshot function is used by a nativenodeowner to keep the NativeNode aware of the balance changes on the beacon chain. NativeVault updates the node owner's shares based on the balance changes on their NativeNode and the beacon chain balance of the validators, which in turn changes the amount the node owner has staked into an Operator, affecting the rewards given to them, anyone can start a snapshot for the user the problem with this is anyone can submit a manipulated snapshot and the nativenode owner wont be able to provide the valid snapshot
until the snapshot is expired (7 days)  due to  checks in nativevault.sol 

if (validatorDetails.lastBalanceUpdateTimestamp >= node.currentSnapshotTimestamp) {
                revert ValidatorAlreadyProved();

 if (node.lastSnapshotTimestamp + Constants.SNAPSHOT_EXPIRY > block.timestamp) {
            revert SnapshotNotExpired();
        }

impact

an incorrect snapshot could lead to decisions based on inaccurate data. native node owners can be unfairly penalized/slashed based on incorrect data 

PROOF OF CONCEPT

*A user submits a malicious snapshot for a node owner
*The node owner sees it and tries to submit the valid snapshot
*but the transaction reverts because the function doesn't allow a new snapshot if there is already a pending one
*After the transaction is completed, the user again tries to submit the valid snapshot, but the function reverts again due to checks in NativeVault.sol, which do not allow a new snapshot if the last snapshot has not expired or if the validator has already proven it.

Recommended Mitigation Steps

only allow the nativenode owner to submit a snapshot for their nodes
