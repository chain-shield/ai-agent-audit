# Vulnerability details

## Impact


## Proof of Concept
When the user calls the validateWithdrawalCredentials function, their balance only increases by 32 ETH, even if the validator has more than 32 ETH. This is because the function uses getEffectiveBalanceWei, which returns a maximum of 32 ETH.

```solidity
uint256 restakedBalanceWei = BeaconProofs.getEffectiveBalanceWei(validatorFieldsProof.validatorFields);
        BeaconProofs.validateValidatorProof(
            validatorFieldsProof.validatorProof.validatorIndex,
            validatorFieldsProof.validatorFields,
            validatorFieldsProof.validatorProof.proof,
            beaconStateRoot
        );

        validatorDetails.status = NativeVaultLib.ValidatorStatus.ACTIVE;
        validatorDetails.validatorIndex = validatorFieldsProof.validatorProof.validatorIndex;
        validatorDetails.lastBalanceUpdateTimestamp = updateTimestamp;
        validatorDetails.restakedBalanceWei = restakedBalanceWei;
        self.ownerToNode[nodeOwner].validatorPubkeyHashToDetails[validatorPubkeyHash] = validatorDetails;
        self.ownerToNode[nodeOwner].activeValidatorCount++;

        emit RestakedValidator(
            nodeOwner,
            self.ownerToNode[nodeOwner].nodeAddress,
            validatorFieldsProof.validatorProof.validatorIndex,
            updateTimestamp,
            restakedBalanceWei
        );
        return restakedBalanceWei;
```

This can cause problems when the user wants to withdraw from the native vault. 

Suppose a user wants to withdraw and calls the validateSnapshotProofs function after starting a snapshot. At that time, the user's native node balance will be 64 ETH, and they can withdraw their funds using the finishWithdrawal function. However, if slashing occurs before the withdrawal, the user will face penalties based on their 64 ETH, not 32 ETH. This is unfair as the user earns DSS rewards based on their vault shares, which are 32 ETH when the user staked.

POC:


Let's consider native vaults with the following values:
- totalSupply: 100e18
- totalAsset: 100e18

When a user stakes, their shares will be 32e18, and they will receive DSS rewards according to their 32e18 shares. 

If the user withdraws from the validator and calls the validateSnapshotProofs function, the vault's totalSupply will become 132e18, and the totalAsset will become 132e18. Consequently, the user's share will increase to 64e18.

When the vault gets slashed, leading to the totalAsset becoming 122e18, the user calls the finishWithdrawal function and they can only withdraw 59.15e18.

The slash reduced the user's share from 64e18 to 59.15e18, resulting in a loss of 4.85e18.
(64e18 * 122e18 / 132e18 = 59.15e18 ==> 64e18 - 59.15e18 = 4.85e18)

If the user only has 32ETH, their loss will be 3.2e18.
(32e18 * 90e18 / 100e18 = 28.8e18 ==> 32e18 - 28,8e18 = 3.2e18)

Due to the use of getEffectiveBalanceWei, users receive lower rewards and can face higher penalties.
## Tools Used
Manual Review
## Recommended Mitigation Steps
Consider using the validateBalance instead of getEffectiveBalanceWei. When the user stakes, they will have 64 ETH instead of 32 ETH, making everything fair.
