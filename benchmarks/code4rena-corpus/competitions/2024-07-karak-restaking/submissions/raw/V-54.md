# Vulnerability details

## Impact

Since anyone can submit balance proofs, if a balance proof has already been submitted the function `validateSnapshotProofs` should simply skip that balance proof instead of reverting the whole transaction. Reverting can cause problems when different array lengths of balance proofs are submitted by different users, making submitting the proofs a convoluted process. Also this process is able to be grieved

Say a user wants to submit 20 balance proofs, a troll can submit just 1, making the original users entire transaction fail, forcing them to review the transaction and alter the array and try again, where they can be dossed again
