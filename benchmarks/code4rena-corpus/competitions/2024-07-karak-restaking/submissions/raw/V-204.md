# Vulnerability details

## Impact
`Since anyone can deploy vaults for any operator` there is a scenario where an attacker deploys vaults with same `depositToken`(allowed) for an operator until the number of vaults reaches `Constants.MAX_VAULTS_PER_OPERATOR`, after which a vault with a different `depositToken` cannot be added. 

## Proof of Concept
More details:
1. `Constants.MAX_VAULTS_PER_OPERATOR = 32`. `Operator` deploys 2 vaults with different allowedAssets and plans to create a vault with other `depositTokens` in the future.
2. `attacker` deploys another 30 vaults with allowed token for this operator
3. The operator can no longer deploy new vaults` as the maximum number of vaults has been reached. The vaults created by the attacker are lying dead.
## Tools Used

## Recommended Mitigation Steps
There is a few way to avoid this risk:
1. Leave the ability to add a vault to the operator only,
2. Do not allow to add vaults with same `depositToken`,
3. Extend MAX_VAULTS_PER_OPERATOR.
