# Vulnerability details

## Intro
In the `BeaconProofs` library, there is a critical bug in the `validateBalance` function where the wrong bit shift operator is used when extracting a validator's balance. This error leads to incorrect balance calculations for most validators.

## Vulnerable Code
https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/BeaconProofsLib.sol#L134

```solidity
return uint256(fromLittleEndianUint64(bytes32((uint256(proof.balanceRoot) << bitShiftAmount)))) * 1 gwei;
```

The issue is the use of the left shift operator (`<<`) instead of the right shift operator (`>>`).

## Why This Is a Problem
The `balanceRoot` contains the balances of four validators packed into a single `bytes32` value. To extract an individual validator's balance, we need to shift the bits right to isolate the correct 64-bit segment. However, the current code shifts left, which moves the desired bits out of the 64-bit window that `fromLittleEndianUint64` reads from.

## How It Should Work
1. The `balanceRoot` contains four 64-bit balance values packed together.
2. `bitShiftAmount` is calculated as `(validatorIndex % 4) * 64`, which determines how far to shift to get the correct balance.
3. We should shift right by `bitShiftAmount` to move the desired 64-bit balance to the least significant bits.
4. `fromLittleEndianUint64` then reads these least significant bits and converts them to a `uint64`.

## Impact
1. For validator index 0 in each group of 4, the balance is accidentally correct (shifting by 0 bits).
2. For the other 3 validators in each group, the balance will be wildly incorrect:
- Index 1: Shifts left by 64 bits, reading the next validator's balance.
- Index 2: Shifts left by 128 bits, reading zeros.
- Index 3: Shifts left by 192 bits, reading zeros.

This means 75% of all validators will have incorrectly reported balances, either showing as zero or as another validator's balance.

## Mitigation
The line should be changed to:

```solidity
return uint256(fromLittleEndianUint64(bytes32((uint256(proof.balanceRoot) >> bitShiftAmount)))) * 1 gwei;
```

This correctly shifts the bits right, isolating the appropriate 64-bit balance value for the `fromLittleEndianUint64` function to process.
