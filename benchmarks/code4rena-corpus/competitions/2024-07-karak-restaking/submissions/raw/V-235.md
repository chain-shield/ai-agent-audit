# Vulnerability details

## Impact
This vulnerability would allow an operator to avoid having their vault's implementation changed when `Core::changeStandardImplementation` is called. This allows the user to sidestep any important vulnerability fixes or potentially opens up a vulnerability if the old implementation is incompatible with any protocol wide changes. The owner of `Core` wouldn't be aware in order to change the implementation manually.

## Proof of Concept
The user calls `Core::deployVaults` function with `vaultImpl` parameter set to the same value as `self().vaultImpl`. From there the implementation will be passed to `CoreLib::deployVaults` and then `CoreLib::validateVaultConfigs` and `CoreLib::isVaultAllowlisted`. In this function the implementation address will be validated and then later in the `CoreLib::createVault` function the implementation will be set in `vaultToImplMap`.

Now whenever an admin wants to globally change the standard implementation they will call the `Core::changeStandardImplementation` function and the new implementation will be set to storage.
```solidity
    function changeStandardImplementation(address newVaultImpl) external onlyOwner {
        if (newVaultImpl == address(0)) revert ZeroAddress();
        if (newVaultImpl == Constants.DEFAULT_VAULT_IMPLEMENTATION_FLAG) revert ReservedAddress();
        _self().vaultImpl = newVaultImpl;
        emit UpgradedAllVaults(newVaultImpl);
    }
```
Now even tho the standard implementation was changed globally the `Core::implementation` function will still return the old vault implementation, because the `vaultToImplMap[vault]` is not set to the `DEFAULT_VAULT_IMPLEMENTATION_FLAG` so `vaultImplOverride` will be returned at the end of the function.
```solidity

@>      if (vaultImplOverride == Constants.DEFAULT_VAULT_IMPLEMENTATION_FLAG) {
            return self.vaultImpl;
        }
        return vaultImplOverride;
    }
```

## Tools Used
Manual review.

## Recommended Mitigation Steps
Don't allow setting the `vaultToImplMap` mapping for the operator to the actual implementation address only the `DEFAULT_VAULT_IMPLEMENTATION_FLAG`.
