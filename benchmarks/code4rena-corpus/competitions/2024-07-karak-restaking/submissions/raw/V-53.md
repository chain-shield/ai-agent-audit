# Vulnerability details

## Impact
`node.withdrawableCreditedNodeETH` = the amount of ETH ever held by the native node as it is increased in `_updateSnapshot()` by `nodeBalanceWei`:
```solidity
node.withdrawableCreditedNodeETH += snapshot.nodeBalanceWei;
```
Note that `node.withdrawableCreditedNodeETH` is not modified anywhere else in the code. `node.withdrawableCreditedNodeETH` is used in `_startSnapshot()` to calculate the amount of ETH gained by the native node since the last snapshot:
```solidity
// Calculate unattributed node balance
uint256 nodeBalanceWei = node.nodeAddress.balance - node.withdrawableCreditedNodeETH;
```
The native node's ETH balance will become smaller than `node.withdrawableCreditedNodeETH`. Thus, when `_startSnapshot()` is called, `node.nodeAddress.balance` - `node.withdrawableCreditedNodeETH` will revert.
## Proof Of Concept
1. Alice's native node has 5 ETH of balance. (`nodeAddress.balance` && `node.withdrawableCreditedNodeETH` = 5e18)
2. Alice withdraws 1 ETH from the native node.
3. After that, `_startSnapshot()` is called
4. `nodeAddress.balance` - `node.withdrawableCreditedNodeETH` = 4e18 - 5e18 (reverts)

Manual Review
## Recommended Mitigation Steps
`node.withdrawableCreditedNodeETH` should store the balance of the native node during the last snapshot
