# Vulnerability details

## Impact

Vault shares can be easily inflated through donating assets. This means that when a user wants to mint shares, an attacker can front-run his transaction and donate tokens to the vault without minting any shares in exchange, this means the shares are now worth more since we have more assets, thus the user will have to pay more assets for the same amount of shares.

## Proof of Concept

Let's look at the following example:

- Bob wants to directly mint shares so he calls `Vault::mint(shares=100e18)`. The current exchange is 1e18 shares = 1e18 assets(1:1). Assume the vault is newly deployed and has low liquidity of let's say 500e18 tokens and 500e18 shares.
- A malicious user sees Bob's transaction and front-runs it by donating 500e18 assets in exchange for 0 shares. Now we have 1000e18 assets and 500e18 shares, meaning 1e18 shares = 2e18 assets(1:2).
- Assume Bob is planning to continuously deposit assets to the vault so he gives it a maximum approval, now his transaction executes and he pays 200e18 assets instead of 100e18.

This way the attecker successfully makes Bob pay more assets than he should have. This can easily be executed in low liquidity vaults.

Another thing to take into account here is that Bob doesn't want to use the deposit function with the slippage parameter because he allows some slippage. Let's say that he wanted to acquire 100e18 shares for a maximum of 150e18 assets(ideally 100e18 but he allows some slippage), then the `Vault::deposit(uint256 assets, address to, uint256 minSharesOut)` doesn't do the job and he has to use the mint function that currently has no slippage protection. This way Bob is tricked into supplying more than he wanted.

## Recommended Mitigation Steps

Adding a `maxAssets` to the `mint()` function will solve this issue.

```diff
-     function mint(uint256 shares, address to)
+     function mint(uint256 shares, address to, uint256 maxAssets)
        public
        override(ERC4626, IVault)
        whenFunctionNotPaused(Constants.PAUSE_VAULT_MINT)
        nonReentrant
        returns (uint256 assets)
    {
        if (shares == 0) revert ZeroShares();
        assets = super.mint(shares, to);
+       if(assets > maxAssets) revert ExceedsMaxAssets();
    }
```
