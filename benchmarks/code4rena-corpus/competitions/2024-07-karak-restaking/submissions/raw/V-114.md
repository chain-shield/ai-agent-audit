# Vulnerability details

## Impact
An honest withdrawal cannot be processed in NativeVault after exiting Beacon.

## Proof of Concept
Consider a NativeVault_A.
1. User deploys a NativeNode on NativeVault_A
2. A validators set the NativeNode as the withdraw credentials on Beacon and calls ```validateWithdrawalCredentials()``` to update shares!
at 1:1, 32e18 was minted to NodeOwner
```solidity
    function _increaseBalance(address _of, uint256 assets) internal {
        NativeVaultLib.Storage storage self = _state();
        if (assets + self.totalAssets > maxDeposit(_of)) revert DepositMoreThanMax();
        uint256 shares = convertToShares(assets);
        _mint(_of, shares);
        self.totalAssets += assets;
        self.ownerToNode[_of].totalRestakedETH += assets;
        emit IncreasedBalance(self.ownerToNode[_of].totalRestakedETH);
    }
```
3. NodeOwner decides to exit beacon.
4. Beacon processes exit after 27hrs lock period, before processing withdrawal to be sent to the NativeNode
5. An attacker calls ```validateExpiredSnapshot()``` with the address of NodeOwner that just exited to initiate a snapshot process.
Note, at this time no funds in NativeNode yet, as withdrawal is yet to arrive, so node.snapshot is set to;
