# Vulnerability details

## Impact
There is an edge case that can cause a decrease in the value of the `activeValidatorCount` variable that is not being considered in the current code, this will cause an incorrect state in the `activeValidatorCount` variable in the nativeVault.

## Proof of Concept
The `activeValidatorCount` variable in the `NativeVault` is used to have a register of the active validators in the beacon chain that are associated to a `NativeNode`in the Karak ecosystem, this variable is incremented every time a withdrawal credential for a validator is linked to a `NativeNode` to reflect the active beacon chain validator associated to the Native Node.
```solidity
function validateWithdrawalCredentials(//...) internal returns (uint256) 
{
  //...
   self.ownerToNode[nodeOwner].validatorPubkeyHashToDetails[validatorPubkeyHash] = validatorDetails;
   self.ownerToNode[nodeOwner].activeValidatorCount++;
}
```
And when a user decides to fully withdraw a node (withdraws all the ETH from the node) the `activeValidatorCount` is decreased to reflect the validator is exited from the beacon chain, the `activeValidatorCount` variable is only decreased in this scenario, but there is another scenario that will cause that a validator exit de beacon chain that is not being taken into account to decrease the `activeValidatorCount` variable.
```solidity
function validateSnapshotProof(//...) internal returns (int256 balanceDeltaWei) 
{
   //...
   if (newBalanceWei == 0) {
       self.ownerToNode[nodeOwner].activeValidatorCount--;
       validatorDetails.status = ValidatorStatus.WITHDRAWN;

       emit ValidatorWithdrawn(nodeOwner, nodeAddress, timestamp, validatorIndex);
   }
}
```

The beacon chain forces a validator to exit the network, thus become inactive, if the effective balance of this validator falls to or below 16 ETH, for any reason, it may fall to this balance probably for an "inactivity leak", or probably because a user decides to withdraw an ETH amount from the node that reduces the ETH balance to or below de 16 ETH, in this case as the validator will exit the network, the `activeValidatorCount` should decrease too.

https://eth2book.info/capella/part3/config/configuration/#ejection_balance

> EJECTION_BALANCE
> If a validator's effective balance falls to 16 Ether or below then it is exited from the system. This is most likely to happen as a result of the "inactivity leak", which gradually reduces the balances of inactive validators in order to maintain the liveness of the beacon chain.
> 
> This mechanism is intended to protect stakers who no longer have access to their keys. If a validator has been offline for long enough to lose half of its balance, it is unlikely to be coming back. To save the staker from losing everything, we choose to eject the validator before its balance reaches zero.
> 
> Note that the dependence on effective balance means that the validator is queued for ejection as soon as its actual balance falls to 16.75 Ether.


## Tools Used
Manual review

## Recommended Mitigation Steps
consider implementing a check to validate if the effective balance of a validator is equal to or less than 16 ETH and decrease the `activeValidatorCount` variable in this case.
