# Vulnerability details

## Impact
`NativeVault.sol`'s `changeNodeImplementation` function can only be called by the `Core` contract or the `MANAGER_ROLE`. As this function is never called in the `Core` contract, practically only the manager of the Native Vault can call it. 

As a result, through the `changeNodeImplementation` function malicious Native Vault managers can steal all funds from users' nodes or may prevent vaults from being slashed.

It is important to note that even though Native Vault managers are granted a role with the same name as the trusted Core manager's role, the two roles are completely different, as the Native Vault manager's role is granted by untrusted addresses.

The issue is that the manager is specified by the operator of the Native Vault. As operators are not trusted, Native Vault managers can also not be trusted and may be malicious contracts.

## Proof of Concept
As we can see `changeNodeImplementation` allows the untrusted manager to change the implementation contract of the Native node:
```solidity
    function changeNodeImplementation(address newNodeImplementation)
        external
        onlyOwnerOrRoles(Constants.MANAGER_ROLE)
        whenFunctionNotPaused(Constants.PAUSE_NATIVEVAULT_NODE_IMPLEMENTATION)
    {
        if (newNodeImplementation == address(0)) revert ZeroAddress();

        _state().nodeImpl = newNodeImplementation;
        emit UpgradedAllNodes(newNodeImplementation);
    }
```

Therefore, any funds stored in the Native node contracts may be stolen by simply changing the implementation to a malicious contract. Furthermore, this can prevent the slash store from receiving any slashed funds.
