# Vulnerability details

### Description:
The `finishRedeem` function in the Vault contract, which completes the redemption process after a delay, lacks slippage protection. This omission exposes users to potential losses if the exchange rate between shares and assets changes unfavorably during the delay period.

### Vulnerable Code:

https://github.com/code-423n4/2024-07-karak/blob/main/src/Vault.sol#L157


```solidity
function finishRedeem(bytes32 withdrawalKey)
    external
    nonReentrant
    whenFunctionNotPaused(Constants.PAUSE_VAULT_FINISH_REDEEM)
{
    (VaultLib.State storage state, VaultLib.Config storage config) = _storage();

    WithdrawLib.QueuedWithdrawal memory startedWithdrawal = state.validateQueuedWithdrawal(withdrawalKey);

    uint256 shares = startedWithdrawal.shares;
    if (shares > maxRedeem(address(this))) revert RedeemMoreThanMax();
    uint256 redeemableAssets = convertToAssets(shares);

    delete state.withdrawalMap[withdrawalKey];

    _withdraw({
        by: address(this),
        to: startedWithdrawal.beneficiary,
        owner: address(this),
        assets: redeemableAssets,
        shares: shares
    });

    emit FinishedRedeem(
        startedWithdrawal.staker,
        startedWithdrawal.beneficiary,
        config.operator,
        startedWithdrawal.shares,
        redeemableAssets,
        withdrawalKey
    );
}
```

### Impact:
Users initiating a redemption may receive significantly fewer assets than expected if the value of the vault's assets decreases during the delay period. This could result in substantial financial losses for users, especially in volatile market conditions or in the event of a malicious attack aimed at manipulating the exchange rate.


### Recommendation:
Implement slippage protection in the `finishRedeem` function. This can be achieved by:

1. Adding a `minAssetsOut` parameter to the `startRedeem` function, which is then stored in the `QueuedWithdrawal` struct.
2. In `finishRedeem`, check that the `redeemableAssets` meet or exceed the stored `minAssetsOut` value.

```solidity
function startRedeem(uint256 shares, address beneficiary, uint256 minAssetsOut)
    external
    whenFunctionNotPaused(Constants.PAUSE_VAULT_START_REDEEM)
    nonReentrant
    returns (bytes32 withdrawalKey)
{
    // ... 
    state.withdrawalMap[withdrawalKey].minAssetsOut = minAssetsOut;
    // ... 
}

function finishRedeem(bytes32 withdrawalKey)
    external
    nonReentrant
    whenFunctionNotPaused(Constants.PAUSE_VAULT_FINISH_REDEEM)
{
    // ... 
    uint256 redeemableAssets = convertToAssets(shares);
    if (redeemableAssets < startedWithdrawal.minAssetsOut) revert SlippageExceeded();
    // ... 
}
```
