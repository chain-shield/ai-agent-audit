# Vulnerability details

## Impact
The `callHookIfInterfaceImplemented` function returns a boolean to confirm whether the call to the DSS contract hooks was successful, but this variable is not checked in the functions that call the `callHookIfInterfaceImplemented` function, when the `ignoreFailure` flag is true for these calls, a failure in the DSS hook call will not revert the transaction, this can cause Core storage variables to be updated with incorrect values that may differ from the possible state in the DSS contract causing conflicts between the states of the core and the DSS contracts and probably messing up the state variables of the operators, slashing and vaults for the DSS in the `core` contract.

## Proof of Concept
The `requestUpdateVaultStakeInDSS, validateAndUpdateVaultStakeInDSS, unregisterOperatorFromDSS, requestSlashing, finalizeSlashing and cancelSlashing` functions call the `callHookIfInterfaceImplemented` function setting the `ignoreFailure` flag as true, this allows these functions to execute without reverting if the call to the DSS hooks fail for any reason, this is a desired behavior in these functions.
```solidity
function finalizeSlashing(//...) external {
   //...
   HookLib.callHookIfInterfaceImplemented({
        dss: dss,
        data: abi.encodeWithSelector(dss.finishSlashingHook.selector, queuedSlashing.operator),
        interfaceId: dss.finishSlashingHook.selector,
        ignoreFailure: true, // no revert
        hookCallGasLimit: self.hookCallGasLimit,
        supportsInterfaceGasLimit: self.supportsInterfaceGasLimit,
        hookGasBuffer: self.hookGasBuffer
    });
}
```
The problem is that if the execution of the hook in the DSS contract fails, the state of that contract is not going to change (assuming the DSS contract handles its own state to reflect the results of hook calls, other functions and internal state It may need to process rewards, slashing, register of operators, etc), but as the transaction for the core contract didn't revert, the state variables that the before mentioned functions calling the `callHookIfInterfaceImplemented` function will be changed as if the hook call were successful, this will cause the core state variables to be updated incorrectly and this will differ from the state in the DSS contract, this different and incorrect state will cause problems as:

* In a call to the `requestUpdateVaultStakeInDSS` function to unstake a vault the core will register the request successfully, but the DSS may not register this request, and so, when the user calls `validateAndUpdateVaultStakeInDSS` in the core to finish the request, in the DSS contract the call will fail and the vault won't be unstaked, this may cause penalization for the operator in the DSS state and the DSS will try to slash it.

I added this test to the `slashing.t.sol` contract to show that Core storage variables are updated even when the call to the DSS hook reverts in a call to the `finalizeSlashing` function. I added some console logs in the `finalizeSlashing` and the `callHook` functions.
```solidity
function test_Fail_DSS_Slashing_Update_Core_Storage_Variables() public {
        // slash percentage 10%
        uint256 slashPercentageWad = 10 * Constants.ONE_WAD;
        // Deposit and Stake vaults to the DSS
        stake_vaults_to_dss();
        uint96[] memory slashPercentagesWad = new uint96[](1);
        slashPercentagesWad[0] = uint96(slashPercentageWad);

        vm.startPrank(address(dss));
        address[] memory operatorVaults = core.fetchVaultsStakedInDSS(operator, dss);

        address[] memory slashedVaults = new address[](1);
        slashedVaults[0] = operatorVaults[0];

        // Creating the Slashin request for 1 vault
        SlasherLib.SlashRequest memory slashingReq = SlasherLib.SlashRequest({
            operator: operator,
            slashPercentagesWad: slashPercentagesWad,
            vaults: slashedVaults
        });
        // Requesting the slashin in the core.
        SlasherLib.QueuedSlashing memory queuedSlashing = core.requestSlashing(slashingReq);
        // SLASHING_VETO_WINDOW pass
        vm.warp(block.timestamp + Constants.SLASHING_VETO_WINDOW);

        uint256[] memory postSlashedAssetsInVault = new uint256[](slashedVaults.length);
        // Calculating the amounts after slash
        for (uint256 i = 0; i < slashedVaults.length; i++) {
            postSlashedAssetsInVault[i] = compute_post_slashed_assets_in_vault(slashedVaults[i], slashPercentagesWad[i]);
            console.log("postSlashedAssetsInVault: ", postSlashedAssetsInVault[i]);
        }
        // llama a finalize Slashin hook in the DSS, which reverts
        core.finalizeSlashing(queuedSlashing);
        // validating assets amounts.
        for (uint256 i = 0; i < slashedVaults.length; i++) {
            assertEq(IVault(operatorVaults[i]).totalAssets(), postSlashedAssetsInVault[i]);
        }

        vm.stopPrank();
    }
```

## Recommended Mitigation Steps
Validate the boolean variable returned by the `callHookIfInterfaceImplemented` function if the return status is false, then the variables that are updated in `requestUpdateVaultStakeInDSS, validateAndUpdateVaultStakeInDSS, unregisterOperatorFromDSS, requestSlashing, finalizeSlashing and cancelSlashing` functions should be left as they were before the call.
