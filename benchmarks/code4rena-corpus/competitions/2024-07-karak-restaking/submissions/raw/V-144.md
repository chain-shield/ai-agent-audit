# Vulnerability details

## Impact
validateWithdrawalCredentials function always be dosed, whenever called after validateSnapshotProofs due to node.currentSnapshotTimestamp equals to zero.

## Proof of Concept
validateWithdrawalCredentials function is used to validate the withdrawal credentials of the validator that is pointed to the owners native node.
On checking for the credentials it passes from two if statement and the issues lies on 2nd if statement which checks if the beaconStateRootProof timestamp is greater or equal to lastSnapshotTimestamp of the node OR if beaconStateRootProof timestamp is greater or equal to currentSnapshotTimestamp of the node else revert,
```solidity
NativeVault.sol#L184
if (
            beaconStateRootProof.timestamp < node.lastSnapshotTimestamp
                || beaconStateRootProof.timestamp < node.currentSnapshotTimestamp
        ) revert BeaconTimestampTooOld();
```
Now here if the 1st statement leads to false it checks for the 2nd statement, which always set to false whenever this function called after validateSnapshotProofs.

Lets take a look at validateSnapshotProofs function how and when currentSnapshotTimestamp = 0.
validateSnapshotProofs internally calls _updateSnapshot function which after checking if remainingProofs == 0 it deletes node.currentSnapshotTimestamp,
```solidity
NativeVault.sol#L487
delete node.currentSnapshotTimestamp;
```
this will make currentSnapshotTimestamp = 0 for that node. Now if validateWithdrawalCredentials function called for the same node the function will always get revert leading to DOS of a function.
