# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/src/entities/HookLib.sol#L48-L64

```solidity
function callHook(
    address target,
    bytes memory data,
    bool ignoreFailure,
    uint32 hookCallGasLimit,
    uint32 hookGasBuffer
) internal returns (bool) {
    if (gasleft() < (hookCallGasLimit * 64 / 63 + hookGasBuffer)) revert NotEnoughGas();

    (bool success, bytes32 returnData) = performLowLevelCallAndLimitReturnData(target, data, hookCallGasLimit);

    if (!ignoreFailure && !success) revert DSSHookCallReverted(returnData);

    if (success) emit HookCallSucceeded(returnData);
    else emit HookCallFailed(returnData);
    return success;
}
```

This function is used in multiple instances within the scope and is employed to perform low-level calls to the DSS. Due to a previous finding (`M-05` from the [Renescance audit](https://github.com/code-423n4/2024-07-karak/blob/main/audits/core/Renascence%20-%20Karak%20Core%20Audit%20Report.pdf)), there is a new check that the provided gas must be more than `hookCallGasLimit * 64 / 63 + hookGasBuffer`. This translates to a subtle invariant where the protocol does not want to query the DSS if not enough gas is passed.

However, this check is not foolproof. In cases where the `hookCallGasLimit` is not a multiple of `63`, the `callHook` function might not revert even if expected to. This occurs due to the precision loss in the calculation `hookCallGasLimit * 64 / 63`.

Per the previous finding, the following conditions must hold to ensure the call never fails:

1. The call to the hook is made with an amount of gas very close to the required amount.
2. The low-level call cannot cause a revert.

To address condition 1, the approach was to perform the low-level call with at most 63/64ths of the gas that the caller context has available. To ensure the low-level call is performed with at least this gas, the check `gasleft() > hookCallGasLimit * 64 / 63 + hookGasBuffer` was implemented. Here, the buffer accounts for the worst-case amount of gas needed from the check until the DSS call.

However, using rough math values, even with this calculation, the call could still fail. Assume `hookCallGasLimit` is `984374` and `hookGasBuffer` is `100000`, and we have `gasleft()` as `1099998`. The check would not revert, even though it should. This is because `hookCallGasLimit * 64 / 63 + hookGasBuffer` would equate to `1099998` due to rounding down from `1099998.984126984`.

To ensure the low-level call is performed with enough gas, `gasleft()` should be greater than `hookCallGasLimit * 64 / 63 + hookGasBuffer`. In our example, even if `gasleft() - 1` equals `hookCallGasLimit * 64 / 63 + hookGasBuffer`, the call should revert, but it doesn’t due to the rounding down, leading the low-level call to revert in the DSS.
