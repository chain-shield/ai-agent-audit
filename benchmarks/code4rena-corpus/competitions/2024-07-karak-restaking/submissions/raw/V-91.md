# Vulnerability details

## Impact
When there is a slash operation in NativeVault, call `NativeVault::startSnapshot()` with `revertIfNoBalanceChange` set to `true` will always revert even balance is changed.
Here before make a snapshot, the code will first check [whether the vault is slashed](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L456), if it is [slashed](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L430), then the slashed ETH will be withdraw to `slashStore` which means `node.nodeAddress.balance` will decrease.Because `node.withdrawableCreditedNodeETH` is actually the sum of `snapshot.nodeBalanceWei` and `snapshot.nodeBalanceWei` is actually the [diff between `node.nodeAddress.balance` and `node.withdrawableCreditedNodeETH`](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L459) So 
`node.withdrawableCreditedNodeETH` is logically equal to `node.nodeAddress.balance`.When `node.nodeAddress.balance` decreases, the code will go to line 444, which will make them equal again.
Here the balance clearly changed, but in line 459 and 461 the `nodeBalanceWei` will be zero because in the above step we make `node.nodeAddress.balance` equal to `node.withdrawableCreditedNodeETH` already.So the function will revert even if the balance has clearly changed.

function test_startSnapshot(bytes32 parentRoot) public {

        vm.assume(parentRoot != bytes32(0));
        validateWithdrawalCredentials();

        address node = nativeVault.createNode();

        payable(node).call{value:10 ether}("");


        vm.store(Constants.BEACON_ROOTS_ADDRESS, timestamp_idx(block.timestamp), bytes32(uint256(block.timestamp)));

        vm.prank(address(core));
        nativeVault.slashAssets(30 * 1e18, slashStore);
        nativeVault.startSnapshot(true); // second time
    }
