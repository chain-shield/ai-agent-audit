# Vulnerability details

## Impact
In the function `validateSnapshotProofs`, the value of `snapshot.remainingProofs` is decremented by 1 in each iteration. This poses a risk as `napshot.remainingProofs` might reach zero before the loop terminates. Consequently, it could become a negative value, which, since it is a uint256, will wrap around to a large value. This can result in node info not being updated properly in the `_updateSnapshot` function, due to the abnormally large value and a sequential increase in `snapshot.balanceDeltaWei`.

## Proof of Concept

```solidity
        for (uint256 i = 0; i < balanceProofs.length; i++) {
            [...]

            snapshot.remainingProofs--;
            snapshot.balanceDeltaWei += balanceDeltaWei;
        }

        _updateSnapshot(node, snapshot, nodeOwner);
```

## Recommended Mitigation Steps
To address this issue, add a check within the validateSnapshotProofs function as follows.
```diff
        for (uint256 i = 0; i < balanceProofs.length; i++) {
            [...]

            snapshot.remainingProofs--;
            if(snapshot.remainingProofs == 0)
                break;
            snapshot.balanceDeltaWei += balanceDeltaWei;
        }

        _updateSnapshot(node, snapshot, nodeOwner);
```
