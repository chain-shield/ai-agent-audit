# Vulnerability details

## Impact
NativeVault user cannot withdraw all stakes within 7 days stipulated period due to ```startWithdrawal()``` validation.

Which goes against protocol's intended design.
>Operator/Staker shouldn’t be blocked by the protocol for withdrawal beyond the withdrawal period.

It is a known fact that users/node owners must wait 7 days to finalize a withdrawal process(a design to ensure no users escape a valid slash request).

However, in NativeVault, users cannot finalize the withdrawal of all stakes in 7 days.

## Proof of Concept
Let us consider the same case for Vault and NativeVault;
1. Alice deposits 115,000_USDC(32_ETH) on Vault_A and pointed the ```Eth1 withdrawal credentials of a validator``` to a node on NativeVault_B.
2. Alice got suspicious of Vault_A Operator and opted to withdraw before any malicious activity was performed by the operator which will lead to slashing of funds(max of 100%).
3. Alice calls ```Vault.startRedeem()``` on Vault_A which was finalized exactly! 7 days later before any slash request came in for the vault. Funds safe!
4. Alice at the same time ```Vault.startRedeem()``` was called, also exited the consensus layer, since withdraw credentials cannot be changed after it has been set.(**[reference](https://eth2book.info/capella/part2/deposits-withdrawals/withdrawal-processing/#:~:text=To%20reiterate%2C%20changing%20withdrawal%20credentials%20is%20a%20one%2Dtime%20process.%20You%20can%20only%20change%20from%20BLS%20to%20Eth1%20credentials.%20It%20is%20not%20possible%20to%20change%20Eth1%20credentials%20without%20exiting%20the%20validator%20and%20re%2Dstaking.)**)
After exiting, full withdrawals can be pushed after a 27hrs wait period in case a slash is required on the validator stake. (**[ref](https://eth2book.info/capella/part2/deposits-withdrawals/withdrawal-processing/#full-withdrawals:~:text=being%20continually%20skimmed.-,Full%20withdrawals,the%20top%2Dup%20amount%20will%20be%20returned%20to%20the%20execution%20layer.,-See%20also)**)
It will take a 5days max for a validator to get credited after withdrawals have been made available. (**[ref](https://eth2book.info/capella/part2/deposits-withdrawals/withdrawal-processing/#:~:text=Validator%20withdrawals%20are,every%205%20days.)**)
In total, based on Beacon chain criteria for exit, Alice Node is expected to have been credited in 6days! after exiting.

The problem lies in the fact that there is a validation in NativeVault that prevents Alice from starting the withdrawal process with her max stake as she did in Vault_A
```solidity
@>> if (weiAmount > withdrawableWei(msg.sender) - self.nodeOwnerToWithdrawAmount[msg.sender]) {
            revert WithdrawMoreThanMax();
        }
```
Meanwhile, ```withdrawableWei()``` returns the minimum between the total worth of node shares and ``` node.withdrawableCreditedNodeETH```
```solidity
  function withdrawableWei(address nodeOwner) public view nodeExists(nodeOwner) returns (uint256) {
        return
 @>>           Math.min(convertToAssets(balanceOf(nodeOwner)), _state().ownerToNode[nodeOwner].withdrawableCreditedNodeETH);
    }
```

This implies that Alice can only initiate withdrawal with whatever is available in the node(that came in from Beacon as validator's reward), and if nothing is present, no withdrawal at all. 

This is problematic in the sense that, as stated earlier, node balance will certainly increase(to 32_ETH) before the withdrawal finalization is due and Alice will still be unable to get funds then

Now Alice get her stake from the erc20 Vault_A but has stake trapped in NativeVault_B, if operator goes on to perform maliciously after 7 days(when withdrawal should have been finalized) and the Vault get slash request from DSS, Alice funds can no longer escape due to the wait period.

Note: withdrawal was intended to be before malicious act  by an operator that result in the slash request in the first place, but the NativeVault design kept Alice funds longer than it should.

Considering the fact that validator will be credited within 7 days if exit request is made on Beacon, users/Node owners should be able to request for their entire stake(Beacon + Node) at the start of the withdrawal process in NativeVault

It makes sense that the check was done in ```finishWithdrawal()```, so the user can only withdraw what is available in their Node
```solidity
        uint256 withdrawableAssets = withdrawableWei(startedWithdrawal.nodeOwner);
        if (startedWithdrawal.assets > withdrawableAssets) {
            startedWithdrawal.assets = withdrawableAssets;
        }
```
