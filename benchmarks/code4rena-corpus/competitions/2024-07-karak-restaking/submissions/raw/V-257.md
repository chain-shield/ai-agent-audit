# Vulnerability details

The operator has the ability to change the staking of their vaults. They can stake their vault to DSS or unstake it from the DSS. However when trying to update the staking status the protocol enforces that the operator has to wait 9 days before being able to stake or unstake their vault from the DSS as to not be able to avoid slashing from the DSS. However due to missing validations when finalizing the staking status the operator can avoid being slashed in the following flow:
The operator requests to unstake their vault from the DSS by calling the `requestUpdateVaultStakeInDSS` function
https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/Core.sol#L130-L141
```
    function requestUpdateVaultStakeInDSS(Operator.StakeUpdateRequest memory vaultStakeUpdateRequest)
        external
        nonReentrant
        whenFunctionNotPaused(Constants.PAUSE_CORE_REQUEST_STAKE_UPDATE)
        returns (Operator.QueuedStakeUpdate memory updatedStake)
    {
        address operator = msg.sender;
        CoreLib.Storage storage self = _self();
        self.checkIfOperatorIsRegInRegDSS(operator, vaultStakeUpdateRequest.dss);
        updatedStake = self.requestUpdateVaultStakeInDSS(vaultStakeUpdateRequest, self.nonce++, operator);
        emit RequestedStakeUpdate(updatedStake);
    }
```
which is later validated and stored in the `pendingStakeUpdates` mapping for later checking and verification as can be seen here:
https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L61-L87
```
    function requestUpdateVaultStakeInDSS(
        CoreLib.Storage storage self,
        StakeUpdateRequest memory requestStakeUpdate,
        uint128 nonce,
        address operator
    ) external returns (QueuedStakeUpdate memory queuedStake) {
        State storage operatorState = self.operatorState[operator];
        validateStakeUpdateRequest(operatorState, requestStakeUpdate);
        queuedStake = QueuedStakeUpdate({
            nonce: uint48(nonce),
            startTimestamp: uint48(block.timestamp),
            operator: operator,
            updateRequest: requestStakeUpdate
        });
        operatorState.pendingStakeUpdates[requestStakeUpdate.vault] = calculateRoot(queuedStake);
        IDSS dss = requestStakeUpdate.dss;

        HookLib.callHookIfInterfaceImplemented({
            dss: dss,
            data: abi.encodeWithSelector(dss.requestUpdateStakeHook.selector, operator, requestStakeUpdate),
            interfaceId: dss.requestUpdateStakeHook.selector,
            ignoreFailure: !requestStakeUpdate.toStake,
            hookCallGasLimit: self.hookCallGasLimit,
            supportsInterfaceGasLimit: self.supportsInterfaceGasLimit,
            hookGasBuffer: self.hookGasBuffer
        });
    }
```

When validating the queued update the following checks are being done in the `validateQueuedStakeUpdate` function:
https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/Operator.sol#L89-L101
```
    function validateQueuedStakeUpdate(State storage operatorState, QueuedStakeUpdate memory queuedStakeUpdate)
        internal
        view
    {
        if (queuedStakeUpdate.startTimestamp + Constants.MIN_STAKE_UPDATE_DELAY > block.timestamp) {
            revert OperatorStakeUpdateDelayNotPassed();
        }
        if (
            calculateRoot(queuedStakeUpdate) != operatorState.pendingStakeUpdates[queuedStakeUpdate.updateRequest.vault]
        ) {
            revert InvalidQueuedStakeUpdateInput();
        }
    }
```

## Impact

However in this function it only validates that the `MIN_STAKE_UPDATE_DELAY` has passed however it doesn't have a max time check. So the operator can request the vault unstake and leave the request in the mapping while not finalizing the request. After some time when the operator notices the slashing request transaction in the mempool they can front-run and finalize their vault unstaking thus instantly unstaking their vault from the DSS and making the DSS unable to slash the operator's assets.

## Proof of Concept
1. Create a vault
2. Register to DSS
3. Stake to DSS
4. Request unstake but don't finalize it
5. Wait arbitrarily long time (longer than 9 days)
6. The DSS requests slashing
7. Operator notices the slashing request transaction and instantly finalizes their unstake request thus avoiding slashing.

## Tools Used
Manual

## Recommended Mitigation Steps
Add max time check (a deadline) so the operator is forced to finalize their update in some time range.
