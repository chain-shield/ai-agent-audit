# Vulnerability details

## Impact

The absence of storage gaps in upgradeable contracts such as NativeNode, NativeVault, Vault, and Core can lead to storage collisions when new state variables are introduced in future upgrades. This could result in data corruption, unexpected behavior, and potential loss of funds. Given that these contracts manage critical operations and significant assets, the risk is substantial. Proper storage layout management is crucial to ensure the integrity and security of the contracts during upgrades.

## Proof of Concept

The following contracts do not include storage gaps to accommodate future upgrades:

1. NativeNode.sol
2. NativeVault.sol
3. Vault.sol
4. Core.sol


## Tools Used

Manual Review

## Recommended Mitigation Steps

Add Storage Gaps in Child Contracts: Ensure that each upgradeable contract includes storage gaps to reserve slots for future state variables. This can be done by adding a placeholder array of a sufficient size to each contract.

```diff
contract NativeNode is Pauser, Ownable, INativeNode, ReentrancyGuard {
    address nodeOwner;
+   uint256[50] _gap;
```

```diff
contract NativeVault is ERC4626, IBeacon, Pauser, INativeVault, OwnableRoles, ReentrancyGuard {
    using NativeVaultLib for NativeVaultLib.Storage;
+   uin256[50] _gap;
```

```diff
contract Vault is ERC4626, Initializable, Ownable, Pauser, ReentrancyGuard, ExtSloads, IVault {
    using VaultLib for VaultLib.State;
+   uin256[50] _gap;
```

```
contract Core is IBeacon, ICore, OwnableRoles, Initializable, ReentrancyGuard, Pauser, ExtSloads {
    using CoreLib for CoreLib.Storage;
    using Operator for CoreLib.Storage;
    using Operator for Operator.State;
    using SlasherLib for SlasherLib.QueuedSlashing;
    using SlasherLib for SlasherLib.SlashRequest;
    using SlasherLib for CoreLib.Storage;
    using VaultLib for VaultLib.Config;
    using CommonUtils for address;
+   uin256[50] _gap;
```
