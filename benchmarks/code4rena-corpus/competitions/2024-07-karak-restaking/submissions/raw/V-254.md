# Vulnerability details

## Impact
Loss of assets for the affected users.

## Proof of Concept
During minting, the user deposits the underlying asset into the `Vault` contract, and the `Vault` contract uses the
`deposit/mint` function to mint shares to the user.

Vault.sol#deposit():
```solidity
    function deposit(uint256 assets, address to, uint256 minSharesOut)
        external
        nonReentrant
        whenFunctionNotPaused(Constants.PAUSE_VAULT_DEPOSIT_SLIPPAGE)
        returns (uint256 shares)
    {
        if (assets == 0) revert ZeroAmount();
        shares = super.deposit(assets, to);
        if (shares < minSharesOut) revert NotEnoughShares();
    }
```

Vault.sol#mint():
```solidity
    function mint(uint256 shares, address to)
        public
        override(ERC4626, IVault)
        whenFunctionNotPaused(Constants.PAUSE_VAULT_MINT)
        nonReentrant
        returns (uint256 assets)
    {
        if (shares == 0) revert ZeroShares();
        assets = super.mint(shares, to);
    }
```
These functions use the standard functions of ERC4626, so the number of shares minted depends on the current size of the `Vault` (i.e. `totalAssets() and `totalSupply()`).

The current size of the `Vault` can increase or decrease at any time depending on the current on-chain conditions when the transaction is executed.
As a result, the current size can change due to malicious actions of an attacker (donate attack) or phenomena such as rounding in large transactions.
if the current size changes, the number of shares minted will change (more or less than expected).

As you can see in the provided code snippet, the `deposit()` function applies slippage control to prevent any malicious frontrunning, but the `mint()` function does not apply slippage control.

Assuming that Alice decides to deposit x USDC and mint 100 shares off-chain.
When she executes the TX, the size increases and the amount of the underlying token that she is going to deposit can become bigger than expected amount. The slippage is greater than she can accept.

In summary, the `mint` function lacks the slippage control that allows the users to revert if the amount of the underlying token they deposits is bigger than the amount they expected.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a slippage control that allows the users to revert if the amount of the underlying token they deposits is bigger than the amount they expected.
