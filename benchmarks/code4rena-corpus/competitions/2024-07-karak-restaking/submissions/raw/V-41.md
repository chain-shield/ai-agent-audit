# Vulnerability details

## Impact

Fee on transfer tokens are unslashable because the amount sent in by the vault will always be less than the amount sent to the zero address

This is because for the case of fee-on-transfer tokens, the amount sent and the amount by the contract are different

so when the contract tries the safetransferfrom `amount`, the tokens it retrieves are actually smaller than `amount` due to the fee taken

So when the contract tries to send `amount` to the address zero, it reverts as the contract does not have enough tokens ans the balance of the contract is actually less than the amount it is trying to send to the zero address

## Proof of Concept

```

    function handleSlashing(IERC20 token, uint256 amount) external {
        if (amount == 0) revert ZeroAmount();
        if (!_config().supportedAssets[token]) revert UnsupportedAsset();

        SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
        // Below is where custom logic for each asset lives
        SafeTransferLib.safeTransfer(address(token), address(0), amount);
    }
```
