# Vulnerability details

## Impact
The `handleSlashing` function is a critical vulnerability that results in the irreversible burning of tokens. This function transfers the specified token amount to the zero address (address(0)), effectively removing these tokens from circulation permanently and should be only called by the slasher contract(Owner)

## Proof of Concept
This function is defined within the `SlashingHandler` contract, which is responsible for executing the slashing of assets when certain conditions are violated by the operators or due to other protocol-defined reasons.
```
function handleSlashing(IERC20 token, uint256 amount) external {
    if (amount == 0) revert ZeroAmount();
    if (!_config().supportedAssets[token]) revert UnsupportedAsset();

    SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
    // Below is where custom logic for each asset lives
    SafeTransferLib.safeTransfer(address(token), address(0), amount);
}
```
The handling of slashes of specified amounts of tokens should be managed by the owner of the SlashingHandler contract. According to the `SlashingHandler.sol` code, the function `addSlashableToken` adds a token to the list of supported assets for slashing, and the function handleSlashing which actually performs the slashing by transferring the specified amount of tokens to address(0), should be both restricted to be called by the owner only. This is enforced by the onlyOwner modifier in the contract.

However, only the `addSlashableToken` was restricted to `Owner` only. If the owner adds any slashable token, an attacker can frontrun/call the function without any restriction before the owner and he loe funds.

When the owner of a token is slashed, the total amount of assets represented by the token in the vault is reduced. This is done to penalize certain behaviors or breaches of contract terms by the token holder.
An attacker can easily slash or burn assets that the owner may have kept for other purposes.

-*Asset Reduction*: The `totalAssets` in the vault, which represents the total amount of ETH or other assets managed by the vault, is decreased by the amount that is being slashed. This reduction simulates the effect of the assets being transferred out of the vault to a designated handler.

This can be risky to legitimate users who called the public function leaving it to drain their funds.

## Recommended Mitigation Steps
Use the `onlyOwner` modifier:
```
function handleSlashing(IERC20 token, uint256 amount) external onlyOwner {
    if (amount == 0) revert ZeroAmount();
    if (!_config().supportedAssets[token]) revert UnsupportedAsset();

    SafeTransferLib.safeTransferFrom(address(token), msg.sender, address(this), amount);
    // Below is where custom logic for each asset lives
    SafeTransferLib.safeTransfer(address(token), address(0), amount);
}
```
