# Vulnerability details

## Impact

Considering Fee-on-transfer effects are in scope, the deposit and mint functions do not take into account fee-on-transfer tokens when calculating the amount of shares to mint. This is because in the current implementation, the share amount is calculated from the `amount` the user sends in but not from the amount the contract actually receives. In the case for fee on transfer tokens, the amount sent to the contract is different to the amount received by the contract, leading to accounting errors when calculating the amount of shares to mint

## Proof of Concept

```
    function mint(uint256 shares, address to)
        public
        override(ERC4626, IVault)
        whenFunctionNotPaused(Constants.PAUSE_VAULT_MINT)
        nonReentrant
        returns (uint256 assets)
    {
        if (shares == 0) revert ZeroShares();
        assets = super.mint(shares, to);
    }
```


```
 function mint(uint256 shares, address receiver) public virtual returns (uint256 assets) {
        assets = previewMint(shares); // No need to check for rounding error, previewMint rounds up.

        // Need to transfer before minting or ERC777s could reenter.
        asset.safeTransferFrom(msg.sender, address(this), assets);

        _mint(receiver, shares);

        emit Deposit(msg.sender, receiver, assets, shares);

        afterDeposit(assets, shares);
    }
```

## Recommended Mitigation Steps

You need to calculate the amount of tokens received by first taking a snapshot of the vaults balance before the transferfrom function and then a snapshot of the balance of the vault after transferfrom is called, and the difference between the first snapshot and the second snapshot is the amount of tokens the contract actually has received.
