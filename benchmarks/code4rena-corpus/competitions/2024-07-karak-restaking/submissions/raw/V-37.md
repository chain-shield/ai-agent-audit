# Vulnerability details

## Impact

Since veto committee is not a trusted role, it can frontrun a reasonable `finalizeSlashing` call at any time for a malicious operator, with whom they might be externally affiliated, because of the lack of the time window within which a veto can be enforced. This would lead to a malicious operator permanently staying in the system, because `finalizeSlashing` could never be executed.

## Recommended Mitigation Steps

Include `SLASHING_VETO_WINDOW` for cancellation, similar to how it's used for finalization.
