# Vulnerability details


## Impact
Due to the `node.withdrawableCreditedNodeETH` update not reflecting balance changes of validators, withdrawing process won't operate as expected.

## Proof of Concept
In `NativeVault::_updateSnapshot()` function, if all validators has proved their balance changes(`snapshot.remainingProofs == 0`), `node.withdrawableCreditedNodeETH` is updated by sum of the validators' balance changes and node balance(by $\Delta \text{totalAssets}$).

$\Delta \text{totalAssets} = \text{nodeBalance}_j + \sum_i \Delta \text{beaconBalance}_{v(i)}$

But in [NativeVault.sol#L484](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L484), `node.withdrawableCreditedNodeETH` is added by only `snapshot.nodeBalanceWei`.

```solidity
    node.withdrawableCreditedNodeETH += snapshot.nodeBalanceWei;
```

The `snapshot.nodeBalanceWei` represents the difference between the node balance and `node.withdrawableCreditedNodeETH` at the beginning of a snapshot, and this value remains static throughout the validation process of the snapshot.

Thus, when finishing the snapshot, 
```solidity
    node.withdrawableCreditedNodeETH += snapshot.nodeBalanceWei;

    // This equals 
    node.withdrawableCreditedNodeETH = node.withdrawableCreditedNodeETH + node.nodeAddress.balance - node.withdrawableCreditedNodeETH;

    // Thus
    node.withdrawableCreditedNodeETH = node.nodeAddress.balance;
```

The above equation indicates that balance changes of the node validators are not reflected to the node's withdrawable assets value.

## Recommended Mitigation Steps

According to the [comment](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/NativeVaultLib.sol#L48), `NativeNode::withdrawableCreditedNodeETH` represents withdrawable ETH amount with shares awarded.

```solidity
    struct NativeNode {
        ... ...
        // withdrawable ETH with shares awarded
        uint256 withdrawableCreditedNodeETH;
        ... ...
    }
```
In the documentation, shares are either minted or burnt by

> $\Delta \text{totalAssets} = \text{nodeBalance}_j + \sum_i \Delta \text{beaconBalance}_{v(i)}$
>
> Based on this the equivalent shares are awarded to the node owner.

Therefore, `node.withdrawableCreditedNodeETH` should be updated by $\Delta \text{totalAssets}$.

```solidity
function _updateSnapshot(
        NativeVaultLib.NativeNode storage node,
        NativeVaultLib.Snapshot memory snapshot,
        address nodeOwner
    ) internal {
        if (snapshot.remainingProofs == 0) {
            int256 totalDeltaWei = int256(snapshot.nodeBalanceWei) + snapshot.balanceDeltaWei;

-           node.withdrawableCreditedNodeETH += snapshot.nodeBalanceWei;
+           node.withdrawableCreditedNodeETH += totalDeltaWei;
            ... 
        }
        ...
    }
```
