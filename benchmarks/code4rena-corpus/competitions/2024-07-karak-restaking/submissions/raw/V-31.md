# Vulnerability details

## Impact
A `uint48` can store values ranging from 0 to 2^48 - 1 (281,474,976,710,655). If a nonce value exceeds this range, truncating it to a `uint48` will result in an incorrect and potentially unsafe value being stored.

The vulnerability arises from the line `nonce: uint48(nonce)`. If a nonce value greater than 281,474,976,710,655 is provided, the higher bits of the `uint128` nonce will be truncated when cast to a `uint48`, leading to an incorrect nonce value being stored in the `queuedStake` structure.

For instance, if an attacker submits a nonce value of 281,474,976,710,656 (2^48), the contract will truncate this value to fit into a `uint48`, resulting in a stored value of 0 due to the higher bits being discarded.

This truncation causes a mismatch between the intended and stored nonce values. The contract may use the nonce for purposes such as tracking request uniqueness, ensuring replay protection, or ordering transactions.

If the contract relies on the nonce for replay protection or other security checks, this truncation can be exploited to bypass these protections. An attacker could submit multiple transactions with large nonce values that all truncate to the same `uint48` value, potentially causing the contract to treat them as identical transactions or bypass replay protection mechanisms.

## Recommended Mitigation Steps
1. Ensure proper nonce management to prevent replay attacks and issues related to incorrect nonce values.
2. Verify the nonce value before casting to confirm it falls within the acceptable uint48 range.
3. If the nonce value is expected to exceed the uint48 range, consider using a larger type, such as uint128.

This is to ensure that the nonce value does not exceed the maximum value for a uint48, preventing truncation and maintaining the integrity of the nonce.
