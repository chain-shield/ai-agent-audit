# Vulnerability details

## Impact

`DSS`s must conform to ERC165 interface call and in doing so enables hooks that are used by the karak protocol for various operations.

By reverting on ERC165 operations a DSS can prevent karak protocol operations like slashing, operator removal, or vault validation from working even when karak protocol could safely ignore this hooks reverting. 


## Proof of Concept

The function `callHookIfInterfaceImplemented` should not revert when `ignoreFailure` is passed as true.
But on the following line a DSS can make a non reverting call revert (as `InterfaceNotSupported()`) by removing the supported of the ERC165 interface during a hook call.

https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/entities/HookLib.sol#L97-L100

## Recommended Mitigation Steps

When `ignoreFailure` is set to true do not revert in case of a ERC165 error:

```diff
    function callHookIfInterfaceImplemented(
        IERC165 dss,
        bytes memory data,
        bytes4 interfaceId,
        bool ignoreFailure,
        uint32 hookCallGasLimit,
        uint32 supportsInterfaceGasLimit,
        uint32 hookGasBuffer
    ) internal returns (bool) {
        ...

-        if (!success || result == bytes32(0)) {
+        if (!ignoreFailure && (!success || result == bytes32(0))) {
            // Either call failed or interface isn't implemented
            emit InterfaceNotSupported();
            return false;
        }
        ...
    }
}
```
