# Vulnerability details

## Impact

`nodeOwners` that are not present during slashing will incur the loss of the slashed assets.

## Bug Description
When a `nodeOwner` deposits into the vault, a share is minted to the nodeOwner signifying a deposit which is equivalent of the ETH on the beacon (validateWithdrawalCredentials)

But an oversight allows a `nodeOwner` to have his node slashed even if he wasn't in the vault when the slashing happens, this is because the actual slashing ( ETH out of nodes ) happens not in the same time as the [slashing](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L299) it self.

Consider this scenario :

1. A vault operator have his vault slashed 10 `ETH` due to malicious behavior with a `totalAsstes()` and `totalSupplly()` of `500e18` before slashing.
2. bob, not knowing of the slashing deploys and deposit in to a node, lets say `100e18` ( or 101, but this will not change the calculations) shares minted
3. now bob, calls the [starSnapshort](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L112) to update the node states and the [_transferToSlahsStore](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L456) is called to transfer the slashed assets out of the node.
4. but due to the vault being slashed ( totalAssets - 10), he will now bear the responsibility and have his node slashed even though  the node wasnt even active when the vault gets slashed

this is due to the calculations used in order to transfer the slashed assets

```solidity
 uint256 o = _decimalsOffset();
        if (o == 0) {
            return FixedPointMathLib.fullMulDiv(shares, totalAssets() + 1, _inc(totalSupply()));
        }
```

remember `totalAssets()` is now minus 10 ( slashed)

using the above calculations 
```solidity
100e18 * 590e18 + 1 / 600e18 + 1 = 99319467554076539101
```

meaning the node has been slashed  approx `680532445923460899` since [totalRestakedETH](https://github.com/code-423n4/2024-07-karak/blob/f5e52fdcb4c20c4318d532a9f08f7876e9afb321/src/NativeVault.sol#L503) == 100e18 ( assets)
```solidity
503         self.ownerToNode[_of].totalRestakedETH += assets;
```

## Recommended Mitigation Steps



The issue can be mitigated by promptly removing the slashed assets immediately after the slashing event. This ensures that node owners that are not present at the time will not even be aware that slashing occurred
