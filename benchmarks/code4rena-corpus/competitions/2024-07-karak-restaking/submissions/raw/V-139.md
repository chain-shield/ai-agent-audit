# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/src/NativeNode.sol#L39-L48

```solidity
    function withdraw(address to, uint256 weiAmount)
        external
        onlyOwner
        nonReentrant
        whenFunctionNotPaused(Constants.PAUSE_NODE_WITHDRAW)
    {
        Address.sendValue(payable(to), weiAmount);
        emit NodeETHWithdrawn(address(this), to, weiAmount);
    }

```

This function allows the `NativeVault` to withdraw funds to the given address. As [documented](https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/src/NativeNode.sol#L36), in the case of slashed assets the NativeVault withdraws those funds to the slashStore.

Issue however is that if we go to how slashings are being handled here https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/src/SlashingHandler.sol#L52-L59 we see that `safeTransfers()` inherently get called on these tokens.

This is also supported by the _### ERC20 token behaviors in scope_ here: https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/README.md#L146-L158, where we see that different sort of tokens could indeed be integrated.

Problem with the current logic is that the withdrawal hardcodes the logic to only allow withdrawal of ETH even though non-ETH tokens are supported, this is because the withdrawal context only uses `Address.sendValue()` as hinted by the `@audit` tag above, which then showcases a broken functionality cause some supported tokens won't be withdrawable.

## Impact

As hinted under _Proof of Concept_, some tokens have a broken functionality attached to them when trying to [withdraw the slashed assets](https://github.com/code-423n4/2024-07-karak/blob/ab18e1f6c03e118158369527baa2487b2b4616b1/src/NativeNode.sol#L36), which is because the current functionality only allows for the withdrawal of native ETH via `sendValue()`

## Recommended Mitigation Steps

Consider first checking if ETH is to be withdrawn in `NativeNode#withdraw()` then use `Address.sendValue(payable(to), weiAmount)` otherwise use `safeTransfer()` on the token.
