# Vulnerability details

## Impact
In `Vaults` contract, which implements ERC4626 contract, is vulnerable to the famous inflation attack, can cause the second ever depositor to receive low or even no shares of the vault.

## Proof of Concept
In the `deposit` function, we see that it only checks if the deposited amount is 0, and then calls the super function:
```solidity
    function deposit(uint256 assets, address to)
        public
        override(ERC4626, IVault)
        whenFunctionNotPaused(Constants.PAUSE_VAULT_DEPOSIT)
        nonReentrant
        returns (uint256 shares)
    {
        if (assets == 0) revert ZeroAmount();
        return super.deposit(assets, to);
    }
```

However, this makes the inflation attack possible, as it allows a malicious frontrunner to deposit 1 wei as the first deposit, then donate some large amount, say 1e18 wei to the vault. When the second depositor comes in, who wants to deposit 1e16 wei of tokens, the attacker then can pull of a sandwich attack to get away with 1e18+1e16+1 wei of tokens.

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a minimum deposit amount for deposit functions.
