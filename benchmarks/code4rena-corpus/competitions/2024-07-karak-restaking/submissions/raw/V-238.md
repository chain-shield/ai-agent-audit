# Vulnerability details

## Impact

Native nodes wouldn't be able to receive the yield (Ether) generated by the `beacon chain`, resulting in a loss of funds for node owners and breaking the contract's only real function - withdraw.

## Proof of Concept

Whenever a contract has to interact with native/raw `Ether`, it has to implement either the [fallback](https://docs.soliditylang.org/en/latest/contracts.html#fallback-function) or [receive](https://docs.soliditylang.org/en/latest/contracts.html#receive-ether-function) function, otherwise it wouldn’t be possible to receive any of the `Ether`. Although it is possible to send `Ether` to a contract that doesn’t implement either of the functions, they are considered malicious and would probably not be implemented by the `beacon chain`.

As per the [documentation](https://docs.karak.network/protocol/v2/native-restaking#terminologies-and-architecture) of the protocol:
> Hence, all the Ethereum yields coming from the validator will be accrued at the `NativeNode` and the owner will be awarded shares for it.

This statement alone confirms that the contract will handle `Ether` and it must implement either [receive](https://docs.soliditylang.org/en/latest/contracts.html#receive-ether-function) or [fallback](https://docs.soliditylang.org/en/latest/contracts.html#fallback-function) (or both) in order to function at all.

The [docs](https://docs.soliditylang.org/en/latest/contracts.html#receive-ether-function) of Solidity also confirm the above statement:
> If neither a receive Ether nor a payable fallback function is present, the contract cannot receive Ether through a transaction that does not represent a payable function call and throws an exception.

All of this can be confirmed with this simple test. Please add it to [nativeVault.t.sol](https://github.com/code-423n4/2024-07-karak/blob/main/src/NativeNode.sol):

```solidity
    function test_sendEthToNode() public {
        address node = nativeVault.createNode();
        assertEq(nativeVault.getNodeOwner(node), address(this));

        vm.deal(address(this), 10 ether);
        vm.expectRevert();
        address(node).call{value: 1 ether}("");
    }
```

## Recommended Mitigation Steps

If there are no plans for utilizing the `msg.data` sent with the transaction, implement `receive`, otherwise implement `fallback`.

```solidity
*// Function to receive Ether. msg.data must be empty*
receive() external payable {}

*// Fallback function is called when msg.data is not empty*
fallback() external payable {}

```
