# Vulnerability details

## Impact
`Core::requestSlashing` allows a slashing to be requested for a given operator+vault by a DSS. A queued slashing is returned. Anyone can then call `Core::finalizeSlashing` to effectively slash funds from the corresponding operator and by consequence slash users depositing to his vault. Interestingly, there's this check in `finalizeSlashing`:
```js
if (queuedSlashing.timestamp + Constants.SLASHING_VETO_WINDOW > block.timestamp) {
    revert MinSlashingDelayNotPassed();
}
```
So there's this `Constants.SLASHING_VETO_WINDOW` where an entity called `SLASHING VETO COMMITTEE`, a trusted role that can overturn/cancel a slashing for any reason by calling `Core::cancelSlashing` during the corresponding `SLASHING_VETO_WINDOW`. Any attempt to finalize slashing during that window will revert.
Now a possible scenario is that `requestSlashing` is called on an operator, then for some reason the vault is paused by owner some time before the end of `SLASHING_VETO_WINDOW`, and unpaused after the veto window expired therefore any right to benefit from veto is lost as well. We emphisize that the veto committee can't call `cancelSlashing` because it's paused. If the operator was wrongly requested to be slashed i.e, the veto was going to be in his favor and cancel the slashing, anyone can then call `finalizeSlashing`, the earlier check for veto window expiry above will pass and the operator and user funds that must have been not slashed will be slashed and lost!!!

To summarize:
1. DSS initiates slashing via `requestSlashing`
2. Owner pauses `cancelSlashing` among other or all functionalities before `SLASHING_VETO_WINDOW` expiration.
3. `SLASHING_VETO_WINDOW` expires during pause.
4. Owner unpauses the system.
5. Anyone can now execute `finalizeSlashing`, causing loss of funds to users.

The impact is High (loss of user funds), the likelihood is Low (only when functions are paused).

## Tools Used
Manual review.

## Recommended Mitigation Steps
There is more than 1 solution to consider:
- Remove pausability from `cancelSlashing`.
- If not, allow for a `PAUSING_COOLDOWN_WINDOW` to finish stuck issues during pausing like exercising veto on wrong slashing requests.
