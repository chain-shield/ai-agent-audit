# Vulnerability details

## Impact
Malicious actor can initialize pool with inflation attack, making it behave incorrectly and possibly profiting from it

## Details
solady ERC4626 have `_decimalsOffset()` virtual function that suppose to defend against this kind of attacks, but default value for its return value is 0.

Version without the decimals offset are still making this attack less certain for the attacker, since there exists some scenarios where it will be unprofitable. For example, if there would be no victims in the pool.

Losing of users funds is happening because ERC4626 pool loosing the ability to operate in the amounts smaller than the quantity chosen by the attacker.

## Proof of Concept
Insert this piece of code into the `vault.t.sol` to run it.


    function mintAndDepositTo(address to, uint256 amount) public returns (uint256 shares) {
        vm.startPrank(to);

        vm.stopPrank();
    }

    function withdrawShares(address from, uint256 shares) public {
        vm.startPrank(from);

        uint256 withdrawalNonce = vault.getNextWithdrawNonce(from);
        vault.approve(address(vault), shares);
        bytes32 withdrawalKey = vault.startRedeem(shares, from);
        
        vm.warp(block.timestamp + Constants.MIN_WITHDRAWAL_DELAY + 1);
        vault.finishRedeem(withdrawalKey);
        vm.stopPrank();
    }
