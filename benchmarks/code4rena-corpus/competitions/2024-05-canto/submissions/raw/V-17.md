# Vulnerability details

## Impact 

sdk.Context is still used instead of context.Context, causing interface mismatch.

## Proof of Concept

According to

https://github.com/cosmos/cosmos-sdk/blob/v0.50.6/UPGRADING.md#modules

> The following modules' Keeper methods now take in a context.Context instead of sdk.Context. Any module that has an interfaces for them (like "expected keepers") will need to update and re-generate mocks if needed:

x/authz
x/bank
x/mint
x/crisis
x/distribution
x/evidence
x/gov
x/slashing
x/upgrade

but many module such as coinswap, x/csr, x/epoch/keepers and x/govshuttle/ (which import x/gov) keeper still use sdk.Context instead of context.Context,

which result in incorrect interface mistmatch, some example code:

```solidity
// GetAuthority returns the x/govshuttle module's authority.
func (k Keeper) GetAuthority() string {
	return k.authority
}

func (k Keeper) Logger(ctx sdk.Context) log.Logger {
	return ctx.Logger().With("module", fmt.Sprintf("x/%s", types.ModuleName))
}

// retrieve the port address from state
func (k Keeper) GetPort(ctx sdk.Context) (common.Address, bool) {
	store := runtime.KVStoreAdapter(k.storeService.OpenKVStore(ctx))
	prefixStore := prefix.NewStore(store, types.PortKey)
	bz := prefixStore.Get(types.PortKey)
	// if not found return false
	if len(bz) == 0 {
		return common.Address{}, false
	}
	return common.BytesToAddress(bz), true
}
```
