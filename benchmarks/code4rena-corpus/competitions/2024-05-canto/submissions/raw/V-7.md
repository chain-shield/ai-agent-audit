# Vulnerability details

## Impact
newMsgEthereumTx function will not revert when chainID, gasPrice, or amount parameters are nil.

## Proof of Concept
https://github.com/code-423n4/2024-05-canto/blob/d1d51b2293d4689f467b8b1c82bba84f8f7ea008/ethermint-main/x/evm/types/msg.go#L78-L154

The newMsgEthereumTx function, which creates a new Ethereum transaction, does not handle the case where the chainID, gasPrice, or amount parameters are nil.

The issue occurs in the following code snippet:

`if chainID != nil {
    chainIDInt := sdkmath.NewIntFromBigInt(chainID)
    cid = &chainIDInt
}

if gasPrice != nil {
    gasPriceInt := sdkmath.NewIntFromBigInt(gasPrice)
    gp = &gasPriceInt
}

if amount != nil {
    amountInt := sdkmath.NewIntFromBigInt(amount)
    amt = &amountInt
}
`

If any of these parameters (chainID, gasPrice, or amount) are nil, the corresponding pointers (cid, gp, or amt) will not be assigned any value. And the code will proceed to other lines without reverting.

## Tools Used
Manual review

## Recommended Mitigation Steps
When chainID, gasPrice, or amount are nil, the return value should be handled appropriately.
