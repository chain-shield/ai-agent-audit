# Vulnerability details

## Impact
The use of panic in the NewKeeper function for handling invalid authority addresses can lead to an application crash. This is particularly dangerous in a production environment, where an unexpected crash can disrupt service, lead to loss of data, and affect user trust. Using panic for error handling is considered a bad practice as it does not allow for graceful error recovery.

## Proof of Concept
Create an invalid authority address.
Call the NewKeeper function with the invalid address.
Observe that the application panics and crashes.

invalidAddress := sdk.AccAddress("invalid_address")
_, err := NewKeeper(cdc, invalidAddress, storeService, transientKey, ss)
if err != nil {
    fmt.Println("Error:", err)
}


## Tools Used
Remix IDE

## Recommended Mitigation Steps
Replace the panic statement with proper error handling. Modify the NewKeeper function to return an error instead of panicking:

func NewKeeper(
    cdc codec.BinaryCodec,
    authority sdk.AccAddress,
    storeService corestoretypes.KVStoreService,
    transientKey storetypes.StoreKey,
    ss paramstypes.Subspace,
) (Keeper, error) {
    // ensure authority account is correctly formatted
    if err := sdk.VerifyAddressFormat(authority); err != nil {
        return Keeper{}, err
    }

    return Keeper{
        cdc:          cdc,
        storeService: storeService,
        authority:    authority,
        transientKey: transientKey,
        ss:           ss,
    }, nil
}
