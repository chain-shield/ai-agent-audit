# Vulnerability details

## Impact
In order to ensure complete compatibility with cosmos 0.50.x, it is necessary to align with their code changes unless when not absolutely necessary. This report demonstrates some cases where this is not the case.

## Proof of Concept
According to the README under `Areas of Concern`, one of the important things to look for is 
- `Ensure compatibility with Cosmos-SDK v0.50.x and identify any breaking changes from v0.45.x.`

In the documentation of Cosmos 0.50.0. It is stated that it is no longer required to set modules in orderBeginBlockers and OrderEndBlockers. 

https://github.com/cosmos/cosmos-sdk/blob/v0.50.6/UPGRADING.md#module-assertions

However, this is still the case within Canto-main/app.go
```
@> app.ModuleManager.SetOrderBeginBlockers(
```
```
app.ModuleManager.SetOrderEndBlockers(
```

Also,
```
When using (legacy) application wiring, the following must be added to app.go:

+app.ModuleManager.SetOrderPreBlockers(
+	upgradetypes.ModuleName,
+)

app.ModuleManager.SetOrderBeginBlockers(
-	upgradetypes.ModuleName,
)

+ app.SetPreBlocker(app.PreBlocker)

// ... //

+func (app *SimApp) PreBlocker(ctx sdk.Context, req *abci.RequestFinalizeBlock) (*sdk.ResponsePreBlock, error) {
+	return app.ModuleManager.PreBlock(ctx, req)
+}

```
This is however not implemented like it is stated here.

This demonstrates that there're several inconsistencies between the  new update and the recommended changes from Cosmos Sdk
