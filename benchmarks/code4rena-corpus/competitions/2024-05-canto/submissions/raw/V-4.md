# Vulnerability details

## Impact
Using the incorrect context type can lead to failures in retrieving or setting staking parameters, potentially causing the upgrade process to malfunction. This may result in incomplete or incorrect application state changes during the upgrade, affecting the network's stability and reliability.


## Proof of Concept
In the `CreateUpgradeHandler` function, there is an issue with the context passed to the staking keeper's `GetParams` and `SetParams` methods. The `context.Context` (denoted as `ctx`) is used instead of the `sdk.Context` (denoted as `sdkCtx`). This can lead to unexpected behavior or errors since these methods are intended to operate within the specific context of the SDK.

Here is the problematic section of the code:
```
{
    params, err := stakingKeeper.GetParams(ctx)
    if err != nil {
        return vm, err
    }
    params.MinCommissionRate = MinCommissionRate
    stakingKeeper.SetParams(ctx, params)
}

```
In the Cosmos SDK, it is essential to use `sdk.Context` for keeper operations to ensure they function correctly within the blockchain application's context. The current implementation mistakenly uses `ctx`, which is a more generic context type.


## Tools Used
Manual
## Recommended Mitigation Steps
To mitigate this issue, ensure that `sdkCtx` is used when interacting with the staking keeper. Here is the corrected version of the code:

```
{
    params := stakingKeeper.GetParams(sdkCtx)
    params.MinCommissionRate = MinCommissionRate
    stakingKeeper.SetParams(sdkCtx, params)
}
```
