# Vulnerability details

## Impact


In the current implementation of `app.go`, the `PreBlocker` is incorrectly set incorrectly which affects current functionality.

## Proof of Concept

According to the Cosmos SDK v0.50.x docs:

https://github.com/cosmos/cosmos-sdk/blob/v0.50.6/UPGRADING.md

```
The following must be added to app.go:
```

```
+app.ModuleManager.SetOrderPreBlockers(
+	upgradetypes.ModuleName,
+)

app.ModuleManager.SetOrderBeginBlockers(
-	upgradetypes.ModuleName,
)

+ app.SetPreBlocker(app.PreBlocker)

// ... //

+func (app *SimApp) PreBlocker(ctx sdk.Context, req *abci.RequestFinalizeBlock) (*sdk.ResponsePreBlock, error) {
+	return app.ModuleManager.PreBlock(ctx, req)
+}

```


However, in the current implementation of `app.go`, `upgradetypes.ModuleName` is not deleted from `SetOrderBeginBlockers()`:

https://github.com/code-423n4/2024-05-canto/blob/main/canto-main/app/app.go#L823
```
upgradetypes.ModuleName
```

That makes the deviation from the spec.

## Tools Used

Manual review.

## Recommended Mitigation Steps

Delete `upgradetypes.ModuleName`
