Premature Rebalancing Triggered at Tick -40 or +40 Instead of -60 or +60
saikumar279
00
Sufficient
383d ago
Finding description and impact

The protocol specifies that rebalancing should be triggered when the price reaches tick -60 or +60(As attached in this picture https://github.com/code-423n4/2024-12-lambowin/tree/main#peg-and-repeg). However, the actual implementation triggers rebalancing prematurely at tick -40 or +40

Proof of Concept

Add below poc to RebalanceTest.t.sol also declare a variable uint256 private constant _SELL_MASK = 0; in same contract.


function test_for_poc_contest() public {
        console.log("Weth balance before first swap:",IWETH(WETH).balanceOf(uniswapPool));
        console.log("Veth balance before first swap:",IERC20(VETH).balanceOf(uniswapPool));
        
        uint256 amount = 402.75 ether;
        uint256 _v3pool = uint256(uint160(uniswapPool)) | (_ONE_FOR_ZERO_MASK);
        uint256[] memory pools = new uint256[](1);
        pools[0] = _v3pool;
        uint256 amountOut0 = IDexRouter(OKXRouter).uniswapV3SwapTo{value: amount}(
            uint256(uint160(multiSign)),
            amount,
            0,
            pools
        );


        console.log("Amount out after first trade/swap:", amountOut0);
        console.log("Weth balance after first swap:",IWETH(WETH).balanceOf(uniswapPool));
        console.log("Veth balance after first swap:",IERC20(VETH).balanceOf(uniswapPool));

        (bool result,,,) = lamboRebalance.previewRebalance();
        
        
        console.log("result(Here result is coming out to be true):",result);

        uint256 amount2 = 1 ether;
        uint256 _v3pooll = uint256(uint160(uniswapPool)) | (_SELL_MASK);
        uint256[] memory poolss = new uint256[](1);
        poolss[0] = _v3pooll;

        deal(VETH, address(this), amount2);
        IERC20(VETH).approve(address(OKXTokenApprove), amount2);
        uint256 amountOut00 = IDexRouter(OKXRouter).uniswapV3SwapTo(uint256(uint160(multiSign)), amount2, 0, poolss);

        console.log("Amount out for 1 value of VETH", amountOut00);
        console.log("Amount Sent in which is 1 Veth", amount2);
        
    }

OutPut of above poc:

Weth balance before first swap: 450000000000000000000
  Veth balance before first swap: 450000000000000000000
  Amount out after first trade/swap: 400336950693547669033
  Weth balance after first swap: 852750000000000000000
  Veth balance after first swap: 49663049306452330967
  result(Here result is coming out to be true): true
  Amount out for 1 value of VETH 1004026390780580213
  Amount Sent in which is 1 Veth 1000000000000000000


Walkthrough above:

The initial balances of WETH and VETH in the Uniswap V3 pool are both 450 ether.
You perform a swap with 402.75 ether of value of weth where you receive 400.3 ether value of veth.
Now the value of 1veth = 1.004 weth(Which we can see through second swap).
But the LamboRebalanceOnUniwap::previewRebalance should trigger at tick = 60 where price would be
price = 1.0001^60 which would approximately be equal to 1.006

But as you can see result is coming out to true through LamboRebalanceOnUniwap::previewRebalance due to first swap itself where still the price of 1veth = 1.004 weth.
Impact

The rebalancing mechanism is triggered at a tick index of ±40 instead of the specified ±60, potentially causing premature or unnecessary rebalancing operations.
