S-613
Fee calculation allows fee bypass through small initial buy amounts in createLaunchPadAndInitialBuy
Evo
52
Sufficient
383d ago
Impact

Users can bypass fees when creating launchpads by specifying small initial buy amounts where integer division results in 0 fees. This impact is magnified when feeRate is lowered by the owner, allowing increasingly larger amounts to completely avoid fees during launchpad creation, resulting in loss of fee revenue for the protocol.

Proof of Concept

The vulnerability exists in the fee calculation during initial buy when creating a launchpad through createLaunchPadAndInitialBuy:

function createLaunchPadAndInitialBuy(
    address lamboFactory,
    string memory name,
    string memory tickname,
    uint256 virtualLiquidityAmount,
    uint256 buyAmount
) public payable nonReentrant returns (address quoteToken, address pool, uint256 amountYOut) {
    require(VirtualToken(vETH).isValidFactory(lamboFactory), "only Validfactory");
    (quoteToken, pool) = LamboFactory(lamboFactory).createLaunchPad(
        name,
        tickname,
        virtualLiquidityAmount,
        address(vETH)
    );

    amountYOut = _buyQuote(quoteToken, buyAmount, 0);
}

The fee calculation happens in _buyQuote:

uint256 fee = (amountXIn * feeRate) / feeDenominator;

Let's demonstrate how fees can be bypassed during launchpad creation:

With default feeRate = 100 and feeDenominator = 10000:

lamboRouter.createLaunchPadAndInitialBuy{value: 99}(
    address(factory),
    "LamboToken",
    "LAMBO",
    10 ether,
    99  // buyAmount that results in zero fees
)
For buyAmount = 99:
fee = (99 * 100) / 10000 = 0

If owner sets feeRate = 50:

For buyAmount = 199:
fee = (199 * 50) / 10000 = 0

This allows users to avoid fees during launchpad creation by:

Setting small initial buy amounts below the fee calculation threshold
Taking advantage of lower feeRate settings to bypass fees on larger amounts during launch

}
