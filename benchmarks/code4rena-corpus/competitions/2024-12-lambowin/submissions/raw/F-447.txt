Incorrect Validation of vETH Underlying Token as ETH
0xiehnnkta
00
Sufficient
383d ago
Summary

createLaunchPadAndInitialBuy function in lamboVEthRouter.sol contract reverts if the underlying token for vETH is an ERC20 token.

Vulnerability Detail

createLaunchPadAndInitialBuy function must check weather the underlying token of vETH is ETH or ERC20. If it is ERC20, then the function reverts when it calls the _buyQuote function as it primirily checks msg.value >= amountXIn. But here it is zero, so it reverts the function.

    function createLaunchPadAndInitialBuy(
        address lamboFactory,
        string memory name,
        string memory tickname,
        uint256 virtualLiquidityAmount,
        uint256 buyAmount
    ) public payable nonReentrant returns (address quoteToken, address pool, uint256 amountYOut) {
        require(VirtualToken(vETH).isValidFactory(lamboFactory), "only Validfactory");
        (quoteToken, pool) = LamboFactory(lamboFactory).createLaunchPad(
            name,
            tickname,
            virtualLiquidityAmount,
            address(vETH)
        );

        amountYOut = _buyQuote(quoteToken, buyAmount, 0);
    }

In the above code, it should check weather the underlying token is ETH or not before checking the lamboFactory is valid or not. And also, there is no purpose for the code for lot of code in VirtualToken.sol contract regarding the underlying token is ERC20 token.

createLaunchPadAndInitialBuy function only valid for the native Ether. But to valid for ERC20 token also it need to have different _buyQuote function itself, as it includes sending fee from the deposited funds. So, the _buyQuote needs to validate the token and then it need to operate entirely in different way compared to the preceding one. And same for the internal _sellQuote function, it also needs to validate the token and then need to send the the funds in terms of ERC20 tokens when underlying token is ERC20 and ether when underlying token is native Ether.

Impact

createLaunchPadAndInitialBuy is only compatible with the native Ether but not with any other ERC20 token. So when user tries to create launch pad with other than native Ether the function reverts, which unjustified the purpose of the protocol.
