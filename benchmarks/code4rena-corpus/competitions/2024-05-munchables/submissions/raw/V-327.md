# Vulnerability details

## Description
In generic transfer and transferFrom calls, Blast's implementation of USDB and WETH will revert if the token sender does not have enough balance.
However, as the scope states the assumption that the team "can add more (tokens) to the future for use in LockManager", the implementation needs a more future-proof logic to handle edge-cases. 
Such as tokens that don't revert but return a false Boolean in such occurrences. 

## Impact
Some tokens may not revert if the LockManager contract or the caller don't have enough balance for the operation. Locks and unlocks can be made without the transfer of any token balance.
## Tools Used
Manual review
## Recommended Mitigation Steps
Make sure to utilize the safeTransfer library instead of transfer and transferFrom as it handles the multitude of ERC-20 implementations and its edge cases.
