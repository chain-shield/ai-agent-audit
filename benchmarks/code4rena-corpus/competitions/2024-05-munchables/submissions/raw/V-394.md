# Vulnerability details

## Impact
In function `_lock`, the validation of `_lockDuration` is misplaced. The result is that *invalid* `_lockDuration` can still be set before the lockdrop starts or after the lockdrop ends.

## Proof of Concept
According to L350 and L357-L359, it is expected that `lockdrop.minLockDuration <= _lockDuration <= configStorage.getUint(StorageKey.MaxLockDuration)`. But the `_lockDuration` validation is checked only in lockdrop phase. So if current timestamp is outside the lockdrop phase, the `_lock` function does not validate the `_lockDuration`. The player's lock duration and his locked tokens' unlock time may be set with unexpected values.
