# Vulnerability details

## Description
The player is able to call `lock/unlock` at will with `zero amount` without any constraint. The root cause is because those functions doesn't do any validation in that regards. 

Such behavior seems unexpected, and since `accountManager.forceHarvest` is called within those functions, it is unclear if this could cause any type of side effects in the game. Overall, this seems to warrant border line `Medium` severity.

## Impacts
`lock` and `unlock` can be called without reverting with a zero amount and fully processing the transaction emitting events, which has the posibility to create sides effetcs:
- Someone could grief the contract which will emit Locked/Unlocked event, which can be annoying for any off-chain tool that consume those (if any).
- `forceHarvest` being called at every call which has the potential to create unexpected behavior.
- If a player do this from the beginning, his `LockedToken` instance will look weird, as remainder and quantity would be zero, while lastLockTime and unlockTime would not, which has the potential to create unexpected behavior.
```diff
        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;
        lockedToken.lastLockTime = uint32(block.timestamp);
        lockedToken.unlockTime = uint32(block.timestamp) + uint32(_lockDuration);
```

        uint256 timing;
        uint256 lockAmount = 0;
        deployContracts();

        // Register me

        // Lock 0 amount
        lm.lock{value: lockAmount}(address(0), lockAmount);

        timing += 2 days;
        vm.warp(timing);

        // Unlock the 0 amount
        lm.unlock(address(0), lockAmount);
    }
