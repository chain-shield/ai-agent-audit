# Vulnerability details

## Impact
Impact: High, as value can be stuck forever
Likelihood: Low
Overall medium

## Proof of Concept

LockManager.sol contract has `receive` and `fallback` functions that are `payable`. If someone sends a transaction with `msg.value != 0` then the ETH will be `stuck` in the contract forever without a way for anyone to withdraw it.

```
fallback() external payable {
        revert LockManagerInvalidCallError();
    }

    receive() external payable {
        revert LockManagerRefuseETHError();
    }
```

A contract is able to receive funds with the payable attribute must have a withdraw function to secure that funds can be sent out from the contract or remove payable attribute.


## Tools Used

manual

## Recommended Mitigation Steps

Best practice here is to implement a function that is used for withdrawing the stuck ETH, or just remove the fallback and receive functions.
