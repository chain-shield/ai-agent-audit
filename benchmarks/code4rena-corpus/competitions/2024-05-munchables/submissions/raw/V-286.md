# Vulnerability details

## Details
The `LockManager::lockOnBehalf` function allows any address to lock tokens on behalf of another user and extend the lock time for that user’s tokens. This function can be exploited to prevent an address from unlocking their tokens.

There are 3 factors which enable an attacker to perform this attack with zero cost:

### 1- Insufficient checks for `_tokenOwner`:
The `_unlock` function only checks if `_tokenOwner` (the attacker's address) has sufficient allowance for the contract or if `msg.value` matches the `_quantity`:

        if (_tokenContract == address(0)) {
            if (msg.value != _quantity) revert ETHValueIncorrectError();
        } else {
            if (msg.value != 0) revert InvalidMessageValueError();
            IERC20 token = IERC20(_tokenContract);
            //@audit only checked to have allowance
            uint256 allowance = token.allowance(_tokenOwner, address(this));
            if (allowance < _quantity) revert InsufficientAllowanceError();
        }

There are no additional checks to verify the identity of the `_tokenOwner`. for example in some protocols a user must explicitly approve another user to modify their stats.

### 2- `_quantity` can be zero, making the attack very cheap (little to no cost):
There are no checks to ensure that the `_quantity` parameter is greater than zero or a minimum value defined by the protocol. The code does not revert if `_quantity` is set to zero. If there was a minimum amount required for locking, the cost of the attack would increase, making it less feasible for an attacker.

### 3- `tokenLock.unlockTime` resets to `block.timestamp + playerSettings[_lockRecipient].lockDuration`:
The unlockTime for the tokens resets to `block.timestamp + playerSettings[_lockRecipient].lockDuration` whenever `LockManager::lockOnBehalf` is called:

    lockedToken.unlockTime =
      uint32(block.timestamp) +
      uint32(_lockDuration);


These vulnerabilities allow an attacker to conduct `DoS` attack on any user at no cost preventing them from unlocking their tokens. The attacker can simply call LockManager::lockOnBehalf with the following parameters:

    _tokenContract: The address of the token that the user has locked.
    _quantity: Zero, allowing the attack to be executed at no cost.
    _onBehalfOf: The victim's address.

## Impact
Attacker is able to perform this attack with little to no cost preventing any user from unlocking their assets.
Attacker can simply front-run the victim's `unlock` transaction by `lockOnBehalf(_token, 0, victim)` transaction to perform this attack.

copy and paste this code into `LockManager.t.sol` and run `forge test --match-test test_poc_prevent`:

    function test_poc_preventAddressFromUnlock() public {
        uint256 lockAmount = 100 ether;

        console.log("Beginning run()");
        deployContracts();

        //note register me

        logSnuggery("Initial snuggery");

        //note lock tokens (100 ETH)
        lm.lock{value: lockAmount}(address(0), lockAmount);

        vm.warp(block.timestamp + 86400);

        uint balance_0 = address(this).balance;
        lm.unlock(address(0), 10 ether);
        uint balance_1 = address(this).balance;

        //note front-run transaction to DoS the next line
        vm.startPrank(makeAddr("Attacker"));
        lm.lockOnBehalf(address(0), 0, address(this));
        vm.stopPrank();

        //note unlock transaction which is front-runned by the last transaction, preventing it from settling due to 
        //lock time not reached yet
        vm.expectRevert(abi.encodeWithSignature("TokenStillLockedError()"));
        lm.unlock(address(0), 50 ether);
    }

## Recommended Mitigation Steps
The most basic solution would be to add a function for users to approve other users for locking tokens on their behalf:

    mapping(address => mapping(address => bool)) approvals;

    function approveOnBhealf(address _anotherUser, bool _status) public {
        approvals[msg.sender][_anotherUser] = _status;
    }

and to check if `_tokenOwner` is approved to lock tokens for `_lockRecipient`:

    function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {
      //@audit-info if _tokenOwner is migration manager, pass
      if(!msg.sender != address(migrationManager) && _tokenOwner != _lockRecipient){
      require(approvals[_lockRecipient][_tokenOwner], "Token owner not authorized");
      }
    }
