# Vulnerability details

## Summary

The protocol permits users to lock tokens to earn rewards and mint NFTs. To mint an NFT, users must lock tokens for at least the minimum lock duration and a specified minimum ETH amount. However, users can exploit the system by locking and unlocking the same amount after the unlock period, then re-locking to mint additional NFTs, effectively recycling their initial investment multiple times.

## Vulnerability Detail

The _lock function facilitates the locking of funds, awarding users NFTs if they meet the minimum lock duration:

- _lock

            if (msg.value != _quantity) revert ETHValueIncorrectError();

        uint256 quantity = _quantity + lockedToken.remainder;

        uint32 _lockDuration = playerSettings[_lockRecipient].lockDuration;

Users are allowed to unlock their funds once the lock period ends:

- unlock
```solidity=401
function unlock(
        address _tokenContract,
        uint256 _quantity
    ) external notPaused nonReentrant {
        LockedToken storage lockedToken = lockedTokens[msg.sender][
            _tokenContract
        ];
        if (lockedToken.quantity < _quantity)
            revert InsufficientLockAmountError();
        if (lockedToken.unlockTime > uint32(block.timestamp))
            revert TokenStillLockedError();

        // force harvest to make sure that they get the schnibbles that they are entitled to
        accountManager.forceHarvest(msg.sender);

        lockedToken.quantity -= _quantity;

        // send token
        if (_tokenContract == address(0)) {
            payable(msg.sender).transfer(_quantity);
        } else {
            IERC20 token = IERC20(_tokenContract);
            token.transfer(msg.sender, _quantity);
        }

        emit Unlocked(msg.sender, _tokenContract, _quantity);
    }
```

the protocol does not account for the NFTs minted during the initial lock, allowing users to re-lock the same funds to mint more NFTs repeatedly after each lockPeriod has passed.

## Impact

This vulnerability allows users to mint multiple NFTs using the same locked funds by merely locking, unlocking, and re-locking them. This undermines the intended scarcity and value of the NFTs, potentially inflating the NFT count and devaluing the entire ecosystem.

## Tool used

Manual Review

## Recommendation

Implement a robust accounting system that tracks the amount of funds previously used for minting NFTs. Prevent the re-use of unlocked funds for further NFT minting unless additional funds are added or a new locking period is initiated
