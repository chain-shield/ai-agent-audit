# Vulnerability details

## Impact
The `setLockDuration` function will eventually be unusable due to excessive gas usage.

## Proof of Concept
Loops that do not have a fixed number of iterations, for example, loops that depend on storage values, have to be used carefully: Due to the block gas limit, transactions can only consume a certain amount of gas. Either explicitly or just due to normal operation, the number of iterations in a loop can grow beyond the block gas limit which can cause the complete contract to be stalled at a certain point.

By calling the `configureToken()` function, a `_tokenContract` will be pushed to the `configuredTokenContracts` array. A player can call the `setLockDuration()` function to set the `lockDuration` for a player's tokens. However, the loop in the `setLockDuration()` function may revert in case of hitting the gas limit of the network. Since there is no way to remove `configuredTokenContracts` elements or decrease their length in the `setLockDuration()` function, it is possible to make it completely impossible to call the `setLockDuration()` function.



## Tools Used
Manual Review

## Recommended Mitigation Steps
Make the contract capable of removing unnecessary `_tokenContract` to reduce the loop round in the `setLockDuration()` function. or Limit the max number of loop iterations to prevent hitting block gas limit.
