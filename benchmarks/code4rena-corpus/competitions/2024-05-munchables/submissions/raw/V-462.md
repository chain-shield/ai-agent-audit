# Vulnerability details

## Impact
Function getLockedWeightedValue will become unusable if tokens with more than 18 decimals are added to the protocol.

## Proof of Concept
According to the README.md, more tokens are going to get added in the future. Just assuming that all tokens have a maximum of 18 decimals is not sufficient, since there are tokens with more that 18 decimals. For tokens like YAMv2 the deltaDecimal will become negative, resulting in an underflow and breaking the function.
```Solidity
function getLockedWeightedValue(
        address _player
    ) external view returns (uint256 _lockedWeightedValue) {
        uint256 lockedWeighted = 0;
        uint256 configuredTokensLength = configuredTokenContracts.length;
        for (uint256 i; i < configuredTokensLength; i++) {
            if (
                lockedTokens[_player][configuredTokenContracts[i]].quantity >
                0 &&
                configuredTokens[configuredTokenContracts[i]].active
            ) {
                // We are assuming all tokens have a maximum of 18 decimals and that USD Price is denoted in 1e18
                uint256 deltaDecimal = 10 **
                    (18 -
                        configuredTokens[configuredTokenContracts[i]].decimals);
                lockedWeighted +=
                    (deltaDecimal *
                        lockedTokens[_player][configuredTokenContracts[i]]
                            .quantity *
                        configuredTokens[configuredTokenContracts[i]]
                            .usdPrice) /
                    1e18;
            }
        }

        _lockedWeightedValue = lockedWeighted;
    }
```
