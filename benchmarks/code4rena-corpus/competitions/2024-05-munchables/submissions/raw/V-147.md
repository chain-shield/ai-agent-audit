# Vulnerability details

## Impact
`getLockedWeightedValue` will not work with token that has high decimals ( > 18)

## Proof of Concept
According to [ERC20 token behaviors in scope](https://github.com/code-423n4/2024-05-munchables/tree/main?tab=readme-ov-file#erc20-token-behaviors-in-scope), tokens that has high decimals ( > 18) will be supported.

But in `getLockedWeightedValue`, the code will revert because of underflow in [LockManager.sol#L474-L475](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L474-L475)
```solidity
461     function getLockedWeightedValue(
462         address _player
463     ) external view returns (uint256 _lockedWeightedValue) {
464         uint256 lockedWeighted = 0;

470                 configuredTokens[configuredTokenContracts[i]].active

477                     (deltaDecimal *

479                             .quantity *
480                         configuredTokens[configuredTokenContracts[i]]

483             }
484         }

486         _lockedWeightedValue = lockedWeighted;

```

`getLockedWeightedValue` is not just a view function, because it will be used in functions like [AccountManager._harvest](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/AccountManager.sol#L372-L387)
