# Vulnerability details

## Impact
Some amounts of USDB might be locked forever in the protocol. In other cases, insolvency could be possible, meaning, the last user might not be able to unlock their full amount. 

## Proof of Concept
USDB on Blast is a rebase token, so the balance can change at any time.
The mechanism behind rebase tokens is altering the token supply proportionally across all existing holders' balances. 

When the token's price deviates from its target, a rebase event is triggered, where in the protocol adjusts the token supply by either increasing or decreasing the number of tokens each user holds. this adjustment aims to push the token's price toward its intended target, stabilizing its value over time.

The issue could happen when some USDB amounts are used in the protocol to be locked, since the lock duration can be up to 90 days, it is possible for the USDB rebase token amount to be changed. Therefore, the balance of LockManager contract might change. 

This would lead to a simple conclusion: big deposits of USDB can decrease or increase with the time while they are being locked, thus incase the amount of X increased, the user will lose the increasing value since he can only claim those stored at the time of locking. These surplus amounts can not be recovered by the protocol as there is no method to do so.

Moreover, if the balance in the contract decreased instead, the last user to unlock their USDB will incur loss, unlike early users who can unlock their full amounts of USDB.



## Tools Used
Manual Review

## Recommended Mitigation Steps

Use a wrapper for the rebase token USDB (or any other rebase token that will be used) to behave as a standard ERC20 token
