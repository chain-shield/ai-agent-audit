# Vulnerability details

Description:In the `_lock` function which is call by `lock` and `lockOnBehalf`, there's no explicit check to ensure that the `_quantity` parameter passed to the function is greater than zero all `lock` , `lockOnBehalf` and `_lock` doesn't check it . This means that if `_quantity` is mistakenly set to zero, it would still execute the lock operation without actually locking any tokens. If an attacker were to exploit this vulnerability by calling `lockOnBehalf` or `lock` with a `_quantity` of zero, they could effectively bypass the intended token locking mechanism. This could lead to loss of funds if users rely on this function to securely lock their tokens.

**Mitigation Steps:**  Add a check at the beginning of the `lock` and `lockOnBehalf` functions to ensure that the `_quantity` parameter is greater than zero before proceeding with locking tokens. This check will prevent the contract from locking tokens with an invalid or zero quantity.

```solidity
if (_quantity == 0) {
        revert InvalidQuantityError();
    }
```
