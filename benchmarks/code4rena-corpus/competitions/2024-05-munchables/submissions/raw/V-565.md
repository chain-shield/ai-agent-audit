# Vulnerability details

##Impact
Increased unlock time for user's previous locked tokens.

##Proof of Concept
Consider a situation where a user locks a token initially, the tokens unlock time is set as the minLockDuration or Whatever the user sets as _lockDuration. If the user locks n amount of the same token at another time, the unlock time of the first lock is unconventionally incremented by minLockDuration or _lockDuration. This leads to a longer wait time for the users initially staked token.

Consider the following example:
Alice locks 2 WETH with a minLockDuration of 30 days.
Days after alice locks another 3 WETH
Her total locked tokens becomes 5 WETH but with an unlock time of 60 days.
It becomes impossible to unlock her initial 2 WETH due to the increased unlock time.

##Recommendation
Set different unlock times for subsequent token locks or add an optional variable which users users can toggle to increase their unlock time if they have previously locked that token.
