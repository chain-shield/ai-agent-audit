# Vulnerability details

## Impact
Allowing users to receive more schnibbles than entitled.

## Proof of Concept
In the `unlock` function, there is no check for a zero quantity, allowing users to call `accountManager.forceHarvest(msg.sender);` with a quantity of 0. This results in schnibbles being harvested even when no tokens are actually unlocked.

Code : https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L401

The issue can be exploited as follows:

- Alice locks 10 WETH tokens.
- Alice calls the unlock function with the tokenContract and a quantity of 0.
- This bypasses the following checks:
`
if (lockedToken.quantity < _quantity) revert InsufficientLockAmountError();
if (lockedToken.unlockTime > uint32(block.timestamp)) revert TokenStillLockedError();
`
- `accountManager.forceHarvest(msg.sender);` is called.
- Since the quantity is 0, no tokens leave the contract, and Alice can call this function again, potentially leading to an unintended increase in schnibbles.
(as the `_harvest` calls `getDailySchnibbles` which takes the value from `getLockedWeightedValue` which returns same everytime.)

The same can be done with the `_lock` function. After locking some tokens, one can call it with a quantity of 0. However, in this case, only schnibbles can be harvested as no NFTs are obtained.

## Tools Used
manual review

## Recommended Mitigation Steps

add something like this at the start of the `_lock` and `unlock` functions.
`if (_quantity == 0) revert InvalidLockQuantityError();`
