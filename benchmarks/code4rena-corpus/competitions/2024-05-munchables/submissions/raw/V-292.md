# Vulnerability details

## Impact
In the `configureToken` function (Lines 115-127), the way the `configuredTokenContracts` array is updated when a new token contract is added. The code checks if the `nftCost` for the given `_tokenContract` is zero, and if so, it assumes it's a new token and adds the contract address to the `configuredTokenContracts` array. [src/managers/LockManager.sol#L120-123](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L120-L123)
```solidity
if (configuredTokens[_tokenContract].nftCost == 0) {
    // new token
    configuredTokenContracts.push(_tokenContract);
}
```
This logic is flawed because it's possible for an existing token contract to be reconfigured with a non-zero `nftCost` value. In such a case, the contract address would be added to the `configuredTokenContracts` array again, leading to duplicates.

## Proof of Concept
The `configuredTokenContracts` array is meant to store the addresses of all token contracts that have been configured for the `LockManager.sol`. This array is likely used by other contracts that interact with the `LockManager`. If this array contains duplicate entries, it can lead to various issues, such as:

> If the `configuredTokenContracts` array contains duplicates, it will no longer accurately represent the set of unique token contracts that have been configured. This can lead to incorrect calculations, incorrect data being displayed, or other unintended behavior in any part of the system that relies on this array.

> In some cases, the presence of duplicate entries in the `configuredTokenContracts` array could potentially be exploited by an attacker. For example, if there are functions or logic that iterate over this array and perform operations based on the contract addresses, an attacker could potentially manipulate the order or presence of duplicates to their advantage.

Here's an example of how this bug could be exploited:
```solidity
function doSomethingWithConfiguredTokens() external {
    for (uint256 i = 0; i < configuredTokenContracts.length; i++) {
        address tokenContract = configuredTokenContracts[i];
        // Perform some operations with the token contract
        // ...
    }
}
```
If the `configuredTokenContracts` array contains duplicates, the loop in `doSomethingWithConfiguredTokens` will perform the same operations multiple times for the duplicated contract addresses. this could lead to unintended behavior, such as double-counting or double-spending of tokens, incorrect state updates, or other vulnerabilities.

To illustrate the concept further, let's consider a scenario where the `configureToken` function is called twice with the same `_tokenContract` address, but with different `nftCost` values:
```solidity
// Initial configuration
configureToken(tokenContractA, { nftCost: 0, ... });
// configuredTokenContracts = [tokenContractA]

// Reconfiguration with non-zero nftCost
configureToken(tokenContractA, { nftCost: 1000, ... });
// Due to the bug, configuredTokenContracts = [tokenContractA, tokenContractA]
```
In this case, the `configuredTokenContracts` array will contain two entries for `tokenContractA`, which is incorrect. Any function or logic that iterates over this array will treat `tokenContractA` as two separate contracts, leading to unintended consequences or vulnerabilities.

## Recommended Mitigation Steps
Check if the `_tokenContract` address already exists in the `configuredTokenContracts` array before adding it. 
```solidity
function configureToken(
    address _tokenContract,
    ConfiguredToken memory _tokenData
) external onlyAdmin {
    if (_tokenData.nftCost == 0) revert NFTCostInvalidError();

    bool isNewToken = configuredTokens[_tokenContract].nftCost == 0;
    if (isNewToken && !configuredTokenContracts.contains(_tokenContract)) {
        // new token
        configuredTokenContracts.push(_tokenContract);
    }

    configuredTokens[_tokenContract] = _tokenData;

    emit TokenConfigured(_tokenContract, _tokenData);
}
```
The `isNewToken` variable checks if the `nftCost` for the given `_tokenContract` is zero, indicating a new token. Then, it checks if the `_tokenContract` address is not already present in the `configuredTokenContracts` array using the contains function (which need to be implemented separately). If both conditions are true, it adds the contract address to the array.
