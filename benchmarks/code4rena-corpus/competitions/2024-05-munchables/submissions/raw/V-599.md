# Vulnerability details

## Impact
The `_lock` function allows tokens to be locked even when the `lockdrop` period is over, without providing any benefits to the user. This can lead to user dissatisfaction and potential loss of trust, as users may lock their tokens without receiving any rewards as munchables are only minted during the `lockdrop` period. 

## Proof of Concept
In the `_lock` function, tokens are locked regardless of whether the `lockdrop` period is active:
```solidity
function _lock(
    address _tokenContract,
    uint256 _quantity,
    address _tokenOwner,
    address _lockRecipient
) private {
    // Existing code...
    if (
        lockdrop.start <= uint32(block.timestamp) &&
        lockdrop.end >= uint32(block.timestamp)
    ) {
        // Benefits are only provided during the lockdrop period
        // Existing code...
    }
    // Tokens are locked regardless of the lockdrop period
    if (_tokenContract != address(0)) {
            IERC20 token = IERC20(_tokenContract);
            token.transferFrom(_tokenOwner, address(this), _quantity);
    }
}
```

Manual Review
## Recommended Mitigation Steps
Restrict the locking of tokens to only within the `lockdrop` period. If the `lockdrop` period is over, the function should revert and not lock the tokens.
