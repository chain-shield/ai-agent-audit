# Vulnerability details

## Impact
Due to wrong calculation of quantity and remainder, the user can lose their fund.

## Proof of Concept
Suppose the `nftCost` of a token is 100e18. An user locks this token by calling the function `lock` with the following parameters:
 - `_tokenContract` = token contract address
 - `_quantity` = 120e18

 In the function `_lock`, the variable `quantity` is set to 120e18, because `uint256 quantity = _quantity + lockedToken.remainder = 120e18 + 0 = 120e18`, assuming `remainder` is zero.
 ```solidity
    function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {

        //.....

        uint256 quantity = _quantity + lockedToken.remainder;

        //.....

        remainder = quantity % configuredToken.nftCost;
        numberNFTs = (quantity - remainder) / configuredToken.nftCost;

        //.....

        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;

        //....
    }
 ```
 https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L311

 Since the `nftCost` is 100e18, the `remainder` will be 20e18, and `numberNFTs` will be one. At the end, we will have:
  - `lockedToken.remainder` = 20e18
  - `lockedToken.quantity` = 100e18

Later the user locks another **80e18** token to use sum of this amount and the remainder to reveal another NFT. This time, the variable `quantity` is set to 100e18, because `uint256 quantity = _quantity + lockedToken.remainder = 80e18 + 20e18 = 100e18`, and the `remainder` will be zero, and one more NFT is revealed for the user. At the end we will have:
  - `lockedToken.remainder` = 0
  - `lockedToken.quantity` = 100e18 + 80e18 = 180e18

**The issue is that the `lockedToken.quantity` and `lockedToken.remainder` are set to 180e18 and 0, respectively, while the user so far locked 200e18.**

Because of this issue, when the user would like to unlock, he is only able to unlock and withdraw 180e18 token, and he loses 20e18.
```solidity
    function unlock(
        address _tokenContract,
        uint256 _quantity
    ) external notPaused nonReentrant {
        //....

        lockedToken.quantity -= _quantity;

        //....
    }
```
https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L416

**The root cause of this issue is that `lockedToken.quantity` is updated based on `_quantity` which is the function parameter, while the contribution of `lockedToken.remainder` to the quantity is missed. In other words, the quantity set for the user misses the remainder part.**

## Recommended Mitigation Steps
Modify the code as follows:
 ```solidity
    function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {

        //.....

        remainder = quantity % configuredToken.nftCost;
        numberNFTs = (quantity - remainder) / configuredToken.nftCost;

        // add the following code to update the quantity with the correct value
        quantity = quantity - remainder;

        //.....

        lockedToken.remainder = remainder;

        // replace the _quantity with quantity
        lockedToken.quantity += quantity;

        //....
    }
 ```
