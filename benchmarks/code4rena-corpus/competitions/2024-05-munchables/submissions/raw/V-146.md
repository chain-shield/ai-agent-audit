# Vulnerability details

In `LockManager.sol` users can lock their tokens at any point. However if there is a lockdrop event, depending on the amount of tokens they lock they will get a number of nft reveals:

```solidity
        if (lockdrop.start <= uint32(block.timestamp) &&
            lockdrop.end >= uint32(block.timestamp)) {
            if (
                _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
            if (msg.sender != address(migrationManager)) {
                // calculate number of nfts
                remainder = quantity % configuredToken.nftCost;
                numberNFTs = (quantity - remainder) / configuredToken.nftCost;

                if (numberNFTs > type(uint16).max) revert TooManyNFTsError();

                // Tell nftOverlord that the player has new unopened Munchables
                nftOverlord.addReveal(_lockRecipient, uint16(numberNFTs));
            }
        }
```
As you can see from the code snippet we get a remainder from the modulo operation between the quantity of tokens we lock and the cost of a single nft:
```solidity
remainder = quantity % configuredToken.nftCost;
```
This remainder is added to future locks:
```solidity
uint256 quantity = _quantity + lockedToken.remainder;
```

The issue is that if the user locks tokens when there is no lockdrop event this remainder will get reset to 0. He won't be able to use it for future lockdrop events so he just loses funds.


## Impact
Loss of funds for the user.

## Proof of Concept
```solidity
    function _lock(address _tokenContract, uint256 _quantity, address 
    _tokenOwner, address _lockRecipient) private {
...
        uint256 remainder; //default value = 0
...
        if (lockdrop.start <= uint32(block.timestamp) &&
            lockdrop.end >= uint32(block.timestamp)) {
...
                remainder = quantity % configuredToken.nftCost;
...
            }
        }
...
        lockedToken.remainder = remainder;
```
As you can see if there is no lockdrop event we don't enter the if statement so the remainder variable doesn't get updated to `quantity % configuredToken.nftCost` which means it keeps its default value of 0. After that `lockedToken.remainder` will get updated to zero in the last line of the code snippet.

Here is an example of how an user can lose his funds:
1. Alice decides to lock 2005e18 DAI
2. The NFT associated with this token costs 1000e18 DAI
3. Alice gets 2 NFT reveals and a remainder of 5e18 DAI which gets stored in `lockedToken.remainder`
4. After the lockdrop event has ended alice decides to lock 995e18 DAI but because of this her `lockedToken.remainder = 5e18` gets reset do 0
5. A new lockdrop event starts and she deposits 1000e18 more DAI and expects to get 2 NFTs because the price of one is still 1000e18 DAI
6. She gets only 1 and has lost 5e18 DAI that she cannot get back.


## Tools Used
Manual Review

## Recommended Mitigation Steps
Don't update `lockedToken.remainder = remainder` if remainder is 0.
```
if (remainder != 0)
{ lockedToken.remainder = remainder }
```
