# Vulnerability details

## Impact
Tokens are stuck for the allowed owner.  This can be used, for example, as extortion from the real owner who promised allowance, but contract fully doesn't support it.

## Proof of Concept
`allowance` can be used to lock tokens, but it cannot be used to unlock the tokens.
If you are allowed to lock the tokens, then you should also be allowed to unlock. Otherwise, you will lock your tokens but can never unlock.


## Tools Used

## Recommended Mitigation Steps

Update `_unlock` function to use `_tokenOwner`. Just as in the `_lock` function.

```solidity
function unlock(
        address _tokenContract,
        uint256 _quantity
+       address _tokenOwner,
    ) external notPaused nonReentrant {
    ...
    
+   uint256 allowance = token.allowance(_tokenOwner, address(this));
+   if (allowance < _quantity) revert InsufficientAllowanceError();
```
