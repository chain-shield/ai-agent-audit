# Vulnerability details

In `LockManager.sol` a user can call `lock()` to lock his tokens. If he does so during a lockdrop event he can get NFT reveals deppending on the cost of a single NFT and the quantity of tokens the user deposits. 

If there is a remainder after calculating how many NFTs he should get it gets stored in `lockedToken.remainder` which is added to future locks.
```solidity
uint256 quantity = _quantity + lockedToken.remainder;
...
remainder = quantity % configuredToken.nftCost;
numberNFTs = (quantity - remainder) / configuredToken.nftCost;
...
lockedToken.remainder = remainder;
```

The problem is that there is no way for the user to withdraw this remainder even if he calls the `unlock()` function. In order to get it back he has to lock an additional specific amount of tokens so that there is no remainder left. However he may not have enough funds to do that.

## Impact
Loss of funds for the user

## Proof of Concept
Here is the unlock function:
https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L401-L427

As you can see it can only return `lockedToken.quantity` back to the user but not `lockedToken.remainder`

Imagine the following scenario:
1. Alice decides to lock 1005e18 tokens
2. The NFT associated with this token costs 1000e18 tokens
3. Alice gets 1 NFT reveal and a remainder of 5e18 tokens which gets stored in `lockedToken.remainder`
4. Alice wants to unlock and withdraw all of her funds but she can't get her remainder back.
5. In order to get it back she has to lock additional 995e18 tokens so that there is no remainder left. She may not have the funds needed to do that.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Allow the user to get `lockedToken.remainder` back using the `unlock()` function
