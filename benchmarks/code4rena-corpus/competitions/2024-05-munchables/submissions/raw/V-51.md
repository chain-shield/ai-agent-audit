# Vulnerability details

`configureLockdrop` function is used by the admin to setup the `lockdrop` by setting the `start`, `end`, ` MinlockDuration ` as stated in the struct
```solidity
struct Lockdrop {
        uint32 start;
        uint32 end;
        uint32 minLockDuration;
    }
```
`minLockDuration` represents the minimum amount of time a user can lock their tokens before being able to unlock and withdraw them. This is stated in the documentation of `munchables` that "a user must lock for a minimum of 30days up to 90days and recieve schnibble harvest". 

However during the configuration of the `lockdrop`, ` MinlockDuration ` is not set which makes ot default to zero.
 
## Impact
Users can unlock at anytime before 30days, this allows users to game the munch points whenever it's in their favour or if not.
Also the user will earn schinbbles from  `forceHarvest.

## Proof of Concept
The struct containing the necessary parameters to configure the lockdrop

```solidity
struct Lockdrop {
        uint32 start;
        uint32 end;
        uint32 minLockDuration;
    }
```
However during the setup the `_lockdropData` do not contain or validate the `minlockDuration ` which makes it default to zero 

https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L98-L112
```solidity
function configureLockdrop(
        Lockdrop calldata _lockdropData
    ) external onlyAdmin {
        if (_lockdropData.end < block.timestamp)
            revert LockdropEndedError(
                _lockdropData.end,
                uint32(block.timestamp)
            ); // , "LockManager: End date is in the past");
        if (_lockdropData.start >= _lockdropData.end)
            revert LockdropInvalidError();

        lockdrop = _lockdropData;

        emit LockDropConfigured(_lockdropData);
    }
```

When locking users first need to set the lock duration, the function only checks if the `_duration` is beyond the `MaxLockDuration` and doesn't check for the `minLockDuration`.

Users can specify a `_duration` of anything below the required 30days even zero to allow unlocking at anytime since zero can't be greater than `MaxLockDuration`.
