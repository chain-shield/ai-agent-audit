# Vulnerability details

## Impact
Loss of yield if USDB/WETH is used as configured/reward token

## Proof of Concept
According to the contest readme, protocol team aims to support ERC20 tokens such as USDB/WETH and protocols need to be deployed on blast:

> ERC20 used by the protocol- 	USDB, WETH, (assume we can add more to the future for use in LockManager)

Both USDB and WETH are set to AUTOMATIC yield mode by default. The `LockManager.sol` contract uses internal accounting to track all rewards accrued for users. For example, when users lock a `_quantity`, the user's balance increases accordingly. Rewards distributed to users are based on these internal accounting values.
[LockManager.sol#L374-L380)](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L374-L380)
```js
        if (_tokenContract != address(0)) {
            IERC20 token = IERC20(_tokenContract);
            token.transferFrom(_tokenOwner, address(this), _quantity);
        }


        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;
```

The Issue:
If USDB or WETH tokens are used as reward tokens, the accrued yield due to automatic rebasing is lost as it cannot be claimed.
## Tools Used
Manual Review

## Recommended Mitigation Steps
To address this issue, add the ability to set native RebasingERC20 tokens to CLAIMABLE and implement a method for claiming the yields to the `LockManager.sol`
