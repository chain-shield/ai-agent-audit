# Vulnerability details

## Impact
Users may lose part of the remainder funds.

## Proof of Concept
remainder represents the non-divisible part of the user's pledge, and quantity represents the divisible part of the user's pledge.

If the user locks during the lockdrop, and the remainder is not equal to 0. After the lockdrop ends, and the user locks again, [the contract will directly set the remainder to 0, and will not add the previous remainder to the quantity](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L379-L380). In this way, the user loses the remainder of locks.

```solidity
        uint256 quantity = _quantity + lockedToken.remainder;
        uint256 remainder;
···
        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;
```

## Tools Used
manual

## Recommended Mitigation Steps
Remainder should be calculated correctly even if addReveal is not called.
