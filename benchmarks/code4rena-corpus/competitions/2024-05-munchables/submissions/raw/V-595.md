# Vulnerability details

## Impact
The `_lock` function does not account for the different values of tokens (USDB, ETH, WETH) and treats the `_quantity` the same regardless of the token type. This can lead to incorrect calculations and potential vulnerabilities, as different tokens have different decimal places and values.

## Proof of Concept
In the `_lock` function, the quantity of tokens is treated uniformly without considering the specific properties of each token:
```solidity
function _lock(
    address _tokenContract,
    uint256 _quantity,
    address _tokenOwner,
    address _lockRecipient
) private {
    // No differentiation between USDB, ETH, WETH
    // Existing code...
}
```
## Tools Used
Manual Review
## Recommended Mitigation Steps
Convert the token quantity to its USD equivalent using the token's USD price before performing any calculations. This ensures that the quantity is treated correctly regardless of the token type.
