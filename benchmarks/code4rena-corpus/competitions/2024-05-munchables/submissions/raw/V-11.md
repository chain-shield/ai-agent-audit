# Vulnerability details

In the [LockManager.sol](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol) contract, users can lock his `WETH` to mint new Munchable NFTs and/or migrate existing ones. This is done by calling the [lock()](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L297C5-L309C6) function, which calls [_lock()](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L311). The [_lock()](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L311) function sets `msg.sender` as the `_tokenOwner` and handles the logic for locking tokens.

However, the transfer of ERC tokens is done using [token.transferFrom()](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L376). 
This approach works well on most chains (Ethereum, Optimism, Polygon, BSC, ...) that use the [standard WETH9 contract](https://github.com/gnosis/canonical-weth/blob/master/contracts/WETH9.sol#L65C6-L68C10).
This contract handles the case where `src == msg.sender`:

```solidity
WETH9.sol:
        if (src != msg.sender && allowance[src][msg.sender] != uint(- 1)) {
            require(allowance[src][msg.sender] >= wad);
            allowance[src][msg.sender] -= wad;
        }
```

The problem is that the `WETH` implementation on `Blast` uses [a different contract](https://blastscan.io/address/0x4300000000000000000000000000000000000004#code), and does not have this `src == msg.sender` handling.

## Impact

The transfer incompatibility issue in the [LockManager.sol](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol) contract prevents users from locking their `WETH` tokens on `Blast`.

## Recommended Mitigation Steps

To address this issue, it's recommended to modify the `LockManager.sol` file as follows:

```diff
src/managers/LockManager.sol:
374:    if (_tokenContract != address(0)) {
375:         IERC20 token = IERC20(_tokenContract);
-376:        token.transferFrom(_tokenOwner, address(this), _quantity);
+376:        token.transfer(address(this), _quantity);
377:    }
```

> If the protocol team plans to implement different tokens on other chains, keep in mind that the same issue exists with [Wrapped Arbitrum](https://arbiscan.io/address/0x8b194beae1d3e0788a1a35173978001acdfba668#code) and  [Wrapped Fantom](https://ftmscan.com/token/0x21be370d5312f44cb42ce377bc9b8a0cef1a4c83#code).
