# Vulnerability details

## Impact
USDB/WETH are the native tokens of the blast chain that are being used in munchables.
Both USDB and WETH yield modes are AUTOMATIC by default, due to which the user's locked balance will keep increasing bit by bit due to this yield.
The problem lies in the [#L330](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L330C29-L330C38)due to this auto accruing yield not configured properly user potentially won't be able to lock funds.
Even if somehow the user is able to lock funds(by locking them prior to the auto-rebasing) he might lose on [number of NFTs](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L364)as the `quantity` data will be stale.
## Proof of Concept
**Scenario-1: User not able to lock funds**
The user tries to lock 100 WETH at 00:00 AM.
- Txn gets reverted due to an issue lying in [#L330](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L330C29-L330C38)
- Issue arises due to change in user's balance:
- After auto-rebasing **User's Balance would be:100.010958904**
>*The above calculation comes from [here](https://docs.blast.io/building/guides/eth-yield)*

**Scenario-2: User getting less number of NFTs**
> According to the docs of [blast eth-yieldhttps://docs.blast.io/building/guides/eth-yield)
a contract gets a 4% yield on the contract's balance if the duration is one year.
> *Due to [quantity](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L344) taking only the sending amount in the accounting.
The number of NFTs that the user will be getting will be low even if the user locks his tokens for a year. It will be according to the old locked balance that he locked one year ago, even though the amount of tokens will be 4% more than the original.*

- User locked 100 weth on 1 Jan 2024 for 365 days.
- The number of Nfts that the user will get during the lockdrop will be according to the 100 WETH that is being used in the accounting process instead of using the user's locked balance.


## Tools Used
Manual review
## Recommended Mitigation Steps
Configure the auto-rebasing of USDB/WETH and decide, do you want it or not.
If yes, change the accounting calculation and make them intake user's locked balance for NFTs distribution.
If no, configure it.
