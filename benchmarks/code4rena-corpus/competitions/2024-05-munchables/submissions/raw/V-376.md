# Vulnerability details

## Impact
When setting new lock duration, `setLockDuration` does not check the lower limit of the duration, thus the new duration can be smaller than the minimum duration (i.e. `lockdrop.minLockDuration`), breaking the minimum lock duration limitation of the contract.

## Proof of Concept
According to function `_lock`, the lock duration should be greater than `lockdrop.minLockDuration` and less than `configStorage.getUint(StorageKey.MaxLockDuration)` (L350, L357), otherwise the lock tx reverts.

## Recommended Mitigation Steps
Revert the tx if `_duration < lockdrop.minLockDuration` at the begining of function `setLockDuration`.
```solidity
    function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration))
            revert MaximumLockDurationError();
+       if (_duration < lockdrop.minLockDuration)
+           revert MinimumLockDurationError();
```
