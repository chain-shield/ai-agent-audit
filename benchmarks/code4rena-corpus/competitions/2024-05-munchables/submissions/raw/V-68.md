# Vulnerability details

### Title

Use of Deprecated `transfer` Method in `unlock` Function Leads to Potential Ether Transfer Failures

### Severity

Medium

## Impact

The `LockManager` contract uses Solidity’s `transfer()` method to send Ether to users who want to unlock their tokens. This approach has significant shortcomings, particularly when the recipient is a smart contract. Specifically, the `transfer()` method can fail if the recipient smart contract:

1. Does not implement a payable fallback function.
2. Implements a payable fallback function that consumes more than 2300 gas units.
3. Implements a payable fallback function consuming less than 2300 gas units but is called through a proxy that raises the call’s gas usage above 2300.

These limitations can render Ether transfers impossible, causing failures in the contract's functionality.

## Proof of Concept

In the `LockManager` contract, the `unlock` function contains the following code:

```solidity
function unlock(
  address _tokenContract,
  uint256 _quantity
) external notPaused nonReentrant {
  LockedToken storage lockedToken = lockedTokens[msg.sender][_tokenContract];
  if (lockedToken.quantity < _quantity) revert InsufficientLockAmountError();
  if (lockedToken.unlockTime > uint32(block.timestamp))
    revert TokenStillLockedError();

  // force harvest to make sure that they get the schnibbles that they are entitled to
  accountManager.forceHarvest(msg.sender);

  lockedToken.quantity -= _quantity;

  // send token
  if (_tokenContract == address(0)) {
    payable(msg.sender).transfer(_quantity); // @audit use call instead of transfer.
  } else {
    IERC20 token = IERC20(_tokenContract);
    token.transfer(msg.sender, _quantity);
  }

  emit Unlocked(msg.sender, _tokenContract, _quantity);
}
```

The use of `transfer()` in the above code can fail under the circumstances mentioned.

These issues with `transfer()` can be further referenced via:

- [Consensys Diligence's article](https://consensys.net/diligence/blog/2019/09/stop-using-soliditys-transfer-now/)
- [OpenZeppelin's blog](https://blog.openzeppelin.com/secure-ether-transfers/)

## Recommended Mitigation Steps

Use `call` with its returned boolean checked in combination with a reentrancy guard to safely send Ether. Here’s an example refactoring of the `unlock` function:

```solidity
if (_tokenContract == address(0)) {
    (bool success, ) = payable(msg.sender).call{value: _quantity}('');
    require(success, "Transfer of ETH Failed");
} else {
    IERC20 token = IERC20(_tokenContract);
    token.transfer(msg.sender, _quantity);
}
```

Alternatively, use `Address.sendValue()` available in OpenZeppelin’s Address library to transfer Ether without being limited to 2300 gas units:

```solidity
if (_tokenContract == address(0)) {
    Address.sendValue(payable(msg.sender), _quantity);
} else {
    IERC20 token = IERC20(_tokenContract);
    token.transfer(msg.sender, _quantity);
}
```

Additionally, to prevent reentrancy attacks, follow the “Checks-Effects-Interactions” pattern and/or use OpenZeppelin’s `ReentrancyGuard` contract.
