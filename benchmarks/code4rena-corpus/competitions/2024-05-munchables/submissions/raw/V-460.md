# Vulnerability details

## Impact

Users cannot set the token `lockDuration < minLockDuration` (30 days) if they directly call the `lock()` function or set the `lockDuration == 0`, this is not in accordance with the protocol provisions which free users to set the lock duration according to their needs

## Proof of Concept

```solidity
        if (_lockDuration == 0) {
            _lockDuration = lockdrop.minLockDuration;
        }
```

It can be seen from the line of code above, if the user does not set the lock duration at the beginning by calling the `setLockDuration()` function or enter `0` as the value of the lock duration, then the `lockDuration = lockdrop.minLockDuration` which has a value of 30 days. 

`lockdrop.minLockDuration` should only be used when there is a `lockdrop` event

Scenario 

1. Bob does not set the duration of the lock or sets the `lockDuration == 0` with the `setLockDuration()` function
2. Then he call `lock()` function
3. Because `lockDuration == 0`, the value is set to `lockDuration = lockdrop.minLockDuration`, which is 30 days

```solidity
        lockedToken.unlockTime =
            uint32(block.timestamp) +
            uint32(_lockDuration);
```

4. Then the value of `lockedToken.unlockTime` is updated
5. That way, the user cannot set the token lock duration less than that value in the `setLockDuration()` function because there is a check 

```solidity
                if (
                    uint32(block.timestamp) + uint32(_duration) <
                    lockedTokens[msg.sender][tokenContract].unlockTime
                ) {
                    revert LockDurationReducedError();
```

In this way, users who accidentally set `lockDuration == 0` or who don't set it from the start will be the subject of a `lockdrop` event which may not take place and the user will not be able to set the lock token duration as desired.

## Tools Used

Manual review

## Recommended Mitigation Steps

Consider adding check `lockdrop` event ongoing or not, if yes use the code as above, otherwise revert if `lockDuration` not set
