# Vulnerability details

## Description
While having role-based access control mechanisms like in the LockManager contract is generally a good practice. But in this case, any address with one of the specified roles can propose USD price without any other require or access check. This could lead to unauthorized changes in USD price proposals.

## Impact
- Unauthorized addresses with the specified roles can propose, approve, or disapprove USD price updates, leading to potential manipulation of the price data.

## Proof of Concept
- A malicious user gains access to an address with one of the specified roles (`Role.PriceFeed_1`) etc.
- The attacker calls the `proposeUSDPrice`, `approveUSDPrice`, or `disapproveUSDPrice` function to propose, approve, or disapprove a USD price update when it shouldn't have access.
[LockManager: 142-172](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L142-L174)

## Tools Used
Manual Code Review

## Recommended Mitigation Steps
Add additional access control checks to ensure that only authorized addresses can propose, approve, or disapprove USD price. This can be achieved by implementing a more robust access control mechanism such as requiring specific addresses to be whitelisted or requiring multi-signature approvals.
