# Vulnerability details

## Impact
The admin could frontrun `proposeUSDPrice` to adjust the thresholds to favor or disfavor certain proposals allowing them to manipulate the voting process.
The USD prices for tokens can be executed without a genuine majority vote from PriceFeed users.

## Proof of Concept

The approval and disapproval thresholds (APPROVE_THRESHOLD and DISAPPROVE_THRESHOLD) are currently hardcoded in the system (set to 3 for both).
```
    uint8 APPROVE_THRESHOLD = 3;
    /// @notice Threshold for removing a proposal
    uint8 DISAPPROVE_THRESHOLD = 3;
```
The contract contains a function `setUSDThresholds` that enables the contract admin to adjust the thresholds for approving and disapproving USD price change proposals

```
    function setUSDThresholds(
        uint8 _approve,
        uint8 _disapprove
    ) external onlyAdmin {
```


The admin can  frontrun `proposeUSDPrice` to temporarily lower the approval threshold and potentially raise the disapproval threshold making it easier for the proposal to pass through the voting process and vice versa.


## Tools Used
Manual analysis

## Recommended Mitigation Steps
Implement multi-signature authorization for modifying voting thresholds requiring approval from multiple trusted parties to prevent unilateral actions by any single admin.
It should be behind a time-lock to allows actors to adjust to changes
