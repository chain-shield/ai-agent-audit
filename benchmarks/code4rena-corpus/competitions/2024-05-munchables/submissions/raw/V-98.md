# Vulnerability details

## Impact
user can unlocked token in the same unlock time due to the operator used to check against current block.timestamp.

## Proof of Concept
unlock function is used to unlock some or whole quantity of the locked token and transfer it to the user, the issue in this function is that the locked tokens can be unlocked at the same exact unlocked time that shouldn't be the case.
Locked token can only be unlocked after successfully passing the unlock time.
```solidity
LockManager.sol#L410
if (lockedToken.unlockTime > uint32(block.timestamp))
            revert TokenStillLockedError();
```
AS we can see above if statement only checks if the unlock time is greater then  block.timestamp, for example suppose a user wants to unlock their locked token and lets assume the unlock time is 1716609517 and the block.timestamp is also 1716609517, the if statement will not revert instead it will unlock the token and transferred it to the user that should not be the case it should make a revert when current and unlock timestamp are same because unlock time not passed its in the range.

## Tools Used
Manual

## Recommended Mitigation Steps
Make the required changes as,
```diff
-    if (lockedToken.unlockTime > uint32(block.timestamp))
            revert TokenStillLockedError();
+    if (lockedToken.unlockTime >= uint32(block.timestamp))
            revert TokenStillLockedError();
```
