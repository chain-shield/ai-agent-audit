# Vulnerability details

## Impact
`LockManager` allows users to lock tokens in return for `rewards`. They can unlock their tokens once their respective `unlockTime` has passed.

When users unlock their tokens, `AccountManager::forceHarvest()` is called, which gives users rewards based off the `USD` value of their locked tokens.

This `USD` value can be changed at anytime by a `proposer` with `Pricefeed` role via a call to `proposeUSDPrice()`.

If a minimum number of `Pricefeed` roles approve the new `USD` value, that value with then be updated.

This leads to a step-wise jump vulnerability, where if the `USD` value suddenly changes then users will get rewards based off that `USD` value for the entire time they locked their tokens.

For example, if a user locks `5000 USD` of tokens for `10 days`, but then the value changes to `1000 USD` for the next `5 days` via `proposeUSDPrice()`, the user will get `1000 USD` of rewards for the entire `15 days`, when they should get `5000 USD` for the first `10 days` and `1000` for `5 days`. The user will suffer in this case.

## Proof of Concept
When users unlock their tokens, the following call is made

[LockManager.sol#L414](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L414)
```javascript
    // force harvest to make sure that they get the schnibbles that they are entitled to
    accountManager.forceHarvest(msg.sender);
```

These are rewards earned based off the user's `locked weighted value`

[AccountManager.sol#L366](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/AccountManager.sol#L366)
```javascript
uint256 weightedValue = lockManager.getLockedWeightedValue(_caller);
```

The `locked weighted value` is based off the user's locked `quantity` and the respective `usdPrice` for the token.

[LockManager.sol#L476-L482](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L476-L482)
```javascript
lockedWeighted += (deltaDecimal * lockedTokens[_player][configuredTokenContracts[i]].quantity * configuredTokens[configuredTokenContracts[i]] .usdPrice) / 1e18;
```

The `usdPrice` for tokens can change via [proposeUSDPrice()](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L142).

If enough approvals are received for the new proposed `usdPrice`, it is officially updated.

[LockManager.sol#L202-L204](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L202-L204)
```javascript
if (usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD) {
            _execUSDPriceUpdate();
    }
```

As explained in the example from above, if the USD value suddenly drops, the user will receive rewards based off that USD amount for the entire time they locked their tokens.

Conversely, if the token value goes up, they will receive rewards based off the new USD value for the entire time locked.

The correct solution is to give users the respective reward based off what the USD value was at that time (i.e, if USD value is 5000 for first 10 days and 1000 for next 5 days, give users reward for 5000 USD for first 10 days and 1000 for 5 days, rather than 1000 USD for the full 15 days).

## Tools Used
Manual Review.

## Recommended Mitigation Steps
Prior to updating the `USD price` of the tokens, update all user rewards, so they can still receive rewards based off what the `USD price` was at that point in time.
