# Vulnerability details

## Impact
I'll take `LockManager.approveUSDPrice` as an example to demonstrate the issue.
In [LockManager.approveUSDPrice](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L177-L207), the function only checks if the price equals to [usdUpdateProposal.proposedPrice](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L196C13-L196C44), but __doesn't check `usdUpdateProposal.contracts`__.

## Proof of Concept
1. WETH and RETH are added into `configuredTokens`, WETH's price is 3800$ and RETH is 4000$
2. contract which has `Role.PriceFeed_1` calls `proposeUSDPrice` to update WETH's price as 3800$
3. contract which has `Role.PriceFeed_3` calls `approveUSDPrice` to approve the proposal
4. but before step3's tx, contract which has `Role.PriceFeed_2` calls `proposeUSDPrice` to update RETH's price 3800$

In such case, Role.PriceFeed_3 will approve Role.PriceFeed_2'tx, which is not correct
