# Vulnerability details

## Impact

The number of NFTs are limited to `type(uint16).max` which is basically 65535. This limit is too small when the cost of NFT is significantly low.
Protocol won't allow user to lock enough tokens (parameter `quantity`) - because of the numberNFTs calculation.

## Proof of Concept


[File: LockManager.sol](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L363-L366)
```
                remainder = quantity % configuredToken.nftCost;
                numberNFTs = (quantity - remainder) / configuredToken.nftCost;

                if (numberNFTs > type(uint16).max) revert TooManyNFTsError();
```

The number of NFTs is calculated as: 

```
(quantity - remainder) / configuredToken.nftCost
```

When `nftCost` is significantly small (e.g. `nftCost = 1`), then `numberNFTs = quantity`.

Because of the revert at line 366, this implies, that user won't be able to lock more than `65535`.


Function `_lock()` is defined as below:

```
    function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {
```

Since `_quantity` is `uint256`, we assume that it should be possible to lock at least `type(uint256).max` tokens. However, because of the restriction at line 366, the max amount of quantity we can lock is just `type(uint16).max`. This limit is unreasonable and should be increased.

## Tools Used

Manual code review


## Recommended Mitigation Steps

Increase the number of NFTs. Change:

```
if (numberNFTs > type(uint16).max) revert TooManyNFTsError();
```

to:

```
if (numberNFTs > type(uint256).max) revert TooManyNFTsError();
```
