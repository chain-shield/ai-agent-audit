# Vulnerability details

## Impact
The vulnerability in the configureLockdrop() function allows the admin to set lockdrop.minLockDuration without proper validation. This missing validation can result in minLockDuration being set to 0 or an excessively large value. Such misconfigurations can severely impact the locking mechanism in the following ways:

```
if (_lockDuration == 0) {
    _lockDuration = lockdrop.minLockDuration;
        }
```

1.Lock Duration Too Short (0): If lockdrop.minLockDuration is set to 0, the _lock function's internal check for a 0 _lockDuration will result in the _lockDuration being set to lockdrop.minLockDuration, which is also 0. This renders the lock functionality meaningless because the intended minimum lock duration is bypassed, allowing immediate unlocking.

2.Lock Duration Excessively Long: If lockdrop.minLockDuration is set to an value bigger than ```uint32(configStorage.getUint(StorageKey.MaxLockDuration))```, any attempt to lock tokens would result in revert.

```
if (
             _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```


## PoC
Case 1
1.lockdrop.minLockDuration is set to 0 by mistake or maliciously.
2.playerSettings[_lockRecipient].lockDuration is 0.
3._lockDuration will be set to 0.

User will not be able to lock, because lock period will be 0.

Case 2
1.lockdrop.minLockDuration is set to bigger than uint32(configStorage.getUint(StorageKey.MaxLockDuration)) by mistake or maliciously.
2.playerSettings[_lockRecipient].lockDuration is 0.
3._lockDuration will be set to bigger than uint32(configStorage.getUint(StorageKey.MaxLockDuration))
 
_lock() will revert because of:
```
if (
            _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```
Case 3

1.lockdrop.minLockDuration is set to a value greater than uint32(configStorage.getUint(StorageKey.MaxLockDuration)) either by mistake or maliciously.
2.If a player sets their lock duration (playerSettings[_lockRecipient].lockDuration) to 15 for example.
This value is considered as a validated because: 
```
 function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration))
            revert MaximumLockDurationError();
```
The lock operation will revert because the player's lock duration (15) is less than the excessively large lockdrop.minLockDuration.

```
if (
            _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```

## Recommended Mitigation Steps
To mitigate this vulnerability, add validation checks in the configureLockdrop() function to ensure that minLockDuration is within a reasonable and expected range. For instance, setting a minimum and maximum threshold for minLockDuration can prevent it from being set to an inappropriate value.
