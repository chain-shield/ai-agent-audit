# Vulnerability details

## Impact
To call `setLockDuration` successfully, the `if check` in [https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L256-L261] has to be passed.

But [lockedTokens[msg.sender][tokenContract].unlockTime](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L258C21-L258C71) can be updated by [_unlock](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L382-L384), and `_unlock` can be called by `lockOnBehalf` and `lock`.

So when after a normal calls `lock` or a malicious user calls `lockOnBehalf`, the value of `_duration` will restricted. Only the value that pass the [if condition](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L256-L261) can be set.

## Proof of Concept
Supposed Alice(the normal user) hasn't locked any assets in the contract, she call call `setLockDuration` with __any value__ as `_duration` as long as the value is not greater than `configStorage.getUint(StorageKey.MaxLockDuration)` in [LockManager.sol#L246-L247](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L246-L247).

But before Alice's call, Bob(the malicious user) calls `lockOnBehalf` with __1 wei__ as _quantity, and Alice's address as `_onBehalfOf`.

Then in [LockManager.sol#L382-L384](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L382-L384), `lockedToken.unlockTime` will be set.

So when Alice's tx is executed, only the `_duration` that can pass the [if check](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L256-L261) can be updated.

__Besides Bob can be DOSed by other user, he might be DOSed by himself after calling `lock`__
