# Vulnerability details

In the setLockDuration function, when the user updates the lock duration, the new unlockTime is required to be longer than the original unlockTime, so for https://github.com/code-423n4/2024-05-munchables/blob/main/src/ The code of managers/LockManager.sol#L257 requires that the current time plus _duration be greater than the original unlockTime, which means that the new unlockTime is calculated based on the current time. But when the code at https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L265 updates unlockTime, it updates according to lastLockTime, and lastLockTime is the user The time the lock was created. So there is obviously an error here, because block.timestamp is greater than lastLockTime, then the user can update unlockTime with a smaller _duration, causing the lock to be released early.
