# Vulnerability details

## Impact

According to the documentation, users aim to acquire as many Munchables (NFTs) as possible to earn MUNCH points. An attacker exploiting this vulnerability can obtain more NFTs with less money by locking and unlocking their assets within a very short period.

## Proof of Concept

**Attack Scenario:**
1. The attacker sets their `lockDuration` to 1 second.
2. The attacker locks their assets just enough to receive an NFT (e.g., if the NFT costs 1000 USD, they lock 1000 USD).
3. The attacker then unlocks their assets immediately.
4. The attacker repeats steps 2 and 3 as many times as possible.

By the end of the day, the attacker can accumulate NFTs worth significantly more than 1000 USD in a much shorter time compared to other users.

## Tools Used

Manual Review

## Recommended Mitigation Steps

This vulnerability exists because the `_lock` function only checks if `lockDuration` is equal to 0. It should instead verify if the `lockDuration` is less than `minLockDuration`.

Suggested code modification:

```diff
-if (_lockDuration == 0) {
+if (_lockDuration < lockdrop.minLockDuration) {
    _lockDuration = lockdrop.minLockDuration;
}
```

By making this change, attackers will be forced to set their `lockDuration` to at least the `lockdrop.minLockDuration`, ensuring the protocol's security.
