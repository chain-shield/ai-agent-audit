# Vulnerability details

## Impact
The value of _duration is used to update the lockDuration of a player.
Before being pushed to the playerSettings, it is checked that it is less than the MaxLockDuration.
The comparison is done in uint256 for _duration and StorageKey.MaxLockDuration which is set in uint32 but upcast to uint256 via configStorage.getUnit().

_duration is then downcast to uint32 which creates the issue with the following scenarios possible as a result.

Scenario 1: Given a user passed the MaxLockDuration check and has no existing locked tokens, the execution of setLockDuration updates their settings and ends. If  the downcasted _duration value is 0 or less than lockdrop.minLockDuration it will be set to minLockDuration which may not be the intention of the user. Limiting their return for locking tokens

Scenario 2: Given a user passed the MaxLockDuration check and has locked tokens, the downcasted _duration value can create a DOS where the block.timestamp + _duration is less than the current unlockTime which was may not be the intention of the user
