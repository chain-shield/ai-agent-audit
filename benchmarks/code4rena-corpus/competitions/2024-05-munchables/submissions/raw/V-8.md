# Vulnerability details

## Impact
In Blast, `WETH` and `USDB` accounts have Automatic yield by default for both EOAs and smart contracts. The `LockManager` will use `WETH` and `USDB` as locked token. When users lock their tokens in `LockManager` contract, the `LockManager` contract will automatically receive `WETH` and `USDB` yields. When users unlock their tokens, these yields will not be sent to users, they will be locked in the `LockManager` contract forever.

## Proof of Concept
As per the doc of blast(https://docs.blast.io/building/guides/eth-yield), Smart contract accounts have three Yield Modes for their rebasing mode:
- Void (DEFAULT): ETH balance never changes; no yield is earned
- Automatic: native ETH balance rebases (increasing only)
- Claimable: ETH balance never changes; yield accumulates separately

For `WETH` and `USDB`, the Automatic yield is the default mode.(https://docs.blast.io/building/guides/weth-yield)

`Munchables` says that it will use `WETH` and `USDB` as locked token.

Users can call `lock` function to lock `USDB` and `WETH`. It will transfer tokens to the current contract and record the quantity:
```solidity
       // Transfer erc tokens
        if (_tokenContract != address(0)) {
            IERC20 token = IERC20(_tokenContract);
            token.transferFrom(_tokenOwner, address(this), _quantity);
        }

        lockedToken.remainder = remainder;
        lockedToken.quantity += _quantity;
        lockedToken.lastLockTime = uint32(block.timestamp);
        lockedToken.unlockTime =
            uint32(block.timestamp) +
            uint32(_lockDuration);
```
This `quantity` will not be changed when the `LockManager` receives yields from Blast.

When users call `unlock` function, it will only send `quantity` tokens to the users and ignore the yields:
```solidity
function unlock(
        address _tokenContract,
        uint256 _quantity
    ) external notPaused nonReentrant {
        LockedToken storage lockedToken = lockedTokens[msg.sender][
            _tokenContract
        ];
        if (lockedToken.quantity < _quantity)
            revert InsufficientLockAmountError();
        if (lockedToken.unlockTime > uint32(block.timestamp))
            revert TokenStillLockedError();

        // force harvest to make sure that they get the schnibbles that they are entitled to
        accountManager.forceHarvest(msg.sender);

        lockedToken.quantity -= _quantity;

        // send token
        if (_tokenContract == address(0)) {
            payable(msg.sender).transfer(_quantity);
        } else {
            IERC20 token = IERC20(_tokenContract);
            token.transfer(msg.sender, _quantity);
        }

        emit Unlocked(msg.sender, _tokenContract, _quantity);
    }
```
As a result, all yields will be locked in the `LockManager` contract.

## Recommended Mitigation Steps

or providing functions for users to claim their yields.
