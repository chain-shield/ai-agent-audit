# Vulnerability details

## Impact
Executing the USD price update upon reaching the `APPROVE_THRESHOLD` creates a scenario where dissenting votes submitted afterward are ignored and unable to reject the proposal.

As a result, it allows bypassing the disapproval process by quickly submitting approval transactions, **leading to the establishment of a price that would have otherwise been rejected.**

This manipulation pathway works for all configurations where:
1. `APPROVE_THRESHOLD + DISAPPROVE_THRESHOLD <= N (PriceFeed wallets)`
2. `APPROVE_THRESHOLD > 0`
3. `DISAPPROVE_THRESHOLD > 0`


**In the default configuration of LockManager, this manipulation does not work**: `APPROVE_THRESHOLD = 3, DISAPPROVE_THRESHOLD = 3, and addresses with PriceFeed_n roles <= 5
`

Examples of cases (numbers are the order of transactions):
```js
N = 5, APPROVE_THRESHOLD = 3, DISAPPROVE_THRESHOLD = 2
1. Yes
2. Yes
3. Yes -> Ignore the following votes, as the installation has been authorized
4. No - ignored
5. No - ignored

Although 2 No's would be enough to remove this offer, the offer is still accepted due to the fast price setting when APPROVE_THRESHOLD is reached

N = 2, APPROVE_THRESHOLD = 1, DISAPPROVE_THRESOLD = 1
1. Yes -> Ignore the following votes
2. No - ignored
```

Although these proposals should have been rejected and withdrawn according to the voting results, they were nevertheless adopted, reaching the required number of votes in favor faster than the number of transactions for votes against

## Proof of Concept

[_execUSDPriceUpdate()](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L202-L204) upon `usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD`

### Test
Path for create test file: tests/maangers/LockManager/issue.test.ts
```ts
import assert from "node:assert/strict";
import { before, describe, it } from "node:test";
import { zeroAddress } from "viem";
import { DeployedContractsType } from "../../../deployments/actions/deploy-contracts";
import { Role } from "../../../deployments/utils/config-consts";
import { assertContractFunctionRevertedError } from "../../utils/asserters";
import { getTestContracts, getTestRoleAddresses } from "../../utils/contracts";

describe("Quick executing `_execUSDPriceUpdate()` upon reaching the `APPROVE_THRESHOLD` prevents accumulating sufficient disapproval votes to reject the proposal", () => {
  let alice: `0x${string}`;
  let priceFeed1: `0x${string}`;
  let priceFeed2: `0x${string}`;
  let priceFeed3: `0x${string}`;
  let testContracts: DeployedContractsType;

  before(async () => {
    testContracts = await getTestContracts();
    const testRoleAddresses = await getTestRoleAddresses();
    [alice] = testRoleAddresses.users;
    priceFeed1 = testRoleAddresses[Role.PriceFeed_1];
    priceFeed2 = testRoleAddresses[Role.PriceFeed_2];
    priceFeed3 = testRoleAddresses[Role.PriceFeed_3];
  });

  it("APPROVE_THRESHOLD: 2, DISAPPROVE_THRESHOLD: 1", async () => {
    const price = 1337n;
    await testContracts.lockManager.contract.write.setUSDThresholds([2, 1]);
    // priceFeed1 create proposol and approve
    await testContracts.lockManager.contract.write.proposeUSDPrice([price, [zeroAddress]], {
      account: priceFeed1,
    });
    // priceFeed2 approve for proposal, proposal executed
    await testContracts.lockManager.contract.write.approveUSDPrice([price], {
      account: priceFeed2,
    });
    // reverted because proposal already executed without waiting for the votes
    await assert.rejects(
      testContracts.lockManager.contract.simulate.disapproveUSDPrice([price], {
        account: priceFeed3,
      }),
      (err: Error) => assertContractFunctionRevertedError(err, "NoProposalError")
    );
  });
});

```

## Recommended Mitigation Steps
One of the following options can mitigate this issue:
1. **Introduce a Voting Period**: Implement a mandatory voting period to neutralize the impact of transaction order on the final decision.
2. **Add Explicit Conditions**: Ensure configurations where APPROVE_THRESHOLD + DISAPPROVE_THRESHOLD <= n are not possible.de in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.
