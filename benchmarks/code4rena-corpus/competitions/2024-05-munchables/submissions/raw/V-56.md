# Vulnerability details

## Impact
Users may be attacked and unable to unlock assets.

## Proof of Concept
Anyone can call the [lockOnBehalf function](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L275C14-L275C26) to create a lock for [someone else](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L278C17-L278C28). This [will extend the lockRecipient lock time](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L382-L384). As long as the attacker repeatedly locks a user for a long time, [the user will not be able to withdraw his assets](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L410-L411). The attacker can set [the lock amount](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L277C17-L277C26) to 0/1wei, which makes the attack almost cost-free.

## Tools Used
manual
## Recommended Mitigation Steps
It is recommended to set a minimum number of locks, or only allow migrationManager to call the lockOnBehalf function.
