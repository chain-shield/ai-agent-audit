# Vulnerability details

## Impact

The `getLockedWeightValue` function in the `LockManager` contract assumes that it can handle tokens with decimals greater than 18 according to the erc20 token behaviors in scope by C4. This assumption is problematic because it can lead to overflow or underflow errors when performing calculations involving these token decimals. Specifically, when calculating `deltaDecimal` as shown below, if `configuredTokens[configuredTokenContracts[i]].decimals` is greater than 18, it will result in a negative exponent, causing an underflow.

## Proof of Concept

In the `LockManager` contract, the `getLockedWeightValue` function includes the following code:

```solidity
uint256 deltaDecimal = 10 ** (18 - configuredTokens[configuredTokenContracts[i]].decimals);
```

If `configuredTokens[configuredTokenContracts[i]].decimals` is greater than 18, the exponent `(18 - configuredTokens[configuredTokenContracts[i]].decimals)` becomes negative, leading to an underflow error. For instance, if the token has 20 decimals:

```solidity
uint256 deltaDecimal = 10 ** (18 - 20); // Equivalent to 10 ** (-2), which causes an underflow
```

## Recommended Mitigation Steps

To prevent overflow or underflow errors, add a check to ensure that the token decimals are within a valid range (0 to 18). If the token has more than 18 decimals, handle the situation appropriately, such as by reverting the transaction or scaling the values differently.

Here’s how you can refactor the `getLockedWeightValue` function:

```solidity
function getLockedWeightValue(
  address[] memory configuredTokenContracts
) public view returns (uint256) {
  uint256 totalWeightValue = 0;
  for (uint256 i = 0; i < configuredTokenContracts.length; i++) {
    uint256 decimals = configuredTokens[configuredTokenContracts[i]].decimals;
    require(decimals <= 18, "Token decimals exceed 18");

    uint256 deltaDecimal = 10 ** (18 - decimals);
    uint256 weightValue = lockedTokens[msg.sender][configuredTokenContracts[i]]
      .quantity * deltaDecimal;

    totalWeightValue += weightValue;
  }
  return totalWeightValue;
}
```

By including a check for decimals greater than 18, you ensure that the contract handles token decimals correctly, avoiding potential overflow or underflow errors. This mitigation maintains the integrity of the `getLockedWeightValue` function and ensures accurate calculations.
