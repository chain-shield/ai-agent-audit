# Vulnerability details

## Impact
The `proposeUSDPrice()` function in the contract automatically records the proposer's approval and increments the `approval count` upon proposal creation. This behavior is inconsistent with the `approveUSDPrice()` function, which explicitly prevents the `proposer` from approving their own `proposal`. The automatic initial approval can lead to misleading `approval counts`, and undermine the governance process.

## Proof of Concept
The [proposeUSDPrice()](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L170-L171) function automatically records the proposer's approval and increments the approval count upon proposal creation.

```solidity
        usdUpdateProposal.approvals[msg.sender] = _usdProposalId;
        usdUpdateProposal.approvalsCount++;
```
However, the [approveUSDPrice()](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L192-L193) function prevents the proposer from approving their own proposal, leading to inconsistent behavior.

```solidity
        if (usdUpdateProposal.proposer == msg.sender)
            revert ProposerCannotApproveError();
```
###### Misleading Approval Count: 
Automatically incrementing the [approval count](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L202-L204) upon proposal creation can mislead other approvers into thinking the proposal has more support than it actually does.

```solidity
        if (usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD) {
            _execUSDPriceUpdate();
        }
```

---> This could result in proposals being approved more easily, as the initial approval count is artificially inflated.
