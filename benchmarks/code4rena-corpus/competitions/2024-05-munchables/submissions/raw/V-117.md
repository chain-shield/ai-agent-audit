# Vulnerability details

## Impact
When a user locks tokens on behalf of another address. the lock duration defaults to the minimum lock duration in cases where the lock recipient has not set a duration

## Proof of Concept
The `_lock` function, responsible for locking tokens, retrieves the lock duration from the `playerSettings` mapping for the lock recipient address `(_lockRecipient)`. However, if the lock recipient has not set a lock duration. In such cases, the function defaults _lockDuration to the `minimum` lock duration `(lockdrop.minLockDuration)`. Consequently, tokens locked on behalf of others often end up with the default minimum lock duration.

 Users cannot specify custom lock durations for recipients when locking tokens on their behalf, potentially limiting flexibility in token locking strategies.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement functionality to allow users to set lock durations for addresses other than their own. This would enable users to specify custom lock durations for recipients,
