# Vulnerability details

The `proposeUSDPrice` may be vulnerable to reentrancy attacks due to the potential reordering of state changes. First checks if there's an ongoing proposal `usdUpdateProposal.proposer != address(0)`, and if not, proceeds to initialize a new proposal. However, between the initial check and the proposal initialization, there is a window of opportunity for an attacker to invoke external contracts that might re-enter this function and modify state variables before the proposal is initialized.

## Impact
An attacker exploiting this vulnerability could potentially manipulate the state of the contract in unintended ways, such as interfering with ongoing proposals or corrupting data related to USD price updates. This could lead to financial losses, disruptions in contract functionality, or manipulation of governance processes.

## Proof of Concept
```solidity
    function proposeUSDPrice(
        uint256 _price,
        address[] calldata _contracts
    )
        external
        onlyOneOfRoles(
            [
                Role.PriceFeed_1,
                Role.PriceFeed_2,
                Role.PriceFeed_3,
                Role.PriceFeed_4,
                Role.PriceFeed_5
            ]
        )
    {
        if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
        if (_contracts.length == 0) revert ProposalInvalidContractsError();
        if(_price == 0) revert ProposalInvalidPriceError();

        delete usdUpdateProposal;


        usdUpdateProposal.proposedDate = uint32(block.timestamp);
        usdUpdateProposal.proposer = msg.sender;
        usdUpdateProposal.proposedPrice = _price;
        usdUpdateProposal.contracts = _contracts;
        usdUpdateProposal.approvals[msg.sender] = ++_usdProposalId;
        usdUpdateProposal.approvalsCount++;

        emit ProposedUSDPrice(msg.sender, _price);
    }
```
