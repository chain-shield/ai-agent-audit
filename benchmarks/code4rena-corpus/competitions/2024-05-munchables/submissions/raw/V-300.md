# Vulnerability details

## Impact
The calculation of the `deltaDecimal` variable in the `getLockedWeightedValue` function

The line: [src/managers/LockManager.sol#L475-L475](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L473-L475)
```solidity
                uint256 deltaDecimal = 10 **
                    (18 -
                        configuredTokens[configuredTokenContracts[i]].decimals);
```
is intended to calculate the factor needed to adjust the token quantity based on the token's decimal places. However, this calculation is incorrect for tokens with more than 18 decimal places.

For example, if a token has 20 decimal places, the calculation would result in `10 ** (18 - 20) = 10 ** (-2) = 0.01`. This means that the token quantity would be divided by 100 instead of being multiplied by 100, leading to an incorrect weighted value.

## Proof of Concept
Let's assume there is a token with 20 decimal places, and the user has locked 1,000,000,000,000,000,000,000 units of that token (1 million tokens with 20 decimal places).

The intended calculation should be.
```solidity
deltaDecimal = 10 ** (20 - 18) = 100
lockedWeighted = (100 * 1,000,000,000,000,000,000,000 * usdPrice) / 1e18
```
However, with the current implementation, the calculation would be.
```solidity
deltaDecimal = 10 ** (18 - 20) = 0.01
lockedWeighted = (0.01 * 1,000,000,000,000,000,000,000 * usdPrice) / 1e18
```
As you can see, the `deltaDecimal` value is calculated incorrectly as `0.01` instead of `100`. This means that the token quantity is divided by 100 instead of being multiplied by 100, leading to an incorrect weighted value.

The impact of this issue is that the `getLockedWeightedValue` function will return an incorrect value for tokens with more than 18 decimal places. This incorrect value could potentially be used in other parts of the system, leading to incorrect calculations or decisions based on the weighted value.

For example, if the weighted value is used to determine the user's eligibility for certain features or rewards, users with tokens having more than 18 decimal places may be incorrectly excluded or included due to the miscalculation.

**To illustrate the concept further, here's how the calculation should be performed correctly:**
```solidity
function getLockedWeightedValue(address _player) external view returns (uint256 _lockedWeightedValue) {
    uint256 lockedWeighted = 0;
    uint256 configuredTokensLength = configuredTokenContracts.length;
    for (uint256 i; i < configuredTokensLength; i++) {
        if (lockedTokens[_player][configuredTokenContracts[i]].quantity > 0 && configuredTokens[configuredTokenContracts[i]].active) {
            uint256 decimals = configuredTokens[configuredTokenContracts[i]].decimals;
            uint256 deltaDecimal = decimals >= 18 ? 10 ** (decimals - 18) : 10 ** (18 - decimals);
            lockedWeighted += (deltaDecimal * lockedTokens[_player][configuredTokenContracts[i]].quantity * configuredTokens[configuredTokenContracts[i]].usdPrice) / 1e18;
        }
    }

    _lockedWeightedValue = lockedWeighted;
}
```
The `deltaDecimal` calculation handles both cases: when the token has more than 18 decimal places and when it has fewer than 18 decimal places. This ensures that the weighted value calculation is accurate for all configured tokens, regardless of their decimal places.

## Recommended Mitigation Steps
The calculation should be modified to handle tokens with more than 18 decimal places correctly. One possible solution is to use the following calculation.
```solidity
uint256 deltaDecimal = configuredTokens[configuredTokenContracts[i]].decimals >= 18
    ? 10 ** (configuredTokens[configuredTokenContracts[i]].decimals - 18)
    : 10 ** (18 - configuredTokens[configuredTokenContracts[i]].decimals);
```
This calculation ensures that the `deltaDecimal` value is calculated correctly, regardless of whether the token has more or fewer than 18 decimal places.

Alternatively, could use the `10 ** uint256(18 - int256(configuredTokens[configuredTokenContracts[i]].decimals))` expression, which should also handle the case where the token has more than 18 decimal places correctly.
