# Vulnerability details

## Details
Each configuredToken has a `nftCost` field that determines the price of an unrevealed NFT in that particular token. I won't get into the details of unrevealed NFTs, their rarity, and how they are minted, as they are out of scope for this audit. However, since `configuredTokens` might not be updated each time the price of the token changes, it creates an unfair market for players.
Consider this scenario:
- The price of ETH is $3,400.
- Alice deposits 1 ETH with `ETH.nftCost` set to 0.1 ETH per NFT ($340) and receives 10 unrevealed NFTs.
- Bob deposits $3,400 and also receives 10 unrevealed NFTs.
- After the end of the `LockDrop` event, the price of ETH rises to $5,000.
Both Alice and Bob received 10 NFTs. Alice spent $5,000 while Bob spent $3,400. Assuming that these unrevealed NFTs `might` have the same value in the market, Alice incurs a loss.

## Proof of Concept

`nftCost` is only updated in `configureToken` function:

    function configureToken(
        address _tokenContract,
        ConfiguredToken memory _tokenData
    ) external onlyAdmin {
        if (_tokenData.nftCost == 0) revert NFTCostInvalidError();
        if (configuredTokens[_tokenContract].nftCost == 0) {
            configuredTokenContracts.push(_tokenContract);
        }
        configuredTokens[_tokenContract] = _tokenData;
        emit TokenConfigured(_tokenContract, _tokenData);
    }


This means that there must be a mechanism for fetching the latest `nftCost` in that `configuredToken`. For example, if `nftCost` is 100 USD and the price of ETH changes during the `LockDrop` event, the nftCost in ETH must also be updated accordingly. this mechanism is not implemented in the codebase.
as we can see [here](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L363-L369), `nftCost` is used directly to calculate number of unrevealed NFTs.


## Impact
some players will receive same amount of NFTs as other players at a higher/lower price which creates an unfair market for players.

## Tools Used
- Manual review

## Recommended Mitigation Steps
I recommend fetching the nftCost for each configuredToken in USD value using an on-chain oracle.
