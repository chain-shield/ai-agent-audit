# Vulnerability details

## Vulnerability Detail
If there is no active LockDrop, the lockdrop.minLockDuration still has the minLockDuration from the last LockDrop. 
Users can set their lockDuration in the player settings to 0, then when using the lock() function, they will enter this if condition:

    if (_lockDuration == 0) {
    _lockDuration = lockdrop.minLockDuration;
    }


And if the lockdrop.minLockDuration is less than their current lockTime, this will reduce the lock time, as there is no check in lock() to make sure the new one is not shorter.

Docs state that "a user should not be able to reduce their lock time, which was previously set."

## Impact
It contradicts the docs, as it is stated that this should not be allowed. 

Also, being able to reduce lock times can lead to getting an unfair advantage and farming faster schnibbles, thus getting more chonk for your Munchable, thus receiving more Munch Points, and gaining more monetary rewards, as you will gain $Munch tokens.


## Recommendation
Add a check in _lock() function to make sure that the current playerSettings[_lockRecipient].lockDuration is less than the _lockDuration that is set.
