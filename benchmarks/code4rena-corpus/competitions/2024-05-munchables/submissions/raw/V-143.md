# Vulnerability details

## Impact
If a user owns enough NFTs and wants to increase his lock, his NFTs will cause an overflow on uint16

## Proof of Concept
When a user calls `lock()` during a Lockdrop event, all of his unused funds are taken in order to calculate `numberNFTs` and ensure that it is not more than what uint16 can handle. But the check is not enough because the number of his NFTs can overflow because of numerous lock increases and not one big lock.

Example:
If `numberNFTs` would overflow if the user deposits e.g. `quantity = 15000`. Alice is allowed to make 2 different deposits of `_quantity = 7500` and not get reverted but her NFTs would have actually overflowed. 

## Tools Used
Manual review

## Recommended Mitigation Steps
Add a check that a user's total NFTs do not exceed `type(uint16).max` not only the current deposit.
