# Vulnerability details

## Impact
The current Munchables smart contract lacks the ability to remove a token once it has been configured. if a malicious or incorrect token is configured it cannot be removed from the configured lists. Without a removal function, the admin cannot correct this mistake or deactivate the malicious token. In such cases the array keeps growing even though some malicious tokens can be removed from the array to have manageable array sizes and avoid unecessay reverts that could occur from large arrays.



## Proof of Concept

The function below allows the admin to configure tokens and set them to active or inactive but there is not possibility of removal of token completely from the list.

```javascript
function configureToken(
    address _tokenContract,
    ConfiguredToken memory _tokenData
) external onlyAdmin {
    if (_tokenData.nftCost == 0) revert NFTCostInvalidError();
    if (configuredTokens[_tokenContract].nftCost == 0) {
        // new token
        configuredTokenContracts.push(_tokenContract);
    }
    configuredTokens[_tokenContract] = _tokenData;

    emit TokenConfigured(_tokenContract, _tokenData);
}
```

Assuming a token can be used regardless of wether it is active or not, if a malicious token is added there should be a way to remove it from the list

```javascript
/// @notice Token supplied must be configured but can be inactive
    modifier onlyConfiguredToken(address _tokenContract) {
        if (configuredTokens[_tokenContract].nftCost == 0)
            revert TokenNotConfiguredError();
        _;
    }
```

the modifier above suggests that a token can be configured even if it is not active. if the configured token is malicious and is inactive that means setting the bool isActive to not active is not sufficiet enough. There should be a way to remove malicious tokens from the configurations if need be.

## Tools Used
Manual Review

## Recommended Mitigation Steps
Implement a `removeToken` function to allow admin to remove tokens from the configuration. This function should delete the token from both the configuredTokens mapping and the configuredTokenContracts array, ensuring complete removal.
