# Vulnerability details

In the `setUSDThresholds()` function, an Admin can update the `APPROVE_THRESHOLD` and `DISAPPROVE_THRESHOLD` storage values that determine the threshold after which a proposal is approved or disapproved.

Unfortunately, setting the `APPROVE_THRESHOLD` to 0 or 1 has no effect because the `proposeUSDPrice()` function does not check if the `APPROVE_THRESHOLD` is reached during its execution but does approve the proposal in the name of `msg.sender`.

Even though the `approvalsCount >= APPROVE_THRESHOLD` might be reached, there is still a need for another PriceFeed role to call `approveUSDPrice()`, resulting in a minimum of 2 approvals required for the proposal to pass.

## Impact

`APPROVE_THRESHOLD` has no desired effect when set to 0 or 1.

## Recommended Mitigation Steps

Either update `setUSDThresholds()` with an additional check ensuring that `APPROVE_THRESHOLD` is >= 2, or update the `proposeUSDPrice()` function to include a check that will execute `_execUSDPriceUpdate` if the `APPROVE_THRESHOLD` is reached.

### Option 1: Update `setUSDThresholds()` with a check

```diff
    function setUSDThresholds(
        uint8 _approve,
        uint8 _disapprove
    ) external onlyAdmin {
        if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
+       if (_approve < 2)
+           revert ApproveThresholdToLow(); 
        
        ...
    }
```

### Option 2: Update `proposeUSDPrice()` with a check

```diff
    function proposeUSDPrice(
        uint256 _price,
        address[] calldata _contracts
    )
        external
        onlyOneOfRoles(
            [
                Role.PriceFeed_1,
                Role.PriceFeed_2,
                Role.PriceFeed_3,
                Role.PriceFeed_4,
                Role.PriceFeed_5
            ]
        )
    {
        ...

        emit ProposedUSDPrice(msg.sender, _price);

+       if (usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD) {
+           _execUSDPriceUpdate();
+       }
    }
```
