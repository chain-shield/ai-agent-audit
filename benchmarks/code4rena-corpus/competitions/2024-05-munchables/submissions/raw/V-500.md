# Vulnerability details

The `lockdrop` contract allows users to lock their asset for a certain period of time while they receive NFTS and Bonuses for doing so. This is fine if users only interact with the UX but if users interact directly with the contract and they send their assets directly into the contract whether the `lockPeriod` is active or not the assets will be lost forever as there's no mechanism in place to retrieve assets sent directly into the contract. 
## Impact
Players who interact with smart contracts directly on the Blockchain might send assets directly into the `lockdrop` without calling the `lock` function as there's no mechanism to retrieve such deposits the assets will remain locked in the contract.

## Proof Of Concept
The required method to use the `lockdrop` is by calling the `lock` function in the contract 
https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L297
```solidity
   function lock(
        address _tokenContract,
        uint256 _quantity
    )
        external
        payable
        notPaused
        onlyActiveToken(_tokenContract)
        onlyConfiguredToken(_tokenContract)
        nonReentrant
    {
        _lock(_tokenContract, _quantity, msg.sender, msg.sender);
    }
```
This locks the assets accordingly.
However users can mistakenly or knowingly send assets into the contract, sending ETH will revert due to the `fallback` and `receive` reverting when such happens 
https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L89-L95
```solidity
fallback() external payable {
        revert LockManagerInvalidCallError();
    }

    receive() external payable {
        revert LockManagerRefuseETHError();
    }
```
But if users send ERC20  tokens the tokens remain locked as there's no way to recover them .
