# Vulnerability details

## Impact
This report identifies a vulnerability in the lockup functionality of the `lockedTokens` contract. The current implementation allows users to potentially reduce their previously set lockup duration. 
Based on the attack ideas given by the sponsor, a user should not be allowed to set the unlocktime below the previous time.
https://code4rena.com/audits/2024-05-munchables#top:~:text=and%20that%20people%20cannot%20reduce%20lockup%20times%20that%20are%20previously%20set.


## Proof of Concept

The code snippet responsible for lockup extension appears to have a flaw:

```solidity
if (uint32(block.timestamp) + uint32(_duration) < lockedTokens[msg.sender][tokenContract].unlockTime) {
  revert LockDurationReducedError();
}
```

This check compares the sum of the current timestamp and the new `_duration` with the existing `unlockTime`. It aims to prevent reducing the lockup period.

**Impact:**

However, the code doesn't consider the `lastLockTime`. Here's how an attacker could exploit this:

1. Set initial lockup duration (`_duration`) to a high value (e.g., 800 seconds).
2. The `unlockTime` gets set based on the current timestamp and `_duration`.
3. Later, the attacker calls the function again with a shorter `_duration`. The check passes because the sum of the current timestamp and the new `_duration` might be less than the existing `unlockTime`.
4. However, the actual lockup duration gets reduced because the `unlockTime` is updated based on the `lastLockTime` and the new `_duration`.


 for example 

let's say 
former duration is set at 1000 .
new duration is set at 800 .
200 seconds have passed.
at the current time stamp is 212000,
the former unlocktime is 212800, 
lastLockTime is 211800. 

 based on the above 

```solidity
if (uint32(block.timestamp) + uint32(_duration) < lockedTokens[msg.sender][tokenContract].unlockTime) {
  revert LockDurationReducedError();
}
```
212000+800 will pass. but  


```solidity

uint32 lastLockTime = lockedTokens[msg.sender][tokenContract]
                    .lastLockTime;
lockedTokens[msg.sender][tokenContract].unlockTime =
                    lastLockTime +
                    uint32(_duration);

```
 The new unlocktime = 211800+800=212600 this is lesser than the previous unlock time 212800.

## Recommended Mitigation Steps

- Replace the check with one that directly compares the new `_duration` with the difference between the current `unlockTime` and the `lastLockTime`:

```solidity
if (_duration < lockedTokens[msg.sender][tokenContract].unlockTime - uint32(lastLockTime)) {
  revert LockDurationReducedError();
}
```
or 
 Instead set unlock time based on the former check.
```solidity
lockedTokens[msg.sender][tokenContract].unlockTime =
                    uint32(block.timestamp) +
                    uint32(_duration);

```
