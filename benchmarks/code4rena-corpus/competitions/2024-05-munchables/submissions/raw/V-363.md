# Vulnerability details

## Impact
As stated from the protocol team in the contest page we should assume that they can add more ERC20 tokens in the future for use in `LockManager.sol` and that the ERC20 tokens can be fee on transfer. However, the protocol does not handle fee-on-transfer tokens correctly which will cause internal accounting issues and ultimately the protocol will lose funds. 

## Proof of Concept
The problem is that the `lock()` function does not account for ERC20 tokens that have fee on transfer. So let's say the user sends 20 tokens but only 18 are actually in the protocol because of the fee. The protocol will still account the 20 tokens instead of the 18

We can see this here:

```solidity

 function _lock(address _tokenContract, uint256 _quantity, address _tokenOwner, address _lockRecipient) private {
      
        ...

>>      if (_tokenContract != address(0)) {
            IERC20 token = IERC20(_tokenContract);
            token.transferFrom(_tokenOwner, address(this), _quantity);
        }


        lockedToken.remainder = remainder;
>>      lockedToken.quantity += _quantity;
        lockedToken.lastLockTime = uint32(block.timestamp);
        lockedToken.unlockTime = uint32(block.timestamp) + uint32(_lockDuration);

        playerSettings[_lockRecipient].lockDuration = _lockDuration;

        emit Locked(_lockRecipient, _tokenOwner, _tokenContract, _quantity, remainder, numberNFTs, _lockDuration);
    }

```
This will lead to unexpected behaviour and loss of funds to the protocol because when a user calls `unlock()` the protocol will send 20 tokens back to him instead of 18

## Recommended Mitigation Steps
Use `balanceOf(address(_lockRecipient))` to track how much tokens the user had before and after the transfer

```diff

 function _lock(address _tokenContract, uint256 _quantity, address _tokenOwner, address _lockRecipient) private {
      
        ...

>>      if (_tokenContract != address(0)) {   
            IERC20 token = IERC20(_tokenContract);
+           uint256 balanceBefore = token.balanceOf(address(_lockRecipient));      
            token.transferFrom(_tokenOwner, address(this), _quantity);    
+           uint256 balanceAfter = token.balanceOf(address(_lockRecipient));     
+           _quantity = balanceAfter - balanceBefore;   
        }
       

        lockedToken.remainder = remainder;
>>      lockedToken.quantity += _quantity;
        lockedToken.lastLockTime = uint32(block.timestamp);
        lockedToken.unlockTime = uint32(block.timestamp) + uint32(_lockDuration);

        playerSettings[_lockRecipient].lockDuration = _lockDuration;

        emit Locked(_lockRecipient, _tokenOwner, _tokenContract, _quantity, remainder, numberNFTs, _lockDuration);
    }

```
