# Vulnerability details

In the `setUSDThresholds()` function, an Admin can update the `APPROVE_THRESHOLD` and `DISAPPROVE_THRESHOLD` storage values that determine the thresholds after which a proposal is approved or disapproved.

Unfortunately, setting the `DISAPPROVE_THRESHOLD` to 0 has the effect that none of the proposals will pass, leading to a temporary denial of service (DoS) situation if all current PriceFeed roles vote in favor of the proposal by calling the `approveUSDPrice()` function.

There is a check in the `_execUSDPriceUpdate()` internal function:

```solidity
if (
    usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD &&
    usdUpdateProposal.disapprovalsCount < DISAPPROVE_THRESHOLD
) {
```

This condition will always be false when `DISAPPROVE_THRESHOLD` is 0, preventing any proposal from being passed no matter the number of approval votes.

The only way to resolve this temporary DoS is to disapprove the proposal, which would require adding an additional PriceFeed role in the worst-case scenario where all current PriceFeed roles vote for approval, manually disapproving the proposal, and changing `DISAPPROVE_THRESHOLD` to a minimum of 1 to prevent this error.

## Impact

When `DISAPPROVE_THRESHOLD` is set to 0, any new price update proposal will never pass, rendering the functionality around price updates temporarily non-functional.

## Recommended Mitigation Steps

Update `setUSDThresholds()` with an additional check ensuring that `DISAPPROVE_THRESHOLD` is greater than 0.

```diff

        uint8 _approve,
        uint8 _disapprove
    ) external onlyAdmin {
        if (usdUpdateProposal.proposer != address(0))
```
