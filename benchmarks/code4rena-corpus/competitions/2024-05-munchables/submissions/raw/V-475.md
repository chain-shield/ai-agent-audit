# Vulnerability details

## Impact
If the threshold value is set greater than 5, with a maximum of only 5 voting addresses, it will cause the `proposeUSDPrice` function to never pass and cannot be reset, ultimately leading to a DoS.

## Proof of Concept
```solidity
function setUSDThresholds(
    uint8 _approve,
    uint8 _disapprove
) external onlyAdmin {
    if (usdUpdateProposal.proposer != address(0))
        revert ProposalInProgressError();//@audit-info we can't set thresholds while in the process.
    APPROVE_THRESHOLD = _approve;
    DISAPPROVE_THRESHOLD = _disapprove;

    emit USDThresholdUpdated(_approve, _disapprove);
}
```
The admin can set any threshold value without validation. If the admin incorrectly sets the THRESHOLD to a value greater than 5, for example, 6, then neither approvalsCount nor disapprovalsCount can reach the THRESHOLD.

Since the current proposal can only be deleted when it is either approved or disapproved, it cannot be reset in this scenario.

Furthermore, due to the usdUpdateProposal.proposer != address(0) check, the admin cannot reconfigure the THRESHOLD.

This situation can lead to a system DoS

## Tools Used
Foundry

## Recommended Mitigation Steps
check `THRESHOLD` is less than 6 when setting it.


## Assessed type

DoS
