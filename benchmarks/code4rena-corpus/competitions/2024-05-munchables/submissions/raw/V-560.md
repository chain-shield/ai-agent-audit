# Vulnerability details

## Impact
The value of `lockedToken.unlockTime` is updated every time that a player locks an amount of a certain token. It is increased at least by 30 days (the value of `lockdrop.minLockDuration`).
A player can unlock his/her funds using the `unlock` method only if the `lockedToken.unlockTime` is in the past. This means that locking new funds of a token resets the timer of the whole deposited quantity of that token. A player should be able to add new funds and mint Munchables without increasing the lock duration of past deposits.

## Proof of Concept
The only variable that tracks the unlock time is `lockedToken.unlockTime`:

```
ILockManager.sol#L29-L39

/// @notice Struct describing tokens locked by a player
/// @param quantity Amount of tokens locked
/// @param remainder Tokens left over after locking, not meeting the full NFT cost
/// @param lastLockTime The last time tokens were locked
/// @param unlockTime When the tokens will be unlocked
struct LockedToken {
 uint256 quantity;
 uint256 remainder;
 uint32 lastLockTime;
 uint32 unlockTime;
 }
```

This value is updated every time the `_lock() method` is called:

```
LockManager.sol#L381-L383

381     lockedToken.lastLockTime = uint32(block.timestamp);
382     lockedToken.unlockTime =
383         uint32(block.timestamp) +
384         uint32(_lockDuration);     
```

Furthermore, this is the value used to check if the `lockedToken` can be unlocked inside the `unlock() method`:

```
LockManager.sol#L410-L411

410     if (lockedToken.unlockTime > uint32(block.timestamp))
411         revert TokenStillLockedError();
```

Let's give an example. Bob locks 10 ethers now, and mints Munchables. Then, he has to wait the `_lockDuration` period, e.g. 30 days.
After 10 days, Bob decides to lock a further 5 ethers having the same lock duration. When he does that, the `lockedToken.unlockTime`
is set again. This means that the initial 10 ethers will be unlocked after 40 days Bob deposited them.
This behavior could lead Bob to avoid locking funds on Munchables or waiting several days to do so. This could slow the NFT minting mechanism.

## Tools Used
Visual inspection.

## Recommended Mitigation Steps
We propose to use a mapping to track the locked quantity and the `unlockTime`. In this way, a player will know when he/she will be able to unlock his/her funds, without being afraid to lock further funds.
