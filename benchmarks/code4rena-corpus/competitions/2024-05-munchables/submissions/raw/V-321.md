# Vulnerability details

## Impact
Malicious can dos other user's unlock function by lock 1 wei token

## Proof of Concept

every time user lock,the unlock time will recalculate and update the unlock time.

```solidity
    function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {
  ...


@>     lockedToken.unlockTime =
    uint32(block.timestamp) +
    uint32(_lockDuration);
```
the issue is there exist permissionless function `lockOnBehalf`, malicious user can use this function to update  the unlock time of other user's token.
Since there is no min value  check for `_quantity` , user can lock 1 wei to update other user's unlock time .



## Tools Used
manual 

## Recommended Mitigation Steps

 lock onbehalf should have min lock amount check to prevent this issue.
