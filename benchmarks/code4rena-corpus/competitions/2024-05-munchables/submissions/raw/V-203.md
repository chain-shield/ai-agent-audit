# Vulnerability details

## Impact
usdPriceProposal can be deleted without approval when approveUSDPrice is called and also without approveUSDPrice reverting.

## Proof of Concept
In prooposeUSDPrice(), it has a parameter called _contracts that accepts a list of addresses. However, these addresses are not checked that non is zero address is present. The only check in the function is _contracts.length is not zero.

`  if (_contracts.length == 0) revert ProposalInvalidContractsError();`

The length of the contract may not be zero but can include a zero address. For instance, if there are 5 contract addresses passed into the _contracts parameter, and one of the addresses is a zero address, this will pass the above check.

The check for zero address in _contracts parameter is also missing in approveUSDPrice() and _execUSDPriceUpdate().

Now in _execUSDPriceUpdate(), `delete usdUpdateProposal` is outside the for loop. What this means is when any of the addresses passed into _contracts parameter is zero in proposeUSDPrice() and approveUSDPrice() is called, which in turn calls the internal _execUSDPriceUpdate(), and gets to this line in _execUSDPriceUpdate():

` if (configuredTokens[tokenContract].nftCost != 0) {`

The for loop will be skipped when a zero address is passed as part of the _contracts parameter without reverting. And the code will proceed to still delete usdUpdateProposal without reverting and also without updating usd price.

Note that this vulnerability would still occur when APPROVE_THRESHOLD is met.

## Tools Used
Manual review

## Recommended Mitigation Steps
There should be a check for address zero in proposeUSDPrice().
Also, delete usdUpdateProposal should be inside the for loop in _execUSDPriceUpdate().
