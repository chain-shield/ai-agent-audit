# Vulnerability details

## Impact
The entire locking/unlocking functionality can be DOS'ed if tokens with >18 decimals are used.

## Proof of Concept
The contest [Readme](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L461) clearly mentions ``High decimals (>18)`` being in scope.

But, if tokens with ``>18`` decimals are configured, The `` getLockedWeightedValue()`` function will revert [here](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L473-L475) due to underflow.
