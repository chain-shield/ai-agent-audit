# Vulnerability details

The `proposeUSDPrice` function initiates a new proposal that can be approved or disapproved. When a proposal is approved the `approvalsCount` increments, when disapproved the `disapprovalsCount` increments. However, each new proposal triggers the deletion of the `usdUpdateProposal` struct, which tracks these counts. Consequently, `approvalsCount` and `disapprovalsCount` are reset to zero with each new proposal, preventing them from reaching the `APPROVE_THRESHOLD` or `DISAPPROVE_THRESHOLD` needed for execution.

## Impact
Cause the `approvalsCount` will never reach the `APPROVE_THRESHOLD`.

```javascript
 if (usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD) {
     _execUSDPriceUpdate();
        }
```

The `_execUSDPriceUpdate()` will never execute thus configuredTokens usd price will not update.

## Proof of Concept

Let's assume a process for updating the USD price for configured tokens:

1) `Role.PriceFeed_1` initiates a proposal.
2) The proposal is approved by `Role.PriceFeed_2`.
3) Now the `usdUpdateProposal.approvalsCount` = 2.
4) `Role.PriceFeed_1` initiates a new proposal.
5) This new proposal deletes the usdUpdateProposal struct, resetting `usdUpdateProposal.approvalsCount` to 0.
6) The new proposal is approved by `Role.PriceFeed_2`.
7) Now still the `usdUpdateProposal.approvalsCount = 2`, which should be 4 because two proposals have been approved.
8) Thus, the `usdUpdateProposal.approvalsCount` will never exceed 2 and usd price will not update.

## Tools Used
Manual review

## Recommended Mitigation Steps
Consider implementing `approvalsCount` and `disapprovalsCount` in a separate struct that is not deleted when a new proposal is initiated. This will allow the counts to persist across multiple proposals.
