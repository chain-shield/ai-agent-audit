# Vulnerability details

## Impact
`setLockDuration` incorrectly set new lock duration,potentially allowing a user to reduce the lockTime and  breaking one of the key invariants of the protocol.

## Proof of Concept

in the `setLockDuration` function, a new _duration is set to increase the lock duration

```solidity
 function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration))
            revert MaximumLockDurationError();
        playerSettings[msg.sender].lockDuration = uint32(_duration);
        uint256 configuredTokensLength = configuredTokenContracts.length;
        for (uint256 i; i < configuredTokensLength; i++) {
            address tokenContract = configuredTokenContracts[i];
            if (lockedTokens[msg.sender][tokenContract].quantity > 0) {
                if (
                    uint32(block.timestamp) + uint32(_duration) <
                    lockedTokens[msg.sender][tokenContract].unlockTime
                ) {
                    revert LockDurationReducedError();
                }

                uint32 lastLockTime = lockedTokens[msg.sender][tokenContract]
                    .lastLockTime;
                lockedTokens[msg.sender][tokenContract].unlockTime =
                    lastLockTime +
                    uint32(_duration);
            }
        }

        emit LockDuration(msg.sender, _duration);
    }

```
The function correctly checks if new duration combined with the current timestamp always has to be greater than the unlock time .Essentially breaking the attempt to reduce lockTime by any user,However the vulnerability lies in the area where the 'unlockTime' is updated.The new unlockTime is incorrectly set after adding new lock duration to 'lastLockTime' without considering the current timestamp the function is being called.Lack of acknowledgment of this time space creates an opportunity for a malicious user to set a new lock time that is lesser than previously set.for further explanation consider the scenario below.

- Alice creates a lock for a duration of 2 days on timestamp: 10:00 monday.
- Alice lockTime will be 10:00 monday & unlockTime will be 10:00 wednesday
- Alice calls `setLockDuration` that sets a new duration of 1 day 1 hr (25hr) on 10:00 tuesday
  (passes 'if' statement because 10:00 tuesday + 1day 1hour > 10:00 wednesday)
- New unlockTime for Alice has been calculated as 11:00 tuesday.
  (because unlockTime is calculated based on lastLockTime + uint32(_duration) so,10:00 monday + 25hr =11:00 tuesday).
- This way Alice reduced her unlockTime from 10:00 wednesday to 11:00 tuesday (23 hours).
