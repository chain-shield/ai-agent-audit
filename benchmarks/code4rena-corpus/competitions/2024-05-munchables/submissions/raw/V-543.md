# Vulnerability details

## Description
The ```disapproveUSDPrice()``` function does not check for ```usdUpdateProposal.approvalsCount < APPROVE_THRESHOLD``` before deleting a proposal. This could lead to a scenario where a proposal with equal number of approval counts and disapproval counts could get deleted when both the thresholds would be set to 1.

## Proof of Concept
The following is a step-by-step detailed description of the issue.

Consider the situation ```APPROVE_THRESHOLD == DISAPPROVE_THRESHOLD == 1```.

Now, consider Role.PriceFeed_1 proposes a proposal using the ```proposeUSDPrice()``` function:

https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L142

```
    function proposeUSDPrice(
        uint256 _price,
        address[] calldata _contracts
    )
        external
        onlyOneOfRoles(
            [
                Role.PriceFeed_1,
                Role.PriceFeed_2,
                Role.PriceFeed_3,
                Role.PriceFeed_4,
                Role.PriceFeed_5
            ]
        )
    {
        if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
        if (_contracts.length == 0) revert ProposalInvalidContractsError();

        delete usdUpdateProposal;

        // Approvals will use this because when the struct is deleted the approvals remain
        ++_usdProposalId;

        usdUpdateProposal.proposedDate = uint32(block.timestamp);
        usdUpdateProposal.proposer = msg.sender;
        usdUpdateProposal.proposedPrice = _price;
        usdUpdateProposal.contracts = _contracts;
        usdUpdateProposal.approvals[msg.sender] = _usdProposalId;
        usdUpdateProposal.approvalsCount++;

        emit ProposedUSDPrice(msg.sender, _price);
    }
``` 

Now, since the ```APPROVE_THRESHOLD``` is set to 1 and, after the proposal is proposed, the ```usdUpdateProposal.approvalsCount``` would also be 1, it would make sense for the proposal to get executed. However, this would be a problem where a proposal gets executed as soon as it is proposed. Therefore, in this case, the proposal is better not executed. However, let us see what happens when Role.PriceFeed_5 decides to disapprove the proposal. Please remember, ```APPROVE_THRESHOLD == DISAPPROVE_THRESHOLD == 1```.

Role.PriceFeed_5 calls the ```disapproveUSDPrice()``` function:

https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L210

```
    function disapproveUSDPrice(
        uint256 _price
    )
        external
        onlyOneOfRoles(
            [
                Role.PriceFeed_1,
                Role.PriceFeed_2,
                Role.PriceFeed_3,
                Role.PriceFeed_4,
                Role.PriceFeed_5
            ]
        )
    {
        if (usdUpdateProposal.proposer == address(0)) revert NoProposalError();
        if (usdUpdateProposal.approvals[msg.sender] == _usdProposalId)
            revert ProposalAlreadyApprovedError();
        if (usdUpdateProposal.disapprovals[msg.sender] == _usdProposalId)
            revert ProposalAlreadyDisapprovedError();
        if (usdUpdateProposal.proposedPrice != _price)
            revert ProposalPriceNotMatchedError();

        usdUpdateProposal.disapprovalsCount++;
        usdUpdateProposal.disapprovals[msg.sender] = _usdProposalId;

        emit DisapprovedUSDPrice(msg.sender);

        if (usdUpdateProposal.disapprovalsCount >= DISAPPROVE_THRESHOLD) {
            delete usdUpdateProposal;

            emit RemovedUSDProposal();
        }
    }
```

The checks would be easily tackled as Role.PriceFeed_5 would be voting first time since the proposal was proposed.
The ```usdUpdateProposal.disapprovalsCount``` is now equal to 1 (which is equal to ```DISAPPROVE_THRESHOLD```).

The code of our interest is at LOC-237:

https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L237

```
        if (usdUpdateProposal.disapprovalsCount >= DISAPPROVE_THRESHOLD) {
            delete usdUpdateProposal;
```

The proposal gets deleted in the same transaction of Role.PriceFeed_5 disapproving the proposal!

This happens even if the proposal has the same number of ```usdUpdateProposal.approvalsCount``` and ```usdUpdateProposal.disapprovalsCount``` (both equal to 1).

After getting proposed, it took just one disapproval for the proposal to get deleted, even though the approvals count == disapprovals count.

This happens because:

1. There no check in the ```setUSDThresholds()``` function to prevent admin from setting the thresholds to 1:

https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L129

```
    function setUSDThresholds(
        uint8 _approve,
        uint8 _disapprove
    ) external onlyAdmin {
        if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
        APPROVE_THRESHOLD = _approve;
        DISAPPROVE_THRESHOLD = _disapprove;

        emit USDThresholdUpdated(_approve, _disapprove);
    }
```

2. There is no check in the ```disapproveUSDPrice()``` function to check for ```usdUpdateProposal.approvalsCount < APPROVE_THRESHOLD``` before deleting a proposal.

## Impact
Impact: The proposal gets deleted even though it had equal approval and disapproval counts. This means that the protocol (in its current state with this bug) is biased towards disapproving a proposal. This must not happen. If the proposed proposals are referred to as assets of the protocol then this is a clear evidence that they are not handled properly, that is, proposed proposals as assets are compromised. This consolidates the impact to be High.

Likelihood: The likelihood of this issue tends to be low as the chance that both thresholds are set to 1 is not much probable.

## Recommended Mitigation Steps

It is recommended to add the following two checks:

1. To the ```setUSDThresholds()``` function:
```
require(_approve > 1);
require(_disapprove > 1);
```

2. To the ```disapproveUSDPrice()``` function:
```
        if ((usdUpdateProposal.disapprovalsCount >= DISAPPROVE_THRESHOLD) && (usdUpdateProposal.approvalsCount < APPROVE_THRESHOLD)) {
            delete usdUpdateProposal; }
```
