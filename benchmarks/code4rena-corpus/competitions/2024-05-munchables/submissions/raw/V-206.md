# Vulnerability details

## Impact
transfer() uses a fixed amount of gas, which can result in revert. https://consensys.net/diligence/blog/2019/09/stop-using-soliditys-transfer-now/


## Proof of Concept

These will inevitably fail when:

1. The unlocker smart contract does not implement a payable fallback function.
2. The unlocker smart contract implements a payable fallback function which uses more than 2300 gas units.
3. The unlocker smart contract implements a payable fallback function which needs less than 2300 gas units but is called through a proxy that raises the call’s gas usage above 2300.

Additionally, using higher than 2300 gas might be mandatory for some multisig wallets.

## Recommended Mitigation Steps

address.call{value:x}() should be used instead of payable.transfer() but be sure to respect the CEI pattern
