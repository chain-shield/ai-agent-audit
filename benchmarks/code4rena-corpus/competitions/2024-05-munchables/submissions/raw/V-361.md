# Vulnerability details

## Impact

The `configureToken()` function is used to add configured token contracts in the `configuredTokenContracts` array but a one for removing them is missing which can lead to unwanted behaviour if one of the tokens is no longer wanted to be supported by the protocol

## Proof of Concept
This is where we push tokens to the `configuredTokenContracts`

```solidity

 function configureToken(
        address _tokenContract,
        ConfiguredToken memory _tokenData
    ) external onlyAdmin {
        if (_tokenData.nftCost == 0) revert NFTCostInvalidError();
        if (configuredTokens[_tokenContract].nftCost == 0) {
>>          configuredTokenContracts.push(_tokenContract);
        }
        configuredTokens[_tokenContract] = _tokenData;

        emit TokenConfigured(_tokenContract, _tokenData);
    }

```

But there is no function that we can remove tokens from the `configuredTokenContracts` array

## Tools Used
Manual Analysis
## Recommended Mitigation Steps
Add a functionality for removing configured token contracts from the `configuredTokenContracts` that can be controlled by the admin
