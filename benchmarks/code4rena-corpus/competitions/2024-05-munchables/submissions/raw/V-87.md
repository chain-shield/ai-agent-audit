# Vulnerability details

## Issue
The constructor of the LockManager contract contains a call to a setter function (__BaseConfigStorage_setConfigStorage) without setting any values in the constructor itself or passing arguments to external calls. This violates the expected behavior of a setter function, which should either modify storage variables or pass arguments to external calls.

## Impact
Confusion: Calling a setter function without setting any values or passing arguments can lead to confusion for developers and readers of the code.
Unexpected Behavior: If the setter function is expected to modify state variables or interact with external contracts, not passing any arguments could result in unexpected behavior or errors during contract deployment or execution.


## Tools Used
Manual Audit

## Recommended Mitigation Steps
To address this issue, it's recommended to ensure that the setter function (__BaseConfigStorage_setConfigStorage) is properly implemented to set values or interact with external contracts as intended. If the intention is to set a configuration storage address, consider passing the address as an argument to the constructor and then calling the setter function with that argument. Alternatively, modify the setter function to accept arguments directly or set appropriate values within the constructor itself.
