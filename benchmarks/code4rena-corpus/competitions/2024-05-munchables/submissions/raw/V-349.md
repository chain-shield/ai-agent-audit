# Vulnerability details

## Description

The proposeUSDPrice function in the LockManager contract does not include a mechanism for proposal expiration. If other oracles do not vote for approval or disapproval, the proposal remains active indefinitely. This can block other functionalities, such as updating approval and disapproval thresholds using the setUSDThresholds function, which checks for an active proposal.

## Impact

- Stale Proposals: Proposals can remain active indefinitely if not enough votes are cast, leading to stale or outdated proposals.
- Blocked Functionality: Functions like setUSDThresholds cannot be executed if there is an active proposal, potentially blocking important updates.
- Operational Inefficiency: The inability to reset or expire proposals can lead to operational inefficiencies and hinder the contract's functionality.


## Proof of Concept

1. Create a Proposal:
        An oracle creates a new USD price proposal using proposeUSDPrice.
2. No Further Action:
        Other oracles do not vote for approval or disapproval, leaving the proposal in a pending state.
3. Blocked Threshold Update:
        Attempting to update the approval and disapproval thresholds using setUSDThresholds fails due to the active proposal check (if (usdUpdateProposal.proposer != address(0))).


## Tools Used

Manual Review

## Recommended Mitigation Steps

Introduce a proposal expiration mechanism to ensure that proposals do not remain active indefinitely. This can be achieved by adding a deadline to the proposal and checking for expiration in relevant functions.
