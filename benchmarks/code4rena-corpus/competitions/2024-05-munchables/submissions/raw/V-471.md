# Vulnerability details

Users are supposed to lock tokens into the `LockManager` and receive [unrevealedNFTs](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L369) in return. However, when tokens are locked outside of the `lockdrop` ([before the lockdrop has started or after it is over)](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L352-L355), the user doesn’t receive any `unrevealedNFTs`.

## Impact

When the user is locking outside of the `lockdrop` period, they will not receive any `nftOverlord.unrevealedNFTs`, but the `lastLockTime` and `unlockTime` will be updated.

## Proof of Concept

When a user [locks](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L308) tokens to the `LockManager`, it checks whether the [`lockdrop` is currently active.](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L352-L355)

- If active, the currently locked amount is [added](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L380) to the user's `quantity` account, and `unrevealedNFTs` are also [added](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L369) to the user's account.
- If not active, only the currently locked amount is [added](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L380) to the user's account.

However, this storage variable `lockedToken.quantity` is not used later when adding new `unrevealedNFTs` during the next opened`lockdrop` round, which results in fewer NFTs for the user.

## Recommended Mitigation Steps

The issue can be mitigated in two ways:

1. `lock` of tokens outside of the `lockdrop` can be restricted
2. When `lock`ing outside of the `lockdrop`, save the locked `_quantity` as `remainder`, which will be used in the next `lock` after a new `lockdrop` is started
