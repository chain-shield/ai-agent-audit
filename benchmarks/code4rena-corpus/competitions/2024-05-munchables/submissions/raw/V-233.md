# Vulnerability details

## Impact
User-B can't able to lock on behalf of User-A.

## Proof of Concept
`_lock()` have following checks
`lockDuration` should be 
- graeter than or equal to `lockdrop.minLockDuration`
- OR lesser than or equal to `configStorage.getUint(StorageKey.MaxLockDuration`
```solidity
            if (
                _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```
https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L356-L360

where `_lockDuration` either `playerSettings[_lockRecipient].lockDuration` or if not setted then equal to `lockdrop.minLockDuration`
```solidity
        uint32 _lockDuration = playerSettings[_lockRecipient].lockDuration;

        if (_lockDuration == 0) {
            _lockDuration = lockdrop.minLockDuration;
        }
```
https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L347-L351

By examining `playerSettings`, there is a function `setLockDuration()` where a User can set `lockDuration` for himself as follows
```solidity
    function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration))
            revert MaximumLockDurationError();

        playerSettings[msg.sender].lockDuration = uint32(_duration);
        // update any existing lock
        uint256 configuredTokensLength = configuredTokenContracts.length;
        for (uint256 i; i < configuredTokensLength; i++) {
            address tokenContract = configuredTokenContracts[i];
            if (lockedTokens[msg.sender][tokenContract].quantity > 0) {
                // check they are not setting lock time before current unlocktime
                if (
                    uint32(block.timestamp) + uint32(_duration) <
                    lockedTokens[msg.sender][tokenContract].unlockTime
                ) {
                    revert LockDurationReducedError();
                }

                uint32 lastLockTime = lockedTokens[msg.sender][tokenContract]
                    .lastLockTime;
                lockedTokens[msg.sender][tokenContract].unlockTime =
                    lastLockTime +
                    uint32(_duration);
            }
        }

        emit LockDuration(msg.sender, _duration);
    }
```
https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L245-L249

Here we see that while setting `_duration` function checks that
- `_duration` should never exceed `configStorage.getUint(StorageKey.MaxLockDuration)`
- And other checks present there as well(but those are not relevent for this Bug report)

But problem is it never check lower limit of `_duration`


So Besically a User can set a `duration` for himself where it lies between 0 and `lockdrop.minDuration`
```
0 < newDuration < lockdrop.minDuration
```

In result this will fail User `lock()` & `lockOnBehalf()` Tx always due to below check present in `_lock()`

```solidity
            if (
                _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```

For User This will not be a issue cause he can change that duration for himself anytime

But when it comes to another user locking for him(user), he(user) can DOS him(another User)

`Currently there is no such use case, but may be in future it arises`

### For Example
#### This protocol integrated with some thing else, which has business logic(like Alice has to lock on behalf of Bob, But if Bob stop Alice from doing this he can get some sort of advantage [A typical DeFi stuff])

So Bob set his `playerSettings.lockDuration` as above
And Alice ended in a DoS situation. Bob get profited(Not financially may be in other way.)

## Recommended Mitigation Steps
This Simply can stop by implemnting a lower limit check in `setLockDuration()` for input parameter

```diff
    function setLockDuration(uint256 _duration) external notPaused {
        if (_duration > configStorage.getUint(StorageKey.MaxLockDuration))
            revert MaximumLockDurationError();

+       if (_duration < lockdrop.minLockDuration)
+           revert LowerLockDurationError();
```
