# Vulnerability details

## Impact
There is currently no mechanism in place to withdraw any remaining locked amounts. If a token is deactivated, any remaining amounts will become inaccessible.

## Proof of Concept

**The issue is that the function `unlock` is implemented so that users can unlock only their `quantity` amount, not the `remainder` amount.**

```solidity
    function unlock(
        address _tokenContract,
        uint256 _quantity
    ) external notPaused nonReentrant {

        //.....

        if (lockedToken.quantity < _quantity)
            revert InsufficientLockAmountError();
        
        //.....

        lockedToken.quantity -= _quantity;

        //.....
    }
```

One solution is that if users would like to withdraw their remainder amount, they should lock some more amount, so that sum of this new amount and the remainder becomes equal to a `nftCost`. By doing so, the user's quantity value will be updated to include the remainder as well. Then the user can unlock his quantity value which is now including the remainder. But, if the token is not active, the users cannot lock anymore, so they will not have access to their remainder.


Please note that when a token is deactivated by the admin, it is reasonable that it is not allowed to lock that token anymore. Moreover, it is reasonable to allow users to unlock that token. This is correctly implemented. But, withdrawing remainder is not implemented properly, especially if the token is deactivated, then the remainder is unreachable.

## Recommended Mitigation Steps
Add a function as follows to support withdrawing of remainder:
```solidity
    function withdrawRemainder(address _tokenContract) external{
        LockedToken storage lockedToken = lockedTokens[msg.sender][
            _tokenContract
        ];

        uint256 amount = lockedToken.remainder;
        lockedToken.remainder = 0;

        if (_tokenContract == address(0)) {
            payable(msg.sender).transfer(amount);
        } else {
            IERC20 token = IERC20(_tokenContract);
            token.transfer(msg.sender, amount);
        }
    }
```
