# Vulnerability details

## Impact
If the current time is not within lockdrop start and end period, users can lock tokens with 1 second to bypass the `lockdrop.minLockDuration` restriction. Potentially benefit from the calculated USD value of locked tokens.

## Proof of Concept
The `_lock()` function allows users to lock tokens for a specified duration within a lockdrop period. However, the function does not revert transactions if the current time is outside the lockdrop start and end period.

The `_lock()` function will not revert the transaction if the `block.timestamp` before the `lockdrop.start` or after the `lockdrop.end`, because the check for `_lockDuration` is applied only in the `if` condition. [_lock()#L352](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L352-L360):

```solidity
        if (
            lockdrop.start <= uint32(block.timestamp) &&
            lockdrop.end >= uint32(block.timestamp)
        ) {
            if (
                _lockDuration < lockdrop.minLockDuration ||
                _lockDuration >
                uint32(configStorage.getUint(StorageKey.MaxLockDuration))
            ) revert InvalidLockDurationError();
```

Additionally, users can lock tokens with a minimal duration of 1 second, bypassing the `lockdrop.minLockDuration` restriction. [_lock()#L349](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/src/managers/LockManager.sol#L349-L351):

```solidity
        if (_lockDuration == 0) {
            _lockDuration = lockdrop.minLockDuration;
        }
```

As the `getLockedWeightedValue()` function does not return zero if current time is not within the lock drop period, it returns locked USD value if token prices have been updated to non-zero, allowing users to lock tokens for 1 second and get the calculated USD value of locked tokens.

## Recommended Mitigation Steps
Revert the transaction if current time is not within the lock drop period.
