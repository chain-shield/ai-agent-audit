# Vulnerability details

## Impact
The unlock function doesn't check the return value of `transfer` function when transferring ERC-20 tokens. Right after calling transfer, function emits the `Unlocked` event assuming that `transfer` returned true. However, for certain ERC20 tokens, if insufficient tokens are present, no revert occurs but a result of `false` is returned. So its important to check this. If you don't, you could emit the `Unlocked` event without checking that you successfully transferred the tokens to the unlocker. Possible user loss of funds.

## Proof of Concept
The issue is in the unlock function, where the `transfer` is called without checking its return value. Here is the relevant part of the code:


```
// send token
        if (_tokenContract == address(0)) {
            payable(msg.sender).transfer(_quantity);
        } else {
            IERC20 token = IERC20(_tokenContract);
            token.transfer(msg.sender, _quantity);
        }
```

If the `transfer` function returns false, the contract will still proceed as if the transfer was successful.
