# Vulnerability details

## Impact
The protocol does not check for a zero duration, which allows users to exploit this by using flash loans to mint a large number of NFTs in a single transaction.

## Proof of Concept
admin can invoke `configureLockdrop` to configure lockdrop.However zero amount of duration is not checked.
[LockManager.sol::configureLockdrop](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L98-L112)

add test:
```solidity
    function test_lock_duration_check() external {
        uint256 lockAmount = 100e18;
        deployContracts();

        // register me
        amp.register(MunchablesCommonLib.Realm(3), address(0));
        logSnuggery("Initial snuggery");

        //reset lockdrop
        lm.configureLockdrop(
            ILockManager.Lockdrop({
                start: uint32(block.timestamp),
                end: uint32(block.timestamp) + 86400,
                minLockDuration: 0
            })
        );

        vm.warp(block.timestamp + 100);

        uint balinit = address(this).balance;
        //lock
        lm.lock{value: lockAmount}(address(0), lockAmount);

        //unlock.
        lm.unlock(address(0), lockAmount);

        //check balance.
        assert(balinit == address(this).balance);
        
        logPlayer("after option");
    }
```
For testing, we use the native token. Note that the user can utilize any flash loan token, such as `DAI`.
