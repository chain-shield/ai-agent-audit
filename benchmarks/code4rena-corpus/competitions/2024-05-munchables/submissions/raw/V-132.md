# Vulnerability details

## Impact
APPROVE_THRESHOLD and DISAPPROVE_THRESHOLD are used in proposal functionality of the protocol. They can be changed from admin  in setUSDThresholds(). In approveUSDPrice() and disapproveUSDPrice() new proposal USD price is approved based on those thresholds. Currently they are set to 3 and this is legit based on the fact that the votes that could be received are 5. (Role.PriceFeed_1 ... Role.PriceFeed_5). The problem is that admin can set those thresholds too high by mistake or maliciously. In this case the whole proposal logic could be stuck if the required approvals and disapprovals are much more than the possible votes. Also then the admin will be not able to set new thresholds, because in setUSDThresholds() we have this check:
```
 if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
```
It will revert because of the fact that there is a proposal that is stuck. This means that no new proposals will be possible and the USD price will never change.

## Proof of Concept
1.Lets say we have Role.PriceFeed_1 ... Role.PriceFeed_5. This means we have 5 possible votes.
2.Admin set APPROVE_THRESHOLD=6 and DISAPPROVE_THRESHOLD=6
3.Proposal is created and the approval process is going.
4.All votes are approves for this proposal, but 5<6 so the proposal cannot be approved and gets stuck
5.New APPROVE_THRESHOLD and DISAPPROVE_THRESHOLD cannot be set because proposal is in progress.

In this scenario the USD price cannot be changed.
Keep in mind that the proposal will be stuck in any of the possible votes scenarios with thresholds higher than the count of possible votes.

## Tools Used
Manual review

## Recommended Mitigation Steps
To enhance safety and reliability, introduce a range of appropriate approval and disapproval thresholds in setUSDThresholds().
