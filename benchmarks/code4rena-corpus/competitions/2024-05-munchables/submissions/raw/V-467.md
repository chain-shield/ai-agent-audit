# Vulnerability details

## Impact

Tokens locked before the lockdrop start time will not be rewarded. (cannot be used for Reveal)

## Proof of Concept

```solidity
    struct LockedToken {
        uint256 quantity;
        uint256 remainder;
        uint32 lastLockTime;
        uint32 unlockTime;
    }
```

The LockedToken's information has a remainder. This indicates how much of the locked up token quantity is left for reveal.

This is in addition to the quantity added to the next lock.

If lock is called before block.timestamp is lockdrop.start, the if statement in the above code will not be executed.

Since lockdrop has not yet started, the locked up token cannot be used for reveal.

It makes sense for the token to be stored in remainder because it was locked up but not used for reveal. However, in the code above, the value of the variable remainder is 0 because the if statement was not performed.

Therefore, it is not stored in lockedToken.remainder.

The user must wait for the unlock time to use the token again.
