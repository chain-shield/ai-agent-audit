# Vulnerability details

## Impact
```LockManager::getLockedWeightedValue``` contains a ```deltaDecimal``` calculation using the decimals set for the configured token, in this calculation the decimals being higher than 18 will result in an underflow error.

The ```AccountManager::getDailySchnibbles``` and ```BonusManager::getHarvestBonus``` contain functionality that depend on calling the ```LockManager::getLockedWeightedValue``` function, which by reverting renders those functions useless.

## Proof of Concept
We can modify the existing test file ```getHarvestBonus.test.ts``` and change line [79](https://github.com/code-423n4/2024-05-munchables/blob/57dff486c3cd905f21b330c2157fe23da2a4807d/tests/managers/BonusManager/getHarvestBonus.test.ts#L79) from ```decimals: 18,``` to ```decimals: 19,```.

After implementing that change we run ```npm run test:typescript``` which when getting to that test will run into the following error:
```
test at file:/home/jesus/Projects/audits/2024-05-munchables/tests/managers/BonusManager/getHarvestBonus.test.ts:1:14763
✖ should return combined max bonus (74.709468ms)
  Error [ContractFunctionExecutionError]: The contract function "getHarvestBonus" reverted with the following reason:
  Arithmetic operation resulted in underflow or overflow.
```

## Tools Used
Manual review + node tests

## Recommended Mitigation Steps
During the token configuration in ```LockManager::configureToken``` add a validation for the maximum number of decimals.
