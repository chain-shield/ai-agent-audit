# Vulnerability details

## Impact
A user can set lockduration before any deposits as there is no check. Now will create issue because when user will deposit, unlockTime will be set to lock duration ,which user set earlier
```solidity
  function _lock(
        address _tokenContract,
        uint256 _quantity,
        address _tokenOwner,
        address _lockRecipient
    ) private {

      
      -->  uint32 _lockDuration = playerSettings[_lockRecipient].lockDuration;


        lockedToken.lastLockTime = uint32(block.timestamp);
     -->   lockedToken.unlockTime =
            uint32(block.timestamp) +
            uint32(_lockDuration);

        // set their lock duration in playerSettings
        playerSettings[_lockRecipient].lockDuration = _lockDuration;

    }
```
User can set lock duration very low before deposit, which allow the user to unlock early
