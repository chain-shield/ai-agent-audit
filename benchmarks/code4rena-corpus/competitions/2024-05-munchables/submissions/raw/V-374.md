# Vulnerability details

## Summary

The protocol employs five price feeds to establish a consensus on the USD value of an asset. These feeds vote to approve or disapprove proposed prices. A price is finalized only after reaching a predefined approval or disapproval threshold. However, if neither threshold is met due to insufficient consensus among the feeds, it results in a deadlock, preventing any new price proposals and leading to the use of outdated prices.

## Vulnerability Detail

the `approveUSDPrice` and `disapproveUSDPrice` functions are critical for voting on proposed prices. Once a proposal accumulates enough votes to reach either threshold, it is either executed or rejected, respectively:

- approveUSDPrice
```solidity=202
if (usdUpdateProposal.approvalsCount >= APPROVE_THRESHOLD) {
            _execUSDPriceUpdate();
        }
```

- disapproveUSDPrice
```solidity=237
if (usdUpdateProposal.disapprovalsCount >= DISAPPROVE_THRESHOLD) {
            delete usdUpdateProposal;
```
and then it's deleted. it's the only way to delete a proposal.
Proposals are introduced through the `proposeUSDPrice` function, which cannot proceed if there is an ongoing proposal:

```solidity=142

=>        if (usdUpdateProposal.proposer != address(0))
```

The inability to propose new prices until the current proposal is resolved can lead to a deadlock. For instance, if the thresholds are misaligned with voting behaviors (e.g., approveThreshold=3, disapproveThreshold=4) and only 2 approve while 3 disapprove, the proposal remains active and unresolved. This scenario prevents the admin from adjusting the thresholds due to existing constraints:

```solidity=128
function setUSDThresholds(
        uint8 _approve,
        uint8 _disapprove
    ) external onlyAdmin {
        if (usdUpdateProposal.proposer != address(0))
            revert ProposalInProgressError();
```

Additionally, price feeds are unable to revise their votes as the system does not permit revoting or vote cancellation:

- approveUSDPrice
```solidity=177
if (usdUpdateProposal.approvals[msg.sender] == _usdProposalId)
            revert ProposalAlreadyApprovedError();
```

Even attempts by the admin to change the roles of the price feeds are ineffective once they have voted, leading to a scenario where the price reporting system can become inoperable. This vulnerability makes the system susceptible to stagnation, where unresolved proposals prevent the updating of price feeds, significantly impacting the protocol's functionality.

## Impact

This deadlock results in a Denial of Service (DOS) within the price reporting system, causing the protocol to operate with stale prices. Consequently, this affects the accurate calculation of user TVLs and leads to incorrect distribution of rewards.

Manual Review

## Recommendation

add a period where if the proposed price isn't accepted or rejected , then it should be deleted to allow proposers to propose a new price.
