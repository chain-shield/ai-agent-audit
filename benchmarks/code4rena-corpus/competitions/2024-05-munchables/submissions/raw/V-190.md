# Vulnerability details

## Impact
The protocol is not compatible with transfer fee tokens. Protocol receive less fund than expected lead to lost of funds.

## Proof of Concept
When a user invokes lockOnBehalf or lock to lock a specific amount of tokens for a duration, the protocol transfers ERC20 tokens from the sender to the protocol.

[https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L374-L377](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L374-L377)
```solidity
// Transfer erc tokens
if (_tokenContract != address(0)) {
    IERC20 token = IERC20(_tokenContract);
    token.transferFrom(_tokenOwner, address(this), _quantity);
}
```

[https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L380](https://github.com/code-423n4/2024-05-munchables/blob/main/src/managers/LockManager.sol#L380)
```solidity
lockedToken.quantity += _quantity;
```

After transferring, the protocol adds the specified quantity (the amount of tokens) to storage. However, for transfer fee tokens, the protocol receives fewer tokens than expected due to the fee deduction, which can lead to a loss of funds for the protocol.


## Tools Used
Foundry

## Recommended Mitigation Steps
Instead of summing up the specified quantity, the protocol should record the balance change during the user's lock operation.


## Assessed type

ERC20
