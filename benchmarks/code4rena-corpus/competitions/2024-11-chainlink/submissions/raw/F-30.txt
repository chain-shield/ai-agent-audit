dont directly use `ecrecover()` in code to be deployed on zksync era.
adeolu

Finding description and impact

In the codebase, ecrecover() is used here and here. This codebase is to be deployed on zksync era as it is listed as a supported chain in the contesst readme. ecrecover() should not be directly used for signature verification on zksync era as zkSync EOA accounts are quite different from the ethereum EOA accounts which ecrecover() is made to work for.

On ethereum, There are two account types:

Contract account, accounts with code and
Externally Onwed Accounts(EOA) accounts which are controlled by anyone with the private keys,

as such only accounts that are controlled by a private key can produce an ESCDA signature of which the signer can be recoverable via ecrecover(). Contract accounts cannot do that.

On zkSync Era, There are two account types, just like ethereum mainnet but the Externally Owned Accounts can also have code logic implemented in them, like a contract account. Therefore this blurs the difference between a traditional contract account and an EOA account on zkSync.

https://docs.zksync.io/build/developer-reference/best-practices#use-native-account-abstraction-over-ecrecover-for-validation

Use native account abstraction over ecrecover for validation
Use ZKsync Era's native account abstraction support for signature validation instead of this function.

We recommend not relying on the fact that an account has an ECDSA private key, since the account may be governed by multisig and use another signature scheme.

Now since EOAs on zksync era are like smart contracts, this means that any account on zksync may be a contract and also be controlled by an ESCDA private key. This affects the usecase of ecrecover() on zksync since EOAs have code, thus they are essentially smart contracts (or smart accounts) and it should only work for accounts without code. Because of this zkSync era warns developers to use native account abstraction (EIP-1271) signature functions over ecrecover() for signature validations.
Zksync advises devs to use openzeppelin's SignatureChecker.sol instead. see here. In SignatureChecker.sol , the function isValidSignatureNow() will work for both signatures generated by accounts with code (smart contracts, smart accounts) and accounts with no code (EOAs).

Link to docs --> https://docs.zksync.io/build/developer-reference/best-practices#use-native-account-abstraction-over-ecrecover-for-validation
https://docs.zksync.io/build/developer-reference/account-abstraction
https://ethereum.org/en/developers/docs/accounts/
https://docs.zksync.io/build/developer-reference/account-abstraction/signature-validation
https://docs.zksync.io/build/developer-reference/account-abstraction/signature-validation#openzeppelin-libraries

Recommended mitigation steps

use SignatureChecker.isValidSignatureNow() for signature verification instead of directly using ecrecover() in code to be deployed on zksync era.
