S-157
MultiOCR3Base MAX_NUM_ORACLES value can lead to DOS on certain EVM-compatible chains
ayden
43
Sufficient
383d ago
Finding description and impact

The Maximum number of oracles the offchain reporting protocol is designed for 256. However, setting 256 oracles consumes a substantial amount of gas, potentially exceeding the current block's gasLimit and resulting in a denial of service (DoS) for the setOCR3Configs function.

Proof of Concept

GasLimit on scroll is 10,000,000 :
https://scrollscan.com/block/10991884

GasLimit on is gnosis 17,000,000
https://gnosisscan.io/block/36960784

test code:

  function test_setOCRConfig_cost_gas() public {
    vm.startPrank(OWNER);
    MultiOCR3Base.OCRConfigArgs[] memory ocrConfigs = new MultiOCR3Base.OCRConfigArgs[](1);
    // Commit plugin config should clear latest epoch & round
    address[] memory max_validSigners = new address[](256);
    address[] memory max_validTransmitters = new address[](256);
    for(uint256 i;i<256;i++){
      max_validSigners[i] = vm.addr(i+1);
      max_validTransmitters[i] = vm.addr(i+257);
    }

    
    ocrConfigs[0] = MultiOCR3Base.OCRConfigArgs({
      ocrPluginType: uint8(Internal.OCRPluginType.Commit),
      configDigest: s_configDigestCommit,
      F: s_F,
      isSignatureVerificationEnabled: true,
      signers: max_validSigners,
      transmitters: max_validTransmitters
    });
    
    uint256 gas2 = gasleft();
    s_offRamp.setOCR3Configs(ocrConfigs);
    console2.log(gas2 - gasleft());
  }

out:

[PASS] test_setOCRConfig_cost_gas() (gas: 23702813)
Logs:
  23419236

Suite result: ok. 1 passed; 0 failed; 0 skipped; finished in 36.85ms (23.80ms CPU time)

Ran 1 test suite in 157.52ms (36.85ms CPU time): 1 tests passed, 0 failed, 0 skipped (1 total tests)

From above test we can see setOCR3Configs cost 23,419,236 much greater than the block gaslimit on scroll and gnosis

Recommended mitigation steps

Reduce the maximum number of oracles
