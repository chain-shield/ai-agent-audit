S-463
`_transmit()` will be reverted with an out-of-bound error when the number of signatures exceeds `32`
stuart_the_minion
83
Sufficient
383d ago
Finding description and impact

In CCIP v1.6, the protocol increases maximum number of oracles from 32 to 256.

abstract contract MultiOCR3Base is ITypeAndVersion, Ownable2StepMsgSender {
  uint256 internal constant MAX_NUM_ORACLES = 256;
  ... ...
}

And, the MultiOCR3Base::_verifySignatures() function takes rs, ss and rawVs to verify the hashed report with the signatures.

  function _verifySignatures(
    uint8 ocrPluginType,
    bytes32 hashedReport,
    bytes32[] memory rs,
    bytes32[] memory ss,
    bytes32 rawVs
  ) internal view {
    // Verify signatures attached to report. Using a uint256 means we can only verify up to 256 oracles.
    uint256 signed = 0;

    uint256 numberOfSignatures = rs.length;
    for (uint256 i; i < numberOfSignatures; ++i) {
      // Safe from ECDSA malleability here since we check for duplicate signers.
      address signer = ecrecover(hashedReport, uint8(rawVs[i]) + 27, rs[i], ss[i]);
      // Since we disallow address(0) as a valid signer address, it can never have a signer role.
      Oracle memory oracle = s_oracles[ocrPluginType][signer];
      if (oracle.role != Role.Signer) revert UnauthorizedSigner();
      if (signed & (0x1 << oracle.index) != 0) revert NonUniqueSignatures();
      signed |= 0x1 << oracle.index;
    }
  }

However, as the data type of rawVs is bytes32 and the function grabs v values from rawVs using byte-wise operation, the rawVs can accommodate up to 32 vs.

    address signer = ecrecover(hashedReport, uint8(rawVs[i]) + 27, rs[i], ss[i]);

Consequently, the commit() function in OffRamp will be reverted with OOO error if the number of signatures(vs.length or ss.length) is greater than 32.

Proof of Concept

I change the following OffRamp configuration for the test purpose:

OffRampSetup.t.sol#L48

- uint8 internal constant s_F = 1;
+ uint8 internal constant s_F = 10;

And also change the number of signatures:

MultiOCR3BaseSetup.t.sol#L28

-   uint160 numSigners = 7;
+   uint160 numSigners = 33;

And after running any successful test cases that invoke the OffRamp::commit() function, they were reverted with OOO errors.

Tools Used

Manual Review

Recommended Mitigation Steps

Consider updating the _verifySignatures() function to take vs using bitwise operations.
