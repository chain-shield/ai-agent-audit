Execution Cost Miscalculation Due to Missing Calldata Cost
0xRobocop
67
Sufficient
383d ago
Finding description and impact

The FeeQuoter contract is responsible for calculating the fee associated with message transmission in the CCIP system via the getValidatedFee function. This function computes the final fee by considering three components: premiumFee, executionCost, and dataAvailabilityCost.

return ((premiumFee * s_premiumMultiplierWeiPerEth[message.feeToken]) + executionCost + dataAvailabilityCost) / feeTokenPrice;

The executionCost is intended to account for the cost associated with executing the message on the destination chain. This cost is computed by adding all the amount of gas it will take to execute the message successfully. The components of the total amount of gas is divided in 4:

A destGasOverhead that is used to cover some fixed gas costs during message execution.
tokenTransferGas which is the amount of gas to relay to token pools for execution.
gasLimit which is the amount of gas to relay to the message receiver.
The cost associated with the calldata size.

However, the current implementation overlooks the tokenTransferBytesOverhead from the point 4 component, which represents the additional bytes required by token transfers in a message. These extra bytes are correctly included in the dataAvailabilityCost (when message is to be executed in an L2) but are omitted from the executionCost. This means that the additional bytes required for token transfers are not being considered in the execution cost, leading to an underestimation of the transaction fee.

Proof of Concept

The highest impact of this finding concerns messages that are going to be executed in the Ethereum network. For instance, on days with high gas prices, such as 100 gwei which did occur several days during November 2024, the system could incur significant losses.

Assuming tokenTransferBytesOverhead is 96 (as configured for USDC), the total gas units required would be 96 * 16 = 1536. If at least one transaction per block involves a USDC transfer, the CCIP system could lose approximately 3672 USD daily.

The exact impact cost will depend on the following factors:

Gas price. The example considered 100 gwei.
The configured bytes overhead for the transferred token. The example considered the USDC configuration of 96 bytes. However, this value could be smaller (32) or can be configured to be bigger than 96.
The number of token transfers within the message, messages can have up to 5 token transfers. The example considered the smallest which is just one token transfer in the message.

The above values were computed using the RareSkill's gas price calculator.

Recommended mitigation steps

To ensure accurate fee calculation, the executionCost should include both the length of message.data and the tokenTransferBytesOverhead, multiplied by destGasPerPayloadByte. This adjustment will account for all non-fixed size data in the cost computation.

uint256 executionCost = uint112(packedGasPrice)
  * (
    destChainConfig.destGasOverhead + ((message.data.length + tokenTransferBytesOverhead) * destChainConfig.destGasPerPayloadByte) + tokenTransferGas
      + _parseEVMExtraArgsFromBytes(message.extraArgs, destChainConfig).gasLimit
  ) * destChainConfig.gasMultiplierWeiPerEth;

Request for Reconsideration: Selection and Severity Classification
Edited: Feb 22
0xRobocop
OP

This finding is a duplicate of submission S-495, which was marked as valid and selected for the report.

I respectfully request the judge reconsider their decision and select this submission instead, as it provides a clearer description of the issue along with a numerical example illustrating the potential impact. This additional context enhances the analysis and facilitates a more meaningful discussion of the issue.

Furthermore, I urge the judge to reclassify this issue as medium severity based on the following rationale:

The example uses a gas price of 100 gwei, which, while external, is not speculative. Such prices have occurred frequently on the Ethereum network, and significantly higher prices are also common.
The example assumes 96 bytes as the overhead, consistent with the current configuration of the USDC pool (so no external requirement). Larger overhead configurations are possible, and these are determined by administrative privilege. Presuming the admin’s action as an error (for configuring a pool that needs for example > 96 bytes as overhead) assumes foreknowledge of this issue, which is unfounded.
The example considers a single token transfer, but the system supports up to five transfers per message. In such cases, even pools configured with a 32-byte overhead would generate a cumulative overhead of 160 bytes that are not being billed—greater than the 96-byte configuration in the example.

Only the gas price assumption (point 1) relies on external factors outside of the CCIP system, but it remains a realistic and frequent occurrence on Ethereum. This demonstrates that the described impact is neither exaggerated nor based on speculative scenarios.

In light of these points, I ask the judge to reconsider both the submission selection and the issue severity classification.
