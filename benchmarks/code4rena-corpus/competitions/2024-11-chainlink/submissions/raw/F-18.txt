Malicious `offChainTokenData` can be passed to mark a message FAILED and dishonour nonce ordering
hash
87
Sufficient
383d ago
Impact

An attacker can intentionally mark a user's message as FAILED and dishonour the nonce ordering

Proof of Concept

When transferring tokens, offChainTokenData is passed as a parameter when calling the token pool. This parameter is not validated in any way before the call to the token pool is made.

  function executeSingleMessage(
    Internal.Any2EVMRampMessage memory message,
    bytes[] calldata offchainTokenData,
    uint32[] calldata tokenGasOverrides
  ) external {
    if (msg.sender != address(this)) revert CanOnlySelfCall();
    Client.EVMTokenAmount[] memory destTokenAmounts = new Client.EVMTokenAmount[](0);
    if (message.tokenAmounts.length > 0) {
      destTokenAmounts = _releaseOrMintTokens(
        message.tokenAmounts,
        message.sender,
        message.receiver,
        message.header.sourceChainSelector,
        offchainTokenData,
        tokenGasOverrides
      );

But in the token pools, the validation of the offChainTokenData might be performed which can cause the execution to revert. Eg:

https://github.com/code-423n4/2024-11-chainlink/blob/69452f45335defa5b41aefd341bff26394aace8c/contracts/src/ccip/pools/USDC/USDCTokenPool.sol#L138-L148

  function releaseOrMint(
    Pool.ReleaseOrMintInV1 calldata releaseOrMintIn
  ) public virtual override returns (Pool.ReleaseOrMintOutV1 memory) {
    _validateReleaseOrMint(releaseOrMintIn);
    SourceTokenDataPayload memory sourceTokenDataPayload =
      abi.decode(releaseOrMintIn.sourcePoolData, (SourceTokenDataPayload));
    MessageAndAttestation memory msgAndAttestation =
      abi.decode(releaseOrMintIn.offchainTokenData, (MessageAndAttestation));

=>  _validateMessage(msgAndAttestation.message, sourceTokenDataPayload);

    ...

In case the execution gets reverted, the user's message is marked as FAILED and the next nonce can be attempted. This allows an attacker to intentionally pass malicious data for the offchainTokenData so that they can revert the execution and dishonour the nonce ordering for execution

User message with nonce 10 contains a token pool which performs validation for offChainTokenData. User expects this message to be executed before his next message with nonce 11
Attacker executes this message by passing in malicious value for offChainTokenData such that the validation will fail. Now the message is marked as FAILED and the attacker can execute the message with nonce 11
Recommended Mitigation Steps

Validate that offChainTokenData passed in is a legit value
