S-462
Initial sender nonce for users that used a previous on/off ramp will be incremented twice
gesha17
57
Sufficient
383d ago
Finding description and impact

When a user first uses the new on/off ramps the nonce manager will fetch the last nonce from the previous ramps. This is done to keep the nonces going from where they stopped at in the previous architecture. However, the nonce will be incremented twice for users that have used a previous on/off ramp. This happens because the call to fetch the sender nonce to the previos ramp will return the next nonce instead of the last one and also that returned value is then incremented again. This will result in messages that are not sent to the destination chain because the offchain code does checks on the sender nonce, so the message will be marked as invalid. This will lead to loss of funds as funds will be locked only on one chain and not released on the other. Also, these users will not be able to further submit CCIP messages as source/destination nonces will be out of sync. It will occur to every user that has used a previous on/off ramp.

Proof of Concept

The _getOutboundNonce() function calls IEVM2AnyOnRamp(prevOnRamp).getSenderNonce(sender):

https://github.com/code-423n4/2024-11-chainlink/blob/main/contracts/src/ccip/NonceManager.sol#L66

  function _getOutboundNonce(uint64 destChainSelector, address sender) private view returns (uint64) {
    uint64 outboundNonce = s_outboundNonces[destChainSelector][sender];

    // When introducing the NonceManager with existing lanes, we still want to have sequential nonces.
    // Referencing the old onRamp preserves sequencing between updates.
    if (outboundNonce == 0) {
      address prevOnRamp = s_previousRamps[destChainSelector].prevOnRamp;
      if (prevOnRamp != address(0)) {
        //  @audit This will return the next sender nonce, instead of hte current one.
        return IEVM2AnyOnRamp(prevOnRamp).getSenderNonce(sender);
      }
    }

    return outboundNonce;
  }

However, that function will return the next sender nonce, instead of the last one as per the interface definition:

https://github.com/code-423n4/2024-11-chainlink/blob/main/contracts/src/ccip/interfaces/IEVM2AnyOnRamp.sol#L14

  /// @notice Get the next nonce for a given sender.
  /// @param sender The sender to get the nonce for.
  /// @return nonce The next nonce for the sender.
  function getSenderNonce(
    address sender
  ) external view returns (uint64 nonce);

This returned value will then once more be incremented in getIncrementedOutboundNonce():

https://github.com/code-423n4/2024-11-chainlink/blob/main/contracts/src/ccip/NonceManager.sol#L48

  /// @inheritdoc INonceManager
  function getIncrementedOutboundNonce(
    uint64 destChainSelector,
    address sender
  ) external onlyAuthorizedCallers returns (uint64) {
    // @audit nonce is increased the second time
    uint64 outboundNonce = _getOutboundNonce(destChainSelector, sender) + 1;
    s_outboundNonces[destChainSelector][sender] = outboundNonce;

    return outboundNonce;
  }

As a result, the sender nonce for user that have used a preivous on/off ramp will be incremented twice.

Recommended mitigation steps

Apply the following change:

  function _getOutboundNonce(uint64 destChainSelector, address sender) private view returns (uint64) {
    uint64 outboundNonce = s_outboundNonces[destChainSelector][sender];

    // When introducing the NonceManager with existing lanes, we still want to have sequential nonces.
    // Referencing the old onRamp preserves sequencing between updates.
    if (outboundNonce == 0) {
      address prevOnRamp = s_previousRamps[destChainSelector].prevOnRamp;
      if (prevOnRamp != address(0)) {
-        return IEVM2AnyOnRamp(prevOnRamp).getSenderNonce(sender);
+        return IEVM2AnyOnRamp(prevOnRamp).getSenderNonce(sender) - 1;
      }
    }

    return outboundNonce;
  }
