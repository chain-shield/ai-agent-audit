# Vulnerability details

## Impact

when try to finalize prososal, malicious user is possible to front run get proof data and call `challengeLPP` to  get profit

## Proof of Concept

`challengeLPP` and `squeezeLPP`  shares same proof params, the diff of these is two is  `challengeLPP` send funds to msg.sender  `squeezeLPP` send
funds to proposal creator.
 
`suqeeZeLPP`  have time limit, only chanllenge period has passed can call it. 
The issue is  `challengeLPP` don't have time limit to mark sure that when calling `challengeLpp` is in chanllenge  period. 
Since these two funciton has same proof params, when user try to `squeezeLPP` , malicious user is possible to front run and get proof data and 
call function `challengeLPP` ,since in `challengeLPP` there is no time check and funds will return to the msg.sender.
