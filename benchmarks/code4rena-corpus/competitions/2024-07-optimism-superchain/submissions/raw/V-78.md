# Vulnerability Details

## Impact

When a challenger invokes the ﻿step() function, they commit a bond based on a ﻿MAX_DEPTH claim.

However, the ﻿step() function does not verify whether the user proposing an LPP or updating the oracle is the one calling the function.

As a result, an attacker could execute ﻿squeezeLPP() and then call ﻿step() after the challenge period has elapsed.

Consequently, the attacker would receive the bond since ﻿step() always allocates the bond to the ﻿msg.sender.

```solidity 
    function step(...)
        public
        virtual
    {
        parent.counteredBy = msg.sender;
    }
```

Hence proposer will not be reimbursed

## Tools Used

Eyes

## Recommended Mitigation Steps

The bonds from `step()` should be assigned to the one that updated the oracle
