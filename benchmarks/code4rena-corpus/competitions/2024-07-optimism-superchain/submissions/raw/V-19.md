# Vulnerability details

## Impact

Background

When creating a dispute game in the factory, a mechanism is in place to ensure that the same game isn't opened more than once. This is achieved through a check that computes a unique identifier (UUID) for each dispute game. The relevant code snippet is as follows:

```
        // Compute the unique identifier for the dispute game.
        Hash uuid = getGameUUID(_gameType, _rootClaim, _extraData);

        // If a dispute game with the same UUID already exists, revert.
        if (GameId.unwrap(_disputeGames[uuid]) != bytes32(0)) revert GameAlreadyExists(uuid);

```

The UUID is calculated using several parameters, including _gameType, _rootClaim, and _extraData. If a dispute game with the same UUID already exists, the function reverts, preventing the creation of a duplicate game. However, the use of _extraData in the UUID calculation introduces a significant vulnerability.

Vulnerability Details

The parameter _extraData can include data that is highly variable and does not necessarily affect the underlying claim. This means that different dispute games can be initiated for the same issue, simply by varying the _extraData parameter.

For example, variables like clock can vary slightly without affecting the underlying claim, but still result in different UUIDs. This allows multiple dispute games to be started for the same issue, circumventing the intended check that prevents duplicate games.

Implications

This undermines the integrity of the dispute resolution process. By manipulating the _extraData parameter, malicious actors can create multiple dispute games for the same underlying claim. This not only leads to inefficiency and unnecessary consumption of resources but also 

Increased Costs: Honest participants may face increased costs as they are forced to address multiple dispute games for the same claim, leading to financial strain and discouragement from participating in the dispute resolution process.

## Recommended Mitigation Steps

Refine UUID Calculation: Ensure that the UUID calculation relies only on parameters that directly impact the underlying claim, minimizing the influence of highly variable data like _extraData.
