# Vulnerability details

## Impact

The game state can be modified after the game clock expired.

In `FaultDisputeGame`, `challengeRootL2Block()` does not check whether the game clock has expired. Hence, a successful challenge can still be made even after the game is closed, i.e. during the bond payment period.

This breaks an important invariant about the game clock and could result in a modified game state after the game expiration. 

Consider the following scenario:

- Alice is a successful challenger to the root claim of the output root game. At the game expiration time, she’s entitled to the bond payment for this claim.
- Bob successfully calls `challengeRootL2Block()` after the game expired.
- Due to how `resolveClaim()` always prioritizes bond payment to L2 block challenger, the bond will be paid back to Bob instead of Alice.
- However, notice that if Alice was able to call `resolveClaim()` before Bob called `challengeRootL2Block()`, the bond would have been paid to Alice. Bob’s challenge call will still succeed, even though he will not be able to claim the bond.
