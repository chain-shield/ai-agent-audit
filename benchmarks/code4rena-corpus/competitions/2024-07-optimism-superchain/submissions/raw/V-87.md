# Vulnerability details

## Vulnerabilities in the Contract

### **Reentrancy Attack in `create` Function**
**Issue:**
The `create` function performs multiple state changes and external calls, which could be exploited by a reentrancy attack.

**Impact:**
If a malicious contract reenters the `create` function before the state changes are complete, it could create multiple dispute games with the same parameters, leading to inconsistency and potential loss of funds.

**Solution:**
To mitigate this risk, the contract should follow the "checks-effects-interactions" pattern, ensuring state changes are made before external calls. Additionally, using the `ReentrancyGuard` from OpenZeppelin can help prevent reentrant calls.

```solidity
import {ReentrancyGuard} from "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract DisputeGameFactory is OwnableUpgradeable, IDisputeGameFactory, ISemver, ReentrancyGuard {
    // rest of the contract code...

    function create(
        GameType _gameType,
        Claim _rootClaim,
        bytes calldata _extraData
    )
        external
        payable
        nonReentrant
        returns (IDisputeGame proxy_)
    {
        // existing logic...
    }
}
