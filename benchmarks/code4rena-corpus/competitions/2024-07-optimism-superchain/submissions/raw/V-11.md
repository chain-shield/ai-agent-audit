# Vulnerability details

## Impact
While not an immediate critical vulnerability, it represents a potential weakness that could be exploited under certain conditions to make the game unresolvable. It's a good candidate for optimization to improve the contract's robustness and resistance to potential DOS attacks.

## Proof of Concept
The `move` function adds the index of each new claim to an array (`subgames[_challengeIndex]`) that represents the subgame rooted at the parent claim. As the game progresses and more moves are made, this array can grow indefinitely.
If the array becomes very large, operations that need to iterate over it could become prohibitively expensive in terms of gas, potentially leading to a situation where the game becomes unresolvable due to exceeding block gas limits.

## Recommended Mitigation Steps
- Implement a cap on the number of claims that can be made in a single subgame.
- Implement a mechanism to prune or compress the subgame data as the game progresses.
