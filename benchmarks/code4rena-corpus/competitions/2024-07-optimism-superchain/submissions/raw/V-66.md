# Vulnerability details

## Impact
The vulnerability exists in the `getChallengerDuration` function, which calculates the remaining time for a challenger to respond to a claim based on the parent’s clock. The specific issue arises when the parent indexer does not exist, and the function uses the default value of `type(uint32).max`.


## Proof of Concept
In the `getChallengerDuration` function:

- If `subgameRootClaim.parentIndex != type(uint32).max`, the function correctly uses the parent’s clock to compute the remaining challenge duration.
- However, if `subgameRootClaim.parentIndex == type(uint32).max` (indicating there is no valid parent claim), the function defaults to using an uninitialized `Clock` object, `parentClock`.
- The uninitialized `parentClock` has its properties (`timestamp` and `duration`) set to their default values, which are likely zeros.
- Consequently, the challenge duration calculation subtracts zero from the current `block.timestamp`, resulting in an incorrectly elevated challenge duration, which disrupts the intended timing logic for challenges.

## Recommended Mitigation Steps
To prevent this issue:
- Add a check in the `getChallengerDuration` function to ensure that if the parent index is `type(uint32).max`, the function immediately returns a reasonable default `Duration` or triggers error handling logic.
- Additionally, ensure proper initialization and validation checks when updating or setting parent indexes to prevent such scenarios.
