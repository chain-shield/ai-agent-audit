# Vulnerability details

## Impact
Silent integer overflows and underflows leading to incorrect calculation results.

## Proof of Concept
In the execute function, the add instruction (func 0x20) is implemented as follows:
```
// add
//*@audit-info ------->>> could be overflow 
else if (func == 0x20) {
    return (rs + rt);
}
```

This implementation directly adds the two 32-bit unsigned integers rs and rt without checking for overflow or underflow. In MIPS architecture, the add instruction should trigger an exception on overflow, but this behavior is not replicated in the current implementation.
Moreover, the function is wrapped in an unchecked block, which means that even Solidity's built-in overflow checks (in versions 0.8.0 and above) are disabled.
While unsigned integers cannot underflow in the traditional sense, the lack of proper signed integer handling can lead to unexpected results when dealing with negative numbers in two's complement representation.
