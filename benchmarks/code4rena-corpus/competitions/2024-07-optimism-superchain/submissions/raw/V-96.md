# Vulnerability details

# Description: 
The for-loop in `resolveClaim` iterates through `challengeIndices`. However if `numToResolve` is excessively large this could cause a denial of service if the loop-iteration hits the block's gas limit.



```solidity
   /// @inheritdoc IFaultDisputeGame
@>    function resolveClaim(uint256 _claimIndex, uint256 _numToResolve) external {

@>        if (_numToResolve == 0) _numToResolve = challengeIndicesLen;

        uint256 finalCursor = lastToResolve > challengeIndicesLen ? challengeIndicesLen : lastToResolve;
@>        for (uint256 i = checkpoint.subgameIndex; i < finalCursor; i++) {
            uint256 challengeIndex = challengeIndices[i];

            // code ...
        }

        // code ..

```

# Impact:
The for-loop is responsible for updating `checkpoint.counteredBy` and `checkpoint.leftmostPosition`. These updates will be interrupted if the unbounded for-loop starts to consume more gas units than the block gas limit. A DoS will then ensue.

# Recommended Mitigation:
A maximum number of iterations can be determined, and a check could be conducted to ensure that `_numToResolve` doesn't exceed this.

```solidity
    require(_numToResolve <= MAX_ITERAION, "this number could cause DoS due to insufficient gas");
```
