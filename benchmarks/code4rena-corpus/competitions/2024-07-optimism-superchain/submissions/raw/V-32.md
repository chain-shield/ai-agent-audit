# Vulnerability details

## Summary 

* The function `getChallengerDuration()` returns an improper value due to a flawed check in the code. The line in question is

FaultDisputeGame.sol#L785

```
duration_ = challengeDuration > MAX_CLOCK_DURATION.raw() ? MAX_CLOCK_DURATION : Duration.wrap(challengeDuration);

```

* This function is used in both `move()` and `resolveClaim()` functions. Due to the incorrect return value from `getChallengerDuration()`, the `resolveClaim()` function encounters a revert.

Issue Details:

The `getChallengerDuration()` function contains the following logic:

FaultDisputeGame.sol#L785

```
duration_ = challengeDuration > MAX_CLOCK_DURATION.raw() ? MAX_CLOCK_DURATION : Duration.wrap(challengeDuration);

```

* This check ensures that duration_ will never exceed `MAX_CLOCK_DURATION`. However, if the returned value is less than `MAX_CLOCK_DURATION`, it conflicts with the check in the `resolveClaim()` function:


FaultDisputeGame.sol#L570

```
if (challengeClockDuration.raw() < MAX_CLOCK_DURATION.raw()) revert ClockNotExpired();

```

Since `getChallengerDuration()` always returns a value less than or equal to `MAX_CLOCK_DURATION`, the `resolveClaim()` function will always revert when called, as it expects the challengeClockDuration to be equal to `MAX_CLOCK_DURATION`.



## Impact

Due to the improper return value of `getChallengerDuration()`, the `resolveClaim()` function is rendered non-functional. This bug effectively prevents users from successfully calling `resolveClaim()`, as it will always revert due to the condition check.


## Proof of Concept

Assume `MAX_CLOCK_DURATION = 55`.

**Function Calls and Results:**

| `challengeDuration` | Comparison (`challengeDuration > MAX_CLOCK_DURATION`) | `getChallengerDuration()` Result | `move()` Result | `resolveClaim()` Result |
|---------------------|-------------------------------------------------------|----------------------------------|------------------|-------------------------|
| 50                  | 50 > 55 = false                                       | 50                               | pass             | revert                  |
| 55                  | 55 > 55 = false                                       | 55                               | pass             | revert                  |
| 56                  | 56 > 55 = true                                        | 55                               | revert           | revert                  |

**Explanation:**

- For `challengeDuration = 50`:
  - Comparison: `50 > 55` is false.
  - `getChallengerDuration()` returns `50`.
  - `move()` function passes.
  - `resolveClaim()` function reverts due to `challengeClockDuration.raw() < MAX_CLOCK_DURATION.raw()`.

- For `challengeDuration = 55`:
  - Comparison: `55 > 55` is false.
  - `getChallengerDuration()` returns `55`.
  - `move()` function passes.
  - `resolveClaim()` function reverts due to `challengeClockDuration.raw() < MAX_CLOCK_DURATION.raw()`.

- For `challengeDuration = 56`:
  - Comparison: `56 > 55` is true.
  - `getChallengerDuration()` returns `55`.
  - `move()` function reverts due to `challengeClockDuration.raw() < MAX_CLOCK_DURATION.raw()`.
  - `resolveClaim()` function reverts due to `challengeClockDuration.raw() < MAX_CLOCK_DURATION.raw()`.
