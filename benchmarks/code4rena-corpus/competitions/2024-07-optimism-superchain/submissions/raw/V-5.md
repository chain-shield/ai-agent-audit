# Vulnerability details

## Impact
Having a single externally owned account (EOA) as the sole owner of critical contract functions poses a significant centralization risk. If the private key of this EOA is compromised, lost, or becomes inaccessible, it can lead to the loss of control over the contract's functionality, potentially causing severe financial and operational damage. This single point of failure undermines the security and reliability of the contract.

## Proof of Concept
In the *'DisputeGameFactory.sol'* file, the functions *'setImplementation'* and *'setInitBond'* are both protected by the *'onlyOwner'* modifier, meaning only the single owner can execute these critical functions.
```
function setImplementation(GameType _gameType, IDisputeGame _impl) external onlyOwner {
    gameImpls[_gameType] = _impl;
    emit ImplementationSet(address(_impl), _gameType);
}

function setInitBond(GameType _gameType, uint256 _initBond) external onlyOwner {
    initBonds[_gameType] = _initBond;
    emit InitBondUpdated(_gameType, _initBond);
}
```

## Tools Used
Manual Review

## Recommended Mitigation Steps
1. Implement Multi-Signature Wallet: Replace the single owner with a multi-signature wallet such as Gnosis Safe, which requires multiple approvals from different parties to execute critical functions.

2. Role-Based Access Control: Introduce a role-based authorization model using libraries such as OpenZeppelin's *'AccessControl'*, allowing different roles to perform specific actions while distributing the control and reducing the risk associated with a single point of failure.
