# Vulnerability details

## Impact
This vulnerability allows attackers to pre-empt the initialization process, allowing them to set their own values, take ownership of the contract, or in the best case force re-deployment of the contract. This may result in loss of control of the contract by the rightful owner and potential loss of funds or sensitive information.

## Proof of Concept
```
// Example of a vulnerable DisputeGameFactory.sol contract
contract DisputeGameFactory is OwnableUpgradeable {
    function initialize(address _owner) public initializer {
        __Ownable_init();
        _transferOwnership(_owner);
    }
}

// The attacker sends the initialization transaction before the legitimate owner
DisputeGameFactory factory = new DisputeGameFactory();
factory.initialize(attackerAddress); // The attacker sets himself as the owner of the contract
```

## Tools Used
Manual review

## Recommended Mitigation Steps
1. Use a separate initializer:
Separate the initialization logic into a separate contract that can only be called by the parent contract or by a secure deployment process.
```
contract DisputeGameFactory is OwnableUpgradeable {
    function initialize(address _owner) public {
        require(msg.sender == deployer, "Unauthorized");
        __Ownable_init();
        _transferOwnership(_owner);
    }
}
```

2. Verify initialization status:
Add additional verification to ensure that initialization only occurs once and by an authorized party.
```
contract DisputeGameFactory is OwnableUpgradeable {
    bool private initialized;

    function initialize(address _owner) public {
        require(!initialized, "Already initialized");
        initialized = true;
        __Ownable_init();
        _transferOwnership(_owner);
    }
}
```
