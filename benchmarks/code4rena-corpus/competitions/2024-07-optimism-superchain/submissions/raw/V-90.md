## Vulnerabilities in the Contract

### **Incorrect Use of Assembly for Array Management**
**Issue:**
The use of inline assembly for array manipulation in `findLatestGames` is complex and prone to errors.

**Impact:**
Improper use of assembly can lead to unexpected behavior, memory corruption, or inefficient gas usage.

**Solution:**
Use native Solidity constructs to handle dynamic arrays, making the code more readable and safer.

```solidity
function findLatestGames(
    GameType _gameType,
    uint256 _start,
    uint256 _n
)
    external
    view
    returns (GameSearchResult[] memory games_)
{
    // If the `_start` index is greater than or equal to the game array length or `_n == 0`, return an empty array.
    if (_start >= _disputeGameList.length || _n == 0) return new GameSearchResult ;

    // Allocate enough memory for the full array, but start the array's length at `0`.
    games_ = new GameSearchResult[](_n);
    uint256 count = 0;

    // Perform a reverse linear search for the `_n` most recent games of type `_gameType`.
    for (uint256 i = _start; i < _disputeGameList.length && count < _n; i++) {
        GameId id = _disputeGameList[i];
        (GameType gameType, Timestamp timestamp, address proxy) = id.unpack();

        if (gameType.raw() == _gameType.raw()) {
            bytes memory extraData = IDisputeGame(proxy).extraData();

            games_[count] = GameSearchResult({
                index: i,
                metadata: id,
                timestamp: timestamp,
                rootClaim: rootClaim,
                extraData: extraData
            });
            count++;
        }
    }

    // Resize the array to the actual count of found games.
    assembly {
        mstore(games_, count)
    }
