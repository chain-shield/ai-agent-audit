# Vulnerability details

## Vulnerability detail
The `step` function in `FaultDisputeGame.sol` contains an incorrect revert condition, which can allow invalid game steps to proceed while potentially preventing valid steps from executing.
Incorrect Condition
The current implementation checks if both `validStep` and `parentPostAgree` are either true or false to determine if the function should revert:

```solidity
if (parentPostAgree == validStep) revert ValidStep();
```
This condition is incorrect because it reverts the transaction when both conditions are either true or false, rather than when one or both conditions indicate an invalid state.
## Impact
The incorrect revert condition impacts the game in several critical ways:

- Invalid Moves Allowed: If `validStep` is true and `parentPostAgree` is false or vice-versa, the step will not revert, allowing an invalid move to proceed. This undermines the integrity of the game by permitting moves that should be disallowed based on the game's rules.

- Valid Moves Prevented: If both `validStep` and `parentPostAgree` are true, the step will revert, incorrectly preventing a valid move. This can frustrate users and halt game progress, as legitimate actions are blocked by the erroneous logic.
