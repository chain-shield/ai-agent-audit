# Vulnerability details

## Impact

The `FaultDisputeGame.move` function is used as the generic move function for both `attack` and `defend` moves. In the function execution there is following `Invariant` which is secured. 

INVARIANT: A defense can never be made against the root claim of either the output root game or any of the execution trace bisection subgames.

The implementation of the above `Invariant` is given as follows:

```solidity
        if ((_challengeIndex == 0 || nextPositionDepth == SPLIT_DEPTH + 2) && !_isAttack) {
            revert CannotDefendRootClaim();
        }
```

As per the `invariant` it is stated that the `defense` can never be made against the root claim of the execution trace bisection subgames. The root claim of the execution trace subgames is the `SPLIT_DEPTH + 1` which is one level below the `SPLIT_DEPTH`, but in the above logic implementation of the invariant the `SPLIT_DEPTH + 2` is used as the `root claim` of the `execution trace bisection subgames`. Hence the function implementation does not actually check the `root claim` of the `execution trace bisection subgames` but a level below that. 

Hence the above implementation allows a `defense` to be made against the root claim of the `execution trace bisection subgames` which is contrary to what is stated by the `invariant`. In addition to that the above implementation will prevent a `defense` being made against the child claim of the `root claim` of the `execution trace bisection subgames`, which is not the intended behavior of the dispute games.

## Recommended Mitigation Steps

Hence it is recommended to update the above logic implementation to check the `root claim` of the `execution trace bisection subgames` which is the `SPLIT_DEPTH + 1` and the `defense` should not be allowed at this level.

```solidity
        if ((_challengeIndex == 0 || nextPositionDepth == SPLIT_DEPTH + 1) && !_isAttack) {
            revert CannotDefendRootClaim();
        }
```
