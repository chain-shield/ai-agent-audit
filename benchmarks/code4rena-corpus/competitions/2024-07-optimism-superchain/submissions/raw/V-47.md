# Vulnerability details

## Impact

if try to call `initLPP` twice , previous funds may get stuck

## Proof of Concept

in function `initLPP` ,there seems don't have any measures to control user init LPP twice with same params. 
Function don't check this  caller's  uuid has been set  or not. 
Let's say  if user try to call  `initLPP` twice due to double click in front end or backend send duplicate msgs, 
,the result is array `proposals`  may exist  duplicate value, and  the previous msg.value may be overided and this 
part of funds may gets stuck in contract.
