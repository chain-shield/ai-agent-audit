# Vulnerability details

## Impact
Any claim including the root claim that is attacked by another false claim will be seen as valid hence allowing an invalid root claim to resolve 

## Proof of Concept
using a simple example 
```
bob creates a game with claim x 
bob malicious attacks his claim with another claim y ensuring it is not possible to attack bobs root claim anymore 
bob then attacks y with a valid claim at position z, once again ensuring it is not possible to place an attack on y
assuming z is not challenged because it is valid claim at that position or it is attacked but the attack failed because z is valid 
when y is being resolved counteredBy will be set to the claimant of z which is bob himself according to 
``
      if (
        claim.counteredBy == address(0) &&
        checkpoint.leftmostPosition.raw() > claim.position.raw()
      ) {
        checkpoint.counteredBy = claim.claimant;
        checkpoint.leftmostPosition = claim.position;
      }
claim.counteredBy == address(0) will be zero because z is valid 
this logic basically says if an attack towards this claim was successful then the claim is invalid and if not the claim is valid 
``
``

``
when resolving x, because the counteredBy of y is not address(0) hence because the attacking claim is invalid then the claim is valid is seen as valid ie the counteredBy remains at address(0)
when resolve() is called the counteredBy of x will be address(0) hence the defendant wins with an invalid claim 
```
