# Vulnerability details

## Impact
Break of Protocol Invariant as the incorrect depth check in the step function allows for invalid step executions, leading to break of proper contract functionality. This can result in unauthorized moves in the game logic, compromising the integrity of the game and its rules. This can be exploited to manipulate the game's state unfairly, which would affect all participants negatively and undermine trust in the contract.

#### Explanation
The invariant mentioned in the comment above the pointer in the code above in the step(...) function from the FaultDisputeGame.sol contract indicates that a step can only be made if the move position is 1 below the MAX_GAME_DEPTH. This means the depth should be MAX_GAME_DEPTH - 1. However, the current implementation checks for MAX_GAME_DEPTH + 1, which contradicts the invariant and allows for invalid steps to be executed.

#### Example
Assuming MAX_GAME_DEPTH is set to 5:

The valid depth for a step should be MAX_GAME_DEPTH - 1 which is 4.
The current code checks for MAX_GAME_DEPTH + 1 which is 6, an incorrect depth.
