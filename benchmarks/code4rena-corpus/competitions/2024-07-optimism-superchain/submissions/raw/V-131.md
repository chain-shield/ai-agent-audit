# Vulnerability details

## Description

In the `FaultDisputeGame` contract, there's an issue with check. The comment suggests that a move should be prevented if the clock has exceeded the maximum duration, but the code only checks for exact equality.

## Current Behavior

The current implementation in the `move` function is:

```solidity
// INVARIANT: A move can never be made once its clock has exceeded `MAX_CLOCK_DURATION`
//            seconds of time.
if (nextDuration.raw() == MAX_CLOCK_DURATION.raw()) revert ClockTimeExceeded();
```

This check only prevents moves when the clock duration is exactly equal to `MAX_CLOCK_DURATION`, not when it exceeds it.

## Expected Behavior

The check should prevent moves when the clock duration is greater than or equal to `MAX_CLOCK_DURATION`, to align with the comment and ensure that no moves can be made once the maximum duration has been reached or exceeded.

## Mitigation

Update the condition to use greater than or equal to:

```solidity
if (nextDuration.raw() >= MAX_CLOCK_DURATION.raw()) revert ClockTimeExceeded();
```

## Impact

The current implementation still prevents moves at the exact `MAX_CLOCK_DURATION`, but it could potentially allow moves if the duration somehow exceeded this value.

## Steps to Reproduce

1. Deploy the `FaultDisputeGame` contract
2. Initiate a game and make moves until a claim's clock reaches exactly `MAX_CLOCK_DURATION`
3. Attempt to make a move against this claim (this will currently revert as expected)
4. If possible, manipulate the clock to exceed `MAX_CLOCK_DURATION` (this may require modifying the contract for testing purposes)
5. Attempt to make a move against the claim with an exceeded clock (this would currently succeed, which is not the intended behavior)
