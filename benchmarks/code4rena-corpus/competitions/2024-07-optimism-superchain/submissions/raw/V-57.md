# Vulnerability details

## Summary

When there is a Dispute Game, both the challenger and the defender has a timer. If the game is played within `MAX_CLOCK_DURATION` and `CLOCK_EXTENSION`, the clock will not time out until the game reaches its `MAX_DEPTH` and be resolved from there.

## Impact

The deadline will not be as effective as intended.

## Proof of Concept

When the game is played, both parties have a clock that counts until `MAX_CLOCK_DURATION`. If their time is before `MAX_CLOCK_DURATION` but after `MAX_CLOCK_DURATION - CLOCK_EXTENSION`, then their time will be set to `MAX_CLOCK_DURATION - CLOCK_EXTENSION`.

```
        // If the remaining clock time has less than `CLOCK_EXTENSION` seconds remaining, grant the potential
        // grandchild's clock `CLOCK_EXTENSION` seconds. This is to ensure that, even if a player has to inherit another
        // team's clock to counter a freeloader claim, they will always have enough time to to respond. This extension
        // is bounded by the depth of the tree. If the potential grandchild is an execution trace bisection root, the
        // clock extension is doubled. This is to allow for extra time for the off-chain challenge agent to generate
        // the initial instruction trace on the native FPVM.
        if (nextDuration.raw() > MAX_CLOCK_DURATION.raw() - CLOCK_EXTENSION.raw()) {
            // If the potential grandchild is an execution trace bisection root, double the clock extension.
            uint64 extensionPeriod =
                nextPositionDepth == SPLIT_DEPTH - 1 ? CLOCK_EXTENSION.raw() * 2 : CLOCK_EXTENSION.raw();
>           nextDuration = Duration.wrap(MAX_CLOCK_DURATION.raw() - extensionPeriod);
        }
```

Assume Alice is the defender and Bob is the challenger. The `MAX_CLOCK_DURATION` is one day and `CLOCK_EXTENSION` is 1 hours.

Alice creates the Fault Dispute Game with an output root at time T1, and Bob's timer starts from 0. 

At time T2 (one hour later), Bob challenges the claim with an attack. Alice timer starts counting from 0 upwards. 

At time T3 (23.5 hours later), Alice disputes the attack with another attack. Since Alice timer is within 1 hour of `MAX_CLOCK_DURATION`, Alice timer is set back to 23 hours. Bob timer starts counting from 1 hour.

At time T4 (22.5 hours later), Bob disputes Alice claim. Since Bob timer is now 23.5 hours, it is within the hour of `MAX_CLOCK_DURATION` and the timer resets to 23 hours. Alice timer starts counting from 23 hour.

At time T5...T6.. until the game reaches `MAX_DEPTH`, as long as Bob and Alice plays within the `CLOCK_EXTENSION` period, the clock is extended indefinitely and Alice and Bob will always have `CLOCK_EXTENSION` to counter the claim.

This is not the intended case. What should happen is if Bob fails to defend his claim with a move before `MAX_DEPTH`, all his future claims should be reverted and Alice should be the default winner, and vice versa.
