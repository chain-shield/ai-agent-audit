# Vulnerability details

## Impact
The line in question is intended to prevent the resolution of a subgame that has already been resolved. However, the logic appears inverted, which could lead to incorrect behavior.
Potential Issues
Inverted Logic:
The condition checks if the subgame is not resolved 
```solidity
(!resolvedSubgames[_claimIndex]) and then reverts with ClaimAlreadyResolved(). 
```
This should instead check if the subgame is resolved.
The revert message ``ClaimAlreadyResolved()`` is misleading because the condition checks for unresolved subgames.
Impact of this bug can prevent the correct resolution of subgames, leading to unresolved disputes and potential loss of funds or incorrect game outcomes.

## Proof of Concept
https://github.com/code-423n4/2024-07-optimism/blob/70556044e5e080930f686c4e5acde420104bb2c4/packages/contracts-bedrock/src/dispute/FaultDisputeGame.sol#L572-L573
The problematic code is in the resolveClaim function:
```solidity
// INVARIANT: Cannot resolve a subgame twice.
if (resolvedSubgames[_claimIndex]) revert ClaimAlreadyResolved();
```
To demonstrate the issue:
A subgame at ``_claimIndex`` is resolved for the first time.
``resolvedSubgames[_claimIndex]`` is set to true.
In a subsequent call to ``resolveClaim`` for the same ``_claimIndex``:
The condition ``resolvedSubgames[_claimIndex]`` is true
The function reverts with ``ClaimAlreadyResolved()``
This prevents any further processing, including for unresolved subgames

## Recommended Mitigation Steps
To fix this, the condition should be:
```solidity
if (resolvedSubgames[_claimIndex]) revert ClaimAlreadyResolved();
```
Consider renaming the error to better reflect its purpose:
```solidity
if (resolvedSubgames[_claimIndex]) revert SubgameAlreadyResolved();
```
Additional Considerations could be ensuring that ``resolvedSubgames[_claimIndex]`` is correctly updated during the resolution process to avoid false positives.
