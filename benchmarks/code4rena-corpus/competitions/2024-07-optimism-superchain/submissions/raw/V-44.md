# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-optimism/blob/2e11e15e7a9a86f90de090ebf9e3516279e30897/packages/contracts-bedrock/src/cannon/PreimageOracle.sol#L609-L637

```solidity
    function challengeFirstLPP(
        address _claimant,
        uint256 _uuid,
        Leaf calldata _postState,
        bytes32[] calldata _postStateProof
    )
        external
    {
        // Verify that the leaf is present in the merkle tree.
        bytes32 root = getTreeRootLPP(_claimant, _uuid);
        if (!_verify(_postStateProof, root, _postState.index, _hashLeaf(_postState))) revert InvalidProof();

        // The poststate index must be 0 in order to challenge it with this function.
        if (_postState.index != 0) revert StatesNotContiguous();

        // Absorb and permute the input bytes into a fresh state matrix.
        LibKeccak.StateMatrix memory stateMatrix;
        LibKeccak.absorb(stateMatrix, _postState.input);
        LibKeccak.permutation(stateMatrix);

        // Verify that the post state hash doesn't match the expected hash.
        if (keccak256(abi.encode(stateMatrix)) == _postState.stateCommitment) revert PostStateMatches();

        // Mark the keccak claim as countered.
        proposalMetadata[_claimant][_uuid] = proposalMetadata[_claimant][_uuid].setCountered(true);

        // Pay out the bond to the challenger.
        _payoutBond(_claimant, _uuid, msg.sender);
    }
```

This function is used to challenge the first keccak256 block that was absorbed, issue howeverr is that it includes a wrong check _logically_, that would always cause for the attempt to use this function to revert, this is because the check `   if (_postState.index != 0) revert StatesNotContiguous();`  assumes the postState index would be `0`, but that wouldn't be the case considering this is the first LPP being challenged, hint on how this correctly works can be seen [here](https://github.com/code-423n4/2024-07-optimism/blob/2e11e15e7a9a86f90de090ebf9e3516279e30897/packages/contracts-bedrock/src/cannon/PreimageOracle.sol#L592), so in the case of `PreimageOracle#challengeFirstLPP()` we should instead expect the postImage index to be `1`.

## Impact
`PreimageOracle#challengeFirstLPP()` would always revert due to the current post image check applied which is attempting to ensure the index is `0` instead of `1`.
