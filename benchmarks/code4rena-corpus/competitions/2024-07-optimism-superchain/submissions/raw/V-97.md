# Vulnerability details

## Description
`loadLocalData` in `PreimageOracle` is used to provide local data to the `MIPS VM`. It is one of multiple functions allowing in the `PreimageOracle` enabling storage of data. One of those is `addLeavesLPP` in combination with some more. In `addLeavesLPP` there is a check whether the `claimedSize` (final size) of the content is equal to zero. This is not allowed as we do not want to store zero-size data in the oracle. The problem is, that this check is missing in `loadLocalData` allowing a user to add zero-size content to the oracle.

`loadLocalData`:
```solidity
function loadLocalData(
    uint256 _ident,
    bytes32 _localContext,
    bytes32 _word,
    uint256 _size,
    uint256 _partOffset
)
    external
    returns (bytes32 key_)
{
    // Compute the localized key from the given local identifier.
    key_ = PreimageKeyLib.localizeIdent(_ident, _localContext);

    // Revert if the given part offset is not within bounds.
    if (_partOffset > _size + 8 || _size > 32) {
        revert PartOffsetOOB();
    }

    // Prepare the local data part at the given offset
    bytes32 part;
    assembly {
        // Clean the memory in [0x20, 0x40)
        mstore(0x20, 0x00)

        // Store the full local data in scratch space.
        mstore(0x00, shl(192, _size))
        mstore(0x08, _word)

        // Prepare the local data part at the requested offset.
        part := mload(_partOffset)
    }

    // Store the first part with `_partOffset`.
    preimagePartOk[key_][_partOffset] = true;
    preimageParts[key_][_partOffset] = part;
    // Assign the length of the preimage at the localized key.
    preimageLengths[key_] = _size;
}
```
We can see, that there is no check for `_size == 0`.


## Impact
This results in users being able to add zero-size data which should not be allowed according to this comment in `addLeavesLPP`: `0-size preimages are *not* allowed.`.


## Proof of Concept
In order to execute the PoC, please add it to the tests in `PreimageOracle.t.sol` and execute it with `forge test --match-test test_loadLocalData_zeroSize_succeeds -vv`.

```solidity
function test_loadLocalData_zeroSize_succeeds() public {
    bytes32 word = hex"deadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeefdeadbeef";

    bytes32 contextKey = oracle.loadLocalData(0, 0, word, 0, 0);

    // Validate that the pre-image part is set
    bool ok = oracle.preimagePartOk(contextKey, 0);
    assertTrue(ok);
}
```

## Recommended Mitigation Steps
I would recommend changing the line checking whether the `_partOffset` is OOB to the following:

```solidity
if (_size == 0 || _partOffset > _size + 8 || _size > 32) {
    revert PartOffsetOOB();
}
```
