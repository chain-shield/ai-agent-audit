This function is used for both attack and defend moves, it includes multiple invariants one of which has been highlighted with the @audit tag above.

Issue is that the wrong check is applied for the invariant `==`, instead of `>=` which then means that the invariant would only hold when the  clock is exactly at `MAX_CLOCK_DURATION` and not when it has exceeded `MAX_CLOCK_DURATION` as is expected/documented

## Impact
Core invariant is broken, considering _moves_  can now be made even if the clock has exceeded `MAX_CLOCK_DURATION`.
