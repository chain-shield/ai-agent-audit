# Vulnerability details

## Impact
When there is a withdraw tx (L2 -> L1), the user makes `FDG` for his withdrawal, he puts the data including `l2blockNumber` that contains his withdraw tx from L2ToL1 in Optimism L2 using `DisputeGameFactory`

[DisputeGameFactory.sol#L105-L117](https://github.com/code-423n4/2024-07-optimism/blob/main/packages/contracts-bedrock/src/dispute/DisputeGameFactory.sol#L105-L117) 
```solidity
        // CWIA Calldata Layout:
        // ┌──────────────┬────────────────────────────────────┐
        // │    Bytes     │            Description             │
        // ├──────────────┼────────────────────────────────────┤
        // │ [0, 20)      │ Game creator address               │
        // │ [20, 52)     │ Root claim                         │
        // │ [52, 84)     │ Parent block hash at creation time │
        // │ [84, 84 + n) │ Extra data (opaque)                │
        // └──────────────┴────────────────────────────────────┘
        proxy_ = IDisputeGame(address(impl).clone(abi.encodePacked(msg.sender, _rootClaim, parentHash, _extraData)));
        proxy_.initialize{ value: msg.value }();
```

`Extra data (opaque)` is the `l2blockNumber` of the user, and the game starts from the last finalized `L2blockNumber` (we get it from `ANCHOR_STATE_REGISTRY`) to the block number he withdrew in it.

The number of blocks is determined by `SPLIT_DEPTH` value where the number of blocks equals `2 ^ SPLIT_DEPTH` starting from the next block after that finalized by the state registry.

So `SPLIT_DEPTH` will occupy blocks from `ANCHOR_STATE_REGISTRY + 1` to the `l2blockNumber` and it can have free available Blocks too.

The game is intended to be played (i.e checking for block validity) from the block `ANCHOR_STATE_REGISTRY` last finalized block + 1 till `l2BlockNumber()`. As if the game is finalized correctly `ANCHOR_STATE_REGISTRY` will set the las finalized block to it.

When the fight between Honest and Malicious challengers reaches the bottom, the `VM` becomes the judger of who is telling the truth and who is lying. And for the `VM` to check for this, challengers should add data into the `PreImageOracle` which the `VM` will use to read the data from it and check the validity of claims. But the problem is that when adding `DISPUTED_L2_BLOCK_NUMBER` we are not checking if the L2 Block we are disputing comes before or after the actual `l2blockNumber` of the FGD withdrawal.

As we can see, the `l2Number` is not checked against the actual `l2blockNumber` of this FDG, which can hold a challenge will in a BlockNumber that does not relate to the validity of the Honest Challenger withdrawal.

Since the Data from L2 is added into L1, the Honest Challengar can make withdrawal at block `1000` and after `2` days, there are new `500` blocks, each has its withdrawals, etc...

What the Malicous Challenger can do is that it can force the Honest Root Claimer to Fight between block `1001` and block `1500` and the withdrawal itself is at block `1000`.

We can't count the issues that can occur because of this.
- If there are Bad Roots from block `1000` to block `1500` occurring after the Honest challenger withdraws, it will be used against him to beat him.
- These Blocks do not have user withdrawal tx, so determining the Claim roots for the Honest Challenger can be a little difficult.
- Incorrect Gaming Logic, as the game is designed to finalize to the `l2blockNumber` if `DEFENDER_WINS` so validating further blocks after `l2blockNumber` that has been minted in l2 at the time between withdrawing and deploying the game, or at the period of the dispute is not intended to get validated and challenged against.
- There may be errors in the `VM` like inconsistency or disturbances when doing such steps, as it is like you are validating the future.

## Proof of Concept
- `ANCHOR_STATE_REGISTRY` last finalized block is at `900`
- The Game logic occupies up to `4096` blocks (`SPLIT_DEPTH` is `12`).
- Honest Challenger Withdrawed from (L2 -> L1) at block `1000` in L2.
- The Honest Challenger deployed the game with the correct data.
- Blocks are minting at L2 and we reached block `1500`.
- Block `1200` in L2 has some problems.
- The Malicous Challenger Fights against the Honest one at this block.
- The game's final results will be determined according to this block `1200` state, which the Honest Challengar has nothing to do with it.

_NOTE: we should keep in mind that this will prevent countering the Last Node, and according to the `MAX_GAME_DEPTH` number even or odd, the game can end up with the `CHALLENGER` not the `DEFENDER`, so the Mitigation should be tests carefully according to the configurations and subGames finalizing logic._
