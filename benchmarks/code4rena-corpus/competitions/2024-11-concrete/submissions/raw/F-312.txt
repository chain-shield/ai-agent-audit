S-1080
Withdrawing directly from vault breaks strategy allocation which leads to loss of funds
gesha17
57
Sufficient
383d ago
Finding description and impact

If the requested withdrawal is less than or equal to the vault contract balance, the withdrawal will directly send the funds to the user, without pulling funds from the strategies. However, this creates a problem for other users, as they will still pull funds from the strategies based on their allocation. If allocation is less than 100%, the part of user withdrawal which will be send from the vaults balance will be lost due to insufficient vault balance.

Proof of Concept

Consider this scenario:

Asset to share ratio is 1:1 for simplicity.
1 strategy with 50% allocation
User A deposits 1000e18 assets.

As a result there are 500e18 assets in vault and 500e18 assets in strategy.

User B deposits 200e18 assets

Now, there are 600e18 assets in vault and 600e18 in strategy.

User B submits a withdrawal request for 200e18 assets. Since there are already 600e18 assets in the strategy, they will be directly sent to the user in the first if-statement:

https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L450

function _withdrawStrategyFunds(uint256 amount_, address receiver_) private {
        ...
        // If there is enough in the vault, send the full amount
        if (amount_ <= float) {
            asset_.safeTransfer(receiver_, amount_);
        } else {
        ...
        }
    }

As a result of this transaction there will now be 400e18 assets in the vault and 600e18 assets in the strategy.

User A now attempts to redeem his 1000e18 shares. In the for loop, only 500e18 will be pulled from the strategy:

https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L464

    function _withdrawStrategyFunds(uint256 amount_, address receiver_) private {
        ...
        if (amount_ <= float) {
            asset_.safeTransfer(receiver_, amount_);
        } else {
            ...
            for (uint256 i; i < len; ) {
                ...
                uint256 amountToWithdraw = amount_.mulDiv(
                    strategy.allocation.amount,
                    MAX_BASIS_POINTS,
                    Math.Rounding.Ceil
                );
                ...
            }
            ...
        }
    }

This is because amountToWithdraw is 1000e18 and at 50% allocation, the calculation for amountToWithdraw results in 500e18 assets, so 100e18 assets are left permanently stuck in the strategy.

Then in the final if statement, the user will fail to pull the 400 assets left in the vault:

https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L478

    function _withdrawStrategyFunds(uint256 amount_, address receiver_) private {
        IERC20 asset_ = IERC20(asset());
        //Not in a loop
        //slither-disable-next-line calls-loop
        uint256 float = asset_.balanceOf(address(this));
        // If there is enough in the vault, send the full amount
        if (amount_ <= float) {
            asset_.safeTransfer(receiver_, amount_);
        } else {
            ...
            // If enough wasn't drawn out, use the float (this is due to dust)
            
            if (totalWithdrawn < amount_ && amount_ - totalWithdrawn <= float) {
                asset_.safeTransfer(receiver_, amount_ - totalWithdrawn);
            }
        }
    }

This is because if we substitue in the if-statement amount_ - totalWithdrawn <= float:
1000e18 - 500e18 <= 400e18, which is false so no further withdrawal will happen.

I want to specifically emphasize here, that even if the last if-statement is fixed to send what is left in the vault, the user will still lose 100e18 assets. On the contrary if the first if-statement is fixed then the latter one can still lead to loss of funds due to rounding up when withdrawing. So they are two separate issues. I have submitted a seprate report detailing the issue with the last if-statement.

Recommended mitigation steps

Apply the following change to remove the first if-statement and preserve the strategy allocation invariant during withdrawals:

    function _withdrawStrategyFunds(uint256 amount_, address receiver_) private {
        IERC20 asset_ = IERC20(asset());
        //Not in a loop
        //slither-disable-next-line calls-loop

-        // If there is enough in the vault, send the full amount
-        if (amount_ <= float) {
-            asset_.safeTransfer(receiver_, amount_);
-        } else {
            uint256 diff = amount_ - float;
            uint256 totalWithdrawn = 0;
            uint256 len = strategies.length;
            for (uint256 i; i < len; ) {
                Strategy memory strategy = strategies[i];
                //We control both the length of the array and the external call
                //slither-disable-next-line calls-loop
                uint256 withdrawable = strategy.strategy.previewRedeem(strategy.strategy.balanceOf(address(this)));
                if (diff.mulDiv(strategy.allocation.amount, MAX_BASIS_POINTS, Math.Rounding.Ceil) > withdrawable) {
                    revert InsufficientFunds(strategy.strategy, diff * strategy.allocation.amount, withdrawable);
                }
                uint256 amountToWithdraw = amount_.mulDiv(
                    strategy.allocation.amount,
                    MAX_BASIS_POINTS,
                    Math.Rounding.Ceil

                //We control both the length of the array and the external call

                strategy.strategy.withdraw(amountToWithdraw, receiver_, address(this));
                totalWithdrawn += amountToWithdraw;
                unchecked {
                    i++;
                }
            }
            // If enough wasn't drawn out, use the float (this is due to dust)
            if (totalWithdrawn < amount_ && amount_ - totalWithdrawn <= float) {
                asset_.safeTransfer(receiver_, amount_ - totalWithdrawn);
            }
-        }
