S-511
ClaimRouter::requestToken() assumes that every cascade token is a stablecoin with 6 decimals.
sl1
68
Sufficient
383d ago
Bug description

The ClaimRouter serves as the connection between Concrete's Borrow flow and Earn flow. One of the responsibilities of the ClaimRouter is managing and routing claim requests from users with blueprints.

To make a borrow request, user with blueprint has to call ClaimRouter::requestToken(), which will try to find protection strategy to borrow from. If there is no protection strategy with enough balance itself or in its related vault, it will trigger the token cascade mechanism. The token cascade is a list of preferred tokens to borrow from in case any of the vaults of the requested token don't have enough balance to fulfill a request.

ClaimRouter.sol#L193-L211

(address protectionStrat, bool requiresFunds) = _getStrategy(
    tokenAddress,
    amount
);
// @audit-info if no such strategy is found => trigger token cascade
if (protectionStrat == address(0x0)) {
    //iterates over array
    uint256 len = tokenCascade.length;
    for (uint256 i; i < len; ) {
        //We avoid using the same token as the one that failed
        if (tokenAddress == tokenCascade[i]) {
            unchecked {
                i++;
            }
            continue;
        }
        //TODO change amount
        amount = _convertFromTokenToStable(tokenAddress, amount_);
        //We control both the length of the array and the external call
        // slither-disable-next-line calls-loop
        (protectionStrat, requiresFunds) = _getStrategy(
            tokenCascade[i],
            amount
        );

The issue is that here amount is always in 6 decimals of precision, while _getStrategy() expects the precision of the asset. Here is how the amount is calculated in _convertFromTokenToStable().

OraclePlug.sol#L49-L53

price
    .mulDiv(tokenAmount_, 10 ** quoteDecimals, Math.Rounding.Floor)
    .mulDiv(
        10 ** CONCRETE_USD_DECIMALS,
        10 ** tokenDecimals,
        Math.Rounding.Floor
    );

In the first call to mulDiv() the result value will have tokenDecimasl of precision, and the second call will result in CONCRETE_USD_DECIMALS of precision, which is set to 6.

Now, when _getStrategy() is called, it will try to look for a strategy that has enough balance and the least amount of yield.

ClaimRouter.sol#L153-L160

if (
    IProtectStrategy(protectionStrat)
        .getAvailableAssetsForWithdrawal() >=
    amount &&
    (protectionStratYield < maxYieldFound || requiresFunds)
) {
    selectedProtectionStrat = protectionStrat;
    requiresFunds = false;
    maxYieldFound = protectionStratYield;
}

If we look at the getAvailableAssetsForWithdrawal() function of the protect strategy, we will see that _getStrategy() tries to compare the amount in 6 decimals of precision against the amount in tokenDecimals of precision.

ProtectStrategy.sol#L82-L84

function getAvailableAssetsForWithdrawal() public view returns (uint256) {
    return IERC20(asset()).balanceOf(address(this));
}

After the strategy has been found, requestToken() will call executeBorrowClaim() on the protection strategy passing an amount in 6 decimals of precision.

ClaimRouter.sol#L225

IProtectStrategy(protectionStrat).executeBorrowClaim(
    amount,
    userBlueprint
);

executeBorrowClaim() will transfer an incorrect amount of tokens, if token decimals are not equal to 6.

ProtectStrategy.sol#L131-L144

function executeBorrowClaim(
    uint256 amount,
    address recipient
) external override onlyClaimRouter {
    if (amount == 0) revert ZeroAmount();
    uint256 balance = getAvailableAssetsForWithdrawal();
    if (balance < amount) {
        _requestFromVault(amount - balance);
    }
    borrowDebt += amount;
    
    IERC20(asset()).safeTransfer(recipient, amount);
    emit BorrowClaimExecuted(amount, recipient);
}

Assume a scenario where the cascade token is GUSD, which has 2 decimals of precision. There is a vault with protect strategy holding 1_000_000e2 of GUSD. The price of ETH is 4000 USD and the user requests 0.025 ETH worth 100 USD. As the ETH vault does not have a protect strategy, the cascade is triggered. _convertFromTokenToStable() returns 100e6 as the amount requested, which is then passed to the GUSD protect strategy. The GUSD protect strategy transfers the whole balance of GUSD to the user.

Impact

A decimal mismatch in ClaimRouter::requestToken() will lead to loss of funds.

Proof of Concept

Please add this test to ClaimRouter.t.sol and run it with forge test --match-test 'test_sl1DecimalsMismatch'.

function test_sl1DecimalsMismatch() public {
    MockERC20 gUSD = new MockERC20("Gemini USD", "gUSD", 2);
    MockERC20 ETH = new MockERC20("Ethereum", "ETH", 18);
    // set gUSD as the only cascade token
    address[] memory cascade = new address[](1);
    cascade[0] = address(gUSD);
    ClaimRouter claimRouter1 = new ClaimRouter(
        admin,
        address(vaultRegistry),
        address(tokenRegistry),
        blueprints,
        cascade
    );
    ConcreteMultiStrategyVault ethVault = _createVault(ETH);
    ConcreteMultiStrategyVault gUSDVault = _createVault(gUSD);
    // Create protect strategy with gUSD as the base asset
    ProtectStrategy gUSDStrategy = new ProtectStrategy(
        gUSD,
        feeRecipient,
        admin,
        address(claimRouter1),
        address(gUSDVault)
    );
    string memory ETHgUSDPair = "ETH/gUSD";
    string[] memory currencyPair = new string[](1);
    currencyPair[0] = ETHgUSDPair;
    oracle.addCurrencyPairs(currencyPair);
    oracle.setPriceDecimalsAndTimestamp(
        "ETH/gUSD",
        int256(4000 * 10 ** ORACLE_QUOTE_DECIMALS),
        ORACLE_QUOTE_DECIMALS,
        1
    );
    // register the token with the TokenRegistry
    vm.prank(admin);
    tokenRegistry.registerToken(
        address(ETH), // token Address
        false, // is Reward
        address(oracle), // oracleAddr_,
        ORACLE_QUOTE_DECIMALS, // oracleDecimals_,
        ETHgUSDPair
    ); // oraclePair_
    Strategy memory newStrategy = Strategy({
        strategy: IStrategy(address(gUSDStrategy)),
        allocation: Allocation({index: 0, amount: 3333})
    });
    vm.prank(admin);
    // Add gUSD strategy to the gUSD vault
    gUSDVault.addStrategy(0, false, newStrategy);
    // gUSD strategy has 1_000_000 of gUSD
    gUSD.mint(address(gUSDStrategy), 1000000e2);
    assertEq(gUSD.balanceOf(address(gUSDStrategy)), 1000000e2);
    // request 0.025 ETH, which equals 100$ with a price of 4000$
    // as ETH vault does not have protect strategy, it triggers the cascade
    // gUSD is the cascade token, so it should transfer 100e2 of gUSD, which would equal 100$
    assertEq(gUSD.balanceOf(blueprints[0]), 0);
    vm.prank(blueprints[0]);
    claimRouter1.requestToken(
        VaultFlags.BUFFER,
        address(ETH),
        0.025e18,
        payable(blueprints[0])
    );
    // While user only requested 100$ worth of ETH, he got transferred 100_000$ worth of gUSD
    assertEq(gUSD.balanceOf(address(gUSDStrategy)), 0);
    assertEq(gUSD.balanceOf(blueprints[0]), 1000000e2);
}

Before proceeding claimRouter should convert stable amount into amount in cascade token.
