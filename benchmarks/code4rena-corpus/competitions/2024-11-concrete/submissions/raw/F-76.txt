S-398
Protocol takes performance fee even if the share rate has dropped
deadrxsezzz
61
Sufficient
383d ago
Finding description and impact

The modifier takeFees is responsible to take two types of fees - time-based one and a performance based one. The problem is that the performance fee one does not take into account the time-based one and therefore results in possible take of a performance fee, even in situations where the share rate has dropped.

Proof of Concept
    ///@notice Modifier that allows protocol to take fees
    modifier takeFees() {
        uint256 totalFee = accruedProtocolFee() + accruedPerformanceFee();
        uint256 shareValue = convertToAssets(1e18);
        uint256 _totalAssets = totalAssets();

        if (shareValue > highWaterMark) highWaterMark = shareValue;

        if (totalFee > 0 && _totalAssets > 0) {
            uint256 supply = totalSupply();
            uint256 feeInShare = supply == 0
                ? totalFee
                : totalFee.mulDiv(supply, _totalAssets - totalFee, Math.Rounding.Floor);
            _mint(feeRecipient, feeInShare);
        }
        feesUpdatedAt = block.timestamp;
        _;
    }

Consider the following situation - since the last time takeFees has been invoked, the protocol has accrued 1% yield from its strategies, but also enough time has gone by that there's 2% in time-based protocol fee.

Now, even though that the share rate's value has dropped by 1%, because the performance fee doesn't account for the protocol fee, it will calculate a performance fee for the 1% yield. Not only the users were at a loss, but they've also been charged a performance fee on top of it.

Note that even in situations where the protocol has been profitable, it would still calculate the performance fee at a higher share rate than what it is in reality, resulting in a loss for the users.

Recommended mitigation steps

First distribute the protocol fee and then calculate the performance fee.

Incorrect assumptions, this issue should be invalid.

0xStalin

The protocolFee is charged overtime based on the totalAssets under management, regardless if the vault generated a profit or a loss.

This fee is the to be paid for the management of assets.

The performanceFee is only charged when the shareValue has gone up more than the last highest value, which is tracked on the highWaterMark variable.

This fee is only paid on the profits made since the last highest value of shareValue.

We can corroborate the previous statements from Investopedia.

This means, there can be the next 2 possible states:

A profit is generated on the Vault.
performanceFee is charged based on whatever is the generated yield, regardless if is that yield is lower or bigger than the protocolFee. protocolFee is charged without regard to returns
A loss happens on the vault.
performanceFee is not charged because in this scenario, shareValues won't exceed the highWaterMark, all the opposite, shareValues will decrase from its latest highest value.

We can verify that performanceFee is only charged on the exceess above the highest shareValue has ever been.

modifier takeFees() {
    //@audit-info => performanceFee is only computed when current shareValue exceeds the highWaterMark.
    uint256 totalFee = accruedProtocolFee() + accruedPerformanceFee();
    //@audit-info => Current shareValue
    uint256 shareValue = convertToAssets(1e18);
    uint256 _totalAssets = totalAssets();

    //@audit => Each time the shareValue exceeds the current highWaterMark, shareValue is saved as the new highWaterMark.
    if (shareValue > highWaterMark) highWaterMark = shareValue;

    if (totalFee > 0 && _totalAssets > 0) {
        uint256 supply = totalSupply();
        uint256 feeInShare = supply == 0
            ? totalFee
            : totalFee.mulDiv(supply, _totalAssets - totalFee, Math.Rounding.Floor);
        _mint(feeRecipient, feeInShare);
    }
    feesUpdatedAt = block.timestamp;
    _;
}

function accruedPerformanceFee() public view returns (uint256 fee) {
    // Calculate the share value in assets
    uint256 shareValue = convertToAssets(1e18);

    //@audit-ok => performanceFee is only computed when shareValue exceeds highWaterMark.
        //@audit-info => Whenever a loss occurs on the Vault, no performanceFee will be charged until shareValue recovers and exceeds its highest value that has ever been.
    // Only calculate if a performance fee is set and the share value exceeds the high water mark
    if (fees.performanceFee.length > 0 && shareValue > highWaterMark) {
        fee = MultiStrategyVaultHelper.calculateTieredFee(shareValue, highWaterMark, totalSupply(), fees);
    }
}



All in all, this submission attempts to outline scenarios that works as expected, both fees are correctly charged on all type of scenarios.
