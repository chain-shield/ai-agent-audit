S-934
`removeStrategy()` can be DoSed by sending 1 wei to the to-be-deleted strategy
thekmj
75
Sufficient
383d ago
Summary

MultiStrategyVaultHelper.removeStrategy() has an erroneous check that can be easy force-failed. This allows removing a strategy to be easy DoS-ed by anyone.

Finding description

When a strategy is removed with ConcreteMultiStrategyVault.removeStrategy(), it calls into MultiStrategyVaultHelper.removeStrategy(), which has the following check:

https://github.com/code-423n4/2024-11-concrete/blob/main/src/libraries/MultiStrategyVaultHelper.sol#L274-L277

// Check if the strategy has any locked assets that cannot be withdrawn
if (stratToBeRemoved_.getAvailableAssetsForWithdrawal() != stratToBeRemoved_.totalAssets()) {
    revert StrategyHasLockedAssets(address(stratToBeRemoved_));
}

For the strategies' getAvailableAssetsForWithdrawal():

For Aave strategy, it is the aToken balance
For Morpho, it is the maximum withdrawable
For Radiant, it is the rToken balance
For Silo, it is the collateral vault token balance
For Compound, it is the cToken balance
For Protect strategy, it is the asset's balance i.e. the amount of deployed funds that has not been borrowed yet.

For totalAssets(), it is the balance of the underlying asset (not the external vault's token), plus the _totalAssets() defined per-strategy, where:

For all non-protect strategies, it is the vault's token balance (converted to assets if needed).
For protect strategy, it is the debt of the vault.

Now, because _totalAssets() also counts the underlying asset balance in, combined with the fact that there's no way to directly withdraw the underlying asset from the strategy's balance itself, anyone can force the above equality to false by transferring 1 wei of asset in, causing removeStrategy() to always fail at that equality check.

Proof of Concept

We first prove that it is possible to force-fail by sending 1 wei of underlying asset in. Paste the test into AaveV3Strategy.t.sol, and run with forge test --match-test test_PoCRemoveStrategyCheckFail:

function test_PoCRemoveStrategyCheckFail(uint256 amount_) public {
    uint256 amount = bound(amount_, 1e10, 1000 ether);
    _mintAsset(amount + 1, hazel);
    vm.startPrank(hazel);

    asset.approve(address(strategy), amount);
    uint256 shares = strategy.deposit(amount, hazel); // deposit first
    assertEq(strategy.getAvailableAssetsForWithdrawal(), strategy.totalAssets());

    // now send 1 wei in
    asset.transfer(address(strategy), 1);
    assertNotEq(strategy.getAvailableAssetsForWithdrawal(), strategy.totalAssets()); // assert not equal, will pass

    vm.stopPrank();
}
Impact

removeStrategy() can be denied at any time. This in turn also denies the replacement part of addOrReplaceStrategy(), which calls into removeStrategy()

Recommended mitigation steps

totalAssets() should only add the underlying balance if it's the protect strategy. Otherwise, it should only count the vault token's balance (converted to underlying assets)
