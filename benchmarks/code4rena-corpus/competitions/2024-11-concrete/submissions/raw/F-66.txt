S-776
Batch withdrawals from withdrawal queue can fail to mark the last withdrawal request as claimed due to off by one error
zzebra83
54
Sufficient
383d ago
Finding description and impact

The purpose of the batchClaimWithdrawal is to process all withdrawal requests in the queue. its a critical function that plays an important role in ensuring all withdrawal requests in the queue are finalized and claimed.

It interacts with the withdrawal queue function by calling prepareWithdrawal. lets take a look at the code block below:

        if (_avaliableAssets > amount) {
            assert(_requestsByOwner[recipient].remove(_requestId));
            avaliableAssets = _avaliableAssets - amount;
            request.claimed = true;
            //This is commented to fit the requirements of the vault
            //instead of this we will call _withdrawStrategyFunds
            //IERC20(TOKEN).safeTransfer(recipient, realAmount);

            emit WithdrawalClaimed(_requestId, recipient, amount);
        }


if the the available funds left is exactly equal to the amount being processed, the function fails to ensure the request has succesfully been claimed, and to clear the user's _requestsByOwner list. this is due to an off by one error via using > instead of >=.

At the time of writing I believe this is either of medium or QA severity, depending on whether ensuring all withdrawals have been succesfully marked as claimed due to accounting reasons is vital and/or will be considered something of a concern for the protocol.

function test_withdrawal_queue_exact_amount() public {
   // 1. Setup vault and withdrawal queue
   (ConcreteMultiStrategyVault newVault, Strategy[] memory strats) = _createNewVault(false, false, true);
   WithdrawalQueue queue = new WithdrawalQueue(address(newVault));
   vm.prank(admin);
   newVault.setWithdrawalQueue(address(queue));

        for (uint256 i = 0; i < strats.length; ) {
            IMockStrategy(address(strats[i].strategy)).setAvailableAssetsZero(true);
            unchecked {
                i++;
            }
        }



   // 2. Hazel deposits 10 ETH
   uint256 depositAmount = 10 ether;
   asset.mint(hazel, depositAmount);
   vm.startPrank(hazel);
   asset.approve(address(newVault), depositAmount);
   newVault.deposit(depositAmount, hazel);
   vm.stopPrank();
   

   // 2. ellie deposits 10 ETH
   asset.mint(ellie, depositAmount);
   vm.startPrank(ellie);
   asset.approve(address(newVault), depositAmount);
   newVault.deposit(depositAmount, ellie);
   vm.stopPrank();

   // 3. Request full withdrawal
   vm.prank(ellie);
   newVault.withdraw(depositAmount, ellie, ellie);

   // 3. Request full withdrawal
   vm.prank(hazel);
   newVault.withdraw(depositAmount, hazel, hazel);
   
   // Check initial state
   assertEq(queue.getLastRequestId(), 2, "Should have two requests");
   //assertEq(newVault.getAvailableAssetsForWithdrawal(), depositAmount, "Should have full amount available");
   
    for (uint256 i = 0; i < strats.length; ) {
            IMockStrategy(address(strats[i].strategy)).setAvailableAssetsZero(false);
            unchecked {
                i++;
            }
        }

   // 4. Try to process via batchClaimWithdrawal
   vm.prank(admin);
   newVault.batchClaimWithdrawal(99); // Process all requests

   
   // 5. Check final state
   uint256[] memory requestIds = new uint256[](2);
   requestIds[0] = 1;
   requestIds[1] = 2;
   WithdrawalQueue.WithdrawalRequestStatus[] memory request = queue.getWithdrawalStatus(requestIds);
   assertEq(request[0].isClaimed, true, "First equest should be claimed");
   assertEq(request[1].isClaimed, false, "Last Request was not claimed");
   assertEq(asset.balanceOf(ellie), 10 ether, "Ellie should have received back her funds");
   assertEq(asset.balanceOf(hazel), 10 ether, "Hazel should have received her funds back");
   assertEq(queue.getLastFinalizedRequestId(), 2, "All requests should be finalized");
  
}
