S-1127
executeBorrowClaim does not account for fee on transfer tokens
zzebra83
54
Sufficient
383d ago
Finding description and impact

executeBorrowClaim in the ProtectStrategy transfers the specified amount of assets to the recipient and updates the borrow debt. But it does not account for assets with fees on transfer( fee on transfer issues in scope for this audit), causing borrow debt of protect strategy to be more than it actually is.

    function executeBorrowClaim(uint256 amount, address recipient) external override onlyClaimRouter {
        if (amount == 0) revert ZeroAmount();
        uint256 balance = getAvailableAssetsForWithdrawal();

        if (balance < amount) {
            _requestFromVault(amount - balance);
        }
        // borrow debt will be higher than it should due to fee on transfer
        borrowDebt += amount;

        IERC20(asset()).safeTransfer(recipient, amount);

        emit BorrowClaimExecuted(amount, recipient);
    }


Now the question is how will this impact protocol negatively?

If we shift our attention the claims router contract, we see it is responsible for repaying debt in the protection strategies, it does this via calling the _addTokensToStrategy internl function

            uint256 stratBorrowDebt = IProtectStrategy(protectionStrat).getBorrowDebt();

            uint256 amountToBeSent = 0;
            if (debtVaults.totalBorrowDebt != 0) {
                if (stratBorrowDebt == 0) {
                    unchecked {
                        i++;
                    }
                    continue;
                }
                // strategy with fee on transfer will have a higher borrow debt than the actual debt
                // causing amount to be sent to be higher than it should be
                amountToBeSent = amount_.mulDiv(stratBorrowDebt, debtVaults.totalBorrowDebt, Math.Rounding.Floor);
            } else {
                //slither-disable-next-line unused-return
                (, amountToBeSent) = amount_.tryDiv(debtVaults.vaultsWithProtect);
            }


the block of code above determine the amount of rewards to be sent to each protection strategy, notice how if a strategy has a borrow debt, the amount to be sent is related to the amount of borrow debt:

amountToBeSent = amount_.mulDiv(stratBorrowDebt, debtVaults.totalBorrowDebt,


A higher borrow debt increases the amount of rewards sent to the strategy.

But if the borrowdebt does not consider fee on transfer rewards, it will be higher than it should be, hence the amount to be sent as rewards will be higher than it should. likewise strategies without fees will receive less rewards than they should.

Proof of Concept

Consider the following:

We have 100 ETH to distribute as rewards.

Strategy A (With Transfer Fees):

Intended borrowDebt: 30
Transfer Fee: 10% (3 units lost)
Actual Transferred Amount: 27
Incorrect borrowDebt Recorded: 30

Strategy B (Without Transfer Fees)
BorrowDebt: 70

Total borrowDebt Recorded: 100

Reward Distribution Based on wrong borrowDebt:

Strategy A: 30 units
Strategy B: 70 units

Actual Debt After Accounting for Fees:

Strategy A: 27
Strategy B: 70
Total Actual borrowDebt: 97

Adjusted Reward Distribution:

Strategy A: 27.8 units
Strategy B: 72.2 units

You can clearly see in the above example how fees can skew reward distribution and unfairly disadvantage protection strategies with no fees.

Recommended mitigation steps
function executeBorrowClaim(uint256 amount, address recipient) external override onlyClaimRouter {
    if (amount == 0) revert ZeroAmount();
    uint256 balance = getAvailableAssetsForWithdrawal();
    if (balance < amount) {
        _requestFromVault(amount - balance);
    }
    
    uint256 preBalance = IERC20(asset()).balanceOf(recipient);
    IERC20(asset()).safeTransfer(recipient, amount);
    uint256 postBalance = IERC20(asset()).balanceOf(recipient);
    
    uint256 actualTransferred = postBalance - preBalance;
    borrowDebt += actualTransferred;
    
    emit BorrowClaimExecuted(actualTransferred, recipient);
}


In order to ensure proper reward distribution based on actual borrowed amounts, it is recommended to remove impact of fees on transfer on borrowed balance
