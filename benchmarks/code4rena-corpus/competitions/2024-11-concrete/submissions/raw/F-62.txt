S-168
Protect strategy doesn't account for allocations when requesting funds and repaying, leading to unexpected reverts on withdrawal
0xAlix2
82
Sufficient
383d ago
Finding description and impact

When users deposit or withdraw funds into/from the vault, those funds get deposited/withdrawn into/from strategies according to each strategy's allocation, regardless of the amount.
https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L258-L261
https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L464-L471

This fund distribution remains valid no matter how much funds were deposited or withdrawn from the vault.
On the other hand, the protect strategy can request funds from other strategies, and can later repay those requested funds. However, when funds are requested from the vault, MultiStrategyVaultHelper::withdrawAssets is called:

function withdrawAssets(
    address asset, // The main asset token
    uint256 amount, // The requested withdrawal amount
    address protectStrategy, // The address of the strategy to skip
    Strategy[] storage strategies // Array of strategy structs
) public returns (uint256) {
    uint256 availableAssets = IERC20(asset).balanceOf(address(this));
    uint256 accumulated = availableAssets;

    // If available assets in main balance are insufficient, try strategies
    if (availableAssets < amount) {
        uint256 len = strategies.length;

        for (uint256 i = 0; i < len; i++) {
            IStrategy currentStrategy = strategies[i].strategy;

            // Skip the protect strategy
            if (address(currentStrategy) == protectStrategy) {
                continue;
            }

            uint256 pending = amount - accumulated;

            // Check available assets in the strategy
            uint256 availableInStrategy = currentStrategy.getAvailableAssetsForWithdrawal();

            // Skip if the strategy has no assets available for withdrawal
            if (availableInStrategy == 0) {
                continue;
            }

            // Determine the amount to withdraw from this strategy
@>          uint256 toWithdraw = availableInStrategy < pending ? availableInStrategy : pending;

            // Update the accumulated amount
            accumulated += toWithdraw;

            // Withdraw from the strategy
@>          currentStrategy.withdraw(toWithdraw, address(this), address(this));

            // Break if the accumulated amount satisfies the requested amount
            if (accumulated >= amount) {
                break;
            }
        }
    }

    return accumulated;
}

Which withdraws all the needed funds from the first strategy(ies) capped out by their withdrawal limit. This messes up the whole allocation work, where strategies that are placed first in the strategies array will end up having funds less than the others, at higher indices, knowing that these "first" strategies could have a higher allocation than other strategies.

This affects the withdrawal function, where on withdrawal the vault withdraws from each strategy according to its allocation, so "first" strategies will end up being asked to withdraw funds way more than they have after the protect strategy withdrew funds from them.

This will cause unexpected reverts here, even if the vault had enough assets to full fill the withdraw.

The above also holds when the protect strategy repays the funds, where they're directly deposited into the protect strategy, dumping away any allocations, https://github.com/code-423n4/2024-11-concrete/blob/main/src/claimRouter/ClaimRouter.sol#L307.

Recommended mitigation steps

Preserve the strategies allocation whenever funds are going out or to the vault, even though the protected strategy, i.e. through both executeBorrowClaim and updateBorrowDebt.
MultiStrategyVaultHelper::withdrawAssets would be something similar to:

function withdrawAssets(
    address asset, // The main asset token
    uint256 amount, // The requested withdrawal amount
    address protectStrategy, // The address of the strategy to skip
    Strategy[] storage strategies // Array of strategy structs
) public returns (uint256) {
    uint256 availableAssets = IERC20(asset).balanceOf(address(this));
    uint256 accumulated = availableAssets;

    // If available assets in main balance are insufficient, try strategies
    if (availableAssets < amount) {
        uint256 allocationsWithoutProtect = 0;

        for (uint256 i = 0; i < strategies.length; i++) {
            if (address(strategies[i].strategy) == protectStrategy) {
                continue;
            }
            allocationsWithoutProtect += strategies[i].allocation.amount;
        }

        for (uint256 i = 0; i < strategies.length; i++) {
            IStrategy currentStrategy = strategies[i].strategy;

            // Skip the protect strategy
            if (address(currentStrategy) == protectStrategy) {
                continue;
            }

            // Check available assets in the strategy
            uint256 availableInStrategy = currentStrategy
                .getAvailableAssetsForWithdrawal();

            // Skip if the strategy has no assets available for withdrawal
            if (availableInStrategy == 0) {
                continue;
            }

            // Determine the amount to withdraw from this strategy
            uint256 toWithdraw = Math.min(
                amount.mulDiv(
                    strategies[i].allocation.amount,
                    allocationsWithoutProtect,
                    Math.Rounding.Floor
                ),
                availableInStrategy
            );

            // Update the accumulated amount
            accumulated += toWithdraw;

            // Withdraw from the strategy
            currentStrategy.withdraw(
                toWithdraw,
                address(this),
                address(this)
            );

            // Break if the accumulated amount satisfies the requested amount
            if (accumulated >= amount) {
                break;
            }
        }
    }

    return accumulated;
}
