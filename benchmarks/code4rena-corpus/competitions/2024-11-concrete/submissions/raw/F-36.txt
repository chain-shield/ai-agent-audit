S-925
Incorrect total assets calculation in SiloV1Strategy
nnez
87
Sufficient
383d ago
Impact

The SiloV1Strategy implementation underestimates the totalAssets value by incorrectly calculating the baseAsset balance. This leads to:

Inaccurate Share Pricing: Vault share price is undervalued, causing a misrepresentation of user holdings.
Description

The _totalAssets function of the SiloV1Strategy contract is responsible for reporting the equivalent baseAsset holdings of the strategy. However, it incorrectly calculates the value by directly returning the balance of collateralToken (a share token) instead of converting the shares into baseAsset using the pool's exchange rate.

Incorrect logic
function _totalAssets() internal view override returns (uint256) {
    uint256 shares = collateralToken.balanceOf(address(this));
    return shares; // @audit: fails to account for the exchange rate between shares and baseAsset
    // return balanceOfUnderlying(shares); // @audit: correct logic is actually commented out
}
Correct logic
function balanceOfUnderlying(uint256 shares) public view returns (uint256) {
    ISilo.AssetStorage memory assetStorage = silo.assetStorage(asset());
    return shares.toAmount(assetStorage.totalDeposits, collateralToken.totalSupply());
}

The correct implementation should use balanceOfUnderlying function to convert the share token balance into baseAsset units based on the exchange rate. The absence of this conversion results in underestimated asset reporting.

Example Scenario
Initial State
Underlying pool:
totalDeposits = 1,000,000 USDC
totalSupply = 500,000 shares
Exchange Rate = 2 (1 share = 2 USDC).
Strategy holdings:
The strategy holds 10,000 collateralToken shares.
The strategy should report 20,000 USDC as its total holding of baseAsset
Current _totalAssets implementation
function _totalAssets() internal view override returns (uint256) {
    uint256 shares = collateralToken.balanceOf(address(this)); // 10,000
    return shares; // Returns 10,000 instead of converting to baseAsset
}
The function reports 10,000 USDC as the strategy's total assets.
Correct implementation using balanceOfUnderlying
function balanceOfUnderlying(uint256 shares) public view returns (uint256) {
    ISilo.AssetStorage memory assetStorage = silo.assetStorage(asset());
    return shares.toAmount(assetStorage.totalDeposits, collateralToken.totalSupply());
}
The correct calculation is:
totalAssets = 10_000 * 1_000_000/500_000 = 20_000 USDC
Proof-of-Concept

The following test demonstrates that current implementation returns an underestimated value, it does so by showing that even after accruing interest event on Silo, this function still return the same value.

Steps
Paste the following test in 2024-11-concrete/test/strategies/SiloV1Strategy.t.sol
  function test_incorrect_totalAssets() public{
      uint amount = 100e18;
      _mintAsset(amount, hazel);

      vm.prank(hazel);
      asset.approve(address(strategy), type(uint).max);

      vm.prank(hazel);
      strategy.deposit(amount, hazel);

      console.log("-- before accrue interest --");
      console.log("totalAssets: %d", strategy.totalAssets());
      console.log("balanceOfUnderlying: %d", strategy.balanceOfUnderlying(collateralTokenBal()));
      
      // warping time to accrue interest
      vm.warp(block.timestamp + 86400);
      console.log("warp time and call accrueInterest on Silo");
      address(strategy.silo()).call(abi.encodeWithSignature("accrueInterest(address)", WETH));

      console.log("-- after accrue interest --");
      console.log("totalAssets: %d", strategy.totalAssets());
      console.log("balanceOfUnderlying: %d", strategy.balanceOfUnderlying(collateralTokenBal()));
  }
Run forge t --match-contract SiloV1StrategyTest --match-test test_incorrect_totalAssets -vv
Observe the result:

Recommended Mitigations

Use balanceOfUnderlying to calculate _totalAssets
