S-515
User with blueprint can add rewards on behalf of a different blueprint.
sl1
68
Sufficient
383d ago
Bug description

The are two way of adding tokens to protection strategies: addRewards() and repay() functions. Both these functions can only be called by a sender with a blueprint role. However, currently it's possible for a user with a blueprint role to steal funds from another blueprint that has approved tokens to the ClaimRouter.

If we look at the addRewards() function userBlueprint address is a user-supplied parameter.

ClaimRouter.sol#L233-L239

function addRewards(
    address tokenAddress,
    uint256 amount_,
    address userBlueprint
) external onlyRole(BLUEPRINT_ROLE) {
    _addTokensToStrategy(tokenAddress, amount_, userBlueprint, true);
}

When _addTokensToStrategy() is called, it will try to transfer tokens from the userBlueprint to the protection strategy, which would result in a loss of funds for the blueprint if he had an unspent approval to the claim router.

ClaimRouter.sol#L307

IERC20(tokenAddress).safeTransferFrom(
    userBlueprint,
    protectionStrat,
    amountToBeSent
);

It's important to note that the only trusted role in the context of this contest is the owner as stated by the contest page, therefore we cannot consider that all of the blueprints will act non-maliciously.

Impact

Loss of funds for the blueprint with an unspent approval to the claim router contract.

Recommended Mitigation

Change addRewards() and repay() function so userBlueprint won't be a user-supplied parameter anymore, and set it to the address of the msg.sender.

ClaimRouter.sol#L233-L240

function addRewards(
    address tokenAddress,
    uint256 amount_,
-    address userBlueprint
) external onlyRole(BLUEPRINT_ROLE) {
-    _addTokensToStrategy(tokenAddress, amount_, userBlueprint, true);
+    _addTokensToStrategy(tokenAddress, amount_, msg.sender, true);
}

ClaimRouter.sol#L246-L248

function repay(
    address tokenAddress,
    uint256 amount_,
-    address userBlueprint
) external onlyRole(BLUEPRINT_ROLE) {
-    _addTokensToStrategy(tokenAddress, amount_, userBlueprint, false);
+    _addTokensToStrategy(tokenAddress, amount_, msg.sender, false);
}
