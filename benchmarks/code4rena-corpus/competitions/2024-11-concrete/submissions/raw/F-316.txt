S-639
User loses share of accumulated rewards processed during every withdraw in Aave strategy
0xrex
69
Sufficient
383d ago
Finding description and impact

Everytime a withdraw/redeem happens in a multi strategy vault that is connected to an Aave strategy, the Aave strategy pulls accumulated rewards in Aave third-party pool through the _handleRewardsOnWithdraw function. These rewards are sent into the Aave strategy contract and not the multi-strategy vault it is tied to.

In this case:

The user who redeemed/withdrew shares will not get their share of the accumulated rewards
The multi-strategy vault will also not be sent the accumulated rewards and thus its rewardIndex[rewardToken] for the aave reward will not be updated to let users claim it based on their share %. Considering user rewards are relative to their shares, once the user' shares are burnt during withdraw, they no longer can claim rewards accumulated.
Proof of Concept
FILE: StrategyBase.sol

function _withdraw(
        address caller_,
        address receiver_,
        address owner_,
        uint256 assets_,
        uint256 shares_
    ) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
        //slither-disable-next-line incorrect-equality
        if (shares_ == 0 || assets_ == 0) revert ZeroAmount();

        _protocolWithdraw(assets_, shares_);

        _burn(owner_, shares_);
        _handleRewardsOnWithdraw();
        IERC20(asset()).safeTransfer(receiver_, assets_);

        emit Withdraw(caller_, receiver_, owner_, assets_, shares_);
    }

FILE: AaveV3Strategy.sol

function _handleRewardsOnWithdraw() internal override {
        _getRewardsToStrategy("");
    }

function _getRewardsToStrategy(bytes memory) internal override {
        if (address(aaveIncentives) == address(0)) return;

        address[] memory _assets = new address[](1);
        _assets[0] = address(aToken);

        //slither-disable-next-line unused-return
        try aaveIncentives.claimAllRewards(_assets, address(this)) {} catch {}
    }

As can be seen from the code snippets above:

The user withdraws >> the _withdraw function which is overriden from ERC4626 runs the logic to withdraw the requested amount in _protocolWithdraw and then calls _handleRewardsOnWithdraw which pulls rewards to the strategy >> the shares are burnt >> the calling user receives their asset and thus their shares are burnt >> the user doesn't get paid their % of the accumulated aave reward because the rewardIndex[rewardToken] for the reward token is not updated as well as the user's reward index.

Recommended mitigation steps

During every withdrawal/shares redemption, the protocol should add some code in the Aave overriden _handleRewardsOnWithdraw function that:

sends the rewards to the connected multi strategy vault (minus the feeRecipient share)
triggers a logic in the connected multi strategy vault to update its rewardIndex[rewardToken] for the reward token
Execute an update of the user's current reward for the reward token before the user shares are burnt in the multi strategy vault contract

hello again judge, I'd like to point out a few facts regarding this issue as I believe it never did get the initial evaluation because it was wrongly marked as a duplicate of S-503.

S-503 discusses the removal of assets before attempting to withdraw the rewards. my issue S-639 on the other hand discusses a complete loss of reward tokens for a user because the user's shares are burnt during withdrawal in the concrete vault without calculating and updating the user's reward index which then leads to the case where the user will never be able to claim rewards for the specific vault

the protocol works in a way whereby after sometime, the protocol calls harvestRewards on a concrete vault which pulls rewards and then users get to call claimRewards. when claimRewards is called, the user's share of rewards is calculated based on the share amount of the user in the concrete vault at that point in time.

the issue:

suppose I deposit into a weth concrete vault at the current time (today), then the concrete vault deposits my weth into the connected strategies (Aave, Compound, Morpho) today.
some time has passed, let us assume 3 days. I go over to the vault and call the withdraw function to withdraw my deposit. the concrete vault would force the _handleRewardsOnWithdraw of e.g the Compound or Aave strategy to be executed. this function harvests the rewards earned from Compound, Aave, and Morpho for the past two days into the strategies but being that my reward index in the concrete vault is not updated and the harvested rewards are not forwarded to the concrete vault, I lose the Aave, Compound, and Morpho reward tokens because my shares in the concrete vault are already burnt. Once burnt, I can no longer call claimRewards later let's say on day 5 hoping to get my rewards when the protocol calls harvestRewards in the concrete vault contract because the amount of reward I get depends on my share balance in the concrete vault which is now non-existent.
