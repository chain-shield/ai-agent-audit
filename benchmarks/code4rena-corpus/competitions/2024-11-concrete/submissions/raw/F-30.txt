S-146
Pausing an external protocol that is used in a strategy DOSes the whole vault
0xAlix2
82
Sufficient
383d ago
Finding description and impact

When users deposit funds into a vault, they are deposited into multiple third-party protocols, and the opposite happens when they withdraw funds. On the other hand, when the admin wants to remove a strategy from a vault, it checks if the strategy still has any deposited funds in the third-party protocols, if so, it redeems them, https://github.com/code-423n4/2024-11-concrete/blob/main/src/libraries/MultiStrategyVaultHelper.sol#L268-L293:

function removeStrategy(IStrategy stratToBeRemoved_, address protectStrategy_, IERC20 asset) public returns (address protectStrategy) {
    protectStrategy = protectStrategy_;
    // Check if the strategy has any locked assets that cannot be withdrawn
    if (stratToBeRemoved_.getAvailableAssetsForWithdrawal() != stratToBeRemoved_.totalAssets()) {
        revert StrategyHasLockedAssets(address(stratToBeRemoved_));
    }

    // Redeem all assets from the strategy if it has any assets
    if (stratToBeRemoved_.totalAssets() > 0) {
@>      stratToBeRemoved_.redeem(stratToBeRemoved_.balanceOf(address(this)), address(this), address(this));
    }

    // ... //
}

The above also holds when replacing a strategy, as it also calls removeStrategy, https://github.com/code-423n4/2024-11-concrete/blob/main/src/libraries/MultiStrategyVaultHelper.sol#L237.

This is all good for now, however, the protocol doesn't consider cases where a third-party protocol is paused (paused for whatever reason, we don't care), and there are no precautions to skip/blur the strategy that uses that paused protocol.
When users want to either deposit or withdraw funds, the TX will revert, because the protocol that is used by some strategy is paused. If an admin tries to remove/replace that strategy, it'll also revert, because as mentioned above, removing/replacing a strategy can't be done unless all shares are redeemed.

As a result, this causes a massive DOS to the whole vault that users that strategy.

Recommended mitigation steps

This can be solved by one of the following:

Have a way for the admin to force remove/eject a strategy, that should only be used in extreme cases.
Have a check inside each strategy's getAvailableAssetsForWithdrawal and _totalAssets, which checks if the third-party protocol is paused, if so return 0, else return the underlying assets. This ensures that the paused protocol isn't included in any action in the vault until it's back unpaused.
