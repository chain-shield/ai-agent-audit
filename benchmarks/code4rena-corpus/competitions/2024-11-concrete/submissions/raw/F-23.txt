swapTokensForReward is lack of slippage protect
ayden
43
Sufficient
383d ago
Finding description and impact

Users can swap vault tokens for reward tokens, and the amount of reward tokens received depends on the token price and the state of the ERC4626 vault. Both of these factors can influence the actual amount of reward tokens received. However, the swapTokensForReward function lacks slippage protection, which could result in users receiving fewer reward tokens than expected.

Proof of Concept

Scenario:

1.Hazel first previews the reward token amount to be received via the previewSwapTokensForReward method
2.The price of reward token changed
3.Hazel submit the swapTokensForReward transaction

Test:

    function test_swap_amount_slippage() public {
        uint256 rewardAmountInTreasury = 100_000_000 * 10 ** ASSET_DECIMALS;
        uint256 initialAssetAmount = 1_000 * 10 ** ASSET_DECIMALS;
        int256 rewardPrice = int256(500 * 10 ** ORACLE_QUOTE_DECIMALS);
        int256 assetPrice = int256(22 * 10 ** ORACLE_QUOTE_DECIMALS);
        // mint some reward tokens to the treasury
        rewardToken.mint(treasury, rewardAmountInTreasury);
        // Hazel to receive ctAssets from the ctAsset Vault
        vm.startPrank(hazel);
        asset.mint(hazel, initialAssetAmount);
        asset.approve(address(ctAsset), initialAssetAmount);
        ctAsset.deposit(initialAssetAmount, hazel);
        vm.stopPrank();

        // set prices for the oracle
        _setOraclePrices(assetPrice, rewardPrice);

        // Hazel wants to swap half of his ctAsset belongings
        uint256 hazelCtAssetAmount = ctAsset.balanceOf(hazel);
        uint256 ctAssetAmountToBeSwapped = hazelCtAssetAmount / 2;
        // treasury to approve the spending of reward tokens
        vm.prank(treasury);
        rewardToken.approve(address(swapper), rewardAmountInTreasury);
        vm.prank(hazel);
        ctAsset.approve(address(swapper), ctAssetAmountToBeSwapped);

        // calculate the expected answer
        uint256 assetAmountFromCtAssetAmount = ctAsset.convertToAssets(ctAssetAmountToBeSwapped);
        uint256 totalRewardTokenAmount = _getExpectedRewardTokenAmount(
            assetAmountFromCtAssetAmount,
            assetPrice,
            rewardPrice
        );

        console2.log("expected reward amount:",totalRewardTokenAmount);

        //price changed.
        oracle.setPriceDecimalsAndTimestamp("REWARD/USDC", int256(600 * 10 ** ORACLE_QUOTE_DECIMALS), ORACLE_QUOTE_DECIMALS, 1);

        //create the swap.
        vm.startPrank(hazel);
        swapper.swapTokensForReward(address(ctAsset), address(rewardToken), ctAssetAmountToBeSwapped);

        console2.log("actually reward amount:",rewardToken.balanceOf(hazel));
    }

Out:

[PASS] test_swap_amount_slippage() (gas: 768209)

Suite result: ok. 1 passed; 0 failed; 0 skipped; finished in 7.76ms (1.69ms CPU time)

From the above test, we can see that the actual reward amount can differ from the expected reward amount.

Recommended mitigation steps

Add a slippage protect
