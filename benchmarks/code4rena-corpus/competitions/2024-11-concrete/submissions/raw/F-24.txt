S-583
Missing Oracle Staleness Check Allows Price Manipulation
Agontuk
41
Sufficient
383d ago

The Concrete Multi-Strategy Vault protocol uses the Bera Oracle (IBeraOracle) to determine token prices for swaps. The oracle integration is handled through the OraclePlug contract, which provides conversion functions between tokens and stables. However, the implementation fails to validate the staleness of oracle prices, which could lead to trades being executed with outdated or manipulated prices.

The _getPriceFromOracle() function in OraclePlug.sol retrieves prices from IBeraOracle but ignores the timestamp returned by getPrice() :

File: OraclePlug.sol
28:     function _getPriceFromOracle(
29:         OracleInformation memory oracle
30:     ) internal view returns (uint256 price, uint8 decimals) {
31:         // TODO: Maybe also include other Oracle options. Inside the oracle struct there can also be a field for the oracle type.
32:         // slither-disable-next-line unused-return
33:         (int256 intPrice, , ) = IBeraOracle(oracle.addr).getPrice(oracle.pair);
34:         price = SafeCast.toUint256(intPrice);
35:         decimals = IBeraOracle(oracle.addr).getDecimals(oracle.pair);
36:     }


Note that getPrice() returns three values:

File: IBeraOracle.sol
19:     // Function to get the price of a currency pair. Returns price, timestamp, and another value.
20:     function getPrice(string calldata pair) external view returns (int256, uint256, uint64);
21: 


The second value (timestamp) is completely ignored in the implementation. This means that even if the oracle price is hours or days old, it will still be used for price conversion in critical functions like _convertFromTokenToStable() and _convertFromStableToToken().

Impact
Trades can be executed using stale prices, potentially at rates very different from current market prices
Attackers can profit from price discrepancies between the stale oracle price and actual market price
In extreme cases (e.g., during high volatility or market crashes), users could drain protocol funds by trading at outdated advantageous prices
The issue affects all token swaps in the protocol since price conversion is a core component of the swapping mechanism
Proof of Concept
Oracle price for TOKEN/USDC is $100, timestamp is current
Market price drops to $50
Oracle update is delayed/fails
Attacker sees the discrepancy and executes this sequence:
// 1. Buy TOKEN at market price ($50)
// 2. Deposit TOKEN to protocol
token.approve(swapper, amount);
swapper.swapTokensForReward(token, rewardToken, amount);
// 3. Protocol values TOKEN at stale price ($100)
// 4. Attacker receives 2x value in reward tokens
Attacker can repeat until treasury is drained or price updates
Tools Used

Manual Review

Recommended Mitigation Steps

Add staleness check in _getPriceFromOracle():

function _getPriceFromOracle(
    OracleInformation memory oracle
) internal view returns (uint256 price, uint8 decimals) {
-   (int256 intPrice, , ) = IBeraOracle(oracle.addr).getPrice(oracle.pair);
+   (int256 intPrice, uint256 timestamp, ) = IBeraOracle(oracle.addr).getPrice(oracle.pair);
+   
+   // Revert if price is older than MAX_PRICE_AGE (e.g. 1 hour)
+   if (block.timestamp - timestamp > MAX_PRICE_AGE) {
+       revert Errors.StalePrice();
+   }
    
    price = SafeCast.toUint256(intPrice);
    decimals = IBeraOracle(oracle.addr).getDecimals(oracle.pair);
}
