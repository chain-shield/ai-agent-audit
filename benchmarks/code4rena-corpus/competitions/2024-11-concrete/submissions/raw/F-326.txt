S-1042
Unrestricted Token Cascade Configuration Leads To Incorrect Usage
0x2517
00
Sufficient
383d ago
Finding description and impact

The ClaimRouter contract contains a critical flaw in its token conversion logic where the tokenCascade array, which should exclusively contain stablecoin addresses, is not properly validated.

The _convertFromTokenToStable function is used to convert token amounts to stable coin values, but the contract fails to enforce that the destination tokens in tokenCascade are actually stablecoins.

                amount = _convertFromTokenToStable(tokenAddress, amount_);

                //We control both the length of the array and the external call
                // slither-disable-next-line calls-loop
                (protectionStrat, requiresFunds) = _getStrategy(tokenCascade[i], amount);

However, the tokenCascade array can be configured with any token addresses, including volatile assets like ETH, which defeats the purpose of the stable conversion and can lead to incorrect calculations.

https://github.com/code-423n4/2024-11-concrete/blob/a32913bac502c8f7c092d02824ab50722f89bdc0/test/ClaimRouter.t.sol#L91-L93
        tokenCascade.push(address(fakeUSDC));
        tokenCascade.push(address(fakeETH));

As a result, this will lead to incorrect results when non-stablecoins like fakeETH are being used which are not stable coins. This will lead to incorrect price calculations when converting between tokens.

Proof of Concept

The issue can be demonstrated in the test setup where tokenCascade includes non-stablecoin tokens:

// From test/ClaimRouter.t.sol
tokenCascade.push(address(fakeUSDC)); // Stablecoin - OK
tokenCascade.push(address(fakeETH));  // Volatile asset - Should not be allowed

When requestToken is called, it uses this conversion:

// From src/claimRouter/ClaimRouter.sol
amount = _convertFromTokenToStable(tokenAddress, amount_);
(protectionStrat, requiresFunds) = _getStrategy(tokenCascade[i], amount);
Recommended mitigation steps

To mitigate this issue:

Consider using a whitelist of known stablecoin addresses instead of allowing arbitrary token addresses to be added to the cascade.
Add documentation clearly stating that tokenCascade must only contain stablecoin addresses
Non-stablecoins should never be used as tokenCascade
