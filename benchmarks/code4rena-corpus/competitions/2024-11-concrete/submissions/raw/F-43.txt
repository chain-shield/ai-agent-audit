Strategies are un-pausable despite being intended to be otherwise
Bauchibred

Proof of Concept

Take a look at https://github.com/code-423n4/2024-11-concrete/blob/c9219f304ed8ce71b8dc8ef67790d76fb42f370d/src/strategies/StrategyBase.sol#L17-L31

abstract contract StrategyBase is
    IERC4626,
    IStrategy,
    ERC4626Upgradeable,
    ReentrancyGuard,
    OwnableUpgradeable,
    Errors,
    PausableUpgradeable
{
    // ... contract implementation
}

Evidently, the contract inherits from PausableUpgradeable, issue however is that it does not expose any functions to actually pause/unpause the contract.

Would be key to note that the contract uses the whenNotPaused modifier on critical functions like _deposit and _withdraw, however there's no way to actually trigger the pause mechanism in case of emergencies.

See:

https://github.com/code-423n4/2024-11-concrete/blob/c9219f304ed8ce71b8dc8ef67790d76fb42f370d/src/strategies/StrategyBase.sol#L128-L172

    function _deposit(
        address caller_,
        address receiver_,
        uint256 assets_,
        uint256 shares_
    ) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
        //slither-disable-next-line incorrect-equality
        if (shares_ == 0 || assets_ == 0) revert ZeroAmount();
        IERC20(asset()).safeTransferFrom(caller_, address(this), assets_);

        _protocolDeposit(assets_, shares_);

        _mint(receiver_, shares_);

        emit Deposit(caller_, receiver_, assets_, shares_);
    }

    function _withdraw(
        address caller_,
        address receiver_,
        address owner_,
        uint256 assets_,
        uint256 shares_
    ) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
        //slither-disable-next-line incorrect-equality
        if (shares_ == 0 || assets_ == 0) revert ZeroAmount();

        _protocolWithdraw(assets_, shares_);

        _burn(owner_, shares_);
        _handleRewardsOnWithdraw();
        IERC20(asset()).safeTransfer(receiver_, assets_);

        emit Withdraw(caller_, receiver_, owner_, assets_, shares_);
    }
Impact

2 — Med: Assets not at direct risk, but the function of the protocol or its availability could be impacted, or leak value with a hypothetical attack path with stated assumptions, but external requirements.

The lack of pause functionality means the contract cannot be stopped in case of emergencies, despite having the infrastructure in place through PausableUpgradeable inheritance.

Recommended Mitigation Steps

Add pause and unpause functions with appropriate access control:

function pause() external onlyOwner {
    _pause();
}

function unpause() external onlyOwner {
    _unpause();
}

Consider also adding events to track pause state changes:

event StrategyPaused(address indexed by);
event StrategyUnpaused(address indexed by);
