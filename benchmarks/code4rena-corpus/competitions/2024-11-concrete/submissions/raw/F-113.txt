S-475
Radiant Strategy's Lack of Fallback Mechanisms Creates Single Point of Failure Risk
Agontuk
41
Sufficient
383d ago

The Concrete Protocol implements a multi-strategy vault system where different strategies can be used to generate yield on user deposits. The RadiantV2Strategy contract is one such strategy that integrates with the Radiant lending protocol to generate yields by depositing user funds into Radiant's lending pools.

The strategy interacts with Radiant's lending pools through the _protocolDeposit() and _protocolWithdraw() functions:

function _protocolDeposit(uint256 amount_, uint256) internal virtual override {
    lendingPool.deposit(asset(), amount_, address(this), 0);
}

function _protocolWithdraw(uint256 amount_, uint256) internal virtual override {
    lendingPool.withdraw(asset(), amount_, address(this));
}

The issue is that these functions implement no fallback mechanisms or safety checks when interacting with Radiant's lending pools. According to Radiant's DataTypes, the protocol implements a reserve freeze mechanism (bit 57 in ReserveConfigurationMap):

DataTypes.sol#L31-L43

struct ReserveConfigurationMap {
    //bit 56: Reserve is active
    //bit 57: reserve is frozen
    //bit 58: borrowing is enabled
    uint256 data;
}

If Radiant's governance freezes a market or implements supply caps, all deposit and withdrawal operations will fail with no alternative path for users to access their funds. The strategy's immutable design means it cannot be upgraded to handle such scenarios, creating a single point of failure that could temporarily lock user funds.

Impact
Users' funds could become temporarily inaccessible if Radiant freezes their markets
The entire vault's operations for affected assets would be disrupted
No way to withdraw funds until Radiant unfreezes the market
Strategy becomes permanently unusable if Radiant retires a market
Proof of Concept

Scenario demonstrating temporary fund lockup:

User deposits 1000 USDC into the vault
Vault allocates funds to RadiantV2Strategy
RadiantV2Strategy deposits into Radiant's lending pool via _protocolDeposit()
Radiant governance detects an issue and freezes the USDC market (sets bit 57 to 1)
User attempts to withdraw their USDC:
Vault calls RadiantV2Strategy._protocolWithdraw()
_protocolWithdraw() calls lendingPool.withdraw()
Transaction reverts due to frozen market
User cannot access their funds until Radiant unfreezes the market
Tools Used

Manual Review

Recommended Mitigation Steps
Implement try-catch blocks around lending pool interactions:
function _protocolWithdraw(uint256 amount_, uint256) internal virtual override {
    try lendingPool.withdraw(asset(), amount_, address(this)) returns (uint256) {
        // Handle successful withdrawal
    } catch {
        // Emit event and handle failure
        emit WithdrawalFailed(amount_);
    }
}
Add emergency withdrawal functionality that can be triggered by governance in case of market freezes
