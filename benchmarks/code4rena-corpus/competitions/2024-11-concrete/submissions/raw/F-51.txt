S-1017
Withdrawal queue can be spammed, forcing the admin to huge gas costs to resolve legit withdraw requests
thekmj
75
Sufficient
383d ago
Finding description

When the user wants to withdraw assets, but the vault doesn't have enough funds (for example, if the protect strategy has high utilization), the withdraw is then inserted into a queue.

https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L425-L433

if (availableAssetsForWithdrawal >= assets_) {
    _withdrawStrategyFunds(assets_, receiver_);
} else {
    if (address(withdrawalQueue) == address(0)) {
        revert InsufficientVaultFunds(address(this), assets_, availableAssetsForWithdrawal);
    }
    withdrawalQueue.requestWithdrawal(receiver_, assets_); // @audit inserted into a queue
}

The admin can later claim these withdrawals for the user, using batchClaimWithdrawal

https://github.com/code-423n4/2024-11-concrete/blob/main/src/vault/ConcreteMultiStrategyVault.sol#L1059

/**
* @notice Claims multiple withdrawal requests starting from the lasFinalizedRequestId.
* @dev This function allows the contract owner to claim multiple withdrawal requests in batches.
* @param maxRequests The maximum number of withdrawal requests to be processed in this batch.
*/
function batchClaimWithdrawal(uint256 maxRequests) external onlyOwner nonReentrant {

However, the function batchClaimWithdrawal forces the admin to resolve all withdrawal requests in the sequential order, without skipping over any requests.

uint256 max = lastCreatedId < lastFinalizedId + maxRequests ? lastCreatedId : lastFinalizedId + maxRequests;
for (uint256 i = lastFinalizedId + 1; i <= max; ) {
    uint256 newAvailiableAssets = claimWithdrawal(i, availableAssets);
    // ...

Combined with the fact that redeem() has no dust protection, this allows an adversary to spam 1-wei withdrawal requests to fill up the queue. This will incur the admin a huge gas cost to resolve all of the dust withdrawals, until they reach the legit withdrawal request.

For specific strategy allocations, this can be turned into exploit in combination with the fact that the protect strategy's available assets is directly linked to the Borrow flow, by making a large borrow and artificially deflating the protect strategy pool's available balance.

Proof of concept

We show the exploit scenario.

Alice deposits some amount of funds into the earn Vault.
Alice makes a large borrow using Blueprint's earn flow.
The borrow flow makes a claim to the protect strategy, and the protect strategy deploys most of its funds to Alice.

At this point, the earn vault's available assets for withdrawal has been significantly reduced, and all new withdrawals are routed to the withdrawal queue. Alice can now spam the withdrawal queue with requests, forcing the admin to withdraw all of Alice's spam requests before reaching the legit requests.

Impact

Withdrawal queue can be grief-spammed, incurring the admin huge gas cost before legit withdrawals can be resolved.

Recommended mitigation steps

Allow the admin to settle specific withdraw requests only (or ranges of withdrawals), skipping over dust requests.
