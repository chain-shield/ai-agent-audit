Wrong check causing incorrect withdrawals leading to reverts

Finding description and impact

Wrong check causing incorrect withdrawals leading to reverts due to an unitialized variable

Proof of Concept

The protocol will call batchClaimWithdrawal() to batch withdraw requests in the withdrawal queue. On each request, we call claimWithdrawal() where we have the following check:

if (avaliableAssets != newAvaliableAssets) {
            _withdrawStrategyFunds(amount, recipient);
        }

The check is true when there are assets to withdraw. If it is true, we withdraw amount from the strategies. The issue is that the check will be true when it shouldn't. This is how newAvailableAssets gets its value:

(address recipient, uint256 amount, uint256 newAvaliableAssets) = withdrawalQueue.prepareWithdrawal(
            _requestId,
            avaliableAssets
        );

availableAssets is a function input, we call the following function:

 if (_avaliableAssets > amount) {
            ...
            avaliableAssets = _avaliableAssets - amount;
            ...
        }

If the available assets are more than the amount to withdraw, we set availableAssets to _availableAssets decreased by amount. Then, availableAssets is the newAvailableAssets in the main function. The issue is that if there is no available assets, availableAssets will not change. This is problematic as it was not initialized, thus it has a value of 0. This makes it so we will still withdraw despite not having enough assets.

Recommended mitigation steps

Refactor the code to handle this case

If available assets is 0, we will end up in the below check as we are checking a non-initialized value with the available assets:

if (avaliableAssets != newAvaliableAssets) {
            _withdrawStrategyFunds(amount, recipient);
        }

Then, we withdraw amount which we don't have. The check assumes that they are not equal when we have deducted from the provided available assets, however the they are also not equal when we don't initialize the return value.

Here is the scenario:

There are 100 assets to withdraw, that is the amount value computed in prepareWithdrawal()
The available assets are 50, so we check whether 50 is enough to fulfil the withdrawal
We don't pass the check so availableAssets returns as 0
As 0 is not equal to the 50, it is assumed that the "withdrawal" was prepared correctly and we conduct it
We revert incorrectly as we withdraw an amount we don't have

This is done in a loop where we must stop before any invalid withdrawal, however we don't causing a DoS on withdrawals.
