S-550
If user is blocklisted for any of the reward tokens they won't be able to withdraw assets from the vault.
sl1
68
Sufficient
383d ago
Bug description

Holders of the vault shares not only receive yield through the increase in their share values but also are entitled to a portion of the rewards from third-party protocols integrated with vault's strategies. When a user wishes to withdraw his assets from the vault, the internal _withdraw() function burns his shares.

ConcreteMultiStrategyVault.sol#L419-L423

function _withdraw(uint256 assets_, address receiver_, address owner_, uint256 shares, uint256 feeShares) private {
    if (msg.sender != owner_) {
       _approve(owner_, msg.sender, allowance(owner_, msg.sender) - shares);
    }
    _burn(owner_, shares);

Before actually burning the shares, _update() function will first claim all of the accrued rewards for the user.

ConcreteMultiStrategyVault.sol#L852-L856

function _update(
    address from,
    address to,
    uint256 value
) internal override {
    if (from != address(0)) updateUserRewardsToCurrent(from);
    if (to != address(0)) updateUserRewardsToCurrent(to);
    super._update(from, to, value);
}

If there are rewards accrued, the updateUserRewardsToCurrent() function will try to transfer them to a user.

ConcreteMultiStrategyVault.sol#L1042-L1045

if (rewardsToTransfer != 0) {
    totalRewardsClaimed[userAddress][
        rewardAddresses[i]
    ] += rewardsToTransfer;
    IERC20(rewardAddresses[i]).safeTransfer(
        userAddress,
        rewardsToTransfer
    );
}

However, this introduces an issue, where if a user is blocklisted for any of the reward tokens, the transfer will fail resulting in a permanent DoS of withdrawals.

Impact

If a user is blocklisted for any of the reward tokens they are then unable to withdraw funds from the vault.

Recommended Mitigation

Consider using attemptSafeTransfer() function of the TokenHelper library with revertOnBadAttempt flag set to false.

ConcreteMultiStrategyVault.sol#L1042-L1045

if (rewardsToTransfer != 0) {
    totalRewardsClaimed[userAddress][
        rewardAddresses[i]
    ] += rewardsToTransfer;
-    IERC20(rewardAddresses[i]).safeTransfer(
-        userAddress,
-        rewardsToTransfer
-    );
+    TokenHelper.attemptSafeTransfer(
+    rewardAddresses[i],
+    userAddress,
+    rewardsToTransfer,
+    false
+     );
}
