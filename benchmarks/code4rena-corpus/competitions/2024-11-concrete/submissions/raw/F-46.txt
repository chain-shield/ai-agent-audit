S-194
Unregistered RewardTokens can still be swapped for reward.
Sancybars
20
Sufficient
383d ago
Vulnerability Discussion

rewardTokens are registered in the TokenRegistry contract to be used as reward tokens, this tokens are then set to true as reward tokens.

 function updateIsReward(address tokenAddress_, bool isReward_) external override(ITokenRegistry) onlyOwner {
        if (!isRegistered(tokenAddress_) && isReward_) {
            revert Errors.UnregisteredTokensCannotBeRewards(tokenAddress_); // check if token is registered
        }
        _token[tokenAddress_].isReward = isReward_;
        emit IsRewardUpdated(tokenAddress_, isReward_);
    }

It checks if the token address is registered and then if the token is already set to true as a reward token.

When a user wants to make a swap they callswapTokensForReward in Swapper.sol which swaps the users ctAssetToken_ for the rewardToken_ specified.

    function swapTokensForReward(
        address ctAssetToken_,
        address rewardToken_,
        uint256 ctAssetAmount_
    ) external nonReentrant {
        if (!_tokenRegistry.isRewardToken(rewardToken_)) revert Errors.NotValidRewardToken(rewardToken_);

        uint256 rewardAmount = _quoteSwapFromCtAssetToReward(ctAssetToken_, rewardToken_, ctAssetAmount_);

        if (!amountAvailableForWithdrawal(rewardToken_, rewardAmount)) {
            revert Errors.NotAvailableForWithdrawal(rewardToken_, rewardAmount);
        }
        

        // first send the ctAsset tokens to the treasury
        IERC20(ctAssetToken_).safeTransferFrom(msg.sender, address(_treasury), ctAssetAmount_);
        // this isn't an issue because the msg,sender first need to pay with the ctAsset token
        // slither-disable-next-line arbitrary-send-erc20
        IERC20(rewardToken_).safeTransferFrom(address(_treasury), msg.sender, rewardAmount);

        emit Swapped(msg.sender, ctAssetToken_, rewardToken_, ctAssetAmount_, rewardAmount);
    }

The issue is that swapTokensForReward function does not verify if the token is still registered in the TokenRegistry. While it checks if the token is a valid reward token using _tokenRegistry.isRewardToken(rewardToken_), this condition only validates whether the token was previously set as a reward. However, the token might have been unregistered from the registry due to potential issues with its contract or other reasons, making it an unregistered token.

If a token is unregistered but its isReward status remains true, it allows users to swap ctAssetTokens for these unregistered tokens. This behavior contradicts the intended design of ensuring only registered tokens are eligible for reward swaps.

Impact

protocol design intends to only allow registered tokens to interact with the protocol. This issue violates that design by failing to
enforce the intended constraint fully.

unregistered tokens can be used to swap ctAssetTokens

Proof Of Concept
    function test_swapTokensForReward_Unregistered() public {
        uint256 rewardAmountInTreasury = 100_000_000 * 10 ** ASSET_DECIMALS;
        uint256 initialAssetAmount = 1_000 * 10 ** ASSET_DECIMALS;
        int256 rewardPrice = int256(500 * 10 ** ORACLE_QUOTE_DECIMALS);
        int256 assetPrice = int256(22 * 10 ** ORACLE_QUOTE_DECIMALS);
        // mint some reward tokens to the treasury
        rewardToken.mint(treasury, rewardAmountInTreasury);
        // Hazel to receive ctAssets from the ctAsset Vault
        vm.startPrank(hazel);
        asset.mint(hazel, initialAssetAmount);
        asset.approve(address(ctAsset), initialAssetAmount);
        ctAsset.deposit(initialAssetAmount, hazel);
        vm.stopPrank();

        // set prices for the oracle
        _setOraclePrices(assetPrice, rewardPrice);

        // Hazel wants to swap half of his ctAsset belongings
        uint256 hazelCtAssetAmount = ctAsset.balanceOf(hazel);
        uint256 ctAssetAmountToBeSwapped = hazelCtAssetAmount / 2;
        // treasury to approve the spending of reward tokens
        vm.prank(treasury);
        rewardToken.approve(address(swapper), rewardAmountInTreasury);
        vm.prank(hazel);
        ctAsset.approve(address(swapper), ctAssetAmountToBeSwapped);

        // calculate the expected answer
        uint256 assetAmountFromCtAssetAmount = ctAsset.convertToAssets(ctAssetAmountToBeSwapped);
        uint256 totalRewardTokenAmount = _getExpectedRewardTokenAmount(
            assetAmountFromCtAssetAmount,
            assetPrice,
            rewardPrice
        );

        vm.prank(admin);
        tokenRegistry.unregisterToken(address(rewardToken)); //unregister the reward token for use as reward token

        vm.startPrank(hazel);
        vm.expectEmit(false, true, true, true, address(swapper));
        emit SwapperEvents.Swapped(
            hazel,
            address(ctAsset),
            address(rewardToken),
            ctAssetAmountToBeSwapped,
            totalRewardTokenAmount
        );
        // create the swap
        swapper.swapTokensForReward(address(ctAsset), address(rewardToken), ctAssetAmountToBeSwapped);

        vm.stopPrank();
        // assert that the balance of reward tokens in the treasury is correct
        assertEq(rewardToken.balanceOf(hazel), totalRewardTokenAmount, "Reward Token balance Of Hazel");
    }

Recommendation

In swapTokensForReward check if the token is registered Or in unregisterToken set the isReward to false.

function unregisterToken(address tokenAddress) external onlyOwner {
    _token[tokenAddress].isReward = false;
    delete _token[tokenAddress]; // Removes the token from the registry
    emit TokenUnregistered(tokenAddress);
}

In swapTokensForReward check to confirm the token is still registered, not just marked as a reward token:

if (!tokenRegistry.isRegistered(rewardToken_)) revert Errors.TokenNotRegistered(rewardToken_);
