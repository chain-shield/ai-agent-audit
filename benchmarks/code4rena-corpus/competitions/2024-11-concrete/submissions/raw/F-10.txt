S-555
The protocol charges `withdrawFee` to the `feeReceiver`, causing funds to become stuck in the contract.
ayden
43
Sufficient
383d ago
Finding description and impact

Fee Receiver can collect fee via two functions:

withdraw
redeem

The withdraw function checks if the sender is the feeReceiver, however the redeem function does not.

Proof of Concept

Preconditions:

1.set DepositFee -> 0
2.set WithdrawFee -> 200

Scenario:

1.jimmy deposit 10e18
2.jimmy withdraw 10e18
3.fee receiver redeem max shares from vault

Test:

    function test_deposit_withdraw_fee() public {
        (ConcreteMultiStrategyVault newVault, Strategy[] memory strats) = _createNewVault(true, false, false);
        asset.mint(jimmy, 10e18);

        vm.prank(jimmy);
        asset.approve(address(newVault), type(uint256).max);

        vm.prank(jimmy);
        uint256 jimmyShares = newVault.deposit(10e18);

        vm.prank(jimmy);
        newVault.redeem(jimmyShares);

        vm.startPrank(feeRecipient);
        newVault.redeem(newVault.maxRedeem(feeRecipient));

        console2.log("feeRecipient",asset.balanceOf(feeRecipient));
    }

Out:

[PASS] test_deposit_withdraw_fee() (gas: 5428350)
Logs:
  feeRecipient 196000000000000000

Suite result: ok. 1 passed; 0 failed; 0 skipped; finished in 12.81ms (3.27ms CPU time)

From above test we can see fee receiver should claim 200000000000000000 instead of 196000000000000000
