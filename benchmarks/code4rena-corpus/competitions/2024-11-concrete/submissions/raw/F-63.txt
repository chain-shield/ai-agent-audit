S-870
Broken Functionality in ConcreteMultiStrategie Vault on Zero Allocation Strategy
a2security
00
Sufficient
383d ago
Description

There exists a denial of service (DoS) vulnerability in the ConcreteMultiStrategie Vault contract where, if the allocation amount for any of the underlying strategies is set to zero, the contract will revert on both deposit and withdrawal attempts.

To summarize, the BaseStrategy.sol contract that all the strategies inherit from will revert if the deposit amount or the withdrawal amount is zero.
src/strategies/StrategyBase.sol

    function _deposit(
        address caller_,
        address receiver_,
        uint256 assets_,
        uint256 shares_
    ) internal virtual override(ERC4626Upgradeable) whenNotPaused onlyVault {
        //slither-disable-next-line incorrect-equality
        if (shares_ == 0 || assets_ == 0) revert ZeroAmount();

when calculting the individual amounts to deposit or withdraw in the different strategies, we will multiply by the allocation amount

uint256 len = strategies.length;
for (uint256 i; i < len; ) {
    //We control both the length of the array and the external call
    //slither-disable-next-line unused-return,calls-loop
    strategies[i].strategy.deposit(
        assets_.mulDiv(strategies[i].allocation.amount, MAX_BASIS_POINTS, Math.Rounding.Floor),
        address(this)
    );

if the allocation.amount is set to zero the amount being deposited or withdrawn will be zero and the ZeroAmount error will be thrown. This will lead to all deposit and withdrawal transactions to be reverted on the vault.

Impact

The described vulnerability poses the following impact:

The vaultowners are not able to manage risk between the different strategies.
In case one of the strategies is paused/deposit limit reached, the owners can't skip depositinn/withdrwing in to it and will lead to Dosing the whole vault.
It is not possible to set the allocation of a strategy to zero.
Tools Used
Manual review
Recommended Mitigation Steps

The simplest way to mitigate this issue is to skip/continue if the withdrawal amount is zero.

uint256 len = strategies.length;
for (uint256 i; i < len; ) {
    //We control both the length of the array and the external call
    //slither-disable-next-line unused-return,calls-loop
+    if (strategies[i].allocation.amount == 0) {
+        continue;
+    }
    strategies[i].strategy.deposit(
        assets_.mulDiv(strategies[i].allocation.amount, MAX_BASIS_POINTS, Math.Rounding.Floor),
        address(this)
    );
