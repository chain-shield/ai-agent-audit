# Vulnerability details

## Impact
This way much more tokens are minted to the treasury and there are some miscalculations in the `newCumulativeIndex` variable
## Proof of Concept
When repaying a loan a user should accumulate the interest of this exact loan in the protocol. Thats not the exact case with partial repayment/liquidation. The reason for this lays in the `CDPVault::calcDecrease` function, more specifically in the following block of code:
```javascript
        if (amountToRepay != 0) {
            uint256 interestAccrued = CreditLogic.calcAccruedInterest({
                amount: debt,
                cumulativeIndexLastUpdate: cumulativeIndexLastUpdate,
                cumulativeIndexNow: cumulativeIndexNow
            });
```
```javascript
    function calcAccruedInterest(
        uint256 amount,
        uint256 cumulativeIndexLastUpdate,
        uint256 cumulativeIndexNow
    ) internal pure returns (uint256) {
        if (amount == 0) return 0;
        return (amount * cumulativeIndexNow) / cumulativeIndexLastUpdate - amount;
    }

```
Right here user accumulates the full interest of the loan, when partially repaying it. This is bad because the loans interest should be payed by the repayment amount. For example if a user pay 50% of 100 dollars loan, he will first pay the interest of those 100 dollars and then after repaying the second 50$ he will pay their interest too which steals money from the user. In this case however the users don't actually pay the accumulated interest, so there is just messed up math remaining to fix

Change the block of code in `CDPVault::calcDecrease` function to this:
```diff
  if (amountToRepay != 0) {
            uint256 interestAccrued = CreditLogic.calcAccruedInterest({          
-                amount: debt,
+                amount: amountToRepay,
                cumulativeIndexLastUpdate: cumulativeIndexLastUpdate,
                cumulativeIndexNow: cumulativeIndexNow
            });
```
