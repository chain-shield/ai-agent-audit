# Vulnerability details

When `deltaDebt` is zero and `deltaCollateral` is negative, the function incorrectly determines that the position is safe, even if the collateral value is insufficient to cover the debt.

The root cause is in the following code block in the `modifyCollateralAndDebt` function: [CDPVault.sol#L451-L454](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L451-L454)
```solidity
if (
    (deltaDebt > 0 || deltaCollateral < 0) &&
    !_isCollateralized(calcTotalDebt(_calcDebt(position)), collateralValue, config.liquidationRatio)
) revert CDPVault__modifyCollateralAndDebt_notSafe();
```
The condition `(deltaDebt > 0 || deltaCollateral < 0)` checks if the debt is increasing or the collateral is decreasing, which would make the position riskier. However, the subsequent check using the `_isCollateralized` function fails to handle the case when `deltaDebt` is zero and `deltaCollateral` is negative.

## Impact
If a position's collateral value falls below the required threshold (debt multiplied by the liquidation ratio), it should be considered unsafe and trigger a revert. However, due to the incorrect safety check, the contract permits the creation of unsafe positions when `deltaDebt` is zero and `deltaCollateral` is negative.

* Users can create positions with insufficient collateral, exposing them to a higher risk of liquidation.
* If many positions become unsafe, it could strain the liquidity of the system, as there may not be enough collateral to cover the outstanding debt.

Consider the following scenario:
```solidity
assert deltaDebt > 0 || deltaCollateral < 0 => collateralValue >= assert_uint256(newDebt * liquidationRatio), "Position became unsafe";
```
See the following values:
```solidity
deltaDebt = 0
deltaCollateral = -1
liquidationRatio = 1000000000000000000
newDebt = 1
collateralValue = 0
```
With these values, the condition `deltaDebt > 0 || deltaCollateral < 0` evaluates to true because `deltaCollateral` is negative (-1). However, the assertion `collateralValue >= assert_uint256(newDebt * liquidationRatio)` fails because:
```solidity
collateralValue = 0
assert_uint256(newDebt * liquidationRatio) = 1 * 1000000000000000000 = 1000000000000000000
```
Since `collateralValue` (0) is less than `assert_uint256(newDebt * liquidationRatio)` (1000000000000000000), the assertion fails, indicating that the position became unsafe.

1. Alice creates a position with an initial collateral value of 10 ETH and a debt of 5000 DAI.
2. The liquidation ratio is set to 150%, meaning the collateral value should always be at least 150% of the debt.
3. Alice calls the `modifyCollateralAndDebt` function with the following parameters:
   * `deltaDebt` = 0
   * `deltaCollateral = -6 ETH

4. The function calculates the new collateral value as 4 ETH (10 ETH - 6 ETH).
5. The safety check condition `(deltaDebt > 0 || deltaCollateral < 0)` evaluates to true because `deltaCollateral` is negative.
6. However, the `_isCollateralized` function incorrectly determines that the position is safe because the collateral value (4 ETH) is greater than the debt (5000 DAI) multiplied by the liquidation ratio (150%).
7. The function allows modification, resulting in an unsafe position with insufficient collateral.

## Recommended Mitigation Steps
The contract should ensure that the collateral value is sufficient to cover the new debt multiplied by the liquidation ratio, even when `deltaDebt` is zero and `deltaCollateral` is negative.

the `modifyCollateralAndDebt` should be updated to handle the case when `deltaDebt` is zero and `deltaCollateral` is negative. The `_isCollateralized` function should be modified to ensure that the collateral value is always sufficient to cover the debt multiplied by the liquidation ratio, regardless of the values of `deltaDebt` and `deltaCollateral`.

update the [_isCollateralized function](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L345-L351) as follows
```solidity
function _isCollateralized(
    uint256 debt,
    uint256 collateralValue,
    uint256 liquidationRatio
) internal pure returns (bool) {
    return collateralValue >= debt * liquidationRatio / WAD;
}
```
By multiplying the debt by the liquidation ratio and dividing by `WAD` (10^18), the function ensures that the collateral value is always compared against the correct threshold.

Additionally, the safety check in the `modifyCollateralAndDebt` function should be updated to use the modified `_isCollateralized` function:
```solidity
if (!_isCollateralized(calcTotalDebt(_calcDebt(position)), collateralValue, config.liquidationRatio)) {
    revert CDPVault__modifyCollateralAndDebt_notSafe();
}
```
This removes the condition `(deltaDebt > 0 || deltaCollateral < 0)` and simply checks if the position is properly collateralized based on the updated `_isCollateralized` function.
