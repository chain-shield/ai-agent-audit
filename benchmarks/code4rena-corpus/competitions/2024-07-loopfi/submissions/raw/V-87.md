# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The setRelock function in the MultiFeeDistribution contract can be called by any address without any access control. 

This function allows users to enable or disable the auto-relock feature. 

Without proper access restrictions, unauthorised users can alter the auto-relock status.

Location: MultiFeeDistribution.sol

***Code Snippet:***
```sol
    function setRelock(bool status) external virtual {
        autoRelockDisabled[msg.sender] = !status;
    }
```

The function is publicly accessible and allows any external address to set the autoRelockDisabled status for the calling address. 

This could be exploited by unauthorised users, leading to unexpected changes in the auto-relock status.

## Recommended Mitigation Steps
To prevent unauthorized access to the setRelock function, implement the following mitigations:

***1.	Access Control:***
	•	Ensure the function is only callable by the intended users or contracts.
	•	Use access control mechanisms, such as OpenZeppelin’s Ownable or AccessControl, to enforce permissions.

***2.	Modifier Implementation:***
	•	Add a modifier to check if the caller is authorized to set their relock status.

***Example Mitigation Code***
```sol
    function setRelock(bool status) external virtual onlyAuthorised {
        autoRelockDisabled[msg.sender] = !status;
    }
```
