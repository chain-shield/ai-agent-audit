# Vulnerability details

## Impact

Wrong shares will be minted to the treasury.

## Proof of Concept

In the contract `PoolV3.sol`, the function `mintProfit` invokes `_mint(treasury, amount)` without converting the amount to shares first. This is wrong because the `amount` actually indicates the underlyingToken's change and not the share's change. Therefore, the function `mintProfit` should convert the amount to share first before invoking `_mint`.

https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L899

```solidity
    function mintProfit(uint256 amount) external creditManagerOnly {
        _mint(treasury, amount);

        _updateBaseInterest({
            expectedLiquidityDelta: amount.toInt256(),
            availableLiquidityDelta: 0,
            checkOptimalBorrowing: false
        }); // U:[LP-14B,14C,14D]
    }
```

As a comparison, the function `repayCreditAccount` did correctly `convertToShares` before `mint()`.
