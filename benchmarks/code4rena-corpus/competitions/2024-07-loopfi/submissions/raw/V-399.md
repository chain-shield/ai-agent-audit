# Vulnerability details

## Proof of Concept
The `addQuotaToken` function is designed to add a new quoted token to the gauge and set its initial rate parameters. The function also attempts to add the token to the quota keeper if it hasn't been added already. However, the function lacks proper validation to ensure that only quoted tokens are added. As a result, it is possible to add non-quoted tokens, which could lead to unintended behavior within the system.

Code Snippet:
```solidity
function addQuotaToken(
    address token,
    uint16 minRate,
    uint16 maxRate
)
    external
    override
    nonZeroAddress(token) // U:[GA-04]
    configuratorOnly // U:[GA-03]
{
    if (isTokenAdded(token) || token == IPoolV3(pool).underlyingToken()) {
        revert TokenNotAllowedException(); // U:[GA-04]
    }
    _checkParams({minRate: minRate, maxRate: maxRate}); // U:[GA-04]

    quotaRateParams[token] = QuotaRateParams({
        minRate: minRate,
        maxRate: maxRate,
        totalVotesLpSide: 0,
        totalVotesCaSide: 0
    }); // U:[GA-05]

    IPoolQuotaKeeperV3 quotaKeeper = _poolQuotaKeeper();
    if (!quotaKeeper.isQuotedToken(token)) {
        quotaKeeper.addQuotaToken({token: token}); // U:[GA-05]
    }

    emit AddQuotaToken({token: token, minRate: minRate, maxRate: maxRate}); // U:[GA-05]
}

```
The purpose of the `addQuotaToken` function is to introduce a new token into the system that can participate in the quota-based management of the pool. This involves setting up the interest rate parameters (`minRate` and `maxRate`) for the token and ensuring it is recognized by the `PoolQuotaKeeperV3` contract.

However, the function only checks if the token is already added or if it is the underlying token of the pool. It does not validate whether the token is a quoted token. The function then adds the token to the `quotaRateParams` and the `PoolQuotaKeeperV3` if it is not already recognized as a quoted token. This lack of validation allows non-quoted tokens to be mistakenly added, potentially leading to inconsistencies in quota management.
## Impact
If non-quoted tokens are added to the system, they will not be properly recognized by the `PoolQuotaKeeperV3` contract as part of the quota system. This could result in these tokens not contributing to or being affected by quota calculations, leading to potential revenue discrepancies and improper quota management. Non-quoted tokens might not be subject to the same quota-based restrictions or benefits, which could lead to unintended financial outcomes.

Manual
## Recommended Mitigation Steps
Introduce a validation check within the `addQuotaToken` function to ensure that only quoted tokens are eligible for addition.
```solidity
require(quotaKeeper.isQuotedToken(token), "Token must be a quoted token");
```
