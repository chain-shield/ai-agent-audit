# Vulnerability details


## Proof of Concept

Take a look at [CDPVault#liquidatePosition()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L509-L574), also see [CDPVault#liquidatePositionBadDebt()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L579-L632).

We can see that these functions are protected by the `whenNotPaused` modifier.

Issue however is that when the protocol indeed gets paused, not all core functionalities are paused with it.

This then allows for malicious users to borrow out outrageous loans so as to game the system, since they know they can't get liquidated while the Vault is paused, considering both the functionality of the borrows and withdrawals are not paused when the protocol gets paused.

- See [CDPVault#borrow()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L256-L266).
- See [CDPVault#withdraw()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L239-L249).

## Impact

Users can easily make bad debts when the protocol is paused, which can push protocol to a bank run if the paused is elongated and multiple of these very risky _risk free to the users_ debt are taken out of the protocol.

## Recommended Mitigation Steps

Consider pausing all core logics when the protocol is paused, i.e in this case apply the `whenNotPaused` to both [CDPVault#borrow()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L256-L266) & [CDPVault#withdraw()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L239-L249).
