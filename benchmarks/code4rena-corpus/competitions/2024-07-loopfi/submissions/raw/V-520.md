# Vulnerability details

## Title
Functions in CDPVault.sol without modifier ```onlyRegisteredVault```, users are still able to deposit and borrow in a removed vault

## Impact
Unlike functions in PositionAction.sol, there is no modifier ```onlyRegisteredVault``` in CDPVault.sol to check if the vault is registered. Users are still possible to deposit and borrow in a removed vault, which breaks the functionality of ```VaultRegistry:::removeVault```.

## Proof of Concept

Add the test below to Tokenomics.t.sol
```
    function test_vaultWithoutonlyRegisteredVaultModifier() public {
        
        // Vault is registered
        console.log("-------- Vault is registered --------");
        ICDPVault[] memory beforeVaults = vaultRegistry.getVaults();
        console.log("Number of vaults created:", beforeVaults.length);

        // Remove vault
        console.log("-------- Remove vault --------");
        vaultRegistry.removeVault(ICDPVault(address(vault)));

        ICDPVault[] memory afterVaults = vaultRegistry.getVaults();
        console.log("Number of vaults created after removal:", afterVaults.length);

        // User deposits and borrows in a removed vault
        address user = vm.addr(uint256(keccak256("user")));
        uint256 collateral = 100 ether;
        uint256 debt = 50 ether;
        _borrow(user, collateral, debt);

        (uint256 collateralAfterDeposit, uint256 debtAfterBorrow, , , , ) = vault.positions(user);
        console.log("User's collateral after _borrow:", collateralAfterDeposit);
        console.log("User's debt after _borrow:", debtAfterBorrow);
    }
```

```
Logs:
  -------- Vault is registered --------
  Number of vaults created: 1
  -------- Remove vault --------
  Number of vaults created after removal: 0
  User's collateral after _borrow: 100000000000000000000
  User's debt after _borrow: 50000000000000000000
```
