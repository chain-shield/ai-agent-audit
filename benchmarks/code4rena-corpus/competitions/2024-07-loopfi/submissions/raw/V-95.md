# Vulnerability details

## Impact

When the Pool is paused, users' debt and collateral valuations may place them at risk of liquidation. However, as soon as the pool is unpaused to resume operations, MEV (Maximal Extractable Value) bots can intercept and execute transactions before users have the opportunity to take actions like repaying debt or adding collateral to avoid liquidation. This exploitation can occur in the first block after the system transitions, potentially leading to the forced liquidation of vulnerable positions.

The issue has been previously identified and confirmed valid in multiple contests including:

 https://github.com/sherlock-audit/2023-05-perennial-judging/issues/190
 https://github.com/sherlock-audit/2023-03-notional-judging/issues/203
 https://github.com/sherlock-audit/2023-02-blueberry-judging/issues/290

## Proof of Concept

Update the ACLNonReentrantTrait pause functions to remove admin restrictions to ease calling these functions:
````

    /// @notice Pauses contract, can only be called by an account with pausable admin role
    function pause() external virtual {
        _pause();
    }

    /// @notice Unpauses contract, can only be called by an account with unpausable admin role
    function unpause() external virtual {
        _unpause();
    }
````

add this POC to the CDPVault.t.sol test file:

## Recommended Mitigation Steps
Consider including a grace period after unpausing during which liquidation is temporarily disallowed to allow users to avoid unfair liquidation by closing their positions or supplying additional collateral.
