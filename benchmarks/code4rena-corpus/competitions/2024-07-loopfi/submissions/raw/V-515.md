# Vulnerability details

## Impact
In order for the user to repay it's debt, it has to call modifyCollateralAndDebt() 
(https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L367C14-L367C37). 
When repaying debt, the following else if is executed (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L402-L432),

and, if the amount that the user is repaying isn't the total debt of the position, this else is executed: (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L418-L426). 

The problem arises in calcDecrease() function (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L652-L714).

The calcDecrease() function first subtracts the quota interest from the repayAmount (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L665-L681), and then, the accrued interest (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L685-L710).

The problem is, is that if the user decides to repay <= cumulativeQuotaInterest, it wont invoke the newCumulativeIndex calculation (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L703-L708). Meaning, that if the user would have repayed atleast cumulativeQuotaInterest+1, they would have received a way lower interest rate, simply because the profit variable (https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L676) is reused in the newCumulativeIndex calculation.

To sum it up, users can have way higher interest rate than normal, simply because they paid <= cumulativeQuotaInterest and didn't invoke the newCumulativeIndex calculation.

We can see we started with the same accruedInterest, same cumulativeQuotaInterest, however our accruedInterest after the repayment is entirely different.
Following the same calculation as above, 13671659951651893633 + 1128082191780821917+1 != 15927824335213537468 (accrued interest after the repayment + cumulativeQuotaInterest != accrued interest before repayment), simply because the newCumulativeIndex recalculation is invoked.

In this case, the user just saved 1128082191780821918 worth of interest, just by repaying cumulativeQuotaInterest+1 instead of, paying <= cumulativeQuotaInterest.

## Recommended Mitigation Steps
You can calculate the newCumulativeIndex inside the cumulativeQuotaInterest repayment logic, something like this: "

if (cumulativeQuotaInterest != 0 && amountToRepay != 0) {
            // All interest accrued on the quota interest is taken by the DAO to be distributed to LP stakers, dLP stakers and the DAO

            if (amountToRepay >= cumulativeQuotaInterest) {
                amountToRepay -= cumulativeQuotaInterest; // U:[CL-3]
                profit += cumulativeQuotaInterest; // U:[CL-3]

                newCumulativeQuotaInterest = 0; // U:[CL-3]
            } else {
                // If amount is not enough to repay quota interest + DAO fee, then send all to the stakers
                uint256 quotaInterestPaid = amountToRepay; // U:[CL-3]
                profit += amountToRepay; // U:[CL-3]
                amountToRepay = 0; // U:[CL-3]

                newCumulativeQuotaInterest = uint128(cumulativeQuotaInterest - quotaInterestPaid); // U:[CL-3]
// you can perform the calculation here
newCumulativeIndex =
                    (INDEX_PRECISION * cumulativeIndexNow * cumulativeIndexLastUpdate) /
                    (INDEX_PRECISION *
                        cumulativeIndexNow -
                        (INDEX_PRECISION * profit * cumulativeIndexLastUpdate) /
                        debt); // U:[CL-3]
            }

        }"
