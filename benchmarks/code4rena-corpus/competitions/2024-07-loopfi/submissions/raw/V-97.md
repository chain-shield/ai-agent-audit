# Vulnerability details

## Impact
The `transferAndJoin` function in the provided codebase does not sort tokens by their addresses before constructing the `maxAmountIn` array. This oversight results in transaction failures or incorrect behavior when joining a Balancer Pool, as the pool *expects*(tokens to be provided in a specific order) As you can see [here](https://docs.balancer.fi/reference/joins-and-exits/pool-joins.html#token-ordering).

https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/PoolAction.sol#L81C2-L94C20

## Proof of Concept
When joining a Balancer pool, tokens must be sorted manually by their addresses to match the pool's internal ordering. The `transferAndJoin` ***does not*** sort the tokens by their addresses. it relies on the `assets` array being pre-sorted before being passed to the function. This assumption can lead to issues if tokens are not already sorted, as the Balancer pool expects tokens to be sorted in a specific order.
```
function transferAndJoin(
        address from,
        PermitParams[] calldata permitParams,
        PoolActionParams calldata poolActionParams
    ) external {
        if (from != address(this)) {
            if (poolActionParams.protocol == Protocol.BALANCER) {
                (, address[] memory assets, , uint256[] memory maxAmountsIn) = abi.decode(
                    poolActionParams.args,
                    (bytes32, address[], uint256[], uint256[])
                );

                if (assets.length != permitParams.length) {
                    revert PoolAction__transferAndJoin_invalidPermitParams();
                }

                for (uint256 i = 0; i < assets.length; ) {
                    if (maxAmountsIn[i] != 0) {
                        _transferFrom(assets[i], from, address(this), maxAmountsIn[i], permitParams[i]);
                    }

                    unchecked {
                        ++i;
                    }
                }
            } else {
                revert PoolAction__transferAndJoin_unsupportedProtocol();
            }
        }

        join(poolActionParams);
    }
```

Additionally, the `maxAmountIn` array, which specifies the maximum amounts of each token to be provided, must be constructed in parallel with the sorted `assets` array, the current implementation of `transferAndJoin` does not perform the sorting, leading to a potential mismatch.

> Scenerio Without Sorting:

Alice wants to join Balancer with the following tokens and amounts:
     - TokenA(addr: 0xAAAAA)
     - TokenB(addr: 0xBBBBB)
     - TokenC(addr: 0xCCCCC)
     she plans to provide:
         - 1000 TokenA
         - 500 TokenB
         - 700 TokenC
```
address[] memory assets = [0xCCCCC, 0XBBBBB, 0xAAAAA];
uint256[] memory maxAmountIn - [700, 500, 1000];
```
Since the [Balancer pool expects tokens to be sorted by address](https://docs.balancer.fi/reference/joins-and-exits/pool-joins.html#token-ordering), the above arrays might cause a mismatch, leading to failed transactions meaning that the Pool might expect ToeknA first, but Alice provided TokenB first.

The function should sort the assets and maxAmountsIn arrays by token address before performing any operations and calling joinPool.

Properly sorting tokens by their addresses and maintaining parallel alignment with the maxAmountsIn array is crucial when joining a Balancer pool. Failing to do so can result in transaction failures or incorrect behavior. The current [transferAndJoin](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/PoolAction.sol#L82) function does not perform this necessary sorting, leading to potential issues.

## Recommended Mitigation Steps
Should be sorted by addresses in a parallel order
```
address[] memory assets = [0xAAAAA, 0XBBBBB, 0xCCCCC];
uint256[] memory maxAmountIn - [700, 500, 1000];
```
Also, include a mechanism in the `transferAndJoin` that sorts assets and maxAmountIn arrays in parallel.
```
  // Sort assets and maxAmountsIn in parallel
            for (uint256 i = 0; i < assets.length - 1; i++) {
                for (uint256 j = i + 1; j < assets.length; j++) {
                    if (assets[i] > assets[j]) {
                        // Swap assets
                        address tempAsset = assets[i];
                        assets[i] = assets[j];
                        assets[j] = tempAsset;

                        // Swap maxAmountsIn to keep the arrays parallel
                        uint256 tempAmount = maxAmountsIn[i];
                        maxAmountsIn[i] = maxAmountsIn[j];
                        maxAmountsIn[j] = tempAmount;
                    }
                }
            }
```
