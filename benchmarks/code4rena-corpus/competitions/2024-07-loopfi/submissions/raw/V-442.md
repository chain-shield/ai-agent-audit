# Vulnerability details

## Vulnerability Details

A liquidation that takes all the collateral should clear the debt to 0. It does not make sense to have a position with 0 collateral and non zero debt for multiple reasons

1. The user will not pay back the loan since there is no collateral to get back
2. No liquidator will liquidate the position because there is no collateral to take

The root cause of this issue is that inside the `liquidatePosition` function, the `maxRepayment` does not account for the `liquidationDiscount`

Consider the following scenario, assume a 10% `liquidationDiscount`

1. User deposits 100 WETH worth of pendle LP tokens as collateral and borrows 80 WETH
2. The pendle LP token price drops, the collateral is now only worth 80 WETH
3. Due to the liquidationDiscount, the liquidator only needs to repay 72 WETH to take all the collateral
4. In the end state of the position the collateral will = 0, but the debt will = 8 WETH (10% of the original position)

This scenario is proven in the following POC

## Impact

One major impact is that all calculations involving `totalDebt` will be wrong since it will be inflated by positions that have debt but no collateral. Every time a user opens/closes/liquidates a position `rewardController.handleActionAfter(owner, position.debt, totalDebt_);` in `_modifyPosition()` is called using the inflated totalDebt_, this affects all users with positions not just the liquidated one

The user that got liquidated will expect that their debt was closed since they lost all their collateral. If they deposit in the protocol again, they will not be able to withdraw the funds because they will be expected to repay the loan that they were already liquidated for which is unfair

## Recommended Mitigation Steps

A simple solution is to check if collateral = 0, then set the debt = 0 as well.

I would recommend testing this out heavily to iron out other issues related to the `liquidationDiscount`
