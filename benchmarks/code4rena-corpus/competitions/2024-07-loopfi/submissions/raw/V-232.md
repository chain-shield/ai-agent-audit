# Vulnerability details

## Vulnerability Details 
Before the AuraVault deposits into the `rewardPool` it approves the rewardPool over the assets using the `safeApprove` function.

```solidity
// Deposit  in reward pool
IERC20(asset()).safeApprove(rewardPool, assets); 
IPool(rewardPool).deposit(assets, address(this));
```

The issue is that OpenZeppelin's `safeApprove` function will revert if the account already is approved and the new safeApprove() is done with a non-zero value

If the `rewardPool` has a deposit cap for example and only deposits some of the approved assets and then refunds the rest back to the `AuraVault` or for any other reason does not use all the assets, then all future calls to `safeApprove(rewardPool, assets)` will revert.

This causes a permanent DOS of these functions in the AuraVault `deposit()`, `mint()` and `claim()`. Rendering the contract useless. 

## Impact
Complete DOS of `deposit()`, `mint()` and `claim()` functions, rendering the contract useless

## Recommended Mitigation Steps
use the `forceApprove` function instead
