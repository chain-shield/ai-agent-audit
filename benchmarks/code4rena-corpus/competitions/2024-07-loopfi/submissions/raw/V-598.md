# Vulnerability details

## Impact
When [`MultiFeeDistribution#removeReward()`](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/reward/MultiFeeDistribution.sol#L365-L398) is called to remove the reward token, user has no way to claim their unclaimed reward.

## Proof of Concept
[`MultiFeeDistribution#removeReward()`](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/reward/MultiFeeDistribution.sol#L365-L398) is used to remove the reward token from reward list. Once removed, the info of removed reward token will be cleared. Any one who hasn't claim their reward yet are unable to claim it anymore, resulting all unclaimed reward of removed token being stuck in `MultiFeeDistribution` permanently.

Copy below codes to [MultiFeeDistribution.t.sol](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/test/unit/MultiFeeDistribution.t.sol) and run `forge test --match-test test_removeRewardCauseGetRewardFailure`:

```solidity
    function test_removeRewardCauseGetRewardFailure() public {
        ERC20Mock rewardToken = new ERC20Mock();
        uint256 amount = 10 ether;
        _addLockDurations();
        address alice = makeAddr("alice");

        address[] memory minters = new address[](1);
        minters[0] = address(this);
        multiFeeDistribution.setMinters(minters);
        multiFeeDistribution.addReward(address(rewardToken));
        rewardToken.mint(address(multiFeeDistribution), 10 ether);

        stakeToken.mint(address(this), amount);
        multiFeeDistribution.setLPToken(address(stakeToken));

        address incentivesController = vm.addr(uint256(keccak256("incentivesController")));
        address treasury = vm.addr(uint256(keccak256("treasury")));
        multiFeeDistribution.setAddresses(IChefIncentivesController(incentivesController), treasury);

        vm.mockCall(
            incentivesController,
            abi.encodeWithSelector(IChefIncentivesController.afterLockUpdate.selector, alice),
            abi.encode(true)
        );
        vm.mockCall(
            mockPriceProvider,
            abi.encodeWithSelector(IPriceProvider.getRewardTokenPrice.selector, address(rewardToken), 10 ether),
            abi.encode(1e18)
        );
        vm.mockCall(
            incentivesController,
            abi.encodeWithSelector(IChefIncentivesController.setEligibilityExempt.selector, alice, true),
            abi.encode(true)
        );
        vm.mockCall(
            incentivesController,
            abi.encodeWithSelector(IChefIncentivesController.setEligibilityExempt.selector, alice, false),
            abi.encode(true)
        );
        stakeToken.approve(address(multiFeeDistribution), amount);
        multiFeeDistribution.stake(amount, alice, 0);
        vm.warp(block.timestamp + multiFeeDistribution.rewardsLookback());
        vm.prank(alice);
        multiFeeDistribution.getAllRewards();
        vm.warp(block.timestamp + multiFeeDistribution.rewardsDuration());
        IFeeDistribution.RewardData[] memory rewardsData = multiFeeDistribution.claimableRewards(alice);
        //@audit-info alice has unclaimed rewardToken reward
        assertNotEq(rewardsData[1].amount, 0);
        multiFeeDistribution.removeReward(address(rewardToken));
        address[] memory rewardTokens = new address[](1);
        rewardTokens[0] = address(rewardToken);
        //@audit-info alice can not claim rewardToken reward since rewardToken has been removed.
        vm.expectRevert(MultiFeeDistribution.InvalidPeriod.selector);
        vm.prank(alice);
        multiFeeDistribution.getReward(rewardTokens);
    }
```

## Recommended Mitigation Steps
When a token is not eligible as reward anymore, it might be better to mark it as `disabled` instead of remove its info.  The new reward distribution on this `disabled` token should not be allowed, but user should be allowed to claim their unclaimed reward.
