# Vulnerability details

## Proof of Concept
In the `balancerSwap` function, the indices for assets in the `BatchSwapStep` array are incorrectly managed for both `EXACT_IN` and `EXACT_OUT` swaps. The asset indices determine the order in which assets are swapped, and improper handling can lead to incorrect asset swaps or unintended behavior.

```solidity
// Construct the BatchSwapStep array
for (uint256 i; i < pathLength; ) {
    unchecked {
        swaps[i] = BatchSwapStep({
            poolId: poolIds[i],
            assetInIndex: i + inIncrement,
            assetOutIndex: i + outIncrement,
            amount: 0, // 0 to autocalculate
            userData: userData
        });
        ++i;
    }
}
swaps[0].amount = amount; // amount always pertains to the first swap
```
Issue Breakdown:
1. EXACT_IN Swap:

- **Expected Behavior**: `assetInIndex` for each step should be the same as the `assetOutIndex` of the previous step. `assetOutIndex` should be the next index.
- **Current Behavior**: `assetInIndex` and `assetOutIndex` are both incremented by fixed increments (`inIncrement` and `outIncrement`), which do not necessarily align with the expected sequential or reversed order.
2. EXACT_OUT Swap:
- **Expected Behavior**: `assetOutIndex` for each step should be the same as the `assetInIndex` of the previous step. `assetInIndex` should be the next index.
- **Current Behavior**: The indices are incremented incorrectly, resulting in `assetInIndex` and `assetOutIndex` not correctly reflecting the necessary asset ordering.
## Impact
The incorrect index handling can lead to improper asset swaps within the `balancerSwap` function, which may result in unintended trades, incorrect asset balances, or losses. The misalignment between the indices can prevent the function from executing swaps in the intended order, potentially causing financial loss or reduced efficiency in the swap operations.

## Recommended Mitigation Steps
Adjust the index assignments in the `BatchSwapStep` array based on the swap type:
```solidity
// Construct the BatchSwapStep array
for (uint256 i; i < pathLength; ) {
    unchecked {
        swaps[i] = BatchSwapStep({
            poolId: poolIds[i],
            assetInIndex: swapType == SwapType.EXACT_IN ? i : pathLength - i - 1,
            assetOutIndex: swapType == SwapType.EXACT_IN ? i + 1 : pathLength - i - 2,
            amount: 0, // 0 to autocalculate
            userData: userData
        });
        ++i;
    }
}
swaps[0].amount = amount; // amount always pertains to the first swap
```
- For `EXACT_IN`, set `assetInIndex` to `i` and `assetOutIndex` to `i + 1` to ensure proper sequential order.
- For `EXACT_OUT`, set `assetInIndex` to `pathLength - i - 1` and `assetOutIndex` to `pathLength - i - 2` to ensure reverse sequential order.
