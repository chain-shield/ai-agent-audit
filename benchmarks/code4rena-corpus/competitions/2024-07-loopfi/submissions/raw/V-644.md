# Vulnerability details

## Impact

The `poolQuotaRevenue()` function in the `PoolQuotaKeeperV3` contract incorrectly calculates the pool's quota revenue. It uses the current rate without considering the time elapsed since the last update, resulting in underreported earnings. This results in an inaccurate representation of the actual accrued interest, potentially leading to incorrect calculations.

## Proof of Concept

Take a look at the `poolQuotaRevenue()` function: https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/quotas/PoolQuotaKeeperV3.sol#L135-L153

```solidity
function poolQuotaRevenue() external view virtual override returns (uint256 quotaRevenue) {
    address[] memory tokens = quotaTokensSet.values();
    uint256 len = tokens.length;

    for (uint256 i; i < len; ) {
        address token = tokens[i];
        TokenQuotaParams storage tokenQuotaParams = totalQuotaParams[token];
        (uint16 rate, , ) = _getTokenQuotaParamsOrRevert(tokenQuotaParams);

        quotaRevenue += (IPoolV3(pool).creditManagerBorrowed(creditManagers[token]) * rate) / PERCENTAGE_FACTOR;

        unchecked {
            ++i;
        }
    }
}
```

The function calculates revenue using the current `rate` without accounting for the time passed since the last update. This approach is flawed because:

1. It doesn't consider the cumulative nature of interest accrual.
2. It effectively calculates revenue as if it were just updated, ignoring any time that has passed since the last update.



Scenario:
- Suppose the last update to the quota rates was a month ago.
- The interest rate for a token is set at 5% Annual Percentage Rate (APR).
- The current implementation of the `poolQuotaRevenue()` function calculates the revenue using the current rate without considering the time that has passed since the last update.
- As a result, the function would return a revenue as if the interest has only accrued for an instant at 5% APR, rather than for the full month that has actually passed.


The correct approach should use the difference between the current cumulative index and the last updated cumulative index to calculate the actual accrued interest over time.
