# Vulnerability details

## Impact
Chainlink aggregators have a built in circuit breaker if the price of an asset goes outside of a predetermined price range. The result is that if an asset experiences a flash crash in value, the price that the oracle returns will be the minPrice instead of the actual price of the asset. An example of such a scenario would be the LUNA crash.

The _fetchAndValidate() function in ChainlinkOracle.sol does not check if the priced returned is equal to the min or max price. In such cases the actual market price of the asset could be less/more than the price returned from the Chainlink Oracle. The internal function _fetchAndValidate() is used by the external spot() function to fetch the price of a token using a Chainlink Oracle. This external spot() function is used by the CDPVault::spotPrice() function to get the current spot price of the collateral token. This spotPrice is used to calculate the collateral value to check if an account is properly collateralized when borrowing or withdrawing. 

During a flash crash where the price dips below the minPrice, users will be able to borrow or withdrawal even when they should not be able to do so because their collateral value will be calculated at the Oracle's minPrice rather than the lower actual market price. 

The spotPrice() value is also used in the liquidatePosition() function, so in the case of a flash crash mentioned above, users who should be liquidated will not be done so due to their inaccurate and inflated collateral values. 

This was the underlying cause behind the Venus Protocol and Blizz Finance drainings : https://rekt.news/venus-blizz-rekt/

## Recommended Mitigation Steps
ChainlinkOracle.sol should have a check to make sure that the answer is in the valid price range. Something like :
```
if (answer >= maxPrice or answer <= minPrice){
    isValid = false;
```
