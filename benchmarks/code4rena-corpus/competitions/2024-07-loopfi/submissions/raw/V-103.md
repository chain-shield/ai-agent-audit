# Vulnerability details

## Impact
Users who have initiated a cooldown period by calling `cooldownAssets()` or `cooldownShares()` in the `StakingLPEth` contract will not be able to immediately withdraw their assets from the `Silo` contract if the cooldown duration is set to zero after their initiation. This situation locks users' assets in the `Silo` contract until their individual cooldown periods expire, despite the global cooldown mechanism being disabled.

## Proof of Concept
The issue comes about as a result of the interaction between the cooldown mechanism implemented in the `StakingLPEth.sol` contract and the withdrawal functionality in both `StakingLPEth.sol` and `Silo.sol`.

Users initiate a cooldown period through either `cooldownAssets()` or `cooldownShares()`, locking their assets in the `Silo` contract until the cooldown expires.

[cooldownAssets:](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L104-L113)
```solidity
104:     function cooldownAssets(uint256 assets) external ensureCooldownOn returns (uint256 shares) {
105:         if (assets > maxWithdraw(msg.sender)) revert ExcessiveWithdrawAmount();
106: 
107:         shares = previewWithdraw(assets);
108: 
109:         cooldowns[msg.sender].cooldownEnd = uint104(block.timestamp) + cooldownDuration;
110:         cooldowns[msg.sender].underlyingAmount += uint152(assets);
111: 
112:         _withdraw(msg.sender, address(silo), msg.sender, assets, shares);
113:     }

```

The contract owner can disable the cooldown mechanism by setting the cooldown duration to zero using `setCooldownDuration(uint24 duration)`.

[setCooldownDuration:](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L130-L138)
```solidity
130:     function setCooldownDuration(uint24 duration) external onlyOwner {
131:         if (duration > MAX_COOLDOWN_DURATION) {
132:             revert InvalidCooldown();
133:         }
134: 
135:         uint24 previousDuration = cooldownDuration;
136:         cooldownDuration = duration;
137:         emit CooldownDurationUpdated(previousDuration, cooldownDuration);
138:     }

```

Users can only withdraw their assets after the cooldown period ends using the `unstake()` function. However, if the cooldown duration is set to zero after some users have initiated a cooldown, these users still need to wait until their individual cooldown periods end.

[unstake:](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L88-L100)
```solidity
088:     function unstake(address receiver) external {
089:         UserCooldown storage userCooldown = cooldowns[msg.sender];
090:         uint256 assets = userCooldown.underlyingAmount;
091: 
092:         if (block.timestamp >= userCooldown.cooldownEnd || cooldownDuration == 0) {
093:             userCooldown.cooldownEnd = 0;
094:             userCooldown.underlyingAmount = 0;
095: 
096:             silo.withdraw(receiver, assets);
097:         } else {
098:             revert InvalidCooldown();
099:         }
100:     }

```

The issue is that even when `cooldownDuration` is set to 0, users who have already initiated a cooldown must still wait until their individual `cooldownEnd` is reached. This creates a situation where new users can withdraw immediately (using the `withdraw()` function), but users with ongoing cooldowns are still locked out.

## Recommended Mitigation Steps
Modify the `unstake()` function to allow immediate withdrawal of assets if the global cooldown duration is set to zero, regardless of individual user cooldown periods. 
```diff
function unstake(address receiver) external {
    UserCooldown storage userCooldown = cooldowns[msg.sender];
    uint256 assets = userCooldown.underlyingAmount;

-   if (block.timestamp >= userCooldown.cooldownEnd || cooldownDuration == 0) {
+   if (cooldownDuration == 0 || block.timestamp >= userCooldown.cooldownEnd) {
        userCooldown.cooldownEnd = 0;
        userCooldown.underlyingAmount = 0;

        silo.withdraw(receiver, assets);
    } else {
        revert InvalidCooldown();
    }
}
```
