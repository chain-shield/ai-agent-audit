# Vulnerability details


The `AuraVault` contract implements a vault that allows users to deposit and withdraw assets, mint and redeem shares, and compound rewards. The contract uses conversion functions [`_convertToShares`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L182-L184) and [`_convertToAssets`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L189-L191) to handle the conversion between assets and shares. However, the rounding direction used in these functions is incorrect, leading to a critical vulnerability.

### Detailed Description

The [`withdraw` function](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L233-L248) in the `AuraVault` contract allows users to withdraw assets from the vault by burning the corresponding amount of shares. The function uses [`previewWithdraw`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L240) to calculate the number of shares to burn based on the assets to withdraw. Internally, `previewWithdraw` calls `_convertToShares` with `Math.Rounding.Down`, which can result in rounding down to zero shares. This allows users to withdraw assets without burning the correct amount of shares.

Similarly, the `mint` function allows users to mint shares by providing the corresponding amount of assets. The function uses `previewMint` to calculate the number of assets required to mint the specified shares. Internally, `previewMint` calls `_convertToAssets` with `Math.Rounding.Down`, which can result in rounding down to zero assets. This allows users to mint shares without providing the correct amount of assets.

## Impact

Malicious users can exploit this vulnerability to drain the assets of the vault without burning the correct amount of shares or providing the correct amount of assets. This can lead to significant financial loss for the protocol and its users. The severity of this issue is high due to the potential impact and ease of exploitation.

## Proof of Concept

1. Assume the vault has the following state:
   - Total Assets: 1000 WETH
   - Total Supply: 10 shares

2. Alice wants to withdraw 99 WETH from the vault. She calls `AuraVault::withdraw(99 WETH)`.

3. The calculation in `_convertToShares` would be:
   - `assets = 99`
   - `shares = assets * totalSupply / totalAssets`
   - `shares = 99 * 10 / 1000`
   - `shares = 0` (rounded down)

4. The function returns 0 shares to be burned, allowing Alice to withdraw 99 WETH without burning any shares.

## Recommended Mitigation Steps

Update the rounding direction in the conversion functions to prevent the exploit. Use `Math.Rounding.Up` for `withdraw` and `mint` functions to ensure the correct number of shares or assets are calculated.

```solidity
function _convertToShares(uint256 assets, Math.Rounding rounding) internal view virtual override returns (uint256) {
    return assets.mulDiv(totalSupply() + 10 ** _decimalsOffset(), totalAssets() + 1, Math.Rounding.Up);
}

function _convertToAssets(uint256 shares, Math.Rounding rounding) internal view virtual override returns (uint256) {
    return shares.mulDiv(totalAssets() + 1, totalSupply() + 10 ** _decimalsOffset(), Math.Rounding.Up);
}
```
