# Vulnerability details

## Proof of Concept
The `modifyCollateralAndDebt` function in the `CDPVault` contract does not efficiently handle situations where a user attempts to repay more than their outstanding debt. While the function correctly caps the repayment amount to the total debt, it does not return any excess funds to the user. This behavior is evident in the following code snippet:
```solidity
 function modifyCollateralAndDebt(
    address owner,
    address collateralizer,
    address creditor,
    int256 deltaCollateral,
    int256 deltaDebt
) public {
    // ... (earlier code omitted for brevity)

    if (deltaDebt < 0) {
        uint256 maxRepayment = calcTotalDebt(debtData);
        uint256 amount = abs(deltaDebt);
        if (amount >= maxRepayment) {
            amount = maxRepayment;
            deltaDebt = -toInt256(maxRepayment);
        }

        poolUnderlying.safeTransferFrom(creditor, address(pool), amount);

        // ... (rest of the function)
    }

    // ... (later code omitted for brevity)
}
```
The function caps the `amount` to `maxRepayment` if the user attempts to repay more than they owe. However, it then proceeds to transfer this capped amount from the user without accounting for any potential excess. This approach, while preventing overpayment to the contract, may lead to user funds being unnecessarily locked if they've approved a larger amount for transfer.

## Impact
Users may unintentionally lock excess funds in the contract or leave unnecessary large approvals, potentially leading to confusion and a poor user experience. In a worst-case scenario, if a user has approved a significantly larger amount than their debt, they might inadvertently transfer more funds than intended in subsequent transactions.

## Tools Used
Manual
## Recommended Mitigation Steps
Modify the repayment logic to calculate and refund any excess amount back to the user.
