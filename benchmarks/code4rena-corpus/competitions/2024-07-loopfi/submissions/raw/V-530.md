# Vulnerability details

`liquidatePositionBadDebt()` function responsible for liquidating positions with bad debt, where the total debt exceeds the value of the collateral at a discounted price. the function does not correctly validate the `repayAmount` parameter, which represents the amount the liquidator wants to repay.

The issue arises here [#L511](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L510-L511)
```solidity
// validate params
if (owner == address(0) || repayAmount == 0) revert CDPVault__liquidatePosition_invalidParameters();
```
If the `repayAmount` is zero, the function will revert with the `CDPVault__liquidatePosition_invalidParameters` error. This prevents the liquidation process from proceeding, even if all other preconditions are met.

## Impact
* If the `repayAmount` is expected to be zero in certain scenarios, the current implementation will prevent valid liquidations from occurring. This could lead to positions with bad debt remaining unliquidated, affecting the overall health and stability of the system.

* If the `repayAmount` should always be greater than zero for a valid liquidation, the current behavior of reverting with an error is appropriate. However, it may still be beneficial to provide a more specific error message indicating that the `repayAmount` cannot be zero.

## Proof of Concept
Here's why:

* Alice has a position with a total debt of 100 tokens and a collateral value of 80 tokens at the current discounted price.
* Bob, a liquidator, attempts to liquidate Alice's position by calling `liquidatePositionBadDebt()` with `repayAmount` set to 0.
* The function reverts with the `CDPVault__liquidatePosition_invalidParameters` error, preventing the liquidation from proceeding.

The code that triggers the revert is:
```solidity
if (owner == address(0) || repayAmount == 0) revert CDPVault__liquidatePosition_invalidParameters();
```

## Recommended Mitigation Steps
If the `repayAmount` can be zero in certain scenarios, the function should be modified to handle that case appropriately. This may involve removing the revert condition for `repayAmount == 0` and adding additional logic to handle zero repayment amounts.

If the `repayAmount` should always be greater than zero for a valid liquidation, the error message can be updated to provide a more specific indication of the issue:
```solidity
- if (owner == address(0) || repayAmount == 0) revert CDPVault__liquidatePosition_invalidParameters();
+ if (owner == address(0)) revert CDPVault__liquidatePosition_invalidOwner();
+ if (repayAmount == 0) revert CDPVault__liquidatePosition_invalidRepayAmount();
```
By separating the validation checks and providing specific error messages, it becomes clearer why the function is reverting and what the expected behavior is.
