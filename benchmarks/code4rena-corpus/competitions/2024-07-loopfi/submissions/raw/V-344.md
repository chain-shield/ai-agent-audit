# Vulnerability details

## Impact
The exit function is designed to handle the withdrawal of tokens from a Balancer pool. However, it lacks a critical validation step to check the validity of the provided poolId. This oversight can lead to several issues, including the inability to exit the pool properly and potential loss of funds.

## Proof of Concept
***A user calls the exit function to withdraw tokens from a Balancer pool. They provide a poolId along with other parameters.***

***The function proceeds with the exitPool operation without validating whether the poolId is valid. It assumes that the provided poolId is correct and that the pool exists.***

***If the poolId is incorrect or does not correspond to a valid pool, the exitPool call to the Balancer Vault will fail.***

***The transaction will either revert or result in undefined behavior, leaving the user’s tokens in an unpredictable state.***

```solidity
function _balancerExit(PoolActionParams memory poolActionParams) internal returns (uint256 retAmount) {
        (
            bytes32 poolId,
            address bpt,
            uint256 bptAmount,
            uint256 outIndex,
            address[] memory assets,
            uint256[] memory minAmountsOut
        ) = abi.decode(poolActionParams.args, (bytes32, address, uint256, uint256, address[], uint256[]));

        if (bptAmount != 0) IERC20(bpt).forceApprove(address(balancerVault), bptAmount);

        balancerVault.exitPool(
            poolId,
            address(this),
            payable(poolActionParams.recipient),
            ExitPoolRequest({
                assets: assets,
                minAmountsOut: minAmountsOut,
                userData: abi.encode(ExitKind.EXACT_BPT_IN_FOR_ONE_TOKEN_OUT, bptAmount, outIndex),
                toInternalBalance: false
            })
        );
```


***Users might not receive the expected tokens or any confirmation that their request was processed correctly.***
