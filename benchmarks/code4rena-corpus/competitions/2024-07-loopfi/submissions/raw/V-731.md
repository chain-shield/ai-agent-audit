# Vulnerability details

## Vulnerability Details

According to ERC-4626, `totalAssets()` should return the total amount of underlying assets managed by the vault. This typically includes the actual balance of underlying tokens held by the vault plus any assets deployed elsewhere (e.g., lent out).

The current implementation returns `expectedLiquidity()`, which, based on its definition elsewhere in the contract, includes not only the actual assets but also accrued interest and quota revenue that hasn't been realized yet.

ERC-4626 expects `totalAssets()` to reflect the current, real value of assets, not projected or expected future values.

## Code Snippet

`totalAssets()` function current implementation

```solidity
function totalAssets() public view override(ERC4626, IERC4626) returns (uint256 assets) {
    return expectedLiquidity();
}
```

## Impact

Incorrect calculations: Other contracts or applications interacting with this vault might make incorrect calculations based on the totalAssets() value, leading to potential errors in deposit/withdrawal amounts or share price calculations.


## Fix

A more compliant implementation would typically look something like this:

```solidity
function totalAssets() public view override(ERC4626, IERC4626) returns (uint256 assets) {
    return IERC20(underlyingToken).balanceOf(address(this)) + totalBorrowed();
}
```

This would account for the actual underlying tokens in the vault plus any assets currently lent out (borrowed), which more accurately reflects the total assets under management by the vault.
