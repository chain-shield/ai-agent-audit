# Vulnerability details

## Impact
A critical flaw in the liquidation logic allows a liquidator to force the protocol into a situation where it accumulates bad debt. This issue arises due to a discrepancy between the checks in the `liquidatePosition` and `liquidatePositionBadDebt` functions, which use different price metrics to determine whether a position is in bad debt. Specifically:

1. **Liquidation Check (`liquidatePosition`)**: Uses the spot price to determine if a position can be liquidated as bad debt.
2. **Bad Debt Liquidation Check (`liquidatePositionBadDebt`)**: Uses a discounted price to determine if a position has bad debt.

This difference in price metrics creates a grey area where a position that appears acceptable using the spot price could be considered bad debt using the discounted price, which is typically 3-4% lower(liquidator profit)-READ DOCS- https://docs.loopfi.xyz/the-protocol/looping-leveraged-restaking/liquidations#:~:text=3%2D4%25%20going,dLP%20/%20lpETH%20staker.


 This discrepancy allows a liquidator to exploit the protocol, liquidating a position that looks safe but leaves the protocol with bad debt, as the liquidation process does not account for this price differential.

## Proof of Concept
Consider the following scenario:
using 4% - liquidator profit 

1. **Debt Floor**: 50
2. **Position Collateral**: 500
3. **Attempted Liquidation / repayAmount **: 1000
4. **Spot Price**: $2.15
5. **Liquidation Ratio**: 1.2
6. **Discounted Price** : $2.064  ( 2.15 * (100 - 4) / 100)
7. **Debt**: 1075

**Example Flow**:

- **Liquidate Position Check**: 

  - The protocol checks whether the total debt exceeds the collateral value using the spot price.
  - In this case: `calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)`
  - Since the spot price is $5, the collateral seems sufficient.

- **Liquidate Bad Debt Check**:

  - The protocol checks whether the total debt exceeds the collateral value using the discounted price.
  - In this case: `calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)`
  - With a discounted price of $4.825, the collateral may not cover the debt.

**Result**: 

Step 1
  
 1.  uint256 takeCollateral = wdiv(repayAmount, discountedPrice);
 2.  uint256 deltaDebt = wmul(repayAmount, liqConfig_.liquidationPenalty);
 3.  uint256 penalty = wmul(repayAmount, WAD - liqConfig_.liquidationPenalty);
 4.  if (takeCollateral > position.collateral) revert CDPVault__tooHighRepayAmount();



1. Take collateral = (1000) / 2.064 = 484.
2. deltaDebt = (1000 *10**18 * 0.985) = 985,000,000,000,000,000,000.
3. penalty= (1000 *10**18 * 0.015) = 15,000,000,000,000,000,000.

4. will pass since 484 is not greater than 500.




Step 2

5.  poolUnderlying.safeTransferFrom(msg.sender, address(pool), repayAmount - penalty);

debt position = 1075 - 985 = 90;
Collateral position = 500 -484 = 16;
Minted profit = 15.
New collateral value is = 16 * 2.15 = 34.

Bad debt = 90 - 34 = 56. 

Bad into treasury = 56 - 15 = 41.




The liquidator exploits this price difference by liquidating the position at the spot price, pushing the protocol into bad debt when the actual liquidation occurs at the discounted price. The liquidator gains a profit of 3-4%, while the protocol incurs a bad debt loss.

## Recommended Mitigation Steps

To prevent this exploit, the protocol should harmonize the liquidation checks across both `liquidatePosition` and `liquidatePositionBadDebt`. Specifically:

1. **Unified Price Metric**:
   - Update the `liquidatePosition` function to use the same price metric as the `liquidatePositionBadDebt` function. This means both checks should use the discounted price to determine whether a position is in bad debt.
   - Example adjustment:
     
```solidity
 // Enusure that there's no bad debt

--        if (calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)) -- 
--        revert CDPVault__BadDebt();

++       if (calcTotalDebt(debtData) > wmul(position.collateral,discountedPrice)) ++       revert CDPVault__BadDebt();

 ```
   - This change ensures that the protocol only allows liquidation when it is genuinely in the best interest of maintaining the protocol's financial health.
