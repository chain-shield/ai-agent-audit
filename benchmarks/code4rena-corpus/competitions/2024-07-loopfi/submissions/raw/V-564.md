# Vulnerability details

## Vulnerability details

When users call `PoolAction#_repay` to repay debt, it call `PositionAction#_repay` to repay the debt:

```solidity
function _repay(address vault, address position, CreditParams calldata creditParams, PermitParams calldata permitParams) internal {
uint256 amount;
    if (creditParams.auxSwap.assetIn != address(0)) {
        if (creditParams.auxSwap.recipient != address(this)) revert PositionAction__repay_InvalidAuxSwap();

        amount = _transferAndSwap(creditParams.creditor, creditParams.auxSwap, permitParams);
    }
    ...

    underlyingToken.forceApprove(address(vault), creditParams.amount);
    ICDPVault(vault).modifyCollateralAndDebt(
        position,
        address(this),
        address(this),
        0,
        -toInt256(creditParams.amount)
    );
}
```

It first call `_transferAndSwap` swap to the `vault` debt token then transfer to the pool proxy.
But the `amount` isn't always the same as `creditParams.amount`, which means if the `_transferAndSwap` return value less than `creditParams.amount`, the pool proxy have no enough debt token, the transaction would revert when pool proxy calling `CDPVault#modifyCollateralAndDebt` to repay debt from the pool proxy to the vault:

```solidity
function modifyCollateralAndDebt()
{
    ...
    poolUnderlying.safeTransferFrom(creditor, address(pool), amount);
    ...
}
```


## Impact

Users would repay debt failed if `_transferAndSwap` less than `creditParams.amount`.
