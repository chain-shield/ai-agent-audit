# Vulnerability details

## Impact
Two separate functions responsible for converting to shares will cause weird errors

## Proof of Concept
Upon different operations in a pool, we convert assets to shares and then mint those shares to different addresses. The issue is that there is 2 separate implementations used for the conversion to shares which will cause accounting issues. Let's take a look at the first implementation used:
```solidity
 function deposit(
        uint256 assets,
        address receiver
    )
        public
        override(ERC4626, IERC4626)
        whenNotPaused // U:[LP-2A]
        nonReentrant // U:[LP-2B]
        nonZeroAddress(receiver) // U:[LP-5]
        returns (uint256 shares)
    {
        uint256 assetsReceived = _amountMinusFee(assets); // U:[LP-6]
        shares = _convertToShares(assetsReceived); // U:[LP-6]
        _deposit(receiver, assets, assetsReceived, shares); // U:[LP-6]
    }
```
```solidity
function _convertToShares(uint256 assets) internal pure returns (uint256 shares) {
        return assets;
    }
```
Which essentially just returns the assets (removed the comments there). Now, let's take a look at the implementation used in `repayCreditAccount()`:
```solidity
_mint(treasury, convertToShares(profit));
```
As seen, this is a different function. This is the function that is directly on the inherited ERC4626 contract.
```solidity
    function convertToShares(uint256 assets) public view virtual override returns (uint256) {
        return _convertToShares(assets, Math.Rounding.Down);
    }
```
Which calls this one:
```solidity
    function _convertToShares(uint256 assets, Math.Rounding rounding) internal view virtual returns (uint256) {
        return assets.mulDiv(totalSupply() + 10 ** _decimalsOffset(), totalAssets() + 1, rounding);
    }
```
As seen, 2 different implementations are used. `totalAssets()` can even be manipulated by directly sending assets to the contract, that way these 2 implementations return completely different values and cause all kinds of accounting issues.
