# Vulnerability details

## Impact
Incorrect price will be used due to underflow from casting `int256` to `uint256` if the  `int` type is negative value because `uint256()` does NOT have underflow/overflow protection.

## Proof of Concept
The issue is that the `answer` from the Chainlink price feed is casted with `uint256()` which has no overflow/underflow protection. Considering the fact that the `answer` variable is an `int` type, `answer` can be negative. When `answer` is negative, there will be an overflow.

Note that [4nalyzer report](https://github.com/code-423n4/2024-07-loopfi/blob/main/4naly3er-report.md#l-23-consider-using-openzeppelins-safecast-library-to-prevent-unexpected-overflows-when-downcasting) does not include this line of the issue I found below and only talks about casting down and not casting from `int` type to `uint` type.

## Recommended Mitigation Steps

Consider using the OZ's safecast library instead of using the uint256() function that has no overflow protection or validating that `answer` is not zero before casting.

