# Vulnerability details

## Impact
The liquidation process reverts even when the liquidator attempts to repay the full debt. A small residual debt remains as newDebt which later is set as position.debt inside `function _modifyPosition`, which if smaller than `vaultConfig.debtFloor` then reverts the whole `function liquidatePosition` 

## Proof of Concept

Before moving in depth I would like to tell why this issue was not caught in unit tests for `function liquidatePosition`, this is because while creating test cases they kept the value of `debtFloor` = 0, while creating a CDPVault vault for test purpose of all test_liquidate, etc.

Here look at the 3rd parameter it is set to 0, which indicates `debtFloor`
```solidity
@>   CDPVault vault = createCDPVault(token, 150 ether, 0, 1.25 ether, 1 ether, 1 ether);
```
So although here in test cases it is set to 0, but in real deployment it will be a non-zero amount which then can create a problem(explain below).

Explanation with code snippets =>

In the `function liquidatePosition`, when a liquidator tries to repay the entire total debt in order to make position.debt = 0 (ie. here newDebt also = 0), the condition fails due to this incorrect check - `if (deltaDebt == maxRepayment)`, this is not going to be true in any situation, even when Liquidator's repay amount is total Debt amount. This is because deltaDebt = `uint256 deltaDebt = wmul(repayAmount, liqConfig_.liquidationPenalty);`
