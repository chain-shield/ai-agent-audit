# Vulnerability details

## Impact
The first user of the vault can easily perform a vault inflation attack, inflating the shares of the vault

## Proof of Concept
The vault inflation attack is well explained right here:
https://mixbytes.io/blog/overview-of-the-inflation-attack

in the case of AuraVault it can still be performed because there are no minted shares before the first deposit in the vault. The idea here is for the malicious user to mint the smallest possible amount of shares (1 wei) and then wait for someone to deposit in the mempool, then transfer the corresponding amount of assets to the vault, which makes the vault to mint 0 shares to the user. Then the malicious user can withdraw all assets from the vault. in this case it won't be that easy because of this line in the `_convertToShares` function `totalSupply() + 10 ** _decimalsOffset()`, which makes the malicious user deposit twice the amount he saw other user deposit in the mempool (1 share + 1 = 2)
## Tools Used
manual review
## Recommended Mitigation Steps
mint some shares to address(0) in the constructor or make a minimum amount of shares that user can receive to ensure that it is not a number as low as 1
