# Vulnerability details

## Impact

The `ChainlinkOracle` is designed to be a `UUPSUpgradeable` contract. However, it lacks core best practices regarding `UUPSUpgradeable` contracts.

* It lacks a `constructor` with the `_disableInitializers()` in the constructor.
* It fails to implement `UUPS` as it lacks `__UUPSUpgradeable_init()` in its `ChainlinkOracle::initialize` function


## Proof of Concept

```
//src/oracle/ChainlinkOracle

    function initialize(address admin, address manager) external initializer {
        // init. Access Control
        __AccessControl_init();
        // Role Admin
        _grantRole(DEFAULT_ADMIN_ROLE, admin);
        // Credit Manager
        _grantRole(MANAGER_ROLE, manager);
    }
```
## Tools Used

Manual Review

## Recommended Mitigation Steps

* Include `_disableInitializers()` in its `constructor`.
* Implement `UUPS` in its `initialize` function

```diff
 function initialize(address admin, address manager) external initializer {
        // init. Access Control
        __AccessControl_init();
        // Role Admin
        _grantRole(DEFAULT_ADMIN_ROLE, admin);
        // Credit Manager
        _grantRole(MANAGER_ROLE, manager); 
+       // Initialiaze UUPS
+       __UUPSUpgradeable_init();

    }

```

Here's a detailed overview by [Pearl Denedo](https://medium.com/@pearliboy1/how-to-implement-an-upgradeable-smart-contract-with-uups-242c57f671ee): "`__UUPSUpgradeable_init()`: This line initializes the contract to be upgradable using the OpenZeppelin's Universal Upgradeable Proxy Standard (UUPS). It is a necessary step to enable upgradeability in the contract."

OpenZeppelin Security Advisory: How to Initialize UUPS Implementation contracts (https://forum.openzeppelin.com/t/security-advisory-initialize-uups-implementation-contracts/15301)

Also, for more details on how to implement UUPS Upgradeable contracts, watch Guardian Audit Owen's YouTube video here: https://youtu.be/6aPyykZhglM?si=CfSLd3ENICZD8pLg
