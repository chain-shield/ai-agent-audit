# Vulnerability details


## Proof of Concept

Per the docs and code snippets, the protocol team plan to roll out with a concept of `minLoanSize = 0` . This however can be a big issue because there will be no incentive for liquidators to liquidate small underwater positions given the gas cost to do so would not make economic sense based on the incentive they would receive.

This also opens up a cheap attack path for would be attackers whereby they can [borrow](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L256) many small loans which will go underwater as they accrue interest but will not be liquidated.

Forcing the protocol to have bad debt, and potentially lead to a bank run.

## Impact

Can cause an underwater state in protocol, and potentially a bank run when users find out not enough assets can cover loans already given out.

## Recommended Mitigation Steps

Implement a minimum loan/borrow size in the vault
