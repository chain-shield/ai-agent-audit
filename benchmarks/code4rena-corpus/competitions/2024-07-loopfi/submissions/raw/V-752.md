# Vulnerability details

## Impact
In the Auravault the [`_chainlinkSpot`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L365) and [`_getAuraSpot`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L381) functions get price from chainlink however they do not check the full validity of the price. In `_chainlinkSpot` it only checks whether the price is greater than 0 which is not fully right because the oracle can return an incorrect stale price which will not be zero and in `_getAuraSpot` there's no validation of the price returned whether it is 0 or stale.

## Proof of Concept
`_chainlinkSpot()`
```
        try AggregatorV3Interface(BAL_CHAINLINK_FEED).latestRoundData() returns (
            uint80 /*roundId*/,
            int256 answer,
            uint256 /*startedAt*/,
->            uint256 /*updatedAt*/,
            uint80 /*answeredInRound*/
        ) {
            price = wdiv(uint256(answer), BAL_CHAINLINK_DECIMALS);
            isValid = (price > 0);
        } catch {}
        //@audit stale price

        if (!isValid) revert AuraVault__chainlinkSpot_invalidPrice();
    }
```
we can both see the updatedAt param has been ignored however there is a check to validate whether the price is > 0 which is okay but won't validate the price entirely like i explained earlier

In `_getAuraSpot()` we will find the following lines that receives data from pricefeed
```
 uint256 ethPrice;
        //audit stale price check
        (, int256 answer, , , ) = AggregatorV3Interface(ETH_CHAINLINK_FEED).latestRoundData();
        ethPrice = wdiv(uint256(answer), ETH_CHAINLINK_DECIMALS);
```
we can see that there's no validation of any form after the price has been received which can make this price stale or even zero

## Recommended Mitigation Steps
Chainlink feeds return `updatedAt` make sure to check your  block.timestamp against it to know how old or valid the data being returned is
