# Vulnerability details

## Impact
The incorrect computation will result in the function returning an overinflated amount.

## Proof of Concept
In the [`_amountWithWithdrawalFee()`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L880) it returns the result of this line `return (amount * PERCENTAGE_FACTOR) / (PERCENTAGE_FACTOR - withdrawFee);` as the amount with withdrawal fee value, however this computation tends to overinflate the amount.

For Example:
PERCENTAGE_FACTOR = 1e4
amount = 1e6
withdrawFee = 2000

so using the computation above, it will be
(1e6 * 1e4) / (1e4 - 2000);
(1e10) / (8000) = 1_250_000

so withdrawFeeAmount = 1_250_000 - 1_000_000 = 250_000

meanwhile,
withdrawFeeAmount = withdrawFee/PERCENTAGE_FACTOR * amount
(2000/10000)*1e6 = 200_000

difference = 250_000 - 200_000 = 50_000

Difference shows there has been an inflation  

you can try this with percentages too, you will see the inflated fees.

## Tools Used
Manual Review
## Recommended Mitigation Steps
Revisit the computation to make sure it returns the correct amount and not an inflated one.
