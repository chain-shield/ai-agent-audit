# Vulnerability details

## Impact

The `BalancerOracle` and `PendleLPOracle` are designed to be UUPSUpgradeable contracts. The following were noted

* Improper use of the `initializer` modifier in the `constructor`
* the lack of the `_disableInitializers()` in the constructor.
* failure to call the `UUPSUpgradeable::__UUPSUpgradeable_init()` in its `BalancerOracle::initialize` function.

According to the `OpenZeppelin::Initializable`'s recommendation, "An uninitialized contract can be taken over by an attacker. This applies to both a proxy and its implementation contract, which may impact the proxy. To prevent the implementation contract from being used, you should invoke the {_disableInitializers} function in the constructor to automatically lock it when it is deployed:

 ```

 constructor() {
     _disableInitializers();
 }
 ```

First, the `BalancerOracle::constructor` lacks the `_disableInitializers()`.

Second, The use of the `initializer` modifier in the constructor is unconventional, and potentially problematic, because `initializer` is typically used for functions that can be called by the proxy contract after deployment, `BalancerOracle::initialize`, not for constructors.  The `constructor` in upgradeable contracts is usually void of logic, containing only the `_disableInitializers()`, as it's only executed when the implementation contract is deployed, not when the proxy is deployed or upgraded.

Third, there stands a risk of double initialization. Having `initializer` on both the `BalancerOracle::constructor` and the `BalancerOracle::initialize` function could potentially allow for double initialization, depending on how the contract is deployed and upgraded.

Fourth, the current structure mixes the initialization of core contract parameters (in the constructor) with access control setup (in the initialize function). In upgradeable contracts, it's generally better to have all initialization in the initialize function.

## Recommended Mitigation Steps

A more typical approach for UUPS upgradeable contracts would be:

* Have an empty constructor calling the `_disableInitializers()` function.
* Move all initialization logic to the `BalancerOracle::initialize` function.
* Use the `initializer` modifier only on the `BalancerOracle::initialize` function.
