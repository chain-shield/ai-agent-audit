# Vulnerability details

## Vulnerability details
In `StakingLPEth` contract, function `_checkMinShares()` is used to check if token have enough

    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
with `MIN_SHARES` = `0.01 ether`, this function is used in `_withdraw()` function as below:

    function _withdraw(
        address caller,
        address receiver,
        address _owner,
        uint256 assets,
        uint256 shares
    ) internal override nonReentrant {
        super._withdraw(caller, receiver, _owner, assets, shares);
        _checkMinShares();   // <--
    }

It can be seen that it is checked after calling withdraw function. If the last user try to withdraw, only dust amount left in the contract (due to rounding down share received when deposit and rounding down amount received when withdraw in ERC4626). Which make last user unable to withdraw all token that avaiable in the contract. Which lead to last user will lost 0,01 LPEth to be able to withdraw the rest of token.

## Impact
Last user will lose some tokens due to checking condition.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Using another approach to prevent inflation attack, for example, creating dead shares like uniswap v2.
