# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The setDefaultRelockTypeIndex function in the MultiFeeDistribution contract can be called by any address. This function allows users to set their default lock index, which determines the locking period for rewards. Without proper access control, any malicious actor can manipulate this index, potentially leading to unexpected locking periods or denial of service for legitimate users.

Vulnerability Details

Location: MultiFeeDistribution.sol

Code Snippet:
```sol
    function setDefaultRelockTypeIndex(uint256 index) external {
        if (index >= _lockPeriod.length) revert InvalidType();
        defaultLockIndex[msg.sender] = index;
    }
```
The function allows any external address to set the defaultLockIndex for the caller without any restrictions or authorization checks. This lack of access control could be exploited by an attacker to set arbitrary lock indices.

## Recommended Mitigation Steps
To prevent unauthorized access to the setDefaultRelockTypeIndex function, implement the following mitigations:

Access Control:
Introduce an access control mechanism to restrict function calls to only authorised users or contracts.

Consider using OpenZeppelin’s Ownable or AccessControl libraries to enforce permissions.

Modifier Implementation:
Add a modifier to check if the caller is authorised to make changes to their defaultLockIndex.

    function setDefaultRelockTypeIndex(uint256 index) external onlyAuthorised {

    }
