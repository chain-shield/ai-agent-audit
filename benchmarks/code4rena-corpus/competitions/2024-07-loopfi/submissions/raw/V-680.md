# Vulnerability details

## Impact
The `liquidatePositionBadDebt` function in the `CDPVault` contract incorrectly updates the quota revenue based on the total debt instead of the actual repaid amount. Thiss leads to inaccurate accounting of quota revenue

## Proof of Concept
In the [`liquidatePositionBadDebt`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L579-L632) function, the `loss` is calculated as the difference between the total debt and the repay amount:

```solidity
uint256 loss = calcTotalDebt(debtData) - repayAmount;
```

The function then calls `pool.repayCreditAccount` with the total debt and zero profit:

```solidity
pool.repayCreditAccount(debtData.debt, 0, loss); // U:[CM-11]
```

But when updating the quota revenue, it incorrectly considers the total debt instead of the actual repaid amount:

```solidity
int256 quotaRevenueChange = _calcQuotaRevenueChange(-int(debtData.debt));
if (quotaRevenueChange != 0) {
    IPoolV3(pool).updateQuotaRevenue(quotaRevenueChange); // U:[PQK-15]
}
```

This means that the quota revenue is updated based on the total debt, even though a portion of that debt was not actually repaid due to the bad debt (`loss`). This can lead to an overestimation of the quota revenue.

The `quotaRevenueChange` should be calculated based on the actual repaid amount (`repayAmount`) instead of the total debt. 

