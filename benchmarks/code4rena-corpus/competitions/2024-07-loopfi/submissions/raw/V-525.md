# Vulnerability details

## Impact

The `PositionAction::onCreditFlashLoan` function does not utilize the `fee` parameter, which can lead to inconsistencies when interacting with the `Flashlender::creditFlashLoan` function. The `Flashlender::creditFlashLoan` function expects the repayment of the loan amount plus a fee, but since `PositionAction::onCreditFlashLoan` does not account for the fee, this can result in underpayment.

Contrary to the function `PositionAction::onFlashLoan`, where the amount borrowed plus fees are returned to the `FlashLender`, this causes inconsistencies. When a `FlashLender.sol` that charges non-zero value fees is deployed, it will cause the function `PositionAction::decreaseLever` to malfunction, as the execution will be reverted. This happens because `FlashLender::creditFlashLoan` expects to receive the borrowed amount plus fees.

## Recommended Mitigation Steps

If a fee repayment is not expected in `Flashlender::creditFlashLoan`, then it should not be included so as not to interfere with `Flashlender::flashLoan`, where a fee repayment is expected.

```diff
    function creditFlashLoan(
        ICreditFlashBorrower receiver,
        uint256 amount,
        bytes calldata data
    ) external override nonReentrant returns (bool) {
-       uint256 fee = wmul(amount, protocolFee);
-       uint256 total = amount + fee;
+       uint256 total = amount;

        pool.lendCreditAccount(amount, address(receiver));

        emit CreditFlashLoan(address(receiver), amount, fee);

        if (receiver.onCreditFlashLoan(msg.sender, amount, fee, data) != CALLBACK_SUCCESS_CREDIT)
            revert Flash__creditFlashLoan_callbackFailed();

        // reverts if not enough Stablecoin have been send back
        underlyingToken.transferFrom(address(receiver), address(pool), total);
        pool.repayCreditAccount(total - fee, fee, 0);

        return true;
    }
```
