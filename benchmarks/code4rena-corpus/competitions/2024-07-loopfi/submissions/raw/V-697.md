# Vulnerability details

## Impact
PoolV3 takes a fee on every withdrawal. Because it uses two different formulas to calculate the fee in `withdraw()` and `redeem()` it's slightly cheaper to use `redeem()`.

## Proof of Concept
`withdraw()` calculates the amount of shares to burn using `_amountWithWithdrawalFee()`:

```sol
    function _amountWithWithdrawalFee(uint256 amount) internal view returns (uint256) {
        return (amount * PERCENTAGE_FACTOR) / (PERCENTAGE_FACTOR - withdrawFee);
    }
```

While `redeem()` calculates the amount of assets the user receives using `_amountMinusWithdrawalFee()`:

```sol
   function _amountMinusWithdrawalFee(uint256 amount) internal view returns (uint256) {
        return (amount * (PERCENTAGE_FACTOR - withdrawFee)) / PERCENTAGE_FACTOR;
    }
```

Given that `PERCENTAGE_FACTOR = 10,000`, `withdrawFee = 100`, and assets and shares being redeemable 1:1:

user calls `withdraw()` with 1e18:

$shares = 1e18 * 10,000 / 9,900 = 1.010101e18$

Same thing but the user redeems 1e18 shares:

$assets = 1e18 * 9,900 / 10,000 = 9.9e17$

In `redeem()` you pay $1e18 - 9.9e17 = 1e16 assets$ in fees. In `withdraw()` you pay $1.010101e18 - 1e18 = 1.010101e16 assets$ in fees.

## Tools Used
none

## Recommended Mitigation Steps
Changr `_amountWithWithdrawalFee()` to:

```sol
    function _amountWithWithdrawalFee(uint256 amount) internal view returns (uint256) {
        return amount + amount * withdrawFee / PERCENTAGE_FACTOR;
    }
```
