# Vulnerability details

## Impact
`CDPVault::_modifyPosition` checks if the position's debt is less than the debt floor, so the TX reverts even if the TX is just moving collateral. So if the debt floor was 10 ETH, a user takes a loan of 10 ETH, and for whatever reason the flow is raised to 11 ETH, the user won't be able to withdraw his collateral, knowing his position is collateralized.

This wrongly blocks users from withdrawing their collateral from their over-collateralized positions.

## Proof of Concept

Add the following in `src/test/unit/CDPVault.t.sol`:

```solidity
address bob = makeAddr("BOB");

function test_cantWithdrawCollateral() public {
    CDPVault vault = createCDPVault(token, 150 ether, 10 ether, 1.25 ether, 1.0 ether, 0);
    createGaugeAndSetGauge(address(vault));

    uint256 amount = 100 ether;
    uint256 borrowAmount = 10 ether;

    token.mint(bob, amount);

    // Initially the debt floor is 10 ether
    (uint128 debtFloor, ) = vault.vaultConfig();
    assertEq(debtFloor, 10 ether);

    vm.startPrank(bob);
    token.approve(address(vault), type(uint256).max);
    // Deposit 100 ETH collateral
    vault.deposit(bob, amount);
    // Borrow 10 ETH
    vault.borrow(bob, bob, borrowAmount);
    vm.stopPrank();

    // Set the debt floor to 11 ETH
    vault.setParameter("debtFloor", 11 ether);

    (debtFloor, ) = vault.vaultConfig();
    assertEq(debtFloor, 11 ether);

    // Bob can't withdraw collateral because his debt is less than the new debt floor
    vm.prank(bob);
    vm.expectRevert(abi.encodeWithSelector(CDPVault.CDPVault__modifyPosition_debtFloor.selector));
    vault.withdraw(bob, 1 ether);
}
```

## Recommended Mitigation Steps

In `_modifyPosition`, only check the debt floor if the position's debt has changed.

```solidity
if (position.debt != newDebt && position.debt != 0 && position.debt < uint256(vaultConfig.debtFloor))
    revert CDPVault__modifyPosition_debtFloor();
```
