# Vulnerability details

## Proof of Concept
The provided `Flashlender` contract calculates the flash fee using a method that differs from the documented specification. Below is the relevant code from the `Flashlender`` contract:
```solidity
   function flashFee(address token, uint256 amount) external view override returns (uint256) {
        if (token != address(underlyingToken)) revert Flash__flashFee_unsupportedToken();
        return wmul(amount, protocolFee);
    }
```
In this contract, the `flashFee` is calculated using the wmul function, which performs a multiplication with proper handling of decimals.

According to the [documentation](https://eips.ethereum.org/EIPS/eip-3156#:~:text=the%20returned%20principal.%0A%20%20%20%20%20*/-,function%20_flashFee(%0A%20%20%20%20%20%20%20%20address%20token%2C%0A%20%20%20%20%20%20%20%20uint256%20amount%0A%20%20%20%20)%20internal%20view%20returns%20(uint256)%20%7B%0A%20%20%20%20%20%20%20%20return%20amount%20*%20fee%20/%2010000%3B%0A%20%20%20%20%7D,-/**%0A%20%20%20%20%20*%20%40dev%20The%20amount), the `flashFee` should be calculated as follows:
```solidity
uint256 fee = _flashFee(token, amount);

function _flashFee(
    address token,
    uint256 amount
) internal view returns (uint256) {
    return amount * fee / 10000;
}

```
Here, the fee is a simple percentage of the amount lent, where fee represents the percentage (e.g., 1 for 0.01%).


## Impact
The inconsistent calculation method may lead to discrepancies in the fee charged for flash loans. Users and integrators expecting the documented fee calculation method might find the actual fees charged by the contract to be unexpectedly higher or lower, potentially leading to a loss of trust and financial inaccuracies.

## Recommended Mitigation Steps
Align the `flashFee` calculation in the `Flashlender` contract with the documented specification.
