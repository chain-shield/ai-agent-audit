# Vulnerability details

## Impact
In StakingLPEth, malicious user can leave 1 wei in the contract. This will cause the last staker cannot withdraw all shares because of `_checkMinShares()` check. The last staker may need to take almost 0.01 ether loss.

## Proof of Concept
In StakingLPEth, when stakers deposit/withdraw, there is one security check to make sure the contract's share amount cannot be less than `MIN_SHARES` if there is some shares in the contract.
Based on this design, all depositors can withdraw their funds from the contract in normal scenario.
For example:
1. Alice mint 0.01 ether share.
2. Bob mint 0.01 ether share.
3. Alice withdraw 0.01 ether share.
4. Bob withdraw 0.01 ether share.

The problem is that if one malicious user leave 1 share when he withdraw, this will cause the last staker cannot withdraw all funds because of this security check.
For example:
1. Alice mint 0.01 ether share.
2. Bob mint 0.01 ether share.
3. Bob withdraw (0.01 ether - 1) share.
4. Alice cannot withdraw her 0.01 ether share because of `_checkMinShares()` check.
```javascript
    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```

## Recommended Mitigation Steps
The MIN_SHARES aims to prevent the donation attack/inflation attack. Compare with this method, suggest to mint some shares to one dead address by the sponsor when we deploy this contract.
