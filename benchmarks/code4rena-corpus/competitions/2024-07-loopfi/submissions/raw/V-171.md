# Vulnerability details

## Details

`lpETH` is intended to be provided to `Lenders` who provide `ETH` liquidity. `Stakers` of `lpETH` are set to earn interest charged to `Loopers` who deposit `Pendle LRT collateral` to borrow `ETH`. This is presumably the function of the `StakingLPEth` contract. The `Staking Vault`.

The `StakingLPEth`, which inherits from `ERC4626`, contains various methods including `unstake` which withdraws users' staked `lpETH` and resets their `UserCooldown` info via the `cooldowns` mapping.

```
//src/StakingLPEth

struct UserCooldown {
        uint104 cooldownEnd;
        uint256 underlyingAmount;
    }

    mapping(address => UserCooldown) public cooldowns;

```

Despite its test suite, `StakingLPEthTest`, suggesting that users can stake by calling the `deposit` of the inherited `ERC4626`, this doesn't update the stakers' `UserCooldown` info, which means that their staked amounts and `cooldownEnd` duration will not be updated in the `cooldowns` mapping.

Even if it's possible for users to stake, as suggested by `StakingLPEthTest`, their respective stake details will not be updated.

# Impact

Intended stakers of `lpEth` can't stake their `lpEth`.
