# Vulnerability details

## Proof of Concept
The `_delegateCall` function in the provided `BaseAction` contract does not validate whether the `to` address is a contract before performing a delegatecall. This omission can lead to unintended behavior or failure if the `to` address is not a contract. Here's the relevant code snippet:

```solidity
function _delegateCall(address to, bytes memory data) internal returns (bytes memory) {
    (bool success, bytes memory returnData) = to.delegatecall(data);
    if (!success) _revertBytes(returnData);
    return returnData;
}

```
In the above code, the `delegatecall` is made to the address `to` with the provided data. If the address `to` is not a contract, the `delegatecall` will fail, and an error will be raised by the `_revertBytes` function. However, this failure does not provide any indication that the target address is not a contract, which could be misleading.


## Impact
If the `to` address is not a contract, the `delegatecall` will fail, causing the entire transaction to revert. This can disrupt the intended functionality of the contract and may lead to loss of execution continuity or unintended contract state changes. The lack of a contract check makes it harder to diagnose the issue and handle such failures gracefully.


## Tools Used
Manual
## Recommended Mitigation Steps
Add a check to ensure that the `to` address is a contract before proceeding with the `delegatecall`.
