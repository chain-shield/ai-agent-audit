# Vulnerability details

`liquidatePositionBadDebt()` responsible for liquidating positions that have fallen below the required collateralization ratio and have accumulated bad debt there is a vulnerability in the calculation of the loss variable within `liquidatePositionBadDebt()` that can lead to an overflow, can cause the system to become insolvent, as the new total debt may exceed the value of the collateral multiplied by the spot price.

[CDPVault.sol#L600-L607](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L600-L607)
```solidity
        // compute collateral to take, debt to repay
        uint256 takeCollateral = wdiv(repayAmount, discountedPrice);
        if (takeCollateral < position.collateral) revert CDPVault__repayAmountNotEnough();


        // account for bad debt
        takeCollateral = position.collateral;
        repayAmount = wmul(takeCollateral, discountedPrice);
        uint256 loss = calcTotalDebt(debtData) - repayAmount;
```
## Impact
If the `calcTotalDebt(debtData)` is significantly larger than `repayAmount`, the subtraction operation `calcTotalDebt(debtData) - repayAmount` can result in overflow.

The inflated loss value will then propagate through the subsequent calculations and updates, leading to an incorrect accounting of the total debt and a violation of the system's solvency invariant. As a result, the system may become insolvent, with the total debt exceeding the value of the collateral.

worst-case scenario, an attacker could exploit this vulnerability to manipulate the debt accounting and potentially drain funds from the system or cause other unintended consequences.

## Proof of Concept
Consider the following scenario:

1. A user has a position with a small amount of collateral (e.g., `oldCollateral = 1`) and a very large debt (e.g., `debtData.debt = 2^256 - 1`).
2. The spot price of the collateral is relatively low (e.g., `spotPrice = 1`).
3. An attacker calls the `liquidatePositionBadDebt()` function with a `repayAmount` that is much smaller than `debtData.debt`.
4. Inside the function, `takeCollateral` is set to `position.collateral`, and `repayAmount` is calculated as `wmul(takeCollateral`, `discountedPrice`).
5. The loss variable is calculated as `calcTotalDebt(debtData) - repayAmount`, which results in an integer overflow due to the large value of `debtData.debt`.
   * A position has a small amount of collateral (e.g., 1 wei) and a large amount of debt.
   * The `calcTotalDebt(debtData)` function returns a value close to the maximum uint256 value.
   * When `liquidatePositionBadDebt()` is called
     ```solidity
     takeCollateral = 1;
     repayAmount = wmul(1, discountedPrice); // Very small value
     loss = MAX_UINT256 - repayAmount; // Overflows to a very large number
     ```
   * This large `loss` value propagates through the system, potentially causing further calculation errors and system instability.

6. The inflated loss value is used in subsequent calculations, leading to an incorrect update of the total debt and a violation of the system's solvency invariant.

As a result, the system becomes insolvent, with `newTotalDebt` exceeding `oldCollateral * spotPrice`, bypassing the intended check for system insolvency.

## Recommended Mitigation Steps
Modify the `liquidatePositionBadDebt()` function to handle the case when `calcTotalDebt(debtData)` is greater than `repayAmount`. Instead of subtracting, compare the two values and set loss accordingly
```diff
uint256 loss;
if (calcTotalDebt(debtData) > repayAmount) {
    loss = calcTotalDebt(debtData) - repayAmount;
} else {
    loss = 0;
}
//...
- uint256 loss = calcTotalDebt(debtData) - repayAmount;
+ uint256 totalDebt = calcTotalDebt(debtData);
+ require(totalDebt >= repayAmount, "Invalid debt calculation");
+ uint256 loss = totalDebt - repayAmount;
+ loss = Math.min(loss, MAX_ALLOWED_LOSS); // Define MAX_ALLOWED_LOSS appropriately
```
