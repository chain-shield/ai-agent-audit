# Vulnerability details

## Impact:
The vulnerability identified in the `recoverERC20` function allows the contract owner to unilaterally withdraw any ERC20 tokens held by the contract, including those intended as user rewards. This can lead to total loss of user rewards if the owner acts maliciously or if the owner's account is compromised. 

## Proof of Concept:
The function `recoverERC20` can be invoked exclusively by the contract owner due to the `onlyOwner` modifier. It allows the owner to specify any token address and amount, which means there is no restriction or verification in place to ensure that the tokens being recovered are not part of the balance meant for users or rewards. This unrestricted control provides a direct avenue for potential misuse, especially if the contract owner's intentions are not aligned with the users' interests.

```solidity
    function recoverERC20(address tokenAddress, uint256 tokenAmount) external onlyOwner {
        _recoverERC20(tokenAddress, tokenAmount);
    }

    function _recoverERC20(address tokenAddress, uint256 tokenAmount) internal {
        IERC20(tokenAddress).safeTransfer(msg.sender, tokenAmount);
        emit Recovered(tokenAddress, tokenAmount);
    }
```

## Recommended Mitigation Steps

Add the following check inside the `recoverERC20` function to provide stronger guarantees.
```solidity
require(
        !validRTokens[tokenAddress],
        "Cannot recover reward tokens"
    );```
