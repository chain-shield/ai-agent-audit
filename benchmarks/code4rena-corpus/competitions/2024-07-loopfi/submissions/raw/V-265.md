# Vulnerability details

## Description

The `EligibilityDataProvider` contract includes a function [`lastEligibleTime()`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/EligibilityDataProvider.sol#L220-L241) that determines the last eligible timestamp for a user based on their locked balances. This function assumes that the `lockInfo` array, which contains the user's locked balances, is ordered by `unlockTime`. However, if this assumption is incorrect, the function may return an inaccurate `lastEligibleTimestamp`.

The `lastEligibleTime()` function iterates over the `lockInfo` array in reverse order, assuming it is ordered by `unlockTime`. If the array is not ordered, the function might return an incorrect `lastEligibleTimestamp`. This could lead to users being incorrectly disqualified or qualified for rewards, affecting their eligibility status.

If the `lockInfo` array is not ordered by `unlockTime`, the function will not correctly calculate the `lastEligibleTimestamp`, leading to potential inaccuracies in determining user eligibility for rewards.

## Impact
The impact of this issue is that users may be incorrectly disqualified or qualified for rewards based on an inaccurate `lastEligibleTimestamp`. This could lead to an uneven distribution of rewards among users, with some users receiving rewards they are not eligible for, while others are unfairly disqualified. 

## Proof of Concept
1. A user locks multiple balances with different `unlockTime` values.
2. The `lockInfo` array is not ordered by `unlockTime`.
3. The `lastEligibleTime()` function is called to determine the user's last eligible timestamp.
4. The function iterates over the unordered `lockInfo` array and returns an incorrect `lastEligibleTimestamp`.
5. The user is incorrectly disqualified or qualified for rewards based on this inaccurate timestamp.
