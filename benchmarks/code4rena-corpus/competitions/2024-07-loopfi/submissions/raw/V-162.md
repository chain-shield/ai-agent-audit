# Vulnerability details

`liquidatePosition()` responsible for liquidating unsafe positions by selling collateral at a discounted price to repay the debt. The function calculates the amount of collateral to seize (`takeCollateral`), the debt to repay (`deltaDebt`), and the penalty to pay (`penalty`) based on the `repayAmount` and the position's current state.

However, there is an issue in the logic that updates the position's debt after the liquidation. The problem occurs in the else block of the following code: [CDPVault.sol#L541-L558](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L541-L558)
```solidity
        uint256 newDebt;
        uint256 profit;
        uint256 maxRepayment = calcTotalDebt(debtData);
        uint256 newCumulativeIndex;
        if (deltaDebt == maxRepayment) {
            newDebt = 0;
            newCumulativeIndex = debtData.cumulativeIndexNow;
            profit = debtData.accruedInterest;
            position.cumulativeQuotaInterest = 0;
        } else {
            (newDebt, newCumulativeIndex, profit, position.cumulativeQuotaInterest) = calcDecrease(
                deltaDebt, // delta debt
                debtData.debt,
                debtData.cumulativeIndexNow, // current cumulative base interest index in Ray
                debtData.cumulativeIndexLastUpdate,
                debtData.cumulativeQuotaInterest
            );
        }
```
`calcDecrease()` is called to calculate the new debt (`newDebt`) and other related values. However, the implementation of `calcDecrease()` does not guarantee that the new debt is always less than or equal to the difference between the old debt and the repay amount (`oldDebt - repayAmount`).

This can lead to a scenario where the debt is not reduced correctly after liquidation, leaving the position with a higher debt than expected and violating the intended behavior of the liquidation process.

## Impact
If the debt is not reduced correctly during liquidation, it can have:

1. The position may remain unsafe even after liquidation, as the debt may be higher than expected relative to the remaining collateral.
2. The vault may accumulate bad debt if the remaining collateral is insufficient to cover the incorrectly reduced debt.
3. The liquidator may not receive the expected amount of collateral for the repaid debt, leading to unfair liquidations.

In the worst-case scenario, if the `calcDecrease()` consistently fails to reduce the debt correctly, it could lead to a systematic accumulation of bad debt in the vault, compromising its financial stability and potentially causing losses for users and the protocol.

## Proof of Concept
Consider the following scenario:

1. Alice has a position with a debt of 1000 tokens and collateral worth 800 tokens at the current price.
2. The liquidation ratio is 150%, meaning the position is considered unsafe if the collateral value falls below 1500 tokens (1000 * 150%).
3. Bob decides to liquidate Alice's position and calls the `liquidatePosition()` function with a `repayAmount` of 500 tokens.
4. The `calcDecrease()` function is called to calculate the new debt, but due to an implementation issue, it returns a `newDebt` value of 800 tokens instead of the expected 500 tokens (1000 - 500).
5. The position is updated with the incorrect `newDebt`, leaving Alice's position with a debt of 800 tokens and collateral worth 300 tokens (800 - 500).
6. Alice's position remains unsafe, and the vault has accumulated 300 tokens of bad debt.

## Recommended Mitigation Steps
To ensure that the debt is correctly reduced during liquidation, the `calcDecrease()` should be modified to guarantee that the `newDebt` value is always less than or equal to the difference between the old debt and the repay amount.

add a check at the end of the `calcDecrease()` function to enforce the debt reduction invariant:
```diff
function calcDecrease(
    uint256 amount,
    uint256 debt,
    uint256 cumulativeIndexNow,
    uint256 cumulativeIndexLastUpdate,
    uint128 cumulativeQuotaInterest
)
    internal
    pure
    returns (uint256 newDebt, uint256 newCumulativeIndex, uint256 profit, uint128 newCumulativeQuotaInterest)
{
    // ...

+   newDebt = min(newDebt, debt - amount);
}
```
