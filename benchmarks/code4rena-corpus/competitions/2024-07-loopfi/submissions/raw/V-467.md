# Vulnerability details

## Vulnerability Details 
Looking in the `_transferFrom()` function inside `TransferAction.sol`, we can see that if the approvalType == ApprovalType.PERMIT, then it uses the `safePermit()` function

```solidity

    ...

    else if (params.approvalType == ApprovalType.PERMIT) {

                params.s

    IERC20(token).safeTransferFrom(from, to, amount);
```

The `safePermit` function will revert if the signature is invalid

```solidity
/**
     * @dev Use a ERC-2612 signature to set the `owner` approval toward `spender` on `token`.
     * Revert on invalid signature.
     */
    function safePermit(
        IERC20Permit token,
        address owner,
        address spender,
        uint256 value,
        uint256 deadline,
        uint8 v,
        bytes32 r,
        bytes32 s
    ) internal {
        uint256 nonceBefore = token.nonces(owner);
        token.permit(owner, spender, value, deadline, v, r, s);
        uint256 nonceAfter = token.nonces(owner);
        require(nonceAfter == nonceBefore + 1, "SafeERC20: permit did not succeed");
    }
```

The issue is that an attacker can force every signature to be invalid by frontrunning this call by directly calling the `permit()` function on the token itself, this will increase the nonce(owner) making the signature invalid for future calls.

## Impact
The honest user's tx will revert, this is significant loss of funds on mainnet.

Anyone calling these functions `transferAndSwap`, `transferAndJoin`, `increaseLever`, `depositAndBorrow` and many more with a permit can be temporarily DOS'd by frontrunning since they call `_transferFrom()`

This is medium severity because by frontrunning the permit the attacker actually increases the allowance according to the permit spec. So the user can now call whatever function without the permit since they have approval

## Recommended Mitigation Steps
Use a try catch method inside `_transferFrom`, so that if it reverts execution continues.

This is safe to do because the `transferFrom` after the permit will revert if there is no approval between the owner and spender.
