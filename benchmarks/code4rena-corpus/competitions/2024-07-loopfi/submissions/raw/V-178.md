# Vulnerability details

## Vulnerability Details 
The `StakingLPEth` contract is an ERC4626 vault. To prevent the well known inflation attack the protocol has implemented a `MIN_SHARES = 0.01 ether`. 

After every deposit/withdraw, there is a `_checkMinShares()` function to ensure the minimum number of shares is >= 0.01 ether. 

The issue is that 0.01 ether is a significant amount of funds to lock in the contract. It can lead to the following fund loss/DOS scenario

1. User A deposits 1 lpETH
2. User B deposits 0.005 lpETH (~$20)
3. User C deposits 0.005 lpETH (~$20)
4. User A withdraws 1 lpETH
5. User B/C withdraw attempts will revert indefinitely 

Simply using MIN_SHARES = 1000, which is a dust amount, is enough to make the inflation attack 1000x more expensive for the attacker i.e. to steal 1 ETH the attacker will lose 1000 ETH, while locking up only a dust amount.

## Impact
Users can have lost funds up to 0.01 lpETH

## Recommended Mitigation Steps
Very simple solution

Use MIN_SHARES = 1000
