# Vulnerability details

## Impact
The repayCreditAccount function, responsible for updating the pool’s state after a debt repayment by a credit manager, does not adequately validate the results of external calls or ensure that the input values provided are consistent with expected pool behavior. This can lead to inconsistent state updates or manipulation by malicious credit managers.

```
function repayCreditAccount(
    uint256 repaidAmount,
    uint256 profit,
    uint256 loss
)
    external
    override
    creditManagerOnly
    whenNotPaused
    nonReentrant
{
    uint128 repaidAmountU128 = repaidAmount.toUint128();

    DebtParams storage cmDebt = _creditManagerDebt[msg.sender];
    uint128 cmBorrowed = cmDebt.borrowed;
    if (cmBorrowed == 0) {
        revert CallerNotCreditManagerException();
    }

    if (profit > 0) {
        _mint(treasury, convertToShares(profit));
    } else if (loss > 0) {
        address treasury_ = treasury;
        uint256 sharesInTreasury = balanceOf(treasury_);
        uint256 sharesToBurn = convertToShares(loss);
        if (sharesToBurn > sharesInTreasury) {
            unchecked {
                emit IncurUncoveredLoss({
                    creditManager: msg.sender,
                    loss: convertToAssets(sharesToBurn - sharesInTreasury)
                });
            }
            sharesToBurn = sharesInTreasury;
        }
        _burn(treasury_, sharesToBurn);
    }

    _updateBaseInterest({
        expectedLiquidityDelta: -loss.toInt256(),
        availableLiquidityDelta: 0,
        checkOptimalBorrowing: false
    });

    _totalDebt.borrowed -= repaidAmountU128;
    cmDebt.borrowed = cmBorrowed - repaidAmountU128;

    emit Repay(msg.sender, repaidAmount, profit, loss);
}
```


Lack of Validation: The function does not thoroughly validate the repaidAmount, profit, and loss parameters. This allows a malicious credit manager to manipulate these values, potentially leading to incorrect state updates and financial discrepancies within the pool.

Unchecked External Calls: The function relies on external calls to calculate profit and loss, but it does not ensure these calculations are accurate or that the external contracts behave as expected. This could lead to situations where the pool is misled about its financial state.



A malicious credit manager could deliberately inflate the profit value, leading to excessive minting of shares to the treasury.
Conversely, by manipulating the loss value, the manager could force the pool to burn more shares than necessary, causing financial harm to the protocol.


## Proof of Concept
A malicious credit manager with control over the input values passed to repayCreditAccount could manipulate the function to either inflate the pool's profit or increase its losses.


The attacker calls repayCreditAccount with an inflated profit value, causing the pool to mint an excessive number of shares in the treasury.
Alternatively, the attacker sets a high loss value, forcing the pool to burn more shares than necessary and potentially draining the protocol's reserves.



```
// Malicious credit manager calling `repayCreditAccount`
pool.repayCreditAccount(1e18, 1e18, 0);  // Inflated profit
```

The pool’s state is manipulated, leading to incorrect financial records and potential exploitation of the treasury's assets.


The protocol could mint excessive shares, diluting the value of existing shares or burning too many shares, depleting the protocol’s assets.
Systemic Risk: Manipulating the pool’s financial state can lead to broader instability, affecting other parts of the protocol.
Security Risk: Exploiting this vulnerability could lead to significant financial damage, reducing trust in the protocol.

Manual


## Recommended Mitigation Steps


Ensure that repaidAmount, profit, and loss values are thoroughly validated and consistent with the protocol's expectations.

Implement sanity checks on the profit and loss calculations to ensure they align with the protocol's rules and expected behavior.

Ensure that any external contract interactions are secure and cannot be exploited to manipulate input values.
