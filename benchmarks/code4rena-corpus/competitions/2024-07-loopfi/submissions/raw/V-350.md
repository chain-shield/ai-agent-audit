# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The lack of a balance check before transferring ERC20 tokens can result in failed transactions when the requested tokenAmount exceeds the contract’s balance. 

This not only leads to wasted gas fees for users but also results in a poor user experience due to unexpected transaction failures. 

The absence of this check can cause operational inefficiencies and confusion among users interacting with the contract.

***Use Case***
A similar issue was encountered in the DeFi protocol Compound. 

Users experienced transaction failures when attempting to withdraw more funds than were available in a particular market. 

This led to wasted gas fees and user dissatisfaction. 

By implementing appropriate checks on token balances before processing transactions, Compound was able to reduce transaction failures, streamline operations, and improve the overall user experience.

Consider the following scenario within the _recoverERC20 function:
```sol
    /**
     * @notice Added to support recovering LP Rewards from other systems such as BAL to be distributed to holders
     */
    function _recoverERC20(address tokenAddress, uint256 tokenAmount) internal {
        IERC20(tokenAddress).safeTransfer(msg.sender, tokenAmount);
        emit Recovered(tokenAddress, tokenAmount);
    }
```

If tokenAmount is greater than the balance of tokenAddress held by the contract, the safeTransfer call will revert, leading to a failed transaction. 

This issue could be encountered in situations where the function is called with an incorrect token amount, intentionally or accidentally.

## Recommended Mitigation Steps
To mitigate this issue, introduce a balance check before attempting the token transfer. 

This will ensure the contract holds enough tokens to fulfil the transfer request, preventing transaction failures due to insufficient balance:
```sol
function _recoverERC20(address tokenAddress, uint256 tokenAmount) internal {
    require(IERC20(tokenAddress).balanceOf(address(this)) >= tokenAmount, "Insufficient tokens");
    IERC20(tokenAddress).safeTransfer(msg.sender, tokenAmount);
    emit Recovered(tokenAddress, tokenAmount);
}
```
Adding this check will ensure that the function only attempts transfers when they are likely to succeed, thus conserving gas and improving the contract’s reliability and user experience.
