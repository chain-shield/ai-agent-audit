# Vulnerability details

## Impact
Detailed description of the impact of this finding.
```CDPVault.calDecrease()``` performs some calculation during debt repayment, in particular, ```newCumulativeIndex``` needs to be calculated when all/part of the cumulativeInterest has been paid. However, the way to calculate ```newCumulativeIndex``` is wrong, leading to the loss of funds for the user or the  protocol. Sometimes we even get ```newCumulativeIndex > cumulatveIndexNow```, effectively giving an interest credit to the user, loss of funds for the protocol.  

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

First of all, ```CDPVault.calDecrease()``` performs some calculation during debt repayment. In particular, when ```amountToRepay < interestAccrued```, ```newCumulativeIndex``` is calculated as follows: 

[https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L703-L709](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L703-L709)

However, this is wrong. To show this, we understand that make sure that the ```accruedInterest``` from ```cumulativeIndexLastUpdate``` to  ```newCumulativeIndex``` should be equal to ```amountToRepay```.

Second, based on creditLogi.calcAccruedInterest(), we should have: 

```amountToRepay = (debt * newCumulativeIndex) / cumulativeIndexLastUpdate - debt```



Therefore, we have:

```
newCumulativeIndex  = (amountToRepay + debt) *  cumulativeIndexLastUpdate / debt
                    = cumulativeIndexLastUpdate + amountToRepay * cumulativeIndexLastUpdate / debt; 
```

Therefore, the way to calculate ```newCumulativeIndex``` in ```CDPVault.calDecrease()``` is wrong. 


In the following, we show that:
1. The test contract creates a position 100 ether collateral and 80 ether debt.
2. After 365 days, it accrues ``` cumulativeQuotaInterest``` in the amount of 80000000000000000 and ```accruedInterst``` in the amount of ```8001505882352941176``` and thus a total interest of 8081505882352941176.
3. The test contract repays in the amount of 8002505882352941176, which is 0.001 ether over ```accruedInterst```. As a result, all of ``` cumulativeQuotaInterest```  will be paid off, and part of the ```cumulativeQuotaInterest``` will be paid. 
4, However, due the wrong calculation of ```newCumulativeIndex```, we get into a situation in which ```newCumulativeIndex > cumulativeIndexNow```, means that effectively, the contract cancels some of the debt for the user ahead of time, loss of funds for the protocol. 
5. Due to ```newCumulativeIndex > cumulativeIndexNow```, the function ```virtualDebt()``` will revert due to underflow.

## Recommended Mitigation Steps
For the case of ```amountToRepay < interestAccrued```, calculate ```newCumulativeIndex``` as follows: 
```
newCumulativeIndex  = (amountToRepay + debt) *  cumulativeIndexLastUpdate / debt
                    = cumulativeIndexLastUpdate + amountToRepay * cumulativeIndexLastUpdate / debt; 
```

Make sure the calculation is done before amountToRepay is set to zero.
