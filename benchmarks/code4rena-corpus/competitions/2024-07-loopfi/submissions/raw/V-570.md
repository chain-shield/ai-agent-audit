# Vulnerability details

## Impact

This allow a malicious borrower to create a lot of **too small** debt positions (i.e. ` 1 wei` debt positions) by borrowing **too** small amount of credit (i.e. `1 wei`), which is difficult to be liquidated - due to less incentive for liquidators to liquidate these **too small** debt positions.


## Proof of Concept

When a borrower would borrow credit against collateral, the borrower would call the CDPVault#`modifyCollateralAndDebt()` via the CDPVault#`borrow()` or via the PositionAction#`borrow()`.

Within the PositionAction#`borrow()`, the PositionAction#`_borrow()` would be called with a given `creditParams` like this:

Within the following functions, which is called during the borrowing process above, the **minimum** borrowing amount is supposed to be set and validated whether or not a given `amount` (or `creditParams.amount`) to be borrowed exceeds the **minimum** borrowing amount: 
- PositionAction#`borrow()`
- CDPVault#`borrow()`
- CDPVault#`modifyCollateralAndDebt()` 
- PoolV3#`lendCreditAccount()`

However, within the functions above, there is **no** validation to check whether or not a given `amount` (or `creditParams.amount`) to be borrowed exceeds the **minimum** borrowing amount. 

This allow a malicious borrower to create a lot of **too small** debt positions (i.e. ` 1 wei` debt positions) by borrowing **too** small amount of credit (i.e. `1 wei`), which is difficult to be liquidated - due to less incentive for liquidators to liquidate these **too small** debt positions.


## Tools Used
- Foundry


## Recommended Mitigation Steps

Within the PositionAction#`borrow()` and the CDPVault#`borrow()`, consider setting the **minimum** borrowing amount and adding a validation to check whether or not a given `amount` (or `creditParams.amount`) to be borrowed exceeds the **minimum** borrowing amount.
