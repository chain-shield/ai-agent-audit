# Vulnerability details

## Impact
Oracle price can be manipulated resulting in loss of funds for users and the protocol

## Proof of Concept
Last year the Balancer team disclosed a read only reentrancy bug in the Balancer vault which can be found [here](https://forum.balancer.fi/t/reentrancy-vulnerability-scope-expanded/4345)

The issue is that an attacker can manipulate the BPT price that is calculated in the `BalancerOracle.sol#update()` function through a pool join or exit. This can be achieved by the attacker by manipulating the Balancer data (`IWeightedPool(pool).totalSupply()`) that is being read in the update() function in a read-only reentrancy. This will cause the resulting calculated BPT price to be wrong leading to loss of funds.

This can be prevented by the solution provided by the Balancer team which is to call the [`VaultReentrancyLib.ensureNotInVaultContext()`](https://github.com/balancer/balancer-v2-monorepo/blob/9c1574b7d8c4f5040a016cdf79b9d2cc47364fd9/pkg/pool-utils/contracts/lib/VaultReentrancyLib.sol#L37C14-L37C37) function in the `BalancerOracle.update() function`. This will activate internal reenterancy validation in a read-only function call.

## Recommended Mitigation Steps
Implement a call to [`VaultReentrancyLib.ensureNotInVaultContext()`](https://github.com/balancer/balancer-v2-monorepo/blob/9c1574b7d8c4f5040a016cdf79b9d2cc47364fd9/pkg/pool-utils/contracts/lib/VaultReentrancyLib.sol#L37C14-L37C37) function in the `BalancerOracle.update() function` as recommended by the balancer [docs](https://docs.balancer.fi/concepts/advanced/valuing-bpt/valuing-bpt.html#on-chain-price-evaluation).
