# Vulnerability details

## Proof of Concept
The `setAutocompound` and `setUserSlippage` functions in the `MultiFeeDistribution` contract contain a logical error in their slippage validation. These functions are designed to allow users to set their preferred slippage tolerance for autocompounding operations. However, the current implementation incorrectly validates the slippage value, potentially allowing users to set dangerously high slippage rates.
The problematic code is as follows:
```solidity
function setAutocompound(bool status, uint256 slippage) external {
    autocompoundEnabled[msg.sender] = status;
    if (slippage < MAX_SLIPPAGE || slippage >= PERCENT_DIVISOR) {
        revert InvalidAmount();
    }
    userSlippage[msg.sender] = slippage;
}

function setUserSlippage(uint256 slippage) external {
    if (slippage < MAX_SLIPPAGE || slippage >= PERCENT_DIVISOR) {
        revert InvalidAmount();
    }
    userSlippage[msg.sender] = slippage;
}
```
The condition `slippage < MAX_SLIPPAGE` is intended to ensure that the slippage doesn't exceed the maximum allowed value (10% or 9000 in basis points). However, this condition actually prevents slippage from being set to any value less than `MAX_SLIPPAGE`, while allowing values between `MAX_SLIPPAGE` and `PERCENT_DIVISOR` (which is 10000, or 100%).
This error defeats the purpose of having a maximum slippage limit and could lead to unexpected behavior in autocompounding operations.
## Impact
Users may unknowingly set extremely high slippage tolerances (up to 99.99%), potentially resulting in significant financial losses during autocompounding transactions due to unfavorable exchange rates.
## Tools Used
Manual
## Recommended Mitigation Steps
Modify the slippage validation condition in both functions to correctly enforce the maximum slippage limit:
```solidity
if (slippage > MAX_SLIPPAGE || slippage == 0) {
    revert InvalidAmount();
}
```
