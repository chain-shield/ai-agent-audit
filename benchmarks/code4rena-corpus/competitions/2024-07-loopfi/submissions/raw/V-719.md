# Vulnerability details

# Front-running liquidation of bad debt positions

The `CDPVault` contract allows liquidation of positions with bad debt through the `liquidatePositionBadDebt()` function. However, the current implementation is vulnerable to front-running  that can prevent legitimate liquidations from occurring, even when a position is still in bad debt.
## Impact

- Positions with bad debt may remain in the system longer than necessary, increasing risk for the protocol
## Proof of Concept

1. Alice's position has 100 units of collateral and 200 units of debt (bad debt scenario)
2. Bob, a liquidator, observes this and prepares a transaction to liquidate Alice's position
3. Alice notices Bob's pending transaction in the mempool
4. Alice quickly submits a transaction to add 10 unit of collateral to her position
5. Alice's transaction is processed first, slightly increasing her collateral
6. Bob's liquidation transaction fails because the check `calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)` now returns false
7. Alice's position remains in bad debt

## Tools Used

Manual review

## Recommended Mitigation Steps

Allow partial liquidations of bad debt positions, so that even if some collateral is added, the liquidator can still process part of the bad debt.
