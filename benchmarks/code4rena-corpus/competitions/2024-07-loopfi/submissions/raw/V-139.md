# Vulnerability details

## Impact

The design of the code allows any user to pay the debt of a position, including their own due to this the attack can be performed permissionlessly at any time. There is a bug in the `calcDecrease` function that allows an arbitrary user to brick a position for a certain number of days or hours relative to the interest accrued by paying a portion of the accrued interest. This bug arises when the `newCumulativeIndex` is calculated in `calcDecrease`. When paying a portion of the interest an attacker can break the implied invariant `cumulativeIndexNow >= cumulativeIndexLastUpdate` due to an incorrect implementation of the calcDecrease function from the CreditLogic library.

## Proof of Concept 
The test below shows that the modifyCollateralAndDebt function will revert until the baseInterestNow is more than the cumulativeIndexLastUpdate. 

Note that this will also revert when using LiquidatePosition as well as LiquidatePositionBadDebt.


Add the test below to `2024-07-loopfi/src/test/unit/CDPVault.t.sol:`

## Reference to Previous Adjudications and Reasoning Behind Severity

**Wise Lending**: [GitHub Issue #123](https://github.com/code-423n4/2024-02-wise-lending-findings/issues/123)

The lead judge in the previous adjudication noted, "Had the report demonstrated a way to exploit this vulnerability to halt liquidations, it would have been easier to justify a higher severity level."

This vulnerability allows for the halting of liquidations and the ability to open and close new positions. It becomes particularly critical during high-price impact scenarios(e.g. black swan events, or hacks), where automated bots will need to trigger liquidations. If an attacker identifies such an impact, they could use this vulnerability to lock positions and prevent liquidations which will lead to many bad debt positions.

## Recommended Mitigation Steps
This is the correct implementation of the calcDecrease functionality from the CreditLogic library. When using this , ensure you set the fee to 1. Additionally, instead of using profit in the calculation, use the amountToPool variable as defined in the CreditLogic library to accurately compute the new cumulative index.

```solidity
       else {
                // If amount is not enough to repay interest, then send all to the stakers and update index
```
