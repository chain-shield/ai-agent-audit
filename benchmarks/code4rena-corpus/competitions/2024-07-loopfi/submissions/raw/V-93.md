# Vulnerability details

## Proof of Concept
In the `liquidatePosition` function, the `discountedPrice` is calculated by multiplying the `spotPrice_` by the `liquidationDiscount`. However, there is no explicit check to ensure that the `spotPrice_` is not zero before performing this multiplication. This could lead to a situation where `discountedPrice` becomes zero if `spotPrice_` happens to be zero, which would then directly impact the calculation of `takeCollateral`.

Here's the relevant part of the code:
```solidity
uint256 spotPrice_ = spotPrice();
uint256 discountedPrice = wmul(spotPrice_, liqConfig_.liquidationDiscount);
if (spotPrice_ == 0) revert CDPVault__liquidatePosition_invalidSpotPrice();
```
The check for `spotPrice_ == 0` is performed after the calculation of `discountedPrice`, which means that if `spotPrice_` is zero, `discountedPrice` would already be incorrectly calculated as zero before the condition is checked.

## Impact
If `discountedPrice` is zero, the calculation of `takeCollateral` would also become problematic, as it relies on `discountedPrice`. This could lead to incorrect liquidation processes, where the intended repayment amount does not match the actual collateral taken, potentially leading to financial losses or other unintended consequences.
## Tools Used
Manual
## Recommended Mitigation Steps
The check for `spotPrice_ == 0` should be performed before calculating `discountedPrice`. This ensures that `discountedPrice` is only calculated when `spotPrice_` is not zero, preventing the possibility of a zero `discountedPrice` and potential divide by zero when calculating `takeCollateral`.
