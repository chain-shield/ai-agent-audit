# Vulnerability details


## Proof of Concept

Take a look at https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/oracle/PendleLPOracle.sol#L103-L112

```solidity
function spot(
  address /* token */
) external view virtual override returns (uint256 price) {
  bool isValid;
  (isValid, price) = _fetchAndValidate();
  if (!isValid) revert PendleLPOracle__spot_invalidValue();
  bool isValidPtOracle = _validatePtOracle();
  if (!isValidPtOracle) revert PendleLPOracle__validatePtOracle_invalidValue();
  uint256 lpRate = market.getLpToAssetRate(twapWindow);
  price = wmul(price, lpRate);
}

```

Evidently, the `spot` function always uses `getLpToAssetRate()` to convert LP tokens to their underlying asset value. This approach is flawed because it doesn't account for the different types of Pendle markets and their specific pricing requirements.

First, note that in regards to Pendle principal tokens there are 2 units `PT / LP` can be denominated in, either SY or in Asset. So to get the price in SY, we can call either `getPtToSyRate()`/ `getLpToSyRate`, or `getLpToAssetRate`/ `getPtToAssetRate()`.

Now according to [Pendle's official documentation for integrating PT/LP oracles](https://github.com/pendle-finance/documentation/blob/e356bb0538cd6de5f5caa7941554fc403d1a1542/docs/Developers/Integration/HowToIntegratePtAndLpOracle.md#fourth-get-the-price), the correct rate conversion method depends on the specific market and its underlying assets. Some markets are better priced using `getLpToAssetRate()`/ `getPtToAssetRate()`, while others should use `getLpToSyRate()`/`getPtToSyRate()`.

Let's use PT for illustration purposes:

- Consider the example of 1 SY-cUSDC (Compound), which is equivalent to 1 cUSDC. However, cUSDC is not a tradable asset. The underlying asset of SY-cUSDC is USDC staked in Compound. Given we can assume that Compound is always solvent, SY-cUSDC can be valued in USDC. Therefore, it is advisable to use `getPtToAssetRate` instead of `getPtToSyRate()`

- Another example is for 1 SY-weETH [(Ether.fi)](https://www.ether.fi) is equivalent to 1 weETH, and since weETH is a tradable asset, the SY price is well-defined. The asset of SY-weETH is eETH, which is also a tradable asset. In this scenario, both functions can be utilized.

- However the above two implementation is not applicable to the case when dealing with 1 SY-rsETH, which is equivalent to 1 rsETH. Since rsETH is a tradable asset, the SY price is well-defined. The asset of SY-rsETH is ETH staked in Kelp, which is not a tradable asset. Hence, `getPtToSyRate` is recommended, and using `getPtToAssetRate()` would not prop the accurate rate.

And a similar case should be made to pricing Lps, however the current implementation doesn't differentiate between these cases, potentially leading to incorrect pricing for certain LP tokens.

## Impact

The hardcoded use of `getLpToAssetRate()` would lead to significant mispricing of LP tokens in markets where `getLpToSyRate()` should be used. This mispricing can have severe consequences in other instances of the ecosystem where valid prices are expected.

MAYBE REMOVE"""""""""""""""""1. Incorrect valuation of user positions in the protocol. 2. Miscalculation of collateral values, potentially leading to under-collateralized positions or preventing users from borrowing their full entitled amount. 3. Inaccurate pricing in trades or swaps involving these LP tokens. 4. Potential for exploitation by arbitrageurs who can take advantage of the mispricing."""""""""""""""""

## Recommended Mitigation Steps

Implement a mechanism to determine the correct rate conversion method for each supported Pendle market. This could involve:

- Adding a flag in the oracle configuration to indicate whether to use `getLpToAssetRate()` or `getLpToSyRate()`.
- Implementing a function to dynamically determine the correct method based on the market's characteristics.

> The flag can be help sorted out for assets by using [this page](https://github.com/pendle-finance/documentation/blob/e356bb0538cd6de5f5caa7941554fc403d1a1542/docs/Developers/Contracts/StandardizedYield.md).

Then modify the `spot` function to use the appropriate rate conversion method:

```solidity
function spot(
  address /* token */
) external view virtual override returns (uint256 price) {
  bool isValid;
  (isValid, price) = _fetchAndValidate();
  if (!isValid) revert PendleLPOracle__spot_invalidValue();
  bool isValidPtOracle = _validatePtOracle();
  if (!isValidPtOracle) revert PendleLPOracle__validatePtOracle_invalidValue();

  uint256 lpRate;
  if (shouldUseAssetRate()) {
    lpRate = market.getLpToAssetRate(twapWindow);
  } else {
    lpRate = market.getLpToSyRate(twapWindow);
  }

  price = wmul(price, lpRate);
}

```
