# Vulnerability details


## Impact
The attacker gains funds, while the user loses funds.

## Proof of Concept


```javascript
 function totalAssets() public view virtual override(IERC4626, ERC4626) returns (uint256) {
        return IPool(rewardPool).balanceOf(address(this));
    }
```
AuraVault references OpenZeppelin’s ERC4626 library, where the total assets are calculated based on the number of reward pool shares held by the contract. From the on-chain address of the rewardPool, it is identified that the rewardPool is also an ERC4626 contract.
https://vscode.blockscan.com/ethereum/0x00A7BA8Ae7bca0B10A32Ea1f8e2a1Da980c6CAd2

Therefore, an inflation attack could potentially be carried out.

Attack Scenario:

	1.	After the AuraVault  contract is deployed, the attacker deposits a very small amount of the asset, such as 1 wei, and receives 1 wei of the share.
	2.	When the attacker notices that a user is depositing funds (e.g., 1e18 assets),
	3.	The attacker performs a frontrun by donating 1e18 assets(by send rewardPool share token to AuraVault or IPool(rewardPool).deposit(assets, address(AuraVault)) ). 
	4.	At this point, the user will receive 0 shares.
	5.	The attacker then uses the redeem() or withdraw() function to withdraw all their  share, gaining all the funds.



## Tools Used
Manual Review

## Recommended Mitigation Steps
Perform a minimum share value check on the shares a user receives.
