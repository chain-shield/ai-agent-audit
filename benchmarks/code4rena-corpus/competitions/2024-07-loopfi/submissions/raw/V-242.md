# Vulnerability details

## Summary

The `_convertToU128` function in the `PoolV3` contract is intended to convert a uint256 limit to a uint128, ensuring compatibility with the protocol's debt management mechanisms. However, when the function encounters a limit slightly above uint128's maximum value (type(uint128).max), it results in an overflow conversion to an incorrect minimal value (0), instead of handling the overflow appropriately. This can lead to significant operational disruptions by inadvertently setting debt limits to extremely low values.

```solidity

function _convertToU128(uint256 limit) internal pure returns (uint128) {
        return (limit == type(uint256).max) ? type(uint128).max : limit.toUint128();
    }

```

## Impact

The function `_convertToU128` misconverts a `uint256` limit slightly above `type(uint128).max` due to its internal casting, leading to potential severe impact:

1. **Total Debt Limit**:
    - When setting the total debt limit using `setTotalDebtLimit`, the incorrect conversion might result in setting `_totalDebt.limit` to a very low number.
    - **Consequences**:
        - This drastically reduces the total borrowing capacity of the pool to nearly zero, severely restricting normal borrowing operations.
        - Such restrictions can disrupt the lending functionality, significantly reducing the protocol’s utility and operational throughput.

2. **Credit Manager Debt Limit**:
    - When setting individual credit manager debt limits using `setCreditManagerDebtLimit`, the incorrect conversion might set `_creditManagerDebt[creditManager].limit` to a minimal value.
    - **Consequences**:
        - This inadvertent restriction limits the borrowing ability of the credit manager to a negligible amount.
        - Such constraints can hamper the credit manager’s ability to operate effectively, potentially stalling their activities and leading to operational inefficiencies.

In both cases, the incorrect conversion leads to setting artificially low debt limits, which disrupts borrowing operations and reduces the utility of the lending protocol.

contract TestConvertToU128 is Test {

    // The function that we are testing
    function _convertToU128(uint256 limit) internal pure returns (uint128) {
        return (limit == type(uint256).max) ? type(uint128).max : uint128(limit);
    }

    // Test to check conversion of a value just above uint128 max
    function testConvertAboveUint128Max() public {
        uint256 limit = uint256(type(uint128).max) + 1;
        uint128 result = _convertToU128(limit);
        emit log_uint(result);  
    }

    // Test to check conversion of a value equal to uint128 max
    function testConvertAtUint128Max() public {
        uint256 limit = uint256(type(uint128).max);
        uint128 result = _convertToU128(limit);
        emit log_uint(result);  
    }

    // Test to check conversion of a value below uint128 max
    function testConvertBelowUint128Max() public {
        uint256 limit = uint256(type(uint128).max) - 1;
        uint128 result = _convertToU128(limit);
        emit log_uint(result);  
    }
}

## Recommended Mitigation Steps

Add a boundary check before performing the conversion. Specifically, if the uint256 limit exceeds type(uint128).max, the function should return type(uint128).max. Otherwise, it should proceed with the conversion as usual. 


```solidity

function _convertToU128(uint256 limit) internal pure returns (uint128) {
    // Check if the limit exceeds the maximum value for uint128
    // If so, return the maximum value of uint128
    if (limit > type(uint128).max) {
        return type(uint128).max;
    }
    // Otherwise, perform the conversion
    return uint128(limit);
}

```
