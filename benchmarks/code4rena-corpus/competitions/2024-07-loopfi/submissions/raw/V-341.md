# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The setCreditManager function does not validate the token and vault parameters, which could lead to erroneous or malicious configurations if zero addresses are inadvertently set. 

This can cause downstream errors in other parts of the contract that rely on creditManagers mapping to be correctly initialised.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

The vulnerable function is as follows:
```sol
    function setCreditManager(
        address token,
        address vault
    )
        external
        override
        configuratorOnly // U:[PQK-2]
    {
        creditManagers[token] = vault;
    }
```

The setCreditManager function is intended to map a token to its respective vault (credit manager). 

However, there are no checks to ensure that token and vault are non-zero addresses. 

This lack of validation allows potentially unintended configurations, which can lead to the following issues:

1. Setting Zero Addresses: 
If a zero address is set as a vault, any logic dependent on creditManagers[token] will fail, potentially leading to incorrect calculations or system failures.

2. Incorrect Configuration: 
Mistakenly setting incorrect or null values can disrupt the relationship between tokens and their credit managers, leading to systemic failures in quota management.

***Example Scenario***

Suppose the following call is made in error or maliciously by an insider to the setCreditManager function:
```sol
setCreditManager(address(0x0000000000000000000000000000000000000000), address(0x0000000000000000000000000000000000000000));
```

This would set the creditManagers mapping for the zero address token to the zero address vault, creating a scenario where other functions, like poolQuotaRevenue, fail or produce incorrect results due to referencing the zero address.

## Recommended Mitigation Steps

To mitigate this issue, the setCreditManager function should include input validation to ensure that neither the token nor the vault is set to a zero address. Here is a possible implementation:
```sol
function setCreditManager(address token, address vault) external override configuratorOnly {
    require(token != address(0), "Token address cannot be zero");
    require(vault != address(0), "Vault address cannot be zero");
    creditManagers[token] = vault;
}
```
