# Vulnerability details

## Impact
Violation of system invariants causing unexpected behavior in other parts of the protocol that assume the debt floor is always enforced.

## Proof of Concept
`liquidatePosition()` function does not enforce the debt floor requirement after liquidation and can result in positions with debt below the debt floor but not zero. In the debt calculation logic between lines [541-558 of CDPVault.sol](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L545-L558). When `deltaDebt` is less than `maxRepayment`, the resulting `newDebt` may fall below the debt floor without being set to zero.  In this case, the `calcDecrease` function is called to calculate the new debt.
```solidity
uint256 newDebt;
// ...
if (deltaDebt == maxRepayment) {
    newDebt = 0;
    // ...
} else {
    (newDebt, newCumulativeIndex, profit, position.cumulativeQuotaInterest) = calcDecrease(
        deltaDebt, // delta debt
        debtData.debt,
        debtData.cumulativeIndexNow, // current cumulative base interest index in Ray
        debtData.cumulativeIndexLastUpdate,
        debtData.cumulativeQuotaInterest
    );
   // ...
           // update liquidated position
        position = _modifyPosition(owner, position, newDebt, newCumulativeIndex, -toInt256(takeCollateral), totalDebt);
   // ...
}
```
While `_modifyPosition()` [#L560-L561](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L560-L561) checks the debt floor, it's bypassed when `deltaDebt` is slightly less than `maxRepayment`. This results in `newDebt` being set by `calcDecrease()` without ensuring it's zero or above the floor.

This allows "dust debt" to persist, violating the intended system state.

There is no check that the resulting `newDebt` is either zero or above the debt floor, which is defined in the [vaultConfig#L70-L75](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L70-L75)
```solidity
struct VaultConfig {
    /// @notice Min. amount of debt that has to be generated by a position [wad]
    uint128 debtFloor;
    /// @notice Collateralization ratio below which a position can be liquidated [wad]
    uint64 liquidationRatio;
}
```
Here's how.

* Alice opens a position with debt slightly above the debt floor.
* The collateral value decreases, making the position eligible for liquidation.
* Bob calls `liquidatePosition()` with a `repayAmount` that reduces the debt to just below the debt floor.
* The function executes successfully, leaving Alice's position with a debt amount that violates the debt floor requirement.

enforce the debt floor requirement after debt reduction.

      (newDebt, newCumulativeIndex, profit, position.cumulativeQuotaInterest) = calcDecrease(
