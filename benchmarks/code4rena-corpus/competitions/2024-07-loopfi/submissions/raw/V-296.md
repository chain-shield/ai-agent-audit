# Vulnerability details

## Impact

The vulnerability allows users to deposit potentially excessive amounts of assets, leading to over-leverage. This exposes users to higher risks of market volatility and credit losses beyond the system's designed risk tolerance. Consequently, such over-leverage could destabilize the financial health of LoopFi, increasing the risk of defaults and adversely affecting all users and stakeholders.

## Proof of Concept

The `depositWithReferral` function allows a user to deposit a certain amount of assets (`assets`) without any checks against the platform's established limits. The function simply calls another function `deposit(assets, receiver)` and emits an event without validating the input against any threshold. This lack of validation is critical because it directly permits the input vulnerability where a user could deposit more assets than the system's constraints intend to allow (currently implied at uint256.max).

Here's the function in question:
```solidity
function depositWithReferral(
uint256 assets,
address receiver,
uint256 referralCode
) external override returns (uint256 shares) {
shares = deposit(assets, receiver);
emit Refer(receiver, referralCode, assets);
}
```

## Recommended Mitigation Steps

1. **Implement Input Validation:** Before proceeding with the deposit, validate the `assets` parameter to ensure it does not exceed the maximum limit set by the platform. This can be done by integrating a check at the beginning of the `depositWithReferral` function or within the `deposit` function it calls.

2. **Daily Limit Enforcement:** Introduce and enforce daily deposit and borrowing limits per user. This helps in managing risk and preventing any form of abuse that could lead to financial instability.
