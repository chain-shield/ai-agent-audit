# Vulnerability details

`liquidatePositionBadDebt()` function aims to handle the liquidation of positions with bad debt, where the collateral value is less than the total debt. However, the current implementation could lead to a loss of funds.

The function checks for bad debt using the discounted price of the collateral, but then proceeds to repay the debt using the full value of the collateral. This discrepancy allows an attacker to profit by repaying bad debt at a discounted rate and potentially draining the vault's funds.

## Impact
* **High Impact:** An attacker could exploit this discrepancy to repay bad debt at a discounted price, leading to a significant loss of funds for the protocol.
**Low Impact:** `liquidatePositionBadDebt()` function is unusable in its current state due to the flawed logic.

* **An attacker identifies a position with bad debt.** This means the `calcTotalDebt(debtData)` is greater than `wmul(position.collateral, spotPrice_)` (as per the `BadDebt` error condition).
* **The attacker calls `liquidatePositionBadDebt()` with a `repayAmount` calculated using the discounted collateral price.** This allows them to repay a portion of the debt at a lower value than it actually represents.
* **The contract accepts the discounted `repayAmount` but transfers the full collateral amount to the attacker.** This results in the attacker gaining more value in collateral than the amount of debt they repaid.
* **This process can be repeated draining the vault of its collateral.**
