# Vulnerability details

## Vulnerability Details

The protocol implements a debtFloor to enforce the minimum amount of debt a position can have at a time.

The issue is that this is enforced when liquidations occur. In edge cases it can lead to liquidation reverting, which should never happen.

The following line from `_modifyPosition()` in `CDPVault.sol` is where the revert happens

```solidity
if (position.debt != 0 && position.debt < uint256(vaultConfig.debtFloor))
        revert CDPVault__modifyPosition_debtFloor();

```

If the liquidator sends a transaction to liquidate a position but in that time even 1 wei of interest accumulates, the whole liqudaition will revert.

## Proof of Concept

Add the following `test__POC__LiquidationRevertsDueToDebtFloorNotMet` to CDPVault.t.sol and run it using the following command

```bash
forge test --mt test__POC__LiquidationRevertsDueToDebtFloorNotMet

```

```solidity
function test__POC__LiquidationRevertsDueToDebtFloorNotMet() public {
    //===========================
    // SETUP
    //===========================

    // Create a CDP vault with a very low debt floor (0.001 ether)
    CDPVault vault = createCDPVault(token, 150 ether, 0.001 ether, 1.25 ether, 1 ether, 1 ether);
    createGaugeAndSetGauge(address(vault));

    address position = address(this);

    //===========================
    // POC STARTS HERE
    //===========================

    // Create a position for address(this) that borrows 80 WETH
    _modifyCollateralAndDebt(vault, 100 ether, 80 ether);

    // repayment amount that will leave debt below the debt floor
    uint256 repayAmount = 80 ether - 100;

    // Prepare for liquidation
    mockWETH.mint(address(this), repayAmount);
    mockWETH.approve(address(vault), repayAmount);

    // Collateral price drops making the position unsafe
    _updateSpot(0.8 ether);

    // Attempt to liquidate the position
    // It reverts due to the debt floor not being reached
    vm.expectRevert(CDPVault.CDPVault__modifyPosition_debtFloor.selector);
    vault.liquidatePosition(position, repayAmount);

}

```

## Impact

The time sensitive liquidation is delayed, increasing risk of bad debt accumulation

Honest liquidator loses gas fees, since the protocol is deployed on Ethereum mainnet this is a significant fund loss and will discourage them from liquidating in the future. This decreases the security of the protocol and increased bad debt risk.

## Recommended Mitigation Steps

Do not enforce the debtFloor if the position is being liquidated because the liquidation is more important
