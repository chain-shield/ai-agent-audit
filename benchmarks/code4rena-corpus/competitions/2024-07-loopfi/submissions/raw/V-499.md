# Vulnerability details

## Impact
`swapParams.recipient` will never receive any incoming ETH transfer or out going transfer. 

The primary impact of this bug is the potential for failed transactions or loss of ETH if the recipient address is not payable. This flaw undermines the reliability of the Uniswap V3 swap functions when dealing with ETH, leading to possible asset losses and user dissatisfaction.

## Proof of Concept
In the Uniswap V3 swap functions, specifically `ExactInputParams` and `ExactOutputParams, the handling of ETH transactions is crucial. These functions facilitate the conversion of one asset into another through the Uniswap V3 router, which includes the possibility of swapping between ERC20 tokens and ETH. However, the current implementation does not adequately address the necessity for recipient addresses to be payable when ETH is involved.
https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/SwapAction.sol#L307
```solidity
function uniV3Swap(
        SwapType swapType,
        address assetIn,
        uint256 amount,
        uint256 limit,
        address recipient,
        uint256 deadline,
        bytes memory args
    ) internal returns (uint256) {
        if (swapType == SwapType.EXACT_IN) {
            IERC20(assetIn).forceApprove(address(uniRouter), amount);
            return
                uniRouter.exactInput(
                    ExactInputParams({
                        path: args,
                        recipient: recipient,    <@
                        amountIn: amount,
                        amountOutMinimum: limit,
                        deadline: deadline
                    })
                );
        } else {
            IERC20(assetIn).forceApprove(address(uniRouter), limit);
            return
                uniRouter.exactOutput(
                    ExactOutputParams({
                        path: args,
                        recipient: recipient,   <@
                        amountOut: amount,
                        amountInMaximum: limit,
                        deadline: deadline
                    })
                );
        }
    }
```

The `ExactInputParams` function is used when the amount of input tokens is predetermined, and the goal is to receive at least a specified minimum amount of output tokens. In scenarios where ETH is involved:

>Recipient Address Requirement:

The recipient address, which receives the output tokens, must be payable if ETH is included in the swap. This is necessary because ETH cannot be transferred to a non-payable address.
However, the function does not ensure that the recipient address is payable, which can result in the failure of transactions where ETH is the output. This gap in validation can cause unexpected transaction reverts or loss of ETH if the recipient is not capable of accepting ETH.

The `ExactOutputParams` function is employed when the desired output amount is specified, and the maximum amount of input tokens is constrained. For ETH swaps:

>Recipient Address Requirement:

Similarly, if ETH is part of the output, the recipient must be payable. This ensures that ETH can be successfully transferred to the recipient address without transaction failure.
The absence of checks for payable recipient addresses in this function poses a significant risk. Transactions involving ETH might fail silently or result in errors if the recipient address does not conform to the payable requirement.

A user specifies that they wish to swap DAI for ETH using the `exactInput` function.
If the recipient address is not payable, the transaction will fail when attempting to transfer ETH to this address.
The user might encounter an unexpected failure or loss of assets due to this oversight. 

A user provides ETH as the input and requests a specific amount of DAI as output using the `exactOutput` function.
If the recipient address is not payable, the ETH cannot be transferred to this address, resulting in a failed transaction. 


## Tools Used
Manual review

## Recommended Mitigation Steps
Modify the Uniswap V3 swap functions to include checks that ensure the recipient address is payable when ETH is part of the transaction. This validation should occur before attempting to transfer ETH.
