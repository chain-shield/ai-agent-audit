# Vulnerability details

## Impact
Users who enter a loopfi position can adjust their risk by decreasing their leverage or repaying their debt before the healthfactor goes down to the liquidation rate.

However, If the user calls the 'decreaseLever' function and the 'protocolFee' of the 'flashLender' contract is greater than 0, the 'decreaseLever' function will always be reverted.

This problem prevents users from lowering leverage to manage liquidation risk when protocolfee exists, exposing them to liquidation risk.

https://github.com/code-423n4/2024-07-loopfi/blob/main/src/Flashlender.sol#L117-L137
```
    function creditFlashLoan(
        ICreditFlashBorrower receiver,
        uint256 amount,
        bytes calldata data
    ) external override nonReentrant returns (bool) {
        uint256 fee = wmul(amount, protocolFee);
        uint256 total = amount + fee;

        pool.lendCreditAccount(amount, address(receiver));

        emit CreditFlashLoan(address(receiver), amount, fee);

        if (receiver.onCreditFlashLoan(msg.sender, amount, fee, data) != CALLBACK_SUCCESS_CREDIT)
            revert Flash__creditFlashLoan_callbackFailed();

        // reverts if not enough Stablecoin have been send back
        underlyingToken.transferFrom(address(receiver), address(pool), total);
        pool.repayCreditAccount(total - fee, fee, 0);

        return true;
    }
```
'creditFlashLoan' function is a flashloan function that lends the underlying token to the receiver and then returns the loan amount plus protocol fee at the end.

https://github.com/code-423n4/2024-07-loopfi/blob/main/src/proxy/PositionAction.sol#L489

```
        underlyingToken.forceApprove(address(flashlender), subDebt);

```
Before returning the debt, the approval amount is set through the 'forceApprove' function in the 'onCreditFlashLoan' function and the underlying token is sent.

```
creditFlashLoan function:
underlyingToken.transferFrom(address(receiver), address(pool), total);

onCreditFlashLoan function:
uint256 subDebt = leverParams.primarySwap.amount;
underlyingToken.forceApprove(address(flashlender), subDebt);
```
Here, when the protocolFee of flashLender exists, the difference between the 'total' amount returned by the creditFlashLoan function and the approval amount (subDebt) of the onCreditFlashLoan function causes an 'insufficient allowance' revert.
