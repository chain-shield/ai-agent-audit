# Vulnerability details



## Impact

The withdrawal logic mishandles the transfer of assets,potentially lead to inconsistencies in asset distribution in case fee is apply. Specifically, the incorrect transfer amount results in :


* Users may receive more assets than intended

*  The protocol may incorrectly distribute assets between users and the treasury. 


## Proof of concept

1. Withdrawal Request:

* User wants to withdraw `1000` units of underlying assets.

* Withdrawal fee is 1%, and an additional fee of 1% is applied.

2. Calculations in `PoolV3::withdraw` Function

https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L292

```js
    uint256 assetsToUser = _amountWithFee(assets);
    // assetsToUser = _amountWithFee(1000) = 1010

    uint256 assetsSent = _amountWithWithdrawalFee(assetsToUser);
    // assetsSent = _amountWithWithdrawalFee(1010) = 1010 * (10000) / (10000 - 100) = 1020

    shares = _convertToShares(assetsSent);
    // Assuming conversion rate is 10:1, shares = 1020 / 10 = 102
```

3. Call to `_withdraw` : 


`_withdraw(receiver, owner, 1020, 1000, 1010, 102);`

* assetsSent = 1020
* assetsReceived = 1000
* amountToUser = 1010
* shares = 102

4. Execution of `_withdraw` function


https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L401

```js
    if (msg.sender != owner) _spendAllowance({owner: owner, spender: msg.sender, amount: shares});
    // Spends the allowance if msg.sender is not the owner.

    _burn(owner, shares);
    // Burns 102 shares from the owner's balance.

    IERC20(underlyingToken).safeTransfer({to: receiver, value: amountToUser});
    // Transfers 1010 units of assets to the user.

    if (assetsSent > amountToUser) {
        unchecked {
            IERC20(underlyingToken).safeTransfer({to: treasury, value: assetsSent - amountToUser});
            // Transfers 1020 - 1010 = 10 units of assets to the treasury.
        }
    }

    emit Withdraw(msg.sender, receiver, owner, assetsReceived, shares);
    // Emits an event showing the withdrawal details. (assetsReceived : 1000, shares : 102)

```

5. Observed Issues :

* Incorrect Amount to User : The user receives 1010 units instead of the intended 1000 units when fee is apply.


* Event Mismatch : The emitted event reports that the user received 1000 units and 102 shares were burned, but the actual transaction transferred 1010 units.

## Recommended Mitigation Steps

Modify the `_withdraw` function to use `assetsReceived` instead of `amountToUser` for the asset transfer to the user. This ensures that the correct amount is transferred to the user as intended in any case.
