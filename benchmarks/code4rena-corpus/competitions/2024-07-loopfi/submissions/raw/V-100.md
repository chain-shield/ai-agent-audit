# Vulnerability details

## Impact
When users call `PoolAction::transferAndJoin` to join a Balancer pool, the protocol transfers the `maxAmountsIn` of each token of the pool to the contract. However, when calling `_balancerJoin` and then calling `balancerVault.joinPool`, Balancer protocol transfers some amount that is `>= assetsIn[token] and <= maxAmountsIn[token]`. So the `PoolAction` could transfer some amount from the user, and send part of it to the Balancer vault, without sending the residual to the sender/recipient.

This causes the user's residual funds to be stuck in the `PoolAction` contract forever.

## Proof of Concept

Add the following test in `src/test/integration/PoolAction.t.sol`:

```solidity
function test_stuckFundsInPoolAction() public {
    uint256 amount = 10 ether;

    deal(wstETH, user, amount * 2);

    address[] memory tokens = new address[](3);
    tokens[0] = wstETH_bb_a_WETH_BPTl;
    tokens[1] = wstETH;
    tokens[2] = bbaweth;

    uint256[] memory maxAmountsIn = new uint256[](3);
    maxAmountsIn[0] = 0;
    maxAmountsIn[1] = amount * 2;
    maxAmountsIn[2] = 0;

    uint256[] memory tokensIn = new uint256[](2);
    tokensIn[0] = amount;
    tokensIn[1] = 0;

    vm.startPrank(user);

    // User holds 20 WSTETH
    // PoolAction holds 0 WSTETH
    assertEq(ERC20(wstETH).balanceOf(user), amount * 2);
    assertEq(ERC20(wstETH).balanceOf(address(poolAction)), 0);

    // Approve pool action to transfer WSTETH
    ERC20(wstETH).approve(address(poolAction), amount * 2);

    poolAction.transferAndJoin(
        user,
        new PermitParams[](3),
        PoolActionParams(Protocol.BALANCER, 0, user, abi.encode(poolId, tokens, tokensIn, maxAmountsIn))
    );

    // User holds 0 WSTETH
    // PoolAction holds 10 WSTETH
    // User holds > 10 ETH Balancer shares
    assertEq(ERC20(wstETH).balanceOf(user), 0);
    assertEq(ERC20(wstETH).balanceOf(address(poolAction)), amount);
    assertGt(ERC20(wstETH_bb_a_WETH_BPTl).balanceOf(user), amount);
}
```

## Tools Used

Manual review

## Recommended Mitigation Steps

After joining a Balancer pool, send the residual amounts to the recipient rather than keeping them in the `PoolAction` contract.
