# Vulnerability details

## Proof of Concept
The `setDqTime` function in the `EligibilityDataProvider` contract allows the `disqualifiedTime` for a user to be set to any arbitrary value passed as `_time`. This could lead to inaccurate disqualification tracking, as there is no restriction on setting the disqualification time to a future or past timestamp, which may not align with the actual time of the user's disqualification.
```solidity
   function setDqTime(address _user, uint256 _time) external {
        if (msg.sender != address(chef)) revert OnlyCIC();
        disqualifiedTime[_user] = _time; // @audit specify that _time is set to block.timestamp otherwise user's disqualifiedTime can be set to future or past time

        emit DqTimeUpdated(_user, _time);
    }
```
The purpose of this function is to update the `disqualifiedTime` for a user when they become ineligible for rewards. However, allowing `_time` to be set arbitrarily can result in scenarios where:

- The disqualification time is set to a future timestamp, delaying the user's disqualification and allowing them to receive rewards they should no longer be eligible for.
- The disqualification time is set to a past timestamp, inaccurately reflecting the user's disqualification time and potentially affecting reward calculations or historical tracking.
## Impact
If the disqualification time is set to a future timestamp, a user might continue to receive rewards despite being ineligible, leading to an unfair distribution of rewards and potentially impacting the protocol's integrity.

## Recommended Mitigation Steps
Modify the `setDqTime` function to enforce that `_time` is always set to the current block's timestamp. This ensures that the disqualification time accurately reflects the moment the function is called, preventing any manipulation.

```solidity
function setDqTime(address _user) external {
    if (msg.sender != address(chef)) revert OnlyCIC();
    _time = block.timestamp;
    disqualifiedTime[_user] = _time;

    emit DqTimeUpdated(_user, _time);
}

```
