# Vulnerability details

## Vulnerability details

`PoolAction#_repay` function use wrong `amount` to repay vault debt:

```solidity
function _repay(address vault, address position, CreditParams calldata creditParams, PermitParams calldata permitParams) internal {
    uint256 amount;
    if (creditParams.auxSwap.assetIn != address(0)) {
        if (creditParams.auxSwap.recipient != address(this)) revert PositionAction__repay_InvalidAuxSwap();

        amount = _transferAndSwap(creditParams.creditor, creditParams.auxSwap, permitParams);
    }
    ...

    // @audit - use `creditParams.amount` instead of amount to repay debt
    underlyingToken.forceApprove(address(vault), creditParams.amount);
    ICDPVault(vault).modifyCollateralAndDebt(
        position,
        address(this),
        address(this),
        0,
        -toInt256(creditParams.amount)
    );
}
```

As we can see, if `amount > creditParams.amount`, then the remained debt token in the pool proxy is `amount - creditParams.amount` after repaying the users's debt. Such that, malicious users can `deposit` then `borrow` some vault debt token, then call `PoolAction#repay` to repay his full debt token as the pool proxy has remained debt token by other users, then withdraw the collateral to gain profits, as the code use `creditParams.amount` instead of `amount` or not.


## Impact

Users would repay debt failed if `_transferAndSwap` less than `creditParams.amount`.
