# Vulnerability details

## Impact

I found precision loss in the debt calculation of [CDPVault](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L652):

- Impact is incorrect debt tracking, causing users to repay more or less debt than they actually owe. 

I wrote a poc to go through it, to show it happening like so: 
- Alice deposits 1 ETH as collateral, borrows 0.1 ETH.
- After about a year, Alice attempts to repay 0.01 ETH.
- Contract calculates that Alice still owes 0.11008 ETH instead of 0.1 ETH.

About 0.01008 ETH (or 1.008% of the original debt) is small, but it can accumulate over time and with larger debt amounts, opening users up to more losses for either the protocol or the users, depending on vector used. It can be mitigated, so this is good to mitigate, for more optimal price flow. 

## Proof of Concept

```solidity
function calcDecrease(
    uint256 amount,
    uint256 debt,
    uint256 cumulativeIndexNow,
    uint256 cumulativeIndexLastUpdate,
    uint128 cumulativeQuotaInterest
)
    internal
    pure
    returns (uint256 newDebt, uint256 newCumulativeIndex, uint256 profit, uint128 newCumulativeQuotaInterest)
{
    // in here
    if (amountToRepay != 0) {
        uint256 interestAccrued = CreditLogic.calcAccruedInterest({
            amount: debt,
            cumulativeIndexLastUpdate: cumulativeIndexLastUpdate,
            cumulativeIndexNow: cumulativeIndexNow
        });
        // All interest accrued on the base interest is taken by the DAO to be distributed to LP stakers, dLP stakers and the DAO
        if (amountToRepay >= interestAccrued) {
            amountToRepay -= interestAccrued;

            profit += interestAccrued;

            newCumulativeIndex = cumulativeIndexNow;
        } else {
            // If amount is not enough to repay interest, then send all to the stakers and update index
            profit += amountToRepay; // U:[CL-3]
            amountToRepay = 0; // U:[CL-3]

            newCumulativeIndex =
                (INDEX_PRECISION * cumulativeIndexNow * cumulativeIndexLastUpdate) /
                (INDEX_PRECISION *
                    cumulativeIndexNow -
                    (INDEX_PRECISION * profit * cumulativeIndexLastUpdate) /
                    debt); // U:[CL-3]
        }
    } else {
        newCumulativeIndex = cumulativeIndexLastUpdate;
    }
    newDebt = debt - amountToRepay;
}
```

So the reason the precision loss occurs, is due to integer division in the calculation of `newCumulativeIndex`. Opening up users to incorrect debt calculation over time.

## Recommended Mitigation Steps

To mitigate, opinionated version is to use Solmate's `FixedPointMathLib` for much higher-precision calculations. 

Updated version of [calcDecrease()](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L652):

```solidity
import {FixedPointMathLib} from "solmate/utils/FixedPointMathLib.sol";

function calcDecrease(
    uint256 amount,
    uint256 debt,
    uint256 cumulativeIndexNow,
    uint256 cumulativeIndexLastUpdate,
    uint128 cumulativeQuotaInterest
)
    internal
    pure
    returns (uint256 newDebt, uint256 newCumulativeIndex, uint256 profit, uint128 newCumulativeQuotaInterest)
{
    // rest is safe
    if (amountToRepay != 0) {
        uint256 interestAccrued = CreditLogic.calcAccruedInterest({
            amount: debt,
            cumulativeIndexLastUpdate: cumulativeIndexLastUpdate,
            cumulativeIndexNow: cumulativeIndexNow
        });
        
        if (amountToRepay >= interestAccrued) {
            amountToRepay -= interestAccrued;
            profit += interestAccrued;
            newCumulativeIndex = cumulativeIndexNow;
        } else {
            profit += amountToRepay;
            
            // Use FixedPointMathLib for high-precision calculations
            uint256 precision = 1e27;
            uint256 numerator = FixedPointMathLib.mulWadUp(cumulativeIndexNow, cumulativeIndexLastUpdate);
            uint256 denominator = FixedPointMathLib.mulWadUp(cumulativeIndexNow, precision) - 
                                  FixedPointMathLib.mulDivUp(profit, cumulativeIndexLastUpdate, debt);
            
            newCumulativeIndex = FixedPointMathLib.divWadUp(numerator, denominator);
            
            // Use small buffer to account for more precision loss
            newCumulativeIndex += 1;
            
            amountToRepay = 0;
        }
    } else {
        newCumulativeIndex = cumulativeIndexLastUpdate;
    }
    
    newDebt = debt - amountToRepay;
    
    // Add a small buffer to the new debt to prevent underestimation
    newDebt += 1;
}
```

Solmate's `FixedPointMathLib` can be used for high-precision calculations, this will help mitigate the precision loss issue. `mulWadUp`, `divWadUp`, and `mulDivUp` from `FixedPointMathLib` perform calculations with 18 decimal places of precision and round up, which helps prevent underestimation of debt.

Also, you can add small buffers to both `newCumulativeIndex` and `newDebt` to further guard against underestimations, due to any remaining precision loss.
