# Vulnerability details

## Impact
In `ChefIncentivesController` there is a `_massUpdatePools` function that calls the `_updatePool` function for the length of `registeredTokens`. This leads to the possibility of the block gas limit to be hit if `registeredTokens` array is big enough.

`_massUpdatePools` is used in `setRewardsPerSecond`, `_updateEmissions`, `registerRewardDeposit`, `batchUpdateAllocPoint` and `setScheduledRewardsPerSecond`. If this block gas limit is reached than all of this functionality will be unavailable and there is no way to delete registered tokens so it will be unavailable indefinitely.

A similar issue was validated in the Aura Finance contest as a Mid: https://solodit.xyz/issues/m-20-massupdatepools-is-susceptible-to-dos-with-block-gas-limit-code4rena-aura-finance-aura-finance-git

## Proof of Concept
https://consensys.github.io/smart-contract-best-practices/attacks/denial-of-service/#dos-with-block-gas-limit

## Tools Used
Manual Review

## Recommended Mitigation Steps
There are two solutions:
1. Add a way to remove registered tokens;
2. Limit the max number of loop iterations to prevent hitting block gas limit.
I would suggest implementing both as a mitigation.
