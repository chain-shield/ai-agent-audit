# Vulnerability details

## Vulnerability Details 
The natspec of the `_authorizeUpgrade()` function clearly states that it should revert if the oracle status check succeeds. The issue is that the function never checks the status of the oracle, it is empty.

```solidity
/// @notice Authorizes an upgrade
/// @param /*implementation*/ The address of the new implementation
/// @dev reverts if the caller is not a manager or if the status check succeeds
function _authorizeUpgrade(address /*implementation*/) internal virtual override onlyRole(MANAGER_ROLE) {} 
```

The devs have clearly implemented the `getStatus()` check in the 2 other oracles ([balancer](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/oracle/BalancerOracle.sol#L111) and [pendle](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/oracle/PendleLPOracle.sol#L85)) so it looks like they just forgot to implement it in the chainlink oracle.


## Impact
The contract can be upgraded inappropriately when a valid price is still available

## Recommended Mitigation Steps
Store an array of tokens that the oracle supports

Within the `_authorizeUpgrade()` function
iterate over the list and call getStatus(token) for each token, if all return true then revert, if at least one returns false then exit the function and continue the upgrade.

```solidity
address[] public tokenAddresses;

function _authorizeUpgrade(address /*implementation*/) internal virtual override onlyRole(MANAGER_ROLE) {
    for (uint i = 0; i < tokenAddresses.length; i++) {
        bool status = IToken(tokenAddresses[i]).getStatus();
        if (!status) {
            return; // Exit the function if any token's status is returning false
        }
    }
    // If we've made it through the entire loop, all statuses were valid
    revert("All token statuses are valid");
```
