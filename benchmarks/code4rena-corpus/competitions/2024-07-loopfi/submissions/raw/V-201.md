# Vulnerability details

## Proof of Concept
The `_lockedUsdValue` function in the `EligibilityDataProvider` contract converts the amount of locked LP tokens into their equivalent USD value using a price fetched from the `PriceProvider` contract. Here is the relevant code snippet:
```solidity
function _lockedUsdValue(uint256 lockedLP) internal view returns (uint256) {
    uint256 lpPrice = priceProvider.getLpTokenPriceUsd();
    return (lockedLP * lpPrice) / 10 ** 18;
}
```
The function retrieves the LP token price (`lpPrice`) from the `PriceProvider` and performs a calculation to convert `lockedLP` (the amount of locked LP tokens) into USD. The key issue here is that there is no check or validation on the `lpPrice` returned by `priceProvider.getLpTokenPriceUsd()`. The `PriceProvider` contract can use different oracles, such as the `UniV2TwapOracle`, which requires frequent updates to provide accurate prices. If these updates are not performed regularly, the `lpPrice` may be stale, leading to potentially incorrect calculations.

## Impact
Using outdated price data can lead to incorrect eligibility determinations. For example, a user might be incorrectly deemed eligible or ineligible for rewards based on stale pricing information, which could affect their ability to receive rewards and impact the fairness of the reward distribution.
## Tools Used
Manual
## Recommended Mitigation Steps
Ensure the price data used is up-to-date, you should call the `update` function of the `PriceProvider` contract before querying the `price`. Modify the `_lockedUsdValue` function to include a call to `update` as follows:
```solidity
function _lockedUsdValue(uint256 lockedLP) internal returns (uint256) {
    priceProvider.update();  // Ensure price data is updated
    uint256 lpPrice = priceProvider.getLpTokenPriceUsd();
    return (lockedLP * lpPrice) / 10 ** 18;
}
```
