# Vulnerability details


## Proof of Concept

When calculating the amount of AURA to distribute, [the `_previewMining` function gets called](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L340).

```solidity
function _previewMining(uint256 _amount) private view returns (uint256 amount) {
  uint256 supply = IERC20(AURA).totalSupply();
  uint256 minterMinted = 0; // Cannot fetch because private in AURA
  uint256 emissionsMinted = supply - INIT_MINT_AMOUNT - minterMinted;

  uint256 cliff = emissionsMinted / REDUCTION_PER_CLIFF;

  if (cliff < TOTAL_CLIFFS) {
    uint256 reduction = ((TOTAL_CLIFFS - cliff) * 5) / 2 + 700;
    amount = (_amount * reduction) / TOTAL_CLIFFS;
    uint256 amtTillMax = EMISSIONS_MAX_SUPPLY - emissionsMinted;
    if (amount > amtTillMax) {
      amount = amtTillMax;
    }
  }
}

```

This logic is accurate if the AURA tokens haven't been minted yet. However, a problem arises because AURA tokens are claimed for all vault participants whenever any user withdraws. This causes issues at _the end of each cliff_, as the emissions decrease and users can lose their rewards.

For example, if User A integrates with the vault, for e.g say deposits tokens into the vault and later withdraws/claims before the end of the first cliff, all rewards for both User A and other users will be claimed and stored in the contract, [via the call to `getReward()` when claiming](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/vendor/AuraVault.sol#L282). Now if another user, say User B, waits until the second cliff ends before withdrawing, the contract will incorrectly calculate User B's rewards as zero because all cliffs have ended, despite rewards being already stored in the contract.

## Impact

The incorrect calculation of AURA distribution across cliffs can lead to significant loss of rewards for users, especially for those who withdraw after the final cliff. Users who delay withdrawal past certain emission points may receive less than their expected share of rewards, causing a loss in expected returns.

## Recommended Mitigation Steps

To prevent the loss of rewards, the reward per token should be cached at the time of claims/withdrawal to ensure that rewards already accumulated in the contract are properly accounted for. Only the unminted AURA should be subject to emission reduction logic, ensuring that all users receive the correct amount of rewards regardless of when they withdraw.
