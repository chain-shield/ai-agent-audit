# Vulnerability details

## Impact
Smart contract will work with incorrect stale price


## Proof of Concept
The `updatedAt` timestamp in `AuraVault.sol` is commented out and not checked for price staleness. This can lead to using stale incorrect price.

Note that this has not been reported by the [4naly3er report](https://github.com/code-423n4/2024-07-loopfi/blob/main/4naly3er-report.md#m-4-chainlinks-latestrounddata-might-return-stale-or-incorrect-results) but a similar issue that was reported did not include this line but it only talks about the roundid which did not even include this line that I reported below.

```solidity
function _chainlinkSpot() private view returns (uint256 price) {
        bool isValid;
        try AggregatorV3Interface(BAL_CHAINLINK_FEED).latestRoundData() returns (
            uint80 /*roundId*/,
            int256 answer,
            uint256 /*startedAt*/,
371 @>      uint256 /*updatedAt*/,
            uint80 /*answeredInRound*/
        ) {
            price = wdiv(uint256(answer), BAL_CHAINLINK_DECIMALS);
            isValid = (price > 0);
        } catch {}

        if (!isValid) revert AuraVault__chainlinkSpot_invalidPrice();
    }

```

## Recommended Mitigation Steps
Consider validating the `updateAt` timestamp instead of commenting it out in the AuraVault.sol

```diff
function _chainlinkSpot() private view returns (uint256 price) {
        bool isValid;
        try AggregatorV3Interface(BAL_CHAINLINK_FEED).latestRoundData() returns (
            uint80 /*roundId*/,
            int256 answer,
            uint256 /*startedAt*/,
--          uint256 /*updatedAt*/,
++          uint256 updatedAt,
            uint80 /*answeredInRound*/
        ) {
++          require(block.timestamp >= updateAt + 86400, "Stale price");//BAL/USD heartbeat is 86400
            price = wdiv(uint256(answer), BAL_CHAINLINK_DECIMALS);
            isValid = (price > 0);
        } catch {}

        if (!isValid) revert AuraVault__chainlinkSpot_invalidPrice();
    }
```
