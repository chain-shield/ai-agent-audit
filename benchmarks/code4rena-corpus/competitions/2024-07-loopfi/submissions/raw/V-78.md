# Vulnerability details

## Impact

The `PositionAction` contract is an implementation contract for a router-like proxy contract, which provides an interface for users to interact with the LoopFi `CDPVaults`, as inferred from the [developer note](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/PositionAction.sol#L57-L60). LoopFi users who set infinite approvals or have leftover approvals after transactions with the contract are at risk of losing funds. This happens because attackers can exploit these approvals to gain unauthorized access to their wallets.

## Proof of Concept

Alice has granted the LoopFi proxy infinite approval to spend her Yield Bearing tokens, as she wants to leverage her yield. An attacker's then see's an exploits this by calling the deposit function on the contract with the following parameters:

```solidity
CollateralParams payload1;
PermitParams payload2;
payload1 = CollateralParams({
  targetToken: 0x2c....,   
  amount: 50e18, 
  collateralizer: Alice_Address, 
  SwapParams: null        
});
payload2 = null;
deposit(CDPVault, ATTACKER_ADDRESS, payload1, payload2);
```
The attacker has used Alice's tokens as collateral for his CDPVault position he can then proceed to withdraw these tokens.
## Vulnerable Code
```solidity
    function _deposit(
        address vault,
        address position,
        CollateralParams calldata collateralParams,
        PermitParams calldata permitParams
    ) internal returns (uint256) {
        uint256 amount = collateralParams.amount;

        if (collateralParams.auxSwap.assetIn != address(0)) {
            if (
                collateralParams.auxSwap.assetIn != collateralParams.targetToken ||
                collateralParams.auxSwap.recipient != address(this)
            ) revert PositionAction__deposit_InvalidAuxSwap();
            amount = _transferAndSwap(collateralParams.collateralizer, collateralParams.auxSwap, permitParams);
        } else if (collateralParams.collateralizer != address(this)) {
            _transferFrom(
                collateralParams.targetToken,
                collateralParams.collateralizer,
                address(this),
                amount,
                permitParams
            );
        }

        return _onDeposit(vault, position, collateralParams.targetToken, amount);
    }

  function _onDeposit(address vault, address position, address /*src*/, uint256 amount) internal override returns (uint256) {
        address collateralToken = address(ICDPVault(vault).token());
        IERC20(collateralToken).forceApprove(vault, amount);
        return ICDPVault(vault).deposit(position, amount);
    }
```

## Recommended Mitigation Steps

Perform a check that the collateralizer is the msg.sender:

```solidity
function deposit(
    address position,
    address vault,
    CollateralParams calldata collateralParams,
    PermitParams calldata permitParams
) external onlyRegisteredVault(vault) onlyDelegatecall {
    // Ensure the caller is the specified collateralizer
    require(collateralParams.collateralizer == msg.sender || address(this), "Caller is not the collateralizer");
    _deposit(vault, position, collateralParams, permitParams);
}
```
The contract now ensures that the msg.sender is the collateralizer and therefore this will prevent unauthorized users to access tokens in the wallets of honest LoopFi users who have set approvals.
