# Vulnerability details

## Impact
By front-running any collateral allocation or position closure of a legitimate user that became under-collateralized during the paused state, liquidators can unfairly liquidate user positions and collect liquidation profit as soon as the protocol is unpaused. This causes a loss of funds to the user. Additionally, on unpause, it is unlikely that any human users will be able to secure their positions before MEV (Miner Extractable Value) or liquidation bots capture the available profit, making the loss certain.

## Proof of Concept

### Pause the Protocol:
Privileged addresses can pause the protocol, preventing users from performing critical operations like depositing more collateral or closing positions.
```solidity
 modifier whenPaused() {
        _requirePaused();
        _;
    }
 function _requirePaused() internal view virtual {
        require(paused(), "Pausable: not paused");
    }

```
### Price Movement During Pause

Oracle prices continue to move during the paused state, potentially causing positions to become under-collateralized.

```solidity
 function spotPrice() public view returns (uint256) {
        return oracle.spot(address(token));
    }
```

### Unpause the Protocol

When the protocol is unpaused, liquidators can immediately front-run users and liquidate their positions.

```solidity
modifier whenNotPaused() {
        _requireNotPaused();
        _;
    }

function _requireNotPaused() internal view virtual {
        require(!paused(), "Pausable: paused");
    }
}
```
### Liquidation Front-Running

Liquidators can call the `liquidatePosition` function before users have a chance to make their positions healthy:

```solidity
    function liquidatePosition(address owner, uint256 repayAmount) external whenNotPaused {
 // Function logic...
}
```

### Example Scenario

1. The protocol is paused due to an emergency.
2. During the pause, the price of the collateral drops, causing some positions to become under-collateralized.
3. The protocol is unpaused by a privileged account.
4. Liquidators immediately call `liquidatePosition` to liquidate the under-collateralized positions before users can add more collateral or close their positions.

## Recommended Mitigation Steps
### Grace Period After Unpause

Implement a grace period after unpausing the protocol during which liquidations are not allowed. This gives users time to make their positions healthy.
