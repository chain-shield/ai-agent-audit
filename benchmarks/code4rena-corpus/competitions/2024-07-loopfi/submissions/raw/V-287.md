# Vulnerability details

## Description

The `PoolV3` contract implements an ERC-4626 compatible lending and borrowing pool. Two important functions, [`withdraw()`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L292-L309) and [`redeem()`](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L316-L333), allow users to withdraw assets or redeem shares for underlying tokens. These functions are designed to apply a withdrawal fee to the amount being withdrawn or redeemed.

However, the current implementation contains a logical error in the order of fee calculations. The withdrawal fee is not correctly subtracted from the total amount before other fee calculations are applied. This leads to users receiving incorrect amounts of tokens, either more or less than expected.

In the `withdraw()` function, the issue occurs in the following lines:

```solidity
File: PoolV3.sol
305:         uint256 assetsToUser = _amountWithFee(assets);
306:         uint256 assetsSent = _amountWithWithdrawalFee(assetsToUser); // U:[LP-8]

```

Here, `_amountWithFee()` is applied before `_amountWithWithdrawalFee()`, which is incorrect. The withdrawal fee should be applied first.

Similarly, in the `redeem()` function:

```solidity
File: PoolV3.sol
329:         uint256 assetsSent = _convertToAssets(shares); // U:[LP-9]
330:         uint256 assetsToUser = _amountMinusWithdrawalFee(assetsSent);
331:         assets = _amountMinusFee(assetsToUser); // U:[LP-9]

```

The order of applying `_amountMinusWithdrawalFee()` and `_amountMinusFee()` may lead to incorrect calculations.

This issue affects all users who attempt to withdraw assets or redeem shares, potentially causing financial losses or unintended gains.

## Impact

The incorrect fee calculation in `withdraw()` and `redeem()` functions will result in users receiving incorrect amounts of tokens. This discrepancy can lead to financial losses for users if they receive fewer tokens than expected, or unintended gains if they receive more.



## Proof of Concept

1. Alice decides to withdraw 1000 tokens from the pool.
2. Alice calls `withdraw(1000, alice, alice)`.
3. The function calculates `assetsToUser = _amountWithFee(1000)`, which might return 990 (assuming a 1% fee).
4. Then it calculates `assetsSent = _amountWithWithdrawalFee(990)`, which might return 1000 (assuming a 1% withdrawal fee).
5. Alice receives 990 tokens instead of the correct amount of 980.4 tokens (1000 * 0.99 * 0.99).

Similarly for the `redeem()` function:

1. Bob decides to redeem 1000 shares.
2. Bob calls `redeem(1000, bob, bob)`.
3. The function calculates `assetsSent = _convertToAssets(1000)`, which might return 1000.
4. Then it calculates `assetsToUser = _amountMinusWithdrawalFee(1000)`, which might return 990.
5. Finally, it calculates `assets = _amountMinusFee(990)`, which might return 980.1.
6. Bob receives 980.1 tokens instead of the correct amount of 970.3 tokens (1000 * 0.99 * 0.98).

## Recommended Mitigation Steps

To fix this issue, the order of fee calculations in both `withdraw()` and `redeem()` functions should be adjusted. The withdrawal fee should be applied first, followed by any other fees. Here's the recommended fix:

For the `withdraw()` function:

```diff
function withdraw(
    uint256 assets,
    address receiver,
    address owner
) public override(ERC4626, IERC4626) returns (uint256 shares) {
-   uint256 assetsToUser = _amountWithFee(assets);
-   uint256 assetsSent = _amountWithWithdrawalFee(assetsToUser);
+   uint256 assetsSent = _amountWithWithdrawalFee(assets);
+   uint256 assetsToUser = _amountMinusFee(assetsSent);
    shares = _convertToShares(assetsSent);
    _withdraw(receiver, owner, assetsSent, assets, assetsToUser, shares);
}
```

For the `redeem()` function:

```diff
function redeem(
    uint256 shares,
    address receiver,
    address owner
) public override(ERC4626, IERC4626) returns (uint256 assets) {
    uint256 assetsSent = _convertToAssets(shares);
-   uint256 assetsToUser = _amountMinusWithdrawalFee(assetsSent);
-   assets = _amountMinusFee(assetsToUser);
+   uint256 assetsWithWithdrawalFee = _amountMinusWithdrawalFee(assetsSent);
+   assets = _amountMinusFee(assetsWithWithdrawalFee);
+   uint256 assetsToUser = assets;
    _withdraw(receiver, owner, assetsSent, assets, assetsToUser, shares);
}
```

These changes ensure that the withdrawal fee is applied first, followed by any other fees, resulting in correct token amounts being sent to users.
