# Vulnerability details

## Impact
The `PendleLPOracle` contract uses the UUPS (Universal Upgradeable Proxy Standard) pattern, which allows for contract upgrades. However, the current implementation of the `_authorizeUpgrade` function has a potential vulnerability that could lead to unauthorized upgrades.

If an attacker can manipulate the `_getStatus` function to return false, and if they gain access to an account with the `MANAGER_ROLE`, they could potentially upgrade the contract to a malicious implementation. This could result in:

1. Complete control over the oracle's functionality
2. Manipulation of price data
3. Theft of funds that rely on this oracle for pricing
4. Disruption of the entire system that depends on this oracle

The impact is severe as it could compromise the integrity and security of the entire protocol that relies on this oracle.

## Proof of Concept
The vulnerable code is in the `_authorizeUpgrade` function:

```solidity
function _authorizeUpgrade(address /*implementation*/) internal override virtual onlyRole(MANAGER_ROLE){
    if(_getStatus()) revert PendleLPOracle__authorizeUpgrade_validStatus();
}
```

An attacker with the `MANAGER_ROLE` could exploit this if they can make `_getStatus()` return false. The `_getStatus` function relies on `_fetchAndValidate` and `_validatePtOracle`, which both have error handling that could potentially be exploited:

```solidity
function _fetchAndValidate() internal view returns (bool isValid, uint256 price) {
    try AggregatorV3Interface(aggregator).latestRoundData() returns (
        uint80 roundId, int256 answer, uint256 /*startedAt*/, uint256 updatedAt, uint80 answeredInRound
    ) {
        isValid = (answer > 0 && answeredInRound >= roundId && block.timestamp - updatedAt <= stalePeriod);
        return (isValid, wdiv(uint256(answer), aggregatorScale));
    } catch {
        // return the default values (false, 0) on failure
    }
}
```

```solidity
function _validatePtOracle() internal view returns (bool isValid) {
    try ptOracle.getOracleState(address(market), twapWindow) returns (
        bool increaseCardinalityRequired,
        uint16,
        bool oldestObservationSatisfied
    ) {
        if(!increaseCardinalityRequired && oldestObservationSatisfied) return true; 
    } 
    catch {
        // return default value on failure
    }
}
```

## Recommended Mitigation Steps
1. Implement a timelock mechanism for upgrades to allow for community review of proposed upgrades.
2. Add additional checks in the `_authorizeUpgrade` function beyond just the `_getStatus` check.
3. Implement a multi-signature requirement for upgrades, involving multiple trusted parties.
4. Improve error handling in `_fetchAndValidate` and `_validatePtOracle` to ensure they can't be easily manipulated to return false.
5. Consider implementing an upgradability governance system where upgrades need to be proposed and voted on by stakeholders.
6. Add extensive logging for any attempted upgrades, successful or not, to aid in monitoring and quick response to any suspicious activities.
