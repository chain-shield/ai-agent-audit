# Vulnerability details

## Summary:

The function _modifyPosition is susceptible to an underflow issue when updating the global debt balance if the new debt value is less than the current debt and the difference exceeds the current total debt.

## Description:

The _modifyPosition function updates a position's debt and collateral and subsequently adjusts the global debt balance. When newDebt is less than currentDebt, the function computes the total debt as follows:

```
if (newDebt > currentDebt) {
    totalDebt_ = totalDebt_ + (newDebt - currentDebt);
} else {
    totalDebt_ = totalDebt_ - (currentDebt - newDebt);
}
```
If the difference between currentDebt and newDebt is greater than totalDebt_, this will result in an underflow, leading to an incorrect and potentially very large total debt value.

## Impact:

  * Incorrect Total Debt: The total debt could become incorrectly large due to underflow, which can lead to miscalculations in related logic, such as debt-to-collateral ratios or interest computations.
  * Security Risks: Incorrect total debt values can impact calculations for financial products, potentially leading to security vulnerabilities, incorrect interest calculations, or exploitability in financial contracts.

## Root Cause:

The root cause of the underflow issue is the subtraction operation when currentDebt is greater than newDebt. If the difference between these values is greater than totalDebt_, it results in an underflow. For example, if totalDebt_ is 100 ether and the debt difference is 150 ether, the subtraction would lead to an underflow, producing a very large number due to uint256 wrapping.

## Proof of Concept:

```
// Define the initial state
uint256 initialTotalDebt = 100 ether;
uint256 currentDebt = 200 ether; // This is intentionally set to be greater than totalDebt_
uint256 newDebt = 50 ether; // This is less than currentDebt

// Simulate the total debt update
uint256 updatedTotalDebt = initialTotalDebt;

if (newDebt > currentDebt) {
    updatedTotalDebt = updatedTotalDebt + (newDebt - currentDebt);
} else {
    updatedTotalDebt = updatedTotalDebt - (currentDebt - newDebt);
}

// Log the result
console.log("Initial Total Debt:", initialTotalDebt);
console.log("Updated Total Debt:", updatedTotalDebt); // This will result in an incorrect large value due to underflow

In the above code:

    initialTotalDebt is set to 100 ether.
    currentDebt is set to 200 ether, which is greater than initialTotalDebt.
    newDebt is 50 ether, which is less than currentDebt.

Running this code would show that updatedTotalDebt becomes a very large value due to the underflow.
```
## Recommended Mitigation:

 * Prevent Underflow: Use safe math operations to prevent underflow:

```

    // Safely update the total debt
    if (newDebt > currentDebt) {
        totalDebt_ = totalDebt_ + (newDebt - currentDebt);
    } else {
        require(totalDebt_ >= (currentDebt - newDebt), "Total debt underflow");
        totalDebt_ = totalDebt_ - (currentDebt - newDebt);
    }
```
