# Vulnerability details

## Proof of Concept
In the `afterLockUpdate` function, the boolean parameter `_execute` is always passed as `true` when calling the `_processEligibility` function. This could lead to unintended consequences in user eligibility management. Below is the relevant code snippet:
```solidity
function afterLockUpdate() external {
    // Other logic...
    _processEligibility(true);
    // Other logic...
}

    function _processEligibility(
        address _user,
        bool _isEligible,
        bool _execute
    ) internal returns (bool issueBaseBounty) {
        bool hasEligDeposits = hasEligibleDeposits(_user);
        uint256 lastDqTime = eligibleDataProvider.getDqTime(_user);
        bool alreadyDqd = lastDqTime != 0;

        if (!_isEligible && hasEligDeposits && !alreadyDqd) {
            issueBaseBounty = true;
        }
        if (_execute && issueBaseBounty) {
            stopEmissionsFor(_user);
            emit Disqualified(_user);
        }
    }
```
The [_processEligibility](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L735-L751) function is designed to manage user eligibility by checking if a user is not currently eligible (`!user.isEligible`), has eligible deposits (`user.hasEligibleDeposits`), and has not already been disqualified (`!alreadyDqd`). If these conditions are met, `issueBaseBounty` is set to true.

Since `_execute` is always passed as true by `afterLockUpdate`, this triggers the `_stopEmissionForUser` function for any user meeting the initial conditions, regardless of whether stopping emissions is genuinely required based on their current status.
The purpose of `afterLockUpdate` is likely to update or validate certain conditions after a lock or specific event has occurred. The intent behind `_processEligibility` is to dynamically manage user eligibility, ensuring that only users who genuinely meet disqualification criteria have their emissions stopped.
However, because `_execute` is always set to `true`, it forces the disqualification logic (`_stopEmissionForUser`) to be executed, potentially stopping emissions for users who should still be eligible.

## Impact
The constant passing of `true` to `_processEligibility` function call within the `afterLockUpdate` function can cause users to be disqualified and have their emissions stopped unintentionally. This may lead to users being unfairly penalized, missing out on rewards or other benefits they were otherwise eligible to receive, which could result in loss of trust in the system and possible financial impact.

## Recommended Mitigation Steps
By passing `isCurrentlyEligible` and a `bool` flag to `_processEligibility` within the `afterLockUpdate`, you can ensure that the function evaluates the user's eligibility based on their current status, which can prevent the universal disqualification issue.
