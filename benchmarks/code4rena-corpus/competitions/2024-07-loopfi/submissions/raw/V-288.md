# Vulnerability details

## Impact
Detailed description of the impact of this finding.

This issue affects the ability to accurately diagnose and understand the causes of failures in delegatecall. 

When a delegatecall fails, the returnData might not contain a properly formatted error message, which can lead to misleading error reporting by reverting with a generic error message. 

This behaviour could make debugging more challenging and obscure the original reason for the failure, potentially hiding critical errors that require attention.

***Use Case***
A similar issue occurred with OpenZeppelin’s Proxy contracts in the past, where inadequate error reporting from delegate calls led to confusion and difficulty in diagnosing failures during deployment. 

OpenZeppelin addressed these issues by improving error handling and revert messages, allowing developers to better understand and react to the causes of failure.

## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

***1.	Function Definition:***
The _delegateCall function is defined as follows:
```sol
    function _delegateCall(address to, bytes memory data) internal returns (bytes memory) {
        (bool success, bytes memory returnData) = to.delegatecall(data);
        if (!success) _revertBytes(returnData);
        return returnData;
    }
```

***2.	Error Handling:***
The _revertBytes function is called when the delegatecall fails. It uses assembly to revert with a message:
```sol
    function _revertBytes(bytes memory errMsg) internal pure {
        if (errMsg.length != 0) {
            assembly {
                revert(add(32, errMsg), mload(errMsg))
            }
        }
        revert Action__revertBytes_emptyRevertBytes();
    }
```

***3.	Problematic Scenario:***
	•	If delegatecall fails but does not return a well-formed revert message, errMsg will be empty or improperly formatted.
	•	This causes the function to revert with the default error Action__revertBytes_emptyRevertBytes(), rather than the original error message, if any.

***In Remix IDE call the following function***
```solidity
_delegateCall(address(0x0000000000000000000000000000000000000000),bytes("0x0000000000000000000000000000000000000000"));
```

## Recommended Mitigation Steps
To mitigate this issue, improve the handling of the returnData to provide more context when the delegatecall fails:

1.	Check for Empty Return Data:
Before passing returnData to _revertBytes, verify whether it contains a valid error message:
```sol
function _delegateCall(address to, bytes memory data) internal returns (bytes memory) {
    (bool success, bytes memory returnData) = to.delegatecall(data);
    if (!success) {
        if (returnData.length == 0) {
            revert("Delegatecall failed: no revert message provided");
        }
        _revertBytes(returnData);
    }
    return returnData;
}
```

2.	Log Detailed Error Information:
Consider logging additional details about the delegatecall, such as the target address and calldata, to provide more context about the failure:
```sol
function _delegateCall(address to, bytes memory data) internal returns (bytes memory) {
    (bool success, bytes memory returnData) = to.delegatecall(data);
    if (!success) {
        emit DelegatecallFailed(to, data, returnData); // Emit an event for easier tracking
        if (returnData.length == 0) {
            revert("Delegatecall failed: no revert message provided");
        }
        _revertBytes(returnData);
    }
    return returnData;
}

event DelegatecallFailed(address indexed target, bytes data, bytes returnData);
```
