# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The use of _amountWithFee and _amountWithWithdrawalFee in the withdraw function suggests that fees are being applied in two steps. 

This might lead to confusion regarding whether multiple fees are being applied correctly or if one function is meant to adjust for transaction fees and the other for withdrawal-specific fees. 

This confusion can result in incorrect fee calculations and impact the amount users receive during withdrawals.
## Proof of Concept
Provide direct links to all referenced code in GitHub. Add screenshots, logs, or any other relevant proof that illustrates the concept.

In the withdraw function, the amount to be sent to the user is calculated using two separate functions for fee application:
```sol
uint256 assetsToUser = _amountWithFee(assets);
uint256 assetsSent = _amountWithWithdrawalFee(assetsToUser);
```

The _amountWithFee function currently returns the amount without modification:
```sol
function _amountWithFee(uint256 amount) internal view virtual returns (uint256) {
    return amount;
}
```

The _amountWithWithdrawalFee function applies a fee based on the withdrawFee:
```sol
function _amountWithWithdrawalFee(uint256 amount) internal view returns (uint256) {
    return (amount * PERCENTAGE_FACTOR) / (PERCENTAGE_FACTOR - withdrawFee);
}
```

Given the current implementation of _amountWithFee, it does not alter the amount, leading to redundant operations. 

If _amountWithFee is intended to eventually include a separate fee, the current logic could lead to confusion over the actual fees applied.

Manual review.
## Recommended Mitigation Steps
Clarify Fee Functions: 
Ensure that each function’s purpose is well-documented and their names reflect their specific role in the fee process. 

If _amountWithFee is intended to apply a different type of fee, implement it accordingly; otherwise, consider removing or refactoring it for clarity.

Single Point of Fee Calculation: 
Consider consolidating fee calculations into a single function that clearly documents all fees being applied, making it easier to manage and verify correctness.
