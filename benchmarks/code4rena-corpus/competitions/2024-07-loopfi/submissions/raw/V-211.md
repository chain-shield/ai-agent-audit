# Vulnerability details

## Proof of Concept
The `vestTokens` function in the `MultiFeeDistribution` contract contains a discrepancy between its documented behavior and actual implementation regarding the application of penalties on vested tokens. The function's comment suggests that vested tokens incur a 50% penalty when withdrawn before the vesting duration has passed. However, the implementation does not apply any penalty at the time of vesting, instead deferring all penalty calculations to the withdrawal process.
Here's the relevant code snippet:
```solidity
/**
 * @notice Add to earnings
 * @dev Minted tokens receive rewards normally but incur a 50% penalty when
 *  withdrawn before vestDuration has passed.
 * @param user vesting owner.
 * @param amount to vest.
 * @param withPenalty does this bear penalty?
 */
function vestTokens(address user, uint256 amount, bool withPenalty) external whenNotPaused {
    if (!minters[msg.sender]) revert InsufficientPermission();
    if (amount == 0) return;

    // ... (other checks)

    Balances storage bal = _balances[user];
    bal.total = bal.total + amount;
    if (withPenalty) {
        bal.earned = bal.earned + amount;
        LockedBalance[] storage earnings = _userEarnings[user];

        // ... (code for adding to or creating new LockedBalance)
    } else {
        bal.unlocked = bal.unlocked + amount;
    }
}
```
The function adds the full `amount` to `bal.total` and `bal.earned` (when `withPenalty` is `true`) without applying any penalty. This contradicts the function's documentation and could lead to unexpected behavior in the contract's vesting mechanism.

## Impact
Users may receive full rewards on the entire vested amount, even for portions that should be subject to penalties. This could result in an unfair distribution of rewards and potentially allow users to circumvent intended vesting restrictions, leading to economic imbalances within the protocol.

## Recommended Mitigation Steps
Modify the `vestTokens` function to apply a 50% penalty when `withPenalty` is `true`. This would align with the current documentation:
```solidity
function vestTokens(address user, uint256 amount, bool withPenalty) external whenNotPaused {
    // ... (existing checks)

    Balances storage bal = _balances[user];
    if (withPenalty) {
        uint256 penaltyAmount = amount / 2;
        uint256 vestedAmount = amount - penaltyAmount;
        bal.total = bal.total + vestedAmount;
        bal.earned = bal.earned + vestedAmount;
        // ... (add vestedAmount to LockedBalance)
    } else {
        bal.total = bal.total + amount;
        bal.unlocked = bal.unlocked + amount;
    }
}
```
