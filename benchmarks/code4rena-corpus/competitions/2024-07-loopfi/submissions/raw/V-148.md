# Vulnerability details

## Impact
If chainlink aggregators fail to update price data at the period that prices of collateral are rapidly falling, liquidations will revert this will lead to the protocol becoming insolvent with a lot of bad debt.

## Proof of Concept
The major issue here is that the `spot()` function of ChainlinkOracle.sol reverts when the price is stale instead of using a fallback oracle. The spot function is used in the liquidation functions and in the event that the Chainlink aggregators fail to update price at the time prices are dropping rapidly, all liquidations will revert due to the staleness check that reverts in the `spot()` function when price is stale.

This makes liquidations imposible when Chainlink aggregators fail to update prices on time due to the revert in the `spot()` function. Consider a better design of using another oracle for example Uniswap TWAP whenever chainlink prices are stale instead of reverting.

function spot(address token) external view virtual override returns (uint256 price) {
        bool isValid;
        (isValid, price) = _fetchAndValidate(token);
        if (!isValid) revert ChainlinkOracle__spot_invalidValue();
    }

    /// @notice Fetches and validates the latest price from Chainlink
    /// @return isValid Whether the price is valid based on the value range and staleness
    /// @return price Asset price [WAD]
    function _fetchAndValidate(address token) internal view returns (bool isValid, uint256 price) {
        Oracle memory oracle = oracles[token];
        try AggregatorV3Interface(oracle.aggregator).latestRoundData() returns (
            uint80 /*roundId*/,
            int256 answer,
            uint256 /*startedAt*/,
            uint256 updatedAt,
            uint80 /*answeredInRound*/
        ) {
            isValid = (answer > 0 && block.timestamp - updatedAt <= oracle.stalePeriod);
            return (isValid, wdiv(uint256(answer), oracle.aggregatorScale));
        } catch {
            // return the default values (false, 0) on failure
        }
    }

## Recommended Mitigation Steps
Consider implementing a fallback price oracle for when Chainlink prices are stale instead of reverting. You can consider using Uniswaps TWAP oracle as a fallback instead of reverting when Chainlink price is stale.
