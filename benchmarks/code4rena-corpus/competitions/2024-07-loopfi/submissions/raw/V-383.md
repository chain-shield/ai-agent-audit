# Vulnerability details

In the FlashLender contract, the transferFrom() function's return value is not being checked to confirm the success of the token transfer. This is a significant oversight, as the function returns a boolean indicating whether the transfer was successful. 

Some ERC20 tokens do not revert the transaction when a transfer fails; instead, they return false. If these return values are not checked, the contract might incorrectly assume that the transfer was successful, even when it wasn't. This can lead to situations where the contract treats failed transfers as successful ones.


## Impact

This vulnerability allows users to potentially exploit the system by avoiding repayment of their flash loans. If a transfer fails but is still counted as successful by the contract, users could escape their repayment obligations, leading to financial losses for the protocol.

## Recommended Mitigation Steps


Ensure that the return value of all transferFrom() calls is checked to confirm successful transfers. Alternatively, use OpenZeppelin's SafeERC20’s safeTransferFrom() function.
