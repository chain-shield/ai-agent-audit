# Vulnerability details

**Description:**
In both the `flashLoan()` and `creditFlashLoan()` functions, there is no validation for the `amount` parameter. This oversight can lead to potential issues, such as zero-value loans, which may not be intended or desirable within the contract's logic.

**Functions Affected:**
- `flashLoan()`
- `creditFlashLoan()`

**Code Snippet:**
```solidity
function flashLoan( 
   ...
) external override nonReentrant returns (bool) {
    if (token != address(underlyingToken)) revert Flash__flashLoan_unsupportedToken();
    uint256 fee = wmul(amount, protocolFee);
    uint256 total = amount + fee;  //@audit-issue zero-value loans

...
    pool.repayCreditAccount(total - fee, fee, 0); 

    return true;
}

function creditFlashLoan(
   ...
) external override nonReentrant returns (bool) {
    uint256 fee = wmul(amount, protocolFee);
    uint256 total = amount + fee; //@audit-issue zero-value loans
...
    pool.repayCreditAccount(total - fee, fee, 0);

    return true;
}
```

## Recommended Mitigation Steps

- **Input Validation:** Add a check to ensure that the `amount` parameter is greater than zero. This will prevent zero-value loans and ensure that the contract behaves as expected.

```
require(amount > 0, "Invalid loan amount");

```
