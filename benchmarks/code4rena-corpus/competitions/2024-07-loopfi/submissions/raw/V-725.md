# Vulnerability details

## Impact
The mintProfit function, which mints new tokens to the treasury based on a specified amount, does not include a check to ensure that the treasury address is not the zero address. If the treasury address is ever mistakenly set to the zero address, calling mintProfit could result in the accidental minting of tokens to the zero address, effectively burning them permanently.

```
function mintProfit(uint256 amount) external creditManagerOnly {
    _mint(treasury, amount);

    _updateBaseInterest({
        expectedLiquidityDelta: amount.toInt256(),
        availableLiquidityDelta: 0,
        checkOptimalBorrowing: false
    });
}
```


Zero-Address Risk: There is no validation to ensure that the treasury address is not set to the zero address. If this occurs, tokens intended for the treasury could be irretrievably lost.

Unrecoverable Loss: If tokens are minted to the zero address, they are effectively burned and cannot be recovered, leading to a direct financial loss for the protocol.



## Proof of Concept

Due to a configuration error, the treasury address is set to the zero address.
A credit manager calls mintProfit, intending to mint tokens to the treasury.
However, because the treasury address is the zero address, the tokens are instead sent to the zero address and lost permanently.


```
// Configuration error sets treasury to the zero address
PoolV3 pool = new PoolV3(...);
pool.setTreasury(address(0));

// Subsequent calls to mintProfit burn tokens unintentionally
pool.mintProfit(1e18);
```
Tokens that should have been allocated to the treasury are instead burned, reducing the protocol's assets and potentially impacting its financial stability.


Impact
Financial Loss: Tokens intended for the treasury are irretrievably lost, reducing the protocol's overall assets and financial health.
Operational Risk: If this issue is not caught immediately, it could result in significant financial damage over time, particularly if mintProfit is called frequently.

## Recommended Mitigation Steps

Add a Zero-Address Check: Implement a check in the mintProfit function to ensure that the treasury address is not the zero address before proceeding with the minting operation.

```
function mintProfit(uint256 amount) external creditManagerOnly {
    require(treasury != address(0), "Treasury address cannot be zero");
    _mint(treasury, amount);

    _updateBaseInterest({
        expectedLiquidityDelta: amount.toInt256(),
        availableLiquidityDelta: 0,
        checkOptimalBorrowing: false
    });
}
```
