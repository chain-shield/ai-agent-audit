# Vulnerability details

## Proof of Concept
In the `batchUpdateAllocPoint` function, the allocation points for multiple pools can be updated within a single transaction. The function is intended to correctly calculate and update the `totalAllocPoint` variable, which represents the sum of allocation points across all pools. However, if the updates for multiple pools are not correctly managed, the `totalAllocPoint` value may not accurately reflect the sum of the allocation points after the updates.

Consider the following code snippet illustrating the issue:
```solidity

    function batchUpdateAllocPoint(address[] calldata _tokens, uint256[] calldata _allocPoints) external onlyOwner {
        if (_tokens.length != _allocPoints.length) revert ArrayLengthMismatch();
        _massUpdatePools();
        uint256 _totalAllocPoint = totalAllocPoint;
        uint256 length = _tokens.length;
        for (uint256 i; i < length; ) {
            VaultInfo storage pool = vaultInfo[_tokens[i]];
            if (pool.lastRewardTime == 0) revert UnknownPool();
            _totalAllocPoint = _totalAllocPoint - pool.allocPoint + _allocPoints[i];
            pool.allocPoint = _allocPoints[i];
            unchecked {
                i++;
            }
        }
        totalAllocPoint = _totalAllocPoint;
        emit BatchAllocPointsUpdated(_tokens, _allocPoints);
    }
```
In this function, `_totalAllocPoint` is updated iteratively for each pool by subtracting the previous allocation points and adding the new allocation points. However, if the updates for multiple pools occur sequentially, there is a potential inconsistency in the final `totalAllocPoint` value.

For Example: 
- Assume Pool A initially has an allocation point of $350$, and Pool B has $400$.
- If Pool A's allocation point is updated to $300$ and Pool B's allocation point is updated to $500$ within the same `batchUpdateAllocPoint` call, the `_totalAllocPoint` for each pool is updated independently, leading to a final totalAllocPoint of $300 + 500 = 800$.

If, after these updates, the `totalAllocPoint` is incorrectly assigned the value of `_totalAllocPoint` from only one pool (e.g., 350 for Pool A), it will not reflect the correct sum of all pools, resulting in an incorrect `totalAllocPoint`.

## Impact
An incorrect `totalAllocPoint` can lead to an inaccurate distribution of rewards among pools. If the `totalAllocPoint` does not reflect the true sum of allocation points across all pools, the rewards distribution logic that relies on this value will be skewed, potentially resulting in one or more pools receiving a disproportionate share of rewards.
## Tools Used
Manual
## Recommended Mitigation Steps
Modify the code to calculate `totalAllocPoint` explicitly at the end of the loop by iterating over all pools and summing their allocation points.
