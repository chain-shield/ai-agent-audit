# Vulnerability details

## Impact
Detailed description of the impact of this finding.
The loop ecosystem implements the pause mechanism to handle emergencies. However, the pause mechanism can be bypaseed by borrowers and implement `deposit` and `withdraw` by calling `modifyCollateralAndDebt` directly in a paused state.

## Proof of Concept
https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L239
https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L223

The `withdraw` and `deposit` functions carry the `whenNotPaused` modifier which means according to the system architecture they should only work when the system is not paused. 

when a user calls any of both functions with an input data, the function makes a call to the `modifyCollateralAndDebt` to carry out the withraw/deposit action. 

In a paused state, the `withdraw` and `deposit` functions cannot be called directly beacuse of the modifier, but users can call `modifyCollateralAndDebt` to carry out their withraw and deposit actions.

```
 function modifyCollateralAndDebt(
        address owner,
        address collateralizer,
        address creditor,
        int256 deltaCollateral,
        int256 deltaDebt
    ) public {
        if (
            // position is either more safe than before or msg.sender has the permission from the owner
            ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender)) ||
            // msg.sender has the permission of the collateralizer to collateralize the position using their cash
            (deltaCollateral > 0 && !hasPermission(collateralizer, msg.sender)) ||
            // msg.sender has the permission of the creditor to use their credit to repay the debt
            (deltaDebt < 0 && !hasPermission(creditor, msg.sender))
// The rest of the code logic adjusts the position as specified by the caller
```
