# Vulnerability details

`modifyCollateralAndDebt()` function is failing to properly update the `sumOfPositionCollaterals` variable when modifying the collateral balance of a position. This inconsistency between the actual collateral held by the vault and the recorded sum of position collaterals can lead to incorrect accounting.

The total collateral should match the sum of position collaterals after the execution of `modifyCollateralAndDebt`. [// CDPVault.sol: Lines 437-443](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L437-L443)
```solidity
if (deltaCollateral > 0) {
    uint256 amount = wmul(deltaCollateral.toUint256(), tokenScale);
    token.safeTransferFrom(collateralizer, address(this), amount);
} else if (deltaCollateral < 0) {
    uint256 amount = wmul(abs(deltaCollateral), tokenScale);
    token.safeTransfer(collateralizer, amount);
}
```
The function updates the collateral balance by transferring tokens based on the `deltaCollateral` value. However, it does not properly update the `sumOfPositionCollaterals` variable to reflect the change in collateral.

For that reason, after the execution of `modifyCollateralAndDebt`, the `sumOfPositionCollaterals` does not match the actual sum of collateral across all positions, violating the invariant.

## Impact
* The mismatch between the actual collateral and the recorded sum violates the invariant that the total collateral should always match the sum of position collaterals.

## Proof of Concept
* **Initial Deposit:** The user deposits 100 tokens as collateral into the vault. The `modifyCollateralAndDebt()` function correctly updates the user's position and sets the `sumOfPositionCollaterals` to 100.

* **Collateral Withdrawal:** The user decides to withdraw 50 tokens of their collateral. The `modifyCollateralAndDebt()` function correctly updates the user's position, reducing their collateral to 50 tokens.

* **Inconsistent Accounting:** Crucially, the function fails to update the `sumOfPositionCollaterals` variable during the withdrawal. As a result, the variable remains at 100, even though the actual total collateral in the vault is now 50 tokens.

## Recommended Mitigation Steps
Should be updated to properly adjust the sumOfPositionCollaterals variable whenever the collateral balance is modified.
```solidity
// CDPVault.sol: Lines 425-431
if (deltaCollateral > 0) {
    uint256 amount = wmul(deltaCollateral.toUint256(), tokenScale);
    token.safeTransferFrom(collateralizer, address(this), amount);
    sumOfPositionCollaterals += deltaCollateral; // Update the sum of position collaterals
} else if (deltaCollateral < 0) {
    uint256 amount = wmul(abs(deltaCollateral), tokenScale);
    token.safeTransfer(collateralizer, amount);
    sumOfPositionCollaterals -= abs(deltaCollateral); // Update the sum of position collaterals
}
```
