# Vulnerability details

## Impact
`PendleRouter::addLiquiditySingleToken(...)` accepts native tokens as input for adding liquidity into Pendle protocol. `addLiquiditySingleToken(...)` accepts native tokens via `payable` operator. But, not all entry points leading to `PendleRouter::addLiquiditySingleToken(...)` accepts ether and hence will not work as expected.

`PoolAction::join()` accepts native tokens which in turn invokes `PendleRouter::addLiquiditySingleToken(...)` should work fine. But, the `PoolAction::join()`  is called via  `PoolAction::transferAndJoin(...)`, since the entry point does not accept native tokens, it will not work as expected.

## Proof of Concept
`PoolAction::_pendleJoin()` function is invoked via `PoolAction::join()` function. But since `PoolAction::join()` can also be invoked via  `PoolAction::transferAndJoin(...)`, msg.value will be 0 as `PoolAction::transferAndJoin(...)` does not have `payable` operator.

```
     function _pendleJoin(PoolActionParams memory poolActionParams) internal {
        (
            address market,
            ApproxParams memory guessPtReceivedFromSy,
            TokenInput memory input,
            LimitOrderData memory limit
        ) = abi.decode(poolActionParams.args, (address, ApproxParams, TokenInput , LimitOrderData));
        
        
        if (input.tokenIn != address(0)) {
                IERC20(input.tokenIn ).forceApprove(address(pendleRouter),input.netTokenIn);
            }

==>        pendleRouter.addLiquiditySingleToken{value: msg.value}(poolActionParams.recipient, market, poolActionParams.minOut, guessPtReceivedFromSy, input, limit);
    }
```

## Recommended Mitigation Steps
Add `payable` operator to `PoolAction::transferAndJoin(...)` and restrict to be a valid value if protocol is `PENDLE`.

```
   function transferAndJoin(
        address from,
        PermitParams[] calldata permitParams,
        PoolActionParams calldata poolActionParams
    ) payable external {
        if (from != address(this)) {
            if (poolActionParams.protocol == Protocol.BALANCER) {
              require(msg.value==0,"Native token Not accepted");
              ...
            } else if(poolActionParams.protocol == Protocol.PENDLE) {
              ... 
            } else  revert PoolAction__transferAndJoin_unsupportedProtocol();
        }

        join(poolActionParams);
    }
```
Also, the `_pendleJoin(...)` should enforce which is the payment token.
The current implementation assumes that native token will come in by defaut.
Also, there is no check for msg.value == 0.
