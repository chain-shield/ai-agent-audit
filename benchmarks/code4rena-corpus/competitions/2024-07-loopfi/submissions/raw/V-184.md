# Vulnerability details

## Vulnerability Details 
In the `CDPVault` contract the `deposit` and `withdraw` functions are meant to revert when the protocol is paused, this is because they have the `whenNotPaused` modifier.

The purpose of the deposit/withdraw functions is to slightly manipulate the user input params and pass them into `modifyCollateralAndDebt()` function to actually change the state.

The issue is that an attacker can easily bypass this by directly calling the public `modifyCollateralAndDebt` function with the appropriate params for a deposit/withdraw. Since this function does not have the `whenNotPaused` modifier, the Tx will go through even if the protocol is paused.

## Impact
Attacker can deposit/withdraw through `modifyCollateralAndDebt` when the protocol is paused.

If there is an exploit involving the depositing/withdrawing, pausing the protocol will not stop the attacker.

## Recommended Mitigation Steps
There are a few solutions

1. Make `modifyCollateralAndDebt()` an internal function
2. If `modifyCollateralAndDebt()` must remain public, revert if paused when `(deltaCollateral > 0 || deltaCollateral < 0)`

Make sure repayments are not paused else borrowers will unfairly accumulate interest and may be quickly liquidated by a bot once unpaused
