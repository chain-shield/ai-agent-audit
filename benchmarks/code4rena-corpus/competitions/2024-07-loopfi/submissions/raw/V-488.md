# Vulnerability details

## Impact
users could be unable to repay their full debt, slight imprecision in calculating base interest 

## Proof of Concept
using a simple example 
assume rate is 0.1% ie rate = 10 
bob borrows 10e18 weth via cdp vault hence quotarevenuechange = 10/10000 * 10e18 = 10e14 hence quota revenue in pool = 1e16
alice also borrows 10e18 weth hence quota revenue in pool = 2e16
bob then places another borrow but this time for 995 weth hence quotarevenue change = 10/10000 * 995 = 0 so no revenue is added however bobs debt increases
bob then places this borrow of 995 one more time, both times revenue is not added but his debt increases 
at this point bobs debt is 10000000000000001990
bob then calls repay, his quotarevenuechange here will be calculated to be -10000000000000001
quotarevenue in pool after bobs repay will be (1e16 - 1)
when alice wants to repay here own debt 
quota revenue change will be -1e16
hence quota revenue in pool will be 1e16 - 1 - 1e16 which would underflow to uint256.max 
this value doesnt fit into uint92 hence a revert would occur and even if it didnt, the value is still to high 

## Tools Used
manual analysis 

## Recommended Mitigation Steps
a check should exist that would revert if debt > 0 and quotarevenuechange = 0
