# Vulnerability details

## Impact

The contract Flashlender.sol does not validate the `amount` parameter from `flashLoan` and `creditFlashLoan` functions before use. 

This means, a malicious user could provide an excessive loan amount causing potential overflow issues.


## Proof of Concept
```solidity
function flashLoan(
    IERC3156FlashBorrower receiver,
    address token,
    uint256 amount,
    bytes calldata data
) external override nonReentrant returns (bool) {
    ...
    uint256 fee = wmul(amount, protocolFee);
    uint256 total = amount + fee;
    ...
}

function creditFlashLoan(
    ICreditFlashBorrower receiver,
    uint256 amount,
    bytes calldata data
) external override nonReentrant returns (bool) {
    ...
    uint256 fee = wmul(amount, protocolFee);
    uint256 total = amount + fee;
    ...
}
```
## Tools Used

Manual Review

## Recommended Mitigation Steps

Validate user inputs before using them in calculations or logic paths. For the `flashLoan` and `creditFlashLoan` methods, ensure the `amount` provided does not exceed the total available loanable amount which can be achieved by using SafeMath library for uint256 type which automatically checks for overflow and underflow situations.

Moreover, it would be recommended to have an upper cap for the loanable amount to prevent excessive borrow.
