# Vulnerability details

## Title
`VaultRegistry::getUserTotalDebt()`  is computed incorrectly because the pending interest is not added.

## Impact
`VaultRegistry::getUserTotalDebt()` returns the aggregated position stats for a user across all vaults. 

It calls `ICDPVault(registeredTokens[i]).positions(_user);` but the issue is that the if we want the user's debt as incentive balance to compute reward / fee distribution, 

we should call the function `CDPVault::_calcDebt()` because it computes debt and updates the interests, otherwise the debt amount is stale because it does not consider the interest rate. 

https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L467

```solidity
    function _calcDebt(Position memory position) internal view returns (DebtData memory cdd) {
        uint256 index = pool.baseInterestIndex();
        cdd.debt = position.debt;
        cdd.cumulativeIndexNow = index;
        cdd.cumulativeIndexLastUpdate = position.cumulativeIndexLastUpdate;
        cdd.cumulativeQuotaIndexLU = position.cumulativeQuotaIndexLU;
        // Get cumulative quota interest
        (cdd.cumulativeQuotaInterest, cdd.cumulativeQuotaIndexNow) = _getQuotedTokensData(cdd);

        cdd.cumulativeQuotaInterest += position.cumulativeQuotaInterest;

        cdd.accruedInterest = CreditLogic.calcAccruedInterest(cdd.debt, cdd.cumulativeIndexLastUpdate, index);

        cdd.accruedInterest += cdd.cumulativeQuotaInterest;
    }
```

The impact is `EligibilityDataProvider::isEligibleForRewards()` will return incorrect state and make user that eligible for reward loss reward.

## Proof of Concept
We can see the function [VaultRegistry::getUserTotalDebt()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/VaultRegistry.sol#L65C14-L65C30) it calls the `(, uint256 debt, , , , ) = ICDPVault(vaultList[i]).positions(user);` to get the debt of user. 

```solidity
    function getUserTotalDebt(address user) external view override(IVaultRegistry) returns (uint256 totalNormalDebt) {
        uint256 vaultLen = vaultList.length;
        for (uint256 i = 0; i < vaultLen; ) {
            (, uint256 debt, , , , ) = ICDPVault(vaultList[i]).positions(user);

            totalNormalDebt += debt;

            unchecked {
                ++i;
            }
        }
    }
```
As the issue described of stale debt above the following functions
[EligibilityDataProvider::requiredUsdValue() and EligibilityDataProvider::isEligibleForRewards()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/EligibilityDataProvider.sol#L187) will incorrect calculations leading to loss of users rewards.

```solidity
    function requiredUsdValue(address user) public view returns (uint256 required) {
        uint256 totalNormalDebt = vaultRegistry.getUserTotalDebt(user);
        required = (totalNormalDebt * requiredDepositRatio) / RATIO_DIVISOR;
        return _lockedUsdValue(required);
    }

    /**
     * @notice Returns if the user is eligible to receive rewards
     * @param _user's address
     */
    function isEligibleForRewards(address _user) public view returns (bool) {
        uint256 lockedValue = lockedUsdValue(_user);

        uint256 requiredValue = (requiredUsdValue(_user) * priceToleranceRatio) / RATIO_DIVISOR;
        return requiredValue != 0 && lockedValue >= requiredValue;
    }
```

## Recommended Mitigation Steps

We recommend to call `CDPVault::_calcDebt()` to compute interest + debt instead of calling getUserTotalDebt
