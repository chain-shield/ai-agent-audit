# Vulnerability details

## Impact

`CDPVault::liquidatePosition` allows anyone to liquidate an unsafe position by buying the position's collateral at a discount.

The problem is the `deltaDebt` calculation is incorrect, which is reponsible for calculating how much of the debt is paid off. Due to this issue, users can buy the full amount of collateral, and the position will still have some debt remaining.

This will cause the liquidity accounting within `PoolV3` to be incorrect, impacting various important features of the protocol regarding accounting for borrowed funds, causing a loss for lenders and the protocol. In addition, it will not allow the user to borrow again unless the extra debt is repaid.

## Proof of Concept

The problem is that the `deltaDebt` doesn't correctly reflect the value of the collateral that is sent to the liquidator. The value of the collateral corresponds to the `repayAmount` with the discount applied, however the debt removed corresponds to the `repayAmount` *without the discount* and without the `liquidation penalty` (multiplying by `liqConfig_.liquidationPenalty` is essentially removing the penalty from the `repayAmount`). This does not correctly reflect the true value of the collateral that is sent to the caller. The following PoC shows that the entire collateral of an unsafe position can be liquidated with debt still remaining:

## Recommended Mitigation Steps

The correct solution is to take the value of the collateral that is sent to the caller, and convert it to the borrowed token to get the value of the debt that is repaid. This can be done by utilizing the `spot price`:
