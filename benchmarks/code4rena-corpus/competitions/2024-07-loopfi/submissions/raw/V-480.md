# Vulnerability details

## Impact
The check for 'if (owner == address(0) || repayAmount == 0) revert CDPVault__liquidatePosition_invalidParameters();' on lines 511 and 581 could be bypassed by passing a non-zero 'owner' address that doesn't correspond to any existing position which results in incorrect logic execution further down the line.

## Proof of Concept
1. If a non-zero owner address is provided, but that address does not correspond to the owner of any position, the behavior of the code depends on how the positions mapping is structured and initialized.
2. Loading the position:
```solidity
// load liquidated position
Position memory position = positions[owner]; // the owner address does not correspond to any existing position (i.e., the owner does not own a position), the positions[owner] will return the default value of the Position struct, which is an "empty" struct with all fields set to their default values (e.g., 0 for numeric fields).
DebtData memory debtData = _calcDebt(position); // debtData most likely is zero or not as intended
```
3. Since Solidity mappings do not store keys explicitly. Instead, they use a hash function to associate keys with values, and if no value has been set for a key, the default value of the value type is returned. the position is empty, the debt calculation will likely result in incorrect or zero debt, which could lead to incorrect logic execution further down the line, lead to unintended behavior, such as incorrectly assuming a position exists when it doesn't.

## Tools Used
VScode, Manual audit

## Recommended Mitigation Steps
1. Validate position existence before proceeding with the liquidation:
```solidity
if (position.someField == 0) revert CDPVault__liquidatePosition_noPositionFound(); // This check should look at a field in the Position struct that should not be zero or default if the position exists(like 'debt').
```
2. Modify the actual check:
```solidity
if (!positionExists(owner) || repayAmount == 0) revert CDPVault__liquidatePosition_invalidParameters();
function positionExists(address user) public view returns (bool) {
    return positions[user].collateral > 0;
} // note: using an additional boolean flag or another data structure to track whether a position has been created would also be appropriate in case of edge cases
```
