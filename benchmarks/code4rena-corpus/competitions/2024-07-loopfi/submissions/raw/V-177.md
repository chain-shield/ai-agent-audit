# Vulnerability details

## Vulnerability Details 
To withdraw lpETH from StakingLPEth contract, users have to first call `cooldownAssets`. This will update the user's `cooldownEnd` and `underlyingAmount`. 

If `cooldownAssets` is called again by the same user in-between `cooldownEnd` and the current time, then it will increase `underlyingAmount` AND increase the `cooldownEnd` for all the funds, not just the newly cooldown funds. 

Consider the following scenario
1. A user calls `cooldownAssets` for 10 lpETH, this updates `underlyingAmount = 10` AND `cooldownEnd = block.timestamp + 30 days`
2. After 25 days the same user wants to unlock their remaining lpETH so they call `cooldownAssets` for 15 lpETH, this updates `underlyingAmount = 25` AND `cooldownEnd = block.timestamp + 30 days`

The issue is that the new cooldown has applied for the OLD 10 lpETH that was already cooling down for 25 days

## Impact
Users will have funds locked for longer than expected

In the worst case this leads to a 30 day DOS

## Recommended Mitigation Steps
1. Create a mapping that maps every user to a size 10 array of UserCooldown structs

```solidity
mapping(address => UserCooldown[10]) public userCooldowns;
```

2. When a user calls `cooldownAssets`, populate a slot in userCooldowns[msg.sender]

3. When a user withdraws iterate over each element of userCooldowns[msg.sender], and for each slot that `if (block.timestamp >= userCooldown.cooldownEnd `, allow them to withdraw the lpETH
