# Vulnerability details

There is an issue with the repayment priority logic in the `calcDecrease()` function. The problem lies in the `else` block of the `if (amountToRepay >= cumulativeQuotaInterest)` condition, triggered when the repayment amount is less than the cumulative quota interest.

In this case, the function incorrectly sets the `newCumulativeQuotaInterest` to `cumulativeQuotaInterest - quotaInterestPaid`, where `quotaInterestPaid` is equal to the repayment amount (`amountToRepay`). This leads to a violation of the expected behavior, which should prioritize reducing the cumulative quota interest by the repayment amount. [CDPVault.sol#L665-L683](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L665-L683)
```solidity
        if (cumulativeQuotaInterest != 0 && amountToRepay != 0) {
            // All interest accrued on the quota interest is taken by the DAO to be distributed to LP stakers, dLP stakers and the DAO

            if (amountToRepay >= cumulativeQuotaInterest) {
                amountToRepay -= cumulativeQuotaInterest; // U:[CL-3]
                profit += cumulativeQuotaInterest; // U:[CL-3]

                newCumulativeQuotaInterest = 0; // U:[CL-3]
            } else {
                // If amount is not enough to repay quota interest + DAO fee, then send all to the stakers
                uint256 quotaInterestPaid = amountToRepay; // U:[CL-3]
                profit += amountToRepay; // U:[CL-3]
                amountToRepay = 0; // U:[CL-3]

                newCumulativeQuotaInterest = uint128(cumulativeQuotaInterest - quotaInterestPaid); // U:[CL-3]
            }
        } else {
            newCumulativeQuotaInterest = cumulativeQuotaInterest;
        }
```

## Impact
When the repayment amount is less than the cumulative quota interest, the function incorrectly calculates the new cumulative quota interest, resulting in an incorrect state of the position.

If the cumulative quota interest is not reduced correctly, it may result in users paying more interest than expected or the protocol not receiving the correct amount of interest payments.

## Proof of Concept
1. A user has a position with a cumulative quota interest of 2 tokens.
2. The user attempts to repay 1 token of debt.
3. The calcDecrease() function is called with the following parameters:
   * `amount` (repayment amount) = 1
   * `cumulativeQuotaInteres`t = 2

4. Inside the `else` block of the `if (amountToRepay >= cumulativeQuotaInterest)` condition, the function sets:
   * `quotaInterestPaid` = 1
   * `newCumulativeQuotaInterest` = `cumulativeQuotaInterest - quotaInterestPaid` = 2 - 1 = 1

5. However, according to the expected behavior, the `newCumulativeQuotaInterest` should be equal to `cumulativeQuotaInterest - amount` = 2 - 1 = 1.

## Recommended Mitigation Steps
update the `else` block by setting `newCumulativeQuotaInterest` to `cumulativeQuotaInterest - amountToRepay` instead of `cumulativeQuotaInterest - quotaInterestPaid`, the function will prioritize reducing the cumulative quota interest by the repayment amount when the repayment amount is less than the cumulative quota interest.
```diff
if (cumulativeQuotaInterest != 0 && amountToRepay != 0) {

}
```
