# Vulnerability details

## Impact
There is a possibility a contract `EligibilityDataProvider` will not work as expected and blocks some users from claiming there rewards due to the `isEligibleForRewards` function, which will returns `false` when a user's **total debt** `totalNormalDebt` is **zero**. This leads to several issues in the contract, affecting the ability of eligible users to claim rewards and potentially causing incorrect disqualification.

**Inability to Claim Rewards:**
Users who meet all other criteria might be **unfairly disqualified** from earning rewards, affecting the integrity of the reward system.



## Proof of Concept
 `totalNormalDebt` represents the total debt a user has in the system, can be retrieved via `vaultRegistry.getUserTotalDebt(user)` as used in the following:
 
 ```js
 function requiredUsdValue(address user) public  view returns (uint256 required) {
    // check this line below
    uint256 totalNormalDebt = vaultRegistry.getUserTotalDebt(user);
    
    // if totalNormalDebt=0 the returned value is 0
    required = (totalNormalDebt * requiredDepositRatio) / RATIO_DIVISOR;
    return _lockedUsdValue(required);
}
```

the function `requiredUsdValue` will return 0 if the user debt is 0 that infects directly `isEligibleForRewards` function:

```js 
function isEligibleForRewards(address _user) public view returns (bool) {
    uint256 lockedValue = lockedUsdValue(_user);

    // if requiredValue=0 then the return of isEligibleForRewards will be false
    // which mean the user is not eligible
    uint256 requiredValue = (requiredUsdValue(_user) * priceToleranceRatio) / RATIO_DIVISOR;

    return requiredValue != 0 && lockedValue >= requiredValue;
}
```

If the `isEligibleForRewards` return `false` for a given user then all the function relying on it will revert such as `claim` and `claimBounty` functions within the `ChefIncentivesController` which used for rewarding users.

## Tools Used

Manual review and fondry

## Recommended Mitigation Steps

Adjust the `isEligibleForRewards` function to ensure that users with zero debt are not automatically marked as ineligible. The function should consider other criteria.
