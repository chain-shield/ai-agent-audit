# Vulnerability details

## Description
The `flashLoan()` function in the contract lacks a critical check to ensure that the requested loan amount does not exceed the maximum allowable flash loan amount (maxFlashLoan). The function correctly verifies that the token being borrowed is supported, but it fails to check whether the requested amount is within the permissible borrowing limit.

## Impact
An attacker could exploit this vulnerability by repeatedly requesting flash loans that exceed the protocol's available liquidity, using the borrowed funds for arbitrage, or other strategies that intensify liquidity strain. Even though the loan is returned within the transaction, the protocol's inability to immediately cover all obligations can disrupt normal operations, gradually draining its funds and compromising financial stability.

Also, In the loopfi system where flash loans are tied to collateralized positions, this liquidity strain could force the liquidation of assets at unfavorable prices, leading to significant losses. This, in turn, could trigger a domino effect of further liquidations and asset devaluations, exacerbating the protocol’s financial instability.

## Proof of Concept:
Consider the following scenario:

* A user calls the flashLoan() function, requesting a loan amount that exceeds the available liquidity for the specified token.
* Due to the lack of a proper liquidity check, the function proceeds with the loan, lending out more than the protocol can sustainably manage.
* Even though the loan is returned, the protocol's liquidity is strained, leading to potential operational disruptions, forced liquidations, and financial losses.
solidity
Copy code

```solidity
function flashLoan(
    IERC3156FlashBorrower receiver,
    address token,
    uint256 amount,
    bytes calldata data
) external override nonReentrant returns (bool) {
    if (token != address(underlyingToken)) revert Flash__flashLoan_unsupportedToken();

    uint256 fee = wmul(amount, protocolFee);
    uint256 total = amount + fee;

    pool.lendCreditAccount(amount, address(receiver));

    emit FlashLoan(address(receiver), token, amount, fee);

    if (receiver.onFlashLoan(msg.sender, token, amount, fee, data) != CALLBACK_SUCCESS)
        revert Flash__flashLoan_callbackFailed();

    // reverts if not enough Stablecoin have been sent back
    underlyingToken.transferFrom(address(receiver), address(pool), total);
    pool.repayCreditAccount(total - fee, fee, 0);

    return true;
}
```
The missing check means that amount is not compared against the available liquidity, leading to potential over-lending.

## Recommended Mitigation
Implement a check in the flashLoan() function to ensure that the requested loan amount does not exceed the maximum flash loan amount (maxFlashLoan). If the requested amount is greater than the maximum allowable amount, the function should revert the transaction.

>Example of the mitigation:

```solidity
uint256 maxBorrowable = maxFlashLoan(token);
if (amount > maxBorrowable) revert Flash__flashLoan_amountExceedsMax();
```
This check should be added immediately after verifying that the token is supported and before proceeding with the loan. This will ensure the protocol only lends out what it can afford, thereby protecting its liquidity and overall stability.
