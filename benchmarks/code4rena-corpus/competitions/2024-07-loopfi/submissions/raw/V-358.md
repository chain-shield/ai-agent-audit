# Vulnerability details

## Impact

Last user will not be able to withdraw `MIN_SHARES`.

## Proof of Concept

In StakingLPEth.sol, users deposit lpETH for slpETH. There is a check in the contract which makes sure that the `totalSupply` is greater than 0 and the totalSupply must be less than the `MIN_SHARES`.

```
    /// @notice ensures a small non-zero amount of shares does not remain, exposing to donation attack
    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
>       if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```

The MIN_SHARES is set as 0.01 ether. This means that at any point in time, the amount of slpETH must either be 0 or > 0.01 ether.

An attacker can deposit lpETH and withdraw all but 1 wei, leaving 1 wei of slpETH inside the contract when the `totalSupply` is greater than `MIN_SHARES`.

When the last user wants to withdraw their lpETH and burn their slpETH, they cannot do so because the `totalSupply` will be greater than 0. The last user has no choice but to leave the 0.01 slpETH inside the contract.

## Tools Used

Manual Review

## Recommended Mitigation Steps

Consider using virtual amounts instead of min shares to tackle inflation attacks.
