# Vulnerability details

## Proof of Concept
The following functions in the contract do not implement slippage checks, which can lead to unintended consequences during token swaps or financial adjustments:
1. `increaseLever` Function
```solidity
        // take out flash loan
        IPermission(leverParams.vault).modifyPermission(leverParams.position, self, true);
        flashlender.flashLoan( //@audit-info not abiding by ERC3156
            IERC3156FlashBorrower(self),
            address(underlyingToken),
            leverParams.primarySwap.amount,
            abi.encode(leverParams, upFrontToken, upFrontAmount)
        );
```
This function is intended to increase leverage by swapping tokens. The amount of tokens to be swapped is specified, but there is no check to ensure that the actual amount received from the swap is within an acceptable range compared to the expected amount.
2. `onFlashLoan` Function
```solidity
       // perform a pre swap from arbitrary token to collateral token if necessary
        if (leverParams.auxSwap.assetIn != address(0)) {
            bytes memory auxSwapData = _delegateCall(
                address(swapAction),
                abi.encodeWithSelector(swapAction.swap.selector, leverParams.auxSwap)
            );
            upFrontAmount = abi.decode(auxSwapData, (uint256));
        }

        // handle the flash loan swap
        bytes memory swapData = _delegateCall(
            address(swapAction),
            abi.encodeWithSelector(swapAction.swap.selector, leverParams.primarySwap)
        );
        uint256 swapAmountOut = abi.decode(swapData, (uint256)); // @audit-info zero slippage check

```
This function handles the flash loan, including performing swaps as part of the loan process. The absence of a slippage check means that price fluctuations during the flash loan can affect the expected results.
3. `_transferAndSwap` Function
```solidity
        uint256 retAmount = abi.decode(response, (uint256));

        // if this is an exact out swap then transfer the remainder to the `sender`
        if (swapParams.swapType == SwapType.EXACT_OUT) {
            uint256 remainder = swapParams.limit - retAmount;
            if (remainder > 0) {
                IERC20(swapParams.assetIn).safeTransfer(sender, remainder);
            }
            amountOut = swapParams.amount; // @@audit no slippage check
        } else {
            amountOut = retAmount;
        }
```
This function transfers tokens and then performs a swap. Without a slippage check, the amount of tokens received from the swap might differ significantly from what was expected, affecting the function’s outcome.
## Impact
Without slippage checks, these functions are vulnerable to price fluctuations, which could result in receiving significantly fewer tokens than expected. This discrepancy can lead to losses or other unintended effects, particularly in functions handling large or critical financial operations.
## Tools Used
Manual
## Recommended Mitigation Steps
Implement slippage tolerance checks for each of these functions to ensure that the actual amounts received from swaps or transfers are within an acceptable range of the expected amounts.
