# Vulnerability details

## Impact
Liquidation would not be possible for certain amounts and possibly make position go in bad debt

## Proof of Concept
The purpose of liquidation is to remove unhealthy positions especially to try not to let them go in bad debt where the money is impermanently lost.

The issue arise with this simple check:
https://github.com/code-423n4/2024-07-loopfi/blame/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L532
```js
if (takeCollateral > position.collateral) revert CDPVault__tooHighRepayAmount();
```
It is designed to stop liquidating positions where the repay amount is high.
But is some cases especially where the time is of essence, the next time the same position is attempted to be liquidated, their value of collateral can go even lower which eventually would go in bad debt bracket and it will incur loses for the protocol and liquidator when this can be stopped. This should not happen often but it is possible and it can be prevented.

## Tools Used
Manual Review.
## Recommended Mitigation Steps
In [liquidatePosition](https://github.com/code-423n4/2024-07-loopfi/blame/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L532) instead of reverting implement the following code:
```diff
- if (takeCollateral > position.collateral) revert CDPVault__tooHighRepayAmount();
+ if (takeCollateral > position.collateral) {
+       takeCollateral = position.collateral;
+       repayAmount = wmul(takeCollateral, discountedPrice); 
+ }
```
