# Vulnerability details

## Vulnerability details
PoolV3 is said [compatible with ERC-4626 standard](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/PoolV3.sol#L47), but `maxRedeem` and `maxWithdraw` will return a non zero value when contract is locked, and zero when paused which is somewhat contradictory.

As it can be seen, in the goal to comply with [the EIP-4626](https://eips.ethereum.org/EIPS/eip-4626), CDPVault return 0 for all [`maxDeposit`/`maxMint`/`maxWithdraw`/`maxRedeem`](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/PoolV3.sol#L356-L378) when the contract is paused:
>  ### maxWithdraw  
> \[...\]  
> MUST factor in both global and user-specific limits, like if withdrawals are entirely disabled (even temporarily) **it MUST return 0**.

Same can be found for the other "max" functions in the EIP.

This is because all `deposit`/`mint`/`withdraw`/`redeem` functions have a `WhenNotPaused` modifier which revert if contract is paused (so nothing can be withdraw/deposited, hence 0 returned)

But `withdraw` and `redeem` also have a `WhenNotLocked` modifier which revert too when contract is locked (which is a separate state from pause)

The issue is that `maxRedeem` and `maxWithdraw` do not take into account the `locked` state, only the `paused` state:

## Impact
EIP-4626 not correctly implemented (one case correct while the other forgotten) which will cause integration issues.
