# Vulnerability details

`liquidatePosition()` function allows liquidators to repay debt and seize collateral from undercollateralized positions. A check is performed to prevent liquidation if the position has "bad debt", meaning the total debt exceeds the collateral value: [CDPVault.sol#L525-L526](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L525-L526)
```solidity
// Ensure that there's no bad debt
if (calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)) revert CDPVault__BadDebt();
```
However, there's a scenario where this check passes even when the position does have bad debt, allowing liquidation to proceed when it should be blocked.

The vulnerability stems from the fact that `calcTotalDebt()` uses the stored `debtData`, while the collateral value is calculated using the current `spotPrice_`. This can lead to the bad debt check passing if the spot price has decreased significantly since the position was opened, even if the debt far exceeds the collateral at current prices.

> For example, consider a position with 1 ETH of collateral and 2000 DAI of debt, opened when the ETH price was 2000 DAI. If the ETH price later drops to 1000 DAI, `calcTotalDebt()` will return 2000 DAI but `wmul(position.collateral, spotPrice_)` will yield only 1000 DAI. The bad debt check will pass since 2000 <= 2000, even though the 2000 DAI debt is double the 1000 DAI collateral value at current prices. Liquidation would be allowed, seizing the entire collateral but still leaving a deficit.

## Impact
Liquidators can seize all collateral from positions whose debt exceeds collateral value, while still leaving the protocol with bad debt. If this occurred on a large scale, it could threaten the solvency and sustainability of the CDP system.

The risk is highest when collateral prices have fallen sharply since positions were opened. Conversely, the risk is low if prices have been stable or increased. However, even temporary price volatility creates windows of vulnerability.

## Proof of Concept

1. Alice opens a 1 ETH position with 2000 DAI debt when the ETH price is 2000 DAI.
2. The ETH price drops to 1000 DAI.
3. Bob calls `liquidatePosition()` on Alice's position.
4. The bad debt check passes since `calcTotalDebt()` returns 2000 DAI which equals `wmul(position.collateral, spotPrice_)` at the original 2000 DAI price.
5. Liquidation proceeds, with Bob seizing the 1 ETH collateral worth 1000 DAI and repaying 1000 DAI of the debt.
6. The protocol is left with a 1000 DAI deficit from Alice's position.

See [CDPVault.sol L529-L532](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L529-L532)

## Recommended Mitigation Steps
Modify the bad debt check to calculate both total debt and collateral value using current data. This ensures positions will only be liquidated if the debt exceeds collateral at current prices.
```diff
- if (calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)) revert CDPVault__BadDebt();
+ if (calcTotalDebt(_calcDebt(position)) > wmul(position.collateral, spotPrice_)) revert CDPVault__BadDebt();
```
