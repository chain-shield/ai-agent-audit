# Vulnerability details

## Impact
Complete DoS of StakingLpEth contract.

## Proof of Concept
Users deposit `lpEth` to `StakingLpEth` contract to get share by invoking public `deposit` or `mint` functions. Let’s see how the shares are being calculated:

```solidity
    function _convertToShares(uint256 assets, Math.Rounding rounding) internal view virtual returns (uint256) {
        return assets.mulDiv(totalSupply() + 10 ** _decimalsOffset(), totalAssets() + 1, rounding);
    }
```

Since `decimalsOffset() == 0` and `totalAssets()` will equal to the balance of `lpEth` in the contract.

The calculation will be:

$$ f(share) = (lpEth \ast totalSupply) / (totalLpEth() + 1) $$

The contract also employs a `MIN_SHARE = 0.01 ether` to ensure that no inflation attacks are possible.

However an attacker can take advantage of the min shares checks and DoS the whole contract:

1. Right after deployment the attacker will transfer a minumum of `MIN_SHARES` to the contract without minting any shares
2. Suppose the next user wants to deposit 1000 ether, which is quite a large amount
3. His shares will be calculated as:
 $$ f(share) = (1000e18 \ast 0 + 1) / (0.01e18 + 1) = 100 000 $$
 which is less than `MIN_SHARES`, which ultimately makes the function revert

Manual Analysis

## Recommended Mitigation Steps

Consider funding the contract upon deployment to make sure this will not be possible.
