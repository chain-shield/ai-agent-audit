# Vulnerability details

## Impact
The `setParameter` function in the `CDPVault.sol` contract is designed to allow privileged users (those with the `VAULT_CONFIG_ROLE`) to modify several critical configuration parameters. These parameters, including `debtFloor`, `liquidationRatio`, `liquidationPenalty`, and `liquidationDiscount`, are vital to the proper functioning and stability of the vault.

However, the current implementation does not include validation checks for the values being set. This oversight creates a vulnerability where these parameters can be configured with unsafe values, potentially leading to under-collateralization of user positions. Such misconfigurations could destabilize the vault, leading to significant risks such as bad debt accumulation, operational inefficiencies, and even the potential insolvency of the vault.

```
function setParameter(bytes32 parameter, uint256 data) external whenNotPaused onlyRole(VAULT_CONFIG_ROLE) {
    if (parameter == "debtFloor") vaultConfig.debtFloor = uint128(data);
    else if (parameter == "liquidationRatio") vaultConfig.liquidationRatio = uint64(data);
    else if (parameter == "liquidationPenalty") liquidationConfig.liquidationPenalty = uint64(data);
    else if (parameter == "liquidationDiscount") liquidationConfig.liquidationDiscount = uint64(data);
    else revert CDPVault__setParameter_unrecognizedParameter();
    emit SetParameter(parameter, data);
}

```

The `setParameter` function allows an administrator with the `VAULT_CONFIG_ROLE` to modify several key parameters:

`debtFloor`: This parameter sets the minimum amount of debt that must be generated by a position. If set too low, it could lead to the creation of many small, inefficient positions, increasing the vault’s operational burden and potentially leading to excessive gas costs.

`liquidationRatio`: This is the collateralization ratio below which a position can be liquidated. If set below 1 (or 100%), it could allow positions to remain under-collateralized, meaning users could borrow more than their collateral should allow.

`liquidationPenalty`: This is the penalty applied during the liquidation process. If set too high, it could deter liquidators from participating, reducing the effectiveness of the liquidation mechanism.

`liquidationDiscount`: This parameter sets the discount applied to collateral during liquidation. If set too high, it could result in significant losses for the vault when liquidating under-collateralized positions.

These parameters are critical for ensuring that positions within the vault are adequately collateralized and that the liquidation process functions as intended to protect the vault and its users.

The lack of input validation in this function is a significant vulnerability for the following reasons:

Under-Collateralization Risk: If the `liquidationRatio` is set below 1 (100%), the vault could allow positions to remain under-collateralized, meaning that users could borrow more than the value of their collateral. This could prevent necessary liquidations, leading to the accumulation of bad debt and potentially causing the vault to become insolvent.

Operational Inefficiency: A very low `debtFloor` could result in a large number of small positions, which could increase the vault's operational complexity and gas costs, making the system inefficient and harder to manage.

Systemic Risk: If these parameters are misconfigured, the vault could be left vulnerable to exploitation or operational failure, leading to potential insolvency and loss of user funds.

##Consequences:

Systemic Risk: Allowing under-collateralized positions to persist could lead to the accumulation of bad debt. This could eventually cause the vault to become insolvent, putting all users' funds at risk.

Operational Instability: Misconfigured parameters could result in a vault that is inefficient and prone to exploitation, leading to significant financial losses and operational challenges.

User Fund Loss: If the vault becomes insolvent due to these misconfigurations, users could lose their deposited collateral or experience delayed or incomplete liquidations, leading to substantial financial losses.


## Proof of Concept
An attacker or a misconfigured administrator could exploit this vulnerability by setting an unsafe `liquidationRatio`. For example, if the `liquidationRatio` is set to 0.5 (50%), the vault would allow users to maintain positions with only 50% collateralization, which is highly dangerous:

```
vault.setParameter("liquidationRatio", 0.5 * 10**18); // Unsafe liquidation ratio of 50%
```
With this configuration, users can maintain positions where the collateral is only 50% of the debt. This setup makes it possible for users to withdraw or borrow significantly more than they should based on their collateral. If the value of the collateral decreases slightly, these positions would typically be liquidated to prevent losses. However, with the `liquidationRatio` set so low, these positions would remain active, leading to a situation where the vault becomes insolvent because it cannot cover the debts owed.

## Recommended Mitigation Steps

To mitigate this risk, implement strict validation checks in the `setParameter` function to ensure that critical parameters are always set within safe, predefined ranges. For example:

```
function setParameter(bytes32 parameter, uint256 data) external whenNotPaused onlyRole(VAULT_CONFIG_ROLE) {
    if (parameter == "debtFloor") {
        require(data >= MIN_DEBT_FLOOR, "Debt floor too low");
        vaultConfig.debtFloor = uint128(data);
    } else if (parameter == "liquidationRatio") {
        require(data >= 1 * 10**18, "Liquidation ratio too low"); // Ensure ratio is always >= 100%
        vaultConfig.liquidationRatio = uint64(data);
    } else if (parameter == "liquidationPenalty") {
        require(data <= MAX_LIQUIDATION_PENALTY, "Liquidation penalty too high");
        vaultConfig.liquidationPenalty = uint64(data);
    } else if (parameter == "liquidationDiscount") {
        require(data <= MAX_LIQUIDATION_DISCOUNT, "Liquidation discount too high");
        vaultConfig.liquidationDiscount = uint64(data);
    } else {
        revert CDPVault__setParameter_unrecognizedParameter();
    }
    emit SetParameter(parameter, data);
}
```

By implementing these validation checks, the contract can ensure that these parameters are always set to values that maintain the vault's stability and protect users' funds from being put at risk.
