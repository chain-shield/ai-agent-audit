# Vulnerability details


## Impact
During auxSwap, it results in a loss of user funds or Dos.

## Proof of Concept
In the decreaseLever() function, it requires leverParams.auxSwap.swapType to be SwapType.EXACT_IN. We know that auxSwap is used to swap the leftover collateral which was not needed to pay back the flash loan,  to an arbitrary token.
```javascript

        uint256 subCollateral,
        address residualRecipient

        // validate the primary swap
        if (leverParams.primarySwap.swapType != SwapType.EXACT_OUT || leverParams.primarySwap.recipient != self)
            revert PositionAction__decreaseLever_invalidPrimarySwap();

        // validate aux swap if it exists
@>>        if (leverParams.auxSwap.assetIn != address(0) && (leverParams.auxSwap.swapType != SwapType.EXACT_IN))
            revert PositionAction__decreaseLever_invalidAuxSwap();

        if (leverParams.auxSwap.assetIn == address(0) && residualRecipient == address(0))
            revert PositionAction__decreaseLever_invalidResidualRecipient();

        IPermission(leverParams.vault).modifyPermission(leverParams.position, self, true);

```
However, as we see in onCreditFlashLoan(), withdrawnCollateral is the amount of collateral that is withdrawn, and swapAmountIn is used to swap collateral to stablecoin to pay back the flash loan. The amount for swapAmountIn is uncertain during the transaction, so the remaining amount, residualAmount, is also uncertain.

The user cannot pre-calculate leverParams.auxSwap.amount to equal residualAmount.

(1) When leverParams.auxSwap.amount > residualAmount, the swap will revert, causing a Denial of Service (DoS).
(2) When leverParams.auxSwap.amount < residualAmount, it will result in leftover funds being stranded.
