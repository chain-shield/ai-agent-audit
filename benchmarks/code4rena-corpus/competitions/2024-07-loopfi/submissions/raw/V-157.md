# Vulnerability details

## Vulnerability Details 
CPDVaults will hold Pendle LP tokens as collateral [(proof from the docs.)](https://docs.loopfi.xyz/the-protocol/looping-leveraged-restaking/supported-strategies)

Therefore it is reasonable to assume that there will be a large number of Pendle LP tokens held within these vaults.

Simply for holding Pendle LP tokens the vaults will generate large amounts of PENDLE incentives and other reward tokens (like WETH for LP for GLP pool).

The issue is that there is no function to redeem these rewards from pendle and then distribute the rewards to LoopFi users. This is also recommended by [pendle themselves in their docs](https://docs.pendle.finance/Developers/Oracles/HowToIntegratePtAndLpOracle#handling-of-pendle-lps-rewards)

## Impact
All rewards generated from holding Pendle LP tokens will be lost

## Recommended Mitigation Steps
Add the following function to redeem all the rewards.

```solidity
function redeemPendleRewards() external {
    // returns the list of reward tokens
    address[] memory rewardTokens = IPMarket(token).getRewardTokens();
    
    // redeems the user's reward
    // returns amounts of reward tokens redeemed, in the same order as `getRewardTokens()`
    uint256[] memory rewardAmounts = IPMarket(token).redeemRewards(address(this));
    ...
    ...
    ...    
}
```

Note the protocol should replace ... with logic to handle rewards distribution
