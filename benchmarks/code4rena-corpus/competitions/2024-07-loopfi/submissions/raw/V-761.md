# Vulnerability details

### Vulnerability Details

The preview functions (e.g., `previewDeposit`, `previewWithdraw`, `previewRedeem`) do not revert when the function they are previewing would revert, which is against ERC4626 standards.

### Impact

- This can lead to unexpected behavior, as users may rely on these functions to assess the viability of their transactions without proper feedback on potential reverts.

### Details

### 1. **Deposit Function**
- The `deposit` function will revert if the pool is paused, if the receiver address is zero, or if the assets sent are less than the required minimum due to fees.
- The `previewDeposit` function does not revert even if the underlying conditions (like pool status) would cause the actual deposit to fail.

### Code

```solidity
    function deposit(uint256 assets, address receiver) public override {
        // Reverts if pool is paused or other conditions
    }

    function previewDeposit(uint256 assets) public view override returns (uint256 shares) {
        shares = _convertToShares(_amountMinusFee(assets)); // Does not revert
    }
```

### 2. **Withdraw Function**
- The `withdraw` function will revert if the requested withdrawal amount exceeds the available liquidity or if the pool is locked.
- The `previewWithdraw` function does not revert even if the actual withdrawal would fail due to insufficient liquidity or locked status.

### Code

```solidity
    function withdraw(uint256 assets, address receiver, address owner) public override {
        // Reverts if insufficient liquidity or pool is locked
    }

    function previewWithdraw(uint256 assets) public view override returns (uint256) {
        return _convertToShares(_amountWithWithdrawalFee(_amountWithFee(assets))); // Does not revert
    }
```

### 3. **Redeem Function**
- The `redeem` function will revert if the number of shares being redeemed exceeds the user's balance or if the pool is locked.
- The `previewRedeem` function does not revert even if the actual redeem would fail due to insufficient shares or locked status.

### Code

```solidity
    function redeem(uint256 shares, address receiver, address owner) public override {
        // Reverts if shares exceed balance or pool is locked
    }

    function previewRedeem(uint256 shares) public view override returns (uint256) {
        return _amountMinusFee(_amountMinusWithdrawalFee(_convertToAssets(shares))); // Does not revert
    }
```
