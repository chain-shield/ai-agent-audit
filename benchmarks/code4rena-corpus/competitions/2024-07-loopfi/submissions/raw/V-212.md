# Vulnerability details

## Proof of Concept
The `individualEarlyExit` function in the `MultiFeeDistribution` contract includes a time check that is overly restrictive. The current implementation prevents withdrawals not only for past unlock times but also for the exact current time:
```solidity
function individualEarlyExit(bool claimRewards, uint256 unlockTime) external {
    address onBehalfOf = msg.sender;
    if (unlockTime <= block.timestamp) revert InvalidTime();
    // ... (rest of the function)
}
```
This check inadvertently blocks users from withdrawing their funds exactly at the unlock time, potentially causing a poor user experience and forcing users to wait for an additional block before they can access their unlocked funds.

## Impact
Users are unable to withdraw their funds at the exact moment of unlocking, potentially leading to user frustration and a slight delay in fund accessibility.
## Tools Used
Manual
## Recommended Mitigation Steps
Modify the time check to allow withdrawals at the exact unlock time:
```solidity
function individualEarlyExit(bool claimRewards, uint256 unlockTime) external {
    address onBehalfOf = msg.sender;
    if (unlockTime < block.timestamp) revert InvalidTime();
    // ... (rest of the function)
}
```
