# Vulnerability details

## Impact
User who withdraws last will be DOS and his funds will be locked.
Initially when shares are worth 1:1 with assets shares locked is about $32 dollars worth but this is subject to increase as the share value increases. Suppose if in the future with more rewards coming in shares are now worth 1:2 i.e. 1 share = 2 assets then the user's loss will also double in value, as can also be seen from [docs](https://docs.loopfi.xyz/the-protocol/lending-passive-eth-yield#:~:text=At%20launch%20the%20value%20will%20be%201%20slpETH%20%3D%201%20lpETH%2C%20but%20slpETH%20is%20expected%20to%20slowly%20increase%20in%20value%20as%20protocol%20yield%20is%20transferred%20into%20the%20Staking%20smart%20contract.). 

## Proof of Concept
Whenever withdraw is called, it checks for min shares 
```javascript
    function _withdraw(
        address caller,
        address receiver,
        address _owner,
        uint256 assets,
        uint256 shares
    ) internal override nonReentrant {
        super._withdraw(caller, receiver, _owner, assets, shares);
        _checkMinShares();
    }
```
```javascript
    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```
and min shares is ```0.01e18``` ;
```javascript
uint256 private constant MIN_SHARES = 0.01 ether;
```
The problem here is that there can be leftover dust which is not owned by a withdrawer which can DOS his transaction due to how the ```_chekMinShares``` works:
```if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();```.

There are two ways in which the last withdrawer can be DOS, 
* unintentionally accumulated dust amount of shares due to roundings when other users withdraw, OR
* intentionally by a malicious actor by leaving just 1(dust amount) of shares when he withdraws his shares.

Example-
* there are five users with 10e18 shares each 
* first four user has withdrawn, leaving 1(dust) amount of shares 
* now 10e18 + 1 shares are left i.e. ```totalSupply() = 10e18 + 1```
* last user(Bob) tries to withdraw and calls redeem with 10e18 but it will revert because of ```_checkMinShares```,
```if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();``` and bob cannot withdraw all because of that 1 dust leftover: ```1 > 0 && 1 < 0.01eth``` so it reverts.

Only way Bob can withdraw is to abandon his 0.01e18 shares which is worth around $32 dollars currently.
The problem is ```0.01 ether``` as ```MIN_SHARES``` is too much since we are dealing with an eth derivative token and 0.01 eth lost by a user is not a negligible amount.

## Recommended Mitigation Steps
reduce the amount of min shares required
```diff
-      uint256 private constant MIN_SHARES = 0.01 ether;
+      uint256 private constant MIN_SHARES = 1000;
```
Just this 1000(dust) is enough to make the attack ```1000 times``` more expensive i.e. to grief ```1 LPEth``` of a user the attacker has to donate more than ```1000 LPEth``` and besides even if he continues to do so, the openzeppelin's ```_decimalsOffset``` will make the attacker lose half of his donation.

This doesn't completely solve the problem but Bob(last withdrawer) will only loss 1000(dust) shares worth $0 dollars, which is negligible. But Bob's transaction will still be unexpectedly reverted the first time and Bob will have to figure out on his own how to overcome his problem(which is to abandon 1000(dust) of his shares).  


OR 

Another suggestion would be to completely remove the additional ```_checkMinShares``` protection, because the ```decimalsOffset``` alone is enough to make the attack unprofitable and lock the attackers assets. 
And require that we mint atleast 1 share everytime someone deposits 
```diff
    function _deposit(address caller, address receiver, uint256 assets, uint256 shares) internal override nonReentrant {
+       require( shares > 0, "mint atleast 1 share");
        super._deposit(caller, receiver, assets, shares);
        _checkMinShares();
    }
```
