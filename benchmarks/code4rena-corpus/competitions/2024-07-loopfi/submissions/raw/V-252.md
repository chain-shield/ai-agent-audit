# Vulnerability details

`CDPVault` contract is designed to allow modification of a position's collateral and debt balances. It includes permission checks to ensure only authorized parties can make certain changes:

- Increasing debt or decreasing collateral requires owner permission 
- Increasing collateral requires collateralizer permission
- Decreasing debt requires creditor permission

However, there is an issue with the logic that checks owner permission. The current code, in C[DPVault.sol:376](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L376), uses an OR condition:

```solidity

((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender))

// The function doesn't revert when it should due to lack of permissions.
```

This means owner permission is only required if either debt is increased OR collateral is decreased. But the correct behavior is that owner permission should be required if debt is increased AND collateral is decreased. 

With the current logic, if a user tries to both increase debt and decrease collateral without owner permission, the transaction would go through, when it should be reverted. This allows unauthorized modifications to a position, potentially putting it at risk of liquidation.

## Impact

Unauthorized users can modify a position's collateral and debt in an unsafe way. By increasing debt and decreasing collateral in the same transaction without owner approval, an attacker could trigger liquidation of the position and loss of funds.

## Proof of Concept

1. Alice creates a position and grants Bob permission to modify collateral but not debt
2. Bob calls `modifyCollateralAndDebt()` with `deltaDebt` of 100 and `deltaCollateral` of -50
3. Even though Bob does not have owner permission, the transaction goes through because only one of the OR conditions is checked
4. Alice's position now has higher debt and lower collateral, putting it at risk of liquidation

See `CDPVault.sol:374-381`

## Recommended Mitigation Steps

Use an AND condition instead of OR to ensure owner permission is required when both debt is increased and collateral is decreased in the same transaction:

```solidity

-- ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender))
++ ((deltaDebt > 0 && deltaCollateral < 0) && !hasPermission(owner, msg.sender))

```

This will properly enforce owner permission and prevent unauthorized unsafe modifications to a position.
