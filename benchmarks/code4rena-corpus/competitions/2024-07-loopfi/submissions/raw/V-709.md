# Vulnerability details

## Impact
The `flashLoan` and `creditFlashLoan` functions in `Flashlender.sol` calculate the fee using the following formula:
```
uint256 fee = wmul(amount, protocolFee);
```
This code calculates the fee based on the amount and `protocolFee`, but there is no validation to ensure that this fee is greater than zero. If the `protocolFee` is incorrectly set to a very low value or even zero, the protocol could end up providing flash loans without charging an appropriate fee, resulting in potential financial loss.


The code calculates the fee to be charged for the flash loan based on the amount borrowed and the `protocolFee`. However, there is no check to ensure that the fee is actually greater than zero or within a reasonable range.


If the `protocolFee` is accidentally or maliciously set to a value that results in a zero or negligible fee, the protocol could end up offering flash loans at little to no cost, allowing users to exploit this by taking multiple loans without paying the intended fee. This could lead to a loss of revenue for the protocol.


## Proof of Concept

Scenario: The `protocolFe`e is set to zero or an extremely low value (e.g., 0.00000001 WAD).

Execution: A user requests a flash loan using the `flashLoan` or `creditFlashLoan` function.

Impact: The fee calculated is zero or negligible, meaning the user can effectively take out a loan without paying any substantial fee, resulting in a financial loss to the protocol.

```
uint256 fee = wmul(amount, 0); // fee would be zero, allowing the loan without any cost
```
Loss of Revenue: The protocol could lose significant revenue if users exploit the ability to take loans without paying appropriate fees.
Financial Instability: Repeated exploitation of this issue could result in financial instability for the protocol.

## Recommended Mitigation Steps

To mitigate this risk, add a check to ensure that the calculated fee is greater than zero and within an acceptable range before proceeding with the loan:
```
require`fee > 0, "Flashlender: Fee must be greater than zero");
```

This check ensures that the fee is always non-zero and that the protocol earns revenue from every flash loan.
