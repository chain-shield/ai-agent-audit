# Vulnerability details

## Impact

The `modifyCollateralAndDebt` function contains a vulnerability due to overlapping permissions. If a user has permission from the creditor, they can withdraw collateral without proper authorization from the position owner. This issue arises because the hasPermission function is used for all roles (owner, collateralizer, and creditor), allowing permission overlap. This exploit is particularly relevant when the position is overcollateralized, ensuring the position remains safe even after the withdrawal.


## Proof of Concept



**Scenario**

1. Creditor Grants Permission:

    * Suppose a creditor gives permission to a user (`msg.sender`). The `hasPermission` check for the creditor will return true

2. Permission Overlap:

    * Since the `hasPermission` function is used for all roles (owner, collateralizer, and creditor), having permission from the creditor (`hasPermission(creditor, msg.sender) == true`) also means that `hasPermission(owner, msg.sender)` will return true.

3. Attacker Calls the Function

    * The attacker calls directly the modifyCollateralAndDebt function with the following parameters :

    ``` js
        vault.modifyCollateralAndDebt(creditor, attackerAddress, creditor, -collateral , 0 );
    ```


4. Permission Check:

    * The function checks permissions

    https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L374C9-L381C67

    ```js
        if (
        ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender)) ||
        (deltaCollateral > 0 && !hasPermission(collateralizer, msg.sender)) ||
        (deltaDebt < 0 && !hasPermission(creditor, msg.sender))
        ) revert CDPVault__modifyCollateralAndDebt_noPermission();
    
    ```

    * The relevant part of the check :

        *  `((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender))`

            * Here, `deltaCollateral < 0`, so `hasPermission(owner, msg.sender)` is checked. Since msg.sender has permission from the creditor, and the permission check uses the same function, `hasPermission(owner, msg.sender)` returns true.

        * Since `hasPermission(owner, msg.sender)` returns true, the function does not revert.

5. Collateral Transfer:

    * The function proceeds to transfer the collateral to `attackerAddress`:

    https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L440C16-L442C56

    ```js
        if (deltaCollateral < 0) {
            uint256 amount = wmul(abs(deltaCollateral), tokenScale);
            token.safeTransfer(collateralizer, amount);
        }
    ```

    * Here, `collateralizer` is `attackerAddress`, so the collateral is transferred to the attacker's address.

## Recommended Mitigation Steps

Using a single function with a type parameter to differentiate permissions. This method reduces redundancy and centralizes permission logic.


```js 

    uint8 constant PERMISSION_TYPE_OWNER = 1;
    uint8 constant PERMISSION_TYPE_COLLATERALIZER = 2;
    uint8 constant PERMISSION_TYPE_CREDITOR = 3;


    mapping(address => mapping(address => bool)) private _ownerPermitted;
    mapping(address => mapping(address => bool)) private _collateralizerPermitted;
    mapping(address => mapping(address => bool)) private _creditorPermitted;



    function hasPermission(address entity, address caller, uint8 permissionType) public view returns (bool) {
        if (permissionType == PERMISSION_TYPE_OWNER) {
            return entity == caller || _ownerPermitted[entity][caller];
        } else if (permissionType == PERMISSION_TYPE_COLLATERALIZER) {
            return entity == caller || _collateralizerPermitted[entity][caller];
        } else if (permissionType == PERMISSION_TYPE_CREDITOR) {
            return entity == caller || _creditorPermitted[entity][caller];
        } else {
            return false;
        }
    }


    function grantPermission(address entity, address user, uint8 permissionType) external {
        if (permissionType == PERMISSION_TYPE_OWNER) {
            _ownerPermitted[entity][user] = true;
        } else if (permissionType == PERMISSION_TYPE_COLLATERALIZER) {
            _collateralizerPermitted[entity][user] = true;
        } else if (permissionType == PERMISSION_TYPE_CREDITOR) {
            _creditorPermitted[entity][user] = true;
        } else {
            revert("Invalid permission type");
        }   
    }

```

So we can simply check in `modifyCollateralAndDebt` : 

```js

    if (
        // position is either more safe than before or msg.sender has the permission from the owner
        ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender, PERMISSION_TYPE_OWNER)) ||
        // msg.sender has the permission of the collateralizer to collateralize the position using their cash
        (deltaCollateral > 0 && !hasPermission(collateralizer, msg.sender, PERMISSION_TYPE_COLLATERALIZER)) ||
        // msg.sender has the permission of the creditor to use their credit to repay the debt
        (deltaDebt < 0 && !hasPermission(creditor, msg.sender, PERMISSION_TYPE_CREDITOR))
    ) revert CDPVault__modifyCollateralAndDebt_noPermission();

```
