# Vulnerability details

## Impact
1) The debt is never fully repaid, leaving residual debt in the system.
2) The protocol keeps updating quota revenue unnecessarily.
3) The protocol accumulates bad debt, leading to potential financial instability.

## Proof of Concept
In the `function liquidatePosition`, when a liquidator tries to repay the entire total debt in order to make position.debt = 0 (ie. here newDebt also = 0), the condition fails due to this incorrect check - `if (deltaDebt == maxRepayment)`, this is not going to be true in any situation, even when Liquidator's repay amount is total Debt amount. This is because deltaDebt = `uint256 deltaDebt = wmul(repayAmount, liqConfig_.liquidationPenalty);`

As a result, `newDebt` is never set to 0, causing the last condition `(debtData.debt - newDebt != 0)` to always pass. This leads to continuous updates to IPoolV3(pool).updateQuotaRevenue(), resulting in bad debt accumulation within the CDPVault and causing a bad debt state for the protocol.

Here the concept of partial liquidation is implemented but still when a liquidator is paying the maximum total Debt, in that case full new position.debt = 0 (ie. newDebt = 0) must be set.

## Recommended Mitigation Steps
when the full repayment amount of a position is given by the liquidator to liquidate that position then `newDebt` and `position.debt` both must be set to 0. And therefore no `updateQuotaRevenue` must be executed as the condition `if (debtData.debt - newDebt != 0)` should aways be false because `0 - 0 = 0`
