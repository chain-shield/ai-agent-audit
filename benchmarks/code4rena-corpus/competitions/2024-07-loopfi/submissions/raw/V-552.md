# Vulnerability details

## Impact
An attacker could mint a large number of shares at zero asset deposit, effectively gaining a disproportionate share of the pool.

## Details
If the `mint` function of ERC4626.sol is accessible to `StakingLPEth.sol` (due to inheritance which is the case here) and the share price is zero (or very very low) due to contract initialization (or a specific edge case), an attacker could mint a large number of shares at zero or neaar-zero asset deposit, effectively gaining a disproportionate(unfair) share of the pool. Note: While `_checkMinShares` is a useful function for ensuring that the total supply of shares doesn’t fall below a small threshold, it does not address the root cause of the exploit described.

## Proof of Concept
1. Inheritance of `mint` function from ERC4626.sol:
* The staking contract inherits the `mint` function from `ERC4626`.
* If the staking contract does not override or restrict this function (as is the case here), it remains accessible to users.
2. Public Access:
* The `mint` function in `ERC4626` is declared public, meaning anyone can call it as long as they meet any conditions specified in the function.
```solidity
/** @dev See {IERC4626-mint}.
     *
     * As opposed to {deposit}, minting is allowed even if the vault is in a state where the price of a share is zero.
     * In this case, the shares will be minted without requiring any assets to be deposited.
     */
    function mint(uint256 shares, address receiver) public virtual override returns (uint256) {
        require(shares <= maxMint(receiver), "ERC4626: mint more than max");

        uint256 assets = previewMint(shares);
        _deposit(_msgSender(), receiver, assets, shares);

        return assets;
    }
```
* If the staking contract doesn't modify the visibility or behavior of the inherited mint function, an attacker can directly interact with it.
3. Near-zero or Zero Share Price:
* The share price could be zero due to the specific state of the staking contract, such as when the pool has just been initialized or under certain edge cases.
* The `ERC4626 mint` function allows minting of shares based on the current share price. If the price is zero or near-zero, the function could mint a large number of shares with no asset (or near zero asset) deposit.
4. Attack Workflow:
* Step 1: The attacker observes that the share price is zero (or near zero), potentially due to contract initialization or a specific edge case.
* Step 2: The attacker calls the `mint` function from the staking contract, passing a high number of shares to mint. Since the share price is zero (or near zero), the required asset deposit calculated by previewMint is zero (or near zero).
* Step 3: The `mint` function mints the requested shares for the attacker. The attacker now holds a significant proportion of the staking pool’s shares for no cost (or minimal cost).
* Step 4: Once assets are deposited into the pool by other users, or if the share price increases, the attacker can redeem their shares for a much larger portion of the underlying assets than they initially deposited (or never deposited).

```solidity
// StakingContract inherits from ERC4626
contract StakingContract is ERC4626 {
    // No override of the mint function
}

// Attack sequence
// Assume `StakingContract` is deployed and the share price is zero or very low
StakingContract stakingContract = StakingContract(addressOfStakingContract);
uint256 sharesToMint = 1_000_000; // Large number of shares
stakingContract.mint(sharesToMint, attackerAddress); // Mint shares with minimal asset deposit

// Later, when the share price normalizes, the attacker redeems the shares
stakingContract.redeem(sharesToMint, attackerAddress, attackerAddress);
```

## Tools Used
VScode, Manual Audit

## Recommended Mitigation Steps
1. Override the mint Function:
* The staking contract can override the mint function to ensure that shares cannot be minted without a proper asset deposit. This can include checks on the share price to prevent minting when the price is too low.
2. Implement Minimum Asset Requirement:
* Add a minimum asset deposit requirement regardless of the share price to prevent zero or near-zero cost minting.
3. Restrict Minting:
* Only allow minting through specific functions that have additional checks or restrict minting to specific addresses (e.g., contract owner).
