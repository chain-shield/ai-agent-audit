# Vulnerability details

## Impact
The bug fundamentally undermines the reliability of the `balancerSwap` and Uniswap:: `ExactOutput/ExactInput` functions when ETH is involved in the transaction. It impairs the contract's ability to perform asset swaps that include ETH, directly affecting user experience and potentially leading to financial loss. 

## Vulnerability Details
***The `balancerSwap` function is expected to interact with the Balancer protocol to facilitate asset swaps. In scenarios where the swap involves ETH, the function must include a mechanism to transfer the ETH along with the function call. This is typically achieved using the `{value: msg.value}` syntax, which explicitly sends the specified amount of ETH with the transaction.***

However, the balancerSwap function, as currently implemented, neglects to utilize msg.value. This results in a critical flaw where the function call does not transmit ETH, even when the operation demands it. Consequently, this leads to scenarios where:

- ETH Swaps Fail: If the swap requires ETH as one of the assets, the absence of ETH due to the missing `msg.value` will cause the swap to fail.

- Transaction Fee Issues: If ETH is needed to cover fees within the Balancer protocol, the function will not provide the required ETH, resulting in failed or incomplete transactions.

- User Funds at Risk: Users attempting to execute swaps involving ETH may unintentionally believe they have transferred ETH, only to find that their transaction has failed, leaving them vulnerable to potential fund loss or additional gas costs to correct the issue.

## Proof of Concept
> Reproduction Steps
- Deploy a Contract with balancerSwap: Deploy a smart contract that includes the balancerSwap function as currently implemented.

- Attempt a Swap Involving ETH: Invoke balancerSwap to swap ETH for another asset using the Balancer protocol.

- Observe the Transaction Failure: The transaction will fail as the ETH is not transferred to the Balancer protocol due to the omission of `msg.value`.
```solidity
return
            abs(
                balancerVault.batchSwap( <--------
                    kind,
                    swaps,
                    assets,
                    FundManagement({
                        sender: address(this),
                        fromInternalBalance: false,
                        recipient: recipient,
                        toInternalBalance: false
                    }),
                    limits,
                    deadline
                )[pathLength]
            );
    }
```
However the [batchSwap is marked payable](https://github.com/balancer/balancer-v2-monorepo/blob/36d282374b457dddea828be7884ee0d185db06ba/pkg/interfaces/contracts/vault/IVault.sol#L575) , When executing a swap involving ETH, the balancerSwap function should successfully transfer the required amount of ETH along with the function call, ensuring that the swap or fee payment is executed correctly.

Unfortunately, The `balancerSwap` function does not transmit ETH, leading to failed transactions, potential fund loss, and an overall disruption of intended functionality.

## Recommended Mitigation Steps
To rectify this issue, the `balancerSwap` function must be updated to properly handle the transfer of ETH when necessary. Specifically, the function should include `{value: msg.value}` in the call to the Balancer protocol’s batchSwap function. This ensures that the required ETH is sent with the transaction, facilitating successful swaps and fee payments.
```solidity
balancerVault.batchSwap{value: msg.value}( <--------
    kind,
    swaps,
    assets,
    FundManagement({
        sender: address(this),
        fromInternalBalance: false,
        recipient: payable(recipient),
        toInternalBalance: false
    }),
    limits,
    deadline
);
```
