# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The BalancerOracle contract incorrectly assumes that the Balancer pool will have exactly three tokens (token0, token1, token2). 

This hardcoded limit can lead to reversion of the _getTokenPrice function for any valid token index beyond 2, causing the update process to fail. 

Consequently, the oracle may be rendered non-functional for pools with more than three tokens, thereby limiting its applicability and potentially leading to inaccurate or stale pricing data in decentralised finance (DeFi) applications reliant on this oracle.

***Use Case***
A similar bug was identified in previous DeFi projects where the assumption of fixed token counts led to systemic failures. 

For example, Uniswap v1 originally assumed a fixed pair of tokens, and subsequent iterations expanded to handle multiple assets dynamically, mitigating these issues.

## Proof of Concept

1.	Code Snippet:
```sol
    function _getTokenPrice(uint256 index) internal view returns (uint256 price) {
        address token;
        if (index == 0) token = token0;
        else if (index == 1) token = token1;
        else if (index == 2) token = token2;
        else revert BalancerOracle__getTokenPrice_invalidIndex();


        return chainlinkOracle.spot(token);
    }
```

2.	Scenario:
	•	Assume the Balancer pool is configured with four tokens.
	•	The balancerVault.getPoolTokens(poolId) call would return an array of four token addresses.
	•	During the update function execution, _getTokenPrice(3) would be called, resulting in a revert due to the missing condition for index 3.

3.	Execution:
•	The function reverts with BalancerOracle__getTokenPrice_invalidIndex() when accessing a token index of 3 or more.
	•	This limits the pool configurations supported by the oracle and leads to a failure in updating price data.

## Recommended Mitigation Steps

1.	Dynamic Token Handling:
Modify the BalancerOracle contract to support dynamic token handling using an array or mapping that accommodates any number of tokens retrieved from the pool:
```sol
address[] public tokens;
```

2.	Constructor and Initialisation:
Modify the constructor to initialise the tokens array:
```sol
(address[] memory tokens, , ) = balancerVault.getPoolTokens(poolId);
```

3.	Update the _getTokenPrice Function:
Modify the function to dynamically handle the number of tokens:
```sol
function _getTokenPrice(uint256 index) internal view returns (uint256 price) {
    if (index >= tokens.length) revert BalancerOracle__getTokenPrice_invalidIndex();
    address token = tokens[index];
    return chainlinkOracle.spot(token);
}
```
