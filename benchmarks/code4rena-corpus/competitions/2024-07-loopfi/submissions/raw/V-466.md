# Vulnerability details

## Impact

`CDPVault:_modifyPosition` is called within every core function within the `CDPVault` contract (liquidation, borrow, repay, deposit, withdraw).

`CDPVault:_modifyPosition` will revert if `address(rewardController) != address(0)`, causing DoS to each of these functionalities.

## Proof of Concept

`CDPVault:_modifyPosition` executes the following when `rewardController` address is set:

[CDPVault.sol#L335-L337](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L335-L337)
```javascript
    if (address(rewardController) != address(0)) {
        rewardController.handleActionAfter(owner, position.debt, totalDebt_);
    }
```

Let's take a look at the implementation of `rewardController::handleActionAfter`:

[ChefIncentivesController.sol#L596-L617](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/reward/ChefIncentivesController.sol#L596-L617)
```javascript
    function handleActionAfter(address _user, uint256 _balance, uint256 _totalSupply) external {
@>      if (!validRTokens[msg.sender] && msg.sender != address(mfd)) revert NotRTokenOrMfd();

        if (_user == address(mfd) || eligibilityExempt[_user]) {
            return;
        }
        if (eligibilityMode == EligibilityModes.FULL) {
            bool lastEligibleStatus = eligibleDataProvider.lastEligibleStatus(_user);
            bool isCurrentlyEligible = eligibleDataProvider.refresh(_user);
            if (isCurrentlyEligible) {
                if (lastEligibleStatus) {
                    _handleActionAfterForToken(msg.sender, _user, _balance, _totalSupply);
                } else {
                    _updateRegisteredBalance(_user);
                }
            } else {
                _processEligibility(_user, isCurrentlyEligible, true);
            }
        } else {
            _handleActionAfterForToken(msg.sender, _user, _balance, _totalSupply);
        }
    }
```

We can see this call will revert if the sender (`CDPVault` address in this case) is not a valid `R Token` and not the `mfd address`, which is the [MultiFeeDistribution](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/reward/MultiFeeDistribution.sol) address.

In this case, the `CDPVault` is neither, causing DoS.

Manual review

## Recommended Mitigation Steps

Ensure the address of the `CDPVault` is whitelisted to call this function.
