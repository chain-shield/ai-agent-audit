# Vulnerability details

## Impact
The current implementation allows users to borrow and repay debt even when the contract is paused. However, the liquidation functions (`liquidatePosition` and `liquidatePositionBadDebt`) are disabled during this time due to the `whenNotPaused` modifier. This creates a situation where bad debt can accumulate unchecked, leading to a potential Denial of Service (DoS) on the liquidation process. This puts the contract at significant risk, as it could result in the accumulation of bad debt, thereby depleting the treasury and causing losses.

## Proof of Concept
The vulnerability lies in the fact that while the `borrow` and `repay` functions remain accessible when the contract is paused, the liquidation functions are not. This creates an imbalance where users can continue to add/reduce their positions, but bad debt cannot be liquidated. This could lead to a situation where bad debt accumulates rapidly, especially in volatile market conditions, without the possibility of liquidation, ultimately leading to significant financial losses.

### Relevant Code Snippets

1. **Borrow Function:**
  
 ```solidity
   function borrow(address borrower, address position, uint256 amount) external {
       int256 deltaDebt = toInt256(amount);
       modifyCollateralAndDebt({
           owner: position,
           collateralizer: position,
           creditor: borrower,
           deltaCollateral: 0,
           deltaDebt: deltaDebt
       });
   }
   ```

2. **Repay Function:**
   
```solidity
   function repay(address borrower, address position, uint256 amount) external {
       int256 deltaDebt = -toInt256(amount);
       modifyCollateralAndDebt({
           owner: position,
           collateralizer: position,
           creditor: borrower,
           deltaCollateral: 0,
           deltaDebt: deltaDebt
       });
   }
   ```

3. **Liquidation Functions:**
   
```solidity
   function liquidatePosition(address owner, uint256 repayAmount) external whenNotPaused {
       // Liquidation logic
   }

   function liquidatePositionBadDebt(address owner, uint256 repayAmount) external whenNotPaused {
       // Liquidation logic
   }
   ```

Proof of Concept Steps:

1. Pause the contract to disable certain functionalities.
2. Borrow and repay functions can still be called, allowing users to manage their debt.
3. Attempt to call the `liquidatePosition` or `liquidatePositionBadDebt` functions, which will revert due to the `whenNotPaused` modifier.

This demonstrates that while users can continue to manage their debt, bad debt cannot be liquidated, creating a risk of accumulating unmanageable debt.

## Recommended Mitigation Steps

To address this issue, it is recommended to remove the `whenNotPaused` modifier from the liquidation functions. This will ensure that even when the contract is paused, liquidations can still occur, preventing the accumulation of bad debt.


```solidity
function liquidatePosition(address owner, uint256 repayAmount) external {
    // Liquidation logic
}

function liquidatePositionBadDebt(address owner, uint256 repayAmount) external {
    // Liquidation logic
}
```

2.  Additional Considerations

While removing the `whenNotPaused` modifier from the liquidation functions will solve the issue, it is also important to consider the broader implications of allowing certain functions to operate while the contract is paused. For example, consider implementing specific conditions under which borrowing and repaying are allowed even when the contract is paused
