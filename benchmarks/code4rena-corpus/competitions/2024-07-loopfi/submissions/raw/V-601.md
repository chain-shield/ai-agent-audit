# Vulnerability details

## Description
The transferAndJoin function does an incomplete sanity check where it only transfer funds from the caller if the `from` argument is not address(this):
```solidity
function transferAndJoin(
        address from,
        PermitParams[] calldata permitParams,
        PoolActionParams calldata poolActionParams
    ) external {
        if (from != address(this)) {
        ...
        _transferFrom(assets[i], from, address(this), maxAmountsIn[i], permitParams[i]);
    }
```

If the from argument is address(this), the function proceeds to join the pool without any sanity check:
```solidity
function transferAndJoin(
        address from,
        PermitParams[] calldata permitParams,
        PoolActionParams calldata poolActionParams
    ) external {
    if (from != address(this)) {
        ... 
        }
        join(poolActionParams);
    }

```

In case any funds are left at the PoolAction contract or its delegate callers, then claiming is free for anyone: a user has to call transferAndJoin with the from argument as address(this) and set the join recipient as himself/herself.

## Impact
Anyone can take excess amounts and funds left at the PoolAction contract or its delegate callers without paying anything.
If there's a contract with funds that calls the PoolAction contract, users can steal its tokens.
## Tools Used
Manual review
## Recommended Mitigation Steps
Make sure to require some sort of access control to the transferAndJoin function if the from argument == address(this), this ways users cannot missappropriate funds that are left at the contract/ at the contract's delegate callers.
