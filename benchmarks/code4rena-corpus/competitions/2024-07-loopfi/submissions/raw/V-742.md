# Vulnerability details

## Impact
A position that isn't bad debt can be liquidated fully when partial liquidation can return it back to a healthy position due to improper checks.

## Proof of Concept
The following code in the function `liquidatePosition` checks if the position is in bad debt or not by checking if the value of the debt is greater than the collateral value.
https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L525-L526
```
// Enusure that there's no bad debt
        if (calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)) revert CDPVault__BadDebt();
```

So a position is considered to be in bad debt if the collateral value is greater than the debt.
But the check in the function `liquidatePositionBadDebt` contradicts the statement in the previous function.
https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L599

```
if (calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)) revert CDPVault__noBadDebt();
```
It checks if the value of the debt is less or equal to the value of the discounted collateral price. And reverts if it is stating that `revert CDPVault__noBadDebt()`. So a position with value not greater than the spotprice of the collateral but above the discounted price of the collateral can be liquidated fully as bad debt.

This might lead to a position wrongfully be closed as bad debt when in fact it isn't, and partial liquidation or normal liquidation can be done.

## Tools Used
VS Code

## Recommended Mitigation Steps
Change the check in `liquidatePositionBadDebt` to:
```
if (calcTotalDebt(debtData) <= wmul(position.collateral, spotPrice_)) revert CDPVault__noBadDebt();
```
