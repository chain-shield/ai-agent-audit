# Vulnerability details

## Impact
In the ```CDPVault.modifyCollateralAndDebt()```, different check was carried out against the caller who is modifying a user position. The check aims to verify the caller is either the owner of the poison or permitted by the owner to modify the position in certain ways.

The problem with the check is that the ```Permission.hasPermission()``` does not check for specific permission. As a matter of fact, there is no method in Permission.sol that allows a user to give specified permission. 

This it is possible for the caller to perform a different modification contrary to what the owner permitted. 

## Proof of Concept
Only check for permission from owner, not modification specific.
```solidity

    function hasPermission(address owner, address caller) public view returns (bool) {
        return owner == caller || _permitted[owner][caller];
    }
```
check is done against
```solidity
if (
            // position is either more safe than before or msg.sender has the permission from the owner
            ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender)) ||
 @>           // msg.sender has the permission of the collateralizer to collateralize the position using their cash
            (deltaCollateral > 0 && !hasPermission(collateralizer, msg.sender)) ||
            // msg.sender has the permission of the creditor to use their credit to repay the debt
@>            (deltaDebt < 0 && !hasPermission(creditor, msg.sender))
        ) revert CDPVault__modifyCollateralAndDebt_noPermission();
```

If for instance, a position owner grant permission to another address to collateralise the position using their cash, permitted address can go on to increases their debt position instead or use the credit of the creditor to repay debt.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Make permission specific, and allow position owners to specify the exact permission they are willing to give another address.
