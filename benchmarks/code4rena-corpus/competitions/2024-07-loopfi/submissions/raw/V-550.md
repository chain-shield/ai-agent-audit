# Vulnerability details

## Impact
From **`MultiFeeDistribution.sol`**:

In `vestTokens`, to reduce the size of the array, the protocol groups similar `earnings[index].unlockTime` together by only considering `unlockTime` upto the nearest `1 days`. (disregarding hours and minutes as an intended action)

However in `vestTokens`, the way the protocol compares the `unlockTime` through 2 variables **divided separately**, causes the inaccuracies to reach upto `2 days`. Giving the chance for malicious users to cheat the system and withdraw `2 days` earlier instead of 1.

## Code
```solidity
function vestTokens(address user, uint256 amount, bool withPenalty) external whenNotPaused {
    ...
    
    if (withPenalty) {
        bal.earned = bal.earned + amount;
        LockedBalance[] storage earnings = _userEarnings[user];

->      uint256 currentDay = block.timestamp / 1 days;
        uint256 lastIndex = earnings.length > 0 ? earnings.length - 1 : 0;
->      uint256 vestingDurationDays = vestDuration / 1 days;

        // We check if an entry for the current day already exists. If yes, add new amount to that entry
->      if (earnings.length > 0 && (earnings[lastIndex].unlockTime / 1 days) == currentDay + vestingDurationDays) {
            earnings[lastIndex].amount = earnings[lastIndex].amount + amount;
        } else {
        ......
}
```
* In the code for the `vestTokens` function, **`currentDay`** and **`vestingDurationDays`** are rounded down to `1 days` **each**. Hence **`currentDay + vestingDurationDays`** is inaccurate up to `2 days`.

* Thus by comparing `(earnings[lastIndex].unlockTime / 1 days) == currentDay + vestingDurationDays`, earnings with `unlockTime` up to `<2 days` later will be grouped together and get to unlock **`2 days` earlier**

## Recommended Mitigation Steps
```diff
function vestTokens(address user, uint256 amount, bool withPenalty) external whenNotPaused {
    ....
-   uint256 currentDay = block.timestamp / 1 days;
    uint256 lastIndex = earnings.length > 0 ? earnings.length - 1 : 0;
-   uint256 vestingDurationDays = vestDuration / 1 days;
-   if (earnings.length > 0 && (earnings[lastIndex].unlockTime / 1 days) == currentDay + vestingDurationDays) {
+   if (earnings.length > 0 && (earnings[lastIndex].unlockTime / 1 days) == (block.timestamp + vestDuration) / 1 days) {
    ....
}
```
We can delete both the `currentDay` and `vestingDurationDays` since they are not used anyway else, and simply divide the sum **once** when comparing.

After this change, only `unlockTime` up to `1 day` inaccuracy can be grouped together, which is now aligned with the protocol's intended action of disregarding hours and minutes.
