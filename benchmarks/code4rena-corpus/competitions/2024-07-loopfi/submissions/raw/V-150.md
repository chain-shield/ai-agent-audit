# Vulnerability details

#### Contract: `CDPVault.sol`

### Issue:

* The `CDPVault.sol` contract is vulnerable due to the lack of access control in the `modifyCollateralAndDebt` function, which is called by both `deposit` and `withdraw` functions. Implementing strict access controls is essential to secure these functions and prevent potential attacks on user balances and the contract state.

### Affected Code:

**`deposit` Function: CDPVault.sol#L223**
```solidity
function deposit(address to, uint256 amount) external whenNotPaused returns (uint256 tokenAmount) {
    tokenAmount = wdiv(amount, tokenScale);
    int256 deltaCollateral = toInt256(tokenAmount);
    modifyCollateralAndDebt({
        owner: to,
        collateralizer: msg.sender,
        creditor: msg.sender,
        deltaCollateral: deltaCollateral,
        deltaDebt: 0
    });
}
```

**`withdraw` Function: CDPVault.sol#L239**
```solidity
function withdraw(address to, uint256 amount) external whenNotPaused returns (uint256 tokenAmount) {
    tokenAmount = wdiv(amount, tokenScale);
    int256 deltaCollateral = -toInt256(tokenAmount);
    modifyCollateralAndDebt({
        owner: to,
        collateralizer: msg.sender,
        creditor: msg.sender,
        deltaCollateral: deltaCollateral,

}
```

### Impact:
- **Unauthorized State Modification**: Any external contract or address can invoke `modifyCollateralAndDebt` directly, bypassing intended controls and potentially manipulating user collateral and debt balances.
- **Indirect Exploitation via `deposit` and `withdraw`**: Attackers can indirectly access the `modifyCollateralAndDebt` function through the `deposit` and `withdraw` functions, further compounding the risk of unauthorized access and manipulation.

## Recommended Mitigation Steps

1. **Implement Access Control**: Add appropriate access control modifiers (e.g., `onlyRole`, `onlyOwner`, or custom modifiers) to the `modifyCollateralAndDebt` function to restrict access to only trusted functions or entities.

   ```solidity
   function modifyCollateralAndDebt(
       address owner,
       address collateralizer,
       address creditor,
       int256 deltaCollateral,
       int256 deltaDebt
   ) public onlyRole(TRUSTED_ROLE) {
       // Critical logic modifying collateral and debt
   }
   ```

2. **Consider Making `modifyCollateralAndDebt` Internal**: If `modifyCollateralAndDebt` is not meant to be called externally, change its visibility to `internal` to prevent any external access.

   ```solidity
   function modifyCollateralAndDebt(
       address owner,
       address collateralizer,
       address creditor,
       int256 deltaCollateral,
       int256 deltaDebt
   ) internal {
       // Critical logic modifying collateral and debt
   }
   ```
