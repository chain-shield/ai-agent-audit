# Vulnerability details

## Impact
It's possible for a user to claim more rewards than he deposited in WETH.

User's must deposit a certain amount of WETH which translates to a corresponding amount of rewards ( BAL and AURA tokens ) they wish to claim. 
To determine this amount of WETH, the `AuraVault::claim` function makes a call to the `AuraVault::_previewReward` function. This function uses the `AuraVault::_chainlinkSpot` function and the `AuraVault::_getAuraSpot` function to get the BAL and AURA prices respectively. Because there is no check of stale prices in both functions, it's possible for this functions to return stale prices, which would lead to an incorrect `AuraVault::_previewReward()` price. If it is greater than the right price, the user can claim more rewards than the corresponding WETH they deposited.

## Tools Used
Manual review

## Recommended Mitigation Steps
Check the time elapsed since the last update against the heartbeat:
* of the BAL/USD feed in the `AuraVault::_chainlinkSpot()`, current heartbeat on Ethereum is 86400s ( 1day )
* of the ETH/USD feed in the `AuraVault::_getAuraSpot()`, current heartbeat on Ethereum is 3600s ( 1 hour )
