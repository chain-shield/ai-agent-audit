# Vulnerability details

Incorrect permission check in `modifyCollateralAndDebt` function that allows unauthorized modifications to a user's collateral and debt positions. The issue lies in the first condition of the permission checks at the beginning of the function. ([line 376 of CDPVault.sol](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L376)):
```solidity
((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender))
```
The condition is meant to check if the debt is being increased (`deltaDebt > 0`) or the collateral is being decreased (`deltaCollateral < 0`), and revert if the `msg.sender` does not have permission from the position owner.

However, this condition uses the logical OR operator (`||`) instead of the logical AND operator (`&&`). As a result, if either `deltaDebt` is positive (debt is being increased) or `deltaCollateral` is negative (collateral is being decreased), and the caller has permission from the owner, the function will not revert. However, the function should revert when both conditions are met, and the caller does not have permission from the owner.

As a result, an attacker can exploit this flaw to manipulate a position's collateral and debt without the owner's consent by crafting the `deltaDebt` and `deltaCollateral` values to bypass the permission check.

## Impact
Unauthorized increases in debt, leading to undercollateralized positions and increased risk of liquidation.

Unauthorized decreases in collateral, reducing the overall collateralization ratio and potentially triggering cascading liquidations.

The violation is in the permission checks at the beginning of the function: [CDPVault.sol:374-381](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L374-L381)
```solidity
if (
    // position is either more safe than before or msg.sender has the permission from the owner
    ((deltaDebt > 0 || deltaCollateral < 0) && !hasPermission(owner, msg.sender)) ||
    // msg.sender has the permission of the collateralizer to collateralize the position using their cash
    (deltaCollateral > 0 && !hasPermission(collateralizer, msg.sender)) ||
    // msg.sender has the permission of the creditor to use their credit to repay the debt
    (deltaDebt < 0 && !hasPermission(creditor, msg.sender))
) revert CDPVault__modifyCollateralAndDebt_noPermission();
```
According to this condition, the function should revert if either `deltaDebt` is positive (debt is being increased) or `deltaCollateral` is negative (collateral is being decreased), and the caller (`msg.sender`) does not have permission from the owner.

However, the violation occurs when both `deltaDebt` is positive and `deltaCollateral` is negative, but the caller does not have permission from the owner. In this case, the function should revert, but it doesn't.

## Proof of Concept
Consider the following scenario:

1. Alice has a position with 100 ETH collateral and 50 ETH debt.
2. Attacker Bob, who does not have permission from Alice, calls `modifyCollateralAndDebt()` with the following parameters:
   * `deltaCollateral` = -10 ETH
   * `deltaDebt` = 1 ETH
4. The permission check in line [376 of CDPVault.sol](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L376) passes because `deltaDebt > 0`, even though Bob does not have Alice's permission.
5. Alice's position is updated to 90 ETH collateral and 51 ETH debt without her consent.

## Tools Used
Manual review

## Recommended Mitigation Steps
Update the permission check in line [376 of CDPVault.sol](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L376) to use the logical AND operator (`&&`) instead of the logical OR operator (`||`):
```solidity
((deltaDebt > 0 && deltaCollateral < 0) && !hasPermission(owner, msg.sender))
```
This ensures that the function will revert if both `deltaDebt` is positive and `deltaCollateral` is negative, and the caller does not have the owner's permission.
