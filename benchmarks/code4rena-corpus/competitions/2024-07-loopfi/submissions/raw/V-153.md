# Vulnerability details

## Impact
When aggregator prices drop below minAnswer or rises above maxAnswer, wrong prices will be returned which can be manipulated to take loans at wrong prices or prevent liquidations when minAnswer is returned instead of the actual lower prices.

## Proof of Concept
Chainlink aggregators have a price boundary that includes minimum and maximum prices that can be returned. When there is massive and rapid drop in price of an asset(for example LUNA crash), The price oracle will continue to return the minimum price stipulated instead of the actual price allowing users to take loans at prices higher than the worth of their collateral. This is exactly the cause of [Venus crash when LUNA rapidly dropped in price](https://rekt.news/venus-blizz-rekt/).

The ChainlinkOracle.sol does not check for the minimum and maximum boundary prices which can allow the [Venus on BSC situation](https://rekt.news/venus-blizz-rekt/) to possbily be repeated.

```solidity
function _fetchAndValidate(address token) internal view returns (bool isValid, uint256 price) {
        Oracle memory oracle = oracles[token];
        try AggregatorV3Interface(oracle.aggregator).latestRoundData() returns (
            uint80 /*roundId*/,
            int256 answer,
            uint256 /*startedAt*/,
            uint256 updatedAt,
            uint80 /*answeredInRound*/
        ) {
            isValid = (answer > 0 && block.timestamp - updatedAt <= oracle.stalePeriod);
            return (isValid, wdiv(uint256(answer), oracle.aggregatorScale));
        } catch {
            // return the default values (false, 0) on failure
        }
    }
```

## Recommended Mitigation Steps
The `answer` from the `oracle.aggregator.latestRoundData()` should be checked to ensure the `answer` is within the minimum and maximum prices used by the aggregators in order not to use a wrong price.

