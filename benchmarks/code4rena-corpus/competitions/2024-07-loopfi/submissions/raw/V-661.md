# Vulnerability details

## Impact
An attacker can cause griefing for users by forcefully exiting them from pools

## Proof of Concept
The PoolAction.sol#exit(...) can by used to exit other users from the pool against their wish by any other user. This can be easily done to cause grief to users that have provided the market token approval to the PoolAction contract or other contracts that inherit it like the PoolAction20.sol.

In the code, users pass in `poolActionParams.recipient` address parameter that is directly passed to the `transferFrom` function of the market token. This can be used to cause greifing to other users by passing their address to exit them from the pool against their wish.
The `exit(...)` function calls the `_pendleExit(...)` function based on the `if` branch which is also supplied by the user.

The `_pendleExit(...)` is where the issue lies. That is where the `poolActionParams.recipient` address parameter supplied by the user is directly passed as the `from` parameter of the market token transferFrom function

## Recommended Mitigation Steps
Consider passing `msg.sender` as the `from` parameter to the `ERC20.transferFrom` instead of using an input address supplied by the user.
