# Vulnerability details

## Impact

`CDPVault::liquidatePosition` allows users to liquidate unsafe positions by buying the collateral at a discount, as long as the position is not in `bad debt`.

`CDPVault::liquidatePositionBadDebt` allows users to liquidate unsafe positions that have accumulated `bad debt`.

A position is considered in bad debt when `total debt > collateral value`. However, `liquidatePositionBadDebt` checks if `total debt > collateral value * discount`, allowing situations where despite the position not being in bad debt due to `collateral value > total debt`, it is possible that `total debt > collateral value * discount`, allowing the `liquidatePositionBadDebt` call on positions that do not have bad debt.

Due to this incorrect invariant check, a position can be liquidated despite not accumulating any bad debt, breaking a core protocol invariant. The protocol and lenders will suffer from this for the following reasons:

1. Liquidators can choose to call `liquidatePositionBadDebt` instead of `liquidatePosition`, avoiding the penalty fee that goes to the protocol's profits.
2. The protocol will incorrectly assume that bad debt is accumulated, which will cause the virtual accounting in `PoolV3` to be incorrect, impacting various core functionalities that affects users and the protocol.

## Proof of Concept

`CDPVault::liquidatePosition` has the following invariant check to ensure positions with bad debt cannot be liquidated via this call:

[CDPVault.sol#L525-L526](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L525-L526)
```javascript
    // Enusure that there's no bad debt
    if (calcTotalDebt(debtData) > wmul(position.collateral, spotPrice_)) revert CDPVault__BadDebt();
```

This is to ensure that the position has not accumulated bad debt, `debt < collateral value` must hold.

If the position is in `bad debt`, then the position must be liquidated via `CDPVault::liquidatePositionBadDebt`. However, the check for `bad debt` is not the same:

[CDPVault.sol#L598-L599](https://github.com/code-423n4/2024-07-loopfi/blob/main/src/CDPVault.sol#L598-L599)
```javascript
    // Enusure that the debt is greater than the collateral at discounted price
    if (calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)) revert CDPVault__noBadDebt();
```

This allows situations where the `total debt < collateral value`, but `total debt > collateral value * discount`. The position is clearly not in `bad debt` in this situation, but it is still considered to be in `bad debt` by the `liquidatePositionBadDebt` function.

The following coded PoC displays that a position not in bad debt can still be liquidated via a call to `liquidatePositionBadDebt`.

## Recommended Mitigation Steps

Ensure the invariant checks remain consistent:

```diff
    function liquidatePositionBadDebt(address owner, uint256 repayAmount) external whenNotPaused {

            revert CDPVault__liquidatePosition_notUnsafe();

        // load price and calculate discounted price
        uint256 discountedPrice = wmul(spotPrice_, liqConfig_.liquidationDiscount);
-       // Enusure that the debt is greater than the collateral at discounted price
-       if (calcTotalDebt(debtData) <= wmul(position.collateral, discountedPrice)) revert CDPVault__noBadDebt();
+       // Enusure that the debt is greater than the collateral
+       if (calcTotalDebt(debtData) <= wmul(position.collateral, spotPrice_)) revert CDPVault__noBadDebt();
        // compute collateral to take, debt to repay
        uint256 takeCollateral = wdiv(repayAmount, discountedPrice);
        if (takeCollateral < position.collateral) revert CDPVault__repayAmountNotEnough();

        position.cumulativeQuotaIndexLU = debtData.cumulativeQuotaIndexNow;

            owner,
            position,
            0,
            debtData.cumulativeIndexNow,
            -toInt256(takeCollateral),
            totalDebt
        );

        pool.repayCreditAccount(debtData.debt, 0, loss); // U:[CM-11]
```
