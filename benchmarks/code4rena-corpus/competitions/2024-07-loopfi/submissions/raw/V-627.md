# Vulnerability details

## Impact

The profitability of Lenders depends on the Utilization Rate(interest rate), which is calculated in the `Poolv3.sol` contract, however there is a mismatch of the formula compared to the documentation provided where this lead to miscalculation of the interest rate when calling `deposit`, `mint`, `withdraw` and *others*.


## Proof of concept

The `calcBorrowRate` compute the utilization rate of the borrowers which is specified in the [documention
of loopfi](https://docs.loopfi.xyz/the-protocol/lending-passive-eth-yield/utilization-rate#two-tick-utilization-curve) as following:

```math
r(t) = r0 + U(t)/U1(r1-r0), U(t)<=U1

r(t) = r0 + r1 + (U(t)−U1)r2/(U2-U1), U(t) ∈ (U1,U2]

r(t) = r0 + r1 + r2(U(t)−U2)r2/(1-U2), U(t) > U2
```
Lets analyze, translate and compare each part of the formula(there is 3 parts) to its related code within `calcBorrowRate` function in the contract `LinearInterestRateModelV3` used in `PoolV3.sol` contract 

1. The 1st formula r(t) = r0 + U(t)/U1(r1-r0) where U(t)<=U1 means if the U(t) is less than or equal U1 then we will compute the interest rate using this as a formula, so in solidity will look like this:

```ts
    if (U_WAD <= U_1_WAD) {
        return R_base_RAY + ((R_slope1_RAY * U_WAD) / U_1_WAD); // U:[LIM-3]
    }
```
however, when we check the code in the `calcBorrowRate` function we will find this:

```ts
    if (U_WAD < U_1_WAD) {
        return R_base_RAY + ((R_slope1_RAY * U_WAD) / U_1_WAD); // U:[LIM-3]
    }
```

which didnt include the case when `U(t) = U1`, hence, this lead to incorrect calculation of the interest rate.

2. The 2nd case is `r(t) = r0 + r1 + (U(t)−U1)r2/(U2-U1), U(t) ∈ (U1,U2]`, which compute the interest rate where U(t) is greater than U1 and U(t) is less than or equal U2, hence **U2** is included, translating it to code will look something like:

```ts
// bear in mind that we already handled the previous case with the previous if
if (U_WAD <= U_2_WAD) {
    return R_base_RAY + R_slope1_RAY + (R_slope2_RAY * (U_WAD - U_1_WAD)) / (U_2_WAD - U_1_WAD); // U:[LIM-3]
}
```
but looking to the `calcBorrowRate` code will find the following:

```ts
if (U_WAD < U_2_WAD) {
    return R_base_RAY + R_slope1_RAY + (R_slope2_RAY * (U_WAD - U_1_WAD)) / (U_2_WAD - U_1_WAD); // U:[LIM-3]
}
```

which exclude U2 from the formula, so this results in incorrect calculation of interest rate.

3. Lastly, when U(t) is **bigger than** U2 `r(t) = r0 + r1 + r2(U(t)−U2)r2/(1-U2), U(t) > U2`, this means U2 is not included, however `calcBorrowRate` function included the U2 which contradict with the formula in the documentation, hence, this leads to *miscalculation* of the **interest rate**.

As a result of the miscalculation returned from the `calcBorrowRate` function, which leads to incorrect results and may lead to loosing funds and liquidating users unfairly.
