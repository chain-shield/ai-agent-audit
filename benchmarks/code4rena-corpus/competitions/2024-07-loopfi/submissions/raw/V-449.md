# Vulnerability details

## Vulnerability Details

The issue in the code is that there is no health factor buffer when taking out the maximum loan. This results in edge cases where a user takes out the max loan and then is liquidated the next block due to extremely minor price fluctuations/ interest accumulations.

The main point is that even a 1 wei accumulation of interest will render the position liquidatable, as a result in the next block when the interest accumulates the position will be liquidated . 

Other lending protocols like AAVE have implemented a 3-5% buffer to prevent this situation.

## Proof of Concept
Here is a POC to prove the next block interest accumulation scenario 

1. User A takes out the max loan
2. In the next block a little bit of interest accumulates
3. Liquidator liquidates user A 

Add the following `test__POC__LackOfSafetyBuffer` to CDPVault.t.sol and run it using the following command


```solidity
function test__POC__LackOfSafetyBuffer___InterestAccumulation() public {
        // Create a CDP vault 
        CDPVault vault = createCDPVault(token, 1000 ether, 0, 1.25 ether, 1 ether, 1 ether);
        createGaugeAndSetGauge(address(vault));
    
        // Set up collateral amount and calculate maximum loan
        uint256 collateralAmount = 100 ether;
        uint256 spotPrice = vault.spotPrice();
        uint256 maxLoan = wmul(wdiv(collateralAmount, 1.25 ether), spotPrice);
    
        // Deposit collateral and take out maximum loan
        _modifyCollateralAndDebt(vault, int256(collateralAmount), int256(maxLoan));
    
        // 1 block alter interest accumulates
        vm.warp(block.timestamp + 1);
    
        // Liquidator liqudiates the position
        uint256 liquidationAmount = maxLoan ;
        mockWETH.mint(address(this), liquidationAmount);
        mockWETH.approve(address(vault), liquidationAmount);

        vault.liquidatePosition(address(this), liquidationAmount);
    }
```

## Impact

Users can create a position that will be liquidated in the next block.

Borrowers of the protocol may be unfairly liquidated due to extremely minor movements in the market or extremely tiny oracle manipulation, when taking out the max loan.

[Here is a similar issue judged as medium severity in the past](https://github.com/code-423n4/2024-03-revert-lend-findings/issues/363)

## Recommended Mitigation Steps

Implement a max loan that is 3-5% away from the liquidation threshold to prevent these scenarios
