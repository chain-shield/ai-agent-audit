# Vulnerability details

## Proof of Concept
The `individualEarlyExit` function is designed to allow users to withdraw specific earnings entries by providing an `unlockTime` parameter. This function calls `_ieeWithdrawableBalance`, which returns the amount, penalty amount, burn amount, and index associated with the specified `unlockTime`.

```solidity
function individualEarlyExit(bool claimRewards, uint256 unlockTime) external {
    address onBehalfOf = msg.sender;
    if (unlockTime <= block.timestamp) revert InvalidTime();
    (uint256 amount, uint256 penaltyAmount, uint256 burnAmount, uint256 index) = _ieeWithdrawableBalance(
        onBehalfOf,
        unlockTime
    );

    uint256 length = _userEarnings[onBehalfOf].length;
    for (uint256 i = index + 1; i < length; ) {
        _userEarnings[onBehalfOf][i - 1] = _userEarnings[onBehalfOf][i];
        unchecked {
            i++;
        }
    }
    _userEarnings[onBehalfOf].pop();

    Balances storage bal = _balances[onBehalfOf];
    bal.total = bal.total - amount - penaltyAmount;
    bal.earned = bal.earned - amount - penaltyAmount;

    _withdrawTokens(onBehalfOf, amount, penaltyAmount, burnAmount, claimRewards);
}

```
However, the function does not correctly handle cases where the specified `unlockTime` does not exist in the user's earnings records. If `_ieeWithdrawableBalance` fails to find a match for the given `unlockTime`, it returns zeros for all values, including the `index`. This `index` is then used in the loop that shifts the earnings entries to remove the selected entry. Since the `index` is 0, the function unintentionally removes the first entry in the `userEarnings` array.

Additionally, the function decreases the user's total and earned balances by the `amount` and `penaltyAmount` values returned from `_ieeWithdrawableBalance`, which are zero when the `unlockTime` is not found. As a result, the user's balance is not correctly adjusted, and the function continues to execute, transferring 0 RDNT tokens to both the user and the DAO treasury.
## Impact
A malicious user can exploit this issue by repeatedly calling `individualEarlyExit` with an invalid `unlockTime`, effectively emptying their `userEarnings` array. After doing so, they can call the exit function, which will return a zero penalty and burn amount since the `userEarnings` array is now empty. This allows the user to withdraw their entire earned balance without incurring any penalties, bypassing the intended early exit penalties and potentially draining the reward pool.

Manual
## Recommended Mitigation Steps
The function should be updated to revert the transaction when the specified `unlockTime` is not found. This can be achieved by adding a check after the call to `_ieeWithdrawableBalance` to ensure that the index returned is within the bounds of the `userEarnings` array. If the index is out of bounds, the function should revert with a custom error, such as `UnlockTimeNotFound`.
