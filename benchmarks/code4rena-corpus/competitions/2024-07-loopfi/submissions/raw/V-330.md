# Vulnerability details

## Impact
Chainlink latestRoundData()'s return value `answeredInRound` is marked `Deprecated `. Using deprecated value may cause Dos

## Proof of Concept
In PendleLPOracle, we fetch price from chainlink latestRoundData().
We do some security check for the return value to make sure that the return value is one valid price.
The problem is that `answeredInRound` has already been marked as `Deprecated`. If the `answeredInRound` keeps the stale value, the check `answeredInRound >= roundId` may fail and this will cause the transaction reverted.

Chainlink doc reference:
https://docs.chain.link/data-feeds/api-reference

```javascript
    function _fetchAndValidate() internal view returns (bool isValid, uint256 price) {
        try AggregatorV3Interface(aggregator).latestRoundData() returns (
            // @audit answeredInRound is already deprecated.
            uint80 roundId, int256 answer, uint256 /*startedAt*/, uint256 updatedAt, uint80 answeredInRound
        ) {
            isValid = (answer > 0 && answeredInRound >= roundId && block.timestamp - updatedAt <= stalePeriod);
            return (isValid, wdiv(uint256(answer), aggregatorScale));
        } catch {
            // return the default values (false, 0) on failure
        }
    }
```
