# Vulnerability details

## Vulnerability Details

When the protocol accumulates any amount of bad debt, there will be more PoolV3 shares than assets.

The issue is that the `_convertToAssets()` function in PoolV3 is always 1 : 1 even when there are more shares than assets. Therefore once the protocol takes on bad debt it will be a race to withdraw all funds since the loss is not socialized to all lenders instead only the last to withdraw.

Consider the following scenario

1. Users 1 and 2 deposit 40 WETH each into PoolV3, they each receive 40e18 shares
2. Borrower deposits collateral and borrows 80 WETH through the CDPVault
3. black swan event happens and liquidator calls `liquidatePositionBadDebt()` repaying 50 WETH
4. At this point the PoolV3 contract has 80e18 shares BUT only 50e18 WETH
5. User A quickly redeems all of his 40e18 shares at 1:1 for his initial 40 WETH
6. Now PoolV3 holds 10 WETH, so user 2 can only redeem 10e18 shares for 10 WETH, making a loss of 30 WETH.

An interesting point is that the PoolV3 contract is forked form gearbox and the original contract from gearbox does not have a 1:1 asset to share ratio, they calculate it based on the totalAssets and totalSupply to prevent this issue. ([see the diff here](https://www.diffchecker.com/PB0ZjztT/))

    liquidityPool.withdraw(1_000_000 ether, address(this), address(this));

    // POC STARTS HERE
    //===========================

    _modifyCollateralAndDebt(vault, 100 ether, 80 ether);

    // black swan event drops the price so fast the collateral is worth less than the loan
    // The protocol has bad debt now
    _updateSpot(0.5 ether);

    // the original borrowed amount, proving the protocol took on bad debt
    uint256 repayAmount = 50 ether;
    mockWETH.mint(address(this), repayAmount);
    mockWETH.approve(address(vault), repayAmount);

    console.log("remaining WETH in PoolV3 after the bad debt liquidation =%e ",  mockWETH.balanceOf(address(liquidityPool)));

    // user 1 sees that bad debt accumulated so he quickly
    // withdraws the 40 WETH he put in
    vm.startPrank(user1);
    liquidityPool.withdraw(40 ether, user1, user1);

    console.log("remaining WETH in PoolV3 after user1 redeemed all his shares =%e ",  mockWETH.balanceOf(address(liquidityPool)));

    // It will revert because there are not enough assets

    vm.expectRevert();

    // He can only withdraw 10 WETH
    liquidityPool.withdraw(10 ether, user2, user2);

    // In the end state
    // user 1 made no loss from the bad debt
    // user 2 suffered a 30 WETH loss

    // Since user1 and user2 hold the same number of shares
    // what should have happened is that user1 will redeem all his shares for 25 WETH
    // similarly user2 will redeem all his shares for the remaining 25 WETH
    // socializing the loss. See the mitigation steps for how to implement this

}

## Impact

The loss from bad debt is not socialized

The last users to withdraw will suffer a huge fund loss unfairly

## Recommended Mitigation Steps

The loss from bad debt should be socialized equally to all lenders

Consider implementing the following `_convertToShares` and `_convertToAssets` functions

```solidity
    /// @dev Internal conversion function (from assets to shares) with support for rounding direction
    /// @dev Pool is not vulnerable to the inflation attack, so the simplified implementation w/o virtual shares is used
    function _convertToShares(uint256 assets, Math.Rounding rounding) internal view override returns (uint256 shares) {
        uint256 supply = totalSupply();
        return (assets == 0 || supply == 0) ? assets : assets.mulDiv(supply, totalAssets(), rounding);
    }

    /// @dev Internal conversion function (from shares to assets) with support for rounding direction
    /// @dev Pool is not vulnerable to the inflation attack, so the simplified implementation w/o virtual shares is used
    function _convertToAssets(uint256 shares, Math.Rounding rounding) internal view override returns (uint256 assets) {
        uint256 supply = totalSupply();
        return (supply == 0) ? shares : shares.mulDiv(totalAssets(), supply, rounding);
    }

```
