# Vulnerability details

## Impact
The `calcDecrease` function in `CDPVault.sol` performs several arithmetic operations to compute the new debt and interest values after a debt repayment. Although Solidity 0.8.x includes built-in checks for overflow and underflow, it is still important to be cautious with arithmetic operations, especially when large values are involved.

The function does not use safe math libraries, which could result in incorrect calculations under specific edge cases where large or unexpected values are processed. If such values lead to overflow or underflow, the function may calculate incorrect debt values, leading to financial discrepancies and potential losses for the protocol.
```
if (amountToRepay >= cumulativeQuotaInterest) {
    amountToRepay -= cumulativeQuotaInterest;
    profit += cumulativeQuotaInterest;
} else {
    uint256 quotaInterestPaid = amountToRepay;
    profit += amountToRepay;
    amountToRepay = 0;
}
...
newDebt = debt - amountToRepay;
```

The c`alcDecrease` function calculates the reduction in debt and interest after a repayment. It deducts the repayment amount from the cumulative quota interest and updates the profit accordingly. Finally, it adjusts the `newDebt` by subtracting the repayment amount from the existing debt.

## Proof of Concept
An edge case where the cumulativeQuotaInterest is significantly larger than expected could cause unintended behavior, such as an underflow or incorrect debt calculation:

```
uint256 largeInterest = type(uint256).max;
CDPVault vault = new CDPVault();
vault.calcDecrease(1, largeInterest, 1, 1, 1); // Edge case that could cause unexpected results
```
simulate an environment where the `cumulativeQuotaInterest` or debt is unusually large.
Call the `calcDecrease` function with a small repayment amount and observe the behavior.
The subtraction of a small amount from a large cumulative interest or debt value could lead to underflow or incorrect debt values, resulting in an inconsistent state.

Impact:

Incorrect Debt Calculations: If the arithmetic operations result in underflow, the calculated debt might be incorrect, leading to users having more or less debt than they should.
Potential Exploits: Attackers could manipulate their debt positions by exploiting these edge cases, potentially causing financial losses for the protocol.
Operational Risks: Incorrect debt management could lead to broader financial instability within the vault, affecting all users.
