# Vulnerability details

## Proof of Concept
The `_modifyPosition` function in the `CDPVault` contract contains a logic flaw in its total debt calculation. This function is responsible for updating a position's collateral and debt balances, as well as maintaining the global debt balance of the vault. The issue lies in the following code snippet:
```solidity
function _modifyPosition(
    address owner,
    Position memory position,
    uint256 newDebt,
    uint256 newCumulativeIndex,
    int256 deltaCollateral,
    uint256 totalDebt_
) internal returns (Position memory) {
    uint256 currentDebt = position.debt;
    // ... (other code)

    // update the global debt balance
    if (newDebt > currentDebt) {
        totalDebt_ = totalDebt_ + (newDebt - currentDebt);
    } else {
        totalDebt_ = totalDebt_ - (currentDebt - newDebt);
    }
    totalDebt = totalDebt_;

    // ... (rest of the function)
}
```
The problem occurs when `newDebt` is $0$ and `currentDebt` is greater than $0$. In this scenario, if multiple calls are made to `_modifyPosition` for the same position without updating `currentDebt`, each call will subtract `currentDebt` from `totalDebt_`. This can lead to an incorrect reduction of the total debt, potentially causing an underflow or significant accounting errors.
The function's purpose is to accurately update the global debt balance based on changes to individual positions. However, this flaw compromises its ability to maintain correct debt accounting across multiple transactions.

The issue arises when the following conditions are met:
a. `newDebt` is $0$
b. `currentDebt` is greater than $0$
c. Multiple calls are made to `_modifyPosition` for the same position without updating `currentDebt`
In this scenario, each call to `_modifyPosition` will execute the else branch of the conditional statement:
```solidity
   totalDebt_ = totalDebt_ - (currentDebt - newDebt);
```
Since `newDebt` is $0$ and `currentDebt` remains unchanged between calls, this effectively becomes:
```solidity
   totalDebt_ = totalDebt_ - currentDebt;
```
This means that with each call, the function is subtracting the entire `currentDebt` from `totalDebt_`, even though the actual debt hasn't changed since the last call.
Let's say we have:
- Initial `totalDebt_` = $1000$
- `currentDebt` for a position = $100$
- `newDebt` = $0$
First call to `_modifyPosition`:
```solidity
   totalDebt_ = 1000 - (100 - 0) = 900
```
Second call (without updating `currentDebt`):
```solidity
   totalDebt_ = 900 - (100 - 0) = 800
```
Third call:
```solidity
   totalDebt_ = 800 - (100 - 0) = 700
```
As we can see, each call incorrectly reduces `totalDebt_` by $100$, even though the actual debt of the position hasn't changed since the first call.
The fundamental issue is that the function assumes that each call represents a new change in debt, rather than checking if there's an actual change between the current state and the new state. It doesn't account for the possibility of multiple calls with the same debt values.

## Impact
If this process continues, it could potentially lead to an arithmetic underflow when `totalDebt_` becomes smaller than `currentDebt`.
The total debt of the system will be artificially reduced, leading to a misrepresentation of the vault's financial state.

## Recommended Mitigation Steps
Modify the debt calculation logic to only update the total debt based on the actual change in debt for the position. Here's a proposed fix:
```solidity
int256 debtChange = int256(newDebt) - int256(currentDebt);
if (debtChange > 0) {
    totalDebt_ = totalDebt_ + uint256(debtChange);
} else if (debtChange < 0) {
    totalDebt_ = totalDebt_ - uint256(-debtChange);
}
totalDebt = totalDebt_;
```
