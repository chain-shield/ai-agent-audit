# Vulnerability details

## Vulnerability Details
The BalancerOracle contract is designed to provide price information for a Balancer pool. The `update()` function is crucial as it updates the pool's price based on individual token prices and pool metrics.

The bug lies in how the `safePrice` is updated at the beginning of the `update()` function. The current implementation allows for a potential price manipulation scenario.

## Code Snippet
```solidity
    if (block.timestamp - lastUpdate < updateWaitWindow) revert BalancerOracle__update_InUpdateWaitWindow();
    // update the safe price first
    safePrice = safePrice_ = currentPrice;
    lastUpdate = block.timestamp;
```

## Impact
An attacker with the KEEPER_ROLE could manipulate the `safePrice` by calling `update()` multiple times in succession. Each call would set `safePrice` to `currentPrice` before `currentPrice` is recalculated, potentially leading to significant price deviations.

## Scenario
1. An attacker gains the KEEPER_ROLE.
2. They manipulate the pool's composition or individual token prices.
3. They call `update()`, which sets `safePrice` to the manipulated `currentPrice`.
4. Before anyone can use the manipulated price, they quickly call `update()` again, locking in the manipulated price as `safePrice`.
5. The `safePrice` now reflects the manipulated state, even if `currentPrice` is corrected in subsequent updates.

## Fix
Modify the `update()` function to only update `safePrice` after calculating the new `currentPrice`:

```solidity
function update() external virtual onlyRole(KEEPER_ROLE) returns (uint256 safePrice_) {
    if (block.timestamp - lastUpdate < updateWaitWindow) revert BalancerOracle__update_InUpdateWaitWindow();
    
    lastUpdate = block.timestamp;

    uint256[] memory weights = IWeightedPool(pool).getNormalizedWeights();
    uint256 totalSupply = IWeightedPool(pool).totalSupply();

    // ... (rest of the price calculation)

    currentPrice = wdiv(wmul(totalPi, IWeightedPool(pool).getInvariant()), totalSupply);
    
    // Update safePrice after calculating currentPrice
    safePrice = safePrice_ = currentPrice;

    return safePrice_;
}
```

```solidity
function test_updatePriceManipulation() public {
    _mockUpdateCalls();
    vm.startPrank(keeper);
    balancerOracle.update();
    vm.warp(block.timestamp + updateWaitWindow);
    balancerOracle.update();
    vm.stopPrank();

    uint256 initialSafePrice = balancerOracle.safePrice();

    // Step 1: Simulate a price spike by changing the mock price
    uint256 manipulatedPrice = 2 ether; // Double the price
    vm.mockCall(chainlinkOracle, abi.encodeWithSelector(IOracle.spot.selector, token0), abi.encode(manipulatedPrice));
    vm.mockCall(chainlinkOracle, abi.encodeWithSelector(IOracle.spot.selector, token1), abi.encode(manipulatedPrice));

    // Step 2: Perform an update to set the manipulated price
    vm.warp(block.timestamp + updateWaitWindow);
    vm.prank(keeper);
    balancerOracle.update();

    uint256 manipulatedSafePrice = balancerOracle.safePrice();

    // Step 3: Revert the price change in the mock
    _mockUpdateCalls(); // This resets prices to 1 ether

    // Step 4: Perform another update
    vm.warp(block.timestamp + updateWaitWindow);
    vm.prank(keeper);
    balancerOracle.update();

    // Assert: The safePrice should still be the manipulated price
    assertEq(balancerOracle.safePrice(), manipulatedSafePrice, "SafePrice should remain at manipulated value");
    assertTrue(balancerOracle.safePrice() > initialSafePrice, "SafePrice should be higher than initial price");
    assertTrue(balancerOracle.safePrice() > balancerOracle.currentPrice(), "SafePrice should be higher than currentPrice");
}
```

The test showcases how the current implementation allows a keeper to potentially lock in a manipulated price as the `safePrice`, even after the actual price (represented by `currentPrice`) has returned to normal.
