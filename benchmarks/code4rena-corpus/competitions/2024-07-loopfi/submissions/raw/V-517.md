# Vulnerability details

## Impact
There is a check `_checkMinShares` in `StakingLPEth:::_withdraw` to ensure the total supply is equal to or larger than the min_shares (0.01 ether). However, malicious actor can use that check to DoS other users, so the users (1) cannot fully withdraw their assets and (2) leave some amount of assets locked.

## Proof of Concept

Part 1: Links to code

Code 2: The check is to check if _totalSupply > 0 && _totalSupply < MIN_SHARES and MIN_SHARES is uint256 private constant MIN_SHARES = 0.01 ether;
```

    @>    if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```

Part 2: Attack path
Alice - Victim, Bob - Malicious actor
1. Alice deposits 0.1
2. Bob deposits 0.1
3. Total supply becomes 0.2
4. Then Bob withdraws 0.09999999, and the total supply decreases to 0.10000001.
5. Then Alice wants to withdraw her full asset 0.1.
6. The withdrawal will fail with Revert MinSharesViolation(), since the new total supply will be 0.00000001 ether < MIN_SHARES = 0.01 ether.
7. Therefore, Alice can only withdraw 0.09000001 for passing the check and leave 0.00999999 (0.01 - 0.00000001) locked.
