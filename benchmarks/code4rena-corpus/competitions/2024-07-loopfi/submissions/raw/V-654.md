# Vulnerability details

## Impact
Since there's No Buffer Zone(gap) between the liquidationRatio and user's Health factor Ratio while taking borrow, user positions may be liquidated as soon as the maximum debt is taken according to collateral deposited by user for the position.

Because if the collateral's price goes down slightly, it will leave no room for collateral token prices fluctuations. Users have no chance to add more collateral or reduce debt before being liquidated at this moment because there is No Gap. This may eventually create more uncovered and bad debt for the protocol.

## Proof of Concept
The protocol allows users to take debt up to the maximum debt, till the peak of Liquidation threshold.

`function modifyCollateralAndDebt` -> 
```solidity
// code
 if (deltaDebt > 0) { // borrow is happening here
// code
        if (
            (deltaDebt > 0 || deltaCollateral < 0) &&
@>            !_isCollateralized(calcTotalDebt(_calcDebt(position)), collateralValue, config.liquidationRatio)
        ) revert CDPVault__modifyCollateralAndDebt_notSafe();

// code
```

which checks if borrower can take this much debt -
```soldity
    function _isCollateralized(uint256 debt, uint256 collateralValue, uint256 liquidationRatio)
        internal
        pure
        returns (bool)
    {    
@>        return (wdiv(collateralValue, liquidationRatio) >= debt);
    }
```

However, a position becomes prone to liquidation even if the collateral's spot price fluctuated a little downward. In `function liquidatePosition` , the check which will allows a position to get liquidate is [_isCollateralized](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L535) , which will return `false` as position is not collateralized, and therefore will pass the check and let the position successfully liquidate.

`function liquidatePosition` ->
```solidity
@>        if (_isCollateralized(calcTotalDebt(debtData), wmul(position.collateral, spotPrice_), config.liquidationRatio))
        {
            revert CDPVault__liquidatePosition_notUnsafe();
        }
```

## Recommended Mitigation Steps
Just explaining with a simple example:

ex. if the Liquidation Threshold's health Factor is set to 1.25

Then while taking a debt, a user must be checked for having a bigger Health Factor than that of Liquidation Threshold's health Factor ie. for example 1.5

So now here a user will have a gap of 1.5 - 1.25 = 0.25 

So now in bad market conditions, even if the collateral price falls slightly, users will have enough time to increase their collateral and won't be getting liquidated immediately.
