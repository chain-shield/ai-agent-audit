# Vulnerability details


The `liquidatePosition()` function in the CDPVault contract lacks slippage protection. This function allows liquidators to liquidate unsafe positions by selling collateral at a discounted oracle price. However, the amount of collateral received by the liquidator is not specified upfront and can change if the oracle price or liquidation discount changes between transaction submission and execution.

## Impact

- Liquidators may receive  less collateral than expected if the price oracle price differ from the actual price. Chainlink prices usually accept 0.5%-2%.
- Liquidators will receive less than expected due to an increase in the discounted price.
## Proof of Concept

1. A liquidator identifies an unsafe position with a discount price of Y% and a market price of X. They expect X * (1-Y) * repayAmount.
2. Since X can differ 0.5%-2% of the actual price the liquidator could receive less than expected.
3. Since Y can change the liquidator could receive less than expected if this is increased.

Manual review

## Recommended Mitigation Steps

Implement slippage protection by adding a `minCollateralReceived` parameter to the `liquidatePosition()` and `liquidatePositionBadDebt()`  function:

```solidity
function liquidatePosition(address owner, uint256 repayAmount, uint256 minCollateralReceived) external whenNotPaused {
    // ...
    uint256 takeCollateral = wdiv(repayAmount, discountedPrice);
    require(takeCollateral >= minCollateralReceived, "Slippage exceeded");
    // ...
}
```

This change allows liquidators to specify the minimum amount of collateral they expect to receive, protecting them from unexpected price movements and failed transactions due to slippage.
