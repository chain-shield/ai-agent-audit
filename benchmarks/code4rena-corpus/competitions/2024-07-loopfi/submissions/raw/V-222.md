# Vulnerability details

## Impact
lack of proper validation in the `onFlashLoan()` function.

## Proof of Concept
The `onFlashLoan()` function does not properly validate the initiator address. The initiator is the address that initiated the flash loan. There should be a validation step to ensure that only trusted addresses can initiate flash loans on the contract. Typically, this address would be the contract owner or a trusted entity, but it should not be assumed to be the correct one without validation.
```solidity
  function onFlashLoan(
        address /*initiator*/,
        address /*token*/,
        uint256 amount,
        uint256 fee,
        bytes calldata data
    ) external returns (bytes32) {
        if (msg.sender != address(flashlender)) revert PositionAction__onFlashLoan__invalidSender();

        (LeverParams memory leverParams, address upFrontToken, uint256 upFrontAmount) = abi.decode(
            data,
            (LeverParams, address, uint256)
        );

        // perform a pre swap from arbitrary token to collateral token if necessary
        if (leverParams.auxSwap.assetIn != address(0)) {
            bytes memory auxSwapData = _delegateCall(
                address(swapAction),
                abi.encodeWithSelector(swapAction.swap.selector, leverParams.auxSwap)
            );
            upFrontAmount = abi.decode(auxSwapData, (uint256));
        }

        // handle the flash loan swap
        bytes memory swapData = _delegateCall(
            address(swapAction),
            abi.encodeWithSelector(swapAction.swap.selector, leverParams.primarySwap)
        );
        uint256 swapAmountOut = abi.decode(swapData, (uint256));

        // deposit collateral and handle any CDP specific actions
        uint256 collateral = _onIncreaseLever(leverParams, upFrontToken, upFrontAmount, swapAmountOut);

        // derive the amount of normal debt from the swap amount out
        uint256 addDebt = amount + fee;

        // add collateral and debt
        ICDPVault(leverParams.vault).modifyCollateralAndDebt(
            leverParams.position,
            address(this),
            address(this),
            toInt256(collateral),
            toInt256(addDebt)
        );

        underlyingToken.forceApprove(address(flashlender), addDebt);

        return CALLBACK_SUCCESS;
    }
```
Initiator is not `msg.sender` or the flash loan contract. It is the address that triggered the flash lending contract to call the receiver’s `onFlashLoan` function.

## Recommended Mitigation Steps
Add the following check in the [PositionAction::onFlashLoan()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/PositionAction.sol#L379-L427) function:
```solidity
require(initiator == trustedInitiator, "FlashBorrower: Untrusted loan initiator");
```
This also applies to the [PositionAction::onCreditFlashLoan()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/PositionAction.sol#L431C14-L492) function.
