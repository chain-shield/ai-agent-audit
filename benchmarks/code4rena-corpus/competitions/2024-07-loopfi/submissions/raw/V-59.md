# Vulnerability details

## Impact
When users claim their Aura RewardsPool rewards, using `AuraVault::claim`, the protocol checks the current price of the `BAL` token, which is fetched from a Chainlink feed. In return, users would have to deposit some WETH according to some calculations done in `_previewReward`. 
However, `_chainlinkSpot` doesn't check the last `updatedAt` of the price feed before confirming that the price is valid.

This is wrong and could result in stale BAL prices, affecting users claiming their rewards.


## Tools Used

Manual review

## Recommended Mitigation Steps

Introduce a stale period and compare the updated date with that period when returning the spot price.

```diff
function _chainlinkSpot() private view returns (uint256 price) {
    bool isValid;
    try AggregatorV3Interface(BAL_CHAINLINK_FEED).latestRoundData() returns (
        uint80 /*roundId*/,
        int256 answer,
        uint256 /*startedAt*/,
-       uint256 /*updatedAt*/,
+       uint256 updatedAt,
        uint80 /*answeredInRound*/
    ) {
        price = wdiv(uint256(answer), BAL_CHAINLINK_DECIMALS);
-       isValid = (price > 0);
+       isValid = (price > 0 && block.timestamp - updatedAt <= STALE_PERIOD);
    } catch {}

    if (!isValid) revert AuraVault__chainlinkSpot_invalidPrice();
}
```
