# Vulnerability details

## Impact
The `repay` function in the contract, which is designed not to revert under normal circumstances, can inadvertently fail due to an external call to the `poolV3` contract. Specifically, the function `pool.repayCreditAccount(debtData.debt - newDebt, profit, 0);` in the `repay` function could revert if the `poolV3` contract is paused. This issue also impacts the flash loan functionality, which relies on this call. The `liquidatePosition` and `liquidatePositionBadDebt` functions are also affected by this issue, as they include external calls that may fail if the `poolV3` contract is paused. This situation creates a risk where critical debt management functions become unreliable during pauses, potentially leading to increased bad debt.

## Proof of Concept

1. **Repay Function Reversion:**
   - When the `poolV3` contract is paused, the `repayCreditAccount` function cannot be called, causing the `repay` function to revert despite being intended to always succeed.
  

 ```solidity
     pool.repayCreditAccount(debtData.debt - newDebt, profit, 0); // U:[CM-11]
 ```


2. **Liquidation Functionality Failure:**
   - The `liquidatePosition` and `liquidatePositionBadDebt` functions also include external calls to `poolV3`. These calls will revert if the `poolV3` contract is paused, preventing liquidation during critical times.
  
    
```solidity
     function liquidatePositionBadDebt(address owner, uint256 repayAmount) external whenNotPaused { ... }
     function liquidatePosition(address owner, uint256 repayAmount) external whenNotPaused { ... }
 ```

3. External call that reverts

 ```solidity
  function repayCreditAccount(
        uint256 repaidAmount,
        uint256 profit,
        uint256 loss
    )
        external
        override
@audit>>This ensures only creditmanager can call >>         creditManagerOnly // U:[LP-2C]
@audit>>reverts (unintended) >>       whenNotPaused // U:[LP-2A]
        nonReentrant // U:[LP-2B]
    {
```


Based on gearbox implementation the  creditManagerOnly modifier was not used in there implementation hence pausing was intended, here the function cannot be called by just anyone hence modification is intended to allow for a smooth operation.

## Recommended Mitigation Steps

1. **Remove `whenNotPaused` Modifier in `repayCreditAccount`:**
   - The `whenNotPaused` modifier in the `repayCreditAccount` function is unnecessary since the `creditManagerOnly` modifier is sufficient to control the function's accessibility. Removing the `whenNotPaused` modifier will prevent the `repay` function from inadvertently failing when the `poolV3` contract is paused.
  
 - Example Mitigation:
    

```solidity
     function repayCreditAccount(
         uint256 repaidAmount,
         uint256 profit,
         uint256 loss
     )
         external
         override
         creditManagerOnly // U:[LP-2C]
         nonReentrant // U:[LP-2B]
     {
         // Function implementation...
     }
  ```
