# Vulnerability details

## Impact

The `_getAuraSpot` function in the AuraVault contract is vulnerable to using stale or incorrect price data from Chainlink. This could lead to inaccurate price assessments, potentially causing incorrect calculations. The absence of a time and price check to validate the freshness of the price data exposes the protocol to using outdated price information, which could have severe consequences on collateral management and other critical functions.
.

## Proof of Concept

### Current Implementation

The `_getAuraSpot` function fetches the latest price from Chainlink without validating the freshness of the data:

```solidity
function _getAuraSpot() internal view returns (uint256 price) {
    uint256 ethPrice;
    (, int256 answer, , , ) = AggregatorV3Interface(ETH_CHAINLINK_FEED).latestRoundData();
    ethPrice = wdiv(uint256(answer), ETH_CHAINLINK_DECIMALS);

    IPriceOracle.OracleAverageQuery[] memory queries = new IPriceOracle.OracleAverageQuery[](1);
    queries[0] = IPriceOracle.OracleAverageQuery(IPriceOracle.Variable.PAIR_PRICE, 1800, 0);
    uint256[] memory results = IPriceOracle(auraPriceOracle).getTimeWeightedAverage(queries);

    price = wmul(results[0], ethPrice);
}
```

### Reference Implementation with Time Validation

A better implementation validates that the price is not stale:

```solidity
function _fetchAndValidate(address token) internal view returns (bool isValid, uint256 price) {
    Oracle memory oracle = oracles[token];
    try AggregatorV3Interface(oracle.aggregator).latestRoundData() returns (
        uint80 /*roundId*/,
        int256 answer,
        uint256 /*startedAt*/,
        uint256 updatedAt,
        uint80 /*answeredInRound*/
    ) {
        isValid = (answer > 0 && block.timestamp - updatedAt <= oracle.stalePeriod);
        return (isValid, wdiv(uint256(answer), oracle.aggregatorScale));
    } catch {
        // return the default values (false, 0) on failure
    }
}
```

### Risk Scenario

If the Chainlink oracle provides a stale price, the `_getAuraSpot` function will not detect it, leading to the use of outdated or incorrect price data in critical functions.

## Recommended Mitigation Steps

To prevent the use of stale prices, the `_getAuraSpot` function should include a time check similar to the one in the reference implementation. This will ensure that the price data is current and reliable.

### Refactored Code

```solidity
function _getAuraSpot() internal view returns (uint256 price) {
    uint256 ethPrice;
    bool isValid;
    uint256 updatedAt;

    try AggregatorV3Interface(ETH_CHAINLINK_FEED).latestRoundData() returns (
        uint80 /*roundId*/,
        int256 answer,
        uint256 /*startedAt*/,
        uint256 updatedAt_,
        uint80 /*answeredInRound*/
    ) {
        ethPrice = wdiv(uint256(answer), ETH_CHAINLINK_DECIMALS);
        updatedAt = updatedAt_;
        isValid = (ethPrice > 0 && block.timestamp - updatedAt <= STALE_PERIOD); // STALE_PERIOD is the acceptable time difference
    } catch {
        isValid = false;
    }

    if (!isValid) revert AuraVault__chainlinkSpot_invalidPrice();

    IPriceOracle.OracleAverageQuery[] memory queries = new IPriceOracle.OracleAverageQuery[](1);
    queries[0] = IPriceOracle.OracleAverageQuery(IPriceOracle.Variable.PAIR_PRICE, 1800, 0);
    uint256[] memory results = IPriceOracle(auraPriceOracle).getTimeWeightedAverage(queries);

    price = wmul(results[0], ethPrice);
}
```
