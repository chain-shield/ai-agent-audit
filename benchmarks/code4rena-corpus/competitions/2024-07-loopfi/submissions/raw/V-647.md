# Vulnerability details

## Vulnerability details
In the `ChefIncentivesController` contract, `rewardsPerSecond` value can be fixed amount that set by owner or dynamically updated according to an emission schedule. Its logic is implemented in the `setScheduledRewardsPerSecond` function, which is triggered by `_updateEmissions()` function:

    function _updateEmissions() internal {
        if (block.timestamp > endRewardTime()) {
            _massUpdatePools();
            lastRPS = rewardsPerSecond;
            rewardsPerSecond = 0;
            return;
        }
        setScheduledRewardsPerSecond();   // <--
    }
However, the `_updateEmissions()` function is only used by `addPool()` and `claim()` functions, but not in `_handleActionAfterForToken()` or `afterLockUpdate()` . The latter two functions both call the `_updatePool` function in order to update pool rewards using the `rewardsPerSecond` value, but do not support emission schedule updates, which may lead to incorrect reward emissions until there is a new pool added or a claim is triggered.

## Impact
Incorrect reward emissions can happen.

## Tools Used
Manual review.

## Recommended Mitigation Steps
Call `_updateEmissions()` function in both `addPool()` and `claim()` functions.
