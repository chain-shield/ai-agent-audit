# Vulnerability details

## Impact
The deposit and withdraw functions are intended to be restricted when the contract is paused to prevent any changes to collateral and debt balances during a paused state as they carry the `whennotpaused` modifier. Both deposit and withdrawal ultimately calls `modifyCollateralAndDebt` function to executes it action. However the `modifyCollateralAndDebt` function is a public function which do not have the whennotpaused modifier. and can be called directly to make deposits and withdrawl when contract is paused.  This undermines the purpose of pausing the contract and can lead to unintended changes to user positions during a paused state

## Proof of Concept
When the contract is paused by an authorized account, direct calls to deposit and withdraw are correctly restricted and will revert as expected (due to whennotpaused modifier)
```
function deposit(address to, uint256 amount) external whenNotPaused returns (uint256 tokenAmount) 

function withdraw(address to, uint256 amount) external whenNotPaused returns (uint256 tokenAmount)
```
Despite the contract being paused, users can still indirectly perform deposit and withdraw operations by calling the modifyCollateralAndDebt function. This function lacks the whenNotPaused modifier, allowing it to be executed even when the contract is paused.
As a result, users can modify their collateral and debt balances, effectively bypassing the intended restrictions of the paused state.
```
    function modifyCollateralAndDebt(
        address owner,
        address collateralizer,
        address creditor,
        int256 deltaCollateral,
        int256 deltaDebt
    ) public {....
}
```
