# Vulnerability details

## Impact
 The ``_updateBaseInterest`` function in our contract does not check the return value of the external call to ``calcBorrowRate()``. This could lead to failed interest rate updates being treated as successful, potentially resulting in incorrect interest calculations and unfair distribution of interest to users.

## Proof of Concept
https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/PoolV3.sol#L642-L668

```solidity
function _updateBaseInterest(
    int256 expectedLiquidityDelta,
    int256 availableLiquidityDelta,
    bool checkOptimalBorrowing
) internal {
    // ... snip ...
    _baseInterestRate = ILinearInterestRateModelV3(interestRateModel)
        .calcBorrowRate({
            expectedLiquidity: expectedLiquidity_,
            availableLiquidity: availableLiquidity_,
            checkOptimalBorrowing: checkOptimalBorrowing
        })
        .toUint128(); // Unchecked return value
    // ... snip ...
}
```
Scenario:
The ``interestRateModel`` contract is updated with a new implementation that has a bug causing it to revert under certain conditions.
When ``_updateBaseInterest`` is called, the ``calcBorrowRate()`` function reverts due to this bug.
However, because the return value is not checked, the transaction doesn't revert, and ``_baseInterestRate`` retains its previous value.
The contract continues to operate with an outdated interest rate, leading to incorrect interest calculations for all users.

Could have this impact:
Alice deposits ``100 tokens`` expecting a ``5%`` interest rate.
The ``calcBorrowRate()`` function should update the rate to ``7%`` due to market conditions, but it reverts silently.
The contract continues using the old ``5%`` rate.
When Alice withdraws her funds after a year, she receives less interest than she should have, while the protocol retains more funds than it should.

This might result in failed interest rate updates that are treated as successful, leading to discrepancies in interest calculations and distributions.

## Recommended Mitigation Steps
If send or call is used, Always make sure to handle the possibility that the call will fail, by checking the return value.
```solidity
(bool success, bytes memory data) = address(interestRateModel).call(
    abi.encodeWithSelector(
        ILinearInterestRateModelV3.calcBorrowRate.selector,
        expectedLiquidity_,
        availableLiquidity_,
        checkOptimalBorrowing
    )
);
require(success, "Interest rate calculation failed");
uint256 newRate = abi.decode(data, (uint256));
require(newRate > 0 && newRate <= type(uint128).max, "Invalid interest rate");
_baseInterestRate = uint128(newRate);
```
Alternatively use this approach: 
```solidity
try ILinearInterestRateModelV3(interestRateModel).calcBorrowRate(
    expectedLiquidity_,
    availableLiquidity_,
    checkOptimalBorrowing
) returns (uint256 newRate) {
    require(newRate > 0 && newRate <= type(uint128).max, "Invalid interest rate");
    _baseInterestRate = uint128(newRate);
} catch {
    // Handle the error, e.g., revert or use a fallback rate
    revert("Failed to calculate new interest rate");
}
```
