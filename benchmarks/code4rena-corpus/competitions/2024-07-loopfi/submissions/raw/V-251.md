# Vulnerability details

`_modifyPosition()` function, which is called by `modifyCollateralAndDebt()`, incorrectly updates the `totalDebt` state variable. This issue stems from passing an outdated `totalDebt` value to `_modifyPosition()`, resulting in inconsistent debt calculations that could lead to system-wide insolvency.

The root of the problem is in the interaction between [modifyCollateralAndDebt()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L367-L460) and [_modifyPosition()](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L305-L342) functions: [CDPVault.sol:L445](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L445)
```solidity
// In modifyCollateralAndDebt()
position = _modifyPosition(owner, position, newDebt, newCumulativeIndex, deltaCollateral, totalDebt);
```
[CDPVault.sol:L328-L333](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L328-L333)
```solidity
// In _modifyPosition()
if (newDebt > currentDebt) {
    totalDebt_ = totalDebt_ + (newDebt - currentDebt);
} else {
    totalDebt_ = totalDebt_ - (currentDebt - newDebt);
}
totalDebt = totalDebt_;
```

The `totalDebt` passed to `_modifyPosition()` doesn't reflect the changes made in `modifyCollateralAndDebt()`, leading to incorrect updates of the global `totalDebt` state variable.

## Impact
> The issue is that the `totalDebt` variable passed to `_modifyPosition` from `modifyCollateralAndDebt` is not updated with the changes made in `modifyCollateralAndDebt`. This leads to the `_modifyPosition` function updating the `totalDebt` state variable incorrectly.

Over time, the discrepancy between the actual total debt and the recorded `totalDebt` could grow, leading to a situation where the system becomes insolvent without detection.

The inaccurate `totalDebt` value may cause the system to misjudge its overall risk exposure, potentially allowing for over-borrowing or under-collateralization.

## Proof of Concept
- Alice calls `modifyCollateralAndDebt()` to increase her debt by 100 tokens.
- The function calculates the new debt and calls `_modifyPosition()` with the old `totalDebt` value.
- `_modifyPosition()` updates Alice's position correctly but uses the outdated `totalDebt` to calculate the new global debt.
- The resulting `totalDebt` is now incorrect, as it doesn't accurately reflect Alice's debt increase.
- This process repeats with multiple users, compounding the error in `totalDebt`.

## Recommended Mitigation Steps
1. Update the `totalDebt` calculation within the `modifyCollateralAndDebt()` function before calling `_modifyPosition()`.
2. Pass the updated `totalDebt` to `_modifyPosition()`.
3. Remove the `totalDebt` update logic from `_modifyPosition()` and instead use it to verify the calculation.
