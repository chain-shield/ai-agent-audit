# Vulnerability details

The `totalDebt` is updated within the `_modifyPosition()` function. The function takes the `totalDebt` as a parameter named `totalDebt_`, modifies it locally based on the changes in debt, and then assigns the modified value back to the `totalDebt` state variable. This can lead to inconsistencies if the `totalDebt_` parameter passed to the function is not the most up-to-date value of `totalDebt`.

In the `modifyCollateralAndDebt()` function: [CDPVault.sol#L445](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L445)
```solidity
position = _modifyPosition(owner, position, newDebt, newCumulativeIndex, deltaCollateral, totalDebt);
```
_Here, the `totalDebt` variable is passed as an argument to `_modifyPosition()` without being updated with the changes made in `modifyCollateralAndDebt()`. As a result, the `_modifyPosition()` function may update the `totalDebt` state variable incorrectly._

The issue manifests in the `_modifyPosition` function ([CDPVault.sol#L327-L333](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/CDPVault.sol#L327-L333)) where the `totalDebt` state variable is updated based on the `totalDebt_` parameter
```solidity
// update the global debt balance
if (newDebt > currentDebt) {
    totalDebt_ = totalDebt_ + (newDebt - currentDebt);
} else {
    totalDebt_ = totalDebt_ - (currentDebt - newDebt);
}
totalDebt = totalDebt_;
```

## Impact
An attacker could potentially exploit the inconsistency in the `totalDebt` variable to manipulate the system's behavior, such as avoiding liquidations or borrowing more than allowed.

## Proof of Concept
1. User A has a position with a debt of 100 tokens and a collateral value of 150 tokens.
2. User B has a position with a debt of 200 tokens and a collateral value of 250 tokens.
3. The current `totalDebt` of the vault is 300 tokens.
4. User A calls the `modifyCollateralAndDebt()` function to increase their debt by 50 tokens and add 60 tokens of collateral.
5. Inside `modifyCollateralAndDebt()`, the `_modifyPosition()` function is called with the outdated `totalDebt` value of 300 tokens.
6. The `_modifyPosition()` function updates the `totalDebt` based on the outdated value, resulting in a `totalDebt` of 350 tokens (300 + 50) instead of the correct value of 350 tokens (100 + 200 + 50).

As a result, the `totalDebt` state variable does not accurately reflect the total debt across all positions in the vault.

## Recommended Mitigation Steps
The `modifyCollateralAndDebt()` function should update the `totalDebt` state variable directly with the changes made, rather than relying on passing it as an argument to `_modifyPosition()`. Additionally, the `_modifyPosition()` function should update `totalDebt` based on its current value and the changes in debt, rather than using the `totalDebt_` parameter.
```diff
// update the global debt balance
if (newDebt > currentDebt) {
-   totalDebt_ = totalDebt_ + (newDebt - currentDebt);
+   totalDebt += (newDebt - currentDebt);
} else {
-   totalDebt_ = totalDebt_ - (currentDebt - newDebt);
+   totalDebt -= (currentDebt - newDebt);
}
- totalDebt = totalDebt_;
```
