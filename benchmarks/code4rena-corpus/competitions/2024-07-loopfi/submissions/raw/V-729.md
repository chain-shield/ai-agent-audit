# Vulnerability details

## Vulnerability Details

The `BalancerOracle` contract is designed to provide price information for tokens in a Balancer pool. The `_getStatus` function is crucial for determining whether the current price data is valid and up-to-date. The `_getStatus` function has a race condition that can lead to returning a false positive status immediately after an update, even if the new price hasn't been properly set.

## Code Snippet

```solidity
function _getStatus() internal view returns (bool status) {
    status = (safePrice != 0) && block.timestamp - lastUpdate < stalePeriod;
}
```

## Impact
This bug could lead to the oracle reporting that it has valid, up-to-date price data when it actually doesn't. This could result in incorrect pricing information being used in downstream systems, potentially leading to financial losses or other serious issues in DeFi applications relying on this oracle.

## Scenario

1. The `update` function is called, setting `lastUpdate` to the current timestamp.
2. However, due to some issue (e.g., a revert in price fetching), `safePrice` remains unchanged.
3. Immediately after this, `_getStatus` is called.
4. `_getStatus` returns `true` because `lastUpdate` is recent, even though `safePrice` might be stale or invalid.

## Fix
Modify the `update` function to only update `lastUpdate` after successfully setting a new `safePrice`.

```solidity
function update() external virtual onlyRole(KEEPER_ROLE) returns (uint256 safePrice_) {
    if (block.timestamp - lastUpdate < updateWaitWindow) revert BalancerOracle__update_InUpdateWaitWindow();
    
    uint256 newPrice = calculateNewPrice(); // New function to calculate the price
    if (newPrice == 0) revert BalancerOracle__update_InvalidPrice();
    
    safePrice = safePrice_ = newPrice;
    currentPrice = newPrice;
    lastUpdate = block.timestamp; // Only update timestamp after successful price update
    
    return safePrice_;
}
```
