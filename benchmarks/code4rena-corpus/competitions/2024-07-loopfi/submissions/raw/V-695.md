# Vulnerability details

The `_withdraw()` function in the `StakingLPEth` contract has a potential vulnerability where an attacker can lock the funds of the last withdrawer indefinitely. This issue arises due to the interaction between the `MIN_SHARES` constraint and the `totalSupply()` check in the `_checkMinShares()` function.

## Impact
This vulnerability allows an attacker to prevent the last withdrawer from accessing their funds. This could lead to a denial of service for users of the `StakingLPEth` contract.

## Proof of Concept
In the `_withdraw()` function, the `_checkMinShares()` function is called after the withdrawal operation. This function checks if the total supply of shares is less than `MIN_SHARES`, which is set to `0.01 ether`. If the total supply is below this threshold, the function reverts the transaction with a `MinSharesViolation` error.

```solidity
    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
@>      if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }
```

An attacker can exploit this by depositing a very small amount of shares (e.g., 1 wei). If a depositor (e.g., Alice) has deposited a significant amount (e.g., 1 ETH). When Alice tries to withdraw her funds,and she is the last withdrawer, the total supply may be reduced to a value below `MIN_SHARES`, causing the transaction to revert. This would lock Alice's funds in the contract indefinitely, as she cannot withdraw without triggering the `MinSharesViolation` error.

## Recommended Mitigation Steps
To mitigate this issue, consider modifying the `_withdraw()` logic to ensure that users can always withdraw their funds, regardless of the total supply. One approach could be implement a minimum deposit amount which should not be less than `MIN_SHARES`.
