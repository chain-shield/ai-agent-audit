# Vulnerability details

## Impact
The rate will get divided first with `SECONDS_PER_YEAR`(31536000) and get rounded down to 0 which will lead to improper calculation of the `cumulativeIndexLU`.

## Proof of Concept
In the function PoolQuotaKeeperV3.updateRates() there is a call to QuotasLogic.cumulativeIndexSince for getting the new `cumulativeIndexLU`. The code is as follows:
```
uint256(cumulativeIndexLU)+ RAY_DIVIDED_BY_PERCENTAGE * (block.timestamp - 
   lastQuotaRateUpdate) * rate / SECONDS_PER_YEAR
        );
```
The function is used to return the new interest index value. But it won't be properly updated because the rate will get divided by `SECONDS_PER_YEAR`(31536000), that is greater than uint16.max (65536) which is the datatype used for the rate , first before getting multiplied with `RAY_DIVIDED_BY_PERCENTAGE * (block.timestamp - 
   lastQuotaRateUpdate)` which will cause it to round down to 0, and then get added with cumulativeIndexLU.

This will lead to the cumulativeIndexLU to be the same.
## Tools Used
VS Code

## Recommended Mitigation Steps
Add brackets so that it will multiply the rate first before getting divided.
```
uint256(cumulativeIndexLU)+ (RAY_DIVIDED_BY_PERCENTAGE * (block.timestamp - 
   lastQuotaRateUpdate) * rate )/ SECONDS_PER_YEAR
        );
```
