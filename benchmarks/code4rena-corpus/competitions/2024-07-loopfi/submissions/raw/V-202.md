# Vulnerability details

## Proof of Concept
In the `ChefIncentivesController` contract, there are two methods for distributing rewards:

- **Fixed Rewards Per Second**: The reward rate is set using a static `rewardsPerSecond` value.
- **Emission Schedule**: The reward rate is adjusted according to a predefined schedule.
The emission schedule is managed by the [setScheduledRewardsPerSecond](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L352) function, which relies on [_updateEmissions](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L439) to update `rewardsPerSecond` based on the schedule. The `_updateEmissions` function is defined as follows:
```solidity
    function _updateEmissions() internal {
        if (block.timestamp > endRewardTime()) {
            _massUpdatePools();
            lastRPS = rewardsPerSecond;
            rewardsPerSecond = 0;
            return;
        }
        setScheduledRewardsPerSecond();
    }
```
However, `_updateEmissions` is invoked only in the [addPool](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L301) and [claim](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L518) functions:
```solidity
function addPool(address pool) external {
    _updateEmissions();
    // Additional logic to add pool
}

function claim(address user) external {
    _updateEmissions();
    // Additional logic to process claim
}
```
The function [_handleActionAfterForToken](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L627) call [_updatePool](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/reward/ChefIncentivesController.sol#L469) to update rewards:
```solidity
function _handleActionAfterForToken(address token) internal {
    _updatePool(token);
}
```
This function do not call `_updateEmissions`, meaning it does not consider updates to the emission schedule. As a result, the `rewardsPerSecond` value used for updating pool rewards may be outdated if the emission schedule has changed since the last update by `addPool` or `claim`.
## Impact
Incorrect reward emissions: Pools using the emission schedule might distribute rewards based on outdated `rewardsPerSecond` values, leading to inaccuracies in the rewards calculation until a new pool is added or a claim is processed.

## Tools Used
Manual
## Recommended Mitigation Steps
Integrate a call to `_updateEmissions` within `_handleActionAfterForToken` and `afterLockUpdate`.
