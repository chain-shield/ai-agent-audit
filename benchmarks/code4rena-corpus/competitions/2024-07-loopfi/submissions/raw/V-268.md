# Vulnerability details

## Description

The `SwapAction` contract facilitates token swaps using different protocols (Balancer, Uniswap V3, Pendle). The [`swap` function](https://github.com/code-423n4/2024-07-loopfi/blob/57871f64bdea450c1f04c9a53dc1a78223719164/src/proxy/SwapAction.sol#L108-L143) handles the logic for executing these swaps based on the parameters provided. One of the swap types supported is `EXACT_OUT`, where the user specifies the exact amount of tokens they want to receive from the swap.

In the current implementation, the `swap` function attempts to transfer any remaining tokens to the recipient after an `EXACT_OUT` swap. However, the calculation used to determine the amount of tokens to transfer is incorrect. Specifically, the function calculates the remaining tokens as `swapParams.limit - retAmount`, where `retAmount` is the amount of tokens received from the swap. This logic is flawed because `retAmount` represents the amount received, not the amount used in the swap.

The incorrect calculation can lead to erroneous token transfers, potentially resulting in financial discrepancies for users. For example, if the `retAmount` is greater than `swapParams.limit`, the calculation would result in a negative value, causing the transfer to fail or behave unexpectedly.

## Impact
The incorrect token transfer calculation in `EXACT_OUT` swaps can lead to financial discrepancies, such as over-transferring or under-transferring tokens. This could result in loss of funds or incorrect balances for users, undermining the reliability and trustworthiness of the contract.

## Proof of Concept
1. **User** initiates an `EXACT_OUT` swap with the following parameters:
   - `swapParams.limit = 100`
   - `retAmount = 120` (amount received from the swap)
2. The `swap` function calculates the remaining tokens to transfer as `swapParams.limit - retAmount`, which equals `100 - 120 = -20`.
3. The negative value causes the transfer to fail or behave unexpectedly, leading to incorrect token balances.
