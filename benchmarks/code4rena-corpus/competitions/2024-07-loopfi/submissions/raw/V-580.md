# Vulnerability details


## Impact

The attacker retains 1wei share, causing the 0.01ETH share of the last user cannot be withdrawn, causing a loss for the user.

## Proof of Concept

In `StakingLPEth`, the `withdraw` function, which reduces `totalSupply` by doing `withdraw`, then checks for the minimum value of share in the pool.

```solidity
    function _withdraw(
        address caller,
        address receiver,
        address _owner,
        uint256 assets,
        uint256 shares
    ) internal override nonReentrant {
        super._withdraw(caller, receiver, _owner, assets, shares);
        _checkMinShares();
    }

    function _checkMinShares() internal view {
        uint256 _totalSupply = totalSupply();
        if (_totalSupply > 0 && _totalSupply < MIN_SHARES) revert MinSharesViolation();
    }

```

So if _totalSupply > 0, the mini amount of share of the last user in the pool cannot be withdrawn,
If a malicious user retains 1wei share(or perhaps unintentionally), `_totalSupply` will be greater than 0.

Depending on the proportion of share and asset, 0.01 ETH share corresponds to a large amount of assets. If the protocol runs for a long time and a large number of assets are sent to the pool, the proportion may be large. Therefore, users may lose a large amount of funds.
