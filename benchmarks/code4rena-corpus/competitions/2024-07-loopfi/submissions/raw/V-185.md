# Vulnerability details

## Impact

The `Silo` contract allows to store `lpETH` during the stake cooldown process.

When a `StakingLPEth::unstake` is called, a `Silo::withdraw` external call is made. 

However, the `Silo::withdraw` makes no check to ensure that it has enough `lpEth` balances before executing a withdraw to the user.

If the contract doesn't check its balance before transferring tokens, it may enter a state where it continually fails to execute transfers due to insufficient funds. This could cause a denial of service, preventing legitimate users from interacting with the contract. In addition, it is possible that the call does not revert but the user receives significantly less `lpEth` than expected.

```
// src/StakingLPEth.sol
//ln#88-100

function unstake(address receiver) external { //
        UserCooldown storage userCooldown = cooldowns[msg.sender];
        uint256 assets = userCooldown.underlyingAmount;

        if (block.timestamp >= userCooldown.cooldownEnd || cooldownDuration == 0) {
            userCooldown.cooldownEnd = 0;
            userCooldown.underlyingAmount = 0;

            silo.withdraw(receiver, assets); //@audit HERE
        } else {
            revert InvalidCooldown();
        }
    }
```

## Recommended Mitigation Steps

Ensure that `Silo::withdraw` checks for its `lpEth` balances and checks that it is sufficient for the `withdraw` before execution.
