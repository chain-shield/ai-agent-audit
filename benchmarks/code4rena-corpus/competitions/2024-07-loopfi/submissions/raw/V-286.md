# Vulnerability details

## Impact
Detailed description of the impact of this finding.

The setOracles function in the ChainlinkOracle contract lacks a validation check to ensure that the input arrays _tokens and _oracles have the same length. 

This can lead to incomplete or incorrect mapping of tokens to their respective oracles, which might result in operational failures or data inconsistencies.

Without the length check, the function may attempt to map tokens to oracles using mismatched array lengths, potentially causing some tokens to remain unmapped. 

This will affect the ability of the contract to fetch price data for those tokens, leading to failures in other parts of the system relying on accurate price feeds. 

***Use Case***
A similar issue was observed in the Uniswap V3 bug bounty, where a length mismatch in array parameters could have led to incorrect liquidity accounting.

The issue was mitigated by enforcing array length checks to ensure data consistency and integrity.

## Proof of Concept

Consider the following scenario where _tokens has 3 elements, but _oracles has only 2:
```sol
address tokens[];
tokens[0] = 0xTokenAddress1;
tokens[1] = 0xTokenAddress2;
tokens[2] = 0xTokenAddress3;

Oracle oracles[];
oracles[0] = Oracle(AggregatorV3Interface(0xAggregatorAddress1), 300, 1e8);
oracles[1] = Oracle(AggregatorV3Interface(0xAggregatorAddress2), 300, 1e8);

chainlinkOracle.setOracles(tokens, oracles);
```

In this case, tokens[2] (0xTokenAddress3) would not be assigned an oracle, leading to undefined behaviour when its price is queried.

## Recommended Mitigation Steps
Add a validation check at the beginning of the setOracles function to ensure that both arrays have the same length:
```sol
function setOracles(address[] calldata _tokens, Oracle[] calldata _oracles) external onlyRole(DEFAULT_ADMIN_ROLE) {
    require(_tokens.length == _oracles.length, "Tokens and oracles length mismatch");

    for (uint256 i = 0; i < _tokens.length; i++) {
        oracles[_tokens[i]] = _oracles[i];
    }
}
```
