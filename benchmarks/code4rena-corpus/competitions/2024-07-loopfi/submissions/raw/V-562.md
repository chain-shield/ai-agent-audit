# Vulnerability details

## Vulnerability details

When users call `TransferAction#_transferFrom` function, it internally call `IERC20Permit(token).safePermit` function to permit the token if the `params.approvalType == ApprovalType.PERMIT`.

```solidity
 function _transferFrom(
    address token,
    address from,
    address to,
    uint256 amount,
    PermitParams memory params
) internal {
    ...
    IERC20Permit(token).safePermit(
        from,
        to,
        params.approvalAmount,
        params.deadline,
        params.v,
        params.r,
        params.s
    );
    IERC20(token).safeTransferFrom(from, to, amount);
    ...
}
```

However, the `IERC20Permit(token).safePermit` function can revert because the `IERC20#permit` function can be called by anyone with the same parameters. If the permit be called before the users's txs, the users's txs will be reverted.

So the later action like `safeTransferFrom` wouldn't be executed as expected.

```solidity
// @audit - called by safePermit, `_useNonce` would increase the user nonce.
function permit(
    address owner,
    address spender,
    uint256 value,
    uint256 deadline,
    uint8 v,
    bytes32 r,
    bytes32 s
) public virtual override {
    require(block.timestamp <= deadline, "ERC20Permit: expired deadline");

    bytes32 structHash = keccak256(abi.encode(_PERMIT_TYPEHASH, owner, spender, value, _useNonce(owner), deadline));

    bytes32 hash = _hashTypedDataV4(structHash);

    address signer = ECDSA.recover(hash, v, r, s);
    require(signer == owner, "ERC20Permit: invalid signature");

    _approve(owner, spender, value);
}
```

## Impact

Users `TransferAction#_transferFrom` related txs can be reverted.

## Tools Used

vscode

## Recommended Mitigation Steps

Use `try...catch` to mitigate, if `safePermit` failed, call `transferFrom` in the catch block.
