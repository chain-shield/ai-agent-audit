## id: jWuI7tcEvGKNrRHhPxhvQ

## Finding Status: Valid
### Finding Status Justification: This finding is a variant of AU-S4980: even if a service initially stakes with a legitimate proxy, the proxy’s delegated logic can be changed (or was malicious from the start) to make nonce retrieval extremely gas-expensive or non-terminating. Because StakingBase forwards essentially all gas to `activityChecker.staticcall` and does not bound downstream gas usage, a single malicious service can cause `checkpoint()` to OOG/revert consistently, which in turn blocks `unstake()`/`stake()`/`checkpointAndClaim()`. No existing guard in StakingBase prevents this class of gas griefing (no gas caps, no per-service isolation), so the staking contract can be frozen, locking NFTs and halting rewards.
### Finding Complexity: 0
### PoC Test Status: ErrorRunningTests
## Minimim Privilege Required:Permissionless


## Description
The `checkpoint` function iterates over all staked services to calculate rewards. It calls `_calculateStakingRewards`, which triggers `activityChecker.staticcall` to query the service's multisig nonce. The `activityChecker` typically forwards gas to the target multisig. Since the `multisig` is user-provided and likely a Gnosis Safe Proxy (verified by codehash in `_stake`), a malicious service owner can exploit the upgradeability of Gnosis Safes. By upgrading their Safe's implementation (Master Copy) to a malicious contract that infinite loops or consumes excessive gas in its `nonce` function, the attacker can force the `activityChecker` call to consume all transaction gas. As `StakingBase` does not limit the gas forwarded to `activityChecker` (and `staticcall` forwards all available gas by default), the `checkpoint` transaction will inevitably revert due to Out of Gas. Since `stake`, `unstake`, and `claim` operations all require a successful `checkpoint` execution, the entire staking contract becomes permanently frozen.

## Impact
Permanent Denial of Service. All funds (rewards and staked NFTs) are locked in the contract as no state transitions can occur.

## Command to Run Test


## Proof of Concept
1. Attacker registers a valid service with a standard Gnosis Safe Proxy.
2. Attacker stakes the service in `StakingBase`.
3. Attacker uses the Safe's `execTransaction` to upgrade the Safe's master copy to a malicious contract that contains an infinite loop in its fallback or `nonce` function.
4. Any user attempts to call `checkpoint` (or `stake`/`unstake`/`claim` which call it).
5. `checkpoint` loops through services and reaches the attacker's service.
6. It calls `activityChecker.getMultisigNonces(attackerMultisig)`.
7. `activityChecker` calls `attackerMultisig.nonce()`.
8. The call consumes all gas.
9. The transaction reverts OOG.
